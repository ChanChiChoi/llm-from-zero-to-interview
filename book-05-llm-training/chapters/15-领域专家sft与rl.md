# 第 15 章 领域专家 SFT 与 RL：让模型在专业工作中说得对、做得成

领域适配的起点不是“给通用模型喂一批专业问答”，而是先定义一项专业工作怎样算完成。例如财报分析要能找到正确版本的表格、复算毛利变化、说明假设并把高风险结论交给人；医疗摘要要忠实保留药物过敏和时间信息，不能把建议写成诊断决定。不同目标对应不同训练信号，也对应不同责任边界。

初学者可以把领域后训练看成三步：先让模型听懂领域语言，再让它照着工作流完成任务，最后让它在证据不足、权限不足或规则冲突时停下来。专家还要继续区分继续预训练、SFT、偏好优化和 RL：继续预训练改变领域语言建模分布，SFT 教输入输出协议和示范流程，偏好优化排序多个合规答案，RL 或 RLVR 则在可验证环境中优化结果。它们可以串联，但不能用一个总 reward 替代所有层次。

一个领域训练计划至少要先固定四个问题：任务成功的可观察定义，证据和知识版本，模型可以执行的动作，出现风险时的人工升级路径。若这四项没有定义，后面的 reward 上升、专家打分或 SFT loss 下降都很难解释。

## 15.0 选择训练路线的依据

| 领域缺口 | 更接近的训练路线 | 主要证据 | 不应假设的事情 |
| --- | --- | --- | --- |
| 术语、格式和表达不熟 | 领域继续预训练或 SFT | 独立领域语言 loss、字段和格式准确率 | 语言流畅等于事实正确 |
| 会说但不会按流程做 | 轨迹 SFT、工具训练 | 步骤顺序、工具 schema、计算可复现 | 生成了工具名就执行成功 |
| 多个答案都对但质量不同 | 偏好优化 | 盲评偏好、证据支持、风格约束 | 偏好标签是客观真值 |
| 有明确可计算结果 | RLVR 或环境反馈 | 单元测试、计算 verifier、任务成功率 | verifier 没有盲点 |
| 有越权、隐私或副作用风险 | 独立 policy 和人工审核 | 拒绝率、误拒率、严重性加权事故 | 训练 reward 能授予权限 |

## 15.1 通用能力为什么不等于领域能力

一个通用模型可能会解释医学术语、阅读合同或编写金融 SQL，但真正的领域工作还要求遵守术语、流程、证据和责任边界。领域专家往往知道哪些回答听起来正确却不满足规范，也知道哪些异常必须升级给人。

因此领域后训练不能只收集“更专业的问答”。它要把专家的任务分解、引用习惯、工具使用、拒答边界和结果验证方式变成训练和评估信号。

## 15.2 SFT 先教什么

监督微调适合教模型领域语言、输入输出格式、工作流程和工具协议。样本可以包括问题、必要上下文、专家答案、引用、结构化字段和失败原因：

```math
\mathcal{L}_{\mathrm{SFT}}
=-\frac{1}{\max(1,\sum_t m_t)}
\sum_t m_t\log p_\theta(y_t\mid x,y_{<t})
```

`m_t` 表示第 `t` 个位置是否是预期的目标答案 token。用户问题、检索上下文、工具 observation 和 padding 通常不应在 assistant-only SFT 中被误算成目标；结构化字段、引用和拒答理由是否参与 loss，要由任务定义决定。分母使用有效 token 数，是为了避免长答案仅凭长度获得更大权重；按样本平均时则要明确采用了另一种加权策略。

高质量样本比大量未经审查的行业文本更重要。专家应标记事实、推断、假设和需要人工确认的部分，避免模型把专业语气误学成确定性。专业文本本身还可能过期或包含隐私，训练前要保留来源、revision、生效日期和脱敏记录。

## 15.3 专家数据的三种层次

第一层是事实和术语：定义、字段、法规和标准引用。第二层是任务演示：如何检索、比较、计算、调用工具和报告。第三层是边界样本：信息不足、证据冲突、越权请求和需要拒答的场景。

如果只有第一层，模型像百科；有第一和第二层，模型能完成常规工作；第三层决定它在不确定和高风险情况下是否可靠。

## 15.4 领域专家如何参与标注

专家不应只给一个最终答案，还要说明依据和关键判断。可以把标注表设计为：

```text
claim -> evidence -> confidence -> action -> escalation
```

不同专家意见不应简单平均。记录争议、适用条件和时间版本；法律、医学和金融知识会更新，数据必须能追溯到来源 revision。

专家标注的价值不只在最终答案，还在于把隐含判断外显出来。一个可复核的标注记录应能回答：主张来自哪段证据，证据属于哪个版本，计算用了哪些输入，哪些条件会改变结论，模型可以提出什么动作，以及为什么需要人工接管。对于无法达成一致的样本，保留 alternative answer 和分歧原因，后续可以把它们变成澄清、拒答或不确定性训练样本。

小白可以把 `claim -> evidence -> confidence -> action -> escalation` 看成答题卡旁边的判卷说明；专家则要进一步检查 evidence 是否足够支持 claim，confidence 是否校准，action 是否在权限范围内。若只记录“专家最终写了什么”，模型很容易学会口吻，却学不到判断条件。

## 15.5 为什么还需要 RL

SFT 模仿一个示范答案，RL 可以让模型在多个候选中偏向更符合领域目标的结果。奖励可以来自规则、测试、专家偏好、引用检查、格式校验和安全策略：

```math
R=R_{\mathrm{correct}}+\alpha R_{\mathrm{evidence}}
+\beta R_{\mathrm{format}}-\gamma R_{\mathrm{risk}}
```

奖励权重不是越多越好。若引用格式权重过大，模型可能生成形式正确但内容无关的引用；若拒答惩罚过强，模型会在证据不足时冒险回答。

奖励设计要先区分两种信号。正确性、证据完整度、表达清晰度和工具效率通常可以在合规轨迹中排序；隐私泄露、越权写入、伪造引用和违反硬性政策的动作则不应被“正确率高”抵消。工程上可以先用 policy/verifier 过滤不可接受轨迹，再在剩余候选中使用偏好或 RL 排序。这样做也更容易定位：是轨迹不合规，还是多个合规答案之间质量不同。

奖励组件还应保留原始分量和版本。例如 `R_evidence` 由哪种检索器或 source verifier 产生，`R_risk` 使用哪版 policy，专家偏好是否经过冲突裁决，都要进入轨迹记录。只记录一个总 reward，会让 reward hacking 发生后难以判断是规则漏洞、数据偏差还是模型真的改进。

## 15.6 一个金融报表例子

任务是解释季度毛利变化。SFT 样本教模型读取收入、成本、汇率和一次性项目，并输出结构化桥接表。验证器检查数字加总，专家检查归因是否有证据。RL 让模型在不同候选解释中偏向“可复算且明确不确定性”的答案。

如果模型只引用财报摘要，没有核对明细，格式评分可能很高但业务结论错误。因此 verifier 应同时检查计算、来源和时间范围。

例如毛利率可以先按定义计算：

```math
\mathrm{GrossMargin}
=\frac{\mathrm{Revenue}-\mathrm{COGS}}
{\mathrm{Revenue}}
```

但季度解释还要处理汇率、一次性项目、币种、期间和同比/环比口径。一个合格的候选答案应能指出使用了哪一版财报、哪些数字是直接读取、哪些是计算结果，并在数据缺失或期间不一致时停下来。数字 verifier 能发现算术错误，却不能独立判断“汇率变动是否是主要归因”；这部分需要来源检查和专家抽样。

## 15.7 领域工具和安全

领域 Agent 可能访问患者记录、交易系统或企业代码。工具权限必须独立于模型训练：SFT 不能授予权限，RL 也不能把高奖励变成写入授权。训练数据要脱敏，评估要加入越权和敏感信息外泄样本。

高风险动作应走人工确认。模型可以生成交易草稿或诊断摘要，但提交或医疗决策仍要由有权限的人员完成。

权限边界最好画成独立的状态转换，而不是写进一句自然语言奖励：`read -> draft -> review -> execute`。模型可以提出工具调用和参数，policy engine 决定是否允许，执行器负责幂等、审计和回滚，人工确认负责高风险动作。这样即使模型被提示注入、工具返回恶意文本或 reward 被绕过，训练信号也不会直接变成生产权限。

评估中还应加入“看起来合理但不应执行”的样本：越权读取患者记录、把合同草稿直接提交、使用过期法规、将用户提供的文本伪装成内部证据。对每个工具保存调用者、参数、返回版本、审批人和副作用，训练数据中的工具轨迹不能自动获得真实系统授权。

## 15.8 评估领域后训练

按事实问答、流程执行、工具调用、引用忠实、冲突判断、拒答和专业风格分桶。报告准确率、证据支持、格式合法、工具成功、人工接管、风险事件和单位成功成本。

还要做时间切分：用旧资料训练，测试新法规或新版本；做专家交叉评审，避免模型只适应某一位标注者的语言。

评估指标也要和任务结构对应。事实问答可以报告关键字段准确率，计算任务要报告可复算率，引用任务要报告支持主张的比例，工具任务要报告 schema 合法率、成功率和副作用率；拒答则要同时报告在应拒场景上的召回率和在正常场景上的误拒率。对高风险字段，可以用严重性加权错误：

```math
R_{\mathrm{severity}}
=\frac{\sum_i s_i\,\mathbf{1}[\mathrm{error}_i]}
{\sum_i s_i}
```

`s_i` 是第 `i` 个错误的业务严重度。一个漏掉药物过敏的样本不应和一个标点错误拥有相同权重。还要报告专家之间的一致性、人工接管率、工具调用延迟和单位成功成本，因为领域系统的质量不只由模型文本决定。

## 15.9 常见失败

把专家风格当专业正确；数据只有正例没有边界；奖励引用格式而不验证内容；知识版本混杂；隐私未脱敏；领域工具权限过宽；平均分掩盖高风险长尾；用模型 judge 代替专家和规则。

这些失败可以按证据链定位：若术语和格式错误，检查 tokenizer、SFT 数据和模板；若事实正确但引用不支持，检查 source span 和版本；若计算正确但动作越权，检查 policy engine 而不是继续训练语言模型；若平均分很好但关键字段召回低，检查采样和分母；若新法规任务提升而旧任务崩溃，检查时间切分、replay 和知识冲突。每类失败都应有单独的回归样本，不能只用总 reward 判断。

## 15.10 从样本结构到可验证闭环

### 15.10.1 一个领域样本为什么要记录“答案之外”的东西

假设任务是根据一份季度财报解释毛利变化。普通问答数据可能只保存问题和答案，但训练一个可用于业务的模型，还需要知道答案引用了哪几张表、使用了哪个财报版本、哪些数字是直接读取、哪些结论是计算得到，以及什么时候必须转交人工。

可以把一条领域样本写成：

```text
sample = {
  input, context, claims, evidence, calculation,
  action, confidence, escalation, knowledge_revision
}
```

`claims` 是原子主张，`evidence` 是来源，`calculation` 保存可复算的中间式，`action` 表示模型可以做什么，`escalation` 表示何时需要人。这样做的直接好处是：训练阶段可以只对答案 token 做 SFT，评估阶段却可以独立验证引用和计算；未来知识库更新时，也能找到受影响的样本。

领域数据中的“专家答案”不是天然真值。两位医生、律师或财务分析师可能在事实相同的情况下选择不同的表达，或者因适用地区、日期和客户身份不同而给出不同动作。标注系统应把争议和条件保留下来，而不是把少数意见静默抹掉。

### 15.10.2 SFT、偏好优化和可验证奖励的分工

SFT 适合教模型领域词汇、格式、流程和工具协议；偏好优化适合让模型在多个合规答案中选择更清楚、更有依据的一种；RLVR 适合结果可以被规则、计算或测试验证的任务。三者不是互相替代的训练开关。

例如金融报表任务可以分成三层：

1. SFT 学会输出收入、成本、汇率和一次性项目四列桥接表；
2. 偏好数据让模型优先选择注明数据期间、假设和不确定性的解释；
3. verifier 检查数字加总、引用版本和敏感字段权限。

如果把三层信号混成一个分数，模型可能为了提高格式分生成漂亮表格，却没有核对数字。训练目标越接近真实成功，奖励越应拆成可诊断的分量。

### 15.10.3 worked example：医疗摘要的三个独立检查

一个医疗摘要系统接收病历片段，输出病情摘要、证据句和待确认事项。第一项检查事实是否能够在输入中找到；第二项检查摘要有没有遗漏药物过敏、时间和严重程度；第三项检查系统是否把诊断建议伪装成医疗决定。三项结果分别记录，不能让格式分数掩盖关键事实或责任边界。

可以将单条样本的质量分数写成：

```math
Q=\alpha Q_{\mathrm{fact}}+\beta Q_{\mathrm{evidence}}
 +\gamma Q_{\mathrm{format}}-\lambda Q_{\mathrm{risk}}
```

在高风险领域，`Q_fact` 和 `Q_risk` 不能被低风险格式分抵消。若事实正确率为 `0.96`，但关键过敏字段召回只有 `0.70`，平均事实分会掩盖最危险的错误。评估应报告 critical-field recall、unsupported claim rate、人工接管率和错误严重度，而不是只有一个总体准确率。

### 15.10.4 专家反馈如何避免变成风格复制

标注指南应要求专家分别填写“事实”“推断”“建议动作”和“仍需确认的信息”。模型可以学习专家的语言风格，但评估器要优先检查事实和边界。对相互冲突的专家意见，保存适用条件和 minority label；对有时间效力的法规、价格和医学指南，保存 source revision 和生效日期。

数据切分也要按时间和实体做隔离。若同一患者、同一合同或同一客户的近重复记录同时出现在训练和测试中，模型可能看似专业，实际只是在记忆实体。敏感领域还应对日志、prompt、工具返回和 checkpoint 做脱敏审计，不能只处理训练集原文。

### 15.10.5 领域后训练的可验证评估表

一个可落地的评估表至少包括：

| 维度 | 最小问题 |
| --- | --- |
| 事实 | 关键字段是否来自正确版本的证据 |
| 推理 | 数字、时间和实体关系能否复算 |
| 引用 | 每个高风险主张是否有支持段落 |
| 流程 | 工具调用和人工升级是否遵守权限 |
| 边界 | 缺证据、冲突和越权请求是否正确处理 |
| 鲁棒性 | 换模板、同义表达和新版本后是否仍成立 |
| 成本 | 单位成功任务的 token、工具和人工成本 |

只有格式通过而事实、边界或权限失败时，系统不能发布。训练阶段得到的能力要在真实业务工作流中重新验证。

## 15.11 面试回答与练习

回答“如何为领域模型做 SFT+RL”时，应从专家数据、来源和版本开始，SFT 教语言/流程/协议，RL 用可验证结果、专家偏好和安全奖励优化；同时做事实、引用、工具、边界和时间切分评估，权限和人工审核不由训练替代。

练习一：为医疗摘要设计 claim/evidence/confidence 标注。

练习二：给一个领域工具设计正确、拒绝、需人工三类奖励。

## 15.12 领域后训练的分布覆盖

领域数据不能只按专家觉得“重要”的案例采样。应按任务频率、风险、难度、用户群、工具状态和错误后果分层，保证训练集和评估集都覆盖常见任务与长尾边界。

设领域任务桶为 i，采样比例为 w_i，验证成功率为 q_i，可以用加权目标观察配方变化：

~~~math
Q_{\mathrm{domain}}=\sum_i w_iq_i,\qquad
\sum_iw_i=1
~~~

提高高风险桶的权重可能降低普通任务平均分，却提高业务安全性。最终配方要由领域评估结果和失败成本决定。

## 15.13 专业数据的三层正确性

领域模型的数据不能只按“问题—答案”收集。第一层是事实正确，例如法规条文、医学术语或代码 API；第二层是过程正确，例如检索、计算、工具调用和引用顺序；第三层是交付正确，例如格式、权限、免责声明和拒答边界。

三层错误的修复方式不同。事实错误需要权威来源和版本；过程错误需要可执行轨迹或 verifier；交付错误需要模板、schema 和安全规则。把它们混成一个 SFT loss，会让模型用流畅语言掩盖事实或权限问题。

## 15.14 领域 RL 的奖励设计

领域强化学习可以把结果奖励、过程奖励和约束奖励分开：

~~~math
R(y)
=R_{\mathrm{outcome}}(y)
+\lambda R_{\mathrm{process}}(y)
-\mu C_{\mathrm{policy}}(y)
~~~

例如代码任务可以检查测试结果，检索任务可以检查引用支持，工具任务可以检查 schema 和副作用；但奖励模型或规则本身都可能有盲点。奖励必须与独立评估集、人工抽检和安全评估配套，不能把可测的格式当成完整专业质量。

## 15.15 领域训练的回归闭环

每次加入专家数据或 RL recipe，都应保留通用能力、领域能力、安全边界、格式和成本五类回归。领域数据过多可能造成通用能力遗忘，领域拒答规则过强可能造成过度拒答，长推理奖励可能增加输出成本。

上线前比较 base、SFT、领域 SFT、偏好优化和 RL 版本，记录每个版本的失败类型、引用、工具执行和单位成功成本。一个领域模型的价值是专业任务成功率，而不是训练 reward 单独升高。

## 15.16 先看训练数据如何进入工程决策

领域专家 SFT 与 RL 的目标不是让模型更像专家，而是让它在专业任务中有依据、可验证、遵守流程并知道边界。专家反馈、结构化 verifier、版本化知识和权限治理要共同成立。

## 15.17 领域任务应先拆成可训练的动作

“让模型懂金融”或“让模型懂医疗”不是可执行的训练目标。更好的拆分方式是把一次专业工作分成动作：

1. 识别任务类型和适用规则。
2. 找到版本正确的证据。
3. 抽取事实和字段。
4. 进行可复算的计算或比较。
5. 生成领域格式的结果。
6. 判断是否需要拒答、升级或人工确认。
7. 在允许的权限内执行工具动作。

不同动作需要不同监督。抽取可以用字段级标签，计算可以用程序 verifier，引用可以用 source span，权限和副作用必须由 policy engine 控制。把这些都压成一个自然语言答案，会让训练信号无法定位错误。

## 15.18 SFT 的 token 监督不等于任务监督

标准 SFT loss 是对目标 token 做交叉熵，但专业任务真正关心的是 claim、evidence、calculation 和 action。可以只对答案字段做 token loss，同时在 batch 外计算结构化指标：

~~~math
L_{\mathrm{train}}
=L_{\mathrm{token}}
+\lambda_1 L_{\mathrm{field}}
+\lambda_2 L_{\mathrm{citation}}
+\lambda_3 L_{\mathrm{format}}.
~~~

这些项不必都反向传播。关键是把“模型说得像”和“任务完成了”分开记录。一个模型可能 token loss 下降，却把日期、单位或适用地区写错；字段级评估能更早暴露这种问题。

数据集还要明确 loss mask。用户问题、检索文档、工具 observation 通常不应被当成目标答案训练；模型生成的引用、结构化字段和拒答理由是否计算 loss，要按任务目标决定。mask 错误会让模型学习复述上下文或泄露标注辅助字段。

## 15.19 专家分歧是信息，不是噪声

领域专家的不同答案可能来自事实错误，也可能来自法规版本、地区、客户身份或风险偏好不同。标注系统可以把分歧拆成：

| 分歧类型 | 数据处理 |
| --- | --- |
| 事实分歧 | 回到权威来源或标为争议 |
| 适用条件不同 | 显式记录条件和版本 |
| 表达风格不同 | 作为偏好数据，不当作真值 |
| 风险阈值不同 | 记录 policy 和审批等级 |
| 信息不足 | 训练澄清、拒答或升级 |

简单多数投票会把少数但关键的安全条件抹掉。训练样本可以同时保存 accepted answer、alternative answers、disagreement reason 和 adjudication source。模型学到的应是“在什么条件下选哪个答案”，而不是盲目模仿多数人的语气。

## 15.20 领域 RL 的策略边界

领域 RL 的奖励通常包含正确性、证据、格式、流程和风险项：

~~~math
R(\tau)
=w_cR_{\mathrm{correct}}
+w_eR_{\mathrm{evidence}}
+w_fR_{\mathrm{format}}
+w_pR_{\mathrm{process}}
-w_rR_{\mathrm{risk}}.
~~~

重要的是奖励项之间有层级。越权、隐私泄露和未经授权的写操作应是硬性条件，而不是一个可以被高正确率抵消的小负分。可接受的奖励结构更接近：

~~~math
D_{\mathrm{release}}(\tau)
=\prod_{j\in\mathcal{C}_{\mathrm{hard}}}
\mathbf 1[c_j(\tau)=1],
\qquad
R_{\mathrm{soft}}(\tau)
\text{ ranks only trajectories with }D_{\mathrm{release}}=1.
~~~

先过滤不合规轨迹，再在合规集合内比较表达质量和效率，通常比把所有目标线性相加更安全。

## 15.21 领域 verifier 的组合

一个专业任务往往需要多个 verifier：

1. schema verifier：字段、类型和单位正确。
2. source verifier：claim 能在指定版本来源中找到。
3. calculation verifier：中间式和结果可复算。
4. policy verifier：动作符合用户和工具权限。
5. domain reviewer：开放性判断和例外条件通过专家抽检。

让一个语言模型 judge 单独承担五项职责，会同时引入事实偏差、权限盲区和版本漂移。verifier 结果要保存 revision、输入、超时和失败原因，才能作为训练信号和回归证据。

## 15.22 数据刷新和灾难性遗忘

领域知识会更新。增量训练不能只追加新资料，还要处理旧知识的失效、冲突和保留范围。一个版本化数据流可以是：

~~~text
source revision
  -> changed claims
  -> affected examples
  -> SFT/RL mixture
  -> regression
  -> canary
  -> release or rollback
~~~

评估要有时间切分：旧版本训练、新版本测试；新旧版本冲突；知识撤销；缺失证据；用户权限变化。若模型仍输出旧规则，错误不一定来自推理能力，可能是训练数据和检索 freshness 没有同步。

## 15.23 一个可复现的金融训练流水线

以毛利分析为例，数据可按以下步骤构造：

1. 保存财报 revision 和表格来源。
2. 抽取收入、成本、汇率和一次性项目。
3. 生成含中间计算式的专家演示。
4. 构造数字冲突、缺失字段和旧版本样本。
5. 用 SFT 学会结构化桥接表。
6. 用计算和引用 verifier 过滤候选。
7. 在合规候选中做偏好或 RL 排序。
8. 用时间切分和专家抽样评估。

评估不只看解释是否流畅，还要检查加总、单位、时间范围、引用和“不确定”字段。模型没有权限提交财务系统；提交动作必须走独立 policy 和人工审批。

## 15.24 领域模型的成本账

领域 RL 的成本包括专家标注、教师或 verifier 调用、长上下文、工具执行和人工复核。单位成功任务成本可以写成：

~~~math
C_{\mathrm{success}}
=\frac{
C_{\mathrm{training}}
+C_{\mathrm{inference}}
+C_{\mathrm{tool}}
+C_{\mathrm{review}}
}{
N_{\mathrm{successful\ tasks}}
}.
~~~

如果训练后平均答案更长、工具调用更多、人工复核率上升，模型 reward 提高也不代表业务成本下降。高价值任务可以接受更高成本，但必须有明确的质量和风险收益。

## 15.25 从领域任务到训练样本：先固定工作流再写答案

领域数据最容易犯的错误，是把一批专业文本改写成“更像专家说话”的问答。这样的数据可以改变措辞，却未必改变任务能力。一个真实的领域任务通常包含输入证据、约束条件、中间计算、结论、引用和后续动作。训练样本应把这些对象显式分开，而不是把它们揉成一段漂亮的回答。

例如，金融风控样本可以抽象成：

| 字段 | 内容 | 训练时的作用 |
| --- | --- | --- |
| `evidence` | 交易、合同和时间窗口 | 约束模型不能凭空补事实 |
| `question` | 判断风险等级并给出依据 | 定义任务目标 |
| `calculation` | 比率、阈值和单位换算 | 允许 verifier 独立复算 |
| `decision` | 通过、人工复核或拒绝 | 连接业务动作 |
| `uncertainty` | 缺失字段和冲突证据 | 训练适当保留未知 |

小白可以把它理解为“答案旁边必须放着答题过程和判卷规则”。面向专家时，要进一步区分 observation、inference 和 action：模型从输入中读到的事实不是模型推断出的风险，也不是已经执行的业务动作。若数据没有这层边界，后训练可能奖励“说得像已经查过系统”的幻觉。

可以为一条样本定义结构化损失：

```math
\mathcal{L}
=\lambda_{\mathrm{text}}\mathcal{L}_{\mathrm{text}}
+\lambda_{\mathrm{evidence}}\mathcal{L}_{\mathrm{evidence}}
+\lambda_{\mathrm{calc}}\mathcal{L}_{\mathrm{calc}}
+\lambda_{\mathrm{action}}\mathcal{L}_{\mathrm{action}}.
```

这不是要求训练时一定使用四个独立 head，而是提醒我们：如果只对最终文本算 loss，就很难知道模型究竟错在事实、计算、决策还是表达。工程上可以先用普通 SFT 训练格式，再用规则、程序和人工复核分别评测这四类行为。

## 15.26 一个领域后训练的反事实实验

假设有一千条历史审批记录，其中一半来自旧政策。直接把全部记录混在一起训练，模型可能学会“历史上经常这样做”，却不知道政策已经变更。更有信息量的实验不是继续堆数据，而是构造三组对照：只用旧政策、旧政策加新政策、只用新政策并保留旧任务的回归集。

每组都在四类数据上测试：旧政策任务、新政策任务、跨时间组合任务和缺字段任务。若第二组在新政策上提高但旧政策任务全面退化，说明数据刷新带来了灾难性遗忘；若只用新政策的模型在缺字段任务上仍然自信作答，说明不确定性和拒答信号没有被学到。

领域 RL 还要把动作模拟器隔离出来。模型可以提出“冻结账户”的建议，但训练环境不应直接连接生产账户。只有模拟器返回可验证结果、策略检查通过、并且动作是幂等的，轨迹才可作为探索数据。真实生产数据可以帮助评估分布，却不应因为“反馈最真实”就成为无保护的探索场。

## 15.27 发布条件：能力提升和风险上升必须同时记录

领域模型发布至少需要两张表。第一张是能力表，记录任务成功率、证据引用、计算准确率、格式通过率和人工复核一致性；第二张是风险表，记录敏感信息泄露、越权建议、过期知识、拒答错误、工具副作用和单位成功成本。只有第一张表上升，不能证明模型适合上线。

一个简单的发布决策表达可以写成：

```math
D_{\mathrm{release}}
=\mathbf{1}[Q\ge Q_{\min}]
\mathbf{1}[R\le R_{\max}]
\mathbf{1}[C\le C_{\max}]
\mathbf{1}[P=1],
```

其中 `Q` 是独立任务质量，`R` 是严重性加权风险，`C` 是单位成功任务成本，`P` 表示协议、权限和回滚测试全部通过，`D_release` 是发布决策的诊断量。乘法形式表达的是硬性条件：不能用平均质量抵消一次越权写入，也不能用低价格抵消不可审计的错误结论。

## 15.28 小结

领域 SFT 与 RL 的对象不是“专业口吻”，而是专业工作流中的事实、证据、计算、动作和边界。训练信号要分解，verifier 要版本化，知识要按时间更新，权限和副作用不能交给模型奖励代替。只有在独立专家、规则和真实工作流评估中都成立，领域后训练才算完成。

这些资料支持方法来源、训练范式和治理概念，不能替代医学、法律或金融场景的领域授权、专家审核和生产 policy。论文里的 reward、数据规模和成功率也不能直接迁移到另一个领域；迁移前必须重新验证证据版本、任务分布、工具副作用和单位成功成本。
