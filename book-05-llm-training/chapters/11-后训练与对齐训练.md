# 第十一章：后训练与对齐训练：从会续写到可靠协作

预训练完成后，模型通常已经学会了如何根据上文预测下一个 token，也从大规模语料中获得了许多知识和表达模式。但“会续写”与“能作为助手工作”之间还有一段距离：模型可能把用户的问题继续写成另一段文章，可能不遵守输出格式，也可能在危险请求、工具调用或多轮上下文中做出不合适的选择。

后训练处理的正是这段距离。它不是一个单独的算法名称，而是一组训练阶段和反馈信号的组合：示范数据告诉模型应该怎样回答，偏好数据告诉模型两个回答哪个更好，规则或程序验证器告诉模型答案是否正确，安全数据和回归集则帮助我们观察新行为有没有破坏旧能力。

对初学者来说，可以把它想成驾驶训练。SFT 像教练先给出一条条正确示范；偏好优化像让教练在两条路线中指出哪条更好；在线强化学习则让学员自己上路，按照到达目的地、遵守交通规则和乘坐体验获得反馈。它们解决的问题不同，不能因为都在“调模型”就混为一谈。

对专家来说，更重要的是辨认反馈信号与采样分布。离线偏好优化只看到数据集里已经存在的 chosen/rejected；在线 RL 会从当前 policy 的真实分布采样；RLVR 依赖数学答案、代码测试或工具执行等外部验证。方法名称只是实现层标签，真正决定训练行为的是数据、reward、reference policy、更新粒度、长度处理和评估闭环。

过去常见的简化路线是：

```text
SFT -> RLHF/PPO -> DPO
```

它适合用来记忆历史，但不能代表今天所有系统。一个更接近工程现实的路线图是：

```text
SFT / cold start
-> reward modeling / rule-based reward / verifiable reward
-> online RL or offline preference optimization
-> long-CoT / reasoning RL
-> safety and behavior alignment
-> regression evaluation and iterative data refresh
```

这张图不是固定流水线。资源有限、目标是通用聊天时，SFT 加小规模离线偏好优化可能已经足够；任务具有可验证答案且需要探索新解法时，在线 RLVR 更有价值；安全、格式和工具约束则可能贯穿多个阶段，而不是最后再补一层 loss。本章依次拆开这些方法，说明每个方法的输入、目标、代价、适用边界和失败模式。

## 为什么后训练是模型变成助手的关键阶段

预训练得到的 base model 主要学到的是语言建模能力。

它知道很多文本模式、知识模式和推理模式，但通常还不适合直接面对用户。

原因包括：

1. 不一定遵循指令。
2. 不一定会拒答危险请求。
3. 不一定知道输出格式要求。
4. 不一定会优先给出帮助性、简洁性和安全性兼顾的回答。
5. 不一定会根据反馈持续改善。

后训练的目标是把 base model 变成 assistant model 或 reasoning model。

可以这样建立分工直觉：预训练主要让模型获得语言和知识的建模能力，后训练则把这种能力塑造成可遵循、可评估、可约束的交互行为。但这不是严格的能力边界，预训练数据、模型架构和后训练数据会共同影响最终结果；后训练也可能强化推理、工具使用和领域知识，而不只是改变说话风格。

### 后训练与对齐训练的资料边界

本章用综述建立后训练地图，再用 InstructGPT、DPO、DeepSeekMath、DAPO、DrGRPO、GSPO、DCPO，以及 DHPO、GAPO 等原始研究核对方法；后两者是早期预印本候选。再用 Anthropic、OpenAI、Z.ai、xAI 的公开资料核对案例披露，并参考 TRL 文档理解训练器接口。不同资料承担不同证据角色：综述帮助分类，论文支持目标和实验结论，官方文档支持发布方公开的做法，框架文档支持具体版本的接口；它们不能互相替代。产品中的 `reasoning effort`、`thinking level` 等运行时字段也不能反推出训练算法。

本章聚焦后训练的三类问题：反馈从哪里来、策略如何更新、整套训练如何组织。正文把 SFT、reward model、PPO-RLHF、DPO/SimPO 等离线偏好方法、GRPO/RLVR、GSPO、DAPO、DrGRPO、DCPO，以及 DHPO/GAPO 早期候选、安全行为和回归评估放到同一条因果链上。长篇 verifier 设计、领域专家训练、OPD 和具体模型配方分别见本册[第十六章](16-rlvr与可验证奖励.md)、[第十五章](15-领域专家sft与rl.md)、[第十七章](17-on-policy-distillation.md)和[第十八章](18-deepseek-v4领域专家与统一蒸馏.md)。

### 后训练目标的统一口径

后训练可以抽象成在初始 policy `pi_0` 上学习新 policy `pi_theta`：

```math
\pi_{\theta}
=
\mathrm{PostTrain}(\pi_0,D_{\mathrm{sft}},D_{\mathrm{pref}},R,C_{\mathrm{safe}})
```

其中 `D_sft` 是监督示范数据，`D_pref` 是偏好数据，`R` 可以是 reward model、规则验证器或环境反馈，`C_safe` 是安全与行为约束的集合。不同路线可以不使用其中某一项：纯 SFT 不需要偏好数据，DPO 不需要在线 reward model，RLVR 则把程序或环境当作主要反馈来源。

最终结果也不适合压缩成一个“对齐分数”。更有解释力的记录是：

```math
E_{\mathrm{align}}=
(E_{\mathrm{follow}},E_{\mathrm{pref}},E_{\mathrm{reward}},
E_{\mathrm{drift}},E_{\mathrm{safety}},E_{\mathrm{regression}})
```

这六个分量分别描述指令遵循、偏好质量、反馈信号是否可靠、policy 相对参考模型的偏移、安全边界和旧能力回归。它们是需要分别观察的证据维度，不是相乘后得到的真假结论；例如偏好胜率上升而安全召回下降时，应该保留这两个相反的事实，而不是让一个总分把退化抵消掉。

## 1. 后训练总体流程

一个典型 LLM 后训练流程可以拆成六层。

### 1.1 SFT：建立基本指令遵循能力

SFT 使用人工或模型生成的高质量 instruction-response 数据，让模型学会按照用户指令回答。

它解决的问题是：

```text
base model 只会续写，不一定会按用户意图回答。
```

SFT 的目标通常是 next-token cross entropy：

```text
max log p_theta(y | x)
```

其中 `x` 是 prompt，`y` 是示范回答。

在最常见的 instruction SFT 中，监督重点放在 assistant token。设 `m_t=1` 表示第 `t` 个 token 属于当前任务要求模型生成的输出：

```math
L_{\mathrm{sft}}=
-
\frac{
\sum_{i,t}m_{i,t}\log \pi_{\theta}(y_{i,t}\mid x_i,y_{i,<t})
}{
\sum_{i,t}m_{i,t}
}
```

这个式子有一个不能省略的前提：`\sum_{i,t}m_{i,t}>0`。每个被 mask 选中的位置都必须有一个合法的目标 token，且模型在该位置给出的条件概率为正，才能取对数。一个 batch 恰好没有 assistant token，不是“loss 等于 0”的成功样本，而是数据拼接、模板、截断或 mask 配置需要排查的信号；训练循环应跳过它或显式报错，并把计数记录下来。对混合任务，分母还应与所声称的监督单位一致：按 token 平均、按 response 平均和按样本平均会给长短回答不同权重，不能在训练和报表中混用。

用两 token 回答手算一次：目标 token 的概率分别为 0.8 和 0.5，且两处都被 assistant mask 选中，则 loss 为 `−(ln 0.8+ln 0.5)/2=−(−0.2231−0.6931)/2≈0.4581` nat。即使 prompt 里另有四个 token，它们也不进入这个监督均值；分母是两个目标 token，而不是整条序列的六个 token。若 mask 全零，分母变成 0，不能把这条样本报成零损失。

如果任务只想训练回答，却把 user prompt 或 padding 也算进分母，模型会被迫学习复制输入或预测填充符。另一方面，tool result、系统消息和多轮 assistant 历史是否计入监督，要由任务定义决定：工具调用格式通常需要监督，外部工具返回的事实文本却可能只应作为条件输入。assistant-only mask 是常见做法，不是脱离数据协议的普遍定律；真正要检查的是 mask 与训练目标是否一致。

还要明确 EOS 的角色。把 EOS 作为回答末尾的目标 token，有助于模型学习何时结束；但 EOS 本身不会自动阻断后续文档的 attention，也不会替代样本边界、packing mask 和 loss mask。一个看似格式正确的 SFT batch，仍可能在跨样本拼接处泄漏上下文或错误累计 loss。

SFT 的优点是简单稳定。

缺点是它主要模仿数据分布，不会主动优化“哪个回答更好”。如果示范数据覆盖不足，SFT 还可能把示范中的冗长风格、拒答习惯或工具错误一并学进去；后续偏好数据和回归集的作用，就是把这些行为差异显式暴露出来。

### 1.2 Reward Modeling：学习偏好信号

Reward Model 使用偏好数据训练一个打分模型。

偏好数据通常长这样：

```text
prompt
chosen response
rejected response
```

Reward Model 学的是：

```text
r(prompt, chosen) > r(prompt, rejected)
```

常见 reward model 训练可以用 Bradley-Terry 形式理解。对偏好样本 `(x,y^+,y^-)`：

```math
P(y^+\succ y^-\mid x)=
\sigma(r_{\phi}(x,y^+)-r_{\phi}(x,y^-))
```

对应 loss 为：

```math
L_{\mathrm{rm}}=
-
\log
\sigma(r_{\phi}(x,y^+)-r_{\phi}(x,y^-))
```

假设某 prompt 的 reward model 对 chosen 和 rejected 分别给出 0.4 与 0.0，分数差为 0.4；偏好概率是 `σ(0.4)≈0.5987`，单对 logistic loss 为 `−ln(0.5987)≈0.5130` nat。分数差变大时，模型认为 chosen 更受偏好的概率上升、loss 下降；这只说明模型更符合训练偏好标签，仍需在保留偏好对和真实任务上检查排序是否可靠。

这个目标默认 chosen 和 rejected 都是同一 prompt 下的非空、可比较回答，`r_\phi` 的输入和输出都是有限数。若偏好是平局、标签冲突，或某一侧在模板截断后没有 response token，就不能把它硬塞进二元 Bradley--Terry loss；可以使用带平局标签的目标、重新标注，或从该批训练中移除并保留原因。数值实现还应使用稳定的 `logsigmoid` / `softplus`，而不是先计算可能下溢为零的 sigmoid 再取对数。

这里的 `r_phi` 首先是一个用于排序的分数，并不天然是跨 prompt 可比较的“真实效用”。如果标注者在不同任务上使用了不同标准，或者 chosen 总是比 rejected 更长，reward model 可能学到长度、格式或表面词汇等捷径。训练前应检查标签一致性、平局样本、prompt 分布和 chosen/rejected 的长度差；训练后还应在未参与训练的偏好对和真实任务上验证排序是否成立。

它解决的问题是：

```text
如何把人类偏好变成可优化的标量 reward。
```

### 1.3 RLHF：用 RL 优化策略模型

有了 reward 后，可以把语言模型看作 policy。

模型生成回答，reward model 给分，训练算法更新 policy，使它更倾向于生成高 reward 回答。

经典路线是 PPO-RLHF。

PPO 还要区分采样时的旧 policy 和正在更新的 policy。设 `pi_old` 是生成 rollout 的策略，`A_t` 是第 `t` 个 token 或时间步的 advantage，概率比为：

```math
\rho_t(\theta)=
\frac{\pi_{\theta}(a_t\mid s_t)}
{\pi_{\mathrm{old}}(a_t\mid s_t)}
```

其 clipped surrogate 常写成：

```math
L_{\mathrm{clip}}(\theta)=
-\mathbb{E}_t\left[
\min\left(
\rho_t(\theta)A_t,
\mathrm{clip}(\rho_t(\theta),1-\epsilon,1+\epsilon)A_t
\right)
\right]
```

例如旧 policy 给已采样 token 的概率为 0.20，新 policy 为 0.25，则 `ρ=0.25/0.20=1.25`。设正 advantage `A=0.6`、`ε=0.2`，clip 后比率是 1.2；未裁剪项为 `1.25×0.6=0.75`，裁剪项为 `1.2×0.6=0.72`，取较小值 0.72。若 `A=−0.6`，两个值分别为 −0.75 和 −0.72，仍取较小值 −0.75。这个符号差异说明 PPO 的 clip 是代理目标的一部分，不能简单理解为把任何超界 ratio 硬夹回区间。

这里要求 `\pi_{\mathrm{old}}(a_t\mid s_t)>0`，新旧 policy 使用相同的动作空间和 tokenizer，`A_t` 为有限数，且 `0<\epsilon<1`。实际实现通常在 log-probability 空间计算 `\log\rho_t`，再以稳定方式得到 ratio；如果旧 policy 从未给该 token 正概率，重要性采样比没有定义，不能用一个很小的常数代替后继续更新。

实际 RLHF 还要估计 value、处理 reward normalization、长度和 KL 统计，并在 batch、sequence、token 三种粒度之间保持口径一致。把 PPO 只写成“reward 减 KL”有助于理解方向，却不能替代这些实现细节。

### 1.4 Offline Preference Optimization：离线偏好优化

DPO、IPO、KTO、ORPO 等方法不一定显式训练 reward model，也不一定在线 rollout。

它们直接用偏好对优化模型。

优点是工程简单、稳定、成本低。

缺点是受限于离线偏好数据，对复杂 reasoning、长链条探索和 verifiable reward 场景不一定够。

### 1.5 Reasoning RL：面向可验证任务的强化训练

数学、代码、逻辑推理、工具调用等任务可以用规则或程序验证答案。

例如：

```text
数学题答案是否正确
代码是否通过单元测试
工具调用结果是否满足目标
```

这类任务可以使用 rule-based reward 或 verifiable reward，进行在线采样和 RL 优化。RLVR 描述的是反馈来源和任务族：验证器能否判断答案或行为是否满足任务契约。它本身不规定采用 PPO、GRPO 还是其他更新式；“有 verifier”也不代表 verifier 正确、覆盖充分或难以被投机。

GRPO、DAPO、GSPO、DCPO 等方法通常出现在这一类讨论中。近年很多资料会把这条路线称为 RLVR，也就是 reinforcement learning with verifiable rewards：核心不是让人或 reward model 主观打分，而是用数学答案、代码测试、工具执行结果、格式校验或环境反馈给出可验证 reward。

### 1.6 Safety Alignment：安全与行为边界

后训练还必须控制：

```text
危险请求
隐私泄露
越狱
偏见
过度拒答
事实幻觉
工具误用
```

安全反馈也有来源差异。RLHF 使用人工偏好；RLAIF 使用模型生成的偏好或评分；[Constitutional AI](https://arxiv.org/abs/2212.08073) 的公开路线先让模型按原则自我批评并修订回答，再让 AI 比较回答、训练偏好模型并用 RL 优化。它减少了逐条人工标注需求，但把一部分误差转移到原则覆盖、AI judge 偏差和模型间相关错误上，不能据此推出 AI feedback 在所有风险领域都与人类判断等价。

因此，安全对齐不是单独一个 loss 就能解决，而是数据、reward、拒答策略、工具权限、红队评估和发布前后的行为评估共同作用。评估时至少分别统计危险请求的错误服从与无害请求的错误拒答；安全召回提高但过度拒答也上升，不能称为无条件改进。

## 2. 方法谱系总览

先把三个经常混在一起的层次拆开。综述通常把后训练放在 SFT、feedback-based RL 和 test-time compute（TTC）等大类中；在具体工程讨论里，还要把“反馈信号”“更新算法”和“训练配方/系统”分开，否则会把 RLVR、GRPO、DAPO 当成同一层级的互斥算法。

| 层次 | 它回答的问题 | 代表概念 | 不能据此推出什么 |
|---|---|---|---|
| 反馈与任务 | 什么被视为更好的输出，反馈由谁或什么产生？ | 人类偏好、RLAIF、规则/程序 verifier、环境结果；RLHF、RLAIF、RLVR 是常见路线称呼 | 不决定 policy 用哪一个优化器，也不保证评分可靠 |
| 更新目标/算法 | 有了示范、偏好或 reward 后，参数怎样更新？ | SFT、PPO、DPO、IPO、KTO、ORPO、SimPO、GRPO、GSPO | 不决定 reward 来自人、模型还是程序 |
| 训练配方/系统 | 数据、采样、过滤、更新、基础设施和阶段怎样组合？ | DAPO 的组合式方法与开源系统；DeepSeek-R1 的多阶段训练；具体厂商训练系统 | 不能把整套配方的收益归因于其中一个 loss |
| 推理时计算 | 请求到来后再投入多少生成、搜索或验证计算？ | best-of-N、self-consistency、reasoning effort、TTC | 不是训练期的 policy optimization 算法 |

下表只比较常见的更新路线。表中“在线采样”指训练过程中是否需要从当前/行为 policy 生成 rollout；不等同于偏好数据是否由模型生成。

| 更新方法 | 输入反馈 | 是否需要在线 rollout | Critic / 独立 RM | 主要问题 |
|---|---|---|---|---|
| SFT | 目标回答 token | 否 | 无独立 RM；无 critic | 用示范建立可遵循的行为和格式 |
| PPO | reward model 或规则 reward | 是 | 经典 PPO-RLHF 通常有 critic；RM 可选于规则 reward 路线 | 在线优化 reward，同时控制策略更新 |
| DPO | chosen / rejected 偏好对 | 否 | 无 | 把 KL 约束偏好目标重写为 policy 的分类损失 |
| IPO / KTO / ORPO / SimPO | 成对偏好或二元好坏标签，依方法而异 | 否 | 方法相关；KTO 使用 reference，ORPO/SimPO 不依赖 reference | 改变偏好目标、标注形态或 reference 依赖 |
| GRPO | 同 prompt 多条 rollout 的组内 reward | 是 | 通常不需要独立 critic | 用组内相对信号估计 advantage |
| GSPO | 同 prompt 多条 rollout 的组内 reward | 是 | 通常不需要独立 critic | 把重要性比率与 clipping 的单位改为序列 |
| DrGRPO / DCPO | 可验证 reward 等在线信号 | 是 | 通常不需要独立 critic | 分别调整长度/标准差归一化与动态 clipping/advantage 统计 |

注意：DAPO 放在“配方/系统”层，是因为其论文同时组合 Clip-Higher、dynamic sampling、token-level loss 和 overlong reward shaping；其中可以拆出具体更新机制，但最终报告值属于整套 recipe 和系统。比较任何两种方法时，都要同时核对 reward、采样 policy、重要性比率粒度、loss reduction、reference/KL、最大响应长度和评测协议。

## 3. PPO-RLHF

PPO 是早期 RLHF 的代表方法。

整体流程如下：

```text
1. 用 SFT 得到初始 policy model。
2. 训练 reward model。
3. policy model 对 prompt 采样回答。
4. reward model 给回答打分。
5. PPO 根据 reward 更新 policy。
6. 使用 KL penalty 防止 policy 偏离 reference model 太远。
```

这条历史路线里至少有五个不同对象，不能把它们都叫“参考模型”：

| 符号/对象 | PPO-RLHF 中的职责 | 常见生命周期 |
|---|---|---|
| 当前 policy `\pi_\theta` | 被优化的模型 | 每次 optimizer step 都变化 |
| rollout policy `\pi_{old}` | 生成当前一批回答，并作为 PPO ratio 的分母 | 收集一批 rollout 后冻结；更新到设定步数后刷新 |
| reference policy `\pi_{ref}` | 通常是冻结的 SFT policy，提供 KL 锚点 | 在该轮对齐训练中通常不更新 |
| reward model `r_\phi` | 对完整回答给出偏好代理分数 | 单独训练后冻结或按特定流程更新 |
| value/critic `V_\psi` | 估计状态价值，帮助构造 advantage | 与 policy 一起或交替训练 |

`\pi_{old}` 与 `\pi_{ref}` 的用途不同：前者处理“这条 rollout 来自哪个策略、更新后概率变化了多少”，后者处理“新 policy 离初始行为分布多远”。即使某次实现让两者权重相同，它们的计算角色仍然不同。规则 reward 的 PPO 可以没有独立 reward model；一些变体也会省略或改变 critic，因此上表描述的是经典 RLHF 配方，不是所有 PPO 系统的硬性组件清单。

PPO 的目标大致可以理解为：

```text
maximize reward(response) - beta * KL(policy || reference)
```

其中 KL 项非常重要。

如果把一条采样到的 response 记为 `y=(y_1,\ldots,y_T)`，下面这个量是 sequence-level KL 的单条样本 log-ratio 估计：

```math
\widehat{\mathrm{KL}}_{\mathrm{seq}}(x,y)
=
\sum_{t=1}^{T}
\left[
\log \pi_{\theta}(y_t\mid x,y_{1:t-1})
-
\log \pi_{\mathrm{ref}}(y_t\mid x,y_{1:t-1})
\right]
```

它是 KL 的单样本 Monte Carlo 项，而不是每条回答都非负的“KL 值”：单条 log-ratio 可以为负，只有在与 `y\sim\pi_\theta` 的期望配合、且两个分布定义在同一支持集上时，才对应 `D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}})`。因此日志中应分别保存 token/sequence、求和/均值的统计口径和长度分布；仅看一个正负号不能诊断 policy 是否漂移。

RLHF 的简化目标是：

```math
J_{\mathrm{rlhf}}=
E_{y\sim \pi_{\theta}}
\left[
r_{\phi}(x,y)
-
\beta\widehat{\mathrm{KL}}_{\mathrm{seq}}(x,y)
\right]
```

PPO 实际训练还会使用 ratio clipping、advantage 和 value / critic 估计。理解时先抓住两个核心：策略在采样分布上最大化 reward，同时用 KL 或其他约束限制 policy 漂移；之后再根据实现核对 clipping、value loss、采样长度和统计分母。

把一条三 token 回答走完，可以看清完整 reward 如何变成逐 token 更新信号。设 reward model 在回答结束时给 1.50 分，KL 惩罚系数 `β=0.1`，三个 token 的当前策略相对 reference 的 log-ratio 样本项假设为 `[0.10,0.20,0.30]`。按每 token `−β log(πθ/πref)` shaping 后，奖励为 `[-0.01,-0.02,1.47]`：前两项只有 KL 惩罚，末项把 1.50 的终局分数加到 −0.03 上。这里的 log-ratio 是单轨迹估计，单项可以为负；1.50、三个比值和 `β` 都是教学输入，不代表 InstructGPT 或任一生产 recipe 的超参数。

critic 为三个前缀状态给出的价值假设为 `[0.20,0.30,0.40]`，终止状态价值为 0。取 `γ=0.99`，一步 TD residual `δ_t=r_t+γV_{t+1}−V_t` 依次为 `−0.01+0.99×0.30−0.20=0.087`、`−0.02+0.99×0.40−0.30=0.076`、`1.47−0.40=1.07`。再取 GAE 参数 `λ=0.95`，从回答末尾反向算：`A_3=1.07`，`A_2=0.076+0.99×0.95×1.07≈1.0823`，`A_1=0.087+0.99×0.95×1.0823≈1.1050`。终局 reward 因而能经折扣的 TD residual 影响较早 token；critic 负责估计前缀价值，不能把它误认为另一个 reward model。

GAE 的 `γ` 控制远期回报权重，`λ` 在低方差的 TD 估计与高方差的完整蒙特卡洛回报之间折中。上面的数值只演示递推顺序；真实系统会根据 EOS、padding、截断和终止状态为每个 token 定义 mask，并使用批内 return 训练 critic。若把 padding 位置放进递推，或把因长度上限截断的回答误当成自然终止，后续 token 的回报会被错误归零。调试时要同时看 reward 的终点定义、value target、advantage 均值/方差和长度分桶。

常见 PPO 训练器还会把策略项、critic 回归项和熵正则组合起来。以最小化损失为记号，可以写成 `L_total=L_clip+c_v L_value−c_H H`：`L_value` 对有效 token 的 value prediction 与 return target 做平方误差，`H` 是策略熵，`c_v,c_H` 是非负权重。若某个状态的 value 预测为 0.4、target 为 1.0，则单项平方误差按 `0.5(1.0−0.4)^2=0.18`；取教学权重 `c_v=0.5`，它贡献 0.09。若该批平均熵为 0.8 nat、`c_H=0.02`，熵项在 loss 中贡献 `−0.016`，鼓励策略保留一定探索。值函数过重会压过策略更新，熵系数过低可能过早收缩输出分布；这些数值仅说明项的量纲和方向，不是推荐系数。

把这组数据放进训练器时，每条 rollout 至少要保留 prompt/response token、response mask、旧 policy log probability、value 预测、终止/截断标记和最终 reward。reference 与 reward model 在经典配方中通常冻结，分别提供偏移锚点和偏好分数；critic 用回报 target 训练，policy 则用 clipped surrogate 更新。这里的组件可以由共享骨干或分离模型实现，但其张量与生命周期仍要能区分。InstructGPT 报告把示范 SFT、偏好比较训练 reward model、再用 PPO 优化策略串成公开的 RLHF 路线；这证明该工程组合曾在其人类偏好任务中应用，不意味着所有现代后训练都必须保留同一套模型布局。[InstructGPT 技术报告](https://arxiv.org/abs/2203.02155)

critic 的价值不是替 reward model 判断回答好坏，而是估计“从当前前缀继续生成的预期回报”，让最终序列 reward 能转换成低方差的 token advantage。若 critic 对某类长回答系统性高估，`δ_t` 会偏负，后续即使完整回答拿到高 reward，早期 token 也可能被压低；若 critic 跟不上新 policy，GAE residual 会整体变大，训练噪声和梯度尺度都会改变。因此需要对照 value target 与 prediction、按 response 长度和 reward 切片看 explained variance，并在策略变化后重新检查 critic 校准。

一次 PPO update 使用同一批 rollout 时，`π_old` 应冻结为采样权重快照，policy 可以在这批数据上做有限轮 minibatch epoch；每轮后都要看 ratio 的中位数和尾部、clip fraction、policy/reference KL、entropy、critic explained variance 及 reward。若复用太多 epoch，ratio 偏离 1 的样本和被 clip 的比例会增加，训练器不一定报错，却可能让实际目标逐渐偏离采样分布。把 KL 单样本惩罚、批均值 KL 与 PPO approximate KL 混成一个字段，会掩盖 reference 漂移和相邻 policy 更新过大的不同问题。

裁剪的 `min` 还会按 advantage 正负选择不同分支。设旧 policy 对某个 token 的概率是 0.25，新 policy 是 0.35，ratio `ρ=1.4`，`ε=0.2`。当 `A=0.5` 时，未裁剪项为 0.70、裁剪项为 `1.2×0.5=0.60`，目标取 0.60，限制继续增大该动作的代理收益；若 `A=−0.5`，两项分别为 −0.70 和 −0.60，取更小的 −0.70。clip 不是把 ratio 硬写回 1.2，也不是把更新后的模型投影到某个概率区间；它只改变这一批采样数据上的 surrogate。因为 token 概率受共享参数耦合，optimizer step 后其他状态的 ratio 也可能变化，仍需监控 KL 和 ratio 尾部。

如果没有 KL 约束，模型可能为了骗 reward model 而生成奇怪回答，也就是 reward hacking。

`β` 决定同一 reward 增益要用多少分布偏移来交换。假设两条回答的 RM 分数都为 1.50，但某条相对 reference 的估计 KL 为 0.40 nat，则取 `β=0.1` 时简化效用是 `1.50−0.1×0.40=1.46`，取 `β=1` 时则是 `1.10`。这不是完整 PPO 更新，只展示 KL 约束怎样改变候选排序；实际 KL 还取决于长度、token/sequence 汇总、采样分布和 reference。若只盯着 RM 平均分，调大 `β` 可能让答案更像 reference，却也可能压住有用的新行为；应同时对照独立偏好、能力回归、KL 分布和输出多样性。

RM 的分数刻度也依赖它训练时看到的 prompt、回答和标注者，不是跨任务统一单位。若同一个 reward model 对聊天回答和代码解释使用不同尺度，固定 `β` 可能让某一类样本主导总目标；对 response 长度越长的样本，若 KL 按 token 求和，惩罚也可能更大。上线前要分任务画出 reward 与 KL 的联合分布，查明约束是否主要由长度或任务类别决定；必要时分组校准 reward、明确 KL 的求和/均值口径，不能把 `β` 当作可跨模型复制的常数。

PPO 的优点：

1. 能在线采样，优化当前模型真实生成分布。
2. 可以直接使用 reward model 或规则 reward。
3. 适合需要探索和迭代优化的任务。
4. 是经典 RLHF 路线，理论和工程经验较多。

PPO 的缺点：

1. 工程复杂，需要 policy、reference、reward、value/critic 多个模型或模块。
2. 显存和计算成本高。
3. 训练不稳定，容易 reward hacking、KL 崩掉、长度偏置。
4. 对 reward model 质量高度敏感。

PPO-RLHF 的工程判断可以这样理解：它的优势是直接在模型自己的采样分布上优化 reward，因此能处理需要探索的任务；代价是 policy、reference、reward 和 value/critic 之间的状态与统计都要对齐，采样成本和不稳定因素明显增加。它适合反馈信号明确、值得在线探索的场景，但不是所有后训练都必须使用 PPO。

## 4. DPO：直接偏好优化

DPO 的核心动机是：能不能不显式训练 reward model，也不跑复杂 PPO，直接用偏好对训练模型？

DPO 使用数据：

```text
(prompt, chosen, rejected)
```

它直接优化模型，让 chosen 的相对概率高于 rejected。

直觉上：

```text
如果人更喜欢 chosen，就提高模型生成 chosen 的概率，降低 rejected 的概率。
```

DPO 的核心量是 policy 和 reference 在 chosen / rejected 上的 log probability gap：

这里的回答概率通常表示整条回答在给定 prompt 下的条件概率。实际实现会对 assistant response token 求 log probability 的和，并用同一套 response mask 计算 chosen 与 rejected；prompt token、padding 和工具字段如何处理，必须与数据模板一致。

```math
\Delta_{\theta}=
\log \pi_{\theta}(y^+\mid x)
-
\log \pi_{\theta}(y^-\mid x)
```

```math
\Delta_{\mathrm{ref}}=
\log \pi_{\mathrm{ref}}(y^+\mid x)
-
\log \pi_{\mathrm{ref}}(y^-\mid x)
```

DPO 的关键不是“把 chosen 概率调高”这么简单，而是把带 KL 约束的 reward 最大化改写成 policy 概率。先看固定 prompt `x` 下的目标：

```math
\max_{\pi(\cdot\mid x)}
\mathbb{E}_{y\sim\pi}[r(x,y)]
-\beta D_{\mathrm{KL}}\left(\pi(\cdot\mid x)\|\pi_{\mathrm{ref}}(\cdot\mid x)\right)
```

对这个分布优化，最优策略满足：

```math
\pi^*(y\mid x)=
\frac{1}{Z(x)}\pi_{\mathrm{ref}}(y\mid x)
\exp\left(\frac{r(x,y)}{\beta}\right)
```

把它取对数并整理，就能把 reward 写成 policy/reference 的 log-ratio：

```math
r(x,y)=
\beta\log\frac{\pi^*(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}
+\beta\log Z(x)
```

在 Bradley–Terry 偏好模型中，同一个 prompt 下 chosen 和 rejected 的比较只依赖两个 reward 之差。两条回答共享的 `\beta\log Z(x)` 因而抵消，剩下的正是 policy 与 reference 的 chosen/rejected log-ratio 差。将未知最优 policy `\pi^*` 换成可训练的 `\pi_\theta`，再对偏好标签做最大似然，就得到下一条二元分类损失。这个推导说明 DPO 省掉了**单独拟合 reward model 和在线 RL 更新环**，但不是“没有 reward 概念”：policy/reference 的相对 log-probability 隐式定义了一个 reward 参数化，而且推导依赖 KL 约束目标与 Bradley–Terry/Plackett–Luce 一类偏好模型假设。

DPO loss 可以写成：

```math
L_{\mathrm{dpo}}=
-
\log
\sigma\left(
\beta(\Delta_{\theta}-\Delta_{\mathrm{ref}})
\right)
```

`\beta` 在推导中的角色是 KL 正则强度：在底层 reward 固定时，较大的 `\beta` 会让最优 policy 相对 `\pi_{ref}` 的偏移变小。训练器里的损失又把 `\beta` 乘在分类 logit 上，因此实际梯度和收敛还取决于学习率、loss reduction、数据质量和训练步数；不能概括成“越大越保守”或“越大越容易过拟合”。必须固定实现口径后再调参，并同时看偏好质量、reference 偏移和能力回归。

做一个可手算的例子。假设某个 prompt 下，reference 对 chosen/rejected 的概率分别为 `0.20/0.40`，当前 policy 为 `0.40/0.20`。则 policy 的偏好 margin 是 `\log 2≈0.6931`，reference margin 是 `\log 0.5≈-0.6931`，两者差为 `\log 4≈1.3863`。当 `\beta=0.1` 时，DPO 分类 logit 是 `0.1386`，模型赋给“chosen 更受偏好”的概率约为 `\sigma(0.1386)=0.5346`，单样本 loss 约为 `-\log(0.5346)=0.626`。若 policy 与 reference 的相对 margin 一样，logit 为 0，预测概率为 0.5，loss 为 `\log 2≈0.693`。这说明它优化的是**相对 reference 的偏好差**，不是单独最大化 chosen 的绝对概率。

也可以从二分类梯度读出更新方向。令 `z=β(Δθ−Δref)`，当偏好标签是 chosen 获胜时，单样本 loss `−log σ(z)` 对 `z` 的导数为 `σ(z)−1`。上例 `z≈0.1386`，导数约为 `−0.4654`；梯度下降会增大 `z`，从而提高 policy 相对 reference 的 chosen/rejected margin。即使 chosen 概率已经大于 0.5，loss 仍为正，因为目标并不是仅仅“猜对标签”，而是继续拟合偏好目标；训练过久或偏好标签有噪声时，margin 仍可能过度增大，所以需要固定训练步数并在独立偏好集和能力回归集上选 checkpoint。

偏好对必须来自相同 prompt，这使两条回答共享的 prompt 项和归一化常数可以在差值里抵消；它不意味着两个不同 prompt 的 DPO logit 可以拿来比较。长度处理也会改变实际目标：若对 response token 的 log probability 求和，长回答通常累积更多负 log-prob 项，chosen/rejected 的长度差会影响 margin；改用 token 平均可以降低直接的长度累积，但已是不同的聚合约定。训练记录必须说明 response mask、是否包含 EOS、采用 token sum 还是 mean，以及 reference 与 policy 是否使用完全相同的模板。

这个 loss 的定义域同样是数据协议的一部分：chosen 和 rejected 必须各自至少含一个被监督的 response token，四个 log probability 都应在同一个 tokenizer、chat template 和 mask 下求得且为有限数，`\beta>0`。若 response 被截成空串、reference 与 policy 的模板不同，或 token 聚合分别使用了 sum 和 mean，表面上仍能得到 margin，语义却已经不再是同一偏好对的比较。

DPO 的 reference model 不是一个额外的 reward model。它提供的是相对锚点，让 policy 提高 chosen 相对 rejected 的偏好时，不至于无约束地离开初始行为。若 reference、tokenizer、chat template 或 response mask 不一致，公式仍然可以运行，但得到的 margin 已经不代表预期的偏好关系。

[DPO 原论文](https://arxiv.org/abs/2305.18290v3)在其情感控制、摘要和单轮对话实验中报告了与 PPO-RLHF 竞争或更好的结果，并且训练流程更简单；这支持“在相应任务设置下，DPO 可以替代一部分 PPO-RLHF 流程”，不能推出所有规模、任务和数据上都更稳定或更优。DPO 的工程优点包括：

1. 工程简单。
2. 不需要在线 rollout。
3. 不需要单独训练和部署显式 reward model。
4. 训练图更直接，少了 PPO 的在线采样、critic 和 reward-model 迭代环节。
5. 适合偏好数据充足、目标相对明确的场景。

DPO 的缺点：

1. 依赖离线偏好数据质量。
2. 不能充分探索当前 policy 的新输出。
3. 对复杂 long-CoT reasoning 的优化能力有限。
4. 容易学到风格偏好，而不一定提升真实任务正确率。
5. 对 verifiable reward、代码执行 reward、数学答案 reward 这类场景不如在线 RL 灵活。

reference 是损失参数化的一部分，不是每一步都把 policy 硬性投影回 reference 的约束器。偏好数据分布之外的行为可能不受充分约束，训练后仍要量化 policy/reference 的分布偏移，并对通用能力、安全、拒答、长度和领域任务做切片回归。后续研究也观察到，直接偏好优化并不会自动免疫代理目标过优化；优化强度和偏好质量仍然会影响真实偏好表现。

偏好标签本身也有信息损失：二元 chosen/rejected 目标把“略好一点”和“明显更好”都编码成同一个方向，默认每对样本不存在平局。如果标注者分歧较大，简单多数标签会把不确定性藏起来，DPO 仍按硬标签推开两条回答。数据整理应保留标注人数、分歧率、平局和弃权规则；高分歧 pair 可以复审、降权或换成适合不确定偏好的目标，并在独立标注集上检查模型学到的是目标行为而非标注噪声。

为什么说“DPO 不是全部后训练”？

因为很多 reasoning model 后训练关注的是：

```text
模型自己采样多条推理链
用规则或程序验证结果
根据正确性、格式、长度、过程质量做 reward
继续优化 policy
```

这类训练天然更接近在线 RL，而不是只用固定偏好对的 DPO。

### 4.1 IPO、KTO、ORPO：偏好数据形态不同，目标也不同

“偏好优化”不是一种固定数据格式。DPO、IPO、KTO 和 ORPO 都不要求在线 rollout，但它们依赖的标签和偏好函数不同，因此不能把它们当成可以互换的同义词。

| 方法 | 训练信号 | reference | 改动的核心 | 主要边界 |
|---|---|---|---|---|
| DPO | 同 prompt 的 chosen/rejected 对 | 需要 | 用 KL 约束下 policy 的 log-ratio 构造隐式 reward，并按偏好标签做 logistic loss | 依赖静态偏好分布；分布外行为和代理目标过优化仍需监控 |
| IPO | 同 prompt 的 chosen/rejected 对 | 需要 | 将 policy/reference 的偏好 margin 回归到有限目标，而不是让 logistic margin 无界增大 | 原始研究的理论分析和小型示例不等同于在所有现代 LLM 配置上的规模化优势 |
| KTO | 每条回答的 desirable / undesirable 二元标签即可，不要求每条样本成对 | 需要 | 以 prospect-theory 风格的效用函数直接优化单样本相对参考 policy 的价值 | 单条标签仍受标注标准和类别比例影响；模型报告结果绑定其任务与模型规模 |
| ORPO | chosen/rejected 成对偏好，并在 chosen 上做 SFT | 不需要 | 把 SFT 似然和 odds-ratio 偏好项合在一个训练目标里 | 组合目标的损失权重、长度和数据分布都要检查；“单阶段”不代表没有偏好数据要求 |
| SimPO | 同 prompt 的 chosen/rejected 对 | 不需要 | 用 response 平均 log probability 作为隐式 reward，并设置目标 margin | 平均 log-probability 会改变长短样本权重，reference-free 不代表没有 policy drift |

IPO 的目标可以用下面的教学式表达：

```math
L_{\mathrm{IPO}}=
\left[
\left(\Delta_{\theta}-\Delta_{\mathrm{ref}}\right)
-\frac{1}{2\beta}
\right]^2
```

其中 `\Delta_\theta-\Delta_{ref}` 是 policy 相对 reference 的 chosen/rejected margin。它把“chosen 必须越来越大”改成对有限 margin 的回归目标；论文进一步分析了这种设定在其偏好模型假设下如何保留 reference 约束。读公式时仍要核对原文的温度/正则符号约定，不能把不同论文里同名 `\beta` 直接等同。

如果标注团队更容易判断“这条回答是否可取”，而不容易构造成对比较，KTO 的标签形态可能更合适；如果希望把 chosen 回答的模仿和偏好惩罚合为一次训练，ORPO 给出另一种工程选择。最终选择先看实际能获得哪种标签、reference 模型的显存/吞吐预算，以及目标是排序、模仿还是限制相对策略漂移，再用同一数据划分和相同回归集比较。不同论文在数据、模型、评测集和训练预算上不相同，不能从各自最高分直接得出方法排名。

## 5. SimPO：Reference-Free 偏好优化

SimPO 可以放在 DPO、IPO、KTO、ORPO 之后理解。它关注的问题是：能不能在不显式依赖 reference model margin 的情况下，直接用偏好对优化 policy。

DPO 的核心比较是 policy 相对 reference 的 chosen / rejected margin：

```text
policy margin - reference margin
```

SimPO 的思路更接近把当前 policy 对整条回答的平均 log probability 当作隐式 reward，并对 chosen 和 rejected 之间设置目标 margin。

设回答 `y` 的 token 数为 `|y|`，平均 log probability 可以写成：

```math
s_{\theta}(x,y)=
\frac{1}{|y|}
\sum_{t=1}^{|y|}
\log \pi_{\theta}(y_t\mid x,y_{1:t-1})
```

这里 `|y|` 是参与比较的 response token 数，必须大于零；`\beta>0`，`\gamma` 和所有 token log probability 必须为有限数。长度归一化只是在目标中改变长短回答的权重，不会自动消除长度偏好：若偏好标签本身系统性奖励冗长解释，平均 log probability 仍会把这种偏好学进去。

对一个偏好对 `(x,y^+,y^-)`，SimPO 关注：

```math
\Delta_{\theta}^{\mathrm{sim}}=
s_{\theta}(x,y^+)-s_{\theta}(x,y^-)
```

再用 target margin `\gamma` 拉开 chosen 和 rejected：

```math
L_{\mathrm{simpo}}=
-
\log \sigma\left(\beta(\Delta_{\theta}^{\mathrm{sim}}-\gamma)\right)
```

若 chosen 与 rejected 的平均 log probability 分别为 −1.0 和 −1.4，则 `Δ_sim=0.4`。取教学值 `β=1`、`γ=0.2`，分类 logit 是 `1×(0.4−0.2)=0.2`，偏好概率约为 `σ(0.2)=0.5498`，loss 约 `−ln(0.5498)=0.5981` nat。若 margin 恰为 0.2，logit 为 0、概率为 0.5、loss 回到 `ln 2≈0.6931`；这显示 target margin 改变了“达到多少相对差距才算满足目标”，不是在鼓励无界地增加回答长度。

若两个回答的平均 logp 一样，`Δ_sim=0`，以上教学参数会给出 `z=1×(0−0.2)=−0.2`，偏好概率约 0.4502，loss 约 0.7981 nat。梯度会推动 chosen 的平均 logp 超过 rejected，并达到正的目标间隔；它不会仅仅让模型复述一个全局质量分数。这个结果也提醒我们，若偏好 pair 的语义差别很小而 `γ` 设得大，每条 pair 都会持续要求模型拉开差距，可能把标注噪声转成过强的概率间隔。

把平均值还原成 token 输入，更能看出 SimPO 改变了什么。假设 chosen 有两个 response token，log probability 为 `[-0.2,-0.4]`，则平均值是 `−0.3`；rejected 有四个 token，log probability 为 `[-0.3,-0.5,-0.6,-0.8]`，平均值是 `−0.55`。所以平均 margin 为 `0.25`。取 `β=2`、`γ=0.2`，logit 为 `2×(0.25−0.2)=0.1`，偏好概率约 0.525，loss 约 0.6444 nat。若错误地对 token log probability 求和，两个回答会得到 `−0.6` 与 `−2.2`，margin 变成 1.6，产生完全不同的 logit 和更新强度。这个差异来自序列归约方式，不是标注突然更可信。

对同一条 chosen/rejected pair，令 `z=β(Δ_sim−γ)`，loss 对平均 margin 的导数是 `β(σ(z)−1)`；在上例中约为 `2×(0.525−1)=−0.95`。梯度下降因此扩大 chosen 相对 rejected 的平均 log-prob margin。增大 `β` 同时改变 logit 尺度和梯度尺度，不能孤立地把它解释为“更偏好 chosen”；`γ` 则要求先达到一定 margin，偏好分类才进入正向置信区域。两者都要与学习率、batch reduction、更新步数一起评估。

reference-free 只表示 loss 不再额外读取冻结 reference 的 chosen/rejected log probability，并不表示不需要 SFT 初始化。训练起点、偏好数据分布和有限训练预算仍是先验约束；但不像 DPO 那样逐样本显式比较当前 policy 与 reference，SimPO 更容易在反复强化 chosen 后偏离初始输出风格或安全行为。因此公平对照要用相同底模、同一偏好 pair 和训练预算，分别记录偏好准确率、长度分布、KL/其他 drift proxy、通用能力、安全切片和真实任务成功率。不能只因 SimPO 少驻留一个 reference 模型，就把省下的显存当成效果增益。

这个写法的直觉是：chosen 不只是要比 rejected 概率高一点，而是要高过一个目标间隔；同时用平均 log probability 减少长回答天然累积更多 log probability 惩罚或奖励的问题。

平均 log probability 是逐 token 的平均 surprisal 的相反数，不是回答的总概率，也不是经过校准的 reward。它把两 token 与四 token 的序列都映射到每 token 平均尺度，使回答长度不再直接把一串负 log probability 相加；但两个回答即使内容质量相同，若一个使用更常见、更容易预测的词，也可能得到更高平均 logp。因而模型可能偏好安全、模板化或高频表达，平均化只能调整长度权重，无法保证语义质量或消除风格偏差。

target margin `γ` 的语义是：chosen 的平均 logp 要比 rejected 高出多少，训练 loss 才开始把该 pair 视为越过零 logit。它不是 reward model 的绝对分数，也不是偏好概率的置信阈值。若所有回答的 margin 都小于 `γ`，训练会同时推动许多 pair 拉开差距；当标注噪声较大时，这可能放大错误标签。反过来，`γ` 设得过低会让轻微概率差异也满足目标，`β` 又决定 logit 与梯度尺度。调参应在固定数据上联合观察 pairwise accuracy、chosen/rejected margin 分布、长度和输出多样性，而不只看训练 loss 下降。

聚合协议要明确哪些 token 进入 `|y|`：assistant 内容、结束符 EOS、拒答标记和工具调用字段可能有不同作用。若 chosen 用 response-only mask、rejected 却把工具或模板 token 算进去，即使二者 token 均值都能算出，也不是相同内容范围的比较。截断还可能移除结尾结论，使一条原本正确的 chosen 变成不完整序列；训练前应统计空 response、被截断 pair、长度差和模板版本，给过滤或重标规则留下记录。

因此 SimPO 的资源收益与目标风险是成对出现的：不再为 reference 额外做两组前向 log-prob 计算，训练图更轻；但 loss 没有逐样本的 reference margin 作锚点。较稳妥的比较是在同一 SFT checkpoint、同一 chosen/rejected pairs、同一 tokenizer/template 与 token budget 下并行训练 DPO 和 SimPO，再对照偏好正确率、输出长度、拒答/帮助切片、通用能力和安全回归。若 SimPO 省下的显存被用来扩大 batch 或训练步数，必须把这些变化记为实验变量，不能将总结果归因于 loss 形式。

平均 logp 的“长度校正”也要按任务解释。一个较长回答可能因包含更多低概率专名、公式或代码 token 而平均 logp 更低；相反，重复一个常见短语会提高可预测度，却不增加正确性。把平均值作为隐式 reward，实际上在比较每 token 的模型熟悉度，而非直接比较回答信息量。数学证明、代码补丁和闲聊回答的 token 分布不同，跨任务混合时应先做任务分桶，再看 chosen margin 和成功率是否同向；总平均 margin 可能掩盖某个领域被挤压。

当 preference pair 极长或包含工具交互时，平均 logp 还可能受多轮 mask 约定影响：如果工具结果被当作 response token 参与均值，工具更长的一侧会改变分母；如果把 assistant 的工具调用结构排除，目标又只评价文本片段。此时 SimPO 仍可优化，但算法名称无法替代数据契约。记录每个角色、action 和终止 token 的监督范围，必要时分别训练和评测纯文本回答、结构化工具动作与工具返回后的总结。

SimPO 的优点：

1. 不需要显式 reference model，训练和显存开销更轻。
2. 目标形式和 generation metric 更贴近，因为都在 policy 自身概率上比较回答。
3. 适合离线 preference 数据质量较高、希望简化 DPO reference 依赖的场景。

SimPO 的风险：

1. 没有 reference model 锚点时，更需要控制过优化和能力回归。
2. target margin `\gamma` 和 `beta` 需要调参，过强会导致风格变窄或长度异常。
3. 它仍然依赖 chosen / rejected 数据质量，不能替代在线探索和 verifiable reward。

SimPO 的位置可以这样记：它仍然是离线偏好优化，只是用当前 policy 的序列平均 log probability 构造 reference-free 的隐式 reward，并以 target margin 分离 chosen 和 rejected。[SimPO 原论文](https://arxiv.org/abs/2405.14734)给出这一目标及其实验。省掉 reference model 会降低资源成本，同时也拿掉了一层 policy drift 的锚点，所以必须额外监控长度、能力回归和安全行为。它适合偏好数据驱动的场景，不能替代需要在线探索和可验证 reward 的 GRPO/DAPO 路线。

## 6. GRPO：Group Relative Policy Optimization

GRPO 是 DeepSeekMath 提出的 group-relative policy optimization 路线，可以理解为一种面向 group sampling 的 RL 优化方法。[DeepSeekMath 原论文](https://arxiv.org/abs/2402.03300)

它常见于 reasoning RL 场景。

基本思想是：对同一个 prompt，模型采样多条回答，形成一个 group：

```text
prompt -> response_1, response_2, ..., response_k
```

然后用 reward 给每条回答打分：

```text
r_1, r_2, ..., r_k
```

再用组内相对优势更新模型。

直觉是：

```text
同一道题里，奖励更高的回答应该被增强，奖励更低的回答应该被压低。
```

对第 `i` 个 prompt 采样 `K` 条回答，reward 为 `r_{i,j}`，组内均值和标准差为：

```math
\bar{r}_i=
\frac{1}{K}\sum_{j=1}^{K}r_{i,j}
```

```math
s_i=
\sqrt{
\frac{1}{K}
\sum_{j=1}^{K}
(r_{i,j}-\bar{r}_i)^2
}
```

组内相对 advantage 可以写成分段形式：

```math
A_{i,j}=
\begin{cases}
\dfrac{r_{i,j}-\bar{r}_i}{s_i},&s_i>0\\
0,&s_i=0
\end{cases}
```

策略概率比按生成 token 计算，组内 advantage 则按完整 response 计算。对 prompt i、第 j 条回答的第 t 个 token：

```math
L_{\mathrm{GRPO}}=
-\mathbb{E}_{i}\left[
\frac{1}{K}\sum_{j=1}^{K}
\frac{1}{L_{i,j}}\sum_{t=1}^{L_{i,j}}m_{i,j,t}
\min\left(
\rho_{i,j,t}A_{i,j},
\mathrm{clip}(\rho_{i,j,t},1-\epsilon,1+\epsilon)A_{i,j}
\right)\right]
```

其中 `L_{i,j}` 是回答参与策略损失的有效 token 数，`m_{i,j,t}` 是 response/loss mask；`K\geq2`，每个旧 policy 概率必须非零，概率比和 reward 必须有限，且 `0<\epsilon<1`。这是 policy-gradient 主项的教学写法；KL/reference 项是否存在、按 token 还是 sequence 汇总，要按具体论文和实现另行核对。

`ρ` 的分子和分母在 rollout 起点通常相同，因此新旧 policy 还没更新时 `ρ=1`。假设旧 policy 对某 token 的概率为 0.20，第一轮更新后变为 0.22，则 `ρ=1.1`；若 `A=0.6`、`ε=0.2`，未裁剪 surrogate 是 `1.1×0.6=0.66`，尚未碰到上界。若新概率升到 0.26，ratio 是 1.3，正 advantage 项会受 `1.2×0.6=0.72` 限制。ratio 分母必须来自生成这条回答的旧 policy；若 rollout queue 混有多个 checkpoint，却统一用最新 policy 当分母，优势和 clipping 统计就不再对应真实采样分布。

用一个小组手算 advantage。若一个 prompt 的三个答案 reward 是 `[1, 0.5, 0]`，组均值为 `0.5`；按总体标准差定义，`s=\sqrt{1/6}\approx0.4082`，三个 advantage 分别约为 `[1.2247, 0, -1.2247]`。中间回答虽然得到正分，但它只等于组均值，因此没有相对更新信号。若三条回答都得到 `1`，则 `s=0`，整组 advantage 应显式置零或跳过，并报告无区分度比例；加一个 epsilon 只能避免除零，不能凭空创造学习方向。

损失归一化会改变不同长度回答的权重。上面的形式对每条回答先除以 `L_{i,j}`，使每个 response 在外层组均值中获得近似相同权重；token-level reduction 则把整批有效 token 放在同一分母下，让长回答贡献更多 token 项。DAPO 会明确采用后者。后续 DrGRPO 进一步质疑按 response 长度和组内标准差归一化产生的偏置，说明分母是算法假设的一部分，不能只写一个 `mean()` 就略过。

这不是所有 GRPO 实现的完整细节，但抓住了方法的关键：用同 prompt 的组内 reward 构造 baseline / advantage，减少对 critic 的依赖。

GRPO 相比 PPO 的一个重要特点是：通常不需要单独训练 critic/value model，而是用 group 内 reward 做 baseline 或 advantage 估计。

这也带来一个容易被忽略的边界：如果同一个 prompt 的所有回答都得到相同 reward，`r_{i,j}-\bar r_i` 全部为零，组内比较就没有方向；如果 group 太小或 reward 噪声很大，标准化会放大偶然差异。工程上需要同时记录 group size、有效样本率、reward 方差、response 长度和 KL/ratio 分布，而不能只看平均 reward。

二元正确性 reward 可以手算“没有区分度的 group”会多常见。若每条回答独立答对的概率暂假设为 `p=0.5`，group size `K=4`，全错的概率是 `(1−p)^4=0.0625`，全对也是 `p^4=0.0625`，因此合计 `0.125` 的 group 没有组内差异。把 `K` 增至 8，这个理想独立假设下的比例变成 `2×0.5^8≈0.0078`，但 rollout token 成本也约翻倍；真实回答并不独立，不能把该概率当作真实训练率。动态过滤或补采可以减少零信号组，却可能把训练分布推向更容易分出对错的题，必须记录原始题池、被丢弃组和最终采样权重。

组内标准化也会抹平 prompt 之间 reward 尺度的差别。比如数学题 reward 差 `0.1` 和代码任务 reward 差 `1.0`，若各自除以组标准差，都可能得到相同大小的 advantage；这有利于避免某个量纲大的 reward 支配更新，却也意味着原始任务价值和 verifier 置信度没有自动保留下来。多任务训练时需要分任务检查 reward 质量和更新量，不能只看全局标准化后的 advantage 均值。

GRPO 节省的是独立 value/critic 的训练与显存，并没有省掉生成 group 所需的模型前向和 token。相同总 token 预算下，增大 `K` 会让每道题有更多候选，但题目数可能下降；固定题目数则总 rollout token 上升。选择 group size 时要以“每个 prompt 的区分度、总体有效 token、verifier 成本和墙钟时间”共同核算，而不是把更大的 group 当作无代价的统计改进。实现还应确认标准差使用总体还是样本定义、是否做 advantage whitening，以及零方差组是跳过、置零还是补采；这些约定会改变更新尺度。

同组的标量 advantage 通常会广播到该 response 的每个有效生成 token；GRPO 因此用序列级结果做 credit signal，再由 token log-prob gradient 执行更新。它并不知道某个答案的哪一步推导正确，若输出先给出错误计算、后面偶然猜中正确答案，终局 reward 仍可能把同一个正 advantage 赋给整条轨迹。过程 verifier 或 step reward 可以增加局部信息，但它们会引入新的标签噪声和 reward 设计问题。训练中要区分“终局答案正确率”“格式/过程 reward”和“token loss reduction”，不要把组内 advantage 的正负当成解释性归因。

group 的边界必须是真正可比较的条件：同一道题、同一工具权限、同一答案 parser 和同一生成上限下采样的回答，才适合共享一个 baseline。若把不同 prompt 或不同 difficulty bucket 混成一组，均值/标准差就反映任务差异，而不是同一问题内哪个策略更好。并发 rollout 还要按 prompt id 与 policy revision 聚合，避免慢返回样本被误并入另一个版本。每步至少记录 unique response 数、group reward 方差、prompt 来源与过滤原因，才能判断训练变化来自算法还是组构造。

分布式实现还要区分训练 batch 的分片单位和计算 advantage 的组单位。假设同一 prompt 的两个回答 reward 为 1 和 0，完整组的均值是 0.5、总体标准差是 0.5，advantage 为 +1 和 −1。若先把两条轨迹分到不同 rank，再让每个 rank 对本地单条样本计算组统计，就会遇到零方差并可能把两条 advantage 都置零；若跨 rank 收集时混入另一道题，组均值又会带入题目难度差异。应先按 prompt id、policy revision、采样配置和 verifier revision 完成同组统计，再分片执行 token loss。异步重试还需去重并等到组完整，或按明确规则丢弃不完整组，不能把重复响应误算成独立探索。

如果任务把答案正确性与格式合成一个标量，例如 `r=r_correct+0.1r_format`，正确且格式合规的答案 reward 是 1.1，错误但格式合规是 0.1，格式错误的正确答案是 1.0。组内标准化会再按当前 prompt 的 reward 分布转换这些值；`0.1` 的格式奖励是否足以改变排序，取决于 reward 权重和 group 里出现的答案，而不是由 GRPO 自动决定。上线前应对 reward 组成做分量消融，并对正确性与格式分别报告，避免一个可钻空子的辅助项把主目标方向反转。

它适合：

1. 数学推理。
2. 代码生成。
3. 可验证 QA。
4. 有明确对错 reward 的任务。
5. 同一 prompt 可以采样多条候选的场景。

优点：

1. 比 PPO 工程上更轻，减少 critic 训练复杂度。
2. 适合 verifiable reward。
3. 能利用同一问题多条采样之间的相对质量。
4. 对 reasoning RL 比纯 DPO 更自然。

缺点：

1. 需要在线采样，成本仍然不低。
2. 对 reward 设计很敏感。
3. group size、KL、长度控制都会影响稳定性。
4. 如果 reward 太稀疏，训练效率会下降。

GRPO 的核心判断是：它用同一个 prompt 的多条输出提供相对基线，通常省去 PPO 的独立 critic，因而适合数学、代码等可验证任务；但它没有消除 rollout 成本，也没有自动解决 reward 稀疏、长度偏置或安全回归。

## 7. GSPO：把重要性比率和裁剪提升到序列级

GSPO 论文作者提出的诊断是：最终 reward 往往针对整条回答给出，但 GRPO/PPO 的重要性比率和 clipping 却逐 token 计算。对于几百到几千 token 的长 CoT，少数 token 的 ratio 波动可能积累为高方差更新；他们报告这种现象在长 response 和大规模 MoE RL 中可能导致训练不稳定或模型坍塌。这是该论文对其训练设置的解释，不是所有 token-level policy gradient 都必然崩溃的定理。

GSPO（Group Sequence Policy Optimization）提出的核心方向，是用序列似然构造重要性比率，并在序列层面进行 clipping、reward 加权和优化。一个便于理解的教学化写法是：

```math
\rho_{i,j}^{\mathrm{seq}}(\theta)=
\exp\left(
\frac{1}{|y_{i,j}|}
\sum_t
\left[
\log\pi_{\theta}(y_{i,j,t}\mid x_i,y_{i,j,<t})
-
\log\pi_{\mathrm{old}}(y_{i,j,t}\mid x_i,y_{i,j,<t})
\right]
\right)
```

这一定义要求 `|y_{i,j}|>0`，每个 token 的新旧 log probability 都有限，且新旧 policy 的 tokenizer、模板和 response mask 完全一致。实现时应先保留括号内的平均 log-ratio `u`：`\exp(u)` 可能溢出，序列 clipping 的比较可以在 log 空间用 `\log(1-\epsilon_{\mathrm{clip}})` 与 `\log(1+\epsilon_{\mathrm{clip}})` 完成；遇到超出浮点表示范围的 ratio，应该记录为策略漂移异常，而不是静默截成一个普通数。

用两个 token 的例子看懂它和普通 sequence likelihood ratio 的区别。若新旧 token ratio 为 [2, 0.5]，未归一化的整句概率比是 2×0.5=1，GSPO 的长度归一化 ratio 是 sqrt(2×0.5)=1。若两个 token ratio 都是 1.2，普通乘积为 1.44，GSPO ratio 为 sqrt(1.2×1.2)=1.2。它保留整句更新和裁剪单位，同时用几何均值弱化长度对 ratio 数值的直接放大；因此它不是标准重要性采样的整句乘积，长度归一化本身也是方法假设。

再用同一组 token 看 clipping 粒度的实际差异。假设两个 token 的新旧 ratio 是 `1.44` 和 `0.81`，sequence ratio 为 `sqrt(1.44×0.81)=1.08`。取教学 clipping 半径 `ε=0.2`、正 advantage `A=1`：逐 token PPO-style surrogate 会把第一个 token 项从 1.44 截到 1.20，第二项保持 0.81；若对两个 token 等权平均，得到 `(1.20+0.81)/2=1.005`。GSPO 看的是整条 response 的 1.08，尚未越过 `[0.8,1.2]`，因此该序列项仍为 1.08。算式说明两种目标即使使用同一 rollout，也会把梯度权重分配到不同位置；它不代表某一种一定更好。

这个聚合有一个明确的代价：两个 token 的 log-ratio 可以互相抵消。上例一个 token 比率很高、另一个偏低，几何均值却靠近 1；整条序列因此不会触发 clip。序列级处理减少长回答中许多独立 ratio 对 reward 的放大，却也失去逐 token 区分“哪个局部选择造成偏差”的粒度。对长 CoT，若一个回答既包含关键正确推导，也包含格式错误或冗余段落，一个 sequence-level advantage 会把同一更新方向分配给整条回答，因此需要外部验证、长度/格式切片和 trajectory-level 质量分析。

长序列时，几何平均会显著改变 ratio 数值。假设 1,000 个 token 的 log-ratio 都是 `0.001`，整句概率乘积为 `exp(1000×0.001)=exp(1)≈2.7183`，而 GSPO 的长度归一化 ratio 是 `exp(0.001)≈1.0010`。它避免 ratio 仅因 token 数增加而远离 1，但也表示“每个 token 都小幅同向改变”的长序列不会像原始乘积那样累计为更大数值。训练诊断应同时保留平均 log-ratio、总 log-ratio 和 sequence ratio，不能只看 1.001 就推断整条轨迹没有累计偏移。

因此长度归一化不只是改善数值范围，也改变了重要性权重的统计含义。若每个 token 的 ratio 都是 1.2，两个 token 的完整轨迹 ratio 是 `1.2^2=1.44`，十个 token 时则约为 `1.2^10=6.19`；GSPO 的几何平均在两种长度下都为 1.2。对同一个 sequence-level reward，后者不会像完整轨迹的概率比那样随长度乘起来，所以不能把它当作未改变目标的无偏重要性采样修正。读论文结果时应把它理解为作者选择的序列级 surrogate；若迁移到明显不同的长度分布，应重新检查长度分桶、序列 ratio 与正确率的关系，不能只因 ratio 更接近 1 就判定更新更稳。

序列裁剪与 token 裁剪的另一个差异是：若一个 response 的序列 ratio 越界，整个 response 会按序列 surrogate 进入 clipping 分支，即使里面多数 token 的 ratio 仍接近 1；逐 token GRPO 则只对越界 token 项进行各自裁剪。反过来，局部 token ratio 变化很大但彼此抵消时，sequence ratio 仍可能在窗口内。选择 GSPO 的代价不是简单的“少算几个 clip”，而是把局部信用分配换成轨迹级权重；应检查 clip response 比例、其中仍在窗口内的 token 比例，以及长回答正确性和单位成功成本。

还要把“ratio 里的长度归一化”和“loss 外层怎样平均”分开记录。GSPO 的几何均值先把一条回答内的 log-ratio 除以有效 token 数，决定这条序列是否越过 clip；外层 `E_{i,j}` 如何对 prompt 和 response 求均值，则决定不同样本的总权重。若外层等权平均 response，10-token 与 90-token 回答在样本层各占一份；若实现又按全批 token 共用分母，长度权重会重新进入总 loss。一个算法使用 sequence ratio，并不能单凭名称推出所有训练器的 reduction 相同。

可以固定每条回答内部的序列 surrogate，只改变外层分母来核算这个区别。设 10-token 回答经序列级 clipping 后的 surrogate 为 0.2，90-token 回答为 0.8；response 等权平均得到 `(0.2+0.8)/2=0.5`，按有效 token 数加权则得到 `(10×0.2+90×0.8)/100=0.74`。两种写法中的 GSPO ratio 和每条回答的 clipping 结果完全相同，批次目标的变化只来自回答间的权重。反过来，序列 ratio 即使不会仅因 token 数多而按乘积远离 1，长回答仍可能在 token-weighted reduction 中主导总 loss。复现时应并列记录 ratio 定义、response surrogate、外层 reduction、分母和各长度桶的权重；缺少其中一项，就无法判断收益来自序列裁剪还是样本加权。

工程比较时至少同时看两种裁剪粒度的 clipping fraction、ratio 分位数、回答长度分桶、正负 advantage 利用率、正确率和训练成本。若 GSPO 的序列 clip 比率很低但 token ratio 方差很大，聚合可能掩盖局部变化；若序列 clip 比率很高，整条回答都可能被降权，包含仍有学习价值的 token。MoE 场景还要检查 router/token dispatch 与训练—rollout 参数一致性，因为序列目标不能修复不同模型权重或不一致采样路径造成的 log-prob 偏差。

再用组内 advantage `A_{i,j}` 做序列级 clipped objective：

```math
L_{\mathrm{gspo}}=
-\mathbb{E}_{i,j}\left[
\min\left(
\rho_{i,j}^{\mathrm{seq}}A_{i,j},
\mathrm{clip}(\rho_{i,j}^{\mathrm{seq}},1-\epsilon,1+\epsilon)A_{i,j}
\right)
\right]
```

这两个式子是帮助读者理解论文设计的简化表示，不应当被当作所有 GSPO 代码的逐行 API。序列比率仍由 token log probability 累积得到，反向传播也仍然经过 token；变化在于裁剪和样本权重的决策单位是完整 response。这样做的目标，是让“这条完整回答得到多少 reward”与“这条回答整体被更新多少”更一致。

论文在 Qwen3 系列训练与其 MoE 设置中报告了相对 GRPO 的训练效率、性能和稳定性收益；这些是作者在特定模型、reward、长度分布和基础设施下的结果。[GSPO 原论文](https://arxiv.org/abs/2507.18071v2)提供该方法的目标和实验设定。DCPO 后续论文则从另一角度指出，GSPO 的序列级 clipping 可能丢弃整条回答里的未超限 token，提出按旧 token 概率动态调整 token clip。两种论文的问题诊断和优化单位不同，不能只靠标题认定其中一个普遍优越。比较时应同时报告有效 response/token 利用率、长度切片、clipping fraction、entropy、reward/外部正确率和总训练成本。

GSPO 没有自动解决 reward 设计、长答案的真实质量、KL 漂移或 rollout 成本问题。评估时应按 response 长度、正确性、格式、KL 和有效 token 分组，而不能只比较一个平均 reward。

适用场景主要是长推理链、长代码生成、多步骤工具调用和多轮任务规划。由于论文发表于 2025 年、实现仍在快速演化，阅读资料时应把它描述为一种有明确原始论文定义的序列级 policy optimization 算法，而不是已经统一定型的行业标准。

## 8. DAPO：把长链推理 RL 的几个瓶颈拆开处理

DAPO 的全称是 Decoupled Clip and Dynamic Sampling Policy Optimization。它不是一个泛称，而是论文和开源系统提出的一套面向大规模 reasoning RL 的组合方法。它关注的不是简单地把 GRPO 换一个名字，而是把 clipping、采样、token-level 更新和过长输出的 reward 处理分别设计。

在 reasoning RL 中，常见痛点是：

```text
1. reward 稀疏：只有最终答案对错。
2. 输出很长：一次 rollout 成本高。
3. 正样本少：模型早期答对率低。
4. 长度偏置：模型可能学会输出更长或更短来投机。
5. KL 不稳定：模型容易偏离初始策略。
6. 难题和易题混在一起，训练信号质量不均衡。
```

DAPO 论文公开讨论的关键组件可以用下面的关系理解：

| 组件 | 解决的问题 | 需要观察的副作用 |
| --- | --- | --- |
| decoupled clip / clip-higher | 对正向更新使用更宽的上界，避免正确样本过早失去梯度 | 上界放宽后可能放大错误 reward 或 policy drift |
| dynamic sampling | 丢弃组内没有区分度的 rollout，提高有效样本比例 | 过滤规则可能改变训练分布，难题不能被误删 |
| token-level loss | 让长回答的有效 token 参与更细的更新 | token credit assignment 和长度权重仍需定义 |
| overlong reward shaping | 对超过预算的回答提供连续惩罚，而不是只在截断时产生突变 | 模型可能学会提前结束，损害真正需要长推理的题目 |

这四项各自对应一个可观察的失败现象，而不是四个可随意互换的超参数：

1. **Clip-Higher**：正 advantage 的低概率 token 在固定上界下只能小幅提高概率，探索 token 更容易被 clip 卡住。DAPO 把正向上界 1+ε_high 与下界 1−ε_low 分开；它扩大低概率 token 的增长空间，但错误 reward 也可能因此造成更大的 policy drift。
2. **Dynamic Sampling**：在论文的二元正确性 reward 设置下，同一 prompt 的 group 若全错或全对，组内 reward 方差为零。DAPO 过采样并丢弃 accuracy 为 0 或 1 的 group，补采到正确答案数满足 0 < correct < K，让进入更新的组含有正负学习信号。代价是额外 rollout，并改变训练 prompt 分布；应报告保留率、被过滤题目的难度/长度和单位有效更新成本。
3. **Token-Level Policy Gradient Loss**：标准 GRPO 先对每条回答的 token loss 按本回答长度求均值，再平均回答；DAPO 改成对 batch 所有有效 token 共用分母。长回答因此贡献更多 token 项，这可能更适合长 CoT，但也意味着长回答会有更大训练权重，必须看长度分桶、正确率和成本。
4. **Overlong Filtering / Soft Overlong Punishment**：被生成上限截断的回答可能因为“没结束”而被当作错误，噪声惩罚了本来正确的长推理。DAPO 先对截断回答屏蔽 loss，再在预设长度之后用软惩罚缓冲区逐步处理超长输出；惩罚阈值若设得过低，模型会为避罚而过早终止。

要把系统截断和模型主动超长分开看。假设生成上限为 512 token，一条回答正好用满预算且没有 EOS，它是被右截断的观测，结尾是否正确未知；直接标成错误会把“系统没给更多生成预算”混进 reward。另一条回答在 400 token 已完整结束但远超项目的软长度目标，才适合进入长度惩罚分析。应记录终止原因、长度上限命中率、EOS 位置和 verifier 结果，按任务绘制长度—正确率曲线；对定理证明、代码修复和短事实问答使用同一长度阈值，可能会系统性压缩真正需要长推理的任务。

例如，解耦 clipping 可以用一个教学化的非对称裁剪表示：

```math
\mathrm{clip}_{\mathrm{dec}}(\rho_t)=
\min\left(\max(\rho_t,1-\epsilon_{\mathrm{low}}),
1+\epsilon_{\mathrm{high}}\right)
```

其中上下界不必相同；具体取值、token-level loss 的归一化和动态采样条件要以论文与代码版本为准。这个式子只说明“解耦”改变了更新窗口，不意味着所有 DAPO 实现都只有这一项改动。

对应的 token-level reduction 可以写成：

```math
L_{\mathrm{DAPO}}=
-\frac{
\sum_{j=1}^{K}\sum_{t=1}^{L_j}
m_{j,t}\min\left(
\rho_{j,t}A_j,
\mathrm{clip}(\rho_{j,t},1-\epsilon_{low},1+\epsilon_{high})A_j
\right)}
{\sum_{j=1}^{K}\sum_{t=1}^{L_j}m_{j,t}}
```

分母是整组的有效 token 数，而不是 K 个 response 均值再平均。比如两条回答长度为 10 和 90，DAPO 的全局 token 分母让每个有效 token 的系数相同，所以 90-token 回答的总 token 项是短回答的 9 倍。按 per-response mean 时，每条回答的总权重近似相等，反而是 10-token 回答中的每个 token 权重为长回答单个 token 的 9 倍。这不是谁“更公平”的普遍结论，而是训练目标选择了不同的样本加权方式。

作为概率比的裁剪区间必须保持为正：通常需要 `0<\epsilon_{\mathrm{low}}<1`、`\epsilon_{\mathrm{high}}\geq0`，并把二者、旧 policy 版本和 token/sequence 聚合口径一同写入实验记录。dynamic sampling 丢弃零方差或其他无效 group 时，也改变了被优化的 prompt 分布；过滤后的有效样本率、被丢弃任务的难度和长度分布必须单独报告，不能只展示保留下来的 reward。

以四条回答的 binary reward `[1,1,0,0]` 为例，`K=4`、均值是 0.5、总体标准差也是 0.5，组内 advantage 为 `[1,1,-1,-1]`，可以同时增强正确轨迹、压低错误轨迹。若 reward 是 `[1,1,1,1]`，方差为零，四条回答没有相对学习方向；DAPO 的 dynamic sampling 会尝试补采有区分度的 group。若 verifier 把错误答案误判为正确，采样器只会按错误标签做筛选，所以它提升的是“进入更新的有效信号比例”，不等于提高标签真值。

非对称 clip 也可用小数值读出作用。若设 `ε_low=0.2`、`ε_high=0.4`、正 advantage `A=0.5`，普通对称上界会把 ratio `1.3` 截到 `1.2`，其 clipped 项是 `0.60`；解耦上界可保留 `1.3`，对应 `0.65`。若 ratio 达到 1.5，则按 1.4 上界给出 0.70。这个教学设置只说明扩大正向更新空间的机制，不是论文超参数；更宽上界也会让错误 reward 造成更大的策略变化，故需和 KL、正确率及安全回归一起观察。

长度控制也不是一个“越短越好”的惩罚。设项目的最大生成预算为 100 token，软惩罚从 80 token 开始：76-token 回答不因长度受罚，90-token 回答进入缓冲区，100-token 回答到预算边界时承受更强的惩罚；超过硬上限而被截断的样本则按论文 recipe 单独屏蔽或处理。这个轨迹只示意阈值的作用，不复刻论文的 reward 数值。若真实任务需要长证明或完整代码，80 token 的惩罚起点就可能过短；应按正确样本的长度分布设置缓冲区，并同时检查截断率、过早 EOS、答案正确率与单位成功 token。

训练日志还应把自然结束与右删失分开记。自然结束表示模型发出了 EOS 或环境确认任务完成，超长惩罚可以针对完整回答讨论；命中 max_new_tokens、墙钟超时或工具执行被中断，则只说明观察窗口结束，未必知道完整回答本来会不会正确。比如 100 条 rollout 中 30 条撞到 token 上限，若验证器把这 30 条都记成错误，完成集准确率就会混入预算截断；若直接剔除，也要同时报告 30% 的删失率和剩余 70 条的分母，避免看起来准确率上升只是难样本消失。可把 `termination_reason`、EOS 位置、最后一个有效 token、partial verifier 结果和 loss mask 一起保存，再按任务长度分布设软阈值；只有先分清观测不完整与主动生成过长，才能判断惩罚是否减少冗余而没有压制必要推理。

它适合：

```text
数学推理强化
代码强化
竞赛题训练
复杂多步任务
长 CoT 模型后训练
```

DAPO 的工程价值在于把长链推理 RL 中的多个瓶颈显式化：稀疏 reward、无效 rollout、长度偏置、token credit assignment 和 clipping 稳定性。它仍然需要可靠的 verifier、合理的长度预算和回归评估；不能因为某个公开 benchmark 提升，就推断这套 recipe 对所有任务都优于 GRPO 或 PPO。

原论文还在其长 CoT 配方中移除了 KL penalty，理由是该 reasoning 训练目标不需要像传统 RLHF 那样始终贴近初始分布。这是该论文针对数学 reasoning 的设计决定，不是“RLVR 不需要 reference/KL”的通则；若任务依赖原模型的通用对话、安全行为或工具习惯，仍要单独决定如何约束漂移并做回归评估。

**论文内证据。** 在 Qwen2.5-32B base、AIME24 Avg@32 设置中，[DAPO 原论文](https://arxiv.org/abs/2503.14476v2)的 progressive ablation 从 naive GRPO 的 30 逐步达到 DAPO 的 50：加入 overlong filtering 后 36、Clip-Higher 后 38、soft overlong punishment 后 41、token-level loss 后 42、dynamic sampling 后 50。论文使用 32 次采样的 Avg@32，报告温度 1.0、top-p 0.7；作者将最终分数与其 DeepSeek-R1-Zero-Qwen-32B 的 47 作对照，并报告训练步数少 50%。这是同一论文的逐步配方分析，不是对六个组件独立随机消融，也不构成对所有算法的统一排名。迁移到其他模型或题集时，应先复现 verifier、数据和采样预算，再判断收益来自哪一组件。

## 9. DCPO：Dynamic Clipping Policy Optimization

本章把 DCPO 指 2025 年公开论文中的 Dynamic Clipping Policy Optimization，而不是把这个缩写泛化成某一种“对比偏好优化”。不同论文可能复用缩写，因此阅读资料时必须同时核对全称、发布时间和公式；只看到 `DCPO` 三个字母，不足以判断它解决的是偏好还是 reasoning RL 问题。

这个缩写后来确实出现了另一个重要复用：2026 年的 [Distribution-Centric Policy Optimization](https://arxiv.org/abs/2601.12730v1) 也缩写为 DCPO，讨论的是分布层 entropy regularization 和探索—利用权衡，不是本节的逐 token 动态 clipping。以下公式、表格和实验数字均指 2025 年 Dynamic Clipping 论文；引用时应写全称，避免把两个目标不同的方法合并比较。

这篇工作针对 RLVR 训练中的一个具体现象：固定 clipping 窗口会压住低概率 token 的更新；若同一 prompt 的一组 reward 全相同，按当前组做标准化又会得到零 advantage。论文给出三项配合的改动：按旧策略 token 概率设置动态 clipping bounds；用当前批次和历史 reward 分布做平滑 advantage 标准化（SAS）；按每条 response 的有效 token 数求均值（Only-Token-Mean, OTM），而不是让整批 token 共用一个分母。

对 prompt `q`、response 中的 token `x`，令 `q(x)` 为 rollout 时旧 policy 给出的 token 概率，`p(x)` 为当前 policy 概率，`r(x)=p(x)/q(x)`。论文从 `|(r(x)-1)p(x)|\leq\epsilon` 推出依赖旧概率的裁剪范围：

```math
0.5+\frac{1}{2}\sqrt{\max\left(1-\frac{4\epsilon_{\mathrm{low}}}{q(x)},0\right)}
\leq r(x)\leq
0.5+\frac{1}{2}\sqrt{1+\frac{4\epsilon_{\mathrm{high}}}{q(x)}}
```

`q(x)` 越小，上下界越宽，低概率 token 因而有更大的探索空间；论文还为正、负 advantage 的最大 clipping bound 设了上限 10，避免极低概率导致窗口无限放大。`q(x)` 是旧 policy 对该 token 的概率，不是 prompt 概率。实际实现必须确认用的是 rollout policy 的原始概率还是经过 top-p 等采样变换后的分布，并检查训练与采样两侧的 log-probability 是否一致。

这是重要性采样的支持集条件：被采样 token 必须在行为分布下有正概率，`q(x)=0` 时 ratio 和动态窗口都没有定义，不能靠给分母加任意 epsilon 修复。如果 rollout 对 logits 做 temperature、top-p 或 top-k 变换，采样分布可能与训练器计算 log-prob 的原始 softmax 不同；这时要么按实际行为分布记 log-prob，要么明确该估计的近似假设，并量化两边差异。截断采样让某些 token 的概率直接归零，和仅把概率变小不是同一种情况；固定 tokenizer、数值精度、采样变换和 policy revision 都应纳入 rollout trace。

用一组教学值计算边界。令 `ε_low=0.1`、`ε_high=0.2`，当旧 token 概率 `q=0.5` 时，下界为 `0.5+0.5√(1−0.4/0.5)≈0.7236`，上界为 `0.5+0.5√(1+0.8/0.5)≈1.3062`。若 `q=0.1`，下界因根号内截为零而成为 0.5，上界为 `0.5+0.5√9=2.0`。于是 ratio `1.6` 在 `q=0.5` 时会被压到约 1.306，在 `q=0.1` 时仍处于可更新区间。数字展示的是动态窗口如何给低概率 token 留出更多上升空间，裁剪公式的各项和概率口径仍必须遵循论文实现；若采样用截断分布而训练用原始 softmax 概率，直接代入就会失去重要性比率含义。

SAS 的关键不是简单把历史 reward 做滑动平均，而是把同一 prompt 当前轮和累计历史的标准化结果组合，再选取绝对值较小者，减轻某一轮采样偶然偏斜造成的 advantage 放大或翻转。它让“本轮所有回答 reward 相同”时仍可能借助历史分布得到非零信号；如果当前与历史 reward 都没有方差，仍需要实现明确定义退化处理，不能凭空制造学习信号。OTM 则先在每条 response 内对有效 token loss 求均值，再对 response 求均值；这与 DAPO 把所有有效 token 放在一个全局分母里的 token-level reduction 不同，二者会给长短回答不同的相对权重。

历史标准化让当前 group 不必独自承担全部尺度估计，但也引入一个状态变量：累计统计究竟按 prompt、任务、verifier 版本还是全局维护。若数学答案 checker 更新了容差，或代码测试集换了版本，旧 reward 分布就不再与新 reward 同一量纲；继续混在一起会使 advantage 的方向和尺度难以解释。工程记录应把 SAS 状态与 reward/verifier revision 绑定，在反馈语义改变时重置或分桶，并比较“只用当前组”与“加入历史”的非零 advantage 率、正确率和长度切片。RUR 增加本身不能证明历史平滑带来更好的 policy。

OTM 的 outer mean 让每条 response 获得近似相同的聚合权重，因而每个 token 的系数会随 response 长度变化；在整批有效 token 共用一个分母的 reduction 中，长回答则贡献更多 token 项。第 11 节用 10-token 和 90-token 的同一组 loss 输入展示了数值差异；DCPO 的重点是这项 reduction 与动态 clipping、历史 advantage 一起组成 recipe，不应把单独 OTM 的结果等同于 DCPO 的整套效果。

论文用 Response Utilization Ratio（RUR）统计 advantage 非零的已生成回答占比。它是样本进入 policy update 的机会指标，不代表样本正确、梯度有益或最终能力提升。[DCPO 论文](https://arxiv.org/abs/2509.02333v2)在四个 Qwen 系列实验、400 个训练 step 上报告 GRPO 平均 43.8%、GSPO 45.6%、DCPO 71.8%；这是一项作者定义的训练期统计量，不能和不同 dynamic-sampling 规则下生成或过滤掉的样本直接等同。

例如五条回答中有四条 advantage 非零，按定义 `RUR=4/5=0.8`。这只回答“多少生成 response 获得非零权重”，不回答四条更新是否方向正确、经过 ratio clipping 后的梯度是否足够大，或模型在未见题上的准确率是否提高。横向比较 RUR 时还要固定统计窗口、group 生成规则、被过滤样本是否进入分母和 response 去重口径；否则分子相同而分母不同，数值就不能直接并列。

分母变化甚至能让“利用率提高”与“可用回答变少”同时发生。假设实验甲生成 100 条回答，其中 70 条 advantage 非零，按生成总数计算 RUR 是 70%。实验乙也先生成 100 条，但过滤掉 40 条后，只在剩余 60 条里有 48 条非零；若分母只记保留样本，RUR 会显示 80%，但实际获得非零信号的回答从 70 条降到了 48 条。比较时应同时列生成数、过滤数、完整组数、非零 advantage 数和 RUR 的分母定义，并将正确率、单位有效 rollout 成本放在同一评估表中。这样才能分辨机制真的增加了有效更新，还是只改变了统计集合。

即便 RUR 的分子和分母完全一致，它也不等于真正产生了多少梯度。以对称 clip `ε=0.2` 为例，某回答的 advantage 为正、ratio 已达到 1.4 时，clipped surrogate 会选上界项 `1.2A`；在标准 clipped objective 中，这一支对 ratio 已经是平的，样本虽被计作“advantage 非零”，该项却不再增加 policy gradient。相反，非零 advantage 也可能对应很小的梯度范数。因而 RUR 应与 clip fraction、有效梯度范数、实际 optimizer update、外部正确率和 token 成本并列；它只测信号是否非零，不能代替样本价值或更新效果。

| 证据口径 | GRPO | DAPO | GSPO | DCPO |
|---|---:|---:|---:|---:|
| Qwen2.5-Math-7B、AIME24 Avg@1 / Avg@32 | 36.7 / 32.1 | 36.7 / 31.6 | 40.0 / 34.9 | 46.7 / 38.8 |
| 四模型平均 RUR（论文定义，400 steps） | 43.8% | 未按相同口径列入该表 | 45.6% | 71.8% |

第一行是论文报告的数学任务结果：评测用 Qwen-Math template，AIME24 Avg@1 为 greedy decoding，Avg@32 为温度 1.0、top-p 1.0 下每题 32 次采样。训练数据约 2.5 万道数学题，来自 DAPO-Math-17K 与 MATH 三级至五级样本的合并。它支持“该 recipe 在作者这一模型、数据与评测协议下得到更高分”，不构成跨论文、跨模型的普遍排名。RUR 与准确率也不是同一指标：前者计数的是非零 advantage 回答，后者看答案是否正确。

因此，复现实验时至少同时记录 clipping ratio 分布、非零 advantage / RUR、每条 response 长度权重、训练与 rollout log-prob 差、验证器正确率和独立 benchmark；若 RUR 提高但真实准确率、长度切片或安全回归恶化，不能把“利用更多回答”当成成功。DCPO 指动态 clipping 方法，不是安全或多目标约束算法；安全约束和拒答评估见 §1.6 与 §15.6。若遇到其他论文复用 DCPO 缩写，应按全称和数据形态重新核对。

## 10. DeepSeek-R1 与 RLVR：公开案例的位置

DeepSeek-R1 发布后，很多介绍会把 reasoning model 后训练简化成“GRPO 让模型会推理”。这个说法过于粗糙。

更稳妥的表达是：

```text
cold-start / SFT -> online sampling -> rule-based or verifiable reward -> RL optimization -> distillation / eval
```

在这条路线里，GRPO 是一种 policy optimization 方法；RLVR 是 reward 形式和任务类型；DeepSeek-R1 是公开展示这条路线影响力的代表案例之一。

R1-Zero 的实验把“无人工推理示范也能做 reasoning RL”变成了可讨论、可复现的研究问题。论文从 DeepSeek-V3-Base 出发，不经过 SFT，使用 GRPO；reasoning reward 由规则计算的答案正确性与格式奖励组成，两者等权，作者没有为该阶段使用 learned reward model。这个选择降低了 reward model 被优化器钻空子的风险，也把适用范围收窄到能可靠判答案或检查格式的任务。代价是输出可读性较差、会混用语言，且单靠窄域规则 reward 不足以建立写作、开放问答等通用行为。

DeepSeek-R1 不是把 R1-Zero 的一个 loss 换掉。公开报告描述的路线是：先收集数千条 cold-start 长推理示范；进行 reasoning RL，兼顾对话式推理与语言一致性；从 RL checkpoint 拒绝采样，再把推理和非推理数据混合做 SFT；最后再做一阶段 helpfulness / harmlessness RL，并将能力蒸馏到小模型。报告还披露约 80 万条监督样本，其中约 60 万条 reasoning、约 20 万条 non-reasoning。这个阶段组合分别处理了可读性、通用任务覆盖、偏好与安全、以及小模型迁移，因而最终结果不能归功于 GRPO 单项。[DeepSeek-R1 技术报告](https://arxiv.org/abs/2501.12948)

按这个公开的样本数粗算，reasoning 类约占 `600,000/800,000=75%`，non-reasoning 类约占 25%，样本数比例约为 3:1。它不等于训练 token 比例：长 reasoning 样本可能含有更多 token，阶段内的采样权重、packing、loss mask 和重复采样也会改变有效曝光。仅凭“75%”不能复刻数据混合，也不能断言 reasoning loss 贡献正好是其他类别的三倍；复现需要数据长度分布、实际 token 曝光、各阶段预算和拒绝采样规则。

R1-Zero 与 R1 的对照因此更适合作为配方问题，而不是单一算法排名。前者说明在 DeepSeek-V3-Base 与特定数学/代码 verifier 上，规则奖励可以驱动无 SFT 的探索；后者再加入 cold start、混合监督、偏好/安全 RL 和蒸馏，以改善语言一致性与任务覆盖。两条路线的数据、训练阶段和模型产物不同，不能把分数差全部归因于 SFT，也不能从 R1-Zero 的有效性推导开放写作和主观质量可以只靠答案正确率训练。

“无 SFT”指这条训练路线没有先对该模型做监督微调，并不表示策略从随机参数开始，也不表示它没有预训练形成的解题先验。base model 的语言模式、数学语料和模板敏感性会影响哪种行为容易被 reward 强化；因此复现实验应先测 base checkpoint 在同一 prompt/template 下的采样正确率和格式分布，再看 RL 带来的增量。若不固定底模与提示模板，模型原有能力和后训练效果会混在一起。

一个容易忽视的争论是“长 CoT 是否由 RL 从零创造”。DrGRPO 研究者在若干 base model 与 prompt 模板上观察到训练前已存在可采样的答题、反思行为，并指出 response-length normalization 会让错误长回答持续得到偏置更新。他们据此提醒，长输出随 reward 同时增长不能单独证明推理行为由 RL 新创造。该分析依赖其模型、模板、样本和行为检测方法；它削弱的是简单的因果叙事，不是否定 R1-Zero 的 RL 训练效果。

阅读 DeepSeek-R1 这类公开报告时要避免两个误区：

1. 不要把 DeepSeek-R1 的所有效果都归因于某一个 loss。公开资料里涉及 cold-start data、RL、verifiable reward、采样、评估和 distillation 的组合。
2. 不要把闭源或未披露细节写成确定事实。能讲的是公开论文和技术报告披露的训练范式、方法关系和工程启发。

把研究贡献拆成可回答的工程问题，可以这样说：

```text
DeepSeek-R1 的研究价值分成三层：R1-Zero 展示规则可验证任务上的无 SFT GRPO 路线；R1 的分阶段配方修复可读性和通用行为覆盖；蒸馏实验检验大模型 reasoning 轨迹能否迁移到小模型。限制也对应三层：规则奖励不能直接扩展到开放写作；多阶段数据和 reward 让单项贡献难以隔离；长推理仍受采样预算、语言一致性和 benchmark 迁移约束。面试或复现实验时应分别说出“解决了什么、证据来自哪里、还有哪些因果和迁移问题”，而不是把整条路线压缩成“GRPO 让模型会推理”。
```

## 11. 从 GRPO 到 DCPO：代表性方案分别修什么

这几个词经常一起出现，但层级不同。

```text
RLVR：reward 来源和任务类型
GRPO：一种 group-relative policy optimization 方法
DAPO：围绕长链 reasoning RL 稳定性和效率的改进路线
DrGRPO：针对 GRPO 长度偏置等问题的修正方法
```

更具体地说：

| 方法 | 它试图解决的问题 | 关键改动 | 代表性证据 | 仍需核对的边界 |
|---|---|---|---|---|
| RLVR | 数学、代码等任务的结果可以程序验证，但人工偏好难以给出稳定、低成本的训练反馈 | 用答案匹配、单元测试、执行环境或任务规则产生 reward；它是反馈/任务范式，不规定 optimizer | DeepSeek-R1-Zero 用规则奖励训练数学 reasoning；DAPO、DCPO 分别报告数学 RLVR 配方 | verifier 可能不完整、可投机；分数提升可能来自数据、模板、采样或系统，不自动迁移到开放对话 |
| GRPO | PPO 的独立 critic 增加显存、训练与调参成本 | 对同 prompt 采样的 group 使用组内 reward 均值/标准差构造 advantage，通常省去 value model | DeepSeekMath 将 GRPO 用于数学推理；R1-Zero 报告其无 SFT 的规则奖励路线 | 组内 reward 同值时 advantage 为零；长度归一化、reward 尺度、group size 和 rollout 分布都会影响更新 |
| DAPO | 长链 RL 中无区分度 group、低概率 token 被固定 clip、截断长回答和 response 长度分母等问题 | 组合 Clip-Higher、dynamic sampling、token-level loss、overlong filtering / soft penalty | Qwen2.5-32B 的 AIME24 progressive recipe 从 naive GRPO 30 到 50；组件是累积加入 | 是一套联合 recipe；dynamic sampling 改变题目分布，token 全局分母会增加长回答权重，消融不能视为独立因果排序 |
| DrGRPO | 按 response 长度求均值和按组内标准差缩放，可能让短回答 token 权重偏大，并让不同 reward 方差组获得不同尺度 | 去掉 `1/|o_i|` 和 group standard deviation 项；masked loss 使用固定 generation budget 作分母 | [作者报告](https://arxiv.org/abs/2503.20783v2)：Qwen2.5-Math-7B、MATH 三级至五级、Qwen-Math template 的训练在其 AIME24 设置达到 43.3%，约 27 小时、8 张 A100 | “unbiased”针对论文中的 policy-gradient 推导及采样假设；相同 reward 组仍无相对信号，未证明任何模型、任务都更好 |
| GSPO | 长 response 的 token 级 ratio / clipping 可能产生高方差，且更新单位与序列 reward 不一致 | 用序列似然构造几何平均 ratio，在 response 级 clipping 和加权 | 作者在 Qwen3 / MoE reasoning RL 设置报告训练稳定性和效率收益 | 不是普通整句重要性采样的乘积 ratio；整条 response 可能被 clip，结论绑定作者训练与系统设定 |
| DCPO | 固定 token clip 和当前组 reward 标准化让较多样本没有或很少产生更新信号 | 旧 token 概率相关的动态 clip、跨步平滑 advantage，以及 response 内 token mean | Qwen2.5-Math-7B AIME24 Avg@1/32 报告 46.7/38.8；四模型 RUR 平均 71.8% | RUR 是作者定义的非零 advantage 占比，不是正确率或有益梯度；数学数据、template 和采样协议限制外推 |

DrGRPO 的改动可以从 loss 的分母看得更清楚。设同一 prompt 的 group 有 `G` 条回答，`m_{i,t}` 是回答 `i` 中有效生成 token 的 mask，`T_{\max}` 是固定生成预算，`\bar R` 是该组 reward 均值，`A_i=R_i-\bar R`。一种对应论文机制的教学写法是：

```math
L_{\mathrm{DrGRPO}}=
-\frac{1}{G T_{\max}}\sum_{i=1}^{G}\sum_{t=1}^{T_{\max}}
m_{i,t}\min\left(
\rho_{i,t}A_i,\,
\mathrm{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i
\right)
```

标准 GRPO 的一类实现会先对每条回答的 token loss 除以该回答实际长度，再平均回答；这使短回答的每 token 权重更大。DrGRPO 用固定 `T_{\max}` 作为共同分母，保留实际产生的有效 token 项但不按当前回答长度重缩放。以 `T_{\max}=100` 为例，2-token 回答的总系数约为 `2/100`，100-token 回答则约为 `100/100`；逐回答取 token mean 会把两者都缩放到相近的总权重。它对准的是“长度归一化改变了 policy-gradient 权重”，不是“长回答天然更正确”。

DrGRPO 还把 GRPO 的标准化 advantage 改为只中心化、不除以 group standard deviation。若 reward 是 `[1,0]`，中心化结果是 `[0.5,-0.5]`；按总体标准差进一步标准化会得到 `[1,-1]`。去掉标准差缩放后，不同 prompt 的 reward 差值保留绝对尺度，减少组内方差对梯度尺度的影响；但这也要求 reward 在任务间有可比较、可控的尺度。若 group reward 全相同，中心化后仍全为零，因此 DrGRPO 不会替代 DAPO dynamic sampling 或 DCPO 的历史平滑机制。

读这些方法时可以按统一问题比较，而不是只记缩写：它改变了 advantage 的构造、ratio/clipping 的粒度，还是 token loss 的分母？它是否丢弃回答或 prompt、如何改变采样分布？公开结果使用什么 base model、任务、模板、reward 和评测预算？新机制带来的利用率提升是否也改善正确率、未见任务、长度切片和单位成功成本？这些问题能区分“方法针对的故障”与“作者报告的收益”。

表中数字的证据角色也不相同：DrGRPO 行引用的是作者报告的训练配方和 benchmark，DCPO 行同时列答案正确率与自定义 RUR，DAPO 行是同一论文逐步叠加组件的 progression，GSPO 行概述作者报告的训练稳定性观察。它们不能拼成一个跨论文排行榜。若要决定是否迁移，应先固定底模、训练题池、verifier、rollout token 预算、生成上限和评测 decoding，再一次只改变目标机制；同时保留完整过滤流量和任务难度切片。只有这样，表格才能用于提出可证伪的实验假设，而不只是复述各论文最好的数字。

因此不能简单说“DAPO 比 GRPO 好”或“DrGRPO 是新标准”。GRPO 给出较简单的 group-relative baseline；DAPO 以组合 recipe 处理无效采样、长回答和 token 更新；DrGRPO 针对长度与方差归一化的目标偏差；GSPO 改变 ratio 与 clipping 单位；DCPO 调整 token 窗口、优势统计和 reduction。它们有不同目标和实验协议，迁移前应做同模型、同数据、同 reward、同采样预算的对照，并报告答案质量、训练 token、rollout 成本、样本利用率和能力回归。长篇 verifier 与 RLVR 设计见本册第十六章。

2026 年还出现两个针对 clipping 粒度的早期预印本候选。DHPO 在 token-level 与 sequence-level importance ratio 之间做混合，并以 entropy 引导权重、分支专用 clipping；作者在 Qwen3 dense/MoE 数学推理设置中报告相对 GRPO 和 GSPO 的结果。[DHPO v1](https://arxiv.org/abs/2601.05607v1)将问题定位在细粒度 credit assignment 与序列稳定性之间的取舍。GAPO 则按 group rollout 的 advantage 调整 clip 边界，保持 PPO/GSPO surrogate 形态；作者报告它在若干低 base-pass-rate 数学和代码任务上改善 Pass@1 与 Pass@k。[GAPO v1](https://arxiv.org/abs/2609.00444v1)把 clipping headroom 分配给不同学习信号。两篇都是作者报告的特定模型、任务与训练协议，尚不足以形成普遍方法排序；比较时应检查它们是否改善外部正确率和单位成功成本，而不只看 ratio 或 clip 利用率。

把三种 loss reduction 放到同一组手算输入中，更容易看出“更新粒度”会改变什么。设短回答有 10 个有效 token，平均 loss contribution 为 0.5；长回答有 90 个 token，平均为 0.1。按 GRPO 的 per-response mean，再等权平均两条回答，结果是 `(0.5+0.1)/2=0.30`。按 DAPO 的全局 token mean，结果是 `(10×0.5+90×0.1)/100=0.14`；长回答因 token 更多，对整批目标的总贡献更大。按 DrGRPO 的固定预算，若 `T_max=100` 且 `G=2`，相同有效项的值为 `(10×0.5+90×0.1)/(2×100)=0.07`，短回答未生成的预算位置仍留在分母中。三个原始 loss 数值的尺度不同，不能只比谁更小；关键是看样本长度如何改变梯度权重，并在相同优化器、学习率、裁剪和数据协议下比较质量及成本。

## 12. 新模型后训练的共同抽象：领域专家、RLVR 与 on-policy distillation

前面的算法名容易让人误以为“选择一个 loss 就能得到 reasoning model”。DeepSeek-R1、GLM-5.3、gpt-oss 和 Grok 4.7 的公开披露分别展示了分阶段数据与 RL、长周期环境与 verifier、SFT 加高算力 RL、以及更长更难的任务训练。它们共同说明训练数据、交互环境、反馈和系统吞吐都影响后训练结果；每个案例披露的细节不同，不能从产品接口或 benchmark 倒推出未公开的 optimizer 与 reward 配方。

### 12.1 领域专家培养不是简单追加领域语料

领域专家训练通常包含四个环节：

1. **领域数据构造**：数学、代码、形式化证明、工具使用或科学任务需要有明确规格和可验证结果。
2. **专家 SFT**：用高质量解题轨迹、工具轨迹、错误修复轨迹建立基本行为。
3. **领域 RL / RLVR**：用答案校验、单元测试、Lean checker、工具执行或环境状态提供 reward。
4. **能力回归与混合训练**：在通用、事实、安全和对话任务上检查是否出现能力遗忘。

因此，“domain expert”更接近一套数据、验证器和训练阶段的组合，不等同于在通用模型后面加一个领域 prompt。

### 12.2 On-policy distillation 为什么重要

离线蒸馏只看教师预先生成的轨迹，学生遇到自己的错误分布时可能没有训练信号。On-policy distillation 让学生先按自己的 policy 生成状态和候选，再由教师、verifier 或规则提供指导。一个教学化目标可以写成：

```math
\mathcal{L}=\lambda_{\mathrm{distill}}
\mathbb{E}_{x\sim D,\,y\sim\pi_{\mathrm{student}}}
\left[D_{\mathrm{KL}}\left(\pi_{\mathrm{teacher}}(\cdot\mid x,y)\,\|\,\pi_{\theta}(\cdot\mid x,y)\right)\right]
+\lambda_{\mathrm{rl}}\mathcal{L}_{\mathrm{RLVR}}
+\lambda_{\mathrm{safe}}\mathcal{L}_{\mathrm{safe}}
```

这里 `y` 来自学生或当前 policy 的 on-policy 轨迹，而不是只来自教师的完美样本。真实系统可能使用 token-level、sequence-level、preference 或 verifier-weighted distillation；公式的重点是：蒸馏分布和学生会犯的错误有关。

这条式子还隐含三项约束：`\lambda_{\mathrm{distill}}`、`\lambda_{\mathrm{rl}}` 和 `\lambda_{\mathrm{safe}}` 应为非负有限权重，至少有一项为正；teacher 与 student 必须在同一候选 token 支持集上定义有效分布；KL 的 token mask 不能把空轨迹平均成零损失。教师在学生轨迹上给出低置信度或不支持的 token 时，需要规定回退、过滤或温度处理策略，否则“on-policy”只是在名称上成立。

做一个两-token 的数值例子：学生在自己采到的某个状态下给两个候选 token 的概率为 `[0.6,0.4]`，教师在同一状态给出 `[0.8,0.2]`。此处 `D_KL(teacher||student)=0.8 ln(0.8/0.6)+0.2 ln(0.2/0.4)≈0.0915` nat。蒸馏更新会在学生实际访问到的状态上增加教师偏好的第一项；若训练数据只由教师生成，学生走到不同错误状态时就没有这条监督信号。这个例子只展示分布差异，不覆盖 tokenizer 对齐、教师拒绝回答或置信度过滤；这些问题在第十七章详讲。

多教师 on-policy distillation（MOPD）进一步把多个领域 RL teacher 的能力蒸馏到 student 自己的 rollout 上；2026 年的原始预印本报告了 Qwen3-30B-A3B 和 MiMo-V2-Flash 相关实验，但这是特定任务和系统的作者报告。此处只把它作为 OPD 的多教师扩展入口，教师调度、冲突和成本留给[第十七章](17-on-policy-distillation.md)展开。[MOPD 论文](https://arxiv.org/abs/2606.30406v1)

### 12.3 公开模型案例：读训练披露，不猜内部配方

公开案例能让抽象方法落到真实工程约束，但厂商披露的粒度并不一致。先用表格划分“它解决的瓶颈”和“证据能支持的结论”，随后再看关键机制；厂商博客、发布页和论文的结论仍需按各自证据范围理解。

| 案例 | 公开披露聚焦的瓶颈 | 可支持的判断 | 仍未公开或不能据此推出 |
|---|---|---|---|
| DeepSeek-R1 / R1-Zero | 如何用可验证任务做 reasoning RL，同时补上可读性、通用行为与小模型迁移 | R1-Zero 的规则奖励 GRPO；R1 的 cold-start、RL、拒绝采样、SFT、再 RL 和蒸馏组合 | 最终增益不能归因单一 loss；规则 reward 无法覆盖所有开放任务 |
| GLM-5.3 | 长周期 coding / agent 任务的环境构造、可执行反馈与训练-采样系统吞吐 | Z.ai 披露任务环境扩展、可解性与 reward shortcut 检查、Megatron/SGLang 训练与 rollout 协同 | 完整数据集、optimizer、全部 reward 权重和独立复现结果未披露 |

#### 12.3.1 GLM-5.3：环境与 verifier 本身也是训练规模的一部分

Z.ai 说 GLM-5.3 沿用 GLM-5.2 的 base model，改进来自继续扩展 post-training：增加环境数量、任务多样性和训练计算。对长周期 coding 来说，真正难扩的并不只是 rollout 数量，而是任务必须可执行、可解、能验收，并且不能让模型靠 reward shortcut 取巧。官方描述的构造流程是：研究 agent 从真实工作模式合成长周期 runnable environment；judge agent 尝试任务以检查可解性；verifier 不读取参考解答生成；solver trajectory 用于发现并封堵奖励漏洞。oracle、no-op 和 unsolved-state 检查分别帮助判断正确方案能通过、无操作不能得分、未解决状态不能伪装成功。

这个设计说明 verifier 工程会反过来限定 RL 能学什么。只做 oracle check 仍不够：环境可能存在未覆盖状态、误判副作用、依赖脆弱顺序或只对某条参考路径有效。部署前应保留独立的成功条件、失败注入、状态差分和人类抽检，测量 false positive、false negative 与 shortcut rate，而不是把 verifier 自己打分当作真实正确性的证明。

系统侧，Z.ai 披露 slime 将 Megatron 训练、SGLang rollout 和数据 buffer 放进同一 dataflow；还提到 top-p mask、top-k / full-vocabulary OPD、训练与 rollout 的数值对齐，报告平均 log-prob 差约 `1e-7`，以及长周期 coding RL 吞吐提升超过 `2.3×`。[GLM-5.3 官方说明](https://z.ai/blog/glm-5.3)中的这些数字属于发布方系统测量，说明异步采样、数值一致性和环境时延会成为训练瓶颈；它们不是 GLM-5.3 的单一算法，也不能在缺少硬件、batch、轨迹长度、并发和基准实现时外推成通用加速比。

异步 rollout 还会带来策略陈旧问题：生成队列中的样本可能来自较早的 policy，而训练端已更新到新版本。运行记录应带上 rollout policy revision、样本等待时间或 staleness 分布，并检查过期样本是丢弃、降权还是 mask；否则更高吞吐可能同时改变实际优化的数据分布。DeepSeek-V4.1-Flash 的公开报告把 policy-lag 控制、stale-token mask 和训练中 checkpoint 切换/恢复作为其 RL/OPD 系统设计的一部分。[报告 v1](https://arxiv.org/abs/2609.19969v1)只支持该团队的公开方案，不说明这些策略对其他 rollout 架构有相同收益；OPD 的数据陈旧和教师信号边界见第十七、十八章。

#### 12.3.2 gpt-oss：公开了阶段目标，未公开优化器细节

OpenAI 说明 gpt-oss 采用与 o4-mini 类似的 SFT 阶段和高算力 RL 阶段，目标包括遵循 Model Spec、学习 CoT reasoning 与工具使用；模型卡还说明训练中没有对 CoT 施加直接优化压力。这提供了比“模型会推理”更具体的训练信息：它说明监督微调与 RL 各自进入 pipeline，也说明 reasoning trace 不是用人工标签逐 token 模仿出来的。[发布说明](https://openai.com/index/introducing-gpt-oss/)；[模型卡](https://cdn.openai.com/pdf/419b6906-9da6-406c-a19d-1bb078ac7637/oai_gpt-oss_model_card.pdf)

不过“高算力 RL”仍是阶段描述，不是算法配方。发布资料没有据此给出 policy optimizer、reward model / verifier、KL、采样策略或训练数据配比，因此不能补写为 PPO、GRPO 或某一种 reward 设计。发布资料中的 low / medium / high reasoning effort 是请求时预算控制接口；比较结果必须同时固定模型 revision、effort、prompt、工具和评测器，不能把 reasoning effort 当作训练方法证据。

#### 12.3.3 Grok 4.7：长周期目标与训练贡献的归因边界

xAI 披露 Grok 4.7 使用更大的 base model，并进行更长的 RL run；训练任务混合加大了困难任务权重，其中一些任务需要数小时完成。发布页还强调自验证和长上下文管理。它传达的工程方向是把任务完成、工具交互和中间校验纳入长周期训练，而不只奖励单轮答案。[Grok 4.7 官方发布说明](https://x.ai/news/grok-4-7)

公开披露没有给出具体算法、reward/verifier、训练样本量、额外计算量或独立消融。因为 base model 也变大，发布页上的 benchmark 差异不能单独归因于更长 RL。严谨复现要固定 base checkpoint、任务环境、最大墙钟预算、effort、重试和工具权限，并同时报告最终 artifact 的独立验证、任务成功率、交互步数、成本与有害副作用。

把这些案例放在一起看，训练出的能力和请求时允许使用的推理预算是两件事。SFT/RL 数据与环境塑造模型会做什么；`reasoning effort`、`thinking level` 或产品档位控制某次请求花多少推理计算。运行时字段可能影响质量、延迟、token 和成本，却不能单独证明训练算法。详见本册第十七章的 on-policy distillation 和第十八章的 DeepSeek-V4 配方案例。

## 13. PPO、DPO、GRPO、GSPO、DAPO、DrGRPO、DCPO 的选择逻辑

方法选择不是按模型名称套模板，而是先确定反馈能否验证、rollout 是否可承受、策略漂移需要多强的约束，以及哪些旧能力不能退化。下面的路线是实验起点；每条路线都需要用相同的评估集和 checkpoint 记录验证。

### 13.1 如果目标是通用聊天偏好

可以考虑：

```text
SFT -> DPO/IPO/KTO/ORPO -> safety tuning -> eval
```

原因是通用聊天偏好往往可以收集离线 preference 数据。DPO 类方法不需要在线 rollout 和独立 reward-model 更新环，系统更简单；它仍会受偏好数据覆盖、reference 质量、长度偏差和 policy drift 影响，不能把“离线”直接等同于“稳定”。

如果希望减少 reference model 依赖，也可以把 SimPO 放进这一类离线偏好优化候选中，但必须用回归评估控制 policy drift、输出长度和安全行为。

### 13.2 如果目标是数学和代码 reasoning

可以考虑：

```text
SFT/cold start -> online sampling -> rule-based reward -> GRPO/DAPO/DrGRPO/GSPO/DCPO -> eval
```

原因是数学和代码任务可以自动验证，在线 RL 能让模型探索新的推理路径。

### 13.3 如果目标是安全和格式约束

可以考虑：

```text
SFT safety data -> preference/constraint optimization -> red-team eval
```

可使用 DPO 或其他偏好/约束优化思路，也可以结合 rule-based reward；若使用本章所指的 DCPO，应明确它解决的是在线 RLVR 的动态 clipping，而不是安全约束算法本身。

### 13.4 如果资源有限

优先路线通常是：

```text
高质量 SFT -> 小规模 DPO -> 重点评估和数据迭代
```

不建议一开始就上复杂 online RL。

这里的“资源有限”不只是 GPU 数量少，也包括没有稳定的 rollout 服务、verifier 或可复现的评估集。若在线采样的吞吐低于训练吞吐，复杂 RL 可能把大量时间花在等待和过滤上；此时先提高 SFT 数据质量、做小规模 DPO 并建立回归集，往往更容易得到可解释的增益。

### 13.5 如果资源充足且任务可验证

可以做：

```text
大规模采样 -> verifiable reward -> GRPO/DAPO/DrGRPO/GSPO/DCPO -> 多轮迭代
```

这更接近 reasoning model 的训练思路。

选择方法时，可以沿着四个问题逐一排除：

| 问题 | 更适合的方向 | 主要代价 |
| --- | --- | --- |
| 是否只有离线 chosen/rejected？ | DPO、SimPO、IPO 等 | 不能主动探索当前 policy 的新路径 |
| 是否有可靠的程序或环境反馈？ | GRPO、DAPO、DrGRPO、GSPO、DCPO 等在线 RLVR；DHPO/GAPO 可作为早期预印本候选受控对照 | rollout、验证器和长度控制成本高；候选方法的证据与实现仍需复核 |
| 是否需要多目标安全/格式约束？ | SFT 加偏好/约束数据，并配合切片回归 | 多目标冲突，单一总分不够解释 |
| 是否需要严格控制策略漂移？ | 保留 reference/KL、replay 或分阶段训练 | 约束过强可能抑制新能力探索 |

表中的方法不是互斥开关。一个实际项目可能先 SFT，再 DPO 建立行为，再用 RLVR 强化代码或数学，最后用安全数据和回归样本修正副作用。所谓“选择 DPO 还是 GRPO”，首先是在选择反馈来源和采样方式，其次才是在选择优化公式。DHPO 与 GAPO 分别探索 token/sequence ratio 混合和 advantage 自适应 clipping；当前证据来自早期预印本，适合放在固定底模、题池、verifier 和预算的消融中与 GRPO/GSPO 对照，不应直接替代已建立的基线。

## 14. 数据要求对比

| 方法 | 数据形态 | 关键质量要求 |
|---|---|---|
| SFT | prompt + answer | 答案高质量、格式统一、覆盖目标任务 |
| Reward Model | prompt + chosen + rejected | 偏好可靠、差异明确、标注一致 |
| PPO | prompt + reward signal | reward 可用、KL 稳定、采样质量可控 |
| DPO | prompt + chosen + rejected | chosen/rejected 质量差异真实，避免虚假偏好 |
| SimPO | prompt + chosen + rejected | 偏好差异清晰，target margin 合理，长度和 policy drift 可控 |
| GRPO | prompt + 多条 sampled responses + reward | reward 可验证，group 内有区分度 |
| GSPO | prompt + sequence reward | 长序列 reward 可靠，长度和格式受控 |
| DHPO | prompt + rollout + token/sequence logp + reward | 两种 ratio 的支持集一致，entropy 权重和分支 clipping 可复现 |
| DAPO | prompt + rollout + reward/constraint | 有效样本比例高，难度和长度分布合理 |
| DCPO | prompt + rollout + old/new logp + verifiable reward | 动态 clipping 规则可复现，非零 advantage 和有效样本比例可解释 |
| GAPO | prompt + group reward + rollout importance ratio | group advantage 计算及自适应 clip 边界可复核，效果按任务与正确率切片报告 |

后训练数据的一个常见风险是 chosen 只是更长，而不是真的更好。可以用长度偏置做初筛：

```math
B_{\mathrm{len}}=
\frac{1}{N}
\sum_i
(\ell_i^+-\ell_i^-)
```

其中 `ell_i^+` 和 `ell_i^-` 分别是 chosen / rejected 的长度，`N>0`，且每对回答都应在同一 tokenizer 和同一 response mask 下计数。如果 `B_len` 过大，DPO 或 RM 很可能学到“长就是好”的伪偏好；若没有可比较的偏好对，统计量应报告为未定义，而不是填成 0。

这个统计量只能作为筛查，不足以证明存在长度偏置。数学证明、代码修复和安全解释本来就可能需要不同长度；更合理的分析是按任务类型、正确性等级和回答模板分层比较长度，并检查在控制长度后 chosen 是否仍然更常被选中。对在线 RL，还要分别观察 reward 与长度的相关性、被截断比例、达到正确答案所需的最短长度，以及模型是否通过重复、免责声明或无关推理刷高分。

## 15. 常见训练风险

### 15.1 Reward Hacking

模型学会骗 reward，而不是解决真实问题。

例如：

```text
输出很长，看起来很有逻辑，但答案是错的。
```

reward hacking 往往不是优化器“坏了”，而是 reward 只测到了目标的一个代理。比如格式检查器只检查 `<answer>` 标签，模型就可能把错误答案包在正确标签里；judge 偏好详细解释，模型就可能重复同一句话来增加表面完整度。定位时应把 reward 拆成正确性、格式、长度、引用和安全等分量，并抽取高 reward 低真实质量的样本做人工复核。

还要检查反馈标签本身是否正确。Zhu 与 Kang 的 2026 年预印本重新核验若干 RLVR 训练标签后，报告其特定数学设置中真正错误的标注使推理 benchmark 比干净数据低约 8—10%；在一个 Text2SQL 真实标注噪声设置中低约 5—12%。这些是作者指定数据、模型和预算下的对照，不是所有 verifier 的通用误差率；它提醒我们，程序能稳定执行不等于它验证了正确的目标。实践中应抽查 false positive / false negative、固定数据与 evaluator 版本，并保留可复现的反例。[论文 v2](https://arxiv.org/abs/2603.16140v2)

### 15.2 Length Bias

reward 偏好长答案或短答案，导致模型输出长度异常。

解决方式包括长度归一化、长度惩罚、按任务切片评估，但不能把“短”本身当作目标。对需要展开证明的数学题，过强的长度惩罚会让模型提前给出未经验证的答案；对工具任务，应该惩罚无效步骤和重复调用，而不是机械惩罚所有 token。

### 15.3 KL Collapse

policy 偏离 reference 太远，语言能力或安全行为退化。

它通常表现为 response 风格突然改变、重复率上升、训练 reward 继续增长但通用评估下降，或重要性 ratio 大量落在裁剪区外。解决方式包括 KL penalty、ratio clipping、参考模型约束、较小更新步长和 checkpoint 回滚；同时要先核对 KL 的统计粒度，是按 token、按 response 求和，还是按长度归一化，否则“KL 变大”的结论可能只是分母改变。

### 15.4 Over-Optimization

模型在训练 reward 上变好，但真实用户体验下降。

这在 reward model 质量不足、训练集过窄或 verifier 可被投机时尤其常见。一个实用对照是同时画出训练 reward、未见 prompt 的 reward、人工偏好和真实任务成功率；只有第一条上升时，应把它视为代理目标过拟合，而不是模型整体提升。

### 15.5 Catastrophic Forgetting

后训练过强导致 base model 的通用能力下降。

常见原因包括数据分布过窄、学习率过大、训练 token 不足以覆盖旧能力，或只对某一角色/格式做 response-only 监督。需要通用能力回归评估、replay 数据、混合 batch 或更保守的 reference 约束，并按语言、代码、数学、知识和长上下文切片观察，而不是只看一个平均 benchmark。

### 15.6 Safety Regression

推理能力提升后，安全拒答或边界控制变差。

推理能力提升后，模型可能更擅长完成危险请求，也可能变得过度拒答无害请求；二者都属于行为变化。reasoning RL 后尤其需要重新做 safety eval，并同时报告危险请求的正确拒答、无害请求的错误拒答、隐私泄露和工具执行风险。安全评估不是一次性的发布前动作，因为新数据、新工具和新 policy 都会改变攻击面。

后训练评估至少要同时看同题评分增益、安全召回、过度拒答和能力回归。同题评分增益只表示新 checkpoint 在同一评估样本、同一评分规程下得分更高的比例，不等同于人工偏好对的胜率：

```math
R_{\mathrm{score\_gain}}=
\frac{1}{N}
\sum_i
\mathbf{1}[s_{\mathrm{new},i}>s_{\mathrm{old},i}]
```

```math
R_{\mathrm{safe}}=
\frac{
\sum_i
\mathbf{1}[q_i=1]\mathbf{1}[\mathrm{refuse}_i=1]
}{
\sum_i\mathbf{1}[q_i=1]
}
```

```math
R_{\mathrm{over}}=
\frac{
\sum_i
\mathbf{1}[q_i=0]\mathbf{1}[\mathrm{refuse}_i=1]
}{
\sum_i\mathbf{1}[q_i=0]
}
```

```math
R_{\mathrm{reg}}=
\frac{
\sum_i
\mathbf{1}[z_i^{old}=1]\mathbf{1}[z_i^{new}=0]
}{
\sum_i\mathbf{1}[z_i^{old}=1]
}
```

其中 `N` 是同一组 prompt 上的新旧 checkpoint 都有分数的配对样本数，`s` 必须由相同 judge / rubric 计算；`q_i=1` 表示样本应该拒答，`z_i` 是能力评估是否通过。四个指标分别要求：配对样本数 `N>0`；至少有一个应拒答样本；至少有一个不应拒答样本；旧 checkpoint 至少有一个通过样本。缺少其中任一类样本时，相应比率没有定义，不能加一个 `\epsilon` 后报告接近 0 或 1 的伪结果。安全召回高但过度拒答也高，说明模型可能变得过保守；同题评分增益上升但 `R_{\mathrm{reg}}` 也上升，说明后训练可能损伤了旧能力。

用 demo 的四个配对评测行复算：新 checkpoint 在 3 行得分更高，所以 `R_score_gain=3/4=0.75`；唯一一个应拒答样本被拒答，`R_safe=1/1=1`；三个不应拒答样本中有一个被误拒，`R_over=1/3≈0.3333`。旧模型原先通过的三行里有一行在新模型上失败，因此 `R_reg=1/3≈0.3333`。这组数字展示为什么“安全召回为 100%”仍不足以判定更安全：同一批评测同时显示了明显的过度拒答和能力回归。样本很小，只是演示分母，不足以估计任何真实模型的质量。

这里的 `R_safe` 只度量“该拒答时是否拒答”，并不判断拒答内容是否给出了安全替代方案，也不判断模型是否泄露了危险细节。因此真实评估还需要独立的 harmfulness、safe-completion、leakage 和 tool-permission 指标；一个拒答率为 1 的模型，可能只是对所有请求都说“不”。

## 16. 现代后训练 pipeline 示例

一个更完整的现代后训练 pipeline 可以这样设计：

```text
1. Base model checkpoint 选择。
2. 高质量 SFT，建立指令遵循和基本回答格式。
3. 构造偏好数据，训练 reward model 或直接做 DPO 类优化。
4. 对通用偏好任务选择 DPO、SimPO、KTO、ORPO 等离线偏好优化方法。
5. 对数学、代码、工具调用任务构造 verifiable reward / RLVR。
6. 对数学、代码等可验证任务，用 GRPO/DAPO/DrGRPO/GSPO/DCPO 做同条件对照，而不是预先假定某个变体胜出。
7. 加入 safety、拒答、隐私和格式约束数据。
8. 使用安全/格式约束数据和切片评估做多目标行为控制；若采用 DCPO，则把它作为 RLVR 动态 clipping 的独立实验变量记录。
9. 做能力回归、安全回归、风格评估、长度评估和真实任务评估。
10. 根据失败样例刷新 SFT、preference 和 RL prompt pool。
11. 多轮迭代后选择进入下一阶段或服务候选的 checkpoint。
```

这比“跑一个 DPO”更接近真实系统。每个阶段都应该保留自己的数据版本、policy/reference checkpoint、reward 或 verifier 版本以及切片评估结果，这样下一阶段的提升才能追溯到具体变化。否则把 SFT、偏好优化和 reasoning RL 串在一起后，只看最终分数，很难知道是示范质量、奖励规则还是采样策略造成了结果。

## 18. 常见误判与诊断路径

前面的公式和方法谱系描述了训练目标，实际工程还需要从现象反推反馈、采样和更新环节。下面的场景把最容易混淆的判断展开为诊断路径：先识别观测到的行为，再检查数据和统计口径，最后决定是否改变训练方法。

### 18.1 同样叫“对齐”，反馈来源却不同

SFT 是监督学习，直接最大化高质量回答在给定 prompt 下的条件概率，主要建立指令遵循、格式和基本行为。DPO 是离线偏好优化，使用 chosen/rejected 对比较 policy 与 reference 的相对 log-probability，不需要显式 reward model 或在线 rollout，工程简单但受限于已有偏好数据。PPO 是在线 RLHF，模型先按当前 policy 采样，reward model 或规则给分，再用 advantage、ratio clipping 和 KL/reference 约束更新 policy；它更能探索新行为，但系统复杂、显存和采样成本更高。

比较三者时还要检查数据边界：SFT 的 response mask、DPO 的 response token 聚合、PPO 的 old policy/critic 状态都必须与实现口径一致，否则算法名称相同也不能保证训练目标相同。

### 18.2 离线偏好数据不足以替代在线探索

DPO 适合离线偏好对齐，但它主要学习数据集中已经出现的比较，缺少让当前 policy 自己探索新推理路径的机制。数学答案、代码单测、工具执行结果这类任务有可验证反馈时，可以让模型在线采样多条候选，再用 verifier 产生 RLVR reward；GRPO、GSPO、DAPO、DCPO 讨论的是这种在线更新中的不同稳定性和样本利用问题。因此 DPO 仍然重要，却不能覆盖需要探索和程序验证的 reasoning RL。

### 18.3 group reward 没有区分度时，GRPO 没有有效方向

PPO 通常借助 value/critic 估计 advantage；GRPO 对同一个 prompt 采样一个 group，利用组内 reward 的均值和方差构造相对 advantage，通常减少独立 critic 的训练和显存开销。它特别适合数学、代码等可验证任务，但 group 内 reward 没有区分度时就没有有效方向，group size、reward 稀疏性、长度和 ratio/KL 仍然决定训练稳定性。

### 18.4 什么时候需要在线采样

因为目标不只是模仿已有答案，而是让模型探索当前 policy 可能产生的新路径。在线采样得到的是模型自己的错误分布和候选解法，verifier 再判断哪些路径正确，更新就能直接作用于模型实际会走到的状态。离线偏好数据仍然适合建立格式和偏好，但很难覆盖所有新出现的推理路径；在线 RL 的代价则是 rollout、验证器、去重和失败样本处理。

### 18.5 近年方法分别改动了哪一层

GSPO 把重要性比率和 clipping 提升到 response 序列级，试图让整条长回答的 reward 与更新单位更一致。DAPO 是一套面向大规模 reasoning RL 的组合 recipe，公开论文重点讨论 decoupled/clip-higher、dynamic sampling、token-level loss 和 overlong reward shaping。DrGRPO 调整 response 长度与组内标准差归一化。DHPO 混合 token 与 sequence ratio；GAPO 按组内 advantage 调整 clip 边界。DCPO 在本章指 Dynamic Clipping Policy Optimization，针对固定 token clipping 造成的零梯度和样本利用率问题，引入动态 clipping 与平滑 advantage。这些方法都处于在线 RLVR 语境，但论文版本、实现细节和证据强度不同，不能只用“新算法更好”概括；DHPO、GAPO 当前是早期预印本候选。

### 18.6 如何识别并控制能力退化

先用 KL/reference 或较小更新控制 policy 漂移，再把通用能力、安全、格式、长度和真实业务样本作为独立回归集；必要时混入 replay 数据，比较 base、SFT 和 RL checkpoint 的逐切片变化。对 reward hacking，要检查训练 reward 与未见任务成功率是否背离；对安全，要同时看正确拒答和过度拒答。最终结论应保留原始输出和评估版本，而不是只看一个偏好胜率。

### 18.7 从训练日志定位分布和系统问题

若 reward 持续上升而留出集正确率停滞，先审计 verifier 的 false positive、参考解覆盖和隐藏测试是否泄漏，再检查有效样本率与不同难度的通过率；RUR 或非零 advantage 占比高，只能说明更多回答进入了更新，不能证明这些梯度改善任务能力。若全组 reward 相同，应报告无区分度 group 的比例，并核对题目难度、采样温度和 verifier 分辨率；给标准差随意加 epsilon 只会避开除零，不会产生组内相对信号。

若拒答召回提高但帮助性或安全总体分数变差，按 `should_refuse` 和风险类别拆成正确拒答、错误服从、过度拒答、正确帮助四格，并检查各自分母。随后确认同一个 prompt、模板、采样配置和评测器用于新旧 checkpoint；只看总拒答率无法区分安全改善与普遍拒答。若回答长度或截断率突然变化，则同时查看生成 token 数、EOS/长度上限命中率、按 response mean 与全局 token mean 计算的 loss，以及长短任务切片，判断是数据组成变化还是 reduction 改变了梯度权重。

异步训练的 reward 和吞吐还需与 rollout policy revision、样本等待时间、staleness、丢弃或 mask 比例一起读。若训练侧 log-prob 与 rollout 侧不一致，应先核对 tokenizer、数值精度、采样配置和 log-prob 汇总口径；若 checkpoint 切换时出现异常，追踪旧 rollout 是否继续进入新策略的更新。DeepSeek-V4.1-Flash 与 TRL 的公开资料展示了这些检查信号的具体实例，但字段和策略绑定各自报告或 trainer 版本；通用排障原则是显式记录生成策略、样本状态和损失 mask，而非假定任意异步流水线语义相同。深入的陈旧轨迹和 OPD 处理见本册第十七、十八章。

## 19. 本章小结

本章扩展了后训练和对齐强化训练的方法谱系。

核心结论如下：

1. 后训练不等于 SFT，也不等于只做 DPO。
2. PPO 是经典 RLHF 方法，适合在线 reward 优化，但工程复杂、成本高、稳定性挑战大。
3. DPO 是重要的离线偏好优化方法，简单稳定，但不适合覆盖所有 reasoning RL 场景。
4. GRPO 用 group 内相对 reward 构造优化信号，适合数学、代码等可验证任务。
5. DrGRPO 质疑 response-length 与 group-standard-deviation 归一化，并以固定 generation budget 作共同分母；它仍依赖可区分的 reward。
6. GSPO 类方法把 ratio / clipping 单位改到 sequence，目标是对齐长回答 reward 与更新粒度。
7. DAPO 组合动态采样、Clip-Higher、token-level reduction 和 overlong 处理；报告收益属于联合 recipe。
8. DCPO 以旧 token 概率决定动态 clipping，并组合平滑 advantage 与 response 内 token mean。
9. 现代后训练 pipeline 往往结合 SFT、偏好优化、online RL、verifiable reward、安全约束和回归评估。
10. 方法选择要看任务类型、reward 形式、loss reduction、资源预算和稳定性要求。
11. 比较代表方案时，要讲清它解决的瓶颈、公开证据、代价、限制和同条件下的改进实验，而不是只背 loss 或榜单名次。
12. DHPO 与 GAPO 分别探索 token/sequence ratio 混合和 advantage 自适应 clipping；当前只能按早期预印本及其任务设置理解，不能当作通用默认方法。

后训练的核心不是把某个算法名换成更新的缩写，而是把反馈信号、采样分布、更新粒度和回归证据对应起来。看到一个新方法时，先问它改变了哪一个环节，再问它的 benchmark 是否覆盖了目标任务。

## 20. 资料与进一步阅读

下面按证据类型列出资料。原始论文适合核对算法定义和实验设定，框架文档适合核对实际 API，模型卡和产品文档只能证明公开的配置或接口，不能证明未公开的内部训练细节。

### 经典方法与原始论文

- [Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)：InstructGPT 的 SFT、reward model 和 PPO-RLHF 路线。
- [Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347)：PPO 的 clipped policy objective 和 advantage 更新背景。
- [Direct Preference Optimization](https://arxiv.org/abs/2305.18290v3)：DPO 将偏好优化写成 policy/reference 相对概率目标的原始论文。
- [A Survey of Post-Training Scaling in Large Language Models](https://aclanthology.org/2025.acl-long.140/)：建立 SFT、反馈式 RL 和 test-time compute 等后训练分类；综述中的问题清单不等于某种方法的实验结论。
- [Towards a Unified View of Large Language Model Post-Training](https://arxiv.org/abs/2509.04419)：v2（2026-01-20）把不同后训练方法拆成稳定掩码、参考策略分母、优势估计和似然梯度等选择，并提出动态组合监督信号的 HPT；实验集中在数学推理及其分布外套件，适合比较离线示范与在线探索的目标假设，不是已验证的通用训练配方。
- [A General Theoretical Paradigm to Understand Learning from Human Preferences](https://arxiv.org/abs/2310.12036)：IPO 的有限目标间隔和平方损失；论文问题设定不代表其在更大模型上普遍优于 DPO。
- [Kahneman-Tversky Optimization](https://arxiv.org/abs/2402.01306)：KTO 使用 desirable / undesirable 单样本反馈的偏好优化目标。
- [ORPO: Monolithic Preference Optimization without Reference Model](https://arxiv.org/abs/2403.07691)：把 SFT 与 odds-ratio preference 项组合的 reference-free 方法。
- [DeepSeekMath](https://arxiv.org/abs/2402.03300)：GRPO 和可验证数学 reward 的公开来源。
- [SimPO](https://arxiv.org/abs/2405.14734)：reference-free、平均 log probability 和 target margin 的原始论文。
- [DeepSeek-R1](https://arxiv.org/abs/2501.12948)：reasoning RL、cold start、RLVR 和 distillation 的公开技术报告。
- [DAPO](https://arxiv.org/abs/2503.14476v2)：Decoupled Clip and Dynamic Sampling Policy Optimization 及其开源大规模 RL 系统。
- [Understanding R1-Zero-Like Training](https://arxiv.org/abs/2503.20783v2)：GRPO 长度偏置分析与 DrGRPO 方案；论文结论应按其模型和任务设定理解。
- [Group Sequence Policy Optimization](https://arxiv.org/abs/2507.18071v2)：序列级 importance ratio、clipping 和 MoE RL 稳定性的公开来源。
- [DCPO: Dynamic Clipping Policy Optimization](https://arxiv.org/abs/2509.02333v2)：本章所指 DCPO 的动态 clipping 与平滑 advantage 方案。
- [DHPO: Orchestrating Tokens and Sequences](https://arxiv.org/abs/2601.05607v1) 与 [GAPO: Group Adaptive Clipping Policy Optimization](https://arxiv.org/abs/2609.00444v1)：2026 年早期预印本，分别探索 token/sequence importance-ratio 混合和 advantage 自适应 clipping；实验仍绑定作者所列模型、任务与实现。
- [Scaling Laws for Reward Model Overoptimization](https://proceedings.mlr.press/v202/gao23h.html)：说明代理 reward 持续优化可能与真实 reward 脱钩；结论绑定其合成与评测设置。
- [RLAIF vs. RLHF](https://arxiv.org/abs/2309.00267) 与 [Constitutional AI](https://arxiv.org/abs/2212.08073)：分别作为 AI feedback 与原则驱动自我批评/修订路线的研究入口。

### 框架与官方训练披露

- [Hugging Face TRL DPO Trainer](https://huggingface.co/docs/trl/main/en/dpo_trainer)：核对 DPO 数据格式、response mask 和 Trainer 参数；具体版本行为以安装版本为准。
- [Hugging Face TRL GRPO Trainer](https://huggingface.co/docs/trl/main/en/grpo_trainer)：核对 group rollout、reward 函数、advantage 和 GRPO 训练接口。
- [GLM-5.3 官方博客](https://z.ai/blog/glm-5.3)：发布方关于长周期 coding 环境、verifier 检查和训练/rollout 系统的披露；页面 benchmark、log-prob 差与吞吐数据均为发布方报告，不能视作独立复现。
- [Introducing gpt-oss](https://openai.com/index/introducing-gpt-oss/)：OpenAI 披露 SFT、高算力 RL、CoT/工具目标与未直接监督 CoT；未披露具体 optimizer 和 reward recipe。
- [Introducing Grok 4.7](https://x.ai/news/grok-4-7)：xAI 披露更长 RL run 与多小时任务导向；未披露算法、reward 和完整消融。

资料的可信度需要分层：arXiv 原始论文能证明作者公开提出了某个方法，但不自动证明其结论适用于所有模型；官方 model card 能证明发布者公开了某项配置，但不能证明完整训练流程；API 文档能证明调用时的协议和运行时控制，但不能反推出模型内部如何进行 SFT、偏好优化或 RL。面对高时效的模型名、别名和产品档位，必须记录访问日期和具体版本。
