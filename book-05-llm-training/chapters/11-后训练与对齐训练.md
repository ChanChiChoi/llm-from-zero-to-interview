# 第十一章：后训练与对齐训练：从会续写到可靠协作

预训练让模型学会根据已有文字继续生成。它没有直接告诉模型：用户提问时要回答问题、要遵守格式、要在危险请求前停下来，也没有规定遇到数学题时怎样判断答案对不对。后训练就是把这些行为目标变成模型能学习的信号。

**背景：** 预训练目标关注下一个 token 是否像训练文本中的延续；助手还需要判断用户意图、选择回答方式并遵守行为边界。

**目的：** 用示范、偏好、可验证结果和安全评估，逐步塑造模型面对真实请求时的回答行为。

**解决的问题：** 让模型从“能生成像样的文字”进一步学会“按任务要求行动”。不同反馈各有盲点：示范没有覆盖所有回答，偏好分数不等于事实，自动验证器也可能写错或被投机。

**意义：** 后训练不是某一个算法，也没有一套对所有任务都适用的固定步骤。它要把正确的反馈接到合适的训练方法上，再用独立评估检查模型是否真的变好。

本章用一道题贯穿主要概念。用户问：“3/4 + 1/4 = ?”

| 训练信号 | 本例给模型或训练器的材料 | 它能教什么 |
| --- | --- | --- |
| 示范回答 | “分母相同，把分子相加：4/4，所以答案是 1。” | 模仿一种可接受的回答方式 |
| 偏好比较 | chosen：“分母相同……答案是 1。”；rejected：“答案是 2。” | 哪个已有回答更受偏好 |
| 可验证反馈 | 模型自己生成答案，程序检查化简后的结果是否为 1 | 当前生成结果是否满足明确的答案条件 |
| 安全评估 | 比较“帮我盗号”和“怎样重置自己的密码”两种请求 | 哪种情况应拒绝，哪种情况应正常帮助 |

这道算术题适合讲自动验证，因为答案可以规范化后检查。它不能代表开放式写作或安全判断；那些任务没有同样可靠的单一答案，通常需要偏好标注、专门规则和人工评估配合。

本章先解释反馈如何进入训练，再沿 PPO-RLHF 的伪代码完整走一轮，接着比较离线偏好优化与在线 RLVR，最后讨论训练配方、评估和常见风险。长篇 verifier 设计、领域专家训练、on-policy distillation 和具体模型配方分别见本册[第十六章](16-rlvr与可验证奖励.md)、[第十五章](15-领域专家sft与rl.md)、[第十七章](17-on-policy-distillation.md)和[第十八章](18-deepseek-v4领域专家与统一蒸馏.md)。

## 1. 后训练使用什么反馈

### 1.1 SFT：先教模型一种可用的回答方式

监督微调（SFT）使用示范回答。对本章的题目，训练样本可以是：

> 用户：3/4 + 1/4 = ?
>
> 助手：分母相同，把分子相加：3+1=4，所以 4/4=1。

训练时，模型把用户问题和已经生成的回答前缀当作上下文，逐步预测示范回答的下一个 token。训练器提高示范中 assistant 回答 token 的概率，让模型学会这类回答怎样组织。汉字、标点和数字会由 tokenizer 切成真实 token；训练器按真实切分和 mask 计算，不按汉字数量猜 token 数。

可以把一条训练记录中的位置这样理解：

| 位置 | 模型看到的内容 | 是否作为 assistant 目标 |
| --- | --- | --- |
| 用户问题 | 3/4 + 1/4 = ? | 否，作为上下文 |
| 助手回答 | 分母相同，把分子相加…… | 是，按目标回答学习 |
| padding 补位 | 为了组成批次而补齐的位置 | 否，mask 排除 |

结束标记 EOS 是否纳入目标、工具调用字段是否纳入监督，要按任务模板决定；但用户输入和 padding 不应误当成 assistant 的目标回答。如果截断后没有任何有效 assistant token，训练器就没有可学习目标，应先检查数据和 mask。

**目的：** 用示范建立基本指令遵循、回答格式和常用行为。

**适用场景：** 已经有高质量的目标回答、操作轨迹或工具使用示范，希望模型先学会基本行为时。

**优缺点：**

- **优点：** 训练信号直观，容易检查示范是否符合要求。
- **局限：** 模型主要模仿示范覆盖的行为；示范有误或覆盖窄，模型也可能学到错误和盲区。SFT 本身不会告诉模型两个未见回答哪一个更受偏好。

### 1.2 Reward Model：把回答比较变成整条回答的分数

偏好标注不一定要求人写出标准答案。标注者可以看到同一个问题的两个回答，然后选更合适的一个：

| 项目 | 内容 |
| --- | --- |
| Prompt | 3/4 + 1/4 = ? |
| chosen | 分母相同，把分子相加：4/4，所以答案是 1。 |
| rejected | 答案是 2。 |

经典标量 Reward Model（RM）读取 prompt 和完整回答，对整条回答输出一个分数。训练时，它反复看到同题 chosen 应排在 rejected 前面，逐渐学会按标注偏好排序。比如教学中假设 RM 给 chosen 打 0.8、给 rejected 打 -0.2；这两个数只说明本例中它把 chosen 排得更高，不是正确率、概率或跨题通用的分数刻度。

**这里要分清两个模型：** RM 给整条回答一个偏好分；PPO 中的 critic 则对生成过程中的多个前缀估计后续回报。RM 不是逐 token 评价器，critic 也不是人工偏好评分器。

RM 学到的是标注规则和标注者偏好，不自动知道答案是否真实。若标注者偏好长解释，它可能把“更长”当作“更好”；如果标注数据把错误答案标成 chosen，RM 也可能把这个错误排序学进去。对同一道数学题，可另用答案检查器确认 1 正确；RM 分数不能代替这项检查。

**目的：** 把许多成对判断浓缩成训练时可以调用的偏好信号。

**适用场景：** 回答质量涉及帮助性、完整度或风格等难以写成精确规则的属性，而且能获得可信偏好标注时。

**优缺点：**

- **优点：** 训练后可以给新回答打分，不必为每条新回答都临时找标注者。
- **局限：** RM 是偏好代理，可能被 policy 迎合；它的分数不证明事实正确，也不宜拿来比较不同任务的绝对质量。

### 1.3 RLHF：让模型根据反馈调整自己生成的回答

RLHF 把语言模型看作逐步生成回答的策略（policy）。模型先生成回答，再由 RM 或其他可信反馈评分，训练算法据此提高较好回答的生成倾向。InstructGPT 报告过“示范做 SFT、偏好比较训练 RM、再用 PPO 优化 policy”的代表路线；这是一种历史上重要的做法，不是所有后训练都必须照走的流水线。[InstructGPT 技术报告](https://arxiv.org/abs/2203.02155)

沿用算术题：人标注“答案是 1”优于“答案是 2”，RM 从偏好对学习排序；policy 自己生成一条新回答后，RM 再给这条完整回答评分；PPO 把这个分数连同相对 SFT reference 的约束转成更新信号。具体的旧策略概率、critic、GAE 和 clipping 见本章 §3，不在这里先堆公式。

### 1.4 离线偏好优化：直接学习已经收集的比较

DPO、IPO、KTO、ORPO 和 SimPO 都属于离线偏好优化的相关路线，但它们使用的标注形态和训练目标不同。它们可以直接学习已有数据，不要求每个训练步骤都让当前 policy 重新采样回答。

以表中的 chosen/rejected 为例，离线方法在训练期间反复学习“这条回答比那条更受偏好”。如果 policy 后来生成了新的解法，而数据集里没有类似比较，离线训练不会自动请人或程序给新回答评分。离线方法因此适合已有反馈数据，不会替代在线探索或 verifier。

### 1.5 Reasoning RL 与 RLVR：程序能检查的任务可以直接验证结果

数学、代码和部分工具任务可以把要求写成检查步骤。对本例，一个答案检查器可以先把“4/4”“1.0”和“1”规范化，再检查化简结果是否等于 1：

| 当前 policy 生成的完整回答 | 检查器结果 | 可用反馈 |
| --- | --- | --- |
| 分母相同，分子相加，4/4=1。 | 解析成功，结果为 1 | 通过 |
| 3+1=5，所以答案是 5/4。 | 解析成功，结果不为 1 | 不通过 |
| 答案是 1，但没有可解析的最终答案字段。 | 若任务要求指定格式，则格式检查失败 | 按任务契约处理 |

这是一条完整反馈链：当前模型生成回答，检查器按预先写定的规则判断，训练器再把结果交给 PPO、GRPO 等更新方法。RLVR（reinforcement learning with verifiable rewards）说的是“反馈可验证”的任务路线，不是某一种 optimizer。若 parser 把正确答案误判为错，或允许模型只猜对最终数字而不检查推理过程，训练得到的目标就会偏离作者原意。

**适用场景：** 答案或动作能由可靠规则判断，例如数学答案、代码单元测试、格式约束或沙盒任务状态。

**优缺点：**

- **优点：** 反馈成本可低于逐条人工偏好标注，并能直接检查当前 policy 新生成的候选。
- **局限：** verifier 只覆盖它写明的条件；答案解析、测试覆盖和环境权限若有漏洞，模型可能学会通过检查器却没有完成真实目标。

### 1.6 安全对齐：判断何时拒绝，也要判断何时正常帮助

安全行为不只是让拒答更多。看两条请求：

| 用户请求 | 合适的行为 |
| --- | --- |
| 帮我窃取别人的账号。 | 拒绝协助，并可转向合法的账号安全建议 |
| 怎样重置我自己的密码？ | 正常提供安全的重置步骤 |

如果模型把两题都拒绝，危险请求确实没有得到帮助，但无害用户也被错误拒绝了。评估时应分别计数危险请求的正确拒绝和无害请求的过度拒绝；总拒答率上升本身不能说明安全性改善。安全训练还需结合拒答示范、偏好反馈、工具权限和红队测试，不能期待单个 loss 覆盖所有风险。

## 2. 先分清反馈、更新方法和训练配方

读到新缩写时，先问它处在哪一层。否则容易把“反馈来源”“更新算法”和“整套系统配方”误当作同类方法互相替代。

| 层次 | 要问的问题 | 本章例子 | 不能由名称推出的事 |
| --- | --- | --- | --- |
| 反馈与任务 | 谁判断回答好不好？ | 人类偏好、AI 反馈、答案检查器、代码测试 | 不决定用哪种优化器，也不保证反馈可靠 |
| 参数更新 | 训练器怎样改变模型？ | SFT、PPO、DPO、GRPO、GSPO 等 | 不决定 reward 来自人、模型还是程序 |
| 训练配方与系统 | 数据、采样、过滤、更新和基础设施怎样组合？ | DAPO、DeepSeek-R1 的分阶段路线、长周期 coding 环境 | 不能把整套配方效果归因于其中一个 loss |
| 推理时计算 | 用户请求到来后再花多少计算？ | 多次采样、搜索、reasoning effort | 不是训练期的 policy optimization |

比如，“RLVR + GRPO”可以同时成立：RLVR 说明这道数学题用可检查的答案给反馈；GRPO 说明同一题采样多条回答并用组内相对 reward 更新 policy。DAPO 则是包含采样、clip、token loss 和长度处理的组合式训练方案，不能和一个单独公式简单等同。

## 3. PPO-RLHF

**背景（PPO 算法）：** 在强化学习里，策略（policy）是模型在当前状态下选择下一动作的概率分布；对语言模型来说，状态是 prompt 加回答前缀，动作就是下一个 token。普通策略梯度可以按采样结果更新这组概率，但如果拿同一批回答反复更新，策略可能一下子改变太多。信赖域策略优化（TRPO）通过限制新旧策略的差异来控制更新，却要近似求解带约束的优化问题，实现更复杂。PPO 于 2017 年提出，常见的裁剪形式用代理目标减少策略比率越过范围后仍继续推动更新的动力，同时允许对同一批样本做多轮小批量更新；原论文在机器人运动和 Atari 等强化学习任务中评估了它。[PPO 原论文](https://arxiv.org/abs/1707.06347)

**背景（语言模型偏好）：** “预测下一个 token”和“按用户意图给出有用、安全的回答”不是同一个目标。监督微调（SFT）教模型模仿示范回答，但许多问题没有唯一的标准措辞。拿本节的题目来说，标注者可以比较“答案是 $1$。”和“答案是 $2$。”，指出哪个回答更合适；reward model 从许多这样的比较中学习给完整回答打分。早期工作已把人类偏好学习用于自然语言任务；InstructGPT 后来采用“示范做 SFT、偏好比较训练 reward model、再用 PPO 优化策略”的流程。[Ziegler 等人的语言偏好学习研究](https://arxiv.org/abs/1909.08593)，[InstructGPT 技术报告](https://arxiv.org/abs/2203.02155)

**目的：** PPO-RLHF 要用偏好信号继续调整 SFT policy，让它更常生成被人偏好的回答，同时用 reference KL 控制它偏离 SFT 的程度。在这道题里，偏好样本告诉训练器“答案是 $1$。”优于“答案是 $2$。”；RM 再给 policy 实际生成的完整回答打分，作为优化信号。

**解决的问题：** PPO 解决策略怎样利用采样回答进行多轮更新、又减少更新过大的推动；RLHF 则把人对回答的比较转成可用于训练生成策略的奖励。clipping 约束 PPO 新旧策略比率的优化压力，reference KL 约束当前 policy 与 SFT reference 的偏离，二者作用不同。它们都不能证明本例的答案在数学上正确，正确性仍需单独检查。

**意义：** 把这几种作用分开，读者就能看懂为什么同一条回答会经过 RM、reference、critic 和 policy 的不同计算，也不会把 RM 高分误当成事实正确。本节沿这条链展开：`SFT → 偏好数据训练 reward model → policy 采样 → reward 加 KL → critic 算 advantage → PPO 更新 → 评估并重复`。下面用虚构的约 320 亿参数模型“云舟-32B”把模型来源和一轮训练串起来。假设预训练已完成；题目和分数都是教学设定，不是实际训练配方。伪代码只保留主要动作，具体计算会在后文用同一条回答展开。

```python
# 云舟-32B-Base 经指令示范数据做完 SFT，得到这个 checkpoint。
sft_32b = load("云舟-32B-SFT")

# 从同一份 SFT 权重分出 PPO 所需的四个角色。
policy_model = copy(sft_32b.model)                  # πθ：继续训练
reference_model = freeze(copy(sft_32b.model))       # πref：固定不变

preference_data = [
    ("3/4+1/4=?", "答案是 1。", "答案是 2。"),  # prompt, chosen, rejected
    ...
]
H = sft_32b.hidden_size
reward_model = copy(sft_32b.model)
reward_model.score_head = Linear(H, 1)  # 回答末尾 hidden state [H] → 整条回答一个分数
train_reward_model(reward_model, preference_data)
freeze(reward_model)

critic_model = copy(sft_32b.model)
critic_model.value_head = Linear(H, 1)  # 每个生成位置的 hidden state [H] → V(prefix)

# 每轮：采样回答 → 计算训练信号 → 更新 policy 和 critic。
for prompts in prompt_batches:
    rollout = policy_model.sample_and_record(prompts)  # 回答 + 这批的旧概率 πold
    # 本批可能采到：“分母相同，分子相加，得到 4/4=1。”
    rewards = shape_rewards(reward_model, reference_model, rollout, beta)  # 回答打分，再扣 KL 代价
    advantages, returns = GAE(rewards, critic_model.value(rollout))
    update_policy_with_PPO(policy_model, rollout, advantages)
    update_critic(critic_model, rollout, returns)
    evaluate(policy_model)
```

上面的伪代码把模型怎样来、每轮怎样接力都列出来了。先对齐各模型的来源：`云舟-32B-Base` 用示范问答做 SFT，得到 `云舟-32B-SFT`；policy 和 reference 都从这份 SFT 权重复制。policy 会继续更新，reference 冻结，作为“不要离 SFT 行为太远”的比较基准。reward model 也从 SFT 权重复制，接上 `score_head`，用同一问题下的 chosen/rejected 回答训练：例如 prompt 是 $3/4+1/4=?$，chosen 可以是“答案是 $1$。”，rejected 可以是“答案是 $2$。”，训练目标是让前者得分更高；完成后 RM 冻结。到了 PPO rollout，RM 读取 prompt 和一条完整回答，只给这一整条回答一个分数。critic 则从 SFT 权重复制并接上 `value_head`；对后面这条六 token rollout，它会在六个生成位置各输出一个前缀价值预测，学习“从这个前缀继续生成，预计能得到多少回报”。这个 value 不是 token 的偏好分，也不是 RM 对整条回答的分数。为便于看清职责，伪代码把这些模型分开写；实际实现可以共享骨干。

现在沿 `for` 循环逐行走一遍，看看一条回答怎样变成 policy 和 critic 的训练信号。

**步骤 1：`sample_and_record` 让 policy 生成回答，并记下当时的概率。** 输入是这一批 prompt，例如 $3/4+1/4=?$。policy 生成“分母相同，分子相加，得到 $4/4=1$。”为把后面的计算串起来，假设这次回答在教学算例中切成下面六个 token 片段：

| 位置 $t$ | 本例假设的 token 片段 $y_t$ | 采样时记录的 $\log\pi_{\mathrm{old}}(y_t\mid s_t)$ |
|---:|---|---:|
| 1 | `分母` | $-0.30$ |
| 2 | `相同，` | $-0.24$ |
| 3 | `分子` | $-0.35$ |
| 4 | `相加，` | $-0.28$ |
| 5 | `得到` | $-0.18$ |
| 6 | `4/4=1。` | $-0.25$ |

这六段是为了演算而设定的 token 切分，不代表某个真实 tokenizer 一定如此；实际训练按 tokenizer 产出的 token 和有效位置 mask 计算。每个 log probability 都是在当时的前缀 $s_t$ 下，policy 选中对应 token $y_t$ 的概率取对数。生成这批回答的 policy 快照记作 $\pi_{\mathrm{old}}$。它不是额外训练的第五个模型：训练器保留这些旧 log probability，后面更新 policy 时就能和生成回答时的概率比较；后续各步也沿用同一条回答。

**步骤 2：`shape_rewards` 让训练器评估偏好，并计算 policy 偏离 reference 的代价。** reward model 读取 prompt 和完整回答“分母相同，分子相加，得到 $4/4=1$。”，只输出一个序列分数。假设它给这条回答 $1.50$ 个教学奖励单位。它的训练数据告诉它哪个回答更受偏好，但这个分数不是数学正确性的证明，也不是给六个 token 各打一个偏好分。reference model 则对 rollout 中相同的六个 token、相同的前缀计算 log probability。对第 $t$ 个 token，令 $s_t$ 表示生成它之前的 prompt 和回答前缀，采样回答的最后一个有效 token 位置记作 $T$：

```math
d_t=
\log \pi_{\mathrm{old}}(y_t\mid s_t)
-
\log \pi_{\mathrm{ref}}(y_t\mid s_t),
\qquad
r_t=-\beta d_t+\mathbb{1}[t=T]r_{\phi}(x,y)
```

本例的 reference log probability 依次假设为 $[-0.32,-0.25,-0.34,-0.31,-0.17,-0.27]$，所以记录的旧策略与 reference 的差为 $[0.02,0.01,-0.01,0.03,-0.01,0.02]$。取教学用的 $\beta=0.5$，逐 token 加入的 KL 项和最终 reward 如下：

| 位置 $t$ | $d_t$ | $-\beta d_t$ | 加上回答分后的 $r_t$ |
|---:|---:|---:|---:|
| 1 | $0.02$ | $-0.010$ | $-0.010$ |
| 2 | $0.01$ | $-0.005$ | $-0.005$ |
| 3 | $-0.01$ | $+0.005$ | $+0.005$ |
| 4 | $0.03$ | $-0.015$ | $-0.015$ |
| 5 | $-0.01$ | $+0.005$ | $+0.005$ |
| 6 | $0.02$ | $-0.010$ | $1.490$ |

最后一个 token 的 reward 是回答分 $1.50$ 加上该位置的 KL 项 $-0.010$；前五个位置只有各自的 KL 项。六个 $d_t$ 之和是 $0.06$，所以本例整条回答的 KL shaping 合计为 $-0.5\times0.06=-0.03$，六个位置的 reward 合计为 $1.47$。这是单条 rollout 上的 log-ratio 计算；单个位置乃至一条回答的总估计都可能为负，不能把它当作必定非负的单条 KL 值。对 policy 采样的许多回答取期望后，这些 log-ratio 才对应常说的 policy/reference KL。若只追着 reward model 分数走，policy 可能学会迎合评分器而产出人不想要的回答；增大 $\beta$ 会加强对 SFT reference 的约束，但也可能压住有用的新行为。reward 分数的尺度取决于训练数据和任务，不能把某个模型上的 $\beta$ 直接照搬；评估时还要看独立偏好和原有能力。

**步骤 3：`critic_model.value` 和 `GAE` 把回答末尾的反馈传回前面。** critic 的 `value_head` 针对每个生成位置对应的前缀 $s_t$ 输出一个标量 $V_{\mathrm{old}}(s_t)$。这里 $s_t$ 是生成 $y_t$ 之前的上下文：prompt 加上已经生成的 $y_1$ 到 $y_{t-1}$。例如 $V_{\mathrm{old}}(s_4)$ 是 critic 看过 prompt、“分母”“相同，”和“分子”之后，对从这个前缀继续生成预计能获得多少后续 reward 的预测。它不是给 token “相加，”评偏好，也不是 reward model 给整条回答的分数。`GAE` 把每个位置的 reward 和相邻前缀的 value 预测合起来，先算一步误差，再从回答末尾向前递推：

```math
\delta_t=r_t+\gamma m_tV_{\mathrm{old}}(s_{t+1})-V_{\mathrm{old}}(s_t),
\qquad
A_t=\delta_t+\gamma\lambda m_tA_{t+1}
```

沿用前面六个 token 的 reward。critic 对每个生成前缀的预测是：

```math
V_{\mathrm{old}}(s_t)=[0.10,0.18,0.26,0.34,0.42,0.60]
```

取 $\gamma=1$、$\lambda=0.5$。回答在 $y_6$ 后正常结束，因此：

```math
m_1=m_2=m_3=m_4=m_5=1,\qquad m_6=0
```

按前文 reward 和 value 逐位置计算，得到：

```math
\delta_{1:6}=[0.070,0.075,0.085,0.065,0.185,0.890]
```

例如末尾位置是 $1.490-0.600=0.890$；前一位置是 $0.005+0.600-0.420=0.185$。这一步误差算出后，GAE 从回答末尾向前递推：

```math
\begin{aligned}
A_6&=0.890,\\
A_5&=0.185+0.5\times0.890=0.630,\\
A_4&=0.065+0.5\times0.630=0.380,\\
A_3&=0.085+0.5\times0.380=0.275,\\
A_2&=0.075+0.5\times0.275=0.2125,\\
A_1&=0.070+0.5\times0.2125=0.17625.
\end{aligned}
```

因此，按本例这组 reward 和 value 预测，GAE 得到的六个 advantage 都为正；policy 更新会倾向于提高这些已采样 token 的概率。critic 的训练目标是把每个旧 value 加上对应 advantage。六个位置的 returns 为：

```math
returns_{1:6}=[0.27625,0.3925,0.535,0.720,1.050,1.490]
```

它会把对应前缀上的 value 预测往这些目标拉近。这里的数值只为演示 GAE 如何把回答末尾的偏好分和逐 token KL 信号传回前面，不代表 reward model 的通用分数或真实训练配方。

$\delta_t$ 是这一步收到的 reward 加上下一状态的预期价值，再减去 critic 原先的预测； $A_t$（advantage，优势）表示这次采样得到的后续结果比原先预期好多少。例子里 $\lambda=0.5$，所以每一步只把后续 advantage 的一半加回来；真实终止处不再向后 bootstrap，padding 位置由 mask 排除。长度上限造成的截断不一定代表任务结束，不能一律把后续价值清零。 $\gamma$ 控制远处回报的权重， $\lambda$ 控制 TD 误差信号向前累积多少。真实训练中逐 token KL 项也会进入各位置的 $r_t$；因此末尾分数会影响前面的 advantage，但每个位置的 advantage 还会受该处 reward 和 critic 预测影响。

**步骤 4：`update_policy_with_PPO` 用 advantage 调整 policy。** policy 重新给同一批已采样 token 计算概率，再和步骤 1 留下的 $\pi_{\mathrm{old}}$ 概率比较。对 token $y_t$，训练器比较的 ratio 是 $\rho_t=\frac{\pi_{\theta}(y_t\mid s_t)}{\pi_{\mathrm{old}}(y_t\mid s_t)}$：刚采完样本、尚未更新时它等于 $1$。以第四个 token “相加，”为例，旧 log probability 是 $-0.28$；假设某次更新后当前 policy 在相同前缀上的 log probability 变为 $-0.22$，那么 $\rho_4=\exp(-0.22-(-0.28))\approx1.06$，表示它现在生成这个 token 的概率约为采样时的 $1.06$ 倍。由于本例 $A_4=0.38$ 为正，这个方向符合 PPO 的优化倾向。取 $\epsilon=0.2$ 时， $1.06$ 仍在 $[0.8,1.2]$ 内，clipping 尚未触发。若同一个正 advantage token 后续被推到 ratio 1.35，取 $A_4=0.38$、$\epsilon=0.2$，未裁剪项为 $1.35\times0.38=0.513$，裁剪项为 $1.2\times0.38=0.456$，训练目标采用较小的 0.456；再提高这个 ratio 不会继续增加该样本的目标值。一般写法是：

```math
J_t^{\mathrm{clip}}(\theta)=
\min\left(
\rho_t A_t,\,
\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t
\right)
```

所以 clipping 限制的是样本继续推动更新的收益，不是把 token 概率强行设成 1.2 倍。这里有两个容易混的比较：步骤 2 中 policy/reference 的差异约束当前策略相对 SFT reference 的漂移；PPO 的新旧 policy ratio 则衡量当前更新相对这批回答的采样策略走了多远。它们服务于不同步骤，应分开看。对同一批 rollout 做有限轮 minibatch 更新时， $\pi_{\mathrm{old}}$ 的记录保持不变；复用过多轮会让新旧概率差距变大。

**步骤 5：`update_critic` 让 critic 学会预测 returns。** 对同一批回答前缀，critic 再算一次 value，并用有效 token 位置上的平方误差把新预测拉向刚才的 `returns`。例如第四个 token 之前，旧预测 $V_{\mathrm{old}}(s_4)=0.34$，GAE 目标是 $returns_4=0.72$；单看这个位置的未归一化平方误差为 $(0.34-0.72)^2=0.1444$，训练会把该前缀的 value 往 $0.72$ 拉近。RM 是从 chosen/rejected 学会给完整回答打一个偏好分；critic 是从 PPO 生成的回答和逐位置 returns 学会估计每个前缀的后续回报。RM 在这一流程中冻结，critic 则随 PPO 训练。若 critic 预测长期偏高或跟不上 policy，advantage 也会不准；检查时可以对照 value 预测和 returns，而不是只看 reward model 分数。

**步骤 6：`evaluate` 检查这轮更新值不值得继续。** 更新后仍用留出的偏好题、安全题和原有能力题检查 policy：例如确认它在这道分数题上仍能给出正确推理，同时在独立偏好评估中没有只学会迎合 RM。RM 给出的 $1.50$ 只是一个代理分数，不能替代这些评估。若偏好有改善且原有能力没有明显退化，再让更新后的 policy 生成下一批回答；新回答及其采样概率成为下一轮 rollout 和新的 $\pi_{\mathrm{old}}$。最初从 SFT 复制的 reference 仍保持冻结，RM 也继续冻结。于是循环每一轮都会把 policy 新生成的回答交给 RM/reference 打分，再用 GAE 和 PPO 更新 policy 与 critic。

**适用场景：** 从这道分数题可以看出，PPO-RLHF 适合能收集回答偏好、能让当前 policy 反复生成新回答并由 reward model 评分，而且在线采样成本可以接受的任务，例如评价回答是否有帮助、完整或符合指定风格。若任务有可验证的客观答案，例如本例的算术正确性，偏好分数仍不能代替独立校验。

**优缺点：**

- **优点：** 在 SFT 模仿示范的基础上，policy 还能根据偏好分数调整自己当前实际生成的回答；PPO 允许对同一批 rollout 做多轮小批量更新，并用 clipping 控制代理目标对更新的推动。
- **缺点：** 每轮都要在线生成回答，并让 policy、reference、reward model 和 critic 分别处理同一批 rollout；即使实现共享部分权重，也会增加前向计算和工程复杂度。
- **缺点：** reward model 只是有限偏好数据的代理，policy 可能学会迎合它；critic 估值不准会让 advantage 失真。clipping 也不是硬性概率边界，reference KL 系数、奖励尺度和回答长度等设置都会影响更新。

若手头主要是固定的 chosen/rejected 偏好对、暂时不需要在线采样更新，可以接着看下一节的 DPO；方法选择取决于训练信号、采样需求和资源条件，PPO 并非所有偏好优化任务的默认答案。

## 4. DPO：用固定偏好对直接更新 policy

**背景：** PPO-RLHF 常见做法需要先训练 RM，再让当前 policy 生成回答并在线优化。若团队手里已经有固定的 chosen/rejected 偏好对，却暂时不需要在线探索，这一整套 rollout 链条可能太重。

**目的：** DPO（Direct Preference Optimization，直接偏好优化）直接用偏好对调整 policy，并用 SFT reference 作相对锚点。

**解决的问题：** 它省去在线 rollout 和单独训练一个显式 RM 的环节。它不负责生成新偏好数据，也不负责判定回答的客观真伪。

**贯穿例子：**

| 训练样本字段 | 本例内容 |
| --- | --- |
| 同一个 prompt | 3/4 + 1/4 = ? |
| chosen | 分母相同，把分子相加：4/4，所以答案是 1。 |
| rejected | 答案是 2。 |

训练器分别让当前 policy 和 SFT reference 对这两条完整回答计算条件概率。直观地说，它会检查：当前 policy 相对 reference，是否更愿意给 chosen 而不是 rejected。若偏好对标注为 chosen 获胜，更新就朝着扩大这一相对偏好的方向走。这里仍然需要 reference，但不需要一个额外训练出来、再单独调用的 RM。

这条训练样本没有让程序检查答案，也没有让标注者为 policy 新生成的回答打分。它只提供了这一对回答的相对偏好。因此，如果标注者把错误答案标作 chosen，DPO 会学习错误方向；若模型后来生成了训练集中没有出现的新推理路径，DPO 也不会自行判定它是否正确。

实现中，policy 和 reference 必须使用相同 tokenizer、对话模板和 response mask；chosen/rejected 的回答长度和 token 聚合方式也会影响相对比较。训练后要看未参与训练的偏好题、数学正确率、长度、安全和原有能力，不能只看训练 loss。

**意义：** DPO 说明人类偏好可以直接成为 policy 的训练目标，不必固定采用“RM 再 PPO”这套模型布局。原论文在其情感控制、摘要和对话实验中报告了与 PPO-RLHF 竞争的结果；这支持该论文设置下的方案，不代表 DPO 在每种模型和任务上都更优。[DPO 原论文](https://arxiv.org/abs/2305.18290v3)

**适用场景：** 有质量较好的同 prompt 偏好对；暂时不需要当前 policy 在线探索；希望降低 reward model 和 rollout 系统成本。

**优缺点：**

- **优点：** 训练链较短，不需要单独训练和部署 RM，也不要求训练过程中持续在线采样。
- **局限：** 受已有偏好对覆盖限制；偏好不等于正确性，reference 也不是把 policy 硬性锁回原模型的投影器。分布外行为和能力漂移仍需评估。

若任务是本例这种可验证数学答案，离线偏好对能提供“标注者更喜欢哪个”的信号；答案检查器则能直接告诉训练器新生成答案是否通过。两种反馈回答的问题不同。

### 4.1 IPO、KTO、ORPO：先看你收集得到什么标签

这些方法都属于偏好优化，但它们不要求完全相同的数据：

| 方法 | 标注者需要提供什么 | reference | 训练器主要做什么 |
| --- | --- | --- | --- |
| DPO | 同题 chosen/rejected 成对比较 | 需要 | 学习 policy 相对 reference 的偏好差 |
| IPO | 同题 chosen/rejected 成对比较 | 需要 | 把偏好差拉向有限目标，避免只追求无限增大 margin |
| KTO | 每条回答单独标“可取/不可取”，不必配对 | 标准方法使用 | 让可取回答相对更可能、不可取回答相对更不可能 |
| ORPO | 同题 chosen/rejected 成对比较 | 不需要单独 reference 模型 | 同时模仿 chosen，并利用偏好对抑制 rejected |
| SimPO | 同题 chosen/rejected 成对比较 | 不需要单独 reference 模型 | 用 policy 自己对回答的平均 token log probability 作隐式奖励 |

对本例，IPO 与 DPO 都可以使用 chosen“答案是 1”和 rejected“答案是 2”；若数据团队只记录“这个回答是否可取”，KTO 可以用一条带正标签的“答案是 1”，而不必为了格式凑出一个 rejected。ORPO 仍需成对比较，同时把 chosen 当作示范学习。实际选型先看能可靠收集哪种标签，再看训练资源和回归结果，不要把不同论文的最高分拼成排行榜。

IPO 的有限目标不是数学答案的阈值，而是偏好优化目标中对 policy/reference 相对差距的控制。KTO 的逐条标签仍会受标注标准和好坏样本比例影响；ORPO 的组合目标仍需检查长度、损失权重和数据分布。[IPO 原论文](https://arxiv.org/abs/2310.12036)、[KTO 原论文](https://arxiv.org/abs/2402.01306)、[ORPO 原论文](https://arxiv.org/abs/2403.07691)

## 5. SimPO：没有 reference 前向计算的离线偏好学习

**背景：** DPO 训练时要让当前 policy 和冻结 reference 都给 chosen/rejected 回答算分。reference 增加了一份前向计算和显存需求。

**目的：** SimPO（Simple Preference Optimization）不再使用独立 reference model 的相对分数，而把当前 policy 对回答的平均 token log probability 当作隐式奖励，再学习 chosen 与 rejected 的偏好差。

**贯穿例子：** 仍然看同一个问题。标注者偏好完整回答“分母相同，把分子相加得到 4/4，所以答案是 1”，而不是“答案是 2”。训练器按真实 tokenizer 把两条 assistant response 切成 token，只对回答部分统计当前 policy 的 log probability，并分别求每条回答的 token 平均值。它不会把回答汉字数当 token 数，也不会把这个平均 log probability 当成人类打分；人类的 chosen/rejected 标签仍决定哪条更受偏好。

使用平均值的动机是避免回答仅仅因为包含更多 token，就把更多负 log probability 累加进隐式奖励。比如另一道题中，标注者偏好一个较长但清楚的证明，拒绝一个很短的错误答案；平均化会调整长度对总分的直接影响，但不会把错误答案变成正确答案，也不会自动消除“标注者偏好长解释”的数据偏差。

**解决的问题：** 减少 reference 模型计算，并让偏好比较与生成时每 token 的平均可能性更接近。

**适用场景：** 有可靠离线偏好对、reference 前向计算成本明显，而且能独立监测长度、能力和安全变化时。

**优缺点：**

- **优点：** 训练目标直接，不需要为每条偏好对额外运行 reference model。
- **局限：** 仍受离线偏好数据限制；平均 token log probability 不是 calibrated reward，reference-free 也不表示训练无需 SFT 初始化或 policy 不会漂移。长度和 mask 口径仍必须固定。

SimPO 论文在其指定模型、偏好数据和聊天评测中报告了与基线的比较；迁移时应在同一底模、数据和预算下验证，不把论文结论扩展成普遍排名。[SimPO 原论文](https://arxiv.org/abs/2405.14734)

## 6. GRPO：同题采多条回答，用组内结果作比较

**背景：** PPO-RLHF 通常训练 critic 来估计每个回答前缀后续能获得多少回报。critic 会增加模型和训练环节。若答案可以验证，同一道题本身就能提供多个候选作对照。

**目的：** GRPO（Group Relative Policy Optimization）对同一个 prompt 采样一组回答，用组内 reward 的相对高低构造更新信号，通常不需要单独 critic。DeepSeekMath 将它用于数学推理训练。[DeepSeekMath 原论文](https://arxiv.org/abs/2402.03300)

**贯穿例子：** policy 对“3/4 + 1/4 = ?”一次采出四条回答。一个程序按化简后的答案是否为 1 检查它们：

| rollout | 完整回答 | verifier reward |
| --- | --- | ---: |
| A | 答案是 1。 | 1 |
| B | 分母相同，把分子相加，得到 4/4=1。 | 1 |
| C | 答案是 2。 | 0 |
| D | 3+1=5，所以答案是 5/4。 | 0 |

因为 A、B 的 reward 高于这组平均水平，训练器会倾向于提高它们中已采样 token 的生成概率；C、D 则得到相反方向的相对信号。GRPO 不必再训练一个 critic 来给每个前缀估值。它却无法仅凭终局“答案正确”指出 B 的哪一步推理值得保留；若一条错误推理最后碰巧猜中 1，答案检查器也可能给它正反馈。

如果四条回答全答对，或全答错，verifier 给出的 reward 都相同，组内就没有“哪条比同题其他回答更好”的方向。增加同题采样数可能更容易出现有差异的回答，但需要生成更多 token，且输出之间通常相关。规则 reward 若有错误，也会把错误方向传播给整条回答。

**意义：** GRPO 用同一题的候选回答提供局部比较，减少了 PPO 对独立 critic 的依赖；它没有省掉在线生成，也没有自动提供逐步推理的信用分配。

**适用场景：** 数学、代码和其他有可靠结果 verifier、同一 prompt 可以采多条候选的在线训练。

**优缺点：**

- **优点：** 不需单独训练 critic；同题多条回答能揭示当前 policy 哪些候选通过了任务检查。
- **局限：** rollout 仍然昂贵；全对或全错的组没有相对信号；终局 reward 通常广播到一条回答的多个 token，不能解释具体哪一步正确。

## 7. GSPO：让整条长回答共用一个更新权重

**背景：** GRPO 的 reward 常以整条回答为单位，但 policy 更新会逐 token 比较新旧概率。长回答里某些 token 变化很大、其他 token 变化很小，局部比率可能互相拉扯。

**目的：** GSPO（Group Sequence Policy Optimization）先把一条回答中 token 的新旧概率变化聚合成一个序列比率，再用整条 response 作为 clipping 和加权单位。[GSPO 原论文](https://arxiv.org/abs/2507.18071v2)

**贯穿例子：** 使用 PPO 算例中 verifier 判为正确的回答：“分母相同，分子相加，得到 4/4=1。”沿用教学设定的六个 token 片段。某次更新后，这六个 token 的新旧概率比假设为 1.40、0.90、1.20、0.80、1.10、1.00。token 级方法会分别处理每个位置：例如第一个 token 的比率已经越过示例中的 1.20 上界，后面几个 token 则在范围内。GSPO 把六个 log-ratio 平均后再还原成一个序列比率，本例约为 1.05；若裁剪窗口是 0.80 到 1.20，整条回答仍在窗口内。

这一步把“这条回答总体得了什么反馈”和“这条回答总体被更新多少”放在相同粒度。它不等于把整条回答的概率直接相乘：GSPO 使用 token log-ratio 的长度归一化几何平均。代价是，某些位置的高比率可能被其他位置的低比率抵消；整句结果也无法告诉我们某一步写错了。

**解决的问题：** 在论文所研究的长回答和 MoE 设置里，作者针对 token 粒度造成的训练不稳定，提出序列级比率与裁剪。该诊断和收益绑定论文的模型、reward、长度分布及训练系统，不说明所有任务都应采用序列级更新。

**适用场景：** 回答通常很长、奖励主要针对整条轨迹，并且日志显示 token-level ratio 波动确实是训练问题时。

**优缺点：**

- **优点：** 整条回答共享一个权重，回答级反馈与裁剪决策的粒度相同。
- **局限：** 局部 token 变化会被聚合抵消；不能据此定位推理步骤错误；效果需在相同 rollout 预算和评估集上验证。

## 8. DAPO：围绕长推理训练同时处理几种常见故障

**背景：** GRPO 的组可能全对或全错；固定 clipping 可能压住低概率但有用的 token；长回答可能被截断，不同长度回答对 loss 的贡献也受平均方式影响。

**目的：** DAPO（Decoupled Clip and Dynamic Sampling Policy Optimization）把采样、clipping、token loss 和超长回答处理组合成一套 reasoning RL 配方，而不是只替换一个公式。[DAPO 原论文](https://arxiv.org/abs/2503.14476v2)

**贯穿例子：** 还是这道分数题。模型前期可能连续采到四个错误答案，或连续采到四个正确答案。前一种组全是失败，后一种组全是成功；两种情况下组内都没有相对差异。DAPO 论文的 dynamic sampling 会过滤全对、全错的组，并继续采样，以便填满含有混合结果的训练批次。这样增加了带区分信号的组，但采样成本变高，也改变了哪些题更容易进入更新。

DAPO 还按几类故障增加处理：

| 遇到的实际问题 | 配方中的处理 | 用本例理解 | 需要监控的代价 |
| --- | --- | --- | --- |
| 正向更新被固定上界过早压住 | 对正负方向采用不对称 clipping（Clip-Higher） | 一条低概率但 verifier 判正确的解题 token 有更多提高空间 | 错误 verifier 信号也可能造成更大策略漂移 |
| 全对/全错组没有区分 | 过采样并筛选无相对信号的组 | 补采到有答对也有答错的候选 | 额外 rollout；保留题分布可能改变 |
| 长回答 token 在样本平均里权重较低 | 对有效 token 使用 token-level loss reduction | 一条长而正确的推导会贡献更多 token 项 | 长回答获得更大总权重，未必代表更高质量 |
| 达到生成上限时回答不完整 | 区分截断与自然结束，并对超长回答平滑处理 | 撞到 token 上限的回答不能简单当成自然结束的错误 | 惩罚过早可能让模型提前结束长证明 |

尤其要区分“模型主动写得太长”和“系统在上限处把回答截断”。若一条推导撞到最大 token 数，最终答案可能还没生成；直接判错会把资源预算造成的删失当成模型错误。另一方面，已经自然结束但超过任务合理长度的回答，才适合分析长度惩罚。阈值要按数学证明、代码修复、短问答等任务分别设定。

**意义：** DAPO 把“无信号采样、更新空间、长回答权重和截断”拆成可观察的工程问题，适合做逐项诊断。论文在 Qwen2.5-32B 和 AIME24 Avg@32 设置中报告，其组合配方从 naive GRPO 的 30 提升到 50；这是该论文的逐步 recipe 结果，不能当作各组件相互独立的因果效果或跨任务排名。

**适用场景：** 有在线 verifier，任务需要较长推理，并且训练日志已显示无区分组、截断或长度权重确实限制训练时。

**优缺点：**

- **优点：** 对应多个常见瓶颈，每项都有可检查的采样率、长度或 clipping 指标。
- **局限：** 组件相互影响；过滤改变样本分布，token-level loss 改变长短回答权重；仍需要 verifier 和独立能力回归。

## 9. DCPO：按 token 概率动态调整裁剪空间

本章中的 DCPO 指 2025 年提出的 Dynamic Clipping Policy Optimization。另有论文使用相同缩写表示 [Distribution-Centric Policy Optimization](https://arxiv.org/abs/2601.12730v1)，讨论主题不同；引用时要写明全称。

**背景：** 固定 clipping 对每个 token 使用相同窗口。若一条经过 verifier 检查的正确回答中，某个罕见 token 的旧概率很低，固定窗口也可能过早压住它的更新空间；GRPO 当前组的 reward 若都相同，组内标准化还会把 advantage 变成零。

**目的：** 该 DCPO 依据 rollout 时旧 policy 给 token 的概率调整 clipping bounds，并结合平滑的 advantage 统计和 response 内 token 平均，尝试增加有非零训练信号的回答。

**贯穿例子：** verifier 判“分母相同，分子相加，4/4=1”正确，但模型过去很少使用“分子相加”这类表达，旧 policy 给对应 token 的概率较低。DCPO 的动态裁剪会给低概率 token 更宽的调整空间。它让模型更容易从这个稀有选择中学习，但若 verifier 把错误回答也判成正确，放宽窗口同样会强化错误行为。

DCPO 还利用当前和历史 reward 分布平滑 advantage。若今天这一组答案 reward 都相同，单看这组没有相对方向；引入历史分布可能让今天的回答仍获得非零信号。论文称这类统计为 response utilization ratio（RUR），也就是生成回答中获得非零 advantage 的比例。举例说，若五条生成回答里四条 advantage 非零，RUR 是 4/5；这只说明信号覆盖到四条回答，不说明四条都正确、梯度方向都有益或未见题性能提升。

作者在四个 Qwen 设置、400 个训练 step 上报告 DCPO 平均 RUR 为 71.8%，GRPO 为 43.8%；在 Qwen2.5-Math-7B 的 AIME24 Avg@1/32 设置报告 DCPO 为 46.7/38.8。上述数值分别是论文定义的训练期利用率和其特定数学 benchmark 成绩，不是跨模型的通用优势。[DCPO 原论文](https://arxiv.org/abs/2509.02333v2)

**意义：** RUR 把“多少回答得到非零 advantage”变成可讨论的样本利用指标；它提醒我们，训练信号覆盖率、更新是否有益、模型真实能力是三个不同问题。

**适用场景：** 在线 RLVR 中观察到大量回答因固定 clipping 或当前组统计而没有有效信号，而且能记录旧概率、verifier 版本、样本利用率和独立任务表现时。

**优缺点：**

- **优点：** 可为低概率 token 提供不同更新空间，也能借历史统计减少只依赖当前组的情况。
- **局限：** 历史 reward 若来自不同 verifier 或任务标准，就不一定可比；非零 advantage 不是正确性的证明。需同时看 RUR、外部正确率、长度切片和样本成本。

## 10. DeepSeek-R1：把 RLVR 放回完整训练路线理解

DeepSeek-R1 的公开报告让 RLVR 成为广泛讨论的 reasoning 训练路线，但不能把它压缩成“用了 GRPO，所以模型会推理”。需要区分 R1-Zero 和 R1 的训练过程。

**R1-Zero 的例子：** 从 DeepSeek-V3-Base 出发，让模型对可验证的数学等任务采样回答；论文描述使用 GRPO，并以答案正确性和格式规则作为主要奖励。这条实验路线没有先用人工推理示范做 SFT，但模型并非从随机参数开始，它已经带着预训练形成的语言和数学先验。公开结果说明这种路线在论文任务上可行，也报告了可读性和语言一致性等限制。

**R1 的公开路线：** 报告另外描述了 cold-start 长推理示范、reasoning RL、拒绝采样、混合推理与非推理数据的 SFT、后续 helpfulness/harmlessness RL，以及把大模型轨迹蒸馏到较小模型。报告统计了约 80 万条 SFT 样本，包含数学、代码、STEM、逻辑和通用任务。最终表现来自这些数据、阶段和评估的组合，不能单独归因于 GRPO。[DeepSeek-R1 技术报告](https://arxiv.org/abs/2501.12948)

这个案例给出的可迁移经验是：验证器能教模型什么，取决于任务是否可被规则覆盖；开放问答、安全和写作还需要不同反馈。R1-Zero 不是开放任务都可用答案规则训练的证明，R1 的多阶段路线也不是所有模型都必须照搬的固定配方。更完整的 RLVR verifier 设计见本册第十六章。

## 11. GRPO、GSPO、DAPO、DrGRPO、DCPO 各自针对什么

这些方法不是按新旧排成一条“升级路线”。它们改动的是不同环节。先用同一道题想象训练日志：组内全错、回答越来越长、某个低概率正确 token 被 clipping、或者回答级 reward 与 token 级更新单位不一致。每篇工作针对其中不同现象提出方案。

| 方法 | 它主要改哪里 | 对应的训练现象 | 适用边界 |
| --- | --- | --- | --- |
| GRPO | 用同 prompt 的组内 reward 建立相对信号，通常省去 critic | PPO critic 成本较高，且任务允许同题采多个候选 | 全组同分时没有相对方向 |
| DAPO | 组合动态采样、非对称 clip、token loss 和超长处理 | 长推理训练中无效组、低概率 token、长度和截断问题 | 组合效果不能归因单一组件；过滤改变样本分布 |
| DrGRPO | 调整回答长度与组内标准差归一化 | 按每条回答长度平均可能改变短长回答的 token 权重 | 固定预算分母不自动解决全组同分或 reward 错误 |
| GSPO | 把重要性比率和 clipping 的单位改成整条回答 | 长序列 token ratio 波动与回答级 reward 不在同一粒度 | 局部 token 变化会被聚合抵消；结果依论文设置 |
| DCPO | 旧概率相关的 token clip、历史 advantage 平滑和 response 内平均 | 固定窗口和只看当前组时，部分回答得不到非零信号 | RUR 不是正确率或有益梯度比例 |
| DHPO | 混合 token 与 sequence ratio，再分别处理 clipping | 希望同时保留局部更新和序列稳定性 | 当前为预印本；作者报告的数学设置不等于通用结果 |
| GAPO | 按组内 advantage 调整 clipping 边界 | 固定边界对不同难度 rollout 一视同仁 | EMNLP 2026 论文的收益仍绑定所列模型和任务 |

DrGRPO 的动机可以用同一批两种回答说明：假设 tokenizer 把短答案切成 10 个有效 token、把长推理链切成 100 个有效 token，且两条回答得到相同质量 reward。这里的 token 数是教学设定，不是按字数推测。若每条回答先把 token loss 平均，两个回答在样本层可能被赋予相近总权重；若全批有效 token 共用分母，长回答就贡献更多 token 项。它也取消按组内标准差缩放 advantage：例如同题的一条正确回答得 1、一条错误回答得 0，传统标准化会再按组内波动缩放两者的差距；DrGRPO 保留中心化后的 reward 差。这样不同题目的 reward 尺度不会自动被抹平，因此跨任务 reward 仍需控制量纲。DrGRPO 不能单独判断长答案是否更正确，也不能替代 verifier。

DHPO 仍是 arXiv 预印本。GAPO 已收录于 EMNLP 2026 主会论文集；官方论文介绍它按 rollout advantage 自适应 clipping 边界。论文在部分 Qwen 和 Llama 数学、代码任务报告了 Pass@1 与 Pass@k 改善。[DHPO 预印本](https://arxiv.org/abs/2601.05607v1)，[GAPO，EMNLP 2026 论文集](https://aclanthology.org/2026.emnlp-main.1882/)。录用和作者实验都不是跨任务保证；比较时要固定底模、数据、verifier、rollout 预算和评测方式。

同名缩写需要核对全称。本章 DCPO 是 Dynamic Clipping Policy Optimization；另有 Distribution-Centric Policy Optimization 使用同一缩写，不能混作同一个方法。

## 12. 领域专家与 on-policy distillation

### 12.1 领域专家训练需要任务和验收条件

数学证明、代码修复、工具使用和科学问答需要不同数据，也需要各自的验收方式。领域专家训练通常要准备领域任务、专家示范、可用时的 verifier、再加通用能力与安全回归。只追加领域文本可以增加知识暴露，却不一定教会模型完成任务或判断结果是否正确。

例如代码修复任务，训练器不只要看到“最后的代码长什么样”，还要知道原始测试是否失败、模型改了什么、修复后测试是否通过。若测试只覆盖一个输入，模型可能把测试样例写死，却没有修复一般问题。第十五、十六章进一步展开领域专家 SFT 与 verifier/RLVR。

### 12.2 On-policy distillation：教师也要看见学生实际走到哪里

离线蒸馏通常拿教师预先写好的轨迹教学生。学生如果沿着自己的错误前缀继续生成，而教师数据里没有这个状态，就可能缺少直接的纠正信号。

设学生在本例中错误地写成“把分母相加……”。on-policy distillation 会先让学生沿自己的 policy 生成到这个错误前缀，再让教师在这个状态上提供下一步 token 分布或让 verifier 标出错误。训练目标由此覆盖学生确实会到达的上下文，而不是只复习教师的理想答案。它的代价是要在线生成学生轨迹并运行教师；教师本身也可能不可靠，仍需验证和过滤。

多教师 on-policy distillation（MOPD）把多个领域教师的指导用于学生自己的 rollout。相关论文报告了特定模型与任务设置下的结果，不能直接当作通用成本或效果结论；训练细节见本册第十七章。[MOPD 论文](https://arxiv.org/abs/2606.30406v1)

### 12.3 公开模型披露能说明什么

公开材料展示的是作者披露的训练方向，不一定是完整配方。

| 案例 | 发布方公开说明 | 仍不能推出什么 |
| --- | --- | --- |
| GLM-5.3 | Z.ai 称其沿用 GLM-5.2 的 base model，并通过增加长周期环境、任务多样性和训练计算扩展 post-training | 完整数据、optimizer、reward 权重和独立复现结果 |
| gpt-oss | OpenAI 公开称模型结合强化学习与来自内部先进模型的训练技术，并强调 reasoning 与工具使用 | 具体 PPO/GRPO 选择、reward 配方和完整超参数 |
| Grok 4.7 | xAI 称其使用更大的 base model，并进行了更长的 RL run 和更难、偏多小时任务的训练 | benchmark 增益中 base model、任务混合和 RL 各自贡献 |

这些是厂商的公开描述，不是独立对照实验。GLM-5.3、gpt-oss 和 Grok 4.7 都不能靠产品 benchmark 或 reasoning effort 字段反推出未披露的训练算法。[GLM-5.3 官方说明](https://z.ai/blog/glm-5.3)、[gpt-oss 发布说明](https://openai.com/index/introducing-gpt-oss/)、[Grok 4.7 官方说明](https://x.ai/news/grok-4-7)

## 13. 如何按项目条件选择方法

**适用场景的判断先看反馈和系统条件，不先看算法名。**

| 项目手头有什么 | 可以先比较什么 | 主要成本或风险 |
| --- | --- | --- |
| 有示范，但没有稳定偏好对或 verifier | SFT，并补充数据覆盖和回归集 | 模仿能力受示范质量限制 |
| 有同 prompt chosen/rejected 偏好对 | DPO、IPO、SimPO；有逐条好坏标签时可看 KTO | 离线数据覆盖不到的行为不会自动得到反馈 |
| 有可靠数学答案或代码测试，能在线 rollout | GRPO；再按无效组、长度或 clipping 现象对比 DAPO、DrGRPO、GSPO、DCPO | rollout、verifier、token 预算和复现成本 |
| 目标是安全和拒答 | 安全示范、偏好/约束数据、红队与切片评估 | 过度拒答、漏拒和工具误用之间的取舍 |
| 资源有限，尚无 rollout 服务或 verifier | 先提高 SFT / preference 数据质量，再建立小规模评估闭环 | 过早上在线 RL 可能主要耗在生成、过滤和排错 |

例如，团队先做通用聊天，只有一批人工偏好对而没有可靠在线评分器，可以用 DPO/SimPO 建立离线基线；后来转向代码修复且已有稳定测试环境，才有条件试 online RLVR。若日志进一步显示组内全对/全错很多，再测试 dynamic sampling；若模型常在 token 上限被截断，再测试超长处理。每次固定同一个 SFT checkpoint、题池和评估集，只改一个主要因素，才知道新方法解决了哪个实际故障。

这不是固定训练流水线。项目可以先做数学 RLVR，也可以先补安全示范；方法选择随任务、数据、verifier、rollout 成本和能力回归结果变化。

## 14. 数据质量决定训练器听到了什么

| 阶段 | 需要的数据 | 先检查什么 |
| --- | --- | --- |
| SFT | prompt + 目标回答 | 回答是否正确、格式是否一致、目标 token mask 是否对 |
| Reward Model | prompt + chosen + rejected | 两条回答是否同题可比、标签是否可靠、长度是否系统性偏向 chosen |
| DPO / IPO / ORPO / SimPO | 偏好对；KTO 可使用逐条好坏标签 | 标注分歧、模板一致性、被截断的空回答、token 聚合口径 |
| PPO-RLHF | 当前 policy rollout + RM/其他反馈 | rollout 是否来自记录的 policy，RM 是否可被投机 |
| GRPO 家族 | 同 prompt 的多条 rollout + reward | group 是否完整、是否有组内差异、verifier 是否正确 |
| 长链 RL | rollout、终止原因和有效 token mask | 自然结束与系统截断是否分开、长短任务是否混在同一阈值 |

回到 chosen“分母相同……答案是 1”和 rejected“答案是 2”：如果 chosen 总是更长，模型可能同时学到长度和答案偏好。数据审计要按任务类型统计两者长度，并抽查控制长度后标注者是否仍偏好 chosen。长度差是排查线索，不单独证明标注者有长度偏差；证明题本来就可能比简答题长。

## 15. 后训练中要防的几类退化

### Reward hacking：模型通过了规则，但没有完成真实任务

如果数学 verifier 只检查输出是否包含字符串“1”，模型可以在错误解释后附上数字 1 通过检查。代码 verifier 若只运行一个公开测试，也可能被模型写死该测试用例。解决方式不是盲目换 optimizer，而是补隐藏测试、语义约束、人工抽检和高 reward 低质量样本分析。

### Length bias：模型把“更长”或“更短”当成目标

如果 RM 偏好详细解释，模型可能增加重复内容来获得高分；若超长惩罚太重，模型又可能过早结束证明。要按任务观察长度、终止原因、正确率和人工偏好，不能把长度本身当质量。

### Reward 上升而真实质量不升

如果训练集 RM 分数持续提高，但留出偏好、数学正确率或用户任务成功率没有提高，模型可能在迎合代理目标。把训练 reward、留出集、真实任务和人工样本并列，而不是只挑一条向上的曲线。

### 能力遗忘与 policy 漂移

窄领域数据可能让模型更会解数学题，却损伤通用问答、代码或长上下文。比较 base、SFT 和后续 checkpoint 的同一批回归题；必要时混合 replay 数据或减小更新，并保留可回滚 checkpoint。

### Safety regression：正确拒绝与过度拒绝要分开数

在留出评估中，危险请求“帮我窃取账号”应拒绝；无害请求“怎样重置自己的密码”应提供帮助。若新模型对两者都拒绝，应同时记录：

| 评估项 | 例子中的结果 |
| --- | --- |
| 危险请求正确拒绝 | 1 条中拒绝 1 条 |
| 无害请求过度拒绝 | 1 条中误拒 1 条 |
| 总体结论 | 拒答增加，但帮助性下降；不能单独称为安全改善 |

真实评估需要更多风险类型、样本和人工审查。一次小例子能说明分母为什么要分开，却不能估计模型实际安全率。

## 16. 一个可复用的后训练工作流

下面用“先训练通用助手，再提高数学解题可靠性”为例。它展示的是可选分支，不是人人必须照走的流水线。

1. 从预训练 checkpoint 开始，检查目标任务和初始能力。
2. 准备通用指令与解题示范，做 SFT，建立可用回答方式。
3. 若要改善开放式回答偏好，收集同 prompt 比较或逐条好坏标签，选择 DPO、KTO 等离线候选；若要用 PPO-RLHF，则另训练 RM 并设计在线采样与评估。
4. 对数学题接入答案验证器，先人工抽查它能否识别等价写法、格式和边界情况。
5. 只有在需要当前 policy 探索新解法且生成成本可接受时，开启 online RLVR；先用 GRPO 建基线，再根据真实日志测试 DAPO、GSPO 等候选。
6. 单独评估数学正确率、解释质量、长度、通用能力和安全边界。
7. 从失败案例改进示范、偏好集或 verifier，记录数据与 policy 版本，再决定是否继续训练。

如果题目没有可验证答案，就不能照搬“答案为 1 给分、答案为 2 扣分”。反馈方式必须随任务改变。后训练是否有效，最终看独立评估上目标行为有没有改善、旧能力和安全有没有可接受地保持，而不是训练器是否报告更高 reward。

先从 SFT 汇总读起。三条合成样本的 assistant token 合计 $54+83+41=178$，prompt token 合计 $22+18+30=70$，序列化输入与回答共 248 token，所以结构性占比为 $178/248\approx0.7177$。类别集合是 format、reasoning、safety，拒答示范只有一条。这个占比回答“样本中 assistant token 占了多少”，不回答“loss 中有多少 token 参与监督”：后者还要套用每个训练样本的 label mask。若把二者混为一谈，可能把 prompt token 错当成监督目标。

偏好部分把 RM 与 DPO 两个 loss 分开计算。以 `pref_helpful` 为例，reward 差是 $1.4−0.2=1.2$，所以 RM logistic loss 是 $−\ln \sigma(1.2)\approx0.2633$；三对样本分别计算后等权平均，输出 0.3749。DPO 则比较 policy 与 reference 的 margin：policy gap 为 $−2.10−(−2.70)=0.60$，reference gap 为 $−2.30−(−2.55)=0.25$，差值为 0.35；乘以 $\beta=0.1$ 后 logit 是 0.035，单对 loss 约 0.6758。三对平均得到 0.6786。chosen 长度减 rejected 长度分别为 11、−25、4，平均 $−10/3\approx−3.33$ token；这只是这三对的方向摘要，不足以说明真实偏好数据存在长度偏置。

在线 group 用 `math_001` 展示 advantage 的来源。三个 reward 是 `[1,0,0.5]`，均值为 0.5，总体标准差约为 0.4082，因此标准化 advantage 为 $[1.2247,−1.2247,0]$。第一条回答的平均 logp 从 −3.00 变为 −2.76，差值 0.24，故序列 ratio 代理为 $\exp(0.24)\approx1.2712$，再按 demo 的 $\epsilon=0.2$ 截到 1.2 后形成代理 surrogate。这里用平均 logp 的差模拟几何平均 token ratio，特意没有从完整序列概率乘出 vanilla GRPO 的逐 token ratio；不能把这个数当作真实训练器的 policy ratio。

评估输出把同四行 old/new checkpoint 记录配对：四行中三行新分数更高，故 gain rate 是 $3/4=0.75$；`safe_001` 是唯一应拒答样本且新模型拒答，安全召回为 1；三个普通样本中 `safe_002` 被误拒，所以 over-refusal 为 $1/3$。该样本也是旧模型通过、新模型失败的唯一回归案例。最后，方法建议只依据任务需要在线探索、rollout 是否可用、verifier 或可信反馈是否可用等布尔条件选候选家族；它不会代替同设置实验。诊断字典中的 `over_refusal_flagged=True` 与 `regression_detected=True` 是发现问题的告警，其他 True 也只表示通过了 demo 内设阈值，不是模型质量认证。

其余诊断值也要回到中间量解释。两个 group 各自标准化后的 advantage 求和为零，因此 `group_advantage_centered=True`；最大的 ratio 偏差是 $1.2712−1=0.2712$，低于教学阈值 0.32。`format_failures` 把 `code_001/r1` 标出来，但代码没有自动修改它的 reward；若格式错误应该有代价，要在 verifier/reward 定义中明确编码。`mean_sequence_surrogate_proxy` 是演示代理项的组内均值，不是反向传播所用的最终 loss。0.32、0.70 和 20-token 等阈值都只是合成输入里的诊断条件，真实实验必须预先说明阈值并报告原始指标，不能把 flag 当成跨任务标准。

`preference_categories_ok` 只核对去重后的类别集合，不检查每类样本量是否平衡、标注者是否一致或各类别 reward 是否可比较。`length_bias_ok` 检查三对长度差的平均值是否落在 ±20 token 内；正负差异可能互相抵消，所以通过这条规则也不能证明没有长度偏置。应进一步看长度差分布、分任务切片和偏好胜率随长度的变化。

这个 demo 的重点是把数据、反馈、采样和评估分开观察：离线偏好 category 只用于覆盖统计，不决定在线/离线 optimizer；method_family_suggestion 先选方法家族候选，算法之间仍要按任务、loss reduction、ratio 粒度、rollout 成本与同设置实测比较。assistant_token_share_of_serialized_tokens 只是输入加回答 token 的结构性占比，不是 SFT loss 的监督比例；真正的 loss 分母仍应只数 mask 选中的 assistant token。序列 ratio 代理使用 response 平均 logp，不能替代 GRPO 的逐 token ratio 或真实训练日志。若 uninformative_groups 非空，代码会明确把该组 advantage 设为 0；它并没有像 DAPO 那样补采，也没有像 DCPO 那样用历史统计。over_refusal_flagged 和 regression_detected 为 True 表示 demo 检出了问题，不代表模型已经健康。

## 18. 常见误判与诊断路径

| 观察到的现象 | 先检查什么 | 可能的判断 |
| --- | --- | --- |
| 把 SFT、DPO、PPO 都叫“对齐训练” | 这次用的是目标回答、固定偏好对，还是当前 policy 新采样 | 三者反馈和训练循环不同；先找对数据，再比较算法 |
| policy 新生成的解法没出现在偏好集 | 任务是否能用程序或环境给它反馈 | 固定偏好集不会自动探索；可验证且需要探索时再考虑 online RLVR |
| 一组 GRPO rollout reward 都一样 | 同 prompt 的组是否完整、verifier 是否有区分度、采样温度是否合适 | 组内没有相对方向；加小常数只会避开除零，不会造出学习信号 |
| 训练 reward 上升但留出正确率停滞 | verifier false positive、reward shortcut、难度切片和题目泄漏 | 优化器可能学会迎合检查器；先审计信号再加训练步数 |
| 安全拒答上升但用户体验变差 | 分开统计危险请求正确拒绝与无害请求错误拒绝 | 可能是过度拒答，不能只看总拒答率 |
| 回答突然变长、变短或被截断 | EOS、生成上限命中率、任务长度分布和 loss reduction | 判断是策略主动变化、任务组成变化还是系统删失 |
| 异步训练效果与同步基线不一致 | rollout policy revision、等待时间、旧样本比例和 log-prob 口径 | 可能混入了 stale rollout 或训练/采样概率不一致 |

需要方法背景时，回到对应章节的小例子，再沿真实 rollout 逐步排查。日志指标必须说明分母、policy 版本、mask 和任务切片；字段名相同不保证不同框架或版本计算口径相同。

## 19. 本章小结

后训练把模型从“能续写”继续训练到“按任务回答并守住行为边界”。先识别训练信号：

- SFT 用示范教模型目标回答长什么样。
- Reward Model 学习同题回答的偏好排序；它的分数不是正确性证明。
- DPO、IPO、KTO、ORPO 和 SimPO 用不同形式的离线偏好标签。
- PPO-RLHF 在线采样回答，根据 RM 与 reference 约束更新 policy；§3 的算例走完了每个模型角色和一轮 GAE/PPO。
- GRPO、GSPO、DAPO、DrGRPO、DCPO 等讨论在线组内反馈的不同更新或配方选择；它们不能只按名称或论文分数排位。
- RLVR 适用于结果能由程序或环境验证的任务，但 verifier 本身需要评估。
- 最后用偏好、安全和原有能力回归判断新 checkpoint 是否真的更适合目标任务。

选择方法时，先问“有什么可靠反馈、是否需要在线探索、采样与评估预算是多少”，再看具体算法；训练 reward 只是中间信号，不是最终结论。
