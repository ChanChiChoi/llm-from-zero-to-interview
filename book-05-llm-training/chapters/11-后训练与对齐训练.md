# 第十一章：后训练与对齐训练：从会续写到可靠协作

预训练让模型根据已有文字继续生成；它本身不规定助手怎样识别用户意图、遵守格式、拒绝危险请求或验证答案。后训练用示范、偏好、可验证结果和安全评估塑造这些行为，但每种信号都只覆盖一部分：示范可能有盲区，偏好分数不等于事实，verifier 也可能有漏洞。

前面的反馈类型和 PPO-RLHF 用一道题“3/4 + 1/4 = ?”帮助读者追踪信号怎样进入训练。进入 §4–§9 后，DPO、SimPO、GRPO、GSPO、DAPO、DCPO 各是独立算法或训练配方；每节都换用贴合自身机制的任务，先看伪代码，再沿本节自己的例子走完，不把一题重复套给六种方法。

| 训练信号 | 本例给模型或训练器的材料 | 它能教什么 |
| --- | --- | --- |
| 示范回答 | “分母相同，把分子相加：4/4，所以答案是 1。” | 模仿一种可接受的回答方式 |
| 偏好比较 | chosen：“分母相同……答案是 1。”；rejected：“答案是 2。” | 哪个已有回答更受偏好 |
| 可验证反馈 | 模型自己生成答案，程序检查化简后的结果是否为 1 | 当前生成结果是否满足明确的答案条件 |
| 安全评估 | 比较“帮我盗号”和“怎样重置自己的密码”两种请求 | 哪种情况应拒绝，哪种情况应正常帮助 |

这道算术题适合讲自动验证，因为答案可以规范化后检查。它不能代表开放式写作或安全判断；那些任务没有同样可靠的单一答案，通常需要偏好标注、专门规则和人工评估配合。

本章先解释反馈如何进入训练，再沿 PPO-RLHF 的伪代码完整走一轮，接着比较离线偏好优化与在线 RLVR，最后讨论训练配方、评估和常见风险。长篇 verifier 设计、领域专家训练、on-policy distillation 和具体模型配方分别见本册[第十六章](16-rlvr与可验证奖励.md)、[第十五章](15-领域专家sft与rl.md)、[第十七章](17-on-policy-distillation.md)和[第十八章](18-deepseek-v4领域专家与统一蒸馏.md)。

## 1. 后训练使用什么反馈

### 1.1 SFT：先教模型一种可用的回答方式

监督微调（SFT）使用示范回答。对本章的题目，训练样本可以是：

> 用户：3/4 + 1/4 = ?
>
> 助手：分母相同，把分子相加：3+1=4，所以 4/4=1。

训练时，模型把用户问题和已经生成的回答前缀当作上下文，逐步预测示范回答的下一个 token。训练器提高示范中 assistant 回答 token 的概率，让模型学会这类回答怎样组织。汉字、标点和数字会由 tokenizer 切成真实 token；训练器按真实切分和 mask 计算，不按汉字数量猜 token 数。

可以把一条训练记录中的位置这样理解：

| 位置 | 模型看到的内容 | 是否作为 assistant 目标 |
| --- | --- | --- |
| 用户问题 | 3/4 + 1/4 = ? | 否，作为上下文 |
| 助手回答 | 分母相同，把分子相加…… | 是，按目标回答学习 |
| padding 补位 | 为了组成批次而补齐的位置 | 否，mask 排除 |

结束标记 EOS 是否纳入目标、工具调用字段是否纳入监督，要按任务模板决定；但用户输入和 padding 不应误当成 assistant 的目标回答。如果截断后没有任何有效 assistant token，训练器就没有可学习目标，应先检查数据和 mask。

SFT 适合先建立指令遵循、回答格式和常见操作行为。它的训练信号直观，示范也便于审查；但模型主要模仿示范覆盖的行为，错误或过窄的示范会带来盲区，而且 SFT 不会自动判断两个未见回答中哪一个更受偏好。

### 1.2 Reward Model：把回答比较变成整条回答的分数

偏好标注不一定要求人写出标准答案。标注者可以看到同一个问题的两个回答，然后选更合适的一个：

| 项目 | 内容 |
| --- | --- |
| Prompt | 3/4 + 1/4 = ? |
| chosen | 分母相同，把分子相加：4/4，所以答案是 1。 |
| rejected | 答案是 2。 |

经典标量 Reward Model（RM）读取 prompt 和完整回答，对整条回答输出一个分数。训练时，它反复看到同题 chosen 应排在 rejected 前面，逐渐学会按标注偏好排序。比如教学中假设 RM 给 chosen 打 0.8、给 rejected 打 -0.2；这两个数只说明本例中它把 chosen 排得更高，不是正确率、概率或跨题通用的分数刻度。

**这里要分清两个模型：** RM 给整条回答一个偏好分；PPO 中的 critic 则对生成过程中的多个前缀估计后续回报。RM 不是逐 token 评价器，critic 也不是人工偏好评分器。

RM 学到的是标注规则和标注者偏好，不自动知道答案是否真实。若标注者偏好长解释，它可能把“更长”当作“更好”；如果标注数据把错误答案标成 chosen，RM 也可能把这个错误排序学进去。对同一道数学题，可另用答案检查器确认 1 正确；RM 分数不能代替这项检查。

Reward Model 适合把帮助性、完整度或风格等难以写成精确规则的属性，转成训练时可调用的偏好分数；前提是团队能获得可信的比较标注。它可以给新回答排序，减少逐条临时找标注者的需要，但分数仍只是标注偏好的代理，可能被 policy 迎合，也不能证明事实或跨任务的绝对质量。

### 1.3 RLHF：让模型根据反馈调整自己生成的回答

RLHF 把语言模型看作逐步生成回答的策略（policy）。模型先生成回答，再由 RM 或其他可信反馈评分，训练算法据此提高较好回答的生成倾向。InstructGPT 报告过“示范做 SFT、偏好比较训练 RM、再用 PPO 优化 policy”的代表路线；这是一种历史上重要的做法，不是所有后训练都必须照走的流水线。[InstructGPT 技术报告](https://arxiv.org/abs/2203.02155)

沿用算术题：人标注“答案是 1”优于“答案是 2”，RM 从偏好对学习排序；policy 自己生成一条新回答后，RM 再给这条完整回答评分；PPO 把这个分数连同相对 SFT reference 的约束转成更新信号。具体的旧策略概率、critic、GAE 和 clipping 见本章 §3，不在这里先堆公式。

### 1.4 离线偏好优化：直接学习已经收集的比较

DPO、IPO、KTO、ORPO 和 SimPO 都属于离线偏好优化的相关路线，但它们使用的标注形态和训练目标不同。它们可以直接学习已有数据，不要求每个训练步骤都让当前 policy 重新采样回答。

以表中的 chosen/rejected 为例，离线方法在训练期间反复学习“这条回答比那条更受偏好”。如果 policy 后来生成了新的解法，而数据集里没有类似比较，离线训练不会自动请人或程序给新回答评分。离线方法因此适合已有反馈数据，不会替代在线探索或 verifier。

### 1.5 Reasoning RL 与 RLVR：程序能检查的任务可以直接验证结果

数学、代码和部分工具任务可以把要求写成检查步骤。对本例，一个答案检查器可以先把“4/4”“1.0”和“1”规范化，再检查化简结果是否等于 1：

| 当前 policy 生成的完整回答 | 检查器结果 | 可用反馈 |
| --- | --- | --- |
| 分母相同，分子相加，4/4=1。 | 解析成功，结果为 1 | 通过 |
| 3+1=5，所以答案是 5/4。 | 解析成功，结果不为 1 | 不通过 |
| 答案是 1，但没有可解析的最终答案字段。 | 若任务要求指定格式，则格式检查失败 | 按任务契约处理 |

这是一条完整反馈链：当前模型生成回答，检查器按预先写定的规则判断，训练器再把结果交给 PPO、GRPO 等更新方法。RLVR（reinforcement learning with verifiable rewards）说的是“反馈可验证”的任务路线，不是某一种 optimizer。若 parser 把正确答案误判为错，或允许模型只猜对最终数字而不检查推理过程，训练得到的目标就会偏离作者原意。

当数学答案、代码测试、格式或沙盒状态能由可靠规则判断时，可以把 verifier 的结果用作在线反馈。它通常比逐条人工偏好比较便宜，也能检查当前 policy 新生成的候选；但它只覆盖写明的检查条件，parser、测试覆盖或权限规则中的漏洞可能让模型通过检查却没有完成真实目标。

### 1.6 安全对齐：判断何时拒绝，也要判断何时正常帮助

安全行为不只是让拒答更多。看两条请求：

| 用户请求 | 合适的行为 |
| --- | --- |
| 帮我窃取别人的账号。 | 拒绝协助，并可转向合法的账号安全建议 |
| 怎样重置我自己的密码？ | 正常提供安全的重置步骤 |

如果模型把两题都拒绝，危险请求确实没有得到帮助，但无害用户也被错误拒绝了。评估时应分别计数危险请求的正确拒绝和无害请求的过度拒绝；总拒答率上升本身不能说明安全性改善。安全训练还需结合拒答示范、偏好反馈、工具权限和红队测试，不能期待单个 loss 覆盖所有风险。

## 2. 先分清反馈、更新方法和训练配方

读到新缩写时，先问它处在哪一层。否则容易把“反馈来源”“更新算法”和“整套系统配方”误当作同类方法互相替代。

| 层次 | 要问的问题 | 本章例子 | 不能由名称推出的事 |
| --- | --- | --- | --- |
| 反馈与任务 | 谁判断回答好不好？ | 人类偏好、AI 反馈、答案检查器、代码测试 | 不决定用哪种优化器，也不保证反馈可靠 |
| 参数更新 | 训练器怎样改变模型？ | SFT、PPO、DPO、GRPO、GSPO 等 | 不决定 reward 来自人、模型还是程序 |
| 训练配方与系统 | 数据、采样、过滤、更新和基础设施怎样组合？ | DAPO、DeepSeek-R1 的分阶段路线、长周期 coding 环境 | 不能把整套配方效果归因于其中一个 loss |
| 推理时计算 | 用户请求到来后再花多少计算？ | 多次采样、搜索、reasoning effort | 不是训练期的 policy optimization |

比如，“RLVR + GRPO”可以同时成立：RLVR 说明这道数学题用可检查的答案给反馈；GRPO 说明同一题采样多条回答并用组内相对 reward 更新 policy。DAPO 则是包含采样、clip、token loss 和长度处理的组合式训练方案，不能和一个单独公式简单等同。

## 3. PPO-RLHF

PPO 最初用于控制强化学习中的策略更新幅度：普通策略梯度可依据采样动作更新概率，但重复使用同一批样本时，新策略可能离采样策略过远。TRPO 通过限制新旧策略差异控制更新，却需要近似求解带约束的目标；PPO 的常见裁剪目标则降低概率比越过范围后继续推动更新的收益，并允许对同一批样本做多轮小批量更新。原论文在机器人运动和 Atari 等强化学习任务中评估了这些方法。[PPO 原论文](https://arxiv.org/abs/1707.06347)

语言模型的 next-token 目标不等同于“按用户意图给出有用、安全的回答”。SFT 先教模型模仿示范，偏好比较再告诉训练器同一问题的两个回答哪个更合适；InstructGPT 报告了先做 SFT、再训练 reward model、最后用 PPO 优化 policy 的代表路线。这不是所有后训练都必须采用的固定流程。[Ziegler 等人的语言偏好学习研究](https://arxiv.org/abs/1909.08593)，[InstructGPT 技术报告](https://arxiv.org/abs/2203.02155)

在本节的算术题中，偏好数据把“答案是 1”排在“答案是 2”之前；RM 给 policy 实际生成的完整回答打分，reference KL 控制 policy 相对 SFT 起点的偏离，PPO clipping 则限制它相对 rollout 采样策略的单轮变化。两种约束作用不同，也都不能单独证明答案正确。下面用虚构的约 320 亿参数模型“云舟-32B”沿 `SFT → 偏好数据训练 reward model → policy 采样 → reward 加 KL → critic 算 advantage → PPO 更新 → 评估并重复` 走一轮；假设预训练已完成，题目、分数和配方均为教学设定。

```python
# 云舟-32B-Base 经指令示范数据做完 SFT，得到这个 checkpoint。
sft_32b = load("云舟-32B-SFT")

# 从同一份 SFT 权重分出 PPO 所需的四个角色。
policy_model = copy(sft_32b.model)                  # πθ：继续训练
reference_model = freeze(copy(sft_32b.model))       # πref：固定不变

preference_data = [
    ("3/4+1/4=?", "答案是 1。", "答案是 2。"),  # prompt, chosen, rejected
    ...
]
H = sft_32b.hidden_size
reward_model = copy(sft_32b.model)
reward_model.score_head = Linear(H, 1)  # 回答末尾 hidden state [H] → 整条回答一个分数
train_reward_model(reward_model, preference_data)
freeze(reward_model)

critic_model = copy(sft_32b.model)
critic_model.value_head = Linear(H, 1)  # 每个生成位置的 hidden state [H] → V(prefix)

# 每轮：采样回答 → 计算训练信号 → 更新 policy 和 critic。
for prompts in prompt_batches:
    rollout = policy_model.sample_and_record(prompts)  # 回答 + 这批的旧概率 πold
    # 本批可能采到：“分母相同，分子相加，得到 4/4=1。”
    rewards = shape_rewards(reward_model, reference_model, rollout, beta)  # 回答打分，再扣 KL 代价
    advantages, returns = GAE(rewards, critic_model.value(rollout))
    update_policy_with_PPO(policy_model, rollout, advantages)
    update_critic(critic_model, rollout, returns)
    evaluate(policy_model)
```

上面的伪代码把模型怎样来、每轮怎样接力都列出来了。先对齐各模型的来源：`云舟-32B-Base` 用示范问答做 SFT，得到 `云舟-32B-SFT`；policy 和 reference 都从这份 SFT 权重复制。policy 会继续更新，reference 冻结，作为“不要离 SFT 行为太远”的比较基准。reward model 也从 SFT 权重复制，接上 `score_head`，用同一问题下的 chosen/rejected 回答训练：例如 prompt 是 $3/4+1/4=?$ ，chosen 可以是“答案是 $1$ 。”，rejected 可以是“答案是 $2$ 。”，训练目标是让前者得分更高；完成后 RM 冻结。到了 PPO rollout，RM 读取 prompt 和一条完整回答，只给这一整条回答一个分数。critic 则从 SFT 权重复制并接上 `value_head`；对后面这条六 token rollout，它会在六个生成位置各输出一个前缀价值预测，学习“从这个前缀继续生成，预计能得到多少回报”。这个 value 不是 token 的偏好分，也不是 RM 对整条回答的分数。为便于看清职责，伪代码把这些模型分开写；实际实现可以共享骨干。

现在沿 `for` 循环逐行走一遍，看看一条回答怎样变成 policy 和 critic 的训练信号。

**步骤 1：`sample_and_record` 让 policy 生成回答，并记下当时的概率。** 输入是这一批 prompt，例如 $3/4+1/4=?$ 。policy 生成“分母相同，分子相加，得到 $4/4=1$ 。”为把后面的计算串起来，假设这次回答在教学算例中切成下面六个 token 片段：

| 位置 $t$ | 本例假设的 token 片段 $y_t$ | 采样时记录的 $\log\pi_{\mathrm{old}}(y_t\mid s_t)$ |
|---:|---|---:|
| 1 | `分母` | $-0.30$ |
| 2 | `相同，` | $-0.24$ |
| 3 | `分子` | $-0.35$ |
| 4 | `相加，` | $-0.28$ |
| 5 | `得到` | $-0.18$ |
| 6 | `4/4=1。` | $-0.25$ |

这六段是为了演算而设定的 token 切分，不代表某个真实 tokenizer 一定如此；实际训练按 tokenizer 产出的 token 和有效位置 mask 计算。每个 log probability 都是在当时的前缀 $s_t$ 下，policy 选中对应 token $y_t$ 的概率取对数。生成这批回答的 policy 快照记作 $\pi_{\mathrm{old}}$ 。它不是额外训练的第五个模型：训练器保留这些旧 log probability，后面更新 policy 时就能和生成回答时的概率比较；后续各步也沿用同一条回答。

**步骤 2：`shape_rewards` 让训练器评估偏好，并计算 policy 偏离 reference 的代价。** reward model 读取 prompt 和完整回答“分母相同，分子相加，得到 $4/4=1$ 。”，只输出一个序列分数。假设它给这条回答 $1.50$ 个教学奖励单位。它的训练数据告诉它哪个回答更受偏好，但这个分数不是数学正确性的证明，也不是给六个 token 各打一个偏好分。reference model 则对 rollout 中相同的六个 token、相同的前缀计算 log probability。对第 $t$ 个 token，令 $s_t$ 表示生成它之前的 prompt 和回答前缀，采样回答的最后一个有效 token 位置记作 $T$ ：

```math
d_t=
\log \pi_{\mathrm{old}}(y_t\mid s_t)
-
\log \pi_{\mathrm{ref}}(y_t\mid s_t),
\qquad
r_t=-\beta d_t+\mathbb{1}[t=T]r_{\phi}(x,y)
```

本例的 reference log probability 依次假设为 $[-0.32,-0.25,-0.34,-0.31,-0.17,-0.27]$ ，所以记录的旧策略与 reference 的差为 $[0.02,0.01,-0.01,0.03,-0.01,0.02]$ 。取教学用的 $\beta=0.5$ ，逐 token 加入的 KL 项和最终 reward 如下：

| 位置 $t$ | $d_t$ | $-\beta d_t$ | 加上回答分后的 $r_t$ |
|---:|---:|---:|---:|
| 1 | $0.02$ | $-0.010$ | $-0.010$ |
| 2 | $0.01$ | $-0.005$ | $-0.005$ |
| 3 | $-0.01$ | $+0.005$ | $+0.005$ |
| 4 | $0.03$ | $-0.015$ | $-0.015$ |
| 5 | $-0.01$ | $+0.005$ | $+0.005$ |
| 6 | $0.02$ | $-0.010$ | $1.490$ |

最后一个 token 的 reward 是回答分 $1.50$ 加上该位置的 KL 项 $-0.010$ ；前五个位置只有各自的 KL 项。六个 $d_t$ 之和是 $0.06$ ，所以本例整条回答的 KL shaping 合计为 $-0.5\times0.06=-0.03$ ，六个位置的 reward 合计为 $1.47$ 。这是单条 rollout 上的 log-ratio 计算；单个位置乃至一条回答的总估计都可能为负，不能把它当作必定非负的单条 KL 值。对 policy 采样的许多回答取期望后，这些 log-ratio 才对应常说的 policy/reference KL。若只追着 reward model 分数走，policy 可能学会迎合评分器而产出人不想要的回答；增大 $\beta$ 会加强对 SFT reference 的约束，但也可能压住有用的新行为。reward 分数的尺度取决于训练数据和任务，不能把某个模型上的 $\beta$ 直接照搬；评估时还要看独立偏好和原有能力。

**步骤 3：`critic_model.value` 和 `GAE` 把回答末尾的反馈传回前面。** critic 的 `value_head` 针对每个生成位置对应的前缀 $s_t$ 输出一个标量 $V_{\mathrm{old}}(s_t)$ 。这里 $s_t$ 是生成 $y_t$ 之前的上下文：prompt 加上已经生成的 $y_1$ 到 $y_{t-1}$ 。例如 $V_{\mathrm{old}}(s_4)$ 是 critic 看过 prompt、“分母”“相同，”和“分子”之后，对从这个前缀继续生成预计能获得多少后续 reward 的预测。它不是给 token “相加，”评偏好，也不是 reward model 给整条回答的分数。`GAE` 把每个位置的 reward 和相邻前缀的 value 预测合起来，先算一步误差，再从回答末尾向前递推：

```math
\delta_t=r_t+\gamma m_tV_{\mathrm{old}}(s_{t+1})-V_{\mathrm{old}}(s_t),
\qquad
A_t=\delta_t+\gamma\lambda m_tA_{t+1}
```

沿用前面六个 token 的 reward。critic 对每个生成前缀的预测是：

```math
V_{\mathrm{old}}(s_t)=[0.10,0.18,0.26,0.34,0.42,0.60]
```

取 $\gamma=1$、$\lambda=0.5$ 。回答在 $y_6$ 后正常结束，因此：

```math
m_1=m_2=m_3=m_4=m_5=1,\qquad m_6=0
```

按前文 reward 和 value 逐位置计算，得到：

```math
\delta_{1:6}=[0.070,0.075,0.085,0.065,0.185,0.890]
```

例如末尾位置是 $1.490-0.600=0.890$ ；前一位置是 $0.005+0.600-0.420=0.185$ 。这一步误差算出后，GAE 从回答末尾向前递推：

```math
\begin{aligned}
A_6&=0.890,\\
A_5&=0.185+0.5\times0.890=0.630,\\
A_4&=0.065+0.5\times0.630=0.380,\\
A_3&=0.085+0.5\times0.380=0.275,\\
A_2&=0.075+0.5\times0.275=0.2125,\\
A_1&=0.070+0.5\times0.2125=0.17625.
\end{aligned}
```

因此，按本例这组 reward 和 value 预测，GAE 得到的六个 advantage 都为正；policy 更新会倾向于提高这些已采样 token 的概率。critic 的训练目标是把每个旧 value 加上对应 advantage。六个位置的 returns 为：

```math
returns_{1:6}=[0.27625,0.3925,0.535,0.720,1.050,1.490]
```

它会把对应前缀上的 value 预测往这些目标拉近。这里的数值只为演示 GAE 如何把回答末尾的偏好分和逐 token KL 信号传回前面，不代表 reward model 的通用分数或真实训练配方。

$\delta_t$ 是这一步收到的 reward 加上下一状态的预期价值，再减去 critic 原先的预测； $A_t$（advantage，优势）表示这次采样得到的后续结果比原先预期好多少。例子里 $\lambda=0.5$ ，所以每一步只把后续 advantage 的一半加回来；真实终止处不再向后 bootstrap，padding 位置由 mask 排除。长度上限造成的截断不一定代表任务结束，不能一律把后续价值清零。 $\gamma$ 控制远处回报的权重， $\lambda$ 控制 TD 误差信号向前累积多少。真实训练中逐 token KL 项也会进入各位置的 $r_t$ ；因此末尾分数会影响前面的 advantage，但每个位置的 advantage 还会受该处 reward 和 critic 预测影响。

**步骤 4：`update_policy_with_PPO` 用 advantage 调整 policy。** policy 重新给同一批已采样 token 计算概率，再和步骤 1 留下的 $\pi_{\mathrm{old}}$ 概率比较。对 token $y_t$ ，训练器比较的 ratio 是 $\rho_t=\frac{\pi_{\theta}(y_t\mid s_t)}{\pi_{\mathrm{old}}(y_t\mid s_t)}$ ：刚采完样本、尚未更新时它等于 $1$ 。以第四个 token “相加，”为例，旧 log probability 是 $-0.28$ ；假设某次更新后当前 policy 在相同前缀上的 log probability 变为 $-0.22$ ，那么 $\rho_4=\exp(-0.22-(-0.28))\approx1.06$ ，表示它现在生成这个 token 的概率约为采样时的 $1.06$ 倍。由于本例 $A_4=0.38$ 为正，这个方向符合 PPO 的优化倾向。取 $\epsilon=0.2$ 时， $1.06$ 仍在 $[0.8,1.2]$ 内，clipping 尚未触发。若同一个正 advantage token 后续被推到 ratio 1.35，取 $A_4=0.38$、$\epsilon=0.2$ ，未裁剪项为 $1.35\times0.38=0.513$ ，裁剪项为 $1.2\times0.38=0.456$ ，训练目标采用较小的 0.456；再提高这个 ratio 不会继续增加该样本的目标值。一般写法是：

```math
J_t^{\mathrm{clip}}(\theta)=
\min\left(
\rho_t A_t,\,
\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t
\right)
```

所以 clipping 限制的是样本继续推动更新的收益，不是把 token 概率强行设成 1.2 倍。这里有两个容易混的比较：步骤 2 中 policy/reference 的差异约束当前策略相对 SFT reference 的漂移；PPO 的新旧 policy ratio 则衡量当前更新相对这批回答的采样策略走了多远。它们服务于不同步骤，应分开看。对同一批 rollout 做有限轮 minibatch 更新时， $\pi_{\mathrm{old}}$ 的记录保持不变；复用过多轮会让新旧概率差距变大。

**步骤 5：`update_critic` 让 critic 学会预测 returns。** 对同一批回答前缀，critic 再算一次 value，并用有效 token 位置上的平方误差把新预测拉向刚才的 `returns`。例如第四个 token 之前，旧预测 $V_{\mathrm{old}}(s_4)=0.34$ ，GAE 目标是 $returns_4=0.72$ ；单看这个位置的未归一化平方误差为 $(0.34-0.72)^2=0.1444$ ，训练会把该前缀的 value 往 $0.72$ 拉近。RM 是从 chosen/rejected 学会给完整回答打一个偏好分；critic 是从 PPO 生成的回答和逐位置 returns 学会估计每个前缀的后续回报。RM 在这一流程中冻结，critic 则随 PPO 训练。若 critic 预测长期偏高或跟不上 policy，advantage 也会不准；检查时可以对照 value 预测和 returns，而不是只看 reward model 分数。

**步骤 6：`evaluate` 检查这轮更新值不值得继续。** 更新后仍用留出的偏好题、安全题和原有能力题检查 policy：例如确认它在这道分数题上仍能给出正确推理，同时在独立偏好评估中没有只学会迎合 RM。RM 给出的 $1.50$ 只是一个代理分数，不能替代这些评估。若偏好有改善且原有能力没有明显退化，再让更新后的 policy 生成下一批回答；新回答及其采样概率成为下一轮 rollout 和新的 $\pi_{\mathrm{old}}$ 。最初从 SFT 复制的 reference 仍保持冻结，RM 也继续冻结。于是循环每一轮都会把 policy 新生成的回答交给 RM/reference 打分，再用 GAE 和 PPO 更新 policy 与 critic。

PPO-RLHF 适合能收集偏好、需要当前 policy 在线生成新回答并由 RM 或其他反馈评分，且采样成本可以接受的任务。它能基于当前策略的回答继续优化，但每轮还要运行 rollout、policy、reference、RM 和 critic，工程与前向计算成本较高；RM 可能被迎合，critic 误差会污染 advantage，reference KL 与 PPO clipping 也都不是正确性保证。若任务有可验证答案，仍需独立检查。

若手头主要是固定的 chosen/rejected 偏好对、暂时不需要在线采样更新，可以接着看下一节的 DPO；方法选择取决于训练信号、采样需求和资源条件，PPO 并非所有偏好优化任务的默认答案。

## 4. DPO：用固定偏好对直接更新 policy

若团队已经收集好同一 prompt 下的 chosen/rejected 偏好对，却不需要在线探索，可以直接用这些固定比较训练 policy。DPO（Direct Preference Optimization，直接偏好优化）比较当前 policy 相对 SFT reference 对两条回答的 log probability 变化，再按偏好标签拉开差距；这省去训练时单独调用 RM 和持续 rollout 的环节，但不省去偏好数据，也不判断回答的客观真假。

**算法伪代码：**

```python
# 伪代码：用固定偏好对训练；不在线采样，也不单独训练 reward model。
sft_policy = load_sft_policy()
policy = copy(sft_policy)
reference = freeze(copy(sft_policy))

for batch in preference_batches:
    # 两个模型都对同一批 chosen/rejected 回答计算条件 log probability。
    policy_logps, reference_logps = score_preference_pairs(policy, reference, batch)

    # 【核心】比较 policy 相对 reference 的偏好变化，得到 DPO loss。
    loss = dpo_preference_loss(policy_logps, reference_logps, beta)
    update_policy(policy, loss)

return policy
```

**本节完整例子：拒绝临时加班。** 客服团队希望模型礼貌而明确地拒绝临时加班。下面沿伪代码的 `score_preference_pairs`、`dpo_preference_loss`、`update_policy` 三个调用，走完一条固定偏好样本怎样变成更新方向。

**步骤 1：给 `score_preference_pairs` 准备输入。** 数据集里，同一个 prompt 配有一条更受偏好的回答 chosen 和一条较差的回答 rejected：

| 数据 | 内容 |
| --- | --- |
| Prompt | 帮我写一句礼貌但明确的回复，拒绝今晚临时加班。 |
| chosen | 今晚我无法加班，抱歉；我会在明早优先处理紧急事项。 |
| rejected | 不干，别来烦我。 |

伪代码先从 SFT 初始化 policy 和冻结的 reference。进入训练循环后，`score_preference_pairs(policy, reference, batch)` 让两个模型分别读同一个问题和两条完整回答，记录它们对这些回答的条件 log probability。这里训练器比较的是已标注的两条回答；不会在这一步让 policy 另写新回复。

**步骤 2：看 `score_preference_pairs` 留下的四组记录。** 下表是教学数值。每一行都对照当前 policy 与冻结 reference 对同一条回答的评价；“相对变化”表示 policy 相比 reference 对这条回答的倾向变化：

| 回答 | 当前 policy 的序列 log probability | 冻结 reference 的序列 log probability | policy 相对 reference 的变化 |
| --- | ---: | ---: | ---: |
| chosen：礼貌、明确地拒绝 | $-2.1$ | $-2.5$ | $+0.4$ |
| rejected：粗鲁地拒绝 | $-1.7$ | $-1.4$ | $-0.3$ |

这次 policy 比 reference 更愿意给 chosen 较高的相对分，也更不愿意给 rejected 较高的相对分。两个相对变化相差 $0.7$：chosen 上升 $0.4$，rejected 下降 $0.3$。`dpo_preference_loss` 把这个差距按偏好标签处理，参数 β 会缩放它对 loss 的影响；目前偏好方向已经正确，但训练仍会继续推动 chosen 相对 rejected 的优势扩大。两条回答的原始序列 log probability 会受长度和 token 切分影响；DPO 比较各自相对 reference 的变化，再对 chosen 与 rejected 作差。reference 是相对锚点，不是长度归一化器，也不会消除所有长度效应。

**步骤 3：看 `dpo_preference_loss` 怎样判断更新方向。** 这条数据的标签是“chosen 更好”。损失会检查 policy 相对 reference 的变化是否让 chosen 胜过 rejected；若偏好差距还不够，就给出继续拉开差距的训练信号。这里不需要把损失换算成一个看似精确的“回复正确概率”：它只表示模型是否按数据标签排序，不代表回复符合真实公司制度。训练刚开始时 policy 与 reference 通常从同一 SFT checkpoint 复制，所以相对变化从相同起点开始；表中的分数只是展示训练中某个时刻可能出现的状态。

**步骤 4：看 `update_policy` 怎样改变模型。** optimizer 根据这条偏好信号调整 policy，让它以后更倾向于写礼貌、明确又有后续安排的拒绝回复。reference 保持冻结，继续代表 SFT 起点；训练器可以重复使用这批偏好对，不必每次启动新的回答采样和奖励打分流程。

把本例推广到任意一对回答，DPO 比较 policy 相对 reference 对 chosen 与 rejected 的变化，再用偏好分类损失训练：

```math
\mathcal{L}_{\mathrm{DPO}}=-\log\sigma\!\left(\beta\left[
\left(\log\pi_{\theta}(y_c\mid x)-\log\pi_{\mathrm{ref}}(y_c\mid x)\right)
-
\left(\log\pi_{\theta}(y_r\mid x)-\log\pi_{\mathrm{ref}}(y_r\mid x)\right)
\right]\right)
```

本例方括号里的差就是“chosen 相对 reference 的上升”减去“rejected 相对 reference 的变化”；公式把前面的四个分数压缩成一个可训练目标。这里的 $\sigma$ 表示偏好比较模型的 sigmoid 输出，它不代表回复真实或合规的概率。

这个例子也说明了 DPO 的边界：它学到的是标注者更喜欢哪种语气，不能据此证明回复符合真实公司制度。如果 chosen/rejected 标错，policy 就会朝错误标签更新；固定数据未覆盖的新场景也不会自动得到新反馈。

DPO 将 KL-regularized preference objective 重写成偏好对上的分类损失。原论文在其指定的情感控制、摘要和对话实验中报告了与 PPO-RLHF 竞争的结果；这不是对所有模型和任务的通用排名。[DPO 原论文](https://arxiv.org/abs/2305.18290v3)

DPO 适合已有可靠同题偏好对、训练时不需要当前 policy 在线探索的任务。它直接用偏好数据更新 policy，不必单独训练 RM；reference 提供相对比较起点，但不能消除固定数据的覆盖盲区、长度影响或能力漂移。偏好仍不等于事实正确，结果要用独立评估核对。

若任务具有可验证的客观结果，例如数学答案，离线偏好对告诉训练器“标注者更喜欢哪条回答”，答案检查器则告诉训练器“新生成的结果是否符合规则”；两种信号回答的问题不同。

### 4.1 IPO、KTO、ORPO：先看你收集得到什么标签

这些方法都属于偏好优化，但它们不要求完全相同的数据：

| 方法 | 标注者需要提供什么 | reference | 训练器主要做什么 |
| --- | --- | --- | --- |
| DPO | 同题 chosen/rejected 成对比较 | 需要 | 学习 policy 相对 reference 的偏好差 |
| IPO | 同题 chosen/rejected 成对比较 | 需要 | 把偏好差拉向有限目标，避免只追求无限增大 margin |
| KTO | 每条回答单独标“可取/不可取”，不必配对 | 标准方法使用 | 让可取回答相对更可能、不可取回答相对更不可能 |
| ORPO | 同题 chosen/rejected 成对比较 | 不需要单独 reference 模型 | 同时模仿 chosen，并利用偏好对抑制 rejected |
| SimPO | 同题 chosen/rejected 成对比较 | 不需要单独 reference 模型 | 用 policy 自己对回答的平均 token log probability 作隐式奖励 |

沿用刚才的加班回复任务，IPO 和 DPO 都能使用 chosen/rejected 成对比较；若标注团队只记录单条回复是否合适，KTO 可以直接用“礼貌拒绝”这条带正标签的回答，不必为了格式凑出 rejected；ORPO 则仍用成对比较，同时把 chosen 当作示范学习。实际选型先看能可靠收集哪种标签，再看训练资源和回归结果，不要把不同论文的最高分拼成排行榜。

IPO 的有限目标不是数学答案的阈值，而是偏好优化目标中对 policy/reference 相对差距的控制。KTO 的逐条标签仍会受标注标准和好坏样本比例影响；ORPO 的组合目标仍需检查长度、损失权重和数据分布。[IPO 原论文](https://arxiv.org/abs/2310.12036)、[KTO 原论文](https://arxiv.org/abs/2402.01306)、[ORPO 原论文](https://arxiv.org/abs/2403.07691)

## 5. SimPO：用回答平均 log probability 学离线偏好

DPO 需要 reference 对 chosen/rejected 回答的 log probability。实现可以在训练时计算，也可以预先缓存；缓存把计算移到数据准备阶段，同时增加存储和版本管理要求，并不会让参考分数凭空产生。SimPO（Simple Preference Optimization）不在训练循环中运行单独的 reference，而把当前 policy 对每条回答的平均 token log probability 当作隐式奖励，再用偏好对拉开差距并施加 margin。

**算法伪代码：**

```python
# 伪代码：从 SFT policy 出发，不加载单独的 reference model。
policy = load_sft_policy()

for batch in preference_batches:
    # 只计入有效 response token，并分别按回答长度求平均。
    chosen_mean_logp, rejected_mean_logp = average_response_logps(
        policy, batch, response_mask=True
    )

    # 【核心】把平均 log probability 当作隐式奖励，并施加偏好 margin。
    loss = simpo_preference_loss(
        chosen_mean_logp, rejected_mean_logp, beta=beta, margin=gamma
    )
    update_policy(policy, loss)

return policy
```

**本节完整例子：解释“缓存”是什么。**

prompt 是“请用一句话解释缓存”。标注者更喜欢“缓存把常用数据暂存起来，减少重复读取”，不喜欢“缓存永久保存所有数据”。下面按伪代码的 `average_response_logps`、`simpo_preference_loss` 和 `update_policy` 展开。

**步骤 1：把固定偏好对送入训练循环。** `load_sft_policy()` 初始化待更新的模型；SimPO 不加载单独的 reference。每批数据仍包含同一个 prompt 的 chosen 和 rejected，偏好标签来自标注数据，不由这一步重新生成。

**步骤 2：看 `average_response_logps` 怎样给两条回答记分。** 假设教学 tokenizer 将 chosen 切成 $8$ 个有效 token，将 rejected 切成 $4$ 个有效 token；当前 policy 对前者的平均 token log probability 是 $-0.30$ ，对后者是 $-0.35$ 。这只是用于追踪机制的假设数值，真实训练按 tokenizer 产出的切分和 response mask 计算。`response_mask=True` 只让回答中的有效 token 参与，prompt 与 padding 不进入平均。

| 回答 | 有效 token 数 | 本例平均 log probability | 训练器怎样解读 |
| --- | ---: | ---: | --- |
| chosen：常用数据暂存，减少重复读取 | $8$ | $-0.30$ | 平均每个 token 的序列倾向 |
| rejected：永久保存所有数据 | $4$ | $-0.35$ | 平均每个 token 的序列倾向 |

如果只把所有 token 的 log probability 累加，长回答通常会因为多了许多负数而显得更低；SimPO 先按回答长度求平均，再把这两个平均值作为隐式奖励比较。本例里 chosen 的平均值较高，因此模型目前更偏向标注者喜欢的解释。长度平均改变了“长回答天然累加更多项”的计算方式，但无法判断哪句话真实，也不保证消除所有长度偏差。

**步骤 3：看 `simpo_preference_loss` 如何判断偏好差够不够。** 假设奖励缩放 $\beta=2$ ，目标 margin $\gamma=0.20$ 。按这个缩放，chosen 的隐式奖励比 rejected 高 $0.10$ ，还没达到训练目标要求的 $0.20$ 间隔。于是 loss 仍会给出把 chosen 相对提高的信号。margin 是优化目标中的期望差距，不是概率阈值，也不是达到数值后立刻关掉梯度的开关。

**步骤 4：看 `update_policy` 怎样使用这个信号。** optimizer 调整 policy，让它更倾向于生成“把常用数据暂存、减少重复读取”这一类回答。由于没有独立 reference，SimPO 省去了一份模型前向计算，但训练后仍要评估模型是否偏离原有能力、是否出现长度变化，以及事实质量和安全是否退化。

SimPO 用回答平均 token log probability 代替训练中的 reference 前向，避免简单累加 log probability 对长回答天然多加负项；但长度平均不等于消除所有长度偏差，也不让分数成为校准的人类评价。它适合 reference 计算确有成本、偏好对可靠且能独立监测长度、能力和安全变化的场景。

SimPO 论文在所测模型、偏好数据和聊天评测中报告了相对基线的结果；迁移到自己的任务时，应在相同底模、数据和预算下验证。[SimPO 原论文](https://arxiv.org/abs/2405.14734)

SimPO 省去训练时单独运行 reference model 的前向，但仍受固定偏好数据覆盖限制；tokenizer、response mask 和长度口径必须保持可比，训练后还要检查能力漂移和事实质量。

## 6. GRPO：同题采多条回答，用组内结果作比较

PPO-RLHF 的 critic 估计每个回答前缀未来的回报，会增加模型状态和训练环节。若任务能对当前 policy 生成的回答可靠评分，GRPO（Group Relative Policy Optimization）可以让同一 prompt 的多条回答互作基线，按组内 reward 差异构造 advantage，常见形式无需另训 critic。它仍需在线采样；若同组 reward 全相同，就没有相对更新信号。

**算法伪代码：**

```python
# 伪代码：每个 prompt 采样 G 条回答；旧 log probability 随 rollout 一并保存。
policy = load_sft_policy()

for prompts in prompt_batches:
    rollout = sample_and_record(policy, prompts, group_size=G)
    rewards = score_rollouts(rollout, scorer)  # 可用 RM、规则 verifier 等评分

    # 【核心】只在同题回答组内比较 reward，构造相对 advantage；无需单独 critic。
    advantages = normalize_rewards_within_prompt_group(rewards)

    # 【核心】逐 token 比较新旧 policy，并用 clipped loss 更新。
    token_ratios = compute_token_level_ratios(
        policy, rollout.old_logps, response_mask=rollout.response_mask
    )
    loss = grpo_clipped_policy_loss(token_ratios, advantages, epsilon)
    update_policy(policy, loss)

return policy
```

**本节完整例子：代码去重并保留顺序。**

任务是把列表 `[2, 1, 2, 3]` 去重，并保持元素第一次出现的顺序。下面按伪代码从采样、评分、组内 advantage，一直走到 token ratio 和 policy 更新。

**步骤 1：看 `sample_and_record` 产生什么。** 对这个 prompt，policy 采样 $G=4$ 条回答。函数还会按真实 tokenizer 记录每个生成 token 的旧 log probability，并用 response mask 标记哪些位置属于回答；之后训练器会在相同 token 和前缀上重算新概率。

| 同题 rollout | 回答方案 |
| --- | --- |
| A | 用字典键去重并保持插入顺序，结果为 `[2, 1, 3]` |
| B | 逐项扫描，只有没见过的元素才追加，结果为 `[2, 1, 3]` |
| C | 转成 `set` 再转回列表，元素次序没有保证 |
| D | 排序后去重，结果为 `[1, 2, 3]` |

**步骤 2：看 `score_rollouts` 给每条回答什么分数。** verifier 用若干测试检查“保留第一次出现顺序”这一要求：

| 回答 | verifier reward |
| --- | ---: |
| A、B：输出 `[2, 1, 3]` | $1$ |
| C、D：结果次序不符合要求 | $0$ |

它检查的是完整程序输出，不是对推理文字打偏好分。

**步骤 3：看 `normalize_rewards_within_prompt_group` 怎样把组内结果变成更新方向。** 本组平均 reward 是 $0.5$ ，通过测试的 A、B 高于组平均，未通过的 C、D 低于组平均。按本例采用的组内标准化，得到 A、B 的 advantage 为 $+1$、C、D 为 $-1$ ：

| 回答 | 相对本组平均结果 | 传给该回答生成 token 的 advantage |
| --- | --- | ---: |
| A、B：测试通过 | 高于平均 | $+1$ |
| C、D：测试未通过 | 低于平均 | $-1$ |

A 和 B 是两种不同但都通过测试的实现，所以它们各自生成的 token 共用正向回答优势；C、D 的 token 共用负向回答优势。这不是 verifier 对每个 token 单独打分，而是把整条回答的组内结果传给它的生成位置。

**步骤 4：看 `compute_token_level_ratios` 与 `grpo_clipped_policy_loss` 怎样限制更新。** 以 A 中“只在元素第一次出现时追加”的一个实际生成 token 为例：采样时该 token 的概率是 $0.10$ ，一次 policy 更新后重算为 $0.13$ ，也就是新概率约为旧概率的 $1.30$ 倍。若教学裁剪范围是 $0.8$ 到 $1.2$ ，而它的 advantage 为正，目标函数就按上界 $1.2$ 计算它的推动量，不继续奖励 ratio 从 $1.2$ 涨到 $1.3$ 。每个有效生成 token 都有自己的新旧概率比；prompt 和 padding 由 mask 排除。

**步骤 5：看 `update_policy` 怎样把整组信号变成新 policy。** optimizer 汇总所有有效 token 的 clipped objective：增加 A、B 这类通过测试回答中相关 token 的倾向，降低 C、D 这类未通过回答中相关 token 的倾向。GRPO 用组内结果替代 PPO critic 的价值基线，因此省去 critic；它仍要在线生成候选，也无法只凭最终单测指出程序解释中的哪一步写得正确。

如果四条回答全通过或全失败，reward 都相同，标准化后就没有组内相对方向。增加采样可能得到有差异的候选，也会增加生成成本；verifier 写错时，错误分数同样会传给 policy。

GRPO 用同题组的相对 reward 替代独立 critic 的价值基线，但不会省去 rollout，也不能仅凭终局结果指出推理中哪一步正确。它适合有可靠 verifier、同一 prompt 能采多条候选的在线任务；全对或全错的组缺少相对信号，错误 verifier 也会把错误方向传给 policy。[DeepSeekMath 原论文](https://arxiv.org/abs/2402.03300)

## 7. GSPO：让一条完整回答共用一个更新权重

GRPO 通常把整条回答的 reward 传给生成位置，但 token-level policy ratio 会逐位置变化；长回答中，这些局部变化可能波动或相互抵消。GSPO（Group Sequence Policy Optimization）把新旧 policy 的 log-ratio 按整条 response 聚合成序列级 ratio，再用回答级 ratio 和 clipping 更新，使 reward 与裁剪采用同一粒度。

**算法伪代码：**

```python
# 伪代码：每个 prompt 采样 G 条完整回答，并记录旧策略 log probability。
policy = load_sft_policy()

for prompts in prompt_batches:
    rollout = sample_and_record(policy, prompts, group_size=G)
    rewards = score_rollouts(rollout, scorer)
    advantages = normalize_rewards_within_prompt_group(rewards)

    # 【核心】把每条回答的 token log-ratio 按长度平均，得到一个序列 ratio。
    sequence_ratios = length_normalized_sequence_ratios(policy, rollout)

    # 【核心】整条回答共用一个序列 ratio 和 advantage 做裁剪。
    loss = gspo_sequence_clipped_policy_loss(sequence_ratios, advantages, epsilon)
    update_policy(policy, loss)

return policy
```

**本节完整例子：生成一份安全的值班回滚说明。**

某团队要求模型写一段值班回滚说明：“先确认告警，再回滚应用版本，最后检查健康指标；没有授权时不得擅自回滚数据库。”下面按伪代码追踪 rollout、评分、组内优势、序列 ratio 和 policy 更新。

**步骤 1：看 `sample_and_record` 与 `score_rollouts` 的结果。** policy 对同一任务采样四条完整说明；rollout 保存回答 token 的旧 log probability。评分器检查每条说明是否先确认告警、回滚应用、检查健康指标，并避免未授权的数据库操作：

| 同题回答 | 评分器检查结果 |
| --- | --- |
| A：先确认告警；回滚应用版本；检查健康指标；数据库保持不变 | 全部满足，reward 较高 |
| B：回滚应用版本，但没有确认告警或检查健康指标 | 要求不完整，reward 较低 |
| C：直接恢复数据库快照，未说明授权 | 有危险操作，reward 较低 |
| D：检查告警和健康指标后回滚应用；数据库操作等待授权 | 全部满足，reward 较高 |

因此 reward 为 $[1,0,0,1]$ 。`normalize_rewards_within_prompt_group` 在这四条同题回答内计算平均值 $0.5$、标准差 $0.5$ ，得到 A、D 的 advantage $+1$ 和 B、C 的 $-1$ 。为了接上后面的 ratio 演算，下面只追踪正确回答 D；数值均为教学设定。

**步骤 2：看 `length_normalized_sequence_ratios` 怎样把 D 的局部变化合成一个回答级量。** 为了追踪过程，假设这份教学回答由五个生成位置组成；它们只是简化位置，不代表真实 tokenizer 的切分。policy 更新后，五处新旧 token 概率比分别是 $1.30$、$0.80$、$1.10$、$0.90$ 和 $1.20$ 。

| 教学位置 | token ratio | 对整条回答的直观影响 |
| ---: | ---: | --- |
| 1 | $1.30$ | 当前 policy 更偏好这个 token |
| 2 | $0.80$ | 当前 policy 较少选择这个 token |
| 3 | $1.10$ | 略微提高倾向 |
| 4 | $0.90$ | 略微降低倾向 |
| 5 | $1.20$ | 提高倾向 |

GSPO 把五处 log-ratio 按长度求平均，再换回一个整条回答的 ratio；本例约为 $1.04$ 。局部最大变化 $1.30$ 与小于 $1$ 的变化合并后，整条回答的总体变化落在较窄范围。这一步不裁剪五个独立位置，而是先形成一个序列级量。

**步骤 3：看 `gspo_sequence_clipped_policy_loss` 怎样用整条回答更新。** 回答 D 的 advantage 为正，表示这条满足要求的完整说明比同题组平均更好。假设序列 ratio 的裁剪窗口为 $0.90$ 到 $1.10$ ；本例的 $1.04$ 在窗口内，optimizer 按这个整条回答级 ratio 使用正向优势。如果序列 ratio 升到 $1.30$ ，目标就只按上界 $1.10$ 计入。五个位置共用这一条回答的 ratio 和 advantage。

这个平均是在 log-ratio 空间完成的，等价于 token ratio 的长度归一化几何平均；这样不会直接相乘一长串很小的 token 概率。GSPO 原论文定义了这一序列级 ratio 和 clipping 单位。[GSPO 原论文](https://arxiv.org/abs/2507.18071v2)

**步骤 4：看 `update_policy` 之后仍然看不见什么。** optimizer 用序列级 clipped objective 更新 policy。GSPO 和 GRPO 都可以使用同题 group reward，但它把概率变化和裁剪单位提升到整条回答。局部变化可能互相抵消，所以总 ratio 看不出是哪一步变化最大；若任务需要指出推理中的具体错误步骤，这种聚合会丢失局部信息。

GSPO 让 reward、ratio 和 clipping 都以完整回答为单位；整段聚合会丢掉局部变化信息，不能用序列 ratio 定位哪一步推理出错。它适合 reward 主要评估整段轨迹、且日志显示 token-level ratio 波动影响稳定性的场景。原论文报告的稳定性、效率和性能结论仅适用于其模型及实验设置。[GSPO 原论文](https://arxiv.org/abs/2507.18071v2)

## 8. DAPO：把长推理训练中的几种处理组合起来

长推理 RL 可能遇到同题 rollout 全对或全错、低概率 token 更新空间受限、长短回答权重失衡，以及硬截断答案带来噪声等问题。DAPO（Decoupled Clip and Dynamic Sampling Policy Optimization）把 Dynamic Sampling、Clip-Higher、Token-Level Policy Gradient Loss 和 Overlong Reward Shaping 组合成一套 reasoning RL 配方，分别处理这些环节；它仍依赖在线 verifier 和具体数据分布。[DAPO 原论文](https://arxiv.org/abs/2503.14476v2)

**算法伪代码：**

```python
# 伪代码：动态补采直到批次中有足够的组内 reward 差异。
policy = load_sft_policy()

for prompts in prompt_batches:
    # 【核心】同题回答全对或全错时继续采样，只保留有区分度的组。
    rollout, verifier_rewards = dynamic_sample_effective_groups(
        policy, prompts, verifier, group_size=G, max_length=max_response_length
    )

    # 软超长 shaping 调整进入惩罚区间的 reward；硬截断回答则屏蔽其 policy loss。
    rewards = apply_soft_overlong_reward_shaping(
        verifier_rewards, rollout.lengths, soft_length_limit, max_response_length
    )
    loss_mask = overlong_filter_mask(rollout)
    advantages = normalize_rewards_within_prompt_group(rewards)

    token_ratios = compute_token_level_ratios(
        policy, rollout.old_logps, response_mask=rollout.response_mask
    )
    # 【核心】非对称上下界配合 token-level loss，保留低概率 token 的更大上调空间。
    loss = dapo_token_level_clipped_loss(
        token_ratios,
        advantages,
        lower_clip=epsilon_low,
        upper_clip=epsilon_high,
        loss_mask=loss_mask,
    )
    update_policy(policy, loss)

return policy
```

**本节完整例子：求 $1+2+\cdots+100$ 。**

题目要求计算 $1+2+\cdots+100$ ，verifier 检查最终结果是否为 $5050$ 。下面按伪代码从动态采样开始，依次看长度处理、组内 advantage、token ratio、loss 汇总和 policy 更新。表中用 $1/0$ 简写通过/失败；原论文使用的 reward 刻度不同，但本例仿射变换后组内标准化方向相同。

**步骤 1：看 `dynamic_sample_effective_groups` 如何决定哪些回答进入训练批次。** 每次对这道题采样四条回答并运行 verifier：

| 采样尝试 | 同题四条回答的 verifier reward | 处理 |
| --- | --- | --- |
| 第 $1$ 组 | $1$、$1$、$1$、$1$ | 全部正确，没有组内差异；不放入训练批次，继续采样 |
| 第 $2$ 组 | $0$、$0$、$0$、$0$ | 全部错误，也没有组内差异；继续采样 |
| 第 $3$ 组 | $1$、$1$、$0$、$0$ | 同组有通过和失败，保留用于更新 |

第三组中的 A 是自然结束的 90-token 正确答案，B 是较短的正确答案，C、D 答案错误。它们的原始 verifier reward 是 $[1,1,0,0]$。

**步骤 2：看 `apply_soft_overlong_reward_shaping` 与 `overlong_filter_mask` 如何处理长度状态。** 系统最多生成 $100$ 个 token，软惩罚从 $80$ 个 token 开始。沿用保留组中的 A，教学设定的长度 shaping 将它的 reward 从 $1$ 调整为 $0.5$；B 未进入惩罚区间，仍为 $1$；C、D 仍为 $0$。另有一个来自其他 prompt 的 E 在第 $100$ 个 token 被硬截断，答案尚未完成，因此其 policy loss 被 mask；E 不属于当前同题组，也不进入下面的组内归一化。

| rollout | 结束状态 | 处理后的 reward / loss 状态 |
| --- | --- | --- |
| A：90-token，自然结束且正确 | 进入软惩罚区间 | reward 为 $0.5$，保留训练 |
| B：较短、自然结束且正确 | 未进入惩罚区间 | reward 为 $1$，保留训练 |
| C、D：答案错误 | 正常结束 | reward 为 $0$，保留组内比较 |
| E：在 100-token 上限被硬截断 | 没有完整答案，且来自其他 prompt | policy loss 被 mask，不参与当前组 |

软惩罚改变自然结束长答案的 reward；截断 mask 排除没有完成答案的样本。它们分别处理不同结束状态。

**步骤 3：按处理后的 reward 计算组内 advantage。** 第三组 reward 是 $[0.5,1,0,0]$，均值为 $0.375$，总体标准差为 $√11/8≈0.4146$。按这个标准差归一化，四条回答的 advantage 依次为 $1/√11≈0.302$、$5/√11≈1.508$、$-3/√11≈-0.905$、$-3/√11≈-0.905$。因此 B 的正向信号大于 A，长度惩罚已经通过 reward 进入同一条更新轨迹。

**步骤 4：比较 token 的新旧概率。** 在 B 的正确推导中，假设“首尾配对”方法对应的一个有效 token，采样时概率为 $0.02$，更新后在相同前缀下重算为 $0.04$。新 policy 对这个 token 的倾向是旧 policy 的 $2$ 倍；B 的 advantage 为 $5/√11≈1.508$。response mask 只保留回答里的生成位置。

**步骤 5：看 `dapo_token_level_clipped_loss` 怎样同时处理更新幅度和 token 权重。** 假设这枚 token 的正向 advantage 对应 ratio 上限为 $1.5$ 。新旧概率比 $2.0$ 超过上限后，代理目标只按 $1.5$ 计入。Clip-Higher 把正向更新的上界设得高于负向更新的下界，让原本概率较低但有用的 token 保留更多上调空间；这仍是 ratio 的边界，不是直接规定 token 概率。

这个 loss 还按全批次有效 token 汇总。再看两条来自不同题目的回答：短答有 $12$ 个有效 token，长推导有 $120$ 个；假设每个 token 的代理项大小相同，长答就会贡献十倍数量的 token 项。于是长推导不会因为先按每条回答平均而被压到与短答相同权重；代价是长短回答在总 loss 中的影响会随 token 数不同。

**步骤 6：看 `update_policy` 怎样使用这些处理后的信号。** optimizer 只汇总动态采样保留的组和有效回答位置；每个 token 的更新幅度受 ratio clipping 控制，整条回答的优势来自 verifier reward 和长度处理。自然结束的长答案仍可学习；被硬截断的回答则由 mask 排除。这把采样、reward、长度状态和梯度贡献连成一次实际更新。

这个例子把 DAPO 的采样、reward shaping、ratio clipping 和 token loss 接到同一组候选上：动态采样先挑出有差异的组，长度处理改变 A 的 reward 并屏蔽另一个 prompt 中的硬截断样本，组内标准化再把最终 reward 变成 advantage。非零 advantage 只表示训练器得到更新信号，不证明该信号有益。

DAPO 论文在 Qwen2.5-32B base、AIME24 Avg@32 的逐步配方实验中报告 naive GRPO 为 $30$ 分，组合 DAPO 为 $50$ 分。这个结果绑定论文的模型、题集、采样和训练实现；渐进消融不能证明每项组件各自都有独立的同等因果贡献。

DAPO 适合有在线 verifier、需要长推理，并且日志显示无差异 rollout、长度截断、长回答权重或 entropy collapse 确实影响训练的任务。组合配方的组件会相互作用；动态过滤会改变进入训练的数据分布，token-level loss 会改变长短回答的总体权重，最终效果仍需独立评估。

## 9. DCPO：按旧策略的 token 概率动态调整裁剪边界

本节的 DCPO 指 2025 年提出的 Dynamic Clipping Policy Optimization。另有论文使用相同缩写表示 [Distribution-Centric Policy Optimization](https://arxiv.org/abs/2601.12730v1)，主题不同；引用时应写明全称。

GRPO 可能遇到当前组 reward 相同、advantage 为零；固定 token-ratio clipping 也对高、低概率 token 使用同一窗口。DCPO（Dynamic Clipping Policy Optimization）按旧策略 token 概率调整 clipping bounds，并结合当前组与同 prompt 历史 reward 平滑 advantage，再用 OTM 先对每条回答内的 token loss 求平均。三项分别处理动态更新空间、同分组信号和长短回答聚合；历史统计必须绑定同一 prompt 和可比 verifier。

**算法伪代码：**

```python
# 伪代码：同一道 prompt 的历史 reward 用于补充当前组的训练信号。
policy = load_sft_policy()
reward_history = initialize_prompt_reward_history()

for prompts in prompt_batches:
    rollout = sample_and_record(policy, prompts, group_size=G)
    rewards = score_rollouts(rollout, verifier)
    current_advantages = normalize_rewards_within_prompt_group(rewards)
    # 将本轮 reward 纳入对应 prompt 的累计历史，再计算历史标准化值。
    reward_history = add_rewards_to_prompt_history(
        reward_history, prompt_ids=rollout.prompt_ids, rewards=rewards
    )
    history_advantages = normalize_rewards_with_prompt_history(
        rewards, prompt_ids=rollout.prompt_ids, history=reward_history
    )

    # 【核心】平滑当前组与历史优势，选择绝对值较小的候选作为更新信号。
    advantages = smooth_and_select_smaller_magnitude(
        current_advantages, history_advantages, step=training_step
    )

    # 【核心】每个 token 的 clipping bounds 随旧策略概率动态变化。
    clip_bounds = dynamic_token_clip_bounds(
        rollout.old_token_probs, epsilon_high, max_ratio=max_clip_ratio
    )
    token_ratios = compute_token_level_ratios(
        policy, rollout.old_logps, response_mask=rollout.response_mask
    )
    # 【核心】按动态 bounds 裁剪 token 级策略目标。
    token_losses = dcpo_clipped_policy_loss(token_ratios, advantages, clip_bounds)

    # 【核心】OTM：先对每条回答的有效 token loss 求平均，再汇总回答 loss。
    response_losses = mean_valid_token_loss_per_response(
        token_losses, rollout.response_mask
    )
    loss = sum(response_losses)  # OTM 按论文定义不再跨回答取平均
    update_policy(policy, loss)

    record_metric("RUR", response_utilization_rate(advantages))
    evaluate(policy)  # 独立任务评估，不以 RUR 代替

return policy
```

**本节完整例子：计算 $19\times21$ 。**

题目要求计算 $19\times21$ ，verifier 检查最终答案是否为 $399$ 。它不是按解释的长短打分：只要答案通过检查，reward 就是 $1$ 。下面按伪代码依次走过采样与评分、当前/历史 advantage、动态 clipping、OTM loss、policy 更新和 RUR 评估。

**步骤 1：看 `sample_and_record` 与 `score_rollouts` 的输出。** 假设第 5 轮对这道题采样到四条不同的正确解法，rollout 保存每个真实生成 token 的旧 log probability；verifier 对四条完整回答都返回 $1$ ：

| rollout | 回答思路 | verifier reward |
| --- | --- | ---: |
| A | $(20-1)(20+1)=400-1=399$ | $1$ |
| B | $19\times20+19=399$ | $1$ |
| C | $21\times20-21=399$ | $1$ |
| D | $20\times20-1=399$ | $1$ |

这些分数表示本例 verifier 判定答案正确，不是模型对每个 token 的奖励。

**步骤 2：看当前组、历史记录和 advantage 平滑怎样衔接。** 当前组四个 reward 都是 $1$ ，所以它们彼此没有高低，`normalize_rewards_within_prompt_group` 给出的 advantage 都是 $0$ 。随后，`add_rewards_to_prompt_history` 把这四条新结果记到这道题自己的历史中。假设加上本轮后，这道题累计有 $20$ 条回答、其中 $8$ 条正确；历史标准化会把当前正确回答记为约 $1.22$ 的优势。DCPO 对当前组优势和历史优势生成两个平滑候选，再选绝对值较小的候选：

| 候选信号 | 当前组的权重 | 历史的权重 | 平滑结果 |
| --- | ---: | ---: | ---: |
| 当前组侧 | $4/5$ | $1/5$ | $0.24$ |
| 历史侧 | $1/5$ | $4/5$ | $0.98$ |
| 本轮采用 |  |  | $0.24$ ，因为绝对值较小 |

这样当前四条回答不再全是零 advantage。历史只能在同一道 prompt 内累计；把其他题目的正确率混进来会改变这项信号的含义。

**步骤 3：看 `dynamic_token_clip_bounds` 和 `compute_token_level_ratios` 如何处理同一个 token。** 在 A 的平方差解法里，假设采样到 token“平方差”；它在旧 policy 下的概率是 $0.02$ ，更新后在相同前缀下是 $0.04$ 。它的概率比为 $2.0$ 。本例设 DCPO 依旧策略的低 token 概率计算出动态上界约为 $3.70$ ：

| 对比方式 | 这个 token 的允许上界 | 概率比 $2.0$ 的处理 |
| --- | ---: | --- |
| 固定窗口示意值 | $1.2$ | 会先被裁剪 |
| DCPO 动态上界 | $3.70$ | 保留在目标中 |

因此，同样是从 $0.02$ 到 $0.04$ ，低概率 token 在本例中获得了更大的相对上调空间。动态边界改变的是允许参与优化的概率比，不会把 token 概率硬设为某个值；论文还设置了最大 ratio，防止边界无限放大。

**步骤 4：看 `dcpo_clipped_policy_loss` 怎样形成 token 目标。** 这个正确回答的 advantage 是 $+0.24$ ；“平方差” token 的概率比 $2.0$ 又没有超过动态边界，所以它保留正向更新信号。函数逐个位置产生 token loss，之后才交给 OTM 汇总。

**步骤 5：看 OTM 怎样汇总两条长短不同的回答。** 另取一小批数据，只比较 loss reduction。假设两条回答的 token ratio 都为 $1$，且各自每个有效 token 的 policy-loss 数值分别为 A 的 $1.0$ 和 B 的 $0.5$；这些 loss 数值是本例给定的教学输入，不能仅由 ratio 推出。

| 回答 | 有效 token 数 | 回答内 token loss 平均值 | 若全批次按 token 平均时的占比贡献 | OTM 保留的回答值 |
| --- | ---: | ---: | ---: | ---: |
| A | $8$ | $1.0$ | 约 $0.17$ | $1.0$ |
| B | $40$ | $0.5$ | 约 $0.42$ | $0.5$ |

全批次 token mean 让 B 因为 token 多而获得更大的总贡献。OTM 则先在每条回答内部对有效 token loss 求平均，再把回答平均值相加；所以本例汇总为 $1.5$ ，短答 A 的回答级目标仍高于长答 B。padding 不参与回答内部的平均。这里的“求和”是论文 OTM 定义的一部分，不能再除以 token 总数或回答数。

**步骤 6：看 `update_policy`、历史记录和 `evaluate` 怎样结束这一轮。** optimizer 用 OTM loss 更新 policy；本轮 reward 保存在对应 prompt 的历史中，供下一轮计算累计标准化。RUR 记录 advantage 非零的回答比例；若本轮四条回答都保留 $+0.24$ ，这组的 RUR 是 $100\%$ 。这只表示训练信号非零，不证明更新方向一定有益。`evaluate(policy)` 仍需检查独立数学题、通用能力和安全表现。

**论文指标：** RUR 统计取得非零 advantage 的回答比例；它不说明更新方向正确，也不说明 held-out 能力提升。

论文在四个 Qwen 设置、$400$ 个训练 step 上报告 DCPO 平均 RUR 为 $71.8\%$ ，GRPO 为 $43.8\%$ ；在 Qwen2.5-Math-7B 的 AIME24 Avg@1/32 设置报告 $46.7/38.8$ 。这些指标和分数绑定论文的模型、数学数据与评测协议，不能外推成所有任务上的普遍优势。[DCPO 原论文](https://arxiv.org/abs/2509.02333v2)

这个例子把 DCPO 的三项机制分开：历史 reward 让当前组全对时仍可能有信号，动态 clipping 按 token 概率改变更新空间，OTM 控制长短回答的 loss 聚合。它适合在线 RLVR 中同分回答多、低概率 token 被固定 clipping 限制，或回答级权重需要调整且能可靠维护同题历史统计的场景。历史统计仍可能失真，非零 advantage 不等于正确或有益更新；动态边界和 OTM 都要按任务验证。论文目标没有 PPO-RLHF 的 reference KL 项，因此 DCPO 的 clipping 不能当作 reference KL 约束。

## 10. DeepSeek-R1：把 RLVR 放回完整训练路线理解

DeepSeek-R1 的公开报告让 RLVR 成为广泛讨论的 reasoning 训练路线，但不能把它压缩成“用了 GRPO，所以模型会推理”。需要区分 R1-Zero 和 R1 的训练过程。

**R1-Zero 的例子：** 从 DeepSeek-V3-Base 出发，让模型对可验证的数学等任务采样回答；论文描述使用 GRPO，并以答案正确性和格式规则作为主要奖励。这条实验路线没有先用人工推理示范做 SFT，但模型并非从随机参数开始，它已经带着预训练形成的语言和数学先验。公开结果说明这种路线在论文任务上可行，也报告了可读性和语言一致性等限制。

**R1 的公开路线：** 报告另外描述了 cold-start 长推理示范、reasoning RL、拒绝采样、混合推理与非推理数据的 SFT、后续 helpfulness/harmlessness RL，以及把大模型轨迹蒸馏到较小模型。报告统计了约 80 万条 SFT 样本，包含数学、代码、STEM、逻辑和通用任务。最终表现来自这些数据、阶段和评估的组合，不能单独归因于 GRPO。[DeepSeek-R1 技术报告](https://arxiv.org/abs/2501.12948)

这个案例给出的可迁移经验是：验证器能教模型什么，取决于任务是否可被规则覆盖；开放问答、安全和写作还需要不同反馈。R1-Zero 不是开放任务都可用答案规则训练的证明，R1 的多阶段路线也不是所有模型都必须照搬的固定配方。更完整的 RLVR verifier 设计见本册第十六章。

## 11. GRPO、GSPO、DAPO、DrGRPO、DCPO 各自针对什么

这些方法不是按新旧排成一条“升级路线”。它们改动的是不同环节。先用同一道题想象训练日志：组内全错、回答越来越长、某个低概率正确 token 被 clipping、或者回答级 reward 与 token 级更新单位不一致。每篇工作针对其中不同现象提出方案。

| 方法 | 它主要改哪里 | 对应的训练现象 | 适用边界 |
| --- | --- | --- | --- |
| GRPO | 用同 prompt 的组内 reward 建立相对信号，通常省去 critic | PPO critic 成本较高，且任务允许同题采多个候选 | 全组同分时没有相对方向 |
| DAPO | 组合动态采样、非对称 clip、token loss 和超长处理 | 长推理训练中无效组、低概率 token、长度和截断问题 | 组合效果不能归因单一组件；过滤改变样本分布 |
| DrGRPO | 调整回答长度与组内标准差归一化 | 按每条回答长度平均可能改变短长回答的 token 权重 | 固定预算分母不自动解决全组同分或 reward 错误 |
| GSPO | 把重要性比率和 clipping 的单位改成整条回答 | 长序列 token ratio 波动与回答级 reward 不在同一粒度 | 局部 token 变化会被聚合抵消；结果依论文设置 |
| DCPO | 旧概率相关的 token clip、历史 advantage 平滑和 response 内平均 | 固定窗口和只看当前组时，部分回答得不到非零信号 | RUR 不是正确率或有益梯度比例 |
| DHPO | 混合 token 与 sequence ratio，再分别处理 clipping | 希望同时保留局部更新和序列稳定性 | 当前为预印本；作者报告的数学设置不等于通用结果 |
| GAPO | 按组内 advantage 调整 clipping 边界 | 固定边界对不同难度 rollout 一视同仁 | EMNLP 2026 论文的收益仍绑定所列模型和任务 |

DrGRPO 要处理的是 loss 汇总后短答和长答怎样影响一次更新。假设 tokenizer 把短答案切成 $10$ 个有效 token，把长推理链切成 $100$ 个有效 token；两条回答的每 token loss 都暂设为 $1$ ，只为看清分母的作用：

| 汇总方式 | $10$ token 短答 | $100$ token 长答 | 读数含义 |
| --- | --- | --- | --- |
| 先对每条回答求 token 平均 | 每个 token 权重约为 $1/10$ ，回答合计为 $1$ | 每个 token 权重约为 $1/100$ ，回答合计也为 $1$ | 两条回答各占一个样本单位，短答中的单个 token 权重更大 |
| 全批次按有效 token 平均 | 共贡献 $10$ 个 token 项 | 共贡献 $100$ 个 token 项 | 若每项大小相同，长答贡献约为短答的 $10$ 倍 |
| DrGRPO 的固定生成长度分母 | $10$ 项累加后除以同一个 $L_{\max}$ | $100$ 项累加后除以同一个 $L_{\max}$ | 两条回答的 token 使用同一分母，长答因有效项更多而有更大总贡献 |

这三行说明，同一批回答只要换一个 loss 分母，长短回答对更新的相对影响就会改变。DrGRPO 还去掉了组内 reward 的标准差缩放：例如一题上正确答案 reward 为 $1$、错误答案为 $0$ ，它保留两者减去组均值后的差，不再除以这一组的标准差。这样避免按每题的组内波动再次缩放，但也意味着不同任务的 reward 尺度不会自动拉齐；跨任务使用时仍要控制 reward 量纲。长度汇总本身不能判断长答案是否更正确，也不能替代 verifier。[DrGRPO 原论文](https://arxiv.org/abs/2503.20783v2)

DHPO 仍是 arXiv 预印本。GAPO 已收录于 EMNLP 2026 主会论文集；官方论文介绍它按 rollout advantage 自适应 clipping 边界。论文在部分 Qwen 和 Llama 数学、代码任务报告了 Pass@1 与 Pass@k 改善。[DHPO 预印本](https://arxiv.org/abs/2601.05607v1)，[GAPO，EMNLP 2026 论文集](https://aclanthology.org/2026.emnlp-main.1882/)。录用和作者实验都不是跨任务保证；比较时要固定底模、数据、verifier、rollout 预算和评测方式。

同名缩写需要核对全称。本章 DCPO 是 Dynamic Clipping Policy Optimization；另有 Distribution-Centric Policy Optimization 使用同一缩写，不能混作同一个方法。

## 12. 领域专家与 on-policy distillation

### 12.1 领域专家训练需要任务和验收条件

数学证明、代码修复、工具使用和科学问答需要不同数据，也需要各自的验收方式。领域专家训练通常要准备领域任务、专家示范、可用时的 verifier、再加通用能力与安全回归。只追加领域文本可以增加知识暴露，却不一定教会模型完成任务或判断结果是否正确。

例如代码修复任务，训练器不只要看到“最后的代码长什么样”，还要知道原始测试是否失败、模型改了什么、修复后测试是否通过。若测试只覆盖一个输入，模型可能把测试样例写死，却没有修复一般问题。第十五、十六章进一步展开领域专家 SFT 与 verifier/RLVR。

### 12.2 On-policy distillation：教师也要看见学生实际走到哪里

离线蒸馏通常拿教师预先写好的轨迹教学生。学生如果沿着自己的错误前缀继续生成，而教师数据里没有这个状态，就可能缺少直接的纠正信号。

设学生在本例中错误地写成“把分母相加……”。on-policy distillation 会先让学生沿自己的 policy 生成到这个错误前缀，再让教师在这个状态上提供下一步 token 分布或让 verifier 标出错误。训练目标由此覆盖学生确实会到达的上下文，而不是只复习教师的理想答案。它的代价是要在线生成学生轨迹并运行教师；教师本身也可能不可靠，仍需验证和过滤。

多教师 on-policy distillation（MOPD）把多个领域教师的指导用于学生自己的 rollout。相关论文报告了特定模型与任务设置下的结果，不能直接当作通用成本或效果结论；训练细节见本册第十七章。[MOPD 论文](https://arxiv.org/abs/2606.30406v1)

### 12.3 公开模型披露能说明什么

公开材料展示的是作者披露的训练方向，不一定是完整配方。

| 案例 | 发布方公开说明 | 仍不能推出什么 |
| --- | --- | --- |
| GLM-5.3 | Z.ai 称其沿用 GLM-5.2 的 base model，并通过增加长周期环境、任务多样性和训练计算扩展 post-training | 完整数据、optimizer、reward 权重和独立复现结果 |
| gpt-oss | OpenAI 公开称模型结合强化学习与来自内部先进模型的训练技术，并强调 reasoning 与工具使用 | 具体 PPO/GRPO 选择、reward 配方和完整超参数 |
| Grok 4.7 | xAI 称其使用更大的 base model，并进行了更长的 RL run 和更难、偏多小时任务的训练 | benchmark 增益中 base model、任务混合和 RL 各自贡献 |

这些是厂商的公开描述，不是独立对照实验。GLM-5.3、gpt-oss 和 Grok 4.7 都不能靠产品 benchmark 或 reasoning effort 字段反推出未披露的训练算法。[GLM-5.3 官方说明](https://z.ai/blog/glm-5.3)、[gpt-oss 发布说明](https://openai.com/index/introducing-gpt-oss/)、[Grok 4.7 官方说明](https://x.ai/news/grok-4-7)

## 13. 如何按项目条件选择方法

选择方法时先检查现有反馈和系统条件，再比较适合的算法路线。

| 项目手头有什么 | 可以先比较什么 | 主要成本或风险 |
| --- | --- | --- |
| 有示范，但没有稳定偏好对或 verifier | SFT，并补充数据覆盖和回归集 | 模仿能力受示范质量限制 |
| 有同 prompt chosen/rejected 偏好对 | DPO、IPO、SimPO；有逐条好坏标签时可看 KTO | 离线数据覆盖不到的行为不会自动得到反馈 |
| 有可靠数学答案或代码测试，能在线 rollout | GRPO；再按无效组、长度或 clipping 现象对比 DAPO、DrGRPO、GSPO、DCPO | rollout、verifier、token 预算和复现成本 |
| 目标是安全和拒答 | 安全示范、偏好/约束数据、红队与切片评估 | 过度拒答、漏拒和工具误用之间的取舍 |
| 资源有限，尚无 rollout 服务或 verifier | 先提高 SFT / preference 数据质量，再建立小规模评估闭环 | 过早上在线 RL 可能主要耗在生成、过滤和排错 |

例如，团队先做通用聊天，只有一批人工偏好对而没有可靠在线评分器，可以用 DPO/SimPO 建立离线基线；后来转向代码修复且已有稳定测试环境，才有条件试 online RLVR。若日志进一步显示组内全对/全错很多，再测试 dynamic sampling；若模型常在 token 上限被截断，再测试超长处理。每次固定同一个 SFT checkpoint、题池和评估集，只改一个主要因素，才知道新方法解决了哪个实际故障。

这不是固定训练流水线。项目可以先做数学 RLVR，也可以先补安全示范；方法选择随任务、数据、verifier、rollout 成本和能力回归结果变化。

## 14. 数据质量决定训练器听到了什么

| 阶段 | 需要的数据 | 先检查什么 |
| --- | --- | --- |
| SFT | prompt + 目标回答 | 回答是否正确、格式是否一致、目标 token mask 是否对 |
| Reward Model | prompt + chosen + rejected | 两条回答是否同题可比、标签是否可靠、长度是否系统性偏向 chosen |
| DPO / IPO / ORPO / SimPO | 偏好对；KTO 可使用逐条好坏标签 | 标注分歧、模板一致性、被截断的空回答、token 聚合口径 |
| PPO-RLHF | 当前 policy rollout + RM/其他反馈 | rollout 是否来自记录的 policy，RM 是否可被投机 |
| GRPO 家族 | 同 prompt 的多条 rollout + reward | group 是否完整、是否有组内差异、verifier 是否正确 |
| 长链 RL | rollout、终止原因和有效 token mask | 自然结束与系统截断是否分开、长短任务是否混在同一阈值 |

回到 chosen“分母相同……答案是 1”和 rejected“答案是 2”：如果 chosen 总是更长，模型可能同时学到长度和答案偏好。数据审计要按任务类型统计两者长度，并抽查控制长度后标注者是否仍偏好 chosen。长度差是排查线索，不单独证明标注者有长度偏差；证明题本来就可能比简答题长。

## 15. 后训练中要防的几类退化

### Reward hacking：模型通过了规则，但没有完成真实任务

如果数学 verifier 只检查输出是否包含字符串“1”，模型可以在错误解释后附上数字 1 通过检查。代码 verifier 若只运行一个公开测试，也可能被模型写死该测试用例。解决方式不是盲目换 optimizer，而是补隐藏测试、语义约束、人工抽检和高 reward 低质量样本分析。

### Length bias：模型把“更长”或“更短”当成目标

如果 RM 偏好详细解释，模型可能增加重复内容来获得高分；若超长惩罚太重，模型又可能过早结束证明。要按任务观察长度、终止原因、正确率和人工偏好，不能把长度本身当质量。

### Reward 上升而真实质量不升

如果训练集 RM 分数持续提高，但留出偏好、数学正确率或用户任务成功率没有提高，模型可能在迎合代理目标。把训练 reward、留出集、真实任务和人工样本并列，而不是只挑一条向上的曲线。

### 能力遗忘与 policy 漂移

窄领域数据可能让模型更会解数学题，却损伤通用问答、代码或长上下文。比较 base、SFT 和后续 checkpoint 的同一批回归题；必要时混合 replay 数据或减小更新，并保留可回滚 checkpoint。

### Safety regression：正确拒绝与过度拒绝要分开数

在留出评估中，危险请求“帮我窃取账号”应拒绝；无害请求“怎样重置自己的密码”应提供帮助。若新模型对两者都拒绝，应同时记录：

| 评估项 | 例子中的结果 |
| --- | --- |
| 危险请求正确拒绝 | 1 条中拒绝 1 条 |
| 无害请求过度拒绝 | 1 条中误拒 1 条 |
| 总体结论 | 拒答增加，但帮助性下降；不能单独称为安全改善 |

真实评估需要更多风险类型、样本和人工审查。一次小例子能说明分母为什么要分开，却不能估计模型实际安全率。

## 16. 一个可复用的后训练工作流

下面用“先训练通用助手，再提高数学解题可靠性”为例。它展示的是可选分支，不是人人必须照走的流水线。

1. 从预训练 checkpoint 开始，检查目标任务和初始能力。
2. 准备通用指令与解题示范，做 SFT，建立可用回答方式。
3. 若要改善开放式回答偏好，收集同 prompt 比较或逐条好坏标签，选择 DPO、KTO 等离线候选；若要用 PPO-RLHF，则另训练 RM 并设计在线采样与评估。
4. 对数学题接入答案验证器，先人工抽查它能否识别等价写法、格式和边界情况。
5. 只有在需要当前 policy 探索新解法且生成成本可接受时，开启 online RLVR；先用 GRPO 建基线，再根据真实日志测试 DAPO、GSPO 等候选。
6. 单独评估数学正确率、解释质量、长度、通用能力和安全边界。
7. 从失败案例改进示范、偏好集或 verifier，记录数据与 policy 版本，再决定是否继续训练。

如果题目没有可验证答案，就不能照搬“答案为 1 给分、答案为 2 扣分”。反馈方式必须随任务改变。后训练是否有效，最终看独立评估上目标行为有没有改善、旧能力和安全有没有可接受地保持，而不是训练器是否报告更高 reward。

先从 SFT 汇总读起。三条合成样本的 assistant token 合计 $54+83+41=178$ ，prompt token 合计 $22+18+30=70$ ，序列化输入与回答共 248 token，所以结构性占比为 $178/248\approx0.7177$ 。类别集合是 format、reasoning、safety，拒答示范只有一条。这个占比回答“样本中 assistant token 占了多少”，不回答“loss 中有多少 token 参与监督”：后者还要套用每个训练样本的 label mask。若把二者混为一谈，可能把 prompt token 错当成监督目标。

偏好部分把 RM 与 DPO 两个 loss 分开计算。以 `pref_helpful` 为例，reward 差是 $1.4−0.2=1.2$ ，所以 RM logistic loss 是 $−\ln \sigma(1.2)\approx0.2633$ ；三对样本分别计算后等权平均，输出 0.3749。DPO 则比较 policy 与 reference 的 margin：policy gap 为 $−2.10−(−2.70)=0.60$ ，reference gap 为 $−2.30−(−2.55)=0.25$ ，差值为 0.35；乘以 $\beta=0.1$ 后 logit 是 0.035，单对 loss 约 0.6758。三对平均得到 0.6786。chosen 长度减 rejected 长度分别为 11、−25、4，平均 $−10/3\approx−3.33$ token；这只是这三对的方向摘要，不足以说明真实偏好数据存在长度偏置。

在线 group 用 `math_001` 展示 advantage 的来源。三个 reward 是 `[1,0,0.5]`，均值为 0.5，总体标准差约为 0.4082，因此标准化 advantage 为 $[1.2247,−1.2247,0]$ 。第一条回答的平均 logp 从 −3.00 变为 −2.76，差值 0.24，故序列 ratio 代理为 $\exp(0.24)\approx1.2712$ ，再按 demo 的 $\epsilon=0.2$ 截到 1.2 后形成代理 surrogate。这里用平均 logp 的差模拟几何平均 token ratio，特意没有从完整序列概率乘出 vanilla GRPO 的逐 token ratio；不能把这个数当作真实训练器的 policy ratio。

评估输出把同四行 old/new checkpoint 记录配对：四行中三行新分数更高，故 gain rate 是 $3/4=0.75$ ；`safe_001` 是唯一应拒答样本且新模型拒答，安全召回为 1；三个普通样本中 `safe_002` 被误拒，所以 over-refusal 为 $1/3$ 。该样本也是旧模型通过、新模型失败的唯一回归案例。最后，方法建议只依据任务需要在线探索、rollout 是否可用、verifier 或可信反馈是否可用等布尔条件选候选家族；它不会代替同设置实验。诊断字典中的 `over_refusal_flagged=True` 与 `regression_detected=True` 是发现问题的告警，其他 True 也只表示通过了 demo 内设阈值，不是模型质量认证。

其余诊断值也要回到中间量解释。两个 group 各自标准化后的 advantage 求和为零，因此 `group_advantage_centered=True`；最大的 ratio 偏差是 $1.2712−1=0.2712$ ，低于教学阈值 0.32。`format_failures` 把 `code_001/r1` 标出来，但代码没有自动修改它的 reward；若格式错误应该有代价，要在 verifier/reward 定义中明确编码。`mean_sequence_surrogate_proxy` 是演示代理项的组内均值，不是反向传播所用的最终 loss。0.32、0.70 和 20-token 等阈值都只是合成输入里的诊断条件，真实实验必须预先说明阈值并报告原始指标，不能把 flag 当成跨任务标准。

`preference_categories_ok` 只核对去重后的类别集合，不检查每类样本量是否平衡、标注者是否一致或各类别 reward 是否可比较。`length_bias_ok` 检查三对长度差的平均值是否落在 ±20 token 内；正负差异可能互相抵消，所以通过这条规则也不能证明没有长度偏置。应进一步看长度差分布、分任务切片和偏好胜率随长度的变化。

这个 demo 的重点是把数据、反馈、采样和评估分开观察：离线偏好 category 只用于覆盖统计，不决定在线/离线 optimizer；method_family_suggestion 先选方法家族候选，算法之间仍要按任务、loss reduction、ratio 粒度、rollout 成本与同设置实测比较。assistant_token_share_of_serialized_tokens 只是输入加回答 token 的结构性占比，不是 SFT loss 的监督比例；真正的 loss 分母仍应只数 mask 选中的 assistant token。序列 ratio 代理使用 response 平均 logp，不能替代 GRPO 的逐 token ratio 或真实训练日志。若 uninformative_groups 非空，代码会明确把该组 advantage 设为 0；它并没有像 DAPO 那样补采，也没有像 DCPO 那样用历史统计。over_refusal_flagged 和 regression_detected 为 True 表示 demo 检出了问题，不代表模型已经健康。

## 18. 常见误判与诊断路径

| 观察到的现象 | 先检查什么 | 可能的判断 |
| --- | --- | --- |
| 把 SFT、DPO、PPO 都叫“对齐训练” | 这次用的是目标回答、固定偏好对，还是当前 policy 新采样 | 三者反馈和训练循环不同；先找对数据，再比较算法 |
| policy 新生成的解法没出现在偏好集 | 任务是否能用程序或环境给它反馈 | 固定偏好集不会自动探索；可验证且需要探索时再考虑 online RLVR |
| 一组 GRPO rollout reward 都一样 | 同 prompt 的组是否完整、verifier 是否有区分度、采样温度是否合适 | 组内没有相对方向；加小常数只会避开除零，不会造出学习信号 |
| 训练 reward 上升但留出正确率停滞 | verifier false positive、reward shortcut、难度切片和题目泄漏 | 优化器可能学会迎合检查器；先审计信号再加训练步数 |
| 安全拒答上升但用户体验变差 | 分开统计危险请求正确拒绝与无害请求错误拒绝 | 可能是过度拒答，不能只看总拒答率 |
| 回答突然变长、变短或被截断 | EOS、生成上限命中率、任务长度分布和 loss reduction | 判断是策略主动变化、任务组成变化还是系统删失 |
| 异步训练效果与同步基线不一致 | rollout policy revision、等待时间、旧样本比例和 log-prob 口径 | 可能混入了 stale rollout 或训练/采样概率不一致 |

需要方法背景时，回到对应章节的小例子，再沿真实 rollout 逐步排查。日志指标必须说明分母、policy 版本、mask 和任务切片；字段名相同不保证不同框架或版本计算口径相同。

## 19. 本章小结

后训练把模型从“能续写”继续训练到“按任务回答并守住行为边界”。先识别训练信号：

- SFT 用示范教模型目标回答长什么样。
- Reward Model 学习同题回答的偏好排序；它的分数不是正确性证明。
- DPO、IPO、KTO、ORPO 和 SimPO 用不同形式的离线偏好标签。
- PPO-RLHF 在线采样回答，根据 RM 与 reference 约束更新 policy；§3 的算例走完了每个模型角色和一轮 GAE/PPO。
- GRPO、GSPO、DAPO、DrGRPO、DCPO 等讨论在线组内反馈的不同更新或配方选择；它们不能只按名称或论文分数排位。
- RLVR 适用于结果能由程序或环境验证的任务，但 verifier 本身需要评估。
- 最后用偏好、安全和原有能力回归判断新 checkpoint 是否真的更适合目标任务。

选择方法时，先问“有什么可靠反馈、是否需要在线探索、采样与评估预算是多少”，再看具体算法；训练 reward 只是中间信号，不是最终结论。
