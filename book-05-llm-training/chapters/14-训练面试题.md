# 第十四章：训练面试题：把知识组织成可验证的工程回答

训练面试题表面上在问一个公式或一个组件，实际是在观察候选人能否把目标、数据、模型、优化、系统、评估、风险和成本串成因果链。回答“我会用 Transformer、AdamW 和分布式训练”只是在报工具名；更有价值的回答要说明为什么选择它、它解决了哪个约束、引入了什么代价，以及怎样用实验判断选择是否有效。

本章覆盖十几个高频问题，但它们不是互相孤立的标准答案。7B 训练设计会用到第五册前面讲过的数据、架构、显存和成本；loss spike 会回到数据 batch、数值精度和 checkpoint；SFT 退化会回到 label mask、数据配比和回归评估；VLM 题则会回到上一章的模态 token 和证据对齐。面试时能主动指出这些依赖，通常比堆更多术语更能体现工程判断。

本章中的数字、公式和 demo 都是量级推理或自评工具。不同模型结构、tokenizer、序列长度、硬件、并行策略和训练框架会改变真实结果；论文中的公开实验也不能直接当成生产 recipe。回答时应把公开事实、个人假设和需要现场测量的数字分开。

## 高频问题地图

本章的问题可以分成四组：训练设计（7B 方案、batch/lr、VLM）、故障与评估（loss spike、loss 与能力、污染、SFT 退化）、系统资源（ZeRO/FSDP/TP、显存、成本），以及模型阶段与算法比较（Base/Instruct/Chat、DPO/PPO）。先识别问题属于哪组，再决定回答从目标、数据、公式还是故障证据开始。

## 训练问题的回答结构

训练类面试题最容易暴露“知道名词但不会做系统判断”的问题。一个稳定的回答可以分成四层：先说明目标和约束，再说明机制和关键公式，接着给出工程实现与观测指标，最后说明失败模式、替代方案和成本。并不是每道题都要把四层讲满，而是要先回答面试官正在追问的那一层。

例如面试官问：

```text
如果让你训练一个 7B 模型，你会怎么做？
```

低质量回答是：

```text
我会用 Transformer、AdamW、数据清洗、分布式训练。
```

更好的回答应该有结构：

```text
目标 -> 数据 -> tokenizer -> 架构 -> 训练目标 -> 优化器 -> 分布式 -> 监控 -> 评估 -> 风险 -> 成本
```

这个结构的价值在于把训练当成一个系统：数据决定输入分布，架构决定计算和显存，优化器决定参数如何更新，分布式策略决定通信，评估决定结论是否可信，成本决定方案能否持续。任何一个环节缺失，都可能让一个看似正确的局部答案在真实项目中失效。

回答中最好至少能写出三个量级公式：

```math
C_{\mathrm{train}}\approx 6ND
```

```math
B_{\mathrm{global}}=B_{\mathrm{micro}}\cdot A\cdot W
```

```math
S_{\mathrm{AdamW}}\approx N(b_w+b_g+2b_m+b_{\mathrm{master}})
```

其中 `N` 是模型参数量，`D` 是训练 token 数，`B_micro` 是单卡 micro-batch，`A` 是 gradient accumulation steps，`W` 是 data parallel world size。这里的 global batch 是样本数口径；若样本长度不同，还要换成有效 token batch。最后一个式子用于提醒：训练显存和 checkpoint 不能只看权重，还要看梯度、Adam 一阶/二阶矩和 master weights；激活、通信 buffer 和框架临时空间还要另加。

一个回答中的公式不必多，但每个公式都要能落到变量和决策上。比如 `6ND` 用来判断训练量级，global batch 用来解释优化器和吞吐，Adam 状态公式用来解释显存与恢复 checkpoint。只写公式而不说明假设，和只背术语一样不完整。

## 1. 如果让你训练一个 7B 模型，你会怎么设计？

### 回答框架

1. 先明确目标：通用、代码、数学、领域还是 chat。
2. 定义数据规模和数据配比。
3. 选择 tokenizer 和模型架构。
4. 设计预训练目标和训练配置。
5. 选择分布式策略。
6. 建立监控、checkpoint 和评估。
7. 规划后训练和成本。

### 标准回答

一个完整回答可以这样展开：先明确 7B 模型究竟要服务通用续写、代码、数学、领域知识还是 chat。这个目标会影响数据配比、tokenizer、上下文长度、是否需要继续预训练，以及最后采用什么评估集。若目标没有说清楚，“7B”只是规模标签，不足以决定 recipe。

数据阶段要说明来源和处理，而不是只说“收集高质量数据”：网页、书籍、代码、数学、多语言和领域数据分别去重、质量过滤、授权审计，并检查 benchmark contamination；之后按目标能力建立 mixture，同时保留 per-domain 统计，避免大体量网页数据把小但关键的领域数据淹没。数据工程的成功标准不是文件数量，而是有效 token、覆盖范围、污染风险和可复现版本。

模型阶段可以以 decoder-only Transformer 作为基线，再确定层数、hidden size、head 数、FFN size、RoPE、RMSNorm、SwiGLU、GQA 和上下文长度。每个选择都要关联约束：GQA 影响 KV cache 和推理带宽，RoPE 影响位置泛化，FFN 和层数影响参数分配，长上下文影响 attention 计算和显存。参数量和 token 数还要与计算预算、数据质量一起解释，不能只追求更大的模型。

训练阶段先用 next-token prediction 和 AdamW 建立稳定基线，再说明 warmup、decay、gradient clipping、BF16/FP8 等数值策略。分布式方面，根据单卡显存、层大小、节点互联和目标吞吐选择 FSDP/ZeRO、Tensor Parallel 或 Pipeline Parallel，并用短程 benchmark 测扩展效率，而不是把 GPU 数线性相乘。

最后要给出观测和退出路径：train/validation/per-domain loss、grad norm、learning rate、有效 tokens/s、MFU、NaN/Inf、checkpoint 状态，以及代码、数学、多语言、安全和污染评估。通过的 checkpoint 再进入 SFT、偏好优化或安全对齐；如果 loss 正常但领域回归下降，应回到数据配比或 checkpoint 选择，而不是盲目增加训练步数。

可以把这个回答压缩成一张因果表：

| 决策 | 它解决的问题 | 必须观察的证据 | 典型反模式 |
| --- | --- | --- | --- |
| 数据 mixture | 能力覆盖和训练分布 | per-domain token、质量、污染、授权 | 只按网页量配比 |
| 架构与上下文 | 表达能力和资源约束 | 参数量、active FLOPs、序列成本 | 只报模型名 |
| 优化与精度 | 收敛和稳定性 | loss、grad norm、非有限值、更新量 | 只调学习率 |
| 并行与 batch | 显存、吞吐和扩展 | global valid tokens、通信占比、MFU | 单卡 benchmark 外推 |
| 评估与 checkpoint | 结论和恢复可信度 | 分层回归、manifest、恢复连续性 | 只看最低 validation loss |

### 常见追问

1. 你怎么定数据配比？应回答目标能力、数据质量、有效 token 和 per-domain 回归之间的关系。
2. 你怎么判断训练是否健康？应同时看 loss、梯度、数值、吞吐、数据和 checkpoint，而不是一个曲线。
3. 你怎么估算训练成本？应从 `6ND`、实测吞吐、扩展效率、存储和失败概率开始。
4. 如果训练中 loss spike 怎么办？应先定位异常 batch 和训练状态，再做单变量修复。

## 2. 训练 loss 突然 spike，你怎么排查？

### 回答框架

1. 定位第一次 spike 的 step。
2. 检查异常 batch。
3. 检查 grad norm 和 learning rate。
4. 检查 mixed precision。
5. 检查 checkpoint 恢复和分布式状态。
6. 做单变量修复。

### 标准回答

我不会一上来就调学习率，而是先定位第一次 spike 的 step，并保存该 step 的 batch、各 rank 的 loss、有效 label 数、grad norm、learning rate 和 scaler 状态。随后检查 input length、decoded text、特殊 token、label mask 和数据来源，判断是否有坏样本、截断错误或监督分母变化。若只有一个 rank 异常，优先查该 rank 的数据和通信；若所有 rank 同时异常，才更像全局学习率、数值或 checkpoint 状态问题。

如果 grad norm 与 loss 同时爆炸，要检查 peak lr、warmup、gradient clipping 是否在 unscale 之后生效，以及 optimizer state 是否出现非有限值。FP16 还要检查 overflow 和 loss scaling，BF16 通常有更宽的指数范围但并不自动解决错误 mask、过大的更新或数据 NaN。若 spike 发生在 checkpoint 恢复后，要逐项核对 optimizer、scheduler、scaler、random state、数据位置、gradient accumulation window 和分布式 shard 是否完整恢复。

修复时一次只改变一个因素，例如隔离异常 batch、降低 peak lr、延长 warmup、调整 clipping 或改用 BF16；每次都在固定回归 batch 上对比，并记录修复是否牺牲吞吐或改变数据分布。若 spike 后自行恢复，也不能直接忽略：它可能已经造成一次异常参数更新，后续 loss 虽恢复，某个 domain 或安全行为可能已经退化。

可以用下面的判别表组织追问：

| 观察组合 | 更可能的方向 | 先做什么 |
| --- | --- | --- |
| 单 rank loss/grad 异常 | batch、解码、局部数据或通信 | 保存 rank-local batch，检查样本和 collective |
| 所有 rank 同时异常，恰逢 lr 峰值 | 优化超参或 warmup | 对照 lr/grad 曲线，回放固定 batch |
| loss 变 NaN，grad norm 也非有限 | 数值溢出或非法输入 | 检查 forward、backward、unscale 和 optimizer state |
| 恢复后 loss 台阶式改变 | checkpoint 状态或数据游标不连续 | 比较恢复前后参数、optimizer、RNG 和 batch |
| 只有某 domain spike | 数据格式、分母或 domain 分布 | 按 domain 重算有效 token loss |

### 常见追问

1. 如果 spike 后自己恢复，要不要管？要查异常更新是否改变了回归集、domain 能力和安全行为。
2. 如何判断是数据问题还是优化器问题？用固定 batch、梯度/学习率对照和替换数据三组实验隔离变量。
3. 如果所有 rank 同时 NaN 怎么办？先停在最近 checkpoint，定位 forward/backward/update 阶段，再检查精度、scaler、学习率和共享输入。

## 3. 为什么训练 loss 降低不代表模型能力一定提升？

### 回答框架

1. train loss 只反映训练分布。
2. 可能存在重复、污染或过拟合。
3. 平均 loss 掩盖 domain 退化。
4. 下游能力和训练目标不完全一致。
5. 需要综合评估。

### 标准回答

训练 loss 只说明模型在当前训练分布上的 next-token prediction 更好，不代表真实能力一定提升。重复数据会让模型更容易记忆，benchmark contamination 会让评估分数虚高，整体平均 loss 还可能掩盖代码、数学、多语言或长上下文 domain 的退化。即使 validation loss 下降，token-level 目标也不一定等价于指令遵循、事实性、安全性、工具调用或推理能力。

因此我会把证据拆成三层：先看独立 validation 和 per-domain loss，再看固定版本的下游 benchmark 与人工抽样，最后看 regression、safety、污染风险和 bad case。评估集要与训练数据和 prompt 模板隔离，且 checkpoint 选择不能只按一个最低 loss 决定。若领域能力提升但通用能力下降，需要讨论数据 mixture、学习率、训练步数和 replay 数据的 trade-off。

可以把综合评估写成加权而不是单一分数：

```math
S_{\mathrm{eval}}
=\sum_{k\in\mathcal{K}}w_k S_k,
\qquad \sum_{k\in\mathcal{K}}w_k=1
```

`S_k` 是某个能力分层的得分，`w_k` 是业务或岗位设定的权重。真正的报告还要同时列出每个 `S_k`，因为一个总分可能通过增大容易任务的权重掩盖关键回归。面试追问“loss 降了为什么能力没升”时，最有力的回答不是说 loss 不重要，而是说明它测量的对象、数据分布和下游目标之间存在怎样的映射缺口。

## 4. 如何检测 benchmark contamination？

### 回答框架

1. 明确污染形式。
2. 做 exact match。
3. 做 near dedup。
4. 做 embedding 检索。
5. 对高风险样本人工抽检。

### 标准回答

Benchmark contamination 是评估集或其近似版本进入训练数据，使模型可能通过记忆而不是泛化得到高分。先要定义污染对象：题面、答案、解析、代码测试样例、网页发布日期和数据生成模板都可能泄漏。对题面做 exact match 只是低成本第一层，之后还要做 n-gram、MinHash/SimHash、编辑距离或 embedding 检索，并对代码、数学、考试题和多轮对话分别设置阈值。

近似匹配并不等于确定污染。一个常见数学模板可能自然出现在很多训练样本中，embedding 相似也可能只是同一主题。反过来，题面改写、答案解析泄漏、合成数据复述和发布日期之后抓取都可能绕过简单的字符串匹配。高风险命中要人工核对来源、时间和关键实体，并在评估报告中区分 confirmed、suspected 和 unknown，而不是把所有命中都删除或把所有分数都当无效。

发现污染后，可以重建时间切分或来源隔离的评估集，报告污染前后分数，必要时做 memorization probe 或新题测试。数据 manifest 需要保存抓取时间、来源版本、hash、过滤规则和评估集隔离策略；否则下一次数据重建很难解释分数变化。污染检测本身也可能泄露 benchmark 内容，因此日志应控制访问权限。

一个简化的风险率可以写成：

```math
\mathrm{ContamRate}
=\frac{N_{\mathrm{high\ risk\ matches}}}
{N_{\mathrm{eval\ items}}}
```

分子必须说明采用了什么匹配规则，不能把这个数字冒充真实泄漏概率。更可靠的结论通常来自多种检测方法、人工抽样和时间/来源隔离的独立评估共同支持。

## 5. 如何选择 batch size 和 learning rate？

### 回答框架

1. batch size 受显存、稳定性和吞吐限制。
2. learning rate 和 batch size 联动。
3. 需要 warmup 和 decay。
4. 用小规模实验搜索。

### 标准回答

Batch size 要看 global batch，而不是单卡 batch。`micro-batch` 决定单卡一次能否放下，gradient accumulation 把多个 micro-step 合成一次 optimizer update，data parallel world size 决定每轮汇总多少样本：

```math
B_{\mathrm{global}}
=B_{\mathrm{micro}}\cdot A\cdot W
```

LLM 中还要进一步看有效 token batch：

```math
D_{\mathrm{step}}
=\sum_{i\in\mathrm{batch}}L_i^{\mathrm{valid}}
```

`L_i^{valid}` 是第 `i` 个样本实际参与 loss 的 token 数。padding 很多或 assistant 答案很短时，样本 batch 相同，实际优化信号可能差很多。batch 变大通常降低梯度噪声并提高硬件吞吐，但也会改变每个 optimizer update 的数据量、学习率尺度和泛化行为。

Learning rate 要和 global batch、模型规模、数据质量、optimizer 和有效 token 归一化一起调。线性 scaling 或平方根 scaling 可以作为初始假设，不能在改变序列长度、loss reduction、梯度累积或数据 mixture 后直接照搬。大模型训练通常需要 warmup，避免初期随机状态下更新过大，再用 cosine decay 或其他 schedule。实际中我会先用小规模实验找稳定区间，观察 loss、grad norm、非有限值、validation loss 和吞吐，再决定 peak lr、warmup steps、clipping 与最终 batch。

如果 `B_micro=2`、`A=8`、`W=16`，那么 global batch 是 256 个样本。LLM 训练里还应进一步换算成 token batch：`B_global * sequence_length`。

这个例子隐含了每个样本长度相同且每个位置都参与 loss 的假设。若是变长 packed sequence 或 assistant-only SFT，应使用有效 token 数；若不同 rank 的有效 token 数不同，还要按有效 token 做全局加权，而不是简单平均 rank loss。

## 6. ZeRO、FSDP、Tensor Parallel 各自解决什么问题？

### 标准回答

ZeRO 和 FSDP 主要解决数据并行下训练状态在单卡上的复制问题。ZeRO-1 切 optimizer state，ZeRO-2 进一步切 gradient，ZeRO-3 连 parameter 也切；FSDP 通过 sharding、按需 all-gather 和计算后 reshard 达到相近的目标。它们节省的是单卡状态显存，同时引入参数/梯度通信和更复杂的 checkpoint、wrap policy 与性能调优。

Tensor Parallel 切的是层内矩阵计算，例如 attention 和 MLP 的大矩阵，使一个层的计算分摊到多张卡。它每层都有较频繁的 collective，通常更适合同节点高速互联；Pipeline Parallel 则按层切成 stage，能放下更深的模型，但会引入 pipeline bubble、micro-batch 调度和跨 stage 传输。实际系统常把 FSDP/ZeRO、TP、PP 和 sequence/context parallel 组合使用。

一个清晰的比较方式是问“切了什么、节省什么、增加什么通信”：

| 方法 | 切分对象 | 主要收益 | 主要代价 | 典型约束 |
| --- | --- | --- | --- | --- |
| ZeRO-1/2/3 | optimizer、gradient、parameter | 单卡训练状态显存下降 | collective、参数 gather、实现复杂度 | 网络和 shard checkpoint |
| FSDP | 参数、梯度、optimizer 状态 | 全分片数据并行、可与 PyTorch 集成 | all-gather/reshard、wrap 和保存策略 | 模块边界与通信时机 |
| TP | 层内矩阵 | 单层计算和参数分摊 | 高频同步通信 | 高速互联、维度可整除 |
| PP | 层/模块 stage | 放下更深模型 | bubble、调度和 stage 不均衡 | micro-batch 和流水线拓扑 |

追问“ZeRO-3 为什么通信更大”时，应说明参数本来在每个 rank 都有副本；切掉 parameter 后，每个 forward/backward 需要按计算范围 gather，计算后再释放或 reshard，所以省的是显存，付出的是通信和调度。最终方案要用 step time、通信占比、显存峰值和恢复测试比较，而不是只看能否启动。

### 常见追问

1. ZeRO-3 为什么通信更大？
2. FSDP 和 DDP 区别是什么？
3. TP 和 PP 怎么组合？

## 7. 如何估算训练显存？

### 回答框架

1. 参数。
2. 梯度。
3. optimizer state。
4. 激活。
5. buffer。

### 标准回答

```text
训练显存不能只看模型权重。以 AdamW 为例，除了参数，还要保存梯度、一阶动量、二阶动量，可能还有 FP32 master weights。粗略看，如果权重和梯度是 BF16，optimizer state 是 FP32，那么仅训练状态就可能接近十几 bytes per parameter。

此外还要算激活显存，它和 batch size、sequence length、hidden size、layers 强相关。长上下文训练时 activation 可能非常大。因此显存优化通常包括 BF16、activation checkpointing、减小 micro-batch、FlashAttention、ZeRO/FSDP 和参数高效微调。
```

量级估算可以写成：

```math
M_{\mathrm{state}}
\approx
N(b_w+b_g+2b_m+b_{\mathrm{master}})
```

其中 `b_w` 是权重字节数，`b_g` 是梯度字节数，`b_m` 是 Adam moment 单个状态字节数，`b_master` 是 FP32 master weights 字节数。这个式子不包含 activation，所以真实训练显存还要再加上 activation、通信 buffer、临时 workspace 和框架开销。

如果按 `b_w=2`、`b_g=2`、`b_m=4`、`b_master=4` bytes/parameter 估算，7B 模型的训练状态约为：

```math
7\times10^9(2+2+8+4)\ \mathrm{bytes}
\approx104.3\ \mathrm{GiB}
```

这只是全量状态的量级，不是“需要一张 104 GiB 的卡”。FSDP/ZeRO 分片后，状态大致按 data-parallel rank 分布，但每卡仍有 activation、通信 buffer、临时 workspace、embedding/未分片参数和显存碎片。若模型采用 FP8、QLoRA、不同 optimizer 或冻结部分参数，字节数和可训练状态都会改变。回答显存题时，最好先说这是哪种精度、哪种 optimizer、是否全量训练，再给数字。

## 8. SFT 后模型变笨了怎么办？

### 回答框架

1. 判断变笨的表现。
2. 检查 SFT 数据质量。
3. 检查数据配比和训练步数。
4. 检查学习率和 loss mask。
5. 做 regression eval。

### 标准回答

我会先把“变笨”拆成可测的回归：数学、代码、事实问答、多语言、长上下文、格式遵循、拒答和工具调用分别下降了多少。然后比较 SFT 前后的固定 regression eval、per-domain loss 和 bad case，确认是能力退化、输出风格变化，还是评估 prompt/template 不一致。

接着检查 SFT 数据：质量是否低或模板化，答案是否过长，领域是否过窄，role/template 是否错位，user prompt、padding 或 image placeholder 是否误算进 loss，训练步数和学习率是否过大。SFT 可能让模型过拟合某种指令风格，也可能因为数据里包含错误事实、过度拒答或低质量格式而改变行为；只看 SFT loss 下降无法区分这些原因。

修复路径包括降低学习率或 epoch、提高数据质量、调整数据配比、混入通用 replay 数据、使用更准确的 assistant-only mask、冻结部分底座或采用 LoRA，并在每个候选 checkpoint 上做回归和安全评估。若新领域能力的收益和通用能力损失同时存在，应把它作为显式 trade-off 报告，而不是笼统地说“模型变笨”。

## 9. 如何训练一个 VLM？

### 回答框架

1. 选择 vision encoder。
2. 设计 connector。
3. 接入 LLM。
4. 做图文对齐和 instruction tuning。
5. 做评估和安全检查。

### 标准回答

VLM 通常由 vision encoder、connector 和 LLM 组成，但面试回答不能停在结构图。视觉 encoder 先把图像转成 `N_v` 个视觉 token，connector 把最后一维映射到 LLM hidden size，随后通过 prefix 拼接、cross-attention 或 query resampler 与文本交互。若文本长度为 `T`，直接拼接后的序列长度大致是 `T+N_v`，因此分辨率、多图数量和视觉压缩比例会同时影响 attention、KV cache 和 batch size。

训练上可以先做图文对齐或 connector 预训练，再做多模态 instruction tuning，覆盖 caption、VQA、OCR、图表理解、空间关系和多轮对话。根据资源和域差异，可以冻结 vision encoder 或 LLM，只训练 connector，也可以使用分组学习率联合微调。label mask 要明确 prompt、placeholder、padding 和 assistant answer 的边界；否则模型可能学会复读输入模板而不是读取图像。

评估上要分层看 OCR/关键字段、幻觉、计数、空间关系、图表、grounding、反事实替图和安全风险。比如图片替换后答案完全不变，说明需要调查模型是否只看了文本先验；caption 流畅也不能证明金额、日期和小字抽取正确。多模态训练的完整答案应同时包含数据协议、训练阶段、资源预算和证据评估。

## 10. 如何控制大规模训练成本？

### 回答框架

1. 目标和规模匹配。
2. 数据和 token 预算。
3. 提升吞吐和 MFU。
4. 降低失败率。
5. 管理 checkpoint 和评估成本。

### 标准回答

我会先从目标能力和可获得数据倒推模型规模、训练 token 和上下文长度，避免模型太大但 token 不够，或把大量预算花在低质量重复数据上。接着用 `6ND` 做 FLOPs 量级估算，再用真实序列长度的短程 benchmark 测单卡吞吐和多卡扩展效率；不能把理论峰值或单卡 tokens/s 直接线性外推。

系统层面通过 BF16/FP8、activation checkpointing、ZeRO/FSDP、FlashAttention、合理 micro-batch 和通信重叠降低每步成本，但每个优化都要写清代价：重计算增加 FLOPs，分片增加通信，降低分辨率或序列长度可能损失能力，冻结模块可能降低适应性。流程上先做小规模 smoke test 和恢复演练，训练中监控有效 tokens/s、MFU、数据等待、非有限值、checkpoint 带宽和回归评估。

checkpoint 可以按 latest、milestone、best、archive 分层保留，成本表还要纳入存储、网络、评估、工程人力和失败重跑。最终比较的不是“每小时 GPU 价格”，而是单位有效 token、单位成功任务或单位能力收益的成本；如果扩卡导致通信效率大幅下降，减少 GPU 反而可能更便宜。

## 11. Base model、Instruct model、Chat model 有什么区别？

### 标准回答

Base model 主要通过预训练的 next-token prediction 学到语言、知识和通用模式，擅长续写和作为下游适配底座，但不保证按照用户指令回答。Instruct model 通常经过 SFT，把问题、角色、答案和格式变成监督样本，学会遵循指令；它的行为仍然取决于数据覆盖和 mask。Chat model 是面向多轮交互的产品形态，通常还加入对话数据、偏好优化、安全对齐、系统消息和拒答边界，但“chat”并不是一个严格统一的训练算法名称。

这三个词描述的重点不同：base 偏能力底座，instruct 偏任务行为，chat 偏交互协议和安全产品体验。一个模型可以同时发布 base 和 instruct 版本，某些所谓 chat 能力也可能来自模板、系统提示或推理时工具，而不是参数更新。判断模型阶段时要看模型卡、训练报告和输入模板，不能只根据名称推断。

## 12. DPO 和 PPO 有什么区别？

### 标准回答

PPO 是常见的在线 RLHF 路线：当前 policy 生成回答，reward model 或环境给出奖励，reference model 提供 KL 约束，critic 估计 value，policy 再用 clipped objective 更新。它能在当前生成分布上探索，也能接入可执行环境，但需要 rollout、reward、value、采样和稳定性控制，成本与工程复杂度都高。

DPO 是离线偏好优化：给定同一个 prompt 的 `chosen/rejected`，直接优化当前 policy 相对于 reference policy 的偏好差异，不需要单独训练 reward model 或在线 rollout。它实现简洁，适合已有偏好对；但效果依赖偏好数据覆盖，离线数据与当前 policy 分布不匹配时可能过拟合，且不能自动探索新的推理轨迹。对于 reasoning RL、代码执行或数学验证，GRPO/RLVR 等路线可以直接使用 verifier 或环境奖励，但会带来 rollout 成本和奖励设计问题。

一个好的比较不应只说“PPO 复杂、DPO 简单”，还要指出优化对象不同：PPO 在策略和环境反馈的闭环中更新，DPO 在固定偏好对上做相对排序学习。选择取决于是否有可靠 reward/verifier、是否需要在线探索、偏好数据规模、分布偏移和单位成功任务成本。

DPO 的核心面试公式可以压缩成：

```math
L_{\mathrm{DPO}}
=
-\log\sigma\left(
\beta(\Delta_\theta-\Delta_{\mathrm{ref}})
\right)
```

其中 `\Delta_\theta` 是当前 policy 对 chosen/rejected 的序列 log probability 差，`\Delta_{\mathrm{ref}}` 是 reference model 的对应差值，`\beta` 控制偏好信号相对 reference 的尺度。序列 log probability 通常是目标 token 的逐 token log probability 之和，mask 和长度归一化会影响实际数据权重。这个公式的面试价值是说明：DPO 不是无约束地提高 chosen 概率，而是相对 reference 调整偏好。

PPO 的 clipped ratio 则可以写成：

```math
L_{\mathrm{PPO}}
=-\mathbb{E}_t\left[
\min\left(r_t(\theta)\hat A_t,
\operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat A_t
\right)\right]
```

`r_t(\theta)` 是新旧 policy 对同一动作的概率比，`\hat A_t` 是 advantage，`\epsilon` 控制单次策略变化的裁剪范围。它与 DPO 的离线 pairwise loss 不是同一个目标；面试追问“为什么 PPO 还要 reference model”时，应区分 PPO 的旧 policy ratio、KL 约束和 reward model 各自承担的角色。

## 13. 训练类面试回答 checklist

回答训练题时，最后可以自检：

```text
1. 是否先讲目标？
2. 是否讲数据和 tokenizer？
3. 是否讲模型架构和规模？
4. 是否讲训练目标和优化器？
5. 是否讲分布式和显存？
6. 是否讲监控和 debug？
7. 是否讲 checkpoint 和评估？
8. 是否讲成本和风险？
9. 是否讲 trade-off？
```

如果一个回答覆盖这些点，就比较完整。

但“覆盖”不等于“讲清”。面试官可能继续追问一个变量的定义、一个选择的代价或一个失败样本。自评时应从 checklist 里随机挑一项继续问自己：数据配比改变后哪个 domain 先受影响？global batch 是样本数还是有效 token？FSDP 节省了哪部分显存、增加了什么通信？loss spike 后如何证明修复没有改变数据分布？能回答这些追问，才说明清单已经转化成机制理解。

### 13.1 最小可运行面试回答自评 demo

下面这个 0 依赖 demo 用关键词和几个量级计算检查一个“训练 7B 模型”的回答是否覆盖关键维度。它不是替代人工判断，而是把面试复盘变成可检查的局部诊断；关键词命中也不代表回答真的有深度。

```python
answer = """
目标是训练一个通用 7B base model，再进入 SFT 和偏好优化。
数据上做网页、代码、数学和多语言 mixture，先清洗、去重并做 contamination 检测。
模型选择 decoder-only Transformer，使用 RoPE、RMSNorm、SwiGLU 和 GQA。
训练目标是 next-token prediction，优化器用 AdamW，配 warmup、cosine decay、BF16、gradient clipping。
系统上根据显存选择 ZeRO/FSDP、TP 和 activation checkpointing。
监控 train loss、val loss、grad norm、lr、tokens/s、MFU、NaN、checkpoint。
评估包括 per-domain loss、代码、数学、安全、人工评估和 regression eval。
风险包括 loss spike、数据污染、能力退化、恢复失败和成本超预算。
成本上用 FLOPs、GPU hours、checkpoint 存储和失败重跑预算做量级估算。
""".lower()

rubric = {
    "target": ["目标", "base model"],
    "data": ["数据", "mixture", "清洗", "去重"],
    "contamination": ["contamination", "污染"],
    "model": ["decoder-only", "rope", "rmsnorm", "swiglu", "gqa"],
    "optimization": ["adamw", "warmup", "cosine", "bf16", "clipping"],
    "distributed": ["zero", "fsdp", "tp", "checkpointing"],
    "monitoring": ["train loss", "val loss", "grad norm", "mfu", "checkpoint"],
    "evaluation": ["per-domain", "代码", "数学", "安全", "regression"],
    "risk": ["loss spike", "能力退化", "恢复失败"],
    "cost": ["flops", "gpu hours", "存储", "重跑"],
}
coverage = {
    name: all(keyword in answer for keyword in keywords)
    for name, keywords in rubric.items()
}
score = sum(coverage.values())

micro_batch = 2
grad_accum = 8
data_parallel = 16
global_batch = micro_batch * grad_accum * data_parallel

params = 7_000_000_000
train_tokens = 1_000_000_000_000
train_flops = 6 * params * train_tokens
adamw_state_gib = params * (2 + 2 + 8 + 4) / 1024**3

diagnostics = {
    "coverage_is_complete": score == len(rubric),
    "global_batch_is_expected": global_batch == 256,
    "adamw_state_estimate_is_expected": round(adamw_state_gib, 2) == 104.31,
}

print(f"coverage={coverage}")
print(f"score={score}/10")
print(f"missing={[name for name, ok in coverage.items() if not ok]}")
print(f"global_batch={global_batch}")
print(f"train_flops={train_flops:.2e}")
print(f"adamw_state_gib={adamw_state_gib:.2f}")
print(f"diagnostics={diagnostics}")
```

这段 demo 的关键输出应该是：

```text
coverage={'target': True, 'data': True, 'contamination': True, 'model': True, 'optimization': True, 'distributed': True, 'monitoring': True, 'evaluation': True, 'risk': True, 'cost': True}
score=10/10
missing=[]
global_batch=256
train_flops=4.20e+22

```

真正面试时不需要把脚本背出来，但要能像脚本一样自查：有没有目标、有没有数据、有没有模型和训练、有没有系统和评估、有没有风险和成本。脚本的 `diagnostics` 只检查覆盖和两个教学数值；回答是否准确、是否能解释取舍，仍然需要人工追问和事实核对。

## 14. 本章小结

本章把第五册的训练知识组织成可复述的工程推理。设计题从目标和数据开始，debug 题从第一次异常和可复现 batch 开始，评估题要说明污染与回归，分布式题要说清切了什么、省了什么、增加了什么通信，成本题要把 FLOPs、吞吐、存储和失败率放进同一张表，后训练题要区分 SFT、PPO、DPO、reasoning RL 和安全对齐，多模态题则要补充模态 token、监督边界和证据评估。

真正成熟的面试回答不会把所有方法都说成“最佳实践”。它会说明基线、约束、可测指标、反例和回退方案：例如 AdamW 是稳定基线但不保证最优，DPO 简洁但依赖离线偏好分布，FSDP 省状态显存却增加通信，VLM connector 能建立桥接却可能压缩掉小字，MFU 高也不等于训练能力提升。这样的回答才能在追问中保持一致。

这些资料支持方法来源和接口解释，不替代针对当前模型、数据、硬件和评估协议的实测。面试回答引用论文时，也要说明论文的训练规模、数据和实验口径，避免把论文结论泛化成所有模型的定律。
