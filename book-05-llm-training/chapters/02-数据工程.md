# 第二章：数据工程：从原始来源到可训练 token

## 2.0 模型学习的不是“数据集文件”

训练目录里可能有网页、书籍、代码、论文、对话、数学题、图片和音频。它们在磁盘上看起来是文件，在训练时却会经过解析、规范化、过滤、去重、tokenizer 编码、采样和 packing，最后才变成真正参与梯度计算的 token。模型学习的不是目录名，也不是下载页面上的总字节数，而是这个过程中留下的 token 分布和监督信号。

初学者可以先把数据工程理解成一个漏斗：最上面是来源很多、格式混乱的原始数据，中间经过质量检查和风险处理，最下面是数量更少但可追踪、可混合、可复现的训练样本。漏斗不是越窄越好；删掉太多会损失稀有知识，留下太多会浪费计算并放大噪声。

专家需要进一步追问：一个 token 来自哪份原始文档？文档是否获得使用授权？它在 exact dedup 和 near dedup 中被怎样处理？它是否接近评估集？它是人工写的、模型生成的还是蒸馏得到的？它在最终 mixture 中被采样了多少次？训练后发现能力变化时，能否把变化追溯到这条 lineage？

因此，数据工程不是训练前的清洁工作，而是模型能力、评估可信度、隐私风险和算力效率的共同基础。本章沿着一条完整生命周期展开：来源与许可、统一 schema、解析与规范化、质量评估、风险过滤、精确和近似去重、benchmark 污染、数据配比、合成数据、任务数据、打包、版本管理、删除和训练前审计。

## 2.1 数据生命周期与三个契约

### 2.1.1 生命周期地图

一个可审计的数据 pipeline 可以抽象为：

~~~text
source
  -> manifest
  -> parse and canonicalize
  -> identify language, domain, and risk
  -> quality filter and quarantine
  -> exact dedup
  -> near dedup
  -> benchmark contamination scan
  -> mixture and sampling
  -> tokenize, pack, and shard
  -> training dataloader
~~~

每个箭头都应产生统计和版本信息。比如，`parse` 阶段需要知道多少文件解析失败，`dedup` 阶段需要知道删除的是多少文档和多少 token，`mix` 阶段需要知道目标比例是按文档数还是按有效 token 数计算，`pack` 阶段需要知道 padding 浪费了多少计算。

### 2.1.2 来源契约

来源契约回答“这条数据从哪里来，能否使用”。它至少包含来源标识、抓取或生成时间、原始 URL 或仓库 commit、许可信息、地区限制、删除请求入口和责任主体。公开可访问不等于可以任意复制、训练或发布；可下载性、版权、个人信息和合同限制是不同问题。

### 2.1.3 结构契约

结构契约回答“下游如何理解这条数据”。同一个字段名必须有稳定语义：`text` 是已经抽取的正文还是包含 HTML？`timestamp` 是来源时间还是入库时间？`language` 是检测结果还是作者声明？如果 schema 语义漂移，后面的过滤和统计仍会运行，但结果不再可比较。

### 2.1.4 训练契约

训练契约回答“哪些样本以什么目标进入梯度计算”。预训练文本、对话 SFT、偏好对、代码执行轨迹和多模态样本的 label mask 不同。数据文件通过了来源和结构检查，不代表它已经满足训练目标。数据工程的最终交付不是“文件存在”，而是每个训练样本都能解释输入、目标、mask 和风险。

## 2.2 数据来源：数量、权威性和适用范围

### 2.2.1 常见来源类型

| 来源 | 能提供什么 | 主要风险 |
| --- | --- | --- |
| 网页和 Common Crawl | 广泛知识、表达方式和时效信息 | 垃圾、重复、个人信息、来源不稳定 |
| 书籍和论文 | 连贯论述和专业知识 | 版权、许可、领域和时间偏差 |
| 代码仓库 | 程序结构、注释、测试和工具使用 | 许可证、密钥、漏洞和 benchmark 泄漏 |
| 对话和客服记录 | 真实任务、澄清和交互风格 | 隐私、授权、模板化和标注偏差 |
| 数学与科学资料 | 符号、推导、可验证答案 | 题目答案泄漏、格式错误和幻觉解析 |
| 人工标注数据 | 任务定义、偏好和安全边界 | 标注一致性、代表性和成本 |
| 合成或蒸馏数据 | 扩展覆盖、格式和难例 | 教师错误、同质化和模型坍缩风险 |
| 图像、音频和视频 | 跨模态对应、时序和声学信号 | 对齐错误、隐私、版权和元数据丢失 |

来源质量不能只按“官方”或“非官方”二分。官方文档通常适合确认 API 语义和产品事实，原始论文适合确认方法和实验，用户生成内容可能包含真实问题和边界案例，但需要更强的隐私和质量处理。数据源的权威性是一个与任务相关的属性：法律条文要关注版本和管辖区，代码要关注可运行性和许可证，医学内容要关注来源和更新时间。

### 2.2.2 来源时间和知识截止

每条文档应保留来源时间、抓取时间和进入训练版本的时间。三者不同：一篇文章可能在 2024 年发布，2026 年被重新抓取；一个代码仓库的 README 可能没有更新，但 commit 已经变化；网页内容可能在同一个 URL 上被替换。

如果模型需要回答时间敏感问题，数据 pipeline 还要区分“文档描述的事件时间”和“页面更新时间”。把网页抓取日期当成事实发生日期，会给后续检索和评估造成系统性错误。

### 2.2.3 许可和隐私不能被质量分替代

一条文字表达很流畅，不代表它可以被训练。许可状态、个人信息、商业秘密和删除请求应作为独立字段记录，而不是被塞进一个总质量分。质量高但未授权的数据，仍然可能不应进入训练；质量低但需要保留用于安全红队的数据，也不应被简单永久删除。

工程上可以把样本分为 `trainable`、`quarantine`、`evaluation_only` 和 `blocked` 等状态，但状态名必须配套明确规则、负责人和变更日志。状态是治理记录，不是对内容本身的价值判断。

## 2.3 Manifest：把原始文件变成可追踪对象

### 2.3.1 最小 manifest

每个原始对象应有稳定 ID 和校验信息。一个最小文本 manifest 可以包含：

~~~json
{
  "record_id": "web_2026_000001",
  "source_uri": "https://example.invalid/page",
  "source_type": "web",
  "retrieved_at": "2026-08-14T00:00:00Z",
  "source_timestamp": "2026-07-20T00:00:00Z",
  "license": "unknown",
  "content_hash": "sha256:...",
  "parser_version": "html-parser-3",
  "language": "zh",
  "domain": "general",
  "status": "quarantine"
}
~~~

`source_uri` 不是稳定身份，网页可能变化；`content_hash` 只能证明某个快照内容，不证明授权；`parser_version` 影响抽取结果；`status` 表示当前处理状态。一个数据版本应有 manifest 的快照和文件级 hash，不能只保存一个总目录名。

### 2.3.2 数据 lineage

把一个训练样本记为 `d`，它的来源和变换可以抽象成：

~~~math
d^{(0)}
\xrightarrow{f_{\mathrm{parse}}}
d^{(1)}
\xrightarrow{f_{\mathrm{clean}}}
d^{(2)}
\xrightarrow{f_{\mathrm{dedup}}}
d^{(3)}
\xrightarrow{f_{\mathrm{mix}}}
d^{(4)}
~~~

每个函数都应绑定代码版本、配置版本和输入输出统计。这样，当某个训练运行出现异常时，可以从训练样本 ID 回到原始来源，也可以从一个原始对象查到它是否被过滤、合并、重复采样或排除。

### 2.3.3 失败对象要保留

解析失败、乱码、疑似 PII、许可未知或污染命中的对象，不应在没有记录的情况下从系统中消失。可以把正文放入隔离区，把原因写入 `filter_reason`，并限制访问权限。失败对象的统计能帮助判断规则是不是误伤了某种语言、文件格式或领域。

## 2.4 解析与规范化：清洗不是随意改写

### 2.4.1 HTML、PDF、代码和对话的差异

不同来源需要不同解析器：

| 输入 | 常见解析问题 | 需要保留的结构 |
| --- | --- | --- |
| HTML | 导航、广告、脚本和重复模板 | 标题、段落、列表、表格和链接上下文 |
| PDF | 阅读顺序、双栏、页眉页脚和 OCR 错误 | 页码、标题、表格、脚注和出处 |
| Markdown | 代码围栏、链接和标题层级 | 代码块、列表、引用和语言标识 |
| 代码仓库 | 生成文件、依赖、密钥和二进制 | 路径、语言、commit、测试和许可证 |
| 对话日志 | 角色、时间、脱敏和上下文边界 | speaker、turn、工具调用和标签 |
| 图文样本 | 图片版本、裁剪和文本对应关系 | media hash、caption、区域和来源 |

“去掉所有标记”可能让训练文本更短，却也可能丢掉代码语言、表格列关系和对话角色。规范化的目标是消除无意义差异，不能把有意义结构一起抹掉。

### 2.4.2 Unicode 和文本边界

中文、英文、数学符号、全角字符、组合字符和 emoji 的边界不同。大小写转换、Unicode normalization、标点替换和空白折叠都可能改变 token 数和内容语义。对代码和数学尤其要谨慎：把下划线、缩进或反斜杠当作普通噪声删除，可能让样本不可执行。

规范化函数可以抽象为 `N(x)`，但每次变换都应有测试样本和前后差异统计：

~~~math
x' = N(x),
\qquad
r_{\mathrm{change}}
=
\frac{\mathrm{len}(x')-\mathrm{len}(x)}{\max(1,\mathrm{len}(x))}
~~~

当原文本为空时，分母中的 `1` 只让审计记录可计算，并不把空文本视为正常样本；空文本应在解析阶段单独统计和隔离。长度变化不是质量证明，却能提示某次规则是否突然删除大量内容。实际审计还需要比较字符、行、代码语法和关键字段，而不只是字符串长度。

### 2.4.3 文档边界和上下文

不同文档被拼接到同一个训练序列时，必须保留边界标记或在 attention mask 中阻断不应跨越的关系。否则模型可能把一个网页结尾和另一个完全无关的网页开头当成自然上下文。

packing 提高利用率，但不应以丢失文档边界为代价。文档边界、角色边界和工具调用边界都应在 tokenizer 与训练样本中有可检查的表示。

## 2.5 语言、领域、长度和重复的基础统计

### 2.5.1 语言识别不是一个完美标签

语言识别器可能把代码、混合语言、短文本、姓名和专有名词误判。一个文本被标成 `zh`，不代表它没有英文、数字或公式；短文本的语言置信度尤其不稳定。

应保存语言预测、置信度、脚本比例和人工抽样结果。对于多语言训练，不仅要看文档数量，还要看 token 数、长度分布、代码和数字比例以及不同语言的过滤率。

### 2.5.2 领域标签可以多标签

一篇医疗机器学习论文同时属于 `medicine`、`research`、`code` 和 `math`。把它强行放进单一 domain 会丢失混合统计。可以使用主领域加辅助标签，或让 `domain` 是集合：

~~~math
\mathcal{L}(d_i)
=
\{\ell_{i1},\ell_{i2},\ldots\}
~~~

混合时再明确按哪个标签计数。统计口径不明确，配比表中的百分比就没有可比性。

### 2.5.3 长度分布比平均长度更重要

只报告平均 token 长度会掩盖大量超短和超长样本。应至少报告分位数、长尾比例、每个领域的长度分布和被截断比例。超长文档可能提供跨段关系，也可能是重复日志或拼接错误；不能按长度单独判断价值。

## 2.6 质量评估：质量是向量，不是一个神奇分数

### 2.6.1 质量维度

可把样本质量表示为一个向量：

~~~math
\mathbf{q}_i
=
\left(
q_{\mathrm{source}},
q_{\mathrm{language}},
q_{\mathrm{structure}},
q_{\mathrm{information}},
q_{\mathrm{domain}},
q_{\mathrm{risk}},
q_{\mathrm{duplicate}}
\right)
~~~

这些分量的语义不同：来源可信度不是文本流畅度，风险不是重复度，领域相关性也不等于正确性。把它们压成一个标量可能方便排序，但不能丢掉原始分量。

### 2.6.2 规则、分类器和困惑度

质量信号通常来自三类方法：

1. 规则：长度、字符比例、HTML 模板、重复行、敏感模式和代码语法。
2. 分类器：语言、垃圾、毒性、领域、PII 和合成文本分类器。
3. 模型信号：困惑度、信息密度、embedding 聚类和与目标语料的相似度。

规则可解释但容易被绕过，分类器覆盖广但会误判，困惑度偏好模型熟悉的写法并不等于事实正确。高质量数据处理通常组合多种信号，再用人工抽检检查误删和漏放。

### 2.6.3 标量质量分的教学形式

如果必须排序，可以使用一个教学形式：

~~~math
s_i
=
\sum_{j=1}^{J}w_j q_{ij}
-
\sum_{k=1}^{K}v_k r_{ik}
~~~

`q_ij` 是正向质量特征，`r_ik` 是风险特征，`w_j` 和 `v_k` 是权重。这个分数适合产生抽样优先级，不应直接作为“训练可用”的唯一证明。权重改变后，保留率、语言分布和领域分布都可能变化，因此配置必须版本化。

### 2.6.4 抽样审计

对每个规则和分数桶进行分层抽样，记录：

| 抽样维度 | 为什么要看 |
| --- | --- |
| 高分样本 | 发现高分垃圾或模板 |
| 低分样本 | 判断是否误删稀有高价值内容 |
| 不同语言 | 检查语言识别和规范化偏差 |
| 不同来源 | 检查某个来源是否被规则过度影响 |
| 不同长度 | 检查短文本和长文档边界 |
| 过滤原因 | 验证规则是否真的命中目标 |

人工抽检不能替代自动统计，但可以发现指标看不到的系统性错误，例如所有 PDF 的表格被解析器打乱，或某种方言被语言分类器统一判成噪声。

## 2.7 清洗、风险过滤和隔离

### 2.7.1 清洗的目标

常见清洗包括去除空对象、乱码、重复空行、导航模板、异常编码、明显广告和损坏的结构。每条规则都应回答三个问题：它要排除什么，可能误删什么，如何抽样验证。

### 2.7.2 PII、secret 和安全内容

个人姓名、电话、邮箱、地址、身份证号、访问令牌和私有密钥的风险不同，不能只用一个“敏感内容”标签。可以记录类型、置信度、来源、处理动作和复核状态。代码数据还应检查 `.env`、证书、云密钥、内部 URL 和生产配置。

处理动作可以是删除、掩码、替换、隔离、仅用于安全评估或保留原文但限制访问。掩码会改变训练分布，删除会损失上下文；选择哪种动作应由用途、授权和风险决定。

### 2.7.3 有害内容与安全数据

预训练数据中的有害内容与安全对齐数据不是一回事。为了训练拒答和红队检测，某些高风险样本可能需要进入专门的安全数据集，但不应无标签地混入通用语料。安全样本需要记录用途、访问权限、训练目标和评估边界。

“全部删除有害内容”可能使模型缺少识别和拒绝有害请求的经验；“全部保留”又可能扩大生成风险。数据治理必须把预训练覆盖、对齐训练、红队评估和发布策略分开设计。

### 2.7.4 过滤过度和过滤不足

过滤过度会损失代码、表格、公式、口语和低资源语言；过滤不足会浪费 token、放大偏见、泄露隐私和污染评估。要同时报告保留率和过滤原因分布：

~~~math
r_{\mathrm{keep}}
=
\frac{|D_{\mathrm{kept}}|}{|D_{\mathrm{raw}}|}
~~~

~~~math
r_{\mathrm{drop},c}
=
\frac{|D_{\mathrm{drop},c}|}{|D_{\mathrm{raw}}|}
~~~

这些比例要求 `|D_{\mathrm{raw}}|>0`，并且每个丢弃对象只能按预先定义的主原因进入一个互斥桶，或显式允许多标签计数并说明各率不再可相加。若原始集为空，保留率与丢弃率应报告 `N/A`。若某次规则更新后中文、代码或长文档桶的保留率突变，应先做抽样和回归，再决定是否继续。

## 2.8 Exact Dedup：先处理最容易确认的重复

### 2.8.1 规范化后 hash

对规范化文本 `N(x_i)` 计算 hash：

~~~math
h_i=H(N(x_i))
~~~

按 hash 保留第一次出现或质量更高的版本，可以去掉完全相同的镜像、重复导入和复制粘贴。保留哪一份并不只是随机选择：来源可信度、时间、新鲜度、许可和元数据完整性都可能决定优先级。

### 2.8.2 Exact dedup 的边界

exact dedup 不会识别改写、模板变化、转码、代码变量名替换和同一题目的不同表述。它也不能证明没有 benchmark 污染。exact dedup 适合做第一层低成本处理，不能替代 near dedup、污染检测和人工审计。

### 2.8.3 统计 token 变化

报告 exact dedup 时应同时给出文档数和 token 数：

~~~math
r_{\mathrm{doc}}
=
\frac{n_{\mathrm{before}}-n_{\mathrm{after}}}{n_{\mathrm{before}}}
,
\qquad
r_{\mathrm{tok}}
=
\frac{D_{\mathrm{before}}-D_{\mathrm{after}}}{D_{\mathrm{before}}}
~~~

前式要求 `n_{\mathrm{before}}>0`，后式要求 `D_{\mathrm{before}}>0`；如果解析前没有有效文档或 token，应报告管线覆盖问题而不是“去重率为零”。文档重复率高而 token 重复率低，和少数长文档被复制的情况，训练影响不同。只报告“删了 20% 文档”不足以估算节省了多少训练计算。

## 2.9 Near Dedup：相似不等于相同

### 2.9.1 Shingle 与 Jaccard

把文本切成长度为 `k` 的 shingle 集合：

~~~math
A_i=\mathrm{shingle}_k(x_i)
~~~

两个样本的 Jaccard 相似度为：

~~~math
J(A_i,A_j)
=
\frac{|A_i\cap A_j|}{|A_i\cup A_j|}
~~~

它直观、容易验证，但所有样本两两比较的成本是平方级，不能直接用于 web-scale 全量数据。

### 2.9.2 MinHash、SimHash 和候选召回

MinHash 可以用较短签名近似 Jaccard，SimHash 更适合某些局部特征的近邻检索，LSH 则把相似签名放入相同桶以减少候选数。生产系统通常分两层：先用便宜的签名或索引召回候选，再用更准确的 token、字符或 embedding 相似度确认。

阈值不是自然常数。阈值太低会把主题相同但内容独立的文档合并，阈值太高会留下大量转载。阈值应在不同语言、代码、数学、模板和长短文档上分别抽样校准。

### 2.9.3 近重复图和保留策略

把样本看作节点，把相似度超过阈值的样本连边，可以形成重复簇。一个簇里应优先保留来源更可靠、内容更完整、版本更新、更少个人信息或许可更清楚的对象。不能只保留最短文本，也不能用随机删除破坏数据 lineage。

代码 near dedup 还要考虑仓库 fork、自动生成文件、许可证头、变量名和测试代码。两个函数主体相同但许可证不同，可能需要保留元数据并改变使用策略，而不是只按文本相似度删除。

### 2.9.4 误删问题

FAQ、法律条款、API 文档和标准协议可能高度重复，但重复本身是语义稳定性的特征。去重的目标是减少无意义重复，而不是让每个概念只出现一次。应在删除前估计簇的来源多样性和领域覆盖，保留必要的独立版本。

## 2.10 Benchmark Contamination：评估集与训练集的边界

### 2.10.1 污染的几种形式

污染不只是训练文件中出现完全相同的题面：

1. 题目原文被抓取。
2. 题目经过改写或翻译后仍高度相似。
3. 参考答案、解析或测试样例进入语料。
4. 代码题的仓库、issue 或单元测试泄漏。
5. 评估集发布时间晚于模型训练，但公开讨论或镜像数据包含答案。

不同形式需要不同检测；一次 exact match 没有命中，不代表没有污染。

### 2.10.2 近似检索和人工复核

令 benchmark 为 `B={b_j}`，训练样本为 `d_i`，相似度函数为 `s`，可以定义最高风险候选：

~~~math
c_i
=
\max_j s(x_i,b_j)
~~~

高 `c_i` 样本进入隔离和人工复核，而不是直接用一个阈值自动宣告“污染”或“无污染”。相似度可能来自字符、n-gram、MinHash、embedding、代码 AST 或题目结构。报告应保存命中的 benchmark ID、相似度、匹配片段、训练版本和处理动作。

### 2.10.3 时间切分和新鲜评估集

使用训练截止时间之后新构建的评估集，可以降低历史泄漏风险，但不能保证绝对没有污染。题目可能来自同一知识源，模型也可能通过预训练数据学到答案。更可靠的做法是组合静态 benchmark、私有或新生成的任务集、人工构造的反事实样本和真实业务切片。

### 2.10.4 污染报告的正确口径

不应把“未检出”写成“没有污染”。应写清楚检测方法、覆盖范围、阈值、抽样规模、已发现命中和未知风险。benchmark 污染是一个带检测能力边界的风险判断，不是一个可以被一次扫描彻底证明为零的属性。

## 2.11 数据配比：有限 token 应该花在哪里

### 2.11.1 文档比例和 token 比例不是一回事

设第 `k` 个数据域进入训练的有效 token 数为 `D_k`，总 token 数为 `D`，token-level 比例为：

~~~math
w_k=\frac{D_k}{D},
\qquad
\sum_{k=1}^{K}w_k=1
~~~

这里每个 `D_k\ge0`，总有效 token `D=\sum_kD_k>0`。某个桶可以暂时为零，但整个 mixture 为空时不存在合法的 token 比例；应停止并检查上游过滤或 tokenization。 如果按文档数采样，长文档域的 token 比例会被低估；如果按原始文件大小采样，压缩比、解析失败和 padding 会改变实际进入 loss 的比例。训练报告应明确比例的分母。

### 2.11.2 温度采样

若第 `k` 个数据桶有规模 `n_k`，一个常见的平滑采样形式为：

~~~math
p_k
=
\frac{n_k^\alpha}{\sum_{j=1}^{K}n_j^\alpha}
~~~

该形式要求每个 `n_k\ge0`、`\alpha>0`，并且至少一个桶的规模为正；空桶在正 `\alpha` 下的权重为零。若取 `\alpha=0`，零规模桶会出现 `0^0` 的歧义，不能把它当作“所有域均匀采样”。当 `alpha=1` 时接近原始规模比例；`alpha` 变小后，小数据桶相对获得更多采样机会。它适合缓解大规模网页淹没代码、数学或低资源语言，但会提高小数据桶的重复次数。

### 2.11.3 重复倍数与过采样风险

若计划训练 token 为 `D`，桶 `k` 的采样比例为 `p_k`，原始有效 token 为 `D_k^{\mathrm{data}}`，粗略重复倍数为：

~~~math
e_k
=
\frac{p_kD}{D_k^{\mathrm{data}}}
~~~

该比率只适用于 `D_k^{\mathrm{data}}>0` 的桶；若配置给空桶正采样概率，说明采样表或数据版本错位，应立即报错而不是得到无穷大重复倍数。高 `e_k` 可能帮助低资源能力，也可能造成过拟合、记忆、风格偏移和 benchmark 泄漏。应结合 per-domain loss、去重后规模和回归评估判断，而不是只看采样器的数学合法性。

### 2.11.4 动态 mixture

预训练早期、继续预训练、领域适配、SFT 和偏好训练的最优数据结构不同。动态 mixture 可以根据阶段、验证集和目标能力调整，但每次改变都要记录版本，否则无法解释能力变化。

一个实用原则是：先建立稳定基线，再一次只改变少数数据因素，保留固定评估集和成本口径。否则同时改变数据比例、tokenizer 和学习率，实验结果无法归因。

## 2.12 合成数据、蒸馏与 Model Collapse

### 2.12.1 合成数据为什么有用

合成数据可以扩展稀缺任务、生成格式样本、构造难例、补充工具轨迹和提供可验证答案。教师模型能够快速生成大量候选，再由规则、执行器或人工筛选。

### 2.12.2 合成数据为什么危险

教师错误会被复制，过滤器可能只保留表面流畅的答案，生成分布可能比真实用户更窄。重复使用同一教师和同一 prompt 会使数据高度同质化，模型再训练这些输出，可能逐步丢失原始分布中的尾部和多样性。

Model Collapse 的讨论提醒我们，递归使用模型生成数据不能被视为免费扩容。数据来源应带 `human`、`synthetic`、`distilled` 等 provenance 标签，并统计各来源的 token 比例、重复度、难度和错误类型。

### 2.12.3 合成数据的验证链

一个可靠的合成数据流程至少包含：

1. 教师版本和生成配置。
2. 生成输入的来源和许可。
3. 多样性和重复统计。
4. 规则、执行器或独立模型验证。
5. 人工抽检和错误分类。
6. 与人类数据的比例和能力对比。
7. 失败样本保留和可回放记录。

对代码，执行测试比文本打分更有用；对数学，独立求解器或符号检查比“看起来像推导”更可靠；对事实问答，检索来源和引用核验比教师模型自评更可靠。

## 2.13 任务数据：SFT、偏好和可验证轨迹

### 2.13.1 SFT 数据的结构

一条对话 SFT 样本应明确角色、顺序、工具结果和 assistant target。一个抽象结构是：

~~~json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "target_roles": ["assistant"],
  "source": "human_reviewed",
  "license": "internal"
}
~~~

如果 assistant 内容中混入未验证的工具结果、隐藏提示或答案泄漏，SFT 会把这些内容当成学习目标。label mask、工具边界和 system instruction 应在数据构建阶段就明确。

### 2.13.2 偏好数据不是“好答案和坏答案”两个字符串

偏好对还需要记录输入、两个候选的生成来源、评审标准、评审者或 judge 版本、分歧、拒答标签和可能的长度偏差。若 preferred 答案总是更长，模型可能学到冗长而不是真正的帮助性。

偏好标签可以表达帮助性、事实性、安全、风格和格式，但这些维度可能冲突。把多个维度粗暴压成一个排序，会丢失拒绝原因和业务优先级。对于高风险任务，应保留单独的安全和权限标签。

### 2.13.3 过程监督和可验证奖励

推理、数学、代码和工具轨迹常有中间步骤。过程标签可以指出哪一步错误，结果验证可以判断最终答案或执行结果。两者各有边界：过程标注成本高，结果验证可能无法定位错误；工具成功也不一定证明解释正确。

数据记录应区分：

| 字段 | 含义 |
| --- | --- |
| `outcome` | 最终答案、测试或工具结果 |
| `process` | 中间步骤、检查点或错误位置 |
| `verifier` | 验证器类型、版本和覆盖范围 |
| `failure` | 失败原因和是否可恢复 |

## 2.14 代码、数学和领域数据的特殊处理

### 2.14.1 代码数据

代码数据要同时处理内容、可运行性、安全和许可证。常见字段包括语言、路径、仓库、commit、许可证、依赖、测试状态和是否生成文件。应过滤密钥和内部地址，区分源代码、构建产物、vendor 目录和自动生成文件。

代码质量可以使用语法解析、静态检查、单元测试和执行沙箱，但执行结果受依赖、网络、随机性和资源限制影响。一个能运行的函数不一定有正确的业务语义；一个测试失败的项目也不一定是无价值数据。

### 2.14.2 数学和科学数据

数学数据要保留公式结构、假设、推导和答案之间的关系。只保留最后答案会削弱过程学习；把错误解析当作标准推导则会污染模型。科学文本还要保留单位、图表、引用和实验条件，避免从上下文中抽掉限定语句。

### 2.14.3 领域数据

领域数据最重要的不是“越专业越好”，而是版本、权威性和任务相关性。医疗、法律、金融和安全数据中的限定条件和适用范围不能在清洗时被删除。领域专家抽检应覆盖高影响结论、数字、否定词、时间和引用。

## 2.15 多语言与多模态数据

### 2.15.1 多语言公平

语言比例应按有效 token 和任务覆盖报告，而不是只按网页数。低资源语言常有更多噪声和更少高质量验证集，单纯上采样可能放大错误和重复。应同时报告语言级 loss、任务准确率、过滤率、重复率和人工抽样。

### 2.15.2 图文、音频文本和视频文本对齐

多模态样本至少要记录媒体 hash、文本来源、时间戳、裁剪或转码、对齐置信度和许可。caption 可能描述的是页面而不是图片，ASR 可能与视频时间轴错位，重复图片可能配有不同文本。模态间不一致应进入隔离或低权重数据，而不是被当作普通文本训练。

### 2.15.3 对齐错误的影响

模型可能学到错误关联：图片中的人名来自页面作者，视频标题描述的是频道而非画面，音频转写把说话人和背景音乐混在一起。多模态数据的质量评估必须分别检查模态内质量和跨模态一致性。

## 2.16 Tokenize、packing 和 shard：文件如何进入训练

### 2.16.1 Tokenize 不是数据工程的终点

第 3 章会专门讨论 tokenizer，但数据工程仍需记录 token 数、截断、未知 token、special token、文档边界和编码错误。原始字符数与有效训练 token 数不是同一指标。

### 2.16.2 Packing 的利用率

把多个短样本装入固定长度序列可以减少 padding。若分配给 batch 的总位置数为 `M`，真正参与 loss 的有效 token 数为 `V`，可以定义简单利用率：

~~~math
\eta_{\mathrm{pack}}
=
\frac{V}{M}
~~~

这里 `M>0`，`0\le V\le M`；空 batch 没有“100% 利用率”，应报告为未形成训练序列。利用率高不代表边界正确；如果没有 document mask，packing 可能让不相关样本互相泄漏上下文。应同时记录 padding 比例、跨文档 attention 规则和每个样本的起止位置。

### 2.16.3 Shard 和可恢复读取

大规模数据通常切成 shard，并配有 manifest、大小、hash、样本数、token 数和顺序。dataloader 需要知道 rank、worker、epoch 或 token 游标，否则重启可能重复读取或跳过样本。

数据 shard 的 hash 能证明“读到的是哪个文件”，不能证明文件内容正确或已授权；还需要把 shard 与上游 manifest 和训练 run 关联起来。

## 2.17 版本、删除和 lineage

### 2.17.1 数据版本

一个数据版本应绑定原始 manifest、解析器、过滤配置、去重配置、污染扫描版本、mixture、tokenizer 和输出 shard。版本号本身不够，必须能通过配置和 hash 重建。

### 2.17.2 删除请求和撤回

当来源要求删除、发现隐私泄露或许可证错误时，系统需要定位受影响的原始对象、派生样本、shard 和训练 run。删除文件只解决后续使用，不自动从已经训练出的模型中消除影响；模型层面的 unlearning 是另一个需要单独验证的研究和工程问题。

因此应保留删除清单、影响范围、处理时间、重新构建的数据版本和回归评估。不能只在最新目录里删掉一行记录。

### 2.17.3 版本差异审计

两版数据的差异应分开报告新增、删除、修改、来源变化和配比变化：

~~~math
\Delta D
=
\left(
\Delta D_{+},
\Delta D_{-},
\Delta D_{\mathrm{edit}},
\Delta D_{\mathrm{mix}}
\right)
~~~

这样训练结果变化时，才能做数据消融或回滚，而不是猜测“新数据可能更好”。

## 2.18 数据评估：从保留率走向训练收益

### 2.18.1 保留率不是质量证明

过滤后保留 80% 不代表比保留 40% 好。保留率只说明规则删掉了多少，不能说明留下的样本是否提高能力。需要结合：

1. 数据统计和人工抽样。
2. 小规模训练或 continued pretraining 对照。
3. per-domain loss 和目标任务。
4. 去重、质量阈值和 mixture 的消融。
5. 训练成本、记忆和安全指标。

### 2.18.2 数据消融

对一个数据子集 `S`，可以比较是否加入它时的目标指标：

~~~math
\Delta M_S
=
M(D\cup S)-M(D)
~~~

两项指标必须使用同一评估集、同一协议和相同的有效样本集合；其中任一侧缺少有效评估分母时，`\Delta M_S` 不应被报告为零。这个差值受随机种子、训练 token、优化器和数据顺序影响，不能被解释为该子集的绝对价值。更可靠的消融需要固定训练预算、重复运行并报告置信区间或误差范围。

### 2.18.3 数据价值和影响函数的边界

Influence Functions、Data Shapley 等方法可以帮助研究“哪些样本可能影响某个验证结果”，但它们通常依赖近似、计算成本和特定模型假设。不能把一个影响分数直接当成数据的真实市场价值、许可价值或删除后模型一定如何变化。

### 2.18.4 业务数据的有效性

最终要看目标任务：检索引用是否正确、代码测试是否通过、关键字段是否准确、工具参数是否安全、人工编辑是否减少。一个数据集在通用 benchmark 上没有提升，仍可能改善某个业务切片；反过来，平均分提升也可能伴随高风险任务退化。

    diversity = len(counts) / len(values)
    noise = sum(counts[token] for token in {"buy", "cheap", "offer"})
    domain_bonus = {"code": 0.18, "math": 0.18}.get(record["domain"], 0.12)
    score = 0.42 + 0.35 * diversity + domain_bonus - 0.12 * noise
    return max(0.0, min(1.0, round(score, 4)))


for threshold_name, threshold in {
    "quality_threshold": quality_threshold,
    "near_threshold": near_threshold,
    "contamination_threshold": contamination_threshold,
}.items():
    if not math.isfinite(threshold) or not 0 <= threshold <= 1:
        raise ValueError(f"{threshold_name} must be in [0, 1]")

for record in records:
    normalized = normalize(record["text"])
    record["quality"] = quality_score(record)
    record["hash"] = hashlib.sha256(normalized.encode()).hexdigest()

quality_kept = [r for r in records if r["quality"] >= quality_threshold]
quality_drop = {r["id"] for r in records if r["quality"] < quality_threshold}

seen = set()
exact_kept = []
exact_drop = set()
for record in quality_kept:
    if record["hash"] in seen:
        exact_drop.add(record["id"])
    else:
        seen.add(record["hash"])
        exact_kept.append(record)

near_kept = []
near_drop = set()
for record in exact_kept:
    current = shingles(record["text"])
    if any(
        (score := jaccard(current, shingles(old["text"]))) is not None
        and score >= near_threshold
        for old in near_kept
    ):
        near_drop.add(record["id"])
    else:
        near_kept.append(record)

benchmark_shingles = shingles(benchmark)
contamination_drop = set()
final_kept = []
for record in near_kept:
    score = jaccard(shingles(record["text"]), benchmark_shingles)
    record["contamination"] = None if score is None else round(score, 4)
    if score is not None and score >= contamination_threshold:
        contamination_drop.add(record["id"])
    else:
        final_kept.append(record)

domain_counts = Counter(record["domain"] for record in final_kept)
alpha = 0.5
raw_weights = {domain: count**alpha for domain, count in domain_counts.items()}
weight_total = sum(raw_weights.values())
if weight_total <= 0:
    raise ValueError("no records remain for mixture construction")
mixture = {
    domain: round(weight / weight_total, 4)
    for domain, weight in sorted(raw_weights.items())
}

checks = {
    "noise_removed": "noise_1" in quality_drop,
    "exact_duplicate_removed": "article_1_copy" in exact_drop,
    "near_duplicate_removed": "article_1_rewrite" in near_drop,
    "benchmark_leak_removed": "leak_1" in contamination_drop,
    "mixture_sums_to_one": abs(sum(mixture.values()) - 1.0) < 1e-3,
}

print("quality_drop=", sorted(quality_drop))
print("exact_drop=", sorted(exact_drop))
print("near_drop=", sorted(near_drop))
print("contamination_drop=", sorted(contamination_drop))
print("kept=", [record["id"] for record in final_kept])
print("mixture=", mixture)
print("checks=", checks)
assert all(checks.values())
assert jaccard(set(), set()) is None
try:
    shingles("text", 0)
except ValueError:
    pass
else:
    raise AssertionError("invalid shingle size must be rejected")
print("data audit toy: ok")
~~~

这个示例把五种统计分开：质量过滤、完全重复、近似重复、评估污染和域混合。空 shingle 集的 Jaccard 值在这里返回 `None`，表示没有可比较的 token 集，而不是把两个空对象误判为完全相同；空的最终保留集也不能生成混合权重。真实系统不应复用这里的阈值，因为样本很少、相似度很粗、没有许可和隐私检查；它的教学价值在于让读者看到每一步都产生了不同的丢弃原因和不同的分母。

## 2.20 常见故障：从训练现象回到数据

### 2.20.1 loss 下降但能力不变

可能是训练集与目标任务分布不同、验证集过于容易、重复数据过多、label mask 错误或 token 统计包含大量 padding。应检查 per-domain loss、有效 token、去重后规模和目标切片，而不是只增加训练步数。

### 2.20.2 某一语言或领域突然退化

优先检查语言识别、解析器、过滤规则、mixture 版本和 tokenizer token 数。保留率突变常比模型 loss 更早暴露数据 pipeline 回归。

### 2.20.3 benchmark 分数异常升高

检查训练快照与 benchmark 的 exact/near match、评估 prompt、答案规范化和数据发布日期。高分不一定是能力提升，也可能是污染或评估脚本变化。

### 2.20.4 模型输出变得同质化

可能来自重复数据、过度上采样小数据桶、合成数据比例过高、SFT 模板单一或偏好数据偏向固定长度。应统计 n-gram/embedding 多样性、来源比例、重复倍数和输出切片。

### 2.20.5 删除数据后仍能生成相关内容

删除训练文件只能阻止未来继续使用，不能自动证明模型已经忘记。需要区分记忆、公开知识、相邻文档和模型泛化，并设计针对性的 unlearning 或影响评估；不能凭一个生成样例下结论。

## 2.21 资料边界与延伸阅读

本章引用资料的证据层级不同：原始论文可以说明作者的数据构建和实验条件，数据集卡可以说明公开版本的组成与限制，源码和 manifest 可以确认本地文件，项目抽样和训练对照才能支撑当前项目的结论。

建议阅读：

- [Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer](https://arxiv.org/abs/1910.10683)：T5 与 C4 的数据处理和预训练设置。
- [The Pile: An 800GB Dataset of Diverse Text for Language Modeling](https://arxiv.org/abs/2101.00027)：多来源语料的组成、版本和限制。
- [Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)：GPT-3 的数据混合和大规模训练报告。
- [Deduplicating Training Data Makes Language Models Better](https://arxiv.org/abs/2107.06499)：去重与记忆、泛化和训练效果的关系。
- [Datasheets for Datasets](https://arxiv.org/abs/1803.09010)：记录数据来源、构成、预处理和适用范围的框架。
- [Common Crawl](https://commoncrawl.org/get-started)：公开网页语料的来源入口和抓取背景。
- [Hugging Face Dataset Cards](https://huggingface.co/docs/hub/datasets-cards)：数据集版本、使用说明和限制的文档实践。

这些资料不能替代版权、隐私和安全审查，也不能证明某个新下载快照与论文中的数据完全相同。阅读公开资料时，应同时记录版本、快照、处理规则、可复现实验和未知边界。

## 2.22 章节练习：把数据当作实验变量

### 练习一：建立来源 manifest

为网页、代码仓库、对话记录和一份 PDF 设计统一 manifest。列出来源、时间、许可、hash、解析器版本、语言、领域、隐私状态和删除入口，并说明哪些字段是事实、哪些字段是分类器预测。

### 练习二：比较过滤阈值

对同一语料设置三个质量阈值，报告总保留率、语言保留率、领域保留率、长度分布和人工抽样错误。解释为什么最高保留率不一定是最优结果。

### 练习三：实现 near dedup 抽样

使用 shingle 和 Jaccard 构造原文、转载、轻微改写、代码 fork 和独立同主题文章。改变阈值，记录误合并和漏合并，说明为什么生产系统需要候选召回和人工复核。

### 练习四：设计污染检测报告

选择一个公开 benchmark，构造 exact、改写、答案泄漏和代码测试泄漏样本。为每个命中保存 benchmark ID、相似度、匹配片段、训练版本和处理动作，并写出“未检出不等于不存在”的边界说明。

### 练习五：计算数据 mixture

有网页 100 亿 token、代码 10 亿 token、数学 1 亿 token。分别计算原始比例和 `alpha=0.5` 的温度采样比例，再计算各域在 200 亿训练 token 下的重复倍数。讨论低资源域上采样的收益和风险。

### 练习六：审计合成数据

构造一批教师模型生成的问答，记录教师版本、prompt、生成时间、验证器、人工抽检和错误类型。比较合成数据比例为 10%、30% 和 70% 时的重复度、答案正确率和任务覆盖。

### 练习七：设计删除影响回溯

给定一个被撤回的原始文档，画出它经过解析、去重、pack、shard、训练 run 和 checkpoint 的 lineage。列出文件删除、未来训练隔离、模型影响评估和重新训练之间的区别。

## 2.23 本章小结

数据工程把原始来源变成可训练、可追溯、可评估的 token。来源、许可、隐私和版本决定数据能否使用；解析和规范化决定结构是否保留；质量与风险过滤决定噪声和敏感内容如何处理；exact/near dedup 决定 token 是否被重复浪费；污染检测决定 benchmark 是否可信；mixture 决定有限训练预算倾向哪些能力。

合成数据、SFT、偏好和可验证轨迹需要单独记录 provenance、验证器和失败边界。多语言、多模态、代码和数学数据不能用一套粗糙规则处理。packing、shard 和数据游标则把已审计的样本变成训练系统真正读取的序列。

最终，数据质量不是一个总分，也不是一次过滤后就永久确定的属性。可信的数据结论需要 manifest、版本差异、抽样、污染检索、消融实验和目标任务评估共同支持。下一章进入 tokenizer 与数据格式，继续解释字符如何变成 token，以及这个转换如何影响成本、公平和模型能力。
