# 第五章：预训练目标与训练循环：从一个 batch 到一次更新

## 5.0 “预测下一个 token”如何变成真正的训练

预训练最常被压缩成一句话：给定前文，预测下一个 token。这句话描述了学习目标，却没有描述一个训练系统真正要做的工作。系统还要把文档变成 block，把 block 错开成 input 和 label，构造 causal 与 padding mask，计算有效 token 的损失，处理梯度累积和混合精度，更新参数，记录状态，并在中断后恢复。

初学者可以先记住一条链：

~~~text
原始 token block
  -> input_ids 与 shifted labels
  -> causal/padding 约束
  -> logits
  -> masked cross entropy
  -> backward
  -> 梯度累积与裁剪
  -> optimizer/scheduler update
  -> 日志、验证和 checkpoint
~~~

专家要进一步检查每一个分母：loss 是按 token、样本还是 batch 平均的？gradient accumulation 的最后一个窗口是否完整？padding 是否同时影响 attention 和 loss？packing 是否允许跨文档可见？validation loss 是否按有效 token 加权？checkpoint 是否保存了能连续更新所需的状态？

本章围绕 decoder-only causal language model 建立完整闭环。第三章已经主讲 tokenizer、样本 schema、label mask 和 packing 协议；这里沿着同一批输入继续推到损失分母、梯度和参数更新。代码示例使用一个极小的 token-to-logits 表，不试图复刻真实 Transformer：它会构造并打印 attention mask 与 causal mask，但模型没有 attention 运算，因此这两张 mask 不参与 logits 或 loss 的计算；代码实际演示的是外部 label shift、有效 pair 过滤、变长 micro-batch 的 token 加权和一次 SGD 更新。

## 5.1 自回归语言模型的概率目标

### 5.1.1 联合概率分解

给定 token 序列 `x_1,x_2,\ldots,x_T`，自回归模型把联合概率写成：

~~~math
p_\theta(x_1,\ldots,x_T)
=
\prod_{t=1}^{T}
p_\theta(x_t\mid x_{1:t-1})
~~~

`theta` 是模型参数。每个位置的预测只依赖前缀，所有位置的条件概率相乘得到整段序列概率。训练时通常最大化数据的对数似然，等价于最小化负对数似然。

### 5.1.2 Teacher forcing

训练时，第 `t` 个位置使用真实前缀作为条件，即使模型在前一个位置的预测并不正确。这种方式叫 teacher forcing，它让一整段序列可以并行前向计算。

推理时则不同：第一个 token 生成后，后续输入包含模型自己的结果。如果早期生成错误，错误会进入后续上下文，这就是训练和自由生成之间的 exposure bias。它不是 next-token 目标错误，而是 token-level teacher forcing 与 sequence-level rollout 之间的差异；后续的偏好训练、拒绝采样、过程监督和测试时计算可以从不同角度处理它。

### 5.1.3 Causal mask 的必要性

如果训练位置 `t` 可以看到未来 token `x_{t+1}`，模型就能直接读取答案，loss 会虚假地很低，但生成时没有未来 token 可用。causal mask 的约束是：

~~~math
C_{i,j}=\mathbf{1}[j\le i]
~~~

位置 `i` 只允许读取不晚于 `i` 的位置。实际 attention 会把不允许的位置加上一个很大的负数，再进入 softmax。

### 5.1.4 预训练目标不只有 next-token

Decoder-only causal LM 是本章训练循环的主线，但“预训练”并不等于“所有目标都对每个位置做 next-token prediction”。不同目标改变的是模型可以读取的上下文、要预测的 token 集合，以及目标序列如何构造；这些设计还会与 encoder-only、encoder-decoder、decoder-only 架构相互作用。比较方案时，必须把架构和训练目标分开记账。

| 目标 | 输入和监督信号 | 它主要补什么能力 | 主要代价或限制 |
| --- | --- | --- | --- |
| Causal LM | 位置 `t` 读取左侧前缀，预测下一个 token；通常所有有效 token 都贡献 loss | 自然地学习从左到右续写和开放式生成；训练与推理的因果方向一致 | 目标位置不能利用右侧文本；直接补全中间缺失片段时，右侧内容难以作为条件 |
| BERT-style MLM | 随机遮住输入中的少量 token，使用左右两侧未遮挡内容预测被遮位置；常见于 encoder-only | 用双向上下文做表示学习、分类或抽取式任务 | 只监督选中的位置；mask/noise 形态与下游生成分布不同，不能直接视为普通自回归联合概率 |
| T5 span corruption | 将连续 token span 替换成唯一 sentinel；decoder 只重建被删除的 span | 直接训练“给定缺口两侧证据，生成缺失内容”的条件生成 | 常与 encoder-decoder 一起使用；输入、目标拼接和 sentinel 规则都是数据协议的一部分 |
| UL2 Mixture-of-Denoisers | 混合短跨度恢复、前缀到后缀生成和高破坏率长目标恢复，并用模式标记选择任务 | 让一个模型同时接触局部补全、顺序生成和长目标重建等训练分布 | 目标混合比例和模式提示成为配方的一部分；任务更多不保证在任意模型与预算上都更好 |
| Fill-in-the-Middle（FIM） | 把原序列的 prefix、suffix、middle 重排为带边界标记的序列，仍使用自回归 next-token loss | 给 decoder-only 模型加入“利用左右文补中间”的代码/文本补全能力 | 它依赖正确的特殊 token、样本重排和结束标记；不是无损地把 causal decoder 变成双向 encoder |
| Multi-Token Prediction（MTP） | 主干表示同时或分深度预测多个未来位置，并按各预测距离汇总交叉熵 | 给同一上下文增加较远未来位置的监督；特定 head 也可为推测解码提议候选 | head 结构、未来距离权重和尾部有效 label 数都要定义；额外预测层与验证路径有成本，MTP 本身不保证推理加速 |
| Masked Diffusion Language Model（离散扩散语言模型） | 按噪声步把部分 token 替换为 mask，再从带噪序列估计原 token；目标通常只计被破坏位置，并按噪声过程加权 | 通过多轮去噪恢复序列，不受单一左到右生成顺序限制 | 目标含噪声/时间步权重，loss 不等同于普通 causal token mean；迭代采样要多次前向，需单独计算质量与成本 |

T5 的 span corruption 可以用一条具体样本看清。原句为 `Thank you for inviting me to your party last week .`，一个训练变换可以得到输入 `Thank you <X> to <Y> week .`，目标为 `<X> for inviting me <Y> your party last <Z>`。模型只需在 decoder 端生成被移除的片段及 sentinel，而不是再生成完整原句。T5 论文在固定 15% token corruption 下比较平均 span 长度 2、3、5、10；作者报告平均长度 3 在多数非翻译 benchmark 上相对 i.i.d. corruption 有小幅且统计显著的提升，同时短目标减少 decoder 侧序列长度。这个结果绑定论文中的 T5/C4 训练与评测设置，不能据此断言 span corruption 在所有规模和任务上胜过 causal LM。[T5 §3.3.4](https://arxiv.org/abs/1910.10683)

UL2 把几种学习信号放进同一训练配方。R-denoiser 接近 T5 的短跨度破坏（约 15% token）；S-denoiser 是 prefix LM，给定前缀预测后缀；X-denoiser 使用更长 span 或更高破坏率，让模型从相对有限的上下文恢复长目标。原论文的配方将七种 denoiser 近似均匀混合。它在约 167M 参数 decoder、335M 参数 encoder-decoder、C4 上约 32B 预训练 token 的实验中，报告 UL2 encoder-decoder 相对 T5 span-corruption 基线的跨任务归一化总分提高 43.6%，相对 GPT-like causal decoder 基线提高 76.1%。这是作者对九项异质任务做等权归一化后的总分，不是单项准确率提升 43.6%；模型结构、C4、训练量和评测都固定在原论文设置，不能据此外推到大规模生产配方。该研究的一个重要启发是：目标函数和网络架构不是同一个变量，选择时要把二者分别控制。[UL2 §3.1、§4.2–4.3](https://arxiv.org/abs/2205.05131)

FIM 则保留 decoder-only 因果训练，只改变部分训练样本的 token 顺序。把原序列分成 `prefix=A`、`middle=B`、`suffix=C`，一种 PSM 序列化方式是：

~~~text
训练序列：<PRE> A <SUF> C <MID> B <EOT>
推理提示：<PRE> A <SUF> C <MID>
目标生成：B <EOT>
~~~

论文在 prefix、suffix、middle 上都保留自回归 loss，并混合普通从左到右样本。其消融中，6 个大模型在 50B token 训练设置下比较 0%、25%、50%、75%、90% 和 100% FIM rate：最高到 90% 时，作者没有观察到从左到右评测明显退化；100% FIM 则使普通自回归测试 loss 变差。与此同时，FIM pass rate 随 FIM 比例增加而提高，FIM perplexity 却未能充分反映这项变化。因此代码补全不能只看普通 PPL，还要在固定任务和采样配置下跑填空通过率。该结果是论文在特定代码/语言语料、模型规模和训练预算上的消融，不是所有语料均可不付成本地加入 90% FIM。[FIM §4.2](https://arxiv.org/abs/2207.14255)

这些标记在上面的序列示意中是可读占位名，真实训练要在 tokenizer 中登记专用 token，并固定各自的 token id、loss mask 和结束条件。FIM 变换发生在文档级还是 pack 后的 context 级也会影响样本：论文的代码模型消融发现 context-level FIM 的填空采样通过率持续高于 document-level FIM，但对应的 FIM perplexity 差异约只有 `0.001` nats/token。文档先切块再做 FIM 时，要保证 prefix、suffix 和 middle 没有因截断丢失；这属于数据管线正确性，不能靠增加 FIM rate 补救。[FIM §3.2、§4.4](https://arxiv.org/abs/2207.14255)

这些目标对应不同的使用场景，而不是一张可脱离设置的排行榜：开放式续写以 causal LM 为直接基线；代码编辑器的中间补全可以评估 FIM；依赖右侧证据的缺口恢复可考虑 span corruption；需要一个预训练模型覆盖多种条件生成形式时，可以研究混合目标。决策时至少固定架构、训练数据、有效目标 token 数、总计算预算和验证集，并为每种目标选合适的任务指标。Causal PPL、只计算遮挡 token 的 loss、扩散模型的加权变分目标和 FIM pass rate 的分母及语义不同，不能拿裸数值互相排序。

MTP 更适合作为附加监督来理解，而不是“模型一次就正式输出多个 token”。设主干在位置 `t` 的表示为 `h_t`，第 `k` 个 head 给出 `p_{t,k}`，目标是 `x_{t+k}`；只在该预测距离有目标的位置计 loss：

~~~math
L_k=\frac{\sum_t m_{t,k}\left[-\log p_{t,k}(x_{t+k})\right]}{\sum_t m_{t,k}},\qquad
L_{\mathrm{total}}=L_{\mathrm{NTP}}+\sum_{k=2}^{K}\beta_k L_k
~~~

`m_{t,k}` 表示位置 `t` 的第 `k` 步目标是否有效，`\beta_k` 是该预测距离的训练权重；不同实现可能把各步损失求和或平均，必须按配置固定分母。用序列 `[BOS,A,B,C,D]` 做两个预测距离：上下文 `[BOS]` 预测 `(A,B)`，`[BOS,A]` 预测 `(B,C)`，`[BOS,A,B]` 预测 `(C,D)`，`[BOS,A,B,C]` 只能预测 `(D,·)` 中的 `D`。因此第一步有 4 个有效目标，第二步有 3 个，共 7 项监督；相邻 head 会重复监督同一个 token，但条件上下文不同。末端第二步没有真实目标的位置要屏蔽对应 head 的 loss，不能把越界位置或 PAD 当作未来 token 来预测。

多 token 头的结构也不唯一。Gloeckle 等人的方案用共享主干和彼此独立的未来预测头；DeepSeek-V3 技术报告则用串联的 MTP 模块逐深度预测，并在相邻深度间保持因果链。两者都可以把额外 head 丢弃而按普通 causal LM 推理，也可以在有对应 target 验证实现时将候选接入 speculative decoding；训练目标本身不保证实际接受长度或端到端加速。[Gloeckle et al.](https://arxiv.org/abs/2404.19737)；[DeepSeek-V3 §2.2](https://arxiv.org/abs/2412.19437)。推测解码中的候选验证和拒绝回滚由[第二十四册 MTP 章节](../../book-24-llm-inference-engine/chapters/61-mtp与多token预测.md)继续主讲。

离散扩散则改变了序列破坏方式和生成顺序：在某个噪声步把输入的一部分替换为 `[MASK]`，训练网络恢复原 token，采样时再经多轮去噪逐步填回序列。它虽然可能把同一轮的多个 mask 位置并行送入模型，却不是把 causal LM 的上三角 mask 简单改成全可见；噪声分布、时间步加权和反向采样器共同定义目标。本章只把它作为与自回归目标不同的一条路线；mask 过程、ELBO 数例和迭代成本已在[第二册 Transformer 架构进阶的离散扩散节](../../book-02-advanced-100/chapters/02-transformer架构进阶.md)完整说明。[Masked Diffusion Language Models](https://arxiv.org/abs/2406.07524)

## 5.2 Label shift：模型到底在每个位置预测什么

第三章已从数据协议角度说明 labels 如何存储、何时内部 shift、哪些位置要设为 ignore；本节只追踪它进入 causal loss 后的索引关系，避免把“字段同位置”误读成“模型预测同位置”。

### 5.2.1 一个具体序列

给定 token：

~~~text
[10, 20, 30, 40, 50]
~~~

取长度为 4 的输入窗口时：

~~~text
input  = [10, 20, 30, 40]
label  = [20, 30, 40, 50]
~~~

含义是：

~~~text
看到 10          -> 预测 20
看到 10, 20      -> 预测 30
看到 10, 20, 30  -> 预测 40
看到 10, 20, 30, 40 -> 预测 50
~~~

若训练器已经外部错开，模型输出 `logits[b,t,:]` 对应 `labels[b,t]`，而不是存储时同一位置的原始 input token。这个约定与另一类“labels 仍和 input 同长、模型内部 shift 一位”的 API 等价，但只能选一个地方做 shift。比如用 `[BOS, A, B, EOS]` 建立外部训练对，输入为 `[BOS,A,B]`、目标为 `[A,B,EOS]`，有效监督数是 3；若把同一目标交给会内部 shift 的模型再手动错开，模型会跳过 `A` 或把 EOS 位置移错。off-by-one 是最容易让训练“能运行但学错目标”的错误之一。

### 5.2.2 张量形状

常见输入形状是：

~~~text
input_ids:      [B, T]
labels:         [B, T]
attention_mask: [B, T]
logits:         [B, T, V]
~~~

有的模型在内部完成 shift，有的训练器在外部完成 shift。代码 review 时不能只看变量名，要确认 logits 的时间位置和 label 的时间位置究竟如何对应。

### 5.2.3 文档 block 的边界

若原始 token 流为 `z_1,\ldots,z_T`，一个长度为 `T-1` 的训练对可以写成：

~~~math
x=(z_1,\ldots,z_{T-1}),
\qquad
y=(z_2,\ldots,z_T)
~~~

如果 block 中包含 EOS 和下一个文档的开头，那么 EOS 后面的下一个 token 仍然可能成为一个合法预测目标。这是否合理取决于预训练是否把整个语料视为连续流；如果要求文档独立，就需要 document-level mask 或独立样本边界。

## 5.3 Cross Entropy：最大似然的可计算形式

### 5.3.1 单个位置

模型输出 logits `a_{b,t,v}`，对词表位置 `v` 做 softmax。真实目标为 `y_{b,t}` 时，单位置损失为：

~~~math
\ell_{b,t}
=
-\log p_\theta(y_{b,t}\mid x_{b,1:t})
~~~

展开 logits：

~~~math
\ell_{b,t}
=
-a_{b,t,y_{b,t}}
+\log\sum_{v=1}^{V}\exp(a_{b,t,v})
~~~

实际实现应使用数值稳定的 cross entropy，而不是先手动 softmax 再取 log；后者在极大或极小 logits 下容易溢出。

手算一个三类位置：logits 为 `[2,1,0]`，真实类别是中间项。先减去最大值 2，得到 `[0,-1,-2]`；指数为 `[1,0.3679,0.1353]`，分母约为 `1.5032`，真实类别概率约为 `0.3679/1.5032=0.2447`。因此该位置的交叉熵为 `-ln(0.2447)≈1.4076` nat。再给一个均匀 logits `[0,0,0]` 的有效位置，损失是 `ln 3≈1.0986` nat；若第三个位置的 label 是 `-100`，batch token mean 为 `(1.4076+1.0986)/2≈1.2531`，而不是把忽略位也放进分母得到的 `0.8354`。这个小账本同时检查了稳定 softmax、目标类别和有效 label 分母。

### 5.3.2 Masked batch loss

padding、文档截断和 assistant-only SFT 都会产生不应参与损失的位置。令 `m_{b,t}` 为有效 label 指示量：

~~~math
L
=
\frac{
\sum_{b,t}m_{b,t}\ell_{b,t}
}{
\sum_{b,t}m_{b,t}
}
~~~

这个式子只在 `\sum_{b,t}m_{b,t}>0` 时有定义。为避免程序报错而使用 `max(\cdot,1)` 是常见实现技巧，却不能把全 padding、全截断或全 ignore 的 batch 变成零损失样本；它们应跳过并记录为数据或模板异常。分母是有效 token 数，而不是固定的 `B*T`。如果把 padding 算入分母，短样本的 loss 会被稀释；如果不同 batch 的有效 token 数差异很大，直接平均 batch mean 也会改变每个 token 的权重。

### 5.3.3 Ignore index

PyTorch 生态常用 `-100` 表示 label 不参与 cross entropy。它不是词表 token，也不会被送入 embedding；它只是 loss 函数的忽略标记。attention mask 和 label mask 仍然要独立处理。

### 5.3.4 困惑度

如果 validation loss 使用自然对数，困惑度为：

~~~math
\mathrm{PPL}=\exp(L_{\mathrm{val}})
~~~

PPL 依赖 tokenizer、数据分布、规范化、上下文长度和 token 分母。不同 tokenizer 的 PPL 不能直接比较；PPL 能描述语言建模不确定性，但不能替代代码执行、事实性、安全和业务任务评估。

## 5.4 三种 mask 不是一回事

第三章 3.7.3 与 3.9 已完整说明这些 mask 在 tokenizer、chat template 和样本协议中的位置；这里把它们放回一个训练 batch，重点看它们分别改变上下文和 loss 的哪一项。

### 5.4.1 Causal mask

causal mask 控制当前位置是否能看未来输入。长度为 4 时，允许关系是：

~~~text
1 0 0 0
1 1 0 0
1 1 1 0
1 1 1 1
~~~

它是模型结构的因果约束。

### 5.4.2 Padding attention mask

当 batch 内序列长度不同时，用 PAD 补齐。输入位置的可见性可以写成：

~~~math
a_{b,t}=\mathbf{1}[x_{b,t}\ne z_{\mathrm{pad}}]
~~~

它避免模型读取占位符。causal 和 padding 约束可以共同作用，但概念不同：前者限制时间方向，后者识别无效输入。

### 5.4.3 Label mask

label mask 决定某个目标位置是否贡献 loss：

~~~math
m_{b,t}=\mathbf{1}[y_{b,t}\ne -100]
~~~

在预训练中，真实 token 通常都参与损失；在 SFT 中，system/user 可能只作为条件，assistant 才是目标；在 packed 数据中，padding label 必须忽略。

三者不能互换：

| mask | 控制什么 | 错误后果 |
| --- | --- | --- |
| causal | 能否看到未来 | 训练偷看答案 |
| padding attention | 是否读取 PAD | 虚假上下文 |
| label | 是否计算该目标 | loss 分母和监督错位 |

以右 padding 的 SFT 样本 `[BOS,user,answer,EOS,PAD]` 为例：causal mask 规定第 `t` 行只能读 `0…t` 列；padding attention mask 让 PAD 不成为可读的 key；label mask 则可以把 BOS、user 设为 `-100`，只监督 `answer` 和 `EOS`。所以 user token 虽不参与 loss，仍是生成 answer 所需的上下文；PAD 即使被从 loss 排除，若未从 key 中屏蔽，仍可能污染真实位置的 attention。若把它们压成一个布尔张量，shape 虽可能广播成功，语义却无法逐项审计。

## 5.5 Packing：提高 token 利用率但保留边界

第三章 3.10 已从样本协议和 attention kernel 讲 packing 的主机制；本节沿着训练目标补看它对目标数量、跨文档 label 和注意力可见范围的影响。

### 5.5.1 为什么 packing

如果每个短文档单独补齐到固定长度，大量位置只包含 PAD。packing 把多个文档编码后拼成固定长度 block：

~~~text
doc1 <eos> doc2 <eos> doc3 <eos> ...
          -> fixed-length blocks
~~~

它可以提高有效 token 利用率和 GPU 吞吐，但把多个文档放入同一块后，边界语义必须被明确处理。

### 5.5.2 EOS 不会自动切断 attention

令第 `i` 个文档编码并追加 EOS：

~~~math
s_i=T(d_i)\oplus[z_{\mathrm{eos}}]
~~~

拼接为：

~~~math
S=s_1\oplus s_2\oplus\cdots\oplus s_n
~~~

再按长度 `C` 切块。EOS 让模型看见一个边界事件，但普通 causal attention 仍允许后文看到此前 token。若训练目标是连续网页流，这可能是有意行为；如果文档必须独立，需要 document mask 或不把它们放到同一个可见区域。

### 5.5.3 Packing 利用率和截断

block 总位置为 `M`，参与 loss 的有效 token 为 `V`，简单利用率是：

~~~math
\eta_{\mathrm{pack}}=\frac{V}{M}
~~~

这里 `M>0` 且 `0\le V\le M`；空数据没有“利用率为 100%”的解释，应单独报告为没有形成训练 block。还要记录 EOS 数、文档起止位置、padding 数、被截断文档和有效 label 数。只报告 block shape 和 tokens/s，无法判断是否把边界或答案截掉了。

假设两篇独立文档各有三个 token `[A,B,EOS]` 与 `[C,D,EOS]`，每篇单独补到 4 个位置时共分配 8 个位置，其中 2 个是 PAD；若 mask 掉两篇各自的首 token，监督目标总数为 `2+2=4`，按有效目标计的利用率为 `4/8=50%`。把两篇紧密拼成一个 6-token block 并在文档边界隔离 attention，同时屏蔽跨界的 `EOS→C` 目标，则有效目标仍是 4，利用率为 `4/6≈66.7%`。若忘了屏蔽跨界 label，分母会变成 5；若忘了 document mask，第二篇还能读取第一篇历史。packing 提升的是张量利用率，不会自动保证 loss 目标和上下文边界与原样本相同。

## 5.6 一个 optimizer update 的完整顺序

一次训练更新可以拆成：

1. dataloader 取一个 micro-batch。
2. 把 input、labels 和 attention mask 移到设备。
3. 前向得到 logits 或 loss。
4. 按有效 token 归一化 loss。
5. 反向得到梯度。
6. 处理梯度累积、unscale 和 gradient clipping。
7. optimizer 更新参数。
8. scheduler 更新学习率。
9. 清理梯度并记录日志。

简化的参数更新可以写成：

~~~math
\theta_{s+1}
=
\mathrm{Optimizer}
\left(\theta_s,\nabla_\theta L_s,\eta_s\right)
~~~

`s` 是 optimizer step，`eta_s` 是学习率。真实 optimizer 还会维护动量、二阶矩、权重衰减和混合精度状态，因此 checkpoint 不能只保存 `theta` 就声称可以严格继续训练。

把顺序当作状态转移来读：一次 optimizer update 消费一个完整的 accumulation window；梯度应先还原到真实尺度，再做范数裁剪，随后更新参数；scheduler 若按 optimizer step 计数，就在这次参数更新后推进一次。若把 scheduler 放进每个 micro-step，累计 4 个 micro-batch 就会把学习率日程推进 4 次，却只更新一次参数。日志和 checkpoint 中的 step 因而应说明它数的是 micro-step 还是 optimizer step。

若把 `optimizer.step()` 也错放在每个 micro-step 中，训练就不再是“用小 batch 计算一次大 batch 更新”。以 Adam 为例，一阶、二阶矩会随每次调用递推，参数在窗口中途改变后，后续 micro-batch 的前向和梯度也基于另一组参数；即使把这些梯度事后平均，状态轨迹仍不同。正确顺序是让窗口内的反向只累积目标梯度，待有效 token 分母、精度还原和裁剪都按整窗处理后，再更新一次参数和对应的优化器状态。Adam 的状态递推与学习率日程将在[下一章](06-优化器与学习率策略.md)展开。

### 5.6.1 Gradient clipping

如果所有参数梯度组成向量 `g`，全局范数裁剪为：

~~~math
g'
=
g\cdot
\min\left(1,\frac{\tau}{\lVert g\rVert_2+\epsilon}\right)
~~~

`tau` 是最大范数。裁剪限制单步更新，但不能修复错误数据、label shift、过大学习率或 NaN。在 FP16 + GradScaler 中，应先 `unscale` 梯度，再计算范数和裁剪。

例如梯度向量 `g=(6,8)`，其二范数是 `sqrt(6²+8²)=10`。若阈值 `tau=5`，裁剪系数为 `5/10=0.5`，得到 `g'=(3,4)`，方向不变、范数变成 5。若当前参数为 `theta=(1,-1)` 且 SGD 学习率为 `0.1`，裁剪后更新为 `(1,-1)-0.1(3,4)=(0.7,-1.4)`；未裁剪则是 `(0.4,-1.8)`。这个小算例只说明范数裁剪怎样限制一步的梯度幅值；它没有修正梯度方向，也不能据此判断阈值是否适合真实模型。

## 5.7 Gradient accumulation：用时间换显存

### 5.7.1 Effective batch

每张 GPU 的 micro-batch 样本数为 `B_micro`，序列长度为 `T_seq`，梯度累积次数为 `A`，数据并行规模为 `P_dp`，一次 optimizer update 的理想 token 数为：

~~~math
B_{\mathrm{tok}}
=
B_{\mathrm{micro}}T_{\mathrm{seq}}AP_{\mathrm{dp}}
~~~

这个理想式要求每个因子为正整数，并且 `T_seq` 是实际参与训练的 token 长度而非含 padding 的张量宽度。它用多个小的 forward/backward 累积出更大的 effective batch，而不是把所有样本同时放进显存。梯度累积增加 wall-clock 时间，且不一定与真正的大 batch 完全等价：dropout、动态 padding、归一化统计、通信时机和数据顺序都可能不同。

### 5.7.2 等 token micro-batch

若每个 micro-batch 的有效 token 数相同，平均梯度可以写成：

~~~math
g
=
\frac{1}{A}
\sum_{a=1}^{A}\nabla_\theta L_a
~~~

伪代码为：

~~~text
optimizer.zero_grad()
for micro_step, batch in enumerate(loader):
    loss = model(**batch).loss
    (loss / accumulation_steps).backward()
    if (micro_step + 1) % accumulation_steps == 0:
        optimizer.step()
        scheduler.step()
        optimizer.zero_grad()
~~~

### 5.7.3 变长 micro-batch 的分母

如果第 `a` 个 micro-batch 的有效 label 集合是 `M_a`，按 token 归一化的一次窗口损失应为：

~~~math
L_{\mathrm{window}}
=
\frac{
\sum_{a=1}^{A}\sum_{t\in M_a}\ell_t
}{
\sum_{a=1}^{A}|M_a|
}
~~~

该窗口必须至少包含一个有效目标，即 `\sum_a|M_a|>0`；若窗口全为空，应跳过 update 并记录，而不是调用 optimizer 进行一次零梯度更新。简单地把每个 micro-batch 的 mean loss 除以 `A`，隐含了每个 micro-batch 有相同有效 token 数。对变长 batch，更严格的实现要累积未归一化 loss 和 token count，或使用训练框架提供的正确归一化接口。

令第 `a` 个 micro-batch 有 `n_a=|M_a|` 个有效目标，`g_a` 是该 micro-batch 按 token 求平均后的梯度，则窗口梯度应为：

~~~math
g_{\mathrm{window}}
=
\frac{\sum_a n_a g_a}{\sum_a n_a}
~~~

例如一个窗口由 2 个有效 token 和 4 个有效 token 组成，正确结果是 `\frac{2}{6}g_1+\frac{4}{6}g_2`，而不是 `\frac{1}{2}g_1+\frac{1}{2}g_2`。前者与把 6 个 token 放进同一 batch 后计算 token mean 一致；后者会把短 micro-batch 中每个 token 的权重放大。若损失已经按 `reduction="sum"` 返回，则累加各 micro-batch 的 loss/梯度和，再除以窗口总 token 数。

把这个差别算成二维梯度：若 2-token micro-batch 的 token-mean 梯度为 `g_1=(2,0)`，4-token micro-batch 的 token-mean 梯度为 `g_2=(0,4)`，则完整窗口的 token mean 是 `(2/6)g_1+(4/6)g_2=(2/3,8/3)`；等 batch 权重给出 `(1/2)g_1+(1/2)g_2=(1,2)`。第二个分量虽然只来自较长 micro-batch，却在错误算法里被压低；第一个分量则被相对放大。这个推导假设 `g_1`、`g_2` 都是各自有效 token 的平均梯度，若框架返回 loss sum，应直接加和后除以 6。

梯度裁剪也要放在累积窗口形成之后，因为裁剪是非线性变换，不能与按 token 加权交换。沿用 `g_1`、`g_2`，正确的窗口梯度为 `(2/3,8/3)`，范数约为 `2.7487`；若阈值 `tau=1`，整窗裁剪得到约 `(0.2425,0.9701)`。若先把两个 micro-batch 的均值梯度分别裁剪到范数 1，再按 token 数加权，则结果是 `(1/3,2/3)`，与整窗裁剪不同。前者遵循“先求本次更新对应的有效 token 平均梯度，再限制这一步幅度”的定义；混合精度下仍要先 unscale，再对累积后的真实梯度裁剪。由此可见，单独记录每个 micro-batch 的梯度范数不足以说明最终 optimizer update 的梯度，诊断还要核对裁剪发生在何处、使用哪种范数以及是否跨 rank 汇总。

数据并行还要把 rank 间分母纳入计算。DDP 默认对各 rank 的梯度做平均；如果每个 rank 的有效 token 数不同，先各自求 token mean 再平均 rank，会让 token 较少的 rank 权重过大。简单 DDP 且没有框架额外缩放时，可先汇总整个 accumulation window 在所有 rank 上的有效 token 总数 `N`，每个 rank 反传本地 loss sum 乘以 `P/N`，其中 `P` 是 data-parallel world size；DDP 的 rank 平均之后，得到全局 token mean 梯度。Accelerate 或 Transformers 的 accumulation helper 可能还会自动除以累积步数、处理 label shift 和 DDP 平均，所以实际调用必须按所用版本的 loss API 核对，不能把这条简化公式叠加到框架缩放上。

例如两个 rank 的有效目标分别为 2 和 4 个，`P=2`、全局 `N=6`。rank 0 的本地 loss-sum 梯度乘 `P/N=1/3`，rank 1 同样乘 `1/3`；DDP 再平均两 rank，结果为 `(1/2)(G_0/3+G_1/3)=(G_0+G_1)/6`，恰好是把 6 个 token 放在一起求均值。若先分别除以 2 和 4 再由 DDP 等权平均，两个 rank 就各占一半，而不是各 token 等权。此例只适用于默认梯度平均且没有其他框架缩放的简单 DDP。

最后一个不完整 accumulation window 也要明确处理：按实际有效 token 归一化、补齐，或丢弃并记录。默默把它当成完整窗口会改变 global batch 和学习率 schedule 的口径。

## 5.8 Mixed precision：速度和数值范围的交换

### 5.8.1 FP16 与 BF16

FP16 能节省显存并提高部分硬件吞吐，但动态范围较小，可能出现 underflow 或 overflow；BF16 指数位更多，动态范围接近 FP32，训练大模型时通常更容易处理尺度，但尾数精度不同，仍依赖硬件和 kernel。

低精度不等于没有数值风险。学习率、异常 batch、softmax logits、归一化、optimizer state 和自定义 kernel 仍可能产生 Inf/NaN。

### 5.8.2 Loss scaling

FP16 常用 loss scaling，把 loss 放大：

~~~math
\widetilde{L}=sL
~~~

反向得到放大梯度，再在更新前除回：

~~~math
g=\frac{1}{s}\nabla_\theta\widetilde{L}
~~~

检测到 Inf/NaN 时，动态 scaler 会跳过这次更新并调整 `s`。梯度裁剪必须放在 unscale 之后，否则阈值对应的是缩放后的梯度。

用一个纯算术例子看出顺序影响：未缩放梯度 `g=(0.006,0.008)` 的范数为 `0.01`，loss scale `s=128` 后梯度为 `(0.768,1.024)`、范数为 `1.28`。若裁剪阈值是 `0.02`，正确顺序先 unscale，真实梯度范数 `0.01` 未超过阈值，因此保持原值；错误地先对放大后的梯度裁剪，会把它缩到范数 `0.02`，随后再除以 128，真实更新范数只剩 `0.00015625`。这个例子中的数值只是演示尺度关系；实际是否下溢、溢出取决于格式、硬件和算子，BF16 通常不采用同一套动态 loss scaling 流程。

loss scaling 只把梯度整体乘上可逆的常数，用来把小梯度移到低精度格式更容易表示的数值范围；它不会修正监督位置、有效 token 分母或不同样本的权重。若一个 accumulation window 中所有 micro-batch 使用同一个 scale `s`，把它们按目标权重累积后再除以 `s`，代数上仍得到原窗口梯度。若同一窗口里各 micro-batch 的 scale 不同，却把总梯度只除以最后一个 scale，各部分就会留下不同的比例误差。因此要把 scale 的更新点、unscale 的时点和梯度累积边界当作同一套状态约定，并在日志中记录 scale 与跳过更新的计数；否则“loss 数值正常”仍可能掩盖更新幅度被改变。

### 5.8.3 数值监控

训练中应记录 loss、梯度、activation、logits、overflow、scaler 状态和跳过的 update。NaN 出现时保存对应 batch、数据来源、序列长度、mask、最近 checkpoint 和硬件/rank 信息；仅保存“step 1234 出现 NaN”不足以复现。

## 5.9 Validation：按有效 token 汇总，而不是平均 batch

验证不进行反向传播和参数更新，但必须使用与训练相同的 tokenizer、label shift、mask 和数据版本口径。伪代码：

~~~text
model.eval()
loss_sum = 0.0
valid_tokens = 0

with torch.no_grad():
    for batch in val_loader:
        outputs = model(**batch)
        count = valid_prediction_target_count(batch)
        loss_sum += outputs.loss.item() * count
        valid_tokens += count

val_loss = loss_sum / valid_tokens if valid_tokens > 0 else None
model.train()
~~~

空 validation 集或 labels 全为 ignore 时，`val_loss=None` 表示没有有效评估分母；不能把它显示为 `0` 后与历史曲线比较。如果 `outputs.loss` 已经是按有效 token 平均，这种加权汇总才成立；若框架返回的是 batch mean 或 sum，需要先确认 reduction 语义。变长 validation batch 直接平均 batch loss，会让短 batch 和长 batch 权重相同。

`valid_prediction_target_count` 必须按模型的 label API 实现：本章 toy 代码已经把 `input` 和 `label` 外部错开，所以数 `labels != -100`；若模型内部执行 causal shift，通常要数 shift 后的有效目标（例如 Hugging Face causal LM 约定中的 `labels[..., 1:] != -100`），避免把没有前置预测位置的首 label 算进分母。

验证的 token 加权也可以直接手算。假设 batch A 有 2 个有效目标、平均 loss 为 `0.5` nat；batch B 有 4 个有效目标、平均 loss 为 `1.0` nat。全局验证 loss 是 `(2×0.5+4×1.0)/(2+4)=5/6≈0.8333` nat，困惑度为 `exp(5/6)≈2.30`。直接平均两个 batch mean 得到 `0.75` nat、PPL `exp(0.75)≈2.12`，相当于让每个 batch 权重相同而非每个 token 权重相同。若 B 的长度或数据域不同，这种偏差还会随 batch 组成变化，因此应先累计未归一化损失与同一口径的有效目标数。

validation 至少要看总体 loss、per-domain loss、长度切片、语言切片和目标任务。PPL 是语言模型信号，不等于代码执行率、工具调用正确率、事实性或安全性。

## 5.10 日志：让一次更新可解释

一条训练日志最好同时关联：

~~~text
run_id, global_step, micro_step, data_cursor,
effective_tokens, train_loss, learning_rate,
grad_norm, clip_ratio, overflow_count,
tokens_per_second, dataloader_time, checkpoint_id
~~~

四类健康信号需要分开看：

| 类别 | 代表指标 | 可能定位的问题 |
| --- | --- | --- |
| 优化 | train/val loss、lr、grad norm | 学习率、目标、过拟合 |
| 数值 | NaN、Inf、overflow、scaler | 精度、异常输入和 kernel |
| 系统 | tokens/s、GPU、数据等待、通信 | dataloader、网络、节点和 kernel |
| 数据 | 有效 token、长度、来源、mask 比例 | 过滤、packing 和 label 错误 |

例如 loss 不下降可能是学习率过低，也可能是 label 全为 ignore；tokens/s 下降可能是序列变长，也可能是 checkpoint 写盘；validation 变好可能来自数据泄漏，也可能来自真实泛化。只有把这些字段放在同一个 run 和版本关系里，才能分析变化。

日志字段的分母同样要明确。假设每个 micro-batch 有 2,048 个有效目标，累积 4 次后才做一次参数更新，那么这次更新对应 `8,192` 个有效 token；若系统吞吐是按 16,384 个输入槽位计算，就把 padding/ignore token 也算进了速率。记录 `micro_step`、`optimizer_step`、`effective_tokens` 和计时窗口后，才能区分“多做了几次前向”与“多更新了几次参数”，也能把 scheduler 曲线和训练速度放在同一口径上。

## 5.11 Checkpoint：保存权重和保存训练状态

### 5.11.1 三类状态

一个推理权重快照通常至少有：

1. model weights。
2. model config。
3. tokenizer 与模板。

一个可恢复的训练快照还需要：

1. optimizer state。
2. scheduler state。
3. scaler state。
4. RNG state。
5. global step 和 token cursor。
6. 数据版本、代码版本和硬件/并行配置。

可以抽象为：

~~~math
C_s
=
(\theta_s,o_s,u_s,q_s,r_s,d_s,c_s)
~~~

其中 `theta` 是权重，`o` 是 optimizer state，`u` 是 scheduler state，`q` 是 scaler state，`r` 是随机状态，`d` 是数据位置，`c` 是配置和版本。只保存 `theta` 可以用于推理，但不能保证从相同的优化状态继续训练。

### 5.11.2 恢复验证

恢复不能只测试文件能否打开。小规模验证应比较连续运行和“保存后恢复运行”的：

1. optimizer step 和学习率。
2. 下一批数据和有效 token。
3. 参数摘要、loss 和梯度。
4. dropout/随机增强的状态。
5. 吞吐、显存和 checkpoint 读取行为。

如果数据 cursor 或 RNG 没有恢复，训练可能重复样本或跳过样本；如果 scheduler 没恢复，学习率曲线可能跳变；如果 scaler 没恢复，FP16 的 update 行为可能改变。

设一次合成训练在 `optimizer_step=1200` 保存，数据 cursor 指向下一个待读取样本，scheduler 当前学习率为 `2×10^{-4}`，并且优化器已有动量状态。完整恢复时，下一次应从同一个数据位置、同一学习率状态和同一优化器状态继续；若只加载 model weights，权重虽相同，下一次更新仍可能因为样本顺序或动量缺失而不同。验收可以在确定性的小数据运行中比较“直接连续一步”和“保存后恢复一步”的 batch id、学习率、loss、梯度与参数摘要。真实大规模任务若含非确定性 kernel、异步数据读取或弹性并行，不能承诺逐位一致，应说明允许的容差与重放边界。

## 5.12 Checkpoint 选择：损失、能力、风险和成本

最后一步不天然最好。预训练后期可能过拟合，后训练可能出现通用能力下降、过度拒答、格式模板化或服务成本变化。

候选 checkpoint 至少比较：

| 维度 | 观察内容 |
| --- | --- |
| 收敛 | validation loss 和 PPL |
| 能力 | 代码、数学、多语言、长上下文和领域任务 |
| 行为 | 指令跟随、格式、事实性和人工偏好 |
| 安全 | 漏放、误拒、隐私和越权 |
| 稳定性 | 长度、seed、语言和用户切片 |
| 成本 | 延迟、显存、吞吐、重试和人工回退 |

如果要写成决策形式，可以表示为带约束的候选集合，而不是随意把不同单位相加：

~~~math
\mathcal{S}_{\mathrm{valid}}
=
\left\{
s:\ R_{\mathrm{risk}}(s)\le\tau_R,
\ C_{\mathrm{serve}}(s)\le\tau_C
\right\}
~~~

再在 `S_valid` 中按任务能力和 validation 指标比较。这样可以避免用很低的 loss 抵消一个不能接受的安全风险或服务成本。

例如两个候选都先过能力最低线；A 的验证 loss 为 `1.00` nat、1,000 个安全样本中观察到 3 次违反（`0.3%`）、服务 p95 为 `0.8 s`；B 的 loss 为 `1.03` nat、同口径样本中观察到 1 次违反（`0.1%`）、p95 为 `0.6 s`。若教学情景规定风险阈值 `0.2%`、p95 上限 `0.7 s`，A 两项都不合格，B 才进入可选集合，尽管 B 的语言建模 loss 略高。这里的比率只是小样本观察，不是安全概率证明；真实筛选还须报告区间、切片、重复次数和失败严重度，若 B 未达到能力底线，则两个候选都不能选。

## 5.13 一个最小 causal LM 训练步

下面的代码用 token-to-logits 表模拟模型。它演示：文档 packing、EOS、PAD、外部 label shift、有效 token、变长 micro-batch 的 token 加权梯度累积和一次 SGD 更新；attention mask 与 causal mask 只被单独构造和打印，没有进入模型计算。它不是 Transformer，也不代表真实模型的训练速度或能力。

> **代码状态：静态审阅，未运行（2026-10-26）。** 仅依赖 Python 标准库；代码用小表模拟 logits 与梯度。

~~~python
import math


PAD = 0
EOS = 1
vocab = {
    "<pad>": PAD,
    "<eos>": EOS,
    "the": 2,
    "cat": 3,
    "sat": 4,
    "dog": 5,
    "ran": 6,
}
id_to_token = {index: token for token, index in vocab.items()}
documents = [
    [vocab["the"], vocab["cat"], vocab["sat"]],
    [vocab["the"], vocab["dog"], vocab["ran"]],
]
block_size = 5
ignore_index = -100


def pack_documents(documents, block_size):
    if (
        not isinstance(block_size, int)
        or isinstance(block_size, bool)
        or block_size <= 1
    ):
        raise ValueError("block_size must be an integer greater than one")
    if not isinstance(documents, list) or not documents:
        raise ValueError("documents must be a non-empty list")
    stream = []
    for document in documents:
        if not isinstance(document, list) or not document:
            raise ValueError("documents must be non-empty token lists")
        if any(
            not isinstance(token, int)
            or isinstance(token, bool)
            or token not in id_to_token
            or token in {PAD, EOS}
            for token in document
        ):
            raise ValueError("document contains invalid content token ids")
        stream.extend(document + [EOS])
    blocks = []
    for start in range(0, len(stream), block_size):
        block = stream[start : start + block_size]
        block += [PAD] * (block_size - len(block))
        blocks.append(block)
    return blocks


def build_batch(blocks):
    if not isinstance(blocks, list) or not blocks:
        raise ValueError("blocks must be a non-empty list")
    width = len(blocks[0])
    if width <= 1 or any(
        not isinstance(block, list)
        or len(block) != width
        or any(token not in id_to_token for token in block)
        for block in blocks
    ):
        raise ValueError("blocks must have a shared valid width greater than one")
    input_ids = [block[:-1] for block in blocks]
    labels = []
    attention = []
    for block in blocks:
        shifted = block[1:]
        labels.append([
            token if token != PAD else ignore_index
            for token in shifted
        ])
        attention.append([
            1 if token != PAD else 0
            for token in block[:-1]
        ])
    return input_ids, labels, attention


def causal_mask(size):
    if not isinstance(size, int) or isinstance(size, bool) or size <= 0:
        raise ValueError("mask size must be a positive integer")
    return [[1 if column <= row else 0 for column in range(size)] for row in range(size)]


def valid_pairs(input_ids, labels):
    if len(input_ids) != len(labels):
        raise ValueError("input and label batch sizes must match")
    pairs = []
    for row_x, row_y in zip(input_ids, labels):
        if len(row_x) != len(row_y):
            raise ValueError("input and label sequence lengths must match")
        for previous, target in zip(row_x, row_y):
            if previous not in id_to_token:
                raise ValueError("input id is outside the vocabulary")
            if target != ignore_index and target not in id_to_token:
                raise ValueError("label id is outside the vocabulary")
            if target != ignore_index:
                pairs.append((previous, target))
    if not pairs:
        raise ValueError("batch has no valid next-token targets")
    return pairs


def init_logits(vocab_size):
    if not isinstance(vocab_size, int) or isinstance(vocab_size, bool) or vocab_size <= 0:
        raise ValueError("vocab_size must be a positive integer")
    return [[0.03 * (row - column) for column in range(vocab_size)] for row in range(vocab_size)]


def softmax(logits):
    if not isinstance(logits, list) or not logits:
        raise ValueError("logits must be non-empty")
    if any(not isinstance(value, (int, float)) or not math.isfinite(value) for value in logits):
        raise ValueError("logits must be finite numbers")
    maximum = max(logits)
    values = [math.exp(value - maximum) for value in logits]
    total = sum(values)
    return [value / total for value in values]


def loss_and_grad(table, pairs):
    if not isinstance(table, list) or not table or any(len(row) != len(table) for row in table):
        raise ValueError("logit table must be a non-empty square matrix")
    if not pairs:
        raise ValueError("pairs must be non-empty")
    vocab_size = len(table)
    gradient = [[0.0] * vocab_size for _ in range(vocab_size)]
    loss_sum = 0.0
    for previous, target in pairs:
        if not 0 <= previous < vocab_size or not 0 <= target < vocab_size:
            raise ValueError("pair ids must be inside the logit table")
        probabilities = softmax(table[previous])
        loss_sum += -math.log(probabilities[target])
        for column, probability in enumerate(probabilities):
            gradient[previous][column] += probability
        gradient[previous][target] -= 1.0
    denominator = len(pairs)
    return loss_sum / denominator, [
        [value / denominator for value in row]
        for row in gradient
    ]


def add_gradients(left, right):
    return [
        [left_value + right_value for left_value, right_value in zip(left_row, right_row)]
        for left_row, right_row in zip(left, right)
    ]


def scale_gradient(gradient, scale):
    if not isinstance(scale, (int, float)) or not math.isfinite(scale):
        raise ValueError("gradient scale must be finite")
    return [[value * scale for value in row] for row in gradient]


def gradient_norm(gradient):
    return math.sqrt(sum(value * value for row in gradient for value in row))


def apply_sgd(table, gradient, learning_rate):
    if not isinstance(learning_rate, (int, float)) or not math.isfinite(learning_rate) or learning_rate <= 0:
        raise ValueError("learning_rate must be finite and positive")
    return [
        [weight - learning_rate * value for weight, value in zip(weight_row, gradient_row)]
        for weight_row, gradient_row in zip(table, gradient)
    ]


blocks = pack_documents(documents, block_size)
input_ids, labels, attention = build_batch(blocks)
pairs = valid_pairs(input_ids, labels)
logits = init_logits(len(vocab))
initial_loss, full_gradient = loss_and_grad(logits, pairs)

micro_batches = [pairs[:2], pairs[2:]]
accumulated = [[0.0] * len(vocab) for _ in range(len(vocab))]
equal_batch_weighted = [[0.0] * len(vocab) for _ in range(len(vocab))]
unscaled = [[0.0] * len(vocab) for _ in range(len(vocab))]
for micro_batch in micro_batches:
    _, micro_gradient = loss_and_grad(logits, micro_batch)
    token_weight = len(micro_batch) / len(pairs)
    accumulated = add_gradients(
        accumulated,
        scale_gradient(micro_gradient, token_weight),
    )
    equal_batch_weighted = add_gradients(
        equal_batch_weighted,
        scale_gradient(micro_gradient, 1 / len(micro_batches)),
    )
    unscaled = add_gradients(unscaled, micro_gradient)

updated = apply_sgd(logits, accumulated, learning_rate=0.5)
after_loss, _ = loss_and_grad(updated, pairs)
max_difference = max(
    abs(left - right)
    for left_row, right_row in zip(full_gradient, accumulated)
    for left, right in zip(left_row, right_row)
)
equal_batch_difference = max(
    abs(left - right)
    for left_row, right_row in zip(full_gradient, equal_batch_weighted)
    for left, right in zip(left_row, right_row)
)

diagnostics = {
    "labels_shifted": labels[0][:3] == blocks[0][1:4],
    "pad_ignored": labels[1][-1] == ignore_index,
    "causal_lower_triangular": causal_mask(4)[2] == [1, 1, 1, 0],
    "micro_batches_have_unequal_tokens": [len(batch) for batch in micro_batches] == [2, 4],
    "accumulation_matches_full": max_difference < 1e-12,
    "equal_batch_weighting_differs": equal_batch_difference > 1e-12,
    "unscaled_accumulation_larger": gradient_norm(unscaled) > gradient_norm(full_gradient),
    "loss_decreased": after_loss < initial_loss,
}

print("blocks=", [[id_to_token[token] for token in block] for block in blocks])
print("input_ids=", input_ids)
print("labels=", labels)
print("attention=", attention)
print("causal_mask=", causal_mask(4))
print("valid_pairs=", [(id_to_token[left], id_to_token[right]) for left, right in pairs])
print("valid_token_count=", len(pairs))
print("micro_batch_token_counts=", [len(batch) for batch in micro_batches])
print("initial_loss=", round(initial_loss, 4))
print("after_one_step_loss=", round(after_loss, 4))
print("gradient_difference=", max_difference)
print("equal_batch_weighting_difference=", equal_batch_difference)
print("full_gradient_norm=", round(gradient_norm(full_gradient), 6))
print("unscaled_gradient_norm=", round(gradient_norm(unscaled), 6))
print("diagnostics=", diagnostics)
assert all(diagnostics.values())
try:
    valid_pairs([[PAD]], [[ignore_index]])
except ValueError:
    pass
else:
    raise AssertionError("empty supervision must be rejected")
try:
    causal_mask(0)
except ValueError:
    pass
else:
    raise AssertionError("zero mask size must be rejected")
print("training step toy: ok")
~~~

这段 toy 的边界要先说清：`attention` 只是一张由非 PAD 输入生成的列表，`causal_mask(4)` 只构造一张下三角矩阵；后续的 `valid_pairs` 只读取 input 与 label，并没有读取任一 mask，也没有 Q/K/V 或 attention 运算。因此程序能示范 label 对齐和 loss 分母，却不能验证 attention mask 是否改变模型输出。要检查注意力可见性，读者应使用第三章的样本协议检查，并在真实模型前向中分别改动 mask 后对照输出。

手工沿一次数据流复核：packing 得到 `[the,cat,sat,eos,the]` 和 `[dog,ran,eos,pad,pad]`；错开后第一块形成 4 对，第二块形成 2 对，两个 PAD 目标被设为 `-100`，故有效目标总数为 6。toy 的 logits 表每一行只按“前一个 token id”查一组 logits，因此同一个 token 无论前面有何上下文都会复用同一行；这是为了缩小例子，而不是一个语言模型。再把 6 对拆成 2 与 4 两个 micro-batch，代码按 `2/6` 和 `4/6` 加权各自的 mean gradient；若改成两个 micro-batch 各占一半，便不再等价于 6 对一次性求均值。

这个 toy 还把一种数据边界选择显式摆了出来：`pack_documents` 先把两篇文档连成一个 token 流，再按 `block_size` 切块，所以第一块包含 `EOS → the` 这一跨文档预测对，第二篇开头也可能保留第一篇的因果上下文。EOS 在这里是一个被预测的边界 token，不会自动重置 attention 或 label；若任务要求文档彼此隔离，就必须额外追踪文档边界、屏蔽跨界目标并让 attention 遵循相同边界。这正是第三章 3.10 所述的协议选择，本程序没有实现隔离模式。

读这段程序时，可以按四个接口检查它是否忠实表达目标。`pack_documents` 先在每篇文档后放 EOS，再按固定宽度切块并补 PAD；`build_batch` 将每块拆成输入和右移一格的标签，并只为非 PAD 输入造 attention 列表；`valid_pairs` 丢弃 `-100` 标签，明确给出进入交叉熵分母的 `(previous,target)` 对；`loss_and_grad` 对每一对计算 softmax 交叉熵和梯度，并除以有效对数。这样读者能把前文的“label shift—有效 token 分母”逐层对到变量上，而不会误以为 `labels` 是同位置预测。

累积部分又把每个 micro-batch 的 token-mean 梯度乘以其有效 token 占比，合成一个窗口梯度；之后 `apply_sgd` 才对这张简化 logits 表做一次更新。`after_loss` 使用同一组有效 pair 重新计算单步后的目标，设计意图是观察一次更新的方向，不是证明训练会持续收敛。代码只设置了一张静态的 token-to-logits 表，没有上下文状态、可学习 Transformer 层、随机数据顺序、验证集或多步训练；因此即使某组断言通过，也只能支持程序范围内的代数关系，不能外推到真实模型的数值稳定性和能力变化。

程序把预期关系写成断言：移位后 labels 与 block 对齐，PAD 目标被忽略，矩阵打印为下三角，累积梯度应匹配 full batch，而等 micro-batch 权重应不同。代码仍标记为“静态审阅，未运行”；这些是代码所声明的检查目标，不是本轮观察到的执行输出。真实框架还要处理 logits shape、内部 shift、dropout、分布式缩放、梯度裁剪、optimizer/scheduler 和混合精度，本例都没有覆盖。

这组数据有 6 个有效预测对，代码将它们拆成 2 个和 4 个 token 的 micro-batch。`accumulated` 按 token 数加权，梯度应与 6 个 pair 一次性求平均一致；`equal_batch_weighted` 故意按 micro-batch 个数等权，诊断会显示它与 full-batch gradient 不同。这样能直接区分“累积了若干个 batch”与“复现同一个 token-level objective”。

诊断字典里的 `max_difference` 把两张梯度表逐元素相减后取最大绝对值，`1e-12` 是这份标准库小程序比较 Python 浮点结果的教学阈值，不是 BF16、FP16 或分布式训练的通用容差。移到张量框架时，读者应先明确 dtype、累加精度、设备和归约顺序，再给出有依据的绝对/相对误差界；不能因为真实设备上的结果不等于零就判定公式错误，也不能把容差放大到足以掩盖 token 权重差异。`diagnostics` 的每个布尔项对应一个可观察不变量，但因本例没有运行，这些键值仍是程序将要计算的结果，而非已报告的实测输出。

## 5.14 常见故障：从 loss 反查训练链

### 5.14.1 Loss 不下降

先在固定的小数据子集上关闭随机增强和 dropout，确认模型能过拟合一两个 batch；若不能，再打印 token、shift 后的 label、有效目标数、目标类别概率和梯度范数。若有效目标数为 0，应跳过 update 并检查模板、截断和 ignore index；若梯度为 0，检查参数是否被冻结或 loss 是否连到这些参数；若梯度非零而 loss 不动，再核对 optimizer 是否真的更新参数、学习率是否为零、scheduler 是否推进错频。按“样本—目标—梯度—状态”顺序缩小故障，比直接改大学习率更容易定位。

### 5.14.2 Loss 虚假地很低

可能是未来 token 泄漏、label 与 input 没有错位、训练集污染、重复数据或 validation 复用了训练样本。固定一个样本，逐位置打印当前可见前缀、logits 对应的 target id、label mask 和 attention 可见列；把未来答案替换成随机 token 后，若早先位置的 hidden/logits 仍能读取答案，说明 mask 或数据拼接有泄漏。再核对训练与验证的样本 hash、近重复统计、模板和数据版本，避免把污染或复用误诊为优化能力。

### 5.14.3 梯度累积后训练变慢或发散

先用相同 6 个有效目标、关闭 dropout，在小 batch 和多个 micro-batch 上比较平均 loss 与梯度；数值不一致时检查分母、尾窗和 DDP all-reduce。确认每个 optimizer update 的有效 token 数后，再看梯度范数、裁剪比例、loss scale、学习率调度和 tokens/s。若只观察到训练变慢，分解 forward/backward、通信和 dataloader 时间；如果发散恰好发生在最后一个不完整窗口或 scaler 溢出时，保存对应 batch 和 rank 的计数再重放。

### 5.14.4 NaN 或 Inf

先记录异常首次出现在哪一层和哪一阶段：输入数据、前向 logits、loss、unscaled gradient、optimizer state 或参数。保留同一步的样本 id、长度、mask、精度、loss scale、GPU/rank 和最近 checkpoint；用相同输入缩小 batch 重放，检查是否由单条坏样本、极端 logits 或某个算子触发。梯度裁剪只能限制有限梯度的范数，不能修复已经非有限的值；也不要用跳过 NaN 的日志把问题隐藏成正常吞吐。

### 5.14.5 吞吐下降

把 step time 拆成数据加载、H2D、forward、backward、通信、optimizer、日志、评估和 checkpoint，并统一吞吐分子是 input tokens 还是有效目标 tokens。若 `input tokens/s` 稳定但 `valid tokens/s` 下降，检查 padding、ignore 比例和截断；若两者同时下降，检查长度分布、数据解码、通信等待和节点健康。每次只比较固定窗口、相同硬件/rank 数和相同评估频率，否则日志写盘或验证插入也会被误认为训练 kernel 变慢。

### 5.14.6 Validation 变化异常

确认 validation 的 tokenizer、shift、mask、有效 token 分母、数据版本和 loss reduction；先在固定样本上把 loss sum 与 token count 独立复算，再看全局曲线。整体改善但某语言或长序列显著退化时，按语言、领域、长度、来源和污染风险切片，并确认切片分母没有被 padding 或空监督稀释。若指标变化发生在 evaluator、模板或 tokenizer revision 更换之后，应先回放旧版 gold set，再决定这是模型变化还是评估协议变化。

## 5.15 资料边界与延伸阅读

## 5.16 章节练习：从公式到可复现训练

### 练习一：手工完成 label shift

给定一个包含两个 EOS 的 token 流，切成长度为 8 的 block，写出 input、label、PAD 和有效 label mask。说明每个位置预测的到底是哪一个 token。

### 练习二：区分三种 mask

画出 causal mask、padding attention mask 和 label mask。构造一个未来 token 泄漏、PAD 参与 attention、PAD 参与 loss 的最小故障，并说明各自的 loss 或输出症状。

### 练习三：验证 packing 假设

将三份不同长度文档 pack 到一个 block，分别使用普通 causal mask 和 document-level mask。比较跨文档可见性、有效 token 数和训练目标的差异。

### 练习四：梯度累积的分母

构造两个有效 token 数不同的 micro-batch，比较“平均每个 batch loss”和“按总有效 token 归一化”的梯度。解释哪一种与 full batch token-level loss 一致。

### 练习五：FP16 更新顺序

用伪代码实现 autocast、loss scaling、unscale、gradient clipping、optimizer step 和 scaler update。故意把 clipping 放在 unscale 前，观察阈值含义如何变化。

### 练习六：checkpoint 恢复测试

让 toy 模型连续运行 20 个 optimizer step，在第 10 步保存权重、optimizer、scheduler、随机状态和数据位置。比较连续运行与恢复运行的下一步输入、loss、梯度和参数。

### 练习七：选择 checkpoint

从一次训练的三个时间点收集 validation、代码执行、数学验证、安全漏放、延迟和人工偏好。先按风险和成本约束筛选，再解释为什么最低 validation loss 不一定是最终版本。

### 练习八：选择预训练目标

为开放式聊天基座、代码中间补全、encoder-decoder 条件生成、多 token prediction 和离散扩散各选一个训练目标。分别写出输入可见范围、被监督的 token、每个 head/噪声步的有效分母、架构要求、训练与采样预算和下游评测；再解释为什么同一个 PPL 表格无法直接给这些方案排名。

## 5.17 本章小结

本章以 causal LM 的自回归最大似然作为训练循环主线，同时区分 BERT-style MLM、T5 span corruption、UL2 混合去噪、FIM、多 token prediction 和离散扩散各自的输入上下文、目标 token、采样路线与证据边界。目标函数必须与架构、数据变换和评测口径一起选择；不同目标下的 loss/PPL 不能脱离有效 token 定义直接比较。对 causal LM，label shift 决定监督对齐，padding 和 label mask 决定哪些位置进入分母，packing 决定 token 利用率与文档边界。

一次可靠的 optimizer update 还要包含有效 token 归一化、梯度累积、unscale 与裁剪、optimizer/scheduler 状态、数值监控和日志。validation 必须按统一分母汇总，checkpoint 必须区分推理权重与可恢复训练状态。

最终，训练循环不是几行 `forward/backward/step` 代码，而是一条可以被打印、验证、恢复和解释的证据链。下一章进入优化器与学习率策略，继续说明梯度如何转成参数更新，以及为什么同一个 loss 曲线会对应完全不同的收敛行为。
