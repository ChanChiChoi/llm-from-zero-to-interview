# 第十二章：多模态训练：从模态表示到可验证的生成能力

当一个模型回答“这张票据的总价是多少”时，它至少要完成四件事：从图像中找到文字，把文字和版式组织成可推理的表示，理解问题要求，最后以正确的格式生成答案。把图片文件放进请求里，只能说明接口收到了图片；它不能说明模型看到了小字，也不能说明答案确实来自图片证据。语音和视频同样如此：音频可能被正确解码，却因为端点切分丢失了否定词；视频可能采样了很多帧，却没有保留动作发生的先后关系。

因此，多模态训练的主线不是“再接一个编码器”，而是把不同模态的表示、时间尺度、监督信号和评估方式接成一条闭环。本章从图文对比学习开始，依次解释视觉语言模型的桥接与分阶段训练、多模态指令微调、OCR/文档、语音、视频和 diffusion 的目标差异，最后把数据对齐、资源预算和评估串起来。

本章使用的证据分为三层。原始论文用于说明方法最初的目标函数和实验设置；官方模型卡或项目文档用于说明某个实现的接口和工程约束；本章中的预算数字、toy demo 和故障排查结论则是教学化推导，不能冒充某个具体模型的公开事实。不同论文的训练数据、分辨率、tokenizer、采样策略和评测集并不相同，不能只凭模型名称横向比较。

## 为什么多模态训练和纯文本训练不一样

纯文本训练只处理 token 序列。

多模态训练要处理：

1. 图像。
2. 音频。
3. 视频。
4. 文本。
5. 甚至结构化元数据和工具信号。

不同模态之间的单位、长度、分辨率和噪声特性都不一样，所以训练流程也不一样。

例如：

```text
文本是离散 token 序列
图像是像素网格
音频是时间序列波形或 codec token
视频是时间上的图像序列
```

多模态训练的核心不是把不同模态简单拼在一起，而是让它们在一个明确的任务目标下相互约束。图文检索需要全局语义接近，OCR 需要字符和区域对应，视频问答需要事件发生顺序正确，实时语音助手还要同时满足转写质量和交互时延。它们都叫“对齐”，但正样本、损失函数和失败样例并不相同。

一个实用的判断顺序是：先问输入被编码成了什么，再问编码之间怎样交互，接着问哪些输出位置得到监督，最后问评估是否能证明答案使用了正确模态的证据。只回答“用了 vision encoder 和 LLM”，还没有回答训练问题的核心。

## 1. 多模态训练的几类主任务

多模态训练常见任务包括：

| 任务 | 输入 | 输出 | 目标 |
| --- | --- | --- | --- |
| 图文对比学习 | 图像 + 文本 | 相似度 | 学对齐表示 |
| 图文生成 | 图像 + prompt | 文本 | 学会描述和问答 |
| OCR / 文档理解 | 图像或文档图 | 文本答案 | 学会读图中文字和布局 |
| 图表理解 | 图像 + 问题 | 文本答案 | 学会数值和结构关系 |
| 语音识别 | 音频 | 文本 | 学会转写 |
| 语音问答 | 音频 + 问题 | 文本答案 | 学会听懂并回答 |
| 视频理解 / 生成 | 视频 + 文本 | 文本或视频 | 学会时序信息 |

不同任务的训练目标不同，但都围绕三个问题展开：表示是否保留了任务需要的信息，跨模态交互是否发生在正确的位置，输出是否能被可靠地验证。举例来说，图文检索只需要判断“这张图和这段文字是否相关”，而票据抽取还需要把金额字符和对应区域绑定；前者的全局 embedding 可能已经足够，后者却需要更细粒度的视觉 token、OCR 监督或 grounding 标注。

还可以把多模态任务按监督形态来分：对比学习监督“哪一对应该更近”，生成式监督“下一个答案 token 是什么”，定位监督“答案来自哪个区域或时间段”，重建式监督“被破坏的信号如何恢复”。一个系统往往会组合这些目标，而不是期待单一损失同时解决所有问题。组合时必须记录每种样本的数量、权重和有效监督位置，否则总 loss 下降并不能说明稀有但关键的 OCR 或时序能力得到了训练。

## 2. CLIP 风格图文对齐

CLIP 是多模态训练里最经典的入门方法之一。原论文用互联网图文对训练两个 encoder，并通过共享 embedding 空间支持检索和 zero-shot 分类；下面只把它作为全局图文对齐的训练基线，不把检索能力等同于 OCR 或视觉问答能力（[CLIP 原论文](https://arxiv.org/abs/2103.00020)）。

它的目标很简单：

```text
匹配的图文对更近，不匹配的更远。
```

### 2.1 训练形式

给定一个 batch 的图文对：

```text
image_i <-> text_i
```

计算图像 embedding 和文本 embedding 的相似度矩阵，然后做对比学习。

更具体地说，图像编码器输出 `u_i`，文本编码器输出 `v_i`，先做 L2 normalize：

```math
\hat{u}_i=\frac{u_i}{\|u_i\|_2},\qquad
\hat{v}_i=\frac{v_i}{\|v_i\|_2}
```

batch 内相似度矩阵可以写成：

```math
S_{ij}=s\cdot \hat{u}_i^\top \hat{v}_j
```

其中 `s` 是正的 logit scale。论文和实现中常把它写成 `exp(lambda)`；如果使用温度 `T` 的记号，则 `s=1/T`。为了避免把温度和缩放因子混为一谈，本章统一使用 `s`。第 `i` 张图的正确文本是第 `i` 个文本，所以 image-to-text loss 是：

```math
L_{\mathrm{i2t}}
=-\frac{1}{B}\sum_{i=1}^{B}
\log
\frac{\exp(S_{ii})}
{\sum_{j=1}^{B}\exp(S_{ij})}
```

text-to-image loss 对相似度矩阵按列做同样的交叉熵：

```math
L_{\mathrm{t2i}}
=-\frac{1}{B}\sum_{i=1}^{B}
\log
\frac{\exp(S_{ii})}
{\sum_{j=1}^{B}\exp(S_{ji})}
```

最终常写成双向 loss：

```math
L_{\mathrm{CLIP}}=\frac{1}{2}(L_{\mathrm{i2t}}+L_{\mathrm{t2i}})
```

这些式子有明确的定义域：每个 embedding 必须是同一维度的有限非零向量，`s>0`，并且每张图和每段文本都必须能找到至少一个正例。单正例的对角线写法还默认 image/text 的顺序一一对应。训练 batch 至少需要两个不同候选才有对比信号；`B=1` 时交叉熵形式可以算出零损失，却没有负例，不能被当成 CLIP 对齐已经学会。数值实现应以 `logsumexp` 计算分母，避免先对大 logit 求指数再溢出。

直觉上，这和普通分类交叉熵很像：每张图要在一个 batch 的所有文本里选中自己的 caption，每段文本也要在一个 batch 的所有图里选中自己的 image。

### 2.2 为什么重要

CLIP 学到的是共享语义空间。

这个空间可以用于：

1. 检索。
2. zero-shot 分类。
3. 作为后续 VLM 的图文对齐底座。

### 2.3 训练难点

1. 正负样本构造。
2. batch 内负样本质量。
3. 图文噪声对齐。
4. 中文/多语言效果。
5. 细粒度和 OCR 场景不足。

所以，CLIP 的核心价值是把图像和文本映射到同一个语义空间，为后续检索、VLM 和多模态理解提供表示基础；它的全局对齐能力仍需要细粒度任务来补充。

### 2.4 batch 大小、假负样本与分布式训练

CLIP 的“负样本”通常来自同一个 batch。batch 越大，模型一次看到的候选文本越多，区分能力通常越强；但这不是无条件成立的规律。若两个不同 caption 实际描述的是同一张图片，或一个 batch 中出现了语义上等价的图片，单标签交叉熵会把它们误当成负样本。模型可能因此被惩罚，而不是学到更细腻的相似度。

设一张图片对应多个正确文本的正例集合为 `P(i)`，多正例版本可以把分子从单个 `S_ii` 改为多个正例的聚合，例如：

```math
L_i=-\log\frac{\sum_{j\in P(i)}\exp(S_{ij})}{\sum_{j=1}^{B}\exp(S_{ij})}
```

这个写法要求 `P(i)` 非空，且其中的索引属于当前候选集合；若所有候选都是正例，目标同样没有把相似对与不相似对拉开的信号。实际实现还要决定如何处理重复图片、缺失 caption 和跨模态采样权重。若使用数据并行，每个 rank 只持有本地 embedding，却想获得全局负样本，通常需要对 embedding 做 `all_gather`。此时要同时核对三件事：gather 后的正样本索引是否仍然正确，梯度是否按实现预期跨 rank 传播，以及有效 global batch 是否真的等于配置值。否则“把 GPU 数乘上 batch size”只是账面数字。

CLIP 的全局相似度也有边界。两张图整体语义接近，不代表模型能定位“左边第二行的数字”；图文相似度高，也不代表 caption 没有遗漏关键对象。需要细粒度能力时，常见补充包括区域-文本对齐、OCR token 监督、grounding 标注和 hard-negative 评估。因而 CLIP 更适合作为共享表示的起点，不能直接当作文档阅读器或视觉事实核验器。

### 2.5 从 CLIP 到 SigLIP：改变归一化，不会自动修复错标签

CLIP 对每一行/列的相似度做 softmax 归一化。一个候选文本的梯度不仅取决于图文对本身，还取决于同 batch 里的其他候选；分布式训练想扩大负例集合时，就需要处理跨 rank 的 embedding 收集和正例索引。SigLIP 把任务改写为图文对的二元判别：每对分别标成匹配 `z_{ij}=+1` 或不匹配 `z_{ij}=-1`，再计算 logistic loss：

```math
q_{ij}=s\,\hat u_i^\top\hat v_j+b,\qquad z_{ij}\in\{-1,+1\}
```

```math
L_{\mathrm{sigmoid}}
=-\frac{1}{B}\sum_{i=1}^{B}\sum_{j=1}^{B}
\log\sigma(z_{ij}q_{ij})
```

`s>0` 是可学习的相似度缩放，`b` 是可学习偏置，`\sigma` 是 sigmoid。匹配标签仍由数据协议提供；默认的一一配对设置把对角线设成正例、其余组合设成负例。论文提出的关键变化是移除 softmax 的全局归一化耦合，报告在较小 batch 上也有竞争力，并发现把 batch 推到百万规模后收益很快递减、约 32k 已足以取得大部分 batch 增益（[SigLIP 原论文](https://arxiv.org/abs/2303.15343)）。这不代表计算不再需要图文 pair 的相似度，也不代表所有 batch、硬件和数据都能省掉跨 rank 通信。

一个两候选手算能看出错标签为何依旧危险。假设一个图像的正确文本 logit 是 `3`，另一个语义高度相关、但数据标成负例的文本 logit 是 `2`。CLIP 对这两个候选的正确类概率为 `e³/(e³+e²)≈0.731`，该行 loss 约为 `0.313`；如果按 SigLIP 把第二对标成负例，它的单对损失是 `softplus(2)≈2.127`，仍会把这对相似度往下推。SigLIP 改了损失耦合方式，没替数据修正正负关系。需要多个正例时，应在标签矩阵中明确标出它们，并为采用的多正例目标说明如何聚合正例和负例；只换 loss 名称不能处理假负例。

SigLIP 2 也不是“换了一个更好的 sigmoid 公式”。它在 SigLIP 对齐目标外组合了 captioning decoder、自蒸馏、masked prediction、在线数据筛选和多分辨率/原始纵横比变体，论文报告了图文检索与 zero-shot 任务的改善，并特别扩展定位和 dense feature 能力（[SigLIP 2 原论文](https://arxiv.org/abs/2502.14786)）。这些是联合训练配方的结果，不能把提升单独归因给某一项辅助损失；要迁移到文档、截图或中文任务，仍需在目标数据上做切片评估。

| 路线 | 主要改变 | 它解决的约束 | 证据与边界 |
| --- | --- | --- | --- |
| CLIP | 双塔 embedding + 双向 softmax 对比 | 用 batch 内负例建立全局语义空间；负例分布与 batch/数据并行策略相连 | 原论文验证图文检索和 zero-shot 迁移；全局相似度不保证局部定位、OCR 或事实支持 |
| SigLIP | 对每个图文 pair 做 sigmoid 分类 | 不要求 softmax 对整个候选集归一化，训练更容易按 pair 分块/分布计算 | 作者报告小 batch 有效、超大 batch 边际收益下降；默认对角正例仍会把未标注的同义/重复 pair 当负例 |
| SigLIP 2 | sigmoid 对齐 + captioning、自监督视觉损失和筛选配方 | 在全局图文语义之外补定位、dense feature、多语言和分辨率适配 | 作者比较同族模型并报告多任务改善；联合 recipe 的收益不能直接归因于单一组件 |

这张表说明，方法演进是在逐步补不同的监督缺口：CLIP/SigLIP 主要监督“整张图和整句文本是否匹配”，SigLIP 2 扩大训练信号种类，但局部证据仍要由 grounding、OCR/文档数据和相应评估来检验。

## 3. VLM：Vision Encoder + Connector + LLM

视觉语言模型通常不是直接把图像像素喂给 LLM，而是通过三段式结构：

```text
vision encoder -> connector / projector -> LLM
```

### 3.1 Vision encoder

Vision encoder 负责把图像变成视觉表示。

常见实现包括：

1. ViT。
2. ConvNet + transformer。
3. CLIP vision tower。

### 3.2 Connector / projector

因为视觉表示和语言 token 的维度、分布不同，需要一个连接器把视觉特征映射到 LLM 可消费的表示空间。

常见 connector：

1. linear projector。
2. MLP projector。
3. Q-Former。
4. Perceiver Resampler。

### 3.3 LLM

LLM 负责把图像表示和文本 prompt 结合起来生成答案。

训练时通常有几种策略：

1. 冻结 vision encoder，只训练 connector 和 LLM。
2. 冻结 LLM，只训练 connector。
3. 联合微调部分或全部参数。

如果视觉编码器输出：

```math
V\in\mathbb{R}^{B\times N_v\times d_v}
```

其中 `B` 是 batch size，`N_v` 是视觉 token 数，`d_v` 是视觉特征维度。connector 的目标是把它投影到 LLM hidden size `d`：

```math
Z=g(V),\qquad Z\in\mathbb{R}^{B\times N_v\times d}
```

文本 token 经过 embedding 得到：

```math
E\in\mathbb{R}^{B\times T\times d}
```

最简单的拼接式 VLM 会把视觉 token 当成一段前缀：

```math
H_0=[Z;E],\qquad H_0\in\mathbb{R}^{B\times (N_v+T)\times d}
```

这里的关键不是公式本身，而是 shape 必须对齐：connector 输出的最后一维必须等于 LLM hidden size；视觉 token 数会进入上下文长度，直接影响 attention 成本和 KV Cache 显存。

由此可见，VLM 的关键不是“把图接到 LLM 上”，而是设计视觉到语言的桥接模块，并在训练中让视觉证据和语言任务真正对齐。

### 3.4 为什么通常要分阶段训练

一个随机初始化的 connector 同时面对两个问题：视觉 encoder 的特征分布还没有被语言任务验证，LLM 也没有理由把一串新来的视觉向量当成有意义的上下文。若一开始就解冻全部模块，梯度会在视觉、桥接和语言三处同时调整，训练成本高，且很难判断失败来自哪里。

常见的教学化流程是：

1. 先固定 vision encoder 和 LLM，只训练线性层或 MLP connector，让视觉特征进入语言模型的 hidden space。
2. 再用 caption、VQA、OCR 和对话样本训练 connector，并视数据规模解冻 LLM 的部分层或使用参数高效微调。
3. 最后用高质量 instruction 数据做任务对齐，同时加入拒答、证据引用、格式和安全回归样本。

这不是所有 VLM 的唯一流程。BLIP-2 用 Q-Former 在冻结视觉编码器和冻结语言模型之间进行桥接；Flamingo 在语言模型中插入带门控的跨注意力层；LLaVA 的早期公开方案则采用预训练 projector 后再做视觉指令微调。阅读论文时要把“论文中采用的训练阶段”与“VLM 的普遍定律”分开。

### 3.5 视觉 token 预算不是免费的前缀

如果一张 `224 x 224` 的图片使用 `14 x 14` patch，空间 patch 数是 `16 x 16=256`。两张图或更高分辨率会使视觉 token 继续增加。把视觉 token 作为文本前缀时，LLM 自注意力的序列长度从 `T` 变成 `T+N_v`，近似计算量从 `T^2` 变成：

```math

  (T+N_v)^2=T^2+2TN_v+N_v^2
```

新增项不仅是视觉 token 自身的注意力，还包括视觉和文本之间的双向交互项（在因果解码器中具体可见位置取决于 mask）。因此，connector 的压缩比例、动态分辨率策略和多图输入策略是训练与部署共同的设计问题。压缩太激进会丢失小字和空间关系，保留全部 patch 又会让长上下文、KV cache 和 batch size 同时承压。

### 3.6 三类桥接方式的取舍

线性 projector 参数少、容易训练，但只能做较弱的维度映射；MLP projector 增加非线性，通常能吸收更复杂的分布差异，却仍然把大量视觉 token 原样交给 LLM。Q-Former 或 Perceiver Resampler 用一组可学习 query 从视觉序列中读取固定数量的摘要，能控制序列长度，但压缩质量依赖 query 数量、交互层和训练任务。跨注意力层则允许语言 token 按需读取视觉特征，表达更灵活，代价是改动 LLM 结构并增加每层计算。

比较 connector 时应同时问四个问题：视觉 token 数是否固定，细粒度证据是否保留，语言模型是否需要改结构，训练时梯度经过哪些模块。只比较参数量，无法解释为什么一个模型在长文档或多图场景下更稳定。

### 3.7 代表性训练配方分别解决什么

“先对齐、再 instruction tuning”是便于理解的总流程，不是所有工作都采用同一种数据、冻结策略或训练预算。下表把几类常被并列讨论的方案按瓶颈拆开；论文成绩不应跨行直接排位。

| 方案 | 主要瓶颈 | 训练设计 | 论文报告的证据 | 代价、边界和后续改进方向 |
| --- | --- | --- | --- | --- |
| [BLIP-2](https://arxiv.org/abs/2301.12597) | 从头端到端训练强视觉塔和大语言模型成本高，冻结 LLM 又难让它理解新视觉表示 | 冻结预训练 image encoder 与 LLM，训练 Q-Former；先做视觉-语言表示学习，再做 vision-to-language 生成学习 | 作者在其 zero-shot VQAv2 设置报告高于 Flamingo-80B 的结果，同时可训练参数少 54 倍 | 计算节省来自复用冻结两端，但 Q-Former 是信息瓶颈；若目标是细小文字或密集区域，需评估 query 数和高分辨率视觉输入，不能据 VQA 分数推断 OCR 足够 |
| [LLaVA-1.5](https://arxiv.org/abs/2310.03744) | 视觉指令模型训练需要降低复现门槛，同时保留较强的视觉问答覆盖 | 使用 CLIP ViT-L/336px、MLP connector，并加入学术任务 VQA 和格式化回答提示；作者报告总训练数据 1.2M | 作者报告 13B checkpoint 在其 11 个 benchmark 上达到较强基线，完整训练约一天、单个 8-A100 节点 | 易复用的 projector 不自动解决高分辨率 OCR、多图与长视频；结果依赖数据、提示格式和 benchmark，不能把时间/分数迁移成通用成本承诺 |
| [MM1](https://arxiv.org/abs/2403.09611) | 只看 connector 架构容易忽略图像 encoder、分辨率、token 数和数据混合 | 做单组件消融；其 1.2B 消融基线使用 45% captioned image、45% interleaved image-text、10% text-only，C-Abstractor 输出 144 个 image token | 作者发现 encoder、图像分辨率、视觉 token 数和数据类型配比影响明显；在该消融设置中 connector 类型相对影响较小 | `45/45/10` 是论文消融基线，不是所有任务的最佳比例；结论受该 encoder、模型规模和评测集约束。后续要在固定 token/FLOPs 下重测数据混合与 connector |

从这些例子可以得到一个可执行的诊断顺序：固定同一 vision encoder、LLM、数据和训练预算，先检查图像分辨率与视觉 token 数，再检查 caption/VQA/OCR/interleaved 数据覆盖和监督 mask，最后消融 connector。否则不同实验同时换了数据和模型，无法知道收益究竟来自哪一环。BLIP-2 的零样本结果、LLaVA-1.5 的指令微调结果和 MM1 的预训练消融属于不同层次，不能拼成同一排行榜。

## 4. 多模态 instruction tuning

多模态 instruction tuning 是把图像、文本、OCR、图表、空间关系等任务统一成对话格式。

例如：

```text
<image>
请描述这张图。
```

或者：

```text
<image>
图中的价格是多少？
```

### 4.1 目标

1. 学会看图回答。
2. 学会 OCR。
3. 学会图表理解。
4. 学会多轮多模态对话。
5. 学会 grounding 和空间关系描述。

### 4.2 关键问题

1. image token 怎么插入。
2. label mask 怎么做。
3. 哪些 token 参与 loss。
4. 图像和文本的对齐是否一致。
5. 多轮对话中如何保留图像上下文。

多模态 SFT 的 loss 和文本 SFT 很像，但必须明确哪些位置参与监督。设序列中第 `t` 个 token 的 label 是 `y_t`，mask 是 `m_t`，集合 `A` 表示 assistant 文本答案所在的位置：

```math
m_t=
\begin{cases}
1, & t\in A\\
0, & t\notin A
\end{cases}
```

则 assistant-only loss 可以写成：

```math
L_{\mathrm{mm\_sft}}
=-
\frac{\sum_{t=1}^{T}m_t\log p_\theta(y_t\mid I,x_{1:t-1})}
{\sum_{t=1}^{T}m_t}
```

其中 `I` 表示图像或其他非文本模态输入。分母必须满足 `\sum_t m_t>0`，每个被选中的 `y_t` 必须是该模型词表中的合法目标，且条件概率为正；一个样本在截断、模板展开后不再含 assistant token，不是零损失样本，而是应跳过或报错的数据协议异常。工程上常把 `m_t=0` 的位置对应到 `labels=-100`，让交叉熵忽略它们。最容易出错的是把 image placeholder、user prompt 或 padding token 也算进 loss，导致模型学会复读输入格式，而不是学习回答。

多模态 instruction tuning 的本质，是把视觉信息包装成语言模型可以学习的对话样本，同时保持图文对应关系和 label mask 的一致性。

### 4.3 一个样本的输入协议

训练代码真正接收的不是“图片加一句话”，而是一份跨模态协议。它至少要同时描述：媒体在哪里、媒体被编码成多少个占位位置、对话角色如何排列、哪些位置是答案、padding 如何处理，以及原始媒体和 token 序列之间怎样对应。

例如，下面的逻辑序列可以表示一轮图文问答：

```text
<bos> <image> <image_end> 用户：总价是多少？ 助手：128 元 <eos>
```

`<image>` 可能只是一个 placeholder，并不等于一个视觉向量；数据 collator 可能把它扩展成 `N_v` 个视觉 embedding。若 tokenizer 只产生一个 placeholder，而模型 forward 期望 `N_v` 个位置，常见结果是 shape 错误；若扩展了视觉 embedding 却没有同步 attention mask、position id 或 label mask，模型可能能够运行，却在错误位置计算 loss。

多轮样本还要明确图片的作用域。一张图片可以只服务于紧随其后的问题，也可以在后续轮次继续可见；这两种语义需要不同的序列组织和缓存策略。把图片重复插入每一轮会增加 token 成本，完全不重复又可能让后续问题失去视觉条件。训练数据中应保留 `image_id`、轮次和引用关系，便于对“模型是否真的使用了这张图”做反事实检查。

### 4.4 label mask 与监督泄漏

assistant-only loss 的形式如下：

```math
L_{\mathrm{mm\_sft}}
=-\frac{1}{\sum_{t=1}^{T}m_t}
\sum_{t=1}^{T}m_t
\log p_\theta(y_t\mid I,x_{<t}),qquad
\sum_{t=1}^{T}m_t>0
```

`I` 是图像、音频或视频等条件，`x_{<t}` 是此前已经放入上下文的 token，`m_t` 只在目标回答位置取 1。这里不使用 `\max(1,\cdot)` 把空监督伪装成可训练样本；应把空 label 的样本数、发生阶段和原始 id 记录到数据审计中。分母使用有效监督 token 数，是为了避免不同回答长度改变样本的权重；如果工程实现采用固定 token 数或按样本平均，必须明确那是另一种加权策略。

至少有三种位置经常被误算进 loss：视觉 placeholder、用户问题和 padding。把用户问题也作为目标并非绝对错误，例如做多轮语言建模时可以有意监督完整对话；错误在于数据意图与 mask 不一致。更隐蔽的错误是把 OCR 标注、工具结果或图片描述作为“用户提供的证据”放入上下文，却在没有标记来源的情况下监督模型复读它。这样得到的 loss 可能很好，但模型并没有学会从图像中恢复证据。

工程上常把忽略位置的 label 写为 `-100`，交给交叉熵实现跳过。审核一个多模态 batch 时，应打印一条样本的 token、role、placeholder 展开数量和 label mask，而不是只检查 batch shape。形状正确只能说明张量能相乘，不能证明监督落在了正确的位置。

## 5. 图像 caption 和 VQA

图像 caption 任务让模型描述图片。

VQA 任务让模型回答关于图片的问题。

这两者看似相近，但训练重点不同：

| 任务 | 强调 |
| --- | --- |
| Caption | 全局语义、描述流畅性 |
| VQA | 局部细节、问答准确性 |

### 5.1 Caption 训练

输入是图像，输出是描述文本。

模型要学会：

1. 识别主要物体。
2. 把视觉内容转成自然语言。
3. 避免无中生有。

### 5.2 VQA 训练

输入是图像加问题，输出是答案。

模型要学会：

1. 根据问题关注局部区域。
2. 结合视觉和文本推理。
3. 回答简洁准确。

### 5.3 常见问题

1. 幻觉。
2. OCR 错误。
3. 计数错误。
4. 空间关系错误。
5. 对小字、遮挡和图表不敏感。

### 5.4 为什么 caption loss 不能代表 VQA 能力

caption 往往允许多个自然语言答案。一个 caption 写“桌上有几本书”，另一个 caption 写“桌面上放着书本”，两者都可能正确，但 token-level cross-entropy 会把参考句的具体措辞当作唯一目标。VQA 的答案空间更窄，问题还会把注意力指向局部对象、数量、颜色或关系。一个模型可能生成流畅 caption，却无法回答“左边的杯子里有几支笔”。

因此训练和评估应拆开看。caption 可以结合 CIDEr、SPICE、人工事实性抽样和对象覆盖率；VQA 可以使用 exact match、规范化字符串匹配、数值容差和按问题类型分层的准确率。对开放式答案，字符串相同不等于事实正确，字符串不同也不一定错误。比如 `128元`、`128 元` 和 `总价是 128 元` 需要先规定规范化规则。

一个简单的按任务分层统计可以写成：

```math
\mathrm{Acc}_{\mathrm{all}}
=\sum_{k\in\mathcal{K}}w_k\,\mathrm{Acc}_k,
\qquad
\sum_{k\in\mathcal{K}}w_k=1
```

`k` 可以是计数、OCR、空间关系和常识问题，`w_k` 是业务选择的非负权重。只有当 `\mathcal{K}` 非空、权重和为 1，且每个有正权重的切片都有可评分样本时，这个总分才有定义；没有 OCR 标注的版本不能靠把 `\mathrm{Acc}_{\mathrm{OCR}}` 填成 0 或 1 来制造一个总分。报告总准确率时必须同时报告各分层结果，否则大量容易的描述题会掩盖少量但关键的金额、日期或否定问句错误。

幻觉也不应只靠一句“答案看起来不对”来统计。若数据带有区域标注，可以检查答案中的实体是否能在对应区域找到；若没有区域标注，至少要保留人工可复核的证据样本，并区分“视觉识别错”“推理错”和“语言补全造成的臆测”。这三类错误的修复路径完全不同。

## 6. OCR 和文档理解

OCR 是多模态训练中的高频任务。

文档理解比普通图像理解更复杂，因为它不仅要识别文字，还要理解版式和结构。

### 6.1 训练数据

1. 票据。
2. 表格。
3. 截图。
4. 表单。
5. PDF 页面。
6. 带布局的扫描文档。

### 6.2 训练目标

1. 文字识别。
2. 结构抽取。
3. 布局理解。
4. 表格填充。
5. 关键信息抽取。

### 6.3 难点

1. 小字。
2. 倾斜。
3. 模糊。
4. 多栏布局。
5. 表格跨行跨列。
6. 文本和视觉证据对齐。

OCR 和文档理解训练的关键，不只是识别文字，还要把文字、布局和语义放在同一个证据链中建模。

### 6.4 文档样本的三种监督

文档模型至少可能接收三类监督。第一类是字符或 subword 转写，要求输出内容正确；第二类是 bounding box 或 reading order，要求文字与页面位置对应；第三类是字段、表格和关系抽取，要求模型知道“这个数字是什么字段的值”。只做第一类监督，模型可能把页面文字读出来，却把表头、脚注和正文的关系弄错。

一个文本框可以表示为：

```math
b_i=(x_i^{(0)},y_i^{(0)},x_i^{(1)},y_i^{(1)},s_i,r_i)
```

其中四个坐标描述矩形，`s_i` 是文本内容，`r_i` 是区域角色或结构标签。为了跨分辨率比较，坐标通常归一化到 `[0,1000]` 或 `[0,1]`；这只是编码约定，不是更精确的真实坐标。训练前要统一旋转、裁剪、坐标原点和阅读顺序，否则模型学到的会是标注工具的差异。

坐标协议还应保证 `x_i^{(0)}<x_i^{(1)}`、`y_i^{(0)}<y_i^{(1)}`，并明确边界是闭区间、开区间还是像素中心坐标。文本为空的框、越界框和旋转后未同步变换的框不能与正常布局监督混在一起；它们要么是可修复的解析错误，要么是被剔除并保留原因的样本。否则区域 grounding 的失败无法区分是视觉模型没有定位，还是标签根本没有描述一个有效区域。

表格尤其容易出现“字符准确但业务错误”。例如模型读出了 `128` 和 `100`，但把 `128` 放到了税额列，把 `100` 放到了含税总额列。评估时应分别统计字符错误、单元格坐标错误、行列关系错误和最终字段准确率。对于关键字段，最终字段准确率比整页 OCR 的平均字符准确率更能反映系统价值。

文档图像还会把隐私和授权问题带入训练：身份证号、病历、合同和发票可能包含个人信息或商业秘密。脱敏不能只做字符串替换，还要检查图像中的文字是否仍可被恢复、原图和裁剪图是否残留、元数据是否泄露来源。数据集版本应保留脱敏规则、抽样复核结果和删除记录，这些信息本身不需要进入模型输入，但必须能支持事后追查。

### 6.5 OCR pipeline、布局模型和 OCR-free 生成各自解决什么

文档路线的关键选择不是给所有系统贴一个“端到端”标签，而是决定文字从哪里来、空间关系在哪里表示，以及训练标签如何验证。假设一张收据上同时有“税额 8 元”和“含税总额 128 元”，系统只输出两个字符正确的数字还不够；还要确认字段关系没有交换。

| 路线 | 输入与训练信号 | 主要解决的问题 | 代价与失败条件 |
| --- | --- | --- | --- |
| OCR 引擎 + 语言/布局模型 | OCR 先产生文字和框，再用文本、位置及图像特征做字段/问答训练 | 可复用成熟 OCR，容易审计文字和坐标；适合有稳定 OCR、需要显式文本证据的系统 | OCR 的漏字、错字和阅读顺序错误会传给下游；多语言、手写、表格和低分辨率场景需要单独验证 |
| [LayoutLMv3](https://arxiv.org/abs/2204.08387) | 外部 OCR 文字和 bounding box 与图像 patch 同时输入；以 MLM、MIM 和 word-patch alignment 预训练 | 让文本重建、视觉 patch 重建与文字-图像局部对应共享目标，兼顾 text-centric 与 image-centric 文档任务 | 仍依赖 OCR 和位置标注；局部对齐分数不能自动保证业务字段抽取正确。作者的 ablation 报告 WPA 在其任务中稳定带来收益 |
| [Donut](https://arxiv.org/abs/2111.15664) | 直接从文档图像自回归生成文本或 JSON；用合成文档读序列预训练，再对下游结构输出做 cross-entropy | 绕开外部 OCR 工具和 OCR 错误传播；适用于可将目标字段规范成 token 序列的抽取任务 | 高分辨率、生成长度和版式变化仍是成本/准确率约束；JSON 字段格式有效不代表内容被正确定位。作者的 SynthDoG 用英文、韩文、日文 Wikipedia 文本各生成 400K 文档，合成覆盖不能代替真实域审计 |
| [Pix2Struct](https://arxiv.org/abs/2210.03347) | 将截图解析为简化结构文本；variable-resolution patches 保留纵横比，并先做阅读 warmup，再做 screenshot parsing | 为文档、图表、UI 等 visually-situated language 提供纯视觉的预训练目标，同时减少固定 resize 对极端长宽比的损伤 | 不依赖 OCR 也需要足够的像素分辨率和较长 patch/decoder 序列；预训练数据需要网页截图与结构化页面来源，迁移到非网页文档需验证 |

这些方法给出了“文字识别”之外的训练信号差异。LayoutLMv3 把 OCR 词与图像 patch 的对应关系显式放进预训练目标；Donut 把字段结构本身作为生成目标；Pix2Struct 从页面截图重建结构化内容，再迁移到具体问答/解析任务。若业务要求审计每个数字来自哪个区域，保留 OCR/box 或加 grounding 目标通常更易追踪；若 OCR 引擎在目标语言或表格上经常失效，OCR-free 路线值得比较，但必须用高分辨率真实文档验证。

Pix2Struct 论文提供了一个可解释的消融例子：base 模型总计 100K 预训练步，其中 30K 是读文字 warmup、70K 是 screenshot parsing；DocVQA 验证 ANLS 在完整配方为 67.8，移除 screenshot parsing 后为 12.2。作者据此指出，学会读线性文字并不足以理解页面结构。该论文同一评测表中，Pix2Struct-Large 在 DocVQA 报告 76.6 ANLS、Donut 67.5；在 InfographicVQA 报告 40.0 和 11.6。数字只对应原文的模型、输入分辨率、任务协议和 benchmark 划分，不能推广成所有 OCR-free 模型都优于 OCR pipeline。纯文本基线在该论文的两个文档任务也取得很高 ANLS，提醒我们先检查答案是否能从页面语言先验猜出，再判断模型有没有使用图像证据。

## 7. 语音训练

语音模型常见训练包括 ASR、TTS 和语音问答。

### 7.1 ASR

ASR 的目标是把语音转成文本。

训练时需要处理：

1. 音频特征提取。
2. 对齐。
3. 长音频切分。
4. 噪声和口音。

如果音频采样率是 `f_s`，时长是 `L` 秒，特征提取的 frame shift 是 `h` 个采样点，那么帧数大致是：

```math
N_{\mathrm{frame}}\approx \left\lceil \frac{L f_s}{h}\right\rceil
```

这里 `L>0`、`f_s>0`、`h>0`，并且 `L` 的秒、`f_s` 的采样/秒和 `h` 的采样/帧必须使用同一时钟语义；固定窗长和边界 padding 会让实际帧数与近似式相差一两帧。零时长、无法解码或采样率未知的音频不应给出“0 帧训练样本”，而应在数据阶段被标成不可训练。比如 16 kHz 音频、20 ms frame shift 时，`h=320`，3.2 秒音频约有 160 帧。帧数决定 encoder 侧序列长度，也会影响流式 ASR 的 chunk size、首包延迟和长音频切分策略。

### 7.2 语音问答

语音问答通常是：

```text
音频 -> 转写 -> 文本理解 -> 生成答案
```

或者端到端直接从音频到文本答案。

### 7.3 难点

1. 噪声。
2. 口音。
3. 方言。
4. 数字和专有名词。
5. 长音频。
6. 流式输出和低延迟。

### 7.4 ASR 的监督目标

语音识别不只有一种训练目标。若声学 encoder 在每个时间帧输出分布，CTC 通过插入 blank 和允许重复路径，把帧序列折叠成目标文本。其目标可以写为：

```math
L_{\mathrm{CTC}}
=-\log\sum_{\pi\in\mathcal{B}^{-1}(y)}
\prod_{t=1}^{T_a}p_\theta(\pi_t\mid h_t)
```

`h_t` 是第 `t` 个声学帧的表示，`\pi` 是包含 blank 的对齐路径，`\mathcal{B}` 把重复符号和 blank 折叠成文本 `y`。CTC 不需要人工逐帧对齐，适合单调的输入输出关系，但它对复杂的跨句语言建模和非单调结构表达有限。

这条 CTC loss 只有在 `\mathcal{B}^{-1}(y)` 非空时才有意义：声学帧数必须足以容纳目标字符及相邻重复字符所需的 blank，所有帧分布还必须定义在同一词表和 blank id 上。目标文本为空、截断后声学帧为零或字典版本不一致时，应分别按任务协议处理，不能让库函数返回一个数后就假设对齐正确。

编码器-解码器 ASR 则直接建模：

```math
L_{\mathrm{seq2seq}}
=-\sum_{u=1}^{U}
\log p_\theta(y_u\mid y_{<u},a_{1:T_a})
```

`a_{1:T_a}` 是声学表示，`U` 是输出 token 数。Whisper 属于公开的 encoder-decoder 语音识别路线，它把多种语音任务统一到带任务提示的序列生成中；这类模型灵活，却需要处理 teacher forcing、解码延迟和幻觉转写。流式产品还常用 RNN-T 或其他 chunk-aware 目标，在准确率和首包时延之间取舍。不能因为两者都输出文字，就把 CTC、seq2seq 和 transducer 的训练假设混为一谈。

对 token-level seq2seq 平均 loss，还要单独指定 `U>0`、EOS 是否计入目标、padding mask 和样本加权方式。转写为空在某些静音检测任务里可能是有效标签，但它不应被默认当成普通语音识别样本；数据 schema 必须区分“静音”“转写缺失”和“转写为空”。

### 7.5 CTC、RNN-T 与 attention seq2seq 的对齐假设

三种目标都能把声学序列映射为文字，但它们对输出历史和时间对齐的处理不同。

| 目标 | 训练时对齐怎么处理 | 主要优势 | 代价与适用边界 |
| --- | --- | --- | --- |
| CTC | 每一帧在 token 与 blank 上输出分布；把会折叠成同一文本的单调路径概率相加 | 不需要逐帧标注；可配合流式/分块 encoder；动态规划结构清楚 | 同一帧分布在给定 encoder 表示后不显式依赖已输出文本；输出依赖常交给外部语言模型或 decoder 补充 |
| RNN-T | 声学 encoder 表示 `h_t` 与已输出前缀表示 `g_u` 进入 joint network，在 `(t,u)` 格点选择 blank 或下一个 token，再对有效路径求和 | 允许当前输出依赖已生成前缀；配合因果/分块 encoder 可增量识别 | 需要沿时间×输出长度格点做 forward-backward，训练、搜索和状态缓存更复杂；高帧数/长输出会扩大格点 |
| Attention encoder-decoder（如 Whisper） | decoder 根据已生成文本和声学 encoder 表示自回归生成目标 token | 直接使用输出语言上下文，任务提示也可以作为条件；适合统一多种转写/翻译目标 | 常见双向 encoder 需要看到较大音频窗口，流式化需另行设计；生成式 decoder 仍可能漏词、重复或幻觉 |

CTC 的最小对齐例子能暴露一个常被忽略的定义域条件。若字符级目标是 `book`，两个相邻的 `o` 必须由 blank 分开；最短可行帧路径至少是 `b, o, blank, o, k`，所以 4 帧输入不可能表示这个目标。真实 tokenizer 若把 `oo` 合成单个 token，最短长度又会不同，判断要依据模型实际词表，而不是文本字符数。

RNN-T 则可以用格点规模估算它多出的计算状态：若 encoder 有 `T=160` 帧、目标有 `U=20` 个 subword，动态规划大约要处理 `T×U=3,200` 个内部时序/前缀位置，另外还要处理边界和每个位置的类别分布；实现可能做剪枝或块化，所以这只是格点量级，不是 FLOPs。CTC 与 RNN-T 的原始工作都旨在免去人工逐帧对齐，但机制不同（[CTC 原论文](https://www.cs.toronto.edu/~graves/icml_2006.pdf)、[RNN-T 原论文](https://arxiv.org/abs/1211.3711)）。Whisper 则是规模化弱监督 encoder-decoder 路线，论文的模型、语种、切窗和解码协议共同决定其报告结果（[Whisper 原论文](https://arxiv.org/abs/2212.04356)）。

因此选目标时先问产品要不要低延迟 partial transcript、是否必须保留人工可审计的转写、数据有没有可靠转写、encoder 是否因果/分块、输出词汇是否长且依赖上下文。CTC 的帧级条件独立有利于简单解码，RNN-T 显式建模已输出前缀，seq2seq 更自然地利用长上下文；这是一组训练与推理约束的取舍，不是脱离数据和硬件的固定排名。

### 7.6 语音错误如何传到下游

最常见的级联系统是 `audio -> ASR -> LLM -> answer`。若 ASR 把“不要删除”转成“要删除”，下游语言模型看到的已是错误文本，后面的推理再流畅也无法恢复原意。可以把级联系统的一个粗略错误分解写成：

```math
P(\mathrm{answer\ correct})
\approx P(\mathrm{ASR\ correct})
\cdot P(\mathrm{reasoning\ correct}\mid\mathrm{ASR\ correct})
```

这不是严格独立性定律，而是提醒我们分别记录 ASR 和下游问答的条件表现。WER 的基本形式为：

```math
\mathrm{WER}=\frac{S+D+I}{N_{\mathrm{ref}}}
```

其中 `S`、`D`、`I` 分别是替换、删除和插入数，`N_ref` 是参考词数。对中文、数字、专有名词和代码口令，分词方式会显著影响 WER，因此应同时报告 CER、关键实体准确率和任务成功率。一个总体 WER 很好的模型，仍可能在药名、金额或否定词上风险很高。

WER 要求 `N_{\mathrm{ref}}>0`。纯静音或没有人工参考转写的样本不能被加进这个分母；它们可以另报 false-accept、端点错误或静音拒识率。中文的 CER 也需要固定字符规范化、数字读法和标点处理，否则模型版本之间的“WER 改善”可能只是评测预处理变了。

端到端语音问答可以避免显式转写瓶颈，但会牺牲可解释性和独立替换 ASR 的灵活性；级联系统容易检查中间文本，却会把转写错误固化为下游事实。选择哪条路线取决于是否需要字幕、审计、搜索和人工纠错，而不是简单追求“端到端”这个标签。

## 8. 视频训练

视频比图像更难，因为它包含空间和时间两种结构。

训练时要处理：

1. 帧采样。
2. 时间建模。
3. 长序列显存。
4. 动作和事件理解。
5. 时序一致性。

如果每帧图像大小是 `H*W`，patch size 是 `P`，采样 `F` 帧，那么视觉 patch token 数近似为：

```math
N_{\mathrm{video}}
=F\cdot
\left\lceil\frac{H}{P}\right\rceil
\cdot
\left\lceil\frac{W}{P}\right\rceil
```

标准 full attention 的 score cell 数量随序列长度近似二次增长：

```math
C_{\mathrm{attn}}\propto N_{\mathrm{video}}^2
```

这里 `F,H,W,P` 都应为正，`P` 的单位必须与 `H,W` 相同。该式只描述 self-attention score 的主要增长项，不包含投影、MLP、视觉编码器、跨注意力、checkpointing 和 kernel 的常数；因此不能把它直接换算成某张 GPU 的精确显存。视频训练常常需要帧采样、时空下采样、latent space 训练、局部/稀疏时序建模或专门的视频 diffusion 架构，否则 token 数和显存会很快失控。

视频任务包括：

1. 视频描述。
2. 视频问答。
3. 事件理解。
4. 视频生成。
5. world model 相关任务。

视频训练的难点不仅是看懂单帧内容，更是理解时序关系和长上下文中的事件演化。

### 8.1 空间 token 和时间 token

前面的估算假设每一帧独立切成二维 patch。若模型使用时间 tubelet，把连续 `P_t` 帧合成一个时空块，则 token 数更接近：

```math
N_{\mathrm{video}}
=\left\lceil\frac{F}{P_t}\right\rceil
\left\lceil\frac{H}{P_h}\right\rceil
\left\lceil\frac{W}{P_w}\right\rceil
```

`F` 是抽取的帧数，`P_t`、`P_h`、`P_w` 分别是时间和空间块大小。提高帧率可以帮助识别快速动作，却会增加序列长度；降低空间分辨率节省显存，却可能抹掉字幕和小物体。训练数据中还要记录原始 fps、采样 fps、起止时间和裁剪窗口，否则“模型没学会动作”与“采样阶段根本没有保留动作”很难区分。

这个估算同样要求各 patch/tubelet 尺寸为正整数；如果采样窗口的时长、fps 和 `F` 对不上，必须规定是向上取整、丢弃尾帧还是补帧。对动作和事件任务，这个尾部策略本身会改变标签对齐，不能只把它藏在数据 loader 的默认参数里。

### 8.2 视频理解与视频生成不是同一个问题

视频理解通常把视频编码成表示，再生成字幕、答案或事件标签；视频生成则要从文本或其他条件构造一段新的时空信号。前者重点是证据召回、时间顺序和事件边界，后者还要满足跨帧身份、运动轨迹、物理连续性和画面质量。

一个视频问答样本可以附带事件区间 `[t_s,t_e]`。如果模型回答的是“什么时候有人打开门”，只看整段视频的全局 embedding 可能不足，训练或评估需要检查预测区间与参考区间的时间交并比：

```math
\mathrm{tIoU}
=\frac{|[\hat t_s,\hat t_e]\cap[t_s,t_e]|}
{|[\hat t_s,\hat t_e]\cup[t_s,t_e]|}
```

这里两个区间都要求起点不晚于终点，且并集长度大于零；需要先约定端点单位是秒、帧号还是归一化位置。对没有时间标注的问题，tIoU 未定义，不能把它记作 0 后与有标注事件平均。视频生成还存在“单帧好看、连续播放不稳定”的问题。相邻帧的像素差很小不一定代表运动正确，运动模糊也可能让像素差看起来很小；评估应同时观察视觉质量、运动一致性、文本条件遵循和人工 bad case。公开视频数据的版权、人物肖像、训练-测试重合和可识别事件风险，也不能被算力讨论掩盖。

### 8.3 变长视频怎样进入同一训练批次

固定帧数的数据管线通常要丢弃很短的视频、截断较长视频，或把不同长度补到同一形状。补齐的 padding 会占计算但没有新视频内容，丢弃/截断则可能删掉动作起因或结尾。CogVideoX 论文将 mixed-duration training 与 Multi-Resolution Frame Pack 结合，把不同帧数和分辨率的视频放进同一个打包 batch；论文还使用 3D causal VAE、3D attention、渐进分辨率训练和视频 captioning pipeline 处理序列长度、时空建模和弱 caption 问题（[CogVideoX 原论文](https://arxiv.org/abs/2408.06072)）。

| 批处理方案 | 解决的问题 | 未解决的限制 |
| --- | --- | --- |
| 固定帧数/分辨率 | batch tensor 形状规则，实现和 kernel 优化简单 | 长短视频都可能被丢帧或补齐；短片和长片分布被人为拉齐 |
| 按长度/分辨率分桶 | 减少 padding 浪费，保持批次形状较规则 | 桶边界会影响采样分布；长尾长度仍有浪费，重采样后要审计每类视频的曝光比例 |
| Frame Pack 一类变长打包 | 尽量同批利用不同长度/分辨率样本，减少固定时长对数据的限制 | 需要正确隔离样本的注意力与位置索引；本身不消除注意力随总 token 数增长的成本，也不证明时间事件被学对 |

以当前公式做一笔教学预算：8 帧 `224×224`、patch `16` 时有 `8×14×14=1,568` 个 patch；16 帧 `448×448` 时有 `16×28×28=12,544` 个，token 数是前者的 8 倍。若把全序列送入普通 full attention，score cell 量级则约为 `8²=64` 倍。Frame Pack 能改善不同样本形状下的利用率，不能把这 64 倍的注意力账单变成零；3D VAE 压缩、局部/分块 attention、帧采样和分辨率策略要分别算。

CogVideoX 还报告了按 data-parallel rank 分区的 explicit uniform timestep sampling：相较每个 rank 独立随机采样扩散时间步，它在论文设置中让 timestep 损失曲线更稳定，40K step 的多个时间点验证 loss 都略低。该结果提示采样噪声可能让时间步覆盖短期不均匀，但这是特定训练 recipe 的消融，不能推导出所有视频模型都需要 rank 分区采样。

## 9. Diffusion 训练

Diffusion 模型是图像和视频生成的重要路线。

### 9.1 训练目标

核心是学习去噪：

```text
给定加噪后的样本，预测噪声或还原原始样本
```

### 9.2 训练流程

1. 从真实图像采样。
2. 随机加噪到某个时间步。
3. 让模型预测噪声或 denoised 表示。
4. 用重建损失训练。

DDPM 风格训练常用的 forward noising 可以写成：

```math
x_t=\sqrt{\bar{\alpha}_t}x_0+\sqrt{1-\bar{\alpha}_t}\epsilon,
\qquad \epsilon\sim\mathcal{N}(0,I)
```

模型学习从 `x_t`、时间步 `t` 和条件 `c` 中预测噪声：

```math
L_{\mathrm{diff}}
=
\mathbb{E}_{x_0,t,\epsilon}
\left[
\left\|\epsilon-\epsilon_\theta(x_t,t,c)\right\|_2^2
\right]
```

其中 `c` 可以是文本 prompt、类别、图像条件或其他控制信号。给定离散 schedule 时，训练时间步应属于合法集合，`0\leq\bar\alpha_t\leq1`，`x_0`、`\epsilon` 和模型输出的 shape 必须一致且为有限值；否则平方误差没有可解释的物理或数值含义。Latent Diffusion 的核心工程动机是先把图像压到 latent space，再在 latent 上做 diffusion，从而降低高分辨率图像生成的训练和采样成本。

### 9.3 难点

1. 训练慢。
2. 采样慢。
3. 对噪声 schedule 敏感。
4. 数据和 prompt 对齐要求高。

Diffusion 训练的核心是学习逐步去噪，而不是像语言模型那样直接做 next-token prediction。

### 9.4 `epsilon`、`x_0` 和 `v` 预测

同一个 forward noising 过程可以配合不同的预测参数化。模型可以预测噪声 `\epsilon`，也可以预测原始样本 `x_0`，或者预测常见的 velocity 表示 `v`。它们不是三套互不相关的扩散过程，而是对同一个信号和噪声分解采用不同的训练坐标。选择哪一种会影响不同时间步的数值尺度、损失权重和采样器实现。

写成 `epsilon` 预测时，基本目标是：

```math
L_{\epsilon}=\mathbb{E}_{t,x_0,\epsilon}
\left[w(t)\,\|\epsilon-\epsilon_\theta(x_t,t,c)\|_2^2\right]
```

`w(t)` 是时间步权重。若所有时间步等权，模型可能在视觉上容易的噪声区间取得较好损失，却没有同样重视高噪或低噪区域的任务效果；实际系统可能按 SNR、参数化方式或经验重新加权。报告 diffusion 训练结果时，不能只写“用了 MSE”，还要说明时间步采样、`beta` schedule、预测参数化和权重。

`w(t)` 应为非负有限权重，且有效时间步上的总权重不能为零；若某个时间区间被设成零权重，报告中要明确它不参与该项训练。`\epsilon` 是扩散噪声的符号，不是为了掩盖空分母或数值故障而随意加入的常数，这一点与训练指标中的稳定项必须区分。

为了看清预测目标和时间步权重的关系，定义 `a_t=√ᾱ_t`、`σ_t=√(1-ᾱ_t)`，则 `x_t=a_t x_0+σ_t ε`。常见 velocity 参数化定义为 `v_t=a_t ε-σ_t x_0`，这是干净信号与噪声的线性旋转；从 `(x_t,v_t)` 可以反解 `x_0=a_t x_t-σ_t v_t`、`ε=σ_t x_t+a_t v_t`。因此三种预测目标在数学上可互换，但由于目标尺度和误差转换系数不同，同一个裸 MSE 不会给不同 timestep 相同的梯度权重。

Min-SNR-`γ` 把扩散训练看成多个 timestep 任务共享参数时的梯度冲突问题，并按 SNR 截断权重。令 `SNR_t=ᾱ_t/(1-ᾱ_t)` 且 `γ>0`，作者按预测参数化给出：

```math
\lambda_{x_0}(t)=\min(SNR_t,\gamma)
```

```math
\lambda_{\epsilon}(t)=\frac{\min(SNR_t,\gamma)}{SNR_t},\qquad
\lambda_v(t)=\frac{\min(SNR_t,\gamma)}{SNR_t+1}
```

当 `SNR_t=0` 时，`λ_ε` 按连续极限取 1，避免除零。手算 `γ=5`：`SNR=100` 时三种目标的权重分别为 `5`、`0.05`、`5/101≈0.0495`；`SNR=0.1` 时分别为 `0.1`、`1`、`0.1/1.1≈0.0909`。这些系数乘在各自参数化的平方误差上，不是三种模型梯度可以直接横比的尺度。

原论文把不同噪声时间步的梯度方向冲突作为收敛慢的一个来源，在 ImageNet `256×256`、ViT-B 设置报告 Min-SNR-5 达到 FID 10 的迭代数约快 3.4 倍，并报告 FID 2.06 的作者结果（[Min-SNR-`γ` 原论文](https://arxiv.org/abs/2303.09556)）。这些数字绑定其数据、网络、schedule、采样器和评估方式。CogVideoX 在其视频生成配方中选用 `v` prediction 与 zero-terminal-SNR schedule，是一个公开模型案例，不构成对其它图像/视频任务的普遍最优证明（[CogVideoX 原论文](https://arxiv.org/abs/2408.06072)）。

### 9.5 条件控制和 latent space

文本条件通常先由文本 encoder 变成 context，再通过 cross-attention 或其他条件注入方式影响 denoising network。classifier-free guidance 常通过训练时随机丢弃条件，使同一个模型学到有条件和无条件预测；推理时再组合：

```math
\hat\epsilon
=\epsilon_\theta(x_t,t,\varnothing)
+s\left(\epsilon_\theta(x_t,t,c)-
\epsilon_\theta(x_t,t,\varnothing)\right)
```

`s` 是 guidance scale。它通常提高条件遵循，但过大时会带来过饱和、细节失真或多样性下降。这里的 `s` 与前面 CLIP 的 logit scale 只是同名符号，语义完全不同，实际代码中应使用不同变量名。

两次预测必须来自相同的 `x_t`、时间步、网络参数和输出 shape；`s` 是有限的 guidance 系数，常取非负值。训练阶段是否进行了条件 dropout、dropout 概率是多少、无条件分支如何表示，都会决定这条推理式是否适用。没有训练无条件分支时，不能在推理时凭空套用 classifier-free guidance。

Latent Diffusion 先用 VAE 将像素 `x` 压缩为 latent `z=E(x)`，在 `z` 上加噪和去噪，最后用 decoder 恢复图像。它节省的是扩散网络处理的空间尺寸，不会自动消除 VAE 编码器丢失的细节；小字、细线和精确几何关系仍可能在压缩环节受损。DiT 则把 latent patch 或 token 交给 Transformer，训练成本还取决于 latent 序列长度、层数和 attention 实现，不能简单用“Transformer 比 U-Net 贵”概括。

### 9.6 图像 diffusion 与视频 diffusion 的额外约束

视频 diffusion 可以把时间维度加入 latent 或 denoising block，但训练样本更大，且单帧质量目标不足以保证跨帧一致。常见工程折中包括：先在图像数据上获得空间生成能力，再用视频片段学习时间模块；采用短片段和分层采样；对相邻帧、光流或轨迹加入一致性约束；在高分辨率阶段使用更少的帧或更低的时间带宽。具体结构依论文而异，应该根据公开方法描述确认，而不是把所有视频模型都称作同一种“时空 diffusion”。

## 10. 多模态数据组织

多模态训练最难的是数据格式。

常见样本可能包括：

```json
{
  "id": "sample_001",
  "image": "...",
  "audio": "...",
  "video": "...",
  "text": "...",
  "task": "vqa",
  "answer": "...",
  "metadata": {
    "domain": "ocr",
    "difficulty": "medium"
  }
}
```

需要特别注意：

1. 模态文件路径或二进制存储。
2. 对齐关系。
3. 采样率和分辨率。
4. 截断策略。
5. 元数据和标签。

可以把多模态样本抽象成：

```math
z_i=(m_i,x_i,y_i,a_i,c_i)
```

其中 `m_i` 是模态集合，例如 image/audio/video/text；`x_i` 是输入内容或文件引用；`y_i` 是答案、caption 或转写；`a_i` 是对齐信息，例如图文是否匹配、音频时间戳、OCR box 或视频事件区间；`c_i` 是任务和元数据。数据审计的目标不是只看字段非空，而是检查模态、文本、答案和证据是否真的对齐。

这个抽象要求每个训练目标都能找到相应的证据字段：VQA/OCR 至少要有图像引用、问题、答案和对齐状态；ASR 要有可解码音频和转写协议；时间定位要有同一时间单位下的事件区间。`m_i` 写了 `video`、`a_i` 却没有采样窗口，或答案只来自模板常识而没有证据引用，都不是可由模型结构补救的训练样本。数据 loader 可以跳过此类记录，但必须把 id、原因和跳过后各任务的实际比例写进 manifest。

### 10.1 从文件存在到样本可训练

多模态数据的失败常发生在模型之前。一个图片路径存在，不代表文件能被解码；音频能播放，不代表采样率和声道符合特征提取器的假设；视频 metadata 有时长，不代表中间帧没有损坏。数据处理应把问题分成几个阶段记录：

1. **可访问性**：文件是否存在，权限和 URI 是否有效。
2. **可解码性**：图片、音频、视频是否能被稳定读取，是否出现空帧或异常时长。
3. **规范化**：颜色空间、尺寸、采样率、声道、fps、旋转元数据是否统一。
4. **语义完整性**：问题、答案、caption、转写和区域或时间标注是否匹配。
5. **授权与隐私**：来源、许可、个人信息和删除请求是否有记录。

这些状态最好与样本版本绑定，而不是只在一次离线脚本的日志里出现。否则同一 `id` 在重采样后换了媒体文件，训练曲线仍然能跑，却无法解释结果为什么变化。

### 10.2 归一化和成本记录

不同模态的“一个样本”成本差别很大。可以为每个样本记录一个近似成本向量：

```math
c_i=(N_{\mathrm{text}},N_{\mathrm{image}},N_{\mathrm{audio}},
N_{\mathrm{video}},r_i)
```

其中前四项是进入各编码器的 token、帧或特征长度，`r_i` 可以记录分辨率、时长等影响计算的原始量。它不是统一的 FLOPs 计量，但能帮助 sampler 避免把很多长视频和高分辨率文档随机放入同一个 batch。更精确的预算还应乘以各模块的 hidden size、层数、精度和并行方式。

成本向量的每个计数都应是非负有限数，且至少有一个与任务相关的模态长度为正；否则“零成本多模态样本”通常只是解码或预处理失败。不同模态的计数不能直接相加后宣称得到统一 token 数，除非先说明权重来自哪个 encoder、哪种 precision 和哪个实际 profile。它适合做分桶和异常检测，不替代峰值显存或训练吞吐测量。

采样器若只按样本条数组 batch，可能出现一个 batch 中只有一条长视频，其他样本被迫等待显存；若只按 token 数截断，又可能让短文本任务过度采样。常见做法是按模态成本分桶，再在桶内做动态 batch，同时为每种任务设置最低采样比例。采样比例、截断比例和被跳过样本数都应进入实验记录，因为它们会改变实际训练分布。

### 10.3 媒体内容与对话模板的版本关系

媒体预处理器、tokenizer、chat template 和模型 checkpoint 是一个整体协议。修改图片 resize 的短边、音频 mel 的窗长、视频采样 fps 或 special token id，都可能使旧 checkpoint 的输入分布发生变化。数据 manifest 至少应保存预处理版本、媒体哈希、文本模板版本、标签 schema 和任务类型。

出现训练回归时，先比较同一媒体和同一文本经过新旧 pipeline 的中间结果，通常比直接重跑整个训练更快定位问题。尤其要警惕“模板能渲染”与“监督位置正确”之间的差别：渲染出来的对话可能很自然，但 assistant 起始位置错一位，所有梯度都会落到错误 token 上。

### 10.4 数据混合与样本筛选不是同一个旋钮

数据混合决定训练中看见哪类任务，样本筛选决定某个候选池中的哪些内容先进入训练；改变两者都会改变实际训练分布。设任务 `k` 的采样概率为 `p_k`、任务内平均损失为 `L_k`、显式损失权重为 `λ_k`，则一个简化的期望目标是：

```math
L(\theta)=\sum_{k=1}^{K}p_k\lambda_k\,\mathbb{E}_{x\sim D_k}[\ell_k(\theta;x)]
```

若 caption、VQA、OCR 的采样比率为 `0.90/0.09/0.01`，显式权重为 `1/1/10`，它们在标量目标中的系数质量是 `0.90/0.09/0.10`。这不代表最终参数更新贡献相等：各任务 loss 尺度、梯度范数、梯度方向和 token reduction 都可能不同。因此需要同时记录原始样本数、经过过滤后的采样率、有效监督 token、按任务 loss 和梯度统计；不能只根据混合百分比判断“模型学到了多少 OCR”。

| 研究/配方 | 解决的训练问题 | 公开设计与证据 | 使用时要保留的边界 |
| --- | --- | --- | --- |
| [MM1](https://arxiv.org/abs/2403.09611) | 单一图文 caption 目标难覆盖交错图文上下文与文本能力 | 在 1.2B 消融基线里混合 captioned image、interleaved image-text、text-only；作者报告数据配比、图像 encoder、分辨率和 token 数影响明显 | 论文的 `45/45/10` 属于消融配置，不应复制成通用最佳配比；文本-only 数据也可能因任务与训练阶段而产生不同作用 |
| [SigLIP 2](https://arxiv.org/abs/2502.14786) | 纯全局对比目标对定位、dense feature 和多语言覆盖不够 | 在 sigmoid 图文目标外组合 captioning、自蒸馏、masked prediction、在线数据筛选与纵横比适配；作者在同族 encoder 评测中报告多项能力改进 | 多项策略一起加入，不能将整体提升归给其中单一目标；筛选器偏好会影响数据分布与覆盖 |
| [JEST](https://arxiv.org/abs/2406.17711) | 独立地给每条样本打分，忽略对比学习中一个 batch 内样本彼此影响 | 以模型估计 batch 的联合可学习性，再从大 super-batch 选训练 batch；作者在其多模态预训练设置报告最多约 13 倍更少迭代、约 10 倍更少计算 | 分数来自论文的模型、数据和参考分布；对大池打分本身有开销，参考数据可能让筛选偏向已覆盖分布，需同时核算筛选成本和长尾丢失 |

这里有三个不同决策：任务混合控制能力覆盖，辅助训练目标改变每个样本提供的监督，JEST 一类方法按 batch 学习难度选择样本。若 OCR 指标没有提升，先看 OCR 样本实际被采到多少、有效 label 数和字段质量；再看高分辨率有没有保住文字；最后才比较采样权重或损失。把样本比例调高但仍使用低分辨率、错误字段或错位 label，不会自动补出缺失的视觉证据。

## 11. 多模态训练中的对齐问题

多模态训练不是把所有模态独立训好就行，而是要让它们对齐。

典型对齐问题：

1. 图像和文本语义对齐。
2. 音频和文本转写对齐。
3. 视频帧和文本事件对齐。
4. OCR 文本和视觉区域对齐。
5. 问题和答案引用同一证据对齐。

如果对齐不好，模型会出现：

1. 幻觉。
2. 答非所问。
3. 只看文本不看图。
4. 只会泛泛描述，不会精确抽取。

### 11.1 全局、局部与时间对齐

图文对比学习主要提供全局对齐：整张图片和整段文字应该接近。OCR 和 grounding 需要局部对齐：某个词、实体或数字应该对应页面中的区域。视频和语音还需要时间对齐：转写片段、动作或事件要落在正确的时间区间。三者可以层层叠加，但全局相似度高不意味着局部和时间关系也正确。

可以把一条证据关系抽象成：

```math
e=(q,\,r,\,\ell,\,y)
```

`q` 是问题或查询，`r` 是区域或时间范围，`\ell` 是对齐类型，`y` 是答案或标签。训练时如果只保留 `y` 而丢掉 `r`，模型仍可能学会凭语言先验猜答案；保留 `r` 才能在评估阶段检查它是否引用了正确证据。不是每个任务都需要显式框标注，但必须知道自己缺少哪一层证据。

`r` 不是装饰性元数据：区域任务应要求有效边界框，时间任务应要求有序的起止位置，`\ell` 应来自固定标签集。没有局部或时间标注的全局 caption 仍然可以用于全局对齐训练，但不应被拿来报告 grounding 或时间定位指标。把监督等级与可验证的证据类型写进 schema，才能避免在同一个“多模态准确率”里混合根本不可比的任务。

### 11.2 用反事实样本检查“模型是否看了模态”

一个很实用的检查是替换或遮挡条件输入，观察答案是否发生符合预期的变化。把猫的图片替换成狗，回答“图里是什么动物”却不变，说明模型可能只读了问题模板或语言先验；把收据金额区域遮住，金额答案仍然完全相同，也需要进一步调查。反事实检查不能单独证明模型使用了视觉证据，因为模型可能从上下文或数据偏差中猜到答案，但它能快速发现明显的“只看文本”现象。

对齐数据还要加入 hard negative：文字相似但图片不同、图片相似但关键数字不同、视频事件顺序互换、音频中只改变一个否定词。hard negative 的价值不在于让 loss 变大，而在于逼迫模型使用任务真正需要的局部或时序信息。它也可能引入过难或错误负例，所以每类负例都要抽样复核。

### 11.3 对齐错误的定位顺序

遇到“模型只会泛泛描述”时，可以沿着证据链逐层排查：先确认媒体解码和预处理，再可视化 encoder 输出或抽样 attention/grounding，再查看 connector 的 token 数和梯度，最后检查 instruction 数据的 prompt 与 label mask。若只调大学习率或增加语言数据，通常无法修复已经丢失的视觉信息。相反，若视觉证据已经正确进入模型而答案格式错误，问题可能在 tokenizer、模板或后训练，而不在 encoder。

## 12. 多模态训练的显存和算力

多模态训练通常比纯文本更贵。

原因包括：

1. 图像和视频输入更大。
2. 视觉 encoder 额外计算。
3. 长序列更长。
4. batch 更难做大。
5. 时序建模更耗显存。

常用优化包括：

1. 冻结部分模块。
2. mixed precision。
3. activation checkpointing。
4. 更小的视觉分辨率。
5. 帧采样。
6. connector 轻量化。

如果把图像或视频 token 直接拼到语言序列前面，最粗略的 self-attention 计算量可以写成：

```math
C_{\mathrm{self}}\approx k\,B\,L\,N^2d,
\qquad N=T+N_v+N_a+N_{\mathrm{video}}
```

`B` 是 batch size，`L` 是层数，`d` 是 hidden size，`k` 汇总了投影和硬件实现的常数。这个公式用于解释趋势，不是某个 kernel 的精确 FLOPs 统计。这里 `B,L,d` 和总序列长度 `N` 都必须为正；如果某一模态在当前样本中缺失，应把相应 token 数显式设为 0 并保留模态 mask，而不是把媒体解码失败误记成免费输入。若采用文本 token 对视觉 token 的 cross-attention，主要交互项更接近 `O(TN_vd)`；如果视觉 encoder 自己先做全局 self-attention，还要另外计算视觉侧成本。工程预算必须把各模块分开，否则“LLM 没变，为什么显存翻倍”没有答案。

显存也不只由参数量决定。训练时要同时考虑视觉 encoder 的激活、视频帧的临时张量、语言模型的激活、梯度和 optimizer state。冻结视觉 encoder 可以省梯度和优化器状态，却不能让 forward 激活凭空消失；activation checkpointing 节省的是保存的中间激活，代价是反向时重算。混合精度减少部分张量的字节数，但不改变 token 数、数据读取和通信量。正确的资源分析要标记每一项到底节省了什么、增加了什么。

### 12.1 最小可运行多模态训练审计 demo

下面这个 0 依赖 demo 同时演示五件事：

1. CLIP 双向对比 loss 如何从相似度矩阵计算。
2. VLM connector 后视觉 token 和文本 token 拼接后的 shape。
3. 多模态 SFT label mask 为什么必须忽略 image token 和 prompt token。
4. Diffusion forward noising、ASR frame 数和视频 patch token 成本的直觉。
5. 多模态样本审计如何发现空答案和图文不对齐。

输入是 toy embedding、toy label mask、toy 音视频参数和 3 条多模态样本；输出是 loss、shape、token 成本和数据审计结果。

```python
import math
from collections import Counter


def require_text(value, name):
    if not isinstance(value, str) or not value.strip():
        raise ValueError(f"{name} must be non-empty text")
    return value


def require_bool(value, name):
    if type(value) is not bool:
        raise ValueError(f"{name} must be bool")
    return value


def require_positive_int(value, name):
    if type(value) is not int or value <= 0:
        raise ValueError(f"{name} must be a positive integer")
    return value


def require_nonnegative_int(value, name):
    if type(value) is not int or value < 0:
        raise ValueError(f"{name} must be a non-negative integer")
    return value


def require_finite(value, name):
    if isinstance(value, bool) or not isinstance(value, (int, float)) or not math.isfinite(value):
        raise ValueError(f"{name} must be finite")
    return float(value)


def require_vector(vector, name, expected_dim=None):
    if not isinstance(vector, list) or not vector:
        raise ValueError(f"{name} must be a non-empty vector")
    if expected_dim is not None and len(vector) != expected_dim:
        raise ValueError(f"{name} has inconsistent dimension")
    return [require_finite(value, f"{name}[{index}]") for index, value in enumerate(vector)]


def dot(a, b):
    if len(a) != len(b):
        raise ValueError("dot product requires equal dimensions")
    return sum(x * y for x, y in zip(a, b))


def norm(a):
    return math.sqrt(dot(a, a))


def normalize(a):
    a = require_vector(a, "embedding")
    length = norm(a)
    if not math.isfinite(length) or length == 0:
        raise ValueError("embedding norm must be finite and non-zero")
    return [x / length for x in a]


def logsumexp(row):
    if not row:
        raise ValueError("logits must be non-empty")
    row = [require_finite(value, "logit") for value in row]
    maximum = max(row)
    return maximum + math.log(sum(math.exp(value - maximum) for value in row))


def cross_entropy(logits, target):
    if type(target) is not int or not 0 <= target < len(logits):
        raise ValueError("target must index the logits")
    return logsumexp(logits) - logits[target]


def patch_tokens(frames, height, width, patch):
    frames = require_positive_int(frames, "frames")
    height = require_positive_int(height, "height")
    width = require_positive_int(width, "width")
    patch = require_positive_int(patch, "patch")
    return frames * math.ceil(height / patch) * math.ceil(width / patch)


def audit_samples(samples):
    if not isinstance(samples, list) or not samples:
        raise ValueError("samples must be a non-empty list")
    issues = []
    seen_ids = set()
    for sample in samples:
        if not isinstance(sample, dict):
            raise ValueError("each sample must be a mapping")
        sample_id = require_text(sample.get("id"), "sample id")
        if sample_id in seen_ids:
            raise ValueError(f"duplicate sample id: {sample_id}")
        seen_ids.add(sample_id)
        require_text(sample.get("task"), f"task for {sample_id}")
        require_text(sample.get("question"), f"question for {sample_id}")
        require_bool(sample.get("aligned"), f"aligned for {sample_id}")

        # These are auditable data findings, not malformed Python input.
        if not isinstance(sample.get("image"), str) or not sample["image"].strip():
            issues.append((sample_id, "missing_image"))
        if not isinstance(sample.get("answer"), str) or not sample["answer"].strip():
            issues.append((sample_id, "empty_answer"))
        if not sample["aligned"]:
            issues.append((sample_id, "modality_misaligned"))
    return issues


# 1. CLIP-style bidirectional contrastive loss.
image_emb = [
    normalize([0.9, 0.1, 0.0]),
    normalize([0.1, 0.8, 0.2]),
    normalize([0.0, 0.2, 0.9]),
]
text_emb = [
    normalize([0.8, 0.2, 0.0]),
    normalize([0.0, 0.9, 0.1]),
    normalize([0.1, 0.1, 0.9]),
]
if len(image_emb) != len(text_emb) or len(image_emb) < 2:
    raise ValueError("CLIP demo needs paired image/text embeddings and at least two candidates")
embedding_dim = len(image_emb[0])
for index, vector in enumerate(image_emb + text_emb):
    require_vector(vector, f"embedding {index}", embedding_dim)
logit_scale = require_finite(8.0, "logit_scale")
if logit_scale <= 0:
    raise ValueError("logit_scale must be positive")
sim = [[logit_scale * dot(img, txt) for txt in text_emb] for img in image_emb]
i2t_loss = sum(cross_entropy(row, i) for i, row in enumerate(sim)) / len(sim)
t2i_loss = sum(
    cross_entropy([sim[i][j] for i in range(len(sim))], j)
    for j in range(len(sim))
) / len(sim)
clip_loss = 0.5 * (i2t_loss + t2i_loss)
top1 = [max(range(len(row)), key=lambda j: row[j]) for row in sim]
clip_top1_acc = sum(pred == i for i, pred in enumerate(top1)) / len(top1)


# 2. VLM connector shape and multimodal SFT label mask.
batch_size = require_positive_int(2, "batch_size")
vision_tokens = require_positive_int(4, "vision_tokens")
llm_dim = require_positive_int(6, "llm_dim")
text_lengths = [5, 3]
if len(text_lengths) != batch_size or any(type(length) is not int or length <= 0 for length in text_lengths):
    raise ValueError("text_lengths must contain one positive length per batch item")
combined_shape = (batch_size, vision_tokens + max(text_lengths), llm_dim)
labels = [
    [-100, -100, -100, -100, -100, 31, 32, 33, 2],
    [-100, -100, -100, -100, -100, 41, 2, -100, -100],
]
if len(labels) != batch_size or any(not isinstance(row, list) or not row for row in labels):
    raise ValueError("labels must contain one non-empty row per batch item")
if any(type(y) is not int for row in labels for y in row):
    raise ValueError("labels must contain integer token ids or ignore_index")
valid_label_count = sum(y != -100 for row in labels for y in row)
image_tokens_ignored = all(
    row[t] == -100 for row in labels for t in range(vision_tokens)
)
prompt_tokens_ignored = labels[0][vision_tokens] == -100 and labels[1][vision_tokens] == -100
if valid_label_count == 0:
    raise ValueError("multimodal SFT batch has no assistant supervision")
mask_ok = image_tokens_ignored and prompt_tokens_ignored and valid_label_count == 6


# 3. Diffusion forward noising.
x0 = require_finite(0.8, "x0")
eps = require_finite(-0.4, "diffusion noise")
alpha_bars = [0.9, 0.5, 0.1]
if not all(0 <= require_finite(alpha, "alpha_bar") <= 1 for alpha in alpha_bars):
    raise ValueError("alpha_bars must lie in [0, 1]")
noised = [
    round(math.sqrt(a) * x0 + math.sqrt(1 - a) * eps, 4)
    for a in alpha_bars
]


# 4. ASR frame count and video patch token cost.
frame_shift_ms = require_positive_int(20, "frame_shift_ms")
audio_seconds = [require_finite(seconds, "audio_seconds") for seconds in [3.2, 18.0]]
if any(seconds <= 0 for seconds in audio_seconds):
    raise ValueError("audio_seconds must be positive")
asr_frames = [
    math.ceil(seconds * 1000 / frame_shift_ms)
    for seconds in audio_seconds
]


video_tokens_short = patch_tokens(8, 224, 224, 16)
video_tokens_long = patch_tokens(16, 448, 448, 16)
attention_cell_ratio = round((video_tokens_long / video_tokens_short) ** 2, 1)
```

## 13. 多模态安全和评估

多模态模型的评估比纯文本更难。

要关注：

1. OCR 准确性。
2. 图表理解。
3. 幻觉率。
4. 计数和空间关系。
5. 语音转写错误传播。
6. 视频时序理解。
7. 安全和隐私风险。

比如语音识别错一个否定词，后面整个问答就会偏掉。

因此多模态训练要带着评估思维，而不是只看 loss。

### 13.1 把评估拆成模态能力和任务结果

多模态系统至少有三层评估：输入层、表示/证据层和任务层。输入层检查解码成功率、分辨率或采样率覆盖；表示层检查图文检索、OCR、区域 grounding、ASR 转写和视频时间定位；任务层检查最终回答、工具调用或生成结果。输入层通过而任务层失败，可能是 connector 或后训练问题；任务层看似通过而证据层失败，则可能只是数据先验带来的猜测。

常见指标需要把变量说清楚。例如 ASR 的词错误率为：

```math
\mathrm{WER}=\frac{S+D+I}{N_{\mathrm{ref}}}
```

OCR 或答案抽取可以报告 normalized exact match，但规范化规则必须固定；区域或视频事件任务可以报告 IoU/tIoU：

```math
\mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}
```

这两个指标分别要求 `N_{\mathrm{ref}}>0`、区域或区间的并集非空；空参考与无标注样本应从相应指标中排除并单独计数。开放式 VQA 则需要答案标注、同义表达规则和人工复核。一个多模态模型的“综合分数”只有在各子任务、样本来源、权重和缺失值处理都公开时才有解释力。

### 13.2 幻觉、证据支持和反事实评估

幻觉率的分母不能只写“回答条数”。应先定义哪些样本要求视觉或音频证据，再定义什么算 unsupported claim。例如对票据金额，答案中的金额必须能在标注区域或 OCR 证据中找到；对视频事件，回答应落在正确时间段；对语音指令，关键实体和否定词应与人工转写一致。可以记录：

```math
\mathrm{UnsupportedRate}
=\frac{\#\,\mathrm{answers\ with\ unsupported\ claims}}
{\#\,\mathrm{evidence\ requiring\ samples}}
```

这个指标要求 evidence-requiring 样本数大于零，且“claim”“支持”和证据范围在标注协议中有可复核定义。没有证据标注的样本应报告为未评估，而不是既不算支持也不算不支持后混入分母。该指标依赖标注质量，不能直接当作跨数据集的绝对真值。评估报告应附带标注协议、抽样方式和置信区间，并把错误分为感知错误、对齐错误、推理错误和表达错误。这样训练团队才能知道应该补数据、改 connector、改 loss mask，还是改解码和提示模板。

安全评估还要覆盖图片中的文字指令、恶意文档、隐私信息、人物身份推断、危险场景描述和语音中的越权请求。多模态输入可以携带 prompt injection；把图像 OCR 文本直接拼进系统提示上下文，会让“被观察到的文字”和“系统真正的指令”混在一起。训练时要给来源加标签，推理时要规定媒体内容只能作为数据而不能改变更高优先级的行为约束。

## 14. 常见训练策略

### 14.1 冻结视觉编码器

常用于数据不够大或训练预算有限的场景。

冻结的好处是保留通用视觉表示，减少梯度和 optimizer state，也降低视觉 encoder 被小数据集过拟合的风险；代价是域差异无法被修正。例如工业红外图像、医学影像或低清票据可能与自然图像预训练分布相差很大，connector 再强也未必能补回 encoder 已经丢失的信号。

### 14.2 只训练 connector

适合先建立模态对齐桥接。

这一步常用于验证数据协议：如果固定两端后 connector 连基本 caption 或 VQA 都学不好，应先检查视觉 token 的顺序、hidden size、位置编码、mask 和正负样本，而不是立即解冻整个模型。connector loss 下降也不能证明视觉细节全部保留，只能说明在当前任务和数据上找到了一个可用映射。

### 14.3 联合微调

适合数据较多、预算较高的场景。

联合微调能让视觉表示适应语言任务，也能让 LLM 学会读取视觉 token，但会带来灾难性遗忘、语言能力回归、不同模态梯度尺度不平衡和更高的显存成本。实践中常用较小的视觉学习率、分组学习率、LoRA 或只解冻高层，并保留纯文本回归集检查语言能力是否下降。

### 14.4 分阶段训练

常见顺序是：

```text
对齐预训练 -> VLM instruction tuning -> 任务特化微调 -> 安全和回归评估
```

四种策略的差别可以概括为：

| 策略 | 主要改变 | 优点 | 风险 | 更适合观察的证据 |
| --- | --- | --- | --- | --- |
| 冻结视觉 encoder | connector/LLM | 成本低、保留通用视觉表示 | 域差异难修复 | 领域图像与通用图像的差距 |
| 只训 connector | 视觉到语言的映射 | 便于排查协议和 shape | 表达能力受两端固定表示限制 | 对齐 loss、VQA/OCR 细节 |
| 联合微调 | 视觉和语言参数 | 适应目标域、上限较高 | 过拟合、遗忘、梯度失衡 | 任务收益与纯文本回归 |
| 分阶段训练 | 不同阶段的参数和数据 | 因果清晰、便于扩展 | 阶段切换可能分布不连续 | 各阶段 checkpoint 与跨任务曲线 |

“分阶段”不是把问题推迟，而是把不同来源的梯度分开，让每个阶段都有可解释的输入、目标和比较基线。阶段之间要固定 tokenizer、媒体预处理和 special token 协议，否则后一个阶段的收益无法归因。

## 15. 常见误判与诊断路径

前面的章节分别讲了结构、数据、目标和评估，真实问题往往出在它们的边界上。下面用几个常见现象把检查路径串起来：先确认媒体和协议，再确认监督位置和证据关系，最后才决定是否调整模型结构或训练策略。

### 15.1 只报模块名称，无法解释 VLM 的训练过程

解释 VLM 时应从数据流开始：图像先经过视觉 encoder 形成视觉 token，connector 把它们变成语言模型 hidden size 能接收的表示，随后按照模型的 cross-attention 或 prefix 拼接协议与文本交互。训练通常先用图文对齐或 caption 数据建立桥接，再用 VQA、OCR 和对话数据学习任务行为；视觉 encoder、connector 和 LLM 是否冻结，取决于域差异、数据量和预算。最后还要用 label mask 确认只有预期目标参与监督，并用替换图片后的反事实样本检查模型确实使用了视觉证据。

一开始全量训练会让视觉、桥接和语言三部分的表示分布同时变化，梯度来源混杂，训练不稳定且难定位。分阶段训练把桥接、任务对齐和安全回归拆开，便于建立因果证据；如果最终解冻全部模块，也应保留各阶段 checkpoint 和对照评估。

### 15.2 把 CLIP 的相似度能力误当成生成能力

CLIP 的基本输出是图像 embedding 和文本 embedding 之间的相似度，训练目标是让匹配对在 batch 候选中排名靠前，因此它适合检索和 zero-shot 分类。VLM 的输出通常是文本或结构化答案，它需要把视觉表示接入自回归或跨注意力语言模型，并解决 token 协议、对话监督、细粒度证据和幻觉。CLIP 可以成为 VLM 的视觉底座，但共享语义空间并不自动提供 OCR、计数、空间定位和多轮生成能力。

### 15.3 把模板渲染成功误当成监督正确

重点是建立一份不含歧义的输入输出协议。要明确 placeholder 如何展开为视觉 token，图片在多轮对话中的作用域，用户、assistant、工具和 OCR 文本的角色，以及哪些 token 参与 loss。答案流畅只是结果的一部分，还要检查答案是否引用了图片中的正确区域、是否在图片被替换时做出合理变化，以及 OCR、图表和多轮样本是否在总数据中有足够权重。

### 15.4 把“都有 prompt”误当成训练目标相同

语言模型通常在离散 token 上做条件 next-token prediction；diffusion 在连续像素或 latent 上先按时间步加噪，再学习噪声、原图或其他等价参数化。它的训练结果不仅受网络和数据影响，还受时间步采样、噪声 schedule、损失权重、条件注入和采样器影响。推理时需要多次 denoising，因此一次请求的计算路径也不同。两者都可以使用文本条件，但“有 prompt”不意味着目标函数相同。

### 15.5 训练 loss 正常但模态证据没有进入模型

最常见的是数据对齐和监督边界错误：图文错配、OCR box 与文字错位、语音转写中的否定词错误、视频采样漏掉关键动作，或者把 prompt 和 image placeholder 误算进 loss。这些问题都可能让训练 loss 看起来正常。排查时应先做媒体解码和 schema 统计，再检查 mask、分层评估和反事实样本，最后才调整模型结构或超参数。对生产系统还要把隐私、版权、图片文字中的恶意指令和语音越权请求纳入安全回归。

要验证模型是否真的使用了图像，可以构造只改变关键区域的成对样本，比较答案、log-prob 或 grounding 区域；同时把 OCR、计数、空间关系拆成独立子集，避免被流畅的通用回答掩盖。这个反事实检查比单独查看 attention map 更可靠，但仍不能把它当作充分的因果证明，因为模型可能利用上下文先验猜到答案。

## 16. 本章练习

下面的问题要求把训练目标、数据协议和评估证据放在一起判断。数值为教学例；不要求复现论文模型。

1. 某图像与其正确 caption 的 logit 为 `3`，另一个语义相关 caption 的 logit 为 `2`，但数据把第二对标成负例。计算两候选 CLIP softmax 的正例概率与 loss，再计算 SigLIP 对错误负例的单对 loss。说明更换 sigmoid 目标为什么不会自动修复标注关系，并写出支持多正例时需要改变的标签结构。
2. 你有冻结的强视觉 encoder 和 7B LLM，预算有限但希望支持图像问答；另一个团队有大量混合图文数据，目标是 few-shot、多图推理。分别比较 BLIP-2、LLaVA-1.5 和 MM1 的训练设计、资源瓶颈和证据；明确哪些论文数字不能横向比较。针对收据小字再设计一项分辨率/视觉 token 消融。
3. 对一张含税额、总额和两栏表格的收据，分别画出 OCR pipeline、LayoutLMv3、Donut、Pix2Struct 的输入、主要预训练/微调目标、最终字段输出和错误追踪点。给出一个只检查整页 CER 会漏掉的字段关系错误，并指定应增加的指标或证据标注。
4. 若字符级目标是 `book`，写出长度最短的合法 CTC 路径并说明为什么 4 帧不够；再用 `T=160` 声学帧、`U=20` 输出 token 估算 RNN-T 格点量级。根据是否要求实时 partial output，比较 CTC、RNN-T 和 attention seq2seq 的模型/数据条件。
5. 设 `γ=5`，分别计算 `SNR=100` 与 `SNR=0.1` 时 Min-SNR 对 `x_0`、`ε`、`v` 目标使用的权重。说明为什么这些权重必须和 prediction target 一起报告，并指出 FID `2.06` 和 `3.4×` 收敛速度属于什么证据范围。
6. 计算 8 帧 `224×224` 与 16 帧 `448×448`、patch `16` 的 token 数和 full-attention score-cell 比值。分别说明固定帧数、按分桶、Frame Pack 能修复什么，以及它们不能替代哪些时序评估。

## 17. 本章小结

读完本章，应该能把一个多模态训练项目还原成一条可追踪的数据流：媒体先被规范化和编码，视觉、音频或视频表示通过 connector 或 cross-attention 进入语言模型，训练目标再决定是对比、生成、定位、转写还是去噪。任何“能力提升”都必须能回到具体数据、有效监督位置、参数更新范围和分任务评估。

最容易被忽略的不是某个新模块，而是接口之间的边界：placeholder 与视觉 token 数是否一致，assistant label 是否错位，视频采样是否保留了事件，ASR 错误是否传到了答案，latent 压缩是否抹掉了小字，评估是否真的要求模型使用输入证据。把这些边界写进 manifest、训练日志和 bad case 集，多模态训练才从“模型能处理图片”变成可解释、可复现、可改进的工程。

## 18. 资料与进一步阅读

下面的资料用于建立概念和核对方法来源。论文摘要与正文说明的是作者报告的模型、数据和实验边界；它们不等于今天所有商业模型的实现细节。

1. [CLIP: Learning Transferable Visual Models From Natural Language Supervision](https://arxiv.org/abs/2103.00020)：图文双向对比目标、zero-shot 迁移和大规模图文数据。
2. [SigLIP: Sigmoid Loss for Language Image Pre-Training](https://arxiv.org/abs/2303.15343) 与 [SigLIP 2](https://arxiv.org/abs/2502.14786)：分别核对 pairwise sigmoid 对比目标，以及加入 captioning、自监督损失、数据筛选和多分辨率的训练配方。
3. [MM1: Methods, Analysis & Insights from Multimodal LLM Pre-training](https://arxiv.org/abs/2403.09611)：阅读 encoder、分辨率、token 数、connector 和混合数据消融；注意论文中的 45/45/10 是其 base ablation configuration。
4. [LLaVA-1.5: Improved Baselines with Visual Instruction Tuning](https://arxiv.org/abs/2310.03744)：核对 336px CLIP encoder、MLP connector 和学术任务 VQA 数据对多模态指令基线的作用。
5. [Data curation via joint example selection](https://arxiv.org/abs/2406.17711)：理解为什么对比预训练的样本价值依赖同 batch 其他样本，以及作者的 JEST 计算效率证据边界。
6. [BLIP-2: Bootstrapping Language-Image Pre-training](https://arxiv.org/abs/2301.12597) 与 [Flamingo](https://arxiv.org/abs/2204.14198)：比较冻结单模态模型、Q-Former 桥接、交错图文和 cross-attention 路线。
7. [Visual Instruction Tuning](https://arxiv.org/abs/2304.08485)：LLaVA 早期公开方案中的视觉指令数据和 projector 训练路径。
8. [LayoutLMv3](https://arxiv.org/abs/2204.08387)、[Donut](https://arxiv.org/abs/2111.15664)、[Pix2Struct](https://arxiv.org/abs/2210.03347)：对照 OCR 文字/布局输入、OCR-free JSON 生成和 screenshot parsing 预训练。
9. [CTC](https://www.cs.toronto.edu/~graves/icml_2006.pdf)、[RNN-T](https://arxiv.org/abs/1211.3711)、[Whisper](https://arxiv.org/abs/2212.04356)：比较无逐帧对齐、时间×前缀格点和 autoregressive seq2seq 目标。
10. [wav2vec 2.0](https://arxiv.org/abs/2006.11477)：自监督语音表示和量化对比学习，可用于理解语音 encoder 的预训练来源。
11. [Conformer](https://arxiv.org/abs/2005.08100)：结合卷积局部建模和 Transformer 全局建模的语音 encoder。
12. [DDPM](https://arxiv.org/abs/2006.11239)、[Latent Diffusion](https://arxiv.org/abs/2112.10752) 与 [DiT](https://arxiv.org/abs/2212.09748)：对照离散时间去噪、latent 压缩和 Transformer denoiser。
13. [Efficient Diffusion Training via Min-SNR Weighting Strategy](https://arxiv.org/abs/2303.09556)：阅读 timestep 梯度冲突诊断和参数化相关的权重设计。
14. [CogVideoX](https://arxiv.org/abs/2408.06072) 与 [Video Diffusion Models](https://arxiv.org/abs/2204.03458)：核对 3D VAE、不同长度/分辨率 frame pack 和视频时空去噪。
15. [From Specific-MLLMs to Omni-MLLMs: A Survey on MLLMs Aligned with Multi-modalities](https://aclanthology.org/2025.findings-acl.453/)：用来建立架构、两阶段训练、数据集和评估的全景地图；分类是阅读索引，不替代原论文证据。
16. [Hugging Face Transformers 多模态 chat template](https://huggingface.co/docs/transformers/main/en/chat_templating_multimodal)：核对媒体消息、placeholder 和对话模板如何进入 processor 与模型输入。
17. [PyTorch CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)：核对 `ignore_index`、reduction 和 label shape，避免把 padding 或非目标位置错误计入 loss。
18. [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)：为隐私、安全、可追溯性和多模态风险评估提供治理层参考；它不是某个模型的训练算法。

使用这些资料时，先核对论文中使用的分辨率、帧数、数据配比、冻结策略和评测集，再把结论迁移到自己的训练项目。论文提出的方法可以作为机制证据，不能替代对当前数据、当前 tokenizer 和当前推理链路的实测。
