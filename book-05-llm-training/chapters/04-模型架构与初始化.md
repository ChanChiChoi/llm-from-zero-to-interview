# 第四章：模型架构与初始化：把目标约束变成可训练的网络

## 4.0 架构选择是一张预算转换表

训练前的架构设计，不是从组件清单里勾选 RoPE、SwiGLU、RMSNorm 和 GQA。它要回答一个更实际的问题：给定目标能力、训练 token、GPU、上下文长度和部署约束，怎样把容量、计算、显存和稳定性分配到一份可运行的模型配置中。

初学者可以先沿着四个账本理解：

1. 参数账本：层数、宽度、词表、FFN 和 expert 一共需要多少参数。
2. 训练账本：这些参数是否有足够 token 和计算预算被训练充分。
3. 运行账本：序列长度、attention、KV cache、路由和通信需要多少显存与带宽。
4. 稳定账本：初始化、归一化、残差和精度是否让梯度能够持续传播。

专家还要检查这些账本是否互相冲突：一个参数量合适的模型可能因为上下文过长而无法训练；一个 MoE 模型可能总参数很大但 active 参数合理，却被 expert 通信和 overflow 拖慢；一个看似支持长上下文的 RoPE 配置可能只改变了最大位置数，却没有长序列训练和有效检索评估。

本章按训练决策展开：先把能力、数据、算力和推理要求写成约束，再估算模型形状、参数、token 与显存，随后检查位置编码、归一化、FFN、KV cache 和 MoE 如何改变训练与运行账本，最后用初始化和小规模回归把配置变成可验证方案。组件的完整数学推导与架构谱系由第二册第二部分和第二十一册主讲；这里聚焦训练前要记录什么、如何估算、改结构后怎样验证。训练目标、token/label 协议、优化器、精度和成本分账分别接本册第 03、05、06、08、13 章。

## 4.1 先写清目标和硬约束

### 4.1.1 同一个“7B”可以是不同系统

参数量只描述一个粗略规模，不能说明：

| 未回答的问题 | 为什么重要 |
| --- | --- |
| 训练多少 token | 决定模型是否充分训练 |
| 上下文多长 | 决定 attention 和 KV cache 成本 |
| dense 还是 MoE | 决定总参数与 active 参数关系 |
| 词表多大 | 决定 embedding、softmax 和 token 长度 |
| GQA 还是 MHA | 决定推理缓存和带宽 |
| 目标语言与领域 | 决定 tokenizer、数据和评估切片 |
| 目标吞吐和延迟 | 决定架构能否上线 |

因此，架构配置必须和目标分布绑定。通用 base model、代码模型、企业助手、长文档分析模型和端侧模型，可能使用相似的 Transformer block，却需要不同的序列长度、词表、数据配比和推理取舍。

### 4.1.2 约束表

设计前可先建立如下表：

| 约束 | 示例问题 |
| --- | --- |
| 能力 | 需要通用知识、代码、数学、多语言还是工具调用 |
| 训练数据 | 有多少去重后的有效 token，长样本比例是多少 |
| 训练资源 | GPU 数量、显存、网络、存储和可接受时长 |
| 服务资源 | 并发、TTFT、TPOT、上下文长度和量化格式 |
| 模型接口 | 自回归文本、encoder-decoder、视觉或音频条件 |
| 稳定性 | 允许多大实验风险，是否已有可加载 checkpoint |
| 评估 | 哪些任务和切片决定架构是否成功 |

“架构更先进”不是约束；它只有在改变了目标能力、成本或可维护性时才有决策意义。

### 4.1.3 历史脉络：为什么 decoder-only 占据主流

Transformer 原论文同时讨论了 encoder-decoder 结构。后来，decoder-only 语言模型把文本、代码、对话、工具调用统一为“根据前缀预测后续 token”，在大规模无监督文本上获得了简洁的训练接口和连续的生成接口。

这条路线并不表示 encoder-only 或 encoder-decoder 没有价值。分类、检索、表征学习、翻译和某些条件生成任务仍可能更适合其他结构。decoder-only 成为通用 LLM 主流，主要是因为它把预训练、SFT、对话和推理放进同一个自回归协议，训练与服务生态也围绕这个协议成熟起来。三种信息流的任务边界见[第二册 Transformer 架构进阶](../../book-02-advanced-100/chapters/02-transformer架构进阶.md)；现代架构的历史和替代路线见[第二十一册](../../book-21-transformer-architecture-evolution/目录.md)。本章只保留训练配置需要的结构差异，不重复架构史。

### 4.1.4 把书系分工写进训练方案

训练方案需要能把每个选择送到负责验证它的环节。完整机制解释、训练协议和系统验收分属不同层次：

| 当前决策 | 训练前写入的字段 | 深讲或后续验收入口 |
| --- | --- | --- |
| 输入/输出接口与因果信息流 | 目标序列、mask 规则、输入模态与输出头 | 本册第 03、05 章；第二册第 21 讲 |
| 深度、宽度、head、FFN 与词表 | 每层形状、参数口径、权重共享方式 | 第二册第 24、25 讲；第二十一册第 03—08 章 |
| 位置、上下文和 KV 结构 | 训练长度分布、位置参数、K/V 头数、目标并发 | 第二册第 16、18 讲；第二十一册第 18、67、81、83 章 |
| Norm、残差、初始化和优化配套 | norm 位置、初始化规则、学习率/批量重搜计划 | 本册第 06、08、09 章；第二册第 13、14 讲 |
| Dense、MoE 或混合路线 | 总参数、每 token active 参数、容量与通信指标 | 第二十一册第 21、22 章；本册第 07、13、14 章 |

表中“深讲入口”表示机制或实验主讲位置，不意味着本章可以跳过选择理由。本章应让读者能从需求写出一份可复核的初始配置；具体实现和论文对照再沿入口深入。

## 4.2 Decoder-only Transformer 的数据流

### 4.2.1 Causal self-attention

给定 token embedding `X`，模型经过多层 self-attention 和 FFN。causal mask 保证位置 `t` 不能看到未来 token，只根据 `x_{1:t}` 预测 `x_{t+1}`。

scaled dot-product attention 的核心计算为：

~~~math
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^\top}{\sqrt{d_h}}+M
\right)V
~~~

`d_h` 是 head dimension，`M` 是 causal、padding 或其他结构 mask。允许访问的位置令 `M_{ij}=0`，禁止访问的位置令 `M_{ij}` 为负无穷或实现支持的最小值，这样 softmax 后对应权重为零。除以 `sqrt(d_h)` 是为了控制点积方差，避免 logits 随维度增大而过度尖锐。

例如 batch 为 2、序列长 128、hidden size 为 4096、query heads 为 32、KV heads 为 8 时，`d_h=4096/32=128`。Q 的形状是 `[2,128,32,128]`，K 和 V 各为 `[2,128,8,128]`；分组映射后，每个 query head 读取所属组共享的 K/V。若实现显式物化 attention 分数，其形状为 `[2,32,128,128]`。这个形状例子可以检查配置和 mask 广播，但训练标签右移与跨样本边界仍由第五章的训练协议说明。

用四个输入 token 检查因果方向：输入为 `[BOS,A,B,C]`，下一 token 目标为 `[A,B,C,EOS]`。第 0 行只允许读取 BOS，第 1 行可读取 BOS、A，第 2 行可读取 BOS、A、B，第 3 行才可读取全部四个输入；因此每个位置预测的是右移后的目标，而不是复制自身输入。对应的可见性矩阵是下三角，四行分别有 1、2、3、4 个可见位置，共 `1+2+3+4=10` 个位置对；无 causal mask 的方阵则有 `4×4=16` 个。这个小例能发现 mask 方向写反、把 padding 当成有效 token 或误让样本边界互相可见等问题。具体 loss 分母和跨样本边界如何处理，留给第五章完整展开。

### 4.2.2 为什么接口统一很重要

同一网络可以处理多种后续目标：

~~~text
预训练：文本前缀 -> 下一个文本 token
SFT：消息前缀 -> assistant token
工具调用：用户上下文 -> tool call token
代码：问题与上下文 -> 代码 token
多模态：文本 + 模态表示 -> 文本或模态 token
~~~

共享接口减少了系统切换成本，但不表示所有任务的监督 mask、数据格式和评估方式相同。统一的是序列预测的骨架，变化的是条件、目标和边界。

### 4.2.3 Encoder-only 和 encoder-decoder 的边界

encoder-only 可以让每个位置双向看到上下文，适合许多理解和表示任务；encoder-decoder 把输入编码和输出生成分开，适合输入输出边界明确的条件生成。选择 decoder-only 应该基于统一生成、规模化训练和服务需求，而不是因为“LLM 都这么做”就跳过任务分析。

## 4.3 参数量账本：从配置看规模

### 4.3.1 基本变量

设 hidden size 为 `d`，层数为 `N_L`，query head 数为 `H_q`，K/V head 数为 `H_kv`，head dimension 为 `d_h`，词表大小为 `V`，FFN 中间维度为 `d_ff`：

~~~math
d=H_qd_h
~~~

GQA 要求 query heads 可以分成若干组共享 K/V：

~~~math
H_q=gH_{\mathrm{kv}}
~~~

这里 `d`、`H_q`、`H_{\mathrm{kv}}` 和 `d_h` 都是正整数，`g` 也是正整数。不能整除时，配置需要调整或由实现采用特殊映射；不能让整数除法静默截去通道，否则 Q、K、V 的形状已经不再属于同一个 attention 协议。

### 4.3.2 Attention 参数

在忽略 bias 的近似下，Q 和 O 投影各约为 `d^2`；GQA 的 K、V 投影分别约为 `dH_kv d_h`。因此：

~~~math
P_{\mathrm{attn}}
\approx
d^2+2dH_{\mathrm{kv}}d_h+d^2
~~~

MHA 是 `H_kv=H_q` 的特殊情况；MQA 则近似使用一个 K/V head。GQA 减少 K/V 投影参数和推理缓存，但不意味着整个模型参数按相同比例下降，因为 FFN 和 Q/O 投影仍然存在。

### 4.3.3 FFN 参数

传统两投影 FFN 约为 `2dd_ff`。SwiGLU 常见形式包含 gate、up 和 down 三个投影，因此：

~~~math
P_{\mathrm{ffn}}
\approx
3dd_{\mathrm{ff}}
~~~

实际模型可能调整 `d_ff` 使参数量对齐、使用 bias 或其他门控形式。FFN 往往是 block 中较大的参数和计算来源，不能只盯着 attention。

### 4.3.4 总参数近似

输入 embedding 约为：

~~~math
P_{\mathrm{emb}}=Vd
~~~

忽略 norm、bias、最终输出层和其他模块：

~~~math
P_{\mathrm{model}}
\approx
P_{\mathrm{emb}}+N_L(P_{\mathrm{attn}}+P_{\mathrm{ffn}})
~~~

若输入 embedding 和输出 softmax 权重不共享，应额外加入约 `Vd`；如果 tied embedding，则不要重复计算。模型配置导出的真实参数统计优先于公式，因为视觉模块、router、shared expert、bias 和权重共享都会改变结果。

### 4.3.5 规模变量之间的取舍

增加层数提高网络深度和逐层变换次数；增加宽度提高每层表示容量，但矩阵乘法和激活显存增长更快；增加词表缩短某些序列，却加重 embedding/softmax；增加上下文扩展输入范围，却加重训练 attention 和推理 cache。架构设计的难点在于这些旋钮相互耦合，而不是记住某个固定 7B 配置。

### 4.3.6 手算一个 block：参数下降比例不等于缓存下降比例

令 `d=4096`、`H_q=32`、`d_h=128`，则 `d=H_qd_h`。MHA 的 Q/K/V/O 四个无 bias 投影约有 `4d^2=67,108,864` 个参数。把 K/V 改成 `H_kv=8` 后，GQA 的 attention 投影约为：

~~~math
P_{\mathrm{GQA-attn}}
=2d^2+2dH_{\mathrm{kv}}d_h
=41,943,040
~~~

attention 投影参数约为 MHA 的 `62.5%`，下降 `37.5%`；但在 head dimension 和 dtype 不变时，K/V cache 变为 `H_kv/H_q=25%`，下降 `75%`。两者比例不同，是因为 attention 参数还包含没有缩小的 Q、O 投影，而 cache 只存 K 和 V。

FFN 也会改变整层的结论。若用普通两矩阵 FFN 且 `d_ff=4d=16,384`，参数约 `2dd_ff=134,217,728`。SwiGLU 有三矩阵，若把中间宽度调到约 `8d/3` 以便等参数比较，取整数 `d_ff=10,923` 时约 `3dd_ff=134,221,824`。在这组设置里，FFN 参数约是 MHA attention 投影的两倍；只报告 GQA 的 attention 参数比，会夸大它对整层参数量的影响。这里不含 bias、norm、embedding、输出头和 kernel 临时张量。

## 4.4 参数量和训练 token 的匹配

### 4.4.1 训练预算的第一阶关系

若模型参数量为 `P`，训练 token 数为 `D`，dense Transformer 的训练 FLOPs 可以用：

~~~math
C_{\mathrm{train}}
\approx
6PD
~~~

它是规模估算，不包括通信、激活重计算、评估、checkpoint、MoE 路由和失败重跑。token/parameter 比例为：

~~~math
r_{\mathrm{tok/param}}
=
\frac{D}{P}
~~~

这两式要求 `P>0`、`D>0`；MoE 的 `P` 还必须说明是总参数还是每 token active 参数。Chinchilla 风格研究说明，在固定计算预算下，参数和数据需要共同规划，训练不足的大模型可能不如训练更充分的较小模型。这个经验关系依赖数据质量、架构、目标和预算，不能被当作跨项目的硬性定律。

`6PD` 是短序列 dense Transformer 的一阶近似，不是每个配置都精确等于它。它把每 token 的主要矩阵乘加按约 `6P` 计入；精确估算还应分开计算 embedding/logits、attention 的 `QK^T` 与 `AV`、激活和具体训练实现。Chinchilla 的 FLOPs 附录把 embedding 和 logits 也纳入计算，并在其模型范围内对照 `6ND`；长序列增加的 attention 项不能因为参数数没变就忽略。[原论文附录 F](https://arxiv.org/html/2203.15556)。因此本章账本用 `6PD` 作第一轮筛选，最终训练时长和资源计划转到[第十三章](13-训练成本与资源规划.md)按目标序列分布和实测吞吐重算。

### 4.4.2 能力模型与部署模型可能不同

如果目标是研究 base model，可能把更多预算放在预训练 token；如果目标是企业助手，可能需要把预算放在领域继续预训练、SFT、偏好、安全和评估；如果目标是端侧部署，模型结构要从一开始考虑量化和缓存，而不是训练结束后才发现无法运行。

参数量不是能力、速度或成本的单一代理。MoE 还要分开总参数和 active 参数；长上下文还要分开短序列训练 throughput 与长序列显存。

## 4.5 RoPE：在 Q/K 几何中加入位置

### 4.5.1 频率表如何确定

设参与旋转的通道维度为偶数 `d_rot`，第 `i` 对通道常用的角频率是：

~~~math
\theta_i=\mathrm{base}^{-2i/d_{\mathrm{rot}}},
\qquad i=0,1,\ldots,d_{\mathrm{rot}}/2-1
~~~

位置 `p` 上的旋转角为 `p\theta_i`。常见的 `base=10,000` 只是配置值，不是 RoPE 的数学定律；不同模型可能调整 base、只旋转部分 head dimension，或再对频率做缩放。以 `d_rot=8`、`base=10,000` 为例，四组频率依次是 `1、0.1、0.01、0.001`。低编号通道随位置变化更快，适合表示近邻差异；高编号通道变化更慢，能覆盖更长距离。实际实现还要核对偶/奇通道配对、频率布局和 position id 是否与 checkpoint 一致。

### 4.5.2 二维旋转

把 Q 或 K 的通道两两分组，位置 `p` 在第 `i` 个二维子空间上的旋转为：

~~~math
\begin{bmatrix}
q'_{2i}\\
q'_{2i+1}
\end{bmatrix}
=
\begin{bmatrix}
\cos(p\theta_i)&-\sin(p\theta_i)\\
\sin(p\theta_i)&\cos(p\theta_i)
\end{bmatrix}
\begin{bmatrix}
q_{2i}\\
q_{2i+1}
\end{bmatrix}
~~~

K 使用同样的旋转。与把一个位置向量直接加到 embedding 上不同，RoPE 改变了 attention 中 Q/K 的几何关系。

可以用第一组通道手算一次：当 `d_rot=8`、`base=10,000` 时，`theta_0=1`。取二维向量 `q=(1,0)`、位置 `p=1`，旋转角为 1 弧度，得到 `q'=(cos 1,sin 1)≈(0.5403,0.8415)`；长度仍为 1，只是方向改变。若 `k=(1,0)` 位于位置 0，则旋转后的点积是 `q'·k=0.5403`，由这两个位置之间的角差决定。实际模型会把不同频率应用于多组通道；这个单对通道例子说明“旋转如何改点积”，不代表完整 head 只有二维。

### 4.5.3 相对位移的性质

旋转满足组合关系，在理想二维子空间中：

~~~math
\langle R_mq,R_nk\rangle
=
\langle q,R_{n-m}k\rangle
~~~

这个等式要求 Q/K 的旋转维度按二维配对，使用同一频率表和一致的位置索引；半精度下的频率计算、partial rotary 和插值会改变实现细节。它解释了相对位置信息如何进入点积，但这个性质不等于任意长度外推。训练长度、频率范围、RoPE base、缩放方式和长文本数据决定模型是否能在远距离上保持稳定。

### 4.5.4 长上下文扩展：从插值到非均匀频率搜索

RoPE 在训练长度以外可能产生模型未见过的旋转相位；单纯把 `max_position_embeddings` 改大只放宽配置检查，并没有教会模型在远距离使用证据。位置扩展方法的共同问题是：如何把新位置映射回训练时熟悉的相位范围，同时避免把近距离结构压坏。

| 方案 | 要解决的问题 | 主要做法 | 论文报告与限制 |
| --- | --- | --- | --- |
| Position Interpolation (PI) | 新位置带来训练中没见过的相位 | 线性缩回原训练范围，再继续长序列训练 | 改变近距离相位，需测原长度回归。[论文](https://arxiv.org/abs/2306.15595) |
| YaRN | 统一缩放会同时改变短距与长距频率 | 按波长分段缩放，并平滑过渡 | 报告收益限于论文模型、数据和预算。[论文](https://arxiv.org/abs/2309.00071) |
| LongRoPE | 不同旋转维度需要不同缩放 | 搜索维度相关的非均匀因子，并分阶段扩展 | 极长窗口是指定模型和评测设置的结果。[论文](https://arxiv.org/abs/2402.13753) |

这些工作共同解决“位置编号能否输入”和“远端信息能否可靠利用”之间的落差，但改变的对象、训练预算和任务集不同，不能仅按最大 context 数字排名。每次扩展至少记录：

1. 原始训练长度和目标长度。
2. 具体频率/位置变换及实现版本，不能只保存 `rope_scaling` 的名字。
3. 继续训练的 token 数、长度分布、训练步数和短上下文回归。
4. 长文中证据所在位置、干扰项密度和跨段组合方式。
5. 目标长度上的检索质量、生成质量、显存、吞吐和失败样例。

长上下文模型可以接收长输入，却在中间位置找不到证据；因此位置容量和有效利用能力必须分开测量。DeepSeek-V4.1-Flash 报告的是一项特定训练选择：稀疏注意力从 64K 序列长度开始训练，并在训练后段扩展到 1M；它证明该团队公开了这条配方，不证明其它模型可以照搬同一长度课程。[技术报告](https://arxiv.org/html/2609.19969v1) 的混合架构与 KV 状态细节见[第二十一册第 81 章](../../book-21-transformer-architecture-evolution/chapters/81-deepseek-v4.1-flash-causal-encoder-decoder.md)。PI、YaRN 和 LongRoPE 的推导则由[第二十一册第 18 章](../../book-21-transformer-architecture-evolution/chapters/18-RoPE与长上下文位置外推.md)深讲；本章验收目标是把训练长度分布、位置配置、短长文回归和显存/吞吐成本写入同一份计划。

## 4.6 RMSNorm、Pre-Norm 与残差流

### 4.6.1 RMSNorm

LayerNorm 先减均值，再按方差缩放：

~~~math
\mu(x)=\frac{1}{d}\sum_i x_i,
\qquad
\mathrm{LN}(x)_i
=\gamma_i\frac{x_i-\mu(x)}{\sqrt{\frac{1}{d}\sum_j(x_j-\mu(x))^2+\epsilon}}+\beta_i
~~~

RMSNorm 不做中心化，而用均方根缩放：

~~~math
\mathrm{RMS}(x)
=
\sqrt{\frac{1}{d}\sum_{i=1}^{d}x_i^2+\epsilon}
~~~

~~~math
y_i
=
\gamma_i\frac{x_i}{\mathrm{RMS}(x)}
~~~

取 `x=(3,4)`、`d=2`、`epsilon` 可忽略且 `gamma=(1,1)`，有 `RMS(x)=sqrt((3^2+4^2)/2)=sqrt(12.5)≈3.536`，所以输出约为 `(0.849,1.131)`。向量长度从 `5` 变为约 `1.414`，即 `sqrt(d)`；这展示的是 RMSNorm 的尺度规范化，不是把每个样本变成单位长度。

这里 `d>0`、`\epsilon>0`，并且输入应为有限值；`\epsilon` 是防止零向量除零的数值常数，不能用来掩盖激活中的 NaN 或 Inf。RMSNorm 保留对输入整体缩放的归一化，但不具备 LayerNorm 的平移不变性。RMSNorm 原论文的出发点是检验 re-centering 是否必要；作者在其多种网络和任务中报告相对 LayerNorm 有相近表现、运行时间减少 7%–64%，但这些数字来自论文当时的模型与硬件，不能直接承诺现代 LLM 训练提速幅度。[RMSNorm 原论文](https://arxiv.org/abs/1910.07467)

### 4.6.2 Pre-Norm 和 Post-Norm

一个子层 `F` 的 Pre-Norm 形式为：

~~~math
x_{\ell+1}=x_\ell+F_\ell(\mathrm{Norm}(x_\ell))
~~~

Post-Norm 的简化形式为：

~~~math
x_{\ell+1}=\mathrm{Norm}(x_\ell+F_\ell(x_\ell))
~~~

Pre-Norm 给残差提供更直接的梯度路径；Post-Norm 则在残差相加后归一化。Xiong 等人的 mean-field 分析指出，Post-LN 初始化时靠近输出层的期望梯度偏大，可解释 warmup 为什么对其训练稳定性有帮助；同一分析发现 Pre-LN 初始化的梯度行为更平稳，并在所测任务上展示了不使用 warmup 的可训练性。[Pre-LN/Post-LN 研究](https://arxiv.org/abs/2002.04745)

这解释的是初始化附近的一类梯度问题，不证明 Pre-Norm 在所有深度、学习率、精度和任务上都更优。Pre-Norm 会保留更直接的 residual stream，也可能改变最终 hidden-state 的尺度和表征；所以比较时要同步报告是否有 final norm、warmup、残差缩放、训练稳定性和下游质量。

### 4.6.3 残差尺度

每一层都向残差流加入更新。若更新尺度过大，深层累积可能导致激活和梯度异常；若过小，模型可能学习缓慢。架构可能通过初始化、residual scaling、norm 或零初始化某些输出投影控制尺度。

一个教学级的残差初始化直觉是：若基础标准差为 `sigma`，层数为 `N_L`，每个 block 含 attention 与 FFN 两条残差分支，且先假设各分支更新近似独立、零均值、方差相近，则总共约有 `2N_L` 次方差累积。让每条支路的标准差下降到下式的量级，可使独立假设下的累计方差保持在原数量级：

~~~math
\sigma_{\mathrm{res}}
\approx
\frac{\sigma}{\sqrt{2N_L}}
~~~

该近似要求基础标准差 `\sigma>0`、层数 `N_L>0`，也依赖残差更新独立、零均值和同方差等简化假设。真实网络中分支相关、Norm、激活和优化器更新都会打破这些假设，因此它只是说明“深度会累计更新尺度”的教学推导，不是通用初始化定律。

### 4.6.4 深度扩展与宽度扩展是不同问题

处理深度和宽度时，先问实验要控制哪一个变量。Pre-LN/Post-LN 研究关注归一化位置与初始化梯度；DeepNorm 同时调整残差尺度和初始化，针对极深网络的 update stability；μP 则改变随宽度扩展的参数化，让部分超参有机会从小模型迁移。三者不能互换，也不能仅凭名称推出目标模型不需要 warmup、相同标准差或超参搜索。

对应的原始研究分别是 [Pre-LN 梯度分析](https://arxiv.org/abs/2002.04745)、[DeepNet](https://arxiv.org/abs/2203.00555) 与 [μTransfer](https://arxiv.org/abs/2203.03466)。完整机制由[第二册第 13—14 讲](../../book-02-advanced-100/chapters/02-transformer架构进阶.md)和[第二十一册第 6 章](../../book-21-transformer-architecture-evolution/chapters/06-residual-layernorm-rmsnorm-prenorm与训练稳定性.md)深讲；本章保留训练前要记录的设计轴，并要求在目标深度、宽度、学习率和精度下复核稳定性。

## 4.7 SwiGLU：门控 FFN 的参数和计算

### 4.7.1 机制

一个常见的 SwiGLU 形式为：

~~~math
\mathrm{SwiGLU}(x)
=
\left[\mathrm{swish}(xW_g)\odot(xW_u)\right]W_d
~~~

`W_g` 是 gate projection，`W_u` 是 up projection，`W_d` 是 down projection，`odot` 是逐元素乘；`swish(z)=z·sigmoid(z)`。门控让一条投影控制另一条投影的通道贡献，相比单一激活函数提供更灵活的非线性变换。

### 4.7.2 为什么 FFN 中间维度要重新校准

SwiGLU 有三个投影，若直接使用传统 FFN 的 `d_ff`，参数量和矩阵乘法会增加。因此模型常调整中间维度，让不同 FFN 方案在目标参数量下比较。以普通 FFN 的 `d_ff=4d` 为例，两次矩阵乘法的参数量和每 token MAC 都是 `2d(4d)=8d^2`；SwiGLU 的 gate、up、down 三个矩阵则为 `3dd_ff`，令 `d_ff≈8d/3` 才能把矩阵主项对齐。这里 MAC 指一次乘加，尚未计入 swish、逐元素门控和内存读写。

取 `d=4096`，普通 FFN 的中间宽度为 `16,384`，对应 `2×4096×16,384=134,217,728` 个参数，也约为每 token 同数目的矩阵 MAC。SwiGLU 的理想宽度是 `8×4096/3≈10,922.67`；按整数取 `d_ff=10,923` 后，三矩阵有 `3×4096×10,923=134,221,824` 个参数，比普通 FFN 多 4,096 个，约高 `0.003%`。差异来自宽度取整，实际配置还常按张量并行分片和 kernel tile 对齐，因此应以导出的真实维度重算。

Shazeer 对 Transformer 序列到序列模型中的 GLU 变体做了实验，发现若干门控激活在其设置下优于 ReLU/GELU；论文支持的是“门控 FFN 值得对照实验”，没有给出对现代 decoder-only LLM 的通用因果解释，也没有证明 SwiGLU 在任意等参数、等训练预算下都胜出。[论文](https://arxiv.org/abs/2002.05202)

等参数不等于等延迟：三次投影的实际成本还取决于矩阵形状、融合 kernel、精度和硬件利用率。比较时应固定 tokenizer、训练数据顺序、global batch、优化器、训练 token 与评估协议，只改变 FFN 形式或宽度；报告真实参数量、MAC 估计和 profiler 吞吐。若通过对齐算力后质量有变化，还要检查激活内存、kernel 利用率和中间维度取整，避免把一次 kernel 差异误判为激活函数本身的质量收益。

### 4.7.3 边界

SwiGLU 改变的是 block 内的非线性变换，不会自动解决数据不足、长上下文检索、工具安全或推理成本。它的收益必须在固定参数、token、优化器、数据和评估协议下比较。门控 FFN 与 MoE 的数学机制由[第二册第 15、19—20 讲](../../book-02-advanced-100/chapters/02-transformer架构进阶.md)及[第二十一册第 5 章](../../book-21-transformer-architecture-evolution/chapters/05-ffn-swiglu-gated-mlp与moe-ffn.md)深讲；训练前只需记录中间宽度、参数预算、精度和目标硬件吞吐。

## 4.8 MHA、MQA 和 GQA：把注意力质量换成缓存成本

### 4.8.1 KV cache 账本

标准 MHA 为每个 query head 保存 K/V；MQA 共享一组 K/V；GQA 把 query heads 分成若干组。每层每 token 的 K/V cache 近似为：

~~~math
M_{\mathrm{KV,layer}}
=
2H_{\mathrm{kv}}d_hb
~~~

`b` 是每个数值的字节数。batch、上下文和层数纳入后：

~~~math
M_{\mathrm{KV}}
=
B C_{\mathrm{ctx}}N_L
\left(2H_{\mathrm{kv}}d_hb\right)
~~~

若从 MHA 改成 GQA，缓存近似按：

~~~math
\frac{M_{\mathrm{GQA}}}{M_{\mathrm{MHA}}}
=
\frac{H_{\mathrm{kv}}}{H_q}
~~~

取 `N_L=32`、`B=4`、`C_ctx=4096`、`d_h=128`、BF16 (`b=2`)。MHA 每层每 token 保存 `2×32×128×2=16,384` bytes；GQA-8 保存 `2×8×128×2=4,096` bytes。乘上 batch、上下文和层数，约为 8 GiB 与 2 GiB，差 4 倍；这里使用 `1 GiB=2^30` bytes，未计 block 对齐和元数据。该例只计算 K/V 数组，不能直接当成可承载并发数。

这些式子要求 batch `B`、上下文 `C_{\mathrm{ctx}}`、层数 `N_L`、K/V head 数、head dimension 和字节数 `b` 都为正；若 runtime 使用分页、量化或压缩缓存，必须按实际 block 和 dtype 重算。这个比例只描述 K/V cache，不等于总模型显存、总延迟或质量变化。

### 4.8.2 三种结构的取舍

| 结构 | K/V 组织 | 主要优势 | 主要代价 |
| --- | --- | --- | --- |
| MHA | 每个 query head 一组 K/V | 表达和迁移直观 | cache 和带宽高 |
| MQA | 所有 query head 共享一组 K/V | cache 最小 | 可能损失表达能力 |
| GQA | 每组 query head 共享 K/V | 质量与 cache 的折中 | 配置、迁移和实现更复杂 |

GQA 不是只在服务端打开的优化开关，而是训练时就确定的 projection 形状和模型结构。若从 MHA checkpoint 转换，可采用分组 K/V 聚合后继续训练等路线，但权重迁移方案必须对应具体实现；原论文的结果不能代替目标模型的训练和服务评测。[GQA 原论文](https://arxiv.org/html/2305.13245v3)与[Llama 2 的架构消融](https://arxiv.org/html/2307.09288v2)展示了质量、KV 带宽和张量并行拓扑之间的联动。

因此，把 MHA checkpoint 转成 GQA 时，不能只平均权重后就宣布完成：要记录 group 划分和 K/V 聚合方式，做继续训练或校准，并在相同模型、prompt、batch、输入长度、输出长度和硬件布局下比较质量、吞吐、P95 延迟与显存。离线质量变化和线上可服务并发是两个不同结果。三种 head 组织的完整机制和缓存并发预算见[第二册第 18 讲](../../book-02-advanced-100/chapters/02-transformer架构进阶.md)和[第二十一册第 4 章](../../book-21-transformer-architecture-evolution/chapters/04-mha-mqa-gqa-mla的演进与trade-off.md)；本章用公式先筛查哪些结构值得进入实测。

## 4.9 上下文长度：训练分布和运行成本的共同约束

### 4.9.1 训练与推理的不同成本

标准全量 attention 的算术量随序列长度近似二次增长；若实现显式保存完整 score 矩阵，其中间存储也随序列长度近似二次增长：

~~~math
M_{\mathrm{attn}}
\propto
B H_q C_{\mathrm{ctx}}^2
~~~

前向中 `QK^T` 和 `AV` 的主项还要乘上 `d_h`，即约为 `B H_q C_ctx^2 d_h`。例如 `B=4`、`H_q=32`、`C_ctx=4096` 时，显式 score 矩阵有 `4×32×4096^2=2,147,483,648` 个元素；以 2 bytes/元素存储约需 4 GiB/层。长度加倍到 8192，元素数和该存储量都变成 4 倍。FlashAttention 通过分块计算避免物化整个 score 矩阵，降低中间存储与读写，但全量 attention 的精确交互计算仍随长度平方增长；机制和 IO 账本见[第八章](08-显存优化与数值精度.md)。

把同一工作负载的长度从 4K 增到 32K，是 8 倍 token 数：上述 GQA-8、32 层、batch 4 的 KV 数组从约 2 GiB 增到约 16 GiB；若仍显式物化每层完整 score，元素数则增加 `8^2=64` 倍，从约 4 GiB 增至约 256 GiB/层。后一个数字说明为什么实际 kernel 不会简单保存整张矩阵；它也不能被误读为使用 FlashAttention 后计算量只增加 8 倍。训练配置要分别列出“是否保存完整分数”和“是否仍计算全量 token 两两交互”，再按目标长度分布实测。

自回归 decode 阶段，KV cache 随上下文线性增长：

~~~math
M_{\mathrm{KV}}
\propto
B C_{\mathrm{ctx}}N_LH_{\mathrm{kv}}d_h
~~~

KV 比例关系只描述正长度序列上的主导项，并省略 layer 数、dtype、block sparsity、cache 元数据和 kernel 常数；空序列或零 head 不是“零成本长上下文”，而是无效配置。因此训练长上下文主要面对 attention 计算、激活与通信，推理长上下文主要面对 cache 容量、读写带宽和并发。两者需要不同的 profiling。

### 4.9.2 长上下文的有效能力

训练数据几乎全是短样本时，模型可能接受长输入但不会使用远端信息。评估应包含：

1. 关键信息在开头、中间和末尾的位置切片。
2. 多文档检索和跨段组合。
3. 长上下文中的干扰项。
4. 代码、表格、JSON 和多语言长文本。
5. 位置外推和截断边界。

上下文窗口是接口上限；有效上下文是模型能在成本约束下可靠使用的输入分布。架构配置、长序列训练、检索策略和评估必须同时出现，不能只把一个数字写进 config。

## 4.10 MoE：总容量与 active 计算分开记账

### 4.10.1 Dense 与稀疏路由

Dense FFN 对每个 token 使用同一套参数。MoE 有 `E` 个 routed experts，每个 token 选择 `k` 个；模型还可以另有每个 token 都执行的 shared experts。若单个 routed expert FFN 参数量为 `P_expert`：

~~~math
P_{\mathrm{total,FFN}}
=EP_{\mathrm{expert}}+P_{\mathrm{shared}}+P_{\mathrm{router}}
~~~

~~~math
P_{\mathrm{active,FFN}}
\approx kP_{\mathrm{expert}}+P_{\mathrm{shared}}+P_{\mathrm{router}}
~~~

这里 `E>0`、`P_{\mathrm{expert}}>0`，且 `1\le k\le E`；`E` 只计 routed experts，`P_{\mathrm{shared}}` 是每个 token 都执行的 shared expert 参数，`P_{\mathrm{router}}` 是路由器参数。没有 shared expert 时令其为 0；路由是否归一化、top-k 是否按组路由及是否按 token 丢弃都会改变真实 active 计算。这只是 FFN 部分的近似；attention、embedding、最终输出头和其他模块还要单独计入。总参数大，不等于每 token 都执行全部参数，也不保证实际 FLOPs 与同 active 参数的 dense 模型相等。

例如沿用 `d=4096`、`d_ff=10,923` 的 SwiGLU expert，一个 expert 约有 `3×4096×10,923=134.22M` FFN 参数。若 `E=8` 且每 token 选 `k=2`，仅 routed FFN 的总参数约 `1.074B`，每 token active 约 `268.44M`；这里还没加 router、shared expert、attention、embedding 和输出头。因此部署不能按 268M 参数准备完整权重显存，训练 FLOPs 也不能把 1.074B 当作每个 token 都实际计算。

### 4.10.2 路由和负载均衡

路由器为 token `t` 和 expert `e` 产生概率 `p_{t,e}`，选择 top-k。一个 batch 有 `T` 个 token 时，可以定义实际分发比例和平均路由概率：

~~~math
f_e
=
\frac{\#\{\text{tokens dispatched to }e\}}{Tk}
,
\qquad
P_e
=
\frac{1}{T}\sum_{t=1}^{T}p_{t,e}
~~~

一种常见的辅助负载均衡损失写成：

~~~math
L_{\mathrm{aux}}
=
E\sum_{e=1}^{E}f_eP_e
~~~

这些统计要求 `T>0`、`k>0`，并明确 `f_e` 是分派尝试还是容量裁剪后的实际接收比例；两种口径会给 overflow 系统不同的结论。该式中的 `p_{t,e}` 还应是有限且按 expert 归一化的路由概率。Switch top-1 和 GShard top-2 对 `f_e`、`P_e` 的定义并不完全相同；batch-wise 平衡也不保证每个序列内部都均衡。辅助项还带一个单独的权重系数；过小可能压不住路由集中，过大又可能把主任务目标推偏。

路由负载和路由数值稳定是两个不同问题。ST-MoE 对 router logits 使用 z-loss：

~~~math
L_z
=\frac{1}{T}\sum_{t=1}^{T}
\left(\log\sum_{e=1}^{E}\exp(z_{t,e})\right)^2
~~~

其中 `z_{t,e}` 是 softmax 前的 router logit。它惩罚过大的 log-sum-exp，降低 router 指数运算在低精度下因舍入误差导致的训练不稳定；它不直接保证 expert 负载均匀，所以不能替代 load-balancing loss 或服务侧的路由统计。ST-MoE 的特定 stability sweep 中，baseline 6 次运行有 4 次稳定，加入 router z-loss 后 3/3 稳定，且报告的质量没有下降；这支持它作为该 recipe 的数值稳定修复，不证明所有 MoE 都需要同一系数或有相同收益。[ST-MoE 的稳定性实验](https://arxiv.org/html/2202.08906)

### 4.10.3 代表方案各自解决了什么

| 研究/方案 | 主要困难 | 机制和作者报告 | 留下的取舍 |
| --- | --- | --- | --- |
| Token-choice top-k（GShard、Switch） | 决定每个 token 激活几个 expert | top-1 降低 dispatch 数；top-2 增加选择路径。论文报告只说明各自的任务、规模与系统设置 | 比较时控制 active 计算、容量和网络通信；不能从一篇翻译实验推算 dense LLM 的通用加速。[GShard](https://arxiv.org/abs/2006.16668)、[Switch](https://arxiv.org/abs/2101.03961) |
| 辅助损失与数值约束（ST-MoE） | 区分路由是否均衡与 router logits 是否稳定 | 负载损失控制分配倾斜；router z-loss 控制 logits 尺度 | 两个目标不同，须分别查看 expert 接收数、logits、溢出与 loss spike。[论文](https://arxiv.org/abs/2202.08906) |
| Expert-choice 路由 | token-choice 下 expert 收到的 token 数不均 | 由 expert 选择固定 bucket 内的 token | 每个 token 收到的 expert 数可变，语义与 top-k 不同；需重新定义容量和质量指标。[论文](https://arxiv.org/abs/2202.09368) |
| 负载 bias（DeepSeek-V3） | batch 级均衡目标可能与主损失竞争 | 通过 per-expert routing bias 调整选择，并额外检查序列内负载 | “auxiliary-loss-free”不表示完全没有辅助项；这是特定模型与集群的共设计案例。[技术报告](https://arxiv.org/html/2412.19437v2) |

这些路线不是从旧到新、每一代全面替代上一代，而是在解决不同约束。逐项比较这些机制和证据条件的入口见[第二十一册第 21—22 章](../../book-21-transformer-architecture-evolution/目录.md)；本章保留它们对训练配置的含义：总参数与 active 计算分开记，负载和数值稳定分开测，通信和 token dropping 都进入失败预算。

### 4.10.4 Capacity 和 token overflow

给定容量系数 `alpha`，expert 容量可以粗略估算为：

~~~math
C_e
=
\left\lceil
\alpha\frac{kT}{E}
\right\rceil
~~~

这里 `\alpha>0`、`T>0`、`E>0` 和 `1\le k\le E`。超过容量的 token 可能被丢弃、转发到 shared expert、使用 residual path 或采用更复杂的 dispatch。应记录 overflow rate、每 expert token 数、router entropy、通信时间和辅助损失，而不是只看总 loss。

例如 `T=1024`、`E=8`、`k=2`、`alpha=1.25` 时，每个 expert 的容量近似为 `ceil(1.25×2×1024/8)=320` 个分派槽。平均分配时每个 expert 是 256 个槽，但真实路由可能集中；只有逐 expert 统计才能知道是否触发裁剪。若使用 token dropping，还要把被丢 token 的比例和对应训练目标一同记录。

### 4.10.5 MoE 的工程边界

MoE 可能在固定 active 计算下扩展总容量，也可能带来多语言或多领域的路由分工；但它增加 expert parallel、all-to-all 通信、负载不均和 checkpoint 管理复杂度。服务端还要处理 expert 权重加载、并发和路由稳定性。选择 MoE 需要用目标集群和目标负载实测，而不是只比较论文参数量。

## 4.11 初始化与稳定性：让第一步更新处在可控尺度

模型从头训练时，初始化决定第一个 batch 会经过怎样的尺度；继续训练时，checkpoint 和训练状态共同决定“初始化”。架构改变还会改变梯度、激活和优化器看到的参数形状，因此不能把配置文件能加载当作稳定性证明。

### 4.11.1 方差直觉

线性层初始化通常希望输入输出方差处在同一数量级。Xavier 风格的一个标准差形式为：

~~~math
\sigma_{\mathrm{xavier}}
=
\sqrt{\frac{2}{f_{\mathrm{in}}+f_{\mathrm{out}}}}
~~~

取 `f_in=f_out=4`，则权重标准差为 `sqrt(2/8)=0.5`。若四个输入独立、均值为零且方差均为 1，一个输出的方差近似为 `4×0.5^2=1`。这说明标准差如何控制初始量级；实际 LLM 还要考虑残差、norm、激活、学习率和精度，不能只凭这一式确定完整初始化 recipe。

### 4.11.2 残差输出和深度

按 4.6.3 的教学关系，令 `N_L=32`，每条残差支路的标准差约为 `sigma/8`；64 条支路各自的方差缩小为 `sigma^2/64`，合计约为 `sigma^2`。这个手算依赖分支独立、零均值、同方差的简化假设，真实网络的相关性、norm、激活和优化器更新都会改变结果，因此它解释的是“深度可能累积尺度”，不是通用初始化规范。

进入训练前还要把这个假设换成可观察信号：用固定输入记录每层 residual stream 与 attention/FFN 输出的 RMS，并在模型前段、中段和末段比较变化。如果残差流随层数持续放大，检查分支输出尺度、norm 位置和残差系数；如果支路更新远小于残差流，则检查初始化或零初始化投影是否让有效更新过弱。两种情况都应在相同数据和优化器下做小规模对照，再决定是否改 residual scaling；单看第一步 loss 无法说明深层传播是否健康。实际方案还可能采用零初始化部分输出投影或 μP 等参数化，完整机制见[第二十一册第 6 章](../../book-21-transformer-architecture-evolution/chapters/06-residual-layernorm-rmsnorm-prenorm与训练稳定性.md)。

### 4.11.3 新 token 和词表变更

扩词表后的新 embedding 行只是数值起点，不自带语义；随机初始化、相关 token 平均和继续训练数据都会影响迁移结果。词表协议、输入/输出矩阵、优化器状态、tokenizer 版本及回归流程已在[第三章](03-tokenizer与数据格式.md)完整展开。本节只要求训练前配置记录旧行映射、新行初始化方式以及新 token 是否会进入训练语料。

### 4.11.4 从 checkpoint 继续训练

继续训练时，初始化来自已有状态，至少核对 tokenizer 与 vocab、架构 config、RoPE 参数、权重 dtype、参数名、optimizer state 和 scheduler state。每项变化都要标出是有意架构迁移还是意外协议偏差；同时保存固定输入的加载/前向结果和一组短训练样本，比较损失、输出及参数更新。配置能够加载并不说明旧 checkpoint 的权重含义与新结构一致。

### 4.11.5 架构变更后重新验证稳定性

Pre-Norm 子层保留较直接的残差梯度路径：

~~~math
x_{\ell+1}=x_\ell+F_\ell(\mathrm{Norm}(x_\ell))
~~~

Post-Norm 则在支路相加后做归一化：

~~~math
x_{\ell+1}=\mathrm{Norm}(x_\ell+F_\ell(x_\ell))
~~~

这两种结构会与最终 norm、残差缩放、初始化、学习率、batch 和精度共同作用。Pre-Norm 不是“无需 warmup 的稳定性开关”；scaled dot-product 中的 `sqrt(d_h)` 也只能控制点积量级，不能保证 softmax、RoPE、低精度 kernel 或 optimizer 更新在训练中都稳定。相关数学与数值机制见[第二册第 13—14 讲](../../book-02-advanced-100/chapters/02-transformer架构进阶.md)，训练精度和异常诊断见[第八、九章](08-显存优化与数值精度.md)。

2026 年 Qwen3.8-Flash-Next 技术报告提供了“结构变化要和训练 recipe 一起复核”的具体案例：报告在 28 层 MoE 的压力测试中固定数据顺序和 AdamW，单独比较是否启用 residual gate；在其 3 倍最优学习率设置下，作者报告 loss spike 率从每万步 32.0 降到 3.2，同一对照中越过 gradient-norm clipping 阈值的累计次数从 256 降到 20（这项计数没有按每万步归一化）。[技术报告](https://arxiv.org/html/2608.30320v1)还显示该架构与 Muon 的组合改变了最优 batch/LR 区域。数字属于指定模型、压力测试和训练配置，不能直接迁移成其他项目的收益或默认超参数；组件机制与完整消融见[第二十一册第 83 章](../../book-21-transformer-architecture-evolution/chapters/83-qwen3.8-qsa-gated-residual-n-gram-muon.md)，Muon 的参数分组和更新方法见本册第六章。

因此，结构变更先经过小规模门禁：

1. 检查 shape、mask、参数量、head 分组和 checkpoint 映射。
2. 用少量样本过拟合，核对初始 loss、梯度是否存在、参数是否按预期更新。
3. 记录每层 activation RMS、attention logits/entropy、gradient norm、overflow、clipping rate 和 loss spike。
4. 固定数据顺序、batch、优化器与精度做单变量对照；随后再评估长序列、不同 seed 和目标能力切片。

小实验不能证明大规模最终能力，但能以较低成本排除 shape、mask、初始化和数值错误。变更后若学习率或 batch 也需要重搜，应把这作为实验变量和资源开销记录，不能只比较单个 loss 数字。

## 4.12 训练前架构账本：从配置推到可行性

架构变量最终要落到训练可执行性和目标服务负载。下表只是第一轮映射；完整成本核算还要经过第十三章，替代架构、跨层缓存和特殊运行时状态则沿第二十一册深入。

| 变量 | 训练前主要影响 | 推理侧主要影响 |
| --- | --- | --- |
| hidden size d | 矩阵参数、激活与通信随宽度上升 | 每 token 矩阵计算和权重带宽增加 |
| 层数 N_L | 参数、反向计算、pipeline 切分 | decode 逐层串行计算与每层 cache |
| 词表 V | embedding、输出头与 logit 计算 | embedding/输出打分和采样开销 |
| 序列长度 C_ctx | attention、激活、并行切分与样本效率 | prefill 计算和 KV cache 容量 |
| KV head H_kv | K/V 投影参数和训练激活 | KV cache 容量、带宽与并发 |
| MoE 的 E、k | 总权重、active 计算、dispatch 与负载均衡 | expert 权重驻留、路由、尾延迟和通信 |

### 4.12.1 从形状计算参数与训练预算

用一组教学配置走完整个账本：d=4096、N_L=32、H_q=32、H_kv=8、d_h=128、d_ff=10,923、词表 V=32,000。设每层用 SwiGLU、norm 有两组 d 维 scale、输入 embedding 与输出头 tied；本例忽略 bias、router、shared expert、final norm 以及其他附加模块。

先算一个 attention block。Q 和 O 各有 d² 参数，K 和 V 各有 d H_kv d_h 参数，所以：

~~~math
P_{\mathrm{attn}}
=2d^2+2dH_{\mathrm{kv}}d_h
=2(4096)^2+2(4096)(8)(128)
=41{,}943{,}040
~~~

FFN 参数为：

~~~math
P_{\mathrm{ffn}}
=3dd_{\mathrm{ff}}
=3(4096)(10{,}923)
=134{,}221{,}824
~~~

两组 norm scale 共 8,192 个参数，因此 32 层 block 合计约 5,637,537,792 个参数。tied embedding 计一次，为 Vd=32,000×4,096=131,072,000；dense reference 总量约为 5.769B。若输出头不共享，还要再加约 131.1M；若有 bias、额外 norm 或视觉模块，也应按实际 config 导出值补入，不能把这个估算当成模型摘要。

给定 D=120B 训练 token，token/parameter 比约为 120B/5.769B=20.8。用 `6PD` 第一轮估算训练计算：

~~~math
C_{\mathrm{train}}
\approx
6(5.769\times10^9)(120\times10^9)
\approx4.15\times10^{21}\ \mathrm{FLOPs}
~~~

这只是该 dense reference 的量级数。长序列上的 attention 额外工作、精度、重计算、通信、评估和失败重跑都要另计；`6PD` 不能替代 profiler 或完整 FLOPs 账本。6PD 与更细 FLOPs 计数的区别见[Chinchilla 原论文附录 F](https://arxiv.org/html/2203.15556)。

`D/P≈20.8` 只表示这份假设配置下的训练 token 与参数之比，不表示每个参数都独立“看过”20.8 个样本，也不是充分训练或最优预算的判定线。数据重复、领域覆盖、tokenizer 切分、目标函数和模型质量都会改变它的含义。若改成 MoE，必须报告总参数与每 token active 参数分别作为哪个分母；把总专家参数直接放进稀疏模型的计算估算会高估每 token 的 routed 计算，把 active 参数用于权重存储估算又会低估模型驻留内存。

还可以把 FLOPs 转成一个明确标注为理想值的时间估算：假设目标集群持续提供 `1 PFLOP/s=10^15 FLOPs/s` 的有效训练算力，则 `4.15×10^21/10^15=4.15×10^6` 秒，约 `48.0` 天。这是假想的恒定吞吐，不包含 attention 长序列额外量、通信停顿、检查点、评估、故障重跑或学习率阶段差异，不能当作采购或排期承诺。工程排期应换成目标模型在目标长度分布上的实测有效吞吐，再把非训练阶段独立加入总账。

### 4.12.2 从 head 数计算 KV 和长序列预算

同一配置下，若用 BF16，每层每 token 的 GQA-8 cache 是：

~~~math
2H_{\mathrm{kv}}d_hb
=2(8)(128)(2)
=4{,}096\ \mathrm{bytes}
~~~

乘上 32 层、batch 4 和 4,096 token，cache 约为 2 GiB；相同 hidden size 的 MHA-32 约为 8 GiB。这里 1 GiB=2^30 bytes，数字只计 K/V 数组，不含模型权重、分页 block 对齐、allocator、临时 buffer 或其他状态。

长上下文训练还有另一个容易混淆的账本。若把完整 attention score 矩阵物化，batch 4、32 个 query heads、4,096 长度需要约 2.15B 个 score 元素；以 BF16 保存约 4 GiB/层，长度变为 8,192 时升至约 16 GiB/层。FlashAttention 避免存下完整矩阵，但不会把全量精确 attention 的二次计算变成线性。训练显存细节见[第八章](08-显存优化与数值精度.md)，长序列的 profile、并行和资源预算见[第十三章](13-训练成本与资源规划.md)。

`C_ctx` 在服务中应按缓存中仍保留的 prompt 与已生成 token 总数理解。由上式可知，本例每条请求在 4K 时约需 `512 MiB` KV，batch 4 合计 `2 GiB`；增至 32K 时每条约 `4 GiB`，四条请求合计 `16 GiB`。这些数字仅是 BF16 K/V 张量，未扣除分页空洞、临时工作区和权重，也未计量化缓存的 scale/metadata。缓存预算因此要和并发、最大输入、最大输出、cache dtype 一起写；只报告一个最大上下文长度无法说明服务能同时处理几条请求。

### 4.12.3 把 MoE 和服务成本放回账本

MoE 配置要同时保留总参数、每 token active 参数、expert 容量、overflow 和通信。以 4.10 的 8-expert、top-2 示例，268M active routed-FFN 参数只说明每 token 计算了几份 expert；服务仍需容纳完整 expert 权重，训练还要为路由、all-to-all 和热点负载预留预算。相反，GQA 将 cache 降低 4 倍也不表示总显存或端到端延迟下降 4 倍。

最终应把架构候选做成同条件实验：固定目标数据与训练 token，记录质量、step time、吞吐、峰值显存、cache bytes/token、通信和稳定性；针对服务目标再固定 prompt 长度、输出长度、batch、并发和硬件测 TTFT/TPOT、P95/P99 与成功率。方案选择依据应是目标约束下的 Pareto 取舍，而不是组件名称或一项参数比。

读账本时要把“容量够不够”和“容量花得值不值”分开。参数及权重精度决定常驻内存，训练激活与优化器状态决定训练峰值，KV cache 随请求长度和并发增长，显式 attention score 另随序列长度平方增长；它们不是能互相抵扣的一种显存。MoE 还要把 all-to-all 流量、expert 热点与丢弃 token 作为独立约束。若吞吐不达标，应先看 profiler 区分算力、访存和通信瓶颈；若质量下降，则检查训练 token、短长样本分布和评估切片；若仅尾延迟恶化，则检查路由负载、长请求比例和并发。把现象映射到具体账本，才能决定该改宽度、head、长度课程、并行方案还是运行批量。

比较候选时建议先设不可违反的门槛，再优化剩余指标。例如必须达到某个长文检索准确率、最大并发和训练时长后，才比较质量、成本或能耗。每个候选至少保留一份来自相同数据顺序、预算、精度和评估集的记录；对结构或长度课程做消融时一次只改变一个主要因素。若参数数相同但质量不同，检查训练 token 和初始化；若 MAC 相近而 step time 不同，检查 kernel 与通信；若名义窗口相同但远端检索失败，检查长度训练分布和位置策略。这种归因记录可交给第十四章综合设计复用，也避免把局部优化误报成架构整体胜出。

把门槛应用到本例：假设服务为 KV cache 单独预留 24 GiB，要求 batch 4、每条请求的输入加生成长度最多 32K。GQA-8 的 cache 估算是 16 GiB，可以通过这一项容量门槛；相同层数、batch 和长度的 MHA-32 约为 64 GiB，不能通过。这个结论只针对 K/V 数组，不说明其余权重和工作区也能放进显存，更没有证明 GQA 的生成质量相同。若质量、吞吐和尾延迟也通过目标评测，才可进入候选；任何一项失败，都应回到对应账本定位，而非用“总参数相同”替代系统决策。

同理，MoE 的 `1.074B` routed FFN 总参数关系到权重存储和分片，`268.44M` active FFN 参数只近似反映单 token 的选择计算；若容量紧张先检查权重驻留与 all-to-all，若训练计算超预算再看 active 路由量和实际 profiler。这样分别回答“能否装下”“能否在时限内训练”“是否达到目标质量”，不会把几种资源问题压成一个模型大小数字。

把这份账本交给训练团队时，应同时附上参数来源、单位、精度、共享权重规则和省略项；“约 5.77B”若不知道是否计 tied embedding、router 或 final norm，无法和另一个模型直接比较。每次改变 hidden size、层数、词表、上下文、batch 或 KV head 数，都要重算受影响的项目，并标出旧值与新值的差额。小账本的用途是找出明显不可能的组合和指导下一轮实测，不是代替真实 config 导出的 parameter count、内存分析器或目标硬件 profiler。

若账本估算和框架导出值差异大到无法由 bias、对齐 padding 或共享规则解释，应暂停资源推算，先核对实际实例化的层数、词表行数和权重绑定状态。保存 config 与 checkpoint revision 的摘要，能让后续的吞吐和显存结果对应到同一模型形状；只有报告舍入后的“模型规模”，无法复现实测的适用条件。

## 4.13 架构故障的最小排查路径

排查时先把昂贵的训练停下来，用静态配置审计和单批数据流逐层缩小范围；每一步记录输入、观察量和结论，避免同时改学习率、精度和架构后无法归因。

第一步核对静态 shape 与配置：hidden size 是否能被 query-head 数整除，query heads 是否能被 KV heads 整除，旋转维度是否为偶数且不超过 head dimension，token id 是否小于 embedding 行数，MoE 的 `top-k` 是否在 expert 数范围内。再对照实际导出的参数量、权重共享和 checkpoint 参数名。若任一关系不成立，先修配置或权重映射；此时不应靠调学习率掩盖错误。第二步取一条很短的手造序列和一条接近长度上限的样本，检查各层张量 shape、causal/padding mask、有效目标数和 loss 分母；短样本 loss 不下降，优先定位输入、标签右移、mask 广播和梯度连通性，具体训练协议回到[第五章](05-预训练目标与训练循环.md)。

第三步在固定 batch 上做少量前向和反向，记录每层 activation RMS、attention logits 范围、softmax entropy、梯度范数、梯度裁剪比例、loss 以及更新前后参数差。如果所有层从第一步就出现 NaN/Inf，检查输入尺度、dtype、初始化和 kernel；如果只有少数层尺度突变，沿该层 norm、残差输出和 RoPE 输入追踪。梯度处处为零时检查 mask、冻结状态和损失路径；梯度正常但更新骤大，则核对学习率、参数分组、optimizer state 与 loss scale。数值精度与 OOM 诊断见[第八章](08-显存优化与数值精度.md)，跨步 loss 漂移和恢复判断见[第九章](09-训练稳定性与debug.md)。

第四步把长上下文与 MoE 分开测。长度测试固定内容和模型，逐档增加上下文，记录峰值显存、step time、远端证据检索和中间位置干扰；能接收 32K 张量但只能回答开头内容，属于有效利用失败，不是接口失败。MoE 测试则记录每个 expert 的分派/接收 token、容量溢出、router 熵、丢弃率和 all-to-all 时间；平均负载正常可能掩盖序列内热点，aggregate loss 正常也可能与少数 expert 长期闲置同时出现。根据哪个量先越界，区分位置训练不足、cache/激活预算、路由拥塞或通信瓶颈。

第五步验证 checkpoint 语义兼容：逐项比较 tokenizer 与 vocab hash、架构 config、RoPE 位置参数、dtype、参数名、optimizer 与 scheduler state。加载成功后用固定文本比较关键 logits，再做一次小 batch 更新并保存、重载，检查输出和训练状态是否在数值容差内一致。若加载后输出变了而 shape 合法，优先查词表行映射、权重共享和位置配置；若输出一致但恢复后的 loss 轨迹变化，检查 optimizer/scheduler、随机数状态和数据游标。完成这些低成本检查后，才进入固定数据顺序的短跑和较长消融；整套训练事故的时间线与证据链交给[第十四章](14-训练系统综合设计与故障诊断.md)收束。

每次比较都保留一份基准配置和候选配置的差异清单，并用相同的一小批样本复核输入、logits、loss、梯度和更新量。若同时修改了结构、数据长度、优化器和精度，即使结果变好或变坏也无法归因；应回退到最近的可复现基线，再每轮只改一个主变量。诊断记录至少写明故障开始的 step、影响层或 expert、首个异常指标、触发条件、修复后复测结果与未覆盖的边界。排障目标不是保证小跑能预测最终质量，而是尽早排除明显不兼容和数值错误，并明确哪些结论仍需长跑或目标硬件实测。

如果故障只在较长训练中出现，应保留最近一次正常 checkpoint、数据游标和逐步指标，再回看第九章的稳定性诊断；不要把短跑通过写成长期稳定的证明。

同一配置在不同 seed 或 batch 顺序下偶发失败时，还要记录失败频率与触发阶段；单次重跑成功不足以判定已修好。将静态检查、短样本和长样本、小步更新、短程训练按顺序保存结果，可以指出风险是在结构接口、数值路径还是训练时长上出现。

## 4.14 资料边界与延伸阅读

本章参数量、`6PD`、KV cache、MoE active 参数和初始化公式都是量级或教学形式。它们忽略 bias、权重共享、激活重计算、通信、expert overflow、kernel、评估和失败重跑；具体结论应以配置导出的参数、profiler、路由日志和目标硬件实测为准。

- [Attention Is All You Need](https://arxiv.org/abs/1706.03762)：Transformer 与 scaled dot-product attention。

- [GLU Variants Improve Transformer](https://arxiv.org/abs/2002.05202)：门控 FFN 与 SwiGLU。
- [Fast Transformer Decoding: One Write-Head is All You Need](https://arxiv.org/abs/1911.02150)：MQA 与解码缓存。

## 4.15 章节练习：从纸面配置走到小规模验证

### 练习一：参数账本

给定 `d`、层数、query/KV heads、FFN、词表和是否 tied embedding，分别计算 attention、FFN、embedding 和总参数。再用框架导出的参数量对照，找出 bias、norm 或共享权重造成的差异。

### 练习二：GQA 缓存账本

固定层数、head dimension、上下文长度、batch 和 dtype，比较 MHA、GQA、MQA 的 KV cache。说明为什么 cache 降低不等于总显存按同样比例降低。

### 练习三：RoPE 长度实验

在固定模型和短训练上比较原始位置范围、位置缩放和继续训练。构造信息位于开头、中间和末尾的长文本，分别测输入可接受性、检索准确率和计算成本。

### 练习四：Pre-Norm 与初始化

构造不同深度的小型残差网络，比较 Pre-Norm、Post-Norm、不同残差初始化和 warmup。记录 activation RMS、gradient norm、loss 和收敛速度，说明为什么单个初始 loss 不能代表稳定性。

### 练习五：MoE 路由

实现一个 top-k toy router，改变 expert 数、top-k、容量系数和输入分布。报告每 expert token 数、overflow、负载均衡项和通信量，分析为什么总参数和 active 计算必须分开。

### 练习六：架构变更回归

把一个 MHA toy checkpoint 改成 GQA 或增加 special token，列出需要同步的 config、权重、tokenizer、训练数据和评估。设计加载、固定文本生成和小数据过拟合测试。

## 4.16 本章小结

架构设计把目标能力、数据、算力、显存、推理和稳定性转换成模型配置。decoder-only 提供统一的自回归接口；层数、宽度、词表、FFN 和上下文共同决定参数和计算；参数量必须和训练 token 及预算匹配。

RoPE 把位置信息放进 Q/K 几何，RMSNorm 和 Pre-Norm 影响尺度与梯度，SwiGLU 提供门控 FFN，GQA/MQA 在表达能力和 KV cache 之间取舍。长上下文不是一个 config 数字，MoE 也不能只看总参数；两者都需要训练分布、系统成本和目标评估支持。

初始化决定训练从什么数值尺度开始，残差、norm、attention logits、精度和学习率共同决定稳定性。最终的架构结论必须来自参数账本、目标数据、目标硬件、小规模验证和能力评估，而不是来自某个组件名称或论文参数量。
