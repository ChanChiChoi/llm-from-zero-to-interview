# 第四章：模型架构与初始化：把目标约束变成可训练的网络

## 4.0 架构选择是一张预算转换表

训练前的架构设计，不是从组件清单里勾选 RoPE、SwiGLU、RMSNorm 和 GQA。它要回答一个更实际的问题：给定目标能力、训练 token、GPU、上下文长度和部署约束，怎样把容量、计算、显存和稳定性分配到一份可运行的模型配置中。

初学者可以先沿着四个账本理解：

1. 参数账本：层数、宽度、词表、FFN 和 expert 一共需要多少参数。
2. 训练账本：这些参数是否有足够 token 和计算预算被训练充分。
3. 运行账本：序列长度、attention、KV cache、路由和通信需要多少显存与带宽。
4. 稳定账本：初始化、归一化、残差和精度是否让梯度能够持续传播。

专家还要检查这些账本是否互相冲突：一个参数量合适的模型可能因为上下文过长而无法训练；一个 MoE 模型可能总参数很大但 active 参数合理，却被 expert 通信和 overflow 拖慢；一个看似支持长上下文的 RoPE 配置可能只改变了最大位置数，却没有长序列训练和有效检索评估。

本章按因果顺序展开：先从自回归接口和目标约束开始，接着建立参数量和训练算力公式，再说明 decoder-only、RoPE、RMSNorm、SwiGLU、GQA、长上下文和 MoE 的机制，最后讨论初始化、训练稳定性、推理成本和架构审计。

## 4.1 先写清目标和硬约束

### 4.1.1 同一个“7B”可以是不同系统

参数量只描述一个粗略规模，不能说明：

| 未回答的问题 | 为什么重要 |
| --- | --- |
| 训练多少 token | 决定模型是否充分训练 |
| 上下文多长 | 决定 attention 和 KV cache 成本 |
| dense 还是 MoE | 决定总参数与 active 参数关系 |
| 词表多大 | 决定 embedding、softmax 和 token 长度 |
| GQA 还是 MHA | 决定推理缓存和带宽 |
| 目标语言与领域 | 决定 tokenizer、数据和评估切片 |
| 目标吞吐和延迟 | 决定架构能否上线 |

因此，架构配置必须和目标分布绑定。通用 base model、代码模型、企业助手、长文档分析模型和端侧模型，可能使用相似的 Transformer block，却需要不同的序列长度、词表、数据配比和推理取舍。

### 4.1.2 约束表

设计前可先建立如下表：

| 约束 | 示例问题 |
| --- | --- |
| 能力 | 需要通用知识、代码、数学、多语言还是工具调用 |
| 训练数据 | 有多少去重后的有效 token，长样本比例是多少 |
| 训练资源 | GPU 数量、显存、网络、存储和可接受时长 |
| 服务资源 | 并发、TTFT、TPOT、上下文长度和量化格式 |
| 模型接口 | 自回归文本、encoder-decoder、视觉或音频条件 |
| 稳定性 | 允许多大实验风险，是否已有可加载 checkpoint |
| 评估 | 哪些任务和切片决定架构是否成功 |

“架构更先进”不是约束；它只有在改变了目标能力、成本或可维护性时才有决策意义。

### 4.1.3 历史脉络：为什么 decoder-only 占据主流

Transformer 原论文同时讨论了 encoder-decoder 结构。后来，decoder-only 语言模型把文本、代码、对话、工具调用统一为“根据前缀预测后续 token”，在大规模无监督文本上获得了简洁的训练接口和连续的生成接口。

这条路线并不表示 encoder-only 或 encoder-decoder 没有价值。分类、检索、表征学习、翻译和某些条件生成任务仍可能更适合其他结构。decoder-only 成为通用 LLM 主流，主要是因为它把预训练、SFT、对话和推理放进同一个自回归协议，训练与服务生态也围绕这个协议成熟起来。

## 4.2 Decoder-only Transformer 的数据流

### 4.2.1 Causal self-attention

给定 token embedding `X`，模型经过多层 self-attention 和 FFN。causal mask 保证位置 `t` 不能看到未来 token，只根据 `x_{1:t}` 预测 `x_{t+1}`。

scaled dot-product attention 的核心计算为：

~~~math
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^\top}{\sqrt{d_h}}+M
\right)V
~~~

`d_h` 是 head dimension，`M` 是 causal、padding 或其他结构 mask。除以 `sqrt(d_h)` 是为了控制点积方差，避免 logits 随维度增大而过度尖锐。

### 4.2.2 为什么接口统一很重要

同一网络可以处理多种后续目标：

~~~text
预训练：文本前缀 -> 下一个文本 token
SFT：消息前缀 -> assistant token
工具调用：用户上下文 -> tool call token
代码：问题与上下文 -> 代码 token
多模态：文本 + 模态表示 -> 文本或模态 token
~~~

共享接口减少了系统切换成本，但不表示所有任务的监督 mask、数据格式和评估方式相同。统一的是序列预测的骨架，变化的是条件、目标和边界。

### 4.2.3 Encoder-only 和 encoder-decoder 的边界

encoder-only 可以让每个位置双向看到上下文，适合许多理解和表示任务；encoder-decoder 把输入编码和输出生成分开，适合输入输出边界明确的条件生成。选择 decoder-only 应该基于统一生成、规模化训练和服务需求，而不是因为“LLM 都这么做”就跳过任务分析。

## 4.3 参数量账本：从配置看规模

### 4.3.1 基本变量

设 hidden size 为 `d`，层数为 `N_L`，query head 数为 `H_q`，K/V head 数为 `H_kv`，head dimension 为 `d_h`，词表大小为 `V`，FFN 中间维度为 `d_ff`：

~~~math
d=H_qd_h
~~~

GQA 要求 query heads 可以分成若干组共享 K/V：

~~~math
H_q=gH_{\mathrm{kv}}
~~~

这里 `d`、`H_q`、`H_{\mathrm{kv}}` 和 `d_h` 都是正整数，`g` 也是正整数。不能整除时，配置需要调整或由实现采用特殊映射；不能让整数除法静默截去通道，否则 Q、K、V 的形状已经不再属于同一个 attention 协议。

### 4.3.2 Attention 参数

在忽略 bias 的近似下，Q 和 O 投影各约为 `d^2`；GQA 的 K、V 投影分别约为 `dH_kv d_h`。因此：

~~~math
P_{\mathrm{attn}}
\approx
d^2+2dH_{\mathrm{kv}}d_h+d^2
~~~

MHA 是 `H_kv=H_q` 的特殊情况；MQA 则近似使用一个 K/V head。GQA 减少 K/V 投影参数和推理缓存，但不意味着整个模型参数按相同比例下降，因为 FFN 和 Q/O 投影仍然存在。

### 4.3.3 FFN 参数

传统两投影 FFN 约为 `2dd_ff`。SwiGLU 常见形式包含 gate、up 和 down 三个投影，因此：

~~~math
P_{\mathrm{ffn}}
\approx
3dd_{\mathrm{ff}}
~~~

实际模型可能调整 `d_ff` 使参数量对齐、使用 bias 或其他门控形式。FFN 往往是 block 中较大的参数和计算来源，不能只盯着 attention。

### 4.3.4 总参数近似

输入 embedding 约为：

~~~math
P_{\mathrm{emb}}=Vd
~~~

忽略 norm、bias、最终输出层和其他模块：

~~~math
P_{\mathrm{model}}
\approx
P_{\mathrm{emb}}+N_L(P_{\mathrm{attn}}+P_{\mathrm{ffn}})
~~~

若输入 embedding 和输出 softmax 权重不共享，应额外加入约 `Vd`；如果 tied embedding，则不要重复计算。模型配置导出的真实参数统计优先于公式，因为视觉模块、router、shared expert、bias 和权重共享都会改变结果。

### 4.3.5 规模变量之间的取舍

增加层数提高网络深度和逐层变换次数；增加宽度提高每层表示容量，但矩阵乘法和激活显存增长更快；增加词表缩短某些序列，却加重 embedding/softmax；增加上下文扩展输入范围，却加重训练 attention 和推理 cache。架构设计的难点在于这些旋钮相互耦合，而不是记住某个固定 7B 配置。

### 4.3.6 手算一个 block：参数下降比例不等于缓存下降比例

令 `d=4096`、`H_q=32`、`d_h=128`，则 `d=H_qd_h`。MHA 的 Q/K/V/O 四个无 bias 投影约有 `4d^2=67,108,864` 个参数。把 K/V 改成 `H_kv=8` 后，GQA 的 attention 投影约为：

~~~math
P_{\mathrm{GQA-attn}}
=2d^2+2dH_{\mathrm{kv}}d_h
=41,943,040
~~~

attention 投影参数约为 MHA 的 `62.5%`，下降 `37.5%`；但在 head dimension 和 dtype 不变时，K/V cache 变为 `H_kv/H_q=25%`，下降 `75%`。两者比例不同，是因为 attention 参数还包含没有缩小的 Q、O 投影，而 cache 只存 K 和 V。

FFN 也会改变整层的结论。若用普通两矩阵 FFN 且 `d_ff=4d=16,384`，参数约 `2dd_ff=134,217,728`。SwiGLU 有三矩阵，若把中间宽度调到约 `8d/3` 以便等参数比较，取整数 `d_ff=10,923` 时约 `3dd_ff=134,221,824`。在这组设置里，FFN 参数约是 MHA attention 投影的两倍；只报告 GQA 的 attention 参数比，会夸大它对整层参数量的影响。这里不含 bias、norm、embedding、输出头和 kernel 临时张量。

## 4.4 参数量和训练 token 的匹配

### 4.4.1 训练预算的第一阶关系

若模型参数量为 `P`，训练 token 数为 `D`，dense Transformer 的训练 FLOPs 可以用：

~~~math
C_{\mathrm{train}}
\approx
6PD
~~~

它是规模估算，不包括通信、激活重计算、评估、checkpoint、MoE 路由和失败重跑。token/parameter 比例为：

~~~math
r_{\mathrm{tok/param}}
=
\frac{D}{P}
~~~

这两式要求 `P>0`、`D>0`；MoE 的 `P` 还必须说明是总参数还是每 token active 参数。Chinchilla 风格研究说明，在固定计算预算下，参数和数据需要共同规划，训练不足的大模型可能不如训练更充分的较小模型。这个经验关系依赖数据质量、架构、目标和预算，不能被当作跨项目的硬性定律。

### 4.4.2 能力模型与部署模型可能不同

如果目标是研究 base model，可能把更多预算放在预训练 token；如果目标是企业助手，可能需要把预算放在领域继续预训练、SFT、偏好、安全和评估；如果目标是端侧部署，模型结构要从一开始考虑量化和缓存，而不是训练结束后才发现无法运行。

参数量不是能力、速度或成本的单一代理。MoE 还要分开总参数和 active 参数；长上下文还要分开短序列训练 throughput 与长序列显存。

## 4.5 RoPE：在 Q/K 几何中加入位置

### 4.5.1 频率表如何确定

设参与旋转的通道维度为偶数 `d_rot`，第 `i` 对通道常用的角频率是：

~~~math
\theta_i=\mathrm{base}^{-2i/d_{\mathrm{rot}}},
\qquad i=0,1,\ldots,d_{\mathrm{rot}}/2-1
~~~

位置 `p` 上的旋转角为 `p\theta_i`。常见的 `base=10,000` 只是配置值，不是 RoPE 的数学定律；不同模型可能调整 base、只旋转部分 head dimension，或再对频率做缩放。以 `d_rot=8`、`base=10,000` 为例，四组频率依次是 `1、0.1、0.01、0.001`。低编号通道随位置变化更快，适合表示近邻差异；高编号通道变化更慢，能覆盖更长距离。实际实现还要核对偶/奇通道配对、频率布局和 position id 是否与 checkpoint 一致。

### 4.5.2 二维旋转

把 Q 或 K 的通道两两分组，位置 `p` 在第 `i` 个二维子空间上的旋转为：

~~~math
\begin{bmatrix}
q'_{2i}\\
q'_{2i+1}
\end{bmatrix}
=
\begin{bmatrix}
\cos(p\theta_i)&-\sin(p\theta_i)\\
\sin(p\theta_i)&\cos(p\theta_i)
\end{bmatrix}
\begin{bmatrix}
q_{2i}\\
q_{2i+1}
\end{bmatrix}
~~~

K 使用同样的旋转。与把一个位置向量直接加到 embedding 上不同，RoPE 改变了 attention 中 Q/K 的几何关系。

### 4.5.3 相对位移的性质

旋转满足组合关系，在理想二维子空间中：

~~~math
\langle R_mq,R_nk\rangle
=
\langle q,R_{n-m}k\rangle
~~~

这个等式要求 Q/K 的旋转维度按二维配对，使用同一频率表和一致的位置索引；半精度下的频率计算、partial rotary 和插值会改变实现细节。它解释了相对位置信息如何进入点积，但这个性质不等于任意长度外推。训练长度、频率范围、RoPE base、缩放方式和长文本数据决定模型是否能在远距离上保持稳定。

### 4.5.4 长上下文扩展：从插值到非均匀频率搜索

RoPE 在训练长度以外可能产生模型未见过的旋转相位；单纯把 `max_position_embeddings` 改大只放宽配置检查，并没有教会模型在远距离使用证据。代表路线按“如何把新位置映射回模型熟悉的相位范围”逐步发展：

| 方案 | 要解决的问题 | 主要做法 | 论文报告与限制 |
| --- | --- | --- | --- |
| Position Interpolation (PI) | 直接外推到新位置会产生训练中没见过的相位，注意力分数可能失控 | 把新位置线性缩回原训练范围，并用少量长序列继续训练 | 在 LLaMA 7B–65B 的测试中扩展到 32K，作者报告最多 1,000 步微调；压缩所有位置也会改变近距离相位，需检查原长度能力回归。[论文](https://arxiv.org/abs/2306.15595) |
| YaRN | 全频率等比例缩放会在短距离精度和长距离范围之间产生不必要的折中 | 根据波长对频率分段插值，并平滑过渡；配合注意力温度校正和高效长上下文微调 | 作者报告相对其比较的既有扩展方法少用约 10 倍 token、2.5 倍训练步数；这不是所有模型或训练配方上的固定倍率。[论文](https://arxiv.org/abs/2309.00071) |
| LongRoPE | 不同旋转维度和位置并不需要统一缩放，极长位置仍可能损害短上下文 | 搜索维度相关的非均匀插值因子，先扩展至 256K，再分阶段推进到 2M，并单独恢复 8K 能力 | 作者在 LLaMA 2、Mistral 设置中报告超过 2M 窗口、最多约 1,000 步扩展微调；这是特定模型、数据和评测结果，不等于任意 2M 输入都可有效推理。[论文](https://arxiv.org/abs/2402.13753) |

这些工作共同解决“位置编号能否输入”和“远端信息能否可靠利用”之间的落差，但它们改变的对象、训练预算和任务集不同，不能仅按最大 context 数字排名。每次扩展应记录：

1. 原始训练长度和目标长度。
2. 具体频率/位置变换及实现版本，不能只保存 `rope_scaling` 的名字。
3. 继续训练的 token 数、长度分布、训练步数和短上下文回归。
4. 长文中证据所在位置、干扰项密度和跨段组合方式。
5. 目标长度上的检索质量、生成质量、显存、吞吐和失败样例。

长上下文模型可以接收长输入，却在中间位置找不到证据；因此位置容量和有效利用能力必须分开测量。PI、YaRN 或 LongRoPE 的论文结果提供可复用的实验设计，不替代目标 checkpoint 的长文评测。

## 4.6 RMSNorm、Pre-Norm 与残差流

### 4.6.1 RMSNorm

LayerNorm 先减均值，再按方差缩放：

~~~math
\mu(x)=\frac{1}{d}\sum_i x_i,
\qquad
\mathrm{LN}(x)_i
=\gamma_i\frac{x_i-\mu(x)}{\sqrt{\frac{1}{d}\sum_j(x_j-\mu(x))^2+\epsilon}}+\beta_i
~~~

RMSNorm 不做中心化，而用均方根缩放：

~~~math
\mathrm{RMS}(x)
=
\sqrt{\frac{1}{d}\sum_{i=1}^{d}x_i^2+\epsilon}
~~~

~~~math
y_i
=
\gamma_i\frac{x_i}{\mathrm{RMS}(x)}
~~~

这里 `d>0`、`\epsilon>0`，并且输入应为有限值；`\epsilon` 是防止零向量除零的数值常数，不能用来掩盖激活中的 NaN 或 Inf。RMSNorm 保留对输入整体缩放的归一化，但不具备 LayerNorm 的平移不变性。RMSNorm 原论文的出发点是检验 re-centering 是否必要；作者在其多种网络和任务中报告相对 LayerNorm 有相近表现、运行时间减少 7%–64%，但这些数字来自论文当时的模型与硬件，不能直接承诺现代 LLM 训练提速幅度。[RMSNorm 原论文](https://arxiv.org/abs/1910.07467)

### 4.6.2 Pre-Norm 和 Post-Norm

一个子层 `F` 的 Pre-Norm 形式为：

~~~math
x_{\ell+1}=x_\ell+F_\ell(\mathrm{Norm}(x_\ell))
~~~

Post-Norm 的简化形式为：

~~~math
x_{\ell+1}=\mathrm{Norm}(x_\ell+F_\ell(x_\ell))
~~~

Pre-Norm 给残差提供更直接的梯度路径；Post-Norm 则在残差相加后归一化。Xiong 等人的 mean-field 分析指出，Post-LN 初始化时靠近输出层的期望梯度偏大，可解释 warmup 为什么对其训练稳定性有帮助；同一分析发现 Pre-LN 初始化的梯度行为更平稳，并在所测任务上展示了不使用 warmup 的可训练性。[Pre-LN/Post-LN 研究](https://arxiv.org/abs/2002.04745)

这解释的是初始化附近的一类梯度问题，不证明 Pre-Norm 在所有深度、学习率、精度和任务上都更优。Pre-Norm 会保留更直接的 residual stream，也可能改变最终 hidden-state 的尺度和表征；所以比较时要同步报告是否有 final norm、warmup、残差缩放、训练稳定性和下游质量。

### 4.6.3 残差尺度

每一层都向残差流加入更新。若更新尺度过大，深层累积可能导致激活和梯度异常；若过小，模型可能学习缓慢。架构可能通过初始化、residual scaling、norm 或零初始化某些输出投影控制尺度。

一个教学级的残差初始化直觉是：若基础标准差为 `sigma`，层数为 `N_L`，每个 block 含 attention 与 FFN 两条残差分支，且先假设各分支更新近似独立、零均值、方差相近，则总共约有 `2N_L` 次方差累积。让每条支路的标准差下降到下式的量级，可使独立假设下的累计方差保持在原数量级：

~~~math
\sigma_{\mathrm{res}}
\approx
\frac{\sigma}{\sqrt{2N_L}}
~~~

该近似要求基础标准差 `\sigma>0`、层数 `N_L>0`，也依赖残差更新独立、零均值和同方差等简化假设。真实网络中分支相关、Norm、激活和优化器更新都会打破这些假设，因此它只是说明“深度会累计更新尺度”的教学推导，不是通用初始化定律。

### 4.6.4 深度扩展与宽度扩展是不同问题

| 研究路线 | 原本遇到的困难 | 主要处理 | 得到的证据和边界 |
| --- | --- | --- | --- |
| Pre-LN 分析 | Post-LN 深层训练初期梯度偏大，需要 warmup 缓冲 | 用 mean-field 梯度分析解释 Norm 的位置如何影响初始化梯度 | 对所测架构说明了 warmup 需求来源；不能推成“Pre-LN 不需要 warmup”，实际 recipe 仍需验证。[论文](https://arxiv.org/abs/2002.04745) |
| DeepNorm / DeepNet | 常规 Pre-LN/Post-LN 设计难以直接扩到极深 Transformer | 同时改残差连接的尺度和初始化，理论约束模型更新幅度 | 论文报告扩展到 1,000 层，并在多语翻译中训练 200 层、3.2B 参数模型；这是 encoder-decoder 翻译设置，不直接证明同样规则适用于现代 decoder-only 预训练。[论文](https://arxiv.org/abs/2203.00555) |
| μP / μTransfer | 每次加宽模型都重新搜索学习率等超参，试验成本随规模上升 | 按宽度定义参数化，使一部分最优超参可从小模型迁移到大模型 | 论文在 Transformer、ResNet 上验证小模型到大模型的超参迁移；μP 不是某一个初始化标准差公式，也不是把普通 checkpoint 直接套上就能迁移。[论文](https://arxiv.org/abs/2203.03466) |

阅读这些路线时应先问它解决的轴是什么：Pre-LN 主要分析归一化位置与初始梯度，DeepNorm 针对深度方向的 update stability，μP 针对宽度变化时的参数化和超参迁移。它们会相互作用，但不能把名字放在同一张“初始化方法”清单里就认为可以互换。

## 4.7 SwiGLU：门控 FFN 的参数和计算

### 4.7.1 机制

一个常见的 SwiGLU 形式为：

~~~math
\mathrm{SwiGLU}(x)
=
\left[\mathrm{swish}(xW_g)\odot(xW_u)\right]W_d
~~~

`W_g` 是 gate projection，`W_u` 是 up projection，`W_d` 是 down projection，`odot` 是逐元素乘。门控让一条投影控制另一条投影的通道贡献，相比单一激活函数提供更灵活的非线性变换。

### 4.7.2 为什么 FFN 中间维度要重新校准

SwiGLU 有三个投影，若直接使用传统 FFN 的 `d_ff`，参数量和矩阵乘法会增加。因此模型常调整中间维度，让不同 FFN 方案在目标参数量下比较。以普通 FFN 的 `d_ff=4d` 为例，参数量为 `8d^2`；SwiGLU 若取 `d_ff≈8d/3`，三矩阵参数量也约为 `8d^2`。不能只看到 “SwiGLU” 就认为模型参数和传统 FFN 相同。

Shazeer 对 Transformer 序列到序列模型中的 GLU 变体做了实验，发现若干门控激活在其设置下优于 ReLU/GELU；论文支持的是“门控 FFN 值得对照实验”，没有给出对现代 decoder-only LLM 的通用因果解释，也没有证明 SwiGLU 在任意等参数、等训练预算下都胜出。[论文](https://arxiv.org/abs/2002.05202)

等参数不等于等延迟：三次投影的实际成本还取决于矩阵形状、融合 kernel、精度和硬件利用率。工程上应固定总参数或训练 FLOPs做消融，同时报告 loss/下游质量与目标硬件吞吐；如果模型变窄后质量变化，也要检查 FFN 激活内存和 kernel 是否变得更高效。

### 4.7.3 边界

SwiGLU 改变的是 block 内的非线性变换，不会自动解决数据不足、长上下文检索、工具安全或推理成本。它的收益必须在固定参数、token、优化器、数据和评估协议下比较。

## 4.8 MHA、MQA 和 GQA：把注意力质量换成缓存成本

### 4.8.1 KV cache 账本

标准 MHA 为每个 query head 保存 K/V；MQA 共享一组 K/V；GQA 把 query heads 分成若干组。每层每 token 的 K/V cache 近似为：

~~~math
M_{\mathrm{KV,layer}}
=
2H_{\mathrm{kv}}d_hb
~~~

`b` 是每个数值的字节数。batch、上下文和层数纳入后：

~~~math
M_{\mathrm{KV}}
=
B C_{\mathrm{ctx}}N_L
\left(2H_{\mathrm{kv}}d_hb\right)
~~~

若从 MHA 改成 GQA，缓存近似按：

~~~math
\frac{M_{\mathrm{GQA}}}{M_{\mathrm{MHA}}}
=
\frac{H_{\mathrm{kv}}}{H_q}
~~~

这些式子要求 batch `B`、上下文 `C_{\mathrm{ctx}}`、层数 `N_L`、K/V head 数、head dimension 和字节数 `b` 都为正；若 runtime 使用分页、量化或压缩缓存，必须按实际 block 和 dtype 重算。这个比例只描述 K/V cache，不等于总模型显存、总延迟或质量变化。

### 4.8.2 三种结构的取舍

| 结构 | K/V 组织 | 主要优势 | 主要代价 |
| --- | --- | --- | --- |
| MHA | 每个 query head 一组 K/V | 表达和迁移直观 | cache 和带宽高 |
| MQA | 所有 query head 共享一组 K/V | cache 最小 | 可能损失表达能力 |
| GQA | 每组 query head 共享 K/V | 质量与 cache 的折中 | 配置、迁移和实现更复杂 |

GQA 不是只在服务端打开的优化开关，而是训练时就确定的 projection 形状和模型结构。Ainslie 等人的上转换路线先把 MHA 每个 group 内的 K/V 投影矩阵做 mean pooling，再按原配方继续预训练。论文 T5-XXL 主表中，约使用原预训练计算 5% 的 GQA-8 平均分是 47.1、每 TPUv4 芯片样本时间 0.28 秒；MHA-XXL 是 47.2 和 1.51 秒，MQA-XXL 是 46.6 和 0.24 秒。平均分混合摘要 ROUGE、翻译 BLEU 和 QA F1，时间也依赖各自调优的并行与 batch 设置，不能当作统一 benchmark 或现代 decoder-only 的速度预测；长摘要评测的 ROUGE 也不足以覆盖全部质量。[GQA 论文及局限](https://arxiv.org/html/2305.13245v3)

Llama 2 团队也做了 attention 架构消融，并为 34B/70B 选择 GQA。其选择同时考虑 benchmark 结果、较大 batch 下的吞吐、张量并行的 KV 分片，以及 MQA 在多 GPU 上需要复制 KV 或改按 batch 切分的服务代价；这说明缓存公式只是系统账本的一项，TP 拓扑和 batch 分布也会改变实际优势。[Llama 2 attention 消融](https://arxiv.org/html/2307.09288v2)

因此，把 MHA checkpoint 转成 GQA 时，不能只平均权重后就宣布完成：要记录 group 划分和 K/V 聚合方式，做继续训练或校准，并在相同模型、prompt、batch、输入长度、输出长度和硬件布局下比较质量、吞吐、P95 延迟与显存。离线质量变化和线上可服务并发是两个不同结果。

## 4.9 上下文长度：训练分布和运行成本的共同约束

### 4.9.1 训练与推理的不同成本

标准全量 attention 的注意力矩阵随序列长度近似二次增长：

~~~math
M_{\mathrm{attn}}
\propto
B H_q C_{\mathrm{ctx}}^2
~~~

自回归 decode 阶段，KV cache 随上下文线性增长：

~~~math
M_{\mathrm{KV}}
\propto
B C_{\mathrm{ctx}}N_LH_{\mathrm{kv}}d_h
~~~

比例关系只描述正长度序列上的主导项，并省略 layer 数、dtype、block sparsity、FlashAttention 的临时存储和 kernel 常数；空序列或零 head 不是“零成本长上下文”，而是无效配置。因此训练长上下文主要面对 attention 和激活成本，推理长上下文主要面对 cache 容量、读写带宽和并发。两者需要不同的 profiling。

### 4.9.2 长上下文的有效能力

训练数据几乎全是短样本时，模型可能接受长输入但不会使用远端信息。评估应包含：

1. 关键信息在开头、中间和末尾的位置切片。
2. 多文档检索和跨段组合。
3. 长上下文中的干扰项。
4. 代码、表格、JSON 和多语言长文本。
5. 位置外推和截断边界。

上下文窗口是接口上限；有效上下文是模型能在成本约束下可靠使用的输入分布。架构配置、长序列训练、检索策略和评估必须同时出现，不能只把一个数字写进 config。

## 4.10 MoE：总容量与 active 计算分开记账

### 4.10.1 Dense 与稀疏路由

Dense FFN 对每个 token 使用同一套参数。MoE 有 `E` 个 routed experts，每个 token 选择 `k` 个；模型还可以另有每个 token 都执行的 shared experts。若单个 routed expert FFN 参数量为 `P_expert`：

~~~math
P_{\mathrm{total,FFN}}
=EP_{\mathrm{expert}}+P_{\mathrm{shared}}+P_{\mathrm{router}}
~~~

~~~math
P_{\mathrm{active,FFN}}
\approx kP_{\mathrm{expert}}+P_{\mathrm{shared}}+P_{\mathrm{router}}
~~~

这里 `E>0`、`P_{\mathrm{expert}}>0`，且 `1\le k\le E`；`E` 只计 routed experts，`P_{\mathrm{shared}}` 是每个 token 都执行的 shared expert 参数，`P_{\mathrm{router}}` 是路由器参数。没有 shared expert 时令其为 0；路由是否归一化、top-k 是否按组路由及是否按 token 丢弃都会改变真实 active 计算。这只是 FFN 部分的近似；attention、embedding、最终输出头和其他模块还要单独计入。总参数大，不等于每 token 都执行全部参数，也不保证实际 FLOPs 与同 active 参数的 dense 模型相等。

### 4.10.2 路由和负载均衡

路由器为 token `t` 和 expert `e` 产生概率 `p_{t,e}`，选择 top-k。一个 batch 有 `T` 个 token 时，可以定义实际分发比例和平均路由概率：

~~~math
f_e
=
\frac{\#\{\text{tokens dispatched to }e\}}{Tk}
,
\qquad
P_e
=
\frac{1}{T}\sum_{t=1}^{T}p_{t,e}
~~~

一种常见的辅助负载均衡损失写成：

~~~math
L_{\mathrm{aux}}
=
E\sum_{e=1}^{E}f_eP_e
~~~

这些统计要求 `T>0`、`k>0`，并明确 `f_e` 是分派尝试还是容量裁剪后的实际接收比例；两种口径会给 overflow 系统不同的结论。该式中的 `p_{t,e}` 还应是有限且按 expert 归一化的路由概率。Switch top-1 和 GShard top-2 对 `f_e`、`P_e` 的定义并不完全相同；batch-wise 平衡也不保证每个序列内部都均衡。辅助项的权重过小会压不住路由集中，过大又可能把主任务目标推偏。

路由负载和路由数值稳定是两个不同问题。ST-MoE 对 router logits 使用 z-loss：

~~~math
L_z
=\frac{1}{T}\sum_{t=1}^{T}
\left(\log\sum_{e=1}^{E}\exp(z_{t,e})\right)^2
~~~

其中 `z_{t,e}` 是 softmax 前的 router logit。它惩罚过大的 log-sum-exp，降低 router 指数运算在低精度下因舍入误差导致的训练不稳定；它不直接保证 expert 负载均匀，所以不能替代 load-balancing loss 或服务侧的路由统计。ST-MoE 的特定 stability sweep 中，baseline 6 次运行有 4 次稳定，加入 router z-loss 后 3/3 稳定，且报告的质量没有下降；这支持它作为该 recipe 的数值稳定修复，不证明所有 MoE 都需要同一系数或有相同收益。[ST-MoE 的稳定性实验](https://arxiv.org/html/2202.08906)

### 4.10.3 代表方案各自解决了什么

| 研究/方案 | 主要困难 | 机制和作者报告 | 留下的取舍 |
| --- | --- | --- | --- |
| Sparsely-Gated MoE | 增加模型容量时，稠密计算也随参数量线性增加 | Shazeer 等人让 gate 按 token 激活少量 FFN experts，展示了条件计算扩大参数容量的可行性 | 路由、负载不均和跨设备 dispatch 使它不只是“多复制几份 FFN”。[论文](https://arxiv.org/abs/1701.06538) |
| GShard | 大规模 MoE 的模型定义和设备切分难以手工管理 | top-2 expert routing 与自动分片配合，在 2,048 个 TPU v3 上训练 600B 级多语翻译模型 | 证明了并行系统能把稀疏模型扩到更大规模；结果绑定 NMT、TPU 与 XLA 设置。[论文](https://arxiv.org/abs/2006.16668) |
| Switch Transformer | top-2 通信和计算复杂，稀疏训练也有不稳定问题 | 简化为每 token 选择 top-1 expert，并改进训练 recipe；报告同资源下最高 7× 预训练加速和 BF16 大模型训练 | top-1 降少 dispatch，但 capacity、token dropping 和负载均衡仍需处理；报告的加速是 T5/多语实验，不是任意 dense LLM 的推理倍速。[论文](https://arxiv.org/abs/2101.03961) |
| ST-MoE | 稀疏模型预训练不稳定，微调质量对 recipe 敏感 | router z-loss 控制 logits，系统比较稳定性、precision、router 与 fine-tuning；构建 269B/32B-compute 级模型 | z-loss 解决数值尺度问题，不负责均匀分发；作者也发现 sparse 与 dense 模型对微调数据和超参的敏感性不同。[论文](https://arxiv.org/abs/2202.08906) |
| Expert Choice | 固定 top-k 的 token-choice 路由使不同 expert 收到的 token 数不均 | 让 experts 反过来选择固定 bucket 中的 top-k tokens，作者在其同资源对照中报告相较 Switch/GShard 收敛时间超过 2× | 每个 token 接收的 expert 数变成可变，可能为 0 或多个；它改变了 token-choice 路由语义，且结果不能迁移成普遍训练加速保证。[论文](https://arxiv.org/abs/2202.09368) |
| DeepSeek-V3 auxiliary-loss-free balance | 均衡辅助损失可能与主任务目标发生拉扯 | 为每个 routed expert 维护 routing bias，根据整批 token 的负载更新；bias 参与 top-k 选择，但实际 gate weight 仍由原 affinity 得出。另用 sequence-wise 辅助损失防止单条序列内部极端失衡 | “auxiliary-loss-free”指其 batch-wise 主平衡策略不靠经典负载损失；并非模型完全没有辅助平衡项。结果是 DeepSeek-V3 的模型/训练/集群共设计案例。[技术报告](https://arxiv.org/html/2412.19437v2) |

这条研究线不是简单从旧到新、每一代全面替代上一代。问题至少分成四类：算力与容量、token/expert 均衡、router 数值稳定、跨设备通信。评估 MoE 方案时，应把每一类问题分别对应到实验指标和故障日志。

### 4.10.4 Capacity 和 token overflow

给定容量系数 `alpha`，expert 容量可以粗略估算为：

~~~math
C_e
=
\left\lceil
\alpha\frac{kT}{E}
\right\rceil
~~~

这里 `\alpha>0`、`T>0`、`E>0` 和 `1\le k\le E`。超过容量的 token 可能被丢弃、转发到 shared expert、使用 residual path 或采用更复杂的 dispatch。应记录 overflow rate、每 expert token 数、router entropy、通信时间和辅助损失，而不是只看总 loss。

### 4.10.5 MoE 的工程边界

MoE 可能在固定 active 计算下扩展总容量，也可能带来多语言或多领域的路由分工；但它增加 expert parallel、all-to-all 通信、负载不均和 checkpoint 管理复杂度。服务端还要处理 expert 权重加载、并发和路由稳定性。选择 MoE 需要用目标集群和目标负载实测，而不是只比较论文参数量。

## 4.11 初始化：让第一步更新处在可控尺度

### 4.11.1 方差直觉

线性层初始化通常希望输入输出方差处在同一数量级。Xavier 风格的一个标准差形式为：

~~~math
\sigma_{\mathrm{xavier}}
=
\sqrt{\frac{2}{f_{\mathrm{in}}+f_{\mathrm{out}}}}
~~~

当输入输出维度都约为 `d` 时，数量级接近 `1/sqrt(d)`。这只是方差传播直觉；真实 LLM 还要考虑残差、norm、激活、学习率和精度。

### 4.11.2 残差输出和深度

如果每个 block 都向 residual stream 加入同量级扰动，深度增加可能积累过大的激活。一个教学级的缩放形式为：

~~~math
\sigma_{\mathrm{res}}
\approx
\frac{\sigma}{\sqrt{2N_L}}
~~~

实际架构可能把某些 residual output 零初始化、使用额外缩放或采用 μP 等参数化策略。判断初始化不能只看一个标准差，还要看：

1. 初始 activation RMS。
2. 每层 gradient norm。
3. attention logits 和 softmax entropy。
4. 第一百个或第一个千个 step 的 loss。
5. 不同宽度和深度的缩放实验。

### 4.11.3 新 token 的 embedding

扩展词表后，原 embedding 从 `V x d` 变为：

~~~math
E'\in\mathbb{R}^{(V+K)\times d}
~~~

新行可以随机初始化、使用相关 token 平均或其他初始化，但都需要包含新 token 的继续训练。随机初始化只是数值起点，不是语义。

### 4.11.4 从 checkpoint 继续训练

继续训练时，初始化来自已有状态，至少要核对 tokenizer、vocab、架构 config、RoPE 参数、权重 dtype、optimizer state 和 scheduler state。改变其中一项可能是有意实验，也可能是隐蔽协议错误；无论哪一种，都要有固定小数据回归和加载日志。

## 4.12 稳定性：架构、优化器和精度共同作用

### 4.12.1 Pre-Norm 的梯度路径

Pre-Norm 子层可以写成：

~~~math
x_{\ell+1}
=
x_\ell+F_\ell(\mathrm{Norm}(x_\ell))
~~~

残差路径使梯度有较直接的传播通道，通常有利于深层训练。Post-Norm 为：

~~~math
x_{\ell+1}
=
\mathrm{Norm}(x_\ell+F_\ell(x_\ell))
~~~

两者的差异还会和最终 norm、初始化、学习率 warmup、残差缩放及精度实现共同作用。不能把 Pre-Norm 当成“无需调参的稳定性开关”。

### 4.12.2 Attention logits 和数值精度

scaled dot-product 的 `sqrt(d_h)` 缩放控制点积量级；softmax、RoPE、norm 和低精度 kernel 又共同决定实际数值分布。训练中应观察 logits 范围、attention entropy、activation RMS、overflow 和 NaN，而不是只在 loss 变坏后再排查。

### 4.12.3 稳定性实验

架构变更应先在小模型和小数据上验证：

1. 能否过拟合少量样本。
2. 初始 loss 是否在合理范围。
3. gradient norm 是否随深度异常增长。
4. 加长序列后是否出现显存或数值突变。
5. 改变 batch、精度和 seed 后是否仍然可训练。

小实验不能证明大规模最终能力，但可以快速排除 shape、mask、初始化和数值错误。

## 4.13 架构如何转换成推理成本

| 架构变量 | 直接影响 |
| --- | --- |
| `d` 增大 | 每 token 矩阵计算、激活和通信增加 |
| `N_L` 增大 | 每步 decode 层数和 cache 增加 |
| `V` 增大 | embedding、logits 和采样成本增加 |
| `C_ctx` 增大 | 训练 attention 和推理 cache 增加 |
| `H_kv` 增大 | KV cache 与带宽增加 |
| MoE experts 增大 | 总权重、路由和通信复杂度增加 |
| `k` 增大 | active FFN 计算和 dispatch 增加 |

端侧模型需要关注参数、量化、KV cache 和单请求延迟；服务端模型需要关注 batch、并发、GQA、expert 并行和显存；研究模型可能把更多预算放在能力上限。训练前决定的结构会限制后续服务优化空间，因此部署约束必须尽早参与架构设计。

## 4.14 一个训练前架构账本

下面的标准库示例把参数量、GQA cache、训练 FLOPs、初始化数量级、RMSNorm、单频率 RoPE 和 MoE FFN 子账本放在一起。为避免把两种模型混为一谈，主账本统计“每层都是 dense FFN”的 dense reference；MoE 统计则是“单个 MoE FFN 层”的专家总参数与 top-k active 专家参数，不并入 dense reference 的总参数和 `6PD`。代码只用于说明口径，不是完整模型配置导出器；真实项目需要把 shared expert、router、MoE 层分布、权重共享、输出头、目标硬件和评估加入账本。

> **代码状态：静态审阅，未运行（2026-10-26）。** 仅依赖 Python 标准库；输出是账本代理值，不是模型 profile。

~~~python
import math


config = {
    "vocab_size": 32000,
    "hidden_size": 4096,
    "num_layers": 32,
    "query_heads": 32,
    "kv_heads": 8,
    "ffn_size": 11008,
    "context_length": 4096,
    "batch_size": 4,
    "bytes_per_value": 2,
    "train_tokens": 120_000_000_000,
    "moe_experts": 8,
    "moe_top_k": 2,
}


def require_positive_int(name, value):
    if not isinstance(value, int) or isinstance(value, bool) or value <= 0:
        raise ValueError(f"{name} must be a positive integer")


def require_finite_number(name, value):
    if not isinstance(value, (int, float)) or isinstance(value, bool):
        raise ValueError(f"{name} must be finite")
    if not math.isfinite(value):
        raise ValueError(f"{name} must be finite")


def validate_config(config):
    if not isinstance(config, dict):
        raise ValueError("config must be a mapping")
    required = {
        "vocab_size",
        "hidden_size",
        "num_layers",
        "query_heads",
        "kv_heads",
        "ffn_size",
        "context_length",
        "batch_size",
        "bytes_per_value",
        "train_tokens",
        "moe_experts",
        "moe_top_k",
    }
    missing = required - set(config)
    if missing:
        raise ValueError(f"config is missing keys: {sorted(missing)}")
    for name in required:
        require_positive_int(name, config[name])
    if config["hidden_size"] % config["query_heads"]:
        raise ValueError("hidden_size must divide evenly by query_heads")
    if config["query_heads"] % config["kv_heads"]:
        raise ValueError("query_heads must divide evenly by kv_heads")
    if config["moe_top_k"] > config["moe_experts"]:
        raise ValueError("moe_top_k cannot exceed moe_experts")


def architecture_stats(config):
    validate_config(config)
    d = config["hidden_size"]
    layers = config["num_layers"]
    query_heads = config["query_heads"]
    kv_heads = config["kv_heads"]
    head_dim = d // query_heads
    ffn = config["ffn_size"]
    vocab = config["vocab_size"]

    q_params = d * d
    k_params = d * kv_heads * head_dim
    v_params = d * kv_heads * head_dim
    o_params = d * d
    attention_params = q_params + k_params + v_params + o_params
    mha_attention_params = 4 * d * d
    ffn_params = 3 * d * ffn
    norm_params = 2 * d
    block_params = attention_params + ffn_params + norm_params
    embedding_params = vocab * d
    dense_reference_params = embedding_params + layers * block_params

    kv_bytes_per_layer_token = 2 * kv_heads * head_dim * config["bytes_per_value"]
    kv_cache_gib = (
        kv_bytes_per_layer_token
        * layers
        * config["context_length"]
        * config["batch_size"]
        / 1024**3
    )
    mha_cache_gib = kv_cache_gib * query_heads / kv_heads
    train_flops_dense_reference = 6 * dense_reference_params * config["train_tokens"]

    return {
        "head_dim": head_dim,
        "attention_params": attention_params,
        "mha_attention_params": mha_attention_params,
        "gqa_attention_ratio": attention_params / mha_attention_params,
        "ffn_params": ffn_params,
        "block_params": block_params,
        "dense_reference_params": dense_reference_params,
        "kv_cache_gib": kv_cache_gib,
        "mha_cache_gib": mha_cache_gib,
        "train_flops_dense_reference": train_flops_dense_reference,
    }


def rms_norm(values, eps=1e-6):
    if not isinstance(values, (list, tuple)) or not values:
        raise ValueError("values must be a non-empty sequence")
    if any(
        not isinstance(value, (int, float))
        or isinstance(value, bool)
        or not math.isfinite(value)
        for value in values
    ):
        raise ValueError("values must be finite numbers")
    require_finite_number("eps", eps)
    if eps <= 0:
        raise ValueError("eps must be positive")
    max_abs = max(abs(value) for value in values)
    if max_abs == 0:
        return [0.0 for _ in values]
    sqrt_eps = math.sqrt(eps)
    if max_abs <= sqrt_eps:
        scaled_values = [value / sqrt_eps for value in values]
        denominator = math.sqrt(
            sum(value * value for value in scaled_values) / len(values) + 1.0
        )
        return [value / denominator for value in scaled_values]
    scaled_values = [value / max_abs for value in values]
    eps_scaled = (sqrt_eps / max_abs) ** 2
    denominator = math.sqrt(
        sum(value * value for value in scaled_values) / len(values) + eps_scaled
    )
    return [value / denominator for value in scaled_values]


def rope_pair_fixed_frequency(first, second, position, theta):
    """Rotate one 2D pair at one fixed frequency, not a full RoPE head."""
    require_finite_number("first", first)
    require_finite_number("second", second)
    if (
        not isinstance(position, int)
        or isinstance(position, bool)
        or position < 0
    ):
        raise ValueError("position must be a non-negative integer")
    require_finite_number("theta", theta)
    try:
        angle = position * theta
    except OverflowError as exc:
        raise ValueError("position * theta must be finite") from exc
    require_finite_number("position * theta", angle)
    cosine = math.cos(angle)
    sine = math.sin(angle)
    return [
        cosine * first - sine * second,
        sine * first + cosine * second,
    ]


def initialization_stds(config):
    validate_config(config)
    d = config["hidden_size"]
    base = math.sqrt(2.0 / (d + d))
    residual = base / math.sqrt(2 * config["num_layers"])
    return base, residual


stats = architecture_stats(config)
base_std, residual_std = initialization_stds(config)
expert_ffn = 3 * config["hidden_size"] * config["ffn_size"]
moe_total = config["moe_experts"] * expert_ffn
moe_active = config["moe_top_k"] * expert_ffn
tokens_per_dense_reference_param = (
    config["train_tokens"] / stats["dense_reference_params"]
)

checks = {
    "hidden_divisible_by_heads": (
        config["hidden_size"] % config["query_heads"] == 0
    ),
    "query_heads_divisible_by_kv": (
        config["query_heads"] % config["kv_heads"] == 0
    ),
    "head_dim_is_positive": stats["head_dim"] > 0,
    "ffn_is_wider": config["ffn_size"] > config["hidden_size"],
    "residual_std_is_smaller": residual_std < base_std,
    "moe_top_k_valid": 1 <= config["moe_top_k"] <= config["moe_experts"],
}

print("head_dim=", stats["head_dim"])
print("dense_reference_params_b=", round(stats["dense_reference_params"] / 1e9, 3))
print("gqa_attention_ratio=", round(stats["gqa_attention_ratio"], 4))
print("kv_cache_gib=", round(stats["kv_cache_gib"], 3))
print("mha_cache_gib=", round(stats["mha_cache_gib"], 3))
print("tokens_per_dense_reference_param=", round(tokens_per_dense_reference_param, 2))
print("train_flops_dense_reference=", f"{stats['train_flops_dense_reference']:.2e}")
print("base_init_std=", round(base_std, 6))
print("residual_init_std=", round(residual_std, 6))
print("rms_norm=", [round(value, 4) for value in rms_norm([1, 2, 3, 4])])
print("rope_pair_fixed_frequency=", [round(value, 4) for value in rope_pair_fixed_frequency(1.0, 0.0, 4, 0.25)])
print("one_moe_layer_total_expert_ffn_m=", round(moe_total / 1e6, 2))
print("one_moe_layer_active_expert_ffn_m=", round(moe_active / 1e6, 2))
print("checks=", checks)
assert all(checks.values())
bad_config = dict(config)
bad_config["kv_heads"] = 7
try:
    architecture_stats(bad_config)
except ValueError:
    pass
else:
    raise AssertionError("invalid GQA grouping must be rejected")
try:
    rms_norm([])
except ValueError:
    pass
else:
    raise AssertionError("empty RMSNorm input must be rejected")
print("architecture ledger: ok")
~~~

示例中的 `gqa_attention_ratio` 只比较 attention projection 的近似参数，不是全模型压缩率；`kv_cache_gib` 只统计 K/V 数组，不含运行时临时 buffer、权重、激活和框架开销。`dense_reference_params` 假设输入 embedding 与输出头 tied，只计一个 `Vd`，并近似给每层计两组 RMSNorm scale；它没有 MoE、router、shared expert、final norm 或 untied output head。`tokens_per_dense_reference_param` 和 `train_flops_dense_reference` 因而只属于这个 dense reference；单层 MoE 子账本不能被读成真实 MoE 总参数或训练 FLOPs。RMSNorm helper 只演示无 affine scale/bias 的归一化数值，并使用缩放计算避免有限但极大的输入平方溢出；RoPE helper 只旋转一个二维向量对、使用固定频率，不实现真实模型的频率表、head 布局、部分旋转或长上下文缩放。示例会在计算前拒绝不可整除的 GQA 分组、空 RMSNorm 输入和不完整配置，避免把形状或数值错误伪装成一张架构预算表。它的作用是让读者把配置变量转换成可检查的数量，再用真实模型配置、运行日志和评估验证。

## 4.15 架构故障的最小排查路径

### 4.15.1 shape 和配置错误

先检查 hidden size 是否被 head 数整除，query heads 是否被 K/V heads 整除，RoPE 作用维度是否匹配，词表 id 是否小于 embedding 行数，MoE top-k 和 expert 数是否合法。许多“训练不收敛”其实在小规模运行中就能发现。

### 4.15.2 初始化和数值错误

打印初始 activation RMS、gradient norm、attention logits、softmax entropy 和第一批 loss。若某层尺度突然放大，检查 norm、残差、初始化和低精度实现；若所有层都异常，检查学习率和输入尺度。

### 4.15.3 长上下文错误

固定短输入和长输入分别运行，比较显存、attention logits、位置分布和检索准确率。只检查模型能否接受长张量，不足以证明它能找到中间证据或完成跨段推理。

### 4.15.4 MoE 路由错误

记录每 expert token 数、overflow、router entropy、负载均衡损失、all-to-all 时间和 dropped token。总 loss 正常而某些 expert 长期空闲，仍然说明系统或训练目标存在问题。

### 4.15.5 checkpoint 兼容错误

加载已有 checkpoint 时比较 tokenizer hash、词表大小、config、RoPE、权重 dtype、参数名和 optimizer state。配置能够加载不等于语义兼容；必须用固定文本和小数据恢复实验验证。

## 4.17 章节练习：从纸面配置走到小规模验证

### 练习一：参数账本

给定 `d`、层数、query/KV heads、FFN、词表和是否 tied embedding，分别计算 attention、FFN、embedding 和总参数。再用框架导出的参数量对照，找出 bias、norm 或共享权重造成的差异。

### 练习二：GQA 缓存账本

固定层数、head dimension、上下文长度、batch 和 dtype，比较 MHA、GQA、MQA 的 KV cache。说明为什么 cache 降低不等于总显存按同样比例降低。

### 练习三：RoPE 长度实验

在固定模型和短训练上比较原始位置范围、位置缩放和继续训练。构造信息位于开头、中间和末尾的长文本，分别测输入可接受性、检索准确率和计算成本。

### 练习四：Pre-Norm 与初始化

构造不同深度的小型残差网络，比较 Pre-Norm、Post-Norm、不同残差初始化和 warmup。记录 activation RMS、gradient norm、loss 和收敛速度，说明为什么单个初始 loss 不能代表稳定性。

### 练习五：MoE 路由

实现一个 top-k toy router，改变 expert 数、top-k、容量系数和输入分布。报告每 expert token 数、overflow、负载均衡项和通信量，分析为什么总参数和 active 计算必须分开。

### 练习六：架构变更回归

把一个 MHA toy checkpoint 改成 GQA 或增加 special token，列出需要同步的 config、权重、tokenizer、训练数据和评估。设计加载、固定文本生成和小数据过拟合测试。

## 4.18 本章小结

架构设计把目标能力、数据、算力、显存、推理和稳定性转换成模型配置。decoder-only 提供统一的自回归接口；层数、宽度、词表、FFN 和上下文共同决定参数和计算；参数量必须和训练 token 及预算匹配。

RoPE 把位置信息放进 Q/K 几何，RMSNorm 和 Pre-Norm 影响尺度与梯度，SwiGLU 提供门控 FFN，GQA/MQA 在表达能力和 KV cache 之间取舍。长上下文不是一个 config 数字，MoE 也不能只看总参数；两者都需要训练分布、系统成本和目标评估支持。

初始化决定训练从什么数值尺度开始，残差、norm、attention logits、精度和学习率共同决定稳定性。最终的架构结论必须来自参数账本、目标数据、目标硬件、小规模验证和能力评估，而不是来自某个组件名称或论文参数量。
