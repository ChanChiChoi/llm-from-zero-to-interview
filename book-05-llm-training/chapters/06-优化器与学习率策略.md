# 第六章：优化器与学习率策略

## 从梯度到参数更新

优化器决定模型拿到一个 noisy gradient 之后，如何结合历史信息、参数尺度和正则项走下一步。它不只是一个配置字段：同样的模型、数据和学习率，换掉优化器后，收敛速度、显存占用、数值稳定性和最终泛化都可能改变。

很多人只记得：

```text
训练大模型一般用 AdamW。
```

但真实训练中，优化器选择会影响：

1. 收敛速度。
2. 训练稳定性。
3. 显存占用。
4. 通信开销。
5. batch size scaling。
6. loss spike 和 NaN 风险。
7. 最终模型泛化能力。

近几年除了 Adam、AdamW，也出现了 Lion、Adafactor、Sophia、Muon 等优化器或优化思路。尤其是 Muon 这类方法重新强调矩阵参数更新方向的几何结构，在一些大模型训练讨论中受到关注。

理解优化器不能停在“AdamW 是默认选项”。初学者需要先看清 SGD、Momentum、Adam 和 AdamW 如何逐步增加状态与自适应；工程师还要把 optimizer state 显存、参数分组、warmup、梯度裁剪、有效 token batch 和验证结果放在同一张实验记录里。Lion、Sophia、Muon 等较新的方法，则要区分论文中的实验结果、简化教学公式和当前项目是否已经验证。

### 优化器与学习率策略的资料边界

本章参考了 Adam、AdamW、Adafactor、Lion、Sophia、Muon 相关论文或公开说明，以及 PyTorch `AdamW` / `clip_grad_norm_`、Hugging Face Transformers warmup/cosine scheduler 和主流训练 recipe 资料。

本章聚焦训练工程中最常用的优化器和学习率策略：SGD、Momentum、Adam、AdamW、Adafactor、Lion、Sophia、Muon、参数分组、warmup、cosine decay、decoupled weight decay、gradient clipping 和 batch size scaling。它不展开每个优化器的完整收敛理论，也不把相对新的优化器写成无条件替代 AdamW 的结论；工程上仍应以 AdamW baseline、消融实验和稳定性指标为准。

## 1. 优化器在训练中解决什么问题

神经网络训练的目标是最小化 loss：

```math
\min_\theta L(\theta)
```

最简单的更新是梯度下降：

```math
\theta_{t+1}=\theta_t-\eta g_t
```

其中 `eta` 是学习率，`g_t` 是当前 mini-batch 梯度：

```math
g_t=\nabla_\theta L_t(\theta_t)
```

但大模型训练里，简单 SGD 往往不够。

原因是：

1. 参数规模巨大。
2. 不同参数梯度尺度差异很大。
3. 训练数据噪声大。
4. batch size 很大。
5. mixed precision 容易带来数值问题。
6. loss landscape 复杂。

优化器本质上是在回答：

```text
拿到当前梯度后，应该朝哪个方向走，走多大一步？
```

## 2. 优化器谱系总览

| 优化器 | 核心思想 | 优点 | 主要问题 | 常见场景 |
|---|---|---|---|---|
| SGD | 直接沿负梯度更新 | 简单、泛化好 | 收敛慢、调参敏感 | CV、小模型、研究基线 |
| Momentum SGD | 累积历史梯度方向 | 减少震荡、加速 | 仍需仔细调 lr | CNN、传统深度学习 |
| Adam | 一阶动量 + 二阶自适应 | 收敛快、鲁棒 | weight decay 耦合不理想 | NLP、Transformer |
| AdamW | Adam + decoupled weight decay | 大模型默认强基线 | optimizer state 显存大 | LLM 预训练、SFT |
| Adafactor | factored second moment | 显存低 | 调参和稳定性更复杂 | T5、大模型省显存训练 |
| Lion | sign-based momentum update | 状态少、可能更省 | 需要重新调 lr/wd | 部分视觉和语言训练实验 |
| Sophia | 利用 Hessian 近似 | 提高样本效率 | 实现和超参复杂 | 研究和特定训练场景 |
| Muon | 对矩阵更新做正交化/几何约束 | 改善矩阵参数更新方向 | 新方法，适用边界仍需验证 | 新一代大模型训练探索 |

面试中最常被问的是 AdamW，但如果能补充 Muon、Adafactor、Lion 等方法，会显得你关注当前训练进展。

## 3. SGD 与 Momentum

SGD 更新公式：

```math
\theta_t=\theta_{t-1}-\eta g_t
```

其中 `g_t` 是当前 mini-batch 梯度。

SGD 的问题是梯度噪声大，容易震荡。

Momentum 引入历史方向：

```math
v_t=\beta v_{t-1}+g_t
```

```math
\theta_t=\theta_{t-1}-\eta v_t
```

直觉是：

```text
如果连续很多步都朝同一个方向，就加速；如果方向来回变，就抵消震荡。
```

Momentum 是理解 Adam 的前置概念。

## 4. Adam

Adam 同时维护一阶动量和二阶动量。

```math
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t
```

```math
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
```

更新时用：

```math
\hat m_t=\frac{m_t}{1-\beta_1^t}
```

```math
\hat v_t=\frac{v_t}{1-\beta_2^t}
```

```math
\theta_t=
\theta_{t-1}
-\eta
\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
```

其中：

1. `m_t` 表示梯度方向的滑动平均。
2. `v_t` 表示梯度平方的滑动平均。
3. 分母让不同参数有自适应学习率。

Adam 的优点：

1. 收敛快。
2. 对学习率相对不那么敏感。
3. 适合 Transformer 这种梯度尺度差异大的模型。

Adam 的问题：

1. optimizer state 大，需要保存 `m` 和 `v`。
2. weight decay 和梯度更新耦合，正则效果不够理想。
3. 大规模训练中仍然需要仔细调 warmup、lr 和 clipping。

如果参数量是 `P`，每个 optimizer state 数值占 `b_s` 字节，Adam 的一阶和二阶状态仅粗略需要：

```math
M_{\mathrm{state}}\approx 2Pb_s
```

这还没有算参数本身、梯度、master weights、分片元数据和临时工作区。以 bf16 权重、fp32 `m/v` 为例，状态和训练副本的实际占用会依赖实现；因此“参数量乘以 2”只能作为状态量级，而不是完整训练显存。

## 5. AdamW：大模型训练默认强基线

AdamW 的核心是 decoupled weight decay。

普通 Adam 中，L2 正则会进入梯度项。

AdamW 把 weight decay 从梯度更新里解耦出来：

```math
u_t=\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
```

```math
\theta_t=
\theta_{t-1}
-\eta u_t
-\eta\lambda\theta_{t-1}
```

其中 `lambda` 是 weight decay 系数。和把 `lambda theta` 加进梯度不同，AdamW 的衰减项不经过 Adam 的二阶自适应分母。

直觉是：

```text
Adam 负责根据梯度找方向，weight decay 单独负责让参数不要无限变大。
```

为什么大模型常用 AdamW？

1. Transformer 上经验稳定。
2. 收敛速度快。
3. 和 warmup + cosine decay 配合成熟。
4. 工具链支持完善。
5. 训练 recipe 和经验很多。

常见超参起点：

```text
beta1 = 0.9
beta2 = 0.95 或 0.999
eps = 1e-8
weight_decay = 0.01 到 0.1
```

注意：不同模型规模、batch size、数据质量和训练阶段会改变最优超参。

## 6. Adafactor：省显存的 Adam 替代

AdamW 的显存开销很大。

对每个参数，要保存：

```text
parameter
gradient
first moment
second moment
```

如果是 mixed precision，还可能有 master weights。

Adafactor 的思路是对二阶矩估计做 factored approximation。

对于一个矩阵参数，不完整保存每个元素的二阶矩，而是保存行统计和列统计。

如果矩阵参数 `W` 的形状是 `r x c`，AdamW 的二阶矩需要存：

```math
S_{\mathrm{Adam}}=rc
```

Adafactor 的二阶统计近似只存行和列统计：

```math
S_{\mathrm{Adafactor}}\approx r+c
```

当 `r` 和 `c` 很大时，状态显存会显著下降。代价是近似带来额外 recipe 和稳定性要求。

优点：

1. 明显降低 optimizer state 显存。
2. 适合超大模型或显存紧张场景。
3. 曾在 T5 等模型训练中使用。

缺点：

1. 调参更复杂。
2. 稳定性依赖具体 recipe。
3. 不一定总能替代 AdamW。

面试表达：

```text
Adafactor 主要解决 Adam 二阶状态显存过大的问题，通过对矩阵二阶矩做分解近似来节省显存，但它的训练稳定性和超参选择需要更谨慎。
```

## 7. Lion：更少状态的符号更新

Lion 是一种使用 momentum 和 sign update 的优化器。

它不像 Adam 那样维护完整二阶矩。

直觉上：

```text
用动量估计方向，再用 sign 决定更新方向。
```

一个简化写法是：

```math
u_t=\beta_1m_{t-1}+(1-\beta_1)g_t
```

```math
\theta_t=\theta_{t-1}-\eta\,\mathrm{sign}(u_t)
```

```math
m_t=\beta_2m_{t-1}+(1-\beta_2)g_t
```

这里的重点是：Lion 不维护 Adam 的二阶矩 `v_t`，但 sign update 会改变学习率和 weight decay 的合适尺度，不能照搬 AdamW 超参。

优点：

1. optimizer state 更少。
2. 更新形式简单。
3. 在部分视觉和语言任务上有不错结果。

缺点：

1. 学习率和 weight decay 通常不能直接沿用 AdamW。
2. 对大模型预训练的通用性需要结合具体实验判断。
3. sign update 可能带来不同的稳定性特征。

面试中可以把 Lion 作为“AdamW 之外的轻量优化器探索”来讲，不要夸成无条件替代 AdamW。

## 8. Sophia：利用二阶信息的高效近似

Sophia 这类方法关注的是：Adam 主要用梯度的一阶、二阶统计，能不能用低成本的 Hessian 对角近似提供曲率信息，从而提高训练效率？

它试图用可承受的方式近似二阶信息。

可以用一个简化形式理解：

```math
\theta_t=
\theta_{t-1}
-\eta\,
\mathrm{clip}
\left(
\frac{m_t}{h_t+\epsilon},
\rho
\right)
```

其中 `h_t` 表示对角 Hessian 或其他曲率相关的估计，`rho` 是对预条件更新的裁剪阈值。真实 Sophia 还涉及曲率估计的更新频率、估计器和超参；上式只是帮助理解“用低成本二阶信息改变更新尺度”的教学抽象，不能当作某个实现的完整算法。

潜在优点：

1. 提高样本效率。
2. 更好适配 loss landscape 曲率。
3. 可能减少训练 steps。

挑战：

1. 实现复杂。
2. 二阶估计成本和噪声要控制。
3. 大规模 LLM recipe 不如 AdamW 成熟。

Sophia 原论文在 125M 到 1.5B 参数的 GPT 类语言模型实验中报告了相对 Adam 的步数、计算和墙钟时间收益，但这属于特定模型规模、数据和实现下的论文结果。它可以证明“轻量曲率估计值得研究”，不能直接推出在更大模型或当前训练栈中一定有相同加速。

## 9. Muon：矩阵参数更新的几何约束

Muon 是近年较受关注的新优化器思路之一。

它的核心动机是：神经网络里很多重要参数是矩阵，例如：

```text
attention projection matrix
FFN up/down/gate matrix
embedding projection
```

普通 AdamW 把矩阵参数看成很多独立元素分别做自适应更新。

Muon 更强调矩阵整体的几何结构，常见理解是对矩阵梯度或更新方向做正交化/规范化，让更新方向更接近“结构良好”的矩阵变换。

如果矩阵参数是 `W`，梯度是 `G`，可以把这类方法抽象成：

```math
\Delta W=\Phi(G)
```

```math
W_t=W_{t-1}-\eta\Delta W
```

其中 `Phi` 表示对矩阵更新方向做归一化、正交化或其他几何约束的变换。不同实现的 `Phi` 不完全相同，面试中不要把某一种实现说成全部 Muon 路线。

为了理解“正交化”这个词，可以把梯度矩阵写成奇异值分解 `G=U\Sigma V^\top`。它的 polar factor 是：

```math
\operatorname{polar}(G)=UV^\top
```

Muon 类实现通常不会每一步都精确做完整 SVD，而是用 Newton--Schulz 一类迭代近似这个方向，再结合动量和学习率更新矩阵。这个公式是几何直觉，不是所有 Muon 实现的逐行伪代码；实际使用还要规定哪些参数走 Muon、哪些参数走 AdamW，以及分布式环境如何同步矩阵更新。

可以用直觉理解：

```text
AdamW：每个参数元素单独自适应缩放。
Muon：把二维权重矩阵作为整体，约束或改善它的更新方向。
```

为什么这可能有用？

大模型中，矩阵乘法是主要计算。

如果矩阵更新方向病态，可能导致：

1. 某些方向更新过强。
2. 表示空间塌缩或过度拉伸。
3. 训练不稳定。
4. 有效 rank 或谱结构不理想。

Muon 类方法希望通过更好的矩阵更新几何，改善训练效率和稳定性。

### 9.1 Muon 和 AdamW 的关系

Muon 不一定要替代所有参数上的 AdamW。

实际讨论中常见做法是：

```text
对二维矩阵参数使用 Muon
对 embedding、bias、norm 参数等使用 AdamW 或其他规则
```

原因是 Muon 的核心优势针对矩阵结构。

对于一维参数，例如 LayerNorm/RMSNorm 的 scale，未必适合做同样的矩阵正交化。

### 9.2 Muon 的优势

潜在优势包括：

1. 对矩阵参数更新更有结构感。
2. 可能提高训练速度或最终效果。
3. 可能降低对部分 AdamW 超参的依赖。
4. 与大模型中大量矩阵乘法结构匹配。

### 9.3 Muon 的风险和边界

需要谨慎看待：

1. 它是相对新的训练优化方向。
2. 不同模型规模和任务上的稳定结论还需要更多验证。
3. 工具链成熟度不如 AdamW。
4. 可能需要重新调学习率、weight decay、warmup 和参数分组。
5. 分布式训练中要考虑额外计算和实现成本。

Muon 的公开技术报告《Muon is Scalable for LLM Training》进一步报告了加入 weight decay、调整更新尺度后，在 Moonlight 3B/16B MoE 训练中的实验结果；官方实现也明确把 hidden weight 与 embedding、head、bias、norm 等参数分开处理。这里的证据仍来自作者的特定 recipe 和代码版本，适合用来理解实现边界，不足以替代自己的 AdamW baseline、消融和长时间稳定性实验。

面试中可以这样说：

```text
AdamW 把每个参数元素独立做自适应更新，而 Muon 更关注矩阵参数作为整体的更新几何，常通过正交化或规范化改善矩阵更新方向。它适合讨论大模型中 attention/MLP 权重矩阵的优化效率，但目前仍属于较新的优化器路线，是否替代 AdamW 要看规模、任务和训练 recipe。
```

## 10. 参数分组策略

大模型训练通常不会对所有参数使用完全相同的优化规则。

常见参数分组：

```text
1. weight matrix：使用 AdamW/Muon，启用 weight decay。
2. bias：通常不使用 weight decay。
3. norm 参数：通常不使用 weight decay。
4. embedding：可单独设置 lr 或 weight decay。
5. LoRA 参数：微调时常设置更大学习率。
```

为什么 norm 和 bias 通常不 decay？

因为它们不是普通权重矩阵，过度衰减可能影响尺度控制和训练稳定性。

参数分组可以写成互不重叠的集合：

```math
\Theta=
\Theta_{\mathrm{matrix}}
\cup
\Theta_{\mathrm{norm}}
\cup
\Theta_{\mathrm{bias}}
\cup
\Theta_{\mathrm{embed}}
```

常见做法是：

```math
\lambda(\theta)=
\begin{cases}
\lambda_w,& \theta\in \Theta_{\mathrm{matrix}}\\
0,& \theta\in \Theta_{\mathrm{norm}}\cup \Theta_{\mathrm{bias}}
\end{cases}
```

也就是说，对矩阵权重做 weight decay，对 norm 和 bias 不做 decay。LoRA、embedding 或新增 token 可以再单独分组。

## 11. Learning Rate Warmup

大模型训练几乎都会使用 warmup。

原因是训练初期参数还不稳定，直接使用大学习率容易导致 loss spike 或 NaN。

warmup 做法：

```text
lr 从 0 或很小值逐步增加到 peak lr
```

线性 warmup 可以写成：

```math
\eta_t=\eta_{\mathrm{max}}\frac{t}{T_{\mathrm{warm}}}
```

其中 `T_warm` 是 warmup step 数，`eta_max` 是 peak learning rate。

这个表达式只适用于 `0\le t\le T_{\mathrm{warm}}`；完整的调度还要定义 warmup 结束后的部分，并明确 `t` 是 optimizer step、global update step 还是 micro step。大多数训练 recipe 按 optimizer update 推进 scheduler；如果把 micro step 误当成 scheduler step，实际 warmup 和衰减长度会随 accumulation 改变。

常见设置：

```text
warmup_steps = 总 steps 的 1% 到 5%
```

如果 warmup 太短：

```text
初期容易不稳定。
```

如果 warmup 太长：

```text
训练前期学习太慢，浪费计算。
```

## 12. Cosine Decay

warmup 后常用 cosine decay：

```text
lr 从 peak lr 平滑下降到 min lr
```

warmup 之后的 cosine decay 可以写成：

```math
\eta_t=
\eta_{\mathrm{min}}
+
\frac{1}{2}
(\eta_{\mathrm{max}}-\eta_{\mathrm{min}})
\left[
1+\cos\left(
\pi
\frac{t-T_{\mathrm{warm}}}{T_{\mathrm{total}}-T_{\mathrm{warm}}}
\right)
\right]
```

这个公式适用于 `T_warm < t\le T_{\mathrm{total}}` 的阶段。真实训练还要处理提前停止、恢复 checkpoint、重复训练周期和最后一个不完整窗口；恢复时 scheduler state 必须和 optimizer step 一起保存。

优点：

1. 下降平滑。
2. 后期有利于收敛。
3. 大模型 recipe 成熟。

常见组合：

```text
linear warmup + cosine decay
```

## 13. Weight Decay

weight decay 控制参数规模，帮助泛化和稳定训练。

大模型里要注意：

1. AdamW 中 weight decay 是 decoupled。
2. norm 和 bias 通常不 decay。
3. weight decay 过大可能欠拟合。
4. weight decay 过小可能参数范数变大，泛化变差。

对于 LoRA/SFT，weight decay 常常要重新调，不要照搬预训练设置。

## 14. Gradient Clipping

Gradient clipping 用于防止梯度爆炸。

常见做法是 global norm clipping：

```math
\|g\|_2=
\sqrt{\sum_i g_i^2}
```

```math
g'=
g\cdot
\min\left(1,\frac{c}{\|g\|_2+\epsilon}\right)
```

某些 recipe 会从 `1.0` 量级的 global norm 开始试验：

```text
clip_grad_norm = 1.0
```

但这不是固定答案。裁剪频率、未裁剪梯度范数的分布和 validation loss，比单独记住一个阈值更有信息。

如果经常触发 clipping，说明可能存在：

1. 学习率过大。
2. batch 数据异常。
3. loss scale 问题。
4. 模型初始化或数值精度问题。

## 15. Batch Size Scaling

batch size 和学习率强相关。

batch size 增大后，梯度噪声降低，可以适当增大学习率。

但大模型训练不是简单线性关系。

LLM 中更常用 token batch 口径：

```math
B_{\mathrm{tok}}=
B_{\mathrm{micro}}
\cdot
T_{\mathrm{seq}}
\cdot
A
\cdot
P_{\mathrm{dp}}
```

其中 `B_micro` 是每张卡每个 micro step 的样本数，`T_seq` 是序列长度，`A` 是 gradient accumulation steps，`P_dp` 是数据并行规模。

如果 batch token 数从 `B1` 变成 `B2`，线性缩放只是一种起点：

```math
\eta_2\approx \eta_1\frac{B_2}{B_1}
```

线性缩放来自保持每个 token 的平均更新量近似不变的直觉，但在有限训练预算、AdamW 自适应、长序列和梯度噪声变化下并不一定成立；平方根缩放、保持训练 token 数不变或直接做小规模 sweep 也可能更合适。大模型训练中通常还要结合 warmup、grad norm、loss spike、数据质量和 validation loss 做实际搜索。

需要关注：

1. global batch size。
2. gradient accumulation。
3. token batch size，而不是 sample 数。
4. sequence length 变化。
5. loss spike 风险。

对于 LLM，常说 batch size 时更应该说：

```text
每步训练多少 token
```

而不是只说多少条样本。

下面这个 demo 用标准库审计一个最小优化器配置。它同时演示：linear warmup + cosine decay、global norm clipping、AdamW 和耦合 L2 Adam 的差异、effective token batch、Adafactor 状态节省、Lion sign update、Sophia 裁剪更新和 Muon 风格的矩阵更新归一化。

```python
import math

base_lr = 0.1
min_lr_ratio = 0.1
warmup_steps = 3
total_steps = 10
weight_decay = 0.1
beta1 = 0.9
beta2 = 0.95
eps = 1e-8
clip_norm = 1.0


def grad(theta):
    return theta - 3.0


def loss(theta):
    return 0.5 * (theta - 3.0) ** 2


def lr_at(step):
    if step <= warmup_steps:
        return base_lr * step / warmup_steps
    progress = (step - warmup_steps) / max(total_steps - warmup_steps, 1)
    cosine = 0.5 * (1.0 + math.cos(math.pi * progress))
    return base_lr * (min_lr_ratio + (1.0 - min_lr_ratio) * cosine)


def clip_grad(g, max_norm):
    norm = abs(g)
    scale = min(1.0, max_norm / (norm + 1e-12))
    return g * scale, norm, scale


def adamw_step(theta, g, m, v, step, lr):
    m = beta1 * m + (1 - beta1) * g
    v = beta2 * v + (1 - beta2) * g * g
    m_hat = m / (1 - beta1**step)
    v_hat = v / (1 - beta2**step)
    adam_update = m_hat / (math.sqrt(v_hat) + eps)
    theta = theta - lr * adam_update - lr * weight_decay * theta
    return theta, m, v, adam_update


def coupled_adam_step(theta, g, m, v, step, lr):
    g = g + weight_decay * theta
    m = beta1 * m + (1 - beta1) * g
    v = beta2 * v + (1 - beta2) * g * g
    m_hat = m / (1 - beta1**step)
    v_hat = v / (1 - beta2**step)
    theta = theta - lr * m_hat / (math.sqrt(v_hat) + eps)
    return theta, m, v


theta = 8.0
m = 0.0
v = 0.0
trace = []
for step in range(1, 6):
    lr = lr_at(step)
    raw_grad = grad(theta)
    clipped_grad, raw_norm, clip_scale = clip_grad(raw_grad, clip_norm)
    theta, m, v, adam_update = adamw_step(theta, clipped_grad, m, v, step, lr)
    trace.append(
        {
            "step": step,
            "lr": round(lr, 5),
            "raw_grad": round(raw_grad, 5),
            "clip_scale": round(clip_scale, 5),
            "theta": round(theta, 5),
            "loss": round(loss(theta), 5),
        }
    )

same_theta = 8.0
aw_m = aw_v = ca_m = ca_v = 0.0
first_grad, _, _ = clip_grad(grad(same_theta), clip_norm)
adamw_theta, aw_m, aw_v, _ = adamw_step(same_theta, first_grad, aw_m, aw_v, 1, base_lr)
coupled_theta, ca_m, ca_v = coupled_adam_step(same_theta, first_grad, ca_m, ca_v, 1, base_lr)

schedule = [round(lr_at(step), 5) for step in range(1, total_steps + 1)]
num_params = 4096 * 11008
adafactor_second_moment = 4096 + 11008
adamw_state_values = 2 * num_params
state_ratio = adamw_state_values / adafactor_second_moment

micro_batch = 2
seq_len = 4096
accum_steps = 8
dp_size = 16
effective_tokens = micro_batch * seq_len * accum_steps * dp_size

lion_update = -base_lr * (1 if (beta1 * 0.0 + (1 - beta1) * 0.25) > 0 else -1)
sophia_update = -base_lr * max(min(0.25 / (0.8 + 1e-12), 0.2), -0.2)
muon_matrix = [[3.0, 0.0], [4.0, 0.0]]
muon_norm = math.sqrt(sum(x * x for row in muon_matrix for x in row))
muon_unit = [[round(x / muon_norm, 4) for x in row] for row in muon_matrix]

diagnostics = {
    "warmup_reaches_peak": schedule[2] == base_lr,
    "cosine_decays": schedule[-1] == round(base_lr * min_lr_ratio, 5),
    "clip_triggered": trace[0]["clip_scale"] < 1.0,
    "loss_decreased": trace[-1]["loss"] < trace[0]["loss"],
    "adamw_differs_from_coupled": round(adamw_theta, 6) != round(coupled_theta, 6),
    "adafactor_saves_state": state_ratio > 1000,
    "effective_tokens_ok": effective_tokens == 1_048_576,
}

print("schedule=", schedule)
print("trace=", trace)
print("adamw_theta_step1=", round(adamw_theta, 6))
print("coupled_adam_theta_step1=", round(coupled_theta, 6))
print("effective_tokens=", effective_tokens)
print("adamw_state_values=", adamw_state_values)
print("adafactor_state_values=", adafactor_second_moment)
print("state_ratio=", round(state_ratio, 1))
print("lion_update=", round(lion_update, 4))
print("sophia_clipped_update=", round(sophia_update, 4))
print("muon_unit_update=", muon_unit)
print("diagnostics=", diagnostics)
```

## 17. 训练不稳定时如何排查

如果出现 loss spike、NaN 或训练发散，可以按下面顺序排查。

### 17.1 学习率是否过大

现象：

```text
loss 突然升高
grad norm 爆炸
参数范数异常增大
```

处理：

```text
降低 peak lr
延长 warmup
增大 grad clipping
回滚 checkpoint
```

### 17.2 warmup 是否太短

训练初期 spike 常常和 warmup 太短有关。

处理：

```text
warmup_steps 增加 2 到 5 倍做对比实验
```

### 17.3 beta2 是否不合适

AdamW 的 `beta2` 控制二阶矩平滑。

`beta2` 太大，二阶统计响应慢。

`beta2` 太小，更新可能更噪。

大模型预训练中常见 `0.95` 或 `0.999`，需要结合 batch size 和训练稳定性调。

### 17.4 weight decay 是否过强

weight decay 过大可能导致欠拟合或能力变差。

尤其是 SFT、RLHF 和 LoRA 阶段，不要无脑沿用预训练 decay。

### 17.5 参数分组是否错误

常见错误：

```text
对 norm 参数使用 weight decay
对 frozen 参数传入 optimizer
LoRA 参数学习率过大
embedding 使用不合适 decay
```

### 17.6 新优化器是否没有重新调参

从 AdamW 换成 Muon、Lion、Sophia 时，不能照搬 AdamW 超参。

必须重新搜索：

```text
lr
weight_decay
warmup
grad_clip
参数分组
```

## 18. 面试高频问法

### 问法 1：Adam 和 AdamW 有什么区别？

可以这样答：

```text
Adam 使用一阶动量和二阶动量做自适应更新，但普通 L2 正则会和 Adam 的梯度归一化耦合。AdamW 把 weight decay 从梯度更新里解耦出来，先按 Adam 方向更新，再单独对参数做衰减，因此正则行为更清晰，也成为 Transformer 和 LLM 训练中的常用默认优化器。
```

### 问法 2：为什么大模型训练常用 AdamW？

可以这样答：

```text
因为 Transformer 参数多、梯度尺度差异大，AdamW 的自适应学习率和动量机制能提供较快且稳定的收敛。同时 decoupled weight decay 更适合控制参数范数。它和 warmup、cosine decay、gradient clipping 的训练 recipe 非常成熟，所以是大模型预训练和后训练的强基线。
```

### 问法 3：Muon 和 AdamW 有什么不同？

可以这样答：

```text
AdamW 基本把参数元素独立看待，维护一阶和二阶矩做自适应更新。Muon 更关注矩阵参数整体的更新几何，通常对矩阵梯度或更新方向做正交化或规范化，让 attention、MLP 这类二维权重矩阵的更新更有结构。它是比较新的优化器方向，潜力在于提升矩阵参数训练效率，但是否稳定优于 AdamW 需要具体规模和 recipe 验证。
```

### 问法 4：Adafactor 解决什么问题？

可以这样答：

```text
Adafactor 主要解决 Adam/AdamW optimizer state 显存过大的问题。它对矩阵参数的二阶矩估计做分解近似，只保存行列统计，从而减少显存开销。代价是训练稳定性和超参选择更复杂，不一定能无脑替代 AdamW。
```

### 问法 5：训练 loss spike 时如何从优化器角度排查？

可以这样答：

```text
我会先看学习率是否过大、warmup 是否太短、grad norm 是否爆炸、gradient clipping 是否生效。然后检查 AdamW 的 beta2、eps、weight decay 和参数分组，确认 norm/bias 是否错误 decay，LoRA 或新参数是否学习率过大。如果使用 Muon/Lion 等新优化器，还要确认没有照搬 AdamW 超参，并和 AdamW baseline 对比。
```

## 19. 资料边界与延伸阅读

本章把 AdamW 作为工程基线，把 Lion、Sophia 和 Muon 作为有明确动机但需要重新验证的路线。论文摘要、作者仓库和单次 benchmark 可以说明算法提出者报告了什么，却不能证明某个新优化器在所有模型规模、数据配比、并行方式和硬件上都更优。比较时至少要固定模型、token 预算、batch token、训练步数、精度、评估集和失败重跑规则。

可以优先阅读以下资料：

- [Adam: A Method for Stochastic Optimization](https://arxiv.org/abs/1412.6980)：Adam 的一阶/二阶矩和偏置修正。
- [Decoupled Weight Decay Regularization](https://arxiv.org/abs/1711.05101)：AdamW 与 L2 正则、weight decay 解耦的原始论文。
- [Adafactor: Adaptive Learning Rates with Sublinear Memory Cost](https://arxiv.org/abs/1804.04235)：分解二阶统计、更新裁剪和子线性状态显存。
- [Symbolic Discovery of Optimization Algorithms](https://arxiv.org/abs/2302.06675)：Lion 的发现、sign update、内存和超参边界。
- [Sophia: A Scalable Stochastic Second-order Optimizer for Language Model Pre-training](https://arxiv.org/abs/2305.14342)：轻量 Hessian 对角估计与裁剪更新。
- [Muon: An optimizer for hidden layers in neural networks](https://github.com/KellerJordan/Muon)：Muon 官方实现对 hidden weight、非矩阵参数和辅助 AdamW 的分组说明。
- [Muon is Scalable for LLM Training](https://arxiv.org/abs/2502.16982)：Muon 在 Moonlight MoE 训练中的公开技术报告。
- [PyTorch AdamW](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html)：AdamW 的官方实现接口和参数定义。
- [PyTorch clip_grad_norm_](https://docs.pytorch.org/docs/stable/generated/torch.nn.utils.clip_grad_norm_.html)：全局梯度范数裁剪接口。

这些资料能支持算法定义和公开实验边界，但不能替代本项目对 loss、grad norm、参数范数、optimizer state、tokens/sec、验证集和 checkpoint 恢复的连续记录。新优化器的“更快”必须说明是更少 steps、更少 FLOPs，还是更短墙钟时间，也要说明是否保持了相同模型质量和风险水平。

## 20. 本章小结

本章系统介绍了大模型训练中的优化器和学习率策略。

核心结论如下：

1. 优化器决定拿到梯度后如何更新参数。
2. SGD 简单但大模型训练中通常不如 Adam 系方法稳定高效。
3. Adam 使用一阶和二阶动量做自适应更新。
4. AdamW 通过 decoupled weight decay 成为 LLM 训练强基线。
5. Adafactor 主要解决 optimizer state 显存问题。
6. Lion 用更少状态和 sign update 探索轻量优化。
7. Sophia 代表利用二阶信息近似提高训练效率的方向。
8. Muon 关注矩阵参数整体更新几何，是当前值得关注的新优化器路线。
9. 新优化器不能无脑替换 AdamW，必须重新调 lr、weight decay、warmup 和参数分组。
10. warmup、cosine decay、gradient clipping、batch size scaling 和优化器必须一起看。
11. 训练不稳定时，优化器和学习率策略是最先排查的方向之一。
