# 第六章：优化器与学习率策略：从梯度到可验证的参数更新

## 6.0 训练中的“下一步”究竟由谁决定

上一章把一次训练循环拆成了数据、损失、反向传播、梯度累积和 optimizer.step()。本章继续追问最后一个动作：模型拿到梯度以后，究竟怎样把梯度变成参数变化？

最简单的答案是梯度下降：

~~~math
\theta_{t+1}
=
\theta_t-\eta_t g_t
~~~

其中：

- theta_t 是第 t 次 optimizer update 之前的参数；
- g_t 是当前有效 token batch 产生的梯度；
- eta_t 是第 t 次更新使用的学习率。

以下各节默认 t 是从 1 开始的整数，theta_t 和 g_t 是形状一致且元素有限的张量，eta_t >= 0。若梯度中已经出现 NaN 或 Inf，优化器公式不会把它“优化回正常值”；应先回到损失、混合精度和数据链路定位来源。

这个公式足以说明方向，却不足以描述现代大模型训练。真实更新还会涉及动量、梯度平方的统计、权重衰减、梯度裁剪、混合精度、参数分组和学习率调度器。优化器还会保存自己的历史状态，调度器也会保存当前进度。因此，一次更新更接近下面这条链：

~~~text
有效 token batch
  -> gradient
  -> clipping / unscale
  -> optimizer state update
  -> adaptive or geometric transform
  -> weight decay
  -> parameter update
  -> scheduler advance
  -> checkpoint and metrics
~~~

初学者可以把优化器理解成“根据当前梯度和历史经验决定走法的规则”。专家还要问得更具体：

1. g_t 是按有效 token 正确归一化的吗？
2. 梯度裁剪发生在 loss scaling 还未还原之前，还是之后？
3. optimizer 的 m、v、曲率估计或投影基是否保存并恢复？
4. weight decay 是经过自适应分母的 L2 项，还是与梯度解耦的参数衰减？
5. scheduler 是按 micro-step 还是 optimizer step 前进？
6. 比较两个优化器时，是否固定了 token 预算、模型、数据、精度和失败重试规则？

本章先建立 SGD、Momentum、Adam 和 AdamW 的主线，再讨论 Adafactor、Lion、Sophia、Muon 和 GaLore 等路线。后面的新方法不是“新闻列表”：每个方法都要说明它改变了哪一部分状态或更新几何，节省了什么，增加了什么代价，公开证据覆盖到哪里。

## 6.1 先建立参数、梯度和状态账本

### 6.1.1 梯度是一个带噪声的估计

训练数据通常来自一个很大的数据分布 D。理想目标是最小化总体风险：

~~~math
\mathcal{L}(\theta)
=
\mathbb{E}_{x\sim D}
[
\ell(\theta;x)
]
~~~

一个 mini-batch 只能给出这个期望的估计：

~~~math
g_t
=
\frac{1}{|B_t|}
\sum_{x\in B_t}
\nabla_\theta \ell(\theta_t;x)
~~~

在语言模型中，|B_t| 最好理解为有效 label token 数，而不是样本条数。若一个 batch 有两个样本，一个样本含 1000 个有效 token，另一个样本只有 10 个有效 token，简单平均两个样本的 loss 与按 1010 个 token 汇总并不相同。上一章已经讨论过这个分母；本章所有关于 batch、梯度和学习率的比较都应继承同一个口径。

这里隐含 |B_t|>0。全是 padding、所有标签都被 ignore，或过滤后没有有效 token 的 batch，不存在这个平均梯度；把分母硬改成 1 虽能避免除零，却会把“没有训练信号”伪装成“梯度为零”，让数据问题进入训练统计而不易察觉。

梯度噪声并不只来自样本。dropout、动态 padding、数据顺序、混合精度舍入、分布式归约顺序和自定义 kernel 都可能使两次运行的 g_t 不完全相同。优化器的历史状态会把这些局部梯度整合成更长时间尺度的更新。

### 6.1.2 三种容易混淆的步数

训练系统至少有三种步数：

| 名称 | 含义 | 是否通常推进 scheduler |
| --- | --- | --- |
| micro-step | 一次 forward/backward | 通常不推进 |
| optimizer step | 一次参数更新 | 通常推进 |
| token step | 消耗了多少有效 token | 用于吞吐和预算 |

假设每次有 8 个 micro-batch 才做一次参数更新，那么 global_step=100 通常意味着已经完成约 800 次 forward/backward，而不是 100 次。若 scheduler 错把每个 micro-step 当作一个更新，warmup 和 decay 会比配置短 8 倍。

### 6.1.3 参数之外还保存什么

令参数量为 P。一个 Adam 类优化器通常至少保存与参数同形状的一阶状态和二阶状态：

~~~math
M_{\mathrm{state}}
\approx
P(b_m+b_v)
~~~

b_m、b_v 是每个状态元素的字节数。若两个状态都使用 FP32，粗略就是 8P 字节。完整训练显存还要加上参数副本、梯度、可能的 FP32 master weights、激活、通信缓冲区和 allocator 碎片。这个公式是账本的起点，不是显存测量的替代品。

可恢复训练至少要记录：

~~~text
model weights
optimizer states
scheduler state
mixed-precision scaler state
random states
data cursor
global optimizer step
parameter-group configuration
model/tokenizer/config version
~~~

如果只保存模型权重，当然可以加载并推理；但重新创建一个“看起来相同”的 optimizer 并不等于从原来的训练轨迹继续。动量、二阶矩、学习率阶段和数据位置一旦改变，下一次更新就已经不是同一个实验。

## 6.2 SGD：把梯度直接变成位移

### 6.2.1 基本更新

随机梯度下降的更新是：

~~~math
\theta_{t+1}
=
\theta_t-\eta_t g_t
~~~

学习率 eta_t 决定步长，梯度方向决定位移方向。若把 loss 想象成一张山谷地图，梯度指向局部上坡方向，负梯度就是下降方向。

SGD 的优点是状态少、规则透明。除了参数和梯度，它不需要保存一阶或二阶历史。它的缺点也很直观：如果 loss 在不同方向的曲率差异很大，固定的标量学习率很难同时适合所有方向。

### 6.2.2 一个二维山谷

考虑一个二次函数：

~~~math
L(x,y)
=
\frac{1}{2}(a x^2+b y^2)
~~~

当 a 远大于 b 时，x 方向很陡，y 方向很平。若学习率足以让 y 方向前进，x 方向可能来回震荡；若为了 x 方向降低学习率，y 方向又会收敛得很慢。这种不同方向的尺度差异是病态性或条件数问题的直观来源。

这个二次例子要求 a>0、b>0 才表示有唯一最低点的碗形曲面；它只用于建立直觉，不是对深层网络非凸损失的全局描述。

在大模型中，参数矩阵不同层、不同通道和不同参数类型的梯度尺度也可能差异很大。SGD 并非不能训练神经网络，而是它通常需要更仔细的学习率、batch 和正则化配合，且在 Transformer 预训练中不如 Adam 系方法常见。

### 6.2.3 Momentum：积累方向而不是只看当前一步

Momentum 维护速度向量 v_t：

~~~math
v_t
=
\beta v_{t-1}
+
(1-\beta)g_t
~~~

~~~math
\theta_{t+1}
=
\theta_t-\eta_t v_t
~~~

beta 越大，历史方向的影响越持久。连续多次朝同一方向的梯度会叠加，反复改变方向的噪声则会相互抵消。

通常取 0<=beta<1：beta=0 退化为只使用当前梯度，beta>=1 则不再是收敛的指数移动平均。学习率仍须结合目标的局部曲率和梯度噪声选择，动量并没有消除步长约束。

有些实现把公式写成 v_t=beta v_{t-1}+g_t，再通过其他方式调整学习率。两种写法不是看到变量名就能直接比较的，必须连同 eta 的定义一起看。教材中采用带 (1-beta) 的指数移动平均形式，便于和 Adam 的一阶矩统一。

## 6.3 Adam：为每个参数估计自己的步长

### 6.3.1 一阶矩和二阶矩

Adam 同时维护梯度的一阶矩和平方梯度的二阶矩：

~~~math
m_t
=
\beta_1m_{t-1}
+
(1-\beta_1)g_t
~~~

~~~math
v_t
=
\beta_2v_{t-1}
+
(1-\beta_2)g_t^2
~~~

这里的平方是逐元素平方。m_t 保留方向信息，v_t 估计每个参数梯度幅度。为了纠正初始化时状态从零开始造成的偏差，Adam 使用：

~~~math
\hat m_t
=
\frac{m_t}{1-\beta_1^t},
\qquad
\hat v_t
=
\frac{v_t}{1-\beta_2^t}
~~~

参数更新为：

~~~math
\theta_{t+1}
=
\theta_t
-
\eta_t
\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
~~~

如果某个参数过去的梯度平方平均较大，分母会把它的更新缩小；如果梯度幅度较小，更新相对会变大。这就是自适应学习率的来源。

这组公式的常用有效域是 0<=beta_1,beta_2<1、epsilon>0、t>=1。这样 1-beta_i^t 为正，偏置修正有定义；epsilon 只处理数值上的小分母，不能替代对非有限梯度和损失溢出的检查。

### 6.3.2 为什么必须做偏置修正

假设 m_0=0，在训练开始的前几步，m_t 仍然明显小于真实梯度均值。若 beta1=0.9，第一步的一阶矩只有当前梯度的 0.1 倍。1-beta1^t 就是对这种从零开始的初始偏差进行校正。

二阶矩同理。忽略偏置修正会让早期更新过小，尤其在 warmup 本来就很短的实验中，可能把调度器变化误判为优化器差异。

### 6.3.3 epsilon 不是装饰参数

epsilon 防止分母为零，也影响小二阶矩区域的更新尺度。不同实现可能把它放在平方根内部或外部，数学上并不完全等价：

~~~math
\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
\quad\text{和}\quad
\frac{\hat m_t}{\sqrt{\hat v_t+\epsilon}}
~~~

当 v 很大时差异可能不明显，当 v 很小或低精度训练时差异会被放大。复现实验时要记录框架、优化器版本和 eps 的位置，而不能只记录 AdamW 四个字。

### 6.3.4 Adam 的代价

Adam 需要保存 m 和 v，因此状态量级为 2P 个元素。对于数十亿参数，状态往往比权重本身更快成为显存瓶颈。分片、8-bit 状态、CPU offload 和低秩投影都在不同层面处理这个问题，但它们不是同一种方法：

- 分片改变状态由哪个设备保存；
- 低比特状态改变每个状态元素的表示；
- 低秩投影改变状态所在的子空间；
- Adafactor 改变二阶统计的存储结构。

混淆这些层次，会导致优化器省显存的描述不准确。

## 6.4 AdamW：把权重衰减从自适应梯度中分离

### 6.4.1 L2 正则与 weight decay 的差别

在普通 SGD 中，把 L2 正则加到目标函数：

~~~math
L_{\mathrm{reg}}(\theta)
=
L(\theta)+\frac{\lambda}{2}\lVert\theta\rVert_2^2
~~~

得到的梯度是：

~~~math
\nabla L_{\mathrm{reg}}(\theta)
=
\nabla L(\theta)+\lambda\theta
~~~

对 SGD 来说，把 lambda theta 加进梯度，和每一步额外做参数衰减具有直接关系。但在 Adam 中，这个正则项也会进入一阶矩和二阶矩，随后被自适应分母重新缩放。参数的衰减强度因坐标的历史梯度而改变，这不再是简单的统一 weight decay。

### 6.4.2 Decoupled weight decay

AdamW 将梯度自适应更新记为：

~~~math
u_t
=
\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
~~~

然后把衰减独立施加到参数：

~~~math
\theta_{t+1}
=
(1-\eta_t\lambda)\theta_t
-
\eta_t u_t
~~~

lambda 不进入 m_t 或 v_t。因此 eta 变化时，每一步衰减量也会变化；weight decay 仍然与学习率的步长尺度相乘，但不再经过 Adam 的坐标自适应。

若把它解释为“收缩”而非仅仅一条代数更新，通常还要求 lambda>=0 且 0<=eta_t lambda<1；后一条件使乘子 1-eta_t lambda 保持在 0 到 1 之间。超出这一范围会翻转或放大参数，不能再称为常规 weight decay。

从实现角度看，也可能写成：

~~~text
theta = theta - lr * weight_decay * theta
theta = theta - lr * adaptive_update
~~~

只要二者都使用更新前的 theta 并遵守同一数值语义，顺序差异通常只是实现细节；但自定义 optimizer 时应明确检查，不能凭名称推测。

### 6.4.3 AdamW 为什么成为强基线

AdamW 的优势不是某个单独公式，而是一套成熟组合：

1. 对不同参数尺度进行自适应更新。
2. 使用动量减少局部噪声。
3. weight decay 的含义相对清楚。
4. 与 warmup、cosine decay、gradient clipping 配合广泛。
5. PyTorch、Transformers、分布式训练框架和 checkpoint 工具支持充分。

这解释了为什么新的优化器通常应该先和 AdamW 做公平比较。强基线不是永远最好，而是为新方法提供稳定且可复现的参照系。

### 6.4.4 Adam 与 AdamW 的最小反例

设参数 theta=8，梯度 g=1，beta1=0.9，beta2=0.95，第一步偏置修正后自适应更新接近 1。若 lr=0.1、weight_decay=0.1：

- AdamW 的衰减项约为 0.08，自适应项约为 0.1；
- 把 lambda theta 加到梯度以后，L2 项会与当前梯度一起进入矩估计，结果不是简单的 0.08+0.1。

一个小 toy 例子就能证明二者不是同一个操作。这个反例比背诵 AdamW 是 decoupled 更有用，因为它把差别落到一个参数的一次更新上。

## 6.5 优化器状态的显存、精度和分布方式

### 6.5.1 一个粗略的训练显存公式

设：

- b_w 是权重每元素字节数；
- b_g 是梯度每元素字节数；
- b_m、b_v 是一阶和二阶状态字节数；
- b_master 是可选 master weight 字节数。

忽略激活和临时缓冲区时：

~~~math
M_{\mathrm{persistent}}
\approx
P
(b_w+b_g+b_m+b_v+b_{\mathrm{master}})
~~~

例如，权重和梯度用 BF16，m/v 用 FP32，另存 FP32 master weight 时，粗略账本是：

~~~text
weight:        2P bytes
gradient:      2P bytes
first moment:  4P bytes
second moment: 4P bytes
master weight: 4P bytes
total:        16P bytes
~~~

实际框架可能把梯度保留在 FP16/BF16，也可能在 optimizer 内部维护 FP32 参数；分片和 fused kernel 还会改变峰值。账本的价值是先发现量级错误，再用 profiler 验证峰值。

### 6.5.2 状态放在哪里

有四种常见手段：

| 手段 | 改变的对象 | 典型代价 |
| --- | --- | --- |
| data/model sharding | 状态的设备归属 | 通信与实现复杂度 |
| CPU/NVMe offload | 状态的存储介质 | 带宽与延迟 |
| 8-bit optimizer state | 状态的精度 | 量化误差与校准 |
| factored/low-rank state | 状态的结构或子空间 | 近似误差与额外逻辑 |

少用显存必须同时说明是降低了总字节数、降低了单卡峰值，还是把状态移动到了别处。否则一个 offload 方案可能被错误宣传成优化器本身更省状态。

### 6.5.3 状态精度也会改变轨迹

如果 m/v 从 FP32 换成低比特表示，内存下降并不意味着计算完全等价。量化误差会进入下一步的自适应分母和动量，长时间积累后可能影响 loss、梯度范数和最终能力。

因此，比较状态精度时至少记录：

~~~text
state dtype
quantization scale or block size
dequantization location
overflow / saturation count
optimizer step time
validation loss and task metrics
~~~

## 6.6 Adafactor：用分解统计降低二阶状态

### 6.6.1 从逐元素二阶矩到行列统计

对于形状为 r x c 的矩阵参数 W，Adam 的二阶状态需要保存 rc 个元素。Adafactor 对二阶矩使用行列统计的近似。

令梯度为 G_t，逐元素平方为 G_t^2。可以维护：

~~~math
r_t
=
\beta_2 r_{t-1}
+
(1-\beta_2)
\operatorname{rowmean}(G_t^2)
~~~

~~~math
c_t
=
\beta_2 c_{t-1}
+
(1-\beta_2)
\operatorname{colmean}(G_t^2)
~~~

再用行列统计重构近似二阶矩：

~~~math
\tilde V_{t,ij}
\approx
\frac{r_{t,i}c_{t,j}}
{\operatorname{mean}(r_t)+\epsilon}
~~~

不同实现可能在均值、缩放和裁剪位置上有差异。关键思想是把 rc 个状态元素换成大约 r+c 个统计元素：

~~~math
S_{\mathrm{Adam}}
=
rc,
\qquad
S_{\mathrm{factored}}
\approx
r+c
~~~

当矩阵两边都很大时，节省非常明显；对向量、标量或很小的张量，则未必值得采用分解表示。

上式假设 r,c 都是正整数，行列统计本身没有 NaN/Inf，且 mean(r_t)+epsilon 为正。实际实现会为向量参数走不同分支；不能把空张量或退化形状静默塞进矩阵分解公式。

### 6.6.2 原始 recipe 的其他部分

Adafactor 不只是把 Adam 的 v 换成行列统计。原始论文还讨论了相对 step size、参数尺度、更新裁剪和可选的一阶动量。某个框架中的 Adafactor 如果开启了 relative step 或 scale parameter，不应直接和固定 learning rate 的 AdamW 进行不加说明的比较。

初学者可以先把它理解为降低二阶状态显存的近似优化器。工程师需要进一步记录：

1. 是否使用 factored 二阶状态。
2. 是否使用 relative step。
3. 是否使用 warmup 初始化。
4. 是否保存额外的一阶状态。
5. 向量参数走哪条分支。
6. 与 AdamW 比较时是否固定 token 预算和评估频率。

### 6.6.3 它适合解决什么问题

Adafactor 的主要收益是显存，不是自动获得更高质量。它适合：

- optimizer state 成为单卡瓶颈；
- 矩阵参数占比高；
- 可以接受近似二阶统计；
- 训练框架已经提供稳定实现。

若训练主要受激活显存、通信或数据加载限制，换 Adafactor 可能不会改善端到端吞吐。状态节省必须放回完整资源账本中判断。

## 6.7 Lion：只保留动量、用符号决定方向

### 6.7.1 更新结构

Lion 由符号动量更新得到。用 m_t 表示保存的动量，一种常见写法是：

~~~math
c_t
=
\beta_1m_{t-1}
+
(1-\beta_1)g_t
~~~

~~~math
\theta_{t+1}
=
\theta_t
-
\eta_t
\left[
\operatorname{sign}(c_t)
+
\lambda\theta_t
\right]
~~~

~~~math
m_t
=
\beta_2m_{t-1}
+
(1-\beta_2)g_t
~~~

这里 c_t 是决定当前方向的中间量，m_t 是下一步使用的动量状态。不同代码可能把 weight decay 的位置或系数写法略作调整，阅读实现时必须看完整更新。

与 Adam 相比，Lion 不保存逐元素二阶矩，因此持久状态少一个 P 量级。代价是每个坐标的更新方向被压成 +1 或 -1，更新幅度的控制更多落在学习率和参数分组上。

### 6.7.2 为什么不能照搬 AdamW 学习率

Adam 的更新通常会除以平方根二阶矩，坐标间幅度经过自适应缩放；Lion 的 sign 更新让每个坐标的基础幅度近似相同。因此同一个 lr 不代表同一个参数位移。

Lion 论文报告了需要更小学习率、通常更大 weight decay 的经验趋势，并报告了在多个视觉和语言任务上的实验结果；这属于论文实验条件下的观察。换用 Lion 时，应重新搜索：

~~~text
peak learning rate
weight decay
beta1 and beta2
warmup length
gradient clipping
parameter groups
~~~

### 6.7.3 适用边界

Lion 的状态节省在大模型中有吸引力，但它不自动解决：

- 激活显存；
- 通信瓶颈；
- 数据质量问题；
- 学习率单位错位；
- checkpoint 恢复；
- 某个任务的泛化差异。

状态更少应当与 tokens/sec、峰值显存、达到同一验证指标所需 token 数和最终任务指标一起报告。

## 6.8 Sophia：让轻量曲率信息参与更新

### 6.8.1 为什么想用二阶信息

一阶梯度只告诉我们当前斜率。若某个方向的曲率很大，沿该方向走得太远容易振荡；若曲率很小，步子又可能太保守。完整 Hessian 是：

~~~math
H(\theta)
=
\nabla_\theta^2 L(\theta)
~~~

但完整 Hessian 的存储和计算都不可接受。Sophia 的思路是用低成本的对角 Hessian 估计作为预条件器，并用裁剪控制非凸训练中的极端更新。

### 6.8.2 教学形式

用 h_t 表示对角曲率估计，先更新一阶动量：

~~~math
m_t
=
\beta_1m_{t-1}
+
(1-\beta_1)g_t
~~~

再构造逐元素更新：

~~~math
u_t
=
\operatorname{clip}
\left(
\frac{m_t}{h_t+\epsilon},
-\rho,
\rho
\right)
~~~

最后：

~~~math
\theta_{t+1}
=
\theta_t-\eta_t u_t
~~~

clip(z,-rho,rho) 把每个坐标限制在 [-rho,rho]。曲率估计不必每一步都刷新，论文讨论了按间隔估计以降低平均成本的做法。

上式是理解机制的教学抽象，不是把所有实现细节压缩掉之后仍可直接替换生产 optimizer 的代码。真实实现还要规定 Hessian 估计器、刷新频率、动量、weight decay、混合精度和分布式同步。

为使这个抽象有定义，可把 h_t 看作逐元素非负的曲率尺度，取 epsilon>0、rho>0、0<=beta_1<1；若估计器给出负值、NaN 或过期的曲率，应该先按具体算法的规则修正或拒绝该状态，而不是直接除以它。

### 6.8.3 证据应如何表述

Sophia 原论文在 GPT 类语言模型的特定规模和训练 recipe 上报告了相对于 Adam 的步数、计算量和墙钟时间收益。它支持轻量曲率估计值得研究这个判断，不支持任何 LLM 都会获得同样倍数加速这个判断。

要在项目中验证 Sophia，至少需要：

1. 同一个模型和 tokenizer。
2. 同一个训练 token 预算。
3. 同一精度和并行配置。
4. 预先固定的验证集与评估频率。
5. 记录 Hessian 估计额外耗时。
6. 记录达到同一质量所需的 steps、tokens、FLOPs 和墙钟时间。

## 6.9 Muon：把矩阵参数当作矩阵来更新

### 6.9.1 元素视角与矩阵视角

AdamW 通常把矩阵 W 的每一个元素视作一个坐标，分别维护动量和二阶统计。Muon 类路线的出发点不同：隐藏层的二维权重本身代表一个线性变换，更新方向可能需要考虑矩阵整体的谱结构。

设矩阵梯度或动量矩阵为 G。它的奇异值分解为：

~~~math
G
=
U\Sigma V^\top
~~~

其 polar factor 可以写为：

~~~math
\operatorname{polar}(G)
=
UV^\top
~~~

这里把 G 视为非零的二维矩阵；对秩亏矩阵，SVD 中零奇异值对应子空间的选取会影响具体的正交扩展，零矩阵则没有唯一的方向。这个因子保留左右奇异向量的方向结构，同时去掉奇异值的尺度差异。Muon 的公开实现路线通常用 Newton-Schulz 一类迭代近似这类正交化方向，而不在每一步做完整 SVD。

### 6.9.2 为什么通常需要参数分组

矩阵正交化适合二维 hidden weight，并不天然适合：

- LayerNorm 或 RMSNorm 的一维 scale；
- bias；
- embedding；
- 输出 head；
- 标量或小向量参数。

因此一种常见结构是：

~~~text
hidden matrix weights -> Muon-like update
norm / bias / embedding / head -> AdamW or a dedicated rule
~~~

这不是所有实现的唯一方案，但它解释了为什么不能只把 optimizer 名称改成 Muon 就结束。参数筛选、矩阵方向约定、学习率缩放、weight decay 和分布式同步都是算法的一部分。

### 6.9.3 公开结果的边界

Muon 的作者实现和后续技术报告展示了在特定模型、MoE 配置和训练 recipe 中的结果。这样的资料能够帮助读者理解：

1. 哪些参数进入 Muon；
2. 哪些参数仍使用 AdamW；
3. 正交化如何近似；
4. 更新尺度如何重新校准；
5. weight decay 如何处理。

但某个报告中的 tokens/sec 或最终 loss 更好不能直接外推到所有模型。Muon 还可能增加矩阵操作和实现复杂度，端到端收益必须包含这部分成本。

## 6.10 GaLore：降低状态维度，而不是冻结参数

### 6.10.1 它解决的不同问题

LoRA 通过增加低秩可训练矩阵、冻结原始权重来减少可训练参数。GaLore 的目标不同：它允许全参数学习，但把梯度和 optimizer state 投影到低秩子空间，以降低状态内存。

设矩阵梯度为 G_t，右侧投影基为 P_t，其中：

~~~math
P_t\in\mathbb{R}^{n\times r},
\qquad
r\ll n
~~~

为了让这一投影有明确几何含义，还应有 P_t^\top P_t=I_r，且 1<=r<=\min(m,n)，其中 G_t\in\mathbb{R}^{m\times n}。这些条件确保 G_tP_t 的形状是 m x r，并且低秩坐标不会重复计量同一个方向。

一种抽象化的投影流程是：

~~~math
\tilde G_t
=
G_tP_t
~~~

在低秩坐标中更新动量或二阶状态，再把更新投影回原矩阵空间：

~~~math
\widehat G_t
=
\tilde G_tP_t^\top
~~~

投影基可以随训练刷新。上式用于解释维度和状态位置，具体实现还要处理矩阵方向、基更新、低秩状态的 optimizer 规则和不同形状参数。

### 6.10.2 GaLore、LoRA 和 Adafactor 的区别

| 方法 | 主要改变 | 原参数是否全量更新 | 主要节省 |
| --- | --- | --- | --- |
| LoRA | 参数化方式 | 通常不更新原权重 | 可训练参数和状态 |
| Adafactor | 二阶状态结构 | 是 | 二阶状态 |
| GaLore | 梯度/state 所在子空间 | 是 | optimizer state |
| 8-bit optimizer | 状态数值表示 | 是 | 每个状态元素字节数 |

它们可以组合，但组合后的内存和质量不能由各自宣传数字简单相加。

### 6.10.3 论文数字应该绑定条件

GaLore 论文报告了在特定 LLaMA 规模、C4 数据、token 数和硬件条件下的状态与训练内存下降，并展示了全参数训练的可行性。正文引用这些数字时必须保留模型、数据和精度条件；它们不是所有模型都能在某种消费级显卡上训练的承诺。

验证 GaLore 时还要测：

- 投影基刷新开销；
- rank 对 loss 和能力的影响；
- 单卡峰值显存与总集群显存；
- 与 LoRA、Adafactor、AdamW 的公平 baseline；
- 恢复 checkpoint 后投影基是否连续。

## 6.11 参数分组：不是每个张量都应使用同一规则

### 6.11.1 常见分组

大模型训练通常把参数划分为多个 optimizer group：

~~~math
\Theta
=
\Theta_{\mathrm{matrix}}
\bigsqcup
\Theta_{\mathrm{norm}}
\bigsqcup
\Theta_{\mathrm{bias}}
\bigsqcup
\Theta_{\mathrm{embed}}
\bigsqcup
\Theta_{\mathrm{adapter}}
~~~

这里的 \bigsqcup 表示对同一轮更新而言，每个可训练 Parameter 对象恰好归入一个组；共享 embedding/head 是同一个对象，不是两个应分别衰减的参数。

常见起点是：

| 参数类型 | 常见处理 | 原因 |
| --- | --- | --- |
| attention/MLP 矩阵 | AdamW 或 Muon，使用 decay | 主体线性变换 |
| norm scale | 不 decay 或单独 decay | 控制激活尺度 |
| bias | 通常不 decay | 维度小且语义不同 |
| embedding | 单独观察或单独学习率 | 词表和表示尺度特殊 |
| output head | 视是否 tied、任务和规模决定 | 可能与 embedding 共享 |
| LoRA A/B | 单独学习率和 decay | 参数尺度与全参不同 |

通常不 decay 是 recipe 经验，不是数学定律。若一个项目对 norm 施加 decay，也应通过消融和参数范数曲线说明影响，而不是把经验规则当作绝对约束。

### 6.11.2 参数分组的实现陷阱

一个参数可能因为别名、权重共享或模块包装而被重复加入 optimizer。应检查：

1. 每个 Parameter 对象只出现一次。
2. frozen 参数不进入可更新 group。
3. group 的 lr、weight_decay、betas 和 eps 与配置一致。
4. embedding/head 权重共享时没有重复衰减。
5. checkpoint 恢复后 group 顺序和超参一致。

参数分组错误通常不会让程序立刻崩溃，却会让实验之间不可比。日志应记录每组参数数量、元素量、学习率、decay 和梯度范数。

## 6.12 Warmup：让训练从小步开始

### 6.12.1 线性 warmup

训练初期，模型参数、动量和二阶统计都处于初始化阶段。直接使用 peak learning rate 可能造成 loss spike。线性 warmup 在 0 <= t <= T_w 内使用：

~~~math
\eta_t
=
\eta_{\max}
\frac{t}{T_w}
~~~

t 必须明确是 optimizer step。若第一个更新使用 t=1，学习率为 eta_max/T_w；若实现从 t=0 记录日志，打印出来的首项可能是 0，但未必真的执行了 0 学习率的更新。

公式中的除法要求 T_w>0。更完整的调度定义是：T 是正的总 optimizer steps，0<=T_w<T；若 T_w=0，跳过 warmup，第一步直接进入后续阶段。这样“没有 warmup”是一个明确分支，而不是把分母偷偷替换成 1。

### 6.12.2 warmup 的长度不是固定比例

1% 到 5% 可以作为试验起点，但不是普适值。合适长度会受以下因素影响：

- 模型规模和初始化；
- peak learning rate；
- global token batch；
- 数据质量和序列长度；
- optimizer 的状态初始化；
- 从 checkpoint 继续训练还是重新开始；
- 预训练、持续训练还是 SFT。

warmup 太短可能表现为前期梯度范数和 loss 突增；太长则可能把大量计算花在过小的更新上。应同时画学习率、loss、grad norm、参数范数和 clipping ratio。

### 6.12.3 恢复训练时的 warmup

如果 checkpoint 在 warmup 中间保存，恢复时 scheduler 必须从原来的 t 继续。把恢复训练错误地当作新 run，再次从 0 warmup，会产生一条不同的学习率轨迹；如果直接跳到 peak lr，也可能制造新的 spike。

## 6.13 Cosine、线性和其他衰减策略

### 6.13.1 Warmup 后 cosine decay

warmup 结束后，令总 optimizer steps 为 T，可以使用：

~~~math
\eta_t
=
\eta_{\min}
+
\frac{1}{2}
(\eta_{\max}-\eta_{\min})
\left[
1+
\cos
\left(
\pi
\frac{t-T_w}{T-T_w}
\right)
\right]
~~~

该式适用于 T_w < t <= T。在 t=T_w 附近接近 peak lr，在 t=T 接近 eta_min。

它要求 T_w<T，以及 0<=eta_min<=eta_max；若训练超过 T，必须由实现明确选择固定在 eta_min、延长稳定段，还是重新定义一条新的曲线，不能让三角函数在预算外继续摆动。

cosine 的吸引力在于平滑下降，并且后期逐渐减小更新幅度。它不是损失函数的余弦，也不保证每个任务都优于线性衰减。切换 scheduler 时，应保持训练 token 预算和 peak lr 口径不变，再比较最终指标。

### 6.13.2 线性衰减和 constant schedule

线性衰减把学习率从 peak 平滑降到目标末值：

~~~math
\eta_t
=
\eta_{\max}
+
(\eta_{\min}-\eta_{\max})
\frac{t-T_w}{T-T_w}
~~~

constant-with-warmup 则在 warmup 后保持 peak lr。它适合持续训练、在线数据不断增加或希望把调度交给后续阶段的场景，但长时间训练中可能需要额外的稳定性控制。

### 6.13.3 调度器的边界问题

实际实现还要回答：

1. 最后一个不完整 accumulation window 算不算一个 optimizer step？
2. 训练提前停止时是否按实际 step 截断 scheduler？
3. 恢复 checkpoint 时 last_epoch 或内部 step 是多少？
4. scheduler 是在 optimizer.step() 前还是后调用？
5. 超过 T 后是固定在 eta_min，还是继续外推？

这些问题看似是接口细节，实际上会改变每个参数的更新量。

## 6.14 Warmup-Stable-Decay：让调度器适应持续训练

### 6.14.1 三个阶段

传统 warmup + cosine 通常假定总训练长度在开始时已经确定。持续预训练和领域适配往往需要在已有模型上不断追加数据，训练者可能希望在中间扩展 stable 阶段，而不是每次重新设计完整 cosine 曲线。

Warmup-Stable-Decay（WSD）可以抽象为：

~~~math
\eta(t)
=
\begin{cases}
\eta_{\max}\dfrac{t}{T_w},
&0\le t<T_w,\\[6pt]
\eta_{\max},
&T_w\le t<T_s,\\[6pt]
\operatorname{Decay}
(\eta_{\max},\eta_{\min},t;T_s,T),
&T_s\le t\le T.
\end{cases}
~~~

其中 T_s 是 stable 阶段结束位置。Decay 部分可以是 cosine 或其他衰减形式。WSD 的重要特征不是某个唯一公式，而是把稳定训练作为可扩展的独立阶段。

时间边界需满足 0<=T_w<=T_s<=T 且 T>0。T_w=0 表示无 warmup；T_s=T 表示这一份已知预算中尚未进入 decay。只有在这些边界被写进 checkpoint 和 scheduler state，后续扩展 stable 段才不会改变已消耗 token 的学习率历史。

### 6.14.2 它和普通 cosine 的关系

两者都可以有 warmup 和 decay。区别在于：

- cosine 通常从 warmup 后就持续衰减；
- WSD 可以在 peak lr 附近保持一段稳定区间；
- WSD 更容易把 stable 区间扩展为持续训练；
- decay 阶段可用于最后收敛或领域切换后的整理。

WSD 不是优化器，它只改变 eta_t。如果更换了 optimizer，同时更换 WSD，最终差异就无法归因。实验中应分别设置 AdamW + cosine、AdamW + WSD 和需要比较的新 optimizer。

### 6.14.3 公开资料的证据边界

MiniCPM 相关论文把 WSD 用于模型和数据规模实验、连续训练以及领域适配，并讨论了 stable 阶段对训练动态的影响。这个证据支持 WSD 在特定持续训练场景中的价值；它不意味着任何模型都应把 cosine 换成 WSD。是否有收益取决于数据流是否持续、训练长度是否可变、stable 阶段是否带来过拟合，以及 decay 末端如何选择。

## 6.15 Weight decay：参数规模控制与学习率绑定

### 6.15.1 衰减强度的实际含义

AdamW 每一步的乘法衰减因子是：

~~~math
\theta_t
\leftarrow
(1-\eta_t\lambda)\theta_t
~~~

因此 lambda 不能脱离学习率解释。若学习率降低，单步衰减也降低；若训练步数变化，总体衰减量也变化。粗略地说，在学习率很小时：

~~~math
\prod_t(1-\eta_t\lambda)
\approx
\exp\left(
-\lambda\sum_t\eta_t
\right)
~~~

这说明比较不同 scheduler 时，即使 weight_decay 字段相同，累计衰减也可能不同。

这个近似以每一步的 eta_t lambda 都足够小为前提；当个别乘子接近零或变号时，应直接计算乘积并重新检查配置，而不能继续引用指数近似。

### 6.15.2 预训练和后训练不能直接复用

预训练通常有较大的 token 预算和较长 schedule；SFT、LoRA 或偏好训练的可训练参数、数据规模和学习率都不同。直接复制预训练的 weight_decay，可能让小数据后训练过度收缩，也可能对 LoRA 参数施加不合适的正则。

记录 weight decay 时要同时记录：

~~~text
optimizer type
peak and final learning rate
number of optimizer steps
parameter groups
decay exclusions
parameter norm trace
~~~

## 6.16 Gradient clipping：限制单次更新的异常幅度

### 6.16.1 Global norm clipping

把所有参数梯度拼成向量 g，其 L2 范数为：

~~~math
\lVert g\rVert_2
=
\sqrt{\sum_i g_i^2}
~~~

给定阈值 c，全局裁剪为：

~~~math
g'
=
g
\cdot
\min
\left(
1,
\frac{c}{\lVert g\rVert_2+\epsilon}
\right)
~~~

它保持梯度方向，只在范数超过阈值时缩短向量。按参数组分别裁剪、按元素裁剪和按值裁剪则会改变方向或不同坐标的相对比例，不能把它们统称为同一种 clipping。

这里要求 c>=0、epsilon>0，且参与拼接的梯度是有限值；c=0 会把有限梯度全部清零，因而通常只适合测试而非训练。触发比例的分母也必须是正的已执行 optimizer steps，尚未发生过更新时该指标应记为未定义而不是 0。

### 6.16.2 混合精度中的顺序

若使用 loss scaling：

~~~text
scaled_loss = loss * scale
scaled_loss.backward()
unscale_(optimizer)
clip_grad_norm_(parameters, max_norm)
optimizer.step()
scaler.update()
~~~

裁剪必须在 unscale 后进行。否则计算出的范数包含 scale，阈值就不再代表原始梯度的阈值。

### 6.16.3 clipping ratio 是诊断信号

不要只记录裁剪后的 grad_norm。还要记录未裁剪范数和触发比例：

~~~math
r_{\mathrm{clip}}
=
\frac{
\#\{t:\lVert g_t\rVert_2>c\}
}{
\#\{\text{optimizer steps}\}
}
~~~

如果几乎每一步都被强烈裁剪，说明学习率、数据异常、loss 分母、初始化或数值精度可能有问题。裁剪可以阻止一次过大的更新，但不能修复错误的 label、未来信息泄漏或持续的学习率失配。

## 6.17 Batch scaling：学习率应跟 token 预算一起看

### 6.17.1 有效 token batch

若每张数据并行设备的 micro-batch 样本数为 B_micro，序列长度为 T，累积次数为 A，数据并行规模为 P_dp，等长情况下每次 optimizer update 消耗：

~~~math
B_{\mathrm{tok}}
=
B_{\mathrm{micro}}
\cdot
T
\cdot
A
\cdot
P_{\mathrm{dp}}
~~~

变长训练中应把 T 换成实际有效 token 数。只报告“每卡 2 条样本”无法说明 global batch，因为序列长度、累积次数和设备数都可能不同。

等长公式要求 B_micro、T、A、P_dp 都为正整数。最后一个不完整累积窗口、动态 padding、样本过滤或某个 rank 的空 batch 都会打破这个乘积；此时应从每个 rank 实际参与 loss 的 token 数求和。

### 6.17.2 线性缩放只是起点

若基线 token batch 从 B_1 变成 B_2，线性缩放假设给出：

~~~math
\eta_2
\approx
\eta_1\frac{B_2}{B_1}
~~~

平方根缩放则是：

~~~math
\eta_2
\approx
\eta_1\sqrt{\frac{B_2}{B_1}}
~~~

两者都不是大模型训练的普遍定律。Adam 的自适应状态、梯度噪声、长序列、动态 padding、数据混合、训练 token 预算和 warmup 都会改变结论。更可靠的做法是固定模型和数据，做小规模 token-batch sweep，并记录：

~~~text
tokens per optimizer step
peak learning rate
warmup tokens or steps
gradient norm distribution
validation loss per consumed token
time to target quality
~~~

### 6.17.3 相同 steps 不等于相同训练量

两个实验都跑 10,000 optimizer steps，但一个每步消耗 1M token，另一个每步消耗 2M token，它们的训练数据量相差一倍。比较优化器时，至少要同时给出：

- optimizer steps；
- consumed tokens；
- estimated FLOPs；
- wall-clock time；
- 达到目标指标的时间和 token 数。

否则“收敛更快”可能只是每一步喂了更多数据。

## 6.18 优化器与调度器的公平实验

### 6.18.1 先固定什么

一个可解释的比较应固定：

~~~text
model architecture and initialization
tokenizer and data order
training data and validation splits
precision and distributed topology
effective token batch
maximum consumed tokens
evaluation schedule
checkpoint policy
random seeds and retry policy
~~~

新 optimizer 的超参可以调，但调参预算也要固定。例如 AdamW 搜索 20 组，Muon 只试 2 组，最后把最好结果比较，结论会受到搜索预算影响。应记录搜索空间、失败实验和选择规则。

### 6.18.2 同时看四种曲线

至少画：

1. loss 对 optimizer steps；
2. loss 对 consumed tokens；
3. loss 对 wall-clock time；
4. 目标能力对 wall-clock time。

如果只画第一张图，无法区分“每步更快”“每 token 更有效”和“kernel 更快”。

### 6.18.3 质量不能只用 PPL

优化器可能让 validation PPL 更低，却使代码、数学、工具调用或指令遵循变化。对 LLM 训练至少分层观察：

| 层次 | 例子 |
| --- | --- |
| 训练信号 | train/validation loss、PPL |
| 通用能力 | 语言、知识、代码、数学 |
| 行为 | 格式、拒答、工具调用 |
| 风险 | 数据泄漏、隐私、越权、安全 |
| 系统 | 显存、吞吐、恢复、故障率 |

每一层都有自己的分母和误差，不能把所有数字未经说明地加成一个总分。

## 6.19 一个可运行的优化器审计示例

下面的示例只用 Python 标准库，使用一维二次损失和一个二维矩阵演示：

- linear warmup 与 cosine decay；
- global norm clipping；
- AdamW 与耦合 L2 Adam 的差异；
- token batch 计算；
- Adafactor 的状态量级；
- Lion 的符号更新；
- Sophia 的裁剪曲率更新；
- Muon 风格的矩阵方向归一化。

它不是生产 optimizer，也不声称实现了论文的全部细节。它的作用是让读者可以检查学习率、衰减、裁剪和状态账本是否按预期变化。

~~~python
import math


def finite_scalar(name, value):
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        raise ValueError(f"{name} must be a finite number")
    value = float(value)
    if not math.isfinite(value):
        raise ValueError(f"{name} must be finite")
    return value


def positive_int(name, value):
    if isinstance(value, bool) or not isinstance(value, int) or value <= 0:
        raise ValueError(f"{name} must be a positive integer")
    return value


def probability(name, value):
    value = finite_scalar(name, value)
    if not 0.0 <= value < 1.0:
        raise ValueError(f"{name} must be in [0, 1)")
    return value


def quadratic_grad(theta):
    theta = finite_scalar("theta", theta)
    return theta - 3.0


def quadratic_loss(theta):
    theta = finite_scalar("theta", theta)
    return 0.5 * (theta - 3.0) ** 2


def linear_warmup_cosine(step, peak_lr, min_ratio, warmup, total):
    step = positive_int("step", step)
    total = positive_int("total", total)
    if isinstance(warmup, bool) or not isinstance(warmup, int):
        raise ValueError("warmup must be an integer")
    if not 0 <= warmup < total:
        raise ValueError("warmup must satisfy 0 <= warmup < total")
    peak_lr = finite_scalar("peak_lr", peak_lr)
    min_ratio = finite_scalar("min_ratio", min_ratio)
    if peak_lr < 0.0 or not 0.0 <= min_ratio <= 1.0:
        raise ValueError("learning-rate parameters are out of range")
    if warmup and step <= warmup:
        return peak_lr * step / warmup
    progress = (step - warmup) / (total - warmup)
    progress = min(max(progress, 0.0), 1.0)
    cosine = 0.5 * (1.0 + math.cos(math.pi * progress))
    return peak_lr * (min_ratio + (1.0 - min_ratio) * cosine)


def clip_scalar(gradient, max_norm):
    gradient = finite_scalar("gradient", gradient)
    max_norm = finite_scalar("max_norm", max_norm)
    if max_norm < 0.0:
        raise ValueError("max_norm must be nonnegative")
    norm = abs(gradient)
    scale = min(1.0, max_norm / (norm + 1e-12))
    return gradient * scale, norm, scale


def adamw_step(theta, gradient, first, second, step, lr, beta1, beta2,
               eps, weight_decay):
    theta = finite_scalar("theta", theta)
    gradient = finite_scalar("gradient", gradient)
    first = finite_scalar("first", first)
    second = finite_scalar("second", second)
    step = positive_int("step", step)
    lr = finite_scalar("lr", lr)
    beta1 = probability("beta1", beta1)
    beta2 = probability("beta2", beta2)
    eps = finite_scalar("eps", eps)
    weight_decay = finite_scalar("weight_decay", weight_decay)
    if lr < 0.0 or eps <= 0.0 or weight_decay < 0.0:
        raise ValueError("lr, eps, or weight_decay is out of range")
    if lr * weight_decay >= 1.0:
        raise ValueError("lr * weight_decay must be smaller than 1")
    first = beta1 * first + (1.0 - beta1) * gradient
    second = beta2 * second + (1.0 - beta2) * gradient * gradient
    first_hat = first / (1.0 - beta1 ** step)
    second_hat = second / (1.0 - beta2 ** step)
    adaptive = first_hat / (math.sqrt(second_hat) + eps)
    decayed = (1.0 - lr * weight_decay) * theta
    theta = decayed - lr * adaptive
    return theta, first, second, adaptive


def coupled_l2_adam_step(theta, gradient, first, second, step, lr,
                         beta1, beta2, eps, weight_decay):
    theta = finite_scalar("theta", theta)
    gradient = finite_scalar("gradient", gradient)
    first = finite_scalar("first", first)
    second = finite_scalar("second", second)
    step = positive_int("step", step)
    lr = finite_scalar("lr", lr)
    beta1 = probability("beta1", beta1)
    beta2 = probability("beta2", beta2)
    eps = finite_scalar("eps", eps)
    weight_decay = finite_scalar("weight_decay", weight_decay)
    if lr < 0.0 or eps <= 0.0 or weight_decay < 0.0:
        raise ValueError("lr, eps, or weight_decay is out of range")
    gradient = gradient + weight_decay * theta
    first = beta1 * first + (1.0 - beta1) * gradient
    second = beta2 * second + (1.0 - beta2) * gradient * gradient
    first_hat = first / (1.0 - beta1 ** step)
    second_hat = second / (1.0 - beta2 ** step)
    theta = theta - lr * first_hat / (math.sqrt(second_hat) + eps)
    return theta, first, second


def matrix_frobenius_norm(matrix):
    if not isinstance(matrix, list) or not matrix:
        raise ValueError("matrix must be nonempty")
    width = None
    squared_norm = 0.0
    for row in matrix:
        if not isinstance(row, list) or not row:
            raise ValueError("matrix rows must be nonempty lists")
        if width is None:
            width = len(row)
        elif len(row) != width:
            raise ValueError("matrix must be rectangular")
        for value in row:
            value = finite_scalar("matrix value", value)
            squared_norm += value * value
    return math.sqrt(squared_norm)


def unit_frobenius_matrix(matrix):
    norm = matrix_frobenius_norm(matrix)
    if norm == 0.0:
        raise ValueError("a zero matrix has no direction to normalize")
    return [[value / norm for value in row] for row in matrix]


peak_lr = 0.1
min_ratio = 0.1
warmup = 3
total_steps = 10
beta1 = 0.9
beta2 = 0.95
eps = 1e-8
weight_decay = 0.1
clip_norm = 1.0

schedule = [
    linear_warmup_cosine(step, peak_lr, min_ratio, warmup, total_steps)
    for step in range(1, total_steps + 1)
]

theta = 8.0
first = 0.0
second = 0.0
trace = []
for step in range(1, 6):
    raw_gradient = quadratic_grad(theta)
    gradient, raw_norm, clip_scale = clip_scalar(raw_gradient, clip_norm)
    theta, first, second, adaptive = adamw_step(
        theta,
        gradient,
        first,
        second,
        step,
        schedule[step - 1],
        beta1,
        beta2,
        eps,
        weight_decay,
    )
    trace.append(
        {
            "step": step,
            "lr": round(schedule[step - 1], 5),
            "raw_norm": round(raw_norm, 5),
            "clip_scale": round(clip_scale, 5),
            "theta": round(theta, 5),
            "loss": round(quadratic_loss(theta), 5),
        }
    )

adamw_theta, _, _, _ = adamw_step(
    8.0, 1.0, 0.0, 0.0, 1, peak_lr, beta1, beta2, eps, weight_decay
)
coupled_theta, _, _ = coupled_l2_adam_step(
    8.0, 1.0, 0.0, 0.0, 1, peak_lr, beta1, beta2, eps, weight_decay
)

micro_batch = 2
sequence_length = 4096
accumulation_steps = 8
data_parallel = 16
effective_tokens = (
    micro_batch * sequence_length * accumulation_steps * data_parallel
)

rows = 4096
columns = 11008
adam_state_values = 2 * rows * columns
adafactor_state_values = rows + columns

lion_direction = 1 if 0.25 >= 0.0 else -1
lion_update = -peak_lr * lion_direction
sophia_update = max(min(0.25 / 0.8, 0.2), -0.2)
muon_matrix = [[3.0, 0.0], [4.0, 0.0]]
muon_unit = [[round(value, 4) for value in row]
             for row in unit_frobenius_matrix(muon_matrix)]

diagnostics = {
    "warmup_reaches_peak": abs(schedule[2] - peak_lr) < 1e-12,
    "cosine_reaches_min": abs(schedule[-1] - peak_lr * min_ratio) < 1e-12,
    "clipping_triggered": trace[0]["clip_scale"] < 1.0,
    "loss_decreased": trace[-1]["loss"] < trace[0]["loss"],
    "adamw_differs_from_coupled": round(adamw_theta, 6) != round(coupled_theta, 6),
    "effective_tokens_ok": effective_tokens == 1048576,
    "factored_state_smaller": adafactor_state_values < adam_state_values,
    "muon_unit_norm": abs(matrix_frobenius_norm(muon_unit) - 1.0) < 1e-12,
}

print("schedule=", [round(value, 5) for value in schedule])
print("trace=", trace)
print("adamw_theta=", round(adamw_theta, 6))
print("coupled_l2_theta=", round(coupled_theta, 6))
print("effective_tokens=", effective_tokens)
print("adam_state_values=", adam_state_values)
print("adafactor_state_values=", adafactor_state_values)
print("lion_update=", round(lion_update, 4))
print("sophia_clipped_direction=", round(sophia_update, 4))
print("muon_unit=", muon_unit)
print("diagnostics=", diagnostics)

assert all(diagnostics.values())
print("optimizer policy toy: ok")
~~~

代码中的 sophia_update 是一个标量裁剪示意，muon_unit 是 Frobenius 归一化示意，不是论文实现的 Hessian 估计或 Newton-Schulz 正交化。读者如果把这段代码扩展到真实模型，必须重新处理张量形状、分布式同步、低精度、参数分组和 checkpoint。

## 6.20 Checkpoint：优化器实验必须可以继续

### 6.20.1 需要保存的字段

比较 AdamW、Lion 或 Muon 时，checkpoint 至少要包含：

~~~text
model state_dict
optimizer state_dict
scheduler state_dict
scaler state_dict if used
global optimizer step
micro-step or accumulation position
data cursor
RNG states
parameter-group hyperparameters
optimizer implementation version
projection basis or curvature state if applicable
~~~

GaLore 的投影基、Sophia 的曲率估计和某些量化 optimizer 的 scale 都是算法状态。只恢复 m/v 而丢失这些额外状态，不能称为严格恢复。

### 6.20.2 连续运行和恢复运行的对照

用一个小模型做恢复测试：

1. 连续运行 20 个 optimizer steps。
2. 在第 10 步保存所有状态。
3. 从第 10 步恢复，再运行 10 步。
4. 比较第 11 步输入、学习率、梯度、参数和 loss。

若两条轨迹不同，按以下顺序定位：

- data cursor 是否重复或跳过；
- RNG 是否恢复；
- accumulation 窗口是否从正确位置开始；
- scheduler step 是否偏移；
- optimizer state dtype 是否变化；
- 参数组顺序和超参是否变化；
- 分布式归约顺序是否变化。

严格 bitwise 一致在不同硬件和 kernel 上未必可得，但差异必须被测量和解释，而不是假设不存在。

## 6.21 从 loss spike 反查优化器链

### 6.21.1 第一步：确认是否真的是优化器问题

loss spike 可能来自异常数据、label shift、mask 分母、数据切换、checkpoint 恢复或评估脚本。先关联异常 step 的：

~~~text
data source and sample ids
valid token count
sequence length distribution
learning rate
raw and clipped grad norm
parameter norm
overflow / NaN flags
optimizer state statistics
~~~

只有当数据和目标链路正常，才适合把原因集中到 optimizer 或 scheduler。

### 6.21.2 学习率过大或 warmup 太短

常见表现是训练刚开始或 scheduler 切换点出现尖峰。可以做最小对照：

- peak lr 减半；
- warmup 延长；
- 保持 optimizer 和 token batch 不变；
- 比较 grad norm、clipping ratio 和验证损失。

如果 spike 消失，仍要继续检查是否牺牲了最终质量，不能只因为曲线平滑就宣布修复。

### 6.21.3 beta、eps 或 decay 不合适

beta1 影响方向的平滑程度，beta2 影响二阶尺度的响应速度，eps 影响小分母区域，weight decay 影响参数范数。它们的变化应一次只改一类，并保存每次实验的 optimizer state 配置。

beta2 较大时，二阶统计对新梯度反应慢；较小时，尺度估计更快但可能更噪。不存在只凭模型名称就能确定的唯一值。

### 6.21.4 clipping 持续触发

检查：

1. loss 是否已按有效 token 归一化；
2. 梯度累积是否正确；
3. unscale 是否先于 clipping；
4. 学习率是否在 scheduler 边界突然变化；
5. 是否只有某个数据来源或 rank 异常；
6. 是否把未裁剪 norm 错当成裁剪后的 norm。

持续裁剪可能是保护措施，也可能在掩盖训练配置错误。要记录裁剪前后的数值。

### 6.21.5 换新优化器却没有收益

先确认新方法是否真的进入了期望参数：

- 参数组数量和元素量；
- optimizer state 的形状；
- 每步更新范数；
- kernel 和通信耗时；
- scheduler 是否仍按旧实验配置；
- 调参预算是否公平。

Muon 若所有参数都走同一逻辑，可能失去其设计前提；Lion 若复用 AdamW 的学习率，可能产生完全不同的更新尺度；Sophia 若曲率估计未刷新，可能退化成异常的预条件器；GaLore 若 rank 太低，可能限制有效更新子空间。

## 6.23 章节练习：从公式到实验

### 练习一：手算 AdamW

给定 theta=2、g=0.5、m_0=v_0=0、beta1=0.9、beta2=0.999、lr=0.01、weight_decay=0.1，分别计算第一步的 AdamW 更新和把 L2 项并入梯度后的 Adam 更新。指出两者在哪一步产生差异。

### 练习二：状态账本

假设模型有 7B 参数，权重和梯度为 BF16，m/v 和 master weight 为 FP32。先计算忽略激活时的粗略字节数，再列出分片、offload、8-bit state、Adafactor 和 GaLore 分别改变了账本的哪一项。

### 练习三：变长 batch

两个 micro-batch 分别有 100 和 300 个有效 token，未归一化 loss 分别为 50 和 120。比较：

1. 平均两个 batch mean；
2. 按总有效 token 汇总。

说明哪一种与 token-level cross entropy 一致，以及错误分母会怎样改变梯度权重。

### 练习四：scheduler 恢复

写出 warmup 10 steps、stable 30 steps、decay 60 steps 的 WSD 学习率表。模拟在第 25 步保存、从第 25 步恢复和错误从第 0 步恢复，比较之后 10 步的学习率总和。

### 练习五：优化器公平比较

设计 AdamW、Lion 和 Muon 的小规模比较。要求固定模型、tokenizer、数据顺序、token batch、精度和最大 token 预算，同时记录每种方法的调参预算、失败实验、显存、吞吐、验证 loss 和三项下游能力。

### 练习六：恢复一致性

给 toy optimizer 增加随机 dropout 和 data cursor。在第 5 步保存权重、optimizer、scheduler、RNG 和 cursor，比较连续运行与恢复运行的第 6 步梯度和参数。

### 练习七：解释一个“更快”

假设新优化器在 1000 steps 时达到同样 PPL，但每步 token 数少一半、kernel 更快 20%。分别用 steps、tokens、FLOPs 和 wall-clock 计算“更快”是否成立，并指出需要补充哪些质量指标。

## 6.24 本章小结

优化器把带噪声的梯度变成参数更新，学习率调度器决定更新尺度随训练进度如何变化。SGD 直接沿负梯度走，Momentum 累积方向，Adam 增加一阶和二阶统计，AdamW 则把 weight decay 从自适应梯度中分离出来，形成大模型训练中成熟的强基线。

Adafactor 通过分解二阶统计降低状态显存；Lion 用符号动量减少状态但需要重新调学习率；Sophia 引入轻量曲率信息并用裁剪控制二阶更新；Muon 关注矩阵参数的整体几何；GaLore 通过低秩梯度投影降低全参数训练的状态压力。这些方法解决的问题不同，不能只按谁更新或谁更省显存排一张没有条件的排行榜。

Warmup、cosine、线性衰减和 WSD 只定义学习率轨迹，不会自动修复错误的 loss 分母。gradient clipping 限制异常更新，但不能替代数据、数值和恢复检查。真正可比较的训练实验必须同时报告 optimizer state、参数分组、有效 token batch、学习率步数、总 token、质量指标、系统成本和 checkpoint 恢复行为。

下一章进入分布式训练，说明当一个 optimizer update 跨越多张设备时，梯度、状态、通信和故障恢复如何共同决定训练系统的实际行为。
