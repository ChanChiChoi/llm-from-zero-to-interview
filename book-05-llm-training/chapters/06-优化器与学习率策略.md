# 第六章：优化器与学习率策略：从梯度到可验证的参数更新

## 6.0 训练中的“下一步”究竟由谁决定

上一章把一次训练循环拆成了数据、损失、反向传播、梯度累积和 optimizer.step()。本章继续追问最后一个动作：模型拿到梯度以后，究竟怎样把梯度变成参数变化？

先看一个只有一个参数的例子。令损失为 $L(\theta)=\frac12(\theta-1)^2$，当前参数是 $\theta_{0}=3$。此时梯度为 $g_{0}=\theta_{0}-1=2$，学习率取 $\eta=0.1$。沿负梯度走一步，参数从 3 变成 2.8；损失也从 $2$ 降到 $1.62$。梯度给出往哪边走，学习率决定走多远。

把这一步写成一般形式，就是最简单的梯度下降：

~~~math
\theta_{t+1}
=
\theta_{t}-\eta_{t} g_{t}
~~~

其中：

- $\theta_{t}$ 是第 $t$ 次 optimizer update 之前的参数；
- $g_{t}$ 是当前有效 token batch 产生的梯度；
- $\eta_{t}$ 是第 $t$ 次更新使用的学习率。

上例用 $\theta_{0}$ 表示初始参数；以下各节为方便按更新次数编号，默认 $t$ 从 1 开始。$\theta_{t}$ 和 $g_{t}$ 形状相同且元素有限，$\eta_{t}\ge0$。若梯度已经出现 NaN 或 Inf，优化器不会把它“更新回正常值”；应先检查损失、混合精度和数据链路。

这个公式足以说明方向，却不足以描述现代大模型训练。真实更新还会涉及动量、梯度平方的统计、权重衰减、梯度裁剪、混合精度、参数分组和学习率调度器。优化器还会保存自己的历史状态，调度器也会保存当前进度。因此，一次更新更接近下面这条链：

~~~text
有效 token batch
  -> gradient
  -> unscale (if needed)
  -> clipping
  -> optimizer state update
  -> adaptive/geometric transform and optional decay
  -> parameter update (if the optimizer step is not skipped)
  -> scheduler advance using its declared clock
  -> checkpoint and metrics
~~~

初学者可以把优化器理解成“根据当前梯度和历史经验决定走法的规则”。专家还要问得更具体：

1. $g_{t}$ 是按有效 token 正确归一化的吗？
2. 梯度裁剪发生在 loss scaling 还未还原之前，还是之后？
3. optimizer 的 m、v、曲率估计或投影基是否保存并恢复？
4. weight decay 是经过自适应分母的 L2 项，还是与梯度解耦的参数衰减？
5. scheduler 是按 micro-step 还是 optimizer step 前进？
6. 比较两个优化器时，是否固定了 token 预算、模型、数据、精度和失败重试规则？

本章先建立 SGD、Momentum、Adam 和 AdamW 的主线，再讨论 Adafactor、Lion、Sophia、Muon 和 GaLore 等路线。后面的新方法不是“新闻列表”：每个方法都要说明它改变了哪一部分状态或更新几何，节省了什么，增加了什么代价，公开证据覆盖到哪里。

## 6.1 先建立参数、梯度和状态账本

### 6.1.1 梯度是一个带噪声的估计

先看两个长度差很多的样本。样本 A 有 1,000 个有效目标 token，平均 token loss 为 0.2；样本 B 有 10 个有效目标，平均 token loss 为 1.0。若先给两个样本各一票，平均 loss 是 $(0.2+1.0)/2=0.6$。若每个目标 token 权重相同，则汇总 loss 是 $(1000\times0.2+10\times1.0)/1010\approx0.208$。两种结果不同，是因为它们回答了不同问题：前者让每条样本等权，后者让每个目标 token 等权。本章讨论 token-level 交叉熵时，沿用上一章的有效目标 token 分母。

训练数据通常来自一个很大的数据分布 D。理想目标是最小化总体风险：

~~~math
\mathcal{L}(\theta)
=
\mathbb{E}_{x\sim D}
[
\ell(\theta;x)
]
~~~

一个 mini-batch 只能给出这个期望的估计：

~~~math
g_{t}
=
\frac{1}{|B_{t}|}
\sum_{x\in B_{t}}
\nabla_{\theta} \ell(\theta_{t};x)
~~~

在语言模型里， $|B_{t}|$ 因而是有效 label token 数，不是样本条数。若某个任务明确定义为“每条样本等权”，分母就应按该目标定义；不能把两种目标的分母混用。

这里隐含 |$B_{t}$|>0。全是 padding、所有标签都被 ignore，或过滤后没有有效 token 的 batch，不存在这个平均梯度；把分母硬改成 1 虽能避免除零，却会把“没有训练信号”伪装成“梯度为零”，让数据问题进入训练统计而不易察觉。

梯度噪声并不只来自样本。dropout、动态 padding、数据顺序、混合精度舍入、分布式归约顺序和自定义 kernel 都可能使两次运行的 $g_{t}$ 不完全相同。优化器的历史状态会把这些局部梯度整合成更长时间尺度的更新。

### 6.1.2 三种容易混淆的步数

训练系统至少有三种步数：

| 名称 | 含义 | 是否通常推进 scheduler |
| --- | --- | --- |
| micro-step | 一次 forward/backward | 通常不推进 |
| optimizer step | 一次参数更新 | 通常推进 |
| token step | 消耗了多少有效 token | 用于吞吐和预算 |

假设每次有 8 个 micro-batch 才做一次参数更新，那么 `global_step=100` 通常意味着已经完成约 800 次 forward/backward，而不是 100 次。若 scheduler 错把每个 micro-step 当作一个更新，warmup 和 decay 会比配置短 8 倍。

### 6.1.3 参数之外还保存什么

令参数量为 P。一个 Adam 类优化器通常至少保存与参数同形状的一阶状态和二阶状态：

~~~math
M_{\mathrm{state}}
\approx
P(b_{m}+b_{v})
~~~

$b_{m}$、 $b_{v}$ 是每个状态元素的字节数。若两个状态都使用 FP32，粗略就是 8P 字节。完整训练显存还要加上参数副本、梯度、可能的 FP32 master weights、激活、通信缓冲区和 allocator 碎片。这个公式是账本的起点，不是显存测量的替代品。

可恢复训练至少要记录：

~~~text
model weights
optimizer states
scheduler state
mixed-precision scaler state
random states
data cursor
global optimizer step
parameter-group configuration
model/tokenizer/config version
~~~

如果只保存模型权重，当然可以加载并推理；但重新创建一个“看起来相同”的 optimizer 并不等于从原来的训练轨迹继续。动量、二阶矩、学习率阶段和数据位置一旦改变，下一次更新就已经不是同一个实验。

假设每个 micro-batch 有 2 条长度为 5 的样本，因内部 causal shift 每条有 4 个目标；累积 4 次并行于 2 个数据 rank，则一个 optimizer step 汇总 $2\times4\times4\times2=64$ 个目标。此时 global optimizer step 增加 1，micro-step 增加 4，已消费目标数增加 64。若 warmup 配置为 10 optimizer steps，它的意义是 10 次参数更新；误按 micro-step 推进会在第 3 次更新附近就把调度器推进到原本第 10 步的位置。三个账本分别回答更新次数、模型看到的监督量和前向/反向次数，日志中不要都命名为 step。

这个小例子也限定了 batch 扩容后的比较：把数据并行 rank 数翻倍，若每步全局目标数也翻倍，momentum 与二阶状态只经历一半多次更新就能看到相同 token 总量。即使最终都是 640 个目标 token，状态衰减按 optimizer step 计数时轨迹仍可能不同。第 17 节会把这种差别带入学习率缩放；第 20 节则会说明这几个计数器都需进入 checkpoint。

一条可复核的训练日志可以把这些账本放在同一行：例如 `optimizer_step=100`、`micro_step=800`、`effective_targets=52428800`、`targets_this_update=524288`、`lr=0.0004`。前两个字段说明已经做了 100 次权重更新和 800 次前后向，后两个说明累计/本次消费的有效监督量，最后一个说明下一次更新的尺度。只留下 `step=100` 无法知道它是 optimizer step、micro-step 还是日志批次；当 batch、序列长度或 mask 发生变化时，这种命名会直接妨碍定位训练差异。

## 6.2 SGD：把梯度直接变成位移

### 6.2.1 基本更新

随机梯度下降的更新是：

~~~math
\theta_{t+1}
=
\theta_{t}-\eta_{t} g_{t}
~~~

学习率 $\eta_{t}$ 决定步长，梯度方向决定位移方向。若把 loss 想象成一张山谷地图，梯度指向局部上坡方向，负梯度就是下降方向。

SGD 的优点是状态少、规则透明。除了参数和梯度，它不需要保存一阶或二阶历史。它的缺点也很直观：如果 loss 在不同方向的曲率差异很大，固定的标量学习率很难同时适合所有方向。

### 6.2.2 一个二维山谷

令 $L(x,y)=\frac12(100x^2+y^2)$，从 $(1,1)$ 出发，学习率取 $0.015$。梯度为 $(100,1)$，所以一步 SGD 得到 $(-0.5,0.985)$：陡峭的 $x$ 方向越过谷底，平缓的 $y$ 方向只前进一点。这个例子先说明了困难：一个统一步长可能让陡峭方向震荡，同时让平缓方向走得很慢。

把这种地形写成二次函数：

~~~math
L(x,y)
=
\frac{1}{2}(a x^2+b y^2)
~~~

当 $a$ 远大于 $b$ 时， $x$ 方向很陡， $y$ 方向很平。若学习率足以让 $y$ 方向前进， $x$ 方向可能来回震荡；若为了 $x$ 方向降低学习率， $y$ 方向又会收敛得很慢。这种不同方向的尺度差异是病态性或条件数问题的直观来源。

这个二次例子要求 $a>0$、 $b>0$ 才表示有唯一最低点的碗形曲面；它只用于建立直觉，不是对深层网络非凸损失的全局描述。

在大模型中，参数矩阵不同层、不同通道和不同参数类型的梯度尺度也可能差异很大。SGD 并非不能训练神经网络，而是它通常需要更仔细的学习率、batch 和正则化配合，且在 Transformer 预训练中不如 Adam 系方法常见。

### 6.2.3 Momentum：积累方向而不是只看当前一步

假设当前速度 $v_{0}=0$，梯度先连续三步为 $+1$，随后反转为 $-1$，并取 $\beta=0.9$。速度依次为 $v_{1}=0.1$、 $v_{2}=0.19$、 $v_{3}=0.271$、 $v_{4}=0.1439$、 $v_{5}\approx0.0295$、 $v_{6}\approx-0.0735$。梯度第一次反向时，速度仍为正；到第六步才翻转。Momentum 平滑了短时变化，也因此带来响应延迟。

Momentum 维护速度向量 $v_{t}$：

~~~math
v_{t}
=
\beta v_{t-1}
+
(1-\beta)g_{t}
~~~

~~~math
\theta_{t+1}
=
\theta_{t}-\eta_{t} v_{t}
~~~

$\beta$ 越大，历史方向的影响越持久。连续多次朝同一方向的梯度会叠加，反复改变方向的噪声则会相互抵消。

通常取 $0\le\beta<1$： $\beta=0$ 退化为只使用当前梯度， $\beta\ge1$ 则不再是收敛的指数移动平均。学习率仍须结合目标的局部曲率和梯度噪声选择，动量并没有消除步长约束。

有些实现把公式写成 $v_{t}=\beta v_{t-1}+g_{t}$，再通过其他方式调整学习率。两种写法不是看到变量名就能直接比较的，必须连同 $\eta$ 的定义一起看。教材中采用带 (1-$\beta$) 的指数移动平均形式，便于和 Adam 的一阶矩统一。

SGD 和 Momentum 的状态量小，是理解 Adam 前的基线，不意味着它们天然更省训练成本。若降低学习率来稳定陡峭方向，平坦方向可能需要更多更新；若提高学习率追赶平坦方向，又可能产生振荡。对比时至少匹配模型、token batch、数据曝光与最终验证目标，并报告总 token 和时间。否则“每步只需一个梯度、状态更少”并不能推出训练更便宜。

Momentum 的指数移动平均可展开成历史梯度的加权和： $v_{t}=(1-\beta)\sum_{j=0}^{t-1}\beta^j g_{t-j}$（忽略初始状态项）。当 $\beta=0.9$，最近一步权重为 0.1，前十步内的信号占大部分；常用的粗略记忆跨度是 $1/(1-\beta)\approx10$ 步。 $\beta=0.99$ 时该跨度约 100 步，方向更平滑但对梯度分布变化更迟钝。该数值是 EMA 时间尺度的直觉，不是优化器可见的精确窗口。
对独立、同分布的样本梯度，batch 平均的方差会随样本数近似按 $1/N$ 缩小；token 序列中的相邻目标、重复文档与同一长样本内 token 并非独立，因此有效样本量未必等于 token 数。Momentum 主要用时间维度的历史梯度平滑方向，增大 token batch 则改变当前梯度估计，两者不能简单互换。调 SGD/Momentum 时同时记录每次更新的梯度和速度范数、梯度方向余弦相似度及验证损失，可判断噪声来自 batch 还是状态滞后。

这不是实现 bug，而是 EMA 历史造成的响应延迟；当训练数据从一个 mixture 切到另一个 mixture 时，较大 momentum 可能在短窗口内沿旧方向更新。监控时把 gradient dot product 与 velocity dot product 的符号一起看，能发现新梯度已经转向、参数更新仍延续旧方向的区间。

对小规模凸二次问题，学习率稳定条件可以由最大曲率推出；非凸深度网络没有一个固定全局 $a$，因此小模型上找到的稳定学习率并不保证迁移到更宽、更深或更长上下文的模型。常见策略是先在代表性子配置上做有限的 LR sweep，检查训练初期和调度器切换点，再把最优候选作为新模型的起始值，而不是将二次函数的 $2/a$ 当成 LLM 配方。

在一维 $L(x)=\tfrac12 ax^2$ 中，更新误差满足 $x_{t+1}=(1-\eta a)x_{t}$： $\eta=1/a$ 一步到达最小值， $1/a<\eta<2/a$ 会交替变号但逐步缩小， $\eta\geq2/a$ 不再收缩。多维二次函数则对每个 Hessian 特征值分别有这样的条件，最大特征值最先限制步长；这说明“沿陡峭方向震荡”不是比喻，而是更新矩阵的特征方向行为。

SGD 仍是有价值的对照基线：它可以帮助判断自适应坐标缩放是否带来收益，也适用于状态内存极紧、梯度尺度已被归一化或研究目标明确希望减少优化器状态的设置。公平比较中 SGD 也需独立调学习率、momentum、weight decay 和 batch；把 AdamW 调好的学习率直接搬到 SGD，会让 baseline 失去解释力。比较的结论应是“在给定调参预算与数据/模型约束下，哪条路线达到目标质量更省总资源”，而不是按公式复杂程度排优劣。

Momentum 的两种常见记法还会让同一个超参数看起来差一个数量级。若实现维护 $v_{t}=\beta v_{t-1}+(1-\beta)g_{t}$，再走 $-\eta v_{t}$；另一种实现维护 $s_{t}=\beta s_{t-1}+g_{t}$，再走 $-\alpha s_{t}$，在零初态且相同步数下有 $v_{t}=(1-\beta)s_{t}$。因此要复现同一条更新，可令 $\alpha=\eta(1-\beta)$；若把两个实现里的学习率数字原样照抄，在 $\beta=0.9$ 时稳态方向的幅度会相差约十倍。比较配置时须连状态递推式和学习率定义一起记录。

## 6.3 Adam：为每个参数估计自己的步长

先把 $m$ 看成梯度方向的记忆，把 $v$ 看成平方梯度尺度的记忆。现在让一个参数连续两步遇到相反梯度： $g_{1}=1$、 $g_{2}=-1$，初始状态为 $m_{0}=v_{0}=0$，取 $\beta_{1}=0.9$、 $\beta_{2}=0.99$。第一步写入的状态是 $m_{1}=0.1,v_{1}=0.01$；偏置修正后分别回到 1 和 1。第二步的一阶状态变成 $m_{2}=-0.01$，因为旧方向和新梯度几乎抵消；二阶状态为 $v_{2}=0.0199$，修正后仍为 1。因此忽略 $\epsilon$ 时，第二步除以学习率后的更新方向只有约 $-0.0526$，而不是直接跟着当前梯度走完整的一步。这个过程包含 Adam 的两件事：记住方向，也按各参数自己的梯度尺度缩放。

### 6.3.1 一阶矩和二阶矩

Adam 同时维护梯度的一阶矩和平方梯度的二阶矩：

~~~math
m_{t}
=
\beta_{1}m_{t-1}
+
(1-\beta_{1})g_{t}
~~~

~~~math
v_{t}
=
\beta_{2}v_{t-1}
+
(1-\beta_{2})g_{t}^2
~~~

这里的平方是逐元素平方。 $m_{t}$ 保留方向信息， $v_{t}$ 估计每个参数梯度幅度。为了纠正初始化时状态从零开始造成的偏差，Adam 使用：

~~~math
\hat m_{t}
=
\frac{m_{t}}{1-\beta_{1}^t},
\qquad
\hat v_{t}
=
\frac{v_{t}}{1-\beta_{2}^t}
~~~

参数更新为：

~~~math
\theta_{t+1}
=
\theta_{t}
-
\eta_{t}
\frac{\hat m_{t}}{\sqrt{\hat v_{t}}+\epsilon}
~~~

如果某个参数过去的梯度平方平均较大，分母会把它的更新缩小；如果梯度幅度较小，更新相对会变大。这就是自适应学习率的来源。

这组公式的常用有效域是 $0\le\beta_{1},\beta_{2}<1$、 $\epsilon>0$、 $t\ge1$。这样 $1-\beta_{i}^t$ 为正，偏置修正有定义； $\epsilon$ 只处理数值上的小分母，不能替代对非有限梯度和损失溢出的检查。

### 6.3.2 为什么必须做偏置修正

刚才的两步例子里，第一步的状态为 $m_{1}=0.1,v_{1}=0.01$，都低于当前梯度及其平方；分别除以 $1-\beta_{1}=0.1$ 和 $1-\beta_{2}=0.01$ 后，估计回到 1。第 $t$ 步就用 $1-\beta_{1}^t$ 和 $1-\beta_{2}^t$ 修正这种从零初始化产生的低估。若省掉修正，Adam 训练初期的更新会偏小，可能让短 warmup 下的调度器变化看起来像优化器差异。第二步方向仍很小，则是历史动量与新梯度相抵，不是偏置修正失效。

在第一步、 $\epsilon\to0$ 的极限下，Adam 的坐标更新近似为梯度符号；加入 $\epsilon$ 后，小梯度坐标会比大梯度坐标缩得更多。若梯度幅度全部乘常数 $a>0$，且 $\epsilon$ 可忽略，则 $\hat m/\sqrt{\hat v}$ 近似不变；这说明 Adam 对共同缩放有一定不变性，却不代表它对学习率、 $\epsilon$、权重衰减或随时间改变的梯度尺度不敏感。真正的运行状态还包括过去的 $m,v$，非平稳梯度会让归一化响应滞后。

偏置修正必须使用实际的 optimizer step 计数。例如一次梯度累积由 8 个 micro-batch 组成，只有完成累积才执行 Adam 更新；幂指数应从这次 optimizer 更新计为 $t=1$，而不是把 8 个 micro-step 当成 8 个 Adam 状态更新。恢复训练时也应恢复该计数，否则同样的 $m,v$ 会配上错误的偏置修正分母。实际框架对 fused/capturable 版本的 step 计数细节应以固定版本的接口文档和实现为准。

### 6.3.3 $\epsilon$ 不是装饰参数

$\epsilon$ 防止分母为零，也影响小二阶矩区域的更新尺度。不同实现可能把它放在平方根内部或外部，数学上并不完全等价：

~~~math
\frac{\hat m_{t}}{\sqrt{\hat v_{t}}+\epsilon}
\quad\text{和}\quad
\frac{\hat m_{t}}{\sqrt{\hat v_{t}+\epsilon}}
~~~

当 v 很大时差异可能不明显，当 v 很小或低精度训练时差异会被放大。复现实验时要记录框架、优化器版本和 eps 的位置，而不能只记录 AdamW 四个字。

单步计算能显示 $\epsilon$ 具体作用在哪里。令 $m_{0}=v_{0}=0$、 $\beta_{1}=\beta_{2}=0$，因此第一步偏置修正后 $\hat m=g,\hat v=g^2$。当 $g=10^{-3}$ 且 $\epsilon=10^{-8}$，更新方向约为 $10^{-3}/(10^{-3}+10^{-8})=0.99999$；若同一个演示把 $\epsilon$ 提高到 $0.01$，方向变为 $0.001/0.011\approx0.0909$。对于 $g=1$，这两个 $\epsilon$ 给出的方向都接近 1。该例说明 $\epsilon$ 主要影响小分母坐标； $0.01$ 只是教学数值，不是训练推荐值。

$\epsilon$ 在平方根内外也有不同数量级。若 $\hat v=10^{-6}$ 且 $\epsilon=10^{-4}$，外置形式的分母是 $0.001+0.0001=0.0011$，内置形式是 $\sqrt{10^{-6}+10^{-4}}\approx0.01005$，相差约 9 倍。真实实现通常使用远小于此示例的数值，但在低精度、归一化极小或实验要求精确复现时，位置差异仍值得核对。它不是可以随意“挪进根号”的同一公式。

$\beta_{1}$ 和 $\beta_{2}$ 也刻画不同时间尺度。较大的 $\beta_{1}$ 会让 $m_{t}$ 更平滑，但对梯度方向快速翻转反应更慢；较大的 $\beta_{2}$ 会让 $v_{t}$ 的尺度统计更稳定，却更难及时响应梯度方差突变。回看前面的 $1,-1$ 两步例， $m_{t}$ 抵消导致第二步更新很小；若第二步后梯度长期变为 -1，动量才会逐渐转向。只用某个 batch 的当前梯度来判断 Adam 的更新方向，会忽略已有状态。

Adam 的自适应作用是逐坐标缩放，而不是直接估计一个全局最优学习率。若两个参数都经历梯度 $(1,0.01)$，偏置修正后的分母也不同，第二个坐标会结合自身历史尺度适应更新；但分母若长期积累了旧分布信息，突然换数据时它可能短时过大或过小。诊断时可记录 $m$ 的 RMS、 $\sqrt v$ 的分位数、每组更新范数和梯度范数，尤其观察数据切换前后这些统计的响应速度。

实际复现还应区别经典 Adam、AdamW、AMSGrad 或 fused 变体：它们的状态更新、最大二阶矩、 $\epsilon$、weight decay 和 step 计数可能不同。比较源码前至少固定框架版本和接口参数；论文公式说明算法家族，官方文档说明特定版本公开接口，二者不能互相替代。本章随后用 AdamW 的独立衰减例子说明其中一个关键扩展。

一个极端但很有用的对照是令 $\beta_{1}=\beta_{2}=0$。此时偏置修正后的 $m_{t}=g_{t}$、 $v_{t}=g_{t}^2$，忽略 $\epsilon$ 时更新为 $g_{t}/|g_{t}|$，即近似 sign direction，而不是原始 SGD 的 $g_{t}$。这说明 Adam 的自适应分母会改变梯度幅度，即使完全没有跨步记忆；momentum 与逐坐标归一化是两个不同机制。

术语上还要避免把 $v_{t}$ 直接叫作统计学意义的“梯度方差”。Adam 通常累积的是梯度平方的指数平均，并未先减去梯度均值，因此它是未中心化的二阶量；若梯度均值很大，它也会很大。这个状态用来构造逐坐标分母，不是对 batch 梯度噪声方差的无偏估计。排查噪声时应另行统计跨 batch 的梯度均值与波动，不能把 $\sqrt{v_{t}}$ 当成误差条。

对于非平稳训练，二阶状态的时间常数也会影响响应。以 $\beta_{2}=0.99$ 为例，单个异常平方梯度以 $0.01$ 权重写入 $v_{t}$，其后每一步旧贡献再乘 0.99；约 69 步后它衰减到原贡献的一半左右。这个半衰期由 $\log(0.5)/\log(0.99)$ 计算，说明旧数据分布的统计可能持续影响后续更新。真实状态中每一步都会加入新梯度，故不是一次异常值的精确恢复时间，但可用于理解为什么 $\beta_{2}$ 变小会加快适应、同时提高尺度噪声。

时间尺度要按 optimizer updates 理解，而不是直接按样本或 token 数理解。若 $\beta_{2}=0.999$，单次状态贡献的半衰期约为 693 次更新；每步处理 1M 个有效目标时，这相当于约 693M 个目标的暴露跨度，若每步 batch 增至 4M，则对应约 2.77B 个目标。这里是在隔离旧贡献的衰减，不代表整个 $v_{t}$ 会在这些 token 后恢复到某个固定值；但它说明改变 batch 会同时改变状态跨越的数据量。

### 6.3.4 Adam 的代价

Adam 需要保存 m 和 v，因此状态量级为 2P 个元素。对于数十亿参数，状态往往比权重本身更快成为显存瓶颈。分片、8-bit 状态、CPU offload 和低秩投影都在不同层面处理这个问题，但它们不是同一种方法：

- 分片改变状态由哪个设备保存；
- 低比特状态改变每个状态元素的表示；
- 低秩投影改变状态所在的子空间；
- Adafactor 改变二阶统计的存储结构。

混淆这些层次，会导致优化器省显存的描述不准确。

## 6.4 AdamW：把权重衰减从自适应梯度中分离

先看两个参数。令 $\theta=(1,1)$、数据梯度 $g=(-0.05,0.01)$、 $\eta=0.1$、 $\lambda=0.1$，并暂取 $\beta_{1}=\beta_{2}=0$、 $\epsilon=0.001$ 以便手算。AdamW 先按各坐标的梯度构造自适应方向，再独立收缩参数，结果约为 $(1.0880,0.8991)$。若把 $\lambda\theta$ 并进梯度，梯度变成 $(0.05,0.11)$，两个坐标的方向都变为正，结果约为 $(0.9020,0.9009)$。第一坐标的原始梯度本来会让参数增加，耦合的 L2 项却把方向翻转了。这个差别来自“正则项是否进入 Adam 的历史状态和自适应分母”。

### 6.4.1 L2 正则与 weight decay 的差别

在普通 SGD 中，把 L2 正则加到目标函数：

~~~math
L_{\mathrm{reg}}(\theta)
=
L(\theta)+\frac{\lambda}{2}\lVert\theta\rVert_{2}^2
~~~

得到的梯度是：

~~~math
\nabla L_{\mathrm{reg}}(\theta)
=
\nabla L(\theta)+\lambda\theta
~~~

对 SGD 来说，把 $\lambda\theta$ 加进梯度，和每一步额外做参数衰减具有直接关系。但在 Adam 中，这个正则项也会进入一阶矩和二阶矩，随后被自适应分母重新缩放。参数的衰减强度因坐标的历史梯度而改变，这不再是简单的统一 weight decay。

严格地说，上述经典等价式针对的是没有动量状态的普通 SGD。若带 momentum，耦合 L2 项会进入速度并影响后续更新；解耦 decay 则每步直接收缩参数而不改速度。因而即使不用 Adam，自定义带动量的实现也应先确认采用哪种正则语义，不能只凭“SGD 加 L2”等字样推断更新完全一致。

这一区别可从代数上验证。对普通 SGD，耦合形式给出 $\theta'=\theta-\eta(g+\lambda\theta)=(1-\eta\lambda)\theta-\eta g$，恰好等于先做独立衰减再沿数据梯度更新。Adam 的预条件算子会作用在 $g+\lambda\theta$ 上，不满足把 $\lambda\theta$ 从算子中直接提出的线性等式；一阶矩和二阶矩也会把正则方向写进之后的状态。[解耦 weight decay 的原始论文](https://arxiv.org/abs/1711.05101v3)正是针对这种自适应算法下的不等价提出 AdamW。

### 6.4.2 Decoupled weight decay

AdamW 将梯度自适应更新记为：

~~~math
u_{t}
=
\frac{\hat m_{t}}{\sqrt{\hat v_{t}}+\epsilon}
~~~

然后把衰减独立施加到参数：

~~~math
\theta_{t+1}
=
(1-\eta_{t}\lambda)\theta_{t}
-
\eta_{t} u_{t}
~~~

$\lambda$ 不进入 $m_{t}$ 或 $v_{t}$。因此 $\eta_{t}$ 变化时，每一步衰减量也会变化；weight decay 仍然与学习率的步长尺度相乘，但不再经过 Adam 的坐标自适应。以 PyTorch 2.15 的 AdamW 说明为例，官方文档把衰减项写成独立于一阶、二阶动量累积的参数更新；该引用支持此版本接口语义，不代替其他框架的实现核对。[PyTorch AdamW 2.15 文档](https://docs.pytorch.org/docs/2.15/generated/torch.optim.AdamW.html)还公开了参数组、状态加载等接口字段。

若把它解释为“收缩”而非仅仅一条代数更新，通常还要求 $\lambda\ge0$ 且 $0\le\eta_{t}\lambda<1$；后一条件使乘子 $1-\eta_{t}\lambda$ 保持在 0 到 1 之间。超出这一范围会翻转或放大参数，不能再称为常规 weight decay。

从实现角度看，也可能写成：

~~~text
theta = theta - lr * weight_decay * theta
theta = theta - lr * adaptive_update
~~~

只要二者都使用更新前的 $\theta$ 并遵守同一数值语义，顺序差异通常只是实现细节；但自定义 optimizer 时应明确检查，不能凭名称推测。

### 6.4.3 AdamW 为什么成为强基线

AdamW 的优势不是某个单独公式，而是一套成熟组合：

1. 对不同参数尺度进行自适应更新。
2. 使用动量减少局部噪声。
3. weight decay 的含义相对清楚。
4. 与 warmup、cosine decay、gradient clipping 配合广泛。
5. PyTorch、Transformers、分布式训练框架和 checkpoint 工具支持充分。

这解释了为什么新的优化器通常应该先和 AdamW 做公平比较。强基线不是永远最好，而是为新方法提供稳定且可复现的参照系。

AdamW 的独立衰减有一个容易忽略的行为：即使本步数据梯度为 0，只要 $\eta_{t}>0$ 且 $\lambda>0$，参数仍乘以 $1-\eta_{t}\lambda$。例如 $\theta=10$、 $\eta=0.01$、 $\lambda=0.1$ 时，一步后是 $10(0.999)=9.99$。现实训练同时有 adaptive update，所以这一步只用于单独观察 decay；它说明 decay 是每个 optimizer step 都执行的参数规则，而不是某个 batch 里才出现的 loss 项。累计收缩留到第 15 节计算。

当学习率降到 0 时，按 AdamW 形式该步不产生梯度位移，也不产生 decay；若一个实现把衰减按固定系数独立于学习率执行，数学行为就不同。weight decay 和 L2 正则在经典 SGD 下的等价还假定一致的损失尺度与更新时序；若每个 batch 的 loss 分母变化， $\lambda$ 相对数据梯度的实际比例也可能变化。要复现某个设置，应连同 loss reduction、梯度累积、decay 排除规则和学习率调用顺序一起记录。

AdamW 也不是一个只由名字决定的单一行为。是否 fused、是否 capturable、bias correction、AMSGrad、 $\epsilon$ 位置、状态 dtype 和参数组都可能改变数值路径；固定版本的官方 API 文档能说明接口，却不能证明特定 GPU kernel 的性能。章节中用于推导的公式是明确的 AdamW 语义，工程实验还须把接口参数和实现版本填全。

还要避免重复施加正则。如果 loss 已显式加入 $\lambda\|\theta\|^2/2$，同时 optimizer 又配置了 AdamW weight decay，参数同时受到耦合项和独立收缩；这可能是刻意设计，也可能是配置重复。检查训练脚本时搜索 loss 中的正则项、optimizer 的 weight_decay 字段和自定义 post-step hooks，按参数组确认每一项作用一次且单位一致。

实现顺序也应写进实验配置。经典 AdamW 语义是在本步使用参数 $\theta_{t}$ 计算自适应方向，并以同一个旧参数施加衰减，最后得到 $\theta_{t+1}$；若自定义代码先用新参数值计算 decay，或 scheduler 在错误时点推进，实际使用的 $\eta_{t}$ 可能偏移一格。对一维例子列出 step、旧参数、LR、adaptive update、decay factor 和新参数，可快速发现这类 off-by-one；大规模训练则用日志记录实际 LR 与 update norm 来确认。

### 6.4.4 Adam 与 AdamW 的最小反例

设参数 $\theta=8$、梯度 $g=1$、 $\beta_{1}=0.9$、 $\beta_{2}=0.95$，第一步偏置修正后自适应更新接近 1。若学习率 $\eta=0.1$、weight decay $\lambda=0.1$：

- AdamW 先把参数乘以 $1-0.1\times0.1$，得到 7.92，再减去约 0.1 的自适应更新，结果约为 7.82；
- 耦合 L2 的梯度是 $1+0.1\times8=1.8$。第一步偏置修正后， $\hat m=1.8$、 $\hat v=1.8^2$，所以自适应更新仍约为 1，参数结果约为 7.90。

结果相差约 0.08，正好对应 AdamW 的独立收缩量。这个标量例子里耦合 L2 的自适应项恰好归一化成梯度符号；更一般的张量会按每个坐标的历史矩分别缩放，差异不会只表现成一次固定的衰减差。

上面的两坐标例子把方向翻转显示出来。这里取 $\beta_{1}=\beta_{2}=0$ 只是为了手算透明；使用非零动量和二阶状态时，耦合 L2 对梯度历史的影响还会继续积累。

所以“L2 正则”和“decoupled weight decay”即使使用相同的 $\lambda$ 字段，也不代表每坐标受到同样的力。若目标是惩罚损失中的参数范数，需说明采用耦合正则还是 AdamW 式解耦衰减；若目标是复现某个训练 recipe，还要记录 optimizer 版本、衰减时序、排除的参数组与学习率调度。AdamW 的强基线地位来自成熟的实现和大量使用经验，不能把“广泛采用”误写为在任何目标上必然最优。

数学上，AdamW 的每步独立收缩是 $\theta\leftarrow(1-\eta\lambda)\theta$。当 $\eta\lambda$ 很小时，累计收缩近似由所有 $\eta_{t}\lambda$ 的和决定；因此同一 weight_decay 字段在不同总步数或 schedule 下可能产生不同参数范数。第 15 节将对此作定量分析。

两步轨迹能显示耦合 L2 的影响会留在状态里。设 $\theta_{0}=1$、 $\lambda=0.1$、 $\eta=0.01$、 $\beta_{1}=0.9$、 $\beta_{2}=0.99$，忽略极小 $\epsilon$，先令数据梯度 $g_{1}=0$，第二步令 $g_{2}=-0.1$。AdamW 第一步只把参数衰减到 0.999， $m,v$ 仍为零；第二步使用数据梯度得到约 $-0.7425$ 的校正方向，参数约为 1.0054。耦合 L2 第一步把 $0.1\theta$ 写进状态，参数约到 0.99；第二步的总梯度约为 $-0.001$，但第一步留下的正动量仍主导，校正方向约为 $+0.664$，参数约到 0.9834。数值刻意构造，只为隔离“正则梯度也进入历史状态”这一机制，不代表常见训练轨迹。

## 6.5 优化器状态的显存、精度和分布方式

先用一个 1B 参数的模型列账：若权重和梯度各用 BF16，一阶矩、二阶矩和 master weight 各用 FP32，那么持久张量合计约 $16\times10^9$ bytes，即 16 GB 或约 14.9 GiB；其中 Adam 的 $m,v$ 两份状态就占 8 GB。这个估算还没算激活和临时缓冲，但已经能看出为什么大模型会先遇到状态显存压力。

### 6.5.1 一个粗略的训练显存公式

设：

- $b_{w}$ 是权重每元素字节数；
- $b_{g}$ 是梯度每元素字节数；
- $b_{m}$、 $b_{v}$ 是一阶和二阶状态字节数；
- $b_{\mathrm{master}}$ 是可选 master weight 字节数。

忽略激活和临时缓冲区时：

~~~math
M_{\mathrm{persistent}}
\approx
P
(b_{w}+b_{g}+b_{m}+b_{v}+b_{\mathrm{master}})
~~~

例如，权重和梯度用 BF16，m/v 用 FP32，另存 FP32 master weight 时，粗略账本是：

~~~text
weight:        2P bytes
gradient:      2P bytes
first moment:  4P bytes
second moment: 4P bytes
master weight: 4P bytes
total:        16P bytes
~~~

实际框架可能把梯度保留在 FP16/BF16，也可能在 optimizer 内部维护 FP32 参数；分片和 fused kernel 还会改变峰值。账本的价值是先发现量级错误，再用 profiler 验证峰值。

### 6.5.2 状态放在哪里

有四种常见手段：

| 手段 | 改变的对象 | 典型代价 |
| --- | --- | --- |
| data/model sharding | 状态的设备归属 | 通信与实现复杂度 |
| CPU/NVMe offload | 状态的存储介质 | 带宽与延迟 |
| 8-bit optimizer state | 状态的精度 | 量化误差与校准 |
| factored/low-rank state | 状态的结构或子空间 | 近似误差与额外逻辑 |

少用显存必须同时说明是降低了总字节数、降低了单卡峰值，还是把状态移动到了别处。否则一个 offload 方案可能被错误宣传成优化器本身更省状态。

### 6.5.3 状态精度也会改变轨迹

如果 m/v 从 FP32 换成低比特表示，内存下降并不意味着计算完全等价。量化误差会进入下一步的自适应分母和动量，长时间积累后可能影响 loss、梯度范数和最终能力。

因此，比较状态精度时至少记录：

~~~text
state dtype
quantization scale or block size
dequantization location
overflow / saturation count
optimizer step time
validation loss and task metrics
~~~

实际分片后单卡占用会下降，但全局状态总量并未因此消失；offload 只是把它移到另一种存储介质。若激活占了 80% 峰值显存，即使把 optimizer state 减半，训练仍可能 OOM；需要用显存时间线区分持久状态、forward/backward 峰值、通信 buffer 与碎片。

估算时要区分三个容量口径：所有 rank 合计保存的逻辑状态、单 rank 的常驻状态、某个 optimizer step 瞬间的峰值。参数分片改变后两项，不一定改变第一项；offload 能降低 accelerator 常驻内存，却可能增加 PCIe/NVLink 传输；低比特状态减少每元素字节数，却增加 scale 元数据和量化误差；低秩状态减少状态形状，却要存投影基并支付刷新开销。先列出每个张量的 shape、dtype、owner 和生命周期，再用 profiler 对实际峰值做校验，才能把“优化器更省显存”说清楚。

例如刚才的 1B 参数例子中，Adam 的两个 FP32 状态合计 8GB；理想地均匀切给 8 个 rank，每个 rank 约驻留 1GB（约 0.93 GiB），但此估算没有包括 replicated 参数、梯度 all-gather、reduce-scatter buffer 和临时工作区。若 profiler 观察到 step 前常驻约 1GB、反向传播峰值却达到 40GB，瓶颈就不在 optimizer state；若初始化 optimizer 的瞬间直接超过显存，则优先核对 state dtype、分片策略和是否意外保留完整 master copy。

状态量化的节省也应单独列账。把两个状态都从 FP32 改为 BF16，理论上从每参数 8 bytes 降到 4 bytes；但块尺度、scale 元数据、对齐填充、累积精度和临时反量化 buffer 会让实测比例不同。连续训练中，小量化误差可能改变二阶分母和参数更新方向，因此必须同时跟踪验证损失、update RMS、溢出/饱和比例与恢复结果。内存估算提出候选方案，只有实际 profiler 与质量实验才能回答它是否解决了当前瓶颈。

状态 dtype 的比较还要说明哪些数据类型被改变。FP32 master weight、BF16 model weight、FP32 gradient accumulation 和 FP32 optimizer state 是可能并存的不同张量；“混合精度”不是一个能替代逐项账本的配置名。优化器融合 kernel 还可能在内部临时把低精度状态升为 FP32，因此要区分常驻字节和峰值临时字节。

可再用一个简化量化账本估算 8-bit 状态的上限。Adam 的两份 FP32 状态是每参数 8 bytes；若每个状态值压到 1 byte，理想主体只剩 2 bytes/参数，表面上省去 75%。真实块量化还要存每块的 scale/offset，可能保留高精度主状态或临时反量化缓冲；小张量的元数据占比尤其大。因此“状态压到 8-bit”不能直接换算成“训练峰值显存减少 75%”，需要按设备峰值和模型其他张量分别测量。

## 6.6 Adafactor：用分解统计降低二阶状态

### 6.6.1 从逐元素二阶矩到行列统计

先看一个 $2\times3$ 的梯度矩阵：

~~~math
G=\begin{bmatrix}
1&2&3\\
2&1&2
\end{bmatrix}
~~~

逐元素平方后得到，其中 $\odot$ 表示逐元素乘法：

~~~math
G\odot G=\begin{bmatrix}
1&4&9\\
4&1&4
\end{bmatrix}
~~~

把每行、每列的平方值分别求平均，得到 $r=[14/3,3]$、 $c=[5/2,5/2,13/2]$。Adafactor 用这两组较短的统计近似恢复每个坐标的二阶尺度，因而存的是“行和列各一份”，不是原矩阵里六个独立的平方梯度。

对于形状为 $r\times c$ 的矩阵参数 $W$，Adam 的二阶状态需要保存 $rc$ 个元素。Adafactor 对二阶矩使用行列统计的近似。原论文的推导不是把矩阵做一次截断 SVD，而是利用平方梯度非负这一点，用秩一非负矩阵去拟合二阶矩；行统计和列统计可以分别做指数平滑，再按总量归一化重构。

令梯度为 $G_{t}$，逐元素平方为 $G_{t}^2$。可以维护：

~~~math
r_{t}
=
\beta_{2} r_{t-1}
+
(1-\beta_{2})
\mathrm{rowmean}(G_{t}^2)
~~~

~~~math
c_{t}
=
\beta_{2} c_{t-1}
+
(1-\beta_{2})
\mathrm{colmean}(G_{t}^2)
~~~

再用行列统计重构近似二阶矩：

~~~math
\tilde V_{t,ij}
\approx
\frac{r_{t,i}c_{t,j}}{\mathrm{mean}(r_{t})}
\cdot\frac{1}{1-\beta_{2}^t}
~~~

这里将乘法与偏置修正写成一行： $\tilde V_{t,ij}\approx [r_{t,i}c_{t,j}/\mathrm{mean}(r_{t})]/(1-\beta_{2}^t)$。当所有行统计为零时，不应执行 $0/0$，而应将重构二阶量按零处理，再由更新分母中的 $\epsilon$ 保持有限。这里采用行均值和列均值记号，所以分母用行统计的均值；若改用原论文的行和、列和，等价形式是“行和乘列和，再除以所有矩阵元素平方的总和”。不同实现可能在向量分支、 $\epsilon$ 和裁剪位置上有差异。关键思想是把 $rc$ 个状态元素换成大约 $r+c$ 个统计元素。[原论文算法明确包含二阶矩偏置修正](https://arxiv.org/html/1804.04235#S3)：

~~~math
S_{\mathrm{Adam}}
=
rc,
\qquad
S_{\mathrm{factored}}
\approx
r+c
~~~

为便于手算，令 $\beta_{2}=0$，所以当前统计就是上面的行列均值；六个平方值的总均值是 $23/6$。重构的左上元素为 $(14/3)(5/2)/(23/6)=70/23\approx3.04$，右下元素为 $3(13/2)/(23/6)=117/23\approx5.09$。这些是近似二阶量，不是原矩阵的逐元素平方；Adafactor 用它们的平方根缩放梯度。行列边际统计能补出坐标尺度，却无法保留矩阵中所有局部差异。

这个例子还说明“状态更少”并不等于“更新完全不变”。完整二阶矩中 $G^2_{12}=4$，因子化值约为 $(14/3)(5/2)/(23/6)=70/23\approx3.04$；后续 $G/\sqrt{\tilde V}$ 的分母和坐标步长就会变化。对 $4096\times11008$ 矩阵，存两个 FP32 完整二阶状态约需 $360,710,144$ bytes；行列统计约为 $60,416$ bytes，未计额外状态和临时张量。矩阵边长增大时，状态项数从乘积降到和；但小矩阵、向量和标量通常另走未因子化分支，实际节省应按参数形状逐组统计。行列统计还共享同一行、同一列内的尺度信号：一个异常值会影响相交的两个统计，因此应观察因子化与完整二阶统计的验证差异，而不能把近似看成无损压缩。

当矩阵两边都很大时，节省明显；对向量、标量或很小的张量，则未必值得采用分解表示。

沿用前面的矩阵，若只看 $G_{12}=2$，因子化二阶量约为 $70/23\approx3.04$，于是忽略 $\epsilon$ 的预条件更新约为 $2/\sqrt{3.04}\approx1.15$；完整 Adam 在同一时刻若二阶量为 $G_{12}^2=4$，更新幅度则是 $2/\sqrt{4}=1$。因子化不仅改变内存，也改变该坐标的实际步长。扩大矩阵时行列边际平均会共享更多坐标，近似的统计收益和局部尺度误差会同时存在；因此应按矩阵形状、层类型和训练阶段检查更新差异。

上式假设 $r,c$ 都是正整数，行列统计本身有限；直接使用重构式时还需 $\mathrm{mean}(r_{t})>0$，否则走前文的零状态保护分支。得到 $\tilde V_{t}$ 后，基本自适应方向是 $G_{t}/(\sqrt{\tilde V_{t}}+\epsilon)$；是否再乘一阶动量、使用 relative step、按参数 RMS 缩放或按更新 RMS clipping，取决于采用的 Adafactor recipe。原论文的算法把因子化 accumulator 与这些更新选择分开描述，因此“使用 Adafactor”并不足以唯一确定更新规则。

对 $4096\times11008$ 的矩阵，完整 Adam 二阶状态有 $45,088,768$ 个 FP32 元素，因子化行列统计只有 $15,104$ 个，状态项数约少 2,988 倍。这个比值仅说明两个状态数组的大小，不表示总训练显存按同样倍数下降：参数、梯度、master weight、临时重构和激活仍在。读者应把“状态项数压缩比”和“单卡峰值显存节省比例”分成两个指标。

从渐近式看，方阵 $N\times N$ 的一个 Adam 二阶统计需 $N^2$ 个值，行列方案需约 $2N$ 个，状态项数比约为 $N/2$；长方阵则用 $mn/(m+n)$ 估计该比值。这个比值随矩阵边长增大而上升，但若一侧很短，收益会减弱；而且该式只比较一个二阶状态数组，Adam 的两个状态、Adafactor 可选的一阶状态和其他模型张量都要另列。

向量参数是一个关键边界。若把长度为 4096 的向量想象成 $4096\times1$ 矩阵，行列状态数约为 $4096+1=4097$，与逐元素保存 4096 个二阶值几乎一样多；因子化没有实质节省，还多了边际统计处理。因此实现通常对向量保留未因子化的二阶状态，或按库规定走另一套分支。embedding、bias、norm scale 和矩阵投影层的形状组成不同，整体状态收益要用逐参数组统计，而不能拿一个大矩阵的压缩比乘全模型参数量。

参数尺度相关步长的直觉是：同样的绝对位移对范数为 0.01 的参数块和范数为 100 的参数块影响不同。相对步长按参数块的 RMS 等尺度量重新定义更新大小，因此启用后学习率含义与固定绝对步长不同；若又使用 warmup、update clipping 或外部 scheduler，需记录每个量的计算顺序和实际值。原论文的 WMT recipe 把这些机制配在一起；框架用户应以自己的版本文档为准，不能将某一篇论文的 relative step 默认当作所有 Adafactor 实现都开启。

### 6.6.2 原始 recipe 的其他部分

Adafactor 不只是把 Adam 的 $v_{t}$ 换成行列统计。原始论文还讨论了相对 step size、参数尺度、更新裁剪、逐渐增大的二阶衰减，并实验了去掉一阶动量以进一步减少状态；保留一阶矩也可以，但会重新增加一份与参数同形状的状态。某个框架中的 Adafactor 若开启 relative step 或 scale parameter，不应直接和固定 learning rate 的 AdamW 进行不加说明的比较。论文的低存储 Transformer 结果由这些设计与其 WMT 训练 recipe 一起得到，不能只归因于 factorization。[原论文的 update clipping 直接约束预条件后的更新 RMS](https://arxiv.org/html/1804.04235#S6)，它和反向传播后裁剪 raw gradient 的位置及被限制对象不同。

读者可用一条数值链检查这个区别。设某个坐标的梯度为 $g=2$，当前二阶估计为 $v=4$， $\epsilon$ 忽略，则预条件更新 $u=g/\sqrt v=1$。若 raw gradient clipping 阈值为 $0.5$，先把梯度缩成 $0.5$，在二阶估计固定为 4 时更新方向变为 $0.25$；若 Adafactor update clipping 的 RMS 阈值为 $0.5$，先得到 $u=1$，再把更新方向缩成 $0.5$。差异来自两个阈值作用于不同量和不同阶段。原论文用 update clipping 处理自适应缩放后仍可能过大的步子，这不意味着它可替代通用的梯度异常排查。

初学者可以先把它理解为降低二阶状态显存的近似优化器。工程师需要进一步记录：

1. 是否使用 factored 二阶状态。
2. 是否使用 relative step。
3. 是否使用 warmup 初始化。
4. 是否保存额外的一阶状态。
5. 向量参数走哪条分支。
6. 与 AdamW 比较时是否固定 token 预算和评估频率。

### 6.6.3 它适合解决什么问题

Adafactor 的主要收益是显存，不是自动获得更高质量。它适合：

- optimizer state 成为单卡瓶颈；
- 矩阵参数占比高；
- 可以接受近似二阶统计；
- 训练框架已经提供稳定实现。

若训练主要受激活显存、通信或数据加载限制，换 Adafactor 可能不会改善端到端吞吐。状态节省必须放回完整资源账本中判断。

## 6.7 Lion：只保留动量、用符号决定方向

### 6.7.1 更新结构

用两个坐标先看 Lion 如何决定方向。若旧动量为 $m_{t-1}=(0.2,-0.1)$、当前梯度为 $g_{t}=(0.4,-0.3)$、 $\beta_{1}=0.9$，本步方向中间量是 $c_{t}=(0.22,-0.12)$，所以 sign 方向为 $(+1,-1)$。用 $\beta_{2}=0.99$ 写入下一步的动量后， $m_{t}=(0.202,-0.102)$。符号把幅度差异丢掉了，但旧动量仍会影响方向。

Lion 由符号动量更新得到。用 $m_{t}$ 表示保存的动量，一种常见写法是：

~~~math
c_{t}
=
\beta_{1}m_{t-1}
+
(1-\beta_{1})g_{t}
~~~

~~~math
\theta_{t+1}
=
\theta_{t}
-
\eta_{t}
\left[
\mathrm{sign}(c_{t})
+
\lambda\theta_{t}
\right]
~~~

~~~math
m_{t}
=
\beta_{2}m_{t-1}
+
(1-\beta_{2})g_{t}
~~~

这里 $c_{t}$ 是决定当前方向的中间量， $m_{t}$ 是下一步使用的动量状态。式中的 $\lambda\theta_{t}$ 是解耦权重衰减项：把括号展开可得 $\theta_{t+1}=(1-\eta_{t}\lambda)\theta_{t}-\eta_{t}\mathrm{sign}(c_{t})$，它不参与 $c_{t}$ 或 $m_{t}$ 的计算。不同代码可能把 weight decay 的位置或系数写法略作调整，阅读实现时必须看完整更新。

与 Adam 相比，Lion 不保存逐元素二阶矩，因此持久状态少一个 P 量级。代价是每个坐标的更新方向被压成 +1 或 -1，更新幅度的控制更多落在学习率和参数分组上。

把方向用于参数更新时，还要加上独立衰减。若 $\theta_{t}=(2,-1)$、 $\eta=0.01$、 $\lambda=0.1$，衰减因子为 $0.999$，因此 $\theta_{t+1}=(1.988,-0.989)$。两个坐标的符号方向幅度相同，参数变化仍因原参数和衰减项而不同。

### 6.7.2 为什么不能照搬 AdamW 学习率

Adam 的更新通常会除以平方根二阶矩，坐标间幅度经过自适应缩放；Lion 的 sign 更新让每个坐标的基础幅度近似相同。因此同一个 lr 不代表同一个参数位移。

Lion 论文报告了需要更小学习率、通常更大 weight decay 的经验趋势，并报告了在多个视觉和语言任务上的实验结果；论文给出的约 3—10 倍差异来自其特定调参，不是可直接套用的换算公式。论文还观察到其 ImageNet ViT 结果偏好较大 batch，但小 batch 下仍能训练；这不能外推为 LLM 上一定需要超大 batch。[Lion 原论文的超参说明](https://arxiv.org/html/2302.06675#S5)把更高的 decay 系数与较小的学习率联系到相近的有效衰减强度。换用 Lion 时，应重新搜索：

~~~text
peak learning rate
weight decay
beta1 and beta2
warmup length
gradient clipping
parameter groups
~~~

### 6.7.3 适用边界

Lion 的状态节省在大模型中有吸引力，但它不自动解决：

- 激活显存；
- 通信瓶颈；
- 数据质量问题；
- 学习率单位错位；
- checkpoint 恢复；
- 某个任务的泛化差异。

状态更少应当与 tokens/sec、峰值显存、达到同一验证指标所需 token 数和最终任务指标一起报告。

符号方向的几何代价可以按参数维度估算。若一层有一百万个非零梯度坐标，Lion 的 sign 向量每个坐标都是 $+1$ 或 $-1$，其 L2 范数就是 $\sqrt{10^6}=1000$；若一个对照优化器在同一假设下每坐标的 RMS 更新只有 0.1，整个向量范数约为 $0.1\sqrt{10^6}=100$。两者使用相同学习率时，Lion 产生的总更新量级可能大很多。这里的 0.1 是为了说明几何关系的教学假设，不是 AdamW 或 Lion 的实测统计；实际应直接记录每组参数的 update RMS，而不要从方法名推断大小。

这种“每坐标近似等幅”的方向也会丢掉梯度幅度差异。例如两个坐标梯度分别为 100 和 0.001，只要符号相同，符号更新会给出相同方向和幅度；Adam 的二阶矩则可能将不同历史尺度纳入分母。若某坐标长期处在接近零的带噪区域，梯度符号可能频繁翻转，batch、数据顺序和动量更新就会影响实际方向。因而评估 Lion 时应同时扫 learning rate 和 weight decay，并检查 batch-size 条件、梯度方向稳定性和目标能力切片。

衰减强度的第一近似还说明了为什么两个超参要联动。设 AdamW 的 $\eta=0.001,\lambda=0.03$，每步乘子为 $1-0.00003$；若 Lion 使用 $\eta=0.0001,\lambda=0.3$，乘子也相同。两组配置每一步的 decoupled shrinkage 相等，但它们的符号更新幅度相差十倍，训练轨迹不会因此等价。论文给出的 3—10 倍学习率和衰减比例是搜索经验，只说明调参时需要一起考虑，不应把乘积相同当作两种优化器的公平性证明。

移植到框架前，逐项核对公式顺序：先用当前梯度和旧动量计算符号方向，再按另一组系数更新要保存的动量，随后对参数施加 decoupled decay 并应用学习率。若把动量状态更新移到方向计算之前，当前方向就会使用另一种插值，算法已经不同。fused implementation 应通过小张量手算、state_dict 检查和与基准实现的差分来确认，而不能只凭 optimizer 类名认定等价。

用字节数估算状态收益。若模型有 $P=10^9$ 个参数且 Adam 的一阶、二阶状态都用 FP32，二者共 $8P=8$ GB；若 Lion 只保存一份 FP32 momentum，则约 $4P=4$ GB，理论上少 4GB 的持久状态。这个差值不含权重、梯度、主权重副本、对齐、分片和量化元数据，因此不等于单卡峰值恰好下降 4GB；若激活本来占主导，减少这部分状态可能仍不足以改变可训练序列长度。

sign 运算减少了逐元素平方、平方根和二阶状态读写，但是否提升 step time 要看 kernel 融合、内存带宽、参数组和通信。若矩阵在每个 optimizer step 都要从内存读取梯度、动量和权重，实际吞吐可能被访存而不是平方根算子限制；若 Lion 需要更小学习率导致更多更新，最终 wall-clock 也可能增加。实验报告应区分 optimizer kernel latency、tokens/sec、time-to-target-loss 和最终能力。

Lion 适合作为一个改变了更新方向和状态预算的候选，不是“省一份状态就必然更快”的替换按钮。先确认目标设备的 memory footprint 是否确由 optimizer state 限制，再在同一模型、数据、token batch 和质量门槛下给 AdamW 与 Lion 相同的调参预算；若只在某一视觉 benchmark 或某个 batch 设置观察到优势，应把结论限定在该实验范围。

符号函数在精确零点的实现也应核对。数学记号通常规定 $\mathrm{sign}(0)=0$；若自定义代码用条件表达式把“非负”都映成 $+1$，零梯度坐标就会被持续推动。对低精度训练，数值下溢可能把很小的梯度变为零，所以零点行为、momentum dtype 和 overflow 路径都可能影响长期轨迹。验证实现时用正值、负值、零值和很小的有限值做手算用例，确认符号与状态更新约定。

动量还会让 Lion 的方向不总跟随当前梯度。若旧动量 $m_{t-1}=0.2$、本步梯度 $g_{t}=-1$、 $\beta_{1}=0.9$，方向中间量是 $c_{t}=0.9(0.2)+0.1(-1)=0.08$，仍为正，所以本步参数继续向负方向移动；若保存动量使用 $\beta_{2}=0.99$，新状态是 $m_{t}=0.188$。这不是符号实现错误，而是两套系数分别控制“本步方向”和“下步状态”的结果。发生数据切换后，需同时看当前梯度符号、 $c_{t}$ 符号和动量状态，才知道更新是否还沿着旧方向。

若一个向量有 $d$ 个非零坐标，逐坐标 sign 的 L2 范数正好是 $\sqrt d$，与原始梯度的数值大小无关；稀疏向量则按非零坐标数计算。比如同为 10,000 个非零值，坐标幅度全为 $10^{-4}$ 或全为 $10^2$，sign 向量范数都为 100。此性质使学习率直接控制近似每坐标位移，却也让小幅噪声在动量符号稳定时仍可能产生持续移动，故应按层观察 sign 翻转率与更新 RMS。

超参数分工也体现在状态时序： $\beta_{1}$ 参与中间量 $c_{t}$，因而直接影响本步 sign 是否翻转； $\beta_{2}$ 主要决定写入的 $m_{t}$ 会在未来保留多久。若只扫 $\beta_{2}$，当前方向在旧动量和梯度不变时可能相同，但后续一串方向会改变；只看本步 loss 选择系数，会漏掉这种延迟作用。应检查连续窗口内的 sign 翻转率、动量范数和 update RMS，并把它们与验证指标一起读。

## 6.8 Sophia：让轻量曲率信息参与更新

### 6.8.1 为什么想用二阶信息

看一个二次损失 $L(x,y)=\frac12(100x^2+y^2)$，在 $(1,1)$ 处梯度是 $(100,1)$，对角曲率是 $(100,1)$。教学时暂令动量 $m$ 等于梯度、曲率估计 $h$ 等于真实对角曲率、 $\gamma=1$，并忽略 $\epsilon$；两个坐标的预条件比例于是都是 1。若把第一坐标曲率改成 1000 而梯度暂时不变，它的比例就降为 0.1。Sophia 想利用这样的局部曲率差异，避免所有坐标都只按同一套梯度尺度前进。

一阶梯度只告诉我们当前斜率。若某个方向的曲率很大，沿该方向走得太远容易振荡；若曲率很小，步子又可能太保守。完整 Hessian 是：

~~~math
H(\theta)
=
\nabla_{\theta}^2 L(\theta)
~~~

但完整 Hessian 的存储和计算都不可接受。Sophia 的思路是用低成本的对角 Hessian 估计作为预条件器，并用裁剪控制非凸训练中的极端更新。

### 6.8.2 教学形式

Sophia 不是把完整 Hessian 放进 Adam 分母，而是维护逐元素的一阶动量和对角曲率估计。论文给出两种估计路线：

| 估计器 | 怎样取得曲率信息 | 优点与代价 |
| --- | --- | --- |
| Sophia-H | Hutchinson 估计量 $z\odot(Hz)$；通过 Hessian-vector product 估计 Hessian 对角线，理论上无偏，但随机方差可能较大 | 不依赖交叉熵特定结构；需要额外 Hessian-vector product |
| Sophia-G | 对交叉熵使用 Gauss-Newton-Bartlett（GNB）估计；从模型分布采样标签，估计 Gauss-Newton 对角线 | 对角估计非负；只近似 Hessian 的 Gauss-Newton 部分，属于有偏 Hessian 估计 |

两个估计器的误差性质不同，不能把它们都概括成“算一个 Hessian”。Hutchinson 估计器的直觉可以用一个 $2\times2$ Hessian 看清。令 Hessian 为：

~~~math
H=\begin{bmatrix}
4&1\\
1&2
\end{bmatrix}
~~~

抽取 Rademacher 向量 $z=(1,1)$，得到 $z\odot(Hz)=(5,3)$；抽取 $z=(1,-1)$，得到 $z\odot(Hz)=(3,1)$。两次样本平均是 $(4,2)$，正好等于 $H$ 的对角线。一般情况下，若各坐标独立取 $\pm1$ 且均值为零、平方为 1，则交叉项在期望中抵消，留下对角元素；有限次抽样仍有噪声，而且每个估计要涉及 Hessian-vector product。这里的两次样本只演示估计量，不代表真实网络只需两次计算。

Sophia-G 利用交叉熵结构从模型输出分布抽样标签，构造 Gauss–Newton–Bartlett（GNB）对角估计；这样估出来的对角量非负，但它只代表指定近似的曲率部分。Sophia-H 可以用于更广义的损失，却有随机估计方差，也可能得到负的 Hessian 对角元素。估计器选择不是“一个更准确”的排序，而是依赖目标函数、计算预算与稳定性偏好的路线选择。

对角估计按间隔 $k$ 步刷新，其间沿用最近状态；论文在 LLM 实验里用 $k=10$，并用一阶动量平滑曲率噪声：

以下按论文伪代码的时间索引书写，并设初始值 $h_{1-k}=0$，这样第一次在 $t=1$ 刷新时 $h_{t-k}$ 有定义；其他代码也可能用从 0 或 $k$ 开始的计数，只要刷新间隔和初值一致，不能混用两种索引。

~~~math
m_{t}
=
\beta_{1}m_{t-1}
+
(1-\beta_{1})g_{t}
~~~

~~~math
h_{t}
=
\begin{cases}
\beta_{2} h_{t-k}+(1-\beta_{2})\hat h_{t},
& t \bmod k = 1,\\
h_{t-1},
& \text{otherwise}.
\end{cases}
~~~

其中 $\hat h_{t}$ 是当前步的随机对角估计， $h_{t}$ 是跨刷新周期平滑后的估计。再做带正分母下界的预条件和逐坐标裁剪：

~~~math
u_{t}
=
\mathrm{clip}
\left(
\frac{m_{t}}{\max(\gamma h_{t},\epsilon)},
1
\right)
~~~

这里 $\mathrm{clip}(x,1)$ 表示逐坐标截到 $[-1,1]$； $\gamma>0$ 控制曲率预条件的尺度以及多少坐标触发裁剪， $\epsilon>0$ 是分母下界。最后更新参数：

~~~math
\theta_{t+1}
=
\theta_{t}-\eta_{t} u_{t}
~~~

为突出曲率预条件，上式先省略 weight decay；Sophia 原伪代码还会对参数施加独立衰减 $\theta_{t}\leftarrow(1-\eta_{t}\lambda)\theta_{t}$，之后再做曲率方向更新，衰减不进入 $m_{t}$ 或 $h_{t}$。[Sophia 原算法](https://arxiv.org/html/2305.14342#S2.SS2)中包含该步骤。前面的数值例均取 $\lambda=0$，只隔离曲率与 clipping 的作用；真实复现还需记录 decay 值、参数排除规则和执行顺序。

例如某个坐标 $m_{t}=0.04$、 $h_{t}=2$、 $\gamma=0.1$ 且 $\epsilon$ 可忽略时，裁剪前方向为 $0.04/(0.1\times2)=0.2$，更新为 $-0.2\eta_{t}$；若 $m_{t}=0.4$，裁剪前为 2，实际方向截到 1。若某个 $h_{t}<0$，分母下界会把它替换成 $\epsilon$；当 $|m_{t}|\geq\epsilon$ 时，裁剪后成为符号方向，若 $|m_{t}|<\epsilon$ 则仍可能未饱和。这是算法的回退行为，不应把负曲率直接除进去。

原论文会调 $\gamma$，使未触发裁剪的坐标比例大致落在 10%—50%；也就是说，约 50%—90% 的坐标会被截断。其 GPT 实验中 Sophia-H 用 $\gamma=0.01$，Sophia-G 用 $\gamma=0.05$；论文在该系列实验中使用 $k=10$，并报告这在计算开销与收敛速度间取得折中。这些数值依赖模型、数据和 estimator，不是推荐默认值。[论文明确把未裁剪坐标比例作为调节目标](https://arxiv.org/html/2305.14342#S3)，真实实现还要规定 label/样本采样、估计器刷新频率、状态精度、weight decay、并行同步和 checkpoint 恢复。

每隔 $k$ 步刷新意味着曲率状态并非每步都来自当前参数。若 $k=10$，一次刷新之后接下来的若干次参数更新都使用上一份 $h$；如果训练刚好处在数据分布切换、强学习率变化或异常 batch 之后，这份估计可能短时过期。缩短 $k$ 会增加曲率估计调用频率，延长 $k$ 能摊薄额外计算，却让预条件器更新更慢。公平实验应测量实际估计耗时和达到目标验证损失的总时间，而非只看一轮 optimizer update 的理论开销。

增大 $\gamma$ 会放大分母、压低裁剪前的比例，通常让更少坐标触发裁剪；减小它则相反。调 $\gamma$ 时应固定其他超参，并记录未裁剪比例、loss、gradient norm 和曲率估计分布，否则裁剪比例变化无法解释。

在章首的二次例子里，高曲率坐标的比例变小、低曲率坐标仍可前进。真实 Sophia 还含随机估计、动量、刷新间隔和非凸损失；这个直觉例子不构成收敛保证。

Hutchinson 方法只需要计算 $Hz$，无需显式构造庞大的 Hessian 矩阵；自动微分可沿向量方向计算 Hessian-vector product，但它仍需要额外前向/反向工作与临时激活。曲率每 $k$ 步刷新时，若单次估计成本是一次常规反向成本的比例 $q$，在稳定区间内均匀摊销后，每个 update 的平均额外成本约为 $q/k$；这个关系只是计算预算账本，真实 kernel、checkpointing 和通信都可能改变 $q$。论文报告的开销必须按其实现与测量口径理解，项目应实测每次估计和总达标时间。

Sophia 相比 AdamW 改变的是预条件信息，不是简单地把 Adam 的 $v_{t}$ 换成 Hessian。 $v_{t}$ 是梯度平方的历史尺度估计，始终非负；Sophia-H 的 Hessian 对角估计可能为负，Sophia-G 则在其近似下给出非负对角量。负值经过 $\max(\gamma h,\epsilon)$ 会落到 $\epsilon$ 下界，再交由裁剪限制最大方向；这一保护可能让更新变成近似 sign step，但不能让坏曲率估计消失。排查时要同时看 $h$ 的正负比例、 $\epsilon$ 命中率、裁剪比例和刷新间隔，不能只记录最后的 loss。

Sophia 的边界条件至少包括 $0\leq\beta_{1},\beta_{2}<1$、 $\gamma>0$、 $\epsilon>0$ 和正整数刷新间隔 $k$。当估计值是 NaN/Inf、状态陈旧或刷新失败时，训练代码仍须显式检查，不能依靠裁剪掩盖非有限数。

估计成本可按刷新间隔先做一笔粗账。假设一次曲率估计额外耗时相当于普通反向的 0.4 倍， $k=10$ 时均摊约为每步 4%；若改为每 2 步刷新，则约为 20%。这只是将估计调用均摊到稳定区间的近似，没有计入缓存、通信和重计算；真正比较仍要记录实测估计耗时及达到相同验证目标的总墙钟时间。

### 6.8.3 证据应如何表述

[Sophia 原论文](https://arxiv.org/abs/2305.14342)用 OpenWebText 训练 GPT-2 125M—770M、用 The Pile 训练 GPT-NeoX 1.5B 和 6.6B；主要对照采用余弦衰减、2,000 步 warmup、梯度范数阈值 1.0，并每 10 步更新一次曲率估计。论文报告在这些配置下，Sophia 达到相同验证损失所需 steps、总计算量和墙钟时间约为 AdamW 的一半；单步额外计算低于 5%。但估计器样本数不同，超参在 30M 模型上调节后迁移，峰值学习率另行搜索，结论仍是作者实验而非独立复现。

要在项目中验证 Sophia，至少需要：

1. 同一个模型和 tokenizer。
2. 对照达到相同验证目标所需的 tokens、FLOPs 和墙钟时间，而不只比较 step 数。
3. 同一精度和并行配置。
4. 预先固定的验证集与评估频率。
5. 记录 Hessian 估计额外耗时。
6. 记录达到同一质量所需的 steps、tokens、FLOPs 和墙钟时间。

## 6.9 Muon：把矩阵参数当作矩阵来更新

### 6.9.1 元素视角与矩阵视角

Muon 的核心变化可先用 $G=\mathrm{diag}(9,1)$ 看出来。普通梯度更新保留 9:1 的两个方向幅度；若取极分解方向，polar factor 是单位矩阵 $I$，两条非零奇异方向就变成相同幅度。它可能减少矩阵方向间的尺度差异，也会丢掉原梯度的幅度比例。

AdamW 通常把矩阵 W 的每一个元素视作一个坐标，分别维护动量和二阶统计。Muon 类路线的出发点不同：隐藏层的二维权重本身代表一个线性变换，更新方向可能需要考虑矩阵整体的谱结构。

设矩阵梯度或动量矩阵为 G。它的奇异值分解为：

~~~math
G
=
U\Sigma V^\top
~~~

其 polar factor 可以写为：

~~~math
\mathrm{polar}(G)
=
UV^\top
~~~

设 $G$ 的秩为 $r$，它的紧致奇异值分解为：

~~~math
G=U_{r}\Sigma_{r}V_{r}^\top
~~~

其中 $U_{r}$ 和 $V_{r}$ 只保留非零奇异值对应的列， $\Sigma_{r}$ 是由这些非零奇异值构成的 $r\times r$ 对角矩阵。polar 因子是部分等距映射 $U_{r}V_{r}^\top$。它在 $G$ 的有效子空间上有定义；若把它扩展成完整的正交矩阵，秩亏部分的补空间选择才会不唯一。零矩阵的部分 polar 因子是零方向。这个因子保留左右奇异向量的方向结构，同时去掉非零奇异值的尺度差异。Muon 的公开实现路线通常用 Newton-Schulz 一类迭代近似这类正交化方向，而不在每一步做完整 SVD。

例如，取下面的秩一矩阵：

~~~math
G=\begin{bmatrix}
3&0\\
0&0
\end{bmatrix}
~~~

它的紧致 SVD 只有一个非零奇异值，左、右奇异向量都为 $(1,0)^\top$，因此部分 polar 因子为：

~~~math
O=\begin{bmatrix}
1&0\\
0&0
\end{bmatrix}
~~~

这个 $O$ 不是任意指定的完整 $2\times2$ 正交矩阵。再取：

~~~math
W=\begin{bmatrix}
1&2\\
0&1
\end{bmatrix}
~~~

若 $\eta=0.01,\;\lambda=0.1$ 且暂取 $s(W)=1$，则一次示意更新为：

~~~math
W'=0.999W-0.01O=
\begin{bmatrix}
0.989&1.998\\
0&0.999
\end{bmatrix}
~~~

实际 Muon 的正交化是对动量矩阵进行，随后还要按矩阵形状缩放；这里把 $O$ 当作已算出的方向，重点是分离方向、全局尺度与衰减三部分。

若取 $\eta=0.01$，上例的原始梯度更新为 $(0.09,0.01)$，polar 方向更新为 $(0.01,0.01)$。Muon 不是“把 AdamW 算得更精确”，而是换了更新几何。

Newton-Schulz 迭代用矩阵乘法构造多项式近似来把奇异值推向 polar 目标区间，避免每步对大型矩阵完整做 SVD。输入缩放、系数、迭代次数和转置布局会影响稳定区间与近似误差；若矩阵元素尺度超出实现假设，迭代可能数值不稳定。大模型实现还需测试低精度矩阵乘、非连续张量、矩阵分片和通信同步。算子“只迭代几次”不保证计算便宜，必须测真实 kernel 的耗时与显存。

从一个常见的动量版本看，Muon 的主路径可以写成：

~~~math
M_{t}=\beta M_{t-1}+(1-\beta)G_{t},\qquad
O_{t}\approx\mathrm{polar}(M_{t})
~~~

~~~math
W_{t+1}
=(1-\eta_{t}\lambda)W_{t}-\eta_{t} s(W)\,O_{t}
~~~

这里 $G_{t}$ 是矩阵梯度， $M_{t}$ 是同形状动量， $s(W)$ 是依参数形状、模型规模和实现而定的更新缩放。Newton-Schulz 通过矩阵多项式迭代逼近 polar factor；系数、迭代步数和缩放方式属于实现的一部分。不同代码可以有不同版本，不能只凭 “Muon” 名称假定更新范数相同。

形状缩放为什么重要，可以把 Moonshot 报告的理论关系代入两个尺寸。对满秩 $A\times B$ 矩阵，其定义下的 Muon update RMS 约为 $\sqrt{1/\max(A,B)}$；对 $2\times3$ 矩阵是 $1/\sqrt{3}\approx0.577$，对 $256\times1024$ 矩阵是 $1/\sqrt{1024}=0.03125$，相差约 18.5 倍。若两种形状直接共享同一个学习率，层间有效更新尺度可能大幅不同。该报告进一步观察到 AdamW update RMS 常在 0.2—0.4，并在其设置中校准 Muon 尺度以便参数组共享部分超参；这些是论文定义和测量下的参考，不是每个实现的固定常数。[Moonshot 报告的 update RMS 分析](https://arxiv.org/html/2502.16982#S2)说明了缩放和参数分工的来源。

同一缩放式也让转置形状的关系更直观： $2\times4$ 和 $4\times2$ 的满秩矩阵都给出 RMS $1/\sqrt{4}=0.5$，因为公式由较长边控制； $4\times4$ 则是 $1/2=0.5$，而 $4\times16$ 降到 $1/4=0.25$。这些数值依据特定缩放定义，不等于实际每层更新的实测 RMS，因为动量、正交化近似、参数尺度、decay 与混合参数组仍会进入最终轨迹。日志里的实测值应与这个理论量级逐层核对，而不是被公式取代。

上述 RMS 关系明确以满秩矩阵为前提。若矩阵秩为 $r<\min(A,B)$，polar 方向只有 $r$ 个非零奇异方向，非零元素密度和 Frobenius 范数会随有效秩改变；此时不能把满秩参考值当作该层的目标 update RMS。做实现对照时可一并记录矩阵 shape、估计有效秩与正交化后的 RMS，分辨偏差来自缩放公式、近似迭代还是本身的秩结构。

### 6.9.2 为什么通常需要参数分组

矩阵正交化适合二维 hidden weight，并不天然适合：

- LayerNorm 或 RMSNorm 的一维 scale；
- bias；
- embedding；
- 输出 head；
- 标量或小向量参数。

因此一种常见结构是：

~~~text
hidden matrix weights -> Muon-like update
norm / bias / embedding / head -> AdamW or a dedicated rule
~~~

这不是所有实现的唯一方案，但它解释了为什么不能只把 optimizer 名称改成 Muon 就结束。参数筛选、矩阵方向约定、学习率缩放、weight decay 和分布式同步都是算法的一部分。

### 6.9.3 矩阵几何路线的分工与公开证据

Muon 用动量方向的正交化处理合适的矩阵参数；相邻的 Shampoo/SOAP 路线则维护矩阵统计。Shampoo 累积左右两侧的梯度协方差并施加矩阵预条件；SOAP 追踪协方差特征基，在该基中做 Adam 式逐元素更新，再旋回原空间。它们都利用矩阵坐标间的相关性，但状态、分解/正交化成本和分布式实现不同。

Muon 的结果也依赖更新尺度和参数分工。[Moonshot 技术报告](https://arxiv.org/abs/2502.16982)观察到 Muon 更新 RMS 随矩阵形状变化，因而对不同矩阵做形状缩放，并将 AdamW 用于 embedding、LM head、RMSNorm 等非矩阵参数；在其 399M—1.5B Llama 架构 scaling experiments 中，作者报告 compute-optimal 对照约用 AdamW 52% 的训练 FLOPs 达到相近损失。报告中的 Moonlight MoE 有约 2.24B 激活参数、15.29B 总参数，训练 5.7T tokens。上述比例与模型结果均是特定数据、模型、scale 法和评估下的作者报告。

后续研究说明这些倍率不能当作 Muon 的固有属性。[ICLR 2026 optimizer 系统比较](https://proceedings.iclr.cc/paper_files/paper/2026/file/ea4f0a6ad7088c9b93f22d74c0c9e8c2-Paper-Conference.pdf)在 C4 英文验证集、Llama-2 架构和约 0.13B—1.2B 模型上，对多种 optimizer 分别调参，并比较 1—8 倍 Chinchilla 数据预算。论文主要按达到相同验证 loss 所需 tokens 衡量；在 1.2B、8 倍预算下，矩阵方法的报告优势约为 1.1×。该指标不是端到端墙钟时间，论文以既有实现研究说明矩阵变换额外开销有机会控制在约 10%，并未将该开销直接计入主要 token 效率指标。中途 checkpoint 的排名也可能在学习率衰减时翻转。另一项 [NeurIPS 2025 研究](https://proceedings.neurips.cc/paper_files/paper/2025/file/bdcd9f6327db5877dee502cdec183159-Paper-Conference.pdf)在 190M—1.4B Llama 模型、FineWeb、1024 context 和约 0.12M token batch 下，采用 μP 学习率迁移与按模型宽度缩放的独立 weight decay，报告 Muon、SOAP、Shampoo 约 1.4× compute multiplier。该计算量只计前向与反向 FLOPs，不计 optimizer transform；错误缩放会明显削弱收益。两项实验的架构、数据、预算、调参方式和度量不同，不能把倍率拼成一个排行榜。

2026 年 [NVIDIA 报告](https://arxiv.org/html/2607.20548)覆盖 8B dense、30B-A3B 和 72B-A8B MoE。论文摘要称其 batch 扫描最高达到 100M tokens；标准对照配置为 3,072 个、每个 8,192-token 的序列，约 25M tokens，72B Figure 2 中 Muon 的大 batch 对照是基线的两倍，即约 50M tokens。作者在这些具体设置中报告 Muon 与经稳定性修正的 SOAP 比 AdamW 更能维持大 batch 下的训练稳定性和 token 效率。报告把矩阵分片、层间分布、通信重叠和 optimizer kernel 纳入实现；SOAP 的实验还采用逐步特征基更新及协方差修正来处理 loss spike。结论仍限于公开模型、数据、学习率缩放、WSD schedule、Megatron 实现与评测，不能外推为所有 MoE 或任意 100M batch 都会得到相同结果。

比较这些路线时，至少同时报告实际进入各 optimizer 的参数、矩阵形状、update RMS、学习率/weight decay 缩放、optimizer state、矩阵统计或 Newton-Schulz 的耗时、通信量、tokens/秒和达到目标质量的 tokens/FLOPs/时间。Muon/SOAP 不会因为“每步更快”或论文中“compute-optimal 更省”就自动成为 AdamW 的通用替代品。

## 6.10 GaLore：降低状态维度，而不是冻结参数

### 6.10.1 它解决的不同问题

用一个 $2\times2$ 梯度看投影过程：

~~~math
G=\begin{bmatrix}
1&2\\
3&4
\end{bmatrix}
~~~

只取左基 $P=(1,0)^\top$ 和右基 $Q=(0,1)^\top$，压缩后的核心梯度是 $C=P^TGQ=2$；若暂把 optimizer 变换 $\rho$ 当作恒等映射，映回原空间得到：

~~~math
PCQ^T=\begin{bmatrix}
0&2\\
0&0
\end{bmatrix}
~~~

这一步只保留“第一行、第二列”这个方向，其他梯度分量都没有进入本次更新。

LoRA 通过增加低秩可训练矩阵、冻结原始权重来减少可训练参数。GaLore 的目标不同：它允许全参数学习，但把梯度和 optimizer state 投影到低秩子空间，以降低状态内存。

设矩阵梯度为 $G_{t}\in\mathbb{R}^{m\times n}$。原论文使用左右两个投影基： $P_{t}\in\mathbb{R}^{m\times r}$、 $Q_{t}\in\mathbb{R}^{n\times r}$，其中：

~~~math
P_{t}^\top P_{t}=I_{r},
\qquad
Q_{t}^\top Q_{t}=I_{r},
\qquad
r\ll\min(m,n)
~~~

列正交约束使每组基向量代表一个不重复的投影方向；实际实现通过 SVD 或近似分解周期性地构造/更新这些基。

先把梯度压到一个 $r\times r$ 的核心矩阵：

~~~math
C_{t}=P_{t}^\top G_{t}Q_{t}
~~~

在这个低秩坐标中应用 optimizer 变换 $\rho_{t}$，例如对核心矩阵维护 Adam 的动量和二阶状态，再映回原矩阵空间：

~~~math
\widehat G_{t}=P_{t}\rho_{t}(C_{t})Q_{t}^\top
~~~

投影基可以随训练刷新。正式方法是双侧投影 $P_{t}^\top G_{t}Q_{t}$；单侧投影 $G_{t}P_{t}$ 只能作为另一个明确标注的简化变体，不能代替 [GaLore 原论文的双侧定义](https://arxiv.org/html/2403.03507#S3.SS3)。

真实算法会在训练中刷新左右子空间，且 $\rho$ 内会更新低秩状态，因此一次投影的秩一形态不意味着模型权重永久被限制成秩一。反过来说，每一步被投影的方向确实与完整梯度不同，所以要用目标验证集检查 rank、刷新频率和任务能力的影响。

基方向改变会改变同一个低维坐标在原矩阵里的含义。仍用 $G=\mathrm{diag}(1,0)$：旧的 $P=Q=(1,0)^\top$ 投影并映回后得到：

~~~math
\begin{bmatrix}
1&0\\
0&0
\end{bmatrix}
~~~

若新基改成 $P=Q=(1,1)^\top/\sqrt{2}$，核心值变成 $1/2$，映回结果是：

~~~math
\begin{bmatrix}
1/4&1/4\\
1/4&1/4
\end{bmatrix}
~~~

因此 rank 相同也不代表方向相同。刷新投影基时，低维动量、二阶状态如何重映射或重置必须遵循所用实现的定义；不能仅因状态张量 shape 未变就认定其语义连续。

rank 选择可从一个小 SVD 例子建立诊断量。若某步梯度的奇异值为 $4,1,0.1$，rank-1 截断保留的平方能量比例是 $16/(16+1+0.01)\approx94.1\%$，rank-2 则约为 $17/17.01\approx99.94\%$。这只是对单个梯度矩阵最佳 Frobenius 低秩逼近的参考；GaLore 的双侧子空间、状态变换和后续训练不等同于每一步直接做同一截断。它可以帮助设候选 rank，但仍要比较更新残差、下游能力和显存/分解时间。

不同层的谱衰减速度可能不同：即使两个矩阵 shape 相同，一个的 rank-1 能量覆盖达到 94%，另一个可能只有 70%。给全模型固定同一 rank 便于实现和比较，却不保证每组参数的梯度近似误差相同；按层分配 rank 能把状态预算给更难压缩的矩阵，但会增加配置和 checkpoint 管理复杂度。应先从代表性层与训练阶段抽样测能量曲线，再决定统一 rank 或分组 rank，并把这项搜索也纳入公平预算。

rank 是压缩率与方向误差之间的旋钮，不是越大越接近“无代价”的版本。增大 $r$ 会让核心状态按 $r^2$ 增长、投影基按 $(m+n)r$ 增长；若 rank 接近短边，因子化节省会逐渐消失。比较时应把每个候选的状态字节和分解耗时都列出，再看同一 token 预算下质量是否值得这笔额外开销。

状态规模随 rank 变化，可以把“降低状态”与“免费”区分开来。取 $m=4096,n=11008,r=128$，完整矩阵有 $mn=45,088,768$ 个元素，Adam 的两个 FP32 状态约需 $90,177,536\times4=360,710,144$ bytes（约 344 MiB）。低秩核心若仍使用两个 FP32 Adam 状态，只需 $2r^2=32,768$ 个值，即 131,072 bytes；但是左右基共有 $(m+n)r=1,933,312$ 个值，若以 FP32 保存约 7.37 MiB，另有分解临时量、完整梯度、参数和通信缓冲。这个教学算例只比较优化器状态和投影基，不是对真实训练峰值的预测；正式报告要把基与临时量分开计，不能把核心状态比率直接叫总训练显存比率。

若 rank 翻倍到 256，核心状态元素会变为原来的 4 倍，而投影基元素翻倍；更高 rank 可保留更多梯度方向，却增加状态与投影成本。刷新过稀时，基难以跟踪训练梯度子空间；刷新过密时，SVD 或近似分解会变成额外热点。要决定某个 rank 是否值得，至少画 rank/refresh 频率对应的验证 loss 与能力、GPU 峰值、分解耗时、tokens/sec 和达标总 token。

这些投影基通常由当前梯度矩阵的主导奇异方向或论文指定的低秩子空间构造，具体刷新间隔属于算法配置。训练目标、batch 分布或梯度子空间变化后，旧基可能不再覆盖主要更新方向；频繁重算能跟踪变化，却会增加矩阵分解开销。基切换时，低秩坐标的第 $i$ 个动量值对应的方向可能已经改变，因此实现需要遵守该算法的状态更新/映射规则；只把一份旧动量数组留在同一索引位置，未必仍代表同一参数空间方向。

LoRA 与 GaLore 的“低秩”落在不同对象上。LoRA 令权重变化受固定低秩乘积参数化约束，原始预训练权重通常冻结；GaLore 保留完整 $W\in\mathbb{R}^{m\times n}$ 参数，只把当前梯度和 optimizer state 放进低秩坐标，参数仍由映回后的矩阵增量更新。因为基会随训练变化，多个不同子空间的增量可以累计到完整权重中；但每一步的可用方向仍被 rank 和投影基近似限制。由此它减的是状态压力，不会自动带来 LoRA 那样更少的可训练参数或反向计算。

GaLore 的理论低秩动机依赖训练梯度在一定阶段呈现低 stable-rank 结构；原论文还在 Transformer 的部分权重梯度上给出分析。这个性质不表示任意模型、任意初始化、任意 batch 或整个训练阶段的梯度都低秩。实际 rank 选择应看奇异值谱或子空间能量覆盖、更新残差、验证 loss 和下游能力；若低秩近似误差随训练阶段上升，应考虑提高 rank 或提高刷新频率，而不是只报告初始几个 step 的显存压缩比。

因此，GaLore 适用的前提是 optimizer state 确实是内存瓶颈、梯度矩阵有可利用的低秩结构，并且投影/刷新成本低于获得的训练收益。若激活是瓶颈，GaLore 可能不解决 OOM；若矩阵规模小，投影基元数据可能抵消状态节省；若 rank 太低，更新方向质量可能变差。论文在 LLaMA/C4 下的 memory 与性能数据只能作为候选方案入口，目标模型仍需公平对照 AdamW、Adafactor 或低比特状态基线。

### 6.10.2 GaLore、LoRA 和 Adafactor 的区别

| 方法 | 主要改变 | 原参数是否全量更新 | 主要节省 |
| --- | --- | --- | --- |
| LoRA | 参数化方式 | 通常不更新原权重 | 可训练参数和状态 |
| Adafactor | 二阶状态结构 | 是 | 二阶状态 |
| GaLore | 梯度/state 所在子空间 | 是 | optimizer state |
| 8-bit optimizer | 状态数值表示 | 是 | 每个状态元素字节数 |

它们可以组合，但组合后的内存和质量不能由各自宣传数字简单相加。

### 6.10.3 论文数字应该绑定条件

GaLore 论文报告了在 LLaMA 1B/7B 架构、C4 数据和最多 19.7B token 的预训练设置下，optimizer-state memory 最多下降 65.5%；8-bit GaLore 的状态与总训练内存数字还绑定 BF16 baseline 和特定测量条件。论文也报告了在单张 24GB RTX 4090 上预训练 7B 的可行性，但该案例不能解释成“任意 7B 配方都能直接放进 24GB 卡”。正文引用这些数字时必须保留模型、数据、精度、序列长度和是否使用激活检查点/offload 等条件。

验证 GaLore 时还要测：

- 投影基刷新开销；
- rank 对 loss 和能力的影响；
- 单卡峰值显存与总集群显存；
- 与 LoRA、Adafactor、AdamW 的公平 baseline；
- 恢复 checkpoint 后投影基是否连续。

## 6.11 参数分组：不是每个张量都应使用同一规则

### 6.11.1 常见分组

设一个小模型只有 $W_{q}\in\mathbb{R}^{64\times64}$、 $b_{q}\in\mathbb{R}^{64}$、 $w_{\mathrm{norm}}\in\mathbb{R}^{64}$ 和 $E\in\mathbb{R}^{32\times64}$；输出头与 $E$ 共享同一个参数对象。若它们都可训练，独立元素数是 $4096+64+64+2048=6272$，不能把 tied head 再计一次。共享权重也只能进入一个 optimizer group，接受一次梯度更新和一次 decay。

一个教学策略可以把 $W_{q}$ 交给 Muon，把其余参数交给 AdamW；norm、bias 设零 decay，embedding 单独设定 decay。这里没有推荐具体超参，只演示分组要同时决定“哪个优化器、哪个学习率、是否衰减”。若按名字看到 `weight` 就加 decay，norm scale 可能被错分；若把共享输出头再次建组，参数就会被重复更新。

大模型训练通常把参数划分为多个 optimizer group：

~~~math
\Theta
=
\Theta_{\mathrm{matrix}}
\bigsqcup
\Theta_{\mathrm{norm}}
\bigsqcup
\Theta_{\mathrm{bias}}
\bigsqcup
\Theta_{\mathrm{embed}}
\bigsqcup
\Theta_{\mathrm{adapter}}
~~~

这里的 $\bigsqcup$ 表示对同一轮更新而言，每个可训练 Parameter 对象恰好归入一个组；共享 embedding/head 是同一个对象，不是两个应分别衰减的参数。

常见起点是：

| 参数类型 | 常见处理 | 原因 |
| --- | --- | --- |
| attention/MLP 矩阵 | AdamW 或 Muon，使用 decay | 主体线性变换 |
| norm scale | 不 decay 或单独 decay | 控制激活尺度 |
| bias | 通常不 decay | 维度小且语义不同 |
| embedding | 单独观察或单独学习率 | 词表和表示尺度特殊 |
| output head | 视是否 tied、任务和规模决定 | 可能与 embedding 共享 |
| LoRA A/B | 单独学习率和 decay | 参数尺度与全参不同 |

通常不 decay 是 recipe 经验，不是数学定律。若一个项目对 norm 施加 decay，也应通过消融和参数范数曲线说明影响，而不是把经验规则当作绝对约束。

### 6.11.2 参数分组的实现陷阱

分组应是按 Parameter 对象建立的互斥、穷尽映射： $p\mapsto(\mathrm{optimizer},\eta_{p},\lambda_{p},\mathrm{state\ dtype})$。共享权重只进入一个组，冻结参数不进入可更新组；恢复时还要保持组结构、顺序和超参。只看参数名不够：`weight` 可能命中矩阵、norm、embedding 或 tied head，包装层也会改变名称。

启动前按模块类型、对象身份和真实 shape 生成组清单，检查每个可训练对象恰好出现一次、未分类对象为空、空组符合预期，并核对组元素总数与框架的 trainable count。只对元素总数求和不能发现“一处重复、一处遗漏”相互抵消的情况。新增层、adapter、冻结规则或包装方式后都要重新审计；同时记录每组的对象数、元素量、shape/dtype、optimizer、LR、decay 和梯度范数。

分组会直接改变更新。若 AdamW 组中 $\theta=(1,-2)$、adaptive update $u=(-1,1)$、$\eta=0.01$、$\lambda=0.1$，则 $\theta'=(0.999,-1.998)-0.01(-1,1)=(1.009,-2.008)$；同一更新放入零 decay 组会得到 $(1.01,-2.01)$。只记一个全局 `weight_decay` 无法还原各组实际规则。

混合 Muon 与 AdamW 时，分组还决定哪些矩阵进入矩阵更新、哪些 embedding/norm/head 使用另一规则。若它们由两个 optimizer 实例更新，应共用同一全局更新时钟和 scheduler 计数；一组因 overflow 被跳过而另一组继续 step，会使状态对应到不同的数据位置。日志应能发现某组 step 没有随全局 step 前进。

## 6.12 Warmup：让训练从小步开始

### 6.12.1 线性 warmup

取峰值学习率 $\eta_{\max}=0.008$，warmup 长度 $T_{w}=4$ 步，并约定第一个更新用 $t=1$。四步学习率为 $0.002,0.004,0.006,0.008$。若每步消费 1M 个有效目标 token，峰值在累计 4M 个目标后到达；batch 加倍且仍按 4 steps 计时，则要消费 8M 个目标。这个例子先说明 warmup 的计时单位会随 batch 改变。

训练初期，模型参数、动量和二阶统计都处于初始化阶段。直接使用 peak learning rate 可能造成 loss spike。线性 warmup 在 $0\le t\le T_{w}$ 内使用：

~~~math
\eta_{t}
=
\eta_{\max}
\frac{t}{T_{w}}
~~~

t 必须明确是 optimizer step。若第一个更新使用 $t=1$，学习率为 $\eta_{\max}/T_{w}$；若实现从 $t=0$ 记录日志，打印出来的首项可能是 0，但未必真的执行了 0 学习率的更新。

公式要求 $T_{w}>0$。完整调度中， $T$ 是正的总 optimizer steps， $0\le T_{w}\lt T$； $T_{w}=0$ 时应明确跳过 warmup，第一步进入后续阶段。

按 steps 定义适合固定更新次数的实验，按 token 定义更适合比较每次更新 batch 不同的方案；配置和日志必须写清楚用的是哪一个单位。

Adam 的偏置修正与 warmup 解决不同问题。偏置修正把从零初始化的 $m,v$ 转换为较少初始偏差的估计；warmup 则限制参数每一步的有效更新尺度。即便第一步 $\hat m$ 和 $\hat v$ 已修正，若 $\eta$ 过大，参数仍可能沿高曲率方向走得过远；反过来，有 warmup 也不能弥补 step 计数错位或非有限梯度。观察时把 learning rate、update norm、gradient norm、loss spike 和 clipping ratio 放在同一时间轴上，才能分辨是调度尺度问题还是数据/数值异常。

warmup 不是由模型名称单独决定的开关。Xiong 等人的 mean-field 分析和实验发现，在论文所研究的设置中，Pre-LN 初始化较平稳、可移除 warmup，而 Post-LN 更容易在大步长下不稳定。[原论文的架构和假设](https://arxiv.org/abs/2002.04745v2)限制了外推范围。另一项小规模 GPT 研究在修改更新归一化方式后减少或消除 warmup，[也不能直接推出生产规模模型可照搬](https://arxiv.org/abs/2410.23922)。是否保留 warmup，应由目标模型、初始化、optimizer、batch 和精度下的稳定性实验决定。

### 6.12.2 warmup 的长度不是固定比例

1% 到 5% 可作为试验起点，不是固定配方。长度会受以下因素影响：

- 模型规模和初始化；
- peak learning rate；
- global token batch；
- 数据质量和序列长度；
- optimizer 的状态初始化；
- 从 checkpoint 继续训练还是重新开始；
- 预训练、持续训练还是 SFT。

warmup 太短可能出现早期 loss 或更新范数突增；太长则让较多训练预算停留在小步阶段。比较长度时固定模型、数据顺序、batch 和精度，并同步看学习率、loss、梯度/更新范数、参数范数与裁剪比例。

### 6.12.3 恢复训练时的 warmup

如果 checkpoint 在 warmup 中间保存，scheduler 应从原来的 $t$ 继续。重新从 0 warmup，或直接跳到 peak lr，都会改变后续轨迹。

以刚才 4-step warmup 为例，若在 step 2 保存，恢复后 step 3 应继续用 $0.006$，而不是重新用 $0.002$，也不是直接从 $0.008$ 起跑。恢复对照要同时检查 scheduler step、optimizer step、数据 cursor 和随机状态。若只是从一个已经预训练好的模型开始新的持续预训练，是否重启 warmup 是新的训练设计决策；它不等于恢复旧 run，应该另建 run ID 并把新阶段的 optimizer/scheduler 状态明确记录。

长度对照应固定 optimizer、有效 token batch、总 token 预算和其余超参，比较早期曲线与最终质量。报告“2% warmup”时还要给出分母是 optimizer steps 还是 consumed tokens，否则无法复现。

warmup 缩放参数更新，不会自动缩小反向梯度或冻结 optimizer state。对 AdamW，首步偏置修正后方向可能已接近梯度符号；从 $0.008$ 起步与 4-step warmup 的 $0.002$ 起步，位移尺度可相差约四倍。若以 `lr=0` 调用 `optimizer.step`，参数可能不动而 $m,v$ 仍更新，具体取决于实现和调用顺序。

它的代价是早期小步可能推迟达到目标更新尺度；潜在收益是缓和随机初始化、重置的 moment、增大 batch 或混合精度下的早期更新。spike 若紧贴 warmup 结束点，可检查峰值 LR；若出现在数据切换点，延长 warmup 可能只会推迟暴露问题。做因果对照时固定数据顺序、batch、初始化和精度。

warmup 以 steps 还是 tokens 计时，是训练预算选择。若每步有效目标从 256K 增至 1M，固定 500 steps 会把到达峰值所需的 token 暴露扩大约四倍；固定 token 暴露则应按新 batch 换算 steps。报告中须写明所选时钟。

warmup 只能逐步提高更新尺度，不能使不稳定的峰值变稳定。对教学二次目标 $L(x)=50x^2$，梯度下降误差乘子为 $1-100\eta$： $\eta=0.01$ 一步到零点， $\eta=0.03$ 则乘子为 $-2$，误差每步变号并扩大一倍。warmup 升到 $0.03$ 只会把发散推迟到峰值附近；峰值仍须在目标配置上验证。

排查时按固定 token 窗口对齐 warmup 前后，比较 raw gradient norm、optimizer update norm、裁剪比例、有效目标数和验证 loss。梯度稳定而 update norm 随 LR 上升时突增，应查峰值、状态初始化和参数组；梯度本身在数据切换或目标数下降时变大，则优先查数据与 loss 分母。

对不同层也可以看相对更新 $\|\Delta\theta\|/(\|\theta\|+\epsilon)$，而不是只看全局 LR。相同的 warmup 曲线若配不同 optimizer、参数分组或初始化，可能对应不同的层级相对步幅；某一层在 warmup 后突然放大时，应先检查该层的有效 LR、状态和 decay，再判断是否要拉长整条 warmup。这样可以避免为了单个异常组而把所有参数都置于过长的小步阶段。

例如全局 peak LR 为 0.008，但某组因参数规则额外乘了 0.1 的系数，该组的实际 LR 只有 0.0008；两组共用 warmup 时，到峰值的时间相同，实际位移尺度却可能差十倍。配置与日志应记录 scheduler 产生的基准 LR、每组缩放因子和 optimizer 真正使用的 LR，避免把“warmup 已完成”误当作所有组都已进入相同的训练强度。

## 6.13 Cosine、线性和其他衰减策略

用同一条 10-step 预算比较两种曲线。warmup 2 步， $\eta_{\max}=0.01$、 $\eta_{\min}=0.001$。在 step 4，衰减进度是 $(4-2)/(10-2)=25\%$：cosine 学习率约为 0.00868，线性约为 0.00775；到 step 8，进度是 75%，两者分别约为 0.00232 和 0.00325。它们走过相同起点和终点，中间却把更新尺度分配得不同。下面再写出两条调度规则。

### 6.13.1 Warmup 后 cosine decay

warmup 结束后，令总 optimizer steps 为 T，可以使用：

~~~math
\eta_{t}
=
\eta_{\min}
+
\frac{1}{2}
(\eta_{\max}-\eta_{\min})
\left[
1+
\cos
\left(
\pi
\frac{t-T_{w}}{T-T_{w}}
\right)
\right]
~~~

该式适用于 $T_{w}\lt t\le T$。在 $t=T_{w}$ 附近接近 peak lr，在 $t=T$ 接近 $\eta_{\min}$。

它要求 $T_{w}\lt T$，以及 $0\le\eta_{\min}\le\eta_{\max}$；若训练超过 T，必须由实现明确选择固定在 $\eta_{\mathrm{min}}$、延长稳定段，还是重新定义一条新的曲线，不能让三角函数在预算外继续摆动。

cosine 的吸引力在于平滑下降，并且后期逐渐减小更新幅度。它不是损失函数的余弦，也不保证每个任务都优于线性衰减。切换 scheduler 时，应保持训练 token 预算和 peak lr 口径不变，再比较最终指标。

### 6.13.2 线性衰减和 constant schedule

线性衰减把学习率从 peak 平滑降到目标末值：

~~~math
\eta_{t}
=
\eta_{\max}
+
(\eta_{\min}-\eta_{\max})
\frac{t-T_{w}}{T-T_{w}}
~~~

constant-with-warmup 则在 warmup 后保持 peak lr。它适合持续训练、在线数据不断增加或希望把调度交给后续阶段的场景，但长时间训练中可能需要额外的稳定性控制。

如果某个单参数在这些步里的梯度方向几乎固定且大小近似相同，较大的早期学习率通常会带来较大的早期位移；但 Adam 的真实参数变化还取决于 $m_{t},v_{t}$、 $\epsilon$、weight decay 和梯度噪声。因此学习率曲线下面积 $\sum_{t}\eta_{t}$ 只能作粗略的 schedule 账本，不能直接当成总参数位移。报告 cosine 与 linear 时应同时记录 optimizer update norm 和验证指标，避免把曲线形状相同误写成训练轨迹相同。

调度器通常只应在一次真正的 optimizer update 后推进一次。若 gradient accumulation 为 8，而调度器每个 micro-step 都调用，10-step warmup 会在两次参数更新后结束；若在最后一个 batch 未完成 accumulation 时也推进，则 scheduler 与权重更新之间再多出一个错位。可在配置中明确顺序，例如每个 optimizer step 使用当前 $\eta_{t}$ 更新参数，再将 scheduler 计数推进到下一步；也可采用框架默认调用顺序，但要用短轨迹核对首步、warmup 末步和最后一步的实际值。

### 6.13.3 调度器的边界问题

实际实现还要回答：

1. 最后一个不完整 accumulation window 算不算一个 optimizer step？
2. 训练提前停止时是否按实际 step 截断 scheduler？
3. 恢复 checkpoint 时 `last_epoch` 或内部 `step` 是多少？
4. scheduler 是在 optimizer.step() 前还是后调用？
5. 超过 $T$ 后是固定在 $\eta_{\min}$，还是继续外推？

这些问题会改变实际更新量，须通过短轨迹核对，而不是只检查 scheduler 配置。尤其要确认 scheduler 每次真正的 optimizer update 后推进一次，并在首步、warmup 末步、衰减中段和终点记录 optimizer step、scheduler step 与实际 LR。

总 token 预算和有效 batch 决定目标更新数。100B tokens、每步 1M 目标约为 100,000 updates；batch 增至 2M 后，同一数据预算只需约 50,000 updates。把旧的 $T=100{,}000$ 原样用于新 run，会使训练在预定曲线中途就耗尽 token。变长 batch 可按累计有效 token 或按 optimizer step 推进，但 warmup、decay、停止条件和 checkpoint 进度必须采用同一时钟。

总步数是 cosine 轨迹的一部分。若原计划 $T=100,T_w=10$，step 50 的衰减进度约为 $40/90=0.444$；将预算改为 $T=200$ 并重算后，同一步变为 $40/190=0.211$，在 $\eta_{\min}=0$ 时学习率会从约 $0.587\eta_{\max}$ 回升到 $0.895\eta_{\max}$。已发生的更新不会被改写，继续前须确定是接受回升、延伸原曲线，还是进入 stable 阶段后再做末端 decay，并保存新的 scheduler 分支。

warmup/decay 都有 off-by-one 风险：同一个 $T_w=2$ 可能按 step 1、2 使用 $0.5\eta_{\max}$、$\eta_{\max}$，也可能因调用顺序被记录为 step 0、1、2。还要定义训练提前停止、超过 $T$、末值 $\eta_{\min}$ 与 scheduler 恢复的行为。余弦到 0 会让最后的梯度更新和 AdamW decay 都趋近零；正末值则保留小步更新。Cosine 与线性在完整区间平均学习率相同，但中段分配不同；梯度和 optimizer state 会随时间变化，因此它们不会因此产生相同参数轨迹。

constant schedule 适合预算未知的持续训练，但没有预先定义的终点；若需要固定预算交付，可在 stable 阶段后安排 decay，或采用 WSD 分支。数据 mixture 中途改变时，不要无说明地重启 cosine：LR 会上升，而 $m,v$ 仍保留旧数据阶段的历史。若把它设计为新阶段，应保存边界 checkpoint，并说明旧 optimizer 状态是保留、转换还是重置。

## 6.14 Warmup-Stable-Decay：让调度器适应持续训练

设一条 100-step 轨迹：前 10 步 warmup，之后学习率保持 $0.01$，step 70 后用 30 步降到 $0.001$。原始 WSD 会从 step 70 的稳定主干复制一个分支做 decay；WSD-S 则把这段 decay 留在同一条训练线上，之后从冷却后的状态升回稳定学习率。两者的学习率曲线可以相似，后续恢复点却不是同一个。

### 6.14.1 三个阶段

传统 warmup + cosine 通常假定总训练长度在开始时已经确定。持续预训练和领域适配往往需要在已有模型上不断追加数据，训练者可能希望在中间扩展 stable 阶段，而不是每次重新设计完整 cosine 曲线。

Warmup-Stable-Decay（WSD）可以抽象为：

~~~math
\eta(t)
=
\begin{cases}
\eta_{\max}\dfrac{t}{T_{w}},
&0\le t\lt T_{w},\\[6pt]
\eta_{\max},
&T_{w}\le t\lt T_{s},\\[6pt]
\mathrm{Decay}
(\eta_{\max},\eta_{\min},t;T_{s},T),
&T_{s}\le t\le T.
\end{cases}
~~~

其中 $T_{s}$ 是 stable 阶段结束位置。Decay 部分可以是 cosine 或其他衰减形式。WSD 的重要特征不是某个唯一公式，而是把稳定训练作为可扩展的独立阶段。

原始 WSD 常用“主干加分支”的训练方式：warmup 后沿固定学习率的 stable 主干继续训练；需要一个候选终点时，从该主干 checkpoint 分出一份副本，只在副本上执行 decay 并评估。若还要继续 stable 训练，应回到尚未 decay 的主干状态。把 decay 后的模型误当成主干恢复点，会改变后续轨迹。

时间边界需满足 $0\le T_{w}\le T_{s}\le T$ 且 $T>0$。 $T_{w}=0$ 表示无 warmup； $T_{s}=T$ 表示这一份已知预算中尚未进入 decay。只有在这些边界被写进 checkpoint 和 scheduler state，后续扩展 stable 段才不会改变已消耗 token 的学习率历史。

### 6.14.2 它和普通 cosine 的关系

两者都可以有 warmup 和 decay。区别在于：

- cosine 通常从 warmup 后就持续衰减；
- WSD 可以在 peak lr 附近保持一段稳定区间；
- WSD 更容易把 stable 区间扩展为持续训练；
- decay 阶段可用于最后收敛或领域切换后的整理。

WSD 不是优化器，它只改变 $\eta_{t}$。如果更换了 optimizer，同时更换 WSD，最终差异就无法归因。实验中应分别设置 AdamW + cosine、AdamW + WSD 和需要比较的新 optimizer。

两种 WSD 轨迹的 checkpoint 角色可以并排理解：

| 轨迹 | decay 从哪里开始 | decay 后的 checkpoint | 若要继续训练 |
| --- | --- | --- | --- |
| 原始 WSD | 从 stable 主干复制出的候选分支 | 当前预算的评估/发布候选 | 回到未衰减的 stable 主干，继续固定 LR |
| WSD-S | 当前训练链上的中间 checkpoint | 同一条训练链的新恢复点 | 从 decay 后的权重和完整状态升回稳定 LR 继续 |

两者都可能产出相似的短程低 LR 权重，但只有第二种会把衰减历史直接带进下一段高 LR 训练；checkpoint 名称和 scheduler stage 因此必须区分。

### 6.14.3 公开资料的证据边界

[MiniCPM 论文](https://arxiv.org/abs/2404.06395)用 36M 模型比较 40N、60N、80N 数据量下的 WSD checkpoint；在这组实验中，约 10% token 的 decay 已足以达到较好结果，2.5% 则不够。它展示了“先扩展 stable 主干，再短程 decay 检查点”的用法，但不能把这个 10% 比例直接当作其他规模或语料的默认值。

WSD 的 loss 曲线常在 stable 阶段较高、进入 decay 后快速下降。2024 年的 [River Valley 研究](https://arxiv.org/abs/2410.05192)把它解释为：较大学习率让参数沿较平坦的“河谷方向”继续前进，同时在较陡方向振荡；降低学习率减小振荡后，先前累积的进展才在 loss 上显现。作者的解释依赖特定损失地形假设，不是所有 LLM 训练轨迹的定理。

[WSD-S 研究](https://arxiv.org/abs/2410.05192)进一步提出：在中间 checkpoint 上短暂 decay 后，直接恢复到较大学习率继续走同一条主干，复用前一次 cooldown，而不是每次都回滚到未 decay 的 stable checkpoint。论文在 Pile、4M token batch、0.1B—1.2B Llama 类模型和 50B/100B/200B 目标预算上，报告 WSD-S 与分别调好的 cosine run 接近，并在固定总预算时优于原始 WSD；8%—12% decay 比例的结果相近，但在 loss spike 后立即 decay 的一组实验中验证 loss 约恶化 0.02。它是特定设置下的作者实验，尤其说明选择分支点要看 spike 是否已经恢复；[实验条件和结果](https://arxiv.org/html/2410.05192#S5)不能外推为默认比例。

因此 WSD 的决策要区分两种流程：若需从同一稳定训练主干生成多个可选终点，用 WSD 的独立 decay 分支；若要以连续单次 run 逐步交付并继续训练，可评估 WSD-S，但需保存包含 scheduler/optimizer 在内的完整状态，并检查 decay 后重新升高学习率的稳定性。是否优于 cosine 取决于训练预算是否预先固定、checkpoint 分支成本、数据流是否持续、峰值学习率下的 loss 波动和目标评估；论文支持的是这些具体实验，不是对所有任务的替换建议。

若在多个 token 预算交付模型，原始 WSD 可从共享 stable 主干分别分出 decay 候选；每个分支都会增加 token 与 FLOPs 成本。比如主干训练到 100B tokens，再从 60B、80B 各运行 10B-token decay，两个候选共消耗 120B tokens 的训练量。应把 stable 主干与 decay 分支分别保存，并记录父 checkpoint、预算、scheduler 阶段和评估结果。

WSD-S 则把 decay 留在同一训练链，随后从冷却后的状态升回较高学习率继续训练；它复用 cooldown 后的权重和 optimizer 历史，但需要验证重新升高学习率时的稳定性。选择分支点前查看最近窗口的 loss 与 gradient norm；若 loss spike 尚未回落，应继续 stable，或从 spike 前状态单独试验，再决定 decay 起点。比较 WSD、WSD-S 与 cosine 时，固定或明确总 token/FLOPs 预算、目标质量和下游评估，避免只按同一步数的 loss 排序。

## 6.15 Weight decay：参数规模控制与学习率绑定

取 $\lambda=0.1$、$\eta=0.01$。无数据梯度时，AdamW 每步把参数乘以 $0.999$；连续 100 步后纯衰减部分约保留 $0.9048$，只做 50 步约保留 $0.9512$。同一个 `weight_decay` 数值会因学习率和更新次数不同而产生不同的累计收缩。

### 6.15.1 衰减强度的实际含义

AdamW 的独立衰减为：

~~~math
\theta_{t+1}
=(1-\eta_{t}\lambda_{t})\theta_{t}
-\eta_{t}u_{t}
~~~

只看 decay 时，累计保留比例是 $\prod_{t=1}^{T}(1-\eta_{t}\lambda_{t})$。当每步 $\eta_{t}\lambda_{t}$ 都很小时，可用

~~~math
s_{\mathrm{decay}}=\sum_{t=1}^{T}-\log(1-\eta_{t}\lambda_{t}),
\qquad
\prod_{t=1}^{T}(1-\eta_{t}\lambda_{t})=e^{-s_{\mathrm{decay}}}
~~~

估算累计收缩，并近似为 $s_{\mathrm{decay}}\approx\sum_t\eta_t\lambda_t$。每步要求 $0\le\eta_t\lambda_t<1$ 才保持常规收缩；若乘积不接近 1，应直接计算乘积，不用指数近似。

例如，方案 A 用 $\eta=0.01$ 连续 100 步，$\lambda=0.1$，纯衰减约保留 $0.999^{100}=0.9048$。方案 B 用相同 $\lambda$，先以 $0.01$ 运行 50 步，再以 $0.001$ 运行 50 步，约保留 $0.999^{50}\times0.9999^{50}=0.9465$。峰值学习率、步数和 `weight_decay` 字段不足以说明累计强度；还要报告实际 LR 轨迹和 optimizer steps。累计衰减只隔离参数收缩，不能单独预测含梯度更新的最终权重或模型质量。

### 6.15.2 预训练和后训练不能直接复用

预训练、SFT、LoRA 与偏好训练的数据规模、可训练参数、loss 目标和更新次数可能不同。直接复制预训练的 `weight_decay`，不代表后训练具有相同正则强度；Lion 等优化器论文也报告了需要联动重调学习率与衰减的特定配方，但这些比例不是跨优化器的通用换算。[Lion 原论文的超参实验](https://arxiv.org/html/2302.06675#S5)只支持其任务中的观察。

记录衰减配置时至少列出：

~~~text
optimizer type and implementation version
peak/final learning rate and optimizer-step count
per-group learning rate and weight decay
parameter groups and decay exclusions
per-group parameter norm and validation metrics
~~~

参数分组决定哪些参数执行独立收缩。矩阵参数可设非零 decay，而 norm/bias 常在一些 recipe 中排除；这属于训练配置而非 AdamW 的定理。零 decay 组仍可接收梯度并更新，冻结参数则不应进入可更新组，二者需分开审计。模型包含 tied embedding/head、adapter 或包装层时，应按 Parameter 对象检查分组，避免重复更新或漏掉参数。

Weight decay 不是泛化保证。比较不同衰减值或 exclusion 规则时，固定 optimizer、数据顺序、batch、scheduler 和 token 预算，只改变待测配置；在同一验证集合上观察 loss、能力切片及各参数组范数。报告每组实际使用的 LR 和 decay，避免一个全局字段掩盖不同参数的更新规则。

## 6.16 Gradient clipping：限制单次更新的异常幅度

### 6.16.1 Global norm clipping

令梯度 $g=(3,4)$，它的 L2 范数是 5。阈值 $c=2$ 时，整个向量乘 $2/5=0.4$，得到 $(1.2,1.6)$，范数正好为 2，方向保持不变。若逐元素截到 2，则得到 $(2,2)$，方向已经变了。两种裁剪限制的对象不同。

把所有参数梯度拼成向量 g，其 L2 范数为：

~~~math
\lVert g\rVert_{2}
=
\sqrt{\sum_{i} g_{i}^2}
~~~

给定阈值 c，全局裁剪为：

~~~math
g'
=
g
\cdot
\min
\left(
1,
\frac{c}{\lVert g\rVert_{2}+\epsilon}
\right)
~~~

它保持梯度方向，只在范数超过阈值时缩短向量。按参数组分别裁剪、按元素裁剪和按值裁剪则会改变方向或不同坐标的相对比例，不能把它们统称为同一种 clipping。

这里要求 $c\ge0$、 $\epsilon>0$，且参与拼接的梯度是有限值； $c=0$ 会把有限梯度全部清零，因而通常只适合测试而非训练。触发比例的分母也必须是正的已执行 optimizer steps，尚未发生过更新时该指标应记为未定义而不是 0。

### 6.16.2 混合精度中的顺序

若使用 loss scaling：

~~~text
scaled_loss = loss * scale
scaled_loss.backward()
unscale_(optimizer)
clip_grad_norm_(parameters, max_norm)
optimizer.step()
scaler.update()
~~~

裁剪必须在 unscale 后进行。否则计算出的范数包含 scale，阈值就不再代表原始梯度的阈值。

### 6.16.3 clipping ratio 是诊断信号

不要只记录裁剪后的 grad_norm。还要记录未裁剪范数和触发比例：

~~~math
r_{\mathrm{clip}}
=
\frac{
\#\{t:\lVert g_{t}\rVert_{2}>c\}
}{
\#\{\text{optimizer steps}\}
}
~~~

如果几乎每一步都被强烈裁剪，说明学习率、数据异常、loss 分母、初始化或数值精度可能有问题。裁剪可以阻止一次过大的更新，但不能修复错误的 label、未来信息泄漏或持续的学习率失配。

在语言模型训练中，梯度通常已经经过 token 平均、累积和分布式归约。若每个 micro-batch 都先单独裁剪，再把裁剪后的梯度相加，结果通常不等于先正确累积各 micro-batch 梯度、再裁剪一次；裁剪是非线性变换，操作顺序会改变方向。若使用 loss scaling，先 unscale；若使用 DDP，确认裁剪看到的是跨 rank 聚合后的完整梯度。对 FSDP/ZeRO 分片梯度，范数计算需要正确汇总所有 shard 的平方和；每个 rank 只按本地分片裁剪，会得到不同于 global norm 的算法。

把分片梯度看成一个完整向量可手算分布式全局范数。rank 0 持有片段 $(3,4)$，rank 1 持有 $(0,12)$，拼接后的范数是 $\sqrt{3^2+4^2+0^2+12^2}=13$。若阈值为 6，两个 shard 都要乘 $6/13\approx0.4615$；裁剪后全局范数才是 6。若各 rank 只在本地裁剪，rank 0 的范数 5 未触发，rank 1 的范数 12 乘 0.5，拼接范数变成 $\sqrt{25+36}\approx7.81$，仍超过 6，且两个 shard 的相对方向比例已改变。FSDP/ZeRO 的实现因此需要跨 shard 汇总平方和，再把同一个缩放系数施加到各片段。

这与 DDP 的数据副本语义不同：DDP 通常在 backward 期间把各 rank 的完整参数梯度做归约，每个副本在归约后持有相同的全梯度；若再把相同向量当作参数 shard 拼接求范数，会把范数错误乘上 rank 数的平方根。裁剪实现要明确梯度是复制还是分片、是否已经 all-reduce、reduce 使用 sum 还是 mean。只看 `max_grad_norm=1` 无法知道实际阈值作用在哪个向量上。

裁剪前先检查每个参与张量是否有限。若含 NaN，范数本身也会变成 NaN，直接按阈值公式计算 scale 可能无法按预期保护参数；Inf 也会导致信息丢失。正确处理通常是由 scaler 或训练循环发现 overflow、跳过本次更新并记录，而不是把非有限值“裁剪成阈值”。对全部梯度为零的 batch，norm 为 0、scale 应为 1；但该 batch 是否应该存在，仍要检查有效 label 数量。

裁剪比例可以转化为每个训练窗口的诊断信号。假设最近 1000 个已执行 optimizer steps 中 20 次触发阈值，则 $r_{\mathrm{clip}}=20/1000=2\%$；如果数据来源切换后升到 900/1000，且 raw norm 中位数从 0.7 升到 8，优先检查数据分布、loss 分母、scale 和学习率，而不是立即把阈值放宽到 10。阈值调整应和训练目标、更新 norm、loss 与最终能力一起评估。

梯度范数阈值和实际参数位移也不等价。Adam 会再除以二阶矩并施加 decoupled decay，Muon 会再做矩阵正交化与 shape scaling；裁剪 raw gradient 后得到的 update norm 仍需单独观测。Adafactor 原论文的 update clipping 更靠近实际参数方向，它直接限制预条件后的更新 RMS；两种机制可以同时存在，但若一起使用要分别记录阈值、触发比例和更新顺序。

因此 clipping 的时序应写成明确的状态流水线。对 FP16 梯度可先完成所有 micro-batch 的缩放梯度累积，随后 unscale、跨 rank 汇总完整梯度、计算 global norm、按统一系数裁剪、再执行 optimizer.step；BF16 通常不使用同样的 loss scaler，但仍须确认梯度有限。若框架为了通信重叠而在归约前裁剪，必须说明这是一种不同算法，并用相同实现对照。阈值也需绑定梯度归一化方式：若 loss 从按样本平均改为按有效 token 平均，raw norm 的尺度会变，沿用旧阈值可能让裁剪比例突然变化。

数值例子能显示为什么不能把 micro-batch 裁剪直接当作累积后裁剪。令两个 micro-batch 梯度分别是 $g_{1}=(3,0)$、 $g_{2}=(-2,4)$，阈值 $c=2$。先相加得到 $(1,4)$，其范数为 $\sqrt{17}$，一次裁剪后约为 $(0.485,1.940)$；若先分别裁剪， $g_{1}$ 变成 $(2,0)$， $g_{2}$ 变成约 $(-0.894,1.789)$，再相加得到约 $(1.106,1.789)$。两个结果的方向不同，因为大 batch 的正负梯度抵消只会发生在累积之后。

全局范数也可能让小层被大层“连坐”。设两组梯度范数分别为 100 和 1，全局拼接范数约 100；阈值 10 会把两组都乘约 0.1，小组范数因此降到约 0.1。若各组独立以 10 为上限，小组则保持为 1，优化方向相对比例不同。按层裁剪有时能避免大层主导，但它定义的是另一种更新规则，阈值要随层规模和任务重新验证，不能只因小组梯度变大就认为全局裁剪有误。

对 Adam 还存在一个容易误解的交互。在第一步、 $\epsilon$ 可忽略且偏置修正启用时，若整条梯度被全局裁剪乘以同一常数 $s>0$，则 $\hat m$ 乘 $s$、 $\sqrt{\hat v}$ 也乘 $s$，比值 $\hat m/\sqrt{\hat v}$ 近似不变；例如 $g=(3,4)$ 裁到范数 2 后变为 $(1.2,1.6)$，第一步 Adam 的坐标更新仍近似 $(1,1)$。这不说明 clipping 对 Adam 无用：后续历史状态、 $\epsilon$、有限精度与裁剪触发的样本都会改变轨迹；它提醒我们不能仅从“raw grad 被缩小”推断实际 Adam update 同比例缩小，应记录两种范数。

若同一例子使用 $\epsilon=0.1$，未经裁剪的第一步坐标更新约为 $(3/3.1,4/4.1)=(0.968,0.976)$；裁剪后则约为 $(1.2/1.3,1.6/1.7)=(0.923,0.941)$。此时 $\epsilon$ 已经打破了按比例缩放的抵消。训练中的 $\epsilon$ 通常另有量级，历史 $m,v$ 也不会只由当前梯度决定；这个数字只是说明裁剪、预条件和稳定项要作为一个更新链来分析，而不是孤立解释阈值。

因此 max norm 限制的是裁剪点的梯度向量长度，不是参数更新的长度。对 SGD，若 $\|g'\|=2$ 且 $\eta=0.1$，这一步的梯度更新范数是 0.2；对 Adam，逐坐标除以历史尺度后，update norm 可由参数维度、 $v_{t}$ 与 $\epsilon$ 决定，可能与 0.2 完全不同。要限制最终参数位移，应另监控 $\|\Delta\theta\|$ 或相对更新量；梯度阈值主要是异常输入保护和状态更新控制。

## 6.17 Batch scaling：学习率应跟 token 预算一起看

### 6.17.1 有效 token batch

两个 rank 的目标数不一样时，先看本地平均梯度。rank 0 有 3 个目标、平均梯度为 1；rank 1 有 1 个目标、平均梯度为 3。正确的全局 token mean 是 $(3\times1+1\times3)/4=1.5$。若先对两个 rank 等权平均，则得到 $(1+3)/2=2$，短 rank 的一个 token 被赋予了和长 rank 三个 token 一样的总权重。

有效 batch 的分母应是 loss 实际归一化的预测目标数。若每个样本输入含 $L$ 个 token，decoder-only 模型在模型内部做 causal label shift，且没有 padding 或 ignore mask，则每个样本通常只有 $L-1$ 个有效预测目标。因此等长情况下：

~~~math
B_{\mathrm{target}}
=
B_{\mathrm{micro}}
\cdot
T_{\mathrm{target}}
\cdot
A
\cdot
P_{\mathrm{dp}},
\qquad T_{\mathrm{target}}=L-1
~~~

这里 $B_{\mathrm{micro}}$ 是每张数据并行设备的 micro-batch 样本数， $A$ 是累积次数， $P_{\mathrm{dp}}$ 是数据并行设备数。若数据管线已外部 shift labels，或使用其他目标， $T_{\mathrm{target}}$ 必须按真实预测目标重新计数，不能机械地减一。只报告“每卡 2 条样本”无法说明 global batch，因为序列长度、累积次数、mask 和设备数都可能不同。

变长或有 mask 的训练应直接汇总每个 rank、每个 micro-batch 真正进入 loss 的目标数：

~~~math
B_{\mathrm{target}}
=
\sum_{r=1}^{P_{\mathrm{dp}}}
\sum_{a=1}^{A}n_{r,a}
~~~

其中 $n_{r,a}$ 按模型实际 label shift、padding 和 ignore mask 统计。最后一个不完整累积窗口、动态 padding、样本过滤或某个 rank 的空 batch 都会打破简单乘积；此时若各 rank 先独立取 token mean 再让 DDP 等权平均，短 rank 的 token 会被过度加权。梯度累积应与第五册第五章的 token-weighted 推导使用同一分母。

例如每卡每个 micro-batch 有 2 条样本、每条输入长 5，完整内部 shift 后每条有 4 个预测目标；若累积 4 次、8 个数据并行 rank，固定长度时每次 update 有 $2\times4\times4\times8=256$ 个有效目标。若其中一条样本经 padding/mask 后只有 3 个有效输入 token，它只贡献 2 个目标，而不是继续计 4 个。

### 6.17.2 线性缩放只是起点

若基线 token batch 从 $B_{1}$ 变成 $B_{2}$，线性缩放假设给出：

~~~math
\eta_{2}
\approx
\eta_{1}\frac{B_{2}}{B_{1}}
~~~

平方根缩放则是：

~~~math
\eta_{2}
\approx
\eta_{1}\sqrt{\frac{B_{2}}{B_{1}}}
~~~

两者都不是大模型训练的普遍定律。Adam 的自适应状态、梯度噪声、长序列、动态 padding、数据混合、训练 token 预算和 warmup 都会改变结论。更可靠的做法是固定模型和数据，做小规模 token-batch sweep，并记录：

~~~text
tokens per optimizer step
peak learning rate
warmup tokens or steps
gradient norm distribution
validation loss per consumed token
time to target quality
~~~

### 6.17.3 相同 steps 不等于相同训练量

两个实验都跑 10,000 optimizer steps，但一个每步消耗 1M token，另一个每步消耗 2M token，它们的训练数据量相差一倍。比较优化器时，至少要同时给出：

- optimizer steps；
- consumed tokens；
- estimated FLOPs；
- wall-clock time；
- 达到目标指标的时间和 token 数。

否则“收敛更快”可能只是每一步喂了更多数据。

再比较两种形状不同但全局目标数接近的 batch。方案 A 每个 rank 每个 micro-batch 取 2 条长度 4096 的序列，内部 causal shift 后每条有 4095 个预测目标；累积 4 次、8 个数据并行 rank，则一轮 optimizer update 有 $2\times4095\times4\times8=262,080$ 个目标。方案 B 每个 rank 取 1 条长度 8192 的序列，其余相同，得到 $1\times8191\times4\times8=262,112$ 个目标，两者只差 32 个。虽然目标 token 数近似，长序列产生不同 attention 计算、激活峰值和样本内上下文；不能只凭相同 global token batch 推断吞吐和梯度噪声也相同。

若把基线 $B_{1}=256,000$ 个目标/update、 $\eta_{1}=0.001$ 改为 $B_{2}=512,000$，线性缩放给出 $\eta_{2}=0.002$，平方根缩放给出 $\eta_{2}=0.001\sqrt{2}\approx0.001414$。这只是两个起始候选。固定 1B 个目标 token 预算时，前者约做 3,906 次更新，后者约做 1,953 次更新；梯度累积和 Adam 状态因此更新的次数减半。若 schedule 仍按原来的 3,906 steps 走，模型会在 token 预算结束前走到曲线中段；要比较相同数据曝光，应按目标 token 或实际 update 预算重新定义 schedule。

batch 越大不一定越容易优化。平均更多样本可降低某些抽样噪声，却可能改变梯度的频谱、训练阶段的更新次数与设备利用率；长上下文还会把显存压力从 optimizer state 转到 activation。做 batch sweep 时固定全局 token 预算和模型结构，分别尝试若干学习率与 warmup 候选，画出每 consumed token 的验证损失及达标时间；同时报告 gradient norm 分布、吞吐和 OOM/重试情况。若 token batch 用于训练步数定义，但 loss 分母仍按样本数或每 rank mean 计算，所谓“线性缩放”比较本身就没有共同口径。

相同总 token 预算下，batch 变大意味着 optimizer 更新次数减少。以 10B 目标 token 为例，global batch 256K 约需 39,063 次更新，1M 约需 10,000 次；如果两者都固定 500-step warmup，前者 warmup 消费约 128M token，后者约 500M token，后者在更多数据曝光后才到达峰值。即使采用线性缩放把学习率乘 4，momentum 和二阶统计仍分别只经历约四分之一的更新次数，不能认为训练轨迹按同一比例伸缩。

batch scaling 的规律依 optimizer 与目标而变。线性缩放常作为较大 batch 下的起始假设；平方根缩放是另一种保守候选；两者都需要重新扫 peak lr、warmup tokens、decay 和梯度裁剪阈值。每个候选要以同样的 token budget 训练并测验证目标，不要固定 steps 后就说大 batch 更快，因为固定 steps 会给它更多 token。若要研究系统吞吐，可以再做固定更新数的测量，但应另列为硬件吞吐实验，不能和同 token 的质量效率结果混在一列。

还要注意，大 batch 的线性缩放不是说 token-mean 梯度本身会自动变大。若 loss 已按所有有效目标取平均，扩大 batch 通常改变梯度估计的波动和 optimizer 更新次数；把 $\eta$ 乘以 batch 比例是额外的实验假设，会使每次参数位移也随之放大。以目标数翻倍为例，若平均梯度仍是 0.1，LR 从 0.001 加到 0.002 会使这一步的 SGD 位移从 $0.0001$ 变成 $0.0002$；只有当更新次数、噪声和稳定性允许时，这才可能让大 batch 的训练进度更有效，不能由“样本多一倍”直接推出。

梯度累积与单个大 batch 只有在若干条件同时满足时才近似等价：每个 micro-batch 的梯度按有效目标数加权，累积期间不调用 optimizer.step、不推进 scheduler、不更新会影响样本间计算的状态，并使用同一批样本和目标。dropout 随机流、浮点归约顺序或动态采样不同，仍可能让数值结果有差异。最容易犯的错误是先对每个 micro-batch 的 token mean 取等权平均；当各 micro-batch 有效目标数不同，这会重复 rank-mean 的偏差，应累积 token-sum 梯度并除以总有效目标数。

预算末尾的残余 batch 也会影响“相同总 token”的说法。若目标预算是 10M、每步目标 batch 为 3M，最后只剩 1M：可以按实际 token 数做一次较小的更新，也可以丢弃尾部数据，但前者的梯度噪声、学习率时钟和 clipping 统计与完整 batch 不同，后者实际只消费 9M。两个 optimizer 的处理策略必须一致并写入账本；否则名义预算相同，真正进入更新的目标数可能不同。

分布式归约的 sum/mean 约定也会改变所谓 batch 缩放。若每个 rank 累积 token-sum 梯度，再做 all-reduce sum，最后应除以全局有效目标总数；若局部先按 token 求 mean，rank 之间又做等权平均，只有各 rank 目标数相同才与全局 token mean 一致。改变数据并行 rank 数时须确认框架有没有自动除以 world size，否则梯度中隐含的 $P_{\mathrm{dp}}$ 因子可能再与学习率缩放叠加。

对变长 batch，global batch 可能每步都变化。设目标数量依次为 240K、260K、190K，则累计 3 次更新消费 690K 目标，而不是用名义的 $3\times256K=768K$ 计算；若 scheduler 按 token 推进，应累计真实目标数，若按 optimizer step 推进，则每步权重相同而 token 预算不均。两种定义都可用，但训练日志、warmup 和终止条件必须一致。动态 packing、padding 和样本过滤会让名义 sequence length 无法代表有效 token 数。

## 6.18 优化器与调度器的公平实验

假设 AdamW 用 900B tokens、吞吐 9B tokens/小时达到验证 loss 2.5，需要 100 小时；候选优化器用 750B tokens 达到同一目标，但吞吐只有 6.25B tokens/小时，需要 120 小时。候选方法少用 16.7% 的 token，却更晚交付。这个例子说明“每 token 更有效”和“墙钟更快”是两种不同结论。

### 6.18.1 先固定什么

一个可解释的比较应固定：

~~~text
model architecture and initialization
tokenizer and data order
training data and validation splits
precision and distributed topology
effective token batch
maximum consumed tokens
evaluation schedule
checkpoint policy
random seeds and retry policy
~~~

新 optimizer 的超参可以调，但调参预算也要固定。例如 AdamW 搜索 20 组，Muon 只试 2 组，最后把最好结果比较，结论会受到搜索预算影响。应记录搜索空间、失败实验和选择规则。

### 6.18.2 同时看四种曲线

至少画：

1. loss 对 optimizer steps；
2. loss 对 consumed tokens；
3. loss 对 wall-clock time；
4. 目标能力对 wall-clock time。

如果只画第一张图，无法区分“每步更快”“每 token 更有效”和“kernel 更快”。

### 6.18.3 质量不能只用 PPL

优化器可能让 validation PPL 更低，却使代码、数学、工具调用或指令遵循变化。对 LLM 训练至少分层观察：

| 层次 | 例子 |
| --- | --- |
| 训练信号 | train/validation loss、PPL |
| 通用能力 | 语言、知识、代码、数学 |
| 行为 | 格式、拒答、工具调用 |
| 风险 | 数据泄漏、隐私、越权、安全 |
| 系统 | 显存、吞吐、恢复、故障率 |

每一层都有自己的分母和误差，不能把所有数字未经说明地加成一个总分。

### 6.18.4 按瓶颈选择优化器路线

不同优化器不是一条从“旧”到“新”的替换链。先确认当前主要约束，再选择改变对应状态或更新几何的方法：

| 路线 | 首要解决的问题 | 主要机制 | 主要代价/边界 | 第一项验证 |
| --- | --- | --- | --- | --- |
| SGD + Momentum | 减少自适应状态和实现复杂度 | 梯度与速度状态直接累积 | LLM 预训练中对曲率尺度缺少逐坐标适配；需重新调 LR 与稳定性 | 与 AdamW 在同 token 预算、充分调参下比较 loss 和稳定性 |
| AdamW | 强而成熟的通用基线 | 逐元素一阶/二阶矩，自适应分母加解耦衰减 | 两个逐参数状态；只表达坐标级缩放 | 先确认 baseline 的 LR、decay、warmup 和预算已经调好 |
| Adafactor | 二阶状态显存 | 矩阵的行列统计近似完整二阶矩 | 近似统计改变轨迹；relative step、更新裁剪、向量分支也影响结果 | 分别报告状态字节、峰值显存和达到同一质量的 token/时间 |
| Lion | 少一个逐参数状态 | 动量决定符号更新方向 | 参数更新幅度较一致，LR/decay 不可照搬 AdamW；小 batch 或部分语料优势可能小 | 独立搜索 LR、decay，按 batch 大小和目标任务分片评估 |
| Sophia | 用低开销曲率估计提高数据/计算效率 | 对角 Hessian 或 Gauss-Newton 估计、动量、按坐标裁剪 | 额外 HVP/曲率采样；估计噪声、刷新间隔和 $\gamma$ 要调 | 同时测 Hessian 开销和相同验证目标的 tokens、FLOPs、墙钟时间 |
| Muon | 利用 hidden matrix 的整体几何 | 动量矩阵做 polar/正交化近似，并按形状缩放 | 需挑选矩阵参数、做矩阵核和通信；update RMS 对形状敏感 | 打印实际参数分组、每层 update RMS、Newton-Schulz 时间和质量曲线 |
| Shampoo / SOAP | 表达矩阵行列间的梯度相关性 | 累积左右协方差；SOAP 还在特征基内做自适应更新 | 协方差/特征基状态与分解开销更高；统计陈旧可能引发不稳定 | 检查块大小、基刷新、 $\epsilon$、状态显存和大 batch loss spikes |
| GaLore | 全参数训练时降低 optimizer state | 投影到动态低秩梯度子空间，在低秩坐标维护状态 | rank 和刷新频率控制近似误差与 SVD 成本 | 扫 rank/刷新间隔，并验证 checkpoint 恢复的投影基连续性 |

这张表用于按瓶颈筛选方案，不是排行榜。若 OOM 来自激活而非 optimizer state，Adafactor/GaLore 未必解决主问题；若目标是缩短训练时间，状态字节、单步 FLOPs 或 step 数都不能替代达到同一质量所需的实测 token 与墙钟。

实证结果没有给出跨配置的固定赢家。2024 年的 [autoregressive LM 对照](https://arxiv.org/abs/2407.07972)在其模型规模、架构变体和超参范围内发现 Adam、Adafactor、Lion 表现接近，而 SGD 较弱；这不等于三者在所有任务上等价。[ICLR 2026 系统比较](https://proceedings.iclr.cc/paper_files/paper/2026/file/ea4f0a6ad7088c9b93f22d74c0c9e8c2-Paper-Conference.pdf)则指出跨 optimizer 复用超参、基线调参不足以及只看中间 checkpoint 会扭曲判断；在其 1.2B 设置中，矩阵方法的收益收敛到约 1.1×。这些论文支持的是可比调参和终点评估原则，不能拼成跨任务排行榜。

公平调参不要求各方法使用相同超参，而是给可比的搜索资源。AdamW、Lion、Sophia 与 Muon 的搜索维度不同，应事先固定搜索空间、试验数、每次 token 上限、评估频率、早停规则与种子数。预算不足以跑完 3×3×3 网格时，可预先规定分阶段搜索；记录失败配置和选择过程，再用独立 run 对 shortlist 做完整预算比较。这样既避免给新方法过多搜索机会，也不把不匹配的配方误称为公平基线。

比较要固定模型与初始化、tokenizer 和数据顺序、验证集、精度、并行拓扑、有效 token batch、最大训练预算及 checkpoint/重试规则。至少报告 loss 对 steps、tokens 和 wall-clock 的曲线，以及目标能力对 wall-clock 的变化；终点表再列验证 loss/PPL、能力切片、达标 tokens、估算 FLOPs、GPU-hours、tokens/sec、峰值显存和故障率。只有一个种子时明确标注单次运行；多种子报告离散程度。验证集用于调参，候选冻结后再评估最终测试集，并固定去污染规则、样本与评分脚本。

这些指标回答不同问题：更少 token 达到同一质量是 token efficiency；同一 token 数耗时更短是吞吐收益；同一墙钟质量更好是 time-to-quality；峰值显存降低是容量收益。若候选吞吐只有 AdamW 的 80%，要比基线少用超过 20% 的 tokens 才可能更快。一般比较 $T_{\mathrm{candidate}}/q_{\mathrm{candidate}}$ 与 $T_{\mathrm{baseline}}/q_{\mathrm{baseline}}$，其中 $T$ 是达到同一质量的 token 数、$q$ 是实测吞吐。最终方案可能是在能力、token、墙钟和显存之间的 Pareto 取舍；应预先定义主要指标、可接受质量范围和最小可测收益，处于误差范围内就报告“未分出胜负”。

    return peak_lr * (min_ratio + (1.0 - min_ratio) * cosine)


def clip_scalar(gradient, max_norm):
    gradient = finite_scalar("gradient", gradient)
    max_norm = finite_scalar("max_norm", max_norm)
    if max_norm < 0.0:
        raise ValueError("max_norm must be nonnegative")
    norm = abs(gradient)
    scale = min(1.0, max_norm / (norm + 1e-12))
    return gradient * scale, norm, scale


def adamw_step(theta, gradient, first, second, step, lr, beta1, beta2,
               eps, weight_decay):
    theta = finite_scalar("theta", theta)
    gradient = finite_scalar("gradient", gradient)
    first = finite_scalar("first", first)
    second = finite_scalar("second", second)
    step = positive_int("step", step)
    lr = finite_scalar("lr", lr)
    beta1 = probability("beta1", beta1)
    beta2 = probability("beta2", beta2)
    eps = finite_scalar("eps", eps)
    weight_decay = finite_scalar("weight_decay", weight_decay)
    if lr < 0.0 or eps <= 0.0 or weight_decay < 0.0:
        raise ValueError("lr, eps, or weight_decay is out of range")
    if lr * weight_decay >= 1.0:
        raise ValueError("lr * weight_decay must be smaller than 1")
    first = beta1 * first + (1.0 - beta1) * gradient
    second = beta2 * second + (1.0 - beta2) * gradient * gradient
    first_hat = first / (1.0 - beta1 ** step)
    second_hat = second / (1.0 - beta2 ** step)
    adaptive = first_hat / (math.sqrt(second_hat) + eps)
    decayed = (1.0 - lr * weight_decay) * theta
    theta = decayed - lr * adaptive
    return theta, first, second, adaptive


def coupled_l2_adam_step(theta, gradient, first, second, step, lr,
                         beta1, beta2, eps, weight_decay):
    theta = finite_scalar("theta", theta)
    gradient = finite_scalar("gradient", gradient)
    first = finite_scalar("first", first)
    second = finite_scalar("second", second)
    step = positive_int("step", step)
    lr = finite_scalar("lr", lr)
    beta1 = probability("beta1", beta1)
    beta2 = probability("beta2", beta2)
    eps = finite_scalar("eps", eps)
    weight_decay = finite_scalar("weight_decay", weight_decay)
    if lr < 0.0 or eps <= 0.0 or weight_decay < 0.0:
        raise ValueError("lr, eps, or weight_decay is out of range")
    gradient = gradient + weight_decay * theta
    first = beta1 * first + (1.0 - beta1) * gradient
    second = beta2 * second + (1.0 - beta2) * gradient * gradient
    first_hat = first / (1.0 - beta1 ** step)
    second_hat = second / (1.0 - beta2 ** step)
    theta = theta - lr * first_hat / (math.sqrt(second_hat) + eps)
    return theta, first, second


def matrix_frobenius_norm(matrix):
    if not isinstance(matrix, list) or not matrix:
        raise ValueError("matrix must be nonempty")
    width = None
    squared_norm = 0.0
    for row in matrix:
        if not isinstance(row, list) or not row:
            raise ValueError("matrix rows must be nonempty lists")
        if width is None:
            width = len(row)
        elif len(row) != width:
            raise ValueError("matrix must be rectangular")
        for value in row:
            value = finite_scalar("matrix value", value)
            squared_norm += value * value
    return math.sqrt(squared_norm)


def unit_frobenius_matrix(matrix):
    norm = matrix_frobenius_norm(matrix)
    if norm == 0.0:
        raise ValueError("a zero matrix has no direction to normalize")
    return [[value / norm for value in row] for row in matrix]

## 6.20 Checkpoint：优化器实验必须可以继续

看 Adam 的一个坐标。第 1 步梯度为 1，取 $\beta_{1}=0.9,\beta_{2}=0.99$，从 $m_{0}=v_{0}=0$ 得到 $m_{1}=0.1,v_{1}=0.01$。若 checkpoint 只存权重并在恢复时清空状态，下一步即使输入相同，更新方向也会改变。训练 checkpoint 因而必须保存优化器历史，而不只是模型参数。

### 6.20.1 需要保存的字段

比较 AdamW、Lion 或 Muon 时，checkpoint 至少要包含：

~~~text
model state_dict
optimizer state_dict
scheduler state_dict
scaler state_dict if used
global optimizer step
micro-step or accumulation position
data cursor
RNG states
parameter-group hyperparameters
optimizer implementation version
projection basis or curvature state if applicable
~~~

GaLore 的投影基、Sophia 的曲率估计和量化 optimizer 的 scale 也属于算法状态；漏掉它们就不是严格恢复。

### 6.20.2 连续运行和恢复运行的对照

用连续运行与保存恢复做短程对照：

1. 连续运行 20 个 optimizer steps。
2. 在第 10 步保存所有状态。
3. 从第 10 步恢复，再运行 10 步。
4. 比较第 11 步输入、学习率、梯度、参数和 loss。

若两条轨迹不同，先定位：

- data cursor 是否重复或跳过；
- RNG 是否恢复；
- accumulation 窗口是否从正确位置开始；
- scheduler step 是否偏移；
- optimizer state dtype 是否变化；
- 参数组顺序和超参是否变化；
- 分布式归约顺序是否变化。

相同硬件、确定性算子和 collective 顺序下可检查逐步一致；换硬件或 kernel 后，浮点归约次序可能造成差异。此时应说明容差，并比较样本 ID、有效目标数、LR、状态/梯度范数和参数更新，而不能只凭两条 loss 曲线肉眼相近判断恢复正确。

仍用同一例子，若恢复后的梯度为 $g_{2}=0.5$，连续轨迹得到 $m_{2}=0.14,v_{2}=0.0124$；按 $t=2$ 偏置修正后，忽略 $\epsilon$ 的方向约为 $0.9335$。若只恢复权重并清零状态，方向约为 $0.7426$；若连 step 也重置为 1，则约为 1。相同权重和当前梯度会因历史状态不同而产生不同更新。

最容易复现的保存点是 optimizer-step 边界：完成累积与更新后，一起保存模型、optimizer、scheduler、scaler、RNG 和 data cursor。若在 accumulation 中途保存，还须保存已累积梯度、micro-step 和未提交样本位置；分布式各 rank 也要在一致边界写入对应 shard。模型权重可用于推理不代表完整训练状态可恢复。

checkpoint 还要标明调度分支：WSD decay 候选不能替代未衰减的 stable 主干；WSD-S 的 decay 后恢复点则是后续升回高 LR 的起点。保存 schedule 阶段、token 预算、optimizer step 和数据版本，避免把不同轨迹当成同一个恢复点。完整保存制度见第10章。

checkpoint 还应绑定参数组结构和 optimizer 实现版本。PyTorch 2.15 按参数组顺序把 state 映射到当前参数，默认不额外核对参数名；官方文档要求先初始化 scheduler，再加载 optimizer state，以免覆盖恢复的 LR。[`state_dict`](https://docs.pytorch.org/docs/2.15/generated/torch.optim.Optimizer.state_dict.html)、[`load_state_dict`](https://docs.pytorch.org/docs/2.15/generated/torch.optim.Optimizer.load_state_dict.html)和 [scheduler 文档](https://docs.pytorch.org/docs/2.15/generated/torch.optim.lr_scheduler.LRScheduler.html)所述语义只适用于该版本接口。参数组重排、模型包装或升级实现后，应做短程恢复对照。切换 optimizer 时，Adam 的 $m,v$ 通常不能直接当成 Lion momentum 或 Muon 矩阵动量；没有经过验证的转换规则，就从同一权重另开新实验。

“跨阶段是否应保持同一 optimizer”也没有普遍结论。一项研究在 GPT-2 与 Llama-2-7B 的特定 SFT/遗忘指标上观察到同族 optimizer 的 Pareto 优势；另一项在 1.2B Llama-3 和最高 14B 开源模型的 AdamW/Muon 对照中发现，匹配 optimizer 可减少遗忘，但这没有转化为普遍的最终 benchmark 优势，调好 LR 后总体切换惩罚很小。[研究一](https://arxiv.org/abs/2605.06654) [研究二](https://arxiv.org/abs/2610.22650)。模型和指标不同，结论不能合并成通则；恢复旧状态与换 optimizer 后重新初始化也应作为不同实验记录。

模型权重、optimizer state 和 data cursor 必须属于同一个提交边界。异步保存若留下“新参数配旧动量”，或 cursor 已前移而状态未提交，都会破坏恢复语义。应在所有 rank 状态齐备后提交同一 checkpoint sequence/完成标记；原子保存实现见第10章。

## 6.21 从 loss spike 反查优化器链

例如裁剪阈值 $c=1$，某步梯度为 $(60,80)$，范数 100，裁剪后为 $(0.6,0.8)$。若数据来源切换后，1,000 步里有 900 步触发近似相同的裁剪，同时有效目标数从 256K 降到 25.6K，应先查 mask、分母和数据切片；直接把阈值提到 100，只会放行异常梯度。若目标数和 raw 梯度正常、只有参数 update norm 突然增大，再查学习率和优化器状态。

### 6.21.1 第一步：确认是否真的是优化器问题

loss spike 可能来自异常数据、label shift、mask 分母、数据切换、checkpoint 恢复或评估脚本。先关联异常 step 的：

~~~text
data source and sample ids
valid token count
sequence length distribution
learning rate
raw and clipped grad norm
parameter norm
overflow / NaN flags
optimizer state statistics
~~~

只有当数据和目标链路正常，才适合把原因集中到 optimizer 或 scheduler。

### 6.21.2 学习率过大或 warmup 太短

常见表现是训练刚开始或 scheduler 切换点出现尖峰。可以做最小对照：

- peak lr 减半；
- warmup 延长；
- 保持 optimizer 和 token batch 不变；
- 比较 grad norm、clipping ratio 和验证损失。

如果 spike 消失，仍要继续检查是否牺牲了最终质量，不能只因为曲线平滑就宣布修复。

### 6.21.3 $\beta$、eps 或 decay 不合适

$\beta_{1}$ 影响方向的平滑程度， $\beta_{2}$ 影响二阶尺度的响应速度，eps 影响小分母区域，weight decay 影响参数范数。它们的变化应一次只改一类，并保存每次实验的 optimizer state 配置。

$\beta_{2}$ 较大时，二阶统计对新梯度反应慢；较小时，尺度估计更快但可能更噪。不存在只凭模型名称就能确定的唯一值。

### 6.21.4 clipping 持续触发

检查：

1. loss 是否已按有效 token 归一化；
2. 梯度累积是否正确；
3. unscale 是否先于 clipping；
4. 学习率是否在 scheduler 边界突然变化；
5. 是否只有某个数据来源或 rank 异常；
6. 是否把未裁剪 norm 错当成裁剪后的 norm。

持续裁剪可能是保护措施，也可能在掩盖训练配置错误。要记录裁剪前后的数值。

### 6.21.5 换新优化器却没有收益

先确认新方法是否真的进入了期望参数：

- 参数组数量和元素量；
- optimizer state 的形状；
- 每步更新范数；
- kernel 和通信耗时；
- scheduler 是否仍按旧实验配置；
- 调参预算是否公平。

Muon 若所有参数都走同一逻辑，可能失去其设计前提；Lion 若复用 AdamW 的学习率，可能产生完全不同的更新尺度；Sophia 若曲率估计未刷新，可能退化成异常的预条件器；GaLore 若 rank 太低，可能限制有效更新子空间。

按时间线找第一个偏离正常范围的量，不要从最终 loss 倒推原因。把有效目标数、raw gradient norm、裁剪比例、update norm、参数范数、LR、验证 loss，与数据来源、序列长度、溢出标志和 checkpoint 恢复点对齐：目标数或梯度先异常就查数据、mask、分母和 loss scaling；梯度平稳而 update norm 跳变，再查二阶状态、参数组、decay 或 scheduler；参数更新正常而验证 loss 单独跳变，则查评测输入和口径。

最小对照应从同一 checkpoint 分叉且一次只改一类因素，例如先减半 peak LR，再单独延长 warmup，最后检查 $\beta/\epsilon$。不要在同一 run 里连续改值；更换 optimizer 时，除非状态转换有明确定义并验证，否则从同一权重初始化新状态并另立实验分支。

排障成功要求异常得到解释或消除，且达标 token/FLOPs/墙钟、能力切片与安全评估没有被悄悄改变；恢复后还应能重复观察结果。出现 NaN/Inf 时暂停更新，保留故障前 checkpoint、样本与状态快照，不要把非有限值写回模型后继续调参；记录假设、唯一改动、观测量与结论。

## 6.23 章节练习：从公式到实验

### 练习一：手算 AdamW

给定 $\theta=2$、 $g=0.5$、 $m_{0}=v_{0}=0$、 $\beta_{1}=0.9$、 $\beta_{2}=0.999$、 $\eta=0.01$、 $\lambda=0.1$，分别计算第一步的 AdamW 更新和把 L2 项并入梯度后的 Adam 更新。指出两者在哪一步产生差异。

### 练习二：状态账本

假设模型有 7B 参数，权重和梯度为 BF16，m/v 和 master weight 为 FP32。先计算忽略激活时的粗略字节数，再列出分片、offload、8-bit state、Adafactor 和 GaLore 分别改变了账本的哪一项。

### 练习三：变长 batch

两个 micro-batch 分别有 100 和 300 个有效 token，未归一化 loss 分别为 50 和 120。比较：

1. 平均两个 batch mean；
2. 按总有效 token 汇总。

说明哪一种与 token-level cross entropy 一致，以及错误分母会怎样改变梯度权重。

### 练习四：scheduler 恢复

写出 warmup 10 steps、stable 30 steps、decay 60 steps 的 WSD 学习率表。模拟在第 25 步保存、从第 25 步恢复和错误从第 0 步恢复，比较之后 10 步的学习率总和。

### 练习五：优化器公平比较

设计 AdamW、Lion 和 Muon 的小规模比较。要求固定模型、tokenizer、数据顺序、token batch、精度和最大 token 预算，同时记录每种方法的调参预算、失败实验、显存、吞吐、验证 loss 和三项下游能力。

### 练习六：恢复一致性

给 toy optimizer 增加随机 dropout 和 data cursor。在第 5 步保存权重、optimizer、scheduler、RNG 和 cursor，比较连续运行与恢复运行的第 6 步梯度和参数。

### 练习七：解释一个“更快”

假设新优化器在 1000 steps 时达到同样 PPL，但每步 token 数少一半、kernel 更快 20%。分别用 steps、tokens、FLOPs 和 wall-clock 计算“更快”是否成立，并指出需要补充哪些质量指标。

### 练习八：Sophia 的裁剪与负曲率回退

使用 $u=\mathrm{clip}(m/\max(\gamma h,\epsilon),1)$。取 $\gamma=0.1$、 $\epsilon\to0$，分别计算 $(m,h)=(0.04,2)$、 $(0.4,2)$ 和 $(0.4,-2)$ 时的方向更新。说明哪两种情况下曲率预条件生效，哪一种退化为符号动量；再讨论提高 $\gamma$ 会怎样改变触发裁剪的坐标比例。

### 练习九：WSD 与 WSD-S 的 checkpoint 轨迹

设 warmup 在第 10k 步结束、stable 主干继续到 50k 步。画出 WSD 在 25k 和 50k 的分支；写清楚要继续训练时分别恢复哪个模型与 optimizer/scheduler 状态。再设计 WSD-S 的 decay、升回 stable 学习率和再次 decay 的单次轨迹，并说明如何避开 loss spike 后立即 decay。

### 练习十：比较不同论文里的 Muon 加速结论

对照 Moonshot 2025、optimizer 系统比较 2025、μP transfer 研究和 NVIDIA 2026 报告。列出各自的模型/数据/训练预算、baseline 调参、token batch、评价指标和 Muon/AdamW 参数分工；解释为什么约 2×、1.4×、1.1× 和大 batch 稳定性不能合并成同一个结论。

## 6.24 本章小结

优化器把带噪声的梯度变成参数更新，学习率调度器决定更新尺度随训练进度如何变化。SGD 直接沿负梯度走，Momentum 累积方向，Adam 增加一阶和二阶统计，AdamW 则把 weight decay 从自适应梯度中分离出来，形成大模型训练中成熟的强基线。

Adafactor 通过分解二阶统计降低状态显存；Lion 用符号动量减少状态但需要重新调学习率；Sophia 引入轻量曲率信息并用裁剪控制二阶更新；Muon、Shampoo、SOAP 利用矩阵几何但增加矩阵统计或正交化的成本；GaLore 通过低秩梯度投影降低全参数训练的状态压力。这些方法解决的问题不同，不能只按谁更新或谁更省显存排一张没有条件的排行榜。近期对照研究显示，加速幅度会随调参质量、规模、数据预算、批大小和实现方式显著变化。

Warmup、cosine、线性衰减和 WSD 只定义学习率轨迹，不会自动修复错误的 loss 分母。gradient clipping 限制异常更新，但不能替代数据、数值和恢复检查。真正可比较的训练实验必须同时报告 optimizer state、参数分组、有效 token batch、学习率步数、总 token、质量指标、系统成本和 checkpoint 恢复行为。
