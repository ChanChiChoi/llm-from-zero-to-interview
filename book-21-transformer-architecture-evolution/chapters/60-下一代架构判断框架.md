# 第 60 章 读懂新架构主张：信息路径、资源变化与证据边界

第五十九章刚把 GPT、LLaMA、Mistral、Qwen 和 DeepSeek 等固定版本放在一起比较。读完历史案例后，读者还会遇到另一个问题：新发布声称“更省缓存”“更大容量”“拥有记忆”或“能自主行动”时，究竟是哪一层发生了变化？这些词听起来都像架构升级，但背后的模型对象、信息路径和可支持的结论可能完全不同。

本章把模型发布和新论文当作需要拆解的主张来读：先确认谈论哪个版本及什么对象，再沿数据和状态的路径找机制，随后看机制预言了什么资源变化、哪些任务可能暴露代价，最后让结论强度与来源和实验范围相称。这样读者能说清一项技术改了什么、证据到哪里为止，也能在新资料出现时更新判断。

## 60.1 从时间线读变化，而不是追代际标签

第二十一册的[架构创新时间线](../主流大模型架构创新时间线.md)用于找到模型和来源的入口，不能单独证明某个版本“代表下一代”。第五十九章已经把历史案例中的架构、训练和发布方式分开；面对一个新案例时，可以沿用这个区分，再识别这次主张属于哪一层。

### 60.1.1 固定对象：家族名称、模型版本与具体 checkpoint

先确认材料究竟说的是哪一版模型。一个系列名之下可能有基础模型、指令微调模型、不同参数规模和多模态变体；同一个 API 名称也可能对应托管端更新。论文修订版、模型卡、配置文件和产品页面描述的对象也不一定相同。

因此，比较时应写清模型或 checkpoint、报告版本及发布日期。DeepSeek-V2、V3 与 R1 就不是一个未分阶段的“DeepSeek 架构”：V2 与 V3 报告描述架构和训练变化，R1 论文描述在 V3-Base 上进行的后训练路线。读者可回看[第五十八章](58-DeepSeek-V2-V3-R1架构训练.md)和[第五十九章](59-主流模型架构创新横向对比.md)中的版本关系。

### 60.1.2 区分模型结构、训练变化、执行实现与外部系统

首先判断新主张改变了什么对象。几类常被混写的变化如下：

| 变化位置 | 例子 | 它描述的是什么 |
| --- | --- | --- |
| 模型内部结构 | MLA、MoE、SSM、attention 与递归状态的组合 | 模型参数和前向计算中的信息路径 |
| 训练阶段或目标 | MTP、监督微调、强化学习 | 模型如何从训练数据或反馈中更新 |
| 执行实现 | FlashAttention、kernel 融合、权重布局 | 相同或近似数学运算怎样映射到硬件 |
| 外部信息与动作 | RETRO 式检索、工具调用、ReAct 轨迹 | 模型怎样读取外部资料或与环境交互 |

这些变化都可能改善特定任务，但不能只因出现在同一产品介绍中就叫作同一种 backbone 创新。FlashAttention 改变 attention 的执行方式而保留其数学计算；DeepSeek-R1 的后训练不等于替换了 V3-Base；ReAct 让模型输出动作并接收环境观察，也不意味着模型新增了一种内部 attention。后文会逐一看这些差异怎样影响判断。

## 60.2 把“新架构”主张拆成可检验的结构变化

一个有意义的架构主张应能回答：哪个对象被改了、机制怎样改变状态或运算、预期解决什么瓶颈、会增加什么代价、怎样的观测能检验这些预期。少了其中的因果连接，读者看到的可能只是一个新名称，或一个无法归因到结构的模型总成绩。

### 60.2.1 找到改变的对象、运算和状态

沿着一次前向计算追问：当前 token 从哪里取得历史信息？哪些表示被保存？什么规则决定读入、压缩、更新或丢弃？如果引入了路由，哪些参数会收到当前 token？如果引入检索，返回的是模型内状态还是数据库里的内容？

例如，MLA 讨论的是 attention 历史怎样编码并缓存；MoE 路由讨论的是 token 选择哪些 FFN 专家；Mamba 讨论的是输入怎样影响递归状态更新。这些机制分别作用在不同对象上。把它们统一叫“更高效的注意力”会掩盖到底是缓存、参数选择还是状态更新发生了变化。

### 60.2.2 从机制推出预期收益和新增代价

结构变化应先导出可检验的预期，而不应直接宣告结果。若缓存表示变小，预期是每个 token 保存的历史状态减少；若专家稀疏激活，预期是某些 token 的 FFN 计算只经过一部分专家；若历史被压入递归状态，预期是生成时不必保留每个位置的显式键值，但模型必须用更新规则维持后续任务所需的信息。

每项预期也有对应的潜在代价：压缩表示可能增加重建或投影计算；专家路由需要分派 token，并可能带来负载不均和跨设备通信；递归状态需要面对信息衰减、覆盖或难以精确回读的问题。这里的机制分析用于提出待测预测，不能把理论路径直接当成已测得的质量或速度收益。

DeepSeek-V2 是一个容易读错的例子。报告称该版本有 MLA 与 DeepSeekMoE，并把模型和 DeepSeek 67B 做训练成本、KV cache 及生成吞吐比较。摘要报告的数字属于这个模型与该对照的结果；由于 MLA、MoE 和训练配置共同出现在案例中，不能把所有变化归因给其中一个组件。[DeepSeek-V2 技术报告 v5](https://arxiv.org/abs/2405.04434v5)说明了作者公开的模型结构与比较口径；[第五十八章](58-DeepSeek-V2-V3-R1架构训练.md)进一步区分各项结构。

## 60.3 多种架构方向改变的是不同信息路径

若把不同的“新架构”名称都放在一条路线里，就容易误以为它们是在争夺同一个位置。下面几种设计所处理的信息对象并不相同：有的重新表示 attention 的历史，有的重新分派参数计算，有的改变历史状态更新，有的接入模型外部的检索或交互环境。

### 60.3.1 MLA 改变注意力历史的缓存表示

标准自回归 attention 会为过去的 token 保存键和值，生成新 token 时用当前 query 读取这份历史。DeepSeek-V2 的 Multi-head Latent Attention（MLA）先把内容相关的键和值压到一个共享 latent 表示中，并缓存该表示；位置编码路径仍需单独处理。这样改变的是历史缓存的表示方式，目标是减小 KV 状态，而不是删除模型权重，也不是取消 attention 对历史的读取。

缓存压缩会把工作从读取较大的历史张量转移到低秩投影、重建或权重吸收等计算路径。缓存数字本身因此不能回答完整推理速度：还要看实际 attention 实现、批量形状、内存流量及并行方式。DeepSeek-V2 报告称，相对 DeepSeek 67B，该模型的 KV cache 减少 93.3%，最大生成吞吐提高 5.76 倍；这些是报告所列模型和测试条件下的比较，不是每个 MLA 实现都能复现的通用比例。[DeepSeek-V2 技术报告](https://arxiv.org/abs/2405.04434v5)给出结果与结构；Manning 的[MLA 章节讲解提纲](https://livebook.manning.com/learn/build-a-deepseek-model-from-scratch/chapter-3)和 [Lior Sinai 的推导与实现笔记](https://liorsinai.github.io/machine-learning/2025/02/22/mla.html)展示了如何把 KV 缓存问题连到 latent、位置路径和逐 token 计算。后两者适合借鉴讲解，数字和模型事实仍应回到原报告。

### 60.3.2 MoE 改变每个 token 激活的参数子集

Mixture of Experts（MoE）通常把部分 dense FFN 替换为多组专家，并用 router 为每个 token 选择一个或多个专家。于是，“模型包含多少权重”和“这个 token 经由哪些专家计算”变成两个不同的量。Switch Transformer、Mixtral 和 DeepSeekMoE 都展示了稀疏专家路线，但专家数、top-k 路由、共享专家和负载平衡方式并不相同。

active parameters 说明某 token 实际经过的部分参数，不能直接当成整个模型所需的存储量或端到端延迟。未激活的专家权重仍需由部署系统保存或按需访问；token 分派、专家负载和设备间通信也会产生额外成本。Switch Transformer 的论文把通信成本和训练稳定性列为 MoE 需要处理的难点，[Hugging Face 的 MoE 机制讲解](https://huggingface.co/blog/moe)则将 router、token 分派和专家执行依次展开。比较稀疏专家时，要同时看总参数、激活参数、分派路径和实际测量对象；本册的[第二十一、二十二章](../目录.md)进一步解释路由及成本。

### 60.3.3 SSM 与递归注意力改变历史进入状态的方式

Mamba 以输入相关的参数控制状态更新，使模型能够选择何时写入、保留或衰减信息。它在推理阶段沿 token 递归更新状态；并行训练则采用硬件感知 scan。与显式 KV 不同，递归状态把历史汇总到状态变量中，因而读取历史的路径也不同。[Mamba 原论文](https://arxiv.org/abs/2312.00752v2)明确说明选择机制使系统不再是固定的线性时不变卷积，并介绍其 scan 实现。

“固定形状状态”既不证明记忆一定足够，也不证明模型必然忘掉所有远处细节；要看任务究竟要求什么样的历史访问。Waleffe 等人将 8B 级 Mamba、Mamba-2、Transformer 与 Mamba-2-Hybrid 放在相同数据和最高 3.5T token 的训练设置下比较：在指定 RULER synthetic 长上下文切片上，混合模型有若干优势；自然长上下文的多文档问答却呈现不同结果，16K/32K Transformer 平均高约 1 个点，差异主要来自多文档 QA。提示格式变化也会影响其中一些任务。[实证研究](https://arxiv.org/abs/2406.07887)展示了架构结论为何需要绑定任务构造，而不是只看一个“长上下文分数”。

2026 年的 Mamba 位置回忆研究进一步考察哪些输入被保留：作者在结构化 recall 任务中报告短时状态、稀疏长期通道和中段信息的转移瓶颈，并通过干预连接到指定的长上下文 QA 与摘要任务。[Findings of EMNLP 2026 论文](https://aclanthology.org/2026.findings-emnlp.1944/)支持的是研究中所测 Mamba 模型及任务范围内的机制分析，不代表全部递归架构或任意自然语言任务。它提醒读者：架构主张应当对应到具体的信息位置和失效任务。

### 60.3.4 内部神经记忆与外部检索提供不同的历史访问路径

“memory”可能指外部存储中的文档、可检索的键值、模型运行时更新的神经状态，或任务上下文中的持久提示。它们保存的位置和更新方式不同，不能只凭同一个名称推断结构相似。

RETRO 按当前上下文从外部语料库检索相关文本块，再把检索结果接到语言模型预测路径上；Titans 则提出在 test time 更新的神经长期记忆，并比较把记忆作为上下文、网络层或门控分支接入的方式。[RETRO 原论文](https://proceedings.mlr.press/v162/borgeaud22a.html)和 [Titans 的 NeurIPS 2025 论文](https://proceedings.neurips.cc/paper_files/paper/2025/file/a4ca07aa108036f80cbb5b82285fd4b1-Paper-Conference.pdf)代表了两类不同设计。判断 memory 结构时，应先问信息位于模型外的索引还是模型内的状态、由谁更新、查询返回原文还是压缩表示；外部语料的版本和检索过程也会影响实验。机制详解分别见本册[第四十五章](45-Retrieval-Augmented-Architecture.md)和[第四十六章](46-Memory-Augmented-Transformer.md)。

### 60.3.5 Agent action-observation loop 不等于新的模型主干

一个模型可以生成动作，宿主程序再执行动作，把环境观察送回模型，形成多轮闭环。ReAct 论文通过交替生成推理文本和动作，并使用 Wikipedia API 或交互环境的观察来完成任务；实验中的 Agent 结果来自模型、提示、动作空间与环境共同作用。[ReAct 原论文](https://arxiv.org/abs/2210.03629)的主体实验使用冻结语言模型来进行这类交互，因此 action-observation loop 本身不是 backbone 改造的证据。

当产品展示新工具或多代理行为时，应分别陈述模型接受什么接口、宿主怎样执行、观察怎样回传以及研究测了哪些任务。仅凭工具调用轨迹无法判定模型内部是 dense、MoE、MLA 还是 SSM。本册第四十九章和第十七、二十册负责进一步讨论 Agent 行为与运行时边界，本章只用它来提醒读者不要把系统能力归到内部结构。

## 60.4 从结构变化推到资源预测与任务风险

机制分析的作用，是预先说明哪些成本和能力最可能变化，帮助读者挑选能区分假设的证据。复杂度和参数字段可以生成预测，但只有和任务表现或目标硬件上的测量对齐，才能说明预测是否成立。

### 60.4.1 让资源指标对应被改变的对象

不同结构需要查看不同的资源量。下表把架构对象与观察量对应起来，避免把 FLOPs、缓存或参数总数当作可互换的“效率”指标。

| 结构主张 | 首先对应的资源量 | 仍需单独确认的代价 |
| --- | --- | --- |
| MLA 压缩历史表示 | 每 token、每层缓存字节数及历史读取量 | 投影/重建计算、内存带宽和并行切分方式 |
| MoE 稀疏路由 | 总权重、每 token 激活参数与专家计算 | token 分派、路由负载、设备间通信和未激活权重存储 |
| SSM 或递归状态 | 每层状态大小与单步更新工作量 | 训练 scan、kernel 效率、状态承载的任务能力 |
| 外部检索或神经记忆 | 索引/记忆存储、查询与更新路径 | 检索准确性、数据版本、更新开销及额外读取延迟 |
| Agent 动作闭环 | 动作次数、环境往返与完整任务成功结果 | 它属于模型外系统的总体成本，不能当作 backbone 计算量 |

此外，训练、prefill 和逐 token decode 处在不同计算阶段。同一个结构可能降低历史状态容量，却增加预填充工作；也可能降低每 token 的专家计算，但不减少整体权重存储。书中的[第四十二章](42-替代架构横向对比.md)、[第三十三章](33-Mamba训练推理与硬件效率.md)和[第五十九章](59-主流模型架构创新横向对比.md)分别提供更具体的架构和阶段成本口径，本章不重复完整服务测试流程。

### 60.4.2 用压力任务检验机制可能丢失什么

设计验证问题时，先问该机制最可能删减、合并或延迟访问哪类信息。压缩历史的路径要查看精确实体、数字、引用和证据位置；递归状态要查看远距离精确复制、关联回忆、中段信息和干扰下的状态更新；路由结构要查看稀有 token、专家负载变化和任务切换；检索记忆要检查返回内容是否过时、相关或相互冲突。

这些任务是机制压力点，不是通用 benchmark 清单。Mamba 的研究在 RULER 的合成检索与 LongBench 的自然多文档问答中得到不同结论，正说明任务分布和输入组织会影响观察结果。若一项设计只在单个长上下文长度或单个平均分上获胜，还不能说明所有需要历史访问的工作负载都受益。完整评测协议属于相关评估书册，本章只要求架构主张和所测任务之间存在明确对应。

## 60.5 让证据强度与主张范围相称

读架构材料时不要只看“来源级别”标签，而要问手里的材料是否直接观察了当前主张。论文、模型卡、固定版本配置、源码、任务评测和硬件测量各能回答不同问题；可信来源也可能对某个问题没有证据。

### 60.5.1 公开报告、配置、实现和行为结果各自支持什么

| 资料类型 | 可以直接支持 | 不能单独推出 |
| --- | --- | --- |
| 论文或技术报告 | 作者描述的模块、公式、训练设置和报告中的实验结果 | 未做消融的单一组件因果贡献，或跨条件的一般收益 |
| 模型卡、配置或固定 revision 源码 | 指定版本公开了哪些字段、实现了哪些路径 | 所有版本或未公开的训练/生产细节 |
| 任务级 benchmark | 指定模型、提示、数据和评分方式下的输出行为 | 隐藏的内部拓扑，或任意任务上的能力 |
| 硬件/profile 测量 | 指定模型实现、shape、硬件与负载下的资源结果 | 其他设备、服务框架或 workload 的性能 |
| API 或产品页面 | 用户可以调用的接口、限制和公开能力说明 | Dense/MoE、attention 类型或未披露的训练配方 |

闭源模型资料尤其需要保留未知项。若官方只公开上下文长度、图像输入或工具接口，可以报告这些可观察能力；不能由此推断内部模型使用 MLA、MoE、稀疏 attention 或特定训练目标。外部行为可提示下一项实验，却不能替代架构证据。

### 60.5.2 用 matched baseline 和消融限制因果归因

若比较的两个版本同时改变数据量、参数规模、训练目标、结构和评测协议，整体结果无法指出哪项变化造成差异。较有解释力的证据会对齐与主张有关的条件，并尽可能通过消融或成对配置隔离组件影响。对于“更快”，要确认比较了同一硬件、负载、阶段和实现；对于“能记得更远”，要确认任务真的要求从远处提取指定信息。

Waleffe 等人的比较价值不在于给 Mamba、Hybrid 或 Transformer 选出永久胜者，而在于报告了较大模型、相同训练数据下，多个任务切片的不同对照关系。作者报告在特定 16K/32K 合成 RULER 任务上 hybrid 有优势，但在 LongBench 的多文档问答任务上 Transformer 仍略高，且作者讨论了提示格式和训练时文档拼接的影响。[实验论文](https://arxiv.org/abs/2406.07887)说明，即使总体训练较受控，也仍需把结论写成“哪种结构在什么任务和提示条件下怎样”，不能把单项成绩提升说成无条件的架构优越。

### 60.5.3 把已披露、观察、推断和未知分开写

可将结论分成四类：**已披露**是原始资料明确给出的结构或配置；**已观察**是实验在某个任务中测到的输出或资源结果；**推断**是从机制预测到其他条件下的表现；**未知**是公开材料尚未回答的问题。每句判断都要让读者看出它属于哪类。

例如，“该报告的模型使用 latent KV cache”是版本范围内的披露；“报告在其对照中测得较小缓存”是有条件的观察；“换到其他 serving 框架仍能得到同样吞吐”则是需要新的推理和测量的推断；“某闭源模型是否用了这一机制”在缺少公开证据时仍未知。保留未知不妨碍形成结论，它能让未来的新报告有明确的更新位置。

## 60.6 对下一代架构作有限而可更新的判断

回看本册的历史案例和当前论文，得到的不是一种已确认的“下一代主干”，而是多个设计方向在不同层级继续发展。第五十章已经展示组合发生在层间、head、记忆分支和 attention 分数等位置；本章补充的是如何判断新主张及其证据，而不是再预测哪种混合路线必然获胜。

### 60.6.1 时间线显示多条演进轴并行，而非一个必然继任者

MLA 处理 attention 历史的缓存表示，MoE 分配每个 token 的专家计算，SSM 与递归注意力研究状态如何更新，检索和神经记忆扩展信息保存与读取方式，Agent 闭环则把模型连接到外部动作和环境。它们不能按单一性能轴直接排序，因为改变对象、资源和任务边界不同。

现有证据足以说明这些设计都在被研究，也能说明部分模型和任务中的收益与限制；还不足以断言某一路线会取代其他路线，或所有模型都将采用同一种组合。第五十章给出的“设计空间扩展”是受公开研究支持的条件性判断，不是单一赢家的预测。第六十一至九十五章将按固定来源逐项展开具体结构，不应把那些机制章节的标题当作它们已经普遍成功的证据。

### 60.6.2 用一段话说清主张、机制、条件与证据边界

讨论新架构时，可以沿着一条推理线作答：先说清具体版本和它改变的对象，再解释机制如何影响信息路径；接着指出对应的资源或任务观察，并给出模型、提示、硬件或数据条件；最后说明哪些结果只是报告观察、哪些是有限推断、哪些仍未知。

例如，读到“长上下文架构更高效”时，先问它采用了什么历史表示、改变的是缓存容量还是历史查询路径，再看论文测了哪些长度、位置、任务和成本。若来源只公开窗口上限，结论就停在接口支持长度；若还公开了固定版本的任务评测和相同条件的比较，才可以按那一范围讨论有效利用和性能。这样的回答能说明架构为何有意义，也允许新证据改变结论。
