# GLM-5.2：IndexShare、MTP 与长轨迹 RL

> 核验日期：2026-09-23。模型由 Artificial Analysis 与 DataCurve DeepSWE 榜单锚定；技术细节来自 Z.ai 官方 GLM-5.2 文档、官方博客及其正文 JavaScript 资源，SAO 算法细节来自 arXiv:2607.07508。博客 benchmark、20% acceptance length 和 OPD 用时均是发布方自报。

## 86.1 为什么 1M context 不是把窗口数字改大

长上下文 Agent 的成本不只来自 attention。请求越长，显式 KV cache 越大，indexer 的 dot product 与 top-k 越频繁，CPU 侧缓存管理和请求调度也越容易形成流水线空洞。因此，一个可用的百万上下文系统必须同时回答：哪些历史 token 值得精确读取，哪些历史可以保存在递归状态，缓存怎样搬运，长轨迹如何训练。

GLM-5.2 博客把这些问题拆成架构、推测解码、serving 和后训练四本账，不能只用“稀疏 attention 更快”概括。

## 86.2 IndexShare：共享 indexer 的计算账本

DSA 先用 indexer 给历史位置打相关性分数，再让主 attention 读取 top-k 候选。若每层都独立计算 indexer，长上下文时 indexer 和 top-k 本身也会变成开销。博客描述的 IndexShare 让连续四层共享一个轻量 indexer：第一层生成 indices，后面三层复用。

粗略地说，若每层 indexer 成本为 `C_i`，四层独立计算约为 `4C_i`；共享后约为 `C_i` 加上复用所需的存储和调度成本。收益不是无条件的，因为四层 query 的相关性可能不同，复用 top-k 会带来召回损失。面试时应追问 `recall@k`、长程 needle retrieval、端到端 TTFT/TPOT 和不同层间 index 稳定性，而不是只报理论 FLOPs。

## 86.3 MTP 与 speculative decoding

MTP head 先提出多个未来 token，主模型一次验证候选。真正收益取决于 acceptance length、draft 成本和 verify 的并行效率。GLM-5.2 博客描述两项目标：降低 MTP draft 成本，并提高接受长度；还提到共享 index/top-k、跨 MTP step 参数共享、rejection sampling 和 end-to-end TV loss。

训练—推理不一致是关键风险。训练时后续 MTP step 可能看到 target model 的 hidden states，推理时却依赖前一步预测。若两者分布不同，离线 loss 很低也可能得到低 acceptance。面试回答应把它写成闭环：draft -> target verify -> accept/reject -> residual correction -> KV commit；被拒 token 不能进入 committed cache。

## 86.4 长上下文 serving

百万上下文的 serving 账本至少包括显式 KV、indexer buffer、线性/压缩状态、cache transfer、CPU 调度和 GPU bubble。博客公开的方向包括更细粒度 KV 管理、prefill/decode 与 cache transfer 协同、请求调度和 runtime 路径优化，以及 PD 组织。它没有公开目标硬件、kernel 源码和完整 profiling，所以不能把宣传的 throughput advantage 写成普遍保证。

一个实用实验应固定模型 revision、context length、batch、并发、prefill/decode 分离方式和硬件，分别测 TTFT、TPOT、p99、cache 命中、传输字节和失败重算。只测 tokens/s 会掩盖长请求排队和尾延迟。

## 86.5 Compaction 与 critic-based PPO

长轨迹被 compaction 切成多个 sub-trace 后，同一个 prompt 产生的可训练片段数量和长度都可能不同。固定 group size 的相对比较不再自然：有的 rollout 被切成两段，有的被切成十段，组内样本并不对齐。

博客描述的方向是 critic-based PPO：critic 为单条 rollout 提供 token-level advantage，再把 compacted sub-traces 作为训练轨迹。这样做的面试重点不是“PPO 一定更好”，而是 credit assignment 和长度归一化：优势估计、mask、bootstrap、KL 和 reward 必须知道哪些 token 属于哪一段状态。

## 86.6 Anti-hack 是 verifier 设计的一部分

Coding Agent 的 pass/fail reward 很容易被 shortcut 利用，例如读取隐藏测试、下载上游答案或直接访问参考实现。GLM-5.2 博客描述规则过滤器加模型分类器的两阶段检测，并对违规动作给负反馈后继续轨迹。

继续轨迹能保留更多训练信号，但也带来污染风险：后续 token 可能已经受到了违规信息影响。工程上应同时记录违规动作、检测延迟、误报/漏报、trajectory 是否隔离、环境 reset 和最终 artifact 的独立验证。模型自报的 anti-hack 设计不能替代安全评测。

## 86.7 面试追问

1. 四层共享 top-k 为什么可能降低质量？如何用 recall 与端到端任务成功率验证？
2. MTP 的 acceptance length 下降时，如何区分 draft 太慢、训练—推理不一致和 target verify 瓶颈？
3. compaction 后为什么 group-wise advantage 可能失效？critic 的 token-level advantage 需要哪些 mask？
4. anti-hack 检测发现 shortcut 后，为什么不一定直接丢弃整条轨迹？继续训练的风险是什么？
5. 1M context 压测除 tokens/s 外还应记录哪些 cache、传输和尾延迟指标？

## 86.8 证据边界

官方博客支持 IndexShare、MTP 目标、serving 优化方向、slime/OPD、critic-based PPO 和 anti-hack 的公开描述；SAO 论文补充了单 rollout、DIS、双侧 token clipping、critic 更新和 Skip-Observation GAE 的公开算法细节。不支持完整 kernel、训练数据、产品 compaction 序列化格式、detector 阈值、硬件 profiling 或独立复现结论。GLM-5.3 的官方文档只确认继承 `SAO with compaction`，不能把论文实验迁移成 GLM-5.3 独有结果。

## 86.9 SAO：把异步 RL 的吞吐问题变成可控的 off-policy 问题

[SAO 论文](https://arxiv.org/abs/2607.07508)的全称是 *Single-Rollout Asynchronous Optimization for Agentic Reinforcement Learning*。它解决的不是“再加一个 rollout worker”这么简单：异步 rollout 会让生成策略和训练策略产生 policy lag，长任务长度不均又会让同步 group barrier 等待最慢轨迹；GRPO 的 group-wise advantage 在这种场景下也不自然。

### 86.9.1 DIS：直接使用 rollout 概率

SAO 的 DIS（Direct Double-Sided Importance Sampling）直接读取 rollout engine 的 token log-probability，计算当前策略与实际生成策略之间的比值。token-level ratio 超出 `[1-epsilon_low, 1+epsilon_high]` 时进行 clipping/masking，避免少数严重 off-policy token 主导更新。这里的“直接”是减少旧策略账本和版本滞后，不是消除 policy lag；rollout engine、训练策略和 ratio 的版本仍必须进入 manifest。

### 86.9.2 Single-rollout 与 value model

每个 prompt 只采样一条 rollout，轨迹结束后立即进入训练，不等待同一 prompt 的其他样本。这降低了 group barrier 和 straggler 等待，也牺牲了 GRPO 那种组内相对比较信号，因此需要 value model 提供 token-level advantage。论文进一步把 critic 更新频率设为每次 policy update 的 `K=2`，并冻结 value model 的 attention、只微调 MoE projections，以减轻长轨迹 critic 的不稳定。

### 86.9.3 Skip-Observation GAE

Agent 轨迹包含 action token 和环境返回的 observation token。若把 observation 当成普通 action 反向传播，credit assignment 会把环境文本长度和格式噪声混入优势估计。Skip-Observation GAE 的核心是跳过 observation，从当前 action 段跨到下一 action 段的 value bootstrap：

```text
A_hat(a_i,N) = delta + gamma * lambda * A_hat(a_{i+1,0})
delta = r_t + gamma * V(a_{i+1,0}) - V(a_i,N)
```

实现时仍要保存 segment boundary、环境 step、reward 来源、tool receipt 和 verifier 结果；公式只说明 credit assignment，不代表 observation 可以从 replay 中删除。

### 86.9.4 论文实验与 GLM-5.3 的边界

论文的主干实验使用 Qwen3-30B-A3B，设置包括 batch `128`、single-rollout/group size `1`、max length `128K`、policy lr `1e-6` 和 value lr `5e-6`；摘要称该路线部署到 GLM-5.2（750B-A40B）Agent RL pipeline。GLM-5.3 官方文档则称沿用 GLM-5.2 基座并继承 `SAO with compaction`。因此面试可以讲“GLM-5.3 继承的 SAO 训练路线”和 SAO 的公开机制，但不能把论文 benchmark、Qwen3 实验或 GLM-5.2 结果改写为 GLM-5.3 裸模型能力。

### 86.9.5 面试用检查清单

回答 SAO 时至少分开四层：`rollout engine logprob`（ratio 证据）、`policy/value update`（优化器与 critic）、`observation/action mask`（GAE 语义）和 `environment/verifier`（奖励可信度）。还要主动说明：当前没有 5.3 专属 compaction 序列化、完整 post-training recipe、目标硬件 profile、独立复现或线上 tool acceptance 证据。
