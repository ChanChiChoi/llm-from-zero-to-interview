# 第四十一章：卷积序列模型在 LLM 中的复兴可能性

## 41.1 卷积为什么没有消失

Transformer 让 attention 成为主流后，卷积在通用语言模型中退居配角，但它在音频、视觉、时间序列和局部代码模式中仍很强。随着长序列成本上升，长卷积、隐式滤波器、gated convolution 和混合 state 路线重新出现。

卷积的吸引力来自规则局部性、成熟硬件和稳定的平移结构；它的限制是固定 kernel 不能天然根据当前 query 任意检索远处内容。复兴不是回到旧 CNN，而是把卷积和隐式长核、门控、SSM、attention 组合。

## 41.2 固定卷积的信息流

一维 causal convolution：

~~~math
y_t=\sum_{j=0}^{w-1}W_jx_{t-j}
~~~

窗口为 `w`，每个位置只看局部历史。堆叠层、扩大 dilation 或使用长核可以扩大感受野：

~~~math
\mathcal{R}_L\approx 1+\sum_{l=1}^{L}(w_l-1)d_l
~~~

感受野大不等于每个远处 token 都有独立可寻址表示。不同历史可能在多个卷积层中混合成相似特征。

## 41.3 Gated convolution 和输入依赖

门控卷积可以写成：

~~~math
y_t=\sigma(g_t)\odot (h*x)_t
~~~

其中 `g_t` 由输入产生。它让卷积的输出强度随内容变化，弥补固定滤波器的僵硬，但门控通常只控制通道/位置的混合，不等价于 full attention 的任意 query-key 排序。

## 41.4 长卷积和隐式核

直接学习长度为 `T` 的 kernel 参数与上下文绑定；隐式核使用位置函数生成：

~~~math
h_j=f_\theta(j)
~~~

再用 FFT、分块或递归方式处理。参数效率和长程范围得到改善，代价是核生成、频率表示、边界和在线缓存更复杂。Hyena 是这类路线的代表之一。

## 41.5 局部模式为什么适合硬件

卷积的权重和数据访问规则，容易使用 im2col、GEMM、Winograd、直接 kernel 或 NPU 算子。固定 block 和 contiguous layout 也便于编译。动态 token 路由、稀疏索引和不规则状态往往更难优化。

但长卷积使用 FFT 时会引入频域读写和复数运算；短序列下 direct convolution 可能更快。不要把“卷积硬件成熟”扩大为所有长卷积都快。

## 41.6 一个多层感受野计算器

~~~python
def receptive_field(layers):
    # layers: [(kernel_size, dilation), ...]
    field = 1
    for kernel, dilation in layers:
        field += (kernel - 1) * dilation
    return field


print(receptive_field([(3, 1), (3, 2), (5, 4)]))
~~~

这个数字只表示理论覆盖范围，不表示模型能可靠使用该范围。应再做 impulse response、远距复制和干扰实验。

## 41.7 与 SSM 的关系

SSM 可以展开成特殊形式的长卷积，卷积也可以看作一种固定/生成滤波器。差异在于 state transition、输入依赖、核是否时不变、训练/推理路径和结构化约束。Mamba 的 selective scan 让卷积/状态关系更输入相关；Hyena 强调隐式长滤波器和多阶 gate。

比较时不要因为都有“线性时间”就把它们合并。一个架构可能用卷积做局部预处理、SSM 做长状态、attention 做全局证据。

## 41.8 在 LLM 中的现实位置

卷积最可能承担三类工作：局部 token mixing、音频/视觉 patch 的时空处理、混合模型中的低成本长流扫描。要成为通用 LLM 主干，仍需证明 variable binding、ICL、精确复制、多文档证据和大规模训练竞争力。

因此“卷积复兴”更像模块级趋势，而不一定是纯卷积取代 Transformer。系统设计会根据模态和 workload 选择不同路径。

## 41.9 训练/推理和状态边界

训练时卷积并行，推理时短 kernel 可以保存最近 `w-1` 个输入；长/FFT kernel 需要 overlap buffer、频域状态或 chunk cache。多层卷积的状态要按层分配，不能只保存最终 hidden。

恢复测试需要比较整段卷积、分 chunk streaming 和中断后 resume。若 padding、overlap 或边界处理不同，输出会在每个 chunk 接缝处出现漂移。

## 41.10 失败模式

常见失败有 receptive field 计算正确但实际 mask 错、causal padding 造成未来泄漏、FFT circular wrap-around、长 kernel 过平滑、gate 饱和、短序列 kernel overhead、状态恢复丢 overlap 和量化后频率失真。

诊断使用 impulse、step response、随机输入的 direct/FFT 对齐以及长度分桶。对语言任务加入变量绑定和精确字符串复制，避免只测平滑信号。

## 41.11 机制与边界：卷积先验与语言 token 的冲突

卷积平移共享提高数据效率，却假设相同局部模式在不同位置有相似意义；语言中的绝对位置、结构层级、实体作用域可能违背这个假设。位置编码、dilation、门控和 attention shortcut 可以缓解，但会增加复杂度。

研究卷积主干时，应报告局部任务收益和远程任务损失，说明长核是否通过训练数据、隐式函数或外部检索补偿了固定先验。

## 41.12 面试追问、误区与练习

**问：卷积为什么适合长序列却没有成为通用 LLM 唯一主干？**

标准回答：卷积有规则局部性和硬件优势，长卷积/隐式核可扩大感受野；但任意内容寻址、变量绑定、ICL 和文档引用更困难，通常需要状态、retrieval 或 attention 补偿。

**问：感受野等于有效上下文吗？**

标准回答：不等于。感受野只说明理论上存在传播路径，信息可能在混合、衰减、门控或数值误差中丢失，需用任务级 recall 验证。

常见误区包括把 dilation 当全局检索、把 FFT 近似直接当低延迟，以及忽略 causal/overlap 边界。

练习：设计三种卷积堆叠达到相同理论感受野，比较参数、kernel 时间、长距复制和变量绑定。

## 41.13 卷积的边界条件

卷积对平移结构和局部模式有强先验，但语言 token 的重要关系可能不是局部的。扩大 kernel 或使用多层 dilation 可以增加感受野，却也会增加边界、padding、计算和信息混合问题。

评估时把局部复制、远距离实体、顺序交换和精确引用分开。卷积在局部任务上的优势不能外推到任意文档推理。

## 41.14 卷积与 SSM 的工程组合

卷积可以作为 SSM 输入预处理或 state update 前的局部混合；也可以在 attention 前减少高频冗余。组合时要验证时间步、padding 和 streaming state 是否一致，避免卷积看到了未来 token。

## 41.15 流式卷积的状态边界

因果卷积在流式场景中只需保留最近 kernel_size−1 个输入或等价状态，但 chunk 边界必须连续。非因果卷积如果读取未来帧，适合离线而不适合实时；同一模型在两种模式下的 mask 和延迟验收条件不同。

用脉冲输入测试边界最直观：把一个事件放在 chunk 末尾，比较一次性、分块和恢复后的输出位置。任何多一位或少一位都可能导致时间对齐错误。

## 41.16 卷积模型的精确引用能力

卷积堆叠可以传播远程信息，却不等于提供了 query-time 的精确寻址。固定卷积核对相邻位置执行相同的混合；即使通过深层堆叠或扩张获得了很长感受野，多个实体、数字和版本号仍可能被压成难以分离的连续状态。Attention 的不同之处在于当前 query 可以根据内容改变读取权重，而不是只能接受固定传播路径。

可以把一个引用任务写成四个约束：正确找到来源位置、保留来源中的原子字段、在多个候选冲突时选择与问题相关的那一个，并在答案中返回正确版本。测试样本应包含“甲的版本是 A17，乙的版本是 B42；大量干扰后询问乙”的复制题，也应包含同格式数字、否定条件和版本更新。只看主题问答会把“语言流畅”误判为“引用正确”。

一个简单的记录方式是：

```math
R_{\mathrm{cite}}
=\frac{N_{\mathrm{source\_and\_field\_correct}}}
{N_{\mathrm{queries}}},\qquad
E_{\mathrm{conflict}}
=\frac{N_{\mathrm{wrong\_candidate\_under\_conflict}}}
{N_{\mathrm{conflict\_queries}}}
```

若卷积模型在局部语法和连续信号上很好，但 `R_cite` 随距离、实体数量或冲突数增加而下降，结论应是“它适合局部/平滑路径，需要显式检索或 attention 完成精确回读”，而不是简单宣布卷积路线失败。这个边界也解释了为什么混合架构常让卷积承担局部模式，再用少量全局路径处理证据对齐。

## 41.17 变量绑定是卷积路线的关键考题

局部模式任务容易让卷积模型看起来很强，但大模型还要处理变量绑定：某个名称在前文绑定了一个值，后文需要根据当前问题选择对应值。可以构造一个简单对照：

~~~text
甲的版本是 A17，乙的版本是 B42。
在大量干扰文本之后，问题是：乙的版本是什么？
~~~

交换实体、增加相同格式的数字、改变证据位置，再测 exact match 和错误引用率。如果模型只学到“最后出现的编号”或“格式最像答案的编号”，说明它拥有传播路径，却没有可靠的 query-time 绑定能力。

卷积并非无法学习这类关系；多层非线性、门控、位置和 attention shortcut 都可能补足它。但这类补足要被单独记录，否则把所有收益都归因于卷积会误解信息流。

## 41.18 卷积长度与实际成本

对直接因果卷积，长度 T、核宽 R 和通道 d 的朴素成本大致为：

~~~math
C_{\mathrm{direct}}=O(T R d)
~~~

FFT 形式在长序列上可能接近 O(T log T)，但还要支付 padding、复数变换、频域缓存和分块重叠的成本。短序列时，直接 kernel 可能因为常数更小而更快；在线 decode 时，重新做 FFT 更可能输给保存窗口的增量更新。

因此压测至少要横跨短、中、长三档，并分别测 prefill、decode、batch 和 chunk。把长序列吞吐数字直接当成逐 token 延迟，或者把一次 FFT 的速度当成 streaming 速度，都是常见误判。

## 41.19 卷积路线的现实演化

卷积序列模型的后续演化并不只有“把 kernel 做得更长”。一条路线是输入依赖的 gate，让模型在事件发生时更新；一条路线是隐式核，用小网络生成不同位置的滤波器；一条路线是与 SSM、attention 或 retrieval 组合，把固定滤波负责的任务限制在最擅长的部分。

判断新模型时，可以沿着三个问题追问：它的 kernel 是固定、可学习还是输入条件的；长程信息是通过传播、递归 state 还是显式回读；线上状态能否被 snapshot、rollback 和迁移。这样既能理解卷积的历史价值，也不会把“长感受野”误写成“通用记忆”。

## 41.20 卷积路线的选择要看查询形态

短卷积、扩张卷积、深度可分离卷积和隐式长卷积分别提供不同的感受野、参数共享和硬件路径。局部语法、音频波形和连续信号通常受益于局部卷积；跨文档精确引用则需要额外 global/ retrieval 路径。感受野扩大不等于任意历史可寻址。

一个公平实验应固定 receptive field、参数量、训练 token 和输出协议，比较局部预测、远距复制、版本冲突、流式恢复、prefill、decode 和 p99。对扩张卷积还要检查栅格化 blind spot：理论感受野很长，但某些位置可能没有有效路径。

## 41.21 卷积的在线状态和 padding 契约

离线一维卷积常用 padding 让输出长度保持不变；在线服务则需要保存最后若干输入、卷积核 revision 和有效长度。每个 chunk 都重新 padding 会造成边界重复或丢失；不同请求共享尾部 buffer 会造成数据泄露。

服务端应比较 full convolution、chunk continuation 和单步更新，记录 reset、取消、batch reorder、状态快照和不同 dtype 的差异。若长卷积走 FFT，在线 decode 还要说明是维护历史、分块重算还是使用近似，不能把 prefill 的 FFT 吞吐当作每 token decode 速度。

## 41.22 causal cache 与在线状态

有限因果卷积可以写成：

```math
y_t=\sum_{i=0}^{K-1}w_i x_{t-i}.
```

在线推理只需保留最近 `K-1` 个输入，但 dilation、chunk、padding 和多层 residual 会改变实际 state。服务端要把 ring buffer 的逻辑位置、dtype、层版本和 owner 绑定起来；batch reorder 或取消时不能把某个请求的历史窗口复制给另一个请求。

长卷积或隐式滤波器可能用 FFT/分块计算提高吞吐，却引入边界和 workspace。评估应分别测 full sequence、chunked streaming、短请求和混合长度，检查输出边界、首 token 延迟、缓存占用和恢复误差。

## 41.23 卷积路线的查询形态实验

卷积对局部模式、平滑趋势和固定感受野很有效，但语言任务还需要变量绑定、远程引用和根据 query 重新选择历史。可以建立四组对照：局部语法、远程复制、两个实体冲突、工具参数引用，分别增加距离、实体数量和卷积层数。

记录 exact match、冲突选择率、引用支持、状态大小、吞吐和 p99。若卷积在局部任务上稳定、在远程任务上下降，说明它提供了有价值的局部路径，但不能单独承担全局证据；这时混合 attention、SSM 或检索比盲目扩大卷积核更可解释。

## 41.24 流式卷积的状态与 padding

在线卷积必须保存足够的左侧历史，且 padding、stride、dilation 和 reset 语义与离线训练一致。请求切换时，上一请求的窗口不能留在 batch slot；chunk 结束时，状态要带位置和有效长度；取消和重试时，要区分已经提交的 token 与临时窗口。

最小测试包括 full sequence 与 token-by-token 对照、不同 chunk 长度、左/右 padding、batch reorder、snapshot/restore 和长时间状态范数。很多“流式效果下降”不是卷积理论问题，而是窗口边界或 padding 被当成真实 token。

## 41.25 硬件效率不能只看理论复杂度

长卷积的理论复杂度可能是线性的，但实际实现还受 FFT/scan、kernel launch、workspace、内存访问、batch 和 state update 影响。短序列小 batch 可能被 launch 开销主导，长序列大 batch 才显示带宽收益；某些形状还会回退到通用实现。

因此应分开报告 kernel、engine 和任务三层结果：卷积算子耗时与显存，完整 prefill/decode 的 TTFT/TPOT/p99，以及局部/远程/工具任务的质量。只有端到端结果同时满足，才可以把卷积路线写成工程收益。

## 41.26 证据范围与路线定位

卷积序列模型的论文和实现可以支持隐式长卷积、门控卷积与局部信息流的公开结论；具体是否适合通用 LLM，要看训练规模、变量绑定、远程检索、硬件 kernel 和 serving 状态。本文讨论的是路线判断框架，不把某个实验结果推广成统一定律。

## 41.27 卷积路线的合理落点

卷积序列模型最有说服力的落点通常不是宣称“重新替代所有 attention”，而是承担局部、平滑、音频或连续流的稳定路径。对于需要精确引用的文档和工具轨迹，可以让卷积/状态先做压缩扫描，再通过检索或少量全局 attention 回读原文。

这种分工应在接口层写清楚：压缩路径输出候选和不确定性，精确路径接收原始证据和来源，执行器只接受通过权限和格式校验的结果。评估要把卷积 backbone 的收益与 retrieval/verification 的收益拆开，否则完整系统的分数会被误写成卷积单独获得的能力。

## 41.28 从感受野到可用长度的三层验证

卷积路线至少有三个不同的长度概念。理论感受野 `R_theory` 是结构上可能影响当前位置的最大范围；数值有效长度 `R_numeric` 是信号经过衰减和有限精度后仍可观测的范围；任务有效长度 `R_task` 是在指定召回、变量绑定或引用验收条件下真正能使用的范围。三者通常不相等：

~~~math
R_{\mathrm{task}}
\le R_{\mathrm{numeric}}
\le R_{\mathrm{theory}}.
~~~

因此扩大 dilation 或 kernel 只能先提高 `R_theory`，不能自动提高远程证据准确率。实验要在多个长度上测 impulse response、信号幅度、远距复制、冲突实体和引用支持；如果 impulse 仍有响应但任务准确率下降，问题是信息混合或可寻址性，而不是没有传播路径。

## 41.29 一个卷积预算的 worked example

假设有 `T=4096` 个 token、通道数 `d=1024`、直接卷积核宽 `R=64`。朴素直接卷积的乘加量级与 `T R d` 成正比，约为 `268M` 个通道级乘加；如果使用 FFT，序列项接近 `d T log_2 T`，约为 `50M` 的对数项，但还要支付正负频率、padding、复数变换、workspace 和 kernel launch。这个数字只用于比较量级，不能直接当设备 latency。

当 `T=128` 时，FFT 的固定成本可能超过直接卷积；当在线 decode 每次只生成一个 token 时，重新做长度 4096 的 FFT 更不划算，应该维护窗口或等价状态。相同的算法在 prefill、长 batch 和 decode 三个阶段可能选择三种不同 kernel。报告“卷积是线性复杂度”时，必须注明序列长度、阶段、batch、dtype 和是否包含状态/工作区。

## 41.30 位置外推和 dilation 的盲区

扩张卷积扩大感受野，但离散采样可能留下栅格化盲区。设第 `l` 层 dilation 为 `d_l`、kernel 宽为 `w_l`，理论感受野可写成：

~~~math
R=1+\sum_l(w_l-1)d_l.
~~~

这个公式没有说明每个输入位置都以相同强度到达输出。若 dilation 组合不合适，某些相对距离只能经过很弱或不存在的路径；序列长度外推时，边界 padding 还会改变有效路径。测试不应只改变总长度，还要平移同一个 needle、改变实体相对距离、交换顺序，并画出位置—准确率矩阵。

如果训练只覆盖短序列，长位置上的 kernel、dilation 和位置编码可能产生周期性别名或幅度衰减。可把训练长度 `T_train` 与测试长度 `T_test` 分开，报告 `R_task(T_test)`、边界误差和引用支持率。长感受野而中间位置召回下降，仍然是失败，而不是“理论上已经覆盖”。

## 41.31 卷积、SSM 和 attention 的最小路由策略

在混合模型中，可以把三类路径看成三种访问模式：卷积提供局部/平滑混合，SSM 提供固定状态的连续累积，attention 或 retrieval 提供 query-time 精确回读。路由不必让每个 token 都运行完整 attention，而可以在检测到数字、实体冲突、引用要求或工具参数时增加显式路径。

路由器要输出不确定性和触发原因，不能只输出一个隐含 gate。对每类请求记录卷积路径成功率、显式回读触发率、额外 token/延迟、引用支持和 fallback。若卷积只负责摘要，系统就不应把摘要状态当作可授权的工具参数；原子证据应重新从可信来源获取并经过 schema/权限验证。

## 41.32 资料边界与小结

Hyena（https://arxiv.org/abs/2302.10866）、S4（https://arxiv.org/abs/2111.00396）和 Mamba（https://arxiv.org/abs/2312.00752）提供了卷积/状态路线的公开证据。具体卷积 kernel 和设备性能需要实测。

卷积序列模型的复兴更可能发生在模块和模态层面：它提供规则局部/长滤波先验，再与 state、attention、MoE 组合，而不是简单回到纯 CNN 语言模型。
