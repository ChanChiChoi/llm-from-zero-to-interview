# 第四十四章：Attention + Convolution + SSM 的模块分工

读一个很长的序列时，模型可能要识别相邻词语的组合、持续跟踪一段过程，也可能要根据当前问题找回前面出现过的某个名称。这些需求看起来都叫“处理上下文”，但不同架构保存和读取历史的方式并不相同。卷积按相对位置混合输入，状态空间模型（state space model，SSM）把前缀写进递归状态，Attention 则根据当前查询读取允许访问的键和值。

因此，“卷积负责局部、SSM 负责长程、Attention 负责全局”只能作粗略记忆。长卷积也能覆盖很远的位置，SSM 可以根据输入选择性更新状态，而 Attention 的可见范围受 mask 限制。理解模块分工，需要沿着信息路径看历史如何保存、当前位置如何读到它，以及这种结构是否适合目标任务。

## 44.1 “局部—长程—全局”只能作粗略提示

先把比较对象限定为因果序列建模：处理位置 $t$ 时，模型不能读取未来位置。这个条件影响卷积的 padding、Attention 的 mask，也决定递归状态只能从过去更新而来。不同实现若采用不同的可见范围，就不能只按模块名称比较。

| 路径 | 历史怎样表示 | 当前表示怎样获得历史信息 | 结构上的限制 |
| --- | --- | --- | --- |
| 因果卷积 | 输入按序列位置排列，核参数按相对位移共享 | 输出按卷积核覆盖的过去位置加权混合 | 局部核只能看到有限邻域；长核虽能覆盖更远位置，权重仍由相对位移决定 |
| SSM | 已读前缀不断更新进状态 | 新输入参与状态转移，输出从当前输入和状态得到 | 递归状态不为每个历史 token 保留单独的键和值；能否保留任务所需细节取决于状态表示和训练 |
| 因果 Attention | 上下文中每个可见位置保留对应的 key/value 表示 | 当前 query 根据与各 key 的匹配，对 value 加权读取 | 可读位置由 mask 限定；存在直接读取路径不等于模型一定找对或正确使用信息 |

这张表比较的是信息流，不是能力排名。卷积核很长并不让它自动变成 query 寻址；SSM 的定长状态也不等于只保留“趋势”；Attention 允许读取某个历史位置，也不保证相关内容未被模型忽略。[第三十章](30-SSM-RNN-CNN-Attention信息流对比.md)从 RNN、CNN、SSM 和 Attention 的信息流出发解释这些差异；这里进一步用它们判断模块组合。

## 44.2 卷积：同一种算子可做局部补充，也可做长核混合

卷积将过去位置按相对距离组织起来。一个短因果核只读取固定邻域，因此适合检验“相邻 token 的组合信息是否有用”这样的结构假设。若卷积层逐通道运算，它可以在不混合通道的情况下先改变每个通道的局部表示；因果 padding 则确保输出不使用未来输入。堆叠多层、使用 dilation 或扩大卷积核，都能把可达的过去位置向外扩展。TCN 对因果卷积与 dilation 感受野的说明见 [Bai 等人的序列建模研究](https://arxiv.org/abs/1803.01271)。

短卷积也可以嵌入 Transformer，而不是替换 Attention。[《Convolution for Large Language Models》](https://arxiv.org/html/2607.18413)在 Qwen3 block 的 17 个位置比较 Conv1D；在该位置消融中，把卷积放在 Q/K/V 投影之后、Attention 聚合之前的配置得到最低的平均 loss 和 perplexity。作者提出的解释是卷积为三种 Attention 输入加入邻域信息，再由 Attention 做后续聚合；论文说明这一机制解释与消融一致，但位置实验没有单独证明因果中间机制。该报告不构成其他模型都应使用同一放置方式的证据。

长卷积则把核扩展到更远甚至整段序列。它可以让一个输出受很早的输入影响，但卷积核仍按相对位移共享权重；它与当前 query 根据内容选择某个任意历史位置，是不同的读取规则。长卷积的参数化、FFT 计算和 Hyena 细节由[第四十一章](41-卷积序列模型复兴.md)展开。

## 44.3 SSM：用递归状态保存前缀的任务相关信息

SSM 在每个时间步接收新输入并更新状态，之后的位置通过这个状态继续获得此前信息。在递归执行时，状态张量的大小由模型状态维度决定，不会像逐位置保存的 key/value 那样随着已读 token 数不断增加。这使“历史能否压进一个有限状态而仍支持目标任务”成为一种可检验的设计假设，而不是 SSM 自动具备的长程能力。

固定线性时不变 SSM 对每个位置使用同一组转移规则，并可写成固定卷积核作用于序列的形式；这层关系由[第二十九章](29-SSM数学直觉.md)和[S4 章节](31-S4核心思想.md)展开。Mamba 则让部分状态空间参数依赖当前输入，使模型可以按内容选择传播或遗忘哪些信息；它仍然通过递归状态传递历史，而不是为每个旧 token 保留一个可供 query 独立寻址的键值条目。[Mamba 原论文](https://arxiv.org/html/2312.00752)描述了这种选择性机制；实现与 scan 路径见[第三十二章](32-Mamba与Selective-Scan.md)。

有限状态并不意味着模型只能记住平滑趋势，也不意味着它不能编码精确内容。它意味着模型必须把对后续任务有用的信息编码进状态；若目标依赖长距离后的精确实体、数字或多个相互独立的事实，就需要专门测试状态是否保留了这些信息。不能用“SSM 天然擅长长程”替代任务证据。

## 44.4 Attention：按 query 访问当前可见的历史表示

Attention 的查询（query）、键（key）和值（value）分别提供当前要读取的表示、匹配依据和可聚合内容。计算时，query 与允许读取的各个 key 比较，得到权重，再按这些权重汇总对应的 value；这就是[Transformer 原论文](https://arxiv.org/html/1706.03762)给出的注意力定义。因果 full attention 下，当前 query 可以直接与前缀中每个未被 mask 的位置比较，所以某个早先 token 存在直接的信息路径。

“可见”要按实际 mask 来理解。滑动窗口会排除窗口以外的位置，稀疏 Attention 也只允许指定连接；[第十九章](19-Sliding-Window与稀疏注意力.md)和[第二十六章](26-稀疏与块稀疏Attention.md)分别讨论这些连接模式。即使位置处于可见范围内，模型是否学会定位并利用它仍是经验问题。Attention 的显式历史访问也不等于外部检索：如果文档没有进入模型上下文，模型内部的 key/value 就不能替它提供该文档。外部资料如何通过检索接入生成过程，由[第四十五章](45-Retrieval-Augmented-Architecture.md)讨论。

## 44.5 融合位置决定路径怎样相互修正

模块组合要说明计算发生在何处，因为相同算子放置不同，后续看到的信息也不同。Qwen3 的局部卷积先改变 Q/K/V 表示，再进入 Attention；因此卷积提供的是局部上下文修正，后续 Attention 仍负责按 query 汇总可见历史。该结构与用卷积替换 Attention 不是一回事。

另一个选择是用长卷积替换主干中的某类序列混合算子，同时保留 Attention 层。Fu 等人的 LongConv 语言建模实验沿用 H3 设置，把长卷积作为 H3 层中 SSM 核的替代，并保留两层 Attention。它说明长卷积可以嵌入仍有 Attention 的模型；该结果不能单独证明纯卷积主干优于 Transformer，也不能把整模型表现都归因于替换的卷积核。方法和实验条件见[ICML 2023 论文](https://proceedings.mlr.press/v202/fu23a.html)及其[原文](https://arxiv.org/html/2302.06646)。

Attention 与 SSM 还可以按层串接，或在同一层并行处理输入；两条路径因此分别经历先后变换，或从共享输入产生并行结果。这两类融合的结构和实验由[第四十三章](43-Attention与SSM混合架构.md)主讲。局部卷积修正、序列混合算子替换、Attention 与 SSM 交错属于不同的设计层级；没有理由假定每个模型都必须同时包含三类模块。

## 44.6 围绕任务需求提出假设，再用证据检验

模块选择可以从任务要访问的历史形态开始，而不是先给架构贴“局部”或“长程”标签：

| 任务中的信息需求 | 可检验的结构假设 | 需要观察的失败边界 |
| --- | --- | --- |
| 预测依赖相邻词语、局部语法或短时模式 | 在主干中加入短因果卷积，可能改善局部表示 | 改变邻域距离或移除卷积后，相关任务切片是否随之变化 |
| 长序列持续输入，且下游目标可由有限状态承载 | SSM 的递归更新可能以受控状态保存任务所需历史 | 增加干扰、延长间隔或改变输入顺序后，目标信息是否仍能从状态读出 |
| 需要对当前问题指定的历史位置做内容相关选择，且来源仍在 mask 可见上下文中 | Attention 提供直接的 query-key 读取路径 | 改变目标位置、相似干扰和 mask 后，是否还能稳定定位目标 |
| 证据尚未进入模型上下文 | 需要评估外部检索路径 | 不应把模型内部三类模块的选择当成补入外部事实的办法 |

这些是假设，不是选型配方。评估时应在尽量匹配模型规模、数据、训练预算、上下文格式和其余架构的条件下，比较替换或移除单一路径后的变化；如果这些因素不能匹配，就明确报告差异。除了总体语言建模指标，还要观察能区分邻域组合、状态保留和精确历史读取的任务切片。一个模块消融若改变了参数量、训练路径或计算预算，也不能把全部分数差异都归因于该模块本身。

质量和资源结论都应绑定具体模型、任务、mask、训练条件与测量实现。理论感受野说明信息路径可能覆盖哪里，状态维度说明递归时携带什么形状的数据，Attention mask 说明哪些历史位置可读；它们都不是独立的质量保证或端到端速度结论。由此得到的是可检验的结构选择：局部卷积、递归状态和显式 Attention 各自提供不同的信息路径，是否组合以及如何组合，取决于任务证据。下一章将讨论历史之外的外部资料如何进入模型。
