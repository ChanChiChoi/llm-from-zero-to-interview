# 第九章：Transformer 的并行性、表达力和 scaling 优势

## 9.1 三种不同的“优势”

第一章已从书系角度说明 Transformer 为什么成为大模型的主要架构之一；第二至第八章已经分别讲过注意力路由、Q/K/V、多头、FFN、残差与归一化、位置表示和 mask。本章进一步核对三类容易混在一起的主张：

1. **并行性：** 训练图中哪些序列位置可以同时计算，位置之间还隔着多长的依赖路径？
2. **表达力：** 给定层数、位置表示、数值和输入范围，模型能够表示哪些函数？理论上的“能够表示”是否意味着训练能找到它？
3. **Scaling：** 在指定模型、数据、训练配方和评估口径下，增加参数、token 或训练计算量与 loss 有什么经验关系？

这三类问题需要不同证据。运算路径短不证明总计算量低；存在性定理不证明样本效率或长度外泛化；一条 loss 曲线也不证明每项下游能力同步提升。

读完本章后，你应能分开说明 Transformer 训练时的位置并行、理论表达结果和经验 scaling 证据，并指出每个结果适用的条件。完整的架构总览见[第一章](01-transformer为什么能成为大模型基础架构.md)；注意力机制与 mask 分别见[第二章](02-self-attention的信息路由本质.md)和[第八章](08-causal-mask-prefix-lm-bidirectional-attention与注意力模式.md)；替代序列架构与归纳偏置见[第十四章](14-Transformer归纳偏置与状态记忆.md)。

## 9.2 并行计算、串行依赖和信息路径

比较架构时，先把三个量分开：一层需要多少计算、序列位置之间有多少步必须依次执行，以及一个位置的信息影响另一个位置时，计算图上的最长依赖路径有多长。Vaswani 等人在 Transformer 原论文中按这一口径比较了标准自注意力、循环层和卷积层。表中符号依次对应序列长度、表示维度和卷积核宽度（$n,d,k$）；复杂度是论文所分析的层结构，不是所有现代实现的统一运行时间模型。

| 层结构 | 单层计算量 | 序列位置上的串行操作数 | 两位置间最长依赖路径 |
| --- | --- | --- | --- |
| 标准自注意力 | $O(n^2 d)$ | $O(1)$ | $O(1)$ |
| 循环层 | $O(n d^2)$ | $O(n)$ | $O(n)$ |
| 卷积层 | $O(k n d^2)$ | $O(1)$ | $O(\log_k n)$ |

这里的串行操作数和路径长度不是同一个量。卷积可以同时处理许多位置，所以它的序列位置串行操作数是常数；但在论文讨论的卷积结构中，远距离信息仍须跨多层传播。循环层则需要先得到上一个时间步的状态，才能算下一个状态。标准自注意力在一层内连接所有可见位置，因此任意一对可见位置的路径长度为常数。[原论文表 1](https://arxiv.org/abs/1706.03762)还指出，在其层计算口径下，当 $n<d$ 时，自注意力的计算量可低于循环层；序列很长时，注意力的成对计算则可能更贵。

因果语言模型的训练也能并行计算整段输入：因果 mask 限制位置 $i$ 读取未来 token，但同一层的各位置都从上一层已经算出的表示开始。层与层之间仍有依赖。生成时则不同：下一个 token 依赖已生成的前文，通常必须逐步产生；训练时的位置并行不等于自回归解码可以一次生成整段。KV cache 怎样减少解码的重复计算由[第十一章](11-kv-cache长上下文推理和显存增长问题.md)主讲。

## 9.3 并行优势不等于更少计算或更短墙钟时间

标准自注意力在一层内计算所有可见 token 对，主要计算量随 $n^2 d$ 增长。循环层的位置计算虽然串行，单层计算量却按 $n d^2$ 增长。因此，不能只看“能否并行”就判断哪种架构总计算量更低。

Transformer 的工程优势在于，投影、注意力乘法和 FFN 中有规则的大矩阵乘法，可映射到 GPU/TPU 的矩阵计算单元；NVIDIA 的矩阵乘法指南和 Google TPU 架构文档分别说明了 GPU GEMM 的分块执行和 TPU 的 MXU 矩阵单元（[NVIDIA 指南](https://docs.nvidia.com/deeplearning/performance/dl-performance-matrix-multiplication/index.html)、[Google TPU 架构](https://docs.cloud.google.com/tpu/docs/system-architecture-tpu-vm)）。这让训练系统有机会获得高吞吐；它不保证每种长度、batch、硬件和实现都更快。墙钟时间还受显存读写、kernel、通信、并行划分和设备利用率影响。Vaswani 等人的复杂度表分析的是操作数和依赖路径，不是对任意现代系统的吞吐承诺。

本章只用这一点解释“并行计算为什么有价值”。注意力 pair 数与显存规模由[第十章](10-o-n2-attention的计算与显存瓶颈.md)展开；kernel 和数据搬运由[第二十章](20-FlashAttention与PagedAttention.md)展开。实际性能结论应同时说明 workload、硬件和实现，并与对应基线比较。

## 9.4 从动态路由到“能够表示”

自注意力根据当前输入形成内容相关的读取权重：每个 query 对可见位置的 key/value 进行选择和汇总。因而，一层的计算图可以直接连接任意一对可见位置；这种连接能力不同于固定卷积邻域，也不同于必须逐步传状态的循环结构。Q/K/V 的读写机制见[第三章](03-qkv-attention-head与表示子空间.md)。

但“有一条直接路径”不等于信息一定被准确读出。注意力权重如何分配、value 携带什么、后续 FFN 怎样变换，都会影响最终表示。Transformer 的函数能力来自注意力的上下文映射、FFN 的逐位置非线性变换以及多层组合；相应模块已在[第三章](03-qkv-attention-head与表示子空间.md)、[第五章](05-ffn-swiglu-gated-mlp与moe-ffn.md)和[第六章](06-residual-layernorm-rmsnorm-prenorm与训练稳定性.md)分别讲解。

理论表达力研究问的是：某类模型的参数中是否存在一组取值，能实现或近似目标函数。它本身不回答优化器能否找到这些参数、需要多少数据和计算、模型能否推广到训练长度之外，或真实任务是否使用了所需的信息。

## 9.5 不同假设下的表达力结果

下列结果看起来有时相互冲突，实际回答的对象并不相同。

| 研究 | 设定与结果 | 能说明什么 | 不能直接说明什么 |
| --- | --- | --- | --- |
| Yun 等人，ICLR 2020 | 无位置编码时，Transformer 可逼近连续、置换等变且紧支撑的序列到序列函数；加入可训练的位置编码后，可在紧致域上逼近一般连续序列到序列函数。 | 在指定输入域和架构构造下，Transformer 具有通用逼近能力；注意力与 FFN 分别参与上下文映射和值映射。 | 不证明高效表示、容易训练、需要的样本量较少或能泛化到任意长度。论文指出最坏情况构造的参数需求可能随问题规模急剧增长。 |
| Hahn，TACL 2020 | 固定自注意力模型并让输入长度增长；对 hard attention 的形式语言识别给出限制，对 soft attention 则给出 PARITY 和 2DYCK 下一符号交叉熵的渐近限制。soft-attention 结论依赖固定深度、固定参数等分析条件。 | 某些自注意力模型在无限增长的形式序列上有可证明的局限；直接连通并不自动实现任意算法。 | 不说明 Transformer 在自然语言任务上普遍无效，也不否定有限最大长度下的逼近结果。 |
| Chiang 与 Cholak，ACL 2022 | 构造可在任意长度上识别 PARITY 和 FIRST 的 Transformer；构造模型的交叉熵仍可随长度趋近随机基线，加入 LayerNorm 后论文将交叉熵压到任意接近零。他们也报告训练出的模型可能无法把较短字符串上的 FIRST 规则推广到更长字符串。 | 识别准确率、置信度、交叉熵、架构构造和训练泛化是不同问题；一个指标上的结果不能替代其他指标。 | 不意味着任意模型都能自动学会这些规则，或形式语言构造能预测自然语言表现。 |

Yun 等人的结果一项针对紧支撑函数族，另一项在固定紧致域上使用可训练位置向量；它们都是存在性结论。Hahn 分析的是同一个受限模型应对长度不断增长的输入时，特定形式语言任务的表现。即使输入长度有界，逼近任意函数所需的构造也可能很大。Chiang 与 Cholak 进一步展示，模型可以在分类准确率上正确，却随着输入变长而对结果越来越不确信；调整架构部件可以改变交叉熵，但训练得到的模型仍可能无法泛化到更长字符串。[Yun 等人](https://openreview.net/forum?id=ByxRM0Ntvr)、[Hahn](https://aclanthology.org/2020.tacl-1.11/)和[Chiang 与 Cholak](https://aclanthology.org/2022.acl-long.527/)的结果合起来提醒我们：读表达力定理时，要同时看输入长度范围、位置表示、注意力形式、层数/参数约束、目标指标和函数域。

## 9.6 Scaling law 拟合的是指定条件下的 loss

Scaling law 通常研究语言模型的 held-out cross-entropy 如何随规模变量 $X$ 变化。三个量的符号依次为（$N,D,C$）。任一次单变量拟合中，用 $X$ 标出当前所研究的规模变量。

一个常见的单变量拟合形式如下：

```math
L(X)\approx L_{\infty}+A X^{-\alpha}
```

其中系数和指数来自实验拟合。比较不同规模变量时，其他训练条件和评估口径也必须明确。

Kaplan 等人使用其 GPT 类模型、训练数据和预算范围，报告 held-out loss 与模型规模、数据规模和计算量之间的幂律关系。[原论文](https://arxiv.org/abs/2001.08361)支持的是这些实验条件下 loss 可用于比较和规划的经验趋势。它不提供跨架构、数据分布、训练配方和规模范围通用的固定指数，更不能从训练交叉熵直接推出数学、工具调用、安全或长上下文能力的同幅度提升。

小规模实验可以帮助估算更大训练的 loss 趋势，但外推仍需把目标模型和实验设置对齐，并保留预测误差。曲线适合回答“在这组条件下 loss 怎样变化”，不自动回答“哪个模型最适合部署”。

## 9.7 Chinchilla 的结论是固定训练预算下共同规划

“Compute-optimal”必须带上优化目标和成本边界。Hoffmann 等人的 Chinchilla 研究针对固定的预训练计算预算，考察参数量与训练 token 数怎样分配，以改善训练结果。他们在约 70M—16B 参数、5B—500B token 的范围训练了 400 多个模型并拟合预算关系；论文报告，在该研究设定中，参数量翻倍时训练 token 也应大致翻倍。随后，他们以同 Gopher 训练计算预算训练 70B 参数、1.4T token 的 Chinchilla；论文报告它在多数所测任务上超过 280B 参数、约 300B token 的 Gopher。[原论文](https://arxiv.org/abs/2203.15556)因此支持“不能只堆参数，还要给模型足够训练数据”这一预算结论。

这个结果不应改写成跨模型、数据和目标都适用的固定 token/parameter 比。数据重复情况、数据质量、模型族、训练目标和可用计算都会改变规划；若优化目标还包括推理成本，也要单独把服务阶段的预算纳入，而不是把预训练 FLOPs 的最优点当成部署最优点。数据质量和配比的详细主题见[第九册第三章](../../book-09-data-engineering/chapters/03-清洗过滤与质量评分.md)和[第五章](../../book-09-data-engineering/chapters/05-data-mixture与配比.md)。

## 9.8 数据处理会改变拟合曲线

训练 token 数相同，不代表训练数据提供了相同的内容和监督信号。数据混合、筛选、去重、重复曝光和改写等处理可能改变目标 loss 以及模型从 token 中得到的信息；因此不能只用 token 总量描述训练数据。

Ardalani 等人在 ICLR 2026 的研究使用 23 组 QualityPajama 数据，训练了 100M 至 8B 参数、100M 至 200B token 的 2,000 多个模型，比较去重、启发式过滤和 LLM 引导改写。他们报告这些干预会改变拟合曲线的系数与指数，且计算最优的数据量/参数量比例依处理方案而变化。[这项研究](https://proceedings.iclr.cc/paper_files/paper/2026/hash/6544c0b53cc1ea51d0c7086b536830a8-Abstract-Conference.html)说明数据处理会影响特定实验下的 scaling 估计；它没有给出可通用于其他语料的单一“质量分数”或固定配方。

## 9.9 下游能力的变化还受任务与指标影响

Wei 等人把 emergent ability 定义为：在较小模型上看不到、较大模型上出现，而且不能由较小模型表现的简单外推预测的能力。[这篇综述性论文](https://arxiv.org/abs/2206.07682)讨论多个模型系列和评估任务中的此类现象。PaLM 报告也称，在其 BIG-Bench 评估中，约四分之一任务随 8B、62B、540B 三种规模出现不连续提升；这是特定模型系列、任务集合与评分口径下的报告，不是所有能力的共同增长曲线。[PaLM 技术报告](https://arxiv.org/abs/2204.02311)

Schaeffer 等人提出了另一种解释：离散或非线性评分可能把平滑的能力变化显示成阈值式跃迁；在 GPT-3/InstructGPT、BIG-Bench 以及视觉任务上的分析支持仔细检查指标和样本分辨率。[他们的 NeurIPS 2023 研究](https://papers.neurips.cc/paper_files/paper/2023/hash/adc98a266f45005c403b8311ca7e8bd7-Abstract-Conference.html)提示不要仅凭某条 accuracy 曲线宣布普遍涌现，也不构成“所有涌现现象都是假象”的证明。

分析下游 scaling 时，应固定模型系列和版本，写明任务与样本数、prompt/评测器、评分指标和重复运行条件；能获得时同时报告连续指标、离散指标及不确定性。GPT-3 的上下文学习机制和评估细节由[第十二章](12-in-context-learning与显式token检索能力.md)主讲。

## 9.10 把架构优势与 scaling 证据分开复述

看到“Transformer 易于并行”，先问比较的是序列位置的串行依赖、总操作数还是实测墙钟时间；三者不能互换。看到“Transformer 表达力强”，先问定理覆盖哪类输入函数、哪些位置表示和长度，以及模型是否只被证明存在。看到“模型遵循 scaling law”，先问 loss 或下游指标、数据与配方、计算预算、模型范围和外推误差。

因此，本章得到的是有条件的结论：标准自注意力缩短可见位置之间的路径，并允许训练时并行计算序列位置；它为连接关系灵活的模型提供了表达机制，但理论可表示性不等于可靠学得；经验 scaling 让指定指标下的预算规划更有依据，却不能替代下游评估。并行计算的机会伴随平方级注意力工作量，下一章将具体计算这项代价。
