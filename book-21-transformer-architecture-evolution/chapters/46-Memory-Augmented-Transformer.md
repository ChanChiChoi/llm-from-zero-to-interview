# 第四十六章：Memory-Augmented Transformer 与长期记忆架构

第十四章把状态记忆作为序列架构的一类归纳偏置；第十一章解释标准 KV cache 怎样保留当前生成前缀的逐层表示，以避免重复计算。本章继续追问：一段输入处理完之后，架构会把什么表示留给后续步骤？新输入如何寻址这些表示？读出的内容又怎样参与下一步预测？

这里的“长期”指记忆状态能跨越当前片段或步骤而被后续计算访问，具体能否跨文档、跨任务或跨会话，由各架构的状态生命周期决定。它不自动等于一个保存用户画像、聊天记录并处理权限的应用服务。读者应能比较记忆表示、写入与读取机制、模型内融合位置和代价边界，并把架构记忆同上下文、推理缓存、外部语料检索及 Agent 运行状态分开。

## 46.1 模型架构里的记忆：表示被留到何时、供谁读取

“模型记住了历史”可能指几种不同事情。当前上下文窗口保留原始 token，当前位置可按注意力规则读取它们；常规推理 KV cache 保留这些位置在各层产生的 key/value，供同一生成过程的后续 token 复用。后者主要避免重算当前前缀，具体生命周期由推理请求和模型实现决定，细节见[第十一章](11-kv-cache长上下文推理和显存增长问题.md)。

Memory-Augmented Transformer 则在模型的信息路径中加入一个可被后续计算读取的状态。这个状态可以是过去 token 的注意力 K/V、被编码的情景向量，或随输入递归更新的矩阵。不同论文可能在一个长文档、一个情景或一条交互轨迹内维护它；“长期记忆”不能单凭名称理解为跨用户、跨服务重启保存的事实档案。

还要区分状态的来源。第[四十五章](45-Retrieval-Augmented-Architecture.md)讨论从外部语料按请求检索证据；第[四十九章](49-Agentic-Model-Architecture.md)讨论 Agent 如何保存可复用事实、任务 checkpoint 和工具结果。两者可以接入 Transformer，但分别以外部文档或运行时状态为对象。第[十四章](14-Transformer归纳偏置与状态记忆.md)介绍递归状态记忆的概念，本章进一步比较把记忆接入模型后的具体结构。

## 46.2 记忆如何写入、读取并参与预测

跨架构比较时，可以沿同一条信息路径追踪四个问题：过去内容怎样编码成状态；状态何时更新或丢弃；当前输入如何找到相关状态；读出结果在模型的哪一层与当前表示融合。各方法对这四步的回答并不相同：有的方法保留可寻址的 K/V 项，有的方法把许多经历压进固定形状的状态，还有的方法把记忆读取器作为独立网络接在主干旁边。

写入和读取也不必由同一计算负责。状态可能在处理当前片段后直接追加，也可能由门控递归更新；查询可以做近似近邻查找、通过注意力读取，或由学习到的关联记忆权重映射到潜在表示。融合可以进入某一注意力层、旁路网络或 Transformer block 内的并行分支。因此，不能把所有 Memory-Augmented Transformer 都画成“向量库检索后拼进 prompt”，也不能假定任何模型输出都会被保存为下一轮记忆。

记忆状态还带有训练边界：旧表示是否参与反向传播，生成记忆的编码器是否会随训练变化，在线新信息如何写入，以及读写器如何学会使用状态。这些选择会影响记忆是否陈旧、模型怎样利用它，以及历史长度增加时的存储形态。下面的架构分别展示了这些设计轴。

## 46.3 Memorizing Transformer：以外部 K/V 缓存访问旧 token

[Memorizing Transformer](https://arxiv.org/abs/2203.08913) 保留 decoder-only Transformer 的局部自注意力，并在靠近顶部的一层增加对外部 K/V 记忆的读取。长文档被分成连续片段；处理当前片段时，查询既计算局部注意力，也用近似 kNN 从过去缓存里为每个 query 找到相似 key，再对取回的 value 做注意力汇总。一个按 head 学习的 gate 合并局部与记忆两路结果。

片段处理后，当前片段的 K/V 被追加到记忆；记忆达到容量限制时，旧项会被丢弃。模型不对已经缓存的旧 K/V 反向传播，因此可以复用较大的历史状态。代价是这些 key/value 由较早的模型参数产生；训练继续更新参数时，新旧表示可能分布不一致。论文把这称为 memory staleness，并研究了归一化及小记忆适配等缓解方式，不能据此假定所有缓存都始终与当前模型对齐。

这项设计针对的是模型在长文档中访问先前 token 表示的路径。论文训练时按文档顺序处理片段，并在新文档开始时清空相应记忆；它不等于存储用户偏好或跨会话事实的产品记忆服务。作者在书籍、长网页、数学论文、代码和形式化证明等语言建模任务中测试不同记忆大小，报告了特定设置下的改善；这些结果不能直接代表问答系统、任意任务或所有模型规模。

## 46.4 LongMem：分离历史编码与记忆读取

[LongMem](https://arxiv.org/abs/2306.07174) 针对同一个网络既生成缓存表示、又学习读取它时可能出现的陈旧问题，将两项工作交给不同组件。冻结的 backbone LLM 编码过去片段，并把指定层产生的 K/V 放入缓存记忆库；轻量、可训练的残差 SideNet 处理当前输入，按 query 从记忆中检索相关 K/V，再把读出结果融合进当前表示。

由于适配阶段冻结了历史编码器，SideNet 的训练不会同时改写生成缓存项的参数；这样设计是为了减少编码端更新带来的表示漂移。它仍然依赖记忆库里有什么、检索是否找到相关项，以及 SideNet 是否能正确融合读取结果。论文测试了长文本建模和带有大量示例的 in-context learning；例如 ChapterBreak 识别成绩属于论文给定模型、数据和训练设置，不能推广为所有长上下文任务的固定优势。

LongMem 的记忆内容可以是过去文本片段的 K/V，也可以是与下游任务相关的示例。它与普通向量库的主要差别不在“有没有检索”，而在于读出的模型内部表示如何进入 SideNet 和生成主干。记忆容量、更新方式、编码器版本和读取网络共同定义了这条架构路径。

## 46.5 Larimar：用情景记忆快速更新事实

[Larimar](https://proceedings.mlr.press/v235/das24a.html) 面向新事实到来后快速更新模型行为的问题。它把输入编码成潜在向量，并通过读写权重将一组情景存入固定形状的关联记忆矩阵；解码器再读取相应潜在表示，生成受记忆条件影响的输出。训练时，编码器、记忆读写机制与解码器共同学习如何利用情景记忆。

部署时收到新事实，Larimar 可以通过一次线性最小二乘式的记忆更新写入潜在矩阵，而不对主模型做梯度微调；读取该事实时，查询编码映射到相应记忆读出，再条件化解码器。论文展示了事实编辑和选择性遗忘实验。这种做法不同于保存原文段落、再用文档相似度取回证据：记忆主要以模型学会读写的潜在表示存在，解码结果也不自动带有可引用的原始文档。

论文的结论限于其事实编辑、改写查询和遗忘任务及所测模型。记忆矩阵可更新，不等于任意外部索引、缓存或备份都能同步删除；模型在基准中忘掉某项事实，也不能被解释为通用隐私删除保证。

## 46.6 MemT-1.0：把递归状态作为原生记忆

[MemT-1.0](https://arxiv.org/abs/2610.26825)（2026 年 10 月发布的预印本）把记忆块加到选定的 Transformer 层中：原有注意力路径与 memory attention 并行计算，然后共同进入后续 block。它包含动态 local memory state 和可训练的 hyper memory 参数；在线交互期间，参数保持固定，动态状态则依据输入更新，并参与后续 token 的记忆读取。

该论文用 Gated DeltaNet-2 的稳定 token 级更新机制来写入动态状态。与保留每个历史 token 的 K/V 列表不同，这种结构把过去信息不断压入由架构参数确定形状的状态；在固定配置下，状态本身不会随已处理 token 数逐项增长。由此得到的是一种不同的信息取舍：计算可访问压缩后的历史状态，但状态并不保留可逐条寻址的原始 token 记录。

论文报告，在 BEAM 任务构造的 128K 历史长度下，MemT-1.0-Nano 相对 full-context KV cache 的端到端推理速度约为 1.86 倍，并将持久状态存储降至约 1/66。作者的测量使用特定模型、两张 GPU、batch size 1 和固定 128-token 输出；短历史时 MemT 较慢，优势随历史长度变化。因此这些数字说明该方案在所测长历史条件下的取舍，不能推导成任意部署场景的普遍加速或容量保证。

## 46.7 按表示、更新和任务比较架构边界

| 架构 | 主要保留的状态 | 读取与融合路径 | 主要设计取舍 |
| --- | --- | --- | --- |
| Memorizing Transformer | 过去片段的逐 token K/V | 近似 kNN 选取候选，再与局部注意力结果门控融合 | 保留较细粒度历史表示；缓存达到容量上限前随保留 token 数增长，旧表示也可能陈旧 |
| LongMem | 冻结主干生成的过去片段 K/V | 可训练 SideNet 检索并联合注意力融合 | 编码器与读取器解耦；效果仍依赖检索覆盖和 SideNet 学习 |
| Larimar | 输入情景的固定形状潜在关联记忆 | 读写权重寻址潜在状态，读出条件化解码器 | 支持快速事实更新与论文设置内的选择性遗忘；不直接返回原文证据 |
| MemT-1.0 | 每个指定层的动态压缩状态及训练得到的记忆参数 | token 级状态更新，并以并行 memory attention 参与 Transformer 计算 | 固定配置下状态大小不随历史逐项增长；历史经过压缩，不能视作原 token 索引 |

这几类架构要用不同任务检查。长文本语言建模和跨片段预测能测试模型是否利用较早表示；多示例 in-context learning 检查记忆读取是否改善当前任务；事实编辑与选择性遗忘检查新信息能否写入，以及覆盖旧信息时是否保留无关事实；多轮交互还应检查噪声、冲突状态和后续回答。跨论文的分数并不处在同一任务或评测协议下，不能据此排一个总名次。评估时也要把“状态写进去了”“相关内容读出来了”和“模型据此正确回答”分开观察。

最后用信息来源和生命周期区分相邻概念：标准 KV cache 主要复用当前请求的解码状态；本章架构记忆让过去表示在后续片段或轨迹中重新参与模型计算；RAG 在请求时从外部语料取得证据；Agent 记忆保存外部任务状态或可复用事实。某个系统可以同时使用这些机制，但它们的存储对象、读写责任和可验证结果不同。架构增加了一条信息路径，并不会自动保证记忆可靠、读取得当或输出正确。
