# 第 59 章 主流模型创新点横向对比：架构、训练与公开证据

第五十一至五十八章分别追踪 GPT、compute-optimal training、InstructGPT/ChatGPT、LLaMA、Mistral/Mixtral、多模态模型、开放权重训练工程和 DeepSeek 的固定版本案例。本章把这些案例放进同一张比较地图：每项变化发生在模型的哪一层，报告或模型卡直接披露了什么，以及哪些问题仍没有足够证据回答。

这张地图不产出一个总排名。不同报告的模型版本、训练数据、提示、评测协议和披露范围并不相同；把结果压成单一分数会丢掉这些差别。我们要练习的是看清变化位置和证据边界。序列架构家族的机制对照见[第四十二章](42-替代架构横向对比.md)，尚在发展中的下一代结构与判断方法留给[第六十章](60-下一代架构判断框架.md)。

## 59.1 比较对象：名称、版本和证据层次

拿到模型名时，先确定它指哪个版本和 checkpoint。一个家族名可能覆盖多种训练阶段、大小、模态和发布接口；只比较名字，容易把架构、行为和产品能力混成同一件事。

### 59.1.1 把模型与报告固定到具体版本

“LLaMA”“Gemini”“DeepSeek”都不是单一模型配置。做横向比较时，至少要能说出论文或模型卡对应的版本、checkpoint 身份和资料修订版。例如，DeepSeek-V2 技术报告、V3 技术报告和 R1 论文描述的不是一套未分阶段的配置；[R1 论文](https://arxiv.org/abs/2501.12948v2)明确把 R1/R1-Zero 建立在 V3-Base 上。具体版本关系见[第五十八章](58-DeepSeek-V2-V3-R1架构训练.md)及[对应研究记录](../../research/deepseek-v2-v3-r1-architecture-training-2026-11-24.md)。

### 59.1.2 区分架构变化、训练变化与使用接口

比较时先问差异属于哪一层：模型内部模块如何连接、训练数据和目标如何变化、后训练怎样改变输出行为，还是用户能通过什么接口输入图像/文本/工具请求。InstructGPT 的监督微调和偏好训练改变了模型如何响应指令，但不能仅凭它们推出 backbone 变更；R1 是 V3-Base 上的后训练路线，不是另一个全新架构。图像输入也只能说明公开接口接受图像，不能单独说明视觉编码器在哪里或如何接入。

### 59.1.3 区分直接披露、受限推断与未知项

报告里明确写出的结构或训练阶段，是直接披露；从表格中的配置字段能够读出的信息，只支持与字段含义相称的有限推断；来源没有公开的内容则仍是未知。比如 [GPT-4 技术报告](https://arxiv.org/abs/2303.08774)说明它不披露模型规模、硬件、训练计算、数据构造和训练方法。外部读者不能根据聊天表现、API 名称或排行榜结果把这些空白补成架构事实。

## 59.2 架构改动落在哪条信息路径

“采用了某个组件”只说明架构的一部分。还要看组件放在哪里、改了什么信息路径、与哪些旧组件共同工作，以及公开证据是否能把观察到的结果归因到这一项改动。

### 59.2.1 组件组合与继承不等于单项发明

LLaMA 报告描述了 RMSNorm、SwiGLU 和 RoPE 等组件在其模型中的组合。[原始报告](https://arxiv.org/abs/2302.13971)也引用了这些组件各自的先行工作；将它们组合到一个公开模型系列中，不等于发明这些组件。读 LLaMA 结果时，应把报告直接说明的模型配置和训练条件放在一起看，不把质量变化归结为其中某一个模块。组件机制由[第四章](04-mha-mqa-gqa-mla的演进与trade-off.md)、[第七章](07-position-encoding总览-sinusoidal-learned-relative-rope-alibi.md)及前序基础章节展开；LLaMA 家族的版本线由[第五十四章](54-LLaMA现代开源LLM基线.md)负责。

### 59.2.2 注意力与历史状态读取的不同改法

Mistral 7B 的 GQA 和滑动窗口注意力分别改变 K/V head 的共享方式与每层直接可见的历史范围；DeepSeek-V2 的 MLA 则用低秩 latent 表示历史 K/V 内容，并另行保留位置相关的 key 路径。这些结构分别见 [Mistral 7B 论文](https://arxiv.org/abs/2310.06825)和 [DeepSeek-V2 技术报告](https://arxiv.org/abs/2405.04434v5)。它们都涉及注意力历史和缓存，却改变了不同对象，不能统称为一种“高效注意力”。具体机制与条件分别见[第四章](04-mha-mqa-gqa-mla的演进与trade-off.md)、[第十一章](11-kv-cache长上下文推理和显存增长问题.md)、[第十八章](18-RoPE与长上下文位置外推.md)和[第十九章](19-Sliding-Window与稀疏注意力.md)。

因此，比较报告时应沿用来源自己的口径：GQA 的 K/V head 数、窗口大小、总上下文字段、MLA 的缓存表示分别描述不同事实。某个模型在一篇论文的对照设置中减少了某项成本，不能直接推导出所有实现、输入长度和硬件上都会得到相同速度或显存收益。

### 59.2.3 稠密 FFN 与条件专家的参数口径

Mixtral 8x7B 保留 Mistral 7B 的其余架构，并把每层 FFN 替换为八个专家；每个 token 由路由器选择两个专家。[Mixtral 原论文](https://arxiv.org/abs/2401.04088)和 DeepSeek-V2/V3 报告也公开了各自 MoE 结构。这里的总参数、每 token 激活参数和专家路由规模分别回答“模型包含多少权重”“一次 token 计算会用哪些专家”等问题。

激活参数少于总参数，并不意味着权重常驻内存、设备间通信、路由开销或端到端延迟会按同一比例下降。[Mixtral 论文](https://arxiv.org/abs/2401.04088)明确提醒 serving 内存成本仍随总稀疏参数规模增长，并报告了专家路由及设备负载相关开销。一般 MoE 路由和稀疏训练/服务取舍见[第二十一章](21-MoE路线Switch-GShard-Mixtral-DeepSeek.md)和[第二十二章](22-Dense与MoE训练服务trade-off.md)；本章只按固定模型报告比较公开结构及其数字口径。

## 59.3 训练和任务适配带来的变化

模型表现不仅由架构决定。规模、训练数据、计算预算、训练阶段和输入提示都可能改变评测行为；不同报告同时改动多项因素时，整体结果不能自动回答哪项变化起了作用。

### 59.3.1 Scaling、上下文学习与计算预算是不同主张

GPT-3 论文评估了 zero-shot、one-shot 和 few-shot 设置：任务说明和样例放在上下文中，评估期间不做梯度更新或 fine-tuning。[原始论文](https://arxiv.org/abs/2005.14165)说明了这些评估条件。这说明论文在其任务和条件下观察到上下文条件化行为；它不是一项计算最优训练配置实验。

Chinchilla 研究的问题不同：在固定训练计算预算下，模型参数量与训练 token 应怎样分配。[原始论文](https://arxiv.org/abs/2203.15556)将 Chinchilla 与 Gopher 放在相近计算预算下比较。它与 GPT-3 都涉及模型规模，但约束、目标和比较基线不同；不能把两项结果拼成同一条受控架构曲线。[第五十一章](51-GPT-decoder-only-scaling-ICL.md)承担 GPT 谱系与 ICL 的历史说明，[第五十二章](52-Chinchilla-PaLM-compute-optimal.md)解释 compute-optimal 研究与 PaLM 的训练系统披露。

### 59.3.2 指令微调和对话发布改变使用方式

InstructGPT 论文将监督微调、偏好比较、奖励建模和强化学习描述为一条后训练路线；[原始论文](https://arxiv.org/abs/2203.02155)给出其训练阶段和评估条件。[ChatGPT 的 2022 年发布说明](https://openai.com/index/chatgpt/)则提供了面向多轮交互的产品入口。二者在读者使用层面改变了“模型如何被要求完成任务”，但不能由此推出底层 decoder-only 主干被替换。

比较时要分别说清训练报告中的流程、论文所测模型和产品发布物；不要把 ChatGPT 产品表现写成 InstructGPT 某一训练阶段的独立因果效果。RLHF 的通用算法由第五册主讲，本书[第五十三章](53-InstructGPT-ChatGPT-RLHF.md)聚焦这一历史转折及其证据边界。

### 59.3.3 开放权重报告披露的数据和配方不等价

Qwen2.5、Llama 3.1 与 Gemma 2 报告展示了不同的训练工程信息：包括预训练 token 规模、数据筛选和混合、长上下文阶段、训练基础设施、蒸馏及不同版本的使用条款（见 [Qwen2.5](https://arxiv.org/abs/2412.15115)、[Llama 3 report v3](https://arxiv.org/abs/2407.21783v3)和 [Gemma 2](https://arxiv.org/abs/2408.00118)）。它们的公开维度并不完全相同，因此不能只拿一个数据量字段来判断哪家训练更好。

即使权重可以下载，也不代表所有训练语料、过滤中间结果、完整配方和许可证条件都相同或齐备。报告中的数据 token 数是发布方对特定版本的陈述，不单独证明数据质量、单位算力效果或能力增益的原因。细节见[第五十七章](57-Qwen-LLaMA3-Gemma训练成熟化.md)和[研究记录](../../research/open-weight-training-engineering-qwen25-llama31-gemma2-2026-11-24.md)；数据工程和训练流程由第五册主讲。

### 59.3.4 DeepSeek 的 MTP 与 R1 后训练不应混成架构代际

DeepSeek-V3 报告把 MTP 描述为训练中预测后续 token 的辅助目标，并讨论了推理时可丢弃预测模块或复用模块的方案（[V3 技术报告](https://arxiv.org/abs/2412.19437v2)）。训练目标、实际推理实现和速度结果属于不同主张。[DeepSeek-R1 论文](https://arxiv.org/abs/2501.12948v2)则把 R1-Zero/R1 建立在 V3-Base 上，介绍了不同后训练阶段；它没有因此成为新的 backbone 架构系列。

所以“DeepSeek 做了什么创新”不能只给一个总答案：MLA/MoE 是结构层面的公开变化，MTP 是训练目标及可选推理复用，R1 是 V3-Base 上的后训练路线。每项结论回到对应报告、checkpoint 和评测条件，详见[第五十八章](58-DeepSeek-V2-V3-R1架构训练.md)。

## 59.4 多模态、长上下文与披露边界

多模态案例常把接口、模型结构和评测结果并列发布。它们互相有关，却不能互相替代：接受某种输入不等于公开了内部处理拓扑，能处理很长的输入也不等于每个任务都能稳定找到其中的证据。

### 59.4.1 输入模态和产品接口不等于内部拓扑

Gemini 1.0 报告给出了一些高层架构和多模态训练描述（[技术报告](https://arxiv.org/abs/2312.11805)）。GPT-4V system card 与 Claude 3 model card 能支持它们在相应发布版本中接受图像输入及公开的高层训练/评估信息（[GPT-4V system card](https://cdn.openai.com/papers/GPTV_System_Card.pdf)，[Claude 3 model card](https://assets.anthropic.com/m/61e7d27f8c8f5919/original/Claude-3-Model-Card.pdf)），但不足以确定视觉编码器类型、融合点、图像 token 化路径或所有模型版本都共享同一设计。

因此可以比较“公开报告披露了什么”，不能把模态接口直接改写成各模型的内部组件图。相应公开材料的版本和阅读范围见[第五十六章](56-Gemini-Claude-GPT4V系统能力.md)及[研究记录](../../research/gemini-gpt4v-claude3-disclosure-evidence-2026-11-24.md)；多模态模型的通用结构由第十五册主讲。

### 59.4.2 上下文窗口和任务级有效性分开比较

上下文窗口字段、报告中实际测试的输入长度和具体任务成绩，是三类不同信息。长上下文实验还受到模型版本、材料分布、needle 位置、问题类型和评分协议影响。Gemini 1.5 与 Claude 3 的 needle-in-a-haystack 结果应分别按各自材料解读（[Gemini 1.5 技术报告 v1](https://arxiv.org/abs/2403.05530v1)，[Claude 3 model card](https://assets.anthropic.com/m/61e7d27f8c8f5919/original/Claude-3-Model-Card.pdf)），不能直接排名，也不能代表长文综合理解或所有信息位置都同样可用。

阅读这类结果时，应把“模型接收了多长的输入”和“模型在指定任务中利用了哪些证据”分开。上下文使用问题回链本册第十二、十三章及第七册相应评估章节；本章不重复长上下文评测流程。

### 59.4.3 披露不对称时结论也必须不对称

GPT-4 报告明确将模型架构（包括规模）、硬件、训练计算、数据构造和训练方法列为未披露内容（[技术报告](https://arxiv.org/abs/2303.08774)）。Gemini 报告、模型卡和发布说明会在各自范围内公开更多或不同字段，但没有哪个单一材料因此自动提供了完整模型实现。

当一个模型有报告架构、另一个只有产品接口和评测卡时，二者能比较的部分有限。比较表里保留“未知”比把空白填成行业猜测更有信息量；两者不同的披露粒度也不构成模型能力或质量的高低证据。

### 59.5.2 沿矩阵读出跨案例关系

矩阵中有些案例主要说明组件位置，有些说明训练预算或后训练，还有些只能确认产品接口和有限的发布评测。横向阅读时，保持这些坐标分开：窗口长度不是架构图，预训练 token 数不是数据质量分数，激活参数不是 serving 成本，论文 benchmark 也不是未披露内部结构的替代证据。

矩阵的“未知”并非缺页。它告诉我们现有公开材料允许说到哪里，也提示不同案例之间哪些问题暂时无法对齐。若要比较运行速度、质量或成本，还需要相同任务、版本、系统配置和测量口径；这些实测和部署设计由相关训练/推理书册承担。

## 59.6 横向比较能够支持的结论

八组案例共同显示，模型家族的演进往往横跨架构、训练和发布方式，但各项变化并不共享一个因果层。比较的价值在于把每项结论放回正确对象和证据，不在于替模型生成一张没有条件的总榜单。

### 59.6.1 不同创新轴能够组合，不能压成单一标签

同一模型可以同时改变注意力状态表示、FFN 条件计算、数据规模、后训练和用户输入方式。称某模型为“MoE”“MLA”或“多模态”只描述局部特征，不足以概括它的质量、效率或能力。比较句子应明确说出改变的对象、它所在的阶段以及来源支持的观察。

### 59.6.2 多项同时变化时谨慎进行因果归因

如果新版本同时改变参数规模、训练数据、结构、训练阶段和 benchmark，整体成绩只能表明该版本在该设置下的结果。要将提升归因于单一组件，需要来源提供相应消融或其他条件相近的对照；缺少这类证据时，应把组件变化和整体结果并列报告，而不是把它们写成因果关系。

### 59.6.3 与架构家族比较及未来判断章节衔接

本章横向比较的是第五十一至五十八章的历史模型谱系和公开报告；[第四十二章](42-替代架构横向对比.md)比较 Attention、SSM、卷积等序列架构家族的信息流，[第六十章](60-下一代架构判断框架.md)处理新架构主张及证据尚不充分时的判断。三者的问题对象不同，后续阅读不应再把它们合并成一份通用发布检查表。
