# 第 50 章 未来大模型架构会如何演进：替代、组合与开放问题

“下一代模型会不会抛弃 Transformer？”听起来像一个二选一问题，但它把多个不同的设计任务压成了一个标签。历史可以显式保留在 attention 的 key/value 中，也可以被递归更新成固定状态，或写入外部记忆；MoE 改变的是每个 token 激活哪些参数，检索和工具则把信息访问延伸到模型外。它们解决的瓶颈并不相同。

第四十三至第四十九章已经展示了多种混合、记忆、检索和 Agent 系统路径。本章把它们放在同一张架构地图上，讨论组合出现在哪里、它为何不自动带来收益，以及当前论文究竟能支持多强的未来判断。重点是识别设计空间与证据边界，而不是给某一种未来 block 下结论。

## 50.1 从单一替代转向信息路径设计

判断一项架构变化，可以先追踪历史信息如何影响当前输出。标准 attention 通过当前 query 对显式保留的 key/value 做内容相关读取；递归模型把不断增长的前缀压进较小状态，生成时状态大小较稳定，但压缩可能损失以后才会需要的细节。外部检索保留原文或结构化记录，让模型按需取回证据；它也增加了模型外部的数据和访问环节。

这些路径可以互补，也可以在具体任务中互相替代一部分工作。代码审查可能同时需要扫描完整日志、回读某条原始 diff，并在冲突证据间作精确对齐；连续音频或视频则可能更依赖流式状态和时间信息。哪条路径合适，取决于任务需要保留什么、之后怎样读取，以及额外存储和计算是否值得。

MoE 又处在另一条设计轴上：它通过路由决定每个 token 激活哪些参数，主要改变模型容量与计算的分配，并不直接规定历史信息以 attention、state 还是检索形式到达当前 token。因此，“混合”不能只按模型中出现了几种新组件来判断。更关键的是每条路径的职责、接口和信息如何汇合；前面的[组合架构章节](43-Attention与SSM混合架构.md)、[MoE/SSM/Attention 专题](47-MoE-SSM-Attention组合.md)、[记忆架构](46-Memory-Augmented-Transformer.md)、[检索架构](45-Retrieval-Augmented-Architecture.md)和[Agent 架构边界](49-Agentic-Model-Architecture.md)分别展开了这些机制。

## 50.2 架构组合可以落在不同粒度

混合路线不只是在 Transformer block 之间插入另一个 block。不同架构把组合放在不同计算位置，改变了模块看到的信息以及它们交换结果的方式。

| 组合位置 | 代表设计 | 组合发生在哪里 | 证据边界 |
| --- | --- | --- | --- |
| 层间 | [Jamba](https://proceedings.iclr.cc/paper_files/paper/2025/hash/a9ed43fa31dc8b4a7d7a673d713dcb5f-Abstract-Conference.html) | 在网络深度方向交错 Transformer 与 Mamba 层，并在部分层使用 MoE | 整体结果同时受专家层和训练设置影响，不能只归因于 Attention–Mamba 交错 |
| 层内 head | [Hymba](https://proceedings.iclr.cc/paper_files/paper/2025/file/f32def07618040e540e0a6182e290562-Paper-Conference.pdf) | Attention heads 与 SSM heads 在同一层并行处理输入 | 论文模型还结合 meta tokens、局部/全局 attention 与 KV sharing |
| 记忆分支 | [Titans](https://proceedings.neurips.cc/paper_files/paper/2025/hash/a4ca07aa108036f80cbb5b82285fd4b1-Abstract-Conference.html) | 将短期 Attention、可在测试时更新的 neural memory 与 persistent memory 组合 | 作者提出 context、layer、gated-branch 等接入方式，不能因此推断所有模型需要这种记忆 |
| Attention 分数 | [SISA](https://arxiv.org/abs/2606.02332) | 2026 年预印本提出在 softmax 之前把 SSM 派生信号加入 attention score | 这是新的研究提案；预印本及其小规模结果尚不证明可扩展或被广泛采用 |

这张表不是按性能给方案排名。它展示的是组合位置带来的架构差异：层间交错让表示依次经过不同模块；head 级并行让多种操作读取同一层输入；记忆分支改变历史信息的保存和读出位置；分数融合则直接影响 attention 选择历史 token 的依据。融合发生在哪里，本身就是需要说明的结构事实。

## 50.3 互补模块不会自动带来可相加的收益

两种计算路径各有优势，并不能推出把它们放进同一个模型就会同时得到两种优势。层间模块传递的是已经变换过的隐藏状态；前一条路径若丢掉了后续任务需要的细节，后一条路径无法凭空恢复。层内并行保留了不同算子访问相同输入的机会，但输出怎样归一化、合并和训练，也会改变最终作用。

组合还会改变训练与执行条件。模块比例、层位置、训练数据、上下文长度和额外参数都可能影响质量；实际生成速度又取决于状态、KV、内存搬运、kernel 和通信。一个理论上更便宜的序列操作，不必然让完整模型更快；额外的 attention 或 memory 也可能带来新的缓存和实现成本。

因此，整模型结果和组件贡献要分开。Jamba 同时包含 MoE，Hymba 同时采用多种 cache 与 token 设计，Titans 的 memory 在推理过程中也会更新。若没有能隔离这些因素的消融，结果只能说明那一组设计与训练配置共同取得了什么表现，不能说明某一个模块单独造成了多少收益。训练配方和硬件实现仍由对应书册深入讲解。

## 50.4 当前证据支持设计空间扩展，不支持统一胜者

公开研究至少支持两个具体观察。第一，架构组合已在层间、层内、记忆分支和 attention 分数等不同位置被提出或实验。Jamba 和 Hymba 提供前两种组合实例；Titans 把可更新的 neural memory 纳入模型结构；SISA 预印本探索更靠近 attention 计算内部的融合。它们证明这些设计可被具体化和研究，不证明它们同样成熟或适用于相同任务。

第二，单一递归路线也没有停止演进。[Mamba-3 论文](https://arxiv.org/abs/2603.15569)报告了更具表达力的递归、复数状态更新和 MIMO 设计，并在其 1.5B 模型与指定的检索、状态跟踪和语言任务中比较效果。这说明改进路线既可能组合多种算子，也可能继续改进一种算子；论文的规模和任务条件不能外推为所有 SSM 的普遍优势。

对层间与层内 hybrid 的系统分析也开始增加。[Bae 等人的比较研究](https://arxiv.org/abs/2510.04800v3)测试了不同融合方式、比例和层位置，但模型规模最高覆盖到 3B，结果依赖论文的训练预算、数据、任务和实现。它有助于发现哪些因素值得进一步比较，却不足以确定更大模型或真实部署中的通用最优方案。不同论文的总分、上下文长度和速度数字也不能拼成统一排行榜。

所以，当前证据支持的是“架构设计空间正在扩展”，而不是“混合架构必然胜过单一路线”或“Transformer 即将被某个替代品取代”。前者描述已经出现的研究方向；后两者则是超出这些实验范围的预测。

## 50.5 未来研究仍需回答的问题

未来工作需要把几个目前分散的问题连起来。其一，某种组合优势能否随着模型规模、训练长度和任务变化保持？其二，层间、head 级、记忆分支或分数级融合之间的差别来自何处，哪些消融能区分“组合本身”与其他共同变化？其三，不同任务对精确回读、流式处理和长程状态的需求，能否形成稳定的结构选择规律？其四，实验中的运算优势能否在目标硬件上变成端到端收益？

这些问题不要求所有模型最终采用同一种结构。即使未来出现多种长期共存的设计，仍需说明它们分别解决什么问题、需要什么训练与执行条件、哪些能力尚未验证。相反，若某条单一信息路径在足够广泛的任务和资源约束下持续占优，组合假设也应接受反证。架构结论应跟着证据调整，而不是先设定一个必然的演进方向。

## 50.6 如何回答“未来架构会走向哪里”

面试官问“下一代模型会是纯 Transformer、纯 SSM，还是混合架构”时，可以先说明这不是一个已有定论的问题。不同路线改变了历史信息的保留、读取或参数激活方式；已有工作给出了多种融合粒度，也继续改进独立的递归模型。它们的实验条件不同，不能据此宣布某一类架构将成为唯一主流。

如果需要给出趋势判断，可以说：**公开研究显示架构设计正在扩展到多种可组合的信息路径，但当前证据还不能预测哪种路径会在所有任务、模型规模和硬件上胜出。**这是一项基于已发表设计与有限实验的推论，不是事实定律。要把它变成更强的结论，需要同预算、同任务、同实现条件下的比较，并验证结果能否迁移到更大模型和真实负载。遇到单个新模型时如何逐项核对主张、证据和未知项，见[第 60 章](60-下一代架构判断框架.md)。
