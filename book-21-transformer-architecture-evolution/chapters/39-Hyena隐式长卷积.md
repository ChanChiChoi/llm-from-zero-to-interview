# 第三十九章：Hyena：隐式长卷积与长序列建模

## 39.1 Hyena 为什么重新使用卷积

卷积序列模型的问题曾经是感受野有限、长卷积核参数多、计算和训练困难。Hyena 通过隐式参数化长卷积核、门控和多阶组合，尝试在不使用二次 attention 的情况下获得长距离交互。

它的关键不是普通的固定短卷积，而是让长滤波器由位置、频率或小网络生成，再通过多阶门控逐步混合输入。长卷积提供全序列影响，门控提供输入依赖。

## 39.2 隐式滤波器的形式

一个教学化隐式滤波器可以写成：

~~~math
h_\theta(t)=\operatorname{MLP}_\theta(\operatorname{pos}(t))
~~~

然后做因果卷积：

~~~math
y_t=\sum_{i\le t}h_\theta(t-i)\odot x_i
~~~

若直接学习每个位置的 `h_i`，参数和长度绑定；隐式函数可以用较少参数生成长核，并通过 FFT 或分块卷积加速。实际 Hyena 的滤波器、指数调制和多阶结构更复杂，不能用一个 MLP 公式替代。

## 39.3 小白直觉：一条很长但可生成的滤波器

固定窗口卷积像只看最近十页；Hyena 像有一条可以覆盖整本书的滤波器，但滤波器不是把每一页的权重都存起来，而是由一个规则生成。门控再决定当前 token 通过哪条滤波路径。

长滤波器能把远处信号带过来，却不一定能像 attention 一样针对每个 query 重新排序所有历史。它更像全局信号处理加内容门控。

## 39.4 多阶 Hyena 结构的抽象

可以用递推的多阶形式理解：

~~~math
v^{(1)}=x
~~~

~~~math
v^{(k+1)}=x_k\odot(h_k*v^{(k)})
~~~

最后通过投影得到输出：

~~~math
y=W_o v^{(K)}
~~~

卷积提供长距混合，逐元素 gate 提供输入条件。阶数越高，表达组合更丰富，但 kernel、内存和训练稳定也更复杂。

## 39.5 FFT 与直接卷积的取舍

长卷积可以用 FFT：

~~~math
h*x=\mathcal{F}^{-1}(\mathcal{F}(h)\odot\mathcal{F}(x))
~~~

理论上能把长卷积从 `O(T^2)` 降到近似 `O(T\log T)`，但 FFT 有 padding、复数、频域内存和 chunk overlap 问题。短序列或短 kernel 上，直接卷积可能更快。

## 39.6 一个教学版隐式核

~~~python
import torch


def implicit_kernel(length, channels):
    positions = torch.linspace(0, 1, length)
    frequency = torch.arange(1, channels + 1).float()
    kernel = torch.sin(positions[:, None] * frequency[None, :] * 6.28)
    envelope = torch.exp(-3 * positions)[:, None]
    return kernel * envelope


kernel = implicit_kernel(16, 4)
print(kernel.shape, kernel[0].tolist())
~~~

这个例子用正弦和衰减生成一个多通道核，不是 Hyena 的完整滤波器。它说明“长核可以由位置函数生成”，也提醒读者核的频率和衰减决定可建模的时间尺度。

## 39.7 与 attention 的差异

attention 的权重由当前 query 和每个 key 的内容相似度决定；Hyena 的长卷积权重主要由位置/隐式滤波器生成，输入依赖性来自 gate 和多阶混合。前者更适合任意内容寻址，后者更适合规则长程滤波和高效序列处理。

如果任务是周期信号、长距离模式、音频或基因组，卷积先验可能有价值；如果任务要求根据末尾问题定位文档中任意一条事实，纯隐式卷积需要 retrieval 或 attention 补偿。

## 39.8 训练和推理

训练可以批量做长卷积，推理则需要维护卷积窗口/FFT overlap state 和每阶 gate 状态。若每步都重新做整段 FFT，在线延迟会失去意义；若使用 overlap-save 或递归分块，必须验证边界。

服务状态比固定向量更复杂：每个阶数、通道和 kernel 都可能有缓存。状态 snapshot、迁移和请求取消需要记录所有边界 buffer。

## 39.9 失败模式

包括 FFT circular convolution 把尾部绕到开头、padding 未屏蔽未来、kernel 频率在长序列上数值不稳定、gate 饱和、长核生成开销高、短序列 kernel 反而慢和 chunk overlap 丢失。

诊断可以用 impulse response：输入只有一个非零 token，检查输出影响是否只出现在未来、幅度是否符合预期；再用同一输入比较直接卷积、FFT 和流式分块。

## 39.10 机制与边界：隐式核的表达与可训练性

隐式滤波器把长度相关参数变成函数参数，改善了长核的参数效率，但滤波器生成网络的频率偏置会影响可表达范围。高频成分对局部细节敏感，低频成分对趋势敏感；门控和多阶组合弥补了固定卷积缺少内容选择的问题。

研究比较要区分：卷积核生成成本、FFT/直接 kernel、输入 gate、状态缓存、训练长度和精确 token 任务。不能把 Hyena 的长卷积优势推广为所有离散语言场景的 attention 替代。

## 39.11 面试追问、误区与练习

**问：Hyena 为什么比普通卷积更适合长序列？**

标准回答：它用隐式函数生成长滤波器，结合多阶卷积和输入门控，在较低的二次交互成本下提供长程混合；但精确内容寻址、FFT/流式 kernel 和状态边界仍需验证。

**问：长卷积为什么不一定在线更快？**

标准回答：FFT、padding、overlap、kernel launch 和状态管理有固定成本；在线场景若不能增量维护卷积状态，可能反复计算历史。

常见误区包括把隐式卷积当固定滑窗、把 FFT 复杂度直接当 latency、忽略 causal/circular 边界，以及把 gate 当 full attention。

练习：实现 impulse response、直接卷积和 overlap-save 流式卷积，测试不同长度和 chunk 的输出一致性及延迟。

## 39.12 长卷积的频域误差

FFT 让长卷积更高效，但 padding、截断、频域数值误差和 kernel 长度会影响结果。循环卷积与线性卷积如果边界处理不同，输出可能在序列尾部出现系统性偏差。

对 reference direct convolution、FFT convolution 和优化 kernel 做逐点对照，检查不同长度、dtype、padding 和 batch。速度测试只有在数值一致性通过后才有意义。

## 39.13 隐式核和输入依赖的能力边界

固定或由位置生成的长核擅长连续模式，但不天然支持 query-time 的任意 token 对齐。Hyena 层如果与 attention 混合，通常由卷积处理长流，attention 处理精确关系；评估应分别遮挡两条路径。

## 39.14 隐式核的学习和外推

Hyena 的长卷积核通常由位置、参数和门控路径生成。训练位置范围过短时，核在更长位置上的外推可能不稳定；训练数据没有长距离任务时，长核也可能只学到平滑主题而不是精确记忆。

可以固定核生成器，改变序列长度和证据位置，比较 kernel impulse response、频谱、任务 recall 和 p99。频域看起来平滑，不代表原子证据保真。

## 39.15 直接卷积、FFT 和 streaming 的选择

短序列可能适合直接卷积，长 prefill 可能适合 FFT，在线 decode 则需要维护卷积历史或使用分块更新。三种实现的边界、padding 和 state contract 不同，不能把一个 kernel 的 benchmark 推广到全部 serving 阶段。

## 39.16 感受野、频谱和可寻址性的三角关系

长卷积核的长度、频谱和输入依赖性是三个相互牵制的因素。低频成分能够传播平滑的长期趋势，高频成分有利于局部边界和短模式；但一个由位置生成的固定核仍然不能像 attention 那样在每个 query 到来时重新选择任意历史位置。

可以用 impulse response 和两个相似实体的对照同时观察这件事。单脉冲实验检查信息能否沿因果方向传播；双实体冲突实验检查后置 query 能否选择正确版本。若 impulse response 很长但冲突选择率低，说明“感受野长”只是传播性质，不是可寻址记忆。

## 39.17 隐式滤波器外推的验证方法

隐式核由位置函数生成时，训练位置范围与部署长度之间存在外推问题。把训练长度从 T_train 外推到 T_test，至少应画出三个曲线：核的幅度、频谱能量和任务准确率。若核在远端出现异常振荡，或者频谱能量集中到少数频段，模型可能在长位置上退化。

一个简单的相对误差定义是：

~~~math
E_{\mathrm{kernel}}
=\frac{\lVert h_{T_{\mathrm{test}}}
-\operatorname{resize}(h_{T_{\mathrm{train}}})\rVert_2}
{\lVert h_{T_{\mathrm{test}}}\rVert_2+\varepsilon}
~~~

这个数值不能直接等同任务损失，但能作为实现诊断信号。任务侧还要区分局部预测、长距复制和多证据合并，因为平滑核在前两者之外可能表现完全不同。

## 39.18 streaming 状态与 overlap 的正确性

流式长卷积不是把序列简单切成独立窗口。对因果卷积，下一 chunk 至少需要接收前一段的有效 overlap，或者接收等价的频域/分块状态。多阶 Hyena 还要为每一阶保存相应边界；只保存输入窗口而丢掉 gate 中间量，恢复后也可能不一致。

设 chunk 长度为 K，卷积核有效长度为 R，直接 overlap-save 通常需要保留至少 R-1 个历史位置。实际优化还可能使用分块 FFT、ring buffer 或 kernel-specific state。测试应随机改变 chunk 边界，比较 full convolution 与 streaming 的逐点输出；任何边界差异都要在 benchmark 前修复。

## 39.19 impulse response 之外还要测变量绑定

单脉冲响应只能证明信息沿时间传播，不能证明模型能选择正确实体。可以把两个格式相同的版本号放在不同位置，末尾分别询问实体甲和实体乙，再改变它们的相对顺序和干扰长度。

若输出总是选择最近编号，说明卷积路径可能学到了局部偏置；若输出能区分实体但不能处理冲突版本，说明表示有绑定能力但缺少时间有效性；若只有加入 attention 或 retrieval 后成功，说明长滤波器需要显式回读补偿。

## 39.20 隐式核的参数效率与外推风险

隐式核用位置函数生成权重，减少了逐位置存储，但生成器本身有频率和幅度偏置。训练长度、位置编码、滤波器网络深度和归一化共同决定更长位置上的行为。参数少不等于外推稳定，频谱平滑也不等于证据保真。

可为不同训练/测试长度报告：

~~~math
G(L)=\frac{\lVert h_{1:L}\rVert_2}{\sqrt{L}},
\qquad
R_{\mathrm{task}}(L)=\Pr(\text{exact answer}\mid L)
~~~

如果 G 稳定而任务 recall 下降，问题可能是内容寻址而非数值发散；如果 G 爆炸或衰减，先查核生成和 dtype。

## 39.21 Hyena 与混合架构的职责边界

Hyena 的长滤波适合先做全序列扫描、局部/趋势特征和低成本流处理；少量 attention 或 retrieval 可以承担精确证据，避免让卷积核同时负责所有任务。组合时要区分训练阶段的全序列卷积和在线阶段的 overlap state。

生产系统还要为每阶状态建立 schema、snapshot 和 rollback。若只保存输入窗口而没有保存 gate 中间结果，恢复后可能与一次性运行不同。新的长卷积路线应以状态协议和任务验收条件，而不仅是 FFT 复杂度，作为工程评价入口。

## 39.22 隐式长卷积的三个计算对象

Hyena 类路线通常把长程混合拆成长卷积、门控和逐点投影。阅读时要区分卷积核如何生成、核如何与序列结合、门控如何改变信息流。称它为“长卷积”并不足以说明是显式 materialize kernel、FFT、递归近似还是分块实现。

## 39.23 长卷积的长度和边界问题

长卷积在训练和推理中都要处理 causal padding、chunk continuation、核截断、频域数值误差和变长 batch。一个整段卷积结果正常的实现，如果每个在线 chunk 都重新从零卷积，就会丢掉跨 chunk 历史；如果保存了错误的尾部状态，又会把旧样本泄露到新请求。

测试应覆盖 impulse response、短核/长核、不同 chunk size、stream reset、padding、state restore 和频域/时域路径一致性。服务 benchmark 还要记录 kernel launch、FFT workspace、带宽和 p99。

## 39.24 隐式长程混合与精确证据

卷积天然聚合历史，适合趋势、音频和长流模式；但聚合不等于可解释的任意位置检索。对文档问答和工具轨迹，需额外检查数字复制、引用来源、版本冲突和权限边界。若隐式路径只能提供摘要，应让外部 retrieval 或显式 attention 负责原子证据。

## 39.25 长卷积的变量绑定实验

卷积核可以传播历史模式，却不会自动知道某个新 query 应该选择哪一个同名实体。为区分“长程混合”和“内容寻址”，构造两组相同长度的文本：一组只要求识别整体趋势，另一组包含两个实体、两个版本号和一个末尾查询。逐步增加实体数量和干扰，比较趋势准确率、精确复制、冲突选择和引用支持。

若 Hyena 在趋势任务上稳定而变量绑定下降，说明长滤波承担了有价值的压缩路径，但需要 attention、retrieval 或选择性门控补偿。这个结论比“卷积不能做语言”更准确，也更能指导混合架构的模块分工。

## 39.26 长卷积状态的线上验收条件

生产验收条件至少包括 full/streaming 一致性、chunk 边界、核截断、FFT workspace、state snapshot、跨请求清理和 fallback。若长核无法在目标 runtime 上稳定执行，系统应回退到较短卷积、SSM 或显式 retrieval，并记录回退原因和质量变化。

## 39.27 长卷积不是可寻址记忆的同义词

Hyena 的长滤波可以让远处信号影响当前位置，但“影响到”与“按 query 找到正确实体”是两回事。可以构造两个相同格式的账户、版本或日期，末尾只改变查询实体；如果模型总是选择最近或频率更高的模式，说明传播路径存在，精确绑定不足。

因此混合架构常把长卷积用于低成本扫描和多尺度趋势，把 attention、检索或显式索引用于少量原子证据。这个分工不是对 Hyena 的否定，而是把“长感受野”“内容选择”和“证据引用”三个能力拆开验收。

## 39.28 把 Hyena 层写成可执行的数据流

读懂 Hyena 不能停在“长卷积加门控”这六个字。把一个 block 展开，至少要区分输入投影、滤波器生成、因果卷积、逐点门控和输出投影。下面是一个便于推导的抽象。令输入为 `x`，先得到若干条值流和门控流：

~~~math
u^{(0)}=V(x),
\qquad
g_k=G_k(x),
\qquad
z^{(k)}=h_k\ast u^{(k-1)},
\qquad
u^{(k)}=g_k\odot z^{(k)}.
~~~

经过 `K` 阶后，再把 `u^(K)` 投影回模型维度。这里的 `h_k` 是由位置输入和参数化滤波器生成器得到的长核，`g_k` 是随输入变化的门控。这个分解解释了 Hyena 为什么不是“把 attention 换成一层普通卷积”：普通卷积只有固定的局部核；只有长核、多阶混合和数据控制共同存在，才可能同时覆盖远程传播和内容条件。

还要明确因果方向。对位置 `t` 的输出，卷积只能读取 `i <= t` 的历史。如果实现用 FFT 做循环卷积却没有足够的零填充，序列尾部会绕回序列头部，模型等价于看到了未来。这个错误不会导致张量 shape 报错，却会让离线 loss 虚假变好、线上生成出现难以复现的差异。

## 39.29 把复杂度拆成核生成、混合和内存三笔账

谈 Hyena 的效率时，至少要把三种成本分开。第一是生成长度为 `T` 的隐式核；第二是每一阶卷积与门控；第三是保存 FFT workspace、overlap 和中间阶状态。一个简化账本可以写成：

~~~math
C_{\mathrm{layer}}
\approx C_{\mathrm{filter}}(T)
 +K\,C_{\mathrm{conv}}(T,d)
 +C_{\mathrm{gate}}(T,d),
~~~

对整段长卷积，频域实现通常接近 `O(T log T)` 的序列项，但常数包含 padding、复数变换和 kernel launch；对短序列，直接卷积的 `O(TRd)` 可能反而更快。对在线 decode，真正的问题不是论文中的整段复杂度，而是能否把历史卷积增量化。如果每生成一个 token 都重算完整长度为 `T` 的 FFT，理论上的长序列优势就不会转化成 TPOT。

显存也不能只写“线性”。权重、滤波器、每阶中间值、FFT 工作区和 batch 维度都要列出来。一个请求的峰值内存可以教学化地写成：

~~~math
M_{\mathrm{peak}}
\approx M_{\mathrm{weights}}+M_{\mathrm{workspace}}
 +M_{\mathrm{overlap}}+M_{\mathrm{activations}}.
~~~

当序列长度、阶数或并发数变化时，四项的增长方式不同。只有把 prefill、decode、单请求和高并发分别压测，才知道节省来自哪一项，以及是否把成本转移到了带宽或延迟。

## 39.30 为什么 recall benchmark 还不够

Hyena 论文中的长序列 recall 结果能说明长程信息传播和某些选择性任务有潜力，但不能直接证明它具备任意内容寻址。一个更有辨识力的测试要把任务分层：

1. **传播测试**：在距离 `d` 的位置放一个标记，末尾判断标记是否出现，测的是远程信号能否到达。
2. **选择测试**：放入多个同格式实体，只询问其中一个，测的是 query 条件下的变量绑定。
3. **冲突测试**：为同一实体写入旧版本和新版本，再询问“截至日期”的正确值，测的是时间有效性。
4. **合并测试**：把答案拆到多个位置，要求同时引用两条证据，测的是多证据组合而不是单点回忆。

可把精确证据指标写为：

~~~math
A_{\mathrm{evidence}}
=\frac{\#\{\text{实体、值和来源都正确的样本}\}}{\#\{\text{有效样本}\}}.
~~~

如果模型在传播测试上很好、选择测试上下降，说明滤波器的感受野不是问题，问题在内容寻址；如果选择正确但冲突测试失败，说明模型能绑定实体，却没有学会版本或时间语义；如果只有增加少量 attention 后多证据合并才稳定，这正是混合架构的职责边界。把这些失败类型混成一个平均准确率，会掩盖真正的设计取舍。

## 39.31 流式实现的状态并不是一个数字

长卷积的流式状态通常包含每一阶的历史尾部、分块 FFT 的 overlap、门控路径需要的中间量，以及当前 kernel 的长度和版本。设第 `k` 阶有效核长为 `R_k`，直接 overlap-save 至少要保留 `R_k-1` 个历史位置；如果实现采用了更紧凑的递推或频域状态，保存的对象不同，但语义仍然必须等价。

状态恢复不能只保存 `token_offset`。一个可恢复的 state record 至少需要：模型 revision、层号和阶号、卷积核配置、dtype、逻辑位置、overlap 内容、归一化/缩放因子和校验和。请求取消时，候选输出产生的中间状态必须丢弃；请求迁移时，旧状态必须和新 runtime 的 kernel 版本兼容。否则会出现“文本前缀相同但恢复后 logits 不同”的隐性错误。

最小回归可以按下面的顺序执行：先让整段路径得到 reference logits；再随机选择 chunk 边界运行 streaming；然后在任意边界做 snapshot/restore；最后插入取消、重试和 batch reorder。逐 token 比较误差，而不是只比较最终字符串：

~~~math
E_{\mathrm{stream}}
=\max_t\lVert y_t^{\mathrm{full}}-y_t^{\mathrm{stream}}\rVert_\infty.
~~~

当 `E_stream` 只在很长序列增长时，优先检查 overlap 截断、FFT padding、累计精度和 state schema，而不是直接把差异解释成模型随机性。

## 39.32 Hyena 在混合架构中的合理分工

把 Hyena 放进实际模型时，更可靠的分工是让它承担低成本的全局扫描、局部与多尺度模式、长流状态更新，再由少量 attention、检索或外部索引处理高价值原子证据。这样做不是承认 Hyena “不能做语言”，而是承认不同算子擅长的访问模式不同。

可以用一个路由验收条件决定是否触发显式回读：当问题包含数字、实体冲突、引用要求或工具参数时，先保留 Hyena 的摘要，再触发 retrieval/attention；普通续写和趋势判断则走长卷积路径。路由质量要同时报告触发率、额外延迟、证据支持率和 fallback 后的任务成功率。若为了追求低触发率而牺牲引用正确性，系统得到的只是便宜的错误。

## 39.33 论文结果、教学抽象与工程结论要分层

Hyena 论文支持的事实包括：它把隐式参数化的长卷积与数据控制门控交错，用于构造不依赖 dense attention 的子二次算子，并在论文设置的长序列任务和语言建模实验中进行比较。本文的 MLP 滤波器、逐阶公式和 overlap-save 示例是帮助理解的教学抽象，不是对论文全部实现细节的逐行复刻。

工程结论还要再降低一层：某个 checkpoint 在某个长度和硬件上取得更好结果，只说明那组训练配方、kernel 和 workload 的联合效果。要把它迁移到语言服务，必须重新测变量绑定、长文档引用、streaming 一致性、p99、显存和 fallback。复杂度标签可以决定“值得实验”，不能替代任务和系统验收条件。

## 39.34 小结与资料边界

Hyena 代表论文为 https://arxiv.org/abs/2302.10866。本文使用隐式核和多阶 gate 的教学抽象，完整实现还包含具体滤波器参数化和高效 kernel。

Hyena 把长序列问题转成可生成的长滤波器与多阶输入混合。它展示了卷积路线的潜力，也清楚暴露了内容寻址和流式边界的代价。
