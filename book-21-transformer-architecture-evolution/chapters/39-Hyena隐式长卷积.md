# 第三十九章：Hyena：隐式长卷积与长序列建模

## 39.1 长卷积怎样提供全局序列混合

卷积能按相对位置混合序列。给定输入 $u_0,\ldots,u_{L-1}$ 和因果滤波器 $h_0,\ldots,h_{L-1}$，位置 $t$ 的输出为：

~~~math
y_t=\sum_{s=0}^{t} h_{t-s}u_s.
~~~

求和只包含当前位置及其以前的输入，因此不会读到未来；同一个滞后量 $t-s$ 对所有位置使用相同的滤波器权重。这种共享关系让因果卷积可以写成下三角 Toeplitz 矩阵乘向量。若核长为 $R$，普通短卷积只连接最近 $R$ 个位置，计算量约随 $LR$ 增长；把核延长到整个序列后，较早的输入也能影响当前输出，但直接逐项求和需要约 $L^2$ 次序列操作。

Hyena 关注的是怎样以较少的序列长度成本保留长程混合。它不为每一对位置单独计算相似度，而是用长卷积核按距离组织交互，再用输入产生的门控改变中间信息流。因而，“全局感受野”在这里表示远处位置存在传播路径，不表示它与 self-attention 使用相同的 query-key 配对规则。原论文把这种设计定义为隐式长卷积与数据控制门控交错的算子。[Hyena Hierarchy 原论文](https://proceedings.mlr.press/v202/poli23a.html)

## 39.2 Hyena 递归：投影、卷积与门控交替

设一层输入为 $u\in\mathbb{R}^{L\times D}$。Hyena 先对每个位置做线性投影，并在投影流上施加短卷积，得到一条 value 流 $v$ 和 $N$ 条 gate 流 $x^1,\ldots,x^N$。它还为每一阶准备一个因果长滤波器 $h^1,\ldots,h^N$。令 $z^1_t=v_t$，各阶更新为：

~~~math
z^{n+1}_t=x^n_t\odot(h^n*z^n)_t,
\qquad n=1,\ldots,N,
\qquad y_t=z^{N+1}_t.
~~~

卷积先把当前中间流与一段因果历史混合；随后 $x^n_t$ 在当前位置逐元素调节混合结果。这个 gate 来自当前输入的投影，因此它让整条算子依赖输入；长滤波器本身则由位置和可学习参数产生。阶数 $N$ 表示卷积与门控交替的次数，不是卷积核长度。

看一个单通道的教学算例。令 $v=(2,1,0)$、$h^1=(1,\frac{1}{2},\frac{1}{4})$，并令 $x^1=(1,0,\frac{1}{2})$。因果卷积给出 $h^1*v=(2,2,1)$；逐位置乘 gate 后，$z^2=(2,0,\frac{1}{2})$。第二个位置的历史信号先被卷积汇入，再被当前位置的 gate 压到零。真实模型的流是多通道、由网络学习得到的，这组数字只展示一次“卷积混合—输入门控”的计算关系。

原论文还给出矩阵视图：每次长卷积对应 Toeplitz 矩阵 $S_{h^n}$，每条 gate 流对应对角矩阵 $D_{x^n}$，于是

~~~math
y=D_{x^N}S_{h^N}\cdots D_{x^2}S_{h^2}D_{x^1}S_{h^1}v.
~~~

这解释了 Hyena 怎样用结构化因子表达一个由输入控制的混合算子，同时避免显式构造完整的 $L\times L$ 矩阵。按原论文的关系，采用状态空间滤波器参数化的 GSS 对应 Hyena-1，H3 对应 Hyena-2；这说的是算子层的特例关系，不代表各论文的完整网络、训练配方或实验可互换。[原论文 §3.1—3.2](https://proceedings.mlr.press/v202/poli23a/poli23a.pdf)

## 39.3 隐式滤波器与位置尺度

若为长度为 $L$ 的核逐位置直接学习全部 $h_t$，核参数会随目标长度增长。Hyena 改为学习一个从位置特征生成核值的函数：

~~~math
h_t=\mathrm{Window}(t)\cdot\mathrm{FFN}(\mathrm{PE}(t)).
~~~

$\mathrm{PE}(t)$ 把相对位置 $t$ 编成特征，浅层前馈网络将这些特征映射为滤波器响应，window 再对响应作位置调制。原论文在不同通道上设置不同的指数衰减尺度，使滤波器具有不同的有效长度；作者还给 window 加入偏置，避免滤波器因衰减率而被强制截成零。滤波器网络使用高频正弦激活，缓解普通网络偏向平滑低频函数的问题。

这种函数式参数化使可学习参数量不必随滤波长度线性增加，却没有让生成长核变成零成本。若要处理 $L$ 个位置，仍要在这些位置上计算滤波器值，随后为长卷积准备相应的频域或时域工作区。模型在训练位置范围以外的行为也取决于位置编码、网络参数和 window；函数可以在更长位置求值，不等于它已学会可靠外推。Hyena 团队对滤波器频谱和可压缩状态的讨论也指出，不同参数化会改变它们所编码的记忆尺度及实现代价。[Hazy Research：The Safari of Deep Signal Processing](https://hazyresearch.stanford.edu/blog/2023-06-08-hyena-safari)

## 39.4 FFT 长卷积的计算与复杂度

对每个输出位置逐项累加全部历史，长卷积的序列计算量是二次的。卷积定理把线性卷积转为频域的逐点乘法：先将输入和滤波器补零到至少 $2L-1$，分别做 FFT，再相乘并做逆 FFT。补零很关键：离散傅里叶变换天然对应循环卷积，若直接对原长序列变换，末尾信号会绕回开头；足够补零后，循环卷积在有效区间才等于所需的线性卷积。Hyena 逐阶重复这一操作，中间再执行逐位置 gate。

在通道独立的长卷积路径中，$N$ 阶、$D$ 通道、长度 $L$ 的主项约为 $O(NDL\log L)$。这个数不包括完整 block 的所有工作：将输入投影成 $N+1$ 条流的主要成本约为 $O((N+1)LD^2)$，输出投影约为 $O(LD^2)$；投影上的短卷积、滤波器生成、门控和 FFT 工作区也会占用时间或显存。因而将“长卷积接近线性”说成“整个 Hyena block 都是 $O(L\log L)$”，会漏掉宽度、阶数和周边算子。

渐近复杂度也不直接等于硬件速度。FFT 的常数、频域中间量、内存流量和 kernel 利用率会影响实际吞吐；序列较短时，启动与变换成本可能抵消渐近优势。原论文的 Hyena 算子测试使用 order 2、batch size 64 和融合 CUDA FFTConv，并报告相对 FlashAttention 的交叉区间约在 $4$k—$8$k、长度 $64$k 时约 $100\times$ 的加速。这个结果属于论文中的算子测试；不能把它当作不同硬件、不同 batch 或完整语言模型端到端的速度保证。[原论文 §3.4、§4.4](https://proceedings.mlr.press/v202/poli23a/poli23a.pdf)；[作者团队对 FFT 硬件利用率的讨论](https://hazyresearch.stanford.edu/blog/2023-06-08-hyena-safari)

## 39.5 数据控制矩阵与 attention 的结构边界

矩阵表达式显示了 Hyena 的两种成分：$S_{h^n}$ 根据位置滤波器在时间轴上混合历史，$D_{x^n}$ 则由输入投影产生并逐位置调节结果。组合后的矩阵随输入而变化，所以 Hyena 不是与内容无关的固定卷积；但它也没有标准 self-attention 那种逐个 query-key 配对、再对一行相似度做 softmax 的步骤。把它称为“数据控制算子”，准确地描述了输入门控与长滤波的乘积结构，不应被简化成“每个 query 会任意查找所有 key”。

反过来，也不能只从这个结构断言 Hyena 必然无法完成精确关联。原论文在特定合成关联回忆任务上取得很高准确率；后续研究在不同配置的另一套任务上则观察到显著困难。两者说明算子可达范围、训练后策略和任务成绩需要分别研究。长感受野说明信息可能传得远，门控说明信息流受输入影响；它们都不单独保证对任意实体、冲突版本或自然语言证据的可靠读取。

Hyena 的算子递归与 H3/GSS 的联系为第四十章的早期混合路线提供了结构背景。它与第四十一章要讨论的卷积家族归纳偏置相关，但本章只解释 Hyena 的隐式长核、逐阶门控和实验；跨架构的复杂度、表达和硬件比较留给第四十二章。

## 39.6 原论文结果及后续证据边界

论文实验分别测量合成任务准确率、语言建模 perplexity 和算子 runtime。它们的目标、模型与比较对象不同，不能合并成一个“Hyena 优于 Transformer”的总判断。

| 证据 | 实验条件 | 报告结果与可支持的判断 |
| --- | --- | --- |
| 原论文 associative recall | 长度 $131072$、词表大小 $30$；两层、宽度 $64$；训练样本数固定为 $2000$ | Hyena 准确率为 $97.2\%$。这说明该参数化在此合成任务和数据量下能学到关联回忆，不能代替自然文本检索或任意长度泛化证据。 |
| 原论文 The Pile 语言建模 | 355M 模型、GPT-2 tokenizer、长度 $2024$、global batch $256$；训练到 $5/10/15$ billion tokens；8 张 A100 80GB | 15B tokens 表格中 Hyena-2 与 GPT 的 perplexity 为 $9.2$ 与 $9.1$，FLOPs 约为 $3.93\times10^{19}$ 与 $4.77\times10^{19}$；论文摘要将差异概述为约 $20\%$ 训练计算节省。结论绑定论文的数据、模型和训练设置。 |
| 原论文算子测试 | order 2、batch size $64$、融合 CUDA FFTConv；与 attention / FlashAttention 比较 | 报告在更长序列上取得明显层级速度收益；长度 $64$k 的约 $100\times$ 结果是算子 microbenchmark，不是完整模型的通用速度。原文测试段落列明 batch 和 kernel，但未在该处注明加速卡型号。 |
| 后续机制研究 | arXiv v3，2026-01-30；从头训练的合成 AR；词表 $8192$、每条样本 $32$ 个 key-value 对和一个 query、约 $100032$ 条训练样本；Hyena 配置 $l_{\max}=1024$、filter order $64$、单头单 block、短滤波器阶数 $3$ | 作者认为 Hyena 未能完整解决该 AR 设置，并通过干预分析其机制；附录中 $d=256$ 的一层与两层 Hyena 准确率分别为 $31.56\%$ 和 $29.69\%$。这不是原论文 $131072$ 长度、词表 $30$、两层宽度 $64$ 任务的直接复现。 |

后续研究与原论文的关联回忆结果看似不同，但序列长度、词表规模、训练集、宽度、层数和模型配置都不同。不能把 $97.2\%$ 当成任意内容检索的能力保证，也不能把另一个任务下的低准确率外推成所有 Hyena 模型都不能做关联回忆。更稳妥的读法是：先固定任务定义与模型版本，再查看行为分数；若要判断模型如何完成任务，还需检查机制，而不能只看架构名称。[原论文 §4 与 Appendix A](https://proceedings.mlr.press/v202/poli23a/poli23a.pdf)；[Arora et al. 机制研究 v3](https://arxiv.org/abs/2505.15105v3)
