# 第三十一章：S4：Structured State Space 的核心思想

## 31.1 S4 要解决长序列的两个矛盾

一般递归模型能在线处理序列，但训练长序列困难、梯度和记忆容易衰减；卷积可以并行训练，但要得到很长且稳定的卷积核并不容易。S4 把连续时间状态空间、长记忆初始化和结构化矩阵计算结合起来，目标是在长序列上同时保留稳定性和效率。

理解 S4 需要把三个层次分开：SSM 的连续/离散方程；HiPPO 类初始化提供多时间尺度记忆；DPLR/低秩结构让卷积核和状态更新可计算。

## 31.2 连续到离散

连续系统为：

~~~math
\dot x(t)=Ax(t)+Bu(t),\qquad y(t)=Cx(t)+Du(t)
~~~

采样步长为 `\Delta` 后得到离散系统：

~~~math
x_k=\bar A x_{k-1}+\bar B u_k,\qquad
y_k=Cx_k+Du_k
~~~

更准确的零阶保持可写为：

~~~math
\bar A=e^{\Delta A},\qquad
\bar B=\int_0^\Delta e^{\tau A}B\,d\tau
~~~

直接计算矩阵指数昂贵，因此 S4 依赖结构化参数化和高效核生成。`A` 的谱决定衰减/振荡频率，`B/C` 决定输入写入和输出读取。

## 31.3 HiPPO 的长记忆直觉

如果只用一个指数衰减状态，模型很难同时保留最近细节和很早的趋势。HiPPO 通过把历史函数投影到正交多项式基上，让不同状态坐标承担不同时间尺度的摘要。

可以把状态看成系数向量：

~~~math
x(t)=[c_0(t),c_1(t),\ldots,c_{N-1}(t)]^\top
~~~

低阶系数偏向平滑全局趋势，高阶系数描述更细局部变化。它不等于保存原始序列，但比单一滑动平均提供更丰富的历史表示。

## 31.4 结构化矩阵的目的

S4 使用特定结构的 `A`，典型讨论包括 normal plus low-rank、DPLR 等形式。抽象地写：

~~~math
A=\Lambda-PQ^\top
~~~

其中 `\Lambda` 是容易处理的对角/正规部分，`PQ^\top` 是低秩修正。这样既保留复杂的谱结构，又能利用 Woodbury 类公式和快速算法计算 resolvent/卷积核。

工程实现通常会在频域或离散域预计算卷积核，不能把上述分解直接当成完整代码。关键是理解：结构约束降低了矩阵运算成本，并帮助控制稳定性。

## 31.5 卷积核和递归核的二重性

展开离散递归：

~~~math
y_t=\sum_{i\le t}C\bar A^{t-i}\bar B u_i+Du_t
~~~

定义核：

~~~math
K_j=C\bar A^j\bar B
~~~

于是可以用一维卷积并行训练；在线推理则用递归 state。两条路径理论上描述同一线性系统，实际数值、截断、长度和 kernel 仍可能产生差异。

## 31.6 一个简化的稳定 SSM

~~~python
import torch


def diagonal_kernel(length, decay):
    powers = torch.arange(length, dtype=decay.dtype)
    return decay.pow(powers)


def causal_filter(x, kernel):
    # x: [batch, seq]；教学版 O(T^2)，只展示卷积核作用
    out = torch.zeros_like(x)
    for t in range(x.size(1)):
        width = min(t + 1, kernel.numel())
        out[:, t] = (x[:, t - width + 1:t + 1]
                     * kernel[:width].flip(0)).sum(-1)
    return out


kernel = diagonal_kernel(8, torch.tensor(0.92))
print(causal_filter(torch.randn(2, 8), kernel).shape)
~~~

这段代码不是 S4 的快速实现；它用有限指数核帮助读者验证“状态递归可展开成卷积”。真正 S4 会使用结构化核生成、频域计算、并行 scan 或专门优化。

## 31.7 训练、推理和长度外推

训练时卷积核可以一次处理整段，适合 GPU 并行；推理时只保存 state，适合 streaming。长度外推取决于状态谱、采样步长、训练长度和任务，不是因为有卷积就自动支持任意长度。

若 kernel 被截断到最大长度，超出后可能丢失尾部；若 state 数值精度不足，长时间递归会漂移；若卷积和递归的初始状态不同，离线/在线结果不一致。应做 chunk continuation 和恢复测试。

## 31.8 S4 相比普通 RNN 的变化

普通 RNN 依赖自由参数化的非线性递归，容易训练困难；S4 从连续系统和谱结构出发，提供多尺度线性记忆和稳定初始化，再叠加门控/非线性层。它的表达不是简单“更大的 hidden state”，而是让状态坐标具有时间尺度意义。

这也带来限制：线性 SSM 对输入内容的选择性有限，离散语言中的“遇到某个 token 才更新/忘记”不容易自然表达。后续 Mamba 的 selective parameter 就直接针对这一点。

## 31.9 常见失败模式

包括矩阵 `A` 不稳定、离散化步长错误、卷积 kernel 与递归状态不一致、state 初始化不匹配、长序列 overflow/underflow、FFT padding/circular convolution 误用、以及把复杂度写成线性却使用了 O(T²) 教学代码。

诊断应检查谱半径、kernel 范数、不同长度输出、chunk 边界、FP16/BF16/FP32 差异和长程任务。任何“稳定”结论都要绑定 dtype 和实现。

## 31.10 机制与边界：DPLR 的实际意义

DPLR 结构让 `A` 不必是简单对角矩阵，又保留可以高效计算的结构。低秩修正增加了谱表达力，但也引入 resolvent、复数参数、共轭对和数值实现细节。论文公式常在连续/频域中表达，工程代码还要处理离散化、kernel cache 和 mixed precision。

阅读 S4 时最值得追问：HiPPO 初始化承担什么，DPLR 减少哪类运算，训练使用卷积还是 scan，推理 state 的 shape 是什么，以及长序列质量是否来自结构本身还是训练配方。

## 31.11 面试追问、误区与练习

**问：S4 为什么同时有卷积和递归两种实现？**

标准回答：线性时不变 SSM 可以展开为卷积核，便于训练并行；也可以按状态递推，便于在线推理和固定状态。两条路径需要做数值和边界一致性验证。

**问：HiPPO 解决什么问题？**

标准回答：它提供一种在线压缩历史的多尺度基底/初始化，使状态不只保留单一指数衰减，而是能表示不同时间尺度的历史统计；它仍不是原始 token 的可逆存储。

常见误区包括把 S4 当普通卷积、把 DPLR 公式当完整实现、忽略复数/离散化和把长序列支持等同于精确检索。

练习：实现不同谱衰减的 SSM，比较卷积和递归两种计算输出；加入 chunk/恢复，找出边界不一致的原因。

## 31.12 HiPPO 的教学意义和实现边界

HiPPO 类思想把连续历史投影到一组基函数系数，使 state 能保留某种时间窗口上的函数统计。它解释了为什么一个固定 state 可以比简单平均更有表达力：不同维度保存不同时间尺度的信息。

但基函数系数仍然是压缩表示，不能任意恢复所有历史 token。任务若要求精确数字和来源，仍需显式或外部证据路径。读者应区分理论上的最优投影和具体 S4 kernel 的工程实现。

## 31.13 S4 的训练和推理一致性

S4 训练时常用卷积形式并行计算，推理时可以使用递推状态。两种形式的输出应在数值误差内一致；如果离散化、padding 或 state 初始化不同，会出现训练通过、在线失败。

测试时对同一序列做 full convolution、chunk continuation 和单步 decode，比较每个位置的 hidden 和最终任务结果。这个实验比只看速度更能验证 SSM 的核心契约。

## 31.14 为什么 HiPPO 不能被简化成“更大的 hidden size”

如果把历史函数 u(t) 投影到基函数 p_0,...,p_{N-1}，状态可以理解为一组系数：

~~~math
c_n(t)=\langle u_{[0,t]},p_n\rangle,\qquad
\hat u(t')=\sum_{n=0}^{N-1}c_n(t)p_n(t')
~~~

增加 N 当然会提高近似容量，但基函数的选择决定了这些容量如何分配。低阶分量通常更适合平滑趋势，高阶分量更敏感于局部变化；当时间窗口变化时，同一组系数的含义也会变化。HiPPO 的价值在于给出一种随时间更新投影系数的结构化方式，而不是简单把隐藏维度加大。

这也说明了 S4 的两个误区。第一，状态维度大不保证精确存储原文；第二，投影误差小不保证下游任务误差小。摘要任务可能偏好平滑的全局统计，数字复制任务却需要保留离散、稀疏和可寻址的信息。必须把表示误差和任务误差分开测量。

## 31.15 从 resolvent 到卷积核：专家需要看懂的桥

离散 SSM 的卷积核为 K_j=C\bar A^j\bar B。在生成很长的核时，可以用生成函数或 resolvent 表达无限和：

~~~math
\sum_{j=0}^{\infty}K_j z^j
=C(I-z\bar A)^{-1}\bar B
~~~

当 \bar A 有结构时，计算 (I-z\bar A)^-1 可以比直接逐项求 \bar A^j 更高效。DPLR 类结构的工程意义就在这里：它在保留更丰富谱结构的同时，利用对角部分和低秩修正降低求解代价。这里的公式是理解计算路径的桥梁，不等同于一个可以直接替换官方 kernel 的实现。

阅读实现时应区分三个成本：预计算卷积核的成本、把 kernel 应用到 batch 序列的成本，以及在线维护 recurrent state 的成本。长序列 prefill 可能被第一项和 FFT 内存主导，短序列 decode 可能被第三项和 kernel launch 主导。只看到渐近复杂度，无法判断端到端速度。

## 31.16 一个能发现边界 bug 的验证矩阵

S4 类实现至少需要覆盖下列四种执行方式：

| 路径 | 输入范围 | 需要检查的契约 |
|---|---|---|
| full convolution | 完整序列 | causal、padding、kernel 截断 |
| recurrent step | 单 token | state shape、初始化、dtype |
| chunk continuation | 多个分块 | chunk 间 state 和位置连续 |
| snapshot restore | 中断后继续 | state、offset、模型版本一致 |

对同一个随机输入，先比较 hidden 的最大绝对误差：

~~~math
\epsilon_\infty=\max_{t,d}|h^{(\mathrm{conv})}_{t,d}
-h^{(\mathrm{rec})}_{t,d}|
~~~

再比较最终任务指标。若 ε∞ 很小但任务结果不同，可能是 logits 处于决策边界；若误差随 t 单调增长，优先检查累计精度、离散化和谱稳定；若只在 chunk 边界跳变，优先检查 padding、位置和 state 传递。

这类测试还有一个实际收益：它把“长上下文支持”从模型宣传语变成可审计的执行契约。一个模型能在离线长序列上运行，并不意味着它能在服务中被抢占、迁移、恢复和批处理。

## 31.17 从 resolvent 到卷积核的验证意义

S4 的结构化矩阵参数化最终要服务于一个可计算的长卷积核。专家阅读时应理解：连续系统和离散化给出转移，结构化矩阵让核可以稳定计算，卷积/递归二重性让训练和推理分别选择合适路径。每一步都可能引入近似、有限精度和边界差异。

验证不能只比较最终 loss。对同一参数和输入，比较 dense reference、结构化 kernel、FFT/卷积路径、递归路径的 kernel 值、输出误差、梯度和长序列稳定性。记录不同长度、chunk size、dtype、batch 和 state reset 下的误差曲线。

## 31.18 HiPPO/S4 的能力边界

结构化长记忆擅长连续趋势和多尺度历史压缩，但不保证对离散实体做精确寻址。需要判断一个任务的答案是“历史的平滑函数”还是“历史中的某个原子证据”。前者可以通过状态逼近，后者可能需要更大的状态、选择性机制、外部检索或 attention。

## 31.19 训练与推理状态的生产契约

一个可部署的 S4 类模型必须明确初始状态、reset、padding、流式 chunk、跨请求隔离、batch reorder 和 checkpoint restore。训练使用卷积、推理使用递归时，chunk 的边界和离散化必须一致；否则整段离线结果正常，流式结果会在每个 chunk 重新初始化而遗忘历史。

## 31.20 卷积路径与递归路径的 worked example

取一个长度为 12 的输入，将 S4 类层分别以 full convolution、四个 chunk 的 continuation 和单步 recurrent update 执行。三条路径理论上应表示同一个离散系统，但实际输出会受到 kernel 截断、padding、离散化、有限精度和 state 初始化影响。

对每个位置比较 hidden 的最大误差和最终任务输出。若 full 与 chunk 只在 chunk 边界不同，检查 state 是否传递；若 recurrent 误差随长度增长，检查矩阵谱和累计精度；若卷积路径在长序列变慢，检查 kernel 预计算、FFT workspace 和内存布局。这个小实验把“SSM 可以训练并行、推理递归”从一句口号变成了可检查的执行契约。

生产部署还要记录 state schema、model revision、step/position、dtype、reset 条件、batch reorder 和 snapshot checksum。训练 checkpoint 能恢复参数，不代表它能恢复某个正在运行请求的 state；两种 artifact 必须分开管理。

## 31.21 S4 适合什么类型的长期依赖

S4 的状态空间记忆擅长把历史压缩成多尺度的连续状态，适合趋势、周期、局部模式和长序列传播；它不自动拥有对任意离散位置做精确寻址的能力。对“过去某个时间点的温度趋势”与“找出第 17,203 个 token 的版本号”使用同一个测试，无法公平评价状态空间模型。

可以用两组反事实区分二者：一组保持整体统计结构不变，只移动一个脉冲或周期；另一组放入两个相同格式的实体和版本号，再在末尾询问指定实体。若前者稳定而后者下降，说明长记忆存在，但内容绑定仍是瓶颈，后续应考虑 selective state、attention 或 retrieval。

## 31.22 S4 的工程含义

S4 原始论文为 https://arxiv.org/abs/2111.00396。本文对 HiPPO、DPLR 和离散化采用教学化表达，具体矩阵参数化与 CUDA/FFT 实现应以论文代码为准。

S4 的贡献是把长记忆、稳定结构和可并行计算放进同一个状态空间框架。它为 Mamba 等后续选择性状态模型提供了重要基础，但也暴露了内容依赖能力的需求。

## 31.23 HiPPO 不是“把所有历史存进向量”

HiPPO 的直觉是用一组基函数的系数近似历史函数，让状态随着新输入更新。状态中的每个维度不是一个明确的 token 槽位，而是某种时间尺度或基函数上的投影。低阶分量可能保留整体趋势，高阶分量可能保留更细的变化；维度有限时，历史必然经过压缩。

因此，HiPPO/S4 对连续信号和多尺度趋势很有启发，但不能直接推导出“任意历史 token 都能精确恢复”。如果任务要求读取一个离散实体，需要评估这个实体在投影空间中的可分离性、读出层是否知道查询方向，以及多个实体叠加后是否发生碰撞。

## 31.24 DPLR 的工程含义

结构化矩阵的目标不是让公式看起来高级，而是让长卷积核和状态转移可以被有效计算。DPLR（diagonal plus low-rank）把复杂矩阵表示成对角部分和低秩修正，通常带来更可控的谱结构和更快的核计算。简化地写成：

```math
A=\Lambda-PQ^\top.
```

这里的对角部分容易处理，低秩部分表达耦合。实际实现还涉及复数参数、稳定化、离散化和数值精度；不能把这个抽象公式当成所有 S4 代码的逐行实现。专家复现时应核对参数化、初始化、kernel 截断、FFT 长度和梯度路径。

## 31.25 S4 的长度外推实验

长度外推要区分三种能力：训练长度内的拟合、相同任务的更长推理，以及输入分布和查询模式同时变化的分布外泛化。可以在固定模型和数据的前提下，用训练最大长度 `T_train`，测试 `T_train/2`、`T_train`、`2T_train` 和 `4T_train`；每个长度都测趋势、脉冲、数字和冲突实体。

若 loss 平稳而 exact recall 下降，说明状态的统计预测还在，但可寻址细节丢失；若 hidden 误差从 chunk 边界开始增长，优先查递归实现；若所有任务都在超长处崩溃，再检查谱稳定、离散步长和训练长度。长度曲线必须和 state norm、吞吐、峰值显存、恢复误差一起保存。

## 31.26 S4 与后续选择性状态模型的关系

S4 解决的是稳定、长记忆和可训练计算路径；Mamba 等后续路线进一步让状态转移或输入注入依赖当前内容，以改善离散选择和内容寻址。两者不是简单的“旧版/新版”替代关系：S4 的结构化稳定性仍是理解状态模型的重要基础，而选择性机制增加了表达力，也增加了状态解释、并行 scan、恢复和硬件实现的复杂度。

读者应沿着四个问题比较：历史如何写入、多久衰减、查询如何读出、服务如何保存和恢复。只背“HiPPO、DPLR、Mamba”三个名字，不能解释为什么一个模型在趋势任务上好、在版本号检索上差，也不能解释为什么同一模型 full scan 与流式 decode 的结果会不同。
