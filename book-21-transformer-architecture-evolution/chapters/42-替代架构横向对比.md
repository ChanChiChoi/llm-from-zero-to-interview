# 第四十二章：替代架构横向对比：复杂度、表达力、硬件和生态

前面各章分别讲过线性注意力、稀疏注意力、SSM、RWKV、RetNet、Hyena 和卷积。本章把它们放到几组共同问题下比较：过去以什么形式留在模型中，当前位置怎样读取历史，计算和状态如何随序列长度变化，以及公开证据能支持多大范围的结论。

比较架构时，先确认比较对象处在同一层级，再区分理论复杂度、训练与生成路径、硬件执行和任务结果。这里不会把这些维度压成单一排行榜。各路线的内部推导见[第二十四至第二十七章](../目录.md)、[第二十九至第四十一章](../目录.md)；attention 与 SSM 的具体混合方式由[第四十三章](43-Attention与SSM混合架构.md)展开。

## 42.1 先对齐比较单位：算子、block、主干与完整系统

“架构更快”或“架构更强”可能指不同对象。比较前至少要分清四个层级：

| 比较对象 | 改变了什么 | 例子 |
| --- | --- | --- |
| 算法或 kernel | 相同运算怎样映射到计算设备 | FlashAttention 通过分块减少 HBM 与片上 SRAM 间的数据移动 |
| 序列混合算子 | 序列位置怎样交换或汇总信息 | dense attention、稀疏 attention、线性注意力、SSM、卷积 |
| block 或模型主干 | attention、状态层、卷积、MLP 等如何组成 | Mamba、Hyena 或交错多个混合层的模型 |
| 完整系统 | 模型外怎样增加检索、工具或运行时 | 模型加向量检索、路由或服务引擎 |

FlashAttention 是第一层的例子：它保留 dense attention 的数学运算，论文给出的核心计算仍为 $O(N^2d)$ FLOPs，同时减少中间矩阵的物化与 HBM 读写。[FlashAttention 原论文](https://arxiv.org/html/2205.14135) Sparse attention 改变可计算的位置连接；线性注意力和状态空间路线改变历史汇总方式；检索系统则增加模型外部的存储与查询。它们可以一起使用，但不能把 kernel 测速、层复杂度和完整系统任务质量放在同一列直接排名。

架构类别之间也并非完全互斥。State Space Duality 说明特定状态空间算法可以与结构化 attention 矩阵建立数学联系；这不代表任意 SSM 与任意 attention 配置具有相同成本或行为。[Transformers are SSMs](https://arxiv.org/abs/2405.21060)

## 42.2 历史表示与查询路径：模型把过去保留成什么

序列模型处理过去的方式，决定当前 token 有哪些读取路径。下面只比较信息表示，不据此直接判定任务成绩。

| 路线 | 历史保留形式 | 当前 token 读取历史的方式 | 需要注意的边界 |
| --- | --- | --- | --- |
| Full attention | 为可见位置保留显式 K/V | Query 与允许读取的 key 逐位置计算权重，再汇集 value | 可见性由 mask、窗口和上下文边界决定；有连接不等于模型一定选对证据 |
| 窗口或稀疏 attention | 保存由窗口、块布局或稀疏图允许的历史位置 | 只计算结构允许的连接；部分方法会动态选择连接 | 能否读取远处证据取决于图结构或路由，而非“稀疏”这个名称 |
| 线性注意力与递归状态 | 按各自更新规则累积有限维状态 | 用 query、当前输入或门控读写汇总状态 | 线性注意力、RNN、SSM、RWKV 和 RetNet 不是同一个算子；状态形状固定也不代表各自容量相同 |
| 卷积与门控卷积 | 按相对位移共享的滤波器，必要时叠加输入门控 | 把不同滞后位置的信号按核权重混合 | 长感受野表示远处信号存在传播路径，不等于 query 对历史位置进行独立内容寻址 |
| 混合主干 | 同时保留多种历史表示 | 由层、分支或路由决定不同路径的组合 | 各状态是否互补、怎样组合，要由具体模型结构和实验确认 |

线性注意力的因果状态可以把过去的 key/value 特征累积后再由 query 读取；其成本受特征宽度与 value 维度影响，且所选有限特征函数不自动等于精确 softmax。[线性注意力原论文](https://arxiv.org/html/2006.16236) Mamba 则通过输入相关状态更新实现选择性保留；它和固定线性时不变 SSM 的更新规则不同。[Mamba 原论文](https://arxiv.org/html/2312.00752v2)

检索或外部记忆可以保留原始文档，并不因此成为与上述算子同层级的序列 mixer。若把外部检索纳入比较，应把模型内状态、外部索引、查询过程与最终任务表现分别列出。

## 42.3 表达能力必须落到任务与训练证据

“表达力更强”需要改写成具体问题：模型要学局部 token 规律、维护一项状态、复制上下文中的 key-value 记录、从远处抽取证据，还是组合多段材料？不同任务暴露的能力不同，单一语言模型分数不会回答全部问题。

可以先把能力问题和证据类型对齐：

| 任务问题 | 有用的评测 | 评测仍不能单独证明什么 |
| --- | --- | --- |
| 常见局部模式是否学好 | 验证集 loss 或 perplexity | 特定历史条目能否被精确取回 |
| 状态更新是否可靠 | parity、计数、有限状态或其他状态追踪任务 | 真实长文档中的多证据理解 |
| 能否按 key 复制对应 value | associative recall、copying、Phonebook 类任务 | 全部 ICL 或自然语言推理能力 |
| 能否从长文本中抽取相关内容 | 固定任务与输入分布的长上下文评测 | 其他文档格式、长度、位置和干扰分布 |

例如，Zoology 在 $70$M—$360$M 模型、$10$B 个 Pile token 的设置中比较 sequence mixer；作者用特定的 n-gram 启发式切出关联回忆 token，并报告这部分约占 gated convolution 与 attention 平均 perplexity 差距的 $82\%$。这说明该实验里的损失差距集中在特定回忆切片，不是“卷积模型普遍缺乏检索能力”的定理。[Zoology 原论文](https://arxiv.org/abs/2312.04927)

同样，Mamba-3 的检索结果在任务之间并不一致。作者的 $1.5$B 模型使用 $100$B FineWeb-Edu tokens、Llama-3.1 tokenizer 和 $2$K context；检索部分将真实数据改成 cloze 格式并截断到 $2$K。论文报告 TQA、SQuAD 等任务有竞争力，半结构化的 SWDE 与非结构化 FDA 信息抽取较弱，合成 NIAH 多数设置可匹配或超过部分基线。任务格式、截断长度和位置编码都是结论的条件。[ICLR 2026 正式页面](https://proceedings.iclr.cc/paper_files/paper/2026/hash/8abd2043b71a074278d5f687947bff9c-Abstract-Conference.html)、[论文实验细节](https://arxiv.org/html/2603.15569)

因此要把结构提供的“可访问路径”和训练后观察到的“任务行为”分开。固定大小状态说明存储形状不随历史长度增加；它本身不能证明模型在任意任务上必然失败。反过来，attention 中存在从 query 到历史 key 的直接边，也不保证训练后的模型能可靠定位并组合证据。复制任务理论也需服从其模型类别和状态假设，不能无条件套到每种递归模型或语言任务上。[Copying 理论与实验](https://proceedings.mlr.press/v235/jelassi24a.html)

## 42.4 序列复杂度：训练、prefill 与逐 token 生成分开看

先区分三个问题：完整序列已知时，混合算子的序列项怎样增长；自回归生成一个新 token 时，需要读取多少历史；保存的历史状态是否随上下文长度增长。设输入长度为 $T$、隐藏宽度为 $d$、attention 窗口为 $w$、线性特征宽度为 $r$、value 宽度为 $d_v$、SSM 内部宽度为 $D$、状态维度为 $N$、卷积核宽为 $k$。下表固定 batch 和 head 数，只写每层的序列混合核心，忽略 projection、FFN、归一化与通信。

| 路线 | 完整序列的核心序列项 | 生成一个新 token 时的核心工作 | 历史状态随 $T$ 的变化 |
| --- | --- | --- | --- |
| Full attention | $O(T^2d)$ | 历史长为 $T$ 时约 $O(Td)$ | 显式 K/V 约 $O(Td)$ |
| 固定窗口 attention | $O(Twd)$ | 约 $O(wd)$ | 若窗口外 KV 可释放，约 $O(wd)$ |
| 一般稀疏 attention | $O(Ed)$，$E$ 为允许的 query-key 边数 | 取决于当前 query 的有效边数 | 取决于保留的边、窗口和全局位置 |
| 有限特征线性 attention | 状态核心约 $O(Trd_v)$，另计 feature map | 约 $O(rd_v)$ | 每头状态约 $O(rd_v+r)$，不随 $T$ 增长 |
| Mamba 式对角 SSM | 原论文记法下 scan 核心约 $O(TDN)$ | 约 $O(DN)$ | 每层状态形状约 $O(DN)$，不随 $T$ 增长 |
| 短因果卷积 | $O(Tkd)$ | 约 $O(kd)$ | 保留最近的卷积窗口，约 $O(kd)$ |
| 长卷积 | FFT 路径每通道约 $O(T\log T)$ | 取决于核的 FIR 或结构化递归表示 | 可能随核长增长，也可能由特定结构压成固定状态 |

这些量级各有假设。普通 RNN 的状态转移若是稠密矩阵，单步成本会随状态维度以平方项增长；表中 Mamba 一行是该类结构化状态更新的例子，不代表所有 SSM。稀疏注意力的成本依赖实际边数和 pattern，规则窗口的公式不能代替不规则路由的实现代价。线性注意力的状态固定也不代表训练反向会自动只用固定内存。

对自回归生成，full attention 每增加一个 token 都读取当前保留的 K/V 历史。若 $G$ 表示新增 token 数且其他维度固定，这 $G$ 步的 attention 主项约为 $O(GTd+G^2d)$；只看单步时，成本随当前前缀长度线性增加。固定状态路线在固定状态维度时，每步核心更新不随历史长度 $T$ 增长，但状态维度和更新算子本身仍有成本。

训练的并行方式也要独立比较。Attention 可并行计算整段位置，但仍有密集配对计算；可结合律允许有限特征状态和部分递归模型使用 prefix scan；卷积可按全序列卷积或 FFT 路径计算。自回归输出仍按 token 推进，训练并行不能直接翻译成生成并行。

渐近项不等于完整 block 成本。投影和 FFN 常带来 $O(Td^2)$ 项，短序列时可能盖过 sequence mixer 的序列项。实现也能显著改变数据移动与常数：FlashAttention 保留 $O(T^2d)$ 密集算术，通过分块降低额外内存和 HBM 往返。[FlashAttention 复杂度分析](https://arxiv.org/html/2205.14135)

## 42.5 硬件与生态：理论路径怎样变成可运行资产

硬件实际执行的是内存访问、矩阵运算、scan、FFT 与 kernel 调度，而不是复杂度标签。不同路径呈现不同实现要求：

| 计算路径 | 实现时要检查什么 | 证据能支持到哪里 |
| --- | --- | --- |
| Dense attention | 设备上的矩阵运算、分块、片上存储和完整交互量 | FlashAttention 证明某种精确算法能减少数据移动，不证明任意 attention kernel 都一样快 |
| 递归/SSM scan | 状态维度、scan 并行度、kernel fusion、临时状态和反向重计算 | Mamba 原论文的效率结论绑定其算法、kernel、GPU 与测试 shape |
| 稀疏连接 | pattern 是否规则、边布局是否成块、跳过零块的开销 | 理论边数减少不自动产生同等 wall-clock 收益 |
| 长卷积 | FFT 长度、频域工作区、通道数、核生成和短序列开销 | FFT 序列项不单独代表整个 block 或生成路径的成本 |

Mamba 作者为输入依赖的状态更新设计了融合、parallel scan 和重计算路径；Mamba-3 论文也指出理论线性的推理可能仍然硬件效率不高。这些工作共同说明，算法复杂度与可用 kernel 是两个需要分别记录的证据。[Mamba 原论文](https://arxiv.org/html/2312.00752v2)、[Mamba-3 论文](https://arxiv.org/html/2603.15569) 具体设备、kernel、shape 与测量阶段改变时，应重新查验，不能沿用旧的速度数值。

生态也应按具体版本检查。可核对的信号包括：是否有固定版本源码和公开 checkpoint；tokenizer、配置与训练数据是否可查；训练和权重转换路径是否有文档；主要框架是否有对应实现；是否存在与该模型版本匹配的 kernel；问题定位资料和维护状态是否足够。它们影响复用与研究成本，但本身不证明架构能力，也不能代替实际运行评估。本节没有材料估算各路线的行业采用比例。

## 42.6 以条件化证据形成比较结论

架构比较可从任务的历史访问需求开始。如果任务重视对指定旧字段的精确读取，可以把显式 attention 或外部 retrieval 列为候选；若输入是持续到达的序列，且任务适合把过去压入状态，可评估递归或状态空间路线；局部邻域模式显著时可考虑短卷积或窗口路径；既要低成本处理长流又要保留精确读取时，再比较混合结构，具体分工见[第四十三章](43-Attention与SSM混合架构.md)。这些是实验候选，不是质量保证。

读取一项比较结果时，至少记录具体模型和版本、纯模型或 hybrid、参数规模、训练数据与 token 预算、tokenizer、上下文长度、任务与输入格式、实现与硬件、测量阶段和指标。论文机制、目标设备的 kernel profile、预训练模型任务分数和完整系统成本回答的是不同问题；证据之间不能互相代替。比如，约 $8$B 规模的 Mamba 研究分别报告纯模型与 hybrid 在下游任务、Phonebook 和长上下文上的表现，结论必须按对应模型、训练预算和任务格式阅读。[An Empirical Study of Mamba-based Language Models](https://arxiv.org/abs/2406.07887)

合格的比较结论应指出：在什么任务、模型版本、训练与上下文条件下，哪种信息路径表现出什么优势；其成本是在理论算术、某个 kernel，还是完整模型层面测得；还有哪些能力或实现条件尚未验证。若条件不同，应分别呈现结果，不能用一个加权分数掩盖检索、状态追踪或硬件瓶颈。这样读者既能理解替代架构的共同取舍，也能把下一章的 attention+SSM 组合问题放回具体机制中分析。
