# 第四十八章：多模态模型中的 Mamba 替代与混合：视觉语言和长视频

“多模态模型使用 Mamba”没有指定它替换了哪一层。它可能改变视觉特征的序列混合方式、视觉到语言的连接器、负责生成回答的语言主干，或不同模态交换信息的位置。每种改变都会影响不同的数据路径，因此不能只看模型名里有没有 Mamba 就判断它更省计算、能处理更长输入，或保留了同一种视觉能力。

第十五册已经解释 VLM 的通用编码器、projector、cross-attention、query bridge、统一主干和多模态 token 预算。本章只追问一个更窄的问题：当 Transformer 序列混合器被 Mamba 替换，或两者被放进同一模型时，视觉特征如何进入序列、文本如何访问视觉证据、长视频信息在哪里被保留？第 43 章讨论 Attention–SSM 的通用混合，第 44 章比较不同序列模块的信息路径；这里把这些区别落到视觉语言与长视频模型。

## 48.1 先确定混合器位于哪条模态路径

一条常见视觉问答路径是：图像经视觉编码器变成 patch 特征；连接器把特征接到语言模型的表示空间；语言模型再结合问题生成答案。SSM 可以进入这条路径的多个位置：

| 架构位置 | 被改变的对象 | 需要追问的问题 |
| --- | --- | --- |
| 视觉编码器内部 | 图像网格如何形成视觉表示 | 二维空间关系如何映射成扫描顺序？是否双向或多方向处理？ |
| 视觉连接器 | patch 特征如何成为语言模型可读的表示 | 连接器是否改变 token 数、空间对应和信息压缩？ |
| 语言模型主干 | 已接入的视觉与文本序列如何更新 | 递归状态能否支持任务所需的历史读取？模型是否仍保留 Attention 层？ |
| 跨模态融合处 | 文本、图像、音频或视频如何相互对应 | 是按序拼接后扫描，还是先显式对齐，或用 query 读取另一模态？ |

这四个位置不能混为一谈。比如把语言主干替换成 Mamba，不表示图像编码器也变成了 Mamba；加入一个 Mamba connector，也不表示文本回答由 SSM 生成。混合架构描述的是哪些模块同时存在，必须进一步说明每个模块更新哪类表示、读取哪些输入。

## 48.2 用 Mamba 替换视觉语言模型的语言主干

Cobra 与 VL-Mamba 都把预训练 Mamba 语言模型用于视觉语言任务，但视觉表示的形成和接入方式不同。Cobra 将 DINOv2 与 SigLIP 的视觉特征组合，经 projector 映射后交给 Mamba 语言主干；它保留独立视觉编码器，改变的是语言主干及模态融合路径。[Cobra 论文](https://ojs.aaai.org/index.php/AAAI/article/download/33131/35286)将这种结构作为视觉语言模型中的一条 SSM 路线，并对多种融合方案做了实验。该结果只支持论文所用的模型、数据和比较条件，不能据此推断任何 VLM 换成 Mamba 后都会更快或维持同样的质量。

VL-Mamba 也使用预训练 Mamba 语言模型，但另设计了包含 Vision Selective Scan（VSS）的 MultiModal Connector（MMC），让视觉扫描机制参与特征连接。它因此不是简单地把传统 projector 换个名字：改变同时涉及视觉特征进入语言序列前的组织方式和序列主干。[PMLR 收录的论文](https://proceedings.mlr.press/v262/qiao24a.html)提供了该结构及其 benchmark 结果；论文属于 NeurIPS Efficient Natural Language and Speech Processing Workshop，结论应限于作者的模型和任务。

判断替换主干带来什么能力，不能只用模型总分。EMNLP 2024 的一项受控对照训练了最多 3B 参数的 Mamba-VL 与 Transformer-based Pythia-VL，固定数据、样本顺序和训练超参数。该研究报告，Mamba-VL 在图像描述、问答和阅读理解上表现有竞争力或更好，而 Transformer 模型在视觉定位任务上更强，规模增大时差距扩大；在合成的上下文多模态检索任务中，Transformer 也明显占优。[原论文](https://aclanthology.org/2024.emnlp-main.793/)把定位困难与图像信息进入模型后的读取方式联系起来，并通过实验考察相关解释。这是特定模型与任务设置下的观察，不能直接推广成所有 SSM 都无法做精确检索的结论。

从已有 Transformer 多模态模型出发再转成 SSM，是另一种构造路线。预印本 mmMamba 提出从训练好的 decoder-only 多模态模型中初始化 Mamba，并通过多阶段蒸馏构造纯线性或混合版本。[该预印本](https://arxiv.org/abs/2502.13145)将速度和显存结果绑定其 HoVLE teacher、输入长度及单卡设置。它说明“替换主干”也可能依赖迁移既有能力的训练过程，但尚不足以证明该转换方式能普遍保留不同模型的多模态能力。

## 48.3 在视觉连接器中保留空间结构

图片 patch 原先排列成二维网格；Mamba 则按一维顺序扫描输入。把网格展平成序列时，必须决定从哪里开始、沿什么方向走，以及怎样表达行列或图像边界。扫描次序会影响信息先后进入状态的顺序，所以图像序列化不是对模型透明的预处理。

VL-Mamba 在连接器中引入 VSS，尝试把视觉空间组织纳入选择性扫描。另一种方案是 Eom 等人的 Querying Mamba（Q-Mamba）：它以可学习 query 为序列，通过 Mamba 层组织 query，再用 cross-attention 从视觉编码器的 patch 特征中读取信息。这样，输出 query 不必对应原始图像的固定栅格扫描顺序；query 数还可以控制进入 Mamba 语言主干的视觉序列长度。[Findings of EMNLP 2024 论文](https://aclanthology.org/2024.findings-emnlp.827/)把这种设计与传统 projector 和已有 Mamba VLM 做了对照。

两条路线把难题放在不同位置：VSS 设计怎样遍历视觉特征；Q-Mamba 设计一组有序 query，让每个 query 从任意视觉位置取信息。前者更直接地处理二维特征的扫描方式，后者以查询和压缩换取较短的因果序列。query 压缩不代表视觉编码器少看了 patch，也不保证高分辨率图像里的每个细节都被保留。若任务需要读出小字、定位某个区域或比较两个局部对象，还要检查压缩后的表示是否保有这些证据。

这与第十五册对 Q-Former、Perceiver Resampler 等连接器的通用解释相接，但本章的问题更具体：投影到 Mamba 主干前，输出序列怎样获得可用的顺序？连接器做的是维度映射、空间扫描，还是 query 驱动的信息读取？只有把这几项分开，才能知道“换了 Mamba”时发生了哪些实际架构变化。

## 48.4 在 SSM 融合前处理跨模态对应关系

把视觉 token 和文本 token 拼成一个序列后交给 Mamba，确实可以让同一主干依次读取不同模态。但“进入同一个序列”不等于模型已经学会精确建立任意两种模态之间的对应关系。SSM 按序更新递归状态；要让某个文本片段对应某个视频帧、语音片段或图像区域，仍取决于输入顺序、训练信号和融合结构。

AlignMamba 展示了先对齐、再由 Mamba 融合的路线。它先由各自的编码器产生音频、视频和语言表示；局部对齐模块使用放松的 Optimal Transport 建立 token 级对应，全局对齐损失使用 Maximum Mean Discrepancy 缩小模态表示分布的差异，之后才把表示送入 Mamba 主干。[CVPR 2025 原论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Li_AlignMamba_Enhancing_Multimodal_Mamba_with_Local_and_Global_Cross-modal_Alignment_CVPR_2025_paper.pdf)将这套方法用于完整和缺失模态下的多模态表示融合，并在 CMU-MOSI 等数据集上评估。

AlignMamba 说明，架构可以把“局部哪两个 token 对应”和“不同模态的整体表示是否协调”作为扫描前的显式问题，再让 SSM 承担融合后的序列建模。不过其任务是音频、视频、语言参与的情感识别与表示融合，不是通用 VLM 的视觉问答；论文报告的任务成绩或效率数字不能直接证明预对齐适合所有多模态主干。若需要回答图像里某个坐标对应什么文本，必须单独验证空间定位，而不能拿情感分类结果替代。

## 48.5 长视频模型把视频混合与文本读取分开设计

长视频通常产生远多于文字指令的视频 token。对所有 token 都做全量自注意力，会让视频序列主导注意力计算；但如果把视频压成一个小摘要，模型又可能失去定位某个时间点的细节。一个可行的架构选择是让视频与文本采用不同的信息更新方式。

VAMBA 将 Mamba-2 放在视频 token 路径，用它更新长视频表示；文本 token 仍由 self-attention 处理，并通过 cross-attention 查询视频 token。于是视频历史可以用递归状态更新，而文本问题仍保留面向视觉序列的显式读取通道。[ICCV 2025 正式论文](https://openaccess.thecvf.com/content/ICCV2025/html/Ren_Vamba_Understanding_Hour-Long_Videos_with_Hybrid_Mamba-Transformers_ICCV_2025_paper.html)报告，在论文设定下，无 token 缩减时模型可处理超过 1024 帧、分辨率为 640×360 的视频；其 Transformer 对照模型可处理 256 帧。该容量比较绑定论文的模型、视频和硬件设置，不能当作所有实现的固定比例。

TimeViper 在混合主干上再加入视频 token 压缩。它保留 ViT 视觉编码器和 projector，在混合语言主干中使用 Mamba-2 与少数 self-attention 层，并通过 TransV 将部分视觉信息转入文本指令 token，再减少保留的视频 token。[CVPR 2026 论文](https://openaccess.thecvf.com/content/CVPR2026/papers/Xu_TimeViper_A_Hybrid_Mamba-Transformer_Vision-Language_Model_for_Efficient_Long_Video_Understanding_CVPR_2026_paper.pdf)报告的主干包含 27 个 Mamba-2 层和 4 个 self-attention 层；每帧视觉 token 还在 projector 中经过 ToMe 合并。TransV 通过 gated cross-attention 做信息转移，因此这不是“完全移除 Attention”的架构。

TimeViper 进一步区分指令中心任务和视觉中心任务：在视频问答与时间定位中，指令 token 可以先吸收视觉信息再生成回答；在细节描述中，视觉 token 仍可能直接影响输出。作者报告，在其 32K 输入、约 2K 帧、1K 输出、batch size 32 的设置下，TimeViper-9B 比 Qwen3-8B 多生成 40.1% token/秒。这一数字同时依赖模型、token 化、层内压缩和硬件条件，不能单独归因于 Mamba 层，也不表示同一速度增益适用于其他输入长度或任务。

## 48.6 按任务和证据判断替代与混合是否成立

几类结果放在一起看，得到的不是“Mamba 优于 Transformer”或相反的总排名，而是不同信息任务需要检查不同读取路径：

| 任务需求 | 已有研究显示什么 | 结论边界 |
| --- | --- | --- |
| 概括图像并回答一般问题 | 在 EMNLP 2024 的受控对照中，Mamba-VL 在 captioning、部分问答和阅读理解任务上具备竞争力 | 只适用于论文所比较的模型、数据、训练设置和 benchmark |
| 读取精确区域、定位对象或检索上下文细节 | 同一研究报告 Transformer-based Pythia-VL 在 grounding 和合成多模态检索任务上更强；query connector 提供了改变视觉读取方式的候选设计 | 不能从一个研究断言 SSM 永远不能做精确检索，也不能从连接器结构推断未实测能力 |
| 处理数百到数千帧视频 | VAMBA 与 TimeViper 将长视频更新、文本查询和 token 压缩分配给不同模块 | 结果依赖帧数、帧分辨率、token 合并、任务类型、训练数据、主干和硬件 |
| 融合异质模态的局部/整体线索 | AlignMamba 把 token 对应和整体分布对齐安排在 Mamba 融合之前 | 论文的情感融合任务不能替代视觉定位或通用多模态问答评测 |

因此，分析一篇多模态 SSM 论文时，先找出它替换了视觉编码、连接器、语言主干还是跨模态融合；随后确认视觉顺序、文本查询、对齐和压缩发生在哪里。比较结果时还要匹配任务、基模型、参数规模、训练数据、输入分辨率或帧数、token 数和测量环境。若连接器、主干、数据和压缩策略同时改变，整模型成绩只能说明这套组合在该设置下的结果，不能拆成某一个模块的独立收益。

本章的架构判断可以归结为一个问题：模型要处理的是可概括的长序列，还是必须从历史中精确取回某个模态证据？SSM 适合处理的路径、Attention 保留的位置、query 的读取方式以及压缩的时机，都应由这个任务需求和对应证据共同决定。
