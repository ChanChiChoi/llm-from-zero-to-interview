# 第四十八章：多模态架构中的 Transformer 替代与混合路线

## 48.1 多模态为什么更需要混合

文本、图像、音频和视频的 token 统计不同：图像有空间局部性，音频有时间连续性，视频同时有空间和时间冗余，文本需要离散符号和精确组合。把所有模态都展开成同一种长 token 序列，容易造成 token 爆炸和 attention 成本。

多模态架构通常分工：模态 encoder/conv/SSM 先提取局部或连续信号，projector 对齐语义，Transformer/attention 处理跨模态关系，外部 memory 或 retrieval 提供长时状态。

## 48.2 多模态 token 的资源模型

若文本 token 数为 T_t，图像 patch 数为 T_i，音频 token 数为 T_a，视频 token 数为 T_v，直接拼接的 attention 交互近似为：

~~~math
C_{\mathrm{full}}\propto
(T_t+T_i+T_a+T_v)^2d
~~~

如果各模态先局部编码到摘要或 latent：

~~~math
C_{\mathrm{hybrid}}\approx
\sum_m C_{\mathrm{local}}^{(m)}
C_{\mathrm{cross}}(T_{\mathrm{summary}},T_t)
~~~

压缩减少成本，却可能丢空间坐标、时间细节和局部文字。token budget 要按任务信息密度分配。

## 48.3 小白直觉：先看各自的“原生语言”

图像不应该先被迫像文字一样逐像素阅读；音频不应该丢掉连续时间；视频不能把所有帧平铺后希望模型自己发现重复。先用适合模态的局部/状态模块提取表示，再让 attention 做跨模态对齐，通常更符合信息结构。

但一旦问题要求“图中左上角的数字与视频第 3 秒的动作有什么关系”，系统仍需要全局对齐和可引用细节。

## 48.4 Encoder、projector 和 cross-attention

常见结构为：

~~~math
z_m=E_m(x_m),\qquad
h_m=P_m(z_m)
~~~

再与文本 hidden 融合：

~~~math
h'=\operatorname{CrossAttn}(Q_{\mathrm{text}},K_m,V_m)
~~~

或把 projected tokens 拼入统一序列。encoder 提取何种信息、projector 是否损失位置、cross-attention 的层数和 mask 都会影响能力。

## 48.5 音频/视频中的 SSM 与卷积

音频帧和视频时间轴具有高局部相关性，卷积、SSM 或时序 transformer 可以先处理长流，避免让语言 attention 直接承受所有帧 token。状态可保存持续上下文，再在事件/查询时提供摘要。

对于精确时间戳、说话人切换、画面文字和跨帧引用，摘要状态可能不足，需要保留关键片段索引或 global tokens。系统应有从摘要回到原始媒体的 provenance。

## 48.6 一个多模态 token 预算器

~~~python
def token_budget(text, image_patches, audio_frames, video_frames,
                 image_stride=4, audio_stride=8, video_stride=16):
    image_tokens = (image_patches + image_stride - 1) // image_stride
    audio_tokens = (audio_frames + audio_stride - 1) // audio_stride
    video_tokens = (video_frames + video_stride - 1) // video_stride
    total = text + image_tokens + audio_tokens + video_tokens
    return {
        "text": text,
        "image": image_tokens,
        "audio": audio_tokens,
        "video": video_tokens,
        "total": total,
        "full_attention_units": total * total,
    }


print(token_budget(2_000, 4_096, 16_000, 32_000))
~~~

这个估算器只描述 token 数，不代表视觉/音频质量。压缩步长变化时，必须测 OCR、时间定位、细粒度动作和跨模态问答。

## 48.7 Native unified 与 encoder-based 的取舍

encoder-based 模型先把图像/音频变成特征，再由 LLM 使用；native unified 模型可能让不同模态 token 更早进入共同 backbone。前者模块化、生态成熟，后者可能有更直接的跨模态交互，但训练数据、tokenizer、预算和硬件更复杂。

“原生多模态”不等于没有 encoder，也不等于所有模态共享同一种信息流。应根据公开模型卡和 processor 说明确认。

## 48.8 多模态 attention 的 mask

不同模态可能允许双向 encoder attention、因果文本生成、文本到图像 cross-attention 或视频时间因果。统一 token 序列时，mask 要表达这些关系。错误 mask 可能让文本看到未来视频帧，或让生成 token读到未提交 observation。

测试用未来模态反事实：只改变未来帧，检查当前输出 logits 是否变化；对因果语音/视频还要检查 chunk boundary 和 timestamp。

## 48.9 多模态 memory 和 retrieval

长期视频、图像文档和音频会产生大量原始数据。系统可以保存 embedding、事件索引、OCR、ASR 和关键帧，并在查询时检索原片段。memory 的摘要必须带时间/空间 provenance，避免模型只引用语义相似但位置错误的片段。

多模态 retrieval 需要同时考虑跨模态相似度和任务证据。例如图像中一个数字可能需要 OCR 证据，不应只靠全局视觉 embedding。

## 48.10 训练、推理和 serving

多模态系统的 prefill 可能被视觉/音频编码耗时主导，decode 仍受文本 KV；长视频的 encoder、token budget、GPU 显存和跨模态 cache 需要独立 profile。PD 分离、异步编码和缓存可以改善服务，但增加同步点。

记录模态级 TTFT、encoder time、projection time、cross-attention time、token count、KV/state bytes、媒体读取和网络延迟，才能知道瓶颈在哪里。

## 48.11 常见失败模式

包括图像 patch 过度压缩、视频时间顺序丢失、音频 chunk 边界断裂、跨模态 position 错、mask 未来泄漏、OCR/ASR provenance 丢失、模型输出引用错帧和 encoder cache 跨用户复用。

用单模态、双模态、长流、精确坐标、时间定位和冲突证据做分桶。平均 MMMU/视频问答分数不能覆盖所有工程风险。

## 48.12 机制与边界：模态混合是 token budget 和信息保真优化

多模态架构的核心约束是每种模态的 token 化、压缩和跨模态交互。减少 token 降低 attention，但会削弱高频细节；保留原始 token 提高能力，却增加 compute、KV 和 latency。最优策略与任务的信息密度、时间窗口和查询分布有关。

专家比较时要区分：encoder 质量、projector 对齐、cross-attention、统一 backbone、position/mask、token budget、retrieval 和安全策略。不能把一个“多模态模型”当作单一架构类别。

## 48.13 面试追问、误区与练习

**问：为什么视频不能简单把所有帧拼进 Transformer？**

标准回答：帧数导致 token 和 attention 计算快速增长，且视频有空间/时间冗余；通常用视觉/时序 encoder、卷积/SSM、token compression 和少量 global/cross-attention，具体取舍要看时间定位和细节任务。

**问：多模态混合架构最重要的正确性验收条件是什么？**

标准回答：模态顺序、空间/时间 position、causal mask、chunk continuation、provenance 和 token budget；再用未来反事实、精确坐标/时间和跨模态证据任务验证。

常见误区包括把 token 数当信息量、把 native unified 当无 encoder、忽略 media cache 和把语义相似当位置正确。

练习：为长视频问答设计 frame sampler、时序 state、关键帧 retrieval 和文本 global attention 的架构，并定义质量/延迟/显存验收条件。

## 48.14 多模态混合的证据回放

每个视觉、音频或视频证据都应保留模态、时间/空间范围、processor 版本和原始来源。模型输出“图中左上角数字”时，系统应能回放对应 crop 或帧，而不是只有一个跨模态 embedding。

跨模态 cache 还要绑定用户、媒体 revision 和采样参数。相同文件如果使用不同分辨率、帧率或 OCR 预处理，表示不能直接复用。

## 48.15 模态级资源预算

多模态请求的总成本可以写成：

~~~math
C_{\mathrm{mm}}
=\sum_m C_{\mathrm{encode}}^{(m)}
+C_{\mathrm{project}}
+C_{\mathrm{cross}}
+C_{\mathrm{text\ decode}}
+C_{\mathrm{media\ io}}
~~~

容量规划应按模态记录 token/帧数、encoder time、cache bytes 和失败率。减少视频帧可能提高吞吐，却可能损害时间定位；提高图像分辨率可能改善 OCR，却增加显存和延迟。

## 48.16 多模态混合的训练—推理一致性

训练时的图像 patch、音频帧和视频采样策略必须与线上 processor 对齐。分辨率、帧率、时间戳、模态顺序和 special token 一旦变化，模型可能仍能生成文本，却失去坐标和时间引用能力。

用同一媒体做离线 full input、分块 streaming 和缓存复用对照，检查模态 token 数、position、mask、encoder output 和最终 logits。不要只比较自然语言答案。

## 48.17 多模态高风险回退

OCR 数字、医疗图像、财务表格和视频时间定位失败时，可以回退专用解析器、原始 crop、关键帧或人工。回退条件应由字段级 recall 和 provenance 决定，而不是模型自报置信度。

## 48.18 原生统一与混合连接的区别

多模态模型的“统一”至少有接口、表示和目标三个层次。统一接口只说明文本、图片、音频可以由同一请求传入；统一表示意味着模态 token 可以进入同一主干；统一目标则进一步要求理解、生成、编辑或动作共享训练路径。一个系统支持多种输入，不代表它采用 encoder-free 或完全共享的内部结构。

混合架构通常保留专用 vision/audio encoder，再用 projector、cross-attention 或 token connector 与语言主干连接。这样可以复用成熟模态编码器，却要支付对齐损失、模态边界和多套 cache 的代价。阅读模型资料时应把公开事实和结构推断分开。

## 48.19 跨模态对齐的失败分解

多模态错误可以分成四类：模态解析错误、时间/空间对齐错误、跨模态推理错误和文本表达错误。图像 OCR 数字错误不能用语言模型的引用能力解释；视频时间点偏移也不能只看最终答案。

可以为每个证据单元记录：

~~~math
e=(\mathrm{modality},\mathrm{span},\mathrm{time},\mathrm{space},\mathrm{source})
~~~

评估时分别比较 encoder 输出、projector 后表示、cross-modal attention、最终文本和 provenance。只有这样，才知道问题发生在采样、编码、连接器还是生成。

## 48.20 端到端多模态成本

同一个请求的媒体输入可能被多次编码、缓存和回读。若第 m 个模态的输入大小为 n_m，编码时间为 E_m，表示缓存为 B_m，则粗略资源为：

~~~math
T_{\mathrm{media}}=\sum_m E_m+T_{\mathrm{fusion}}+T_{\mathrm{decode}},
\qquad
B_{\mathrm{media}}=\sum_m B_m+B_{\mathrm{fusion}}
~~~

降低帧数、分辨率或音频采样率会改变质量和成本的 Pareto 前沿。真实压测要按媒体时长、分辨率、帧数、并发、缓存命中和输出长度分桶，不能只用文本 token 估算。

## 48.21 多模态统一首先是编码契约

“统一 token”不意味着图像、音频和文本已经拥有相同的信息密度。视觉 patch、音频帧、离散 codec token 和文本 token 的粒度、位置和噪声都不同。模型需要明确 media placeholder、模态边界、时间/二维位置、attention mask、loss mask 和缺失模态行为。

一个多模态输入的抽象可以写成：

```text
media -> processor -> modality tokens -> position/type ids
      -> fusion layers -> decoder/tool/output protocol
```

任何一层漂移都可能表现为“模型不会看图”。因此 golden test 要保存 processor revision、媒体尺寸/采样率、token 数、placeholder、mask 和输出事件，不能只保存最终文本。

## 48.22 融合位置决定能力和成本

早期融合让模态 token 尽早进入主干，可能提高跨模态交互，但会增加序列长度和 attention/KV 成本；晚期融合保留专用 encoder，资源更可控，却可能限制细粒度交互；混合融合通常在局部层或跨模态 block 中折中。

比较这些路线时，固定媒体内容、文本任务、token budget、分辨率/帧率、参数量和训练数据，测 OCR、空间关系、时间关系、跨模态引用、延迟和显存。只测图文问答平均分，无法说明融合位置的真实收益。

## 48.23 多模态系统的降级与安全

媒体 processor 失败、图像过大、音频噪声、视频帧缺失或模型不支持某种输入时，系统要给出明确降级：只处理文本、抽取 OCR、减少帧率、请求用户重传或拒答。不能把空 embedding 当作有效视觉证据。

多模态输入还会承载图中提示注入、音频指令和文档隐写内容。分类器、策略和执行器要分层，视觉内容默认是外部数据，不会因为“图里写着请执行”就获得工具权限。

## 48.24 多模态 token budget 的具体账本

多模态混合架构的成本不能只用文本 token 估计。图像 patch、音频帧、视频时空 token 和离散 codec token 的数量、维度和采样率不同，融合位置还会改变它们参与 attention/KV 的范围。一次请求至少记录媒体尺寸/时长、processor revision、各模态 token 数、placeholder、总序列长度、KV bytes 和输出预算。

设文本 token 为 `N_text`，图像 token 为 `N_image`，音频 token 为 `N_audio`，视频 token 为 `N_video`，若它们在同一主干中做 full attention，则 token pair 近似随 `(N_text + N_image + N_audio + N_video)^2` 增长。压缩图像或减少帧率可以降低资源，却可能损害 OCR、空间和时间能力；因此必须用任务分桶做质量门。

安全门也要贯穿 processor、模型和执行器。图片中的文字、音频中的指令和文档中的二维码都是外部数据，不能因为被编码成 token 就获得工具权限。高风险动作需独立做权限、引用和人工确认。

## 48.25 多模态混合的资源分工

原始 Transformer 见 https://arxiv.org/abs/1706.03762；多模态模型的 encoder/projector/cross-attention 细节应依据对应论文、模型卡和 processor 文档。不同厂商的 native multimodal 口径不能直接互换。

多模态混合架构的核心是让每种模态先用合适的信息流处理，再在关键位置做全局对齐，同时保存可追溯的原始证据。

## 48.26 模态 token 不是同质 token

文本 token 往往对应离散词片段，视觉 patch 对应空间区域，音频 token 对应时间窗口，视频 token 同时带有空间和时间位置。把它们简单拼接后使用同一个 token budget，会掩盖每种模态的密度、噪声和错误类型。

一个输入预算应拆为模态预算和主干预算：

```math
T_{\mathrm{total}}
=T_{\mathrm{text}}+T_{\mathrm{vision}}
 +T_{\mathrm{audio}}+T_{\mathrm{video}}+T_{\mathrm{special}}.
```

压缩某一模态可能降低成本，却先损害小字 OCR、时间边界或空间关系。质量评估要按媒体尺寸、时长、分辨率、语言和任务切片，不能只看统一平均分。

## 48.27 跨模态引用与工具边界

多模态系统输出的事实可能来自原图区域、音频时间段、视频帧或 OCR 文本。引用应携带 modality、坐标/时间、processor revision 和原始 artifact，而不是只生成一段文本。模型说“图中金额是 100”不等于已经证明了哪个区域、哪个版本的图支持这个数字。

工具调用同样要把媒体理解与执行权限分开。图中二维码、音频命令和文档截图属于外部数据；只有经过结构校验、权限策略和用户确认，才可以进入 executor。多模态 encoder 提供的 representation 不能绕过安全门。

## 48.28 多模态系统的可复现包

复现一条多模态结果至少保存原始媒体 hash、尺寸/采样率、解码器、processor/tokenizer revision、模态 token 数、placeholder、position/mask、模型 revision、输出协议和评估器。只保存图片 URL 或最终回答，无法解释媒体重新编码、帧采样和 token 压缩造成的差异。

部署时还要把媒体超时、损坏、缺失和预算不足作为明确错误码，并提供文本/OCR/低分辨率回退。回退路径的质量、安全、延迟和权限必须独立测试。
