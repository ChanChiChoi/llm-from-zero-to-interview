# 第三十六章：SSM 会不会替代 Transformer：证据、争议与面试回答

“SSM 会不会替代 Transformer”其实包含几个范围不同的主张：某个 SSM 模型在特定任务上能否接近或超过 Transformer；某类 workload 是否可以把 SSM 用作主要序列层；通用语言模型是否会整体迁移到 SSM。前一类结果不能自动证明后一类。这里的 SSM（state-space model，状态空间模型）也不是单一架构：固定线性时不变模型、输入依赖的 Mamba，以及不同版本和 hybrid，信息处理方式并不相同。

读这类研究时，先确认比较的是哪一版模型、训练了多少 token、采用什么任务和输入构造，以及对照模型是什么。纯 SSM 的结果要与包含 attention 的混合模型分开。第三十五章的 SSD 说明特定递归形式可写成结构化矩阵计算；这项代数关系本身不代表两个架构拥有相同的任务能力。第三十四章细讲 Mamba 的检索与 ICL 证据，本章将相关工作放到跨架构问题中综合。

## 36.1 “替代”主张的对象与范围

模型在一组基准上有竞争力，说明它在该组模型、训练设置和任务中有竞争力；这不等于它能承担所有 Transformer 当前承担的任务。若把“替代”解释为普遍取代，就需要证据覆盖不同任务、规模、数据分布和模型版本，单篇研究通常做不到。

还要区分纯 SSM 与 hybrid。纯 SSM 对照回答“只用状态路径能做到什么”；含 attention 的 hybrid 回答“状态路径与显式注意力组合后能做到什么”。混合模型的成绩可以说明组合方案值得研究，但不能作为纯 SSM 已经取代 Transformer 的证明。

因此，本章的结论以论文实际比较对象为单位。模型名称相近、都属于 SSM，或使用同一 benchmark 名称，都不足以保证架构、训练条件和输入分布一致。

## 36.2 复杂度说明资源路径，不直接决定能力

递归状态让模型在处理新 token 时更新一份紧凑状态；自回归 Transformer 则保留历史 token 的键和值表示，使后续位置可以按内容与过去交互。两种方式给出了不同的信息保存与访问路径：前者持续压缩历史，后者保留较细的逐位置表示。它们带来不同的计算和存储增长方式，却不直接决定模型是否会答对某道题。

一个有用的阅读线索是：任务需要持续更新概括性状态，还是需要从上下文中精确找回某个条目？Albert Gu 用“压缩状态”和“逐 token cache”的差异解释这组权衡，并把它作为架构直觉；这是一种帮助读者看问题的启发式，不是“SSM 一定不能检索”或“Transformer 一定能完美记忆”的定理。[Gu 对 SSM 与 Transformer 权衡的说明](https://goombalab.github.io/blog/2025/tradeoffs/)

渐近复杂度只能描述计算或状态随序列长度怎样变化，不能单独推出真实硬件吞吐、端到端延迟或任务质量。第 33 章核对了 Mamba 论文中的算子与推理效率数据；这里不把理论复杂度重新包装成速度保证。

## 36.3 匹配规模实验中的任务差异与训练量变化

Waleffe 等人训练了约 8B 参数的 Mamba、Mamba-2 和 Transformer，并在 1.1T 与 3.5T token 设置中比较多个任务。模型规模相近、训练数据和主要超参数对齐，使这项研究比跨论文榜单更适合观察任务差异；但模型结构仍有其他配置差别，实验范围也只覆盖论文列出的模型与任务。[8B 模型比较论文](https://arxiv.org/html/2406.07887)

| 比较设置 | 论文观察 | 结论范围 |
| --- | --- | --- |
| 1.1T token，五项常见任务（不含 MMLU） | 纯 Mamba 与 Mamba-2 的平均准确率略高于 Transformer；五项任务整体接近 | 纯 SSM 能在这些任务上有竞争力 |
| 1.1T token，5-shot MMLU | Transformer 为 46.28；Mamba 为 28.00；Mamba-2 为 29.19 | 同一组模型也可能在特定任务上有明显差距 |
| 3.5T token，5-shot MMLU | 只比较了 Mamba-2 与 Transformer，分别为 48.70 和 50.07 | 更多训练 token 缩小了此项差距；不能据此声称纯 Mamba 也在 3.5T 下完成了对照 |

MMLU 本身也不是一个完全固定的输入形式。论文对比了标准选项、把答案文本作为目标和 cloze 等提示格式；在较短训练设置下，纯 SSM 在标准格式中的差距较大，而 cloze 格式的相对结果不同。一个基准的分数不仅反映模型，也受题目如何呈现和如何计分影响。

这组结果既不支持“SSM 在所有任务都落后”，也不支持“SSM 已普遍超过 Transformer”。它说明在约 8B 的特定训练和评估条件下，任务类别、训练 token 数及提示格式都能改变结论。

## 36.4 复制、检索与 ICL 证据回答的是不同问题

一些研究把重点放在精确复制和上下文查找。Jelassi 等人在广义状态空间模型的形式化定义下分析合成复制任务，并比较了预训练模型的电话簿查找；其理论结论依赖固定大小状态与精确复制等设定。Waleffe 等人的电话簿实验也观察到，纯 Mamba/Mamba-2 会给出部分数字正确、但未必精确匹配的答案。这些结果揭示了某些精确寻址任务的困难，不等于证明 SSM 不能完成自然语言任务。[复制与查找研究](https://arxiv.org/html/2402.01032)、[Mamba 电话簿实验](https://arxiv.org/html/2406.07887)

另一些研究研究的是从示例中学习函数或序列规律。Grazzi 等人在函数近似和若干 NLP ICL 任务中报告 Mamba 与 Transformer 的表现接近；Bondaschi 等人则在 Markov 链预测任务中证明并观察到单层 Mamba 可以学到特定的 Laplacian smoothing 估计器。这些结果说明，至少有些 ICL 任务可以由 Mamba 完成，但不证明任意形式的 ICL 或任意上下文检索都一样容易。[Grazzi 等人的 ICL 研究](https://proceedings.mlr.press/v256/grazzi24a.html)、[Markov 链 ICL 研究](https://proceedings.iclr.cc/paper_files/paper/2026/hash/8fef8a350b54e18758ea546bc984ba28-Abstract-Conference.html)

这些发现并不冲突：精确复制、查找条目、从样例归纳函数和估计 Markov 转移规律要求模型执行不同的操作。把它们统称为“记忆”或“ICL”，再用单个分数概括，会遮住真正的任务差异。更完整的 Mamba 任务切片见[第三十四章](34-Mamba局限与证据边界.md)。

## 36.5 新版本与 hybrid 结果改变比较对象

架构能力会随设计和版本改变。Mamba-3 论文在约 1.5B 的模型上评估 retrieval，并将真实数据任务限制为 2K token、cloze 格式。作者报告：Mamba-3 在部分问答和关联召回任务上有竞争力，在半结构化或非结构化信息抽取任务上仍有困难；合成 NIAH 的多数设置可以匹配或超过基线，其中部分分布外结果优于 Mamba-2。该论文同时指出，Transformer baseline 在整体 retrieval 分数上仍然更强。上述判断只适用于论文选用的模型和任务构造。[Mamba-3 正式论文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/8abd2043b71a074278d5f687947bff9c-Abstract-Conference.html)、[Mamba-3 实验全文](https://arxiv.org/html/2603.15569)

同样，混合模型不能并入纯 SSM 的统计。Waleffe 等人的 8B Mamba-2-Hybrid 在 3.5T token 设置下，于论文评估的 12 项常见任务中高于对应 Transformer，平均高 2.65 个百分点。其长上下文实验也有任务差异：RULER 与 LongBench 中 HotpotQA 的上下文构造不同，模型的相对结果随之变化。论文还报告了长输入、batch 32 下接近 8 倍的单 token 生成时间预测；这是特定模型条件下的预测值，不是通用端到端服务实测。[Mamba-2-Hybrid 比较与长上下文实验](https://arxiv.org/html/2406.07887)

这些结果说明，版本更新可能改善一些能力，attention 与 SSM 的组合也可能取得很强的任务结果。它们没有把 hybrid 变成纯 SSM，也没有证明纯 SSM 或某一 hybrid 配置会在其他任务、规模和服务条件下普遍胜出。混合结构的层间安排和信息路径见[第四十三章](43-Attention与SSM混合架构.md)；硬件效率证据边界见[第三十三章](33-Mamba训练推理与硬件效率.md)。

## 36.6 面对开放题时给出有边界的结论

公开证据支持这样的判断：SSM 已经是若干序列任务和语言模型中的可行竞争路线；纯 SSM 的相对表现会随任务、训练量和版本变化；一些 hybrid 研究显示，状态路径与 attention 可以共同发挥作用。现有证据还不足以推出通用 Transformer 会被 SSM 全面替代。

面试中可以这样回答：

> 目前不能说 SSM 会整体取代 Transformer。约 8B 的公开对照显示，纯 Mamba 系列在部分任务上有竞争力，但精确复制等任务仍会遇到困难，训练 token 和评测格式也会改变差距。Mamba-3 改善了部分 retrieval 结果，而表现较强的 Mamba-2-Hybrid 属于混合架构，不能算成纯 SSM 的胜出。比较稳妥的结论是，SSM 已成为可选择的序列建模路线；要判断某个 workload 是否适合它，仍需回到对应模型和任务证据。若要展开一般架构取舍，可接着读[第四十二章](42-替代架构横向对比.md)。
