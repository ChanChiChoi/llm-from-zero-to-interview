# 第 68 章 MetaP 与超参数迁移：长上下文训练的证据边界

训练规模增大后，研究者不仅要决定模型有多宽、多深，还要决定每一类参数如何初始化、以多大步长更新。若每次调整模型规模都从头搜索，超参数调优本身就会消耗很多算力。超参数迁移研究怎样利用较小模型上的实验，为更大或训练时间更长的目标模型找到合适设置。

Meta 在 Llama 4 发布资料中称其使用 MetaP 来设置关键超参数，并给出了迁移到不同 batch size、模型宽度、深度和训练 token 数的定性主张。公开材料没有附上完整算法或可复现配置。本章先把这项主张读准确，再用公开的 μP/μTransfer 和 Complete(d)P 研究解释“迁移”意味着什么。长上下文训练只作为区分训练变量与证据边界的案例；位置机制和 Llama 4 长上下文评测详见[第 67 章](67-irope与超长上下文位置机制.md)。训练配方与稳定性排障分别见第五册[第 4 章](../../book-05-llm-training/chapters/04-模型架构与初始化.md)、[第 6 章](../../book-05-llm-training/chapters/06-优化器与学习率策略.md)和[第 9 章](../../book-05-llm-training/chapters/09-训练稳定性与debug.md)。

## 68.1 MetaP：Llama 4 发布资料明确说了什么

Meta 的 Llama 4 发布页称 MetaP 是一种新的训练技术，用来可靠地设置关键模型超参数。它举出的例子是逐层学习率和初始化尺度；Meta 还称所选超参数可以迁移到不同的 batch size、模型宽度、深度和训练 token 数。[Meta 发布页](https://ai.meta.com/blog/llama-4-multimodal-intelligence/)

这是有具体内容的发布方主张，但仍是定性说明。理解它要同时看见“公开了什么”和“没有给出什么”。

### 68.1.1 逐层学习率与初始化尺度是公开举例

学习率控制优化器每次更新参数时走多大的步子。逐层学习率意味着不同网络层可以使用各自的学习率；它不同于给所有参数组共用一个全局学习率。初始化尺度描述训练开始时权重的取值范围，常见地由分布的标准差或方差表达。

这两类量都会影响训练早期的激活和参数更新。若模型宽度变化后某些层的更新幅度变得过大或过小，原来在小模型上有效的学习率就可能失效。因此，“怎样随模型规模设置各层学习率与初始化”是一个明确的技术问题。

但 Meta 的发布页没有说明 MetaP 怎样分组参数、如何计算每层学习率、采用什么初始化分布或用哪种优化器。我们只能复述页面公开的作用范围，不能从这两个例子还原具体 recipe。

### 68.1.2 四种迁移轴是不同的实验变量

Meta 说所选超参数跨不同 batch size、模型宽度、深度和训练 token 数迁移良好。它们不是同一个“规模”变量：

| 变化轴 | 主要改变什么 | 不应混同于 |
| --- | --- | --- |
| Batch size | 每次更新聚合多少训练样本或 token | 模型宽度或总训练 token 数 |
| 模型宽度 | 隐藏表示的维度及相关参数张量形状 | 网络层数 |
| 深度 | Transformer block 的层数及重复更新路径 | 隐藏维度 |
| 训练 token 数 | 训练过程累计处理的 token 量或训练 horizon | 每条训练序列的长度、推理上下文窗口 |

宽度和深度改变模型结构；batch 和训练 token 数改变训练配置或训练过程。研究若同时调整多个轴，就需要说明采用了什么规则处理这些变化，才能判断 hyperparameter transfer 到底跨过了哪一条轴。

### 68.1.3 名称和定性主张没有公开实现细节

Meta 的发布页没有给出 MetaP 的公式、逐层缩放规则、代码、具体 proxy/target 模型、完整消融或“transfer well”的误差口径。2025 年一篇优化器论文的相关工作也把 MetaP 称为尚未说明的新技术；这只是该论文作者当时对发布资料的概括，不能证明此后没有新披露。[Practical Efficiency of Muon for Pretraining](https://arxiv.org/html/2505.02222)

因此，本章不把 MetaP 展开成一个推测出的算法名，也不把它写成位置参数化或长上下文扩展方法。名称与 μP 相似，并不足以证明它们相同。读者需要掌握 Meta 公布的主张，同时知道哪些实现细节尚不能复现。

## 68.2 超参数迁移：从小模型调参到目标模型

考虑一个研究团队准备训练更大的模型。直接在目标模型上扫很多学习率、初始化尺度和 Adam 参数，每个候选配置都可能要消耗大量计算。超参数迁移的思路是先在更小、较便宜的 proxy 上搜索，再将候选配置按一套尺度规则映射到 target。

迁移不是把小模型权重放大，也不只是把所有配置字段原样复制。关键问题是：proxy 和 target 的差异是什么，改变模型规模时每类参数的规则是什么，以及目标模型上的结果离直接调优能有多远。

### 68.2.1 Proxy 与 target 必须保持可解释的对应关系

Proxy 是较小模型或较小训练设置，用来便宜地评估候选超参数；target 是实际关心的模型或训练规模。要让 proxy 的实验对 target 有意义，两者应有明确的对应关系，例如相同的 block 类型、目标函数、数据处理和优化器，而只在本轮研究的尺度轴上变化。

如果 proxy 和 target 同时更换架构、数据、优化器、训练长度和上下文长度，即使 target 最后训练成功，也无法判断成功来自哪种迁移规则。迁移研究的重点不是比较两份任意配置，而是说明从什么设置转移到了什么设置。

### 68.2.2 参数化规则决定怎样解释“同一超参数”

模型宽度增加时，权重矩阵的形状改变；同一数值的学习率经过这些矩阵产生的更新，对隐藏激活的影响不一定相同。参数化规则描述初始化、前向尺度与更新尺度如何随网络宽度等结构量变化。

因此，迁移前要区分两个东西：proxy 上被搜索的基础值，以及将这个值映射到 target 各层时采用的规则。μP 是公开的宽度参数化案例；它说明映射规则可以让不同宽度模型上的训练动态和调参曲线更相似。Meta 没有公开 MetaP 的对应规则，不能拿 μP 的规则替 MetaP 补空白。

### 68.2.3 成功意味着目标尺度上仍接近有效配置

迁移成功不要求每个配置字段的原始数字都相同。不同参数组可能按不同规则缩放；训练 token horizon 或 batch size 改变时，也可能需要改变学习率或其他参数。更实用的判断是：proxy 得到的候选配置映射到 target 后，是否仍能稳定训练，并在目标损失、下游任务和计算成本上保持有竞争力。

所以不能只看 target 有没有发散。没有 NaN 说明训练可以运行；验证损失较低说明训练目标完成得较好；下游能力和训练效率还需要各自的测量。它们回答不同问题。

## 68.3 μP 与 μTransfer：可以查阅的公开参照

μP（Maximal Update Parametrization，最大更新参数化）与 μTransfer 是公开研究中最常见的超参数迁移案例。它们可用于理解小模型调参为什么可能帮助大模型，但它们不是 MetaP 的同义词或官方解释。

### 68.3.1 宽度改变会影响训练中的更新尺度

常见的初始化规则可以让网络在训练开始时的激活保持合理尺度，但这并不自动保证训练开始后，宽度变化时每层的更新也保持相似。数据相关的梯度更新与随机初始化权重不是同一类量；如果其尺度随宽度变化，模型在不同宽度上的最优学习率也可能不同。

[Dive into Deep Learning 的 Scaling Up 教学材料](https://d2l.smola.org/slides/pytorch/chapter_optimization/scaling.html)用一个三层隐藏层 MLP 展示这个现象：隐藏宽度从 128 增至 1024，标准参数化下实验找到的最佳学习率从约 $7.8\times10^{-3}$ 移到约 $9.8\times10^{-4}$；在该材料采用的简化 μP 规则下，四种宽度的最佳点都在约 $7.8\times10^{-3}$。示例采用固定随机种子、400 次 Adam 更新、batch size 512 和训练集 loss。它是教学设置，不是大型语言模型的训练结果；它具体展示了迁移要对齐的是不同宽度上的优化行为，而非盲目复制配置文件。

### 68.3.2 μTransfer 把小模型搜索映射到大模型

Tensor Programs V 给出的 μTransfer 流程是：先把目标网络按 μP 参数化，在较小模型上调超参数，再把这些选择迁移到更大模型，而无需在后者上重新完整搜索。Microsoft Research 的解释材料用损失随学习率变化的曲线说明其直觉：如果不同宽度上的曲线最低点接近，小模型搜索就更可能找到大模型可用的学习率。[Tensor Programs V](https://arxiv.org/abs/2203.03466)；[Microsoft Research：μTransfer](https://www.microsoft.com/en-us/research/blog/%C2%B5transfer-a-technique-for-hyperparameter-tuning-of-enormous-neural-networks/?lang=zh-cn)

在这里，“迁移”不是把 proxy 模型复制一份再扩宽，而是目标模型按相应规则重新构造，学习率、初始化等参数按参数化方式解释。模型张量的角色不同，所需规则也可能不同。

### 68.3.3 公开实验也有深度与训练设置限制

Tensor Programs V 的核心证据是宽度迁移，但论文也研究了深度、batch size、sequence length 和训练时间。作者明确报告了限制：最佳初始化标准差不一定能跨深度迁移，深度迁移在 post-LayerNorm Transformer 上更脆弱，而论文中的深度迁移结果依赖特定归一化设置与实验范围。

这说明“μP 对宽度迁移有效”不能被改写成“μP 自动解决所有尺度变化”。更不能把它转述为“MetaP 就是 μP”。可借鉴的是问题结构和验证方法，不是把一个研究的结论移植给另一个名称。

## 68.4 宽度、深度、batch 与训练 horizon 不可互换

迁移方法要说明模型或训练过程的哪一条轴变化了。2026 年 ICLR 的 Complete(d)P 研究将宽度与深度参数化扩展到 batch size 和训练 token horizon，并研究逐模块超参数迁移；它是一个独立的公开方法，展示了每条轴可能需要单独的重参数化规则。[ICLR 2026 论文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/4b0c1645f3d6a1730931e65ecbf91ac3-Abstract-Conference.html)

### 68.4.1 宽度和深度需要分别说明模型变化

宽度增加隐藏维度，深度增加重复的 Transformer block。前者改变矩阵大小和每层更新的尺度关系；后者改变信息通过残差路径累积的层数。Tensor Programs V 对宽度和深度分别做实验并报告不同限制，Complete(d)P 则扩展深度方向的参数化规则。

这些结果告诉我们应分别记录 proxy 和 target 的宽度、层数、归一化方式及参数映射。只说“模型扩大十倍”会掩盖它究竟变宽、变深，还是两者都变。

### 68.4.2 Batch size 与训练 token horizon 改变优化轨迹

Batch size 增大，通常意味着一次更新汇总更多样本；训练 token horizon 增大，意味着模型经历更多训练数据或更新步数。两者会改变优化器看到的梯度统计与训练轨迹。它们不属于改变网络拓扑的同一类变量。

Complete(d)P 研究指出，μP 本身没有自动覆盖 batch size 与 token horizon 的迁移；作者为这些轴额外引入基于随机微分方程的缩放规则，并在特定训练设置下验证。这个结果说明经验迁移需要明确适用条件，不代表该论文的规则就是 MetaP 的实现。

### 68.4.3 Sequence length、training tokens 与 inference window 是三件事

三个常被混称的量需要分开：

| 名称 | 含义 |
| --- | --- |
| Training sequence length | 单条训练序列或样本中可见的 token 长度 |
| Training tokens / horizon | 训练累计处理的 token 总量或训练时间范围 |
| Inference context window | 模型或服务宣称可接收的最大输入长度 |

ACL 2025 的 ProLong 研究在 Llama-3-8B 上将训练最大序列长度从 64K 扩到 512K，并在 64K 评估长度下比较结果。作者先训练 20B token，再分别追加 4B token：一组保持 64K 训练长度，另一组切到 512K；两组使用相同超参数和数据混合。论文报告 512K 训练组在其 Recall、RAG、重排和 ICL 任务上取得更高分，同时提醒更长序列训练成本更高、未必是计算最优方案。[How to Train Long-Context Language Models (Effectively)](https://aclanthology.org/2025.acl-long.366.pdf)

这个实验改变的是单条训练序列长度，并把追加训练 token 数控制一致；它不研究 MetaP，也不是对所有模型通用的长度配方。它说明“训练用了多少 token”“每条训练序列多长”和“推理最多接收多少 token”是不同字段。

## 68.5 Llama 4 的长上下文训练与 MetaP 主张

Meta 的 Llama 4 发布页在不同段落分别介绍 MetaP 与长上下文 mid-training。读者需要把两项公开信息并列保留，而不是自动把一项的能力归因于另一项。

### 68.5.1 发布方把 10M 输入窗口连接到专门 mid-training

Meta 称 Llama 4 Scout 在 256K context length 上进行了预训练和后训练，并称专门数据集参与的 mid-training 长上下文扩展帮助解锁 10M 输入窗口。发布页另行描述 iRoPE、针尖检索与 10M token 代码 NLL；位置机制和这些评测结果的范围由[第 67 章](67-irope与超长上下文位置机制.md)详细讨论。

在公开资料所述范围内，可以说 Meta 将长上下文扩展与专门数据集的 mid-training 联系起来；不能把输入窗口、某项检索结果或代码 NLL 当成所有任务的有效长度保证。

### 68.5.2 公开材料不足以建立 MetaP 到长上下文能力的因果链

Meta 发布页分别称 MetaP 帮助设置并迁移训练超参数，以及专门 mid-training 数据集参与 Scout 长上下文扩展。它没有报告 MetaP 的单独消融来证明 10M 输入窗口由 MetaP 造成，也没有公开两项技术之间的具体因果路径。

因此，合适的结论是“Llama 4 发布资料同时披露了这两类训练信息”，而不是“MetaP 使 Llama 4 获得 10M 上下文”。两种说法差别在证据强度，不在措辞保守程度。

## 68.6 如何判断一项超参数迁移主张

判断迁移研究时，先问它迁移了哪些超参数、跨过哪些模型或训练轴，再看目标尺度上的训练和验证结果。训练是否发散、损失是否接近目标最优、下游能力是否改善、需要多少训练时间，是几种不同的结果，不能压成一个“稳定/不稳定”标签。

### 68.6.1 先写清迁移的是哪些参数、跨越哪条轴

一份可检查的迁移报告应说明 proxy 与 target、网络结构和参数化、被搜索的超参数，以及改变的宽度、深度、batch、训练 token horizon 或 sequence length。还应交代搜索是在全局学习率还是逐层学习率上进行，有无映射规则，以及哪些设置保持不变。

最近一项 2026 年 ICLR 研究展示了逐模块学习率、AdamW 参数、weight decay、初始化尺度和残差缩放的迁移实验；作者在其模型和训练设置下比较 proxy 与 target，并报告训练速度收益。它说明逐模块搜索也能研究迁移，但并没有公开 MetaP 的配置。[Complete(d)P 论文](https://proceedings.iclr.cc/paper_files/paper/2026/file/4b0c1645f3d6a1730931e65ecbf91ac3-Paper-Conference.pdf)

### 68.6.2 分开观察是否发散、loss 质量和下游能力

超参数迁移最先要跨过的是“能否训练”的门槛：若 target 上出现非有限数或持续发散，代理搜索的设置没有成功迁过去。但即使训练能完成，也还要检查验证损失是否接近 target 上更充分搜索的结果。

对语言模型而言，预训练验证损失不是所有能力的充分替代。任务级评估还要检查目标能力和可能的回归；效率比较则需记录到达相近质量所用 token、步数或墙钟时间。2026 年的一篇 arXiv 预印本进一步提出从 scaling-law 拟合质量、外推误差鲁棒性和渐近 loss penalty 三方面量化迁移。该框架是作者提出的分析方法，不是 MetaP 的指标定义或已统一采用的标准。[Kalra 与 Barkeshli 的预印本](https://arxiv.org/abs/2605.21486)

### 68.6.3 迁移结论需保留模型、数据、训练与比较条件

报告迁移结果时，应能从正文或论文中找到下列信息：

| 信息 | 为什么需要 |
| --- | --- |
| Proxy 与 target 的模型结构、宽度和深度 | 确定迁移覆盖的模型范围 |
| 参数化、优化器、调度与待调超参数 | 说明实际迁移了什么 |
| Batch size、训练 token horizon、sequence length | 区分不同训练变化轴 |
| 数据、目标函数、验证集与下游任务 | 确定比较的任务及训练分布 |
| 随机种子、发散情况与训练成本 | 判断结果稳定性和效率 |
| 直接在 target 上搜索的基准或参考曲线 | 判断 proxy 迁移离 target 可达效果有多远 |

缺少这些字段时，发布方的“transfer well”仍可作为官方公开主张引用，但读者无法判断它覆盖多少模型、数据和训练范围。未知字段应继续标为未知，不以其他公开方法的公式或经验代填。
