# 第 65 章 Hybrid Attention：局部、全局与递归状态如何分工

混合架构把不同的历史访问方式放进同一个模型。要读懂它，先分清三个问题：当前 token 能直接看到哪些位置，历史以什么表示保留下来，以及不同路径在网络的哪里相遇。局部 attention、全局 attention 和递归状态可以互补，但“混合”本身不保证模型会把任务分给正确的路径。

本章把“版本号 v2.1 出现在长日志开头，末尾问题要问哪个版本触发了异常”作为一个教学设定。它不是某个线上系统的案例，而是用来比较：如果关键信息在窗口内、窗口外或被写进递归状态，各条路径分别能直接做什么。

## 65.1 三种历史路径分别让当前 token 看到什么

局部与全局主要描述 attention 的可见范围，递归状态描述另一种保存历史的计算方式。混合模型可能只组合其中两种，也可能在一个模块内并行处理；需要按信息流判断结构，而不是从名字猜能力。

| 路径 | 历史如何进入当前计算 | 主要边界 |
| --- | --- | --- |
| 局部 attention | query 只和固定邻域内允许读取的 key 匹配，再聚合相应 value | 当前层不能直接读取窗口外的位置；更深层可能转递信息，但不保证保留原位置内容 |
| 全局 attention | query 可以在完整的可见前缀中按内容寻址历史表示 | 访问仍受 mask、表示质量和学习到的匹配能力影响；压缩缓存或稀疏选择会改变实际读到的对象 |
| 递归状态 | 每个 token 根据当前内容更新固定形状的历史状态，当前位置再从状态读出 | 状态不为每个历史 token 保留单独地址，精确细节是否保留取决于状态和训练 |

### 65.1.1 局部 attention 限定单层直接读取的邻域

因果滑动窗口 attention 通常允许位置 $t$ 读取当前 token 和它前面的至多 $w-1$ 个位置，即一个长度为 $w$ 的局部窗口。窗口内的 key 和 value 仍可被 query 分别比较，因此它保留了邻近 token 的直接读取路径。代码括号、短语搭配、相邻实体和局部复制等任务可以利用这条路径。

“局部”描述单层可见集合，不是整网的总感受野。后续位置可能通过多层局部更新，把较早 token 的影响传到更远处；但那是逐层传递后的表示，不等于当前 query 直接查看原始历史位置的 key/value。窗口外的信息可能到达，也可能在中途被弱化或覆盖。

### 65.1.2 全局 attention 保留前缀位置的直接寻址路径

全局 causal attention 允许当前位置的 query 对前缀内所有未被 mask 的位置计算匹配。标准实现按位置保存 key/value，于是较远的历史 token 仍有独立的读取入口。它提供的是直接路径，不是正确答案保证：模型仍可能给错误位置较高权重，读到相似干扰项，或在后续层里没有正确使用读出的信息。

全局可见性和存储格式是两个问题。GQA 或 MQA 通过共享 key/value head 改变每个 token 的缓存大小；MLA 把每个位置的 key/value 信息压入 latent，再由 attention 按位置读取；稀疏 attention 则可能先挑出 token 或块，再执行 attention。它们不自动等价于“只保留一个全局摘要”。全局 attention 也不一定使用标准 full KV 的表示方式。

### 65.1.3 递归状态累计历史，但不逐 token 保留地址

递归模块读入 token 后更新状态，再把新状态交给下一个 token。常见 SSM 用状态转移表达这种过程；Gated DeltaNet 或 KDA 也用递归状态保存并更新 key-value 关联，但更新规则与普通 SSM 不完全相同。第 61 章专讲 KDA，第 62 章讲通用 Gated DeltaNet；[第 76 章](76-kda从delta规则到线性注意力.md)用 Kimi Linear 展示 KDA 如何与全局 MLA 组成一个模型。本章只比较它们在混合网络中的路径角色。

推理时递归状态的形状由模型的层数、head 和状态维度等配置决定，不会因为读过的 token 多了就为每个位置再添加一份状态。这降低了随长度增长的状态存储，但状态不是原文索引：若当前位置要回答“开头出现的版本号是什么”，模型必须学会让状态保留足够辨别力。固定状态可能存住答案，也可能只保留了“曾出现一次版本变更”这类较粗的信息。

## 65.2 混合架构怎样连接不同路径

同一个局部/全局/递归路径集合，可以用不同结构连接。沿层间串接时，信息经过前一层变换后才进入下一类层；同层并行时，两条分支从同一输入开始，再把输出合起来。attention 的局部窗口或稀疏选择又是另一维度，不能与层间/层内融合混为一谈。第 43 章已系统比较融合形式，这里关注怎样从模型结构图读出这些差别。

### 65.2.1 层间交替让下游模块读取前序层的表示

在层间混合中，输入依次经过不同类型的层，例如递归层后接全局 attention 层。递归层可能已经把部分前缀信息写入 hidden state；后续全局层还可以按位置读取当前可见的历史表示。反过来，先前的 attention 层也可能让递归层接触到跨位置组合后的特征。

不过，后层读到的是前一层传来的表示，并不等于任意原始细节都可逆恢复。残差连接、归一化、投影和门控会共同决定信息保留与融合；具体影响要看模型结构，不能仅凭“后面还有一层全局 attention”断言远程回忆一定准确。

### 65.2.2 层内并行让不同模块从同一表示出发

在层内并行或 hybrid-head 设计中，同一层把输入分成 attention heads 和 SSM heads 等分支，同时处理后再融合。并行路径可以让模型在这一层就获得逐位置读取和状态更新两类候选信息；实际是否形成互补，还取决于分支维度、输出投影、归一化和融合方式。

Hymba 就在同一 hybrid-head 模块中并行使用 attention 与 SSM heads。它再结合局部/全局 attention、跨层 KV sharing 和 meta tokens，因此不能把完整模型效果只归因于“两个 head 类型并行”这一项。层内并行不是简单地把层间交替提前，也不意味着每个样本会动态选择其中一个分支。

### 65.2.3 attention 的局部性与递归状态是不同设计轴

滑动窗口 attention 仍通过 query-key-value 读取位置，只是 mask 限定了可见范围。全局 attention 允许更广范围的读取，稀疏 attention 则限制选择的 token 或块。递归状态改的是历史的保存和更新方式。因此模型可以同时包含 local attention、global attention 和递归层，也可以把短卷积放在递归模块内部；不能把所有结构都归为“local vs global”。

一个实用的阅读顺序是分别查看每层的 token-mixing operator、attention mask、状态对象和输出融合。比如“GDN 中有短因果卷积”说明输入特征先有局部混合，不代表模型另外插入了一个 local-attention layer。

## 65.3 一条远距离信息沿不同路径会发生什么

继续看教学设定中的日志：位置 $i$ 记录“版本 v2.1”，位置 $t$ 的问题问“异常发生时用的是哪个版本”。信息是否能到达输出，取决于当前位置与 $i$ 的距离、层的可见范围、状态更新和最终读出，不只是上下文总长度。

### 65.3.1 事实仍在窗口内时，局部层可直接匹配邻近表示

若 $i$ 落在第 $l$ 层的窗口中，位置 $t$ 在该层存在直接 attention 路径，可以根据 query-key 匹配读取带有版本号的 value。把问题位置逐步移到窗口边缘、再移出窗口，可以观察该路径的局部边界。工程配置中的窗口通常按 token 计数，是否把当前位置算入窗口也应以具体实现为准。

如果 $i$ 已在单层窗口之外，局部层并非绝对无法传递它的影响。更早的层可以先让邻近位置吸收信息，后续层再读取这些位置的表示；这种跨深度传播需要多次更新，可能改变原始实体、数字或版本条件。它与直接寻址有不同的路径长度和误差方式。

### 65.3.2 超出局部窗口后，全局读取和状态读出不同

如果当前有全局层，而且目标位置仍处于其 causal mask 允许的前缀中，那么 query 可以直接对位置 $i$ 的 key 或 latent 表示打分。若该层使用稀疏索引，前置选择器还必须选中包含目标的 token 或块。全局层提供可寻址入口，但并不保证选择器或 attention 会正确找到版本号。

若上下文只有递归层，版本号要经过 $i$ 之后的状态更新保留到 $t$。模型可能学到针对任务的内容编码，也可能在重复版本、干扰记录或长距离后失去精确值。判断关键在“状态是否存住并能读出这个值”，不能从状态大小固定推断它一定能或一定不能完成任务。

### 65.3.3 混合输出不会自动把不同路径变成同一种记忆

全局 attention 输出可以影响后续递归层的输入；递归状态也可以为后续 attention 提供已混合过的表示。但这不代表状态变成逐位置 KV，或 KV 自动变成足以回答未来问题的摘要。路径输出相加、拼接、门控或经过残差通路的具体方式会影响哪些信息继续传播，需按对应模型报告和实现确认。

因此对同一项问题，应分别考察“目标位置能否被当前 attention 读到”“过去是否已把目标写入状态”“两类输出怎样被后续层使用”。仅看最终回答无法判断模型依赖的是哪条路径。

## 65.4 从层表推断状态构成与资源增长

层数比例提供的是结构线索，不是完整资源账本。要判断长序列上的内存和计算变化，先确认每种层存什么、长度如何影响存储，再确认 kernel 和运行实现是否兑现理论路径。

### 65.4.1 为每类层登记实际保存的表示

标准 attention 常为每个可见历史 token 保存 key/value；滑动窗口层只需保留窗口所需的历史，但运行时是否及时淘汰旧位置取决于实现。GQA/MQA、MLA 与跨层共享会改变单 token payload 或层间复用关系。递归层保存状态张量及可能的卷积历史；其大小依赖 head、通道、状态维度和 dtype。

因此看配置时不能只记“12.5% 是 attention 层”。还要区分 attention 类型、head 数和维度、缓存精度、窗口长度、共享策略，以及递归模块有几个状态对象。具体缓存形式和完整模型账本由第 69—71 章展开。

### 65.4.2 上下文增长对三条路径的影响不同

对标准 dense full attention，单层 prefill 的成对交互随上下文长度 $T$ 近似按 $O(T^2)$ 增长；decode 时每生成一个 token，要访问该层当前可见的历史表示，KV 缓存随 $T$ 增长。窗口为 $w$ 的局部 attention 将单层直接读取量限制在 $w$ 附近；当 $w \ll T$ 时，其 prefill attention 配对数约为 $O(Tw)$，理想滑窗缓存也可被限制在窗口大小。递归层的持久状态形状不随 $T$ 增长；在状态维度固定时，逐 token scan 对序列长度的计算量按 $O(T)$ 增长，但每步成本仍由具体状态更新和 kernel 决定。

这些是机制级增长关系，不是端到端速度数字。稀疏 attention 可能少算部分 token，却未必减少缓存中保留的全部 KV；MLA 可以压缩每个位置的 payload，但历史位置数仍可能随 $T$ 增长；某些训练 scan 在长序列上更适合并行执行，单步 decode 的表现却取决于具体 kernel。比较时把 prefill、decode、缓存字节数和测量设备分开报告。

### 65.4.3 层比例不能单独决定质量或服务成本

假设两个模型的全局层比例相同，一个可以保存低秩 latent，另一个保存完整多头 KV；其 cache 并不相同。若递归层状态宽度、窗口长度或 MoE 路由也不同，参数总量更不能替代激活状态量。质量方面，少数 global 层可能足够解决某些精确检索任务，也可能在另一些任务中无法弥补压缩路径的遗漏。

所以，层表可以产生可检验预测：全局层较少时显式逐位置历史可能减少；更多递归层会增加固定大小状态对象；窗口缩小会改变直接局部访问范围。预测是否转成实际优势，需要具体模型、训练、评估、硬件和 workload 证据，不能用一个比例直接估算 p99 或并发数。

## 65.5 模型报告展示不同的混合组合

下面的模型用于对照结构组合，不构成由旧到新的性能排名。每个模型的层比例、任务成绩和上下文长度都绑定相应报告版本；第 43 章已讨论早期混合模型的系统比较，本节关注路径类别和组合位置。

### 65.5.1 Griffin：局部 MQA 与门控线性递归交替

Griffin 的 temporal-mixing blocks 交替使用 Real-Gated Linear Recurrent Unit（RG-LRU）递归块和 local MQA；论文的模型结构以两个递归块后接一个 local-attention block 的节奏组织。实验中的局部窗口通常为 1,024 个 token。论文还报告，固定大小递归状态与局部 attention 结合后，在其复制和检索任务中能取得不同于纯局部 Transformer 的表现；当目标超出窗口覆盖范围时，检索表现会下降。[Griffin 论文 §2.3、§3 和附录 E/H](https://arxiv.org/html/2402.19427v1)的这些结论限于论文模型、窗口和合成任务，不证明任意递归状态都能精确保存长历史。RecurrentGemma 官方页面将其结构概括为 Griffin 的门控递归加局部滑窗 attention。

### 65.5.2 Jamba：Transformer attention 与 Mamba 按层间比例组合

Jamba 报告的单 GPU 配置将 8 层组成一个 block，其中 1 层是 Transformer attention、7 层是 Mamba；MoE 每隔两层使用一次。论文在 1.3B 参数、250B training tokens 的消融中比较 attention:Mamba 的 $1:3$ 与 $1:7$，两种比例在所测指标上差异很小，于是较大配置选择计算开销较低的 $1:7$。[Jamba 技术报告 §2、§3.1 和 §6.1](https://arxiv.org/html/2403.19887v2)

这个配置把全局 attention 的逐位置读取与 Mamba 状态路径放在不同深度；MoE 又是另一个参数容量设计。论文结果不表示任何训练规模都应采用 $1:7$，也不能把 MoE、训练预算或各评测指标的共同变化归成单一的 hybrid 收益。

### 65.5.3 Hymba：同层 attention 与 SSM heads 并行

Hymba 在同一 hybrid-head 模块里并行处理 attention heads 和 Mamba/SSM heads。作者的模型还结合 partial sliding-window attention、少量 global attention、跨层 KV sharing 和 meta tokens。[Hymba 论文 §2](https://arxiv.org/html/2411.13676v1)因此它既展示了同层的局部/全局读取安排，也展示 attention 与状态模块如何从共享输入并行计算。

这类结构不能被缩写成“attention 管回忆、SSM 管摘要”后便认为分工已被证明。attention 输出和状态输出经投影与融合后是否各自专门化，需要相应消融和任务证据；论文中完整模型的 cache、throughput 和 benchmark 数字同时包含多项设计及其测量条件。

### 65.5.4 Qwen3.8-Flash-Next：递归、全局层与稀疏 attention 随阶段变化

Qwen3.8-Flash-Next 技术报告公开每组 3 层 Gated DeltaNet（GDN）配 1 层 full attention。GDN 模块内部还有短 causal convolution 和递归状态；这说明“局部特征混合”可以嵌在状态路径里，而不是必须另建一层 local attention。继续预训练阶段，报告又以 Qwen Sparse Attention（QSA）替换 full-attention 层：QSA 先以压缩索引选择 micro-block，再由 sparse attention 读取。[报告 v1 §2.1.1—2.1.2](https://arxiv.org/html/2608.30320v1)

报告的 full-attention、sliding-window hybrid 与 GDN hybrid 消融使用 28 层、25B-A3B 的 checkpoint，并在 400B 与 80B token 两阶段训练后通过同一评估 pipeline 比较；结果因任务而异，不能外推到所有模型或把完整 Qwen3.8 配方的表现归因于一个路径。这里尤其要区分“基础 hybrid 层表”和“continued-pretraining 后以 QSA 改造全局层”的阶段性结构。

### 65.5.5 Kimi K3：KDA 递归层与 Gated MLA 全局读取交替

Kimi K3 技术报告 v2 说明，其主干重复每组三层 KDA 接一层 Gated MLA，并在最后另加一个 Gated MLA 层。报告把 KDA 描述为 position-sensitive、recency-aware 的序列混合，把 Gated MLA 描述为全局内容交互；MLA 层本身对 query/key 使用 NoPE。[Kimi K3 技术报告 v2 §2.1—2.1.2](https://arxiv.org/html/2607.24653v2)

报告所称 1M context 同时依赖长文本数据处理、渐进 context extension、后训练任务和系统基础设施，不能归因给 $3:1$ 层比、KDA 或 NoPE 单项。位置分工见[第 64 章](64-nope与隐式顺序.md)，Gated MLA 的缓存表示见[第 63 章](63-gated-mla门控潜变量注意力.md)，完整模型证据由[第 88 章](88-kimi-k3-kda-stable-latentmoe与百万token-agent.md)负责。

## 65.6 怎样检验路径分工是否兑现

评估应针对不同的信息访问任务，而不是只把总体困惑度或一个长上下文分数当作“混合架构有效”的证明。路径测试需要改变目标位置、干扰、窗口和历史长度，并保留足以解释结果的对照条件。

### 65.6.1 按历史距离与信息类型拆分任务

要测局部路径，可把短语、括号或复制目标放在窗口内，并逐步移动到边界附近。要测全局寻址，可将版本号、实体或精确数字放到不同距离的位置，再加入相似干扰和冲突版本。要测递归状态，可测试重复模式、顺序变化或长流中需要累积的统计/状态。每类任务要标明它测的是位置可见、内容保持还是精确引用；短文本成功不能推出长距离精确回忆。

### 65.6.2 用路径消融区分组合收益与共同变化

比较全局 attention、局部 attention、递归路径与 hybrid 时，尽量对齐模型宽度、参数/FLOPs、训练 tokens、数据、tokenizer、位置处理、训练阶段和上下文。再单独改变层比例或深度位置，观察不同任务切片如何变化。若一个完整模型同时增加 MoE、换训练数据和改上下文扩展配方，模型总体变好只能说明整套设计有效，不能证明其中某个路径独立造成收益。

移除一条路径、遮蔽某些层或比较注意力/门控的使用情况，可以补充机制证据，但不自动解释模型内部全部因果。路径对照要与任务本身的输入和输出相对应，避免只看 attention map 或 gate histogram 就给模块贴上稳定职责。

### 65.6.3 质量、缓存与速度保留各自的测量口径

质量结果按精确检索、跨窗口关联、状态保持、扰动和上下文长度分桶；资源结果分别报告 prefill、单 token decode、缓存/状态字节数、batch 与硬件。稀疏 attention 需报告索引预算和被选中的位置，递归模型需说明状态维度和更新路径。不同实现或模型的单项数字不能未经条件对齐就排成性能优劣。

如果目标任务只依赖短距离关系，较多全局层可能没有必要；若必须精确引用远处的字面事实，只有递归状态的方案需要特别强的任务证据或外部检索；若两类需求并存，hybrid 才是值得验证的候选。选择依据是目标任务下的质量—资源取舍，而不是 hybrid 名称或某个模型的层比。
