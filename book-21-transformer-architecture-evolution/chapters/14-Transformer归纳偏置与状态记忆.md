# 第十四章：Transformer 的归纳偏置与状态记忆

## 14.1 先回答“归纳偏置”是什么

归纳偏置不是模型犯的偏见，而是模型在数据不足时更倾向采用哪类规律。学习者如果只看到两个样本，可能相信“相邻的词更相关”“同一个实体的名字应该保持一致”或“时间序列的最近状态更重要”。这些先验会影响模型如何用有限数据泛化。

Transformer 的核心注意力对任意 token 建立内容相关连接，局部性和顺序规律主要通过位置编码、mask、训练数据和参数学习获得。它的优势是连接灵活；代价是没有天然的递归状态、局部平移不变性或固定时间常数。RNN 把历史压进状态，CNN 把局部邻域写进卷积核，Transformer 则让当前 query 在上下文中动态选取信息。

## 14.2 小白直觉：三种“记忆方式”

可以把三种架构想成三种阅读方式：

1. **RNN** 像边读边写摘要，下一词只拿到当前摘要和新词；摘要固定大小，成本稳定，但早期细节可能被覆盖。
2. **CNN** 像用固定宽度的放大镜扫描，局部模式提取很快，远距离关系需要堆很多层或扩张窗口。
3. **Transformer** 像保留整份笔记，当前问题可以回头指向任意段落；灵活，却需要处理越来越大的笔记。

“状态记忆”不是记忆越大越好。它包含信息容量、更新规则、遗忘规律和查询方式。一个状态如果不能按当前问题选择性读取，存了很多信息也可能只是混合后的摘要。

## 14.3 Transformer 的主要归纳偏置来自哪里

一个 decoder block 可以抽象为：

```math
H' = H + \operatorname{Attn}(\operatorname{Norm}(H),P,M)
```

```math
H'' = H' + \operatorname{FFN}(\operatorname{Norm}(H'))
```

其中 `P` 是位置机制，`M` 是因果或稀疏 mask。内容相似性由 `QK^\top` 学习，顺序由 `P` 和训练分布共同约束，局部性由窗口、数据结构和层数间接形成。

对于标准 self-attention：

```math
\operatorname{Attn}(Q,K,V)=operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V
```

它没有强制“相邻位置优先”，也没有强制“相同模式平移后保持同样响应”。这让 Transformer 能学习跨句、跨文档关系，也意味着在小数据、长流和分布外长度上，模型必须从训练样本中学出这些规律。

## 14.4 顺序不是自动存在的

如果把一个句子的 token 顺序随机打乱，同时不给模型任何位置线索，self-attention 对输入集合的处理接近置换等变，模型难以区分“猫追狗”和“狗追猫”。位置编码打破了这种对称性。

绝对位置编码可把一个向量加到 token 表示：

```math
h_p=e_p+x_p
```

RoPE 则把位置写入 query/key 的旋转，使点积依赖相对位移。相对偏置、ALiBi、NoPE 或局部 mask 也提供不同的顺序先验。位置机制的选择会影响长度外推、局部性、检索和流式状态，不应只当作一个可替换的装饰模块。

## 14.5 状态记忆和显式历史的差别

显式 KV cache 保存过去每个位置的 key/value：

```math
\mathcal{K}_{1:t},\mathcal{V}_{1:t}
```

当前 query 可以对任意历史位置重新计算权重。递归模型则维护固定大小的状态：

```math
s_t=f(s_{t-1},x_t),\qquad y_t=g(s_t,x_t)
```

两者的能力边界不同。显式历史有更强的任意访问能力，但内存随 `t` 增长；固定状态内存稳定，却必须在更新时决定保留什么。若任务需要回答“第 18,237 个 token 的原始数值”，递归摘要很难保证可逆；若任务是连续传感器分类，固定状态可能更合适。

状态容量可以用一个粗略信息预算表达：

```math
I(s_t)\le d_s\cdot b_s
```

`d_s` 是状态元素数，`b_s` 是每个元素的有效比特数。这个式子不是严格的模型互信息上界，却能提醒我们：有限状态要同时保留实体、顺序、条件和异常细节，必然需要选择性写入或外部记忆。

## 14.6 一个顺序消融实验

构造四类输入：原顺序、随机 token 顺序、句子顺序打乱、只打乱位置 id。分别测下一 token loss、关系分类、远距离复制和长度外推。

```python
def rotate_sentence_order(sentences, shift):
    shift %= len(sentences)
    return sentences[shift:] + sentences[:shift]


sentences = [
    "A 在 B 左边。",
    "B 在 C 上方。",
    "问题：A 相对 C 在哪里？",
]
for shift in range(len(sentences)):
    print(shift, " ".join(rotate_sentence_order(sentences, shift)))
```

这个 demo 只展示数据变换，不代表模型结果。真正实验要保证 tokenizer、长度、标签和训练/测试划分一致。若只换字符串顺序却没有同步 position id，测到的可能是模板错误，而不是归纳偏置。

## 14.7 为什么 Transformer 仍能学出局部性

“没有天然局部性”不等于“学不会局部性”。语言数据本身包含大量相邻依赖，训练会让某些 head 学会短窗口语法；相对位置编码和局部 attention 进一步降低学习难度。问题在于这种局部规律是参数学到的，不像卷积那样由结构强制共享，因此在数据稀疏、长度改变或噪声增大时可能不稳定。

这也解释了混合架构的吸引力：局部卷积或递归路径提供稳定的短程/流式先验，少量 full attention 负责灵活的全局对齐。选择混合模块不是宣称 Transformer 失效，而是把不同先验放回结构中。

## 14.8 训练、推理和硬件取舍

训练阶段，full attention 可以并行处理整段序列，GPU 适合大矩阵乘；递归状态沿时间更新，需要 scan、chunk 或特殊 kernel。推理阶段，Transformer 的 KV cache 随历史长度增长，递归模型的 state 可保持固定，但递归依赖可能降低并行度。

对于 batch serving，显式 KV 还能通过 paged cache、prefix cache 和 GQA 降低浪费；状态模型则需要处理 state 的分配、快照、迁移、回滚和租户隔离。不能只拿 `O(T^2)` 与 `O(T)` 比较，必须把 kernel、带宽、状态通信和质量验收条件放在同一张表里。

## 14.9 与 RNN、CNN、SSM 的比较

| 路线 | 主要记忆 | 长度成本 | 内容寻址 | 适合场景 | 主要风险 |
|---|---|---:|---|---|---|
| RNN | 固定递归 state | 线性 | 较弱，取决于 state | 在线流、控制 | 长期梯度和精确回忆 |
| CNN | 局部/扩张感受野 | 近线性 | 固定局部模式 | 局部信号、视觉、音频 | 远距路径长 |
| Transformer | 显式 K/V 或稀疏历史 | full attention 近二次 | 强 | 文档推理、ICL、多任务 | KV、带宽、长上下文利用 |
| SSM/Delta | 递归矩阵或向量 state | 线性或近线性 | 输入依赖时可增强 | 长流、音频、超长序列 | 压缩损失、生态成熟度 |

这个表不是能力排名。一个训练得更好的小 Transformer 可能胜过未经优化的 SSM，一个带 global attention 的混合模型也可能同时具备两类性质。比较时要固定数据、参数规模、训练 token、kernel 和评测任务。

## 14.10 机制与边界：状态是否可逆是关键问题

若更新 `s_t=f(s_{t-1},x_t)` 不是可逆映射，多个历史会落到近似相同状态。模型依然可以完成预测，但不能保证事后恢复任意细节。门控、外部检索、显式 global token 和多尺度 state 都是在缓解这个信息瓶颈。

训练中还要注意 state 的梯度传播：全序列反向传播成本高，截断反向传播会改变模型看到的有效依赖长度；chunk 边界若处理错误，训练和流式推理的状态分布不一致。机制与边界的评测应加入 state reset、跨 chunk continuation、顺序交换、冲突版本、精确数字和异常 token，而不是只看 perplexity。

## 14.11 面试追问、误区与练习

**问：Transformer 没有递归 state，能不能说它没有记忆？**

标准回答：不能。推理时它可以通过 KV cache 保存历史表示，层内 attention 也会利用上下文；只是这种记忆是显式 token 级历史，不是固定大小的递归状态。两者在成本和精确访问能力上不同。

**问：归纳偏置越强越好吗？**

标准回答：不是。强局部/平移先验能提高数据效率，却可能限制跨位置、跨模态或长距离关系；弱先验更灵活，但需要更多数据和训练，外推稳定性可能较差。架构应匹配任务分布。

常见误区包括把 self-attention 等同于无偏置、把 state size 等同于有效记忆、把线性复杂度等同于更快，以及忽略训练/推理的状态初始化和 mask 差异。

练习：实现一个小型 attention、RNN 和 gated state 模型，在“局部分类、远距复制、流式预测、冲突版本选择”四个任务上固定参数量比较，记录准确率、显存和 p99。

## 14.12 从归纳偏置到样本效率

归纳偏置的价值可以从样本效率理解。若任务天然包含局部性、平移不变性或时间连续性，带有相应结构的模型可能用更少样本学会规律；通用 attention 的偏置较弱，理论表达更灵活，却可能需要更多数据从训练中“重新发现”这些规律。

可以把任务风险写成：

~~~math
R_{\mathrm{test}}
=R_{\mathrm{approximation}}
+R_{\mathrm{estimation}}
+R_{\mathrm{optimization}}
~~~

加入局部卷积或状态更新，可能降低某类任务的估计难度，却限制了另一类需要任意远程对齐的任务。架构选择本质上是在不同任务分布上重新分配这三类误差。

## 14.13 记忆类型的可分解测试

一个“模型记住了信息”的结论不够精确。至少要区分参数记忆、显式上下文记忆、递归状态记忆和外部检索记忆。可以用四组输入：

1. 删除上下文但保留训练常识。
2. 在上下文中加入反事实规则。
3. 把关键信息放到长流早期。
4. 改变外部数据库而不改变模型参数。

观察答案如何变化，才能判断模型依赖哪个记忆层。若删除上下文后仍输出旧答案，可能是参数先验；若 context 反事实无效，可能是 ICL 没有真正覆盖先验；若只有检索版本改变，说明事实来自外部路径。

## 14.14 归纳偏置如何改变样本效率

归纳偏置的价值可以用“在相同数据和计算下，模型需要学多少东西”来理解。若任务具有局部性，卷积或局部 attention 让模型不用从零学习邻近 token 的相关；若任务依赖精确全局引用，显式 attention 提供更短的寻址路径。偏置不是好坏标签，而是把有限参数和训练样本投入到更可能有用的函数族中。

假设任务真实分布为 `D`，模型的假设空间为 `H`，加入架构偏置后可行空间变成 `H_B`。如果 `H_B` 排除了大量不合理函数，样本效率可能提高；如果它排除了任务需要的函数，训练 loss 可能仍下降但能力上限受限。实际实验要比较学习曲线，而不是只比较最终 checkpoint。

一个最小的顺序消融应同时改变：position encoding、causal mask、局部连接和状态初始化。若去掉位置信息后短任务仍正常但反转顺序任务崩溃，说明模型依赖的是可学习的内容模式而非可靠顺序表示。若增加参数能恢复结果，不能说明偏置不重要，只说明模型用更多容量补偿了缺失结构。

## 14.15 状态记忆的可分解测试

“记住了上下文”至少包含四个不同问题：是否保存信息，是否能在正确时间更新，是否能忘掉过时信息，是否能在查询时精确读出。可以用四类合成任务分别测试 `write`、`retain`、`reset` 和 `retrieve`，并改变干扰长度、实体数量和证据位置。

对于显式历史，测试还要检查 attention 是否真的指向证据；对于压缩 state，检查状态范数、不同事实的冲突和恢复后的 state 是否一致。一个模型可能在主题分类上表现很好，却无法在两个版本号之间选出最新版本，这说明它有摘要记忆但没有可靠的版本检索。

工程上建议把状态视为带契约的对象：记录 shape、dtype、position、reset 条件、batch reorder 行为和 snapshot 版本。不同请求的 state 不能因为 batch 合并而串联；padding token 不能意外更新状态；取消后释放 state 也不能影响同页的其他请求。

## 14.16 什么时候应选择显式历史

如果任务经常需要引用原文、比较远处的多个片段、处理版本冲突或根据用户临时示例改变规则，显式 attention 或 retrieval 往往更容易验证。若任务是连续信号、长流分类、固定格式的在线预测，递归或卷积状态可能更高效。

选择不是二元的。混合架构可以用局部 state 处理大多数 token，再保留少量 global attention 处理精确证据；外部 RAG 也可以把无限历史变成少量候选文档。评测时应同时报告状态大小、精确召回率、长流吞吐、恢复成本和证据可追踪性。

## 14.17 状态容量不等于可查询记忆

把状态写成 `s_t` 很容易让人误以为它像一个可以随时检索的数据库。实际上，状态的每个维度都在承载多个历史因素，写入和读取都受到参数化更新规则的限制。若两个历史序列 `H` 和 `H_prime` 经过更新后得到相近状态，而后续 query 又无法把它们区分开，那么这个状态对该 query 来说已经发生了信息碰撞。

可以用一个教学化的碰撞实验观察这种边界。构造两段前缀，它们主题相同但在一个稀有数字上不同；让模型分别读完前缀，再给出同一个查询。增加状态维度、增加门控或引入外部检索，都可能改变碰撞率，但不能只看主题分类准确率，因为分类允许丢掉数字细节。

```math
rho_collision(delta) = P[ distance(s(H), s(H_prime)) < delta AND y(H) != y(H_prime) ]
```

这个量是实验定义，不是某个架构的理论定律。它把“状态看起来相似”和“任务答案本应不同”联系起来。对显式 KV cache，状态通常保留每个位置的 K/V，碰撞形式不同，但仍可能因量化、截断、错误复用或注意力竞争而读错证据。

直觉下，可以把递归 state 想成一页不断改写的便签：便签面积固定，写新信息时必须覆盖旧信息。进一步分析时，需要区分覆盖是随机的还是由输入门控的，状态是否有多尺度通道，查询是否能直接定位某个历史位置，以及训练损失是否真正惩罚了精确回忆。

## 14.18 用 matched experiment 判断偏置是否真的有益

比较 attention、RNN、CNN 和 SSM 时，不能拿不同规模、不同数据和不同训练时间的成品模型直接下结论。一个可解释的实验至少要固定 tokenizer、训练 token、参数量范围、优化器、batch、上下文长度和后训练协议，只改变位置机制、局部路径或递归 state 这一个主变量。

任务也要覆盖偏置真正可能影响的方向。局部分类测试局部性，远距复制测试精确寻址，顺序反转测试位置依赖，state reset 测试在线契约，版本冲突测试选择性记忆。每项任务都报告学习曲线，而不只是最后一个 checkpoint：如果带局部偏置的模型在前 20% 数据中更快收敛，说明样本效率改善；如果在长程任务上最终上限下降，说明偏置也带来了表达约束。

```math
Delta_A_bias(n) = A_biased(n) - A_baseline(n)
Delta_C_state = M_state / N_active
```

`n` 是训练样本量，第二个量是每个活跃 token 分摊的状态资源。将质量增益和资源增益放在同一张表中，才能回答“为什么选择这个偏置”，而不是把“更像卷积/更像 RNN”当成答案。

还要检查训练路径和推理路径是否一致。训练用全序列卷积、推理用递归 state 时，必须验证 chunk continuation；训练用随机 reset、线上不 reset 时，必须验证跨请求污染；训练 mask 和线上 mask 不同，则任何样本效率结论都不可靠。

## 14.19 小结与资料边界

Transformer 结构和并行优势可追溯到 Vaswani 等人的 *Attention Is All You Need*（https://arxiv.org/abs/1706.03762）；状态空间路线可参见 S4（https://arxiv.org/abs/2111.00396）和 Mamba（https://arxiv.org/abs/2312.00752）。本章的状态容量和信息瓶颈公式是解释性抽象，不应被当作某个具体实现的严格容量证明。

Transformer 的归纳偏置不是“没有”，而是主要由位置、mask、数据和学习到的 attention pattern 共同形成。显式历史换来灵活寻址，递归 state 换来稳定成本；理解这组交换，才能判断一个替代架构究竟解决了什么问题。
