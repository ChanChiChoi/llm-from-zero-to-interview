# 第十四章：Transformer 的归纳偏置不足：顺序、局部性和状态记忆

## 14.1 同一段历史，可能需要不同的记忆

一份服务变更记录先写着“atlas 的超时设为 2 秒”，后来又改成 4 秒。问“现在的超时是多少”，只要状态里保留最新值就够了；问“第一次变更时的值是多少”，则需要还能访问那条旧记录。如果状态更新时没有留下 2 秒这个值，之后的查询就不能只凭当前状态把它还原出来。若未来问题只涉及最新配置，保留所有旧记录反而不是必要条件。

这类差别说明，序列模型既要处理输入顺序，也要决定怎样保留过去。**归纳偏置**是架构预先施加的限制或偏好，影响哪些规律更容易表示和从数据中学到。卷积把局部连接和位置间共享写进结构；递归模型规定新输入要与旧状态一起更新；Transformer 的注意力则允许当前位置根据内容与其他可见位置交互。归纳偏置不是“模型带着错误偏见”，也不按强弱排好坏：偏置适合任务时能缩小学习范围，不适合时也会限制可用的信息路径。

## 14.2 三种结构如何组织序列信息

| 结构 | 写入或连接方式 | 结构直接提供的先验 | 不能据此保证什么 |
| --- | --- | --- | --- |
| 一维卷积 | 每个位置查看局部窗口；不同位置复用同一组卷积核 | 相邻模式可在不同位置用同一规则检测；感受野可随层数、膨胀等设计扩展 | 不保证只靠少数层就能访问任意远处记录；平移等变不等于分类结果平移不变 |
| RNN / SSM | 按序列顺序把当前输入并入递归状态 | 每一步都能用一个固定形状的状态继续处理后续输入 | 状态会保留哪些细节取决于更新规则和训练；“有状态”不等于能精确找回任意旧记录 |
| Transformer | 注意力在 mask 允许的位置之间，根据内容计算交互 | 当前表示可以对多个 token 位置赋予不同权重；标准 dense attention 不强制只看邻近位置 | 可连接不等于实际用对证据；注意力结构本身也不强制局部模式共享 |

Transformer 原论文把这种选择概括为以 attention 取代序列转导中的 recurrence 和 convolution，并另行加入位置编码；这是一种信息路径设计，不表示 Transformer 没有结构先验。[《Attention Is All You Need》](https://arxiv.org/abs/1706.03762)

卷积的两项限制承担不同作用：局部感受野让每个位置只读取附近区域，共享卷积核让同一种检测规则能在多个位置重用。在规则网格且边界处理与平移相容时，这带来平移**等变**：输入移动时，特征响应相应移动；它不表示最终分类对位置变化完全不敏感。[《Dive into Deep Learning》的卷积章节](https://d2l.smola.org/chapter_convolutional-neural-networks/why-conv.html)从“只看局部”与“各位置使用同一规则”推导这两项先验。对于文本，卷积窗口可以抓取短程词形或局部模式；想扩大可见范围，还要改变窗口、层数或连接方式。

递归结构采用另一种组织方法：不把每个历史位置单独留作可寻址条目，而是让状态随输入推进。Transformer 则提供按内容交互的路径；位置相近与否可以成为学习或架构设计的一部分，但普通全连接 attention 并未规定邻近位置一定更重要。使用局部 attention、卷积混合或递归分支时，模型会再加入相应结构先验。

## 14.3 Transformer 怎样获得顺序信息

在 dropout 关闭，且 self-attention 不带位置输入、位置相关偏置或 mask 时，打乱 token 只会以相同方式打乱输出表示，这叫**置换等变**。这不是说 attention 无法计算内容关系，而是这组运算本身没有区分 token 原来处于第几个位置。[《Dive into Deep Learning》的位置编码章节](https://d2l.smola.org/chapter_attention/positional-information.html)给出了这一性质及其条件。

因果语言模型还使用 causal mask：当前位置可以读取较早位置，却不能读取未来位置。这个可见性约束已经把“先前”和“之后”区分开来，因此不能把无 mask 时的置换等变性质直接套到 causal decoder 上。位置机制则按具体设计提供绝对位置、相对距离或其他位置信号；mask 规定哪些信息可见，位置机制表达位置线索，两者作用相关但不相同。位置编码的实现细节见[第七章](07-position-encoding总览-sinusoidal-learned-relative-rope-alibi.md)，可见性模式见[第八章](08-causal-mask-prefix-lm-bidirectional-attention与注意力模式.md)，长上下文下的位置扩展见[第十八章](18-RoPE与长上下文位置外推.md)。

## 14.4 历史可以存成逐位置表示，也可以压进状态

在常见 autoregressive Transformer 中，KV cache 为已处理 token 保存各注意力层的 key/value 表示。新 query 可以对 mask 允许的缓存位置重新计算权重；这保留了逐位置可访问的表示，但 cache 不是原始文本数据库，也不保证模型能正确回答所有关于历史的问题。完整的逐层缓存与容量计算由[第十一章](11-kv-cache长上下文推理和显存增长问题.md)主讲。

递归模型把旧状态和当前输入送入更新函数，再由新状态产生输出或继续下一步计算；这是 RNN 常见的状态写法，[RNN 教材章节](https://d2l.smola.org/chapter_recurrent-neural-networks/rnn.html)也说明固定状态的容量要结合具体任务判断：

```math
s_t = f(s_{t-1}, x_t), \qquad y_t = g(s_t, x_t)
```

这里，$x_t$ 是第 $t$ 步输入，$s_t$ 是更新后的状态，$y_t$ 是当前输出。对于固定形状的状态实现，单步推进时不需要随序列长度继续保存每个旧位置；代价是哪些历史细节能留到下一步，由状态表示和更新规则决定。若任务只问最新配置，状态可以专门保留最新配置；若任务会查询任意旧版本，就要让模型状态保留足以区分这些版本的信息，或另行保存和检索记录。这是任务需要与信息保留方式的匹配问题，不是“状态模型一定会忘记”或“缓存一定能答对”的定理。

“递归状态”也不等于“训练只能逐 token 串行执行”。对于时间不变的结构化状态空间模型，完整序列计算可改写为卷积形式；[《The Annotated S4》](https://srush.github.io/annotated-s4/)用递归视角、卷积视角和推理时的递归更新讲解这种转换。Mamba 的选择机制让部分状态参数依赖当前输入，因此不再等价于固定卷积核；[Mamba 原论文](https://arxiv.org/abs/2312.00752v1)给出的训练算法使用并行 scan。这里区分的是模型更新规则和计算实现；更深入的状态方程与硬件机制见[第二十九章](29-SSM数学直觉.md)、[第三十一章](31-S4核心思想.md)和[第三十三章](33-Mamba训练推理与硬件效率.md)。

外部检索又是另一种记忆：文档或事件由模型外部的数据存储保留，查询时先选出候选，再交给模型处理。它不等同于 Transformer 的 KV cache，也不等同于递归隐藏状态；检索结果会受索引、召回范围和候选排序影响。模型外部的检索增强架构和 memory-augmented Transformer 分别见[第四十五章](45-Retrieval-Augmented-Architecture.md)和[第四十六章](46-Memory-Augmented-Transformer.md)。

## 14.5 记忆能力要结合将来会问的问题

“需要记住历史”仍不够具体。若后续只做总体分类，压缩摘要可能保留了足够信息；若后续要从长序列中取出某个旧键对应的精确值，就要保留可区分这些记录的信息。查询是否可预先限定、历史是否重复、答案允许近似还是必须精确，都会改变任务对状态的要求。

Zoology 研究训练了 17 个模型，覆盖五种架构和 70M 至 1.4B 参数规模，并在 Pile 上分析重复 n-gram 的上下文关联检索。按论文的启发式切片，这类 token 约占评测 token 的 6.4%，却解释了被比较的 gated-convolution 模型与 attention 之间平均困惑度差距的 82%。作者还指出，语言中的同一段输入可能要在多个位置执行关联检索，因此提出多查询 associative recall 任务。这个结果说明特定任务里的取回能力可能影响总体指标；它不表示所有序列模型或所有语言任务都有相同比例的差距。[Zoology 原论文](https://arxiv.org/abs/2312.04927v1)给出模型、数据、切片规则和任务定义；作者的[技术讲解](https://hazyresearch.stanford.edu/blog/2023-12-11-zoology1-analysis)展示了用不同距离的键值对说明多次检索为何更难。

后续的 BASED 研究在合成多查询 recall 任务上改变状态规模，并比较六类序列混合器：训练序列长 256 token，测试序列长 1,024 token，测试中键值对数量也高于训练范围。论文观察到 recall 准确率与状态规模、架构类型有关；理论部分针对形式化的精确 associative recall，对因果递归模型且状态元素有界的情形给出空间下界。这一结论依赖该查询任务和模型假设，不能扩写成“所有固定状态模型都无法处理真实文本回忆”。[论文原文](https://arxiv.org/abs/2402.18668v1)将合成任务实验与理论条件分开陈述。

因此，讨论 memory 时要把问题说完整：状态保存了什么；更新发生在什么时候；之后的查询能从哪里读取；目标只要一个预测摘要，还是要恢复指定的旧值。具体架构比较和适用范围由[第三十章](30-SSM-RNN-CNN-Attention信息流对比.md)和[第四十二章](42-替代架构横向对比.md)展开。

## 14.6 用归纳偏置提出结构问题

读到一种新序列架构时，可以先追问三个问题：它把哪些位置连接起来，连接方式是否偏向局部或内容相关；顺序来自递归更新、因果可见性、位置机制还是几者组合；过去被保存在逐位置表示、递归状态还是外部记录中，未来查询怎样读取它。回答这些问题，能看出结构让什么变容易，也能指出可能丢失的信息路径。

这组问题不提供单一排名。短程模式共享、按顺序持续更新、对任意旧位置进行内容相关访问，是不同的结构选择；实际结果还取决于训练、任务分布、状态实现和读出机制。本册[第十五章](15-Transformer流式在线与低延迟局限.md)继续讨论流式与在线处理的交界；RNN、CNN、SSM 和 attention 的信息流与取舍由后续章节对齐比较。
