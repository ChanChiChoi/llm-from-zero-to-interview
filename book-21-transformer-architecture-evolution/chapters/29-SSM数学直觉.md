# 第二十九章：状态空间模型 SSM 的数学直觉

## 29.1 从连续系统开始

状态空间模型原本来自控制和信号处理：系统在每个时刻维护一个隐藏状态，输入推动状态变化，输出从状态中产生。对序列模型来说，这提供了一种不同于逐 token 查阅 KV 的记忆方式。

连续时间线性 SSM 的教学形式是：

~~~math
\frac{d x(t)}{dt}=A x(t)+B u(t)
~~~

~~~math
y(t)=C x(t)+D u(t)
~~~

`u(t)` 是输入，`x(t)` 是状态，`y(t)` 是输出，`A/B/C/D` 是系统参数。`A` 决定状态如何自然衰减和混合，`B` 决定输入如何写入，`C` 决定读取哪些状态，`D` 是输入到输出的直接通路。

## 29.2 小白直觉：有多个衰减速度的记忆抽屉

想象有很多抽屉：有的只保留最近几步，有的保留很久，有的记录平滑趋势。输入到来时按 `B` 写入抽屉，系统按 `A` 让旧内容衰减，输出时按 `C` 读取。

Transformer 保存较多显式历史，当前 query 再决定读哪个位置；SSM 把历史逐步压进状态，读取的是状态的组合。前者更像检索原文，后者更像持续滤波和记忆。

## 29.3 离散化

神经网络处理离散 token，需要把连续系统离散化。最简单的 Euler 离散为：

~~~math
x_t=\bar A x_{t-1}+\bar B u_t
~~~

~~~math
\bar A=I+\Delta A,\qquad \bar B=\Delta B
~~~

更稳定的离散方法可能使用零阶保持、双线性变换或可学习步长 `\Delta`。状态更新的稳定性取决于 `\bar A` 的谱半径：

~~~math
\rho(\bar A)<1
~~~

是一个常见的稳定性直觉；实际模型可能通过参数化、归一化和输入门控获得更复杂的行为。

## 29.4 卷积视角

若系统是线性、时不变的，递归可以展开成卷积：

~~~math
y_t=\sum_{i\le t}K_{t-i}u_i,\qquad
K_j=C\bar A^j\bar B
~~~

这样就不需要为每个 query 访问全部历史。训练时可以生成卷积核，用并行卷积处理整段；推理时维护递归状态，每步更新。卷积适合并行，递归适合固定状态和在线生成，这是 SSM 工程吸引力的重要来源。

## 29.5 一个离散 SSM demo

~~~python
import torch


def diagonal_ssm(sequence, decay, input_gain, output_gain):
    # sequence: [batch, seq, channels]
    state = torch.zeros_like(sequence[:, 0])
    outputs = []
    for step in range(sequence.size(1)):
        state = decay * state + input_gain * sequence[:, step]
        outputs.append(output_gain * state)
    return torch.stack(outputs, dim=1)


x = torch.randn(2, 6, 4)
y = diagonal_ssm(x, decay=0.95, input_gain=0.2, output_gain=1.0)
print(y.shape)
~~~

当 `decay` 接近 1，信息保留时间较长但数值漂移风险增加；当它较小，模型更偏近期信息。真实 SSM 具有多维、复数或结构化状态以及输入投影，这里只用标量衰减说明记忆寿命。

## 29.6 记忆长度不是一个数字

对标量衰减 `a`，过去 `j` 步的权重近似为：

~~~math
w_j=a^j
~~~

若 `a=0.9`，几十步后影响迅速下降；若 `a=0.999`，长程影响更强，但相邻状态更相似。多维 SSM 通过不同特征值提供多尺度衰减。输入依赖的 gate 还能让模型在关键 token 到来时暂时延长或缩短记忆。

因此“SSM 有固定状态”不等于“只记住固定窗口”。状态维度、谱结构、输入选择和训练任务共同决定有效记忆。

## 29.7 与 RNN 的关系

RNN 的一般形式为：

~~~math
x_t=f_\theta(x_{t-1},u_t),\qquad y_t=g_\theta(x_t)
~~~

SSM 的结构通常更受线性系统、稳定性和可并行卷积约束。它可以被看作一类有强数学结构的递归模型，而不是所有 RNN 的同义词。Mamba 进一步让部分 SSM 参数输入依赖，增强离散 token 上的选择能力。

## 29.8 训练并行、推理递归

训练要处理整段序列，递归 loop 可能串行；如果能用卷积或 scan，就能让 GPU 并行。推理只需保存 `x_t`，状态大小不随 token 长度增长，但每一步的状态更新可能受 kernel 和带宽影响。

训练和推理使用不同计算路径时，必须验证数值等价和 chunk 边界。一种常见错误是训练卷积路径的 padding 与推理递归初始化不一致，导致短样本 loss 正常、流式输出漂移。

## 29.9 SSM 的优点、缺点和适用边界

优点：长序列计算近似线性；推理状态固定；对连续信号和流式数据自然；有稳定性和滤波的数学直觉。缺点：历史被压缩，精确 token 检索困难；输入依赖和复杂状态需要专门 kernel；通用语言训练的规模证据和生态曾弱于 Transformer。

适合评估的场景包括音频、传感器、日志、基因组、视频时间轴和长流分类；通用文档问答、任意引用和复杂 ICL 则需要额外 global/retrieval 路径。

## 29.10 机制与边界：HiPPO 和结构化状态

长记忆 SSM 常通过把历史信号投影到一组基函数上，使状态近似保存不同时间尺度的系数。HiPPO 提供了连续在线压缩历史的理论框架，S4 再对状态矩阵进行结构化参数化，以便稳定、快速计算。

这些方法的关键不只是“状态维度大”，而是状态基底如何分配记忆容量、矩阵谱如何控制衰减、离散化如何保持稳定。对专家而言，应关注 `A` 的参数化、DPLR/diagonal 结构、卷积核生成、scan 和梯度长度，而不是只记住线性复杂度。

## 29.11 面试追问、误区与练习

**问：SSM 为什么能在线性复杂度下处理长序列？**

标准回答：它通过递归状态或卷积核累积历史，不需要为每个 query 构造全部历史的两两 score；状态大小近似固定，但历史信息被压缩，精确任意检索能力需要单独验证。

**问：SSM 和 RNN 是一回事吗？**

标准回答：SSM 属于状态递归序列模型的一类，通常带有线性系统、稳定性和可并行卷积结构；一般 RNN 的状态更新更自由，二者有交集但不等同。

常见误区包括把固定 state 等同于固定窗口、把卷积路径当作所有 SSM 的推理路径、忽略离散化稳定性，以及只看长度复杂度不看状态维度和 kernel。

练习：实现不同衰减谱的 diagonal SSM，测局部预测、远距复制和状态恢复；改变 chunk 边界，验证训练式卷积和推理式递归是否一致。

## 29.12 离散化是从方程到代码的桥

连续时间 SSM 需要离散化才能在 token 序列上运行。给定步长 Δ，状态转移可近似为：

~~~math
x_t=\bar A x_{t-1}+\bar B u_t,\qquad
y_t=Cx_t+Du_t
~~~

\bar A、\bar B 由连续参数和步长共同决定。步长、参数初始化和数值格式会影响稳定性；同一个连续方程，离散化方式不同也会有不同的记忆寿命。

## 29.13 状态稳定与长程记忆

若转移矩阵的谱半径过大，状态可能爆炸；过小则旧信息迅速衰减。实际模型还会加入输入依赖、门控和归一化，让不同 token 使用不同的有效记忆时间。

评估应记录 state norm、谱相关代理、梯度 norm 和长度曲线。不能只用短序列 loss 判断状态在百万 token 上是否稳定。

## 29.14 用时间常数估算记忆寿命

“状态大小固定”仍然太粗糙。即使状态只有一个标量，不同的衰减系数也会产生完全不同的有效记忆长度。对标量递推

~~~math
x_t=a x_{t-1}+b u_t,\qquad 0<a<1
~~~

输入在 t-j 时刻对当前状态的直接系数是 a^j。若把影响下降到 e^-1 的距离称为时间常数，那么：

~~~math
\tau=-\frac{1}{\log a}
~~~

影响下降到一半的距离则是：

~~~math
\tau_{1/2}=\frac{\log 0.5}{\log a}
~~~

例如 a=0.9 时，半衰期约为 6.6 步；a=0.99 时约为 69 步；a=0.999 时约为 693 步。这个计算解释了为什么多维状态需要覆盖多个衰减尺度：只用 a=0.9 的状态会很快忘掉远处趋势，只用 a=0.999 又容易把过时信息和新信息混在一起。

这只是线性影响的上界式直觉，不是任务记忆长度。非线性层、输入门控、归一化和训练数据会改变有效能力；一个状态即使数学上仍有非零影响，也可能因为信噪比太低而无法恢复事实。

## 29.15 状态容量与精确召回不是一回事

考虑一个最小探针：在长度为 L 的序列中随机位置写入一个数字，其他位置填入干扰 token，最后要求模型输出这个数字。若状态只是 d 维连续向量，它并没有一个天然的“每个 token 一个槽位”。多个事实会竞争同一组坐标，最终可分辨性取决于表示、噪声和读取函数。

可以把探针结果分成三项：

~~~math
\text{Recall}=\Pr(\hat z=z),\qquad
\text{FalsePositive}=\Pr(\hat z\ne z\mid z\text{ 未出现})
~~~

还要记录证据所在位置 p/L、事实数量 m 和状态维度 d。只报告平均准确率会掩盖一个重要现象：模型也许能回答主题摘要，却不能恢复精确数字；也许单事实召回很好，多实体冲突时却把两个版本拼成一个。

一个不依赖深度学习框架的状态基线如下。它故意使用加权和，作为“压缩状态会发生什么”的可解释下界：

~~~python
import math
import random


def scan(values, decay):
    state = 0.0
    for value in values:
        state = decay * state + value
    return state


def probe(length=64, trials=200, decay=0.98):
    hits = 0
    for _ in range(trials):
        position = random.randrange(length)
        values = [0.0] * length
        values[position] = 1.0
        state = scan(values, decay)
        expected = decay ** (length - 1 - position)
        if math.isclose(state, expected, rel_tol=1e-12, abs_tol=1e-12):
            hits += 1
    return hits / trials


print(probe())
~~~

这个基线的召回率看起来是 1，是因为探针提前知道衰减系数和位置，现实中的读取器并没有这些信息。将多个数字、随机符号和噪声加入后，状态的可逆性会迅速下降。实验的意义不是证明某个 SSM 足够或不够，而是让读者看到“保留非零影响”和“可以从状态中可靠解码”之间的差距。

## 29.16 训练路径与在线状态的契约

离线训练通常把一个 batch 的序列一次性送入 scan 或卷积核，在线推理却按请求逐步更新状态。二者至少要在四个约定上保持一致：

1. 初始状态是全零、可学习向量，还是来自 prefix；
2. padding 是否更新状态；
3. chunk 边界是否携带位置和归一化信息；
4. 请求结束时状态是否销毁、快照或交给下一个 worker。

设序列被拆成两个 chunk，状态转移为 F，则正确的连续执行应满足：

~~~math
s_{1:T}=F(F(s_0,u_{1:k}),u_{k+1:T})
~~~

而不是把第二段错误地写成 F(s_0,u_{k+1:T})。测试时可以分别比较 full scan、两段 chunk、逐 token decode 的 hidden 和 logits；如果只有最终答案相同，仍要检查中间误差是否随长度累积。

服务层还要把状态视为租户隔离的数据。复用 batch slot 时，旧请求的 state 若没有清零，下一请求可能获得不可见的前缀；做 preemption 时只保存 token offset 而不保存 state，也会导致恢复后的输出改变。状态 checksum、请求 ID、模型 revision 和 dtype 应成为 snapshot 的元数据。

## 29.17 从连续方程到可训练实现的检查链

学习 SSM 时容易从连续公式直接跳到“线性复杂度”。完整链条应是：连续系统假设、离散化、参数稳定化、卷积或 scan 训练路径、递归推理路径、状态 snapshot 和服务调度。任何一环不一致，都可能让论文里的模型和线上行为不同。

可以为每个实现保存一个 state contract：状态 shape、dtype、初始值、position/step、reset 规则、padding 行为、chunk continuation、batch reorder 和版本。测试至少比较 full convolution、chunked scan、single-step recurrence 和 restore 后的 logits。

## 29.18 记忆时间常数不是有效任务记忆

衰减系数给出的半衰期只描述线性影响的大小，不描述信噪比、可分离性和读取难度。两个事实可能在状态中都留下非零影响，但输出层无法区分它们；一个很弱的远程信号也可能被新 token 的强激活覆盖。

因此要同时做单事实、多个事实、冲突事实、删除事实和精确数字探针。记录 exact recall、旧值误报、状态范数、位置曲线和不同查询模板。只有这些指标一起稳定，才能把“有长记忆”说成“能完成长程任务”。

## 29.19 状态模型与外部证据

状态模型适合把长期趋势、摘要或流式上下文压缩成固定状态；对需要原文引用、权限检查和版本回读的任务，应保留外部 artifact 或显式检索路径。状态不是 provenance 的替代物，也不自动满足删除和租户隔离要求。

实际系统可以让 SSM 负责连续上下文，让 retrieval 或少量 global attention 负责精确证据。评测要测状态路径单独运行、外部证据单独运行和混合路径，避免把外部检索带来的收益误归因给 SSM。

## 29.20 从时间常数到可测任务

连续 SSM 中的衰减参数可以提供一个时间常数直觉，但时间常数不是有效任务记忆。设某个状态分量的离散衰减为 `a`，经过 `k` 步后旧信息的线性贡献近似为 `a^k`。当 `a` 接近 1 时，趋势能保留更久；当 `a` 较小时，状态更快忘记历史。可是，多个通道、输入驱动和非线性读出会改变最终任务表现。

可以用三组 probe 把数学直觉落地：平滑趋势预测、稀有数字复制和冲突版本选择。趋势任务可能随着记忆时间常数变长而改善；数字复制需要可寻址容量，不能只靠衰减变慢；冲突版本还要求选择性覆盖旧信息。对每组任务记录 state norm、exact recall、false positive、chunk continuation 和恢复误差，才能判断是稳定性问题还是表达能力问题。

## 29.21 离散化和在线实现的检查链

从连续方程到代码至少经过参数化、离散化、kernel、状态初始化和输出投影五步。每一步都可能引入边界差异：步长改变衰减，padding 改变有效输入，chunk reset 丢失历史，低精度改变 state norm，错误的输出投影让状态即使保存了信息也无法读出。

验证时先用单步输入比较离散方程与实现，再比较短序列 full convolution 和 recurrent scan，最后做长流、随机 reset、batch reorder 和 snapshot restore。不要只检查最终分类准确率，因为一个 state bug 可能被分类任务的冗余特征掩盖。

## 29.22 SSM 数学直觉的使用边界

S4 见 *Efficiently Modeling Long Sequences with Structured State Spaces*（https://arxiv.org/abs/2111.00396），Mamba 见 https://arxiv.org/abs/2312.00752。本文的离散化和稳定性公式是教学抽象，具体 SSM 变体需要核对论文和代码。

SSM 的核心是用有结构的递归状态表示历史，训练可寻找卷积/scan 的并行路径，推理可保持固定状态。它的优势和边界都来自同一件事：历史不再以每个 token 的形式完整保存。

## 29.23 稳定性、可表达性和可读性是三个不同问题

当离散状态转移矩阵的谱半径小于一时，旧状态的线性影响通常会衰减；谱半径接近或超过一时，可能出现长程保持、放大或数值不稳定。但稳定并不等于记忆有用，可表达也不等于能够被查询读出。一个状态可以范数稳定，却把两个实体混到同一方向；也可以保留信息，却因为输出投影能力不足而无法恢复。

对标量更新 `s_t=a s_{t-1}+b_t`，若 `|a|<1`，旧输入在 `k` 步后的直接系数为 `a^k`。这只解释单通道的线性影响，不代表完整模型的任务记忆。专家需要把三类测试分开：

1. 稳定性：state norm、NaN、梯度和长序列误差是否受控；
2. 表达性：多个事实、趋势和冲突是否能写入状态；
3. 可读性：给定查询能否从状态找回正确实体、数值和版本。

只做第一类测试，不能得出“SSM 解决了长上下文”的结论。

## 29.24 离散化选择会改变有效模型

连续方程经过离散化才成为实际网络。以零阶保持的线性系统为例，步长 `\Delta` 下可能得到：

```math
\bar A=\exp(\Delta A),
\qquad
\bar B=\int_0^\Delta\exp((\Delta-	au)A)B\,d\tau.
```

不同离散化、步长参数化和数值近似会改变衰减、相位和梯度。把连续方程写对，不代表实现就等价；如果在训练和推理中使用不同的 `\Delta`、padding 或 state reset，模型实际看到的动力系统已经改变。

验证应从单个通道开始：给定 `A,B,\Delta` 和一串输入，用高精度 reference 计算状态，再比较代码的 full scan、chunk scan、single-step 和 restore。只有单通道通过后，才进入结构化矩阵、混合精度和多 batch 测试。这样能把数学错误与 kernel/调度错误分开。

## 29.25 状态预算与请求生命周期

固定 state 并不意味着服务完全没有状态成本。若每层 state 形状为 `m`，请求并发为 `B`，层数为 `L`，元素字节数为 `b`，则：

```math
M_{\mathrm{state}}\approx B L m b.
```

当 state 维度很大、层数很多或请求需要 snapshot 时，复制、迁移和校验也会占用带宽。状态还必须与请求 owner、模型 revision、logical position、dtype 和 reset policy 绑定。复用 worker slot 时清理 state 是正确性要求，不是性能优化。

请求取消、抢占和故障恢复会暴露显式 KV 与递归 state 的差异。KV 可以按 page 重算或迁移；递归 state 可能需要完整快照，或者从最近 chunk 重放。系统应在 trace 中区分 `state_saved`、`state_restored`、`state_recomputed` 和 `state_discarded`，否则恢复后的质量变化无法归因。

## 29.26 SSM 与外部 memory 的职责分工

SSM state 适合保存对未来有用的压缩统计，却不天然保存来源、权限和可回读原文。外部 memory/RAG 保存可审计 artifact，检索器负责选择候选，SSM 可以负责在连续流中整合趋势和上下文。二者组合时，必须明确哪个模块是事实来源，哪个模块只是表示摘要。

一个可靠的引用流程可以是：SSM 扫描长流并生成候选时间段，检索或索引系统返回原始片段与 ACL，decoder 对候选片段做精确回答，最终引用只指向外部 artifact。若只从 state 生成引用 ID，却没有验证 ID 是否真实存在，状态压缩会把幻觉包装成 provenance。

这解释了 SSM 的现实边界：它不需要在所有任务上复制 full attention 才有价值，但需要把“压缩记忆”和“可审计证据”分层。选择架构时，问题不是它有没有 memory，而是这个 memory 是否满足当前任务的可寻址性、可恢复性和治理要求。
