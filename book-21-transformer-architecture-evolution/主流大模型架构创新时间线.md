# 主流大模型架构创新时间线

## 本章定位

学习 Transformer 架构演进时，不能只按模块学习：RoPE、RMSNorm、GQA、MoE、MLA、长上下文、稀疏注意力、推理优化。

真实的大模型演进更像一条时间线：一个模型提出某个设计，另一个模型吸收其中一部分，再结合自己的训练数据、系统约束和产品目标继续改造。

所以本章按时间维度梳理主流大模型的架构创新，帮助读者理解：

```text
这些模型不是孤立出现的，而是在不断借鉴、取舍和工程化。
```

重点关注：

1. GPT 早期谱系如何发展生成式预训练、规模化语言建模与 ICL 评测。
2. PaLM、Chinchilla、LLaMA 如何改变训练配比和开源架构范式。
3. Mistral、Mixtral 如何推动 GQA、滑窗注意力和开放权重 MoE。
4. Gemini、Claude、Qwen、DeepSeek 等模型如何在多模态、长上下文、MoE、MLA、推理强化上继续演进。
5. DeepSeek 系列中的 MLA、DeepSeekMoE、MTP、GRPO 等设计为什么重要。
6. 面试中如何从时间线讲“主流大模型如何一点点升级”。

说明：公开资料会持续变化，很多闭源模型不会完整披露架构细节。本章对公开论文、技术报告中明确披露的信息会直接描述；对社区传闻、未正式公开或命名不稳定的实现细节会标注为“待核验”，不把它当作确定事实。

## 1. 总体演进主线

先给出一个简化时间线。

| 时间 | 代表模型 | 关键创新 | 对后续模型的影响 |
|---|---|---|---|
| 2017 | Transformer | Self-Attention、Encoder-Decoder、并行训练 | 奠定大模型架构基础 |
| 2018 | GPT（后称 GPT-1） | 生成式预训练后进行任务监督微调 | 展示未标注文本预训练可迁移到若干有标注 NLP 任务 |
| 2019 | GPT-2 | WebText 语言模型与零样本任务评估 | 测试无需任务微调的迁移表现；论文报告不同任务结果不均 |
| 2018-2019 | BERT | Encoder-only 双向预训练 | 与生成式 decoder 路线并行发展；其能力和用途不由 GPT 谱系定义 |
| 2020 | GPT-3 | 175B 自回归模型；zero/one/few-shot ICL 评测 | 论文在固定参数的前向评估中报告多项 few-shot 结果，也记录任务弱项与污染分析 |
| 2021-2022 | Gopher / Chinchilla / PaLM | 训练 token 与参数配比、Pathways、规模化训练 | 推动 compute-optimal training 思路 |
| 2022-2023 | InstructGPT / ChatGPT | SFT + RLHF、PPO、对话对齐 | 让 base model 变成 assistant model |
| 2023 | LLaMA | 以稠密 decoder 组合 Pre-Norm/RMSNorm、RoPE、SwiGLU | 成为可复用的公开研究基线；组件来自既有工作 |
| 2023 | Falcon / MPT / Baichuan / ChatGLM | MQA/GQA、长上下文、本地化训练 | 推动开源生态多样化 |
| 2023 | Mistral 7B v0.1 | GQA、Sliding Window Attention、7B 稠密模型 | 论文结果绑定其基准与对照模型 |
| 2023–2024 | Mixtral 8x7B | Mistral 主干 + 每层 8 个 FFN experts、每 token top-2 | 2023 年发布权重、2024 年发表论文；总权重和激活计算分开 |
| 2023-2024 | Gemini / GPT-4V / Claude 3 | 多模态、长上下文、工具和安全系统 | 模型从文本生成器走向通用助手 |

| 2025 | GPT-5.x、Claude 4.x、Gemini 3、Grok 4.x | 闭源通用模型继续叠加 reasoning、长上下文、多模态、工具和安全运行时 | 模型能力开始由基础模型、后训练、工具编排和服务合同共同决定；内部 block 多未公开 |
| 2025-2026 | Qwen3、Qwen3-Omni、Qwen3-VL、Kimi K2.5/K2.6、GLM-5.1 | 开源/半开放模型把 thinking 开关、原生多模态、代码 Agent 和 MoE 配置做成可比较的模型家族 | 推动模型卡、工具协议、评测 harness 与架构字段一起记录 |

| 2026 | Gemini 3.1-3.8、Gemini 4 Argon | 长上下文、多模态、Interactions/tool schema、coding/enterprise/cyber 产品合同 | schema 与发布方 benchmark 可作为运行时证据；不能据此推断闭源模型 block 或专家路由 |

| 2026 | Grok 4.20 Multi-agent | 多代理 harness、工具编排和 API/runtime 合同 | 体现 agent orchestration 的产品化方向；xAI 未公开完整参数、attention、MoE 和训练 recipe |

这条线说明一个趋势：

```text
早期重点是模型变大。
中期重点是训练更高效、推理更便宜。
后期重点是长上下文、多模态、MoE、推理能力和系统级优化。
```

## 1.1 项目模型登记规则

本章的时间线同时承担项目模型目录的作用。模型首先由 Artificial Analysis 或 DataCurve/DeepSWE 排行榜发现，再把论文、技术报告、模型卡、官方博客和 serving 实现作为该模型的补充证据。官方资料单独发现的历史模型可以保留，但不伪装成排行榜新发现。

登记时按模型家族或 canonical model 归并，不把 `reasoning/non-reasoning`、`effort`、provider、fallback、地区路由和 hosted revision 重复计为不同基础模型。每一行都区分以下证据边界：

- **架构事实**：论文、技术报告、固定 revision 模型卡或配置明确披露的层数、注意力、MoE、路由等信息。
- **运行时合同**：上下文、工具、缓存、compaction、流式输出和 API 路由；不能据此推断内部 Transformer 结构。
- **榜单观察**：Artificial Analysis 或 DataCurve/DeepSWE 的配置、分数、成本和速度；这些结果属于具体 provider、工具环境和评测时点。
- **未公开**：官方没有披露的参数规模、训练配方、注意力变体、专家路由或生产验收，不用社区猜测补齐。

新模型候选只从[项目计划第 2.3 节](../plan.md)规定的 Artificial Analysis 或 DataCurve/DeepSWE 榜单发现；官方博客、模型目录、论文、GitHub、Hugging Face 和 API 文档用于核验已发现候选及其周边技术，不另行充当候选入口。登记时先建立真实的 source note，再同步 `PAPERS.md`、`BOOK_SERIES.md` 和本时间线；只有形成明确架构读者结果时才增补正式章节、题目和练习。只有榜单证据的模型也可列入观察表，但必须标为“架构未公开/官方资料待核验”，不能据排名推断内部结构。

## 2. 2017：Transformer 奠定基础

Transformer 的关键创新是 Self-Attention。

它解决了 RNN/CNN 在长距离依赖和并行训练上的问题。

核心特点：

1. 用 attention 让任意两个 token 直接交互。
2. 训练时可以并行处理整个序列。
3. 使用多头注意力学习不同子空间关系。
4. 使用 FFN 提供 token-wise 非线性变换。
5. 用残差和 LayerNorm 提高训练稳定性。

它最早是 encoder-decoder 架构，用于机器翻译。

但后来大模型主流逐渐转向 decoder-only。

原因是 decoder-only 更适合统一成一个目标：

```text
next-token prediction
```

这个目标简单、可扩展、数据来源广，并且天然适合生成。

## 3. 2018-2020：GPT 系列推进生成式预训练与任务迁移

早期 GPT 论文共享自回归语言建模路线，但任务适配和评估方式逐步变化。下面的谱系不表示三代实验只改变了参数量，也不代表后来所有 GPT 产品都使用同一内部结构。

### 3.1 GPT（后称 GPT-1）与 GPT-2

2018 年的 [GPT 论文](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)把 decoder-only Transformer 的生成式语言模型预训练与任务监督微调结合起来，并为不同任务设计输入变换。论文标题没有 GPT-1 这一编号；用这个称呼时应理解为后来的谱系命名。

GPT-2 将重点推进到零样本迁移评估：模型在 WebText 上训练后，以文本任务格式直接生成结果。[技术报告](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf)记录了若干任务上的随规模变化，也明确指出部分任务的定量表现仍较弱。因此，这组结果说明语言模型可以在一些条件下不经任务微调而迁移，不是证明它能可靠完成所有任务。

### 3.2 GPT-3 与 In-Context Learning

GPT-3 [论文](https://arxiv.org/abs/2005.14165)系统比较 zero-shot、one-shot 和 few-shot 评测：任务说明和 demonstration 作为文本输入，评测时不执行梯度更新或任务微调。论文报告多类任务上的 few-shot 结果，同时列出明显弱项和预训练语料与 benchmark 重叠的分析。

其历史影响是让固定参数下的上下文条件化成为可测量的研究对象，而不是证明模型已学会任意新规则，也不确定唯一的内部机制。ICL 的示例作用、上下文读取及机制解释见第二十一册第十二章；本章仅记录它在 GPT 谱系中的位置。

GPT-3 进一步提升了 decoder-only 自回归路线在通用语言模型研究中的影响力；后来它成为主流，还受到数据、训练规模、后训练和工程生态等因素共同推动，不能由单篇论文解释。

## 4. 2021-2022：Chinchilla、PaLM 与 compute-optimal 训练

早期 scaling 往往强调参数变大。

Chinchilla 之后，一个重要观念变得清晰：

```text
在固定计算预算下，模型参数和训练 token 数要匹配。
```

如果模型参数很大但训练 token 不够，模型可能 undertrained。

这影响了后来的开源模型训练策略：

1. 不盲目堆参数。
2. 更重视高质量 token 数。
3. 更重视数据清洗和数据配比。
4. 用较小模型训练更多 token，也可能很强。

PaLM 则展示了大规模训练系统和 Pathways 思路。

这一阶段的核心不是某一个 attention 改造，而是训练范式变化：

```text
模型能力 = 架构 × 参数 × 数据 × 训练 token × 系统效率
```

## 5. 2022-2023：InstructGPT、ChatGPT 与对齐训练

Base model 不等于 assistant。

InstructGPT 和 ChatGPT 的历史作用，是把“指令示范 + 人类偏好反馈”的后训练路线带到更广泛的指令使用场景。人类偏好学习此前已见于语言模型微调与摘要研究；可对照 [InstructGPT 原论文](https://arxiv.org/abs/2203.02155)、[Ziegler 等（2019）](https://arxiv.org/abs/1909.08593)和 [Stiennon 等（2020）](https://arxiv.org/abs/2009.01325)。

```text
预训练 base model
-> SFT
-> Reward Model
-> PPO-RLHF
-> 对话助手
```

这一阶段的重要变化在于训练目标、数据和产品交互；InstructGPT 论文展示的是 GPT-3 基座经过后训练后的行为变化，并未提出新的 Transformer block。

它让大家意识到：

1. 预训练提供通用生成能力，但不保证模型稳定遵循用户意图。
2. SFT 用示范回答塑造指令格式和常见任务行为。
3. 偏好优化改变候选回答的选择倾向；偏好分数不能替代事实、安全和任务成功评估。
4. 多轮对话产品还包含上下文组织、政策和系统实现，不能从网页体验反推内部架构。

InstructGPT 的偏好结果绑定论文中的 API prompt 分布与标注协议。ChatGPT [2022 年发布说明](https://openai.com/index/chatgpt/)描述的是初始产品，不能当作当前版本的完整技术披露。后续 DPO 与 reasoning RL/RLVR 使用不同目标和训练设置，不能只因都涉及反馈或奖励便视为同一方法。

## 6. 2023：LLaMA 带来可复用的开源研究基线

LLaMA 对开源权重研究生态影响很大。

它不是第一个 decoder-only 模型，也没有发明 RoPE、RMSNorm 或 SwiGLU；原论文把这几项设计分别关联到 GPT-3、PaLM 与 GPT-Neo 等先前工作，再组合进一组基础语言模型。[原始 LLaMA 论文](https://arxiv.org/abs/2302.13971)

典型设计包括：

1. 稠密、自回归 decoder-only Transformer。
2. 子层输入侧的 Pre-Norm 与 RMSNorm。
3. 每层 attention 中使用 RoPE。
4. 前馈层采用 SwiGLU。

这些设计后来被大量开源模型吸收。

### 6.1 RoPE

RoPE 把位置信息编码到 Q/K 旋转中。它描述位置表示路径；长上下文外推仍取决于位置映射、训练长度与任务评测，详见第十八章。

### 6.2 RMSNorm

RMSNorm 用均方根缩放而不做均值中心化。它是归一化函数选择，单独使用并不能保证训练更稳定或整体模型更强。

### 6.3 SwiGLU

SwiGLU 是带门控的 FFN 变体；比较它与普通 FFN 时还需控制中间维度、参数预算和训练 recipe。

LLaMA 之后，很多模型可以被描述为：

```text
版本化的 LLaMA-like 基线：稠密 decoder + Pre-Norm/RMSNorm + RoPE + SwiGLU；Llama 2/3 加入 GQA，Llama 4 转向 MoE 与 early fusion
```

后续版本体现的是逐步调整，而不是一成不变的家族配方：Llama 2 将上下文从 $2\mathrm{k}$ 增至 $4\mathrm{k}$ 并在较大模型中采用 GQA；Llama 3.1 延续稠密主干并将官方上下文声明扩展到 $128\mathrm{k}$；Llama 4 则在模型卡中披露 MoE 与原生多模态 early fusion。[Llama 2 论文](https://arxiv.org/abs/2307.09288)、[Llama 3.1 发布说明](https://ai.meta.com/blog/meta-llama-3-1/)、[Llama 4 模型卡](https://github.com/meta-llama/llama-models/blob/main/models/llama4/MODEL_CARD.md)

## 7. 2023：Mistral 7B v0.1 的 GQA 与滑窗

2023 年的 Mistral 7B v0.1 论文组合 grouped-query attention（GQA）与 causal sliding-window attention（SWA）。论文配置列出 $4{,}096$ 的窗口和 $8{,}192$ 的 context_len；其理论跨层传播跨度不等于任务级有效上下文。论文报告的基准比较绑定其评估流程与对照模型。[Mistral 7B 论文](https://arxiv.org/abs/2310.06825)

配置字段详解见[第十七章](chapters/17-LLaMA-GPT-Mistral架构对比.md)，GQA/KV cache 与滑窗信息路径分别见[第四章](chapters/04-mha-mqa-gqa-mla的演进与trade-off.md)、[第十一章](chapters/11-kv-cache长上下文推理和显存增长问题.md)、[第十九章](chapters/19-Sliding-Window与稀疏注意力.md)；固定版本的综合案例见[第五十五章](chapters/55-Mistral-Mixtral高效与MoE.md)。

## 8. 2023–2024：Mixtral 8x7B 的稀疏 MoE

Mixtral 权重于 2023 年 12 月发布，论文于 2024 年 1 月发表。它保留 Mistral 主干，在每层 FFN 放入八个专家，并为每个 token 路由两个；论文给出的约 $47\mathrm{B}$ 总参数、每 token 约 $13\mathrm{B}$ 激活参数和 $32\mathrm{k}$ 训练上下文是不同口径。[官方发布说明](https://mistral.ai/news/mixtral-of-experts/)；[Mixtral 论文](https://arxiv.org/abs/2401.04088)

论文摘要概括 Mixtral 与 Llama 2 70B、GPT-3.5 在所测基准上的总体比较，逐项结果仍应按正文表格与对应协议读取。它是开放权重且采用 Apache 2.0 许可；MoE 路由与系统成本分别由[第二十一章](chapters/21-MoE路线Switch-GShard-Mixtral-DeepSeek.md)、[第二十二章](chapters/22-Dense与MoE训练服务trade-off.md)展开，固定版本案例见[第五十五章](chapters/55-Mistral-Mixtral高效与MoE.md)。

## 9. 2023–2024：Gemini、GPT-4V 与 Claude 3 的多模态和长上下文披露

Gemini 1.0 技术报告将模型描述为 decoder-only Transformer，说明图像、音频、视频与文本联合训练，并报告最高 32k 上下文与 multi-query attention。Gemini 1.5 报告披露稀疏 MoE 模型类型；Google 2024-02-15 发布页给出的 128k 标准窗口与 1M private preview 是产品开放状态，不能与研究报告中的更长上下文检索实验混为一谈。

GPT-4V system card 说明图像输入并描述视觉部署评估；GPT-4 报告明确没有公开精确架构和规模。Claude 3 的模型卡和发布说明确认图像输入、文本输出及发布时的 200k 窗口，同时将更长输入能力限定在选择性开放/当时生产范围之外。三者公开信息的层级不同，不能仅凭“多模态”标签推断相同内部路径，也不能把不同 NIAH 协议的召回率排成架构排名。详见[第五十六章](chapters/56-Gemini-Claude-GPT4V系统能力.md)及[证据记录](../research/gemini-gpt4v-claude3-disclosure-evidence-2026-11-24.md)。

## 10. 2024：Qwen2.5、Llama 3.1 与 Gemma 2 的训练工程披露

这三份报告公开的是不同训练选择，不能合并成同一 recipe 或跨论文性能排名。Qwen2.5 报告将预训练数据从 7T 扩到 18T，并说明数据 mixture、代码/数学数据与后训练阶段；开放权重稠密模型要和托管服务的 MoE 型号分开。Llama 3.1 报告披露 405B 模型使用 15.6T 文本 token、128K tokenizer，并描述数据清洗、配比、长上下文继续训练与训练系统可靠性；论文标题为 Llama 3，但其报告表明实验结果对应 Llama 3.1。Gemma 2 则披露 2B、9B、27B 分别训练 2T、8T、13T token，并对较小两个尺寸采用知识蒸馏。

这些案例说明训练工程不只是层数和注意力类型：数据、词表、阶段安排、集群可靠性与学生模型训练信号都会进入报告。但三家披露的数据、许可证和完整复现条件并不相同。权重可取得不能推出原始训练语料和全部过滤流程可复现；详见[第五十七章](chapters/57-Qwen-LLaMA3-Gemma训练成熟化.md)及[研究记录](../research/open-weight-training-engineering-qwen25-llama31-gemma2-2026-11-24.md)。

这一阶段说明：

```text
模型强不强，不只看 block 结构，还看 tokenizer、数据、训练 recipe、后训练和评估。
```

## 11. 2024：DeepSeek-V2 把 MLA 与 DeepSeekMoE 放进同一架构

[DeepSeek-V2 技术报告 v5](https://arxiv.org/html/2405.04434v5)公开了一个版本明确的架构组合：MLA 改变注意力层保存的历史表示，DeepSeekMoE 改变 FFN 中每个 token 经过的专家路径。报告将 V2 描述为 236B 总参数、每 token 激活 21B 参数、支持 128K 上下文的 MoE 模型；这些是该报告的模型字段和评估范围，不等于任意部署的权重、显存或延迟账本。

### 11.1 MLA：latent KV 与位置相关分支

V2 的 MLA 将 key/value 内容压入共享低秩 latent，并单独保留携带 RoPE 的位置相关 key。它改变缓存里每个历史 token 表示的形式，并没有移除历史状态或 attention 计算。MLA 的通用信息流与缓存口径见[第四章](chapters/04-mha-mqa-gqa-mla的演进与trade-off.md)和[第十一章](chapters/11-kv-cache长上下文推理和显存增长问题.md)；V2 报告中的对照数据绑定其模型、配置与评测。

### 11.2 DeepSeekMoE：共享专家和路由专家的版本配置

V2 报告列出每个 MoE 层 2 个共享专家和 160 个路由专家，每个 token 激活 6 个路由专家。共享路径与路由路径分别做什么、以及活跃参数为什么不能代表全部驻留权重或通信成本，见[第二十一章](chapters/21-MoE路线Switch-GShard-Mixtral-DeepSeek.md)和[第二十二章](chapters/22-Dense与MoE训练服务trade-off.md)。这里的专家数量和路由数只绑定 V2 报告配置。

## 12. 2024–2025：DeepSeek-V3 延续架构，R1 改变后训练

V3 与 R1 不能合并成一个模型版本。V3 报告延续 V2 的 MLA/DeepSeekMoE，并加入新的负载均衡策略与 MTP 训练目标；R1/R1-Zero 则以 V3-Base 为架构基座，训练差异主要在后训练路线。V3 的参数数字、R1 的奖励与评测结论均须绑定各自报告。

### 12.1 V3 的 MTP：顺序预测目标与可选推理复用

[DeepSeek-V3 技术报告 v2](https://arxiv.org/html/2412.19437v2)描述的 MTP 模块按预测深度顺序工作，并保留预测未来 token 所需的因果链。其训练目标不是让若干独立 head 无条件输出多个答案；报告将它作为增加未来 token 监督的目标，并在报告配置中做消融。

推理时，主模型可以丢弃 MTP 模块；报告也提出将这些模块复用于 speculative decoding。前者是训练辅助目标的正常部署路径，后者是可选推理方案，仍需要 draft/target 验证协议，不能把 MTP 与 speculative decoding 视为同义词。相关机制见[第二十一册第五十八章](chapters/58-DeepSeek-V2-V3-R1架构训练.md)。

### 12.2 R1：V3-Base 上的 RL 与多阶段后训练

R1-Zero 从 V3-Base 开始，不经预先 SFT，使用规则型正确性与格式奖励训练推理任务；完整 R1 加入冷启动示范、第一轮 RL、拒绝采样与混合推理/非推理 SFT，再进行第二轮 RL。两种路线共享公开的 V3-Base 架构起点，区别在训练阶段与奖励信号，不是新一代 backbone。[DeepSeek-R1 论文 v2](https://arxiv.org/html/2501.12948v2)

GRPO/RLVR 的机制由[第五册第十六章](../book-05-llm-training/chapters/16-rlvr与可验证奖励.md)主讲，R1 路线与蒸馏见[第十六册第十七章](../book-16-reasoning-models/chapters/17-deepseek-r1的rlvr与蒸馏路线.md)。论文报告和排行榜结果分别绑定作者任务、提示、基线及评测条件，不据此推断所有开放任务都会受益。

### 12.3 DeepSeek V4 与 tid2eid：从专家路由到工程索引

据苏剑林博客《DeepSeek V4的tid2eid是怎么来的？》介绍，`tid2eid` 可以作为理解 DeepSeek V4 一类 MoE 工程改造的一个切入点。

从命名上看：

```text
tid2eid = token id to expert id
```

它关注的是 MoE 中 token 和 expert 之间的映射关系。

普通 MoE 的路由过程可以简单理解为：

```text
每个 token -> router 打分 -> 选择 top-k expert -> 送入对应 expert 计算
```

这个过程在概念上很清楚，但在大规模训练和推理中会带来工程问题：

1. 每个 token 选择的 expert 不同，导致数据需要重排。
2. 不同 expert 负载可能不均衡。
3. 跨卡 dispatch 和 combine 会带来通信成本。
4. serving 时需要快速知道 token 应该发给哪个 expert。
5. 专家并行、token 排序、bucket、all-to-all 通信都会影响吞吐。

`tid2eid` 这类映射的意义在于把“路由结果”变成一个更明确的工程索引：

```text
token index -> expert index
```

有了这个映射，就可以围绕它做 token 重排、专家分组、dispatch、combine 和通信优化。

可以用一个简化例子理解：

```text
token 0 -> expert 3
token 1 -> expert 7
token 2 -> expert 3
token 3 -> expert 1
```

那么 `tid2eid` 可以帮助系统快速构造：

```text
expert 1 receives: token 3
expert 3 receives: token 0, token 2
expert 7 receives: token 1
```

这背后反映的是 MoE 从“算法结构”走向“系统实现”的关键问题。

对于 MoE 模型，架构论文里常说的是：

```text
top-k routing
load balancing
shared expert
fine-grained expert
```

但真正训练和部署时，还必须关心：

```text
token 如何分发到 expert
expert 输出如何还原到原 token 顺序
跨 GPU 通信如何组织
路由索引如何压缩和复用
负载不均衡如何缓解
```

所以 `tid2eid` 的价值不只是一个变量名，而是提醒读者：现代 MoE 创新不只发生在 loss 或 routing 公式里，也发生在 token-expert 映射、通信调度和推理引擎实现里。

写进本书时需要注意边界：这里根据苏剑林博客进行概念性解释，具体到 DeepSeek V4 的完整实现仍应以官方技术报告、源码或可复现实验为准。

## 14. 从时间线看互相借鉴

可以把主流大模型的互相借鉴关系理解为几条线。

### 14.1 Decoder-only 主线

```text
GPT -> GPT-2 -> GPT-3 -> LLaMA -> Mistral/Qwen/DeepSeek 等
```

这条线说明 decoder-only + next-token prediction 是最强主干。

### 14.2 归一化和 FFN 改造线

```text
LayerNorm -> RMSNorm
GELU FFN -> SwiGLU / Gated MLP
Dense FFN -> MoE FFN
```

这条线说明模型内部模块不断朝训练稳定、表达更强、计算更高效演进。

### 14.3 Attention 推理效率线

```text
MHA -> MQA -> GQA -> MLA
```

这条线的核心是 KV cache。

上下文越长，KV cache 越成为瓶颈，所以注意力结构不断向更低缓存成本演进。

### 14.4 长上下文线

```text
RoPE -> NTK scaling / YaRN -> sliding window / sparse attention -> long-context training -> retrieval/memory
```

这条线说明长上下文不是只改位置编码，还涉及训练数据、attention pattern、推理系统和评估。

### 14.5 MoE 线

```text
Switch/GShard -> GLaM -> Mixtral -> DeepSeekMoE -> Qwen-MoE 等
```

MoE 的核心是容量与计算解耦。

但是 MoE 的难点也很明确：routing、负载均衡、通信、serving 和稳定训练。

从工程实现看，还可以继续细分为：

```text
token -> expert routing
tid2eid 映射
expert bucket 构造
all-to-all dispatch
expert compute
combine 回原 token 顺序
```

这说明 MoE 架构演进和 AI Infra、推理框架高度耦合。

### 14.6 后训练与 reasoning RL 线

```text
SFT -> PPO-RLHF -> DPO/IPO/KTO/ORPO -> GRPO/DAPO/GSPO -> verifiable reward RL
```

这条线说明模型能力不只来自预训练架构，也来自后训练目标。

特别是 reasoning model，往往需要在线采样、可验证 reward 和多轮 RL。

## 15. 面试中怎么讲这条时间线

如果面试官问：

```text
你怎么看近几年主流大模型架构的演进？
```

可以这样回答：

```text
我会把演进分成几条主线。第一条是生成式预训练和任务迁移：GPT（后称 GPT-1）结合预训练与任务微调，GPT-2 评估零样本迁移，GPT-3 比较上下文示例条件；Scaling 研究测量的损失趋势与下游能力需要分开描述。第二条是现代 Transformer block 改造，比如 RoPE、RMSNorm、SwiGLU、GQA，这些组件在不同模型中有不同用途和成本。第三条是长上下文和 KV cache 优化，从 GQA/MQA 到 DeepSeek 的 MLA，具体收益要绑定模型和实现。第四条是 MoE，从 Switch/GShard 到 Mixtral、DeepSeekMoE，通过稀疏激活扩大总容量。第五条是后训练和 reasoning RL，从 RLHF/DPO 走向 GRPO、verifiable reward；能力结论需要对应到具体训练与评测任务。
```

如果继续追问 DeepSeek，可以这样答：

```text
DeepSeek 这条路线要按版本讲。V2 的报告给出 MLA 与 DeepSeekMoE 的架构组合；V3 延续二者，同时报告新的 routing-bias 负载均衡策略和 MTP 训练目标。R1 与 R1-Zero 则以 V3-Base 为基座，差异主要在冷启动、RL、拒绝采样、SFT 和后续 RL；R1-Distill 使用 Qwen/Llama 稠密基座。参数、缓存、训练成本和 benchmark 都应绑定对应报告和条件，不能把它们合成一个“高效架构”的因果结论。
```

如果被问到 `tid2eid`，可以这样答：

```text
tid2eid 可以理解成 token id 到 expert id 的映射，是 MoE 路由结果的一种工程索引表达。MoE 不只是让 router 选 top-k expert，还要把大量 token 高效 dispatch 到对应 expert，再把输出 combine 回原顺序。tid2eid 这类设计体现了 MoE 从算法结构走向工程实现的关键问题：token 重排、专家分组、all-to-all 通信、负载均衡和 serving 吞吐。具体实现细节需要结合官方报告或源码核验。
```

## 16. 本章小结

本章按时间线梳理了主流大模型架构创新。

核心结论如下：

1. Transformer 奠定了 attention + 并行训练的基础。
2. GPT 早期谱系展示了生成式预训练、任务微调、零样本迁移和 ICL 评测的变化；scaling 证据须注明所测指标和条件。
3. Chinchilla 改变了大家对参数和训练 token 配比的理解。
4. InstructGPT/ChatGPT 让 SFT + RLHF 成为 assistant model 的关键流程。
5. 原始 LLaMA 将既有的 RoPE、RMSNorm、SwiGLU 等设计组合成可复用基线；后续版本逐步调整，Llama 4 已超出经典稠密配方。
6. Mistral 7B v0.1 提供 GQA 与滑窗注意力组合的论文案例，收益按基准和版本限定。
7. Mixtral 8x7B 把稀疏专家放入 Mistral 主干的 FFN 层；路由、权重和通信仍是模型成本的一部分。
8. Gemini、GPT-4V、Claude 等模型推动多模态、长上下文和系统能力。
9. Qwen2.5、Llama 3.1、Gemma 2 展示了数据规模、tokenizer、训练阶段和蒸馏等不同工程选择；权重开放不代表完整训练资料可复现。
10. DeepSeek-V2/V3 报告可用于对照 MLA、DeepSeekMoE、V3 routing bias 与 MTP；R1 是 V3-Base 上的后训练路线，不能当作新 backbone。各报告的规模、结果和效率结论须按版本、训练与评测条件解读。
11. DeepSeek V4 相关 `tid2eid` 讨论说明 MoE 创新不只在 routing 公式，也在 token-expert 映射、dispatch 和通信优化。
12. 面试中最好按时间线和技术主线讲演进，而不是孤立背模型名。

13. 2025-2026 的排行榜模型显示，闭源模型的主要公开增量往往在 reasoning、工具、状态管理和安全运行时；不能因为缺少参数或 attention 披露就臆测架构。
14. Qwen、Kimi、GLM、DeepSeek 等开放或半开放路线则进一步公开了 GQA/MLA、MoE、混合注意力、多模态编码和 serving 实现，适合做结构级面试分析。
15. 未来新增模型应先登记排行榜 canonical 条目，再补权威资料和专题，避免总览、时间线和专题章节出现不同步。

## 17. 2025-2026：排行榜新模型的架构与系统补充

本节把总登记表中的新模型落到技术主线。对于闭源模型，只记录公开的 API、模型卡、System Card、官方博客和排行榜事实；对于开放模型，才记录配置、层数、专家和注意力等架构字段。

### 17.1 GPT-6、Claude 5.x 与 Gemini 3/4：运行时成为公开创新面

GPT-6/GPT-6.1 的公开资料集中在 reasoning effort、长上下文、Responses tools、异步状态和 compaction；Claude Sonnet 5/5.5、Opus 5、Fable 5 则公开了 thinking block、签名/前缀绑定、tool/computer-use、cache 和动态工作流；Gemini 3.x/4 Argon 的资料集中在多模态、Interactions/tool schema、coding/enterprise/cyber 能力。

这些信号可以用于面试中的系统设计分析，但不能推出 Dense/MoE、层数、MLA 或训练 recipe。正确结论是：闭源模型的公开创新面从 Transformer block 扩展到了状态机、工具协议、评测 harness 和安全门禁。

### 17.2 Qwen3.5-Qwen3.8：从通用 MoE 到多分支与环境扩展

Qwen3.5、Qwen3.6、Qwen3.7 和 Qwen3.8 覆盖开放模型与 hosted revision。项目资料涉及 Qwen3.5-397B-A17B、Qwen3.6-27B/35B-A3B、Qwen3.7 Max，以及 Qwen3.8-27B、2.4T-A95B、Flash-Next 和 Max。

公开技术信号包括 GDN/Gated Attention、QSA、N-gram 分支、A95B 稀疏专家、thinking 开关、原生视觉和 environment scaling。比较这些模型时必须固定 checkpoint 或 hosted revision，不能把开放权重的参数字段与托管服务的工具、价格或榜单成绩拼成一条架构结论。

### 17.3 GLM-5、GLM-5.3-Flash：稀疏注意力与工程闭环

GLM-5 的 DSA/indexer、256 routed experts/top-8/1 shared、MLA 低秩字段和 `slime` 异步 RL，把长上下文候选召回、MoE 容量和 rollout-trainer 解耦放在一起。GLM-5.3-Flash 进一步公开 linear+sparse hybrid attention、IndexPool、mHC、原生视觉 coding 和 EPD serving。

这条路线的面试重点不是背参数，而是解释：历史 token 如何被索引，稀疏层如何选择计算路径，残差稳定性如何保障，以及 prefill/decode/主机调度如何协同。发布方 speedup 仍须绑定硬件、量化、batch 和 provider 配置。

### 17.4 Kimi K3 与 DeepSeek V4：新一代 MoE 的路由和 serving

Kimi K3 公开资料涉及 KDA、Stable LatentMoE、AttnRes、93 层、896 experts 和 MLA/KV 压缩；DFlash、DSpark、FlashKDA 是围绕 K3 的 speculative decoding、kernel 和 serving 资料，不应另列为排行榜模型。DeepSeek V4/V4.1 的项目资料则补充 Vision API、MegaMoE shared-expert fusion、FP4/FP8 路径和 stream-overlap serving。

共同的演进方向是：MoE 不再只讨论 router loss 和 top-k，还要记录 token-expert 映射、shared expert、KV 状态、通信、量化和 graph capture。性能数字必须绑定具体 revision、硬件和负载。

### 17.5 Grok 4.x：多代理产品合同

Grok 4.3-4.7 和 4.20 variants 的公开项目资料主要是长上下文、工具、多代理 harness 和 API/runtime 合同。它们补充了“模型如何被编排成 agent”的时间线，但 xAI 未公开的参数规模、attention、MoE 和训练 recipe 仍保持未公开状态。

## 18. 2026：Qwen3-Omni 把多模态理解和流式语音生成拆成 Thinker-Talker

Qwen3-Omni 展示了另一条多模态演进路线：模型不把音频理解、视觉理解、文本推理和语音输出都压在同一个顺序文本链路里，而是将 Thinker 与 Talker 分工，并通过多模态特征和时间坐标连接起来。

核心技术链可以概括为：

```text
AuT audio encoder + Qwen3-VL vision encoder
  -> TM-RoPE temporal/height/width alignment
  -> Thinker: multimodal understanding and tool/policy interface
  -> Talker: first-codebook AR + residual-codebook MTP
  -> Code2Wav causal vocoder
  -> streaming audio packets
```

其中 AuT 以约 12.5 Hz 的音频 token rate 工作，TM-RoPE 把音频和视频按约 80 ms 的时间粒度对齐；Talker 使用首码本自回归、MTP 预测剩余 residual codebooks，Code2Wav 使用轻量 causal ConvNet。它们分别对应编码长度、跨媒体位置、码本并行度和 waveform 实时性的不同瓶颈，不能合并成一个“语音模块优化”。

Qwen3-Omni 还把模型架构和宿主系统边界暴露得更清楚：Thinker 的输出可以经过 RAG、function calling、安全策略和 verifier，再交给 Talker；异步 chunked prefill 需要同时维护媒体 timestamp、Thinker chunk、Talker 多码本状态和音频 packet。报告的 `234 ms` audio first packet 与 `547 ms` video first packet 是报告口径，不是通用服务 SLO。

因此，2026 年的多模态架构主线不只是“给 Transformer 加视觉/音频 encoder”，还包括：

1. 跨媒体时间坐标如何对齐。
2. 理解和生成是否需要不同的计算节奏。
3. 多码本语音 token 如何降低串行深度。
4. 工具、策略、取消、恢复和 verifier 如何插入模型流水线。
5. 开源仓库、Thinker serving、完整音频输出和目标硬件 acceptance 如何分层验收。

专题正文见 [`第 91 章`](chapters/91-qwen3-omni-thinker-talker-aut与流式多模态.md)，证据底稿见 [`qwen3-omni-source-notes.md`](../research/model-update-2026-09/qwen3-omni-source-notes.md)。

## 19. 2026：Qwen3-VL 把视觉层级、三轴位置和显式视频时间结合起来

Qwen3-VL 代表了视觉语言模型的一条完整化路线：它不是只在文本 decoder 前拼接一段图像 embedding，而是由 SigLIP2 vision encoder、两层 MLP vision-language merger 和 Qwen3 MoE decoder 组成三模块结构，并用 DeepStack 把视觉中间层残差送入语言模型早期层。

它的核心架构线可以概括为：

```text
SigLIP2 vision encoder
  -> MLP merger
  -> visual tokens + DeepStack residuals
  -> Qwen3 MoE decoder
```

位置表示上，Interleaved-MRoPE 仍保留 temporal/height/width 三轴，但把轴对应的 rotary frequency 在低频和高频中交错分配，缓解长视频中的频谱偏置。Video Timestamp 则在视频时间 patch 前加入 `<3.0 seconds>` 等可读时间锚点，训练中同时使用 seconds 和 HMS 格式。前者是模型内部的频率分配，后者是显式输入证据，二者都不能代替宿主的采样、丢帧和时间轴回放审计。

训练路线也从“把最大位置改大”变成 curriculum：S0 约 67B/8K 先对齐 merger，S1 约 1T/8K 做全参数多模态预训练，S2 约 1T/32K 做长上下文预训练，S3 约 100B/262K 做 ultra-long adaptation；square-root normalized per-token loss 用来平衡 text-only 与 multimodal 数据贡献。后训练进一步使用 SAPO、General RL 和 Thinking with Images 的 answer accuracy、multi-turn reasoning、tool-calling reward。最后一种 reward 用于避免模型固定只调用一次工具的 shortcut。

因此，视觉语言模型的演进不只是增加一个视觉 encoder，还包括：

1. 不同视觉抽象层级如何进入语言 decoder。
2. 时间、高度和宽度如何共享频率而不互相掩盖。
3. 真实视频 timestamp 如何成为可引用证据。
4. 长上下文和多模态数据如何通过阶段 curriculum 训练。
5. GUI/tool Agent 如何把模型 proposal、宿主执行和 verifier 分开。

专题正文见 [`第 92 章`](chapters/92-qwen3-vl-interleaved-mrope-deepstack与视频时间戳.md)，证据底稿见 [`qwen3-vl-source-notes.md`](../research/model-update-2026-09/qwen3-vl-source-notes.md)。

## 20. 2026：K2 Horizon 用 dense checkpoint 对照稀疏 value routing

K2 Horizon 家族把同一长上下文方向拆成两种可比较路径：3.7B 当前 revision 是 36 层 dense `K2HorizonForCausalLM`，使用 32Q/8KV GQA、524K position、BF16，MoE/MoVA expert 数为零；36B/A4B 在 48 层中后 45 层加入 MoVA value top-4、FFN top-8 和 shared expert。两者共享 GQA/512K 并不意味着 serving 复杂度相同，比较时要分别测 GEMM、KV、router metadata、dispatch、通信和 workspace。

3.7B 的 22.9T pretraining、分阶段长上下文 midtraining、512K SFT、RL specialist merge 和公开中间 checkpoint 还说明：长上下文能力是 checkpoint curriculum，而不是单独修改 `max_position_embeddings`。当前 artifact migration、vLLM/SGLang recipe 和旧 APPENDIX 字段冲突则提醒读者，模型类、dtype、参数 core/embedding 口径和部署 revision 必须一起固定。完整证据见 [`k2-horizon-3.7b-source-notes.md`](../research/model-update-2026-09/k2-horizon-3.7b-source-notes.md) 与第二十一册第 82 章。
