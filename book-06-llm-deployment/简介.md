# 第六册简介：大模型部署与推理工程

## 本书解决什么问题

模型生成了 checkpoint，并不代表它已经成为可交付的服务。线上系统还要处理真实请求分布、首 token 与后续 token 延迟、并发和队列、KV 状态、硬件容量、模型质量、安全、故障恢复及成本。本册沿着“定义 workload → 估算与测量 → 选择 runtime 和调度策略 → 集成应用请求 → 运营与优化 → 设计和复盘生产系统”讲清这条工程链。

## 读者与能力目标

本册适合准备 LLM serving、推理优化、部署/后端工程及相关系统设计岗位的读者。了解 Transformer 自回归生成、Python 和基本服务概念会有帮助；推理阶段、性能指标和 cache 账本由前几章逐步补齐，不要求读者已有某个推理引擎的源码经验。

读完核心路径后，读者应能：

1. 从到达率、输入/输出长度、并发和 SLO 描述 workload，区分 QPS、tokens/s、TTFT、TPOT、ITL、goodput 等指标的测量口径。
2. 推导 KV Cache、权重、激活和运行时开销的显存账本，并据此估算并发、容量和扩缩容边界。
3. 按模型协议、请求形态、质量门槛、硬件和维护条件选择推理引擎、调度方式、量化 artifact 与并行拓扑。
4. 将 RAG、Agent、多模态请求接入服务链路，处理状态、工具权限、数据边界和可观测性。
5. 用服务指标与目标任务评估质量、可靠性、安全和单位成功成本，形成灰度、回滚和故障处理方案。

## 本册范围与相邻书册

本册主讲服务运行时和面向应用的部署工程：怎样测量、估算、选择、集成、运营和优化。第五册讲训练与后训练如何产出模型及 artifact；第七册讲评估方法与证据；第十五册讲多模态模型机制；第十七、二十、二十二册承担 Agent 的方法、构建和安全专题；第二十三册讲 AI Infra 平台、集群资源、网络、存储和平台治理；第二十四册沿推理框架源码与运行机制深入。本册在需要的位置使用这些知识，但不重讲相邻册的完整主线。

## 阅读路径

第 1—14 章构成核心路径：第 1 章定义部署问题，第 2—4 章建立推理、状态和生成控制基础，第 5—8 章处理 runtime、调度、压缩与多 GPU，第 9—10 章应用到 RAG/Agent 和多模态，第 11—12 章建立运营与成本闭环，第 13—14 章完成生产系统综合与案例复盘。

第 15—17 章是低精度部署专题分支，分别深入 FP4 家族、FP8 KV Cache 和 Native INT4 artifact；建议先掌握第 3、5、7 章中与各专题相关的状态、runtime 和量化基础。第 18 章是托管 API 的长上下文、推理档位、工具状态与费用预算案例，建议先读第 2、4、9、11、12 章。模型、接口、版本与价格会变化，正文结论只按注明日期的公开合同理解。

## 各章在主线中的作用

1. **部署总览**：从 workload 和 SLO 出发建立全书地图，说明 checkpoint 到服务之间要作出的关键决定，并把细节引向后续章节。
2. **推理基础**：澄清首 token 与 prefill/decode 的阶段关系，统一 TTFT、TPOT/ITL 和分位数口径，再以 roofline、trace 与压测把性能诊断推进到容量决策。
3. **KV Cache 与内存管理**：计算每 token 状态和活跃并发显存，区分可复用前缀工作集容量，解释分页、量化、淘汰与长上下文并发问题，支撑调度和容量设计。
4. **解码策略与生成控制**：从 logits 到输出梳理采样、停止、结构化生成和推测解码，讨论质量、延迟与 token 预算的关系。
5. **推理引擎**：建立按 workload 和公开兼容性选型的流程；源码内部实现留给第二十四册。
6. **批处理与调度**：分析请求队列、continuous batching、长短请求争用、token/KV budget、公平性、抢占和 prefill/decode 分离如何影响服务。
7. **量化与模型压缩**：提供选择权重或状态压缩方案时共用的精度、校准、质量和性能框架，并为第 15—17 章铺垫。
8. **并行推理与多 GPU 服务**：比较并行拓扑、P/D 资源解耦、副本、负载均衡、通信与 KV 所有权，连接单机优化和多卡系统。
9. **RAG 与 Agent 部署**：把文档与索引版本、检索服务容量、请求状态、权限和工具调用接入可观测的生产链路，并设计灰度与回滚；RAG/Agent 方法本身由相关专题册主讲。
10. **多模态部署**：沿 OCR 证据、ASR/TTS 流、视频采样与剪枝，规划多阶段容量、评估和发布。
11. **监控、评估与安全**：从请求 trace 推算 SLO 与单位成功成本，再把质量/安全门禁、隐私最小化、灰度回滚和事故回流连成闭环。
12. **成本优化**：拆开 GPU/运行资源与供应商账单，按单位成功任务成本比较路由、缓存、压缩、批处理和优化实验，并用质量、尾延迟与安全门槛约束降本。
13. **生产系统设计**：从 workload 与异质服务目标出发，综合容量、请求链路、可靠性、观测、多租户和成本形成系统方案。
14. **部署方案推导与故障复盘**：通过资源账本、延迟、调度、cache、量化和生产故障案例练习方案推导与定位，收束核心路径。
15. **FP4、MXFP4 与 NVFP4**：比较低位浮点数据格式、scale、artifact 和执行 kernel 的部署差异。
16. **FP8 KV Cache**：深入低精度 KV 状态、分页分配、容量收益、质量评估和回滚。
17. **Native INT4**：检查原生量化权重与 runtime、kernel、硬件和质量门禁组成的联合部署契约。
18. **GPT-6 Astra 长上下文与工具预算**：以 2026-11-02 核对的官方 API 合同为案例，推演上下文、reasoning effort、缓存费率与整项工具 job 预算，并区分 replay、异步工具、steering、后台响应、compaction 和安全监控的状态边界；不据此推断本地 runtime 或未公开的模型内部实现。

## 学习建议

初次学习按 1—14 顺序阅读；做引擎/推理工程岗位准备时，可在核心路径中重点复习第 2、3、5、6、7、8、11、12、13、14 章。处理特定精度格式或受管 API 账单时，再进入相应专题。示例、性能数字和接口行为均应结合正文注明的来源、测量条件和版本边界理解。
