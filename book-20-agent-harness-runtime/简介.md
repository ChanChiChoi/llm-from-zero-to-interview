# 第二十册简介：Agent Harness 与 Coding Agent Runtime

## 本书定位

本书讲 Coding Agent 如何成为一个可运行、可控、可观察、可恢复的软件系统。Harness 和 Runtime 把模型调用、上下文、工具、文件编辑、终端、权限、执行环境、持久状态、trace、回放和任务验收连成一条运行链。我们从一项代码任务出发，追踪每一步是谁提出、谁批准、谁执行、什么状态被改变，以及哪些证据能说明任务完成。

本书包含三类内容：通用运行时机制、公开 Coding Agent 产品案例，以及带版本边界的 Provider/API 合同。后两类用来练习应用通用分析框架，不代表各家闭源系统内部结构相同，也不把某一版 API 的行为推广为通用规则。

## 读者起点

开始阅读前，读者应理解大模型如何接收 prompt 并生成输出，知道工具调用会把模型请求交给宿主执行。能读懂基础 Python、JSON、Git diff 和常见命令行操作会更容易完成算例；生产 Agent 经验不是前置条件。若不熟悉 Agent 的状态、工具、记忆和规划，可先读[第十七册：Agent 与工具调用](../book-17-agent-tool-use/目录.md)。

本书涉及真实文件、命令、外部工具和 API；书中的示例会使用合成任务与明确标出的版本，不要求读者在生产系统运行示例。

## 学完后应具备的能力

- 沿一次任务追踪用户目标、上下文、模型提议、权限决定、工具副作用、观察结果、持久状态和最终 artifact。
- 为工具 schema、文件编辑、终端执行、权限确认和执行隔离设计互相一致的边界，并指出各机制无法保证什么。
- 区分对话历史、模型内部或 provider 状态、workspace 文件、任务 checkpoint、执行回执和业务验收结果。
- 为长任务设计可恢复记录，为失败重放设置版本、幂等和人工确认条件。
- 构造 agent evaluation：固定模型/harness/environment/task 条件，用任务特定 verifier 检查 artifact，并把质量、安全、成本和延迟分别报告。
- 根据公开资料比较产品与 API，说明版本、来源和未知项，不把闭源内部推断当作事实。

## 阅读路径

- **系统学习：** 第 1—10 章从运行时概念走到工具、状态、权限、trace 和评估；第 15—16 章综合为系统设计和故障排查。第 11—14 章是公开产品/协议案例，可按兴趣穿插阅读。
- **搭建 Coding Agent：** 第 1—8 章厘清动作和安全边界 → 第 9—10 章增加可观测与验收 → 第 15 章做系统设计 → 第 16 章按失败场景检查。
- **长任务与状态恢复：** 第 7、9 章建立上下文和 trace 基础 → 第 17 章设计 checkpoint → 第 18 章处理 Context Folding → 第 20—21、23—24 章对照 Provider 状态合同。
- **评估或排错：** 第 9—10 章学习 trace 与 evaluation harness → 第 16 章定位常见工程失败 → 第 19 章比较模型、harness、环境与 verifier 的共同影响。评估统计方法见[第七册](../book-07-evaluation-experiments/目录.md)。
- **查某个产品/API：** 第 11—13 章比较公开 Coding Agent；第 20—24 章查 Responses、workspace、兼容接口、Gemini Interactions 和 Claude thinking state。进入这些专题时，以章内标明的官方资料日期和版本为准。
