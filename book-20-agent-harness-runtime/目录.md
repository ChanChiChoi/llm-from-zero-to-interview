# 第二十册：Agent Harness 与 Coding Agent Runtime

本书的核心路线是第 1—10 章的运行闭环，再用第 15—16 章综合设计与排障。第 11—14 章用公开产品和协议案例应用前面的框架；第 17—19 章深入长任务恢复、上下文折叠和归因评估；第 20—24 章是按需查阅的 Provider/API 合同，不应把某一版接口当作通用 Runtime 规则。

## 阅读入口

- **设计一个 Coding Agent：** 1 → 2 → 3 → 4—8 → 9—10 → 15 → 16。
- **研究长任务状态：** 7、9 → 17 → 18 → 20—21、23；如需评估，接第 19 章。
- **比较公开产品：** 1—2 → 11—13；安全案例接第 8 章和第 16 章。
- **接入协议与外部 Agent：** 4、8—10 → 14；协议本身见[第二十二册](../book-22-tool-protocol-ecosystem/目录.md)。
- **核验供应商 API：** 20—24 按所用 API 和日期查阅；先读 7、9、17、21 章理解历史记录、任务状态、workspace 与执行事实的区别。

## 一、Runtime 基础与动作执行

1. [Harness 总览](chapters/01-harness总览.md)：沿一条修复任务轨迹区分模型提议、策略决定、真实副作用、任务状态、trace 和验收证据。
2. [Agent Runtime 架构](chapters/02-agent-runtime架构.md)：沿一个 step 检查上下文、模型适配、动作解析、执行、状态和 trace。
3. [Coding Agent 工作流](chapters/03-coding-agent工作流.md)：从任务澄清和仓库探索走到小步修改、验证、恢复和交接。
4. [工具系统与 Tool Registry](chapters/04-工具系统与tool-registry.md)：定义可发现工具、参数、权限、副作用、错误和版本。
5. [文件系统与代码编辑](chapters/05-文件系统与代码编辑.md)：限制 workspace 读写并保护 patch、diff、并发修改和回滚。
6. [终端执行与命令安全](chapters/06-终端执行与命令安全.md)：沿命令提议、策略、OS 隔离、资源与取消、输出回执走到任务验收。
7. [上下文管理与记忆压缩](chapters/07-上下文管理与记忆压缩.md)：选择每轮模型所需信息，在预算内控制丢失、过期和注入风险。
8. [权限模型与安全沙箱](chapters/08-权限模型与安全沙箱.md)：区分工具可见性、权限决定、用户确认、业务授权和环境隔离。

## 二、运行证据、评估与案例

9. [Trace、日志、回放与可观测性](chapters/09-trace日志回放与可观测性.md)：保存足以解释一次运行的事件、状态、artifact 和隐私边界。
10. [Evaluation Harness](chapters/10-evaluation-harness.md)：固定任务和环境，用 verifier 判断结果并记录可比条件。
11. [Claude Code 架构分析](chapters/11-claude-code架构分析.md)：从公开资料和可观察证据分析产品工作循环、执行边界及内部实现未知项。
12. [OpenCode 架构分析](chapters/12-opencode架构分析.md)：检查开源 Runtime 的配置、工具、扩展、权限和服务接口。
13. [Codex 与主流 Coding Agent 对比](chapters/13-codex与主流coding-agent对比.md)：用相同维度比较公开产品形态，不推断未披露的内部实现。
14. [MCP、A2A 与 Harness 集成](chapters/14-mcp-a2a与harness集成.md)：说明外部工具/Agent 如何进入注册、授权、执行、trace 和验收链。

## 三、系统综合、故障与长任务可靠性

15. [Agent Harness 系统设计](chapters/15-agent-harness系统设计.md)：把需求、数据模型、Context Builder、执行、安全和评估组织成完整架构。
16. [Harness 实战坑与面试题](chapters/16-harness实战坑与面试题.md)：按现象和证据定位工具、上下文、权限、命令、trace 与评估故障。
17. [Long-Running Agent 与 Checkpoint](chapters/17-long-running-agent与checkpoint.md)：把对话历史和任务状态分开，为中断、恢复和幂等执行设计 checkpoint。
18. [Context Folding 上下文折叠](chapters/18-context-folding上下文折叠.md)：压缩上下文时保留任务所需事实、来源、约束和恢复依据。
19. [Harness-Aware Evaluation](chapters/19-harness-aware-evaluation.md)：区分模型、harness、环境和任务交互的影响，避免把组合结果归因给单一组件。

## 四、Provider/API 状态合同

20. [Responses API](chapters/20-responses-api.md)：检查 response/item、工具事件、流式恢复、会话状态、用量和成本的公开合同。
21. [Persistent Workspace 与状态边界](chapters/21-persistent-workspace与状态边界.md)：区分模型记忆、文件 workspace、数据库、checkpoint 和外部系统真相。
22. [OpenAI-Compatible API 边界](chapters/22-openai-compatible-api边界.md)：比较字段、模板、工具、reasoning、计费和错误语义，而不把兼容误当等价。
23. [Gemini Interactions 与 thought-state 回放](chapters/23-gemini-interactions与thought-state回放.md)：核对 Interaction ID、thought signature、工具副作用、保留期和无状态续传。
24. [Claude Sonnet 5.5 thinking state 与安全路由](chapters/24-claude-sonnet-5.5-thinking-state与安全路由.md)：按官方版本资料区分 thinking block、工具迁移、安全防护和评测证据。
