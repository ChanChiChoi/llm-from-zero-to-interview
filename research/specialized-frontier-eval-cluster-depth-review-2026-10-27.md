# Specialized Frontier Eval Cluster：来源与证据笔记

资料核验日期：2026-11-03  
证据状态：论文和官方页面支持各自公开的任务合同、环境、评分方式及作者报告的实验；以下基准数字都绑定到所列版本，不代表任意模型或生产工作流的普遍能力。

## 软件工程与终端

- [SWE-bench，arXiv v3](https://arxiv.org/abs/2310.06770)，2024-11-11 修订。阅读摘要及版本记录。论文说明其原始集合由 12 个 Python 仓库的 2,294 个 GitHub issue/PR 任务组成，要求模型根据 issue 修改代码库。支持“仓库修复比自包含函数生成包含更多定位和跨文件工作的任务定义”；其论文分数仍受任务版本、测试、模型与 agent scaffold 限制。
- [SWE-Gym，arXiv v2](https://arxiv.org/abs/2412.21139)，2025-06-06 修订。阅读摘要、HTML §§3.1、3.3、4.2、5.1 和结论/限制。论文报告 2,438 个 Python issue 任务，来自 11 个仓库；每题含代码库、可执行环境、单元测试和自然语言任务，并发布 Agent 轨迹。作者称这 11 个仓库与 SWE-Bench 使用的仓库分离以降低直接污染风险；论文训练和 SWE-bench 结果仍绑定其模型、训练轨迹、verifier、scaffold 和采样预算，不能据此替代其他任务集或新时间切分上的泛化评估。
- [Terminal-Bench 2.0，arXiv v1](https://arxiv.org/abs/2601.11868)，2026-01-17 提交。阅读 HTML 论文的任务定义、数据构造、验证、harness 和局限（§§2.1–2.3、§3.4、§5）。89 个任务分别以容器环境、指令、测试、人工参考解和时间限制描述；测试检查最终容器状态，不按 Agent 执行了哪些命令评分。论文也说明其实验使用 Harbor harness，Agent 与模型难以完全拆开，环境允许联网安装依赖，因此公开解法污染仍是使用者要监控的边界。摘要中的“89 个”及 `<65%` 结果属于该版本任务和所测模型/Agent 配置。

## 浏览器与桌面操作

- [WebArena，arXiv v4](https://arxiv.org/abs/2307.13854)，2024-04-16 修订。阅读摘要和版本记录。论文提供四类网站环境，并按任务完成后的功能正确性评估；它支持网页状态任务这一设计例，不直接代表企业生产网页或权限安全。
- [OSWorld，arXiv v2](https://arxiv.org/abs/2404.07972)，2024-05-30 修订。阅读摘要。论文报告 369 个电脑任务，提供初始状态设置与执行式评估脚本，覆盖真实网页、桌面应用和跨应用流程。任务集合、操作系统和执行判定均限定其分数解释。
- [BrowserGym Ecosystem，arXiv v4](https://arxiv.org/abs/2412.05467)，2025-02-28 修订。阅读摘要与 HTML 中关于环境 API、整合 benchmark 和 AgentLab 的说明。BrowserGym 提供 Gymnasium 风格观察/动作接口和研究生态，整合多个已有任务集；由此可推断它本身不把各任务集变成同一 grader 或同一能力量尺，不能把该推论写成统一评分协议。
- [OSWorld 2.0，arXiv v2](https://arxiv.org/abs/2606.29537)，2026-07-13 修订。阅读摘要、§§1、2.1（任务设计与评测协议）和 §6（局限）。论文报告 108 个跨日常与专业工作的长流程任务，人工中位操作时间约 1.6 小时；作者报告的模型结果还依赖 500 步二元完成指标、partial 指标、thinking 配置和 batched tool calls。任务域和职业覆盖不穷尽，作者明确将切片结果定位为诊断信号。不得把这些结果与 OSWorld v1 合并成同一量尺。

## 工具和状态化工作流

- [τ-bench，arXiv v1](https://arxiv.org/abs/2406.12045)，2024-06-17 提交。阅读 HTML §3 的 pass^k 定义及 §4 的任务/环境构造。它以模拟用户、领域 API 与对话结束时数据库状态对照目标状态评估业务任务。`pass^k` 表示同一任务多个独立试次全部成功的可靠性，`pass@k` 表示至少一次成功，两者回答不同问题；分数依赖模拟用户、领域政策和状态判定。
- [ToolSandbox，arXiv v2](https://arxiv.org/abs/2408.04682)，2025-04-16 修订。阅读 HTML §§1–3 及附录统计。论文描述 1,032 个场景和 34 个工具；以可交互的对话、状态化工具、里程碑 DAG 和必须避免的 minefield 事件评估多种有效轨迹。论文报告模拟用户可出现幻觉或指令跟随问题，因此模拟器错误需要与 Agent 错误分开。任务数、工具集和作者标注决定其结论边界。
- [AgentDojo，arXiv v3](https://arxiv.org/abs/2406.13352)，2024-11-24 修订。阅读摘要及版本记录。论文环境包含 97 个正常任务和 629 个安全测试用例，用于动态评估不可信工具数据中的 prompt injection 攻击与防御。任务效用与安全行为需要并列看；该环境结果不构成目标系统授权或副作用控制的证明。

## 科学与研究任务

- [GAIA，arXiv v1](https://arxiv.org/abs/2311.12983)，2023-11-21 提交。阅读摘要。论文定义一般助理任务，涉及推理、多模态、网页浏览和工具使用，并报告 466 个问题；它提供综合助理任务入口，答案质量、可执行产物和工作流副作用不是同一评分对象。
- [ScienceAgentBench，arXiv v3](https://arxiv.org/abs/2410.05080)，2025-03-31 修订。阅读摘要和 HTML §§1–2.3、附录局限。论文从 44 篇同行评审出版物整理 102 个四学科数据分析任务，由 9 名领域专家参与校验；每题产出可独立运行的 Python 程序，并分别观察执行、任务成功、程序相似性、成本和分阶段 rubric。它针对数据驱动科学任务中的程序生成，不覆盖完整科学发现流程。
- [PaperBench，arXiv v3](https://arxiv.org/abs/2504.01848)，2025-04-07 修订。阅读摘要、HTML §§1、2、实验、局限和 JudgeEval 附录。论文以 20 篇 ICML 2024 Spotlight/Oral 论文构造从理解到实现/运行的复现任务，含 8,316 个 rubric 子项；Rubric 与论文作者共同设计。`21.0%` 是所测 Claude 3.5 Sonnet（New）及其开源 scaffold 的平均 replication score，不表示完整复现了 21% 的论文。JudgeEval 的 F1 也绑定其 judge、scaffold、rubric 和评测样本。

## 长时程与动态环境

- [METR Task-Completion Time Horizons](https://metr.org/time-horizons/)，官方页面最后更新于 2026-09-08；2026-11-03 访问时注明不再主动更新。阅读当前页面的方法说明和不确定性提示。页面用人类专家完成时间描述任务难度，将成功概率对人类任务时长拟合 logistic curve，并给出 50%/80% 成功率交点；页面提示当前任务集下 16 小时以上的测量不可靠。
- [Measuring AI Ability to Complete Long Software Tasks，arXiv v4](https://arxiv.org/abs/2503.14499)，2026-07-10 修订。阅读摘要、HTML §§1–3、§4.1、§6 和任务集限制。论文定义的人类时间来自领域专家在没有任务专属上下文时的基线；AI 测量对象为模型加 scaffold 的 Agent 配置，作者在其 task family 间使用逆平方根任务数加权并用 logistic model 拟合 50%/80% 交点。具体任务集以软件工程、机器学习和网络安全为主，不能解释成通用劳动时间；高于 16 小时的公开页面结果当前标为不可靠。页面时间是任务难度坐标，不是 Agent 连续运行时长，外部有效性仍受任务覆盖、基线抽样与配置选择影响。
- [Gaia2，arXiv v1](https://arxiv.org/abs/2602.11964)，2026-02-12 提交。阅读摘要和 HTML 中写操作 verifier 说明。论文将事件异步演进、时间约束、模糊信息和协作放入环境，并以 write-action verifier 对照每个状态改变动作。论文报告绑定该环境、动作定义、模型与 verifier；异步模拟环境与真实组织协作仍有差距。

## 评测合同审计

- [Do Agent Benchmarks Do What They Say?，arXiv v1](https://arxiv.org/abs/2609.37315)，2026-09-29 提交；页面标为提交至 IEEE BigData 2026 的预印本。阅读摘要及 HTML 方法和实验部分（§§III–V）。方法将工具接口宣称的状态效果作为可执行合同，对照固定 commit 的实现、任务文件与 evaluator 实际读取字段。作者在固定版本的 34 个可变更工具中报告 7 个工具缺陷和 1 个 evaluator 属性；其 AgentDojo 扩展审计另有独立工具范围。作者也说明静态/动态检查器有漏检，暴露集合依赖可解析字段，某些结果属于有限被测环境。缺陷可触达性不证明 Agent 曾触发、实际副作用已发生或公开排行榜分数已经变化。

## 跨来源边界

上述工作测量的对象分别可能是仓库 patch、终端最终状态、网页/桌面 workflow、事务后数据库、可运行程序、长程论文复现、按人工任务时长刻度的难度，或工具合同实现。每项分数都须保留任务 revision、环境初始状态、模型与 scaffold、预算、grader/verifier、试次和样本范围；仅因名称里都有 Agent 或 benchmark，不能把它们排成一个通用能力榜。
