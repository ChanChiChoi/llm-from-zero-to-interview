# 第二章：概率论：从条件分布到语言模型行为

语言模型的直接输出不是一个“答案”，而是词表上每个候选 token 的一组分数，经过归一化后形成条件概率分布。训练让真实文本在模型分布下获得更高概率；解码从这个分布中选择下一个 token；评估则要判断分布是否能支持正确、稳定、可校准和符合任务约束的行为。

概率论因此连接了几件看起来不同的事情：next-token prediction、最大似然、交叉熵、perplexity、temperature、top-p、KL、DPO、校准和幻觉。它们不是一堆孤立术语，而是在回答同一个问题的不同侧面：给定上下文，模型认为哪些结果可能发生，为什么这样认为，怎样用数据更新这种判断，以及这种概率判断和现实正确性之间差多远。

初学者可以先记住一条主线：先定义随机结果，再定义条件概率；用链式法则把整段文本拆成每一步的预测；用负对数似然训练这些预测；用采样或贪心策略消费分布；最后用交叉熵、校准和任务成功率检查分布是否有用。专家还要追问分母、tokenization、mask、数据分布、随机种子、温度、证据来源和未覆盖条件，因为同一个“概率”在这些条件变化后未必仍有可比意义。

本章的数值例子和 Python 实验是教学构造，不代表任何线上模型的实测结果。公式会注明变量和适用条件；代码会显式处理空输入、零概率、非法温度和概率不归一等边界，让概率模型的前提成为可检查的程序契约。

## 2.1 概率对象：模型到底在预测什么

### 2.1.1 样本空间、事件和随机变量

概率论先规定可能发生什么。所有可能结果组成样本空间 `Omega`；样本空间中的一个集合叫事件。若掷骰子，样本空间可以是 `{1,2,3,4,5,6}`，“结果为偶数”就是事件 `{2,4,6}`。

随机变量不是“随机生成的数字”这么简单，而是把随机结果映射成可计算的数值。语言模型中，给定上下文后，下一个 token 可以看成离散随机变量：

~~~math
X_t\in\{1,2,\ldots,V\}
~~~

其中 `V` 是词表大小，`X_t=v` 表示第 `t` 个位置生成了 token `v`。模型参数为 `theta`，给定此前 token 后输出：

~~~math
p_{\theta}(X_t=v\mid x_{1:t-1})
~~~

这里的概率是模型对生成结果的分布描述，不是“这个 token 在现实世界中为真”的概率。回答一个事实问题时，模型可能给错误句子很高概率，因为训练目标首先是预测数据分布中的语言延续，而不是直接访问世界真值。

### 2.1.2 数据分布、模型分布和世界事实

理解大模型概率时，至少要分开三种对象：

1. 数据分布：训练或评估语料中样本出现的统计规律；
2. 模型分布：参数 `theta` 给定后，模型对 token 或序列分配的概率；
3. 现实事实：某个命题是否与外部世界、权威文档或业务状态相符。

最大似然训练主要让模型分布贴近数据分布。若数据中存在过时、冲突或错误的信息，模型并不会因为输出概率高就自动发现问题。RAG、工具验证、引用和人工审核的作用，是把模型生成过程连接到额外证据，而不是简单把“概率”变成“真值”。

这一区分也解释了为什么一个 benchmark 分数不能直接等同于产品可靠性。benchmark 测的是规定数据和评估协议下的行为；它可以提供证据，但证据的范围受数据切分、污染、提示、评审器和任务定义限制。

### 2.1.3 条件概率是语言模型的接口

无条件概率只问“某个 token 通常出现多大可能”；语言模型更关心在上下文已经给定时，下一个 token 的可能性：

~~~math
P(X_t=x_t\mid X_{1:t-1}=x_{1:t-1})
~~~

例如：

~~~text
P(Paris | The capital of France is)
~~~

这个写法省略了随机变量名，但含义是：上下文固定为 `The capital of France is` 时，下一个 token 为 `Paris` 的条件概率。上下文改变，条件分布也会改变；同一个 token 在不同位置并没有一个固定的“全局概率”。

## 2.2 离散分布和 softmax：从 logits 到概率

### 2.2.1 合法的离散概率分布

一个离散分布需要满足：

~~~math
p_i\ge 0,
\qquad
\sum_{i=1}^{V}p_i=1
~~~

`p_i` 表示第 `i` 个候选结果的概率。神经网络最后一层通常输出 logits，而不是概率。logit 可以是任意实数，平移所有 logits 不会改变 softmax 后的分布。

### 2.2.2 Softmax 的定义

给定 logits `z_1,...,z_V`，softmax 为：

~~~math
p_i
=
\frac{\exp(z_i)}{\sum_{j=1}^{V}\exp(z_j)}
~~~

指数保证结果为正，分母保证总和为 1。若 `z_i` 更大，`p_i` 也更大，但概率差异取决于所有候选的相对分数，而不是只取决于某一个 logit。

例如 logits 为 `(2,1,0)` 时，三项的相对权重是 `(e^2,e^1,e^0)`；把它们都加 10，比例不变。这个平移不变性正是数值稳定实现的基础。

### 2.2.3 稳定的 softmax

直接计算很大的指数可能溢出。令 `z_max=max_j z_j`，则：

~~~math
\frac{\exp(z_i)}{\sum_j\exp(z_j)}
=
\frac{\exp(z_i-z_{\max})}
{\sum_j\exp(z_j-z_{\max})}
~~~

这是严格的代数等价变形，不是近似。减去最大值后，所有指数的输入不大于 0，至少能避免最大项的指数超过浮点范围。

但稳定 softmax 不能解决所有问题：输入包含 `NaN` 时仍会传播异常；所有候选被 mask 时可能出现空分布；低精度下接近的概率仍可能因舍入而改变排序。工程实现还需要规定这些边界的行为。

### 2.2.4 概率分布不等于置信度

softmax 的最大值常被叫作模型置信度，但它首先只是模型分布中最大类别的概率。若模型在分布外问题上过度自信，最大 softmax 概率可以很高而准确率很低。要把概率解释成“正确的可能性”，需要独立的校准评估，不能只看输出中的最大数。

## 2.3 联合、条件、边缘和 Bayes

### 2.3.1 联合概率与条件概率

两个事件同时发生的概率是联合概率 `P(A,B)`。当 `P(B)>0` 时，条件概率定义为：

~~~math
P(A\mid B)=\frac{P(A,B)}{P(B)}
~~~

把等式移项，可以得到乘法规则：

~~~math
P(A,B)=P(A\mid B)P(B)
~~~

在语言模型中，`A` 可以是“当前位置 token 为 `Paris`”，`B` 可以是给定的上下文。条件概率的分母不是装饰，它决定了“在什么信息已经知道”的前提。换上下文、换候选集合或换数据切分，概率的解释都会变化。

### 2.3.2 边缘概率和全概率公式

如果 `Y` 是不关心的变量，可以把所有可能的 `Y` 加总掉：

~~~math
P(X=x)=\sum_yP(X=x,Y=y)
~~~

若事件 `H` 与其补集构成划分，则：

~~~math
P(E)=P(E\mid H)P(H)+P(E\mid\neg H)P(\neg H)
~~~

这一步在诊断问题中非常重要。一个证据在“有问题”和“没问题”两种情况下都可能出现，仅知道 `P(E|H)` 还不够，还要知道先验 `P(H)` 以及 `P(E|not H)`。

### 2.3.3 Bayes 公式和基率

Bayes 公式为：

~~~math
P(H\mid E)
=
\frac{P(E\mid H)P(H)}{P(E)}
~~~

`P(H)` 是看到证据前的先验，`P(E|H)` 是假设成立时看到证据的可能性，`P(H|E)` 是看完证据后的后验。

假设一个高风险故障在所有请求中的先验比例为 `P(H)=0.01`。监控信号在故障发生时触发的概率为 `P(E|H)=0.95`，在没有故障时误触发的概率为 `P(E|not H)=0.05`。则：

~~~math
P(E)=0.95\times0.01+0.05\times0.99=0.059
~~~

~~~math
P(H\mid E)=\frac{0.95\times0.01}{0.059}\approx0.161
~~~

即使监控信号有 95% 的命中率，单次告警真正对应故障的后验也只有约 16.1%，因为基率很低且误报并非零。这个例子不是为了否定监控，而是说明“检测率很高”与“告警为真”是两个不同的条件概率。

在 RAG 中也有相似结构：某段文字与问题相似，不等于它就是正确、最新且有权限的证据。相似度、版本、权限和人工标注共同影响后验判断，不能把一个排序分数直接称为事实概率。

## 2.4 链式法则：为什么只预测下一个 token 就够了

### 2.4.1 联合序列概率的分解

对长度为 `T` 的 token 序列 `x_1,...,x_T`，概率链式法则给出：

~~~math
P(x_{1:T})
=
\prod_{t=1}^{T}P(x_t\mid x_{1:t-1})
~~~

例如长度为 3 的序列：

~~~math
P(x_1,x_2,x_3)
=
P(x_1)P(x_2\mid x_1)P(x_3\mid x_1,x_2)
~~~

因此，自回归语言模型只要学会每一步的条件分布，就定义了整段序列的联合概率。它不需要直接为所有可能的完整句子分别存一个概率。

### 2.4.2 训练时并行，生成时顺序

训练中，给定真实序列后，所有位置的上下文都可以由已知 token 构造。通过 causal mask，模型一次前向可以并行计算多个位置的 next-token logits；每个位置的 label 是右移后的真实 token。

生成时，下一个 token 尚未知道，模型必须先选出 `x_t`，再把它加入上下文计算 `x_{t+1}`。所以同一概率分解在训练和推理阶段有不同的计算形态：训练可以并行，生成通常是顺序依赖的。

这也解释了 KV cache 的价值。缓存并没有改变链式概率本身，只是避免每一步重复计算已经处理过的 key/value。概率建模的顺序依赖仍然存在，缓存优化的是实现成本。

### 2.4.3 依赖关系和上下文窗口

如果错误地假设 token 独立，就会写成：

~~~math
P(x_{1:T})\overset{\mathrm{wrong}}{=}\prod_{t=1}^{T}P(x_t)
~~~

自然语言中的词通常强烈依赖上下文。n-gram 模型通过有限历史近似依赖，Transformer 通过注意力在上下文窗口内建立更灵活的交互。窗口之外的信息并不会因为链式法则存在就自动可见；模型只能使用输入、检索、记忆或工具实际提供的证据。

## 2.5 最大似然、NLL 与交叉熵

### 2.5.1 最大似然的序列形式

给定训练样本集合 `D`，最大似然估计寻找参数 `theta`，使观测数据在模型下的概率最大：

~~~math
\theta^*
=
\arg\max_{\theta}
\prod_{x\in D}P_{\theta}(x)
~~~

使用对数可以把乘积变成求和：

~~~math
\theta^*
=
\arg\max_{\theta}
\sum_{x\in D}\log P_{\theta}(x)
~~~

因为 `log` 是单调递增函数，最大化 likelihood 与最大化 log-likelihood 等价；求和更适合数值计算和梯度优化。

### 2.5.2 自回归语言模型的 NLL

将链式分解代入，单条序列的负对数似然为：

~~~math
L_{\mathrm{NLL}}(x)
=
-\sum_{t=1}^{T}\log p_{\theta}(x_t\mid x_{1:t-1})
~~~

真实 token 的条件概率越高，对 NLL 的贡献越小；如果模型给真实 token 很小的概率，`-log(p)` 就会很大。概率不能为零，否则 NLL 为无穷大，这也是平滑、数值稳定和合理词表覆盖重要的原因。

### 2.5.3 交叉熵如何出现

设真实标签分布为 `P`，模型分布为 `Q`。交叉熵定义为：

~~~math
H(P,Q)=-\sum_{i}P(i)\log Q(i)
~~~

如果真实标签是 one-hot 分布，正确类别 `y` 的 `P(y)=1`，其他类别为 0，于是：

~~~math
H(P,Q)=-\log Q(y)
~~~

这正是单个 token 的 NLL。对所有 token 求平均，就得到常见的 token-level cross entropy。交叉熵不是一个脱离标签的“模型自信度”，它必须相对于指定的目标分布计算。

### 2.5.4 padding、mask 和分母

如果一个 batch 中有 padding，不能把 padding 位置当成真实 token 参与平均。设 `m_t` 是有效 token mask，`ell_t` 是每个位置的 NLL，则 masked mean 为：

~~~math
L_{\mathrm{masked}}
=
\frac{\sum_t m_t\ell_t}{\sum_t m_t}
~~~

这里的分母是有效 token 数，而不是张量总位置数。若不同样本还有任务权重 `w_t`，则可以写成：

~~~math
L_{\mathrm{weighted}}
=
\frac{\sum_t w_tm_t\ell_t}{\sum_t w_tm_t}
~~~

错误的 loss reduction 会让长样本、短样本、padding 比例不同的 batch 产生不可比结果。报告训练或评估 loss 时，应写清 tokenizer、有效 token 定义、mask、权重和 reduction。

### 2.5.5 一个 NLL 数值例子

假设三个真实 token 的模型概率分别为 `0.8`、`0.5` 和 `0.1`，则总 NLL 为：

~~~math
L_{\mathrm{NLL}}
=-\log0.8-\log0.5-\log0.1
\approx2.526
~~~

平均 token loss 为 `2.526/3≈0.842`。第三个 token 的概率只有 0.1，因此它贡献了最大的惩罚。训练时一个“平均 loss 下降”可能来自大量容易 token 的改善，同时掩盖少数关键字段或否定词的退化；高影响任务需要额外报告按错误类型分桶的指标。

## 2.6 熵、交叉熵与 KL：分布之间的距离

### 2.6.1 熵衡量分布自身的不确定性

离散分布 `P` 的熵为：

~~~math
H(P)=-\sum_iP(i)\log P(i)
~~~

若分布把全部概率放在一个结果上，熵为 0；若在 `V` 个结果上均匀分布，熵为 `log V`。熵高表示分布更分散，不表示答案一定更有价值；熵低表示模型更集中，也不表示它一定正确。

以二分类为例，`P=(0.5,0.5)` 比 `P=(0.99,0.01)` 的熵高。前者更不确定，后者更自信，但若 0.99 的类别是错误类别，低熵就是过度自信。

### 2.6.2 交叉熵分解为真实熵和 KL

交叉熵与 KL 散度满足：

~~~math
H(P,Q)=H(P)+D_{\mathrm{KL}}(P\Vert Q)
~~~

其中 KL 散度为：

~~~math
D_{\mathrm{KL}}(P\Vert Q)
=
\sum_iP(i)\log\frac{P(i)}{Q(i)}
~~~

KL 满足非负性：

~~~math
D_{\mathrm{KL}}(P\Vert Q)\ge0
~~~

并且只有 `P` 与 `Q` 几乎处处相同才为 0。因为 `H(P)` 对给定真实分布是常数，最小化交叉熵等价于最小化 `D_KL(P||Q)`。

### 2.6.3 KL 是有方向的

一般情况下：

~~~math
D_{\mathrm{KL}}(P\Vert Q)
\ne
D_{\mathrm{KL}}(Q\Vert P)
~~~

方向不能随意交换。`D_KL(P||Q)` 以 `P` 中真实出现的区域为权重，若 `Q` 在这些区域给出很小概率，会受到很大惩罚；反向 KL 的行为不同。

这件事在知识蒸馏、策略约束和参考模型正则化中很重要。写出 KL 公式时，应明确谁是目标分布、谁是被优化分布，不能只说“加一个 KL 让模型别偏太远”。

### 2.6.4 一个分布比较例子

设真实分布 `P=(0.7,0.3)`，模型分布 `Q=(0.6,0.4)`。则：

~~~math
H(P)=-0.7\log0.7-0.3\log0.3
~~~

~~~math
H(P,Q)=-0.7\log0.6-0.3\log0.4
~~~

两者的差就是 `D_KL(P||Q)`。如果把 `Q` 的第一项降到接近零，交叉熵会显著增大，因为模型几乎排除了真实分布的重要结果。

## 2.7 期望、方差和抽样估计

### 2.7.1 期望是分布加权的平均

离散随机变量 `X` 的期望为：

~~~math
\mathbb{E}[X]=\sum_xxP(X=x)
~~~

机器学习目标常写成数据分布上的期望损失：

~~~math
J(\theta)=\mathbb{E}_{x\sim P_{\mathrm{data}}}
[\ell(\theta;x)]
~~~

实际训练只能看到有限 batch，因此用样本平均估计：

~~~math
\hat{J}_B(\theta)
=
\frac{1}{B}\sum_{i=1}^{B}\ell(\theta;x_i)
~~~

在样本独立同分布且抽样合理等条件下，增大样本量通常会让估计更稳定。但“batch loss 更稳定”不等于“模型泛化更好”；优化动态、数据顺序、学习率和硬件并行都会一起变化。

### 2.7.2 方差衡量估计波动

方差定义为：

~~~math
\mathrm{Var}(X)
=
\mathbb{E}\left[(X-\mathbb{E}[X])^2\right]
=
\mathbb{E}[X^2]-\mathbb{E}[X]^2
~~~

标准差是方差的平方根，和随机变量使用相同量纲。方差大的 loss、梯度或评估分数意味着单个样本对均值的影响更强，通常需要更多样本或分层分析。

### 2.7.3 样本均值的方差

若 `X_1,...,X_n` 独立同分布，单个样本方差为 `sigma^2`，样本均值的方差为：

~~~math
\mathrm{Var}\left(\bar{X}\right)=\frac{\sigma^2}{n}
~~~

这解释了为什么评估样本量增加通常会降低均值估计的随机波动。但真实评估经常存在相关样本、分桶不均、重复提示、judge 一致性不足和选择偏差，不能机械套用独立同分布假设。

### 2.7.4 协方差和相关性

两个随机变量的协方差为：

~~~math
\mathrm{Cov}(X,Y)
=
\mathbb{E}[(X-\mathbb{E}[X])(Y-\mathbb{E}[Y])]
~~~

正协方差表示两者倾向于一起增大，负协方差表示一个增大时另一个倾向于减小。训练中不同任务 loss 可能相关；评估中同一来源的题目可能共享模板，导致样本并不独立；多个指标同时提升也可能只是被共同的难度因素影响。

相关性不是因果性。若要声称某个模块导致质量提升，仍需要配对比较、消融、随机化或其他能够排除混杂因素的设计。

## 2.8 序列 log probability 与 perplexity

### 2.8.1 为什么用 log probability

序列概率是各步条件概率的乘积：

~~~math
P(x_{1:T})
=
\prod_{t=1}^{T}p_t
~~~

长序列中这个乘积很容易下溢。取对数后：

~~~math
\log P(x_{1:T})
=
\sum_{t=1}^{T}\log p_t
~~~

因此工程中通常累加 log probability，而不是直接累乘概率。对数还把序列比较从乘法变成加法，便于分析每个位置的贡献。

### 2.8.2 NLL、平均 loss 和 PPL

平均 token NLL 为：

~~~math
\bar{L}
=
-\frac{1}{T}\sum_{t=1}^{T}\log p_t
~~~

以自然对数为底时，perplexity 定义为：

~~~math
\mathrm{PPL}=\exp(\bar{L})
~~~

PPL 可以直观理解为：在这个评估分布上，模型平均面对的“等价候选数”尺度。但它依赖 tokenizer、文本规范化、是否包含边界 token、padding mask、上下文长度和平均方式。不同 tokenizer 或不同数据集上的 PPL 不应直接排序。

### 2.8.3 句子长度和概率比较

完整序列概率通常随长度增加而变小，所以直接用 `log P(sequence)` 比较不同长度句子，会天然偏向较短序列。平均 log probability 或长度归一化可以缓解长度因素，但会引入另一种偏好：过度归一化可能偏爱局部高概率、缺少完整信息的短答案。

在生成、候选排序和 beam search 中，长度惩罚不是“数学真理”，而是任务目标的一部分。应在固定任务、固定答案标准和独立验证集上选择，而不能看到某个样例有效就把它当成普遍规则。

### 2.8.4 PPL 的能力边界

较低 PPL 说明模型在指定文本分布上给出了更高平均概率，但它不能单独证明：

1. 事实性更高；
2. 指令遵循更好；
3. 工具调用更安全；
4. 长文档检索更可靠；
5. 生成答案对用户更有帮助。

一个模型可以用流畅、常见但错误的语言获得较低 PPL。生产系统要把 PPL 与任务成功率、关键字段准确率、引用支持率、拒答质量、延迟和成本分开报告。

## 2.9 解码：如何消费条件分布

### 2.9.1 Greedy 和随机采样

给定下一个 token 分布 `p`，greedy decoding 选择：

~~~math
x_t=\arg\max_i p_i
~~~

它确定性强、复现方便，但可能重复、缺乏多样性，也可能把早期局部高概率选择带入不理想的后续路径。

随机采样按 `p` 抽取 token。它保留分布中的不确定性，可以产生更多样的结果，但需要随机种子、概率校验和重复运行统计。采样不是“让模型更聪明”，而是改变从模型分布到输出序列的决策过程。

### 2.9.2 Temperature

温度 `tau>0` 对 logits 变换为：

~~~math
p_i(\tau)
=
\frac{\exp(z_i/\tau)}
{\sum_j\exp(z_j/\tau)}
~~~

`tau<1` 通常使分布更尖锐，`tau>1` 通常使分布更平。极限上，温度趋近 0 时趋向于选择最大 logit；温度很高时分布趋向更均匀，但具体有限范围仍取决于 logits 差异。

温度影响生成随机性，不等于校准温度。生成时调温度是为了控制输出行为；校准时的 temperature scaling 是在留出的验证集上拟合一个参数，使置信度和实际正确率更匹配。两者都出现 `tau` 不代表用途相同。

### 2.9.3 Top-k

top-k 先按概率排序，只保留最大的 `k` 个候选，然后在保留集合中重新归一化：

~~~math
S_k=\mathrm{TopK}(p,k)
~~~

~~~math
p_i'=\frac{p_i}{\sum_{j\in S_k}p_j},
\qquad i\in S_k
~~~

重新归一化很重要。如果仍使用原概率直接采样，保留集合的总质量小于 1，采样过程就没有定义完整的概率空间。

`k=1` 退化为 greedy；`k` 太小可能把合理候选排除；`k` 太大则保留更多低概率尾部。它是解码超参数，不能代替数据质量、事实核验或安全约束。

### 2.9.4 Top-p 或 nucleus sampling

top-p 动态选择最小候选集合，使排序后概率的累计和达到阈值 `p`：

~~~math
S_p
=
\min\left\{S:\sum_{i\in S}p_i\ge p\right\}
~~~

实现时应按概率从高到低累加，至少保留一个候选，然后对集合重新归一化。与固定 `k` 相比，top-p 会根据分布尖锐程度改变候选数量：分布尖锐时集合可能很小，分布平时集合会变大。

边界需要明确：`p` 必须在 `(0,1]` 内；如果 `p` 很小仍应保留最高概率候选；存在相同概率时要规定稳定排序；过滤后必须保留候选 token 与其原始身份的对应关系。

### 2.9.5 解码组合和失败模式

temperature、top-k 和 top-p 可以组合，但每一步的顺序要固定并记录。常见顺序是先调整 logits，再排序和截断，最后归一化采样；不同实现的细节可能不同。

失败模式包括：

1. 温度过低导致重复和模式坍缩；
2. 温度过高保留大量不稳定尾部；
3. top-k 或 top-p 过滤掉任务所需的低频专有名词；
4. 过滤后未重新归一化，导致采样概率不合法；
5. 随机种子未记录，无法复现一个 bad case；
6. 把解码改变后的样例质量提升误认为模型训练能力提升。

## 2.10 独立性、条件独立和上下文依赖

### 2.10.1 独立性的定义

若事件 `A` 与 `B` 独立，则：

~~~math
P(A,B)=P(A)P(B)
~~~

等价地，在分母非零时：

~~~math
P(A\mid B)=P(A)
~~~

语言 token 通常不独立。句子“the capital of France is Paris”中，`Paris` 的概率明显依赖前面的 token。把所有 token 当作独立变量会丢掉语言结构。

### 2.10.2 Markov 假设和 n-gram

n-gram 模型用有限历史近似条件概率，例如二阶 Markov 假设：

~~~math
P(x_t\mid x_{1:t-1})
\approx
P(x_t\mid x_{t-2:t-1})
~~~

这种限制降低了估计难度，但无法直接利用更远上下文。Transformer 也不是“无限记忆”：它在给定上下文窗口、位置机制、压缩和注意力实现的条件下建模更长依赖。窗口变长不自动保证中间证据被有效使用。

### 2.10.3 条件独立不能被随意假设

在某些图模型中，给定变量 `Z` 后，`X` 和 `Y` 可能条件独立：

~~~math
P(X,Y\mid Z)=P(X\mid Z)P(Y\mid Z)
~~~

但在多模态 RAG、工具轨迹和多轮对话中，文档、用户权限、工具状态和模型输出经常相互关联。若把它们当作独立样本，可能低估错误传播和评估方差。

## 2.11 期望下的训练：batch 是估计，不是总体

### 2.11.1 经验风险和真实风险

真实数据分布上的风险可以写成：

~~~math
R(\theta)
=
\mathbb{E}_{(x,y)\sim P_{\mathrm{data}}}
[\ell(\theta;x,y)]
~~~

有限训练集上的经验风险是：

~~~math
\hat{R}(\theta)
=
\frac{1}{n}\sum_{i=1}^{n}\ell(\theta;x_i,y_i)
~~~

mini-batch 进一步用一小部分样本估计经验风险。batch loss 的波动可能来自样本难度、类别比例、padding、随机增强和数据顺序，不应直接解释为模型能力在每一步都真实变差。

### 2.11.2 梯度是随机估计

若总体目标梯度为：

~~~math
g(\theta)=\mathbb{E}[\nabla_{\theta}\ell(\theta;X)]
~~~

batch 梯度为：

~~~math
\hat{g}_B(\theta)
=
\frac{1}{B}\sum_{i=1}^{B}
\nabla_{\theta}\ell(\theta;x_i)
~~~

小 batch 通常带来更大的梯度估计噪声；大 batch 通常让估计更稳定，但需要更多显存和计算，且可能改变学习率、更新次数、正则化和泛化行为。梯度累积增加有效 batch 不等于每一步都完全等价于真正的大 batch，尤其当 dropout、动态 padding、batch normalization 或优化器更新发生在累积内部时。

### 2.11.3 评估中的重复运行

采样模型、judge 或人工评估都可能有随机性。一个结果应至少记录：

1. 样本数和采样方式；
2. 随机种子或随机化协议；
3. 指标的分母和聚合方式；
4. 置信区间或重复运行的离散程度；
5. 错误类型和高影响切片。

如果一个方法只在单一 seed、少量样本或单个 judge 提示下提升，就不能把这个差异直接写成稳定能力。

## 2.12 校准：模型的概率是否能当作可信度

### 2.12.1 校准的定义

对一个二分类预测器，若它给出置信度 `c`，理想校准要求：

~~~math
P(Y=1\mid C=c)=c
~~~

实际评估通常把置信度分成若干区间。第 `b` 个区间 `B_b` 中，平均置信度为 `conf(B_b)`，真实正确率为 `acc(B_b)`。Expected Calibration Error 可以写成：

~~~math
\mathrm{ECE}
=
\sum_{b=1}^{M}
\frac{|B_b|}{n}
\left|\mathrm{acc}(B_b)-\mathrm{conf}(B_b)\right|
~~~

ECE 依赖分桶数量、区间边界和样本量，不是一个完全与评估协议无关的常数。样本很少时，细分过多会让每个桶极不稳定。

### 2.12.2 Brier score 和 NLL

对二分类结果 `y_i` 和置信度 `c_i`，Brier score 为：

~~~math
\mathrm{Brier}
=
\frac{1}{n}\sum_{i=1}^{n}(c_i-y_i)^2
~~~

越小表示概率预测与结果的平方误差越小。NLL 也衡量概率质量，但会对极小的错误概率施加很大惩罚；ECE 更关注分桶后的校准偏差。它们测量不同性质，不能只选一个数字代表“概率可靠”。

### 2.12.3 语言模型的置信度有多个层级

对 LLM，至少要区分：

1. token-level 概率：某个位置的下一个 token 概率；
2. sequence-level log probability：整段输出的逐 token log 概率和；
3. claim-level 置信度：某个事实断言是否有证据支持；
4. task-level 成功概率：整个任务是否完成且满足约束。

高 token 概率不自动推出高 claim 正确率；把一段流畅的长回答压缩成一个平均 token confidence，也不一定能反映其中某个关键数字的风险。高风险系统应让置信度与可验证的任务单位对应。

### 2.12.4 温度缩放和留出校准

对分类 logits，可以在独立校准集上拟合一个温度 `T_cal`：

~~~math
q_i
=
\frac{\exp(z_i/T_{\mathrm{cal}})}
{\sum_j\exp(z_j/T_{\mathrm{cal}})}
~~~

`T_cal` 应在不参与模型训练的校准数据上选择，并在另一个测试集上验证。它可以改善某些分布内的概率匹配，但不保证分布外、语言切片、长上下文或工具失败场景仍然校准。

### 2.12.5 选择性预测和 abstention

如果系统允许对低置信任务请求补充信息、调用工具或交给人工，就可以研究 coverage-risk trade-off。设系统接受并自动回答的样本集合为 `A`：

~~~math
\mathrm{Coverage}=\frac{|A|}{n}
~~~

~~~math
\mathrm{SelectiveRisk}
=
\frac{\#\{i\in A:\text{prediction}_i\text{ is wrong}\}}{|A|}
~~~

降低 coverage 可能降低自动回答错误率，但也可能造成过度拒答、用户负担和人工成本。正确目标不是让模型永远拒绝，而是在风险、覆盖率、延迟和人工升级成本之间做任务级取舍。

## 2.13 高概率不等于事实正确

### 2.13.1 语言似然和事实真值是不同目标

next-token 训练优化的是：

~~~math
\mathbb{E}_{x\sim P_{\mathrm{data}}}
[-\log p_{\theta}(x_t\mid x_{1:t-1})]
~~~

这个目标奖励符合训练分布的延续。它没有在公式中直接出现“命题是否被现实证据证实”。因此以下情况都可能发生：

1. 训练语料包含错误或过时说法；
2. 问题的上下文不足以区分多个候选答案；
3. 模型根据常见模板补齐不存在的细节；
4. SFT 或偏好数据奖励完整、自信、流畅的表达；
5. 外部文档本身不可信或包含注入内容。

### 2.13.2 为什么只调温度不能根治幻觉

降低温度通常减少随机变化，但如果错误 token 在模型分布中本来就是最高概率，greedy 也会稳定地产生它。提高温度可以暴露更多候选，却不能提供缺失的证据。

降低幻觉需要把目标和证据链分开处理：检索相关资料、检查文档权限和版本、要求 claim 绑定证据、在证据不足时 abstain、对关键数字使用工具验证，并用反事实样本检查模型是否真的读取输入。

### 2.13.3 概率和证据在系统中的分工

一个企业知识助手可以采用这样的分工：

~~~text
model probability -> 生成候选和排序线索
retrieval         -> 找到可能相关的证据
permission        -> 判断用户是否能读
verification      -> 检查数字、规则和约束
answer policy     -> 决定回答、澄清、升级或拒答
~~~

模型的概率适合帮助生成和排序，但不能越过权限、事实验证和动作授权边界。

## 2.14 从概率到偏好优化：DPO 的基本读法

### 2.14.1 偏好数据不是事实标签

偏好数据通常包含同一个 prompt `x` 下的 chosen response `y_w` 和 rejected response `y_l`。它表达的是在给定评价标准下，人或评审器更喜欢哪个回答，不一定表达哪个回答在现实中绝对为真。

如果偏好数据奖励礼貌、简洁和格式正确，模型可能学到这些行为；若数据没有覆盖事实核验和安全边界，偏好优化不会凭空补齐这些目标。

### 2.14.2 序列概率比值

对自回归策略 `pi_theta`，一个回答的序列 log probability 是：

~~~math
\log\pi_{\theta}(y\mid x)
=
\sum_{t=1}^{|y|}
\log\pi_{\theta}(y_t\mid x,y_{1:t-1})
~~~

DPO 使用当前策略和参考策略的 log-probability ratio 比较 chosen 与 rejected：

~~~math
m_{\theta}
=
\left[
\log\pi_{\theta}(y_w\mid x)
-\log\pi_{\mathrm{ref}}(y_w\mid x)
\right]
-
\left[
\log\pi_{\theta}(y_l\mid x)
-\log\pi_{\mathrm{ref}}(y_l\mid x)
\right]
~~~

一个常见的 DPO 损失写成：

~~~math
L_{\mathrm{DPO}}
=
-\log\sigma(\beta m_{\theta})
~~~

其中 `sigma` 是 logistic 函数，`beta` 控制偏好差异进入损失的尺度。这个公式的关键不是背下来，而是看清它比较的是“相对于 reference 的策略变化”，以及 chosen 和 rejected 的整段 log probability。

### 2.14.3 长度和 tokenization 的边界

序列 log probability 是 token log probability 的和，较长回答通常更容易得到更小的总 log probability。DPO 的实现必须明确是否使用整段 response、如何处理 prompt token、是否 mask padding、是否进行长度归一化，以及 chosen/rejected 是否经过同一 tokenizer。

如果一个回答只是因为更短而获得较高平均概率，不能直接解释成内容更好；如果两个回答的 tokenization 不同，逐 token 的数值也不应脱离 tokenizer 直接比较。

### 2.14.4 偏好优化的能力边界

DPO 或其他偏好优化可以改变模型在给定偏好数据上的分布，但不自动保证：

1. 偏好标签无噪声；
2. 评审器没有长度和风格偏差；
3. 事实性在未见领域提升；
4. 安全边界在对抗输入下保持；
5. 任务成本和延迟不恶化。

因此评估偏好优化时，既要看偏好胜率，也要看事实、拒答、证据支持、长度、基础能力和分布外切片。

## 2.15 一个可运行的概率审计实验

下面的标准库 Python 实验把本章的几个概念放在一起：bigram 条件概率、稳定 softmax、序列 log probability、NLL/PPL、熵、KL、Bayes 更新、top-k、top-p、采样、期望方差、校准和 DPO 的 log-ratio。bigram 只是最小模型，不能代表 Transformer；它的价值在于让每个概率从计数或显式 logits 中可追溯地构造出来。

~~~python
from collections import Counter, defaultdict
from math import exp, isclose, log
from random import Random


texts = [
    "I love machine learning",
    "I love deep learning",
    "machine learning is useful",
    "deep learning is powerful",
]
START = "<s>"
END = "</s>"

counts = defaultdict(Counter)
for sentence in texts:
    tokens = [START] + sentence.split() + [END]
    for current, following in zip(tokens, tokens[1:]):
        counts[current][following] += 1


def validate_distribution(probs):
    if not probs:
        raise ValueError("probability distribution must not be empty")
    if any(prob < 0 for prob in probs):
        raise ValueError("probabilities must be non-negative")
    if not isclose(sum(probs), 1.0, rel_tol=1e-9, abs_tol=1e-9):
        raise ValueError("probabilities must sum to one")


def next_token_distribution(current):
    next_counts = counts[current]
    total = sum(next_counts.values())
    if total == 0:
        return {}
    return {
        token: count / total
        for token, count in next_counts.items()
    }


def sequence_logprob(tokens):
    sequence = [START] + list(tokens) + [END]
    total = 0.0
    details = []
    for current, following in zip(sequence, sequence[1:]):
        distribution = next_token_distribution(current)
        probability = distribution.get(following, 0.0)
        if probability <= 0:
            raise ValueError(
                f"unseen transition: {current!r} -> {following!r}"
            )
        details.append((current, following, round(probability, 3)))
        total += log(probability)
    return total, details


def softmax(logits, temperature=1.0):
    if not logits:
        raise ValueError("logits must not be empty")
    if temperature <= 0:
        raise ValueError("temperature must be positive")
    scaled = [value / temperature for value in logits]
    pivot = max(scaled)
    exponentials = [exp(value - pivot) for value in scaled]
    total = sum(exponentials)
    return [value / total for value in exponentials]


def entropy(probs):
    validate_distribution(probs)
    return -sum(prob * log(prob) for prob in probs if prob > 0)


def cross_entropy(target, prediction):
    validate_distribution(target)
    validate_distribution(prediction)
    if len(target) != len(prediction):
        raise ValueError("distributions must have equal lengths")
    if any(prob <= 0 and weight > 0 for weight, prob in zip(target, prediction)):
        return float("inf")
    return -sum(
        weight * log(prob)
        for weight, prob in zip(target, prediction)
        if weight > 0
    )


def kl_divergence(target, prediction):
    validate_distribution(target)
    validate_distribution(prediction)
    if len(target) != len(prediction):
        raise ValueError("distributions must have equal lengths")
    if any(prob <= 0 and weight > 0 for weight, prob in zip(target, prediction)):
        return float("inf")
    return sum(
        weight * log(weight / prob)
        for weight, prob in zip(target, prediction)
        if weight > 0
    )


def top_k(tokens, probs, k):
    validate_distribution(probs)
    if len(tokens) != len(probs) or not 0 < k <= len(tokens):
        raise ValueError("top-k inputs are invalid")
    ranked = sorted(
        zip(tokens, probs),
        key=lambda item: (-item[1], item[0]),
    )[:k]
    mass = sum(prob for _, prob in ranked)
    return [(token, prob / mass) for token, prob in ranked], mass


def top_p(tokens, probs, threshold):
    validate_distribution(probs)
    if len(tokens) != len(probs) or not 0 < threshold <= 1:
        raise ValueError("top-p inputs are invalid")
    ranked = sorted(
        zip(tokens, probs),
        key=lambda item: (-item[1], item[0]),
    )
    kept = []
    mass = 0.0
    for token, prob in ranked:
        kept.append((token, prob))
        mass += prob
        if mass >= threshold:
            break
    normalized = [(token, prob / mass) for token, prob in kept]
    return normalized, mass


def sample_from(tokens, probs, seed=7):
    if len(tokens) != len(probs):
        raise ValueError("tokens and probabilities must have equal lengths")
    validate_distribution(probs)
    random = Random(seed)
    threshold = random.random()
    cumulative = 0.0
    for token, prob in zip(tokens, probs):
        cumulative += prob
        if threshold <= cumulative:
            return token, round(threshold, 3)
    return tokens[-1], round(threshold, 3)


def expectation(values, probs):
    validate_distribution(probs)
    if len(values) != len(probs):
        raise ValueError("values and probabilities must have equal lengths")
    return sum(value * prob for value, prob in zip(values, probs))


def variance(values, probs):
    mean = expectation(values, probs)
    second_moment = expectation(
        [value * value for value in values],
        probs,
    )
    return second_moment - mean * mean


def bayes_posterior(prior, evidence_given_true, evidence_given_false):
    if not 0 <= prior <= 1:
        raise ValueError("prior must be in [0, 1]")
    evidence_probability = (
        evidence_given_true * prior
        + evidence_given_false * (1 - prior)
    )
    if evidence_probability == 0:
        raise ValueError("evidence has zero probability")
    return evidence_given_true * prior / evidence_probability


def expected_calibration_error(confidences, outcomes, bins=5):
    if len(confidences) != len(outcomes) or not confidences:
        raise ValueError("calibration inputs must have equal non-zero length")
    if bins <= 0:
        raise ValueError("bins must be positive")
    buckets = [[] for _ in range(bins)]
    for confidence, outcome in zip(confidences, outcomes):
        if not 0 <= confidence <= 1 or outcome not in (0, 1):
            raise ValueError("invalid confidence or outcome")
        index = min(int(confidence * bins), bins - 1)
        buckets[index].append((confidence, outcome))
    total = len(confidences)
    error = 0.0
    for bucket in buckets:
        if bucket:
            confidence_mean = sum(item[0] for item in bucket) / len(bucket)
            accuracy = sum(item[1] for item in bucket) / len(bucket)
            error += len(bucket) / total * abs(confidence_mean - accuracy)
    return error


def brier_score(confidences, outcomes):
    if len(confidences) != len(outcomes) or not confidences:
        raise ValueError("Brier inputs must have equal non-zero length")
    return sum(
        (confidence - outcome) ** 2
        for confidence, outcome in zip(confidences, outcomes)
    ) / len(confidences)


def dpo_margin(policy_w, policy_l, reference_w, reference_l):
    if min(policy_w, policy_l, reference_w, reference_l) <= 0:
        raise ValueError("probabilities must be positive")
    return log(policy_w / reference_w) - log(policy_l / reference_l)
~~~

## 2.17 练习：从概率公式走到系统判断

### 练习一：从 logits 计算概率

给定 logits `(2,1,0)`，分别计算普通 softmax 和先减最大值后的 softmax，验证两者相同。再把 temperature 从 `1` 改为 `0.5` 和 `2`，比较熵如何变化，并说明这只是分布变换，不是校准证明。

### 练习二：链式概率和 log probability

构造一个长度为 4 的 token 序列，给出每个位置的条件概率，计算联合概率、联合 log probability、平均 NLL 和 PPL。再把一个位置的概率从 `0.8` 改成 `0.01`，观察它对总 NLL 的影响。

### 练习三：padding 和 loss 分母

两个样本的有效 token 数分别为 2 和 6。设计一个 batch，其中 padding loss 为零，分别计算按所有张量位置平均和按有效 token 平均的结果，说明为什么两者不可混用。

### 练习四：交叉熵和 KL

取 `P=(0.8,0.2)`、`Q=(0.6,0.4)`，计算 `H(P)`、`H(P,Q)` 和 `D_KL(P||Q)`，验证交叉熵分解。再交换 P、Q，观察 KL 是否相同，并解释其方向含义。

### 练习五：Bayes 基率

设计一个低基率故障检测例子，给出 `P(H)`、`P(E|H)` 和 `P(E|not H)`，计算 `P(H|E)`。再把误报率减半，观察后验如何变化，说明为什么只汇报命中率不完整。

### 练习六：比较解码策略

给定五个 token 的概率，手工执行 greedy、top-k 和 top-p。对 top-k/top-p 都写出过滤前质量、过滤后归一化概率和随机数落点。改变同一随机种子以外的 temperature，记录输出变化，不把一次生成样例当成平均效果。

### 练习七：设计校准评估

构造至少 30 个二分类预测，计算 ECE 和 Brier score。改变分桶数量，观察 ECE 是否变化；再按简单/困难样本分组，说明总体校准可能掩盖哪个切片的问题。

### 练习八：选择性预测

为一个文档问答系统设置置信度阈值。分别计算 coverage、自动回答错误率和人工升级量，画出 risk-coverage 曲线，并讨论阈值升高造成的用户等待成本。

### 练习九：偏好概率比值

给定 chosen、rejected 在策略和 reference 下的序列概率，计算 DPO margin。再把回答长度加倍但每 token 概率不变，比较总 log probability 与平均 log probability，说明为什么 tokenization 和长度口径必须记录。

## 2.18 本章小结：概率是模型行为的中间层

概率论给出了从数据到模型行为的一条连续链：

1. 随机变量描述下一个 token 等不确定结果；
2. 条件概率把上下文写进预测接口；
3. 链式法则把整段序列拆成逐 token 条件分布；
4. 最大似然、NLL 和交叉熵训练模型贴近目标数据分布；
5. 熵和 KL 描述分布自身的不确定性以及两个分布的差异；
6. 期望和方差解释 batch、seed 和评估结果为什么会波动；
7. greedy、temperature、top-k 和 top-p 决定如何从分布生成文本；
8. PPL 衡量指定 token 分布上的平均似然，不等于事实性或任务成功；
9. 校准和选择性预测检查概率能否支持风险决策；
10. DPO 用相对 reference 的序列概率比值表达偏好，但偏好标签不等于现实真值。

最需要保留的边界是：模型概率是对数据和上下文的预测，事实正确性需要外部证据；概率最高的输出可以稳定地错误，低温度可以减少随机性却不能创造知识；一个漂亮的平均 loss 或 PPL 不能替代关键字段、引用支持、拒答质量和分布外评估。真正理解概率论，意味着能同时说清概率的对象、条件、分母、估计误差和它在系统中的责任边界。
