# 第一章：线性代数：从向量空间到 Transformer 表示

线性代数是大模型内部计算的基本语言。一个 token 的 hidden state 是向量，一批 token 的 hidden states 是矩阵或更高阶张量，Linear layer 是线性变换，Attention 是相似度矩阵与加权求和，LoRA 是对权重增量施加低秩约束，embedding 检索则是在向量空间中比较方向和距离。

这门数学真正困难的地方，不在于公式数量多，而在于同一个符号会同时承担三种角色：它既是一个有几何意义的对象，也是一个有具体 shape 的数组，还是模型计算图中的一个接口。只记住“Q 乘 K 的转置”而不知道最后两维为什么是 `T x T`，只记住“LoRA 省参数”而不会计算两个矩阵的形状，或者只知道 cosine similarity 而不知道归一化会丢掉什么信息，都不能算真正理解。

初学者可以把本章看成一条逐步搭建的路线：先学会读向量和矩阵，再学会检查矩阵能不能相乘，然后把这些动作放进 Attention、投影、SVD、LoRA 和检索。专家则需要进一步关注约束的边界：shape 是否包含 batch 和 head，数值精度是否足够，低秩假设是否成立，检索度量是否与训练目标一致，某个漂亮的相似度是否真的能支持业务事实。

本章中的数字示例是教学构造，用于说明机制和算术关系，不代表任何线上模型的实测结果。正文会同时给出直觉、公式、shape、例子和失败模式，使“会算”与“知道什么时候不能这样算”保持在一起。

## 1.1 模型为什么需要线性代数

### 1.1.1 从 token id 到 hidden state

词表中的 token 可以先用整数表示。假设词表大小为 `V`，hidden size 为 `d`，embedding matrix 可以写成：

~~~math
E\in\mathbb{R}^{V\times d}
~~~

第 `i` 个 token 的 embedding 是矩阵 `E` 的第 `i` 行：

~~~math
h_i^{(0)}=E_{i,:}\in\mathbb{R}^{d}
~~~

这里的 `h_i^(0)` 只是进入 Transformer 前的初始表示。它通常包含词法、子词和训练语料中学到的统计关系，但还没有充分结合当前句子的上下文。相同的 token id 在不同句子中，初始 embedding 可以相同；经过 self-attention 和 MLP 后，最终 hidden state 会因为上下文不同而不同。

例如“苹果”出现在“我买了一个苹果”和“苹果发布了新芯片”中，词表 lookup 得到的向量可以相同，但后续层会读取“买了”“芯片”等周围 token，使它们在上下文中的表示发生变化。这个例子说明向量不是固定的词典释义，而是模型在某一层、某一位置对当前输入的数值状态。

### 1.1.2 一句话为什么会成为矩阵

如果一个 batch 有 `B` 个样本，每个样本有 `T` 个 token，每个 token 的 hidden size 是 `d`，hidden states 的 shape 通常写成：

~~~text
X: [B, T, d]
~~~

三个维度分别表示：

1. `B`：一次并行处理的样本数；
2. `T`：序列中的位置数；
3. `d`：每个位置的表示维度。

固定一个 batch 样本后，`X[b]` 是一个 `T x d` 矩阵；固定一个 token 位置后，`X[b, t]` 是一个 `d` 维向量。换句话说，向量、矩阵和张量不是三种互不相关的东西，而是同一批数字在不同固定维度方式下的视图。

这也是读 Transformer 公式时最重要的习惯：先说明一个符号的 shape，再讨论它做了什么。若只说“把 Q、K、V 送入 attention”，而不说明它们的 batch、head、sequence 和 head dimension，后面的转置和乘法就很容易在实现中错位。

### 1.1.3 线性代数动作在模型中的对应关系

| 线性代数动作 | 模型中的例子 | 需要检查的事实 |
| --- | --- | --- |
| 查表和选行 | token embedding | token id 是否落在词表范围 |
| 线性变换 | `XW`、`Q=XW_Q` | 中间维度是否匹配 |
| 内积 | query 与 key 的相似度 | 两个向量长度是否相同 |
| 范数和归一化 | embedding 检索、梯度监控 | 零向量和数值精度 |
| 投影 | PCA、表示方向分析 | 投影子空间和残差定义 |
| 加权求和 | attention 输出 | 权重是否归一化、mask 是否正确 |
| 低秩分解 | SVD、LoRA | rank、参数量和误差 |

模型参数量、计算量和显存通常都依赖这些维度。线性代数因此不仅解释“公式为什么这样写”，还解释系统为什么会变慢、显存为什么会增加，以及一个压缩策略可能损失什么信息。

## 1.2 向量：表示、方向和尺度

### 1.2.1 向量不是标签，而是坐标

一个 `d` 维向量可以写成：

~~~math
x=(x_1,x_2,\ldots,x_d)^{\top}\in\mathbb{R}^{d}
~~~

初学者可以把它想成空间中的一个箭头：从原点出发，方向由各坐标共同决定，长度由坐标的整体大小决定。模型中的向量并不一定对应人类能直接命名的单一属性。一个维度可能同时参与多个语义特征，多个维度也可能共同编码一个概念。

因此，“向量某一维就是‘是否为动物’”通常是过强的解释。除非通过对照数据、干预实验或其他证据验证，否则只能说某个方向与某种行为相关，不能直接把单个坐标当作稳定的人类标签。

### 1.2.2 内积把两个向量变成一个数

两个同维向量的内积定义为：

~~~math
x^{\top}y=\sum_{j=1}^{d}x_jy_j
~~~

几何上，内积还可以写成：

~~~math
x^{\top}y=\lVert x\rVert_2\lVert y\rVert_2\cos\theta
~~~

其中 `theta` 是两个向量之间的夹角。这个等式揭示了内积同时受到两个因素影响：方向是否接近，以及两个向量本身有多长。

以 `x=(3,4)`、`y=(1,0)` 为例：

~~~math
x^{\top}y=3,
\qquad
\lVert x\rVert_2=5,
\qquad
\lVert y\rVert_2=1
~~~

因为 `y` 是横轴方向，内积正好取出 `x` 在横轴上的分量。若 `x` 和 `y` 方向相近，内积通常为正且较大；若接近垂直，内积接近零；若方向相反，内积可以为负。

在 attention 中，query 和 key 的点积不是“事实相似度”，而是当前参数、位置和上下文下的匹配分数。模型学习权重，使有用的 query-key 组合倾向于得到更高分，但分数本身仍需经过 softmax、mask 和后续层共同解释。

### 1.2.3 范数衡量向量尺度

最常用的是 L2 范数：

~~~math
\lVert x\rVert_2
=
\sqrt{\sum_{j=1}^{d}x_j^2}
~~~

常见的其他范数包括：

~~~math
\lVert x\rVert_1=\sum_{j=1}^{d}|x_j|,
\qquad
\lVert x\rVert_{\infty}=\max_j|x_j|
~~~

不同范数回答的问题不同。L1 更关注坐标绝对值总量，L2 衡量欧氏长度，L-infinity 只看最大坐标。训练中常监控梯度的 L2 范数；检索中常用 L2 归一化；量化和数值稳定性分析有时更关心最大绝对值。

梯度裁剪可以用 L2 范数写成：

~~~math
g'=
g\cdot\min\left(1,\frac{c}{\lVert g\rVert_2}\right)
~~~

其中 `g` 是梯度向量，`c` 是允许的最大范数。若范数不超过 `c`，梯度保持不变；若超过 `c`，所有坐标按同一个比例缩小。它限制的是一次更新的整体尺度，不会自动修复错误的 loss、错误标签或错误的梯度方向。

### 1.2.4 归一化和零向量边界

L2 归一化为：

~~~math
\bar{x}=\frac{x}{\lVert x\rVert_2}
~~~

归一化后，非零向量的长度为 1。这样做会去掉长度信息，只保留方向。若一个 embedding 的长度包含“模型对输入的置信线索”或“文档质量线索”，归一化可能同时丢掉有用信息；所以归一化不是永远正确的默认选项，而是度量设计的一部分。

零向量不能被 L2 归一化，因为分母为零。工程代码要明确选择：拒绝零向量、加入很小的 epsilon，还是定义零向量与任何向量的相似度为某个约定值。不同选择会产生不同排序结果，不能悄悄依赖浮点异常。

### 1.2.5 Cosine similarity 与 dot product

余弦相似度定义为：

~~~math
\cos(x,y)=
\frac{x^{\top}y}{\lVert x\rVert_2\lVert y\rVert_2}
~~~

若 `x` 和 `y` 已经归一化，则：

~~~math
\bar{x}^{\top}\bar{y}=\cos(x,y)
~~~

因此，归一化向量上的最大内积检索，与最大 cosine similarity 检索给出相同排序。对归一化向量，平方欧氏距离还满足：

~~~math
\lVert\bar{x}-\bar{y}\rVert_2^2
=2-2\cos(x,y)
~~~

这说明 cosine 越大，归一化后的欧氏距离越小。但这个等价关系只适用于同一组已经归一化的向量。未归一化时，dot product、cosine 和 L2 距离可能产生完全不同的近邻。

更重要的边界是：几何相似度只描述向量空间中的关系，不自动证明文本事实相同。embedding 模型可能把主题相近但结论相反的句子映射得很近，检索系统还需要 rerank、权限过滤、版本控制和证据核验。

## 1.3 矩阵：把线性变换写成可组合的对象

### 1.3.1 矩阵的行、列和变换

矩阵可以看成数字表，也可以看成一个线性变换。设：

~~~math
A\in\mathbb{R}^{m\times n},
\qquad
x\in\mathbb{R}^{n}
~~~

则：

~~~math
y=Ax\in\mathbb{R}^{m}
~~~

矩阵 `A` 把 n 维输入映射到 m 维输出。按列看，`A` 的每一列是一个输入坐标基向量被映射后的结果；按行看，每一行会从输入中提取一个线性组合。两种视角在分析权重、表示方向和输出通道时都很有用。

大模型实现中也常见另一种约定：把 batch 中的向量按行放置，使用 `Y=XW`。此时：

~~~math
X\in\mathbb{R}^{B\times d_{\mathrm{in}}},
\qquad
W\in\mathbb{R}^{d_{\mathrm{in}}\times d_{\mathrm{out}}},
\qquad
Y=XW\in\mathbb{R}^{B\times d_{\mathrm{out}}}
~~~

只要始终说明向量是按行还是按列存放，`AX` 和 `XW` 都可以是清楚且正确的记号。很多实现错误并不是数学公式错了，而是阅读代码时把两种约定混在了一起。

### 1.3.2 矩阵乘法的 shape 规则

若：

~~~text
A: [m, n]
B: [n, p]
C = A @ B: [m, p]
~~~

中间维度 `n` 必须相等，输出保留外侧维度 `m` 和 `p`。元素级定义是：

~~~math
C_{ij}=\sum_{k=1}^{n}A_{ik}B_{kj}
~~~

这个求和下标 `k` 是 shape 推导的关键。它说明 `A` 的第 `i` 行和 `B` 的第 `j` 列做内积，输出位置 `(i,j)` 是一个标量。

用小例子计算：

~~~math
A=
\begin{bmatrix}
1&2&0\\
0&1&3
\end{bmatrix},
\qquad
B=
\begin{bmatrix}
1&0\\
2&1\\
1&4
\end{bmatrix}
~~~

得到：

~~~math
AB=
\begin{bmatrix}
5&2\\
5&13
\end{bmatrix}
~~~

`A` 是 `2 x 3`，`B` 是 `3 x 2`，所以结果是 `2 x 2`。手算这个例子时，不能把矩阵乘法误当成同位置相乘；同位置相乘属于逐元素乘法，shape 规则和语义都不同。

### 1.3.3 Linear layer 实际上通常是仿射变换

带偏置的全连接层写成：

~~~math
Y=XW+b
~~~

其中 `b` 的 shape 通常是 `d_out`，在 batch 维上广播。严格地说，`XW` 是线性变换，而加上偏置后是仿射变换，因为零输入不一定映射到零输出。

若 `X` 的 shape 是 `[B, d_in]`，`W` 是 `[d_in, d_out]`，`b` 是 `[d_out]`，那么每个输出通道对应 `W` 的一列和偏置的组合。可训练参数量为：

~~~math
N=d_{\mathrm{in}}d_{\mathrm{out}}+d_{\mathrm{out}}
~~~

如果忽略 bias，常见的参数量近似就是 `d_in * d_out`。这个近似适合粗略显存和容量估算，但在小层、低秩层或大量 bias 参数中，应该把偏置单独计入。

### 1.3.4 线性变换可以组合

两个没有偏置的线性层可以合并：

~~~math
(XW_1)W_2=X(W_1W_2)
~~~

这说明多次线性变换仍然是一个线性变换，矩阵乘法具有结合律，但一般不具有交换律：

~~~math
(AB)C=A(BC),
\qquad
AB\ne BA\ \text{通常成立}
~~~

在模型结构中，非线性激活、归一化、残差和 attention 使网络不再等价于一个大矩阵。若把两个线性层中间的激活删掉，模型表达能力会发生根本变化，而不是只减少一段代码。

## 1.4 Attention：相似度矩阵如何变成上下文表示

### 1.4.1 Q、K、V 来自三个投影

设输入序列的表示为 `X`。在单个 attention head 中，三个投影通常写成：

~~~math
Q=XW_Q,
\qquad
K=XW_K,
\qquad
V=XW_V
~~~

如果 `X` 是 `[B,T,d]`，多头实现通常把最后一维拆成 `H` 个 head，每个 head 的宽度为 `d_h`：

~~~math
Q,K,V\in\mathbb{R}^{B\times H\times T\times d_h}
~~~

`Q` 可以理解为“当前位置想查什么”，`K` 可以理解为“每个位置能被什么查询匹配”，`V` 则是匹配后真正要读取的内容。这是帮助初学者建立直觉的说法，不是把三个向量强行解释成数据库字段；它们都是由训练得到的连续表示。

### 1.4.2 为什么 score 是 `T x T`

对每个 query 位置和每个 key 位置做内积：

~~~math
S=QK^{\top}
\in\mathbb{R}^{B\times H\times T\times T}
~~~

最后两个维度的含义是：第一个 `T` 选择 query 位置，第二个 `T` 选择 key 位置。矩阵中的 `S[b,h,i,j]` 表示第 `i` 个 query head 对第 `j` 个 key 位置的匹配分数。

这是一个容易通过口头记忆却在代码中写错的地方。`K^T` 只转置用于矩阵乘法的最后两维；batch 和 head 维不应该被交换。若代码把 `[B,H,T,d_h]` 错转成 `[T,H,B,d_h]`，可能仍然得到某种可广播的数组，但语义已经错位。

### 1.4.3 为什么要除以 `sqrt(d_h)`

假设 query 和 key 的每个分量独立、均值为零、方差为 `sigma^2`，则单个乘积 `q_j k_j` 的方差约为 `sigma^4`，`d_h` 个乘积相加后，内积方差近似为：

~~~math
\mathrm{Var}(q^{\top}k)\approx d_h\sigma^4
~~~

因此 head dimension 增大时，未缩放的点积尺度会增大。softmax 接收很大的 logits 后容易变得过于尖锐，几乎只把概率放在一个位置，梯度也更容易变得不稳定。缩放后的 score 为：

~~~math
S=\frac{QK^{\top}}{\sqrt{d_h}}
~~~

这个除法不是为了让每一行直接变成概率；它只是在 softmax 之前控制分数尺度。温度、归一化、低精度和实际权重分布都会影响最终数值，所以这个方差推导是稳定性直觉，而不是对训练中每个张量的精确描述。

### 1.4.4 softmax 和加权求和

对每个 query 行做 softmax：

~~~math
A_{ij}=\frac{\exp(S_{ij})}{\sum_{j'=1}^{T}\exp(S_{ij'})}
~~~

于是每行满足：

~~~math
A_{ij}\ge 0,
\qquad
\sum_{j=1}^{T}A_{ij}=1
~~~

再用这些权重对 value 做加权求和：

~~~math
O=AV
\in\mathbb{R}^{B\times H\times T\times d_h}
~~~

初学者可以把一行 `A[i,:]` 看成第 `i` 个位置在所有 value 位置上的注意力分布；专家要注意，它是由当前 query、所有 key、mask、位置编码和数值精度共同决定的动态权重，不等同于可直接解释的人类“因果重要性”。

### 1.4.5 Causal mask 改变的是可见性，不是 shape

自回归语言模型不允许位置 `i` 读取未来位置 `j>i`。可以定义 mask：

~~~math
M_{ij}=
\begin{cases}
0,&j\le i\\
-\infty,&j>i
\end{cases}
~~~

然后：

~~~math
A=\mathrm{softmax}(S+M)
~~~

被屏蔽的位置在 softmax 后接近零，但 score 和 attention 的 shape 仍然是 `T x T`。mask 的语义是禁止某些边，不是把矩阵缩成三角形后再随意相乘。

padding mask、causal mask 和 loss mask 也不是同一个东西：padding mask 控制注意力是否读取填充位置，causal mask 控制时间方向，loss mask 控制哪些目标 token 参与损失。把它们混用，会让模型看见不该看见的 token，或让训练目标包含不应计分的区域。

如果某个 query 行被全部屏蔽，softmax 可能出现 `0/0`、`NaN` 或实现相关的特殊值。生产实现需要规定这种输入是否允许存在，并通过单元测试覆盖，而不能假设“softmax 总会返回合法分布”。

### 1.4.6 GQA 和 MQA 仍然可以用 shape 读懂

标准多头 attention 通常有 `H` 个 query head、`H` 个 key head 和 `H` 个 value head。Grouped-Query Attention 让多个 query head 共享一个 key/value head，设 query head 数为 `H_q`，KV head 数为 `H_kv`，每个 KV head 被 `g=H_q/H_kv` 个 query head 共享：

~~~math
Q\in\mathbb{R}^{B\times H_q\times T\times d_h},
\qquad
K,V\in\mathbb{R}^{B\times H_{kv}\times T\times d_h}
~~~

实现时需要把 KV head 按组映射到 query head。MQA 是 `H_kv=1` 的极端情况。共享 KV 可以减少 KV cache 的存储和带宽压力，但会改变可表达的匹配结构；它不是只改一个数字就必然保持质量不变。要判断收益，必须同时看 cache 容量、带宽、延迟和任务质量。

## 1.5 正交、投影与子空间

### 1.5.1 正交表示没有内积重叠

两个向量正交，当且仅当：

~~~math
x^{\top}y=0
~~~

在二维平面中，正交就是直角；在高维表示空间中，它更准确的含义是这两个方向的欧氏内积为零。它不自动表示两个语义概念完全独立，因为模型表示中的坐标系、度量和分布都可能发生变化。

若 `u` 是单位向量，任意向量 `x` 可以分解为沿 `u` 的分量和与 `u` 正交的残差：

~~~math
x=(x^{\top}u)u+r,
\qquad
u^{\top}r=0
~~~

这个分解是很多表示分析和误差分析的基础。

### 1.5.2 投影到一个方向

若 `u` 不一定是单位向量，`x` 在 `u` 张成直线上的投影为：

~~~math
\mathrm{proj}_{u}(x)=
\frac{x^{\top}u}{u^{\top}u}u
~~~

分母 `u^T u` 是 `u` 的平方长度。若漏掉它，公式只在 `u` 已经归一化时成立。

例如 `x=(3,4)`、`u=(1,0)`，投影为 `(3,0)`，残差为 `(0,4)`。如果把 `u` 换成 `(2,0)`，投影仍然是 `(3,0)`；方向相同但坐标尺度不同，不应改变投影结果。

### 1.5.3 投影到多维子空间

设矩阵 `U` 的列向量线性无关，子空间由这些列张成。投影矩阵为：

~~~math
P_U=U(U^{\top}U)^{-1}U^{\top}
~~~

投影结果为 `P_U x`。若 `U` 的列已经正交归一化，则 `U^T U=I`，公式简化为：

~~~math
P_U=UU^{\top}
~~~

这两个公式的适用条件很重要：列向量线性相关时，`U^T U` 不可逆，需要使用正交化或伪逆；数值计算中也不应直接手算矩阵逆，而应使用更稳定的分解和求解方法。

投影的残差 `x-P_Ux` 与子空间正交。对最小二乘问题而言，投影就是在给定子空间中寻找距离原向量最近的点。

### 1.5.4 PCA 为什么寻找“主要方向”

给定已经中心化的数据矩阵 `X`，每一行是一个样本，每一列是一个特征。协方差矩阵可以写成：

~~~math
C=\frac{1}{n}X^{\top}X
~~~

对单位方向 `u`，数据投影后的方差为：

~~~math
\mathrm{Var}(Xu)=u^{\top}Cu,
\qquad
\lVert u\rVert_2=1
~~~

最大化这个量会得到协方差矩阵最大特征值对应的特征向量。后续主成分要求与前面的方向正交，并依次解释剩余的最大方差。

初学者可以把 PCA 理解为“寻找一条投影轴，让数据在这条轴上展开得最开”；专家要注意，最大方差不等于最大任务信息。一个与标签无关的噪声方向也可能有很大方差，PCA 降维后的下游效果必须在独立验证数据上测量。

## 1.6 特征值与特征向量：线性变换的特殊方向

### 1.6.1 定义和几何直觉

对方阵 `A`，如果非零向量 `v` 满足：

~~~math
Av=\lambda v
~~~

则 `v` 是特征向量，`lambda` 是对应特征值。矩阵作用后，向量方向不变，只发生缩放；`lambda` 为负时还会发生方向翻转。

特征值问题只对方阵定义，因为 `Av` 必须和 `v` 处在同一个向量空间中。矩形矩阵可以做 SVD，但不能直接套用普通特征值定义。

### 1.6.2 对称矩阵和协方差矩阵

实对称矩阵有一组正交归一化的特征向量，并且特征值为实数。协方差矩阵还满足半正定性质：

~~~math
z^{\top}Cz\ge 0
~~~

所以协方差的特征值不会为负。PCA 正是利用这个结构，用最大特征值对应的方向解释最大投影方差。

对优化而言，Hessian 的特征值可以描述局部曲率：正特征值方向倾向于局部上弯，负特征值方向表示鞍点性质，接近零的方向较平坦。这是理解学习率、条件数和训练稳定性的数学入口，但实际神经网络 Hessian 往往巨大，通常需要近似估计。

### 1.6.3 特征值不是所有矩阵分析的唯一工具

若矩阵不是对称矩阵，特征向量可能不正交，甚至不能找到完整的特征向量基；若矩阵接近缺陷矩阵，数值计算也可能很敏感。处理任意矩形权重矩阵时，SVD 通常比特征值分解更自然，因为 SVD 可以把输入空间和输出空间分别处理。

因此，“主方向由特征值决定”需要附带条件：讨论的是哪个矩阵、是否对称、是否已经中心化、使用的是协方差还是原始数据矩阵。把 PCA、SVD 和任意权重矩阵的谱性质混成一句话，会掩盖这些条件。

## 1.7 SVD：旋转、缩放与低秩近似

### 1.7.1 SVD 的形状

任意实矩阵 `W` 都可以进行奇异值分解：

~~~math
W=U\Sigma V^{\top}
~~~

若 `W` 的 shape 是 `m x n`，完整分解中 `U` 是 `m x m`，`V` 是 `n x n`，`Sigma` 是 `m x n` 的对角形矩阵。其非零对角元素是按降序排列的奇异值：

~~~math
\sigma_1\ge\sigma_2\ge\cdots\ge 0
~~~

工程库还经常返回 reduced 或 thin SVD，矩阵形状会更小，但乘积仍然恢复原矩阵。阅读 API 时要看清返回的 `full_matrices`、截断 rank 和 dtype 选项，不能只看变量名。

### 1.7.2 SVD 的几何意义

把一个向量乘以 `W`，可以分成三步理解：

1. `V^T` 把输入坐标旋转或反射到一组特殊方向；
2. `Sigma` 沿这些方向分别缩放，缩放倍数是奇异值；
3. `U` 把结果旋转或反射到输出空间。

奇异值大的方向对输出变化贡献更大，奇异值小的方向可能被强烈压缩。这里的“重要”是相对于矩阵变换的平方能量而言，不等于对所有下游任务都重要。

### 1.7.3 rank-r 近似和能量比例

保留最大的 `r` 个奇异值，可以得到：

~~~math
W_r=U_r\Sigma_rV_r^{\top}
~~~

若奇异值已经按降序排列，`W_r` 是在 Frobenius 范数意义下的最佳 rank-r 近似。保留的平方能量比例为：

~~~math
\eta_r=
\frac{\sum_{i=1}^{r}\sigma_i^2}
{\sum_i\sigma_i^2}
~~~

例如奇异值为 `(5,2,0.5)`，前两个方向的能量比例为：

~~~math
\eta_2=\frac{5^2+2^2}{5^2+2^2+0.5^2}
=\frac{29}{29.25}
\approx0.99145
~~~

这说明前两个方向已经保留了大部分矩阵平方能量，但不说明每个输入、每个输出通道或每个任务的误差都只有约 1%。平均 Frobenius 误差与最坏样本误差不是一回事。

### 1.7.4 SVD、特征值分解和低秩不是同义词

对称半正定矩阵可以用特征值分解描述，其特征向量和特征值有清楚的几何意义；一般矩形矩阵更适合用 SVD。SVD 的奇异值平方与 `W^T W` 或 `W W^T` 的特征值相关，但两者作用的空间和矩阵形状不同。

低秩近似也不等于“删除小数字”。rank 是线性独立方向的数量；一个单独坐标很小的矩阵，经过旋转后可能仍然有重要的组合方向。低秩压缩需要基于分解、误差和下游任务验证，而不是按元素阈值随意清零。

## 1.8 LoRA：把权重更新限制在低秩子空间

### 1.8.1 全量更新和低秩更新

设线性层使用 `XW`，权重为 `W`。全参数微调直接学习：

~~~math
W_{\mathrm{new}}=W+\Delta W
~~~

LoRA 不把 `Delta W` 的每个元素都设为独立参数，而是令：

~~~math
\Delta W=AB
~~~

其中：

~~~math
A\in\mathbb{R}^{d_{\mathrm{in}}\times r},
\qquad
B\in\mathbb{R}^{r\times d_{\mathrm{out}}},
\qquad
r\ll\min(d_{\mathrm{in}},d_{\mathrm{out}})
~~~

乘积 `AB` 的 shape 仍然是 `[d_in,d_out]`，因此可以和原权重相加；但可训练参数量从 `d_in*d_out` 变成：

~~~math
N_{\mathrm{LoRA}}=r(d_{\mathrm{in}}+d_{\mathrm{out}})
~~~

这就是它节省参数的直接算术原因。

### 1.8.2 一个具体的参数量计算

若 `d_in=d_out=4096`，全量更新的参数量是：

~~~math
4096\times4096=16,777,216
~~~

当 `r=8` 时：

~~~math
8(4096+4096)=65,536
~~~

参数比例为：

~~~math
\rho=
\frac{65,536}{16,777,216}
=0.00390625
~~~

也就是约 `0.39%`。这个比例只描述可训练权重数量，不等同于训练显存、总 checkpoint 大小、通信量或推理延迟都下降到 `0.39%`。基础模型仍然需要加载，优化器状态、激活和数据供给也可能成为主要成本。

### 1.8.3 缩放和初始化

实际 LoRA 常对低秩更新加一个缩放系数：

~~~math
W_{\mathrm{new}}
=W+\frac{\alpha}{r}AB
~~~

`alpha` 控制 adapter 更新的整体尺度，`r` 的归一化让不同 rank 的量级更容易比较。不同实现可能使用不同约定，阅读代码时要确认缩放放在训练前、前向过程中还是合并权重时。

为了让训练开始时不改变基础模型，一个常见初始化方式是让其中一个因子初始为零，另一个因子使用随机初始化，于是初始 `AB=0`。这不是低秩数学定理，而是训练工程选择；初始化、学习率、目标层、rank 和数据都会影响最终行为。

### 1.8.4 LoRA 与 SVD 的关系和区别

SVD 是对已经存在的矩阵进行分解，能够根据奇异值选择近似方向；LoRA 是在训练时直接把更新参数化为两个小矩阵。LoRA 通常不会先对真实的完整更新矩阵做 SVD，因为完整更新本身并没有被显式存储。

二者共享“少数方向可能足够”的直觉，但不能据此断言某个任务一定适合小 rank。若任务需要修改很多相互独立的方向，rank 太小会形成表达瓶颈；若目标层和数据分布不合适，单纯提高 rank 也可能只是增加参数而没有修复问题。

### 1.8.5 低秩假设的失败方式

低秩适配可能失败于：

1. 任务需要广泛改变基础模型行为，而不是局部领域映射；
2. 选中的层不是产生目标行为的主要位置；
3. 训练数据太少，低 rank 只是在记忆样本；
4. rank 增大后出现过拟合或遗忘；
5. 多个 adapter 合并时更新方向相互冲突；
6. 量化、归一化或权重合并改变了原本的数值尺度。

因此，评估 LoRA 不能只报告可训练参数比例。至少要同时看目标任务质量、基础能力保留、不同 rank 的曲线、显存/吞吐、合并前后输出一致性和未覆盖数据。

## 1.9 Embedding 检索：向量几何如何进入 RAG

### 1.9.1 文档和查询进入同一空间

向量检索通常包含两个编码过程：

~~~text
document -> document embedding d_i
query    -> query embedding q
~~~

系统根据某个度量计算 `q` 与每个 `d_i` 的分数，再取前若干个候选。若使用 cosine similarity：

~~~math
s_i=\frac{q^{\top}d_i}{\lVert q\rVert_2\lVert d_i\rVert_2}
~~~

若先归一化，则可以直接计算 `q_bar^T d_bar`。这里的“同一空间”不是说查询和文档的原始文字相同，而是编码器训练出了一种可比较的表示坐标系。

### 1.9.2 相似度排序的教学例子

设查询向量为 `q=(3,4)`，三个候选分别为：

~~~math
d_1=(3,4),
\qquad
d_2=(4,3),
\qquad
d_3=(-3,4)
~~~

则：

~~~math
\cos(q,d_1)=1,
\qquad
\cos(q,d_2)=\frac{24}{25}=0.96,
\qquad
\cos(q,d_3)=\frac{7}{25}=0.28
~~~

在这个人为构造的空间中，`d_1` 与查询方向完全一致，`d_2` 很接近，`d_3` 只有部分方向一致。真实 embedding 的维度通常很高，候选之间还可能存在多个主题、语言和长度因素，所以不能从一个三维例子推出线上排序质量。

### 1.9.3 Exact search 和近似搜索

如果数据库有 `N` 个文档、每个向量维度为 `d`，最直接的精确检索要计算约 `N` 次向量相似度，粗略计算量随 `N*d` 增长。数据规模较大时，可以使用倒排、图索引或量化等近似最近邻方法，以牺牲一部分召回换取速度和存储效率。

这带来两个必须分开的指标：

1. embedding 度量本身是否把相关文档排在前面；
2. 索引搜索是否找回了度量应该找出的候选。

如果 exact search 的 Recall@k 已经很低，换一个 ANN 索引不能修复 embedding 语义；如果 exact search 很好而 ANN 召回下降，问题则可能在索引参数、量化或搜索预算。

### 1.9.4 相似不是证据，召回不是授权

RAG 系统不能把最高相似度文档直接当成事实来源。还要检查：

1. 文档版本是否最新；
2. 用户是否有权限读取；
3. 片段是否包含完整条件和否定词；
4. 多个文档之间是否存在冲突；
5. 模型回答是否真的被返回片段支持。

向量相似度是排序信号，不是权限判断、事实验证或引用支持的替代品。即使一个机密文档和查询向量最相似，也不能因为分数高就把它送给没有权限的用户。

## 1.10 数值稳定性：公式正确还不够

### 1.10.1 范数、内积和精度

高维向量的内积包含很多乘加操作。低精度计算可以提高吞吐，但也可能带来溢出、下溢、舍入累积和相似度排序改变。常见的工程策略包括：

1. 在更高精度中累加乘积；
2. 计算范数时避免先平方到溢出范围；
3. 对输入做范围检查或缩放；
4. 对排序边界样本使用更高精度复核；
5. 在目标硬件上实测，而不是只看理论 dtype。

“公式用 float32 写出来正确”并不表示使用 float16 或 bfloat16 时每个结果都相同。尤其在近邻分数非常接近的情况下，极小的舍入差异可能改变 top-k 边界。

### 1.10.2 Softmax 的稳定写法

直接计算 `exp(z_i)` 可能溢出。因为分子分母同时乘以同一个正数不改变比值，可以先减去最大 logit：

~~~math
\mathrm{softmax}(z_i)=
\frac{\exp(z_i-z_{\max})}
{\sum_j\exp(z_j-z_{\max})}
~~~

这不是近似，而是代数等价变形。它只能解决指数范围问题，不能解决全行被 mask、输入已经是 NaN 或低精度下的精度损失。

### 1.10.3 形状错误比数值错误更隐蔽

如果两个矩阵的 shape 完全不匹配，框架通常会立即报错；但广播可能让错误的张量得到一个“合法” shape。例如把 `[B,H,T,T]` 和 `[T,T]` 相加在数学上可能是有意设计的 mask 广播，也可能是误把 batch 维丢掉。判断它是否正确，需要回到每一维的语义。

一个可靠的 shape 检查至少应记录：

~~~text
batch dimension
sequence or spatial dimension
head dimension
feature dimension
padding and mask convention
dtype and device
~~~

shape 文档和断言不是多余的注释，而是模型模块之间的接口契约。

### 1.10.4 低秩误差与任务误差不是同一个量

矩阵近似的 Frobenius 误差为：

~~~math
\lVert W-W_r\rVert_F^2
=\sum_{i>r}\sigma_i^2
~~~

它描述所有元素平方误差的总和。若下游输入集中在某个被截断方向，任务输出可能大幅变化；若输入几乎不访问该方向，即使某些矩阵元素误差不小，任务影响也可能很小。

因此压缩实验要同时报告矩阵误差、输出误差和任务指标。只报一个奇异值能量比例，不能证明模型行为保持不变。

## 1.11 综合案例：从合同查询到有证据的回答

### 1.11.1 先区分向量检索和事实判断

假设“澄明”企业知识助手收到问题：“差旅住宿的报销上限是多少？”系统有三份候选片段：旧版制度、新版制度和一份员工经验总结。embedding 检索根据 query 与文档向量的相似度召回候选，但这个分数不能直接决定最终答案。

正确的处理链至少包含：

~~~text
query embedding
    -> candidate similarity ranking
    -> tenant and document permission filter
    -> version and effective-date filter
    -> rerank or claim extraction
    -> evidence-supported answer
~~~

如果旧版制度的文字与问题更相似，但新版制度已经生效，单纯 top-1 相似度会给出过期答案。若员工经验总结相似度很高，却没有正式制度来源，也不能把它当成具有同等证据等级的条款。

### 1.11.2 用数字看归一化的作用

设两个候选的方向完全相同，但长度分别为 1 和 10。它们的 cosine similarity 都是 1；未归一化 dot product 却相差十倍。若向量长度只反映文本长度或编码器激活尺度，dot product 可能偏向长文档；若长度还包含相关性强度，盲目归一化又可能丢掉信号。

这不是“cosine 一定优于 dot”的结论。应使用与 embedding 模型训练目标、索引实现和验证集一致的度量，并在长度、语言、领域和版本切片上检查排序。

### 1.11.3 证据链中的线性代数边界

线性代数可以解释：

1. 查询和文档如何被表示；
2. 候选如何按距离排序；
3. 低秩或量化为何改变计算成本；
4. attention 如何聚合上下文。

它不能单独解释：

1. 文档是否拥有真实世界的权威性；
2. 用户是否有权读取文档；
3. 生成答案是否忠实引用了片段；
4. 业务系统是否应该执行后续动作。

把数学空间中的“接近”直接等同于业务上的“正确”，是 RAG 系统中最常见的概念越界之一。

## 1.12 一个可运行的线性代数审计实验

下面的 Python 示例只使用标准库，演示五种关系：向量归一化、矩阵乘法 shape、scaled dot-product attention、奇异值平方能量和 LoRA 参数量。它不是高性能张量库，也没有实现完整 SVD；`singular_values` 是教学输入，用来演示截断能量的计算。

~~~python
from math import exp, sqrt


def matrix_shape(matrix):
    if not matrix:
        return (0, 0)
    columns = len(matrix[0])
    if columns == 0 or any(len(row) != columns for row in matrix):
        raise ValueError("matrix must be a non-empty rectangle")
    return len(matrix), columns


def require_vector(vector):
    if not vector:
        raise ValueError("vector must not be empty")
    if any(not isinstance(value, (int, float)) for value in vector):
        raise TypeError("vector values must be numeric")


def dot(left, right):
    require_vector(left)
    require_vector(right)
    if len(left) != len(right):
        raise ValueError("dot product requires equal lengths")
    return sum(a * b for a, b in zip(left, right))


def l2_norm(vector):
    return sqrt(dot(vector, vector))


def cosine(left, right):
    denominator = l2_norm(left) * l2_norm(right)
    if denominator == 0:
        raise ValueError("cosine is undefined for a zero vector")
    return dot(left, right) / denominator


def normalize(vector):
    norm = l2_norm(vector)
    if norm == 0:
        raise ValueError("cannot normalize a zero vector")
    return [value / norm for value in vector]


def matmul(left, right):
    left_rows, inner = matrix_shape(left)
    right_inner, right_columns = matrix_shape(right)
    if inner != right_inner:
        raise ValueError(
            f"incompatible shapes: {(left_rows, inner)} and "
            f"{(right_inner, right_columns)}"
        )
    return [
        [
            sum(left[row][k] * right[k][column] for k in range(inner))
            for column in range(right_columns)
        ]
        for row in range(left_rows)
    ]


def transpose(matrix):
    rows, columns = matrix_shape(matrix)
    return [
        [matrix[row][column] for row in range(rows)]
        for column in range(columns)
    ]


def softmax(row):
    require_vector(row)
    pivot = max(row)
    values = [exp(value - pivot) for value in row]
    total = sum(values)
    return [value / total for value in values]


def scaled_dot_product_attention(query, key, value):
    query_rows, head_dim = matrix_shape(query)
    key_rows, key_dim = matrix_shape(key)
    value_rows, value_dim = matrix_shape(value)
    if head_dim != key_dim:
        raise ValueError("query and key feature dimensions must match")
    if key_rows != value_rows:
        raise ValueError("key and value sequence lengths must match")

    raw_scores = matmul(query, transpose(key))
    scaled_scores = [
        [score / sqrt(head_dim) for score in row]
        for row in raw_scores
    ]
    weights = [softmax(row) for row in scaled_scores]
    context = matmul(weights, value)
    assert matrix_shape(context) == (query_rows, value_dim)
    return raw_scores, weights, context


def project(vector, direction):
    denominator = dot(direction, direction)
    if denominator == 0:
        raise ValueError("projection direction must be non-zero")
    scale = dot(vector, direction) / denominator
    return [scale * value for value in direction]


def lora_parameter_report(d_in, d_out, rank):
    if min(d_in, d_out, rank) <= 0:
        raise ValueError("dimensions and rank must be positive")
    full = d_in * d_out
    lora = rank * (d_in + d_out)
    return {
        "full": full,
        "lora": lora,
        "ratio": lora / full,
    }


x = [1.0, 2.0, 2.0]
y = [2.0, 0.0, 1.0]
x_normalized = normalize(x)
y_normalized = normalize(y)
normalized_distance_squared = sum(
    (left - right) ** 2
    for left, right in zip(x_normalized, y_normalized)
)

    query, key, value

    == round(2 - 2 * cosine(x, y), 3),

        abs(sum(row) - 1.0) < 1e-9 for row in weights
    ),
    "score_shape_ok": matrix_shape(raw_scores) == (3, 3),
    "context_shape_ok": matrix_shape(context) == (3, 2),
    "lora_saves_parameters": lora["lora"] < lora["full"],
}

print("dot=", round(dot(x, y), 3))

    "projection_on_x_axis=",

)
~~~

代码中有几个值得注意的设计：`matrix_shape` 拒绝不规则矩阵，`dot` 拒绝长度不同的向量，`cosine` 和 `normalize` 显式拒绝零向量，attention 检查 query/key/value 的关键维度。教学代码的目的不是复制生产 kernel，而是把每个数学前提变成可观察的程序契约。

## 1.13 练习：从算术走到判断

### 练习一：检查矩阵接口

给定 `X: [32,128,768]` 和 `W: [768,3072]`，说明如何把最后一维与 `W` 相乘，并写出输出 shape。再说明为什么 `W: [3072,768]` 不能在不转置的情况下直接使用。答案应同时说明 batch 和 sequence 维没有参与内积求和。

### 练习二：手算一次注意力

取两个 query、三个 key 和二维 value，先计算 `QK^T`，再除以 `sqrt(d_h)`，对每一行做稳定 softmax，最后得到 context。检查每一行权重和是否为 1，并说明 causal mask 加在哪里。

### 练习三：区分三种相似度

构造两个方向相同但长度不同的向量，以及两个长度相同但方向不同的向量。分别计算 dot product、cosine similarity 和 L2 distance，写出哪一种度量会受到长度影响。再讨论为什么这个数学结论不等于某个 embedding 模型的语义结论。

### 练习四：投影和残差

对 `x=(3,4)` 和方向 `u=(1,1)` 计算投影与残差，验证残差与 `u` 的内积为零。若把 `u` 改成 `(2,2)`，比较投影是否改变，并解释原因。

### 练习五：PCA 的条件

给出一个二维数据集，其中最大方差方向是噪声而不是标签方向。先中心化数据，再计算协方差矩阵的主方向，说明为什么“最大方差”不保证“最有预测价值”。最后写出训练集拟合、验证集投影的正确数据流程。

### 练习六：SVD 截断

给定奇异值 `(10,3,1,0.1)`，计算保留前一个、前两个和前三个奇异值时的平方能量比例。再说明为什么能量比例不能直接当作每个输入样本的任务准确率。

### 练习七：LoRA 参数和边界

对 `d_in=2048`、`d_out=4096`、`r=16` 计算全量更新和 LoRA 更新的参数量及比例。然后讨论 rank 从 16 提高到 64 可能带来的收益和代价，至少包括表达能力、显存、过拟合和基础能力保留。

### 练习八：定位检索退化

一个 RAG 系统的 exact Recall@10 为 `0.92`，换成 ANN 索引后变成 `0.74`；另一个系统 exact Recall@10 只有 `0.55`，ANN 仍为 `0.54`。分别判断更可能是索引问题还是 embedding/切分问题，并列出下一项最小验证实验。

### 练习九：找出 shape bug

阅读一段把 `[B,H,T,T]` 的 attention score 与 `[B,T,T]` mask 相加的伪代码。说明它何时可以通过广播得到正确结果，何时会把不同 head 的 mask 语义混在一起。再为 padding、causal 和 loss mask 各写一个独立的测试断言。

## 1.14 资料与证据边界

本章的基础定义优先参考大学课程和数值计算库文档；Transformer 与 LoRA 的结构和训练方法优先参考原始论文；向量索引的工程行为参考官方项目资料。不同资料支持的结论范围不同：

1. MIT 18.06 课程支持向量、矩阵、投影、特征值和线性变换的基础学习路径；
2. NumPy 与 PyTorch 文档支持 API 的 shape、dtype 和数值计算语义，不能替代对具体硬件的性能实测；
3. Transformer 论文支持 scaled dot-product attention 和多头结构的论文定义，不能自动支持所有后续模型的实现细节；
4. LoRA 论文支持低秩更新参数化及其论文实验条件，不能自动证明任意任务都适合某个 rank；
5. scikit-learn 的分解文档支持 PCA/SVD 工程接口入口，不能把默认求解器的结果当成所有矩阵上的理论保证；
6. Faiss 项目资料支持向量索引的使用和工程入口，不能替代目标数据分布上的 Recall、延迟和内存评估。

## 1.15 本章小结：用形状和几何读懂模型

线性代数为大模型提供了两条互补的阅读路径。

第一条是几何路径：向量有方向和尺度，内积衡量匹配，范数衡量大小，归一化改变度量，投影提取子空间分量，特征方向描述变换结构，SVD 把矩阵拆成旋转、缩放和旋转。

第二条是工程路径：每个向量和矩阵都有 shape，矩阵乘法有中间维度契约，attention 的 `T x T` 来自 query-key 两两匹配，LoRA 的参数量来自两个低秩因子的形状，embedding 检索的效果取决于度量、索引和数据分布共同作用。

真正可靠的理解还要再多走一步：相似度不是事实，低秩误差不是任务误差，参数比例不是总成本，mask 的合法 shape 不等于语义正确，论文中的结构也不等于线上服务的全部实现。能够同时说清公式、变量、shape、直觉、数值边界和证据边界，线性代数才真正成为理解 LLM 的工具。
