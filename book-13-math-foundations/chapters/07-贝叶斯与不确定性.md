# 第七章：贝叶斯与不确定性：从概率判断到可验证决策

大模型最容易制造的一种错觉，是把流畅表达误认为可靠判断。模型可以用完整的句子解释一个不存在的论文，也可以在没有检索到内部资料时生成一段听起来合理的制度说明。文字越顺，错误有时越难被发现。

因此，可靠性问题不能只问“模型会不会回答”。还要问三个更具体的问题：模型认为自己有多大把握，这个把握是否经过校准，系统在证据不足或风险过高时会采取什么动作。一个低风险的天气闲聊可以容忍不确定，一次合同付款、医疗用药或生产变更却不能只依靠语言上的自信。

贝叶斯方法提供了一种清晰的语言。先验表示在当前证据出现以前的判断，似然表示某个假设产生当前证据的可能性，后验表示结合证据之后的判断。这个公式本身不会自动让大模型变得正确，但它帮助我们把“好像更可信”拆成可以记录、比较和复查的量。

本章沿着一个企业合同助手的运行过程展开。助手先接收问题，再从带版本的文档中检索证据，必要时调用合同数据库，随后生成带引用的回答。我们会看到：模型 token 概率、整段回答的一致性、检索分数、工具返回值和人工审核意见都只是不同来源的信号，它们不能直接互换。最终系统需要把这些信号转成任务级概率、校准结果和 answer、verify、abstain 等可审计动作。

章节中的数值和事故均为教学构造。论文用于说明特定方法和实验条件，官方文档用于说明 API 或评估工具的语义；它们不构成任意模型、数据集或生产系统的性能承诺。

## 7.1 不确定性究竟在描述什么

### 7.1.1 从一句话到一个可检验的命题

用户问：“合同 A 的自动续期条款是否已经在 2025 年 7 月失效？”

模型可能给出：“是的，该条款已于 2025 年 7 月失效。”这句话至少包含三个不同层次：

1. 语言层：模型能否生成语法正确、符合对话风格的句子；
2. 命题层：句子中的“已失效”是否与事实和文档一致；
3. 任务层：回答是否满足用户的证据、版本、权限和格式要求。

模型的 token 概率主要描述第一层的局部生成倾向。用户真正关心的通常是第二层和第三层。一个回答即使每个 token 都很常见，也可能把旧版本条款误套到新版本合同上。

因此，分析不确定性之前，要先写清随机对象是什么。可以把一个任务的成功事件记为：

~~~math
Y_i
=\mathbf{1}
[\mathrm{content}_i=1
\land \mathrm{format}_i=1
\land \mathrm{evidence}_i=1
\land \mathrm{policy}_i=1]
~~~

这里的 Y_i 不是“句子看起来像不像预先写好的答案”，而是内容正确、格式满足协议、证据支持结论并且没有违反权限或安全策略时才取 1。相应的任务成功率为：

~~~math
\widehat{p}_{\mathrm{task}}
=\frac{1}{n}\sum_{i=1}^{n}Y_i
~~~

直观地说，它表示“这一整件事做成的比例”。严格分析还要明确：Y_i 的标签由谁判断，证据支持如何定义，失败是模型、检索、工具还是策略造成的，样本是否具有代表性。

这个比例要求评估样本数 `n > 0`，并且每个 `Y_i` 都已经按照同一版本的任务协议标注。`n=0` 时成功率不是 `0`，而是没有任务证据；如果一部分样本缺少标签，也不能把缺失标签默认为失败或成功后继续平均。实际系统还应保存标签来源、复核状态和时间范围，否则一个看似精确的小数可能只是对不一致标注的精确计算。

### 7.1.2 三种经常被混为一谈的概率

对于一个回答，至少有三种不同概率：

| 概率对象 | 它试图描述什么 | 常见来源 | 主要局限 |
| --- | --- | --- | --- |
| token 概率 | 下一段文字在语言模型中的相对可能性 | softmax、log probability | 高概率不等于事实正确 |
| 命题概率 | 某个明确事实为真的可能性 | 校准器、证据模型、verifier | 需要可靠标签和清晰命题 |
| 任务成功概率 | 整个端到端任务成功的可能性 | 任务评估、线上回放、分层统计 | 受到检索、工具、权限和协议影响 |

例如，模型可以很有把握地生成“合同已续期”这几个词，但如果它没有看到合同版本，命题概率就不应被直接设成很高。更不能因为句子生成得顺利，就推断数据库更新、通知发送和审计记录都已经完成。

### 7.1.3 不确定性不是一个越低越好的数

低熵、强一致性和高置信度有时是好信号，有时却表示模型在错误答案上非常稳定。高不确定性也不总是坏事：输入确实含糊、证据互相冲突或任务本来就有多个合理答案时，系统能够暴露不确定性，反而比武断回答更可靠。

本章会区分四件事：

1. 描述性信号：模型输出的概率、熵和多次采样结果；
2. 统计校准：信号是否与长期真实正确率匹配；
3. 证据强度：检索、工具或人工意见是否真正支持命题；
4. 决策动作：系统是回答、验证、澄清、转人工还是拒答。

把这四件事分开，才能避免“有一个分数，所以系统已经知道自己是否正确”的错误直觉。

## 7.2 贝叶斯公式：证据如何改变判断

### 7.2.1 先验、似然和后验

设 H 是一个假设，E 是观察到的证据。贝叶斯公式为：

~~~math
p(H\mid E)
=\frac{p(E\mid H)p(H)}{p(E)}
~~~

各个量的含义是：

- p(H)：在看到 E 之前，对 H 的先验概率；
- p(E|H)：如果 H 为真，观察到 E 的似然；
- p(H|E)：结合 E 之后，H 的后验概率；
- p(E)：证据出现的总概率，用于归一化。

分母可以由全概率公式展开。对 H 和非 H 两个互斥情况：

~~~math
p(H\mid E)
=\frac{p(E\mid H)p(H)}
{p(E\mid H)p(H)
+p(E\mid \neg H)p(\neg H)}
~~~

直观地说，公式就是“原来的信念乘以证据对它的支持程度，再把所有可能性归一化”。严格分析还要求先验和似然针对同一个命题、同一种证据和同一个目标分布定义，否则计算出来的数字没有清楚的解释。

二元公式的基本定义域是 `0 <= p(H) <= 1`、`0 <= p(E|H) <= 1` 和 `0 <= p(E|not H) <= 1`，并且证据的边际概率 `p(E) > 0`。若 `p(E)=0`，说明当前模型下这个证据不可能出现，后验不能通过除法得到；这不是把后验填成 `0` 或 `1` 就能解决的数值问题，而是模型、证据或数据定义需要重新检查。

### 7.2.2 用赔率看证据强弱

贝叶斯公式也可以写成赔率形式：

~~~math
\frac{p(H\mid E)}{p(\neg H\mid E)}
=
\frac{p(E\mid H)}{p(E\mid \neg H)}
\cdot
\frac{p(H)}{p(\neg H)}
~~~

其中：

~~~math
\mathrm{BF}_{H,E}
=\frac{p(E\mid H)}{p(E\mid \neg H)}
~~~

称为 Bayes factor，表示证据对 H 相对于非 H 的支持强度。如果 Bayes factor 大于 1，证据倾向于支持 H；如果小于 1，证据倾向于反对 H。赔率形式的好处是多个证据在条件独立假设成立时可以相乘，缺点是现实系统中证据往往并不独立。

赔率形式还要求先验赔率和似然比有定义：通常需要 `0 < p(H) < 1`，并且 `p(E|not H) > 0`。当先验恰好是 0 或 1 时，赔率落在边界，任何有限的证据都不能把它从边界拉回来；这反映的是先验已经排除了某种假设，而不是证据具有无限力量。

### 7.2.3 一个合同证据的数值例子

假设系统在没有查看当前合同以前，认为“条款已经失效”的概率为 0.70。现在检索到一份带签名的 2025 年 8 月变更单 E。若条款确实已经失效，看到这份变更单的概率估计为 0.90；若条款没有失效，出现同样变更单的概率为 0.20。

代入公式：

~~~math
p(H\mid E)
=\frac{0.90\times0.70}
{0.90\times0.70+0.20\times0.30}
=\frac{0.63}{0.69}
\approx0.913
~~~

证据把后验从 0.70 提升到约 0.913。这个计算并没有证明条款一定失效，因为 0.90 和 0.20 只是需要通过历史标注或领域专家估计的似然；如果变更单可能是伪造的、版本错了或检索系统把另一份合同拿了过来，似然也应随之调整。

### 7.2.4 弱证据也会降低后验

假设检索结果与 H 不一致。在 H 为真时看到这个结果的概率只有 0.20，在 H 为假时却有 0.70。则：

~~~math
p(H\mid E_{\mathrm{weak}})
=\frac{0.20\times0.70}
{0.20\times0.70+0.70\times0.30}
=0.40
~~~

“没有找到支持证据”和“找到了反对证据”不是同一件事。检索为空时，可能是文档不存在，也可能是召回失败；只有当检索过程的召回能力被验证过，空结果才更像负证据。

### 7.2.5 多份文档不能机械相乘

现实中三份文档可能都来自同一个数据库快照，或者相互复制。若把它们当作条件独立证据，便会重复计算同一信息：

~~~math
p(E_1,E_2\mid H)
\neq p(E_1\mid H)p(E_2\mid H)
~~~

除非独立性假设有依据。工程上可以对来源去重、按 artifact 归并、给同源证据设置相关性折扣，或者直接让评估数据学习“同源证据组合”的可靠性。贝叶斯公式要求诚实描述联合分布，而不是鼓励把证据条目数量当成可信度。

## 7.3 语言先验、外部证据与回答生成

### 7.3.1 语言模型先学到的是什么

自回归语言模型优化的是在上下文 x 下生成序列 y 的条件概率：

~~~math
p_\theta(y\mid x)
=\prod_{t=1}^{T}
p_\theta(y_t\mid x,y_{<t})
~~~

这个目标要求模型学习语言、格式、主题和大量世界知识的统计规律，但它没有天然的“当前命题已经被现实证据验证”的标记。模型可以知道什么样的句子通常出现在故障报告中，却不一定知道某一家公司真实发生了哪次故障。

于是出现一种常见现象：语言先验很强，事实证据很弱。模型看到“请总结 2025 年第三季度内部故障报告”这样的提示时，可能根据公开报告的写法续写一份完整总结，而不是指出自己没有访问内部报告。

### 7.3.2 RAG 不是自动的贝叶斯更新

把文档拼接到 prompt 中，并不等于后验已经正确更新。至少还要满足：

1. 检索到的文档确实属于当前租户和合同；
2. 文档版本和生效时间与问题匹配；
3. 文档中的句子包含支持命题的内容；
4. 模型能在长上下文中找到并正确使用该内容；
5. 引用范围与生成的具体主张对应；
6. 冲突文档、缺失文档和权限拒绝都有明确处理。

因此，系统应当把回答拆成命题和证据，而不是只保存一段最终文字。一个最小的证据记录可以包括：

| 字段 | 作用 |
| --- | --- |
| claim_id | 标识一个可以单独判断真假的主张 |
| source_id | 指向原始文档或工具返回的 artifact |
| version | 记录内容版本和生效时间 |
| span | 指向支持或反驳主张的具体片段 |
| relation | support、contradict、ambiguous 或 unrelated |
| permission | 说明当前调用者是否有权使用该证据 |
| checked_at | 记录证据被检索和核验的时间 |

这张表使“模型很自信”变成可追溯的问题：到底是哪一个主张，依据哪一段资料，资料是否过期，是否允许当前用户看到。

### 7.3.3 证据可靠性也需要建模

令 H 表示一个命题为真，E 表示检索到的支持片段，Q 表示来源质量、版本和权限检查通过。更实际的后验写法是：

~~~math
p(H\mid E,Q)
\propto
p(E,Q\mid H)p(H)
~~~

如果 Q 没有通过，文本即使内容相似，也不应作为同等强度的证据。权限是治理条件，不是可以被概率平均掉的软特征；当权限不满足时，系统应直接禁止使用或展示该证据。

## 7.4 MLE、MAP 与先验约束

### 7.4.1 最大似然只看数据

给定数据 D 和参数 theta，最大似然估计选择使数据最可能出现的参数：

~~~math
\theta_{\mathrm{MLE}}
=\arg\max_\theta p(D\mid\theta)
~~~

通常使用对数似然以便把乘法变成加法：

~~~math
\theta_{\mathrm{MLE}}
=\arg\min_\theta
-\log p(D\mid\theta)
~~~

在语言模型中，最大化序列似然对应最小化 next-token negative log-likelihood。它回答的是“哪组参数最能拟合观察到的数据”，并没有单独回答“哪组参数在新数据上最可靠”。

### 7.4.2 最大后验把先验加入目标

贝叶斯公式中与 theta 无关的 p(D) 可以在优化时省略：

~~~math
\theta_{\mathrm{MAP}}
=\arg\max_\theta p(\theta\mid D)
=\arg\max_\theta p(D\mid\theta)p(\theta)
~~~

取负对数：

~~~math
\theta_{\mathrm{MAP}}
=\arg\min_\theta
\left[-\log p(D\mid\theta)-\log p(\theta)\right]
~~~

如果先验是均值为 0 的高斯分布：

~~~math
p(\theta)
\propto
\exp\left(-\frac{\lambda}{2}\|\theta\|_2^2\right)
~~~

那么：

~~~math
-\log p(\theta)
=\frac{\lambda}{2}\|\theta\|_2^2+C
~~~

MAP 目标就具有 L2 正则形式：

~~~math
L_{\mathrm{MAP}}(\theta)
=L_{\mathrm{NLL}}(\theta)
+\frac{\lambda}{2}\|\theta\|_2^2
~~~

这个推导说明“正则化可以解释为先验”的数学联系，但不应把所有优化实现都简单等同为相同的贝叶斯模型。尤其是 AdamW 的 decoupled weight decay、参数分组、学习率 schedule 和非凸训练轨迹，都会影响实际结果。

### 7.4.3 一个均值估计的例子

假设观察到三个带噪声的测量值 2.4、2.0、1.6，噪声方差为 0.25。最大似然估计就是样本均值：

~~~math
\hat{\mu}_{\mathrm{MLE}}
=\frac{2.4+2.0+1.6}{3}
=2.0
~~~

如果先验认为真实均值更接近 0，先验均值为 0、先验方差为 1，则数据精度为 3/0.25=12，先验精度为 1/1=1。高斯共轭更新给出：

~~~math
\hat{\mu}_{\mathrm{MAP}}
=\frac{12\times2.0+1\times0}{12+1}
\approx1.846
~~~

MAP 没有说数据均值“错了”，而是在样本有限时把估计向先验收缩。样本越来越多，数据精度变大，先验的相对影响会减弱。

这个共轭例子要求观测集合非空，噪声方差 `sigma^2 > 0`，先验方差也严格大于零，且观测值和先验均值是有限数。零方差是退化模型，不能直接代入通常的精度 `1/sigma^2`；空观测集合也没有 MLE，不能用默认均值替代。

## 7.5 不确定性的来源：噪声、知识缺口与系统链路

### 7.5.1 Aleatoric uncertainty

Aleatoric uncertainty 指数据或任务本身带来的不确定性。例子包括：

- 用户说“把它改得更正式”，但没有说明受众；
- 一张低分辨率扫描件有多个可能的字符；
- 同一个开放问题存在多个都合理的答案；
- 标注员对边界案例无法达成一致。

这类不确定性通常不能只靠扩大模型消除。更合适的动作可能是澄清问题、给出条件化答案、保留多个候选，或者把任务定义改得更明确。

### 7.5.2 Epistemic uncertainty

Epistemic uncertainty 来自模型或系统知识不足。例子包括：

- 新版本法规不在模型训练范围内；
- 用户问题来自模型很少见的专业领域；
- 检索索引缺少目标文档；
- 任务需要超过模型能力的多步推理；
- 工具 schema 刚刚变更，模型没有见过。

这类不确定性可以通过新数据、检索、工具、验证器或人工反馈降低，但不一定能靠一句“请自信回答”解决。

### 7.5.3 端到端系统还有系统不确定性

在大模型产品中，还要单独记录系统不确定性。即使模型参数和问题都不变，检索服务可能超时，缓存可能命中旧版本，工具可能返回 UNKNOWN，权限服务也可能暂时不可用。它们不属于传统的模型 aleatoric 或 epistemic 分类，却直接决定端到端任务是否成功。

| 来源 | 典型症状 | 优先动作 |
| --- | --- | --- |
| 输入或标签歧义 | 多个答案都有合理解释 | 澄清、条件化回答、保留候选 |
| 模型知识不足 | 对新领域和新组合没有稳定能力 | 检索、工具、训练或拒答 |
| 证据缺失 | 检索为空或证据不支持主张 | 说明资料不足、补充检索 |
| 工具不确定 | 超时、部分成功、结果未知 | 保留 UNKNOWN，不编造成功 |
| 策略不确定 | 风险分级或权限判断未完成 | 转人工或延迟动作 |

分类的价值不在于给每次失败贴一个漂亮的标签，而在于让处理动作与原因相匹配。

## 7.6 Token 概率、熵与整段回答的置信度

### 7.6.1 Softmax 概率是什么

在位置 t，模型输出 logits z_t。温度为 T 时，token 概率可以写为：

~~~math
p_t(v)
=\frac{\exp(z_{t,v}/T)}
{\sum_{u\in V}\exp(z_{t,u}/T)}
~~~

V 是词表，T 控制分布的尖锐程度。T 较低时分布更集中，T 较高时分布更平坦。这个概率描述模型在当前上下文中倾向生成哪个 token，并不直接描述完整命题为真的概率。

通常要求词表 `V` 非空、温度 `T > 0` 且有限，logit 也应是有限数。`T=0` 不是普通除法可以处理的温度，而是需要另行定义的贪心极限；负温度会反转概率排序，不应在没有明确语义时传入 softmax。实现还应使用减去最大 logit 的数值稳定形式，避免指数溢出。

### 7.6.2 熵描述分布的分散程度

给定离散分布 p，预测熵为：

~~~math
H(p)
=-\sum_{v\in V}p(v)\log p(v)
~~~

熵高表示概率分布更分散，熵低表示模型集中偏好少数 token。对同一个问题，模型可能在句法上非常确定，却在事实内容上没有外部依据，所以低熵不能被解释成低事实风险。

熵公式要求 `p(v) >= 0` 且 `sum_v p(v)=1`，并且词表非空；零概率项按约定取 `0 log 0 = 0`。如果输入是未归一化权重，应先明确归一化再计算，不能把任意分数直接称为概率。全零向量和含负数的向量都没有离散概率分布的含义。

### 7.6.3 序列概率的长度偏差

一个答案 y=(y_1,\ldots,y_T) 的序列概率是：

~~~math
p_\theta(y\mid x)
=\prod_{t=1}^{T}
p_\theta(y_t\mid x,y_{<t})
~~~

由于许多小于 1 的数相乘，长答案的序列概率通常更小。工程上常用平均 log probability 或几何平均：

~~~math
\mathrm{conf}_{\mathrm{seq}}(y\mid x)
=\exp\left(
\frac{1}{T}
\sum_{t=1}^{T}\log p_\theta(y_t\mid x,y_{<t})
\right)
~~~

这个量便于比较不同长度答案，但它仍然是语言模型分数。它可能偏好熟悉、保守和短的表达，也可能因 prompt、tokenizer、温度和生成策略变化而变化。

这里要求序列长度 `T > 0`，并且被纳入平均的 token 概率满足 `0 < p_t <= 1`。若回答为空，平均 log probability 没有定义；若某个 token 概率为零，序列 log probability 为负无穷，不能继续把它当成普通有限置信度参与排序。实际实现通常在相同 tokenizer 和 mask 规则下比较候选，并明确是否排除结束符。

### 7.6.4 两个回答都可能高概率但都不可靠

如果一个错误事实在训练语料中被大量重复，模型可能用很高的 token 概率生成它。反过来，一个正确但罕见的答案可能获得较低的局部概率。概率高低要经过任务标签校准，才有机会被用作决策信号。

因此，保存 log probability 时至少要同时保存：

1. 计算的是哪些 token，是否排除了 prompt 和 padding；
2. 使用了什么 tokenizer、温度和解码策略；
3. 是 token 平均、序列总和还是结构化字段分数；
4. 置信度对应的任务标签如何定义；
5. 该信号在什么数据切片上校准过。

## 7.7 多次采样、一致性与模型分歧

### 7.7.1 Self-consistency 提供的是稳定性信号

对同一个问题采样 m 次，得到答案 a_1,\ldots,a_m。若把完全相同的字符串视为同一答案，最高频答案的占比为：

~~~math
\mathrm{share}(a^*)
=\frac{1}{m}\sum_{j=1}^{m}
\mathbf{1}[a_j=a^*]
~~~

答案分布的熵为：

~~~math
H(A)
=-\sum_a \hat p(a)\log\hat p(a)
~~~

最高频答案占比高、熵低，说明在当前采样设置下输出更稳定。它不能证明答案正确，因为模型可能稳定地重复同一个错误。

这里要求采样次数 `m > 0`，并且答案归并规则把每个采样映射到一个有限类别。若答案是连续文本，直接按字符串计数会产生许多只出现一次的类别；若先做语义聚类，则还要报告聚类器和人工抽检误差。熵的零概率项按约定取 `0 log 0 = 0`，但负的“概率”或未归一化的权重不能直接代入熵公式。

### 7.7.2 字符串一致不等于语义一致

“合同已失效”“该条款不再生效”和“续期权已终止”可能是不同字符串，却表达相近结论。另一方面，两个答案可能文字相似，但一个包含了相反的时间条件。实际评估应先做命题抽取或语义归并，再计算一致性。

语义熵方法试图把答案按含义而不是按表面字符串聚类。它更贴近事实判断，但聚类器本身也会犯错，且成本高于直接比较字符串。任何“语义一致”指标都要给出聚类规则、人工抽检和失败样本。

### 7.7.3 Ensemble disagreement

如果有多个模型、多个 checkpoint 或多个独立训练种子，可以比较它们的预测分布。一个简单的分歧度量是平均分布与各成员分布之间的 KL：

~~~math
\bar p
=\frac{1}{K}\sum_{k=1}^{K}p_k
~~~

~~~math
D_{\mathrm{ens}}
=\frac{1}{K}\sum_{k=1}^{K}
D_{\mathrm{KL}}(p_k\Vert\bar p)
~~~

分歧大说明模型族对问题的判断不稳定，可能暴露分布外样本或知识缺口。但如果所有成员共享同一训练数据、同一错误来源或同一提示，低分歧也可能只是共同偏差。

集合分歧的公式要求 `K > 0`，每个 `p_k` 都是在同一标签空间上的合法概率分布，并且平均分布 `bar p` 的支持集与 KL 的计算规则一致。若某个成员没有输出某个类别的概率，不能把缺失项静默当成零后声称它们可直接比较。

### 7.7.4 把一致性变成实验而不是口号

一次有意义的 self-consistency 实验至少要固定问题集、采样次数、温度、最大长度和答案归并规则，同时报告：

- 一致性与真实正确率的相关性；
- 高一致低正确的失败比例；
- 低一致但最终正确的比例；
- 不同任务和风险切片的差异；
- 额外采样带来的延迟和成本。

如果一致性不能改善校准或风险决策，就没有理由仅因为它看起来稳定而把它加入生产链路。

## 7.8 校准：置信度是否像概率

### 7.8.1 理想校准性质

设模型对输入 X 输出预测标签 Y_hat 和置信度 C。理想校准要求对任意置信度水平 r：

~~~math
p(Y=\hat Y\mid C=r)=r
~~~

实际数据中很难恰好观察到每个 r，因此通常把置信度划分成 B 个区间。第 b 个区间中的样本集合记为 S_b，平均置信度和准确率分别为：

~~~math
\mathrm{conf}(S_b)
=\frac{1}{|S_b|}\sum_{i\in S_b}c_i
~~~

~~~math
\mathrm{acc}(S_b)
=\frac{1}{|S_b|}\sum_{i\in S_b}y_i
~~~

可靠性图把两者画在一起。点落在对角线附近，表示该置信度区间大致符合真实正确率；点在对角线上方，表示模型偏保守；点在对角线下方，表示模型过度自信。

每个非空分箱才有平均置信度和准确率。空分箱不应被填成 0，也不应进入分箱平均；若整个校准集为空，可靠性图、ECE、Brier 和 NLL 都没有定义。分箱边界还应预先固定，例如把置信度恰好为 `1.0` 的样本放入最后一个分箱，避免边界样本被丢弃。

### 7.8.2 ECE、Brier 和 NLL

Expected Calibration Error 的常见估计为：

~~~math
\mathrm{ECE}
=\sum_{b=1}^{B}
\frac{|S_b|}{n}
\left|
\mathrm{acc}(S_b)-\mathrm{conf}(S_b)
\right|
~~~

ECE 越小通常表示分箱平均差距越小，但它依赖分箱数量、分箱方式和样本量。小 ECE 不等于模型的事实能力高，也不保证未测切片同样校准。

对于二元正确性标签 y_i 和预测概率 p_i，Brier score 为：

~~~math
\mathrm{Brier}
=\frac{1}{n}\sum_{i=1}^{n}(p_i-y_i)^2
~~~

Brier 同时惩罚概率偏离和错误方向；它是 proper scoring rule，在预测概率评估中很有用。对多类任务，需要使用多类扩展，并明确概率向量和标签编码。

还可以使用负对数似然：

~~~math
\mathrm{NLL}
=-\frac{1}{n}\sum_{i=1}^{n}
\log p_i(y_i)
~~~

NLL 会对“非常自信但错了”的预测施加较大惩罚。选择 ECE、Brier 或 NLL，要看目标是展示可解释校准、整体概率质量还是对极端错误敏感。

这些指标都要求校准集非空，即 `n > 0`；置信度应满足 `0 <= c_i <= 1`，正确性标签应按同一任务协议取 `0` 或 `1`。NLL 还要求被评价的真实标签概率严格大于零，否则对应项为正无穷。ECE 对分箱数量和边界敏感，Brier 与 NLL 的数值也不能脱离类别比例、标签质量和切片样本量单独解读。

### 7.8.3 校准不等于区分能力

模型可能把容易和困难样本排序得很好，却整体过度自信；也可能通过输出接近总体基准率的概率获得看似不错的校准，却无法区分正确和错误。区分能力、校准能力和任务收益是三个不同维度。

例如一个所有样本都输出 0.5 的二分类器，在类别比例接近 0.5 时可能不太过度自信，但它没有提供有用的排序。生产系统需要同时报告任务质量、校准和覆盖率。

### 7.8.4 温度缩放

对分类 logits z，可以在独立校准集上学习温度 T：

~~~math
p_T(y\mid x)
=\mathrm{softmax}\left(\frac{z(x)}{T}\right)
~~~

T 大于 1 会让分布变平，常用于缓解过度自信；T 小于 1 会让分布更尖锐。温度缩放只改变概率形状，不会改变 argmax 标签，因此它通常改善校准而不改变准确率。

关键约束是：T 必须在开发校准集上学习，不能看最终测试标签后再调。LLM 的开放式生成还需要决定校准对象是 token、整段答案、命题还是任务成功，不能把分类模型的温度缩放无条件套用到长文本。

## 7.9 Beta-Bernoulli：用后验表达可靠率

### 7.9.1 从成功失败记录开始

假设某个明确切片上的任务成功率为 q，观察到 s 次成功和 f 次失败。Beta 分布是二项成功率的共轭先验：

~~~math
q\sim\mathrm{Beta}(\alpha,\beta)
~~~

观察数据后：

~~~math
q\mid D
\sim\mathrm{Beta}(\alpha+s,\beta+f)
~~~

后验均值为：

~~~math
\mathbb{E}[q\mid D]
=\frac{\alpha+s}{\alpha+\beta+s+f}
~~~

当后验参数都大于 1 时，后验众数 MAP 为：

~~~math
q_{\mathrm{MAP}}
=\frac{\alpha+s-1}
{\alpha+\beta+s+f-2}
~~~

### 7.9.2 小样本为什么需要收缩

取均匀先验 Beta(2,2)，观察到 8 次成功、2 次失败，则后验是 Beta(10,4)：

~~~math
\mathbb{E}[q\mid D]
=\frac{10}{14}
\approx0.714
~~~

~~~math
q_{\mathrm{MAP}}
=\frac{9}{12}
=0.75
~~~

直接用 8/10 得到 0.8，但这会忽略小样本的不确定性和先验。如果先验选择不合理，后验也会被错误地拉动，所以实验必须记录 alpha 和 beta 的来源。

### 7.9.3 后验均值不是保证

Beta 后验可以进一步计算可信区间和下一次成功的后验预测概率。它表达的是在给定模型、数据和先验下的统计不确定性，不是系统在任何未来分布上的保证。发生时间漂移、用户变化或工具升级时，旧数据的权重需要重新评估。

对于多个用户、语言或风险等级，单一 q 往往不够。至少应分层记录：

- 低风险和高风险任务；
- 训练时间覆盖范围；
- 新旧文档版本；
- 召回成功和证据支持成功；
- 自动回答、验证后回答和人工处理。

如果把所有切片混在一起，整体后验可能掩盖一个关键小切片的灾难性失败。

## 7.10 幻觉：不支持的主张如何产生

### 7.10.1 先区分三类错误

“幻觉”经常被用来描述所有错误，但至少应该区分：

1. 事实错误：主张与可验证事实相矛盾；
2. 证据不足：主张可能为真，但当前系统没有支持它的资料；
3. 引用错配：引用存在，但引用内容不支持生成的主张。

这三类错误的处理不同。事实错误需要纠正知识或工具结果，证据不足需要降低断言强度或拒答，引用错配需要改进 claim 切分和引用绑定。

### 7.10.2 生成目标与事实目标并不相同

next-token 训练奖励在语料中生成合理的后续文本。SFT 可能让模型更熟悉完整回答的格式，偏好优化可能使回答更有帮助、更连贯或更礼貌。这些训练目标都可能提高可读性，却不会自动提供当前问题的事实验证。

当问题缺少外部证据时，模型可能把相关主题中最常见的模式拼接成一个具体答案。它不是“随机胡说”这么简单，而是在一个不适合事实判断的目标下完成了高概率续写。

### 7.10.3 用 claim 级别测量

设回答包含 M 个可验证主张，support_j 表示第 j 个主张是否被允许使用的证据支持，则证据支持率可以写为：

~~~math
\mathrm{SupportRate}
=\frac{1}{M}\sum_{j=1}^{M}
\mathbf{1}[\mathrm{support}_j=1]
~~~

如果不同主张风险不同，可以用加权版本：

~~~math
\mathrm{WeightedSupport}
=\frac{\sum_{j=1}^{M}w_j
\mathbf{1}[\mathrm{support}_j=1]}
{\sum_{j=1}^{M}w_j}
~~~

权重 w_j 可以反映金额、法律后果、个人隐私或安全影响。一个回答有九个普通主张被支持、一个付款金额主张没有证据时，平均支持率 90% 仍然不能说明它适合自动执行。

这两个比例都要求主张数 `M > 0`。若回答没有可验证主张，应记录为“不适用”或“没有可评估主张”，而不是把支持率设为 `0` 或 `1`。加权版本还要求 `w_j >= 0` 且总权重严格大于零；若所有权重都是零，风险没有被定义。权重改变的是业务决策中的重要性，不会把一个没有证据的主张变成已支持主张。

## 7.11 RAG 中的不确定性传播

### 7.11.1 检索链条不是一个分数

一个 RAG 回答至少经过以下环节：

1. 原始文档是否正确接入；
2. 解析是否保留了标题、表格、脚注和版本；
3. query 是否表达了用户真正的问题；
4. 检索是否召回相关证据；
5. reranker 是否保留关键片段；
6. 上下文是否被长度限制截断；
7. 生成模型是否理解了证据；
8. 引用是否绑定到正确主张；
9. 权限、时效和冲突检查是否完成。

任何一个环节出错，都可能让最终答案失败。检索相似度高只说明文本表面或向量关系较近，不等同于“这个片段支持答案”。

### 7.11.2 把召回和支持分开

检索 Recall@k 可以描述相关证据是否进入前 k 个结果：

~~~math
\mathrm{Recall@k}
=\frac{\#\{\text{问题的相关证据被 top-k 召回}\}}
{\#\{\text{问题的相关证据}\}}
~~~

引用支持率则描述生成的主张是否被所引用片段支持。两者可能出现不同组合：

Recall@k 的分母是该问题已知的相关证据数量，要求相关证据集合非空；如果标注者没有定义“相关证据”，就不能把召回率写成一个看似精确的数字。对一组问题求平均时，还要说明使用 macro average、micro average 还是按证据数加权。引用支持率同样要求被评估的主张数非零，空主张集合应标记为不适用。

| 召回 | 支持 | 解释 |
| --- | --- | --- |
| 低 | 低 | 证据根本没有进入上下文 |
| 高 | 低 | 找到了资料，但模型引用或推理错误 |
| 高 | 高 | 检索和证据使用都较好 |
| 低 | 高 | 可能是模型记忆或评估标签不完整，需要核查 |

最后一种情况尤其需要小心。模型在没有检索到证据时恰好答对，不能自动证明 RAG 工作正常。

### 7.11.3 证据冲突和版本优先级

当旧制度说“需要两级审批”，新制度说“金额低于一万元只需一级审批”时，系统不能把两段文字简单拼接。必须把版本、生效日期、适用范围和用户组织作为判断条件。

一个可解释的冲突处理记录应包含：

- 每个候选证据的版本和生效时间；
- 证据适用的组织、产品或合同范围；
- 支持、反驳和条件限定；
- 版本选择规则；
- 无法解决冲突时的回答动作。

如果没有足够信息确定适用版本，回答“当前资料不足以确定”比选择一段看起来更新的文字更诚实。

### 7.11.4 引用不是装饰

引用的最低要求不是“回答后面放一个链接”，而是读者能够从具体主张回到具体证据。评估时可以对每个 claim 检查：

1. 引用的 source 是否存在；
2. source 是否对当前用户可见；
3. 引用片段是否包含支持关系；
4. 时间和版本是否适用；
5. 生成内容是否超出了证据能支持的范围。

如果系统无法完成 claim 级绑定，应降低回答断言强度，而不是用统一的“资料来源”尾注掩盖证据缺口。

## 7.12 工具、验证器与 UNKNOWN

### 7.12.1 工具返回值是证据，不是神谕

调用数据库、计算器、审批系统或搜索 API，可以获得比模型记忆更直接的证据，但工具也可能：

- 超时；
- 返回旧缓存；
- 只返回部分结果；
- 因权限不足而省略字段；
- 成功接受请求，却没有完成后端动作；
- 返回格式合法但语义错误。

因此工具协议至少要区分 success、failure 和 unknown。网络请求收到了 200，不等于付款已经结算；写接口返回 request_id，也不等于后端状态已经成功。

### 7.12.2 用灵敏度和特异度理解验证器

假设验证器输出 E，H 表示答案正确。验证器的灵敏度和特异度分别为：

~~~math
\mathrm{sensitivity}
=p(E=1\mid H=1)
~~~

~~~math
\mathrm{specificity}
=p(E=0\mid H=0)
~~~

若先验正确率为 p(H)=0.70，验证器通过时 p(E=1|H)=0.90、p(E=1|not H)=0.20，则答案正确的后验是约 0.913。验证器通过并不代表 100% 正确，验证器失败也可能是工具误报。

验证器的误差应在和生产任务相似的金标集上测量。把一个未经校准的 LLM judge 当作绝对真值，只是把不确定性从生成模型转移到了评估器。

### 7.12.3 UNKNOWN 必须保留

如果工具超时后系统把结果改写成“操作失败”，它可能误导用户再次执行；如果改写成“操作成功”，则可能造成重复副作用。更安全的状态是 UNKNOWN，并根据操作的幂等性和查询能力决定下一步：

1. 对只读查询，可以重试或重新读取；
2. 对有副作用的写操作，先使用幂等键或状态查询确认；
3. 无法确认时，暂停后续动作并交给人工；
4. 对用户清楚说明“当前无法确认”，不编造最终状态。

不确定性在这里不是模型概率，而是外部世界状态的不可观测性。两者都需要进入系统状态机。

## 7.13 选择性预测：什么时候回答，什么时候停下来

### 7.13.1 覆盖率和选择性风险

设 c(x) 是置信度，阈值为 tau。系统只对 c(x)>=tau 的样本自动回答。覆盖率为：

~~~math
\mathrm{Coverage}(\tau)
=p(c(X)\ge\tau)
~~~

在被选择回答的样本上，选择性风险为：

~~~math
\mathrm{Risk}(\tau)
=\mathbb{E}
[L(X,Y)\mid c(X)\ge\tau]
~~~

提高阈值通常会降低覆盖率，但如果置信度经过校准，风险可能下降。生产系统不应只报告“自动回答样本的准确率”，还要报告拒答或转人工的比例，否则可以通过拒绝所有困难问题得到虚假的高分。

覆盖率是概率对象，经验估计要求总评估样本数 `n > 0`；选择性风险要求被选集合 `S_tau={i:c_i>=tau}` 非空。若没有任何样本达到阈值，覆盖率可以报告为 `0`，但选择性风险是未定义，不应填成 `0`。阈值 `tau` 也应明确是否允许等号，并限制在置信度的定义范围内。

### 7.13.2 Answer、verify 和 abstain

可以把动作写成一个最小决策规则：

~~~math
a(x)=
\begin{cases}
\mathrm{answer},
& c(x)\ge\tau_{\mathrm{answer}}
\land r(x)=\mathrm{low}\\
\mathrm{verify},
& c(x)\ge\tau_{\mathrm{verify}}
\land \left(r(x)\in\{\mathrm{medium},\mathrm{high}\}
\ \lor\ r(x)=\mathrm{low}\land c(x)<\tau_{\mathrm{answer}}\right)\\
\mathrm{abstain},
& c(x)<\tau_{\mathrm{verify}}
\end{cases}
~~~

c(x) 是经过校准的任务置信度，r(x) 是风险等级。高风险样本即使置信度高，也可能必须验证；低风险样本在置信度不足时可以先澄清，而不是直接拒绝。

为了让分支覆盖且不重叠，需要预先规定 `tau_answer >= tau_verify`，并把风险等级映射到有限集合。若中高风险样本的置信度低于 `tau_verify`，它们会进入 abstain；若低风险样本的置信度落在两个阈值之间，则进入 verify。现实系统还可以增加 clarify 分支，但必须把它的成本和成功标签纳入同一个决策表。

真实策略还需要加入证据状态、权限状态、工具健康度和副作用类型。阈值不是自然常数，应该在开发集上用错误成本、延迟和人工容量共同选择。

### 7.13.3 以成本而不是准确率选动作

设动作集合为 A，动作 a 的结果为 z，条件损失为 L(a,z|x)。期望损失为：

~~~math
\mathbb{E}[L(a,Z)\mid x]
=\sum_z p(z\mid x)L(a,z\mid x)
~~~

系统应选择期望损失最低且满足治理约束的动作：

~~~math
a^*(x)
=\arg\min_{a\in A}
\mathbb{E}[L(a,Z)\mid x]
~~~

验证有额外延迟和费用，拒答有用户体验成本，错误自动执行可能有很高的业务损失。把这些成本写出来，才能解释为什么高风险场景宁可多一次人工确认。

这里要求动作集合 `A` 非空，`p(z|x)` 是归一化的条件分布，且损失项在候选动作上可比较。若某个动作的副作用或治理条件未知，不能把它的期望损失默认为零；应先把该动作标记为不可用或 UNKNOWN。

## 7.14 Conformal prediction：覆盖率承诺的条件

### 7.14.1 从一个分数到一个预测集合

传统分类器只输出一个标签。Conformal prediction 可以根据校准样本构造预测集合 C(x)，在交换性等条件下给出覆盖率承诺：

~~~math
p\{Y\in C(X)\}
\ge 1-\alpha
~~~

其中 alpha 是允许的错误覆盖率。集合可能包含多个标签；在回归中也可以输出区间。它的核心价值是把“我希望覆盖 90% 的真实标签”转成可检查的有限样本程序。

通常要求 `0 <= alpha <= 1`，校准集非空，预测集合和标签空间可定义。覆盖率承诺是对交换性目标分布下的概率保证，不是对每一条样本的确定保证；当校准集为空、分位点索引不存在或数据分布明显改变时，公式不能被直接宣称成立。

### 7.14.2 非一致性分数和分位点

设校准样本的非一致性分数为 s_1,\ldots,s_m。选择适当的有限样本分位点 q_alpha，并定义：

~~~math
C(x)
=\{y:s(x,y)\le q_\alpha\}
~~~

如果数据满足方法所需的交换性，新的样本被集合覆盖的概率可以得到相应保证。分位点的具体索引要按样本量和有限样本校正规则实现，不能随意使用普通百分位数后宣称严格覆盖。

### 7.14.3 生成模型中的边界

开放式文本的标签空间巨大，直接为整段回答构造预测集合通常不可行。可以把 conformal 思想用于：

- 分类式路由；
- 风险等级；
- 检索文档是否足够；
- 结构化字段；
- 工具参数的区间或候选集；
- 经过定义的答案属性。

它不能自动保证一段自由文本事实正确。交换性在时间变化、用户变化、文档版本变化和攻击分布下也可能失效。因此报告 conformal 结果时必须说明校准集、目标分布、非一致性分数和覆盖率的适用范围。

## 7.15 LLM-as-a-Judge 也需要不确定性管理

### 7.15.1 Judge 是测量仪器

LLM judge 不是裁判意义上的绝对真理，而是一种测量仪器。它可能受到：

- 答案长度；
- 位置顺序；
- 语言和格式；
- 自我偏好；
- 评估 rubric 的歧义；
- 对事实细节缺少外部验证；
- 模型版本和温度。

因此 judge 输出的分数应与测量误差一起解释。一个稳定输出 4.2 分的 judge，不代表它和人类对高风险错误的判断一致。

### 7.15.2 建立人工金标准

校准 judge 时，先构造覆盖主要任务和失败类型的人工金标准。每条样本记录：

1. 任务和风险切片；
2. 人工标签及判定依据；
3. judge 的输入 prompt 和模型版本；
4. judge 的分数、理由和置信度；
5. 人工与 judge 的一致或分歧；
6. 分歧样本的复核结论。

对于 pairwise 评价，还应随机交换 A/B 顺序，检查位置偏差。对开放式回答，最好把总分拆成事实、完整性、证据、格式和安全等维度。

### 7.15.3 总体一致不代表关键切片可靠

如果 95% 的普通样本都很容易，judge 在这些样本上表现良好，仍可能在 5% 的高风险样本上完全失效。应分别报告总体、一致性、分歧率和高风险切片。必要时设置人工复核预算，优先抽取 judge 置信度低、模型与验证器分歧大、损失后果高的样本。

## 7.16 一个完整决策案例：合同助手的错误自信

### 7.16.1 事故经过

合同助手收到问题：“供应商 B 的自动续期是否已经取消？请给出合同条款和生效日期。”

系统先检索到旧版合同，旧版写着“每年自动续期”；新版变更单在另一个索引中，因为租户过滤配置错误没有被召回。模型随后生成：“自动续期已取消，生效日期为 2025 年 7 月 1 日”，并引用了旧版条款附近的一段文字。

这次失败不是一个单点问题：

1. 权限和版本过滤错误；
2. 检索没有召回变更单；
3. 生成模型没有检查旧版与新问题的时间关系；
4. 引用与主张不一致；
5. token 置信度没有经过任务级校准；
6. 系统把高风险合同结论当作普通问答直接返回。

### 7.16.2 把回答拆成证据链

正确的分析先列出命题：

| claim | 需要的证据 | 当前状态 |
| --- | --- | --- |
| 自动续期被取消 | 最新有效变更单或正文 | 未确认 |
| 生效日为 2025-07-01 | 包含该日期且适用供应商 B 的条款 | 未确认 |
| 旧版条款不再适用 | 版本关系和替代规则 | 冲突 |

系统应把旧版文档标记为 stale 或 conflicting，而不是因为它被召回就把它当作支持证据。若变更单无法读取，正确动作是说明当前资料不足，并请求授权或转交合同管理员。

### 7.16.3 修复后的决策

修复链路包括：

1. 检索前绑定租户、合同 ID 和版本时间范围；
2. 对同一 artifact 的版本做不可变记录；
3. 先判断证据是否支持 claim，再组织自然语言；
4. 对高风险合同结论强制查询最新版本；
5. 生成 claim 级引用和冲突提示；
6. 把工具超时、权限拒绝和版本冲突保留为 UNKNOWN；
7. 用人工标注的任务成功和证据支持数据校准置信度；
8. 记录自动回答、验证后回答和人工转交的覆盖率与风险。

### 7.16.4 教学实验结果

假设在 1,000 条历史合同问题上，旧系统自动回答覆盖率为 92%，任务成功率为 0.79，高风险错误率为 0.06。修复后自动回答覆盖率下降到 76%，但任务成功率上升到 0.88，高风险错误率下降到 0.015。这里的数字是教学构造，重点是取舍关系：系统少回答了一部分问题，却减少了未经证据支持的高代价回答。

如果只看自动回答子集的平均准确率，可能误以为系统变好了或变差了；必须同时报告 coverage、selective risk、验证成本和人工容量。

## 7.17 最小可运行的贝叶斯与校准实验

下面的 Python 示例只使用标准库。它把本章的几个概念放在同一个小实验中：二元 Bayes 更新、Beta-Bernoulli 可靠率、MLE 与 MAP、token 熵和多次采样一致性、ECE 与 Brier、选择性风险以及按风险分级的动作。示例中的标签和概率是教学构造，不是某个真实模型的测量结果。

~~~python
import math
from collections import Counter


def bayes_binary(prior_h, likelihood_e_given_h, likelihood_e_given_not_h):
    values = (prior_h, likelihood_e_given_h, likelihood_e_given_not_h)
    if not all(isinstance(value, (int, float)) and math.isfinite(value) for value in values):
        raise ValueError("Bayes inputs must be finite numbers")
    if not all(0 <= value <= 1 for value in values):
        raise ValueError("Bayes probabilities must be in [0, 1]")
    numerator = likelihood_e_given_h * prior_h
    denominator = numerator + likelihood_e_given_not_h * (1 - prior_h)
    if denominator <= 0:
        raise ValueError("evidence probability must be positive")
    return numerator / denominator


def beta_update(alpha, beta, successes, failures):
    values = (alpha, beta, successes, failures)
    if not all(isinstance(value, (int, float)) and math.isfinite(value) for value in values):
        raise ValueError("beta parameters and counts must be finite")
    if alpha <= 0 or beta <= 0 or successes < 0 or failures < 0:
        raise ValueError("alpha and beta must be positive; counts non-negative")
    post_alpha = alpha + successes
    post_beta = beta + failures
    mean = post_alpha / (post_alpha + post_beta)
    if post_alpha > 1 and post_beta > 1:
        map_estimate = (
            (post_alpha - 1)
            / (post_alpha + post_beta - 2)
        )
    else:
        map_estimate = None
    return {
        "alpha": post_alpha,
        "beta": post_beta,
        "mean": mean,
        "map": map_estimate,
    }


def gaussian_map_estimate(observations, noise_var, prior_mean, prior_var):
    if not observations:
        raise ValueError("observations and variances must be valid")
    if not all(isinstance(value, (int, float)) and math.isfinite(value) for value in observations):
        raise ValueError("observations must be finite numbers")
    if not all(
        isinstance(value, (int, float)) and math.isfinite(value)
        for value in (noise_var, prior_mean, prior_var)
    ):
        raise ValueError("Gaussian parameters must be finite")
    if noise_var <= 0 or prior_var <= 0:
        raise ValueError("noise_var and prior_var must be positive")
    sample_mean = sum(observations) / len(observations)
    mle = sample_mean
    data_precision = len(observations) / noise_var
    prior_precision = 1 / prior_var
    posterior_mean = (
        data_precision * sample_mean
        + prior_precision * prior_mean
    ) / (data_precision + prior_precision)
    return {"mle": mle, "map": posterior_mean}


def entropy(probabilities):
    if not probabilities:
        raise ValueError("probability list must not be empty")
    if not all(isinstance(value, (int, float)) and math.isfinite(value) for value in probabilities):
        raise ValueError("probabilities must be finite numbers")
    if any(value < 0 for value in probabilities):
        raise ValueError("probabilities must be non-negative")
    total = sum(probabilities)
    if total <= 0:
        raise ValueError("probabilities must have positive total")
    normalized = [p / total for p in probabilities if p > 0]
    return -sum(p * math.log(p) for p in normalized)


def self_consistency(answers):
    if not answers:
        raise ValueError("answers must not be empty")
    counts = Counter(answers)
    total = len(answers)
    probabilities = [count / total for count in counts.values()]
    top_answer, top_count = counts.most_common(1)[0]
    return {
        "top_answer": top_answer,
        "top_share": top_count / total,
        "entropy": entropy(probabilities),
    }


def calibration_report(records, num_bins=5):
    if not records or not isinstance(num_bins, int) or num_bins <= 0:
        raise ValueError("records and num_bins must be valid")
    buckets = [[] for _ in range(num_bins)]
    for confidence, correct in records:
        if (
            not isinstance(confidence, (int, float))
            or not math.isfinite(confidence)
            or not 0 <= confidence <= 1
            or correct not in (0, 1)
        ):
            raise ValueError("invalid confidence or correctness label")
        index = min(int(confidence * num_bins), num_bins - 1)
        buckets[index].append((confidence, correct))

    total = len(records)
    ece = 0.0
    summaries = []
    for index, bucket in enumerate(buckets):
        if not bucket:
            continue
        average_confidence = (
            sum(confidence for confidence, _ in bucket)
            / len(bucket)
        )
        accuracy = sum(correct for _, correct in bucket) / len(bucket)
        gap = abs(average_confidence - accuracy)
        ece += len(bucket) / total * gap
        summaries.append({
            "bin": f"{index / num_bins:.1f}-{(index + 1) / num_bins:.1f}",
            "n": len(bucket),
            "avg_conf": round(average_confidence, 3),
            "acc": round(accuracy, 3),
            "gap": round(gap, 3),
        })

    brier = sum(
        (confidence - correct) ** 2
        for confidence, correct in records
    ) / total
    return {
        "ece": ece,
        "brier": brier,
        "bins": summaries,
    }


def selective_metrics(records, threshold):
    if not records:
        raise ValueError("records must not be empty")
    if (
        not isinstance(threshold, (int, float))
        or not math.isfinite(threshold)
        or not 0 <= threshold <= 1
    ):
        raise ValueError("threshold must be a finite number in [0, 1]")
    for confidence, correct in records:
        if (
            not isinstance(confidence, (int, float))
            or not math.isfinite(confidence)
            or not 0 <= confidence <= 1
            or correct not in (0, 1)
        ):
            raise ValueError("invalid confidence or correctness label")
    selected = [
        (confidence, correct)
        for confidence, correct in records
        if confidence >= threshold
    ]
    if not selected:
        return {"coverage": 0.0, "risk": None}
    coverage = len(selected) / len(records)
    risk = sum(1 - correct for _, correct in selected) / len(selected)
    return {"coverage": coverage, "risk": risk}


def route_decision(posterior_reliable, risk, evidence_available):
    if not isinstance(posterior_reliable, (int, float)) or not math.isfinite(posterior_reliable):
        raise ValueError("posterior must be finite")
    if not 0 <= posterior_reliable <= 1:
        raise ValueError("posterior must be in [0, 1]")
    if risk not in {"low", "medium", "high"}:
        raise ValueError("risk must be low, medium, or high")
    if not isinstance(evidence_available, bool):
        raise TypeError("evidence_available must be boolean")
    if not evidence_available:
        return "abstain"
    if posterior_reliable < 0.60:
        return "abstain"
    if risk == "high":
        return "verify"
    return "answer"


prior_reliable = 0.70
posterior_strong = bayes_binary(prior_reliable, 0.90, 0.20)
posterior_weak = bayes_binary(prior_reliable, 0.20, 0.70)

beta_posterior = beta_update(
    alpha=2,
    beta=2,
    successes=8,
    failures=2,
)
point_estimates = gaussian_map_estimate(
    observations=[2.4, 2.0, 1.6],
    noise_var=0.25,
    prior_mean=0.0,
    prior_var=1.0,
)

token_distribution = [0.70, 0.20, 0.10]
sampled_answers = [
    "answer_a",
    "answer_a",
    "answer_b",
    "answer_a",
    "answer_c",
]
uncertainty = {
    "token_entropy": entropy(token_distribution),
    "self_consistency": self_consistency(sampled_answers),
}

calibration_records = [
    (0.95, 1), (0.90, 1), (0.85, 0), (0.80, 1),
    (0.75, 1), (0.70, 0), (0.65, 1), (0.60, 0),
    (0.55, 0), (0.40, 0),
]
calibration = calibration_report(calibration_records)
selective = selective_metrics(calibration_records, threshold=0.90)

decision_cases = {
    "low_risk_strong_evidence": route_decision(
        posterior_strong,
        risk="low",
        evidence_available=True,
    ),
    "high_risk_strong_evidence": route_decision(
        posterior_strong,
        risk="high",
        evidence_available=True,
    ),
    "low_risk_weak_evidence": route_decision(
        posterior_weak,
        risk="low",
        evidence_available=True,
    ),
    "low_risk_missing_evidence": route_decision(
        posterior_strong,
        risk="low",
        evidence_available=False,
    ),
}

checks = {
    "strong_evidence_raises_posterior": posterior_strong > prior_reliable,
    "weak_evidence_lowers_posterior": posterior_weak < prior_reliable,
    "map_shrinks_mle_toward_prior": (
        point_estimates["map"] < point_estimates["mle"]
    ),
    "calibration_detects_gap": calibration["ece"] > 0.10,
    "selective_risk_is_lower": (
        selective["risk"] < 0.30
    ),
    "high_risk_requires_verification": (
        decision_cases["high_risk_strong_evidence"] == "verify"
    ),
    "weak_evidence_abstains": (
        decision_cases["low_risk_weak_evidence"] == "abstain"
    ),
    "missing_evidence_abstains": (
        decision_cases["low_risk_missing_evidence"] == "abstain"
    ),
}

print(
    "bayes_update=",
    {
        "strong_evidence": round(posterior_strong, 3),
        "weak_evidence": round(posterior_weak, 3),
    },
)
print(
    "beta_posterior=",
    {key: round(value, 3) for key, value in beta_posterior.items()},
)
print(
    "mle_map=",
    {key: round(value, 3) for key, value in point_estimates.items()},
)
print(
    "uncertainty=",
    {
        "token_entropy": round(uncertainty["token_entropy"], 3),
        "top_share": round(
            uncertainty["self_consistency"]["top_share"],
            3,
        ),
        "sample_entropy": round(
            uncertainty["self_consistency"]["entropy"],
            3,
        ),
    },
)
print(
    "calibration=",
    {
        "ece": round(calibration["ece"], 3),
        "brier": round(calibration["brier"], 3),
    },
)
print(
    "selective=",
    {
        "coverage": round(selective["coverage"], 3),
        "risk": round(selective["risk"], 3),
    },
)
print("decision_cases=", decision_cases)
print("checks=", checks)
~~~

## 7.18 如何设计一套可复查的不确定性实验

### 7.18.1 先定义命题和标签

不要直接给整段回答标一个模糊的“可信”。先定义可判断的命题和任务：

- 答案中的事实是否正确；
- 每个事实是否有允许使用的证据；
- 引用是否支持对应主张；
- 工具动作是否真的完成；
- 输出是否满足结构协议；
- 错误是否达到需要人工介入的风险级别。

标签定义不清，任何校准指标都只是对标注噪声做精确计算。

### 7.18.2 固化数据和证据边界

校准集必须记录问题来源、用户分组、文档版本、训练截止时间、索引构建时间、工具版本和权限上下文。评估期间不应反复查看最终测试标签并据此修改 prompt 或阈值。

如果目标分布会随时间变化，应建立滚动评估集。旧校准温度和旧后验不能自动适用于新法规、新产品或新攻击方式。

### 7.18.3 同时测量排序、概率和动作

一份完整实验至少包含：

| 层次 | 问题 | 例子 |
| --- | --- | --- |
| 排序 | 哪些样本更可能正确 | AUROC、风险排序 |
| 概率 | 0.8 是否大约代表 80% 正确 | ECE、Brier、NLL |
| 覆盖 | 自动回答了多少样本 | coverage |
| 选择风险 | 自动回答子集错多少 | selective risk |
| 证据 | 主张是否有支持 | claim support rate |
| 系统动作 | 是否做了正确的验证或拒答 | action success |
| 资源代价 | 额外检索、验证和人工成本 | 延迟、费用、人工工时 |

只报告一个分数会隐藏动作层的失败。例如系统可以通过把所有问题都转人工获得零自动回答错误，但这不是一个有用的服务。

### 7.18.4 做分层和配对分析

至少按以下因素切片：

- 低、中、高风险；
- 有证据、证据冲突、无证据；
- 旧版本、新版本和时间外数据；
- 短答案、长答案和多轮对话；
- 普通用户、专业用户和不同语言；
- 模型直接回答、RAG 回答和工具验证回答。

比较两个版本时，尽可能对同一批问题做配对评估，并保存每条样本的动作变化。总体成功率上升，可能是高风险样本被全部转人工；这对风险是好事，对覆盖率却有代价，必须同时呈现。

## 7.19 练习：把不确定性变成可计算对象

### 练习一：后验更新

某类合同问题的先验正确率为 0.6。一个验证器在答案正确时以 0.85 的概率通过，在答案错误时以 0.25 的概率通过。计算验证器通过后的后验正确率，并解释先验变化会如何影响结果。

### 练习二：相关证据

构造三份看似独立、实际上都来自同一网页复制链的文档。说明为什么不能直接把三份似然相乘，并设计一种记录来源相关性的方式。

### 练习三：MLE 与 MAP

用一个高斯观测模型推导均值的 MLE 和 MAP。改变观测样本量，观察先验对后验的影响何时变小。

### 练习四：三种概率

给出一个 token 平均 log probability 很高、但事实错误的例子；再给出一个 token 概率一般、但经过工具验证后任务成功的例子。说明三种概率对象分别是什么。

### 练习五：自洽性

为同一个数学问题采样十次，设计字符串归并和语义归并两种一致性指标。列出至少两种“高一致但错误”的可能原因。

### 练习六：校准实验

给出二十条 confidence 和 correctness 记录，分别计算 ECE、Brier 和 NLL。改变分箱数，观察 ECE 为什么会变化。

### 练习七：温度缩放

在开发集上学习一个温度参数，比较缩放前后的可靠性图和 NLL。说明为什么不能用最终测试集学习温度。

### 练习八：Beta 后验

对两个风险切片分别使用 Beta(2,2) 先验。一个切片有 8/10 成功，另一个有 80/100 成功。比较后验均值和不确定性，说明为什么样本量也必须报告。

### 练习九：RAG 证据链

设计五个问题，分别覆盖召回失败、证据冲突、引用错配、证据充分和无权限访问。为每个问题定义 claim、source、relation 和动作。

### 练习十：选择性预测

给定十个样本的置信度和正确性，计算阈值从 0.5 到 0.9 时的 coverage 与 selective risk。画出风险覆盖率曲线，并说明拒答成本如何改变阈值选择。

### 练习十一：Conformal prediction

为一个三分类任务设计非一致性分数和校准集。说明交换性假设可能因时间漂移和用户分组而失效，并记录一个覆盖率不能外推的场景。

### 练习十二：高风险决策

为合同付款、普通知识问答和生产配置变更分别定义 answer、verify、abstain 的损失。计算在不同置信度和证据状态下的最小期望损失动作。

## 7.20 资料与证据边界

本章的贝叶斯公式、Beta-Bernoulli 和 MAP 推导属于概率统计基础；校准、预测不确定性、选择性预测和生成模型不确定性则依赖特定论文、数据和假设。资料入口如下：

1. scikit-learn 的概率校准文档用于核对 calibration curve、CalibratedClassifierCV 等 API 和评估语义；
2. Guo 等的 On Calibration of Modern Neural Networks 研究温度缩放和现代神经网络校准现象，实验对象不是任意 LLM；
3. Gal 与 Ghahramani 的 Dropout as a Bayesian Approximation 说明 dropout 与近似贝叶斯推断的联系，近似假设不能被忽略；
4. Lakshminarayanan 等的 Deep Ensembles 研究用模型集合估计预测不确定性，额外模型成本和相关错误仍需评估；
5. Kuhn 等的 Semantic Entropy 研究按语义而非字符串分析语言模型输出不确定性，语义聚类和任务标签仍会影响结论；
6. Geifman 与 El-Yaniv 的 selective classification 研究覆盖率和选择性风险，拒答策略不能只报告被选择子集的准确率；
7. Angelopoulos 与 Bates 的 conformal prediction 教程说明交换性、有限样本覆盖和预测集合的关系，不保证开放式文本事实正确；
8. REALM、DPR 等检索增强研究说明外部检索如何进入模型系统，但检索到文档不等于生成主张得到支持；
9. LLM-as-a-judge 相关研究揭示位置、长度和自我偏好等评估偏差，judge 需要人工金标准和切片核验。

## 7.21 把不确定性写进系统

贝叶斯方法首先教会我们区分先验、证据和后验。对于大模型，这意味着不能把模型已有的语言模式当成当前问题的事实依据。检索、工具和人工意见只有在来源、版本、权限和支持关系都明确时，才具有可解释的证据价值。

token 概率、熵和多次采样一致性可以提供信号，却不是正确性的证明。它们要在明确的任务标签上做校准，并同时报告 ECE、Brier、NLL、覆盖率和选择性风险。Beta 后验能表达小样本可靠率的不确定性，MAP 能说明先验如何影响有限数据下的估计，但二者都不能代替目标分布上的复测。

RAG 的关键不是“检索到文本”，而是每个主张是否得到适用证据支持；工具的关键不是“请求返回成功”，而是外部状态是否真正可确认。证据缺失、版本冲突、权限拒绝和工具超时都应保留为可见状态。

最后，可靠系统不追求在所有问题上都自动回答。它根据任务风险、证据状态、校准置信度和动作成本选择回答、验证、澄清、转人工或拒答。能够在不知道时停下来，并且能说明为什么停下来，是模型能力进入真实系统后不可缺少的一部分。
