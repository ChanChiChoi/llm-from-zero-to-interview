# 第六章：统计学习与泛化：从训练分数到可迁移能力

统计学习研究一个朴素却很难的问题：模型在已经见过的数据上表现很好，为什么有时能在新数据上继续工作，有时却一换表述、一换用户或一换文档就失效？

这个问题在大模型系统里反复出现。预训练 loss 下降，不代表模型学到了可迁移的规律；SFT 训练集上的格式通过率上升，不代表真实用户会得到稳定答案；DPO 的偏好胜率提升，不代表过度拒答和基础能力回归没有变坏；RAG 在固定文档和固定问题上表现很好，不代表换一批文档、换权限或换时间版本后仍然可靠。

初学者可以把“泛化”理解成从样本走向新样本的能力。专家则需要把它拆成几个不同的问题：目标分布是什么，训练集如何抽样，验证集是否被反复使用，测试集是否污染，模型是在记忆字符串还是学习结构，线上请求和离线评测有哪些分布差异，以及一次质量提升是否只是评估协议改变造成的。

本章先建立统计学习的风险语言，再讨论数据划分、交叉验证、偏差方差、过拟合、正则化和过参数化。之后把这些概念放进大模型，分别分析记忆、训练数据重复、benchmark contamination、分布外泛化和组合泛化。最后用一个零依赖 Python 审计实验把训练/验证/测试差距、early stopping、分布偏移和 exact overlap 放在同一个可运行例子里。

章节中的数值例子是教学构造，不代表某个真实模型的性能承诺。论文和官方文档用于说明方法定义或 API 语义；真实系统结论仍需保存模型、数据、代码、硬件和评估协议后复测。

## 6.1 泛化要回答的到底是什么

### 6.1.1 从已见样本到目标分布

设输入为 x，标签或目标输出为 y，模型为 f，损失函数为 ell。训练集只是一组有限样本：

~~~math
S=\{(x_i,y_i)\}_{i=1}^{n}
~~~

泛化关心的不是模型能否背下这 n 个样本，而是它在目标分布中继续完成任务的表现。目标分布可以是未来用户请求、未来时间段的文档、未参与训练的实体组合，或者某个明确规定的安全测试分布。

因此，“在测试集上表现好”只是一个证据，不是泛化的定义。测试集本身也只是从某个分布抽出的有限样本，而且一旦被反复用于调 prompt、改数据或挑 checkpoint，它就不再是完全独立的最终证据。

### 6.1.2 大模型里的几种泛化

大模型中的泛化至少有几种不同形式：

1. 表述泛化：问题换一种说法，模型仍能完成相同任务；
2. 实体泛化：把训练中见过的关系迁移到新实体；
3. 组合泛化：把已学到的组件组合到此前没见过的结构；
4. 时间泛化：面对较新的文档、事实或用户习惯仍保持有效；
5. 领域泛化：从通用语料迁移到专业领域，或从一个领域迁移到另一个领域；
6. 工具泛化：工具 schema、返回格式或环境发生变化时，调用仍然正确；
7. 行为泛化：换用户、语言、长度或风险场景后，帮助性和安全边界仍稳定。

这些能力可以彼此分离。模型可能擅长同义改写，却不擅长新实体组合；可能在短文本上泛化，却在长上下文中退化；可能能回答知识问题，却不能在新工具环境中遵守协议。因此评估时不能用一个平均分代表所有泛化。

### 6.1.3 训练集分数为什么不够

训练集分数高只说明优化过程找到了一个能解释或拟合训练样本的参数。它无法单独排除：

- 样本重复导致的记忆；
- 标签或答案泄漏；
- 评估集与训练集的近重复；
- 模型只学会了模板表面；
- 指标没有覆盖真实任务；
- 线上系统的检索、权限、工具或解码链路出错。

成熟的分析会把“模型学得好不好”和“我们测得准不准”分开。前者是学习问题，后者是数据和实验问题；两者都可能让训练分数与真实效果脱钩。

## 6.2 真实风险、经验风险和泛化差距

### 6.2.1 真实风险

如果目标数据分布为 P，模型预测为 f，真实风险或期望风险定义为：

~~~math
R_P(f)=\mathbb{E}_{(x,y)\sim P}
[\ell(f(x),y)]
~~~

P 是未来真实样本的联合分布，ell 是损失函数。分类任务可以使用 0-1 loss，语言模型可以使用 token-level negative log-likelihood，结构化任务也可以使用格式失败、字段错误或任务失败构成的组合损失。

真实风险是目标，但通常不能直接计算，因为我们看不到完整的未来分布。我们只能通过有限样本估计它，并明确这个样本来自哪里。

### 6.2.2 经验风险

在训练集 S 上计算的平均损失是经验风险：

~~~math
\widehat{R}_{S}(f)
=\frac{1}{n}\sum_{i=1}^{n}
\ell(f(x_i),y_i)
~~~

经验风险最小化（ERM）写成：

~~~math
\widehat{f}
\in\arg\min_{f\in\mathcal{F}}
\widehat{R}_{S}(f)
~~~

这里 F 是模型假设空间。深度学习中通常还会受到优化算法、初始化、正则化和训练时间影响，所以实际得到的是某个训练过程产生的参数，而不是抽象集合中任意一个全局最优解。

大语言模型常把 token 级损失按有效 token 汇总：

~~~math
\widehat{R}_{S}(f)
=\frac{\sum_{i=1}^{N}w_i\ell_i}
{\sum_{i=1}^{N}w_i}
~~~

w_i 可以表示有效 token mask。若直接把不同长度样本的平均 loss 再做不加权平均，长短样本对结果的贡献可能与“按 token 平均”不同。比较两个训练 run 时，必须确认 loss reduction、padding、ignore label 和 token 数口径一致。

### 6.2.3 泛化差距不是完整泛化误差

用独立验证集近似目标风险时，常观察：

~~~math
G_{\mathrm{val}}
=\widehat{R}_{\mathrm{val}}(f)
-\widehat{R}_{\mathrm{train}}(f)
~~~

如果指标是越大越好的分数，则可写成：

~~~math
G_{\mathrm{score}}
=S_{\mathrm{train}}(f)-S_{\mathrm{val}}(f)
~~~

这个差距是诊断信号，不是一个自动判断模型好坏的阈值。训练和验证都可能很差，说明模型没有学到目标；两者都很好，可能说明任务简单，也可能说明数据泄漏；验证很好而线上很差，则要检查分布和链路。

更重要的是，验证集被用于选择超参数、checkpoint、prompt 或数据版本后，模型选择过程已经依赖验证集。此时报告的验证分数会有选择偏差，不能把它当作完全独立的泛化估计。最终测试集或隐藏评测集应在选择过程结束后再使用。

### 6.2.4 风险分解的限制

经验风险和真实风险之间的差距受到样本量、样本依赖、假设空间复杂度、数据噪声和选择过程影响。经典学习理论可以给出某些条件下的上界，但上界往往很松，不能直接预测一个具体 LLM 的真实分数。

实际工作中更有用的做法，是保存风险估计的来源和限制：

| 估计对象 | 样本来源 | 能回答的问题 | 不能自动回答的问题 |
| --- | --- | --- | --- |
| 训练风险 | 参与优化的数据 | 目标是否被拟合 | 是否能迁移 |
| 验证风险 | 开发期间保留的数据 | 配置如何比较 | 是否未被选择过程污染 |
| 最终测试风险 | 结束后才使用的数据 | 一次相对独立的报告 | 线上所有场景是否有效 |
| 线上抽样风险 | 真实请求或回放 | 目标业务的部分表现 | 未出现的长尾风险 |
| 隐藏/动态评估风险 | 未公开或新生成样本 | 降低记忆和调参污染 | 未来全部分布 |

## 6.3 数据划分：先保证比较有意义

### 6.3.1 随机切分的隐含假设

随机 train/validation/test split 隐含一个重要假设：样本可以近似看作从同一目标分布独立抽样。如果同一个用户、同一篇文档、同一段代码或同一条对话的相邻片段同时出现在不同集合，样本之间就不再独立。

例如把一份长合同按 chunk 随机切分，训练集可能包含第 1、3、5 段，验证集包含第 2、4 段。模型或检索系统可能利用文档风格、重复条款甚至直接记忆来获得高分。这不是模型在新合同上的泛化。

### 6.3.2 按组切分

如果多个样本共享用户、文档、项目、仓库、作者或时间窗口，应先定义 group，再按 group 切分。一个 group 只能属于一个评估集合，或者按任务目标明确设计跨集合关系。

常见 group 包括：

- 同一个用户的所有对话；
- 同一份原始文档及其所有 chunk；
- 同一个代码仓库的文件和 issue；
- 同一个视频或音频的不同片段；
- 同一个模板生成的样本；
- 同一实体的不同问法。

按组切分会减少可用样本量，但通常能换来更可信的评估。若任务目标本来就是同一文档内的检索，应该把“允许共享文档”和“要求跨文档泛化”分别定义成不同评估设置，而不是含糊地使用一个随机切分。

### 6.3.3 时间切分和版本切分

时间敏感任务适合使用时间切分：

~~~math
S_{\mathrm{train}}<S_{\mathrm{val}}<S_{\mathrm{test}}
~~~

符号表示训练数据时间早于验证数据，验证数据早于最终测试数据。这样可以模拟未来请求，但必须检查未来数据是否被回灌到训练集、搜索索引或人工开发记录中。

文档问答还需要按版本切分。若测试问题针对新版本文档，而训练集包含旧版本相同条款，结果可能同时包含迁移能力和版本记忆。评估表应记录文档版本、发布日期、索引构建时间和模型训练截止时间。

### 6.3.4 分层切分与长尾

当标签或任务类型严重不均衡时，完全随机切分可能让某些稀有类别只出现在一个集合。可以按任务、语言、风险级别、长度和来源做分层，但分层键不能泄漏答案。

分层不是让每个集合都长得完全一样。若要测试分布外能力，验证集或测试集可以有意改变某个因素，但必须把这种变化写进实验目标。把 OOD 集混入普通平均分，会掩盖模型在关键新分布上的失败。

### 6.3.5 数据切分的先后顺序

一个较稳妥的顺序是：

1. 固化原始 artifact、来源和时间；
2. 定义 group、版本和目标分布；
3. 按 group 或时间切分；
4. 在每个集合内部做去重和质量检查；
5. 检查集合之间的 exact/near duplicate；
6. 生成训练、开发和最终评估视图；
7. 锁定最终评估集合后再开始大量调参。

如果先把所有文本混在一起做近重复清洗，再随机切分，可能无意中使用了测试集信息决定训练样本；是否构成严重泄漏取决于清洗规则和流程，但至少应记录这个顺序。

## 6.4 交叉验证和模型选择

### 6.4.1 K 折交叉验证的基本思想

将数据分成 K 个互不重叠的 fold，每次用 K-1 个 fold 训练，用剩下的一个 fold 验证，轮换 K 次。若第 k 次验证损失为 R_k，平均估计为：

~~~math
\overline{R}_{\mathrm{CV}}
=\frac{1}{K}\sum_{k=1}^{K}R_k
~~~

不同 fold 的波动可以反映数据划分带来的不确定性。K 折交叉验证适合中小规模数据和传统模型，能减少“恰好某个 split 很容易”的偶然性。

### 6.4.2 交叉验证不能修复泄漏

如果同一用户或同一文档的样本被拆到不同 fold，K 折只是重复地泄漏，并不会变得更可信。应使用 GroupKFold、时间滚动验证或任务特定的 split。验证流程越复杂，越要先明确独立性单位。

### 6.4.3 为什么大模型很少对完整训练做 K 折

对大模型做 K 折意味着重复多次昂贵的训练，而且每个 fold 的计算预算、随机性和 checkpoint 都会增加。实践中常采用：

- 固定训练集、开发集和最终隐藏集；
- 在较小模型或小数据上做多 split 试验；
- 对少量候选配置运行多个随机种子；
- 只对评估器、路由器或小型 reward model 使用交叉验证；
- 在训练后用新数据、动态数据或线上回放检查。

选择何种方案不是“传统方法 versus 大模型方法”的对立，而是计算预算、数据规模和失误代价的权衡。

### 6.4.4 验证集的选择偏差

假设研究者尝试了 M 个 prompt、模型 checkpoint 或数据版本，并选择验证分数最高的一个。即使每个分数都是无偏的，最大值也会倾向于包含随机好运：

~~~math
\max_{1\leq j\leq M}\widehat{S}_{j}
~~~

通常会高于这些候选真实分数的最大值。候选越多，验证集越容易被开发过程间接过拟合。解决方法包括减少无记录试验、使用多个开发切片、保留最终隐藏集、记录所有候选而不是只记录胜者，以及对最终结论使用新的数据。

## 6.5 Bias-variance：一个有条件的解释框架

### 6.5.1 平方损失下的分解

假设真实标签满足：

~~~math
y=g(x)+\epsilon,\qquad
\mathbb{E}[\epsilon\mid x]=0,\qquad
\mathrm{Var}(\epsilon\mid x)=\sigma^2(x)
~~~

训练数据集记为 D，训练后模型记为 f_D。在固定输入 x 的平方损失下：

~~~math
\mathbb{E}_{D,\epsilon}
[(f_D(x)-y)^2]
=B^2(x)+V(x)+\sigma^2(x)
~~~

其中偏差平方为：

~~~math
B^2(x)
=\left(\mathbb{E}_{D}[f_D(x)]-g(x)\right)^2
~~~

方差为：

~~~math
V(x)
=\mathbb{E}_{D}
\left[
(f_D(x)-\mathbb{E}_{D}[f_D(x)])^2
\right]
~~~

B² 反映模型平均预测偏离真实函数的程度，V 反映换一批训练数据后预测的波动，sigma² 是数据噪声带来的不可约部分。

### 6.5.2 一个数字直觉

如果三个随机训练得到的模型在同一个样本上预测 [1.2, 1.8, 2.4]，真实函数值为 2，预测均值为 1.8，偏差平方为：

~~~math
(1.8-2)^2=0.04
~~~

若用总体方差定义，预测方差为：

~~~math
\frac{(1.2-1.8)^2+(1.8-1.8)^2+(2.4-1.8)^2}{3}
=0.24
~~~

这个例子中模型均值略有偏差，但不同训练数据导致的波动更大。增加数据、改变模型约束或改善训练稳定性可能降低方差；增强模型表达能力、改进特征或增加训练量可能降低偏差，但也可能在小数据上增加过拟合风险。

### 6.5.3 不能把公式机械套到生成模型

经典分解最直接适用于固定输入、平方损失和特定噪声假设。LLM 的 token 分布、序列损失、采样随机性和人工评价通常不满足这个简单形式。生成模型的 variance 可能来自：

- 训练数据和随机种子；
- 解码随机性；
- prompt 轻微变化；
- evaluator 或人评波动；
- 真实用户分布变化。

因此可以借用 bias-variance 作为诊断语言，但不能把一次生成差异直接当作经典统计方差，也不能从一个 train-val gap 精确分解出偏差和方差。

### 6.5.4 训练曲线中的信号

| 现象 | 可能解释 | 还需要检查 |
| --- | --- | --- |
| train 和 val 都高 | 欠拟合、数据/代码问题、预算不足 | label、mask、学习率、模型容量 |
| train 降、val 先降后升 | 过拟合或开发集被利用 | 数据规模、early stopping、重复率 |
| train 和 val 都降但线上差 | 目标分布不一致或指标错位 | 线上切片、任务成功、系统链路 |
| 多 seed 波动大 | 方差高或训练不稳定 | 初始化、数据顺序、精度、优化器状态 |
| benchmark 提升而真实任务不变 | 评估污染或指标不相关 | 动态集、bad case、独立人评 |

每一种现象都只是线索。尤其是 loss 曲线不能单独区分模型错误和数据错误。

## 6.6 过拟合：从训练细节到错误的迁移

### 6.6.1 定义和典型曲线

过拟合不是“模型参数多”这一个原因，而是模型在当前训练过程中过度利用了训练样本的偶然细节，导致目标分布上的风险变差。最常见的曲线是训练损失继续下降，而验证损失先下降后上升：

~~~math
t_{\mathrm{best}}
=\arg\min_{t\in\mathcal{T}}
\widehat{R}_{\mathrm{val}}(f_{\theta_t})
~~~

`t_best` 是验证损失最低的 checkpoint。若继续训练，模型可能继续记住训练样本，训练集越来越好，但未见数据的表现开始退化。

然而“训练 loss 低、验证 loss 高”并不总是过拟合。训练和验证的 tokenizer、mask、loss reduction、数据质量或任务定义不一致，也能制造同样的曲线。因此过拟合诊断必须先排除评估实现错误。

### 6.6.2 预训练阶段的过拟合

预训练数据规模很大，并不意味着不会过拟合。风险包括：

1. 网页、代码或书籍的重复率很高；
2. 某些高价值数据被重复采样；
3. 训练 token 相对模型容量不足或训练过久；
4. 训练数据包含测试题、答案、密钥或个人信息；
5. 数据混合比例让模型过度适应单一来源。

预训练中的过拟合不一定表现为整体验证 loss 上升。某个领域的 loss 可能下降，同时其他语言、长尾知识或安全行为退化。因此需要按来源、语言、时间、长度和任务切片评估。

### 6.6.3 SFT 阶段的过拟合

监督微调通常数据量更小、格式更规则，过拟合可能表现为：

- 回答开始机械重复训练模板；
- 对改写后的指令理解下降；
- 只在训练风格的语言和长度上表现好；
- 结构化输出格式看似稳定，但字段内容错误；
- 真实用户问题上的澄清、拒答或多轮能力下降。

SFT 训练集的 token loss 是必要的优化指标，但还要用独立指令集、改写集、长尾任务和基础能力回归来检查是否真正学到目标行为。

### 6.6.4 偏好优化阶段的过拟合

DPO、RLHF 或其他偏好优化方法可能过拟合偏好数据和奖励模型：

1. 模型学会迎合评估器的表面风格；
2. 输出变得更长，却没有更多有效信息；
3. 为避免风险而过度拒答；
4. win rate 上升，但事实性、代码和数学能力下降；
5. 只在偏好数据的提示分布上变好。

因此偏好优化后的泛化不能只看 preference win rate。至少要并行记录帮助性、事实性、安全拒答、误拒、格式、基础能力和真实任务成功率。

### 6.6.5 RAG 和 prompt 的隐性过拟合

RAG 系统也会过拟合：如果 prompt、chunk 大小、reranker 或 top-k 只在一套固定文档和问题上调优，系统可能学会评测集的词法规律，而不是形成稳健检索链路。类似地，一个 prompt 在固定 benchmark 上调到最好，可能只是把该 benchmark 的答案格式写进了提示。

应对方法是更换文档、query、版本、权限和领域，并把检索 recall、证据支持率和最终任务成功率分开报告。只看最终答案流畅度，无法知道系统是检索变好了，还是模型在没有证据时更会猜。

## 6.7 欠拟合：模型或训练还没有学到目标

### 6.7.1 欠拟合的定义

欠拟合表示模型连训练分布中的目标都没有充分拟合。典型表现是训练和验证都差，或者训练 loss 长期停在高位。它可能来自模型容量不足，但也可能来自数据和实现错误。

常见原因包括：

1. 模型规模或表示能力不足；
2. 有效训练 token 不够；
3. 学习率过小、过大或 schedule 不合适；
4. label、loss mask 或 shift 错误；
5. 数据质量差、目标冲突或噪声太大；
6. 训练步数太少；
7. LoRA rank 太小或目标模块覆盖太少；
8. 低精度、梯度缩放或通信实现损坏了更新。

### 6.7.2 为什么不能直接“把模型做大”

如果损失高的原因是 label 全被 ignore、padding 权重错了或 tokenizer 与 checkpoint 不匹配，增大模型只会让错误系统更贵。排查欠拟合应先用很小的数据集做过拟合测试：让模型在几十条样本上训练到接近零损失，确认数据读取、前向、反向和目标计算正确，再讨论模型容量和训练预算。

对于 LoRA，还要检查 adapter 是否真的被加入计算图、是否有梯度、参数是否更新、初始化是否让梯度可流动。rank 小可能限制表达，但不能解释一个完全不下降的 loss，除非目标任务确实超出 adapter 的更新路径。

### 6.7.3 训练资源和目标的匹配

模型容量、数据规模和计算量需要一起看。模型很大但训练 token 不够，可能没有得到充分训练；模型很小但数据和任务复杂，可能无法表示规律；数据质量差时，增加 token 可能增加噪声而非有效信息。

这不是一个只看参数量的比较题。应记录有效 token、数据混合、训练 compute、模型规模、验证 loss 和任务指标，再判断是 undertrained、underfit 还是数据目标本身不一致。

## 6.8 正则化：限制不可靠的自由度

### 6.8.1 目标函数中的正则化

正则化通过限制参数或训练过程，降低模型利用训练集偶然细节的机会。L2 正则化的教学形式为：

~~~math
L_{\mathrm{reg}}(\theta)
=\widehat{R}_{S}(f_\theta)
+\lambda\|\theta\|_2^2
~~~

`lambda` 越大，参数范数被惩罚得越强。设任务损失为 `0.42`，参数为 `[3,4]`，`lambda=0.01`，则：

~~~math
\lambda\|\theta\|_2^2
=0.01(3^2+4^2)=0.25
~~~

总目标为 `0.67`。这个例子只解释加法关系，不说明生产环境应选择这个 lambda。正则过强会限制必要的表达能力，造成欠拟合。

### 6.8.2 Weight decay 和 L2 penalty 的边界

在简单 SGD 中，把 L2 penalty 加进 loss 与对参数施加 weight decay 有相近形式；在 Adam 这类自适应优化器中，二者不再完全等价。AdamW 将权重衰减与梯度更新解耦，更新可以写成：

~~~math
\theta_{t+1}
=(1-\eta_t\lambda)\theta_t
-\eta_t\,\mathrm{AdamStep}(g_t)
~~~

这里的具体实现还涉及参数组、bias、Norm 参数是否衰减和优化器版本。不能把“用了 weight decay”直接等同于“使用了某个固定的 L2 目标”。

### 6.8.3 数据和训练过程也是正则化

大模型中正则化不只有一个 loss 项：

- 去重降低重复记忆；
- 增加数据多样性减少模板依赖；
- 混入通用数据减轻领域微调后的遗忘；
- dropout 改变每次训练的子网络；
- early stopping 限制训练时间；
- LoRA 的低 rank 限制可训练更新空间；
- KL 惩罚限制策略偏离参考模型；
- 数据增强让模型适应表述变化。

这些措施作用在不同层面，不能用一个“正则化强度”简单排序。增加 dropout 不能修复测试集泄漏，去重也不能替代正确的验证切分。

### 6.8.4 Early stopping

对 checkpoint 集合 T，只用开发集选择：

~~~math
t^*=\arg\min_{t\in\mathcal{T}}
\widehat{R}_{\mathrm{val}}(f_{\theta_t}),
\qquad
\theta^*=\theta_{t^*}
~~~

如果验证损失在第 300 步最低，第 500 步训练损失最低，应该选择第 300 步作为开发阶段模型。最终测试集只能在选择结束后使用，否则 early stopping 本身会污染测试集。

## 6.9 过参数化：参数多为何仍可能泛化

### 6.9.1 传统直觉和实际现象

传统教材常用“模型越复杂，越容易过拟合”的直觉。但现代深度学习经常出现：模型参数量超过训练样本数后，训练误差可以接近零，测试表现仍继续改善，或者先恶化后改善。这种现象不能用“参数多一定坏”解释。

大模型能泛化可能与以下因素共同有关：

1. 训练数据极其庞大且包含可迁移结构；
2. next-token 目标迫使模型压缩和复用统计规律；
3. Transformer 和优化器带来特定归纳偏置；
4. 初始化和梯度下降偏向某些解；
5. 数据混合、权重衰减和训练 schedule 形成隐式正则；
6. 任务本身存在冗余结构，很多参数并不等于很多独立自由度。

这些是可能机制，不是对任意 LLM 的单一因果结论。大模型仍然会记忆、污染和过拟合。

### 6.9.2 训练误差为零也不说明学习方式相同

两个模型都能把训练集准确率做到 100%，可能有完全不同的行为：

- 一个记住每个样本的表面字符串；
- 一个学习了可迁移的规则；
- 一个利用了标签泄漏或近重复；
- 一个只学会了数据模板。

因此需要改写、实体替换、组合、时间切分和动态测试，把这些可能性区分开。训练误差相同不意味着表示、机制或泛化相同。

### 6.9.3 模型容量不是唯一预算

泛化的实际预算还包括数据覆盖、优化步数、有效 token、标签噪声、评估次数和系统约束。一个大模型在数据不足时可能处于 undertrained 状态；一个小模型在高质量、结构清楚的任务上可能足够。讨论“模型够不够大”时，要同时问：数据是否够、目标是否清楚、训练是否稳定、评估是否独立。

## 6.10 记忆与泛化：不是二选一

### 6.10.1 什么叫记忆

在本章语境中，记忆是模型对训练数据中的特定信息形成了可被提示触发的保留。它可能表现为逐字复现、近似复现、罕见事实的记住、代码片段的延续，或者某种训练模板的机械模仿。

记忆不是一个单一开关。一个模型可以记住某个字符串，同时也学习了更一般的语法和结构；同一条知识可能既来自训练样本的直接暴露，也来自多个来源的统计归纳。把模型行为简单分成“背诵”或“理解”会遮蔽真正可检验的问题。

### 6.10.2 哪些样本更容易被记住

以下因素通常会提高直接记忆的可能性：

1. 样本在训练数据中重复出现；
2. 内容稀有、独特且容易定位；
3. 样本包含固定格式、代码、密钥或个人信息；
4. 训练时间或模型容量给了模型更多拟合机会；
5. 提示与原文高度相似；
6. 数据没有去重、来源边界和删除记录。

这些只是风险因素，不是只要出现其中一个就一定被记住。记忆评估需要定义提示方式、输出匹配规则和对照集。

### 6.10.3 用扰动测试区分记忆和结构学习

对一条训练样本，可以设计多个版本：

- 原始表述；
- 同义改写；
- 实体替换；
- 顺序改变；
- 新实体组合；
- 保持结构但改变表面词汇；
- 与训练样本无关但任务形式相同的样本。

如果模型只在原始字符串上好，在改写和组合上明显下降，说明直接记忆或模板依赖的解释更有可能；如果它在表面变化后仍能完成任务，说明至少存在某种可迁移结构。这个实验不能单独证明“理解”，但比一个训练集分数提供更具体的证据。

### 6.10.4 记忆风险和隐私风险

训练数据记忆可能导致隐私泄露、版权争议、秘密暴露或对特定群体的重复偏见。删除原始数据后，模型是否仍能输出相关内容，还取决于训练过程、重复来源、checkpoint 和后续微调。数据库删除不等于模型影响自动消失。

因此数据治理需要同时保存：

1. 原始数据的来源和授权；
2. 去重和过滤规则；
3. 训练数据版本与 checkpoint 关系；
4. 评估提示和输出；
5. 删除、修复或 unlearning 实验记录。

## 6.11 数据重复与近重复

### 6.11.1 重复为什么会改变训练动态

若同一信息在数据中重复 r 次，它在经验风险中的权重可能远高于只出现一次的信息。理想化地，重复样本对损失的贡献可以写成：

~~~math
\widehat{R}_{S}(f)
=\frac{1}{n}
\left(
r\ell_{\mathrm{repeat}}
+\sum_{i\notin\mathrm{repeat}}\ell_i
\right)
~~~

这不是实际数据管线的完整公式，但能说明重复会改变采样概率、梯度贡献和模型看到该信息的次数。重复还可能把训练集样本泄漏到验证集或测试集的近邻中。

### 6.11.2 Exact duplicate 和 near duplicate

完全相同的文本可以用规范化后的 hash 检查。近重复则更难：可能只改了空格、数字、实体、段落顺序或少量词汇。代码、网页、翻译和模板数据尤其容易产生近重复。

近重复检测的阈值、分词器、hash 算法和去重方向都会影响结果。过于严格可能删除有价值的不同样本，过于宽松又可能保留泄漏。正文和实验报告应记录规则，而不是只说“做过 dedup”。

### 6.11.3 训练集去重不等于评估无污染

即使训练集内部完成了去重，公开 benchmark 仍可能以另一种格式、答案或网页副本进入训练集。评估污染需要比较训练数据和评估样本，也要考虑开发过程是否反复使用了公开测试题。

因此应把三件事分开：

1. 训练数据内部重复；
2. 训练数据与评估数据重叠；
3. 开发者对评估集的调参污染。

它们的检测方法和修复方法不同，不能用一个 dedup 指标代替全部结论。

## 6.12 Benchmark contamination：分数为什么会虚高

### 6.12.1 污染的来源

benchmark contamination 指评测样本、答案或高度相似的内容进入了训练或开发过程。常见来源包括：

- 公开题目被网页抓取进入预训练语料；
- 训练数据包含答案解释或相同题目的改写；
- SFT、偏好数据和评测集共享模板；
- 研究者多次查看测试结果并据此改 prompt；
- 自动生成训练数据时引用了评测集。

污染可能是无意的，也可能没有办法从最终 checkpoint 中完全追溯。因此评估结果必须附带数据截止时间、去重规则和污染检测能力的说明。

### 6.12.2 Exact overlap 率

若评估样本规范化后的 hash 为 h_j，训练集合的 hash 集合为 H_train，可以计算：

~~~math
C_{\mathrm{exact}}
=\frac{1}{m}\sum_{j=1}^{m}
\mathbf{1}[h_j\in H_{\mathrm{train}}]
~~~

C_exact 只检测完全匹配，不能检测改写、翻译、代码重命名或答案级重叠。它等于零，也不能证明没有污染；它大于零，则至少需要解释重叠来源，最终测试集通常应更换或单独报告污染样本。

### 6.12.3 近重复和语义污染

更强的检测会使用 n-gram、MinHash、局部敏感 hash、编辑距离、embedding 近邻或人工核查。不同方法有不同误报和漏报：

- n-gram 对局部文本重叠敏感；
- MinHash 适合大规模近似集合；
- embedding 近邻能发现语义相近，但容易把同一主题的独立样本误报为污染；
- 人工核查成本高，却能判断题目、答案和模板的实际关系。

可信结论通常需要多种信号交叉，而不是把一个相似度阈值当作事实。

### 6.12.4 污染后的分数怎么处理

一旦发现最终评估集与训练数据有重叠，不应只把重叠样本删除后继续报告剩余平均分而不说明。应至少记录：

1. 重叠比例和检测规则；
2. 重叠样本在总体分数中的贡献；
3. 清理后分数及置信区间或波动；
4. 未污染的新评估集；
5. 结论从“模型能力”降级为何种证据。

公开榜单的高分可以作为线索，但不能替代独立、动态和任务相关的评估。

## 6.13 分布外泛化

### 6.13.1 什么是分布外

训练分布为 P_train，目标评估分布为 P_target。当二者在输入、标签关系、来源、时间或任务环境上有明显差异时，可以把目标测试称为分布外评估。性能差异可用一个教学指标表示：

~~~math
\Delta_{\mathrm{shift}}
=S_{\mathrm{val}}(f)-S_{\mathrm{target}}(f)
~~~

若分数越大越好，Delta_shift 越大表示从验证分布到目标分布的下降越明显。它不是一个普适阈值，因为不同任务的分数尺度和风险不同。

### 6.13.2 常见的分布变化

大模型系统中常见的变化包括：

- 用户语言、地区和表达风格变化；
- 文档来源、格式和版本变化；
- 问题长度、上下文长度和多轮深度变化；
- 领域术语和实体变化；
- 工具 schema、错误码和返回格式变化；
- 风险等级和攻击方式变化；
- 解码参数、模型路由和检索索引变化。

一个模型可以在文本内容分布稳定时，因为工具或索引变化而失效。因此 OOD 评估不应只生成“更难的题”，还要改变实际系统的输入和依赖。

### 6.13.3 切片而不是只看总平均

若总样本集合为 S，按语言、长度、来源或风险分成切片 S_k，应分别报告：

~~~math
S_k(f)
=\frac{1}{|S_k|}
\sum_{(x,y)\in S_k}
s(f(x),y)
~~~

总体分数可能被大切片主导，掩盖少数关键切片的严重失败。对安全、金融、医疗或权限任务，最小切片的失败代价可能比总体平均更重要。

### 6.13.4 验证分布好不代表线上好

线上性能还受到路由、检索、缓存、工具、权限、提示拼接和解码的共同影响。模型本身在 OOD 数据上表现不错，但检索返回旧版本文档，系统最终仍会失败；反过来，模型离线分数一般，线上可能因为真实 query 更简单而表现尚可。

因此要分别测模型、子系统和端到端任务，并在日志中保留足够的证据链。把线上失败全部归因于“模型泛化差”通常过早。

## 6.14 组合泛化：把已学组件重新组合

### 6.14.1 组合和记忆的区别

组合泛化要求模型把已学到的关系、操作或概念重新组合到新结构。例如训练数据中分别出现：

- A 比 B 大；
- B 比 C 大；
- 比较和传递关系的任务；

测试时要求模型处理新实体并推出 A 比 C 大。若只记住具体名称和句子，换成新实体就会失败；若学到关系结构，应该更稳定。

这个例子很简单，真实 LLM 的组合任务可能涉及多步推理、变量绑定、工具调用和长上下文。组合泛化测试要明确哪些组件训练中出现过、哪些组合只在测试中出现。

### 6.14.2 组合泛化实验的控制变量

一个有解释力的实验至少控制：

1. token 长度和输出格式；
2. 词汇难度和实体频率；
3. 任务指令和示例数量；
4. 训练与测试的组件集合；
5. 解码温度、最大长度和停止条件；
6. 评估器对格式和内容的判断规则。

否则模型失败可能来自生僻词、长度或格式，而不是真正的组合能力不足。

### 6.14.3 RAG、工具和多模态中的组合泛化

组合泛化也存在于系统中：

- RAG：新 query 与新文档类型的组合；
- Agent：已知工具在新任务顺序中的组合；
- 多模态：新图表布局与新问题类型的组合；
- 代码：已知 API 与未见过的调用顺序组合；
- 安全：已知攻击成分组合成新的注入方式。

单独评估每个组件都通过，不代表组合后一定正确。应增加跨组件的任务集，并记录是组件失败还是组合协议失败。

## 6.15 泛化评估：从分数到证据链

### 6.15.1 评估矩阵

一个可解释的泛化实验可以把评估集按两个维度组织：数据分布和任务性质。

| 数据/任务 | 原分布 | 改写 | 新实体/组合 | 新来源或版本 | 线上回放 |
| --- | --- | --- | --- | --- | --- |
| 事实问答 | 基线正确性 | 表述迁移 | 实体迁移 | 时间迁移 | 用户任务成功 |
| 代码 | 常见语言和 API | 注释/变量改写 | API 组合 | 新仓库 | 测试通过率 |
| RAG | 已知文档 | query 改写 | 新问题类型 | 新文档版本 | 引用支持 |
| 安全 | 已知风险样本 | 语言/措辞变化 | 攻击组合 | 新攻击模板 | 漏放与误杀 |
| 多模态 | 常见布局 | 视觉扰动 | 图文组合 | 新来源图片 | 端到端任务 |

这张表不是要求所有项目都拥有同样规模的评测，而是提醒读者：一个分数只覆盖一个坐标。报告中应说明哪些格子没有测试，不能用平均分掩盖未知区域。

### 6.15.2 任务成功率的定义

对生成任务，字符串相似度经常不足以定义成功。可以定义每个样本同时满足内容、格式和证据条件：

~~~math
\mathrm{success}_i
=\mathbf{1}
[c_i=1\land f_i=1\land e_i=1]
~~~

其中 c_i 表示内容正确，f_i 表示格式满足协议，e_i 表示证据或工具结果支持要求。任务成功率为：

~~~math
S_{\mathrm{task}}
=\frac{1}{n}\sum_{i=1}^{n}\mathrm{success}_i
~~~

如果把三个条件分别报告，可以定位失败来源；如果只报告一个总体分数，无法知道模型是知道答案但格式错了，还是格式正确但没有证据。

### 6.15.3 置信区间和重复运行

有限样本分数有统计波动。对成功率为 p_hat、样本数为 n 的简单二项估计，标准误差的教学近似为：

~~~math
\mathrm{SE}(\widehat{p})
\approx\sqrt{\frac{\widehat{p}(1-\widehat{p})}{n}}
~~~

这不是所有评估的完整置信区间方法；配对样本、分层抽样、相关对话和人评都可能需要更合适的统计处理。至少应报告样本量、切片和随机种子，而不是把小样本的一次提升写成确定规律。

### 6.15.4 变化归因

若新方案同时改变数据、模型、prompt、检索和解码，观察到的分数差异是总效果：

~~~math
\Delta S
=S(\mathrm{new\ system})-S(\mathrm{baseline})
~~~

要把它归因到某个因素，需要对照或消融。例如固定模型和数据，只改变去重规则；固定检索，只改变 prompt；固定 prompt，只改变 adapter。实验越昂贵，越应该在小模型、缩小数据或离线回放上先做归因，再把候选方案带到大模型。

## 6.16 最小可运行泛化审计实验

下面的例子不调用机器学习库，而是用三个 toy predictor 表示三种不同学习结果：memorizer 只记住训练字符串，keyword rule 学到一个可迁移但不完整的规则，underfit 几乎没有学到目标。代码还计算 bias-variance 的教学数值、L2 惩罚、early stopping、线上切片下降和 exact overlap。

~~~python
from collections import defaultdict


train = [

    {"id": "tr_07", "text": "weather small talk", "label": 0},
    {"id": "tr_08", "text": "movie preference chat", "label": 0},
    {"id": "tr_09", "text": "music playlist request", "label": 0},
    {"id": "tr_10", "text": "casual greeting", "label": 0},
]

validation = [
    {"id": "va_01", "text": "math word problem", "label": 1},
    {"id": "va_02", "text": "code task parsing", "label": 1},
    {"id": "va_03", "text": "reasoning chain with distractor", "label": 1},
    {"id": "va_04", "text": "math geometry proof", "label": 1},
    {"id": "va_05", "text": "weather forecast chat", "label": 0},
    {"id": "va_06", "text": "recipe suggestion", "label": 0},
]

test = [
    {"id": "te_01", "text": "math contest problem", "label": 1},
    {"id": "te_02", "text": "code parse json", "label": 1},
    {"id": "te_03", "text": "reasoning logic grid", "label": 1},
    {"id": "te_04", "text": "code unit test", "label": 1},
    {"id": "te_05", "text": "travel planning", "label": 0},
    {"id": "te_06", "text": "friendly greeting", "label": 0},
]

production = [
    {"id": "pr_01", "text": "math word problem", "label": 1, "slice": "in_domain"},
    {"id": "pr_02", "text": "code review task", "label": 1, "slice": "in_domain"},
    {"id": "pr_03", "text": "weather small talk", "label": 0, "slice": "in_domain"},
    {"id": "pr_04", "text": "algebra equation", "label": 1, "slice": "new_terms"},
    {"id": "pr_05", "text": "python bug report", "label": 1, "slice": "new_terms"},
    {"id": "pr_06", "text": "friendly greeting", "label": 0, "slice": "new_terms"},
]


def normalize(text):
    return " ".join(text.lower().split())


memorized_labels = {normalize(row["text"]): row["label"] for row in train}


def predict_memorizer(row):
    return memorized_labels.get(normalize(row["text"]), 0)


def predict_keyword_rule(row):
    words = set(normalize(row["text"]).split())
    return int(bool(words & {"math", "code", "reasoning"}))


def predict_underfit(row):
    return 0


def accuracy(predict_fn, rows):
    correct = sum(int(predict_fn(row) == row["label"]) for row in rows)
    return correct / len(rows)


def summarize_model(predict_fn):
    train_acc = accuracy(predict_fn, train)
    val_acc = accuracy(predict_fn, validation)
    test_acc = accuracy(predict_fn, test)
    return {
        "train": round(train_acc, 3),
        "val": round(val_acc, 3),
        "test": round(test_acc, 3),
        "gap": round(train_acc - val_acc, 3),
    }


models = {
    "memorizer": predict_memorizer,
    "keyword_rule": predict_keyword_rule,
    "underfit": predict_underfit,
}
score_summary = {name: summarize_model(fn) for name, fn in models.items()}

diagnosis = {
    "memorizer_overfits": (
        score_summary["memorizer"]["train"] >= 0.9
        and score_summary["memorizer"]["gap"] >= 0.25
    ),
    "underfit_detected": (
        score_summary["underfit"]["train"] < 0.7
        and score_summary["underfit"]["val"] < 0.7
    ),
    "rule_generalizes": (
        score_summary["keyword_rule"]["val"] >= 0.9
        and score_summary["keyword_rule"]["test"] >= 0.9
    ),
}


def bias_variance(predictions, true_value, noise_var):
    mean_prediction = sum(predictions) / len(predictions)
    bias_sq = (mean_prediction - true_value) ** 2
    variance = sum(
        (prediction - mean_prediction) ** 2
        for prediction in predictions
    ) / len(predictions)
    return {
        "mean_prediction": round(mean_prediction, 3),
        "bias_sq": round(bias_sq, 3),
        "variance": round(variance, 3),
        "noise": round(noise_var, 3),
        "expected_error": round(bias_sq + variance + noise_var, 3),
    }


weights = [3.0, 4.0]
task_loss = 0.42
lambda_l2 = 0.01
l2_penalty = lambda_l2 * sum(weight * weight for weight in weights)
regularized_loss = task_loss + l2_penalty

checkpoints = [
    {"step": 100, "train_loss": 0.82, "val_loss": 0.86},
    {"step": 200, "train_loss": 0.55, "val_loss": 0.61},
    {"step": 300, "train_loss": 0.38, "val_loss": 0.49},
    {"step": 400, "train_loss": 0.25, "val_loss": 0.54},
    {"step": 500, "train_loss": 0.16, "val_loss": 0.67},
]
best_checkpoint = min(checkpoints, key=lambda row: row["val_loss"])


def slice_scores(predict_fn, rows):
    grouped = defaultdict(list)
    for row in rows:
        grouped[row["slice"]].append(row)
    return {
        name: round(accuracy(predict_fn, subset), 3)
        for name, subset in sorted(grouped.items())
    }


prod_acc = accuracy(predict_keyword_rule, production)
shift = {
    "val_acc": score_summary["keyword_rule"]["val"],
    "prod_acc": round(prod_acc, 3),
    "score_drop": round(
        score_summary["keyword_rule"]["val"] - prod_acc,
        3,
    ),
    "slice_scores": slice_scores(predict_keyword_rule, production),
}

eval_for_leakage = validation + [
    {"id": "eval_copy", "text": "math proof induction", "label": 1}
]
train_hash_to_id = {
    normalize(row["text"]): row["id"]
    for row in train
}
exact_overlaps = [
    (row["id"], train_hash_to_id[normalize(row["text"])])
    for row in eval_for_leakage
    if normalize(row["text"]) in train_hash_to_id
]
overlap_rate = len(exact_overlaps) / len(eval_for_leakage)

checks = {
    "memorizer_overfits": diagnosis["memorizer_overfits"],
    "underfit_detected": diagnosis["underfit_detected"],
    "rule_generalizes_clean_sets": diagnosis["rule_generalizes"],
    "early_stopping_before_overfit": best_checkpoint["step"] == 300,
    "shift_detected": (
        shift["score_drop"] > 0.2
        and min(shift["slice_scores"].values()) < 0.7
    ),
    "contamination_detected": overlap_rate > 0,
}

print("score_summary=", score_summary)
print("diagnosis=", diagnosis)
print(
    "bias_variance=",
    bias_variance([1.2, 1.8, 2.4], true_value=2.0, noise_var=0.1),
)
print(
    "regularization=",
    {
        "task_loss": task_loss,
        "l2_penalty": round(l2_penalty, 3),
        "total": round(regularized_loss, 3),
    },
)
print("best_checkpoint=", best_checkpoint)
print("shift=", shift)
print(
    "exact_overlaps=",
    exact_overlaps,
    "overlap_rate=",
    round(overlap_rate, 3),
)
print("checks=", checks)
~~~

这个例子的重点不是分类器本身，而是诊断链条：

1. memorizer 训练集 100%，验证和测试很差，说明训练集好不等于泛化好；
2. underfit 训练集和验证集都差，说明模型或训练配置还没学到目标；
3. keyword rule 在干净验证集和测试集好，但遇到 algebra、python 这类新表述就掉分，说明分布偏移仍然存在；
4. early stopping 选择验证损失最低的 checkpoint，而不是训练损失最低的 checkpoint；
5. final eval 出现训练样本 exact overlap 时，要解释污染来源，不能直接把分数当作泛化能力。

这个 toy 实验有意把“模型问题”和“数据问题”放在一起：keyword rule 在 validation/test 上是满分，但 production 的 new_terms 切片较差，说明干净离线集不足以覆盖线上词汇；eval_copy 则直接展示了 exact overlap 如何进入评估。真实模型需要更强的 near-duplicate 检测、更多切片和任务级判断，但诊断顺序相同。

## 6.17 评估结果的可信度和实验边界

### 6.17.1 先写清主张

“模型变强了”不是足够精确的主张。更好的写法应指定：

- 在什么模型和 checkpoint 上；
- 使用什么数据切分和 tokenizer；
- 哪个任务、哪个切片；
- 比较了哪个 baseline；
- 指标如何定义；
- 是否包含检索、工具、解码和人工评价；
- 运行了多少随机种子；
- 结果是否经过污染和 near-duplicate 检查。

主张越具体，读者越能判断证据是否支持它。

### 6.17.2 训练、验证和测试的职责

训练集用于更新参数；验证集用于开发和选择；最终测试集用于在选择结束后给出一次相对独立的报告。线上回放、动态数据和隐藏集用于检验开发集未覆盖的情况。

如果研究者看过最终测试结果后继续改模型，那个集合就变成开发集的一部分。文件名叫 test 不会自动恢复独立性。应该重新建立一个未使用的评估集合，或者如实把结论降级为开发结果。

### 6.17.3 指标和目标错位

语言模型的 token loss 可能下降，但用户任务成功率不变；答案相似度可能上升，但引用不被证据支持；偏好胜率可能上升，但误拒率和安全漏放变坏。不同指标测量不同对象，不能只挑对自己有利的一个。

一个完整结果表可以包含：

| 层次 | 指标例子 | 解释 |
| --- | --- | --- |
| 训练目标 | NLL、token accuracy | 是否拟合训练目标 |
| 预测质量 | PPL、校准、事实性 | 指定分布上的预测 |
| 任务结果 | 成功率、代码测试、引用支持 | 是否完成用户任务 |
| 安全行为 | 漏放、误杀、误拒 | 风险场景表现 |
| 系统成本 | 延迟、吞吐、单位成功成本 | 是否具备实际价值 |

### 6.17.4 负结果也有信息

如果一个去重策略没有改善验证分数，却降低了记忆暴露；如果一个更大 rank 提高训练分数，却损伤 OOD 组合任务；如果一个新 prompt 只改善固定 benchmark，不能把它们简单称为失败。它们说明当前假设、数据或指标存在边界。

记录负结果可以避免团队重复尝试，也能帮助读者理解方法为什么没有在所有场景中工作。

## 6.20 本章回顾

泛化不是一个榜单分数，而是模型从有限训练样本迁移到目标分布的能力。真实风险是目标分布上的期望损失，经验风险是训练样本上的平均损失，二者之间的差距受数据、模型、优化和选择过程共同影响。

可靠的评估从数据切分开始：按用户、文档、仓库、时间和版本定义独立性；交叉验证可以减少 split 偶然性，却不能修复泄漏；验证集可用于开发，最终测试集必须在选择结束后使用。Bias-variance 是有条件的诊断框架，不能机械套用到 LLM 的生成随机性。

过拟合可以发生在预训练、SFT、偏好优化、RAG prompt 和 benchmark 开发中；正则化既包括 weight decay 和 early stopping，也包括去重、数据多样性、LoRA 低 rank 和 KL 约束。大模型参数很多仍可能泛化，但这不意味着记忆、污染和分布外失败消失。

判断模型是在记忆还是学习结构，需要原始、改写、实体替换、组合和动态测试；判断一个系统是否真的更好，需要同时看任务成功、证据支持、安全切片、线上分布和系统成本。最终结论的质量，取决于主张有多具体、证据链有多完整，而不取决于训练分数看起来有多漂亮。
