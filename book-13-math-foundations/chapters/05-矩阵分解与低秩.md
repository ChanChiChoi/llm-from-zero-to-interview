# 第五章：矩阵分解与低秩：从奇异值到参数高效微调

矩阵分解把一个看起来庞大的线性变换拆成几个更容易观察的部分。对大模型来说，这个拆分连接了几条经常同时出现、却不能混为一谈的路线：

- SVD 把一个矩阵的输入方向、缩放强度和输出方向分开；
- PCA 从一批样本中寻找方差最大的线性方向；
- 低秩压缩用较少的方向近似原始权重；
- LoRA 不压缩原始权重，而是把微调增量限制在低秩参数化中；
- QLoRA 再把量化后的基础模型和可训练的低秩适配器组合起来；
- embedding 可视化借助降维观察表示空间，但图上的结构不能直接等同于模型能力。

这些概念共享“少数方向可能承载主要变化”的直觉，却对应不同的对象、目标和误差。一个矩阵的奇异值能量保留率很高，不代表压缩后的模型在所有任务上都不掉点；一个 LoRA adapter 参数很少，也不代表它能表达任意任务的完整更新；二维图中出现了聚类，更不代表模型已经理解了类别语义。

本章从线性代数的对象开始，逐步推导到大模型里的使用方式。初学者可以先把每个公式看成一个可计算的描述，先理解输入和输出的形状，再回头理解它为何成立。已经熟悉 SVD 和 LoRA 的读者，则应重点关注数值秩、误差范数、任务风险、量化内存和实验设计之间的边界。

## 5.1 先明确对象：矩阵是一个线性变换

把矩阵只看成一张数字表，很容易在形状和转置上出错。更有用的看法是：矩阵描述了一个从输入向量空间到输出向量空间的线性变换。

设输入向量是列向量，权重矩阵为：

~~~math
W\in\mathbb{R}^{d_{\mathrm{out}}\times d_{\mathrm{in}}},\qquad
y=Wx,\qquad
x\in\mathbb{R}^{d_{\mathrm{in}}},\quad
y\in\mathbb{R}^{d_{\mathrm{out}}}
~~~

这里 `d_in` 是输入特征数，`d_out` 是输出特征数。工程代码也常把 batch 放在左侧，把样本写成行向量：

~~~math
X\in\mathbb{R}^{B\times d_{\mathrm{in}}},\qquad
Y=XW^{\mathsf T}\in\mathbb{R}^{B\times d_{\mathrm{out}}}
~~~

两种写法描述的是同一个线性层，只是向量约定不同。很多论文把权重写成 `d_out × d_in`，而一些深度学习模块在内部保存的张量维度或公式习惯可能使读者看到转置。讨论 rank 和参数量时，矩阵转置不改变 rank，但计算图中的乘法顺序和 shape 必须保持一致。

一个线性层的完整矩阵有 `d_in * d_out` 个参数。若 `d_in=d_out=4096`，参数量为：

~~~math
4096\times4096=16\,777\,216
~~~

这个数字还只是一个矩阵的权重，不包括 bias、梯度、优化器状态、激活和通信缓冲区。低秩方法的价值，首先来自把“需要学习的自由度”从乘积规模改成加法规模；它是否同时降低前向计算，则要看使用的是哪一种低秩方法。

## 5.2 Rank：独立方向的数量

### 5.2.1 列空间和线性独立

矩阵的 rank 是列空间的维度，也等于行空间的维度。直观地说，如果一组列中有些列可以由其他列线性组合得到，那么这些列没有带来新的方向。

例如：

~~~math
A=
\begin{bmatrix}
1&0&1\\
0&1&1\\
1&1&2
\end{bmatrix}
~~~

第三列等于前两列之和，因此这个矩阵至多只有两个独立列方向。前两列本身独立，所以：

~~~math
\mathrm{rank}(A)=2
~~~

对于一个 `m × n` 矩阵，其中 `m,n>0`，rank 同时满足：

~~~math
0\leq \mathrm{rank}(A)\leq \min(m,n)
~~~

rank 为零意味着矩阵全是零；rank 等于 `min(m,n)` 称为满秩。满秩并不表示矩阵在任务上一定有用，它只说明没有精确的线性冗余。

在机器学习中，rank 代表表达能力和自由度。高 rank 更灵活，但参数多；低 rank 更受限，但更省参数，也可能有正则化效果。

### 5.2.2 Rank-nullity 定理

矩阵也可以看成一个线性映射。输入中被映射到零向量的部分称为零空间，零空间维度称为 nullity。对于 `A` 从 `R^n` 映射到 `R^m` 的情形：

~~~math
\mathrm{rank}(A)+\mathrm{nullity}(A)=n
~~~

这个等式说明了 rank 与“真正能被矩阵区分的输入方向”有关。如果 `A` 有 `n=5` 个输入维度，但 rank 只有 2，那么至少有 3 个相互独立的输入方向会在变换后丢失，或者与其他方向无法区分。

在神经网络里，低 rank 并不自动表示信息被错误地丢失。一个任务可能只需要使用输入空间中的一个低维子空间，或者某个增量本来就只改变少数方向。关键是要区分“矩阵本身的 rank”和“任务所需要的有效 rank”。

### 5.2.3 精确秩与数值秩

在纸面计算中，元素为零就能判断线性相关；在浮点计算中，原本应该为零的量可能因为舍入变成 `1e-8`。因此工程中常用数值秩：

~~~math
\mathrm{rank}_{\tau}(A)
=\#\{i:\sigma_i>\tau\}
~~~

其中 `sigma_i` 是奇异值，`tau>=0` 是相对于数据尺度设置的阈值。阈值不能脱离矩阵尺度随意指定：同一个绝对阈值对数值范围为 `1` 的矩阵和数值范围为 `1e6` 的矩阵含义不同。实际实现还应记录阈值是绝对阈值还是按最大奇异值、维度或 dtype 缩放后的相对阈值。

数值秩不是矩阵的唯一“真实秩”，而是某个精度、阈值和数据尺度下的判断。它用于诊断近似低秩性，而不是宣称模型表示只有某个固定维度。这个区别在分析 hidden states 和权重矩阵时尤其重要，因为不同层、不同批次和不同归一化方式会改变奇异值的尺度。

## 5.3 奇异值分解：把变换拆成三个动作

### 5.3.1 SVD 的形式

任意实矩阵 `W` 都可以写成奇异值分解：

~~~math
W=U\Sigma V^{\mathsf T}
~~~

若 `W` 的形状是 `m × n`，完整 SVD 中：

~~~math
U\in\mathbb{R}^{m\times m},\qquad
\Sigma\in\mathbb{R}^{m\times n},\qquad
V\in\mathbb{R}^{n\times n}
~~~

`U` 和 `V` 的列向量是正交单位向量，`Σ` 只有主对角线可能非零。非负奇异值按非递增顺序排列：

~~~math
\sigma_1\geq\sigma_2\geq\cdots\geq\sigma_{\min(m,n)}\geq0
~~~

实际库经常返回 reduced SVD。令 `p=min(m,n)`，则：

~~~math
U_r\in\mathbb{R}^{m\times p},\qquad
\Sigma_r\in\mathbb{R}^{p\times p},\qquad
V_r\in\mathbb{R}^{n\times p}
~~~

这时仍有：

~~~math
W=U_r\Sigma_rV_r^{\mathsf T}
~~~

初学者最容易犯的错误，是把 `V` 和 `V^T` 的形状记反，或者把库返回的 `Vh` 当成 `V`。例如 NumPy 和 PyTorch 的 SVD API 通常返回 `U, S, Vh`，其中 `Vh=V^T`。恢复矩阵时应该写成 `U @ diag(S) @ Vh`，而不是再转置一次。

### 5.3.2 几何意义

对于输入向量 `x`：

~~~math
Wx=U\Sigma V^{\mathsf T}x
~~~

可以按三个动作理解：

1. `V^T` 把输入投影到一组正交坐标轴上；
2. `Σ` 沿这些轴分别放大或缩小，缩放倍数就是奇异值；
3. `U` 把缩放后的坐标旋转或反射到输出空间。

因此奇异值不是“某个神秘重要性分数”，它描述的是线性变换在特定正交方向上的伸缩强度。最大的奇异值是算子范数：

~~~math
\|W\|_2=\sigma_1
~~~

它给出单位输入可能产生的最大输出长度。所有奇异值平方之和等于 Frobenius 范数平方：

~~~math
\|W\|_F^2=\sum_i\sigma_i^2
~~~

这个恒等式使得奇异值平方可以作为一种矩阵能量分解，但“能量”只是矩阵误差指标，不是语义质量指标。

### 5.3.3 一个小矩阵例子

考虑对角矩阵：

~~~math
W=
\begin{bmatrix}
5&0&0\\
0&2&0\\
0&0&0.5
\end{bmatrix}
~~~

它已经处于 SVD 的对角形式，三个方向的伸缩分别是 `5`、`2` 和 `0.5`。在这个例子中，沿第一方向的变化最强，沿第三方向的变化最弱。若把第三个奇异值置零，等于完全丢弃第三个方向；若保留前两个方向，则仍保留：

~~~math
\frac{5^2+2^2}{5^2+2^2+0.5^2}
=\frac{29}{29.25}\approx0.991
~~~

的 Frobenius 能量。这个数字很高，但它只回答“矩阵的平方误差有多大”，不回答“某个分类、生成或检索任务是否还能工作”。

## 5.4 截断 SVD：最好的固定 rank 近似

### 5.4.1 如何构造 rank-r 近似

把 SVD 的前 `r` 个方向保留下来：

~~~math
W_r=U_{:,1:r}\Sigma_{1:r,1:r}V_{:,1:r}^{\mathsf T}
~~~

这里 `r` 是整数且满足 `0<=r<=p=min(m,n)`。被丢弃的部分由剩余奇异值描述：

~~~math
W-W_r=\sum_{i=r+1}^{p}\sigma_i u_i v_i^{\mathsf T}
~~~

每一项 `sigma_i u_i v_i^T` 都是 rank-1 矩阵，所以截断 SVD 是把若干 rank-1 方向相加。它不是随便把矩阵切成两个小块，而是寻找在给定 rank 下最有信息的方向组合。

### 5.4.2 两种常用误差

Frobenius 范数误差为：

~~~math
\|W-W_r\|_F^2=\sum_{i>r}\sigma_i^2
~~~

当 `0<=r<p` 时，谱范数误差为：

~~~math
\|W-W_r\|_2=\sigma_{r+1}
~~~

如果 `r=p`，没有被丢弃的方向，两种误差都为 0；此时不能继续引用不存在的 `\sigma_{p+1}`。

前者把所有方向的平方误差加起来，适合衡量总体近似误差；后者只看最坏方向，适合关注最大放大误差的场景。两者都必须结合输入分布和下游任务解释。

### 5.4.3 Eckart–Young 的含义

当 $0\le r<p$ 时，截断 SVD 同时达到 Frobenius 范数和谱范数下的最小误差：

~~~math
W_r\in\arg\min_{\mathrm{rank}(A)\leq r}\|W-A\|_F,\qquad
W_r\in\arg\min_{\mathrm{rank}(A)\leq r}\|W-A\|_2
~~~

为什么 Frobenius 误差是被丢弃奇异值的平方和？截断残差可以写成各个剩余 rank-1 方向之和。因为奇异向量分别正交，不同方向的 Frobenius 内积为零：

~~~math
\left\langle u_i v_i^{\mathsf T},u_jv_j^{\mathsf T}\right\rangle_F
=(u_i^{\mathsf T}u_j)(v_i^{\mathsf T}v_j)=\delta_{ij}
~~~

所以残差的平方长度就是各项平方长度相加，即 $\|W-W_r\|_F^2=\sum_{i>r}\sigma_i^2$；谱范数只取残差中最大的奇异值，即 $\|W-W_r\|_2=\sigma_{r+1}$。用前面的对角矩阵 $\mathrm{diag}(5,2,0.5)$，秩 2 的两种误差都是 $0.5$；秩 1 的 Frobenius 误差为 $\sqrt{2^2+0.5^2}\approx2.062$，谱误差为 $2$。

要说明没有别的秩不超过 $r$ 的矩阵误差更小，可以看两个下界。对任意矩阵 $A$，令 $P$ 为投影到 $A$ 列空间的正交投影，则 $(I-P)W$ 与 $PW-A$ 的列空间互相正交，因此：

~~~math
\|W-A\|_F^2
=\|(I-P)W\|_F^2+\|PW-A\|_F^2
\geq \|(I-P)W\|_F^2
~~~

由于 $WW^{\mathsf T}$ 的特征值按 $\sigma_i^2$ 从大到小排列，任意秩不超过 $r$ 的正交投影 $P$ 最多保留前 $r$ 个特征方向的能量：

~~~math
\|PW\|_F^2=\mathrm{tr}(PWW^{\mathsf T})
\leq\sum_{i=1}^{r}\sigma_i^2
~~~

又因 $P$ 是正交投影，$\|(I-P)W\|_F^2=\|W\|_F^2-\|PW\|_F^2$，所以 Frobenius 误差至少为 $\sum_{i>r}\sigma_i^2$；投影到前 $r$ 个左奇异向量时恰好取到该下界。谱范数也有相应下界：$A$ 的零空间与 $v_1,\ldots,v_{r+1}$ 张成的空间至少有一个共同的单位向量 $x$，此时 $Ax=0$ 且 $\|Wx\|_2\geq\sigma_{r+1}$，所以任何秩不超过 $r$ 的近似，其谱误差都不小于 $\sigma_{r+1}$。截断 SVD 正好达到这两个下界。这个经典矩阵近似结论源于 Eckart 与 Young，Mirsky 将其推广到酉不变范数；本节只用到 Frobenius 范数和谱范数。[Eckart–Young 原论文](https://doi.org/10.1007/BF02288367)、[Mirsky 的范数推广](https://doi.org/10.1093/qmath/11.1.50)。

最优性仍只针对矩阵范数。它不保证 rank-r 模型在任务指标上最优，因为任务损失一般不是矩阵 Frobenius 误差。比如某个平方误差较小的权重方向，仍可能承担安全拒答、格式约束或少数类别的区分；仅看总能量不能判断它对任务是否重要。

### 5.4.4 计算和存储的变化

一个 `m × n` 的矩阵有 `mn` 个参数。若写成两个因子：

~~~math
W\approx AB,\qquad
A\in\mathbb{R}^{m\times r},\quad
B\in\mathbb{R}^{r\times n}
~~~

参数量变成：

~~~math
N_{\mathrm{factor}}=r(m+n)
~~~

当 `r` 很小时，存储从乘法规模变为加法规模。对 batch 输入 `X`，原计算：

~~~math
XW
~~~

可以改写为：

~~~math
X(AB)=(XA)B
~~~

若 batch 有 $n_b$ 个样本，输入形状是 $n_b\times m$，中间结果是 $n_b\times r$。理想情况下，乘法量也会下降；但实际收益还取决于 kernel 是否高效、矩阵是否足够大、是否需要先合并权重，以及低秩矩阵带来的内存访问是否抵消了算术节省。

## 5.5 能量保留率为什么不是任务质量

### 5.5.1 矩阵指标和任务指标回答不同问题

当奇异值有限、非负且总平方能量严格大于 0 时，能量保留率通常写为：

~~~math
E_r=\frac{\sum_{i=1}^{r}\sigma_i^2}{\sum_{i=1}^{p}\sigma_i^2}
~~~

全零矩阵的分母为 0，此时能量保留率没有定义，应报告“零矩阵”或 `undefined`，而不是把它当作 0% 或 100%。`r` 仍需满足 `0<=r<=p`。

它表示 rank-r 近似保留了多少 Frobenius 能量。等价地，归一化平方误差是 `1-E_r`。这对选择候选 rank 很有用，因为它告诉我们矩阵近似的基本代价。

但任务真正关心的往往是：

- 分类准确率或校准误差；
- 生成任务的约束满足率；
- 代码测试通过率；
- 检索的 recall、MRR 或引用支持率；
- 安全拒答的误拒率和漏拒率；
- 延迟、吞吐、峰值显存和单位成功任务成本。

从权重到任务输出之间还隔着非线性激活、归一化、残差、注意力、层间组合和解码策略。因此一个局部矩阵的误差可能被后续层吸收，也可能被放大。

### 5.5.2 一个局部误差上界

对于固定输入 `x`，线性层输出扰动是：

~~~math
\|(W-W_r)x\|_2
\leq \|W-W_r\|_2\|x\|_2
=\sigma_{r+1}\|x\|_2
~~~

这是谱范数提供的最坏方向上界。它说明：如果输入恰好沿着被丢弃部分的最大奇异方向，输出变化可能达到这个量；如果真实输入很少落在这些方向上，平均扰动可能小得多。

对有 Lipschitz 常数的后续函数 `f`，可以写出教学性的边界：

~~~math
\|f(Wx)-f(W_rx)\|_2
\leq L_f\,\|(W-W_r)x\|_2
~~~

这里 `L_f` 是后续映射对输入扰动的放大上界。真实 Transformer 的层叠结构通常很复杂，难以用一个紧的常数描述，所以这条式子适合建立直觉，不应被当成生产质量承诺。

### 5.5.3 评估应当怎样设计

一个低秩压缩实验至少应同时记录四类量：

1. 矩阵层面：rank、Frobenius 误差、谱误差、能量保留率；
2. 模型层面：困惑度、log probability 或隐藏层偏移；
3. 任务层面：代码、数学、格式、事实性、安全和业务指标；
4. 系统层面：权重大小、峰值显存、吞吐、延迟和单位成功任务成本。

如果只报告能量保留率，就无法判断压缩是否值得上线。如果只报告一个平均准确率，又可能掩盖安全、长尾类别或结构化输出的回归。矩阵分解提供候选方案，实验协议负责判断候选方案是否适合目标。

## 5.6 PCA：从样本矩阵中寻找主方向

### 5.6.1 数据矩阵和中心化

PCA 的对象不是一个待压缩的权重矩阵，而是一批样本。设有 `n>0` 个样本，每个样本有 `d>0` 个特征，按行组成：

~~~math
X\in\mathbb{R}^{n\times d}
~~~

第 `j` 个特征的均值组成向量 `mu`。中心化是：

~~~math
X_c=X-\mathbf{1}\mu^{\mathsf T}
~~~

其中 `1` 是长度为 `n` 的全 1 列向量。中心化非常重要：如果不减均值，第一主方向可能主要描述“所有样本都离原点很远”，而不是描述样本之间的变化。

以总体协方差的教学定义为例：

~~~math
C=\frac{1}{n}X_c^{\mathsf T}X_c
~~~

`C` 的形状是 `d × d`，第 `i,j` 个元素描述两个特征共同变化的程度。统计学中也常用 `1/(n-1)` 的样本协方差。两者只差整体缩放，特征向量方向不变，但特征值和 explained variance 的绝对数值会随约定变化。

### 5.6.2 特征值和最大方差方向

对任意单位方向 `v`，样本投影到该方向后的方差是：

~~~math
\mathrm{Var}(X_cv)=v^{\mathsf T}Cv,\qquad \|v\|_2=1
~~~

最大化这个方差，会得到协方差矩阵最大特征值对应的特征向量：

~~~math
Cv_i=\lambda_i v_i
~~~

按 `lambda_1 >= lambda_2 >= ...` 排序后，前 `k` 个向量构成主成分方向。样本降维结果为：

~~~math
Z=X_cV_k,\qquad
V_k\in\mathbb{R}^{d\times k},\quad
Z\in\mathbb{R}^{n\times k}
~~~

PCA 不是在寻找“最能分类的方向”。它优化的是线性投影下的方差或重构误差。如果类别差异位于低方差方向，PCA 可能把它排在后面。

### 5.6.3 PCA 和 SVD 的关系

令 $p=\min(n,d)$，对中心化矩阵做 reduced SVD：

~~~math
X_c=U_p\Sigma_pV_p^{\mathsf T},\qquad
U_p\in\mathbb{R}^{n\times p},\quad
\Sigma_p=\mathrm{diag}(\sigma_1,\ldots,\sigma_p),\qquad
V_p\in\mathbb{R}^{d\times p}
~~~

于是协方差可写成：

~~~math
C=\frac{1}{n}V_p\Sigma_p^2V_p^{\mathsf T}
~~~

$V_p$ 的列是协方差矩阵对应的特征方向，对应前 $p$ 个特征值；若 $p<d$，其余 $d-p$ 个特征值为 0：

~~~math
\lambda_i=\frac{\sigma_i^2}{n}
~~~

例如取四个二维样本 $(2,1),(1,0),(-1,-1),(-2,0)$，它们的均值为零。直接相乘得到：

~~~math
X_c^{\mathsf T}X_c=
\begin{bmatrix}10&3\\3&2\end{bmatrix},\qquad
C=\frac14X_c^{\mathsf T}X_c=
\begin{bmatrix}2.5&0.75\\0.75&0.5\end{bmatrix}
~~~

特征方程为 $(2.5-\lambda)(0.5-\lambda)-0.75^2=0$，即 $\lambda^2-3\lambda+11/16=0$，所以特征值是 $\lambda_1=11/4=2.75$、$\lambda_2=1/4=0.25$。代入 $(C-\lambda_1I)v_1=0$，可取第一主方向 $v_1=(3,1)^{\mathsf T}/\sqrt{10}$；它解释的方差比例为 $2.75/(2.75+0.25)=11/12\approx91.7\%$。对应的奇异值是 $\sqrt{11}$ 和 $1$，代入 $\lambda_i=\sigma_i^2/n$ 会得到同一组特征值。这也说明软件库可以直接通过中心化数据的 SVD 实现 PCA，而不必显式构造 $d\times d$ 的协方差矩阵；特征维度很大时，这样还能减少协方差矩阵的内存和数值计算负担。

### 5.6.4 Explained variance ratio

当总方差 `\sum_j\lambda_j>0` 时，第 `i` 个主成分解释的方差比例是：

~~~math
\mathrm{EVR}_i=\frac{\lambda_i}{\sum_j\lambda_j}
~~~

前 `k` 个主成分累计比例为：

~~~math
\mathrm{EVR}_{1:k}=\frac{\sum_{i=1}^{k}\lambda_i}{\sum_j\lambda_j}
~~~

如果所有样本完全相同，总方差为 0，EVR 没有定义；这不是“第一主成分解释了 0%”的普通结果，而是数据没有可解释的方差。`k` 也必须是 `0<=k<=d` 的整数。

它和 SVD 的奇异值能量比例形式相同，但对象不同：SVD 可以直接作用于任意矩阵，PCA 作用于中心化样本矩阵并把方向解释为数据方差。一个权重矩阵做 SVD，不等于对它做了 PCA；只有明确了样本、特征、中心化和协方差语义，才可以说是在做 PCA。

## 5.7 PCA 的预处理、泄漏和解释边界

### 5.7.1 训练集统计量必须隔离

如果 PCA 用于下游预测，均值、标准差和主成分方向都属于从数据学习到的变换。正确流程是只用训练集拟合：

~~~math
(\mu_{\mathrm{train}},V_{\mathrm{train}})
=\mathrm{fit}(X_{\mathrm{train}})
~~~

然后把同一个变换应用到验证集和测试集：

~~~math
Z_{\mathrm{test}}
=(X_{\mathrm{test}}-\mathbf{1}\mu_{\mathrm{train}}^{\mathsf T})
V_{\mathrm{train},k}
~~~

如果先把测试集也用于计算均值或主方向，测试分布的信息就泄漏进了训练流程。即使 PCA 本身没有标签，也会让测试指标过于乐观。分析 hidden states 时也应记录采样范围、层、位置、语言和任务分布，否则不同实验的主方向无法直接比较。

可以用三个二维点看出这种泄漏怎样改变坐标系。训练样本取 $(0,0)$ 和 $(2,0)$，按 $1/n$ 计算的协方差为 $\begin{bmatrix}1&0\\0&0\end{bmatrix}$，第一主方向沿 $x$ 轴。现在有一个测试点 $(0,10)$；若错误地把它并入拟合，三个点的均值变为 $(2/3,10/3)$，协方差变为 $\begin{bmatrix}8/9&-20/9\\-20/9&200/9\end{bmatrix}$，最大方差方向几乎转到 $y$ 轴。模型并没有看测试标签，但变换已经使用了测试分布，后续指标因此不再是纯粹的留出评估。PCA 拟合数据与评估数据的切分顺序，属于更广义的数据划分和泛化问题，详见[第六章《统计学习与泛化》](06-统计学习与泛化.md)；本节聚焦变换统计量如何改变坐标系。

### 5.7.2 标准化不是总是正确

对每个特征除以标准差，会让量纲不同的特征拥有相近的影响；但在 embedding 分析中，标准化可能改变原本有意义的坐标尺度。是否标准化取决于问题：

- 对量纲差异很大的传感器特征，标准化可能合理；
- 对已经归一化的 embedding，重复标准化可能改变距离结构；
- 对不同层 hidden state，先记录范数和均值，再决定是否处理；
- 对异常值明显的数据，PCA 可能被少数样本牵引，需要稳健方法或先做数据审计。

因此“PCA 前一定标准化”不是通用规律。预处理应当成为实验变量，并和目标解释保持一致。

例如，三点 $(1,1000),(2,1100),(3,900)$ 的两个特征彼此不相关，按 $1/n$ 计算的方差分别为 $2/3$ 和 $20000/3$。不标准化时，第一主成分完全沿第二个特征轴；按各自标准差标准化后，两轴方差都变成 $1$，最大特征值出现并列，方向不再唯一。这里的变化并非算法出错，而是研究者把“保留原单位下的总变化”改成了“让两个特征拥有相同权重”。先写清问题采用哪一种权重，才能解释主方向。

### 5.7.3 PCA 不是因果解释

主成分方向是样本协方差的统计结果，不自动对应“知识方向”“安全方向”或“语义方向”。如果研究者把某个方向和标签相关联，需要进一步做投影、分类、干预和反事实实验。例如，观察某方向上的类别均值差异只能说明相关性；沿该方向修改表示后行为发生变化，才为因果作用提供更强证据，但仍需排除其他变化。

## 5.8 四个相似概念的边界

### 5.8.1 SVD 是分解工具

SVD 对一个矩阵进行正交方向分解，给出奇异值和左右奇异向量。它可以用于求解最小二乘、分析条件数、构造伪逆、做低秩近似或帮助理解表示。它本身没有规定矩阵来自权重、样本还是 embedding。

### 5.8.2 PCA 是统计降维方法

PCA 先把样本矩阵中心化，再寻找最大方差的线性子空间。它有明确的数据统计语义，目标通常是保留方差或降低线性重构误差。PCA 可以用 SVD 计算，但二者不是同义词。

### 5.8.3 低秩压缩近似原始权重

低秩压缩直接把原权重 `W` 替换为 `W_r` 或 `AB`。它的收益可能包括模型文件变小、矩阵乘法变快和内存带宽降低；代价是原模型函数发生变化，必须做回归评估。

### 5.8.4 LoRA 参数化微调增量

LoRA 冻结基础权重 `W`，训练：

~~~math
\Delta W=BA
~~~

并在前向时使用 `W + scaling * Delta W`。它并不要求 `W` 本身是低秩，也不保证训练后的完整权重 `W+\Delta W` 低秩。LoRA 的主要收益在训练参数、梯度和优化器状态，而不是必然降低基础模型的前向成本。

### 5.8.5 可视化是观察手段

PCA、t-SNE、UMAP 等可以把高维向量映射到二维或三维，帮助发现聚类、离群点和分布漂移。它们的坐标和距离带有算法偏差，适合探索和生成假设，不适合独立证明模型能力或因果机制。

因此选方法时先说清要保留的关系：PCA 保留线性投影中的方差，t-SNE 和 UMAP 主要围绕邻域关系优化布局。若问题是“近邻检索有没有变化”，应在原向量上计算近邻重合率、Recall@k 或 MRR，再把降维图当作定位异常点的辅助视图；若问题是“某个因素造成了行为变化”，二维图本身不构成因果识别设计。

实际分析时可以先用 PCA 检查主变化方向，再用邻域方法观察局部结构，最后回到原空间抽查最近邻文本。若 PCA 与 UMAP 都把某批样本显示成一簇，这仍只是两种变换下的观察，不代表该簇在任务中有稳定意义；应检查不同随机种子、采样和标签切分，并用留出的查询计算检索指标。可视化的作用是提出“哪些样本值得查”的问题，结论需要由样本内容和定量评估来回答。

## 5.9 低秩权重压缩：收益和代价

### 5.9.1 计算图的改变

假设一个线性层按行向量写成 $Y=XW$，其中 $X$ 有 $n_b$ 个样本、形状是 $n_b\times m$，$W$ 的形状是 $m\times n$。为避免和 batch 大小混淆，低秩因子记作 $P,Q$：

~~~math
W\approx PQ,\qquad
P\in\mathbb{R}^{m\times r},\quad
Q\in\mathbb{R}^{r\times n}
~~~

则：

~~~math
Y\approx (XP)Q
~~~

忽略常数和实现细节，按一次乘加计一个单位，原始乘法规模约为 $n_bmn$，因子化后约为：

~~~math
n_bmr+n_brn=n_br(m+n)
~~~

例如 $m=4$、$n=6$、$r=2$、$n_b=3$ 时，原矩阵有 $mn=24$ 个参数，因子只有 $r(m+n)=20$ 个；原始乘法约需 $3\times4\times6=72$ 个乘加单位，因子化后约需 $3\times2\times(4+6)=60$ 个。按此口径，只有 $r<mn/(m+n)$ 时理论乘加量才会降低；方阵 $m=n=d$ 时即 $r<d/2$。若用 FLOPs 计数，一次乘加通常记为两次浮点运算。实际速度还会受到 kernel、并行度、内存访问和 batch 大小影响。

### 5.9.2 分层压缩不能只看一个阈值

不同 Transformer 层的奇异值谱可能差异很大。统一使用同一个 rank 有利于实现简单，却可能浪费容量：谱衰减快的层可以用更低 rank，谱衰减慢的层需要更高 rank。更合理的做法是先对各层计算候选 rank，再在总参数或延迟预算下分配：

~~~math
\min_{r_1,\ldots,r_L}
\sum_{\ell=1}^{L}\mathcal{E}_{\ell}(r_\ell)
\quad
\mathrm{s.t.}\quad
\sum_{\ell=1}^{L}r_\ell(m_\ell+n_\ell)\leq P_{\max}
~~~

其中 `E_l` 可以是矩阵误差，也可以加入敏感性权重。仅凭矩阵误差排序仍不够，最终需要在任务集上验证。

### 5.9.3 误差补偿

压缩后可以做少量校准或蒸馏，让压缩模型在代表性输入上的中间激活接近原模型。例如：

~~~math
\mathcal{L}_{\mathrm{distill}}
=\frac{1}{N}\sum_{i=1}^{N}
\|h_{\mathrm{compressed}}^{(i)}
-h_{\mathrm{base}}^{(i)}\|_2^2
~~~

这类目标能减少局部表示偏移，但也可能把校准集分布过拟合。校准数据需要覆盖真实请求，包括长上下文、结构化输出、工具调用和安全场景；否则模型在未覆盖的行为上仍可能出现回归。

## 5.10 LoRA：低秩的是更新，不是基础权重

### 5.10.1 从全参数微调开始

设基础线性层为 `W`。全参数微调会学习一个与 `W` 同形状的增量：

~~~math
W'=W+\Delta W,\qquad
\Delta W\in\mathbb{R}^{m\times n}
~~~

若 `m` 和 `n` 都很大，`Delta W` 的参数量为 `mn`。LoRA 的假设是：对于某类下游任务，所需的变化可以在一个低维子空间中表达，因此将增量写成：

~~~math
\Delta W=BA,\qquad
B\in\mathbb{R}^{m\times r},\quad
A\in\mathbb{R}^{r\times n},\quad
r\ll\min(m,n)
~~~

这里采用与行向量线性层一致的形状约定。如果采用列向量约定，也常写成 `AB`，其中两个因子的形状相应转置。真正不变的是：乘积的结果必须和 `W` 同形状，且乘积 rank 不超过 `r`。

### 5.10.2 前向计算

对 batch 输入 `X`：

~~~math
Y=XW+\frac{\alpha}{r}XBA
~~~

其中 `alpha` 是缩放超参。将其写成：

~~~math
Y=X\left(W+\frac{\alpha}{r}BA\right)
~~~

可以看出，LoRA 训练时的有效权重是基础权重加上一个低秩增量。基础权重通常冻结，梯度只更新 `A` 和 `B`。冻结不意味着基础权重不参与反向图的计算，它仍然参与前向和对 adapter 参数的梯度传播；冻结主要减少了基础参数本身的梯度和优化器状态。

### 5.10.3 为什么常见初始化让增量一开始为零

为了让训练开始时的模型行为接近基础模型，常见做法是把一个因子初始化为零，另一个因子使用随机初始化。于是：

~~~math
\Delta W_0=B_0A_0=0
~~~

这样第一步的输出不会突然偏离基础模型。若两个因子都初始化为零，虽然增量也是零，但对两个因子的梯度可能同时为零，训练无法正常启动。因此“保持初始行为”和“让梯度能够开始流动”需要同时考虑。

### 5.10.4 缩放因子不是免费旋钮

常见 LoRA 将 $\Delta W$ 乘以 $\alpha/r$。增大 $\alpha$ 可能加快行为变化，也可能造成训练不稳定或过度偏离基础模型；而固定 $\alpha$ 时，秩增大又会让这个显式系数变小。它只是乘在两个因子乘积外的系数，不等于实际更新范数，因为 $A$、$B$ 的初始化、范数和训练轨迹也会变化。

rank-stabilized LoRA（rsLoRA）针对高秩下的缩放提出另一种取法：在论文给出的初始化与渐近稳定性条件下，将 $\alpha/r$ 改为 $\alpha/\sqrt r$。[rsLoRA 原论文](https://arxiv.org/abs/2312.03732)以零初始化的一个因子、另一个因子各元素独立同分布且方差不随 $r$ 增长等条件推导该结论；论文也报告了特定模型与数据实验。它提供了一个值得纳入秩消融的候选设置，但不保证在每个模型、目标模块或数据集上都更好。

用 $\alpha=16$ 看显式系数如何随秩变化：

| $r$ | $\alpha/r$ | $\alpha/\sqrt r$ |
| ---: | ---: | ---: |
| 4 | 4 | 8 |
| 16 | 1 | 4 |
| 64 | 0.25 | 2 |

表格只比较缩放公式，不直接比较训练后的 $\|\Delta W\|$ 或任务分数。公平实验仍需记录秩、缩放规则、学习率、初始化、目标模块、训练步数与数据量。

2026 年一篇 LoRA-$\alpha$ 预印本进一步把缩放系数和学习率作为不同的优化变量，在论文所测的 Llama 3、Tulu 3 与 OpenThoughts 等设置中报告：提高 $\alpha$ 与提高学习率并不等价，并将其最优系数拟合为带较大常数的平方根随秩变化。[LoRA-$\alpha$ 预印本](https://arxiv.org/abs/2606.12883)的理论和实验仍受其优化器、初始化、模型与任务设定限制，尚不足以替代通用配方。它提醒我们：上表只演示两种归一化函数的秩依赖；$\alpha$ 的合适取值仍须和学习率、初始化及目标任务一起消融。

### 5.10.5 DoRA：把更新拆成幅度和方向

DoRA 处理的是另一种限制：它把权重更新分成幅度变化和方向变化，方向仍由低秩更新表达。按原论文的矩阵约定，$W_0\in\mathbb{R}^{d_{\mathrm{out}}\times d_{\mathrm{in}}}$；$\|\,\cdot\,\|_c$ 表示逐列的 L2 范数，$m$ 为每列一个可训练幅度参数：

~~~math
W'=
m\odot
\frac{W_0+BA}{\|W_0+BA\|_c}
~~~

初始时令 $m=\|W_0\|_c$ 且 $BA=0$，即可还原基础权重。一个二维列向量 $w_0=(3,4)^{\mathsf T}$ 的长度为 5；若低秩方向更新后变为 $v=(4,3)^{\mathsf T}$，同时学得幅度 $m=6$，则新列为 $\frac65v=(4.8,3.6)^{\mathsf T}$。方向发生变化而长度单独变为 6，这就是幅度与方向分开学习的直觉；这个二维算例只解释归一化，不代表模型训练结果。

DoRA 论文在其 LLaMA、LLaVA、VL-BART 任务上报告了相对 LoRA 的结果，并说明合并权重后可用于推理；这属于作者报告的具体实验，不构成所有任务的质量保证。有关权重合并、量化兼容和训练开销的实际行为仍应按框架版本与目标模型核验。[DoRA 原论文](https://arxiv.org/abs/2402.09353)。

## 5.11 LoRA 参数量、显存和实际计算

### 5.11.1 参数量公式

对于 `m × n` 的权重，LoRA 两个因子的参数量为：

~~~math
N_{\mathrm{LoRA}}=mr+rn=r(m+n)
~~~

在 `m,n>0` 且 `1<=r<=min(m,n)` 的低秩设定下，相对全参数更新比例为：

~~~math
\rho=\frac{r(m+n)}{mn}
~~~

当 `m=n=4096`、`r=8` 时：

~~~math
N_{\mathrm{full}}=4096^2=16\,777\,216
~~~

~~~math
N_{\mathrm{LoRA}}=8(4096+4096)=65\,536
~~~

~~~math
\rho=\frac{65\,536}{16\,777\,216}
\approx0.003906
~~~

也就是约 `0.3906%` 的可训练参数。这个比例只对应一个线性层；真实模型要把所有目标模块的因子参数相加。若 Q、K、V 和 MLP 都挂 adapter，参数量会高于只给 Q、V 挂 adapter 的配置。

### 5.11.2 为什么训练显存通常下降

训练显存大致由以下部分组成：

~~~math
M_{\mathrm{train}}
\approx M_{\mathrm{weights}}
+M_{\mathrm{gradients}}
+M_{\mathrm{optimizer}}
+M_{\mathrm{activations}}
+M_{\mathrm{temporary}}
~~~

LoRA 主要减少可训练参数对应的梯度和优化器状态。它不自动消除基础模型权重和前向激活，因此长序列、较大 batch 或深层网络仍然可能受 activation memory 限制。使用 gradient checkpointing、量化或更小的 micro-batch 是不同的内存手段，不能都归功于 LoRA。

### 5.11.3 训练省参数不等于推理省延迟

如果推理时保留两个 adapter 分支，线性层会多出：

~~~math
XBA
~~~

这部分计算在 rank 很小时可能可接受，但仍会增加 kernel 调度和内存访问。若把 adapter 合并：

~~~math
W_{\mathrm{merged}}=W+\frac{\alpha}{r}BA
~~~

推理图就可以恢复为一个普通线性层。合并适合只服务一个 adapter 的部署；需要在多个任务间切换时，保留独立 adapter 更灵活。合并前要确认 dtype、量化格式和存储精度，否则写回可能引入额外舍入误差。

## 5.12 LoRA 的目标模块和能力分工

### 5.12.1 Attention 投影

Transformer 注意力中的 Q、K、V 和输出投影都是线性变换。给 Q 或 K 加 adapter，可能改变 token 之间的匹配和注意力分布；给 V 或输出投影加 adapter，可能改变被传递和混合的内容。它们不是严格的一一对应关系，具体能力还受层位置、数据和基础模型影响。

### 5.12.2 MLP 投影

MLP 的 up、down、gate 投影负责把隐藏状态映射到更高维中间空间，再压回 hidden size。它们会影响特征组合和非线性变换。只调 attention 可能对格式或上下文交互有效，但在需要较大知识或风格变化的任务上，加入 MLP 目标模块可能更有表达空间，同时增加参数和回归风险。

### 5.12.3 选择模块的实验逻辑

与其把“全模块”当成默认最优，不如把目标模块看成一个实验因素。一个最小消融可以包含：

| 配置 | 目标模块 | 观察重点 |
| --- | --- | --- |
| A | Q、V | 参数少，观察基本适配能力 |
| B | Q、K、V、输出投影 | 观察注意力路径的额外收益 |
| C | Attention 加 MLP | 观察更大表达空间是否带来任务收益 |
| D | 全模块但降低 rank | 在相近参数预算下比较覆盖范围 |

每个配置要使用相同数据切分、训练步数、随机种子集合和评估脚本。只比较训练 loss 会偏向更容易拟合的配置；应同时报告任务质量、基础能力回归、峰值显存和推理延迟。

## 5.13 Rank 选择：把超参变成可解释实验

### 5.13.1 rank 太小和太大的两种失败

rank 太小时，`BA` 的列空间和行空间都受到限制。即使训练 loss 下降，模型也可能无法同时学习多个独立行为，例如既遵守结构化输出，又保持领域术语准确，还要完成工具调用。表现上常见为某些简单样本变好，但复杂组合样本不变。

rank 太大时，adapter 更接近自由矩阵，参数、优化器状态和过拟合风险增加。它并不保证更好的泛化，尤其在样本少、标签噪声大或训练轮次过多的场景。大 rank 还可能把基础模型原有能力改得过深，造成通用能力回归。

### 5.13.2 参数预算下的选择

如果给定总 adapter 参数预算 `P`，目标模块集合为 `S`，每个模块形状为 `m_j × n_j`，rank 相同时可近似满足：

~~~math
r\sum_{j\in S}(m_j+n_j)\leq P
~~~

因此“加入更多模块”和“提高每个模块 rank”是两个不同方向。前者扩大被修改的路径，后者增加每条路径的子空间维度。预算固定时，应通过消融判断哪一种更适合任务。

### 5.13.3 一个完整的 rank 消融

以 `r∈{2,8,32}` 为例，实验表至少包括：

| 项目 | r=2 | r=8 | r=32 |
| --- | ---: | ---: | ---: |
| 可训练参数 | 记录实测 | 记录实测 | 记录实测 |
| 训练峰值显存 | 记录实测 | 记录实测 | 记录实测 |
| 结构化输出通过率 | 记录实测 | 记录实测 | 记录实测 |
| 领域事实准确率 | 记录实测 | 记录实测 | 记录实测 |
| 基础能力回归 | 记录实测 | 记录实测 | 记录实测 |
| p95 延迟 | 记录实测 | 记录实测 | 记录实测 |

如果 `r=32` 只带来很小的质量收益，却显著增加成本，那么 `r=8` 可能是更好的工程选择；如果 `r=2` 在关键任务上出现结构性失败，即使平均分差不大，也不能只因为它便宜就选它。rank 的选择是一个带预算和约束的决策，而不是数学上存在唯一答案。

## 5.14 QLoRA：量化基础模型与低秩适配器

### 5.14.1 两个正交的动作

QLoRA 将冻结的低比特基础模型与可训练 LoRA adapter 组合；梯度穿过量化基础模型以更新 adapter。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)进一步组合 NF4、Double Quantization 和 paged optimizer 来处理量化与显存峰值。本章只用两个动作建立数学账本：

1. 用低比特格式存储冻结的基础模型权重；
2. 在计算图上训练一个低秩 adapter。

计算图中要分清存储值和参与乘法的值。QLoRA 论文描述的做法是把低比特权重临时反量化到计算 dtype，再执行前向和反向；冻结表示不计算基础权重的参数更新，但这些权重仍参与前向，也让误差梯度传回 adapter。换言之，训练没有切断基础网络，也不是直接用 4-bit 算术完成所有乘法。存储位宽、计算精度和哪些参数接收更新，是三个不同问题。

量化降低的是基础权重的存储成本，LoRA 降低的是可训练更新的参数成本。二者可以组合，但一个并不推出另一个。没有量化的 LoRA 仍然是 LoRA；没有 LoRA 的量化也可以用于纯推理或其他微调方法。NF4、双重量化、分页优化器和完整训练显存账本见[第五册第八章第 8.11 节](../../book-05-llm-training/chapters/08-显存优化与数值精度.md)；这里的计算只估算理想化基础权重存储。

### 5.14.2 权重显存的下界估算

如果有 `N>0` 个参数，每个参数平均用 `b>0` bit 存储，理想化权重大小为：

~~~math
M_{\mathrm{weight}}\approx\frac{Nb}{8}
~~~

例如 7B 参数模型：

~~~math
M_{\mathrm{BF16}}\approx\frac{7\times10^9\times16}{8}
=14\times10^9\ \mathrm{bytes}
\approx13.04\ \mathrm{GiB}
~~~

~~~math
M_{\mathrm{INT4}}\approx\frac{7\times10^9\times4}{8}
=3.5\times10^9\ \mathrm{bytes}
\approx3.26\ \mathrm{GiB}
~~~

这是理想化的权重存储估算，不是“运行 7B QLoRA 只需要 3.26 GiB”。实际还包括 group scale、zero point 或其他量化元数据、未量化参数、adapter 权重、激活、梯度、优化器状态、临时 workspace 和框架缓存。序列长度和 micro-batch 可能使 activation 成为主要开销。

元数据也能手算。QLoRA 原论文在权重分块大小为 64、一级缩放常数用 FP32 的设置下，量化常数平均额外占 $32/64=0.5$ bit/参数；二次量化后，论文给出的平均开销是 $8/64+32/(64\times256)=0.127$ bit/参数，节省 $0.373$ bit/参数。若按 7B 参数估算，这相当于约 $0.304$ GiB 的存储差额；该数值依赖论文中的分块和元数据格式，不能直接套到其他后端。

再单独估计一个 $4096\times4096$ 层上的 rank-8 adapter：它有 $65{,}536$ 个参数。若仅作账本假设，把 adapter 权重和梯度各按 2 bytes、Adam 的两个 FP32 矩各按 4 bytes 计，每个可训练参数合计 12 bytes，四项共 $786{,}432$ bytes，也就是 $0.75$ MiB。实际优化器实现可能改变状态精度或存放位置；这个小账本只帮助区分基础权重、adapter 状态与 activation，不能代替峰值显存实测。

### 5.14.3 量化误差的传递

把权重 `W` 量化为 `Q(W)`，可以写出线性层的输出变化：

~~~math
\Delta y=(Q(W)-W)x
~~~

如果量化误差集中在输入经常使用的方向上，任务影响会比同样大小的随机误差更严重。LoRA adapter 可以在一定程度上补偿这些误差和任务适配差异，但它不是无限容量的误差修复器。rank、校准数据、量化格式和计算 dtype 共同决定结果。

用一个人为的粗量化矩阵算一次输出。令 $W=\begin{bmatrix}1&-0.5\\0.25&-0.75\end{bmatrix}$，把一个元素按假设的网格近似成 $0.75$，得到 $Q(W)=\begin{bmatrix}0.75&-0.5\\0.25&-0.75\end{bmatrix}$。对输入 $x=(2,1)$，原输出是 $(2.25,-1.75)$，量化输出是 $(1.75,-1.75)$，所以 $\Delta y=(-0.5,0)$。这只是说明量化误差怎样沿输入传播，不是 NF4 的实际量化规则或性能实验；换一个输入方向，输出误差也会不同。adapter 若拟合了这一个样本，仍须检查其他输入上的残差和任务回归。

### 5.14.4 量化训练的评估

QLoRA 实验至少应与 BF16/FP16 LoRA baseline 对照，并固定：

- 基础模型和 tokenizer；
- chat template、数据切分和有效 token 数；
- adapter 的目标模块、rank、alpha 和学习率；
- 计算 dtype、量化配置和硬件；
- 评估任务、解码参数和随机种子。

除了平均任务分数，还要观察长文本、代码、数学、结构化输出、安全和多轮对话。量化可能在平均值变化很小的情况下，显著影响某个脆弱行为。

比较时应从同一基础 checkpoint 派生量化和 BF16 两条支路，并使用相同 tokenizer、模板、训练数据、有效 token、adapter 目标模块与优化步数。若量化支路换了 adapter rank 或学习率，就同时改变了训练容量和优化轨迹，不能把差异只归给位宽。报告峰值显存时也要写清设备、序列长度、micro-batch 和是否启用 checkpointing；否则一个模型大小数字无法说明实际训练预算。

分页 optimizer 处理的是显存紧张时优化器状态的换入换出，不等于把状态自动量化，也不会减少需要更新的参数数量。它可能降低某些峰值，却带来换页和吞吐代价。复现实验应分别报告峰值显存、训练速度和是否发生换页；否则容易把显存峰值改善误认为基础权重又压缩了一层。

## 5.15 Embedding 几何：相似度、降维与检索

### 5.15.1 向量相似度不等于语义真值

embedding 检索常使用余弦相似度：

~~~math
\mathrm{cos}(u,v)=\frac{u^{\mathsf T}v}{\|u\|_2\|v\|_2}
~~~

这里要求 `u` 和 `v` 同维、有限且都不是零向量；零向量的余弦相似度没有定义。工程系统应把 embedding 失败单独记录，而不是把它静默转换成某个最低分。

当向量已做 L2 归一化时，余弦相似度等于内积。它适合把“方向相近”作为检索信号，但相似度由训练目标、数据分布、语言、领域和归一化方式决定。一个高相似度结果仍可能缺少时间、权限或数值条件，不能仅凭 embedding 分数直接作为生成答案的证据。

以二维构造向量手算排序。查询 $q=(1,1)$，相关条款 $d_1=(1,0)$，而一个措辞相近但不支持问题的条款 $d_2=(2,1)$。它们的余弦分数分别为 $1/\sqrt2\approx0.707$ 和 $3/\sqrt{10}\approx0.949$，所以系统会把不支持答案的 $d_2$ 排在前面。若只看 Top-1，这个查询未命中；看 Top-2 才包含相关条款。该构造例不代表真实编码器，只说明向量相似度给出的是候选排序，相关性和证据支持仍要用标注查询集测量。

### 5.15.2 PCA 可视化的正确问题

把 embedding 降到二维后，可以问：

- 同一数据源是否出现异常簇；
- 微调前后同一类样本的相对位置是否变化；
- 新请求是否落在训练分布之外；
- 某种预处理是否造成了明显的语言或长度分层。

这些是分布探索问题。若要回答“检索是否变好”，还需要 recall@k、MRR、nDCG、引用支持率或任务成功率。若要回答“模型是否理解某概念”，还需要受控测试和反事实实验。

### 5.15.3 t-SNE 和 UMAP 的距离边界

t-SNE 把高维邻近关系转成概率，并在低维空间优化相似度分布；UMAP 先构造带权邻域图，再优化低维布局。[t-SNE 原论文](https://jmlr.org/papers/v9/vandermaaten08a.html)、[UMAP 原论文](https://arxiv.org/abs/1802.03426)均说明其目标是保留特定的邻域/图结构，而不是所有高维点对距离。UMAP 论文还展示了邻居数和 min_dist 等超参会改变图形。因此，不能把不同簇之间的二维间距直接当作高维距离或任务质量；PCA 保持的则是线性投影下的方差结构。三者的二维坐标不能直接互换，也不能用“簇更紧”作为未经校准的质量指标。

做可视化时应固定采样、随机种子、预处理和超参，并保留高维定量指标。对于大量 token-level hidden states，还要明确采的是哪个层、哪些位置、多少 token，以及是否按文档或样本聚合；否则一张漂亮的图可能只是采样策略的产物。

一个小评估账本可以把图和检索指标分开：假设有 10 个带人工相关文档的查询，原向量的 Recall@2 为 $8/10=0.8$；降维图看起来簇更分明，并不改变这个检索结果。若改用另一种投影后 Recall@2 变成 $7/10=0.7$，应先调查近邻损失和失败查询，而不是用视觉上更紧的簇覆盖定量回退。样本数只有 10 时，比例也很不稳定；它适合演示分母，不足以作生产结论。

UMAP 的近邻参数 $n$ 控制局部度量所看的邻域尺度，$\mathrm{min\_dist}$ 影响低维布局中近点可以挤得多紧；原论文用同一数据改变这两个设置，展示了布局和可见结构会随设置变化。比如对 30 条构造向量分别用 5 个和 20 个近邻作图，前者可能把细小差别显示为多个小簇，后者可能把它们平滑到较大的邻域。图形变化说明分析尺度变了，不能据此断言数据真实存在两层类别。对照图应固定其余设置，只改变一个旋钮并保留参数记录。

要比较两个 embedding 版本的邻居稳定性，可以对同一查询保留原空间的 Top-5 文档。假设旧版本为 A、B、C、D、E，新版本为 A、B、C、F、G，交集有 3 个，合并集合有 7 个，Jaccard 重合率是 $3/7\approx0.429$。这个数值只表示邻居变化幅度，无法判断新版本更好；还要检查被换出的文档是否相关，并用带标注的查询集计算 Recall@k 或 MRR。这样图、向量距离和业务相关性各自承担不同的判断任务。

实际检索评估还要固定查询语言、文档切片长度、去重规则和相关性标注粒度。若同一篇文档切成很多重叠片段，Recall@k 可能因重复命中而显得较高；若训练和评测共享近重复条款，结果也会高估跨文档泛化。报告指标时应同时给出查询数、切片策略和按查询聚合的规则，才能复算分母并定位排序错误。

## 5.16 综合案例：为合同助手选择低秩方案

假设一个合同助手需要在三类任务上工作：

1. 把合同条款抽取为固定 JSON；
2. 根据检索到的条款回答问题并给出支持片段；
3. 在缺少证据时明确表示无法判断。

团队有两种候选方案。方案 A 只给 Q、V 投影挂 rank-8 LoRA，基础模型使用 BF16；方案 B 给 attention 和 MLP 的多个投影挂 rank-32 LoRA，基础模型用 4-bit 存储。不能只看方案 B 的可训练参数是否更多，也不能只看量化后的权重大小。

首先建立对象账本：

| 层次 | 方案 A | 方案 B |
| --- | --- | --- |
| 基础权重 | BF16 | 4-bit，含量化元数据 |
| 更新路径 | Q、V | Attention 加 MLP |
| adapter rank | 8 | 32 |
| 训练成本 | 受权重和 adapter 状态影响 | 受激活、量化 kernel 和 adapter 状态影响 |
| 推理路径 | 可合并或保留 adapter | 需确认量化推理与 adapter 组合 |

然后建立任务指标。JSON 任务记录 schema 合法率和字段准确率；问答任务记录答案正确率、引用支持率和无证据时的拒答质量；系统记录 p50/p95 延迟、峰值显存和单位成功任务成本。一个只提高答案流畅度、却降低引用支持率的方案不能被定义为整体改进。

接着做预算和消融。若方案 B 的大 rank 只改善常见条款，而在无证据测试集上增加了无依据回答，就需要单独调低 adapter 学习率、改变目标模块或增加拒答数据，而不是继续提高 rank。若方案 A 的 JSON 通过率好，但复杂条款组合失败，可以先扩大目标模块或提高 rank，再观察是否值得增加量化复杂度。

最后进行故障归因：

- 若所有任务的 hidden state 偏移很大，先检查 alpha、学习率和 merge；
- 若只有长合同失败，检查 chunk、位置和激活显存，不要先归因于 rank；
- 若检索正确但回答无引用，检查 prompt、解码和证据接口；
- 若 BF16 正常而 4-bit 失败，比较量化误差和 kernel 路径；
- 若训练集改善而测试集恶化，检查数据泄漏和过拟合。

再把方案差异落到可复算的对象上。假设比较的线性层都是 $64\times64$：方案 A 仅给 Q、V 两个投影挂 rank-8 adapter，每个投影有 $8(64+64)=1{,}024$ 个参数，总计 $2{,}048$；方案 B 给八个 attention/MLP 投影挂 rank-32 adapter，每个投影有 $4{,}096$ 个参数，总计 $32{,}768$，是 A 的 16 倍。这个算式只比较该教学层组，不代表真实模型所有层的总参数。

这个小矩阵还提醒我们检查是否真的省了参数。对 $64\times64$ 方阵，参数交叉点是 $r=64^2/(64+64)=32$；因此 B 的 rank-32 因子数恰好等于该投影的完整矩阵参数数。若只讨论这个教学尺寸，它可以比较“改更多路径”的效果，却不应称为压缩；把 rank 降到 16，每个投影才用 $2{,}048$ 个因子参数。真实模型投影通常远宽于 64，交叉点也随维度变化，实验要用实际 shape 重新计算。

假设团队另用一组 100 条构造查询做验收，其中 60 条检查 JSON、25 条检查带证据回答、15 条专门检查无证据场景。A 有 55/60 条 JSON 合法、21/25 条引用支持、1/15 条无证据错误作答；B 分别为 58/60、22/25 和 4/15。B 的格式合法率由 91.7% 升到 96.7%，引用支持率由 84% 升到 88%，但无证据错误率从 6.7% 升到 26.7%。若上线门槛要求无证据错误不超过 10%，B 即使前两项更好也不合格。所有计数都是教学用假设；15 条无证据样本只能演示分母，不能证明真实错误率，正式比较须增加样本并报告不确定性。

下一轮可先固定基础模型、量化格式、数据切分、训练步数和随机种子，只改变目标模块；确认覆盖范围后再固定模块比较 rank。这样能判断是“路径太窄”还是“子空间不够”，避免同时改 rank、模块和量化后把因果归到某一个旋钮。先约定安全、格式、引用等硬门槛，再在过门槛的候选间比较延迟和成功成本。

失败归因也应按指标分开：若 25 条有证据问题中只有引用支持不足，先检查检索召回、候选排序和引用接口；若 15 条无证据问题里错误作答明显增多，再检查拒答训练和决策边界。增加 rank 可能提高拟合能力，却不能自动修复检索漏召回或无证据时的校准。这样的分桶让下一次实验针对一个可观测机制，而不是笼统追求总分。

这个案例的核心不是选出一个固定的 rank，而是说明低秩方案必须放在“对象、预算、任务、系统和失败归因”共同构成的实验中判断。

对仅有 15 条的无证据子集，还应报告区间或继续积累失败样本，不能把一次构造计数当成稳定错误率；正式决策可将硬门槛应用于更大且按风险分层的留出集。

因此案例只支持一个带条件的当前决定：按给定的硬门槛先淘汰 B，再收集更多无证据样本复核 A；它不能证明 A 在总体上更优。若两方案都过门槛，可在同一批查询上比较逐例成败，并报告差异区间。配对数据能控制问题难度的部分差异，但随机生成和训练种子仍需单独重复，不能把查询数直接当成所有不确定性的样本量。

## 5.17 可运行的低秩实验

下面的纯 Python 代码故意使用一个已知奇异值的对角矩阵，而不是假装手写一个工业级 SVD。它验证五件事：高斯消元得到的数值 rank、截断误差、与 §5.6.3 同一组四点输入的 PCA 协方差和特征值、LoRA 因子乘积的 rank 上界，以及量化权重的理想化显存比例。辅助函数包含空矩阵、行长度不一致和乘法 shape 不匹配的检查。数值秩函数使用默认绝对阈值 $10^{-10}$；改变矩阵整体尺度会影响阈值判断，因此它只用于展示数值秩依赖容差，不替代数值库里的 rank/SVD 算法。

> **代码状态：已验证（2026-11-09；Python 3.12.9 标准库）**

~~~python
import math


def is_finite_number(value):
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        return False
    try:
        return math.isfinite(float(value))
    except OverflowError:
        return False


def matrix_shape(matrix):
    if not matrix or not matrix[0]:
        raise ValueError("matrix must be non-empty")
    if any(
        not isinstance(row, (list, tuple))
        or any(
            isinstance(value, bool)
            or not is_finite_number(value)
            for value in row
        )
        for row in matrix
    ):
        raise ValueError("matrix must contain finite numeric rows")
    width = len(matrix[0])
    if any(len(row) != width for row in matrix):
        raise ValueError("matrix rows must have equal length")
    return len(matrix), width


def transpose(matrix):
    rows, cols = matrix_shape(matrix)
    return [[matrix[i][j] for i in range(rows)] for j in range(cols)]


def matmul(left, right):
    left_rows, left_cols = matrix_shape(left)
    right_rows, right_cols = matrix_shape(right)
    if left_cols != right_rows:
        raise ValueError(
            f"shape mismatch: {(left_rows, left_cols)} x {(right_rows, right_cols)}"
        )
    right_t = transpose(right)
    return [
        [sum(x * y for x, y in zip(row, col)) for col in right_t]
        for row in left
    ]


def add(left, right):
    if matrix_shape(left) != matrix_shape(right):
        raise ValueError("add requires equal shapes")
    return [
        [x + y for x, y in zip(left_row, right_row)]
        for left_row, right_row in zip(left, right)
    ]


def subtract(left, right):
    if matrix_shape(left) != matrix_shape(right):
        raise ValueError("subtract requires equal shapes")
    return [
        [x - y for x, y in zip(left_row, right_row)]
        for left_row, right_row in zip(left, right)
    ]


def scale(matrix, factor):
    matrix_shape(matrix)
    if (
        not is_finite_number(factor)
    ):
        raise ValueError("scale factor must be finite")
    return [[factor * value for value in row] for row in matrix]


def frobenius(matrix):
    matrix_shape(matrix)
    return math.hypot(*(value for row in matrix for value in row))


def numerical_rank(matrix, tolerance=1e-10):
    if (
        not is_finite_number(tolerance)
        or tolerance < 0
    ):
        raise ValueError("tolerance must be finite and non-negative")
    work = [row[:] for row in matrix]
    rows, cols = matrix_shape(work)
    rank_value = 0
    for column in range(cols):
        if rank_value == rows:
            break
        pivot = max(
            range(rank_value, rows),
            key=lambda row: abs(work[row][column]),
        )
        if abs(work[pivot][column]) <= tolerance:
            continue
        work[rank_value], work[pivot] = work[pivot], work[rank_value]
        pivot_value = work[rank_value][column]
        work[rank_value] = [
            value / pivot_value for value in work[rank_value]
        ]
        for row in range(rows):
            if row == rank_value:
                continue
            factor = work[row][column]
            work[row] = [
                value - factor * pivot_value_row
                for value, pivot_value_row in zip(
                    work[row], work[rank_value]
                )
            ]
        rank_value += 1
    return rank_value


def diagonal(values):
    if not values or any(
        not is_finite_number(value)
        or value < 0
        for value in values
    ):
        raise ValueError("singular values must be finite and non-negative")
    return [
        [values[i] if i == j else 0.0 for j in range(len(values))]
        for i in range(len(values))
    ]


def truncated_diagonal(values, rank_value):
    if not isinstance(rank_value, int) or isinstance(rank_value, bool):
        raise ValueError("rank must be an integer")
    if not 0 <= rank_value <= len(values):
        raise ValueError("rank must be within the singular-value count")
    kept = values[:rank_value]
    kept += [0.0] * (len(values) - rank_value)
    return diagonal(kept)


def covariance_2d(points):
    if (
        len(points) < 2
        or any(
            len(point) != 2
            or any(
                not is_finite_number(value)
                for value in point
            )
            for point in points
        )
    ):
        raise ValueError("need at least two two-dimensional points")
    mean_x = sum(point[0] for point in points) / len(points)
    mean_y = sum(point[1] for point in points) / len(points)
    centered = [
        (point[0] - mean_x, point[1] - mean_y)
        for point in points
    ]
    cxx = sum(x * x for x, _ in centered) / len(centered)
    cxy = sum(x * y for x, y in centered) / len(centered)
    cyy = sum(y * y for _, y in centered) / len(centered)
    return [[cxx, cxy], [cxy, cyy]]


def symmetric_eigenvalues_2x2(matrix):
    if matrix_shape(matrix) != (2, 2) or matrix[0][1] != matrix[1][0]:
        raise ValueError("expected a 2x2 symmetric matrix")
    a, b = matrix[0]
    _, d = matrix[1]
    trace = a + d
    gap = math.sqrt((a - d) ** 2 + 4 * b * b)
    return sorted(
        [(trace + gap) / 2, (trace - gap) / 2],
        reverse=True,
    )


def rejects_invalid(operation):
    try:
        operation()
    except ValueError:
        return True
    return False


singular_values = [5.0, 2.0, 0.5]
weight = diagonal(singular_values)
weight_rank1 = truncated_diagonal(singular_values, 1)
weight_rank2 = truncated_diagonal(singular_values, 2)
error_rank1 = frobenius(subtract(weight, weight_rank1))
error_rank2 = frobenius(subtract(weight, weight_rank2))
total_energy = sum(value * value for value in singular_values)
if total_energy <= 0:
    raise ValueError("energy ratio is undefined for a zero matrix")
rank2_energy = sum(value * value for value in singular_values[:2])
rank2_energy /= total_energy

points = [
    (2.0, 1.0),
    (1.0, 0.0),
    (-1.0, -1.0),
    (-2.0, 0.0),
]
covariance = covariance_2d(points)
eigenvalues = symmetric_eigenvalues_2x2(covariance)
total_variance = sum(eigenvalues)
if total_variance <= 0:
    raise ValueError("PCA explained variance is undefined without variance")
pca_ratio = eigenvalues[0] / total_variance

factor_b = [
    [0.2, -0.1],
    [0.0, 0.3],
    [0.4, 0.1],
    [-0.2, 0.2],
]
factor_a = [
    [0.5, -0.4, 0.1],
    [0.2, 0.3, -0.6],
]
if len(factor_b[0]) != len(factor_a):
    raise ValueError("LoRA factors have incompatible inner dimensions")
delta_weight = matmul(factor_b, factor_a)

sample = [[1.0, 0.5, -1.0, 2.0]]
base_weight = [
    [0.1, -0.2, 0.3],
    [0.0, 0.4, -0.1],
    [0.2, 0.1, 0.0],
    [-0.3, 0.2, 0.5],
]
base_output = matmul(sample, base_weight)
lora_delta = scale(
    matmul(matmul(sample, factor_b), factor_a),
    8 / 2,
)
lora_output = add(base_output, lora_delta)

full_parameters = 4096 * 4096
rank = 8
if not 0 < rank <= min(4096, 4096):
    raise ValueError("rank must be within the layer dimensions")
lora_parameters = rank * (4096 + 4096)
lora_ratio = lora_parameters / full_parameters
parameter_count = 7_000_000_000
if parameter_count <= 0:
    raise ValueError("parameter count must be positive")
bf16_bits = 16
int4_bits = 4
bf16_7b_gib = parameter_count * bf16_bits / 8 / (1024 ** 3)
int4_7b_gib = parameter_count * int4_bits / 8 / (1024 ** 3)

try:
    matmul([[1.0, 2.0]], [[1.0, 2.0]])
except ValueError:
    shape_error_checked = True
else:
    shape_error_checked = False

checks = {
    "rank_delta_le_r": numerical_rank(delta_weight) <= 2,
    "rank2_error_lower": error_rank2 < error_rank1,
    "rank2_energy_high": rank2_energy > 0.98,
    "pca_manual_covariance": covariance == [[2.5, 0.75], [0.75, 0.5]],
    "pca_manual_eigenvalues": eigenvalues == [2.75, 0.25],
    "lora_parameters_smaller": lora_parameters < full_parameters,
    "quantized_weight_smaller": int4_7b_gib < bf16_7b_gib,
    "shape_error_checked": shape_error_checked,
    "oversized_integer_inputs_rejected": all(
        rejects_invalid(operation)
        for operation in (
            lambda: matrix_shape([[10**1000]]),
            lambda: scale([[1.0]], 10**1000),
            lambda: numerical_rank([[1.0]], tolerance=10**1000),
            lambda: diagonal([10**1000]),
            lambda: covariance_2d([(10**1000, 0.0), (0.0, 1.0)]),
        )
    ),
}

print(
    "ranks=",
    {
        "weight": numerical_rank(weight),
        "delta_weight": numerical_rank(delta_weight),
    },
)
print(
    "svd_approximation=",
    {
        "rank1_error": round(error_rank1, 3),
        "rank2_error": round(error_rank2, 3),
        "rank2_energy": round(rank2_energy, 3),
    },
)
print(
    "pca=",
    {
        "covariance": [
            [round(value, 3) for value in row]
            for row in covariance
        ],
        "eigenvalues": [round(value, 3) for value in eigenvalues],
        "first_ratio": round(pca_ratio, 3),
    },
)
print(
    "lora_parameters=",
    {
        "full": full_parameters,
        "rank8": lora_parameters,
        "ratio": round(lora_ratio, 6),
    },
)
print(
    "lora_output=",
    [[round(value, 3) for value in row] for row in lora_output],
)
print(
    "qlora_weight_memory_gib=",
    {
        "bf16_7b": round(bf16_7b_gib, 2),
        "int4_7b": round(int4_7b_gib, 2),
    },
)
print("checks=", checks)
~~~

## 5.18 如何阅读真实实验结果

### 5.18.1 先核对矩阵约定

看到一张低秩实验表时，先确认权重的 shape、因子顺序、rank 的定义和是否包含 bias。不同代码库可能把 A、B 的名字互换；只要乘积 shape 正确，符号命名本身不重要。若报告的参数量与下面的公式不一致，要查目标模块数量、bias、embedding、分类头和是否包含多个 adapter。

~~~math
r(m+n)
~~~

还要确认线性层采用的是行向量还是列向量约定。对于列向量，基础层可能写成 y=Wx；对于行向量，可能写成 Y=XW。两者的 W 形状互为转置，但参数量和 rank 相同。把两个约定混在一起，最常见的结果是代码能运行，却把 adapter 加到了错误的输入或输出维度。

### 5.18.2 再核对比较是否公平

低 rank 和高 rank 若训练步数、学习率、有效 token 数或数据切分不同，结果不能直接归因于 rank。量化和非量化方案若使用了不同的计算 dtype 或不同的 kernel，也应把硬件和软件栈写清楚。对于生成任务，还要固定 temperature、top-p、最大长度和停止条件。

如果一次实验同时改变 rank、目标模块、alpha、数据量和量化格式，它可以回答“这一整套配置是否有用”，却不能回答“究竟是哪一个因素造成变化”。要解释原因，至少需要一个基线和逐因素或成组消融。多次运行时还要报告随机种子之间的波动，而不是只展示最好的那一次。

### 5.18.3 最后看失败样本

平均分只显示整体趋势。低秩方案最有价值的诊断往往来自失败样本：

- 失败是否集中在长输入或多轮上下文；
- 是格式坏了，还是内容错了；
- 是检索没找到，还是模型没有使用证据；
- 是普通任务变差，还是安全/拒答行为变差；
- 是所有层都受影响，还是单个目标模块异常。

把失败样本与奇异值谱、hidden state 偏移和 adapter norm 联系起来，才能形成可检验的解释。不能因为某个解释听起来符合“低秩直觉”，就跳过反事实实验。

### 5.18.4 一个成本收益判断

如果基线任务成功率 `s0` 和新方案成功率 `s1` 都严格大于 0，每个请求的平均成本分别为非负的 `c0`、`c1`，可以用单位成功任务成本做一个直观比较：

~~~math
c_{\mathrm{success}}=\frac{c}{s}
~~~

这里的成功必须先定义清楚，例如“答案正确且引用支持且格式合法”，不能只把 HTTP 200 当作成功。如果某个方案 `s=0`，单位成功任务成本没有定义，不能报告成无穷小或 0。若新方案质量略高但单位成功任务成本大幅增加，是否值得取决于业务价值；若平均分不变却显著降低显存或延迟，也可能有部署价值。数学指标、任务指标和系统指标需要一起解释。

例如，在 100 个相同请求上，基线每次成本按 $0.08$ 个预算单位计，成功 82 次；新方案每次 $0.05$ 单位，成功 78 次。基线总成本为 $8$，单位成功成本 $8/82\approx0.0976$；新方案总成本为 $5$，单位成功成本 $5/78\approx0.0641$，约低 34%。这是构造输入，只能说明成本口径的算法。若新方案未通过拒答、引用或正确率下限，低单位成本不能抵消质量门槛；若二者都过门槛，还须查看配对请求上的失败类型和多次运行波动。

比较实验时，可以先定义“每请求成本”的边界：是否含重试、检索、reranker、工具调用和失败请求；分子若只计成功请求的推理成本，会漏掉为了得到成功结果而消耗的失败尝试。配对相同请求能减少样本难度差异，但随机生成还要用多组种子或重复运行估计波动。成本比率只是一种汇总，最终选择仍需同时过质量、安全和时延约束。

例如 10 个请求累计发生 12 次模型调用，单次成本为 $0.05$，总成本是 $12\times0.05=0.60$；若其中 8 个达到预先定义的成功条件，单位成功成本为 $0.60/8=0.075$。若另一方案每次只花 $0.04$，却为 10 个请求触发 15 次调用并成功 7 个，总成本也是 $0.60$，单位成功成本变为 $0.60/7\approx0.0857$。只看单次调用价格会误判；要把达到成功所需的重试和失败尝试放进同一个分子与分母。

成本单位可以是货币、GPU 秒或能耗，但同一比较必须使用相同的计量边界和资源价格口径。若用 GPU 秒，应说明是否计入数据加载、空闲等待与重试；若用货币，则说明硬件或云实例的计费规则。吞吐受并发和批处理影响时，还要固定负载条件，否则相同的单位请求成本可能对应不同的尾延迟与资源占用。

## 5.20 资料与证据边界

本章的定义和公式属于标准线性代数与统计学习内容；工程 API 和论文主张需要区分来源：

1. NumPy 的 numpy.linalg.svd 文档适合核对返回值、full_matrices 和重构用法；
2. PyTorch 的 torch.linalg.svd 文档适合核对张量 shape、device、dtype 和自动微分接口；
3. scikit-learn 的 PCA 文档适合核对中心化、组件和 explained variance 的工程 API 语义；
4. LoRA 原论文（Hu 等，2021，arXiv:2106.09685）提出冻结基础模型并训练低秩更新的参数高效微调方法；
5. QLoRA 原论文（Dettmers 等，2023，arXiv:2305.14314）讨论量化基础模型、低秩适配器和显存受限微调组合；
6. Eckart 与 Young 的矩阵近似论文给出低秩近似的经典结果；Mirsky 的论文推广到酉不变范数，本章的推导限于 Frobenius 范数和谱范数；
7. rsLoRA 原论文分析 rank-dependent scaling，并在其初始化与渐近稳定性假设下提出 $\alpha/\sqrt r$；
8. DoRA 原论文提出将权重幅度与方向拆开，并以低秩更新参数化方向变化；实验结论限于论文模型和任务；
9. LoRA-$\alpha$ 预印本研究缩放系数与学习率的不同作用；本章只将其作为特定模型、优化器和数据条件下的实验候选，不把拟合规律当成通用配方；
10. van der Maaten 与 Hinton 的 t-SNE 原论文，以及 McInnes 等人的 UMAP 原论文，支持本章关于邻域结构、低维布局和可视化边界的说明；
11. Hugging Face PEFT 的 LoRA 文档适合核对目标模块、adapter 管理、合并和加载等工程接口，但具体行为仍受版本、模型架构和量化后端影响。

## 5.21 本章回顾

矩阵秩描述独立方向数量，数值秩还依赖阈值和尺度。SVD 把线性变换拆成输入正交方向、奇异值缩放和输出正交方向；截断 SVD 在 Frobenius 范数和谱范数下给出固定秩的最佳近似，并能用奇异值计算误差。

PCA 面向中心化样本矩阵，主成分是协方差最大特征值对应的方向，也可以通过中心化数据的 SVD 得到。低秩压缩近似原始权重，可能减少模型存储和矩阵乘法；LoRA 用两个小矩阵表达微调增量，rsLoRA 调整秩缩放，DoRA 分开参数化权重幅度与方向。QLoRA 把量化基础权重和 LoRA 组合起来，但实际显存和质量仍由量化元数据、激活、kernel、数据和任务共同决定。

最后，必须把数学近似指标和任务指标分开。能量保留率、谱误差和 adapter 参数量是有价值的诊断量，却不是任务成功的同义词。一个可靠的低秩实验应同时解释矩阵误差、能力变化、失败样本、系统成本和证据来源。只有当读者能从矩阵形状一路追到任务行为，低秩才不再是“省参数”的口号，而成为可以计算、实验和复盘的工程方法。
