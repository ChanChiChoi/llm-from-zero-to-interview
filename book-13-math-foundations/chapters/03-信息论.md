# 第三章：信息论：从编码代价到模型约束

概率论回答“结果以多大概率出现”，信息论进一步回答“观察这个结果需要付出多大的描述代价”“一个变量到底为另一个变量提供了多少信息”“两个概率分布之间的额外代价是多少”。这组语言正好落在大模型的几个核心问题上：token loss、cross entropy、perplexity、KL regularization、互信息、表示压缩、对比学习和证据选择。

本章和上一章的分工很明确。概率论负责定义随机变量、条件分布、链式法则和抽样过程；信息论把这些分布变成可比较的量，并研究压缩、预测和分布偏离的代价。看到 `-log p` 时，上一章可以告诉你它是 NLL；本章还要说明它是一个事件的信息量，平均以后是编码代价，指数化后形成 PPL，并解释为什么 tokenizer、数据分布和任务目标会改变它的含义。

初学者可以沿着一条主线阅读：稀有事件信息量更大；分布平均信息量是熵；用错误分布预测真实分布产生交叉熵和 KL；知道额外变量后不确定性减少的量是互信息；压缩表示会在计算成本和任务信息之间取舍；偏好优化用 KL 或 reference 约束分布漂移；RAG 的价值不在于相似度好看，而在于证据是否真正降低了任务不确定性。

专家需要额外保留边界：熵不是事实性，互信息不是语义质量，InfoNCE 不是无条件的互信息测量，KL 不是安全证明，低 PPL 不是产品成功，信息压缩也不等于保留了任务相关信息。下面的公式、数字和 Python 实验都是教学构造，除非明确说明，不代表某个公开模型或线上系统的实测结果。

## 3.1 信息量：一个结果有多意外

### 3.1.1 自信息的定义

设事件 `x` 的概率为 `p(x)`。观察到它以后获得的自信息定义为：

~~~math
I(x)=-\log p(x)
~~~

这里默认使用自然对数，单位是 nat；如果使用以 2 为底的对数，单位是 bit：

~~~math
I_2(x)=-\log_2p(x)
~~~

概率越小，信息量越大。一个概率为 `1` 的确定事件信息量为 0；概率为 `1/2` 的事件带来 1 bit；概率为 `1/8` 的事件带来 3 bit。

这个定义抓住的是“意外程度”，不是事件的价值、危险程度或事实重要性。一个罕见但无关紧要的 token 可能信息量很大，一个常见但对业务极关键的否定词信息量可能很小。风险评估不能只用信息量代替影响程度。

### 3.1.2 信息量为什么使用负对数

负对数有三个适合语言模型的性质。

第一，概率越大，代价越小；第二，独立事件的联合信息量可相加。若 `x` 和 `y` 独立：

~~~math
I(x,y)
=-\log[p(x)p(y)]
=I(x)+I(y)
~~~

第三，很多概率相乘时容易下溢，信息量和 log probability 把乘法转成加法，方便计算长序列。

语言模型中，真实 token `x_t` 的单步 NLL 为：

~~~math
\ell_t=-\log p_{\theta}(x_t\mid x_{1:t-1})
~~~

它既可以看作模型预测真实 token 的损失，也可以看作在给定上下文下编码这个 token 的信息代价。二者是同一个数，但解释目的不同：训练关心梯度，信息论关心代价和分布差异。

### 3.1.3 预测不等于压缩事实

如果一个模型对文本分布预测得好，平均 NLL 较低，就意味着在该分布上可以用更短的理想编码描述样本。但这不是说模型已经把文本压缩成了现实世界的真相，也不是说压缩后的表示保留了用户需要的每条证据。

例如，网页语料中反复出现的一句错误说法可能很容易预测，因此信息量很低；它在现实中仍然可能是错误的。编码代价衡量统计规律，不自动衡量真值、权威性和业务影响。

## 3.2 熵：分布自身的平均不确定性

### 3.2.1 熵是自信息的期望

离散随机变量 `X` 的熵定义为：

~~~math
H(X)
=
\mathbb{E}_{x\sim p}[I(x)]
=-\sum_xp(x)\log p(x)
~~~

熵是观察一个来自 `X` 的结果时，平均需要付出的信息量。它不是某个具体结果的意外程度：具体 token 的信息量可能很高，但整个分布的熵还要对所有结果加权平均。

如果 `X` 在 `V` 个结果上均匀分布：

~~~math
H(X)=\log V
~~~

如果所有概率集中在一个结果上，熵为 0。在相同支持集合内，均匀分布具有最大熵。

### 3.2.2 语言模型中的预测熵

给定上下文 `c`，模型对下一个 token 的条件熵为：

~~~math
H_{\theta}(X_t\mid c)
=-\sum_vp_{\theta}(v\mid c)\log p_{\theta}(v\mid c)
~~~

低熵表示模型分布集中，高熵表示分布分散。开放式创作、歧义消解和缺少证据的任务可能合理地具有较高熵；一个本应由明确文档决定的金额字段却有高熵，可能说明证据缺失或视觉/OCR 处理失败。

熵不能单独判断好坏。错误模型也可以对错误答案低熵；一个允许多个答案的任务也可能被高熵模型很好地完成。解释熵时必须同时说明任务、候选空间和正确性标准。

### 3.2.3 条件熵和联合熵

联合熵描述同时观察两个变量的平均信息量：

~~~math
H(X,Y)=-\sum_{x,y}p(x,y)\log p(x,y)
~~~

条件熵描述已经知道 `Y` 后，`X` 还剩多少平均不确定性：

~~~math
H(X\mid Y)
=-\sum_{x,y}p(x,y)\log p(x\mid y)
~~~

熵的链式法则为：

~~~math
H(X,Y)=H(Y)+H(X\mid Y)
~~~

对语言序列也可以逐步展开。上下文越有用，给定上下文后的下一个 token 条件熵通常越低；但“更低”只表示模型分布更集中，不能单凭它判断模型是否知道真实答案。

### 3.2.4 熵与不确定性的两个陷阱

第一个陷阱是把低熵当作高可信。模型可以因为训练语料偏置、提示模板或错误先验而非常确定地输出错误内容。

第二个陷阱是把高熵当作无能。对“写五个不同标题”这类开放任务，高熵可能正是多样性的来源；对安全决策，高熵则可能应该触发补充证据、工具验证或人工升级。

因此，熵更适合成为路由和诊断信号，而不是直接的发布指标。它可以帮助系统发现“模型分布发生变化”的位置，最终动作仍要由任务正确性、证据和风险规则决定。

## 3.3 交叉熵：用一个分布解释另一个分布

### 3.3.1 定义和 one-hot 情形

设真实分布为 `P`，预测分布为 `Q`。交叉熵定义为：

~~~math
H(P,Q)=-\sum_xP(x)\log Q(x)
~~~

如果真实标签是 one-hot，正确类别为 `y`，那么：

~~~math
P(y)=1,
\qquad
P(x)=0\ \text{for}\ x\ne y
~~~

交叉熵退化为：

~~~math
H(P,Q)=-\log Q(y)
~~~

这就是分类和语言模型中单个真实 token 的 NLL。它惩罚的不是“预测类别错了”这一件事，而是模型给真实结果分配了多小的概率。把真实类别从 `0.4` 提高到 `0.8` 会显著降低损失，即使 top-1 类别没有发生变化。

### 3.3.2 交叉熵和最大似然

自回归序列的平均交叉熵可以写成：

~~~math
L_{\mathrm{CE}}
=-
\frac{1}{N}
\sum_{i=1}^{N}
\log p_{\theta}(x_i\mid c_i)
~~~

其中 `N` 是参与统计的有效 token 数，`c_i` 是第 `i` 个位置可见的上下文。最大化真实 token 的似然等价于最小化这一个平均负对数似然。

如果 chat SFT 只对 assistant 输出计算损失，`N` 不能包含 system、user、padding 等被 mask 的位置。loss reduction 不是实现细节，而是信息代价的分母定义。

### 3.3.3 交叉熵分解

交叉熵和 KL 散度有关系：

~~~math
H(P,Q)=H(P)+D_{\mathrm{KL}}(P\Vert Q)
~~~

其中 `H(P)` 是真实分布本身的不确定性，`D_KL(P||Q)` 是用 `Q` 代替 `P` 产生的额外代价。固定 `P` 时，最小化交叉熵等价于最小化这个方向的 KL。

这条分解解释了一个常见误读：两个数据集的交叉熵不同，不一定代表模型差异，因为数据分布自身的熵也可能不同。比较模型时要固定语料、tokenizer、mask、上下文和聚合方式。

## 3.4 Perplexity：从平均编码代价到可比性边界

### 3.4.1 定义

若平均 token NLL 使用自然对数，perplexity 为：

~~~math
\mathrm{PPL}=\exp(L_{\mathrm{avg}})
~~~

它可以作为“等价候选数量”的教学直觉：平均 loss 为 `log 10` 时，PPL 为 10。但真实语言分布通常不是均匀的，PPL 不是模型在每一步真的只面对 10 个候选，也不是答案空间的物理大小。

若使用 bit 为单位，则对应的二进制 perplexity 是：

~~~math
\mathrm{PPL}_2=2^{L_{\mathrm{bit}}}
~~~

两者只是对数底不同的表示。

### 3.4.2 tokenizer 会改变信息单位

同一段文本被不同 tokenizer 切成不同数量的 token，每个 token 的条件分布也不同。一个 tokenizer 可能把常见词作为一个 token，另一个 tokenizer 可能把它拆成多个子词；直接比较 token-level PPL 会把词表、切分和序列长度差异混进结果。

在统一文本上，可以补充按字节归一化的指标。例如总负对数似然使用 bit，UTF-8 字节数为 `B`：

~~~math
\mathrm{BitsPerByte}
=
\frac{L_{\mathrm{bits}}}{B}
~~~

它仍然依赖文本规范化和编码约定，但比跨 tokenizer 的 token PPL 更接近共同的输入单位。它也不能解决模型架构、上下文窗口和数据污染的比较问题。

### 3.4.3 低 PPL 不等于高任务质量

PPL 低只能说明在指定语料和协议下平均 token 似然较好。它不能单独证明：

1. 事实性更强；
2. 长上下文中间证据使用更好；
3. 指令遵循更可靠；
4. 工具参数更正确；
5. 安全拒答更合适；
6. 单位成功任务成本更低。

对齐训练甚至可能让通用语料 PPL 略有变化，但改善真实交互目标。只要目标不同，这并不矛盾。PPL 是语言建模证据，不是所有产品目标的总分。

## 3.5 KL 散度：方向、支持和额外代价

### 3.5.1 定义

KL 散度定义为：

~~~math
D_{\mathrm{KL}}(P\Vert Q)
=\sum_xP(x)\log\frac{P(x)}{Q(x)}
~~~

它也可以写成交叉熵减去真实熵：

~~~math
D_{\mathrm{KL}}(P\Vert Q)=H(P,Q)-H(P)
~~~

KL 非负，且在分布相同处为 0；但它不满足对称性和三角不等式，所以不是普通欧氏距离。

### 3.5.2 方向为什么重要

`D_KL(P||Q)` 以 `P` 的概率作为权重。若 `P(x)>0` 而 `Q(x)=0`，对应项发散，表示预测分布完全漏掉了真实分布支持的结果。反向的 `D_KL(Q||P)` 则把 `Q` 的区域作为权重，优化行为可能更倾向于避免把质量放到 `P` 不支持的区域。

在蒸馏、语言模型约束和策略优化中，“谁是目标、谁是近似”必须写清楚。只说“加 KL 让两个模型接近”会掩盖方向带来的差异。

### 3.5.3 KL 与总变差的关系

在满足相应概率条件时，Pinsker 不等式给出一个教学性上界：

~~~math
\mathrm{TV}(P,Q)
\le
\sqrt{\frac{1}{2}D_{\mathrm{KL}}(P\Vert Q)}
~~~

其中 `TV` 是总变差距离。它说明 KL 小可以约束某种整体分布差异，但这个上界可能很松，也没有告诉你哪个具体任务或哪个高风险尾部最安全。生产评估仍要看关键事件概率和任务切片。

### 3.5.4 KL、JS 和“距离”措辞

Jensen-Shannon divergence 可以用两个方向的 KL 组合构造对称、有限的比较量，但换一个散度就换了优化含义。工程上选择 KL、JS、余弦或其他度量，都要说明：比较的是 token 分布、hidden state、embedding 还是行为结果，使用这个量会奖励什么、忽略什么。

## 3.6 互信息：一个变量减少了多少不确定性

### 3.6.1 定义

变量 `X` 和 `Y` 的互信息为：

~~~math
I(X;Y)=H(X)-H(X\mid Y)
~~~

它也可以写成联合分布与独立乘积分布之间的 KL：

~~~math
I(X;Y)
=D_{\mathrm{KL}}\left(
p(x,y)\Vert p(x)p(y)
\right)
~~~

如果知道 `Y` 后 `X` 的不确定性显著降低，互信息就大；如果 `X` 和 `Y` 独立，互信息为 0。互信息是对称的：

~~~math
I(X;Y)=I(Y;X)
~~~

### 3.6.2 信息增益的直觉例子

假设 `Y` 是文档问答的真实答案，`X` 是一个候选片段。检索前系统对答案分布有熵 `H(Y|Q)`；加入片段后变成 `H(Y|Q,X)`。理想的信息增益可以写成：

~~~math
\mathrm{IG}(X;Y\mid Q)
=H(Y\mid Q)-H(Y\mid Q,X)
~~~

一个片段与问题词面很相似，但没有金额、日期或否定条件，可能对答案不提供多少信息；一个短小的正式条款可能真正降低答案不确定性。实际系统无法直接知道完整真实分布，因此 embedding 分数、rerank 分数和引用支持率只是代理测量。

### 3.6.3 数据处理不等式

如果 `X -> Z -> Y` 构成马尔可夫链，即 `Z` 只通过 `X` 获得关于 `Y` 的信息，那么数据处理不等式给出：

~~~math
I(X;Y)\ge I(Z;Y)
~~~

直觉是，经过一个压缩或噪声处理，通常不会凭空增加原始输入关于目标的信息。视觉 token 压缩、OCR、摘要和 embedding 都可以看作某种表示变换；它们如果丢掉了任务所需细节，后续语言模型不能从已经消失的信息中恢复真实证据。

这里的“不能增加信息”是关于统计变量和给定分布的理论关系，不等于任何训练后的下游指标都必然下降。表示变换可能去掉噪声、改善可学习性，导致有限样本任务表现提高；因此要同时测信息保留、任务质量和计算成本。

### 3.6.4 互信息的估计陷阱

高维连续变量的互信息通常难以直接估计。常见估计器会受到样本量、负样本、密度假设、数值稳定性和 critic 过拟合影响。一个估计值变大，不自动说明表示更语义、更可解释或更有用。

互信息也可能奖励模型保留与任务无关的身份、背景或数据集捷径。表示学习实验需要检查下游泛化、反事实、隐私和不变性，而不能把 MI 数字当作单一质量目标。

## 3.7 对比学习和 InfoNCE：共享信息的代理目标

### 3.7.1 图文配对中的对比目标

给定一个 batch 中的 `N` 个图文配对，图像表示为 `u_i`，文本表示为 `v_i`，相似度为 `s(u_i,v_j)`，温度为 `tau`。图像到文本的 InfoNCE 形式可以写成：

~~~math
L_{\mathrm{i2t}}
=-
\frac{1}{N}
\sum_{i=1}^{N}
\log
\frac{\exp(s(u_i,v_i)/\tau)}
{\sum_{j=1}^{N}\exp(s(u_i,v_j)/\tau)}
~~~

文本到图像可以交换两个方向，再取平均。目标鼓励匹配 pair 的相似度高于 batch 内其他 pair。

在某些理想化假设下，InfoNCE 损失与互信息下界有关系，常见教学写法为：

~~~math
I(X;Y)\gtrsim\log N-L_{\mathrm{NCE}}
~~~

这里的符号不是无条件定理。负样本是否来自正确边缘分布、batch 是否足够大、配对是否唯一、相似度函数是否有足够表达能力，都会影响这个解释。假负样本会让一个本来合理的配对被当成错误，数据重复会让指标虚高。

### 3.7.2 相似空间不等于事实推理

对比学习擅长把图像和文本的全局语义拉近，但全局相似度不能保证模型掌握：

1. 小字体 OCR；
2. 物体数量；
3. 左右和前后关系；
4. 图表中的计算关系；
5. 文字描述中的否定和条件。

因此，CLIP 式对齐是表示和检索的强工具，却不能单独证明视觉证据被正确使用。细粒度任务还需要区域、结构、反事实和 claim-level 评估。

### 3.7.3 负样本和污染边界

batch 内负样本可能是假负样本：两张图片都包含猫，只是文本描述关注不同属性；同一文档的两个版本可能都合理；多个 caption 可能都能描述一幅图。训练数据还可能重复评估样本或带入网页模板。

实验报告应记录负样本构造、去重、语言和领域比例、温度、batch、评估污染和多正样本处理。不能把更大的 batch 或更低的 InfoNCE loss 自动解释为更强的通用理解。

## 3.8 信息瓶颈：压缩和任务信息的取舍

### 3.8.1 目标的形式

设输入为 `X`，表示为 `Z`，任务目标为 `Y`。信息瓶颈的经典直觉是在保留 `Z` 关于 `Y` 的信息的同时，减少 `Z` 关于输入 `X` 的不必要信息。一个教学目标可以写成：

~~~math
\min_Z\ I(X;Z)-\beta I(Z;Y)
~~~

`I(X;Z)` 代表表示保留了多少输入信息，`I(Z;Y)` 代表表示对任务目标有多少信息，`beta` 控制压缩与任务保留的折中。

在实际神经网络中，通常不会直接精确计算这两个互信息，而是使用变分上界、噪声、瓶颈层、稀疏约束或任务损失做代理。读论文时必须区分“理论目标”“可优化的 surrogate”和“实验证据”。

### 3.8.2 视觉 token、摘要和 RAG chunk

视觉 token 合并、音频下采样、长文档摘要和 RAG chunk 都是信息预算问题。压缩可以降低上下文、显存和延迟，但可能丢掉：

1. 数字和单位；
2. 否定词和例外条件；
3. 空间坐标和表格关系；
4. 权限、版本和来源元数据；
5. 低频但高风险的事实。

更少的 token 不等于更少的任务成本。若压缩后导致更多重试、人工复核或错误动作，单位成功任务成本可能反而上升。

### 3.8.3 压缩实验应该测什么

一个有意义的压缩实验至少要同时测：

1. 表示或重建误差；
2. 任务成功率和关键字段准确率；
3. 证据支持率和反事实敏感性；
4. TTFT、TPOT、显存和吞吐；
5. 多轮、多图和长上下文退化；
6. 隐私、权限和不可逆信息丢失。

只测平均 loss 或 token 数，无法判断压缩保留了哪类信息。

## 3.9 KL 约束：从 reward 优化到策略漂移

### 3.9.1 为什么 reward 需要锚点

偏好模型或 reward model 通常只是人类评价的代理。若策略只追求 reward，可能学会利用评审器偏好而不是完成真实目标，出现长度偏置、模板化、过度拒答或其他 reward hacking。

一个带 KL 约束的教学目标为：

~~~math
J(\theta)
=
\mathbb{E}_{y\sim\pi_{\theta}(\cdot\mid x)}[r(x,y)]
-\beta D_{\mathrm{KL}}
\left(
\pi_{\theta}(\cdot\mid x)
\Vert
\pi_{\mathrm{ref}}(\cdot\mid x)
\right)
~~~

第一项鼓励高 reward，第二项惩罚策略相对于 reference 的分布变化。`beta` 越大，漂移成本越高；`beta` 越小，策略更容易追逐 proxy 的漏洞。

### 3.9.2 KL 太小和太大都可能有问题

`beta` 太小可能导致：

1. reward hacking 更容易积累；
2. 语言风格和基础能力退化；
3. 输出分布进入训练数据没有覆盖的区域；
4. 安全拒答或工具行为发生意外变化。

`beta` 太大可能导致：

1. 新偏好无法学到；
2. 原有错误被牢固保留；
3. 任务适配不足；
4. reward 提升被过度压制。

KL 是一个可调的分布约束，不是“越大越安全”的总开关。发布判断仍需要独立的事实、安全、工具和回归评估。

### 3.9.3 序列 KL 和 token KL 的口径

实现中可能用每个 token 的 KL 求和、平均，或近似整个 response 的序列 KL。不同 reduction 会改变 `beta` 的实际尺度：回答越长，求和形式通常积累更多约束；平均形式则更接近每 token 的偏离。

实验记录需要明确 prompt 是否计入、response 是否 mask、padding 如何处理、是否按 token 平均，以及 reference 与 policy 使用的 tokenizer 和 chat template 是否一致。

## 3.10 DPO：reference model 和偏好分布

### 3.10.1 偏好数据表达什么

偏好样本通常包含 prompt `x`、chosen response `y_w` 和 rejected response `y_l`。它表达在给定标准下哪个回答更受偏好，不自动表达哪个回答在现实中绝对正确。

如果标注只奖励简洁和礼貌，模型可能学会简洁和礼貌；如果标注没有检查引用和事实，DPO 不会凭空创造事实验证能力。偏好数据的覆盖、噪声、评审器偏差和任务定义仍然决定优化结果。

### 3.10.2 相对于 reference 的 log-ratio

对自回归策略，response 的序列 log probability 为：

~~~math
\log\pi_{\theta}(y\mid x)
=
\sum_{t=1}^{|y|}
\log\pi_{\theta}(y_t\mid x,y_{1:t-1})
~~~

DPO 的核心比较量可以写成：

~~~math
m_{\theta}
=
\left[
\log\pi_{\theta}(y_w\mid x)
-\log\pi_{\mathrm{ref}}(y_w\mid x)
\right]
-
\left[
\log\pi_{\theta}(y_l\mid x)
-\log\pi_{\mathrm{ref}}(y_l\mid x)
\right]
~~~

常见的损失形式为：

~~~math
L_{\mathrm{DPO}}
=-\log\sigma(\beta m_{\theta})
~~~

reference 不只是一个用于比较的旧模型，它提供了策略变化的基线。DPO 与 KL 正则化有理论联系，但阅读具体实现时，不能把“目标中有 reference”简单说成“实现中显式计算了同一个 sequence KL”。需要看 log probability、mask、beta 和 reduction 的实际定义。

### 3.10.3 长度和 tokenizer 的偏差

总 log probability 是 token log probability 的和，较长回答通常更容易得到更小的总值。若 chosen 和 rejected 长度差异很大，训练目标可能混入长度偏好。实现必须记录：

1. response 是否单独计算；
2. prompt token 是否 mask；
3. padding 是否排除；
4. 是否使用总和或平均；
5. chosen/rejected 是否使用同一 tokenizer；
6. beta 是否随长度或 batch 口径调整。

偏好胜率提高不等于真实任务质量提高。DPO 之后应检查事实、引用、拒答、工具参数、长度、基础能力和分布外样本。

## 3.11 RAG：把“相关”转化为“减少答案不确定性”

### 3.11.1 理想的信息增益

设 `Y` 是问题答案，`Q` 是用户问题，`C` 是检索到的 chunk。理想情况下，证据带来的信息增益为：

~~~math
\mathrm{IG}(C;Y\mid Q)
=
H(Y\mid Q)-H(Y\mid Q,C)
~~~

如果 chunk 提供了决定答案的数字、条件和来源，加入它以后答案分布应更集中或更容易被验证。如果 chunk 只是主题相关的背景，信息增益可能很小；如果它与另一份版本冲突，加入后不确定性可能暂时变大，但这也可能是有价值的冲突信号。

### 3.11.2 相似度不是互信息

向量相似度是检索模型训练出来的排序信号，不是直接计算的 `I(C;Y|Q)`。它可能偏爱词面相似、长文档、模板或常见主题。要判断检索质量，需要把以下层次分开：

1. 召回：相关证据是否进入候选；
2. 选择：重排是否把决定性片段放在前面；
3. 证据：片段是否包含完整条件、版本和来源；
4. 生成：回答 claim 是否被片段支持；
5. 系统：权限、延迟、成本和新鲜度是否满足要求。

### 3.11.3 证据可能降低或增加熵

教学实验常用“加入正确文档后答案熵下降”来表达信息增益，但生产数据并不总是这样。错误文档、冲突版本、注入文字或过多无关 chunk 都可能扩大候选空间，让模型更加不确定，甚至自信地选择错误证据。

因此不能用“context entropy 下降”单独证明 RAG 变好。应同时报告答案正确率、claim-level support、冲突识别、引用准确率、权限错误、检索召回和单位成功成本。

## 3.12 安全：信息量、可操作性和责任边界

### 3.12.1 信息多不一定更有帮助

对普通教育问题，更多背景信息可能提高理解；对高风险请求，增加具体可操作细节可能降低危险行为的门槛。安全系统关心的不是把所有输出压成最短，而是区分：

1. 有益且低风险的概念解释；
2. 能帮助防御、检测或求助的安全信息；
3. 会直接促进危险行动的操作性细节；
4. 没有证据却会误导用户的高置信断言。

可以把风险粗略表示为：

~~~math
\mathrm{Risk}
=
\sum_{a\in\mathcal{A}}
P(a\mid o)\,\mathrm{Impact}(a)
~~~

其中 `a` 是可能后果，`o` 是系统输出，`Impact` 是后果严重度。这个式子只是风险分析框架，不是让模型直接估计现实危害的可靠工具。

### 3.12.2 拒答不是信息论总目标

面对证据不足的问题，系统可以表达不确定、请求澄清、检索、调用工具或人工升级；面对高风险可操作请求，系统应限制危险细节并提供安全替代。拒绝所有信息会造成误拒，提供过多信息会造成风险。

安全评估要同时看：危险信息暴露、正常帮助率、误拒率、替代建议质量、人工升级和不同语言/模态切片。一个更短的回答不一定更安全，一个熵更低的拒答也不一定更有帮助。

## 3.13 综合案例：澄明制度助手的信息账本

### 3.13.1 场景

“澄明”制度助手回答企业报销、采购和差旅问题。它收到用户问题后检索制度片段，再生成带页码或条款编号的回答。系统必须处理旧版本、新版本、员工经验帖、租户权限和文档中的不可信指令。

### 3.13.2 两类检索候选

问题是：“上海出差的住宿上限是多少？”系统召回三个片段：

| 片段 | 统计相似度 | 内容 | 主要风险 |
| --- | ---: | --- | --- |
| A | 0.91 | 2023 年旧版上限 | 版本过期 |
| B | 0.86 | 2025 年生效制度，含城市档位和例外 | 需要核对权限和条款 |
| C | 0.89 | 员工经验总结，没有正式来源 | 权威性不足 |

如果系统只按相似度取 A，排序分数看起来很好，答案仍然可能错误。加入 B 后，答案不确定性可能下降；发现 A 与 B 冲突时，暂时上升的不确定性反而提示系统必须做版本判断，而不是随便挑一个最高分。

### 3.13.3 信息论能解释什么，不能解释什么

信息论可以帮助团队讨论：

1. 一个 token 或文档片段的预测/编码代价；
2. 答案分布在加入证据前后的变化；
3. 检索片段是否提供了减少不确定性的信号；
4. 视觉 token、摘要或 chunk 压缩带来的信息预算；
5. policy 偏离 reference 的分布代价。

它不能单独决定：

1. 哪个制度版本具有法律或组织权威；
2. 用户是否有权读取某份文档；
3. 生成的 claim 是否真的被原文支持；
4. 某个高风险动作是否应执行；
5. 一个 reward proxy 是否代表真实业务价值。

信息论为决策提供量化线索，责任判断仍然属于数据治理、权限系统、业务规则和人工审计。

## 3.14 一个可运行的信息论审计实验

下面的标准库 Python 实验计算熵、交叉熵、KL、PPL、互信息、InfoNCE、KL 约束目标和证据加入前后的答案熵。所有分布都是教学数据；代码拒绝负概率、空分布和不归一化输入，避免把非法数字当成信息论结论。

~~~python
from math import exp, isclose, log


def validate_distribution(distribution):
    if not distribution:
        raise ValueError("distribution must not be empty")
    if any(prob < 0 for prob in distribution.values()):
        raise ValueError("probabilities must be non-negative")
    if not isclose(
        sum(distribution.values()),
        1.0,
        rel_tol=1e-9,
        abs_tol=1e-9,
    ):
        raise ValueError("probabilities must sum to one")


def entropy(distribution):
    validate_distribution(distribution)
    return -sum(
        prob * log(prob)
        for prob in distribution.values()
        if prob > 0
    )


def cross_entropy(target, prediction):
    validate_distribution(target)
    validate_distribution(prediction)
    keys = set(target) | set(prediction)
    if any(target.get(key, 0.0) > 0 and prediction.get(key, 0.0) <= 0 for key in keys):
        return float("inf")
    return -sum(
        target.get(key, 0.0) * log(prediction.get(key, 0.0))
        for key in keys
        if target.get(key, 0.0) > 0
    )


def kl_divergence(target, prediction):
    validate_distribution(target)
    validate_distribution(prediction)
    keys = set(target) | set(prediction)
    if any(target.get(key, 0.0) > 0 and prediction.get(key, 0.0) <= 0 for key in keys):
        return float("inf")
    return sum(
        target.get(key, 0.0)
        * log(target.get(key, 0.0) / prediction.get(key, 0.0))
        for key in keys
        if target.get(key, 0.0) > 0
    )


def mutual_information(joint):
    if not joint or any(prob < 0 for prob in joint.values()):
        raise ValueError("joint distribution must be non-empty and non-negative")
    if not isclose(sum(joint.values()), 1.0, abs_tol=1e-9):
        raise ValueError("joint probabilities must sum to one")
    marginal_x = {}
    marginal_y = {}
    for (x, y), prob in joint.items():
        marginal_x[x] = marginal_x.get(x, 0.0) + prob
        marginal_y[y] = marginal_y.get(y, 0.0) + prob
    return sum(
        prob * log(prob / (marginal_x[x] * marginal_y[y]))
        for (x, y), prob in joint.items()
        if prob > 0
    )


def info_nce_loss(similarities, temperature=1.0):
    if not similarities or any(len(row) != len(similarities) for row in similarities):
        raise ValueError("similarities must be a non-empty square matrix")
    if temperature <= 0:
        raise ValueError("temperature must be positive")
    losses = []
    for row_index, row in enumerate(similarities):
        scaled = [value / temperature for value in row]
        pivot = max(scaled)
        denominator = sum(exp(value - pivot) for value in scaled)
        numerator = exp(scaled[row_index] - pivot)
        losses.append(-log(numerator / denominator))
    return sum(losses) / len(losses)


true_dist = {
    "Paris": 0.7,
    "Lyon": 0.2,
    "Marseille": 0.1,
}
model_good = {
    "Paris": 0.6,
    "Lyon": 0.25,
    "Marseille": 0.15,
}
model_bad = {
    "Paris": 0.2,
    "Lyon": 0.3,
    "Marseille": 0.5,
}
uniform = {"A": 0.25, "B": 0.25, "C": 0.25, "D": 0.25}
peaked = {"A": 0.92, "B": 0.04, "C": 0.03, "D": 0.01}

entropy_true = entropy(true_dist)
cross_entropy_good = cross_entropy(true_dist, model_good)
cross_entropy_bad = cross_entropy(true_dist, model_bad)
kl_good = kl_divergence(true_dist, model_good)

token_probabilities = [0.6, 0.75, 0.5, 0.8]
average_nll = sum(-log(prob) for prob in token_probabilities) / len(token_probabilities)
ppl = exp(average_nll)

joint = {
    ("image_cat", "text_cat"): 0.45,
    ("image_cat", "text_dog"): 0.05,
    ("image_dog", "text_cat"): 0.10,
    ("image_dog", "text_dog"): 0.40,
}
mi = mutual_information(joint)

similarities = [
    [0.9, 0.1, 0.0],
    [0.2, 0.8, 0.1],
    [0.0, 0.2, 0.7],
]
nce = info_nce_loss(similarities, temperature=0.2)

reference = {"helpful": 0.55, "refuse": 0.25, "unsafe_detail": 0.20}
policy = {"helpful": 0.70, "refuse": 0.25, "unsafe_detail": 0.05}
policy_kl = kl_divergence(policy, reference)
reward = 1.35
beta = 0.2
kl_objective = reward - beta * policy_kl

without_evidence = {"correct": 0.45, "wrong_a": 0.35, "wrong_b": 0.20}
with_evidence = {"correct": 0.85, "wrong_a": 0.10, "wrong_b": 0.05}

checks = {
    "entropy_uniform_is_larger": entropy(uniform) > entropy(peaked),
    "cross_entropy_decomposition": isclose(
        cross_entropy_good,
        entropy_true + kl_good,
    ),
    "better_model_has_lower_cross_entropy": cross_entropy_good < cross_entropy_bad,
    "ppl_is_exp_average_nll": isclose(exp(average_nll), ppl),
    "mutual_information_is_positive": mi > 0,
    "infonce_is_below_log_batch": nce < log(len(similarities)),
    "kl_is_non_negative": policy_kl >= 0,
    "evidence_reduces_entropy": entropy(with_evidence) < entropy(without_evidence),
}

print("entropy_true=", round(entropy_true, 3))
print("entropy_uniform=", round(entropy(uniform), 3))
print("entropy_peaked=", round(entropy(peaked), 3))
print(
    "cross_entropy_good=",
    round(cross_entropy_good, 3),
    "cross_entropy_bad=",
    round(cross_entropy_bad, 3),
)
print("kl_good=", round(kl_good, 3))
print("avg_nll=", round(average_nll, 3), "ppl=", round(ppl, 3))
print("mutual_information=", round(mi, 3))
print("infonce=", round(nce, 3), "log_batch=", round(log(len(similarities)), 3))
print("policy_kl=", round(policy_kl, 3))
print("kl_objective=", round(kl_objective, 3))
print(
    "entropy_without_evidence=",
    round(entropy(without_evidence), 3),
    "entropy_with_evidence=",
    round(entropy(with_evidence), 3),
)
print("checks=", checks)
~~~

~~~text

~~~

代码的几个重要边界是：

1. `cross_entropy` 和 `kl_divergence` 对目标分布有概率而预测分布为零时返回无穷大，保留了理论上的 support 约束；
2. `info_nce_loss` 只计算一个小方阵的对角正样本，不能把它当作完整多模态训练或无偏互信息估计；
3. “证据降低熵”只在合成分布上成立，真实检索可能因冲突或噪声使熵升高；
4. `policy_kl` 是离散三类行为的教学数字，不是完整 response-level RLHF 轨迹的 KL；
5. 所有输出都使用自然对数，若换成 bit，PPL 和数值单位也要相应改变。

## 3.15 研究与工程中的信息账本

信息论公式只有放进实验协议才有意义。一个完整记录至少包括：

| 对象 | 要记录的条件 | 常见误读 |
| --- | --- | --- |
| token loss | tokenizer、有效 token、mask、reduction | 低 loss 等于任务更好 |
| PPL | 语料、切分、上下文、对数底 | 跨 tokenizer 直接排序 |
| KL | 方向、support、token/sequence reduction | KL 越大越安全 |
| MI/InfoNCE | 正负样本、batch、温度、估计假设 | loss 低等于语义理解强 |
| entropy | 候选空间、条件、分布版本 | 低熵等于事实正确 |
| RAG 信息增益 | 证据、版本、权限、claim 标注 | 相似度等于信息增益 |
| 偏好目标 | chosen/rejected、reference、长度、beta | 偏好等于真值 |

这张账本的作用不是增加形式，而是防止不同对象被同一个“分数”替代。模型训练、检索、对齐和安全使用的分布不同，分数的分母和解释也必须跟着变化。

## 3.16 资料与证据边界

本章优先使用信息论课程、原始论文和训练方法论文。资料支持的结论范围如下：

1. Stanford EE376A 课程支持信息论、熵、互信息、编码和信道的系统学习入口，不自动支持任意 LLM 的产品指标；
2. Shannon 的经典论文支持信息量、熵和通信理论的原始背景，不能直接证明现代 tokenizer 的压缩效果；
3. Contrastive Predictive Coding、Deep InfoMax 或 MINE 资料支持互信息代理目标的研究背景，但估计器的假设和偏差必须单独检查；
4. InstructGPT 支持特定 RLHF 流程和实验条件，不证明 reward 一定等于真实质量；
5. DPO 支持 reference model、偏好对和目标函数的特定推导，不能把所有实现都概括成相同的 KL 约束；
6. RAG 论文和 RAGAS 资料支持检索增强与评估的研究入口，不能把相似度或自动评审分数当成事实证据；
7. 本章中的 InfoNCE、信息瓶颈、风险和证据熵公式是教学抽象，必须在目标任务上用配对数据、反事实和人工复核验证。

## 3.17 练习：把信息论放回模型系统

### 练习一：信息量和单位

计算概率为 `1/2`、`1/8` 和 `0.01` 的事件在 nat 和 bit 下的信息量。说明为什么对数底变化单位，却不改变事件之间的信息量排序。

### 练习二：条件熵和证据

构造一个二分类答案分布，分别计算加入无关片段、正确片段和冲突片段后的条件熵。不要只观察熵大小，还要说明哪个片段能提供可引用证据。

### 练习三：交叉熵分解

对 `P=(0.7,0.2,0.1)` 和两个不同的 `Q`，计算熵、交叉熵和 KL，验证 `H(P,Q)=H(P)+KL(P||Q)`。交换 KL 的方向并解释变化。

### 练习四：PPL 和 tokenizer

同一段文字分别被切成 10 个和 20 个 token。构造两组 token loss，计算 PPL 和 bits-per-byte，说明为什么 token PPL 不足以比较两个 tokenizer。

### 练习五：InfoNCE 负样本

构造一个 `3 x 3` 相似度矩阵，分别改变对角正样本、假负样本和 temperature，观察 InfoNCE 变化。解释为什么 loss 变化不必然等于真实语义能力变化。

### 练习六：信息瓶颈

设视觉表示压缩率从 25% 提高到 75%，列出可能改善的系统指标和可能丢失的任务证据。设计一个同时测 OCR、空间关系、证据支持和延迟的实验矩阵。

### 练习七：KL 约束

构造一个 policy 和 reference 分布，计算两个 KL 方向。改变 `beta`，比较 reward、KL 和目标函数；说明为什么不能只根据总目标决定安全性。

### 练习八：RAG 信息增益

为一个问答任务制作正确、过期、无关和冲突四类 chunk。分别统计检索 Recall、claim support、答案熵变化和权限错误，讨论为什么相似度最高的 chunk 可能不是最有价值的证据。

### 练习九：信息风险

对一个高风险请求，写出低风险的概念解释、可帮助防御的替代信息和不应输出的操作性细节类别。只讨论信息边界和评估方法，不写可直接执行的危险步骤。

## 3.18 本章小结：信息论提供的是约束语言

本章建立了从事件到模型系统的连续链条：

1. 自信息用负对数衡量一个结果的意外程度；
2. 熵是自信息的期望，条件熵表示知道上下文后仍剩多少不确定性；
3. 交叉熵是用预测分布解释真实分布的代价，one-hot 情形就是真实 token 的 NLL；
4. PPL 是平均 token loss 的指数，必须绑定 tokenizer、语料和评估协议；
5. KL 衡量分布替换的额外代价，方向、support 和 reduction 决定解释；
6. 互信息衡量一个变量减少另一个变量多少不确定性，但高维估计和代理目标都有假设；
7. InfoNCE、信息瓶颈和 embedding 相似度是有用的优化或排序工具，不是语义真值证明；
8. KL 约束和 DPO reference 可以控制策略漂移，但不能替代事实、安全和任务评估；
9. RAG 的价值是提供可验证、可授权、可定位的证据，而不只是降低一个熵或提高一个相似度；
10. 安全输出要同时考虑信息粒度、可操作性、帮助率、误拒和现实影响。

真正理解信息论，不是会背 `H`、`KL` 和 `I(X;Y)` 的公式，而是能说明每个量比较的对象、使用的条件、隐藏的假设和没有覆盖的风险。当模型分数、检索相似度和策略目标都变得漂亮时，信息论提醒我们继续追问：它究竟压缩了什么、保留了什么、相对于哪个分布变好了，以及用户真正需要的证据是否仍然存在。
