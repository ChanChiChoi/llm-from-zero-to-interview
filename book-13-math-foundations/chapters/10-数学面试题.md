# 第十章：数学面试题：从公式复述到可验证判断

前九章分别讨论了线性代数、概率论、信息论、优化、低秩、统计学习、贝叶斯、强化学习和评估统计。最后一章不再引入一套新的数学体系，而是把这些对象放回同一个问题：当一个大模型的训练曲线、回答质量或线上指标发生变化时，我们怎样用数学说明发生了什么，又怎样知道自己的说明没有越过证据边界。

“数学面试题”这个标题容易让人想到一页页固定答案。真正有价值的数学训练却不是背诵结论，而是从一个现象出发，明确变量，写出假设，推导关系，构造反例，再把结果放回模型和系统。有人问“交叉熵和 KL 有什么关系”，背出分解式只能完成第一步；还要知道数据分布是否固定、padding 如何参与 reduction、PPL 能否跨 tokenizer 比较。有人问“LoRA 为什么有效”，写出 Delta W=BA 还不够；还要知道低秩是可表达性假设，rank 太小会欠拟合，参数量少也不代表任务成本必然低。有人问“新模型提升是否显著”，p-value 更不是终点，还要看配对单位、区间、效应量、长尾和发布代价。

本章贯穿一个候选模型升级案例。一个合同助手准备从旧版本升级到新版本：新版本使用了新的训练目标、低秩适配、证据引用和更严格的评估策略。我们会沿着它的训练损失、概率分布、参数更新、检索结果、偏好优化和发布评估一路追踪，看看不同数学对象如何互相连接，也看看它们不能互相替代的地方。

每一节都尽量同时提供三种视角。初学者先理解公式描述的对象和方向；熟悉机器学习的人再检查假设、变量和边界；工程读者最后要问这个量是否能支持一个真实动作。章节中的数据、代码和数字是教学构造，不是任何模型的性能承诺。原始论文和官方文档用于说明定义、方法或 API 语义，目标系统仍需在自己的数据、模型、硬件和风险切片上复测。

## 10.1 一道数学题真正考查什么

### 10.1.1 先把自然语言变成对象

数学问题常以一句自然语言出现：

“为什么模型训练时使用交叉熵？”
“为什么 attention 要除以 sqrt(d)？”
“为什么 DPO 还要 reference model？”
“新模型只提升 0.5%，这算不算变好？”

每句话都隐含了对象和比较关系。以第一句为例，至少需要明确：

- 真实或目标分布记为什么；
- 模型预测分布记为什么；
- loss 是对一个 token、一个序列还是一个 batch 定义；
- 训练时哪些参数变化，哪些分布保持不变；
- 评价的是优化方向，还是最终用户任务。

如果这些对象没有写出来，后面的公式即使形式正确，也可能回答了另一个问题。

设一个有限样本为：

~~~math
S=\{(x_i,y_i)\}_{i=1}^{n}
~~~

模型输出分布为 q_theta，目标分布为 p，损失为 ell。一个完整的数学描述至少要说明：

~~~math
\text{优化对象}:\quad
\theta
\qquad
\text{观测数据}:\quad
S
\qquad
\text{评价对象}:\quad
\mathbb{E}_{(x,y)\sim P}[\ell(q_\theta(\cdot\mid x),y)]
~~~

初学者可以把它理解为“谁在变、看到了什么、最后要衡量什么”。专家会进一步检查训练分布 P 和线上目标分布是否相同，样本是否独立，loss 是否按有效 token 归一化，以及 q_theta 是否包含检索和工具链路。

### 10.1.2 公式之后要追问假设

同一个公式在不同条件下可能有不同解释。例如：

~~~math
H(p,q)=H(p)+D_{\mathrm{KL}}(p\Vert q)
~~~

当 p 固定时，最小化 H(p,q) 可以等价为最小化 KL；当 p 也随训练过程变化时，H(p) 不再是关于 theta 的常数。一个好的推导不能只写等号，还要说明等号两边在什么条件下用于优化。

一个实用的检查顺序是：

1. 公式中的每个符号是什么对象；
2. 哪些量是常数，哪些量是变量；
3. 公式是定义、恒等式、近似还是经验估计；
4. 公式依赖哪些分布、独立性或终止条件；
5. 这个量能解释模型行为，还是只能描述训练过程；
6. 是否存在一个简单反例会让结论失效。

### 10.1.3 反例比背诵更能暴露理解

如果有人说“PPL 越低，模型一定越好”，一个反例就足够检验这句话：模型在普通网页文本上的 PPL 下降，但合同问答中的证据支持率下降。两者并不矛盾，因为 PPL 测量的是指定 token 分布上的预测损失，而合同任务还包含检索、版本、引用和决策条件。

如果有人说“LoRA 参数更少，所以一定不如全参数微调”，可以构造另一个反例：目标任务只需要沿少数方向调整，低秩适配在任务指标上与全参数更新相当，却显著降低训练和存储成本。低秩限制的是更新空间，不是直接规定最终任务分数。

数学训练的目标不是让每个结论都变成一句绝对话，而是学会写出：

“在假设 A、B、C 下，量 X 与量 Y 有关系；如果缺少条件 B，结论可能退化为某种近似，应该用额外评估区分。”

## 10.2 交叉熵、KL 与语言模型损失

### 10.2.1 三个分布量

设真实分布为 p(x)，模型分布为 q(x)。熵、交叉熵和 KL 散度分别为：

~~~math
H(p)
=-\sum_x p(x)\log p(x)
~~~

~~~math
H(p,q)
=-\sum_x p(x)\log q(x)
~~~

~~~math
D_{\mathrm{KL}}(p\Vert q)
=\sum_x p(x)\log\frac{p(x)}{q(x)}
~~~

把最后一个式子展开：

~~~math
D_{\mathrm{KL}}(p\Vert q)
=\sum_x p(x)\log p(x)
-\sum_x p(x)\log q(x)
~~~

因为第一项等于 -H(p)，所以：

~~~math
H(p,q)
=H(p)+D_{\mathrm{KL}}(p\Vert q)
~~~

初学者可以这样理解：真实分布自身有不可消除的不确定性 H(p)；使用 q 来描述 p 还会产生额外代价 KL。q 越接近 p，额外代价越小。

### 10.2.2 为什么训练中常说“最小化 CE 等价于最小化 KL”

如果训练数据分布 p 不随模型参数 theta 改变，那么 H(p) 与 theta 无关：

~~~math
\arg\min_\theta H(p,q_\theta)
=
\arg\min_\theta
\left[
H(p)+D_{\mathrm{KL}}(p\Vert q_\theta)
\right]
=
\arg\min_\theta
D_{\mathrm{KL}}(p\Vert q_\theta)
~~~

这里的关键不是“CE 和 KL 完全相同”，而是它们相差一个对 theta 固定的常数。若数据重采样策略、标签平滑分布或在线生成分布也随着 theta 改变，就不能不加条件地套用这句话。

### 10.2.3 语言模型中的 token 级交叉熵

自回归模型将序列概率分解为：

~~~math
p_\theta(x_{1:T})
=\prod_{t=1}^{T}
p_\theta(x_t\mid x_{<t})
~~~

负对数似然为：

~~~math
L_{\mathrm{NLL}}
=-\sum_{t=1}^{T}
\log p_\theta(x_t\mid x_{<t})
~~~

在 batch 中，实际通常按有效 token 汇总。令 m_{i,t} 属于 {0,1}，表示第 i 个样本的第 t 个位置是否参与 loss：

~~~math
L_{\mathrm{token}}
=
-\frac{
\sum_{i,t}
m_{i,t}
\log p_\theta(x_{i,t}\mid x_{i,<t})
}{
\sum_{i,t}m_{i,t}
}
~~~

这个分母决定了不同长度样本如何影响结果。若先对每条样本求平均，再对样本平均，短样本和长样本会各占一个权重；若直接按 token 汇总，长样本的有效 token 更多，贡献也可能更大。两种 reduction 都可以合理，但比较实验时必须保持口径一致。

### 10.2.4 数值例子：CE 的含义

假设真实分布为：

~~~math
p=[0.7,0.2,0.1]
~~~

模型分布为：

~~~math
q=[0.6,0.25,0.15]
~~~

使用自然对数：

~~~math
H(p)
=-0.7\log0.7-0.2\log0.2-0.1\log0.1
\approx0.802
~~~

~~~math
H(p,q)
=-0.7\log0.6-0.2\log0.25-0.1\log0.15
\approx0.825
~~~

~~~math
D_{\mathrm{KL}}(p\Vert q)
\approx0.023
~~~

因此约有：

~~~math
0.825\approx0.802+0.023
~~~

q 不是“错得一塌糊涂”，它只是比 p 多付出约 0.054 nat 的编码代价。真实语言模型的词表和上下文更复杂，但解释方式相同。

### 10.2.5 工程边界：loss 下降不代表回答变好

交叉熵只评价模型是否提高了目标 token 的概率。它不能直接检查：

- 答案是否引用了正确版本；
- 工具动作是否真的执行；
- 内容是否满足用户任务；
- 安全策略是否被绕过；
- 长答案是否只是变得更流畅。

所以合同助手升级时，训练 CE 下降只能说明优化目标被更好地拟合。还要独立测任务成功、证据支持、引用正确、拒答和工具状态。

## 10.3 PPL、tokenizer 与比较口径

### 10.3.1 Perplexity 的定义

平均 token NLL 为：

~~~math
L_{\mathrm{avg}}
=
-\frac{1}{N_{\mathrm{valid}}}
\sum_{j=1}^{N_{\mathrm{valid}}}
\log p_\theta(x_j\mid x_{<j})
~~~

PPL 定义为：

~~~math
\mathrm{PPL}
=\exp(L_{\mathrm{avg}})
~~~

如果使用以 2 为底的对数，则：

~~~math
\mathrm{PPL}
=2^{L_{\mathrm{avg}}}
~~~

PPL 可以理解为模型在指定分布上平均面对的“有效候选数”直觉。它不是字面上真正剩下多少个答案，而是交叉熵的指数变换。

### 10.3.2 为什么 PPL 低通常表示预测更好

因为 exp 是单调函数：

~~~math
L_{\mathrm{avg}}^{(1)}
<
L_{\mathrm{avg}}^{(2)}
\quad\Longrightarrow\quad
\mathrm{PPL}^{(1)}
<
\mathrm{PPL}^{(2)}
~~~

在同一个数据集、同一个 tokenizer、同一个有效 token mask 和同一个 log base 下，PPL 可以作为语言建模预测质量的汇总指标。

### 10.3.3 为什么不能随便跨 tokenizer 比

假设同一段中文在 tokenizer A 中被切成 100 个 token，在 tokenizer B 中被切成 70 个 token。每个 token 的平均 NLL 即使相同，token 数和语义片段也不同。PPL 测量的是 token 级分布，不是语言无关的句子难度。

跨 tokenizer 比较至少要说明：

- tokenizer 版本；
- 词表和 special token；
- 评估文本完全相同；
- 是否按字符、字节或 token 重新归一化；
- 是否存在不同的前缀和模板。

否则“模型 A PPL 低于模型 B”可能只是 tokenization 差异。

### 10.3.4 PPL 与指令跟随的反例

一个基础语言模型在百科文本上 PPL 很低，但未必会严格输出 JSON；一个经过 SFT 的模型可能因为更关注格式和任务行为，在通用语料 PPL 上略差，却更适合企业助手。PPL 衡量的是语言预测，不能替代：

- 结构化格式通过率；
- 事实正确率；
- 代码测试通过率；
- 证据支持率；
- 工具调用成功率；
- 人工偏好和任务成功。

## 10.4 Softmax、温度与数值稳定性

### 10.4.1 Softmax 把 logits 变成分布

给定 logits z_1,\ldots,z_K：

~~~math
p_i
=\frac{\exp(z_i)}
{\sum_{j=1}^{K}\exp(z_j)}
~~~

概率非负且满足：

~~~math
\sum_{i=1}^{K}p_i=1
~~~

对于 one-hot 标签 y，交叉熵为：

~~~math
L=-\sum_i y_i\log p_i
~~~

结合 softmax 后，对 logit 的梯度是：

~~~math
\frac{\partial L}{\partial z_i}
=p_i-y_i
~~~

如果正确类的 p_i 很低，梯度会推动其 logit 上升；如果错误类的 p_i 很高，梯度会推动其 logit 下降。

### 10.4.2 Log-sum-exp 为什么重要

直接计算 exp(z_i) 可能溢出。令 M=max_i z_i，则：

~~~math
\log\sum_i e^{z_i}
=
M+\log\sum_i e^{z_i-M}
~~~

因为每个 z_i-M 都不大于 0，指数运算更稳定。实际框架通常使用 fused cross entropy 或 log-softmax，而不是先显式计算概率再取 log。

这不仅是数值技巧，也影响训练诊断。如果低精度下出现 NaN，应该检查 logits 范围、mask 值、loss scaling 和 reduction，而不是首先把学习率随意调小。

### 10.4.3 温度改变分布形状

温度 T>0 时：

~~~math
p_i(T)
=
\frac{\exp(z_i/T)}
{\sum_j\exp(z_j/T)}
~~~

T 较小，最大 logit 的相对优势被放大，分布更尖锐；T 较大，分布更平滑。T=1 是原始 softmax。

温度只改变解码时使用的分布形状，不改变模型参数，也不自动提升事实性。高温可能增加多样性和探索，低温可能提高确定性，却也可能让错误答案更稳定。

### 10.4.4 生成策略改变了评估对象

如果同一个 checkpoint 分别用 greedy、temperature sampling 和 top-p 生成，得到的回答分布不同。比较质量时要固定或记录：

- temperature；
- top-k/top-p；
- random seed；
- max new tokens；
- stop sequence；
- repetition penalty；
- 是否使用 beam search。

否则一次提升可能来自解码设置变化，而非模型本身。

## 10.5 最大似然、MAP 与 AdamW

### 10.5.1 最大似然

给定数据 D 和模型参数 theta，最大似然估计为：

~~~math
\theta_{\mathrm{MLE}}
=
\arg\max_\theta p(D\mid\theta)
~~~

等价地：

~~~math
\theta_{\mathrm{MLE}}
=
\arg\min_\theta
-\log p(D\mid\theta)
~~~

语言模型的 next-token NLL 正是这种目标在序列分解下的实现。

### 10.5.2 最大后验

加入参数先验 p(theta) 后：

~~~math
\theta_{\mathrm{MAP}}
=
\arg\max_\theta p(\theta\mid D)
=
\arg\max_\theta p(D\mid\theta)p(\theta)
~~~

取负对数：

~~~math
\theta_{\mathrm{MAP}}
=
\arg\min_\theta
\left[
-\log p(D\mid\theta)-\log p(\theta)
\right]
~~~

若先验是均值为零的高斯分布：

~~~math
p(\theta)
\propto
\exp\left(-\frac{\lambda}{2}\|\theta\|_2^2\right)
~~~

则：

~~~math
-\log p(\theta)
=
\frac{\lambda}{2}\|\theta\|_2^2+C
~~~

这说明 L2 正则可以在特定模型假设下解释为高斯先验。它不意味着所有正则化和所有优化器都对应同一个贝叶斯后验。

### 10.5.3 Adam 的两个统计量

SGD 使用当前梯度 g_t：

~~~math
\theta_{t+1}
=
\theta_t-\eta g_t
~~~

Adam 维护一阶和二阶指数移动平均：

~~~math
m_t
=\beta_1m_{t-1}
+(1-\beta_1)g_t
~~~

~~~math
v_t
=\beta_2v_{t-1}
+(1-\beta_2)g_t^2
~~~

因为初始 m_0、v_0 为零，还要进行偏差修正：

~~~math
\hat m_t
=\frac{m_t}{1-\beta_1^t},
\qquad
\hat v_t
=\frac{v_t}{1-\beta_2^t}
~~~

基本 Adam 更新为：

~~~math
\theta_{t+1}
=
\theta_t
-\eta
\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
~~~

m 反映带动量的方向，v 反映梯度尺度。它们不是参数的不确定性，也不是 Hessian 的精确估计。

### 10.5.4 AdamW 的解耦 weight decay

AdamW 把参数衰减从自适应梯度更新中分离：

~~~math
\theta_{t+1}
=
\theta_t
-\eta
\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
-\eta\lambda\theta_t
~~~

普通 SGD 下，把 L2 项加到梯度和直接 weight decay 有相近的形式；在 Adam 中，L2 梯度会进入 m 和 v，导致不同参数的衰减受到自适应缩放影响。AdamW 的设计让衰减项直接作用于参数。

这仍然不等于“AdamW 必然泛化更好”。学习率、weight decay、参数分组、归一化参数是否衰减、训练步数和数据规模都会共同决定结果。

### 10.5.5 一个最小数值更新

假设某一时刻已经完成偏差修正，theta=[1,-2]，归一化后的 Adam 方向为 [1,-1]，学习率为 0.01，weight decay 为 0.1。则：

~~~math
\theta_{\mathrm{adam}}
=[1,-2]-0.01[1,-1]
=[0.99,-1.99]
~~~

直接衰减项为：

~~~math
-\eta\lambda\theta
=-0.001[1,-2]
=[-0.001,0.002]
~~~

合并后：

~~~math
\theta_{\mathrm{new}}
=[0.989,-1.988]
~~~

这个例子只说明更新方向，不代表真实训练中的完整 optimizer state。

## 10.6 Warmup、梯度裁剪、归一化与残差

### 10.6.1 Warmup 控制训练初期的步长

如果目标学习率为 eta_max，前 W 个 step 做线性 warmup：

~~~math
\eta_t
=
\eta_{\mathrm{max}}
\min\left(1,\frac{t}{W}\right)
~~~

训练初期的梯度统计、激活尺度和通信状态可能尚未稳定，直接使用大步长容易造成 loss spike。Warmup 让参数先在较小步长下进入合理区域。

它不是万能的稳定器。如果 label shift、mask、数据顺序或 loss reduction 出错，warmup 只会让错误发生得慢一些。

### 10.6.2 梯度裁剪改变的是更新幅度

对梯度 g 和最大范数 c，global norm clipping 为：

~~~math
g'
=
\min\left(1,\frac{c}{\|g\|_2}\right)g
~~~

当 ||g||_2<=c 时，g'=g；当梯度过大时，方向保持不变，整体缩小。裁剪不是把每个分量独立截到 [-c,c]，也不是修复错误梯度的根因。

在混合精度中，通常应先 unscale 再裁剪，否则缩放因子会改变裁剪判断。长序列、RLHF 和异常 batch 都可能使梯度分布出现长尾，应该记录裁剪触发比例。

### 10.6.3 LayerNorm 和 RMSNorm

LayerNorm 对一个向量 x 的均值和方差做归一化：

~~~math
\mu
=\frac{1}{d}\sum_{j=1}^{d}x_j
~~~

~~~math
\sigma^2
=\frac{1}{d}\sum_{j=1}^{d}(x_j-\mu)^2
~~~

~~~math
\mathrm{LN}(x)
=
\gamma\odot
\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}
+\beta
~~~

RMSNorm 不减均值，只使用均方根：

~~~math
\mathrm{RMSNorm}(x)
=
g\odot
\frac{x}
{\sqrt{\frac{1}{d}\sum_{j=1}^{d}x_j^2+\epsilon}}
~~~

它们都在控制表示尺度，却不是把所有信息“标准化成同一个向量”。参数 gamma、beta 或 g 仍允许网络恢复任务需要的尺度和方向。

### 10.6.4 Pre-LN 与残差

残差连接为：

~~~math
h_{l+1}
=
h_l+F_l(h_l)
~~~

梯度可以沿 h_l 的直接路径传播。Pre-LN 结构可抽象为：

~~~math
h_{l+1}
=
h_l+F_l(\mathrm{Norm}(h_l))
~~~

残差和归一化共同改善深层训练的条件，但具体架构还涉及初始化、学习率、attention、MLP 和输出层。不能把“有 LayerNorm”简单等同为“训练一定稳定”。

## 10.7 Attention 的缩放、mask 与残差路径

### 10.7.1 缩放因子的推导

设 q 和 k 的每个分量独立、均值为 0、方差为 1，则点积：

~~~math
q^\top k
=\sum_{j=1}^{d_k}q_jk_j
~~~

每个 q_j k_j 的期望为 0，方差约为 1，因此：

~~~math
\mathrm{Var}(q^\top k)
\approx d_k
~~~

标准差约为 sqrt(d_k)。如果直接把点积送入 softmax，d_k 增大时 score 的绝对值也增大，softmax 更容易饱和。因此 scaled dot-product attention 使用：

~~~math
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^\top}{\sqrt{d_k}}
\right)V
~~~

缩放让 score 的尺度大致保持稳定，但它依赖的方差假设在真实网络中只是近似。Norm、初始化和 learned representation 会改变实际分布，所以工程上仍要监控 logits 和 attention entropy。

### 10.7.2 Causal mask 的作用

自回归训练要求位置 t 不能看到未来位置 j>t。可以定义：

~~~math
M_{t,j}
=
\begin{cases}
0,&j\le t\\
-\infty,&j>t
\end{cases}
~~~

attention logits 加上 M 后，未来位置的 softmax 概率为 0。mask 必须和 query、key 的形状对应；在 KV cache、padding 和不同长度 batch 中，causal mask 不是一个固定的方阵就能解决所有问题。

全屏蔽一行时，softmax 可能出现 NaN 或未定义行为。实现需要保证每个有效 query 至少有一个可见 key，或者对全屏蔽行显式处理。

### 10.7.3 位置编码和缩放不是同一件事

除以 sqrt(d_k) 处理的是点积尺度；RoPE、ALiBi 或其他位置机制处理的是 token 顺序和相对位置。一个模型即使使用 RoPE，也仍然需要 attention scale。把二者混为“都是让 attention 稳定”会丢掉它们不同的数学作用。

### 10.7.4 为什么残差连接仍然重要

attention 和 MLP 计算的是对隐藏状态的变换 F(h)，残差把输入保留下来：

~~~math
h'
=h+F(h)
~~~

如果某一层暂时学不到有用变换，F(h)接近 0 时，信息仍可沿残差路径传递。深层 Transformer 的表达能力来自许多增量变换叠加，而不是每层都必须从零重建完整表示。

## 10.8 SVD、低秩近似与 LoRA

### 10.8.1 SVD 把矩阵拆成方向和尺度

任意实矩阵 W 可写为：

~~~math
W
=U\Sigma V^\top
~~~

U、V 的列是正交方向，Sigma 的对角线包含奇异值：

~~~math
\sigma_1\ge\sigma_2\ge\cdots\ge0
~~~

保留前 r 个奇异值：

~~~math
W_r
=U_r\Sigma_rV_r^\top
~~~

在 Frobenius 范数下，Eckart-Young 定理说明这是秩不超过 r 的最佳近似之一：

~~~math
\min_{\mathrm{rank}(X)\le r}
\|W-X\|_F^2
=
\sum_{j>r}\sigma_j^2
~~~

这条式子把“压缩误差”与被舍弃方向的能量联系起来，但权重重构误差小不等于任务质量损失小。某个被舍弃方向可能对少量关键任务很重要。

### 10.8.2 LoRA 约束的是更新

LoRA 冻结 W，学习：

~~~math
W'
=
W+\Delta W
~~~

~~~math
\Delta W
=
BA
~~~

若 B 属于 R^{d_out x r}，A 属于 R^{r x d_in}，则：

~~~math
\mathrm{rank}(\Delta W)
\le r
~~~

可训练参数数量为：

~~~math
N_{\mathrm{LoRA}}
=
r(d_{\mathrm{in}}+d_{\mathrm{out}})
~~~

全量矩阵参数数量为 d_out d_in，理想化参数比例是：

~~~math
\rho
=
\frac{r(d_{\mathrm{in}}+d_{\mathrm{out}})}
{d_{\mathrm{out}}d_{\mathrm{in}}}
~~~

当两个维度都为 4096、r=8 时：

~~~math
\rho
=
\frac{8(4096+4096)}{4096^2}
\approx0.003906
~~~

也就是约 0.39%。这只是可训练参数比例，不是总显存比例；冻结权重、优化器状态、激活、梯度和量化格式仍然占用资源。

### 10.8.3 为什么低秩可能足够

预训练模型已经包含通用表示。某个下游任务也许只需改变少数行为方向，低秩更新就可以找到有效的局部适配。这个解释是经验假设，不是数学定理。若任务需要新增大量知识、改变广泛的表示或跨越很大的领域差异，小 rank 可能导致训练集和验证集都欠拟合。

选择 rank 时应观察：

- 训练和验证任务指标；
- 基础能力回归；
- 不同目标模块；
- rank 与显存、吞吐的关系；
- OOD 和长尾切片；
- 单位成功任务成本。

### 10.8.4 低秩误差和任务误差要分开

权重近似误差：

~~~math
E_{\mathrm{weight}}
=\|W-W_r\|_F
~~~

任务误差变化：

~~~math
\Delta E_{\mathrm{task}}
=
E_{\mathrm{task}}(W_r)
-
E_{\mathrm{task}}(W)
~~~

两者没有固定的单调关系。要判断低秩方案是否有效，不能只报告奇异值能量或参数比例，还要在目标任务上比较质量、成本和风险。

## 10.9 Bias-variance、正则化与泛化

### 10.9.1 平方损失下的分解

在 y=g(x)+epsilon、E[epsilon|x]=0 的条件下，固定 x 的期望平方误差可以分解为：

~~~math
\mathbb{E}_{D,\epsilon}
[(f_D(x)-y)^2]
=
B^2(x)+V(x)+\sigma^2(x)
~~~

其中：

~~~math
B^2(x)
=
\left(
\mathbb{E}_D[f_D(x)]-g(x)
\right)^2
~~~

~~~math
V(x)
=
\mathbb{E}_D
\left[
\left(
f_D(x)-\mathbb{E}_D[f_D(x)]
\right)^2
\right]
~~~

sigma^2(x) 是不可约噪声。增加模型容量可能降低 bias，却可能提高小数据环境下的方差；更多数据、正则化和更稳定的优化可能改变这个平衡。

### 10.9.2 不能把生成随机性直接叫方差

LLM 输出变化可能来自：

- 训练数据和随机种子；
- 解码采样；
- prompt 改写；
- judge 或人工标注；
- 线上用户分布；
- 检索和工具状态。

这些来源不都属于经典 bias-variance 分解中的 V。若想估计训练随机性，应固定输入和解码，改变训练 seed；若想估计解码随机性，应固定 checkpoint，重复采样；若想估计用户分布变化，则要按用户或时间分层。这些实验不能用一个总 train-validation gap 代替。

### 10.9.3 正则化的不同作用层面

常见手段有不同作用对象：

| 手段 | 主要限制对象 | 不能解决的问题 |
| --- | --- | --- |
| weight decay | 参数尺度 | 测试集泄漏 |
| dropout | 表示和路径共适应 | 错误标签 |
| early stopping | 训练时间和 checkpoint | 评估集污染 |
| 数据去重 | 重复样本权重 | 任务定义不清 |
| LoRA rank | 更新子空间 | 外部工具失败 |
| KL penalty | 策略相对 reference 的偏离 | reference 本身错误 |
| 数据增强 | 表面变化覆盖 | 目标分布完全不同 |

“加正则化”不是一个统一动作。选择方法时要先判断失败来自参数容量、数据重复、训练时长还是评估协议。

### 10.9.4 训练、验证和线上差异

一个候选模型可能出现：

- 训练 loss 下降、验证 loss 上升：可能过拟合，也可能 mask 或 reduction 不一致；
- 训练和验证都好、线上差：可能目标分布或系统链路不同；
- benchmark 上升、任务成功不变：可能指标错位或污染；
- LoRA 训练 loss 下降、OOD 下降：可能 rank 或目标模块不适合。

数学指标只能作为诊断线索，必须结合数据切分、错误样本和端到端链路。

## 10.10 Bayes、MLE/MAP 与不确定性

### 10.10.1 Bayes 更新

对假设 H 和证据 E：

~~~math
p(H\mid E)
=
\frac{p(E\mid H)p(H)}
{p(E)}
~~~

用两个互斥假设展开：

~~~math
p(H\mid E)
=
\frac{
p(E\mid H)p(H)
}{
p(E\mid H)p(H)
+
p(E\mid\neg H)p(\neg H)
}
~~~

如果合同助手原先认为“条款已失效”的先验概率为 0.7，找到一份强证据的似然分别为 0.9 和 0.2，则：

~~~math
p(H\mid E)
=
\frac{0.9\times0.7}
{0.9\times0.7+0.2\times0.3}
\approx0.913
~~~

这不是把模型“变成了贝叶斯推断器”，而是提供一种审查证据强度的语言。证据必须与命题、版本、权限和来源质量绑定；文档相似不等于命题被支持。

### 10.10.2 MLE 和 MAP 的差异

MLE 只看数据：

~~~math
\theta_{\mathrm{MLE}}
=\arg\max_\theta p(D\mid\theta)
~~~

MAP 加入先验：

~~~math
\theta_{\mathrm{MAP}}
=\arg\max_\theta p(D\mid\theta)p(\theta)
~~~

在小样本或噪声较大时，先验可以让估计向合理区域收缩；数据足够多时，似然的相对作用通常增强。MAP 不是“永远比 MLE 准”，先验错误时也会带来偏差。

### 10.10.3 置信度、熵与事实正确

token 概率和熵描述模型输出分布的形状：

~~~math
H(p)
=-\sum_i p_i\log p_i
~~~

熵低表示分布集中，不能自动推断事实正确。一个错误事实可能在训练语料中非常常见，因此生成概率很高。要把置信度用于动作，需要在带标签的任务集上校准，并报告 ECE、Brier、覆盖率和选择性风险。

### 10.10.4 证据缺失时的动作

低风险任务可以给出条件化回答；高风险任务在证据不足时应检索、验证或转人工。工具超时和写操作状态未知时，系统应保留 UNKNOWN，而不是把未知改写成成功或失败。Bayes 提供的是判断语言，状态机和权限策略负责执行边界。

## 10.11 RLHF、PPO、DPO 与优势函数

### 10.11.1 生成过程的 MDP 映射

给定 prompt x，状态和动作可以写为：

~~~math
s_t=(x,y_{<t}),
\qquad
a_t=y_t
~~~

策略是：

~~~math
\pi_\theta(a_t\mid s_t)
~~~

完整回答形成 trajectory，reward model 或验证器给出结果。这个映射有用，但不应掩盖 RLHF 与传统环境交互的差异：策略从预训练和 SFT 初始化，奖励常常在序列末尾出现，外部工具还可能有真实副作用。

### 10.11.2 Return、value 和 advantage

折扣回报：

~~~math
G_t
=
\sum_{k=0}^{T-t-1}
\gamma^k r_{t+k}
~~~

状态价值：

~~~math
V^\pi(s)
=
\mathbb{E}_\pi[G_t\mid s_t=s]
~~~

动作价值：

~~~math
Q^\pi(s,a)
=
\mathbb{E}_\pi[G_t\mid s_t=s,a_t=a]
~~~

优势：

~~~math
A^\pi(s,a)
=
Q^\pi(s,a)-V^\pi(s)
~~~

在一个教学轨迹 [0,0.2,1.0]、gamma=0.9 中：

~~~math
G_2=1.0,\qquad
G_1=1.1,\qquad
G_0=0.99
~~~

若 value 估计为 [0.70,1.25,0.20]，Monte Carlo advantage 是：

~~~math
\widehat A
=[0.99-0.70,\;1.10-1.25,\;1.00-0.20]
=[0.29,-0.15,0.80]
~~~

正优势表示结果高于当前状态的预期，负优势表示低于预期。value 是 baseline，不是任务真值；估计错误会影响有限样本中的方差和偏差。

### 10.11.3 Policy gradient

策略目标：

~~~math
J(\theta)
=
\mathbb{E}_{\tau\sim\pi_\theta}[R(\tau)]
~~~

常见梯度估计：

~~~math
\widehat{\nabla_\theta J}
=
\frac{1}{N}
\sum_{i,t}
\nabla_\theta
\log\pi_\theta(a_{i,t}\mid s_{i,t})
\widehat A_{i,t}
~~~

正优势会推动对应动作的 log probability 增大，负优势会推动它减小。这是期望方向，不意味着一次 optimizer step 中每个 token 的概率都单调变化。

### 10.11.4 PPO clipping

新旧策略对同一 action 的概率比：

~~~math
\rho_t(\theta)
=
\frac{
\pi_\theta(a_t\mid s_t)
}{
\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)
}
~~~

PPO surrogate：

~~~math
L_{\mathrm{clip}}
=
\mathbb{E}_t
\left[
\min
\left(
\rho_t\widehat A_t,
\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)
\widehat A_t
\right)
\right]
~~~

若 old probability=0.25、new probability=0.40、advantage=0.80、epsilon=0.20：

~~~math
\rho=1.6,
\qquad
\rho\widehat A=1.28,
\qquad
1.2\widehat A=0.96
~~~

surrogate 取 0.96。Clipping 是局部目标保护，不是整个策略分布的严格 KL 证明，所以仍要监控 approximate KL、clip fraction、entropy、长度和 reward-human gap。

### 10.11.5 KL 和 reference

KL 方向为：

~~~math
D_{\mathrm{KL}}(p\Vert q)
=
\sum_a p(a)\log\frac{p(a)}{q(a)}
~~~

RLHF 常用抽象目标：

~~~math
J(\theta)
=
\mathbb{E}
\left[
r_\psi(x,y)
-\beta
D_{\mathrm{KL}}
\left(
\pi_\theta
\Vert
\pi_{\mathrm{ref}}
\right)
\right]
~~~

beta 太小，策略可能追逐 reward proxy 的漏洞；beta 太大，偏好更新受限。reference 只是相对锚点，不是安全和事实的绝对真值。

### 10.11.6 DPO 的相对 log probability

对 chosen y_w 和 rejected y_l，DPO 的核心 margin 可以写为：

~~~math
z
=
\beta
\left[
\log\frac{\pi_\theta(y_w\mid x)}
{\pi_{\mathrm{ref}}(y_w\mid x)}
-
\log\frac{\pi_\theta(y_l\mid x)}
{\pi_{\mathrm{ref}}(y_l\mid x)}
\right]
~~~

损失：

~~~math
L_{\mathrm{DPO}}
=
-\log\sigma(z)
~~~

DPO 省略了显式 reward model 和 PPO rollout，但仍依赖偏好数据、reference、beta、response mask 和 chat template。它不是“没有 KL”，而是把 reference 约束写进了相对 log probability 目标。

## 10.12 评估统计：从提升到证据

### 10.12.1 点估计不是结论

同一批样本上，新旧版本的逐样本差异为：

~~~math
d_i
=
m_{\mathrm{new},i}
-
m_{\mathrm{old},i}
~~~

平均提升：

~~~math
\bar d
=
\frac{1}{n}\sum_{i=1}^{n}d_i
~~~

标准误：

~~~math
\mathrm{SE}(\bar d)
=
\frac{s_d}{\sqrt n}
~~~

正态近似的 95% 区间：

~~~math
\bar d
\pm1.96\mathrm{SE}(\bar d)
~~~

如果任务是二分类，McNemar 关注旧错新对的 b 和旧对新错的 c：

~~~math
\chi^2_{\mathrm{cc}}
=
\frac{(|b-c|-1)^2}{b+c}
~~~

这些量只能回答样本和检验假设下的统计问题，不能替代目标分布、标签质量和成本判断。

### 10.12.2 Bootstrap 适合复杂指标

对基本评估单位重采样，得到统计量 T* 的经验分布：

~~~math
\mathrm{CI}_{\mathrm{boot}}
=
[
q_{0.025}(T^*),
q_{0.975}(T^*)
]
~~~

对于 paired evaluation，重采样单位必须同时包含新旧结果。对同一用户、合同或会话高度相关的样本，还应按用户或文档聚类重采样。

### 10.12.3 统计显著与实际显著

定义最小实际有意义提升 delta_min：

~~~math
\mathrm{publish\ candidate}
\Longrightarrow
\mathrm{lower\ bound}(\Delta)
>\delta_{\mathrm{min}}
~~~

这还只是候选条件。实际发布要同时检查：

- 高风险错误率；
- 自动覆盖率和转人工率；
- p95/p99 延迟；
- 单位成功任务成本；
- 权限和安全回归；
- 关键租户和语言切片。

p-value 小不代表新模型值得上线；p-value 不小也不代表模型一定没有提升，可能只是证据不足。

### 10.12.4 多重比较和消融

如果同时尝试许多 prompt、checkpoint、指标和分层，偶然显著的机会会上升。Bonferroni 控制更保守的 family-wise error，Benjamini-Hochberg 更适合探索性发现，但两者都不能修复样本污染或指标错位。

消融要固定其他条件，记录模型、数据、索引、prompt、解码、seed 和失败样本。组件之间可能存在交互，因此只做“全系统”和“去掉一个组件”有时不足以解释贡献。

## 10.13 一个综合案例：新模型为什么不能只看训练 loss

### 10.13.1 观察到的现象

合同助手新版本有四个变化：

1. 用 rank=8 的 LoRA 适配合同问答；
2. 增加版本过滤和 claim 级引用；
3. 使用偏好数据做 DPO；
4. 将最终评估从单一 judge 分数改成任务成功率和证据支持率。

训练日志显示：

- SFT token loss 下降；
- DPO loss 下降；
- 输出平均长度上升；
- judge 偏好分上升。

这些数字看起来方向一致，却还不能推出“新模型可靠性提升”。需要把每个数字放回它的数学对象：

| 观测 | 直接说明 | 不直接说明 |
| --- | --- | --- |
| token loss 下降 | 目标 token 概率提高 | 事实、权限和任务成功 |
| DPO loss 下降 | chosen 相对 reference 的 margin 被优化 | 人工偏好和真实任务一定提升 |
| 长度上升 | 生成策略改变 | 信息量和证据支持提高 |
| judge 分上升 | 某个测量器给分更高 | 人工金标准和高风险正确 |
| LoRA 参数少 | 更新空间受限、资源可能降低 | 欠拟合或泛化一定不存在 |
| 证据支持率上升 | claim 与引用绑定更好 | 检索和版本链路全都正确 |

### 10.13.2 逐步建立证据链

第一步，固定同一批合同问题和文档版本，保存旧新回答及逐 claim 标签。

第二步，计算端到端任务成功：

~~~math
Y_i
=
\mathbf{1}
[
\mathrm{content}_i
\land
\mathrm{format}_i
\land
\mathrm{citation}_i
\land
\mathrm{permission}_i
]
~~~

第三步，对新旧版本做 paired bootstrap，并按合同版本、风险等级和租户分层。

第四步，检查 DPO 后输出长度、拒答率、引用覆盖率和错误类型，排除“写得更长所以 judge 更喜欢”的解释。

第五步，记录 LoRA rank、目标模块、训练 token 和基础能力回归，确认低秩适配没有在 OOD 任务上明显退化。

第六步，在小流量线上实验中按用户或组织稳定分流，预先设置延迟、成本和安全护栏。

### 10.13.3 一个可能的结果

教学数据如下：

| 指标 | 旧版本 | 新版本 |
| --- | ---: | ---: |
| 任务成功率 | 0.78 | 0.82 |
| 证据支持率 | 0.71 | 0.86 |
| 高风险错误率 | 0.040 | 0.018 |
| 自动覆盖率 | 0.94 | 0.83 |
| p95 延迟 | 620 ms | 810 ms |
| 单位成功成本 | 1.00 | 1.25 |

这个结果支持一种有条件的结论：新版本在目标合同任务上更可靠，但它通过更多验证和转人工换来了覆盖率下降、延迟上升和成本增加。如果某租户的权限过滤仍有回归，就不能直接扩大到所有租户。

### 10.13.4 反例：所有数字都好看仍可能错

如果评估集主要来自旧版合同，新的版本过滤自然很容易得到提升；如果开发者反复使用这些合同调 prompt，结果可能被污染；如果 judge 对长回答偏好，DPO 的输出变长会带来表面分数提升。只有加入新版本文档、未见租户、动态问题和人工复核，才能判断提升是否可迁移。

## 10.14 综合实验：把数学对象放在同一张实验台

下面的 Python 示例只使用标准库。它不模拟一个完整大模型，而是把前面讨论的数学对象放在一起：稳定 softmax、熵/交叉熵/KL、PPL、梯度裁剪、AdamW 单步更新、LoRA 参数比例、Bayes 更新、PPO surrogate、DPO margin 和 paired lift。每个输出都对应一个明确的定义，代码中的 checks 用来检查代数关系，而不是给学习者贴“准备好”或“没准备好”的标签。

~~~python
from math import exp, log, sqrt
import random


def stable_softmax(logits, temperature=1.0):
    if not logits or temperature <= 0:
        raise ValueError("logits must be non-empty and temperature positive")
    scaled = [value / temperature for value in logits]
    shift = max(scaled)
    weights = [exp(value - shift) for value in scaled]
    total = sum(weights)
    return [weight / total for weight in weights]


def entropy(probabilities):
    if not probabilities:
        raise ValueError("probabilities must not be empty")
    if any(probability < 0 for probability in probabilities):
        raise ValueError("probabilities must be non-negative")
    total = sum(probabilities)
    if abs(total - 1.0) > 1e-9:
        raise ValueError("probabilities must sum to one")
    return -sum(
        probability * log(probability)
        for probability in probabilities
        if probability > 0
    )


def cross_entropy(target, prediction):
    if len(target) != len(prediction):
        raise ValueError("distributions must have equal length")
    if any(probability <= 0 for probability in prediction):
        raise ValueError("prediction probabilities must be positive")
    if abs(sum(target) - 1.0) > 1e-9:
        raise ValueError("target must sum to one")
    return -sum(
        target_probability * log(prediction_probability)
        for target_probability, prediction_probability
        in zip(target, prediction)
        if target_probability > 0
    )


def kl_divergence(target, prediction):
    if len(target) != len(prediction):
        raise ValueError("distributions must have equal length")
    if any(probability <= 0 for probability in prediction):
        raise ValueError("prediction probabilities must be positive")
    return sum(
        target_probability
        * log(target_probability / prediction_probability)
        for target_probability, prediction_probability
        in zip(target, prediction)
        if target_probability > 0
    )


def perplexity(log_probabilities):
    if not log_probabilities:
        raise ValueError("log probabilities must not be empty")
    average_nll = -sum(log_probabilities) / len(log_probabilities)
    return exp(average_nll)


def clip_gradient(gradient, max_norm):
    if not gradient or max_norm <= 0:
        raise ValueError("gradient and max_norm must be valid")
    norm = sqrt(sum(value * value for value in gradient))
    scale = min(1.0, max_norm / norm)
    return [value * scale for value in gradient], norm, scale


def adamw_one_step(
    parameters,
    gradients,
    learning_rate,
    weight_decay,
):
    if len(parameters) != len(gradients):
        raise ValueError("parameters and gradients must have equal length")
    if learning_rate <= 0 or weight_decay < 0:
        raise ValueError("invalid optimizer settings")

    # A first-step, bias-corrected Adam direction is used for a small audit.
    direction = [
        gradient / (abs(gradient) + 1e-12)
        for gradient in gradients
    ]
    return [
        parameter
        - learning_rate * update
        - learning_rate * weight_decay * parameter
        for parameter, update in zip(parameters, direction)
    ]


def bayes_binary(prior, evidence_given_true, evidence_given_false):
    numerator = prior * evidence_given_true
    denominator = numerator + (1 - prior) * evidence_given_false
    if denominator <= 0:
        raise ValueError("evidence probability must be positive")
    return numerator / denominator


def ppo_surrogate(old_probability, new_probability, advantage, epsilon):
    if old_probability <= 0 or new_probability <= 0 or epsilon <= 0:
        raise ValueError("probabilities and epsilon must be positive")
    ratio = new_probability / old_probability
    clipped_ratio = max(1 - epsilon, min(1 + epsilon, ratio))
    return {
        "ratio": ratio,
        "unclipped": ratio * advantage,
        "clipped": clipped_ratio * advantage,
        "surrogate": min(
            ratio * advantage,
            clipped_ratio * advantage,
        ),
    }


def dpo_terms(
    policy_chosen,
    policy_rejected,
    reference_chosen,
    reference_rejected,
    beta,
):
    if beta <= 0:
        raise ValueError("beta must be positive")
    margin = beta * (
        (policy_chosen - reference_chosen)
        - (policy_rejected - reference_rejected)
    )
    return margin, -log(1 / (1 + exp(-margin)))


def mean(values):
    if not values:
        raise ValueError("values must not be empty")
    return sum(values) / len(values)


target = [0.7, 0.2, 0.1]
prediction = [0.6, 0.25, 0.15]
target_entropy = entropy(target)
model_cross_entropy = cross_entropy(target, prediction)
distribution_kl = kl_divergence(target, prediction)

probabilities = stable_softmax([2.0, 1.0, 0.0])
one_hot = [1.0, 0.0, 0.0]
softmax_gradient = [
    probability - label
    for probability, label in zip(probabilities, one_hot)
]

sequence_log_probabilities = [-0.2, -0.5, -1.1, -0.7]
sequence_ppl = perplexity(sequence_log_probabilities)

clipped_gradient, gradient_norm, clip_scale = clip_gradient(
    [3.0, 4.0, 12.0],
    max_norm=5.0,
)
adamw_parameters = adamw_one_step(
    parameters=[1.0, -2.0],
    gradients=[0.5, -0.25],
    learning_rate=0.01,
    weight_decay=0.1,
)

full_parameters = 4096 * 4096
lora_parameters = 8 * (4096 + 4096)
lora_ratio = lora_parameters / full_parameters

posterior = bayes_binary(
    prior=0.70,
    evidence_given_true=0.90,
    evidence_given_false=0.20,
)

ppo = ppo_surrogate(
    old_probability=0.25,
    new_probability=0.40,
    advantage=0.80,
    epsilon=0.20,
)
dpo_margin, dpo_loss = dpo_terms(
    policy_chosen=-1.2,
    policy_rejected=-2.0,
    reference_chosen=-1.5,
    reference_rejected=-1.7,
    beta=0.5,
)

old_results = [1, 0, 1, 0, 1, 0, 1, 0]
new_results = [1, 1, 1, 1, 0, 0, 1, 1]
paired_differences = [
    new - old
    for old, new in zip(old_results, new_results)
]
paired_lift = mean(paired_differences)

random_generator = random.Random(11)
bootstrap_means = []
for _ in range(1000):
    sample = [
        paired_differences[
            random_generator.randrange(len(paired_differences))
        ]
        for _ in paired_differences
    ]
    bootstrap_means.append(mean(sample))
bootstrap_means.sort()
bootstrap_ci = (
    bootstrap_means[25],
    bootstrap_means[975],
)

checks = {
    "ce_kl_decomposition": abs(
        model_cross_entropy
        - target_entropy
        - distribution_kl
    ) < 1e-9,
    "softmax_gradient_sums_zero": abs(sum(softmax_gradient)) < 1e-9,
    "ppl_is_positive": sequence_ppl > 0,
    "gradient_was_clipped": abs(clip_scale - 5 / 13) < 1e-9,
    "adamw_applies_decay": adamw_parameters[0] < 0.99,
    "lora_is_parameter_efficient": lora_ratio < 0.01,
    "evidence_raises_posterior": posterior > 0.70,
    "ppo_clips_large_positive_ratio": (
        ppo["surrogate"] < ppo["unclipped"]
    ),
    "dpo_margin_prefers_chosen": dpo_margin > 0,
    "bootstrap_contains_paired_lift": (
        bootstrap_ci[0] <= paired_lift <= bootstrap_ci[1]
    ),
}

report = {
    "distribution": {
        "entropy": round(target_entropy, 3),
        "cross_entropy": round(model_cross_entropy, 3),
        "kl": round(distribution_kl, 3),
    },
    "softmax": {
        "probabilities": [round(value, 3) for value in probabilities],
        "gradient": [round(value, 3) for value in softmax_gradient],
    },
    "sequence": {"ppl": round(sequence_ppl, 3)},
    "optimization": {
        "gradient_norm": round(gradient_norm, 3),
        "clip_scale": round(clip_scale, 3),
        "clipped_gradient": [
            round(value, 3)
            for value in clipped_gradient
        ],
        "adamw_parameters": [
            round(value, 3)
            for value in adamw_parameters
        ],
    },
    "low_rank": {
        "full_parameters": full_parameters,
        "lora_parameters": lora_parameters,
        "ratio": round(lora_ratio, 6),
    },
    "bayes": {"posterior": round(posterior, 3)},
    "rlhf": {
        "ppo": {
            key: round(value, 3)
            for key, value in ppo.items()
        },
        "dpo": {
            "margin": round(dpo_margin, 3),
            "loss": round(dpo_loss, 3),
        },
    },
    "evaluation": {
        "paired_lift": round(paired_lift, 3),
        "bootstrap_ci": tuple(
            round(value, 3)
            for value in bootstrap_ci
        ),
    },
    "checks": checks,
}

print(report)
~~~

代码的重点不是把这些对象拼成一个“总分”，而是让读者看到它们之间的接口：

## 10.15 常见反例：一句“正确的话”为什么仍然不够

### 10.15.1 “交叉熵就是 KL”

缺少条件。正确关系是：

~~~math
H(p,q)
=
H(p)+D_{\mathrm{KL}}(p\Vert q)
~~~

只有在 p 固定、优化变量只影响 q 时，二者的最小化才等价。若标签平滑分布、数据混合权重或评估对象变化，解释要重新检查。

### 10.15.2 “PPL 越低，模型越强”

PPL 只覆盖指定 token 分布上的预测。模型可能 PPL 更低，却在指令、工具、引用或安全任务上更差。必须说清评估分布和任务层指标。

### 10.15.3 “LoRA rank 越大越好”

rank 增大提高更新空间，也提高参数、显存和过拟合风险。实际需要做 rank 消融，并同时看验证、OOD、基础能力和单位成本。

### 10.15.4 “KL 越小越稳定”

KL 很小可能表示策略没有学到新偏好，也可能 reference 本身已经很接近目标。KL 不是质量指标，必须与 reward、任务成功和安全约束一起解释。

### 10.15.5 “DPO 一定比 PPO 简单，所以一定更好”

DPO 的训练链路通常更简洁，但偏好数据是离线固定的，可能存在 support mismatch；PPO 能使用当前策略 rollout 和显式 reward，却需要 value、采样和稳定性管理。哪种方法更好取决于反馈形式、数据覆盖和成本。

### 10.15.6 “p-value 小就能上线”

显著性只针对当前检验假设。即使主指标显著，延迟、成本、权限或高风险错误恶化，也不能直接发布。发布结论必须包含效应量、区间、护栏和分层。

## 10.16 练习：从复述公式到完成推理

### 练习一：交叉熵的 reduction

构造两个 batch：一个含 2 条短序列，一个含 2 条长序列。分别按样本平均和按有效 token 平均计算 loss，解释为什么结果不同，并说明在比较训练 run 时应保存哪些元数据。

### 练习二：PPL 的比较边界

用同一段文本和两个不同 tokenizer 构造一个思想实验。说明为什么 token-level PPL 不应直接横向比较，并提出一个更合适的报告方式。

### 练习三：数值稳定性

给出 logits=[1000,999,998]。分别说明直接计算 exp 可能发生什么，使用 log-sum-exp 如何改写。再说明 temperature 对稳定性和生成多样性的作用不同在哪里。

### 练习四：AdamW 单步更新

给定参数、梯度、学习率和 weight decay，分别写出 Adam 方向和解耦衰减项。说明为什么在自适应优化器中，L2 正则和 AdamW 不能简单当作同一个实现。

### 练习五：梯度裁剪

给出梯度向量 [6,8] 和最大范数 5，计算裁剪后的向量。再解释 global clipping 与逐元素 clipping 对方向有什么不同。

### 练习六：Attention 缩放

假设 q、k 各维独立且方差为 1，推导 q^T k 的方差随 d_k 如何变化。构造一个不满足独立假设的情况，说明 sqrt(d_k) 缩放为什么只是近似。

### 练习七：LoRA rank

对 d_in=2048、d_out=4096，计算全量参数和 rank=4、rank=16 的 LoRA 参数比例。设计一个 rank 消融，至少包含训练、验证、OOD 和成本四列。

### 练习八：泛化反例

设计一个训练 loss 下降、验证 loss 下降、线上任务成功率却下降的系统。把失败拆成模型分布、评估指标和系统链路三种可能原因。

### 练习九：Bayes 证据

某命题先验为 0.4，证据在命题为真时出现概率为 0.8，在命题为假时出现概率为 0.2。计算后验，并说明证据相关性会怎样改变多文档更新。

### 练习十：PPO 和 DPO

给定 old/new action probability、advantage、epsilon，计算 PPO surrogate；再给定 chosen/rejected 的 policy/reference log probability，计算 DPO margin。解释两者为什么不能只比较 loss 数值大小。

### 练习十一：任务成功率

为合同问答定义 content、format、evidence、permission 四个二值条件。构造一个“平均支持率很高但高风险付款金额错误”的例子，说明为什么需要加权风险或硬约束。

### 练习十二：统计发布

给定新旧版本在同一批问题上的结果，计算 paired lift、bootstrap 区间和高风险切片。制定一个包含最小实际提升、延迟、成本和安全护栏的发布规则。

### 练习十三：反事实解释

选择本章一个结论，改变它的关键假设，构造一个结论不再成立的反例。例如让目标分布变化、让 reference 本身不可靠或让评估集被开发过程使用。

## 10.18 把数学变成工程判断

数学面试真正检验的不是记忆量，而是能否在一条连续链上保持对象、方向和证据一致。

交叉熵、KL 和 PPL 让我们理解模型在预测什么；softmax、log-sum-exp、AdamW、warmup、裁剪、归一化和残差让我们理解参数为什么能够稳定更新；attention 的缩放、SVD 和 LoRA 让我们理解架构和参数高效适配的结构；泛化、Bayes 和校准提醒我们训练分数与真实任务之间仍有距离；PPO、DPO 和 KL 让我们看到偏好优化如何在 reward、reference 和策略变化之间取舍；配对评估、bootstrap、效应量和护栏则决定一个结果是否足以支持发布。

一个成熟的数学判断通常具备四个部分：

1. 先说明对象和目标，而不是直接扔公式；
2. 写出公式并解释变量、方向和归一化；
3. 给出一个数值例子或反例，检验公式是否真的支持结论；
4. 把结论放回数据、模型、系统和风险边界。

当一个数字看起来很好时，先问它测量的是什么；当一个公式看起来漂亮时，先问它依赖什么假设；当一个模型看起来更强时，先问提升是否能在新分布、真实任务和可接受成本下重复。这样，数学才不只是面试中的回答材料，而是理解模型、设计实验和承担工程决策的共同语言。
