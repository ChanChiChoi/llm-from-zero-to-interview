# 第 14 章 重要论文索引

论文索引的价值不在于把标题排列得更长，而在于把技术变化还原成问题、假设、实验和影响。一个方法只有在明确回答了“它改变了什么、靠什么改变、在哪些条件下成立、付出了什么代价”之后，才真正进入知识，而不只是进入记忆。

本章把论文放回技术谱系中阅读。架构论文通常改变表示和计算路径，训练论文通常改变数据或优化目标，系统论文通常改变内存、通信和调度，应用论文则把这些能力放入检索、工具、多模态或安全场景。不同论文的模型规模、数据质量、硬件、评测集和实现版本经常不同，所以论文中的单个分数不能直接组成一张跨论文排行榜。

论文提供的是有条件的证据。原论文可以支持“在该实验设置下观察到某种现象”，官方实现可以支持“某个接口或算法按照该方式工作”，复现实验可以支持“在当前环境中重新得到某种结果”，但它们都不自动支持“所有模型、所有数据和所有生产系统都具有同样结论”。本章在每个主题中都把这些边界写出来。

## 14.1 一篇论文究竟贡献了什么

### 从标题退回研究问题

论文标题往往只告诉读者方法名称，真正决定论文价值的是它所针对的瓶颈。例如，Transformer 针对循环结构的并行性和长距离依赖问题；Chinchilla 针对固定算力下参数和数据配比问题；FlashAttention 针对 attention 的内存访问问题；DPO 针对 RLHF 流程的优化复杂度问题。若只记住“它提出了某某方法”，就无法解释为什么这项工作会出现。

一个适合阅读的最小问题描述包含五部分：

1. 任务输入和输出是什么；
2. 旧方法在哪个环节失败或成本过高；
3. 新方法改变了模型、数据、优化或系统的哪一部分；
4. 实验用什么基线和指标区分“真的改善”和“换了条件”；
5. 结果在哪些数据、规模、硬件和攻击模型之外不应直接外推。

初学者可以先用这五个问题把摘要还原成因果链。有经验的读者还要检查控制变量：如果新方法用了更多数据、更长训练、更大的 batch 或更强的后处理，最终提升究竟来自方法本身，还是来自额外预算。

### 分数、成本和外推

设方法在测试集上的指标为 A，基线指标为 A0，最直接的绝对增益是：

~~~math
\Delta A=A-A_0
~~~

如果方法改变了延迟、显存或训练计算，还要记录成本差异：

~~~math
\Delta C=C-C_0
~~~

只有在任务、指标和成本口径一致时，才可以讨论单位成本收益。一个简单的比较量是：

~~~math
\operatorname{GainPerCost}
=\frac{\Delta A}{\Delta C},\qquad \Delta C>0
~~~

这个量只在成本增量 `ΔC` 严格为正时有定义。如果成本没有增加，应单独报告成本节省或成本不变，不能把分母替换成一个小常数来制造比较数字。它也不是通用排名指标，因为不同成本可能不能互换；它只是提醒读者，准确率提升和资源代价应同时被记录。

论文结论的外推还受到分布差异影响。设训练或论文测试分布为 Dpaper，目标系统分布为 Dtarget，则：

~~~math
\mathbb{E}_{x\sim D_{\text{paper}}}[u(x)]
\neq
\mathbb{E}_{x\sim D_{\text{target}}}[u(x)]
~~~

即使论文中方法的平均效用很高，目标用户、语言、长度、工具权限和错误代价变化后，结论也可能改变。

### 一个小型证据账本

下面的代码只演示如何把绝对增益和成本一起记录。它不模拟任何真实论文结果，数值是教学构造：

~~~python
from dataclasses import dataclass
import math


@dataclass(frozen=True)
class Experiment:
    name: str
    baseline: float
    method: float
    cost: float

    def __post_init__(self):
        if not isinstance(self.name, str) or not self.name.strip():
            raise ValueError("experiment name must be non-empty")
        for value in (self.baseline, self.method, self.cost):
            if not isinstance(value, (int, float)) or isinstance(value, bool):
                raise TypeError("experiment values must be numeric")
            if not math.isfinite(value):
                raise ValueError("experiment values must be finite")
        if self.cost <= 0:
            raise ValueError("experiment cost must be positive")

    @property
    def gain(self):
        return self.method - self.baseline

    @property
    def gain_per_cost(self):
        return self.gain / self.cost


experiments = [
    Experiment("attention kernel", 0.82, 0.86, 1.20),
    Experiment("retrieval rerank", 0.82, 0.85, 0.60),
]

for item in sorted(experiments, key=lambda value: value.gain_per_cost, reverse=True):
    print(item.name, round(item.gain, 3), round(item.gain_per_cost, 3))
try:
    Experiment("zero-cost", 0.8, 0.9, 0)
except ValueError:
    print("non-positive experiment cost rejected")
else:
    raise AssertionError("non-positive experiment cost was accepted")
~~~

输出可以帮助读者发现一个常见误区：绝对分数最高的方法，不一定是单位成本收益最高的方法。真正的论文复现还需要把数据版本、随机种子、硬件、软件版本和统计区间加入账本。

## 14.2 Attention Is All You Need：从循环序列到全局依赖

### 旧问题

在 Transformer 之前，序列建模的主力是 RNN、LSTM 和卷积网络。循环结构沿时间步传递状态，理论上能够处理长序列，但训练过程难以完全并行；距离很远的两个 token 之间需要经过多次状态传递，优化和信息保留都比较困难。

Transformer 论文把序列中的每个位置映射成 query、key 和 value，并允许一个位置直接读取其他位置的信息。缩放点积 attention 写成：

~~~math
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(
\frac{QK^{\mathsf T}}{\sqrt{d_k}}
\right)V
~~~

Q 是查询矩阵，K 是被查询的键，V 是要聚合的值，dk 是每个 key 向量的维度。除以根号 dk 是为了控制点积的尺度，避免维度变大后 softmax 过早饱和。

### 方法改变在哪里

论文同时提出 multi-head attention、位置编码、encoder-decoder 结构、残差连接、LayerNorm 和前馈网络。多头结构让模型可以在不同表示子空间中学习不同关系；位置编码为没有循环顺序的 attention 注入位置信息；残差和归一化让深层堆叠更容易训练。

Self-attention 的核心矩阵 QKT 具有序列长度平方级的计算和中间存储。对长度 T、head 维度 d 的单头 attention，教学级复杂度可写为 O(T²d)。这解释了为什么 Transformer 获得了全局依赖能力，却也为长上下文带来成本。

### 证据和局限

原论文在机器翻译上比较了循环、卷积和 attention 方案，证明并行训练和翻译质量可以同时改善。但现代 decoder-only LLM 并没有原样保留 encoder-decoder、正弦位置编码和所有训练设置，而是沿着这套模块继续改变。

Transformer 的贡献不是“attention 永远优于其他结构”，而是证明了全局内容寻址、并行训练和深度残差堆叠可以组成一个高效的序列建模框架。后来的 RoPE、GQA、FlashAttention、Mamba 和 MoE 都是在不同约束下重新分配表达能力、内存和计算。

## 14.3 BERT：双向理解与预训练迁移

### 掩码语言模型

BERT 代表 encoder-only 路线。训练时随机遮盖输入中的一部分 token，让模型利用左右两侧上下文恢复它们。与单向 next-token prediction 相比，masked language modeling 更直接地构造了整段文本的双向表示。

它解决的是理解任务的统一预训练问题：分类、问答、序列标注和句子关系判断原本需要各自设计模型，BERT 先在大规模无标注文本上学习通用表示，再用少量任务数据微调。

### 影响与边界

BERT 的重要性不只是一个模型分数，而是“预训练加下游适配”成为通用范式。它也暴露了目标和使用方式之间的约束：训练时遮盖 token，推理时却通常输入完整句子；模型可以理解双向上下文，但不天然适合自回归长文本生成。

因此，BERT 与 GPT 不能简单比较谁更强。BERT 的 inductive bias 更适合理解和编码，GPT 的 causal mask 更贴近开放式生成。后续 encoder-decoder、decoder-only 和双向上下文方法的选择，都应回到任务输出形式和推理路径。

## 14.4 GPT 系列：统一的自回归生成目标

### 从 GPT-1 到 GPT-3

GPT 路线用 decoder-only Transformer 预测下一个 token：

~~~math
\mathcal{L}_{\text{AR}}
=
-\sum_{t=1}^{T}
\log p_{\theta}(x_t\mid x_{<t})
~~~

xt 是第 t 个 token，x<t 是它之前的上下文，T 是序列长度，θ 是模型参数。这个目标与生成接口天然一致，训练时可以对整个序列并行计算 logits，推理时再逐 token 采样。

GPT-2 的重要信号是：规模化的无监督语言模型能够在没有显式任务头的情况下表现出多任务能力。GPT-3 进一步展示了 few-shot 和 in-context learning 的规模效应。这里的关键不是“只要扩大模型就会解决一切”，而是模型容量、数据覆盖、上下文示例和解码方式共同改变了任务表现。

### 自回归目标的代价

错误会沿生成链传播，事实性和工具调用不能只依赖 next-token loss。模型还可能生成流畅但不真实的文本，因为语言概率和世界事实不是同一个目标。后训练、检索、验证器、工具权限和系统评估因此成为生成模型的必要补充。

GPT 系列建立了现代通用 LLM 的主干，但不是一套固定架构。RoPE、RMSNorm、SwiGLU、GQA、MoE、长上下文训练和 reasoning post-training 都是后来围绕这条主干做的改造。

## 14.5 T5：把任务统一为 text-to-text

T5 选择 encoder-decoder 架构，把分类、翻译、摘要、问答等任务都写成文本到文本映射。统一接口减少了任务特定的输出头，让预训练目标和下游生成形式更接近。

这项工作的研究价值在于系统比较了预训练数据、目标、模型规模和迁移方式，而不只是提出一个新的网络模块。它说明“统一任务形式”本身可以成为模型设计变量。

T5 并没有成为现代聊天模型的唯一主流架构。长序列自回归生成、工具调用和开放式对话使 decoder-only 路线更常见；但 encoder-decoder 仍适合条件生成、翻译、摘要和某些编辑任务。论文的真正遗产是任务接口和预训练迁移思想，而不是固定的模型形态。

## 14.6 Scaling Laws：把规模扩展变成可估计问题

### 经验规律

Scaling Laws 研究模型参数量 N、训练数据量 D、计算量 C 与 loss 之间的关系。常见的教学近似是：

~~~math
L(N,D,C)
\approx
L_{\infty}
+aN^{-\alpha}
+bD^{-\beta}
+cC^{-\gamma}
~~~

L∞ 是经验极限，a、b、c 和指数 α、β、γ 需要根据数据和训练配方拟合。它不是任意模型、任意数据和任意下游任务都成立的自然定律，而是预算规划的经验工具。

### 论文带来的方法论

研究团队可以先训练一组较小模型，在控制数据和优化器的条件下拟合 loss 曲线，再预测更大配置的收益。这使模型规模、数据规模和训练步数不再完全依赖经验拍板。

但 loss 的可预测性不等于所有能力都可预测。推理、工具使用、安全行为和长上下文利用可能在某些规模或数据条件下出现不连续变化；污染、数据质量和训练后处理也会破坏简单外推。

### 工程边界

使用 scaling law 时必须记录 token 去重、数据质量、训练 token 是否重复、硬件效率和目标指标。一个在预训练 loss 上更优的配方，不一定在事实性、代码执行或拒答质量上更优。

## 14.7 Chinchilla：固定计算预算下重新平衡模型与数据

早期扩展实践常把大量预算投入更大的参数量，却没有给模型足够训练 token。Chinchilla 论文研究固定计算预算下参数量 N 和数据量 D 的平衡，强调 compute-optimal training。

可以抽象为：

~~~math
\min_{N,D}L(N,D)
\qquad
\text{subject to}\qquad
C(N,D)\leq C_{\max}
~~~

Cmax 是计算预算。具体的成本函数依赖层数、隐藏维度、序列长度、并行方式和硬件，所以不能把论文结论简化成对所有模型都适用的固定 token/parameter 比例。

Chinchilla 的重要影响是改变了“参数越大越好”的直觉。较小但训练更充分的模型可能在固定推理成本下取得更好的效果；与此同时，数据质量、重复率、领域覆盖和后训练预算都会改变最佳点。

这项工作也提醒读者区分训练最优和部署最优。训练 token 更多可能增加预训练成本，模型更小可能降低线上延迟，但能力、上下文容量和并发成本还要另外评估。

## 14.8 PaLM 与 LLaMA：规模化配方和开放生态

PaLM 展示了大规模 dense decoder-only 模型在多任务、推理、多语言和代码任务上的扩展效果。它的重要性在于公开了大规模训练、数据混合和能力评估的系统经验，而不是证明参数量单独决定能力。

LLaMA 则把“高质量数据加现代 decoder-only 配方”与开放权重生态连接起来。RMSNorm、SwiGLU、RoPE 等组件后来成为许多开源模型的常见选择；开放权重又推动了 LoRA、量化、推理框架和社区评测的发展。

这两类论文不能只按榜单数字比较。PaLM 重点是规模化训练经验，LLaMA 重点是开放生态和高效配方。读者应分别关注数据、训练计算、许可、权重开放范围和复现实验条件。

## 14.9 RoFormer：RoPE 如何把位置信息放进内容关系

### 旋转位置编码

RoPE 不把一个独立位置向量简单加到 token 表示上，而是对 query 和 key 的二维子空间做与位置有关的旋转。对位置 m 的二维分量，可以抽象写为：

~~~math
R_{\theta,m}
=
\begin{bmatrix}
\cos(m\theta)&-\sin(m\theta)\\
\sin(m\theta)&\cos(m\theta)
\end{bmatrix}
~~~

将不同维度使用不同频率 θ 后，query 与 key 的内积会带有相对位置关系。这个性质让 attention 分数同时依赖内容和相对距离。

### 为什么重要

RoPE 在 decoder-only LLM 中广泛使用，因为它不需要额外的位置 embedding 表，并且与自回归 attention 结合自然。它也让长上下文扩展变成频率、缩放、训练长度和插值策略的系统问题。

RoPE 不等于无限长度外推。若训练时覆盖的相位范围与推理时相差太大，旋转角度分布、注意力分辨率和数值行为都会改变。线性 scaling、NTK-aware scaling、YaRN 等后续方法都要在目标长度和任务上重新评估。

## 14.10 ALiBi：用注意力偏置表达距离

ALiBi 不旋转 token 表示，而是在 attention logits 上加入与相对距离相关的线性偏置：

~~~math
s_{ij}
=
\frac{q_i k_j^{\mathsf T}}{\sqrt{d_k}}
-m_h(i-j)
~~~

m_h 是第 h 个 attention head 的斜率。距离越远，偏置通常越不利于注意力连接，因此模型在训练长度之外可能保留一定的距离归纳偏置。

ALiBi 的价值在于展示位置机制不只有“给 token 加 embedding”这一种形式。它的代价是偏置结构可能限制某些长距离关系，且与现代模型的训练 recipe、局部注意力和缓存策略需要一起分析。

RoPE 与 ALiBi 的比较不能只看单个长上下文分数。还要观察短上下文质量、长度外推、不同任务、不同语言和 attention pattern。位置编码是模型能力的一部分，也是推理账本的一部分。

## 14.11 Mamba：从二次 attention 到选择性状态空间

Mamba 研究选择性状态空间模型，希望用线性序列计算处理长序列，同时保留对输入内容的选择能力。连续状态空间的离散形式可以写成：

~~~math
h_t=\bar{A}_t h_{t-1}+\bar{B}_t x_t
~~~

~~~math
y_t=C_t h_t
~~~

ht 是递归状态，xt 是输入，yt 是输出。Mamba 的选择性机制让部分参数随输入变化，使模型可以决定哪些信息应该写入状态、哪些信息应该忘记。

它解决的是 attention 在长序列上的计算和内存成本问题，并提供了另一条递归建模路线。Mamba 的线性复杂度不代表所有任务都一定更好：需要精确 token-to-token 交互的任务、长距离复制和复杂检索可能仍受状态压缩影响。

后续 hybrid architecture 把 attention 与 SSM 交替或组合，说明架构选择正在从“attention 对 SSM”转向“不同状态访问模式如何分工”。比较时应同时记录训练吞吐、decode 延迟、长距离检索、状态内存和 kernel 成熟度。

## 14.12 FlashAttention：改变 attention 的内存访问

标准 attention 的数学形式不一定是硬件上的高效实现。中间的 attention matrix 可能需要在高带宽显存和片上 SRAM 之间反复读写，实际瓶颈因此可能来自 IO 而不是乘加次数。

FlashAttention 使用分块计算和 online softmax，在不显式保存完整 attention matrix 的情况下得到 exact attention。对分块中的最大值 m 和归一化因子 l，可以递推合并不同块的统计量，从而保持数值稳定。

它没有把 attention 的理论复杂度从平方级变成线性，而是降低了内存读写和中间结果存储。收益依赖 GPU 架构、tile 大小、序列长度、head 维度、mask 类型和 kernel 实现。

FlashAttention 的论文贡献是算法与硬件内存层级的协同设计。它影响了训练和推理框架，但不能替代长上下文稀疏注意力、状态空间模型或分页缓存；这些方法解决的是不同层次的问题。

## 14.13 FlashAttention-2：让并行划分更贴近 GPU

FlashAttention-2 继续优化 work partitioning，减少非矩阵乘法操作和线程块之间的不平衡，让 GPU 的并行资源更充分地利用。它说明同一个数学算子仍可能因为线程组织、共享内存、warp 分工和序列长度产生明显性能差异。

阅读 FlashAttention-2 时要把“kernel 更快”和“系统端到端更快”分开。kernel benchmark 常使用固定 shape 和预热后的稳定输入，生产请求则包含动态 batch、不同长度、KV cache、mask、并发和调度开销。真实系统还需要报告 TTFT、TPOT、p99、显存峰值和吞吐。

## 14.14 GQA：在质量与 KV Cache 之间做结构折中

Grouped-Query Attention 让多个 query head 共享较少的 key/value head。若 query head 数为 Hq，KV head 数为 Hkv，且 Hkv 小于 Hq，则 decode 时缓存的 K/V 数量近似按 Hkv 缩减：

~~~math
\operatorname{KVBytes}
\propto
L\cdot H_{\text{kv}}\cdot d_{\text{head}}\cdot b
~~~

L 是上下文长度，dhead 是每个 head 的维度，b 是每个元素的字节数。MQA 把 Hkv 减到 1，GQA 则在共享程度和表达能力之间取中间位置。

GQA 的论文价值是把 attention 质量和 serving 内存放到同一张设计表里。它不只是训练时的 head 配置，也改变了 KV cache 容量、批处理上限和 decode 带宽。比较 MHA、MQA 和 GQA 时必须固定模型质量、序列长度和硬件，否则无法判断收益来自结构还是环境。

## 14.15 InstructGPT：后训练把 base model 变成助手

### 三阶段 pipeline

InstructGPT 论文把预训练语言模型的行为调整拆成 SFT、Reward Model 和 RLHF。首先用人工示范训练监督模型；然后让标注员比较候选答案，训练奖励模型；最后用 PPO 等方法优化 policy，并用 KL 约束减少偏离参考模型。

这个 pipeline 解决了一个重要错位：预训练目标是预测文本，用户目标却是遵循指令、保持有用、诚实和安全。论文显示，一个经过人类偏好训练的较小模型，可能比更大的纯预训练模型更符合用户偏好。

### 证据和代价

偏好数据定义了什么叫“好回答”，所以标注指南、标注员分布、任务范围和奖励模型错误都会影响结果。RLHF 还引入了 rollout、奖励模型、策略优化和 KL 调参的系统复杂度。

InstructGPT 的后续影响不是“RLHF 永远优于其他训练”，而是建立了现代 assistant post-training 的问题分解。DPO、RLAIF、RLVR 和 process supervision 都是在改变其中的反馈来源、优化方式或监督粒度。

## 14.16 Constitutional AI：把安全原则变成反馈来源

Constitutional AI 用一组原则指导模型对回答进行 critique 和 revision，再使用 AI feedback 形成偏好或训练信号。它试图减少高风险偏好数据的人工标注压力，并让安全原则更显式、更可审查。

与纯人工偏好相比，原则化反馈的优势是规则可以被记录、修改和分析；代价是原则本身需要选择，评价模型仍可能继承偏差，模型生成的批评也可能只是在模仿安全语言。

因此，Constitutional AI 的论文证据支持一种训练路线，不支持“写下原则后系统就安全”。必须另外检查 under-refusal、over-refusal、越狱、多语言、工具调用和外部内容注入。安全原则要落到可观察事件和回归样本中。

## 14.17 DPO：把偏好优化改写为直接目标

DPO 的核心是利用偏好数据和 reference policy，直接优化 chosen 与 rejected 响应的相对对数概率。常见单样本损失为：

~~~math
\mathcal{L}_{\text{DPO}}(\theta)
=
-\log\sigma
\left(
\beta
\left[
\log\frac{\pi_{\theta}(y_w\mid x)}
{\pi_{\text{ref}}(y_w\mid x)}
-
\log\frac{\pi_{\theta}(y_l\mid x)}
{\pi_{\text{ref}}(y_l\mid x)}
\right]
\right)
~~~

x 是输入，yw 是被偏好的响应，yl 是被拒绝的响应，πθ 是待训练策略，πref 是参考策略，β 控制偏好间隔的尺度。

DPO 把原本需要显式 reward model 和在线策略优化的部分转化为更接近监督学习的目标，工程上更容易复现。但它仍然依赖偏好数据的质量，序列 log-prob 如何聚合、assistant mask 如何定义、reference 是否冻结和数据是否包含长度偏差都会影响训练。

DPO 的意义不是证明 RL 不需要，而是把“离线偏好学习”的一个重要子问题变得更简单。长期工具任务、稀疏奖励和真实环境探索仍可能需要在线反馈、验证器或强化学习。

## 14.18 DeepSeekMath 与 GRPO：用可验证奖励训练推理

DeepSeekMath 把数学数据、规则验证和 Group Relative Policy Optimization 联系起来。对于同一个问题采样一组输出，用结果是否正确形成组内相对优势，可以减少对单独 value model 的依赖。

若一组样本的奖励为 r1 到 rG，组均值为 rbar，组标准差为 s，则一种标准化相对优势是：

~~~math
A_i=\begin{cases}
  \frac{r_i-\bar r}{s}, & s>0\,
  0, & s=0\text{ 且组内奖励完全相同}
\end{cases}
~~~

G 是组大小，s 是组内奖励的标准差。当组内奖励完全相同时，所有样本的相对优势定义为 0；不能在零标准差上加一个小常数后假装仍然有区分信号。真实算法还包含 KL、clip、token mask 和长度处理，不能把这条公式当成完整实现。

GRPO 的研究价值在于把“结果可验证”的数学和代码任务变成强化学习信号，减少主观 reward model 的依赖。代价是训练依赖可靠 verifier，奖励容易被投机，难以直接迁移到没有明确答案的开放任务。

## 14.19 DeepSeek-R1：推理能力、RLVR 与蒸馏的组合

DeepSeek-R1 公开材料把大规模强化学习、可验证任务、推理行为和蒸馏放在同一条路线中。它引起广泛关注的原因不是某一个算法名，而是展示了 reasoning model 可以通过更长的测试时计算和训练时反馈获得更强的数学、代码与科学推理能力。

阅读这类报告时需要分开三个层次：

1. base model 和 post-training recipe 的能力差异；
2. 采样预算、思考长度、verifier 和答案聚合带来的测试时收益；
3. 蒸馏模型是否保留了原始 reasoning policy，以及在不同任务上的迁移范围。

“模型会生成更长推理”不等于“每一步都真实可靠”。必须检查最终答案、过程错误、停止行为、成本、拒答和工具轨迹。RLVR 的强项是可验证结果，弱点是 verifier 覆盖有限时可能出现 reward hacking。

DAPO、Dr.GRPO 等后续工作围绕 clipping、长度偏差、采样效率和训练稳定性继续调整。这条谱系说明 reasoning post-training 仍在快速演进，不宜把某个版本的 recipe 当成固定标准。

## 14.20 LoRA：把微调更新限制在低秩子空间

LoRA 冻结基础模型权重 W，只训练一个低秩更新：

~~~math
W'=W+\frac{\alpha}{r}BA
~~~

A 的形状为 r × din，B 的形状为 dout × r，r 是低秩维度，α 是缩放系数。训练参数量从 dout × din 降为 r × (din + dout)。

LoRA 解决的是每个任务都复制一份大模型参数的问题。它降低训练显存、保存体积和多任务切换成本，也使个人和小团队能够适配大模型。

低秩假设不是免费午餐。任务差异很大、插入层不合适、rank 太小或 adapter 合并方式错误时，能力可能受限。评估不能只看训练 loss，还要看基座能力保留、不同任务干扰、adapter 组合和实际部署延迟。

## 14.21 QLoRA：量化基座与低秩适配的组合

QLoRA 把 4-bit 量化基座、LoRA adapter、NF4、double quantization 和 paged optimizer 组合起来，降低微调大模型的显存门槛。它解决的是“即使只训练少量参数，加载基础模型仍然很贵”的问题。

量化影响的不只是存储，还可能影响计算精度、梯度路径、kernel 支持和训练稳定性。不同硬件、量化格式、累加精度和框架实现会产生不同结果。

QLoRA 的证据应同时报告基础模型、量化配置、LoRA rank、目标模块、训练 token、batch、梯度累积、评估基线和合并后的推理精度。只写“用 QLoRA 微调成功”无法说明显存、质量和复现条件。

## 14.22 ZeRO：用通信换数据并行显存

普通数据并行把参数、梯度和 optimizer state 的完整副本放在每个 rank 上。ZeRO 分阶段切分这些状态：

- ZeRO-1 切 optimizer state；
- ZeRO-2 进一步切 gradient；
- ZeRO-3 连 parameter 也切分，并在需要时通信聚合。

如果参数量为 P、优化器和梯度等状态总占用为 S，复制式数据并行的每卡状态约为 S；理想均匀切分后，持久状态可接近 S/N，其中 N 是 data-parallel rank 数，但通信和临时 gather 会增加。

ZeRO 的核心 trade-off 是显存、通信、带宽、容错和实现复杂度。它不等于张量并行或流水并行，实际系统常把多种并行方式组合起来。评估时要记录峰值显存、step time、通信量、checkpoint 语义和故障恢复。

## 14.23 GShard 与 Switch Transformer：MoE 的稀疏容量

GShard 展示了条件计算和自动分片如何把稀疏专家模型扩展到大规模训练；Switch Transformer 用 top-1 routing 简化每个 token 的专家选择。路由器可以写成：

~~~math
p_t=\operatorname{softmax}(W_rh_t),
\qquad
e_t=\arg\max_j p_{t,j}
~~~

ht 是 token 表示，Wr 是 router 参数，pt 是专家概率，et 是被选择的专家。真实系统还要处理 capacity、overflow、负载均衡和跨设备 all-to-all。

MoE 把总参数量和每 token 激活计算分离开来，但通信和负载不平衡可能成为瓶颈。某个专家过热时，token 可能被丢弃、溢出或转发到远端设备；因此不能只用 active parameters 估算成本。

## 14.24 Mixtral：开放 MoE 的工程化样本

Mixtral 是开放权重 MoE 的代表案例。它让每个 token 选择多个专家，从而在总参数量较大的同时控制单 token 激活量。与 Switch 的 top-1 路由相比，top-k 路由可能带来更强表达能力，也会增加专家计算和通信。

这篇模型报告更适合用来研究 MoE 的公开实现、推理加载和部署取舍，而不是抽象成“MoE 一定更省”。总参数、激活参数、专家数、每卡放置、通信拓扑、batch 和 context length 共同决定真实成本。

## 14.25 RAG：把知识从参数外置到可检索证据

RAG 将检索器与生成器连接起来。记检索到的文档为 z，一个简化的生成分布可以写成：

~~~math
p(y\mid x)
=
\sum_{z\in\operatorname{TopK}(x)}
p_{\eta}(z\mid x)
p_{\theta}(y\mid x,z)
~~~

x 是问题，pη 是检索器分布，pθ 是条件生成分布。生产系统通常只保留有限候选，并经过重排、过滤和上下文预算截断，因此召回率、证据支持率和最终答案正确率必须分开测量。

RAG 解决参数知识过时、私有知识无法训练进模型和答案缺少证据的问题。它也引入了新的失败：切块不完整、权限过滤错误、检索到恶意文档、证据之间冲突、上下文超长和模型引用了没有支持的句子。

RAG 论文的贡献是建立检索增强生成的统一范式，而不是保证任何检索器都能提升回答。真实系统需要记录知识库版本、文档权限、嵌入模型、召回 top-k、重排模型、上下文顺序和答案引用。

## 14.26 REALM 与 RETRO：检索成为模型记忆的一部分

REALM 把检索模块引入预训练过程，让模型学习在知识密集任务中检索外部文本。RETRO 则展示了用大规模近邻 chunk 作为外部记忆，在较少参数下增强语言建模。

两者共同说明，模型能力可以在参数记忆和外部记忆之间分配。外部记忆更容易更新和审计，但会产生存储、索引、权限和检索延迟；参数记忆读取快，却难以精确更新和删除。

这条路线后来在企业 RAG、长上下文和 Agent memory 中继续演化。比较参数扩展和检索扩展时，不能只比较模型分数，还要比较更新时延、数据治理、引用质量、隐私边界和单位请求成本。

## 14.27 ReAct：把推理和行动放进循环

ReAct 通过 thought、action 和 observation 的交替轨迹，让模型在回答过程中调用搜索、计算或环境工具。它解决了单次生成无法获取新信息、无法执行动作和无法根据反馈修正计划的问题。

ReAct 的关键不是固定的文字格式，而是闭环状态：

~~~math
s_{t+1}
=
F(s_t,a_t,o_{t+1})
~~~

st 是当前任务状态，at 是动作，ot+1 是工具观察结果，F 是状态更新过程。实际 Agent 需要把这个状态持久化，处理工具失败、重试、未知结果、权限和成本。

ReAct 也暴露了循环风险：模型可能重复调用、把外部文本当成指令、在错误观察上继续计划，或在最终答案中隐瞒工具失败。论文展示的是一种轨迹组织方式，生产安全还要依靠独立授权和状态机。

## 14.28 Toolformer：让模型学习何时调用工具

Toolformer 研究通过自动构造工具调用样本，让语言模型学习调用 calculator、search 等工具的时机、参数和结果使用方式。它把 tool use 从纯手写规则扩展为可以被训练的行为。

这项工作的关键假设是：工具调用的价值可以通过预测损失或任务收益识别。但开放系统中的工具可能有副作用、权限范围和费用，不能只用“调用后语言更像目标文本”作为安全标准。

后续 function calling、structured output、MCP 和 programmatic tool calling 把接口契约、参数 schema、权限和运行时状态放到更明确的系统层。Toolformer 是学习工具使用的研究起点，不是完整的 Agent runtime。

## 14.29 PagedAttention：把 KV Cache 当成分页内存管理

PagedAttention 借鉴虚拟内存思想，把不同请求的 KV cache 切成固定大小的 block，用 block table 映射逻辑序列位置和物理存储。这样可以减少长短请求混合时的内部碎片，并支持 prefix sharing 等优化。

KV cache 的近似内存量为：

~~~math
\operatorname{Bytes}
=
2\cdot L\cdot H_{\text{kv}}\cdot d_{\text{head}}\cdot b
~~~

L 是已缓存 token 数，Hkv 是 KV head 数，dhead 是 head 维度，b 是每个元素字节数，2 表示 key 和 value。分页管理改变的是分配和复用方式，不会让单个 token 的信息量消失。

论文的系统价值在于把推理服务中的内存碎片和请求调度问题显式化。实际收益还取决于 block size、引用计数、prefix 命中、batch 动态变化和 kernel。不能把 PagedAttention 的论文吞吐直接当成目标硬件上的服务 SLO。

## 14.30 Chain-of-Thought：把中间状态变成测试时计算

Chain-of-Thought prompting 通过示例引导模型生成中间推理步骤，再输出最终答案。对同一任务和解码配置，可用：

~~~math
\Delta A
=
A_{\text{CoT}}-A_{\text{direct}}
~~~

表示 CoT 与直接回答的准确率差异。这个差异依赖模型规模、示例选择、任务难度、答案抽取和解码预算。

CoT 的机制直觉是让模型有更多 token 表示中间状态，从而获得额外测试时计算。但生成的解释不一定是导致答案的真实内部因果过程；它可能是事后合理化，也可能包含隐藏错误。

因此，CoT 评估应把最终答案、过程正确性、token 成本、延迟、隐私和是否泄露不应展示的内部内容分开。简单任务、低延迟任务和高隐私任务不一定适合输出长推理。

## 14.31 Self-Consistency：用多条路径降低偶然错误

Self-Consistency 不固定一条 greedy 推理链，而是采样多条推理路径，再对标准化答案投票。对第 i 个问题的 K 条路径：

~~~math
\hat a_i
=
\arg\max_a
\sum_{j=1}^{K}
\mathbf{1}[a_{ij}=a]
~~~

aij 是第 j 条路径抽取出的答案。效果依赖采样温度、路径多样性、K、答案标准化和投票等价关系。若所有路径共享同一个错误前提，增加样本数只会让错误更自信。

这篇论文把推理质量与测试时计算联系起来。生产使用时还要比较单次回答的延迟、并发、成本、可解释性和失败合并策略；Self-Consistency 不是免费提高准确率。

## 14.32 Training Verifiers 与 GSM8K：结果监督的力量和盲区

Training Verifiers to Solve Math Word Problems 研究用结果验证器判断候选解答，GSM8K 则提供了大量小学数学应用题，成为早期多步推理评估的重要基准。

验证器把“生成答案”和“判断答案”分开，允许系统采样多个候选，再选择验证器认为正确的候选。它也带来新的代理目标问题：若验证器只检查最终数字，模型可能生成错误但恰好得到目标数字的过程；若验证器过度依赖格式，模型会优化格式而不是数学。

GSM8K 的价值是任务清晰、答案可验证、容易比较 CoT 和 self-consistency。它的边界同样清晰：题型相对集中，公开数据存在污染可能，不能代表高级数学、代码、科学研究和真实业务推理。

## 14.33 Tree of Thoughts：从单链生成到状态搜索

Tree of Thoughts 把推理过程看成多个中间状态的搜索，而不是一条固定 token 链。对状态 s，可以由生成器提出候选扩展，再用评估器判断保留哪些节点：

~~~math
\mathcal{S}_{t+1}
=
\operatorname{Select}
\left(
\operatorname{Expand}(\mathcal{S}_t)
\right)
~~~

它可以与 beam search、best-first search 或 MCTS 组合。方法的收益来自更多候选和搜索预算，代价是模型调用次数、状态去重、评估器误差和终止条件。

Tree of Thoughts 的重要性是把 reasoning scaffold 显式化。随着模型内置 planning、长上下文和工具能力增强，外部树搜索有些场景可能被模型吸收，有些高价值任务仍会保留，因为显式搜索更容易施加预算和验证。

## 14.34 CLIP：用自然语言监督视觉表示

CLIP 用大规模图文对进行对比学习，把图像和文本映射到共享语义空间。设图像嵌入和文本嵌入归一化后的相似度矩阵为 S，温度为 τ，则对称对比损失可写成：

~~~math
\mathcal{L}_{\text{CLIP}}
=
\frac{1}{2}
\left(
\operatorname{CE}(S/\tau,I)
+
\operatorname{CE}(S^{\mathsf T}/\tau,I)
\right)
~~~

I 表示 batch 内正确配对的对角标签。图文数据规模和开放词汇监督让 CLIP 具备 zero-shot 分类与检索能力。

CLIP 的限制来自数据：网页文本可能含噪、偏见、版权和重复，图文对应关系也不等于精确区域标注。zero-shot 分数依赖 prompt 模板、类别名称、图像分布和语言。

CLIP 的长期影响是把自然语言变成视觉监督入口，后续 VLM、图文检索、扩散模型条件和多模态 Agent 都继承了这种对齐思想。

## 14.35 ViT：把图像切成 token

Vision Transformer 把图像划分为固定大小 patch，将每个 patch 投影为 token，再用 Transformer 编码。若图像尺寸为 H × W、patch 边长为 P，则 patch 数近似为：

~~~math
N_{\text{patch}}
=
\frac{H}{P}\cdot\frac{W}{P}
~~~

P 越小，视觉序列越长，空间细节越多，但 attention 成本按 token 数平方增长。ViT 证明在足够数据和预训练条件下，Transformer 可以成为视觉骨干。

这篇论文也揭示了数据规模的重要性：在小数据上，卷积的局部归纳偏置可能更有优势；在大规模预训练下，Transformer 的可扩展性更突出。现代视觉模型常把 patch、窗口 attention、层级特征和多模态连接器组合使用。

## 14.36 Latent Diffusion：把扩散过程移到压缩空间

像素空间扩散需要反复处理高分辨率图像，Latent Diffusion 先用 autoencoder 把图像压缩为 latent，再在 latent 空间加噪和去噪。噪声预测目标可以写为：

~~~math
\mathcal{L}
=
\mathbb{E}_{x,\epsilon,t}
\left[
\left\|
\epsilon-\epsilon_{\theta}(x_t,t,c)
\right\|_2^2
\right]
~~~

xt 是时间步 t 的带噪 latent，ε 是加入的噪声，c 是文本或其他条件。latent 空间降低计算量，但 VAE 压缩损失、采样步数、条件控制和安全过滤会影响最终图像。

Stable Diffusion 把这条路线带入开放生态。阅读它时要区分论文中的 latent diffusion 方法、具体 checkpoint、训练数据许可、采样器和社区插件；“Stable Diffusion”不是一个固定不变的单一模型。

## 14.37 Whisper：弱监督语音任务的统一接口

Whisper 用大规模弱监督音频文本数据训练端到端模型，把多语言转写、语音翻译和语言识别放在统一接口中。它展示了数据规模、任务多样性和噪声覆盖对 ASR 泛化的重要作用。

弱监督的优势是数据量大、语言和场景覆盖广，代价是转写质量、时间戳、说话人、版权和领域分布不完全可控。生产 ASR 还要处理 VAD、说话人分离、噪声、术语、实时延迟和错误修复。

Whisper 的论文结果不能直接等价于某个具体音频流的 WER。评估应按语言、口音、噪声、说话速度、专有名词和长音频切片，并把端到端延迟和人工纠错成本纳入系统账本。

## 14.38 Red Teaming Language Models：把安全失败变成实验对象

红队研究关注模型在恶意提示、有害内容、越狱、偏见和危险能力场景下的失败。与标准能力 benchmark 不同，红队样本主动寻找边界，攻击者会改变措辞、角色、语言、编码和多轮上下文。

一个攻击成功率可以写成：

~~~math
\operatorname{ASR}
=
\frac{\text{完成预先定义攻击目标的样本数}}
{\text{有效攻击样本总数}}
~~~

成功目标必须具体：输出危险文本、泄露秘密、生成越权工具参数和实际完成外部动作是不同事件。报告还要记录攻击预算、模型版本、系统提示、工具权限、人工判定和修复后的回归结果。

红队论文提供的是发现风险的方法，不是“测过一次就安全”的证明。最有价值的产物是版本化失败样本、风险严重度、根因和修复后反事实，而不是一组孤立的炫技对话。

## 14.39 ROME 与 MEMIT：修改参数化知识的研究路线

ROME 把某些事实关联近似为 Transformer MLP 中的键值映射，并通过局部权重更新改变事实。抽象表示为：

~~~math
W'=W+\Delta W
~~~

编辑目标包括新事实生效、同一事实的别名泛化和无关知识保持。MEMIT 将思路扩展到多事实和多层编辑，但编辑之间可能冲突，更新也可能累积副作用。

任何知识编辑都至少需要编辑集、泛化集和保留集。编辑集回答“目标事实是否改变”，泛化集回答“不同模板和关系是否一致”，保留集回答“无关事实、语言能力和安全行为是否保持”。

ROME 和 MEMIT 说明模型内部知识具有一定可塑性，但不等于它们已经成为可靠的知识库更新方案。频繁变化、需要审计和需要精确删除的事实，通常仍适合放在外部知识库中。

## 14.40 Transformer Circuits 与机制解释性

机制解释性试图从 attention head、MLP、残差流和特征回路层面解释模型如何产生行为。与只观察 attention heatmap 不同，它更关心干预是否改变结果，以及改变是否具有跨样本稳定性。

一个 activation patching 的差分可以写为：

~~~math
\Delta_{\text{patch}}
=
f(h_{\text{patched}})
-
f(h_{\text{corrupt}})
~~~

hpatched 是替换过中间激活的模型状态，hcorrupt 是对照状态，f 是任务评分函数。单次成功干预只说明该激活与任务相关；还需要随机方向、不同层、不同 token 位置、负向任务和跨样本测试。

Sparse Autoencoder 等方法试图把高维激活分解成较稀疏的特征。解释性工具可以帮助发现行为回路和诊断问题，但目前不能把一个人类可读标签直接当成完整因果解释，也不能替代输出评估、权限控制和事故响应。

## 14.41 Agent 评估论文：从静态答案到环境闭环

SWE-bench、WebArena 和 OSWorld 等工作把模型放进代码仓库、浏览器或桌面环境，观察它能否完成真实任务。评价对象从单个答案变成一条轨迹：

~~~math
\operatorname{Success}
=
\mathbf{1}
[
\text{任务状态满足验收条件}
]
~~~

中间动作很多不等于成功，文本解释漂亮也不等于环境状态正确。Agent 评估需要记录任务初始状态、工具版本、权限、网络、时间和预算，并区分模型失败、环境失败、工具失败和验收器失败。

这些 benchmark 推动了代码 Agent、浏览器 Agent 和 computer-use 系统的发展，也暴露了污染、任务泄漏、环境不稳定和自动验收器偏差。论文分数只能说明特定环境下的任务完成率，不能直接代表线上业务成功率。

## 14.42 论文谱系中的继承、修正与替代

技术并不是沿着“新论文完全替代旧论文”的直线发展。更常见的情况是：

- Transformer 保留了 attention，但改变位置机制、归一化、专家路由和缓存；
- Chinchilla 修正了早期 scaling 直觉，但没有否定规模研究；
- DPO 简化了离线偏好优化，但没有消除在线反馈和 verifier 的需求；
- RAG 把知识外置，却没有消除参数记忆和上下文推理；
- Toolformer 研究学习工具使用，后续协议和运行时把权限、schema、审计独立出来；
- 外部 CoT、树搜索和 Agent scaffold 的一部分，可能被更强模型和更长上下文吸收，另一部分仍因可验证性和权限控制而保留。

因此，判断一项新技术是否值得进入主干，不应只看发布日期或榜单热度，而应看它解决的约束是否仍然存在、抽象是否稳定、证据是否可复现，以及它在系统中会保留、下沉还是被替代。

## 14.43 一条可复核的论文阅读记录

读完一篇论文后，最有用的记录不是几句宣传式结论，而是以下信息：

~~~text
研究问题：旧方法在哪个约束下失败
方法改变：架构、数据、目标、系统或评估中的具体变化
对照条件：基线、模型规模、训练 token、硬件和随机性
主要结果：指标、置信区间、成本和失败样本
消融证据：去掉哪个组件后结果如何
适用边界：任务、语言、长度、权限和攻击模型
后续演化：哪些工作继承、修正或替代了它
复现状态：代码、数据、环境和当前重跑结果
~~~

这份记录把“读过论文”与“能解释论文证据”区分开来。若某一项没有资料支持，就应明确标成未知，而不是用常识填补。

## 14.44 按问题组织的阅读路径

### 想理解模型为什么能生成

Attention Is All You Need、GPT、Scaling Laws、Chinchilla、RoPE、GQA 和 Mamba 组成架构与规模路径。它们分别回答表示交互、训练目标、规模收益、数据配比、位置信息、缓存成本和递归状态问题。

### 想理解模型为什么会听指令

InstructGPT、Constitutional AI、DPO、DeepSeekMath 和 DeepSeek-R1 组成后训练与 reasoning 路径。它们把示范、偏好、原则、可验证奖励和测试时计算连接起来。

### 想理解大模型为什么能部署

LoRA、QLoRA、ZeRO、FlashAttention、PagedAttention、Switch/Mixtral 组成训练和 serving 路径。它们分别处理适配成本、量化显存、分布式状态、内存 IO、KV cache 和稀疏专家。

### 想理解 Agent 为什么不只是聊天

RAG、ReAct、Toolformer、SWE-bench 和 WebArena 组成环境闭环路径。它们把外部知识、行动、工具学习、代码修改和环境验收纳入模型系统。

### 想理解多模态和安全

CLIP、ViT、Latent Diffusion、Whisper、Red Teaming、ROME/MEMIT 和机制解释性组成感知、生成、语音、风险与内部诊断路径。每条路径都需要结合数据治理、权限和目标系统实测。

## 本章小结

重要论文组成的不是一张标题清单，而是一条约束变化的历史：Transformer 重新安排了序列交互；Scaling Laws 和 Chinchilla 重新安排了训练预算；InstructGPT、DPO、可验证奖励和 reasoning post-training 重新安排了反馈；LoRA、ZeRO、FlashAttention、PagedAttention 和 MoE 重新安排了参数、内存、通信与计算；RAG、ReAct、Toolformer 和 Agent benchmark 把模型放进外部环境；CLIP、ViT、扩散和 Whisper 把语言模型方法扩展到多模态；红队、编辑、遗忘和机制解释性则把可靠性与安全变成研究对象。

读论文时，最重要的不是记住哪篇论文“最好”，而是说清它解决了哪个旧问题、依赖什么条件、牺牲了什么、被后续工作怎样修正，以及这些条件是否仍然存在于目标系统。只有这样，论文才能从来源变成可验证的工程知识。
