# 第 14 章 重要论文索引

论文索引的价值不在于把标题排列得更长，而在于把技术变化还原成问题、假设、实验和影响。一个方法只有在明确回答了“它改变了什么、靠什么改变、在哪些条件下成立、付出了什么代价”之后，才真正进入知识，而不只是进入记忆。

本章把论文放回技术谱系中阅读。架构论文通常改变表示和计算路径，训练论文通常改变数据或优化目标，系统论文通常改变内存、通信和调度，应用论文则把这些能力放入检索、工具、多模态或安全场景。不同论文的模型规模、数据质量、硬件、评测集和实现版本经常不同，所以论文中的单个分数不能直接组成一张跨论文排行榜。

论文提供的是有条件的证据。原论文可以支持“在该实验设置下观察到某种现象”，官方实现可以支持“某个接口或算法按照该方式工作”，复现实验可以支持“在当前环境中重新得到某种结果”，但它们都不自动支持“所有模型、所有数据和所有生产系统都具有同样结论”。本章在每个主题中都把这些边界写出来。

## 14.1 一篇论文究竟贡献了什么

### 从标题退回研究问题

论文标题往往只告诉读者方法名称，真正决定论文价值的是它所针对的瓶颈。例如，Transformer 针对循环结构的并行性和长距离依赖问题；Chinchilla 针对固定算力下参数和数据配比问题；FlashAttention 针对 attention 的内存访问问题；DPO 针对 RLHF 流程的优化复杂度问题。若只记住“它提出了某某方法”，就无法解释为什么这项工作会出现。

一个适合阅读的最小问题描述包含五部分：

1. 任务输入和输出是什么；
2. 旧方法在哪个环节失败或成本过高；
3. 新方法改变了模型、数据、优化或系统的哪一部分；
4. 实验用什么基线和指标区分“真的改善”和“换了条件”；
5. 结果在哪些数据、规模、硬件和攻击模型之外不应直接外推。

初学者可以先用这五个问题把摘要还原成因果链。有经验的读者还要检查控制变量：如果新方法用了更多数据、更长训练、更大的 batch 或更强的后处理，最终提升究竟来自方法本身，还是来自额外预算。

### 分数、成本和外推

设方法在测试集上的指标为 A，基线指标为 A0，最直接的绝对增益是：

~~~math
\Delta A=A-A_0
~~~

如果方法改变了延迟、显存或训练计算，还要记录成本差异：

~~~math
\Delta C=C-C_0
~~~

只有在任务、指标和成本口径一致时，才可以讨论单位成本收益。一个简单的比较量是：

~~~math
\mathrm{GainPerCost}
=\frac{\Delta A}{\Delta C},\qquad \Delta C>0
~~~

这个量只在成本增量 `ΔC` 严格为正时有定义。如果成本没有增加，应单独报告成本节省或成本不变，不能把分母替换成一个小常数来制造比较数字。它也不是通用排名指标，因为不同成本可能不能互换；它只是提醒读者，准确率提升和资源代价应同时被记录。

论文结论的外推还受到分布差异影响。设训练或论文测试分布为 Dpaper，目标系统分布为 Dtarget，则：

~~~math
\mathbb{E}_{x\sim D_{\text{paper}}}[u(x)]
\neq
\mathbb{E}_{x\sim D_{\text{target}}}[u(x)]
~~~

即使论文中方法的平均效用很高，目标用户、语言、长度、工具权限和错误代价变化后，结论也可能改变。

### 一个小型证据账本

下面的代码只演示如何把绝对增益和成本一起记录。它不模拟任何真实论文结果，数值是教学构造：

~~~python
from dataclasses import dataclass
import math


@dataclass(frozen=True)
class Experiment:
    name: str
    baseline: float
    method: float
    cost: float

    def __post_init__(self):
        if not isinstance(self.name, str) or not self.name.strip():
            raise ValueError("experiment name must be non-empty")
        for value in (self.baseline, self.method, self.cost):
            if not isinstance(value, (int, float)) or isinstance(value, bool):
                raise TypeError("experiment values must be numeric")
            if not math.isfinite(value):
                raise ValueError("experiment values must be finite")
        if self.cost <= 0:
            raise ValueError("experiment cost must be positive")

    @property
    def gain(self):
        return self.method - self.baseline

    @property
    def gain_per_cost(self):
        return self.gain / self.cost


experiments = [
    Experiment("attention kernel", 0.82, 0.86, 1.20),
    Experiment("retrieval rerank", 0.82, 0.85, 0.60),
]

for item in sorted(experiments, key=lambda value: value.gain_per_cost, reverse=True):
    print(item.name, round(item.gain, 3), round(item.gain_per_cost, 3))
try:
    Experiment("zero-cost", 0.8, 0.9, 0)
except ValueError:
    print("non-positive experiment cost rejected")
else:
    raise AssertionError("non-positive experiment cost was accepted")
~~~

输出可以帮助读者发现一个常见误区：绝对分数最高的方法，不一定是单位成本收益最高的方法。真正的论文复现还需要把数据版本、随机种子、硬件、软件版本和统计区间加入账本。

## 14.2 Attention Is All You Need：从循环序列到全局依赖

### 旧问题

在 Transformer 之前，序列建模的主力是 RNN、LSTM 和卷积网络。循环结构沿时间步传递状态，理论上能够处理长序列，但训练过程难以完全并行；距离很远的两个 token 之间需要经过多次状态传递，优化和信息保留都比较困难。

Transformer 论文把序列中的每个位置映射成 query、key 和 value，并允许一个位置直接读取其他位置的信息。缩放点积 attention 写成：

~~~math
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^{\mathsf T}}{\sqrt{d_k}}
\right)V
~~~

Q 是查询矩阵，K 是被查询的键，V 是要聚合的值，dk 是每个 key 向量的维度。除以根号 dk 是为了控制点积的尺度，避免维度变大后 softmax 过早饱和。

### 方法改变在哪里

论文同时提出 multi-head attention、位置编码、encoder-decoder 结构、残差连接、LayerNorm 和前馈网络。多头结构让模型可以在不同表示子空间中学习不同关系；位置编码为没有循环顺序的 attention 注入位置信息；残差和归一化让深层堆叠更容易训练。原论文在 WMT14 英德翻译报告 28.4 BLEU，在英法翻译报告单模型 41.8 BLEU；这些数字只说明论文所用数据、模型和训练配置下的结果，不能用来直接比较今天的机器翻译系统。[原论文](https://arxiv.org/abs/1706.03762)

Self-attention 的核心矩阵 QKT 具有序列长度平方级的计算和中间存储。对长度 T、head 维度 d 的单头 attention，教学级复杂度可写为 O(T²d)。这解释了为什么 Transformer 获得了全局依赖能力，却也为长上下文带来成本。

### 证据和局限

原论文在机器翻译上比较了循环、卷积和 attention 方案，证明并行训练和翻译质量可以同时改善。但现代 decoder-only LLM 并没有原样保留 encoder-decoder、正弦位置编码和所有训练设置，而是沿着这套模块继续改变。

Transformer 的贡献不是“attention 永远优于其他结构”，而是证明了全局内容寻址、并行训练和深度残差堆叠可以组成一个高效的序列建模框架。后来的 RoPE、GQA、FlashAttention、Mamba 和 MoE 都是在不同约束下重新分配表达能力、内存和计算。比较这些后续工作时要先问它改的是模型表示、训练 kernel、缓存结构还是专家路由；它们通常可以叠加，不能只凭一个“速度更快”的数字互相排名。

## 14.3 BERT：双向理解与预训练迁移

### 掩码语言模型

BERT 代表 encoder-only 路线。训练时随机遮盖输入中的一部分 token，让模型利用左右两侧上下文恢复它们。与单向 next-token prediction 相比，masked language modeling 更直接地构造了整段文本的双向表示。原论文不只使用 MLM，还加入 next sentence prediction（NSP）：给模型两个文本片段，判断第二段是否为原文中紧接第一段的后续。预训练目标可以概括为：

~~~math
\mathcal{L}_{\text{BERT}}
=\mathcal{L}_{\text{MLM}}+\mathcal{L}_{\text{NSP}}
~~~

MLM 主要训练 token 级别的双向上下文；NSP 则对 `[CLS]` 表示做句对二分类，尝试让编码器学习片段关系。BERT 原论文报告了多项 GLUE、SQuAD 和 SWAG 结果，但这类下游成绩来自特定任务微调，不等价于开放式生成能力。[BERT 原论文](https://arxiv.org/abs/1810.04805)

它解决的是理解任务的统一预训练问题：分类、问答、序列标注和句子关系判断原本需要各自设计模型，BERT 先在大规模无标注文本上学习通用表示，再用少量任务数据微调。

### 影响与边界

BERT 的重要性不只是一个模型分数，而是“预训练加下游适配”成为通用范式。它也暴露了目标和使用方式之间的约束：训练时遮盖 token，推理时却通常输入完整句子；模型可以理解双向上下文，但不天然适合自回归长文本生成。

因此，BERT 与 GPT 不能简单比较谁更强。BERT 的 inductive bias 更适合理解和编码，GPT 的 causal mask 更贴近开放式生成。后续 encoder-decoder、decoder-only 和双向上下文方法的选择，都应回到任务输出形式和推理路径。

### BERT 到 RoBERTa：训练配方也是变量

RoBERTa 不是一种与 BERT 完全不同的网络结构，而是对 BERT 预训练配方的系统复核。论文考察动态 masking、移除 NSP、文本片段构造、大 batch、更长训练、更多数据和较长序列；作者认为原始 BERT 在其复现实验里训练不足。重要的是，这些变化不全是同一项消融：最终 RoBERTa 配方联合了多项调整，所以不能把整体分数提升简单写成“去掉 NSP 带来提升”。它的价值在于提醒读者，比较预训练目标时必须控制 token 数、数据、batch、训练步数和输入格式。[RoBERTa 原论文](https://arxiv.org/abs/1907.11692)

| 方案 | 训练信号与主要变化 | 论文支持的结论 | 仍需控制的变量 |
| --- | --- | --- | --- |
| BERT | MLM + NSP；原始配方使用静态 mask | 建立了双向 encoder 的预训练与下游微调范式 | 不能据此说明 NSP 对每类任务都必要；分数绑定论文数据和微调流程 |
| RoBERTa | MLM；动态 mask，并改变训练时长、batch、数据和片段/序列设置 | 复现实验显示充分训练的 BERT 式目标可达到或超过当时若干新方法 | 多个配方变量共同变化；对某一变量的因果结论要看对应单项实验，不能从最终排行榜倒推 |

## 14.4 GPT 系列：统一的自回归生成目标

### 从 GPT-1 到 GPT-3

GPT 路线用 decoder-only Transformer 预测下一个 token。GPT-1 把无监督预训练与任务微调结合起来，GPT-3 则进一步研究 few-shot 和 in-context learning；这里引用的是研究路线，不意味着 GPT 各代训练配方完全相同。[GPT-1](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)、[GPT-3](https://arxiv.org/abs/2005.14165)

~~~math
\mathcal{L}_{\text{AR}}
=
-\sum_{t=1}^{T}
\log p_{\theta}(x_t\mid x_{<t})
~~~

xt 是第 t 个 token，x<t 是它之前的上下文，T 是序列长度，θ 是模型参数。这个目标与生成接口天然一致，训练时可以对整个序列并行计算 logits，推理时再逐 token 采样。

GPT-2 的重要信号是：规模化的无监督语言模型能够在没有显式任务头的情况下表现出多任务能力。GPT-3 进一步展示了 few-shot 和 in-context learning 的规模效应。这里的关键不是“只要扩大模型就会解决一切”，而是模型容量、数据覆盖、上下文示例和解码方式共同改变了任务表现。

### 自回归目标的代价

错误会沿生成链传播，事实性和工具调用不能只依赖 next-token loss。模型还可能生成流畅但不真实的文本，因为语言概率和世界事实不是同一个目标。后训练、检索、验证器、工具权限和系统评估因此成为生成模型的必要补充。

GPT 系列建立了现代通用 LLM 的主干，但不是一套固定架构。RoPE、RMSNorm、SwiGLU、GQA、MoE、长上下文训练和 reasoning post-training 都是后来围绕这条主干做的改造。

## 14.5 T5：把任务统一为 text-to-text

T5 选择 encoder-decoder 架构，把分类、翻译、摘要、问答等任务都写成文本到文本映射。统一接口减少了任务特定的输出头，让预训练目标和下游生成形式更接近。原论文还系统比较了模型架构、预训练目标、数据集与规模，因而其贡献也包括对迁移学习配方的实验拆解。[T5 原论文](https://arxiv.org/abs/1910.10683)

这项工作的研究价值在于系统比较了预训练数据、目标、模型规模和迁移方式，而不只是提出一个新的网络模块。它说明“统一任务形式”本身可以成为模型设计变量。

T5 并没有成为现代聊天模型的唯一主流架构。长序列自回归生成、工具调用和开放式对话使 decoder-only 路线更常见；但 encoder-decoder 仍适合条件生成、翻译、摘要和某些编辑任务。论文的真正遗产是任务接口和预训练迁移思想，而不是固定的模型形态。

## 14.6 Scaling Laws：把规模扩展变成可估计问题

### 经验规律

Scaling Laws 研究参数量 N、训练 token 数 D 与计算预算 C 的耦合，以及它们和验证 loss 的经验关系。一个可分解的教学近似是：

~~~math
L(N,D)
\approx L_{\infty}
+A N^{-\alpha}
+B D^{-\beta}
~~~

L 是验证交叉熵，N 是参数量，D 是训练 token 数；L∞ 是经验极限，`A,B>0` 和正指数 `α,β` 按具体数据与训练配方拟合。该式只是分离项示意，不是 Kaplan et al. 的唯一拟合形式。计算预算 C 限制可行的 (N,D) 组合；对固定架构和序列设定下的 dense Transformer，训练 FLOPs 可粗略随 N×D 增长，但实际成本还取决于序列长度、注意力实现、训练协议和硬件效率。因此，不应把 N、D、C 当作彼此独立的幂律变量再相加。Scaling Law 的经验研究见 [Kaplan et al., 2020](https://arxiv.org/abs/2001.08361)。

### 论文带来的方法论

研究团队可以先训练一组较小模型，在控制数据和优化器的条件下拟合 loss 曲线，再预测更大配置的收益。这使模型规模、数据规模和训练步数不再完全依赖经验拍板。

但 loss 的可预测性不等于所有能力都可预测。推理、工具使用、安全行为和长上下文利用可能在某些规模或数据条件下出现不连续变化；污染、数据质量和训练后处理也会破坏简单外推。

### 工程边界

使用 scaling law 时必须记录 token 去重、数据质量、训练 token 是否重复、硬件效率和目标指标。一个在预训练 loss 上更优的配方，不一定在事实性、代码执行或拒答质量上更优。

## 14.7 Chinchilla：固定计算预算下重新平衡模型与数据

早期扩展实践常把大量预算投入更大的参数量，却没有给模型足够训练 token。Chinchilla 论文研究固定计算预算下参数量 N 和数据量 D 的平衡，强调 compute-optimal training（[Hoffmann et al., 2022](https://arxiv.org/abs/2203.15556)）。论文训练了约 400 个模型以拟合规模关系，并在约定的训练 FLOPs 预算下重新分配模型规模与 token 数；它提供的是预训练计算最优性分析，不直接给出部署时延、数据清洗或后训练预算的最优点。

可以抽象为：

~~~math
\min_{N,D}L(N,D)
\qquad
\text{subject to}\qquad
C(N,D)\leq C_{\max}
~~~

Cmax 是计算预算。具体的成本函数依赖层数、隐藏维度、序列长度、并行方式和硬件，所以不能把论文结论简化成对所有模型都适用的固定 token/parameter 比例。

Chinchilla 的重要影响是改变了“参数越大越好”的直觉。较小但训练更充分的模型可能在固定推理成本下取得更好的效果；与此同时，数据质量、重复率、领域覆盖和后训练预算都会改变最佳点。

这项工作也提醒读者区分训练最优和部署最优。训练 token 更多可能增加预训练成本，模型更小可能降低线上延迟，但能力、上下文容量和并发成本还要另外评估。

## 14.8 PaLM 与 LLaMA：规模化配方和开放生态

PaLM 展示了大规模 dense decoder-only 模型在多任务、推理、多语言和代码任务上的扩展效果。它的重要性在于公开了大规模训练、数据混合和能力评估的系统经验，而不是证明参数量单独决定能力。[PaLM 原论文](https://arxiv.org/abs/2204.02311)

LLaMA 则把“高质量数据加现代 decoder-only 配方”与开放权重生态连接起来。RMSNorm、SwiGLU、RoPE 等组件后来成为许多开源模型的常见选择；开放权重又推动了 LoRA、量化、推理框架和社区评测的发展。[LLaMA 原论文](https://arxiv.org/abs/2302.13971)

这两类论文不能只按榜单数字比较。PaLM 重点是规模化训练经验，LLaMA 重点是开放生态和高效配方。读者应分别关注数据、训练计算、许可、权重开放范围和复现实验条件。

## 14.9 RoFormer：RoPE 如何把位置信息放进内容关系

### 旋转位置编码

RoPE 不把一个独立位置向量简单加到 token 表示上，而是对 query 和 key 的二维子空间做与位置有关的旋转。对位置 m 的二维分量，可以抽象写为：

~~~math
R_{\theta,m}
=
\begin{bmatrix}
\cos(m\theta)&-\sin(m\theta)\\
\sin(m\theta)&\cos(m\theta)
\end{bmatrix}
~~~

将不同维度使用不同频率 θ 后，query 与 key 的内积会带有相对位置关系。这个性质让 attention 分数同时依赖内容和相对距离。

### 为什么重要

RoPE 在 decoder-only LLM 中广泛使用，因为它不需要额外的位置 embedding 表，并且与自回归 attention 结合自然。它也让长上下文扩展变成频率、缩放、训练长度和插值策略的系统问题。

RoPE 不等于无限长度外推。若训练时覆盖的相位范围与推理时相差太大，旋转角度分布、注意力分辨率和数值行为都会改变。线性 scaling、NTK-aware scaling、YaRN 等后续方法都要在目标长度和任务上重新评估。[RoFormer 原论文](https://arxiv.org/abs/2104.09864)

## 14.10 ALiBi：用注意力偏置表达距离

ALiBi 不旋转 token 表示，而是在 attention logits 上加入与相对距离相关的线性偏置：

~~~math
s_{ij}
=
\frac{q_i k_j^{\mathsf T}}{\sqrt{d_k}}
-m_h(i-j)
~~~

m_h 是第 h 个 attention head 的斜率。距离越远，偏置通常越不利于注意力连接，因此模型在训练长度之外可能保留一定的距离归纳偏置。

ALiBi 的价值在于展示位置机制不只有“给 token 加 embedding”这一种形式。它的代价是偏置结构可能限制某些长距离关系，且与现代模型的训练 recipe、局部注意力和缓存策略需要一起分析。

RoPE 与 ALiBi 的比较不能只看单个长上下文分数。ALiBi 论文报告了在其训练长度和模型配置下的长度外推实验，但那不是任意模型的上限保证。还要观察短上下文质量、长度外推、不同任务、不同语言和 attention pattern。位置编码是模型能力的一部分，也是推理账本的一部分。[ALiBi 原论文](https://arxiv.org/abs/2108.12409)

## 14.11 Mamba：从二次 attention 到选择性状态空间

Mamba 研究选择性状态空间模型，希望用线性序列计算处理长序列，同时保留对输入内容的选择能力。传统固定参数的次二次序列模型在语言任务上容易缺少内容寻址能力；Mamba 让状态参数依赖输入，并配合硬件感知算法计算选择性递归。连续状态空间的离散形式可以写成：

~~~math
h_t=\bar{A}_t h_{t-1}+\bar{B}_t x_t
~~~

~~~math
y_t=C_t h_t
~~~

ht 是递归状态，xt 是输入，yt 是输出。Mamba 的选择性机制让部分参数随输入变化，使模型可以决定哪些信息应该写入状态、哪些信息应该忘记。

它解决的是 attention 在长序列上的计算和内存成本问题，并提供了另一条递归建模路线。Mamba 的线性复杂度不代表所有任务都一定更好：需要精确 token-to-token 交互的任务、长距离复制和复杂检索可能仍受状态压缩影响。

后续 hybrid architecture 把 attention 与 SSM 交替或组合，说明架构选择正在从“attention 对 SSM”转向“不同状态访问模式如何分工”。比较时应同时记录训练吞吐、decode 延迟、长距离检索、状态内存和 kernel 成熟度。论文中的吞吐和长序列成绩绑定作者实现、数据与硬件，不表示同参数量模型在所有生产负载都更快。[Mamba 原论文](https://arxiv.org/abs/2312.00752)

## 14.12 FlashAttention：改变 attention 的内存访问

标准 attention 的数学形式不一定是硬件上的高效实现。中间的 attention matrix 可能需要在高带宽显存和片上 SRAM 之间反复读写，实际瓶颈因此可能来自 IO 而不是乘加次数。

FlashAttention 使用分块计算和 online softmax，在不显式保存完整 attention matrix 的情况下得到数学上等价的 attention（浮点舍入误差除外）。对分块中的最大值 m 和归一化因子 l，可以递推合并不同块的统计量，从而保持数值稳定。[FlashAttention 原论文](https://arxiv.org/abs/2205.14135)

它没有把 attention 的理论复杂度从平方级变成线性，而是降低了内存读写和中间结果存储。收益依赖 GPU 架构、tile 大小、序列长度、head 维度、mask 类型和 kernel 实现。

FlashAttention 的论文贡献是算法与硬件内存层级的协同设计。它影响了训练和推理框架，但不能替代长上下文稀疏注意力、状态空间模型或分页缓存；这些方法解决的是不同层次的问题。

## 14.13 FlashAttention-2：让并行划分更贴近 GPU

FlashAttention-2 继续优化 work partitioning，减少非矩阵乘法操作和线程块之间的不平衡，让 GPU 的并行资源更充分地利用。它说明同一个数学算子仍可能因为线程组织、共享内存、warp 分工和序列长度产生明显性能差异。[FlashAttention-2 原论文](https://arxiv.org/abs/2307.08691)

阅读 FlashAttention-2 时要把“kernel 更快”和“系统端到端更快”分开。kernel benchmark 常使用固定 shape 和预热后的稳定输入，生产请求则包含动态 batch、不同长度、KV cache、mask、并发和调度开销。真实系统还需要报告 TTFT、TPOT、p99、显存峰值和吞吐。

## 14.14 GQA：在质量与 KV Cache 之间做结构折中

Grouped-Query Attention 让多个 query head 共享较少的 key/value head。若 query head 数为 Hq，KV head 数为 Hkv，且 Hkv 小于 Hq，则 decode 时缓存的 K/V 数量近似按 Hkv 缩减：

~~~math
\mathrm{KVBytes}
\approx
2N_{\text{layers}}B T H_{\text{kv}}d_{\text{head}}b_{\text{elem}}
~~~

这里假设 batch 中 B 条序列都缓存 T 个 token、每层使用相同的 head 维度和 KV head 数；Nlayers 是 Transformer 层数，Hkv 是每层的 key/value head 数，dhead 是每个 head 的维度，belem 是每个缓存元素占用的字节数，系数 2 对应 key 和 value。不同序列长度时用各序列缓存 token 数之和替换 B×T。公式不含 block 对齐、量化元数据、共享前缀和分配器开销。

MQA 把 Hkv 减到 1，GQA 则在共享程度和表达能力之间取中间位置。GQA 论文展示了从 MHA checkpoint 继续训练、以约 5% 原始预训练计算量转成 GQA 的实验路线，并在其评测中获得接近 MHA 的质量、接近 MQA 的速度；这个结果绑定论文模型与设置，不等于转换任意 checkpoint 都无损。[GQA 原论文](https://arxiv.org/abs/2305.13245)

GQA 的论文价值是把 attention 质量和 serving 内存放到同一张设计表里。它不只是训练时的 head 配置，也改变了 KV cache 容量、批处理上限和 decode 带宽。比较 MHA、MQA 和 GQA 时必须固定模型质量、序列长度和硬件，否则无法判断收益来自结构还是环境。

## 14.15 InstructGPT：后训练把 base model 变成助手

### 三阶段 pipeline

InstructGPT 论文把预训练语言模型的行为调整拆成 SFT、Reward Model 和 RLHF。首先用人工示范训练监督模型；然后让标注员比较候选答案，训练奖励模型；最后用 PPO 等方法优化 policy，并用 KL 约束减少偏离参考模型。

这个 pipeline 解决了一个重要错位：预训练目标是预测文本，用户目标却是遵循指令、保持有用、诚实和安全。论文的标注者偏好评估显示，1.3B 的 InstructGPT 在该评估提示分布上比 175B GPT-3 更受偏好；论文还观察到真实性和毒性指标的改善及部分能力退化。这是特定标注流程和提示分布的结果，不应概括为“小模型普遍胜过大模型”。[InstructGPT 原论文](https://arxiv.org/abs/2203.02155)

### 证据和代价

偏好数据定义了什么叫“好回答”，所以标注指南、标注员分布、任务范围和奖励模型错误都会影响结果。RLHF 还引入了 rollout、奖励模型、策略优化和 KL 调参的系统复杂度。

InstructGPT 的后续影响不是“RLHF 永远优于其他训练”，而是建立了现代 assistant post-training 的问题分解。DPO、RLAIF、RLVR 和 process supervision 都是在改变其中的反馈来源、优化方式或监督粒度。

## 14.16 Constitutional AI：把安全原则变成反馈来源

Constitutional AI 用一组原则指导模型对回答进行 critique 和 revision，再使用 AI feedback 形成偏好或训练信号。它试图减少高风险偏好数据的人工标注压力，并让安全原则更显式、更可审查。论文把监督式 self-critique/revision 与 AI 生成偏好再训练分成两个阶段；它支持的是这条训练流程在作者评估中的效果，不证明任意一份原则或任意评判模型都能可靠控制安全行为。[Constitutional AI 原论文](https://arxiv.org/abs/2212.08073)

与纯人工偏好相比，原则化反馈的优势是规则可以被记录、修改和分析；代价是原则本身需要选择，评价模型仍可能继承偏差，模型生成的批评也可能只是在模仿安全语言。

因此，Constitutional AI 的论文证据支持一种训练路线，不支持“写下原则后系统就安全”。必须另外检查 under-refusal、over-refusal、越狱、多语言、工具调用和外部内容注入。安全原则要落到可观察事件和回归样本中。

## 14.17 DPO：把偏好优化改写为直接目标

DPO 的核心是利用偏好数据和 reference policy，直接优化 chosen 与 rejected 响应的相对对数概率。常见单样本损失为：

~~~math
\mathcal{L}_{\text{DPO}}(\theta)
=
-\log\sigma
\left(
\beta
\left[
\log\frac{\pi_{\theta}(y_w\mid x)}
{\pi_{\text{ref}}(y_w\mid x)}
-
\log\frac{\pi_{\theta}(y_l\mid x)}
{\pi_{\text{ref}}(y_l\mid x)}
\right]
\right)
~~~

x 是输入，yw 是被偏好的响应，yl 是被拒绝的响应，πθ 是待训练策略，πref 是参考策略，β 控制偏好间隔的尺度。

DPO 把经典 RLHF 中显式奖励模型加在线策略优化的目标改写为偏好对分类损失，不需要在微调阶段从当前策略在线采样。作者在情感控制、摘要和单轮对话上报告了相对 PPO-RLHF 有竞争力的结果；这不是对长期环境任务、工具调用或任意偏好分布的证明。它仍然依赖偏好数据的质量，序列 log-prob 如何聚合、assistant mask 如何定义、reference 是否冻结和数据是否包含长度偏差都会影响训练。[DPO 原论文](https://arxiv.org/abs/2305.18290)

DPO 的意义不是证明 RL 不需要，而是把“离线偏好学习”的一个重要子问题变得更简单。长期工具任务、稀疏奖励和真实环境探索仍可能需要在线反馈、验证器或强化学习。

## 14.18 DeepSeekMath 与 GRPO：用可验证奖励训练推理

DeepSeekMath 把数学数据、规则验证和 Group Relative Policy Optimization 联系起来。对于同一个问题采样一组输出，用结果是否正确形成组内相对优势，可以减少对单独 value model 的依赖。DeepSeekMath 7B 继续预训练使用了约 120B 个数学相关 token；论文在 MATH 上报告单样本 pass@1 为 51.7%，64 路 self-consistency 为 60.9%。两项结果的采样预算不同，不能当成算法单独带来的同口径提升。[DeepSeekMath 原论文](https://arxiv.org/abs/2402.03300)

若一组样本的奖励为 r1 到 rG，组均值为 rbar，组标准差为 s，则一种标准化相对优势是：

~~~math
A_i=
\begin{cases}
\dfrac{r_i-\bar r}{s}, & s>0,\\
0, & s=0.
\end{cases}
~~~

G 是组大小，s 是组内奖励的标准差。当组内奖励完全相同时，所有样本的相对优势定义为 0；不能在零标准差上加一个小常数后假装仍然有区分信号。真实算法还包含 KL 惩罚、概率比裁剪、token mask 和序列归一化，不能把这条公式当成完整实现。GRPO 相比常见 PPO 路线省掉独立 value model，但每个问题需要采样多个候选，生成和打分成本会上升。

GRPO 的研究价值在于把“结果可验证”的数学和代码任务变成强化学习信号，减少主观 reward model 的依赖。代价是训练依赖可靠 verifier，奖励容易被投机，难以直接迁移到没有明确答案的开放任务。组内奖励若全相同，当前样本组不给出区分方向；组采样不足也会让优势估计噪声很大。后续分析还指出，按每条回答长度归一化可能让长回答获得不同的梯度权重，这说明 advantage 公式之外，loss 的 token/response/batch 归一化也会改变优化行为。

## 14.19 DeepSeek-R1：推理能力、RLVR 与蒸馏的组合

DeepSeek-R1 的论文把大规模强化学习、可验证任务、推理行为和蒸馏放在同一条路线中。应先区分两个常被混为一谈的模型：

| 阶段 | 训练做法 | 论文指出的收益与问题 |
| --- | --- | --- |
| R1-Zero | 从 DeepSeek-V3-Base 直接做 RL，不先进行 SFT；主要用可判定结果的规则奖励 | 作者报告推理表现和较长的反思轨迹随训练出现；同时指出可读性弱、语言混杂，写作和开放域问答能力有限 |
| R1 | 先用数千条 cold-start 推理样本做 SFT，再做 RL；随后从 RL checkpoint 拒绝采样生成推理数据，与非推理数据混合做 SFT，最后再做一阶段 RL | 目标是在保留推理改进的同时改善表达、指令跟随和非推理任务；额外阶段带来数据筛选、奖励模型和训练成本 |

论文 v2 记录的 R1 流程并非“把 R1-Zero 多训几步”：它显式加入冷启动数据、拒绝采样和非推理 SFT，还用模型奖励处理一般帮助性/安全偏好；公开蒸馏模型则把大模型轨迹作为较小模型的监督来源。该论文也报告了可读性与语言一致性权衡、模型奖励 reward hacking 等问题。相关结果绑定作者模型、数据、评测设置与 2026-01-04 的 v2 版本。[DeepSeek-R1 原论文 v2](https://arxiv.org/abs/2501.12948)

阅读这类报告时需要分开三个层次：

1. base model 和 post-training recipe 的能力差异；
2. 采样预算、思考长度、verifier 和答案聚合带来的测试时收益；
3. 蒸馏模型是否保留了原始 reasoning policy，以及在不同任务上的迁移范围。

“模型会生成更长推理”不等于“每一步都真实可靠”。必须检查最终答案、过程错误、停止行为、成本、拒答和工具轨迹。RLVR 的强项是可验证结果，弱点是 verifier 覆盖有限时可能出现 reward hacking。测试时计算的增长也需要配对测量正确率、无效 token、延迟和单位成本；否则模型可能只是把更多 token 花在错误路径上。

DAPO 和 Dr.GRPO 针对的瓶颈不同，不能缩成“改进 GRPO”一个结论：

| 后续工作 | 具体改动 | 想解决的现象 | 证据范围与限制 |
| --- | --- | --- | --- |
| DAPO | clip-higher 放宽正向概率比上限以保留探索；dynamic sampling 筛选奖励不全相同的问题组；token-level policy loss 按有效输出 token 汇总；overlong reward shaping 处理截断回答 | 熵过早下降、零优势样本浪费、长短序列梯度权重和截断带来的奖励噪声 | 作者在 Qwen2.5-32B 与 AIME 2024 报告 50 分；提升来自开放数据、训练系统和算法配方整体，不能归因到单个组件，也不能直接外推到开放式任务 |
| Dr.GRPO | 移除按 response length 和组内 reward 标准差做归一化的项 | 针对 GRPO 实现中观察到的错误回答长度持续增长及相关 token 效率问题 | 作者在特定 Qwen/MATH 设置报告了实验支持；它是对特定目标与实现问题的后续修正，是否适合不同 reward、采样与 loss 聚合方式仍须实测 |

这条谱系说明 reasoning post-training 仍在快速演进。阅读时应把模型先验、奖励、采样、policy objective、loss 归一化、推理预算和数据配方拆开，才知道收益来自哪一环。[DAPO](https://arxiv.org/abs/2503.14476)、[Dr.GRPO 研究](https://arxiv.org/abs/2503.20783)、[推理 RL 综述](https://arxiv.org/abs/2509.08827)

## 14.20 LoRA：把微调更新限制在低秩子空间

LoRA 冻结基础模型权重 W，只训练一个低秩更新。论文在 GPT-3 175B 案例中报告了显著减少可训练参数与训练显存，并指出将 adapter 合并进权重后不额外增加推理延迟；这些量化收益依赖 rank、适配模块和具体部署方式。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

~~~math
W'=W+\frac{\alpha}{r}BA
~~~

A 的形状为 r × din，B 的形状为 dout × r，r 是低秩维度，α 是缩放系数。训练参数量从 dout × din 降为 r × (din + dout)。

LoRA 解决的是每个任务都复制一份大模型参数的问题。它降低训练显存、保存体积和多任务切换成本，也使个人和小团队能够适配大模型。

低秩假设不是免费午餐。任务差异很大、插入层不合适、rank 太小或 adapter 合并方式错误时，能力可能受限。评估不能只看训练 loss，还要看基座能力保留、不同任务干扰、adapter 组合和实际部署延迟。

## 14.21 QLoRA：量化基座与低秩适配的组合

QLoRA 把 4-bit 量化基座、LoRA adapter、NF4、double quantization 和 paged optimizer 组合起来，降低微调大模型的显存门槛。它解决的是“即使只训练少量参数，加载基础模型仍然很贵”的问题。论文报告了 65B 模型在 48GB 单卡上微调的案例；这是 NF4、优化器、模型配置和实现配合下的结果，不表示任意模型/序列长度都能装入同样显存。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)

量化影响的不只是存储，还可能影响计算精度、梯度路径、kernel 支持和训练稳定性。不同硬件、量化格式、累加精度和框架实现会产生不同结果。

QLoRA 的证据应同时报告基础模型、量化配置、LoRA rank、目标模块、训练 token、batch、梯度累积、评估基线和合并后的推理精度。只写“用 QLoRA 微调成功”无法说明显存、质量和复现条件。

## 14.22 ZeRO：用通信换数据并行显存

普通数据并行把参数、梯度和 optimizer state 的完整副本放在每个 rank 上。ZeRO 分阶段切分这些状态；论文还分析了通信、模型规模和训练可扩展性。[ZeRO 原论文](https://arxiv.org/abs/1910.02054)

- ZeRO-1 切 optimizer state；
- ZeRO-2 进一步切 gradient；
- ZeRO-3 连 parameter 也切分，并在需要时通信聚合。

如果参数量为 P、优化器和梯度等状态总占用为 S，复制式数据并行的每卡状态约为 S；理想均匀切分后，持久状态可接近 S/N，其中 N 是 data-parallel rank 数，但通信和临时 gather 会增加。

ZeRO 的核心 trade-off 是显存、通信、带宽、容错和实现复杂度。它不等于张量并行或流水并行，实际系统常把多种并行方式组合起来。评估时要记录峰值显存、step time、通信量、checkpoint 语义和故障恢复。

## 14.23 GShard 与 Switch Transformer：MoE 的稀疏容量

GShard 展示了条件计算和自动分片如何把稀疏专家模型扩展到大规模训练；Switch Transformer 用 top-1 routing 简化每个 token 的专家选择。论文报告了在其大型翻译和语言建模配置中的扩展结果，并讨论路由/训练稳定性。路由器可以写成：[GShard](https://arxiv.org/abs/2006.16668)、[Switch Transformer](https://arxiv.org/abs/2101.03961)

~~~math
p_t=\mathrm{softmax}(W_rh_t),
\qquad
e_t=\arg\max_j p_{t,j}
~~~

ht 是 token 表示，Wr 是 router 参数，pt 是专家概率，et 是被选择的专家。真实系统还要处理 capacity、overflow、负载均衡和跨设备 all-to-all。

MoE 把总参数量和每 token 激活计算分离开来，但通信和负载不平衡可能成为瓶颈。某个专家过热时，token 可能被丢弃、溢出或转发到远端设备；因此不能只用 active parameters 估算成本。

## 14.24 Mixtral：开放 MoE 的工程化样本

Mixtral 是开放权重 MoE 的代表案例。其 8×7B 配置每个 token 选择两个专家；报告总参数约 46.7B、每 token 激活约 12.9B 参数。与 Switch 的 top-1 路由相比，top-k 路由可能增加可用专家容量，也会增加专家计算和通信；论文的模型报告不证明所有 workload 下 MoE 都比 dense 模型更便宜。[Mixtral 模型论文](https://arxiv.org/abs/2401.04088)

这篇模型报告更适合用来研究 MoE 的公开实现、推理加载和部署取舍，而不是抽象成“MoE 一定更省”。总参数、激活参数、专家数、每卡放置、通信拓扑、batch 和 context length 共同决定真实成本。

## 14.25 RAG：把知识从参数外置到可检索证据

RAG 将检索器与生成器连接起来。下面的式子是原论文 RAG-Sequence 的 top-k 简化：同一候选文档 z 为整段输出提供条件，再对文档变量边缘化。

~~~math
p_{\text{RAG-Sequence}}(y\mid x)
\approx
\sum_{z\in\mathrm{TopK}(x)}
p_{\eta}(z\mid x)
p_{\theta}(y\mid x,z)
~~~

x 是问题，pη 是检索器分布，pθ 是条件生成分布。RAG-Token 则在每个输出位置分别对检索文档求和，两种边缘化方式导致不同的解码和计算路径。生产系统通常只保留有限候选，并经过重排、过滤和上下文预算截断，因此召回率、证据支持率和最终答案正确率必须分开测量。[RAG 原论文](https://arxiv.org/abs/2005.11401)

RAG 解决参数知识过时、私有知识无法训练进模型和答案缺少证据的问题。它也引入了新的失败：切块不完整、权限过滤错误、检索到恶意文档、证据之间冲突、上下文超长和模型引用了没有支持的句子。

RAG 论文的贡献是把参数记忆与非参数文档记忆组合成可端到端微调的生成模型，而不是保证任何检索器都能提升回答。后来的 RAG 系统研究将问题扩展到 chunking、query 改写、混合检索、重排、上下文压缩、迭代检索和评估；这些是可独立替换的组件，需按检索失败类型选择，不能用“加 RAG”概括。真实系统需要记录知识库版本、文档权限、嵌入模型、召回 top-k、重排模型、上下文顺序和答案引用。[RAG 综述](https://arxiv.org/abs/2312.10997)

## 14.26 REALM 与 RETRO：检索成为模型记忆的一部分

REALM 把可学习的潜在知识检索器引入 MLM 预训练，梯度通过检索步骤影响检索器；检索可用于预训练、微调与推理。RETRO 则在自回归建模过程中按前文相似度检索邻近 chunk，再通过 chunked cross-attention 提供外部上下文。它们并非普通产品 RAG 的两个名字，而是分别探索“检索器怎样和预训练一起学”与“生成模型怎样逐块读取大语料”。[REALM 原论文](https://arxiv.org/abs/2002.08909)、[RETRO 原论文](https://arxiv.org/abs/2112.04426)

两者共同说明，模型能力可以在参数记忆和外部记忆之间分配。外部记忆更容易更新和审计，但会产生存储、索引、权限和检索延迟；参数记忆读取快，却难以精确更新和删除。

这条路线后来在企业 RAG、长上下文和 Agent memory 中继续演化。比较参数扩展和检索扩展时，不能只比较模型分数，还要比较更新时延、数据治理、引用质量、隐私边界和单位请求成本。REALM/RETRO 的检索发生在训练好的模型架构或训练流程内部；现代应用 RAG 常在推理时把检索结果作为上下文输入，替换索引不要求重训生成模型，但也不保证生成器能忠实使用证据。

## 14.27 ReAct：把推理和行动放进循环

ReAct 通过 thought、action 和 observation 的交替轨迹，让模型在回答过程中调用搜索、计算或环境工具。它解决了单次生成无法获取新信息、无法执行动作和无法根据反馈修正计划的问题。论文在知识问答、事实验证、文本环境和网页购物等不同任务中测试这种轨迹组织方式；结果受模型、示例和环境设置约束，不代表生产 Agent 自动具备权限管理或故障恢复。[ReAct 原论文](https://arxiv.org/abs/2210.03629)

ReAct 的关键不是固定的文字格式，而是闭环状态：

~~~math
s_{t+1}
=
F(s_t,a_t,o_{t+1})
~~~

st 是当前任务状态，at 是动作，ot+1 是工具观察结果，F 是状态更新过程。实际 Agent 需要把这个状态持久化，处理工具失败、重试、未知结果、权限和成本。

ReAct 也暴露了循环风险：模型可能重复调用、把外部文本当成指令、在错误观察上继续计划，或在最终答案中隐瞒工具失败。论文展示的是一种轨迹组织方式，生产安全还要依靠独立授权和状态机。与 Toolformer 相比，ReAct 侧重运行中显式交替推理、行动和观察；Toolformer 研究训练数据如何让模型学会何时调用 API。前者是执行轨迹范式，后者是工具使用行为学习，二者可组合。

## 14.28 Toolformer：让模型学习何时调用工具

Toolformer 研究先让模型提出 API 调用候选，再依据调用结果是否降低后续 token 的语言建模损失筛选训练样本，使模型学习何时调用 calculator、search、翻译、日历等工具、如何提供参数以及怎样使用返回值。它把 tool use 从纯手写规则扩展为可以被训练的行为；自动筛样本降低了人工构造调用轨迹的成本，但收益仍依赖候选调用、API 结果和语言损失能否代表任务价值。[Toolformer 原论文](https://arxiv.org/abs/2302.04761)

这项工作的关键假设是：工具调用的价值可以通过预测损失或任务收益识别。但开放系统中的工具可能有副作用、权限范围和费用，不能只用“调用后语言更像目标文本”作为安全标准。

后续 function calling 和 structured output 把工具请求与参数 schema 放到 API 接口层；以 OpenAI API 为例，当前文档明确把工具调用描述成多步交互：模型发出调用请求，应用端执行函数，再把结果发回模型。MCP 2026-07-28 规范则标准化 host/client/server 之间的资源、prompt 与工具能力交换。两者描述接口流程和互操作契约，不会自动提供具体业务授权、撤销、幂等或审计策略。[OpenAI function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)、[MCP 规范（2026-07-28）](https://modelcontextprotocol.io/specification/2026-07-28)。Toolformer 是学习工具使用的研究路线之一，不是完整的 Agent runtime；论文实验不覆盖真实副作用的审批、审计和幂等处理。

## 14.29 PagedAttention：把 KV Cache 当成分页内存管理

PagedAttention 借鉴虚拟内存思想，把不同请求的 KV cache 切成固定大小的 block，用 block table 映射逻辑序列位置和物理存储。这样可以减少长短请求混合时的内部碎片，并支持 prefix sharing 等优化。论文把该内存管理机制集成到 vLLM，并在与 FasterTransformer、Orca 的特定延迟比较中报告了 2–4 倍吞吐；这个数字不是单独 kernel 的普遍加速比。[PagedAttention 原论文](https://arxiv.org/abs/2309.06180)

逻辑 KV 容量按 14.14 的公式估算，PagedAttention 影响的是这批 K/V 张量的物理分配和复用：block table 允许按需分配并避免为每条请求预留连续的大块空间，但分页对齐和元数据仍有开销，prefix sharing 还要求正确处理引用计数与生命周期。它不会减少每层、每 token 要保存的 key/value 数值。

论文的系统价值在于把推理服务中的内存碎片和请求调度问题显式化。实际收益还取决于 block size、引用计数、prefix 命中、batch 动态变化和 kernel。不能把 PagedAttention 的论文吞吐直接当成目标硬件上的服务 SLO。

## 14.30 Chain-of-Thought：把中间状态变成测试时计算

Chain-of-Thought prompting 通过示例引导模型生成中间推理步骤，再输出最终答案。Wei et al. 在大模型和数个多步推理基准中研究了 few-shot CoT；其增益依赖模型规模、示例和任务，不能外推成任何提示都能增强推理。对同一任务和解码配置，可用：

~~~math
\Delta A
=
A_{\text{CoT}}-A_{\text{direct}}
~~~

表示 CoT 与直接回答的准确率差异。这个差异依赖模型规模、示例选择、任务难度、答案抽取和解码预算。[CoT 原论文](https://arxiv.org/abs/2201.11903)

CoT 的机制直觉是让模型有更多 token 表示中间状态，从而获得额外测试时计算。但生成的解释不一定是导致答案的真实内部因果过程；它可能是事后合理化，也可能包含隐藏错误。

因此，CoT 评估应把最终答案、过程正确性、token 成本、延迟、隐私和是否泄露不应展示的内部内容分开。简单任务、低延迟任务和高隐私任务不一定适合输出长推理。

## 14.31 Self-Consistency：用多条路径降低偶然错误

Self-Consistency 不固定一条 greedy 推理链，而是采样多条推理路径，再对标准化答案投票。它利用不同采样路径的答案分布，而不是假设第一条链可靠；对第 i 个问题的 K 条路径：

~~~math
\hat a_i
=
\arg\max_a
\sum_{j=1}^{K}
\mathbf{1}[a_{ij}=a]
~~~

aij 是第 j 条路径抽取出的答案。论文在 GSM8K、AQuA、StrategyQA 等任务上报告投票收益；效果依赖采样温度、路径多样性、K、答案标准化和投票等价关系。若所有路径共享同一个错误前提，增加样本数只会让错误更自信。[Self-Consistency 原论文](https://arxiv.org/abs/2203.11171)

这篇论文把推理质量与测试时计算联系起来。生产使用时还要比较单次回答的延迟、并发、成本、可解释性和失败合并策略；Self-Consistency 不是免费提高准确率。

## 14.32 Training Verifiers 与 GSM8K：结果监督的力量和盲区

Training Verifiers to Solve Math Word Problems 研究用结果验证器判断候选解答，GSM8K 则提供 8.5K 道小学数学应用题，成为早期多步推理评估的重要基准。[Verifiers 原论文](https://arxiv.org/abs/2110.14168)、[GSM8K 数据集](https://github.com/openai/grade-school-math)

验证器把“生成答案”和“判断答案”分开，允许系统采样多个候选，再选择验证器认为正确的候选。它也带来新的代理目标问题：若验证器只检查最终数字，模型可能生成错误但恰好得到目标数字的过程；若验证器过度依赖格式，模型会优化格式而不是数学。

GSM8K 的价值是任务清晰、答案可验证、容易比较 CoT 和 self-consistency。它的边界同样清晰：题型相对集中，公开数据存在污染可能，不能代表高级数学、代码、科学研究和真实业务推理。

## 14.33 Tree of Thoughts：从单链生成到状态搜索

Tree of Thoughts 把推理过程看成多个中间状态的搜索，而不是一条固定 token 链。对状态 s，可以由生成器提出候选扩展，再用评估器判断保留哪些节点：

~~~math
\mathcal{S}_{t+1}
=
\mathrm{Select}
\left(
\mathrm{Expand}(\mathcal{S}_t)
\right)
~~~

它可以与 beam search、best-first search 或 MCTS 组合。论文在 Game of 24、文字创作和交叉字谜等设定中展示了显式搜索的作用；方法的收益来自更多候选和搜索预算，代价是模型调用次数、状态去重、评估器误差和终止条件。[ToT 原论文](https://arxiv.org/abs/2305.10601)

Tree of Thoughts 的重要性是把 reasoning scaffold 显式化。随着模型内置 planning、长上下文和工具能力增强，外部树搜索有些场景可能被模型吸收，有些高价值任务仍会保留，因为显式搜索更容易施加预算和验证。

## 14.34 CLIP：用自然语言监督视觉表示

CLIP 用约 4 亿图文对进行对比学习，把图像和文本映射到共享语义空间。原论文在 30 多个视觉数据集上评估 zero-shot transfer；这证明了该训练路线在论文评测中的迁移价值，不等于任意类别、语言或部署分布都无需监督。[CLIP 原论文](https://arxiv.org/abs/2103.00020) 设图像嵌入和文本嵌入归一化后的相似度矩阵为 S，温度为 τ，则对称对比损失可写成：

~~~math
\mathcal{L}_{\text{CLIP}}
=
\frac{1}{2}
\left(
\mathrm{CE}(S/\tau,I)
+
\mathrm{CE}(S^{\mathsf T}/\tau,I)
\right)
~~~

I 表示 batch 内正确配对的对角标签。图文数据规模和开放词汇监督让 CLIP 具备 zero-shot 分类与检索能力。

CLIP 的限制来自数据：网页文本可能含噪、偏见、版权和重复，图文对应关系也不等于精确区域标注。zero-shot 分数依赖 prompt 模板、类别名称、图像分布和语言。

CLIP 的长期影响是把自然语言变成视觉监督入口，后续 VLM、图文检索、扩散模型条件和多模态 Agent 都继承了这种对齐思想。

## 14.35 ViT：把图像切成 token

Vision Transformer 把图像划分为固定大小 patch，将每个 patch 投影为 token，再用 Transformer 编码。原论文发现，大规模预训练后 ViT 能在多个图像识别基准上竞争；作者也显示数据规模变化会改变 ViT 与 CNN 的相对表现。若图像尺寸为 H × W、patch 边长为 P，则 patch 数近似为：[ViT 原论文](https://arxiv.org/abs/2010.11929)

~~~math
N_{\text{patch}}
=
\frac{H}{P}\cdot\frac{W}{P}
~~~

P 越小，视觉序列越长，空间细节越多，但 attention 成本按 token 数平方增长。ViT 证明在足够数据和预训练条件下，Transformer 可以成为视觉骨干。

这篇论文也揭示了数据规模的重要性：在小数据上，卷积的局部归纳偏置可能更有优势；在大规模预训练下，Transformer 的可扩展性更突出。现代视觉模型常把 patch、窗口 attention、层级特征和多模态连接器组合使用。

## 14.36 Latent Diffusion：把扩散过程移到压缩空间

像素空间扩散需要反复处理高分辨率图像，Latent Diffusion 先用 autoencoder 把图像压缩为 latent，再在 latent 空间加噪和去噪，并通过 cross-attention 接入文本等条件。[LDM 原论文](https://arxiv.org/abs/2112.10752) 噪声预测目标可以写为：

~~~math
\mathcal{L}
=
\mathbb{E}_{x,\epsilon,t}
\left[
\left\|
\epsilon-\epsilon_{\theta}(x_t,t,c)
\right\|_2^2
\right]
~~~

xt 是时间步 t 的带噪 latent，ε 是加入的噪声，c 是文本或其他条件。latent 空间降低计算量，但 VAE 压缩损失、采样步数、条件控制和安全过滤会影响最终图像。

Stable Diffusion 把这条路线带入开放生态。阅读它时要区分论文中的 latent diffusion 方法、具体 checkpoint、训练数据许可、采样器和社区插件；“Stable Diffusion”不是一个固定不变的单一模型。

## 14.37 Whisper：弱监督语音任务的统一接口

Whisper 用约 68 万小时的弱监督音频文本数据训练端到端模型，把多语言转写、语音翻译和语言识别放在统一接口中。论文在多项公开数据集上评估 zero-shot 表现；结果不能替代目标语言、口音、噪声与专有名词上的现场 WER 测量。[Whisper 原论文](https://arxiv.org/abs/2212.04356)

弱监督的优势是数据量大、语言和场景覆盖广，代价是转写质量、时间戳、说话人、版权和领域分布不完全可控。生产 ASR 还要处理 VAD、说话人分离、噪声、术语、实时延迟和错误修复。

Whisper 的论文结果不能直接等价于某个具体音频流的 WER。评估应按语言、口音、噪声、说话速度、专有名词和长音频切片，并把端到端延迟和人工纠错成本纳入系统账本。

## 14.38 Red Teaming Language Models：把安全失败变成实验对象

红队研究关注模型在恶意提示、有害内容、越狱、偏见和危险能力场景下的失败。与标准能力 benchmark 不同，红队样本主动寻找边界，攻击者会改变措辞、角色、语言、编码和多轮上下文。Perez 等人研究了用语言模型生成红队提示、再由分类器或标注过程判断有害响应的自动化路径；该工作展示的是扩充风险搜索样本的方法，不是完整安全验收标准。[Red Teaming 原论文](https://arxiv.org/abs/2202.03286)

一个攻击成功率可以写成：

~~~math
\mathrm{ASR}
=
\frac{\text{完成预先定义攻击目标的样本数}}
{\text{有效攻击样本总数}}
~~~

成功目标必须具体：输出危险文本、泄露秘密、生成越权工具参数和实际完成外部动作是不同事件。报告还要记录攻击预算、模型版本、系统提示、工具权限、人工判定和修复后的回归结果。

红队论文提供的是发现风险的方法，不是“测过一次就安全”的证明。最有价值的产物是版本化失败样本、风险严重度、根因和修复后反事实，而不是一组孤立的炫技对话。

## 14.39 ROME 与 MEMIT：修改参数化知识的研究路线

ROME 把某些事实关联近似为 Transformer MLP 中的键值映射，并通过定位因果层后做 rank-one 权重更新改变特定事实。MEMIT 把编辑扩展到多个事实、多个层和更大批次。抽象表示为：[ROME](https://arxiv.org/abs/2202.05262)、[MEMIT](https://arxiv.org/abs/2210.07229)

~~~math
W'=W+\Delta W
~~~

编辑目标包括新事实生效、同一事实的别名泛化和无关知识保持。编辑多个事实时，更新之间可能冲突或累积副作用。

任何知识编辑都至少需要编辑集、泛化集和保留集。编辑集回答“目标事实是否改变”，泛化集回答“不同模板和关系是否一致”，保留集回答“无关事实、语言能力和安全行为是否保持”。

ROME 和 MEMIT 说明模型内部知识具有一定可塑性，但不等于它们已经成为可靠的知识库更新方案。频繁变化、需要审计和需要精确删除的事实，通常仍适合放在外部知识库中。

## 14.40 Transformer Circuits 与机制解释性

机制解释性试图从 attention head、MLP、残差流和特征回路层面解释模型如何产生行为。与只观察 attention heatmap 不同，它更关心干预是否改变结果，以及改变是否具有跨样本稳定性。代表性入口包括 Transformer Circuits 的机制框架和 GPT-2 small 间接宾语识别回路研究；它们解释的是特定小模型、特定任务的电路证据，不能直接推广到所有规模模型。[机制框架](https://transformer-circuits.pub/2021/framework/index.html)、[IOI circuit 研究](https://arxiv.org/abs/2211.00593)

一个 activation patching 的差分可以写为：

~~~math
\Delta_{\text{patch}}
=
f(h_{\text{patched}})
-
f(h_{\text{corrupt}})
~~~

hpatched 是替换过中间激活的模型状态，hcorrupt 是对照状态，f 是任务评分函数。单次成功干预只说明该激活与任务相关；还需要随机方向、不同层、不同 token 位置、负向任务和跨样本测试。

Sparse Autoencoder 等方法试图把高维激活分解成较稀疏的特征。解释性工具可以帮助发现行为回路和诊断问题，但目前不能把一个人类可读标签直接当成完整因果解释，也不能替代输出评估、权限控制和事故响应。

## 14.41 Agent 评估论文：从静态答案到环境闭环

SWE-bench、WebArena 和 OSWorld 等工作把模型放进代码仓库、浏览器或桌面环境，观察它能否完成真实任务。三者测的不是同一种能力：SWE-bench 从 GitHub issue 和真实仓库改动验收补丁；WebArena 在多个网站中验收网页状态变化；OSWorld 在桌面应用和操作系统中执行任务并检查环境状态。OSWorld 论文构建了 369 个任务；三类论文均用各自的环境、工具和验收器，因此成功率不可直接排成一张榜。[SWE-bench](https://arxiv.org/abs/2310.06770)、[WebArena](https://arxiv.org/abs/2307.13854)、[OSWorld](https://arxiv.org/abs/2404.07972)

评价对象从单个答案变成一条轨迹：

~~~math
\mathrm{Success}
=
\mathbf{1}
[
\text{任务状态满足验收条件}
]
~~~

中间动作很多不等于成功，文本解释漂亮也不等于环境状态正确。Agent 评估需要记录任务初始状态、工具版本、权限、网络、时间和预算，并区分模型失败、环境失败、工具失败和验收器失败。

这些 benchmark 推动了代码 Agent、浏览器 Agent 和 computer-use 系统的发展，也暴露了污染、任务泄漏、环境不稳定和自动验收器偏差。读论文时要对齐初始状态、可用工具、模型/Agent scaffold、超时与预算、任务版本和验收脚本；线上业务还会额外包含权限、回滚、用户中断和长期状态，论文分数不能直接代表线上成功率。

## 14.42 按研究问题比较代表方案

前面的条目分别解释单篇论文。本节把常被放在一起讨论的方法拉到相同问题下比较，重点是“它改了哪一环、证据能支持什么、还留下什么约束”。表格里的收益来自各自论文，不构成跨模型排行榜；若下一步改进是工程推论，会明确写为推论。

### 14.42.1 长序列：改模型、改 kernel，还是改缓存管理

| 方案 | 直接针对的瓶颈 | 机制改变 | 论文证据与限制 | 后续改进关系 |
| --- | --- | --- | --- | --- |
| Transformer | RNN 训练沿 token 顺序递归，难以并行 | 让位置通过 self-attention 直接读取全序列内容 | WMT 翻译结果证明该架构在论文任务上可并行且有竞争力；全 attention 的序列交互成本随长度平方增长 | 后续不是一条替代路线：位置编码改表示，GQA 改 K/V 结构，稀疏注意力改交互集合 |
| Mamba | 长序列下 attention 的计算与 KV 状态成本 | 让状态转移依赖输入，用硬件感知算法并行计算选择性递归 | 作者报告线性序列扩展和若干吞吐结果；状态是压缩摘要，随机读取远处任意 token 与 attention 不同 | Hybrid 模型组合全局检索和递归状态，是面向随机访问限制的设计推论；要在目标任务实测 |
| FlashAttention / FlashAttention-2 | 标准 attention 中间矩阵的 HBM 读写与 kernel 利用率 | 用分块、online softmax 和更好的 GPU 工作划分，计算同一 attention 结果 | 降低特定 GPU/shape 下的 IO 和 kernel 时间；不把理论 attention FLOPs 从平方改成线性 | 可与 Transformer、RoPE、GQA 组合；端到端服务仍需测动态 batch、KV cache 和调度 |
| GQA | 自回归 decode 时每层、每 token 的 K/V 缓存太大 | 多个 query head 共享较少 KV head | 论文用约 5% 预训练计算上采样 MHA checkpoint，并在测试设置中接近 MHA 质量、接近 MQA 速度；结论依赖转换方式和模型 | 工程推论：若缓存仍是瓶颈，可结合量化或分页；需单独验证质量和带宽 |
| PagedAttention | 不同长度请求导致 KV 内存预留、碎片和前缀重复 | 固定 block + block table 管理逻辑位置到物理页 | vLLM 论文在指定基线和延迟条件下报告 2–4 倍吞吐；它不减少单 token 的 K/V 张量大小 | 工程推论：与 GQA/量化一起降低缓存压力；之后仍要优化 block 尺寸、前缀复用和调度策略 |

选型时先区分复杂度来源。如果单请求 attention kernel 读写效率差，FlashAttention 直接针对该层；如果每 token 的 K/V 头数占用高，GQA 改模型缓存形状；如果缓存分配碎片导致 batch 上不去，PagedAttention 改服务内存管理；如果目标是把长序列状态成本改成线性路线，才讨论 Mamba 或混合架构。前几项常可叠加，最后一项改变模型计算路径，质量和随机访问能力需要重新评测。

### 14.42.2 位置机制：相对关系来自旋转，还是 logit 偏置

| 方案 | 注入位置的方式 | 主要收益 | 失效边界与后续工作 |
| --- | --- | --- | --- |
| RoPE | 按 token 位置旋转 query/key 的二维分量，使内积携带相对位置信息 | 与自回归缓存和内容 attention 结合自然，成为许多 decoder-only 模型的选择 | 训练长度之外的相位分布可能改变；扩长通常需要缩放或插值，并检查短上下文退化 |
| ALiBi | 在 attention logits 上加 head-specific 的距离线性偏置 | 不依赖可学习的位置向量；原论文在其训练/测试长度设置中研究长度外推 | 距离惩罚会改变远距离连接偏好；不能将论文的外推结果当作任意模型、任务或长度的保证 |

二者不是只换一个公式：RoPE 改变 Q/K 的位置相关表示，ALiBi 改变 softmax 前的注意力分数。比较时要固定 tokenizer、模型容量、训练 token 和评测长度，并检查长程复制、检索、短上下文与不同语言；只报告“最大可输入长度”不能说明模型能否利用该长度。

### 14.42.3 外部知识：检索在哪个阶段进入模型

| 方案 | 检索发生的位置 | 关键机制 | 适合回答的问题 | 主要代价和边界 |
| --- | --- | --- | --- | --- |
| RAG-Sequence / RAG-Token | 微调后的生成任务中，把候选文档作为潜变量条件 | Sequence 让一个文档条件化整段回答；Token 在每个输出位置边缘化文档分布 | 如何把可更新文档库与生成任务结合；两种检索粒度怎样影响答案与解码 | 原论文使用 Wikipedia dense index、检索器和 seq2seq 生成器；生产 RAG 另需处理权限、chunking、重排、证据引用和上下文预算 |
| REALM | 预训练、微调和推理 | MLM 损失通过潜在检索步骤训练检索器，模型从大语料中读取文档 | 检索器能否与语言模型预训练共同学习 | 全语料索引、检索反传与索引刷新增加训练/系统复杂度；不是即插即用的检索 API |
| RETRO | 自回归预训练与逐块生成 | 按前文相似度取邻居 chunk，经 encoder 和 chunked cross-attention 注入 | 能否用大规模显式语料补充参数容量 | 论文报告 2T-token 数据库及特定 Pile 配置下较少参数达到可比语言建模表现；需要专用语料/索引和模型结构，不能直接推成普通 RAG 的收益 |

因此，工程问题若是“公司文档今天更新了，怎样让回答读到新版本”，通常首先考虑推理时 RAG；若问题是“预训练模型怎样学习检索知识”，REALM 更贴切；若问题是“语言模型怎样在每个生成块读取超大 token 记忆”，RETRO 是代表路线。选型还要看更新频率、延迟、隐私、索引治理、答案引用和可接受的训练改造量。

### 14.42.4 对齐反馈：谁提供“好回答”的信号

| 路线 | 反馈信号 | 主要优化路径 | 优势 | 失败边界与后续改进 |
| --- | --- | --- | --- | --- |
| InstructGPT / RLHF | 人工示范 + 成对偏好排序 | SFT → reward model → PPO 等在线策略优化 | 把“续写文本”转成“按指令回答”，并能在候选回答间学习偏好 | 标注成本、偏好群体代表性和 reward model 误差；需要用评测样本监控 reward hacking 与能力回退 |
| Constitutional AI / RLAIF | 原则文本、模型 critique/revision、AI 偏好反馈 | 先按原则自我批评和修订，再从 AI feedback 形成偏好训练 | 把一部分反馈标准写成可审阅原则，减少某些场景的人工偏好标注 | 原则选择和评判模型仍带偏差；应增加多语言、拒答、越狱和真实工具权限测试 |
| DPO | 离线 chosen/rejected 偏好对 | 通过参考策略的概率比构造分类损失 | 免去典型 RLHF 流程中的显式 reward model 和在线 rollout，训练链路更简单 | 仍受离线偏好覆盖、长度偏差和分布外行为影响；当目标需要环境探索或延迟奖励时，需比较在线反馈方案 |

这三类工作不能只按“哪种对齐更强”排序：InstructGPT 重点是完整人类反馈管线，Constitutional AI 改变反馈生成来源，DPO 改变离线偏好优化目标。面试或系统设计中应先问偏好由谁定义、能否离线采集、反馈是否可验证、任务是否需要在线探索，再讨论算法。

### 14.42.5 推理强化学习：算法、训练配方和模型结果分开看

| 工作 | 改变的部分 | 论文想解决的问题 | 读取结果时要避免的误判 |
| --- | --- | --- | --- |
| GRPO / DeepSeekMath | 用同题多个回答的组内奖励估计相对优势，不训练独立 value model | 降低 PPO critic 的显存与训练负担，让规则可验任务可直接给奖励 | 组采样本身有生成成本；奖励同分时没有相对区分信号；评测分数绑定 verifier 与采样预算 |
| R1-Zero | 在 base model 上直接 RL，不先做 SFT | 测试可验证奖励能否促成新的解题轨迹 | 更长回答可能是有用探索，也可能是长度偏差；还要查正确率、可读性、语言一致性和错误轨迹 |
| R1 | cold-start SFT、RL、拒绝采样、混合 SFT、第二阶段 RL 和蒸馏 | 在探索推理行为后补充对话、写作、安全及可读性能力 | 多阶段系统有更多数据与训练变量；不能把结果只归因于 GRPO |
| DAPO | 改 clipping、采样、token loss 聚合和 overlong 奖励处理 | 长 CoT RL 的熵衰减、无效样本、长短样本权重和截断噪声 | 报告的成绩来自算法、数据和系统共同作用；须看同模型、同采样和同 verifier 的消融 |
| Dr.GRPO | 去除按 response 长度和组标准差归一化项 | 检查 GRPO objective/实现是否让错误长回答获得不合理权重 | 作者在具体模型和数学任务中验证；换奖励类型、loss reduction 或训练栈时仍需复核 |

R1 公开的是多阶段训练研究，DAPO 是开源的大规模 RL 系统与算法配方，Dr.GRPO 聚焦于目标归一化偏差。它们证据粒度不同。复现表至少要同时记录 base model、问题集、正确性 verifier、每题采样数、最大生成长度、过滤规则、loss 聚合、计算量和评测推理预算；少一个关键条件都可能让“算法提升”实际来自数据或 token 预算差异。

### 14.42.6 测试时计算：采样、判分和搜索分别花预算

| 方法 | 新增计算用在哪里 | 如何选出最终答案 | 典型失败 |
| --- | --- | --- | --- |
| CoT | 生成一条更长的中间轨迹 | 取该轨迹末尾答案 | 文字解释不保证是真实因果过程；单链错误会贯穿后续步骤 |
| Self-Consistency | 对同一问题采样 K 条轨迹 | 标准化答案后多数投票 | 路径相关错误会一起投票；答案解析和等价判断会影响结果 |
| Verifier / Best-of-N | 先生成多个候选，再花判分器计算或人力挑选 | 选择 verifier 分最高的候选 | verifier 错误会把采样质量反向排序；候选数提高成本 |
| Tree of Thoughts | 逐层扩展多个中间状态并搜索 | 用状态评估器/搜索策略保留节点 | 搜索预算和剪枝策略敏感；评估器误判会提前丢掉正确分支 |

比较这些方法必须固定总预算或同时报告准确率—成本曲线：包括生成 token、候选数、判分调用、端到端延迟和单位成本正确率。Self-Consistency 与 verifier 依赖多样候选，ToT 还要维护搜索状态；它们不只是“让模型多想”，而是把额外计算分配到不同决策环节。

### 14.42.7 Agent benchmark：成功率只在各自环境里成立

| Benchmark | 被测环境与动作 | 结果验收 | 不可直接外推之处 |
| --- | --- | --- | --- |
| SWE-bench | 从 GitHub issue 出发，在指定代码仓库中定位、修改并提交补丁 | 运行仓库测试/任务验收，衡量 issue 是否解决 | 依赖仓库版本、测试覆盖、提示上下文、工具权限与执行预算；通过测试不等同于所有维护者都会接受补丁 |
| WebArena | 在多个功能网站中浏览、搜索、填写和修改状态 | 网站数据库/页面状态检查 | 与真实互联网的登录、动态内容、网络变化、反机器人和长尾页面不同 |
| OSWorld | 在 Linux/Windows/macOS 桌面应用中完成 GUI/CLI 跨应用任务 | 任务专属脚本检查实际环境状态；论文给出 369 个任务 | 依赖虚拟机镜像、桌面分辨率、应用版本和任务脚本；不等价于任意用户电脑上的成功率 |

这几类 benchmark 的任务单元、状态变化和验收方式不同，不能把论文成功率直接放入一列排名。可比较的做法是报告同一基准同一版本、统一 Agent scaffold 与预算下的结果，再用人工审查和真实业务失败成本补上自动验收器看不到的部分。

## 14.43 论文谱系中的继承、修正与替代

技术并不是沿着“新论文完全替代旧论文”的直线发展。更常见的情况是：

- Transformer 保留了 attention，但改变位置机制、归一化、专家路由和缓存；
- Chinchilla 修正了早期 scaling 直觉，但没有否定规模研究；
- DPO 简化了离线偏好优化，但没有消除在线反馈和 verifier 的需求；
- RAG 把知识外置，却没有消除参数记忆和上下文推理；
- Toolformer 研究学习工具使用，后续协议和运行时把权限、schema、审计独立出来；
- 外部 CoT、树搜索和 Agent scaffold 的一部分，可能被更强模型和更长上下文吸收，另一部分仍因可验证性和权限控制而保留。

因此，判断一项新技术是否值得进入主干，不应只看发布日期或榜单热度，而应看它解决的约束是否仍然存在、抽象是否稳定、证据是否可复现，以及它在系统中会保留、下沉还是被替代。

## 14.44 一条可复核的论文阅读记录

读完一篇论文后，最有用的记录不是几句宣传式结论，而是以下信息：

~~~text
研究问题：旧方法在哪个约束下失败
方法改变：架构、数据、目标、系统或评估中的具体变化
对照条件：基线、模型规模、训练 token、硬件和随机性
主要结果：指标、置信区间、成本和失败样本
消融证据：去掉哪个组件后结果如何
适用边界：任务、语言、长度、权限和攻击模型
后续演化：哪些工作继承、修正或替代了它
复现状态：代码、数据、环境和当前重跑结果
~~~

这份记录把“读过论文”与“能解释论文证据”区分开来。若某一项没有资料支持，就应明确标成未知，而不是用常识填补。

## 14.45 按问题组织的阅读路径

### 想理解模型为什么能生成

Attention Is All You Need、GPT、Scaling Laws、Chinchilla、RoPE、GQA 和 Mamba 组成架构与规模路径。它们分别回答表示交互、训练目标、规模收益、数据配比、位置信息、缓存成本和递归状态问题。

### 想理解模型为什么会听指令

InstructGPT、Constitutional AI、DPO、DeepSeekMath 和 DeepSeek-R1 组成后训练与 reasoning 路径。它们把示范、偏好、原则、可验证奖励和测试时计算连接起来。

### 想理解大模型为什么能部署

LoRA、QLoRA、ZeRO、FlashAttention、PagedAttention、Switch/Mixtral 组成训练和 serving 路径。它们分别处理适配成本、量化显存、分布式状态、内存 IO、KV cache 和稀疏专家。

### 想理解 Agent 为什么不只是聊天

RAG、ReAct、Toolformer、SWE-bench 和 WebArena 组成环境闭环路径。它们把外部知识、行动、工具学习、代码修改和环境验收纳入模型系统。

### 想理解多模态和安全

CLIP、ViT、Latent Diffusion、Whisper、Red Teaming、ROME/MEMIT 和机制解释性组成感知、生成、语音、风险与内部诊断路径。每条路径都需要结合数据治理、权限和目标系统实测。

## 本章小结

重要论文组成的不是一张标题清单，而是一条约束变化的历史：Transformer 重新安排了序列交互；Scaling Laws 和 Chinchilla 重新安排了训练预算；InstructGPT、DPO、可验证奖励和 reasoning post-training 重新安排了反馈；LoRA、ZeRO、FlashAttention、PagedAttention 和 MoE 重新安排了参数、内存、通信与计算；RAG、ReAct、Toolformer 和 Agent benchmark 把模型放进外部环境；CLIP、ViT、扩散和 Whisper 把语言模型方法扩展到多模态；红队、编辑、遗忘和机制解释性则把可靠性与安全变成研究对象。

读论文时，最重要的不是记住哪篇论文“最好”，而是说清它解决了哪个旧问题、依赖什么条件、牺牲了什么、被后续工作怎样修正，以及这些条件是否仍然存在于目标系统。只有这样，论文才能从来源变成可验证的工程知识。
