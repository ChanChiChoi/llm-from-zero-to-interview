# 第 14 章 重要论文索引

本章精选改变研究问题、方法路线或系统设计的代表性论文，帮助读者从标题进入原始证据。它不是穷尽书目，也不按论文分数排列名次。论文结果只适用于其模型、数据、基线、评测和计算预算；模型报告、数据集、benchmark 和协议规范也各有不同的证据边界。

本章条目承担“定位与判断”功能：说明论文关注的问题、主要改变和结论范围。机制推导、代码复现和工程实施由书系专题正文承担。论文链接尽量指向原始论文的固定版本；不断更新的产品文档和协议入口会单独标为动态资料。

若要追踪后续候选论文和官方技术报告，见仓库级[论文路线](../../PAPERS.md)；新增条目的来源类型、版本与证据范围仍须分别判断。

## 14.1 怎样使用这份索引

读一篇论文时，先找清它的研究问题和对照方法，再确认它改变的是表示、数据、训练目标、系统实现还是评估方式。随后核对结果对应的任务、数据、版本、指标、成本和失败样本，最后阅读作者明确列出的局限，并判断结论能否迁移到自己的场景。完整的阅读、贡献分析、消融和复现方法见[第十册第 2—6 章](../../book-10-paper-reproduction-research/chapters/02-如何读论文.md)、[如何判断论文贡献](../../book-10-paper-reproduction-research/chapters/03-如何判断论文贡献.md)、[实验复现方法](../../book-10-paper-reproduction-research/chapters/04-实验复现方法.md)、[消融与受控实验](../../book-10-paper-reproduction-research/chapters/05-ablation与controlled-experiment.md)及[负结果与实验报告](../../book-10-paper-reproduction-research/chapters/06-负结果与实验报告.md)。

## 14.2 Attention Is All You Need：从循环序列到全局依赖

**问题与改变**：论文用 self-attention 取代循环状态传递，让序列位置可以直接聚合其他位置的信息，并与多头结构、位置编码、残差和前馈层组成 Transformer。它建立了并行序列建模的一条主线，后续工作继续改变位置表示、注意力实现和缓存结构。

**证据边界**：原论文在 WMT14 翻译设置下比较模型质量和训练效率；这些结果不能直接代表今天的 decoder-only LLM 或生产系统表现。[原论文](https://arxiv.org/abs/1706.03762)

## 14.3 BERT：双向理解与预训练迁移

**问题与改变**：BERT 用掩码语言模型和下一句预测训练双向 encoder，再微调到分类、问答和序列标注等任务。它展示了“通用预训练表示加下游适配”的影响力，不等价于开放式生成能力。[原论文](https://arxiv.org/abs/1810.04805)

**后续修正**：RoBERTa 复核 BERT 配方，调整动态 masking、NSP、数据、batch 和训练长度。其结果提醒读者控制训练预算和数据条件；最终配方同时改变多个因素，不能仅凭总分把提升归因于移除 NSP。[原论文](https://arxiv.org/abs/1907.11692)

## 14.4 GPT 系列：统一的自回归生成目标

GPT-1 把无监督预训练和任务微调连接起来；GPT-2 展示了大规模语言模型的零样本迁移信号；GPT-3 系统研究 few-shot 和 in-context learning。它们共同推动 decoder-only 自回归模型成为通用生成主线，但不代表不同代际沿用同一训练配方，也不证明规模本身能解决事实性和工具可靠性。[GPT-1](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)、[GPT-2](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf)、[GPT-3](https://arxiv.org/abs/2005.14165)

## 14.5 T5：把任务统一为 text-to-text

T5 将分类、翻译、摘要和问答等任务统一为文本输入到文本输出，并系统比较预训练目标、数据、模型架构和迁移方式。它的贡献是任务接口与迁移学习的研究框架，而不是所有应用都应使用 encoder-decoder 架构。[原论文](https://arxiv.org/abs/1910.10683)

## 14.6 Scaling Laws：把规模扩展变成可估计问题

Kaplan 等人研究参数量、数据量、计算预算与语言模型 loss 的经验关系，展示了在受控训练条件下拟合趋势并预测部分规模变化的方法。它不能单独预测所有下游能力，也不能把某个数据、优化器或训练协议下的曲线外推到不同模型家族。[原论文](https://arxiv.org/abs/2001.08361)

## 14.7 Chinchilla：固定计算预算下重新平衡模型与数据

Chinchilla 研究固定训练计算预算下模型参数和训练 token 的配比，指出当时不少模型相对计算最优点训练 token 偏少。这个结论描述论文设定下的预训练 loss 最优，不给出所有部署、数据质量、后训练和推理成本的通用最优比例。[原论文](https://arxiv.org/abs/2203.15556)

## 14.8 PaLM 与 LLaMA：规模化配方和开放生态

PaLM 报告大规模 dense 模型的训练方法和多任务评测；LLaMA 报告不同规模模型、数据与训练计算的组合，并推动开放权重研究生态。两者适合比较数据、训练预算、公开范围和许可条件，不能只按论文分数得出架构优劣。[PaLM](https://arxiv.org/abs/2204.02311)、[LLaMA](https://arxiv.org/abs/2302.13971)

## 14.9 RoFormer：RoPE 如何把位置信息放进内容关系

RoFormer 提出旋转位置编码（RoPE），把位置相关旋转施加到 query 和 key，使注意力内积含有相对位置关系。它影响了许多 decoder-only 架构；长上下文扩展仍受训练长度、频率变换和目标任务约束，不等于无限长度外推。[原论文](https://arxiv.org/abs/2104.09864)

## 14.10 ALiBi：用注意力偏置表达距离

ALiBi 在注意力分数中加入与距离有关的线性偏置，展示了不通过位置向量、而直接影响注意力权重的位置注入路线。论文的长度外推结果绑定其训练长度、模型和测试任务，不能当作任意模型的长度保证。[原论文](https://arxiv.org/abs/2108.12409)

## 14.11 Mamba：从二次 attention 到选择性状态空间

Mamba 让状态空间参数依赖输入，并设计硬件感知的 selective scan，以线性序列复杂度处理输入。论文展示了其模型和实现下的长序列表现；线性计算并不保证所有需要精确远距检索的任务都胜过 attention。[原论文](https://arxiv.org/abs/2312.00752)

## 14.12 FlashAttention：改变 attention 的内存访问

FlashAttention 通过分块和 online softmax 减少 attention 中间矩阵的显存读写，同时保持数学目标不变。其收益来自 IO 与 kernel 设计，不能表述为把 attention 的理论平方级计算复杂度改成线性；性能受硬件、shape、mask 和实现影响。[原论文](https://arxiv.org/abs/2205.14135)

## 14.13 FlashAttention-2：让并行划分更贴近 GPU

FlashAttention-2 调整工作划分和线程并行，减少非矩阵乘法开销并改善 GPU 利用。论文 kernel 结果绑定特定硬件和输入 shape；实际服务还要测动态 batch、KV Cache、调度和端到端延迟。[原论文](https://arxiv.org/abs/2307.08691)

## 14.14 GQA：在质量与 KV Cache 之间做结构折中

Grouped-Query Attention 让多个 query head 共享较少的 key/value head，降低自回归推理的 K/V 缓存需求。论文报告了将 MHA checkpoint 转换为 GQA 的训练方案及特定质量、速度结果；转换成本和效果依赖 checkpoint、模型与评测设置。[原论文](https://arxiv.org/abs/2305.13245)

## 14.15 InstructGPT：后训练把 base model 变成助手

InstructGPT 将监督微调、人类偏好奖励模型与策略优化组织成 RLHF 流程，直接回应预训练目标与遵循用户指令之间的错位。论文中的偏好、真实性和毒性结果属于其标注者、提示分布和评测条件，不能推成“小模型普遍优于大模型”。[原论文](https://arxiv.org/abs/2203.02155)

## 14.16 Constitutional AI：把安全原则变成反馈来源

Constitutional AI 用显式原则指导模型 critique/revision，并用 AI feedback 构造偏好训练信号，探索减少部分人工偏好标注的路线。原则选择和评价模型自身仍可能有偏差，因此论文不证明只要写下规则系统就安全。[原论文](https://arxiv.org/abs/2212.08073)

## 14.17 DPO：把偏好优化改写为直接目标

Direct Preference Optimization（DPO）利用 chosen/rejected 响应及参考策略概率比直接形成偏好优化目标，省去典型 RLHF 流程中的显式 reward model 和在线 rollout。它仍受偏好数据覆盖、长度偏差和离线分布限制；长期交互和延迟奖励问题不因此消失。[原论文](https://arxiv.org/abs/2305.18290)

## 14.18 DeepSeekMath 与 GRPO：用可验证奖励训练推理

DeepSeekMath 将数学语料、可验证结果奖励和 Group Relative Policy Optimization（GRPO）结合。对同一问题采样多条回答，用组内相对奖励估计优势，减少对独立 value model 的依赖；多候选生成仍有成本，验证器覆盖不足时也会留下奖励投机空间。论文分数绑定其模型、题集、采样预算和 verifier。[原论文](https://arxiv.org/abs/2402.03300)

## 14.19 DeepSeek-R1、DAPO 与 Dr.GRPO：推理强化学习的后续路线

DeepSeek-R1 论文区分直接 RL 的 R1-Zero 与加入 cold-start、RL、拒绝采样和后续微调的 R1；公开蒸馏模型又是另一条监督迁移路径。阅读结果时应把 base model、训练配方、verifier、采样预算和蒸馏分开。本文固定引用 arXiv v2（2026-01-04）；该版本仍是作者技术报告中的特定模型实验，不证明生成的长推理都忠实或可靠。[DeepSeek-R1 v2](https://arxiv.org/abs/2501.12948v2)

DAPO 报告一套开放的大规模 RL 系统及算法配方，并在 Qwen2.5-32B 与 AIME 2024 上报告 50 分；数据、系统、采样与算法组件共同构成结果，不能归因于单项改动。[DAPO arXiv v2（2025-05-20）](https://arxiv.org/abs/2503.14476v2)

Dr.GRPO 分析特定 GRPO 训练中的回答长度偏差，并提出调整目标归一化的方案；结论绑定论文模型、数学任务和实现配置，换 reward 与 loss reduction 时仍要复核。[Dr.GRPO arXiv v2（2025-10-06）](https://arxiv.org/abs/2503.20783v2)。更广的技术路线和证据争论可从[推理强化学习综述](https://arxiv.org/abs/2509.08827)进入。

## 14.20 LoRA：把微调更新限制在低秩子空间

LoRA 冻结基座参数，只训练插入模块的低秩更新，降低可训练参数和 adapter 存储成本。论文还报告合并权重后不增加推理延迟的设置；效果取决于 rank、目标模块、任务和部署方式，低秩更新并非对任意任务都足够。[原论文](https://arxiv.org/abs/2106.09685)

## 14.21 QLoRA：量化基座与低秩适配的组合

QLoRA 把 4-bit NF4 基座、LoRA、double quantization 和 paged optimizer 组合，用于降低微调显存。论文报告的 65B 单卡案例绑定模型、序列长度、硬件和实现；不能据此保证任意模型都能放进 48GB 显存。[原论文](https://arxiv.org/abs/2305.14314)

## 14.22 ZeRO：用通信换数据并行显存

ZeRO 分阶段切分 optimizer state、gradient 和 parameter，以降低数据并行中的冗余显存。切分阶段越深，通信、临时聚合和系统实现越重要；它与 tensor/pipeline parallel 是可组合但不同的并行维度。[原论文](https://arxiv.org/abs/1910.02054)

## 14.23 GShard 与 Switch Transformer：MoE 的稀疏容量

GShard 研究稀疏专家模型的自动分片与规模化训练；Switch Transformer 以 top-1 路由简化 token 到专家的派发。MoE 将总参数与每 token 激活计算分开，但通信、容量限制、负载不均和 token overflow 会影响真实训练及推理成本。[GShard](https://arxiv.org/abs/2006.16668)、[Switch Transformer](https://arxiv.org/abs/2101.03961)

## 14.24 Mixtral：开放 MoE 的工程化样本

Mixtral 报告 8×7B 开放权重 MoE 配置，每个 token 选择两个专家，并披露总参数与激活参数估计。它提供了一个可分析的模型案例，不证明所有 workload 下 MoE 都比 dense 模型更便宜；设备拓扑、batch、序列长度和通信实现都会改变成本。[模型报告](https://arxiv.org/abs/2401.04088)

## 14.25 RAG：把知识从参数外置到可检索证据

Retrieval-Augmented Generation（RAG）把参数化生成器与检索文档结合，并区分以整段输出为条件的 RAG-Sequence 与逐 token 边缘化的 RAG-Token。原论文证明其方案在指定任务和数据上的效果，不保证任意检索器都会提高回答质量。现代 RAG 的切块、重排、权限过滤、上下文预算和引用评估，见[原论文](https://arxiv.org/abs/2005.11401)及[RAG 综述](https://arxiv.org/abs/2312.10997)。

## 14.26 REALM 与 RETRO：检索成为模型记忆的一部分

REALM 将潜在知识检索纳入语言模型的预训练和微调过程；RETRO 在自回归建模中按邻近 chunk 检索语料，并通过 cross-attention 读取。它们研究的是检索如何成为模型训练/架构的一部分，不等于推理时把文档拼进提示的普通产品 RAG。[REALM](https://arxiv.org/abs/2002.08909)、[RETRO](https://arxiv.org/abs/2112.04426)

## 14.27 ReAct：把推理和行动放进循环

ReAct 将模型生成的思考线索、动作和环境观察交替组织，让模型在工具反馈后继续决策。论文在指定问答、验证和交互环境中评估轨迹范式；真实 Agent 还需独立处理权限、工具失败、重试、状态恢复和副作用。[原论文](https://arxiv.org/abs/2210.03629)

## 14.28 Toolformer：让模型学习何时调用工具

Toolformer 用候选 API 调用及其返回结果筛选训练样本，研究模型能否学到何时调用工具、如何填写参数和怎样使用返回值。语言建模损失下降不等于业务动作值得执行，也不提供真实工具的审批、幂等和审计机制。[原论文](https://arxiv.org/abs/2302.04761)

## 14.29 PagedAttention：把 KV Cache 当成分页内存管理

PagedAttention 把 KV Cache 切成固定大小的 block，并用映射表管理逻辑 token 位置与物理内存，以减少请求长度差异造成的碎片并支持前缀共享。vLLM 论文的吞吐结果对应作者实现、硬件和基线；分页不会减少每个 token 实际需要保存的 K/V 值。[原论文](https://arxiv.org/abs/2309.06180)

## 14.30 Chain-of-Thought：把中间状态变成测试时计算

Chain-of-Thought（CoT）提示用示例引导模型生成中间步骤，再给出答案。论文的增益依赖模型规模、任务、示例和解码预算；可读文本不自动等于模型内部因果过程，也不保证每一步正确。[原论文](https://arxiv.org/abs/2201.11903)

## 14.31 Self-Consistency：用多条路径降低偶然错误

Self-Consistency 对同一问题采样多条推理路径，再对规范化答案投票。论文报告了特定数学、问答任务中的改善；路径相关错误、答案解析和额外生成成本会限制收益。[原论文](https://arxiv.org/abs/2203.11171)

## 14.32 Training Verifiers 与 GSM8K：结果监督的力量和盲区

Training Verifiers 研究用结果验证器从多个候选解答中选出较可靠答案；GSM8K 提供可核对的小学数学应用题数据集，便于研究多步推理。验证器准确率和题集覆盖决定结论范围，GSM8K 不能代表高级数学或开放域业务推理。[验证器论文](https://arxiv.org/abs/2110.14168)、[GSM8K 数据集](https://github.com/openai/grade-school-math)

## 14.33 Tree of Thoughts：从单链生成到状态搜索

Tree of Thoughts 将中间思路表示为可扩展和筛选的搜索状态，并在若干规划/谜题任务上研究搜索预算的作用。收益来自候选扩展与评估，代价和失败受状态表示、剪枝、评估器误差及调用预算影响。[原论文](https://arxiv.org/abs/2305.10601)

## 14.34 CLIP：用自然语言监督视觉表示

CLIP 用大规模图文对比学习把图像与文本映射到共享表示空间，并报告跨多个视觉数据集的 zero-shot 迁移。结果依赖预训练数据、类别命名和 prompt；共享语义表示不等于精确区域理解或所有语言上的均衡表现。[原论文](https://arxiv.org/abs/2103.00020)

## 14.35 ViT：把图像切成 token

Vision Transformer（ViT）将图像 patch 投影成序列 token，再由 Transformer 编码。论文展示了大规模预训练条件下的视觉迁移效果，也说明数据规模和归纳偏置会影响 ViT 与 CNN 的相对表现。[原论文](https://arxiv.org/abs/2010.11929)

## 14.36 Latent Diffusion：把扩散过程移到压缩空间

Latent Diffusion Models（LDM）先把图像压到 latent 空间，再执行扩散去噪，并用 cross-attention 接入文本等条件，以降低高分辨率生成成本。压缩损失、采样步数、条件控制和具体 checkpoint 都会影响结果；论文方法、Stable Diffusion checkpoint 与社区插件应分开看。[原论文](https://arxiv.org/abs/2112.10752)

## 14.37 Whisper：弱监督语音任务的统一接口

Whisper 使用大规模弱监督音频文本数据训练统一的语音识别与翻译模型，并在多项公开任务上报告 zero-shot 结果。部署表现仍需按语言、口音、噪声、专名、切片策略和端到端延迟实测。[原论文](https://arxiv.org/abs/2212.04356)

## 14.38 Red Teaming Language Models：把安全失败变成实验对象

Perez 等人研究用语言模型生成红队提示，并通过评估流程发现模型有害响应；它提供了扩展风险搜索样本的方法，不是完整安全验收。更早的[Concrete Problems in AI Safety](https://arxiv.org/abs/1606.06565)则整理了若干具体安全问题，为风险分类提供背景。测试结论必须绑定攻击目标、预算、模型和工具权限。[Red Teaming 原论文](https://arxiv.org/abs/2202.03286)

## 14.39 ROME 与 MEMIT：修改参数化知识的研究路线

ROME 研究通过定位因果层并做 rank-one 权重更新修改特定事实关联；MEMIT 将编辑扩展到多个事实。编辑集成功不等于知识库级可靠更新，还需检查别名泛化、无关知识保留、安全行为、冲突累积和编辑后可审计性。[ROME](https://arxiv.org/abs/2202.05262)、[MEMIT](https://arxiv.org/abs/2210.07229)

## 14.40 Transformer Circuits 与机制解释性

Transformer Circuits 提供从 attention、MLP、残差流和特征回路研究模型机制的框架；IOI circuit 工作分析 GPT-2 small 上特定间接宾语任务的回路。此类局部因果证据不自动推广到更大模型、其他任务或完整行为解释。[机制框架](https://transformer-circuits.pub/2021/framework/index.html)、[IOI circuit 研究](https://arxiv.org/abs/2211.00593)

## 14.41 Agent 评估论文：从静态答案到环境闭环

SWE-bench 在代码仓库任务中检查补丁是否解决 issue；WebArena 在模拟网站中检查页面/数据库状态变化；OSWorld 在桌面应用任务中检查环境最终状态。它们的环境、工具、任务和验收器不同，成功率不能直接互排；线上迁移还需报告权限、版本、超时、工具故障和人工回滚条件。[SWE-bench](https://arxiv.org/abs/2310.06770)、[WebArena](https://arxiv.org/abs/2307.13854)、[OSWorld](https://arxiv.org/abs/2404.07972)

## 14.42 按研究问题横向比较

论文条目回答“这项工作改变什么”；方法之间的机制、条件和取舍比较，集中放在[第 15 章《方法比较与工程取舍》](15-面试高频对比表.md)。长序列注意力、位置编码、RAG 与微调、后训练、Agent 评估等问题均可从该章对应主题进入，避免把不同任务、模型和预算的论文分数排成一张榜。

## 14.43 论文谱系中的继承、修正与替代

研究路线通常是局部改动和约束重分配，不是新论文让旧论文整体失效：FlashAttention 改变 attention 的执行效率，GQA 改变缓存结构，二者可以叠加；DPO 改变离线偏好优化路径，不消除环境反馈的需要；RAG 增加外部知识入口，不替代模型参数和上下文推理。阅读新工作时先指出它接续的旧问题、改动的具体环节和仍未解决的限制。

## 14.44 可复核的论文记录

书面记录至少保留：研究问题与基线、实际改动、模型/数据/版本/评测与预算、作者报告的结果和局限、关键消融、后续工作的关系，以及复现状态。缺少来源或条件的字段标为未知，不用宣传性总结补齐。详细记录方法见[第十册第 3—6 章](../../book-10-paper-reproduction-research/chapters/03-如何判断论文贡献.md)。

## 14.46 官方接口与协议资料（非论文）

论文研究工具使用的学习机制；接口文档描述特定产品的调用流程；协议规范定义参与方之间的互操作契约，三者不能混作同一种证据。

- [OpenAI API function calling 指南](https://developers.openai.com/api/docs/guides/function-calling)：当前文档展示应用提供工具、接收模型调用、在应用侧执行、回传结果的多步流程。具体 API 字段会随产品版本变化。
