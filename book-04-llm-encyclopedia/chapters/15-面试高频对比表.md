# 第 15 章 方法比较与工程取舍

比较两个方法，真正困难的地方不在于列出它们的定义，而在于判断它们是否在解决同一个问题。AdamW 和 FlashAttention 不属于同一层，LoRA 和量化也不属于同一层；把它们都放进“谁更好”的问题里，结论必然失真。

一个可靠的比较要先固定对象和约束：任务是什么，输入长度多大，模型规模多少，训练还是推理，硬件是什么，延迟和成本上限是多少，质量用什么指标，失败的代价是什么。之后再问方法改变了哪一层，以及它把多少资源从一个位置转移到了另一个位置。

本章把常见比较关系拆成独立主题。每节先说明共同问题，再解释机制差异；公式只表达关键数量关系，变量会在正文中定义；代码是无外部依赖的教学实验。表格可以帮助快速定位，但不能代替数据切片、消融、失败分析和目标系统实测。

## 15.1 比较的第一原则：先固定问题和账本

### 同一个指标不等于同一个任务

两个模型都得到 85% 的准确率，并不意味着它们能力相同。一个可能是在短文本分类上测得的，另一个可能是在长上下文、工具调用或代码执行上测得的。即使数据集名称相同，提示模板、答案抽取、采样次数和评估脚本不同，也会改变结果。

比较前至少需要记录：

- 输入分布、长度、语言和用户切片；
- 模型参数量、激活参数量、上下文长度和版本；
- 训练 token、微调数据、解码配置和候选预算；
- GPU、显存、batch、并发、kernel 和软件版本；
- 质量、延迟、吞吐、显存、成本和安全指标；
- 失败是否可逆，以及错误会不会作用于外部系统。

### 质量和成本同时写

设方案 A 和方案 B 的质量为 QA、QB，单位请求成本为 CA、CB，延迟为 TA、TB。比较不能只看：

~~~math
\Delta Q=Q_A-Q_B
~~~

还要记录：

~~~math
\Delta C=C_A-C_B,
\qquad
\Delta T=T_A-T_B
~~~

当质量差异和成本差异都存在时，可以画出 Pareto 前沿：如果一个方案在质量、延迟和成本上都不如另一个方案，它被支配；如果它用更高成本换来更高质量，就需要结合业务价值决定是否值得。

### 机制、代价和失败模式

一个完整的比较至少回答五个问题：

1. 两种方法共同解决什么旧问题；
2. 它们在数据流、参数、计算或权限上的机制差异是什么；
3. 质量、显存、延迟、工程复杂度分别发生了什么变化；
4. 哪些输入或部署条件会让优势消失；
5. 如何用反事实、消融和线上切片验证判断。

如果只说“B 更先进”，读者无法知道换了硬件、数据、预算之后结论是否仍成立。

## 15.2 Adam 与 AdamW：权重衰减放在哪里

### Adam 的自适应更新

Adam 为每个参数维护一阶矩和二阶矩。省略偏置修正时，梯度 gt 的更新可写为：

~~~math
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t
~~~

~~~math
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
~~~

~~~math
\theta_{t+1}
=
\theta_t-\eta
\frac{m_t}{\sqrt{v_t}+\epsilon}
~~~

θ 是参数，η 是学习率，β1 和 β2 是矩估计的衰减系数，ε 防止除零。Adam 的每个参数都有自己的有效步长，因此把 L2 正则直接加到梯度中时，正则项也会被二阶矩缩放。

### AdamW 的解耦衰减

AdamW 把衰减从梯度自适应项中拿出来：

~~~math
\theta_{t+1}^{\mathrm{AdamW}}
=
(1-\eta\lambda)\theta_t
-\eta\frac{m_t}{\sqrt{v_t}+\epsilon}
~~~

λ 是 weight decay 系数。这个更新让参数衰减的作用更直接，不会因为不同参数的 v_t 不同而被不均匀地重塑。

这不意味着 AdamW 在所有数据和任务上都必然更好。真正影响结果的还有学习率、warmup、decay 系数、参数分组、是否衰减 bias/normalization 参数和训练步数。公平比较需要固定超参数搜索预算，否则“优化器比较”可能只是“谁调得更充分”的比较。

### 一个最小更新实验

~~~python
import math
from numbers import Real


def _finite(value):
    if isinstance(value, bool) or not isinstance(value, Real):
        return False
    try:
        return math.isfinite(float(value))
    except (TypeError, OverflowError):
        return False


def _validate_optimizer_args(theta, moment, square, grad, lr, beta1, beta2, eps, decay=0.0):
    if not all(_finite(value) for value in (theta, moment, square, grad, lr, beta1, beta2, eps, decay)):
        raise ValueError("optimizer inputs must be finite real numbers")
    if lr <= 0 or not 0 <= beta1 < 1 or not 0 <= beta2 < 1 or eps <= 0 or decay < 0:
        raise ValueError("invalid optimizer hyperparameters")
def adam_step(theta, moment, square, grad, lr, beta1, beta2, eps):
    _validate_optimizer_args(theta, moment, square, grad, lr, beta1, beta2, eps)
    moment = beta1 * moment + (1.0 - beta1) * grad
    square = beta2 * square + (1.0 - beta2) * grad * grad
    update = lr * moment / (square ** 0.5 + eps)
    return theta - update, moment, square


def adamw_step(theta, moment, square, grad, lr, beta1, beta2, eps, decay):
    _validate_optimizer_args(theta, moment, square, grad, lr, beta1, beta2, eps, decay)
    moment = beta1 * moment + (1.0 - beta1) * grad
    square = beta2 * square + (1.0 - beta2) * grad * grad
    update = lr * moment / (square ** 0.5 + eps)
    decayed_theta = (1.0 - lr * decay) * theta
    return decayed_theta - update, moment, square


adam_theta, _, _ = adam_step(1.0, 0.0, 0.0, 0.5, 0.1, 0.9, 0.999, 1e-8)
adamw_theta, _, _ = adamw_step(
    1.0, 0.0, 0.0, 0.5, 0.1, 0.9, 0.999, 1e-8, 0.1
)
print(round(adam_theta, 4), round(adamw_theta, 4))
try:
    adam_step(1.0, 0.0, 0.0, 0.5, 0.0, 0.9, 0.999, 1e-8)
except ValueError:
    print("invalid learning rate rejected")
else:
    raise AssertionError("invalid learning rate was accepted")
~~~

这个实验只展示更新位置的差异，不包含 bias correction、参数组和真实训练。它适合帮助读者检查实现，而不是证明某个优化器在目标任务上更优。

## 15.3 SGD 与 Adam：统一步长和自适应步长

SGD 的基本更新是：

~~~math
\theta_{t+1}=\theta_t-\eta g_t
~~~

加入 momentum 后，还会累积历史梯度。它的优点是状态简单、额外显存小，有时具有较好的泛化行为；代价是对学习率、schedule 和梯度尺度更敏感。

Adam 为每个参数估计梯度的尺度，通常在训练初期更容易获得稳定下降，尤其适合稀疏梯度、不同层梯度尺度差异很大的模型。代价是需要保存一阶和二阶状态，优化器显存可能接近甚至超过参数本身。

大模型预训练常用 AdamW，不是因为 SGD 在理论上不能训练 Transformer，而是因为超大模型的优化曲面、训练稳定性和 warmup 习惯让自适应方法更容易作为强基线。视觉模型或某些大规模监督任务中，SGD 仍可能有竞争力。

比较时要同时观察训练 loss、最终任务、总优化器状态显存、收敛步数和超参搜索成本。若只看前几千步的 loss，可能把“早期收敛快”误认为“最终泛化更好”。

## 15.4 BatchNorm 与 LayerNorm：统计量沿哪条轴计算

BatchNorm 依赖 batch 统计量，对一个特征通道在 batch 或空间维度上计算均值和方差。它在图像卷积网络中常见，因为 batch 结构相对稳定。

LayerNorm 则对单个样本的 hidden 维度做归一化：

~~~math
\operatorname{LN}(x)
=
\gamma\odot
\frac{x-\mu(x)}
\sqrt{\operatorname{Var}(x)+\epsilon}
+\beta
~~~

对于每个 token 的向量，统计量不依赖其他样本，因此更适合变长序列、动态 batch 和自回归推理。

两者的主要差异不是“一个新一个旧”，而是统计维度和部署假设不同。BatchNorm 在小 batch、分布变化、逐 token 解码时需要额外处理 running statistics；LayerNorm 每次直接使用当前样本的 hidden 值，代价是对每个 token 做归约。

在多模态模型或视觉语言模型中，两种归一化都可能出现：视觉 encoder 可能采用 BatchNorm 或 LayerNorm，语言 decoder 可能采用 LayerNorm/RMSNorm。不能根据整个系统的输入模态直接推断归一化类型。

## 15.5 LayerNorm 与 RMSNorm：中心化是否值得

LayerNorm 先减均值，再除以标准差；RMSNorm 只控制均方根尺度：

~~~math
\operatorname{RMSNorm}(x)
=
\gamma\odot
\frac{x}
\sqrt{\frac{1}{d}\sum_{j=1}^{d}x_j^2+\epsilon}
~~~

d 是 hidden 维度，γ 是可学习的缩放参数。RMSNorm 少了一次均值中心化和相关计算，在现代 LLM 中常能提供足够稳定的训练。

选择 RMSNorm 的理由通常是计算路径简单、残差结构配合自然和经验质量足够，而不是它在所有网络上都严格优于 LayerNorm。某些任务需要中心化带来的优化性质，或已有 checkpoint 的归一化结构不能随意替换。

比较时应固定初始化、残差顺序、学习率和 epsilon。把一个已经训练好的 LayerNorm 模型直接改成 RMSNorm，不是公平的结构消融，因为参数分布和训练动态都已经改变。

## 15.6 Pre-Norm 与 Post-Norm：残差路径如何传梯度

Post-Norm 的典型形式是：

~~~math
x_{l+1}
=
\operatorname{Norm}
\left(
x_l+F_l(x_l)
\right)
~~~

Pre-Norm 则是：

~~~math
x_{l+1}
=
x_l+F_l(\operatorname{Norm}(x_l))
~~~

xl 是第 l 层输入，Fl 是 attention 或 FFN 子层。Pre-Norm 给残差流保留了更直接的恒等路径，深层训练往往更容易稳定；Post-Norm 的归一化位置不同，可能具有不同的表示和最终优化性质。

现代大模型多采用某种 Pre-Norm 或其变体，但这并不意味着“Pre-Norm 永远正确”。超深网络还可能使用额外的 residual scaling、初始化、NormFormer 或 sandwich norm。比较时要一起记录深度、初始化、学习率 warmup、最终 loss 和梯度范数。

## 15.7 BERT 与 GPT：理解式编码和生成式建模

BERT 使用 encoder-only 和 masked language modeling，输入中的 token 可以同时利用左右上下文；GPT 使用 decoder-only 和 causal language modeling，第 t 个位置只能读取 t 之前的内容。

这导致两条路线适合不同接口。BERT 的输出是整段输入的表示，适合分类、检索、实体识别和 embedding；GPT 的输出是逐 token 的概率分布，适合对话、代码、长文本和工具调用。

两者不能简单用某个 benchmark 分数比较，因为任务头和训练目标不同。若任务需要为每个 token 生成后续文本，BERT 的双向编码并不会直接提供自然的自回归接口；若任务只需要快速得到句向量，使用大型 decoder-only 模型可能浪费计算。

近年来 decoder-only 模型也可以通过 prompt 完成分类和抽取，encoder 模型也可以被扩展为生成式结构，但这改变了模型和部署成本。架构选择仍应从输出形式、延迟、上下文共享和数据规模出发。

## 15.8 Encoder-Decoder 与 Decoder-Only：两种条件生成组织方式

Encoder-decoder 把输入先编码成双向表示，再由 decoder 生成输出。输入长度和输出长度在结构上分开，翻译、摘要和条件改写很自然。

Decoder-only 把输入、指令和输出放在同一个 causal 序列中，用统一的 next-token loss 训练。它的优势是架构简单、预训练目标统一、in-context learning 和对话模板容易扩展。

Encoder-decoder 的 cross-attention 让 decoder 可以直接访问 encoder 表示；decoder-only 需要通过上下文 token 和 causal attention 访问输入。前者可能在某些长输入短输出任务上更高效，后者则更容易把预训练、对话、代码和工具轨迹统一到一个接口。

“通用大模型普遍采用 decoder-only”是生态事实，不是理论定理。文本到文本、语音转文本和某些结构化转换仍然可以从 encoder-decoder 中获益；选择要结合序列长度、输出长度、预训练数据和服务架构。

## 15.9 MHA、MQA 与 GQA：质量换 KV Cache

Multi-Head Attention 为每个 query head 保存独立的 K/V；Multi-Query Attention 让所有 query head 共享一组 K/V；Grouped-Query Attention 则让一组 query head 共享一组 K/V。

若 batch 为 B、层数为 N、缓存长度为 L、KV head 数为 Hkv、head 维度为 dh、元素字节数为 b，粗略 KV cache 大小为：

~~~math
M_{\mathrm{KV}}
\approx
2BNLH_{\mathrm{kv}}d_hb
~~~

2 表示 key 和 value。MHA 取 Hkv=Hq，MQA 取 Hkv=1，GQA 位于两者之间。GQA/MQA 减少缓存容量和 decode 带宽，但共享过多可能损失注意力表达能力。

这不是只在模型结构表里出现的差异。KV head 数会直接影响并发上限、长上下文可用长度和 paged cache 的物理块数量。比较时要固定模型质量、上下文长度、batch、量化格式和 kernel；否则“GQA 更快”可能只是因为它使用了不同的 batch。

## 15.10 Absolute Position、RoPE 与 ALiBi：顺序信息的三种注入

Absolute position 通常为每个位置学习或计算一个独立向量，再与 token 表示相加。它直观，但超过训练位置表或训练分布后，外推能力需要额外设计。

RoPE 对 Q/K 子空间施加位置相关旋转，使内积带有相对位置关系。ALiBi 则直接在 attention score 上加入距离偏置：

~~~math
s_{ij}
=
\frac{q_i k_j^{\mathsf T}}{\sqrt{d}}
-m_h|i-j|
~~~

d 是 head 维度，mh 是第 h 个 head 的距离斜率。三种方法的差异是“改 token 表示”“改 Q/K 几何”还是“改 attention 分数”。

长上下文比较不能只看最大支持长度。应观察训练长度与推理长度的比例、首尾检索、位置中间的证据利用、不同语言、短上下文质量和 KV cache 行为。窗口声明不等于有效使用能力。

## 15.11 ReLU、GELU 与 SwiGLU：FFN 的非线性和门控

ReLU 是：

~~~math
\operatorname{ReLU}(x)=\max(0,x)
~~~

GELU 使用平滑的概率式门控，SwiGLU 则把一个分支作为门控：

~~~math
\operatorname{SwiGLU}(x)
=
\operatorname{Swish}(xW_g)
\odot
(xW_u)
~~~

Wg 和 Wu 是两组投影，⊙ 是逐元素乘法。门控结构让 FFN 可以根据输入选择性地传递信息，通常需要重新设计中间维度以保持相近参数量和 FLOPs。

比较激活函数时要固定 FFN 中间维度、总参数、训练 token 和优化器。若 SwiGLU 模型同时更宽、训练更久，那么不能把全部提升归因于激活函数。实际选择还受 kernel、权重布局和量化支持影响。

## 15.12 SFT、RLHF 与 DPO：后训练的三个层次

SFT 使用高质量示范，学习条件分布：

~~~math
\mathcal{L}_{\mathrm{SFT}}
=
-\sum_t m_t
\log p_{\theta}(y_t\mid x,y_{<t})
~~~

mt 是 assistant token mask，避免把用户输入当成需要预测的目标。SFT 擅长模仿格式、风格和任务流程，但上限受示范数据覆盖影响。

RLHF 先从偏好比较训练 reward model，再用强化学习优化 policy。它可以表达有用性、风格和安全等难以写成固定标签的目标，但训练链路复杂，reward hacking 和策略不稳定需要额外控制。

DPO 直接从 chosen/rejected 对优化 policy，省掉显式 reward model 和 PPO 的一部分复杂度。它更适合离线偏好数据；长期工具任务和可验证环境仍可能需要在线反馈或 verifier。

三者不是互斥的替代关系。常见流程是 SFT 先让模型学会任务格式，再使用 DPO、RLHF、RLAIF 或 RLVR 改善偏好、安全和推理。比较时要区分“会做任务”“回答更讨喜”“结果可验证”和“真实行动成功”。

## 15.13 RLHF 与 DPO：在线策略优化和离线偏好优化

RLHF 的奖励模型可表示为对两个回答的偏好概率：

~~~math
P(y_w\succ y_l\mid x)
=
\sigma\left(r_{\phi}(x,y_w)-r_{\phi}(x,y_l)\right)
~~~

rφ 是 reward model。训练 policy 时还要处理 KL、采样分布和策略更新。

DPO 将偏好关系转化为相对 log-prob 目标：

~~~math
\mathcal{L}_{\mathrm{DPO}}
=
-\log\sigma
\left(
\beta
\left[
\log\frac{\pi_{\theta}(y_w\mid x)}
{\pi_{\mathrm{ref}}(y_w\mid x)}
-
\log\frac{\pi_{\theta}(y_l\mid x)}
{\pi_{\mathrm{ref}}(y_l\mid x)}
\right]
\right)
~~~

RLHF 的优势是可以在 policy 改变后继续采样，探索当前模型分布；代价是训练复杂和 reward model 可能被钻漏洞。DPO 的优势是简单、稳定、容易重跑；代价是离线数据覆盖不了的新行为不会被主动探索。

因此，偏好数据充足、任务主要是离线回答时，DPO 常更省工程成本；需要长期行动、环境反馈和稀疏奖励时，RLHF 或其他在线方法可能更合适。

## 15.14 RLHF 与 RLAIF：反馈来源不同，监督风险仍在

RLHF 使用人类比较，RLAIF 使用 AI judge、规则或原则生成反馈。人类反馈更接近产品真实偏好，但成本高、速度慢、标注一致性有限；AI feedback 覆盖大、成本低，却可能继承评价模型偏差和被评价模型的盲点。

如果 AI judge 对高风险样本的漏判率为 q，扩大样本数量不会自动降低这类系统性错误。应该保留人工金标准集，按语言、风险等级、长度和任务切片测量：

~~~math
\operatorname{FNR}_{\mathrm{AI}}
=
\frac{FN_{\mathrm{AI}}}
{TP_{\mathrm{AI}}+FN_{\mathrm{AI}}}
~~~

RLAIF 更适合生成原则性安全样本、长文本批评和低风险初筛；高影响发布决策仍需要人工或可执行验证器。两种反馈可以组合，而不是把 AI feedback 当成廉价真值。

## 15.15 Top-k 与 Top-p：限制采样候选集的两种方式

设 logits 为 zi，温度为 T，softmax 概率为：

~~~math
p_i^{(T)}
=
\frac{\exp(z_i/T)}
{\sum_j\exp(z_j/T)}
~~~

Top-k 保留概率最高的固定 k 个 token；top-p 先排序，再保留累计概率达到 p 的最小集合。前者控制候选数量，后者控制候选质量的总概率。

当分布很尖锐时，top-p 的候选可能很少；当分布很平坦时，候选会自动扩大。top-k 在不同上下文下的随机性范围更固定，top-p 对 logits 形状更自适应。

两者都可能破坏结构化输出：只要合法 token 被截掉，JSON、代码或函数参数就可能无法继续。因此结构化生成通常还需要 grammar constraint、schema mask 或专用解码器，而不是只调 k 和 p。

## 15.16 Temperature 与 Top-p：改变分布还是裁剪分布

Temperature 作用在 softmax 前，改变整个概率分布的尖锐程度；top-p 作用在排序和截断阶段，删除低概率尾部。低温通常提高确定性，高温提高候选多样性；top-p 则控制保留下来的概率质量。

如果先把温度调得很低，再设置很高的 top-p，后者可能几乎没有作用；如果温度很高，top-p 仍可能保留大量候选。二者不是两个独立旋钮，实验时应记录组合而不是分别比较。

对于代码、函数调用和数字抽取，优先固定随机性、使用较窄的候选并增加语法约束；对于创意写作，可以增加温度或 top-p，但仍要监控重复、事实性和有害内容。

## 15.17 Greedy、Beam Search 与 Sampling：序列目标怎样被搜索

Greedy 每一步选择当前最大概率 token：

~~~math
\hat{x}_t
=
\arg\max_{x_t}
p(x_t\mid x_{<t})
~~~

它速度快且可复现，但只优化局部选择，不保证完整序列概率最优。

Beam search 保留 b 条候选序列，扩展后再按累计 log-prob 排序。它适合翻译等相对确定的条件生成，但在开放式对话中可能偏向高概率套话、重复和长度偏差。

Sampling 按概率随机选择 token，能够得到多个不同候选，更适合创意文本、self-consistency 和候选生成；代价是方差、不可复现和安全评估复杂。

解码策略不能脱离任务。一个模型在代码修复中可能需要确定性和语法约束，在故事生成中需要多样性，在数学推理中需要多候选加 verifier。比较时应测质量、重复率、pass@k、成本和跨次稳定性。

## 15.18 LoRA 与全量微调：更新多少参数

全量微调更新整个 W，表达能力和可塑性最大，但显存、优化器状态和 checkpoint 存储都高；数据量有限时还可能遗忘基础能力。

LoRA 只学习低秩更新：

~~~math
W'=W+\frac{\alpha}{r}BA
~~~

r 是 rank，A 和 B 的参数量为 r(din+dout)，远小于 doutdin。它适合领域风格、格式、轻量任务适配和多个 adapter 共享同一基座。

当任务需要改变大量知识、底层推理能力或多个层的行为时，低 rank 可能成为瓶颈。LoRA 也会引入 adapter 加载、合并、路由和多租户隔离问题。选择不能只看训练显存，还要看质量上限、部署切换、长期维护和安全回归。

## 15.19 LoRA、Adapter 与 Prefix Tuning：改权重、加模块还是改上下文

LoRA 将更新限制在权重低秩子空间；Adapter 在 Transformer 层之间插入小网络；Prefix Tuning 学习虚拟 token 或可训练的 KV 前缀。

三者对基础模型的侵入位置不同：

| 方法 | 主要改变 | 推理影响 | 常见优点 |
| --- | --- | --- | --- |
| LoRA | 权重更新方向 | 可合并，运行时开销小 | 训练和部署生态成熟 |
| Adapter | 层间小模块 | 可能增加计算路径 | 模块化、可组合 |
| Prefix Tuning | 输入或 KV 前缀 | 占用上下文或缓存 | 参数很少，适合条件控制 |

Prefix 的参数少不代表任务表达能力无限；Adapter 的模块化也不代表多个模块可以无冲突叠加。比较时应测任务质量、基座保留、多个任务并存、切换延迟和 adapter 间干扰。

## 15.20 Quantization 与 Distillation：压数值还是压能力

量化把权重、激活或 KV cache 从高精度表示映射到低比特表示：

~~~math
\hat{w}
=
s\left(
\operatorname{clip}
\left(
\operatorname{round}\left(\frac{w}{s}\right)+z
\right)
-z
\right)
~~~

s 是 scale，z 是 zero point。量化通常保留模型结构，但降低存储、带宽和部分计算成本。

蒸馏使用教师模型产生 logits、答案、偏好或过程标签，让更小的学生模型学习教师行为。常见温度蒸馏项为：

~~~math
\mathcal{L}_{\mathrm{KD}}
=
T^2
\operatorname{KL}
\left(
p_{\mathrm{teacher}}^{(T)}
\parallel
p_{\mathrm{student}}^{(T)}
\right)
~~~

T 是蒸馏温度。蒸馏改变模型结构和能力分布，量化主要改变数值表示；二者可以组合，但误差也可能叠加。

如果模型结构已经合适、主要瓶颈是显存和带宽，量化通常更直接；如果需要更低的算力、延迟和部署体积，蒸馏可能更有价值。两种方法都要在真实任务和长尾样本上检查能力回归。

## 15.21 PTQ 与 QAT：什么时候让模型适应量化误差

Post-Training Quantization 在训练完成后量化，通常只需要校准数据，成本低、部署快；Quantization-Aware Training 在训练中模拟舍入和低精度误差，让参数适应量化。

PTQ 适合已有 checkpoint、快速试验和量化误差较小的模型。它容易在 activation outlier、长上下文、代码、数学和多模态视觉 token 上出现局部退化。

QAT 可以恢复部分精度，但需要重新训练、保存量化配置和维护额外的训练路径。它也不保证目标硬件上的 kernel 一定支持对应格式。

比较 PTQ 与 QAT 时要报告校准数据、比特宽度、权重/激活/KV 是否量化、训练步数、最终质量和端到端速度。只写“QAT 精度更高”忽略了它的训练成本。

## 15.22 FP16 与 BF16：尾数精度和指数范围

FP16 与 BF16 都使用 16 bit，但位分配不同。FP16 有更多尾数位，指数范围较小；BF16 的指数范围接近 FP32，能表达更大的数值范围，但尾数精度更低。

大模型训练常偏好 BF16，因为梯度和激活更不容易溢出，通常少依赖复杂 loss scaling。FP16 在支持良好的硬件上仍然有效，但更需要检查溢出、下溢和归约精度。

位宽相同不代表性能相同。矩阵乘、归约、通信、optimizer state、显存带宽和 kernel 支持共同决定端到端结果。应测训练稳定性、吞吐、峰值显存和最终任务，而不是只比较理论位数。

## 15.23 FlashAttention 与 Sparse Attention：优化实现还是改变连接图

FlashAttention 计算标准 exact attention，通过 tiling 和 online softmax 减少 HBM 读写；Sparse Attention 只计算预先选择的局部、全局或块状连接，改变了 attention graph。

因此二者可以组合。稀疏 attention 减少理论上需要计算的 token pair，FlashAttention 可以把剩下的密集块算得更高效。前者牺牲或限制部分连接，后者主要改变 kernel 和内存访问。

Sparse Attention 在长上下文中可能降低复杂度，但如果关键证据落在被剪掉的连接之外，质量会下降；FlashAttention 不会解决二次连接数量，只会降低其实现成本。评估必须包含检索、长距离依赖、随机位置和不同 mask，而不是只测短序列吞吐。

## 15.24 PagedAttention 与 FlashAttention：缓存管理和算子实现

FlashAttention 关注一次 attention 运算如何读取 tile、计算 softmax 和写回结果；PagedAttention 关注多个请求的 KV cache 如何分配、映射、共享和释放。

二者处于不同层，可以同时使用：

~~~math
\operatorname{KVBytes}
\approx
2BLN H_{\mathrm{kv}}d_hb
~~~

PagedAttention 通过 block table 管理 L 个 token 的缓存，FlashAttention 或其他 kernel 负责读取这些 block 并完成 attention。一个优化请求内存碎片，一个优化计算中的 IO。

如果只替换 FlashAttention，跨请求的 allocator 碎片和 prefix 生命周期可能仍是瓶颈；如果只使用 PagedAttention，单次 kernel 的访存效率仍可能不足。系统 benchmark 需要分开报告 cache 命中、block 利用率、TTFT、TPOT、吞吐和 p99。

## 15.25 KV Cache 与 Activation Checkpointing：避免重算和主动重算

KV cache 是推理阶段的时间换空间：历史 token 的 key/value 保存下来，后续生成只计算新 token 的 query。其容量随层数、长度、KV head 数和 batch 增长。

Activation checkpointing 是训练阶段的空间换时间：前向只保存部分激活，反向时重新计算被丢弃的中间结果。它降低训练显存，但增加计算和可能的通信。

两者服务于相反的运行阶段：

| 机制 | 阶段 | 节省什么 | 增加什么 |
| --- | --- | --- | --- |
| KV cache | 自回归推理 | 历史 token 重算 | 显存、缓存管理和泄露边界 |
| Activation checkpoint | 训练反向 | 中间激活存储 | 重算 FLOPs 和训练时间 |

把二者都叫“缓存优化”会误导设计。一个需要严格的请求生命周期清理，另一个需要正确的随机状态、dropout 和反向重算。

## 15.26 Data、Tensor 与 Pipeline Parallel：沿哪条维度拆分

Data Parallel 让不同 rank 处理不同数据副本，同步梯度；Tensor Parallel 把一层中的矩阵或 attention head 切到多卡；Pipeline Parallel 把不同层放到不同 stage。

如果全局 batch 为 B、data parallel size 为 D、gradient accumulation 为 A、每个 rank 的 micro-batch 为 b，则常见关系是：

~~~math
B=D\cdot A\cdot b
~~~

Tensor Parallel 需要层内 all-reduce、all-gather 或 reduce-scatter，通信频率高但能放下单卡无法容纳的层。Pipeline Parallel 降低单卡参数容量，却出现 stage bubble；micro-batch 增加可以提高流水线填充，但会影响优化语义和激活占用。

真实训练通常组合三种并行，再加入 sequence/context parallel 或 expert parallel。比较时应分别计算参数显存、激活显存、通信量、bubble 比例和故障恢复复杂度。

## 15.27 DDP、ZeRO 与 FSDP：复制状态还是分片状态

DDP 每张卡保存完整模型、梯度和 optimizer state，通过 collective 同步梯度，工程简单、吞吐稳定，但当模型状态超过单卡显存时无法启动。

ZeRO 分阶段切 optimizer state、gradient 和 parameter；FSDP 以模块为单位分片参数，需要前向或反向时 all-gather，使用后释放。二者都以通信换显存，但 API、调度、checkpoint 和参数生命周期不同。

理想均匀切分下，持久状态占用可以近似从 S 降到 S/N，其中 S 是完整状态大小，N 是分片 rank 数；但实际峰值还包含 gather、prefetch、通信 buffer、梯度和碎片。

选择时要看模型能否单卡放下、网络带宽、参数访问粒度、checkpoint 需求、故障恢复和团队熟悉度。DDP 的简单有时比节省显存更有价值；FSDP/ZeRO 的省显存也会带来更复杂的调试和通信。

## 15.28 RAG 与 Fine-Tuning：知识访问还是行为改变

RAG 把文档放在外部索引中，查询时检索相关证据；fine-tuning 把任务模式、术语或部分知识写入模型参数。

如果知识经常更新、必须按权限访问、需要引用和删除，RAG 更容易审计和回滚。如果问题是模型不会输出固定格式、不会遵循内部流程或缺少领域表达，微调更直接。

两者也可以组合：微调模型学习如何读取和引用检索证据，RAG 提供最新事实。不能用微调替代一个需要每小时更新的数据库，也不能期待 RAG 自动修复模型不会执行的任务格式。

评估要分开测检索召回、证据支持、答案正确、更新延迟、数据权限和模型行为。一个微调模型在旧知识上准确，并不意味着它能回答新知识；一个 RAG 模型引用了文档，也不意味着结论真的被文档支持。

## 15.29 Dense Retrieval 与 Sparse Retrieval：语义相似和词项精确

Sparse retrieval 依赖倒排索引、词项匹配和 BM25 等统计信号，擅长数字、代码、专有名词和精确短语；dense retrieval 把 query 和 document 编成向量，擅长同义改写和语义相近表达。

Dense 检索可能忽略一个字符的型号差异，sparse 检索可能无法理解没有词项重合的改写。企业知识库常用 hybrid retrieval，把两个候选集合并后再重排。

比较时要分别测：

- 同义改写和跨语言召回；
- 数字、版本号、实体名和代码片段召回；
- 文档库增长后的索引成本；
- 过滤条件、权限和更新延迟；
- top-k 候选的证据支持率。

没有一种检索方式在所有数据上都优于另一种。检索器的目标通常是高召回，最终证据质量还需要 reranker 和上下文构造共同负责。

## 15.30 Retriever 与 Reranker：先扩大候选，再精排

Retriever 面向大规模文档库快速召回 top-k，通常使用向量、倒排或混合索引；reranker 对 query-document 对做更昂贵的交互建模，再把少量候选排序。

设正确证据在候选池中的概率为 Rretriever，reranker 在候选池内把正确证据排进最终 top-m 的概率为 Rreranker，则最终证据到达上下文的概率近似受两者共同限制：

~~~math
P(\text{evidence reaches context})
\approx
R_{\text{retriever}}
\cdot
R_{\text{reranker}\mid\text{retrieved}}
~~~

如果 retriever 没召回正确文档，reranker 无法凭空补救；如果候选很多但 reranker 错排，扩大 top-k 也可能增加噪声和成本。

排障时要记录召回阶段和精排阶段的 label。只看最终答案无法区分“没有找到证据”和“找到了但排序/生成失败”。

## 15.31 Long Context 与 RAG：容量和选择

长上下文让模型一次接收更多材料，适合完整审阅一份固定文档、保留长对话或合并多步工具结果；RAG 在生成前从大规模外部库中选择相关证据，适合动态知识和权限过滤。

长上下文的成本通常随输入 token 增长，且有效利用可能受 Lost in the Middle、注意力稀释、位置外推和上下文噪声影响。RAG 降低输入规模，却把错误转移到切块、召回、排序和权限过滤。

两者常常组合：RAG 先选择候选证据，长上下文再容纳证据、历史、工具状态和引用。选择指标包括：

~~~math
\operatorname{ContextCost}
\approx
N_{\text{input}}\cdot c_{\text{prefill}}
+
N_{\text{output}}\cdot c_{\text{decode}}
~~~

Ninput 和 Noutput 是 token 数，cprefill 和 cdecode 是对应单位成本。窗口更大不代表应该把所有材料都塞进去；应比较证据召回、回答支持、延迟和成本。

## 15.32 Agent 与 Workflow：动态决策和确定流程

Workflow 把步骤、分支和审批预先写出，状态可预期、审计容易、失败路径清晰；Agent 让模型在运行时决定下一步、工具和计划，适合任务结构不确定的场景。

Agent 的自由度带来状态漂移、循环、工具误用、提示注入和成本失控。Workflow 的限制则可能无法处理长尾和新任务。生产系统常把高影响关键路径固定为 workflow，把局部搜索、文本归类和候选生成交给模型。

判断一个系统是否值得 Agent 化，可以问：

1. 任务步骤是否稳定；
2. 每个动作能否定义输入和验收条件；
3. 错误是否可回滚；
4. 模型是否真的需要动态选择；
5. 动态自由度带来的收益是否超过验证和监控成本。

Agent 不是 workflow 的升级版本，而是把部分控制权从程序转给模型。控制权越多，越需要权限、预算、状态和人工接管。

## 15.33 Chain-of-Thought 与 Tool Use：内部推理和外部证据

CoT 通过额外 token 表示中间步骤，适合模型自身可以完成的逻辑分解；tool use 把计算、检索、代码执行、数据库查询或真实动作交给外部系统。

二者不是互斥的。模型可以先规划，再调用计算器，读取结果后继续生成；关键是区分内部推测和外部事实。实时价格、订单状态、复杂算术和代码测试不应只依赖模型生成的推理链。

工具调用增加了权限、延迟、失败和副作用，CoT 增加了 token 成本和潜在信息泄露。比较时要测答案正确、证据支持、工具成功、错误恢复、延迟和敏感内容暴露，而不是只看最终文本是否更长。

## 15.34 Human Evaluation 与 LLM-as-a-Judge：谁来判断开放式质量

人评能接近真实用户或领域专家判断，适合高影响、模糊和需要常识的任务，但成本高、速度慢、标注一致性和疲劳效应需要控制。

LLM-as-a-Judge 可以快速比较大量回答，适合回归、初筛和候选排序，但可能有长度偏好、位置偏好、模型自偏好、语言偏差和事实判断错误。

一个合理的评估链是：先用自动指标和 judge 扩大覆盖，再用人工金标准校准 judge，最后把分歧、高影响和新分布样本交给人工。应报告 judge 与人工的一致性、分歧切片和错误类型。

“judge 分数提升”不等于用户体验提升。长度、引用数量和格式都可能被评价器奖励，却没有提高事实性或任务成功。

## 15.35 Accuracy 与 Pass@k：一次正确还是候选中有一个正确

Accuracy 统计单次输出是否正确：

~~~math
\operatorname{Accuracy}
=
\frac{1}{N}\sum_{i=1}^{N}c_i
~~~

ci 是第 i 个样本的一次正确指示。Pass@k 关注生成 k 个候选时至少有一个通过测试。若一次采样 n 个候选，其中 c 个通过，常见无偏估计为：

~~~math
\operatorname{pass@}k
=
1-
\frac{\binom{n-c}{k}}{\binom{n}{k}}
~~~

Pass@k 更适合代码、数学和有执行验证的任务，但它依赖采样预算、候选多样性和测试覆盖。高 pass@k 可能隐藏单次成功率低、候选生成贵、选择器不会挑正确答案等问题。这里要求 `n>0`、`0≤k≤n` 且 `0≤c≤n`；没有候选或超出候选数时应报告 N/A，而不是用默认分母继续计算。

生产系统若只能给用户一个答案，应同时报告 pass@1、pass@k、候选成本、选择器准确率和端到端延迟。

## 15.36 Factuality 与 Grounding：真实和有证据不是一回事

Factuality 问输出在外部世界中是否真实；grounding 问输出是否由当前给定的文档、图像、音频或工具结果支持。

一个回答可能是事实正确但没有引用证据，也可能引用了相关文档却夸大了文档没有说的内容。RAG 系统需要分别测：

- 事实是否正确；
- 证据是否覆盖结论；
- 引用片段是否与结论对应；
- 不确定时是否明确降级；
- 外部知识和当前证据冲突时如何处理。

因此，引用存在不等于 grounding 成立，grounding 成立也不自动保证外部事实永久正确。

## 15.37 Robustness 与 Generalization：未见数据和扰动稳定

Generalization 关注训练分布到测试分布的迁移；robustness 更强调输入改写、噪声、格式变化、对抗提示、缺失字段和分布外条件下的稳定。

一个模型可以在同分布测试集上泛化良好，却因为换一种语言、插入无关文本或改变上下文顺序而失败。鲁棒性评估应设计受控扰动：

~~~math
\Delta_{\text{robust}}
=
u(x)-u(T(x))
~~~

T 是保持任务语义的扰动，u 是任务效用。理想情况下差值接近零，但不同扰动的可接受范围不同。

鲁棒性不是无限不变。对输入做强语义改变后，输出改变可能是正确的；因此测试集必须明确哪些字段应该保持不变，哪些字段应该触发不同决策。

## 15.38 Over-Refusal 与 Under-Refusal：安全边界两侧的错误

Under-refusal 是危险请求被放行，通常对应安全漏判；over-refusal 是正常或防御性请求被拒绝，通常对应可用性损失。两者分母不同：

~~~math
\operatorname{UnsafePassRate}
=
\frac{FN}{TP+FN}
~~~

~~~math
\operatorname{FalseRefusalRate}
=
\frac{FP}{TN+FP}
~~~

降低一个指标可能使另一个上升。正确的系统应根据风险等级分层回答：低风险直接帮助，有歧义先澄清，防御性任务提供安全替代，高影响动作停止或转人工。

只看拒答率会奖励过度保守；只看帮助率会掩盖危险漏放。评估还要包含语言、双重用途、用户授权、工具权限和多轮上下文。

## 15.39 Jailbreak 与 Prompt Injection：攻击模型策略还是污染数据边界

Jailbreak 通常由用户直接设计对话，试图让模型绕过安全策略；prompt injection 更广泛，尤其指外部文档、网页、邮件、代码注释或工具结果试图改变模型原任务。

两者都可能利用角色扮演、编码、上下文拼接和多轮诱导，但间接注入还需要处理数据流和执行器。一个系统即使模型被文档诱导，只要外部内容没有获得工具权限，攻击链仍可能在执行前停止。

因此防御分两层：模型策略、输入输出审核和对齐应降低文本层攻击成功；消息类型、taint、最小权限、参数校验和人工确认应限制系统层影响。单一关键词过滤无法替代边界和权限。

## 15.40 Helpful 与 Harmless：帮助不等于无条件满足

Helpful 关注用户任务是否被推进，Harmless 关注回答和行动是否会造成伤害。双重用途请求最能暴露冲突：网络安全、化学、生物、医疗、金融和法律问题都可能既有防御用途又有滥用路径。

系统不应把 harmless 简化成全量拒绝，也不应把 helpful 简化成提供所有执行细节。更细的响应可以是澄清授权、解释风险、提供防御性方法、给出沙箱实验或拒绝高风险动作。

比较两种策略时应同时看正常任务成功、过度拒答、危险漏放、安全替代质量和用户是否获得了可执行但合法的下一步。安全边界最终要落到工具权限和审计，而不仅是回答语气。

## 15.41 Dense Model 与 MoE：每个 token 使用多少参数

Dense 模型每个 token 经过所有层和全部 FFN 参数，结构简单、负载稳定、部署直接；MoE 拥有多个专家，每个 token 只路由到少数专家，激活计算小于总参数容量。

MoE 的路由概率可写成：

~~~math
p_t=\operatorname{softmax}(W_rh_t),
\qquad
e_t=\operatorname{TopK}(p_t)
~~~

ht 是 token 表示，Wr 是 router 参数，et 是被选择的专家集合。实际成本还包含专家容量、跨设备 all-to-all、负载均衡、溢出 token 和专家 checkpoint。

Dense 适合资源和延迟可预测、模型规模中等或硬件不适合动态路由的场景；MoE 适合用较大总容量换取每 token 较低激活计算，但通信和服务调度更复杂。

比较时至少报告 total parameters、active parameters、每 token FLOPs、通信量、专家负载分布、显存和尾延迟。MoE 的“激活参数少”不等于部署成本一定低。

## 15.42 一张比较表怎样写才不误导

表格适合放已定义的差异，不适合藏住未经说明的结论。一个可复用的结构是：

| 比较维度 | 方法 A | 方法 B | 仍需验证的条件 |
| --- | --- | --- | --- |
| 解决的问题 | 它首先优化什么 | 它首先优化什么 | 任务是否相同 |
| 主要机制 | 改数据、参数、连接或运行时 | 改数据、参数、连接或运行时 | 是否有额外预算 |
| 资源代价 | 显存、通信、延迟、人工成本 | 显存、通信、延迟、人工成本 | 硬件和并发 |
| 失败模式 | 哪些输入会失效 | 哪些输入会失效 | 是否可回滚 |
| 适用边界 | 适合什么 workload | 适合什么 workload | 线上切片是否一致 |
| 评估证据 | 用什么指标和对照 | 用什么指标和对照 | 分母、样本和版本 |

如果表格中的“更快”“更稳定”“更准确”没有对应的 workload 和测量口径，它们只是宣传词。正文应在表格之前解释机制，在表格之后说明如何验证。

## 15.43 资料与证据边界

本章的比较关系来自原始论文、官方文档和前面章节的系统实验。论文用于支持方法提出时的假设和实验；框架文档用于支持接口、实现和部署语义；教学代码只验证公式或局部逻辑；目标系统实测才可以支持当前版本的延迟、成本和失败率。

可继续阅读：

- [AdamW](https://arxiv.org/abs/1711.05101)、[LayerNorm](https://arxiv.org/abs/1607.06450) 与 [RMSNorm](https://arxiv.org/abs/1910.07467)：优化器和归一化；
- [RoFormer](https://arxiv.org/abs/2104.09864)、[ALiBi](https://arxiv.org/abs/2108.12409) 与 [GQA](https://arxiv.org/abs/2305.13245)：位置和注意力缓存；
- [DPO](https://arxiv.org/abs/2305.18290)、[InstructGPT](https://arxiv.org/abs/2203.02155) 与 [Constitutional AI](https://arxiv.org/abs/2212.08073)：后训练与反馈；
- [LoRA](https://arxiv.org/abs/2106.09685)、[QLoRA](https://arxiv.org/abs/2305.14314)：参数高效适配；
- [FlashAttention](https://arxiv.org/abs/2205.14135)、[PagedAttention](https://arxiv.org/abs/2309.06180) 与 [ZeRO](https://arxiv.org/abs/1910.02054)：系统效率；
- [RAG](https://arxiv.org/abs/2005.11401)、[ReAct](https://arxiv.org/abs/2210.03629) 与 [Toolformer](https://arxiv.org/abs/2302.04761)：检索和工具；
- [Pass@k](https://arxiv.org/abs/2107.03374)、[Tree of Thoughts](https://arxiv.org/abs/2305.10601) 与 [SWE-bench](https://arxiv.org/abs/2310.06770)：推理和 Agent 评估。

这些入口不是答案排名。比较某个当前模型或系统时，仍要重新记录版本、提示、数据、硬件、预算、人工流程和安全边界。

## 本章小结

方法比较的核心不是找到一个永远更优的选项，而是理解约束如何在系统中移动。AdamW 把衰减从自适应梯度中分离，RMSNorm 减少归一化路径，GQA 减少 KV head，LoRA 减少可训练更新，量化减少数值位宽，FlashAttention 减少内存 IO，PagedAttention 管理跨请求缓存，ZeRO/FSDP 用通信换状态显存，RAG 把知识放到外部索引，Agent 把部分控制权交给模型。

这些变化都伴随着新代价：质量回归、通信、缓存生命周期、数据新鲜度、工具副作用、评估器偏差或安全风险。真正可靠的结论必须同时说明机制、资源账本、失败模式、适用边界和验证方法。这样，比较表才是知识的入口，而不是把复杂问题压扁成一句“谁更好”。
