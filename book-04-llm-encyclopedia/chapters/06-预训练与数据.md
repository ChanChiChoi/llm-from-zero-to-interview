# F. 预训练与数据：从语料来源到可复现训练

## 阅读边界

预训练不是把一堆文本送进 GPU 就结束。模型从什么来源学习、哪些内容被过滤、不同语言和领域如何配比、评估集是否被污染、数据能否追溯和删除，都会改变最终模型。数据工程还必须和 tokenizer、sequence length、loss mask、训练 token、checkpoint 以及下游评估连接起来。

本章沿着一条真实的数据流水线展开：

~~~text
来源与许可
 -> 原始快照
 -> 解析与规范化
 -> 质量 / 隐私 / 安全过滤
 -> 去重与污染检测
 -> 语言 / 领域分桶
 -> mixture sampling
 -> packing 与训练样本
 -> 版本血缘与 manifest
 -> 训练、评估、checkpoint
~~~

全章分为十四个独立主题。每个主题都包含初学者视角、专家变量、公式、最小代码、失败边界和资料来源。这里的代码用于解释数据结构和统计口径，不代表生产级分布式数据平台。关于更完整的数据工程实现，可以继续阅读[第五册：大模型训练](../../book-05-llm-training/目录.md)和[第九册：数据工程](../../book-09-data-engineering/目录.md)。

## 6.1 预训练：把文本变成可优化的目标

### 预训练学什么

预训练通常以 causal language modeling 为目标。给定 token 序列 x_1,\ldots,x_T，模型在每个位置预测下一个 token：

~~~math
L_{\mathrm{pretrain}}
=-\frac{1}{N}
\sum_{t\in\mathcal{I}}
\log p_\theta(x_t\mid x_{<t}).
~~~

I 是有效 label 位置，N 是有效 token 数。模型参数通过这个目标学习语言模式、知识关联、代码结构、文档格式和任务线索。它不会自动区分“事实”“观点”“广告”和“恶意指令”，除非数据分布、过滤策略或后续训练让它学到这些区别。

### 一条预训练流水线

一个简化的离线到训练链路是：

~~~text
raw source
 -> parser
 -> normalized document
 -> quality / risk classifier
 -> exact and near dedup
 -> language/domain buckets
 -> tokenizer encode
 -> sequence builder
 -> training shard
 -> dataloader
 -> model loss
~~~

每一步都可能丢失信息或引入偏差。只保存最终 token shard 而不保存原文 id、过滤理由和 tokenizer 版本，之后很难解释一个能力或事故来自哪里。

### base model 是什么

预训练通常产出 base model。它更接近训练语料的文本分布，擅长续写、模式补全和上下文统计，但不一定稳定遵循指令，也不一定具备产品级安全和多轮对话行为。instruction tuning、偏好优化和安全训练是在这个底座上塑造交互方式，不能把两者混成同一个阶段。

### 预训练决策表

训练前至少要冻结或记录：

~~~text
tokenizer 与版本
模型参数和架构
训练 token 目标
数据来源和许可
质量与风险过滤
语言 / 领域配比
sequence length 与 packing
optimizer、learning rate、batch
并行策略与精度
验证集、污染检测和 checkpoint
~~~

“训练了多少 token”必须指 tokenizer 后、实际参与目标的 token，而不是网页字符数或文档条数。

## 6.2 语料来源、领域权威性与许可边界

### Web data 的价值和噪声

网页数据提供巨大的规模和主题覆盖，能让模型看到多语言、代码、问答、新闻、论坛和文档。但网页也包含 SEO 模板、自动生成垃圾、重复镜像、乱码、过期信息、隐私、秘密、恶意内容和版权风险。

网页采集不是单纯的爬虫问题。数据系统需要记录来源、采集时间、许可或服务条款边界、解析方式、删除策略和下游数据版本。技术上能访问某页面，不代表可以把页面用于训练。

### 专业数据

代码、数学、医疗、法律、金融、科研和企业文档具有不同质量标准：

~~~text
代码：许可证、secret、语法、依赖、测试和功能正确性
数学：题目来源、推导、答案、难度、重复和可验证性
医疗：指南版本、证据等级、隐私和专家审计
法律：法域、发布日期、修订状态、引用和适用范围
金融：时效、数据口径、权限和风险披露
企业文档：owner、版本、访问权限、失效日期
~~~

把这些数据混成一个 quality score 会掩盖领域差异。更稳妥的做法是先分桶，再在桶内制定质量与风险规则。

### Domain authority

领域权威性不是文本流畅度。一个专业来源应记录机构、作者、发布日期、更新日期、适用地区、引用、版本、撤回状态和审核责任人。高风险领域还要有专家抽检。权威性低的数据不一定必须全部删除，但应降权、隔离或限制用途，并在 manifest 中保留理由。

### 数据许可与使用范围

数据卡片至少需要说明：

~~~text
来源和采集时间
许可证 / 合作授权
允许的用途
再分发限制
个人信息和秘密处理
删除请求流程
训练、评估和展示的边界
~~~

模型卡不能替代数据许可证明；数据集能公开发布，也不表示训练出的模型可以无条件用于所有场景。

### Web-scale collection 的元数据

每个原始文档至少可关联：

~~~text
source_id
source_type
license_or_policy
source_uri_hash
crawl_time
content_hash
language
domain
parser_version
risk_flags
quality_score
dataset_version
delete_status
~~~

其中 URI hash 用于减少直接暴露来源地址，content hash 用于去重和追踪内容变更。真实平台可能需要额外保存加密映射和访问控制。

## 6.3 数据质量：有效信号密度而不是文本数量

### 质量的多维定义

高质量数据通常同时具有较高的可读性、信息密度、真实性、任务价值、多样性和风险可控性。一个长度很长的页面可能只有导航、模板和重复广告；一个短的单元测试可能对代码能力非常有价值。

可以把文档质量表示成一个向量，而不是单一分数：

~~~math
q(d)=
(q_{\mathrm{read}},
q_{\mathrm{info}},
q_{\mathrm{domain}},
q_{\mathrm{diversity}},
q_{\mathrm{risk}},
q_{\mathrm{authority}}).
~~~

最终保留规则可以是多目标约束，而不是简单取最高分：

~~~math
\operatorname{keep}(d)
=\mathbf{1}
\left[
q_{\mathrm{read}}\ge a
\land q_{\mathrm{risk}}\le b
\land q_{\mathrm{authority}}\ge c
\right].
~~~

阈值 a、b、c 应按语言、领域和用途校准。代码和数学不能直接套普通网页文本的阈值。

### 清洗步骤

典型清洗包括：

1. 解压、编码修复和格式解析。
2. HTML、PDF、OCR 或 notebook 正文抽取。
3. Unicode、空白和控制字符规范化。
4. 语言识别和领域分类。
5. 长度、乱码、重复行和模板页过滤。
6. PII、secret、恶意内容和许可证风险扫描。
7. 去重、版本关联和质量抽样。
8. 生成过滤理由与 lineage 记录。

清洗不是越激进越好。过度过滤会丢掉口语、代码、少数语言、数学符号和真实错误样本；过滤过弱则会把噪声和风险放大。

### Quality classifier

质量分类器可以从人工标注、规则标签或高质量参考集学习文本质量，但它会继承标注数据的偏好。若训练集主要是英文百科，分类器可能系统性低估论坛、口语、低资源语言或专业文本。

成熟做法是：

~~~text
按语言 / 领域分桶校准
保存分数和模型版本
抽样估计误删与漏删
比较过滤前后 token 分布
做小模型能力 ablation
监控来源和长尾覆盖
~~~

质量分类器是过滤流水线的一个信号，不是独立裁判。

### 信息密度与重复模板

可以观察 unique token ratio、重复句比例、链接比例、模板命中率、有效字符比例和困惑度等特征。困惑度过滤有用但不充分：高困惑度可能是乱码或罕见专业内容，低困惑度可能是大量模板和重复文本。特征必须和来源、语言、领域一起解释。

### 一个质量记录函数

~~~python
import math


def quality_record(text, language, domain, flags, score):
    if (not isinstance(text, str) or not text.strip()
            or not isinstance(language, str) or not language.strip()
            or not isinstance(domain, str) or not domain.strip()):
        raise ValueError("text, language and domain must be non-empty strings")
    if not isinstance(flags, (list, tuple)):
        raise TypeError("flags must be a list or tuple")
    if any(not isinstance(flag, str) or not flag.strip() for flag in flags):
        raise ValueError("flags must contain non-empty strings")
    if (isinstance(score, bool) or not isinstance(score, (int, float))
            or not math.isfinite(score) or not 0 <= score <= 1):
        raise ValueError("score must be a finite number in [0, 1]")
    return {
        "chars": len(text),
        "language": language,
        "domain": domain,
        "risk_flags": sorted(set(flags)),
        "quality_score": float(score),
        "keep_candidate": not flags and score >= 0.6,
    }


print(quality_record("short example", "en", "general", [], 0.82))
~~~

这个函数只展示记录结构。生产系统需要保存 classifier version、阈值、抽样结果和变更原因，不能用一个 0.6 作为跨领域通用标准。

## 6.4 去重、相似文档与 Benchmark Contamination

### 为什么要去重

重复文本会浪费训练计算，增加模型记忆训练样本的概率，并让评估集更容易被污染。重复可能来自同一页面镜像、引用转载、代码 fork、模板页、翻译版本、近似题目和自动生成变体。

### Exact deduplication

精确去重可以对规范化后的文档计算 hash：

~~~math
h(d)=\operatorname{Hash}(\operatorname{Normalize}(d)).
~~~

相同 hash 只能说明规范化后完全相同。规范化规则不同会改变结果；过度规范化可能把有意义的代码空白、数学符号或文档边界抹掉。

### Near deduplication

近重复可以使用 n-gram、MinHash、SimHash、局部敏感哈希或 embedding 相似度。它们分别在速度、召回、语义泛化和误报之间取舍。实际系统应先用便宜的候选生成，再用更精确的方法确认。

近重复阈值不是越低越好。太低会把不同但相似的专业文档误删，太高则会留下大量转载。阈值应在不同语言、领域和文档类型上抽样评估。

### 训练集内部与训练评估之间

至少有两种 overlap：

~~~text
训练集内部重复：浪费 token，增加记忆和过拟合
训练集与评估集重叠：让评估结果虚高
~~~

二者都需要记录 cluster id、来源、保留样本和删除理由。评估集不能只在训练完成后临时检查，因为污染会影响整个训练和模型选择过程。

### Benchmark contamination

公开 benchmark 可能以原题、答案、解析、翻译、论坛讨论、代码测试或近似改写的形式进入训练语料。污染检测可以结合：

~~~text
n-gram overlap
MinHash / SimHash
embedding nearest neighbors
时间 cutoff
私有或动态测试集
新题和反事实题
~~~

热门 benchmark 越公开，越需要报告训练数据截止时间、过滤范围和污染分析。一个高分如果没有污染边界和新题验证，不能直接解释为泛化能力。

### 一个精确去重和污染标记例子

~~~python
import hashlib


def normalized_hash(text):
    if not isinstance(text, str) or not text.strip():
        raise ValueError("text must be a non-empty string")
    normalized = " ".join(text.split())
    if not normalized:
        raise ValueError("normalized text must be non-empty")
    return hashlib.sha256(normalized.encode("utf-8")).hexdigest()


def overlap_report(train_texts, eval_texts):
    if (not isinstance(train_texts, (list, tuple))
            or not isinstance(eval_texts, (list, tuple))):
        raise TypeError("train_texts and eval_texts must be lists or tuples")
    if not train_texts or not eval_texts:
        raise ValueError("train_texts and eval_texts must be non-empty")
    if any(not isinstance(text, str) or not text.strip()
           for text in list(train_texts) + list(eval_texts)):
        raise ValueError("texts must contain non-empty strings")
    train_hashes = {normalized_hash(text) for text in train_texts}
    eval_hashes = {normalized_hash(text) for text in eval_texts}
    overlap = train_hashes.intersection(eval_hashes)
    return {
        "train_documents": len(train_texts),
        "eval_documents": len(eval_texts),
        "exact_overlap": len(overlap),
        "contaminated": bool(overlap),
    }


print(overlap_report(["a b", "private"], ["a   b", "new"]))
~~~

输出会把规范化后相同的 a b 标记为 overlap。它不检测近重复，也不能处理翻译、代码变体和语义改写。

## 6.5 PII、Secrets、Toxicity 与高风险数据

### PII

个人身份信息可能包括姓名、电话、邮箱、地址、身份证号、健康信息、财务信息、账号和组合后可识别个人的字段。过滤方式有规则、实体识别、哈希化、脱敏、删除和访问控制。自动识别会漏报和误报，必须抽样审计。

### Secrets

代码和配置中可能包含 API key、私钥、密码、连接串、内部 URL 和 token。secret scanning 应在原始数据、解析后文本、代码块和生成 shard 多个阶段执行。仅在最终 tokenizer 后扫描可能已经失去上下文，难以定位和删除。

### Toxicity 与安全数据

有害内容过滤要区分训练用途。某些安全研究需要保留经过隔离和访问控制的 red-team 数据，不能简单把所有风险文本都混入通用预训练。安全数据还要标注任务、攻击类型、目标行为、允许的研究用途和处理权限。

### 过滤的副作用

如果一刀切删除所有包含敏感或有害词的文本，可能损害医学、法律、安全研究和拒答能力。更好的策略是：

~~~text
确定不可训练的内容
隔离需要研究的数据
脱敏仍有价值的样本
保留拒答和风险识别的标注
按用途建立独立数据池
记录删除与保留理由
~~~

### 风险率不是一个总数

可以按来源、语言、领域和严重度统计风险命中率：

~~~math
r_{\mathrm{risk},g}
=\frac{N_{\mathrm{flagged},g}}
{N_{\mathrm{all},g}}.
~~~

整体风险率低，不代表高风险小桶安全。医疗、儿童、企业秘密和高权限代码等小桶应有独立阈值和人工抽检。

## 6.6 Data Mixture：不同能力如何分配 token

### 为什么要混合数据

单一网页语料难以同时覆盖高质量语言、代码、数学、多语言、专业领域和安全样本。Data mixture 用不同数据池及其采样权重形成训练分布：

~~~math
p_{\mathrm{mix}}(x)
=\sum_{k=1}^{K}w_kp_k(x),
\qquad
w_k\ge0,\quad\sum_k w_k=1.
~~~

w_k 是第 k 个数据池的采样权重。它描述抽样概率，不一定等同于最终保留 token 比例，因为文档长度、过滤率和 packing 会改变实际有效 token。

### Temperature sampling

当语言或领域数据规模差异很大时，常使用温度采样。若原始池大小为 n_k，温度 τ 的一个常见形式是：

~~~math
w_k
=\frac{n_k^{\alpha}}
{\sum_j n_j^{\alpha}},
\qquad
\alpha=\frac{1}{\tau}.
~~~

τ 越大，分布越平，低资源池相对被上采样；但重复和过拟合风险也会增加。不同实现的温度定义可能相反，必须写出公式而不是只说“使用温度采样”。

### Effective epoch

如果第 k 个数据池有 D_k 个有效 token，训练实际抽取了 S_k 个 token，可以定义有效 epoch：

~~~math
E_k=\frac{S_k}{D_k}.
~~~

某个小而高价值数据池如果被过度上采样，E_k 可能远高于通用数据，造成记忆和风格过拟合。只记录全局 token 数会掩盖这个问题。

### Mixture ablation

混合比例要通过消融验证。一个最小实验可比较：

~~~text
通用基线
通用 + 代码
通用 + 数学
通用 + 多语言
通用 + 领域
完整 mixture
~~~

每个版本要固定模型、训练 token、学习率、评估集和随机策略，再按语言、代码、数学、事实性、安全和通用任务分桶。若只看总 loss，无法知道哪类数据带来了收益或退化。

### Mixture shift

训练分布、验证分布和线上请求分布不同，会导致 mixture shift。线上数据中的语言、长度、领域、工具和用户群体变化，都可能让模型表现漂移。上线前应记录训练 mixture，线上按同一桶统计请求和失败率，定期判断是否需要补数据或调整路由。

### 采样配置的最小记录

~~~text
pool name
raw documents
kept documents
valid tokens
sampling weight
temperature
effective epoch
language / domain
quality threshold
risk threshold
dataset version
~~~

没有这些字段，训练日志中的“数据比例”通常无法复现。

## 6.7 Sequence Length、Data Packing 与 Document Boundary

### Sequence length 的能力与成本

训练序列长度 T 决定模型在一次样本中看到的上下文范围。更长的 T 可能帮助学习长依赖和文档结构，但 full attention 的关键成本近似为 O(T²)，激活、通信和数据读取也会增加。

训练时可以混合长度，或先用短序列训练大部分 token，再用长序列继续训练。无论哪种策略，都要记录每个长度桶的有效 token 和训练比例。推理配置把 max context 调大，不等于模型学会了长上下文。

### Packing 减少 padding

如果短样本直接补到 T_max，大量计算消耗在 PAD 上。Packing 把多个样本拼成一个固定长度序列，可以提高 token 利用率，但必须保留样本边界。

padding waste 可写为：

~~~math
r_{\mathrm{waste}}
=1-\frac{\sum_i T_i}{B T_{\max}}.
~~~

packing 的收益是减少这个浪费，代价是 mask、EOS、position id 和 loss 的实现复杂度。

### Document boundary

多个文档拼接时，通常在边界加入 EOS 或其他分隔符。若没有边界，模型可能把两个无关文档当作自然连续文本，学到错误的衔接。EOS 是否参与 loss、是否重置 position、不同文档是否互相可见，要根据训练目标定义。

### Packed sequence mask

如果把多个对话或独立样本装进同一序列，只使用普通 causal mask，后面的样本可能看到前面样本的 token。需要使用 block-diagonal causal mask 或等价的样本边界约束：

~~~text
sample A：只看 A 内部的左侧 token
sample B：只看 B 内部的左侧 token
A 与 B：互相不可见
~~~

SFT packing 还要同时处理 role label mask；attention 可见不等于 loss 必须参与。

### Packing 审计

每个 packed shard 可以保存：

~~~text
sample ids
start / end offsets
EOS positions
position ids
attention boundary
loss mask
有效 token 数
padding token 数
~~~

这些字段能帮助定位跨文档泄漏、样本截断、EOS 丢失和 loss 分母错误。

### 一个简单的 packing 函数

~~~python
def pack_sequences(sequences, max_length, eos_id):
    if (not isinstance(sequences, (list, tuple))
            or not isinstance(max_length, int) or isinstance(max_length, bool)
            or max_length <= 0
            or not isinstance(eos_id, int) or isinstance(eos_id, bool)
            or eos_id < 0):
        raise ValueError("sequences, max_length and eos_id have invalid types")
    packed = []
    current = []
    for sequence in sequences:
        if not isinstance(sequence, (list, tuple)):
            raise TypeError("each sequence must be a list or tuple")
        if any(isinstance(token, bool) or not isinstance(token, int)
               or token < 0 for token in sequence):
            raise ValueError("sequence tokens must be non-negative integers")
        if len(sequence) + 1 > max_length:
            raise ValueError("a sequence plus EOS exceeds max_length")
        candidate = current + list(sequence) + [eos_id]
        if current and len(candidate) > max_length:
            packed.append(current)
            current = list(sequence) + [eos_id]
        else:
            current = candidate
    if current:
        packed.append(current)
    return packed


print(pack_sequences([[1, 2], [3], [4, 5, 6]], 5, 0))
~~~

这是教学版本，它会拒绝加上 EOS 后超过 max_length 的单个样本，且没有返回 sample offsets 和 mask。生产 packing 还必须显式记录超长样本的处理策略和边界元数据。

## 6.8 合成数据、教师模型与 Model Collapse

### 为什么使用合成数据

高质量人工数据昂贵、覆盖有限、更新慢。合成数据可以用教师模型或规则生成指令、答案、负例、代码、数学步骤、安全对话和结构化样本。它适合扩大覆盖、生成边界案例和构造验证数据，但不应被当作天然高质量数据。

### 合成数据流水线

~~~text
任务或种子样本
 -> teacher generation
 -> schema / program verifier
 -> quality and safety filter
 -> deduplication
 -> diversity sampling
 -> human or expert audit
 -> train / validation split
~~~

生成器、验证器和过滤器不能完全是同一个未经校准的模型，否则错误会在闭环里自我确认。

### Distillation data

蒸馏数据把教师模型输出作为学生训练目标。教师可以提供答案、排序、解释、工具轨迹或 soft logits。学生不只继承教师的能力，也可能继承教师的偏差、幻觉、格式和拒答模式。蒸馏前要保留 teacher version、采样参数、输入和验证结果。

### Self-Instruct 与 Evol-Instruct

自指令方法从少量种子任务生成更多指令，演化方法通过增加约束、难度或推理步骤扩展样本。它们的收益来自覆盖和多样性，而不是生成量本身。应按任务类型、长度、难度、语言、约束和答案质量去重与抽样。

### Model collapse

如果模型反复在由模型生成的数据上训练，数据分布可能逐步丢失真实长尾，模型错误和偏差被放大。这类风险常被称为 model collapse。缓解方法包括保留真实数据比例、限制合成数据递归深度、做来源标记、验证答案、保留新鲜人类数据和评估长尾覆盖。

### 合成数据的验证

一个合成样本进入训练前，至少应知道：

~~~text
来源模型和版本
生成提示与采样参数
答案验证方法
是否经过人工或专家审计
近重复 cluster
安全与隐私状态
任务类型和难度
是否进入评估集
~~~

### 一个合成样本过滤示例

~~~python
def accept_synthetic(sample):
    if not isinstance(sample, dict):
        return False
    required = {"prompt", "answer", "verified", "source"}
    if not required.issubset(sample):
        return False
    if (not isinstance(sample["prompt"], str)
            or not sample["prompt"].strip()
            or not isinstance(sample["answer"], str)
            or not isinstance(sample["source"], str)
            or not sample["source"].strip()):
        return False
    if not isinstance(sample["verified"], bool) or not sample["verified"]:
        return False
    if sample["source"] == "unknown":
        return False
    if len(sample["answer"].strip()) < 2:
        return False
    return True


samples = [
    {"prompt": "1+1?", "answer": "2", "verified": True, "source": "teacher-a"},
    {"prompt": "bad", "answer": "", "verified": False, "source": "teacher-a"},
]
print([accept_synthetic(sample) for sample in samples])
~~~

输出为 [True, False]。验证字段本身也可能被错误标记，真实系统要说明 verifier 的独立性和误判率。

## 6.9 代码、数学、偏好与安全数据

### 代码数据

代码数据需要同时保留需求、实现、测试和依赖。许可证、secret、重复 fork、自动生成代码和 benchmark 测试泄漏都要处理。文本相似度不能替代功能正确性，代码训练和评估应使用沙箱、单元测试和隐藏测试隔离。

### 数学与 verifier data

数学样本应该有题目、答案、步骤、难度和可验证信号。程序化验证优先于只让另一个语言模型判断。错误但语言流畅的推导是重要负例，不能因为它写得像教材就保留为正例。

### Preference data

偏好数据通常包含 prompt、chosen 和 rejected response。它用于偏好优化或 reward model，但数据标签可能含有长度偏好、风格偏差、标注者差异和安全边界不一致。训练数据应记录标注来源、任务类型、难度、冲突和 tie。

### Safety data

安全数据应覆盖拒答、合规帮助、越权请求、隐私、工具风险、prompt injection 和边界案例。过度过滤会导致 over-refusal，过滤过弱会产生 unsafe leak。安全数据要按风险类型和严重度分桶，不能只报一个总体通过率。

### 多模态数据

图文、音频文本和视频文本样本除了内容质量，还要考虑模态对齐：

~~~text
图片是否属于对应文本
OCR 文字是否准确
音频转写时间戳是否对齐
视频描述是否覆盖正确时间段
敏感人物和隐私是否获授权
图像 caption 是否包含臆造内容
~~~

多模态数据的 source、license、privacy、alignment 和质量证据应与文本数据同等完整。

## 6.10 数据血缘、版本与删除请求

### Dataset manifest

Manifest 是一个可机器读取的版本说明，至少包含：

~~~text
dataset version
source snapshot ids
parser / normalizer versions
filter versions and thresholds
dedup version
language / domain counts
token counts
risk counts
train / eval split
license summary
hashes and storage locations
~~~

它让团队知道一个 shard 是如何产生的。manifest 自身也应版本化并与训练 run 关联。

### Immutable snapshot

训练输入应来自不可变快照或内容寻址对象。若同一个 dataset version 后来被原地覆盖，旧 checkpoint 就无法准确复现。修正数据应生成新版本，并保留从旧版本到新版本的变更记录。

### Data lineage

血缘关系可以表示为图：

~~~text
source document
 -> parsed document
 -> normalized document
 -> filtered document
 -> dedup cluster
 -> bucket
 -> shard
 -> training run
 -> checkpoint
~~~

一个模型能力或事故样本应尽可能沿着这张图回溯。Lineage coverage 可以定义为有完整来源链的训练 token 比例：

~~~math
c_{\mathrm{lineage}}
=\frac{N_{\mathrm{tokens,traceable}}}
{N_{\mathrm{tokens,total}}}.
~~~

### 删除请求

收到删除请求时，系统要定位原始文档、派生文档、去重 cluster、shard、缓存、评估集和模型版本。能否从训练数据中删除，不等于能从已经训练的模型参数中精确擦除；这需要单独的模型编辑、重训或风险评估策略。数据平台必须诚实说明删除边界。

### Datasheet 与 Dataset Card

Datasheet 记录数据集的动机、组成、来源、处理、用途、限制和风险；Dataset Card 更偏向使用者说明。它们不是宣传材料，应包含版本、偏差、许可、评估、已知问题和维护责任。

Model Card 依赖这些数据治理文档提供事实基础。没有数据血缘和版本，模型卡中的训练数据描述很容易退化成无法核查的概述。

## 6.11 Scaling Law、Training Token 与 Compute-Optimal

### 参数、数据与计算

常用变量是参数量 N、训练 token 数 D 和计算量 C。一定范围内，验证 loss 可近似随这些变量平滑下降：

~~~math
L(N,D,C)
\approx L_\infty
+aN^{-\alpha}
+bD^{-\beta}
+cC^{-\gamma}.
~~~

这是经验拟合，不是所有模型、数据和能力的严格定律。下游指令遵循、数学、代码、安全和多模态能力可能与 pretraining loss 有不同曲线。

### Training token

要区分：

~~~text
原始字符数
文档数
tokenizer 后 token 数
参与 loss 的 token 数
被 padding 或 mask 的 token 数
重复 token
合成 token
~~~

scaling 讨论中的 D 应明确采用哪一种计数。不同 tokenizer 下的 token 数不能直接等同于同样的信息量。

### Effective epoch

对一个数据池 k，若其有效 token 数为 D_k，训练中实际采样 S_k：

~~~math
E_k=\frac{S_k}{D_k}.
~~~

大规模预训练常用总 token 而非传统 epoch 作为主要口径，但领域继续预训练和 SFT 中的有效 epoch 仍然很重要。小数据池被反复采样时，模型可能记忆和过拟合。

### Chinchilla 的启发

固定 compute 下，参数量和训练 token 都应合理扩展。参数很大但数据不足的模型可能 undertrained；更小但 token 充分的模型可能在语言建模和部分下游任务上更有效。

真实工程还要加入推理成本。服务场景可能偏向较小、训练充分且易部署的模型；前沿探索可能接受更大的训练和推理成本。compute-optimal 不是只优化一次训练 FLOPs。

### Scaling 预实验

可以用小模型和短训练做趋势实验：

~~~text
固定数据、改变模型大小
固定模型、改变 token 数
固定 compute、平衡 N 与 D
改变数据质量或 mixture
记录验证 loss 和下游切片
记录吞吐、显存和失败率
~~~

小规模趋势只能作为规划证据，不能保证大规模训练后的所有能力都会按同一曲线增长。

## 6.12 Checkpoint、训练恢复与数据事故

### checkpoint 应保存什么

一个可恢复 checkpoint 通常包括：

~~~text
model weights
optimizer state
scheduler state
AMP scaler state
global step / epoch
random states
data sampler / cursor state
model config
tokenizer version
dataset manifest version
training code version
~~~

只保存 model weights 可以用于部署或阶段评估，但不等价于无缝恢复训练。Adam 的一阶和二阶状态、scheduler 位置和数据游标都会改变下一步轨迹。

### 数据事故

数据事故可能包括：

~~~text
训练集误含评估答案
秘密或 PII 未过滤
许可证范围错误
去重误删高价值数据
packing 跨样本泄漏
混合比例配置错
评估集版本漂移
删除请求无法定位
~~~

事故评估要回答影响范围、开始时间、涉及版本、是否进入 checkpoint、是否影响公开结果、如何止血、如何修复和如何防复发。不能只在日志中写“清洗规则有问题”。

### 数据风险率

按数据桶 g 统计命中风险的样本比例：

~~~math
r_{\mathrm{risk},g}
=\frac{N_{\mathrm{risk},g}}{N_g}.
~~~

还要报告严重度、置信度、漏检估计和是否进入训练。整体比例低不代表高风险桶可以忽略。

### 训练恢复的一致性

恢复后要比较：

~~~text
loss 与梯度曲线
learning rate
optimizer step
有效 token 数
数据 shard 和 cursor
随机采样
验证集版本
checkpoint key
~~~

如果恢复后只保证程序能继续跑，不能把它描述为与中断点完全等价的训练恢复。

## 6.13 数据评估：从 token 保留到下游能力

### 数据级指标

数据流水线可以记录：

~~~text
保留率
语言分布
领域分布
平均 token 长度
重复率
风险命中率
PII / secret 命中率
训练评估 overlap
source lineage coverage
effective epoch
packing waste
~~~

这些指标解释“输入了什么”，但不能单独证明模型能力。

### Ablation

数据消融比较不同数据池或处理规则对模型的影响。必须固定模型、compute、token budget、训练步数和评估口径。若去掉某一数据池后总 loss 没变，但代码或数学能力下降，说明只看总 loss 会漏掉目标能力。

### 数据价值

Influence function、Data Shapley、梯度相似度和 proxy model 可以估计样本或数据池对某个目标的价值，但这些方法通常是近似的，成本和稳定性也不同。更可靠的工程决策常把近似价值、风险、覆盖和小规模 ablation 结合起来。

### 负价值数据

数据可能对一个目标有正价值、对另一个目标有负价值。例如，低质量网页提高覆盖，却增加幻觉；过多代码数据提升代码，却挤压多语言；过度安全拒答数据降低危险输出，却损害正常帮助。数据选择要绑定明确目标和护栏。

### Active learning

Active learning 根据模型不确定性、覆盖缺口、失败样本或业务价值选择下一批标注和审计数据。它比盲目扩大数据更有效，但不确定性估计可能失真，仍需人工抽样和分层覆盖。

## 本章回顾

预训练数据工程的核心不是收集最多文本，而是让每个训练 token 都尽可能有可解释的来源、质量、用途和风险边界：

~~~text
来源可追溯
 -> 清洗有理由
 -> 去重可复核
 -> 污染可检测
 -> mixture 可解释
 -> packing 不泄漏
 -> 合成可验证
 -> 版本可冻结
 -> 删除可定位
 -> 训练可恢复
 -> 能力可消融
~~~

当模型能力异常时，应沿着这条链路查找：是数据没覆盖、质量变差、比例失衡、重复污染、mask 边界错误、合成数据退化，还是训练恢复和评估口径出了问题。只有把数据工程事实与模型指标连接起来，预训练才不只是一次昂贵的 token 消耗，而是可解释、可复现、可治理的学习过程。
