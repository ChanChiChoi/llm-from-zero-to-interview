# 第 16 章 多模态学习：让模型看见证据、理解关系并生成结果

## 16.0 从“输入了图片”到“完成了多模态任务”

多模态系统把文字、图像、音频、视频等信号转换为可计算表示，再建立对应关系、联合使用证据，并输出文本或媒体。系统是否完成任务，取决于预处理有没有保留所需证据、表示和融合有没有传递证据，以及输出和后续动作是否符合任务与安全条件。

本章是速查入口，聚焦跨模态表示、对齐、融合和感知。图像与视频生成、语音和完整评估流程保留概念索引，专题机制沿表中链接继续学习。

## 16.1 四种信号，四类表示问题

文本经 tokenizer 变为离散 token；图像是具有二维邻域结构的像素或 patch；音频是带时间顺序的采样点、频谱帧或 codec token；视频则同时包含帧内空间结构和帧间时间关系。同为向量或 token 不表示粒度、位置含义和误差模式相同。

例如，一分钟 16 kHz 单声道音频有 $16{,}000\times60=960{,}000$ 个采样点。系统通常先降采样、提取声学特征或压缩成 codec token；这些步骤减少序列长度，也可能丢失音色、韵律、短促事件或说话人线索。

## 16.2 Modality Gap：为什么不同模态不能直接拼接

不同模态在空间结构、时间尺度、噪声和监督信号上各异。处理链通常分别完成三项工作：**对齐**让相关表示可比较，**融合**让模型联合使用它们，**生成**把条件转换为目标模态。CLIP 的共享向量空间提供对齐，但本身不等于能完成细节问答；融合模型读过图像，也不保证答案忠实于图像。

将“输入可用、任务证据可见、答案正确、动作合规”定义为成功所需事件 $U,E,C,A$，链式法则给出：

~~~math
P(\mathrm{success})
=P(U)P(E\mid U)P(C\mid U,E)P(A\mid U,E,C)
~~~

这是条件概率的精确分解，不假设事件独立；它只覆盖已定义的四个成功条件。它提示排障应沿输入、证据、答案和动作逐层定位，不能把预处理丢失的字段归因为语言模型推理。

## 16.3 输入表示与采样：模型究竟看到了什么

高宽为 $H,W$ 的图像采用边长为 $P$ 的 patch 时，忽略 padding、resize 和额外 global token 的近似 patch 数是：

~~~math
N_{\mathrm{patch}}
=\left\lceil\frac{H}{P}\right\rceil
 \left\lceil\frac{W}{P}\right\rceil
~~~

例如 $336\times336$ 图像配 $14\times14$ patch，得到 $24\times24=576$ 个 patch；两边都扩大一倍，就变成 $48\times48=2{,}304$，即约四倍 token。若后续使用密集全注意力，token pair 数随序列长度平方增长，所以分辨率提升可能显著增加延迟和显存。真实 processor 还会 resize、多 crop 或补边，须读取实际张量和 token 布局。

视频若采样 $F'$ 帧、每帧产生 $N_{\mathrm{img}}$ 个视觉 token，可先估为 $N_{\mathrm{video}}=F'N_{\mathrm{img}}$。稀疏均匀抽帧对场景概览便宜，却可能漏掉很短的事件；事件定位需要更密采样、检索或显式时间戳。

## 16.4 Multimodal Context Budget：媒体也占计算预算

模型实际处理的序列或 latent 数量可记为：

~~~math
T_{\mathrm{total}}
=T_{\mathrm{text}}+T_{\mathrm{image}}+T_{\mathrm{audio}}+T_{\mathrm{video}}+T_{\mathrm{control}}
~~~

图片文件大小和 API 展示的单个 image placeholder 都不能直接代表模型内部长度。Processor 可能把图像展开为多 crop、patch 或专用 latent；音频和视频也会经过重采样、压缩或抽帧。密集注意力的 token pair 约随 $T_{\mathrm{total}}^2$ 增长，但实际延迟还受 kernel、带宽、批处理和缓存影响，不能把渐近复杂度当成线上时延估计。

## 16.5 Input Fidelity 与 Evidence Recall：证据是否到达答案

沿链路区分三个集合：原始媒体中的任务证据 $E_0$、预处理后仍可读的证据 $E_1$，以及最终进入模型上下文的证据 $E_{ctx}$。可分别计算输入保真、上下文证据召回和 claim 支持率：

~~~math
F_{\mathrm{input}}=\frac{|E_0\cap E_1|}{|E_0|},\qquad
R_{\mathrm{evidence}}=\frac{|E_{gold}\cap E_{ctx}|}{|E_{gold}|},\qquad
S_{\mathrm{claim}}=\frac{\text{有证据支持的 claim 数}}{\text{全部可评估 claim 数}}
~~~

分母为零时相应指标是 N/A。构造一个四字段票据例：金额、日期、商户和明细中有三个在裁剪后仍可读，故 $F_{input}=3/4$；若只有金额和日期进入上下文，则任务证据召回为 $2/4$；若回答提出三项 claim，其中两项可由上下文支持，支持率为 $2/3$。三个数分别定位预处理、上下文构建和回答忠实性，不能用一个端到端准确率替代。完整评测协议见[多模态评估与安全主讲](../../book-15-multimodal-generative-models/chapters/11-多模态评估与安全.md)。

## 16.6 CLIP：把图像和文字放进可比较的空间

CLIP 用图像编码器和文本编码器把配对样本映射到共享向量空间。对归一化向量 $v_i,t_j$，温度为 $\tau>0$ 时，相似度 logit 为 $S_{ij}=v_i^\top t_j/\tau$；对比损失让正确图文配对在 batch 内相对更接近。经典目标分别对图到文、文到图做交叉熵，再取平均。

一个两候选的构造例中，正确描述的余弦相似度为 $0.8$，错误描述为 $0.2$，取 $\tau=0.1$ 后 logits 为 $8$ 和 $2$。正确候选 softmax 概率约为 $1/(1+e^{-6})\approx0.9975$。这说明温度控制相似度差转为概率的陡峭程度；它不是图片问答准确率，也不是对任意域数据的校准概率。

CLIP 可用于图文检索和零样本分类：把类别写成文本候选并比较相似度。细粒度 OCR、计数、区域定位和多步推理仍需相应的视觉语言任务训练与评测。机制细节和实验边界见[第十五册 CLIP 章节](../../book-15-multimodal-generative-models/chapters/02-clip与图文对齐.md)。

## 16.7 SigLIP 与图文对齐目标

CLIP 的 softmax 让一个 batch 内样本相互竞争；SigLIP 对每个图文 pair 独立做正负二分类，常见损失可写为：

~~~math
L_{ij}=\log\left(1+\exp(-y_{ij}S_{ij})\right),\qquad y_{ij}\in\{-1,+1\}
~~~

这改变的是对比目标的归一化和 batch 耦合方式，不意味着没有负样本、无需考虑 batch 构成或在所有数据规模下必然更好。比较训练结果要固定数据、负样本构造、模型和计算预算；详见[图文对齐主讲](../../book-15-multimodal-generative-models/chapters/02-clip与图文对齐.md)。

## 16.8 Vision Encoder：视觉信息从哪里来

Vision encoder 将像素转换为局部或层级特征。ViT 把图像切为 patch、投影成 token，再用 Transformer 建模全局关系；Swin 等层级结构以局部窗口和逐层降采样处理空间尺度。输入分辨率、patch 大小、位置编码和训练数据都会影响小字、细粒度对象与全局布局的保留。

编码器的输出可能是单个全局向量，也可能是一列空间特征。检索通常需要紧凑 embedding，VLM 问答和 grounding 通常需要保留更多区域信息。结构与 shape 的完整推导见[第十五册 Vision Encoder](../../book-15-multimodal-generative-models/chapters/03-vision-encoder.md)。

## 16.9 Text Encoder 与 Decoder-only LLM

双向 text encoder 可同时利用句子两侧上下文，常用于检索和表示学习；decoder-only LLM 通过自回归预测后续 token，适合按指令生成答案。两者的注意力方向、预训练目标和输出接口不同。把视觉向量接入 decoder-only 模型还要定义投影、位置、mask 和训练目标，单纯维度对齐不等于语义已对齐。

## 16.10 Vision-Language Model：视觉前端连接语言推理

典型 VLM 数据流为“图像预处理 → vision encoder → connector → LLM 上下文 → 文本或结构化输出”。问答是否可靠，既取决于 LLM，也取决于缩放/crop、编码器特征、连接器压缩和指令数据。OCR、定位、图表读取、计数应单独测量，不能由流畅回答推断成功。架构谱系见[VLM 主讲](../../book-15-multimodal-generative-models/chapters/04-vlm架构.md)。

## 16.11 Connector：视觉特征如何进入语言模型

连接器把视觉特征转换成 LLM 可消费的表示，常见方案各有信息与预算取舍：

| 方案 | 主要机制 | 典型取舍 |
| --- | --- | --- |
| Linear projector | 逐 patch 投影到 LLM 维度 | 简单、保留 patch 序列；视觉 token 可能较多 |
| Q-Former | 少量可学习 query 从视觉特征读取信息 | 可压缩序列；瓶颈 query 可能漏细节 |
| Perceiver Resampler | latent query 对可变长视觉特征做交叉注意力 | 支持固定 latent 数；实现和训练更复杂 |
| Cross-attention | 在语言层间插入视觉交互 | 多层融合灵活；改变主干计算和训练接口 |

Flamingo、BLIP-2 和 LLaVA 是不同连接路线的代表，不宜把不同模型、数据和训练预算下的榜单分数当作连接器的因果比较。详细结构与实验条件见[VLM 架构章节](../../book-15-multimodal-generative-models/chapters/04-vlm架构.md)。

## 16.12 Image Placeholder 与连接器形状审计

对话模板中的图片占位符常用于标记媒体在消息中的位置；它不一定等于一个实际视觉 token。Processor 可能在该位置展开高分辨率 crop、patch 序列或模型专用 latent。调试时要同时检查原图、预处理尺寸、占位符顺序、视觉张量 shape、有效 token 数和文本/图像 attention mask，避免把序列错位归因于模型推理。

## 16.13 Visual Token Compression：预算和证据的交换

视觉压缩把较长的 patch 序列缩成更少的 token，以节省上下文和注意力计算。可用 $1-N_{compressed}/N_{raw}$ 描述 token 数压缩比例，但这个数不是信息保真率：全局场景概览可能保持良好，小字、表格单元或稀有目标却可能被抹去。压缩前后应在相同任务切片上比较 OCR、grounding、计数和证据召回。高分辨率与压缩路线详见[Native Multimodal Token Budget](../../book-15-multimodal-generative-models/chapters/14-native-multimodal-token-budget.md)。

## 16.14 Multimodal Instruction Tuning：教模型按任务使用媒体

多模态指令微调通过图像/音频/视频与指令、期望回答的配对样本，教模型完成描述、问答、定位和拒答等任务。训练审计应记录媒体预处理、样本来源、模态比例、任务分布、答案证据和权限条件；只看总 loss 会掩盖模型是否偏向语言流畅性而忽略媒体证据。

若训练目标只对 assistant 目标 token 计损失，监督集合需明确排除用户输入及作为上下文使用的媒体位置。数据配比、标注和损失 mask 影响实际能力；深入讨论见[多模态 Instruction Tuning 主讲](../../book-15-multimodal-generative-models/chapters/05-多模态instruction-tuning.md)与[第五册多模态训练](../../book-05-llm-training/chapters/12-多模态训练.md)。

## 16.15 扩散模型：把生成拆成一串可学习的去噪步骤

扩散模型先逐步向训练样本加噪，再学习从不同噪声等级恢复数据。常见噪声预测目标让网络从带噪样本、时间步和条件估计加入的噪声；推理时 scheduler 决定反向路径和步数。训练目标、参数化及采样器是不同选择，不能把“换 scheduler”说成重新训练模型。

扩散训练和反向路径的可复算推导见[第十五册扩散基础](../../book-15-multimodal-generative-models/chapters/06-diffusion基础.md)；图像生成入口见[本册第 17 章](17-图像生成与视频生成.md)。

## 16.16 条件控制：CFG、负条件和结构约束

不同控制方式修改生成过程中的条件信息：

| 方法 | 条件如何影响生成 | 主要边界 |
| --- | --- | --- |
| Classifier-Free Guidance（CFG） | 外推有条件与无条件预测的差向量 | guidance 过强会放大伪影、降低多样性 |
| Negative prompt | 提供希望模型降低的概念条件 | 不是安全规则，也不能保证彻底排除目标 |
| ControlNet | 将边缘、深度、姿态等结构特征注入去噪网络 | 输入控制图误差会传到结果 |
| img2img / inpainting | 从已有图像或局部 mask 定义生成起点与编辑区域 | 生成可能改动未授权区域或遗漏局部条件 |

这些术语给出控制接口的速查；CFG 的推导、ControlNet 的零卷积初始化和编辑保真评估分别见[第十五册扩散基础](../../book-15-multimodal-generative-models/chapters/06-diffusion基础.md)与[图像生成专题](../../book-15-multimodal-generative-models/chapters/07-stable-diffusion与dalle.md)。

## 16.17 Latent Diffusion、Stable Diffusion 与 DALL·E

Latent diffusion 在压缩后的空间中去噪，以较低空间分辨率降低每一步的成本；VAE 编解码会带来细节损失和额外接口约定。Stable Diffusion 是“文本编码器 → latent 去噪器 → VAE 解码器”类 pipeline 的代表。DALL·E 的早期路线则将图像编码成离散 token，再自回归预测图像 token 序列。

扩散路线以多步去噪为主要迭代，离散自回归路线逐 token 生成；两者的序列长度、并行性、控制方式和质量指标不同。完整模型和 pipeline 细节见[本册第 17 章](17-图像生成与视频生成.md)及[第十五册 07](../../book-15-multimodal-generative-models/chapters/07-stable-diffusion与dalle.md)。

## 16.18 视频生成：时间维度带来的新问题

视频模型除了单帧空间结构，还要表示帧间运动、身份连续性和事件顺序。时空 patch 可把相邻帧共同切块，减少逐帧处理的冗余；但抽帧和压缩可能漏掉短事件，较长时间跨度还会增加显存和长程一致性难度。

Fréchet Video Distance（FVD）比较视频特征分布，无法单独证明 prompt 遵循、人物身份稳定或物理合理。评估应把单帧质量、时间一致性、运动、事件召回和安全切片分开。视频生成与 World Model 的完整路线见[本册第 17 章](17-图像生成与视频生成.md)和[第十五册 08](../../book-15-multimodal-generative-models/chapters/08-视频生成与world-model.md)。

## 16.19 音频表示：从 waveform 到 codec token

Waveform 保留采样时间序列；Log-Mel Spectrogram 把短时频谱映射为时间—频率特征；神经 codec 将音频压缩为离散码本 token。若采样率为 $r$ Hz、时长为 $D$ 秒，原始采样点数为 $N=rD$；codec 若帧率为 $q$ Hz、包含 $K$ 个码本，token 数可近似为 $N_{codec}=\lceil Dq\rceil K$。压缩可缩短序列，但重建质量、韵律细节与 token 长度需要一起评估。

码本 token 是音频压缩表示，不等同于词或句子的语义标签。实际布局会受分层量化、可变码率和帧对齐方式影响。音频表示与生成的完整讲解见[第十五册 09](../../book-15-multimodal-generative-models/chapters/09-语音与音频生成.md)及[本册第 18 章](18-语音大模型.md)。

## 16.20 ASR、TTS 与语音交互

Automatic Speech Recognition（ASR）把音频转写为文本；Text-to-Speech（TTS）从文本生成 waveform，通常还要控制音色、韵律和停顿。Whisper 是大规模弱监督 encoder-decoder ASR 的代表路线，但论文测试集上的平均错误率不能直接代表目标业务的关键字段准确率。

级联系统可表示为 speech → ASR → LLM → TTS，模块易替换和审计，但延迟与错误会沿链路累积；端到端 speech-to-speech 可保留语气等信息，内部决策则更难定位。Voice Activity Detection、流式端点、打断和回声消除都会影响实时体验。系统级机制和交互状态见[第十五册语音主讲](../../book-15-multimodal-generative-models/chapters/09-语音与音频生成.md)。

## 16.21 WER、CER 与 MOS：不要用一个数字代表语音系统

Word Error Rate 和 Character Error Rate 分别按参考词、参考字符计替换、删除和插入：

~~~math
\mathrm{WER}=\frac{S+D+I}{N_{ref}},
\qquad
\mathrm{CER}=\frac{S_c+D_c+I_c}{N_{char}}
~~~

分母须大于零，且要固定分词、标点、数字和大小写规范。构造一个 20 词参考句例，若有 1 次替换、1 次删除和 2 次插入，则 WER 为 $4/20=0.20$，即 20%；若出错的是金额或地址，应另算关键字段准确率。Mean Opinion Score（MOS）是主观听感量表，报告时需说明 MOS 类型、评审和播放条件，并与内容准确率、延迟分开看；参照[ITU-T P.800.2](https://www.itu.int/itu-t/recommendations/rec.aspx?id=12973)。完整语音评估见[第十五册 09](../../book-15-multimodal-generative-models/chapters/09-语音与音频生成.md)和[本册第 18 章](18-语音大模型.md)。

## 16.22 统一多模态：统一发生在哪一层

“统一”至少可能指统一用户接口、共享中间表示、共同 token 序列或共享生成架构。一个助手调用 OCR、ASR 和独立媒体生成器，可以在产品接口上统一，内部仍是模块级联。Any-to-any 描述输入输出覆盖目标，不代表一个 decoder 对所有模态具有同等质量、延迟和成本。

| 路线 | 统一发生处 | 关键取舍 |
| --- | --- | --- |
| Chameleon | 文本和离散图像 token 进入共同自回归序列 | 跨模态交互直接；视觉 token 序列可能很长 |
| NExT-GPT | LLM 中枢连接专用 encoder 与生成器 | 组件可替换；模块边界和接口对齐复杂 |
| AnyGPT | 多模态 codec/tokenizer 接入自回归目标 | 统一 next-token 接口；重建质量依赖 tokenization |
| Encoder-free 路线 | 以共享模型直接处理模态信号 | 减少部分显式模块；训练数据和 token 预算要求高 |

这些研究路线的训练数据、模型规模和评估协议不同，不能据此做分数排名。更细架构、native token budget 和前沿模型入口见[第十五册统一多模态](../../book-15-multimodal-generative-models/chapters/10-统一多模态模型.md)、[Encoder-Free 专题](../../book-15-multimodal-generative-models/chapters/13-encoder-free-unified-multimodal.md)及[Native Token Budget 专题](../../book-15-multimodal-generative-models/chapters/14-native-multimodal-token-budget.md)。

## 16.23 多模态生成和理解的统一评估

先按任务选择指标，再固定样本、预处理、匹配规则和分母。常见指标回答的问题不同：

| 任务 | 常见指标 | 必须补充的口径 |
| --- | --- | --- |
| 图像问答 | VQA accuracy / soft score | evaluator 版本、答案规范化和多参考答案处理 |
| 文档与图表 | CER、关键字段准确率、数值容忍准确率 | 字符/单位/百分比规范化和字段分母 |
| 区域定位 | IoU、Recall@K、mAP | box/mask 几何定义和匹配策略 |
| 忠实性 | claim-level evidence support、hallucination rate | 原子 claim 切分、外部知识是否允许、空 claim 处理 |
| 视频 | FVD、时间定位误差、身份/运动切片 | 帧率、长度、特征提取器和镜头切换 |
| 语音 | WER/CER、MOS、实时延迟 | 语言、分词与播放条件；内容和听感分开 |

单一平均分不能替代按小字、遮挡、短时事件、口音、噪声和高风险动作切片。经典 VQA 评分含多标注者 leave-one-out 规则，应按[官方 evaluator 说明](https://visualqa.org/evaluation.html)核对，不能把简化公式冒充所有版本的协议。指标设计和评测代码见[第十五册评估与安全](../../book-15-multimodal-generative-models/chapters/11-多模态评估与安全.md)。

## 16.24 多模态安全：媒体是数据，不是更高权限的指令

图像 OCR、音频转写、字幕和网页截图可能承载 prompt injection。媒体抽取内容应保留来源并视为不可信数据；工具执行前仍需独立做权限、参数和副作用检查。arXiv:2603.03637 在 COCO 图像与 GPT-4-turbo 的特定受控实验中，对一种配置报告最高 64% 攻击成功率；这是该论文攻击和实验设置下的结果，不是所有多模态模型的总体风险率。[论文](https://arxiv.org/abs/2603.03637)

人脸、声音和步态等可含生物识别信息，模型相似度不能替代授权。C2PA 2.5 的 manifest 和签名用于验证来源声明与内容绑定；验证通过不等于断言内容真实。[C2PA 2.5 技术规范](https://spec.c2pa.org/specifications/specifications/2.5/specs/C2PA_Specification.html)。安全策略和威胁分类见[本册安全与治理](13-安全与治理.md)及[第十五册评估与安全](../../book-15-multimodal-generative-models/chapters/11-多模态评估与安全.md)。

## 16.25 事故复盘：沿着媒体证据链定位错误

回答错误可能起于上传、裁剪、转码、OCR/ASR、抽帧、编码器、连接器、上下文、生成或工具执行。复盘应固定原始媒体和授权状态，逐层保存预处理参数、中间证据、模型上下文、原子 claim、工具参数和最终影响；修复后把脱敏或合成样本加入按质量、模态和严重度切片的回归集。

复现率的分母必须是已定义并可重放的事故集合。没有纳入回归集的事故属于覆盖缺口，不能因为回归集没有失败就报告“生产事故率为零”。[第十五册评估与安全](../../book-15-multimodal-generative-models/chapters/11-多模态评估与安全.md)提供数据集、回归和事故记录流程。

## 16.26 统一系统的端到端账本

可用同一个 request ID 关联各阶段，确保结论能追溯到媒体证据和系统动作：

| 阶段 | 记录项 | 排查问题 |
| --- | --- | --- |
| 输入 | 媒体元数据、授权、预处理版本 | 输入是否清晰、完整且允许使用 |
| 表示 | patch/latent/codec 数量、OCR/ASR/帧证据 | 关键细节是否保留并进入上下文 |
| 推理 | 模板、路由、预算、模型版本 | 模型看见了哪些证据和指令 |
| 输出 | claim、区域或时间引用、不确定性 | 回答是否能被证据支持 |
| 动作 | 工具参数、权限、确认、执行结果 | 是否越权或误操作 |
| 结果 | 任务成功、回退、人工成本和影响 | 指标是否覆盖真实用户目标 |

这张表把输入保真、证据召回、回答忠实性和执行授权分开，便于定位故障，不把中间环节隐藏在最终语言输出里。

## 16.27 用一个小实验检查 token、支持率和拒答边界

下面的示例只依赖 Python 标准库，用于演示多模态系统的三个基本账本：媒体 token 预算、claim 证据支持率和资料不足时的拒答漏判。它不是模型质量评测，也不产生任何生产结论。

~~~python
from dataclasses import dataclass


@dataclass
class Media:
    kind: str
    tokens: int
    evidence_ids: set[str]


def context_tokens(text_tokens, media_items, special_tokens=0):
    if text_tokens < 0 or special_tokens < 0:
        raise ValueError("token counts must be non-negative")
    if any(item.tokens < 0 for item in media_items):
        raise ValueError("media token counts must be non-negative")
    return text_tokens + sum(item.tokens for item in media_items) + special_tokens


def evidence_support(claims, available_evidence):
    if not claims:
        return None
    if any(not claim.get("evidence_id") for claim in claims):
        raise ValueError("every claim must cite an evidence id")
    if not available_evidence:
        return 0.0
    supported = sum(
        1 for claim in claims if claim["evidence_id"] in available_evidence
    )
    return supported / len(claims)


def missing_refusal_rate(samples):
    if any(
        "should_refuse" not in sample or "did_refuse" not in sample
        for sample in samples
    ):
        raise ValueError("each sample needs expected and observed refusal labels")
    required = [sample for sample in samples if sample["should_refuse"]]
    if not required:
        return None
    missed = sum(not sample["did_refuse"] for sample in required)
    return missed / len(required)


invoice = Media("image", tokens=576, evidence_ids={"total"})
claims = [{"text": "金额为 128.00 元", "evidence_id": "total"}]
samples = [
    {"should_refuse": True, "did_refuse": False},
    {"should_refuse": True, "did_refuse": True},
]

assert context_tokens(80, [invoice], special_tokens=4) == 660
assert evidence_support(claims, invoice.evidence_ids) == 1.0
assert missing_refusal_rate(samples) == 0.5
assert evidence_support([], invoice.evidence_ids) is None
assert evidence_support(claims, set()) == 0.0
assert missing_refusal_rate([]) is None
print("multimodal audit toy: ok")
~~~

> 代码状态：静态审阅，未运行（2026-10-30）。依赖 Python 3.9+ 标准库；保存为 `audit.py` 后可用 `python3 audit.py` 运行。静态预期输出：`multimodal audit toy: ok`。

读者可以把 `evidence_ids` 替换成页码、框坐标、时间区间或音频词段，把 `tokens` 替换成真实 encoder 输出，从而检查自己的数据管线是否把关键证据送入模型。这里空 claim 集和“没有应拒答样本”返回 `None`，表示指标没有定义；这与支持率为 `0`、拒答漏判率为 `0` 是不同的事实。示例中拒答漏判率的分母只包含应该拒答的样本，不能和普通任务准确率直接相加。

## 16.28 从 demo 到产品：按工作流选择结构

先定位工作瓶颈，再选模块组合。架构表只用于提出方案，具体质量、成本和时延要在目标数据上测量。

| 工作流 | 常见结构 | 关键验收项 |
| --- | --- | --- |
| 图片问答 / 企业文档 | VLM，必要时加 OCR、版面分析或检索 | 字段准确率、证据页码、拒答 |
| GUI 与空间操作 | VLM + grounding + 受限工具 | 区域 IoU、动作成功、越权率 |
| 长视频 | 抽帧或事件检索 + 视频模型 | 事件召回、时间定位、长程一致性 |
| 实时语音 | VAD + 流式 ASR/LLM/TTS 或端到端语音模型 | 关键字段、首包延迟、打断和回退 |
| 媒体生成 | diffusion、自回归或专用音频/视频 pipeline | 条件遵循、编辑保真、授权和内容安全 |

若一次任务包含人工复核、工具和重试，总成功成本可写为：

~~~math
C_{success}=\frac{C_{inference}+C_{tool}+C_{retry}+C_{human}}{P_{task\ success}},
\qquad P_{task\ success}>0
~~~

单位和测量窗口须一致；成功概率为零时该比率无定义。部署设计见[第六册多模态部署](../../book-06-llm-deployment/chapters/10-多模态部署.md)，系统设计见[第十一册多模态助手](../../book-11-system-design-interview/chapters/07-设计多模态助手.md)。

## 16.29 证据等级与延伸阅读

读多模态结论时，要区分论文机制和实验结果、官方接口行为、标准的验证边界、benchmark 协议，以及本地教学例子。一个来源能证明的范围取决于其模型、数据、处理参数和评分器；产品宣传和单个成功样例不能代替系统评估。

建议按问题读取原始资料，再沿章首导航进入完整专题：

- [CLIP](https://arxiv.org/abs/2103.00020)、[SigLIP](https://arxiv.org/abs/2303.15343)、[ViT](https://arxiv.org/abs/2010.11929)：图文对齐和视觉编码。
- [DDPM](https://arxiv.org/abs/2006.11239)、[Latent Diffusion](https://arxiv.org/abs/2112.10752)、[ControlNet](https://arxiv.org/abs/2302.05543)：去噪、latent 和结构条件。
- [Video Diffusion Models](https://arxiv.org/abs/2204.03458)、[FVD](https://arxiv.org/abs/1812.01717)：视频生成与分布级评估。
- [Whisper](https://arxiv.org/abs/2212.04356)、[ITU-T P.800.2](https://www.itu.int/itu-t/recommendations/rec.aspx?id=12973)：语音识别及 MOS 报告。
- [C2PA 2.5](https://spec.c2pa.org/specifications/specifications/2.5/specs/C2PA_Specification.html)：内容来源 manifest、签名和验证边界。
- [Transformers Processor 文档](https://huggingface.co/docs/transformers/main/processors)：模型处理器入口；具体行为需按目标模型与版本核对。

论文、评测协议和官方文档的阅读边界由对应主讲章节及其证据记录说明。

## 16.30 章节练习：用机制推导现象

做完整学习和数值推导时，继续使用[第十五册多模态面试题](../../book-15-multimodal-generative-models/chapters/12-多模态面试题.md)。本章用四个问题检查能否跨阶段定位：

1. 将图像高宽扩大两倍，按 patch 公式算出 token 数变化，再指出上下文预算和证据召回分别可能在哪里受影响。
2. 票据金额回答错误时，设计对照检查输入裁剪、OCR/视觉 token、连接器和最终 claim 支持；说明每一步的可观察证据。
3. 比较 VLM + OCR、统一多模态 encoder 和中心 LLM 模块方案，给出任务切片、工具权限和单位成功成本的验收口径。
4. 图片含越权指令、用户只要求转述时，说明如何保留原始媒体证据、隔离指令文本，并阻止未经授权的工具动作。

## 16.31 小结：多模态能力的边界来自证据链

多模态系统可以沿着以下链条理解：输入预处理决定保留哪些证据，encoder 把信号转换成表示，connector 或共享空间建立模态关系，融合模型决定如何联合推理，解码器把结果转换成目标模态，评估和安全策略约束系统在证据不足时如何降级。

CLIP 和 SigLIP 代表图文对齐路线；ViT 等视觉塔把图片转换为 patch 表示；Q-Former、Perceiver Resampler 和 projector 代表不同的视觉—语言连接方式；Flamingo、BLIP-2 和 LLaVA 展示了不同的架构取舍。扩散模型把生成拆成去噪路径，视频模型还要处理时间连续性，语音系统要同时处理内容、音色、韵律和实时交互，统一多模态模型则要面对不均衡 token rate、路由、损失配比和模态冲突。

真正可交付的结论不能只是“模型支持图像或音频”。更有意义的结论是：在给定输入分布、采样策略、证据保真、上下文预算、权限和成本下，哪些任务可以稳定完成，哪些任务必须要求确认、明确拒答或转人工。
