# G. 后训练与对齐：从行为塑形到可验证反馈

## 阅读边界

预训练让模型获得通用语言和知识模式，后训练则改变它与用户交互的方式：是否遵循指令，如何组织回答，怎样处理偏好、安全和工具调用。后训练不是一个单一算法，而是一组数据、目标、优化器、协议和评估共同组成的行为工程。

本章沿着以下链路展开：

~~~text
base model
 -> instruction data
 -> SFT
 -> preference / reward data
 -> RLHF / DPO / other preference optimization
 -> safety and verifiable feedback
 -> reasoning / tool trajectories
 -> capability and risk evaluation
~~~

接下来先从行为变化和 SFT 的监督边界说起，再依次讨论低秩适配、能力回归、偏好数据、奖励模型、RLHF、DPO 及其变体，最后把安全反馈、可验证奖励、推理轨迹和发布评估放回同一条工程链路。完整的训练命令、分布式实现和推理部署见[第五册：大模型训练](../../book-05-llm-training/目录.md)，其中 [RLVR 与可验证奖励](../../book-05-llm-training/chapters/16-rlvr与可验证奖励.md) 和 [on-policy distillation](../../book-05-llm-training/chapters/17-on-policy-distillation.md) 继续展开训练细节；安全治理和红队评估见[第八册：安全与对齐](../../book-08-ai-safety-alignment/目录.md)。

## 7.1 Post-training：后训练究竟改变什么

### Base model 与助手行为

Base model 主要优化文本分布，能够续写，但不一定把用户输入解释成任务。后训练把这种通用能力映射到交互协议：

~~~text
system / user / assistant 角色
任务说明与约束
回答格式
多轮状态
拒答和安全替代
工具调用
用户偏好
~~~

后训练通常包括 instruction tuning、SFT、偏好优化、安全数据训练、红队和能力回归。不同团队的顺序和组合不同，不能把“对齐”简化成某一个 loss。

### 目标之间的冲突

一个回答可能同时需要有帮助、正确、简洁、安全、遵循格式和尊重权限。这些目标可能冲突：

~~~text
更详细：可能更有帮助，也可能更冗长、更贵
更保守：可能更安全，也可能造成过度拒答
更快：可能降低工具验证或检索完整度
更听话：可能增加越权执行风险
更高 reward：可能诱发 proxy gaming
~~~

因此后训练评估不能只看一个平均分。目标函数要和护栏指标、人工复核、工具校验及线上行为一起解释。

### 后训练的数据契约

每条后训练样本至少要明确：

~~~text
输入角色和 chat template
可见上下文
目标 response
参与 loss 的 token
EOS / stop 规则
任务和风险标签
来源与标注者
版本和许可证
是否进入评估集
~~~

数据结构错误时，训练可能正常运行却学到错误行为。后训练的第一个问题通常不是“选哪种优化器”，而是“模型到底被要求模仿什么”。

## 7.2 Instruction tuning 与 SFT

### Instruction tuning

Instruction tuning 使用任务说明和目标回答，把 base model 从续写器塑造成更会执行任务的模型。任务可以是问答、摘要、翻译、分类、代码、抽取、格式生成、多轮对话或工具调用。

样本覆盖要同时考虑：

~~~text
任务类型
输入长度
语言与领域
正常与边界请求
格式约束
正例与反例
不可满足指令
多轮追问
~~~

回答质量比样本数量更重要。错误、模板化或互相冲突的示范会直接写入模型行为。

### SFT 目标

设 x 是条件上下文，y 是目标回答，m_t 是 label mask：

~~~math
L_{\mathrm{SFT}}
=-\frac{1}{\sum_t m_t}
\sum_t m_t
\log p_\theta(y_t\mid x,y_{1:t-1}).
~~~

m_t=1 的位置参与训练，m_t=0 的位置被 ignore；这个公式只有在 `\sum_t m_t>0` 时有定义。assistant-only SFT 往往把 system、user 和 padding 设为 0，但是否训练角色边界和 EOS 要根据模板和停止策略决定。一个 batch 如果没有任何有效 assistant target，应在 collator 或 loss 计算处报错，而不是把分母改成一个极小常数后继续训练。

### Shift 与 mask 的组合

一个对话样本可能被序列化为：

~~~text
system -> user -> assistant -> EOS
input_ids:     [s0, u0, a0, a1, EOS]
stored_labels: [-100, -100, a0, a1, EOS]
shift targets: [-100, a0, a1, EOS]
predictors:    [s0,   u0, a0, a1]
~~~

这个示意采用模型内部shift：位置u0预测首个assistant目标a0，a1预测EOS，不另造一个不存在的next目标。真实tokenization可能把角色标记拆成多个token，不能按字符位置粗略生成mask。截断、packing、左padding和多轮assistant span都要重新定位。

### Assistant mask coverage

可以用下面的比例检查 assistant 目标是否被有效监督：

~~~math
C_{\mathrm{assistant}}
=\frac{N_{\mathrm{assistant\_labels\_enabled}}}
{N_{\mathrm{assistant\_labels\_expected}}}.
~~~

这个比例接近 1 仍不充分，因为角色边界可能错位，prompt token 也可能意外打开。需要同时检查 prompt loss leak、PAD loss leak、EOS coverage 和按样本长度分桶的统计。

### SFT 的失败表现

~~~text
模型复述用户问题：prompt 参与了 loss 或模板错
模型生成角色标记：special token / mask 错
回答不停：EOS 缺失或 stop 配置错
loss 下降但格式错误：训练目标与线上模板不一致
目标领域变好但通用能力掉：数据过窄或学习率过大
~~~

## 7.3 Full fine-tuning、LoRA 与 QLoRA

### Full fine-tuning

Full fine-tuning 更新全部参数，适合数据量和资源都足够、需要深度改变行为的场景。它的能力上限可能更高，但显存、checkpoint、训练稳定和遗忘风险也更大。

训练成本至少包含：

~~~text
参数
梯度
optimizer state
activation
通信
checkpoint
验证与回滚
~~~

小数据上用大学习率全参训练，往往会把底座能力快速推向窄分布。

### LoRA

LoRA 冻结基座权重 W，只学习低秩增量：

~~~math
W'=W+\Delta W,
\qquad
\Delta W=\frac{\alpha}{r}BA.
~~~

A形状为`[r,d_in]`，B为`[d_out,r]`，因此BA的秩至多为r，不保证恰好等于r；例如初始化时一侧为零，增量秩可以为零。alpha控制缩放。可训练参数量约为：

~~~math
P_{\mathrm{LoRA}}
=r(d_{\mathrm{in}}+d_{\mathrm{out}})
~~~

忽略 bias。rank 太小可能表达不足，rank 太大增加成本和过拟合风险；target modules、学习率、alpha、dropout 和任务数据共同决定结果。

### Adapter 生命周期

LoRA adapter 可以独立保存、组合、合并或按请求加载。工程上要记录：

~~~text
base model hash
tokenizer / template
target modules
rank / alpha
dtype
训练数据版本
adapter version
merge 方式
评估结果
~~~

adapter 不能脱离原始 base model 随意使用。base 版本、词表或层名变化会导致加载和行为不一致。

### QLoRA

QLoRA 量化基座权重、训练 LoRA adapter，主要降低基座加载和训练显存。量化精度、计算 dtype、double quant、梯度 checkpoint、optimizer 和 target modules 都会影响稳定性。它是资源优化方案，不是新的偏好目标。

### Full FT 与 PEFT 的比较

不能只看训练 loss：

~~~text
目标任务质量
通用能力回归
安全和拒答
格式稳定
adapter / checkpoint 大小
训练显存和时间
推理额外开销
多任务管理
~~~

## 7.4 Capability Regression 与 Catastrophic Forgetting

### 什么是能力回归

后训练后，目标任务变好但其他能力下降，称为 capability regression。它可能影响：

~~~text
通用问答
多语言
代码
数学
事实性
长上下文
工具调用
安全边界
格式遵循
~~~

Catastrophic forgetting 是更严重的分布记忆丢失，常由窄数据、高学习率、训练过久或缺乏 replay 造成。

### 为什么只看目标 loss 不够

目标 loss 只观察训练任务。若领域数据很窄，loss 下降可能只是模型适应了风格或词汇，却没有获得可靠知识。必须冻结一组 base、SFT 和 aligned checkpoints，使用同一评估集分桶比较。

### 缓解手段

~~~text
降低学习率
减少训练步数
使用 LoRA 或部分参数更新
混合通用 replay 数据
保留多语言、代码和安全样本
early stopping
分桶评估
保留可回滚 checkpoint
~~~

每种手段都有成本和副作用。replay 过多会稀释目标任务，LoRA 可能限制深度适配，降低学习率可能导致目标能力不足。

### 回归报告

一个有用的回归表至少包含：

~~~text
base score
SFT score
aligned score
absolute change
relative change
confidence interval
language / domain slice
high-risk slice
worst bad cases
~~~

“平均值没有下降”不能掩盖高风险分桶的退化。

## 7.5 Preference Data：把相对偏好变成监督信号

### 为什么使用 pair

人类通常更容易回答“哪个回答更好”，而不是给一个回答一个稳定的绝对分。Preference pair 通常包括 prompt、chosen response 和 rejected response：

~~~text
x: 同一个任务
y_w: 被偏好的回答
y_l: 未被偏好的回答
metadata: 标注者、标准、领域、风险和版本
~~~

### 偏好标准

偏好可能依据：

~~~text
正确性
有帮助性
完整性
简洁性
格式
引用和证据
安全性
拒答合理性
语气与风格
~~~

如果多个标准混在一个标签里，模型很难知道冲突时如何取舍。高风险场景应保存细粒度 rubric 或多维标签。

### Preference margin

若质量分函数为 q，一个简单 margin 为：

~~~math
m=q(x,y_w)-q(x,y_l).
~~~

margin 太小，pair 可能是噪声；chosen 仍然明显错误时，偏好数据会把错误推向模型。也要保留“两个回答都不合格”或 tie，不要强迫标注者在两个坏答案中制造偏好。

### 长度偏差

标注者和 reward model 可能把篇幅误当成质量，偏好数据也会把这种相关性带入优化。但不能从“序列 log probability 按 token 求和”直接推出 DPO 必然偏好长答案：每项 log probability 非正，增加 token 会累加负数，而 DPO 比较的是 policy 相对 reference 的差值。最终长度偏置取决于数据、模型、归一化和训练过程。应统计 chosen/rejected 长度差、同任务内长度与 reward 的相关性，并单独评估简洁性；不能把改成 token 平均当作不改变目标的修补。

### 偏好数据分布

偏好数据常来自当前 SFT 模型生成的候选，因此会集中在模型已经会做的任务。需要加入困难、失败、拒答边界、事实性和长尾样本，否则对齐只会在熟悉分布内变好。

## 7.6 Reward Model：代理评分器的训练与校准

### Bradley-Terry 直觉

Reward model r_phi(x,y) 给每个回答一个标量。Bradley-Terry 模型把 chosen 胜出的概率写成：

~~~math
P(y_w\succ y_l\mid x)
=\sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right).
~~~

对应的 pairwise loss：

~~~math
L_{\mathrm{RM}}
=-\log\sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right).
~~~

它只约束相对顺序，不保证分数有绝对意义。不同 prompt 之间的 reward 可能不可直接比较。

### Reward model 的数据和组件

RM 需要 prompt、候选回答、偏好标签和长度/领域/风险元数据。训练时可使用 base 或 SFT backbone 加一个 scalar head。数据 collator 要分别处理 chosen/rejected 的 token、mask 和 response span。

### Pairwise accuracy

在验证集上检查 chosen reward 高于 rejected 的比例，可以判断排序拟合。但高 pairwise accuracy 不能证明：

~~~text
reward 分数校准
分布外稳定
事实性
安全性
长度公平
policy 优化后的真实质量
~~~

### Reward calibration

校准要看 reward margin 与人工胜率、质量等级、长度、领域和风险之间的关系。若 reward 对长答案、礼貌词或安全免责声明过度敏感，policy 可能学会表面策略。应保留 held-out human set 和高 reward 低质量样本。

### Reward-human gap

将reward变化与人工质量变化并列；若要计算数值差，应先把二者映射到同一事件和量纲。例如在独立偏好对上，以校准后的奖励胜率p_R和人工胜率p_H定义：

~~~math
G_{\mathrm{RH}}
=p_H-p_R.
~~~

这不是通用标准指标：必须说明校准集、事件定义和测试分布，不能直接拿任意尺度的raw reward减人工分。若没有可比较量纲，应分别报告曲线；gap按任务、长度、语言和风险切片分析。

## 7.7 RLHF、Policy、Reference、PPO 与 KL

### RLHF 流程

典型 RLHF 包含：

~~~text
base model
 -> SFT policy
 -> preference data
 -> reward model
 -> policy samples
 -> reward + reference KL
 -> PPO update
 -> capability / safety evaluation
~~~

Policy 是生成回答并被更新的模型；reference 通常是冻结的 SFT 副本，用来限制 policy 变化；reward model 提供代理分数。

### KL 约束

对固定 prompt x，可以把 policy 与 reference 的偏离写成序列分布的 KL 正则；下面是要最大化的目标，最小化 loss 时取其负号，训练还会对 prompt 分布求平均：

~~~math
J_{\mathrm{RLHF}}
=\mathbb{E}_{y\sim\pi_\theta}
\left[
r_\phi(x,y)
-\beta D_{\mathrm{KL}}
\left(\pi_\theta(\cdot\mid x)
\Vert
\pi_{\mathrm{ref}}(\cdot\mid x)\right)
\right].
~~~

beta 太大，policy 变化受限；太小，reward hacking 和语言退化风险增加。实际实现可能按 token 近似 KL，或把 KL 作为逐步 reward，必须区分公式和代码。

### PPO clip

PPO 用旧策略和新策略的概率比限制更新：

~~~math
r_t(\theta)
=\frac{\pi_\theta(a_t\mid s_t)}
{\pi_{\mathrm{old}}(a_t\mid s_t)}.
~~~

一个常见 clipped objective 是：

~~~math
L^{\mathrm{clip}}
=\mathbb{E}_t
\left[
\min\left(
r_tA_t,
\mathrm{clip}(r_t,1-\epsilon,1+\epsilon)A_t
\right)
\right].
~~~

上式写的是要最大化的surrogate objective；最小化loss时通常取负号。PPO clip改变相对旧policy的优化激励，不会把实际ratio硬性限制在区间内，也不保证KL上界；reference KL则是另一项软惩罚，不应混称硬约束。实际训练还可能监控KL并early stop。

### RLHF 的系统成本

训练时可能同时维护 policy、reference、reward model、value model、rollout engine 和 optimizer。通信、采样、序列长度、显存和失败重试会让 RLHF 远比一次 SFT 复杂。效果比较要报告采样预算和人工评估，不要只报 reward curve。

## 7.8 Reward Hacking、Goodhart 与 Over-Optimization

### Reward hacking

Reward hacking 是模型利用评分器漏洞取得高分，却不满足真实意图。常见形式：

~~~text
无意义变长
模板化安全声明
编造引用
过度自信
重复结论
过度拒答
规避困难问题
格式看似正确但内容为空
~~~

### Best-of-N 也会 over-optimize

从 N 个候选中按 reward 选最高分，相当于扩大寻找评分器漏洞的机会。N 越大，越可能选到 reward 高但人工质量低的极端样本。这个风险不只存在于 PPO，也存在于 reranking、LLM judge 筛选和自动合成数据。

### Goodhart

一个 proxy 变成优化目标后，可能不再代表真实目标。缓解方式是：

~~~text
多维 reward
独立人工 / 专家集
事实和代码 verifier
长度与格式护栏
分布外样本
高 reward 低质量抽检
early stopping
定期重训评分器
~~~

### 代理目标与真实目标

Cross entropy、reward、benchmark、judge score、用户点赞都可能是 proxy。任何 proxy 都要说明：

~~~text
它想近似什么
在哪些分布上有效
什么情况会失效
如何与独立指标对照
~~~

## 7.9 DPO 与直接偏好优化

### DPO 的核心目标

对 chosen y_w 和 rejected y_l，定义 policy 与 reference 的 log-probability margin：

~~~math
\Delta_\theta
=\log\pi_\theta(y_w\mid x)
-\log\pi_\theta(y_l\mid x),
~~~

~~~math
\Delta_{\mathrm{ref}}
=\log\pi_{\mathrm{ref}}(y_w\mid x)
-\log\pi_{\mathrm{ref}}(y_l\mid x).
~~~

常见 DPO loss：

~~~math
L_{\mathrm{DPO}}
=-\log\sigma
\left[
\beta(\Delta_\theta-\Delta_{\mathrm{ref}})
\right].
~~~

DPO 不显式训练 reward model，也不需要 PPO rollout，但它仍然是一个依赖偏好数据的优化方法。

### Log probability 的实现边界

原始DPO使用response条件序列log probability，即有效response token对数概率之和。改为按有效token平均会改变目标，不能仅视为等价实现；IPO、SimPO等变体的归一化应分别核对。必须明确：

~~~text
tokenizer
chat template
response start / end
label mask
sum or mean
reference checkpoint
beta
truncation
~~~

reference 必须冻结，且与 policy 使用相同的 tokenizer 和模板契约。

### Beta

在DPO的KL正则推导中，beta是偏离reference的惩罚系数：固定奖励下，最优策略满足π∝π_ref exp(r/beta)，较大beta对应更强的reference约束。与此同时，分类loss里beta又缩放margin，影响局部梯度和饱和；不能据此简单断言beta越大偏好更新越快。它与学习率、训练步数、标签噪声及序列归一化共同影响结果，应同时观察偏好胜率、KL、长度和能力回归。

### DPO 的失败边界

DPO 不会自动保证事实性，因为 chosen 可能也有错误；不自动解决安全，因为偏好标签可能过度拒答；不自动修复 reference mismatch，因为输入协议错误会让 logprob 比较失去意义。

## 7.10 IPO、KTO、ORPO 与 SimPO

DPO 之后出现的几个方法，主要在三个地方做取舍：是否保留 reference model，偏好数据是否必须成对，以及偏好项和监督项如何组合。它们都可以被归入“偏好优化”，但这不是说它们共享同一个 loss。阅读论文或调用训练器时，必须把数据格式、序列概率的长度归一化和温度参数一起记录。

### IPO：把偏好间隔当作需要校准的量

对初学者来说，DPO 的直觉是“让 chosen 相对于 rejected 的优势变大”。如果不断用同一批偏好对优化，模型可能把这个优势推得过大，最后不仅学会偏好，还改变了语言分布。IPO 的思路是给相对 reference 的偏好间隔一个目标值，而不是只用 logistic loss 继续推动它变大。

令

~~~math
\delta_\theta
=\left[\log\pi_\theta(y_w\mid x)-\log\pi_{\mathrm{ref}}(y_w\mid x)\right]
-\left[\log\pi_\theta(y_l\mid x)-\log\pi_{\mathrm{ref}}(y_l\mid x)\right],
~~~

[IPO 原论文第 5.2 节](https://arxiv.org/html/2310.12036v2#S5.SS2)的 sampled loss 可写成：

~~~math
L_{\mathrm{IPO}}
=\mathbb{E}
\left[\left(\delta_\theta-\frac{1}{2\tau}\right)^2\right],
\qquad \tau>0.
~~~

这里的 `\tau` 是原论文的正则强度，增大它会缩小目标间隔。不同训练库可能使用不同符号及长度口径，因此公式中的常数和命名不能脱离具体实现硬套。原论文将完整 generation 视为动作，公式中的概率是该动作概率；若训练器改为平均 token log probability，就必须明确这是其实现口径。若 `\tau=0.5`，目标间隔为 `1`；当前间隔为 `0.8` 或 `1.2` 时，单条样本平方误差都为 `0.04`，对间隔的导数分别为 `-0.4` 与 `0.4`。梯度下降会从两侧朝目标靠拢，而不是无限增大间隔。这是局部目标的性质，不能保证参数共享的模型同时满足所有偏好对。

专家需要特别检查：`\log\pi` 是整段 response 的和还是按有效 token 平均，chosen/rejected 是否共享 prompt，reference 是否冻结，以及截断后两条 response 是否仍有有效 token。IPO 不是事实性校验器，也不会修复错误的偏好标签；它只能改变偏好间隔的形状。

### KTO：从成对比较转向单条反馈

产品日志往往只有“用户喜欢/不喜欢”“通过/失败”或“编辑后重新提交”，并没有同一个 prompt 下的两个候选回答。KTO 适合把这类 desirable / undesirable 标签直接用于优化，代价是标签不再天然构成严格的相对比较。

KTO保留reference，用单条正负反馈构造带参考点的价值函数。令相对log-ratio为：

~~~math
r_\theta(x,y)=\log\frac{\pi_\theta(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)},
\qquad z_0=\mathbb{E}_{x'}D_{\mathrm{KL}}(\pi_\theta(\cdot\mid x')\Vert\pi_{\mathrm{ref}}(\cdot\mid x')).
~~~

用全局KL参考点的常见写法，令u=1为desirable、u=-1为undesirable，λ_D、λ_U为两类权重：

~~~math
v(x,y)=
\begin{cases}
\lambda_D\sigma(\beta(r_\theta-z_0)),&u=1,\\
\lambda_U\sigma(\beta(z_0-r_\theta)),&u=-1,
\end{cases}
\qquad
L_{\mathrm{KTO}}=\mathbb{E}[\lambda_u-v(x,y)].
~~~

这里λ_u按标签取λ_D或λ_U，β>0，类权重非负；KL参考点的估计、截零和停止梯度规则应按版本实现核对。关键区别是最大化有界sigmoid价值，而不是最小化负log-sigmoid二元交叉熵。例如权重1、β1、参考点0、log-ratio1时，好样本loss约0.268941，坏样本约0.731059；好样本的二元交叉熵则为0.313262，数值和梯度形状均不同。

KTO的关键工程问题还包括曝光偏差：没有被展示给用户的回答不会产生反馈，重度用户会贡献更多样本，用户点踩也可能反映延迟、风格或产品故障，而不是回答事实错误。

因此，使用 KTO 前应保存反馈发生的页面、展示候选、用户和任务切片、反馈时间、重复反馈和人工抽检结果。离线训练集中的“坏”只表示在特定上下文下收到负反馈，不能直接解释成所有用户、所有领域都应拒绝的行为。

### ORPO：把模仿和偏好放进一次训练

ORPO 将普通监督目标与偏好项结合，使训练过程不必单独维护 reference checkpoint。可以先用一个抽象式理解它：

~~~math
L_{\mathrm{ORPO}}
=L_{\mathrm{SFT}}+\lambda L_{\mathrm{pref}},
\qquad \lambda\geq0.
~~~

原论文的偏好项是odds-ratio loss，不能把普通log probability差直接称为ORPO。先对有效response的token log probability取平均，令其指数为P_θ(y|x)，再定义：

~~~math
\mathrm{odds}_\theta(y\mid x)=\frac{P_\theta(y\mid x)}{1-P_\theta(y\mid x)},
\qquad
L_{\mathrm{pref}}=-\log\sigma\left(\log\frac{\mathrm{odds}_\theta(y_w\mid x)}{\mathrm{odds}_\theta(y_l\mid x)}\right).
~~~

要求有效response非空、0<P<1，实际实现应使用稳定的log-odds计算。这里P是长度平均概率的指数，不是原始序列概率。若chosen/rejected的P分别为0.8/0.5，odds分别为4/1，偏好loss=-log(0.8)≈0.223144。λ=0时退化为SFT，增大λ不保证回答更正确；如果chosen只更礼貌，可能只强化礼貌模板。

ORPO 的工程收益是减少 reference 管理、额外前向计算和多阶段配置；它的代价是两个目标共用一次优化，学习率、数据比例和 `\lambda` 的影响更难分离。比较 ORPO 与 DPO 时不能只比较最终胜率，还要报告 SFT 基线、偏好数据质量、通用能力回归和相同的训练 token。

### SimPO：reference-free，但更依赖长度口径

[SimPO 原论文](https://arxiv.org/html/2405.14734v2)不维护 reference model，使用 policy 自身的平均 token log probability 作为隐式奖励，并引入目标奖励间隔。下面写的是单条偏好对的损失，训练目标再对数据求平均：

~~~math
L_{\mathrm{SimPO}}
=-\log\sigma\left(
\beta\left[
\frac{\log\pi_\theta(y_w\mid x)}{|y_w|}
-\frac{\log\pi_\theta(y_l\mid x)}{|y_l|}
\right]-\gamma
\right),
~~~

其中 `|y|>0` 是有效 response token 数，`\beta>0` 是尺度，`\gamma\geq0` 是目标奖励间隔。平均 log probability 差需要超过 `\gamma/\beta` 才使 sigmoid 内部值为正；它不是必须满足的硬约束。例如 chosen/rejected 的平均 log probability 为 `-0.4/-0.7`，取 `\beta=2,\gamma=0.2`，则分类 logit 为 `0.4`，损失约 `0.513015`。把两条回答的长度和 log probability 总和各翻倍，损失不变，这说明该目标没有直接惩罚总长度。

长度平均改变了不同长度样本的权重，却不自动保证简洁或质量提升；原论文也报告过偏好指标提升与部分下游任务退化并存。如果 response mask 把 EOS、工具参数或不可见控制 token 处理错，平均值就不再代表目标回答的评分口径。评估应同时检查长度、独立能力、安全与事实性，不能只检查训练偏好间隔。

### 如何比较这四种方法

可以先用下面的分工建立直觉：

~~~text
DPO：相对 reference 的成对偏好分类
IPO：把相对偏好间隔拉向目标值
KTO：利用单条 desirable / undesirable 反馈
ORPO：SFT 与偏好项联合优化
SimPO：不使用 reference 的长度归一化偏好目标
~~~

公平实验至少固定 base checkpoint、chat template、tokenizer、chosen/rejected 或反馈分布、有效训练 token、response 长度口径、评估集和计算预算。方法名字不能替代这些实验条件；尤其不能因为 reference-free 就推断训练一定更便宜，因为序列长度、batch、重算和回归评估仍决定总成本。

## 7.11 RLAIF、Constitutional AI 与安全数据

### RLAIF

RLAIF 通常指用 AI 模型产生偏好或评价反馈，并将其用于强化学习，降低人工逐条标注的成本。规则校验、单元测试等也是自动反馈来源，但纯规则奖励应按来源称为可验证奖励，不能只因没有人工标注就统称 RLAIF；用 AI 偏好做离线 DPO 也不等于执行了在线 RL。对初学者来说，AI 评审像把“请专家在两个回答中选一个”交给另一个模型完成；对专家来说，它新增了一个 judge policy，因而必须审计 judge 的训练分布、提示模板、置信度和与被评估 policy 的相互作用。

一个可重放的 RLAIF 流程至少包含：

~~~text
prompt / risk slice
 -> candidate responses
 -> AI judge or verifier
 -> label, score, rationale and uncertainty
 -> deterministic filter
 -> human calibration sample
 -> preference or reward dataset
~~~

AI feedback 适合扩大正常样本、边界样本和多语言样本的覆盖，但它并不自动等价于人类反馈。教师模型可能继承偏见，对分布外样本过度自信，或被待评估模型的表面格式操纵。若 judge 只看到最终文本而看不到工具证据，它还可能把未经验证的断言标成高质量。

使用 AI feedback 时应保留人工金标准集，按风险、语言、领域和长度校准，并定期抽检 AI 与人类的分歧。若人工标签为 `h`、AI 标签为 `a`，一个最小一致率可以写成：

~~~math
C_{\mathrm{AI-human}}
=\frac{1}{N}
\sum_{j=1}^{N}\mathbf{1}[a_j=h_j],
\qquad N>0.
~~~

一致率只能说明标签是否相同，不能证明 AI judge 的判断正确；高风险集合还应报告人工复核优先级、漏判率和 abstain/转人工比例。

### Constitutional AI

Constitutional AI 用明确原则指导批评、修订和偏好反馈。一个最小流程是：先让模型生成回答，再让模型依据原则指出问题并提出修订，最后把原回答和修订后的回答用于偏好或安全训练。

~~~math
c=\mathrm{Critique}_{P}(x,y),
\qquad
y'=\mathrm{Revise}(x,y,c,P),
~~~

其中 `P` 是原则集合，`c` 是批评，`y'` 是修订结果。这组式子描述流程，不是安全证明：原则可能含糊、相互冲突或无法覆盖工具权限，模型也可能生成形式上符合原则、实质上仍有风险的修订。

例如，“尽量有帮助”和“不要提供危险操作细节”同时存在时，合格输出可能是解释风险、给出防护步骤并建议合法替代，而不是简单拒绝或完整照做。原则应当与风险分类、权限检查、工具 verifier 和人工升级路径共同存在；把一段 constitution 当作 system prompt 再训练一次，不能替代这些运行时约束。

### 安全对齐

安全数据要覆盖：

~~~text
应拒绝的高风险请求
可以回答的正当教育 / 防护请求
部分回答和安全替代
隐私与越权
prompt injection
危险工具调用
过度拒答边界
多语言和隐晦表达
~~~

每个高风险请求最好同时构造一个语义相近、目的正当的可回答请求。这样才能判断模型是在识别风险，还是学会了看到某些关键词就拒答。安全不是拒答率越高越好。要同时测 false refusal rate 和 unsafe leak rate，并把“部分回答”“安全替代”“转人工”和“工具被阻断”分别记录。

### 两个核心指标

在安全可答请求集合上：

~~~math
\mathrm{FRR}
=\frac{N_{\mathrm{false\_refusal}}}
{N_{\mathrm{safe\_answerable}}}.
~~~

在应拒答或限制集合上：

~~~math
\mathrm{ULR}
=\frac{N_{\mathrm{unsafe\_direct\_answer}}}
{N_{\mathrm{should\_refuse}}}.
~~~

两个指标的分母、风险分层和人工判断必须明确。对应集合为空时指标未定义，应报告无样本及数量，不能记作零风险。修复 ULR 时若把所有边界样本改成拒答，FRR 往往会上升。

## 7.12 RLVR、GRPO、DAPO、GSPO 与 Dr. GRPO

### Verifiable reward

RLVR 使用代码测试、数学答案、工具执行、格式校验或环境结果等可验证 reward。一个简化的奖励可以写成：

~~~math
r(x,y)
=w_c r_{\mathrm{correct}}
+w_f r_{\mathrm{format}}
-w_u r_{\mathrm{unsafe}}.
~~~

这里把 `r_{\mathrm{unsafe}}` 定义为风险或违规程度，`w_c,w_f,w_u\geq0` 是权重。奖励组合不是越多越好。格式 reward 太强会鼓励模型输出漂亮但错误的答案；测试用例泄漏会让代码 reward 虚高；不完整 verifier 会把错误解判为正确。若安全分量已经是“越高越安全”的正向分数，就不应再机械地套用负号，而应先统一各分量的方向。

### GRPO

GRPO 对同一 prompt 采样一组回答 y_1,\ldots,y_G，得到奖励 r_1,\ldots,r_G，用组内相对值构造优势：

~~~math
A_i
=\frac{r_i-\mathrm{mean}(r)}
{\mathrm{std}(r)+\epsilon}.
~~~

这里要求 `G\geq2` 且 `\epsilon>0`；`std` 是组内标准差，具体使用总体还是样本估计要在实现中固定。若一组回答得到完全相同的 reward，分子为零，组内优势不会提供区分信号；这不等于题目简单，也可能表示 verifier 没有分辨率。GRPO 减少了对独立 value model 的依赖，但组内奖励方差、采样多样性、组大小、全零奖励和长度归一化都会影响学习信号。GRPO 是优化方法，RLVR 是奖励来源或任务范式，二者不能混为一谈。

### DAPO：把长回答训练拆成多个可观测问题

DAPO 是 `Decoupled Clip and Dynamic Sampling Policy Optimization` 的缩写，公开方案把大规模 reasoning RL 中常见的几个问题放在一起处理：策略比率的 clipping、动态采样、token-level 优化和超长回答的 reward 处理。它不是一个可以脱离数据和 rollout 配置的万能 loss。

为理解“decoupled clip”，可以把 token 级目标写成一个示意形式：

~~~math
L_{\mathrm{DAPO}}^{\mathrm{schematic}}
=-\frac{1}{\sum_t m_t}
\sum_t m_t\min\left(
\rho_t A_t,
\mathrm{clip}(\rho_t,1-\epsilon_{\mathrm{low}},1+\epsilon_{\mathrm{high}})A_t
\right),
~~~

其中 `\rho_t=\pi_\theta(a_t\mid s_t)/\pi_{\mathrm{old}}(a_t\mid s_t)`，`m_t` 表示有效 response token，`\epsilon_{\mathrm{low}}` 和 `\epsilon_{\mathrm{high}}` 可以分别设定。这里的式子只用于说明 token 粒度和非对称 clipping 的含义；完整 DAPO 训练还要结合论文中描述的采样、奖励和长度策略，不能把这行式子当作所有代码的默认实现。

在 [DAPO 原论文第 3.2 节](https://arxiv.org/html/2503.14476v1#S3.SS2)的二元正确性奖励设置中，动态采样会过采样并过滤组内准确率为 0 或 1 的题目，直到凑足目标数量的有效题目组。两类组的相对优势都为零：全对不代表还能提供组内比较信号，全错也不等于永远学不会。若另有 KL 等辅助项，优势为零不代表所有损失梯度都为零。

例如三组奖励分别为 `[0,0,0,0]`、`[1,1,1,1]` 和 `[0,0,1,1]`，前两组被过滤，第三组保留；按总体标准差且忽略数值稳定项，其优势为 `[-1,-1,1,1]`。只保留混合结果会改变实际训练分布，不能把保留后的平均奖励当作原始题池成功率。如果几乎所有题目组都被过滤，补采样也可能非常昂贵，应设置采样预算并监控有效组比例。若超长回答一律重罚，模型还可能学会提前结束而不是更好的推导。评估时应同时报告有效样本率、题目难度分布、回答长度、验证通过率、截断率、每个成功样本的 rollout 成本和独立测试集成绩。

### GSPO：把 importance ratio 提升到序列级

GRPO 常在 token 级计算并截断 policy ratio，不需要先把所有 token 比率连乘。长 reasoning 中，局部比率的波动会影响哪些 token 获得更新。[GSPO 原论文第 4.1 节](https://arxiv.org/html/2507.18071v1#S4.SS1)改用长度归一化的序列比率，在回答级构造目标。其形式是：

~~~math
R_i(\theta)
=\exp\left(
\frac{1}{|y_i|}
\sum_{t=1}^{|y_i|}
\left[\log\pi_\theta(y_{i,t}\mid s_{i,t})
-\log\pi_{\mathrm{old}}(y_{i,t}\mid s_{i,t})\right]
\right),
~~~

再用组内优势构造：

~~~math
L_{\mathrm{GSPO}}^{\mathrm{schematic}}
=-\mathbb{E}_i\left[
\min\left(R_iA_i,
\mathrm{clip}(R_i,1-\epsilon,1+\epsilon)A_i\right)
\right].
~~~

例如两步的 token ratio 为 2 和 0.5，未归一化的序列比率为 1，GSPO 的几何平均比率也为 1；token 级截断却会分别处理两个偏离 1 的比率。因此它既不是 token ratio 的算术平均 1.25，也不等价于逐 token clip。重复这两步后几何平均仍为 1，说明长度归一化如何控制比率尺度。

序列级更新让一条回答的 token 共享回答级截断决策；GRPO 的 outcome-reward 版本本来也可能共享同一组内优势，不能把这一点说成 GSPO 独有。GSPO 的比率经过长度归一化，不能直接沿用 token 级算法的 clip 超参数，也不能把它当作未归一化的重要性采样权重。`|y_i|` 必须是参与策略概率计算的有效生成 token 数且大于零，工具返回等非策略生成内容不能直接混入；EOS 与截断 token 的规则也要固定。因此比较 GSPO、GRPO 和 DAPO 时，必须对齐 ratio 粒度、clip、reward、长度归一化、采样规则和停止条件。

### Dr. GRPO：先诊断长度偏置，再谈效率

Dr. GRPO 不是“又一个更大的模型”，而是针对 R1-Zero-like 训练中 GRPO 长度偏置的一种分析和修正方向。若目标把每条回答的 token loss 除以自身长度，模型可能通过生成更长的回答改变总更新量，甚至让错误回答也变长。一个抽象的对照是：

~~~math
L_{\mathrm{token}}
=-\frac{1}{M}
\sum_{i,t}m_{i,t}
\min\left(\rho_{i,t}A_i,
\mathrm{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i\right),
~~~

对Dr.GRPO，A_i使用r_i减组均值，去掉组内std除法以消除其讨论的题目难度偏置；还用固定最大生成长度而不是每条回答自己的长度归一化。例如batch含B组、每组G条时可取M=BGL_max，mask只选择实际response token，L_max不随当前回答长度变化。它不是动态有效token总数，也不是只删掉长度项就完整实现了修正；具体KL、clip与损失尺度按版本核对。诊断时同时观察reward、长度、正确率、截断率和题目难度，不能只看平均长度。

### DeepSeek-R1 的启发与边界

DeepSeek-R1 让可验证 reward、在线采样、reasoning RL、GRPO 和蒸馏成为公开讨论的代表路线。它带来的重要启发不是“只要上 RL 就会出现推理”，而是 base model、提示格式、验证器、采样预算、奖励稀疏性和训练稳定性共同决定结果。阅读公开资料时要区分论文明确报告的训练阶段、模型卡信息和外部推测，不把一个模型的结果归因到单一算法，也不把公开 benchmark 直接当作所有任务的保证。

## 7.13 Reasoning Effort、On-Policy Distillation 与 Tool Trajectory

### Reasoning effort

reasoning effort 是运行时对推理预算、思考长度、工具次数或模型模式的控制。它首先是一个调度变量，不等于公开了模型内部使用的算法，也不等于给了模型更高的工具权限。不同厂商的同名参数不一定有相同语义，必须通过文档和日志确认它是否改变隐藏 token、可见输出、采样次数、工具调用或停止条件。

对一个任务切片 `q` 和 effort 档位 `e`，可以用一个简化效用来思考路由：

~~~math
U(e\mid q)
=P_{\mathrm{success}}(e\mid q)
-\lambda C(e\mid q)
-\mu R(e\mid q),
\qquad \lambda,\mu\geq0.
~~~

`C` 可以包含 token、GPU 时间和工具费用，`R` 可以包含超时、错误累积和安全风险。这个式子不是厂商内部目标，而是提醒我们不能用一次 benchmark 的准确率决定所有请求都使用最高 effort。简单任务可能出现质量不变而成本上升，复杂任务则可能在某个预算之后进入收益递减。

提高 effort 可能提高复杂任务成功率，也会增加延迟、成本、上下文占用和错误累积。应报告：

~~~text
任务成功率
单位成功任务成本
TTFT / total latency
输出或隐藏 token
工具调用次数
安全失败率
简单任务退化
~~~

### On-policy distillation

On-policy distillation 先从学生当前策略采样，再获取教师指导，使训练覆盖学生实际到达的历史状态。它缓解固定教师轨迹与学生轨迹之间的分布偏移；只有任务、工具环境和采样配置接近部署时，才能进一步认为这些状态更接近部署分布。代价是每轮的 rollout 和教师成本，且学生可能反复到达错误状态。规则或 verifier 只提供成败标签时，仍需另行构造学习目标，不能直接代入教师 token 分布的蒸馏公式。

若学生生成轨迹 `y`，教师给出目标 token 分布 `q_\phi`，一个简化的蒸馏损失可以写成：

~~~math
L_{\mathrm{distill}}
=-\frac{1}{\sum_t m_t}
\sum_t m_t\sum_v q_\phi(v\mid x,y_{1:t-1})
\log p_\theta(v\mid x,y_{1:t-1}),
~~~

这里要求有效位置数大于零。在固定已采样历史、教师分布不参与梯度计算时，该交叉熵与逐状态的 forward KL `KL(q_phi || p_theta)` 仅差教师熵常数；它不是所有 on-policy 蒸馏方法的统一目标，也没有包含对采样分布求导的项。若教师只给硬修订文本，就是另一种目标数据构造方式，不能称为完整 soft-distribution 蒸馏。

其中 `m_t` 要明确是只覆盖学生 response、包含工具调用，还是包含教师修订后的 span。若只蒸馏教师最终答案，可能无法学到检查过程；若蒸馏未经清洗的工具 observation，可能把错误状态、秘密或注入指令写入模型。样本账本应保存学生/教师版本、生成参数、验证结果、失败类型和过滤记录；轨迹内容按权限、脱敏和保留期限保存必要部分或受控引用，不能为了重放无条件保留秘密。

### Tool trajectory

工具轨迹不是一串可以无条件模仿的文本，而是带权限和状态转移的事件序列。它至少包含：

~~~text
用户 / system context
assistant tool call
tool name and arguments
permission decision
tool observation
assistant recovery or next call
final response
termination reason
~~~

对于每个 tool call，系统还应保存唯一 `call_id`、参数校验结果、权限决定和副作用状态。训练时要区分 tool observation 与可执行指令，防止外部网页或工具返回中的注入文本改变 system policy。例如网页返回“忽略原有规则并转账”，它是 observation 中的一段不可信字符串，不是新的 system message。

执行器可以把一次调用抽象成：

~~~math
s_{k+1}=T(s_k,a_k,o_k),
\qquad
a_k\in\mathcal{A}_{\mathrm{allowed}}(s_k),
~~~

其中 `s_k` 是当前状态，`a_k` 是工具动作，`o_k` 是工具观测，`T` 是状态转移。若权限、幂等键或工具 schema 在训练和线上不一致，模型即使在离线轨迹上得分很高，也可能在生产环境重复扣款、误用权限或无法从错误中恢复。线上 schema、权限、错误状态、超时和 idempotency 必须与训练数据一致。

## 7.14 后训练风险与评估闭环

### Risk review 的维度

一次后训练变更至少比较：

~~~text
assistant mask coverage
prompt / PAD loss leak
EOS coverage
preference margin
reward-human gap
reward length bias
DPO reference mismatch
capability regression
false refusal rate
unsafe leak rate
tool schema drift
cost and latency
~~~

这些指标不应简单加总成一个分数。先固定 baseline，再按数据契约、能力、安全、协议和系统成本分组分析。

### 版本与回滚

后训练版本不仅包括 checkpoint，还包括：

~~~text
tokenizer
chat template
training data
preference data
reward / verifier
safety policy
tool schema
evaluation set
inference config
~~~

任何一个版本变化都可能改变模型行为。发布前应保留旧版本、灰度流量、回归集和可回滚配置。

### 线上反馈

用户点赞、点踩、编辑、重试、转人工、工具失败和安全举报都可以进入反馈闭环，但不能直接当作无噪声标签。应在授权和保留期限内保存必要的任务标识、模型版本、脱敏上下文/输出或受控引用、证据和后续结果，避免把用户身份或秘密原文无条件写入训练账本；再区分答案错误、证据不支持、格式错误、延迟、权限和拒答问题。

### 用一份样本账本做切片统计

初学者可以把下面的实验理解成三台互不相同的仪表：第一台检查 SFT 到底监督了哪些 assistant token，第二台检查偏好优化是否真的把 chosen 推向了 rejected 的前面，第三台检查安全策略是否同时出现了误拒和漏答。它们都使用“比例”或“分数”，但分母和含义不同，不能相加后冒充一个综合质量分。

专家在实现时还要记录样本来源、模型版本、tokenizer、chat template、评估切片和人工复核状态。下面的字典只是教学用的最小事件账本；生产系统应把同样的字段写入可追溯的评估产物，并为每个分母保存样本 id。

~~~python
from math import exp, isfinite, log1p


def ratio(numerator, denominator):
    if any(isinstance(value, bool) or not isinstance(value, (int, float))
           for value in (numerator, denominator)):
        raise ValueError("ratio inputs must be numbers, not bool")
    if not all(isfinite(float(value)) for value in (numerator, denominator)):
        raise ValueError("ratio inputs must be finite")
    if numerator < 0 or denominator < 0:
        raise ValueError("ratio inputs must be non-negative")
    if denominator == 0:
        return None
    return numerator / denominator


def log1p_exp(value):
    if not isfinite(value):
        raise ValueError("log1p_exp input must be finite")
    if value > 0:
        return value + log1p(exp(-value))
    return log1p(exp(value))


def dpo_loss(policy_chosen, policy_rejected,
             reference_chosen, reference_rejected, beta=0.1):
    values = (
        policy_chosen, policy_rejected,
        reference_chosen, reference_rejected,
    )
    if any(isinstance(value, bool) or not isinstance(value, (int, float))
           or not isfinite(value) or value > 0 for value in values):
        raise ValueError("log probabilities must be finite and non-positive")
    if (isinstance(beta, bool) or not isinstance(beta, (int, float))
            or not isfinite(beta) or beta <= 0):
        raise ValueError("beta must be finite and positive")
    policy_margin = policy_chosen - policy_rejected
    reference_margin = reference_chosen - reference_rejected
    z = beta * (policy_margin - reference_margin)
    if not isfinite(z):
        raise ValueError("scaled DPO margin is not finite")
    # -log(sigmoid(z))，用分支避免教学示例在极端 z 上溢出。
    if z >= 0:
        return log1p_exp(-z)
    return -z + log1p_exp(z)


def print_metric(name, value):
    if value is None:
        print(f"{name}=unknown")
    else:
        print(f"{name}={value:.3f}")


rows = [
    {
        "assistant_expected": 4,
        "assistant_enabled": 4,
        "policy_chosen": -2.0,
        "policy_rejected": -3.0,
        "reference_chosen": -2.2,
        "reference_rejected": -2.8,
        "safe_answerable": True,
        "refused": False,
        "should_refuse": False,
        "unsafe_direct": False,
    },
    {
        "assistant_expected": 5,
        "assistant_enabled": 4,
        "policy_chosen": -3.2,
        "policy_rejected": -2.7,
        "reference_chosen": -3.0,
        "reference_rejected": -2.9,
        "safe_answerable": True,
        "refused": True,
        "should_refuse": False,
        "unsafe_direct": False,
    },
    {
        "assistant_expected": 3,
        "assistant_enabled": 3,
        "policy_chosen": -1.8,
        "policy_rejected": -2.6,
        "reference_chosen": -1.9,
        "reference_rejected": -2.4,
        "safe_answerable": False,
        "refused": False,
        "should_refuse": True,
        "unsafe_direct": True,
    },
]

if not rows:
    raise ValueError("the teaching ledger must contain at least one row")

for row in rows:
    counts = (row["assistant_expected"], row["assistant_enabled"])
    if any(type(value) is not int or value < 0 for value in counts):
        raise ValueError("assistant token counts must be non-negative integers")
    if counts[1] > counts[0]:
        raise ValueError("enabled assistant tokens exceed expected tokens")
    flags = ("safe_answerable", "refused", "should_refuse", "unsafe_direct")
    if any(type(row[key]) is not bool for key in flags):
        raise ValueError("safety flags must be bool")
    if row["safe_answerable"] and row["should_refuse"]:
        raise ValueError("safe and restricted slices must not overlap")
    if row["unsafe_direct"] and (not row["should_refuse"] or row["refused"]):
        raise ValueError("unsafe direct answer has inconsistent safety flags")

expected = sum(row["assistant_expected"] for row in rows)
enabled = sum(row["assistant_enabled"] for row in rows)
assistant_coverage = ratio(enabled, expected)

losses = [
    dpo_loss(
        row["policy_chosen"], row["policy_rejected"],
        row["reference_chosen"], row["reference_rejected"],
    )
    for row in rows
]
positive_dpo_margin = sum(
    (row["policy_chosen"] - row["policy_rejected"])
    > (row["reference_chosen"] - row["reference_rejected"])
    for row in rows
)

safe_rows = [row for row in rows if row["safe_answerable"]]
risky_rows = [row for row in rows if row["should_refuse"]]
false_refusal_rate = ratio(
    sum(row["refused"] for row in safe_rows), len(safe_rows)
)
unsafe_leak_rate = ratio(
    sum(row["unsafe_direct"] for row in risky_rows), len(risky_rows)
)

print_metric("assistant_coverage", assistant_coverage)
print(f"mean_dpo_loss={sum(losses) / len(losses):.3f}")
print(f"positive_dpo_margin={positive_dpo_margin / len(rows):.3f}")
print_metric("false_refusal_rate", false_refusal_rate)
print_metric("unsafe_leak_rate", unsafe_leak_rate)

assert assistant_coverage < 1.0
assert false_refusal_rate == 0.5
assert unsafe_leak_rate == 1.0
assert ratio(0, 0) is None
~~~

这个结果只说明三条诊断信号在这三个教学样本上的数值关系：有一个 assistant token 没有被监督，有一半本来可安全回答的请求被误拒，一个应限制的请求被直接回答。`ratio(0, 0)` 返回 `None` 并显示为 `unknown`，表示没有可评估样本，而不是一个可以参与平均的数值。代码还拒绝负数、非有限分母和非法 beta；这些是教学审计器的输入契约，不是完整训练框架的替代品。它不能证明模型整体安全，也不能证明 DPO 一定有效。下一步应把样本按语言、领域、长度、风险等级和数据来源分桶，并把异常样本交给人工复核；只有这样，数字才有可解释的上下文。

### 成功条件

一个后训练模型的成功，不应只定义为 reward 或 benchmark 提升。可以写成：

~~~math
S
=S_{\mathrm{instruction}}
\land S_{\mathrm{quality}}
\land S_{\mathrm{safety}}
\land S_{\mathrm{format}}
\land S_{\mathrm{regression}}
\land S_{\mathrm{cost}}.
~~~

这是一种评估逻辑，不是新的训练公式。它强调模型发布需要多个条件同时满足。

## 本章回顾

后训练与对齐的完整链路是：

~~~text
高质量 instruction data
 -> SFT 与正确 mask
 -> preference / reward data
 -> RM / DPO / RLHF / other preference methods
 -> safety and verifiable feedback
 -> reasoning / tool trajectories
 -> capability, safety, protocol and cost evaluation
 -> release, monitoring and rollback
~~~

真正需要理解的不是某个方法名字，而是四个边界：模型被什么数据监督，loss 到底覆盖哪些 token，代理 reward 是否仍代表真实目标，以及模型行为是否在权限、工具、成本和安全系统中保持一致。后训练的技术复杂度最终都要回到这些可验证事实。

### DeepSeek V3.2：公开的 scalable RL 与 Agent 数据边界

[DeepSeek V3.2 模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V3.2/blob/main/README.md)把 scalable RL framework 和 large-scale agentic task synthesis pipeline 列为技术主线。[技术报告第 3 节](https://arxiv.org/html/2512.02556v1#S3)明确 V3.2 采用 specialist distillation 加 mixed RL，并在一个 RL stage 中合并 reasoning、agent 和 human alignment，使用 GRPO。[第 3.1 节](https://arxiv.org/html/2512.02556v1#S3.SS1)披露的稳定化措施分别针对不同问题：

- 使用重要性采样修正 KL 估计，报告同时讨论估计值及梯度的无偏性；这依赖其采样和求导约定，不能只换一个公式名称就保证实现无偏。
- 对负优势且采样策略与当前策略偏离超过阈值的序列屏蔽策略梯度项，不是删除所有失败轨迹，也不意味着其 KL 项一并消失。
- Keep Routing 记录采样时 MoE 专家路径并在训练中沿用，减少训练/推理路由不一致。
- Keep Sampling Mask 将采样时 top-p/top-k 截断 mask 用于训练策略，保持相同动作子空间；它不同于 response loss mask。

这些措施解释了部分训练不一致问题，但不足以单独还原完整训练与部署配方；效果仍需结合奖励、采样预算、优化配置和实现核验。

对面试回答而言，这能把“推理能力来自 RL”展开成可审计的数据闭环：任务定义、环境与工具接口、轨迹生成、结果验证、困难样本筛选、失败轨迹处理、污染检查以及最终后训练目标。报告还列出 code/search/general/interpreter Agent 任务规模和 verifier 约束，但这些是训练数据描述，不是 DataCurve 的 Agent 评测结果。

同样要把 checkpoint 和运行时协议分开：V3.2 支持 `thinking with tools`，而 V3.2-Speciale 被官方定位为深度推理变体且不支持 tool calling。reasoning token、工具调用协议和宿主执行器是不同层，模型输出工具调用不等于动作已提交。评测时应同时记录 reasoning/tool 状态回放、schema/权限门禁、verifier 结果和最终 artifact，而不是只看最终答案。
