# 第 17 章 图像生成与视频生成：从随机性到可控的视觉结果

## 17.0 生成一张图，实际上要解决多少问题

图像生成和视频生成并不只是把 prompt 变成一张好看的图片。系统首先要把文本、参考图、布局、姿态或深度等条件转换成模型能够使用的表示，然后选择在像素、latent 或离散视觉 token 空间中生成，最后还要检查结果是否兑现了主体、属性、数量、空间关系、动作和安全约束。

视频在图像问题上增加了时间维度。同一个人、物体和场景要在连续帧中保持身份、纹理、遮挡、运动和光照关系；一个单帧很漂亮的结果，如果人物每秒换一张脸、物体穿过墙壁或镜头运动突然跳变，仍然不是可用视频。

初学者可以把生成系统想成“表示器—生成器—解码器”的链路：表示器把条件和目标数据转换成可计算的形式，生成器从噪声或 token 开始逐步形成视觉内容，解码器把 latent 或离散 token 还原成图片、视频或音频。工程读者还要把采样步数、分辨率、压缩比、显存、延迟、版权、来源和人工编辑成本写进同一张账本。

本章沿着八条主线展开：生成路线和空间选择、扩散模型数学、U-Net/DiT/VAE、条件控制与图像编辑、视频的时空表示和运动先验、world model 边界、图像/视频评估，以及安全、版权和产品取舍。每个主题都说明它解决什么问题，也说明它不能解决什么问题。

## 17.1 三条生成路线：扩散、自回归和统一建模

### 扩散模型

扩散模型把生成任务拆成一串去噪步骤。训练时先把真实样本破坏成不同噪声等级，模型学习在每个等级上预测去噪方向；生成时从随机噪声开始，按时间顺序还原内容。它的优点是训练目标相对稳定、条件控制和编辑生态成熟，代价是通常需要多次网络调用。

### 自回归视觉 token

自回归路线先用视觉 tokenizer 把图像或视频压缩成离散 token，再用 Transformer 逐个预测 token。它和语言模型的 next-token prediction 统一，方便把文字和视觉 token 放在一条序列中；代价是高分辨率下序列很长，生成速度和 tokenizer 重建质量成为瓶颈。

### 统一多模态建模

统一模型可能共享表示、共享 Transformer 或共享训练目标。它有机会让文本、图像、音频和视频在同一个上下文中交互，但不同模态的 token rate、解码器、质量指标和安全边界差异很大。接口统一并不等于架构统一：一个中心 LLM 调用多个专用生成器，也可以提供统一助手体验。

### 图像生成路线如何一步步转移瓶颈

“扩散还是自回归”太粗，无法说明一项研究真正解决了什么。把代表工作放在同一张问题图上，能看到瓶颈从序列长度，转移到语义表示、像素计算、条件注入和骨干扩展：

| 代表路线 | 当时要解决的问题与机制 | 得到什么、又留下什么 |
| --- | --- | --- |
| [DALL·E 1](https://arxiv.org/abs/2102.12092) | 用离散视觉 tokenizer 将图像编码成 token，再让自回归 Transformer 按文本和先前视觉 token 逐个生成。 | 文本与图像可以共享 next-token 训练范式；高分辨率需要很长的串行 token 序列，图像质量也受 tokenizer 重建上限约束。 |
| [DALL·E 2（unCLIP）](https://arxiv.org/abs/2204.06125) | 先由 prior 根据文本生成 CLIP 图像 embedding，再由 diffusion decoder 从 embedding 生成像素图像。 | 把语义表示预测和像素合成拆开，论文观察到多样性提升而照片真实感和 caption 相似度损失较小；CLIP embedding 会压掉非关键细节，因此 decoder 不能恢复输入表示从未保留的信息。 |
| [Imagen](https://arxiv.org/abs/2205.11487) | 以冻结的文本编码器（论文研究 T5）提供语言条件，再用级联扩散模型逐级生成和放大图像。 | 论文的消融显示，扩大文本编码器对图文对齐和样本质量的作用可超过扩大图像扩散模型；多级模型让推理链更长，COCO FID 7.27 和 DrawBench 人评只对应论文数据、版本和协议。 |
| [Latent Diffusion](https://arxiv.org/abs/2112.10752) | 先由感知压缩 autoencoder 把像素映射到较小 latent 网格，再在 latent 上做扩散，并以 cross-attention 接入文本等条件。 | 显著减小高分辨率 denoiser 的空间计算；压缩与 decoder 的信息损失成为文字、细线和几何细节的上限。 |
| [DiT](https://arxiv.org/abs/2212.09748) | 把带噪 latent 切成 patch token，用 Transformer block 建模，并用 timestep/条件调制 block。 | 论文展示 FLOPs、模型规模和 FID 的 scaling 关系；其 2.27 FID 是 class-conditional ImageNet 256×256 结果，不能当成文生图对齐或所有分辨率的排名。attention 计算仍随 token 数快速增长。 |

这不是把不同时期的分数排成排行榜，而是追踪问题如何迁移：DALL·E 2 把像素合成从语言模型中拆出，Imagen 和 Latent Diffusion 分别调整语言条件与生成空间，DiT 再检验 Transformer 是否能扩展去噪主干。选型或改进时，先找当前系统的限制是在条件表达、视觉 token、VAE 保真、采样调用还是 backbone 吞吐，再决定改哪一环。

选择路线时先固定 workload：输出分辨率和时长、是否要求编辑、可接受延迟、GPU 预算、是否需要与文本模型共享 token，以及安全和版权要求。不能把“扩散更先进”或“自回归更统一”当成脱离任务的结论。

## 17.2 Diffusion Model：把一次生成拆成许多局部预测

扩散模型包含两个过程：

| 过程 | 做什么 | 是否由模型学习 |
| --- | --- | --- |
| Forward Diffusion | 从真实数据逐步加入噪声 | 通常由噪声日程固定 |
| Reverse Denoising | 从噪声逐步恢复数据 | 由神经网络学习 |

设真实样本为 `x_0`，时间步为 `t`，条件为 `c`。训练时随机采样 `t`，构造一个带噪样本 `x_t`，让模型根据 `x_t,t,c` 预测噪声、干净样本或 velocity。生成时从近似高斯噪声开始，重复应用去噪模型和采样器。

这条路线的关键直觉是：模型不必一次学会“从任意噪声直接画出完整图片”，而是学习在当前噪声水平下应该往哪个方向移动。不同时间步的信号强弱不同，因此模型实际面对的是一组难度不同的条件预测任务。

## 17.3 Forward Diffusion：可控地破坏信号

### 马尔可夫加噪过程

给定 `x_{t-1}`，一个常见的前向过程是：

~~~math
q(x_t\mid x_{t-1})
=
\mathcal{N}
\left(
x_t;
\sqrt{\alpha_t}x_{t-1},
\beta_t I
\right),
\qquad
\alpha_t=1-\beta_t
~~~

`\beta_t` 是第 `t` 步的噪声强度，`\alpha_t` 是本步保留的信号比例。累计保留比例为：

~~~math
\bar{\alpha}_t=\prod_{u=1}^{t}\alpha_u
~~~

当时间步增大时，`\bar{\alpha}_t` 通常减小，`x_t` 中原始样本的信号变弱。

这个写法隐含每一步满足 `0<\beta_t<1`，因此 `0<\alpha_t<1`。若日程中出现非正噪声、噪声强度不小于一，或时间步索引与累计乘积错位，前向分布和后面的开方都会失去原有含义；这类错误常表现为训练初期就产生 `NaN`，却不应被归因于模型容量。

### 闭式采样与 SNR

前向过程可以直接写成：

~~~math
x_t=
\sqrt{\bar{\alpha}_t}x_0+
\sqrt{1-\bar{\alpha}_t}\epsilon,
\qquad
\epsilon\sim\mathcal{N}(0,I)
~~~

因此训练时不需要真的执行 `1,2,\ldots,t` 个加噪步骤，只需随机选 `t`，一次性构造 `x_t`。信噪比可以粗略写成：

~~~math
\mathrm{SNR}(t)
=
\frac{\bar{\alpha}_t}{1-\bar{\alpha}_t}
~~~

该比率只在 `0<\bar{\alpha}_t<1` 时有定义；把 `t=0` 的无噪声状态代入会得到无穷大，它不是一个可以和有限时间步平均的普通样本。高 SNR 时间步仍保留较多内容，低 SNR 时间步更接近纯噪声。时间步采样和损失加权会改变训练重点；如果只看总 loss，不知道模型在哪些噪声范围上变好，就无法解释细节、结构或 prompt 遵循的变化。

## 17.4 Reverse Denoising：模型到底预测什么

### 噪声预测目标

最经典的训练目标是预测加入的真实噪声：

~~~math
L_{\epsilon}
=
\mathbb{E}_{x_0,t,\epsilon,c}
\left[
\left\|
\epsilon-
\epsilon_\theta(x_t,t,c)
\right\|_2^2
\right]
~~~

`\epsilon_\theta` 是网络预测的噪声，期望表示对数据、时间步、噪声和条件的采样平均。根据预测噪声可以估计干净样本：

~~~math
\hat{x}_0
=
\frac{x_t-
\sqrt{1-\bar{\alpha}_t}\epsilon_\theta(x_t,t,c)}
{\sqrt{\bar{\alpha}_t}}
~~~

### 三种常见参数化

| 参数化 | 预测对象 | 解释 |
| --- | --- | --- |
| epsilon prediction | 加入的噪声 | 经典 DDPM 目标，直观 |
| x0 prediction | 干净样本 | 直接描述最终数据 |
| v prediction | 与信号和噪声相关的速度 | 在某些噪声范围更稳定 |

不同实现的 scheduler 和网络输出可能使用不同参数化。阅读代码时要确认模型输出的语义、训练损失、采样器如何把它转换成 `x_0` 或 `x_{t-1}`；不能看到变量名 `pred` 就假定它一定是噪声。

`v` 预测的转换可以直接从两条定义推出来。令 `a=√(ᾱ_t)`、`s=√(1-ᾱ_t)`，并采用 `v=aε-sx_0` 这一约定；前向式是 `x_t=ax_0+sε`。这两个式子构成一个正交线性变换：

~~~math
\begin{bmatrix}x_t\\v\end{bmatrix}
=
\begin{bmatrix}a&s\\-s&a\end{bmatrix}
\begin{bmatrix}x_0\\\epsilon\end{bmatrix},
\qquad
\begin{bmatrix}x_0\\\epsilon\end{bmatrix}
=
\begin{bmatrix}a&-s\\s&a\end{bmatrix}
\begin{bmatrix}x_t\\v\end{bmatrix}
~~~

因此 `\hat{x}_0=ax_t-s\hat{v}`，`\hat{\epsilon}=sx_t+a\hat{v}`。例如 `\bar{\alpha}_t=0.36` 时 `a=0.6,s=0.8`，采样器要用 `\hat v` 还原预测噪声，就应计算 `0.8x_t+0.6\hat v`。如果模型权重训练为 `v` 输出，却把它当成 `\epsilon` 交给 scheduler，张量形状仍然正确，语义却错了，常会表现为整张图结构崩坏。不同论文或实现可能采用不同符号约定，必须以 checkpoint 的训练配置和 scheduler 的 `prediction_type` 为准。

### 反向均值

在 DDPM 的噪声预测形式下，一个常见的反向均值为：

~~~math
\mu_\theta(x_t,t,c)=
\frac{1}{\sqrt{\alpha_t}}
\left(
x_t-
\frac{\beta_t}{\sqrt{1-\bar{\alpha}_t}}
\epsilon_\theta(x_t,t,c)
\right)
~~~

采样器根据均值和当前时间步决定是否加入随机项。DDPM、DDIM、Euler、Heun 和 DPM-Solver 等方法可能采用不同的离散化和步数。模型权重相同，scheduler 改变也可能改变速度、细节、多样性和可复现性。

## 17.5 Noise Scheduler 与采样预算

Noise Scheduler 负责定义训练噪声日程、推理时间步和每一步的更新规则。它与去噪网络分工不同：网络学习如何预测，scheduler 决定如何把预测转成下一状态。

采样步数是最直接的成本旋钮。若每步需要一次或两次 denoiser 调用，步数增加会近似增加网络调用和延迟；少步采样可以降低成本，却可能导致细节不足、结构不稳定或 prompt 遵循下降。CFG 通常还会增加条件和无条件分支的计算，除非实现把它们批量合并。

一个可复现的生成实验至少保存：模型 checkpoint、VAE、text encoder、scheduler、采样步数、CFG scale、seed、分辨率、prompt、negative prompt、后处理和安全组件版本。只保存 prompt 和一张输出图，无法判断差异来自模型、随机种子还是采样器。

### 少步采样有两种不同代价：换积分路径，或重新训练模型

“把步数从 50 改成 10”不是单一算法。已有模型可以直接换采样路径；若要把极少步数下的质量拉回来，另一条路是花额外训练成本蒸馏模型：

| 方法 | 改动位置 | 解决什么问题 | 限制与使用判断 |
| --- | --- | --- | --- |
| [DDIM](https://arxiv.org/abs/2010.02502) | 保留原去噪网络和训练目标，选择较稀疏的反向时间步，可构造确定性采样轨迹。 | 不重新训练就减少 denoiser 调用，并可在固定 seed 下复现轨迹。 | 少步时结果取决于被跳过的时间区间、噪声日程和条件强度；论文中的速度/质量结论只对应其任务和配置。 |
| [DPM-Solver](https://arxiv.org/abs/2206.00927) | 把扩散采样写成 probability-flow ODE 的数值积分，利用专门的高阶求解器近似多步更新。 | 用较少模型评估次数逼近连续反向轨迹，不需为每个 solver 重新训练权重。 | 高阶不是无条件更好；时间网格、预测参数化、CFG 和模型误差共同决定误差，必须按目标 checkpoint 做质量回归。 |
| [Progressive Distillation](https://arxiv.org/abs/2202.00512) | 让学生模型用一次更新逼近教师模型的两次确定性采样，重复蒸馏以逐级减半步数。 | 把“推理调用多”转化为“额外训练换低延迟”；原论文在 CIFAR-10 等设置中报告从最多 8192 步蒸馏到 4 步的实验。 | 4 步与 FID 3.0 是论文的 CIFAR-10 结果，不是现代文生图或视频 checkpoint 的承诺；蒸馏目标、指导强度和训练数据变化都可能造成质量损失。 |

对同一个 checkpoint，先比较 DDIM、DPM-Solver 等无需重训的路径；若目标延迟仍达不到，再评估蒸馏版 checkpoint，并把额外训练、模型存储和质量回归成本列入总账。Hugging Face Diffusers 的 scheduler 文档展示了 timestep spacing、sigma 和从既有 scheduler config 构造新 scheduler 的接口；这个入口说明哪些设置可显式配置，不保证任意 scheduler 都与任意 checkpoint 兼容。[官方 Scheduler 文档](https://huggingface.co/docs/diffusers/main/en/using-diffusers/schedulers)

## 17.6 U-Net 与 DiT：两种去噪 backbone

### U-Net 的多尺度路径

U-Net 包含下采样路径、瓶颈层和上采样路径，并通过 skip connection 传递多尺度特征。图像生成同时需要全局语义和局部纹理：下采样有利于扩大感受野，上采样和跳跃连接有利于重建边缘和细节。

在文本到图像系统中，U-Net 通常接收 noisy image 或 latent、时间步 embedding 和文本条件。文本条件常通过 cross-attention 进入若干层，影响去噪方向。

U-Net 的优点是图像归纳偏置和多尺度路径成熟；局限是大规模扩展和长程关系建模不如 Transformer 直接，视频还需额外引入时间模块。U-Net 的“成熟”不代表它自动解决文字、数量和空间关系。

### Diffusion Transformer（DiT）

DiT 把 noisy image 或 latent 切成 patch token，再用 Transformer block 建模 token 关系，并将时间步和文本条件注入 block。若 latent 空间高宽为 `H,W`，patch size 为 `P`，忽略 padding 时：

~~~math
N_{\mathrm{patch}}
=
\frac{H}{P}\frac{W}{P}
~~~

这里假设 `H`、`W` 都能被 `P` 整除；若实现采用 padding，则两个商应改为向上取整，并将补齐区域的 mask 和坐标映射纳入条件契约。DiT 的优势是结构接近 Transformer 和视觉 token 模型，便于研究 scaling 和条件融合；代价是全 attention 的 token 成本、显存和局部归纳偏置需要重新规划。DiT 也不自动带来更好文字渲染或视频一致性，最终结果仍受数据、VAE、条件注入、采样器和评估协议影响。

DiT 原论文比较了 in-context token、cross-attention、adaptive LayerNorm 与 adaLN-Zero 条件注入。adaLN-Zero 将 timestep 和类别条件映射为每层的归一化调制与残差门控，并把调制初始化为零，使每个 block 初始接近恒等映射；在论文的 class-conditional ImageNet 实验中，它比所比较的 cross-attention 和 in-context 方案更省计算且 FID 更低。[DiT 论文的消融](https://arxiv.org/abs/2212.09748)支持的是该 backbone、训练和任务设定，不能推出所有文生图模型都应去掉 cross-attention。

Patch size 是另一项直接影响计算的选择。若 32×32 latent 切成 8×8 patch，得到 16 个 token；改成 4×4 patch 后得到 64 个 token。密集 self-attention 的 token-pair 数从 `16^2=256` 增至 `64^2=4096`，即增加 16 倍；更细 patch 同时保留更多局部状态，所以不能只按 FLOPs 选大 patch，也不能把更细 patch 当成免费提升。

### U-Net 和 DiT 的比较实验

公平比较应固定 latent 分辨率、训练 token、条件数据、优化器、采样步数、硬件和评估集，同时报告训练吞吐、峰值显存、采样延迟、prompt 对齐、局部细节和失败类型。只比较一张样例图，无法判断 backbone 的差异是否真实存在。

## 17.7 VAE 与 Latent Diffusion：用压缩换取计算量

### VAE 在生成链中的位置

VAE 或 autoencoder 负责像素空间和 latent 空间的转换，不负责理解 prompt：

~~~text
training image -> VAE encoder -> latent z
latent z -> noise and denoising -> clean latent
clean latent -> VAE decoder -> generated image
~~~

若图片大小为 `H×W`，空间下采样倍率为 `f`，latent 通常形如 `z\in\mathbb{R}^{C_z\times H/f\times W/f}`。只看空间网格，压缩后的 cell 数比例约为：

~~~math
R_{\mathrm{spatial}}=\frac{1}{f^2}
~~~

若同时考虑 latent 通道和 RGB 通道，元素比例可近似为：

~~~math
R_{\mathrm{element}}
=
\frac{C_z(H/f)(W/f)}{3HW}
~~~

这些比例假设 `H`、`W` 能被下采样倍率 `f` 整除；真实 VAE 可能先 padding 或裁剪，因而还要保留原图到 latent 的坐标映射。`1/f^2` 只是空间网格比例，不是无损压缩率。VAE 重建误差会影响文字、细线、纹理和精确几何；如果信息在 encoder 阶段已经丢失，后面的 diffusion 不能凭空恢复。

### Stable Diffusion 作为 pipeline

Stable Diffusion 代表一条由多个组件组合而成的 latent diffusion 路线：

~~~text
prompt -> tokenizer -> text encoder -> condition embedding
random latent + condition -> U-Net or DiT + scheduler -> clean latent
clean latent -> VAE decoder -> image
~~~

不同 checkpoint、VAE、text encoder、scheduler、安全过滤和许可条件都会改变实际系统。名称只说明一条路线，不等于固定的质量、速度或商业使用结论。

## 17.8 Classifier-Free Guidance：加强条件，也放大错误

CFG 让模型同时学习有条件和无条件预测，采样时将二者的差异放大：

~~~math
\hat{\epsilon}_{\mathrm{cfg}}
=
\epsilon_\theta(z_t,t,\varnothing)
+w\left(
\epsilon_\theta(z_t,t,c)-
\epsilon_\theta(z_t,t,\varnothing)
\right)
~~~

`c` 是正条件，`\varnothing` 是空条件，`w` 是 guidance scale。`w` 较小时 prompt 约束弱，`w` 较大时可能过饱和、结构僵硬、细节异常、多样性下降或放大训练数据偏差。

训练时通常以一定概率 `p_drop` 把文本条件替换为空条件，让同一网络既学到 `\epsilon_\theta(z_t,t,c)`，也学到 `\epsilon_\theta(z_t,t,\varnothing)`；采样时两种预测的差近似表示模型认为“加入条件后应往哪里移动”。按本节公式，`w=0` 完全使用无条件预测，`w=1` 恢复条件预测，`w>1` 则越过条件预测继续沿两者差值外推。比如 `\epsilon_u=(1,0)`、`\epsilon_c=(2,1)` 时，`w=3` 得到 `(4,3)`；这不是更准确的证据，而是更强的条件外推，因此可能让模型过度强化提示词中学到的相关特征。

CFG 的代价还包括计算：如果 conditional 和 unconditional 分支分开执行，每个采样步需要两次 denoiser 推理。工程实现通常将两个 batch 合并，但计算量仍然存在。比较 CFG 结果时应固定 seed 和 prompt，并同时观察质量、对齐、多样性、失败率和延迟。

注意 `guidance_scale` 的数值不可脱离公式比较：有的实现把 `w` 直接乘在“条件减无条件”的差上，有的把旋钮定义为 `s` 并计算 `\epsilon_c+s(\epsilon_c-\epsilon_u)`，二者满足 `w=1+s`。读配置时要确认公式约定，而不只抄一个 scale 数字。

### Negative Prompt 的边界

negative prompt 可以作为负条件影响采样方向，但不是硬约束。它不能保证严格删除某个对象，也不能代替安全分类、版权策略或身份保护。需要精确布局、姿态或区域编辑时，ControlNet、mask、参考图或显式结构条件通常比堆叠形容词更可靠。

## 17.9 DALL·E 与自回归图像生成

[DALL·E 1](https://arxiv.org/abs/2102.12092) 把文本和离散图像 token 放进自回归 Transformer；[DALL·E 2（unCLIP）](https://arxiv.org/abs/2204.06125) 则先预测 CLIP image embedding，再由 diffusion decoder 合成像素。DALL·E 2 的论文分别尝试自回归和扩散 prior，并报告扩散 prior 在其设置下计算更高效、样本质量更好；decoder 还能在保留 embedding 语义/风格时改变 embedding 未编码的细节。这也明确了一个代价：CLIP latent 更像语义条件，不是对输入图像细节的无损表示。两项研究展示的是不同的分解方式，并不构成相同数据和算力下的直接竞赛。

### 自回归图像 token 的概率分解

设视觉 tokenizer 将图像编码成 `y_1,\ldots,y_M`，文本条件为 `u`，自回归生成概率为：

~~~math
p(y_1,\ldots,y_M\mid u)
=
\prod_{m=1}^{M}
p(y_m\mid u,y_{<m})
~~~

优点是训练目标与语言模型统一、文本和图像可以进入同一上下文、概率建模清晰；代价是高分辨率会产生很长序列，tokenizer 重建误差会限制质量，逐 token 解码也会带来较高延迟。

### 自回归与扩散的工程比较

| 方面 | 自回归图像生成 | 扩散图像生成 |
| --- | --- | --- |
| 状态 | 离散或连续视觉 token 序列 | 噪声 latent / 图像 |
| 训练目标 | next-token prediction | denoising objective |
| 生成方式 | 逐 token | 多步并行计算或迭代去噪 |
| 主要瓶颈 | token 数、解码串行性、tokenizer | 采样步数、denoiser 调用、控制强度 |
| 主要优势 | 与 LLM 和统一上下文自然衔接 | 编辑、控制和高质量生态成熟 |

比较时要固定输出分辨率、token 数、采样预算和硬件。不能把“扩散每步并行”简单等同于“扩散一定更快”，也不能忽略自回归系统对 KV cache、批处理和 token 压缩的优化。

## 17.10 Text-to-Image：文本对齐不等于画面漂亮

一个文生图任务至少包含四个质量维度：

| 维度 | 问题 |
| --- | --- |
| Prompt alignment | 主体、属性、动作和关系是否符合文字 |
| Visual quality | 清晰度、纹理、光照和构图是否自然 |
| Compositionality | 多个对象及其关系是否同时正确 |
| Controllability | 风格、布局、主体和细节能否稳定改变 |

复杂 prompt 可能包含主体、属性、数量、空间关系、动作、镜头、光照和风格。模型常见失败包括数错对象、混淆左右、把风格词压过主体语义、生成不可读文字、手部异常和多主体交互崩溃。

因此评估不应只选随机成功样例，而要设计 prompt suite：单主体、属性组合、计数、空间关系、文字、人物、长 prompt、多语言、参考图和安全边界。每类样本都要记录失败类型，才能知道问题来自条件表示、生成 backbone、采样器还是数据覆盖。

已有 benchmark 已把若干高频失败拆成可定位任务：

| 基准 | 重点覆盖 | 评测机制与局限 |
| --- | --- | --- |
| [DrawBench](https://arxiv.org/abs/2205.11487) | 具有挑战性的文本到图像 prompt，比较整体质量与文本对齐。 | Imagen 论文使用 side-by-side 人评；结果依赖模型版本、样本生成设置、评审说明和评审者群体。 |
| [GenEval](https://arxiv.org/abs/2310.11513) | 对象共现、数量、位置和颜色等可分解属性。 | 以检测器和判别模型检查对象/属性，能定位组合失败；检测器本身的漏检和类别覆盖会传递到分数。 |
| [T2I-CompBench](https://arxiv.org/abs/2307.06350) | 颜色、形状、纹理绑定，空间/非空间关系和复杂组合。 | 设计专门的组合评测指标，也研究多模态评估器的局限；合成 prompt 覆盖仍不等于真实用户工作流。 |

一轮可复查的对比至少固定 checkpoint/revision、prompt 原文、分辨率、采样器与步数、CFG、seed 数、图像后处理和评估器版本。报告每个 prompt 的成功数与失败类别，并对人评做盲化、随机左右位置和分歧统计；不能只保留各模型最漂亮的一张图。

## 17.11 Image Editing：改该改的地方，保留不该改的地方

图像编辑以原图、编辑指令、mask、参考图或结构条件为输入。常见任务包括 inpainting、outpainting、背景替换、主体替换、风格迁移、姿态控制、图像增强和参考图编辑。

与纯文生图相比，编辑任务多了一个保真约束：非目标区域应尽量不变，目标区域要按指令变化，边界还要保持光照、透视、纹理和身份连续。

### img2img strength

img2img 将输入图片编码到 latent，再按 denoising strength 加噪并重新采样。强度低时更靠近原图，强度高时自由度更大但漂移风险增加。它不是一个跨模型通用的物理量，必须结合具体 scheduler 和实现解释。

### Inpainting 与 mask

Inpainting 使用 mask 指定可修改区域。系统需要处理像素 mask 到 latent 网格的下采样、边缘混合、上下文区域扩张和未修改区域保护。mask 太窄会造成边界接缝，太宽会让主体身份和构图一起漂移。

### ControlNet 与参考条件

ControlNet 可以使用边缘、深度、姿态、分割或草图等结构条件。可以把它抽象为向基础去噪网络隐藏状态加入条件残差：

~~~math
h_l^{\mathrm{out}}
=
h_l^{\mathrm{base}}+r_l(C)
~~~

这要求 `r_l(C)` 与 `h_l^{\mathrm{base}}` 在 batch、空间网格、通道数、dtype 和设备上可相加。prompt 更适合表达语义，ControlNet 和参考图更适合表达结构。控制强度过低时布局不稳，过高时可能限制风格和细节；条件图的裁剪、分辨率、坐标系和 latent 对齐必须写进实验记录。

几个常被统称为“图像编辑”的方案，实际控制的是不同变量：

| 方法 | 输入如何影响生成 | 主要解决的问题 | 代价和典型失效 |
| --- | --- | --- | --- |
| [SDEdit](https://arxiv.org/abs/2108.01073) | 先把草图或原图加噪到选定强度，再用预训练扩散 prior 去噪。 | 无需为每种草图/合成任务训练专用模型，在输入忠实度和生成真实感之间调节。 | 噪声强度低时保留输入但可能残留不真实痕迹；强度高时更真实却更容易偏离原布局，不能保证像素级保留。 |
| [InstructPix2Pix](https://arxiv.org/abs/2211.09800) | 把原图与自然语言编辑指令作为条件，训练条件扩散模型直接预测编辑结果；训练对由 GPT-3 生成指令、Stable Diffusion 与 Prompt-to-Prompt 合成图像对。 | 把“调 strength/写 mask”转成可直接表达的指令，推理时不需要逐样本微调或 inversion。 | 合成编辑对不覆盖所有真实图像和用户措辞，容易发生指令漏做、非目标区域漂移或主体身份变化；论文的快速推理不等于编辑必然正确。 |
| [ControlNet](https://arxiv.org/abs/2302.05543) | 额外输入边缘、深度、姿态等空间条件，通过可训练控制分支向预训练扩散 backbone 注入特征。 | 让布局、姿态或轮廓比纯文字更可控。 | 需要准备与原图坐标对齐的条件图并承担附加网络计算；结构图正确不保证语义、文字或安全要求正确。 |

选型要先问编辑请求的权威信号是什么：用户要“变成水彩”主要是语义/风格指令；用户要求“人保持在画面左侧、手臂姿态不变”则需要结构条件或明确 mask；只希望让草图更写实，可测试 SDEdit 的噪声强度。任何方案都应同时测 mask 内完成度与 mask 外保真，不能只凭整体美观选型。

### 编辑保真不能只看整图相似度

编辑任务有两个相反的目标：mask 内要产生目标变化，mask 外要尽量不变。设原图为 `x`，编辑结果为 `\tilde{x}`，可编辑区域为二值 mask `M`，其中 `M=1` 表示允许修改。可以把非目标区域漂移写成：

~~~math
D_{\mathrm{preserve}}
=
\frac{\left\|(1-M)\odot(\tilde{x}-x)\right\|_1}
{\left\|(1-M)\odot\mathbf{1}\right\|_1}
~~~

分母必须大于零；若 mask 覆盖整张图，就没有“未编辑区域保真”可测，应报告 `N/A`。这个像素级代理会把正常的曝光变化也视为漂移，实际评估还可增加感知特征距离、关键点一致性、身份相似度和人工复核。与此同时，mask 内是否完成指令不能由低漂移推出，仍要分别标注目标对象、属性和边界连续性。

## 17.12 Video Diffusion：从二维画面扩展到时间轴

视频 diffusion 在视频像素或 video latent 上进行加噪和去噪。若视频 latent 为 `z_0`，条件为 `c`，噪声预测目标可以写成：

~~~math
L_{\mathrm{video}}
=
\mathbb{E}_{z_0,t,\epsilon,c}
\left[
\left\|
\epsilon-
\epsilon_\theta(z_t,t,c)
\right\|_2^2
\right]
~~~

公式形式与图像 diffusion 相似，但 `z_t` 多了时间维度。模型必须同时学习空间纹理、动作和跨帧状态，显存和序列长度也随帧数增长。

视频生成的主要难点是：

| 难点 | 为什么重要 |
| --- | --- |
| 计算量 | 多帧和高分辨率同时放大 token 和激活 |
| 时序一致 | 主体、背景和纹理不能无故跳变 |
| 运动自然 | 速度、加速度和动作阶段要合理 |
| 物理关系 | 接触、遮挡、碰撞和光照要自洽 |
| 长程记忆 | 长视频中角色、场景和事件要持续 |
| 数据质量 | 视频文本对、镜头切分和版权清洗更难 |

常见结构包括 temporal attention、3D convolution、时序 latent、关键帧条件和先低分辨率后超分辨率。逐帧独立生成的系统即使每帧质量不错，也容易出现闪烁和身份漂移。

### 视频生成代表路线解决了哪些瓶颈

视频模型的演进同时在处理配对数据、分辨率、长序列计算和文本—动作对齐。下表按论文公开机制比较；每篇工作的训练数据、分辨率、视频长度和评估协议不同，不能据此给模型排统一名次。

| 代表工作 | 试图解决的约束与机制 | 代价、证据范围和后续改进方向 |
| --- | --- | --- |
| [Make-A-Video](https://arxiv.org/abs/2209.14792) | 复用已有文生图模型学习外观和文本语义，再从无文本配对的视频中学习运动，并增加空间/时间模块。目标是减少高质量 text-video 配对数据的依赖。 | 迁移已有图像生成能力可降低视频训练门槛，但图像先验不自动提供动作和跨帧状态；论文提出的高分辨率/插帧/超分链路仍是多组件系统。改进时应分别验证动作对齐与单帧画质。 |
| [Imagen Video](https://arxiv.org/abs/2210.02303) | 用 base video diffusion 加交错的空间、时间超分辨率模型生成高分辨率视频，并采用 `v` 参数化和 classifier-free guidance 的 progressive distillation 加速采样。 | 解决逐级生成高清帧的表示和推理预算问题，但级联推理需要多阶段模型，低分辨率阶段的结构错误会传到后续阶段。蒸馏步数与质量需在目标模型上重新测。 |
| [CogVideoX](https://arxiv.org/abs/2408.06072) | 以 3D VAE 同时压缩时间和空间，用 expert Transformer 加强文本与视频 latent 的深度融合，并以渐进训练和稠密视频描述改进时序连贯与语义对齐。 | 3D 压缩降低序列长度，但 VAE 重建能力会限制小字、细节和高速运动；作者报告的自动指标与人工评测绑定其数据和协议。数据过滤、caption 密度和 VAE 都是可继续优化的瓶颈。 |
| [Wan 2.1](https://arxiv.org/abs/2503.20314) | 采用 3D causal VAE 和 DiT；论文中的 Wan-VAE 将时空网格压到约 `[1+T/4,H/8,W/8]` 并增加 latent 通道，再以 patchified latent 和文本条件进行去噪。因果 VAE 与 feature cache 服务于分块编码/解码和长视频内存管理。 | 这是开放模型的系统级例子，说明数据筛选、VAE、文本编码器、DiT 和推理优化需要一起设计；14B/1.3B 模型指标、显存和速度都是论文/仓库指定配置，不能视为所有硬件的保证。进一步改进要同时检查压缩误差、时序边界和实际 attention 长度。 |

比较时可以把改进路径写清楚：Make-A-Video把视频生成的数据瓶颈转向迁移图像 prior 后如何学 motion；Imagen Video用级联解决高清生成，代价是链路和重复去噪；CogVideoX/Wan用时空 VAE 降低 latent 序列负担，再把问题推向重建保真、时间因果与文本动作对齐。具体模型之间的效果排序仍需同 prompt、同分辨率/帧率、同采样预算和同评测器的本地对照。

## 17.13 Video Token 与 Spatiotemporal Patch

### Video Token 的两种含义

在自回归路线中，video token 通常指经 tokenizer 压缩后的离散码；在扩散路线中，它也可能指连续 latent patch 或中间特征。阅读论文时要确认 token 是离散词表项、连续向量，还是仅仅对 latent 网格位置的称呼。

token 设计要平衡压缩和保真。压缩太弱，训练和推理成本爆炸；压缩太强，运动细节、身份、文字、小物体和时间边界容易消失。一个视频平均指标提升，不能证明短事件和细节都没有被压掉。

### 时空 patch 数量

设视频时间长度为 `T`，空间高宽为 `H,W`，时间 patch size 为 `P_t`，空间 patch size 为 `P`，时空 token 数近似为：

~~~math
N_{\mathrm{st}}
=
\left\lceil\frac{T}{P_t}\right\rceil
\left\lceil\frac{H}{P}\right\rceil
\left\lceil\frac{W}{P}\right\rceil
~~~

这里 `T,H,W,P_t,P` 都应为正数，且 `P_t,P` 表示实际 tokenizer 的时间和空间步长；任何一项为零都不是“零 token 视频”，而是输入或配置错误。例如 16 帧、每帧 32×32 个空间 patch，在不做时间压缩时有 16,384 个位置。全 attention 直接作用于这样的序列成本很高，因此系统会采用时间下采样、窗口 attention、factorized attention、latent compression、分层生成或事件检索。

时间 patch 太大，会把快速动作平均掉；空间 patch 太大，会损失小物体和文字。采样粒度应由问题的最短关键事件决定，而不是只由平均视频长度决定。

## 17.14 Temporal Consistency：视频不是一堆独立图片

Temporal Consistency 要求同一主体在不同帧中的身份、外观、颜色、位置变化和光照合理连续。常见失败包括 flickering、identity drift、shape deformation、motion jitter 和 object permanence failure。

### 身份稳定代理

若 `e_t` 是第 `t` 帧中同一主体的归一化特征，可以用相邻帧余弦相似度的平均观察身份稳定性：

~~~math
C_{\mathrm{id}}
=
\frac{1}{T-1}
\sum_{t=2}^{T}
\mathrm{cos}(e_t,e_{t-1})
~~~

该指标至少要求 `T\ge2`，每个 `e_t` 非零且已经确认为同一主体；主体出画、遮挡未恢复或镜头切换时，应先标记为不可比片段，不能把缺失 embedding 当作低相似度。这个指标会受主体运动、遮挡、镜头切换和特征提取器影响；它不是视频质量的完整定义。还应记录亮度/纹理变化、跟踪轨迹、遮挡恢复、运动平滑度和人工偏好。

### Flickering 与 Identity Drift

Flickering 是亮度、颜色、纹理或局部细节快速抖动。一个简单代理可以用相邻帧亮度统计的变化：

~~~math
F_{\mathrm{flicker}}
=
\frac{1}{T-1}
\sum_{t=2}^{T}|b_t-b_{t-1}|
~~~

它同样要求 `T\ge2`，并且 `b_t` 的统计区域、帧率和亮度空间必须固定；单帧不能据此称为“没有闪烁”。真实镜头切换也会产生较大变化，因此应先识别 shot boundary。Identity drift 则是同一个人、物体或角色随时间变成另一个样子，通常暴露出长程状态记忆、条件控制或时序训练不足。

### Motion Prior

Motion Prior 是模型对动作、速度、加速度、遮挡和相机运动的统计先验。它可以来自大规模视频、光流、姿态序列、物理模拟、相机轨迹和人类偏好。文本条件只能描述“从左向右跑”等高层意图，模型还要把它转成连续的位移和形变。

运动控制可以通过起止帧、姿态骨架、深度序列、相机轨迹、参考视频或显式光流实现。运动先验不足时，结果可能主体静止、动作阶段跳跃、速度不稳定或违反接触关系。

## 17.15 Text-to-Video：描述“有什么”还不够

Text-to-Video 的 prompt 同时描述主体、场景、动作、时间变化和镜头语言。例如“穿红衣服的人从左向右跑过雨中的街道，镜头缓慢跟随”，模型需要生成静态元素，也要让跑步、雨、镜头跟随和时间顺序共同成立。

评估应分别记录：

| 维度 | 观察对象 |
| --- | --- |
| 文本对齐 | 主体、属性、动作和镜头是否符合 prompt |
| 单帧质量 | 清晰度、纹理、光照和构图 |
| 时序一致 | 主体、背景和光照是否稳定 |
| 运动质量 | 动作速度、方向和阶段是否自然 |
| 身份保持 | 人物、车辆和物体是否连续 |
| 物理合理 | 遮挡、碰撞、重力和接触是否合理 |
| 长程连贯 | 后半段是否偏离初始场景和事件 |

常见失败是开头符合 prompt、后面逐渐漂移，主体变形，动作停滞，相机和物体运动混乱，文字和手部错误，以及多主体交互无法维持。短视频平均分不能掩盖这些长程问题。

## 17.16 World Model 与 Sora：公开证据到哪里为止

### World Model 的最小抽象

World Model 关注状态如何随时间和动作变化。一个最小抽象是：

~~~math
s_{t+1}\sim p_\theta(s_{t+1}\mid s_t,a_t)
~~~

`s_t` 是状态，`a_t` 是动作或外部干预。高质量视频生成可能需要模型学习对象持久性、遮挡、运动和场景变化，但视频生成通常只观察视觉轨迹，不一定显式表示动作、目标和可验证的状态转移。

因此要区分三个命题：

1. 模型能生成视觉上逼真的短片段。
2. 模型能预测给定动作后的未来观测。
3. 模型能在交互环境中进行长期规划并保持物理、因果和不确定性校准。

第一个命题不能自动推出后两个。机器人、自动驾驶、游戏和仿真场景需要专门测试动作条件、反事实预测、对象追踪、碰撞和长期 rollout，而不能只看视频观感。

### Sora 的公开边界

OpenAI 2024 年的 Sora 技术报告公开了若干结构事实：先把视频压入时空 latent，再切成 spacetime patch，交给 diffusion Transformer 预测干净 patch；表示方式支持不同分辨率、宽高比和时长。该报告明确没有给出完整模型与实现细节，也记录了玻璃破碎、物体状态变化和长片段连贯性等模拟限制。[Sora 技术报告](https://openai.com/index/video-generation-models-as-world-simulators/)支持的是这些公开结构和演示观察，不能据此补写未披露的训练数据、参数规模或可靠物理推理能力。

2025 年的 [Sora 2 System Card](https://openai.com/index/sora-2-system-card/)描述了更强的物理表现、同步音频和可控性等发布方主张，也公开了产品部署与安全限制；它是 system card，不是完整架构论文。OpenAI 的 Sora 页面目前注明 Sora 产品自 2026 年 4 月 26 日起不再提供。[当前官方页面](https://openai.com/index/sora/)因此更适合作为公开研究和系统治理案例，不能当作可调用服务的现状说明。

一个审慎的复现实验应固定 prompt、视频时长、分辨率、帧率和采样版本，并分别测文本对齐、时序一致性、动作合理性、身份保持和安全风险。产品演示是资料入口，不是对所有输入分布的保证。

## 17.17 图像生成评估：FID 只是分布信号

### 生成质量的多个维度

图像评估应至少覆盖：

| 维度 | 说明 |
| --- | --- |
| 文本对齐 | 主体、属性、数量、关系和风格是否兑现 |
| 视觉质量 | 清晰度、纹理、光照、构图和美感 |
| 多样性 | 同一条件是否能产生多个合理结果 |
| 结构正确 | 手、脸、物体边界和空间关系 |
| 文字能力 | 图中文字是否正确可读 |
| 可控性 | mask、布局、参考图和姿态是否有效 |
| 安全与来源 | 有害、侵权、身份和 provenance 风险 |

### FID

若真实图像和生成图像在固定特征提取器下的特征分别近似为高斯分布，均值、协方差为 `\mu_r,\Sigma_r` 和 `\mu_g,\Sigma_g`，FID 使用两组高斯分布间的 Fréchet 距离：

~~~math
\mathrm{FID}
=
\|\mu_r-\mu_g\|_2^2
+\mathrm{Tr}
\left(
\Sigma_r+\Sigma_g-
2\left(\Sigma_r^{1/2}\Sigma_g\Sigma_r^{1/2}\right)^{1/2}
\right)
~~~

矩阵平方根用对称半正定形式书写，避免直接对可能非对称的 `\Sigma_r\Sigma_g` 做数值平方根。FID 最常见的实现使用 ImageNet 预训练 Inception-v3 特征。[FID 原始工作](https://arxiv.org/abs/1706.08500)把它作为生成图像与真实图像的分布距离，不是 prompt 遵循分数。

这个特征选择会造成可观测的盲区。[FID 特征空间的类别偏置研究](https://arxiv.org/abs/2203.06026)展示，只要生成结果的 ImageNet top-N 类别直方图更接近参考分布，即使视觉质量没有相应改善，FID 也可能下降。FID 是分布级指标，受特征提取器、预处理、样本量和真实数据分布影响；它不能直接判断某一张图片是否符合 prompt，也不能充分反映小字、计数、空间关系、安全或编辑保真。

协方差估计要求真实集和生成集都按同一预处理协议提供足够样本。样本少于特征维度、预处理不一致或矩阵病态时，开方项会不稳定；有限样本下的估计也会随样本量变化。报告 FID 时应同时给出样本量、特征网络、图像 resize/crop 规则、随机种子和数值稳定化做法。近期一项 FID 复核研究指出，ImageNet 预训练的 Inception 特征对现代文生图内容覆盖有限，FID 可能与人类偏好不一致，并提出基于 CLIP 特征和最大均值差异的 CMMD。[Rethinking FID](https://arxiv.org/abs/2401.09603) 是对单一 FID 结论的挑战，不代表 CLIP 特征的 CMMD 已适用于所有图像任务；二者仍需与组合能力和业务指标并报。不能把不同论文或不同平台的 FID 数字直接排成能力排行榜。

### CLIPScore、美学评分与人工评测

CLIPScore 可以提供图文语义相关性信号，但可能忽略细节、数量和空间关系；美学评分可能奖励漂亮却不准确的图片。人工评测应按主体、对齐、结构、细节、安全和可控性分项打分，并报告评审协议、样本随机化和分歧，而不是只给一个总分。

固定 prompt suite 应覆盖简单主体、复杂组合、空间关系、计数、文字、人物、风格、多语言、参考图和风险边界。评测集要避免只挑容易生成的 prompt，否则优化会变成挑样本。

## 17.18 视频生成评估：空间质量和时间质量必须分开

视频评估比图像多了帧间维度：

| 维度 | 关注点 |
| --- | --- |
| Prompt alignment | 场景、主体、动作和镜头是否符合文本 |
| Frame quality | 单帧是否清晰自然 |
| Temporal consistency | 身份、背景、纹理和光照是否稳定 |
| Motion naturalness | 速度、方向和动作阶段是否合理 |
| Identity preservation | 角色和物体是否保持一致 |
| Physical plausibility | 接触、碰撞、遮挡和重力是否合理 |
| Long-range coherence | 长时段事件是否持续一致 |
| Safety and provenance | 生成风险、来源和滥用边界 |

### FVD

在视频特征空间中，FVD 通常先用同一视频特征网络提取真实与生成片段，再将特征分布近似为高斯，计算与 FID 类似的 Fréchet 距离：

~~~math
\mathrm{FVD}
=
\|\mu_r-\mu_g\|_2^2
+\mathrm{Tr}
\left(
\Sigma_r+\Sigma_g-
2\left(\Sigma_r^{1/2}\Sigma_g\Sigma_r^{1/2}\right)^{1/2}
\right)
~~~

公式中的矩阵平方根按对称半正定形式计算；`\mu` 和 `\Sigma` 取决于真实/生成视频特征，原始 FVD 工作使用 I3D 视频特征。[后续对 FVD 的系统分析](https://arxiv.org/abs/2410.05203)指出 I3D 特征的高斯假设不完全成立、特征对部分时间扰动不敏感，而且稳定估计可能需要很大的样本量；该研究提出 JEDi 作为另一种候选度量。视频长度、帧率、裁剪、特征提取器和采样协议都会影响 FVD。它是分布级信号，不能单独证明动作自然、身份稳定、物理合理或 prompt 遵循。

FVD 同样要求两个视频集合在数量、帧率、片段长度和特征提取协议上可比，并且有足够样本估计协方差。把 2 秒、24 fps 的生成片段与 10 秒、30 fps 的真实片段直接比较，得到的距离混入了时长和采样差异，不能解释成模型质量变化。

视频还需要任务型指标，例如事件召回和时间定位、关键帧覆盖、轨迹误差、遮挡恢复率和动作成功率。长视频尤其要报告不同时间段的质量，不能只抽取开头几帧。

围绕视频 benchmark 的演进也说明为什么一个总分不够：[VBench](https://arxiv.org/abs/2311.17982) 把视频质量拆成 16 个维度，包括主体一致性、运动平滑、时序闪烁和空间关系；[VBench-2.0](https://arxiv.org/abs/2503.21755) 又把评估扩展到人类保真、可控性、创造性、物理和常识等 5 个方面、18 个细分能力，并组合 VLM/LLM 与专用检测器。论文报告了与人类判断的对齐实验，但这些分数仍依赖其 prompt suite、评估模型和被测模型版本；VLM-as-judge 不是无偏真值，关键结论应抽样人工复核并公布具体失败样例。

## 17.19 生成安全、版权与内容来源

图像和视频生成涉及虚假信息、深度伪造、人脸冒用、商标和版权、色情暴力、未成年人、医疗金融误导、政治内容和风格模仿等风险。真实感越强，某些滥用的传播成本越低，因此安全要求不是生成质量之外的附加项。

### 内容安全链路

一个完整的安全链路至少包括：

1. 训练数据的来源、授权和敏感内容治理。
2. prompt、参考图和控制条件的风险分类。
3. 生成中间结果和最终结果的内容审核。
4. 人脸、声音、名人、未成年人和高影响场景的额外策略。
5. 来源凭证、水印、生成日志和编辑记录。
6. 用户申诉、撤回、事故回归和人工复核。

OpenAI 的 Sora 2 System Card 是分层实现的公开例子：它描述了输入 prompt/图片审核、生成后视频帧与音频转录检查，以及命中后的阻断和产品级身份保护措施。该资料支持“安全不仅是一个 prompt classifier，而是跨输入、输出和产品操作的检查链”这一工程观察；其阈值、模型和部署措施绑定当时的产品配置，不能视为其它系统的默认做法或安全保证。

### Content Provenance

Provenance 记录内容来源、模型版本、生成参数、编辑历史和可验证凭证。它可以帮助平台判断内容是否生成、如何编辑和由谁发布，但 metadata 可能在转码时丢失，水印可能被破坏，检测器也会误报漏报。因此 provenance 不能单独替代用户授权、内容检测和人工审核。

### 安全指标的分母

安全系统不能用“一律拒绝”获得看似完美的安全分。应分别报告高风险漏放、正常内容误拦、隐私/身份风险、版权策略命中、生成后审核漏检和工具动作越权。不同严重度不能被大量低风险样本平均掉。

## 17.20 工程账本：质量、速度、成本和控制如何交换

常见取舍如下：

| 选择维度 | 方案 A | 方案 B | 需要观察 |
| --- | --- | --- | --- |
| 生成路线 | 扩散 | 自回归 | 质量、采样成本、统一建模 |
| 生成空间 | 像素 | latent | 细节、压缩误差、显存 |
| backbone | U-Net | DiT | 归纳偏置、扩展、kernel |
| 采样 | 多步 | 少步/蒸馏 | 质量、延迟、稳定性 |
| 条件 | prompt | 参考图/布局/ControlNet | 易用性、结构控制 |
| 个性化 | 全量微调 | LoRA/adapter | 训练成本、主体保持 |
| 视频 | 逐帧 | 时序建模 | 实现简单性、身份和运动 |
| 评估 | 公开指标 | 场景集和人工 | 横向比较、真实工作流 |

### 单位成功任务成本

一次生成调用价格不足以表示产品成本。可以粗略写成：

~~~math
C_{\mathrm{success}}
=
\frac{
C_{\mathrm{inference}}
+C_{\mathrm{retry}}
+C_{\mathrm{moderation}}
+C_{\mathrm{human\ edit}}
}{P_{\mathrm{accepted\ output}}}
~~~

`C_retry` 包括失败重试和重新上传，`C_moderation` 包括安全审核，`C_human edit` 包括人工筛选和后期编辑。若只比较单次 GPU 时间，会低估低质量结果和安全回退造成的真实成本。

这个式子只在 `P_{\mathrm{accepted\ output}}>0` 时有定义。若一个工作流尚未产出任何可采纳结果，单位成功成本应明确记录为不可定义或无穷大，而不是用一个很大的有限数制造“已经可以交付”的错觉。

### 一个最小的生成审计实验

下面的代码不生成图片，而是帮助读者记录分辨率、latent 压缩、采样步数与每个被采纳结果所需推理延迟之间的关系：

~~~python
from dataclasses import dataclass
from math import isfinite


@dataclass
class GenerationConfig:
    height: int
    width: int
    downsample: int
    steps: int
    denoiser_ms: float
    accepted: float

    def __post_init__(self):
        if any(
            not isinstance(value, int) or isinstance(value, bool)
            for value in (self.height, self.width, self.downsample, self.steps)
        ):
            raise ValueError("dimensions, downsample, and steps must be integers")
        if self.height <= 0 or self.width <= 0:
            raise ValueError("image dimensions must be positive")
        if self.downsample <= 0:
            raise ValueError("downsample must be positive")
        if self.height % self.downsample or self.width % self.downsample:
            raise ValueError("dimensions must divide evenly by downsample")
        if self.steps <= 0:
            raise ValueError("steps must be positive")
        if not isfinite(self.denoiser_ms) or self.denoiser_ms <= 0:
            raise ValueError("denoiser time must be finite and positive")
        if not isfinite(self.accepted) or not 0 < self.accepted <= 1:
            raise ValueError("accepted rate must be finite and in (0, 1]")

    @property
    def latent_cells(self):
        return (self.height // self.downsample) * (
            self.width // self.downsample
        )

    @property
    def latency_ms(self):
        return self.steps * self.denoiser_ms

    @property
    def latency_per_accepted_ms(self):
        return self.latency_ms / self.accepted


base = GenerationConfig(512, 512, 8, 30, 40.0, 0.60)
fast = GenerationConfig(512, 512, 8, 12, 40.0, 0.20)

assert base.latent_cells == 4096
assert fast.latency_ms < base.latency_ms
assert base.latency_per_accepted_ms == 2000.0
assert fast.latency_per_accepted_ms == 2400.0
assert fast.latency_per_accepted_ms > base.latency_per_accepted_ms
try:
    GenerationConfig(512, 512, 8, 12, 40.0, 0.0)
except ValueError:
    pass
else:
    raise AssertionError("zero acceptance must not produce finite latency per accepted result")
print("generation latency ledger toy: ok")
~~~

这里的 `latency_per_accepted_ms` 是平均推理延迟的简化代理，不是货币成本；`C_success` 公式还要另外计入重试、审核和人工编辑。`accepted` 是预先统计的采纳率，真实系统要按 prompt 类型、分辨率、用户和安全拦截切片。示例拒绝零采纳率、非有限耗时和不能被 VAE 整除的尺寸；在给定数值下，30 步配置为每个采纳结果约 2,000 ms，12 步配置因采纳率从 0.60 降到 0.20，反而需要约 2,400 ms。`denoiser_ms` 必须是目标 CFG 配置下实测的每步耗时；示例不单独计算两路 CFG 前向，也不计 text encoder、VAE、排队或 moderation。少步模型如果采纳率下降，单位成功成本可能反而上升；因此应同时看一次调用延迟和单位成功任务成本。

## 17.21 证据边界与延伸阅读

不同资料支持的结论范围不同：

| 资料 | 可以确认 | 不能直接确认 |
| --- | --- | --- |
| 原始论文 | 结构、训练目标和论文实验 | 当前产品在所有输入上的质量 |
| 官方技术报告 | 公开的表示、系统方向和示例 | 未披露的架构、数据和安全保证 |
| 模型卡/官方文档 | 输入限制、版本、许可和接口 | 未测试场景的稳定性 |
| benchmark | 固定协议下的横向结果 | 真实工作流和单位成功成本 |
| 教学代码 | 公式、shape 和成本关系 | 生产吞吐、版权合规和安全保证 |

推荐优先阅读：

- [Denoising Diffusion Probabilistic Models](https://arxiv.org/abs/2006.11239)：前向加噪、反向去噪和训练目标。
- [Denoising Diffusion Implicit Models](https://arxiv.org/abs/2010.02502)、[DPM-Solver](https://arxiv.org/abs/2206.00927) 与 [Progressive Distillation](https://arxiv.org/abs/2202.00512)：对照无需重训的少步采样与额外训练蒸馏。
- [High-Resolution Image Synthesis with Latent Diffusion Models](https://arxiv.org/abs/2112.10752)、[Imagen](https://arxiv.org/abs/2205.11487) 和 [DiT](https://arxiv.org/abs/2212.09748)：比较 latent 压缩、文本编码/级联生成和 Transformer 去噪骨干。
- [DALL·E 1](https://arxiv.org/abs/2102.12092) 与 [DALL·E 2 / unCLIP](https://arxiv.org/abs/2204.06125)：离散视觉 token 与 CLIP latent prior/decoder。

## 17.22 章节练习：把生成结果还原成可解释的账本

### 练习一：估算 latent 和采样成本

给定 1024×1024 图片、VAE 下采样倍率 8 和 20 个采样步，计算 latent 空间 cell 数，并估算 denoiser 调用次数。如果 CFG 使用两个分支，说明在没有 batch 合并时调用次数如何变化。

### 练习二：定位一张图的 prompt 失败

固定 seed，构造包含两个对象、数量、左右关系和小字的 prompt。逐步改变分辨率、patch/latent 配置、CFG、negative prompt 和采样步数，记录主体、数量、空间、文字和安全切片。说明每个反事实实验能排除哪一类原因。

### 练习三：比较 U-Net 与 DiT

固定训练数据、latent 尺寸、参数量和采样器，分别测训练吞吐、峰值显存、采样延迟、FID、文本对齐、文字可读性和局部结构错误。解释为什么参数量相同不代表显存和实际速度相同。

### 练习四：设计图像编辑评估

为背景替换任务准备原图、mask 和编辑指令。分别测目标区域的指令遵循、非目标区域变化、边界连续、主体身份保持和失败重试率；不要用整图 CLIPScore 代替这些指标。

### 练习五：设计短事件视频集

构造包含遮挡、镜头切换、快速动作和多主体交互的视频 prompt。标注关键事件时间窗、主体跟踪、动作阶段和安全边界，分别评估事件召回、时间定位、身份保持、flicker、物理错误和人工偏好。说明 FVD 在这个评估中能覆盖什么，不能覆盖什么。

### 练习六：分析来源和授权

给出一张包含真实人物参考图的生成请求，要求系统保留身份并发布。列出需要检查的授权、隐私、内容来源、输出审核、日志和撤回字段，说明为什么“模型生成了新像素”不自动等于可以公开发布。

### 练习七：把论文路线转成可辩护的方案选择

假设团队要先做海报生成，后续可能扩展到短视频。请比较 DALL·E 1、DALL·E 2、Imagen、Latent Diffusion/Stable Diffusion、Make-A-Video、Imagen Video、CogVideoX 和 Wan 2.1：每项工作针对的瓶颈是什么，改变了表示、条件、数据或推理链路中的哪一环，带来了什么代价？为第一版选型时列出同协议要测的 prompt 组合、分辨率/帧率、采样预算、VAE 重建、文本/动作对齐和安全切片。不要把不同论文的 FID、人工偏好或发布方榜单拼成横向排名；若建议用蒸馏、改 caption 或改 latent 压缩，说明它试图修复哪项已观察失败，并标注这是论文支持还是待验证推断。

## 17.23 小结：视觉生成的核心是可控证据链

扩散模型通过固定的 forward diffusion 和学习到的 reverse denoising 把生成拆成多步预测；scheduler、参数化、采样步数和 CFG 共同决定速度、质量和条件遵循。VAE 和 latent diffusion 通过压缩降低计算，却把一部分细节和文字保真交给 latent 表示；U-Net 和 DiT 是不同的去噪 backbone，自回归视觉 token 则提供与语言模型统一的另一条路线。

视频生成在图像生成之上增加时间轴，需要处理 video token、时空 patch、运动先验、temporal consistency、identity drift、flickering、长程事件和物理关系。Sora 等公开系统推动了 world simulator 讨论，但逼真视频不能自动推出可靠的动作条件预测和长期规划能力。

评估必须把 prompt 对齐、视觉质量、结构、文字、可控性、安全、时序、运动和身份保持拆开。真正的产品结论还要包含采样预算、单位成功成本、来源凭证、人工编辑和回退。生成系统的价值不在于偶尔产出一张成功图片，而在于面对给定输入分布时，能稳定地产出符合约束、可追溯且风险可管理的结果。
