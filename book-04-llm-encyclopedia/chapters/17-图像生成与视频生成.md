# 第 17 章 图像生成与视频生成：从随机性到可控的视觉结果

## 17.0 生成系统要把哪些约束一路传到输出

图像生成不是“给 prompt 就出图”，而是一条表示、生成、解码和验收链：条件编码器把文本、参考图、布局或姿态转换成模型输入；生成器在像素、latent 或视觉 token 空间形成结果；解码器还原媒体；评估与安全组件检查任务约束、失败类型和来源信息。视频在这条链上增加时间轴，必须检查动作、主体身份、遮挡和场景变化能否跨帧保持。

本章是第四册的速查和路由入口。生成算法、系统搭建、视频动态和评估安全的完整讲解分别在第十五册；本章保留最小定义、关键公式、跨方法比较、可复算例子及证据边界。

## 17.1 三条生成路线：扩散、自回归和统一建模

三类路线的区别首先是“生成状态”不同。扩散模型迭代更新噪声图像或 latent；自回归模型顺序预测离散或连续视觉 token；统一多模态模型共享表示、骨干或训练接口。统一的产品界面可能只是一个语言模型调用多个专用生成器，不能据接口外观判断内部架构。

Flow Matching 则是概率路径上的速度场训练框架，可以与 DiT 等骨干组合；它不是与 Transformer、U-Net 并列的网络结构。相关训练目标与路径选择见[第十五册 06 扩散基础](../../book-15-multimodal-generative-models/chapters/06-diffusion基础.md)。

| 路线 | 生成状态与优势 | 主要成本或边界 |
| --- | --- | --- |
| 扩散 | 连续噪声状态，多步去噪；条件编辑和空间控制路径成熟 | 多次 denoiser 调用；结果受 VAE、采样器和指导强度共同影响 |
| 自回归视觉 token | 按序列分解逐 token 生成，容易接入语言模型上下文 | 高分辨率序列变长，串行解码和 tokenizer 重建误差成为瓶颈 |
| 统一多模态 | 可共享 token、Transformer 或上下文接口 | 各模态 token rate、解码器、时序和安全边界仍不同 |

代表工作体现瓶颈转移，而非同一协议下的胜负排序：

| 工作 | 机制改变 | 主要遗留问题 |
| --- | --- | --- |
| [DALL·E 1](https://arxiv.org/abs/2102.12092) | 将图像量化为离散 token，由自回归 Transformer 结合文本生成 | 高分辨率 token 序列较长，tokenizer 决定重建上限 |
| [DALL·E 2 / unCLIP](https://arxiv.org/abs/2204.06125) | 先预测 CLIP 图像 embedding，再由扩散 decoder 合成像素 | embedding 保留语义但不保留全部细节 |
| [Imagen](https://arxiv.org/abs/2205.11487) | 冻结文本编码器提供条件，扩散模型级联生成和放大 | 多阶段推理；论文 FID 与人工评测仅适用于其配置 |
| [Latent Diffusion](https://arxiv.org/abs/2112.10752) | 在感知压缩后的 latent 上去噪，以 cross-attention 接入条件 | 压缩会损伤文字、细线和几何信息 |
| [DiT](https://arxiv.org/abs/2212.09748) | 用 Transformer patch 建模扩散 latent | token 数增加会显著推高密集 attention 成本；原论文是 class-conditional ImageNet 设置 |

选路线前固定目标分辨率/时长、编辑要求、延迟预算、硬件、条件来源和安全约束。论文里的 FID、人工偏好、采样步数和分辨率不能拼成跨任务排行榜。

## 17.2 Forward Diffusion：从数据构造带噪状态

令干净样本为 $x_0$，第 $t$ 步噪声方差为 $\beta_t$，且 $\alpha_t=1-\beta_t$。前向马尔可夫过程每一步给当前样本加入高斯噪声：

~~~math
q(x_t\mid x_{t-1})
=
\mathcal{N}\left(
x_t;\sqrt{\alpha_t}x_{t-1},\beta_t I
\right),
\qquad
\bar{\alpha}_t=\prod_{u=1}^{t}\alpha_u
~~~

利用高斯过程的闭式结果，可直接抽取任意时刻：

~~~math
x_t=
\sqrt{\bar{\alpha}_t}x_0+
\sqrt{1-\bar{\alpha}_t}\epsilon,
\qquad
\epsilon\sim\mathcal{N}(0,I)
~~~

这让训练只需随机抽一个 $t$，不必真的循环加噪 $t$ 次。举一维教学例子：取 $\bar{\alpha}_t=0.36$、$x_0=2$、$\epsilon=-1$，则信号系数为 $0.6$、噪声系数为 $0.8$，所以 $x_t=0.6\times2+0.8\times(-1)=0.4$。低 SNR 时噪声占比更大；若公式、时间索引或噪声日程不一致，训练输入和采样状态便不再匹配。

常用信噪比写作 $\mathrm{SNR}(t)=\bar{\alpha}_t/(1-\bar{\alpha}_t)$，要求 $0<\bar{\alpha}_t<1$。它描述某一噪声级的信号/噪声比例，不表示最终图像质量。

## 17.3 Reverse Denoising：预测值的语义必须对上采样器

噪声预测是经典训练目标：

~~~math
L_\epsilon=
\mathbb{E}_{x_0,t,\epsilon,c}
\left[
\|\epsilon-\epsilon_\theta(x_t,t,c)\|_2^2
\right],
\qquad
\hat{x}_0=
\frac{x_t-\sqrt{1-\bar{\alpha}_t}\,\epsilon_\theta}
{\sqrt{\bar{\alpha}_t}}
~~~

模型也可以预测干净样本 $x_0$ 或速度 $v$；三者是不同参数化，不可只按输出张量的形状判断语义。采用 $a=\sqrt{\bar{\alpha}_t}$、$s=\sqrt{1-\bar{\alpha}_t}$ 和 $v=a\epsilon-sx_0$ 这一约定时：

~~~math
x_t=ax_0+s\epsilon,
\qquad
\hat{x}_0=ax_t-s\hat{v},
\qquad
\hat{\epsilon}=sx_t+a\hat{v}
~~~

沿用上一节 $a=0.6,s=0.8,x_t=0.4,x_0=2,\epsilon=-1$，对应真实 $v=0.6(-1)-0.8(2)=-2.2$；代回可得 $\hat{x}_0=0.6(0.4)-0.8(-2.2)=2$，$\hat{\epsilon}=0.8(0.4)+0.6(-2.2)=-1$。实际 checkpoint 和 scheduler 必须采用相同的 prediction_type 及符号约定。

DDPM 的一个常见反向均值是：

~~~math
\mu_\theta(x_t,t,c)=
\frac{1}{\sqrt{\alpha_t}}
\left(
x_t-
\frac{\beta_t}{\sqrt{1-\bar{\alpha}_t}}
\epsilon_\theta(x_t,t,c)
\right)
~~~

这只是反向分布均值的一种表达，不含所有方差与随机项，也不是 DDIM、ODE solver 等采样器的通用更新式。参数化或时间表错配可能形状正常、语义错误，表现为整体结构崩坏。

## 17.4 Scheduler 与采样预算

Scheduler 把网络预测转为下一采样状态；网络权重不变，更新路径和步数变化也会改变结果。成本大致随 denoiser 调用数增长，但端到端延迟还受批处理、CFG、VAE、排队和硬件影响。

| 方法 | 是否需重训 | 取舍 |
| --- | --- | --- |
| DDPM ancestral sampling | 否 | 每步保留随机项；调用多，可表达多样采样轨迹 |
| [DDIM](https://arxiv.org/abs/2010.02502) | 否 | 可选稀疏时间步和确定性轨迹；少步质量取决于 checkpoint 与设置 |
| [DPM-Solver](https://arxiv.org/abs/2206.00927) | 否 | 将采样写作扩散 ODE 的数值求解；高阶 solver 不保证所有模型都更好 |
| [Progressive Distillation](https://arxiv.org/abs/2202.00512) | 是 | 额外训练学生以减少步数；论文步数/FID 不能外推到现代文生图或视频 |

对同一 checkpoint，先在固定 prompt、seed、分辨率和条件下比较无需重训的路径；再考虑蒸馏，并将训练、存储和质量回归成本纳入账本。框架 API 会随版本变化，具体参数需查目标版本的[官方 scheduler 文档](https://huggingface.co/docs/diffusers/main/en/using-diffusers/schedulers)。

## 17.5 U-Net 与 DiT：去噪主干的空间组织

| 主干 | 结构直觉 | 主要代价 |
| --- | --- | --- |
| U-Net | 下采样扩大感受野，上采样恢复细节，skip connection 传递多尺度特征 | 长程关系和扩展方式受卷积/注意力层布局影响 |
| DiT | 把 noisy latent 切成 patch token，以 Transformer block 建模关系 | 全局 attention 的时间、显存和 token 数成本较高 |

若高宽为 $H,W$ 的 latent 切成边长 $P$ 的 patch（忽略 padding），token 数为：

~~~math
N_{\mathrm{patch}}=
\left\lceil\frac{H}{P}\right\rceil
\left\lceil\frac{W}{P}\right\rceil
~~~

例如 $32\times32$ latent 用 $8\times8$ patch 得 16 个 token，用 $4\times4$ patch 得 64 个；密集 attention 的 token pair 从 $16^2=256$ 增到 $64^2=4096$，约 16 倍。更细 patch 保留更多局部状态，但会显著增大 attention 计算，不能只凭 token 粒度判断画质或速度。

## 17.6 VAE 与 Latent Diffusion：压缩不是无损

常见流水线是“像素图 → VAE encoder → latent → 加噪和去噪 → VAE decoder → 图像”。空间下采样倍率为 $f$ 时，latent 网格约为 $(H/f)\times(W/f)$；该比例描述空间位置数，不是端到端 FLOPs 或延迟比例。encoder 丢掉的文字笔画、细线和几何关系，后面的去噪不能凭空补回。

可手算一个表示规模例子：$512\times512$ RGB 图有 $512\times512\times3=786{,}432$ 个标量；若 latent 为 $64\times64\times4$，则有 $16{,}384$ 个标量，数量比例是 $16{,}384/786{,}432=1/48$。这只比较张量元素数量；不包含 encoder/decoder、通道宽度、attention、内存布局和硬件 kernel。

[Latent Diffusion](https://arxiv.org/abs/2112.10752) 与 [Stable Diffusion](../../book-15-multimodal-generative-models/chapters/07-stable-diffusion与dalle.md) 是在压缩空间生成的代表入口。tokenizer、text encoder、VAE、denoiser、scheduler、安全过滤器和许可共同组成实际 pipeline，不能用模型系列名替代具体 checkpoint/版本。

## 17.7 Classifier-Free Guidance：增强条件会放大偏差

先明确本文使用的系数约定：

~~~math
\epsilon_g=
\epsilon_u+g(\epsilon_c-\epsilon_u)
~~~

$\epsilon_u$ 是无条件或负条件预测，$\epsilon_c$ 是正条件预测。按此式 $g=0$ 为无条件、$g=1$ 为条件预测，$g>1$ 沿条件差异外推；过强时可能过饱和、结构僵硬、细节异常或多样性下降。若 $\epsilon_u=(1,0)$、$\epsilon_c=(2,1)$、$g=3$，则 $\epsilon_g=(1,0)+3(1,1)=(4,3)$。这表示更大幅度外推，不代表有了更强的条件证据。

原论文和不同库可能把旋钮定义为 $\epsilon_c+s(\epsilon_c-\epsilon_u)$，此时 $g=1+s$；有的实现也用 negative prompt 替代空条件分支。比较 guidance_scale 前先检查公式、分支和版本。Negative prompt 不是硬约束，不能替代 mask、空间条件或安全策略。

## 17.8 DALL·E 与自回归图像 token

若 tokenizer 把图像表示成 $y_1,\ldots,y_M$，给定文本 $u$ 的自回归分布为：

~~~math
p(y_1,\ldots,y_M\mid u)
=
\prod_{m=1}^{M}p(y_m\mid u,y_{<m})
~~~

优点是与语言模型 next-token 目标统一，代价是高分辨率时序列较长、解码串行且质量受 tokenizer 量化误差影响。DALL·E 1 直接预测离散 image token；DALL·E 2 把文本到 CLIP image embedding 的 prior 与像素 decoder 分开。二者解决的表示问题不同，不能只按“自回归/扩散”两个标签比较。

## 17.9 Text-to-Image：分别检查对齐、质量和控制

| 质量切片 | 检查什么 | 常见漏项 |
| --- | --- | --- |
| Prompt alignment | 主体、属性、数量、关系、动作和风格 | 主题相近却漏掉限定条件 |
| Composition | 多对象绑定、左右/远近、遮挡 | 单对象正确但关系错误 |
| Visual quality | 清晰度、纹理、光照和构图 | 美观不代表忠实 |
| Text rendering | 文字内容、拼写和位置 | 小字与数字仍容易错 |
| Controllability | seed、mask、布局、参考图、姿态能否按要求变化 | 只展示成功样例 |

[DrawBench](https://arxiv.org/abs/2205.11487) 以人工比较挑战性 prompt；[GenEval](https://arxiv.org/abs/2310.11513) 拆解对象、计数和位置；[T2I-CompBench](https://arxiv.org/abs/2307.06350) 关注组合属性与关系。其数据集、评估器和标注协议各有覆盖范围，分数不构成通用质量排名。建立本地 prompt suite 时按失败切片统计，不只保留每个模型最漂亮的一张图。

## 17.10 Image Editing：定义允许变化的区域

编辑任务同时要求目标区域按指令变化、非目标区域尽量保真。主要控制入口不同：

| 方法 | 条件方式 | 适用问题与边界 |
| --- | --- | --- |
| img2img / [SDEdit](https://arxiv.org/abs/2108.01073) | 对原图或草图加噪，再从所选噪声强度去噪 | 强度低更贴近原图，强度高自由度更大；不保证像素保留 |
| Inpainting | 用 mask 标出可修改区域 | 需处理 mask 到 latent 的缩放和边缘融合；mask 太宽会导致非目标区域漂移 |
| [InstructPix2Pix](https://arxiv.org/abs/2211.09800) | 指令和原图共同作条件 | 便于表达编辑意图，仍可能漏做指令或改动主体身份 |
| [ControlNet](https://arxiv.org/abs/2302.05543) | 用边缘、深度、姿态或分割等结构图控制 | 结构图需与原图坐标对齐；控制正确不保证语义和安全正确 |

若原图为 $x$、编辑结果为 $\tilde{x}$、二值 mask $M=1$ 表示可修改区域，可用下面的像素代理测非目标区域漂移：

~~~math
D_{\mathrm{preserve}}=
\frac{
\|(1-M)\odot(\tilde{x}-x)\|_1
}{
\|(1-M)\odot\mathbf{1}\|_1
}
~~~

分母为零（整图均可改）时应记为 N/A；像素距离还会把正常曝光变化算成漂移。因此需同时评估 mask 内的指令完成、mask 外保真、边界连续性和身份保持，不能用整图相似度替代。

## 17.11 图像编辑的诊断路径

出现“主体变了”时先检查 seed、编辑强度和 mask 外保真；“布局不听话”时检查条件图分辨率、裁剪、坐标系和控制权重；“结构对但语义错”时回看 prompt 与视觉条件是否冲突；“图好看但小字错误”时单独评估文字或交给文字渲染/排版工具。每次只改变一个条件，并保留原图、mask、prompt、模型 revision、scheduler 和 seed，才能定位原因。

## 17.12 Video Diffusion：在空间去噪之外建模时间

视频扩散可在像素或连续 video latent 上定义类似的去噪目标，但状态多了时间轴；模型还要学习纹理、动作和跨帧状态。逐帧独立生成即使单帧清晰，也容易闪烁、身份漂移或动作跳变。

| 代表路线 | 主要机制 | 代价或证据边界 |
| --- | --- | --- |
| [Video Diffusion Models](https://arxiv.org/abs/2204.03458) | 以 3D U-Net 的空间/时间模块联合建模帧块 | 结构与效果绑定论文的固定片段和实验 |
| [Make-A-Video](https://arxiv.org/abs/2209.14792) | 复用文生图先验，再从无文本视频学习运动，增加时间层和插帧/超分模块 | 图像先验不自动提供动作和长程状态 |
| [Imagen Video](https://arxiv.org/abs/2210.02303) | base video model 与空间、时间超分组成级联 | 多阶段计算；前段结构误差可能延续到后段 |
| [CogVideoX](https://arxiv.org/abs/2408.06072) | 3D 因果 VAE 压缩时空，再以 expert Transformer 融合文本和视频 latent | 压缩损失影响小字、细节和快速运动 |
| [Wan 2.1](https://arxiv.org/abs/2503.20314) | 3D causal VAE、DiT 与分块编码/解码工程 | 论文配置指标和速度不是任意硬件的保证 |
| [Pyramidal Flow Matching](https://arxiv.org/abs/2410.05954) | 在空间分辨率金字塔上训练单个 DiT 的 flow-matching 轨迹，并以时间金字塔压缩自回归历史 | 作者报告的画质、时长和计算成本绑定论文数据/配置；长时间范围仍有主体一致性风险 |

这些工作分别处理配对数据、时空计算、分辨率和 latent 序列长度。训练数据、时长、帧率、分辨率和指标不一致时，不应把论文分数排成一个榜单。

## 17.13 时空 token：长度决定了注意力账本

“video token”可能指离散码本 token，也可能指连续 latent patch 或网格位置。设视频 latent 的时间长度为 $T$、空间高宽为 $H,W$，时间 patch 为 $P_t$、空间 patch 为 $P$，位置数近似为：

~~~math
N_{\mathrm{st}}=
\left\lceil\frac{T}{P_t}\right\rceil
\left\lceil\frac{H}{P}\right\rceil
\left\lceil\frac{W}{P}\right\rceil
~~~

例如 16 帧、每帧 $32\times32$ 个空间 patch、时间 patch $P_t=1$，得到 $16\times32\times32=16{,}384$ 个位置；密集 attention 有约 $16{,}384^2=268{,}435{,}456$ 个 token pair。这个数量级解释了时空压缩、窗口/分解 attention 和分层生成的动机，不代表某一实际模型的 FLOPs。时间压缩过强会抹掉短动作，空间 patch 太大会漏掉小物体和文字，粒度应由最短关键事件和目标细节共同决定。

## 17.14 Temporal Consistency：明确哪些内容应保持稳定

常见失败有 flickering（亮度/纹理跳变）、identity drift（主体逐渐变样）、motion jitter（速度不平滑）、遮挡恢复错误和物体持久性失败。跨帧指标是诊断代理，必须标注特征提取器、主体轨迹、帧率和可比区间。

若 $e_t$ 是同一主体的归一化特征，可用相邻帧余弦相似度观察身份稳定性：

~~~math
C_{\mathrm{id}}=
\frac{1}{T-1}\sum_{t=2}^{T}
\mathrm{cos}(e_t,e_{t-1})
~~~

若 $b_t$ 是固定区域的帧亮度统计，可用 $F_{\mathrm{flicker}}=\frac{1}{T-1}\sum_{t=2}^{T}|b_t-b_{t-1}|$ 作简单闪烁代理。两者都要求 $T\ge2$；主体出画、遮挡或镜头切换时要先筛掉不可比帧，亮度突变也可能是有意转场，不能直接判成质量差。

## 17.15 Text-to-Video：条件中还要编码动作和时间

视频 prompt 除主体与场景外，还要表达动作顺序、速度、镜头运动和时间变化。评估应分开记录文本/事件对齐、单帧质量、运动自然度、身份保持、物理关系、长程连贯、安全和来源。平均视频分会掩盖“开头符合、后段漂移”等失败，需按时间窗、主体和事件切片。

例如，“穿红衣的人从左向右跑，镜头跟随”至少包含人物属性、位移方向、跑步状态和相机跟随四个断言。把它们分别标注为事件和时间窗，才能判断是条件未执行、主体跟踪漂移还是相机运动错误。

## 17.16 World Model 与 Sora：把视觉生成和状态预测分开

一个最小状态转移写作 $s_{t+1}\sim p_\theta(s_{t+1}\mid s_t,a_t)$，其中 $s_t$ 是环境状态，$a_t$ 是动作。视频生成只需产生符合条件的视觉序列；预测器根据历史观测预测未来；控制意义上的 world model 还需在动作条件下预测结果并支持规划。逼真视频本身不能证明动作因果、反事实预测或闭环控制可靠。

2024 年 [Sora 研究报告](https://openai.com/index/video-generation-models-as-world-simulators/)公开描述了将视频压缩为时空 latent、切成 patch 并交给扩散 Transformer 预测的路线，同时指出报告不含完整模型和实现细节。服务生命周期已变化：OpenAI [帮助中心](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation)列明网页/应用于 2026-04-26 停止、API 于 2026-09-24 停止。因此 Sora 应作为历史研究和治理案例引用，不能作为当前可调用服务举例。

近期交互式世界模型评估把问题从“视频看起来像不像”扩展到多轮动作、视角切换、场景一致性与物理符合度。[WBench](https://arxiv.org/abs/2605.25874v1) 的 2026 预印本用 289 个案例、1,058 轮交互组织五类维度和 22 个自动子指标；评分器及样本仍是论文协议的一部分。[World-in-Context](https://arxiv.org/abs/2610.33169v1) 的 2026-10 v1 预印本把视角、角色动作和摄像机轨迹作为上下文条件，在 WBench 上报告其模型结果。两者提供新的评估和控制入口，不证明一般视频生成器具备真实环境的世界建模能力。

## 17.17 图像生成评估：FID 是特征分布距离

评估至少分开报告 prompt 遵循、组合关系、视觉质量、多样性、文字、可控性、安全和 provenance。FID 在固定特征空间中，把真实/生成图像特征近似为高斯并计算 Fréchet 距离：

~~~math
\mathrm{FID}=
\|\mu_r-\mu_g\|_2^2+
\mathrm{Tr}\left(
\Sigma_r+\Sigma_g-
2(\Sigma_r^{1/2}\Sigma_g\Sigma_r^{1/2})^{1/2}
\right)
~~~

$\mu$、$\Sigma$ 分别为特征均值和协方差；经典实现使用 Inception 特征。[原始 FID 工作](https://proceedings.neurips.cc/paper_files/paper/2017/file/8a1d694707eb0fefe65871369074926d-Paper.pdf)定义的是集合级分布距离，不是单张图片的 prompt 遵循分数。用一维特征演示公式：真实分布 $\mu_r=0,\Sigma_r=1$，生成分布 $\mu_g=1,\Sigma_g=4$，则 FID $=1^2+(1+4-2\sqrt{1\times4})=2$。这只是高斯假设下的教学计算。

特征网络、预处理、样本量和真实数据分布会改变结果；FID 可能遗漏小字、计数、空间关系和安全问题。[类别偏置研究](https://arxiv.org/abs/2203.06026)与 [Rethinking FID](https://arxiv.org/abs/2401.09603)讨论了这些盲区及 CMMD 候选指标，但不证明新指标适合所有任务。不同论文的 FID 不可脱离数据和协议直接排名。

## 17.18 视频生成评估：分布质量不能代替时间任务

FVD 将 FID 思路用于视频特征：按固定特征提取器得到真实和生成片段的向量，再比较其均值/协方差分布。分数受特征网络、帧率、片段长度、裁剪和样本量影响；原始 FVD 使用 I3D 特征。[后续系统分析](https://arxiv.org/abs/2410.05203)指出特征高斯假设和部分时间扰动存在限制，并提出 JEDi 候选。FVD 不能单独证明动作自然、主体稳定、物理合理或 prompt 遵循。

至少还需测事件召回与时间定位、轨迹、遮挡恢复、闪烁、动作阶段和人工偏好。[VBench](https://arxiv.org/abs/2311.17982)及 [VBench-2.0](https://arxiv.org/abs/2503.21755)提供多维视频评估例子；其样本、评分器和被测版本限制分数含义。2 秒、24 fps 片段与 10 秒、30 fps 片段不具备直接比较条件。交互式模型还要补多轮动作遵循和状态保持，可参见 17.16 的 WBench 入口。

## 17.19 生成安全、版权与 Content Provenance

图像/视频产品的风险覆盖训练数据授权、参考图隐私、身份冒用、深度伪造、未成年人、有害内容和输出误导。安全链要覆盖输入审核、生成策略、输出审核、身份/来源保护、申诉和事故回归；单个 prompt classifier 不能代表整条风险控制。

[C2PA 2.5 技术规范](https://spec.c2pa.org/specifications/specifications/2.5/specs/C2PA_Specification.html)提供内容凭证、签名和资产绑定的来源/完整性信号。验证成功说明相应凭证与内容绑定通过了规范检查，不等于内容陈述真实、取得授权或没有有害内容。来源、真实性、许可和安全是不同问题，评估也应分别报告漏放、误拦和高风险类别，不能靠全拒绝得到虚高安全分。

## 17.20 工程账本：看单位成功任务成本

单次 GPU 时间不能完整表示产品成本。可将一次可采纳结果的简化成本写成：

~~~math
C_{\mathrm{success}}=
\frac{
C_{\mathrm{inference}}+C_{\mathrm{retry}}+
C_{\mathrm{moderation}}+C_{\mathrm{edit}}
}{
P_{\mathrm{accepted\ output}}
}
~~~

分母必须大于零；若尚无可采纳结果，成本应记为未定义/无穷大，不能以有限值暗示可交付。分子各项需使用相同成本单位，且采纳率要按 prompt、分辨率、用户和安全拦截切片。

下面的标准库小例子比较 latent 位置数、名义采样延迟和采纳率。可执行代码没有改动。

状态：静态审阅，未运行（2026-10-30）。依赖：Python 3.9+ 标准库。将代码保存为 generation_ledger.py 后运行 python3 generation_ledger.py；手算预期输出：generation latency ledger toy: ok。该代理不包括货币、队列、审核和人工编辑成本。

~~~python
from dataclasses import dataclass
from math import isfinite


@dataclass
class GenerationConfig:
    height: int
    width: int
    downsample: int
    steps: int
    denoiser_ms: float
    accepted: float

    def __post_init__(self):
        if any(
            not isinstance(value, int) or isinstance(value, bool)
            for value in (self.height, self.width, self.downsample, self.steps)
        ):
            raise ValueError("dimensions, downsample, and steps must be integers")
        if self.height <= 0 or self.width <= 0:
            raise ValueError("image dimensions must be positive")
        if self.downsample <= 0:
            raise ValueError("downsample must be positive")
        if self.height % self.downsample or self.width % self.downsample:
            raise ValueError("dimensions must divide evenly by downsample")
        if self.steps <= 0:
            raise ValueError("steps must be positive")
        if not isfinite(self.denoiser_ms) or self.denoiser_ms <= 0:
            raise ValueError("denoiser time must be finite and positive")
        if not isfinite(self.accepted) or not 0 < self.accepted <= 1:
            raise ValueError("accepted rate must be finite and in (0, 1]")

    @property
    def latent_cells(self):
        return (self.height // self.downsample) * (
            self.width // self.downsample
        )

    @property
    def latency_ms(self):
        return self.steps * self.denoiser_ms

    @property
    def latency_per_accepted_ms(self):
        return self.latency_ms / self.accepted


base = GenerationConfig(512, 512, 8, 30, 40.0, 0.60)
fast = GenerationConfig(512, 512, 8, 12, 40.0, 0.20)

assert base.latent_cells == 4096
assert fast.latency_ms < base.latency_ms
assert base.latency_per_accepted_ms == 2000.0
assert fast.latency_per_accepted_ms == 2400.0
assert fast.latency_per_accepted_ms > base.latency_per_accepted_ms
try:
    GenerationConfig(512, 512, 8, 12, 40.0, 0.0)
except ValueError:
    pass
else:
    raise AssertionError("zero acceptance must not produce finite latency per accepted result")
print("generation latency ledger toy: ok")
~~~

手算：基础配置 latent 网格为 $(512/8)^2=4{,}096$；30 步乘每步 40 ms 为 1,200 ms，除以采纳率 0.60 得 2,000 ms/采纳结果。快速配置的名义调用延迟为 $12\times40=480$ ms，但采纳率 0.20 时为 $480/0.20=2{,}400$ ms。因此少步不必然降低单位成功成本。此教学示例不代表真实模型、GPU 实测或生产采用率。

## 17.23 小结：生成结果必须回到条件与证据

视觉生成路线的核心差别在表示和状态更新：自回归逐 token 预测，扩散沿噪声轨迹去噪，统一模型共享部分表示或计算接口。VAE 压缩会交换计算与细节，scheduler 和 CFG 会交换调用预算与条件强度；这些旋钮都要和具体 checkpoint、目标输入及评估协议一起解释。

视频在图像上增加了时间状态，除单帧质量外还要验证动作、身份、遮挡、物理关系与长程一致性。FID/FVD 是特征分布信号，不代替任务型或人工评估；provenance 凭证也不证明内容真实、已授权或安全。只有把条件是否满足、失败分母、重试/人工成本和风险控制一并记入账本，才能判断生成系统是否适合目标工作流。
