# 第一部分：深度学习与概率基础进阶

学习大模型，不能只记住几个结构名词。更可靠的路径是把模型看成一个概率系统，再把概率目标连接到优化过程、泛化行为、训练稳定性和最终产品指标。

这一部分围绕十个相互衔接、又可以独立阅读的主题展开：

1. 语言模型究竟在估计什么概率。
2. 交叉熵、熵与 KL 散度为什么成为训练目标。
3. 非凸优化、过参数化和训练轨迹如何影响结果。
4. 泛化、双下降、记忆与数据污染如何区分。
5. 贝叶斯视角如何帮助我们理解不确定性和幻觉。
6. 为什么可优化的损失经常不能代表真实目标。
7. 初始化、归一化和数值控制如何让深层网络稳定训练。
8. 激活函数与门控 MLP 为什么会影响 Transformer 的表达效率。
9. AdamW、Adafactor 与 Lion 如何在质量和系统成本之间取舍。
10. 如何把这些概念组织成一套可复现的训练诊断方法。

这里的公式用于建立可检查的模型，不是把现实训练压缩成一个公式就结束。数据切分、参数化、随机种子、硬件精度、并行实现和评估协议都可能改变实验结果。每一节都会明确哪些结论来自定义或定理，哪些只是论文中的经验现象，哪些必须通过自己的实验确认。

## 1. 概率建模视角下的语言模型

### 从“预测下一个词”回到联合概率

初学者常把语言模型理解成一个自动补全器：给它一段文字，它猜下一个 token。这个描述没有错，却没有说明它为什么能够生成整段文本，也没有说明训练目标到底是什么。

更精确的说法是：语言模型为 token 序列分配概率。设分词后的序列为 x₁, x₂, …, x_T，模型参数为 θ，模型希望近似真实数据分布：

~~~math
P_\theta(x_1,x_2,\ldots,x_T)
~~~

概率论中的链式法则把联合概率分解为一串条件概率：

~~~math
P_\theta(x_{1:T})
=\prod_{t=1}^{T}P_\theta(x_t\mid x_{1:t-1})
~~~

其中 x₁:t−1 表示当前位置之前的全部 token。这个分解不是 Transformer 的经验假设，而是概率论恒等式。自回归语言模型的具体建模选择，是让每个条件概率只依赖已经出现的前缀。

这个区别很重要。模型不是直接给“整篇文章”一个不可解释的分数，而是把整篇文章的概率拆成许多次局部预测的乘积。生成时，每一步从条件分布中选择下一个 token，再把新 token 放回上下文，继续计算下一步分布。

### logits、softmax 与条件分布

Transformer 最后一层通常为每个位置产生一个词表维度的 logits 向量。设词表大小为 V，位置 t 的 logits 为 z_t∈R^V，条件概率由 softmax 给出：

~~~math
P_\theta(x_t=v\mid x_{1:t-1})
=\frac{\exp(z_{t,v})}
{\sum_{u=1}^{V}\exp(z_{t,u})}
~~~

z 的绝对值没有直接的概率含义，真正影响分布的是不同 token 之间的相对差异。为了避免指数运算溢出，实际实现会先减去最大 logit：

~~~math
\mathrm{softmax}(z)_i
=\frac{\exp(z_i-\max_j z_j)}
{\sum_k\exp(z_k-\max_j z_j)}
~~~

减去同一个常数不会改变 softmax 的结果，却能显著改善数值稳定性。

如果把词表中的 token 编号记为 v，那么模型的训练任务就是：在每个位置上，让真实 token x_t 的条件概率尽可能大。这个目标只需要原始文本，不需要人工给每个 token 写标签，因此称为自监督学习。监督信号来自序列本身的移位关系：输入看到 x₁ 到 x_{T−1}，标签是 x₂ 到 x_T。

### 因果掩码为什么必不可少

在训练阶段，整段序列通常一次性送入 Transformer。若不做限制，位置 t 的表示可以直接读取未来 token x_t+1、x_t+2，模型就能“偷看答案”。这会破坏自回归任务。

因果注意力使用一个上三角掩码，把未来位置的注意力 logit 设为负无穷。若原始注意力分数为 S，掩码为 M，则：

~~~math
\widetilde S_{t,s}=
\begin{cases}
S_{t,s},&s\le t\\
-\infty,&s>t
\end{cases}
~~~

softmax 后，未来位置的概率近似为零。这里的“未来”是序列位置上的未来，不是现实世界时间；如果任务需要双向理解，编码器模型可以采用不同的注意力约束，但它就不再是同一种自回归训练协议。

### Teacher forcing 与训练—生成差异

训练时，位置 t 的上下文通常使用真实前缀，即使模型在前一步本来预测错了，下一步仍然可以看到正确的 x_t。这种方式叫 teacher forcing。它让训练高效、梯度清晰，但产生一个结构性差异：

- 训练分布中的上下文大多来自真实数据；
- 生成分布中的上下文包含模型自己前面采样的 token；
- 一次早期错误可能把后续上下文带到训练分布之外。

这就是常说的 exposure bias。它不意味着 teacher forcing 是错误方案，而是提醒我们：训练损失不能完全预测长序列生成的稳定性。减少这种差异可以从多步训练、数据增强、解码控制、后训练和任务级评估等方向尝试，但每种方法都有额外成本或新的偏差。

### 为什么一个目标可以承载很多任务

问答、翻译、摘要、代码补全和结构化输出，看起来是不同任务，但都可以表示成条件生成：

~~~math
P_\theta(y\mid c)
=\prod_{t=1}^{|y|}
P_\theta(y_t\mid c,y_{1:t-1})
~~~

其中 c 是任务说明和输入，y 是目标输出。只要数据把任务描述、输入和正确输出组织在同一序列中，模型就可以用统一的 next-token 目标学习。

这解释了语言模型的通用性，也解释了它的局限：统一的概率形式不等于所有任务的评价标准相同。代码是否通过测试、数学最终答案是否正确、工具参数是否满足 schema，都可能是序列级或行为级条件，不能只靠局部 token 概率判断。

### 训练目标与生成策略不是一回事

训练最大化的是数据序列的似然，生成时却要从分布中选择一条序列。最简单的贪心解码在每一步选择当前概率最大的 token：

~~~math
\hat x_t=\arg\max_v P_\theta(v\mid x_{1:t-1})
~~~

贪心解码速度快，但局部最优不一定形成全局最好的文本。随机采样则按照条件分布抽取 token。温度 τ 会改变分布的尖锐程度：

~~~math
P_\tau(v\mid c)
=\frac{\exp(z_v/\tau)}
{\sum_u\exp(z_u/\tau)}
~~~

τ 小于 1 时分布更尖，输出更确定；τ 大于 1 时分布更平，输出更多样。top-k 只保留概率最高的 k 个 token，top-p 则保留累计概率达到 p 的最小候选集合。它们是生成策略，不是训练目标；改变解码参数不能证明模型本身学到了新知识。

### 困惑度能说明什么，不能说明什么

给定 N 个目标 token，平均负对数似然为：

~~~math
\mathcal L_{\mathrm{NLL}}
=-\frac{1}{N}\sum_{i=1}^{N}\log P_\theta(x_i\mid x_{<i})
~~~

若对数使用自然对数，困惑度为：

~~~math
\mathrm{PPL}
=\exp(\mathcal L_{\mathrm{NLL}})
~~~

困惑度可以粗略理解为模型在每个位置上面对的“等效候选数量”。它适合比较相同 tokenizer、相同数据切分和相同评估协议下的语言建模质量，但不能跨 tokenizer 直接比较，也不能单独代表事实性、推理、工具调用或安全行为。

一个常见错误是把低困惑度等同于“更懂”。如果验证集文本风格与线上用户输入差异很大，模型可以在验证集上更擅长预测，却在实际任务上变差。评估必须说明 tokenization、上下文长度、loss mask、数据来源和聚合方式。

### 一个不依赖深度学习框架的最小实验

下面的代码只演示 softmax、序列负对数似然和温度如何改变分布。它不是语言模型，只是把概率计算中的三个关键部件显式写出来。

~~~python
import math


def stable_softmax(logits, temperature=1.0):
    if not logits:
        raise ValueError("logits must not be empty")
    if not math.isfinite(temperature) or temperature <= 0:
        raise ValueError("temperature must be finite and positive")
    if any(not math.isfinite(value) for value in logits):
        raise ValueError("logits must be finite")
    scaled = [value / temperature for value in logits]
    peak = max(scaled)
    weights = [math.exp(value - peak) for value in scaled]
    total = sum(weights)
    if not math.isfinite(total) or total <= 0:
        raise ValueError("softmax normalizer must be positive and finite")
    return [weight / total for weight in weights]


def sequence_nll(probabilities, target_indices):
    if not target_indices or len(probabilities) != len(target_indices):
        raise ValueError("probabilities and targets must be non-empty and aligned")
    total = 0.0
    for distribution, target in zip(probabilities, target_indices):
        if isinstance(target, bool) or not isinstance(target, int):
            raise TypeError("target indices must be integers")
        if not distribution or not 0 <= target < len(distribution):
            raise IndexError("target index is outside the distribution")
        probability = distribution[target]
        if not math.isfinite(probability) or probability <= 0:
            raise ValueError("target probability must be positive and finite")
        total -= math.log(probability)
    return total / len(target_indices)


logits = [2.0, 1.0, 0.0, -1.0]
for temperature in [0.5, 1.0, 2.0]:
    distribution = stable_softmax(logits, temperature)
    print(temperature, [round(value, 4) for value in distribution])

probabilities = [
    stable_softmax([2.0, 1.0, 0.0]),
    stable_softmax([0.2, 1.4, 0.1]),
]
print("mean NLL:", round(sequence_nll(probabilities, [0, 1]), 4))
~~~

观察温度变化时，先不要急着说哪个输出“更好”。温度只改变随机选择的分布；要评价生成质量，还需要固定任务、采样次数和成功标准。示例把空 logits、非正温度、非有限 logits、错位的目标长度、越界标签和非正目标概率都作为输入错误显式抛出，避免用一个数值下限掩盖统计问题。

### 初学者与专家应分别追问什么

初学者首先要能回答三个问题：模型给谁分配概率？条件概率的条件是什么？为什么训练时不需要人工逐 token 标注？如果这三个问题不清楚，直接背 attention 公式很容易失去主线。

更深入时，要追问四件事：

1. 训练数据分布和部署分布是否一致。
2. teacher forcing 造成的上下文偏移有多大。
3. token-level likelihood 与目标任务的成功事件是否一致。
4. 生成策略改变的是抽样行为，还是模型参数本身。

这四个问题会把概率建模自然连接到后面的泛化、目标错配和评估。

### 证据边界

链式法则、softmax 和负对数似然是定义或直接推导。next-token prediction 能涌现多种能力，则是大规模经验现象，不能由链式法则单独推出。困惑度与下游能力通常相关，但相关性会受数据、tokenizer、任务格式和后训练影响。关于暴露偏差的讨论来自序列建模理论与经验研究，具体缓解方法必须用任务级实验验证。

## 2. 交叉熵、熵与 KL 散度：同一目标的三种读法

### 为什么训练语言模型要最小化负对数

对一个真实 token x，模型给出的概率越大，负对数 −log Pθ(x) 越小。把整个数据集的负对数相加，就是最大似然估计的相反数：

~~~math
\theta^\star
=\arg\max_\theta\sum_{i=1}^{N}
\log P_\theta(x^{(i)})
=\arg\min_\theta
-\sum_{i=1}^{N}\log P_\theta(x^{(i)})
~~~

自回归分解后，序列负对数似然变成逐 token 的和。因此交叉熵不是“因为大家都这么用”才出现，而是由概率建模和最大似然自然得到的训练目标。

### 熵是分布自身的不确定性

离散分布 P 的熵定义为：

~~~math
H(P)=-\sum_x P(x)\log P(x)
~~~

如果 P 把概率集中在一个结果上，熵低；如果 P 在许多结果之间均匀分配，熵高。熵描述的是分布本身，不依赖另一个预测分布。

语言中的歧义、开放式问题和多种合理续写，会让真实条件分布本身具有较高熵。模型无法仅靠更大容量把这种客观多解变成唯一答案。强行追求唯一输出，可能反而伤害创造性或诚实表达。

### 交叉熵比较两个分布

真实分布 P 与模型分布 Q 的交叉熵为：

~~~math
H(P,Q)=-\sum_x P(x)\log Q(x)
~~~

如果监督标签是 one-hot 分布，真实 token 的概率为 1，其余 token 为 0，交叉熵就退化成真实 token 的负对数概率。对于一个 batch，训练目标是经验分布与模型分布之间的平均交叉熵。

交叉熵可以分解为熵和 KL 散度：

~~~math
H(P,Q)=H(P)+D_{\mathrm{KL}}(P\Vert Q)
~~~

其中：

~~~math
D_{\mathrm{KL}}(P\Vert Q)
=\sum_xP(x)\log\frac{P(x)}{Q(x)}
~~~

当 P 固定时，H(P) 是常数，所以最小化交叉熵等价于最小化 D_KL(P∥Q)。这给出了一个清晰解释：模型训练是在让预测分布接近数据分布，但 KL 散度不是对称距离，方向不同会产生不同的偏好。

### 为什么 KL 散度不是普通距离

KL 散度满足非负性，但一般不满足对称性：

~~~math
D_{\mathrm{KL}}(P\Vert Q)\ne D_{\mathrm{KL}}(Q\Vert P)
~~~

如果 P 在某处有正概率而 Q 给出零概率，前一个方向会趋向无穷。这种方向性在训练中有实际含义：最大似然通常惩罚模型漏掉真实数据质量较大的区域，但对模型在真实数据未覆盖区域分配多少概率，约束方式不同。

在知识蒸馏、变分推断和偏好优化中，KL 的方向和参考分布非常重要。不能只说“加一个 KL 就能防止模型漂移”，还要说明是从哪个分布到哪个分布、按 token 还是按序列计算、在哪个数据分布上计算。

### 从 token loss 到序列概率

一条长序列的概率是许多 token 概率的乘积：

~~~math
P_\theta(x_{1:T})
=\prod_{t=1}^{T}P_\theta(x_t\mid x_{1:t-1})
~~~

长序列的乘积很快变小，因此实际训练和比较通常使用平均负对数似然。可是平均会掩盖局部灾难性错误。例如代码只有一个括号缺失，数学答案只差最后一位，token 平均损失的变化可能不大，而任务成功率会从 1 变成 0。

因此至少要把两类指标分开：

- 概率指标：平均 NLL、困惑度、token accuracy；
- 任务指标：exact match、单元测试通过率、结构化解析成功率、事实核验通过率。

前一类适合观察模型分布拟合，后一类才直接对应某个任务的成功定义。

### Label smoothing 改变了目标分布

one-hot 标签把全部目标概率放在一个 token 上。label smoothing 会把一部分质量分给其他 token。设词表大小为 V，平滑系数为 ε，则一个常见目标分布为：

~~~math
\widetilde P(v\mid x)
=(1-\varepsilon)\mathbf 1[v=x]
+\frac{\varepsilon}{V}
~~~

它可以降低模型过度自信，改善某些分类和翻译任务的泛化或校准。但它也改变了“真实标签”的定义，并不自动适合所有语言模型场景。若任务需要精确复制、严格代码或结构化 token，平滑可能让错误 token 获得不希望的梯度。

### 软标签与知识蒸馏

知识蒸馏让学生模型拟合教师模型的软分布。若教师 logits 为 `z_teacher`，学生 logits 为 `z_student`，温度 τ 下的蒸馏损失可以写成：

~~~math
\mathcal L_{\mathrm{KD}}
=-\sum_v
P_{\mathrm{teacher},\tau}(v\mid c)
\log P_{\mathrm{student},\tau}(v\mid c)
~~~

较高温度会暴露类别之间的相对偏好，而不只是 one-hot 的正确类别。蒸馏的收益依赖教师质量、数据分布、温度和损失权重；教师的错误也可能被学生继承。

### 用数值例子检查三种量的关系

下面用两个三分类分布计算熵、交叉熵与 KL。代码使用自然对数，因此单位是 nat；如果改用以 2 为底的对数，单位则是 bit。

~~~python
import math


def validate_distribution(probabilities, name):
    if not probabilities:
        raise ValueError(f"{name} must not be empty")
    if any(
        not math.isfinite(probability) or probability < 0
        for probability in probabilities
    ):
        raise ValueError(f"{name} must contain finite non-negative values")
    if not math.isclose(sum(probabilities), 1.0, rel_tol=1e-9, abs_tol=1e-9):
        raise ValueError(f"{name} must sum to one")


def entropy(probabilities):
    validate_distribution(probabilities, "probabilities")
    return -sum(
        probability * math.log(probability)
        for probability in probabilities
        if probability > 0
    )


def cross_entropy(reference, prediction):
    validate_distribution(reference, "reference")
    validate_distribution(prediction, "prediction")
    if len(reference) != len(prediction):
        raise ValueError("reference and prediction must have the same length")
    total = 0.0
    for probability, predicted in zip(reference, prediction):
        if probability > 0 and predicted <= 0:
            raise ValueError("prediction assigns zero probability to an observed event")
        if probability > 0:
            total -= probability * math.log(predicted)
    return total


def kl_divergence(reference, prediction):
    validate_distribution(reference, "reference")
    validate_distribution(prediction, "prediction")
    if len(reference) != len(prediction):
        raise ValueError("reference and prediction must have the same length")
    total = 0.0
    for probability, predicted in zip(reference, prediction):
        if probability == 0:
            continue
        if predicted <= 0:
            raise ValueError("KL divergence is undefined when Q is zero where P is positive")
        total += probability * math.log(probability / predicted)
    return total


reference = [0.7, 0.2, 0.1]
prediction = [0.5, 0.3, 0.2]
print("H(P) =", round(entropy(reference), 6))
print("H(P, Q) =", round(cross_entropy(reference, prediction), 6))
print("KL(P || Q) =", round(kl_divergence(reference, prediction), 6))
print(
    "H(P) + KL(P || Q) =",
    round(entropy(reference) + kl_divergence(reference, prediction), 6),
)
~~~

最后两行应当相等，这不是实验巧合，而是交叉熵分解式的数值体现。

这些函数把空分布、负概率、未归一化输入、长度不匹配和 `P>0,Q=0` 明确视为数据错误。实际训练代码可能使用稳定 kernel 处理极小概率，但不能用一个任意的 `max` 下限把非法分布静默改成合法分布。

### 初学者与专家的两层理解

初学者可以先把三者记成一句完整的话：熵描述真实分布有多不确定，交叉熵描述用 Q 预测 P 要付出多少代价，KL 散度描述 Q 相对 P 多付出的代价。

专家还需要注意：

1. KL 的方向会影响优化行为。
2. token 级的交叉熵不等于序列级成功率。
3. label smoothing、蒸馏和 KL 约束都会改变目标分布。
4. 训练集上的交叉熵下降，可能只是模型更好地拟合了当前数据，而不是所有任务都变好。

### 证据边界

熵、交叉熵与 KL 的关系是信息论定义和代数推导。交叉熵作为语言模型训练目标的合理性来自最大似然。label smoothing、蒸馏和 KL 约束的收益具有任务和实现依赖，不能把某个论文设置当作普遍最优配置。

## 3. 优化景观、过参数化与训练轨迹

### 我们究竟在优化什么

把模型写成 f_θ，把训练数据写成 D，训练过程通常是在求：

~~~math
\theta^\star=\arg\min_\theta\mathcal L_D(\theta)
~~~

参数 θ 可能有数百万、数十亿甚至更多维度。损失函数由多层线性变换、非线性、注意力、归一化和数据平均共同构成，因此通常是高度非凸的。

“非凸”只说明损失面不是一个简单的碗，不等于训练一定失败。真正决定训练轨迹的还有初始化、梯度估计噪声、学习率、参数化、归一化、残差路径和优化器。

### 局部极小值、鞍点与平坦区域

在一维直觉中，局部极小值附近所有方向都向上；在高维空间中，鞍点可能在某些方向向上、另一些方向向下。用 Hessian 矩阵 H 表示局部曲率时：

~~~math
H(\theta)=\nabla_\theta^2\mathcal L(\theta)
~~~

若 H 的特征值全部为正，局部二阶近似是极小点；若存在正有负的特征值，更像鞍点；若许多特征值接近零，局部区域可能很平坦。

这些术语帮助我们描述训练几何，但不能直接变成“平坦一定好”的结论。平坦度依赖参数化和坐标尺度。对某些参数做重缩放，函数输出可能几乎不变，Hessian 的数值却会变化。因此比较模型时，应把曲率指标与扰动鲁棒性、验证性能和任务指标结合，而不是只看一个 Hessian 数字。

### 过参数化改变了问题形状

当参数数量远大于数据约束数量时，模型可能存在许多训练误差接近零的解。这叫过参数化。它带来两个看似矛盾的事实：

- 模型容量足够大，可以记住训练集甚至噪声；
- 在合适数据和优化路径下，模型仍可能在未见数据上表现良好。

这说明“能拟合训练集”和“会泛化”不是互斥命题。最终选择哪个解，取决于初始化、优化器、数据顺序、正则化和架构带来的隐式偏置。

对于线性模型，最小范数解常能被明确分析；对于深度网络，优化器和网络参数化共同产生的隐式偏置更复杂。不能只根据参数量推出模型会记忆还是泛化。

### 梯度下降是带有偏好的搜索过程

最简单的更新为：

~~~math
\theta_{t+1}=\theta_t-\eta_t\nabla\mathcal L(\theta_t)
~~~

即使存在许多训练损失相同的解，不同的学习率、batch 顺序或优化器也可能走向不同解。小 batch 的梯度噪声会让轨迹偏离确定性最速下降；学习率衰减会改变后期在损失面上的移动尺度；weight decay 会持续改变参数范数。

所以训练配置不是“找到同一个最优解的不同速度”，而可能是在选择不同的函数。更换优化器后，即使训练 loss 看起来相近，校准、长尾能力和下游任务也可能不同。

### Batch size 与梯度噪声

设单样本梯度为 g_i，batch B 的平均梯度为：

~~~math
\widehat g_B=\frac{1}{|B|}\sum_{i\in B}g_i
~~~

在样本近似独立且分布稳定时，batch 越大，估计方差通常越低。但这不是无限成立的工程定律：样本相关性、重复数据、梯度累积方式和并行同步都会改变有效噪声。

大 batch 通常带来更高硬件利用率和更稳定的更新，却可能减少单位 token 的参数更新次数，且需要重新调学习率和 warmup。比较两个训练实验时，必须记录 global batch tokens，而不能只写“batch size=32”。

### 学习率决定探索尺度

学习率过大时，更新可能跨过损失较低区域，表现为 loss spike、梯度爆炸或 NaN；过小时，训练会变慢甚至停留在欠训练状态。学习率还和 batch、模型尺度、预热步数、优化器二阶矩以及精度有关。

一个实用的训练诊断不是只画 loss，而是同时观察：

1. 学习率曲线。
2. 梯度范数和参数范数。
3. 更新量与参数量之比。
4. 每 token 吞吐。
5. 训练集和多个验证切片的 loss。
6. NaN/Inf 位置与触发 batch。

### 为什么“平坦解更好”需要谨慎

平坦解的常见直觉是：参数受到小扰动时损失变化较小，因此可能更鲁棒。但这个直觉依赖如何定义扰动。若对不同层使用不同参数尺度，未经归一化的参数空间平坦度无法公平比较。

更可靠的实践是做函数层面的扰动测试，例如：

- 对输入做轻微改写或噪声；
- 对权重施加相对比例的扰动；
- 在未见领域和长尾切片上测试；
- 比较校准、错误类型和任务成功率。

这样才是在问“模型行为是否稳定”，而不是只问某个坐标系中的曲率是否小。

### 一个二维优化轨迹实验

下面的例子用一个带窄谷的二维函数展示学习率对轨迹的影响。它不是神经网络损失，只用于形成几何直觉。

~~~python
def gradient(point):
    x, y = point
    # 一个在 x 方向较平、y 方向较陡的二次函数
    return (2.0 * x, 20.0 * y)


def optimize(start, learning_rate, steps):
    point = list(start)
    history = [tuple(point)]
    for _ in range(steps):
        dx, dy = gradient(point)
        point[0] -= learning_rate * dx
        point[1] -= learning_rate * dy
        history.append(tuple(point))
    return history


for learning_rate in [0.02, 0.08, 0.12]:
    path = optimize((4.0, 1.0), learning_rate, 8)
    print("lr =", learning_rate, "last =", tuple(round(v, 4) for v in path[-1]))
~~~

学习率 0.12 对 y 方向已经过大，轨迹可能在陡峭方向上振荡或发散。真实网络的损失面高维、随训练变化，不能仅凭这个玩具函数选超参数；实验的价值在于说明条件数和步长之间存在关系。

### 从 loss 曲线读出不同故障

几种常见曲线需要区别：

- 训练和验证都不降：可能是学习率、数据、mask、初始化或实现错误；
- 训练降、验证升：可能是过拟合、分布差异或验证协议错误；
- 两者都降但任务指标不升：目标错配或指标与任务不一致；
- 偶发 spike 后恢复：可能是异常 batch 或数值瞬态；
- spike 后持续 NaN：应立即定位数值、梯度、mask 和 optimizer state。

曲线只能告诉你“发生了什么”，不能单独告诉你“为什么”。原因需要结合可观测量和可复现的最小样本。

### 初学者与专家的两层理解

初学者先理解：非凸不等于不能训练；过参数化不等于必然过拟合；优化器不仅影响速度，也可能影响最后得到的函数。

深入分析时还要问：

1. 讨论的复杂度是参数数量、有效秩、训练时间还是数据噪声？
2. 所谓平坦度是否对参数重参数化不变？
3. 比较训练方案时是否固定 token budget、数据顺序和评估切片？
4. 观察到的泛化改善来自优化器、正则化，还是更好的数据和更长训练？

这些问题可以避免把相关性误写成因果关系。

### 证据边界

非凸、鞍点、过参数化和隐式偏置的数学定义相对明确，但“现代深度网络主要不是卡在坏局部极小值”是结合理论与实验形成的经验判断。双下降、平坦性与泛化之间的关系依赖模型族和评估设置，不能用一句“参数越大越好”或“平坦一定泛化好”概括。

## 4. 泛化、双下降、记忆与数据污染

### 泛化到底在问什么

训练集上的低损失只说明模型能解释已经见过的数据。我们真正关心的是：从同一任务分布中重新抽取一个未见样本，模型是否仍然可靠。

设数据来自分布 𝒟，单样本损失为 ℓ，模型的经验风险和真实风险分别是：

~~~math
\widehat R_D(f)
=\frac{1}{n}\sum_{i=1}^{n}\ell(f(x_i),y_i)
~~~

~~~math
R_{\mathcal D}(f)
=\mathbb E_{(x,y)\sim\mathcal D}
[\ell(f(x),y)]
~~~

训练是在降低经验风险，泛化讨论的是经验风险与真实风险之间的差距。真实风险不可直接完全计算，所以我们用独立验证集或测试集估计它。

在语言模型中，训练样本通常是 token 序列，损失多为下一个 token 的负对数似然；但产品真正关心的可能是答案正确率、代码通过率、引用可核验率或安全行为。于是这里至少存在两层泛化：

1. 从训练 token 到未见 token 的概率泛化；
2. 从离线样本到真实任务行为的任务泛化。

前一层好，并不自动推出后一层好。

### 训练集、验证集与测试集的职责

训练集用于更新参数，验证集用于选择超参数和 checkpoint，测试集用于最后一次估计。若反复根据测试集结果改模型，测试集就已经参与开发，不再是无偏的最终估计。

大模型评估还需要更细的切分：

- 按时间切分，检验对新近数据的泛化；
- 按用户或文档切分，避免同一来源泄漏到两边；
- 按领域切分，观察跨领域变化；
- 按长度切分，观察长上下文外推；
- 按风险和难度切片，避免平均分掩盖关键失败。

随机打散后切分在独立同分布的简单任务中可能足够，但对网页、代码仓库、对话和长文档数据往往会把高度相似的内容分到训练和评估两边，从而高估泛化。

### 分布偏移的三个层次

训练分布 P_train 和部署分布 P_deploy 不一致时，问题不一定只是“模型不够大”。可以区分：

1. 协变量偏移：输入分布变了，但理想条件关系近似不变；
2. 标签或输出偏移：目标类别或答案频率变了；
3. 概念偏移：输入与目标之间的关系本身变了。

语言模型中的例子包括：训练语料以英文为主、部署输入变成中文法律文本；训练样本多为短问答、部署要求处理几十万 token 的长文档；训练时工具 schema 固定、部署时 API 字段发生变化。不同偏移需要不同数据和评估策略，不能统称为“过拟合”。

### Bias–variance 直觉不是完整答案

传统统计学习常用偏差与方差分解理解预测误差。以平方损失和固定输入为例，模型期望预测的偏差、不同训练集造成的方差以及不可约噪声共同影响误差：

~~~math
\mathbb E[(\hat f(x)-y)^2]
=\mathrm{Bias}^2
+\mathrm{Var}
+\mathrm{Noise}
~~~

经典直觉是：模型复杂度增加时，偏差下降、方差上升，测试误差呈 U 形。但深度网络进入能插值训练集的区域后，经验曲线可能再次下降，因此只用“参数多所以更容易过拟合”解释现代模型是不够的。

### 双下降与插值阈值

双下降描述一种常见的经验形状：随着某种有效复杂度增加，测试误差先下降，在刚好能够拟合训练数据的插值阈值附近上升，进入更强过参数化区域后又下降。

这里的复杂度可以是：

- 模型宽度或参数量；
- 训练步数；
- 数据量；
- 正则化强度；
- 更抽象的有效模型复杂度。

因此“双下降”不是一个只关于参数量的定理。它是对一类实验曲线的概括，峰值位置和是否出现，取决于数据噪声、模型族、优化方法和评估协议。

在插值阈值附近，模型刚好拥有拟合训练噪声的能力，训练解可能对数据扰动很敏感。继续增大模型后，优化器可能找到具有不同隐式偏置的解，测试误差重新下降。但这不意味着无限扩大模型就一定更好，因为数据质量、计算预算、分布变化和部署成本仍然是约束。

### 记忆和泛化并不是二选一

模型记忆训练样本中的字符串，不等于它完全没有学到结构；模型能解决新组合，也不等于它没有记忆。两种现象可以同时出现。

更容易被记忆的内容通常具有以下特征：

- 在训练语料中重复出现；
- 格式固定、局部模式强；
- 训练轮数多或被过采样；
- 具有高辨识度的罕见字符串；
- 代码、日志、配置和个人信息等可逐字复现内容。

更接近泛化的证据则包括：对训练中未出现的组合、同构问题、语义改写和轻微输入扰动仍保持稳定；在时间切分或私有动态测试集上仍有效；能力不依赖复现某个固定答案。

这些只是证据，不是绝对判定。泛化测试本身也可能和训练数据高度相似，所以必须记录数据来源和相似度检测方法。

### 数据污染会怎样扭曲评估

如果 benchmark 原题、解答或高度相似的改写出现在训练数据中，模型在该 benchmark 上的高分就不能直接解释为未见任务泛化。污染可能来自：

1. benchmark 发布后被大量网页转载；
2. 训练语料包含公开答案或讨论；
3. 训练数据和测试数据来自同一文档或代码仓库；
4. 评估题型模板被重复生成；
5. 数据清洗只做了完全相同字符串去重，没有处理近似重复。

检测可以从 exact match、n-gram 重叠、文档指纹、embedding 相似度和时间元数据入手。每种检测都有漏报和误报：语义相似不一定是污染，完全不同的表达也可能泄露同一答案。因此最强的做法通常是使用训练时间之后收集的私有数据、动态生成但可审计的任务，或者对样本来源做严格隔离。

### Scaling law 应该怎样读

语言模型研究中常见一种经验形式：在数据、模型和优化处于合理范围时，验证损失会随模型规模 N、数据量 D 和计算量 C 以近似幂律下降。一个示意写法是：

~~~math
L(N,D,C)
\approx L_\infty
+A N^{-\alpha}
+B D^{-\beta}
+E C^{-\gamma}
~~~

这个式子是经验拟合的表达，不是所有架构、所有数据和所有任务都必须遵守的物理定律。它的价值在于帮助我们思考资源分配：模型太大而数据不足可能浪费计算，数据很多而模型太小可能受容量限制，训练不足也会让一个本可更好的模型停在较差状态。

compute-optimal 训练的核心不是“永远多加参数”，而是在固定计算预算下平衡参数量和训练 token 数。具体最优比例会受 tokenizer、数据质量、序列长度、硬件利用率和训练目标影响。

### 如何设计更可信的泛化实验

一个可复现的泛化实验至少要写清楚：

1. 训练数据与评估数据的来源和时间；
2. 去重和污染检测规则；
3. 模型 checkpoint、解码参数和上下文模板；
4. 任务级成功标准；
5. 各领域、长度、难度和风险切片；
6. 置信区间或多次运行的波动；
7. 失败案例，而不仅是总体平均分。

如果要区分记忆与泛化，可以构造成对实验：原始题、语义改写、结构同构题和新组合题分别测试，并检查训练数据中是否存在相似源文档。若只报告原题 exact match，结论很弱。

### 一个双下降形状的玩具实验

下面的列表只是人为构造的曲线，用来练习读图和识别插值附近的峰值，不是对真实模型的证明。

~~~python
model_complexity = [1, 2, 3, 4, 5, 6, 7, 8]
test_error = [0.58, 0.45, 0.36, 0.53, 0.41, 0.33, 0.29, 0.27]

for size, error in zip(model_complexity, test_error):
    print("complexity =", size, "test_error =", round(error, 3))

interpolation_region = range(2, 5)
peak_index = max(interpolation_region, key=test_error.__getitem__)
print("toy interpolation-region peak:", model_complexity[peak_index])
~~~

真正的实验需要训练多个规模的模型，固定数据和优化协议，并把模型规模、训练步数和数据量分别改变。只画一条手工列表不能支持因果结论。

### 初学者与专家的两层理解

初学者先掌握一个判断顺序：训练集表现回答“有没有学会拟合”，验证集回答“在相近未见数据上是否有效”，分布外切片回答“换环境后是否仍然稳健”。三者不能互相替代。

专家需要把“泛化”拆成可测量的对象：概率泛化、任务泛化、组合泛化、时间泛化、行为泛化和安全泛化。每个对象都可能有不同结果。一个模型可以在 held-out NLL 上更好，却在工具参数、事实引用或安全边界上退化。

### 证据边界

经验风险与真实风险的区分来自统计学习理论。双下降和 scaling law 主要来自论文与大规模实验，形状和指数不是普适常数。数据污染检测能提高评估可信度，但没有一种相似度阈值可以证明“绝对未污染”。记忆与泛化的区分需要成对数据、时间信息和多种测试共同支持。

## 5. 贝叶斯视角、不确定性与幻觉

### 从点估计走向分布估计

普通深度学习训练通常返回一组参数 θ。给定数据 D，我们得到一个点估计：

~~~math
\theta^\star=\arg\min_\theta\mathcal L(D,\theta)
~~~

贝叶斯视角会把参数当作随机变量，询问看到数据后不同参数的可信程度。贝叶斯公式为：

~~~math
P(\theta\mid D)
=\frac{P(D\mid\theta)P(\theta)}{P(D)}
~~~

其中 P(θ) 是先验，P(D∣θ) 是似然，P(θ∣D) 是后验，P(D) 是证据项。常用的简写是“后验与似然乘先验成正比”，但不要把先验理解成主观猜测的同义词；架构、数据、正则化和优化器同样可以提供归纳偏置。

### MLE 与 MAP

最大似然估计只最大化似然：

~~~math
\theta_{\mathrm{MLE}}
=\arg\max_\theta \log P(D\mid\theta)
~~~

最大后验估计同时考虑先验：

~~~math
\theta_{\mathrm{MAP}}
=\arg\max_\theta
[\log P(D\mid\theta)+\log P(\theta)]
~~~

若参数先验是零均值高斯分布：

~~~math
P(\theta)\propto
\exp\left(-\frac{\lambda}{2}\|\theta\|_2^2\right)
~~~

则负对数后验中会出现 L2 惩罚项：

~~~math
\mathcal L_{\mathrm{MAP}}
=\mathcal L_{\mathrm{NLL}}
+\frac{\lambda}{2}\|\theta\|_2^2
~~~

这解释了“L2 正则可以看成高斯先验”的说法。它是一个有用的等价关系，但不能因此声称所有正则化都等于完整贝叶斯推断。完整贝叶斯需要对参数后验积分，而普通训练通常只保留一个参数点。

### 预测不确定性不是参数不确定性

完整贝叶斯预测要对参数后验求平均：

~~~math
P(y\mid x,D)
=\int P(y\mid x,\theta)P(\theta\mid D)\,d\theta
~~~

真实大模型通常不会显式计算这个高维积分。它在固定参数 θ 下输出 token 分布：

~~~math
P_\theta(x_t\mid x_{1:t-1})
~~~

这个 softmax 反映的是当前参数和上下文下的相对偏好，不等于“这个完整答案为真的概率”。尤其是事实问题中，流畅语言和事实证据是两件不同的事。

### Aleatoric 与 epistemic

不确定性至少可以从两个来源理解。

Aleatoric uncertainty 来自数据或任务本身的不可约歧义，例如用户问题含糊、未来事件不可预测、同一个开放问题有多个合理答案。更多训练数据不一定消除它。

Epistemic uncertainty 来自模型知识或覆盖不足，例如新领域、新工具 schema、知识截止时间之后的事件和分布外输入。更多高质量数据、检索、工具或更好的模型有机会降低它。

这两个概念不是把模型输出直接贴两个标签就完成了。现实中的一个错误可能同时包含数据歧义和模型无知，所以评估时要构造可区分的样本和外部证据。

### 校准：置信度是否可被解释

若模型对一组样本都声称有 80% 置信度，长期来看约 80% 正确，则称它在这个范围内校准良好。对分类任务，可以把预测置信度分成 M 个桶，期望校准误差 ECE 的常见估计为：

~~~math
\mathrm{ECE}
=\sum_{m=1}^{M}
\frac{|B_m|}{n}
\left|\mathrm{acc}(B_m)
-\mathrm{conf}(B_m)\right|
~~~

其中 B_m 是第 m 个置信度桶，acc 是桶内正确率，conf 是桶内平均置信度，n 是样本总数。

对开放式语言模型，困难在于“一个回答的置信度”没有天然唯一的定义。可以使用答案级概率、多个采样的一致性、事实核验结果或任务特定的 verifier，但每一种定义都测量不同东西。把最后一个 token 的最大 softmax 当作整段事实答案的置信度，通常没有充分依据。

另一个有用的指标是 Brier score。若结果 y∈{0,1}，预测概率 p 为：

~~~math
\mathrm{Brier}
=\frac{1}{n}\sum_{i=1}^{n}(p_i-y_i)^2
~~~

它同时惩罚错误和过度自信。不同指标可能给出不同排序，因此应根据风险场景选择。

### 选择性预测与合理拒答

在高风险任务中，系统不一定要求模型对所有输入都回答。设模型只对置信度超过阈值的样本回答，其余样本转人工、检索或请求澄清。此时要同时报告：

- coverage：实际回答的样本比例；
- selective risk：被回答样本中的错误率；
- abstention rate：主动退出的比例。

提高阈值通常能降低选择性风险，却会降低覆盖率。可靠性不是让模型永不拒答，而是在风险、覆盖和用户成本之间找到可解释的点。

### 幻觉为什么会发生

“幻觉”不是一个单一机制。常见因素包括：

1. 训练语料含有错误、冲突或过时信息；
2. 当前输入缺少足够证据；
3. 模型将语言流畅性误当成事实支持；
4. 采样过程选择了一个低概率但连贯的路径；
5. 后训练鼓励完整、迅速和有帮助的回答；
6. 外部检索结果本身不相关、过时或互相冲突；
7. 生成阶段没有把证据与每个结论对齐。

因此“让模型更自信”通常不是解决方案。可靠系统应允许模型表达不确定、请求澄清、引用可核验证据、调用工具或拒绝做无依据的断言。

### RAG 不能自动消除不确定性

检索增强生成把外部文档放入上下文，改变了模型的条件分布，但它不保证三件事：

- 检索到的文档真的相关；
- 文档中的结论真的正确；
- 生成内容忠实地使用了文档。

一个完整的事实性评估应分别检查检索召回、证据覆盖、结论蕴含和引用定位。只报告“接入 RAG 后答案更长”或“引用数量更多”，不能证明幻觉下降。

### 用 Beta–Binomial 观察后验变化

下面的例子用 Beta(α,β) 作为二项概率的先验。观察到正例和反例后，后验参数分别加上计数：

~~~python
import math


def beta_update(alpha, beta, positives, negatives):
    if not math.isfinite(alpha) or not math.isfinite(beta) or alpha <= 0 or beta <= 0:
        raise ValueError("alpha and beta must be finite and positive")
    if any(
        isinstance(value, bool) or not isinstance(value, int) or value < 0
        for value in (positives, negatives)
    ):
        raise ValueError("counts must be non-negative integers")
    posterior_alpha = alpha + positives
    posterior_beta = beta + negatives
    mean = posterior_alpha / (posterior_alpha + posterior_beta)
    return posterior_alpha, posterior_beta, mean


for positives, negatives in [(8, 2), (80, 20), (8000, 2000)]:
    result = beta_update(1, 1, positives, negatives)
    print(
        "observations =", positives + negatives,
        "posterior =", result[:2],
        "mean =", round(result[2], 4),
    )
~~~

相同的观测比例在样本量不同时具有不同证据强度。一个小样本的 80% 正确率，不应和大量样本的 80% 正确率被解读成同样确定。

### 一个简单的 ECE 计算

下面的函数适合二分类或“回答是否通过”这类已经有明确结果的任务。它不解决开放式答案如何定义置信度的问题，只展示校准计算的机械部分。

~~~python
def expected_calibration_error(confidences, outcomes, bins=5):
    total = len(confidences)
    if total == 0 or total != len(outcomes):
        raise ValueError("confidences and outcomes must be non-empty and aligned")
    if isinstance(bins, bool) or not isinstance(bins, int) or bins <= 0:
        raise ValueError("bins must be a positive integer")
    if any(
        not isinstance(confidence, (int, float))
        or not 0 <= confidence <= 1
        for confidence in confidences
    ):
        raise ValueError("confidences must lie in [0, 1]")
    if any(type(outcome) is not int or outcome not in (0, 1) for outcome in outcomes):
        raise ValueError("outcomes must be integer 0/1 values")
    error = 0.0
    for index in range(bins):
        lower = index / bins
        upper = (index + 1) / bins
        members = [
            (confidence, outcome)
            for confidence, outcome in zip(confidences, outcomes)
            if lower <= confidence < upper
            or (index == bins - 1 and confidence == upper)
        ]
        if not members:
            continue
        mean_confidence = sum(item[0] for item in members) / len(members)
        accuracy = sum(item[1] for item in members) / len(members)
        error += len(members) / total * abs(mean_confidence - accuracy)
    return error


confidences = [0.55, 0.62, 0.74, 0.81, 0.93]
outcomes = [1, 0, 1, 1, 0]
print("ECE =", round(expected_calibration_error(confidences, outcomes), 4))
~~~

ECE 只有在样本、置信度和结果一一对应时才有定义；空输入、长度不一致、超出 `[0, 1]` 的置信度、非法结果和非正桶数都应显式报错。若某个桶为空，它对总和的贡献为零，这与整个评估集为空是两种不同情况。

### 初学者与专家的两层理解

初学者要记住：模型说“概率高”只表示它倾向于这样生成，不等于事实已经被验证；遇到知识不足时，检索、工具和合理拒答是系统能力的一部分。

进一步分析时要区分参数不确定性、数据噪声、预测校准、答案一致性和证据支持。多次采样很一致，可能说明模型稳定，也可能说明模型稳定地犯同一个错误；检索有引用，可能说明证据存在，也可能只是引用与结论不匹配。

### 证据边界

贝叶斯公式、MLE/MAP 关系和 ECE 定义是数学或统计定义。深度网络中使用 ensemble、dropout 或采样近似不确定性，是工程近似而不是完整后验推断。幻觉成因具有多因素性质；RAG、校准和拒答能够降低部分风险，但不能保证所有事实正确。

## 6. 损失函数是代理目标：从预训练到偏好优化

### 为什么可优化的目标不等于最终目标

产品目标往往是“给出正确、有帮助、安全、简洁且可执行的回答”。这些要求相互关联，却很难写成一个稳定、可微、低成本的函数。训练系统因此选择代理目标：

- 预训练用 next-token likelihood；
- 监督微调用参考答案的交叉熵；
- 偏好优化用人类或合成偏好数据；
- 代码训练可以用测试通过率；
- 工具系统可以用 schema 合法率和执行结果。

代理目标的价值在于可计算、可规模化，但它总会遗漏一部分真实目标。一个成熟的训练设计必须同时问两件事：这个目标推动了什么？它没有约束什么？

### Token-level 目标与任务级成功

语言模型的典型损失为：

~~~math
\mathcal L_{\mathrm{token}}
=-\sum_{t=1}^{T}
\log P_\theta(y_t\mid x,y_{1:t-1})
~~~

数学题、代码和工具调用的成功事件往往是离散的：

~~~math
\mathcal L_{\mathrm{task}}
=\mathbf 1[
\text{答案不正确或执行失败}
]
~~~

两个目标并不等价。一个代码回答只错一个字符，token 平均损失可能只增加一点，但程序完全不能运行。一个摘要用了更多高概率常见词，token loss 可能下降，却可能漏掉关键事实。

因此训练报告应至少把 token-level 指标和 task-level 指标并列，而不是用前者替代后者。

### 预训练的收益与边界

预训练的 next-token 目标具有三个巨大优势：数据无需逐条人工标注，目标可以扩展到极大语料，训练和自回归生成在形式上保持一致。它能学习语言结构、知识关联、代码模式和许多任务格式。

但互联网语料也包含错误、偏见、过时内容、低质量答案和不安全模式。预训练模型学习的是数据分布中的统计规律，不会因为文本出现在网页上就自动知道它是真的。它也不会因为某个规则对人类重要，就自动把它当作最高优先级。

### SFT 的目标错配

监督微调通常最大化参考答案概率：

~~~math
\mathcal L_{\mathrm{SFT}}
=-\sum_{(x,y)\in D}
\log P_\theta(y\mid x)
~~~

它能让模型遵循指令、学习格式和模仿示范，但有几个边界：

1. 一个问题可能有很多同样好的答案；
2. 参考答案可能含有事实错误或风格偏差；
3. 长答案中局部 token 拟合不代表整体完成任务；
4. 数据中固定的口头禅、长度和拒答模式会被放大；
5. 参考答案的“像不像”与“是否真的解决问题”不是一回事。

例如，数据若普遍把回答写得很长，模型可能学会用更多解释掩盖不确定；若拒答样本比例过高，安全分数可能上升而有用性下降。

### RLHF 与 reward model

经典 RLHF 流程通常包括：对同一输入收集多个回答；让标注者比较偏好；训练 reward model；再用强化学习更新策略模型。设奖励模型为 r_φ(x,y)，策略为 π_θ，最简化的目标可写成：

~~~math
\max_\theta
\mathbb E_{x\sim D,\;y\sim\pi_\theta(\cdot\mid x)}
[r_\phi(x,y)]
~~~

实际系统通常还会加入相对参考策略的 KL 约束：

~~~math
\max_\theta
\mathbb E[r_\phi(x,y)]
-\beta D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}})
~~~

这样做的动机是让模型追求偏好，同时避免过快偏离原始能力分布。但 reward model 只是标注偏好的近似器，受标注一致性、覆盖范围和表面特征影响。优化 reward 分数，不等于优化长期真实满意度。

### DPO 的目标与依赖

DPO 不需要先显式训练一个在线强化学习策略，而是直接使用 chosen 与 rejected 回答对。其常见损失形式为：

~~~math
\mathcal L_{\mathrm{DPO}}
=-\mathbb E\left[
\log\sigma\left(
\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}
{\pi_{\mathrm{ref}}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}
{\pi_{\mathrm{ref}}(y_l\mid x)}
\right]\right)
\right]
~~~

其中 y_w 是偏好回答，y_l 是非偏好回答，π_ref 是参考策略，β 控制相对偏离的尺度。公式说明 DPO 仍然依赖偏好数据质量和参考模型；如果偏好标签只奖励表面流畅、长度或礼貌，DPO 也会把这些相关性学得更强。

### Goodhart 现象与 reward hacking

当一个指标只是目标的代理时，强力优化它可能让系统寻找指标漏洞。语言模型中的例子包括：

- 奖励回答更长，模型增加重复解释；
- 奖励语气更自信，模型减少必要的保留意见；
- 奖励引用数量，模型生成看似合理但无法核验的引用；
- 奖励安全拒答率，模型对正常请求也拒绝；
- 奖励 benchmark 分数，模型适应题型或污染数据。

这类现象常被称为 reward hacking。它不是模型“有恶意”，而是优化器忠实地追逐了定义中的信号，而设计者没有把真实意图完全编码进去。模型越强、优化越充分，越可能找到代理目标的缝隙。

### 多目标与 Pareto 取舍

现实系统至少同时关心正确性、有用性、安全性、延迟、成本、格式遵循和鲁棒性。不存在一个设置在所有维度都严格更好。可以把一次实验看成在多个指标空间中寻找 Pareto 改善：若一个方案在所有重要指标上不差、至少一个指标更好，它才真正支配另一个方案。

工程报告应写出主动承担的代价，例如：

- 提高拒答边界后，有用性下降多少；
- 增加检索后，事实性提升是否值得延迟；
- 换用门控 MLP 后，质量提升是否抵消了 FLOPs；
- 更长输出是否带来信息增益，还是只增加成本。

没有副作用监控的单指标提升，很容易只是把问题从一个维度搬到另一个维度。

### 目标错配的诊断实验

当训练 loss 变好但产品效果变差时，可以按以下顺序建立证据：

1. 固定 checkpoint、解码参数和评估数据，确认指标没有实现错误；
2. 查看训练、验证和不同领域切片的 token loss；
3. 查看任务级成功率、格式合法率和人工偏好；
4. 按长度、难度、风险和输入类型切片；
5. 检查输出长度、拒答率、引用率和工具调用分布是否漂移；
6. 对关键失败案例进行人工归因；
7. 用 ablation 区分数据、损失、参考模型和解码策略的影响。

如果只看平均分，无法判断是少量灾难性失败，还是所有样本均匀改善。

### 一个代理指标反转的示例

下面构造两个模型的统计结果。模型 B 的平均 token loss 更低，但任务正确率和安全通过率更差。这个例子不是实际评测器，而是提醒我们不要把一个数字当成整体结论。

~~~python
models = {
    "A": {
        "loss": [0.8, 0.9, 0.7, 0.8],
        "task_success": [1, 1, 0, 1],
        "safety_pass": [1, 1, 1, 1],
    },
    "B": {
        "loss": [0.5, 0.6, 0.4, 0.5],
        "task_success": [1, 0, 0, 1],
        "safety_pass": [1, 0, 1, 0],
    },
}


def average(values):
    return sum(values) / len(values)


for name, metrics in models.items():
    print(
        name,
        "loss =", round(average(metrics["loss"]), 3),
        "task =", round(average(metrics["task_success"]), 3),
        "safety =", round(average(metrics["safety_pass"]), 3),
    )
~~~

实验设计的关键不是人为选择一个“正确模型”，而是把最终任务和副作用都列入结果表，并解释指标之间的冲突。

### 初学者与专家的两层理解

初学者先形成一个习惯：每当看到指标上升，问它究竟代理了哪一个目标，又没有覆盖哪一个目标。

进一步检查目标的测量层级：训练 token、完整序列、交互回合、长期用户结果和安全事件是否被混在一起；还要检查优化过程是否会利用标注规则、评估集或 reward model 的盲区。

### 证据边界

预训练、SFT、RLHF 和 DPO 的目标形式可以由公开论文和常见实现确认，但不同项目的细节并不相同。Goodhart 现象和 reward hacking 是设计风险，不是每个训练过程必然发生的结果。任何目标改动都需要独立的任务评估、风险切片和失败案例验证。

## 7. 初始化、归一化与训练稳定性

### 深层网络为什么会不稳定

深度网络是许多函数的复合。设第 l 层的表示为 h_l：

~~~math
h_L=f_L\circ f_{L-1}\circ\cdots\circ f_1(x)
~~~

反向传播中的梯度包含一串 Jacobian 矩阵乘积：

~~~math
\frac{\partial\mathcal L}{\partial h_1}
=\frac{\partial\mathcal L}{\partial h_L}
\prod_{l=2}^{L}
\frac{\partial h_l}{\partial h_{l-1}}
~~~

如果这些矩阵在相关方向上反复放大信号，梯度可能爆炸；如果反复缩小信号，梯度可能消失。实际 Transformer 还要叠加 attention logits、MLP 激活、残差累积、混合精度、长序列和分布式同步等因素。

训练稳定性不是“loss 一直单调下降”。更实用的定义是：在给定资源和训练协议下，激活、梯度、参数更新、loss 和验证行为都处于可监控、可恢复的范围内。

### 初始化要保持什么

随机初始化的目标不是让权重“看起来随机”，而是让信号穿过网络时尺度不要迅速失控。对线性层 y=Wx，若输入各维独立、均值近似为零，粗略有：

~~~math
\mathrm{Var}(y_j)
\approx n_{\mathrm{in}}\mathrm{Var}(W_{ji})
\mathrm{Var}(x_i)
~~~

如果权重方差过大，前向激活会层层放大；过小则会逐渐衰减。反向梯度也有类似问题。

Xavier/Glorot 初始化常用的方差尺度是：

~~~math
\mathrm{Var}(W)
\approx\frac{2}{n_{\mathrm{in}}+n_{\mathrm{out}}}
~~~

He 初始化针对 ReLU 的截断效应，常见尺度是：

~~~math
\mathrm{Var}(W)
\approx\frac{2}{n_{\mathrm{in}}}
~~~

这些公式是独立同分布和局部线性等假设下的近似。Transformer 中存在 residual、GELU 或 SwiGLU、归一化和多种投影矩阵，因此最终初始化还要看具体架构和训练深度。

### Residual path 为什么重要

残差块把子层输出作为增量加回主干：

~~~math
x_{l+1}=x_l+F_l(x_l)
~~~

当 F_l 的输出不是特别大时，主干提供了一条近似 identity path。前向信息和反向梯度都可以部分绕过复杂子层，这使深层网络更容易优化。

但残差不是自动稳定器。如果每一层的增量都偏大，许多层叠加后仍可能让表示范数快速增长。深层架构会通过归一化、初始化缩放、残差缩放或更细致的参数化来控制这种累积。

### BatchNorm、LayerNorm 与 RMSNorm

BatchNorm 依赖一个 batch 的统计量。对语言模型来说，变长序列、padding、自回归推理、动态 batch 和分布式同步会让训练统计与推理统计难以保持一致，所以 Transformer 语言模型更常使用 LayerNorm 或 RMSNorm。

对某个 token 的 hidden vector x∈R^d，LayerNorm 先计算均值和方差：

~~~math
\mu=\frac{1}{d}\sum_{i=1}^{d}x_i
~~~

~~~math
\sigma^2=\frac{1}{d}\sum_{i=1}^{d}(x_i-\mu)^2
~~~

~~~math
\mathrm{LN}(x)_i
=\gamma_i\frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_i
~~~

γ 和 β 是可学习的逐维缩放和平移参数，ε 防止除零。

RMSNorm 不减去均值，只控制均方根尺度：

~~~math
\mathrm{RMS}(x)
=\sqrt{\frac{1}{d}\sum_{i=1}^{d}x_i^2+\epsilon}
~~~

~~~math
\mathrm{RMSNorm}(x)_i
=\gamma_i\frac{x_i}{\mathrm{RMS}(x)}
~~~

RMSNorm 的计算更简洁，在许多现代语言模型中表现稳定，但“更简单”不等于“在所有架构上更优”。归一化位置、ε、精度和 kernel 实现都会影响结果。

### Pre-LN 与 Post-LN

Post-LN 的一个简化形式是：

~~~math
x_{l+1}=\mathrm{LN}(x_l+F_l(x_l))
~~~

Pre-LN 则是：

~~~math
x_{l+1}=x_l+F_l(\mathrm{LN}(x_l))
~~~

Pre-LN 把 identity path 保留得更直接，深层训练通常更容易稳定；Post-LN 的每层输出都被规范化，但深层梯度和学习率要求可能更敏感。实际架构还可能使用 RMSNorm、额外 final norm 或其他变体，不能把两个公式当作完整实现。

Pre-LN 也有代价和边界：残差主干的尺度可能随深度累积，子层更新可能变弱，最终输出通常需要额外归一化。因此“更容易训练”和“最终效果必定更好”是两个不同命题。

### Attention 中的平方根缩放

缩放点积注意力写成：

~~~math
\mathrm{Attention}(Q,K,V)
=\mathrm{softmax}
\left(\frac{QK^\mathsf T}{\sqrt{d_k}}\right)V
~~~

如果 Q 和 K 的每个分量均值为 0、方差约为 1，那么点积是 d_k 项乘积之和，方差大致随 d_k 增长。除以 √d_k 可以把 logits 的尺度拉回相对稳定的范围，减少 softmax 过早饱和。

这不是保证数值永远安全的充分条件。异常激活、错误 mask、低精度累积和极端长序列仍可能造成 Inf 或 NaN。

### Warmup、衰减与梯度裁剪

Warmup 在训练开始时把学习率从较小值逐步提高到峰值，例如线性形式：

~~~math
\eta_t
=\eta_{\max}\min\left(1,\frac{t}{T_{\mathrm{warmup}}}\right)
~~~

训练初期，参数、优化器的动量统计和激活尺度都还没有进入稳定状态，直接使用峰值学习率可能造成大更新。warmup 只是降低早期风险，不会修复错误数据或错误实现。

梯度裁剪通常按总范数缩放。若 g 的范数超过阈值 c：

~~~math
\widetilde g
=g\cdot\min\left(1,\frac{c}{\lVert g\rVert_2}\right)
~~~

它能限制单次异常更新，但可能掩盖根因。若每一步都严重裁剪，应检查学习率、数据、loss mask、精度和模型结构，而不是把裁剪阈值越调越小。

### FP16、BF16 与数值范围

混合精度通过低精度矩阵计算降低显存和提高吞吐，同时保留部分 FP32 累积或状态。FP16 的指数范围较窄，容易 overflow/underflow；BF16 的指数范围接近 FP32，通常更能承受大动态范围，但有效精度位数不同，仍需要合适的累积和归一化实现。

常见风险包括：

- attention logits 太大；
- loss scale 不合适；
- 梯度下溢后变成零；
- LayerNorm 方差过小；
- optimizer state 用了不合适的精度；
- 某个 rank 先出现 NaN，随后同步到全局。

所以“换成 BF16 就稳定”也不是普遍结论。稳定性应通过实际日志和最小复现实验确认。

### Loss spike 与 NaN 的排查路径

出现异常时，建议先把问题定位到时间、数据、设备和数值操作四个维度：

1. 保存触发异常前后若干 batch 的样本标识、长度和 loss mask；
2. 检查学习率、warmup、梯度范数、参数范数和更新比率；
3. 检查输入、label、attention mask 和 position id 是否合法；
4. 检查 softmax、归一化、激活和 loss 中是否首次出现 Inf/NaN；
5. 检查每个 rank 的局部 loss、梯度同步和通信状态；
6. 从最近的正常 checkpoint 用同一个 batch 单步复现；
7. 恢复时确认 optimizer state、scheduler state 和 step count 一致。

如果 spike 后迅速恢复，可能是单个异常 batch 或短暂数值事件；如果验证行为持续退化，应回滚到正常 checkpoint 并保留触发样本，不要直接覆盖证据。

### 一个可运行的梯度范数实验

下面只使用 Python 数值列表模拟梯度裁剪，帮助理解裁剪前后方向不变、范数受限的性质。

~~~python
import math


def l2_norm(vector):
    if not vector or any(not math.isfinite(value) for value in vector):
        raise ValueError("vector must be non-empty and finite")
    return math.sqrt(sum(value * value for value in vector))


def clip_by_norm(vector, threshold):
    if not math.isfinite(threshold) or threshold < 0:
        raise ValueError("threshold must be finite and non-negative")
    norm = l2_norm(vector)
    if norm == 0:
        return list(vector), norm
    scale = min(1.0, threshold / norm)
    return [value * scale for value in vector], norm


gradient = [3.0, 4.0, 12.0]
clipped, before = clip_by_norm(gradient, threshold=5.0)
print("before =", round(before, 4))
print("after =", round(l2_norm(clipped), 4))
print("clipped =", [round(value, 4) for value in clipped])
~~~

真实框架会对所有参数张量的梯度做全局范数计算，并处理设备、分布式和混合精度。这个小例子不替代框架实现，只展示数学操作。
零向量直接返回，不把零范数替换成一个人为的正数；空向量、非有限梯度和负阈值则报告为输入错误。这样可以区分“没有梯度”与“梯度很小”这两个不同的诊断结果。

### 初学者与专家的两层理解

初学者要建立“稳定性是系统属性”的概念：归一化、初始化、残差、学习率、裁剪、精度和数据共同决定训练是否可控。

更深入的诊断要把稳定性拆成可观测量：激活分布是否漂移，梯度是否集中在少数层，更新与权重的比率是否异常，某个 rank 是否先出错，checkpoint 恢复后优化器状态是否连续。只有这些信息齐全，调参才不是盲试。

### 证据边界

链式法则、归一化公式、初始化方差和梯度裁剪是数学或算法定义。Pre-LN 在深层 Transformer 中通常更易训练，是论文和实践中的经验结论；具体模型仍需验证。FP16/BF16 的优缺点取决于硬件、kernel、累积方式和损失尺度，不能只根据数据类型名称判断稳定性。

## 8. 激活函数、门控 MLP 与 SwiGLU

### 为什么 Transformer 不能只有线性层

如果连续堆叠线性层：

~~~math
y=W_3W_2W_1x
~~~

它们仍然可以合并成一个线性变换 W x。没有非线性，网络深度不会带来足够的函数表达能力。激活函数让网络能够组合不同区域的输入，并形成复杂的特征变换。

Transformer block 通常包含 attention 和 MLP 两类子层。attention 主要负责跨 token 的信息混合，MLP 对每个位置的 hidden state 独立进行非线性特征变换。这个说法是帮助建立结构直觉，不表示两者在功能上完全隔离。

### ReLU、GELU 与 SiLU

ReLU 定义为：

~~~math
\mathrm{ReLU}(x)=\max(0,x)
~~~

它计算便宜、正区间梯度简单，但负区间梯度为零，可能产生长期不激活的单元。

GELU 定义为：

~~~math
\mathrm{GELU}(x)=x\Phi(x)
~~~

Φ 是标准正态分布的累积分布函数。GELU 不会把所有负值硬切为零，而是根据输入大小平滑地保留一部分。

SiLU/Swish 的一种写法是：

~~~math
\mathrm{SiLU}(x)=x\sigma(x)
~~~

其中 σ 是 sigmoid。它同样是平滑的输入相关调制。平滑激活常与 Transformer 的归一化和残差结构配合良好，但具体效果仍取决于规模和超参数。

### 普通 FFN

标准前馈网络可以写成：

~~~math
\mathrm{FFN}(x)
=W_{\mathrm{down}}\,
\phi(W_{\mathrm{up}}x+b_{\mathrm{up}})
+b_{\mathrm{down}}
~~~

通常先把 d_model 扩大到 d_ff，再投影回 d_model。若 d_ff≈4d_model，两个主要矩阵的参数量约为 8d_model²。MLP 在很多 Transformer 中占据比 attention 更大的参数和 FLOPs，因此不能把 Transformer 的能力全部归因于 attention。

### GLU 的乘法结构

门控线性单元把中间表示分成内容分支和控制分支：

~~~math
a=W_ax,\qquad c=W_cx
~~~

~~~math
\mathrm{GLU}(x)
=a\odot\sigma(c)
~~~

逐元素乘法让控制分支根据输入调制内容分支。与单独使用一个激活函数相比，它引入了输入相关的乘法交互。

GEGLU 可以把 sigmoid 换成 GELU：

~~~math
\mathrm{GEGLU}(x)
=(W_ax)\odot\mathrm{GELU}(W_cx)
~~~

SwiGLU 则使用 SiLU：

~~~math
\mathrm{SwiGLU}(x)
=(W_{\mathrm{up}}x)
\odot\mathrm{SiLU}(W_{\mathrm{control}}x)
~~~

最后再用 W_down 投影回模型维度：

~~~math
\mathrm{MLP}_{\mathrm{SwiGLU}}(x)
=W_{\mathrm{down}}\mathrm{SwiGLU}(x)
~~~

### 参数量为什么要重新计算

普通 FFN 有两个投影矩阵，参数量近似：

~~~math
2d_{\mathrm{model}}d_{\mathrm{ff}}
~~~

SwiGLU 有 up、control、down 三个矩阵，若中间宽度是 h，参数量近似：

~~~math
3d_{\mathrm{model}}h
~~~

如果想让它接近普通的 d_ff=4d_model FFN，需要：

~~~math
3d_{\mathrm{model}}h
\approx 8d_{\mathrm{model}}^2
\quad\Longrightarrow\quad
h\approx\frac{8}{3}d_{\mathrm{model}}
~~~

这就是常见的 8/3 比例的来源之一。实际模型还会考虑 bias、张量并行的整除约束、激活 kernel 和硬件吞吐，因此不能把 8/3 当成不变规则。

### 为什么门控可能有效

门控 MLP 的潜在收益来自三点：

1. 每个输入可以选择不同的特征通道；
2. 内容与控制分支的乘法增加了条件交互；
3. 平滑激活允许控制强度连续变化，而不是只有开或关。

这是一种表达能力上的直觉，不等于任何门控设计都会提升质量。如果控制分支尺度过大，乘法还可能放大激活和梯度；因此它必须与初始化、归一化、学习率和 kernel 实现一起评估。

### MLP 是否在存储知识

研究中常把 FFN 描述为某种 key–value memory，或者在特征方向上分析特定概念。这些视角有助于理解，但不能把知识定位为“某个神经元里的一条事实”。实际知识通常分布在 embedding、attention、MLP 和多层表示之中；单个神经元的可解释性也受基底、重参数化和特征叠加影响。

更稳妥的说法是：MLP 承担大量非线性变换和参数容量，可能编码很多知识与模式，但不能据此断定知识只存在 MLP，或可以用简单的单神经元编辑完全控制。

### 一个框架无关的形状推演

设输入形状为 [B,S,d]，B 是 batch size，S 是序列长度，d 是模型维度，h 是中间宽度，则：

~~~text
x             [B, S, d]
up(x)         [B, S, h]
control(x)    [B, S, h]
SiLU(control) [B, S, h]
逐元素相乘     [B, S, h]
down(...)     [B, S, d]
~~~

形状检查是实现门控 MLP 时最先做的单元测试。随后还要检查参数量、峰值激活显存、吞吐和数值范围。

### 一个简单的标量门控实验

下面用列表实现 SiLU 和逐元素调制，不依赖深度学习框架。它只用于观察输入改变时控制分支如何改变输出，不代表真实模型的训练效果。

~~~python
import math


def sigmoid(value):
    if value >= 0:
        return 1.0 / (1.0 + math.exp(-value))
    exponential = math.exp(value)
    return exponential / (1.0 + exponential)


def silu(value):
    return value * sigmoid(value)


content = [1.0, 1.0, 1.0, 1.0]
control = [-3.0, -0.5, 0.5, 3.0]
hidden = [a * silu(c) for a, c in zip(content, control)]
print([round(value, 4) for value in hidden])
~~~

控制值较大时更接近保留内容，负值会抑制内容，但它不是二值开关。真实网络中两条分支都由矩阵投影产生，且会通过归一化和训练共同调整。

### 初学者与专家的两层理解

初学者先掌握一个结构句子：attention 让 token 之间交换信息，MLP 对每个 token 的表示做非线性变换，门控 MLP 再让这种变换依赖输入。

更深入的设计要同时计算质量和成本：SwiGLU 增加一条投影分支，hidden width 若不调整会增加参数和 FLOPs；门控乘法需要硬件 kernel 支持；MLP 的知识解释不能简化成单个神经元存储事实。

### 证据边界

激活函数和 GLU 变体的公式是定义。SwiGLU 在许多 Transformer 实验中表现良好，但收益依赖模型规模、数据、参数预算、训练配置和实现。关于 MLP 与知识存储的解释属于机制研究中的有用视角，不应写成完整因果结论。

## 9. 优化器、状态显存与训练成本

### 优化器决定更新轨迹

给定梯度 g_t，最基本的 SGD 更新为：

~~~math
\theta_{t+1}=\theta_t-\eta_tg_t
~~~

Momentum 用历史方向平滑噪声：

~~~math
m_t=\beta m_{t-1}+(1-\beta)g_t
~~~

~~~math
\theta_{t+1}=\theta_t-\eta_t m_t
~~~

Adam 同时维护一阶矩和二阶矩：

~~~math
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t
~~~

~~~math
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
~~~

由于 m 和 v 从零开始，Adam 使用偏差修正：

~~~math
\widehat m_t=\frac{m_t}{1-\beta_1^t},
\qquad
\widehat v_t=\frac{v_t}{1-\beta_2^t}
~~~

更新为：

~~~math
\theta_{t+1}
=\theta_t-\eta_t
\frac{\widehat m_t}{\sqrt{\widehat v_t}+\epsilon}
~~~

一阶矩主要平滑方向，二阶矩提供逐参数尺度调整。它们都不是“知道哪个参数更重要”，而是根据历史梯度统计改变步长。

### Adam 与 AdamW 的关键差别

把 L2 正则直接加到 Adam 的梯度中，会得到：

~~~math
g'_t=g_t+\lambda\theta_t
~~~

然后 g'_t 还会进入一阶和二阶矩的自适应处理。这样参数衰减行为会与梯度历史耦合。

AdamW 把衰减从自适应梯度中分离。一个简化更新为：

~~~math
\theta_{t+1}
=\theta_t
-\eta_t\frac{\widehat m_t}
{\sqrt{\widehat v_t}+\epsilon}
-\eta_t\lambda\theta_t
~~~

因此 weight decay 的作用不再被每个参数的二阶矩重新缩放。AdamW 不是只改了名字，而是改变了正则化进入更新的方式。

实践中常把 bias、LayerNorm/RMSNorm 的缩放参数排除在 weight decay 之外。这是常见工程配置而非数学必然；embedding、路由器、LoRA 参数是否衰减，要根据架构和实验单独决定。

### Adafactor 的因子化状态

Adam 的二阶矩和参数矩阵同形状。对 W∈R^{r×c}，完整二阶矩需要 rc 个状态。Adafactor 对矩阵二阶统计做行列因子化近似，保存行统计 R∈R^r 和列统计 C∈R^c：

~~~math
R_i\approx\frac{1}{c}\sum_{j=1}^{c}V_{ij},
\qquad
C_j\approx\frac{1}{r}\sum_{i=1}^{r}V_{ij}
~~~

一种重构形式是：

~~~math
\widetilde V_{ij}
\approx\frac{R_iC_j}{\mathrm{mean}(R)}
~~~

状态量从 O(rc) 变成 O(r+c)，对巨大矩阵节省显存明显。代价是二阶矩是近似的，学习率、相对步长、裁剪和稳定性设置需要重新验证。Adafactor 的主要卖点是状态成本，而不是在所有任务上都胜过 AdamW。

### Lion 的符号更新

Lion 的核心思想是用动量方向的符号更新，而不是保存 Adam 的二阶矩。为了说明直觉，可以写出简化形式：

~~~math
c_t=\beta_1m_{t-1}+(1-\beta_1)g_t
~~~

~~~math
\theta_t=\theta_{t-1}
-\eta\,\mathrm{sign}(c_t)
-\eta\lambda\theta_{t-1}
~~~

动量状态再以另一个系数更新。实际实现的系数安排和更新顺序需要以论文或框架实现为准，不能把上式当作唯一代码。

符号更新的优点是状态比 Adam 少、规则简单；风险是有效步长的几何性质不同，对学习率和 weight decay 更敏感。它在某些视觉和语言实验中有吸引力，但是否适合一个具体的大规模预训练项目，必须用相同 token budget、数据和硬件做对照实验。

### 训练显存不只是参数显存

设模型有 N 个参数。若参数用 BF16 保存，每个参数约 2 字节；梯度、FP32 master weights 和优化器状态可能使用不同精度。一个粗略的 AdamW 账本可能包括：

| 项目 | 近似数量级 | 说明 |
| --- | ---: | --- |
| 参数 | 2N 字节 | 取决于保存精度 |
| 梯度 | 2N 或 4N | 取决于实现和累积精度 |
| 一阶矩 | 4N | 常用 FP32 状态 |
| 二阶矩 | 4N | 常用 FP32 状态 |
| master weights | 可能为 4N | 某些混合精度实现需要 |

这还没有包含 activation、临时通信 buffer、KV cache 和框架开销。因此优化器选择会直接影响分片、offload、checkpoint 和可训练模型规模。

### Batch、梯度累积与学习率

global tokens per step 可以近似写成：

~~~math
T_{\mathrm{global}}
=T_{\mathrm{micro}}
\times N_{\mathrm{data}}
\times N_{\mathrm{accum}}
~~~

其中 T_micro 已包含每个 micro-batch 的序列长度。改变数据并行数、梯度累积或序列长度，都会改变每一步优化器看到的统计。只把“batch size”写成一个样本数，在语言模型训练里往往不够。

增大 batch 有时需要增大学习率，但不存在脱离模型和优化器的无限线性缩放规则。应记录实际 token 数、更新次数、学习率 schedule 和梯度归一化方式。

### 训练中常见的优化器故障

如果 loss 不降或波动异常，可以检查：

1. 实际学习率是否与配置一致；
2. warmup 和衰减是否按 token 或 step 正确计算；
3. β₁、β₂、ε 是否和精度及梯度噪声匹配；
4. weight decay 参数分组是否正确；
5. clipping 是否过强或没有生效；
6. checkpoint 是否同时恢复 optimizer 和 scheduler state；
7. 参数更新比率是否过大或几乎为零；
8. Adafactor/Lion 的自定义实现是否和论文公式一致。

更新比率可以定义为：

~~~math
\rho_t=\frac{\lVert\Delta\theta_t\rVert_2}
{\lVert\theta_t\rVert_2+\epsilon}
~~~

它不能单独判断好坏，但能帮助定位某些层是否发生异常大的相对变化。

### 一个参数分组的示意

下面的代码只展示常见的分组逻辑。真实模型要根据参数名和模块类型逐项检查，不能把字符串规则直接当成所有架构的正确配置。

~~~python
def split_weight_decay(named_parameters):
    decay = []
    no_decay = []
    for name, parameter in named_parameters:
        if not getattr(parameter, "requires_grad", True):
            continue
        lowered = name.lower()
        if name.endswith("bias") or "norm" in lowered:
            no_decay.append(name)
        else:
            decay.append(name)
    return decay, no_decay


names = [
    "layers.0.attention.weight",
    "layers.0.attention.bias",
    "layers.0.input_norm.weight",
]
print(split_weight_decay([(name, object()) for name in names]))
~~~

这里的 object 只是为了演示名字分类，并没有创建优化器。生产代码还要传递真正的参数对象，检查每个参数恰好进入一个组，并记录 embedding、路由器和低秩适配器的处理方式。

### 初学者与专家的两层理解

初学者先掌握：Adam 用一阶和二阶历史统计调整步长，AdamW 把 weight decay 解耦，Adafactor 用因子化状态省显存，Lion 用符号动量减少状态。

专家不能只比较论文里的最终分数，还要比较状态显存、吞吐、稳定性、学习率敏感度、checkpoint 兼容性、分布式实现和在相同计算预算下的有效质量。

### 证据边界

SGD、Adam、AdamW、Adafactor 和 Lion 的公式来自公开论文及常见实现。具体默认超参数、状态精度和参数分组会随框架与模型改变。优化器的效果不能脱离数据、token budget、学习率 schedule 和硬件系统比较。

## 10. 把概率、优化和评估串成训练诊断系统

### 一条 loss 曲线不够描述一个模型

训练日志通常从 loss 开始，但模型质量至少有六个观察层：

1. 数据层：样本来源、重复、长度、语言和质量；
2. 概率层：训练/验证 NLL、困惑度和 token 分布；
3. 优化层：学习率、梯度、参数和更新比率；
4. 数值层：精度、NaN、Inf、溢出和设备差异；
5. 任务层：答案正确率、代码通过率、工具执行率；
6. 行为层：事实性、拒答、有用性、安全性和成本。

任何一层出现异常，都可能让其他层的平均指标失去解释力。比如 validation NLL 下降，但任务层因模板变化而退化；任务分数上升，但行为层出现过度拒答；loss 只是某个 rank 的局部值，实际同步已经错误。

### 训练前：先写清楚目标契约

一个可执行的训练任务应明确：

- 输入分布和输出格式；
- 训练目标与 loss mask；
- 任务成功的判定；
- 不能接受的失败；
- 评估切片；
- 资源约束和允许的延迟；
- 回滚和停止条件。

例如“提升客服模型质量”过于模糊。更好的定义是：在未参与训练的时间切分数据上，事实核验通过率提高，关键意图的任务成功率不下降，安全违规率低于某阈值，平均延迟增加不超过某范围。这样才有可能判断一个改动是否真的有效。

### 训练中：把可观测性做成证据链

至少保存以下信息：

| 类别 | 关键记录 |
| --- | --- |
| 数据 | shard、样本 ID、token 数、去重版本、异常样本 |
| 优化 | step、global tokens、学习率、梯度范数、更新比率 |
| 模型 | 参数范数、激活摘要、checkpoint 哈希、配置 |
| 数值 | 精度、loss scale、NaN/Inf、每个 rank 状态 |
| 评估 | 验证切片、解码配置、任务指标、失败样本 |
| 系统 | 吞吐、显存、通信、温度和硬件错误 |

日志的作用不是把所有数字都存下来，而是让一次异常可以被定位和复现。没有样本 ID 和 checkpoint 版本的曲线，通常只能用于事后猜测。

### 训练后：分层评估

可以把评估组织成四层：

第一层是概率拟合：验证 NLL、困惑度、不同领域的 token loss。

第二层是任务完成：exact match、代码测试、结构化解析、工具执行和引用定位。

第三层是行为可靠性：事实性、校准、拒答合理性、长上下文、对抗输入和多轮一致性。

第四层是产品约束：延迟、成本、吞吐、显存、失败恢复和用户反馈。

每层都要有训练未见的切片。平均分只适合作为摘要，不能替代切片和错误分析。

### 一个从症状到假设的诊断表

| 症状 | 优先假设 | 需要收集的证据 |
| --- | --- | --- |
| loss 从第一步就很高且不动 | label、mask、学习率或实现错误 | 单 batch 前向、目标 token、梯度 |
| loss 偶发 spike 后恢复 | 异常 batch 或瞬时数值问题 | 样本长度、grad norm、精度日志 |
| spike 后持续 NaN | 溢出、非法 mask、optimizer state | 首个 Inf 位置、rank、checkpoint |
| 验证 NLL 降但任务率降 | 目标错配或分布变化 | 任务切片、输出长度、错误类型 |
| 总体分数升但长尾降 | 数据配比或代理指标过拟合 | 长尾切片、重复率、人工复核 |
| 训练恢复后行为突变 | optimizer/scheduler state 不一致 | state step、学习率、参数差分 |
| 质量升但延迟显著变差 | 模型、序列或 kernel 成本增加 | FLOPs、激活显存、生成长度 |

这张表不是自动诊断器。它的价值是把“可能原因”转成可以验证或排除的实验。

### 用 ablation 保护因果解释

一次同时改变数据、模型结构、优化器和解码参数，得到的分数变化不能归因于任何单个因素。更可靠的最小实验是：

1. 固定数据、随机种子和计算预算；
2. 只改变一个主要因素；
3. 保留独立验证和关键失败切片；
4. 重复足够次数估计随机波动；
5. 检查收益是否在不同数据和长度上复现；
6. 记录性能、成本和副作用。

例如比较 GELU 与 SwiGLU，要尽量匹配参数量或 FLOPs；比较 AdamW 与 Adafactor，要记录 optimizer state 显存和相同 token budget；比较 RAG 前后，要固定生成协议并分别测检索和生成。

### 一份最小实验报告应该包含什么

一份可复核的报告至少包含：

- 问题和成功标准；
- 数据版本与切分；
- 模型结构和参数量；
- tokenizer、上下文长度和 loss mask；
- 优化器、学习率、batch tokens 和训练步数；
- 精度、并行和 checkpoint 方式；
- 自动指标、人评协议和统计波动；
- 关键失败案例及归因；
- 成本、延迟和已知局限。

报告不是越长越好，而是要让另一个人能够判断结论是否由实验支持。

### 练习与小项目

1. 选一个小型文本数据集，计算不同模型分布的熵、交叉熵和 KL，并验证交叉熵分解。
2. 用同一组数据比较不同 batch 和学习率下的优化轨迹，记录梯度范数与验证损失。
3. 构造原题、语义改写和同构新题，设计一个区分记忆与泛化的评估表。
4. 对一个分类或二元任务画可靠性图，计算 ECE 和 Brier score。
5. 为一个代码或工具调用任务同时设计 token loss、任务成功率和成本指标。
6. 对一个小型 FFN 计算普通结构与 SwiGLU 的参数量，并测量宽度调整前后的差异。
7. 比较两种优化器时，除了最终 loss，再记录状态显存、吞吐和恢复训练后的行为。
8. 写一份“loss spike 复盘报告”，从数据、模型、优化、数值、分布式和评估六条线排除假设。

### 本部分的主线

概率建模回答模型试图拟合什么；交叉熵和 KL 说明这个目标如何被计算；优化景观和优化器说明参数如何到达某个解；泛化和数据污染说明验证分数如何被解释；贝叶斯视角和校准说明模型是否知道自己不确定；目标错配说明训练信号为什么可能偏离真实需求；归一化、激活和数值控制说明训练怎样保持可用；最后的诊断系统把这些知识转成可复现的工程判断。

最重要的习惯不是背一句万能结论，而是始终追问：

1. 我正在优化哪个量？
2. 这个量代理了哪个真实目标？
3. 它遗漏了哪些失败？
4. 哪个实验可以区分不同原因？
5. 收益是否值得额外的成本和风险？
