# 第一部分：深度学习与概率基础进阶

学习大模型，不能只记住几个结构名词。更可靠的路径是把模型看成一个概率系统，再把概率目标连接到优化过程、泛化行为、训练稳定性和最终产品指标。

这一部分围绕十个相互衔接、又可以独立阅读的主题展开：

1. 语言模型究竟在估计什么概率。
2. 交叉熵、熵与 KL 散度为什么成为训练目标。
3. 非凸优化、过参数化和训练轨迹如何影响结果。
4. 泛化、双下降、记忆与数据污染如何区分。
5. 贝叶斯视角如何帮助我们理解不确定性和幻觉。
6. 为什么可优化的损失经常不能代表真实目标。
7. 初始化、归一化和数值控制如何让深层网络稳定训练。
8. 激活函数与门控 MLP 为什么会影响 Transformer 的表达效率。
9. AdamW、Adafactor 与 Lion 如何在质量和系统成本之间取舍。
10. 如何把这些概念组织成一套可复现的训练诊断方法。

本章按“目标是什么—怎样优化—怎样判断学会—怎样稳定实现—如何复盘”推进。第 1—2 节确定概率目标和损失，第 3—5 节讨论优化轨迹、泛化与不确定性，第 6 节把代理目标和真实任务分开，第 7—9 节回到网络数值和训练成本，第 10 节再把这些量接成诊断路径。每个概念的作用都要落回同一个问题：观测到的训练信号，能否支持我们对模型行为的判断？

## 1. 概率建模视角下的语言模型

### 从“预测下一个词”回到联合概率

初学者常把语言模型理解成一个自动补全器：给它一段文字，它猜下一个 token。这个描述没有错，却没有说明它为什么能够生成整段文本，也没有说明训练目标到底是什么。

更精确的说法是：语言模型为 token 序列分配概率。设分词后的序列为 x₁, x₂, …, x_T，模型参数为 θ，模型希望近似真实数据分布：

~~~math
P_\theta(x_1,x_2,\ldots,x_T)
~~~


概率论中的链式法则把联合概率分解为一串条件概率：

~~~math
P_\theta(x_{1:T})
=\prod_{t=1}^{T}P_\theta(x_t\mid x_{1:t-1})
~~~


其中 x₁:t−1 表示当前位置之前的全部 token。这个分解不是 Transformer 的经验假设，而是概率论恒等式。自回归语言模型的具体建模选择，是让每个条件概率只依赖已经出现的前缀。

这个区别很重要。模型不是直接给“整篇文章”一个不可解释的分数，而是把整篇文章的概率拆成许多次局部预测的乘积。生成时，每一步从条件分布中选择下一个 token，再把新 token 放回上下文，继续计算下一步分布。

### logits、softmax 与条件分布

Transformer 最后一层通常为每个位置产生一个词表维度的 logits 向量。设词表大小为 V，位置 t 的 logits 为 z_t∈R^V，条件概率由 softmax 给出：

~~~math
P_\theta(x_t=v\mid x_{1:t-1})
=\frac{\exp(z_{t,v})}
{\sum_{u=1}^{V}\exp(z_{t,u})}
~~~


z 的绝对值没有直接的概率含义，真正影响分布的是不同 token 之间的相对差异。为了避免指数运算溢出，实际实现会先减去最大 logit：

~~~math
\mathrm{softmax}(z)_i
=\frac{\exp(z_i-\max_j z_j)}
{\sum_k\exp(z_k-\max_j z_j)}
~~~


减去同一个常数不会改变 softmax 的结果，却能显著改善数值稳定性。

如果把词表中的 token 编号记为 v，那么模型的训练任务就是：在每个位置上，让真实 token x_t 的条件概率尽可能大。这个目标只需要原始文本，不需要人工给每个 token 写标签，因此称为自监督学习。监督信号来自序列本身的移位关系：输入看到 x₁ 到 x_{T−1}，标签是 x₂ 到 x_T。

### 因果掩码为什么必不可少

在训练阶段，整段序列通常一次性送入 Transformer。若不做限制，位置 t 的表示可以直接读取未来 token x_t+1、x_t+2，模型就能“偷看答案”。这会破坏自回归任务。

因果注意力使用一个上三角掩码，把未来位置的注意力 logit 设为负无穷。若原始注意力分数为 S，掩码为 M，则：

~~~math
\widetilde S_{t,s}=
\begin{cases}
S_{t,s},&s\le t\\
-\infty,&s>t
\end{cases}
~~~


softmax 后，未来位置的概率近似为零。这里的“未来”是序列位置上的未来，不是现实世界时间；如果任务需要双向理解，编码器模型可以采用不同的注意力约束，但它就不再是同一种自回归训练协议。

### Teacher forcing 与训练—生成差异

训练时，位置 t 的上下文通常使用真实前缀，即使模型在前一步本来预测错了，下一步仍然可以看到正确的 x_t。这种方式叫 teacher forcing。它让训练高效、梯度清晰，但产生一个结构性差异：

- 训练分布中的上下文大多来自真实数据；
- 生成分布中的上下文包含模型自己前面采样的 token；
- 一次早期错误可能把后续上下文带到训练分布之外。

这种训练/生成上下文差异常称 exposure bias；Scheduled Sampling 是研究这一差异的早期方案之一（[Bengio et al., 2015](https://arxiv.org/abs/1506.03099)）。但后续分析指出，它对应的训练目标不一致，不能视为通用修复（[Huszár, 2015](https://arxiv.org/abs/1511.05101)）。这不意味着 teacher forcing 本身错误，而是提醒我们：训练损失不能完全预测长序列生成的稳定性。多步训练、数据增强、解码控制、后训练和任务级评估都可能改变这种差异，但各自有额外成本或新的偏差。

### 为什么一个目标可以承载很多任务

问答、翻译、摘要、代码补全和结构化输出，看起来是不同任务，但都可以表示成条件生成：

~~~math
P_\theta(y\mid c)
=\prod_{t=1}^{|y|}
P_\theta(y_t\mid c,y_{1:t-1})
~~~


其中 c 是任务说明和输入，y 是目标输出。只要数据把任务描述、输入和正确输出组织在同一序列中，模型就可以用统一的 next-token 目标学习。

这解释了语言模型的通用性，也解释了它的局限：统一的概率形式不等于所有任务的评价标准相同。代码是否通过测试、数学最终答案是否正确、工具参数是否满足 schema，都可能是序列级或行为级条件，不能只靠局部 token 概率判断。

### 训练目标与生成策略不是一回事

训练最大化的是数据序列的似然，生成时却要从分布中选择一条序列。最简单的贪心解码在每一步选择当前概率最大的 token：

~~~math
\hat x_t=\arg\max_v P_\theta(v\mid x_{1:t-1})
~~~


贪心解码速度快，但局部最优不一定形成全局最好的文本。随机采样则按照条件分布抽取 token。温度 `τ>0` 会改变分布的尖锐程度：

~~~math
P_\tau(v\mid c)
=\frac{\exp(z_v/\tau)}
{\sum_u\exp(z_u/\tau)}
~~~


τ 小于 1 时分布更尖，输出更确定；τ 大于 1 时分布更平，输出更多样。top-k 只保留概率最高的 k 个 token，top-p 则保留累计概率达到 p 的最小候选集合。它们是生成策略，不是训练目标；改变解码参数不能证明模型本身学到了新知识。

### 困惑度能说明什么，不能说明什么

给定 N 个目标 token，平均负对数似然为：

~~~math
\mathcal L_{\mathrm{NLL}}
=-\frac{1}{N}\sum_{i=1}^{N}\log P_\theta(x_i\mid x_{<i})
~~~


若对数使用自然对数，困惑度为：

~~~math
\mathrm{PPL}
=\exp(\mathcal L_{\mathrm{NLL}})
~~~


困惑度可以粗略理解为模型在每个位置上面对的“等效候选数量”。它适合比较相同 tokenizer、相同数据切分和相同评估协议下的语言建模质量，但不能跨 tokenizer 直接比较，也不能单独代表事实性、推理、工具调用或安全行为。

一个常见错误是把低困惑度等同于“更懂”。如果验证集文本风格与线上用户输入差异很大，模型可以在验证集上更擅长预测，却在实际任务上变差。评估必须说明 tokenization、上下文长度、loss mask、数据来源和聚合方式。

### 一个不依赖深度学习框架的最小实验

下面的代码只演示 softmax、序列负对数似然和温度如何改变分布。它不是语言模型，只是把概率计算中的三个关键部件显式写出来。

~~~python
import math


def is_finite_number(value):
    return (
        isinstance(value, (int, float))
        and not isinstance(value, bool)
        and math.isfinite(value)
    )


def stable_softmax(logits, temperature=1.0):
    if not logits:
        raise ValueError("logits must not be empty")
    if not is_finite_number(temperature) or temperature <= 0:
        raise ValueError("temperature must be finite and positive")
    if any(not is_finite_number(value) for value in logits):
        raise ValueError("logits must be finite numbers")
    scaled = [value / temperature for value in logits]
    if any(not math.isfinite(value) for value in scaled):
        raise ValueError("scaled logits must remain finite")
    peak = max(scaled)
    weights = [math.exp(value - peak) for value in scaled]
    total = sum(weights)
    if not math.isfinite(total) or total <= 0:
        raise ValueError("softmax normalizer must be positive and finite")
    return [weight / total for weight in weights]


def sequence_nll(probabilities, target_indices):
    if not target_indices or len(probabilities) != len(target_indices):
        raise ValueError("probabilities and targets must be non-empty and aligned")
    total = 0.0
    for distribution, target in zip(probabilities, target_indices):
        if isinstance(target, bool) or not isinstance(target, int):
            raise TypeError("target indices must be integers")
        if not isinstance(distribution, (list, tuple)) or not distribution:
            raise ValueError("each probability distribution must be a non-empty sequence")
        if any(
            not is_finite_number(probability) or not 0 <= probability <= 1
            for probability in distribution
        ):
            raise ValueError("probabilities must be finite numbers in [0, 1]")
        if not math.isclose(sum(distribution), 1.0, rel_tol=1e-9, abs_tol=1e-9):
            raise ValueError("each probability distribution must sum to one")
        if not 0 <= target < len(distribution):
            raise IndexError("target index is outside the distribution")
        probability = distribution[target]
        if probability <= 0:
            raise ValueError("target probability must be positive")
        total -= math.log(probability)
    return total / len(target_indices)


logits = [2.0, 1.0, 0.0, -1.0]
for temperature in [0.5, 1.0, 2.0]:
    distribution = stable_softmax(logits, temperature)
    print(temperature, [round(value, 4) for value in distribution])

probabilities = [
    stable_softmax([2.0, 1.0, 0.0]),
    stable_softmax([0.2, 1.4, 0.1]),
]
print("mean NLL:", round(sequence_nll(probabilities, [0, 1]), 4))
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

输入 logits 为 `[2, 1, 0, -1]`，示例输出温度 `0.5/1.0/2.0` 下的四项概率分别为 `[0.865, 0.1171, 0.0158, 0.0021]`、`[0.6439, 0.2369, 0.0871, 0.0321]` 和 `[0.4551, 0.276, 0.1674, 0.1015]`；两步序列的平均 NLL 为 `0.4305`。温度只改变采样分布；要评价生成质量，还需要固定任务、采样次数和成功标准。示例显式拒绝空 logits、非法温度、非有限缩放 logits、未归一化分布、错位目标长度、越界标签和非正目标概率，避免用数值下限掩盖输入错误。

### 初学者与专家应分别追问什么

初学者首先要能回答三个问题：模型给谁分配概率？条件概率的条件是什么？为什么训练时不需要人工逐 token 标注？如果这三个问题不清楚，直接背 attention 公式很容易失去主线。

更深入时，要追问四件事：

1. 训练数据分布和部署分布是否一致。
2. teacher forcing 造成的上下文偏移有多大。
3. token-level likelihood 与目标任务的成功事件是否一致。
4. 生成策略改变的是抽样行为，还是模型参数本身。

这四个问题会把概率建模自然连接到后面的泛化、目标错配和评估。

### 证据边界

链式法则、softmax 和负对数似然是定义或直接推导。next-token prediction 能涌现多种能力，则是大规模经验现象，不能由链式法则单独推出。困惑度与下游能力通常相关，但相关性会受数据、tokenizer、任务格式和后训练影响。关于暴露偏差的讨论来自序列建模理论与经验研究，具体缓解方法必须用任务级实验验证。

## 2. 交叉熵、熵与 KL 散度：同一目标的三种读法

### 为什么训练语言模型要最小化负对数

对一个真实 token x，模型给出的概率越大，负对数 −log Pθ(x) 越小。把整个数据集的负对数相加，就是最大似然估计的相反数：

~~~math
\theta^\star
=\arg\max_\theta\sum_{i=1}^{N}
\log P_\theta(x^{(i)})
=\arg\min_\theta
-\sum_{i=1}^{N}\log P_\theta(x^{(i)})
~~~


自回归分解后，序列负对数似然变成逐 token 的和。因此交叉熵不是“因为大家都这么用”才出现，而是由概率建模和最大似然自然得到的训练目标。

### 熵是分布自身的不确定性

离散分布 P 的熵定义为：

~~~math
H(P)=-\sum_x P(x)\log P(x)
~~~


如果 P 把概率集中在一个结果上，熵低；如果 P 在许多结果之间均匀分配，熵高。熵描述的是分布本身，不依赖另一个预测分布。

语言中的歧义、开放式问题和多种合理续写，会让真实条件分布本身具有较高熵。模型无法仅靠更大容量把这种客观多解变成唯一答案。强行追求唯一输出，可能反而伤害创造性或诚实表达。

### 交叉熵比较两个分布

真实分布 P 与模型分布 Q 的交叉熵为：

~~~math
H(P,Q)=-\sum_x P(x)\log Q(x)
~~~


如果监督标签是 one-hot 分布，真实 token 的概率为 1，其余 token 为 0，交叉熵就退化成真实 token 的负对数概率。对于一个 batch，训练目标是经验分布与模型分布之间的平均交叉熵。

交叉熵可以分解为熵和 KL 散度：

~~~math
H(P,Q)=H(P)+D_{\mathrm{KL}}(P\Vert Q)
~~~


其中：

~~~math
D_{\mathrm{KL}}(P\Vert Q)
=\sum_xP(x)\log\frac{P(x)}{Q(x)}
~~~


当 P 固定时，H(P) 是常数，所以最小化交叉熵等价于最小化 D_KL(P∥Q)。这给出了一个清晰解释：模型训练是在让预测分布接近数据分布，但 KL 散度不是对称距离，方向不同会产生不同的偏好。

### 为什么 KL 散度不是普通距离

KL 散度满足非负性，但一般不满足对称性：

~~~math
D_{\mathrm{KL}}(P\Vert Q)\ne D_{\mathrm{KL}}(Q\Vert P)
~~~


如果 P 在某处有正概率而 Q 给出零概率，前一个方向会趋向无穷。这种方向性在训练中有实际含义：最大似然通常惩罚模型漏掉真实数据质量较大的区域，但对模型在真实数据未覆盖区域分配多少概率，约束方式不同。

在知识蒸馏、变分推断和偏好优化中，KL 的方向和参考分布非常重要。不能只说“加一个 KL 就能防止模型漂移”，还要说明是从哪个分布到哪个分布、按 token 还是按序列计算、在哪个数据分布上计算。

### 从 token loss 到序列概率

一条长序列的概率是许多 token 概率的乘积：

~~~math
P_\theta(x_{1:T})
=\prod_{t=1}^{T}P_\theta(x_t\mid x_{1:t-1})
~~~


长序列的乘积很快变小，因此实际训练和比较通常使用平均负对数似然。可是平均会掩盖局部灾难性错误。例如代码只有一个括号缺失，数学答案只差最后一位，token 平均损失的变化可能不大，而任务成功率会从 1 变成 0。

因此至少要把两类指标分开：

- 概率指标：平均 NLL、困惑度、token accuracy；
- 任务指标：exact match、单元测试通过率、结构化解析成功率、事实核验通过率。

前一类适合观察模型分布拟合，后一类才直接对应某个任务的成功定义。

### Label smoothing 改变了目标分布

one-hot 标签把全部目标概率放在一个 token 上。label smoothing 会把一部分质量分给其他 token。设词表大小为 V，平滑系数 `ε∈[0,1]`，则一个常见目标分布为：

~~~math
\widetilde P(v\mid x)
=(1-\varepsilon)\mathbf 1[v=x]
+\frac{\varepsilon}{V}
~~~


它可以降低模型过度自信；图像分类中关于 label smoothing 的实验结果见 [Szegedy et al., 2016](https://arxiv.org/abs/1512.00567)，但这不能推出它对所有语言模型任务都更好。平滑也改变了训练目标中的标签分布，并不自动适合所有场景。若任务需要精确复制、严格代码或结构化 token，平滑可能让错误 token 获得不希望的梯度。

### 软标签与知识蒸馏

知识蒸馏让学生模型拟合教师模型的软分布；软目标蒸馏的代表性入口见 [Hinton et al., 2015](https://arxiv.org/abs/1503.02531)。若教师 logits 为 `z_teacher`，学生 logits 为 `z_student`，温度 τ 下的蒸馏损失可以写成：

~~~math
\mathcal L_{\mathrm{KD}}
=-\sum_v
P_{\mathrm{teacher},\tau}(v\mid c)
\log P_{\mathrm{student},\tau}(v\mid c)
~~~


较高温度会暴露类别之间的相对偏好，而不只是 one-hot 的正确类别。蒸馏的收益依赖教师质量、数据分布、温度和损失权重；教师的错误也可能被学生继承。

### 用数值例子检查三种量的关系

下面用两个三分类分布计算熵、交叉熵与 KL。代码使用自然对数，因此单位是 nat；如果改用以 2 为底的对数，单位则是 bit。

~~~python
import math


def validate_distribution(probabilities, name):
    if not isinstance(probabilities, (list, tuple)) or not probabilities:
        raise ValueError(f"{name} must be a non-empty sequence")
    if any(
        not isinstance(probability, (int, float))
        or isinstance(probability, bool)
        or not math.isfinite(probability)
        or probability < 0
        for probability in probabilities
    ):
        raise ValueError(f"{name} must contain finite non-negative numbers")
    if not math.isclose(sum(probabilities), 1.0, rel_tol=1e-9, abs_tol=1e-9):
        raise ValueError(f"{name} must sum to one")


def entropy(probabilities):
    validate_distribution(probabilities, "probabilities")
    return -sum(
        probability * math.log(probability)
        for probability in probabilities
        if probability > 0
    )


def cross_entropy(reference, prediction):
    validate_distribution(reference, "reference")
    validate_distribution(prediction, "prediction")
    if len(reference) != len(prediction):
        raise ValueError("reference and prediction must have the same length")
    total = 0.0
    for probability, predicted in zip(reference, prediction):
        if probability > 0 and predicted <= 0:
            raise ValueError("prediction assigns zero probability to an observed event")
        if probability > 0:
            total -= probability * math.log(predicted)
    return total


def kl_divergence(reference, prediction):
    validate_distribution(reference, "reference")
    validate_distribution(prediction, "prediction")
    if len(reference) != len(prediction):
        raise ValueError("reference and prediction must have the same length")
    total = 0.0
    for probability, predicted in zip(reference, prediction):
        if probability == 0:
            continue
        if predicted <= 0:
            raise ValueError("KL divergence is undefined when Q is zero where P is positive")
        total += probability * (math.log(probability) - math.log(predicted))
    return total


reference = [0.7, 0.2, 0.1]
prediction = [0.5, 0.3, 0.2]
print("H(P) =", round(entropy(reference), 6))
print("H(P, Q) =", round(cross_entropy(reference, prediction), 6))
print("KL(P || Q) =", round(kl_divergence(reference, prediction), 6))
print(
    "H(P) + KL(P || Q) =",
    round(entropy(reference) + kl_divergence(reference, prediction), 6),
)
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

预期 `H(P)=0.801819`、`H(P,Q)=0.886941`、`D_KL(P∥Q)=0.085123`，最后一行仍为 `0.886941`。这不是实验巧合，而是交叉熵分解式的数值体现。

这些函数把空分布、负概率、未归一化输入、长度不匹配和 `P>0,Q=0` 明确视为数据错误。实际训练代码可能使用稳定 kernel 处理极小概率，但不能用一个任意的 `max` 下限把非法分布静默改成合法分布。

### 初学者与专家的两层理解

初学者可以先把三者记成一句完整的话：熵描述真实分布有多不确定，交叉熵描述用 Q 预测 P 要付出多少代价，KL 散度描述 Q 相对 P 多付出的代价。

专家还需要注意：

1. KL 的方向会影响优化行为。
2. token 级的交叉熵不等于序列级成功率。
3. label smoothing、蒸馏和 KL 约束都会改变目标分布。
4. 训练集上的交叉熵下降，可能只是模型更好地拟合了当前数据，而不是所有任务都变好。

### 用同一个 top-1 预测看交叉熵的区别

假设一个二分类任务的真实频率是 `P=(0.6, 0.4)`。模型 A 给出 `Q_A=(0.9, 0.1)`，模型 B 给出 `Q_B=(0.65, 0.35)`。两者的 top-1 都是第一类，因此按单个确定标签的准确率观察时，它们可能看起来相同；但如果这组频率近似真实条件分布，平均交叉熵会不同：

~~~math
H(P,Q_A)=-0.6\ln 0.9-0.4\ln 0.1\approx 0.984
~~~


~~~math
H(P,Q_B)=-0.6\ln 0.65-0.4\ln 0.35\approx 0.679
~~~


模型 B 保留了第二类并非不可能的概率，因此对真实分布付出的平均编码代价更低。这个例子说明交叉熵评价的是整张概率分布，而 top-1 只看最大项；如果训练集标签是一次抽样而不是已知频率，单个样本的损失不能直接用 `P=(0.6,0.4)` 代替，必须区分经验标签和真实条件分布。

同一原则也解释了 label smoothing 为什么会改变损失数值。取词表大小 `V=5`、平滑量 `ε=0.1`，目标 token 的概率是 `1−0.1+0.1/5=0.92`，其他四个 token 各为 `0.02`。若模型输出目标概率 `0.8`，硬标签交叉熵只计算 `−ln 0.8≈0.223`；平滑后还要计入其余 token 的负对数项，例如一个分布为 `[0.8,0.08,0.06,0.04,0.02]` 时，loss 约为 `0.92×0.223+0.02×(2.526+2.813+3.219+3.912)=0.455`。目标分布要求模型保留其他 token 的概率质量，不能把 smoothing 当成只影响显示的置信度后处理。

再把 token loss 接回整条序列。若一个三 token 目标的条件概率依次是 `0.5、0.25、0.8`，序列概率为 `0.5×0.25×0.8=0.1`，序列负对数似然是 `−ln 0.1≈2.303`；按 token 平均则为 `2.303/3≈0.768` nat/token，对应困惑度 `exp(0.768)≈2.15`。按序列相加和按 token 平均回答的是不同问题：前者会随长度自然增长，后者便于比较平均预测代价，但两者都不会自动表达代码是否通过、答案是否有证据等任务目标。

困惑度是平均负对数似然的指数变换，方便把“平均编码代价”映射到有效分支数的直觉；它不是答案可靠率。不同 tokenizer 会把同一字符串切成不同数量、不同难度的 token，因此跨 tokenizer 比较 perplexity 时，分母和 token 单位并不完全相同。若要比较语言覆盖或字节效率，应同时报告 tokenizer、有效字符/字节量和评估文本边界，而不是只看一个 PPL 数字。

### 证据边界

熵、交叉熵与 KL 的关系是信息论定义和代数推导。交叉熵作为语言模型训练目标的合理性来自最大似然。label smoothing、蒸馏和 KL 约束的收益具有任务和实现依赖，不能把某个论文设置当作普遍最优配置。

## 3. 优化景观、过参数化与训练轨迹

### 我们究竟在优化什么

把模型写成 f_θ，把训练数据写成 D，训练过程通常是在求：

~~~math
\theta^\star=\arg\min_\theta\mathcal L_D(\theta)
~~~


参数 θ 可能有数百万、数十亿甚至更多维度。损失函数由多层线性变换、非线性、注意力、归一化和数据平均共同构成，因此通常是高度非凸的。

“非凸”只说明损失面不是一个简单的碗，不等于训练一定失败。真正决定训练轨迹的还有初始化、梯度估计噪声、学习率、参数化、归一化、残差路径和优化器。

### 局部极小值、鞍点与平坦区域

在一维直觉中，局部极小值附近所有方向都向上；在高维空间中，鞍点可能在某些方向向上、另一些方向向下。用 Hessian 矩阵 H 表示局部曲率时：

~~~math
H(\theta)=\nabla_\theta^2\mathcal L(\theta)
~~~


若 H 的特征值全部为正，局部二阶近似是极小点；若存在正有负的特征值，更像鞍点；若许多特征值接近零，局部区域可能很平坦。

这些术语帮助我们描述训练几何，但不能直接变成“平坦一定好”的结论。重参数化会改变参数空间中的曲率尺度，而不一定改变函数；相关反例见 [Dinh et al., 2017](https://arxiv.org/abs/1703.04933)。平坦度依赖参数化和坐标尺度。对某些参数做重缩放，函数输出可能几乎不变，Hessian 的数值却会变化。因此比较模型时，应把曲率指标与扰动鲁棒性、验证性能和任务指标结合，而不是只看一个 Hessian 数字。

### 过参数化改变了问题形状

当参数数量远大于数据约束数量时，模型可能存在许多训练误差接近零的解。这叫过参数化。它带来两个看似矛盾的事实：

- 模型容量足够大，可以记住训练集甚至噪声；
- 在合适数据和优化路径下，模型仍可能在未见数据上表现良好。

这说明“能拟合训练集”和“会泛化”不是互斥命题。最终选择哪个解，取决于初始化、优化器、数据顺序、正则化和架构带来的隐式偏置。

对于线性模型，最小范数解常能被明确分析；对于深度网络，优化器和网络参数化共同产生的隐式偏置更复杂。不能只根据参数量推出模型会记忆还是泛化。

### 梯度下降是带有偏好的搜索过程

最简单的更新为：

~~~math
\theta_{t+1}=\theta_t-\eta_t\nabla\mathcal L(\theta_t)
~~~


即使存在许多训练损失相同的解，不同的学习率、batch 顺序或优化器也可能走向不同解。小 batch 的梯度噪声会让轨迹偏离确定性最速下降；学习率衰减会改变后期在损失面上的移动尺度；weight decay 会持续改变参数范数。

所以训练配置不是“找到同一个最优解的不同速度”，而可能是在选择不同的函数。更换优化器后，即使训练 loss 看起来相近，校准、长尾能力和下游任务也可能不同。

### Batch size 与梯度噪声

设单样本梯度为 g_i，batch B 的平均梯度为：

~~~math
\widehat g_B=\frac{1}{|B|}\sum_{i\in B}g_i
~~~


在样本近似独立且分布稳定时，batch 越大，估计方差通常越低。但这不是无限成立的工程定律：样本相关性、重复数据、梯度累积方式和并行同步都会改变有效噪声。

大 batch 通常带来更高硬件利用率和更稳定的更新，却可能减少单位 token 的参数更新次数，且需要重新调学习率和 warmup。比较两个训练实验时，必须记录 global batch tokens，而不能只写“batch size=32”。

### 学习率决定探索尺度

学习率过大时，更新可能跨过损失较低区域，表现为 loss spike、梯度爆炸或 NaN；过小时，训练会变慢甚至停留在欠训练状态。学习率还和 batch、模型尺度、预热步数、优化器二阶矩以及精度有关。

一个实用的训练诊断不是只画 loss，而是同时观察：

1. 学习率曲线。
2. 梯度范数和参数范数。
3. 更新量与参数量之比。
4. 每 token 吞吐。
5. 训练集和多个验证切片的 loss。
6. NaN/Inf 位置与触发 batch。

### 为什么“平坦解更好”需要谨慎

平坦解的常见直觉是：参数受到小扰动时损失变化较小，因此可能更鲁棒。但这个直觉依赖如何定义扰动。若对不同层使用不同参数尺度，未经归一化的参数空间平坦度无法公平比较。

更可靠的实践是做函数层面的扰动测试，例如：

- 对输入做轻微改写或噪声；
- 对权重施加相对比例的扰动；
- 在未见领域和长尾切片上测试；
- 比较校准、错误类型和任务成功率。

这样才是在问“模型行为是否稳定”，而不是只问某个坐标系中的曲率是否小。

### 一个二维优化轨迹实验

下面的例子用一个带窄谷的二维函数展示学习率对轨迹的影响。它不是神经网络损失，只用于形成几何直觉。

~~~python
import math


def is_finite_number(value):
    if not isinstance(value, (int, float)) or isinstance(value, bool):
        return False
    try:
        return math.isfinite(value)
    except OverflowError:
        return False


def gradient(point):
    if (
        not isinstance(point, (list, tuple))
        or len(point) != 2
        or any(not is_finite_number(value) for value in point)
    ):
        raise ValueError("point must contain two finite coordinates")
    x, y = point
    # 一个在 x 方向较平、y 方向较陡的二次函数
    result = (2.0 * x, 20.0 * y)
    if any(not is_finite_number(value) for value in result):
        raise OverflowError("gradient must remain finite")
    return result


def optimize(start, learning_rate, steps):
    if (
        not isinstance(start, (list, tuple))
        or len(start) != 2
        or any(not is_finite_number(value) for value in start)
    ):
        raise ValueError("start must contain two finite coordinates")
    if not is_finite_number(learning_rate) or learning_rate <= 0:
        raise ValueError("learning_rate must be finite and positive")
    if isinstance(steps, bool) or not isinstance(steps, int) or steps < 0:
        raise ValueError("steps must be a non-negative integer")
    point = list(start)
    history = [tuple(point)]
    for _ in range(steps):
        dx, dy = gradient(point)
        updated = (point[0] - learning_rate * dx, point[1] - learning_rate * dy)
        if any(not is_finite_number(value) for value in updated):
            raise OverflowError("optimization step produced a non-finite coordinate")
        point = list(updated)
        history.append(tuple(point))
    return history


for learning_rate in [0.02, 0.08, 0.12]:
    path = optimize((4.0, 1.0), learning_rate, 8)
    print("lr =", learning_rate, "last =", tuple(round(v, 4) for v in path[-1]))
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

三条轨迹的最终点分别约为 `(2.8856, 0.0168)`、`(0.9915, 0.0168)` 和 `(0.4452, 14.7579)`。学习率 `0.12` 对 y 方向过大，更新反复换向并把幅值放大。真实网络的损失面高维、随训练变化，不能仅凭这个玩具函数选超参数；实验只展示条件数和步长之间的关系。输入坐标和学习率必须是有限数；若一次更新产生非有限坐标，示例会显式报错。

### 从梯度算出稳定步长范围

这个二维例子等价于 `L(x,y)=x²+10y²`，梯度是 `(2x,20y)`，曲率最大的方向在 y 轴。只看这个方向，梯度下降一步为 `y_{t+1}=y_t-η(20y_t)=(1-20η)y_t`。要让误差幅度持续缩小，需要 `|1-20η|<1`，也就是 `0<η<0.1`。当 `η=0.08` 时，每一步把 y 乘以 `-0.6`；从 `y_0=1` 出发，三步后 `y_3=-0.216`，符号来回变但幅值下降。当 `η=0.12` 时乘数是 `-1.4`，三步后 `y_3=-2.744`，误差会放大。

因此“学习率太大”不是一句抽象警告，而是更新系数跨过稳定区间。真实神经网络的局部曲率随参数和 batch 改变，不能把 `0.1` 当作模型超参；它只说明为什么同一学习率能在平缓方向前进、同时在陡峭方向震荡。调参时可以同时观察 loss、梯度范数和更新量，而不是只试一个全局常数。

### 从 loss 曲线读出不同故障

几种常见曲线需要区别：

- 训练和验证都不降：可能是学习率、数据、mask、初始化或实现错误；
- 训练降、验证升：可能是过拟合、分布差异或验证协议错误；
- 两者都降但任务指标不升：目标错配或指标与任务不一致；
- 偶发 spike 后恢复：可能是异常 batch 或数值瞬态；
- spike 后持续 NaN：应立即定位数值、梯度、mask 和 optimizer state。

曲线只能告诉你“发生了什么”，不能单独告诉你“为什么”。原因需要结合可观测量和可复现的最小样本。

### 初学者与专家的两层理解

初学者先理解：非凸不等于不能训练；过参数化不等于必然过拟合；优化器不仅影响速度，也可能影响最后得到的函数。

深入分析时还要问：

1. 讨论的复杂度是参数数量、有效秩、训练时间还是数据噪声？
2. 所谓平坦度是否对参数重参数化不变？
3. 比较训练方案时是否固定 token budget、数据顺序和评估切片？
4. 观察到的泛化改善来自优化器、正则化，还是更好的数据和更长训练？

这些问题可以避免把相关性误写成因果关系。

### 证据边界

非凸、鞍点、过参数化和隐式偏置的数学定义相对明确，但“现代深度网络主要不是卡在坏局部极小值”是结合理论与实验形成的经验判断。双下降、平坦性与泛化之间的关系依赖模型族和评估设置，不能用一句“参数越大越好”或“平坦一定泛化好”概括。

## 4. 泛化、双下降、记忆与数据污染

### 泛化到底在问什么

训练集上的低损失只说明模型能解释已经见过的数据。我们真正关心的是：从同一任务分布中重新抽取一个未见样本，模型是否仍然可靠。

设数据来自分布 𝒟，单样本损失为 ℓ，模型的经验风险和真实风险分别是：

~~~math
\widehat R_D(f)
=\frac{1}{n}\sum_{i=1}^{n}\ell(f(x_i),y_i)
~~~


~~~math
R_{\mathcal D}(f)
=\mathbb E_{(x,y)\sim\mathcal D}
[\ell(f(x),y)]
~~~


训练是在降低经验风险，泛化讨论的是经验风险与真实风险之间的差距。真实风险不可直接完全计算，所以我们用独立验证集或测试集估计它。

在语言模型中，训练样本通常是 token 序列，损失多为下一个 token 的负对数似然；但产品真正关心的可能是答案正确率、代码通过率、引用可核验率或安全行为。于是这里至少存在两层泛化：

1. 从训练 token 到未见 token 的概率泛化；
2. 从离线样本到真实任务行为的任务泛化。

前一层好，并不自动推出后一层好。

### 训练集、验证集与测试集的职责

训练集用于更新参数，验证集用于选择超参数和 checkpoint，测试集用于最后一次估计。若反复根据测试集结果改模型，测试集就已经参与开发，不再是无偏的最终估计。

大模型评估还需要更细的切分：

- 按时间切分，检验对新近数据的泛化；
- 按用户或文档切分，避免同一来源泄漏到两边；
- 按领域切分，观察跨领域变化；
- 按长度切分，观察长上下文外推；
- 按风险和难度切片，避免平均分掩盖关键失败。

随机打散后切分在独立同分布的简单任务中可能足够，但对网页、代码仓库、对话和长文档数据往往会把高度相似的内容分到训练和评估两边，从而高估泛化。

### 分布偏移的三个层次

训练分布 P_train 和部署分布 P_deploy 不一致时，问题不一定只是“模型不够大”。可以区分：

1. 协变量偏移：输入分布变了，但理想条件关系近似不变；
2. 标签或输出偏移：目标类别或答案频率变了；
3. 概念偏移：输入与目标之间的关系本身变了。

语言模型中的例子包括：训练语料以英文为主、部署输入变成中文法律文本；训练样本多为短问答、部署要求处理几十万 token 的长文档；训练时工具 schema 固定、部署时 API 字段发生变化。不同偏移需要不同数据和评估策略，不能统称为“过拟合”。

### Bias–variance 直觉不是完整答案

以固定输入 `x` 的回归为例，假设 `y=f^*(x)+ε`、`E[ε|x]=0`，且噪声与训练集抽样独立。令 `\hat f_D` 表示由训练集 `D` 得到的估计器，则不同训练集造成的方差、估计偏差和不可约噪声满足经典平方损失分解：

~~~math
\mathbb E_{D,\epsilon}[(\hat f_D(x)-y)^2]
=\left(\mathbb E_D[\hat f_D(x)]-f^*(x)\right)^2
+\mathrm{Var}_D[\hat f_D(x)]
+\mathrm{Var}(\epsilon\mid x)
~~~


经典直觉是：模型复杂度增加时，偏差下降、方差上升，测试误差呈 U 形。但深度网络进入能插值训练集的区域后，经验曲线可能再次下降，因此只用“参数多所以更容易过拟合”解释现代模型是不够的。

### 双下降与插值阈值

双下降描述一类实验中观察到的形状；其模型规模、训练轮数和数据规模变体见 [Belkin et al., 2019](https://arxiv.org/abs/1812.11118) 与 [Nakkiran et al., 2021](https://arxiv.org/abs/1912.02292)：随着某种有效复杂度增加，测试误差先下降，在刚好能够拟合训练数据的插值阈值附近上升，进入更强过参数化区域后又下降。

这里的复杂度可以是：

- 模型宽度或参数量；
- 训练步数；
- 数据量；
- 正则化强度；
- 更抽象的有效模型复杂度。

因此“双下降”不是一个只关于参数量的定理。它是对一类实验曲线的概括，峰值位置和是否出现，取决于数据噪声、模型族、优化方法和评估协议。

在插值阈值附近，模型刚好拥有拟合训练噪声的能力，训练解可能对数据扰动很敏感。继续增大模型后，优化器可能找到具有不同隐式偏置的解，测试误差重新下降。但这不意味着无限扩大模型就一定更好，因为数据质量、计算预算、分布变化和部署成本仍然是约束。

### 记忆和泛化并不是二选一

模型记忆训练样本中的字符串，不等于它完全没有学到结构；模型能解决新组合，也不等于它没有记忆。两种现象可以同时出现。

更容易被记忆的内容通常具有以下特征：

- 在训练语料中重复出现；
- 格式固定、局部模式强；
- 训练轮数多或被过采样；
- 具有高辨识度的罕见字符串；
- 代码、日志、配置和个人信息等可逐字复现内容。

更接近泛化的证据则包括：对训练中未出现的组合、同构问题、语义改写和轻微输入扰动仍保持稳定；在时间切分或私有动态测试集上仍有效；能力不依赖复现某个固定答案。

这些只是证据，不是绝对判定。泛化测试本身也可能和训练数据高度相似，所以必须记录数据来源和相似度检测方法。

### 数据污染会怎样扭曲评估

如果 benchmark 原题、解答或高度相似的改写出现在训练数据中，模型在该 benchmark 上的高分就不能直接解释为未见任务泛化。污染可能来自：

1. benchmark 发布后被大量网页转载；
2. 训练语料包含公开答案或讨论；
3. 训练数据和测试数据来自同一文档或代码仓库；
4. 评估题型模板被重复生成；
5. 数据清洗只做了完全相同字符串去重，没有处理近似重复。

检测可以从 exact match、n-gram 重叠、文档指纹、embedding 相似度和时间元数据入手。每种检测都有漏报和误报：语义相似不一定是污染，完全不同的表达也可能泄露同一答案。因此最强的做法通常是使用训练时间之后收集的私有数据、动态生成但可审计的任务，或者对样本来源做严格隔离。

### Scaling law 应该怎样读

语言模型研究发现，在特定数据和训练范围内，验证交叉熵可随参数量 `N`、训练 token 数 `D` 近似按幂律变化。下面是分离项的示意形式，不是 Kaplan et al. 论文中唯一或通用的拟合公式：

~~~math
L(N,D)
\approx L_\infty
+A N^{-\alpha}
+B D^{-\beta}
~~~


其中 `L` 是验证交叉熵，`N` 是参数量，`D` 是训练 token 数；`L_∞`、`A`、`B`、`α` 和 `β` 是由具体实验拟合的常数，幂律下降项中的指数取正值。该类经验关系见 [Kaplan et al., 2020](https://arxiv.org/abs/2001.08361)，不适用于所有架构、数据和任务。训练计算量 `C` 会限制可行的 `(N,D)` 组合；在固定架构和序列设定下可粗略理解为随 `N×D` 增长，因此不应把 `N`、`D`、`C` 当作三个彼此独立的幂律变量再相加。

compute-optimal 训练的核心不是“永远多加参数”，而是在固定计算预算下平衡参数量和训练 token 数。[Hoffmann et al., 2022](https://arxiv.org/abs/2203.15556) 在其训练设置中研究了这一平衡；具体最优比例会受 tokenizer、数据质量、序列长度、硬件利用率和训练目标影响。

### 如何设计更可信的泛化实验

一个可复现的泛化实验至少要写清楚：

1. 训练数据与评估数据的来源和时间；
2. 去重和污染检测规则；
3. 模型 checkpoint、解码参数和上下文模板；
4. 任务级成功标准；
5. 各领域、长度、难度和风险切片；
6. 置信区间或多次运行的波动；
7. 失败案例，而不仅是总体平均分。

如果要区分记忆与泛化，可以构造成对实验：原始题、语义改写、结构同构题和新组合题分别测试，并检查训练数据中是否存在相似源文档。若只报告原题 exact match，结论很弱。

### 初学者与专家的两层理解

初学者先掌握一个判断顺序：训练集表现回答“有没有学会拟合”，验证集回答“在相近未见数据上是否有效”，分布外切片回答“换环境后是否仍然稳健”。三者不能互相替代。

专家需要把“泛化”拆成可测量的对象：概率泛化、任务泛化、组合泛化、时间泛化、行为泛化和安全泛化。每个对象都可能有不同结果。一个模型可以在 held-out NLL 上更好，却在工具参数、事实引用或安全边界上退化。

### 证据边界

经验风险与真实风险的区分来自统计学习理论。双下降和 scaling law 主要来自论文与大规模实验，形状和指数不是普适常数。数据污染检测能提高评估可信度，但没有一种相似度阈值可以证明“绝对未污染”。记忆与泛化的区分需要成对数据、时间信息和多种测试共同支持。

## 5. 贝叶斯视角、不确定性与幻觉

### 从点估计走向分布估计

普通深度学习训练通常返回一组参数 θ。给定数据 D，我们得到一个点估计：

~~~math
\theta^\star=\arg\min_\theta\mathcal L(D,\theta)
~~~


贝叶斯视角会把参数当作随机变量，询问看到数据后不同参数的可信程度。贝叶斯公式为：

~~~math
P(\theta\mid D)
=\frac{P(D\mid\theta)P(\theta)}{P(D)}
~~~


其中 P(θ) 是先验，P(D∣θ) 是似然，P(θ∣D) 是后验，P(D) 是证据项。常用的简写是“后验与似然乘先验成正比”，但不要把先验理解成主观猜测的同义词；架构、数据、正则化和优化器同样可以提供归纳偏置。

### MLE 与 MAP

最大似然估计只最大化似然：

~~~math
\theta_{\mathrm{MLE}}
=\arg\max_\theta \log P(D\mid\theta)
~~~


最大后验估计同时考虑先验：

~~~math
\theta_{\mathrm{MAP}}
=\arg\max_\theta
[\log P(D\mid\theta)+\log P(\theta)]
~~~


若参数先验是精度为 `λ` 的零均值各向同性高斯分布，且 `L_NLL` 采用未按样本数平均的负对数似然：

~~~math
P(\theta)\propto
\exp\left(-\frac{\lambda}{2}\|\theta\|_2^2\right)
~~~


则负对数后验中会出现 L2 惩罚项：

~~~math
\mathcal L_{\mathrm{MAP}}
=\mathcal L_{\mathrm{NLL}}
+\frac{\lambda}{2}\|\theta\|_2^2
~~~


这解释了“L2 正则可以看成高斯先验”的说法。它是一个有用的等价关系，但不能因此声称所有正则化都等于完整贝叶斯推断。完整贝叶斯需要对参数后验积分，而普通训练通常只保留一个参数点。

### 预测不确定性不是参数不确定性

完整贝叶斯预测要对参数后验求平均：

~~~math
P(y\mid x,D)
=\int P(y\mid x,\theta)P(\theta\mid D)\,d\theta
~~~


真实大模型通常不会显式计算这个高维积分。它在固定参数 θ 下输出 token 分布：

~~~math
P_\theta(x_t\mid x_{1:t-1})
~~~


这个 softmax 反映的是当前参数和上下文下的相对偏好，不等于“这个完整答案为真的概率”。尤其是事实问题中，流畅语言和事实证据是两件不同的事。

### Aleatoric 与 epistemic

不确定性至少可以从两个来源理解。

Aleatoric uncertainty 来自数据或任务本身的不可约歧义，例如用户问题含糊、未来事件不可预测、同一个开放问题有多个合理答案。更多训练数据不一定消除它。

Epistemic uncertainty 来自模型知识或覆盖不足，例如新领域、新工具 schema、知识截止时间之后的事件和分布外输入；这一区分可参照 [Kendall and Gal, 2017](https://arxiv.org/abs/1703.04977)，其论文实验范围是计算机视觉任务。更多高质量数据、检索、工具或更好的模型有机会降低它。

这两个概念不是把模型输出直接贴两个标签就完成了。现实中的一个错误可能同时包含数据歧义和模型无知，所以评估时要构造可区分的样本和外部证据。

### 校准：置信度是否可被解释

若模型对一组样本都声称有 80% 置信度，长期来看约 80% 正确，则称它在这个范围内校准良好。对分类任务，可以把预测置信度分成 M 个桶；[Guo et al., 2017](https://arxiv.org/abs/1706.04599) 讨论了现代神经网络校准，并使用了常见的 ECE 估计：

~~~math
\mathrm{ECE}
=\sum_{m=1}^{M}
\frac{|B_m|}{n}
\left|\mathrm{acc}(B_m)
-\mathrm{conf}(B_m)\right|
~~~


其中 B_m 是第 m 个置信度桶，acc 是桶内正确率，conf 是桶内平均置信度，n 是样本总数。

对开放式语言模型，困难在于“一个回答的置信度”没有天然唯一的定义。可以使用答案级概率、多个采样的一致性、事实核验结果或任务特定的 verifier，但每一种定义都测量不同东西。把最后一个 token 的最大 softmax 当作整段事实答案的置信度，通常没有充分依据。

另一个有用的指标是 Brier score。若结果 y∈{0,1}，预测概率 p 为：

~~~math
\mathrm{Brier}
=\frac{1}{n}\sum_{i=1}^{n}(p_i-y_i)^2
~~~


它同时惩罚错误和过度自信。不同指标可能给出不同排序，因此应根据风险场景选择。

### 选择性预测与合理拒答

在高风险任务中，系统不一定要求模型对所有输入都回答。设模型只对置信度超过阈值的样本回答，其余样本转人工、检索或请求澄清。此时要同时报告：

- coverage：实际回答的样本比例；
- selective risk：被回答样本中的错误率；
- abstention rate：主动退出的比例。

提高阈值通常能降低选择性风险，却会降低覆盖率。可靠性不是让模型永不拒答，而是在风险、覆盖和用户成本之间找到可解释的点。

### 幻觉为什么会发生

“幻觉”不是一个单一机制。常见因素包括：

1. 训练语料含有错误、冲突或过时信息；
2. 当前输入缺少足够证据；
3. 模型将语言流畅性误当成事实支持；
4. 采样过程选择了一个低概率但连贯的路径；
5. 后训练鼓励完整、迅速和有帮助的回答；
6. 外部检索结果本身不相关、过时或互相冲突；
7. 生成阶段没有把证据与每个结论对齐。

因此“让模型更自信”通常不是解决方案。可靠系统应允许模型表达不确定、请求澄清、引用可核验证据、调用工具或拒绝做无依据的断言。

决定系统如何奖励这些行为的，不只有训练目标，还有评价规则。Kalai 等人在 2026 年的 Nature 论文分析了 next-token 训练和准确率型评测如何在某些设定下奖励不加区分的猜测，并提出把错误惩罚或 abstain 规则写进 open rubric。它说明评估指标会进入研发反馈环；但不表示每次幻觉都由排行榜造成，也不意味着开放评分规则能覆盖真实用户的全部效用。这里引用它，是为了把目标设计与不确定性连起来，具体结论仍限于论文任务和协议。[论文](https://www.nature.com/articles/s41586-026-10549-w)

### RAG 不能自动消除不确定性

检索增强生成把外部文档放入上下文，改变了模型的条件分布（[Lewis et al., 2020](https://arxiv.org/abs/2005.11401)）；它不保证三件事：

- 检索到的文档真的相关；
- 文档中的结论真的正确；
- 生成内容忠实地使用了文档。

一个完整的事实性评估应分别检查检索召回、证据覆盖、结论蕴含和引用定位。只报告“接入 RAG 后答案更长”或“引用数量更多”，不能证明幻觉下降。

### 用 Beta–Binomial 观察后验变化

下面的例子用 Beta(α,β) 作为二项概率的先验。观察到正例和反例后，后验参数分别加上计数：

~~~python
import math


def beta_update(alpha, beta, positives, negatives):
    if any(
        not isinstance(value, (int, float))
        or isinstance(value, bool)
        or not math.isfinite(value)
        or value <= 0
        for value in (alpha, beta)
    ):
        raise ValueError("alpha and beta must be finite positive numbers")
    if any(
        isinstance(value, bool) or not isinstance(value, int) or value < 0
        for value in (positives, negatives)
    ):
        raise ValueError("counts must be non-negative integers")
    posterior_alpha = alpha + positives
    posterior_beta = beta + negatives
    mean = posterior_alpha / (posterior_alpha + posterior_beta)
    return posterior_alpha, posterior_beta, mean


for positives, negatives in [(8, 2), (80, 20), (8000, 2000)]:
    result = beta_update(1, 1, positives, negatives)
    print(
        "observations =", positives + negatives,
        "posterior =", result[:2],
        "mean =", round(result[2], 4),
    )
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

先验为 `Beta(1,1)` 时，三组观测后验均值依次为 `0.75`、`0.7941`、`0.7999`，对应的后验参数分别为 `(9,3)`、`(81,21)`、`(8001,2001)`。相同的观测比例在样本量不同时具有不同证据强度；不能把小样本的 80% 正确率和大量样本的 80% 正确率解读成同样确定。

把第二组数据手算一遍：原先验 `Beta(1,1)` 的均值是 `1/(1+1)=0.5`；观察到 80 个成功和 20 个失败后，后验为 `Beta(81,21)`，均值 `81/(81+21)=81/102≈0.7941`。它没有直接等于 0.8，因为先验仍贡献了两个伪计数。第三组有一万次观测，先验相对样本的影响变得很小，后验均值才接近 0.8。这里的 Beta 模型把每次结果近似为独立同分布 Bernoulli；若任务、难度或用户群混在一起，单一成功率会掩盖分层差异。

### 一个简单的 ECE 计算

下面的函数适合二分类或“回答是否通过”这类已经有明确结果的任务。它不解决开放式答案如何定义置信度的问题，只展示校准计算的机械部分。

~~~python
import math


def expected_calibration_error(confidences, outcomes, bins=5):
    total = len(confidences)
    if total == 0 or total != len(outcomes):
        raise ValueError("confidences and outcomes must be non-empty and aligned")
    if isinstance(bins, bool) or not isinstance(bins, int) or bins <= 0:
        raise ValueError("bins must be a positive integer")
    if any(
        not isinstance(confidence, (int, float))
        or isinstance(confidence, bool)
        or not math.isfinite(confidence)
        or not 0 <= confidence <= 1
        for confidence in confidences
    ):
        raise ValueError("confidences must be finite numbers in [0, 1]")
    if any(type(outcome) is not int or outcome not in (0, 1) for outcome in outcomes):
        raise ValueError("outcomes must be integer 0/1 values")
    error = 0.0
    for index in range(bins):
        lower = index / bins
        upper = (index + 1) / bins
        members = [
            (confidence, outcome)
            for confidence, outcome in zip(confidences, outcomes)
            if lower <= confidence < upper
            or (index == bins - 1 and confidence == upper)
        ]
        if not members:
            continue
        mean_confidence = sum(item[0] for item in members) / len(members)
        accuracy = sum(item[1] for item in members) / len(members)
        error += len(members) / total * abs(mean_confidence - accuracy)
    return error


confidences = [0.55, 0.62, 0.74, 0.81, 0.93]
outcomes = [1, 0, 1, 1, 0]
print("ECE =", round(expected_calibration_error(confidences, outcomes), 4))
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

本例把 `[0,1]` 等宽划成 5 个桶，输出 `ECE = 0.31`。ECE 只有在样本、置信度和结果一一对应时才有定义；空输入、长度不一致、非有限或越界置信度、非法结果和非正桶数都应显式报错。若某个桶为空，它对总和的贡献为零，这与整个评估集为空是两种不同情况。

按代码的 5 个等宽区间逐桶复算：前两个桶 `[0,0.2)` 和 `[0.2,0.4)` 为空；第三桶 `[0.4,0.6)` 只有置信度 0.55 的正确样本，贡献 `(1/5)×|0.55-1|=0.09`。第四桶 `[0.6,0.8)` 包含 0.62（错误）与 0.74（正确），平均置信度 `0.68`、准确率 `0.5`，贡献 `(2/5)×|0.68-0.5|=0.072`。第五桶 `[0.8,1]` 包含 0.81（正确）与 0.93（错误），平均置信度 `0.87`、准确率 `0.5`，贡献 `(2/5)×|0.87-0.5|=0.148`。总和为 `0.09+0.072+0.148=0.31`，与代码输出一致。这个值对分桶边界敏感，ECE 还可能因样本量和切桶方式掩盖桶内误差，因此适合作为诊断摘要，不能单独作为置信度验收指标。

### 初学者与专家的两层理解

初学者要记住：模型说“概率高”只表示它倾向于这样生成，不等于事实已经被验证；遇到知识不足时，检索、工具和合理拒答是系统能力的一部分。

进一步分析时要区分参数不确定性、数据噪声、预测校准、答案一致性和证据支持。多次采样很一致，可能说明模型稳定，也可能说明模型稳定地犯同一个错误；检索有引用，可能说明证据存在，也可能只是引用与结论不匹配。

### 证据边界

贝叶斯公式、MLE/MAP 关系和 ECE 定义是数学或统计定义。深度网络中使用 ensemble、dropout 或采样近似不确定性，是工程近似而不是完整后验推断。幻觉成因具有多因素性质；RAG、校准和拒答能够降低部分风险，但不能保证所有事实正确。

## 6. 损失函数是代理目标：从预训练到偏好优化

### 为什么可优化的目标不等于最终目标

产品目标往往是“给出正确、有帮助、安全、简洁且可执行的回答”。这些要求相互关联，却很难写成一个稳定、可微、低成本的函数。训练系统因此选择代理目标：

- 预训练用 next-token likelihood；
- 监督微调用参考答案的交叉熵；
- 偏好优化用人类或合成偏好数据；
- 代码训练可以用测试通过率；
- 工具系统可以用 schema 合法率和执行结果。

代理目标的价值在于可计算、可规模化，但它总会遗漏一部分真实目标。一个成熟的训练设计必须同时问两件事：这个目标推动了什么？它没有约束什么？

### Token-level 目标与任务级成功

语言模型的典型损失为：

~~~math
\mathcal L_{\mathrm{token}}
=-\sum_{t=1}^{T}
\log P_\theta(y_t\mid x,y_{1:t-1})
~~~


数学题、代码和工具调用的成功事件往往是离散的：

~~~math
\mathcal L_{\mathrm{task}}
=\mathbf 1[
\text{答案不正确或执行失败}
]
~~~


两个目标并不等价。一个代码回答只错一个字符，token 平均损失可能只增加一点，但程序完全不能运行。一个摘要用了更多高概率常见词，token loss 可能下降，却可能漏掉关键事实。

因此训练报告应至少把 token-level 指标和 task-level 指标并列，而不是用前者替代后者。

### 预训练的收益与边界

预训练的 next-token 目标具有三个巨大优势：数据无需逐条人工标注，目标可以扩展到极大语料，训练和自回归生成在形式上保持一致。它能学习语言结构、知识关联、代码模式和许多任务格式。

但互联网语料也包含错误、偏见、过时内容、低质量答案和不安全模式。预训练模型学习的是数据分布中的统计规律，不会因为文本出现在网页上就自动知道它是真的。它也不会因为某个规则对人类重要，就自动把它当作最高优先级。

### SFT 的目标错配

监督微调通常最大化参考答案概率：

~~~math
\mathcal L_{\mathrm{SFT}}
=-\sum_{(x,y)\in D}
\log P_\theta(y\mid x)
~~~


它能让模型遵循指令、学习格式和模仿示范，但有几个边界：

1. 一个问题可能有很多同样好的答案；
2. 参考答案可能含有事实错误或风格偏差；
3. 长答案中局部 token 拟合不代表整体完成任务；
4. 数据中固定的口头禅、长度和拒答模式会被放大；
5. 参考答案的“像不像”与“是否真的解决问题”不是一回事。

例如，数据若普遍把回答写得很长，模型可能学会用更多解释掩盖不确定；若拒答样本比例过高，安全分数可能上升而有用性下降。

### RLHF 与 reward model

基于人类偏好的 RLHF 代表性工作见 [Christiano et al., 2017](https://arxiv.org/abs/1706.03741)。典型流程包括：对同一输入收集多个回答；让标注者比较偏好；训练 reward model；再用强化学习更新策略模型。设奖励模型为 r_φ(x,y)，策略为 π_θ，最简化的目标可写成：

~~~math
\max_\theta
\mathbb E_{x\sim D,\;y\sim\pi_\theta(\cdot\mid x)}
[r_\phi(x,y)]
~~~


实际系统通常还会加入相对参考策略的 KL 约束：

~~~math
\max_\theta
\mathbb E[r_\phi(x,y)]
-\beta D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}})
~~~


这样做的动机是让模型追求偏好，同时避免过快偏离原始能力分布。但 reward model 只是标注偏好的近似器，受标注一致性、覆盖范围和表面特征影响。优化 reward 分数，不等于优化长期真实满意度。

### DPO 的目标与依赖

DPO 将偏好优化改写为直接使用 chosen 与 rejected 回答对的目标（[Rafailov et al., 2023](https://arxiv.org/abs/2305.18290)），不需要按经典 RLHF 流程在线更新策略。其常见损失形式为：

~~~math
\mathcal L_{\mathrm{DPO}}
=-\mathbb E\left[
\log\sigma\left(
\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}
{\pi_{\mathrm{ref}}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}
{\pi_{\mathrm{ref}}(y_l\mid x)}
\right]\right)
\right]
~~~


其中 y_w 是偏好回答，y_l 是非偏好回答，π_ref 是参考策略，β 控制相对偏离的尺度。公式说明 DPO 仍然依赖偏好数据质量和参考模型；如果偏好标签只奖励表面流畅、长度或礼貌，DPO 也会把这些相关性学得更强。

### Goodhart 现象与 reward hacking

当一个指标只是目标的代理时，强力优化它可能让系统寻找指标漏洞。语言模型中的例子包括：

- 奖励回答更长，模型增加重复解释；
- 奖励语气更自信，模型减少必要的保留意见；
- 奖励引用数量，模型生成看似合理但无法核验的引用；
- 奖励安全拒答率，模型对正常请求也拒绝；
- 奖励 benchmark 分数，模型适应题型或污染数据。

这类规格缺陷和奖励漏洞是 [Amodei et al., 2016](https://arxiv.org/abs/1606.06565) 讨论的 AI 安全问题之一，后来常用 reward hacking 描述。它不是模型“有恶意”，而是优化器忠实地追逐了定义中的信号，而设计者没有把真实意图完全编码进去。模型越强、优化越充分，越可能找到代理目标的缝隙。

### 多目标与 Pareto 取舍

现实系统至少同时关心正确性、有用性、安全性、延迟、成本、格式遵循和鲁棒性。不存在一个设置在所有维度都严格更好。可以把一次实验看成在多个指标空间中寻找 Pareto 改善：若一个方案在所有重要指标上不差、至少一个指标更好，它才真正支配另一个方案。

工程报告应写出主动承担的代价，例如：

- 提高拒答边界后，有用性下降多少；
- 增加检索后，事实性提升是否值得延迟；
- 换用门控 MLP 后，质量提升是否抵消了 FLOPs；
- 更长输出是否带来信息增益，还是只增加成本。

没有副作用监控的单指标提升，很容易只是把问题从一个维度搬到另一个维度。

### 目标错配的诊断实验

当训练 loss 变好但产品效果变差时，可以按以下顺序建立证据：

1. 固定 checkpoint、解码参数和评估数据，确认指标没有实现错误；
2. 查看训练、验证和不同领域切片的 token loss；
3. 查看任务级成功率、格式合法率和人工偏好；
4. 按长度、难度、风险和输入类型切片；
5. 检查输出长度、拒答率、引用率和工具调用分布是否漂移；
6. 对关键失败案例进行人工归因；
7. 用 ablation 区分数据、损失、参考模型和解码策略的影响。

如果只看平均分，无法判断是少量灾难性失败，还是所有样本均匀改善。

### 一个代理指标反转的示例

下面构造两个模型的统计结果。模型 B 的平均 token loss 更低，但任务正确率和安全通过率更差。这个例子不是实际评测器，而是提醒我们不要把一个数字当成整体结论。

~~~python
models = {
    "A": {
        "loss": [0.8, 0.9, 0.7, 0.8],
        "task_success": [1, 1, 0, 1],
        "safety_pass": [1, 1, 1, 1],
    },
    "B": {
        "loss": [0.5, 0.6, 0.4, 0.5],
        "task_success": [1, 0, 0, 1],
        "safety_pass": [1, 0, 1, 0],
    },
}


def average(values):
    return sum(values) / len(values)


for name, metrics in models.items():
    print(
        name,
        "loss =", round(average(metrics["loss"]), 3),
        "task =", round(average(metrics["task_success"]), 3),
        "safety =", round(average(metrics["safety_pass"]), 3),
    )
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

运行结果为 A：平均 loss `0.8`、任务成功率 `0.75`、安全通过率 `1.0`；B：平均 loss `0.5`、任务成功率 `0.5`、安全通过率 `0.5`。实验设计的关键不是人为选择一个“正确模型”，而是把最终任务和副作用都列入结果表，并解释指标之间的冲突。

如果上线门槛预先规定安全通过率必须 `≥0.95`、任务成功率不得低于 `0.70`，A 满足两项门槛，B 虽然平均 loss 更低，却在两项行为约束上都不合格。若事后再根据结果调门槛，会产生新的选择偏差；门槛应在对照实验开始前和目标风险方共同定义。这也是代理目标管理的关键：软分可以用于排序，不能覆盖硬条件。

### 初学者与专家的两层理解

初学者先形成一个习惯：每当看到指标上升，问它究竟代理了哪一个目标，又没有覆盖哪一个目标。

进一步检查目标的测量层级：训练 token、完整序列、交互回合、长期用户结果和安全事件是否被混在一起；还要检查优化过程是否会利用标注规则、评估集或 reward model 的盲区。

### 证据边界

预训练、SFT、RLHF 和 DPO 的目标形式可以由公开论文和常见实现确认，但不同项目的细节并不相同。Goodhart 现象和 reward hacking 是设计风险，不是每个训练过程必然发生的结果。任何目标改动都需要独立的任务评估、风险切片和失败案例验证。

## 7. 初始化与训练稳定性：怎样判断信号在哪一层失控

### 梯度为什么会在深层网络里放大或消失

深层网络把许多函数连续复合。若第 $l$ 层的表示是 $h_l$，从末层传回前层的梯度会乘上每一层的局部 Jacobian：

~~~math
\frac{\partial\mathcal L}{\partial h_1}
=\frac{\partial\mathcal L}{\partial h_L}
\prod_{l=2}^{L}\frac{\partial h_l}{\partial h_{l-1}}
~~~

单个矩阵未必很大，但许多层的乘积可能在某些方向上反复放大或缩小信号。梯度爆炸、梯度消失、激活尺度漂移和 loss spike 因此不是四个互不相关的故障；它们可能来自同一条前向/反向路径，也可能由数据、学习率、混合精度或通信同步触发。训练稳定的目标不是让 loss 每一步都下降，而是让关键状态可观察、故障可定位、训练能从一致的 checkpoint 恢复。

这种连乘效应即使每层只偏离 1 也会累积。假设某个方向上每层 Jacobian 的增益都是 1.1，经过 10 层后梯度尺度约为 $1.1^{10}\approx2.59$；若每层是 0.9，则约为 $0.9^{10}\approx0.35$。真实网络有多个方向，增益也不相同，所以这只是单方向示意；它说明为什么应观察逐层信号，而不是只看首尾两处的范数。

### 初始化是在给信号传播设起点

对线性层 $y=Wx$，若输入各维近似独立、均值为零且方差相近，输出方差粗略满足：

~~~math
\mathrm{Var}(y_j)\approx n_{\mathrm{in}}\,\mathrm{Var}(W_{ji})\,\mathrm{Var}(x_i)
~~~

这说明权重尺度需要随 fan-in 和 fan-out 调整。Xavier/Glorot 常用方差尺度 $2/(n_{\mathrm{in}}+n_{\mathrm{out}})$；针对 ReLU 的 He 初始化常用 $2/n_{\mathrm{in}}$。它们是在特定独立性和激活假设下控制前向、反向尺度的近似，不是套进每个 Transformer 投影就能保证稳定的定理。残差分支、归一化位置、门控激活和网络深度都会改变整体递推。

用一个小矩阵看尺度差别：若 $n_{\mathrm{in}}=4$、$n_{\mathrm{out}}=2$，Xavier 方差约为 $2/6=0.333$，标准差约 $0.577$；He 方差约为 $2/4=0.5$，标准差约 $0.707$。两者是在不同激活假设下设定起始尺度。这个估算假定输入各维尺度相近，不能自动修复已经偏大的 embedding、残差流或投影输出；实际网络应在初始化后用固定小 batch 记录逐层均值、RMS、最大值、梯度范数和 logits，若某层第一步就偏离邻层一个数量级，应先定位分支来源再启动长跑。

### 残差和归一化是稳定性接口，不是自动保险

残差路径让子层以增量形式更新主干，归一化则约束进入某些计算的表示尺度。它们改变梯度怎样穿过网络，也会影响残差流怎样累积；若分支增量过大，残差堆叠仍可能漂移，若缩放过强，子层又可能长期贡献很弱。不能只凭“使用了 Pre-LN”或“换成 RMSNorm”就判定训练一定稳定。

本讲只把残差与 norm 作为训练诊断接口：观察每层主干与 attention/MLP 分支的 RMS 比值、梯度和更新是否集中，再按长短样本、语言/任务及 rank 切片，和数据批次、学习率及精度日志对齐。若异常只出现在长样本，可能与长度或位置处理有关；所有长度都在同层突增，则更像该分支的数值变化。具体递推公式由[第二部分第 13 讲](02-transformer架构进阶.md)主讲，统计轴和 ε 由[第 14 讲](02-transformer架构进阶.md)主讲，attention 缩放由[第 11 讲](02-transformer架构进阶.md)主讲；本讲用这些接口提出假设，原因仍需同一输入的对照运行确认。

### Warmup、梯度裁剪和混合精度各自处理什么

Warmup 在训练初期逐步提高学习率，降低模型和优化器状态尚未进入稳定区域时的大更新风险。若峰值学习率为 $10^{-4}$、warmup 共 1,000 步，则第 250 步的线性学习率是 $2.5\times10^{-5}$；这里改变的是更新的尺度，不是梯度方向。线性 warmup 可写成：

~~~math
\eta_t=\eta_{\max}\min\left(1,\frac{t}{T_{\mathrm{warmup}}}\right)
~~~

它不能修复错误 label、错位 mask 或损坏的数据 batch。若 warmup 结束后仍持续出现大幅震荡，应检查梯度、参数更新量和验证切片，而不是只延长 warmup。

梯度裁剪按总范数限制一次更新的幅度。给定梯度向量 $g$ 和阈值 $c$，其规则是：

~~~math
\widetilde g=g\cdot\min\left(1,\frac{c}{\lVert g\rVert_2}\right)
~~~

它会保持方向、缩短过大的向量，但如果每步都触发，可能掩盖学习率或数据问题。混合精度则是计算和存储的资源选择：FP16 指数范围较窄，容易出现溢出或下溢；BF16 范围接近 FP32，但有效精度较低，统计量和累积方式仍需检查。换 dtype 不能代替发现第一个 Inf/NaN 的位置。

全局范数裁剪把所有参数的梯度一起缩放，能够限制整步更新，却会让一个异常张量牵动其他层。ICML 2026 的 AdaGC 研究逐张量维护历史裁剪范数，再按各张量自己的尺度裁剪；论文在 Llama-2 7B、Mixtral 8×1B 和 ERNIE 10B-A1.4B 等设置中报告了稳定性改善。它提供的是另一种故障处理设计，不证明逐张量裁剪对所有模型都更好；使用时仍要比较 spike、任务质量、通信和新增状态，并核对训练实现。[AdaGC](https://proceedings.mlr.press/v306/wang26dg.html)
排查精度问题时，分别检查动态范围造成的 Inf/0 与有效位数造成的舍入误差；用同一 batch 对比目标 dtype 和 FP32 的激活、loss、梯度摘要，并定位首个明显分叉的算子。若 loss scaler 频繁回退，也要检查长样本、异常 label 和 norm 统计，不能只看最终 loss 仍为有限值。

### 把一次梯度裁剪完整算出来

设梯度为 $g=[3,4,12]$，阈值 $c=5$。先算范数：$\lVert g\rVert_2=\sqrt{3^2+4^2+12^2}=13$；因为 $13>5$，缩放系数为 $5/13\approx0.3846$。逐项相乘得到 $\widetilde g\approx[1.1538,1.5385,4.6154]$，新范数为 5。三个分量都按同一系数缩小，因此方向保持不变。真实训练会把所有可训练参数的梯度纳入全局范数，并受分布式归约、梯度累积和混合精度影响；这里的小向量只说明算法本身。

下面的标准库示例沿用同一组输入，显式处理零向量和非法值，便于核对“未超过阈值时不变、超过阈值时按比例缩放”这两种情况。

~~~python
import math


def is_finite_number(value):
    if not isinstance(value, (int, float)) or isinstance(value, bool):
        return False
    try:
        return math.isfinite(value)
    except OverflowError:
        return False


def l2_norm(vector):
    if not isinstance(vector, (list, tuple)) or not vector or any(
        not is_finite_number(value) for value in vector
    ):
        raise ValueError("vector must contain finite numbers")
    return math.hypot(*vector)


def clip_by_norm(vector, threshold):
    if (
        not is_finite_number(threshold)
        or threshold < 0
    ):
        raise ValueError("threshold must be finite and non-negative")
    norm = l2_norm(vector)
    if norm == 0:
        return list(vector), norm
    scale = min(1.0, threshold / norm)
    return [value * scale for value in vector], norm


gradient = [3.0, 4.0, 12.0]
clipped, before = clip_by_norm(gradient, threshold=5.0)
print("before =", round(before, 4))
print("after =", round(l2_norm(clipped), 4))
print("clipped =", [round(value, 4) for value in clipped])
~~~

> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

输出范数从 13 变成 5，向量为 `[1.1538, 1.5385, 4.6154]`。零向量返回原值；空向量、非有限梯度和负阈值会报错。这个例子不是训练模拟，而是把一个可观测的防护操作拆成可复算步骤。

### 从 loss spike 找到第一处异常

看到 spike 或 NaN 时，可以沿数据流从外到内定位，而不要立即把原因归结为学习率：

1. 保存异常前后的样本 ID、序列长度、有效 token 数和 loss mask，确认是否由单批异常输入触发。
2. 对同一 checkpoint 和同一批数据重放一次，记录每层 activation、loss、梯度范数及更新量首次变成非有限值的位置。
3. 核对学习率、warmup、optimizer state、梯度裁剪和精度配置是否与 checkpoint 一致。
4. 在多卡训练中对比各 rank 的局部 loss 与梯度；若某 rank 先异常，再检查归约、通信和设备错误。
5. 用固定小 batch 做对照，逐项关闭或替换可疑路径，并把恢复训练前后的 scheduler step、optimizer step 和模型 step 对齐。

这条路线把“不稳定”变成可检验假设：异常是否伴随长样本、只出现在某层、能否由同一 seed 和 batch 重放？恢复时还要让 scheduler、optimizer 与模型 step 对齐，否则即使从同一 checkpoint 开始，也可能走上不同参数轨迹。最终比较固定数据、token 数、深度和优化器，报告发散率、spike、达到目标 loss 的步数、吞吐和下游任务；裁剪公式可推导，初始化/精度结论依赖假设，AdaGC 的收益绑定论文设置。修复应在同 checkpoint、同 batch 下确认异常消失且质量未回退。

## 8. 激活函数与非线性：表达能力怎样进入优化路径

### 为什么深度需要非线性

多个线性层直接相乘仍然是一个线性变换：$W_3W_2W_1x=Wx$。如果网络没有非线性，无论堆多少层，都不能因此表达更复杂的分段关系。激活函数在层与层之间改变信号，使不同输入能沿不同路径传播；它因此同时影响表达能力和反向梯度。

这讲只建立理解激活与训练的基础：激活函数改变哪些输入能通过、梯度如何流动、训练中应观察什么。Transformer 里的普通 FFN、GLU/SwiGLU 公式、hidden size 和参数账本由[第二部分第 15 讲](02-transformer架构进阶.md)完整主讲。这里先用简单标量模型解释非线性，再讨论激活统计怎样帮助定位训练问题。

### 三种常见激活的差别

ReLU、GELU 和 SiLU 都把输入映射到新的数值，但曲线与梯度不同。ReLU 对负输入直接输出 0，正输入原样通过；GELU 依据标准正态分布的累积分布函数平滑调制输入；SiLU 用 sigmoid 对输入自身做平滑缩放。定义如下：

~~~math
\mathrm{ReLU}(x)=\max(0,x),\qquad
\mathrm{GELU}(x)=x\Phi(x),\qquad
\mathrm{SiLU}(x)=x\sigma(x)
~~~

ReLU 的优点是计算简单、正区间梯度直接；若一个单元长期只收到负输入，它的梯度可能长期为零。GELU 和 SiLU 不会在负半轴上做硬截断，但仍可能对很负的值给出很小的响应。它们不保证模型更准，选择还受初始化、归一化、训练预算、kernel 实现和目标任务影响。
把输入固定在 $x=-2$ 时，ReLU 输出 0，GELU 约为 $-0.0455$，SiLU 约为 $-0.2384$；在 $x=2$ 时，三者分别约为 2、1.9545 和 1.7616。前一组数字显示平滑激活保留了较小的负信号，后一组显示它们也会调节正信号幅度。输出值的差异会传到下一层，而对应导数决定反向更新能否穿过该单元；因此不能只比较激活曲线的正半轴，也不能把“平滑”简化成“梯度总是更大”。

| 激活 | 对负输入的处理 | 优化时观察什么 |
| --- | --- | --- |
| ReLU | 直接变为 0 | 正值比例、长期零激活通道 |
| GELU | 平滑保留部分负值 | 激活范围、梯度尺度与低精度误差 |
| SiLU | 按 sigmoid 平滑缩放 | 负值尾部、门控幅度和 kernel 成本 |

这个表只比较机制，不是质量排名。真正的结构选择还要比较参数量、训练 token、延迟和目标切片；详细的 Transformer FFN 预算留在第 15 讲，避免在两处重复推导。

### 用一个输入看激活如何改变梯度

取两层标量网络 $f(x)=3\,\mathrm{ReLU}(2x)$。输入 $x=1$ 时，第一层得到 $2$，ReLU 保留它，输出 $6$；在这个分段区域内，$\mathrm{d}f/\mathrm{d}x=3\times2=6$。输入 $x=-1$ 时，第一层得到 $-2$，ReLU 输出 $0$，最终输出也是 $0$，梯度为 $0$。若删去 ReLU，两层就合并成 $6x$，负输入会输出 $-6$，且仍有梯度 6。激活因此改变了函数形状，也改变了哪些输入能继续影响参数更新。

小样本可以让这个现象更直观。对输入 `[-2,-1,-0.5,0,0.5,1,2,3]` 使用 ReLU，4 个非正样本输出为 0，零激活比例为 `4/8=50%`；八个样本的 ReLU 输出均值为 `(0.5+1+2+3)/8=0.8125`。如果这只是单个 batch，50% 不能证明通道“死亡”；若同一层、同一批代表性数据在很多训练阶段都保持近乎全零，还要检查前置权重、bias、归一化、学习率和数据切片。一个统计量先提示问题，再由反事实输入和任务输出确认影响。
把阈值和梯度也写出来：令 $z=2x-1$、$y=\mathrm{ReLU}(z)$。当 $x=0.25$ 时，$z=-0.5$、输出为 0，该样本通过这个单元的反向梯度为 0；当 $x=1$ 时，$z=1$、输出为 1，局部导数为 $\mathrm{d}y/\mathrm{d}x=2$。若训练改变了偏置，使 $z=2x-0.25$，原先的 $x=0.25$ 就会得到 $z=0.25$ 和非零梯度。一个单元是否活跃由输入分布、权重和偏置共同决定，不是给神经元贴上永久属性。对 Transformer 的残差块，还要检查主干能否绕过某个分支；局部激活变零不等于整层信息完全消失。
假设某隐藏通道在 20,000 个激活位置里有 18,400 个输出为零，表面稀疏率是 `18,400/20,000=92%`。如果这 18,400 个零几乎都来自英文样本，而中文、代码切片仍有大量非零值，它可能反映了输入分布差异；若所有切片和多个 checkpoint 都接近全零，且该通道梯度也长期为零，才更有理由检查初始化、偏置和数据覆盖。统计激活率时要固定 mask，只对有效 token 计数，否则 padding 会人为抬高零比例。这个例子把“通道不活跃”变成可复核的分母、切片和梯度问题，而不是凭一张均值图下结论。

### 从激活分布追到训练症状

训练时可以按层和输入类型观察 activation mean、RMS、最大绝对值、零激活比例和梯度范数。若只有代码任务切片上的某些通道变化，可能是数据组成或领域能力变化；若所有切片都出现幅值突增，则更像学习率、初始化或数值路径问题。不要把通道激活直接命名为某个概念，也不要仅凭零值比例推断模型失去能力；应改变输入、做消融并看目标输出是否随之改变。
这些统计量各自有盲点：均值接近零可能来自正负抵消，RMS 能看到整体能量却看不到少数极端值，稀疏率又看不到非零值是否已经过大。因此至少把分位数或最大绝对值与均值/RMS并列，并沿层、训练步数和有效 token 切片查看。若某项统计变化但任务指标不变，它是诊断线索；若统计变化与特定失败同步出现，再用固定输入和层级干预检查因果路径。这样初学者可以从曲线认识“什么在变化”，专家则能追问“哪种分布变化造成了哪类错误”，两者沿同一条解释链工作。

比较激活函数时，单次训练的 loss 曲线不够。先匹配模型宽度、参数量或 FLOPs、训练 token 和优化器，再记录吞吐、激活与梯度统计，最后在相同的验证集、长尾数据和目标任务上做配对比较。若两种结构使用不同 hidden width，结果既可能来自非线性，也可能来自容量差异；若一个用融合 kernel、一个没有，wall-clock 时间也不能直接归因于公式。
做局部诊断时，可以构造一对只差一个小扰动的输入，让某个 pre-activation 从阈值一侧跨到另一侧；固定其余 token、mask 和位置，记录 pre-activation、输出、梯度及目标 logit。若仅局部数值改变而任务结果稳定，它说明函数曲线的差异；若多个真实失败样本都在同一通道附近翻转，才值得进一步做通道消融和数据切片评估。构造例用于解释机制，不能替代自然输入上的回归。

这一层基础解释与后续结构设计的分工是：本讲回答“非线性为什么改变表示和梯度”，第 15 讲回答“在 Transformer 中怎样把它做成 FFN 或 SwiGLU，以及容量和计算如何匹配”。理解这条接口后，下一讲转向优化器：给定同一批梯度，不同更新规则怎样改变参数轨迹、状态显存和训练成本。

关于激活函数的定义可由公式直接确认；GELU 的论文实验支持它在论文所测任务中的比较结果，但不能证明它对所有 LLM 配置最优。门控 MLP 的结构和代价由第 15 讲结合原始研究进一步讨论。上面的输入和数字是教学构造，用来说明函数和梯度，不是训练效果数据。

## 9. 优化器、状态显存与训练成本

### 优化器决定更新轨迹

给定梯度 g_t，最基本的 SGD 更新为：

~~~math
\theta_{t+1}=\theta_t-\eta_tg_t
~~~


Momentum 用历史方向平滑噪声：

~~~math
m_t=\beta m_{t-1}+(1-\beta)g_t
~~~


~~~math
\theta_{t+1}=\theta_t-\eta_t m_t
~~~


Adam 同时维护一阶矩和二阶矩：

~~~math
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t
~~~


~~~math
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
~~~


由于 m 和 v 从零开始，Adam 使用偏差修正：

~~~math
\widehat m_t=\frac{m_t}{1-\beta_1^t},
\qquad
\widehat v_t=\frac{v_t}{1-\beta_2^t}
~~~


更新为：

~~~math
\theta_{t+1}
=\theta_t-\eta_t
\frac{\widehat m_t}{\sqrt{\widehat v_t}+\epsilon}
~~~


一阶矩主要平滑方向，二阶矩提供逐参数尺度调整。它们都不是“知道哪个参数更重要”，而是根据历史梯度统计改变步长。

### Adam 与 AdamW 的关键差别

把 L2 正则直接加到 Adam 的梯度中，会得到：

~~~math
g'_t=g_t+\lambda\theta_t
~~~


然后 g'_t 还会进入一阶和二阶矩的自适应处理。这样参数衰减行为会与梯度历史耦合。

AdamW 把衰减从自适应梯度中分离。一个简化更新为：

~~~math
\theta_{t+1}
=\theta_t
-\eta_t\frac{\widehat m_t}
{\sqrt{\widehat v_t}+\epsilon}
-\eta_t\lambda\theta_t
~~~


因此 weight decay 的作用不再被每个参数的二阶矩重新缩放。AdamW 不是只改了名字，而是改变了正则化进入更新的方式。

实践中常把 bias、LayerNorm/RMSNorm 的缩放参数排除在 weight decay 之外。这是常见工程配置而非数学必然；embedding、路由器、LoRA 参数是否衰减，要根据架构和实验单独决定。

### Adafactor 的因子化状态

Adam 的二阶矩和参数矩阵同形状。对 W∈R^{r×c}，完整二阶矩需要 rc 个状态。Adafactor 对矩阵二阶统计做行列因子化近似，保存行统计 R∈R^r 和列统计 C∈R^c：

~~~math
R_i\approx\frac{1}{c}\sum_{j=1}^{c}V_{ij},
\qquad
C_j\approx\frac{1}{r}\sum_{i=1}^{r}V_{ij}
~~~


一种重构形式是：

~~~math
\widetilde V_{ij}
\approx\frac{R_iC_j}{\mathrm{mean}(R)}
~~~


状态量从 O(rc) 变成 O(r+c)，对巨大矩阵节省显存明显。代价是二阶矩是近似的，学习率、相对步长、裁剪和稳定性设置需要重新验证。Adafactor 的主要卖点是状态成本，而不是在所有任务上都胜过 AdamW。

### Lion 的符号更新

Lion 的核心思想是用动量方向的符号更新，而不是保存 Adam 的二阶矩。为了说明直觉，可以写出简化形式：

~~~math
c_t=\beta_1m_{t-1}+(1-\beta_1)g_t
~~~


~~~math
\theta_t=\theta_{t-1}
-\eta\,\mathrm{sign}(c_t)
-\eta\lambda\theta_{t-1}
~~~


动量状态再以另一个系数更新。实际实现的系数安排和更新顺序需要以论文或框架实现为准，不能把上式当作唯一代码。

符号更新的优点是状态比 Adam 少、规则简单；风险是有效步长的几何性质不同，对学习率和 weight decay 更敏感。它在某些视觉和语言实验中有吸引力，但是否适合一个具体的大规模预训练项目，必须用相同 token budget、数据和硬件做对照实验。

### 训练显存不只是参数显存

设模型有 N 个参数。若参数用 BF16 保存，每个参数约 2 字节；梯度、FP32 master weights 和优化器状态可能使用不同精度。一个粗略的 AdamW 账本可能包括：

| 项目 | 近似数量级 | 说明 |
| --- | ---: | --- |
| 参数 | 2N 字节 | 取决于保存精度 |
| 梯度 | 2N 或 4N | 取决于实现和累积精度 |
| 一阶矩 | 4N | 常用 FP32 状态 |
| 二阶矩 | 4N | 常用 FP32 状态 |
| master weights | 可能为 4N | 某些混合精度实现需要 |

这还没有包含 activation、临时通信 buffer、KV cache 和框架开销。因此优化器选择会直接影响分片、offload、checkpoint 和可训练模型规模。

### Batch、梯度累积与学习率

global tokens per step 可以近似写成：

~~~math
T_{\mathrm{global}}
=T_{\mathrm{micro}}
\times N_{\mathrm{data}}
\times N_{\mathrm{accum}}
~~~


其中 T_micro 已包含每个 micro-batch 的序列长度。改变数据并行数、梯度累积或序列长度，都会改变每一步优化器看到的统计。只把“batch size”写成一个样本数，在语言模型训练里往往不够。

增大 batch 有时需要增大学习率，但不存在脱离模型和优化器的无限线性缩放规则。应记录实际 token 数、更新次数、学习率 schedule 和梯度归一化方式。

例如 2 个数据并行 rank、每个 rank 每个 micro-batch 有 4 条长度 1,024 的序列、梯度累积 8 次，则无 padding 时每次更新覆盖 `2×4×1,024×8=65,536` 个 token。若每条序列只有 768 个有效 token，其余位置是 padding，实际参与 loss 的 token 只有 `2×4×768×8=49,152`。同一个“每步 8 个 micro-batch”因此可能对应不同的有效训练信号；变长 batch 要记录真实有效 token 数和 loss reduction 方式，才能复算学习率与 token budget 的关系。

### 训练中常见的优化器故障

如果 loss 不降或波动异常，可以检查：

1. 实际学习率是否与配置一致；
2. warmup 和衰减是否按 token 或 step 正确计算；
3. β₁、β₂、ε 是否和精度及梯度噪声匹配；
4. weight decay 参数分组是否正确；
5. clipping 是否过强或没有生效；
6. checkpoint 是否同时恢复 optimizer 和 scheduler state；
7. 参数更新比率是否过大或几乎为零；
8. Adafactor/Lion 的自定义实现是否和论文公式一致。

更新比率可以定义为：

~~~math
\rho_t=\frac{\lVert\Delta\theta_t\rVert_2}
{\lVert\theta_t\rVert_2+\epsilon}
~~~


它不能单独判断好坏，但能帮助定位某些层是否发生异常大的相对变化。

例如某层参数范数是 10、一次更新范数是 0.1，则 `ρ≈0.1/10=0.01`，相对变化约为 1%；另一层参数范数只有 0.1、更新范数仍为 0.1，则 `ρ≈1`，更新的尺度已经和参数本身相当。第二种情况不必然错误——小初始化或接近零的参数可能合理——但它值得检查该层梯度、归一化、weight decay 和 loss 贡献。按层查看更新比率，比全模型的单个梯度范数更容易定位局部失稳。

### 一个参数分组的示意

下面的代码只展示常见的分组逻辑。真实模型要根据参数名和模块类型逐项检查，不能把字符串规则直接当成所有架构的正确配置。

~~~python
def split_weight_decay(named_parameters):
    decay = []
    no_decay = []
    for name, parameter in named_parameters:
        if not getattr(parameter, "requires_grad", True):
            continue
        lowered = name.lower()
        if name.endswith("bias") or "norm" in lowered:
            no_decay.append(name)
        else:
            decay.append(name)
    return decay, no_decay


names = [
    "layers.0.attention.weight",
    "layers.0.attention.bias",
    "layers.0.input_norm.weight",
]
print(split_weight_decay([(name, object()) for name in names]))
~~~


> **代码状态：已验证（2026-10-07；Python 3.12.9；标准库）**

本例输出 `(['layers.0.attention.weight'], ['layers.0.attention.bias', 'layers.0.input_norm.weight'])`。这里的 `object()` 只是为了演示名字分类，并没有创建优化器。生产代码还要传递真正的参数对象，检查每个参数恰好进入一个组，并记录 embedding、路由器和低秩适配器的处理方式。

### 用第一步更新区分 Adam 加 L2 与 AdamW

取单个参数 `θ₀=1`、数据梯度 `g₀=0.2`、学习率 `η=0.01`、`β₁=0.9`、`β₂=0.999`、`ε=0.001` 和衰减系数 `λ=0.1`。对未修正动量，Adam 第一步是 `m₁=0.1×0+0.9×0.2=0.02`，`v₁=0.001×0+0.999×0.2²=0.00003996`；偏差修正后约为 `m̂₁=0.2`、`v̂₁=0.04`。

在 AdamW 中，梯度更新量约为 `0.01×0.2/(√0.04+0.001)=0.00995`，解耦衰减量为 `0.01×0.1×1=0.001`，所以 `θ₁≈1-0.00995-0.001=0.98905`。若采用 Adam 加 L2，进入矩估计的梯度是 `g'_0=0.2+0.1×1=0.3`，一阶、二阶矩跟着变为约 `0.3` 和 `0.09`，第一次自适应更新约 `0.00997`，参数约为 `0.99003`。数值接近，但公式路径不同；训练多步后，L2 项进入历史矩会累积影响，因此不能把二者当作同一个算法。

再看状态显存：7B 参数若权重、梯度各按 2 字节存储，约各占 14 GB；Adam 的两个 FP32 矩约各占 28 GB，另存 FP32 master weights 时再占 28 GB。粗略合计 112 GB，尚未计算激活、通信和临时峰值。这个量级估算解释了为什么优化器状态会影响并行切分与 offload，但不等于某个模型在某张 GPU 上的实测占用。

### 初学者与专家的两层理解

初学者先掌握：Adam 用一阶和二阶历史统计调整步长，AdamW 把 weight decay 解耦，Adafactor 用因子化状态省显存，Lion 用符号动量减少状态。

专家不能只比较论文里的最终分数，还要比较状态显存、吞吐、稳定性、学习率敏感度、checkpoint 兼容性、分布式实现和在相同计算预算下的有效质量。

优化器比较还要固定“训练走了多远”。若方案 A 每步看 65,536 个 token、训练 1,000 步，名义预算是 65,536,000 token；方案 B 每步看 32,768 个 token、训练 2,000 步，名义 token 数相同，但更新次数翻倍，学习率 schedule 和 optimizer state 演化也不相同。若一个方案因 packing 或 padding 损失实际只训练 80% 的有效 token，名义预算相同也不等于训练信号相同。

因此完整的优化器实验至少要同时报告：有效 token、参数更新步数、每步耗时、峰值状态/激活内存、训练中断后的恢复方式和验证曲线。一个状态更省的优化器可能允许更大 batch 或更多参数，但如果它造成更多更新不稳定或恢复后轨迹断裂，节省的状态显存未必转化为更好的最终模型。这里必须用实际配置和多次运行验证，不能从某篇论文的最优表格直接移植默认参数。

### 证据边界

SGD、Adam、AdamW、Adafactor 和 Lion 的公式分别有经典教材或论文支持：Adam ([Kingma and Ba, 2014](https://arxiv.org/abs/1412.6980))、AdamW ([Loshchilov and Hutter, 2019](https://arxiv.org/abs/1711.05101))、Adafactor ([Shazeer and Stern, 2018](https://arxiv.org/abs/1804.04235)) 与 Lion ([Chen et al., 2023](https://arxiv.org/abs/2302.06675))。具体默认超参数、状态精度和参数分组会随框架与模型改变。优化器的效果不能脱离数据、token budget、学习率 schedule 和硬件系统比较。

## 10. 把概率、优化和评估串成训练诊断系统

### 一条 loss 曲线不够描述一个模型

训练日志通常从 loss 开始，但模型质量至少有六个观察层：

1. 数据层：样本来源、重复、长度、语言和质量；
2. 概率层：训练/验证 NLL、困惑度和 token 分布；
3. 优化层：学习率、梯度、参数和更新比率；
4. 数值层：精度、NaN、Inf、溢出和设备差异；
5. 任务层：答案正确率、代码通过率、工具执行率；
6. 行为层：事实性、拒答、有用性、安全性和成本。

任何一层出现异常，都可能让其他层的平均指标失去解释力。比如 validation NLL 下降，但任务层因模板变化而退化；任务分数上升，但行为层出现过度拒答；loss 只是某个 rank 的局部值，实际同步已经错误。

### 训练前：先写清楚目标契约

一个可执行的训练任务应明确：

- 输入分布和输出格式；
- 训练目标与 loss mask；
- 任务成功的判定；
- 不能接受的失败；
- 评估切片；
- 资源约束和允许的延迟；
- 回滚和停止条件。

例如“提升客服模型质量”过于模糊。更好的定义是：在未参与训练的时间切分数据上，事实核验通过率提高，关键意图的任务成功率不下降，安全违规率低于某阈值，平均延迟增加不超过某范围。这样才有可能判断一个改动是否真的有效。

### 训练中：把可观测性做成证据链

至少保存以下信息：

| 类别 | 关键记录 |
| --- | --- |
| 数据 | shard、样本 ID、token 数、去重版本、异常样本 |
| 优化 | step、global tokens、学习率、梯度范数、更新比率 |
| 模型 | 参数范数、激活摘要、checkpoint 哈希、配置 |
| 数值 | 精度、loss scale、NaN/Inf、每个 rank 状态 |
| 评估 | 验证切片、解码配置、任务指标、失败样本 |
| 系统 | 吞吐、显存、通信、温度和硬件错误 |

日志的作用不是把所有数字都存下来，而是让一次异常可以被定位和复现。没有样本 ID 和 checkpoint 版本的曲线，通常只能用于事后猜测。

### 训练后：分层评估

可以把评估组织成四层：

第一层是概率拟合：验证 NLL、困惑度、不同领域的 token loss。

第二层是任务完成：exact match、代码测试、结构化解析、工具执行和引用定位。

第三层是行为可靠性：事实性、校准、拒答合理性、长上下文、对抗输入和多轮一致性。

第四层是产品约束：延迟、成本、吞吐、显存、失败恢复和用户反馈。

每层都要有训练未见的切片。平均分只适合作为摘要，不能替代切片和错误分析。

### 贯穿案例：更低的验证损失是否值得发布

以下是人为构造的教学数据：旧 checkpoint 在 100 道保留题上验证 NLL 为 `1.20`，准确完成 70 题，产生 4 条无依据事实断言，端到端延迟为 400 ms；新 checkpoint 的 NLL 降到 `1.10`，完成 71 题，但无依据断言升到 12 条，延迟为 460 ms。若发布前已经规定“无依据断言最多 6 条、p50 延迟最多 450 ms”，新 checkpoint 虽然 NLL 降了 `0.10`、准确率从 `70/100=70%` 到 `71/100=71%`，仍同时违反风险和时延约束。

这个例子把概率目标、任务结果和产品条件接在一起：验证 NLL 说明下一 token 分布拟合改善；准确率只看最终正确项；事实断言审计关注错误风险；延迟描述用户等待。它们不能压成一个无条件的“质量提升”。若两组结果来自不同数据切分、解码设置或运行硬件，也不能把差异归因到 checkpoint 本身。下一步应检查哪些题变对、哪些断言变错、证据是否可检索，并在固定配置上重复评估。

把评价规则也放进案例：再构造 10 道需要事实作答的问题。模型 A 答对 8 题、对 2 题拒答；模型 B 答对 9 题、错答 1 题。传统 exact accuracy 分别为 `8/10=0.8` 和 `9/10=0.9`，会偏向 B；若预先约定正确 `+1`、错误 `−1`、合理拒答 `0`，A 得 8 分，B 得 `9−1=8` 分，二者按该教学规则打平，但 B 仍多产生 1 条错误断言。这个例子不是普适效用函数，它说明评分协议必须把“回答、错误、拒答”的代价写清楚，否则榜单分数可能和部署目标不同。任何新指标仍需要与目标使用场景、人类判断和风险分级校准。

还要注意 100 个样本上的一题净提升只有 1 个百分点。若新旧模型的正确题目并不相同，单看 `70→71` 不能说明改动稳定有效；应对同一批题做配对比较，列出两边都正确、都错误、仅旧版正确、仅新版正确的数量，再用重复采样或置信区间检查波动。如果样本集中在常见题，整体准确率仍可能掩盖稀有语言、长上下文或高风险场景的退化。诊断的目标是定位哪条链路产生差异，而不只是选出总分更高的一行。

### 一个从症状到假设的诊断表

| 症状 | 优先假设 | 需要收集的证据 |
| --- | --- | --- |
| loss 从第一步就很高且不动 | label、mask、学习率或实现错误 | 单 batch 前向、目标 token、梯度 |
| loss 偶发 spike 后恢复 | 异常 batch 或瞬时数值问题 | 样本长度、grad norm、精度日志 |
| spike 后持续 NaN | 溢出、非法 mask、optimizer state | 首个 Inf 位置、rank、checkpoint |
| 验证 NLL 降但任务率降 | 目标错配或分布变化 | 任务切片、输出长度、错误类型 |
| 总体分数升但长尾降 | 数据配比或代理指标过拟合 | 长尾切片、重复率、人工复核 |
| 训练恢复后行为突变 | optimizer/scheduler state 不一致 | state step、学习率、参数差分 |
| 质量升但延迟显著变差 | 模型、序列或 kernel 成本增加 | FLOPs、激活显存、生成长度 |

这张表不是自动诊断器。它的价值是把“可能原因”转成可以验证或排除的实验。

### 用 ablation 保护因果解释

一次同时改变数据、模型结构、优化器和解码参数，得到的分数变化不能归因于任何单个因素。更可靠的最小实验是：

1. 固定数据、随机种子和计算预算；
2. 只改变一个主要因素；
3. 保留独立验证和关键失败切片；
4. 重复足够次数估计随机波动；
5. 检查收益是否在不同数据和长度上复现；
6. 记录性能、成本和副作用。

例如比较 GELU 与 SwiGLU，要尽量匹配参数量或 FLOPs；比较 AdamW 与 Adafactor，要记录 optimizer state 显存和相同 token budget；比较 RAG 前后，要固定生成协议并分别测检索和生成。

### 一份最小实验报告应该包含什么

一份可复核的报告至少包含：

- 问题和成功标准；
- 数据版本与切分；
- 模型结构和参数量；
- tokenizer、上下文长度和 loss mask；
- 优化器、学习率、batch tokens 和训练步数；
- 精度、并行和 checkpoint 方式；
- 自动指标、人评协议和统计波动；
- 关键失败案例及归因；
- 成本、延迟和已知局限。

报告不是越长越好，而是要让另一个人能够判断结论是否由实验支持。

### 练习与小项目

1. 选一个小型文本数据集，计算不同模型分布的熵、交叉熵和 KL，并验证交叉熵分解。
2. 用同一组数据比较不同 batch 和学习率下的优化轨迹，记录梯度范数与验证损失。
3. 构造原题、语义改写和同构新题，设计一个区分记忆与泛化的评估表。
4. 对一个分类或二元任务画可靠性图，计算 ECE 和 Brier score。
5. 为一个代码或工具调用任务同时设计 token loss、任务成功率和成本指标。
6. 对一个小型 FFN 计算普通结构与 SwiGLU 的参数量，并测量宽度调整前后的差异。
7. 比较两种优化器时，除了最终 loss，再记录状态显存、吞吐和恢复训练后的行为。
8. 写一份“loss spike 复盘报告”，从数据、模型、优化、数值、分布式和评估六条线排除假设。

### 本部分的主线

概率建模回答模型试图拟合什么；交叉熵和 KL 说明这个目标如何被计算；优化景观和优化器说明参数如何到达某个解；泛化和数据污染说明验证分数如何被解释；贝叶斯视角和校准说明模型是否知道自己不确定；目标错配说明训练信号为什么可能偏离真实需求；归一化、激活和数值控制说明训练怎样保持可用；最后的诊断系统把这些知识转成可复现的工程判断。

最重要的习惯不是背一句万能结论，而是始终追问：

1. 我正在优化哪个量？
2. 这个量代理了哪个真实目标？
3. 它遗漏了哪些失败？
4. 哪个实验可以区分不同原因？
5. 收益是否值得额外的成本和风险？

把这五问带到第二部分，问题会从训练曲线转成结构选择：注意力、残差、门控 MLP 和位置机制各自改变了什么计算，代价落在 FLOPs、显存还是通信上？下一部分沿着这些接口继续推演，避免把优化和模型架构当成互不相干的知识点。
