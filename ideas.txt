# 新书灵感：第 25 册起

这里收集现有 24 册之外，未来可以新增的书籍选题。下方册号仅用于讨论和排序，不表示已决定扩册。每个候选书单独成章，便于后续增删、比较和扩写。

## 本项目新增书的方向与本次讨论共识

前 24 册已经承担基础知识、原理和面试体系的主要职责。第 25 册起的候选书应优先增加进阶实战：读者跟着一册书，从零搭建一个完整样例，系统了解主流方法并实际操作，最后得到可运行、可评估、可部署的项目经验。新增册不应退回面试知识点罗列，也不应拆成彼此无关的 demo。册号只是讨论顺序，未来还可以重排。

### 每册用一条主线项目贯穿

每册先选定一个清楚的业务/工程样例，然后从需求和验收目标开始，经过数据获取与处理、模型/系统架构、框架与工具选择、训练或应用构建、评估和部署运维，逐阶段累积出一个最终系统。读者应能跟着步骤实际做出每个阶段的产物，并理解选择背后的工程判断；书的目标是形成系统经验和可展示作品，而不是只认识名词。

### 每阶段先完整讨论方法，再选主线产物

每个阶段都要尽量完整地整理重要方法：讲清定义、意义、前置条件、操作步骤、优缺点、失败模式和适用范围；再说明方法之间哪些可以组合以及顺序，哪些是互斥选择。兼容方法按正确依赖叠加；互斥方法在相同输入和验收指标下做对照实验，择一作为当前主线产物，交给下一阶段。其他方法通过小实验和结果分析纳入学习，但不强行串进最终系统。例如数据清洗可把格式校验、规范化、去重、脱敏、质量筛选等步骤按需要组合；偏好优化中的 DPO 与 GRPO 要按任务和奖励条件比较后选型，不能默认先 DPO 再 GRPO；量化方法从同一未量化模型各自产生候选，不能把 GPTQ 后再 AWQ 当成默认流水线。

方法比较要有具体产物、统一评测和决策记录，说明选中的主线版本为什么适合当前目标，未选方案在哪些条件下可能更合适。重要主流方法应有实际操作或可复现实验；算力、设备或授权限制导致无法完整运行时，明确提供小模型、模拟器、云端或替代实验，并标出它与真实规模生产环境的差距。

### “开箱即用、对标主流、前沿一线”的交付要求

- **可复现**：写明操作系统、硬件、驱动、框架和依赖版本；提供模型/数据来源、许可、获取方式、配置、运行命令、预期输出和验收指标。安排低算力路径，并标明必须使用专用 GPU、真实设备或付费 API 的步骤。
- **有工程闭环**：最终样例应有适用的质量、安全、性能、成本、稳定性和可观测性验收，并覆盖发布、监控、故障恢复和回滚。只有达到这些验收条件，才称为工业级交付；研究性或模拟结果须如实标注。
- **主流与前沿分层**：稳定、可复现的方法构成主线；前沿模型和方法通过独立实验单元跟进。记录版本/日期、原始论文或官方资料、证据等级、复现状态和已知边界，不把厂商宣传或尚未复现的结果写成生产事实。
- **逐章积累**：每章的代码、配置、数据版本、检查点、评测结果和故障处理都服务于同一项目，最终能从干净环境按文档走通，不是只在作者机器上成立的片段。

### 后续候选册的分析模板

继续分析第 28 册及后续候选时，逐册回答：①最适合贯穿全书的一个样例系统是什么；②从零到部署的阶段和阶段产物是什么；③各阶段有哪些主流/重要前沿方法，哪些可叠加、哪些互斥，主线如何选型；④模型、数据、硬件、许可和代码是否能开箱复现；⑤最终怎样验收质量与工业可用性；⑥与前 24 册及其他候选册是否重复。最后标成“适合直接做完整系统教程”“先缩小范围后适合”或“暂不适合”，给出下一步优先级和原因。若候选更适合研究导读而非可跟做系统，应说明，不为统一形式强行改造成教程。

## 第 25 册：从零构建垂直领域大模型后训练系统

**教程定位**：从 Hugging Face 等渠道取得已有基础模型或开源权重，围绕一个明确的垂直任务，从零搭建可复现的后训练流水线。读者最终得到一套能管理数据、运行 SFT 与偏好/强化学习实验、评估模型、登记产物并部署适配模型的系统。本册不讲从零预训练，也不以面试知识点罗列方法。

**建议动手构建的系统**：

- **任务与基线**：选定一个医疗、法律、金融、客服或制造任务；定义验收指标，先比较提示词、RAG、工具调用和直接调用模型等不训练方案。
- **底座、系统架构与数据入口**：按任务、许可、硬件和目标质量比较底座模型家族、架构与规模，选择 Hugging Face 等渠道的已有 checkpoint 并固定 revision/依赖；本册从已有权重做垂直适配，不从随机初始化开始预训练。从业务样本、专家标注、文档和合成数据建立可追溯数据源。数据清洗阶段系统比较格式/schema 校验、规范化、精确去重、近重复去重、隐私/敏感信息处理、质量与异常筛选、领域/安全过滤及污染检查，说明哪些按顺序叠加、哪些阈值互斥选择；逐步产出 raw、clean、训练集/验证集/测试集版本，并保证授权、脱敏和隔离。
- **先讲清训练路线图**：把领域继续预训练/领域自适应预训练、SFT、偏好优化、强化学习、安全对齐、合成数据、自训练和蒸馏放进一张统一地图；说明它们解决的问题、所需数据、模型起点和彼此的先后/替代关系。一次性的领域适配与部署后长期接收新任务的持续学习要划清边界。
- **领域适配与 SFT 实战**：比较继续预训练、全参数微调、LoRA/QLoRA 等参数高效微调；动手处理指令、多轮对话、格式约束、工具使用、推理和领域术语数据，比较数据配比、训练目标、显存/算力、效果和遗忘。
- **偏好学习全路线实战**：从人工/AI 偏好采集、成对/排序/打分数据、奖励模型和标注一致性开始；实践经典 RLHF 的奖励模型 + PPO 流程，以及 DPO、IPO、KTO、ORPO、SimPO 等代表性直接偏好优化路线。逐项记录是否需要奖励模型、reference model、在线采样、成对偏好数据和额外显存，并测试奖励投机、过度优化和偏好噪声。
- **强化学习与推理后训练实战**：实践 PPO、REINFORCE/RLOO、GRPO 等策略优化路线；结合奖励模型、规则/可验证奖励、结果监督/过程监督、verifier、工具调用和长答案任务，区分 RLHF、RLAIF 与 RLVR 的目标和反馈来源。按调研纳入重要变体和新方法，不能把“强化学习”压缩成只做一次 PPO 或 GRPO。
- **数据生成、迭代改进与压缩实战**：覆盖拒绝采样、best-of-N、合成数据、自训练/自奖励、教师到学生蒸馏、过程数据和安全对齐；分别实现代表性流程，检查合成数据污染、能力坍塌、蒸馏损失和安全回归。
- **训练框架与工程全链路**：比较适合各阶段的 Transformers/TRL、Axolotl、Unsloth、分布式训练栈等工具及版本支持，按硬件和算法选择一套主线框架并固定环境；实现训练配置、全量或 PEFT 微调、checkpoint/adapter 管理、断点恢复、训练日志、显存/算力估算、实验追踪和故障诊断。在资源有限时用小模型或缩小数据集复现实验，解释与大规模训练的差距。
- **实验与验收平台**：统一基线、数据版本、配置、随机种子、算力/成本、训练曲线、离线评测和人工抽检；检查领域效果、通用能力遗忘、安全回归和数据泄漏。
- **产物交付**：登记基础模型、adapter/合并权重、评估报告和运行配置；把通过验收的模型接入推理服务，完成灰度、监控和回滚演练。

**全方法比较与实战要求**：书中每条重要方法路线都要有能跟做的训练/运行实验，而不只列公式或概念；在同一垂直任务、受控数据、统一评测和明确算力预算下比较效果、稳定性、成本、标注需求、显存需求、通用能力保留、安全和适用条件。最后交付横向对照表和选型决策树，明确各路线的优势、短板、失败模式及何时不值得训练。方法持续演进，正式写作时按版本更新全景图；不能承诺穷尽尚未提出或无法复现的每篇论文和闭源配方。

**一条主线如何逐阶段产出**：固定一个垂直任务和一个基础模型，从“不训练基线”开始；数据获取、清洗、标注和切分完成后，选择一个训练框架与可复现配置。继续预训练是否进入主线，先由小规模对照和验收决定；SFT 阶段对全参数、LoRA、QLoRA 等候选做受控实验，再选定一个 SFT 产物。偏好/强化学习阶段比较奖励模型 + PPO、DPO 家族、GRPO/RLOO 等适用路线，依据任务反馈类型和预算选一个作为主线对齐产物；DPO 与 GRPO 不默认先后串联，若研究组合训练则另设实验并证明收益。经过安全与能力回归验收后，才进入模型压缩/推理服务和灰度上线。每一关记录选型理由、输入版本、配置、指标、产物和失败结果。

**与现有书系的关系**：第五册讲从数据到训练、评估的通用全流程；本册把后训练方法、目标、算法、实验设计和工程实现做深。第七册讲通用评估方法，第八册讲安全，第九册讲数据工程；本册在后训练场景中应用并链接这些内容，不重写其通用教材。

**与第 29 册候选的区别**：本册研究后训练方法本身，以及怎样通过实验改善模型；第 29 册研究模型怎样按顺序学习新知识和新任务，同时保持旧能力。持续学习可以使用本册介绍的 SFT、偏好优化或强化学习方法，但两册回答的问题不同。

**可用作案例的 GLM-5.3**：Z.ai 官方材料称 GLM-5.3 沿用 GLM-5.2 的基础模型，报告的提升来自扩大后训练；材料提到长程任务环境、更多训练，以及 OPD、采样策略和训练/rollout 一致性等做法。官方仓库同时把 GLM-5.3-Flash 描述为采用新训练基础与不同架构路线的模型，不能把标准版和 Flash 版的变化混为一谈。此案例适合展示后训练如何提升特定能力，不代表已公开完整训练配方，也不应把厂商报告当成独立复现。来源：[Z.ai 官方发布说明](https://z.ai/blog/glm-5.3)、[GLM-5 官方仓库与技术报告入口](https://github.com/zai-org/GLM-5)。

**灵感线索（用户提供，待核验）**：DeepSeek 摘录提到 RLHF 中文手册涵盖 SFT、奖励建模、PPO、DPO。后续可核对该手册的版本、完整度、代码和许可，再决定是否作为读者参考资料。

**方法调研入口（代表性原始资料，非完整清单）**：InstructGPT/RLHF（https://arxiv.org/abs/2203.02155）、DPO（https://arxiv.org/abs/2305.18290）、ORPO（https://arxiv.org/abs/2403.07691）、SimPO（https://arxiv.org/abs/2405.14734）、DeepSeekMath/GRPO（https://arxiv.org/abs/2402.03300）、Hugging Face TRL 训练器文档（https://huggingface.co/docs/trl/main/trainer）。这些入口用于扩展路线图，不能替代对方法假设和对照实验的核验。

## 第 26 册：从零构建资源受限大模型部署与量化加速系统

**教程定位**：面向只有存量或老旧 GPU、显存紧张、预算受限的团队，带读者从 Hugging Face 等渠道选择并取得开源模型，构建一套可复现、可压测、可运维的本地推理服务。重点是回答“这批现有硬件能稳定提供什么模型服务”，而不是只介绍量化算法名词。

**最终动手项目**：输入公司的 GPU/CPU、显存、驱动和业务负载约束；输出经过基线测试、精度/格式转换、量化与推理配置比较后部署的模型 API，以及模型兼容矩阵、质量与性能报告、运行手册和回滚方案。

**系统构建路线与全知识点实战**：

- **盘点硬件与定义服务目标**：采集 GPU 型号/代际、显存、互联、CPU、内存、驱动和功耗限制；定义请求长度、并发、首 token 延迟、吞吐、可接受质量下降和成本目标。
- **选型并固定模型**：筛选模型尺寸、架构、权重格式、许可证和推理框架支持；固定仓库 revision、tokenizer、配置和校验信息，记录无法满足的兼容条件。
- **建立资源基线**：估算并实测权重、KV cache、激活和运行时开销；比较单卡、多卡、CPU offload、上下文长度和并发配置，找出稳定运行边界。
- **先建立量化与压缩知识地图**：区分权重/激活/KV cache 量化、权重格式、量化算法、量化感知训练与推理 kernel；再讲 PTQ、校准数据、精度/位宽、分组大小、混合精度、权重-only 与 W+A 量化的关系。不得把某种格式（如 GGUF）和某种算法（如 GPTQ/AWQ）混成同一概念，也不得把用于训练的 QLoRA 误当成单纯的推理量化格式。
- **逐条实现主流量化路线**：实践 GPTQ、AWQ、SmoothQuant、bitsandbytes 的 8-bit/NF4/FP4、GGUF/llama.cpp 的不同量化等级，以及 FP8/INT8/INT4 等路线；视调研与硬件覆盖纳入 HQQ、AutoRound、AQLM 等新旧方法。每条路线都要完成模型转换或加载、必要的校准、推理验证与质量评估。
- **补齐其他压缩和训练期路线**：对剪枝、蒸馏、量化感知训练及 QLoRA 等方法说明它们改变模型、权重或训练方式的具体位置，并安排可复现实验或小模型练习；和推理期 PTQ 单独比较，不把名字相似但目标不同的方法混写。
- **实践推理加速而不只压缩权重**：比较 KV cache 管理/量化、连续批处理、分页注意力、前缀缓存、算子融合/低精度 kernel、CPU offload、张量并行和投机解码等。按旧显卡支持情况实测；不支持的路线说明硬件门槛并用可用设备或缩小实验做对照，不能声称旧卡能跑它。
- **适配推理引擎并部署服务**：根据旧卡能力选择 Transformers、llama.cpp、vLLM、SGLang 等方案；处理驱动、CUDA/ROCm、算子、模型格式、容器和服务接口的组合兼容问题。框架及版本支持情况须在写作时按官方文档核验。
- **压测、监控与故障演练**：用代表性请求测首 token 延迟、端到端延迟、吞吐、显存峰值、错误率和长稳表现；覆盖 OOM、进程退出、模型加载失败、限流、降级和回滚。
- **交付验收**：生成可重复部署配置、模型与环境清单、精度/性能对照报告、容量边界、运维手册和更新流程；以业务质量门槛与稳定性指标决定是否上线。

**一条主线如何逐阶段产出**：先固定原始模型和 FP16/BF16 基线，再确定量化目标与校准数据。量化阶段从同一个未量化 checkpoint 分别生成 GPTQ INT4、AWQ INT4、bitsandbytes NF4、GGUF Q4 等候选版本（具体组合以工具支持为准），在相同任务和旧 GPU 上比较后选一个进入主线；不把 GPTQ 后再 AWQ 这样的互斥量化方法串行套用。随后单独处理模型导出/封装格式，再在兼容的推理引擎中选择部署方案，最后叠加经实测兼容的 KV cache、批处理、缓存等运行优化，生成正式服务版本。量化算法、量化位宽、权重文件格式和推理后端分别记录，避免把 GGUF 这类格式误当作和 GPTQ 同一层级的算法。

**全路线对照与实战要求**：每个主要量化/加速类别都安排真实操作或可复现实验；在相同模型、提示集、上下文、并发和硬件条件下比较显存占用、模型/缓存大小、任务质量、困惑度或领域指标、首 token/生成延迟、吞吐、稳定性、转换成本和兼容范围。比较实验用于确定主线，不意味着多个候选版本都要进入最终生产系统。最终按“旧 GPU 型号 × 模型架构 × 量化格式/算法 × 推理框架”形成兼容矩阵和选型表，选定一个通过门槛的模型服务版本上线，并明确其他候选不入主线的原因。

**与现有书系的关系**：第六册讲部署与推理工程，第二十四册深入推理引擎，第二十三册讲 AI Infra。本册的主线是存量硬件上的模型选型、兼容、压缩、实测和上线验收；可以链接这些书的原理章节，不重复写完整推理引擎或平台工程教材。

**与第 25 册候选的关系**：本册构建模型推理与服务系统，优化模型如何在有限资源上运行；第 25 册构建后训练流水线，研究怎样通过训练改变模型能力。两册可以在综合项目中串联，但各自交付物和验收目标不同。

**灵感线索（用户提供，待核验）**：DeepSeek 摘录提到《大模型训练与推理加速实战》覆盖 CUDA 优化、TensorRT、量化裁剪和端侧推理。后续需核对书名、版本、目录、目标硬件与实践深度，再决定它能作为竞品参照还是参考资料；目前不把摘录当作已验证的书目事实。

## 第 27 册：从零构建工业级 Agent 应用系统——MCP、Agent 与 Harness

**教程定位**：面向需要把大模型接入真实业务流程的工程师，从一个有边界、可验收的业务任务出发，构建包含模型、工具、Agent 执行循环、Harness 控制层、MCP 接入、评估和运维能力的完整应用系统。重点是让系统可控、可追踪、可恢复并达到业务验收标准，而不是把 MCP、Agent、Harness 写成面试概念合集。

**最终动手项目**：以“企业 IT 工单处理 Agent”为贯穿案例：接收工单、检索知识库与资产信息、给出诊断和处理建议，并在权限允许或人工审批后执行受控操作、更新工单。交付可部署的端到端服务，包括模型与工具接入、任务状态管理、评估回放、监控告警和灰度/回滚方案；其他行业工作流可作为迁移练习。

**系统构建路线**：

- **业务任务建模**：梳理输入、预期结果、不可做的动作、外部依赖和人工接管点；将成功率、错误代价、时延、成本及需审批比例写成验收指标，建立不用 Agent 的基线。
- **模型与应用服务骨架**：实现模型网关、提示与策略版本管理、结构化输入输出、超时/重试/限流、密钥管理和多模型路由；区分模型本身的能力与应用层控制逻辑。
- **应用架构决策关**：对同一工单集用小型可复现实验比较直接模型调用、确定性工作流、单 Agent、多 Agent 等主架构；另把 RAG/知识检索作为可组合能力，分别测试是否加入不同架构。解释各自定义、复杂度和适用边界后，按业务门槛选定一个主架构及需要的组合，再把它扩展成贯穿全书的系统。
- **工具系统与协议实战**：实现原生 function/tool calling 和 MCP client/server 接入；实践工具 schema、发现与注册、参数校验、认证授权、错误语义、超时、重试和版本治理，并对比协议接入与直接集成的开发/治理成本。按范围纳入 A2A 等 Agent 间协作接口，说明它们的适用边界。
- **Agent 设计路线实战**：在已选定的主架构上，按需求加入规划与任务分解、ReAct/执行循环、状态和记忆、上下文管理、工具选择、结构化输出、长任务恢复。对单/多 Agent、顺序/并行/委派和不同记忆策略等互斥设计做小型对照，符合门槛才替换当前方案；不把它们全部叠加到主线。
- **Harness 与编排控制实战**：比较手写最小运行时与成熟框架/工作流引擎；把策略、工具白名单、权限、预算、重试/中止、幂等、状态持久化、输出约束、审批规则和任务恢复放入可测试的控制层。框架与版本按写作时官方资料确定，不让一本教程绑定单一框架接口。
- **权限、安全与韧性实战**：把读操作、可逆写操作和高风险动作分级，实践沙箱、最小权限、密钥管理、提示注入防护、人工确认、审计、故障隔离、限流和降级；记录每次工具调用的主体、参数、结果和副作用。
- **评估与回放**：建立任务集、工具调用轨迹、规则检查和人工抽检；覆盖成功率、工具选择、参数正确性、越权、安全、成本、时延、重试和恢复。支持对生产轨迹脱敏后回放，比较提示、模型和编排版本。
- **上线与运维**：补齐审计日志、指标、分布式追踪、告警、故障隔离、速率限制、数据保留策略、灰度发布、降级、回滚和事故演练；对工具故障、模型不可用、循环调用和部分完成设计恢复流程。
- **交付验收**：提供可运行的参考系统、部署配置、威胁与权限清单、任务评估报告、运维手册和演练记录；按业务质量、安全约束、成本和可用性共同决定是否上线。

**一条主线如何逐阶段产出**：从一个 IT 工单数据集和人工处理流程建基线；架构阶段讲清直接模型调用、确定性工作流、单 Agent、多 Agent 的定义和边界，用同一任务集做小型对照后选定适合本案例的主架构；再判断 RAG 等可组合能力是否带来足够收益。工具阶段比较原生 tool calling 与 MCP 的接入方式，选择一个作为主要集成路径；确有兼容需要时才保留适配器组合。再逐步加入与主架构兼容的记忆/状态、规划、Harness 约束、权限审批和运维能力，每阶段只把通过验收的版本送入下一阶段。单 Agent 与多 Agent 等互斥架构不作为连续工序叠加；其他实现保留为对照结果。最后完成安全评估、部署、灰度、监控、故障恢复和回滚演练，交付一套主线系统。

**全路线对照与实战要求**：对同一个样例、固定评测集和明确的业务门槛，实测直接调用、RAG、工作流、单 Agent、多 Agent、原生工具调用、MCP、不同记忆/规划和 Harness 策略。横向比较任务成功率、步骤数、工具错误与恢复率、越权率、人工接管率、时延、token/工具成本、可解释性、维护难度和业务适用范围。对照实验用于作阶段决策，最终只把选定并通过验收的主线版本接入生产部署；报告其他路线的差别、优势、缺点和未被选中的原因，不能只给一个“万能 Agent”实现，也不把所有候选架构堆进生产系统。

**与现有书系的关系**：第十七册讲 Agent 概念与模式，第二十册讲 Agent Harness 和 Runtime，第二十二册讲 MCP 等工具协议。本册要用这些内容构建一个带有业务数据源、权限流程、人工审批、验收指标和运行保障的垂直业务应用；不重复讲通用 Runtime 的内部实现或 MCP 协议本身。与现有书册的边界是否足以支撑独立成册，后续应以完整项目目录再核对。

**灵感线索（用户提供，待核验）**：DeepSeek 摘录提到《Harness Engineering实战》涉及 MCP 接入、Agent 循环、约束层和工具系统，也称招聘需求正向 Agent 应用落地发展。书名、目录和市场判断都需另行核实；它们目前只是检索线索，不作为选题成立或市场规模的证据。

**灵感定位**：把持续学习作为大模型训练的拓展，讲一个通用模型如何面对不断到来的新知识、新任务和变化的数据分布持续改善，同时尽量保住旧能力。它可以发生在模型部署前后，核心是连续学习与训练，不是发布运维。

**与现有书系的关系**：第五册提供通用训练原理，第七册提供评估方法，第八册涉及模型行为与安全，第九册负责数据工程，第十七册涉及 Agent 外部记忆。新书若成立，应系统讲清跨数据与任务序列的训练机制及能力保持问题；上线治理只作支撑内容。

- 图像质量、文本遵循、编辑一致性、安全、版权与来源标记等评估问题。
- 可复现的生成与编辑案例，比较任务目标和失败模式。

**与相邻候选的区别**：集中在图像，不把视频时间一致性或语音生成并入一本书；通用多模态表征与理解归第 32 册候选。现有第十五册已有图像生成内容，因此新增前需确认它是否具备独立的完整教学链。

**灵感来源**：Veo 与 Gemini Omni 的公开能力页面可以帮助识别媒体控制任务的颗粒度，但不能替代图像生成方法与质量评估资料：https://deepmind.google/models/veo/、https://deepmind.google/models/gemini-omni/。

## 第 34 册：视频生成与编辑模型

**灵感定位**：系统讲视频生成、视频编辑和时间一致性，面向需要理解视频模型训练、控制、评估与应用的读者。

**可以展开的内容**：

- 视频数据、时空表示、压缩和生成模型路线。
- 文生视频、图生视频、视频续写、局部编辑、参考视频驱动和风格变换。
- 镜头、主体、运动、首尾帧和长时序一致性的控制方法。
- 生成质量、运动合理性、提示遵循、身份保持和编辑成功率评估。
- 数据、训练、推理成本、产品控制和失败诊断。

**与相邻候选的区别**：本册侧重合成与编辑视频；涉及动作后果、规划、物理闭环的世界模型内容归第 28 册。视频生成不能仅靠一个任务矩阵或单章概览替代完整课程。

**灵感来源**：Veo（https://deepmind.google/models/veo/）和 Gemini Omni（https://deepmind.google/models/gemini-omni/）展示了公开的生成与编辑控制入口；它们只说明各自公开的产品能力。

## 第 35 册：语音与音频生成模型

**灵感定位**：从语音合成扩展到自然语音、音乐、环境声等音频生成，讲清表示、模型、控制、流式输出和评估。

**可以展开的内容**：

- 音频 codec/token、声学表示、文本与语音对齐及生成模型路线。
- TTS、语音转换、说话人和风格控制、音乐/环境音生成等任务边界。
- 分块生成、低延迟流式合成、韵律和长音频一致性。
- 语音自然度、可懂度、说话人保持、文本遵循、时间对齐和安全评估。
- 训练数据、推理系统、端到端示例和失败诊断。

**与相邻候选的区别**：聚焦生成侧的音频模型；实时双向语音交互和多模态输入输出协同更适合第 36 册候选。现有第十五册和第九册已有交叉内容，新增前需证明专门课程的深度和必要性。

## 第 36 册：Omni 原生多模态模型与实时交互

**灵感定位**：研究能够接收多种模态并生成文本、语音或媒体内容的统一模型系统，以及实时、流式或全双工交互方式。重点是输入、内部处理、输出和时间状态如何协同。

**可以展开的内容**：

- 按具体模型版本整理输入/输出模态、混合输入、流式能力和明确限制；“Omni”名称本身不是能力证明或统一架构。
- 多路媒体输入、时间戳和跨模态对齐；共享模块与专用模块的组织方式。
- 理解、推理、文本/语音/媒体生成及其联合训练和评估。
- 流式状态、首包延迟、打断、轮次切换、全双工和感知/生成并行。
- 端到端多模态交互案例，并拆分任务质量、时间对齐、延迟和系统成功率。

**与相邻候选的区别**：本册研究一体化多模态交互系统，不等于把所有图像、视频和音频生成算法再写一遍；与第 32 册的输入理解、第 33—35 册的单一媒体生成方向要有清楚边界。

**灵感来源**：GPT-4o System Card（https://cdn.openai.com/gpt-4o-system-card.pdf）、Qwen3-Omni Technical Report（https://arxiv.org/abs/2509.17765）、Qwen3.5-Omni Technical Report（https://arxiv.org/abs/2604.15804v2）、Qwen3-Omni 官方仓库（https://github.com/QwenLM/Qwen3-Omni）、Gemini Omni Flash Model Card（https://deepmind.google/models/model-cards/gemini-omni-flash/）。这些来源各自说明特定版本的公开能力，不能由产品名称推断统一能力或内部架构。
