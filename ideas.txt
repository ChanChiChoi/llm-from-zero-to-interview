2026-10-27｜书系完整性与分册负载审计：LLM 缺口、扩册与拆册候选

范围：对照 24 册简介、目录、BOOK_SERIES.md、ROADMAP.md，并用全文关键词检索抽查持续学习、模型融合、扩散语言模型、多语言、联邦学习和 VLA。属于书系级目录盘点，不代表逐篇正文质量审计；本条只记想法，不表示已决定增章或改目录。执行时点：当前正在做全书精修；本审计供精修完成后的第二轮结构调整使用，不触发本轮逐章扩写或拆章。

覆盖深度判定口径：大知识点不能因为目录出现术语、某章举过例子或某节有介绍，就计为“已覆盖”。逐项标成三档：①系统主线：有连续的章节组和清楚学习目标，覆盖核心概念/表示、主要方法与数据、训练或系统链路、评估与失败边界，并能串成读者可跟进的学习路径；②实质性局部：有成体系的一章或章节的一部分，但缺少方向所需的完整链路，记为“部分覆盖/入口”；③提及/接口：仅术语、案例或边界说明，只记作导航，不记作领域覆盖。单章可以承载边界清楚的小主题；对世界模型、视频生成等大型方向，不能把单章默认视为系统覆盖。拆分时也不能把多个大方向简单装进一本新书，必须分别验证定位、简介、目录和学习主线是否成立。

第二轮结构审视顺序：等当前全书精修完成后，再按“本册定位 → 简介 → 目录 → 全册大纲 → 各大章内部知识链”的顺序做架构复审；先标出每个大知识点由哪一组章节承担及其覆盖深度，再决定调序、拆章、补章或独立成册。对大型方向先分别形成定位、简介和目录草案，再比较边界与读者路径；联网用于发现现有目录之外的新方向和更新证据，不用搜索到的术语直接替代结构设计。此顺序是第二轮修改的规划，不打断当前正在进行的精修。

总判断：现有 24 册已为 LLM 学习与工程的主要主干提供册级入口，但还不能据此断言每个大方向都系统覆盖；后续需要按上面的深度档位复核，尤其不能把单章入口当成完整领域。册与册体量不均，第二十一至第二十四册需要拆分、瘦身或重新划界。新增/拆分候选包括：具身智能/物理世界基础模型（最明确的相邻领域专题）、部署后持续学习/模型演进（条件性新册），以及第十五册内部多模态理解与生成式媒体的结构重组（是否再拆成一册或多册待各自大纲验证）。AI for Science 属于更外层的应用研究扩展。下文是简介/目录层面的宏观审计，不代替逐篇正文审读。

目录中可找到的主干入口（不应误报为“完全空白”，也不应直接当成完整覆盖）：Transformer 与替代架构；数据、预训练、SFT/RL/蒸馏；推理优化与推理扩展；RAG 与长上下文；Agent、Harness、工具协议；评测与实验；安全、可解释性、隐私和治理；图像/视频/语音多模态；Serving 与基础设施。每项仍需按覆盖深度口径复核，后续标出唯一主讲册、章节组和只作接口的册。

待考虑的板块，按“书系中缺少完整主线”的程度排序：

1. 【高优先级｜参数层面的持续学习与模型生命周期更新】现有第五册提到持续预训练/领域适配的学习率安排，第五册领域适配部分引用持续学习综述；第十七册 Memory 章明确聚焦外部记忆，不讲把知识写回模型参数。缺少从部署后新数据/反馈进入持续预训练、持续微调或持续对齐，再到遗忘/迁移评估、安全回归、版本发布和回滚的完整链条。应明确区分参数更新、test-time training、外部记忆和 RAG；不能把“Agent 有 Memory”当作模型持续学习已覆盖。轻量补缺可由第五册新增章节组，连接第九册数据版本、第七册回归评测、第八册安全、第十七册外部记忆和第二十三册发布平台；若要把部署后模型演进、在线/测试时适应、合并、评估门禁和发布治理都讲完整，则应评估独立成册，避免把第五册从训练全流程扩成所有模型生命周期。近期综述把持续预训练、持续微调、持续对齐及遗忘/迁移评估列为仍在发展的研究方向；其中 2026 arXiv survey 是预印本，不能当作成熟工业配方。

2. 【中高优先级｜非自回归/离散扩散语言模型】第十五册有图像、视频扩散；第二十一册一处前沿模型材料引用离散扩散加速论文，但目前没有系统讲文本扩散模型的噪声过程、训练目标、并行去噪生成、采样、与自回归模型的质量/延迟比较及 Serving 约束。它是架构和生成范式的候选补缺，优先作为第二册架构/生成范式中的一讲或第二十一册中的专题章，并由第二十四册承接 Serving；文本扩散虽与图像扩散共享部分数学工具，训练目标和解码接口不同，不宜为了“都有 diffusion”而整块并入第十五册。当前材料尚不足以支撑独立成册。

3. 【中优先级｜模型融合/合并与能力组合】当前训练目录讲 SFT、偏好优化、RLVR、蒸馏等，但全文关键词未找到模型合并/融合的系统主线。候选内容包括 checkpoint/adapter 合并、任务向量、参数/表示/行为层融合、专家能力组合、冲突与遗忘评估及安全回归。可放第五册（训练后的模型组合与验证）或第二十一册（模型形态与组合路线），不要与知识蒸馏、MoE 路由或模型编辑混为一谈。ACL Findings 2026 已有统一模型融合分类综述，说明可作为专题候选；单独不足以支撑新册，若后续建立“持续学习与模型演进”专题，可把模型合并作为其中一种能力组合方法。

4. 【中优先级｜多语言、低资源语言与 code-switching 的端到端路径】这不是“完全没有”：第五册覆盖 tokenizer 语言差异，第九册深入多语言数据配比，第七册和第八册涉及多语言评测/安全。但目前缺少把 tokenization、公平 token 成本、数据混合、跨语言迁移与微调、代码切换、judge 偏差、安全覆盖连起来的统一案例或阅读路径。建议先做跨册主线/综合案例，不急着新开一册。ACL 2026 的 code-switching survey 汇总 327 项研究、80 多种语言，并指出数据和评估仍有问题；ACL 2025 的多语言 judge 研究也发现低资源语言的一致性更弱。

5. 【条件性扩展｜VLA、机器人和具身基础模型】第十五册第八章介绍了 world model、动作条件和机器人/自动驾驶关系，并讨论 V-JEPA 2；按本审计口径，这些是重要入口，不构成具身方向的系统覆盖。缺少 VLA 动作表示/动作块、机器人轨迹与人类演示数据、策略训练、闭环控制、仿真到现实迁移、具身评估和真实环境安全的连续章节链路。若只需导航，可在第十五册保留边界说明；若要系统覆盖 VLA、机器人策略、物理世界模型、仿真闭环和自主驾驶，应按独立专题规划完整定位和大纲，而不是继续扩宽第十五册。GR00T N1、SmolVLA 等论文是当前代表实例，实验结论仍限于论文任务、机器人和数据设置。

   与 LLM 的关系校准：VLA/具身模型常把视觉、语言理解和动作预测放进同一个基础模型系统，因此会复用 Transformer、VLM/LLM 预训练、指令微调、RL、推理和评估等技术；它们属于与 LLM 相邻的多模态/物理 AI 方向。自动驾驶是可应用 VLA 和世界模型的领域，不等于 LLM。自动巡航/自适应巡航更窄，主要是纵向车速与跟车距离控制，通常归在驾驶辅助/控制系统；其中可以使用机器学习，但并不要求 LLM。世界模型也不是 LLM 的同义词：它可能是语言模型内部的状态预测能力、独立的视频/动力学模型，或与 VLA 配合的未来模拟器。只有讨论“语言/视觉语言基础模型怎样感知、预测、规划并输出动作”时，这几项才进入 LLM 书系的边界。

6. 【专项方向｜联邦/隐私保护的大模型训练与协作】第八册覆盖隐私风险和差分隐私，第九册覆盖数据治理，第二十三册覆盖分布式训练基础设施；但这些不等于跨数据所有者的联邦微调/聚合、通信成本、非 IID 数据、客户端安全与隐私泄漏评估。属于医疗、金融、企业数据不能集中场景下的重要专项，主线优先级低于上面几项；可先由第五册或第二十三册加专题节，并链接第八册隐私内容。IEEE 2025 survey 将其作为覆盖预训练到微调的独立方向，但不意味着它是通用 LLM 岗位必修主干。

7. 【范围依赖｜科学与专业领域模型】第九册已有医学、法律、科学等领域数据，第五册有领域 SFT/RL，第十八册讨论业务落地；若目标从通用 LLM 扩展到“科学基础模型/专业工作流”，还缺科研工作流、工具验证、实验闭环和领域评测的系统专题。这属于应用领域扩展，不建议仅为百科式完整而纳入核心书系；只有决定把书系扩成“LLM 与科学智能”时，才值得规划独立的 AI for Science / Scientific Agents 专题册。

书系结构风险：更普遍的问题可能不是册数少，而是“同一主题每册都讲一点，却没有唯一主讲位置”。需要后续用主讲册/前置册/交接册关系整理几组边界：第一/二/四/二十一册的架构深度；第五/第九册的训练与数据；第六/第二十四/第二十三册的部署、引擎和平台；第十七/第二十/第二十二册的 Agent、Runtime 和协议；第十五/第十六/第二十一册的多模态、推理和前沿模型案例。目录盘点阶段先记录，不据此推定这些内容必须合并。

会议/期刊扫描对现有结构的具体影响：
1. **具身智能独立专题的理由增强**：NeurIPS、ICLR 和期刊专题都把世界模型、机器人/物理交互、闭环控制或部署系统放在同一问题空间；这不意味着它变成 LLM 核心内容，但说明它值得作为单独相邻专题册规划，而不是继续扩张第十五册。
2. **持续学习候选应明确包含 Agent 的环境适应，但区分适应机制**：Post-training in Changing Environments、test-time continual learning 与 enterprise continual agents 是相邻而非同义主题。章纲需要区分模型参数更新、test-time learning、外部/长期记忆、策略或工具适应，以及它们各自的遗忘和安全回归验证。
3. **Agent 评估存在一个适合补接口的节点，不必新开一册**：NeurIPS 的 Grounded User Simulation 与 Interactive Agents Evaluation 提醒我们，评测时不仅要测 Agent，也要审查模拟用户/环境是否有足够的多样性、真实性和效度。当前第七册已通过 τ-bench 等内容使用模拟用户，第十七册也讨论 AgentWorld；可以考虑补一张“环境/用户模拟器自身的验证”对照表或阅读路径，避免把模拟器当作无误差的真值。
4. **实时多模态交互先做跨册主线**：NeurIPS 的实时多模态对话主题与书内第十五册实时语音评估、第二十一册流式多模态案例、第二十四册流式 Serving 已有交集。更可能需要的是把首包延迟、轮次切换、打断、全双工、感知/生成并行和任务成功串成端到端案例；是否新增章先看现有正文是否已经把这些接口讲完整，不单凭 workshop 题目增章。
5. **AI for Science 信号变强，但仍属于书系边界选择**：分子科学 Agent、科学实验强化学习和 AI for Meta-Science 把“领域模型”推进到可调用工具、执行实验和组织研究流程。若纳入，应规划科研 Agent 与实验闭环的独立专题，不要把几篇 science-agent 论文散插进通用训练册。

后续选题扫描建议：先看 NeurIPS/ICLR/ICML/ACL 等会议的 CFP、已录用 workshop 名单、tutorial、position paper、benchmark/competition track 和正式论文；再看相关期刊的 special issue / research topic CFP。先将跨 venue 重复出现的主题记为候选信号，再用代表论文、系统报告、代码和评测复核其技术内容、成熟度与书系落点。单个 workshop 或期刊专题只能启发选题；只有多届持续出现、多个独立团队有实证、且与本书定位形成明确接口的方向，才考虑进入核心目录或独立成册。

#### Omni 原生多模态模型与实时交互：有多章材料，需审视串联

“Omni”常被模型名或产品名使用，但它不是一张固定的输入/输出能力证书，也不说明内部必然采用同一类架构。关键要查具体模型版本能接收哪些模态、是否能混合输入、输出哪些模态，以及输出是否流式、同步或全双工。官方资料展示的能力契约已经不同：

| 例子与原始资料 | 输入侧声明 | 输出侧声明 | 书系审视时的区分 |
|---|---|---|---|

### 四、当前建议的书系结构决策

1. **不为扩册而扩册。** 现有 24 册已覆盖从基础、模型、数据、训练、推理、评估、安全、多模态到 Agent 和部署的主路线入口；是否足以支撑每个大方向的深度学习，需在第二轮按章节组复核。
2. **先拆第二十一册的稳定教材与滚动模型档案。** 这是当前最明确的“内容多到破坏一本书定位”的问题；增加新技术章节无法修复这个结构问题。
3. **第二十二、二十三、二十四册先做职责去重和部分重排，再决定是否拆成独立册。** 它们目前更像三个相邻层级（协议/平台/引擎）同时过度展开，先明确所有权，避免拆册后仍然重复。
4. **第八册先分层，不预设马上加安全新册。** 先将模型对齐/安全研究与 Agent/工具/运行时安全的内容分开，再衡量系统安全是否形成独立课程。
5. **如扩展到 LLM 相邻领域，优先规划具身智能与物理世界基础模型专题册；持续学习/模型演进列为第二候选。** AI for Science 是独立的领域线选择；当前不应与前两者一并自动扩册。
6. **第十五册进行整册结构重审，不能把“提到”算“完善”。** 先分别为多模态理解、图像生成与编辑、视频生成与编辑、语音/音频生成、Omni 原生交互写定位、简介和目录，再判断如何组合或分册；T2I/I2I/T2V/I2V/V2V 矩阵只作索引，Omni 也不能当作统一能力标签。各方向都需核查其章节组是否形成足够的概念、数据/方法、训练或系统、评估和实作链路。World model 的动作预测、规划和物理闭环也需章节组，不能由第十五册一个混合章节代表。
