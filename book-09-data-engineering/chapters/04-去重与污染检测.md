# 第四章 去重与污染检测：让训练和评估各自保持可信

上一章讨论了样本是否可读、是否有价值以及是否带有隐私和安全风险。本章处理两个容易被混为一谈的问题：训练数据内部是否有不合理的重复，以及训练数据是否已经看到了评估集的题目、答案或近似变体。

重复和污染都表现为“相似文本”，但责任不同。训练集内部的重复会浪费 token、放大某些来源、提高记忆风险并改变 data mixture；训练集与评估集的重叠会削弱 benchmark 的解释力，让分数看起来像泛化能力。前者的主要动作是去重、聚类、降权和保留代表样本，后者的主要动作是隔离、改换评估集、降低结论等级和在报告中披露。

本章从一个数据对象的生命周期开始，逐层讲清 exact dedup、段落和子串重复、近重复、MinHash/LSH、SimHash、embedding 相似、代码 fork、benchmark contamination、时间切分、私有 holdout 和合成 canary。最后用一个只含合成内容的审计 demo，把训练集内部簇、评估命中、canary 命中、保留量和后续动作分开输出。

## 4.1 两类相似：重复与污染不是同一个问题

### 4.1.1 小白视角：复印资料和提前看到试卷

假设你准备考试。复习资料中有十份同一篇文章的复印件，这是馆藏内部重复；复习资料中出现了考试题和答案，这是评估污染。两者都可能让你“读过很多页”，但处理方法不同：复印件可以保留质量最高的一份，试卷内容则应该从复习资料中隔离，并检查考试分数是否仍然可信。

模型数据也一样：

1. 同一网页换了 URL，是内容重复问题。
2. 同一文章加了广告和页脚，是近重复问题。
3. 同一代码仓库被 fork 多次，是结构化代码重复问题。
4. benchmark 题目被博客转载，是训练-评估重叠问题。
5. 评估答案出现在题解中，即使题目表面没有完全匹配，也可能污染评估。

### 4.1.2 专家视角：两个集合和两个目标

设训练候选为 `D_train`，评估集合为 `E`。训练内部去重研究的是：

~~~math
pair(d_i, d_j),  d_i, d_j in D_train.
~~~

污染检测研究的是：

~~~math
pair(e_j, d_i),  e_j in E, d_i in D_train.
~~~

它们可以使用相似度工具，但阈值、分母、人工协议和后续动作不能混用。去重报告可以说“训练候选中有多少文档被聚成近重复簇”；污染报告要说“评估样本中有多少被检出重叠、重叠的是题目还是答案、证据强度如何”。

## 4.2 为什么重复会改变模型行为

### 4.2.1 重复不是无害的存储浪费

训练集的 token 数常被当作数据规模，但重复 token 的信息增量远低于独立 token。重复会产生几种后果：

1. 训练计算反复花在同一模式上。
2. 某个网站、作者、模板或观点获得过高隐含权重。
3. 罕见文本更容易被模型记住并原样复述。
4. 去重前后语言、领域和来源比例发生变化。
5. train-test overlap 让验证结果失去独立性。

重复不一定总是坏的。标准数学定义、常用 API 和安全边界需要一定曝光量，完全删除相似表达会损失泛化。因此目标不是集合意义上的“每个字符串只出现一次”，而是控制不合理的频率和来源放大。

### 4.2.2 数据分布的频率视角

如果来源 `s` 在去重前有 `d_s` 个 token，训练候选总量为 `D`，其原始比例是：

~~~math
p_s = d_s / D.
~~~

当该来源有大量转载和镜像时，`p_s` 可能远高于它在真实知识分布中的合理权重。去重后比例变为 `p_s'`，即使模型架构和训练步数不变，实际经验分布也已经变化。去重因此必须和 data mixture 一起报告。

## 4.3 去重层次：从完全相同到语义相似

### 4.3.1 exact dedup

对规范化后的文档计算 hash，相同 hash 的样本属于完全重复候选。它适合发现重复下载、镜像页面、同一文件多份拷贝和相同版本的训练 shard。

常见规范化包括统一换行、合并空白、Unicode 规范化、去除明确的 HTML 残留和保留原文与规范化版本的双份证据。是否统一大小写、标点和代码格式，要按数据类型决定。

exact dedup 的优点是快、便宜、可解释；缺点是无法发现只改了标题、页脚、广告、空格或少量词语的内容。它是第一层证据，不是完整去重结论。

### 4.3.2 文档、段落和子串

去重粒度决定误删风险：

1. 文档级去重适合整页镜像和重复文件，但会把一个页脚差异视为不同文档。
2. 段落级去重适合模板、免责声明和转载片段，但直接删除段落可能破坏上下文。
3. 子串级去重适合查找重复数万次的固定句子、题目和敏感片段，但索引和存储成本更高。

段落和子串重复可以先作为质量和采样信号。只有当重复来源明确、上下文替代关系清楚时，才适合直接删除。

### 4.3.3 near dedup

近重复包括轻微改写、转载、翻译、插入广告、OCR 差异、代码 fork 和格式变换。它要回答的不是“两个文本是否相似”，而是“相似程度是否已经使第二份样本的边际训练价值很低”。

常用相似度包括字符或 token n-gram、Jaccard、编辑距离、MinHash 签名、SimHash 汉明距离和 embedding cosine。不同方法观察的是不同层次，不能把一个阈值在所有数据类型上复用。

## 4.4 规范化和 exact hash

### 4.4.1 为什么原文 hash 不够

同一篇文章可能因为换行、HTML 实体、空格、编码和广告字段不同而得到不同 hash；如果规范化过度，又可能把不同语言版本、不同查询结果或不同代码配置错误合并。

因此应保留：

1. 原始载体 hash。
2. 规范化文本 hash。
3. 规范化函数和版本。
4. 原始 URL、规范化 URL 和取得时间。
5. 内容长度、语言、领域和解析器版本。

### 4.4.2 exact 重复率

设候选文档总数为 `N`，规范化 hash 的第 `k` 个桶大小为 `n_k`，文档口径的 exact 删除率为：

~~~math
R_exact = sum_k(max(n_k - 1, 0)) / N.
~~~

如果按 token 计算，则应把每个被删除副本的 token 加总，而不能拿文档比例代替 token 比例。报告中要明确分母和保留哪一份的规则。

### 4.4.3 保留代表样本

一个重复簇中可以按质量分、来源可信度、解析完整性、许可证范围、时间和语言版本选择代表样本。不要简单保留遇到的第一份，因为它可能是转载、解析损坏或许可状态不清的副本。

代表样本选择也要保留 cluster ID 和被移除成员的 provenance，否则后续无法解释数据量下降和删除请求传播。

## 4.5 Jaccard 和 shingle：近重复的可解释基础

把文档切成 token 或字符 shingles，得到集合 `S_i`。两个文档的 Jaccard 相似度是：

~~~math
J(i, j) = |S_i intersect S_j| / |S_i union S_j|.
~~~

如果两个文档完全相同，Jaccard 接近 1；如果共享的 n-gram 很少，值就低。shingle 大小越小，对局部改动越宽容，但也更容易把主题相近的短文本误判为重复；shingle 大小越大，对改写越敏感，但可能漏掉复制片段。

短文本特别容易出现相似度虚高：两个问题都包含“什么是 Transformer”，并不代表它们只应保留一个。短样本要结合长度、意图、答案和领域处理。

## 4.6 MinHash：把大规模集合比较变成候选检索

### 4.6.1 它解决的计算问题

如果有十亿篇文档，逐对计算 Jaccard 不可行。MinHash 为每个 shingle 集合生成紧凑签名，使相似文本更可能拥有相同的签名位置；LSH 再用这些签名召回候选。

工程流程通常是：

1. 按语言和类型规范化。
2. 生成字符或 token shingles。
3. 计算多个 MinHash 分量。
4. 用 LSH band 把可能相似的样本放进候选桶。
5. 对候选对计算精确 Jaccard 或其他相似度。
6. 按阈值和人工协议建簇。

### 4.6.2 MinHash 的概率性质

对集合 `A`、`B` 和一个随机排列 `pi`，MinHash 的基本性质是：

~~~math
P(minhash_pi(A) = minhash_pi(B)) = J(A, B).
~~~

用 `K` 个独立或近似独立的签名分量，可以用相等比例估计 Jaccard：

~~~math
J_hat(A, B) = (1 / K) * sum_k I(sig_k(A) = sig_k(B)).
~~~

这不是“相似度必然准确”的保证。hash 函数、shingle 大小、签名长度、短文本和多语言切分都会影响误差。

### 4.6.3 LSH 的候选概率

若签名被分为 `b` 个 band，每个 band 有 `r` 行，真实相似度为 `s` 时被至少一个 band 召回的概率可近似写成：

~~~math
P_candidate(s) = 1 - (1 - s^r)^b.
~~~

band 太宽会产生过多候选，band 太窄会漏掉相似样本。LSH 只是候选召回器，最终判定仍要回到精确相似度、来源和人工抽样。

## 4.7 SimHash：快速筛选相似指纹

SimHash 把文本特征映射为固定长度二进制指纹，相似文本通常具有较小的汉明距离。它适合快速发现网页近重复和模板变化，但其效果依赖 token 特征、权重、位数和阈值。

设每个 bit 的加权投票为 `v_b`，指纹位为：

~~~math
z_b = I(v_b >= 0).
~~~

两个指纹的汉明距离是：

~~~math
H(a, b) = sum_k I(z_k(a) != z_k(b)).
~~~

SimHash 的优点是指纹短、计算快、索引简单；缺点是对短文本、语义改写和特征选择敏感。它可以与 MinHash 并行，用一个方法扩大召回，再用另一个方法和人工审计减少误合并。

## 4.8 embedding 相似：发现语义近邻，但不要直接删除

embedding 检索能够找到字面不同但语义相近的文本，例如改写后的 FAQ、同一道题的不同表述和同一功能的代码说明。这对污染候选发现、聚类和人工审计很有价值。

但语义相似不等于训练冗余：

1. 同一主题的两篇文章可能提供不同事实和细节。
2. 数学题方法相似，数值和推理步骤可能不同。
3. 法律解释的适用条件可能不同。
4. 多个用户问法相似，有助于指令泛化。
5. 不同语言的平行表达可能是多语言能力所需的信号。

embedding 去重应记录模型版本、距离、阈值、语言和人工判断。更安全的默认动作是聚类、降权或抽样，而不是根据一个向量距离直接删除所有近邻。

## 4.9 去重后的频率控制和 data mixture

去重改变的不只是数据量，还包括各来源和领域的相对权重。假设来源 `s` 的有效 token 从 `d_s` 变为 `d_s'`，去重后比例为：

~~~math
p_s' = d_s' / sum_j(d_j').
~~~

新闻转载、代码 fork、题库模板和百科镜像的重复率不同，去重后它们的相对比例会重新排序。每个数据版本都要报告：

1. raw、parsed、deduped 和 sampled token。
2. 语言、领域、来源和时间比例。
3. 每个重复簇的大小分布。
4. 代表样本选择规则。
5. 被删除副本的质量和许可状态。

有价值的标准表述可以保留一定 exposure；低质量模板、隐私复制和 benchmark 复制需要更严格处理。去重系统是频率控制器，而不是唯一性追求者。

## 4.10 代码数据：fork、vendor 和生成文件

代码的重复关系比普通文本更复杂：同一实现可以出现在原仓库、fork、vendor 目录、依赖镜像、教程和题解中。文件级 hash 只能发现完全复制，函数级 token 或 AST 相似度可以发现改名和轻微重排。

代码去重应分层处理：

1. 自动生成文件和构建产物通常优先移除。
2. vendor 和第三方依赖要结合许可证与用途处理。
3. fork 仓库应保留来源、commit 和差异，而不是把所有 fork 当成同一份。
4. 常见 API 模式不应因为相似就全部删除。
5. 题库、测试答案、函数签名和 benchmark 代码需要单独做污染检测。

代码重复的保留策略要与目标能力绑定。代码补全需要常见 API exposure，coding agent 还需要仓库结构、依赖和测试；一个只有函数字符串的 dedup 结果不能代表仓库级训练价值。

## 4.11 Benchmark contamination：评估为何会失真

### 4.11.1 污染的形态

公开 benchmark 可能被论文、博客、课程、题解、GitHub 和论坛复制。训练集与评估集的重叠包括：

1. 题目原文重叠。
2. 选项、答案或解析重叠。
3. 题目轻微改写、翻译或格式转换。
4. 评估代码、函数签名、测试样例和参考实现重叠。
5. benchmark 讨论中的隐藏答案或解题模板重叠。

题目原文不匹配不代表没有污染。对生成模型来说，答案、解析和固定模板可能比题干更直接地提供了得分路径。

### 4.11.2 污染的结果如何影响结论

污染会让分数混合了泛化、记忆、提示模板熟悉度和答案复现。它不一定意味着模型每次都能直接输出答案，但会降低“独立测试”的解释力。

因此评估报告应记录评估集版本、公开时间、训练数据时间窗口、相似度方法、阈值、人工复核、污染候选数量和最终结论等级。不要在发现污染后只删除命中数字，应该重新评估或明确不确定性。

## 4.12 污染检测：从 query 到证据

把每个评估样本作为 query，在训练候选中检索：

1. exact hash 和规范化文本。
2. n-gram overlap 和长公共片段。
3. MinHash/LSH 近重复。
4. embedding 或 BM25 语义候选。
5. 答案、选项、解析和代码测试的单独匹配。
6. 时间和来源证据。
7. 人工对候选关系进行分级。

评估样本 `e_j` 对训练集合的最大相似度可以写成：

~~~math
c_j = max_i sim(e_j, d_i).
~~~

若有 `M` 个评估样本，阈值 `tau` 下的污染候选率是：

~~~math
R_contam(tau) = (1 / M) * sum_j I(c_j >= tau).
~~~

这个指标只表示候选命中，不表示所有命中都已人工确认。应再报告确认率、答案泄漏率、严重度和未覆盖的污染路径。

### 4.12.1 训练集内部去重与污染检测分离

同一个训练集可以内部高度去重，却包含某个 benchmark；也可以内部重复很多，却没有污染某个私有评估集。系统要分别维护 `train_dedup_version` 和 `eval_overlap_version`，让数据和评估报告能独立回放。

## 4.13 时间切分、私有 holdout 和公开 benchmark

训练数据早于 benchmark 发布日期可以降低直接泄漏的可能，但不是独立性证明：题目可能提前出现在教材、预发布稿、题库或相似问题中。训练数据晚于评估发布则需要更严格的污染检查和结论披露。

私有 holdout 可以减少公开复制，但它也需要访问控制、调参隔离、judge 隔离和反馈链路审计。一个没有公开的评估集，如果结果被反复用于选模型，仍可能通过反馈间接成为训练信号。

长期运行的 benchmark 应记录：

1. 题目和答案版本。
2. 谁访问过原始内容。
3. 哪些结果用于调参或 prompt 修改。
4. 哪些训练快照已经做过污染检查。
5. 题目何时退役或替换。

## 4.14 Canary：受控记忆风险探针

canary 是插入或标记的特殊合成字符串，用来测量模型是否更容易复现罕见序列。它不应使用真实用户隐私、真实凭证或可复用攻击内容。

一个安全的 canary 实验要固定：

1. 合成字符串的生成方式。
2. 出现次数和上下文。
3. 训练阶段和数据版本。
4. 查询模板、采样温度和尝试次数。
5. 精确复现、部分复现和近似复现的判定。

若进行 `N_trial` 次受控查询，精确复现次数为 `N_hit`，可以报告：

~~~math
R_canary = N_hit / N_trial.
~~~

这个比率只描述当前模型、提示、解码和探针条件下的风险信号，不代表真实用户数据的总体泄露率。canary 应用于比较去重、隐私训练和输出防护前后的变化，而不是用来复原真实训练内容。

## 4.15 去重、记忆与隐私的边界

重复会增加罕见文本被模型记住的机会，但记忆还受到模型容量、训练轮数、采样策略、文本长度、熵、后训练和推理提示影响。去重可以降低风险，却不能替代 PII/秘密检测、隐私评估、访问控制、输出监控和删除流程。

尤其要区分：

1. 从训练候选中删除一个重复副本。
2. 从 RAG 索引删除一份文档。
3. 限制模型输出某类字符串。
4. 证明模型权重已经忘记某段内容。

这些动作作用于不同层，不能互相替代。

## 4.16 去重系统的工程架构

一个持续运行的系统可以包括：

1. 规范化和 tokenizer 版本服务。
2. 文档、段落和子串 hash。
3. MinHash/SimHash 签名生成。
4. LSH 或近邻索引。
5. 候选对精确相似度服务。
6. cluster/连通分量构造。
7. 代表样本选择和 provenance。
8. benchmark query 检索和答案泄漏分析。
9. canary/记忆风险评估服务。
10. 人工审计、申诉和阈值校准。
11. 数据版本、训练 manifest 和评估报告关联。

每个服务都要记录输入版本、参数、输出、失败和处理时间。近重复候选不是最终删除证据；污染候选也不是自动判定模型分数无效，二者都需要审计状态。

## 4.17 阈值和审计：控制误合并与漏检

### 4.17.1 近重复的两种错误

把本来有独立价值的文档合并，是 false merge；放过本应合并的重复，是 false separate。对候选对集合 `A`，人工标签 `y_ij` 为 1 表示应该合并，系统决策 `m_ij` 为 1 表示合并，可以写成：

~~~math
R_merge_fp = count(y = 0 and m = 1) / count(y = 0).
~~~

~~~math
R_merge_fn = count(y = 1 and m = 0) / count(y = 1).
~~~

在代码、数学、低资源语言和短文本上分别估计这两个错误。整体平均值可能掩盖一个切片已经不可用。

### 4.17.2 候选对分层抽样

按 Jaccard、SimHash 距离、embedding 距离、长度、语言、领域和来源分桶抽样，人工标注“同一内容”“高重复但有独立价值”“主题相似”“无关”。这比只看阈值附近的少数样本更能发现系统偏差。

### 4.17.3 污染证据等级

可以把污染候选分为：

1. 强证据：题目和答案/解析 exact 或高置信近重复。
2. 中证据：题目改写、固定结构和关键实体高度重叠。
3. 弱证据：主题或方法相似，但无法证明来自同一评估样本。

强证据可以触发隔离或评估替换；中证据需要人工和多方法交叉；弱证据适合记录为不确定性，不应直接宣布 benchmark 无效。

## 4.18 工程案例：公开题解污染了新模型评估

### 4.18.1 现象

一个数学模型在公开 benchmark 上得分大幅提高，但私有新题和改写题提升很小。训练数据审计发现，benchmark 题目和一批公开题解出现在网页语料中。

### 4.18.2 排查

团队先对评估集做 exact、n-gram、MinHash 和答案检索，发现部分题目没有原文匹配，但答案数值、固定解题模板和题目实体组合高度相似。仅查题干会低估污染范围。

随后记录每个命中：训练来源、数据版本、发布时间、相似度方法、题目/答案/解析字段、人工等级和是否进入训练 shard。

### 4.18.3 处置

1. 将强证据样本从训练数据和后续训练 manifest 中隔离。
2. 对已训练模型重新评估私有 holdout、改写题和时间后数据。
3. 在报告中区分原始分数和污染敏感分数。
4. 修正数据构建的 benchmark quarantine 列表和版本流程。
5. 用 canary 和成员/复现风险实验检查去重是否降低了记忆信号。

### 4.18.4 教训

公开评测的高分不是孤立事实。数据血缘、发布时间、答案泄漏和评估独立性共同决定分数的解释范围。发现污染后，重新测量比争论一个“是否算泄漏”的标签更重要。

## 4.19 可运行的合成去重与污染审计示例

下面的 demo 只使用合成文档、合成评估题和一个合成 canary。它实现规范化、exact hash、shingle Jaccard、简化 MinHash、SimHash、重复簇、代表样本、评估污染和 canary 命中，并输出 `signals/actions/decision`。它不是生产级分布式去重服务，也没有读取真实网页或评估集。

~~~python
from __future__ import annotations

import hashlib
import re
from collections import defaultdict
from itertools import combinations


train_docs = [
    {
        "id": "attention_blog",
        "domain": "web_ml",
        "quality": 0.92,
        "text": "Scaled dot product attention compares query and key vectors. It normalizes scores with softmax and uses value vectors to build contextual representations for transformer language models.",

    {

        "quality": 0.61,

    },
    {
        "id": "attention_blog_near",
        "domain": "web_ml",
        "quality": 0.85,
        "text": "Scaled dot product attention compares query and key vectors, normalizes scores with softmax, and uses value vectors to build contextual representations for transformer models. This mirrored article adds a footer.",
    },
    {
        "id": "python_code",
        "domain": "code",
        "quality": 0.88,

    },
    {
        "id": "python_code_fork",
        "domain": "code",
        "quality": 0.70,
        "text": "def load_config(file_path): read yaml settings, validate required keys, raise ValueError for missing fields, then return normalized configuration dictionary for tests.",

    {

    },

        "domain": "eval",

    },
    {
        "id": "canary_note",
        "domain": "privacy",
        "quality": 0.30,
        "text": "Synthetic canary QXZ-9142-LMN appears in a controlled memorization test log and must be quarantined from normal training data.",
    },
    {
        "id": "zh_data_note",
        "domain": "zh_web",
        "quality": 0.86,
        "text": "去重系统需要记录来源、规范化文本、哈希、近重复簇、保留样本、污染命中和版本审计结果。",
    },
]

eval_items = [
    {
        "id": "gsm_toy",
        "text": "Alice has 3 apples and buys 4 more apples. What is the correct answer?",
        "answer": "7",
    },
    {
        "id": "attention_eval",
        "text": "Explain scaled dot product attention and why softmax is applied to key scores.",
        "answer": "softmax",
    },
]

CANARIES = {"QXZ-9142-LMN"}


def tokens(text: str) -> list[str]:
    return re.findall(r"[A-Za-z0-9_]+|[\u4e00-\u9fff]", text.lower())


def normalize(text: str) -> str:
    return " ".join(tokens(text))


def stable_int(value: str) -> int:
    return int(hashlib.sha1(value.encode("utf-8")).hexdigest()[:16], 16)


def exact_hash(text: str) -> str:
    return hashlib.sha1(normalize(text).encode("utf-8")).hexdigest()[:12]


def shingles(text: str, n: int = 3) -> set[str]:
    tok = tokens(text)
    if len(tok) < n:
        return set(tok)
    return {" ".join(tok[i : i + n]) for i in range(len(tok) - n + 1)}


def jaccard(left: set[str], right: set[str]) -> float:
    if not left and not right:
        return 1.0
    return len(left & right) / max(len(left | right), 1)


def minhash_signature(shingle_set: set[str], size: int = 64) -> list[int]:
    if not shingle_set:
        return [0] * size
    return [
        min(stable_int(f"{seed}:{shingle}") for shingle in shingle_set)
        for seed in range(size)
    ]


def minhash_similarity(left: list[int], right: list[int]) -> float:
    return sum(a == b for a, b in zip(left, right)) / max(len(left), 1)


def simhash(text: str, bits: int = 32) -> int:
    weights = [0] * bits
    for tok in tokens(text):
        hashed = stable_int(tok)
        for bit in range(bits):
            weights[bit] += 1 if (hashed >> bit) & 1 else -1
    value = 0
    for bit, weight in enumerate(weights):
        if weight >= 0:
            value |= 1 << bit
    return value


def hamming(left: int, right: int) -> int:
    return (left ^ right).bit_count()


id_to_doc = {doc["id"]: doc for doc in train_docs}
shingle_map = {doc["id"]: shingles(doc["text"]) for doc in train_docs}
signatures = {
    doc_id: minhash_signature(shingle_set)
    for doc_id, shingle_set in shingle_map.items()
}
simhashes = {doc["id"]: simhash(doc["text"]) for doc in train_docs}

hash_groups = defaultdict(list)
for doc in train_docs:
    hash_groups[exact_hash(doc["text"])].append(doc["id"])
exact_groups = [sorted(ids) for ids in hash_groups.values() if len(ids) > 1]

near_pairs = []
for left, right in combinations([doc["id"] for doc in train_docs], 2):
    jac = jaccard(shingle_map[left], shingle_map[right])
    estimated = minhash_similarity(signatures[left], signatures[right])
    distance = hamming(simhashes[left], simhashes[right])
    exact_pair = any({left, right}.issubset(group) for group in exact_groups)
    if not exact_pair and (jac >= 0.42 or distance <= 6):
        near_pairs.append((left, right, round(jac, 3), round(estimated, 3), distance))

parent = {doc["id"]: doc["id"] for doc in train_docs}


def find(node: str) -> str:
    while parent[node] != node:
        parent[node] = parent[parent[node]]
        node = parent[node]
    return node


def union(left: str, right: str) -> None:
    left_root, right_root = find(left), find(right)
    if left_root != right_root:
        parent[right_root] = left_root


for group in exact_groups:
    for other in group[1:]:
        union(group[0], other)
for left, right, *_ in near_pairs:
    union(left, right)

clusters_by_root = defaultdict(list)
for doc in train_docs:
    clusters_by_root[find(doc["id"])].append(doc["id"])
clusters = [sorted(ids) for ids in clusters_by_root.values() if len(ids) > 1]


def choose_representative(ids: list[str]) -> str:
    return max(
        ids,
        key=lambda doc_id: (
            id_to_doc[doc_id]["quality"],
            len(tokens(id_to_doc[doc_id]["text"])),
        ),
    )


removed_by_dedup = set()
for cluster in clusters:
    representative = choose_representative(cluster)
    removed_by_dedup.update(set(cluster) - {representative})
dedup_kept = sorted(set(id_to_doc) - removed_by_dedup)

contamination_hits = {}
for item in eval_items:
    query_set = shingles(item["text"])
    best_doc, best_score = None, 0.0
    for doc in train_docs:
        score = jaccard(query_set, shingle_map[doc["id"]])
        answer_leak = item["answer"].lower() in tokens(doc["text"])
        if answer_leak and item["id"] == "gsm_toy":
            score += 0.20
        if score > best_score:
            best_doc, best_score = doc["id"], score
    if best_score >= 0.30:
        contamination_hits[item["id"]] = (best_doc, round(best_score, 3))

canary_hits = sorted(
    doc["id"]
    for doc in train_docs
    if any(canary in doc["text"] for canary in CANARIES)
)
quarantine_ids = {doc_id for doc_id, _ in contamination_hits.values()} | set(canary_hits)
final_kept = sorted(set(dedup_kept) - quarantine_ids)

raw_tokens = sum(len(tokens(doc["text"])) for doc in train_docs)
dedup_tokens = sum(len(tokens(id_to_doc[doc_id]["text"])) for doc_id in dedup_kept)
final_tokens = sum(len(tokens(id_to_doc[doc_id]["text"])) for doc_id in final_kept)
signals = {
    "exact_groups": exact_groups,
    "near_pairs": near_pairs,
    "clusters": sorted(clusters),
    "dedup_kept": dedup_kept,
    "contamination_hits": contamination_hits,
    "canary_hits": canary_hits,
    "final_kept": final_kept,
    "dedup_retention": round(dedup_tokens / raw_tokens, 3),
    "final_retention": round(final_tokens / raw_tokens, 3),
}
actions = []
if exact_groups or near_pairs:
    actions.append("retain_cluster_provenance_and_review_thresholds")
if contamination_hits:
    actions.append("quarantine_eval_overlap_and_retest")
if canary_hits:
    actions.append("isolate_canary_and_measure_memorization")
decision = "hold_for_repair" if actions else "continue_to_manifest"

print("signals=", signals)
print("actions=", actions)
print("decision=", decision)

assert exact_groups == [["attention_blog", "attention_blog_dup"]]
assert len(near_pairs) >= 3
assert contamination_hits["gsm_toy"][0] == "benchmark_leak"
assert canary_hits == ["canary_note"]
assert final_kept == ["attention_blog", "math_note", "python_code", "zh_data_note"]
assert decision == "hold_for_repair"
~~~

这个 demo 把训练集内部簇和训练-评估命中分开：三个 attention 文档属于训练内部重复簇，`benchmark_leak` 是评估污染候选，`canary_note` 是受控记忆探针。代表样本选择依据质量分和长度，实际生产还要加入来源许可、解析质量、语言覆盖和人工审计。

## 4.20 常见失败模式

### 4.20.1 只有 exact hash

转载加页脚、OCR 差异、代码 fork 和轻微改写会绕过 exact dedup。修复方式是分层使用段落、shingle、MinHash/LSH、结构化代码相似度和人工抽样。

### 4.20.2 embedding 相似就删除

语义相似样本可能提供不同事实、问法、语言和推理路径。embedding 更适合作为候选召回、聚类和审计信号，直接删除需要很高置信度和领域验证。

### 4.20.3 把 LSH 当最终判定

LSH 只解决候选召回。桶参数变化会改变召回和计算量，最终仍要用精确相似度、来源和人工协议确认。

### 4.20.4 用训练集内部去重代替污染检测

内部重复减少后，benchmark 题目和答案仍可能留在训练集。必须把评估集作为独立 query，检查题目、答案、解析和代码。

### 4.20.5 只查题目不查答案

答案、选项、解析和固定模板可能提供更强的泄漏信号。污染检测应保存字段级命中证据。

### 4.20.6 只看一个污染比例

强命中和主题相似的弱命中不能混成一个数字。报告要提供证据等级、人工确认率、评估集覆盖和结论边界。

### 4.20.7 canary 使用真实敏感信息

canary 应是合成、受控、不可用于真实访问的字符串。真实 PII 和凭证必须在数据处理层隔离，不应拿来做实验探针。

### 4.21.1 去重和数据构造

4. [Dolma: an Open Corpus of Three Trillion Tokens](https://arxiv.org/abs/2402.00159)：支持开放多来源语料和处理文档化案例。
5. [DataComp-LM](https://arxiv.org/abs/2406.11794)：支持受控比较过滤、去重和 mixture 的数据选择实验。
6. [On the Resemblance and Containment of Documents](https://doi.org/10.1109/SEQUEN.1997.666900)：给出基于文档 shingle 集合的 resemblance/containment 与 MinHash 思路的经典来源，支持本章对大规模近重复候选检索的算法解释。
7. [Similarity Estimation Techniques from Rounding Algorithms](https://doi.org/10.1145/509907.509965)：给出随机投影和舍入算法的相似度估计基础，可作为 SimHash 类二进制指纹方法的经典方法来源。

这些研究说明去重和数据选择会影响训练和评估，但具体阈值依赖数据类型、模型规模、训练预算和评估条件。

### 4.21.2 评估和文档化

1. [Language Models are Few-Shot Learners（GPT-3）](https://arxiv.org/abs/2005.14165)：支持公开大规模语料与 benchmark 方法问题的研究背景。
2. [Datasheets for Datasets](https://arxiv.org/abs/1803.09010)：支持记录数据来源、组成、收集过程、用途和限制。
3. [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)：支持把评估可信度、数据风险和生命周期治理联系起来。

这些资料提供研究和治理框架，不自动证明某个模型没有记忆、某个 benchmark 没有污染，或某个公开数据集可以无条件训练。

## 4.22 思考与实践

### 题目一：设计三层去重

为网页、代码和数学数据分别设计 exact、near 和语义相似层。说明每层的输入、阈值、候选动作和误合并风险。

### 题目二：解释 MinHash/LSH

用一个小的 shingle 集合手算 Jaccard 和两个 MinHash 签名，说明为什么 LSH 只能召回候选，不能直接作为删除结论。

### 题目三：建立污染报告

给定一个公开 benchmark 和一份训练语料，设计题目、答案、解析、代码签名和时间证据的检索表。定义强、中、弱三档证据及其处置。

### 题目四：比较代表样本

对一个包含原文、转载、低质量镜像和不同语言版本的重复簇，设计代表样本选择函数，说明质量、来源、许可、时间和覆盖如何共同影响选择。

### 题目五：设计 canary 实验

使用不可访问的合成字符串设计出现次数、训练版本、查询模板、解码参数和复现率报告。说明实验不能推出哪些关于真实用户数据的结论。

## 4.23 结语：保护训练分布，也保护评估解释力

去重控制的是训练数据内部的频率、冗余和记忆风险；污染检测控制的是训练与评估之间的独立性。exact hash 提供便宜的第一层，MinHash/LSH 和 SimHash 扩大近重复召回，embedding 帮助发现语义候选，代码结构和答案字段补足专门场景，人工审计和版本血缘把相似度变成可复查的工程证据。

真正成熟的系统不会把“删除了多少 token”当作唯一成绩，也不会把一个相似度阈值写成普遍规律。它会说明哪些簇被合并、为什么保留某个代表、哪些评估样本命中题目或答案、污染证据有多强、去重如何改变 data mixture，以及 canary 结果只覆盖什么实验条件。

当训练数据内部的重复被合理控制，评估数据的独立性被明确记录，模型分数才更接近我们真正想知道的能力，而不是数据处理过程制造的假象。
