# 第三章 清洗、过滤与质量评分：决定哪些信号值得学习

上一章解决的是数据从哪里来、按照什么边界取得，以及如何保留来源和原始证据。本章继续沿着这条链路往前走，处理一个更难的问题：取得的记录中，哪些内容值得让模型学习，哪些内容应该删除、降权、隔离或交给人工复核。

清洗过滤经常被描述成“去掉脏数据”。这个说法不够准确。模型不会自动知道一段文本是正文、广告、导航、乱码、重复复制、隐私记录还是 benchmark 答案；它只会把最终看到的 token 当作训练分布的一部分。过滤规则因此会改变模型的知识覆盖、语言风格、事实性、安全边界、记忆风险和训练效率。

本章把清洗看成一个有目标、有代价、有证据的分布塑形过程。我们会先区分结构有效性、内容质量、任务价值和风险控制，再讨论规则、统计特征、质量分类器、困惑度、PII/秘密检测、毒性和合成数据。之后把阈值校准、分桶审计、小模型消融和失败案例连起来，最后用一个只含合成数据的审计 demo 展示如何输出独立信号和后续动作。

这里的“质量”始终是相对于目标任务而言的。适合百科预训练的文章，不一定适合对话；适合代码补全的片段，不一定适合 coding agent；适合安全分类器的风险样本，也不应未经分层直接混进普通预训练池。涉及个人信息、版权、安全和用户日志的处理，需要组织的隐私、安全和法务团队共同确认。

## 3.1 清洗对象：不是“干净文本”，而是可解释样本

### 3.1.1 小白视角：图书馆中的四种书

把采集后的数据想成一座还没有整理的图书馆。书架上有教材、广告传单、重复影印本、读者留言、损坏页面和带个人地址的信件。管理员不会只用一个问题判断它们是否“干净”，而会分别问：

1. 这是不是一本能读的书，而不是乱码纸片？
2. 它是不是正文，而不是书架标签或重复广告？
3. 它是否适合当前区域，例如儿童区、医学区或技术区？
4. 它是否包含不应公开保存的个人信息？
5. 它是否已经在馆藏中出现过？
6. 它是否正好是考试题和答案，导致考试失去意义？

模型数据也一样。一条记录可能结构完整却信息空洞，语言流畅却事实错误，质量很高却包含不能使用的个人信息，或者对普通预训练不合适却是安全训练必需的边界样本。

### 3.1.2 专家视角：质量是多目标决策

设样本 `x_i` 有 token 数 `T_i`、质量特征 `f_i`、来源和领域桶 `c_i`，风险向量 `r_i`，过滤输出不是一个不可解释的“好/坏”标签，而是多个信号：

~~~math
signals_i = (valid_i, quality_i, privacy_i, safety_i, contam_i, duplicate_i).
~~~

随后根据训练阶段和目标能力选择动作：保留、降权、隔离、脱敏、人工复核或删除。可以把过滤决策写成：

~~~math
action_i = A(signals_i, target, policy, budget, version).
~~~

`target` 是目标模型或数据池，`policy` 是用途和风险约束，`budget` 是处理和训练成本，`version` 绑定规则与分类器版本。这个表达式提醒我们：同一条样本在不同数据池中可能有不同动作，清洗不是脱离上下文的普适真理。

## 3.2 为什么更多数据不自动等于更好数据

### 3.2.1 每个 token 都有计算成本

一个 token 会消耗加载、tokenization、前向、反向、通信和存储资源。如果训练集含有大量重复页脚、乱码、模板导航、关键词堆砌和空洞改写，模型仍会对这些 token 做完整训练计算。

更大的问题在于，噪声会产生可观察的行为：

1. 低信息密度降低有效 token 的比例。
2. 重复文本提高某些来源的隐含采样权重。
3. 模板和广告改变输出的风格与格式。
4. 低可信内容增加事实冲突和幻觉。
5. 稀有个人信息与重复样本共同增加记忆风险。
6. benchmark 题目进入训练后会削弱评估解释力。
7. 风险语料被无上下文混入时，模型可能学习到有害续写而不是安全识别。

因此，数据报告不能只写原始 TB 或文件数，还要报告解析后 token、过滤后 token、各桶保留率、重复和污染候选、PII/秘密信号以及实际训练采样量。

### 3.2.2 质量也不是越高越好

如果质量分类器只偏好正式、完整、长篇的文章，系统可能误删口语、短问题、方言、社区调试和低资源语言。一个聊天模型需要看到自然用户表达，一个代码模型需要看到错误代码和修复过程，一个安全模型需要看到风险语义和安全替代。

所以更准确的目标是：在给定训练预算和风险约束下，让每个数据池获得与能力目标匹配的有效信号。过滤器不能单独决定 data mixture，但必须提供能支撑 mixture 决策的统计和证据。

## 3.3 清洗历史：从启发式规则到模型化治理

早期 NLP 数据通常由研究者或标注团队整理，预处理重点是分词、大小写、长度截断和标签格式。预训练规模扩大后，数据不再是几万条人工检查样本，而是从网页、书籍、论文、代码、论坛和日志中构成的复杂混合。

过滤方法大致经历了三个阶段：

1. 启发式阶段：长度、字符比例、语言、重复、黑名单和模板规则。
2. 统计阶段：词频、n-gram、压缩率、困惑度、重复度和来源分布。
3. 模型化阶段：质量分类器、毒性分类器、PII/秘密检测器、领域分类器、embedding 聚类和人工审计闭环。

现代数据管线通常把三类方法组合起来。规则负责便宜、明确、可解释的异常；统计特征负责发现同桶分布中的极端样本；模型负责处理语义质量和上下文风险；人工审计负责校准标签、发现新分布和检查误删。

公开数据研究也显示，过滤和数据选择会显著改变训练结果，但不同论文使用的模型规模、训练配方、数据来源和评估集合不同。一个数据集论文中的阈值不能直接复制成所有模型的最佳阈值。

## 3.4 一条可追溯的过滤流水线

### 3.4.1 阶段顺序

一个可解释的清洗流程可以是：

~~~text
parsed artifact
  -> structural validity
  -> language / domain bucketing
  -> boilerplate and template analysis
  -> rule features
  -> quality scoring
  -> privacy / secret / safety signals
  -> contamination and dedup signals
  -> stratified human audit
  -> target-specific action
  -> versioned dataset artifact
~~~

顺序不是绝对固定的。高风险秘密可能在质量评分之前就需要隔离，评估污染可以在近重复之前单独执行，代码和数学可能需要专用解析器。重要的是每一步都有输入、输出、版本、失败原因和可抽样的中间结果。

### 3.4.2 数据对象和特征

对解析后的样本记录：

~~~math
x_i = (text_i, source_i, type_i, language_i, domain_i, T_i, version_i).
~~~

可以抽取如下特征：

~~~math
f_i = (length_i, unique_i, symbol_i, repeat_i, link_i, boilerplate_i, ppl_i).
~~~

`length_i` 描述 token 或字符长度，`unique_i` 描述 token 多样性，`symbol_i` 描述符号和异常字符比例，`repeat_i` 描述重复行或 n-gram，`link_i` 描述链接密度，`boilerplate_i` 描述模板信号，`ppl_i` 是参考模型困惑度或其分桶统计。特征只是证据，不是自动真相。

### 3.4.3 质量分的教学抽象

可以把一个简单的质量分写成：

~~~math
q_i = sum_k(w_k * f_ik)
      - lambda_repeat * repeat_i
      - lambda_noise * noise_i
      - lambda_template * template_i.
~~~

`w_k` 是正向特征权重，`lambda_*` 是惩罚强度。真实系统可以用分类器、ranker 或多任务模型取代线性式，但这个式子能清楚说明：质量分是多个信号的组合，并且惩罚项的代价会改变分布。

### 3.4.4 分桶比全局阈值更重要

设样本属于语言、领域或来源桶 `c_i`，阈值写成 `tau_c` 而不是全局的 `tau`：

~~~math
keep_i = I(q_i >= tau_{c_i}).
~~~

代码、数学、论文、聊天和网页的字符结构不同；中文、英文和低资源语言的 token 统计也不同。分桶阈值不能解决所有偏差，却能避免把一种数据的正常特征当作另一种数据的异常。

## 3.5 基础有效性：先处理明显不能用的记录

### 3.5.1 长度和空内容

空文档、只有标题的页面、单个按钮和截断响应通常不能直接进入普通预训练。超长样本也不一定有价值，可能是日志倾倒、重复模板堆叠或解析器把多个页面连接在一起。

长度阈值要按数据类型设定：短数学题、代码函数、对话轮次和长论文不能使用同一个最小或最大长度。长度异常更适合作为复核信号，而不是无条件删除。

### 3.5.2 字符、控制符和不可见字符

基础检查可以统计不可打印字符、Unicode replacement character、方向控制符、异常空白和二进制残留。乱码会增加稀有 token，干扰语言分布，也可能制造极长序列。

但代码、公式、表格和多语言文本本来就可能有高符号比例。检查要同时观察 MIME、领域、语言和解析器版本，不能单独用“非字母比例高”作为删除理由。

### 3.5.3 tokenizer 视角的异常

同一个字符数下，样本被 tokenizer 切成极多 token，可能说明编码异常、混入二进制或语言与 tokenizer 不匹配。可以使用 token/character 比率作为特征：

~~~math
ratio_i = tokens_i / max(chars_i, 1).
~~~

它适合发现同一桶中的极端值，不适合跨语言直接比较。中文、日文、代码和数学的正常比率本来就不同。

## 3.6 正文、模板和低信息密度

### 3.6.1 boilerplate 的问题

网页正文旁边常有导航、页脚、版权说明、cookie banner、相关推荐、分享按钮和评论框。它们单独看并不一定是错误，但在数百万页面中重复出现，会消耗 token 并改变模型风格。

正文抽取可以使用 DOM 结构、文本密度、链接比例、站点模板指纹和段落位置等信号。删除前后应保留对照 artifact，检查标题、警告、表格和代码是否被一起删掉。

### 3.6.2 反事实审计

过滤器的一个实用审计方法是构造反事实对：同一页面分别经过旧规则和新规则，人工比较删除和保留的片段。重点观察：

1. 删除的是不是跨页面重复模板。
2. 保留段落是否仍有标题和上下文。
3. 代码块和表格是否完整。
4. 不同语言、领域和页面布局是否有差异。
5. 过滤结果改变后，模型是否出现风格或能力回归。

### 3.6.3 SEO 和广告文本

SEO 垃圾往往语言通顺，却信息密度低、关键词堆砌、句子改写重复、链接和联系方式过多。单个推广词不能直接作为删除理由，因为新闻、商业案例、合同和电商评论也可能包含价格、品牌或地址。

更稳的组合信号包括：词汇重复、段落相似、链接比例、模板指纹、来源、质量分和人工样本。过滤系统还可以把边界样本降权或隔离，而不是把所有营销语言当成同一类。

## 3.7 规则过滤：便宜、明确，但不能代替判断

规则适合处理空样本、替换字符过多、明确的秘密格式、重复行、超出安全范围的字段和已知评估模板。它的优点是快、可解释、易于回放；缺点是难以理解语义，容易在边界处误删。

规则版本应记录：

1. 规则目的和适用数据桶。
2. 输入字段和正则/词表版本。
3. 阈值和例外列表。
4. 正例、负例和边界样本。
5. 命中后动作是删除、隔离、降权还是复核。
6. 版本变更前后的命中率和下游影响。

一个规则命中率升高不一定代表质量变好，可能只是某个来源或语言被系统性删掉。每条规则都应该能回答“删掉谁、误删谁、留下谁、代价是什么”。

## 3.8 质量分类器：从启发式到语义评分

### 3.8.1 标签从哪里来

质量分类器可以用人工标注、弱监督、来源先验、对比样本、LLM 辅助标注和下游反馈训练。无论来源是什么，标签都不是世界真理，而是一个面向目标任务的判断协议。

例如，把技术文档和百科当作正例、模板页和明显垃圾当作负例，分类器可能学到正式文风和较长段落；它未必学到事实正确性，也可能把口语、方言和低资源语言判成低质量。

### 3.8.2 分类器输出什么

二分类输出可以用于粗筛，连续分数更适合采样和版本比较。一个分数 `q_i` 至少要伴随模型版本、训练标签、校准集、阈值、语言/领域桶和不确定性。

如果分类器只输出“保留/删除”，后续无法区分高置信度垃圾和边界样本。保留分数、命中特征和人工复核结果，可以让边界样本进入下一轮标签和阈值校准。

### 3.8.3 LLM-as-judge 的边界

更强模型可以辅助判断可读性、结构和任务价值，但它也会偏好自己的文风、过度相信流畅表述、忽略事实错误，或对非主流语言缺乏判断能力。LLM judge 适合生成候选标签和解释，不能跳过人工协议、负对照和下游消融。

### 3.8.4 分组审计

至少要按以下切片检查质量分类器：

1. 语言、脚本和方言。
2. 领域、文档类型和长度。
3. 来源、时间和作者类型。
4. 代码、数学、表格、对话和普通正文。
5. 高质量但非主流的边界样本。

如果某个切片的保留率突然下降，应先查看样本和标签协议，而不是立即把阈值调高或调低。

## 3.9 困惑度：有用的异常信号，不是质量裁判

参考语言模型对文本的平均负对数似然可以转成困惑度：

~~~math
PPL_i = exp((1 / T_i) * sum_t(-log p_ref(x_t | x_<t))).
~~~

困惑度高可能表示乱码、拼接错误、专业领域陌生或语言不匹配；困惑度低可能表示自然文本，也可能表示重复模板和常见套话。因此应在语言、领域和来源桶内计算分布，使用同桶极端值，而不是全局阈值。

可进一步使用标准化分数：

~~~math
z_i = (log(PPL_i) - mean_c) / std_c.
~~~

`mean_c` 和 `std_c` 是桶 `c` 的统计量。低资源语言和专业技术文本的参考模型本身可能不充分，困惑度过滤尤其需要人工负对照和小模型验证。

## 3.10 PII、秘密和安全语义

### 3.10.1 PII 检测不是一个正则表达式

邮箱、电话、证件号和常见 token 格式可以用规则发现；人名、地址、健康信息、多个字段组合后的身份关系则需要实体识别、上下文分类和人工复核。Microsoft Presidio 等工具可以提供可扩展的检测与匿名化组件，但工具输出仍需按组织数据和法域校准。

误报包括小说人物、公开机构地址、论文作者邮箱和明确标注为 fake 的示例；漏报包括图片 OCR、非标准电话格式、口语地址和组合型身份信息。工程上要保存命中类型、检测器版本、处理动作和人工复核结果。

### 3.10.2 秘密检测和轮换

代码、日志和配置中可能有 API key、访问令牌、密码、私钥和内部 URL。发现秘密后不能只把字符串替换掉，还要判断凭证是否已经使用，必要时轮换相关凭证，并清理缓存、日志和版本库副本。

训练数据处理应使用合成值和占位符测试检测器，不要在测试代码中放入可复用真实密钥。秘密扫描通过只说明当前扫描器没有命中，不能证明内容没有敏感信息。

### 3.10.3 毒性和风险内容的分层

普通预训练、风险识别、安全 SFT 和红队评估对风险文本的需要不同。把所有仇恨、暴力、自伤或危险语义都删除，可能削弱模型识别和安全回应能力；不加上下文地全部保留，又可能增加有害续写。

可以按用途分层：

1. 明显高风险、无法安全处理的内容删除或受控隔离。
2. 新闻、研究、教育和安全讨论保留上下文、来源和用途标签。
3. 安全拒答、澄清和替代帮助进入安全或后训练数据池。
4. 需要模型识别但不应复述的样本使用受控评估和最小暴露。

### 3.10.4 评估污染与质量过滤的边界

benchmark 题目、答案和模板需要单独检测。它们可能质量很高，却不应该进入训练数据。质量分类器分数高不能覆盖 contamination 信号，污染动作也不应被混进普通低质量理由。

## 3.11 合成数据和机器生成数据

Web 上的机器生成文本越来越多。未经筛选的机器生成内容可能降低语言多样性，复制教师错误，放大模板和事实幻觉；高质量合成数据则可能补足数学、代码、指令和安全边界。

处理机器生成数据时应保留：

1. 生成来源和教师模型版本。
2. 生成提示、验证器和过滤器版本。
3. 是否通过执行、证明、事实或人工检查。
4. 与自然语料的配比和重复关系。
5. 允许进入预训练、SFT、偏好或安全数据池的范围。

“机器生成”不是自动删除标签，“高质量”也不能替代验证。合成数据的价值要通过任务成功、错误率、改写泛化、长尾覆盖和教师错误传播来评估。

## 3.12 按数据类型使用不同过滤策略

### 3.12.1 网页正文

重点是正文抽取、模板分析、广告和链接密度、语言、重复和来源时间。页面质量分需要与解析版本绑定，否则 parser 变化可能被误认为内容质量变化。

### 3.12.2 代码

代码符号多、短函数多、重复 API 调用多，普通自然语言阈值会误删正常样本。代码处理应关注 AST/编译可解析性、许可证、秘密、vendor/fork、依赖、测试、文件关系和漏洞标签。

### 3.12.3 数学和科学

公式、编号、符号和短证明不应因为字符比例高或困惑度高被删除。可以使用公式解析、问题类型、答案可验证性、定理/证明结构和独立 verifier。

### 3.12.4 对话

对话需要检查角色、轮次、系统/用户/助手边界、隐私、同意、工具结果和拒答语境。单轮文本质量高，不代表多轮任务状态完整。

### 3.12.5 多语言

应对语言识别器、质量分类器和困惑度模型做低资源切片审计。翻译文本可以作为独立来源标记，避免与原生表达混合后无法解释模型风格变化。

## 3.13 阈值校准：把误删和漏删放进同一张账

### 3.13.1 两种错误

过滤器把好样本删掉，是 false positive；把坏样本留下，是 false negative。两种错误都需要代价模型：

~~~math
L_filter
= C_fp * P(false_delete)
  + C_fn * P(false_keep).
~~~

`C_fp` 在低资源语言、关键领域和安全识别数据上可能很高；`C_fn` 在秘密、隐私、评估污染和高风险动作样本上可能很高。阈值不是越严越好，而是要与切片和用途匹配。

### 3.13.2 分层抽样

人工审计不能只随机抽总体，因为高质量样本和稀有风险样本的比例可能很低。可以按质量分桶、语言、领域、来源、风险命中和长度分层抽样，再对估计结果做权重修正。

每个抽样报告应记录样本数、抽样框、标注协议、标注者一致性、置信区间和未覆盖切片。一个“抽了 100 条”的数字没有这些信息就很难解释。

### 3.13.3 阈值扫描

对质量分阈值 `tau` 扫描，记录保留率、人工 precision、人工 recall、各切片保留率和下游小模型结果。阈值变化引起的分布变化应写入版本 diff，不能只保留最终阈值。

## 3.14 过滤后的验证：数据指标和模型指标要连起来

### 3.14.1 过滤前后数据指标

至少比较：

1. raw、parsed、kept 和 sampled token。
2. 语言、领域、来源和时间分布。
3. 质量分、困惑度和长度分布。
4. exact/near duplicate、污染和 PII/secret 命中。
5. 人工 precision、recall、误删和漏删。

平均质量提高但中文覆盖下降，或保留率提高但污染上升，都可能是回归。

### 3.14.2 小模型消融

在昂贵的大模型训练前，可以用较小模型、较短 token 预算和多个随机种子比较过滤版本。应同时观察验证 loss、代码/数学/语言切片、事实性、安全误拒、风险输出和训练成本。

小模型趋势不保证大模型完全一致，但可以发现明显的过滤灾难，例如某个规则删掉了所有代码、某个质量分类器压低了低资源语言或某个安全过滤使风险识别能力骤降。

### 3.14.3 训练 loss 不是唯一答案

某个过滤版本可能降低验证 loss，却让事实引用、对话风格或安全边界变差；也可能保留更多真实噪声，让 loss 略高但用户任务更好。数据实验应把能力、行为、安全、覆盖和成本放在同一张评估表中。

## 3.15 工程案例：高质量分类器误删低资源语言

### 3.15.1 现象

一个团队用英文高质量文章和百科作为正例训练质量分类器。新版本上线后，总体平均质量分提高，网页模板比例下降，但某低资源语言的保留率从 62% 降到 18%，该语言问答和代码注释能力明显回退。

### 3.15.2 根因

分类器把较短句子、不同标点、少见词和非标准拼写当作低质量特征。它的标签协议没有覆盖该语言，评估只看总体 precision，没有按语言统计误删。

### 3.15.3 修复

1. 从被删除样本中按语言和质量分桶抽样。
2. 引入该语言的原生高质量样本和正常口语负对照。
3. 重新校准分类器并使用语言桶阈值。
4. 将重要教育、政策和技术来源设置为保留候选，不绕过隐私和许可证检查。
5. 用小模型和目标语言任务做过滤前后消融。
6. 把保留率、误删率和能力回归加入版本报告。

### 3.15.4 教训

总体质量分并没有回答“哪些人、哪些语言、哪些任务被删掉了”。质量系统必须报告分母、切片和代价，才能把平均收益与分布损失放在一起判断。

PII_PATTERNS = [
    re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+"),
    re.compile(r"1[3-9]\d{9}"),
]
SECRET_PATTERNS = [re.compile(r"DEMO_SECRET_[A-Z0-9]{8,}")]
SAFETY_TERMS = {"hate", "harassment", "demeaning", "insults"}
CONTAM_TERMS = {"benchmark answer", "hidden test answer", "answer key"}
PROMO_TERMS = {"buy", "discount", "promo", "click", "cheap"}


def tokens(text: str) -> list[str]:
    return re.findall(r"[A-Za-z0-9_]+|[\u4e00-\u9fff]", text.lower())


def content_hash(text: str) -> str:
    normalized = " ".join(tokens(text))
    return hashlib.sha1(normalized.encode("utf-8")).hexdigest()[:12]


def safe_ratio(numerator: float, denominator: int):
    return round(numerator / denominator, 3) if denominator else None


def line_repeat_ratio(text: str) -> float:
    parts = [part.strip().lower() for part in re.split(r"[\n.!?。！？]", text) if part.strip()]
    if not parts:
        return 1.0
    counts = Counter(parts)
    return sum(count - 1 for count in counts.values() if count > 1) / len(parts)


def symbol_ratio(text: str) -> float:
    if not text:
        return 1.0
    allowed = lambda char: char.isspace() or char.isalnum() or "\u4e00" <= char <= "\u9fff"
    return sum(not allowed(char) for char in text) / len(text)


def quality_features(sample: dict) -> dict:
    text = sample["text"]
    tok = tokens(text)
    return {
        "tokens": len(tok),
        "length_score": min(len(tok) / 24, 1.0),
        "unique_ratio": len(set(tok)) / max(len(tok), 1),
        "alpha_or_cjk": sum(
            char.isalpha() or "\u4e00" <= char <= "\u9fff" for char in text
        ) / max(len(text), 1),
        "repeat": line_repeat_ratio(text),
        "symbol_ratio": symbol_ratio(text),
        "replacement_ratio": text.count("\ufffd") / max(len(text), 1),
        "promo_ratio": sum(token in PROMO_TERMS for token in tok) / max(len(tok), 1),
    }


def quality_score(sample: dict) -> float:
    features = quality_features(sample)
    symbol_penalty = 0.05 if sample["domain"] in {"code", "math"} else 0.20
    score = (
        0.30 * features["length_score"]
        + 0.25 * features["unique_ratio"]
        + 0.25 * min(features["alpha_or_cjk"] / 0.65, 1.0)
        - 0.30 * features["repeat"]
        - symbol_penalty * features["symbol_ratio"]
        - 0.50 * features["replacement_ratio"]
        - 0.50 * features["promo_ratio"]
    )
    return round(max(0.0, min(1.0, score)), 3)


def risk_flags(sample: dict) -> dict:
    text = sample["text"]
    lower = text.lower()
    tok = set(tokens(text))
    return {
        "pii": any(pattern.search(text) for pattern in PII_PATTERNS),
        "secret": any(pattern.search(text) for pattern in SECRET_PATTERNS),
        "safety": bool(tok & SAFETY_TERMS),
        "contamination": any(term in lower for term in CONTAM_TERMS),
    }


def audit(items: list[dict], threshold: float = 0.62) -> dict:
    seen = set()
    kept, rejected, rows = [], {}, []
    for item in items:
        features = quality_features(item)
        score = quality_score(item)
        flags = risk_flags(item)
        reason = None
        if features["tokens"] < 8 or features["replacement_ratio"] > 0.05:
            reason = "invalid_or_garbled"
        elif flags["pii"] or flags["secret"]:
            reason = "privacy_or_secret"
        elif flags["contamination"]:
            reason = "eval_contamination"
        elif flags["safety"]:
            reason = "safety_isolate"
        elif score < threshold:
            reason = "low_quality"
        else:
            key = content_hash(item["text"])
            if key in seen:
                reason = "exact_duplicate"
            seen.add(key)
        if reason:
            rejected[item["id"]] = reason
        else:
            kept.append(item)
        rows.append({"id": item["id"], "score": score, "reason": reason or "kept"})

    kept_tokens = sum(len(tokens(item["text"])) for item in kept)
    raw_tokens = sum(len(tokens(item["text"])) for item in items)
    domain_tokens, language_tokens = defaultdict(int), defaultdict(int)
    for item in kept:
        token_count = len(tokens(item["text"]))
        domain_tokens[item["domain"]] += token_count
        language_tokens[item["language"]] += token_count
    reason_counts = Counter(rejected.values())
    signals = {
        "kept_ids": [item["id"] for item in kept],
        "rejected": dict(sorted(rejected.items())),
        "reason_counts": dict(sorted(reason_counts.items())),

        "domain_mix": {
            key: safe_ratio(value, kept_tokens)
            for key, value in sorted(domain_tokens.items())
        },
        "language_mix": {
            key: safe_ratio(value, kept_tokens)
            for key, value in sorted(language_tokens.items())
        },
        "score_preview": {row["id"]: row["score"] for row in rows[:6]},
    }
    actions = []
    if not items:
        actions.append("restore_or_collect_source_records")
    if items and not kept:
        actions.append("restore_nonempty_training_set")
    if reason_counts["invalid_or_garbled"]:
        actions.append("repair_or_isolate_invalid_records")
    if reason_counts["low_quality"]:
        actions.append("review_quality_threshold_and_samples")
    if reason_counts["privacy_or_secret"]:

    if reason_counts["safety_isolate"]:

    decision = "hold_for_repair" if actions else "continue_to_manifest"
    return {"signals": signals, "actions": actions, "decision": decision}

## 3.17 过滤策略的版本和回放

每个数据集版本应绑定：

~~~text
dataset_id
source_snapshot
parser_revision
feature_revision
quality_model_revision
threshold_config
privacy_detector_revision
safety_policy_revision
contamination_revision
dedup_revision
mixture_revision
manifest_digest
created_at
~~~

版本 diff 不仅要报告保留 token，还要报告各语言/领域保留率、误删抽样、风险命中、污染候选、质量分分布和规则命中变化。一个新的质量模型可能提高平均分，却删除了某一语言的全部短句；如果没有分桶 diff，这个回归会被平均数隐藏。

收到删除或许可撤回时，需要根据 source、hash、cluster 和 revision 定位样本及下游副本。删除过滤后的文本不等于权重遗忘；过滤器本身也不负责证明模型已经忘记。

## 3.18 常见失败模式

### 3.18.1 用一个全局质量阈值处理所有数据

语言、领域、代码、数学、对话和网页的正常特征不同。全局阈值容易偏爱某种语言和文风。修复方式是分桶统计、边界抽样和目标任务消融。

### 3.18.2 只看删除比例

删除 50% 可能意味着过滤有效，也可能意味着解析器失败或低资源数据被误删。必须同时看分桶保留率、precision、recall、风险和下游能力。

### 3.18.3 把质量分类器当事实裁判

分类器反映标签协议和训练来源，可能把流畅误认为正确，把正式误认为重要。需要事实抽样、领域专家、负对照和能力回归。

### 3.18.4 把困惑度低当作高质量

模板和套话可以很容易被参考模型预测，专业文本和低资源语言可能困惑度高。困惑度适合作为同桶异常信号，不是最终裁判。

### 3.18.5 PII 只用正则处理

正则适合结构化模式，无法覆盖组合型身份、图像 OCR、非标准格式和上下文风险。需要多检测器、人工抽样、保留记录和删除链路。

### 3.18.6 把所有风险语义删除

安全模型需要风险识别、拒答和替代帮助的训练信号。应按用途分层、隔离和最小暴露，而不是让普通预训练池承担所有安全数据责任。

### 3.18.7 过滤后不做小模型验证

规则和分类器的局部指标可能很好，整体分布却已变化。小模型消融不是大模型结论，但可以低成本发现灾难性回归。

## 3.19 资料与证据边界

### 3.19.1 数据集构造和选择

1. [Documenting Large Webtext Corpora: A Case Study on the Colossal Clean Crawled Corpus（C4）](https://arxiv.org/abs/2104.08758)：支持网页语料来源、过滤影响、评估样本混入和数据文档化讨论。
2. [The RefinedWeb Dataset for Falcon LLM](https://arxiv.org/abs/2306.01116)：支持网页过滤、去重和高质量 Web 数据构造的研究案例。
3. [The FineWeb Datasets](https://arxiv.org/abs/2406.17557)：支持多快照网页数据、过滤/去重消融和教育数据切片的较新案例。
4. [Dolma: an Open Corpus of Three Trillion Tokens](https://arxiv.org/abs/2402.00159)：支持多来源语料构造、处理文档和数据工具开放的案例。
5. [DataComp-LM](https://arxiv.org/abs/2406.11794)：支持通过受控数据选择实验比较过滤、去重和配比价值的方法。
6. [Deduplicating Training Data Makes Language Models Better](https://arxiv.org/abs/2107.06499)：支持重复、记忆和 train-test overlap 的研究讨论。

这些论文的过滤规则和结果依赖具体数据、模型、训练预算和评估，不是所有项目的默认阈值。它们也不自动授予任何来源的版权、隐私或商业使用权。

### 3.19.2 隐私、质量与治理工具

1. [Microsoft Presidio](https://data-privacy-stack.github.io/presidio/)：提供 PII 识别和匿名化工具入口，不能替代组织的隐私影响评估和人工复核。
2. [Datasheets for Datasets](https://arxiv.org/abs/1803.09010)：支持记录数据集动机、组成、采集过程、推荐用途和限制。
3. [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)：支持把数据质量、隐私、安全和治理放进生命周期管理。
4. [NIST Generative AI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)：支持生成式 AI 的数据来源、隐私、评估和风险管理边界。

这些资料说明工具和治理框架能覆盖哪些问题，但不能证明某个数据集已经没有 PII、偏见、版权、污染或安全风险。

## 3.20 思考与实践

### 题目一：设计分桶阈值

为英文网页、中文论坛、Python 代码和数学证明分别设计质量特征、阈值和人工抽样方案。说明哪些指标不能跨桶直接比较。

### 题目二：比较规则和分类器

构造一个包含正文、模板、SEO、口语、代码和低资源语言的标注集。分别测量规则和质量分类器的 precision、recall、误删切片和处理成本。

### 题目三：设计过滤消融

固定 tokenizer、训练 token、模型和评估集，比较无过滤、规则过滤和规则加质量模型三种数据版本。除 loss 外，增加语言覆盖、代码执行、事实支持、安全误拒和成本指标。

### 题目四：处理 PII 误报

列出论文作者邮箱、小说人物、合成邮箱和真实用户邮箱四种样本，设计规则、上下文和人工复核的组合流程，并说明怎样记录处理依据。

### 题目五：解释风险样本的分层

把一段风险新闻、一条有害请求、一条安全拒答示例和一条研究论文分别放入普通预训练、SFT、安全数据和评估池，说明每个选择的理由、风险和验证方法。

## 3.21 结语：过滤是在选择模型要学什么

清洗、过滤与质量评分不是数据管线中可有可无的“卫生工作”。它们决定哪些语言、文体、事实、代码、错误、风险和行为信号进入模型；也决定训练预算花在什么地方。

规则提供速度和可解释性，统计特征帮助发现异常，质量模型提供语义排序，PII/秘密和安全检测控制风险，人工审计校准边界，小模型消融检验下游后果，版本血缘让结果可以复现和回滚。任何一个信号都不应被写成普遍真理，也不能由平均质量分替代分桶覆盖和风险证据。

一个成熟的清洗系统最终要回答的不只是“删掉了多少数据”，还要回答：哪些样本被删掉，哪些被降权或隔离，谁因此获得或失去覆盖，过滤器可能错在哪里，训练结果是否支持这次选择，以及下一次数据版本能否复核这条因果链。只有这样，过滤才真正成为模型能力工程，而不是一组看似整洁的删除规则。
