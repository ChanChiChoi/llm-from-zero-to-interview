# 第十二章：数据工程综合设计与故障诊断

前面十一章分别讨论了数据从哪里来、如何清洗、怎样去重、怎样配比，以及代码、数学、领域、合成、偏好、安全、多模态、数据估值和版本治理。本章把这些知识放回同一个真实系统中：一家企业要建设一个能够回答内部技术文档、生成代码修改建议、引用领域资料并在风险请求上保持边界的知识助手。

这个系统同时需要继续预训练、监督微调、偏好与安全数据、检索数据和评估数据。原始数据规模约为 100 TB，来源包括公开技术资料、获得授权的企业文档、代码仓库、人工标注记录和多模态会议资料。团队希望提高技术问答和代码任务的完成度，却发现新版本有三个回归：部分答案引用了过期文档，代码建议的测试通过率下降，安全数据增加后正常的内部查询也更容易被拒绝。

这三个现象表面上分别属于知识、代码和安全问题，实际上都可能由数据版本、过滤规则、配比、标签或评估协议造成。本章不把它们拆成互不相干的技巧，而是沿着“目标契约 -> 数据对象 -> 处理状态 -> 训练输入 -> 评估证据 -> 故障回放 -> 发布决策”的链路，把系统设计和诊断方法讲完整。

本章讨论合法合规的数据处理、训练数据治理、评估污染控制、隐私保护和防御性安全工程，不提供未授权采集、访问控制绕过、训练数据反推或有害行为实施方法。

## 0. 本章要解决的工程问题

一个成熟的数据系统不能只回答“有多少 token”。它至少要回答六个问题：

1. 模型要为哪些用户完成什么任务？
2. 每类任务需要什么输入、监督和证据？
3. 原始对象经过哪些处理，为什么被保留或隔离？
4. 训练实际消费的是哪个不可变版本和哪种配比？
5. 某项能力变化来自数据、训练、运行时还是评估协议？
6. 删除、授权、隐私和风险状态能否沿血缘回放？

初学者可以把这条链理解为“教材、作业、考试、成绩和修订记录”。如果教材版本变了，考试题混入教材，作业答案标错，或者成绩统计漏掉一类学生，就不能只根据最后分数判断学习效果。专家需要进一步把每个对象绑定到 hash、版本、分母、处理器、责任人和反事实实验。

### 0.1 一个贯穿案例

企业知识助手的目标不是生成尽可能长的文字，而是在用户有权限访问的资料范围内，给出可追溯、不过度确定且能够完成任务的结果。它包含四类核心任务：

| 任务 | 输入 | 主要证据 | 关键失败 |
| --- | --- | --- | --- |
| 技术问答 | 问题、租户、检索文档 | 文档片段和版本 | 引用过期、凭空补全 |
| 代码修改 | 代码、测试、依赖 | 编译和测试结果 | 旧 API、测试不通过 |
| 领域问答 | 问题、领域文档 | 权威来源和日期 | 把过期内容当现行规则 |
| 风险请求处理 | 请求、上下文、策略 | 风险标签和安全动作 | 漏拒、误拒、越权 |

一个样本的最小记录可以写成：

~~~math
z_i=(u_i,x_i,y_i,e_i,q_i,r_i,a_i,v_i)
~~~

`u_i` 是样本或来源标识，`x_i` 是输入，`y_i` 是目标输出或候选输出，`e_i` 是外部证据，例如文档片段、测试结果或验证器结果，`q_i` 是质量信号，`r_i` 是风险信号，`a_i` 是授权与访问状态，`v_i` 是数据和处理版本。

这里的关键是把“内容”和“责任条件”放在同一个对象中。只有文本而没有来源、许可、版本和证据的记录，可以用于探索性分析，却不应直接被当作可训练样本。

### 0.2 训练分布和任务分布

模型通常直接优化训练分布，而产品关心的是任务分布。设训练样本来自 `P_train`，真实任务来自 `P_task`，则语言模型训练目标可以抽象为：

~~~math
L_{train}(theta)=E_{(x,y)~P_{train}}[ell(f_theta(x),y)]
~~~

当 `P_train` 和 `P_task` 差异较大时，训练损失下降并不能推出真实任务质量提高。数据工程的工作，就是通过来源选择、清洗、配比、验证和治理，让训练分布在可接受风险和成本内覆盖目标任务，同时保留必要的长尾和自然表达。

## 1. 先写数据契约，再写流水线

数据契约不是一张字段清单，而是对输入、输出、证据和责任边界的共同约定。没有契约，清洗团队会优化保留率，训练团队会优化吞吐，评估团队会优化分数，最后没人能说明这些数字是否对应同一个目标。

### 1.1 任务契约

技术问答的任务契约应至少说明：用户身份和权限如何确定，允许使用哪些文档，回答是否必须引用，证据不足时如何表达不确定性，答案的时效要求是什么。代码任务还要说明语言、依赖、测试命令、沙箱权限、超时和网络边界。安全任务要说明允许回答、拒绝和安全转向三种动作，以及不同风险等级下的责任人。

领域资料还需要时间和适用范围。一个旧版本规范可能在历史查询中有价值，在现行流程问答中却不应被当作当前规则。数据契约应该把 `as_of` 时间、法域或组织范围、来源等级和引用格式写入样本协议。

### 1.2 成功不等于流畅

对一条问答样本，成功可能意味着答案被证据支持、引用位置正确、权限没有越界，并且在不能确认时明确说明。对代码样本，成功可能意味着编译通过、目标测试通过、没有越权副作用。对安全样本，成功不只是拒绝危险请求，还要在正常请求上保持帮助性。

可以把任务成功写成约束选择：

~~~math
y^*=argmax_y U(y|x)
subject to Risk(y|x)<=tau,
Evidence(y,x)>=eta
~~~

`U` 是任务效用，`Risk` 是风险函数，`tau` 是场景相关的风险上限，`Evidence` 是回答可由输入、工具或授权来源支持的程度，`eta` 是最低证据要求。这个式子不是生产系统的万能打分器，而是提醒我们：最流畅的答案不一定是可接受答案，最保守的拒答也不一定完成了任务。

### 1.3 目标矩阵

目标矩阵把能力、风险、成本和证据放在一起。一个小型矩阵可以包括：

| 目标 | 主指标 | 重要切片 | 不能牺牲的约束 | 证据来源 |
| --- | --- | --- | --- | --- |
| 技术问答 | grounded answer rate | 语言、文档年龄、租户 | 权限、引用 | 检索评估和人工抽样 |
| 代码修改 | hidden test pass rate | 语言、依赖、任务难度 | 沙箱、license | 编译、测试、人工审计 |
| 领域问答 | source-supported accuracy | 版本、法域、风险级别 | 时效、专家复核 | 引用检查和专家评审 |
| 安全处理 | leak rate、over-refusal | 语言、动作、工具权限 | 高风险请求不能泄露 | 红队回归和正常样本 |

主指标只是一个观察窗口。发布判断还要查看切片分母、错误严重度、单位成功成本和回滚能力。

## 2. 把 100 TB 原始数据变成状态账本

100 TB 是原始存储量，不是训练数据量，也不是有效 token 数。容量规划必须把不同阶段的对象分开，否则原始副本、解析中间结果、隔离对象和版本保留会互相覆盖，最终既无法算成本，也无法保证可回放。

### 2.1 数据状态

每个对象可以沿着状态机流动：

~~~text
discovered -> registered -> raw -> parsed -> assessed -> eligible
                                      |              |
                                      v              v
                                  isolated       published
                                      |
                                      v
                                  deleted/rebuilt
~~~

状态不是简单的字符串。每次状态改变都应记录输入对象、输出对象、处理器版本、配置摘要、运行身份、时间、原因和重试标识。`isolated` 表示不进入当前训练候选，不等于对象已经删除；`published` 表示进入某个不可变版本，也不等于所有下游模型已经受到影响评估。

### 2.2 容量账本

可以把总存储需求粗略写成：

~~~math
B_total=B_raw+B_parsed+B_index+B_quarantine+B_versions+B_replay
~~~

`B_raw` 是原始对象，`B_parsed` 是解析和派生结果，`B_index` 是检索、去重和统计索引，`B_quarantine` 是隔离对象，`B_versions` 是保留的不可变版本，`B_replay` 是删除、重洗和失败重跑所需的临时空间。

假设 100 TB 原始媒体和网页解析后膨胀为 1.4 倍，索引和特征占原始量 0.25 倍，隔离对象占 0.1 倍，保留两个版本且每版约占清洗后候选的 0.4 倍，那么容量估算至少要把这些比例作为独立假设记录。它们不是普遍常数，必须通过小批量测量校准。

token 账本也要分层：

~~~math
D_raw=sum_i b_i,
\qquad
D_eligible=sum_i b_i g_i,
\qquad
D_consumed=sum_i b_i c_i
~~~

`b_i` 是按指定 tokenizer 计算的 token 数，`g_i` 表示是否进入候选，`c_i` 表示某次训练是否实际消费以及消费次数。`D_raw`、`D_eligible` 和 `D_consumed` 不能互相替代。上采样会让 `D_consumed` 大于 `D_eligible`，而全量过滤会让 `D_eligible=0`。

### 2.3 幂等和数量守恒

解析任务重试时，同一个原始对象不能被重复计入 token 或 manifest。常见做法是用 `(source_id, object_hash, processor_version, config_digest)` 组成幂等键，并让输出对象的身份可验证。阶段统计要保留输入数、成功数、隔离数、失败数和重试数，满足：

~~~math
N_{in}=N_{success}+N_{isolated}+N_{failed}
~~~

如果任务允许部分处理，还要额外记录重复重试和最终唯一对象数。简单的“任务成功率 100%”不能证明每个输入都被正确处理。

## 3. 来源登记和采集设计

采集层首先解决来源身份和使用边界，再解决网络吞吐。来源登记至少包含来源类型、访问路径、采集时间、许可或授权依据、使用范围、删除方式、隐私风险、内容年龄和责任人。

### 3.1 来源不是 URL 字符串

同一个 URL 在不同时间可能对应不同内容，同一组织也可能有公开网页、登录后页面、用户上传内容和授权数据接口。`source_id` 应稳定指向来源主体或数据集版本，URL 只是对象定位信息。登录状态、访问范围和请求目的也要进入采集记录。

公开可访问不等于允许训练。技术上能下载，只说明当前访问路径可用；是否能够训练、再分发、商业使用或生成派生数据，要依据许可、条款、授权和适用政策判断。无法确认时，数据应进入待审或隔离状态，而不是默认放行。

### 3.2 原始层和处理层分离

原始层保存可回放的对象身份、响应元数据、hash 和必要的来源信息；处理层保存解析、清洗、语言识别、去重、风险和质量事件。解析器升级时，可以在相同 raw snapshot 上重跑，区分来源变化和处理器变化。

原始层也不是无限保存的借口。敏感数据需要最小化、访问控制、保留期限和删除路径。对不需要保存正文的场景，可以只保留必要的 hash、统计和处理状态，但必须确认这些摘要仍足以支持审计和删除映射。

### 3.3 采集停止条件

一个来源即使规模大、质量高，也应在以下情况暂停进入训练：授权范围无法确认，删除请求无法定位，隐私风险无法隔离，污染查询无法完成，或处理器不能稳定解析。停止条件是数据系统的一部分，不是采集团队的失败。

## 4. 解析、清洗与质量塑形

清洗不是把数据变得“看起来干净”，而是把训练分布塑形成适合目标任务的输入。规则、质量模型和人工抽样都只是证据，不能把一个代理分数写成客观真值。

### 4.1 分层清洗

第一层是结构有效性：编码、空文本、坏文件、异常长度、解析失败和损坏媒体。第二层是正文与结构：去导航、广告、模板、重复页脚，同时保留代码、表格、公式和文档层级。第三层是语言、领域、质量和风险分桶。第四层是 PII、秘密、授权和污染隔离。第五层才是按目标任务做质量阈值、采样和下游消融。

不同领域不能使用同一套阈值。短 API 文档、数学定义、代码函数和低资源语言文本可能在通用质量模型上得分低，却对目标能力重要。困惑度高可能是乱码，也可能是公式、代码或新的语言表达；链接比例高可能是模板，也可能是高质量引用文档。

### 4.2 保留率的分母

token 保留率可以写成：

~~~math
R_keep=\frac{sum_i b_i g_i}{sum_i b_i}
~~~

如果原始对象存在且所有对象都被过滤，分母存在，结果是 `0.0`。如果输入集合为空，或没有任何可计量 token，结果应为 `undefined`。这两个状态会触发不同动作：前者通常需要检查阈值或恢复数据，后者需要补充来源或修复计量链路。

风险率也要保留分桶分母。一个总体 PII 命中率很低，不代表高风险来源安全；一个总体质量分很高，不代表低资源语言没有被误删。发布报告至少要给出总体值、语言/领域/来源切片和最差重要切片。

### 4.3 质量变化如何验证

清洗版本至少做两个对照。第一，比较原始、解析、候选和最终版本的数量、token、语言、领域、风险和重复分布。第二，固定模型、tokenizer、训练预算和评估集，只替换清洗版本，观察目标能力、通用能力、安全和污染指标。

如果保留率提高但目标能力下降，可能是保留了更多低信息数据，也可能是以前被误删的困难样本没有恢复。若 validation loss 改善但专项能力退化，可能是分布过度收窄。清洗实验不能只用一个总 loss 结束。

## 5. 去重与污染：两个相邻但不同的问题

训练集内部重复关注有效曝光和数据多样性，训练集与评估集重叠关注评估可信度。两者可以共享候选生成器，但结论、分母和处置不同。

### 5.1 多粒度去重

文档级 exact hash 适合完全相同对象，段落级统计适合网页模板，shingle/Jaccard 和 MinHash/LSH 适合近重复候选，代码还要处理 fork、vendor、生成文件和函数级重复。相似候选不能自动变成删除命令；版本更新、不同语言、不同测试和不同证据可能需要保留。

Jaccard 为：

~~~math
J(A,B)=\frac{|A cap B|}{|A cup B|}
~~~

假设两段文本各有 100 个 shingle，共享 80 个，则 `J=80/(100+100-80)=0.667`。这个数字只说明候选相似，不说明它们的来源、时间和用途相同。生产系统还要测候选召回率、误合并率和人工复核结果。

### 5.2 污染查询集

评估污染查询不能只包含题目原文。代码任务还要包含函数签名、测试样例、参考解和注释；数学任务要包含答案、解析和改写变体；多模态任务要检查 OCR、字幕、ASR、caption 和派生文本。强匹配、近重复和只共享通用短语应分级记录。

污染命中后的正确动作是冻结受影响版本和评估结果，定位命中对象、训练阶段和派生层，再决定移除、隔离、替换私有 holdout 或降低结论强度。删除当前目录不能自动恢复历史评估的可信度。

## 6. Data mixture：训练预算如何塑造能力

Data mixture 是训练分布的一部分，不是把几个文件夹拼接。设第 `m` 个数据池的采样权重为 `alpha_m`，则：

~~~math
L_mix(theta)=sum_m alpha_m E_{x~D_m}[L_theta(x)],
\qquad sum_m alpha_m=1
~~~

不同数据池可以代表通用文本、代码、数学、多语言、领域、合成、偏好和安全。`alpha_m` 不是能力贡献率，因为质量、重复、难度、label mask 和训练阶段会改变有效影响。

### 6.1 有效 epoch

若总消费 token 为 `T`，数据池 `m` 的有效 token 为 `D_m`，采样权重为 `alpha_m`，则近似有效曝光次数为：

~~~math
e_m=\frac{T alpha_m}{D_m}
~~~

小数据池被高比例采样时，`e_m` 可能很高，带来记忆、过拟合、污染放大和风格偏移。报告配比时要同时写权重、池大小、有效 epoch、重复率和下游切片。

### 6.2 配比实验

先做源级或领域级粗粒度消融，再对高价值区间做局部搜索。比较时固定总 token、训练步数或明确说明哪个变量不固定；否则加入数据源后训练更多，提升不能归因于数据质量。结果要同时报告目标能力、通用能力、多语言、安全、事实性、成本和失败样本。

代码比例升高可能提高代码任务，却占用自然语言 token、增加 license 和 secret 风险；安全数据增加可能降低漏拒，却增加误拒；合成数据增加可能改善格式，却造成同质化。配比是多目标约束，不存在脱离目标的固定答案。

## 7. 专项数据的责任边界

### 7.1 代码数据

代码数据同时是语言资料、软件供应链和可执行对象。每条记录要关联仓库、文件、函数/类范围、commit 时间、license、依赖、测试和 secret 状态。样本结构可以是 `docstring-code`、`test-code`、`bug-fix`、`code-explanation` 和 API 使用，但不能把源码字符串当成完整的运行条件。

代码质量至少拆成语法、编译、功能测试、安全扫描和依赖可用性。测试通过率在没有测试样本时是 `undefined`，不是 0；没有测试证据和测试失败是两种不同的问题。执行评估要使用沙箱、资源上限和最小网络权限。

### 7.2 数学与推理数据

数学样本至少包括题目、过程、答案、难度和验证器状态。答案正确不等于过程可靠，过程很长也不等于每一步正确。改写题、难度切片和未见题型能检验模型是否学到结构，而不是记住模板。

推理数据还要保存来源、隐私、安全和发布状态。过程监督、结果验证和是否公开完整轨迹是三个不同决策，不应把它们混为一个字段。

### 7.3 领域数据

医疗、法律、金融等领域数据需要来源权威性、发布日期、适用范围、证据等级、版本、PII 和专家审计。继续预训练可以补术语与文体，SFT 可以学习任务格式，RAG 更适合提供最新、可引用和权限受控的资料；模型参数不会因为看过旧文档就自动获得当前规则。

### 7.4 合成与蒸馏数据

合成数据记录 generator/teacher、输入种子、提示、采样参数、验证器和人工复核。数学、代码、事实、工具和安全样本分别接入专属验证。teacher 越强，错误和风格偏差越可能以更有说服力的形式传播；自然数据锚点仍然需要保留。

### 7.5 偏好与安全数据

偏好数据要记录 prompt、chosen、rejected、rubric、标注者、语言、风险和版本。安全数据必须同时覆盖允许回答、拒绝和安全转向，并分别计算漏拒和误拒的分母。只有拒答样本会教模型把风险词当作捷径，导致正常教育、防御和专业咨询被误拒。

### 7.6 多模态数据

图文、OCR、语音和视频数据的核心是证据对齐。图像与 caption 要语义对应，OCR 要保留坐标和阅读顺序，转录要有时间和说话人边界，视频要绑定镜头、字幕、音频、OCR 和事件。相似度、WER 或字幕准确率都不能替代 grounded 任务和人工抽样。

## 8. 数据价值：从排行榜回到反事实实验

数据源的价值不是永久属性，而是相对于目标模型、训练阶段、已有分布、替代来源、成本和风险的边际贡献。加入变化可以写成：

~~~math
Delta_add_k=U(S cup C_k)-U(S)
~~~

`U` 应包含目标能力、副作用、风险、成本和覆盖。gradient similarity、embedding 近邻、loss 分桶和小模型 proxy 只能生成候选线索；源级消融、固定预算对照和多随机种子复现提供更强的干预证据。Influence 和 Shapley 的思想有帮助，但不应被写成大模型全量 token 的精确因果证明。

数据选择还要保留长尾、自然分布和风险覆盖。单一 benchmark 相似度高的样本可能是污染或模板，低相似度的低资源语言和边界样本可能对产品不可替代。

## 9. 版本、血缘和删除回放

训练引用的不是 `latest/` 目录，而是不可变的整体输入：

~~~math
V_t=(D_t,M_t,P_t,S_t,A_t)
~~~

`D_t` 是内容快照，`M_t` 是 manifest，`P_t` 是处理器和配置，`S_t` 是 schema，`A_t` 是审计和授权记录。只给 shard 打 hash，而不版本化处理器和采样配置，仍然无法复现。

manifest 应包含 shard hash、样本数、token 数、来源、语言、风险和处理版本。lineage 应能从训练样本回到原始对象，也能从一个来源找到受影响的版本、训练运行和发布物。

删除请求至少分为定位、隔离和完成。排除新版本不等于历史版本和模型参数已经消除影响；无命中请求也不等于删除完成。工程系统要分别记录 `unresolved_target`、`isolated`、`future_excluded`、`replayed` 和例外状态，并把法律和产品判断交给有权限的责任人。

## 10. 综合故障诊断：三个回归如何回放

### 10.1 过期引用

现象：总体答案质量上升，但引用过期率增加。

第一步比较新旧数据版本的来源年龄、领域分布、`as_of` 时间和 RAG 索引版本。第二步抽查引用是否来自训练文本而不是当前检索证据。第三步固定模型和提示词，只替换索引或领域数据版本。若问题只在旧文档桶出现，应隔离过期来源或把时效性知识转移到版本化 RAG，而不是盲目增加训练 token。

### 10.2 代码测试下降

现象：代码生成文本更流畅，但隐藏测试通过率下降。

先检查训练版本中是否加入了没有可执行测试的代码池，测试证据是否被错误写成 0，旧 API 文档是否占比上升，代码 fork 是否重复，以及评估题是否被污染。然后做固定总 token 的代码池消融，按语言、依赖和难度切片运行编译与测试。没有测试证据的样本应隔离或补测，不能用语言模型分数替代执行证据。

### 10.3 正常查询误拒

现象：高风险漏拒下降，但正常内部查询也更容易被拒绝。

比较安全数据中应拒答、应答和安全转向三类分母；检查某个语言、领域或关键词桶是否只有拒答样本；核验 rejected 是否把过度拒答当成 chosen；再用正常教育、防御和专业场景做反事实评估。修复通常是补边界允许样本、调整安全偏好权重、重新标注冲突样本和增加多语言回归，而不是继续提高拒答阈值。

### 10.4 证据强度分层

故障归因应分成三层：相关线索、受控干预、重复干预。来源相似度、版本同时变化和错误样本近邻属于相关线索；固定训练配置只替换数据版本属于受控干预；多随机种子、替代来源和独立切片重复得到相同方向，才构成更强证据。报告必须说明结论停在哪一层。

## 11. 发布前的独立检查

发布前至少检查以下对象：训练实际引用的 manifest、schema 和 pipeline digest；授权、PII、污染和删除状态；语言、领域、任务和风险分布；专项数据的测试、验证器、专家或人工抽样；评估集 hash 和污染结果；训练配置、tokenizer、mixture、checkpoint 和环境。

检查结果不要压成一个总开关。可以分别给出：

~~~math
C_data=(C_manifest,C_lineage,C_license,C_privacy,C_contam,C_eval,C_replay)
~~~

每个分量都应带分母、证据、例外和动作。一个版本可能适合内部消融，但因为删除链路未完成而不适合对外发布；也可能质量和授权合格，但评估集污染未解决，不能把 benchmark 结果当作可靠证据。

## 12. 最小可运行综合审计

下面的示例用一组 toy 记录模拟综合数据管线。它不执行真实模型训练，也不代替许可证审查、PII 检测器、代码沙箱、专家复核或删除系统；它只演示如何把样本类型、分母、风险、验证、血缘和动作放在同一份可回放报告中。

代码特意保留四种状态：空输入返回 `None`，有原始对象但全部隔离返回 `0.0`，某一数据类型没有保留样本时其 mixture 为 `None`，缺少安全动作类别时触发补充动作。这样，数字不会把“没有证据”伪装成“没有风险”。

~~~python
from collections import Counter, defaultdict
import hashlib


TARGET_KINDS = {"text", "code", "math", "safety", "multimodal"}
EXPECTED_ACTIONS = {"answer", "refuse", "safe_alt"}


def safe_ratio(numerator, denominator):
    return round(numerator / denominator, 3) if denominator else None


def safe_mean(values):
    return round(sum(values) / len(values), 3) if values else None


def digest(value):
    return hashlib.sha256(value.encode("utf-8")).hexdigest()[:12]


def audit(items, deletion_sources=()):
    raw_tokens = sum(item.get("tokens", 0) for item in items)
    kept, rejected, rows = [], {}, []

    for item in items:
        reason = None
        if not item.get("license_ok", False):
            reason = "license_or_source"
        elif item.get("pii", False):
            reason = "privacy_or_sensitive"
        elif item.get("contam", False):
            reason = "eval_contamination"
        elif not item.get("aligned", True):
            reason = "modality_misaligned"
        elif not item.get("verified", True):
            reason = "missing_task_verification"
        elif not item.get("lineage"):
            reason = "missing_lineage"
        elif item["kind"] == "safety" and item.get("expected_action") not in EXPECTED_ACTIONS:
            reason = "unknown_safety_action"

        row = {"id": item["id"], "kind": item["kind"], "reason": reason or "kept"}
        rows.append(row)
        if reason:
            rejected[item["id"]] = reason
        else:
            kept.append(item)

    raw_kind_tokens = defaultdict(int)
    kept_kind_tokens = defaultdict(int)
    risk_tokens = defaultdict(int)
    alignment_by_kind = defaultdict(list)
    action_raw = Counter()
    action_kept = Counter()

    for item in items:
        raw_kind_tokens[item["kind"]] += item.get("tokens", 0)
        if item["kind"] == "safety":
            action_raw[item.get("expected_action", "unknown")] += 1
    for item in kept:
        kept_kind_tokens[item["kind"]] += item.get("tokens", 0)
        risk_tokens[item.get("risk", "unknown")] += item.get("tokens", 0)
        alignment_by_kind[item["kind"]].append(item.get("alignment", 0.0))
        if item["kind"] == "safety":
            action_kept[item.get("expected_action", "unknown")] += 1

    deletion_hits = {
        source: [item["id"] for item in items if item.get("source") == source]
        for source in deletion_sources
    }
    kept_tokens = sum(item.get("tokens", 0) for item in kept)
    reasons = dict(sorted(Counter(rejected.values()).items()))
    kind_retention = {
        kind: safe_ratio(kept_kind_tokens[kind], raw_kind_tokens[kind])
        for kind in sorted(raw_kind_tokens)
    }
    mixture = {
        kind: safe_ratio(kept_kind_tokens.get(kind, 0), kept_tokens)
        for kind in sorted(raw_kind_tokens)
    }
    action_coverage = {
        action: safe_ratio(action_kept[action], action_raw[action])
        for action in sorted(EXPECTED_ACTIONS | set(action_raw))
    }
    report = {
        "kept_ids": [item["id"] for item in kept],
        "rejected": dict(sorted(rejected.items())),
        "reason_counts": reasons,
        "retention": safe_ratio(kept_tokens, raw_tokens),
        "kind_retention": kind_retention,
        "mixture": mixture,
        "avg_alignment": {
            kind: safe_mean(values) for kind, values in sorted(alignment_by_kind.items())
        },
        "action_coverage": action_coverage,
        "deletion_hits": deletion_hits,
        "manifest": {
            shard: {
                "sample_count": sum(item.get("shard") == shard for item in kept),
                "tokens": sum(item.get("tokens", 0) for item in kept if item.get("shard") == shard),
                "checksum": digest(";".join(sorted(item["id"] for item in kept if item.get("shard") == shard))),
            }
            for shard in sorted({item.get("shard", "unknown") for item in kept})
        },
    }
    checks = {
        "retained_samples_present": bool(kept),
        "kind_coverage": set(kept_kind_tokens) >= {"text", "code", "math", "safety"},
        "license_privacy_blocked": reasons.get("license_or_source", 0) >= 1 and reasons.get("privacy_or_sensitive", 0) >= 1,
        "contamination_blocked": reasons.get("eval_contamination", 0) >= 1,
        "task_verification_observed": reasons.get("missing_task_verification", 0) >= 1,
        "lineage_observed": all(item.get("lineage") for item in kept),
        "safety_actions_balanced": all(
            action_raw[action] > 0 and action_kept[action] > 0
            for action in EXPECTED_ACTIONS
        ),
        "deletion_targets_resolved": bool(deletion_hits) and all(bool(hits) for hits in deletion_hits.values()),
    }
    actions = []
    if not items:
        actions.append("restore_or_collect_source_records")
    if items and not kept:
        actions.append("restore_nonempty_training_candidate_pool")
    if not checks["kind_coverage"]:
        actions.append("rebalance_missing_training_kinds")
    if not checks["safety_actions_balanced"]:
        actions.append("add_answer_refusal_and_safe_alt_samples")
    if not checks["deletion_targets_resolved"] and deletion_hits:
        actions.append("resolve_deletion_targets_before_release")
    if reasons.get("missing_lineage", 0):
        actions.append("repair_lineage_before_claiming_reproducibility")
    if reasons.get("missing_task_verification", 0):
        actions.append("add_tests_or_domain_verifiers")
    decision = "continue_to_small_ablation" if all(checks.values()) else "hold_for_data_repair"
    report["checks"] = checks
    report["actions"] = actions
    report["decision"] = decision
    return report
~~~

### 12.1 为什么要测试空集和全量过滤

空集常出现在上游任务没有产出、权限过滤全部拒绝或分区查询没有命中。此时 `None` 代表没有可解释的分母；全量过滤则表示输入存在但没有任何对象通过，保留率为 `0.0`，通常需要恢复或调整处理。把两者都写成 0，会让监控无法区分“没有数据”和“数据全部被拒绝”。

同样，只有拒答样本而没有应答样本，不能计算安全边界的平衡；只有高质量代码但没有测试证据，也不能报告“代码数据质量为 0”，而应报告 `missing_task_verification`。审计代码的价值就在于把这些状态显式化。

## 13. 发布、回滚与可回放实验

一个数据版本进入训练前，至少要经过内容、处理、风险、授权和评估五类确认。内容确认 manifest 和 shard hash；处理确认 processor、schema 和配置；风险确认 PII、污染、许可证和安全状态；授权确认使用范围；评估确认训练和评估引用没有交叉污染。

### 13.1 发布不是复制目录

发布动作应生成不可变版本、manifest、统计报告、异常队列、审批记录和训练引用。训练入口不接受会移动的 `latest` 路径，只接受版本 ID 或 digest。发布后若发现问题，创建 child version 或 copy-on-write 版本，记录 parent 和变更摘要。

### 13.2 回滚对象

回滚也要区分层级：可以回滚数据版本、处理规则、采样权重、训练 checkpoint、评估协议或产品路由。回滚模型而不回滚其数据和评估引用，可能让问题再次出现；回滚数据而不重新评估，也不能声称行为已经恢复。每个回滚动作要写出固定了哪些变量、改变了哪些变量以及仍然未知什么。

### 13.3 删除回放

收到删除请求时，先定位 source/hash/user 与版本和派生对象的关系，再阻止对象进入未来快照，随后重建受影响 shard、索引和统计。历史训练运行是否需要重训，取决于适用政策、模型用途和风险评估；工程系统只提供影响范围和可验证状态，不把一个字段写成普遍法律结论。

## 14. 常见失败模式

### 14.1 把原始规模当训练规模

原始 TB、解析后字节、候选 token、有效 token 和实际消费 token 是不同对象。修复时建立容量和 token 账本，明确 tokenizer、过滤状态和重复曝光。

### 14.2 把质量分当事实

质量模型可能偏爱长英语网页，误伤代码、公式和低资源语言。修复时按语言、领域、来源和任务切片抽样，并用下游消融确认阈值影响。

### 14.3 把相似度当污染结论

相似候选可能是自然共用表达、版本更新或真正泄漏。修复时保存命中片段、来源、时间、答案和人工复核状态，并分级处理。

### 14.4 把拒答率当安全能力

拒答率上升可能只是误拒增加。修复时保留应答、拒答、安全替代和澄清分母，按语言、风险、工具和领域分桶评估。

### 14.5 把 teacher 强当合成正确

teacher 会传播错误、风格和评测污染。修复时加入任务专属验证器、自然数据锚点、授权字段和版本回放。

### 14.6 把删除当前文件当完成

旧版本、缓存、索引、embedding 和训练运行可能仍然包含对象。修复时建立影响图，分别记录定位、隔离、派生处理和完成状态。

### 14.7 把一个总体指标当发布依据

总体分数可能掩盖高风险小桶。修复时报告分母、切片、最差重要桶、置信区间和异常队列，不能用默认值填满空字段。

## 15. 资料与证据边界

本章引用的资料承担不同角色。C4、The Pile、RefinedWeb、FineWeb、Dolma 和 DCLM 说明公开语料的构成、过滤、规模或配方实验；它们的统计属于对应论文和版本，不是所有模型的固定比例。Datasheets for Datasets 和 Model Cards 提供数据集与模型文档框架，不能替代当前项目的授权或隐私事实。

W3C PROV、DVC 和 OpenLineage 帮助理解实体、活动、版本和运行事件如何建模；官方工具文档能说明接口和实现边界，不能自动证明项目已经完成治理。NIST AI RMF 和 Generative AI Profile 提供风险管理语言，不是某个数据集的法律证明。Influence Functions、Data Shapley、DoReMi 和 LESS 支持归因、估值或配比实验的研究背景，但任何迁移都要重新确认模型规模、目标、数据版本、评估集和随机性。

主要入口如下：

1. [C4](https://arxiv.org/abs/2104.08758)、[The Pile](https://arxiv.org/abs/2101.00027)、[RefinedWeb](https://arxiv.org/abs/2306.01116)、[Dolma](https://arxiv.org/abs/2402.00159) 和 [DCLM](https://arxiv.org/abs/2406.11794)：公开语料、过滤和配方研究。
2. [Datasheets for Datasets](https://arxiv.org/abs/1803.09010) 与 [Model Cards](https://arxiv.org/abs/1810.03993)：数据集和模型文档框架。
3. [W3C PROV](https://www.w3.org/TR/prov-overview/)、[DVC](https://dvc.org/doc) 与 [OpenLineage](https://openlineage.io/docs/)：版本和血缘工程入口。
4. [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) 与 [NIST Generative AI Profile](https://www.nist.gov/itl/ai-risk-management-framework/ai-rmf-generative-ai-profile)：风险治理入口。
5. [Influence Functions](https://arxiv.org/abs/1703.04730)、[Data Shapley](https://arxiv.org/abs/1904.02868)、[DoReMi](https://arxiv.org/abs/2305.10429) 和 [LESS](https://arxiv.org/abs/2402.04333)：归因、估值和数据配比研究。

阅读这些入口时，要区分论文实验、数据集或模型卡自述、标准、官方接口说明、当前系统实测和法律判断。正文中的综合审计 demo 是教学抽象，帮助读者理解对象和分母；它不应被误读为真实数据平台、许可证判断器或模型质量保证。

## 16. 结语：数据系统是模型能力的证据链

大模型数据工程不是把更多文件搬进训练集，而是在目标、覆盖、质量、配比、风险、成本和治理之间建立可回放的证据链。一个数据版本只有在对象身份稳定、处理过程可追溯、风险和授权状态明确、评估关系可信时，才值得进入下一轮训练实验。

当技术问答出现过期引用时，回到来源年龄、索引版本和证据时间；当代码测试下降时，回到测试证据、API 版本和污染；当安全误拒增加时，回到应答/拒答分母、标签规范和边界样本。每次回归都先固定能固定的变量，再做小规模、可撤销的干预实验。

成熟的数据系统不会把未知值填成好看的 0 或 1，也不会把相似度、训练 loss 或一个 benchmark 当成最终结论。它保留来源、版本、分母、例外和责任人，让数据能够被解释、修复、删除和重新验证。只有这样，模型能力才不只是一次训练结果，而是可以持续负责的工程产物。
