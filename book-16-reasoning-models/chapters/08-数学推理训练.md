# 第八章：数学推理训练：从题目、步骤到可迁移能力

数学是训练 reasoning model 的重要场景，因为很多数学任务有明确答案、相对清晰的中间结构和可执行的验证方法。它可以让研究者观察模型是否会读题、建模、推导、计算、检查条件和表达结论，而不只是看最后一个数字。

数学也很容易制造错觉。模型可能背过公开题目和解析，可能学会某类题的模板，可能写出很长却不成立的证明，也可能在最终答案碰巧正确时掩盖错误过程。一个数学 benchmark 分数不能自动证明模型拥有通用 reasoning 能力，更不能直接证明它能处理开放世界中的证据、工具和权限问题。

因此，数学推理训练应该被理解为一个闭环：定义任务，收集题目，生成或标注解法，验证答案和步骤，控制难度与模板分布，训练生成器和 verifier，使用独立评估集检查迁移，再根据失败类型更新数据。只增加题目数量而不检查这些环节，往往会把数据噪声和模板偏差一起放大。

本章从初学者能够理解的“答案为什么不够”开始，逐步讲到数据 schema、答案归一化、步骤监督、合成题、难度 curriculum、程序和符号验证、多解法、错误纠正、SFT/PRM/RL、污染审计、评估和成本。最后的 demo 不是训练一个真实模型，而是模拟训练集进入实验前应做的审计。

## 0.1 一个答案正确但训练价值很低的样本

考虑下面两条解法。题目是：一个水箱每分钟进水 3 升、出水 1 升，需要增加 20 升，问需要多少分钟。

~~~text
解法 A：
净流入速度 = 3 - 1 = 2 升/分钟。
需要增加 20 升，所以时间 = 20 / 2 = 10 分钟。

解法 B：
答案是 10 分钟。
~~~

如果只监督最终答案，A 和 B 都可以被标记为正确。可是 A 展示了可检查的建模和计算，B 没有提供任何能帮助模型学习的中间结构。若题目换成出水速度更大、单位改变或需要判断是否能注满，B 几乎没有迁移价值。

再看第三条：

~~~text
解法 C：
净流入速度 = 3 + 1 = 4 升/分钟。
时间 = 20 / 4 = 5 分钟。
最后把答案写成 10 分钟。
~~~

C 的最终答案碰巧对，但过程错误。把它当成正确示范，会让训练目标相互冲突：模型一方面被要求学会加法式的错误净速度，另一方面又被要求输出 10 分钟。

数学训练的第一个原则因此很简单：最终答案是必要信号，但不是完整监督。任务需要什么样的推理，数据就必须尽可能表达什么样的中间约束。

## 0.2 资料与证据边界

GSM8K 和 `Training Verifiers to Solve Math Word Problems` 提供了小学数学文字题和结果验证器研究的入口；MATH 数据集覆盖更广泛的竞赛数学题型，适合说明题型和难度的扩展，但 benchmark 上的结果不能自动外推到真实应用。

`Let's Verify Step by Step` 和 PRM800K 是过程监督与数学步骤评价的重要公开资料。它们支持“给中间步骤提供反馈”的研究背景，不意味着所有步骤标签都没有分歧，也不意味着同一过程模型适用于所有领域。

DeepSeekMath 和 OpenWebMath 提供了数学语料、数学预训练和数据规模化的公开研究入口；AlphaGeometry 代表了神经模型与符号推理系统结合处理几何问题的一条路线；NuminaMath 的公开数据页可以帮助读者了解社区数据资源的组织方式。论文、数据页和仓库各自能证明的内容不同，不能把名称、数据规模和模型能力混为一谈。

DeepSeek-R1 的公开论文可以作为 reasoning 训练、验证和推理时计算关系的研究入口。本章只引用其公开论文能够支持的研究背景，不把它或任何其他公开模型的内部数据过滤、奖励细节和生产路由写成确定事实。

本章的公式是教学定义，代码和样本是人为构造。任何数字都应注明它是论文实验、公开数据统计、教学 demo 输出还是目标系统复测。

## 0.3 初学者视角和专家视角

初学者先记住四个层次：

1. 题目是否被正确理解；
2. 过程中的每一步是否成立；
3. 最终答案是否与题目和单位一致；
4. 换一种题面或条件后是否仍然有效。

专家还要追问：样本来自哪里，训练和评估是否有重叠，步骤边界是否稳定，自动验证覆盖了什么，合成题模板是否泄漏，错误标签是否定位了根因，训练损失是否把长答案当成质量，难度切片是否真的改善，额外计算的单位成功成本是多少。

## 1. 为什么数学适合训练 reasoning

### 1.1 可定义的成功事件

很多数学任务可以把成功写成数值、符号、集合或证明约束。例如：

- 数值题要求答案在容差内相等；
- 方程题要求代入原方程成立；
- 组合题要求计数值与穷举或递推一致；
- 几何题要求结论由条件和定理推出；
- 形式化证明题要求检查器接受证明项。

成功事件越清晰，自动筛选和对比实验越容易。但“可验证答案”不等于“可验证过程”。数值相同可能来自错误方法或碰巧抵消的错误。

### 1.2 结构化的中间操作

数学推理通常包含相对稳定的操作：提取条件、定义变量、列方程、变形、代入、分类讨论、检查边界和归纳。模型可以在这些操作上得到比“整题对/错”更细的反馈。

### 1.3 可构造变体

参数化题目可以改变数字、实体、单位和条件，产生一组结构相近但答案不同的变体。变体有助于测试模型是否学会了关系，而不是记住题面和答案。

但变体不是简单替换数字。替换可能改变可行性、整数性、解的个数和证明条件；生成后必须重新验证题目和解法。

### 1.4 难度可以分解

难度可以来自步骤长度、概念数量、分支数量、抽象程度、计算规模、证明要求或自然语言歧义。把难度只定义成“题目长短”会误判：短的反例题可能比长的机械计算更难。

## 2. 数学样本的数据对象

### 2.1 基本 schema

第 `i` 道训练题可以抽象为：

~~~math
m_i=(x_i,y_i^\star,z_i,q_i,d_i,t_i,s_i,r_i)
~~~

其中：

- `x_i` 是题目文本和必要条件；
- `y_i^star` 是参考答案或答案等价类；
- `z_i` 是解题步骤序列；
- `q_i` 是步骤正确性或错误影响标签；
- `d_i` 是难度信息；
- `t_i` 是题型，例如代数、几何或证明；
- `s_i` 是来源、模板或生成器标识；
- `r_i` 是污染、重复、验证失败和争议等风险元数据。

一个可读的 JSON 记录可以是：

~~~json
{
  "id": "water_tank_001",
  "problem": "进水 3 升/分钟，出水 1 升/分钟，增加 20 升需要多久？",
  "answer": "10 分钟",
  "answer_set": ["10", "10 分钟"],
  "steps": [
    {
      "id": "s1",
      "text": "净流入速度 = 3 - 1 = 2 升/分钟",
      "correct": true,
      "relevant": true,
      "error_type": null
    },
    {
      "id": "s2",
      "text": "时间 = 20 / 2 = 10 分钟",
      "correct": true,
      "relevant": true,
      "error_type": null
    }
  ],
  "topic": "word_problem",
  "difficulty": 1,
  "source": "expert_review",
  "verification": "numeric_substitution",
  "contamination_risk": false
}
~~~

schema 的目的不是规定唯一格式，而是把题目、答案、步骤、来源和风险分开。没有这些字段，后续很难判断一个失败来自题目本身、解析、模型还是 verifier。

### 2.2 答案等价类

数学答案不能总用字符串完全匹配。`0.5`、`1/2` 和 `50%` 在特定单位和语境下可能等价；`x=2` 和 `2=x` 也可能表示同一个结论。

答案归一化函数可以写成：

~~~math
\operatorname{norm}(y)=
\operatorname{canonicalize}(y;\mathcal{U},\mathcal{S},\mathcal{T})
~~~

`U` 表示单位规则，`S` 表示符号或表达式规则，`T` 表示文本和格式规则。归一化过宽会把不同答案错误合并，过窄会把正确表达判为错误。

对有限的数值答案还需要非负容差：

~~~math
|\hat y-y^\star|
\le
\epsilon_{\mathrm{abs}}
+\epsilon_{\mathrm{rel}}|y^\star|
~~~

`\epsilon_{\mathrm{abs}}\ge0` 和 `\epsilon_{\mathrm{rel}}\ge0` 应根据量纲、数值规模和任务要求设置。金融金额、几何长度和近似数值不能随意使用同一个容差；如果参考值、预测值或容差不是有限数，这个比较本身就没有意义。

### 2.3 题目条件和解空间

题目不只是字符串。可以把它解析成条件集合 `C(x)`、目标 `G(x)` 和允许的答案类型 `Y(x)`：

~~~math
\mathcal{P}(x)
=
\{y\in\mathcal{Y}(x): y\text{ satisfies }C(x)\text{ and }G(x)\}
~~~

如果题目有多个解，参考答案不应只保留一个字符串；如果题目条件不充分，正确答案可能是“无法确定”或一个解集。数据 schema 必须表达这些情况，否则训练会惩罚合理的拒答或多解表达。

## 3. 结果监督为什么不够

### 3.1 最终答案损失

当有效答案 token 数 `M_{\mathrm{ans}}>0`，且每个参考 token 的概率满足 `0<P_\theta(y_{ij}^\star\mid\cdot)\le1` 时，只训练题目到答案，可以使用答案 token 的负对数似然：

~~~math
\mathcal{L}_{\mathrm{ans}}(\theta)
=
-\frac{1}{M_{\mathrm{ans}}}
\sum_i\sum_{j=1}^{L_i^y}
\log P_\theta(y_{ij}^\star\mid x_i,y_{i,<j}^\star)
~~~

其中 `L_i^y` 是第 `i` 个答案的有效 token 数，`M_{\mathrm{ans}}=\sum_iL_i^y`；如果训练目标包含参考解法，也可以把步骤放进条件，但最终标签仍然只告诉模型结论是否符合答案。`M_{\mathrm{ans}}=0` 时损失没有定义；不能把空答案或被 mask 掉的样本当成零损失。

### 3.2 过程监督损失

设 `q_ij\in\{0,1\}` 是第 `i` 题第 `j` 步的正确性标签，`0<\hat q_{ij}<1` 是 PRM 的预测概率，且有效步骤总数 `M>0`，可以使用二元交叉熵：

~~~math
\mathcal{L}_{\mathrm{proc}}(\phi)
=
-\frac{1}{M}
\sum_{i,j}
\left[
q_{ij}\log \hat q_{ij}
+(1-q_{ij})\log(1-\hat q_{ij})
\right]
~~~

`M` 是所有有效步骤数量。工程实现通常会对概率做数值裁剪，避免 `\log 0`；`M=0` 时损失没有定义。若后续步骤只是第一处错误的连锁结果，应增加 `affected` 标签或降低其权重，不要无条件当成独立错误。

### 3.3 两种互相打脸的样本

最终答案正确、过程错误的样本会让结果监督产生假正例；过程正确、最后格式或单位错误的样本会让结果监督产生假负例。数据审计应显式报告两类样本数量，而不是假设它们不存在。

### 3.4 过程监督的边界

过程标签也不是数学真理。一个证明步骤是否“必要”可能存在多个合理判断；一个局部变换在错误前提下可能算术正确；一条简短证明可能省略读者已经熟知的引理。过程监督必须先定义任务契约，再定义标签含义。

## 4. 步骤数据如何构造

### 4.1 专家解法

专家解法适合提供高质量参考路径、证明结构和错误说明。它的成本高，且专家可能倾向于使用自己熟悉的表达方式。收集时应鼓励多种可证明正确的解法，避免把某一种风格当成唯一真值。

### 4.2 模型生成与人类筛选

模型可以大量生成候选，再由规则、数学工具和人类筛选。筛选不能只看最终答案；应检查条件抽取、关键变换、单位、边界和引用的完整性。

模型初标会降低成本，但会把初标模型的错误带入训练集。人类复核应优先覆盖低置信度、模型分歧、长轨迹、证明题、高难度和已知 hard negative。

### 4.3 程序生成

程序可以生成参数化题目、计算答案并记录生成过程。例如先生成整数方程，再用解析器求解，最后把题目和解法写成文本。程序生成的优点是规模、可复现和答案验证；缺点是题目可能机械、模板集中或偏离真实分布。

程序生成器也需要测试。应检查参数边界、不可行实例、答案多解、整数性和题面语义。如果生成器本身有 bug，规模化会把错误快速扩散。

### 4.4 多源混合

真实训练集可以混合教材题、竞赛题、合成题、错误纠正题、证明数据和工具轨迹。每个来源要有 source id、授权信息、题型、难度和验证状态，切分时避免同一模板或参数家族跨 train/test 泄漏。

## 5. 合成数学题：规模和真实感的交换

### 5.1 合成题的价值

合成题可以精确控制数字、步骤数、分支数和错误类型，也能覆盖稀有题型。它特别适合构造反事实：只改变一个条件，观察模型是否改变对应结论。

### 5.2 模板化风险

如果训练集中的题目都来自少数模板，模型可能记住词汇、数字位置和固定解法。模板多样性可以用：

~~~math
D_{\mathrm{template}}
=
\frac{|\{s_i\}_{i=1}^{N}|}{N}
\qquad (N>0)
~~~

`s_i` 是模板或生成器标识。这个比率越高，不一定越好；模板太多但题型质量低也没有价值。它需要和题型覆盖、难度覆盖、语义去重和变体迁移一起看。

### 5.3 生成后的验证

合成数据至少需要四层检查：

1. 题面是否语义完整；
2. 参考答案是否满足条件；
3. 解法中的每一步是否成立；
4. 题目是否与现有训练和评估数据重复。

数值求解器通过只能证明它检查的方程成立，不代表自然语言题面没有歧义。必要时要让另一套解析器或人类抽查题面。

### 5.4 参数变体和真正泛化

变数字容易，变结构难。好的测试不仅改变数字，还改变实体顺序、叙述风格、单位、条件顺序、干扰信息和问题目标。对证明题，则应改变命题形式、辅助构造和定理组合。

## 6. 难度和 Curriculum

### 6.1 难度不只是步骤长度

数学题的难度可以来自：

- 计算规模；
- 概念数量；
- 多步依赖；
- 分类讨论；
- 边界条件；
- 证明或构造要求；
- 自然语言歧义；
- 多解和反例；
- 自动验证难度。

因此一个四步证明题可能比十步机械计算更难。难度标签应来自题目结构、专家判断、历史错误率或多个指标，而不是只由文本长度决定。

### 6.2 分级训练

一个可能的课程顺序是：

~~~text
基础算术 -> 一步代数 -> 多步代数 -> 文字题
-> 几何计算 -> 组合计数 -> 证明与构造 -> 竞赛难题
~~~

课程学习可能让模型先建立稳定操作，再处理长链和抽象约束；但如果课程过于人工，模型可能只会按训练顺序解决问题。评估时要打乱题型顺序，并测跨级迁移。

### 6.3 混合比例和难例采样

训练集不一定要严格从易到难。实践中常用基础样本保持稳定性，同时提高 hard case、错误步骤和新题型的采样比例。采样权重改变了训练分布，应记录有效样本数和各切片曝光量。

### 6.4 课程的失败

课程太简单会造成训练分布和真实难题脱节；跳跃太大可能让模型在基础操作上不稳定；只优化高难题会降低简单题的格式和事实可靠性。课程效果必须用独立的 easy、medium、hard 和跨题型评估验证。

## 7. 数学 verifier 和自动检查

### 7.1 答案 verifier

答案 verifier 检查最终值或表达式，例如代入方程、比较符号表达式、检查单位和归一化答案。它成本低、目标清晰，但只能判断终局。

### 7.2 过程 verifier

过程 verifier 判断步骤或前缀是否成立。它能定位第一处错误、为搜索剪枝和训练提供信号，但需要步骤切分、标注和校准。

### 7.3 符号和数值工具

符号工具可以化简、求解和证明部分恒等式；数值工具可以随机代入、穷举小规模空间和检查边界。随机测试通过不等于普遍证明，穷举小规模通过也不等于大规模算法正确。

### 7.4 形式化证明系统

形式化系统可以提供更硬的证明检查，但需要把自然语言题目和解法编译成形式语言。形式化成功证明了形式项被系统接受，不一定证明模型正确理解了原始题意。

### 7.5 LLM verifier

LLM verifier 对自然语言推导覆盖更广，却可能被长答案、格式、自信语气和错误但合理的局部步骤欺骗。它应与程序、符号、答案检查和人工抽查组合，不能成为唯一裁判。

### 7.6 验证覆盖率

设第 `i` 个样本可以被至少一种可靠自动方法检查时 `v_i\in\{0,1\}`，且有效样本数 `N>0`，自动验证覆盖率为：

~~~math
C_{\mathrm{verify}}
=
\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}[v_i=1]
~~~

`N=0` 时覆盖率没有定义。覆盖率高只表示存在自动信号，不表示证明完整；覆盖率低也不表示样本无价值，而是说明需要更谨慎的人工或模型判断。

## 8. 多解法与错误纠正

### 8.1 多种正确方法

同一道题可能有代数、几何、构造、归纳、反证和穷举等解法。多解法数据可以降低模型对单一模板的依赖，也给 test-time search 提供不同分支。

多解法的标签应关注是否满足题目约束和结论，而不是是否复现参考顺序。对于证明任务，可以把关键引理和依赖关系结构化，避免只按文字相似度判断。

### 8.2 第一处错误

设第 `i` 条轨迹的步骤标签为 `q_ij`，且步骤编号从 1 开始；当轨迹至少有一个错误步骤时，第一处错误位置为：

~~~math
e_i^\star=\min\{j\in\{1,\ldots,L_i\}:q_{ij}=0\}
~~~

没有错误步骤时，`e_i^\star` 不存在，应记录 `None`，不能把它编码成 0 或某个位置。第一处错误比“错误步骤总数”更适合修复。后续步骤可能只是错误前提的连锁后果，应记录 `affected` 或 `downstream`，而不是重复惩罚。

### 8.3 错误类型

数学训练可以分开记录：读题、变量定义、公式选择、代数变形、计算、单位、边界、分类讨论、偷换概念和未证结论。分类应服务于下一轮数据和模型改进，不能只为报告增加标签。

### 8.4 纠错任务

一个纠错样本可以组织为：

~~~text
题目 + 错误解法
-> 找到第一处错误
-> 解释为什么错误
-> 给出最小修正
-> 重新验证最终答案
~~~

“最小修正”很重要。让模型每次都重写整道题，无法判断它是否真的定位了根因，也会增加无关文本。

## 9. 训练路线：SFT、PRM 和 RL

### 9.1 SFT 学什么

监督微调可以使用题目—解法—答案样本，让模型学习题型表达、步骤顺序和答案格式。标签通常只在 assistant 解法部分计算，避免把题目和元数据当成目标输出。

SFT 质量取决于参考解法。错误或过度模板化的解法会被模型模仿；长解法不一定比短解法好，需要控制步骤功能和答案一致性。

### 9.2 PRM 学什么

PRM 使用步骤标签、偏好或程序反馈，学习判断中间过程。它可以用于数据过滤、候选重排、搜索和错误定位。PRM 训练数据要保留 hard negative、多解法和第一处错误，否则会学到表面风格。

### 9.3 Outcome reward 和 process reward

最终答案奖励可以表示为 `R_outcome`，步骤奖励可以表示为 `R_process`。一个教学组合是：

~~~math
R
=
\lambda R_{\mathrm{process}}
+(1-\lambda)R_{\mathrm{outcome}}
~~~

`lambda` 越高，训练越重视局部步骤；越低，越重视终局。实际使用还要处理奖励尺度、轨迹长度、非法步骤和安全约束。

### 9.4 数学 RL 的风险

模型可能优化 verifier 喜欢的格式、猜最终答案、重复高分措辞或利用检查器漏洞。若代理奖励提高而独立数学质量不提高，就出现目标错配：

~~~math
\Delta R_{\mathrm{proxy}}>0
\quad\not\Rightarrow\quad
\Delta Q_{\mathrm{math}}>0
~~~

因此必须保留独立题、变体题、证明题、工具检查和人工抽查。

## 10. 数学评估：从答案分数到迁移

### 10.1 最终答案准确率

~~~math
A_{\mathrm{ans}}
=
\frac{1}{N}
\sum_{i=1}^{N}
\mathbb{1}[\hat y_i=y_i^\star]
~~~

这里要求有效评估样本数 `N>0`；`N=0` 时准确率没有定义。它是必要指标，但不是充分指标。报告时要说明答案归一化、数值容差、多解处理和是否使用工具。

### 10.2 步骤准确率

~~~math
A_{\mathrm{step}}
=
\frac{
\sum_{i,j}\mathbb{1}[\hat q_{ij}=q_{ij}]
}{
\sum_iL_i
}
~~~

公式中的 `L_i` 是第 `i` 个样本有效步骤数，分母必须大于 0；没有有效步骤时，步骤准确率没有定义。步骤准确率容易被大量简单正例抬高，应同时报告错误类召回、第一处错误和按题型分组的结果。

### 10.3 第一处错误准确率

设 `E` 是存在错误步骤的样本集合：

~~~math
A_{\mathrm{first}}
=
\frac{1}{|E|}
\sum_{i\in E}
\mathbb{1}[\hat e_i=e_i^\star]
~~~

当 `|E|=0` 时，第一处错误准确率没有定义。还可以报告位置误差和无错误样本的误报率，避免把“没有错误”和某个整数位置混为一谈。

### 10.4 难度和题型切片

对难度组 `G_g`，准确率为：

~~~math
A_g
=
\frac{
\sum_{i\in G_g}\mathbb{1}[\hat y_i=y_i^\star]
}{|G_g|}
~~~

当 `|G_g|>0` 时，按难度组 `G_g` 计算准确率；空切片没有定义。至少按 easy、medium、hard 和 algebra、geometry、word problem、combinatorics、proof 分组。平均分提升而 proof 下降，是重要回归，不应被平均值掩盖。

### 10.5 变体和反事实

测试题面改写、数字替换、单位变化、干扰条件、问题顺序和目标变化。若模型只记住表面模板，反事实会暴露它。

要注意变体之间的污染：同一题的近邻版本不能随机分散到训练和测试，否则结果会过于乐观。

### 10.6 多次采样和推理时预算

测量 greedy、self-consistency、verifier reranking 和 search 在不同预算下的曲线。报告候选中存在正确答案的比例和最终选择准确率，区分生成能力与评分能力。

### 10.7 成本和可复现性

记录总 token、模型调用、工具、verifier、延迟、硬件、随机种子、版本、答案解析和数据切分。没有这些信息，数学 benchmark 数字很难复现和公平比较。

## 11. 数据污染与切分

### 11.1 污染来源

数学题面、答案和解析常出现在公开题库、论坛、博客、课程和代码仓库。污染还可能来自同一题的改写、参数化模板和模型生成的题解。

训练污染率可以定义为：

~~~math
R_{\mathrm{contam}}
=
\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}[o_i=1]
~~~

`o_i=1` 表示样本与评测题面、答案、解析或高相似变体存在重叠风险。实际检测需要文本、公式、结构和模板多层去重，不能只做字符串匹配。

### 11.2 按来源切分

同一作者、教材、竞赛、模板或参数族应尽量整体切分。随机按题目切分会让相近题目同时出现在 train 和 test，导致模型只需复用模式。

### 11.3 时间切分和新题

时间切分可以减少已公开题目污染，但新题也需要验证质量。真正的外推评估应包含题型变化、题面风格变化和新组合，而不是只依赖一套熟悉 benchmark。

### 11.4 负结果也要记录

如果某种合成数据让平均分上升却让变体题下降，这个结果很有价值。实验记录不应只保存最好的 checkpoint 和最好的切片，否则训练方向会被选择偏差掩盖。

## 12. 常见失败模式

### 12.1 背题和模板匹配

模型看到熟悉词汇和数字结构就套用解法，换顺序或加入否定条件后失败。反事实、模板外测试和结构化错误分析可以发现它。

### 12.2 长步骤但逻辑错误

训练数据或 verifier 把长度、编号和术语当成质量。应做等长度正负样本、删掉冗余解释的消融和独立数学检查。

### 12.3 答案碰巧正确

计算中有两个错误互相抵消，或模型猜中了常见答案。过程标签、不同参数变体和中间工具检查可以识别这种假成功。

### 12.4 证明跳步

模型使用未证明结论、漏掉除零条件或默认图形关系。数值抽样可能发现部分反例，但不能替代完整证明审查。

### 12.5 Verifier 被欺骗

LLM verifier 偏好格式和自信语气，程序 verifier 覆盖不足，符号 verifier 验证了错误前提。多重验证和 hard negative 是基本修复方向。

### 12.6 合成分布过窄

模型在合成题上学习了生成器模板，迁移到教材、竞赛和自然语言变体时下降。数据混合和模板外评估可以缓解。

### 12.7 Curriculum 只提升 easy

训练顺序让简单题更稳定，却没有改善证明和组合难题。需要提高 hard slice 的有效曝光，并单独观察简单题回归。

### 12.8 只优化 benchmark

模型为公开题库调参，最终结果在熟悉集合上变好，新的题型、反事实和真实任务没有改善。评估必须包含独立新题和迁移任务。

## 13. 综合案例：合同金额中的数学训练闭环

### 13.1 把合同问题转成数学任务

一份合同包含基础金额 100,000 元、折扣 5% 和税率 6%。训练样本不应只写最终金额 100,700，还应记录：

~~~text
步骤 1：确认基础金额来自第 3 页。
步骤 2：折后金额 = 100000 × (1 - 0.05) = 95000。
步骤 3：含税金额 = 95000 × (1 + 0.06) = 100700。
步骤 4：核对币种、版本和引用页码。
~~~

这是数学计算、文档证据和业务状态的组合任务。只训练算术，模型可能算对数字却把旧合同的税率或错误页码带入结果。

### 13.2 错误样本

应构造：税率 60% 的比例错误、折扣加而不是减、含税与未税混淆、单位和币种错误、引用存在但不支持数字、过程正确但输出 schema 错误。每种错误都要有明确第一处错误和修复目标。

### 13.3 验证层次

数值 verifier 检查乘法，文档 verifier 检查页码支持，schema verifier 检查字段，业务规则检查金额和审批状态。任何一层失败都不能被其他分数简单抵消。

### 13.4 训练和上线的边界

训练数据可以让模型学会计算和证据表达；上线系统仍需要实时合同版本、权限、工具和人工复核。数学模型在静态题目上的高准确率不能授权真实付款。

TARGET_TOPICS = {"algebra", "word_problem", "geometry", "combinatorics", "proof"}


def require(condition, message):
    if not condition:
        raise ValueError(message)


def ratio(numerator, denominator):
    require(type(numerator) is int and numerator >= 0, "numerator must be a non-negative integer")
    require(type(denominator) is int and denominator >= 0, "denominator must be a non-negative integer")
    return round(numerator / denominator, 3) if denominator else None


def validate_samples(samples):
    require(isinstance(samples, list) and samples, "samples must be a non-empty list")
    ids = []
    topics = TARGET_TOPICS
    for sample in samples:
        require(isinstance(sample, dict), "each sample must be a dictionary")
        require(isinstance(sample.get("id"), str) and sample["id"], "sample id must be non-empty")
        require(sample["id"] not in ids, "sample ids must be unique")
        ids.append(sample["id"])
        require(isinstance(sample.get("topic"), str) and sample["topic"] in topics, "unknown topic")
        require(type(sample.get("difficulty")) is int and 1 <= sample["difficulty"] <= 5, "difficulty must be an integer in [1, 5]")
        require(isinstance(sample.get("template"), str) and sample["template"], "template must be non-empty")
        for field in ("synthetic", "train_overlap", "answer_correct", "verifier_pass"):
            require(type(sample.get(field)) is bool, f"{field} must be boolean")
        gold = sample.get("first_error_gold")
        pred = sample.get("first_error_pred")
        require(gold is None or (type(gold) is int and gold >= 0), "first_error_gold must be None or a non-negative integer")
        require(pred is None or (type(pred) is int and pred >= 0), "first_error_pred must be None or a non-negative integer")
        steps = sample.get("steps")
        require(isinstance(steps, list) and steps, "steps must be a non-empty list")
        for step in steps:
            require(isinstance(step, dict), "each step must be a dictionary")
            for field in ("ok", "relevant", "auto"):
                require(type(step.get(field)) is bool, f"step {field} must be boolean")
            require(type(step.get("human_cost")) is int and step["human_cost"] >= 0, "human_cost must be a non-negative integer")
        if gold is None:
            require(pred is None, "a no-error sample must not have a predicted error position")
            require(all(step["ok"] for step in steps), "no-error sample cannot contain an incorrect step")
        else:
            require(0 <= gold < len(steps), "gold error position must use zero-based step index")
            require(not steps[gold]["ok"], "gold error position must point to the first incorrect step")
            require(all(step["ok"] for step in steps[:gold]), "gold error position must be the first incorrect step")


validate_samples(SAMPLES)


def bucket(difficulty):
    if difficulty <= 2:
        return "easy"
    if difficulty <= 4:
        return "medium"
    return "hard"

print(f"training_mix={training_mix}")

print(f"review={review}")

slice_accuracy={'difficulty': {'easy': 1.0, 'hard': 0.0, 'medium': 0.5}, 'topic': {'algebra': 1.0, 'combinatorics': 1.0, 'geometry': 0.0, 'proof': 0.0, 'word_problem': 1.0}}
curriculum_order=['linear_easy', 'algebra_duplicate', 'ratio_word']
training_mix={'algebra': 0.667, 'word_problem': 0.333}
risks={'contaminated': ['counting_template'], 'verified_wrong': ['proof_polished_wrong'], 'hard_failures': ['proof_polished_wrong'], 'repeated_templates': ['linear_v1']}
review={'answer_quality': False, 'process_quality': False, 'contamination_ok': False, 'coverage_ok': True, 'hard_slice_ok': False}
~~~

逐项解读这个结果。平均答案准确率只有 0.667；`proof_polished_wrong` 被 verifier 放过，说明 verifier 有误报；`counting_template` 存在训练重叠风险；hard 切片为 0，说明当前样本不能支撑稳定的难题训练。

如果只保留 `accepted` 中通过答案、verifier 且没有重叠的样本，训练混合会严重偏向 easy algebra 和 word problem。过滤器看起来更严格，却可能把 geometry、proof 和 hard case 全部过滤掉。数据清洗不能只追求“剩下的样本都干净”，还要检查清洗后分布是否仍覆盖真正需要的能力。

## 15. 如何把审计结果转成训练决策

### 15.1 先修数据，再调超参数

如果训练集中存在错误答案、污染题和错误步骤，优先修正数据来源、验证器和切分；直接调学习率、batch size 或训练轮数，通常不能解决目标错误。

### 15.2 保留风险切片

困难证明题、不同模板、反事实和 verifier 误判样本不应因为难以自动筛选就全部丢弃。可以单独存放、降低训练权重、由专家复核，或作为验证集和 hard negative 集。

### 15.3 训练混合要可解释

记录每种题型、难度、来源、模板、错误类型和步骤长度的 token 或样本比例。混合比例改变了模型看到的任务分布，也改变了最终指标的解释。

### 15.4 训练目标分开测

如果同时训练答案生成和步骤判断，分别测答案、步骤、第一处错误、答案格式和变体迁移。一个总 loss 下降不能证明每个目标都改善。

## 16. 资料、污染和可复现性

### 16.1 记录来源证据

每条样本至少记录来源类型、许可证或使用条件、生成器版本、验证器版本、标注方式和时间。公开数据页能说明数据存在，不自动说明数据适合任意商业训练。

### 16.2 评测隔离

评测题面、答案、解析、模板和近邻变体不应进入训练。去重需要结合文本、公式、结构和参数族；单纯字符串去重会漏掉改写和变量重命名。

### 16.3 保存随机性

合成题、采样解法和 verifier 过滤都可能受随机种子影响。保存种子、代码版本、依赖、题目生成参数和过滤统计，才能重建一个数据快照。

### 16.4 记录失败样本

保留被过滤的错误答案、题目无解、工具超时、标注分歧和 verifier 误判样本，并说明它们不能进入哪个训练阶段。失败样本是改进数据和评估鲁棒性的材料。

## 17. 数学训练的工程成本

数学数据成本包括题目生成、解法生成、符号或数值验证、人工复核、去重、存储和训练。过程标注通常比最终答案标注贵，因为标注员要理解每个中间操作。

训练成本还不是全部。数学 reasoning 模型上线后可能使用 self-consistency、verifier 和 search，推理时成本会再增加。数据、训练和推理应在同一个质量—成本账本中评估。

如果至少有一个任务通过独立成功检查，单位成功成本可以写成：

~~~math
C_{\mathrm{success}}
=
\frac{
C_{\mathrm{data}}
+C_{\mathrm{train}}
+C_{\mathrm{inference}}
+C_{\mathrm{verification}}
}{
N_{\mathrm{correct}}
}
~~~

`N_{\mathrm{correct}}` 是通过独立成功检查的任务数；当它为 0 时，单位成功成本没有定义，应报告 `None` 或“没有成功任务”，不能用分子本身代替。这个指标不一定用于所有研究比较，但它提醒我们：一个只在高预算下正确的模型，未必比一个较短但稳定的模型更适合真实系统。

## 18. 安全与数学训练边界

数学题看起来低风险，但训练和工具链仍可能有安全问题。数据集可能包含未经授权的内容，日志可能保存用户文档，自动执行器可能运行恶意生成代码，工具验证可能访问不应公开的文件。

训练数据中的外部文本也可能包含提示注入，诱导模型改变目标或泄露上下文。数学工具只应接收结构化表达式和受控输入，代码执行应使用沙箱，工具权限应独立于模型分数。

数学高分不能直接推断现实决策安全。付款、医疗、法律和权限任务还需要领域规则、证据、权限和人工复核。

## 19. 小练习

### 练习一：设计样本 schema

为一道多解方程题设计题目、答案等价类、步骤、难度、题型、来源、验证和污染字段。说明为什么最终答案不能只保存一条字符串。

### 练习二：答案归一化

列出三个数值表达式等价的例子和两个看似相近但不等价的例子。为它们设计绝对误差、相对误差或符号归一化规则。

### 练习三：合成题验证

设计一个参数化题目生成器，并列出题面、答案、步骤、不可行条件和模板重复的检查方法。

### 练习四：第一处错误

构造一个最终答案碰巧正确但中间有两处错误的解法，标记第一处错误和后续受影响步骤。

### 练习五：难度 curriculum

为代数、几何、组合和证明设计 easy、medium、hard 切片。说明如何避免课程只按文本长度排序。

### 练习六：verifier 边界

分别给出数值验证、随机代入、穷举、符号化简和 LLM verifier 能检查与不能检查的内容。

### 练习七：运行 demo

把 `proof_polished_wrong` 的 `verifier_pass` 改为 `False`，观察 `verified_wrong`、`review` 和 accepted training mix 的变化。解释为什么清洗结果改变，不代表 hard proof 能力自动提高。

## 20. 本章总结

数学推理训练适合研究 reasoning，是因为答案、步骤、难度和部分验证信号都可以被明确描述。但数学 benchmark 和数学训练数据也容易受到公开题库、模板、答案泄漏和错误 verifier 的影响。

高质量闭环应包含：清晰的题目和答案 schema，答案等价类与单位处理，多种正确解法，第一处错误和错误类型，合成题验证，难度与题型覆盖，程序/符号/人工的多层检查，以及独立的变体和新题评估。

训练阶段可以使用 SFT、过程监督、PRM、结果奖励和 RL；推理阶段可以使用 self-consistency、verifier、search 和工具。但每一个额外模块都引入新的偏差、成本和失败面，需要独立评估。

最重要的判断不是“数学分数有多高”，而是模型是否在新题、变体、难题、证明和错误纠正上表现稳定，是否能说明哪里错，是否在可接受的单位成功成本内工作。

下一章将进入代码推理与执行反馈，讨论为什么编译器、测试集和运行时状态可以成为比自然语言评价更硬的反馈，以及它们仍然有哪些覆盖边界。
