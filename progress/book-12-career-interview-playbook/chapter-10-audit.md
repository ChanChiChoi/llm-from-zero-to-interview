## Scope 与章级扫描

- 全章审阅《大模型系统设计：从服务契约到可恢复系统》，覆盖 §§10.1—10.20。主线从面试澄清、服务目标和系统边界，经请求状态、Chat/推理、训练平台、RAG、Agent、多模态、评估与安全，延伸到容量、可靠性、可观测性、事故诊断、代码算例和证据边界。
- 章级扫描问题：候选人能否先说清用户结果、动作权限和假设，再把工作负载转成容量；一次请求的身份、状态所有者、证据版本和失败终态是否可追踪；读查询未知与写副作用未知是否分开；RAG 权限和引用是否早于生成验证；Agent 是否有预算、授权、稳定操作身份和终态确认；多模态结果是否保留来源区域/时间和不确定性；评估指标的样本、分母、版本与评分错误是否完整；资源池、重试和成本是否按实际负载及任务成功口径估算。
- 研究方式：先复核本章相关的架构、SLO/过载、训练恢复、推理服务/KV、RAG、Agent 授权与工具安全、评估平台、judge 和遥测研究记录；再按具体事实缺口检查官方接口、原始论文、RFC 与框架评分语义。复用的证据入口包括[系统设计架构](../../research/llm-system-design-architecture-evidence-2026-11-04.md)、[生产 SLO 与服务设计](../../research/production-system-design-and-slo-serving-2026.md)、[训练平台与 checkpoint](../../research/training-platform-checkpoint-elastic-evidence-2026-11-05.md)、[推理服务](../../research/llm-inference-serving-evidence-2026-11-05.md)、[KV 容量与分页](../../research/kv-cache-capacity-paging-and-compression-2026.md)、[RAG 检索与证据管线](../../research/rag-retrieval-and-evidence-pipeline-2026.md)、[评估平台](../../research/evaluation-platform-evidence-2026-11-05.md)、[LLM judge 协议](../../research/llm-judge-protocol-reliability-and-resolution-2026-11-03.md)、[Agent 授权标准](../../research/agent-authorization-interoperability-standards-2026-11-03.md)、[Agent 工具安全](../../research/agent-tool-calling-security-2026.md)、[Agent trace 与在线评估](../../research/agent-trace-diagnosis-and-online-evaluation-2026.md)和[项目工具与可观测性](../../research/project-tooling-and-observability-2026.md)。研究资料只保留新知识、来源和边界；本章的扫描决定、修改状态及未完成事项记录在此文件。

## 候选主题与处置

| 候选或问题 | 去向与处理 | 证据边界/不纳入理由 |
| --- | --- | --- |
| 系统设计回答容易变成组件清单，缺少需求到决策的推理 | §10.1.5 加入澄清目标/权限、询问负载和 SLO、走请求与失败、估容量、说明评估和发布的面试推进顺序；§§10.2—10.3 将服务契约、控制/数据/证据边界及离线/在线链路连起来 | SLO、容量值均为构造教学输入；章节讲面试推演，不声称存在唯一生产架构 |
| 超时、取消与工具结果被混成 `FAILED` 或一个笼统 `UNKNOWN` | §10.4 增加请求状态图；区分只读查询 `UNKNOWN_RESULT` 与已发出且可能有副作用的写操作 `UNKNOWN_EXTERNAL_EFFECT`，分别说明有界重试、凭证查询和人工核对；§10.9、§10.16、§10.17 使用同一语义 | RFC 9110 支持 HTTP 幂等与重试边界；操作状态、授权和下游回执仍由应用合同定义，不能由模型文本或协议名替代 |
| Chat、推理、训练平台只列组件，缺少资源/恢复推演 | §§10.5—10.7 补足会话/流式状态、prefill/decode 吞吐与 KV 账本、训练 checkpoint 恢复和发布 artifact；训练平台明确是接口级辅助例，优化器和并行内部机制转训练章节 | PagedAttention、DistServe、Mooncake、TaiChi 只支持各自论文方法及设定；PyTorch 2.15 DCP/torchrun 文档不保证应用状态或训练轨迹自动恢复 |
| RAG 缺少证据版本、权限失效和可定位的失败归因 | §10.8 增加 chunk 来源范围、权限 revision、缓存复授权、删除传播、RRF 手算、Recall@k 与 citation support 分母；按 50 条教学查询拆出解析、召回、引用和端到端漏斗 | RRF 只融合名次；教学查询数不是线上数据。USENIX Security 2026 注入结果绑定论文 embedding-retrieval 设置，不外推到所有 hybrid/reranker 系统 |
| Agent schema 通过被误当成授权，未知写状态可能被重复执行 | §10.9 补 schema/授权区分、执行器负责终态、稳定 operation_id、幂等键设计、重试/调用/时间预算及固定工作流与 Agent 循环取舍 | OpenAI Function Calling 和 OWASP Transaction Authorization 说明接口与授权关注点；具体预算、状态 owner 和恢复流程是设计合同，数字为教学假设 |
| 多模态输出丢失图像区域、音频修订或视频时间范围 | §10.10 用票据 OCR/VLM 冲突、partial/final ASR、稀疏抽帧和 token 账本说明证据应保留区域/时间/revision；加入 crop 坐标映回原图的解释 | 本节是系统设计中的辅助入口，不替代第九章的多模态模型机制；视觉 token 数不外推为任意模型固定成本 |
| 离线分数掩盖评分器失效、安全误拒或高严重度风险 | §§10.11—10.12 绑定 dataset/rubric/model 等 revision，区分系统失败、scorer error 与 unscored，增加配对差异、覆盖率、不同安全分母、灰度硬门槛及“0/300 不等于风险为零”的边界 | Inspect 是特定评估框架的评分语义示例；NIST AI 600-1 是自愿风险管理参考，文中准确率和跨租户门槛是业务负责人设定的教学条件，不归于 NIST/OWASP |
| 容量、降级、重试、遥测和事故只有原则，缺少具体数字与证据链 | §§10.13—10.16 分开估算 input/output 资源池，按 KV、峰值、故障、成功成本和重试放大推演；添加 trace 敏感内容边界及权限撤销/只读超时合成事故时间线 | throughput、成本、时间线均为教学假设；OpenTelemetry 动态语义约定不自动实施访问控制/保留；Google SRE 数字不当成通用门槛 |
| 代码输出可算但缺少状态、单位和成功分母解释 | §10.17 保留一个短 Python 示例，手算输入/输出 token 速率及成本，并要求 0 个成功任务时成本未定义；比较时按唯一逻辑 task_id 去重 | 示例“静态审阅，未运行”；未把静态检查写成执行验证 |
| 资料结论混用论文、产品、框架与生产证据 | §10.18 解释来源类型、版本和适用范围；对截至 2026-11-06 的 OpenAI Evals 控制台生命周期加日期边界，并链接官方指南 | 产品控制台时间线是动态事实，不表示通用评估架构过时；页面状态需随日期复查 |

本章保留 §§10.1—10.20 顺序，未发现需要新增、删减或迁移 H2 的证据。与训练、推理、多模态和安全技术册重叠的部分保持面试设计层的请求、边界、估算与追问视角；继续深挖算法或框架内部实现时使用对应书册，不在本章重复完整技术主讲。
