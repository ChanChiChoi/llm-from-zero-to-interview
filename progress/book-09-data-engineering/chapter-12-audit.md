## 正文修改、篇幅与例子

- 修正训练目标、风险约束、容量账本、token 账本、数量守恒、保留率、Jaccard、mixture、有效 epoch、数据边际价值、版本元组和发布检查向量的 MathJax 写法；为变量和分母补充定义。
- 容量手算：以 100 TB 原始数据为输入，解析层 140 TB、索引 25 TB、隔离区 10 TB、两个历史快照合计 112 TB、回放空间 20 TB，总量估算 407 TB；明确比例均为假设，并说明解析层与历史快照按增量空间计算。
- token 账本手算：三对象分别为 1,000、800、1,200 token，过滤状态 `(1,0,1)`、消费次数 `(1,0,2)`，得到 raw 3,000、eligible 2,200、consumed 3,400；说明重试事件不并入最终状态守恒。
- 数量守恒手算：1,000 个输入分为 930 成功、50 隔离、20 失败。保留率补充独立小例子 760/1,000=0.76；Jaccard 例子明确两个集合的含义；有效 epoch 补充代码池 0.6、数学池 2.4 的预算算例；数据价值差值补充净效用玩具值 `72.4-70.0=2.4`。
- §10.4 重写证据强度层次，说明版本组合同时变化时不能识别单项效果；随机种子复现能评估稳定性，但不自动消除混杂因素。
- 修正 §12 Python 示例：将坏样本拦截检查与发布候选门禁拆开；要求检查目标类型和安全动作覆盖；把 `balanced` 改为 action retention / class presence 语义；空集不再令 lineage 检查真值失实；删除来源命中仅代表样本候选匹配，不称为请求闭合；manifest 字段改为 `record_id_set_digest`，明确它只摘要记录 ID、不验证内容。删除未使用的 alignment/risk 聚合，避免缺少跨类型共同定义的代理指标。
- 三个连续核心单元统计解释性汉字数：§§0—4 **3,519**；§§5—10 **3,003**；§§11—16 **2,276**，均超过 1,800 字下限。计数排除标题、表格、公式围栏、代码围栏、行内代码和行内公式；分组分别对应任务契约到处理管线、数据质量/配比到回归诊断、发布检查/综合审计/回滚闭环。
