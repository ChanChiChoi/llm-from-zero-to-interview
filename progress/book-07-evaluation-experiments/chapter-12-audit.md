## 正文修改与可复算例子

- 前言和 §1—2 明确本章是 capstone：同一个企业知识助手模型 A→B 的案例连接前章方法；各章专门方法保留在第 2—11 章主讲位置。
- §1.1 把合成模型差异写为准确率 +3 个百分点、引用支持率 −7 个百分点、P95 延迟 +18%，并加入跨租户敏感文档风险。该例用于说明不能用单一均值决定发布，不是实测结果。
- §2.6 和 §8 使用同一任务背景。合成线上示例的完成率由 0.41 到 0.43，P95 从 4.8 秒到 5.7 秒，单位成本从 1.00 到 1.28；未给样本量或区间，因此正文明确它不足以证明改进或支撑上线结论。
- §§3—10 重组为单一交接流程：管理 benchmark/golden/regression 资产；按问题选测量器；把 judge 作为带误差测量；管数据血缘与污染；按任务类型组合证据；连接离线与线上；预先固定统计问题；用错误分析改变下一轮运行。每段链接到前章完整论述。
- §11 系统设计保留对象边界、数据/执行/评分/分析/决策层、manifest 和恢复机制。§11.8 定义状态向量：输入校验 `unchecked/valid/invalid_data`；执行 `queued/running/succeeded/failed/cancelled/unknown_outcome`；评分 `not_started/scored/evaluator_error/not_applicable`；成熟度 `pending/final/not_applicable`。示例逐一说明无效输入不适用评分、judge 故障不抹去成功的模型执行、观察窗口未完不等于模型失败。
- §11.9 比较 MLflow、OpenTelemetry 与 OpenAI 的工作流时，区分平台文档、遥测规范和评估有效性证据；不从接口存在推出评估可信。
- §12 Python 完整性诊断例的所有输入和门槛均为合成教学值。手算最大 rubric 分为 27，实际 23，覆盖率 `23/27≈0.852`；加权分子 4.626、权重和 5.7，加权分约 `0.812`；pairwise `8/12≈0.667`。安全与延迟示例通过；单位成本 0.30 高于假设门槛 0.25，且缺失组件也需要动作，因此发布结果为 hold。阈值是策略输入，不是行业标准。代码未执行。
- §13 保留为前文的误区速查清单；各项回指前述测量、切片、judge、发布、分母、trace 与 holdout 方法，不作为独立主讲单元。
