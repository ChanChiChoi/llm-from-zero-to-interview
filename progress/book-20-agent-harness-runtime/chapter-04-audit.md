# 第四章《工具系统与 Tool Registry》精修审计

审计日期：2026-11-18。状态：本轮章级扫描、正文精修与静态检查完成；第二十册第 5—24 章待逐章处理。

## Reader path 与章节结果

- **读者前置：** 能读 JSON、文件路径和简单 Git diff；无需有生产 Agent 经验。第一至三章的 Harness、Runtime 与任务工作流概念在本章开头通过认证修复任务唤回。
- **书册贡献：** 把模型动作提议接到工具发现、参数检查、授权、确认、执行回执和结果回传，给第五章文件系统、第六章终端、第八章权限和第九章 Trace 提供动作接口。
- **中心问题：** 一项模型提出的工具请求怎样在当前主体、任务和资源范围内经过检查，变成真实且可追踪的副作用？
- **预期结果：** 读者能区分模型提议、策略决定、工具执行和任务验收；能设计包含调用合同与运行时治理信息的工具记录；能区分 schema 合法与业务授权、测试退出码与工具执行故障，并按副作用确定性选择恢复路径。
- **主要任务与讲解路径：** 系统/工程机制解释。沿一条明确标记为教学构造的认证修复分支，追踪 Registry 能力面、参数和目标校验、策略和用户确认、资源版本冲突、实际 patch、测试结果、错误恢复与 trace。该分支不是前三章所记录的共享真实运行事件。

## 章级扫描与候选去向

扫描日期：2026-11-18。问题：工具注册、模型可见能力、schema、输出结构、权限/副作用、MCP 工具错误及工具结果信任边界是否需要按当前接口更新；现稿是否把产品字段写成通用规则？资料类型：OpenAI Function Calling 与 Agents SDK 官方动态文档、MCP 2026-07-28 版本 Tools 规范。

| 候选主题 | 证据与适配性 | 去向与判断 |
| --- | --- | --- |
| 模型工具请求与宿主执行是不同阶段 | OpenAI Function Calling 描述模型请求、应用侧执行自有函数、结果按调用 ID 回传并继续；Agents SDK 说明直接调用 wrapped function 会绕过其 runtime pipeline | 纳入 4.1、4.2、4.9。明确执行责任按工具类型变化，不把模型输出当作真实副作用 |
| 工具目录可按需暴露 | Agents SDK 当前文档介绍工具搜索和 deferred loading，以较大工具面为适用背景 | 纳入 4.3 作为产品实现例；不要求所有 Registry 使用相同发现协议或延迟加载 |
| 输出 schema 并非统一必填字段 | MCP 2026-07-28 Tool 定义中的 outputSchema 为可选；声明后由服务端遵守、客户端验证 | 纳入 4.4、4.7；保留对稳定结构结果使用 schema 的建议 |
| schema 严格性不等于动作安全 | OpenAI 当前 strict mode 约束参数形状；MCP 安全章节另列服务端输入验证、访问控制、输出净化和客户端结果验证 | 纳入 4.6、4.8。把 schema、主体授权、目标资源校验、确认和执行隔离分开解释 |
| 协议错误与工具执行错误不同 | MCP 版本规范分别描述 JSON-RPC 协议错误和带 isError 的工具执行错误，并建议客户端将可恢复执行错误交回模型 | 纳入 4.12；配合本地示例区分执行器已完成但测试退出非零 |
| 工具 annotations 和敏感动作确认有可信边界 | MCP 规范要求不信任非可信服务器的 annotations，并对敏感操作、结果校验和日志提出 SHOULD 建议；协议不规定唯一用户交互模型 | 纳入 4.4、4.8、4.13；明确区分规范 MUST/SHOULD 与本书的系统设计建议 |

未发现需要新增独立章节的读者结果。文件并发、shell 隔离、权限系统和协议语义分别交第五、六、八章及第二十二册，第四章说明这些组件的调用合同和交接边界。
