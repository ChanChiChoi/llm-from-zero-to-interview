# 第二十册第一章《Harness 总览》精修审计

审视日期：2026-11-17。范围：章级发现扫描、正文重构、示例与配套入口检查。

## 章节契约与读者路径

- **本册贡献：** 从 Harness 的总览定义开始，读者沿一次 coding task 追踪模型输出、解析、权限决定、工具副作用、环境反馈、持久状态、trace 和验收，给第二章的 Runtime 组件图和第三章的工作流建立共同对象。
- **读者前置：** 知道 LLM 可以根据上下文生成文本或结构化工具调用；能读懂普通文件路径、测试结果和 Git 工作区状态。无需有生产 Agent 经验。遇到 Harness/Runtime 边界时正文说明该边界是本书采用的分析约定，因为不同产品的命名会重叠。
- **读者结果：** 能逐步复走一个任务；能区分候选动作和实际副作用、工具成功和任务成功、用户确认和执行隔离、运行时状态和 trace；能画出 Harness 的最小控制闭环，并说出一次任务至少需要什么验收证据。
- **主要任务：** 系统/工程机制解释。主线为一个显式的合成 bug-fix 场景 → 状态与动作的逐步轨迹 → 一般化的组件职责 → 控制、安全与评估边界 → 回收定义并交给第二章。

## 章级发现扫描

- **检索日期与问题：** 2026-11-17。检查 overview 是否需要额外解释 agent loop、工具调用如何经过执行管线、用户审批的作用范围、trace 与 state 的区别，以及权限界面和环境隔离的边界。资料包括 OpenAI Agents SDK 官方 Runner/Tools/Human-in-the-loop/Tracing/Testing 文档、OpenCode 官方 `SECURITY.md`，并复用本册扫描记录中的 Gemini Interactions、OpenCode 和 SDK 证据。
- **候选与去向：**
  - 模型调用 → 最终答复/工具调用 → 工具执行 → 将结果回送下一轮的循环：纳入本章过程例与流程图；SDK 文档只作为一个公开实现例，通用概念不宣称为统一接口标准；细节交第二章和第四章。
  - schema、guardrail、timeout、error handling 和 trace 属于工具执行管线：纳入 Harness 的控制点说明，OpenAI SDK 的直接函数调用绕过其自身运行管线这一事实作具体边界例，详细实现交第二、四、八、九章。
  - 用户审批、permission gate 和 sandbox 隔离不是同一控制：纳入本章核心安全解释；OpenCode 官方文档明确其确认提示不提供隔离。部署方式和产品实现交第八、十一、十二章。
  - trace/span 记录和任务持久状态、workspace、provider conversation history 不等价：纳入状态对象说明；trace 工具细节交第九章，checkpoint 与 provider 状态分别交第十七、二十至二十四章。
  - 评估须固定任务环境和 verifier，区分模型、harness、工具和环境影响：保留 overview 入口，不扩成方法章节；完整评测设计交第十章和第十九章。
- **不新增独立主题的理由：** 这些材料补足现有闭环的边界，并没有形成超过本章及现有专题覆盖能力的独立读者结果。
