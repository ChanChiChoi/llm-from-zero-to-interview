# 第三章《Coding Agent 工作流》精修审计

审计日期：2026-11-17；2026-11-19 连续复读补记。状态：章级扫描、首轮正文精修和相关静态检查完成；整册连续复读中发现的口径修正见下方跨章一致性记录。

## Reader path 与章节结果

- **读者前置：** 能读基础 Python、JSON、Git diff 和常见命令行任务；无需有生产 Coding Agent 经验。第一、二章的 Harness/Runtime 概念在正文开头用登录认证任务唤回。
- **书册贡献：** 将前两章的任务状态、workspace 版本、动作副作用、失败恢复和 verifier 接成一个完整代码任务，交给第四至第九章的工具、文件、终端、上下文、权限及 trace 机制。
- **中心问题：** Coding Agent 怎样把用户目标转成可检查结果，按仓库证据逐步修改，并以可复核证据完成交接？
- **预期结果：** 读者能辨认任务类型，形成任务约定，按问题探索仓库，基于当前文件版本作窄修改，使用失败反馈，区分功能检查与任务验收，并报告修改范围和未验证项。
- **关键解释路径：** 明确结果/验收/范围/限制 → 查看当前工作区和相关测试/实现 → 按证据计划 → 发现文件版本变化时重新探索 → 小步修改 → 运行对应检查 → 核对 diff、既有用户改动和权限结果 → 交接事实与未知项。
