## 范围与读者路径

- **scope**：完整复读并精修 13.1—13.16，覆盖任务合同、指标树、baseline、实验记录、版本链、跨团队交付、RACI、范围变更、bad case、回归、灰度/停止/回滚/降级、延迟/容量/成本、事故响应、状态与公式、项目协作账本及 SRE/DORA/NIST/RACI 来源边界。
- **reader_path**：从离线分数上涨、线上体验和权限退化、Prompt 热改无版本、无人负责暂停的 RAG 项目开始；依次定义任务与失败边界、分开主指标/护栏/诊断、冻结 baseline、验证单项假设、固定版本链、为交付接口和变更指定 owner；再用 bad case 进入回归，以灰度监控和恢复路径控制发布，最后把事实、影响、缓解动作和未知项交给第十四章复盘，把取舍和决定交给第十五章。
- **书册贡献**：本章把前十二章的技术发现组织成项目合同和协作接口；不重复教授检索、Agent、安全和性能机制。事故期间的角色、止损、沟通和交接属于本章；根因证据和完整复盘报告交第十四章，决策表达与接手交第十五章。
- **读者结果**：能说明交付的是哪项任务能力，判断实验是否可比较，追溯请求运行的模型/Prompt/数据/索引/工具/策略版本，识别范围变化的资源与风险代价，指定谁产出证据、谁能暂停/恢复，并分开报告有效失败、unknown 和 not applicable。
- **读者检查**：复走一个合成 RAG 观测窗口的五条请求，手算任务成功率 3/5、线性插值 P95 6,240 ms 和单位成功任务成本 0.19 个合成成本点；再核对热修记录、请求版本、权限事故、暂停责任和回滚证据。没有进行目标读者试读。

扫描与来源核验日期：2026-11-17。扫描问题：项目管理怎样把模型分数、用户任务、跨团队依赖和上线恢复连接成可交付能力，同时避免一个综合分替代实际责任？新核验来源事实和版本边界单独记于[项目交付与事故治理来源记录](../../research/project-delivery-and-incident-governance-sources-2026-11-17.md)；NIST 风险框架/生成式 AI Profile 的官方状态亦见[安全数据生命周期与治理来源记录](../../research/security-data-lifecycle-and-governance-sources-2026-11-17.md)。

| 候选主题 | 去向与判断 |
| --- | --- |
| 项目目标与模型分数 | 保留 13.1—13.3；先定义用户、场景、失败边界、主指标和护栏。评估统计细节回链第七章，产品价值回链第十八册。 |
| baseline、实验和版本 | 保留 13.4—13.6；强调公平对照、成对样本、可证伪假设和请求级组件版本，不把多项改动的结果归因给单个组件。 |
| 跨团队接口、RACI 与范围 | 保留 13.7—13.8；将“沟通不足”改成缺少输入/输出/失败语义/验收/决定权的协作接口；范围变化需说明新增任务、资源和被推迟的事项。 |

| SRE、DORA、NIST 与 RACI | 保留 13.15，但按官方页面核对版本和边界；更新 DORA 当前五项软件交付指标，并把这些组织/治理方法限制在各自对象内，不将其写成 LLM 质量标准或自动合规证明。 |
