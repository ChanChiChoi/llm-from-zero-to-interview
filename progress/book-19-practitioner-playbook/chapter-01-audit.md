# 第十九册第一章《实战排障的证据链》精修审计

精修日期：2026-11-16。状态：首轮精修完成；逐章顺序的下一入口为第二章。

## 范围与读者路径

- **scope**：建立所有领域共用的事故排查路径：先确定任务契约和影响范围，再建立时间线、竞争假设和证据，固定条件做最小复现/对照，最后止损、修复、回归并交接。训练、评估、Serving、RAG、Agent、多模态和安全只在通用方法层给入口，具体机制交给第 2—12 章。
- **reader_path**：读者能看懂常见请求记录、训练日志和系统指标；本章帮助读者把“答案变差/请求变慢/任务未完成”转成可检查的任务失败，追出第一处分歧，并说明当前能下什么结论、还缺什么证据。
- **中心问题与结果**：如何用可复核证据将用户可见现象连接到触发变化和具体故障机制，并验证修复不只改变了表面指标？读者能为单次案例写出任务边界、影响切片、时间线、假设—检查关系、对照结果和剩余未知。
- **章节主线**：现象/故障/根因 → 任务契约与影响范围 → 时间线和可证伪假设 → 证据范围与受控检查 → 最小复现和 baseline/反事实 → trace → RAG 固定样本案例 → 跨领域入口 → 止损、修复、回归和交接。
- **视觉机会**：保留 1 张 Mermaid 请求证据链图，把身份/版本、系统决定、外部结果和修复验证连接起来；图块做了源码语法静态检查，未在 GitHub 页面确认实际渲染。

## 逐章扫描与来源

- **扫描日期和范围**：2026-11-16。核对 Google SRE 在线手册中监控、有效排障、事件管理、事后复盘章节；核对当前 OpenAI Agent 工作流评估指南；复查已有 OpenTelemetry GenAI 语义约定与 NIST AI RMF 来源记录。Google SRE 事实和边界写入[故障排查与事故证据来源](../../research/troubleshooting-and-incident-evidence-2026-11.md)；OpenAI Agent Evals 记于[Agent 轨迹诊断与线上评估来源](../../research/agent-trace-diagnosis-and-online-evaluation-2026.md)；OpenTelemetry 与 NIST 状态记于[项目工具与可观测性来源](../../research/project-tooling-and-observability-2026.md)及[企业 LLM 安全与治理来源](../../research/enterprise-llm-security-and-governance-sources-2026-11.md)。
- **候选主题及去向**：SRE 的症状/原因区分、假设测试、止损和系统复盘纳入通用主线；Agent trace 与固定评测数据集的先后关系留在 trace 段落，标明是动态供应商指南；GenAI trace 内容采集的敏感性用于日志最小化段落，注明语义约定不自动执行权限/保留；NIST AI RMF 仅作自愿框架及状态边界提示。此章没有足够证据或读者必要性新增专题，不扩章；每个领域的专门机制由相应章节扫描。
- **证据等级及限制**：Google SRE 手册支持其公开描述的可靠性实践，不证明 LLM 任务质量、权限或因果结论；OpenAI 文档说明自家平台的评估入口，不是独立方法学证据；OpenTelemetry `main` 是动态语义约定，应用须核对固定规范/SDK 版本及配置；NIST 当前状态属于访问日期快照。没有把供应商/框架文档写成目标系统已通过验证的证据。
