## 证据、公式与例子状态

- **evidence**：PagedAttention 原论文 v1 仅支持其论文条件下的分页 KV 机制与结果；JITServe NSDI 2026 支持按交互、完整响应和复合任务区分 serving 目标；DistServe v3 用于说明 P/D 资源池拆分的设计与条件收益。vLLM 指标、调度、prefix cache 和安全事实固定于 v0.33.0 官方文档；供应商及引擎入口不替代目标集群实测。证据细节和未验证边界存于[研究记录](../../research/inference-serving-metrics-and-disaggregation-2026.md)。
- **example_status**：8.0 合成短请求 TTFT 为 `180+40+160+40+70=490 ms`，调度增加到 430 ms 后 TTFT 为 740 ms，差 250 ms；客户端另需 40 ms 渲染。8.17 FAQ TTFT/TPOT/E2E 为 200 ms/100 ms/token/450 ms；代码 JSON 请求为 1,050 ms/195 ms/token/1,900 ms，且解析失败。五请求线性插值 P95：TTFT 860→1,410 ms、TPOT 174→214 ms/token、E2E 1,672→2,372 ms；独立 10 秒窗口输出吞吐为 24→32 token/s（+33.3%）。输入 token 总量 6,220→9,320，示例缓存命中率 500/9,320≈5.4%。KV 估算 128 KiB/token、9,340 token 约 1.140 GiB；按 128-token block 分配 9,728 token，空位 388（约 4.0%），占用约 1.1875 GiB。单位成功任务成本为 10/5=2 与 15/4=3.75 个构造成本点。单独记录首 token 前 1,300 ms 取消，和 5 条完整候选请求里的 1 条 JSON 失败。上述数据均为合成教学输入；候选 prompt 也变化，不能据此隔离调度参数的因果作用。
- **code_status**：删除原 8.17 长 Python 审计脚本，以逐步手算账本替代；正文没有可独立执行的 Python/脚本代码。未执行书中代码、测试、模型、API 或 benchmark。
