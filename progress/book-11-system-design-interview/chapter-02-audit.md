## 章级扫描与候选去向

- **扫描问题：** 用户可见的“完成”是否被误当成正文已保存；取消、失败和截断是否被塞进同一个终止状态；SSE 重连是否有可传递的事件 ID 和可重放语义；模型路由的不同量纲是否被直接相减；响应时延、上下文、路由和成本公式是否有可复算例子；首次出现的服务指标、协议、安全和容量术语是否便于独立阅读；协议与安全引用是否仍指向现行原始来源。
- **资料范围与日期：** 2026-11-04 至 2026-11-05；定向核验 WHATWG HTML Living Standard 的 SSE 事件 ID 与重连行为、OpenAI 当前公开流式指南及 Responses streaming events reference、OWASP GenAI LLM Top 10 2026、NIST AI RMF 1.0 官方页面，以及 OpenTelemetry Observability Primer。WHATWG、OpenAI、OWASP、NIST 和 OpenTelemetry 的事实与证据边界记于[流式协议、安全与风险框架证据记录](../../research/chatgpt-service-streaming-security-evidence-2026-11-04.md)；WebSocket 使用 RFC 6455 协议定义。
- **候选主题去向：** 不增章。把执行生命周期与持久化结果拆成正交状态字段；SSE 的 id 与应用序号一一对应，重连由服务端事件保留和授权策略完成；归一化质量、成本、延迟和风险后再做路由效用比较；把供应商事件名留在厂商资料示例中，白鹭事件明确作为应用层教学设计。推理阶段、KV Cache 与模型缓存的深入实现分别链接第四章和第十三章。OWASP 引用更新到 2026 版；原 OpenAI API 文档不可访问的旧说明已由当前官方指南和事件参考替换。以上内容仍服务于“从用户消息到可恢复响应”的同一系统设计案例。

## 主要修订

1. 开篇增加请求链路 Mermaid 图，标出网关、编排器、上下文存储、安全、路由、推理、持久化和评估的边界；补充 response_id、执行状态、持久化状态和事件序号的责任归属，并连接第一章答题路线。
2. 用 execution_state 表示 created、queued、generating、completed、canceled、failed；用独立 persistence_state 表示 pending、saved、persist_failed 和受控重试。同步修正 API 错误分类、取消响应、数据库故障、监控、故障演练和同步/异步保存取舍；明确 finish_reason 是结束原因，不是生命周期状态。
3. 给响应时间和 TTFT 增加假设阶段输入，手算首 token 延迟 **1.70 秒**、串行完整并保存时间 **3.30 秒**；说明并行阶段按关键路径计时。
4. 给 32,768-token 上下文窗口做预算推演，扣除输出、系统、工具和余量后得到 **24,576 token** 输入预算，并分配到当前问题、最近原文、摘要、记忆和证据。
5. 在 SSE 示例增加 id 行，使其与 JSON 的应用层 sequence 对齐；解释 EventSource 的 Last-Event-ID 传递、事件存储和重放由应用负责，并明确白鹭事件不是厂商 API 契约。
6. 将路由效用输入归一化至 0—1，增加质量底线和风险上限，并手算 A **0.137**、B **0.248** 的假设分数及过滤结果。
7. 增加多设备会话版本 12/13 的乐观并发冲突案例、请求成本及每成功任务成本例子、日成本账本；定义 API、SLA、TTFT、TPOT、SSE、PII、DAU、QPS、OCC、KV Cache、前缀缓存、prefill/decode 和百分位等首次出现术语。
8. 更新 OpenAI 流式 API、WHATWG SSE、OWASP GenAI Top 10 2026、NIST AI RMF 1.0 和 OpenTelemetry 的来源说明及证据边界。研究事实和时间版本仅记录在 research 文件；章级决定和修改记录留在本文件。
