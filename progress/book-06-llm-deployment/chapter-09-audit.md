## Scope 与章节职责

- **中心问题**：怎样把 RAG 与 Agent 的离线数据、在线检索、证据 payload、工具动作和业务状态接成可版本化、可授权、可恢复、可观察的生产服务。
- **本章职责**：聚焦服务接口、容量与发布闭环。RAG 文档处理/检索/评估方法分别链接第三册、第二册和第七册；Agent 工具、规划、安全、harness 与 trace 主讲链接第十七、二十、二十二册。本章不展开成向量数据库实现、Agent 框架或协议手册。
- **结构决定**：保留原有 1—17 节和文件名，不拆并或增章。把 §§2—7 收束为 artifact 与索引版本、embedding 迁移、向量服务可见性/权限、检索 deadline、payload 预算、灰度和回滚的部署链；把 §§8—12 作为 Agent 状态、工具、权限、安全和 trace 的连续生命周期；§13 为风险/事故辅助案例，§14 为 toy 诊断 demo，§15 为端到端综合案例。两处重复的预算/状态数值段落已各保留一份。
- **简介/目录**：已同步第 9 章摘要，突出版本、容量、权限、工具状态、观测和灰度回滚；章节入口及原编号不变。

**主要可复算例子**：新鲜度阶段按 `8+5+20+12+3=48` 分钟；2,400 个文档中隔离 18 个，合格率 `2,382/2,400=99.25%`，低于示例 99.5% 门槛；watermark 8,000 后 14 个增量只应用 13 个时阻止切流。12,000×256 个 token 在 24,000 token/s 下编码下界 128 秒，双版本为 256 秒；双写需求 36,000、容量 24,000 token/s，60 秒积压 720,000 token，常态负载后以 6,000 token/s 余量需 120 秒排空。百万条 768 维 FP16 向量裸 payload 约 1.43 GiB；蓝绿各三副本并加 30% 示例余量约 11.154 GiB，明确不含索引等开销。分片预算为 170 ms；三可用区失一区容量为 4/6；分片偏斜示例显示总空闲 88 GiB 仍可能无法容纳热点分片所需 10 GiB。

检索账本 `70+60+80+160+30+420+40=860 ms`；并行召回 `max(95,35)+15=110 ms`；50 req/s 服务遇到 60 req/s 到达率，60 秒积压 600 个请求，停止新流量后 12 秒理想排空。4,096-token payload 示例推得 evidence budget 1,920，保留前两段为 1,620、剩余 300；估算 1,900 与实际 2,052 相差 152（约 8%）。灰度 2,000 请求中 18 次超过阈值为 0.9%，高于 0.5% 门槛；任何一次无权内容进入 prompt 都单独阻断。

Agent 数例包含 $0.07 累计预算、版本 12 的并发写冲突、一次 820 ms trace、合成条件概率 `0.90×0.90×0.95×0.98=0.75411`、长上下文近似耗时 2,080 ms，以及总成本 $80 下 320 个成功任务的 $0.25/成功任务（按全部 400 请求计算则为 $0.20）。§14 toy demo 手算 query 集合 15 个词项、检索分数 0.4/约 0.133/0、重排后 return_policy 0.95、上下文 16+10=26 个词单位、工具 allow/deny 和预设延迟总和 600 ms；引用检查只验证 ID 存在，不代表 claim 获得支持。以上均为合成教学值。
