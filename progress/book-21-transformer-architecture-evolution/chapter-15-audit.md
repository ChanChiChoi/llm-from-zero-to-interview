审阅日期：2026-11-20。状态：章节职责与边界复核、章级研究、结构调整、主题重写、练习/题库同步及静态验收完成。正文不含公式或代码；未运行测试、模型、API、benchmark 或 PDF，也未更新 `plan.md`。

## 读者契约与跨章边界

- **前置：** 读者已了解 causal attention、自回归生成和基本 KV Cache。第十五章只唤回理解延迟所需的 prefill/decode 与历史状态，不重讲 attention 复杂度、KV 容量、窗口 kernel 或 serving 调度实现。
- **离章结果：** 能区分输入分段到达、模型逐 token 输出和在线 serving；解释自回归输出的依赖、prefill 与 decode 对等待的不同影响、KV 复用并不消除历史读取与增长状态；能判断一个流式问题来自输入策略、模型结构还是 runtime 排队；能说明固定递归状态如何改变历史访问及其证据边界。
- **本章职责：** 接续第十四章的显式历史与递归状态概念，说明这些表示对流式输入、首 token 和后续 token 延迟的含义，为第十六章 decoder-only 架构讨论提供在线推理语境。
- **范围外：** 第十一章主讲 KV 容量和逐层 cache；第十九章主讲窗口/稀疏 attention；第二十章主讲 attention kernel 和 PagedAttention；第二十四章主讲线性 attention；第二十九至三十三章主讲 SSM/RNN/Mamba 机制和硬件；第四十二/四十三章主讲替代及混合架构比较。第六册第二、五、六章主讲推理基础、引擎、批处理和调度；第十三章主讲生产系统设计。

## 结构与正文修改

- 旧稿有 23 个小节；其中时间预算、取消语义、状态机、安全副作用、公平性、benchmark 和上线 gate 多次重复，且扩展为 serving runtime 手册。按模块 02a 先确定本章主结果及跨册职责，再将结构重组为六节：流式类型、等待指标、自回归与 KV、增量输入、调度层缓解、有限状态取舍。章名、文件路径和在目录中的位置保持不变。
- 旧稿中的纯 Python 延迟演示使用未绑定硬件或 workload 的自设系数；删除，避免读者把教学数字当成延迟预测。删除无法从模型自身推出的固定 token budget、状态机、admission 公式、租户隔离/工具事务验收和自拟上线评分门；生产系统内容由第六册与相关系统章节承接。
- 主题正文重新写作，建立“输入何时可用—prefill 何时结束—首 token 何时可见—后续 token 如何依赖—历史状态怎样保留—调度器能改变什么”的解释路径。保留一个指标比较表和一个在线输入/输出分类表；没有公式或可执行代码，因为本章读者结果不要求公式推导或程序复现。
- 关键边界明确：流式输出并非 Transformer 不可用；自回归依赖属于普通逐步解码机制；prefill 与 decode 的实时瓶颈依 workload/runtime/hardware；chunked prefill 是调度层缓解，不是消除 token 依赖；递归状态的速度与质量结论必须绑定来源设置。
- 新增 `EXERCISES.md` 31T，将输入流、输出流、并发排队和递归状态放进同一条可手绘时间线；在 `INTERVIEW_BANK.md` 增加第 52 题，覆盖“Transformer 能否流式/在线”的常见混淆。TTFT、TPOT、ITL 与 serving 调度术语已有 glossary/题库定义，不重复增加条目；`PAPERS.md` 已有 Orca、Sarathi 和 Mamba 入口，本章正文直接链接 Ma 等同步翻译论文。
