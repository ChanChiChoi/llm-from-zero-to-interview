## 任务与旧稿诊断

本章按“主题思想不变重写”执行。旧稿 356 行、36 个二级标题，把递归状态的定义、代数、状态缓存、speculative decode、事务、snapshot/restore、迁移、tenant、容量规划、监控、endpoint 和生产排障流程反复混写。它既没有沿一个具体状态更新机制讲清“前缀怎样进入状态、状态怎样产生输出”，又把模型数学状态与 serving 实现策略混为一谈；若干状态求和、回滚和服务 API 主张不能推广到不同递归架构。

## 结构与范围决定

本章现行结构为 6 个二级标题、16 个三级标题。主线从显式 KV 的逐位置地址转到递归表示，再解释 RetNet 矩阵状态的累积、衰减与 query 读出；用 Mamba2 v2.2.4 的 conv_state/ssm_state 说明一个模块可以有多个状态对象。随后区分递归关系、并行扫描和 chunkwise recurrent，比较状态大小相对上下文长度的增长方式及访问路径，说明 reset 与分块连续性，最后明确模型状态机制和 serving 生命周期的边界。

第 69 章负责混合模型中各层采用的历史表示；第 70 章负责逐 token latent cache 与保真。第 71 章负责递归状态的模型语义与状态延续，不再讲通用状态池、调度、tenant、snapshot、迁移、抢占或生产 API；这些运行时细节按具体系统交给第二十四册。
