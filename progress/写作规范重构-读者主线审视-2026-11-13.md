## 差距判断

当前规范已经强调目标读者、读者问题、完整推理、例子、公式直觉和边界，方向是读者友好的。但它此前主要告诉作者“要检查哪些内容”，对“先讲什么、后讲什么”缺少稳定的默认顺序。方法章节容易出现术语、目标、推导和实现细节一同展开，读者需要自己补出问题动机、概念关系和公式用途。

前三册定位不同，但目录承诺和正文密度之间仍需要一条稳定的解释路径。对刚接触大模型的读者，仅要求首次给出术语释义或公式变量说明还不够：读者还需要知道术语在文本进入模型、训练参数更新或逐 token 生成的哪一步发挥作用，也需要知道公式中的量对应哪个数据对象、优化方向是什么、例子说明了什么。字符数下限可以促使内容变长，却不能保证这些桥接解释存在。

《统计学习方法》的组织方式可借鉴之处是围绕具体问题逐步建立方法，并在统一的概念框架下讲清定义、目标、算法和推导；本书系不照搬其章节内容，也不要求系统、项目、概念章节硬套方法教材结构。

## 写作规范的修订决定

1. 方法章节的默认讲解顺序改为“问题 → 定义与假设 → 目标函数 → 推导 → 算例 → 局限”。适用时，在推导之后、算例之前加入算法步骤；用回收段回答开篇问题。
2. 保留“模型—学习策略—算法”作为理解方法的三个观察维度，并分别映射到模型定义、优化目标和求解过程。
3. 明确大模型术语须按当前问题放回数据流解释，例如 token/token ID、logits/概率、目标 token/损失、prompt/completion，以及策略模型、参考模型和奖励模型。说明关键概念的区别，不把术语表或缩写展开当作讲解。
4. 明确公式解释须对应真实数据对象和大模型流程，交代变量范围、形状、单位、求和/平均、mask 口径和优化方向；保留必要推导，并用同一组小输入做数值算例。
5. 取消统一字数下限及“是否达标”式篇幅记录。篇幅仅作为诊断线索：用于发现动机、推理或例子缺失，以及重复和非必要深度。
6. 概念、系统、论文、项目和方案比较继续使用适配各自任务的读者路径，方法章节顺序是默认骨架，不是全书统一目录模板。

## 用户补充的总体原则

这套规范的核心还要保证“目标—内容—结果”跨层级连起来。每册说明它要把读者带到什么能力；每章说明自己如何贡献于这项能力；每个核心小节或知识点说明自己解决什么问题、为什么在这里出现、依赖什么假设、通过什么机制起作用，以及适用条件、代价和未解决边界。书册类型和目录结构可以不同，但不能让读者看不出组成内容之间的关系。

理解和比较方法时，继续追问三个问题：模型表示什么，学习目标是什么，算法怎样实现目标。比较时先对齐任务和条件，再说明各方法的假设、证据、适用场景、优势、代价和改进之处。它是贯穿各册、章节和知识点的认知坐标，不是所有书都必须采用的统一组织模板。

## 第二轮审视：讲述声音与模板风险（2026-11-13）

本轮重新核对《统计学习方法》第一版和第二版的出版社介绍、前言及目录。出版社对第一版的说明强调：章节从具体问题或例子起步，由浅入深，解释思路并给出必要推导；前言说明各章相对独立，同时尝试用统一框架保持全书系统性。第二版仍保留方法为中心的组织，并扩充了无监督学习内容。出版社也明确第一版预设读者具备较好的数学基础，因此值得借鉴的是问题驱动、推理递进和统一比较坐标，不是把它的读者前置或简洁程度照搬到本书系。[第一版介绍与目录](https://www.tup.tsinghua.edu.cn/bookscenter/book_02536702.html)、[第二版介绍与目录](https://www.tup.tsinghua.edu.cn/bookscenter/book_08132901.html)。

第一版目录也体现了这种组织：第 1 章先搭建统计学习的全局地图，介绍问题形式化、模型/策略/算法、模型评估与选择、泛化和任务类型；后续方法章再进入具体方法。以感知机章为例，先讲模型，再讲学习策略，随后讲算法，并细分原始形式、收敛性和对偶形式；章末配有概要、继续阅读、习题和参考文献。对本书系有用的启发是：先给读者一张地图，再带读者深入；每个方法的定义、目标与求解过程有清楚位置；章节结尾帮助读者整理和继续学习。它的结构稳定，但不是所有章节内容都写成同一种套话或逐项清单。

复读现行六份规范后发现，读者主线已较清楚，但模块 02 的多个顺序表、作者问题清单和完成检查，以及模块 05 的门禁，仍可能被直接套成正文结构。那样每项要求都齐了，读起来却像报告或模板。本轮将“规范是作者脚手架、正文是自然讲述”设为明确原则，并提醒简介、引用、代码状态和正文门禁不要抢走面向读者的解释空间。方法顺序保留为推理路线，不要求机械生成同样的小节；相关知识点可以共享一个真正有解释作用的贯穿例子。

### 本轮修改

- `写作规范/总纲.md`：新增规范与正文模板的区别，要求正文呈现问题、判断和推理的自然关系。
- `写作规范/01-书册定位与全书架构.md`：说明读者定位清单用于作者规划，简介应写成连贯、可供读者判断的说明。
- `写作规范/02-章节诊断与正文教学.md`：将方法次序明确为默认推理路线；新增讲述声音指导，覆盖具体疑问、自然承接、作者判断、清单使用和朗读检查。
- `写作规范/03-研究与证据管理.md`：要求正文解释证据与当前问题的关系及其支持边界，不让读者从引用堆中自行拼结论。
- `写作规范/04-图表公式代码与引用.md`：将代码验证状态限定为简短的读者出处信息，提醒正文仍须解释机制。
- `写作规范/05-维护同步与完成门禁.md`：门禁明确为内部复核；允许相关知识点共用贯穿案例，避免为了打勾增加重复小节和空泛例子。

研究证据、公式、代码状态和安全门禁属于必要的可靠性要求，本轮没有削弱它们；调整的是这些后台要求如何转化成面向读者的讲解。此次没有重写前三册正文，也没有运行书中代码。

## 第三轮审视：GitHub 数学公式解析（2026-11-13）

在第三册第 5 章 §5.4.1，行内 `\(\pi(y\mid x)\)` 正常显示，展示公式中的 `y_{<t}` 则触发 `Extra open brace or missing close brace`。源码的大括号成对；问题在于下标以 `<` 开头，可能在 Markdown/HTML 处理阶段被当作标签，令 MathJax 收到的公式残缺。该写法已在章节中改为 `y_{1:t-1}`，并补充前缀含义和 `t=1` 时为空的说明。用户确认修复后 GitHub 显示正常。

已把此故障特征写入 `写作规范/04-图表公式代码与引用.md` 的公式规则：排除尖括号下标，遇到花括号报错时检查 HTML/Markdown 解析干扰，并在 GitHub 页面目标端确认渲染。`git diff --check` 通过；规范修订没有运行书中代码或测试。

用户随后指出 §5.4.1 周围的行内公式仍以原始 `\(...\)` 文本显示。核对 GitHub 官方数学表达式文档后，发现行内支持语法是 `$...$` 或 `$` 反引号 `$`，与本章原有分隔符不一致；已将第三册第 5 章全部 61 对行内分隔符改为 `$...$`，并保留展示公式和代码不变。模块 04 已进一步明确 GitHub 正文行内公式不使用 `\(...\)`。等待用户确认 GitHub 页面显示。
