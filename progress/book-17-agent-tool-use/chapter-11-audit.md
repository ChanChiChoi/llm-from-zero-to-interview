## scope 与 reader_path

本章回答：当模型会读取不可信材料并调用有副作用的工具时，系统怎样限制权限和数据流、在执行前检查状态、处理未知结果，并留下能复盘和补救的证据？读者应能把身份、数据、执行和恢复边界落到策略状态、执行状态、确认记录和评估样本上，而不是只依赖模型遵守提示。

主线从 Agent 的事故半径和威胁模型出发，定义身份、资源、动作和信任边界；接着通过最小权限、能力凭证和策略状态机约束工具，再处理提示注入、工具输出、数据外发、沙箱和人工确认；随后把审计、补偿、Memory、供应链和多 Agent 委派纳入同一安全闭环，最后用评估矩阵、合成审计事件和合同助手案例回收。章节范围仍连贯，不拆分；与第二章的工具协议、第三章的行动循环、第八章的界面操作和第十章的指标口径保持短回链，不重复它们的完整主讲。

## examples、formula 与 code 状态

- 数据流例子：合同 OCR 中把金额、税率、公司名、手机号、签名图像和文档 id 分级。以明确标作教学假设的 1—3 序数评分手算，原图出域指数为 `23`，最小化并别名化后的 payload 为 `6`；说明该指数只能在同一评分假设下比较字段方案，不能代替政策授权或合规判断。
- 指标口径与第十章一致：`unauthorized_proposal_rate` 的分母为所有动作提案；`unauthorized_execution_rate` 的分母为实际执行动作；`unauthorized_block_rate` 只将状态明确为 `blocked` 的提案计入分子，`drafted` 不算阻断。高风险确认率只统计已执行高风险动作，高风险安全处置率则覆盖全部高风险提案。
- 数据阻断率的分母改为“按策略禁止的敏感数据流/外部传输”，避免把经过授权、最小化、脱敏的合法数据流误算成阻断失败。dry-run 只对已执行且支持预演的高风险动作计算；安全替代方案覆盖率只统计已阻断且存在可行替代方案的请求；未知外部状态不折算为阻断或草稿。
- §11.16 合成事件共 9 条；按最终执行状态手工计数：`executed=5`、`blocked=3`、`drafted=1`。输出手算为：未授权提案 `2/9=0.222`、未授权执行 `0/5=0`、未授权阻断 `2/2=1`；不可信指令 `3/3=1`、工具输出风险 `1/1=1`、禁止敏感流阻断 `0/1`、禁止外传阻断 `0/1`；已执行高风险确认 `2/3=0.667`、高风险安全处置 `5/6=0.833`、可预演高风险动作覆盖 `2/3=0.667`；沙箱 `1/1`、memory 污染 `1/1`、审计完整 `8/9=0.889`、适用安全替代方案 `2/2=1`。失败事件为 `send_sensitive_report`、`shell_out_of_scope`、`missing_confirmation`，综合门槛为 False。以上均为静态逐项复算，不是代码运行输出。
