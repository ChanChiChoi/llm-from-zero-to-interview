## 章节契约与读者路径

- **读者前置：** 已了解工具调用、观察—行动循环和任务拆分；本章把这些概念应用到网页与桌面 UI。
- **本章结果：** 读者能为 UI 任务选择 API、DOM/accessibility tree 或视觉通道，追踪状态变化，确认不可逆动作，并以结果、过程和风险共同审计执行轨迹。
- **中心问题：** UI Agent 如何在部分可观察、易变化且持有真实用户权限的界面中完成任务，同时证明动作正确并限制外部副作用？
- **读者路径：** Browser/Computer Use 边界 → observation 与 action 表示 → 指标和安全门 → 状态/身份/注入/鲁棒性 → 合成轨迹 demo → 通道选择、两阶段确认与评估 → 练习、总结和版本化资料。

## 来源事实与边界

- OSWorld 2.0 论文的 108 个长程任务及论文指标必须绑定论文设置；OSWorld-V2 仓库的 `osworld-v2.1` 是独立固定的代码、任务、资产、站点和 VM 发布。不得把论文版分数改称 v2.1 结果。依据与来源快照见[UI Agent 与 Computer Use 研究记录](../../research/ui-agent-and-computer-use-2026-11.md)。
- OpenAI Responses API 与 Anthropic `computer_toolset_20260801` 仅作 2026-11-16 接口案例；名称、动作合同、模型兼容性和服务支持需按使用版本复核。宿主执行器仍负责权限、动作执行、状态回传和实际结果验证。
- 产品文档、论文和 benchmark 不能证明目标生产网站上的定位精度、凭据隔离、注入防护、确认策略或错误恢复已经达标；这些必须在目标环境下另行评估。
