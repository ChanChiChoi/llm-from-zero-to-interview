## 本章契约与读者路径

- **读者前置：** 了解基本的大模型输入/输出；JSON 和 API 经验有帮助但不是硬性前置，不依赖某一 Agent 框架。
- **对书册目标的贡献：** 建立模型动作提议与宿主控制的边界，让读者能设计、检查和审计工具调用；详细协议生态交第二十二册，Runtime 与长任务执行交第二十册。
- **中心问题：** 模型何时该调用工具，结构化动作如何经过参数、语义、身份、权限、风险和确认检查，再由执行器执行并将结果安全地送回状态？
- **预期结果：** 读者能区分 direct/ask/stop/call，设计输入与返回 schema，说明执行器的职责，识别失败后的正确恢复动作，并按动作、参数、权限、确认、观察和恢复等维度解释评估结果。
- **读者路径：** 先用天气、订单和邮件场景理解模型提议不等于真实副作用；再顺着工具生命周期、形式化对象、schema、选择和参数来源进入执行器与观察处理；随后用权限、恢复和指标解释失败；最后读 toy 审计例及任务切片练习。

## 例子、代码与公式

- **贯穿场景：** 天气和计算器展示合法调用；缺少订单号展示追问；发送邮件展示角色与确认门禁；搜索结果注入展示“观察不是指令”。所有身份、工具和数据均为教学构造。
- **核心案例：** 第 12 节 demo 的动作标签区分 direct、ask 和 call；六个样本覆盖正确调用、缺参、高风险写入、不可信结果诱导和直接回答。预期数字按代码逻辑静态推导，未运行。
- **分母修订：** 动作准确率使用所有已标注决策；过度调用率用所有决策，漏调用率只用期望调用的决策；参数 exact match 仅在工具选对且存在参考参数时计算；schema、角色权限和未授权尝试按实际调用计数；确认率只对要求确认的调用计数；注入率只看含不可信外部 observation 的样本；恢复率只看确需恢复的失败案例。
- **门禁职责：** Toy demo 把角色权限和确认分开，并把 schema/权限/确认合并为“预执行门禁通过率”；它不访问真实资源、不调用服务，因此不报告真实执行成功率。
- **代码状态：** 章节中的独立 Python demo 标记为“静态审阅，未运行”，仅依赖 Python 标准库。代码发生变化后没有沿用旧的运行验证，也未声称输出已实测。后续运行后应复核整组预期输出和边界样本。
- **公式：** 章内公式现在明确区分动作标签、工具调用参数、服务状态、角色资源、确认、观察、恢复和成本/延迟口径；行内公式使用单美元符号，display math 使用 math 围栏，operatorname 函数数量为 0。
