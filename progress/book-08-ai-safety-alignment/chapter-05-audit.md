## 章节职责与衔接

- **中心问题：** 区分直接诱导模型违反行为策略的 Jailbreak，与外部内容影响 LLM 应用任务和动作边界的 Prompt Injection；沿 RAG、Agent、工具、长期记忆和评估数据流定位风险，并把防护落实为服务端权限、来源追踪、状态验证和回归评测。
- **读者收获：** 能按“来源 × 受影响边界”分类事件；拆分检索可达性、检索后影响、未授权动作和用户任务效用；区分当前提示与跨会话记忆污染；为工具参数和高影响动作设置执行器授权条件；解释研究数字的评测范围和分母。
- **主线：** Prompt 从交互方式变成控制接口 → Jailbreak 与 Prompt Injection 的定义和关系 → RAG 检索及信任边界 → Agent 行动与持久记忆 → 攻击类型 → 多层防御与能力边界 → 分层评估 → 合成邮件工作流 → 审计 demo。
- **书系衔接：** 本章讲攻击概念、应用信任边界和安全责任；第七册第八章负责安全评测协议、统计和不确定性；第二十册负责 Agent runtime、上下文与记忆实现；第二十二册负责工具协议和 schema；第六章继续讲红队流程、危险能力和发布条件。没有发现需要返回册级调整骨架的问题。

## 正文修改与关键决定

- §1 澄清 API 消息角色和工具调用结构会提供消息级来源线索，但不能证明消息中的每个字段均可信或获准执行；补充邮件摘要请求从检索、候选动作到服务端拒绝发送的合成轨迹。
- §§2—4 将事件分类改为“来源 × 被影响边界”两个维度，并补四条合成轨迹；直接有害请求、外部邮件、正常 RAG 对照和合法工具参数污染分别对应不同评估对象。
- §5 增加条件概率分解和合成算例：20 次查询中 8 次命中、3 次违规，检索命中率 `8/20=0.40`、条件违规率 `3/8=0.375`、端到端违规率 `3/20=0.15`。补充语料来源/所有权/租户/版本/撤销状态、chunk 溯源、ACL、缓存和 claim/动作分离；新增配对评估控制条件和阶段分母说明。USENIX 论文数字仅限其 11 个 benchmark、8 种 embedding 与特定 GPT-4o 多 Agent 邮件设置。
- §6 明确工具处理链为候选、授权、提交、观察和审计；补充部分资源 ACL、超时后结果未知、幂等恢复，以及记忆的四条写入通道。MPBench 报告的平均写入 ASR `50.46%`、写入成功后的检索影响率 `41.05%` 绑定其 3,240 个攻击/2,997 个良性样例、GPT-OSS-120B 和 OpenClaw/HERMES 默认配置。
- §7 说明分类标签可以重叠；审计字段应保留来源、目标、受影响边界和持久化阶段。
- §§8—9 增加服务端参数来源和动作特定授权边界，并将 CounterSteer 限定为白盒逐模型的补充干预；论文报告的五模型 holdout 结果及 13/18 开发样本参数污染结果不作为部署保证。进一步澄清消息角色存在，但普通文本并不因此拥有可由执行器强制的权限类型。布尔规则手算 `1∧1∧0∧0=0`。
- §10 纳入 ATOM 在 16,273 条 AgentDojo 轨迹上的安全未完成 `21.7%`、不安全但完成 `3.8%`；同时注明静态攻击、特定 harness 和 LLM judge 的证据限制。修正原 `A_attack` 分母错误，排除本不应完成的有害 Jailbreak 请求。
- §13 明确邮件案例为合成案例；用 `u42/t7/m17` 推演 ACL、`mail.read`、`draft.create`、`mail.send`、一次性确认、权限撤销、超时和幂等状态。新增日志最小化与保留边界。
- §16 将 demo 标题改为中性 toy demo，代码状态改为“静态审阅，未运行（2026-11-03）”。在每条 case 中显式增加 `attack_utility_eligible`；攻击效用只计算五条受攻击且仍有合法用户任务的样例，其中安全完成一条，故 `attack_task_success=1/5=0.20`。两条有害 Jailbreak 拒绝不进入任务效用分母。代码语句和预期输出与解释均静态核对，未执行。
- §17 总结修正为：消息角色提供来源线索，但应用仍须保存并验证外部内容的来源和动作授权；避免把“统一 token 序列”作为对现有消息角色/结构的过度简化。
