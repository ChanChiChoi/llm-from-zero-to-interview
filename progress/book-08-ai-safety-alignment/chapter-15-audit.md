## 章节职责与边界

- **中心问题：** 如何按主体、资源、动作与范围、风险、证据和实时状态，决定 Agent 的某一次工具访问是否允许、需要复核或必须拒绝。
- **读者收获：** 能区分内容/动作风险与身份授权；理解 PDP/PEP、委托、最小 scope、证据新鲜度、revision 绑定、撤销、TOCTOU、受限故障策略和访问策略评估；知道如何将模型提出的动作约束到真实 executor 与外部状态。
- **前后章衔接：** 第 14 章分类器只提供内容风险信号，本章负责服务端的访问策略判断；第 16 章继续处理策略、工具和状态故障下的降级与恢复。跨册的 Agent runtime / harness 落地交第二十册，授权协议与 MCP 映射交第二十二册。
- **结构：** 保留开篇和 15.1—15.21 共 21 个一级章节。主线由请求建模、风险/授权/证据/状态，推进到 PDP/PEP、身份、证据和信任边界，再到审批竞态、故障、校准评估、代码 Agent 流程、审计示例与失败排查；未发现需增删或重排章节的稳定问题。

## 例子、公式与示例代码静态核对

- 风险加权例：五项乘积 `0.15 + 0.20 + 0.10 + 0.10 + 0.04 = 0.59`，权重和为 1；明确此分值是合成排序量，不是 59% 事故概率。
- 有效动作集合：`{read_public, write_workspace, deploy_production}` 与 grant / 环境均只允许前两项相交，最终仍为前两项。
- compare-and-check 轨迹：09:00 主体版本 12、资源 `c41`、策略 `p8`；09:02 主体版本变 13 且资源变 `c42`；09:03 执行前发现版本变化，结论为 `re-evaluate`，不调用生产 executor。
- ECE 两桶例：20 个样本风险均值 0.2、2 个事件；10 个样本风险均值 0.8、6 个事件；逐项加权结果 `0.1333`。事件标签、桶样本和合成口径均已注明。
- 期望损失：100 次请求中 high-risk allow 2、normal deny 5、review 10；假设代价分别为 20、3、1，计算 `20×0.02+3×0.05+1×0.10=0.65` 损失点/请求。
- 严重度加权：四次失败权重 `{1,1,5,3}` 中权重 1、5 的两项失败，计算 `6/10=0.6`；解释该比例不等于概率。
- 策略评估指标：20 次高风险尝试中 3 次执行级允许；12 次未授权尝试中 2 次有外部副作用；20 次合法任务中 3 次误阻；各自分母和状态定义不同，空分母记 N/A。
- 延迟：请求到策略决定 `120 ms`；撤销请求接收至执行点开始阻断 `2.5 s`；指出时钟和“已阻断”的事件定义。
- 漂移总变差：旧分布 `(0.6,0.3,0.1)`、新分布 `(0.3,0.5,0.2)`，计算 `0.3`，说明不是事故率涨 30%。
- Python 示例五个风险输入静态手算：公开读取 `0.100`、沙箱 patch `0.435`、生产风险 `0.590`、高风险发布 `0.815`、无 grant/撤销主体 `0.200`。逐支复核 11 个请求的预期决策：`allow_read`、`allow_sandbox`、审批 `review`、`allow_canary`、revision `re_evaluate`、缺证据 `hold`、缺少双人审批 `hold`、满足双人审批 `allow_canary`、错误 scope `hold`、无 grant `deny`、已撤销主体 `deny`。所有阈值为合成固定政策，不是部署建议；没有运行代码。
