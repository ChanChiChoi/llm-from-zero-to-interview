# 第二章：数据事故与证据链

大模型训练和评估中的许多异常，最后都会回到数据。训练损失（loss）下降得很快，可能是重复样本过多；公开基准测试（benchmark）分数很高，可能是测试题或题解进入训练集；某种语言能力突然变差，可能是数据混合配比（mixture）或分词器（tokenizer）变化；代码模型表现不错，却可能携带了不清晰的许可证、密钥（secret）或评估答案。

数据事故的危险之处在于，它通常不会像程序崩溃那样立刻停止任务。它更常见的表现是模型悄悄学到了偏差：训练过程看起来更稳定，评估结果看起来更漂亮，输出风格变得更单一，长尾输入却越来越差。等问题在生产环境暴露时，团队往往已经无法回答数据来自哪里、经过了哪些处理、哪个版本进入了训练以及哪些评估结果受到了影响。

本章把数据看成一份带有来源、版本、用途、质量、风险和分布的训练契约。先用一个“评估分数异常升高、线上长尾能力下降”的事件贯穿全文，再分别讨论精确重复、近重复、评测污染、网页质量、多语言、代码数据、合成数据、过度过滤、数据配比和数据血缘（lineage）。重点不是背过滤规则，而是学会从样本和版本出发，证明某个数据变化是否真的解释了模型行为。

## 2.1 数据不是文件，而是带约束的分布

把训练数据理解成一个目录或若干个 JSONL 文件，会忽略它真正决定的东西。训练数据决定模型在什么输入分布上获得梯度，哪些表达被重复强化，哪些领域被上采样，哪些风险样本被保留，哪些评估题可能已经被模型见过。

文本进入模型前会由分词器切成 token（词元），再变成 token ID（词元编号）。一个 token 可能是一个词、词的一部分、标点或多个汉字；因此本章的 token 数指给定分词器实际产生的词元数量，不等同于字符数、词数或记录数。

一条数据记录至少可以抽象为：

```math

d_i=(x_i,s_i,l_i,q_i,r_i,v_i,h_i,p_i)

```

其中：

- `x_i` 是文本、代码、图像描述、对话或其他训练内容；
- `s_i` 是来源，例如网站、仓库、人工标注集或教师模型；
- `l_i` 是语言、领域或任务标签；
- `q_i` 是质量信号，不等于最终质量真值；
- `r_i` 是许可证、密钥、个人可识别信息（PII）、危险内容等风险标记；
- `v_i` 是来源或处理版本；
- `h_i` 是内容哈希、文档 ID 或稳定 lineage 标识；
- `p_i` 是用途和保留策略，例如预训练、监督微调（SFT）、评估候选或仅供分析。

如果只有 `x_i`，没有来源、版本和用途，后续发生删除请求、污染调查或训练回滚时就缺少定位依据。数据处理脚本输出的文件名也不能替代记录级 lineage，因为同一个文件可能经过过滤、去重、重采样和格式转换后产生多个派生对象。

训练目标可以写成数据分布上的期望：

```math

\mathcal{L}(\theta)=\mathbb{E}_{x\sim P_D}[\ell(\theta;x)]

```

清洗、去重和配比改变的不是一个无关紧要的附件，而是 `P_D`。当数据池被过滤、某些来源被重复采样或合成数据被大量加入时，模型优化的目标已经改变。判断这种改变是否合理，必须回到目标任务和评估切片，而不是只看剩余 token 数。

## 2.2 贯穿案例：分数上升但真实能力下降

先说明案例性质：下面的团队、变化和数字均为教学构造，用来串起调查步骤，不是某个真实模型的事故记录，也不代表常见发生率。

某团队更新了预训练数据后，内部数学和代码 benchmark 分数上升，训练 loss 也低于上一版。上线到企业知识助手后，用户却反馈长尾领域问题变差，中文口语输入出现更多翻译腔，代码生成会重复某些公开仓库的固定片段。

团队最初提出了三个解释：模型容量不够、学习率不合适、线上提示词（prompt）与离线评估不一致。这些假设都可能成立，却没有解释为什么公开基准测试上升、长尾和代码风险同时恶化。

工程师先把新旧数据版本的清单（manifest）对齐，发现有四个变化：

1. 新网页数据做了更强的模板过滤，低资源语言和方言样本的保留率显著下降。
2. 一个公开数学题解集被合成数据生成流程重新写入，部分题目和答案没有被识别为评估污染。
3. 代码数据的来源字段在转换时丢失，无法确认许可证和仓库版本。
4. 为了增加“高质量推理数据”，教师模型生成的数据在这个教学案例中占比从 10% 上升到 24%。

这四个变化分别对应分布收缩、污染、治理缺口和合成数据偏置。它们可能共同造成当前现象，但修复顺序仍然要根据风险和证据确定：先隔离代码风险和评估污染，再验证语言和领域数据是否被过度过滤，最后通过混合配比消融实验（mixture ablation）评估合成数据比例。

这个案例说明，数据事故不是一个“清洗脚本有 bug”的单点问题。来源、处理、评估、配比、版本和业务输入必须连成一条证据链，才能解释模型行为。

## 2.3 精确重复：训练量增加不等于信息增加

精确重复是内容归一化后完全相同的记录。它可能来自同一网页的多个抓取时间、多个 URL、不同文件名的相同代码、数据集拼接或数据管道重复运行。

重复会产生几个后果：

- 相同内容获得过多梯度，等效采样权重被放大；
- 训练 token 数看起来增加，实际覆盖的信息量没有同步增加；
- 评估中出现相同或近似内容时，分数可能虚高；
- 高频模板被模型过度记忆，输出多样性下降；
- 隐私、许可证或危险内容的暴露次数增加。

精确重复率要明确分子。若总记录数为 `N>0`，每个重复组只保留一个代表，其他记录数量为 `N_extra`，可以定义：

```math

R_{\mathrm{exact}}=\frac{N_{\mathrm{extra}}}{N}
```

如果 `N=0`，这个比例没有定义，不应写成 0。若记录有不同质量、时效或许可证，即使内容相同，也不能只按字符串删除；应该先判断哪个版本是可保留代表，以及派生对象如何关联到被删除来源。

第 2.15 节会用 10 条构造记录演算一次：若其中 1 条是重复组里多出的记录，精确重复率就是 `1/10=10%`。这是按记录数计算；若这条记录很长，按 token 算出的比例会不同。

实现上通常先做规范化，再计算稳定 hash。规范化可能包括 Unicode 处理、空白压缩、HTML 模板清除和大小写规则，但任何规范化都会带来误合并风险。代码、数学公式和自然语言的规范化策略不能完全相同：把变量名、缩进或字符串字面量全部抹掉，可能把功能不同的代码误认为重复。

重复也不一定总是错误。对话中的系统指令、法律模板、代码库中被多个项目复用的接口定义，可能在任务上确实需要重复出现。关键问题是重复是否经过有意采样，以及它是否改变了目标分布。数据工程师应同时报告原始重复率、去重后的 token 保留量、按来源的重复分布和高风险重复内容。

一项去重研究在其训练数据和模型设置中报告了泛化及记忆相关收益；它支持实际测量去重效果，但不意味着所有重复都应删除，也不给出可直接迁移到任意语料的阈值。[Deduplicating Training Data Makes Language Models Better](https://arxiv.org/abs/2107.06499)。

## 2.4 近重复：相似不是删除结论

近重复通常是同一模板经过少量字段替换、网页导航变化、翻译改写或代码变量重命名后的多个版本。它比精确重复更难，因为相似度阈值会在漏合并和误合并之间取舍。

一种教学上直观的相似度是由连续 n 个词元组成的片段（shingle）集合的 Jaccard 相似度：

```math

J(x,y)=\frac{|G_n(x)\cap G_n(y)|}{|G_n(x)\cup G_n(y)|}
```

其中 `G_n(x)` 是文本的 n 元词元片段集合。当两个集合都为空时，Jaccard 没有正常定义；实现不能用一个固定的小数掩盖空输入。生产系统通常用最小哈希（MinHash）和局部敏感哈希（LSH）生成候选，再做精确片段或编辑距离复核，因为全量两两比较的复杂度随记录数平方增长。

阈值不能脱离数据类型。新闻网页、代码、表格、短问答和多语言文本的相似分布不同。一个在英文网页上有效的阈值，可能把中文短句、代码函数和数学题误合并。近重复候选应该保留相似证据、来源和代表选择原因，而不是只输出“删除”。

常见误合并包括：

1. 两个只共享法律免责声明的网页被合并，主体内容被错误删除。
2. 两个代码函数只因变量名和格式相似而被合并，功能差异丢失。
3. 翻译后的多语言内容被当成重复，低资源语言被删除。
4. 数学题共享题型模板，但条件和答案不同。
5. 合同版本只修改了一个关键金额，却因为大部分文本相同被折叠。

因此，近重复检测的正确输出不是一个布尔值，而应包括候选对、相似度、共享片段、来源关系、时间关系和建议动作。自动删除只适合高置信、低风险的粒度；其余候选应隔离后人工或规则复核。

例如，设两个样本的三元片段集合分别为 `G_3(x)={现行-安全-规则, 安全-规则-生效}` 和 `G_3(y)={现行-安全-规则, 安全-规则-生效, 规则-生效-说明}`。交集有 2 项、并集有 3 项，所以 `J(x,y)=2/3≈0.67`。它只说明这对文本值得复核；共享片段也可能来自模板，不能据此直接删除其中一条。

## 2.5 Benchmark 污染：高分可能没有测到能力

评估污染是训练数据包含评估题目、答案、解析、测试输入、代码签名或高度相似变体。污染不只发生在原题逐字出现时。公开题解、论坛讨论、仓库测试文件、合成数据提示和模型生成的“参考答案”都可能让模型在评估前接触了答案信息。

污染证据可以分层：

| 证据层级 | 例子 | 解释强度 |
| --- | --- | --- |
| 强 | 训练记录与测试题精确匹配（exact match），或答案字段直接出现 | 高度怀疑污染 |
| 中 | 题面大段重合，或题解和解析出现在训练数据 | 需要排除污染影响 |
| 弱 | 主题、模板或常识相似 | 不能单独证明污染 |
| 未知 | 只看到分数异常，没有训练数据证据 | 只能标记待调查 |

命中是调查线索，不等于模型确实靠记忆答对。GPT-3 论文对训练语料与基准题做 n 元片段重叠分析时发现了误报，也报告过分析流程缺陷，因此重叠应结合答案字段、公开时间和人工核对解释，而不能直接改写成能力归因。另一项 ICLR 2026 研究在其推理模型设置中报告：监督微调阶段的污染信号仍可被当时的方法检测，但短程组相对策略优化（GRPO）训练即可掩盖多数方法依赖的信号。因此，检测器未命中不能证明没有污染；该结果绑定论文的模型、污染构造和检测方法。[GPT-3 论文](https://arxiv.org/abs/2005.14165)；[ICLR 2026 污染检测研究](https://proceedings.iclr.cc/paper_files/paper/2026/hash/a3860475ddbfb8c644c43f0dcd266b66-Abstract-Conference.html)。

设训练候选集合为 `D`，其中 `N_D>0`，与评估集或其解析命中的记录数为 `N_hit`，可以报告候选污染率：

```math

R_{\mathrm{contam}}=\frac{N_{\mathrm{hit}}}{N_D}
```

但这个比例依赖检测器、阈值和被扫描的字段，不等于真实污染概率。若没有可比较的评估签名集合，状态是“不适用”（`not_applicable`）；如果训练数据集合或版本缺失，状态是“未知”（`unknown`）。分母有效但没有命中时可以报告“本轮检测命中为 0”，不能据此宣布“没有污染”。第 2.15 节的构造案例有 1 条候选命中、共 10 条记录，所以候选命中率为 `1/10=10%`，仍需逐条判断命中证据强度。

污染调查应同时做：

1. exact match 和规范化 match；
2. n 元片段、MinHash/LSH 或文本向量相似度候选；
3. 答案和解析字段单独扫描；
4. 代码测试、函数签名和样例输入扫描；
5. 时间切分，确认训练记录是否早于评估题公开时间；
6. 改写题、参数变体和私有保留集（holdout）评估；
7. 对高影响命中做人工复核。

污染发生后，不能只删除命中的几条记录然后继续引用旧分数。应该重建干净评估集或明确标注受污染的指标，重新运行旧模型和新模型，并报告分数变化。一个模型在原题上高分、变体题上明显下降，说明它可能依赖记忆或模板匹配，而不是掌握了可迁移能力。

## 2.6 Web 数据：从原始页面到可训练文本

Web 数据的规模很大，但网页不是天然的训练样本。原始 HTML 里同时包含正文、导航、页脚、评论、广告、跟踪参数、重复模板、机器翻译和错误编码。把 HTML 去掉标签后直接送入 tokenizer，往往会把页面结构噪声当成语言能力学习。

一个可追溯的 Web 数据路径应保留阶段边界：

```text
抓取快照
  -> 原始响应和抓取时间
  -> HTML/PDF/代码解析
  -> 正文、标题、链接和版面元数据
  -> 语言、质量、版权和风险分类
  -> exact/near dedup
  -> 来源配比和任务筛选
  -> tokenizer 统计
  -> 训练分片和 manifest
```

每一阶段都可能改变内容。解析器升级可能让正文长度变化，语言识别器可能误删低资源语言，去重粒度可能把多篇文章合并，分片程序可能丢失最后一段。只保存最终文本，无法定位是哪一步造成变化。

网页质量过滤常用的信号包括文本长度、字符分布、语言置信度、重复模板比例、链接和正文比例、困惑度、质量分类器、人审抽样以及来源历史。但没有一个单独阈值适合所有下游任务。高困惑度可能意味着乱码，也可能意味着专业数学、代码或小众方言；低困惑度可能意味着高质量模板，也可能意味着大量重复的 SEO 页面。

更稳妥的过滤流程是先分层抽样，再做阈值实验：

1. 按来源、语言、长度、领域和质量分桶。
2. 在每个桶中抽取保留、拒绝和边界样本。
3. 由人工或高质量评审定义“可训练”的具体标准。
4. 测量过滤对下游切片的保留率和能力影响。
5. 对阈值附近样本设置审查或随机保留比例。

过滤器只删除，不会创造信息；错误过滤造成的长尾损失可能比保留少量噪声更难恢复。

这类偏差并非只是假设。C4 是从单个 Common Crawl 快照构造的网页语料；对它的研究发现了非预期来源、机器生成文本和其他基准的样本，并报告屏蔽词表（blocklist）过滤对少数群体本人及相关文本产生不成比例的移除。这个结果说明要审查过滤对不同群体和任务的影响，但它只描述 C4 的语料与规则，不能外推为所有过滤器都会造成同样偏差。[C4 语料研究](https://arxiv.org/abs/2104.08758v2)。

## 2.7 数据配比改变的是模型的能力预算

数据 mixture 不是训练脚本里的一个装饰参数。若某个桶被重复采样，它在优化中获得的权重就会提高；若另一类数据因为质量过滤损失更多，它的实际贡献会下降。最终模型能力、风格、拒答倾向和语言覆盖都可能随之变化。

按 token 统计时，桶 `k` 的实际占比可以定义为：

```math

p_k=\frac{T_k}{\sum_{j\in K}T_j}
```

其中 `T_k` 是保留并实际进入训练的 token 数，`K` 要覆盖目标桶与实际出现桶的并集，缺少实际 token 的桶记为 0；实际 token 总数必须大于 0。按文档数计算的比例与按 token 计算的比例可能完全不同，长文档来源会在 token 口径下占据更大份额。

目标配比 `p_k^*` 和实际配比之间的偏移为：

```math

\Delta_k=p_k-p_k^*,\qquad
S_{\mathrm{mix}}=\max_{k\in K}|\Delta_k|
```

如果目标桶集合与实际桶集合不一致，应显式处理缺失桶，而不是只对实际出现的桶归一化。`S_mix` 大不一定是事故：有时上采样低资源语言、增加代码或降低风险数据权重就是有意设计；但必须有实验和版本记录支持这个决策。

过滤后的配比尤其容易漂移。原始计划可能是“通用 50%、代码 20%、中文 15%、数学 15%”，但代码数据因为许可证缺口被大量隔离，最终训练分布可能只剩通用、中文和数学。训练日志只记录计划采样器参数而不记录实际 token 分布，就无法解释能力变化。

配比实验应至少包含一个简单基线、一个目标配比和一个或多个反事实版本。固定总 token、训练步数、学习率和评估集，分别观察通用、代码、数学、多语言、长尾和安全切片。DataComp-LM 研究在统一训练配方下比较了多种数据选择与混合策略，但模型规模和评估口径有限，不能据此认定某个配比对其他任务普遍最优。[DataComp-LM](https://proceedings.neurips.cc/paper_files/paper/2024/hash/19e4ea30dded58259665db375885e412-Abstract-Datasets_and_Benchmarks_Track.html)。一个总分上升但关键切片下降的配比，不能只以总分决定采用。

## 2.8 多语言数据事故：平均值会隐藏失衡

多语言训练中，语言能力不是把所有语言分数平均后就能描述的。语言之间有 tokenization 效率、数据质量、资源规模、领域覆盖和脚本差异；机器翻译数据还可能引入翻译腔和错误事实。

至少要按语言记录：

- 原始和保留文档数、token 数；
- tokenizer 平均 token/字符或 token/词；
- 质量和去重率；
- 任务类型与领域覆盖；
- 人工或可靠评估集；
- 语言混用、乱码和格式异常率；
- 过滤前后保留率和实际训练占比。

低资源语言的样本量小，整体平均指标可能对它几乎没有权重。可以报告宏平均（macro average）和微平均（micro average），但两者回答不同问题：

```math

M_{\mathrm{macro}}=\frac{1}{|L|}\sum_{\ell\in L}M_\ell
```

要求语言集合 `L` 非空，且每个 `M_ell` 有有效评估分母。对准确率这类可以按样本汇总的指标，微平均按样本数加权，因而容易被高资源语言主导；宏平均让每种语言权重相同，却会放大小评估集的波动。其他指标要依其定义说明怎样聚合，不能一律把语言分数按样本数加权。报告时应同时给出每语言分数和样本数，不能只报一个总平均。

语言过滤还要注意“看起来脏”的内容可能是目标能力的一部分。口语、错别字、方言、混合语言和非标准标点，在通用网页质量任务中可能被判为低质量，在客服、搜索或语音转写任务中却是必要输入。数据清洗目标必须绑定产品或模型任务。

例如，中文评估有 10 题答对 8 题，英文评估有 100 题答对 90 题。宏平均为 `(0.8+0.9)/2=0.85`，把两种语言各看作一个单位；微平均为 `(8+90)/(10+100)=98/110≈0.891`，让每道题权重相同。两者差异来自评估样本数，不代表哪一种“正确”；应同时列出各语言分数和分母，才能看见小样本波动及高资源语言对总体值的影响。

## 2.9 代码数据的价值和风险必须一起审计

代码数据能提升编程、工具调用和结构化推理能力，但它同时携带许可证、秘密、个人信息、供应链和评估污染风险。仅仅检测文本里有没有 `api_key` 这样的字符串远远不够，却也不能因为风险复杂就不记录任何证据。

代码数据至少需要区分：

1. 来源仓库、提交版本和许可证。
2. 文件路径、语言、构建系统和依赖。
3. 是否包含 secret、token、证书或内部域名。
4. 是否包含个人信息、生产数据或客户样例。
5. 是否有测试文件、参考答案和 benchmark 签名。
6. 是否通过解析、编译、静态检查或最小功能测试。
7. 是否存在重复仓库、fork 和复制粘贴片段。

许可证检查不是一个简单的布尔字段。仓库许可证、单文件头部声明、第三方依赖和生成文件可能具有不同的约束；缺少许可证信息应记录为“未知”，不能自动当作允许，也不能在没有法律判断的情况下把所有未知都标为违法。训练用途、模型输出用途和商业发布用途的风险边界也可能不同。

秘密清理应在原始文件、解析后的文本、代码注释、提交历史和生成的派生数据上分别进行。删除当前文件中的字符串，不代表 token 缓存、向量、快照和训练分片中已经删除。GitHub Secret Scanning 文档说明，其覆盖依赖支持的模式与配置；部分成对模式还要求标识符和 secret 出现在同一文件，推送保护（push protection）也只拦截可高置信识别的一部分模式。因此，它是扫描入口，不是对代码及全部派生数据的完备证明。[GitHub Secret Scanning 检测范围](https://docs.github.com/en/code-security/reference/secret-security/secret-scanning-scope)。发现高风险代码记录后，首先隔离并限制访问，再确定删除传播和重新构建范围。

## 2.10 合成数据要用真实任务与来源链校验

合成数据可以补充难以获得的任务、格式和推理过程；同时，教师模型（teacher）的错误、偏见、拒答风格和模板也可能被学生模型继承。只比较训练损失或合成题上的分数，无法说明它是否改善了真实任务。需要看生成来源、验证过程、真实输入切片，以及合成数据进入训练后带来的分布变化。

合成数据审计至少要记录：

- 教师模型版本和提示版本；
- 生成时使用的工具、检索和验证器；
- 任务、难度和领域分布；
- 接受、拒绝和人工修订的比例；
- 自然数据和合成数据的重复率；
- 教师输出与自然答案的独立错误模式；
- 合成数据在不同训练阶段的使用比例。

验证器通过不等于数据整体正确。数学答案可以通过最终数值检查，却在推理过程、题目条件或单位上出错；代码可以通过一个测试，却包含未覆盖的安全问题。对于不可完全验证的任务，应保留抽样人审和未参与训练的真实数据保留集。

可以用合成 token 占比描述混合情况：

```math

R_{\mathrm{syn}}=\frac{T_{\mathrm{syn}}}{T_{\mathrm{all}}}
```

要求 `T_all>0`。如果清洗后没有任何训练 token，比例未定义；如果总 token 存在但没有合成 token，比例才是 0。自然数据锚点也要按实际保留 token 统计，而不是只看原始数据目录中“存在自然数据”。

为识别教师风格趋同，可以在固定真实问题集上比较自然数据训练、合成数据训练和混合训练的输入改写鲁棒性、答案多样性、事实错误类型和长尾任务表现。合成数据的收益必须超过它引入的分布偏差和验证成本。

“合成数据占比高”本身也不是模型退化的充分条件。递归地用模型生成数据替代真实分布时，研究者观察到模型崩塌风险；一项预印本研究在其设置中发现，把合成数据与真实数据累积混合，避免了替代式训练里出现的崩塌现象。两项结果都受数据、模型和训练方式约束，不能推出一个通用安全占比；工程上应记录每阶段来源，并在固定的真实任务集上比较替代、混合和不加入等反事实方案。[递归训练中的模型崩塌研究](https://www.nature.com/articles/s41586-024-07566-y)（[2025 年勘误](https://www.nature.com/articles/s41586-025-08905-3)）；[真实数据与合成数据累积混合预印本](https://arxiv.org/abs/2404.01413v2)。

## 2.11 过度过滤：干净不等于有用

过滤阈值越高，数据表面上可能越干净，但模型需要的长尾、口语、专业术语、代码边界和少数语言也可能被删掉。过滤器的优化目标不是让数据集看起来整齐，而是让下游任务在可接受风险下获得更好的能力。

设某个切片 `c` 的原始记录数为 `N_c`，保留数为 `K_c`，当 `N_c>0` 时，切片保留率为：

```math

R_{\mathrm{retain},c}=\frac{K_c}{N_c}
```

应同时比较不同切片的保留率、训练占比和下游指标。整体保留率稳定，并不代表低资源语言或罕见领域没有被全部过滤。

过滤阈值附近的样本特别重要。它们能揭示分类器把什么当作噪声，也能发现“低质量信号”和“任务相关性”之间的冲突。一个好的过滤实验至少保留：被保留样本、被拒绝样本、阈值附近样本和人工复核结果。

过度过滤的修复不一定是降低全局阈值。可以采用来源分层阈值、领域专用规则、随机保留小比例、人工标注边界样本、对高风险字段单独处理，或者在训练阶段降低采样权重而不是彻底删除。过滤和采样要能解释每类数据为何被保留或隔离。

例如，一个低资源方言切片原有 10 条，统一阈值只保留 2 条，则该切片保留率为 `2/10=20%`。即使大语种保留率很高、全局保留率看起来稳定，这个切片也可能已经失去训练价值。第 2.15 节中的低资源记录分数只有 0.43，却因任务抽检确认有用而保留，说明质量分数不能独自决定去留。

## 2.12 数据版本和 lineage 决定能否复现、删除和回滚

一个训练版本的数据清单（manifest）不应只有文件路径和总 token。它至少要说明输入来自哪个数据发布和原始快照、原始对象如何识别、每一步处理用了什么版本、实际使用了什么配比，以及最终保留了多少记录和 token：

| 字段 | 记录什么 |
| --- | --- |
| 数据发布与来源快照 | `dataset_release_id`、`source_snapshot_ids`：本次数据版本的标识及抓取/来源快照 |
| 原始对象标识 | `raw_object_hashes`：用稳定哈希把派生记录连回原始对象 |
| 处理版本 | `parser_version`、`normalizer_version`、`dedup_version`、`quality_filter_version`、`risk_scanner_version`：解析、规范化、去重、质量和风险检查各自的规则版本 |
| 训练设置 | `mixture_config`、`tokenizer_version`：目标混合配比和分词器版本 |
| 数据规模 | `record_count`、`token_count`、`retained_count`、`excluded_count`：处理前后记录数及实际 token 规模 |
| 责任与时间 | `created_at`、`owner`：生成时间和负责维护的人或团队 |

每个派生对象要能够回到来源对象。删除一个源文档时，系统需要知道它产生了哪些清洗文本、分块、向量、缓存、评估样本和训练分片；反过来，一个训练分片也要能够追溯到记录集合和处理版本。否则“删除原文件”并不等于删除所有派生数据。

版本比较必须区分内容变化和处理规则变化。相同原始快照使用不同解析器（parser），产生的差异不应被误认为来源更新；同一个清洗脚本处理不同的网页快照，也不应被误认为过滤器回归。

lineage 完整率可以写成：

```math

C_{\mathrm{lineage}}=\frac{N_{\mathrm{complete}}}{N_{\mathrm{records}}}
```

要求 `N_records>0`。完整的定义必须事先写明，例如来源、版本、内容哈希和处理版本都存在才算 complete。没有数据记录时是 `not_applicable`；记录存在但字段缺失是低完整率或 `unknown`，不能用空集合的统计结果冒充 1。

完整率只回答工程记录是否齐全，不回答模型行为由哪个来源造成。DebugLM 研究的是让模型在回答中学习输出来源标签；它与逐记录追踪到处理版本、训练快照和 batch 的工程 lineage 是两类不同问题，标签正确也不是因果归因。[DebugLM 正式论文](https://aclanthology.org/2026.emnlp-main.182/)。数据集说明表可以记录来源、组成、收集和维护信息，但也不自动证明数据具备某项使用权。[Datasheets for Datasets](https://doi.org/10.1145/3458723)。

## 2.13 数据事故的处理顺序

发现疑似数据事故后，先控制影响，再还原证据。一个实用的顺序是：

1. **标记事件**：保存当前训练、评估或上线版本，不覆盖原始结果。
2. **冻结变更**：暂停继续扩展受影响数据或发布，避免调查对象不断变化。
3. **保留样本**：记录原始记录、来源、处理版本、命中规则和评估证据。
4. **分级风险**：区分污染、许可证/秘密/PII、能力分布损失和普通质量问题。
5. **隔离高风险记录**：限制访问，记录删除和重建范围。
6. **重建数据画像**：重新统计重复、污染、风险、配比、语言和 lineage。
7. **做最小反事实实验**：只改变一个数据因素，固定训练和评估条件。
8. **重建干净评估**：对受污染指标、变体题和私有保留集重新测量。
9. **决定修复路径**：重清洗、调整配比、回滚数据版本或重新训练。
10. **补回归与监控**：把这次事故转成样本、规则、指标和版本检查。

其中“隔离”不一定意味着立即永久删除。需要法律、隐私或安全处理的记录，应先保证访问受控和证据保全，再按照组织政策和适用法规完成删除传播。对疑似污染的评估记录，也应保留调查结果和证据等级，避免日后误用旧分数。

## 2.14 汇总数据指标前先问分母和状态

每个指标都要说明统计对象、分母、扫描范围和“完整/命中/风险”的定义。下表中 `N` 是纳入该指标的记录数；`N_scan` 是对应检测器按声明范围实际完成扫描的记录数，检测覆盖不足时不能把未扫描项当作未命中。前文已经给出精确重复、近重复、配比、宏微平均、合成占比、保留率和 lineage 的计算式；这里汇总它们容易被误读的地方。

| 指标 | 统计口径 | 读数时的限制 |
| --- | --- | --- |
| 精确重复 | $R_{\mathrm{exact}}=N_{\mathrm{extra}}/N$；重复组中代表记录之外的记录数 / 被扫描记录数 | 代表版本的选择规则会影响被保留内容，记录数率不能代替 token 率 |
| 近重复候选 | $R_{\mathrm{near}}=N_{\mathrm{pairs}}/[N(N-1)/2]$；候选对数 / 可比较的记录对数，至少有 2 条记录 | 候选率不等于误合并率；检测器没覆盖的记录对也不算已检查 |
| benchmark 候选命中 | $N_{\mathrm{hit}}/N_{\mathrm{scan}}$；命中记录数 / 有效扫描记录数 | 必须存在可比签名、数据版本和扫描范围；命中需要复核，0 命中只表示本次扫描结果 |
| 风险项 | 对每种风险 $j$ 分别报告 $N_{\mathrm{risk},j}/N_{\mathrm{scan},j}$，如许可证未知、secret、PII | 只有在明确联合条件并去重后，才可补充“至少命中一种”的记录比例；不要混成一个含义不清的总分 |
| 配比偏移 | $S_{\mathrm{mix}}=\max_k|p_k-p_k^*|$；按 token 比较实际桶占比与目标 | 目标与实际需覆盖同一桶集合；缺失桶按 0 明示，权重应有限且目标和为 1 |
| 切片保留率 | 某切片保留记录数 / 该切片原始记录数 | 要同时看语言、领域、来源和任务；全局率可能掩盖某一切片被清空 |
| 合成占比 | 实际进入训练的合成 token / 实际训练 token | 说明统计阶段和 token 范围；占比不是质量、正确性或崩塌风险的替代指标 |
| lineage 完整率 | 符合预先定义的完整字段合同的记录数 / 有记录的总数 | 来源、内容标识、转换和快照字段须事先定义；文件存在不代表记录级 lineage 完整 |

没有可用分母时，应区分 `not_applicable`（指标不适用）和 `unknown`（数据、版本或扫描范围缺失）。分母有效但计数为零，可以如实报告 0；它不等于证明总体风险为零。重复、污染、许可、秘密、配比和 lineage 失败的后果不同，应分别报告和修复，不应机械相乘成“数据质量总分”。

## 2.15 用一组记录手算数据事故画像

下面 10 条记录和全部数值都是教学构造，并假设 token 数都由同一分词器版本统计。除表中明确注明的 J 外，记录的来源快照、内容标识和处理版本齐全；A、B 归一化后的正文完全一致。我们先逐条决定“保留、去重、隔离、复核或排除”，再汇总分布；这些标签是这个场景中的调查决定，不是通用阈值或法律结论。

| 记录 | 桶 | token 数 | 观察到的证据 | 初步处理 |
| --- | --- | ---: | --- | --- |
| A | web | 100 | 正常正文；来源和转换版本齐全 | 暂留；作为精确重复组的代表 |
| B | web | 100 | 内容与 A 完全相同，来源和版本齐全 | 去重；保留 A，登记代表选择关系 |
| C | web | 80 | 与 A 有大量共享片段，是近重复候选 | 隔离复核；相似不直接等于重复 |
| D | 低资源中文 | 60 | 质量分类器给 0.43；任务抽检确认是有用方言输入 | 保留；不让单一质量分数决定去留 |
| E | math | 50 | 命中公开评测题和答案的组合 | 隔离复核评测污染；不直接据此判断模型记忆 |
| F | code | 70 | 许可证信息未知 | 暂停使用并查明权利状态；不把“未知”写成“违法” |
| G | code | 40 | 秘密扫描有命中 | 限制访问、隔离，并查删除传播范围 |
| H | synthetic | 90 | 教师生成；答案经本例所用验证流程检查；来源版本齐全 | 暂留为候选，后续仍须看真实任务效果 |
| I | web | 50 | 抽样确认是重复关键词的垃圾页面 | 按本例质量规则排除 |
| J | rare domain | 40 | 处理版本缺失，其他来源记录存在 | 隔离补 lineage；不能据此推断内容质量 |

10 条记录合计 680 个 token。先看重复：重复组里多出的记录只有 B，所以按记录数的精确重复率为 `1/10=10%`。A、B token 数相同，因此本例按 token 计算也为 `100/680≈14.7%`；如果重复样本长短不同，这两个比例就会分开。

再看近重复。10 条记录共有 `10×9/2=45` 个无序记录对，本例发现 A–C 这一对候选，因此候选对率为 `1/45≈2.2%`。如果这对共享的三元片段集合分别为 `G_3(A)={现行-安全-规则, 安全-规则-生效}` 和 `G_3(C)={现行-安全-规则, 安全-规则-生效, 规则-生效-说明}`，交集大小为 2、并集大小为 3，Jaccard 相似度就是 `2/3≈0.67`。这表示值得复核，不表示 C 一定应删除。

评测命中方面，E 是 10 条扫描记录中的 1 条候选命中，因此本轮候选命中率为 `1/10=10%`。该数字只描述这批记录和当前签名扫描；要判断污染影响，还需核对题目、答案、公开时间和模型评估表现。

风险分类应拆开计数：F 的许可证状态未知，G 有秘密扫描命中，各为 `1/10`；若只为汇总“至少命中上述一种”的记录，本例是 `2/10=20%`。这个并集率不能替代两项各自的处置，也不能把未知许可与确认泄露说成同一风险等级。

lineage 合同在本例要求来源快照、内容标识和处理版本。只有 J 缺少处理版本，所以完整记录为 9 条，完整率是 `9/10=90%`。缺字段不代表数据内容一定有问题，但它会使重建和删除传播缺少一个必要锚点。

按前述决定，A、D、H 暂列实验候选，共 3 条记录、250 个 token。记录保留数是 `3/10=30%`；该数字只是本例当前处置后的候选率，C、E、F、G、J 仍待相应复核，并非可以直接训练的许可结论。若后续实验目标桶及目标占比分别为 web 30%、低资源中文 20%、code 15%、math 15%、synthetic 10%、rare domain 10%，则候选集的实际配比如下：

| 数据桶 | 目标占比 | 候选 token | 候选占比 | 偏移 |
| --- | ---: | ---: | ---: | ---: |
| web | 30% | 100 | 40% | +10 个百分点 |
| 低资源中文 | 20% | 60 | 24% | +4 个百分点 |
| code | 15% | 0 | 0% | −15 个百分点 |
| math | 15% | 0 | 0% | −15 个百分点 |
| synthetic | 10% | 90 | 36% | +26 个百分点 |
| rare domain | 10% | 0 | 0% | −10 个百分点 |

目标占比合计 100%，候选占比也合计 100%。最大绝对偏移是 `26` 个百分点，来自 synthetic 桶。它不是自动失败判定，而是提示当前候选数据没有兑现原定 mixture；需要决定是补数据、改实验目标，还是说明这次实验只回答有限问题。H 的合成 token 占候选 token 的 `90/250=36%`，这个教学比例也不代表合成数据天然有害；是否采用仍要按第 2.10 节的真实任务对照来判断。

这份账本给出的不是一个总分，而是一组不同动作：B 去重、C 和 E 复核、F 和 G 按风险隔离、I 按质量规则排除、J 补 lineage，A/D/H 才进入下一轮候选评估。这样能看出每个结果由哪条证据触发，也能避免用一个任意的“通过/不通过”阈值掩盖未解决事项。

## 2.16 从数据事故中恢复分布

修复数据后不能只看“删除了多少条”。应该重新计算：

1. 每个来源、语言、领域和任务的保留率。
2. 精确重复和近重复的剩余候选。
3. 评估集和训练集的污染命中及证据等级。
4. secret、PII、许可证未知和其他风险的隔离数量。
5. 实际 token mixture 与计划配比的偏移。
6. 自然、合成、蒸馏数据的实际占比。
7. 记录级 lineage 完整率和删除传播覆盖。
8. 过滤前后固定评估集的能力变化。

如果某个切片被大量过滤，应把它作为一个独立实验，而不是让它消失在总体统计中。例如，在一组教学统计中，rare domain 的保留率从 80% 降到 5%；即使总保留率仍然是 50%，也应该触发人工抽样和下游能力评估。数据治理的目标不是尽可能让统计表漂亮，而是让分布变化可以被看见、解释和回滚。

## 2.17 数据事故复盘应回答的事实

一份可执行的数据事故记录至少包含：

```text
现象：训练、评估或线上行为发生了什么变化
数据版本：原始快照、处理版本和训练 manifest
影响范围：哪些任务、语言、领域、模型或评估受到影响
第一处分歧：哪个处理阶段最早偏离预期
证据：样本、hash、命中规则、统计切片和版本对照
风险动作：隔离、停止使用、删除传播或权限限制
修复：规则、数据、配比、评估集和脚本的变化
验证：固定集、变体集、反事实 mixture 和安全扫描结果
剩余未知：哪些结论仍缺少训练或业务证据
防复发：manifest、lineage、监控、抽样和回归负责人
```

“数据清理完成”不是验证结果。验证应该回答“什么样本被改变”“哪些能力恢复”“哪些风险已经隔离”“新版本是否仍可追溯”。如果没有保存旧版本和处理日志，无法证明清理前后的差异，也无法在修复过度时回退。

## 2.18 资料与证据边界

本章把论文、官方文档和数据集资料用于不同范围的问题：

- [GPT-3: Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165) 的训练集重叠分析说明，大规模语料需要检查重复与评估集交叉；论文也显示重叠命中会有误报，不能单独证明分数被污染。
- [Deduplicating Training Data Makes Language Models Better](https://arxiv.org/abs/2107.06499) 报告了特定语料和模型上的去重实验结果，支持把去重作为泛化与记忆风险的调查方向；它不提供跨数据类型通用的相似度阈值。
- [C4 语料研究](https://arxiv.org/abs/2104.08758v2)、[The Pile](https://arxiv.org/abs/2101.00027)、[FineWeb](https://arxiv.org/abs/2406.17557) 和 [DataComp-LM](https://proceedings.neurips.cc/paper_files/paper/2024/hash/19e4ea30dded58259665db375885e412-Abstract-Datasets_and_Benchmarks_Track.html) 展示了不同语料的来源、过滤、文档化和评估方法；各自的数据版本、清洗目标和许可证不能互相替代。
- [Datasheets for Datasets](https://doi.org/10.1145/3458723) 提供记录动机、组成、收集、使用建议和维护过程的文档框架；填写说明不能自动证明数据拥有特定用途的权利。
- [GitHub Secret Scanning 文档](https://docs.github.com/en/code-security/concepts/secret-security/secret-scanning) 和[检测范围说明](https://docs.github.com/en/code-security/reference/secret-security/secret-scanning-scope)展示一种工程扫描入口；支持的模式与配置有限，不能代替对提交历史和训练派生对象的全链路处置。
- [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) 提供风险识别、管理和治理的框架语言；它不是许可证、隐私或数据跨境处理的法律意见。

网页、代码和模型生成数据的来源可信度不同。公开页面可以作为采集对象，但不自动等于可靠事实；模型生成答案可以作为候选数据，但不自动等于正确标签；产品页的基准测试可以作为调查入口，但不能替代固定评估集和逐样本证据。数据结论必须标注来源、版本、检测器和评估条件。

## 2.19 本章小结

数据事故的核心不是某条过滤规则写错，而是数据分布和证据链失去控制。精确重复、近重复和 benchmark 污染影响训练有效信息与评估可信度；网页噪声、过度过滤和多语言失衡改变能力覆盖；代码风险和合成数据引入许可证、秘密、隐私和 teacher 偏差；配比漂移和 lineage 缺口则让实验无法解释、删除无法传播、回滚无法执行。

处理数据事故时，应先保存原始记录和版本，再分离重复、污染、风险、质量和配比问题；先隔离高风险数据，再用固定样本和反事实实验验证修复；最后把规则、统计、lineage 和回归写进下一版 manifest。只要数据能够被追溯、被切片、被复现和被质疑，模型效果异常才有机会从“感觉不对”变成可验证的工程结论。
