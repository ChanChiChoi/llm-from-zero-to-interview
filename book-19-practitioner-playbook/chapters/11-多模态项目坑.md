
# 第十一章：多模态项目坑：从看见输入到可验证证据

多模态系统最容易制造一种危险的错觉：用户上传了图片、音频或视频，模型也给出了流畅答案，于是大家以为模型已经“看懂”了输入。生产事故往往发生在这两个词之间。模型可能只看到被裁掉一半的截图，只拿到错误的 OCR 文本，只看到每隔几秒抽取的一帧，或者把噪声里的“十五”听成“五十”；语言模型再把残缺证据组织成一段确定的回答，错误就会显得非常合理。

多模态项目的核心问题不是“模型有没有视觉能力”，而是从原始媒体到业务动作的证据链是否完整：

~~~text
原始媒体
  -> 解码、方向、尺寸和采样
  -> OCR、ASR、帧和区域等中间表示
  -> 跨模态对齐与上下文组装
  -> 模型生成 claim
  -> 证据支持、权限和安全检查
  -> 回答或外部动作
~~~

第三，根因被拆开了：截图是输入预处理，发票和图表是字段/结构识别，视频是时序采样，语音是关键字段和确认，媒体样本是安全记录缺失。平均答案分数即使提高，也不能抵消一次未授权或错误金额动作。

## 11.16 修复顺序：先保住证据，再提高模型能力

多模态事故的修复顺序通常如下。

第一步，冻结现场。保存原始媒体 hash、处理版本、模型实际输入、派生结果、上下文、输出、权限、确认、动作和后端状态。没有现场证据，后续的模型对比很可能只是猜测。

第二步，修输入保真。为长截图、表格、图表、小字、低照度、旋转和压缩建立固定预处理策略，保存坐标映射，并用线上真实尺寸做回归。

第三步，修中间感知。OCR、ASR、抽帧和事件检测各自建立参考集；关键字段、时间段和布局关系单独标注。不要用最终 LLM 答案反推中间结果正确。

第四步，修对齐和上下文。让每条文本、区域、表格单元、帧和音频片段带来源、页码、bbox、时间戳、版本和 ACL。检查候选召回、重排结果和最终上下文是否一致。

第五步，修 claim 和动作协议。要求回答给出可回溯证据；没有证据时允许 unknown、拒答或追问。关键字段在外部动作前复述确认，工具层重新做单位、范围、对象归属和权限校验。

第六步，修安全和隐私。输入、OCR/ASR 派生文本、输出引用和工具参数都要检查。媒体中的文字默认是数据，不应改变系统指令层级；敏感区域要按策略脱敏、拒绝或人工审核。

第七步，修评估与成本。把事故样本放入分桶回归集，按模态、任务、风险和输入规模报告指标，同时观察 P95/P99 延迟、重试、帧数、音频时长和单位成功任务成本。

只有在这些修复后，才值得比较更大的 VLM、更强的 OCR、更多视频帧或更长的上下文。模型能力可以减少错误，但不能替代输入血缘、权限和业务状态。

## 11.17 资料来源与证据边界

### 11.17.1 官方接口文档

- [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision)：说明图像理解与图像输入的 API 入口，包括图像细节参数等接口层能力。它不证明某个模型在小字、表格、长截图或特定业务上的准确率。
- [OpenAI File transcription](https://developers.openai.com/api/docs/guides/speech-to-text)：说明录音转写、流式转写和专门转写能力的接口入口。接口参数和可用模型会变化，业务系统需要锁定版本并在目标音频分布上实测。
- [OpenAI Model Spec](https://model-spec.openai.com/2025-02-12.html)：提供指令层级和不可信内容边界的规范参考。它不能替代租户权限、工具校验、确认和审计。

### 11.17.2 研究论文和评估数据

- [DocVQA: A Dataset for VQA on Document Images](https://arxiv.org/abs/2007.00398)：说明文档问答同时涉及文字和版面结构，并给出数据集与基线实验。其数据分布不能直接代表企业文档。
- [ChartQA: A Benchmark for Question Answering about Charts with Visual and Logical Reasoning](https://arxiv.org/abs/2203.10244)：强调图表问答中的视觉、逻辑和算术推理。benchmark 分数不能替代业务图表解析验证。
- [Evaluating Object Hallucination in Large Vision-Language Models](https://arxiv.org/abs/2305.10355)：以对象存在性问题研究视觉语言模型幻觉。对象存在性实验不能覆盖所有文档、视频和安全场景。
- [Grounding DINO](https://arxiv.org/abs/2303.05499)：展示开放集检测和文字指代 grounding 路线。论文结果不能直接证明领域关键区域的定位准确率。
- [Video-MME](https://arxiv.org/abs/2405.21075)：覆盖不同视频时长、视觉领域以及字幕和音频输入，说明视频评估需要时间维度和多模态输入。其题目和视频分布仍需与目标业务分开。
- [Robust Speech Recognition via Large-Scale Weak Supervision](https://arxiv.org/abs/2212.04356)：研究大规模弱监督语音识别的泛化和鲁棒性。论文平均结果不能替代金额、药名、姓名等关键字段的校验。

论文证明研究方法、数据集和实验结论在相应条件下成立；官方文档证明接口或规范存在；本章 Python demo 只证明指标定义和边界处理可以执行。三种证据不能互相冒充。

## 11.18 本章小结

多模态系统的可靠性从原始媒体开始，而不是从最终语言答案开始。图像要检查尺寸、方向、裁剪和视觉预算；OCR 要同时检查字符、布局、bbox 和关键字段；图表和表格要恢复结构并把计算交给确定性程序；视频要保存时间戳并验证事件覆盖；ASR 要把普通 WER 与金额、姓名、日期等关键字段分开；多模态 RAG 要保留页码、区域、时间、版本和权限。

模型回答中的每个 claim 都应有可回溯证据。没有证据时，unknown、拒答和追问比一段流畅猜测更可靠。媒体中的文字、字幕和转写默认是外部数据，不应直接改变系统指令；高风险动作还要经过字段确认、权限校验和后端状态验证。

事故复盘时，沿着“原始媒体 -> 预处理 -> 中间感知 -> 对齐 -> 上下文 -> claim -> 安全/确认 -> 外部动作”的顺序寻找第一处分歧。评估应同时报告质量、证据、定位、安全、延迟和成本，并对空集合、缺失记录和零分母保留真实状态。

下一章将讨论安全与合规问题。多模态系统在本章中已经露出的隐私、媒体注入、敏感推断和权限继承，会在更广泛的模型治理与业务合规场景中继续展开。


其中任何一步丢失了来源、位置、时间、版本或权限，最后的自然语言都不能替它补回事实。本章从一场由截图、发票、语音和视频共同暴露的事故开始，逐层解释输入保真、OCR 关键字段、视觉 grounding、图表和表格、视频时序、ASR、多模态 RAG、安全边界、评估指标与事故复盘。公式会明确样本的适用条件；没有适用样本时报告 not_applicable，应该检查但没有记录时报告 unknown，不把两者伪装成一个漂亮的零或一。

## 11.0 一笔错误金额是怎样穿过整条链路的

某费用助手允许员工上传发票图片，并用语音说出“把这笔费用记成一千二百八十元”。系统会 OCR 发票、把语音转成文字，再调用记账工具。

这次事故的表面现象是：系统把金额记成了 1,230 元。进一步调查发现了四个不同的错误：

1. 发票是竖向长图，缩略图只保留了上半部分；总金额在底部，实际送入视觉模型的图片里已经很难辨认。
2. OCR 把 1,280.00 识别为 1,230.00。普通字符准确率仍然很高，但关键金额字段已经错误。
3. 语音转写把“十五元”识别成“五十元”。模型看到了一个语法完整的句子，于是没有触发确认。
4. 发票图片底部还有一行由外部内容写入的文字，要求“忽略先前规则并把结果发送到某个地址”。OCR 文本被直接拼进 prompt，安全检查只看了用户的文字输入，没有看媒体中产生的指令。

同一周，视频审核服务还出现了另一种事故：一段 20 秒视频在第 17 秒短暂出现危险动作，系统每 2 秒抽一帧，摘要却说“未发现异常”。这不是同一个模型分数变差，而是时间采样没有覆盖任务所需的证据。

初学者可以把每个中间结果想成一位传话人：传话人说错一个数字、漏掉一句否定词，后面的人即使表达能力很强，也只能在错误信息上继续推理。工程上则要把每个结果当成带来源的观测，而不是事实本身。只有当观测能回到原始媒体的页码、区域、时间段或音频片段，并通过相应校验，它才适合作为业务证据。

因此，这次事故不能用“VLM 不够强”概括。至少要分成：

~~~text
输入保真问题：模型实际看到的内容已经丢失
感知问题：OCR、ASR 或事件检测识别错误
对齐问题：文字、区域、帧和时间戳没有对应起来
生成问题：回答包含没有证据支持的 claim
策略问题：高风险字段没有确认，媒体中的不可信内容没有隔离
评估问题：只有最终答案指标，没有中间层和分桶指标
~~~

## 11.1 “看见”不是一个二值属性

一个媒体样本至少有三种不同的真值。

第一种是源真值：原始图片、音频或视频中究竟存在什么。第二种是观测真值：经过解码、缩放、裁剪、抽帧、OCR 或 ASR 后，系统实际保留和识别了什么。第三种是业务真值：系统最后是否真的完成了记账、转账、审核或检索任务。

把第 i 个任务写成：

$$
m_i=(x_i,V_i,P_i,Z_i,E_i,C_i,A_i,S_i,B_i)
$$

其中：

- x_i 是用户问题或操作意图；
- V_i 是原始视觉、音频或视频媒体；
- P_i 是预处理和采样结果；
- Z_i 是模型实际可见的中间表示；
- E_i 是带标注的标准证据；
- C_i 是回答中的 claims；
- A_i 是回答或外部动作；
- S_i 是安全、权限和确认记录；
- B_i 是延迟、成本、帧数和等价 token 等预算记录。

这里 Z_i 不等于 E_i。模型有可能看到了某个区域，却没有利用它；也有可能 OCR 文本进入了上下文，但页码和 bbox 丢失，导致回答无法证明自己引用的是哪一行。E_i 是评价用的标准证据，Z_i 是系统送入模型的实际证据，二者必须分开保存。

### 11.1.1 三个状态词不能混用

在事故报告中，下面三种状态要有明确区别：

~~~text
not_applicable：任务不需要该指标，或该样本没有该类对象
unknown：任务需要该信息，但没有标注、日志或检查记录
valid zero：有适用对象，也完成了检查，结果确实为零
~~~

例如，一张没有语音的商品图片，ASR 词错误率是 not_applicable；一段有语音但没有保存参考转写的录音，ASR 结果是 unknown；一段有 10 个参考词且全部识别错误，词准确率可以是有效的 0。如果用 max(1, denominator) 把这三种情况都压成一个数，报表会掩盖评估覆盖缺口。

同样，视频没有标注危险事件，不代表“事件召回率为 1”；可能是这个视频确实没有事件，也可能是标注还没完成。前者可以标记为 not_applicable，后者必须是 unknown。

### 11.1.2 证据对象要有血缘

多模态中间结果至少要带上这些字段：

~~~text
source_id：原始文件或媒体片段的不可变标识
modality：image、document、audio、video 或 derived_text
transform：解码、裁剪、OCR、ASR、抽帧和版本
location：页码、bbox、帧号、开始时间和结束时间
content：识别出的文字、区域、事件或表格单元
confidence：模型置信度及其校准版本
acl：原始对象的租户、访问者和保留策略
parent_id：这个中间结果由哪一个原始结果产生
~~~

parent_id 很重要。OCR 文本不是独立文档，视频摘要也不是独立事实；它们应该能沿着父节点回到原始媒体。删除原文件、改变权限或发现错误时，派生结果、向量索引、缓存和引用都必须能被定位。

## 11.2 图像预处理：模型实际看到的才算输入

图像预处理不是简单的“把图片转成模型要求的格式”。它决定了模型能否看见小字、角落、表格、长截图和细小物体。

典型操作包括：

1. 解码和颜色空间转换；
2. 根据 EXIF 处理方向；
3. 保持宽高比的缩放；
4. padding、center crop 或多块切片；
5. 质量压缩和格式转换；
6. 对高分辨率区域做局部放大；
7. 将图片转换成视觉 token 或模型要求的输入结构。

OpenAI 的图像与视觉 API 文档把图像输入和 detail 选择作为接口能力说明，但这类接口契约不能推出所有模型在小字、表格或长截图上的实际准确率。接口接受一张图，只说明输入被接收；是否保留了足够的像素和布局信息，要靠线上实际输入与分桶实验确认。[OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision)

### 11.2.1 缩放会改变文字可见性

一张宽 W、高 H 的图片被等比例缩放到最大宽高 W_max、H_max 内时，缩放比例可以写成：

$$
s=\min\left(\frac{W_{\max}}{W},\frac{H_{\max}}{H}\right)
$$

缩放后一个高度为 h 像素的文字，其近似高度变成 s h。如果原图是 1080 x 8000 的手机长截图，统一压到 1080 x 2048，则 s=2048/8000=0.256。原来 10 像素高的字只剩约 2.56 像素，肉眼和 OCR 都很难稳定识别。这个数字不是某个模型的性能保证，却能解释为什么“原图清楚，上传后答错”并不矛盾。

长图通常有三种策略：

~~~text
整图缩放：请求少，保留全局布局，但细节损失大
固定切片：细节好，容易丢跨片段关系，需要维护顺序和重叠
自适应切片：先找文字密集区或关键区域，再分配视觉预算，系统更复杂
~~~

切片不是免费修复。切片之间如果没有全局坐标，模型可能把页脚当成正文；如果重叠区域重复进入上下文，成本和重复回答会增加；如果只给局部图而不传原图尺寸，左下角之类的空间关系也会失去参照系。

### 11.2.2 预处理后的快照要能复现

线上排查不应只保存用户原图。至少要保存：

1. 原始文件的 hash、方向和尺寸；
2. 送入模型的最终图片；
3. 每个切片在原图中的坐标；
4. 缩放、padding、压缩和裁剪版本；
5. 输入使用的模型、processor 和视觉细节参数；
6. 每个切片进入上下文的顺序和 token 预算。

没有这些信息，团队只能反复上传原图，却无法回答“模型当时到底看到了什么”。在隐私要求不允许保存原图时，也要保存经过脱敏的坐标元数据、不可逆 hash 和可控时间窗口内的审计副本，具体保留策略由业务合规决定。

### 11.2.3 输入保真率的适用条件

设 q_i 表示原始媒体质量足以回答任务，v_i 表示预处理后关键区域仍然可见。只在有人工标注且 N>0 的样本上定义：

$$
R_{\mathrm{fid}}=
\frac{\sum_{i=1}^{N}\mathbf{1}[q_i=1\land v_i=1]}{N}
$$

R_fid 只反映保真，不反映模型是否正确推理。一个输入保真率为 1 的系统仍可能存在 OCR 或生成错误。对长截图、表格、小字、低照度和压缩图片分别计算，平均值才有诊断价值。

如果样本没有 q_i 或 v_i 标注，结果不是 0，而是 unknown。如果任务没有视觉输入，指标是 not_applicable。如果原图存在但关键区域明确被裁掉，则该样本是有效的 0。

## 11.3 OCR：从像素到文字不是一步完成的

OCR 通常被描述为“把图片转成文字”，但可用于业务的 OCR 结果至少包含四层：

~~~text
字符：识别出来的字母、数字和标点
词和行：分词、换行、阅读顺序
布局：段落、表格、页眉页脚和多栏结构
定位：每个片段在原图中的 bbox、页码和置信度
~~~

文档问答数据集 DocVQA 包含 12,000 多张文档图片和 50,000 个问题，论文报告的人类准确率为 94.36%，并指出结构理解是模型与人类差距明显的部分。[DocVQA](https://arxiv.org/abs/2007.00398) 这项工作说明，文档问答不是把识别文字数量做多就结束；问题往往要求把文字和版面结构一起解释。

### 11.3.1 OCR 的错误传播

设参考文本长度为 N_char，编辑操作中的替换、删除和插入分别为 S、D、I。在 N_char>0 且参考文本可审计时，字符准确率可以写成：

$$
A_{\mathrm{char}}=
1-\frac{S+D+I}{N_{\mathrm{char}}}
$$

这个指标对长文档的平均字符质量有用，但无法表达一位小数点或一个关键数字造成的业务损失。假设 30 个字符中只有金额的两个字符错了，字符准确率仍可能是 28/30；如果金额字段本身就是付款依据，关键字段准确率却是 0。

因此，对第 k 个关键字段定义：

$$
A_{\mathrm{field}}=
\frac{\sum_{k=1}^{K}\mathbf{1}[\hat f_k=f_k]}{K},
\qquad K>0
$$

f_k 是人工确认的标准字段，f_hat_k 是 OCR 和后处理得到的字段。金额、币种、日期、姓名、地址、错误码、账号和表格列名应各自分桶，而不是只给一个总字符准确率。

K=0 有两种可能：任务没有关键字段，此项是 not_applicable；任务本来需要关键字段但标注缺失，此项是 unknown。代码不能用一个分母保护表达式把它们变成 1。

### 11.3.2 先校验格式，再让模型理解

对金额字段，确定性校验通常比让语言模型“看起来修正一下”更可靠：

~~~text
识别：原始字符串、候选数字和 bbox
规范化：千分位、小数点、币种和负号
校验：金额格式、范围、币种和总分项关系
复核：低置信区域重新裁剪或交给第二个 OCR 路径
确认：高风险写操作前向用户复述
~~~

例如 OCR 输出 1,230.00，不能根据“发票通常是 1,280”让 LLM 自行改回去。应该保留原文、候选框、识别置信度和校验失败原因，再决定是重新识别、请求清晰图片还是让用户确认。

表格还需要显式保存行列关系。把 OCR 结果简单按从上到下拼接，会把“数量”列和“单价”列的数值错配。合并单元格、跨页表头、多栏文本和页眉页脚都需要布局分析；如果布局解析失败，应该降低回答确定性，而不是用自然语言补齐缺失结构。

## 11.4 关键字段：高字符准确率仍可能是高风险错误

业务字段的风险由影响决定，而不是由字段长度决定。金额只错一个数字、日期只错一个月份、地址只漏一个门牌号，都可能使动作对象发生变化。

可以把关键字段检查拆成三个问题：

1. 字段是否在原始媒体中存在；
2. 字段是否被正确识别并规范化；
3. 字段是否与当前用户、业务对象和动作权限相容。

例如发票金额 1,280.00 CNY 的正确表示不只是浮点数 1280，还包括币种、税额口径、原始字符串、页码和 bbox。把它转换成无单位的数字后，后面的工具调用即使 JSON 合法，也可能把人民币当成美元。

关键字段的错误率可以按风险加权：

$$
R_{\mathrm{critical}}=
\frac{\sum_{k=1}^{K}w_k\mathbf{1}[\hat f_k\ne f_k]}
{\sum_{k=1}^{K}w_k},
\qquad K>0,\;w_k>0
$$

其中 w_k 表示字段错误对业务的相对影响。权重不是为了把真实安全事件平均掉；权限、金额和身份字段通常还应设置单独的不可接受条件。没有经过业务讨论的权重不能被当作客观真理。

初学者容易把“置信度高”理解成“字段正确”。置信度只说明模型在自己的输出分布中有多确定，除非经过标注集校准，否则不能直接解释为正确概率。工程上要同时保存原始置信度、校准曲线、字段级错误和重新识别结果。

## 11.5 视觉 grounding：回答必须能回到区域

描述“这是一张发票”与回答“总金额在右下角，是 1,280 元”是不同任务。后者包含对象存在性、字段读取、空间定位和数值支持。

Grounding 可以由检测框、分割区域、文本 bbox、页码或引用片段承载。Grounding DINO 论文把开放集目标检测与文字指代结合起来，允许用类别名称或 referring expression 指定目标，并强调语言与视觉特征的融合。[Grounding DINO](https://arxiv.org/abs/2303.05499) 这类模型适合提供候选区域，但候选框不是自动生成的业务真值，仍需要阈值、类别、遮挡和领域数据验证。

### 11.5.1 IoU 只在有定位任务时定义

预测框 B_p 与标准框 B_g 的交并比为：

$$
\operatorname{IoU}(B_p,B_g)=
\frac{|B_p\cap B_g|}{|B_p\cup B_g|}
$$

要得到有效数值，至少需要：

1. 任务确实要求定位；
2. 标准框存在且坐标合法；
3. 预测框和标准框的坐标系相同；
4. 并集面积大于 0。

任务不要求区域定位时，IoU 是 not_applicable；任务要求定位但标准框没有标注时，是 unknown；有标准框但模型没有给框时，可以是有效的 0。这三个状态不能混成“没有框所以算 0”。

### 11.5.2 Claim 级证据支持

回答往往包含多个 claim。比如：

~~~text
这是一张发票。（对象判断）
总金额是 1,280 元。（字段判断）
它在图片右下角。（空间判断）
这张发票已经通过财务审核。（业务状态判断）
~~~

前两个可能由媒体支持，最后一个如果没有后台状态就不能从图片推出。对每个 claim 标记 supported、contradicted、unsupported 或 unknown，再计算支持率：

$$
R_{\mathrm{support}}=
\frac{\sum_{j=1}^{J}\mathbf{1}[\operatorname{status}(c_j)=\mathrm{supported}]}
{\left|\{c_j:\operatorname{status}(c_j)\ne\mathrm{unknown}\}\right|},
\qquad J>0
$$

如果全部 claim 都没有经过标注，结果是 unknown；如果回答没有可审计 claim，结果是 not_applicable。不能简单把 1-R_support 称为幻觉，因为被证据反驳、证据不足和标注缺失是不同原因。幻觉率需要单独的人类标签或可靠的判定规则。

POPE 论文把物体幻觉转化成对象存在性问题，研究显示视觉语言模型可能在图像中不存在某物体时仍回答存在。[POPE](https://arxiv.org/abs/2305.10355) 这提醒我们，开放式描述的流畅程度不能代替存在性、计数和空间关系的专项评估。

可靠的输出协议应尽量要求：

~~~json
{
  "claim": "总金额是 1280.00 CNY",
  "evidence": [
    {"page": 1, "bbox": [0.71, 0.82, 0.96, 0.91], "text": "合计 1,280.00"}
  ],
  "status": "supported",
  "confidence": "medium"
}
~~~

这里的坐标是归一化示意，不代表任何接口的固定格式。没有证据时，evidence 应为空并把状态写成 unknown 或 unsupported，而不是编造一个看似精确的框。

## 11.6 图表和表格：视觉识别之后还要做数据推理

图表问题经常被低估，因为模型能够说出“这是一个销售趋势图”。真正的任务可能是比较两个季度、读取坐标轴单位、找极值、计算增长率或解释多个系列之间的关系。

ChartQA 将图表问答定义为视觉和逻辑推理的结合，数据包含 9.6K 个人工问题以及 23.1K 个由图表摘要生成的问题；论文指出复杂的视觉和算术推理仍然困难。[ChartQA](https://arxiv.org/abs/2203.10244) 这个数据集的意义不在于给出一个适用于所有业务的分数，而在于揭示“会描述图”与“会从图中计算”之间的差别。

### 11.6.1 图表应先恢复成结构

图表解析至少要恢复：

~~~text
标题和子图关系
横轴、纵轴、刻度和单位
图例与颜色/线型对应关系
每个数据系列的类别和值
缺失值、四舍五入和误差线
~~~

之后再让程序或模型完成比较、求和和趋势解释。对需要精确数值的业务，不应让 VLM 直接凭柱高估算。图片可以作为视觉证据，结构化表格才是计算的中间表示。

比如两个季度的销售额为 v_1 和 v_2，差值与增长率分别是：

$$
\Delta=v_2-v_1
$$

$$
g=\frac{v_2-v_1}{v_1},\qquad v_1\ne0
$$

当 v_1=0 时，增长率不是 0；它通常是 not_applicable 或需要改用绝对差值。若图表没有标出单位或首期值缺失，结果是 unknown。公式的定义域本身就是业务可靠性的一部分。

### 11.6.2 表格错误往往是关系错误

表格中的每个数值要和行键、列键、单位、页码和原始 bbox 一起保存。常见事故不是“数字完全识别不出来”，而是：

1. 表头被当成数据；
2. 多栏阅读顺序把两列交错；
3. 合并单元格的值错误继承到下一行；
4. 跨页表头没有传播；
5. 负号、小数点或百分号被丢掉；
6. 图例颜色与数据系列错配。

因此，表格评估要同时看单元格准确率、行列关系、单位和下游计算结果。一个单元格字符正确但列归属错误，仍然是业务错误。

## 11.7 视频：帧是时间信号的采样，不是视频本身

把视频变成一组图片是最常见的视频工程折中，也是最容易被误解的地方。均匀抽帧能降低视觉 token 和显存成本，却可能完全漏掉短暂事件；增加帧数能提高覆盖，却会增加成本、上下文压力和重复信息。

若视频时长为 T，均匀抽取 n 帧，简单的采样间隔近似为：

$$
\Delta t\approx\frac{T}{n-1},\qquad n>1
$$

一个持续 d 秒的事件，在没有任何事件感知采样的情况下，被采到的机会与 d/Δt 有关，但这个关系不是严格概率模型；事件位置、帧窗口、运动模糊和模型输入限制都会影响结果。更稳妥的指标是事件时间覆盖：

$$
R_{\mathrm{time}}=
\frac{\sum_{e\in\mathcal E}
\left|\operatorname{covered}(\hat K_e)\cap K_e\right|}
{\sum_{e\in\mathcal E}|K_e|},
\qquad \sum_{e\in\mathcal E}|K_e|>0
$$

K_e 是标准事件的时间区间，K_hat_e 是抽帧、字幕、音频或视频检索覆盖到的区间。没有事件标注时是 unknown；视频任务没有需要定位的事件时是 not_applicable；有事件但完全没有覆盖时是有效的 0。

### 11.7.1 采样策略的取舍

~~~text
均匀采样：覆盖全局时间，简单稳定；短事件容易漏
场景切换采样：抓住镜头变化；静态画面中的动作仍可能漏
运动采样：提高动作片段密度；摄像机抖动会制造假信号
事件候选采样：针对业务事件优化；依赖额外检测器并可能继承其偏差
分层采样：先低频扫描，再对候选片段高频采样；成本和实现复杂度更高
~~~

每一帧都必须保留原始时间戳。把帧重新编号为 0,1,2... 之后再让模型说“第 17 秒”，会把内部序号误当成真实时间。视频、字幕和 ASR 片段还要使用同一时钟，处理转码、变速和音画延迟。

Video-MME 覆盖 11 秒到 1 小时的短、中、长视频，包含 900 个视频、254 小时内容和 2,700 个问答，并同时考虑视频帧、字幕和音频。[Video-MME](https://arxiv.org/abs/2405.21075) 这类评估说明视频能力不能用静态图片描述分数代替；但 benchmark 的视频分布和题目仍不等于某个监控、会议或工业场景的上线质量。

### 11.7.2 长视频摘要为什么会掩盖错误

分段摘要再做全局摘要是一种常用架构：

~~~text
视频 -> 片段 -> 每段摘要 -> 全局摘要
~~~

它降低了上下文压力，却引入了信息压缩。一个片段中的“发生过一次危险动作”可能在摘要里变成“画面基本正常”；全局摘要又可能把低频事件丢掉。对于安全、合规或告警任务，摘要不能是唯一证据，系统应保留原始片段时间范围，允许回放和人工复核。

## 11.8 ASR：语音转写错误会变成确定的业务参数

语音链路常见为：

~~~text
音频解码 -> 降噪/VAD -> 说话人和时间戳 -> ASR
-> 领域词规范化 -> 意图解析 -> 工具参数或回答
~~~

ASR 不是前端小功能。金额、日期、姓名、地址、药名和账号中的一个音节错误，都可能改变后续动作。Whisper 论文研究了大规模弱监督语音识别，报告使用约 68 万小时的多语言、多任务监督来获得较强的泛化和鲁棒性；这说明规模能改善许多场景，但不意味着每个领域关键字段都无需校验。[Robust Speech Recognition via Large-Scale Weak Supervision](https://arxiv.org/abs/2212.04356)

OpenAI 的语音转写文档说明了文件转写以及流式和专门转写能力的接口入口；接口能力、模型版本和语言支持会变化，工程系统应锁定实际使用的模型与参数，不把文档中的功能描述当成业务准确率保证。[File transcription](https://developers.openai.com/api/docs/guides/speech-to-text)

### 11.8.1 WER 的定义域

设参考词序列长度为 N_word，替换、删除和插入数分别为 S、D、I。在 N_word>0 时，词错误率为：

$$
\operatorname{WER}=
\frac{S+D+I}{N_{\mathrm{word}}}
$$

词准确率可以写成 1-WER，但当插入错误很多时可能小于 0，因此报告时更适合直接报告 WER 或同时显示错误计数。空音频、无语音片段或不需要 ASR 的样本不是 WER 为 0；它们要分别标记为 not_applicable。有语音但没有人工参考转写，则为 unknown。

普通 WER 也会掩盖字段风险。应该额外计算：

$$
A_{\mathrm{asr,field}}=
\frac{\sum_{k=1}^{K}\mathbf{1}[\hat a_k=a_k]}{K},
\qquad K>0
$$

a_k 可以是金额、日期、收款人或药名。转写“转账十五元给李”为“转账五十元给李”时，句子大部分词可能正确，关键金额准确率仍为 0。

### 11.8.2 置信度与确认不是同一个东西

ASR 置信度可以帮助筛选风险片段，但它不是确认。对于会产生副作用的动作，应该把字段确认记录成独立状态：

~~~text
转写：系统听到了什么
解析：系统把它解释成什么字段
复述：系统向用户展示了什么
确认：用户是否明确同意该字段和动作
执行：业务后端是否完成
~~~

如果有 K 个需要确认的关键动作，其中 h_k 表示用户完成了明确确认，则：

$$
C_{\mathrm{confirm}}=
\frac{\sum_{k=1}^{K}\mathbf{1}[h_k=1]}{K},
\qquad K>0
$$

没有需要确认的动作是 not_applicable；策略要求确认但日志缺失是 unknown；有需要确认的动作且用户没有确认是有效的 0。不能因为 ASR 置信度高就跳过确认，也不能把“用户没有反对”当作明确同意。

## 11.9 多模态 RAG：引用必须指向媒体中的位置

多模态 RAG 不只是把图片加一个 caption 再放进向量库。可审计的证据单元通常包括：

~~~text
原始图片/页面/音频/视频片段
OCR 文本及其 bbox
图表结构或表格单元
caption 和视觉 embedding
ASR 文本、说话人和时间戳
文档版本、来源、权限和更新时间
~~~

检索时可以组合关键词、稀疏检索、dense embedding、图像检索和 reranker，但检索命中后仍要把原始位置带入上下文。只保存 caption 会丢失小字、空间关系和表格结构；只保存 OCR 又会丢失图形、颜色和视觉布局。

### 11.9.1 多模态证据单元

一条证据可以抽象成：

$$
e=(\operatorname{source},\operatorname{version},\operatorname{location},
\operatorname{content},\operatorname{acl},\operatorname{time})
$$

其中 location 在图片/文档中是页码和 bbox，在视频中是时间区间，在音频中还可包含说话人。没有 location 的证据仍可能用于粗粒度摘要，但不适合支持精确引用或高风险动作。

多页 PDF 要保存页序和文档层级。视频检索要区分“召回了相关视频”与“召回了包含答案的时间段”。权限要在原始媒体和所有派生结果之间继承；一个被撤销权限的 PDF 页面，不能因为 OCR 文本已经进入向量库就继续被检索出来。

### 11.9.2 证据支持率不等于检索召回率

检索 Recall 只说明标准证据是否进入候选集合；最终回答还可能在 rerank、context 截断、引用定位和生成中失败。至少要保存：

~~~text
candidate：初始召回
reranked：重排结果
context：真正送入模型
claims：回答中的断言
citations：每个断言引用的位置
~~~

一个文档在 candidate 中而没有进入 context，与根本没有召回，是两个不同的修复方向。一个引用指向正确页面但没有支持对应数字，也不能算引用准确。

## 11.10 多模态安全：不可信媒体是数据，不是指令

攻击者可以把文字放入图片、PDF、二维码、字幕、音频或视频画面中。OCR、ASR 和 caption 只负责描述媒体内容，不应该自动提升其中的文字为系统指令。外部网页、用户上传文件和检索结果也可能包含诱导模型越权的内容。

OpenAI Model Spec 的指令层级和不可信内容边界可以作为理解数据与指令分离的参考，但规范本身不能替代工具执行层的权限检查。[Model Spec](https://model-spec.openai.com/2025-02-12.html)

### 11.10.1 四层安全检查

多模态安全至少需要四个位置：

1. 输入层：文件类型、恶意载荷、隐私区域、危险内容和访问权限；
2. 转换层：OCR/ASR/caption 中的注入文本、敏感字段和派生结果权限；
3. 生成层：回答是否泄露隐私、做未经证据支持的敏感推断或提供危险指引；
4. 动作层：工具参数、确认、租户、资源归属和人工审核。

安全分类的结果不应只有 allow/block。更实用的状态包括：

~~~text
allow：可以继续
transform：先打码、降级或去除敏感区域
refuse：拒绝回答或拒绝动作
review：交给人工或更严格的审核路径
unknown：检查缺失，不能假设安全
~~~

如果风险样本数为 N_risk>0，安全拦截率可以定义为：

$$
R_{\mathrm{block}}=
\frac{\sum_{i=1}^{N_{\mathrm{risk}}}
\mathbf{1}[\operatorname{risk}_i=1\land \operatorname{handled}_i=1]}
{N_{\mathrm{risk}}}
$$

这里 handled 不只表示拒绝，也可以是符合策略的脱敏、降级或人工审核。没有风险标签是 unknown；测试集没有风险样本是 not_applicable。把空的安全测试集报告成 1，是最危险的统计幻觉之一。

### 11.10.2 业务动作不能由媒体单独授权

图片中出现一个人的脸，不等于系统获得了识别这个人的授权；录音中出现一个账户，不等于当前用户有权向该账户转账；发票上出现一个姓名，也不等于该姓名可以成为当前工具的收款人。

多模态模型只能提供候选事实，权限服务和业务后端负责决定动作是否允许。高风险动作至少要绑定：

~~~text
当前用户和租户
原始媒体与派生证据的访问权
关键字段的确认记录
动作的幂等键和审计 trace
后端最终状态
~~~

## 11.11 跨模态对齐：不同模态的时空坐标必须能相遇

图片中的文字通过 bbox 对齐到页面；视频中的事件通过时间戳对齐到帧；语音中的词通过音频时间段对齐到说话人。多模态系统一旦丢失这些坐标，模型仍然可以生成文本，却无法可靠地回答“在哪里”“什么时候”“谁说的”和“哪一页”。

### 11.11.1 对齐的三类错误

空间错位：OCR bbox 使用了裁剪图坐标，却被当成原图坐标；缩放和 padding 的偏移没有逆变换；多图输入的第 2 张图被引用成第 1 张。

时间错位：转码改变了帧率；字幕从 00:17 开始而音频从 00:16.8 开始；片段摘要使用片段内相对时间，却在回答中当成全局时间。

语义错位：图例和颜色对应关系丢失；说话人标签在拼接时互换；表格行与列仍然存在，但数值和字段名来自不同页。

每个派生对象都要记录变换矩阵或时间偏移。对一个 bbox 从裁剪图映射回原图，不能靠字符串说明“在左下角”，而应保存可计算的坐标变换。

### 11.11.2 多图和多页输入的顺序

多图问答中的顺序不是展示细节。比较“第一张与第二张发票”的任务，如果系统在切片或批处理时重排图片，模型即使分别读对每张图，也会给出错误比较。

上下文中的每个媒体对象应带：

~~~text
document_id、page_index、image_index
original_width、original_height
crop_origin、scale、padding
~~~

多页文档还要保留文档级标题、章节路径和跨页表头。引用应优先使用稳定的 document_id + page_index + bbox，不要只引用最终拼接文本中的字符偏移。

## 11.12 评估要覆盖模态边界，而不是只看漂亮 demo

多模态评估应从任务和错误来源两个方向切片。

图像切片可以包括长截图、小字、表格、图表、低清、暗光、旋转、遮挡、压缩和多图比较。语音切片可以包括噪声、口音、语速、专有名词、数字、多人和中英文混说。视频切片可以包括短事件、长视频、静态镜头中的动作、字幕延迟、音画不同步和多事件顺序。安全切片还要包含图片文字注入、二维码、隐私区域和不应执行的敏感推断。

### 11.12.1 证据召回率

对第 i 个样本，标准证据集合为 E_i，系统送入上下文的证据集合为 E_hat_i。在 |E_i|>0 且标注完整时：

$$
R_{\mathrm{evidence},i}=
\frac{|\hat E_i\cap E_i|}{|E_i|}
$$

它可以按模态和粒度计算：字符、关键字段、区域、页面、时间片段和表格单元分别统计。若标准证据缺失，报告 unknown；若任务明确没有相关证据，报告 not_applicable。

### 11.12.2 OCR 和 ASR 指标

字符准确率、关键字段准确率和 WER 已在前面给出。实际报表至少要同时展示：

~~~text
普通字符/词错误
关键字段错误
低置信样本比例
重新识别后的变化
下游回答或动作错误
~~~

一个 OCR 系统可以普通字符准确率很高，却在金额字段上持续失败；一个 ASR 系统可以 WER 很低，却把少量专有名词全部识别错。平均数应该帮助定位，而不是替业务风险打分。

### 11.12.3 Grounding 与 claim 评估

视觉定位使用 IoU 或点/区域命中率；视频定位使用时间交并比和事件召回；文档引用使用页码、bbox 和文本 span 的准确性。回答层再做 claim 支持、反驳、无证据和未知状态标注。

评估员不能只问“答案看起来对不对”。还要问：

1. 这个答案需要哪些证据？
2. 证据是否在原始媒体中存在？
3. 证据是否被系统实际送入模型？
4. 引用是否指向正确的位置？
5. 如果证据不存在，模型是否正确拒答或追问？

### 11.12.4 成本和延迟

高分辨率图片、更多视频帧、多轮 OCR、二次 ASR 和局部重试都会改变成本。可以定义预算超限率：

$$
R_{\mathrm{over}}=
\frac{\sum_{i=1}^{N}
\mathbf{1}[l_i>L_i\lor c_i>C_i\lor u_i>U_i]}{N},
\qquad N>0
$$

l_i 是端到端延迟，c_i 是成本，u_i 是帧数、音频秒数或等价 token，L_i、C_i、U_i 是按任务设定的上限。不同媒体不能简单把帧数和 token 相加；应记录各自原始量和系统换算。

没有预算记录是 unknown，没有这类媒体任务是 not_applicable。超时样本不能从平均延迟中删除，否则系统会在报表中看起来更快。

## 11.13 一次事故的定位顺序

遇到“图片问答错了”“视频漏报了”或“语音动作执行错了”，按以下顺序冻结现场：

~~~text
原始媒体 hash 和访问权限
模型实际输入和预处理快照
OCR/ASR/帧/区域及其版本
上下文中真正出现的证据
模型 claims、引用和置信度
安全、确认、权限和工具调用记录
业务后端最终状态
延迟、成本和重试
~~~

然后从最靠近输入的位置开始找第一处分歧：

1. 原始媒体是否包含任务所需内容；
2. 预处理是否保留了内容；
3. 中间感知是否识别正确；
4. 坐标、页码和时间戳是否一致；
5. 正确证据是否进入上下文；
6. claim 是否被证据支持；
7. 安全、权限和确认是否生效；
8. 外部动作是否真的完成。

如果第 2 步已经失败，就不应先调 prompt；如果第 6 步失败，就不应把问题归因给 OCR；如果文本答案正确但外部动作错误，就要检查字段规范化、权限和工具状态。

### 11.13.1 事故归因示例

| 现象 | 第一处分歧 | 主要修复 |
| --- | --- | --- |
| 长截图答错底部错误码 | 预处理后的切片没有覆盖底部 | 分块、全局坐标、长图回归集 |
| 发票金额错一位 | OCR 关键字段错误 | 局部重识别、格式校验、确认 |
| 图表增长率错误 | 坐标轴单位或分母未解析 | 结构化表格和确定性计算 |
| 视频说“无异常” | 关键事件未被采样 | 事件感知采样、时间戳、片段回放 |
| 语音转账金额错误 | ASR 关键字段错误且无确认 | 复述确认、领域词和动作策略 |
| 图片文字诱导工具调用 | 派生文本未被视为不可信数据 | 数据/指令隔离、权限和审计 |
| 引用页码正确但数字不支持 | claim 与证据 span 不匹配 | claim 级引用校验 |

这张表的作用不是给事故贴一个大类，而是帮助团队决定第一笔工程投入应该放在哪里。

## 11.14 可运行的多模态事故审计示例

下面的示例使用 Python 标准库，模拟八个样本：正常商品图、长截图裁剪、发票 OCR 金额错误、图表字段遗漏、视频事件漏采、噪声音频金额错误、缺少安全检查的媒体输入，以及一个没有需要定位事件的安静视频。示例数据是教学构造，不是任何模型或 API 的 benchmark。

代码有几个刻意的约束：

1. 空音频和没有事件的视频返回 not_applicable；
2. 缺少安全检查记录返回 unknown，不会自动当成安全；
3. 有标准框但没有预测框时，IoU 是有效的 0；
4. 零分母只有在分子也为 0 时返回 not_applicable，否则直接报错；
5. NaN、负数和用整数冒充布尔值的输入在入口拒绝。

~~~python
from dataclasses import dataclass
from math import ceil, isfinite
from typing import Optional


@dataclass(frozen=True)
class Metric:
    value: Optional[float]
    status: str


def finite_number(value, name):
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        raise ValueError(f"{name} must be a finite number")
    if not isfinite(float(value)):
        raise ValueError(f"{name} must be finite")
    return float(value)


def safe_mean(values, name="mean"):
    if not values:
        return Metric(None, "not_applicable")
    checked = [finite_number(value, name) for value in values]
    return Metric(sum(checked) / len(checked), "valid")


def safe_ratio(numerator, denominator, name="ratio"):
    numerator = finite_number(numerator, f"{name}.numerator")
    denominator = finite_number(denominator, f"{name}.denominator")
    if numerator < 0 or denominator < 0:
        raise ValueError(f"{name} cannot contain negative values")
    if denominator == 0:
        if numerator == 0:
            return Metric(None, "not_applicable")
        raise ValueError(f"{name} has a positive numerator and zero denominator")
    return Metric(numerator / denominator, "valid")


def percentile(values, pct, name="percentile"):
    pct = finite_number(pct, f"{name}.pct")
    if pct < 0 or pct > 100:
        raise ValueError("percentile must be between 0 and 100")
    if not values:
        return Metric(None, "not_applicable")
    ordered = sorted(finite_number(value, name) for value in values)
    rank = max(1, ceil(len(ordered) * pct / 100))
    return Metric(ordered[rank - 1], "valid")


def aggregate(metrics, name):
    unknown = sum(metric.status == "unknown" for metric in metrics)
    values = [metric.value for metric in metrics if metric.status == "valid"]
    if not values:
        return Metric(None, "unknown" if unknown else "not_applicable")
    return Metric(sum(values) / len(values), "valid")


def render(metric):
    if metric.status != "valid":
        return metric.status
    return round(metric.value, 3)


def check_bool(value, name):
    if type(value) is not bool:
        raise ValueError(f"{name} must be a real bool")


def check_non_negative_int(value, name):
    if isinstance(value, bool) or not isinstance(value, int) or value < 0:
        raise ValueError(f"{name} must be a non-negative integer")


def check_box(box, name):
    if box is None:
        return
    if not isinstance(box, tuple) or len(box) != 4:
        raise ValueError(f"{name} must be a 4-tuple or None")
    x1, y1, x2, y2 = box
    for value in box:
        finite_number(value, name)
    if x2 <= x1 or y2 <= y1:
        raise ValueError(f"{name} must have positive area")


def validate_case(case):
    if not isinstance(case["id"], str) or not case["id"]:
        raise ValueError("case id must be non-empty")
    for key in ("source_available", "preprocess_ok"):
        check_bool(case[key], f"{case['id']}.{key}")

    ocr = case["ocr"]
    for key in ("reference_chars", "substitutions", "deletions",
                "insertions", "critical_total", "critical_ok"):
        check_non_negative_int(ocr[key], f"{case['id']}.ocr.{key}")
    if ocr["critical_ok"] > ocr["critical_total"]:
        raise ValueError("OCR critical successes cannot exceed total")

    asr = case["asr"]
    for key in ("reference_words", "substitutions", "deletions",
                "insertions", "critical_total", "critical_ok"):
        check_non_negative_int(asr[key], f"{case['id']}.asr.{key}")
    if asr["critical_ok"] > asr["critical_total"]:
        raise ValueError("ASR critical successes cannot exceed total")

    events = case["events"]
    check_bool(events["label_available"], f"{case['id']}.events.label_available")
    if not events["label_available"]:
        raise ValueError("this demo requires an explicit event-label status")
    if not events["covered"].issubset(events["expected"]):
        raise ValueError("covered events must come from expected events")

    grounding = case["grounding"]
    check_bool(grounding["required"], f"{case['id']}.grounding.required")
    check_box(grounding["expected_box"], f"{case['id']}.grounding.expected_box")
    check_box(grounding["predicted_box"], f"{case['id']}.grounding.predicted_box")

    for claim in case["claims"]:
        if claim["support"] not in {"supported", "unsupported", "contradicted", "unknown"}:
            raise ValueError("invalid claim support status")
        if claim["hallucination"] is not None:
            check_bool(claim["hallucination"], "claim.hallucination")

    safety = case["safety"]
    if safety["risk"] is not None:
        check_bool(safety["risk"], f"{case['id']}.safety.risk")
    check_bool(safety["checked"], f"{case['id']}.safety.checked")
    check_bool(safety["blocked"], f"{case['id']}.safety.blocked")

    confirmation = case["confirmation"]
    check_bool(confirmation["required"], f"{case['id']}.confirmation.required")
    check_bool(confirmation["confirmed"], f"{case['id']}.confirmation.confirmed")

    for key in ("latency_ms", "cost", "token_equiv"):
        if finite_number(case[key], f"{case['id']}.{key}") < 0:
            raise ValueError(f"{key} cannot be negative")
    for key in ("latency_ms", "cost", "token_equiv"):
        if finite_number(case["budget"][key], f"{case['id']}.budget.{key}") <= 0:
            raise ValueError(f"{key} budget must be positive")

def evidence_recall(case):
    expected = case["expected_evidence"]
    if expected is None:
        return Metric(None, "unknown")
    if not expected:
        return Metric(None, "not_applicable")
    return Metric(len(case["observed_evidence"] & expected) / len(expected), "valid")


def ocr_char_accuracy(case):
    ocr = case["ocr"]
    errors = ocr["substitutions"] + ocr["deletions"] + ocr["insertions"]
    if ocr["reference_chars"] == 0:
        return Metric(None, "not_applicable")
    return Metric(1 - errors / ocr["reference_chars"], "valid")


def ocr_critical_accuracy(case):
    ocr = case["ocr"]
    return safe_ratio(ocr["critical_ok"], ocr["critical_total"], "ocr_critical")


def asr_word_accuracy(case):
    asr = case["asr"]
    errors = asr["substitutions"] + asr["deletions"] + asr["insertions"]
    if asr["reference_words"] == 0:
        return Metric(None, "not_applicable")
    return Metric(1 - errors / asr["reference_words"], "valid")


def asr_critical_accuracy(case):
    asr = case["asr"]
    return safe_ratio(asr["critical_ok"], asr["critical_total"], "asr_critical")


def temporal_recall(case):
    events = case["events"]
    if not events["label_available"]:
        return Metric(None, "unknown")
    if not events["expected"]:
        return Metric(None, "not_applicable")
    return Metric(
        len(events["covered"]) / len(events["expected"]),
        "valid",
    )


def box_area(box):
    if box is None:
        return 0.0
    x1, y1, x2, y2 = box
    return (x2 - x1) * (y2 - y1)


def grounding_iou(case):
    grounding = case["grounding"]
    if not grounding["required"]:
        return Metric(None, "not_applicable")
    expected = grounding["expected_box"]
    if expected is None:
        return Metric(None, "unknown")
    predicted = grounding["predicted_box"]
    if predicted is None:
        return Metric(0.0, "valid")
    ex1, ey1, ex2, ey2 = expected
    px1, py1, px2, py2 = predicted
    ix1, iy1 = max(ex1, px1), max(ey1, py1)
    ix2, iy2 = min(ex2, px2), min(ey2, py2)
    intersection = max(0.0, ix2 - ix1) * max(0.0, iy2 - iy1)
    union = box_area(expected) + box_area(predicted) - intersection
    if union <= 0:
        raise ValueError("grounding boxes must have positive union")
    return Metric(intersection / union, "valid")


def claim_metrics(case):
    claims = case["claims"]
    if not claims:
        return Metric(None, "not_applicable"), Metric(None, "not_applicable")
    labeled = [claim for claim in claims if claim["support"] != "unknown"]
    if not labeled:
        return Metric(None, "unknown"), Metric(None, "unknown")
    support = sum(claim["support"] == "supported" for claim in labeled)
    hallucinated = sum(
        claim["hallucination"] is True
        for claim in labeled
        if claim["hallucination"] is not None
    )
    hallucination_labels = sum(
        claim["hallucination"] is not None for claim in labeled
    )
    return (
        Metric(support / len(labeled), "valid"),
        safe_ratio(hallucinated, hallucination_labels, "hallucination"),
    )


def safety_block(case):
    safety = case["safety"]
    if safety["risk"] is None:
        return Metric(None, "unknown")
    if not safety["risk"]:
        return Metric(None, "not_applicable")
    if not safety["checked"]:
        return Metric(None, "unknown")
    return Metric(float(safety["blocked"]), "valid")


def confirmation_coverage(case):
    confirmation = case["confirmation"]
    if not confirmation["required"]:
        return Metric(None, "not_applicable")
    return Metric(float(confirmation["confirmed"]), "valid")


def budget_overrun(case):
    exceeded = (
        case["latency_ms"] > case["budget"]["latency_ms"]
        or case["cost"] > case["budget"]["cost"]
        or case["token_equiv"] > case["budget"]["token_equiv"]
    )
    return Metric(float(exceeded), "valid")
~~~
