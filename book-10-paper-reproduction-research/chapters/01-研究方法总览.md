# 第一章：研究方法总览

第十册讨论的不是某一篇论文，而是研究能力本身。研究能力不等于“看过很多论文”，也不等于“能复述摘要”。真正重要的是：能不能看懂一篇论文解决了什么问题，为什么这个问题重要，作者的方法为什么可能有效，实验是否支持结论，局限在哪里，复现时应该控制什么变量，以及如何把论文启发转化成自己的实验和项目改进。

只说“这篇论文提出了一个新方法，在某个 benchmark 上提升了几个点”，仍然停留在论文阅读的表层。更有价值的研究说明要继续追问：这个提升是否可信？比较是否公平？差异来自方法本身，还是来自数据、规模、训练预算或调参？方法在哪些场景失效？要复现它，最小的可观察实验是什么？当结果无法复现时，哪些原因已经排除，哪些原因仍然未知？

本章是全书总览，先建立一套研究判断框架。后续章节会分别把论文阅读、实验复现、消融、负结果和具体技术路线展开；本章的作用，是给这些工作提供共同的语言和判断尺度。

重点：研究问题、假设、实验、证据、复现、负结果和技术判断。

## 1. 研究能力到底是什么？

研究能力可以拆成六个层次：

1. 问题识别：能看出论文真正要解决什么问题。
2. 假设建模：能理解作者的核心假设是什么。
3. 方法分析：能判断方法为什么可能有效。
4. 证据评估：能判断实验是否支撑结论。
5. 复现诊断：能把论文方法变成可运行实验，并定位差异。
6. 延伸创造：能提出合理改进、替代实验和后续问题。

初级读者停留在“论文讲了什么”。中级读者能说“方法怎么做”。高级读者要能回答“为什么这样做、证据够不够、边界在哪里、如果我是作者下一步会做什么”。

这六个层次不是互相独立的标签，而是一条逐步收紧的推理链。问题识别决定实验要测什么；假设建模决定应该改变哪个变量；方法分析决定哪些实现细节不能省略；证据评估决定结果能否支持结论；复现诊断决定差异来自哪里；延伸创造则建立在前五步已经足够可靠的基础上。如果问题本身没有说清楚，后面再复杂的 ablation 也可能只是在优化错误目标。

研究能力可以通过一篇论文的“证据卡片”练习。卡片不抄摘要，而是写下：目标变量、主要干预、比较对象、评估指标、关键假设、替代解释、最小实验和已知限制。例如阅读一个长上下文方法时，目标变量可以是长文档检索准确率，干预是位置编码或训练课程，比较对象是同参数量的标准模型，替代解释则包括更多训练 token、不同 tokenizer 或评测污染。卡片越具体，越容易在复现时转成代码和日志。

初学者可以先用自然语言写卡片，再逐渐给变量、单位和分母。专家还要补充实验的可识别性：当前设计能区分哪些假设，不能区分哪些假设，下一次实验需要增加什么控制。这样“会读论文”才会转化为“会提出下一步实验”。

## 2. 为什么研究工作需要论文讨论？

大模型领域变化很快。很多技术从论文发布到工程验证只有几个月，团队需要在信息不完整的情况下判断哪些路线值得复现、哪些结论还不能外推。论文讨论的价值不在于考查记忆，而在于让研究者共享问题定义、证据等级和下一步实验。

一场有质量的论文讨论通常要处理几类问题：

1. 抽象能力：能否从细节中抽出问题和机制。
2. 批判能力：能否判断实验是否可信。
3. 工程感：能否看出论文落地成本和系统瓶颈。
4. 实验能力：能否设计 ablation 和 controlled experiment。
5. 表达能力：能否用清晰结构讲复杂工作。
6. 后续问题：能否提出有意义且可验证的下一步。

所以，阅读和讨论论文不是背结论，而是训练一种判断方式。

论文讨论之所以适合承载这件事，是因为它同时包含技术、证据和表达三个层面。只会背算法的人可能说出正确公式，却无法解释 baseline 为什么公平；只会做工程的人可能知道延迟和显存，却无法判断提升是否来自额外数据；只会批评的人又可能忽略方法在目标场景中的实际价值。成熟的研究说明要在“作者声称了什么”和“当前证据允许我声称什么”之间保持距离。

这种判断也有明确的工程收益。读论文时提前发现数据泄漏，可以避免把污染的 benchmark 分数带进产品计划；发现方法依赖昂贵的 teacher 或重新训练，可以尽早选择 RAG、蒸馏或更简单的 baseline；发现结论只在单一切片成立，可以在资源有限时把实验范围缩小，而不是盲目搭建完整系统。换句话说，论文阅读不是研发流程之外的文献工作，而是资源分配、风险控制和实验设计的一部分。

## 3. 论文阅读的第一性问题

读任何论文，先问六个问题：

1. Problem：它解决什么问题？
2. Motivation：为什么这个问题重要？
3. Prior work：之前方法怎么做，哪里不够？
4. Hypothesis：作者相信什么假设？
5. Method：方法如何实现这个假设？
6. Evidence：实验是否证明假设，而不只是证明分数上涨？

如果这六个问题答不清，说明你还没有真正读懂论文。

这六个问题还可以变成一张论文摘要表：

~~~text
problem -> motivation -> prior gap -> hypothesis -> method -> evidence
~~~

表中的箭头不是论文目录，而是论证关系。方法必须回应假设，实验必须能区分假设和替代解释，结论必须不超过证据覆盖的范围。若作者从“某数据集分数上升”直接跳到“方法普遍有效”，读者就应该把泛化性作为未完成的问题，而不是自动接受。

例如，LoRA 不只是“低秩矩阵微调”。原论文把全参数微调成本高作为动机，并在 RoBERTa、DeBERTa、GPT-2 和 GPT-3 的指定任务中报告低秩适配达到相当或更好的任务表现；这支持的是论文所测模型、任务和配置下的结论，不足以推出任意模型与任务都能无损替代全量微调。[LoRA 原论文](https://arxiv.org/abs/2106.09685v2)

DPO 也不应被简化成“不用 PPO”。原论文在特定偏好建模假设下，将目标写成直接优化的分类式损失，并在情感控制、摘要和单轮对话等设置中报告与 PPO-based RLHF 的比较。读者仍须检查偏好数据、reference policy、截断和超参数等条件，不能把这些实验结果当成跨任务的普遍优劣排序。[DPO 原论文](https://arxiv.org/abs/2305.18290v3)

## 4. 研究问题：论文真正问了什么？

一篇论文的标题和摘要通常会给出表面问题，但真正的 research question 往往更具体。

例如：

1. “如何提升长上下文能力？”太泛。
2. “如何在不线性增加显存和计算的情况下扩展 attention context？”更具体。
3. “如何通过稀疏、压缩、重用或外部检索降低长上下文训练和推理成本？”更接近研究问题。

研究记录中描述问题时，要避免只说大方向。应该把问题说成一个明确冲突：

1. 效果 vs 成本。
2. 规模 vs 稳定性。
3. 泛化 vs 过拟合。
4. 安全 vs 帮助性。
5. 长上下文 vs 计算复杂度。
6. 多模态对齐 vs 数据噪声。
7. 推理能力 vs 训练数据污染。

好的研究问题通常来自一个真实 trade-off。

研究问题还应具有可证伪性。可以把它写成“在固定条件 `C` 下，采用干预 `T` 是否使结果 `Y` 相比 baseline `B` 改善，并且代价不超过约束 `K`”。如果问题只能写成“这个方法是不是更先进”，就没有明确的观测变量；如果只写“分数能否提高”，又可能忽略成本、稳定性和风险。

例如，长上下文研究可以具体化为：在相同模型规模、训练 token 和评测协议下，位置方法 `T` 是否提高 [RULER](https://arxiv.org/abs/2404.06654v3) 某类长距离任务的准确率，同时不让 KV Cache 显存和 TPOT 超过预算。RULER 在 needle 检索之外加入多 needle、多跳追踪和聚合任务；具体任务结果仍只支持对应评测设置。这个表述自然产生实验字段，也提醒研究者不能只报告一个平均分。

### 4.1 从宏大主题到最小问题

把问题缩小不是降低研究价值，而是提高可识别性。先选择一个主要任务、一个主要指标和一个明确 baseline，再规定数据版本、训练预算和评估切片；如果最小实验无法观察到机制信号，就没有理由直接扩大到更多模型和数据。最小问题得到支持后，再通过多尺度、多任务和真实流量检验外推。

## 5. 研究假设：作者相信什么？

论文方法背后一定有假设。能否抓住假设，是判断论文深度的关键。

常见假设包括：

1. 模型参数更新具有低秩结构。
2. 更高质量数据比更多低质量数据更有效。
3. 人类偏好可以通过 pairwise comparison 学到。
4. 检索能弥补参数记忆的时效性不足。
5. 稀疏激活能在不同比例增加计算的情况下增加参数容量。
6. 长上下文能力可以通过位置外推或数据课程迁移。
7. 多模态表示可以通过对比学习对齐。

读论文时要问：如果这个假设不成立，方法会怎样？

好的假设要写出适用条件和可观察预测。例如，若低秩更新是当前任务的限制，固定底座、数据和训练预算后，增加 rank 应能缓解欠拟合；如果没有出现这一趋势，就要检查目标模块或假设本身。对 RAG，可先固定生成器，观察证据召回变化是否先于 claim 支持变化；若找回的证据变多而答案支持不变，问题可能位于上下文截断、模型使用证据或生成流程。若假设不能产生这类可观察预测，实验就很难区分“机制有效”和“只是在一个设置上碰巧得分高”。

还要区分机制假设和部署假设。一个方法可能在离线任务上有效，但部署时受 kernel、batch、缓存、网络或权限约束而不成立；一个数据方法可能提高质量，却因授权和删除要求无法使用。研究判断既要问模型为什么会变好，也要问系统是否允许把这个变化交付出去。

## 6. 方法：机制、实现和代价

分析方法时，至少分三层：机制、实现、代价。

机制层问：它为什么可能有效？

实现层问：具体怎么做？训练目标、数据格式、模型改动、推理流程是什么？

代价层问：它引入了什么成本？显存、计算、延迟、数据、标注、系统复杂度、稳定性风险是什么？

很多论文在机制上漂亮，但工程代价很高。比如某些长上下文方法理论上能扩展 context，但训练成本、实现复杂度、kernel 支持和质量回归都可能成为落地障碍。

研究报告中如果能主动补上代价层，结论就不会停留在方法公式和离线分数上，而能回答它是否值得进入真实系统。

可以把方法分析写成三列账本：

| 层次 | 要回答的问题 | 常见证据 |
| --- | --- | --- |
| 机制 | 为什么可能改善目标？ | 公式、归纳偏置、信息路径、理论或消融 |
| 实现 | 需要哪些具体条件？ | 数据格式、代码、超参、硬件、运行时日志 |
| 代价 | 为收益付出什么？ | token、显存、延迟、标注、维护和失败率 |

例如一个 reranker 可能通过重新排序证据改善 claim grounding，这是机制；候选数、模型版本、上下文预算和 batch 是实现；额外的排序延迟、GPU 和缓存压力是代价。三列没有同时填写时，所谓“有效”通常只是局部实验结论。

在系统研究中，代价还要带单位和分母。总延迟、每请求延迟、每千 token 延迟和单位成功任务成本不是同一个指标；总训练 token 也不能替代每个数据池的有效 epoch。把量纲写清楚，能避免把一个看似很大的收益建立在不公平的资源口径上。

## 7. 实验：证据链是否完整？

论文实验不是分数表，而是证据链。

一个完整证据链通常包括：

1. Main result：主要指标是否提升。
2. Baseline：比较对象是否公平。
3. Ablation：关键组件是否真的有贡献。
4. Scaling：不同模型大小、数据量、任务上是否稳定。
5. Robustness：换数据、换 seed、换 setting 是否有效。
6. Efficiency：成本、显存、吞吐、延迟是否可接受。
7. Error analysis：失败案例说明什么。
8. Limitation：作者是否诚实说明边界。

如果一篇论文只有 main result，没有 ablation，你要谨慎。如果 baseline 很弱，提升不一定可信。如果只在一个数据集有效，泛化要打问号。如果没有成本分析，工程价值不明确。

可以把证据分成“结果、归因、外推、交付”四层。结果层回答分数是否变化；归因层回答变化是否来自论文声称的组件；外推层回答换模型、数据、seed 和任务后是否仍成立；交付层回答收益是否足以抵消成本、风险和维护。很多论文只把结果层写得很完整，读者却需要主动检查后三层。

为了提醒读者分开检查结论的不同部分，可以用下面这个教学向量作记录框架；它不是统一的学术标准，也不是可以直接加权求分的量表：

~~~math
E=(E_{\mathrm{result}},E_{\mathrm{attribution}},E_{\mathrm{generalization}},E_{\mathrm{cost}},E_{\mathrm{failure}})
~~~

每个分量不是 0/1 的总开关，而是带样本范围、实验设置和不确定性的记录。例如目标方法在主 benchmark 上有提升，结果项可以较强；但只有一个 seed、没有强 baseline 时，归因和外推仍然有限。读论文时保留这种分层，能避免“主结果显著”被误读成“机制已经被证明”。

### 7.1 从分数差到可信结论

若 baseline 在 `n` 个样本上的均值为 `m_b`，方法均值为 `m_t`，最基本的效应量是：

~~~math
\Delta=m_t-m_b
~~~

例如把每题的 claim 支持记作 0 或 1，假设 200 题上的均值分别为 $m_b=142/200=0.71$ 和 $m_t=156/200=0.78$，则 $\Delta=0.78-0.71=0.07$，表示支持率提高 7 个百分点。这个差值是点估计；它本身不提供抽样不确定性，也没有说明多少题由支持变成不支持，需结合配对记录和评估设计解释。

但 `Delta` 还不够。需要知道样本是否独立、结果是否跨 seed 稳定、差异是否超过测量噪声，以及提升集中在哪些切片。小样本下一个百分点可能只是抽样波动，大规模测试下很小的差异又可能统计显著但没有工程意义。

因此报告中应同时保留均值、离散程度、置信区间或重复运行范围、切片结果和成本变化。若任务是生成式开放评估，还要说明人工/模型评审协议、打分者一致性和可能的 judge 偏差。

## 8. Baseline 公平性

评价论文时，baseline 公平性是最重要的问题之一。

常见不公平包括：

1. 新方法调参更多，baseline 调参不足。
2. 新方法用更多数据，baseline 没用。
3. 新方法模型更大，baseline 更小。
4. 新方法训练更久，baseline 训练不足。
5. 新方法用了额外 teacher 或合成数据。
6. baseline 是过时方法，不是当前强基线。
7. 评估集和训练数据存在污染。

在研究报告中，可以把这种审查写成一段带条件的判断：

“这项工作的主结果值得进一步检查。需要先对齐 baseline 的 compute、数据、模型规模和调参预算；在这些条件未对齐前，观测到的提升可能来自资源差异，而不能直接归因于方法本身。”

这句话还可以落成一份资源对齐表。列出训练 token、参数量、激活参数、batch、训练步数、硬件时间、调参次数、外部数据和评测脚本；对每个差异标记为“方法必需”“实验选择”或“未说明”。如果新方法必须依赖更大模型才能工作，就应该把“方法收益”和“规模收益”分开报告，而不是把二者合并。

baseline 也不能只看名称。一个旧方法若使用过时的 tokenizer、较差的超参或不同的数据处理方式，名义上是 baseline，实际上并没有形成公平对照。研究者可以加入强 baseline、简单替代方案和去掉复杂组件的版本，以判断收益是否值得额外复杂度。

## 9. Ablation：证明组件真的有用

Ablation 的目标是拆掉某个组件，看效果是否下降，从而证明它有贡献。

好的 ablation 应该回答：

1. 哪个组件最重要？
2. 每个组件是否独立贡献？
3. 有没有组件其实没用？
4. 组件之间有没有交互？
5. 方法对超参是否敏感？
6. 是否存在更简单替代方案？

很多论文会把多个 trick 组合起来。如果没有 ablation，你不知道提升来自核心思想，还是来自数据、调参、训练技巧或实现细节。

单因素 ablation 适合快速定位，但当组件之间存在交互时，逐个删除可能产生误导。假设组件 A 和 B 单独使用都无效，组合后才有效，简单的 `A off` 或 `B off` 只能告诉你组合依赖，却不能解释交互方向。资源允许时，可以做一个小型二因素实验，比较 baseline、A、B 和 A+B 四组，并记录交互差异。令 $Y_0$、$Y_A$、$Y_B$、$Y_{A+B}$ 分别表示四组在同一评估条件下的结果；以下按“数值越高越好”的指标说明：

~~~math
I_{A,B}=Y_{A+B}-Y_A-Y_B+Y_0
~~~

例如四组准确率假设分别为 $Y_0=70$、$Y_A=72$、$Y_B=71$、$Y_{A+B}=78$（单位均为百分比），代入得到 $I_{A,B}=78-72-71+70=5$ 个百分点。A、B 单独比 baseline 高 2 和 1 个百分点，若按简单相加预期组合为 73；实际假设值 78 比该预期高 5 个百分点。这个构造例只说明交互量如何计算；真实实验还要让四组使用可比数据、预算和评估条件，并通过重复运行判断交互是否稳定。

`I_{A,B}` 只是一个描述交互的教学量，仍需固定训练预算和重复运行。若它接近零，组件可能近似可加；若明显偏离零，就不能用单组件得分推断组合行为。

超参敏感性也属于 ablation。只展示作者最好的 rank、temperature 或阈值，会让读者不知道方法是否需要精细调参。好的报告至少给出合理范围、选择规则和失败点，并说明 baseline 是否获得同等调参预算。

## 10. 复现：不是跑通代码这么简单

为安排工作，本书把复现目标分成三个操作层次；这是本书的工作分类，不是学界统一的术语体系：

1. **代码与流程检查**：按作者给出的入口运行代码，确认输入、依赖、数据流和产物。它只能说明这条运行路径可执行，不能证明论文数字或主张成立。
2. **结果再现**：在尽量对齐的代码、数据、模型和评估条件下，检查能否得到与论文相同或足以支持同一分析结论的结果。
3. **主张边界检验**：通过受控实验检查论文的核心主张在原设置或明确的新设置中是否仍得到支持，并报告外推范围。

研究文献对 repeatability、reproducibility、replicability 等词的使用并不一致；有综述对 101 篇论文归纳出八类科学严谨性议题，说明“复现”也可能指向模型选择、数据质量、可维护性等更广的问题。因此，先说明本次复现究竟要验证什么，比只给任务贴一个术语更重要。[术语综述](https://arxiv.org/abs/2412.03854)

复现要记录：

1. 数据版本。
2. 预处理方式。
3. 模型初始化。
4. tokenizer。
5. 超参数。
6. batch size 和梯度累积。
7. 学习率 schedule。
8. 训练步数。
9. 随机种子。
10. 硬件和框架版本。
11. 评估脚本版本。

一次运行失败本身不是负结果，也不能直接说明论文错了。先定位数据、实现、超参、评估、随机性、环境和未公开实现细节；只有实验问题和控制条件清楚、结果可以解释时，才能把观察纳入结论证据。

复现过程最好有一份差异账本，按“已匹配、已发现差异、尚未确认”记录数据 hash、tokenizer、模型初始化、训练步数、评估脚本和环境。先做 smoke test 确认代码路径和张量 shape，再做小数据过拟合检查损失和梯度，再做短训练趋势，最后才跑完整规模。这样可以把几天的全量计算拆成多个便宜的诊断阶段。

还要区分再现论文设定和重建论文结论。作者代码能运行，说明接口和环境基本可用；指标接近，说明结果在该设置下可再现；如果换数据、模型或规模仍观察到同方向变化，才对 claim 的稳健性增加证据。任何一层失败，都应报告具体层次和已排除的原因。

复现还有一个时间维度。依赖库、GPU kernel、数据下载地址和第三方模型可能变化，未来运行未必能得到完全相同的字节结果。因此应保存 commit、容器/依赖、数据 manifest、随机种子、硬件摘要和评估输出，必要时保留关键中间产物，而不是只保存最终分数。以 NeurIPS 当前公开的 checklist 为例，论文要说明主张范围、局限、实验细节和合理的复现路径；代码与数据开放受到鼓励，但代码并非对所有论文一律强制的唯一复现方式。具体提交要求应以目标会议当年的规则为准。[NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)；[Code and Data Submission Guidelines](https://neurips.cc/public/guides/CodeSubmissionPolicy)

一项 AAAI 2025 复现研究提供了一个有边界的例子：作者从 30 篇高引用 AI 研究中排除 8 篇，实际尝试 22 篇，其中 6 篇完全复现、5 篇部分复现；在同时开放代码和数据的 7 篇中，6 篇至少部分复现，而仅开放数据的 15 篇中有 5 篇至少部分复现。[研究全文](https://doi.org/10.1609/aaai.v39i25.34818) 这些比例只描述该研究的样本与判定规则。样本小、文章选择偏向高引用研究，每篇最多投入 40 小时，而且只有 3/22 篇完成了论文中的全部实验，因此不能把 `11/22` 当成当前 AI 论文的普遍复现率，也不能据此断言开放代码单独造成了成功。它更适合作为检查“数据、代码和实验说明是否同时可用”的案例。

## 11. 负结果：研究能力的重要部分

控制清楚、结果可解释的负结果可以成为证据；一次失败运行本身不是证据。

如果你尝试复现某个方法，发现它在你的任务上无效，这可能说明：

1. 方法依赖特定数据分布。
2. 超参敏感。
3. baseline 已经很强。
4. 论文评估场景有限。
5. 工程实现差异影响结果。
6. 你的任务有不同瓶颈。

好的负结果报告要说明：你试了什么，控制了什么变量，结果如何，排除了哪些原因，还剩哪些不确定性。

在研究协作中，一个讲清楚边界的负结果，往往比一个没有控制变量的成功结果更有用。

负结果首先要避免过度归因。“没有提升”可能表示方法无效，也可能表示 effect 小于噪声、实现没有覆盖关键条件、任务瓶颈不在该方法、baseline 已经饱和或评估不敏感。报告应明确观察范围，例如“在两个数据切片、三个 seed 和固定 50k steps 下未观察到超过区间的收益”，而不是写成“该方法无效”。

负结果也可以改变资源决策。若方法在目标任务上收益小、成本高，就应停止扩展；若只在长上下文切片有效，可以缩小到该路径；若失败原因是数据或实现缺口，则下一步不是否定方法，而是补控制实验。研究记录中保留这些结果，能防止团队重复尝试同一个已知失败配置。

## 12. 技术判断：论文值不值得做？

不是每篇热门论文都值得复现。判断是否值得做，可以看：

1. 是否解决你的真实问题。
2. 是否和现有系统兼容。
3. 收益是否足够大。
4. 成本是否可接受。
5. 风险是否可控。
6. 是否有清晰 ablation 路径。
7. 是否能快速做最小验证。
8. 是否有替代方法更简单。

例如，如果一个长上下文方法需要重训底座模型，而你的业务只需要几十篇文档问答，RAG 或 chunking 可能比重训更现实。如果一个 MoE 方法吞吐高但部署复杂，而团队没有 serving 基础设施，短期未必适合。

技术判断可以写成一个约束问题：在目标收益达到最低要求、风险不超过上限的前提下，选择总成本和交付时间更低的方案。成本不仅包括训练 GPU，还包括数据准备、标注、评估、服务、监控、回滚和团队维护。论文方法在实验室中排名靠前，并不自动意味着它是当前项目的最优决策。

一个实用的筛选表可以记录：目标匹配、证据强度、最小验证成本、上线额外依赖、失败后回滚难度、替代方案和未解决问题。先做可逆的小实验；只有当收益在强 baseline 上稳定、机制路径可解释、成本和风险可接受时，才进入不可逆的大规模训练或架构改造。

## 13. 从论文到项目：如何转化？

论文转项目需要降维。

不要一上来完整复现大论文，而是先提炼最小可验证假设。

例如：

1. LoRA：在我们任务上，低秩适配是否接近全参微调？
2. RAG：检索证据能否降低我们场景的事实错误？
3. DPO：偏好数据能否改善回答风格和安全边界？
4. FlashAttention：在我们序列长度下，是否提升吞吐并降低显存？
5. 多模态对齐：过滤低图文相似样本是否提升 VQA？

先做小实验验证关键假设，再决定是否工程化。

“最小”不是随意缩小模型，而是保留会影响假设的变量，去掉暂时不影响判断的规模。研究 LoRA 时，可以先固定底座模型和数据，比较 full fine-tuning 与多个 rank 的任务指标、训练显存和 adapter 大小；研究 RAG 时，可以先固定生成器，只比较无检索、dense retrieval 和同候选集 reranker；研究 FlashAttention 时，可以先固定输出和数值精度，测量不同序列长度下的显存、吞吐和误差。

最小实验要有停止规则。若方法在核心切片没有方向性信号，或收益始终小于测量噪声，就先停止扩展；若信号存在但成本或失败模式不清，就增加一个针对性控制；若信号稳定且与假设一致，才扩大模型、数据和任务范围。这样可以把研究预算用在减少不确定性上，而不是用在盲目放大上。

## 14. 研究记录中的表达结构

一份可供他人复核的论文说明，可以用下面八个部分组织：

1. 论文解决的问题是……
2. 既有方法的瓶颈是……
3. 作者的核心假设是……
4. 方法具体改变了……
5. 实验实际支持了……
6. 这项工作的贡献范围是……
7. 仍然存在的局限是……
8. 下一步最能减少不确定性的实验是……

这个结构比按论文顺序复述更清晰。

八句话之间还应保持论证顺序。第 1、2 句定义问题和旧瓶颈；第 3 句给出可被检验的假设；第 4 句说明方法如何改变系统；第 5 句只陈述实验实际支持的结论；第 6、7 句区分自己的评价、作者声明和局限；第 8 句提出一个能减少剩余不确定性的下一步，而不是随意罗列“未来工作”。

资源或篇幅有限时，可以先写前三项和结论边界，再展开公式、实验和失败案例。这样即使不能复述论文全部细节，也不会把摘要中的宣传语误当成已经验证的判断。

这八个部分不是固定的写作模板，而是一条证据顺序。前两项限定问题范围；第三项把方法转成可检验假设；第四项说明干预如何作用；第五项严格限制结论的外延；第六、七项区分贡献和局限；最后一项把剩余不确定性转成实验。若一份说明只有方法和分数，没有假设、控制条件和失败范围，读者就无法判断该结果能否迁移。

### 14.1 一张最小证据卡片

下面是一张针对 reranker 的假设教学卡片。表中的数字均为构造输入，不是论文或真实项目的实测结果；它展示的是记录方式，不是对任何具体论文的重新评价：

| 字段 | 示例记录 |
| --- | --- |
| 目标问题 | 长文档问答中，正确证据是否经常被截断或排在上下文末尾 |
| 干预 | 在固定候选集上增加 reranker，并固定最终证据预算 |
| 主要结果 | 200 条 claim 中支持数从 `142/200=0.71` 变为 `156/200=0.78`；P95 延迟假设从 `420 ms` 变为 `760 ms` |
| 关键控制 | 文档快照、生成模型、prompt、解码参数、候选数和评估样本相同 |
| 支持范围 | 仅为这一组假设的 200 条长文档 claim；未测短问答，也不能据此外推 |
| 替代解释 | reranker 可能通过改变证据长度或提高拒答率带来部分收益 |
| 未完成实验 | 固定证据覆盖率后比较排序；测量跨段证据的完整性 |
| 当前决策 | 在高风险长文档路径继续验证，短问答路径暂不默认启用 |

这张卡片把“效果更好”拆成结果、控制、范围、替代解释和决策五种不同信息。`0.78` 本身不是结论；只有与评估切片、延迟和实验设计一起出现，读者才能知道它代表什么。由于这里的数字只是教学输入，不应据此声称统计显著或真实收益。真实研究卡片还应保留原始数据位置、代码提交、评估脚本和运行时间，方便后来者复核，而不是只留下人工转写的数字。

## 15. 常见错误读法

错误一：只读摘要和结论。

摘要告诉你作者想让你相信什么，实验和 ablation 才告诉你是否该相信。

错误二：把公式当成理解本身。

公式重要，但还要知道它解决什么问题、对应什么实现、引入什么代价。

错误三：只看分数最高。

分数要结合 baseline、公平性、成本、污染风险和统计显著性看。

错误四：把论文方法当成通用真理。

论文结论通常有实验边界。换模型、数据、任务、规模后未必成立。

错误五：复现失败就说论文不行。

复现失败可能来自数据、超参、环境、实现和评估差异。

还有一个常见错误是把“能复现”与“能解释”混为一谈。成功复制分数不代表已经知道哪一个组件产生收益；失败也不代表方法不存在，只说明当前实验与原结论之间有差异。阅读报告时要把复现层级、控制变量和剩余不确定性写在一起。

## 16. 机制与边界：研究判断是因果思维

深入读论文时，不只是问“有没有提升”，还要问“提升由什么造成”。

可能原因包括：

1. 方法机制真的有效。
2. 数据更多或更好。
3. 模型更大。
4. 训练更久。
5. 调参更充分。
6. baseline 较弱。
7. 评估集被污染。
8. 指标选择有偏。
9. 随机波动。

所以研究判断本质是因果拆解：控制变量，排除替代解释，建立证据链。

若论文要把结果差异归因于方法，可以用下面的账本式记号提醒自己检查替代解释：

~~~math
\Delta Y=\Delta Y_{\mathrm{method}}+\Delta Y_{\mathrm{data}}+\Delta Y_{\mathrm{scale}}+\Delta Y_{\mathrm{compute}}+\epsilon
~~~

这只是教学记号，不是通用的可识别统计模型，也不意味着这些因素的影响能够独立、线性地相加；方法与数据、规模或算力之间可能存在交互，`epsilon` 也不自动等于可估计的随机噪声。通过同数据、同模型、同 compute 的对照，可以减少部分替代解释；通过多 seed 和独立评测，可以量化一部分不确定性；通过数据和规模消融，可以观察收益是否迁移。证据不足时，正确结论是“当前实验与方法收益一致”，而不是“已经证明方法导致收益”。

因果判断也有边界。并非所有研究主张都是因果干预主张：描述性 benchmark 报告可以先说明测量了什么、样本来自哪里；只有当论文要声称某项干预造成结果变化时，才需要追问控制组、随机化或其他识别策略。训练系统中的数据、优化器和硬件往往不能完全独立；观察到的相关性可以帮助提出假设，却不能替代干预。对论文的评价应明确自己拥有的是实验控制、自然观察还是作者报告，避免使用超过设计能力的因果措辞。

## 17. 一个可落地的研究工作流

如果要在项目中研究一篇新论文，可以按这个流程：

第一步，一页纸读论文。写清问题、方法、假设、实验、局限、工程成本。

第二步，找最小假设。不要复现全量实验，先验证最核心机制。

第三步，建立 baseline。确保 baseline 是当前系统强基线，而不是弱基线。

第四步，做最小复现。控制数据、模型、训练步数和评估脚本。

第五步，做 ablation。拆关键组件，看是否真的贡献。

第六步，做误差分析。看提升和失败分别发生在哪些样本。

第七步，做成本评估。显存、延迟、吞吐、实现复杂度、维护成本。

第八步，写实验报告。包括正结果、负结果、不确定性和下一步。

这八步可以落成一个可重复的状态流：`questioned -> specified -> baselined -> implemented -> diagnosed -> compared -> interpreted -> decided`。每次状态转换都要有输入和产物，例如从 `specified` 到 `baselined` 需要固定数据、模型、指标和预算，从 `compared` 到 `interpreted` 需要差异、置信范围、切片和成本。研究日志不能只保存最终 notebook，因为最终结论往往依赖被放弃的失败实验。

工作流还要有资源边界。先运行低成本的 shape/数据/小样本检查，再做短训练和小模型，再做完整训练；当 smoke test、验证损失或权限检查失败时停止向后推进。停止并不是放弃研究，而是避免在前置条件不成立时消耗更大的计算预算。

## 17.1 Worked case：从一个 claim 到最小实验

假设一篇论文声称：“把普通检索结果交给带 reranker 的 RAG，可以降低长文档问答的事实错误。”研究者不能直接复述这个结论，而要把它拆成可证伪的假设：在文档、生成模型、上下文预算、解码参数和评估集都不变时，reranker 是否能让正确证据更常出现在最终上下文中，并因此提高 claim-level grounding？

先用一组假设输入手算。假设在同一批 200 个问题上，每个问题都抽取一个待核查 claim；原始检索支持其中 142 个，reranker 条件支持 156 个，则支持率分别为 $142/200=0.71$ 和 $156/200=0.78$。绝对差是 $(156-142)/200=0.07$，即提高 7 个百分点；相对基线的增幅约为 $0.07/0.71\approx9.9\%$。若 P95 延迟由 `420 ms` 变为 `760 ms`，增加 $760-420=340$ ms，相对增幅约为 $340/420\approx81\%$，新延迟约为基线的 $760/420\approx1.81$ 倍。这些数值与上一节证据卡片一致，都是教学构造值，不是实测结果。

这组边际比例只能说明这个假设样本中的差值，不能证明差异统计显著，也不能单凭它确认 reranker 是原因。即使同一批问题前后配对，还需保留逐题从“不支持”变“支持”及从“支持”变“不支持”的数量，才能选择合适的配对分析；还要报告评审协议、重复运行或区间，并在独立切片上检查稳健性。

首先画出可能的因果链：

~~~mermaid
flowchart LR
    R["Reranker"] --> O["Evidence order"]
    O --> C["Prompt context"]
    C --> A["Answer claims"]
    A --> G["Claim grounding"]
    R --> L["Latency"]
    C --> T["Token cost"]
    A --> F["Refusal / coverage"]
~~~

这张图的价值在于提醒研究者：答案分数的变化可能来自证据顺序，也可能来自上下文变短、模型看到的 token 变少、生成变保守或 reranker 把低置信问题过滤掉。若只测最终准确率，无法知道哪条路径发生了变化。

最小实验可以设计成四组：原始 dense retrieval、同候选集的 lexical rerank、目标 reranker，以及打乱目标 reranker 分数的对照。四组都使用相同文档版本、候选文档、最终证据 token 预算、生成模型、prompt 和 temperature，并记录 Recall@K、证据顺序、引用支持率、答案准确率、拒答率、rerank 延迟和总 token。这样既能检查排序质量是否带来收益，也能看结果是否来自模型复杂度或额外上下文。

把机制走完一条具体数据流。假设某个问题必须同时引用文档 D2 中的版本条件和文档 D4 中的失败例，候选集还有 D1、D3 两篇干扰文档。四篇文档各 100 token，最终证据预算为 300 token，因此系统只能把其中三篇交给生成模型。原始检索次序是 D1、D2、D3、D4，预算截断后只留下 D1、D2、D3，两个必要证据只找到一个；若把“必要证据找回率”定义为命中的必要文档数除以必要文档总数，则为 $1/2=0.5$。假设 reranker 输出 D2、D4、D1、D3，仍取前三篇，D2 和 D4 都在上下文中，找回率为 $2/2=1.0$。这个小例子解释了排序怎样通过预算截断影响证据覆盖，但只展示一条请求的机制路径，不能证明总体答案质量会提高。

这个计算还暴露一个容易漏掉的控制条件：四篇文档等长是本例的简化假设。真实系统若只固定文档条数，重排可能把更长的文档放进上下文，导致 token 数、证据内容和延迟同时改变；若只固定 token 数，末尾文档可能被截断。实验应记录实际序列化后的 token 数，并明确截断发生在文档边界还是文档内部。必要时分别报告固定文档数和固定 token 预算的结果，避免把更大输入误归因于更好的排序。

汇总 200 条假设样本时，也要保留逐题变化。与 `142/200` 和 `156/200` 两个边际比例相容的一张可能配对表是：142 条原来已支持的 claim 中，122 条在重排后仍受支持、20 条失去支持；58 条原来不受支持的 claim 中，34 条变为受支持、24 条仍不受支持。于是基线支持数为 $122+20=142$，重排后为 $122+34=156$；净增加是 $34-20=14$ 条，即 $14/200=0.07$。这张表仍是构造输入，但它显示两种系统的边际支持率无法告诉我们有多少问题改善、又有多少问题退化。真实实验应保存这种逐题转移信息，并按预先选定的配对分析方法报告不确定性；仅仅改善条数多于退化条数，并不自动意味着统计结论稳定。

进入确认实验时，还要把“证据找回”与“答案变好”分开测量。证据找回率是中间机制指标；claim 支持率、答案正确率和拒答率是不同的结果指标。若证据覆盖提高而答案支持率不变，可能是生成模型没有使用证据、提示没有要求引用，或被找回的文档仍不完整，此时不能宣称完整因果链已经得到验证。若支持率提高却伴随大量拒答，也要报告覆盖率和拒答率，避免只看留下来的可回答样本。

每条请求应保存固定的查询与文档版本、候选文档 ID、原始和重排后的顺序、各文档 token 数、实际截断位置、生成文本、claim 级评分、拒答标签，以及检索、重排和生成各自的延迟。评估者最好不知道样本来自哪种系统，评分规则要先定义“证据支持”的判定边界；有分歧时保留分歧并按既定流程复核。延迟测试则需说明并发、缓存和硬件条件，分别报告组件延迟与端到端尾延迟。这样一旦总指标变化，研究者才能沿日志判断变化来自候选召回、排序、截断、生成还是评分流程，而不是事后凭印象选择解释。

整个验证应按成本递增推进：先用少量人工构造样本检查 D2/D4 这类多文档证据能否按预期进入上下文，再用固定的开发集选择配置，最后在未参与调参的保留集上比较预先指定的主指标。人工构造样本适合验证实现逻辑，却不能代替自然问题分布；开发集上的最优阈值也不能继续在保留集上反复调整。若保留集只显示窄切片收益，就把结论限定在该切片，并据此决定是否值得追加样本或测量另一类风险，而不是直接扩大到所有 RAG 请求。

假设项目团队事先为高风险长文档路径写下一个试验门槛：支持率至少提高 5 个百分点，且 P95 增幅不超过 400 ms。上面的构造值满足这两个门槛，所以只支持进入更大、预先设计的确认实验；它还不能支持直接上线。短问答路径没有纳入这 200 个样本，也没有证据说明它受益。这个门槛只是该假设项目的决策约束，不是通用业务标准。

最后再做一个最小反例：构造一个需要同时使用文档 A 和文档 B 的问题，让两个文档单独都不足以回答。如果 reranker 只优化单文档相关性，可能把 A、B 之一排到末尾，最终答案反而变差。反例能检验研究者是否理解“排序分数高”与“证据链完整”不是同一件事，也提醒实验同时检查证据覆盖，而不只看单篇相关性。

## 18. 把阅读判断变成下一步

本节是全章的自检入口，不重复前面各节的答案。读完一篇论文或一轮复现实验后，可以沿下表从问题回到证据，再把未解决部分写成下一步行动。

| 自检问题 | 回看位置 | 留下的可复核产物 |
| --- | --- | --- |
| 研究问题是否具体到对象、指标和条件？ | §§3—5 | 一个可观察的问题、核心假设及其预测 |
| 方法究竟改变了什么，依赖哪些实现和资源？ | §6 | 输入、机制、实现条件、成本和失效边界 |
| 结果能否归因于方法，哪些结论仍未被检验？ | §§7—9、16 | 公平 baseline、关键对照、效应与不确定性 |
| 当前工作停留在代码运行、结果再现还是主张检验？ | §10 | 本轮目标层次、已匹配条件和差异账本 |
| 证据是否足以支持继续投入？ | §§11—13、17.1 | 决策约束、停止条件、未解风险和下一实验 |

检查时，不要把空白直接填成“方法无效”或“论文可复现”。如果问题和指标清楚而关键控制缺失，下一步应补控制；如果实现、数据或评估协议尚未对齐，先修复这些条件；如果区间太宽或样本范围太窄，增加能缩小该不确定性的样本或切片。每次行动都要对应一个尚未回答的问题，并预先写明什么观察会支持或削弱原假设。

读书会或项目评审可以先让每位参与者独立写下“作者声称什么”“证据直接支持什么”“仍有哪些替代解释”，再比较分歧。讨论的结果不必是同一个方案，而应是共享的问题定义、可追溯的证据和一项能够减少分歧的下一步实验。这样，研究判断才会从个人印象变成团队可以复查和接续的工作。

## 19. 资料与证据边界

本章的研究判断框架是教学抽象，不是任何单篇论文的官方评价标准。LoRA、DPO、RAG、FlashAttention 和 MoE 只是用来说明“问题—假设—方法—证据—代价”如何连接；引用这些论文不代表本章对它们的全部实验结论做了重新验证。阅读具体论文时，应回到原文的数据、代码、实验设置和版本。

研究方法、复现和评估的资料也有不同层次。论文说明作者在特定设定下做了什么，官方仓库和文档说明实现入口，实验报告说明当前项目实际观察到什么，复现清单帮助记录变量；它们不能互相替代。一个可运行的 GitHub 仓库不自动证明论文 claim，论文中的显著结果也不自动证明当前业务收益。

继续阅读本章例子时，可以从这些原始入口开始：

1. [LoRA v2](https://arxiv.org/abs/2106.09685v2)、[Direct Preference Optimization v3](https://arxiv.org/abs/2305.18290v3) 与 [RAG](https://arxiv.org/abs/2005.11401)：参数高效适配、偏好优化和检索增强的论文入口。
2. [FlashAttention](https://arxiv.org/abs/2205.14135) 与 [Switch Transformers](https://arxiv.org/abs/2101.03961)：高效 attention 和稀疏专家架构的论文入口。
3. [The Unreasonable Effectiveness of Open Science in AI](https://doi.org/10.1609/aaai.v39i25.34818)：一个有明确样本与时间预算边界的 AI 研究复现案例。
4. [What Do Machine Learning Researchers Mean by “Reproducible”?](https://arxiv.org/abs/2412.03854)：复现术语与科学严谨性议题的综述入口。
5. [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist) 与 [Code and Data Submission Guidelines](https://neurips.cc/public/guides/CodeSubmissionPolicy)：研究报告、复现路径、实验细节和资源说明的官方检查入口；使用时核对目标年份的规则。
6. [ML Reproducibility Challenge](https://reproml.org/)：复现工作和复现报告的生态入口，具体项目仍需核对其版本与要求。

这些资料应被视为研究和实现的起点。引用论文结论时，要说明它的实验范围；当自己的实验与论文不同，应报告差异和不确定性，不把作者声明、社区观点或个人推测混成同一等级的证据。

## 20. 本章小结

研究方法的核心不是读更多论文，而是建立判断能力。

研究方法最终要回答两个问题：在什么条件下，当前证据允许我们相信什么；下一步实验能以多大成本减少剩余不确定性。沿着“问题—假设—方法—对照—结果—边界—决策”记录，论文阅读、复现和项目判断才会进入同一条可复核的研究链。
