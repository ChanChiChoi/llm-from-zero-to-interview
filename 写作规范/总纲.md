# 项目写作规范

本规范用于让不同背景的读者沿着清楚的主线学会大模型知识。它同时规定事实、公式、代码和维护要求，但这些要求服务于读者理解，不能替代讲解本身。

## 首要原则

1. **初学者是核心读者。** 本书系的核心主线面向希望从已声明前置出发学习大模型的初学者。具备本节所声明前置知识的读者，读完每个核心知识点的完整讲解后，应能说出它是什么、解决什么问题、关键对象或步骤怎样起作用、结论怎样来。若读者仍反复要问“这是什么”“这个符号指什么”“为什么做这一步”，说明定义、对象对应或推理台阶还缺；先补足主线解释。初学者不等于零基础，作者要说明读者前置，不让读者替作者补缩写、背景、对象关系或推理步骤。完整讲解可以由多个自然段组成，不要求把所有解释塞进一个段落。
2. **先让读者有的放矢，再用合适的锚点讲清。** 可先说明问题、目的、意义、背景及本知识点对章节的作用；抽象或易卡处再选锚点，解释对象、动作、变化、原因和结果，并归纳一般规则。方法的提出、演进或比较还须交代必要前置、相关旧做法及不足、当前回应、解决结果与限制。锚点可用小例子、输入输出、过程、伪代码、图示或对照；相关知识可共用，不同知识可选不同形式。流程长且要演算时，可用伪代码搭路线，再沿同一例子讲计算；这是可选方式，细见模块 02。顺序按主题调整，易懂处直接讲，不硬造锚点。公式、代码和比喻均非配额；公式须有理解、推广、目标/约束或推理用途，并核实来源和条件；代码只在章节承诺编码或 API 任务时作为交付。影响理解或结论的假设、边界须讲清，其余深度按读者结果取舍。
3. **篇幅服从理解，不以长短论好坏。** 本规范不设正文统一字数或页数上限、下限。简单内容一句能说清，就不拉成长篇；复杂内容若少了定义、背景、因果、桥接句或中间结果会让初学者卡住，就把必要台阶展开。背景、目的和意义也按读者理解需要交代：写到读者知道问题从何而来、为什么要学即可，不用泛泛拔高或反复强调。压缩时删重复和不推进理解的内容，不删读者走完推理必需的步骤。若必要知识确实超出一章能连贯承载的范围，应扩写、拆章或分成连续篇章，不能把内容压成只有专家能解码的提纲。
4. **用一条主线组织本章需要的知识。** 一个中心问题可以带出多个相互依赖的小问题和知识点；主线规定它们的关系与顺序，不限制章节的知识点数量、广度或应有深度。若单章无法在读者能跟上的前提下充分覆盖并讲透，就扩展内容或拆成多章、连续篇章。理解本章承诺所必需的知识要纳入初学者主线；额外的专家视角或拓展内容只有在能增加明确读者价值时才作为选读支线加入，不得因为某个知识点存在专家材料就一律添加。
5. **让目标逐层落地。** 书册说明要把读者带到什么能力，章节说明自己怎样贡献于书册目标，知识点说明自己解决什么问题、依赖什么假设、通过什么表示或机制起作用。章节之间、章节内部和知识点之间都应能看出前后关系；下一级内容不能脱离上一级目标。
6. **用稳定问题理解和比较方法。** 对方法追问“模型表示什么、目标是什么、算法怎样实现”，并按读者卡点说明三者如何连接；不要求配齐例子、步骤、伪代码和推导。完整证明或深数学仅在本章承诺或读者结果需要时展开。章节定位与组织见模块 02a，正文路径见模块 02；概念、系统和项目按各自任务组织，不套统一目录。
7. **深度来自因果和推演。** 术语、引用、公式、代码、例子、图表、字数和清单数量都不能单独证明讲清楚；重点是这些内容是否共同帮助读者理解本知识点。
8. **事实可靠是底线。** 读者友好不意味着省略会改变结论的假设、来源或安全边界。
9. **规范是作者的脚手架，不是正文模板。** 规范中的问题、表格和门禁用于构思与复核；正文应像作者在带读者理解一个真实问题，让读者看见为什么谈到这里、结论怎样得出、下一步为什么接着讲。不要机械地把检查项逐条改写成标题或段落。不过，如果一个知识点确实能分别说明背景、目的、解决的问题、意义、适用场景或优缺点，而且显式分区能帮助初学者定位信息，可以直接用相应标签、小标题或列表讲清，不必把它们全部融进连续叙述。只保留有具体内容且适用的栏目；重复项可以合并，没有内容的栏目可以省略，不为凑格式硬造内容。
10. **专家向内容是加分项，不是知识点配额。** 不要求每个知识点都设置“专家模式”，也不要求每章都附上高阶推导、实现细节、替代方案或研究争议。只有当这些内容能兑现本章承诺、解释会影响结论的差异，或解决明确的读者需要时才加入；没有额外专家内容，不构成写作缺陷。必要的定义、证据、假设和边界若影响初学者理解或结论正确性，仍须在主线中用读者能理解的方式讲清，不能误标为可选专家内容。
11. **门禁看整体理解，不清点表达配件。** 验收以本章读者结果和正文整体为单位：读者是否知道为什么学、能否跟上解释并理解关键行为逻辑、章节是否兑现承诺、事实是否可靠。代码、公式、例子、图表和伪代码是可选教学工具；它们的出现或缺席本身不构成通过或阻断条件。只有当某种形式是本章承诺的交付物，或缺少它确实让读者无法理解/完成任务时，才按具体需要检查。

## 规则强度

**必须**表示完成前应满足，或记录清楚的例外理由；**应该**表示默认做法，可按内容类型采用等效方式；**可以**表示可选的组织或表达手段。规范中的检查问题是定位断点的工具，不要求逐点、逐项机械打勾；不能把某种教学形式的存在转化为普遍门槛。各项要求应共同服务于读者结果，不能为换取表面流畅而降低事实核验、证据边界或已确认的读者结果。出现张力时，补足理解台阶、调整顺序，或按必要范围扩写、拆分；实现细节和版式应服务于读者目标与事实表达。

## 整册和实质修订的必经顺序

清楚表达是正文质量要求，不能代替书册定位、结构审视或资料研究。用户要求整册、完整或系统精修，或任务会改变主题范围、章节职责或重要结论时，按以下顺序推进；不能只做词句润色就称为整册精修：

1. **界定研究对象，不预判结构（模块 01）**：只用书系目标、目标读者和主题范围限定搜索边界。简介、目录和相邻册可以帮助确认研究对象，但不能据此穷举检索主题、预判章节去向或形成最终结构方案。
2. **先联网收集和梳理外部知识（模块 03）**：书册定位/组织、章节定位/组织、章节正文实质编写或修订都需要按任务范围联网研究；网络研究是形成判断和校对正文的必经步骤，不是先照现有目录或稿件列完结论后再找资料佐证。书册任务要查本领域的重要知识、能力框架、前置关系和新进展，也要查同类书和课程怎样组织；章节定位要查主题知识、依赖、新进展及教学组织；正文实质修订要核对方法机制、核心结论、时效事实和效果主张，并判断是否需要补充知识。记录检索范围、时间窗、来源和证据边界。不得离线凭已有目录、稿件或记忆完成这些判断。
3. **再用外部证据复核并更新结构地图**：将联网所得的主题、能力目标、前置关系和组织经验映射到现有书册与章节，识别缺口、重叠、前置断层、路径不清及可独立成章的新主题。对本册目标有明确贡献、能形成独立且可检查的读者结果，且范围和前置关系足以支撑连贯讲解的新主题，必须增设章节或连续篇章，不能只为维持原章数而塞入旧章。
4. **稳定并同步书册骨架（模块 01）**：依据研究结果确定书册定位、章节职责、阅读路线及章节增删、拆并、迁移；更新简介、目录和导航。后续发现改变范围或章节关系的新证据时，返回研究和结构判断步骤。
5. **再做逐章研究与结构审视（模块 03、02a）**：书册骨架稳定后，限定本章主题、书册目标和读者；联网梳理外部知识、机制、演进、评估、工程环节与教学组织，再对照正文和相邻章节，确定位置与结构。符合独立成章条件的新主题必须另设章节；影响书册范围时返回上游。
6. **按章节任务精修正文（模块 02、04）**：结构稳定后，保留必要覆盖、深度、证据和边界，再改进讲解、例子、术语和表达。语言直白不能成为删知识、降核验或跳过结构修复的理由。
7. **同步并按门禁验收（模块 05）**：检查简介、目录、链接、图表、代码状态、配套资料和遗留风险；沿声明的阅读路径复读后，才判断完成。

仅改错字、格式或不改变含义的局部措辞，可以按模块 03 的规定免做研究扫描；但若它是整册精修的一部分，仍须先完成上游的书册定位、结构与研究步骤。已有扫描只有在问题、范围和结论未变化时才可复用。

## 工作时怎样读取规范

- 上下文压缩或新会话恢复时，先读 [恢复速读版](00-恢复速读版.md) 和 `progress/` 交接记录，再按任务路由加载。
- 全书精修按完整顺序：模块 01 → 模块 03 书册级联网研究 → 模块 02a → 模块 03 章级联网研究 → 模块 02（正文实质修订联网校对）→ 模块 04（按需）→ 模块 05。
- 已定结构的章节内部实质重写：读模块 02、模块 03（联网校对核心事实和方法主张，并判断是否需扩充知识）及章节契约；有公式/代码/图表时加模块 04，交付时读模块 05。纯错字、排版或公式渲染修正等不改语义的局部任务可免模块 03。若发现上游问题，再读模块 01、02a。
- 书册定位/组织读模块 01、模块 03 书册级研究；章节定位/组织读模块 02a、模块 03 章级研究；章节正文实质编写或修订读模块 02、模块 03 正文核验。三类任务都须联网，研究范围随任务层级变化。纯错字、排版、公式渲染等不改变知识含义的局部修正可免新检索；改动结构、事实、公式语义或适用条件时仍须研究。公式/代码/图表读模块 04；同步与验收读模块 05。

局部任务读对应模块的完整相关章节；跨模块、全书或范围不清时再读完整总纲与所有相关模块。摘要不能代替需要核对的规范正文或进度记录。

如用户明确要求不查看既有 `progress/`，遵守该要求，不读取旧进度；仍应根据可读取的书册材料独立完成必要审视，并按任务要求记录本轮决定和交接。

## 记录职责

plan.md 只保存书系总计划、原则、任务队列和完成条件。progress/ 保存书籍审阅、内容去向、正文改动、状态、未解问题和交接。research/ 只保存联网发现的新知识、来源、版本、证据范围和未验证项。正文不写作者指令、工作日志或维护路径。
