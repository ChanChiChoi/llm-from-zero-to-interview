# 项目写作规范

本规范用于让不同背景的读者沿着清楚的主线学会大模型知识。它同时规定事实、公式、代码和维护要求，但这些要求服务于读者理解，不能替代讲解本身。

## 首要原则

1. **先保证读者跟得上，再考虑覆盖多少内容。** 读者应能说清本节在回答什么、核心概念怎样工作、例子说明了什么，以及它怎样连接下一节。
2. **一节只推进一条主要思路。** 新术语、公式、边界和实现细节都要说明为什么在此处出现；与主线无关的内容转为选读或移至合适入口。
3. **让目标逐层落地。** 书册说明要把读者带到什么能力，章节说明自己怎样贡献于书册目标，知识点说明自己解决什么问题、依赖什么假设、通过什么表示或机制起作用。章节之间、章节内部和知识点之间都应能看出前后关系；下一级内容不能脱离上一级目标。
4. **用稳定问题理解和比较方法。** 对方法，持续追问“模型表示什么、学习目标（优化准则）是什么、算法怎样实现这个目标”。方法章节默认按“问题 → 定义与假设 → 目标函数 → 推导 → 算例 → 局限”展开；需要说明算法时，在推导后、算例前补上算法步骤。这组问题是理解和比较方法的共同坐标，不要求每册书采用同一种组织结构。概念、系统和项目内容按各自任务使用合适结构。
5. **深度来自因果和推演。** 术语、引用、公式、代码、字数和清单数量都不能单独证明讲清楚。
6. **事实可靠是底线。** 读者友好不意味着省略会改变结论的假设、来源或安全边界。
7. **规范是作者的脚手架，不是正文模板。** 规范中的问题、表格和门禁用于构思与复核；正文应像作者在带读者理解一个真实问题，让读者看见为什么谈到这里、结论怎样得出、下一步为什么接着讲。不要把检查项逐条改写成标题或段落。

## 规则强度

**必须**表示完成前应满足，或记录清楚的例外理由；**应该**表示默认做法，可按内容类型采用等效方式；**可以**表示可选的组织或表达手段。发生冲突时，先保证事实正确和读者能跟随，再处理范围、证据、实现与版式。

## 工作时怎样读取规范

- 定位书册、调整目录或判断跨册分工：先读模块 01。
- 审视、改写或扩充章节：先读模块 02。
- 加入新主题、更新时效事实或修改重要结论：同时读模块 03。
- 处理公式、代码、图表、术语：同时读模块 04。
- 更新简介、配套资料、进度或验收状态：同时读模块 05。

按工作实际进入后续步骤时，再补读对应模块；范围无法判断时读全部相关模块。上下文被压缩或在新会话恢复书籍工作时，先完整重读本总纲，再读相关模块和 progress/ 中的交接记录。摘要不能代替规范正文或进度记录。

## 记录职责

plan.md 只保存书系总计划、原则、任务队列和完成条件。progress/ 保存书籍审阅、内容去向、正文改动、状态、未解问题和交接。research/ 只保存联网发现的新知识、来源、版本、证据范围和未验证项。正文不写作者指令、工作日志或维护路径。
