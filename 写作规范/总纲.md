# 项目写作规范

本文件是本书系长期写作与精修规范的总纲和唯一索引，适用于二十四册正文及题库、练习、项目、论文索引、术语表、知识图谱和维护资料。完整细则按主题存放于本目录的五个模块中；模块是本规范的正式组成部分，不是摘要或可选参考。

本规范不记录当前进度、执行日志和易过时的模型事实。项目计划写入 `plan.md`；凡是针对书籍的架构审视、章节审阅、正文或配套资料修改、修改决定、状态、遗留问题和交接，统一且只写入 `progress/`。`research/` 只记录联网搜索发现的新知识点及其来源证据、版本和证据边界，不记录每册或每章的精修进度、审计结论、修改历史或工作交接。

进度记录和研究资料中的规范章节号按其引用的规范版本理解；新建的书籍进度记录写入 `progress/`，新发现的知识及来源证据写入 `research/`。

规则使用以下强度：**必须**表示完成前应修复，或记录明确的例外理由；**应该**表示默认要求，可按内容类型采用等价做法；**可以**表示推荐做法；**不适用**表示该项不适合当前内容，但仍需提供等价的验收方式。发生冲突时，优先保证事实与证据边界、读者理解、公式和代码正确性、书册结构、配套同步，最后才考虑格式美观。

## 恢复与读取规则

每次上下文压缩或摘要化后，以及在新会话恢复书籍审阅、正文或配套资料工作时，先从头到尾重读本总纲。恢复已有任务时，再读对应的 `progress/` 交接或审阅记录，确认当前书册、章节、已定决定和下一步；进度记录说明工作状态，不能替代规范模块。随后按下面的加载工作流，在开始每个工作阶段前读取该阶段需要的完整模块。不得以摘要、记忆或此前读过的内容替代本次重读。模块保留原规范章节编号，规则强度和冲突优先级以本总纲开头为准。

## 加载工作流

按“当前要做的动作”逐阶段加载，不必每次开始任务就读完五个模块。先读主模块，再在进入相应步骤前补读配套模块：

| 当前工作阶段 | 开始前读取 | 进入以下步骤时再读取 |
| --- | --- | --- |
| 书册定位、契约、简介/目录审视、骨架决策 | 模块 01 | 做册级扫描、核验新方向或技术事实时读模块 03；判断整册完成时读模块 05 |
| 章节结构审视、章节精修、重写或扩写 | 模块 02 | 做章级扫描、实质扩写或核验技术结论时读模块 03；处理图表、公式、代码或术语时读模块 04；同步配套、写维护记录或判断完成时读模块 05 |
| 新模型或前沿主题更新 | 模块 03 | 判断是否改变书册边界时读模块 01；纳入正文时读模块 02；涉及技术呈现时读模块 04；执行同步或验收时读模块 05 |
| 修改图表、公式、代码、术语或正文边界 | 模块 04 | 需要重组章节讲解时读模块 02；涉及新事实或来源核验时读模块 03；更新验证记录或验收时读模块 05 |
| 记录配套同步、审计状态或判断任务是否完成 | 模块 05 | 按被验收的对象补读对应主模块：整册读模块 01 和 03，章节读模块 02 和 03，并按内容读模块 04 |
| 纯错字、空白排版等不改变含义、结构、链接、公式或代码的局部修正 | 本总纲 | 若发现改动影响上述任一方面，再加载对应模块 |

若章级扫描发现内容会改变书册边界或章节关系，先暂停局部精修，加载模块 01 重新审视骨架；需要新增主题或核验依据时同时加载模块 03。任务跨越多个阶段时按表逐步补读，不要因开始阶段而预先跳过后续阶段的规则。若无法判断范围，读取全部相关模块；仍不能确定时读取全部模块。
