# 模块 02：章节正文写作规范

本模块指导已确认章节定位、职责、范围和结构后的正文编写与实质修订。它规定写作过程、讲解选择和交付质量，不是书稿目录模板。不要把本模块的流程、表格或检查项原样变成正文标题。

章节职责、依赖或范围不清时，先回到[模块 02a：章节定位与组织结构](02a-章节定位与组织结构.md)；正文涉及事实、方法、效果或时效信息时，按[模块 03：研究与证据管理](03-研究与证据管理.md)核验；公式、代码、图表和引用按[模块 04：图表公式代码与引用](04-图表公式代码与引用.md)处理；交付记录与验收按[模块 05：维护同步与完成门禁](05-维护同步与完成门禁.md)执行。

## 一、执行流程

按以下顺序完成正文任务。顺序是工作流程，不是固定的章节结构；可根据主题合并或调整讲解步骤，但不得跳过相应判断。

### 1. 确认写作契约

开始写正文前，读取已确认的章节定位、读者前置和读者结果，并确认：

- 本章解决什么问题，属于全书或本册的哪项承诺。
- 读者是谁，默认具备哪些知识；哪些必要前置需在本章简短唤回。
- 读者读完应能解释、判断、操作或完成什么。
- 本章必须覆盖什么，哪些内容不属于本章，哪些实现或推导是选读。

若契约缺失或互相冲突，不要靠扩写正文猜定范围，返回模块 02a 澄清。重写允许调整讲解顺序和表达，不自动意味着可以缩小或扩大章节承诺。

### 2. 研究并列出必要内容

实质编写或修订前，按模块 03 联网核对本章涉及的方法机制、关键事实、时效信息、效果与比较主张，并判断读者是否需要尚未覆盖的知识。优先使用原始论文、技术报告、官方文档等与主张直接相关的来源；记录来源支持什么、不能推出什么以及尚未验证的边界。

将本章承诺拆成必要知识点，标明它们服务的读者结果、依赖关系和去向。此清单用于发现遗漏、重复和错位，不是保留配额。删、并、移内容时，确保必要前置、因果桥接、关键中间步骤、证据和边界没有随篇幅一起消失。新增知识与来源证据写入 `research/`；本轮编辑决定、状态和未解问题写入 `progress/`。

只改错字、排版或不改语义的公式渲染时，可免新检索。凡改变事实、结构、公式含义、推导或适用条件，仍须核验。

### 3. 选择主导讲解路径

判断本章或当前小节主要帮助读者完成哪类任务。内容可以混合，但应有清楚的主导任务；任务切换时用结构和过渡让读者知道阅读目标已改变。

| 主要任务 | 读者要回答的问题 | 常见组织路径 |
| --- | --- | --- |
| 概念或架构 | 这是什么？现象为何发生？ | 现象或疑问 → 对象关系 → 必要术语 → 机制与边界 |
| 方法、算法或推导 | 为何需要此法？它怎样工作？ | 问题与必要前置 → 关键过程 → 目标/规则 → 必要推导 → 条件与限制 |
| 系统或工程机制 | 请求、数据或状态经过什么？ | 输入与初态 → 关键动作 → 中间状态 → 输出 → 并发、失败与取舍 |
| 操作教程 | 怎样完成一个明确任务？ | 目标与前置 → 环境和输入 → 操作及预期输出 → 错误恢复 → 验证 |
| 项目或实战 | 怎样组合技术交付成果？ | 任务与验收 → 最小实现 → 逐步扩展 → 评估、故障与取舍 → 交付 |
| 论文、证据或方案比较 | 主张是什么？证据支持到哪里？ | 对齐问题和条件 → 方法差异 → 可比证据 → 结果、代价和边界 |
| 参考或查询 | 参数、接口或限制的准确值是什么？ | 对象入口 → 定义、输入输出、版本、约束和错误 → 最小示例及相关入口 |

这些路径只帮助选择讲解顺序，不要求逐项变成标题。操作教程可以解释必要原理，机制章节也可以包含操作。参考型内容可直接围绕真实对象、用途和约束说明，不必虚构情境。

方法章节可用“模型表示什么、目标是什么、算法怎样实现目标”作为检查坐标，避免把表示、优化准则和求解过程混为一谈。这是分析方法的工具，不是每章都要出现的固定三段式。比较方法时先对齐任务、数据和假设，再比较机制、证据、适用条件、代价及失败边界。

### 4. 为每个知识点选一个主锚点

每个需要正文讲解的知识点，都要有一个读者可以跟随的主锚点；相关知识点可以共用锚点，但必须说明它如何承载当前知识。锚点是解释对象、关键关系或变化的具体入口，不是开头装饰。单独的术语定义、公式、孤立数字或组件名称不构成锚点。

根据读者卡点，从以下形式中选最合适的一种作为主锚点；只在提供新信息时增加辅助形式：

| 锚点形式 | 适用情况 | 写作要求 |
| --- | --- | --- |
| 真实问题或小场景 | 读者不知道知识为何出现、要处理什么 | 交代真实任务、输入、目标和困难；场景简短并服务于机制 |
| 完整小例子 | 抽象关系或结果难以想象 | 交代对象为何需要处理、输入/初态、关键动作、变化原因和结果，并在后文继续使用 |
| 数值演算 | 读者需要复算损失、更新或中间结果 | 说明玩具数值和假设；展示必要中间量及原因，并嵌入能解释整个知识点的例子 |
| 状态表或执行轨迹 | 变量、张量、请求、资源或参与者逐步变化 | 按初态、动作、新状态和原因追踪；表格之外仍需解释因果 |
| 伪代码或编号步骤 | 循环、分支、顺序或停止条件容易混淆 | 交代输入、输出、关键动作和状态；只呈现算法骨架，不扩成工程程序 |
| 流程图、架构图、数据流或时间线 | 组件关系、数据去向或时序难以用段落呈现 | 标清对象、起止点和箭头含义，并追踪代表性对象；图不能代替因果解释 |
| 对齐的多种表示 | 从例子、图、公式到代码时容易断开 | 指出同一对象在各表示中的对应关系，以及新表示增加了什么信息 |
| 类比 | 关系抽象且读者确实熟悉对应经验 | 说明对应关系和失效边界，随后回到真实对象和机制 |
| 代码、交互或模拟 | 读者需要观察执行或变量变化 | 先提出观察问题，再比较输入与输出，并把模拟状态连回真实系统或模型 |

完整例子要能解释整个知识点，而非只把公式变量替换成数字。数值不是必要条件：若算术会遮住系统关系，就追踪对象、消息、请求、状态或决策过程。教学简化、假设值和模拟输出要明确标注，不得让它们看起来像真实数据、通用配置或方法保证。

同一锚点应贯穿讲解：读者能看出起点是什么、发生了什么动作、状态如何变化、为何变化以及结果意味着什么。公式、代码、图和术语中的对象要能对应到锚点。换例时说明新例子多解释了什么；不要用多种形式重复同一层内容。

### 5. 沿锚点完成解释

让读者从具体对象走到一般规则。可根据主题调整顺序，但主线通常需要完成以下工作：

1. 交代问题、目标或读者当前要理解的现象。
2. 呈现主锚点，并说明必要对象、输入、初始状态和假设。
3. 沿锚点解释关键步骤、状态变化、因果和输出；补齐理解所需的术语、前置和中间推理。
4. 在确有帮助时加入公式、伪代码、图表或代码，并明确它们与锚点的对应关系。
5. 概括可推广的规则，说明适用条件、证据边界、代价和失败情况。
6. 回答开篇问题，说明本知识点对本章读者结果的贡献，并自然连接后续内容。

不要求每章都显式写出“背景、目的、问题、意义、场景、优缺点”等栏目。只有这些内容确有不同且具体的信息，并且显式分区有助定位时才分别标出；重叠项合并，不适用项省略。没有真实技术前史时说明必要依赖和问题，不编造冲突或演进故事。

### 6. 判断公式、代码和扩展内容是否进入主线

公式用于准确表达关系、目标或约束，用于计算、比较、推导，或帮助从具体锚点推广一般规则。通常先讲清锚点中的具体过程，再决定是否需要公式。保留公式前确认：它解决什么问题，读者是否需要使用它，符号和条件是否与锚点一致，删去后是否会失去本章承诺的能力。不能只逐项解释符号来代替机制讲解。公式作为主要入口时，也要配合例子、状态追踪、图示或其他具体过程。来源、条件、符号口径、mask 及求和/平均方式按模块 04 核对。

代码只在本章承诺读者完成编码、API 操作或程序复现时作为必需交付；其他情况下可作为辅助验证。代码段须说明任务、输入输出和关键状态，不能只因可运行就算讲清机制。实现版本、配置、日志、API 和更深推导仅在影响本章结果、读者任务或结论时进入主线；其余内容可移入明确标识的进阶入口。影响结论或正确使用的条件、证据和限制始终属于主线。

正文没有统一字数或页数配额。删去重复、离题和不推进理解的内容，但不删必要前置、锚点、因果桥接、中间步骤、证据和边界。若本章范围内的覆盖和深度无法连贯兼顾，应扩写或拆分为衔接清楚的章节，而不是压缩成专家摘要。调整内容去向时，在 `progress/` 记录主要取舍和理由。

## 二、讲解质量规则

### 面向声明前置的初学者

“初学者”指具备本章明确声明的前置知识，不代表毫无基础。不能用有经验的工程师能猜懂来替代必要解释，也不能以简化语言为由删掉必要术语、数学、实现深度或证据。读者完成核心阅读后，应能说明知识点解决什么、关键对象或步骤如何工作、结果为何成立；专家证明、变体和争论只在本章承诺或读者结果需要时展开。

只唤回当前推理需要的前置。新术语在读者需要处解释其对象、作用和易混点；连续出现多个缩写时分组介绍。跨章链接不能代替本章理解所必需的一两句说明。涉及大模型数据流时，按主题需要解释文本、token 与 token ID，模型分数与概率，训练目标与参数更新，生成与上下文延续之间的关系；不要默认这些关系读者已经掌握。

### 说明对象、动作和真实因果

段落围绕一个主要解释任务。告诉读者当前要看什么，并解释动作为何发生、产生何种变化、结论由什么支持。步骤复杂时拆开或编号；不要把多个动作、条件和结论塞进一句。避免用“显然”“简单来说”“只要……就……”跳过推理，也不要用拟人化、空泛设问或同义句堆叠代替机制。

比较概念时先对齐维度，再说明差别；使用反例是为了揭示容易误判的边界。判断要落到当前对象：假设在哪一步起作用，证据支持什么，限制影响什么。结论有条件就写出条件，不把局部结果推广成普遍事实。

### 控制信息量和讲述声音

每段或步骤处理一个主要任务。新对象较多时先分组并说明关系；短句、列表和小标题服务于追踪，不要拆成没有因果的口号。标题、术语表格和检查项只在帮助读者定位关系时使用。

正文要像作者在解释真实问题，而不是逐项填规范。段落之间应有真实承接：问题引出锚点，锚点带出术语和机制，必要公式帮助归纳，边界限制结论。避免重复段首提示、段末总结和“下面介绍”“为后文打基础”等无实际作用的套句。讲述声音来自完整推理、具体取舍和诚实边界，不来自聊天口吻或故事数量。

## 三、章节验收

交付前沿章节整体复读，并按本章承诺检查：

- **契约**：读者、前置、目标和范围与已确认的章节定位一致；本章说明其对书册目标的贡献。
- **覆盖**：本章承诺的重要知识点都有正文入口；标题出现不等于讲清，段落多也不等于讲深。
- **锚点**：每个正文讲解的知识点都有明确主锚点；共用锚点时，读者仍能看出它如何解释每个知识点。
- **理解**：读者能沿锚点复述关键对象、动作、变化和结果；仍会问“这是什么”或“为什么做这一步”时，补上定义、对应关系或推理台阶。
- **表达形式**：例子承载完整知识点；公式和代码服务读者结果；图表与正文一致。形式的存在不代表解释充分。
- **事实**：关键方法、事实、效果与比较主张有相称证据；影响结论的假设、条件和限制出现在读者需要的位置。
- **取舍**：没有为满足模板新增空洞栏目；删减没有破坏必要覆盖、因果、证据或边界；选读内容有明确入口。
- **连贯**：章节前后承接，读者知道当前任务及结论如何回应开篇问题。

有目标读者时，观察其独立复述、复走过程或预测条件变化时卡在哪里；不要先给答案再问是否理解。没有试读时做初次接触检查：沿正文路线复走锚点，标出未解释术语、隐含条件、记号切换和无理由跳步。朗读可检查句段衔接，但不能单独证明机制已理解。

发现断点时先定位问题属于契约、前置、对象对应、步骤、因果、证据还是范围，再修正文中缺失环节。不要只堆近义句或改成模糊口语。单章无法连贯交付约定读者结果时，返回模块 02a 调整结构或拆章。
