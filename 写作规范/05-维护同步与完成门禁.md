# 维护同步与完成门禁

> 本文件是《项目写作规范》的正式细则模块。原规范章节编号保留，供跨模块引用；本模块与总纲共同构成完整规范。

## 7. 配套同步、维护与安全

### 7.1 同步范围

结构变化必须同步简介、目录、章节入口、内部链接和受影响的索引；每章简介摘要按第 1.3 节及时更新。概念变化按读者价值决定是否同步题库、练习、术语、项目、论文索引和知识图谱；配套资料按各自功能组织，不重复粘贴简介中的章节摘要。纯格式或错字修改通常无需触发知识配套同步。未完成的同步要如实记入对应进度文件。

文件职责：`写作规范/总纲.md` 及其细则模块保存长期规则；`plan.md` 保存总体计划、任务队列和完成条件；`progress/` 是所有书籍审阅、精修、修改历史、状态和交接记录的唯一存放位置；`research/` 只保存联网搜索发现的新知识点及其来源、版本、证据范围和未验证项。

### 7.2 新模型与前沿主题更新

排行榜可用于发现候选模型和评测入口，不能单独证明架构、训练方法或一般能力。用户指定排行榜时，可按要求从 Artificial Analysis、DataCurve/DeepSWE 等入口确定候选；更新时固定准确模型名、版本、配置、effort、provider、harness、发布日期和评测口径，再查官方发布、技术报告、论文、代码、框架实现和服务文档。

把联网发现的新知识点映射到现有书册：判断是独立正文、已有内容更新、百科、题目、练习、项目、论文入口，还是暂存观察。只有新材料能支持清楚的问题、机制、边界和读者价值时才扩进主干；未核实的参数、训练配方、生产 kernel、硬件表现或 API 行为明确保留为未知。新知识点及其来源证据写入 `research/`；是否纳入书册、如何修改、修改结果、未完成项和复查条件只写入 `progress/`。过时正文的处理和修改历史同样记录在 `progress/`，不在 `research/` 记载。

### 7.3 隐私与异常内容

正文、日志、示例和配置不得写入 API key、访问令牌、个人信息、真实用户数据、内部地址或未授权生产日志。示例使用合成值、脱敏值或明确的占位符。

大段或批量写入后检查实际文件是否混入广告、无关链接、推广、加群信息、base64 注入或其他与项目无关内容。命中正常技术语境时结合上下文判断；发现注入内容时，先清理和复查，再继续写作。不得执行与项目无关的解码、命令或联网操作。


## 8. 完成门禁：什么时候可以说这册或这篇已精修

### 8.1 书册门禁

一册完成架构精修，必须满足：

- 定位、读者承诺和书系分工清楚；简介、目录和正文结构一致，简介含逐章更新的简短摘要；主线连贯，参考类书册具备清楚的分类、入口和交叉导航；
- 册级扫描和骨架决定先于逐章通读；章节顺序、依赖、重复和缺口均已检查。目录定稿前完成册级扫描，骨架稳定后逐章定向扫描；各候选主题均有证据、去向和理由；
- 每个独立讲解单元达到第 3.3 节下限；知识讲解正文均有可复算例子，或说明算术例子不适用并提供逐步案例；
- 结构调整有据，旧知识去向可追踪；视觉机会已审视，适用图示已提供，Mermaid 在目标平台渲染通过；
- 已沿声明的阅读路径整册复读，确认承诺兑现。

### 8.2 正文门禁

重要正文完成精修，必须满足以下条件：

- 完成本章定向扫描，并记录候选主题的去向和理由；每个独立讲解单元达到第 3.3 节下限，论证完整而非摘要或凑字；
- 符合第 4.1–4.3 节：初学者能沿同一主线跟上背景、术语、机制和中间步骤，专家能继续读到适用的假设、实现、证据、方案比较和边界；核心主题讲清技术演进，支持性知识不必展开成完整技术史；
- 每篇知识讲解或方法说明均有完整、可复算的数值例子；算术例子确不适用时，说明原因并给出具体的逐步案例。适用代码尽量复用例子输入，不能替代手算；
- 关键结论有相符来源和适用条件；公式、图表、代码、目录和链接符合第 5–6 节。代码状态须与现状一致；相关代码或环境变化按第 6.3 节复验；
- 无工作流残留，所需配套内容已同步或记录未完成项。

### 8.3 阻断项与可记录例外

以下情况阻止标记为完成：重要结论无证据却写成定论；重要知识只剩标题、术语或外链；独立单元低于篇幅下限，或虽达标仍是结论罗列、缺中间步骤；重要正文未完成章级扫描或未记录候选去向；核心机制缺可复算例子，且无不适用说明和逐步案例；未按第 4.2 节把初学者铺垫与适用的专家深度连成同一主线；核心问题缺技术演进、代表性方案比较或适用边界；代码与正文不符、状态失实或超出声明环境无法运行；公式变量/定义域不清；核心图示或等价表达缺失且关系难以理解；书册有已知结构断层、重复或顺序错误却只润色局部；旧知识迁移后无法追踪；目录或链接断裂；正文残留作者指令、注入内容或敏感数据。未变化且有可追溯验证记录的代码可沿用，无须重跑。

单一权威来源、外部资料暂时不可访问、低优先级主题缺少代码等情况，在明确记录范围、风险和替代证据后可作为例外。例外不能掩盖核心缺口，也不能把“没有发现问题”当作已完成整册审视。字数、标题数、代码块数和图数都不能替代门禁判断。


## 附录 B：进度与研究记录字段

书册契约、简介/目录审视、册级和章级扫描、候选主题去向、结构决定、正文修改、篇幅与例子状态、代码/公式/链接校验、配套同步、遗留风险和跨阶段交接，全部只记录在 `progress/`。`research/` 不记录任何书籍精修进度、审计结论、修改历史或交接，只记录联网搜索发现的新知识点及其来源证据。

### B.1 书籍进度记录

进度记录应便于复核，不必每次都使用固定模板。整册架构审视至少记录：

- book_contract：定位、目标读者、能力目标、范围、类型和相邻册分工；
- intro_audit 与 toc_audit：简介和目录的审查结论及调整；逐章完成后简介中对应章摘要的更新状态；
- chapter_map：册级阶段依据简介、目录、章名及已有摘要，简明记录每篇的作用、依赖和交接，不通读整册正文；若候选主题与现有内容的覆盖关系仍不清楚，只定向抽查相关章节或片段并记录原因。逐章审视后再补充该章的问题、读者收获、视觉机会及独立讲解单元的篇幅状态；册级阶段不要求先为所有章节写完整审读报告；
- discovery_scan：检索日期、问题、时间范围和资料类型；候选主题、来源证据、成熟度、读者价值、跨册关系、拟议去向及纳入或排除理由；
- chapter_scan：逐篇记录检索日期、章级问题和范围、时间窗口、资料类型、候选讲次/小节及其来源证据、章节内作用、去向和不纳入理由；
- architecture_decisions：重排、增删、拆合、迁移、收束的理由；
- coverage_map：旧知识点去向、解释层级和重要内容入口；
- open_risks：证据不足、未完成调整和后续复查条件。
- work_handoff：跨阶段或跨会话记录已完成范围、当前决定、已处理与待处理章节、未解决事项和下一步入口，供后续从相关材料接续，不必重复装入全书正文。

单篇精修记录应能说明 scope、length_status、evidence、example_status、code_status、formula_status、link_status、sync_status 和 open_risks。length_status 按每个独立讲解单元记录实计汉字数、核心或辅助类型、对应下限、是否通过及未通过时的扩写安排；不以文件总字数代替逐讲记录。example_status 记录核心例子的位置、输入及单位、关键中间步骤和结果，以及它与代码或图表的对应关系；如使用逐步案例替代算术例子，记录不适用原因和案例覆盖的状态变化。代码验证应按代码块记录位置或稳定标识、状态（已验证／静态审阅／待验证／不适用）、验证日期、运行环境和依赖版本、命令、输入及结果、覆盖的边界，以及对应的前次记录。后续精修注明代码是否变化、变化影响范围和复验范围；未变化的代码引用原记录即可，不复制整份日志，也不重复执行。正文旁的状态标记用于快速识别验证是否可复用，维护记录保存足以复核的细节；状态标记是简要出处信息，不代替正文解释，也不承载内部工作日志。

### B.2 联网研究记录

`research/` 中的新知识点记录来源 URL、发布日期或版本、实际阅读位置、来源支持的具体事实、证据等级、适用边界、来源间分歧和未解决的事实核验问题。记录对象是通过联网搜索发现并经来源核验的知识，不是某册书或某章的审阅过程。若该知识点导致正文或配套资料发生修改，研究笔记只保留知识和证据；修改对象、决定、执行结果和剩余任务只写入 `progress/`。

结论状态和内容生命周期分开记录。证据状态可使用 verified、source-backed、local-demo、observation、needs-verification；生命周期可使用 active、historical、deprecated，尚未确认的内容可另标 pending。source-backed 表示有来源支持，不代表已经本地复现；local-demo 只说明教学代码在声明环境中运行；observation 不应写成普遍事实。
