# 01：书册定位与全书架构

本模块决定一册书为什么成立、服务谁、承诺什么，以及内容范围和深度如何取舍。每册的有效产出必须写入 `写作规范/全套书不同册的章节大纲结构/<book-目录名>/总纲.md`；不能只在对话、进度记录或研究记录中提出定位而不更新该文件。本模块不产出目录、章节划分或逐章职责。

01 交付书册定位与内容承诺；02a 据此联网研究，设计完整目录、各章职责、章内标题和各正文部分的中心思想；02 按确认的大纲联网研究并展开正文。总纲应让 02a 明白需要交付什么，同时保留具体知识点发现和教学组织的空间。

## 一、两种工作方式与执行顺序

### 新建书册总纲

适用于新增一册书，或用户明确要求重新确定整册定位。先提出读者、中心任务和范围假设，再按模块 03 研究领域知识、能力依赖和同类书型，检验这些假设，形成完整总纲。不能先复制某份目录，再逐项寻找支持材料。

### 修订已有书册总纲

适用于新增内容领域，或调整读者、目标、范围、深度与跨册分工。完整读取现行总纲，结合简介、目录和相关章节设计理解已有承诺；覆盖情况不清时读取相关正文。现有目录用于了解现状，不是本模块的产出，也不能限制研究发现。

研究后重新组织完整的现行总纲，使新内容融入读者结果、范围、深度与依赖。不能只在末尾追加“补充主题”。同一书册尚无总纲时，先根据研究建立总纲，不把现有目录当成已经确认的定位。

两种方式都按以下顺序执行：

1. 明确已有约束和待验证假设，包括用户要求、书系职责、主要读者、中心任务和预期规模。
2. 按模块 03 联网研究领域内容、读者前置和同类书型，形成外部主题与能力关系，再对照现有书稿。
3. 确定主要承诺，处理目标冲突，为候选内容决定范围、深度和去向。
4. 按第五节形成完整总纲，检查内容是否构成整体、承诺是否可兑现。
5. 按第六节交给 02a；将依据与执行记录分别存入对应位置。

实质定位工作必须联网。论文和官方资料用于核验定义、事实及技术边界；高质量博客、notes、讲义、课程与教材同时用于理解领域和研究讲解方式。具体入口见[联网数据来源](联网数据来源.md)，证据规则见[模块 03](03-研究与证据管理.md)。本模块不代替后续章级和正文研究。

## 二、先明确读者与整册任务

### 读者起点与需要解决的问题

指定主要读者，并说明兼顾哪些次要读者、哪些需求超出定位。不能把初学者、研究者和生产工程师列为同等服务对象。读者起点要具体到已有能力和当前障碍，例如能调用模型但解释不了行为，或懂算法但不能实现和排错。

前置分为进入本册必需、本册会补足、仅进阶材料需要三类。说明必要的模型概念、数学、编程或工程能力及补学入口，不能用“懂一点深度学习”代替。进阶主题只要属于核心承诺，就仍需沿声明的前置讲清，不能以“进阶”为由省略必要解释。

读者困难也需要依据。区分实际教学或读者反馈中观察到的问题、课程与资料支持的判断、作者尚待验证的假设。公开课程只能说明其安排和前置，不能证明本书读者都存在同样困难；没有反馈时可以提出假设并说明依据，不能虚构调查或用户结论。

### 核心任务与独立价值

用具体问题说明整册主要解决什么，以及相对其他书册、官方文档或资料合集增加什么能力。“系统全面、深入浅出”不能代替定位。主要书型可以是课程学习、机制解释、项目实践、工程查询或面试准备；混合用途需明确主次。

读者结果要描述任务和独立程度：能跟随完成、能修改迁移，还是能独立设计与判断。区分概念理解、机制推理、数学分析、实现、实验、排错和系统取舍，不要求每个主题达到所有层次。面试表达应建立在准确解释、比较和追问能力上，不以背诵结论代替学习结果。

01 从整册层面规划内容版图、覆盖重点、深度分配、领域依赖与整体可行性，并说明这些内容围绕什么共同对象、过程或决策构成一本书。不能只为当前想补的主题写局部介绍，也不能拼接热门主题。总纲应让 02a 看见整册的主次与承接，避免关键领域缺失、重复主讲或深浅失衡；它描述领域与能力关系，不提前编写目录，也不把全局判断留给 02 临场补救。

## 三、决定范围、深度与规模

### 内容要求写到领域与能力层次

对重要内容领域说明它服务哪个结果、覆盖什么、讲到什么程度、需要哪些基础，以及在哪里停止。01 不必穷尽算法内部步骤、公式、具体实现环节或全部知识点，这些由 02a 和 02 继续研究。

| 层次 | 01 应明确 | 留给后续模块 |
| --- | --- | --- |
| 范围 | 哪些内容领域必须覆盖、哪些支撑理解、哪些排除 | 02a 发现具体知识点、补齐依赖和设计章节 |
| 方法 | 经研究确认的必讲方法及其纳入理由；其他方法的选择标准 | 02a 比较候选、细化覆盖并组织大纲 |
| 深度 | 概念辨析、机制、关键推导、教学实现或工程分析需要达到哪里 | 02a 分配章内要求；02 展开具体推理和实现 |
| 表达与检验 | 本册读者需要的解释完整度，以及核心能力如何检验 | 02 选择锚点、例子、公式、代码与具体题目 |

例如可以要求“覆盖奖励建模与策略优化的关系，比较 PPO 与 DPO 的训练机制，读者能追踪目标与更新对象，不要求复现大规模训练”。不必在总纲里逐项预写 PPO 的内部流程，更不能提前指定它属于第几章。深度按领域分别确定，不统一规定公式、代码或例子配额。

### 核心承诺优先于覆盖数量

先确定必须兑现的主要承诺，再将内容分为核心、必要支撑、进阶扩展、查询或范围外。每项纳入都应能说明对读者任务的贡献；新、热门或资料丰富本身不是进入主线的充分理由。稳定基础和新进展都应接受这一判断。

目标冲突时，先遵守用户明确要求、事实正确性和必要前置，再保护主要读者与核心结果。次要用途不能挤掉主线所需的解释。通常先移出无关扩展、压缩重复、调整次要用途，再判断是否需要扩大整册规模或调整定位；不得把核心机制压成摘要，也不能把必要支撑降为选读以制造“精简”。仍无法兼顾时，明确冲突和备选取舍；涉及改变用户已明确的核心要求，应提交具体方案供用户决定。

记录关键取舍的理由即可，不要求所有小主题都有冗长的排除说明。被排除的重要候选应说明由其他册承接、作为外部参考，还是不在当前书系承诺内。

### 规模与学习成本

说明本册预期是集中入门、系统学习还是长期参考，读者主要进行连续阅读、专题学习还是边做边学。给出有依据的内容容量与学习投入预期；信息不足时用定性范围，不虚构精确页数、小时数或完成周期，也不预设章数。

学习成本包括前置补学、数学推理、编程、实验和反复查询，不能只估阅读量。若主线过重，先依核心承诺调整范围与深度；是否需要拆成多册属于 01 的定位判断，具体章数与拆章属于 02a。规模是可行性约束，不得成为省略必要解释的理由。

承诺实践能力时，明确教学规模、数据、硬件、软件与预算条件，以及预期交付物。条件不足时可提供替代路径，但要说明能验证什么、不能验证什么。教学实现不等于生产实现，解释方法不等于能够独立开展前沿研究。

## 四、跨册分工与证据边界

每个重要主题应明确哪册承担完整主讲，其他册为各自任务回顾到哪里、增加什么新能力。本册核心承诺需要的解释不能全部推给别册；也不能仅因别册出现同一术语就判定重复。具体跨章分工由 02a 设计。

册号不自动表示阅读顺序。明确本册依赖其他册的哪些能力，读完可进入什么方向，以及能否凭等效经验直接进入；具体章节阅读路线在目录确定后由 02a 落实。混合书型须有主导用途，不能让教程、操作手册与研究综述的要求互相牵制。

联网研究先形成外部候选及其读者价值、前置、成熟度和证据边界，再对照书稿。研究既要核查技术内容，也要检验定位假设；发现冲突应调整判断，不能只找支持旧定位的材料。同类教材与课程可提供组织参照，不能直接证明某种安排对本书读者更有效。

区分稳定基础与易变的模型、框架、接口、评测和实践经验，说明资料时间范围、关键版本和需要重新核查的变化。对争议、闭源推断和证据不足的内容保留边界。关键定位依据链接到研究记录，不把所有检索过程搬进总纲。

具体书册定位以各册现行总纲为准。早期前三册的定位假设已移至[独立参考材料](参考资料/前三册定位假设.md)，仅供核对，不是通用规范，也不能覆盖后续确认的定位。

## 五、总纲的产出结构

### 用于生成总纲的内容维度

下表提供总纲可以展开的内容方面。各册根据自身定位选择、合并和扩展，不必包含所有维度，也不必沿用表中顺序。每个选用维度应写出本册具体的定位和内容，形成能指导 02a 的说明，不能只复述维度名称。这里的内容可以成为总纲的标题或融入连贯段落，不是供逐项打勾的检查表。

| 总纲维度 | 在总纲中展开的内容 |
| --- | --- |
| 当前册书的定位 | 本册的主题、中心问题、主要用途和整体特点；说明它是一册怎样的书，以及在书系中承担的任务。 |
| 面向的读者 | 主要读者的学习阶段、知识背景和实际需求，可兼顾的其他读者，以及本册不承担的入门或专业需求。 |
| 小白视角下的理解需要 | 从本册声明的前置出发，读者对主题尚未建立的整体认识、容易困惑的概念和缺失的理解环节；据此说明本册需要补足的直觉、知识背景和机制联系，让读者从不熟悉走向真正理解，而不是只记住名词。小白不等于没有任何基础。 |
| 学习者视角下的知识成长 | 读者从已有认识走向新知识的过程，以及本册希望帮助形成的知识框架、概念联系和自主学习能力；说明零散知识怎样在本册形成系统认识，不在这里编排具体章节。 |
| 实践者视角下的使用需要 | 读者把知识用于实际任务时需要的实现认识、选择依据、实验经验和排错能力；据此确定本册对方法落地、资源约束与真实问题的展开程度。 |
| 专家视角下的内容价值 | 熟悉领域的人阅读时重视的关键机制、方法间的深层联系、假设与适用边界、证据和争议，以及本册在准确性、深度和独特解释上的价值；据此明确应保留的关键内容与研究深度，不把专家熟悉的前置直接施加给主要读者。 |
| 不同经验读者的内容层次 | 适合全体主要读者的核心内容，以及有价值时为已有经验者提供的深入分析、工程讨论或延伸材料；说明这些层次怎样共同服务本册定位，避免基础读者被隐含前置阻断，也避免深入内容只是重复基础定义。 |
| 阅读所需的基础 | 理解本册所需的概念、数学、编程和工程基础，本册会补充的前置，以及需要事先补学的内容。 |
| 学习目标与能力收获 | 读者通过本册建立的知识认识，能够解释、比较、实现或解决的问题，以及能够独立完成任务的程度。 |
| 覆盖的知识范围 | 本册涉及的主要知识领域、核心主题和必要支撑内容，形成对整册“要讲什么”的完整说明，不分配章节。 |
| 知识深度 | 各主要领域讲到概念认识、机制理解、关键推导、实现分析或工程运用的具体程度；不同领域可以采用不同深度。 |
| 内容重点与侧重 | 本册重点展开的领域、方法或问题，以及理论、算法、数据、系统、应用等视角的主次关系。 |
| 知识主线与内在联系 | 各领域围绕什么共同问题形成整体，概念、机制和能力之间的依赖与关联；描述内容关系，不编写目录或章节顺序。 |
| 理论与实践的结合 | 理论解释与代码、实验、项目或系统分析之间的关系，实践用于帮助理解还是形成独立交付能力，以及教学实现与真实工程的差别。 |
| 实践内容与学习成果 | 适合本册的实验、项目、实现、方案分析或其他成果类型，涉及的任务范围与预期完成程度；具体任务由后续模块设计。 |
| 内容边界与不展开的部分 | 只作必要介绍的内容、不在本册展开的领域及其去向，以及核心、扩展和参考内容的大致区分。 |
| 与其他书册的关系 | 本册与前置、并行及后续书册的知识承接、讲解视角和覆盖边界，必要回顾与完整主讲的分工。 |
| 讲解风格与阅读体验 | 面向本册读者的讲解基调，如重直觉与机制、重推导、重实现过程或重工程判断；说明需要的解释程度，不预先规定锚点和例子数量。 |
| 学习与使用方式 | 本册适合系统学习、专题研读、项目实践、面试准备还是长期查询，以及这些用途的主次；具体阅读路线由 02a 设计。 |
| 整册体量与学习投入 | 本册作为入门、系统专题或参考书的预期展开规模，以及阅读、补学和实践的投入特点；不预设章数或虚构精确时长。 |
| 实践环境与资源条件 | 实践涉及的数据、软件、硬件、预算和外部服务条件，以及资源受限时可以采用的学习方式。 |
| 经典基础与前沿内容 | 本册稳定基础、代表性方法和新进展的覆盖侧重，前沿内容作为主线、扩展或研究导读的定位。 |
| 技术背景与适用边界 | 本册讨论的技术场景、重要版本或时间范围，以及涉及的假设、适用条件和争议背景。 |
| 资料基础与延伸方向 | 支撑本册定位和范围的主要研究资料、课程、博客或 notes，相关证据记录入口，以及读完后的深入学习方向。 |

读者视角用于帮助生成定位与内容要求，不等于本册必须同时面向所有层次。例如，面向初学者的书也可以借专家视角明确哪些关键机制和边界不能遗漏；面向有经验工程师的书也可以借初学者视角发现某个新领域中需要补足的认识。最终总纲应写出这些视角带来的具体内容决定，不输出一串“小白是否看懂、专家是否满意”的审查问题。

总纲应围绕本册自身的内容展开。例如，训练专题册可以重点写清训练知识范围、算法理解深度和实验侧重；工程实践册可以重点说明任务范围、实现深度和交付成果。不同维度之间自然衔接即可，不要求每个维度单独成节，也不额外套用固定的五部分结构。

文件位置如下；只有总纲由 01 产出，其余由 02a 产出：

```text
全套书不同册的章节大纲结构/
└── <book-目录名>/
    ├── 总纲.md
    ├── 目录.md
    └── 序号-主题.md
```

此处保存当前有效设计。联网发现的新知识及来源证据写入仓库 `research/`；定位决定的修改历史、进度、状态和交接写入 `progress/`；`plan.md` 不接收执行日志或研究事实。没有研究确认的书册不批量生成貌似定稿的总纲。

完整的产出粒度示例见[书册总纲示例](示例参考/书册总纲-教学设定示例.md)。示例中的读者、规模和取舍都是教学设定，不能当成实际书册定位或研究证据。

## 六、交接与完成判断

交给 02a 时提供有效总纲路径和本轮设计范围。02a 应能据此判断哪些结果必须兑现、哪些内容不可缺、深度到哪里，以及哪些方面可自主研究设计；无需再猜书册面向谁、为何而写。章节划分、增删、拆并、标题与顺序都由 02a 负责。

02a 发现具体知识点或调整章节关系，通常不需要修改总纲；只有影响书册定位、主要读者、核心承诺、覆盖深度、整体规模或跨册分工时，才返回 01。正文研究同样可以发现上游问题，不能把总纲当作拒绝新证据的理由。

交付前沿“读者起点—核心结果—必要内容—深度—条件—检验”检查：

- 声明的前置能否支撑阅读，主要困难是否有依据或已标为假设。
- 内容是否围绕共同任务形成整体，核心承诺有无缺失支撑或互相冲突。
- 范围、深度和学习成本是否相称，关键取舍是否明确。
