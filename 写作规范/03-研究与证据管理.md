# 03：研究与证据管理

本模块统一规定何时研究、如何检索和核验，以及证据能支持到哪里。结构判断由模块 01/02a 承担，正文讲解由模块 02 承担；研究记录与书籍工作记录分别写入 `research/` 和 `progress/`。

不同类型材料的发现入口见[联网数据来源](联网数据来源.md)；本模块规定如何选择来源、核对主张和记录证据边界。

## 一、研究触发与复用

以下工作必须按任务范围联网研究：

- 书册定位、主题范围、全书架构和跨册分工。
- 章节职责、范围、顺序、拆并和增删。
- 正文实质编写或修订中涉及的方法机制、关键事实、时效信息、效果/比较主张，或可能存在知识缺口的内容。
- 公式含义、推导、适用条件或重要结论发生变化。

只改错字、排版、链接格式或不改变知识含义的局部表达，可免新检索。既有研究仅在问题、范围、时间窗、关键版本仍适用时复用；快速变化主题要补查新版本和新证据。联网受阻时记录暂定判断与待查问题，不把方案称为最终结论。

研究范围随任务变化：书册研究领域知识、能力/前置关系和书型组织；章节结构研究主题、依赖、新进展和教学组织；正文核验研究方法、事实、效果主张及必要补充。现有简介、目录和正文用于界定对象与后续对照，不能代替外部研究，也不能限制候选主题。

## 二、研究流程

1. **界定问题**：记录目标读者、需要作出的判断、主题边界及时间窗/版本。
2. **独立发现资料**：分别检索领域知识和组织经验。前者覆盖核心概念、机制、前置、评估、边界、争议与变化；后者查相近读者任务的教材样章、课程、框架、指南和教学研究。
3. **追到原始来源**：用摘要、综述、搜索结果和模型总结发现线索，再阅读关键论文、标准、官方资料、源码版本或教材原文。不同类型来源分别支持其实际内容；单本目录不能证明普遍效果，主张编排改善学习需要直接相关的学习研究。
4. **记录外部发现**：在检查现有结构前，列出主题、读者结果、前置、来源、成熟度/时效和争议，避免只围绕现有标题找佐证。
5. **对照并决定**：映射现有覆盖为充分、部分、仅提及、缺失、重复、过时或超出目标；指定主讲位置、必要回顾、选读/查询入口、其他书册承接或不纳入理由。
6. **检查证据和停止条件**：重要结论已核原文、来源支持范围明确、差异和未解边界已记录；继续搜索不再带来可能改变结构或结论的重要发现。此条件不表示穷尽领域。

技术主题可查原始论文、技术报告、标准、官方文档、固定 revision 源码及条件明确的评估资料；理解机制和设计讲解时，也要主动查高质量博客、教程、课程讲义、公开 notes 和教材样章。教学材料可帮助发现解释顺序、推导、例子和常见误区；其中的关键事实与结论仍按其证据来源核验。组织经验可查公开教材序言/目录/样章、课程框架、教学指南和相关研究。用中英文同义词、缩写、新旧称迭代检索，并追查参考文献、被引资料、版本记录和课程链接。PRISMA-S、Cochrane 等系统综述方法可借鉴透明检索记录，不要求每次书籍审视做成系统综述。

首次开展教材/课程组织研究时，可从[研究组织与学习设计入门来源](参考资料/研究组织与学习设计入门来源.md)建立问题和检索入口；这些起步来源不能替代当前主题的直接证据。

## 三、按任务核验

### 书册级

在定书册定位、目录和跨册职责前，先形成领域主题/能力图和组织样本表。确认稳定基础、核心能力、前置、进阶主题、跨领域关系、时效风险及争议；再决定每个候选在书系的主讲位置、回顾点、参考入口或不纳入理由。达到独立章节条件的主题必须单列，不能为了维持章数塞进旧章。无重大新增时也记录扫描范围和现有结构仍适用的理由。

### 章节级

书册骨架稳定后，围绕本章主题研究知识、机制、任务、评估、工程环节、边界和前置；同时查相近课程单元和教材章节的读者、目标和组织选择。先形成外部主题表，再对照正文和相邻章，确定章节职责、读者结果、顺序、范围及候选去向。若研究结果改变书册范围或跨册路线，返回模块 01。

### 正文级

实质写作或修订时，核对方法机制、关键技术事实、时效信息、效果/比较结论，以及章节需要的新增知识。逐个确认来源支持什么、不支持什么、适用条件、版本和证据边界。正文引用贴近主张，并解释证据如何支撑该句；不能只列链接让读者自行推断。

## 四、证据等级与结论边界

| 来源 | 可支持 | 不能单独支持 |
| --- | --- | --- |
| 论文、技术报告 | 方法定义、实验设置、作者报告的结果和限制 | 当前线上接口行为或普遍生产性能 |
| 官方文档、模型卡、发布说明 | 已公开能力、参数、配置和产品说明 | 未披露训练细节或内部机制 |
| 固定 revision 源码 | 指定版本的实现路径 | 所有版本或生产部署结果 |
| Benchmark / harness | 指定任务、环境、工具和评分口径下的结果 | 裸模型的一般能力 |
| 高质量博客、技术教程、课程讲义、公开 notes | 作者明确给出的解释、推导、实现经验或教学组织；可用于形成讲解路径 | 对所有读者有效，或未核验的效果、跨版本事实和普遍结论 |
| 教材、样章、课程、设计指南 | 具体组织方式或明确建议 | 对所有读者有效，或建议已证明提升学习效果 |
| 学习研究与综述 | 指定读者、材料和任务下的效果与限制 | 脱离条件的普遍效果 |
| 本地实验、教学代码 | 声明环境和输入下的观察 | 论文、模型或生产环境复现 |
| 社区讨论、榜单、社交信息 | 候选方向、实践反馈和线索 | 未交叉核验的确定事实或普遍结论 |

尽量用不同类型来源交叉核验重要判断。记录来源冲突、不可访问内容和未解决问题；证据不足时降低确定性、缩窄结论或标为待核。数字比较需核对任务、数据集、指标、分母、模型/配置、硬件、harness 和测量时间。不得从单一模型、配置、provider、effort、数据集或环境外推整个家族或生产场景。闭源模型须区分官方披露、外部评测、实现推断和社区猜测。

## 五、记录格式与存放位置

每项研究记录应便于他人复核，至少包含：

- 研究问题、读者和范围；实际检索日期、平台、检索词、语言、时间窗/版本及筛选范围。
- 来源标题、URL、作者/机构、日期/版本、类型和实际阅读位置。
- 来源支持与不支持的主张、适用条件、证据强弱、来源分歧和待核项。
- 重要候选主题及其读者价值、前置、决定去向和纳入/排除理由。

`research/` 只保存联网发现的新知识点及来源证据，不写审阅流程、章节修改历史或交接。新知识若引发内容取舍，研究事实记 `research/`，决定、执行、状态和遗留事项记 `progress/`。写作规范中的例子值应明确标为教学设定；`source-backed` 不表示本地复现，`local-demo` 只表示在所述环境运行，`observation` 不应写成普遍事实。
