# 研究与证据管理

> 本文件是《项目写作规范》的正式细则模块。原规范章节编号保留，供跨模块引用；本模块与总纲共同构成完整规范。

## 5. 资料研究与证据管理

### 5.1 哪些工作必须先研究

核心技术结论、重要知识扩写或重写、书系/书册/章节主题边界变化，以及模型、论文、benchmark、框架、API、训练和部署等时效内容，都必须先联网检索并阅读原始资料。清楚表达和正文润色不能替代结构研究。

纯错字、格式或不涉及主题、结构、结论的局部措辞修改可以免做新扫描。同一研究问题的扫描只有在范围、时间窗口和关键版本仍适用时才可复用；快速变化领域出现新版本或新证据后必须补查。

#### 5.1.1 联网研究的起点和门槛

书系、书册或章节定位与结构任务必须先联网研究，扫描要早于详细目录设计、拆并决定和正文改写。联网研究不是为现有目录找佐证，而是先独立梳理本领域的重要知识、前后依赖和适合的组织方式，再拿外部发现检查现有结构。

现有简介、目录、正文和本地笔记只可帮助确定研究对象、读者和大致范围。它们不能替代外部资料，也不能先把搜索问题限定成现有标题清单。联网受阻时，只能整理暂定范围、待查问题和已有材料；不能声称已完成结构审视，也不能把新增、删除、拆分、合并或迁移定为最终方案。

#### 5.1.2 书系和书册级研究流程

在决定每册定位、全书目录或跨册分工前，按以下步骤完成研究：

1. **界定范围**：记录全书系/本册要服务的读者、要带来的能力、覆盖领域和大致时效范围。现有书名和目录只用来认出对象，不先把它们当作候选主题的完整清单。
2. **独立梳理领域知识**：联网查本领域的知识框架、课程或能力框架、综述、关键论文、标准和官方资料。分别辨认稳定基础、核心能力、重要进阶主题、前置关系、跨领域联系、近期变化和仍有争议的内容。快速变化主题要注明检索日期，并把近期资料与仍有效的基础来源一起看。
3. **研究组织经验**：查与目标读者和主要任务相近的教材序言、目录、样章，课程大纲/框架、教学设计指南和相关学习研究。记录样本面向谁、承担何种任务、怎样安排前置和主线、怎样区分必读/选读/查询内容。教材目录只能证明该书这样安排，指南只能证明它提出了这种建议；要主张某种安排改善学习效果，必须找与该主张相称的研究。
4. **核验关键发现**：打开原始论文、官方文件、标准或教材原文，找到支持该判断的具体段落、数据、课程单元或样章。对会影响书册定位和新增章节的主题，分别核对两件事：学科资料是否支持该主题的定义、机制、边界或现实重要性；读者/组织资料是否说明它怎样服务本书目标、能力顺序和读者任务。不能只靠搜索摘要、单篇论文、单本目录或社交帖决定新增章节；重要或有争议的判断要用不同类型的来源交叉核对。若声称某种编排能改善学习效果，必须另有直接相关的学习研究；证据不足时说明不确定性，不把案例当成效果证明。
5. **建立外部主题表**：逐项写明主题/能力、读者需要达到的结果、前置知识、证据来源、成熟度或时效性、与其他主题的关系。先建立这张表，再查看本地简介、目录和正文，避免目录缺什么就只搜什么。
6. **逐项决定去向**：将外部主题与现有书系对照，选择主讲书册/章节、必要回顾位置、选读或参考入口、另册去向，或不纳入。说明决定如何服务读者结果、依赖关系和全书路线；重要决定要能追溯到证据。若主题对本册目标有明确贡献，能形成独立且可检查的学习结果，且范围和前置关系足以支撑完整、连贯的讲解，就必须新开章节或连续篇章。
7. **检查全书路线**：核对读者能否从声明的前置走到全书承诺；检查关键能力是否缺失、章节/册之间是否有前置断层、主题是否被重复完整主讲，以及是否有新主题改变了原路线。若有，返回前面步骤补查并调整。

不能只按搜索命中数量决定研究是否足够。至少要确认领域知识扫描和组织经验扫描都已覆盖；关键候选都有来源、前置和去向；快速变化主题已查到明确的时间点；新的检索不再持续带来会改变结构的重要主题。没有发现新主题也要记录查过的范围和时间窗、主要来源类型，以及现有结构为何仍能满足读者目标。这个检查用于判断本轮结构审视是否有依据，不代表已穷尽全领域。

#### 5.1.3 章节级研究流程

书册定位和骨架稳定后，逐章按以下顺序研究和审视。若是单章任务，也必须先读清本册目标和章节大致主题，再完成本流程；只改局部措辞的例外见本节开头。

1. **划定检索边界**：写明本章要服务的书册能力、目标读者、本章大致主题和需核对的时间范围。不要先把现有小节标题复制成封闭检索清单，也不要因为本章已放在某一位置就默认它的职责正确。
2. **独立画出主题范围**：联网查主题的基本概念、主要问题、机制/方法、常见任务、评估方式、工程环节、边界和前置关系；对时效内容查当前版本，对基础机制回溯关键原始来源。留意本章现有目录之外的候选主题。
3. **补查教学组织**：查能代表相同读者任务的教材章节、课程单元和教学研究，比较其前置、讲解范围、章节结果和相邻内容关系。不能只照搬目录顺序；记录该安排适用的读者、目的和限制。
4. **读本章和相邻章并对照**：外部主题图完成后，再检查本章正文与相邻章节。逐项标记已讲清、只提到未讲、缺失、重复、前置不足、过时或不属于本章目标的内容；同时检查本章在全书中的前后交接。
5. **确定职责和结构**：明确本章的中心问题、读者结果、真实前置、必需主线、支撑内容、进阶内容和后续入口。再决定保留、扩写、拆分、合并、移动、增设章节或不纳入，并给出外部依据和读者理由。
6. **做结构门禁**：只看目录和章节职责，确认每节都服务于本章结果、顺序符合依赖或任务过程、读者能看见承接与交接，且外部扫描中的高价值候选都有去向。存在改变本册分工或路径的发现时，返回册级研究，不在章内私自消化。

#### 5.1.4 检索设计、扩展和停止规则

- 把问题写成可检索的概念组，列出常见同义词、缩写、旧称/新称和中英文关键词。涉及全球研究或英文术语的技术领域，不能只用中文检索；若一个词覆盖范围很宽，可分成多组查询，不要用过多限定词过早排除结果。
- 分别运行领域知识查询和组织经验查询。前者可查“知识框架/课程核心/能力/先修关系/综述/标准/官方文档/新方法”；后者可查“教材序言/目录/样章/课程大纲/教学设计/读者目标”。关键词按具体主题改写，不能把这些例子当固定搜索模板。
- 可把每轮查询拆成几种角度，例如“领域 + curriculum/body of knowledge/competency/prerequisites”“主题 + survey/review/standard/official documentation/original paper”“目标读者 + textbook sample chapter/syllabus/learning outcomes”。这些是起步用的检索式，查到新术语和参考来源后要迭代，不要求每次机械使用全部组合。
- 先做宽口径扫描发现术语和关键来源，再按来源中的参考文献、被引资料、官方版本记录或课程交叉链接追查。新资料改变了主题图或提出重要反例时，更新检索词并再查一轮。
- 记录实际使用的搜索平台或资料库、完整检索词、检索日期、时间范围/版本、筛选条件及未覆盖范围。PRISMA-S 和 Cochrane 是系统综述的检索/报告规范；本项目借用它们的透明记录、迭代搜索和追查关键引用做法，不要求每次书册或章节审视都执行完整系统综述流程。
- 搜索摘要、AI生成总结和二手文章只能提供线索。重要来源要打开原文，核对作者、发布日期/版本、范围、方法和限制；引用链只能帮助找资料，不能替代实际读到的证据。

每轮研究的最低记录包括：

| 记录项 | 写清什么 |
| --- | --- |
| 问题和范围 | 本轮要判断什么、面向哪类读者、覆盖哪个主题/书册、哪些内容暂不研究 |
| 检索记录 | 日期、平台/资料库、实际检索词、语言、时间范围/版本和筛选条件 |
| 来源卡 | 标题与链接、作者/机构、日期或版本、来源类型、直接读过的部分 |
| 证据说明 | 来源具体支持什么、不支持什么、适用条件、证据强弱、与其他来源的冲突 |
| 未解边界 | 找不到原文、版本不明、来源相互矛盾或尚未验证的内容 |

`research/` 保存新知识及来源、版本和证据边界；书册/章节的定位、增删和去向决定记入 `progress/`，并链接到对应来源。不要在 `research/` 写审阅流水账，也不要把结构取舍藏在正文脚注里。

#### 5.1.5 完成研究扫描的门槛

在进入最终结构决定前，逐项确认：

- 已联网查过领域知识和组织经验，而不是只读当前目录、书稿或搜索摘要；
- 关键主题的来源已读到原文或官方材料，且能说明它们分别支持什么；
- 基础知识、近期变化、前置依赖、关键交叉关系和高价值候选已纳入主题表；
- 现有每册/每章的职责都与外部主题表对照，缺口、重叠和读者跳转都有处理方案；
- 所有符合独立成章条件的主题都已新增章节/篇章，没有因旧章篇幅、原有章数或改动成本而压回去；
- 检索时间范围、来源限制、分歧和未解决问题已记录；
- 新一轮搜索已不再带来会改变本轮结构决定的重要主题；若仍有这类主题，继续研究或保留为未完成项。

未达到门槛时，只能报告暂定结论和缺失的证据，不能称书册或章节结构已审完。结构审视不要求穷尽所有资料，但要求关键决定都有足以支撑它的外部证据，且未覆盖边界说得清楚。

首次做组织研究时，可从以下资料入手，再按具体书册和学科继续搜索：

- [Diátaxis](https://www.diataxis.fr/start-here/)区分教程、操作指南、参考和解释，适合用来辨认读者任务；它是技术文档框架，不是教材目录模板。
- [CMU 学习目标指南](https://www.cmu.edu/teaching/designteach/syllabus/newcourse/learningobjectives.html)建议把课程结果写成可观察的动作，并让目标、活动和评价对齐；它提供课程设计建议，不证明任一固定章节顺序有效。
- [ACM/IEEE-CS/AAAI 的 CS2023](https://csed.acm.org/wp-content/uploads/2025/11/CS2023-Report.htm)同时整理知识范围和能力结果，并讨论核心/深入主题、重复知识、先修关系和课程编排；这是计算机学位课程框架，不能直接决定本书系的册数和篇幅。
- [UBC 开放教材设计指南](https://pressbooks.bccampus.ca/openubcpub/chapter/textbook-design-rules-open-ubc/)强调把章节结构作为读者路线呈现；它是教材设计指南，不是对所有书型的效果保证。
- O’Reilly 的[《Learning Python》第六版序言](https://www.oreilly.com/library/view/learning-python-6th/9781098171292/preface01.html)和[目录](https://www.oreilly.com/library/view/learning-python-6th/9781098171292/)可作为一部技术教材如何说明读者、用途和章节安排的实际样本；单本书只说明一种设计选择。
- 美国国家科学院《How People Learn》[第二章](https://nap.nationalacademies.org/resource/hpl/Chapter2.pdf)讨论学科教学知识、学习者先备和典型理解路径，可帮助提出教学组织问题；它不是大模型教材的直接试验。
- [Cochrane 检索指南](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-04)和 [PRISMA-S](https://pmc.ncbi.nlm.nih.gov/articles/PMC8270366/)可借鉴迭代检索、追查关键引用以及记录检索日期和完整检索式的方法。它们面向系统综述；本规范只借用透明、可追溯的做法，不要求把每次书册审视做成系统综述。

以上资料分别提供框架、建议、研究背景或个案。它们只帮助提出问题和比较选择；书册/章节定位还必须建立在与本书读者和学科主题直接相关的外部资料上。

### 5.2 证据类型与结论范围

| 资料类型 | 可以支持 | 不能单独支持 |
| --- | --- | --- |
| 论文或技术报告 | 方法定义、论文实验设置、作者报告的结论和局限 | 当前线上接口行为或普遍生产性能 |
| 官方文档、模型卡、发布说明 | 公开能力、参数、配置和产品说明 | 未披露的训练细节或内部机制 |
| 教材序言、目录、样章及教学/内容设计指南 | 作品的实际组织选择或指南明确提出的建议 | 某种编排对所有读者都有效，或指南建议已被因果研究证实 |
| 课程框架或能力模型 | 某领域建议覆盖的能力范围、核心与选修层次 | 对本书系读者、岗位或篇幅的自动适配 |
| 学习研究与综述 | 指定读者、材料和任务中的学习效果或限制 | 脱离研究条件后对所有书型、学科和读者的普遍效果 |
| 固定 revision 的源码 | 指定版本的实现路径 | 所有版本或生产部署结果 |
| benchmark 与 harness | 指定任务、环境、工具和评分口径下的结果 | 裸模型的一般能力 |
| 本地实验或教学代码 | 当前代码、环境和输入下的观察 | 论文、模型或生产复现 |
| 社区文章、榜单和社交信息 | 候选方向、观察信号和问题线索 | 未经交叉验证的确定事实 |

重要判断尽量交叉核验。记录来源之间的分歧、无法访问的资料和未解决的问题；证据不足时降低确定性、缩窄正文结论或标为待核验。不得从一个模型、配置、effort、provider、harness、数据集或环境外推至整个模型家族或所有生产场景。

### 5.3 引用和研究记录

关键事实的引用应贴近结论，链接尽量直达论文版本、官方页面、固定 revision、release 或具体 benchmark 记录。引用必须支持所在句子的实际含义；正文还要说清这条证据为什么与当前问题有关、它支持到什么范围，不能让读者从一串引用里自行拼结论。对联网搜索发现的新知识点，`research/` 保存完整来源、日期或版本、证据范围、分歧和待核验项，正文保留读者追溯所需的入口，不堆资料清单代替解释。书籍审阅结论和修改过程只记在 `progress/`。

涉及数字时同时核对指标定义、分母、数据集、配置、硬件、测量条件和时间。只有条件足够接近时才做数值横向比较，否则解释不可比因素。教学例子可以使用自行构造的小数据，但须标明这是示例输入或假设值；论文、产品或生产环境的实测数字必须有来源和条件，不能把玩具例子的结果写成经验事实。闭源模型要区分官方披露、外部测评、实现推断和社区猜测。
