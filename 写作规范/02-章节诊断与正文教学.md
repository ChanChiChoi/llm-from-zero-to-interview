# 章节诊断与正文教学

> 本文件是《项目写作规范》的正式细则模块。原规范章节编号保留，供跨模块引用；本模块与总纲共同构成完整规范。

## 3. 诊断与处置：发现问题后怎样改

| 发现的问题 | 应采取的处理 |
| --- | --- |
| 为定骨架先通读全书，导致上下文堆积、结构失焦 | 依第 2.1 节先定位、扫描、定骨架；仅覆盖难判时抽查，后逐章处理并以进度续接 |
| 本册价值不清或与邻册重叠 | 重定契约、主题边界和交接，校准简介、目录、正文 |
| 目录只是名词清单 | 按读者问题、前置依赖、能力递进排序，标主线、选读和阶段收束 |
| 只修旧目录，可能漏掉新方向 | 依定位作册级扫描，按证据、成熟度、价值决定增章、并入、列选读、转交或暂缓；记范围和理由 |
| 只修现有小节，可能漏掉新讲次/子主题 | 依本章问题/边界定向扫描，决定增讲、并入、链接或暂缓；记范围、来源、理由 |
| 同一文件内各节各讲各的 | 先定上位问题；有共同主线则补因果、依赖、过渡，无共同主线则拆分或迁移 |
| 单篇冗长而结论不明 | 提炼中心问题与论证链，去重删枝并重排 |
| 核心主题仅列定义、优缺点或清单 | 依第 4.1、4.3 节补问题、前人局限、机制、推演、证据、边界、演进；清单/外链不算主讲 |
| 知结论却不会推算 | 依第 4.1 节补可复算输入、步骤、中间量和解释；代码不代手算 |
| 讲次过短或像摘要 | 依第 3.3 节达篇幅下限，再按第 4.1 节补动机、前置、推演、例子、边界、承接；勿凑字 |
| 初学者或专家一端跟不上 | 依第 4.2 节，在同一解释链中补初学者铺垫与适用的专家深度 |
| 篇幅多而啰嗦重复 | 删重复定义、空泛过渡、无结论总结；保留机制、证据、例子 |
| 复杂关系只靠长文说明 | 依第 6.1 节选图表，并解释读法、条件和结论 |
| 旧知识重组后无处可寻 | 去向表记修正、合并、迁移后的新位置；暂不展开者留准确入口 |
| 结论缺证或来源冲突 | 依第 5.2 节收窄结论、注明条件/证据等级或标待核验；勿猜补空白 |

### 3.1 选择内容深度，避免词典化

整理旧稿时不能把“出现过”当作“覆盖过”，也不能把所有旧内容同等扩写。结合本册契约和资料证据，把候选内容分为：

- **核心问题**：理解本册主题不可缺少，或对目标读者、方法实践和关键判断有持续价值。应完整解释适用的机制、例子、边界和验证。
- **支持内容**：用于补背景、建立前置关系或对比方法，可简明说明，并链接到完整主讲位置。
- **延伸内容**：与主线相关但不值得在本册完整展开。保留准确定位和可到达的延伸入口；必要时说明未展开的范围。

重要性根据书册目标、前置依赖、代表性研究、官方实现、工程与评测问题共同判断。目录旧标题、单篇资料提及或搜索热度本身不能证明它应当成为核心。对核心问题的取舍和旧内容去向要留维护记录，读者入口不能因重组而消失。

### 3.2 让单篇和小节形成一条解释链

一篇一中心问题。解释链通常为：问题/场景 → 旧法局限 → 新法假设与机制 → 具体运行/推演 → 收益、代价、失效条件 → 评估/迁移；顺序可调整，节间须有因果、依赖、对比或递进关系。

各节须贡献于主问题：起首点明本节所解，段间说明概念/状态如何推进，结尾收束结论并引出后文。技术谱系须交代方法的继承或替代，不按年份列名。

### 3.3 篇幅、拆分与阅读节奏

正文勿摘要化，亦勿以篇幅代深度。知识讲解单元解释性正文下限：**核心单元不少于 1,800 汉字；独立辅助单元不少于 1,000 汉字。** 下限非目标或上限；篇幅随讲清机制所需的背景、推演、例子、证据和比较而定，不设封顶。章节过长则去重、重排或拆分，不删理解所需解释。

按读者可独立学习的单元计数：单篇文件按整篇；编号讲次逐讲；连续论证的小标题不单列，目录独立篇目或实际承担完整教学任务的标题单列。核心机制、算法或方法属于核心单元；辅助单元仅用于有边界的前置、局部比较或过渡，不能以改名规避下限。目录、索引、术语表、题单等不适用；若实际承担完整主讲，仍按讲解单元验收。

仅计连贯中文解释性文字；标题、代码、表格/图示、公式、引用清单、状态标记和空白不计，其解释文字计入。可脚本统计，但 `progress/` 须逐单元记实计汉字数、类型和下限，质量仍由人工判断。低于下限不得标完成，不能以内容简单、前文提过或求简洁为由豁免；不承担完整讲解的内容须链接主讲位置。

达标非充分。勿以重复定义、空泛过渡、同义复述或无关旁支凑数；须补足机制所需的因果、中间步骤、例子和边界。主线重复或内容过载，先重组、去重、合并或拆分，再保留完整解释。

同问题、同论证链的小节可重排去重后保留一篇；若分别回答独立问题、采用不同机制或例子，且阅读顺序有别，宜拆分。拆后明确入口、顺序、依赖，并更新目录和交叉引用。每个重要知识点仅设一处完整主讲，余处简述并链接。


## 4. 正文教学标准

### 4.1 解释要完整，不要靠堆点制造深度

重要知识点应让读者沿着输入或问题推到机制结果，并能判断结论在哪里成立。按主题适用部分说明：

1. 讨论对象、输入、状态、接口或系统边界；
2. 要解决的具体约束和旧办法的不足；
3. 核心机制、必要假设、公式或状态变化；
4. 一个具体、可复算的数值例子：给出输入值及含义，逐步代入公式或算法，列出关键中间量和结果，再解释结果对应的机制；
5. 收益、成本、适用条件、失败模式和可观测信号；
6. 评测、排障、工程决策或面试迁移；
7. 来源证据和仍未知的范围。

七项按主题取用，不必每节齐备；但每篇知识/方法正文均须至少给一组可复算数例。须列明输入、变量含义与单位，逐步计算关键中间量和结果，并解释其机制；数值宜易算，近似/舍入须注明精度。代码不得代替手算。系统类可走完一组请求、张量、预算或状态的数据流；算法类可手算小向量、样本或矩阵的一轮。若无有意义的算术过程，须说明原因，并以含具体输入、状态变化和可观察结果的逐步案例替代；不得泛称“主题偏概念”。系统内容还须说明组件、状态所有权、数据流或请求生命周期；算法内容须说明关键变量、步骤、目标和约束。证据不支持的细节须缩窄结论或标未知，不得把设计假设写成行业事实。

七项须融入一条读者可跟随的讲解链，不可拆作七个结论标题：由问题/直觉切入，补足前置，解释因果；数例后回扣机制与成立条件，再引出后文。关键术语首次出现须释义，影响理解的推导不得跳步；摘要、清单、表格、代码和链接均不能替代解释链。

### 4.2 让初学者和专家沿同一主线深入

初学者须读懂背景、必要术语、因果与关键步骤，并循例理解机制；专家沿同一问题和机制继续读到假设、实现差异、证据条件、代表方案比较、工程取舍、失败模式及评测。深入内容须承接前文概念、变量和例子，说明其如何加深或限定前述结论；勿骤堆术语或略去关键推理。方案比较至少说明各自的问题/约束、机制、证据支持的收益、代价、适用场景和失效条件；数据不可比须说明原因。按本篇核心问题取舍，不要求每个知识点面面俱到。

达到第 3.3 节的篇幅下限只是避免过度压缩的必要门槛，不代表深度合格。深度来自可推演的机制和能核验的证据，不来自术语数量、引用数量、公式密度或单纯增加篇幅。面试回答要从问题约束推导方案，不写成脱离条件的口号或优缺点背诵。

### 4.3 问题驱动的技术谱系

核心问题与重要技术主题须沿问题演进娓娓道来：问题缘何而生；前人解决何题、受限何处；新法改变何种机制/约束；后续如何继承/弥补；当前仍有哪些未解问题。择代表方案比较其思路、证据支持的收益/代价、适用场景与失效边界；须讲清因果，不可只按年份罗列。每个术语或支持项不必展开成技术史，可简述并链接主讲。区分论文算法、框架接口、产品行为与生产架构；不可比的分数、接口描述、单次实验不得并列为同一结论。改进方向须注明是来源方案还是证据推论；未经验证者不得写成行业共识。



## 附录 A：不同内容类型的结构参考

以下是按内容类型选择的参考项，不是要求每篇正文都机械采用相同目录。

| 内容类型 | 应覆盖的主要问题 |
| --- | --- |
| 普通技术章节 | 本篇问题与目标、背景和动机、核心机制、必要公式或状态、至少一个可复算的数值例子、适合时与该例共用输入的代码、方案对照、工程边界、失败与评测、延伸练习 |
| 实战或事故排查 | 现象、假设、排查顺序、日志指标、最小复现、修复、回归验证和复发预防 |
| 项目章节 | 项目目标、技术栈、数据、结构、核心实现、实验指标、结果、复现条件、常见故障、面试表达和扩展方向 |
| 论文解读 | 论文问题、前人局限、方法、关键公式、实验设计、作者结论、限制、复现要点和后续影响 |
| 百科条目 | 定义、直觉、问题来源、结构、场景、限制、误区、相关概念和独立正文入口 |
| 模型或前沿更新 | 精确名称、来源类型、版本时间、公开能力、资料增量、证据边界、生命周期和未验证项 |
