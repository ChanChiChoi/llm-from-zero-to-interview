# 写作规范：恢复与任务路由

本页用于会话恢复和任务分流，不替代规范正文、书稿或 `progress/` 交接记录。先确定任务改变的是书册结构、章节结构、正文内容还是呈现/维护，再读取对应文件。

## 恢复顺序

1. 读取本页和相关 `progress/` 交接记录。
2. 按任务路由读取完整的相关规范章节，并读取对应书册的有效总纲、大纲及相关研究入口；跨模块或范围不清时，读取规范总纲和所有涉及模块。本文中的“规范总纲”是本目录的 `总纲.md`，“书册总纲”是各册设计子目录中的 `总纲.md`。
3. 按相应模块研究、修改、验证并记录。摘要不能代替需要核对的规范或进度原文。

若用户明确要求不读取既有 `progress/`，遵守该要求，并按可用材料独立完成本轮工作。

## 任务路由

| 任务 | 必读与顺序 |
| --- | --- |
| 新知识扩充 | [新知识扩充](新知识扩充.md) → 03 研究核验 → 对照各册现行 01/02a/正文及配套资料 → 按影响依次执行 01、02a、02 → 05 验收；研究证据写 `research/`，书系映射和执行状态写 `progress/` |
| 整册/全书架构或跨册分工 | 01 → 03 册级研究 → 01 产出定位总纲（不含目录）→ 03 结构研究 → 02a 产出目录与各章大纲（涉及结构时）→ 02 正文（涉及实质改写时）→ 04（涉及图表、公式或代码时）→ 05 |
| 新建或修正全册/局部章节大纲 | 02a → 书册总纲 → 03 结构研究 → 产出目录、标题及中心思想 → 05；修正模式须完整读取涉及的当前章节，整册修正逐章读取。影响书册定位时返回 01 |
| 已定结构章节的实质正文写作/修订 | 02 → 有效书册总纲与 02a 章节大纲 → 03 知识、讲法与实践研究 → 正文；涉及图表、公式、代码时读 04；交付读 05。无需重新执行未改变的 01、02a 设计流程 |
| 只改错字、格式或不改语义的局部表达 | 对应模块；通常可免新研究。若同时属于整册/结构审视，仍执行上游流程 |
| 只处理图表、公式、代码或引用 | 04；若同时改变正文解释，增加 02；交付同步读 05 |
| 配套资料、记录、交接与验收 | 05；内容/事实有变化时再读对应模块和 03 |

涉及书册定位、章节结构、知识或讲解意图与读者目标修正的实质工作都须按模块 03 联网研究，局部段落修改也不例外。书册级研究关注领域和书型组织，章级结构研究关注主题、依赖和教学组织，正文研究关注事实、机制、效果及知识缺口。仅不改变知识含义、适用条件和讲解意图的语句润色、错字及格式/显示修复可免新检索；公式含义变化仍须联网核验。

## 恢复后必须保留的分工

- **01 管整册定位**：从整册角度规划知识版图、范围、深度和跨册承接，产出书册总纲，不编目录。内容维度表供按需展开总纲，不要求每册填满。
- **02a 管组织结构**：新建时基于总纲研究；修正时基于总纲及当前章节研究。产出完整标题层级与各部分一段中心思想、知识范围说明，在适当处提供经研究确认的术语、机制和关系作为后续检索抓手；不规定正文教学锚点、讲解步骤或正文脚本。充分挖掘章内层次，优先有依据的聚焦细分，不默认四至六节。
- **02 管正文讲解**：围绕小节中心思想扩展知识、选择锚点并讲清机制。主题推翻重写不参考旧正文；主题思想不变重写可以参考旧稿并重新组织，是常规精修默认方式；打补丁只修限定局部。首次写作按从头写作流程执行。
- **小白理解是正文底线**：复杂算法必须有机制全貌与可追踪的具体执行，不能以公式和符号释义代替。锚点形式可选，理解不能省略；公式用于准确表达与升华。按本册深度形成与企业面试官讨论机制、场景、失败与成本收益的能力。
- **研究兼顾事实、讲法与实践**：两种重写都须本轮联网，主动查论文、官方资料、高质量博客、笔记、notes、讲义及行业经验，不能只模仿论文叙述；实践与效果主张保留条件和证据边界。
- **按阶段验收**：01 总纲完成、02a 大纲完成、02 正文完成与整册实施完成分别判断。公式按 05 逐式检查并验证应交付平台的实际渲染，不能以源码检查冒充渲染通过。
