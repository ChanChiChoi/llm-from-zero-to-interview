# 第八部分：Reasoning Model 与 Test-Time Compute

本部分讨论推理时额外计算何时值得花：先把中间步骤作为可检查状态，再比较多路径采样、验证、搜索和训练时过程监督，进而检查数学、代码、自我改进与基准评估。最终把模型行为、运行时预算和产品约束放在一起判断。

## 讲次大纲

### 第 87 节：Chain-of-Thought——把隐式求解变成可检查的中间状态

解释显式推理轨迹的用途和局限，区分可读步骤、真实求解过程和最终正确性。

### 第 88 节：Self-Consistency——用多条推理路径近似答案分布

从多次采样与答案聚合推导 self-consistency，核算成功率、调用数和答案相关性。

### 第 89 节：Verifier、ORM 与 PRM——把生成和评价拆成两个可测量模块

比较 outcome 与 process verifier 的信号及训练代价，检查验证器偏差和 reward hacking。

### 第 90 节：Search、Tree-of-Thought 与 MCTS——把推理组织成有预算的探索

把生成空间组织为搜索树，说明分支、估值、剪枝与预算分配如何影响结果。

### 第 91 节：Test-Time Compute Scaling——把有限推理预算分给最值得计算的请求

分析推理计算与准确率、延迟和成本的关系，区分论文曲线与服务策略。

### 第 92 节：数学推理训练——把题解、过程监督和验证闭合起来

比较答案监督、过程监督和可验证奖励，建立数学能力与评测器的对应关系。

### 第 93 节：代码推理与执行反馈——让程序结果参与求解

把生成、执行、观察错误和修订连接起来，说明沙箱、测试覆盖和执行反馈边界。

### 第 94 节：自我改进与合成推理数据——从一次求解走向数据闭环

追踪候选生成、验证、筛选和再训练，检查合成数据污染和闭环偏差。

### 第 95 节：Reasoning Model 评估——从一个分数扩展到能力剖面

按任务难度、工具、采样预算、长尾错误和成本切分推理评估，防止总分掩盖退化。

### 第 96 节：从 Chat Model 到 Reasoning Model——把训练、运行时和产品合在一起

综合训练信号、推理时预算和产品交互，形成模型选择、路由和发布判断。
