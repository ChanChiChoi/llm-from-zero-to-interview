# 第 60 章 读懂新架构主张：信息路径、资源变化与证据边界

本章承接第五十一至五十九章的历史模型谱系，转向读者面对新模型发布和架构论文时会遇到的判断问题。中心认识是：名称相近的“创新”可能改的是不同对象——注意力历史的表示、每 token 激活的参数、递归状态、外部检索记忆，或模型与环境交互的闭环；必须先定位变化，再问机制预言什么资源和任务表现，最后检查来源与实验究竟支持哪一层结论。章节不重新比较全部序列架构家族（第四十二章）、不推测唯一未来赢家（第五十章），也不复制历史案例矩阵（第五十九章）或其他册的 serving/Agent 操作手册。

## 60.1 从时间线读变化，而不是追代际标签

本节将上一章的历史案例综合转成阅读新主张的起点：先固定所讨论的模型、版本与组件，再把报告中的结构、训练、执行实现和外部系统能力拆开。所谓“新一代”不能代替对象和版本，也不能从产品能力倒推出未披露的模型内部结构。本节连接第二十一册的[模型创新时间线](../../../book-21-transformer-architecture-evolution/主流大模型架构创新时间线.md)及第五十九章，不复述其模型历史条目。

### 60.1.1 固定对象：家族名称、模型版本与具体 checkpoint

模型家族名称可能覆盖多个规模、训练阶段、模态和发布版本；论文修订、模型卡、公开配置和托管接口也可能描述不同对象。本节说明分析架构主张时要让模型身份与资料版本可追溯，明确引用的是某个 checkpoint、某个技术报告版本还是某个 API 行为，避免把同名系列中的差异合并为一套结构。

### 60.1.2 区分模型结构、训练变化、执行实现与外部系统

架构 block、训练目标/数据、kernel/权重布局、检索库/Agent 工具环分别位于不同层。以 DeepSeek-V2 的 MLA 和 DeepSeekMoE、R1 的后训练、FlashAttention 的执行算法、RETRO 的外部检索及 ReAct 的 action-observation 交互为对照，说明它们都可能改善模型使用结果，却不能被统称为一种 backbone 更新；完整算法仍由相应章节和书册主讲。

## 60.2 把“新架构”主张拆成可检验的结构变化

本节把宣传式标签还原为一条可以核验的因果链：哪一个结构对象被改写、它改变了什么表示或运算、希望改善什么瓶颈、同时引入什么新成本，以及这些后果能在哪一类观测中出现。主张若缺少这几个联系，就还只是名称或结果描述，不能据此断定架构机制。

### 60.2.1 找到改变的对象、运算和状态

沿着模型计算路径查看新机制改变的是 attention 的历史读写、FFN 的条件路由、逐 token 的递归状态、隐藏层之间的信息交换，还是模型外的索引和动作循环。尤其要区分“读到压缩后的历史表示”“重新计算某批权重”和“从外部数据库取回原文”；这些操作看起来都像记忆，但对象、可寻址方式与可验证的失败模式不同。

### 60.2.2 从机制推出预期收益和新增代价

每个结构变化都应给出与机制相连的预测，而非从模型总分倒推原因。例如 latent KV 可能减少每 token 缓存状态，却增加投影/重建或改变张量并行行为；稀疏专家减少选中计算路径的 FFN 工作，但不自动移除未激活权重及其路由/通信；递归压缩可使显式历史状态不随输入长度同速增长，却把可用信息交给有限状态的更新与读取过程。预测先作为待测假设，不能替代实测。

## 60.3 多种架构方向改变的是不同信息路径

本节用本册已有历史和前沿案例说明几个常见名称并非相互替代的同一类结构：有的改变历史怎样缓存，有的改变参数怎样被选中，有的改变历史如何递归保存在状态中，有的增加模型外部的证据通道或交互闭环。比较时要对齐各自处理的信息对象和变化层级，而不是把 MLA、MoE、SSM、retrieval 和 Agent 排成一条“谁替代谁”的路线。

### 60.3.1 MLA 改变注意力历史的缓存表示

DeepSeek-V2 的 Multi-head Latent Attention 将键和值的历史信息压缩到共享 latent 表示用于缓存，并保留位置相关路径；它针对的是显式 KV 状态的表示与读取成本，不等同于减少模型全部权重或消除 attention。作者报告中的 KV-cache 降幅和生成吞吐绑定该模型与 DeepSeek-67B 对照，且 MLA 与 DeepSeekMoE 等变化同时出现；本节据此界定主张层级，不重讲 MLA 推导。

### 60.3.2 MoE 改变每个 token 激活的参数子集

MoE 路由器根据 token 表示选择一个或多个专家 FFN，使总参数容量与单 token 专家计算成为不同数值。分析“稀疏更高效”时，不能把 active parameters 当作驻留权重、路由开销、跨设备通信或端到端时延的同义词；Switch Transformer、Mixtral 与 DeepSeekMoE 说明稀疏激活是一类计算分配机制，其成本受路由和系统实现条件影响。

### 60.3.3 SSM 与递归注意力改变历史进入状态的方式

Mamba 通过输入相关的状态更新选择保留、写入和衰减信息；KDA、Gated DeltaNet 等路线继续改变递归状态更新。固定状态量不能直接推出任务层的记忆充分或不足：Mamba 及其 hybrid 在 copying、RULER、长上下文问答等任务上的结果随任务构造和提示不同，2026 年针对 positional recall 的研究进一步将早期/近期保留与中段信息转移瓶颈拆开。本节据此说明状态结构主张需要配相应的信息保留任务。

### 60.3.4 内部神经记忆与外部检索提供不同的历史访问路径

RETRO 把从外部语料检索的文本块接入语言模型；Titans 提出在推理过程中更新的神经长期记忆，并实验不同接入位置。两者都可被称为 memory，却分别依赖外部数据库检索和模型内可更新状态。比较时要标明记忆保存在哪里、由谁更新、查询返回原文还是压缩表示，以及结果是否受外部语料版本影响；第45、46章继续负责各路线机制。

### 60.3.5 Agent action-observation loop 不等于新的模型主干

ReAct 将语言模型的推理、动作和环境观察交织成任务轨迹，系统因此可以经工具获得模型上下文中原本没有的信息。该行为闭环依赖模型之外的动作空间和环境反馈；它本身不能证明 backbone 新增了特定 attention、MoE 或递归状态。引用此类结果时应把模型能力与完整交互配置分开，Agent runtime 和方法分别回到第十七、二十册及本册第四十九章。

## 60.4 从结构变化推到资源预测与任务风险

本节把“架构导致更快、更省、更能记”分解成可分别检查的后果。读者将结构变化对应到状态形状、参数激活、计算工作、数据移动、通信或外部查询，再用能暴露相应失效模式的任务检查能力；复杂度只生成预测，是否形成测得的质量和系统收益仍取决于完整模型、任务和实现。

### 60.4.1 让资源指标对应被改变的对象

缓存压缩应量缓存字节和读取带宽；MoE 应分开总权重、激活参数、token dispatch 和 expert 通信；递归状态应分开每步更新与训练 scan、状态容量及任务表现；外部 retrieval 应把索引存储和检索路径与 backbone 计算区分。训练、prefill、decode、存储和系统开销不可用一个 FLOPs 或参数量数字互换。

### 60.4.2 用压力任务检验机制可能丢失什么

测试应匹配结构主张暴露出的能力边界：KV/latent 压缩看细节回读与不同位置的证据；有限递归状态看长跨度精确复制、关联回忆和干扰下的信息选择；稀疏路由看 token 分布变化及任务覆盖；检索看证据是否被找回并正确使用；Agent 闭环看动作与观察的贡献能否和模型输出分离。单项合成任务只支持这一任务构造下的观察，不代表通用能力。

## 60.5 让证据强度与主张范围相称

本节说明不同资料类型各自能回答什么，以及如何从架构事实走到效果结论。论文与报告可公开方法、版本和作者实验；模型配置/固定 revision 可支撑指定实现事实；行为评测只能说明任务条件下的输出，不能揭示隐藏拓扑；kernel 或系统测试回答指定实现与硬件问题。重要的是主张和来源直接对齐，而非把来源分成脱离问题的抽象等级。

### 60.5.1 公开报告、配置、实现和行为结果各自支持什么

以明确发表的架构图/公式、模型卡与配置字段、固定版本代码、任务级评测和硬件测量为例，分别说明它们能够支持的结构/实现/行为/性能事实及不能单独支撑的外推。闭源模型若只公开 API 与外部评测，可以陈述接口和观测到的行为，但 Dense/MoE、attention 路线、训练配方等未公开字段仍是未知。

### 60.5.2 用 matched baseline 和消融限制因果归因

当模型同时改变规模、数据、目标、结构和训练阶段时，整体分数不能单独归因于其中一项。对照实验需对齐有意义的训练预算、数据、任务格式、参数/计算口径和实现条件，并用消融区分组件贡献。Waleffe 等人在最高 8B、3.5T token 的 Mamba/Mamba-2/Transformer 实验中发现结果按 RULER、自然多文档 QA、Phonebook 等任务变化，说明“同一架构谁胜出”也必须写出具体任务与对照。

### 60.5.3 把已披露、观察、推断和未知分开写

结论表述应区分报告直接披露的结构事实、实验中观察到的任务结果、由机制作出的条件推断和资料没有回答的未知项。例如，公开模型标明了 latent cache 可作为结构事实；发布方报告的成本结果是其配置下的观察；将这项结果推广到其他硬件属于待验证推断。未知不是缺少专业判断，而是约束判断范围的有效结论。

## 60.6 对下一代架构作有限而可更新的判断

本节回到本册中心问题，整理时间线和当前证据可以支持的未来判断，并把可复核的表达方式交给读者。已经出现的设计说明多个信息路径都在发展和组合，不足以证明一种结构将取代其余路线；预测需要标记为推论，说明变化条件，并留出新实验推翻它的可能。

### 60.6.1 时间线显示多条演进轴并行，而非一个必然继任者

历史模型中 MLA、MoE、后训练和多模态披露各自改变不同层；当前 SSM、memory、retrieval 和 hybrid 工作也围绕不同约束提出方案。由此可支持“设计空间仍在展开”的有限判断，不能把第50章讨论的组合趋势或某个近期模型发布升级为架构代际结论。第61—95章的专题将逐项分析新机制及固定版本证据。

### 60.6.2 用一段话说清主张、机制、条件与证据边界

成熟的架构判断应把对象/版本、结构变化、要解决的瓶颈、测到的任务与资源结果、对照条件以及未知项放在同一条推理线上，并区分事实和推断。读者据此可以回答“这项技术改了什么、适合什么问题、证据还缺什么”，而非机械复述一张模型审计表或给出无条件的采用结论。
