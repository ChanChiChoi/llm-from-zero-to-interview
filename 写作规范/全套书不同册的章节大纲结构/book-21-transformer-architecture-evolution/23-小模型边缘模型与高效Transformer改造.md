# 第二十三章：小模型、边缘模型与高效 Transformer 改造

## 章节契约

- **前置：** 已理解 Transformer block、参数/激活路径、KV cache、局部注意力、MoE 和 attention 替代路线；必要时回看本册第 4、11、19—22、24 章，以及第五册的训练与权重成本口径。
- **离章结果：** 能区分“小参数量”“适合端侧”和“在特定任务/设备上高效”；能解释不同架构、训练和压缩改动分别影响什么计算、状态或存储账本；能判断公开结果支持的是模型能力、设备性能还是某个系统实现，并据任务质量与目标硬件限制结论范围。
- **本章职责：** 把小模型设计和边缘设备约束放在同一个架构视角下，说明有限参数预算如何分配、不同改造作用于哪些资源，以及硬件/实现条件如何决定理论收益能否兑现。
- **边界：** 第 21—22 章负责 MoE 路由和 Dense/MoE 成本比较；第 11、19、20、24 章分别主讲 KV cache、经典稀疏 attention、attention kernel 与线性 attention；第五册负责训练、蒸馏与训练成本，第六册负责部署和量化/压缩实践，第二十四册负责推理引擎、runtime 和系统压测。本章只建立这些改动与端侧成本的关系，不重讲其机制教程或提供发布 gate。
- **研究依据：** 旧稿 23 个 H2 将模型质量来源、结构选项、量化、端侧运行、预算算例、通用验收和回退流程多次重复；部分内容与前后章节及训练/serving 书册重叠。独立研究显示，小模型设计需要同时对齐参数预算、任务质量、目标设备和执行栈；证据边界见[小模型与边缘 Transformer 设计研究记录](../../../research/small-models-edge-transformer-design-2026-11-20.md)。

## 正文编号大纲

### 23.1 小模型、边缘模型与高效分别回答什么问题

本节围绕“有限资源下达到什么任务结果”界定小模型、边缘执行和效率评价的关系。参数量与文件大小不等同于运行时峰值内存、每 token 计算、延迟或能耗；本地离线、隐私和网络可用性是部署约束或收益，也不能替代任务质量。比较之前需要明确目标任务、输入/输出长度、质量门槛、设备资源和要优化的指标，并说明这些指标之间可能冲突。

### 23.2 小模型如何利用有限参数预算

本节说明小模型不是把大模型按比例缩小：层数与宽度、层间参数分配、嵌入/块权重共享、注意力头配置等会改变给定参数预算的表达与执行方式；数据质量、token 配比、训练阶段和后训练也会影响目标任务能力。MobileLLM、OpenELM 与 SmolLM2 等工作分别提供小模型结构选择与数据设计的具体案例，但结论绑定各自模型、训练和评测条件，不构成通用配方，也不单独证明目标设备上的速度优势。

### 23.3 改造选项分别改变哪些计算、状态或信息路径

本节将结构改造与权重压缩、训练方法和输入压缩区分开来，说明它们作用于不同资源：GQA/MQA 改变 KV heads 与缓存读取；局部/稀疏或线性 attention 改变 token 间交互或历史状态；FFN 宽度/共享和 MoE 改变参数分配与 expert 计算；量化改变数值表示，剪枝/低秩改变权重结构，蒸馏改变 student 学到的函数，token/patch 压缩则减少输入序列但可能丢失细节。详细机制由对应章节主讲，本节只澄清每类改造能节省什么、仍可能留下什么成本及其主要风险。

### 23.4 目标设备的内存层次和执行栈决定收益

本节围绕权重从存储到计算单元的路径，解释权重驻留、缓存、带宽、数据搬运、算子支持、批量形态和温度/功耗状态如何改变模型选择。参数共享可能减少权重移动却增加重复计算；把权重放在较慢存储层或按需载入能减少某类驻留压力，却可能增加传输延迟；低比特和稀疏结构只有在目标执行栈能有效处理时才可能转化为端到端收益。Gemma 3n 的参数缓存/嵌套模型，以及 MobileMoE 的手机端自定义 MoE 执行作为不同的公开案例，其效果均须限制在文档或论文的具体机制与测试条件内。

### 23.5 用与任务和设备相匹配的证据比较改造

本节说明如何区分能力证据、架构消融和真实设备 profile。有效比较需固定或明确任务质量、模型与 tokenizer 版本、权重格式、上下文/输出负载、硬件、runtime/kernel 和测量方法；同时分别报告权重文件、峰值运行内存、prefill 与 decode、能耗或热稳态等与目标有关的结果。跨设备或跨论文的单项速度数字不能隔离结构本身的贡献。结论应回答指定任务和设备上的具体约束，而不建立通用“小模型排名”或部署验收清单。
