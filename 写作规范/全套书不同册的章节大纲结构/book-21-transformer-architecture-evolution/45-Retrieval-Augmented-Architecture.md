# 第四十五章：Retrieval-Augmented Architecture：把外部检索变成架构组件

本章围绕模型如何从自身参数和当前请求上下文之外，按需读取外部语料中的证据，说明检索路径与生成器的不同接入方式、信息流、失效点和评估边界。读者应能追踪一次检索增强回答从语料、检索与证据组装到生成和引用的完整路径，并辨别问题发生在语料、检索、上下文构造还是生成阶段。长距离上下文中的证据读取由第十三章讨论；模型内部的卷积、SSM 与 Attention 信息路径由第四十四章讨论；跨请求的记忆读写由第四十六章展开；由 Agent 决定调用搜索工具和多轮探索由第四十九章展开。

## 45.1 参数记忆、请求上下文与外部语料处在不同位置

本节区分模型参数中隐式形成的知识、请求中显式提供的上下文和模型外可查询的语料。检索增强架构的关键是给生成过程增加一条按请求选择外部证据的路径；它能否提供新内容取决于语料和索引是否更新，不能仅凭存在检索模块推断证据新鲜、完整或回答正确。

## 45.2 一次检索增强回答怎样流过系统

本节组织离线语料准备与在线请求两条衔接的数据流：文档被解析、分段并建立可查索引；请求到达后，检索器为查询找候选片段，选择与整理阶段将证据及来源信息交给生成器，生成器再据此形成回答。内容说明语料、索引、检索器、证据上下文和生成器各自提供什么，不把某种向量数据库、分段算法或重排器当作所有架构的必要组件。

## 45.3 检索结果在提示边界接入生成器

本节说明一种应用层接入方式：系统保留现成生成模型，在请求时把检索到的片段与用户问题共同组成模型输入。生成器收到的证据由检索和上下文构造共同决定；外部片段可以被模型利用，却不强制模型忠实遵循。因此，提示中放入证据不等于模型已经验证或引用了证据。

## 45.4 检索也可纳入模型训练与层内信息流

本节比较潜在文档建模、检索增强预训练和模型层内交叉注意力等接入方式。RAG-Sequence 与 RAG-Token 在输出序列或 token 粒度使用检索文档；REALM 将学习检索器纳入预训练、微调和推理；RETRO 按序列块检索邻居并通过 chunked cross-attention 接入自回归模型。内容聚焦这些设计如何改变检索器、生成器与外部语料的耦合，不把单篇论文的任务结果推广成通用优势。

## 45.5 固定检索与按需检索改变控制位置

本节区分请求开始时固定检索一组文档，和模型判断当前生成是否需要检索、并检查候选证据与生成内容的方式。Self-RAG 以 retrieval/reflection tokens 展示一种在模型内进行按需检索和自我批评的设计；它代表特定训练路线，并不等同于所有 RAG 系统已有的能力，也不代替 Agentic Search 的工具调用与多轮探索。

## 45.6 错误会沿证据路径传递

本节将失败区分为语料未覆盖或未更新、相关证据未进入候选、证据在排序或上下文组装中丢失，以及生成器误读、忽略或错误引用已提供的内容。每类失效对应不同原因；只看最终回答不能判断检索质量，也不能由检索命中推断回答得到证据支持。

## 45.7 评估要分开检查检索覆盖、生成忠实度和回答质量

本节说明评估需分别关注候选上下文的相关性、回答是否忠实于所给证据、回答是否解决问题，以及声明和引用之间是否存在支持关系。ARES 的 context relevance、answer faithfulness 与 answer relevance，以及 ALCE 的 correctness 和 citation recall/precision，展示了互补评估维度；有 gold evidence 时可将其与实际检索上下文作诊断对照。自动评分及基准结果仍受数据、任务和评审协议约束。

## 45.8 按信息来源与任务控制方式划清架构边界

本节把外部语料的请求时检索与长上下文中直接提供材料、跨请求保存并更新的长期记忆、以及 Agent 主动调用工具进行多轮搜索区分开。讨论选择时关注证据规模与位置、数据更新方式、是否需要跨会话写入状态、是否要由模型决定下一次搜索，而不为 RAG、长上下文或 Agent 搜索建立脱离任务的普遍排名。
