# 第 71 章 Recursive State Cache：递归状态缓存

本章解释递归架构怎样把已读前缀映射为模型内部状态，并在后续 token 到来时更新和读取它。读者需能区分逐位置保留的显式 KV cache 与无 token 地址的递归状态，理解单步递推如何与整段并行扫描、chunkwise 计算并存，判断固定状态的内存收益及信息访问代价。状态边界与连续性属于模型机制；具体状态池、分页、调度、租户隔离和跨设备迁移由 serving 系统章节承担。第 70 章主讲逐 token latent cache 与任务保真，本章不重复其 latent 表示压缩。

## 71.1 从逐 token 的历史地址转向递归状态

本节建立显式历史槽位与递归摘要状态的区别。前者保留每个历史位置的表示供后续 query 定址读取；后者通过状态转移把前缀折叠为一组模型定义的变量。递归状态是对特定任务训练出的内部表示，不是可读文本摘要，也不能仅凭“固定维度”推断它等同于完整历史。

### 71.1.1 显式 KV 为每个位置保留独立槽位

说明 causal self-attention 的 KV cache 如何为过去各位置保存 key/value，并由当前 query 对可见历史逐位置计算权重。重点是“历史位置仍有地址”：模型可对不同位置单独取值，缓存大小随保留位置数增加。对照第 69 章的逐层混合架构与第 70 章的 latent cache，强调压低每个位置的表示宽度仍保留位置轴；递归状态改变的是历史表示方式和访问路径。

### 71.1.2 递归状态将前缀映射为模型内部表示

围绕状态递推的抽象形式，说明模型处理新 token 时由前一状态和当前输入计算新状态，之后输出依赖更新状态及当前 query。历史贡献通过状态更新累积，不再为所有 token 保留独立地址。该表示的维度、结构和保真度取决于具体架构；避免把状态称为一个“压缩后的完整上下文”或自然语言摘要。

## 71.2 状态在每个 token 上怎样更新并产生输出

本节把状态机制拆成状态转移与输出读出两种关系，给出读者可追踪的递归过程。先用通用函数说明状态从何而来，再选 RetNet 作为可显式展开的矩阵例子，最后用 Mamba-2 真实实现提醒读者状态可能是多个不同用途对象的组合，而非每种模型共用一种公式或张量。

### 71.2.1 转移与读出是状态机制的两部分

使用 $s_t=F(s_{t-1},x_t;\theta)$ 和 $y_t=G(s_t,x_t;\theta)$ 归纳递归模型的共同接口：转移决定旧信息怎样保留、衰减、覆盖或更新，读出决定当前表示如何生成模型输出。公式只表达抽象结构，不预设状态是向量、矩阵还是 tuple；须区分模型状态的数学定义、训练参数与运行时存储对象。

### 71.2.2 RetNet 用矩阵状态展示累计、衰减与查询

以 RetNet 的 retention 递推 $S_t=\gamma S_{t-1}+K_t^{\mathsf T}V_t$、$o_t=Q_tS_t$ 说明当前 key/value 如何写入矩阵状态，历史项如何按衰减因子继续影响后续，query 又如何从聚合表示读出结果。通过状态变化关系说明不同 token 的贡献相加在同一矩阵中，且不再保有独立 token 槽位。明确此式是 RetNet retention 的具体结构，不代表所有 SSM、linear attention 或递归状态都满足同一更新。

### 71.2.3 Mamba-2 的状态由 SSM 和记忆卷积窗口共同组成

根据官方仓库 tag v2.2.4 的 Mamba2 实现，说明单 token step 同时推进 causal convolution 的有限窗口 conv_state 和 SSM 的 ssm_state，二者负责不同的历史依赖，且形状由配置决定。此例用于纠正“每层只有一个递归 tensor”的泛化；不得把该 tag 的 API、tensor layout 或更新细节推广成 Mamba 全系或其他框架的必然接口。

## 71.3 递归定义不等于训练必须逐 token 串行

本节解释同一序列模型可以按不同计算形式执行。递归形式揭示因果依赖和逐 token 解码接口；当整段输入已知时，特定递归关系可改写为并行扫描、卷积或块内并行计算。具体等价方式取决于算子结构，不能从一个模型的训练实现推断所有递归模型都具有相同并行形式。

### 71.3.1 递归是依赖关系，不是唯一执行算法

区分“数学上 $s_t$ 依赖 $s_{t-1}$”与“硬件上只能顺序执行”。递归定义是理解更新状态的依据，而实施该映射时可变换计算顺序或并行扫描中间算子。解释自回归生成每次只新增少量 token、因而适合显式递推；训练或 prompt 处理通常一次拿到整段 token，拥有并行或分块执行的机会。

### 71.3.2 并行扫描和整段计算如何利用已知序列

以 Mamba 论文所述 SSM recurrence 与 global convolution / selective scan 为例，指出整段运算可利用已知序列、并行计算多个位置，再通过硬件感知扫描减少中间状态物化。描述限定在论文方法与实现；不把 Mamba v1 的 convolutional training 形式套到选择性参数已依赖输入的所有模块，也不把理论并行度直接等同于速度优势。

### 71.3.3 Chunkwise recurrent 如何连接块内并行与块间状态

以 RetNet 的 chunkwise recurrent 形式说明输入可切成连续片段：块内用并行表示处理多个 token，块间将前一片段形成的状态传给下一片段。交代它解决长序列计算与状态传递之间的组织问题；块长、边界状态与数值等价性依模型定义，训练 chunk、推理 chunk 及系统 batch chunk 不能混为一谈。

## 71.4 固定长度带来什么收益，又改变什么能力

本节把固定大小的存储账本与历史访问信息的改变并列讨论。固定状态消除缓存随上下文长度直接线性扩展的那一维，但仍须为每层、状态通道、精度和并发请求付费；与此同时，递归聚合取消逐 token 的独立地址，具体任务是否保留有用信息必须通过质量评估回答。

### 71.4.1 按上下文长度计算 cache，保留维度与并发账本

比较显式 KV 的逻辑大小 $O(T)$ 与固定宽度递归状态在固定模型配置下对 $T$ 不直接增长的特点。再列出剩余变量：层数、state/head dimension、状态分量数、dtype、卷积窗口和同时驻留的序列数。区分 per-token memory、状态更新 FLOPs、整段 prefill、模型权重与运行时开销；固定状态不意味着总推理成本为常数。

### 71.4.2 无 token 地址后的读取与保真问题

说明递归状态以历史聚合支持后续预测，不像显式 KV 那样允许 query 直接对每个 token 独立寻址。由此提出具体验证问题：需要复制、精确回读、跨很远距离关联或受干扰时，输出质量是否保持；不能将其夸大为“递归模型必然无法记住某项内容”，也不能从状态维度单独证明模型必然丢失某类信息。第 34 章承接 Mamba 的精确检索与 ICL 证据，本章保持架构层解释。

### 71.4.3 以质量、内存和运行条件共同比较

比较递归状态与显式 KV 时，先对齐模型能力/质量目标、层数和宽度、训练数据与预算，再记录上下文长度、batch、dtype、硬件、kernel、prefill/decode 区间及内存统计口径。分别报告准确检索或长程任务质量、状态/KV payload、实际峰值显存、吞吐与延迟；论文中的单一模型结果不能充当跨架构普遍结论。

## 71.5 序列边界与分块决定状态怎样延续

本节聚焦状态随一条序列的开始、连续输入和结束如何变化。初始化和 reset 是模型语义的一部分，决定旧序列信息能否泄漏到新序列；跨块处理则必须传递正确的末状态。这里只讲模型级边界与等价性检查，不把运行时 snapshot、状态租约、迁移与抢占写作通用操作流程。

### 71.5.1 初始化、reset 与 packed sequence 边界

说明模型定义的初始状态、预填充后的状态和结束状态，并讨论将独立样本拼在同一计算批次时必须在边界隔离其递归历史。Mamba 论文的 boundary resetting 是具体例子。区分显式的模型 reset 语义与某个框架提供的 reset API；padding、packed sequence、batch slot 复用须按模型的 mask/segment 与 state-update 实现解释，不能默认增加 padding 就等于处理相同 token。

### 71.5.2 分块处理怎样传递状态并核对一致性

讲明把一段前缀拆成 $A$、$B$ 两段时，处理 $B$ 必须接收处理 $A$ 后的末状态；若每段都重置，计算的是不同序列。可比较整段前向与连续分块结果，对齐 token 边界、初始状态、精度和归一化方式，检查输出与最终状态是否在目标容差内一致。数值差异可能来自浮点执行次序；不得把测试要求变成所有模型都可任意 restore 或迁移的承诺。

## 71.6 数学状态与运行时缓存是两个设计层次

本节厘清模型定义的状态更新与程序为了执行该更新而保存的数据之间的区别。主流接口可以直接存递归张量，但实现也可能使用 checkpoint、输入缓冲或别的等价表示。这个区别有助于审阅 cache 论文和服务实现；通用状态池、内存分页、调度、租户与跨设备状态迁移由推理系统册主讲。

### 71.6.1 同一状态可有不同存储和读取表示

分别定义数学状态 $s_t$（足以继续模型计算的中间表示）与运行时缓存（具体内存中保留的 tensor、输入历史、checkpoint 或组合）。一种实现可以直接写回每步更新后的状态，另一种实现可保留检查点与有限窗口输入，按需要重建状态或直接求当前输出。判断等价性需要核对输出、边界状态、数值精度和适用操作，不能只看变量名是否相同。

### 71.6.2 ReplaySSM：将近期输入放进缓存的限界示例

依据 2026-10-09 的 ReplaySSM v1 预印本，简要说明其针对 Mamba-2 与 Gated DeltaNet 的 checkpoint 加近期输入 buffer 设计，以及在 buffer 满时折叠递推贡献的做法；论文称输出匹配仅在浮点误差意义下成立。此例用于证明实现的缓存布局可以不同于递归方程里的 $S_t$，不将它的性能数字外推至其他模型、框架、硬件、batch 或负载，也不宣称它是通用部署方案。

### 71.6.3 模型状态机制与 serving 生命周期的职责边界

收束到模型架构可回答的问题：状态包含哪些模型内存、怎样更新、何时跨 token/块延续、何时按序列语义初始化或清除。状态池容量、请求路由、租户隔离、snapshot/restore、迁移和抢占属于运行系统实现，应按相应系统章节的具体框架和版本讨论；本章不设通用事务模型或生产 API。
