# 第四十七章：MoE、SSM 与 Attention 的组合设计：架构位置与证据

本章围绕不同组件放在何处、各自改变哪条模型路径，以及现有实验能支持怎样的组合结论展开。Attention 与 SSM 决定序列信息混合方式，MoE 通常扩展条件 FFN 参数路径，也可以进入 SSM 内部投影；因此需要比较具体组合结构，而不是将三者写成三个可直接相加的通用预算。章节以 Jamba、BlackMamba 和 Routing Mamba 为例，辨认 FFN 专家化与 SSM 投影专家化的不同设计，并根据匹配消融判断模块增益和交互证据。

本章承接第二十一章的 MoE 路由、第二十二章的 Dense/MoE 成本、第四十三章的 Attention–SSM 混合结构，以及第四十四章的模块信息路径；这里只回顾读懂组合位置所需的前置，不重新推导各组件。第六、二十四册负责 serving/runtime 成本，第五册负责训练机制，第五、六、十七、二十册负责系统层细节；第四十八章承担多模态架构，第四十九章承担 Agent/runtime，第四十五、四十六章分别承担外部检索和模型记忆。第五十章负责更广的未来架构判断。

## 47.1 Attention/SSM 与 MoE 改变的是不同结构位置

本节先建立比较坐标：Attention 和 SSM 是序列混合路径，分别通过内容相关读取显式历史与递归状态处理序列；MoE 通常把共享 FFN 改为按 token 选择的参数路径，改变条件容量和激活参数。说明“含三种模块”不足以定义一种架构，需继续指出 MoE 是替换 FFN，还是专家化 SSM 投影，以及其所在层与路由范围。

## 47.2 Jamba：在 Attention–Mamba 主干的 MLP 位置加入 MoE

本节以 Jamba 说明三种组件怎样在层级结构中并存：Attention 与 Mamba 层交错，部分层中的 MLP 被 MoE 替换，而 MoE 不等同于替换序列混合器。覆盖论文所用的八层 block、1:7 Attention/Mamba 比例、每隔两层设置 MoE、16 个专家与每 token top-2 等架构选择；再概括作者对 Attention/Mamba 比例及 MoE 增量的分开消融。重点是从实验中区分混合主干与 FFN-MoE 的贡献，不把第 43 章的融合分类重讲一遍，也不将单一配置说成普遍最优。

## 47.3 BlackMamba：Mamba 序列路径与 routed MLP 的组合

本节比较一种不保留显式 Attention 路径的组合：Mamba 负责序列处理，MoE 取代 FFN/MLP。覆盖 block 的结构关系，以及论文所用 340M/1.5B、630M/2.8B active/total 参数模型、300B 自建语料训练等证据条件。该例说明 SSM 与 MoE 可以作为不同功能路径协同扩展；质量、FLOPs 和逐 token 生成结果只支持论文对应模型、数据、实现与测量口径，不外推为规模无关的架构优势。

## 47.4 Routing Mamba：把专家化移入 SSM 投影，并扩展到混合主干

本节解释 MoE 不一定只替换 MLP。Routing Mamba 将专家化放入 Mamba 的部分线性投影，并通过共享路由协调相关子模块；对照独立专家化单个投影路径的实验，说明 SSM 内部各投影并非可任意替换的独立 FFN。进一步覆盖其在 Samba（Mamba 与滑动窗口 Attention 混合）上的测试，以及与 FFN-MoE 组合的消融。报告 23% FLOPs 差值时必须限定为论文具体模型、SlimPajama 训练数据、硬件、序列长度、验证困惑度与单次 forward 计算口径；与 FFN-MoE 的组合结果也不能概括成必然增益。

## 47.5 比较专家化位置与序列混合路径

本节用一致的维度并列 Jamba、BlackMamba 与 Routing Mamba：主干采用哪些序列混合器、MoE 位于 FFN 还是 SSM 投影、专家路由作用于什么对象、实验要检验什么增量。由此说明专家化位置会改变路由输入、被扩展的函数子模块及其与序列状态的关系；不能把不同论文的模块名字、参数量和分数拼成横向排名。与第二十一章、第二十二章分别按职责回链，避免重复 MoE 路由细节和系统成本账本。

## 47.6 组合收益需要能隔离主效应与交互的消融

本节总结如何判断组合是否值得：分别比较纯/混合序列主干、加入 FFN-MoE、把专家化转入 SSM 投影，以及这些选择联合后的模型；对齐数据、训练 token、模型与 active/total 参数、计算口径、评测任务和实现版本，分别报告质量、计算与上下文行为。单个三组件模型的高分只能证明该模型在该设置下的结果，不能证明三者存在协同或哪个模块导致收益。结尾将未解决的问题限定为专家化位置、共享路由、层比例及任务/规模迁移，由第五十章综合讨论更广的架构演进判断。
