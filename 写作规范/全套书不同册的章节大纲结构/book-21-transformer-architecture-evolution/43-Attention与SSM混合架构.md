# 第四十三章：Attention + SSM 混合架构为什么现实

本章解释 Attention 与 SSM 为什么被放进同一语言模型，以及不同融合结构能够回答什么架构问题。读者从显式读取 key/value 历史与递归压缩上下文两种信息访问路径出发，理解层间串接与层内并行不是同一种 block；再依据比例、层位置、上下文和任务实验判断混合结构的收益与代价。核心范围是 Attention–SSM 融合和其证据边界，不展开 Mamba/SSD 内部算法，不规定卷积、SSM、Attention 的通用职责，也不把外部检索或 serving runtime 纳入模型内部结构。

## 43.1 两种历史信息访问路径为何互补

本节围绕“模型怎样保留并读取已处理的 token”说明混合的动机。覆盖 Attention 对显式 key/value 历史的内容相关查询、SSM 将前缀更新进递归状态的摘要路径，以及两种路径各自的资源形态与信息边界；指出混合提供并置路径的设计选择，但不能由结构动机直接推出普遍质量或速度优势。

## 43.2 层间混合：让表示依次经过 Attention 与 SSM

本节说明 inter-layer / sequential 融合的结构：模型层按既定位置交错，某层输出成为后一类模块的输入。以 Jamba 和 Mamba-2-Hybrid 作为对照案例，覆盖 block 比例、MoE 是否同时介入、Attention/MLP/SSM 的相对分布，以及这些实现各自优化的资源与目标；避免将模型名简化成同一固定配方。

## 43.3 层内并行混合：同一输入分配给不同 head

本节说明 intra-layer / parallel 的融合粒度：Attention heads 与 SSM heads 在同一层处理共享输入，随后合并表征。以 Hymba hybrid-head 为代表，覆盖其与层间串接的计算路径差异，并交代 meta tokens、局部/全局 Attention 和跨层 KV sharing 等共设计如何限制单独归因。

## 43.4 比例与层位置是需要实验回答的设计变量

本节把 Attention 所占比例、层位置和融合粒度视为可消融的架构变量，而不是可从“互补”直觉直接推出的固定答案。综合 Jamba 的 1:3 与 1:7 对比、Bae 等人在约 350M/1B 和 60B tokens 条件下的层比例/位置实验，说明质量、效率与配置之间的条件性折中，并明确其证据规模和任务范围。

## 43.5 结果如何归因：模型规模、任务与测量口径

本节用不同实验结果展示混合收益为何不能写成一个总排名。覆盖 Waleffe 等人在 8B、3.5T tokens 和 12 项任务上的 Mamba-2-Hybrid 结果，区分生成速度预测与实测；讨论长上下文多文档问答中相对优势变化，并结合 Lee 等人关于上下文长度、记忆任务和融合方式的预印本结果。归因时分开结构、训练数据与预算、其他模块、提示构造和评价协议。

## 43.6 何时值得采用混合结构，以及下一步比较什么

本节归纳混合结构作为架构假设的适用判断：当任务需要压缩长历史，同时又需要对部分历史进行选择性读取时，混合值得与纯 Attention、纯 SSM 在同预算和同任务下比较；比例、融合位置和测量负载都须作为变量报告。结尾将三类序列运算的职责比较交给第 44 章，并把模型外部的检索路径交给第 45 章。
