# 第二十二章：Dense 与 MoE：训练、服务和成本的完整取舍

## 章节契约

- **前置：** 读者已理解第二十一章的 token-to-expert 路由，以及第五册第四章的 total/active 参数、MoE 训练账本和第五册第七章的 Expert Parallel 与 all-to-all；prefill/decode 和 KV cache 分别由本册第十五、十一章铺垫。
- **离章结果：** 能说明稀疏激活具体减少或增加哪项工作，区分模型总参数、每 token 激活计算、权重驻留、训练更新成本和线上延迟/吞吐；能把训练和服务放入不同负载与硬件条件下比较，不从 active 参数或单篇论文数字推出普遍成本结论。
- **本章职责：** 从训练、设备通信和服务三个系统阶段比较 Dense 与 MoE 的资源代价及其相互影响；用有明确配置边界的研究案例说明系统共设计可以改变结果，并说明比较证据所需的共同条件。
- **边界：** 第二十一章主讲路由与代表性结构；第五册第四章主讲 router loss、capacity、token dropping 与训练前账本；第五册第七章主讲并行策略、all-to-all 和 EP 操作；第六册与第二十四册主讲服务调度、runtime、SLO 设计与完整压测。本章不重复这些机制或提供发布 gate，而解释它们怎样改变 Dense/MoE 的总体比较。
- **研究依据：** 旧稿 21 个 H2 中多处重复参数/容量账本、并行教程、router 诊断、服务检查清单与单位成功成本公式；其中训练/serving成本反复复述同一结论。章级研究显示，必要主线应围绕参数口径、训练有效工作、通信关键路径、prefill/decode 条件和公平比较证据组织。来源边界见[MoE 系统成本与比较证据研究记录](../../../research/moe-system-costs-and-tradeoffs-2026-11-20.md)。

## 正文编号大纲

### 22.1 Dense 与 MoE 的资源账本分别回答什么

本节围绕“一个数字能说明哪种资源需求”区分总参数、每 token 激活参数、实际驻留权重和完整执行时间。Dense 的固定参数路径与 MoE 的条件 FFN 路径会改变计算与存储的关系，但激活参数不包含 attention、调度、通信、量化和共享权重等全部工作；权重是否全驻留、分片或 offload 又由部署方式决定。参数数字只有连同阶段、设备和执行条件一起解释，才可用于比较。

### 22.2 训练：稀疏计算必须放回每次更新

本节比较训练中的理论 expert 计算与实际完成一次优化更新所需的工作。MoE 的活跃 expert 矩阵计算只覆盖局部前向/反向路径，路由分布、capacity 对齐或 token 丢弃、expert 小批量效率、梯度与优化器状态、通信和检查点均会改变总步时及内存压力；负载损失和容量规则由第五册第四章主讲。本节以固定目标质量或固定训练预算为比较口径，并将 MegaBlocks 与 DeepSeek-V3 报告作为各自实现、数据、硬件及训练配方下的例证，不把它们转写成 Dense/MoE 通用倍率。

### 22.3 训练通信：拓扑与重叠改变暴露等待

本节说明 expert 分布在单节点或跨节点、expert parallel group 大小和计算/通信重叠程度，怎样改变 MoE 训练的关键路径。第五册第七章已经解释 all-to-all 的分组与交换过程，本节关注其系统后果：通信总量、链路带宽、路由倾斜和排程重叠并非同一量；优化器若隐藏了部分通信等待，未必减少实际数据量。DeepSeek-V3 和 Megatron-Core 的报告展示了架构、dispatcher、硬件拓扑与训练 schedule 的共设计，但结果绑定各自的集群配置和测量分母。

### 22.4 服务：prefill 和 decode 暴露不同瓶颈

本节比较一批 prompt token 的 prefill 与逐步生成的 decode 如何产生不同 expert 批量、权重访问和延迟约束。模型总 expert 权重通常仍需在服务集群的某个存储层可用；分片、复制、缓存或 offload 改变驻留位置与传输路径，却不由 active 参数单独决定。Decode 的 KV 状态还由 attention 层与序列负载决定，不因 FFN 稀疏自动变小。DuoServe 与 METRO 的研究作为具体系统条件下的例证，说明同一服务策略或“均衡”目标不必同时适合 prefill 和 memory-bound decode；其指标不推广到其他模型、批量、硬件或 runtime。

### 22.5 对比结果要先对齐问题和分母

本节区分两个不同问题：固定训练预算/设备时哪种模型达到更好的目标质量，以及达到相同目标质量时哪种模型消耗更少的资源。训练对照需说明数据、token、精度、模型版本、质量指标、系统和计时范围；服务对照还需固定任务、输入/输出分布、并发、硬件、量化、runtime 和延迟约束。DeepSeek-V3 的总/激活参数与作者报告的官方训练成本、MegaBlocks 的同验证损失系统比较分别回答有限问题，不能拼成横向排行榜或直接归因给 MoE 结构。

### 22.6 选 Dense 还是 MoE 取决于当前约束

本节收束为条件化判断：Dense 的固定路径可能适合模型可驻留、请求量较低或部署网络受限的场景；MoE 只有在条件容量确实带来目标质量收益，且系统能承担权重驻留、路由通信和相应时延时才兑现其优势。任务分布、训练栈、互联拓扑、batch 与 SLO 会移动两者的取舍边界，因此结论应指向具体负载与资源条件，而不是给出脱离条件的优胜者。
