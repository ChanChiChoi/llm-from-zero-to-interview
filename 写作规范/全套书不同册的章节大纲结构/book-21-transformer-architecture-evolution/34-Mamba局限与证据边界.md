# 第三十四章：Mamba 的局限：精确检索、ICL、规模验证与生态

本章围绕 Mamba 的递归状态怎样影响历史信息读取，以及哪些实验能支持具体能力判断展开。中心不是给架构贴上能/不能的标签，而是把固定状态路径、精确关联检索、上下文学习任务、规模与版本证据、实现生态分别纳入读者的判断范围。完整的 Mamba-2/SSD 机制由第三十五章负责；跨架构能否替代由第三十六章负责；混合结构由第四十三章展开；服务引擎和部署评测回到第六册与第二十四册。

## 34.1 局限要落在具体信息访问任务

本节说明 Mamba 逐 token 更新递归状态与 attention 显式保留可寻址 K/V 历史的差别，并限定固定状态所支持的结构性判断。围绕复制、关联回忆和一般上下文学习区分模型需要保存、按 query 定位、组合还是泛化的能力；理论状态容量结果应连同模型类别、精度和任务假设理解，不能把它改写成任意语言问题必然失败的断言。

## 34.2 多条目精确检索如何暴露状态路径边界

本节聚焦输入中已给定 key-value 事实、末尾 query 要求精确返回 value 的任务，说明单条局部线索与多个分散/密集条目的差异。覆盖证据位置、实体数量、干扰模式、query 与证据的顺序、prompt 是否提供局部相关性标记等条件；结合受控实验解释检索失败可能涉及状态写入、内容选择、相关性信号形成或输出读取，不能只凭固定 state 推断唯一病因。

## 34.3 ICL 是若干任务的集合

本节把 ICL 中的函数/规则学习、Markov 序列预测、关联召回与任务格式适配分开，使同一模型可以在一种任务中成功、另一种任务中落后。综合 Mamba 与 Transformer 在回归、稀疏 parity、MQAR、自然语言和 Markov 链任务上的研究结果，说明行为表现依赖任务定义、示例分布及评测协议；机制分析也应与输出成绩分开。

## 34.4 规模与版本比较能确认哪些结果

本节依据同数据、近似参数规模的 8B 研究讨论纯 Mamba/Mamba-2、Transformer 与 Hybrid 的不同结果，交代训练 token 数、上下文训练、任务格式和对照实现如何限制结论。Mamba-3 的新实验用于说明后续版本可能改善 retrieval/state tracking；它与早期 Mamba/Mamba-2 的任务、结构及 baseline 不同，不能拼成不受版本约束的架构胜负结论。

## 34.5 用匹配证据评估目标 workload 与生态

本节将能力主张转为可以复查的对照设计：精确检索按位置、密度和实体冲突切分，ICL 按所学规则和示例任务切分；质量、错误类型、模型/训练条件与硬件实现分别记录。生态讨论只覆盖 checkpoint、训练/推理实现、兼容性和维护支持如何影响迁移判断，不重讲 serving 调度或 hybrid 结构，并明确本章证据不足以替代第三十六章的全架构判断。
