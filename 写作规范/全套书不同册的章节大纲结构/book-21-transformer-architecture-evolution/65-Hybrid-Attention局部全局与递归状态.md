# 第 65 章 Hybrid Attention：局部、全局与递归状态如何分工

本章围绕一个问题组织：当一个序列模型同时含有局部注意、全局注意与递归/线性序列模块时，历史信息分别以什么形式可见、保存和传递，设计者怎样判断组合后的路径到底支持什么任务。先把注意范围与状态更新区分开，再观察它们在层间或层内的连接、历史信息经过这些路径时会发生什么变化、资源随上下文如何变化，并以版本化模型报告检验通用直觉的边界。第 43 章承担 Attention–SSM 融合形式和系统比较，第 44 章承担 Attention、卷积与 SSM 的模块级信息流；本章聚焦读懂具体混合模型的路径图及其任务/资源含义，不重复二者的基础讲解，也不转为通用 serving 手册。

## 65.1 三种历史路径分别让当前 token 看到什么

本节区分局部 attention、全局 attention 和递归状态保存历史的方式。局部与全局描述 attention 的可见位置范围；递归状态描述一种逐 token 更新、把前缀累积到状态中的序列运算。它们可以单独出现或组合，不能按“局部/全局/递归”误认为三个互斥模型类别；每种路径提供的信息地址、持久表示和失败边界不同。

### 65.1.1 局部 attention 限定单层直接读取的邻域

局部或 sliding-window attention 仅允许 query 读取窗口内的位置，直接注意成本和保留的逐位置 KV 受窗口长度限制。窗口外的信息仍可能通过更深层表示或其他序列路径传递，所以“当前层看不到”不等于“整网永远不可达”；反过来，层间可传递也不等于保留了原 token 的精确地址。研究抓手包括 causal window、window size、层间感受野与跨窗口传递。

### 65.1.2 全局 attention 保留前缀位置的直接寻址路径

全局 causal attention 允许当前 query 在可见前缀中按内容匹配历史 key 并读取相应 value；标准实现通常为每个历史 token 保留表示。GQA/MQA、MLA 或稀疏索引可改变头数、缓存 payload 或实际计算位置，但它们与全局可见性不是同一维度：需要按具体模型确认每个历史位置是否仍可被寻址、以何种表示存储。直接访问路径不保证模型会找到、理解或正确引用目标。

### 65.1.3 递归状态累计历史，但不逐 token 保留地址

SSM、门控线性递归和 delta-rule 类线性 attention 会随新 token 更新固定形状或由模型维度确定的状态，推理缓存规模不随历史 token 数线性增长。状态能否保存一项精确信息取决于其表示、更新规则、其他通路与训练任务；“固定大小”不等于“自动总结得好”，也不等于“可以逐 token 回读”。KDA/Gated DeltaNet 的状态更新细节由第 61、62、76 章承担。

## 65.2 混合架构怎样连接不同路径

本节把融合的粒度与 attention 的可见范围分开。串接不同类型的层、同一层并行处理、以及一个 attention 模块内部的窗口或稀疏 mask，改变的是不同的结构对象；它们不能仅凭“hybrid”名称相互替代。详细的历史分类与策略消融见第 43 章，本节将其落到读模型路径图时应追问的连接关系。

### 65.2.1 层间交替让下游模块读取前序层的表示

在 inter-layer 组合中，序列依次经过不同类型的 token-mixing 层。后一层处理的是前序路径更新后的 hidden state，因此跨层组合有机会让一种路径提供表示、另一种路径再读取或整合；若前一条路径已经丢失细节，后层不能仅凭“存在 global attention”保证恢复原内容。层类型、重复节奏和位置须绑定报告/配置版本。

### 65.2.2 层内并行让不同模块从同一表示出发

在 intra-layer 或 hybrid-head 结构中，同一层把输入送入 attention 与 SSM/递归分支，再合并各分支输出。并行分支不必彼此独立，也不必学出固定职责；投影维度、融合操作和后续残差决定信息怎样继续流动。Hymba 是同层 attention/SSM heads 的代表案例；层内融合与层间交错的差别已在第 43 章展开。

### 65.2.3 attention 的局部性与递归状态是不同设计轴

一个模型可以在部分层使用滑窗 attention，在其他层使用全局或 query-selected sparse attention，并在更多层中使用递归状态。窗口/稀疏 mask 规定 attention 的读取集合，递归算子改变历史的保存表示；短卷积也可以作为递归模块内部的局部混合，而不是独立的局部 attention 分支。读架构图时应逐项辨认计算路径，不能从“有局部与全局能力”推断模型一定有三个并行分支。

## 65.3 一条远距离信息沿不同路径会发生什么

本节借助同一项历史事实，解释不同通路提供的访问条件。核心是区分“事实所在位置可见”“事实内容被状态编码”“模型输出能引用来源”三种要求；长上下文窗口、任务平均分或路径数量都不能单独证明它们等价。

### 65.3.1 事实仍在窗口内时，局部层可直接匹配邻近表示

当目标位置落在某层的可见窗口中，query 可在该层直接比较对应 key 并聚合 value。移动事实或 query 接近窗口边缘时，直接可见性随 mask 变化；更深的局部层还可能接收到此前已混合过的表示。窗口大小、包含当前位置的计数约定和层间传递方式共同决定边界行为。

### 65.3.2 超出局部窗口后，全局读取和状态读出不同

若目标位置仍在全局层可见前缀中，query 存在对该位置 key/value（或对应 latent 表示）的直接读取路径。若只有递归状态，历史事实必须通过此前更新编码进状态，并由当前 query 从状态读出；这一过程不保留普通 KV cache 的逐位置索引。精确数字、否定词、冲突版本等内容应分别测量，不能用一个“远程依赖”总称掩盖差异。

### 65.3.3 混合输出不会自动把不同路径变成同一种记忆

全局 attention 输出可以影响后续递归层的输入；递归状态也可以为后续 attention 提供已混合过的表示。但这不代表状态变成逐位置 KV，或 KV 自动变成足以回答未来问题的摘要。路径输出相加、拼接、门控或经过残差通路的具体方式会影响哪些信息继续传播，需按对应模型报告和实现确认。

## 65.4 从层表推断状态构成与资源增长

本节把结构图转成可核对的资源账本：识别各层缓存/状态对象、这些对象怎样随序列增长，并区分理论增长与具体推理实现。重点是理解层比例为何不足以预测总内存、计算或速度，完整 cache 类型和Serving机制由第 69—71 章承担。

### 65.4.1 为每类层登记实际保存的表示

标准 attention 常按历史 token 存储 K/V；局部 attention 的可保留范围受窗口和缓存实现限制；MLA、GQA/MQA 或跨层共享改变每个位置的 payload；递归层保存模型维度决定的状态。比较前必须固定 layer count、head/dimension、dtype、窗口、sharing 规则和状态格式，不能只记录全局层比例。

### 65.4.2 上下文增长对三条路径的影响不同

标准 full attention 的 prefill 需要处理长范围 token 交互，decode 每个新 query 要读取其可见历史；局部窗口把单层可读范围限制在窗口内；递归状态的持久大小对序列长度固定，但状态更新仍消耗计算和带宽。稀疏 attention 可减少实际计算位置，却不自动说明所有历史 KV 都不再存储。按 prefill/decode 分开量化，并把缓存与 kernel/硬件联系起来。

### 65.4.3 层比例不能单独决定质量或服务成本

一个 global 层可能保留所有历史 payload，也可能采用压缩表示；少量 global 层未必提供足够远程检索，多数递归层也未必能胜任需要逐 token 证据定位的任务。层的顺序还决定其他路径收到什么 hidden state。训练预算、数据、位置编码、FFN/MoE、kernel 和硬件均会影响测得结果，不能从单个比例推算通用最优配置。

## 65.5 模型报告展示不同的混合组合

本节以有限模型案例对照三类路径及其融合粒度，目的在于学会从论文/配置中读出真实结构，不把一种模型的层表推广为模板。每个案例的比例、窗口和实验结果都绑定对应来源版本；历史背景可回看第 43 章，KDA/Gated MLA 的局部机制与 Kimi K3 全案分别由第 61、63、88 章承担。

### 65.5.1 Griffin：局部 MQA 与门控线性递归交替

Griffin 的 temporal-mixing blocks 结合 RG-LRU recurrent block 和 local MQA；论文通过特定局部窗口与合成复制/检索任务研究两种路径的互补。该例用于说明模型可以在局部逐位置读取和递归状态之间分工，而不含一个 standard full-global attention 分支。

### 65.5.2 Jamba：Transformer attention 与 Mamba 按层间比例组合

Jamba 报告的结构以 Mamba 和 Transformer attention 层交错，并在特定层使用 MoE。论文中的 1:7 attention-to-Mamba 比例是其大模型实现选择；较小模型消融在对应训练和指标下比较 1:3 与 1:7。该例说明混合模型的计算与参数容量设计可同时包含不同轴，不能把 MoE 结果记作 attention–Mamba 融合的单独收益。

### 65.5.3 Hymba：同层 attention 与 SSM heads 并行

Hymba 将 attention 与 SSM heads 放进同一 hybrid-head 模块，并在整模型里结合局部/全局 attention、KV sharing 和 meta tokens。该例帮助区分层内同时处理与层间顺序串接，同时提醒整模型的质量、cache 和 throughput 结果包含多项共同设计。

### 65.5.4 Qwen3.8-Flash-Next：递归、全局层与稀疏 attention 随阶段变化

Qwen3.8-Flash-Next 技术报告公开每组 3 个 GDN 层配 1 个 full-attention 层；GDN 模块自身还含短 causal convolution 和递归状态。在 continued pretraining 中，full-attention 层又由 QSA 的压缩索引和稀疏块读取替换。该案例说明局部预混合、递归状态与全局/稀疏 attention 可以出现在不同层级及训练阶段，结构与阶段都须以版本化报告为准。

### 65.5.5 Kimi K3：KDA 递归层与 Gated MLA 全局读取交替

Kimi K3 v2 报告以每组三层 KDA 接一层 Gated MLA 的节奏组织主干，并在末尾追加 Gated MLA；KDA 提供 position-sensitive/recency-aware 序列混合，MLA 提供全局内容交互。报告的 1M 窗口还包含长上下文数据、渐进扩展训练和系统基础设施，不能归因给 3:1 层比或 NoPE 单项；完整模型证据由第 88 章综合。

## 65.6 怎样检验路径分工是否兑现

本节将结构假设转成可比较的质量、覆盖和成本问题。评估既要区分局部模式、远程精确回读和可压缩历史处理，也要尽量控制规模、训练预算与其余架构变化；实验结果只对所测模型、任务和实现成立。

### 65.6.1 按历史距离与信息类型拆分任务

局部语法/复制、跨窗口关联、远程精确实体/数字、重复模式摘要、冲突版本判断与多条证据组合对应不同访问需求。改变事实位置、query 距离、干扰 token 数和窗口边界，可以暴露局部可见性、递归状态保留和全局选择器漏读等不同失败。长上下文长度本身不是检索能力指标。

### 65.6.2 用路径消融区分组合收益与共同变化

若要解释路径的作用，应在相近训练 token、参数/FLOPs 预算、数据、tokenizer、上下文和实现条件下比较 full/global、local、recursive 与 hybrid 变体，并单独改变层位置或比例。整模型同时更换 MoE、数据、RoPE、latent cache 或训练阶段时，结果支持的是整套变更；单次 ablation 不保证因果机制已被独立识别。

### 65.6.3 质量、缓存与速度保留各自的测量口径

按任务给出检索/支持正确性和位置/距离分桶；资源报告区分 prefill、逐 token decode、峰值缓存/状态以及目标硬件和实现版本。只有质量边界与成本同时匹配实际 workload，才可讨论取舍。若缺乏可比条件，应说明证据只能支持结构描述或定性预测，不能得出通用优劣结论。
