# 第 59 章 主流模型创新点横向对比：架构、训练与公开证据

本章将第五十一至五十八章的固定版本案例放进同一组比较坐标，帮助读者区分架构构件、训练目标与配方、对话/多模态接口和公开评测各自能够支持的结论。横向比较的重点不是给模型排总名次，而是看每项变化落在哪个层次、来源直接披露了什么、哪些差异仍无法归因。第二十一册第四十二章负责序列架构家族的机制对照，第六十章负责评估尚未形成历史定论的新架构。

## 59.1 比较对象：名称、版本和证据层次

模型家族名不能替代具体比较对象。本节把版本、checkpoint、训练状态、配置和报告修订分开，避免将不同时间、任务或发布形态下的说法拼成一个模型事实。

### 59.1.1 把模型与报告固定到具体版本

说明系列名、模型版本、基础/指令/推理 checkpoint、技术报告修订版与产品接口各自回答不同问题。后续案例按第五十一至五十八章已核对的版本读取；同名系列的数字和结论不得自动推广到其他代际。

### 59.1.2 区分架构变化、训练变化与使用接口

将比较对象分成模型内部的信息流与计算结构、训练数据/目标/阶段、以及用户可见的任务和多模态接口。InstructGPT/ChatGPT 与 R1 的案例说明，行为或训练阶段变化不必然意味着 backbone 改动；多模态输入接口也不自动披露视觉编码和融合拓扑。

### 59.1.3 区分直接披露、受限推断与未知项

把报告/模型卡明确陈述的事实、由特定配置或实验可推出的有限判断、以及来源没有披露的内部细节标为不同证据层。闭源报告中的未知项应保持未知，不用榜单、API 行为或经验猜测补全。

## 59.2 架构改动落在哪条信息路径

本节比较模型内部结构变化的具体位置，并强调相同组件名不说明模型采用了相同实现或相同效果。组件组合、历史状态读取和条件计算是互相关联但不能互相替代的比较面。

### 59.2.1 组件组合与继承不等于单项发明

以 LLaMA 系列为例，说明 RMSNorm、SwiGLU、RoPE 等构件有各自先行工作；公开模型的贡献应按报告所述组合、规模和训练设置描述，不把采用某构件说成发明该构件，也不把综合结果归到单个模块。

### 59.2.2 注意力与历史状态读取的不同改法

区分 Mistral 7B 的 GQA 与滑动窗口注意力，以及 DeepSeek-V2 的 MLA：前者分别改变 K/V head 共享和单层直接可见范围，后者改变历史 K/V 的表示与读取路径。它们都与注意力/缓存有关，但不是一个统一的“省显存模块”；通用机制回链第四、十一、十八和十九章。

### 59.2.3 稠密 FFN 与条件专家的参数口径

以 Mixtral 与 DeepSeekMoE 说明每 token 激活专家、总参数和激活参数是不同字段；稀疏计算并不表示总权重、通信、权重常驻内存和端到端延迟同比下降。通用路由与训练/服务成本由第二十一、二十二章主讲，本章只比较具体报告披露的结构位置和口径。

## 59.3 训练和任务适配带来的变化

模型间可观察的行为差异可能来自规模、数据、计算预算、训练阶段或提示接口；本节将这些因素放回各自的证据层，避免把训练成果误归因于架构。

### 59.3.1 Scaling、上下文学习与计算预算是不同主张

区分 GPT-3 在无梯度更新的 zero/one/few-shot 评估中呈现的上下文条件化行为，与 Chinchilla 在固定计算预算下重新分配参数量和训练 token 的研究问题。两者涉及规模与数据，但测量对象、预算约束和结论并不相同；计算最优关系由第五十二章详讲。

### 59.3.2 指令微调和对话发布改变使用方式

以 InstructGPT/ChatGPT 区分预训练目标、监督微调、偏好信号、后训练过程和产品化对话入口。比较结论可以落在报告披露的训练阶段和任务行为上，但不能仅凭对话方式推断 decoder backbone 变更；通用 RLHF 机制由第五册主讲。

### 59.3.3 开放权重报告披露的数据和配方不等价

对照 Qwen2.5、Llama 3.1 与 Gemma 2 的报告，区分 token 数、数据处理说明、训练阶段、蒸馏与许可证等披露维度。数据规模不等于语料质量或可复现数据，开放权重也不等于完整训练配方公开；训练细节回链第五册与第五十七章。

### 59.3.4 DeepSeek 的 MTP 与 R1 后训练不应混成架构代际

区分 V3 的未来 token 预测辅助目标与推理时可能复用的模块，以及建立在 V3-Base 上的 R1 后训练路线。报告支持它们作为训练/使用阶段的不同变化，不支持把 R1 描述成独立的新 backbone，也不把某一评测提升归因给单个训练环节。

## 59.4 多模态、长上下文与披露边界

多模态输入能力、窗口字段和实验结果属于不同观察层次。本节用 Gemini、GPT-4V 和 Claude 3 的发布期材料说明，比较时既要记录公开的接口和评测，也要保留未公开的内部架构。

### 59.4.1 输入模态和产品接口不等于内部拓扑

对照 Gemini 报告中明确公开的部分结构描述，与 GPT-4V/Claude 3 资料对图像输入和高层训练流程的披露。接口可确认模型处理什么输入，不足以补出编码器、融合位置、token 路径或所有版本共享的实现。

### 59.4.2 上下文窗口和任务级有效性分开比较

区分模型/产品所列窗口字段、论文中测试过的输入长度和特定任务对长距离证据的使用效果。Gemini 1.5 与 Claude 3 的 needle-in-a-haystack 等结果受各自版本、样本、协议与评分方式约束，不能直接排成统一的长上下文能力榜。

### 59.4.3 披露不对称时结论也必须不对称

说明技术报告详述程度不同会造成可比较信息不齐：GPT-4 报告明确不披露架构规模、硬件和训练计算等细节；其他模型公开的报告字段也不代表其公开完整系统实现。未知本身是比较结果的一部分，而不是待作者猜测填空的空白。

## 59.5 第五十一至五十八章的版本化比较矩阵

本节把前述坐标落实到八组历史案例，表格用于快速定位每组材料的变化层次和推断边界。它是章节导航与证据摘要，不是将不同指标加权后的排名表；每行需要回到对应章节和固定来源理解。

### 59.5.1 按案例并列变化层次与推断边界

矩阵覆盖 GPT 谱系与 Scaling/ICL、Chinchilla/PaLM、InstructGPT/ChatGPT、LLaMA、Mistral/Mixtral、Gemini/GPT-4V/Claude 3、Qwen2.5/Llama 3.1/Gemma 2、DeepSeek-V2/V3/R1。每行标出主要比较轴、直接证据入口和不可由该证据推出的结论；来源不同、版本不同或评测不对齐时明确保留边界。

### 59.5.2 沿矩阵读出跨案例关系

从矩阵观察架构、训练、接口和公开披露如何彼此正交或组合，以及哪些案例只公开行为/结果而未公开内部机制。不得用家族标签、参数规模、单一 benchmark 或“开源/闭源”二分法替代逐项证据。

## 59.6 横向比较能够支持的结论

本章最后提炼可迁移的阅读结论，同时限定其用途：历史比较帮助识别变化所属层次和证据边界，不自动提供新模型优胜判断或工程部署建议。

### 59.6.1 不同创新轴能够组合，不能压成单一标签

说明注意力状态表示、FFN 条件计算、训练预算、后训练目标和任务接口可同时变化；“某模型采用 MoE/MLA/多模态”只回答局部结构事实，不能概括整个模型的质量、成本或能力。

### 59.6.2 多项同时变化时谨慎进行因果归因

当版本间规模、数据、训练配方、架构和评测同时改变时，报告总体结果不能单独识别某一模块的贡献。单项因果结论需要该来源中相应消融或条件匹配证据；缺乏这些材料时只陈述并行变化与作者报告结果。

### 59.6.3 与架构家族比较及未来判断章节衔接

回扣第四十二章的序列架构家族对照，并将尚无定论的新结构、组合方式和判断方法交给第六十章。本章止于固定历史案例的综合，不扩展为 serving 工作流、排行榜或下一代模型预测。
