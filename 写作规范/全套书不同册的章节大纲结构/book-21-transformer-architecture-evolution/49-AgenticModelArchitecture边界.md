# 第 49 章 Agentic Model Architecture：模型能力与执行闭环

本章从模型架构角度区分语言模型本身、工具使用能力和外部 Agent 系统。Agent 能力可以来自模型参数中的工具行为、提示中的决策模式，也可以来自模型与运行时、工具、环境及结果反馈组成的交互闭环；这些层次可以组合，却不能据此推断有一个统一的“Agent Transformer block”。第十七册主讲 Agent 行为与方法，第二十册主讲 Harness/Runtime 执行，第 22 册主讲工具协议；本章只解释架构层级和能力证据的归属。

## 49.1 语言模型、单次工具调用与 Agent 系统

一次文本生成只根据输入上下文产生输出；单次工具调用将结构化模型输出交给宿主并把结果返回；Agent 系统则把多轮模型决策、环境动作和新观察组织成可继续或结束的闭环。本节界定这三种对象以及它们之间的包含关系，说明 Agent 不对应一种固定神经网络层，同时保留专门训练或多模态动作模型等不同实现可能。

## 49.2 工具使用能力可以放在不同架构层

ReAct 以提示轨迹引导模型交替生成思考、动作和观察；Toolformer 通过自监督数据构造和微调学习 API 调用；Gorilla 将 API 文档检索与工具调用微调结合。本节比较这些路线分别改变模型权重、输入上下文和测试时资料的哪些部分，以及它们可组合之处与实验边界，不把工具使用能力等同于 API 执行或长任务成功。

## 49.3 模型提出的动作如何经过宿主进入环境

Agent 的动作链包含模型生成的候选、宿主对结构化请求的接收、外部工具或环境的执行，以及返回给模型的观察；工具副作用和执行事实由外部环境与宿主维护，不能由模型文本自行确认。本节说明这些架构职责如何连接，并把协议 schema、权限策略、事务、恢复和具体 runtime 实现留给第二十、二十二册。

## 49.4 当前上下文、外部检索、持久记忆与验证

当前任务轨迹、供本轮决策引用的外部资料、跨任务可复用的持久记忆和独立结果验证器处在不同的信息路径上：前者提供工作状态，检索提供候选证据，记忆保存可复用信息，验证器检查动作或产物是否达标。本节解释这些模块在闭环中的接入位置及其相互边界，并将检索与模型记忆的机制分别交回第四十五、四十六章，Agent 的完整记忆与 RAG 方法交回第十七册。

## 49.5 Agent 评测成绩属于完整交互配置

AgentBench、OSWorld 与 τ-bench 分别以多种交互环境、真实桌面任务或带领域规则的多轮用户/工具交互组织评测。模型版本、提示/控制器、工具集合、环境初态、策略规则、任务 verifier 和调用预算共同限定成绩含义；本节据此区分 Agent benchmark 对系统行为的证据与对内部模型结构的证据，并说明异构分数不能直接拼成模型架构排名。完整评测设计与运行验收由第七、十七、二十册进一步承担。

## 49.6 根据环境变化决定控制权如何分配

环境变化少、操作顺序稳定且失败可预先枚举时，固定工作流通常能让动作路径更明确；当下一步取决于工具结果、环境状态或新证据时，模型选择下一动作的闭环才提供额外适应空间。本节归纳这一架构取舍及其成本、可预测性和验证责任，不把更高自主度当作无条件的能力提升，并交代需要深入规划、执行或协议设计时的跨册阅读入口。
