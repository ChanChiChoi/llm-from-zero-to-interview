# 第三十三章：Mamba 的训练、推理和硬件效率优势

本章围绕 Mamba 的输入依赖递归如何在现代 GPU 上执行、它在哪些资源维度上改变了长序列成本，以及原论文的效率数据能支持哪些判断展开。核心是把序列长度复杂度、scan 算子效率、训练内存和自回归吞吐分开；由此解释硬件感知 Selective Scan 的内存路径、训练反向的中间状态重计算、生成时固定状态相对 KV cache 的容量变化，以及基准测试所绑定的任务、模型与设备。服务引擎中的完整调度、迁移和 SLO 仍由第六册与第二十四册主讲，跨架构能力和总体胜负由第三十四、三十六章处理。

## 33.1 复杂度、阶段与实际速度

本节厘清“线性”这一描述的适用对象：对固定模型宽度与状态维度，Mamba 的序列扫描工作量随序列长度增长，但训练、整段 prefill、自回归 decode 和完整模型不是同一个测量对象。重点包括理论算量、内存访问、并行深度、kernel 启动和权重流量之间的关系，使渐近复杂度不被直接当作 wall-clock 结论。

## 33.2 训练路径：硬件感知 Selective Scan

输入依赖系数使 Mamba 不能沿用固定 LTI SSM 的共享卷积核；直接展开所有 token 的状态会产生与 batch、长度、通道和状态维相关的大型中间量。本节说明并行前缀 scan 如何处理逐位置递归、kernel fusion 如何把离散化/状态扫描/读出融合到硬件存储层级中，以及序列过长时分块怎样维持计算。知识范围覆盖 HBM 与片上 SRAM 的读写职责、状态扩展为何不应完整写回 HBM，以及融合的资源取舍。

## 33.3 训练内存：反向阶段重计算状态

扫描前向可避免保存完整的逐位置扩展状态，但反向传播仍需要这些中间结果。本节说明重计算怎样用额外算术减少 HBM 中间状态读写，并区分 scan 层的激活占用、整层模型的训练显存和优化器/权重内存。论文单层估算与全模型显存表的差异用于界定结论范围；训练配方和分布式优化不在本章重复展开。

## 33.4 自回归推理：固定状态与 KV cache

decode 时，Mamba 每生成一个 token 都按递归方式更新各层状态；其核心状态容量随模型宽度、状态维度和层数变化，但不像 attention KV 那样随历史 token 数线性增长。本节涉及两种状态表示的逐请求容量估算、卷积缓存的附加部分、模型权重读取和 batch 对总吞吐的影响。固定状态提供的是上下文长度方向上的容量性质，不等于所有模型配置下状态更小或 decode 必然更快。

## 33.5 原论文效率结果与可迁移边界

本节分开读取 scan 微基准、端到端推理吞吐和训练显存三类证据，保留原论文的 A100、BF16、长度、batch、baseline 实现及模型规模等条件。重点说明算子比较没有包含完整模型开销，端到端数据绑定论文中的 Transformers baseline 和输入/输出长度，显存表也不能由单层 activation 估算直接推出。跨硬件、后续 kernel、服务负载或不同精度的结论需要重新测量；不把论文数字作为当前所有部署的性能承诺。
