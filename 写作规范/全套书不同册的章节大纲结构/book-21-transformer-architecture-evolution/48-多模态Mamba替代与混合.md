# 第 48 章 多模态模型中的 Mamba 替代与混合：视觉语言和长视频

本章聚焦状态空间模型（以 Mamba 为代表）进入视觉语言与长视频模型后的架构位置。它承接第 43 章对 Attention–SSM 混合的通用比较、第 44 章对模块信息路径的说明，但把问题落到视觉特征、模态连接、语言主干和长视频序列等具体路径；第 15 册已经完整主讲的视觉接口、统一多模态模型与 token 预算不在此重复。

## 48.1 先确定混合器位于哪条模态路径

“多模态模型使用 Mamba”可能指视觉特征编码、视觉到语言的连接器、语言模型主干或跨模态融合阶段，改变的位置不同，影响的对象和能力也不同。本节梳理这些架构位置及它们的职责，说明本章讨论视觉语言理解和长视频序列，不把模型服务流程或通用多模态系统设计混入架构比较。

## 48.2 用 Mamba 替换视觉语言模型的语言主干

Cobra、VL-Mamba 等路线保留视觉编码器并把 Mamba 语言模型作为解码主干，但在视觉特征组织和连接方式上并不相同；从已有 Transformer 多模态模型蒸馏出 Mamba 或混合主干又构成另一条转换路径。本节比较替换对象、连接器与预训练来源，并结合受控的 Transformer/SSM 视觉语言对照区分图像摘要、问答、阅读、定位和上下文检索任务上的结果，限定这些证据对应的模型规模与训练设置。

## 48.3 在视觉连接器中保留空间结构

图像 patch 原本位于二维网格，进入因果 SSM 主干前通常需要转成序列；扫描方向、空间边界标记和视觉 token 压缩因此成为连接器设计的一部分。VL-Mamba 的 Vision Selective Scan 与基于可学习 query、交叉注意力和 Mamba 的 Querying Mamba 代表不同处理方式：前者把视觉扫描机制纳入多模态连接，后者让 query 从任意位置读取视觉特征并形成适配语言主干的因果序列。本节比较二者改变了什么，以及空间对应、信息压缩和下游读取各自留下的限制。

## 48.4 在 SSM 融合前处理跨模态对应关系

直接拼接不同模态后交给 Mamba 扫描，可以共享一个融合主干，但顺序扫描本身不保证任意两种模态的细粒度 token 一一对应。AlignMamba 在 Mamba 融合前分别加入 token 级局部对齐和分布级全局对齐，展示了另一种处理路线。本节说明这些对齐机制与扫描融合的先后关系，并将其音频、视频、语言情感任务及缺失模态实验限定为特定表示融合证据，不推广成通用视觉语言模型结论。

## 48.5 长视频模型把视频混合与文本读取分开设计

长视频产生的视频 token 远多于文本指令，适合针对不同序列设置不同信息路径。VAMBA 让 Mamba-2 更新视频 token，同时由文本查询通过自注意力与交叉注意力读取视频；TimeViper 在混合主干之外加入层内视觉信息转移与 token 压缩。本节比较视频状态更新、文本对视频的可访问性以及压缩位置，明确这些设计仍保留 Attention 或交叉注意力，不等于用单一线性序列算子解决全部多模态关系。

## 48.6 按任务和证据判断替代与混合是否成立

不同研究支持的不是一个统一的 Mamba 优劣结论：概括图像的任务与需要精确定位、复制或检索证据的任务，对表示访问提出不同要求；短图像输入、长视频输入和音频视频融合也处于不同的序列规模与对齐条件。本节归纳如何把主张绑定到具体架构位置、任务、模型规模、数据与训练设置、输入长度和硬件测量，区分论文结果、作者解释与尚待验证的跨架构判断。
