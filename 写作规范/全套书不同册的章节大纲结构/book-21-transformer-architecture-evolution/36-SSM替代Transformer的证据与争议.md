# 第三十六章：SSM 会不会替代 Transformer：证据、争议与面试回答

本章围绕“SSM 会不会替代 Transformer”这一跨架构主张，说明公开证据能够支持到什么范围。重点是区分特定任务上的模型结果、纯 SSM 与混合模型、模型版本和实验条件，不将复杂度关系、某一基准成绩或单篇论文结论扩大为整个架构家族的胜负。第二十九至三十五章已经解释状态、信息路径、Mamba 与 SSD 的机制；第三十四章细讲 Mamba 的检索和 ICL 证据；本章负责把相关研究放在同一判断尺度上。第四十二章承担一般替代架构选择框架，第四十三章详讲 hybrid 结构，本章不重写其选型流程或混合实现。

## 36.1 “替代”主张的对象与范围

本节区分几类容易混为一谈的结论：某一 SSM 变体在特定任务达到竞争力、某类 workload 可以采用 SSM 主干，以及通用语言模型整体迁移到 SSM。比较对象还需分清纯 SSM 与含 attention 的 hybrid，因为后者的成绩不能归给纯 SSM。结论的范围受模型版本、参数规模、训练 token、数据与任务构造共同限定；结构关系本身不等于能力结果。

## 36.2 复杂度说明资源路径，不直接决定能力

本节连接前文的递归状态与显式 token 历史：固定状态更新提供紧凑的顺序处理路径，attention cache 保留逐位置表示并支持内容相关读取。复杂度可以说明序列变长时计算或状态规模怎样变化，却不能单独给出实际硬件速度、训练效率或任务质量。用“在线状态更新还是细粒度回看”作为读结果的机制线索，同时指出它是解释权衡的启发式，不是由架构名称推出的必然能力判断。

## 36.3 匹配规模实验中的任务差异与训练量变化

本节分析约 8B 规模 Mamba、Mamba-2 与 Transformer 的公开对照，覆盖共同训练数据、1.1T 与 3.5T token 设置及标准下游任务。重点说明纯 SSM 在部分任务平均值上的竞争表现与 MMLU 差距可以并存；更多训练 token 会改变部分差距，而 3.5T 设置并没有训练纯 Mamba。MMLU 的选项格式也影响比较，因此单一平均分或任务名称不足以代表同一种能力。

## 36.4 复制、检索与 ICL 证据回答的是不同问题

本节并置精确复制/电话簿查找中的困难，以及函数学习、NLP ICL 或 Markov 链预测中的正面结果，解释它们并不矛盾：一个任务要求保存并按 query 精确定位任意条目，另一个可能要求从上下文归纳规则或估计序列统计规律。“ICL”与“retrieval”都包含不同任务定义，行为结果不能直接充当内部机制证明。第 34 章已承担各任务设置和 Mamba 局限的完整讲解，本节只提取对跨架构判断有用的对照。

## 36.5 新版本与 hybrid 结果改变比较对象

本节考察 Mamba-3 在固定长度、真实数据及合成 retrieval 任务上的结果，说明后续版本能改善部分状态跟踪或召回能力，同时仍可能在另一些信息抽取任务落后于 attention baseline。再将纯模型与 Mamba-2-Hybrid 的 8B 对照分开：特定 hybrid 在多项任务上超过对应 Transformer，是混合方案的证据，不是纯 SSM 已取代 Transformer 的证据。生成速度估计、模型级任务结果和端到端服务测量保持各自的结论边界；hybrid 机制转交第四十三章。

## 36.6 面对开放题时给出有边界的结论

本节综合当前公开研究能确认的内容：SSM 已是若干序列任务和模型中的可行竞争路线，纯模型的比较表现依任务、训练量和版本而变，部分 hybrid 结果显示两种信息路径可以互补；现有证据尚不能推出通用 Transformer 生态会被 SSM 全面替代。面试回答应把架构判断绑定到已比较的模型和任务，并明确哪些部分是实验结果、哪些仍未验证；一般选型维度回链第四十二章。
