# 第四十二章：替代架构横向对比：复杂度、表达力、硬件和生态

本章把前面分别介绍的 dense/sparse attention、线性注意力、SSM/RNN、RWKV、RetNet 与卷积路线放进共同比较坐标：历史怎样保存、当前位置能怎样读取、计算与状态如何随序列长度变化、理论路径如何映射到硬件，以及公开资料与可复用实现能支持怎样的生态判断。各路线的算子推导由第二十四至第四十一章主讲；本章负责横向综合，不提供统一胜负排名或 serving 手册。检索、外部记忆和完整运行系统作为比较单位边界简要定位，attention+SSM 的具体组合交给第四十三章。

## 42.1 先对齐比较单位：算子、block、主干与完整系统

本节区分 kernel/执行算法、序列混合算子、模型 block/主干和包含外部检索或运行时的完整系统。FlashAttention 可改变 dense attention 的数据移动而保留其稠密交互，稀疏 attention 改变连接集合，线性注意力与状态空间路线改变历史汇总方式；这些改动属于不同层级。比较时须说明结论针对哪一级，避免把 kernel 速度、层复杂度和完整模型任务质量排在同一尺度上。

## 42.2 历史表示与查询路径：模型把过去保留成什么

本节对齐各路线保存历史的形式和当前 token 读取历史的方式：full attention 保留允许位置的 K/V 并由 query 计算内容相关权重；窗口或稀疏 attention 受连接图限制；线性注意力、递归网络、SSM、RWKV 与 RetNet 以各自不同的更新规则形成有限状态；卷积按相对位移组织历史混合并可叠加输入门控；hybrid 同时保留多类路径。固定状态、长感受野或存在计算路径本身都不等于相同的可寻址能力。

## 42.3 表达能力必须落到任务与训练证据

本节将“表达力”拆成局部预测、状态追踪、关联回忆/精确复制、多证据检索和语言建模等可区分任务。结构上的直接访问或压缩状态说明信息路径的差异，不能单独预测训练后的任务分数；合成理论、受控小模型、预训练模型和长上下文评测各自支持不同范围。涉及检索结果时核对模型版本、训练 token、上下文长度、prompt/任务构造和纯模型或 hybrid 身份，不把一个总分解释成架构家族的通用能力排名。

## 42.4 序列复杂度：训练、prefill 与逐 token 生成分开看

本节在声明固定宽度、head 数、状态维度和实现假设后，对比 dense attention、窗口/稀疏 attention、有限特征线性注意力、递归状态和卷积的序列项。内容分别说明完整序列计算的并行形式、单个新 token 面对长度为 T 的历史时要做的工作，以及缓存/状态随 T 的增长；对线性特征维度、SSM 状态维度、卷积核宽、稀疏边数和层内 projection/FFN 成本标明口径。渐近复杂度不代表总 block 成本、训练显存或实际延迟。

## 42.5 硬件与生态：理论路径怎样变成可运行资产

本节比较 dense 矩阵运算、parallel scan/递归更新、FFT 卷积与稀疏连接在内存访问、并行度、融合和 kernel 适配上的差异，并用 FlashAttention 与 Mamba 的原论文说明实现算法和硬件特性会改变实际结果。生态部分只定义可检查的公开信号，如固定版本源码、checkpoint 与 tokenizer、训练配置、框架支持、可用 kernel、转换路径、调试文档和维护状态；不推断当前行业采用率，也不把生态成熟度写成模型内部能力。

## 42.6 以条件化证据形成比较结论

本节给出读者判断新架构的比较顺序：先说明任务需要何种历史访问和状态行为，再对齐参数规模、数据与 tokenizer、训练 token/预算、上下文、评测、实现版本和目标硬件，最后分别报告质量、计算/状态代价与证据边界。输出应是带条件的候选判断，而非加权总分或单一排行榜。需要同时保留压缩状态与显式 attention 路径时，后续第四十三章继续分析混合架构的分工。
