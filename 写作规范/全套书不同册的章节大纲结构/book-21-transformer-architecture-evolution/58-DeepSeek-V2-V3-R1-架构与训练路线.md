# 第58章 DeepSeek-V2、V3 与 R1：MLA、MoE、MTP 和推理强化

本章将 DeepSeek-V2、DeepSeek-V3 与 DeepSeek-R1 作为版本化公开报告案例，考察 Transformer 架构、MoE 负载均衡、未来 token 预测目标与后训练路线各自承担什么作用。中心判断是：V2 与 V3 的架构沿用关系可以从报告中核对，R1 则主要是在 V3-Base 架构上的后训练系列；模型规模、架构变化、训练目标和评测结果不能合成一套未分版本的“DeepSeek 配方”。MLA、MoE 的通用机制分别由第四、十一、二十一和二十二章主讲，GRPO/RLVR 与 R1 后训练细节由第五册第十六章和第十六册第十七章主讲。

## 58.1 版本边界：从模型名称回到公开对象

本节确立 V2、V3、V3-Base、R1-Zero、R1 与 R1-Distill checkpoint 之间的关系。版本间名称相近不表示它们共享完全相同的训练阶段或公开事实；特别是 R1 与 R1-Zero 建立在 V3-Base 上，因此 R1 应作为后训练案例阅读，而不是另一个架构名称。

### 58.1.1 区分基础模型、指令模型与推理 checkpoint

说明 V3-Base、经过后训练的 V3，以及以 V3-Base 为基础的 R1-Zero/R1 各自处于哪一层；指出 R1-Distill-Qwen/Llama 是以不同稠密基座训练出的独立 checkpoint。读者需要据此避免将版本名、模型结构和训练阶段混为一谈。

### 58.1.2 将数字和结论绑定报告、配置与评测口径

界定总参数、每 token 激活参数、上下文长度和训练 token 数为特定报告字段，不由这些数字直接推出权重常驻量、服务延迟或跨模型能力排名。benchmark 与效率主张须保留发布方评测框架、模型版本及其条件。

## 58.2 DeepSeek-V2：MLA 与 DeepSeekMoE 的架构组合

本节说明 V2 如何在同一 Transformer 中结合注意力状态压缩与稀疏专家前馈网络。案例关注两种结构分别改变的信息与资源路径，并将一般原理留给前序主讲章节；V2 报告所列规模是定位版本的证据，不是独立的质量或部署成本指标。

### 58.2.1 MLA 的联合低秩 KV 表示与解耦位置键

概括 V2 将 key/value 内容压入共享低秩 latent，并为携带 RoPE 的位置相关 key 保留单独表示的结构。应明确缓存中仍有历史状态，attention 仍按模型机制读取历史；详细的 latent 投影、吸收计算与 MHA/GQA/MLA 比较由第四章和第十一章承担。

### 58.2.2 DeepSeekMoE 的共享专家与细粒度路由专家

说明共享专家和路由专家在 V2 FFN 路径中的分工，并记录技术报告公开的每个 MoE 层专家配置与每 token 路由规模。token 路由、专家计算及通信机制回链第二十一、二十二章，避免将参数稀疏直接等同于总权重驻留或端到端成本下降。

### 58.2.3 V2 报告数据能说明什么

以 V2 报告公开的总参数、激活参数与 128K 上下文定位案例，说明这些数值对应报告中的特定模型和扩展设置。作者报告的 cache、吞吐或基准优势只能按原比较条件解读，不外推为 MLA/MoE 的普遍收益。

## 58.3 DeepSeek-V3：沿用架构并改变负载均衡方案

本节将 V3 的结构连续性和新变化分开：它采用经 V2 验证的 MLA 与 DeepSeekMoE，同时披露新的 expert routing 负载均衡策略和 MTP 训练目标。模型总量和激活量帮助描述规模变化，不能替代匹配条件下的训练或推理成本比较。

### 58.3.1 V2 到 V3 的结构继承与规模变化

概括 V3 保留 MLA 与 DeepSeekMoE 的基本架构位置，并记录报告中的总参数、每 token 激活参数和预训练 token 口径。章节不将规模变化解释为某项能力或效率增长的单一原因。

### 58.3.2 Auxiliary-loss-free routing bias 与序列级辅助平衡

解释 V3 报告中的每专家 bias 如何参与 top-k 路由选择、原始 affinity 如何继续提供输出 gate，以及训练步结束时如何根据整批专家负载调整 bias；另说明极小的 sequence-wise auxiliary loss 用于降低单个序列内极端失衡。与一般 MoE 负载均衡机制的关系回链第二十一章。

### 58.3.3 报告中的 token dropping 与系统协同边界

记录 V3 技术报告称其训练和部署设置未丢弃 token，并将此结论限制在报告所述的负载均衡和部署策略下。FP8、DualPipe 与通信优化属于该报告的系统协同证据；完整训练系统、成本和部署性能由第五册及第二十二、二十四册主讲。

## 58.4 MTP：训练目标与推测解码不是同一件事

本节区分 V3 的 multi-token prediction 训练目标与推理阶段可选的模块复用。知识范围包括未来 token 监督、预测模块之间的因果依赖、训练目标可能提供的信号，以及报告允许与不支持的推理解释。

### 58.4.1 V3 的顺序预测模块与因果链

说明 V3 的 MTP 模块按预测深度顺序构成，并保持每个预测位置所依赖的完整因果链；这不同于若干独立 head 并行预测互不依赖的未来 token。MTP 是对主干隐状态和未来 token 监督关系的扩展，不是模型可同时无条件输出多个最终 token 的证明。

### 58.4.2 训练目标、作者解释与消融范围

说明 MTP 在当前位置增加未来 token 预测信号，报告作者将其动机联系到训练信号密度、数据效率和未来表示规划。报告内消融只能支持其模型、训练配置与评测中的观察，不证明所有模型采用 MTP 都会获得相同收益。

### 58.4.3 推理时丢弃模块与可选 speculative reuse

说明 V3 主模型可以在推理时不携带 MTP 模块，报告也提出把模块复用到 speculative decoding 的路径。训练辅助目标、draft 候选生成、target verification 与接受/回滚协议属于不同层次；运行时是否复用和实际收益须由具体推理实现验证。

## 58.5 R1：V3-Base 架构上的两种后训练路线

本节把 R1 系列的架构基座与推理后训练分开，呈现 R1-Zero 和完整 R1 各自的训练路径。这里只覆盖报告支持理解版本关系的关键节点；GRPO 推导、verifier 设计和 R1 训练细节由第五册第十六章和第十六册第十七章展开。

### 58.5.1 R1-Zero：不经预先 SFT 的直接 RL 案例

说明 R1-Zero 从 V3-Base 开始，在没有先做监督微调的条件下使用 RL；其规则奖励包含数学、代码和逻辑任务的答案正确性与格式要求，论文将优化器说明为 GRPO。作者报告的 reasoning 变化与 readable output、重复和语言混杂问题都限于该路线与论文评测，不能解释为通用 RL 规律。

### 58.5.2 完整 R1：冷启动、采样筛选、混合 SFT 与第二轮 RL

呈现公开的阶段关系：少量冷启动推理示范、第一轮 RL、从 checkpoint 采样并筛选推理轨迹、加入非推理数据进行 SFT、以及第二轮 RL。说明后续阶段扩展了任务与反馈来源，包括推理任务的规则奖励、一般任务的模型奖励和语言一致性信号；完整算法、数据与奖励细节链接到第五册和第十六册主讲内容。

### 58.5.3 从作者报告中保留结果与限制的并存

区分论文对 benchmark、训练阶段和输出行为的作者报告，与独立复现或通用能力结论。特别保留 R1-Zero 可读性、重复和语言混杂等作者记录的问题，以及 R1 评测受模型、提示、任务、采样和评分设置约束的边界。

## 58.6 R1 蒸馏 checkpoint 与版本化证据汇总

本节说明 R1 生成的推理数据如何用于训练不同基础架构的稠密学生模型，并汇总 V2、V3、R1-Zero、R1 和蒸馏版本在结构与训练上的差异。它帮助读者把公开证据放回正确层次，不把不同报告或 checkpoint 的数字拼成统一排名。

### 58.6.1 Qwen/Llama 蒸馏模型不是 R1 主模型的架构复制

说明公开的 Distill-Qwen/Distill-Llama checkpoint 基于 Qwen2.5 与 Llama 系列稠密模型，并用 R1 生成的数据进行监督微调；论文没有在这些蒸馏模型上继续报告同一套 RL 阶段。区分学生架构、教师生成数据和 R1 主模型的 V3-Base 架构。

### 58.6.2 V2、V3、R1 与 Distill 的公开证据矩阵

按版本列出架构延续或改变、训练路线、报告直接披露的字段与仍未知的生产/实现信息。矩阵用于限定比较问题，不对不同版本的 benchmark、自报成本或模型大小作跨报告排行榜判断。
