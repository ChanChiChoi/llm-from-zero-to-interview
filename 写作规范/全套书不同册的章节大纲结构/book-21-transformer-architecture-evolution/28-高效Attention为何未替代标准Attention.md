# 第二十八章：高效 Attention 为什么没有完全替代标准 Attention

本章综合第 20 章的 dense attention 执行优化以及第 24—27 章的核/线性与稀疏路线，围绕一个区别展开：高效方法改变的可能是数据搬运、可见交互、attention 算子或历史缓存，所节省的资源和所改变的语义并不相同。读者应能说明各路线的主要成本、保留的计算对象和适用边界，并理解渐近复杂度不能单独决定替代关系；第 29 章再展开状态空间模型的状态更新。

## 28.1 不同路线，优化不同账目

本节厘清“高效 attention”不是一个统一算法类别。需要区分保持 dense attention 运算而减少中间数据搬运的实现路线、减少 query-key 交互的稀疏路线、以特征映射或状态分解改写 attention 计算的线性路线、只压缩历史 KV 存储的路线，以及降低训练激活存储的可逆层/前馈分块；这些方法省下的资源不同，后两类都不必然减少 dense attention 的配对计算。分类用于明确比较对象，不声称互斥或穷尽。

## 28.2 精确 dense attention：保留交互图，改变数据路径

本节说明 FlashAttention 一类 IO-aware 方法为何可以减少中间 score/probability 矩阵的物化和 HBM 往返，同时仍计算 dense query-key 对并保留原 attention 数学运算。需要区分算法层的精确、浮点执行差异、额外重算、二次配对计算与硬件相关的实际耗时；online softmax 的完整推导和 kernel 版本细节分别由第 10、20 章承担。

## 28.3 稀疏 attention：削减交互，依赖连接先验

本节把 local/global、random、block-sparse 与 LSH 等路线共同放在“候选 key 集合如何确定”这一问题下，说明减少交互意味着哪些信息路径被限制或保留。方法效果取决于任务所需的远近关系、连接图或选择过程，不能因复杂度较低就推断任务质量不变。Reformer 的可逆残差和前馈分块另行减少训练激活存储，不改变 attention 候选集合；具体 pattern、块映射和 Longformer/BigBird/Reformer 机制分别回链第 19、26、27 章。

## 28.4 线性/核路线：分解 attention 并承担算子边界

本节概括通过结合律、有限特征映射或随机特征估计实现较低序列增长成本的路线，并区分对选定 kernel 的精确重排与对标准 softmax attention 的近似。复杂度依赖固定特征宽度、因果状态和具体方法假设；采用这些路线意味着接受相应表达、误差和访问方式边界，而非自动取得与 dense softmax 相同的输出。推导、状态递推和 FAVOR+ 保证由第 24—25 章主讲。

## 28.5 替代判断要绑定任务、设备和保留的能力

本节综合上述路线，解释选择取决于任务需要的访问关系、输入长度和流式要求、硬件和实际瓶颈，以及质量允许的语义变化。强调不同路线可以组合，效率类别不是互斥阵营；KV cache 压缩、SSM 状态和 Reformer 可逆层分别作用于不同资源，在此仅标出边界，状态空间模型的机制交给下一章，系统服务细节和跨架构横向比较回链第六册、第二十四册及本册第 42 章。结论不推断当前行业采用率，也不把某篇论文的 speedup 推广为普遍结果。
