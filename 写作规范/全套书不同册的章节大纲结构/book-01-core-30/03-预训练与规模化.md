### 从训练目标到可交接的 base model

前两部分已经给出 Transformer 和 next-token 目标。现在把视野从一次前向扩展到整场训练：团队先选定模型要服务的任务，再取得并处理语料，把文本转成训练样本，配置优化和计算系统，最后通过 checkpoint 与评估决定哪一版值得交给后训练。

### 什么是预训练

对 decoder-only 语言模型，预训练通常是在大量 token 序列上最小化 next-token 负对数似然。模型会拟合训练语料中的统计规律，并可能在下游任务中表现出语言、知识、代码或推理能力；这些表现仍需用独立评估验证，不能仅从训练目标推出。

### 预训练总流程

简化的预训练流程依次经过目标定义、数据收集与清洗、tokenization、训练运行和 checkpoint 评估。

### 第一步：明确模型目标

训练前先说清模型要做什么：通用聊天、代码生成、数学推理、多语言、专业问答或多模态理解，对数据配比、tokenizer、模型规模、上下文长度和评估集的要求都不一样。目标还会影响之后采用哪种后训练策略，所以最好先定目标，再谈模型和数据预算。

### 第二步：收集原始数据

预训练语料可能包含网页、书籍、论文、百科、新闻、论坛问答、代码、数学、多语言材料和合成数据。来源不同，质量和覆盖面也不同。

### 第四步：去重和污染检测

### Base Model 为什么不能直接聊天

即使在提示词里问 base model 一个问题，也不代表它已经学会稳定的助手行为。它可能继续补全文档、模仿网页格式、不遵循用户指令，或在该拒答时继续作答。

### 一个可手算的预训练账本

假设训练计划消费 1T 个 token，序列长度为 2048，global batch size 为 512 个序列，并且每个位置都参与 loss，那么每次 optimizer update 对应 2048\times512=1{,}048{,}576 个目标 token，约需 95.4 万次更新。若有 padding、被 mask 的标签、尾块丢弃或恢复时重复读取，输入 token 数与实际参与 loss 的目标 token 数会不同，账本要分别记录。

### 16 讲·怎样判断一次预训练是否值得交接

流程图能帮我们看到环节，却不能证明各环节都按预期工作。训练时出现 loss 突升或 NaN，应先核对当前 batch、有效标签数、学习率、梯度范数和数值精度；tokens/sec 低时，profile 数据输入、计算与通信等待，不能只看 GPU 利用率；validation loss 下降而某领域能力回退时，则要固定评估口径，查看领域切片和数据变化。

## 第 17 讲：数据质量与 Scaling Law

本讲从“预算有限时，模型大小和数据量怎样配”切入，再通过“什么是 Scaling Law”“参数量、数据量、计算量”逐步展开，最后以“用同一组条件读懂规模实验”收束。

### 预算有限时，模型大小和数据量怎样配

第 16 讲把训练走成了一个流程，但流程本身没有回答预算该怎样分配。给定有限计算量，我们可以训练更大的模型、喂更多 token，或先改善数据质量；这些选择会怎样影响验证损失和目标能力？

### 什么是 Scaling Law

Scaling law 是用经验拟合描述模型规模变量与语言建模 loss 之间的规律。经典实验观察到，在没有被其他资源变量卡住的范围内，held-out cross entropy 会随参数量、数据量和训练计算近似按幂律变化；这是特定 Transformer、语料和训练范围内的实验规律，不等同于下游能力的通用增长定律。

### 参数量、数据量、计算量

参数量影响模型容量，训练 token 数决定模型看过多少数据，计算预算则限制这两项能做到多大。三者要一起规划：模型很大但数据太少，参数可能没充分训练；数据很多而模型太小，容量可能接不住复杂模式；计算不足时，两边都无法充分利用。

### Compute-Optimal Training

在固定计算量下，问题是：参数量和训练 token 数应该怎么分配？

### 数据质量为什么重要

数据不是越多越好。

### 数据配比

Data mixture 是预训练中的关键问题。

### 数据重复和记忆

重复曝光会改变样本的实际抽样权重；大量近重复还可能增加记忆和训练/评估重叠风险。Lee 等人在其 C4 与特定模型实验中报告，去重后模型未提示时复现训练文本的频率约下降一个数量级；这一结果说明应检查重复度，不证明所有重复样本都会伤害每个任务。

### 17 讲·Benchmark Contamination

如果评估样本或其答案进入训练数据，模型可能利用见过的内容；但发现文本重叠本身还不足以证明模型记住了答案或分数一定被抬高。

### Scaling Law 的局限

Scaling law 通常拟合的是 validation loss，不是所有下游能力。loss 下降不一定表示 reasoning 也提升；数据质量、后训练、多模态任务、安全行为和 test-time compute 都会改变模型表现。

预训练里常用 C\approx6ND 粗估 decoder-only Transformer 的训练计算量，其中 N 是非 embedding 参数量， D 是训练 token 数；这种估算依赖 dense Transformer 等近似假设，不是精确 profiler。Kaplan 等，2020 给出每个训练 token 约 6N 的非 embedding FLOPs 估算；Chinchilla 论文也采用该近似构造 compute-optimal 前沿。

### 把预算关系变成可检验的选择

Scaling law 的价值不在于给出一个脱离语境的“最佳参数量”，而在于帮助我们排除明显不合理的预算分配。先用 C ≈ 6ND 做量级估算，再对参数量、token 数和数据质量做小规模实验；如果只改变模型大小而不记录有效数据量，实验就无法回答“容量不足”还是“训练不足”。

### 用同一组条件读懂规模实验

规模规律描述的是特定实验范围内参数、token、计算与 held-out loss 的关系。它能提醒我们要共同规划模型大小、数据量和预算；不能推出参数越大所有能力都越强，也不能解释 reasoning、安全、多模态或 Agent 等全部能力。

### 17 讲·Scaling Law 资料边界

经典 scaling law 的 held-out cross entropy 拟合见 Kaplan et al., 2020，compute-optimal 参数/token 关系见 Hoffmann et al., 2022。两者的实验结论都依赖各自的模型族、数据和预算设定。

## 第 18 讲：分布式训练基础

本讲从“单张卡放不下时，切分什么”切入，再通过“为什么需要分布式训练”“显存粗略构成”逐步展开，最后以“哪种切分适合当前瓶颈”收束。

### 单张卡放不下时，切分什么

前两讲分别确定了训练流程和预算关系。即便总 FLOPs 估算合理，一张 GPU 也可能装不下模型参数、激活、梯度与优化器状态，或者训练速度无法接受。

### 为什么需要分布式训练

大模型训练常遇到两种限制：参数、梯度、优化器状态、激活和临时 buffer 放不进一张卡，或者单卡训练耗时太长。以 AdamW 为例，优化器还要保存一阶和二阶矩，所以训练显存远大于只保存模型权重时的占用。

### 显存粗略构成

训练显存至少包含模型参数、梯度、优化器状态和激活值；实际峰值还受临时工作区与并行通信缓冲区影响。

### Data Parallel

Data Parallel 是最直观的并行方式。

### DDP 如何工作

DDP 是 PyTorch 的 DistributedDataParallel 实现，常见配置是每个训练进程绑定一张 GPU。

### ZeRO 解决什么问题

ZeRO 的核心思想是：不要让每张 GPU 都保存完整训练状态。

### FSDP 是什么

FSDP 是 Fully Sharded Data Parallel。PyTorch 2.14 同时有传统 FSDP API 与以 fully_shard 为入口的 FSDP2 API；以下讲的是它们共享的全分片思路，不把不同版本的调用接口混为一谈。

### 张量并行（Tensor Parallel）

张量并行（TP）把同一层的大矩阵计算切分到多张 GPU。

### 流水线并行（Pipeline Parallel）

流水线并行（PP）把前后相接的模型层放到不同 GPU；一段连续层组成一个 stage（阶段）。

### 三维并行（3D Parallelism）

这三种并行可以放在同一套设备布局里。用 8 张 GPU 看一次，先按 \mathrm{DP}=2 分成两份相同的模型布局，每份处理不同的数据；每份有 4 张卡。

### Activation Checkpointing

训练时反向传播需要保存激活。

### 通信开销

分布式训练不是 GPU 越多越快。

### 设备拓扑决定并行取舍

并行方式会把不同 collective 放到不同位置：TP 在层内切分矩阵，频繁交换中间结果，通常更依赖快速互联；PP 主要在 stage 边界 send/recv 激活和梯度，并会出现填充/排空 bubble；DDP 保留完整副本状态并在反向阶段同步梯度；FSDP/ZeRO 通过 all-gather 与 reduce-scatter 交换分片状态。

### 用显存账本和通信剖析选择并行方式

分布式策略的选择可以从两个问题开始：哪个状态放不下，以及哪种通信会成为每一步的关键路径。若模型副本本身能放进单卡，DDP 往往是最简单的基线；若 optimizer state 和梯度占据主要空间，ZeRO-1/2 或 FSDP 可能更合适；若单层矩阵就无法容纳，则必须引入 Tensor Parallel；层数很多且设备间带宽允许时，再考虑 Pipeline Parallel。

### 哪种切分适合当前瓶颈

DDP 是数据并行的一种做法：每张卡保留模型副本，切分数据并同步梯度。ZeRO/FSDP 通过分片训练状态节省容量；Tensor Parallel 把单层计算切开，Pipeline Parallel 把不同层放到不同设备。

### 18 讲·分布式训练资料边界
