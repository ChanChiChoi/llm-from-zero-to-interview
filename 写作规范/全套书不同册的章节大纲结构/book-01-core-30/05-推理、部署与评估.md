## 第 24 讲：推理采样策略

本讲从“模型给出分布之后，怎样选下一个 token”切入，再通过“推理时模型输出什么”“Greedy Decoding”逐步展开，最后以“练习：从分布推到输出行为”收束。

### 模型给出分布之后，怎样选下一个 token

训练好的自回归语言模型每一步都会给出下一 token 的 logits。解码策略可以直接选择一个 token，也可以缩放、过滤分布后再抽样；选出的 token 又会进入下一步上下文。

### 推理时模型输出什么

自回归语言模型每一步输出 logits。

### Greedy Decoding

Greedy decoding（贪心解码）每一步都选择当前条件分布中概率最高的 token。

### Sampling

Sampling（随机采样）是按当前 token 分布抽取下一个 token。经过 temperature 或候选过滤后，应先对保留项重新归一化，再按新分布抽样。

### Temperature

Temperature（温度）用来缩放 logits，再通过 softmax 得到采样分布。

### Top-k Sampling

Top-k sampling 只保留概率最高的 k 个 token，把其余 token 的概率置零，再对保留项重新归一化并采样。

### Top-p Sampling

Top-p sampling 也叫 nucleus sampling（核采样）。

### Top-k 和 Top-p 的区别

### Beam Search

Beam search（束搜索）维护多个候选序列，每一步扩展后保留累计序列分数较高的若干条。常见分数是 token 对数概率之和，具体生成配置还可能加入长度惩罚等修正；有限 beam size 并不保证找出全局最高分序列。

### Decoding 参数如何影响幻觉

温度和候选过滤改变的是模型已有 logits 到下一 token 的选择过程，并不会检索或验证事实。较高温度会提高非最大 logit token 的相对概率；较宽 top-p 会允许更多尾部候选参与抽样，但两者是否提高某个评测集的错误率，必须按模型、提示、任务与评分规则实测。

### 不同任务的参数选择

参数不是任务标签对应的固定配方，而是待验证的假设。先固定模型、提示集、停止条件与 token 预算，再比较少量候选配置；若比较随机采样，每种设置都要重复运行并报告随机种子或重复次数。

### 多样性、一致性与成本的评估

“稳定”与“多样”不是单一质量轴。固定设置可能提高复现性，却不保证正确；增加候选可能提高找到合格答案的机会，却增加生成 token、打分计算和服务成本。

### Best-of-N 和 Self-Consistency

Best-of-N 是先生成 N 个候选，再由选择器挑一个；选择器可以是规则、外部 verifier 或 reward model。Self-consistency 是面向多条推理路径的候选聚合方法，通常先提取最终答案，再按答案一致性投票或聚合；它不等于逐字比较推理过程，也不必然依赖独立 reward model。

#### 坑 1：把某一任务的配置照搬到所有任务

低 temperature 会让即时分布更集中，但不能保证事实正确。

#### 坑 4：混淆控制 token 与运行时停止条件

EOS/end-of-turn、最大 token 数和 stop string 由不同层控制；配置不匹配会造成截断或轮次边界错误。

### 25 讲·KV Cache 的对象

对使用标准 Transformer 因果自注意力的自回归模型，推理不是简单地“跑一次 forward”。模型要逐 token 生成；如果每一步都从头计算完整上下文，前面位置的大量工作会重复。

### 自回归推理为什么慢

### Latency 和 Throughput

推理系统常看两个指标。

### Batching

Batching 把多个请求合并到一次模型执行里，通常能提高吞吐并更充分地利用 GPU，也可能降低单位 token 的成本。代价是请求要等待凑批，不同长度的请求更难调度，KV Cache 管理也更复杂；吞吐提升不一定能换来更低的单请求延迟。

### Dynamic Batching 和 Continuous Batching

Dynamic batching 会在短时间窗口内收集请求组成 batch。

### 从单请求指标到批服务指标

单请求的 tokens/sec 不能直接推断服务能力。设请求 i 的到达时间为 a_{i}、首 token 时间为 f_{i}、完成时间为 d_{i}，则可以分别记录 \mathrm{TTFT}_{i}=f_{i}-a_{i}、端到端延迟 d_{i}-a_{i} 和输出 token 数。

### PagedAttention

PagedAttention 借鉴操作系统分页，把每条序列的 KV Cache 切成固定 token 数的逻辑 block，再用块表（block table）映射到 GPU 上不连续的物理 block。注意，PagedAttention 指 attention kernel 按映射读取这些 block；分配与回收由 KV cache manager 管理，请求何时进入或退出批次由 scheduler（调度器）决定。

LLM 推理瓶颈取决于阶段。

### 降低首 Token 延迟

TTFT 受 prefill 影响大。

### 提高 Decode 吞吐

提高 decode 阶段吞吐可以尝试以下方向，但收益取决于瓶颈所在，检查步骤见下列清单。

### KV Cache 的代价

KV Cache 用显存保存历史 K/V，换取少做重复计算。上下文越长、并发请求越多，占用就越大；分配碎片和缓存读取带宽也可能成为瓶颈。

### 25 讲·服务现场的缓存故障

本讲从“坑 1：只估算模型权重显存”切入，再通过“坑 2：忽略请求长度分布”“坑 3：batch 越大越好”逐步展开，最后以“坑 5：max_tokens 设置过大”收束。

#### 坑 1：只估算模型权重显存

部署时不仅要放权重，还要给 KV Cache、激活、workspace 留显存。

#### 坑 2：忽略请求长度分布

平均长度不代表峰值。少量超长请求可能占用大量 KV Cache。

#### 坑 3：batch 越大越好

Batch 大提高吞吐，但可能增加延迟，并占用更多 KV Cache。

#### 坑 4：没有区分 prefill 和 decode

两个阶段瓶颈不同，优化方法也不同。

#### 坑 5：max_tokens 设置过大

max_tokens 限定一次请求最多能生成多长，不代表分页引擎一定会在开始时预分配全部 KV Cache；但更长的输出会逐步占用更多 block，并让请求更久地留在服务中，影响 admission 和并发预算。应按业务需要设上限，再用真实长度分布测量容量和尾延迟。

### 用容量曲线定位 KV Cache 瓶颈

KV Cache 的收益和代价应放在同一张曲线上观察。对每个请求记录 prompt token 数、生成 token 数、峰值缓存长度、TTFT、TPOT 和被调度时的 batch 宽度；再逐步增加并发，观察吞吐何时饱和、P95 延迟何时陡升。

### 为什么 FlashAttention 省显存

FlashAttention 不把完整的 attention score 和 probability 矩阵留在显存里；反向传播时，它保留输入、输出和逐行 log-sum-exp 等必要信息，再按 tile 重算局部 score、probability 和梯度。它因此少保存大量中间状态，但要多做一部分计算；节省的是 attention 中间存储，不是整场训练的全部显存。

### 为什么 FlashAttention 更快

当 HBM 读写和中间矩阵是主要开销时，FlashAttention 可以通过减少数据往返、复用 SRAM/register 中的 tile，并把相关计算融合到 kernel 里来提速。短序列、小 batch、不支持的 dtype，或模型其他部分成为瓶颈时，这些收益可能很小，甚至被额外开销抵消。

### FlashAttention 与训练

训练时 FlashAttention 常有价值，尤其当长序列 attention 的中间激活或显存访问限制了训练时；实际收益仍须在目标 shape、dtype 和 GPU 上测量。它省下的中间存储可让某些配置容纳更长序列或更大 batch，但不会自动消除模型其他部分的显存成本。

### FlashAttention 与推理

Prefill 一次处理 prompt 中的一段序列，query 轴通常比单 token decode 更长，因而 dense attention kernel 的 tile 计算和中间矩阵节省可能更明显；是否降低端到端首 token 延迟（TTFT），仍取决于队列、调度、其他层、kernel 覆盖和输入长度。

### Weight-Only Quantization

Weight-only quantization（仅权重量化）是只把权重存为低位宽格式，activation 仍可使用 FP16/BF16 等较高精度。它常用于权重容量或权重搬运是主要瓶颈的 LLM 推理，但不是所有场景的默认最优方案。

### PTQ 和 QAT

PTQ：Post-Training Quantization。

### GPTQ 的直觉

先用一个两权重的小层看“补偿”在做什么。设输出是 y=x_{1}w_{1}+x_{2}w_{2}，原权重为 (1,1)；两条校准输入 (1,1)、 (2,1) 的原输出分别是 2、 3。

### AWQ 的直觉

看一个两通道的手算例子。线性层输出为 y=x_{1}w_{1}+x_{2}w_{2}，输入是 (100,1)，权重是 (0.02,1)，所以原输出为 3。

### INT8 和 INT4 如何选择

在相同量化码本、粒度和校准条件下，INT8 可用的整数等级多于 INT4，通常能给单个权重提供更细的量化步长；模型质量差异仍取决于误差校准、层敏感性、任务、实现和 kernel，必须实测。

量化不一定必然加速。

### 量化和 KV Cache

权重量化主要降低模型权重显存。

量化模型上线前可以分四层验证。第一层是数值层：比较权重反量化误差、logits 差异和困惑度。

### 27 讲·从部署症状判断量化代价

量化方案出问题时，先看症状来自哪一层。权重文件变小但服务仍无法启动，通常是只算了权重 payload，遗漏 KV Cache、activation、workspace、量化元数据或显存碎片；INT4 模型能加载但速度更慢，可能是 kernel 覆盖不足或反量化开销抵消了带宽收益；校准集上的误差很低、真实请求却退化，说明校准分布没有代表业务输入；通用 benchmark 持平但 JSON、工具调用、代码或数学失败率上升，则是评估切片不匹配；平均延迟改善而 P95/P99 恶化，也不能据此判定服务变快。

## 第 28 讲：幻觉、评估与安全

本讲从“28 讲·可靠性问题的对象”切入，再通过“什么是幻觉”“幻觉为什么会发生”逐步展开，最后以“28 讲·事实性与安全复核实验”收束。

### 28 讲·可靠性问题的对象

大模型不仅要“会回答”，还要“答得对、答得稳、答得安全”。幻觉、评估和安全之所以重要，是因为它们把模型的语言能力连接到证据、风险和真实用户后果；本讲将把这些问题拆成可以复现实验和持续监控的指标。

### 什么是幻觉

“幻觉”在不同论文和评测中的口径并不完全相同。为了让本讲的测试可复现，我们把它操作化为：模型对可核验内容作出错误断言、违背给定证据，或把没有证据支持的推断表述成已确认事实。

### 幻觉为什么会发生

核心原因之一：语言模型训练目标是 next-token prediction，不是事实验证。

### Helpful 和 Honest 的张力

模型被训练成 helpful，可能会倾向于回答用户问题。

### 如何降低幻觉

没有单一方法能完全消除幻觉。

### 大模型评估为什么难

评估 LLM 很难，因为，检查步骤见下列清单。

### 28 讲·Benchmark Contamination

Benchmark contamination（基准污染）通常指评测题目、答案或其近似版本进入模型训练数据。更广义的评估泄漏还包括开发者反复查看测试结果后调 prompt、阈值或候选方案，使测试集事实上变成了开发集。

### 自动评估和人工评估

自动评估，检查步骤见下列清单。

### LLM-as-a-Judge

LLM-as-a-Judge 用语言模型按给定 rubric 评价开放式回答。它适合生成候选评分和解释，是否能用于回归或放行仍要在目标任务上验证。

### 一个引用支持率的审计例子

假设回答包含五个可独立核验的断言，其中三个被引用段落实际蕴含，一个虽与文档主题相关但推论超出证据，另一个没有可追溯来源。若把每个断言按“被证据充分支持/未被充分支持”计数，支持率为 3/5=0.60；只看“引用存在”会掩盖后两种情况。

### 安全对齐

安全对齐目标是让模型在保持有用性的同时，避免造成伤害。

### Jailbreak

Jailbreak（越狱）指输入诱导模型绕开预期的安全限制。OWASP LLM01:2025 将 jailbreak 视为 prompt injection 的一种：测试时常用“直接用户输入试图绕过策略”作为工程分类，但 direct/indirect 还描述输入来源，两个分类维度会重叠。

### Prompt Injection

Prompt injection（提示注入）是输入内容改变模型预期行为的风险。直接注入来自用户输入；间接注入藏在网页、文件、图像或工具返回内容中，常见于 RAG 与 Agent。

### Red Teaming

Red teaming 是系统性寻找模型风险和漏洞的过程。

### Robustness

鲁棒性指模型面对扰动、改写、噪声、分布外输入时表现稳定。

### 风险分层与帮助率的联合评估

安全评估至少要区分风险对象和期望动作，再用相应分母算指标，涉及对象和取舍见下表。

### 从“模型会说”到“系统可信”的评估闭环

幻觉评估不应只问答案是否像人话，而要把任务拆成证据、结论、行动和后果。对事实问答，可以分别记录证据召回率、引用支持率、结论正确率和无证据断言率；对工具任务，还要记录参数 schema、权限检查、工具返回值使用和最终状态是否正确。

### 28 讲·事实性与安全复核实验

本节通过具体检查项落实方法：给出 5 个不同类型的幻觉例子；设计一个事实性评估集，说明数据来源和评分方式。

### 28 讲·评估与安全资料边界

事实性、偏见、鲁棒性和安全评估没有一个足以覆盖全部风险的单一基准。TruthfulQA（Lin et al., 2021）可作为事实性研究入口，HELM（Liang et al., 2022）可作为多维评估入口；OWASP LLM01:2025 Prompt Injection讨论直接与间接注入风险以及权限最小化等缓解措施。
