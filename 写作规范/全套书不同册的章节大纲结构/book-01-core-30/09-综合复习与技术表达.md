# 第 9 章：综合复习与技术表达

把全书机制用于开放技术问题、陌生变体和面试追问；读者需用任务契约、基线、实验、证据、成本和边界说明自己的判断。

## 第 37 讲：开放技术问题的系统拆解

本讲从“37.1 闭合问题与开放问题”切入，再通过“37.2 先写任务契约，再讨论方案”“37.3 症状、机制与根因”逐步展开，最后以“37.12 技术判断应留下什么证据”收束。

### 37.1 闭合问题与开放问题

闭合问题有相对明确的对象和答案空间，例如“为什么因果语言模型训练时要错开输入和目标 token”“KV Cache 缓存了什么”。回答时讲清机制、形状和限制，通常就能说明问题。

### 37.2 先写任务契约，再讨论方案

一个可用的任务契约至少要写清输入、期望结果、失败定义、运行约束、判断证据和失败处理。写成一页表格即可，不需要先创造新的评分公式，涉及对象和取舍见下表。

### 37.3 症状、机制与根因

同一个表面症状可以由不同环节造成。知识助手答错可能是源文档过期、索引没有刷新、检索排序不对、提示丢了版本信息、模型忽略了证据，也可能是引用解析或评估标签出错。

### 37.4 用最小实验区分当前假设

排查不是先挑最复杂的方法，而是先找能区分当前假设、成本可接受的检查。按顺序问，检查步骤见下列清单。

### 37.5 完整示例：知识助手引用了旧版流程

假设一名员工问：“设备 E17 报错后还能继续运行吗？”助手引用了旧版手册。

#### 第一步：确认影响和基线

固定同一组失败请求，记录当前和旧模型版本、索引快照、提示、解码设置、工具、原始输出和引用链接。先人工确认“引用旧版流程”确实违反本次任务目标，并标出对应的当前有效文档。

#### 第二步：对照各环节的输入输出

表格按“检查位置、结果 A、结果 B、下一步”组织本节要核对的对象和差异。

#### 第三步：选一处改动并建立回归

如果证据显示新文档没进入索引，先修入库和索引更新，不同时换模型。用原失败样本、新旧版本对照样本、相似问题和无答案问题回归，分别记录文档命中、回答正确、引用支持、拒答和延迟。

#### 第四步：向工程师说明结论

说明“当前证据将问题定位到索引刷新，修复并重放了固定回归集；相关问题已通过，仍需确认周期性更新和权限过滤”。如果还没有足够样本，就把结论说成暂定，并列明下一项验证。

### 37.6 示例：幻觉不是一个单一指标

把“回答有幻觉”直接当成一个比例，会把不同修复路径混在一起。对知识助手，可以按一条条可核对的陈述做审计，检查步骤见下列清单。

### 37.7 示例：设计统一多模态系统

“设计一个能处理文本、图像、语音和视频的模型”也不能直接落到“使用统一 Transformer”。先区分目标任务：实时语音对话关心首包延迟和打断，发票审核关心 OCR 和字段证据，视频检索关心时间覆盖，开放创作关心生成质量和安全来源。

### 37.8 新模型信息的证据等级

快速发布的模型容易造成一种错觉：只要记住模型名和宣传语，就掌握了最新技术。本节的 A—D 是本书为面试和研究记录采用的工作分类，不是行业标准；等级应贴到具体陈述及其来源上，不能给整个模型或发布打一个笼统等级。

### 37.9 质量、延迟、成本与安全的取舍

“质量更高、成本更低、响应更快”不是一个完整决策。要先说明哪些指标有硬门槛，再比较满足门槛的方案。

### 37.10 开放问题中的安全推理

安全不是开放题最后附加的一句“注意风险”。它应该在任务契约中出现：输入是否含有个人信息，输出是否会触发外部动作，错误是否可逆，证据是否可审计，谁有权批准高风险步骤。

### 37.11 从低成本验证开始

不需要把候选实验换算成一个看似精确的分数。把它们按“先查现成证据、再做隔离回放、最后才做昂贵改动”排队，并写出每一步会改变什么决定，涉及对象和取舍见下表。

### 37.12 技术判断应留下什么证据

一次开放问题分析至少应该留下四种产物，检查步骤见下列清单。

## 第 38 讲：学习迁移与技术表达

本讲从“38.1 “见过”不等于“会用””切入，再通过“38.2 用小任务安排复习”“38.3 用四种产物证明一个知识点”逐步展开，最后以“38.12 从“会说”到“能负责””收束。

### 38.1 “见过”不等于“会用”

阅读一个公式时产生的熟悉感，很容易被误认为掌握。真正遇到空白纸张、陌生题目或代码错误时，能否从定义重建公式、解释变量、写出 shape、预测失败模式，才是更强的证据。

### 38.2 用小任务安排复习

重读一遍会让内容看起来熟悉，但并不能说明自己能在没有资料时解释或排查。每次复习都安排一个能观察结果的小任务，按需要调整间隔，而不是先套固定日历，涉及对象和取舍见下表。

### 38.3 用四种产物证明一个知识点

为每个重要主题留下一种或几种能复核的学习证据。不同主题不必凑同样形式，具体的输入和结果见下文。

#### 解释产物

用自己的话说清它解决什么问题、改变什么对象、结果传给哪里。比如，不能只说“KV Cache 加速推理”，还要说明它缓存哪些历史计算、为何能省重复计算，以及缓存占用会随哪些模型和请求因素变化。

#### 推导或 shape 产物

不看原文重建必要公式，解释符号、尺寸和边界。对 Attention，要能沿 QK^\top 的维度说明 mask 和输出；对 DPO，要能解释 chosen/rejected 以及 reference 比较在目标中的作用。

#### 实现产物

用小数组或公开工具做最小实现，写清输入、输出、依赖和检查条件。调用框架 API 可以验证使用方式，但还要能说明关键张量和计算路径。

#### 失败产物

主动给方法一个会失败的输入：padding、重复数据、过期文档、错误工具结果、权限冲突或分布外请求。记录系统表现和下一步修复方向。

### 38.5 用一份可调整的学习计划落实主线

下面是十二周的安排样例，不是必须遵循的时间表。每周按自己的时间和基础调整；如果前置还没掌握，就先补齐再继续。

### 38.6 项目叙述是一条证据链

技术项目不能只写成“用了某模型，指标提升了”。可信说明要把问题、数据、方案、基线、测量、失败和下一步连成证据链；下文给出记录模板。

### 38.7 模拟交流应当是测量工具

模拟面试不是背熟一组答案。选一个没提前准备过的变体问题，限定回答时间，并请同伴继续追问方案的机制、证据、成本和失败条件。

### 38.8 错误日志要指向下一次动作

“这题不会”不是可执行的错误类别。更有用的分类包括，涉及对象和取舍见下表。

### 38.9 用未知变体做迁移评估

熟悉题目答得好，可能来自理解，也可能只是记住了题面。迁移练习改变输入或约束，同时保留要检查的核心机制，检查步骤见下列清单。

### 38.10 第一册的最终综合评估

读完第一册后，综合评估不应是把 38 个标题逐个朗读。更好的评估包含四个部分，具体的输入和结果见下文。

#### 机制重建

随机抽取一个核心对象，要求从定义写到公式和 shape，例如从 next-token 目标推到 cross entropy，或从 Q/K/V 推到 attention 输出。评分重点是变量关系和边界，而不是术语数量。

#### 实验设计

给出一个异常现象，例如“loss 下降但真实任务变差”，要求写出至少三个可区分假设、固定变量和结果解释。没有实验控制的方案建议只能算猜测。

#### 最小实现

在不调用大型模型 API 的情况下，写一个小实现验证 mask、log probability、cache 容量、对比损失或 token 预算。代码应有输入、输出、断言和已知失败案例。

#### 未知变体

对一个没有见过的模态、模型版本或系统约束，要求说明哪些事实已知、哪些只是推测、下一步如何核验。它测的是方法迁移，不是新闻记忆。

### 38.11 把复习记录变成下一步动作

每次复习后记录主题、题目变化、卡点和下一项动作。用简单表格即可，不需要先实现遗忘模型或自动调度器，涉及对象和取舍见下表。

### 38.12 从“会说”到“能负责”

技术表达的最后一层不是语言流畅，而是能够对判断负责。一个成熟的回答或报告应当让读者知道：结论是什么，依据是什么，哪些条件成立，哪里可能失败，下一步如何验证。

## 资料与证据边界

本章的企业知识助手、问题样本和排查结果均为教学构造，不代表真实企业部署、事故或性能数据。复习计划、项目表格与面试追问是用于练习的工作工具，不是经过验证的通用面试评分标准或学习效果保证。
