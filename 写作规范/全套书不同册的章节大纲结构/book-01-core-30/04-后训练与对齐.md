# 第 4 章：后训练与对齐

区分指令数据、SFT、RLHF/PPO、DPO 和 Reward Model 的训练信号、目标及适用条件；将行为变化与数据质量、代理目标和独立评估联系起来。

## 本文件的阅读路径

预训练给模型一个续写文本的能力，但这还没有规定它怎样回应用户、怎样处理角色边界，或在偏好冲突时选择哪一种回答。本文件从这个缺口往下走：先看指令和示范怎样成为监督目标，再看偏好怎样变成奖励或直接优化信号，最后检查代理分数是否真的代表任务目标。

## 第 19 讲：Instruction Tuning

本讲从“从续写文本到回应用户”切入，再通过“从 Base Model 到 Instruct Model”“Instruction Tuning 是什么”逐步展开，最后以“练习：检查一份指令训练数据”收束。

### 从续写文本到回应用户

预训练目标只告诉模型接下来哪个 token 常见，并没有告诉它在问答里应把用户消息当作任务。指令微调用带有指令和目标回答的样本继续训练，让模型学习“遇到这样的上下文时，目标回答是什么”。

### 从 Base Model 到 Instruct Model

Base model 的训练目标是 next-token prediction。

### Instruction Tuning 是什么

Instruction Tuning 通常指用“任务指令—目标响应”样本对模型做后训练。训练信号可以来自人工示范、经过筛选的公开任务数据或模型生成的数据；是否把它称为 SFT，取决于具体文献和配方。

### 为什么很多对话 SFT 只对 Assistant 目标算 Loss

在对话式监督微调中，模型要根据 system、user 和历史对话来生成 assistant 响应。若训练目标就是“给定上下文，模仿目标回答”，常见做法是把上下文 token 保留在 input_ids 中，却将这些位置的 labels 设为 -100，只让目标回答参与 loss。

### Chat Template

Chat template 把结构化消息序列化为模型训练或推理时使用的 token 序列。不同模型可以用不同控制 token 表示角色、轮次结束和工具交接；模板是输入协议的一部分，不是统一的聊天语法。

### 模板差分的最小实验

把同一条消息分别序列化成模板 A 和模板 B，先对照 token 数、控制 token、assistant 起始位置和结束标记，再用同一 checkpoint、同一解码设置比较首 token 分布、格式通过率和停止位置。差异是需要测量的结果，不应从单个模板差分推断成所有模型的固定规律。

### 指令数据类型

Instruction tuning 数据可以包括，检查步骤见下列清单。

### 数据质量、覆盖面与数量如何共同起作用

“数据质量比数量更重要”不是跨模型、任务和预算都成立的定律。有效监督既取决于目标回答是否正确、是否遵循约束，也取决于任务和表达方式的覆盖；增大数据量有时能扩展覆盖，有时也会带来重复、噪声或相互冲突的目标。

### Instruction Tuning 和 SFT 的关系

前面所说的 Instruction Tuning 是希望改善的行为目标；SFT（Supervised Fine-Tuning，监督微调）是用带目标输出的样本做监督训练的方法。二者常结合，但 SFT 也可用于非对话任务，指令微调也可能与偏好或其他训练阶段组合。

### Instruction Tuning、RLHF、DPO 的关系

一种常见但非必经的后训练路径会组合监督微调、偏好数据和策略优化；具体阶段及接口见下文。

### 单轮和多轮指令

单轮任务把用户指令映射为一条目标回答；消息序列示例见下文。

### System Prompt 的作用

System prompt 通常是序列化对话中用于提供较高优先级指令的消息，可向模型提供身份、风格或任务规则等上下文；具体角色优先级由模型和模板约定决定。它本身不是权限控制或安全隔离机制；模型是否按它执行仍取决于训练、模板、运行时策略和具体输入。

### 合成指令数据

合成指令数据可以减少逐条撰写的工作，也能围绕目标能力扩展样本；生成调用、去重过滤、质量审核和训练评估仍有成本。Self-Instruct 给出一个具体流程：用少量人工任务作种子，让 GPT-3 生成新任务及输入/输出，再过滤无效或相似样本。

### 指令微调的评估

评估要与训练时承诺改善的行为对应，不能只看训练 loss。可以固定 tokenizer、模板、提示和解码参数，在未参与训练的任务与多轮切片上检查指令遵循、事实、代码/数学、格式、拒答和长上下文表现；涉及偏好时，记录盲评人群、成对比较规则和分歧，而不是只报一个总体分数。

### 19 讲·指令数据的失败模式

本讲从“坑 1：训练和推理 chat template 不一致”切入，再通过“坑 2：loss mask 和训练目标不一致”“坑 3：数据太模板化”逐步展开，最后以“坑 5：只做 helpful，不做 safety”收束。

#### 坑 1：训练和推理 chat template 不一致

训练与推理格式不一致会改变模型看到的 token 序列，但具体影响随模型和模板而异。应核对 tokenizer/template 版本、generation prompt 和结束标记，再用固定 checkpoint 做对照。

#### 坑 2：loss mask 和训练目标不一致

若目标是 assistant-only，却意外把 user token 计入 loss，或把所有 assistant label 都屏蔽，实际优化目标就和预期不符。检查有效目标 token 数、assistant 起止位置及 padding/end token 的标记；若任务本来要预测完整对话，则不应机械套用 assistant-only mask。

#### 坑 3：数据太模板化

格式高度重复可能让模型更常复用固定回答模式；是否损害目标行为要通过不同措辞、任务类型和对话切片评估。

#### 坑 4：过度依赖合成数据

生成模型的错误、偏见和重复模式若未筛查，可能进入训练目标；同时还要核算生成、过滤、人工抽查和训练成本。

#### 坑 5：只做 helpful，不做 safety

如果评估只奖励 helpfulness 而不检查安全和拒答，模型可能在部分危险请求上给出不合要求的响应。要用明确的安全切片检验目标之间的冲突，不能把单一分数当作安全保证。

### Instruction Tuning 的行为差分实验

Instruction Tuning 是目标，SFT 是常见实现方式。要验证哪些监督带来了行为变化，可从同一个 base checkpoint 做消融：通用续写基线、单轮指令样本、多轮样本，以及格式约束样本。

### 练习：检查一份指令训练数据

本节通过具体检查项落实方法：用自己的话解释 base model 和 instruct model 的区别；写一个单轮 instruction tuning 样本。

### 19 讲·Instruction Tuning 资料边界

InstructGPT 对特定提示分布上的 SFT、偏好比较与 PPO 路线提供一手案例（Ouyang et al., 2022）；FLAN、LIMA 和 Self-Instruct 分别展示多任务指令微调、小规模精选示范和模型生成指令的实验及边界（FLAN、LIMA、Self-Instruct）；质量与多样性的条件性比较见 QDIT，EMNLP Findings 2024。模板序列化和 generation prompt 以 Transformers v5.17.0 文档为例；assistant-only mask 的模板标记以 TRL v1.16.0 文档为例。

### 20 讲·SFT 的监督边界

SFT 是大模型后训练中的一种监督训练方法。第 19 讲讨论指令数据和目标选择，本讲进一步说明怎样把对话变成 next-token 训练信号。

### SFT 是什么

SFT 是 Supervised Fine-Tuning，中文通常叫监督微调。

预训练和 SFT 都可以用 next-token prediction，但数据和目标不同。

### 学习率和训练轮数

SFT 数据常比预训练数据少得多，模型可能更快适配目标分布，也可能过度拟合训练样本；是否发生要看验证集和真实目标任务。

灾难性遗忘指模型适配新任务时，在先前任务或分布上的表现下降。它是一种需要实际测量的风险，不是每次 SFT 都会出现，也不能只凭训练集 loss 或参数更新方式判断。

### SFT 和 RLHF/DPO 的关系

### 20 讲·SFT 训练现场的故障模式

本讲从“坑 1：labels 没有正确 mask”切入，再通过“坑 2：chat template 和 tokenizer 不匹配”“坑 3：训练集答案质量差”逐步展开，最后以“坑 6：能力退化没被发现”收束。

#### 坑 1：labels 没有正确 mask

若目标本应只覆盖回答，模型却被训练去预测 user/system token，优化目标就与预期不同；其他任务也可能有意监督整段对话。

#### 坑 2：chat template 和 tokenizer 不匹配

特殊 token 没加、EOS 不正确、assistant 起始标记不一致，都会影响训练。

#### 坑 3：训练集答案质量差

SFT 是模仿学习。答案错，模型就学错；答案啰嗦，模型就学啰嗦。

#### 坑 4：只看 validation loss

SFT loss 下降不代表真实用户体验提升。

#### 坑 5：过拟合小数据集

模型在训练样本上表现好，但泛化到真实指令时变差。

#### 坑 6：能力退化没被发现

只测指令任务，不测代码、数学、多语言和安全，容易漏掉回归。

### SFT 改变行为的可验证路径

SFT 的关键不是“把 labels 设成 -100”这一句实现口诀，而是明确模型究竟被要求预测什么。令序列为 u_{1},\ldots,u_{L}， m_{t}\in\{0,1\} 表示位置 t 的 token 是否是有效训练目标；padding 和被忽略的上下文位置取 0。

## 第 21 讲：RLHF

本讲从“21 讲·RLHF 的对象与假设”切入，再通过“RLHF 是什么”“为什么 SFT 之后还需要 RLHF”逐步展开，最后以“练习：从偏好数据追到策略更新”收束。

### 21 讲·RLHF 的对象与假设

SFT 用示范回答提供一种监督目标，但一次示范不一定表达了偏好者对多个可接受答案的取舍。RLHF 将偏好比较转成模型优化信号；这个信号仍是有限标注和 Reward Model 学出的代理目标，不是人类意图或回答质量的完整真值。

### RLHF 是什么

RLHF 是 Reinforcement Learning from Human Feedback，中文是基于人类反馈的强化学习。

### 为什么 SFT 之后还需要 RLHF

SFT 的训练数据通常只有一个目标回答。

### 偏好数据

偏好数据通常是成对比较。

### Reward Model

Reward Model（奖励模型，RM）的目标是根据 prompt 和回答输出一个标量，帮助预测比较标签。

### Reward Model 如何接入策略优化

PPO 不直接读取人类比较标签，而是接收 Reward Model 对整条回答的标量分数。RM 应从偏好 pair 学习把 chosen 排在 rejected 前面，但这个分数只在其标注和生成分布附近提供排序信号，不是正确性分数，也没有绝对单位。

### PPO 在 RLHF 中做什么

有了 Reward Model 后，我们希望优化语言模型，让它生成高 reward 的回答。

### 为什么需要 Reference Model

如果只最大化 reward，模型可能为了骗过 Reward Model 而偏离原本语言能力。

### KL Penalty

KL penalty 惩罚当前 policy 和 reference model 的分布差异。

### RLHF 的训练流程

RLHF 的训练流程把 prompt、policy rollout、奖励评估和策略更新串起来，下面按步骤说明。

### RLHF 和普通强化学习的区别

传统强化学习常见于游戏、机器人等环境。

### Reward Hacking

Reward hacking 指 policy 找到提高代理 reward 的捷径，但该变化没有带来相应的人类偏好改善。

### 21 讲·Over-Optimization

过度优化是指 policy 越来越会提升代理指标，但这些提升没有继续转化为独立偏好或任务改善。摘要任务论文观察到 RM 分数与人工偏好逐渐分离；拐点取决于 RM、数据和优化强度，不能只用训练步数或单一 reward 阈值定义。

### RLHF 和 DPO 的关系

在本讲讨论的 PPO-style RLHF 配方中，常见组成是，检查步骤见下列清单。

### RLHF 的评估

评估时要把用于优化的信号与独立的人类/任务结果并列，并尽量控制 prompt、解码、输出长度与评审标准。除了以下指标，还应报告测试分布、评审者和标注协议，避免把单一总分外推为普遍行为，检查步骤见下列清单。

### 一个 toy rollout：奖励为什么要延迟观察

把一次回答看成三个 token 动作：先给出结论，再给出理由，最后给出限定条件。Reward Model 只在完整回答结束后输出序列分数，分数本身没有标出是哪个 token 改变了质量。

### 21 讲·RLHF 的失败模式

本讲从“坑 1：偏好标注标准不一致”切入，再通过“坑 2：Reward Model 泛化差”“坑 3：KL 系数设置不合适”逐步展开，最后以“坑 5：安全和 helpfulness 冲突”收束。

#### 坑 1：偏好标注标准不一致

不同标注者对“好回答”的理解不同，会让 reward model 学到噪声。

#### 坑 2：Reward Model 泛化差

训练集上排序准确，但遇到新类型 prompt 打分不可靠。

#### 坑 3：KL 系数设置不合适

系数过小可能造成较大策略漂移，过大则可能压低偏好信号的作用；两种现象都需通过 KL、任务表现和人工偏好曲线判断。

#### 坑 4：只优化 reward score

Reward 上升但人类偏好下降，是 RLHF 的典型风险。

#### 坑 5：安全和 helpfulness 冲突

模型可能为了安全过度拒答，也可能为了 helpfulness 满足危险请求。

### RLHF 的闭环与可观测量

RLHF 不是一条只看最终 reward 的流水线。每个阶段都应保留可以诊断的数据：偏好标注的一致性，Reward Model 的分领域排序与校准，policy 采样的长度和分布变化，PPO 的优势估计、KL 距离、熵、value loss，以及人工和客观任务评估。

## 第 22 讲：DPO

本讲从“22 讲·DPO 的监督边界”切入，再通过“DPO 是什么”“DPO 为什么出现”逐步展开，最后以“练习：检查一个离线偏好目标”收束。

### 22 讲·DPO 的监督边界

DPO 是偏好后训练的代表方法之一。标准 DPO 不显式训练独立的 reward model，也不在固定偏好数据集上运行 PPO rollout，而是把 chosen/rejected 比较写成一个直接优化 policy 的目标。

### DPO 是什么

DPO 是 Direct Preference Optimization，中文可译为直接偏好优化。

### DPO 为什么出现

第 21 讲介绍的 PPO-style RLHF 是一条代表路线：先用偏好数据训练 Reward Model，再由当前 policy 生成 rollout 并用 PPO 更新。标准离线 DPO 试图简化这条训练闭环，检查步骤见下列清单。

### DPO 和 RLHF 的核心区别

RLHF 先采样回答并按奖励信号更新策略；与 DPO 偏好对直接优化的目标对照见下文。

### DPO 使用的数据

DPO 数据和 reward model 数据类似，都是 preference pair。

### DPO 的直觉

对于同一个 prompt，policy 和 reference 都会为 chosen response y_{w}、rejected response y_{l} 分配条件概率。标准 DPO 比较的是：policy 相对 reference 在多大程度上改变了 chosen 与 rejected 的概率差，而不只是要求 policy 单独提高 chosen 的概率。

### Reference Model 的作用

DPO 的标准目标使用冻结的 reference policy，常见选择是用于生成候选回答的 SFT checkpoint。它为 chosen/rejected 的序列 log probability 提供基线；在原始推导假设下，policy/reference 的 log-ratio 构成隐式 reward，并对应 KL 约束的最优策略关系。

### DPO Loss 的直觉

DPO 的推导从一个带 KL 正则的奖励目标开始。对固定 prompt x 和潜在 reward r(x,y)，求解，具体表达见下式。

### Beta 参数

推导中的 \beta 是 KL 惩罚系数：固定 reward 时，增大它会提高偏离 reference 的代价，使最优策略更靠近 reference。标准 DPO loss 又将同一个 \beta 乘到 margin 上，因此它同时改变偏好 logit 和单样本梯度尺度；它不是策略概率的硬性上限，也不能脱离学习率、数据、reference 和训练步数单独解释实际更新大小。

### 22 讲·DPO 的失败模式

本讲从“坑 1：偏好数据质量差”切入，再通过“坑 2：chosen/rejected 差异太弱”“坑 3：reference model 选错”逐步展开，最后以“坑 5：偏好优化导致过度拒答”收束。

#### 坑 1：偏好数据质量差

chosen 不一定真的好，rejected 不一定真的差，模型会学到错误偏好。

#### 坑 2：chosen/rejected 差异太弱

两个回答差不多，训练信号弱，标注噪声影响大。

#### 坑 3：reference model 选错

reference 太弱或和 policy 初始化不匹配，会影响约束效果。

#### 坑 4：只看 win rate

Win rate 提升可能来自风格迎合，而不是事实性或推理能力提升。

#### 坑 5：偏好优化导致过度拒答

如果安全偏好数据处理不好，模型可能学会对很多正常请求也拒答。

### DPO 的小型对照实验

DPO 的训练日志至少应同时记录四类量：chosen/rejected 的平均 token 数、policy 与 reference 的相对 log-probability、偏好对的训练准确率，以及独立评估集上的真实任务指标。只看 DPO loss，会把“模型更会拟合偏好对”误认为“模型更适合用户”。

## 第 23 讲：Reward Model 与 Reward Hacking

本讲从“代理目标的边界”切入，再通过“Pairwise Ranking Loss”“Reward Model 的结构”逐步展开，最后以“复核练习”收束。

### 代理目标的边界

Reward Model（奖励模型，简称 RM）把 prompt 和 response 映射成一个标量 r_{\phi}(x,y)。它的用途不是给答案颁发绝对质量分，而是把一套明确的偏好标注协议变成可供优化器使用的排序信号。

### Pairwise Ranking Loss

常见 Bradley–Terry 建模把同一 prompt 下 chosen 回答胜过 rejected 回答的概率写成分数差的 sigmoid。记 r_{w}=r_{\phi}(x,y_{w})、 r_{l}=r_{\phi}(x,y_{l})，并定义 \sigma(z)=1/(1+e^{-z})，则单个偏好 pair 的概率和负对数损失为，具体表达见下式。

### Reward Model 的结构

一种常见结构是从语言模型的 backbone 出发，为整段 prompt 与 response 产生隐藏状态，再用标量 reward head 输出一个分数。具体实现可能取 response 末尾、EOS 位置或经过 mask/pooling 得到的表示；“使用最后一个 token”是某类实现选择，不是 RM 的定义。

### Reward Model 评估

评估要回答的是：RM 在什么样的样本和标注协议下能复现排序，哪些变化会让它失准，以及这个排序能否预测目标任务。训练 loss 下降只说明模型更贴合训练 pair，不说明它对新回答可靠。

### 分布偏移与 Reward Hacking

RM 是在有限 prompt 和回答分布上训练的；RL 优化中的 policy 则会根据 RM 分数持续改变回答。当新 policy 生成了训练集中少见的长度、格式、语气或推理错误时，RM 仍会给出分数，但这个分数可能外推到未验证区域。

下面这个 demo 用一个玩具例子说明 reward hacking：Reward Model 可能过度奖励“看起来礼貌和冗长”的回答，但真实用户更喜欢准确、简洁、直接的回答。

### Over-Optimization 与 Over-Refusal

Over-optimization 指继续提高 RM 分数，却没有提高目标任务表现，或使目标表现下降。判断时要同时画 RM 指标和独立目标指标随优化步数、KL 或采样强度变化的轨迹，并检查分领域结果。

### 盲区、独立验证与风险控制

偏好 RM 可以判断候选回答更像哪类已标注答案，但许多任务需要额外证据来判定是否正确。代码需要测试或运行结果，数学需要可核算步骤或形式化检查，事实问题需要能追到来源，工具调用需要检查实际执行状态；长上下文、多语言和新型攻击也需要专门切片。

### 常见失效判断

本节通过具体检查项落实方法：标注协议含混：同一个 pair 让标注者按不同目标判断，训练误差混合了偏好冲突；先明确标准、保留分歧，再解释可达到的排序上限；验证集和训练样本太近：高准确率可能只反映相似 prompt 或格式；按 prompt、来源和时间隔离留出样本，并检查当前 policy 生成内容。

### 复核练习

本节通过具体检查项落实方法：写一个 chosen/rejected 样本，并说明两种回答的排序依据和可能分歧；用自己的话解释 pairwise ranking loss，手算一个正向与反向分差。

### 本讲结论与资料边界

RM 把指定偏好协议压缩成可优化的排序代理；pairwise loss 训练的是 chosen/rejected 的相对次序，不能建立绝对质量刻度。policy 优化会改变生成分布，并可能放大 RM 依赖的表面捷径，因此应对模型分数和独立任务表现做并行、分层观察。
