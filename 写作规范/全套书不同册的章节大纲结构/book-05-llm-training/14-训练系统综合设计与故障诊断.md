# 第十四章：训练系统综合设计与故障诊断

## 本章定位与中心

本章把前文的训练组件放进一份可审计方案，训练读者从证据和时间线诊断故障、从目标和资源约束选择配置。它承担全书综合演练，不替代第 7—13 章对各子系统的机制解释，也不重复第 10 章完整实验管理 demo。

## 0. 从三个层次理解训练设计

区分模型目标、可观测训练系统和交付结论三个层次，建立案例推理框架。

### 0.1 初学者先分清三件事

先识别训练目标、实现配置和评估证据分别回答什么问题。

### 0.2 专家需要额外记录四条边界

补充方法假设、数据口径、测量口径和风险边界，防止把局部结果写成普遍事实。

## 1. 训练账本：把局部配置连接成系统

用一个统一账本连接任务、数据、模型、优化、资源和验收条件。

### 1.1 目标契约

把预期能力转成输入、输出、约束、成功判据和不适用范围。

### 1.2 证据账本

为每个设计判断标记来自实测、论文报告、估算还是待验证假设。

### 1.3 三类数字不能混用

区分参数与 token 等规模数字、训练运行测量和下游能力分数的含义。

## 2. 7B 预训练设计：从目标到 checkpoint

以 7B 预训练为统一案例，从业务目标逐步推至数据、模型、训练与验收。

### 2.1 先定义模型的用途

明确目标用户、任务分布和部署约束，避免参数规模先于问题定义。

### 2.2 数据 mixture 不是文件拼盘

按来源、质量、领域、重复和训练权重建立数据混合方案。

### 2.2.1 代表研究：DoReMi 怎样从域损失推导采样比例

介绍 DoReMi 的领域损失信号与采样分布优化思路，说明研究设置和生产数据混合之间的距离。

### 2.3 tokenizer 与上下文预算

将切分效率、语言覆盖、上下文长度和部署兼容作为 tokenizer 与序列预算的联动因素。

### 2.4 架构选择必须绑定约束

说明模型形状选择需绑定硬件、目标能力、上下文和工程团队条件。

### 2.5 训练目标与优化策略

把 next-token objective、batch、学习率与优化器配成可验证的实验假设。

### 2.6 并行与长期吞吐

按模型规模、设备拓扑和稳定运行需求选择并行组合，并用长时间实测校准。

### 2.7 监控、checkpoint 与评估

为训练过程定义健康指标、保存点和能力检查，形成继续、暂停或回滚的门槛。

## 3. 训练量级公式：把方案变成数字

用少量公式检查方案数量级，同时强调必须回到实测和口径说明。

### 3.1 FLOPs 粗估

由模型规模和 token 数给出粗估，并解释长序列、MoE 与实现差异。

### 3.2 Global batch 与有效 token batch

把微批、累积步数、数据并行和有效 token 共同纳入更新规模。

### 3.3 AdamW 状态与训练状态

对齐参数、梯度和优化器状态的显存账本与保存需求。

### 3.4 单位能力成本

提出以任务成功或目标质量为分母的比较思路，避免只用计算量衡量价值。

## 4. Loss spike：从时间线而不是直觉开始

把 loss 异常诊断组织为证据时间线与最小对照，而非猜测式改参。

### 4.1 第一次异常的时间线

记录异常前后数据、更新、硬件和运行状态变化，以定位触发窗口。

### 4.2 用固定 batch 隔离数据与优化

固定小批样本做重放，判断错误更可能来自样本管线还是优化状态。

### 4.3 根据观测组合定位

联合读取 loss、梯度范数、激活、吞吐和设备指标，避免单指标归因。

### 4.4 修复与恢复

定义修复后回归、检查点恢复和继续训练的验证流程。

### 4.5 Adam 与有限精度机制：把论文假说变成可检验分支

把优化器低精度状态等可能机制转为检查假设，区分研究发现和当前故障事实。

### 4.6 从首次异常到最小反事实

设计只改变一个关键因素的对照，判断哪一变化能复现或消除异常。

## 5. Loss 与能力：为什么平均曲线不够

说明训练目标指标与实际任务表现之间的映射缺口。

### 5.1 训练目标和下游目标的映射缺口

解释语言建模损失不会覆盖所有任务约束、事实性和工具行为。

### 5.2 分层评估

按能力类别、数据切片和任务结果分层检查进展。

### 5.3 能力回归的定位

用历史基线、分项评估和训练数据变化定位能力损失。

## 6. Benchmark contamination：把高分和泛化分开

讨论评测集污染如何让分数偏离泛化能力，并要求报告风险证据。

### 6.1 污染的几种形态

区分精确重复、近似重复、答案泄漏、预训练覆盖和模板记忆。

### 6.2 分层检测

组合来源追踪、字符串与语义匹配、人工抽查和反事实评估。

### 6.3 代表性方法回答的是不同问题

对比不同污染检测方法的观测对象与漏检边界，不将分数合并成单一结论。

### 6.4 风险标注与报告

要求公开评测风险、审计方法、已知覆盖和剩余不确定性。

## 7. Batch size 与 learning rate：同一个更新的两面

联结有效 batch 和优化步幅，帮助解释改变并行或累积时的训练差异。

### 7.1 样本 batch 与 token batch

区别样本数和变长序列下真正参与损失的 token 数。

### 7.2 Batch 变大改变了什么

说明梯度估计噪声、更新次数和吞吐效率同时变化。

### 7.3 Learning rate 的搜索

描述有界、分阶段和受控的学习率搜索，而非无条件扩大学习率。

## 8. 分布式切分：切了什么，省了什么，又付出什么

对照数据、状态、张量和流水并行的切分对象、显存效益和通信代价。

### 8.1 DDP 的复制模型

说明每副本保留完整模型并同步梯度的计算和内存特点。

### 8.2 ZeRO 与 FSDP 的状态分片

比较参数、梯度与优化器状态分片如何节省内存并带来通信。

### 8.3 Tensor Parallel 与 Pipeline Parallel

分别解释层内切分与层间切分的拓扑和调度代价。

### 8.4 混合并行与拓扑

根据节点内互联与跨节点网络安排并行维度。

## 9. 显存账本：稳态占用和瞬时峰值

从常驻状态和峰值临时内存两方面排查 OOM。

### 9.1 训练状态

核算权重、梯度和优化器状态的精度与分片。

### 9.2 激活和长上下文

解释激活随序列、层数和批量变化，说明重计算等取舍。

### 9.3 量化与参数高效微调的边界

指出量化和 adapter 改变部分存储及更新成本，但不能消除所有激活与系统开销。

## 10. SFT 后能力回归：先定义“变差”

将模糊的能力退化转成任务级可观察指标。

### 10.1 把模糊退化拆成指标

按准确性、拒答、格式、工具调用和语言质量拆分回归表现。

### 10.2 SFT 数据和监督边界

检查训练样本覆盖、标签掩码、混合比例和回答模板造成的影响。

### 10.3 训练强度与回放

比较学习率、步数、数据回放和冻结策略，测试是否能保留通用能力。

## 11. VLM 训练：视觉 token 必须有证据作用

用视觉语言模型案例检查媒体证据是否经过模型结构进入答案。

### 11.1 三个模块和三条数据流

分别追踪视觉编码器、连接器和语言模型的数据张量与训练信号。

### 11.2 分阶段训练

说明连接器对齐和指令训练阶段的目标差异。

### 11.3 监督与反事实证据

用标签掩码和媒体替换验证监督正确与模型使用视觉证据。

## 12. 训练成本：选择资源而不是堆资源

综合算力、目标能力、可用率和重跑风险形成资源决策。

### 12.1 从目标能力倒推规模

先定义任务和评测，再估算模型、数据和训练预算。

### 12.2 计算与实测

以基准测量修正理论 FLOPs 和扩展效率假设。

### 12.3 失败和 checkpoint 成本

把停机、保存、恢复与重训代价纳入运行计划。

## 13. Base、Instruct 与 Chat：阶段名称不是算法名称

澄清产品阶段标签和训练方法之间的关系。

### 13.1 Base model

说明基础语言模型的训练目标和典型能力边界。

### 13.2 Instruct model

说明指令微调如何形成可执行用户指令的行为。

### 13.3 Chat model

说明对话格式与多轮行为是接口和训练内容的组合，而不是单一算法。

## 14. DPO 与 PPO：离线偏好与在线策略更新

用一对代表方法说明监督数据分布和在线采样方式的差别。

### 14.1 PPO 的闭环

梳理采样、奖励、优势估计和受约束更新。

### 14.2 DPO 的离线目标

说明固定偏好对如何直接形成策略更新信号。

### 14.3 如何选择

根据是否需要在线探索、反馈成本和可用数据决定方法路径。

## 15. 一个完整训练方案的审计示例

将前述账本应用于一项综合方案，练习读者区分事实、假设和未决项。

### 15.1 方案账本

列出目标、数据、模型、训练、资源、评估和发布条件的对应证据。

### 15.2 如何阅读审计结果

解释如何从风险、测量缺口和实验结果得出继续或修改方案的结论。

## 16. 常见概念误区

把容易混淆的系统指标转成检查问题。

### 16.1 把模型名称当成训练方案

要求补充数据、目标、优化和评估配置。

### 16.2 把 token 数当成有效学习量

同时检查质量、重复、分布和目标相关性。

### 16.3 把能启动当成能训练

用长跑、扩展、恢复和指标稳定性验证系统。

### 16.4 把高利用率当成高能力

区分硬件效率与模型任务表现。

### 16.5 把方法名当成选择结论

回到项目约束和验证证据说明方法适配性。
