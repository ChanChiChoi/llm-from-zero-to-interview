# 第七章：分布式训练：把一次更新放到多张设备上

本章围绕一次全局参数更新如何跨多设备拆分、通信、同步和恢复展开。读者应能追踪 rank、batch、梯度、状态分片及并行布局，理解 collective 的数据流与系统代价，并按内存、通信和拓扑选择方案；第八章主讲单设备显存/数值策略，第十章主讲通用实验 checkpoint，本章分别聚焦分布式机制及其恢复边界。

## 7.0 一次更新为什么会变成一个系统问题

多卡训练需保证每个设备处理局部数据后仍形成定义清楚的全局目标和一致参数。本节以全局更新为问题主线。

## 7.1 分布式训练的基本对象

World、rank、process group 和设备映射定义训练进程间的关系。本节建立后续切分和通信讨论的对象模型。

### 7.1.1 world、rank 和 local rank

World 表示作业进程集合，rank 标识全局进程，local rank 标识节点内位置。本小节说明这些标识在设备绑定和通信中的作用。

### 7.1.2 为什么要显式建立 process group（通信组）

Process group 定义哪些进程共同参与 collective。本小节说明不同并行维度可建立不同通信子组。

### 7.1.3 一次更新的全局时间线

一次分布式更新包含局部计算、通信、同步和状态写回。本小节概述各阶段依赖和同步点。

## 7.2 一次更新的 loss 分母怎样算

并行训练必须让局部梯度聚合后对应预期的全局 loss。本节说明样本和 token 口径以及 DP 与累积的归一化。

### 7.2.1 样本 batch 与 token batch

变长序列下样本数无法准确表示有效监督量。本小节区分样本 batch、输入 token 和目标 token。

### 7.2.2 不等长 rank 的 loss 归一化

不同 rank 的有效 token 数不等时，平均各 rank 的局部均值会改变 token 权重。本小节说明以全局有效目标分母得到正确梯度的条件。

### 7.2.3 accumulation 和 DP 的组合

梯度累积和数据并行共同构成一次全局更新窗口。本小节说明局部 loss scaling 如何与 DDP rank 平均相抵。

## 7.3 Data Parallelism：复制模型，切分数据

Data parallelism 在各 rank 保持模型副本并处理不同数据，再同步梯度。本节说明 DDP 的训练数据流和适用边界。

### 7.3.1 DDP 的数据流

每个 rank 前向/反向计算本地梯度，通过同步更新维持模型副本一致。本小节说明梯度通信所在的步骤。

### 7.3.2 数据 shard 不是简单切数组

数据打乱、随机种子、尾批和故障恢复会影响 rank 间样本划分。本小节说明可复现分片需要的 sampler 状态。

### 7.3.3 DDP 的优势与边界

DDP 易于扩展但会复制完整训练状态。本小节说明其适用规模及显存限制。

## 7.4 Collective communication：数据怎样合并、分发和收集

Collective 定义多进程如何组合或交换张量。本节通过参与者、输入输出和通信量解释常用操作。

### 7.4.1 All-reduce

All-reduce 对各 rank 的张量执行归约并让结果回到所有 rank。本小节说明它如何同步梯度。

### 7.4.2 Reduce-scatter

Reduce-scatter 先归约张量再将结果分片分发给各 rank。本小节说明它与状态分片训练的关系。

### 7.4.3 All-gather

All-gather 收集各 rank 分片并形成完整张量。本小节说明分片参数在计算时为何需要聚集。

### 7.4.4 All-to-all

All-to-all 将各 rank 输入片段按目标进程重排交换。本小节说明它在 MoE token 路由中的作用。

### 7.4.5 Broadcast、send/recv 和 barrier

Broadcast 复制数据，点对点通信定向传送，barrier 建立同步点。本小节区分其语义与 collective 数据归约。

### 7.4.6 Ring all-reduce 的量级

Ring 算法通过 reduce-scatter 和 all-gather 传递分片数据。本小节估算每 rank 通信量并限定其算法假设。

### 7.4.7 $\alpha$-$\beta$ 通信模型

延迟与带宽项描述消息启动开销和传输成本。本小节说明该模型有助于理解规模效应，但不能直接替代真实 profiling。

## 7.5 训练状态显存：DDP、ZeRO 和 FSDP

ZeRO 与 FSDP 将模型状态在数据并行 rank 间分片，换取单卡内存并增加通信。本节比较状态分片层级和模块生命周期。

### 7.5.1 DDP 的常驻状态

DDP 每个 rank 常驻参数、梯度和优化器状态副本。本小节建立基线显存口径。

### 7.5.2 ZeRO-1

ZeRO-1 分片优化器状态而保留参数及梯度副本。本小节说明内存收益与更新通信。

### 7.5.3 ZeRO-2

ZeRO-2 进一步分片梯度。本小节说明与参数复制相比新增的通信和内存变化。

### 7.5.4 ZeRO-3

ZeRO-3 将参数也分片，计算时需按需聚集参数。本小节说明更高内存节省与更多通信的关系。

### 7.5.5 FSDP 的模块生命周期

FSDP 按模块组织参数分片、计算前 all-gather 和计算后释放/分片。本小节追踪参数从存储到执行的生命周期。

### 7.5.6 Wrap 粒度的取舍

包装模块大小影响通信次数、峰值显存和调度效率。本小节说明过细与过粗分片的成本。

### 7.5.7 Offload 与分片不是一回事

Offload 改变状态存储位置，分片改变状态在设备间的分布。本小节区分两种内存策略及其带宽成本。

### 7.5.8 用一组数字比较 DDP、ZeRO 与 FSDP

统一参数和状态假设下的账本可比较不同分片阶段的显存与通信。本小节要求说明估算项和实现边界。

## 7.6 Tensor Parallelism：把一层矩阵运算分给多张卡

Tensor parallelism 将同一层矩阵按维度切分并通过 collective 组合结果。本节从线性层到 attention 解释切分数据流。

### 7.6.1 列切分线性层

列并行将权重输出维拆到多个 rank，各 rank 计算部分输出通道。本小节说明局部结果如何被使用。

### 7.6.2 行切分线性层

行并行将输入维拆分，局部输出需归约合并。本小节说明对应的通信操作。

### 7.6.3 Attention 中的 TP

Attention 可按 head 或投影维度切分。本小节说明 Q/K/V 与输出投影之间的布局和通信关系。

### 7.6.4 词表和 embedding 的特殊情况

词表并行需处理 token ID 分区、局部 logits 和跨 rank 归一化。本小节说明 embedding/输出层为何有独特通信路径。

### 7.6.5 TP 的拓扑边界

TP 频繁通信，因此 rank 间带宽和拓扑影响效率。本小节说明节点内外切分的成本差异。

## 7.7 Pipeline Parallelism：切分模型层

Pipeline parallelism 将不同层放在不同 stage，以 micro-batch 流水执行。本节解释调度、气泡和负载平衡。

### 7.7.1 Stage 和 micro-batch

Stage 切分模型层，micro-batch 依次经过各 stage。本小节说明激活和梯度沿流水线传播。

### 7.7.2 Pipeline bubble

流水启动和排空时部分 stage 空闲形成 bubble。本小节说明 stage 数和 micro-batch 数对利用率的影响。

### 7.7.3 为什么不能无限增加 micro-batch

更多 micro-batch 可隐藏流水气泡，但会增加调度和状态压力，且不一定改善目标分母。本小节说明收益递减因素。

### 7.7.4 1F1B 的基本思路

1F1B 交错前向和反向以控制激活存储。本小节说明 warmup、steady state 和 cooldown 的调度关系。

### 7.7.5 流水线 schedule 的取舍

不同调度在 bubble、激活内存和实现复杂度间做权衡。本小节以相同 stage 布局比较其影响。

### 7.7.6 Stage 划分不均

计算负载或通信不平衡会让最慢 stage 限制整体吞吐。本小节说明 profile 驱动的负载平衡。

## 7.8 Sequence Parallel 与 Context Parallel

序列/上下文并行将长序列维度上的计算和状态分散到多设备。本节区分两种名称相近但目标不同的技术路线。

### 7.8.1 Sequence Parallel 的位置

Sequence parallel 通常与 tensor parallel 配合，拆分部分序列维操作。本小节说明其作用范围和通信边界。

### 7.8.2 Context Parallel 的目标

Context parallel 将长上下文 token 分布到多个 rank 以控制内存和计算。本小节说明注意力需要跨分片读取信息。

### 7.8.3 attention 规模和通信

长序列 attention 的计算与跨 rank 数据交换需共同核算。本小节说明并行收益取决于序列长度、算法和拓扑。

## 7.9 混合并行：这些卡怎样排成一份布局

大型模型通常组合 DP、TP、PP、CP 或 EP。本节说明并行维度乘积、rank 映射与全局 batch 的关系。

### 7.9.1 3D parallel 的乘积

DP、TP 和 PP 组大小共同构成总 world size。本小节说明并行维度分工和布局约束。

### 7.9.2 为什么 world size 相等还不够

相同卡数可以形成不同通信组和状态布局。本小节说明拓扑、层划分和设备负载使其性能不等价。

### 7.9.3 拓扑感知的 rank mapping

Rank 到物理设备的映射决定高频通信是否落在高速链路。本小节说明节点、机架和互联结构的影响。

### 7.9.4 并行维度与 batch

并行设置会改变每个 rank 的数据量和全局有效 batch。本小节说明布局选择需与优化器和 loss 分母共同校准。

## 7.10 Expert Parallelism：路由 token 怎样找到专家

Expert parallel 将不同专家放在不同设备，并通过路由交换 token。本节说明 capacity、all-to-all 和负载观测。

### 7.10.1 MoE 的 token 路由

门控网络选出的 token 需发送到对应 expert 所在 rank。本小节说明 dispatch、专家计算和返回路径。

### 7.10.2 Expert capacity

每个专家容量限制可接收 token 数。本小节说明 overflow 的处理会影响训练目标与样本覆盖。

### 7.10.3 All-to-all 的两次交换

输入 token 分发和专家输出回收通常各需一次交换。本小节追踪两阶段通信中的数据对象。

### 7.10.4 负载均衡不是只看辅助 loss

辅助损失不能完整表示 token 分布、热点和实际 all-to-all 时间。本小节说明需要观察的路由和系统指标。

## 7.11 Activation checkpointing：重计算如何影响分布式布局

激活重计算可降低保存的中间状态，但会改变计算与通信调度。本节只处理它和 FSDP、TP、PP 的交互，显存/重计算机制由第八章主讲。

### 7.11.1 为什么激活重算会影响并行执行

重算改变反向传播中前向操作的执行时机，可能触发额外参数聚集或通信。本小节限定跨并行维度的影响。

### 7.11.2 计算与峰值显存的联合账本

分布式环境下重算收益需与 transient all-gather、通信缓冲共同核算。本小节说明稳态节省不保证峰值下降。

### 7.11.3 与 FSDP、TP、PP 的组合

分片、张量和流水并行对重计算区域有不同约束。本小节说明组合设置需要在真实执行图上验证。

## 7.12 通信与计算重叠

异步调度可让通信与计算同时推进，但真实重叠受依赖和资源竞争限制。本节解释重叠模型与实现信号。

### 7.12.1 不重叠的时间模型

计算与通信完全串行时，一步时间由二者相加组成。本小节作为性能分析基线。

### 7.12.2 理想重叠

理想条件下可并行的通信隐藏在计算窗口内。本小节说明理论下界和依赖假设。

### 7.12.3 DDP bucket overlap

DDP 可按 bucket 在反向计算中逐步启动梯度通信。本小节说明 bucket 大小与启动时机的关系。

### 7.12.4 FSDP 的 overlap

FSDP 可调度参数 all-gather 与模块计算重叠。本小节说明预取窗口和显存峰值的相互影响。

### 7.12.5 overlap 不是免费加速

重叠会竞争带宽、流和缓存，也可能增加峰值内存。本小节要求以时间线和 profiler 验证实际收益。

## 7.13 Checkpoint 与分布式恢复

分布式 checkpoint 必须保存分片模型及训练状态，并能在目标拓扑恢复。本节说明保存格式、异步一致性与重分片边界。

### 7.13.1 需要保存哪些状态

模型、优化器、随机状态、数据进度和并行布局影响恢复一致性。本小节说明与分布式运行相关的字段。

### 7.13.2 global checkpoint 与 sharded checkpoint

全局整合格式和分片格式在保存、加载和转换成本上不同。本小节说明两类布局的使用边界。

### 7.13.3 异步 checkpoint 的一致性

异步写盘需保证保存状态对应同一训练时间点。本小节说明快照、版本和完成信号的要求。

### 7.13.4 改变 world size 后恢复

恢复到不同设备数需重新分片并验证每个状态的映射。本小节说明拓扑弹性不等于训练状态自动兼容。

## 7.14 故障与恢复：一个 rank 出错，为什么整组训练会停下来

集体通信依赖所有参与 rank 按一致顺序推进，单 rank 故障可能阻塞全组。本节分析 hang、错误顺序和数据恢复。

### 7.14.1 一个 rank 失败为什么会影响全局

同步 collective 等待参与进程，故单点失败可能停止全局更新。本小节说明故障传播机制。

### 7.14.2 collective 顺序不一致

控制流差异会令不同 rank 进入不匹配的 collective。本小节说明如何根据日志定位顺序问题。

### 7.14.3 恢复点的选择

恢复点需兼顾丢失工作、状态一致性和故障频率。本小节说明选择依据。

### 7.14.4 数据一致性与样本重复

重启、重分片或游标错误可能导致样本遗漏或重复。本小节说明如何记录和检查数据进度。

## 7.15 怎样看出训练慢在哪里：分布式训练的可观测性

定位性能问题需从训练级指标下钻到 rank、模块和时间线。本节说明可观测信号与并行执行的对应关系。

### 7.15.1 训练级指标

整体 tokens/s、step time、利用率和通信比例描述训练运行状态。本小节说明指标口径需覆盖有效 token。

### 7.15.2 rank 级指标

各 rank 时间、显存和数据量可以发现负载偏斜。本小节说明总体平均如何掩盖慢 rank。

### 7.15.3 MoE 和 PP 的专用指标

专家负载、overflow、stage 空闲与队列等待揭示稀疏和流水特有瓶颈。本小节说明对应观测量。

### 7.15.4 用时间线而不是单一平均数

分阶段时间线能显示同步等待、通信重叠和故障恢复过程。本小节说明为何均值不足以解释性能回退。

### 7.15.5 MFU、HFU 与吞吐口径

MFU/HFU 与设备 busy 使用不同分子、分母和理论峰值口径。本小节说明报告效率指标时应同时交代计算方式。

## 7.16 如何选择并行方式

并行方案应从实际内存、计算、通信和设备拓扑瓶颈出发。本节给出条件化的选择路线。

### 7.16.1 先确认瓶颈

先判断显存、算力、带宽、通信还是负载不均限制训练。本小节说明用 profile 证据避免过早引入复杂并行。

### 7.16.2 一个保守的决策顺序

从可行的 DP/分片布局起步，再按瓶颈加入 TP、PP、CP 或 EP。本小节说明渐进式方案比较。

### 7.16.3 64 张 GPU 的两个对照

固定设备数但改变并行拓扑的对照说明通信布局会改变有效吞吐。本小节要求绑定带宽、模型和实现假设。

## 7.17 一个分布式资源账本示例

账本将每种并行布局的显存份额、通信量和吞吐假设放在一起比较。本节明确估算值与真实集群测量的差别。

## 7.18 常见故障：从现象回到切分和通信

分布式故障需结合 rank、同步阶段和内存生命周期定位。本节将常见症状映射到候选机制。

### 7.18.1 GPU 数量增加但吞吐不变

扩展收益可能被通信、同步或数据加载抵消。本小节要求查看 scaling efficiency 和等待时间。

### 7.18.2 某个 rank 显存特别高

负载映射、分片边界、局部序列或专家热点可能导致不均。本小节说明按 rank 对照状态。

### 7.18.3 作业 hang

Hang 常与 collective 顺序、进程退出或网络故障有关。本小节说明利用 rank 日志和同步点缩小范围。

### 7.18.4 loss 与单卡不一致

全局分母、数据顺序、随机状态和数值归约都可能造成差异。本小节说明进行匹配配置的对照。

### 7.18.5 FSDP 省了稳态显存却仍然 OOM

参数聚集、prefetch 和临时 buffer 可能造成瞬时峰值。本小节说明稳态统计不足以预测真实峰值。

### 7.18.6 MoE overflow 很高

专家容量或路由偏斜可能丢弃大量 token。本小节说明需同时检查容量策略、负载指标和质量变化。
