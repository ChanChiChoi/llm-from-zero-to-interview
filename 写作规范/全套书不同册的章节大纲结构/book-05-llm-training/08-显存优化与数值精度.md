# 第八章：显存优化与数值精度：预算、峰值与数值轨迹

本章围绕训练显存的时间变化和数值格式如何改变计算轨迹展开。读者应能拆分参数、梯度、优化器、激活与临时峰值，按故障阶段选择重计算、分片、offload 或精度策略，并区分节省稳态内存与控制真实峰值；并行算法本身由第七章主讲，优化器算法由第六章主讲。

## 8.0 先问显存峰值发生在哪里

OOM 是某个执行阶段的瞬时结果，不只由模型参数量决定。本节以峰值出现时机引出全章账本。

## 8.1 训练显存的五类账本

训练内存由参数、梯度、优化器状态、激活和临时运行空间共同构成。本节建立可区分的显存组成。

### 8.1.1 参数

参数张量的数量、精度和分片决定权重常驻内存。本小节说明参数存储的主要口径。

### 8.1.2 梯度

反向传播产生的梯度通常与参数形状相关，精度和是否分片会改变其大小。本小节说明梯度状态的内存影响。

### 8.1.3 Optimizer state

动量和方差等状态可能超过参数自身内存。本小节说明不同优化器和状态精度造成的差异。

### 8.1.4 激活和 attention 中间结果

前向中间激活需为反向传播保留，序列长度和 batch 会显著影响占用。本小节说明激活与 score 张量的来源。

### 8.1.5 临时空间、通信和 allocator

Kernel workspace、通信 buffer、缓存碎片和分配器保留空间会增加峰值。本小节说明它们不能由静态参数公式涵盖。

## 8.2 一个 7B 全参数训练的量级账本

教学账本估算一组模型和精度假设下的权重、梯度、优化器状态与激活规模。本节说明估算用途和未包含的运行峰值。

## 8.3 稳态显存和瞬时峰值

训练过程中显存占用随阶段变化，稳态总和可能低于短时峰值。本节说明如何按时间点分析峰值。

### 8.3.1 为什么平均值会误导

平均占用不能显示某个阶段的短时分配尖峰。本小节说明需结合时间序列和峰值事件定位。

### 8.3.2 FSDP/ZeRO 的 transient all-gather

分片参数在计算前聚集会形成短时完整参数或通信 buffer。本小节说明稳态节省不保证峰值同幅下降。

### 8.3.3 evaluation 和 checkpoint 的额外峰值

验证、权重转换和保存可能额外创建张量或副本。本小节说明推理/训练切换及 checkpoint 写出需纳入峰值预算。

## 8.4 激活显存：batch 和 context 的乘积

激活保存随 batch、序列长度、层数和实现形态变化。本节解释为何长上下文训练容易受到激活内存限制。

### 8.4.1 影响激活的变量

层数、隐藏维度、batch、上下文和保存策略共同决定激活量。本小节明确主要增长因子。

### 8.4.2 为什么长上下文特别昂贵

长序列会放大激活保存及某些 attention 中间项。本小节区分线性增长的状态与二次项实现。

### 8.4.3 激活不是参数

参数驻留与每个 batch 的激活占用具有不同的缩放方式。本小节说明两者不能相互替代地推算。

## 8.5 Attention 中间结果与 FlashAttention

标准 attention 的显式 score 矩阵会产生大规模中间存储，FlashAttention 通过分块避免完整物化。本节区分内存读写收益和算术复杂度。

### 8.5.1 标准 attention 的 score 矩阵

QKᵀ 形成 query-key 位置间的分数矩阵。本小节说明其形状、存储精度和序列长度影响。

### 8.5.2 FlashAttention 改变什么

FlashAttention 使用 IO-aware 分块计算减少中间写回和存储。本小节说明它解决的内存瓶颈及保持的全量交互计算。

### 8.5.3 FlashAttention 与 checkpointing 的区别

FlashAttention 改变 attention kernel 的中间数据流，checkpointing 通过反向重算减少跨层激活保存。本小节比较两者作用范围。

## 8.6 FP32、FP16、BF16 与 FP8 的表示边界

浮点格式在指数范围、精度、字节数和硬件支持上不同。本节说明选择格式需绑定运算、状态和目标硬件。

### 8.6.1 字节数不是全部

低比特占用减少不一定降低所有运算成本，scale、转换和累积精度也重要。本小节说明存储位宽与数值行为不同。

### 8.6.2 FP32

FP32 提供较宽动态范围和较高精度，常用于部分状态或累计运算。本小节说明其资源成本。

### 8.6.3 FP16

FP16 存储较小但指数范围有限。本小节说明 overflow/underflow 风险和 loss scaling 的联系。

### 8.6.4 BF16

BF16 保留较宽指数范围但尾数精度较低。本小节说明其数值特征和硬件支持条件。

### 8.6.5 FP8

FP8 训练依赖格式类型、缩放策略和累积路径。本小节说明它需要额外校准并验证数值质量。

### 8.6.6 FP4 训练：低比特结果绑定格式、舍入与硬件

FP4 训练涉及量化格式、scale、舍入、累积和硬件 kernel 的联合设计。本小节限定论文结果不能脱离这些条件比较。

## 8.7 Mixed precision：不同张量使用不同精度

混合精度将权重、激活、梯度、累积和优化器状态分配给不同数值格式。本节说明 autocast 和 scaler 的角色。

### 8.7.1 典型精度分工

常见方案在矩阵运算、参数副本和优化器状态使用不同精度。本小节说明其内存与稳定性权衡。

### 8.7.2 autocast 不等于所有操作降精度

Autocast 按算子策略选择 dtype，而非机械降低所有张量精度。本小节说明需核对运算级实际 dtype。

### 8.7.3 梯度裁剪和 unscale 的顺序

裁剪应使用还原缩放后的实际梯度尺度。本小节说明顺序错误会改变阈值含义。

### 8.7.4 scaler 如何处理异常

动态 scaler 可在检测到 overflow 后跳过更新并调整 scale。本小节说明跳步和 scale 记录是训练状态的一部分。

## 8.8 Activation checkpointing：用重计算换激活

Activation checkpointing 只保存选定边界，在反向时重算内部激活。本节解释其内存收益、额外计算和真实峰值。

### 8.8.1 普通 forward/backward

常规反向依赖前向保存的中间激活。本小节说明哪些状态被保留以计算梯度。

### 8.8.2 理想模型与真实峰值

简单的节省估算会忽略重算工作区和瞬时张量。本小节说明真实 profiling 需要观察的峰值。

### 8.8.3 重计算代价

重计算以额外前向计算换取更少持久激活。本小节说明吞吐损失随重算范围变化。

### 8.8.4 与 selective checkpointing

Selective checkpointing 依据算子成本和内存价值选择保存或重算。本小节说明策略性选择比整层重复更精细。

## 8.9 Gradient accumulation：降低 micro-batch，不降低单次激活

Gradient accumulation 通过减少 micro-batch 控制单次激活，但不改变同一序列前向的激活峰值。本节聚焦显存效果，数学分母由第五章主讲。

### 8.9.1 它改变什么

累积减少单步并行样本数，同时增加完成一次更新所需的 micro-step。本小节说明显存与时间变化。

### 8.9.2 归一化

各 micro-batch 的 loss 应按全局有效目标数构造。本小节指出变长场景不能无条件平均局部均值。

### 8.9.3 no_sync 与通信

数据并行可在非末次累积步骤延迟梯度同步。本小节说明节省的通信与额外本地梯度存储。

## 8.10 Optimizer state sharding、offload 和低比特状态

优化器状态可按数据并行切分、移至主机或压缩表示。本节聚焦内存代价与访问成本，第七章主讲并行通信机制。

### 8.10.1 Sharding 改变单卡份额

状态分片降低每设备驻留量，但需通过通信维护更新。本小节说明单卡份额计算。

### 8.10.2 Offload 改变存储位置

Offload 将状态从加速器移至 CPU 或其他存储层。本小节说明主机带宽、传输和同步成本。

### 8.10.3 8-bit optimizer state

低比特状态压缩需scale/分块等量化机制。本小节说明内存收益及状态误差可能对更新轨迹的影响。

## 8.11 LoRA 与 QLoRA：微调时缩小可训练状态

LoRA 限制可训练更新参数，QLoRA 进一步量化底座权重。本节区分训练状态减少与激活、计算成本仍存在的事实。

### 8.11.1 LoRA 的参数量

低秩矩阵更新以较少参数近似权重变化。本小节说明 rank 和目标模块影响可训练参数量。

### 8.11.2 LoRA 没有消除激活

冻结底座参数仍需通过模型前向与反向传递梯度至适配器。本小节说明激活峰值并未因此消失。

### 8.11.3 QLoRA 的量化底座

QLoRA 在低比特底座上训练高精度适配器。本小节说明量化格式、反量化路径和优化器状态的边界。

## 8.12 OOM：按发生阶段定位

OOM 发生在不同阶段对应不同临时张量和状态生命周期。本节要求记录阶段、张量和配置。

### 8.12.1 forward OOM

Forward OOM 多与参数聚集、激活、attention 中间量或 workspace 有关。本小节说明先检查的变量。

### 8.12.2 backward OOM

Backward OOM 可能源于激活保存、梯度或反向 workspace。本小节说明按层和序列长度定位峰值。

### 8.12.3 optimizer step OOM

优化器首次创建状态或更新临时张量可能导致峰值。本小节区分稳态参数与首步额外分配。

### 8.12.4 evaluation OOM

验证时的生成缓存、batch 和训练状态释放策略会影响内存。本小节说明训练/评估切换需单独测量。

### 8.12.5 一套可复现的 OOM 记录

可复现记录需包含阶段、显存曲线、输入形状、并行布局、dtype 和最后成功操作。本小节明确事故报告字段。

## 8.13 NaN、Inf、overflow 和 underflow

数值异常可由格式范围、尺度和运算路径共同产生。本节区分异常种类及其首发位置。

### 8.13.1 数值异常的时间点

异常首次出现于前向、反向、梯度归约或 optimizer step 可区分根因。本小节要求保留第一个坏值。

### 8.13.2 Overflow

数值超出格式上界会产生 Inf 或 NaN。本小节说明输入尺度、乘积和累积导致溢出的路径。

### 8.13.3 Underflow

过小数值可能被舍入为零，削弱梯度或状态更新。本小节说明低精度与尺度选择的影响。

### 8.13.4 Gradient clipping 的边界

Clip 可以限制异常梯度幅度，但不能恢复已经产生的 Inf/NaN，也不能修复错误标签。本小节明确其适用界限。

## 8.14 显存优化策略的对应关系

不同技术减少的是不同账本项目：重计算针对激活，分片针对状态，低精度针对表示，micro-batch 针对单次并行激活。本节将策略和瓶颈一一对应。

## 8.15 一个显存与数值预算审计示例

审计示例将参数、状态、激活、attention 临时量和数值格式统一到一个假设配置。本节说明估算与实际峰值的差异。

## 8.16 OOM 和数值异常的实验流程

故障排查要使用逐项控制变量和可回滚基线。本节说明 OOM 与数值问题各自的最小验证流程。

### 8.16.1 OOM 流程

OOM 流程需先定位阶段和峰值对象，再通过 batch、长度、重算或布局做隔离实验。本小节说明避免同时改多个因素。

### 8.16.2 NaN/Inf 流程

数值流程需定位首个异常张量、对应操作及其输入范围。本小节说明如何区分数据、精度和更新因素。

### 8.16.3 结果应该怎样报告

报告应保留硬件、软件、模型、输入、峰值、吞吐和精度配置。本小节说明优化结果的可比较边界。

## 8.17 资料边界与延伸阅读

延伸资料分别支持混合精度、attention kernel、checkpointing 和量化微调。本节提醒低比特结果必须绑定格式、scale、舍入与硬件。
