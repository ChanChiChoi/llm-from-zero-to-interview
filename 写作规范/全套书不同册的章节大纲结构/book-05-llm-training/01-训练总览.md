# 第一章：训练总览：从目标到可复现的 checkpoint

本章把大模型训练定义为一条从任务目标、数据与模型配置，经由参数更新、系统执行和阶段评估，最终得到可验证 checkpoint 的证据链。读者应能说明训练项目由哪些对象组成，区分训练量、资源成本与能力结果，并用同一套术语定位后续章节；具体机制由第 2—14 章分头主讲，本章不替代这些章节的推导和实现。

## 1.0 训练不是一次运行，而是一条证据链

训练结果需要由目标、数据版本、模型配置、更新轨迹、评估协议和恢复状态共同解释；权重文件只是这条链上的一个产物。本节确立全章共用的判断方式：任何训练结论都要指出它依据的对象、过程和证据。

## 1.1 从一个 checkpoint 反推训练项目

Checkpoint 可作为入口，反向追踪模型经历的阶段、训练状态和验证过程。本节统领权重、配置、数据及评估之间的关联，使读者理解为何一个可加载文件不等于可复现的训练项目。

### 1.1.1 权重只是结果，不是完整实验

参数张量不能单独说明模型由何种数据、目标、优化器和训练时长产生。本小节明确权重文件缺少的实验上下文及其对复现和比较的影响。

### 1.1.2 从产物反推阶段

训练产物、配置和评估记录可以帮助判断模型处于预训练、监督微调、偏好优化或后续适配阶段。本小节说明阶段推断需要哪些证据，以及仅凭模型命名推断训练路线的风险。

### 1.1.3 一个最小的可追溯关系

最小血缘关系应把模型版本连接到数据、训练配置、运行记录和评估结果。本小节限定可追溯的基本对象，为第十章实验管理和 checkpoint 机制提供总览入口。

## 1.2 先定义问题，再决定训练方法

训练方法必须回应明确的目标任务与约束；先选算法再补目标，容易产生无法验收的实验。本节把能力需求转成可观测的任务契约，并区分用户结果、训练目标和工程约束。

### 1.2.1 目标要包含输入、输出和约束

目标描述需界定模型接收什么输入、应产生什么输出，以及时延、权限、成本或安全等边界。本小节说明这些条件如何决定数据、训练信号和评估方式。

### 1.2.2 能力目标必须有切片

总体分数可能掩盖不同语言、领域、长度和失败类型的差异。本小节将能力目标落实为有代表性的切片，并指出切片定义、样本覆盖和指标选择对结论的限制。

### 1.2.3 小白视角与专家视角

可用语言描述的任务与工程上可测量的训练对象需要互相映射。本小节说明如何从读者熟悉的任务解释走到有效 token、更新数、指标和资源等专家口径，而不把二者混为一谈。

## 1.3 训练方法的历史脉络

训练方法的变化可由目标、反馈和可用计算能力的变化来理解，而不应写成互相替代的算法清单。本节只提供理解当前训练阶段的必要背景，并把历史事实与当前通用做法分开。

### 1.3.1 从统计语言模型到神经语言模型

语言建模从显式统计计数扩展到可学习的分布式表示和神经网络。本小节交代这一变化怎样引出大规模自回归建模，不展开与本册训练工程目标无关的模型史细节。

### 1.3.2 从 base model 到可交互模型

预训练语言模型的续写能力与按指令协作的行为并不相同。本小节说明监督微调、偏好反馈等阶段如何改变模型的使用方式，并为 1.11—1.12 节建立概念入口。

### 1.3.3 从结果奖励到过程和可验证奖励

后训练反馈由整段偏好扩展到可检查的任务结果及过程信号。本小节概述这些反馈类型解决的问题及其可验证范围，将算法细节交给第十一和第十六章。

## 1.4 完整训练链路的输入与输出

训练项目由多个相互依赖的阶段构成，每个阶段接收可追溯输入并产出可检查状态。本节梳理阶段之间的对象交接，并强调训练质量不能被单一 loss 概括。

### 1.4.1 阶段总表

阶段图景应覆盖数据准备、tokenizer/协议、模型初始化、训练、评估、后训练和交付。本小节明确每一环的主要输入输出以及后续章节的主讲位置。

### 1.4.2 训练项目不是只有一个 loss

优化目标衡量局部训练信号，不能单独证明任务能力、系统健康或安全要求。本小节列明训练项目还需观察的质量、资源、可靠性和回归证据。

## 1.5 自回归预训练目标

自回归预训练通过条件概率分解，把下一个 token 的预测转成可优化的目标。本节建立全书共用的语言建模对象，并交代 loss、mask 与监督位置的联系。

### 1.5.1 概率分解

序列概率可按前缀条件概率逐位置分解。本小节说明上下文前缀与目标 token 的关系，及其如何对应因果语言模型的预测任务。

### 1.5.2 交叉熵与困惑度

交叉熵汇总模型对目标 token 分配的概率，困惑度则是相同统计口径下的指数变换。本小节说明指标如何计算与解释，并限制其作为能力代理的适用范围。

### 1.5.3 label shift 与 padding mask

输入位置与监督目标需正确错开，padding 位置也不能混入有效损失分母。本小节说明因果预测、标签右移和有效 token mask 的对应关系。

### 1.5.4 从预训练到 SFT 的损失范围

预训练通常监督文本序列中的广泛位置，指令微调则可能只监督特定角色或消息片段。本小节比较目标范围变化如何改变有效监督量和训练行为。

## 1.6 Token 数、batch 和训练步数

训练数据量和更新量必须用一致的 token 口径连接，不能把样本条数、序列长度与优化器步数当作同一单位。本节说明有效 token、梯度累积和 epoch 在大规模训练中的含义。

### 1.6.1 为什么按 token 计算

文本样本长度不一，按文档或 batch 计数无法准确表示模型实际处理的监督位置。本小节区分原始 token、有效 token 和目标 token，并指出它们各自用于什么账本。

### 1.6.2 梯度累积改变了什么

梯度累积把多个 micro-batch 的梯度合并为一次参数更新，但它不会自动保证目标分母和不同长度样本的权重正确。本小节说明更新次数、吞吐和有效 batch 的换算边界。

### 1.6.3 Epoch 在 web-scale 训练中的含义

流式或重复采样数据不一定对应一次固定数据集的完整遍历。本小节说明 epoch、重复曝光和已处理 token 的区别，避免以名义 epoch 替代真实训练预算。

## 1.7 参数量、训练算力与 scaling law

参数量、训练 token 和计算量共同描述模型规模，但它们不能单独决定最终能力。本节介绍常见第一阶估算与 scaling law 的用途，区分估算账本和经验预测。

### 1.7.1 $6ND$ 是什么

$6ND$ 是 dense Transformer 训练主项的粗略算力估算，依赖参数量和训练 token 的具体口径。本小节说明它适合早期筛选、遗漏哪些项，以及不能代替 profiler 的原因。

### 1.7.2 Scaling Laws 提供什么信息

缩放关系用于在特定模型、数据和计算条件下估计损失随资源变化的趋势。本小节说明拟合变量、适用范围与外推风险，不把研究曲线当作跨任务的保证。

### 1.7.3 Dense 与 MoE 的参数账本

稠密模型参数通常参与每个 token 的主要计算，稀疏 MoE 则需分别记录总容量与 active 计算。本小节说明两类规模口径如何影响训练 FLOPs、权重存储和系统需求。

## 1.8 训练时间、GPU 小时和显存

计算量必须经过实测吞吐、并行效率和运行时停顿，才能转成可用的训练计划。本节将理论算力与 wall-clock、设备资源及完整成本分开核算。

### 1.8.1 从吞吐估算总时间

训练 token 数除以有效吞吐可给出理想训练时长，实际时长还受评估、保存、通信和故障影响。本小节区分计划下界与项目排期。

### 1.8.2 权重、梯度和 optimizer state

训练显存不仅存模型权重，还包括梯度、优化器状态、激活和临时缓冲。本小节概述主要占用来源，并把精细计算留给第八章。

### 1.8.3 训练成本不止 GPU 价格

算力之外还需考虑存储、网络、数据生产、人员、失败重跑和评估成本。本小节明确成本核算边界，并指向第十三章的单位成功成本方法。

## 1.9 Tokenizer、数据和架构的联动

数据单位、切分方式和模型形状互相影响实际训练工作量。此节说明常见配置变量之间的约束，避免分别优化一个组件却让整体预算或能力目标恶化。

### 1.9.1 Tokenizer 影响训练预算

Tokenizer 改变相同原文对应的序列长度、词表参数和输出层计算。本小节说明比较 tokenizer 时为何要区分固定原文 bytes、token 数和计算预算。

### 1.9.2 数据 mixture 不是样本列表

数据配比决定有限训练预算中各领域被观察和重复的程度。本小节解释文档占比与 token 曝光的差异，并为第二章的数据 mixture 设计提供入口。

### 1.9.3 架构是目标和约束的折中

架构选择会同时改变表达能力、计算、显存、缓存与部署可行性。本小节说明模型宽度、层数、上下文及稀疏化应绑定目标任务和资源限制。

## 1.10 一次 optimizer update 内部发生什么

一次更新连接前向、loss、反向、梯度处理、优化器状态和参数写回。本节给出全册共用的更新对象及顺序概念，具体实现由第五至第九章展开。

### 1.10.1 梯度裁剪不是修复所有异常

梯度裁剪只限制某类更新幅度，不能修复错误标签、损坏数据、无穷值或恢复状态不一致。本小节说明它的机制边界和诊断价值。

### 1.10.2 训练步、数据步与评估步

数据消费、参数更新和验证运行以不同频率推进。本小节区分三种步数及其日志口径，避免将同一个 step 数误当成完整训练进度。

## 1.11 Base、Instruct、Chat 与 Reasoning Model

模型阶段名称描述训练后呈现的行为属性，不等同于唯一算法或 checkpoint 格式。本节用四类常见模型状态解释能力目标和训练信号的关系。

### 1.11.1 Base model

Base model 主要学习给定前缀下的文本续写分布。本小节说明其基本训练目标与仍未保证的指令、对话和任务行为。

### 1.11.2 Instruct model

Instruct model 经示范数据学习遵循任务指令的输出形式。本小节说明监督微调所建立的行为接口及其与更广义能力的区别。

### 1.11.3 Chat model

Chat model 需要遵循多轮消息协议、角色边界和停止语义。本小节说明对话格式和用户可见行为之间的联系。

### 1.11.4 Reasoning model

Reasoning model 通过训练或推理期预算呈现更复杂的多步问题解决行为。本小节区分模型训练信号、测试时计算与外显推理文本，不将其等同于单一训练配方。

## 1.12 后训练：把能力组织成行为

后训练在预训练模型上调整行为、偏好和可验证任务表现。本节建立 SFT、偏好优化与验证反馈的总览关系，细节由第十一及第十五至十八章承担。

### 1.12.1 SFT 先建立协议

监督微调用示范让模型学习期望输入输出协议和回答方式。本小节说明示范信号能教会什么，以及 token-level 监督与任务成功的区别。

### 1.12.2 偏好优化改变选择倾向

偏好训练使模型在多个可行回答中更常选择被偏好的响应。本小节概览显式奖励模型、在线策略优化和直接偏好目标的差异。

### 1.12.3 偏好和验证器的边界

主观偏好判断与程序可检查的正确性提供不同监督信号。本小节说明二者的互补关系以及各自可能产生的误导。

## 1.13 训练监控：四张互相连接的仪表盘

训练是否健康需同时看优化、数值、系统和能力证据。本节把监控指标连接到可诊断的问题，而非把看板读数当成故障根因。

### 1.13.1 优化健康

Loss、梯度和参数更新反映优化过程是否按预期推进。本小节说明常见信号与需要进一步核查的机制。

### 1.13.2 数值健康

有限精度训练需要关注溢出、下溢、非有限值和异常梯度。本小节界定数值监控的观测对象，详细处理留给第八和第九章。

### 1.13.3 系统健康

吞吐、显存、通信和设备故障影响训练能否持续执行。本小节说明系统指标如何与训练轨迹相连。

### 1.13.4 能力健康

验证集和目标任务切片用于观察能力增长、回归或评测异常。本小节强调评估协议和训练数据边界对解释的影响。

## 1.14 Checkpoint、恢复和选择

Checkpoint 既可以用于推理交付，也可能保存继续训练所需的完整状态。本节概述保存、恢复和选择之间的区别，为第五、十章机制主讲建立入口。

### 1.14.1 三类 checkpoint

推理权重、可继续训练状态和评估候选可能具有不同的包含内容及用途。本小节明确区分这些交付对象。

### 1.14.2 为什么最后一步不一定最好

训练最后的参数可能在目标能力、稳定性或回归指标上弱于中间 checkpoint。本小节说明模型选择需要多目标证据，而不是只看训练步数。

### 1.14.3 恢复验证

恢复验证需确认权重、优化器、调度器、随机状态、数据游标和分布式状态是否连续。本小节区分“能够加载”与“能够从同一训练状态继续”。

## 1.15 常见失败链：从现象追到根因

训练异常需要沿数据、优化、数值、系统和评估链条定位。本节建立症状到候选根因的排查地图，不以单一修复动作替代证据。

### 1.15.1 Loss 不下降

Loss 不降可能源于目标、标签、数据流、参数更新或优化配置问题。本小节整理首轮定位方向。

### 1.15.2 Loss spike 或 NaN

突增和非有限值具有不同时间特征与候选机制。本小节说明应先定位第一个异常对象，再区分数据、学习率、精度和恢复因素。

### 1.15.3 吞吐下降

吞吐变化可能来自输入、通信、同步、计算负载和长序列分布。本小节强调按阶段和设备观测拆分瓶颈。

### 1.15.4 评估分数异常

分数异常可能反映真实变化，也可能来自评测协议、污染、提示或样本覆盖。本小节将模型能力判断与评测实现检查分开。

### 1.15.5 后训练能力退化

后训练可能提升目标行为同时损害其他能力或安全边界。本小节说明回归诊断需要按目标切片和更新信号定位。

## 1.16 一个可复现训练项目应交付什么

项目交付物应使第三方能够追踪数据、配置、训练状态、评估结论和已知限制。本节汇总最小证据包，并与第十章实验管理衔接。

### 1.16.1 数据与 tokenizer 产物

数据 manifest、处理版本、tokenizer 和序列化协议共同定义模型实际看到的输入。本小节说明必要版本信息和回放入口。

### 1.16.2 模型与训练产物

模型配置、权重、优化器/调度器状态和运行记录使训练状态可解释和恢复。本小节界定这些产物的相互关系。

### 1.16.3 评估与事故产物

评估协议、回归结果、故障时间线和修复记录说明交付能力及其边界。本小节要求保留结论依据，而不只报告最终分数。

## 1.17 一个最小训练规划账本

训练规划将参数量、训练 token、global batch、更新数、吞吐、时间和存储放入同一组假设中。本节限定账本是早期可行性估算，不把教学假设冒充硬件实测或交付承诺。

## 1.18 证据边界：什么可以由资料确认

论文、官方披露、实现文档、benchmark 和本地实验分别支持不同层次的主张。本节说明如何标记来源、条件与未验证项，并避免从单个模型或实验外推普遍结论。

## 1.19 章节练习：把训练链路变成可计算对象

练习围绕训练量口径、方案诊断、checkpoint 判断和资源选择，检验读者能否把总览概念转成可核查的分析。

### 练习一：检查 token 口径

读者应辨认文档 token、有效输入 token 与参与 loss 的目标 token，并说明各自的分母。

### 练习二：比较两种 tokenizer

读者应在固定原文与固定 token 预算两种口径下比较压缩收益和模型计算成本。

### 练习三：定位 loss 不下降

读者应把训练现象拆成标签、数据、梯度和优化器等可区分假设。

### 练习四：比较 base 和 instruct checkpoint

读者应根据训练阶段、输入协议和行为证据解释两个 checkpoint 的差别。

### 练习五：设计 checkpoint 选择实验

读者应提出包含质量、能力回归和恢复要求的选择证据。

### 练习六：拆解一次吞吐下降

读者应区分输入、通信、设备利用率和有效 token 口径等候选原因。

### 练习七：恢复训练一致性

读者应列出验证连续训练与 checkpoint 恢复是否等价所需的状态和观测。

### 练习八：在固定预算下选择模型规模

读者应在计算、数据和模型能力证据之间作有条件的规模判断。

## 1.20 本章总结

总结训练闭环各对象之间的依赖关系，并把读者从全流程地图引向数据、协议、架构和更新的逐章学习。
