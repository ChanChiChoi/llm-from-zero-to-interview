# 第三章：Tokenizer 与数据格式：从字符到训练协议

本章说明模型看到的训练对象不是原始句子，而是经过 tokenizer、模板、媒体表示、标签与 mask 共同定义的序列协议。读者应能追踪文本如何变成 token ID 和训练目标，检查序列化、packing、工具调用及词表扩展的一致性；tokenizer 算法谱系由第二册深入，本章承担训练接口与协议审计。

## 3.0 模型看到的不是句子，而是一串带协议的整数

训练输入由 token ID、位置、边界事件和监督 mask 构成。本节确立数据格式与模型行为之间的接口关系，提醒读者可见文本不等于模型实际接收的表示。

## 3.1 Tokenizer 的输入、输出和不变量

Tokenizer 将规范化后的文本映射为 ID 序列，并承担解码和特殊 token 解释。本节界定输入输出及编码协议的不变量。

### 3.1.1 编码和解码

编码将文本转为 token ID，解码则依赖同一词表和规则恢复可见文本。本小节说明两者的接口关系和可能的信息损失。

### 3.1.2 Token id 不是 token 字符串

Token ID 是词表中的索引，其数值大小不表示语义或排序。本小节说明字面 token、ID、词表行与模型参数之间的对应关系。

### 3.1.3 Tokenizer 的不变量

同一版本 tokenizer 应保持特定输入输出映射、特殊 token 行为和词表索引约定。本小节界定版本回归需要验证的稳定性质。

### 3.1.4 规范化决定“可逆”究竟指什么

文本规范化可能改变空白、字符或拼写，因此 round-trip 可逆性需相对于明确的规范化步骤定义。本小节区分字节级、字符级与语义层面的还原。

### 3.1.5 把编码过程变成可回放记录

回放记录需保存原文、token ID、tokenizer 版本和特殊 token 处理结果。本小节说明如何定位编码差异。

## 3.2 切分方法在训练协议里的位置

分词算法影响 token 序列长度和建模单位，但模型训练协议还需决定边界、mask 和任务目标。本节把算法切分和训练接口分开。

## 3.3 BPE：训练语料会决定合并表

BPE 根据统计合并规则构建词表，语料和合并顺序会影响最终 token 分布。本节关注该机制对训练长度、覆盖和版本兼容的影响。

## 3.4 SentencePiece 与 Unigram LM：工具、模型和采样要分开

SentencePiece 是 tokenizer 工具框架，Unigram LM 是一种子词建模方法，分词采样又是独立训练选择。本节澄清这些层次，避免将工具名和算法行为混为一谈。

## 3.5 Byte-level BPE 与 byte fallback：覆盖不等于效率

字节级表示可扩大任意输入的可编码性，但未知字符覆盖和 token 效率是两个不同指标。本节说明 fallback 机制与低资源语言/特殊输入成本。

## 3.6 词表大小：序列长度和输出层成本的交换

更大的词表可能减少序列长度，却会增加 embedding、输出层和通信成本。本节建立词表规模的多项账本，并限定压缩率作为选择指标的边界。

### 3.6.1 参数账本

词表行数和 hidden size 决定 embedding 与可能不共享的输出矩阵规模。本小节说明参数、权重存储及词表通信之间的关系。

### 3.6.2 词表大的好处

较大词表可能让常见片段以更少 token 表示，改善上下文容量或某些语言/领域的序列效率。本小节说明收益需要按数据切片测量。

### 3.6.3 词表大的代价

更大词表会扩展 embedding 和 logits 计算，并加重 softmax 与并行通信。本小节说明序列缩短不保证总训练计算下降。

### 3.6.4 一个词表扩大的账本

受控计算例把序列长度、词表大小、输出投影和参数量放到同一组假设下。本小节要求明确计算口径和忽略项。

### 3.6.5 不能只看平均压缩率

整体 token/byte 均值可能掩盖不同语言、代码、数学和长尾文本的极端膨胀。本小节强调分桶和分位数统计。

### 3.6.6 压缩率重要，但它不是 tokenizer 质量的全部

压缩率与下游质量之间不存在无需条件的单指标映射。本小节比较 intrinsic 指标、受控训练和目标任务评估各自回答的问题。

### 3.6.7 从 token 统计走到训练预算

Tokenizer 比较必须说明固定原文、token 数还是 FLOPs，并计入模型结构和硬件影响。本小节把长度统计连接到训练和推理账本。

## 3.7 序列化与监督协议：特殊符号、模板和标签

特殊 token、消息模板和 mask 共同定义序列的控制结构与训练目标。本节区分可见标记、token ID、上下文可见性和 loss 参与范围。

### 3.7.1 三类控制符号

边界、结束和填充等控制符号承担不同协议作用。本小节明确这些事件不可仅凭相似字符串互换。

### 3.7.2 EOS 的训练与推理语义

EOS 可表示样本/回答终止并影响训练目标和推理停止。本小节说明其注册、监督及服务端停止条件应保持一致。

### 3.7.3 PAD、attention mask 和 loss mask

Padding mask 控制可见位置，loss mask 控制参与监督的位置，二者并不相同。本小节梳理各 mask 的职责和错配风险。

## 3.8 Chat template：消息如何变成生成提示

Chat template 将角色、消息体、工具和结束事件编成模型可读序列。本节把模板视为可执行的数据协议，而非装饰性文本格式。

### 3.8.1 两层转换

模板通常先将对话对象映射为可见序列，再由 tokenizer 编码为 token ID。本小节说明两层接口及其各自可能引入的差异。

### 3.8.2 模板不一致的症状

训练与推理模板不一致会造成角色、边界或停止行为偏移。本小节说明如何从输入序列和生成结果中识别协议漂移。

### 3.8.3 生成提示和训练标签

同一模板中的提示部分与目标回复部分承担不同监督作用。本小节说明生成前缀、assistant 回合及标签区间的关系。

### 3.8.4 模板是可执行的数据协议

模板版本会改变 token 序列和训练接口，因此需要像代码配置一样测试和追踪。本小节说明模板回归和版本记录的重要性。

## 3.9 Label mask：输入可以完整，监督必须有边界

模型可读取完整上下文，但只有部分位置应承担目标损失。本节明确 assistant-only、工具和多轮样本中的监督范围。

### 3.9.1 Assistant-only SFT

Assistant-only 监督让模型读取整段对话而只预测 assistant 指定片段。本小节说明角色边界、目标 token 数和损失分母。

### 3.9.2 多轮和工具数据的 mask

多轮工具轨迹需要区分 assistant 调用、工具响应和后续回答。本小节说明每类消息是否参与监督由训练任务契约决定。

### 3.9.3 Label 在模型里还要右移一位

因果语言模型在位置 $t$ 的输出通常预测下一个位置的目标。本小节说明 mask 与 shift 的对齐关系及常见错位后果。

## 3.10 预训练文本、EOS 与 packing

预训练样本如何序列化、拼接和截断会影响文档边界与有效监督。本节梳理文本流进入固定长度训练块时的协议选择。

### 3.10.1 文档序列化

文档边界、标题和结束符需以一致方式编码。本小节说明序列化如何保留文档单位和上下文关系。

### 3.10.2 Packing 利用率

Packing 将多个样本填入较少 padding 的训练序列。本小节说明吞吐收益与边界隔离、注意力行为的权衡。

### 3.10.3 截断策略

截断决定过长样本的内容保留和监督丢失。本小节比较截断位置与任务目标之间的关系。

### 3.10.4 用一组文档复算 packing 与边界成本

离散文档例用于核对 packing 利用率、截断和边界标记对 token 数的影响。本小节要求明确每种序列化假设。

## 3.11 训练任务的数据格式：JSON 只是容器

JSON 语法并不自动定义样本字段的语义、监督目标或运行协议。本节区分容器、schema 与训练器对字段的解释。

### 3.11.1 单轮与多轮

单轮问答和多轮对话的上下文依赖与终止条件不同。本小节说明样本结构如何表达消息顺序。

### 3.11.2 数据质量边界

格式合法不代表答案正确、完整或适合训练。本小节要求单独审计内容质量与目标一致性。

### 3.11.3 训练框架字段不等于模型协议

框架内部字段可被转换或丢弃，不能假设与 tokenizer 序列一一对应。本小节说明数据读取、collator 和模型接口之间的验证点。

## 3.12 偏好、强化和可验证数据格式

偏好对、组内候选和工具轨迹需要保存不同的比较、奖励与状态信息。本节说明数据结构如何对应不同训练目标。

### 3.12.1 Pairwise preference

偏好记录需关联同一 prompt 下的候选回答及其比较标签。本小节说明 chosen/rejected 数据的关系和标注条件。

### 3.12.2 组内候选和验证器

强化学习组样本需关联 prompt、各条轨迹、奖励和 verifier 输出。本小节说明轨迹级数据与可复放结果的字段边界。

### 3.12.3 长度和偏好偏差

回答长度及评分方式可能改变偏好数据中的比较信号。本小节要求记录长度分布并识别评分偏置。

## 3.13 Tool calling：数据格式连接模型和外部副作用

Tool calling 样本把模型生成、工具请求、执行结果和权限边界连接成轨迹。本节说明训练协议如何与运行时外部动作相接。

### 3.13.1 一条完整轨迹

完整轨迹包含请求、参数、工具返回和 assistant 后续响应。本小节明确事件顺序和回放所需的信息。

### 3.13.2 Schema 和边界检查

参数 schema 可检查结构与类型，但业务规则和权限仍需独立验证。本小节说明多层校验的职责。

### 3.13.3 训练与运行时的边界

模型学会输出调用格式不等于工具已安全执行。本小节区分生成协议、执行器授权和结果验收。

## 3.14 多模态 token 与占位符

媒体输入可能由特殊 token、非文本 payload 和多个视觉/音频片段共同表示。本节说明可见占位符无法揭示完整媒体序列成本。

### 3.14.1 `<image>` 不一定是一个视觉 token

一个图像标记可能展开为多个 patch、crop 或编码器状态。本小节说明实际视觉 token 数依赖模型和预处理路径。

### 3.14.2 粗略 token 账本

媒体分辨率、帧数和音频长度会改变序列、计算与内存成本。本小节建立估算所需的单位和边界。

### 3.14.3 视觉、音频与文本的边界

模态边界、时间戳和媒体片段要与文本任务目标相对应。本小节说明多模态样本的结构化序列化需求。

## 3.15 Tokenizer 扩展：改变词表就是改变模型接口

新增 token 会同时影响映射、参数矩阵、训练目标和推理模板。本节将词表扩展视为模型状态迁移，而非单独修改 tokenizer 文件。

### 3.15.1 需要同步的对象

Tokenizer、配置、embedding、输出头、优化器状态、checkpoint 和服务端 parser 必须兼容。本小节界定扩词表需要同步的接口。

### 3.15.2 新 token 如何获得语义

初始化只提供新向量起点，语义还需由目标数据与训练过程建立。本小节比较初始化方式及其证据限制。

### 3.15.3 旧数据和新词表

保存 token ID 的旧数据可能无法直接用于新词表，而原始文本可以重新编码。本小节说明数据迁移和训练预算重算。

### 3.15.4 词表扩展需要模型状态迁移和回归

扩词表需验证行索引、权重共享、优化器状态和 checkpoint 一致性。本小节把结构检查连接到旧能力与新增领域的回归验收。

## 3.16 一个最小的数据格式审计器

审计器应检查 schema、消息边界、tokenizer 输出、mask 与训练器解释是否一致。本节说明小工具可验证的协议范围及未覆盖的语义问题。

## 3.17 常见协议故障

协议故障通常表现为训练和推理接口不一致、监督位置错误或新增符号没有学会。本节按故障类型说明需追踪的链路。

### 3.17.1 训练和推理 tokenizer 不一致

词表或规范化差异会改变输入 ID 和输出解码。本小节说明如何比较版本、样本和回放序列。

### 3.17.2 EOS、PAD 和停止条件不一致

结束标记、填充和运行时停止规则混用会导致过早结束或持续生成。本小节区分各事件的训练与推理行为。

### 3.17.3 Label mask 错位

mask 偏移会让模型在错误角色或位置上承担监督。本小节说明通过对齐 token、label 和损失分母定位问题。

### 3.17.4 Packing 边界错误

文档间注意力泄漏或错误重置会改变训练上下文。本小节说明边界策略及其验证方法。

### 3.17.5 截断丢失监督

截断可能保留提示却移除目标，或破坏工具/多轮轨迹。本小节要求统计空监督、部分轨迹与目标覆盖。

### 3.17.6 新 token 未被学习

Tokenizer 已能输出新 ID 不等于模型已能正确读写该 token。本小节检查出现频率、输入输出矩阵和监督路径。

## 3.18 评估 tokenizer 与数据格式

协议评估需覆盖编码、解码、模板、标签、packing 和跨版本行为。本节定义训练接口的系统性回归范围。

### 3.18.1 Tokenizer 评估

Tokenizer 评估检查覆盖、压缩率、分桶长度、特殊 token 与回放一致性。本小节说明指标需要按语料和任务分层。

### 3.18.2 数据格式评估

数据格式评估验证字段、消息顺序、角色、mask 与目标行为。本小节说明结构通过并不等于内容质量通过。

### 3.18.3 跨版本回归

版本升级需要对照旧样本的编码、解码和模型输入变化。本小节界定哪些变化需显式批准。

### 3.18.4 一套可复查的协议回归样例

代表样例应覆盖普通文本、多轮、工具、padding、截断和媒体内容。本小节说明可复查集合如何支撑版本对照。

### 3.18.5 版本通过条件

通过条件应将不可破坏的不变量、可接受变化和未验证范围写清。本小节要求将版本判定绑定目标系统。

## 3.19 资料边界与延伸阅读

延伸资料分别支持 tokenizer 算法、格式规范、实现行为和跨版本评估，不将单一教程当作所有模型的协议定义。

## 3.20 章节练习：从协议打印到协议回归

练习从 token 预算和协议 manifest 开始，逐步检查模板、mask、packing、扩词表和收益归因。

### 练习一：为训练建立 token 预算

读者应按一致口径计算目标 token、更新数和输出层成本。

### 练习二：做一份 tokenizer manifest

读者应记录词表版本、规范化规则、特殊 token 和编码回放信息。

### 练习三：检查 chat template

读者应将结构化消息、渲染文本与最终 token ID 对齐。

### 练习四：定位 label mask 错位

读者应从角色和位置映射解释损失错误的来源。

### 练习五：比较 packing 边界

读者应核算 padding 利用率并检查文档间上下文是否符合目标。

### 练习六：扩展工具 token

读者应设计从新符号注册到模型生成和 parser 处理的端到端检查。

### 练习七：设计 tokenizer 版本升级回归

读者应用代表样本比较旧新 tokenizer 的输入输出协议。

### 练习八：区分压缩收益与训练收益

读者应在固定 bytes、token 和计算预算下区分结论。

### 练习九：评估受控的词表扩展

读者应组合参数成本、目标语言收益和旧能力回归设计评估方案。

## 3.21 本章小结

总结 tokenizer、消息格式和训练监督共同形成模型接口的观点，并引向第四章的架构配置。
