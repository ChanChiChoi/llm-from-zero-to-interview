# 第 8 章 Agent 项目实战

**正文对应：** [协议与状态循环](../../../book-03-practical-handbook/chapters/08-agent项目实战-1-协议与状态循环.md)、[安全审计与验收](../../../book-03-practical-handbook/chapters/08-agent项目实战-2-安全审计与验收.md)

本章围绕 Agent 如何在明确权限、预算和业务状态内提出并执行工具动作展开。读者要区分模型提议、schema 校验、授权判定、真实副作用、回执和最终状态，建立有界可恢复循环、可审计轨迹与可验收项目。

## 8.1 模型提出请求，程序决定是否执行

本节以结构化工具协议建立模型与执行器之间的边界，并检查 schema、工具注册、执行状态与回执。

### 8.1.1 为什么需要工具调用协议

说明自然语言请求为何需转换成带名称、参数和调用 ID 的结构化消息。

### 8.1.2 Schema 能检查形状，不能替代授权

区分字段类型/必填约束与用户权限、业务状态和动作风险。

### 8.1.3 先把一个小工具做得可控

界定单工具函数、输入校验、确定性返回和可观察副作用。

### 8.1.4 工具目录、参数检查与执行函数要分开

说明声明能力、验证请求和调用外部系统的职责分离。

### 8.1.5 调用标识、并行和结果状态

覆盖 call ID 关联、并行调用结果对齐和成功/失败/超时状态。

### 8.1.6 让调用过程留下可读回执

说明工具返回结构应反映执行事实、外部状态和可恢复信息。

## 8.2 从一次调用走到有界循环

本节把工具交互建模为状态事件循环，明确工具协议与 ReAct 策略的差别，并管理预算、中断与恢复。

### 8.2.1 用轨迹表示一轮 Agent 任务

定义任务事件、模型节点、工具请求和回执之间的关联。

### 8.2.2 把状态存成事件，而不是一段不断变长的文字

说明事件状态的结构化、因果关联和恢复能力。

### 8.2.3 Tool Calling 是协议，ReAct 是循环

区分接口如何表达动作与 Agent 如何根据观察继续推理的策略。

### 8.2.4 给循环设硬预算和终止状态

限定轮数、token、时间、成本和成功/失败/未知等明确终态。

### 8.2.5 “有进展”要能被检查

界定状态变化、证据获得或目标条件满足等可检验进展。

### 8.2.6 持久化状态，让任务能在中断后恢复

覆盖状态快照、事件顺序、幂等调用和恢复时的外部一致性。

### 8.2.7 用一个可核算例子估算循环成本

将模型调用、工具调用、重试和人工处理合并为任务级成本。

## 8.3 一次动作需要独立的控制条件

本节从风险分级和最小权限开始，将提示注入、业务语义、确认、重试和隔离落实到执行边界。

### 8.3.1 风险分级与最小权限

按读取/写入/不可逆程度限定工具权限、数据范围与确认门槛。

### 8.3.2 外部内容是数据，不能变成新的系统指令

说明检索文档、工具结果和用户内容可能包含恶意指令，应保持数据边界。

### 8.3.3 Schema 通过之后，还要核对业务语义

检查金额、对象归属、状态前置条件和业务规则，超出字段类型校验。

### 8.3.4 高风险确认要绑定具体参数

要求确认对象、金额、目标状态等动作要素及其版本，避免笼统同意被复用。

### 8.3.5 重试要服从副作用语义

区分幂等与非幂等写操作、超时未知状态和安全重试条件。

### 8.3.6 沙箱和网络边界控制爆炸半径

说明进程隔离、文件/网络权限和密钥暴露限制的作用与局限。

### 8.3.7 用 guard 把检查点放在一次请求里

把身份、授权、参数、状态、确认和审计检查放到执行前后流程。

## 8.4 让每一步可以关联和复盘

本节定义轨迹证据与明确终态，建立覆盖边界样例的评估集和分项报告。

### 8.4.1 轨迹回答“发生了什么”

记录提议、程序判定、执行回执、外部状态变化和用户可见响应。

### 8.4.2 first failure stage 与明确终态

定位首个破坏关键不变量的阶段，区分超时、停止、失败和未知状态。

### 8.4.3 评估集要覆盖边界和失败类别

覆盖正常、权限拒绝、歧义、重试、并行、注入和副作用恢复场景。

### 8.4.4 公开 benchmark 借鉴测试构造，不替本地系统背书

说明公开任务集与真实工具/权限/业务约束之间的迁移距离。

### 8.4.5 报告不要揉成一个总分

分别呈现任务成功、策略合规、真实副作用、恢复和成本等结果。

## 8.5 把任务范围写清，再检查结果

本节将项目能力边界、事件因果关系、任务对象、业务语义和验收证据组成可交付项目。

### 8.5.1 先写清系统能做什么

定义支持的任务、用户、可调用工具和明确不支持的场景。

### 8.5.2 让事件链保留因果关系

关联请求、授权、工具调用、回执和状态变化，支持回放与审计。

### 8.5.3 最小任务对象

确定任务 ID、状态、输入、目标、权限、预算和完成判定的记录结构。

### 8.5.4 用边界样例检查业务语义

通过反例、临界值、旧状态和歧义请求验证业务规则执行。

### 8.5.5 把 RAG 证据和 Agent 动作接在正确边界

说明证据支持回答不自动授予动作权限，来源与授权要分别核验。

### 8.5.6 处理时点变化和版本冲突

处理文档更新、外部状态变化和执行中版本不一致造成的失效。

### 8.5.7 交付可复核的项目证据

汇总版本、轨迹、回归集、权限测试、失败案例和验收记录。
