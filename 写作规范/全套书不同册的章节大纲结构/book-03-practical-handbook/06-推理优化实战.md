# 第 6 章 推理优化实战

**正文对应：** [缓存、延迟与调度](../../../book-03-practical-handbook/chapters/06-推理优化实战-1-缓存延迟与调度.md)、[量化与推测解码](../../../book-03-practical-handbook/chapters/06-推理优化实战-2-量化与推测解码.md)、[长上下文压测与报告](../../../book-03-practical-handbook/chapters/06-推理优化实战-3-长上下文压测与报告.md)

本章围绕推理请求的状态、时间、内存和任务质量组织工程优化。读者从 KV cache 与请求时间线开始，比较分页调度、量化和 speculative decoding，再通过长上下文压测判断服务是否满足业务条件；理论容量和 API 存在不等于目标负载下的实测收益。

## 6.1 KV Cache：把历史注意力状态保存下来

本节说明自回归解码为什么缓存历史 Key/Value，如何估算容量、保持位置状态正确，并区分前缀缓存、会话记忆和语义记忆。

### 6.1.1 每生成一个 token，为什么要保留前面的计算结果

说明逐 token 解码中重复计算历史注意力的代价以及缓存复用目的。

### 6.1.2 从注意力公式看 cache 保存了什么

明确每层、每个 token 的 Key/Value 张量及其与当前 Query 的关系。

### 6.1.3 MHA、GQA 和 MQA 如何改变 cache 形状

比较 query head 与 KV head 数量对缓存张量布局和内存规模的影响。

### 6.1.4 KV Cache 显存公式

估算层数、KV heads、head dimension、序列长度、batch 与 dtype 共同决定的容量。

### 6.1.5 Prefill 和 Decode 阶段的 cache 写入

说明输入提示的并行处理与后续单步生成如何分阶段写入并读取缓存。

### 6.1.6 RoPE offset：cache 正确性中的位置编号

解释缓存续算时位置索引必须延续已处理 token，而非从零重新开始。

### 6.1.7 Prefix Cache、会话 cache 和语义记忆不是一回事

区分 token 前缀复用、运行时会话状态与检索型长期记忆的对象和失效条件。

### 6.1.8 失败模式：从形状和长度逐步定位

覆盖缓存长度、batch/head 维、位置偏移和资源估算不符等常见问题。

### 6.1.9 资料与证据边界

明确缓存计算公式、框架 API 与具体 runtime 行为分别需要何种版本和硬件证据。

## 6.2 Prefill/Decode：把延迟和吞吐拆成可测量的部分

本节建立请求时间线和延迟指标，区分 prefill 与 decode 的资源特征，说明 GPU 异步计时、chunked prefill 和排队影响。

### 6.2.1 从一次请求的时间线开始

按到达、排队、prefill、首 token、后续生成和结束拆解端到端请求。

### 6.2.2 四个基本指标

定义 TTFT、TPOT、端到端延迟与吞吐并说明各自分母。

### 6.2.3 一个简单的时间拆分

以阶段时长组合说明串行延迟近似及并发关键路径的边界。

### 6.2.4 为什么 CUDA 异步会让计时失真

解释主机计时与 GPU kernel 调度不同步时的测量偏差及同步代价。

### 6.2.5 Prefill 和 Decode 各自消耗哪些资源

比较提示处理的批量计算与逐 token 生成在算力、带宽和 KV 读写上的负载。

### 6.2.6 无依赖的延迟计算示例

用固定阶段数据演示指标计算与统计口径，不将算例当作 runtime 基准。

### 6.2.7 Chunked Prefill 与调度取舍

说明切分长提示的目的及对长请求完成时间、短请求公平性和吞吐的影响。

### 6.2.8 失败模式：指标好看但体验变差

识别平均延迟、吞吐或 token 速度掩盖排队尾延迟和请求级体验的情形。

### 6.2.9 资料与证据边界

界定测量代码、硬件同步方式及服务压测数据所支持的结论范围。

## 6.3 vLLM：PagedAttention、连续批处理和协议边界

本节用分页 KV block 和连续批处理解释服务调度，进一步区分 OpenAI 兼容协议与实际模型/服务行为。

### 6.3.1 KV Cache 为什么可以分块存放

说明固定物理 block 对动态长度请求和碎片管理的价值。

### 6.3.2 KV block 容量估算

将 block token 数、每 token KV 字节数与并发请求容量相连。

### 6.3.3 分页为什么能减少浪费，但不能消灭开销

分析尾块浪费与索引、调度、复制和模型自身计算开销。

### 6.3.4 Continuous Batching：按 token 调度，而不是等整批结束

解释请求动态加入/退出 batch 的执行逻辑与吞吐/公平性权衡。

### 6.3.5 一个无依赖的 block allocator demo

以简化分配状态展示 block 生命周期，不把示意程序当作 vLLM 实现。

### 6.3.6 vLLM 参数如何映射到资源问题

将常见配置映射到缓存、并发、批处理与内存预算，并要求核对具体版本。

### 6.3.7 OpenAI 兼容服务的边界

说明协议形状相似不保证模型能力、生成选项、错误语义和运维特性完全相同。

### 6.3.8 vLLM 与其他 runtime 的比较方法

建立相同模型、工作负载、硬件、指标和质量要求下的对照边界。

### 6.3.9 资料与证据边界

标明论文机制、官方版本文档和本地压测结果各自能支持的陈述。

## 6.4 量化：分别看权重、计算和 KV Cache 的占用

本节区分量化存储、计算精度与缓存量化三条路径，覆盖数值误差、资源估算和质量回归。

### 6.4.1 4 bit 只说明一种存储表示

说明位宽不自动决定实际峰值内存、计算速度或任务质量。

### 6.4.2 对称量化的基本公式

定义 scale、zero point/对称映射、rounding 与反量化误差。

### 6.4.3 FP16、BF16、INT8、INT4 和 NF4 的差异

比较浮点格式、整数线性量化和非均匀量化的表示假设。

### 6.4.4 粗略估算 7B 模型的权重显存

用参数量和每参数位宽估算权重存储，并列明未计入的运行时开销。

### 6.4.5 无依赖的分组量化 demo

以分组 scale 展示量化与反量化误差，限定为小型数值示例。

### 6.4.6 QLoRA、NF4 和 double quant 的位置

连接训练态量化基座、低秩参数和量化常数存储，避免与推理量化混用。

### 6.4.7 KV Cache 量化是另一条链路

区分权重与运行时状态的量化对象、误差传播和服务支持条件。

### 6.4.8 量化质量回归应该测什么

要求按目标任务、风险类别、延迟、吞吐和内存同时验证。

### 6.4.9 失败模式

覆盖校准失配、算子回退、混合精度不一致和低频关键行为回退。

### 6.4.10 资料与证据边界

指出量化算法论文、runtime 支持表与指定模型实测之间的边界。

## 6.5 Speculative Decoding：让小模型先提议，大模型批量验证

本节解释 draft/target 提议与验证过程，区分 greedy 和采样分布校正，并从接受率与硬件实测判断加速收益。

### 6.5.1 一次核验为什么可能接受多个 token

说明 target 模型可并行验证候选 token，接受前缀后减少逐步 target 调用。

### 6.5.2 Greedy 验证的教学版

界定贪心目标下候选一致性与回退到 target token 的逻辑。

### 6.5.3 采样时的分布校正

说明为了保持目标采样分布，拒绝候选时需要按校正规则继续抽样。

### 6.5.4 接受率与期望收益

把候选长度、接受前缀和每轮开销联系起来，解释高接受率不等于实际加速倍数。

### 6.5.5 无依赖接受率 demo

用构造分布展示接受与拒绝流程，不替代 runtime 的性能测量。

### 6.5.6 Transformers assisted generation 的工程位置

核对目标版本中 assistant、prompt lookup 和 cache 等接口及其限制。

### 6.5.7 Draft 来源不止一种

比较独立小模型、prompt lookup、自 speculative 与模型内多 token 预测等提议来源。

### 6.5.8 失败模式：接受率高也不代表总收益高

分析 draft 开销、批处理、显存、长度分布和调度带来的净收益变化。

### 6.5.9 资料与证据边界

限定算法等价性、框架支持和目标硬件加速的证据来源。

## 6.6 长上下文压测：从“能接收”到“能完成任务”

本节将最大长度声明转成任务、内存、延迟和质量压测，并检查位置分布和长会话负载。

### 6.6.1 最大上下文长度能证明什么

区分模型/服务接受长度上限与在该长度下可靠完成任务。

### 6.6.2 长度如何影响注意力和 KV

说明序列长度对 attention 计算、KV cache 与延迟的影响和架构差异。

### 6.6.3 估算推理需要的总显存

合并权重、缓存、激活、临时 workspace 和并发的资源估算。

### 6.6.4 Needle-in-a-Haystack 只是起点

指出单 needle 合成任务的覆盖边界，并扩展到多事实、冲突和组合查询。

### 6.6.5 Lost-in-the-middle 与位置曲线

分析证据位置变化对检索/回忆成功率的影响及分布式测试要求。

### 6.6.6 无依赖的位置检索 demo

以小型控制实验演示按位置分桶的评估方式。

### 6.6.7 一个可复现的长上下文压测矩阵

固定长度、位置、并发、任务类别、重复轮次和版本形成压测矩阵。

### 6.6.8 定位显存溢出、超时和质量下降的原因

区分容量、队列、attention、截断和证据利用等故障来源。

### 6.6.9 长上下文压测伪代码

界定可复现实验循环、分桶记录和结果聚合字段。

### 6.6.10 “支持 1M”应如何写成有边界的结论

要求长度声明同时附模型版本、任务覆盖、资源、延迟和成功判定。

### 6.6.11 资料与证据边界

区分模型卡/文档长度、公开 benchmark 与本地业务请求压测。

## 6.7 把前述优化放进一份推理实验报告

本节把实验对象、质量指标、系统指标、决策规则和 Agent 多轮负载汇总成可复核的优化报告。

### 6.7.1 先写清楚实验对象

固定模型、runtime、硬件、提示、请求集和采样配置。

### 6.7.2 结果表应同时包含质量和系统指标

并列任务质量、尾延迟、吞吐、显存、错误率和成本。

### 6.7.3 最小的决策顺序

先验证质量底线与可靠性，再比较性能和成本收益。

### 6.7.4 多轮 Agent 负载：把真实会话形状放进压测

用轮次、工具调用、长短请求与等待模式还原 Agent 请求链负载。

### 6.7.5 把结果整理成可交付报告

要求结果含实验边界、样本、指标定义、失败样例和复现资产。
