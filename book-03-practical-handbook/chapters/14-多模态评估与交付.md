# 第 14 章 多模态评估与交付

前面各章分别建立了图文理解与检索、扩散数值实验和语音问答的小型链路。本章回答它们共同的交付问题：原始媒体经过哪些转换，哪些证据支撑结果，权限与版本是否一致，质量、成本和失败能否被复查？

多模态评估不能把输入变化隐藏在一个总分里。图像分辨率、音频采样率、时间戳、检索版本、权限范围和模型配置都可能改变任务结果。本章先建立按任务与切片评估的工具，再把它扩展为跨模态项目的可复核交付流程。

## 14.1 多模态模型评估小工具

### 14.1.1 统一 schema，分任务指标

多模态系统的输入形态不同，但评估记录可以统一为：

~~~math
e_i=(id_i,task_i,input_i,reference_i,metadata_i)
~~~

这里 $e_i$ 表示第 $i$ 条评估样本，字段依次是样本 ID、任务类型、输入、参考答案和元数据；元数据可记录媒体来源、预处理与模型配置。模型输出记为 $prediction_i$，它可以是正常结果，也可以是缺失输出；评估记录另存状态，如 ok、timeout、parse_error、missing_prediction 或 refused。把第 $j$ 个指标记为 $m_j$，它是根据参考答案和预测结果计算的函数，第 $i$ 条样本的分数记为 $m_j(i)$：

~~~math
m_j(i)=m_j(reference_i,prediction_i)
~~~

令 $N$ 为符合预先定义纳入条件的样本总数；总体平均只在 $N>0$ 时有定义：

~~~math
\bar{m}_j=\frac{1}{N}\sum_{i=1}^{N}m_j(i)
~~~

这是按样本先算指标再求平均的宏平均。对词错误率或字符错误率，若报告语料级微平均，应先汇总全部样本的编辑错误数，再除以全部参考词数或字符数；逐样本 CER 的平均是另一种口径，须在报告中标明。Accuracy 或规则通过率也应说明它是样本等权平均还是按任务分组后再平均。

端到端任务成功率应把未返回、超时和解析失败按预先声明的规则计为失败，并保留在 $N$ 中；拒答只有在任务明确定义“适当拒答”为成功时才通过。字符错误率等只对有效文本有定义的指标，应另报成功返回数和条件分母，不能把无答案静默删除后仍称作全请求平均。如果某项指标只适用于一个任务子集，应在 schema 中标记适用范围，并分别报告该子集的分母。

设 $E_c$ 是切片 $c$ 中适用的样本集合，$|E_c|$ 是集合大小；切片指标只在该集合内平均：

~~~math
\bar{m}_{j,c}=\frac{1}{|E_c|}\sum_{i\in E_c}m_j(i)
~~~

切片指标要求 $|E_c|>0$。没有该切片样本时结果是“不适用”，不应伪装成 0 分。

评估文件应记录模型、数据、processor、prompt、检索器和代码版本，否则新旧数字无法解释。

### 14.1.2 指标如何对应任务

~~~text
光学字符识别（optical character recognition, OCR）/字段抽取：Exact Match、字段准确率、字符错误率
分类与存在性：Accuracy、Precision、Recall、F1（Precision 与 Recall 的调和平均）
计数：绝对误差、精确计数率
图表：数值误差、相对关系正确率
开放描述：人工正确性（correctness）、证据支撑度（groundedness）、要点完整性（completeness）
自动语音识别（automatic speech recognition, ASR）：词错误率（word error rate, WER）/字符错误率（character error rate, CER）、关键实体准确率、时间戳结构
视频/音视频定位：时间区间重叠、事件顺序和模态证据支持
语音问答：ASR、检索、回答、引用和端到端通过率
安全：敏感信息泄露率、危险动作率、拒答适当性
~~~

这里的 VLM 指视觉语言模型（vision-language model）。F1 是 Precision 与 Recall 的调和平均；F1、Accuracy、Precision 和 Recall 都须结合任务定义及正负类分母解释。

Exact Match 对短字段有用，但对开放回答过于严格；关键词覆盖能粗筛信息点，但不能保证逻辑正确。大语言模型评审（large language model as a judge, LLM judge）是让大语言模型按 rubric 对回答打分；它需要人工标注样本（gold set）校准，不能把 judge 的一个分数当作事实真值。

如果任务要求定位视频中的一个事件，可用时间区间交并比（Intersection over Union, IoU）比较预测区间 $P$ 与人工标注区间 $G$：

~~~math
\mathrm{IoU}(P,G)=\frac{\mathrm{duration}(P\cap G)}{\mathrm{duration}(P\cup G)}
~~~

例如标注区间为 $G=[10,20]$ 秒，预测为 $P=[15,25]$ 秒，交集长 5 秒、并集长 15 秒，因此 IoU 为 $5/15=1/3$。平均交并比（mean IoU, mIoU）按评测协议对各查询的 IoU 求平均；Recall@IoU=0.3 则统计预测区间与标注区间的 IoU 至少为 0.3 的查询占比。音视频时间定位预印本 [RVG-Bench](https://arxiv.org/html/2610.32268v1) 报告这类指标；其样本、模型、输入采样和评分协议限定了结果，不能据此概括所有视频系统。更完整的多模态 benchmark 设计与限制见[第二册第十三章](../../book-02-advanced-100/chapters/13-多模态评估与开放研究.md)。IoU 只说明时间重叠，不证明事件描述正确，也不保证答案受到音频或视频证据支持。

失败样本（bad case）集合可以定义为：

~~~math
B=\{e_i:pass_i=0\}
~~~

其中 $pass_i$ 是预先定义的规则或人工验收门槛在样本 $i$ 上的结果；规则通过不自动等于任务真实正确。每个 bad case 还应有根因和修复状态：

~~~text
perception_error、ocr_error、asr_entity_error
retrieval_miss、evidence_conflict、generation_hallucination
format_error、privacy_risk、timeout
~~~

### 14.1.3 一个零依赖评估器

> 代码状态：静态审阅，未运行（2026-10-30）

样本列表保存任务与参考答案，预测字典按样本 ID 索引。缺少字典项或值为 None 时记作 missing_prediction；预测也可携带 timeout、parse_error、missing_prediction 或 refused 状态。拒答是否成功由样本字段 refusal_is_success 明确指定。代码在 rows 中为每条样本保存规则分数与状态，并把所有纳入样本都保留在任务通过率分母中。

~~~python
import re
from collections import defaultdict


def normalize(text):
    if not isinstance(text, str):
        raise TypeError("text must be a string")
    return re.sub(r"\s+", "", text.lower()).replace("，", ",")


def edit_distance(left, right):
    table = [[0] * (len(right) + 1) for _ in range(len(left) + 1)]
    for i in range(len(left) + 1):
        table[i][0] = i
    for j in range(len(right) + 1):
        table[0][j] = j
    for i in range(1, len(left) + 1):
        for j in range(1, len(right) + 1):
            cost = int(left[i - 1] != right[j - 1])
            table[i][j] = min(table[i - 1][j] + 1,
                              table[i][j - 1] + 1,
                              table[i - 1][j - 1] + cost)
    return table[-1][-1]


def cer(reference, prediction):
    if not isinstance(reference, str) or not isinstance(prediction, str):
        raise TypeError("reference and prediction must be strings")
    reference = [char for char in reference if not char.isspace()]
    prediction = [char for char in prediction if not char.isspace()]
    if not reference:
        raise ValueError("reference must be non-empty for CER")
    return edit_distance(reference, prediction) / len(reference)


def keyword_recall(answer, keywords):
    if not isinstance(answer, str):
        raise TypeError("answer must be a string")
    if (not isinstance(keywords, (list, tuple)) or not keywords
            or any(not isinstance(word, str) or not word.strip() for word in keywords)):
        raise ValueError("keywords must be non-empty strings")
    answer = normalize(answer)
    return sum(normalize(word) in answer for word in keywords) / len(keywords)


def prediction_text(prediction, field):
    value = prediction.get(field)
    return value if isinstance(value, str) else None


def evaluate(sample, prediction):
    if not isinstance(sample, dict):
        raise TypeError("sample must be a dictionary")
    if not isinstance(sample.get("task"), str) or "reference" not in sample:
        raise ValueError("sample needs task and reference")
    if prediction is None:
        return {"status": "missing_prediction", "rule_pass": False}
    if not isinstance(prediction, dict):
        raise TypeError("prediction must be a dictionary or None")
    status = prediction.get("status", "ok")
    if not isinstance(status, str):
        raise ValueError("prediction status must be a string")
    if status in {"timeout", "parse_error", "missing_prediction", "error"}:
        return {"status": status, "rule_pass": False}
    if status == "refused":
        refusal_is_success = sample.get("refusal_is_success", False)
        if not isinstance(refusal_is_success, bool):
            raise ValueError("refusal_is_success must be boolean")
        return {"status": status, "rule_pass": refusal_is_success}
    if status != "ok":
        raise ValueError(f"unknown prediction status: {status}")

    task = sample["task"]
    reference = sample["reference"]
    if task == "asr":
        transcript = prediction_text(prediction, "transcript")
        if transcript is None:
            return {"status": "parse_error", "rule_pass": False}
        score = cer(reference["transcript"], transcript)
        return {"status": "ok", "cer": round(score, 4),
                "rule_pass": score <= 0.2}
    if task == "image_qa":
        answer = prediction_text(prediction, "answer")
        if answer is None:
            return {"status": "parse_error", "rule_pass": False}
        score = keyword_recall(answer, reference["keywords"])
        return {"status": "ok", "keyword_recall": round(score, 4),
                "rule_pass": score == 1.0}
    if task == "voice_qa":
        transcript = prediction_text(prediction, "transcript")
        answer = prediction_text(prediction, "answer")
        if transcript is None or answer is None:
            return {"status": "parse_error", "rule_pass": False}
        asr_score = cer(reference["transcript"], transcript)
        answer_score = keyword_recall(answer, reference["keywords"])
        forbidden = any(normalize(word) in normalize(answer)
                        for word in reference["forbidden"])
        passed = asr_score <= 0.2 and answer_score >= 0.8 and not forbidden
        return {"status": "ok", "asr_cer": round(asr_score, 4),
                "keyword_recall": round(answer_score, 4),
                "forbidden_hit": forbidden, "rule_pass": passed}
    raise ValueError(f"unknown task: {task}")


samples = [
    {"id": "image_1", "task": "image_qa",
     "reference": {"keywords": ["128", "元"]}},
    {"id": "asr_1", "task": "asr",
     "reference": {"transcript": "我不是会员可以保价"}},
    {"id": "voice_1", "task": "voice_qa",
     "reference": {"transcript": "耳机有杂音可以退货吗",
                    "keywords": ["质量问题", "售后检测"],
                    "forbidden": ["一定退款"]}},
]
predictions = {
    "image_1": {"answer": "总金额是 128 元。"},
    "asr_1": {"transcript": "我是会员可以报价"},
    "voice_1": {"transcript": "耳机有杂音可以退货吗",
                 "answer": "可以提交质量问题检测，售后检测后处理。"},
}

rows = []
bad = []
by_task = defaultdict(list)
for sample in samples:
    metrics = evaluate(sample, predictions.get(sample["id"]))
    row = {"id": sample["id"], "task": sample["task"], "metrics": metrics}
    rows.append(row)
    by_task[sample["task"]].append(metrics["rule_pass"])
    if not metrics["rule_pass"]:
        bad.append(row["id"])

summary = {task: round(sum(values) / len(values), 4)
           for task, values in sorted(by_task.items())}
assert summary == {"asr": 0.0, "image_qa": 1.0, "voice_qa": 1.0}
assert bad == ["asr_1"]
print("summary=", summary)
print("bad_cases=", bad)
~~~
按例中输入手算，ASR 参考有 9 个汉字；预测删除“不”并把“保”替换成“报”，编辑距离为 2，因此 CER 为 $2/9\approx0.2222$，超过教学阈值 0.2。完整输入的预期输出为：

~~~text
summary= {'asr': 0.0, 'image_qa': 1.0, 'voice_qa': 1.0}
bad_cases= ['asr_1']
~~~

这里汇总的是 `rule_pass`，不能称为真实任务正确率：回答“不是 128 元”仍包含两个关键词，会被 image_qa 规则放过；较长转写只漏一个关键否定词也可能满足 CER≤0.2。`forbidden` 子串规则还可能把“不能保证一定退款”判为禁句命中。规则既可能误放也可能误拒，需要用结构化字段、证据标签和人工 gold 分别测误差。

评估器中的阈值是教学构造，不能直接当作上线标准。没有预测、超时与解析失败应保留在任务分母并记录失败状态，不能只统计成功返回的样本。生产系统还应使用版本化测试集、置信区间、人工抽检、风险加权和旧版本对照，并保留完整预测文件。

### 14.1.4 自动指标与人工评估的组合

开放式回答至少需要从以下维度打分：

~~~text
correctness（事实正确性）：回答是否与事实相符
groundedness（证据支撑度）：是否得到输入或检索证据支持
completeness（要点完整性）：是否覆盖必要信息
conciseness（简洁性）：是否包含大量无关内容
safety（安全性）：是否越过隐私和风险边界
format（格式合规性）：是否遵守结构化输出契约
~~~

人工评估要有标注指南、正反例和一致性检查。LLM judge 可以降低成本，但需要人工 gold set 检查位置偏差、长度偏差、风格偏差和模型自偏好。公开 benchmark 的分数只能作为外部参照，业务数据上的人工评估仍不可省略。

### 14.1.5 版本回归与 loss cases

模型版本比较不能只看平均分。对同一测试集，应把样本分为：

~~~text
both_right：旧版和新版都正确
win：旧版错误、新版正确，表示新版修复了该样本
loss：旧版正确、新版错误，表示新版在该样本上回退
both_wrong：旧版和新版都错误
~~~

这些是逐样本配对结果，不是模型版本的总体判决。高风险任务中的 loss case 即使数量少，也可能比普通描述任务的许多 win case 更重要。评估报告至少写出数据版本、模型 revision、prompt、工具链、总体指标、切片指标、主要 bad case、延迟和下一步行动。

下面的流程把一次模型升级拆成可复核的评估步骤。关键是先固定样本和指标，再比较旧版与新版；如果看到退化，追踪原始失败样本，而不是从汇总分数猜原因。

```mermaid
flowchart LR
    A["固定测试集与任务定义"] --> B["并行运行旧版和新版"]
    B --> C["按模态与风险切片"]
    C --> D["检查错误分母与缺失输出"]
    D --> E["人工复核关键 bad case"]
    E --> F["决定发布、回退或补数据"]
```

#### 跟着算一次：规则通过率不等于任务正确率

假设一次回归有 100 个请求：70 个图片问答、30 个语音问答。规则检查通过的分别是 64 和 24，因此图片切片通过率是 64/70≈91.43%，语音切片是 24/30=80%，合并后的 rule_pass 为 88/100=88%。这个数只表示样本满足了当前自动规则，不代表人工 gold 下有 88 个正确回答。比如语音回答漏掉“不要”却命中订单号和商品名，浅规则仍可能通过。

再假设人工抽检发现 8 个任务错误，其中 5 个涉及订单取消或金额，3 个是普通图片描述。总体错误率是 8%，高风险错误占所有错误的 5/8=62.5%；仅看总分无法看见这种集中风险。评估报告应同时保留两个分母：全部请求用于总体任务成功率，高风险子集用于该类风险率。若 20 个高风险样本中有 5 个失败，风险切片失败率就是 25%，而不是 5/100。没有高风险样本时应报告“不适用”，不能报告零风险。

置信区间、人工一致率和 judge 与 gold 的混淆矩阵有助于说明估计的不确定性。若结果用于发布决策，还需先固定可接受的回归范围和风险权重，并确保测试数据未被用于挑选阈值。分数的标签、覆盖范围和分母都应与预测文件一起保存；只有一个“模型得分”字段无法支撑复查。

#### 相同比例不代表相同把握

比较两个切片：第一组 5 个样本中通过 4 个，表面通过率是 80%；第二组 50 个样本通过 40 个，也是 80%。点估计相同，证据强度却不同。第一组只错 1 个样本就会变成 60% 或 100%，第二组同样一条样本只改变 2 个百分点。报告比例时必须同时给出分子和分母，重要指标还应给置信区间或重复抽样范围。

若同一用户、同一图片或同一录音派生出多个相关问题，把这些行当成完全独立样本会让置信区间显得过窄。组自助重采样（group bootstrap）先按用户、图片或原始媒体等独立组抽样，再带上该组的全部问题；这样保留组内相关性。固定测试集上的区间只反映有限样本的不确定性，不代表换了模型、业务人群或输入设备后的不确定性。

多模态系统还需要把未返回、超时、解析失败和拒答单独记为状态。若从 100 条请求中只对 88 条成功返回的答案计算准确率，另 12 条就从分母消失；当超时集中在长视频或大图上时，剩余样本的平均分会偏高。以全部有效请求作为任务分母报告完成率，同时对已完成任务报告条件准确率，才能区分服务可用性和回答质量。

再用版本对比说明为什么要保留逐样本结果。假设 100 条测试中，旧版和新版都正确 82 条；另有 8 条从旧错变新对，即 win，10 条从旧对变新错，即 loss。新版总体正确数是 90、旧版是 92，净变化为 -2 个百分点。若 10 个 loss 中有 4 个是金额或订单操作，而 8 个 win 都是普通图片描述，单一总体准确率仍低估了风险变化。

可以先列出如下账本，再逐条检查差异：

| 配对结果 | 样本数 | 业务复核重点 |
| --- | ---: | --- |
| both_right | 82 | 是否有共同的脆弱输入条件 |
| win | 8 | 新版收益是否集中于某类任务 |
| loss | 10 | 是否触及高风险字段或权限边界 |
| both_wrong | 0 | 是否存在应优先修复的共同盲点 |

这张表只说明配对结果数量，不判断错误严重性。下一步要检查模型版本变化是否同时改变 processor、prompt、检索索引或工具 schema；若一次改了多项，不能把全部差异归因于权重。保留原始输出、请求配置、任务标签和人工裁决（adjudication，即对标注分歧作出的最终判断）后，才能按“机制假设—反事实切片—定向修复”推进。

评估集还要防止“看过答案再改规则”。如果人工抽检发现 5 个错误，其中 3 个都是规则没识别的否定句，修正规则后必须在未参与开发的留出集上重新测量；否则新结果只说明规则适配了这 5 个样本。修规则前后都保存 evaluator revision，并用相同预测文件回放，确认变化来自评分器而不是模型输出。

模型判断器也应有自己的校准账本：选一批人工标注样本，分别统计 judge 的真阳性、假阳性、真阴性和假阴性，再按模态、回答长度与风险等级切片。若 judge 在长回答中更容易给高分，整体相关系数可能仍不错，却不能用于安全关键任务。人工 gold、judge 版本和最终 adjudication 结果要分开存储。

评估过程最终要能回答三个问题：被测对象是否相同，错误的定义是否相同，分母是否保留了失败请求。少任何一个，模型版本之间的数字就无法作可靠比较。把答案、证据、指标和版本一起保存，才可以在未来改变 rubric 时重新计算而不必重跑模型。

### 14.1.6 资料与证据边界

评估平台可参考 [HELM](https://crfm.stanford.edu/helm/latest/)、[Hugging Face Evaluate](https://huggingface.co/docs/evaluate/index) 和 [VHELM](https://arxiv.org/abs/2410.07112v2)。VHELM 将视觉感知、知识、推理、偏差、公平性、多语言、鲁棒性、毒性和安全纳入多维评估，并统一部分推理参数、提示和指标；它提供组织评估的参考，不会替业务定义正确性、风险阈值和标注标准。

## 14.2 从实验到可复核系统

### 14.2.1 多模态项目的事实结构

一个完整项目不应只留下“调用了哪个模型”的描述，而应留下可以被另一位工程师复跑和质疑的事实链：背景、目标、输入、输出、模块、数据、指标、失败、负责边界和未覆盖范围。

可以把项目记录抽象成：

~~~math
P=(B,G,I,O,D,M,E,R,C,L)
~~~

其中 B 是背景，G 是目标，I 是输入，O 是输出，D 是数据，M 是模块及其版本，E 是评估结果，R 是风险与失败，C 是个人或团队贡献，L 是适用限制。

任何效果结论都应带条件：

~~~math
claim=(statement,model,data,metric,baseline,condition,uncertainty)
~~~

这里 statement 是待检验的结论，model 是模型与 revision，data 是评估数据及切分，metric 是指标和分母，baseline 是对照版本或方法，condition 是预处理、提示和解码等条件，uncertainty 是样本量、区间或其他不确定性。“OCR 变好了”至少要写成“在某版本视觉语言模型、某种图片预处理、某个字段评估集和相同解码参数下，字段准确率从多少变为多少”。否则它只是印象，不是实验结论。

### 14.2.2 统一系统架构

一个同时处理图片和语音的业务助手可按逻辑层拆开，图中的层不要求部署成独立服务。语音活动检测（voice activity detection, VAD）用于识别音频中的语音片段，是感知层可选的一种组件：

```mermaid
flowchart LR
  U["媒体输入与身份、租户"] --> I["接入：鉴权、解码、规范化"]
  I --> P["感知：VLM、OCR、ASR、VAD"]
  P --> E["结构化证据：字段、片段、时间戳"]
  E --> R{"需要外部证据？"}
  R -->|需要| K["权限过滤检索：用户权限、索引版本"]
  R -->|不需要| G["证据融合与生成"]
  K --> G
  G --> S{"安全门与动作门"}
  S -->|普通回答| A["返回答案"]
  S -->|确认通过| X["执行受控动作"]
  S -->|拒答或升级| H["拒答或人工接管"]
  I -.-> T["脱敏、版本化 trace"]
  P -.-> T
  E -.-> T
  K -.-> T
  G -.-> T
  S -.-> T
  T --> V["离线评估与人工复核"]
  V --> D["发布或回滚"]
  D -.->|切换服务版本| I
```

VLM 是视觉语言模型，OCR 是光学字符识别，ASR 是自动语音识别。Whisper 是本系列前文介绍的一种 ASR 模型。embedding（嵌入表示）是把文本或媒体编码成便于检索或后续计算的向量/序列表示，具体结构依模型而异；OCR 字段、ASR 片段和 embedding 都只是候选证据，仍需记录来源、时间戳和版本。ACL 指访问控制列表（access control list）；检索只有在权限过滤后才能把证据交给生成层，直接回答的任务则可以跳过检索。

系统图不应把“模型”画成不可解释的黑盒。各层的输入、输出和中间证据要有协议，服务还要分别测量关键阶段的延迟和失败率。trace 应保存脱敏摘要、版本与受控证据 ID，不默认保存原始媒体、完整提示或敏感工具参数。

### 14.2.3 容量、成本与上下文

先统一负载账本的单位：$QPS_{\mathrm{peak}}$ 是峰值请求到达率，单位为请求/秒；$A$ 是每请求平均音频时长，单位为秒/请求；$V$、$T_{\mathrm{in}}$、$T_{\mathrm{out}}$ 分别是每请求平均视觉 token、文本输入 token、文本输出 token 数。token 数按被测模型的 tokenizer 或视觉 token 计量口径确定；不含某种模态的请求在该项记 0，或按请求类型单独统计。定义 $TPS_{\mathrm{demand}}$ 为粗略 token 工作量需求率：

~~~math
TPS_{\mathrm{demand}}\approx QPS_{\mathrm{peak}}(V+T_{\mathrm{in}}+T_{\mathrm{out}})
~~~

这只是负载需求账本，不是实测服务 TPS，也不表示所有 token 消耗相同资源：输入 prefill 与输出 decode 的单 token 成本不同，图像解码和视觉编码的成本还未计入。应至少分开报告 $QPS_{\mathrm{peak}}(V+T_{\mathrm{in}})$ 与 $QPS_{\mathrm{peak}}T_{\mathrm{out}}$。音频用时长而非 token 计入该近似，因此另算 $QPS_{\mathrm{peak}}A$，单位为音频秒/墙钟秒；实时因子 RTF 是处理音频所用墙钟时间与音频时长之比，仍须结合并发、模型和硬件测量容量。请求类型混合时，均值要包含不使用该模态请求的零值，或先按类型拆分流量。

例如每秒 2 个请求、每请求平均 512 个视觉 token、256 个文本输入 token 和 128 个输出 token，对应输入到达率 1536 token/s、输出需求 256 token/s，不能据此判断硬件已能承载。语音服务还要把 `QPS_peak×A` 音频秒/秒与实时因子纳入 ASR 吞吐；图片服务要计入分辨率、视觉编码和多图请求；检索服务要计入 OCR、embedding 和 rerank 的资源。

令 $L_{\mathrm{e2e}}$ 表示请求被服务接受到完整回答返回的端到端延迟；下面每个 $L$ 项的单位都是秒，分别表示排队、媒体解码、感知、检索、LLM prefill、LLM 输出 token 解码和后处理时长：

~~~math
L_{\mathrm{e2e}}=L_{\mathrm{queue}}+L_{\mathrm{media\_decode}}+L_{\mathrm{perception}}
+L_{\mathrm{retrieval}}+L_{\mathrm{prefill}}+L_{\mathrm{llm\_decode}}+L_{\mathrm{post}}
~~~

该和式只近似表示串行关键路径；若感知、检索或安全检查并行执行，应按实际依赖图计算关键路径，不能把并行阶段时长一律相加；跳过检索时 $L_{\mathrm{retrieval}}=0$。首 token 延迟（time to first token）也应与完整回答延迟分开报告。媒体解码是图片/音频预处理，不是 LLM 生成 token 的 decode。

单位成功任务成本把同一窗口内全部任务成本除以成功任务数，比单次请求成本更能反映交付效率。令 $C_{\mathrm{task}}$ 为每个纳入任务的平均总成本（含失败和重试），令 $P_{\mathrm{task\ success}}$ 为按预先定义标准成功的任务比例，则：

~~~math
C_{\mathrm{success}}=\frac{C_{\mathrm{task}}}{P_{\mathrm{task\ success}}}
~~~

单位成功任务成本要求成功概率满足 $P_{\mathrm{task\ success}}>0$，且成本、成功任务数和任务身份来自同一时间窗口。若成功概率为零，单位成功成本没有有限值，应先报告“没有成功任务”并定位失败原因。

这里 $C_{\mathrm{task}}$ 取该窗口总成本除以纳入的用户任务数，成功率也按同一批任务计算，因此该比率等于总成本除以成功任务数。若账单按请求记录，须先将同一用户任务的重试费用归并，再与任务成功数相除。例如 100 个任务总成本 20 元、成功 80 个，单位成功成本为 $20/80=0.25$ 元/成功任务。

如果更大的 VLM 让单次回答质量上升，但延迟、重试和人工转接也上升，单位成功任务成本未必下降。多模态方案要在同一任务分布、同一图片/音频质量和同一成功定义下比较。

### 14.2.4 状态、权限和失败恢复

图片问答通常是无状态请求，语音客服和多轮 VLM 则会积累会话状态。状态至少包括：

~~~text
原始输入引用和脱敏版本
ASR segments 或图片版本
用户确认状态
检索证据 ID 与版本
生成结果与引用
工具调用、重试和人工接管
~~~

权限过滤必须在检索前后都存在：租户、用户、文档版本和图片来源应进入缓存键；模型不能替代 ACL。高风险动作需要结构化参数、幂等键、二次确认和审计，不能因为 VLM 或 LLM 的回答听起来合理就直接执行。

失败恢复要区分：

~~~text
输入不可读：要求重新上传或转码
感知低置信度：请求用户确认或人工处理
检索无证据：明确说明信息不足
证据冲突：列出冲突并暂停确定性结论
生成超时：返回可解释的部分结果或重试
模型升级回归：停止扩大流量并恢复兼容版本
~~~

### 14.2.5 一个项目记录审计器

> 代码状态：静态审阅，未运行（2026-10-30）

~~~python
import math


def relative_change(base, new, higher_is_better=True):
    if (isinstance(base, bool) or not isinstance(base, (int, float))
            or not math.isfinite(base)
            or isinstance(new, bool) or not isinstance(new, (int, float))
            or not math.isfinite(new)):
        raise ValueError("metric values must be finite numbers")
    if not isinstance(higher_is_better, bool):
        raise TypeError("higher_is_better must be boolean")
    if base == 0:
        raise ValueError("zero baseline needs an absolute comparison")
    delta = new - base if higher_is_better else base - new
    return round(delta / abs(base), 4)


project = {
    "background": "业务输入包含图片、截图和语音。",
    "goal": "提高证据约束回答的可用率并定位链路错误。",
    "data": "按图片和音频来源切分的评估集 v3。",
    "modules": ["vlm", "whisper", "retrieval", "evaluation"],
    "metrics": {
        "voiceqa_pass": {"base": 0.61, "new": 0.76, "higher": True},
        "asr_cer": {"base": 0.18, "new": 0.11, "higher": False},
    },
    "bad_cases": [
        {"root": "asr_negation", "fix": "user_confirmation"},
        {"root": "ocr_small_text", "fix": "crop_and_validate"},
    ],
    "boundary": "没有实时双工语音和生产流量数据。",
}

if not isinstance(project["metrics"], dict) or not project["metrics"]:
    raise ValueError("project metrics must be non-empty")
if not isinstance(project["bad_cases"], list) or not project["bad_cases"]:
    raise ValueError("project bad_cases must be non-empty")

required = ["background", "goal", "data", "modules", "metrics",
            "bad_cases", "boundary"]
missing = [field for field in required if not project.get(field)]
changes = {
    name: relative_change(spec["base"], spec["new"], spec["higher"])
    for name, spec in project["metrics"].items()
}
bad_case_ready = all(case.get("root") and case.get("fix")
                     for case in project["bad_cases"])

assert missing == []
assert changes == {"voiceqa_pass": 0.2459, "asr_cer": 0.3889}
assert bad_case_ready
print("missing=", missing)
print("relative_changes=", changes)
print("bad_case_ready=", bad_case_ready)
~~~
按输入手算，voiceqa_pass 的相对变化是 $(0.76-0.61)/0.61\approx0.2459$；asr_cer 是低值更好，因此相对下降为 $(0.18-0.11)/0.18\approx0.3889$。预期输出为：

~~~text
missing= []
relative_changes= {'voiceqa_pass': 0.2459, 'asr_cer': 0.3889}
bad_case_ready= True
~~~

输入中的数据版本和指标全是合成设定，`voiceqa_pass` 从 0.61 到 0.76 是增加 15 个百分点、相对增加约 24.59%，CER 相对降低约 38.89%。`bad_case_ready` 只表示填了候选根因和修复文字，不表示根因成立或修复通过。审计器检查记录字段和变化方向，不能替代真实评估与证据核验。

### 14.2.6 从实验到发布

发布前至少需要完成以下闭环：

~~~text
固定模型、processor、prompt、检索器和工具版本
冻结 dev/test 切分，避免反复调参污染 test
跑总体、分任务、分风险、分输入质量指标
审查 win/loss cases 和高风险 bad cases
检查权限、隐私、引用和确认状态
测量 p50/p95、吞吐、显存、存储和单位成功成本
小流量观察失败率、人工转接和用户反馈
准备可回放日志与兼容回退组合
~~~

回退不能只换模型权重，还要恢复与之兼容的 tokenizer/processor、prompt、索引、工具 schema、安全策略和评估版本。多模态系统的输入协议比纯文本更容易发生隐式变化，图片占位符、音频采样率和时间戳格式都应进入版本记录。

### 14.2.7 把多模态知识放回同一张图

CLIP 解决跨模态表示对齐；VLM 解决视觉条件生成；多模态 SFT 解决指令和行为分布；RAG 解决外部证据与知识更新；Diffusion 解决从噪声到图像的生成路径；Whisper 解决音频到文字的感知入口；语音问答把感知错误传播问题暴露出来；评估工具和发布系统则决定这些能力能否被复核、比较和安全使用。

这些模块不能被一个“多模态模型”名词替代。一个模型 benchmark 很高，不代表它的图片预处理、OCR、证据引用、权限、延迟和回滚已经可靠；一个 toy demo 能运行，也不代表目标业务上的模型能力已经得到证明。

真正可迁移的判断方式是：先写出模态和证据的契约，再用最小实验验证局部机制；随后在真实切片上测量质量、成本和失败；最后把模型放进有版本、有日志、有权限、有人工作业和可回放的系统中。这样读者得到的不是一组热点名词，而是一套能够继续扩展到视频、文档、实时语音和多模态 Agent 的工程方法。

#### 跟着算一次：版本回滚要恢复一整组接口

设发布版本 R17 使用模型 revision m17、processor p4、prompt p9、图片索引 i12、语音采样率协议 a2、工具 schema t6 和安全策略 s8。上线后发现新版对金额 OCR 的字段准确率从 96/100 降到 88/100。只把模型权重切回 R16 并不一定能恢复旧行为：若 R17 的 processor 已把图片缩放方式改掉，或新 prompt 与旧模型不兼容，回滚后的服务仍不是 R16。可回滚对象应是完整版本元组 (R16,m16,p3,p8,i11,a1,t5,s7)，并与当时通过的评估集和配置绑定。

再看成本。一个评估窗口处理 100 个用户任务，总费用为 20 元，其中 80 个满足预先定义的成功条件，单位成功任务成本是 20/80=0.25 元。若新版单请求成本降到 0.16 元，却只有 50 个成功任务，总支出约为 16 元，单位成功成本变为 16/50=0.32 元。只比较每请求成本会得出“新版更省”的结论；按成功交付衡量则成本反而上升。这个算例假设费用和成功数对应同一批任务，重试费用已计入总额。

发布记录还要指明谁拥有索引、模板、策略和回滚操作，避免出现模型团队能回权重、但无人能恢复关联数据协议的情况。演练时可以抽取一条真实失败 trace，确认版本元组、访问权限、用户确认状态和可重放输入都完整；若依赖外部模型 API，不可重放原始内部状态时，应记录哪些字段只能做脱敏复现。回滚本身也要跑一组冒烟评估，确认恢复的是旧行为，而不只是服务重新启动。

### 14.2.8 资料与证据边界

系统风险治理可参考 [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)；NIST 将 AI RMF 定义为自愿采用的风险管理框架，并说明 1.0 版本正在修订，引用时要核对适用版本。可观测性字段可参考 [OpenTelemetry GenAI semantic conventions](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)，但相关约定仍在演进；输入、输出、指令和工具参数可能含敏感内容，trace 的脱敏、访问控制和保存期限仍由具体系统负责。语义约定不能替代授权或隐私控制。模型服务与成本设计还要结合目标 runtime、硬件和业务 SLA。公开论文、官方文档、教学 demo、离线评估和线上实测属于不同证据层级，不能用其中一层替代另一层。

## 练习与迁移

1. 修改同图同问题的答案，观察构造器拒绝冲突；再用两个路径指向同一图片，设计按内容或来源分组的切分方案。
2. 给图片关联一份未授权文本，检查关联扩展仍被拒绝；无权限或无相关候选时，应记录证据不足而非生成确定结论。
3. 对比扩散第一步与第五步的累计 alpha 和后验方差，解释已知 x0 的噪声反解与生成用噪声预测器的区别。
4. 构造低 CER 但关键否定错误、关键词命中但金额否定的回答，将规则输出和真实 gold 判断分开报告。
