# 第 7 章（第三部分）：评估、失败定位与报告

同一条错误答案，可能是文档解析丢了条件、检索没找到证据、排序把证据挤出上下文、模型误解了原文，或引用编号指向了错误来源。若评估只给最终答案一个分数，我们就不知道该改哪一层。评估集因此要同时保存问题、文档版本、人工标注的标准证据（gold evidence）、参考答案和允许拒答的条件。

评估时把质量分数和系统风险分开看：

| 检查层 | 要回答的问题 |
| --- | --- |
| 检索 | 必需证据是否进入候选，排名是否足够靠前？ |
| 生成 | 答案是否正确、完整、忠于提供的材料，格式是否可处理？ |
| 证据 | 每项主张有没有支持，引用是否属于本次有效来源？ |
| 系统 | 延迟、token、显存、错误率和单位成功成本是多少？ |
| 风险 | 是否越权、泄露敏感内容、错误拒答或在证据不足时仍断言？ |

这些层次可以指向不同的修复动作。比如检索 Recall@k 足够而答案忠实性低，问题更可能在上下文构造或生成；引用编号合法而 claim 支持率低，则不能靠增加检索候选数来掩盖。

### 7.5.2 Hit@k、Recall@k 和 MRR

设第 $i$ 个问题的 gold chunk 集合为 $G_{i}$，检索 top-k 集合为 $P_{i}(k)$。top-k 指按分数排在前 $k$ 位的候选；命中率（Hit@k）表示这部分候选里至少有一个标准证据：

```math
\mathrm{Hit@k}_{i}
=
\mathbb{1}\left[P_{i}(k)\cap G_{i}\ne\varnothing\right]
```

平均命中率：

```math
\mathrm{Hit@k}
=
\frac{1}{N}
\sum_{i=1}^{N}\mathrm{Hit@k}_{i}
```

如果一个问题需要多个证据片段，Recall@k 更有信息：

```math
\mathrm{Recall@k}_{i}
=
\frac{|P_{i}(k)\cap G_{i}|}{|G_{i}|}
```

第一个 gold 片段的排名为 $r_{i}$ 时，倒数排名：

```math
\mathrm{RR}_{i}
=
\begin{cases}
1/r_{i},&r_{i}>0\\
0,&r_{i}=0
\end{cases}
```

平均倒数排名：

```math
\mathrm{MRR}
=
\frac{1}{N}\sum_{i}\mathrm{RR}_{i}
```

MRR 是平均倒数排名（Mean Reciprocal Rank）：gold 第 1 名贡献 1，第 2 名贡献 $1/2$，第 4 名贡献 $1/4$；先算每题第一个 gold 的倒数名次，再对题目取平均。它看“第一个可用证据排得多靠前”，不能替代多证据题的 Recall@k。

这些平均指标要求评估样本数 $N>0$。Recall@k 和 reciprocal rank 还要求该样本有非空 gold 集合；对于本来就不可回答的问题，应记录为 not applicable 或单独统计拒答，而不是把空 gold 当成一次召回失败。

对应的无依赖实现：

> 代码状态：静态审阅，未运行（2026-10-30）

```python
def hit_at_k(rows, gold_ids, k):
    if type(k) is not int or k <= 0:
        raise ValueError("k must be a positive integer")
    gold = set(gold_ids)
    if not gold:
        return None
    returned = {row["chunk_id"] for row in rows[:k]}
    return int(bool(returned & gold))


def recall_at_k(rows, gold_ids, k):
    if type(k) is not int or k <= 0:
        raise ValueError("k must be a positive integer")
    gold = set(gold_ids)
    if not gold:
        return None
    returned = {row["chunk_id"] for row in rows[:k]}
    return len(returned & gold) / len(gold)


def reciprocal_rank(rows, gold_ids):
    gold = set(gold_ids)
    if not gold:
        return None
    for rank, row in enumerate(rows, start=1):
        if row["chunk_id"] in gold:
            return 1.0 / rank
    return 0.0


rows = [
    {"chunk_id": "noise"},
    {"chunk_id": "gold_a"},
    {"chunk_id": "gold_b"},
]
print("hit_at_1=", hit_at_k(rows, ["gold_a", "gold_b"], 1))
print("hit_at_2=", hit_at_k(rows, ["gold_a", "gold_b"], 2))
print("recall_at_3=", recall_at_k(rows, ["gold_a", "gold_b"], 3))
print("rr=", reciprocal_rank(rows, ["gold_a", "gold_b"]))
```
这三条候选的标准证据是 gold_a 和 gold_b。top-1 只有 noise，所以 Hit@1 为 0；top-2 已包含 gold_a，因此 Hit@2 为 1、Recall@2 为 $1/2$；top-3 包含两个 gold，Recall@3 为 1。第一个 gold 排在第 2 位，倒数排名是 $1/2$。这些数只说明检索列表覆盖和排序，不说明生成器一定会使用证据；MRR 上升也不保证端到端答案一定上升。

### 7.5.3 答案正确性、忠实性和完整性

答案正确性回答“结论是否符合参考答案或任务真值”；忠实性回答“结论是否被给定证据支持”；完整性回答“是否遗漏了问题要求的条件、例外和范围”。

可以定义一个简单的人工评分表：

```text
0：错误、无关或完全无依据。
1：包含少量相关内容，但核心结论错误或缺少证据。
2：基本正确，但遗漏重要条件、范围或引用。
3：正确、完整、与证据一致，引用粒度合适。
```

自动关键词分数：

```math
S_{\mathrm{kw},i}
=
\frac{1}{|K_{i}|}
\sum_{w\in K_{i}}\mathbb{1}[w\in a_{i}]
```

这个指标要求关键词集合 $K_{i}$ 非空；没有预先定义关键词时应记为 not applicable，不能用一个人为的分母把“没有评估”变成满分或零分。

只能发现明显缺词，无法处理否定、单位、数字关系和事实冲突。LLM judge 可以辅助批量筛选，但需要 rubric、参考证据、校准样本和人工抽查；模型自评不能被当作独立真值。

### 7.5.4 引用与支持率

引用存在率：

```math
R_{\mathrm{presence}}
=
\frac{\#\{\text{非拒答答案中至少有一个引用}\}}
{\#\{\text{非拒答答案}\}}
```

引用合法率：

```math
R_{\mathrm{valid}}
=
\frac{\#\{\text{所有引用编号均属于候选集合}\}}
{\#\{\text{被评估答案}\}}
```

claim 支持率则需要先拆 claim：

```math
R_{\mathrm{support}}
=
\frac{\#\{\text{被证据支持的 claims}\}}
{\#\{\text{被检查的 claims}\}}
```

存在率、合法率和支持率的分母都必须是正数；拒答答案是否进入分母要在评估协议中预先固定。没有被检查的 claim 时，支持率是未定义，不是 $0$。

分母必须写清楚。把“没有 claim 的拒答”混入支持率，会让数字看起来更好；把无法判断的 claim 强行记成支持或不支持，也会造成偏差。

### 7.5.5 选择性回答和拒答

对允许拒答的问题，记录：

```text
answer accuracy（回答准确率）：回答的问题中有多少正确；
coverage（回答覆盖率）：系统回答了多少问题；
abstention precision（拒答精确率）：拒答中有多少确实缺少证据；
unsafe answer rate（无证据仍断言率）：证据不足时仍给出高置信断言的比例；
false refusal rate（错误拒答率）：有充分证据却拒答的比例。
```

这几项需要一起看。一个系统可以通过全部回答“资料中没有提到”获得很低的错误率，但 coverage 为零，没有业务价值。



指标给出差异后，还要找到第一处失败并计算改动的实际代价；接下来把这些内容整理成一份可复查报告。

上一部分定义了检索、回答、引用和拒答的指标。现在用这些指标查问题：先找每道题最早出错的环节，再用同一批样本比较不同版本，并把质量、成本、权限风险和人工复核写进报告。这样读者才能看清结论适用于哪些文档、问题和版本。

## 7.6 从失败样本到可复查的实验报告

### 7.6.1 按最早出错环节分类

每个失败样本尽量标记第一处分歧：

```text
解析失败：
  文档、表格、版本或元数据丢失。

检索漏召回：
  gold 不在初始 top-k。

排序失败：
  gold 被召回但排得太后，最终上下文没有它。

上下文失败：
  gold 在 prompt 中，但被截断、重复或被无关内容淹没。

生成失败：
  证据存在且可读，答案仍然错误或不完整。

引用失败：
  答案基本正确，但编号非法、缺失或不支持 claim。

权限失败：
  返回了用户无权读取的文档。

协议失败：
  JSON、字段、停止条件或流式格式不合法。
```

一个样本可能有多个错误标签，但要标出最早能修复的问题，方便安排下一轮实验。

### 7.6.2 无依赖的分层评估 demo

> 代码状态：静态审阅，未运行（2026-10-30）

```python
import re
from collections import Counter


CASES = [
    {
        "id": "q1",
        "gold": ["policy_001"],
        "answer": "工作满一年有 10 天带薪年假。[1]",
        "keywords": ["10 天", "带薪年假"],
        "references": [{"ref_id": 1, "chunk_id": "policy_001"}],
    },
    {
        "id": "q2",
        "gold": ["policy_002"],
        "answer": "报销需要审批。[1]",
        "keywords": ["部门负责人"],
        "references": [{"ref_id": 1, "chunk_id": "policy_001"}],
    },
    {
        "id": "q3",
        "gold": [],
        "answer": "资料中没有提到。",
        "keywords": ["资料中没有提到"],
        "allow_abstain": True,
        "references": [{"ref_id": 1, "chunk_id": "policy_001"}],
    },
]


def keyword_score(answer, keywords):
    if not keywords:
        return None
    if not isinstance(answer, str) or not all(
        isinstance(word, str) for word in keywords
    ):
        raise TypeError("answer and keywords must contain strings")
    return sum(word in answer for word in keywords) / len(keywords)


def citation_ids(answer):
    return [int(value) for value in re.findall(r"\[(\d+)\]", answer)]


def classify(case):
    available = {row["chunk_id"] for row in case["references"]}
    if not case["gold"]:
        if case.get("allow_abstain") and "资料中没有提到" in case["answer"]:
            return "correct_abstention"
        return "abstention_or_policy_failure"
    if not set(case["gold"]) & available:
        return "retrieval_or_context_failure"
    score = keyword_score(case["answer"], case["keywords"])
    if score is None:
        return "not_applicable"
    if score < 1.0:
        return "generation_or_abstention_failure"
    used = citation_ids(case["answer"])
    if any(value not in {row["ref_id"] for row in case["references"]} for value in used):
        return "citation_failure"
    return "ok"


for case in CASES:
    case["keyword_score"] = keyword_score(case["answer"], case["keywords"])
    case["error_type"] = classify(case)

print(
    "keyword_scores=",
    [
        None if case["keyword_score"] is None else round(case["keyword_score"], 3)
        for case in CASES
    ],
)
print("error_counts=", dict(Counter(case["error_type"] for case in CASES)))
print("case_count=", len(CASES))
```
这个 demo 中，q2 的 gold 不在可用证据里，答案也没有包含要求的关键词。`classify` 按检查顺序只返回最早的问题，`keyword_score` 则单独记录答案缺口。q3 展示的是正确拒答，不计入召回指标。真实系统应保存每一层的原始结果，才能分清“gold 没进入候选”和“gold 已进入候选但没有被引用”。

### 7.6.3 评估报告与成本

端到端报告应包含：

```text
模型、embedding、reranker、runtime 和文档版本；
评估集切分、样本数和任务类别；
Hit@1/3/5、Recall@k、MRR；
answer correctness、faithfulness、citation support、abstention；
TTFT、生成延迟、检索延迟、token 数和错误率；
权限泄露、格式错误、重试和人工复核成本；
失败样本对应的 request_id、错误阶段、文档快照和候选 chunk 标识；原文、完整检索结果、最终 prompt 与答案只进入经授权、脱敏且隔离的离线评估材料。
```

生产 trace 默认只保存排查问题所需的元数据，例如模型和索引 revision、文档版本、候选 chunk ID、处理阶段、延迟和 token 数。不要默认记录完整用户问题、检索正文、prompt 或答案，因为这些内容可能包含个人信息、商业资料或受限信息。排障确实需要原文时，应先按策略抽样和脱敏，再存入单独的加密位置，限制访问并设置保留期限；观测平台不会替系统自动做好这些控制。[OpenTelemetry GenAI 语义约定](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)也提醒，输入、输出和系统指令可能包含敏感内容，建议默认不采集完整文本。

单位成功任务成本可以写成：

```math
C_{\mathrm{success}}
=
\frac{C_{\mathrm{retrieval}}+C_{\mathrm{rerank}}+C_{\mathrm{generation}}+C_{\mathrm{review}}}
{N_{\mathrm{correct\ and\ supported}}}
```

这里要求 $N_{\mathrm{correct\ and\ supported}}>0$，并把重试、人工复核和失败请求产生的成本纳入同一统计周期。没有成功且有证据支持的任务时，单位成本应报告为未定义，而不是返回零。

不能只把成功答案放入分母而把重试和人工审核成本丢掉。若业务允许人工复核，复核成本应明确计入。


### 7.6.4 用分层结果决定下一轮改什么

再看一个 20 题的分层例子。离线标注为每题保存 gold evidence 和允许拒答标记；系统在 16 题中召回到 gold，Recall@5 为 $16/20=80\%$。系统实际回答了 14 题，其中 12 题答案正确，因此回答准确率是 $12/14\approx85.7\%$，coverage 是 $14/20=70\%$。如果其余 6 题中有 4 题资料不足、系统正确拒答了其中 2 题，拒答精确率就是 $2/4=50\%$。这几个比例回答的是不同问题，不能把 $80\%$、 $85.7\%$、 $70\%$ 和 $50\%$ 平均成“整体分数”。比较方案时，还应记录每题最早出错的环节，确认问题出在解析、召回、排序、生成、引用还是权限检查。

小评测集的比例不稳定。比如 20 题中 12 题答对，增加或减少一题就会改变 5 个百分点；如果题目全部来自同一种政策，80% 不能外推到财务、HR、采购和多语言请求。把数据按时间版本、问题类型、证据是否冲突、权限、表格/扫描件、是否需要计算等条件分组，分别报告每组的分子和分母。随机抽取的总体指标可回答平均表现，定向构造的压力样例则用于检查具体风险，两者不能互相替代。

自动 judge 也属于被评估对象。先用人工标注的一小批样本校准 judge：给它正确但措辞不同的答案、含有引用却不被引用支持的答案、以及证据正确但答案遗漏条件的答案，检查它是否按 rubric 区分。若两位人工标注者本身分歧很大，应先修订 rubric；若 judge 的判断只和答案流畅度相关，则它不能代替正确性标注。新模型、提示词或评分标准变化时，对同一批固定样本重跑 judge 并保留原始理由和版本，避免把评分器漂移误认为 RAG 改进。

比较两个版本时最好对同一批 query 做成对差分，并保留每题的旧/新候选、答案与判定变化。例如 100 题中，版本 B 有 8 题从错变对、3 题从对变错、89 题不变，净正确数只增加 5；只报 B 的总体准确率会隐藏那 3 个回归。ACL 越权、旧版本误引用和证据不足仍作答属于高风险类别，即使样本很少也要报告分子、分母和失败案例，不能让它们被大批简单查找题的平均值淹没。评估集或判定 rubric 变化时，要同时记录新旧口径，不能把口径变更造成的分数差异当作系统改进。

### 7.6.5 资料与证据边界

- RAGAS：<https://arxiv.org/abs/2309.15217>
- FActScore：<https://arxiv.org/abs/2305.14251>
- ARES：<https://arxiv.org/abs/2311.09476>
- BEIR：<https://arxiv.org/abs/2104.08663>
- MTEB：<https://arxiv.org/abs/2210.07316>
- HELM：<https://arxiv.org/abs/2211.09110>

公开指标和 benchmark 定义评估维度，不保证某个领域系统的答案质量。人工 rubric、评估集构造和目标系统实测决定最终结论；LLM judge 需要与人工样本比较校准。

本章的交付终点是“答案主张—当前证据—权限范围—评估结果”能够逐项对应。第八章会把检索能力作为 Agent 可调用的只读证据服务，再处理工具提议、授权和外部状态变化；检索到的内容可以支持决策，但不会自动授予执行权限。
