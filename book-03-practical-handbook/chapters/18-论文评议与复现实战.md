# 第 18 章：论文评议与复现实战

读论文时很容易记住作者的结论，却说不清结论为什么成立。比如有人说“FlashAttention 让 attention 又快又省显存”，这里至少混着几个不同主张：它是否仍计算精确 attention？减少的是哪一类数据搬运？速度是在什么硬件和序列长度上测得？一个本地小例子可以检查公式，但不能直接证明论文里的 GPU 性能。

[第十六章](16-项目答辩与技术表达.md)练习用证据说明项目结果，[第十七章](17-开放问题与系统设计实战.md)把约束变成系统方案。本章把这套判断方法用于论文：先还原作者要解决的问题和方法，再看实验到底支持什么，最后设计与手头资源相称的复现。读者不必复现每篇论文的全部规模，但应能分清公式核对、机制演示、方向性实验和论文结果复现。

## 18.1 从摘要到机制：怎样评议一篇论文

论文阅读的最低要求不是记住标题和结论，而是能够说明：作者试图解决什么瓶颈，核心方法改变了哪个变量，实验如何排除替代解释，局限是什么，能否在自己的资源和数据上复现。

### 论文卡片不是摘要

一页论文卡片可以抽象成：

~~~math
P=(B,M,F,E,L,A,R)
~~~

其中 `B` 是背景问题，`M` 是方法，`F` 是公式或结构，`E` 是实验设计，`L` 是局限，`A` 是工程应用，`R` 是复现计划。论文讨论覆盖率可以写成：

~~~math
C_{\mathrm{paper}}
=
\frac{1}{|K|}\sum_{k\in K}I_k
~~~

论文卡片覆盖率要求字段集合 `K` 非空。若没有任何字段，覆盖率没有定义；部分字段缺失应保留缺失列表，而不是把空卡片报告为零覆盖率后继续比较论文。

当 $I_k=1$ 时，表示该字段不仅被提到，而且能用自己的变量和证据解释。只背“这篇论文效果很好”不能算覆盖实验。

例如，若预先把 `K` 定为“问题、方法、实验、局限”四项，其中前三项能用证据解释而局限尚未读懂，则覆盖率为 $3/4=0.75$。这个比例只表示卡片审阅覆盖，不代表论文质量或结论可信度。

### Transformer：把序列依赖转成可并行的 attention

RNN 按时间步传递状态，训练时难以并行；卷积可以并行，但要扩大感受野通常需要增加层数。Transformer 的回答是让序列位置通过 self-attention 直接交换信息，再用多头、位置表示、残差连接、归一化和前馈网络组成模型：

~~~math
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right)V
~~~

对每个查询，$QK^{\mathsf T}$ 计算它与各位置 key 的匹配分数，除以 $\sqrt{d_k}$ 后经 softmax 变成权重，再用这些权重组合 value；$d_k$ 是 key 向量维度。任意两个位置之间的交互路径缩短，整段序列也可以并行计算；多头结构则让不同子空间学习不同关系。但标准 attention 的计算和中间存储仍随序列长度呈二次增长，位置表示能否外推也取决于具体机制与训练范围。原论文使用 encoder-decoder 架构，因此不能把论文里的机器翻译结果直接当成现代 decoder-only GPT 的性能结论。

若要检验它相对 RNN 或卷积的优势，应在同一小数据集上比较训练吞吐、长距离复制准确率和序列长度扩展曲线。只看最终 loss，会漏掉并行效率和内存代价；而这些正是论文论证的一部分。

机制定义和论文实验设置见 [Transformer 原论文 v7](https://arxiv.org/abs/1706.03762v7)；其机器翻译结果不能直接当作现代 decoder-only 模型的性能结论。

### LoRA：低秩参数更新

全参数微调要为基座参数保存梯度和优化器状态，多任务场景还会产生较大的 checkpoint。LoRA 冻结原权重 $W_0$，只学习一个低秩增量：

~~~math
W'=W_0+sBA,\qquad s=\frac{\alpha}{r}
~~~

~~~math
A\in\mathbb{R}^{r\times d_{\mathrm{in}}},\qquad
B\in\mathbb{R}^{d_{\mathrm{out}}\times r}
~~~

新增参数量为：

~~~math
N_{\mathrm{LoRA}}=r(d_{\mathrm{in}}+d_{\mathrm{out}})
~~~

这里 $A$ 和 $B$ 的中间秩为 $r$，新增参数量是 $r(d_{\mathrm{in}}+d_{\mathrm{out}})$，前提是秩和输入、输出维度为正，且矩阵形状与定义一致。这个数只算 adapter 参数，不能替代训练显存、优化器状态或多 adapter 并发切换的完整成本。

LoRA 本身不规定新的任务目标；例如 SFT 仍按任务对应的 token loss 学习，只是反向传播更新低秩矩阵 $A$、$B$，冻结 $W_0$。因此，比较 LoRA 与全参数微调时，要同时对齐损失、数据和训练条件，才能把差异归到参数更新方式上。

验证时应把冻结基座、全参数微调和不同 rank/target modules 放在同一任务条件下比较，同时记录任务得分、训练显存、checkpoint 大小和通用能力回归。可训练参数变少，只能说明更新参数的规模变小；它不能单独证明低秩更新足以完成目标任务。rank 太小可能欠拟合，rank 或目标模块太大又可能过拟合；工程收益还取决于 adapter 的加载、合并、并发切换和 dtype。

低秩参数化和原论文结果见 [LoRA 原论文 v2](https://arxiv.org/abs/2106.09685v2)；不同基座、数据和实现上的效果仍需单独评估。

### DPO：直接优化相对偏好

传统 RLHF 常包含偏好数据、奖励模型和 PPO 等环节。DPO 仍使用偏好对，但直接比较同一 prompt $x$ 下 `chosen` 与 `rejected` 的序列 log probability，并把当前策略 $\pi$ 相对参考策略 $\pi_0$ 的变化写进目标。令 $\ell_{\pi,c}=\log\pi(y_c\mid x)$，另外三项同理；每个 $\ell$ 都是对 response token 计算的序列 log probability，$\beta$ 是正的偏好温度参数：

~~~math
\mathcal{L}_{\mathrm{DPO}}
=
-\log\sigma\left(
\beta[(\ell_{\pi,c}-\ell_{\pi,r})
-(\ell_{\pi_0,c}-\ell_{\pi_0,r})]
\right)
~~~

这个目标要求两个回答都非空、四个 log probability 都是有限数，并且 $\beta>0$。采用 token log probability 求和时，回答长度会影响 margin；改成平均值会改变目标，必须作为实验配置的一部分。

例如，若当前策略对 chosen/rejected 的 log probability 差为 0.6，参考策略的差为 0.5，则相对 margin 是 0.1。取 $\beta=0.1$，sigmoid 输入为 0.01，损失约为 $-\ln \sigma(0.01)\approx0.688$，仍接近随机二选一的 $\ln 2\approx0.693$。这个算例说明目标在比较“偏好差距相对参考策略扩大了多少”，并不说明 chosen 回答在事实层面更正确。

评估时应比较 SFT 与 DPO 的 pairwise 胜率、偏好切片、输出长度、安全行为、通用能力回归和训练成本，并对 `β` 做消融。偏好数据质量会影响结果，长度、风格、过度拒答和 judge 偏差都可能被放大；偏好胜率提高也不等于事实能力提升。

目标函数和论文比较结果见 [DPO 原论文 v3](https://arxiv.org/abs/2305.18290v3)；结果限于作者报告的任务、模型和训练设置。

### FlashAttention：IO-aware 的精确 attention

标准 attention 实现除矩阵运算外，还可能反复把 $T\times T$ 的分数和权重写入、读出 GPU HBM；序列很长时，数据搬运会成为瓶颈。FlashAttention 将计算切成 tile，在更快的 SRAM 中处理局部块，再用 online softmax 合并各块统计量，从而不必显式保存完整 attention 矩阵，也能得到精确结果。

对一行 score，可以维护最大值 $m$、归一化因子 $l$ 和未归一化加权和 $u$。$J$ 是当前 tile 中可见位置的索引集合，$s_j$ 是位置分数，$v_j$ 是对应 value；旧状态初始化为 $m_{\mathrm{old}}=-\infty$、$l_{\mathrm{old}}=0$、$u_{\mathrm{old}}=0$。假设当前 tile 至少有一个可见位置，其统计量为：

~~~math
m_{\mathrm{tile}}=\max_{j\in J}s_j,\qquad
l_{\mathrm{tile}}=\sum_{j\in J}e^{s_j-m_{\mathrm{tile}}},\qquad
u_{\mathrm{tile}}=\sum_{j\in J}e^{s_j-m_{\mathrm{tile}}}v_j
~~~

~~~math
m_{\mathrm{new}}=\max(m_{\mathrm{old}},m_{\mathrm{tile}})
~~~

~~~math
l_{\mathrm{new}}
=
l_{\mathrm{old}}e^{m_{\mathrm{old}}-m_{\mathrm{new}}}
+l_{\mathrm{tile}}e^{m_{\mathrm{tile}}-m_{\mathrm{new}}}
~~~

加权和需要同步重标定，最后才除以归一化因子：

~~~math
u_{\mathrm{new}}
=u_{\mathrm{old}}e^{m_{\mathrm{old}}-m_{\mathrm{new}}}
+u_{\mathrm{tile}}e^{m_{\mathrm{tile}}-m_{\mathrm{new}}},\qquad
o=\frac{u}{l},\quad l>0
~~~

如果维护的是已归一化的 $o_{\mathrm{old}}$，应先乘回 $l_{\mathrm{old}}$，不能只按指数因子直接相加。下面用标量 value 验证不同 tile 大小得到相同的加权输出；向量 value 可逐通道使用同一组系数。

算法的 IO-aware 精确计算和原论文实验范围见 [FlashAttention 原论文 v2](https://arxiv.org/abs/2205.14135v2)。

手算验证时取 scores 为 `[1000, 1001, 999]`、标量 values 为 `[10, 0, 5]`，最大分数为 $m=1001$。稳定权重的未归一化值为 $e^{-1}\approx0.3679$、$e^0=1$ 和 $e^{-2}\approx0.1353$，所以 $l\approx1.5032$，加权和 $u\approx0.3679\times10+1\times0+0.1353\times5=4.3555$，输出 $u/l\approx2.8974$。改变 tile 大小只改变统计量的分组合并顺序，不改变这个数学结果。

import math


def tiled_weighted_sum(scores, values, tile_size):
    if (not isinstance(scores, list) or not isinstance(values, list)
            or not scores or len(scores) != len(values)):
        raise ValueError("scores and values must be non-empty aligned lists")
    if isinstance(tile_size, bool) or not isinstance(tile_size, int) or tile_size <= 0:
        raise ValueError("tile_size must be a positive integer")
    if any(isinstance(s, bool) or not isinstance(s, (int, float))
           or (not math.isfinite(s) and s != -math.inf) for s in scores):
        raise ValueError("scores must be finite or negative infinity")
    if any(isinstance(v, bool) or not isinstance(v, (int, float))
           or not math.isfinite(v) for v in values):
        raise ValueError("values must be finite")
    maximum, normalizer, numerator = None, 0.0, 0.0
    for start in range(0, len(scores), tile_size):
        visible = [(s, v) for s, v in zip(scores[start:start + tile_size],
                                         values[start:start + tile_size])
                   if s != -math.inf]
        if not visible:
            continue
        tile_max = max(s for s, _ in visible)
        new_max = tile_max if maximum is None else max(maximum, tile_max)
        old_scale = 0.0 if maximum is None else math.exp(maximum - new_max)
        normalizer = normalizer * old_scale + sum(
            math.exp(s - new_max) for s, _ in visible
        )
        numerator = numerator * old_scale + sum(
            math.exp(s - new_max) * v for s, v in visible
        )
        maximum = new_max
    if normalizer <= 0:
        raise ValueError("at least one visible score is required")
    return numerator / normalizer


scores = [1000.0, 1001.0, 999.0]
values = [10.0, 0.0, 5.0]
weights = [math.exp(s - max(scores)) for s in scores]
direct = sum(w * v for w, v in zip(weights, values)) / sum(weights)
for size in (1, 2, 3):
    tiled = tiled_weighted_sum(scores, values, size)
    assert math.isclose(tiled, direct, rel_tol=1e-12, abs_tol=1e-12)
    print("tile_size=", size, "weighted_output=", round(tiled, 6))
~~~
三个 tile 大小都输出约 2.897438；指数只处理分数与当前最大值的差，因此无需计算会溢出的 $e^{1001}$。将全部 score 设为负无穷应报错，单个全 mask tile 则可跳过。它不实现 GPU tiling、反向重算或 HBM 调度，不能用于 FlashAttention 性能比较。论文的核心是精确 attention 的 IO 优化，不是让理论 $T^2$ 算术复杂度消失；进一步实现见[第二十一册对应章节](../../book-21-transformer-architecture-evolution/chapters/20-FlashAttention与PagedAttention.md)。

### RAG：把外部证据接入生成

RAG 针对的是参数知识难以即时更新、模型不能直接访问私有资料、答案缺少出处等问题。它把检索到的文档作为生成条件，但效果取决于整条链：解析与切分、embedding、召回、重排、prompt、引用和权限控制缺一不可。

因此评估也要分层：检索看 Recall@K、MRR、NDCG；生成看正确性、依据充分性、引用准确率、证据不足时的拒答和权限错误；服务还要看延迟、token 用量和索引新鲜度。召回不到证据时模型仍可能编造；召回过期或错误证据时，引用也会给错误结论披上一层可信外衣。原始 RAG 论文的定义和结果绑定于其 seq2seq 模型、Wikipedia 索引与任务设置，不能直接推出企业系统结论，见 [RAG 原论文 v4](https://arxiv.org/abs/2005.11401v4)。

### Mamba/SSM：另一种序列建模路线

Attention 的二次长度项和 cache/带宽压力推动了另一类序列模型的发展。先看一个省略了直通项和多通道布局的状态空间递推：

~~~math
h_t=\bar A_t h_{t-1}+\bar B_t x_t
~~~

~~~math
y_t=C_t h_t
~~~

这是省略直通项和多通道布局的离散递推抽象：若单通道输入是标量、状态维度为 $N$，则 $h_t$ 是 N 维状态，$\bar A_t$ 控制状态转移，$\bar B_t$ 控制输入注入，$C_t$ 把状态映射为输出。Mamba 的选择性主要让 $B_t$、$C_t$ 和正的离散步长 $\Delta_t$ 依赖输入；连续状态矩阵 $A$ 通常是学习参数，离散后的 $\bar A_t$ 可通过步长依赖输入，因此不能把所有连续参数都写成任意的 $A(x_t)$。

只看这个抽象递推，令 $h_0=0$、每步 $\bar A_t=0.5$，输入依次为 2、3、4：若注入系数 $\bar B_t$ 依次为 1、0、1，则状态依次是 2、1、4.5；若每步都注入，则是 2、4、6。选择性改变了哪些输入进入状态，而非简单把所有历史相加。该数值是门控递推的教学例子，不是 Mamba 官方离散化或训练参数。

这种结构能以固定维度状态沿序列递推，但线性或近线性的计算量不自动意味着通用任务更好；attention 仍能显式建立 token 与 token 的交互。模型、硬件 kernel、训练数据、任务长度和 batch 形状都会改变结果，复杂度符号不能替代 benchmark。选择性状态空间结构及原论文实验边界见 [Mamba 原论文 v2](https://arxiv.org/abs/2312.00752v2)。

### 复现从哪一步开始

复现不必一开始就复制论文的全部规模。先核对公式、shape 和单步数值，再尝试最小模型与小数据 baseline；随后复现关键方法和主指标，最后做消融、失败分析与资源/质量权衡：

~~~text
层 1：复现公式、shape 和单步数值
层 2：复现最小模型与小数据 baseline
层 3：复现关键方法和论文主指标
层 4：做 ablation、失败分析和资源/质量权衡
~~~

固定随机种子、数据切分、tokenizer、模型 revision、硬件、dtype、训练步数和评估脚本。若论文使用大规模数据而本地只能使用小数据，应把结果写成“机制最小复现”或“方向性实验”，不要声称复现了论文全部结论。

### 一个论文卡片审计器

下面以 LoRA 卡片为具体输入：`formula` 必须包含 $d_{\mathrm{in}}$、$d_{\mathrm{out}}$ 和秩 $r$，实验分数按越大越好解释。迁移到其他论文时，必须替换这些方法专属检查和指标方向。字段检查只帮助发现记录缺项，不能自动核验材料真实性或实验有效性。

import math


REQUIRED_FIELDS = [
    "title", "problem", "prior_limit", "method", "formula",
    "why_effective", "experiment", "limitation", "engineering",
    "reproduction", "questions",
]
REQUIRED_EXPERIMENT = ["dataset", "baseline", "metric", "ablation", "failure_case"]
REQUIRED_REPRODUCTION = [
    "minimal_model", "fixed_seed", "baseline", "paper_method", "ablation", "bad_case"
]


def coverage(found, required):
    if not isinstance(found, (dict, list, tuple, set)):
        raise TypeError("found must be a collection or dictionary")
    if not isinstance(required, (list, tuple, set)) or not required:
        raise ValueError("required must be a non-empty collection")
    def populated(value):
        return bool(value.strip()) if isinstance(value, str) else bool(value)

    missing = [item for item in required
               if item not in found or isinstance(found, dict) and not populated(found[item])]
    return round((len(required) - len(missing)) / len(required), 4), missing


def lora_counts(d_in, d_out, rank):
    if (isinstance(d_in, bool) or not isinstance(d_in, int) or d_in <= 0
            or isinstance(d_out, bool) or not isinstance(d_out, int) or d_out <= 0
            or isinstance(rank, bool) or not isinstance(rank, int) or rank <= 0):
        raise ValueError("LoRA dimensions and rank must be positive integers")
    adapter = rank * (d_in + d_out)
    full = d_in * d_out
    return adapter, full, round(adapter / full, 4)


def audit(card):
    if not isinstance(card, dict):
        raise TypeError("card must be a dictionary")
    for field in REQUIRED_FIELDS:
        if field not in card:
            raise ValueError(f"card is missing field: {field}")
    if not isinstance(card["experiment"], dict) or not isinstance(card["reproduction"], (list, tuple, set)):
        raise TypeError("experiment and reproduction have invalid types")
    if not isinstance(card["formula"], dict):
        raise TypeError("formula must be a dictionary")
    for field in ("baseline_score", "method_score"):
        value = card["experiment"].get(field)
        if (isinstance(value, bool) or not isinstance(value, (int, float))
                or not math.isfinite(value)):
            raise ValueError("experiment scores must be finite numbers")
    field_score, field_missing = coverage(card, REQUIRED_FIELDS)
    experiment_score, experiment_missing = coverage(
        card["experiment"], REQUIRED_EXPERIMENT
    )
    reproduction_score, reproduction_missing = coverage(
        card["reproduction"], REQUIRED_REPRODUCTION
    )
    adapter, full, ratio = lora_counts(
        card["formula"]["d_in"], card["formula"]["d_out"], card["formula"]["rank"]
    )
    gain = round(card["experiment"]["method_score"]
                 - card["experiment"]["baseline_score"], 4)
    issues = []
    if not card["limitation"]:
        issues.append("no_limitation")
    if experiment_missing:
        issues.append("weak_experiment")
    if reproduction_missing:
        issues.append("weak_reproduction")
    return {
        "field_score": field_score,
        "field_missing": field_missing,
        "experiment_score": experiment_score,
        "reproduction_score": reproduction_score,
        "adapter": adapter,
        "full": full,
        "ratio": ratio,
        "gain": gain,
        "issues": issues,
        "record_complete": field_score == 1.0 and experiment_score == 1.0
        and reproduction_score == 1.0 and not issues,
        "evidence_verified": False,
    }


card = {
    "title": "LoRA",
    "problem": "full fine-tuning is expensive",
    "prior_limit": "all task copies store full weights",

        "low_rank_a": "A", "low_rank_b": "B", "d_in": 4096, "d_out": 4096,
    },
    "why_effective": "task updates can be low rank",
    "experiment": {
        "dataset": "task validation",
        "baseline": "frozen model",
        "metric": "task score",
        "baseline_score": 0.78,
        "method_score": 0.86,
        "ablation": "rank sweep",
        "failure_case": "underfit domain shift",
    },
    "limitation": "rank and target modules depend on task",
    "engineering": "share base and save adapters",
    "reproduction": REQUIRED_REPRODUCTION[:],
    "questions": ["contribution", "limitation"],
}
report = audit(card)
assert report["field_score"] == 1.0
assert report["experiment_score"] == 1.0
assert report["reproduction_score"] == 1.0
assert report["adapter"] == 65536
assert report["full"] == 16777216

assert report["gain"] == 0.08
assert report["issues"] == []

## 18.2 从最小复现走到有边界的结论

### 把结论绑定到条件

论文评议中最容易误导人的，是把有条件的观察写成无条件结论，例如“量化一定提升吞吐”“RAG 一定减少幻觉”“DPO 一定让回答更好”。报告结果时要说清在什么模型、什么数据、什么指标、什么硬件和什么版本上观察到什么变化。

一个结论记录可以写成：

~~~math
E=(claim,condition,measurement,uncertainty,boundary)
~~~

`claim` 是结论，`condition` 是运行条件，`measurement` 是测量，`uncertainty` 是统计或实验不确定性，`boundary` 是不能外推的范围。没有条件和测量的名词堆砌，无法支持工程决策。

### 先讲因果链，再讲名词

解释论文方法时，先把任务瓶颈和方法改变的量连起来，再说明作者如何验证、观察到什么副作用、结论在哪些条件下不成立。例如“使用 GQA 降低推理显存”还需要解释：共享 KV head 会减小 KV Cache 公式中的 $H_{\mathrm{KV}}$；显存与吞吐要在相同 batch、长度、dtype 和 kernel 下比较；质量和 decode 速度还要分别检查。名词一旦放回这条因果链，听者就能判断它为什么出现、证据够不够。

### 最小实验优先

当一个概念难以解释时，先做最小实验：Attention 用小矩阵检查 mask；SFT 用字符模板检查 label；DPO 用固定 log probability 检查 beta；RAG 用三个文档检查 ACL 和 citation；系统设计用几个数字检查 QPS 和 cache；论文复现先做单步公式和小数据 baseline。

最小实验不是生产系统，也不是最终效果证明。它的作用是缩小变量空间，使错误能够被定位。只有最小实验通过后，才值得增加模型规模、数据规模和系统复杂度。

### 练习：检查一个结论能否复现

改变 FlashAttention 数值例子的 tile 大小，并加入一个全屏蔽 tile；再把论文卡片中的实验指标留空。说明哪些数值性质仍应成立，卡片还缺少什么证据。脚本成功只能说明这段教学计算按预期运行，不能证明 GPU kernel 性能，更不能推出论文结论已经复现。

论文评议的结果不一定是“作者证明了方法更好”。更诚实的结论可能是：公式和最小计算能复现，公开实验支持某个范围内的改进，但本地硬件、数据或预算不足以检验全部主张。这样的边界不是回答的缺点，而是证据本身的范围。
