# 第九章：多模态模型与研究判断：从表征到证据

多模态模型处理的不是“把图片接到语言模型上”这么简单。图像、声音、视频和文档都有自己的采样方式、局部结构、时间尺度和噪声来源；模型要先把这些信号变成表示，再通过对齐、融合或生成机制完成任务。研究者还要判断：模型是否真的使用了输入证据，实验是否排除了数据和规模因素，结果是否值得付出额外的 token、显存、延迟和人工标注成本。

一个只会背模型名称的人，可能知道 CLIP 做图文对齐，知道 LLaVA 用视觉编码器和语言模型，知道 diffusion 从噪声生成图片，知道 Whisper 做语音识别，却仍然无法解释四个关键问题：

1. 不同模态的输入如何被表示成可计算的对象？
2. 对齐、融合、生成和推理分别解决什么问题？
3. 一个回答正确时，如何确认它来自图像或声音证据，而不是语言先验？
4. 一个实验得到提升时，如何确认提升不是更多数据、更大分辨率、更长推理或评审偏差造成的？

本章把多模态模型和研究方法放在同一条证据链上。前半部分讲像素、音频、视频和文档如何进入模型，后半部分讲如何提出主张、建立 baseline、设计消融、复现实验、解释负结果和管理安全边界。文中的数字示例是教学构造，除非特别注明，不代表某个公开模型的实测结果。

## 9.1 先定义任务：多模态不是一个单一能力

### 9.1.1 输入和输出决定模型问题

“多模态理解”至少包含几类不同任务：

| 任务 | 输入 | 输出 | 主要困难 |
| --- | --- | --- | --- |
| 图文检索 | 图片、文本 | 相似度或排序 | 语义对齐、细粒度区分 |
| 图片问答 | 图片、问题 | 文本答案 | 视觉证据、组合推理 |
| 文档理解 | 页面图像、文字、版面 | 字段、表格或摘要 | OCR、布局和阅读顺序 |
| 图像生成 | 文本或参考图 | 图片 | 条件控制、细节和安全 |
| 视频生成 | 文本、图片或视频 | 视频 | 时空一致性和长程结构 |
| 语音识别 | 音频 | 文本 | 噪声、口音、重叠语音和延迟 |
| 语音对话 | 音频、文本、工具状态 | 音频或动作 | 打断、端点、工具副作用 |
| 多模态 Agent | 图像、网页、文件、工具 | 解释或动作 | 权限、证据链和状态恢复 |

初学者可以把任务理解成“输入中有不止一种信息”。专家必须继续问：模型需要识别什么，是否需要定位证据，输出是否可验证，错误会造成什么后果，系统是否能承受一次错误。

例如，“这张图里有几辆车”主要是计数问题；“根据这张发票填写报销字段”是 OCR、版面理解、字段抽取和业务校验的组合；“根据监控视频判断是否应该报警”则还包含时间窗口、事件定义、误报代价和人工复核。它们不能用同一个 VQA 分数概括。

### 9.1.2 表征、对齐、融合和生成不是同义词

可以把一个多模态系统拆成四个动作：

1. 表征：把原始信号变成向量、token、latent 或状态。
2. 对齐：让不同模态中描述同一语义的表示彼此接近或可互相预测。
3. 融合：让模型在同一任务中联合读取多种模态。
4. 生成：根据条件产生文本、图像、音频、视频或工具动作。

CLIP 主要解决图文表示对齐，不能因此推出它能生成长答案；典型 VLM 解决视觉条件下的语言生成，不能因此推出它能准确定位每个物体；diffusion 解决条件生成，不能因此推出它拥有可交互的世界模型。

### 9.1.3 先画证据链，再谈模型大小

一个可靠的多模态分析应先画出：

~~~text
原始输入
    -> 预处理与切分
    -> 模态编码器
    -> 对齐或连接层
    -> 融合/解码模型
    -> 输出、证据和动作
    -> 评估、监控与人工复核
~~~

这张图能帮助定位错误。图片被缩得过小，问题在预处理；视觉 token 映射到语言空间后失去细节，问题在 connector 或压缩；答案看起来流畅却没有图像依据，问题可能在训练数据、语言先验或评估；模型识别正确却填错了报销金额，问题还可能在业务校验和动作层。

不要先用参数量解释一切。参数量是容量线索，不是证据链的替代品。不同模型的视觉编码器、图像分辨率、token 压缩、训练数据和解码设置不同，直接比较参数量通常不能解释任务差异。

## 9.2 图像如何变成视觉 token

### 9.2.1 从像素矩阵到 patch

一张 RGB 图像可以表示为高度 H、宽度 W、通道数 C=3 的张量。Vision Transformer 一类模型把图像切成边长为 P 的不重叠 patch。假设 H、W 能被 P 整除，patch 数量为：

~~~math
N_{\mathrm{patch}}
=
\frac{H}{P}
\times
\frac{W}{P}
~~~

每个 patch 的原始维度是 `P^2 C`。把 patch 展平成向量后，通过线性映射投影到隐藏维度 d：

~~~math
Z
=
X_{\mathrm{patch}}W_{\mathrm{e}}
+
b_{\mathrm{e}}
+
E_{\mathrm{pos}}
~~~

其中，`X_patch` 的形状是 `N_patch x (P^2 C)`，`W_e` 是 patch 投影矩阵，`b_e` 是偏置，`E_pos` 是位置表示。输出 Z 的每一行可以看作一个视觉 token。

以 224×224 图像和 16×16 patch 为例，token 数是：

~~~math
N_{\mathrm{patch}}
=
\frac{224}{16}
\times
\frac{224}{16}
=
196
~~~

如果分辨率变成 448×448，patch 大小不变，token 数变为 784，是原来的四倍。全注意力的理论两两交互数量近似随 token 数平方增长，因此提高分辨率通常同时增加显存、计算和上下文占用。

### 9.2.2 CNN 和 ViT 的差异

CNN 通过局部卷积、共享权重和逐层下采样建立空间表示，天然带有局部性和平移等归纳偏置。ViT 把 patch 当作序列元素，用 self-attention 建模远距离 patch 之间的关系，更容易与 Transformer 语言模型和统一 token 流程连接。

这不是“ViT 一定优于 CNN”的结论。CNN 在数据规模有限、局部纹理重要或设备对卷积优化更成熟时可能更有优势；ViT 在大规模预训练、跨模态对齐和全局关系建模中更容易扩展。真正的比较要固定数据、分辨率、训练预算和下游评估。

### 9.2.3 分辨率、patch 和细节的三方取舍

分辨率提高可能改善小文字、小物体和细粒度属性，但会带来三个代价：

1. 视觉 token 增多，语言模型上下文变长；
2. prefill 和视觉编码计算增加；
3. 显存、传输和缓存压力增大。

patch 变小也会增加 token。小 patch 保留更多局部细节，但让模型更难在固定预算内处理多张图片或长文本。patch 变大可以降低成本，却可能把一行小字平均到同一个 patch 中，使 OCR 直接失去信息。

工程上常见的折中包括多尺度输入、局部 crop、动态分辨率、区域重采样和视觉 token 合并。它们不是免费优化：crop 需要决定看哪些区域，动态分辨率会使批处理更复杂，token 合并可能丢失空间关系。评估时必须把这些策略和推理成本一并记录。

### 9.2.4 位置关系不能被语义相似度替代

图像里“猫在桌子左边”和“桌子在猫左边”包含不同的空间关系。全局 image embedding 可能足够做粗粒度检索，却不足以回答方向、遮挡、距离和相对位置问题。需要保留区域 token、二维位置信息或显式 grounding 目标。

因此，单一向量适合低成本检索，序列或网格 token 适合细节理解。表示的选择应由下游任务决定，而不是因为单向量更容易存储就把所有图像压成一个数字。

## 9.3 CLIP：图文对比学习如何建立共享语义空间

### 9.3.1 Batch 内负样本

CLIP 类方法使用图像编码器 f 和文本编码器 g。对第 i 个图文对 `(x_i, y_i)`，得到归一化向量：

~~~math
u_i
=
\frac{f(x_i)}{\lVert f(x_i)\rVert_2},
\qquad
v_i
=
\frac{g(y_i)}{\lVert g(y_i)\rVert_2}
~~~

归一化后，点积就是余弦相似度。一个 batch 有 N 对样本，图像 i 和文本 j 的 logit 可以写成：

~~~math
\ell_{ij}
=
\frac{u_i^\top v_j}{\tau}
~~~

其中 τ 是温度参数。匹配对位于对角线，其他位置通常作为 batch 内负样本。图像到文本的交叉熵为：

~~~math
\mathcal{L}_{\mathrm{i2t}}
=
-\frac{1}{N}
\sum_{i=1}^{N}
\log
\frac{\exp(\ell_{ii})}
{\sum_{j=1}^{N}\exp(\ell_{ij})}
~~~

文本到图像同理：

~~~math
\mathcal{L}_{\mathrm{t2i}}
=
-\frac{1}{N}
\sum_{i=1}^{N}
\log
\frac{\exp(\ell_{ii})}
{\sum_{j=1}^{N}\exp(\ell_{ji})}
~~~

最终常见目标是两者的平均：

~~~math
\mathcal{L}_{\mathrm{clip}}
=
\frac{1}{2}
\left(
\mathcal{L}_{\mathrm{i2t}}
+
\mathcal{L}_{\mathrm{t2i}}
\right)
~~~

初学者可以把它理解成“给每张图片找对文字，同时给每句话找对图片”。专家要注意，batch 中的其他样本不一定是真负样本。两张图片可能都包含狗，只是描述重点不同；同一图片可能有多个合理 caption；网页 alt-text 还可能包含错误或无关内容。

### 9.3.2 Zero-shot 分类是如何发生的

给定类别集合 C，可以为每个类别生成文本模板，例如“a photo of a bicycle”。对图片 x 计算图像向量和类别文本向量的相似度：

~~~math
p(c\mid x)
=
\frac{
\exp(\operatorname{sim}(f(x),g(t_c))/\tau)
}{
\sum_{c'\in C}
\exp(\operatorname{sim}(f(x),g(t_{c'}))/\tau)
}
~~~

选择概率最高的类别，就得到 zero-shot 预测。它没有为这个下游数据集训练一个固定分类头，而是利用语言空间中的类别描述定义任务。

这个机制的收益是迁移灵活，代价是 prompt wording、类别粒度、语言和数据分布都会影响结果。把“zero-shot”理解成完全不需要任务设计是不准确的；类别名称、模板、图像裁剪和候选集合都属于评估协议。

### 9.3.3 对齐不等于理解

如果图片和文本都出现“红色汽车”，对比学习会鼓励它们接近，但不必然学习：

- 汽车有几个轮子；
- 哪辆车位于另一辆车左侧；
- 图片中的文字是什么；
- 这个物体是否真的存在而不是 caption 中的错误；
- 多个证据组合后应该得出什么结论。

这是对比学习目标和任务目标的差异。检索任务需要全局语义相似，计数、OCR 和空间推理需要局部结构和组合关系。评价 CLIP 类表示时，要明确它解决的是跨模态匹配还是事实级视觉理解。

### 9.3.4 数据噪声、重复和捷径

大规模图文数据的主要风险不只是噪声，还包括：

1. 重复图片和模板化 caption 让模型记住网站格式；
2. 图片和文字只在页面主题上相关，未必互相描述；
3. 文化、语言和人群分布不均；
4. 版权、个人信息和敏感内容的处理不透明；
5. 下游 benchmark 可能已经出现在训练语料中。

因此，CLIP 指标提升时要同时检查数据过滤、去重、语言覆盖、评估污染和 prompt 选择。一个更大的 batch 可能带来更多负样本，但也可能增加假负样本，不能只把 batch size 当作无条件收益。

## 9.4 VLM：视觉编码器如何接入语言模型

### 9.4.1 三段式结构

典型视觉语言模型可以写成：

~~~text
image
    -> vision encoder
    -> visual features
    -> connector/projector
    -> visual tokens in language space
    -> language model
    -> answer tokens
~~~

视觉编码器提取图像特征，connector 将特征映射到语言模型的隐藏维度，语言模型再把视觉 token 和文本 token 放入同一个条件生成过程。最简单的 connector 是线性投影：

~~~math
V'
=
VW_{\mathrm{proj}}
+
b_{\mathrm{proj}}
~~~

其中 V 是视觉特征矩阵，`W_proj` 把视觉维度映射到语言隐藏维度，V' 才能在形状上与语言 token 表示拼接或交互。

### 9.4.2 Connector 的不同形态

Linear projection 参数少、训练稳定、容易复现，但表达能力有限；MLP projector 可以做非线性变换，代价是参数和训练复杂度增加；Q-Former 或 resampler 用少量可学习 query 从大量视觉 token 中提取摘要，能压缩上下文，却可能丢掉小文字和空间细节；cross-attention 让语言层按需读取视觉特征，灵活但计算和实现更复杂。

不能只用“更复杂”推断“更好”。如果任务是图文检索，少量全局 token 可能已经足够；如果任务是票据字段抽取，过度压缩会直接伤害 OCR；如果任务包含多轮对话和多图比较，还要考虑视觉 token 在历史上下文中如何保留、复用和失效。

### 9.4.3 冻结、解冻和训练阶段

一种常见的教学性训练路径是：

1. 先冻结 vision encoder 和语言模型，只训练 connector，让两种表示建立接口；
2. 再用多模态指令数据训练语言模型的一部分或全部；
3. 最后根据任务需要做偏好优化、工具训练或领域适配。

冻结视觉编码器能减少训练成本并保护已有视觉表示，但域差异较大时可能不够；解冻视觉编码器能适应文档、医学或工业图像，却可能破坏通用能力并增加显存需求。训练阶段的命名不能替代实验：需要记录哪些参数更新、使用什么数据、loss 对哪些 token 计算。

### 9.4.4 图像 placeholder 和 loss mask

许多 VLM 工程故障来自协议而非算法。文本模板中的一个 image placeholder 可能在运行时展开成多个视觉 token；如果 placeholder 数量、视觉特征数量和 attention mask 不一致，就会出现错位。训练时如果把用户问题、图片占位符和 assistant 答案全部计算 loss，模型可能学习复制提示格式而不是回答。

应至少检查：

1. 原始消息中的图片数量与图像张量数量一致；
2. 每张图片经过预处理后的尺寸和色彩顺序正确；
3. placeholder 展开位置与视觉 token 顺序一致；
4. padding、截断和右侧/左侧对齐没有改变图文关系；
5. assistant-only loss mask 只覆盖目标输出；
6. 推理模板和训练模板使用同一套 special token 规则。

这些检查属于数据和协议的可复现条件，不能因为模型能够启动就忽略。

## 9.5 原生多模态、统一 token 和 token budget

### 9.5.1 “原生”不是一个统一技术定义

产品或模型资料中的“原生多模态”可能指不同事情：有的模型在预训练阶段同时处理多种模态，有的模型使用统一的自回归 token 流，有的模型只是把多个专用编码器和生成器放在同一个产品接口里。阅读资料时必须区分：

- 模态是否在同一个训练目标中共同优化；
- 是否存在专用 encoder、decoder 或 adapter；
- 输入是否能交错排列；
- 输出是否可以跨模态生成；
- 评估是否覆盖每种模态和组合任务。

统一接口不等于统一内部表示，统一 token 也不等于不同模态的信息密度相同。没有技术报告或模型卡支持时，不应从产品名称推断内部架构。

### 9.5.2 多模态上下文的长度账本

一个请求可能同时包含文本、图片、音频、视频和工具结果。把各模态折算为 token 或等价计算单元后，可写一个预算：

~~~math
L_{\mathrm{total}}
=
L_{\mathrm{text}}
+
L_{\mathrm{image}}
+
L_{\mathrm{audio}}
+
L_{\mathrm{video}}
+
L_{\mathrm{tool}}
~~~

在标准全注意力的粗略模型中，注意力交互成本随总序列长度平方增长：

~~~math
C_{\mathrm{attn}}
\propto
L_{\mathrm{total}}^2 d
~~~

其中 d 是隐藏维度。真实系统可能使用局部注意力、窗口、稀疏注意力、latent bottleneck 或专用视觉模块，因此这个公式是预算直觉，不是所有架构的精确 FLOPs。

当图片 token 从 256 增加到 1024 时，单图细节可能提高，但它会挤占文本、历史和工具结果的上下文空间。多图任务还要考虑图片之间的比较关系，而不是独立处理后简单拼接。

### 9.5.3 压缩视觉 token 的收益和损失

设原始视觉 token 数为 N，压缩后为 K，压缩比例可以写成：

~~~math
r_{\mathrm{compress}}
=
1-\frac{K}{N}
~~~

压缩减少 prefill 和显存，但可能损失细粒度证据。一个合理评估要同时报告：

1. OCR、计数和空间关系的质量变化；
2. 多图比较和长文本场景的质量变化；
3. TTFT、TPOT、显存和吞吐；
4. 图片数量增加时的退化曲线；
5. 失败是否集中在小物体、边缘区域或低对比文字。

只报告“token 更少”不等于系统更好。应关注单位成功任务成本，而不是孤立的压缩率。

### 9.5.4 音频和视频的 token 化更容易掩盖成本

音频和视频本身是长序列。视频若按帧提取视觉 token，序列长度大致与帧数、空间 patch 数和时间窗口共同增长：

~~~math
N_{\mathrm{video}}
\approx
T_{\mathrm{frame}}
\times
N_{\mathrm{spatial}}
~~~

如果再加入音频、字幕和工具轨迹，语言模型上下文可能很快成为瓶颈。工程上常用时间采样、关键帧、层级摘要、检索和 latent 压缩；每一种压缩都需要回答“丢掉了什么证据”。

## 9.6 多模态预训练与指令调优

### 9.6.1 不同数据对应不同目标

多模态训练数据至少可以分为：

1. 图文配对：学习跨模态相似度；
2. 图片描述：学习从视觉条件生成文本；
3. 交错文档：学习在长文本中读取图片、表格和图注；
4. OCR 和版面：学习文字、区域和阅读顺序；
5. 图表与空间关系：学习结构化视觉推理；
6. 多轮指令：学习按用户目标组织输出；
7. 工具轨迹：学习检索、裁剪、计算和验证；
8. 安全样本：学习隐私、危险内容和不确定性边界。

这些目标不应被压成一个“多模态 loss”。图文对比损失擅长全局对齐，caption loss 训练生成，OCR 目标约束文字，grounding 目标约束区域，偏好数据改变交互行为。训练混合比例会改变模型能力分布。

一个教学性的混合目标可以写成：

~~~math
\mathcal{L}
=
\alpha\mathcal{L}_{\mathrm{align}}
+
\beta\mathcal{L}_{\mathrm{caption}}
+
\gamma\mathcal{L}_{\mathrm{ground}}
+
\delta\mathcal{L}_{\mathrm{instruction}}
~~~

α、β、γ、δ 是各任务权重。它们不是可跨项目复用的常数；改变权重时，必须报告每个子任务的单独变化，防止总体 loss 下降掩盖 OCR 或安全能力退化。

### 9.6.2 多模态指令数据的真正难点

把一张图片和一个问题拼成 JSON 并不自动构成高质量指令数据。样本至少要说明：

- 图片是否真的包含回答所需证据；
- 问题是否有唯一或可接受答案；
- 回答是否引用了图像而不是凭语言先验猜测；
- OCR、表格和坐标是否保留；
- 不确定时是否允许回答“不足以判断”；
- 多轮上下文中的图片是否仍然可访问；
- 是否存在个人信息、版权或不可信指令。

错误 caption 会教模型产生视觉幻觉；含糊问题会让评估分歧看起来像模型错误；只写“请描述图片”会过度奖励长而泛化的描述，无法检查关键事实。

### 9.6.3 训练规模不是质量的替代品

一百万条低质量图文对可能不如十万条经过去重、审计和任务覆盖的数据。评估数据还可能泄漏到训练集，造成看似很高的结果。数据数量、图片分辨率、文本长度、领域比例和合成数据来源都应进入实验记录。

合成数据可以补充稀缺的 OCR、图表和空间样本，但教师模型的错误会被复制；合成图像的纹理、字体和布局也可能与真实世界不一致。合成数据的价值要通过真实分布 holdout 和错误类型分析来判断。

## 9.7 视觉 grounding：回答正确还不够

### 9.7.1 什么叫基于视觉证据

如果模型回答“图片里有一只猫”，需要知道它是否真的读取了猫所在区域；如果回答“右边的数字是 128”，则还要确认数字、位置和读取顺序都得到支持。grounding 关注答案和输入证据之间的对应关系，而不仅是最终字符串是否与参考答案相同。

可以把回答拆成若干可验证 claim。设被评估的视觉 claim 总数为 N_claim，其中能由图像区域、OCR 结果或结构化证据支持的数量为 N_supported，则教学性的 grounding rate 为：

~~~math
\mathrm{GroundingRate}
=
\frac{N_{\mathrm{supported}}}{N_{\mathrm{claim}}}
~~~

这不是一个完全客观的指标。标注员需要定义“支持”是像素级定位、区域重叠、OCR 字符一致，还是人工判断。对于开放式描述，一个 claim 可能有多个合理表达，不能机械地用字符串匹配。

### 9.7.2 视觉幻觉的四种来源

常见失败至少可以分成四类：

1. 看不见：分辨率、裁剪、遮挡或视觉编码器没有保留信息；
2. 看错：模型识别了错误的颜色、物体、文字或位置；
3. 语言补全：图像证据不足，语言模型根据常见场景补出答案；
4. 证据错配：回答中的某个 claim 有证据，另一个 claim 没有，但整体语气很确定。

这四类失败的修复不同。提高分辨率可能帮助第一类；增加 OCR 或区域监督可能帮助第二类；训练 abstention、检索和不确定性可能帮助第三类；claim-level citation 和结构化输出可能帮助第四类。

### 9.7.3 评估“反事实图片”而不是只看正常样本

一个有效的诊断方法是构造只改变关键视觉事实的成对样本。例如只把票据金额从 128 改成 182，只交换左右位置，只改变对象数量，保持文字问题和模板不变。如果模型答案不随视觉事实改变，说明它可能依赖语言先验或模板。

反事实样本不等于真实分布的全部，但能帮助区分“会生成看似合理的句子”和“真正读取了图像”。报告时应同时保留原图、变体、预处理版本和评估规则，避免图像压缩或字体变化引入新的混杂因素。

### 9.7.4 视觉证据链的产品形式

在文档和高风险场景中，系统可以要求输出：

~~~text
claim
    -> source page or image
    -> region/OCR span
    -> transformation or calculation
    -> answer
    -> uncertainty and reviewer status
~~~

这条链不是让模型生成一段解释就算完成，而是由系统保存可复核的页面、区域、文本和计算结果。自然语言理由可能是事后合理化，不能替代原始证据。

## 9.8 Diffusion：从噪声学习数据分布

### 9.8.1 正向加噪过程

扩散模型先定义一个逐步加噪的过程。给定干净样本 x_0，在第 t 步加入高斯噪声：

~~~math
q(x_t\mid x_0)
=
\mathcal{N}
\left(
\sqrt{\bar{\alpha}_t}x_0,
(1-\bar{\alpha}_t)I
\right)
~~~

其中，β_t 是第 t 步噪声率，α_t=1-β_t，`bar_alpha_t` 是从第一步到第 t 步的 α 的乘积。等价地，可以直接采样：

~~~math
x_t
=
\sqrt{\bar{\alpha}_t}x_0
+
\sqrt{1-\bar{\alpha}_t}\epsilon,
\qquad
\epsilon\sim\mathcal{N}(0,I)
~~~

当 t 增大，样本逐渐接近纯噪声。

### 9.8.2 反向去噪与训练目标

模型 ε_θ 接收带噪样本 x_t、时间步 t 和条件 c，预测加入的噪声。一个常见训练目标是：

~~~math
\mathcal{L}_{\epsilon}
=
\mathbb{E}_{x_0,\epsilon,t}
\left[
\left\|
\epsilon
-
\epsilon_{\theta}(x_t,t,c)
\right\|_2^2
\right]
~~~

推理时从近似高斯噪声开始，沿学习到的反向过程逐步得到 x_0。每一步都需要一次或多次网络前向，因此采样步数、采样器、分辨率和 batch 会直接影响延迟与成本。

初学者可以把它看成“先把答案打乱，再学会一点点恢复”；专家要知道训练目标、参数化方式、噪声 schedule、采样器和条件注入共同决定结果，不能只说“去噪”两个字。

### 9.8.3 文本条件和 classifier-free guidance

设 ε_cond 是有条件预测，ε_uncond 是无条件预测，可以用 classifier-free guidance 构造更强的条件方向：

~~~math
\hat{\epsilon}
=
\epsilon_{\mathrm{uncond}}
+
s
\left(
\epsilon_{\mathrm{cond}}
-
\epsilon_{\mathrm{uncond}}
\right)
~~~

其中 s 是 guidance scale。s 较大通常增强文本条件，但也可能造成过饱和、构图僵硬、细节重复或多样性下降。条件越强不等于语义越准确，仍要评估文字、数量、空间关系和安全边界。

### 9.8.4 生成质量不能只看漂亮样例

生成模型容易出现 demo bias：展示最好的几张图，而隐藏失败样例。研究报告应至少覆盖：

1. prompt 遵循：对象、属性、数量和关系是否出现；
2. 图像质量：清晰度、结构、细节和伪影；
3. 多样性：相同条件下是否只复制一种构图；
4. 稳定性：随机种子、分辨率和长 prompt 改变时是否退化；
5. 安全：隐私、版权、危险内容和深伪风险；
6. 成本：采样步数、显存、延迟和失败重试。

FID、CLIP 相似度和人工偏好各自只测一部分。指标提高不能自动证明用户任务完成。

## 9.9 Latent Diffusion、DiT 与条件控制

### 9.9.1 为什么在 latent space 里扩散

像素空间的高分辨率图像维度很大。Latent Diffusion 先用 autoencoder 的编码器 E 把图片映射到 latent：

~~~math
z
=
E(x),
\qquad
\hat{x}
=
D(z)
~~~

扩散过程在 z 上进行，最后通过解码器 D 恢复图像。若图像每个空间维度压缩 r 倍，理想化情况下 latent 空间的空间位置数约变为原来的 `1/r^2`。这能显著降低 U-Net 或 Transformer 的计算。

代价是压缩器决定了哪些细节被保留。如果 autoencoder 对文字、细线和手部结构重建不好，后面的 diffusion 再强也无法恢复已经丢失的信息。评价 latent diffusion 时，要分别测压缩重建误差和生成误差。

### 9.9.2 DiT 把扩散 backbone 变成 Transformer

Diffusion Transformer 把 latent 切成 token，使用 Transformer block 预测噪声或其他去噪参数。它可以复用 attention、并行训练和规模扩展的工程经验，但 token 数、分辨率、时间步和条件长度仍决定计算量。

“用 Transformer”不是自动优于 U-Net。U-Net 的多尺度卷积结构对局部空间细节有明确归纳偏置，DiT 的优势可能来自规模、训练 recipe 或硬件效率。公平比较必须固定 latent 压缩、采样步数、数据和参数预算。

### 9.9.3 控制条件和控制强度

文本条件、边缘图、深度图、姿态、参考图和局部 mask 都可以作为条件输入。条件控制通常在保持生成自由度与遵守输入约束之间折中：

- 条件太弱，结果不遵守结构；
- 条件太强，结果缺少多样性或产生伪影；
- 条件编码器与主模型分布不匹配，可能出现局部正确、整体不一致；
- 多个条件冲突时，优先级和融合方式必须明确。

控制模型的实验不能只展示一张“输入到输出”的图。应做条件强度扫描、冲突条件、空条件和跨域测试，分析模型到底使用了哪一个条件。

## 9.10 视频生成：空间质量和时间一致性的联合问题

### 9.10.1 为什么逐帧生成会失败

独立生成每一帧可以得到清晰图片，却无法保证同一人物的身份、物体的形状、背景纹理和光照在时间上稳定。常见现象包括闪烁、身份漂移、物体突然出现、运动方向改变和接触关系不合理。

视频模型需要同时建模：

1. 单帧空间结构；
2. 相邻帧运动；
3. 遮挡和重新出现；
4. 镜头运动；
5. 长时间事件和因果关系。

这使数据、模型、采样和评估都比图像生成更复杂。

### 9.10.2 视频 token 和计算账本

设视频有 T 帧，每帧被编码为 H×W 个空间位置，若每个时空位置都对应一个 token，则 token 数近似为：

~~~math
N_{\mathrm{video\_token}}
\approx
T\times H\times W
~~~

实际模型可能有空间 patch、时间 patch、latent 压缩和局部注意力，因此 H、W 可能表示压缩后的空间格点。但无论采用哪种形式，帧数、分辨率和上下文长度都会增加计算与显存。

视频生成还要考虑输出存储、解码、后处理、审核和失败重试。只报告每秒生成速度而不报告分辨率、帧率、采样步数和成功率，不能形成可比较结论。

### 9.10.3 视频评估要区分四类质量

可以把评估拆为：

- 帧质量：清晰度、构图和局部细节；
- 文本遵循：对象、动作、场景和镜头是否符合条件；
- 时间一致：身份、背景、物体和运动是否稳定；
- 物理与事件：运动、接触、遮挡和事件顺序是否合理。

自动指标可以帮助筛选，但难以完整衡量物理合理性和叙事连续性。人工评估要定义盲评、随机化、评分维度和样本顺序，避免评审者被模型名称或样例质量影响。

### 9.10.4 视频生成不等于世界模型

视频生成模型能够预测视觉上 plausible 的后续画面，不代表它能在动作、反事实和长期规划中保持可验证的环境状态。世界模型通常还需要：

1. 明确的状态表示；
2. 动作条件和动作后果；
3. 反事实预测；
4. 长期一致性；
5. 对下游决策的可用性。

因此，“生成了很真实的视频”是视觉生成证据，不是完整世界建模能力的证明。

## 9.11 语音和音频模型：连续信号进入语言系统

### 9.11.1 ASR 的基本链路

自动语音识别通常把连续音频转为文本。一个典型链路是：

~~~text
波形
    -> 分帧和窗函数
    -> STFT/log-mel 特征或音频 token
    -> speech encoder
    -> CTC/attention decoder
    -> 文本、时间戳和置信信息
~~~

声学特征保留时间结构，但会受到采样率、噪声、混响、说话人重叠和端点切分影响。下游 LLM 看到的是 ASR 结果而不是原始声音，因此 ASR 错一个否定词、数字或人名，可能比普通拼写错误更严重。

### 9.11.2 Whisper 类 encoder-decoder

Whisper 代表一种大规模弱监督语音到文本路线：将音频特征输入 encoder，由 decoder 生成文本 token，并可扩展到多语言识别、翻译和时间戳。它的公开论文和模型资料能支持方法与评估条件的讨论，但具体模型大小、语言覆盖和部署质量必须绑定版本。

“能转写”也不代表“适合实时对话”。离线转写可以等待完整音频并使用更大上下文，实时系统还要处理 partial transcript、端点检测、用户打断、网络抖动和延迟上界。

### 9.11.3 WER 的定义与误读

给定参考文本长度 N，识别结果相对于参考文本的替换数 S、删除数 D、插入数 I，可以定义词错误率：

~~~math
\mathrm{WER}
=
\frac{S+D+I}{N}
~~~

WER 依赖分词、语言、标点和文本规范化。中文、英文、数字和专有名词的切分方式不同，跨语言直接比较 WER 会产生误导。语音助手还要额外评估关键字段准确率、数字准确率、说话人归属、首字延迟和完整端到端任务成功率。

### 9.11.4 Pipeline 和端到端语音对话

Pipeline 是 ASR -> LLM -> TTS，组件职责清楚、便于替换和审计，也容易出现误差累积和多段延迟。端到端系统可以直接在音频表示上建模对话和语气，潜在交互更自然，但训练数据、可解释性、工具协议和安全评估更复杂。

选择路线应看任务：

- 需要逐字稿、引用和合规审计时，pipeline 便于定位；
- 需要低延迟自然打断时，端到端或流式组件可能更有优势；
- 需要工具副作用时，无论哪种路线，都要把权限和执行确认放在模型之外。

## 9.12 文档、表格和图表：多模态系统中的结构化阅读

### 9.12.1 OCR 不是文档理解的终点

文档任务通常包含页面图像、文字、字体、坐标、阅读顺序、表格结构和跨页关系。OCR 只把像素转成文字，不能自动回答：

- 哪个数字属于哪个字段；
- 表格的行列关系是什么；
- 页眉是否是正文；
- 同一个合同条款是否跨页延续；
- 印章、手写批注和删除线是否改变语义。

一个较完整的文档流程是：

~~~text
页面渲染
    -> OCR/版面检测
    -> 区域与阅读顺序
    -> 表格/字段结构化
    -> 证据检索
    -> 模型推理
    -> schema 校验与人工复核
~~~

### 9.12.2 图表需要数据关系而不只是文字

图表理解要同时读取标题、坐标轴、图例、数据点、单位和趋势。仅把图表 OCR 成一段文本可能丢失二维关系；仅让模型看图又可能无法准确读取小数字。

对于金额、比例和趋势，推荐保留结构化中间结果：

~~~text
chart_id
    -> axis labels and units
    -> legend mapping
    -> extracted points
    -> calculation
    -> final claim
~~~

如果回答“第二季度比第一季度增长 12%”，应能追溯到两个数值、单位和计算过程。一个语言模型生成了正确数字，不代表它真的从图表读取了数字。

### 9.12.3 多模态 RAG 的证据对象

多模态检索可以返回图片区域、页面、OCR span、表格单元格、音频时间段和视频帧。每个证据对象至少应带：

- 文档或媒体 ID；
- 版本和访问权限；
- 页码、坐标或时间区间；
- OCR/ASR 版本；
- 内容摘要和原始引用；
- 是否包含不可信指令；
- 召回和重排分数。

权限检查必须发生在召回、缓存、上下文拼接和最终工具动作等多个边界。文档里的文字属于待分析数据，不能因为出现在高优先级上下文中就获得系统权限。

## 9.13 多模态评估：把能力拆成可验证维度

### 9.13.1 感知、理解、推理和生成分开测

建议至少建立以下维度：

| 维度 | 例子 | 主要指标 |
| --- | --- | --- |
| 感知 | OCR、物体、属性、计数 | 字符、对象和数量准确率 |
| 结构理解 | 表格、图表、版面 | 单元格、关系和字段 F1 |
| 空间关系 | 左右、前后、遮挡 | 关系准确率、定位质量 |
| 多证据推理 | 多图、跨页、图文结合 | 任务准确率和证据支持率 |
| 生成 | caption、图片、视频 | 人评、质量和条件遵循 |
| 语音 | ASR、翻译、说话人 | WER、关键字段和延迟 |
| 安全 | 隐私、注入、危险内容 | 漏报、误报、人工升级 |
| 系统 | 延迟、成本、可用性 | P50/P95、单位成功成本 |

通用 VQA 分数只能覆盖其中一部分。一个模型可能在开放式回答上得分不错，却在小字体 OCR 或租户隔离上失败。

### 9.13.2 组合指标不能掩盖短板

如果各维度得分为 q_1 到 q_K，权重为 w_k，一个汇总分可以写成：

~~~math
Q_{\mathrm{overall}}
=
\sum_{k=1}^{K}w_kq_k,
\qquad
\sum_{k=1}^{K}w_k=1
~~~

这个公式方便排序，却会掩盖某一维度接近零的情况。高风险产品应把关键维度设为独立约束，并同时报告每个 q_k、置信区间、样本数和失败类型。权重必须来自业务风险和决策责任，不能为了榜单好看而事后调整。

### 9.13.3 证据支持率和任务成功率

设任务完成且答案正确的样本数为 N_success，全部任务数为 N，任务级成功率为：

~~~math
\mathrm{TaskSuccess}
=
\frac{N_{\mathrm{success}}}{N}
~~~

若正确答案还要求证据链完整，设正确且证据支持的数量为 N_supported_success，则：

~~~math
\mathrm{SupportedSuccess}
=
\frac{N_{\mathrm{supported\_success}}}{N}
~~~

这两个指标可能差距很大。模型猜对了金额但没有定位发票区域，可能算作 TaskSuccess，却不应算作 SupportedSuccess。产品发布要根据任务风险决定采用哪一个作为主要指标。

### 9.13.4 公开 benchmark 的证据等级

多模态 benchmark 适合提供共同入口，但不是现实能力的完整证明。可以把资料分成：

1. 原始论文：说明任务、数据和实验定义；
2. 官方数据或项目仓库：支持下载、评估脚本和版本；
3. 模型卡或官方报告：支持某个版本的自报结果；
4. 社区复测：提供补充线索，但条件可能不一致；
5. 产品展示：适合说明功能，不足以支持通用性能结论。

MMMU、MathVista、MME、OCRBench、HallusionBench、Video-MME 等项目各自覆盖不同能力。使用时要记录版本、语言、提示、图像预处理、是否允许工具、评审方法和污染风险。

### 9.13.5 评估器也会产生错误

如果用视觉不可见的文本评审器判断图像回答，评审器无法验证视觉证据；如果把图片和回答同时交给另一个多模态模型，评审器可能继承相同的视觉盲点。自动 judge 适合筛选和一致性比较，但高风险样本需要人工或领域专家复核。

评审器校准至少包括：

- 与人工金标的准确性；
- 对答案长度和风格的敏感性；
- 对图片分辨率和格式的敏感性；
- 对语言、文化和图像类型的偏差；
- 在对抗和反事实样本上的稳定性。

## 9.14 多模态安全、隐私和内容来源

### 9.14.1 图片和音频都是敏感输入

多模态输入可能包含人脸、证件号码、地址、屏幕内容、会议录音、儿童、医疗图像和内部文档。风险不只发生在模型输出：

1. 上传、预处理和缓存可能保存原始媒体；
2. OCR/ASR 中间结果可能比图片更容易搜索和复制；
3. 视觉 token 和 trace 可能进入日志；
4. 供应商、标注员和评估者可能接触原始内容；
5. 输出图像可能保留训练数据风格或个人特征；
6. 多租户缓存可能复用错误权限。

数据治理要说明保存对象、保存时间、访问主体、删除范围和派生 artifact。删除索引记录不等于删除 OCR、缩略图、备份、日志和模型上下文。

### 9.14.2 OCR prompt injection 是数据和指令混淆

图片中的文字可能是用户要识别的内容，也可能是恶意文档写入的指令。系统应把它当作不可信数据：

~~~text
用户指令 -> 任务目标
图片文字 -> 待识别/待引用内容
外部文档 -> 证据或风险信号
图片文字 -/-> 修改系统策略
OCR 结果 -/-> 获得工具权限
模型输出 -/-> 绕过服务端授权
~~~

防护不能只靠模型说“我不会执行图片中的指令”。服务端仍要隔离外部文本、限制工具权限、校验资源归属、记录证据来源，并在高影响动作前要求确认。

### 9.14.3 视觉安全判断的边界

图像分类器或多模态模型可以帮助筛选危险内容、个人信息和违规媒体，但分类置信度不是现实风险概率。误报可能阻碍求助、教育和正常医学场景，漏报可能让高影响内容进入后续动作。

安全评估应包含：

- 正常敏感样本；
- 轻微和边界样本；
- 多语言和文字嵌入图像；
- 多轮和工具组合；
- 隐私、版权和数据留存；
- 人工申诉和回滚。

### 9.14.4 生成内容的来源和水印

水印、元数据和内容来源标准可以帮助标记媒体来源，但它们不是事实真实性证明，也不能覆盖截图、转码和二次编辑的全部路径。安全说明要区分：

- 内容是谁生成的；
- 内容是否被修改；
- 内容中的事实是否真实；
- 处理过程是否有授权；
- 用户是否能查看来源和申诉。

一个媒体带有来源元数据，不代表其中的事件一定发生；没有元数据，也不自动代表它是伪造的。

## 9.15 把研究问题写成可证伪的主张

### 9.15.1 从“效果更好”改成可检查句子

“我们的方法效果更好”不是充分的研究主张。更可检查的句子应说明：

- 在什么任务和数据上；
- 相对于哪个 baseline；
- 改善哪个指标；
- 付出什么额外成本；
- 在什么条件下可能失效。

例如：

~~~text
在固定视觉编码器、语言模型、训练样本和推理分辨率的条件下，
将 256 个视觉 token 改为区域自适应的 384 个 token，
预计能提高小字体 OCR 的字段准确率，
但会增加首 token 延迟和显存占用。
~~~

这句话可以被实验支持或否证，而“更聪明”“更统一”“更强”不能直接测量。

### 9.15.2 主张账本

可以为每个研究项目建立主张账本：

| claim_id | 主张 | 预测 | 证据 | 未覆盖条件 |
| --- | --- | --- | --- | --- |
| C1 | 动态 token 提高 OCR | 小字样本字段准确率上升 | 配对测试和分辨率消融 | 手写、低对比 |
| C2 | 质量提升值得成本 | 单位成功成本不恶化 | 延迟、显存和成功率 | 峰值并发 |
| C3 | grounding 改善 | 支持率和反事实一致性上升 | 区域标注与成对样本 | 开放式描述 |

主张账本能防止研究报告只保留最漂亮的指标。每个 claim 都要有反例入口和证据责任。

### 9.15.3 新方法的贡献类型

多模态研究贡献可能来自：

1. 新模型结构；
2. 新连接或压缩机制；
3. 新数据或数据配方；
4. 新训练目标；
5. 新评估集或诊断工具；
6. 新系统和部署方法；
7. 对已知方法的边界、负结果或统一解释。

“使用了更大模型并得到更高分”可能是有效工程结果，但未必是方法贡献。研究判断要把容量、数据、计算、推理 scaffold 和核心机制分开。

## 9.16 Baseline、公平比较和单位成本

### 9.16.1 Baseline 要匹配问题而不是只匹配名称

一个强 baseline 应该在任务、数据和预算上与方法相邻。至少要记录：

- 模型和视觉编码器版本；
- 可训练参数和初始化；
- 训练数据、清洗和采样；
- 分辨率、视觉 token 数和上下文；
- 优化器、步数、随机种子和早停；
- 推理采样、工具和后处理；
- 评估集、评审器和统计方法。

如果新方法使用了更高分辨率、更多 OCR 数据和更长推理，却只与低分辨率旧 baseline 比较，结果不能归因到方法本身。

### 9.16.2 配对差异

对同一组样本，在 baseline 和变体上分别得到 M_i^b 和 M_i^v。单样本差异为：

~~~math
\Delta_i
=
M_i^v-M_i^b
~~~

平均配对差异为：

~~~math
\bar{\Delta}
=
\frac{1}{n}
\sum_{i=1}^{n}\Delta_i
~~~

配对比较能减少样本难度差异，但不能修复数据污染、评估器偏差或两个版本使用不同随机条件的问题。报告时还要看差异分布，而不是只报均值。

### 9.16.3 质量提升是否值得成本

设一个评估窗口内模型、工具、人工复核和存储的累计成本分别为 C_model、C_tool、C_review、C_storage，按预先定义的成功标准完成的任务数为 N_success，则单位成功任务成本可以写为：

~~~math
C_{\mathrm{success}}
=
\frac{
C_{\mathrm{model}}
+
C_{\mathrm{tool}}
+
C_{\mathrm{review}}
+
C_{\mathrm{storage}}
}{
N_{\mathrm{success}}
}
~~~

这里的成本和成功数必须来自同一个评估窗口；不能拿一次请求的成本除以另一批请求的成功数，也不能把“答案看起来正确”和“证据充分”混成没有定义的成功标准。一个模型把准确率从 90% 提升到 92%，如果延迟、人工复核和失败重试成本翻倍，产品选择未必应该偏向它。成本账本也要写清硬件、批量、缓存命中和失败重试条件。

## 9.17 Ablation：把机制贡献从混杂因素中分离出来

### 9.17.1 先写假设，再决定消融

消融不是把模块随便删掉，而是测试一个明确假设：

- connector 的非线性是否帮助细粒度视觉特征；
- 增加视觉 token 是否改善 OCR；
- 高分辨率是否只帮助小字而不帮助整体 caption；
- OCR 数据是否改善字段抽取；
- grounding loss 是否减少视觉幻觉；
- 解冻 vision encoder 是否提高领域图像性能；
- 更长推理是否真的改善多图推理。

每个假设都要有正向指标、负向指标和预期失败模式。

### 9.17.2 2×2 设计和交互效应

假设因素 A 是“使用 grounding loss”，因素 B 是“使用高分辨率”，四组结果为 Y_00、Y_10、Y_01、Y_11。二者的交互效应为：

~~~math
I_{AB}
=
(Y_{11}-Y_{10})
-
(Y_{01}-Y_{00})
~~~

如果 I_AB 很大，说明 grounding loss 的收益依赖高分辨率，不能把两个因素的提升简单相加。只做“完整模型”和“去掉一个模块”可能看不到这种依赖。

### 9.17.3 多模态消融的常见维度

一个完整的消融矩阵可以包含：

| 因素 | 变体 | 需观察的副作用 |
| --- | --- | --- |
| encoder | CNN、ViT、不同预训练来源 | 领域迁移和细节 |
| connector | linear、MLP、query 压缩 | token、OCR、延迟 |
| 分辨率 | 低、中、高或动态 | 小字、成本、显存 |
| token 数 | 固定、区域自适应 | 长上下文和多图 |
| 数据 | caption、OCR、图表、交互 | 泛化和污染 |
| 参数冻结 | 只训 connector、LoRA、全参 | 遗忘和稳定性 |
| 目标 | caption、grounding、偏好 | 流畅、证据和误拒 |

如果同时改变三行因素，结果只能说明“配方发生变化”，不能说明哪一项有效。

### 9.17.4 消融也要有失败样本

完整模型平均分上升，可能只是容易样本提高。应保留按错误类型分桶的结果，例如小字体、遮挡、手写、跨页、长视频、低信噪比和多语言。一个模块如果只改善 caption，却损害表格和安全任务，结论要明确写成分布变化，而不是总分提升。

## 9.18 复现实验：从运行成功到主张复现

### 9.18.1 四个复现层级

复现“代码能运行”只是最低层级：

1. 运行复现：代码、依赖和权重能启动；
2. 数值复现：关键指标落在合理容差内；
3. 机制复现：改变核心因素时出现同方向的行为；
4. 主张复现：论文的主要结论在明确条件下仍成立。

论文没有公开数据、权重或精确预处理时，不能把替代实现写成直接复现。应标注复现层级和差异。

### 9.18.2 实验 manifest

每次实验至少保存：

~~~text
model_revision
vision_encoder_revision
tokenizer_and_template
data_snapshot_and_filter
image_resolution_and_token_budget
trainable_parameter_scope
optimizer_and_schedule
seed_and_hardware
inference_sampling
evaluation_split_and_judge
raw_outputs_and_failure_buckets
~~~

多模态项目尤其要保存图像解码库、颜色空间、EXIF 方向、字体渲染、视频抽帧和音频重采样版本。看似无关的预处理差异，可能改变 OCR、颜色、时间戳和模型输入长度。

### 9.18.3 最小复现路径

大项目不应一开始就跑全规模。可以按四步缩小：

1. 单样本 smoke test：确认图片、模板、mask 和输出可对齐；
2. 小数据过拟合：确认 connector 或训练目标能学到；
3. 小规模 holdout：检查是否只是记忆训练样本；
4. 扩大数据和模型：再比较性能、成本和稳定性。

如果第一步的图片 token 就错位，继续扩大训练只会得到更昂贵的错误。

## 9.19 负结果：把“没有提升”变成信息

### 9.19.1 先区分实现错误和假设错误

负结果的排查顺序可以从低成本、高概率问题开始：

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| loss 不下降 | mask、shape、学习率、dtype | 单样本梯度和中间张量 |
| 输出与图片无关 | placeholder、冻结范围、数据配对 | 图像替换和 attention 输入 |
| OCR 变差 | 分辨率、压缩、字体、token 合并 | 原图与裁剪对照 |
| 只在 benchmark 提升 | 污染、模板过拟合、评审偏差 | 时间切分和反事实 |
| 视频闪烁 | 时间建模、采样或数据帧 | 固定身份和运动测试 |
| ASR 词错但任务失败 | 数字、人名、否定词 | 关键字段指标 |
| 平均分不变 | 改善和退化互相抵消 | 错误类型分桶 |

实现排查完成后，才适合讨论模型假设是否不成立、规模是否不足或 baseline 是否更强。

### 9.19.2 负结果报告的结构

一份有价值的负结果报告应写明：

1. 原始主张和预期方向；
2. 实验条件和公平 baseline；
3. 观察到的结果和不确定性；
4. 已排除的实现问题；
5. 仍然可能的解释；
6. 哪个最小实验能区分这些解释；
7. 对原主张的修改。

“方法无效”通常太强。更严谨的说法可能是：“在固定数据、分辨率和参数范围的条件下，未观察到对小字体 OCR 的提升；结果不足以支持扩大 token 预算的成本收益主张。”

## 9.20 开放研究：从问题到实验优先级

### 9.20.1 三个层次

开放问题可以分为：

1. 诊断：当前系统到底在哪里失败；
2. 机制：为什么某种输入、架构或训练目标会改变失败；
3. 设计：怎样用最低成本改善关键失败。

先做诊断通常比直接发明新模块更有效。没有错误类型分布时，改 connector、改 loss 和扩大数据都可能只是猜测。

### 9.20.2 研究假设示例

以“图表问答不可靠”为例，可以提出：

- H1：低分辨率导致坐标轴和数据标签丢失；
- H2：OCR 文字保留了数字，却丢失了二维图例关系；
- H3：语言模型根据问题模板补全趋势，没有检查图像；
- H4：答案计算正确，但单位和证据引用缺失。

对应实验可以是：

- 分辨率和 crop 消融；
- 图像 token 与结构化 OCR 的对照；
- 反事实图表；
- 强制输出数据点和计算式；
- claim-level grounding 评估。

每个实验都要有区分假设的能力，不能所有假设都只测一个总分。

### 9.20.3 研究优先级

可以用一个教学性的优先级分数帮助排序：

~~~math
P_i
=
\frac{
\mathrm{Impact}_i
\times
\mathrm{Confidence}_i
\times
\mathrm{Coverage}_i
}{
\mathrm{Cost}_i
}
~~~

Impact 表示失败对任务的影响，Confidence 表示现有证据对假设的支持，Coverage 表示可能覆盖多少请求，Cost 表示实验和上线代价。它不是客观真理，但能迫使研究者把“有趣”与“值得先做”区分开。

## 9.21 综合案例：衡川合同助手的多模态证据链

### 9.21.1 场景和约束

“衡川合同助手”接收扫描合同、手机拍摄的票据和用户问题，帮助员工查找条款、抽取金额、比较两个版本并生成待审核摘要。它可以调用只读的文档检索工具，但不能自行提交报销、发送邮件或修改合同。

任务约束是：

- 合同和票据包含企业机密，按租户隔离；
- 关键金额必须能定位到页码和区域；
- 低清图片允许请求补拍或人工复核；
- 检索文档中的文字是不可信内容；
- 摘要不能把模型推断写成合同原文；
- 任何写操作都由业务系统和人工审批负责。

这个场景同时包含 OCR、版面、RAG、语言生成、证据链和安全。它不适合只用一个“视觉问答准确率”判断。

### 9.21.2 两个版本的教学对照

团队比较两个合成版本。版本 A 使用固定 224 分辨率和 256 个视觉 token；版本 B 对疑似小字区域进行 crop，并保留结构化 OCR span。两者使用相同语言模型、训练样本和离线请求，数字是教学构造：

| 指标 | 版本 A | 版本 B |
| --- | ---: | ---: |
| 字段值准确率 | 0.84 | 0.91 |
| 关键金额证据支持率 | 0.71 | 0.90 |
| 合同条款定位率 | 0.76 | 0.83 |
| P95 首 token 延迟 | 1.2 s | 1.9 s |
| 单任务估算成本 | 0.010 | 0.017 |
| 低清图片人工升级率 | 0.22 | 0.16 |

版本 B 的质量提升并不自动证明它值得上线。需要继续检查：字段准确率是否只来自容易样本，证据支持率的标注是否可靠，crop 是否把其他页面信息丢掉，延迟是否超过用户可接受范围，成本是否被缓存命中或失败重试低估。

### 9.21.3 红队和错误分析

审计发现三个组合失败：

1. 扫描件里的 OCR 文字包含“忽略系统规则”的内容，模型在摘要中复述了它；
2. 低清金额被模型从常见票据格式中补全，答案没有对应区域；
3. 旧版本合同仍在向量缓存中，用户权限变化后被错误召回。

它们分别属于不可信内容、视觉幻觉和缓存权限问题。单纯增加多模态指令数据不能修复第三个问题；增加拒答数据也不能代替服务端权限检查。

### 9.21.4 修复和回归

团队采取以下修复：

- OCR 文本带来源类型和区域 ID，只能作为待分析证据；
- 金额字段必须绑定 OCR span 或人工确认，缺证据时输出待复核；
- 缓存键加入租户、权限版本、文档版本和查询规范化；
- 对同一票据生成金额变体，检查模型是否随像素变化；
- 将摘要中的每个合同 claim 与原文区域关联；
- 将注入、越权缓存和无证据金额加入长期回归集。

修复后的发布结论应是条件性的：在注册租户、已覆盖的文档版本、预处理和评估分布内，三类故障未再复现；这不等于所有新扫描件、所有权限变化和所有模型版本都安全。

## 9.22 一个可运行的多模态评估小实验

下面的代码不读取真实图片，也不判断图片内容。它演示三个可复用的研究动作：计算对比学习损失、按任务统计正确性和 grounding、比较同一批样本的版本差异。样本标签已经由人工或独立评审产生。

~~~python
from dataclasses import dataclass
from math import exp, log
from typing import Sequence


def logsumexp(values: Sequence[float]) -> float:
    if not values:
        raise ValueError("values must not be empty")
    pivot = max(values)
    return pivot + log(sum(exp(value - pivot) for value in values))


def symmetric_clip_loss(
    similarity: Sequence[Sequence[float]],
    temperature: float,
) -> float:
    rows = [list(row) for row in similarity]
    size = len(rows)
    if size == 0 or any(len(row) != size for row in rows):
        raise ValueError("similarity must be a non-empty square matrix")
    if temperature <= 0:
        raise ValueError("temperature must be positive")

    logits = [[value / temperature for value in row] for row in rows]
    image_to_text = []
    text_to_image = []
    for index in range(size):
        image_to_text.append(
            -logits[index][index]
            + logsumexp(logits[index])
        )
        column = [logits[row][index] for row in range(size)]
        text_to_image.append(
            -logits[index][index]
            + logsumexp(column)
        )
    return (
        sum(image_to_text) + sum(text_to_image)
    ) / (2 * size)


@dataclass(frozen=True)
class EvalRow:
    task: str
    correct: bool
    grounded: bool
    latency_ms: float
    cost: float


def summarize(rows: Sequence[EvalRow]) -> dict[str, float]:
    if not rows:
        raise ValueError("rows must not be empty")
    if any(row.latency_ms < 0 or row.cost < 0 for row in rows):
        raise ValueError("latency and cost must be non-negative")

    count = len(rows)
    correct = sum(row.correct for row in rows)
    supported = sum(row.correct and row.grounded for row in rows)
    total_cost = sum(row.cost for row in rows)
    return {
        "task_success": correct / count,
        "supported_success": supported / count,
        "grounding_rate": sum(row.grounded for row in rows) / count,
        "p95_latency_ms": sorted(row.latency_ms for row in rows)[
            max(0, (95 * count + 99) // 100 - 1)
        ],
        "total_cost": total_cost,
        "cost_per_task_success": (
            total_cost / correct if correct else float("inf")
        ),
        "cost_per_supported_success": (
            total_cost / supported if supported else float("inf")
        ),
    }


def paired_delta(
    baseline: Sequence[EvalRow],
    variant: Sequence[EvalRow],
) -> float:
    if len(baseline) != len(variant) or not baseline:
        raise ValueError("paired inputs must have equal non-zero length")
    deltas = [
        int(new.correct and new.grounded)
        - int(old.correct and old.grounded)
        for old, new in zip(baseline, variant)
    ]
    return sum(deltas) / len(deltas)


similarity = [
    [0.90, 0.10],
    [0.20, 0.80],
]
clip_loss = symmetric_clip_loss(similarity, temperature=0.2)
assert 0.0 < clip_loss < 1.0

baseline = [
    EvalRow("ocr", True, True, 420.0, 0.009),
    EvalRow("chart", False, False, 480.0, 0.010),
    EvalRow("spatial", True, False, 390.0, 0.008),
    EvalRow("caption", True, True, 350.0, 0.007),
]
variant = [
    EvalRow("ocr", True, True, 610.0, 0.015),
    EvalRow("chart", True, True, 680.0, 0.017),
    EvalRow("spatial", True, True, 590.0, 0.014),
    EvalRow("caption", True, True, 530.0, 0.012),
]

base_summary = summarize(baseline)
variant_summary = summarize(variant)
delta = paired_delta(baseline, variant)

assert round(base_summary["task_success"], 3) == 0.75
assert round(base_summary["supported_success"], 3) == 0.5
assert round(variant_summary["supported_success"], 3) == 1.0
assert round(base_summary["cost_per_supported_success"], 3) == 0.017
assert round(variant_summary["cost_per_supported_success"], 3) == 0.014
assert round(delta, 3) == 0.5
print({
    "clip_loss": round(clip_loss, 3),
    "baseline": base_summary,
    "variant": variant_summary,
    "supported_success_delta": round(delta, 3),
})
~~~

这里的 `supported_success` 只把“正确且有证据支持”的样本计入成功，因此它可能低于普通 task success。示例中版本 B 的总成本更高、延迟更长，但按 supported success 计算的单位成功成本反而更低；这只是四个教学样本的结果，不能替代更大样本、置信区间和失败重试统计。代码中的 P95 只是一个不插值的教学实现，生产统计应明确分位数算法、样本量和时间窗口。真正的多模态评估还需要保存图片版本、预处理、标注指南、区域证据和评审分歧。

## 9.24 章末练习：把知识变成可检查的研究

### 练习一：计算视觉 token 预算

比较 224、336 和 448 分辨率在 patch size=16 时的视觉 token 数。假设文本和工具 token 不变，讨论哪一种任务适合高分辨率，哪一种任务更需要多图上下文。不要只比较质量，还要估算上下文和 prefill 的变化。

### 练习二：实现并验证 CLIP 损失

用两个图文对构造相似度矩阵，手算温度参数变化对 softmax 分布的影响，再用本章代码验证。增加一个假负样本，观察 loss 如何变化，并说明这个变化是否代表模型真的变差。

### 练习三：设计 VLM connector 消融

固定 vision encoder、语言模型、数据和推理条件，只比较 linear、MLP 和 query 压缩。为 OCR、caption、grounding、TTFT 和显存分别写出指标和预期副作用。若无法获得区域标注，说明如何用反事实图片替代一部分 grounding 证据。

### 练习四：构造图表反事实

制作四对只改变一个数字或图例位置的图表。要求模型回答趋势、数值和计算式，记录答案是否随视觉事实变化。将“答对了”与“引用了正确数据点”分开统计。

### 练习五：写一个可证伪主张

选择“增加视觉 token”“加入 OCR 数据”或“加入 grounding loss”中的一个，写出固定条件、预测指标、成本指标、失败模式和未覆盖场景。不能使用“更强”“更智能”“更稳定”作为唯一结论。

### 练习六：复盘一个负结果

假设高分辨率使 OCR 提升，但总体 VQA 不变且延迟增加一倍。写出三种可能解释和最小区分实验，再决定是否值得在生产中启用动态分辨率。

## 9.25 结语：多模态能力要靠证据链成立

多模态模型的核心不是把所有输入都变成 token，而是让表示保留任务真正需要的证据，让融合过程能使用这些证据，让输出可以被验证，让系统在看不清、听不清、证据冲突或权限不足时承认边界。

CLIP 说明跨模态对齐如何建立共享空间；VLM 说明视觉表示如何进入语言生成；diffusion 说明条件生成如何从噪声恢复数据；视频和语音说明时间结构会带来新的计算与评估问题；文档和多模态 RAG 说明证据区域、权限和来源不能被自然语言摘要替代。

研究判断则要求把每个结论写成可证伪主张，用公平 baseline 和消融分离因素，用复现实验确认机制，用负结果修正假设，并把质量、延迟、成本、安全和证据支持放在同一本账上。一个漂亮 demo 可以成为研究入口，但只有可复核的输入、条件、指标、失败样本和资料边界，才能成为可靠结论。
