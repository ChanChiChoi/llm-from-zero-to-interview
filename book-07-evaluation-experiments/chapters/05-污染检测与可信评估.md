# 第五章：污染检测与可信评估

一个 benchmark 分数高，并不一定表示模型真正掌握了被测能力。模型也可能见过
原题、答案、解析、相同模板，或者在开发过程中反复看过这批题，逐渐学会了
如何迎合评估器。对 RAG 系统来说，评估答案甚至可能已经被写进检索库；对
Agent 来说，历史工具轨迹和最终状态也可能回流训练数据。

这类问题通常被称为 data contamination、benchmark contamination 或 benchmark
leakage。它们的共同点不是“数据重复”四个字，而是评估样本的信息通过某条路径
进入了被评系统、评估 prompt、检索库、judge 或模型选择过程，使分数不再代表
对新样本的泛化能力。

可信评估不能承诺绝对没有污染。预训练语料往往无法完全取证，公开网页会不断
复制，模型训练截止时间也可能不透明。更实际的目标是：明确威胁模型，尽可能
检测已知路径，隔离最终 holdout，保存数据血缘，做时间和扰动验证，并在报告中
诚实写出仍然无法排除的风险。

## 1. 先理解“污染”到底改变了什么

### 1.1 小白视角：会做题还是见过题

假设考试题是：

~~~text
某公司的报销政策规定，超过 5000 元需要部门负责人审批。请判断 6000 元报销还需要什么。
~~~

模型答对有两种完全不同的原因。第一种是它读懂了题目中的金额和条件，能够把
规则迁移到新的表达；第二种是训练数据里已经出现过同一题、答案或课程解析，
模型只是在复现熟悉的字符串。

如果把这两种情况都记为一次正确，分数就会高估模型在新政策、新金额和新句式
上的能力。轻微改写题目、替换数字或更换上下文后，记忆型回答可能迅速下降。

### 1.2 专家视角：污染是信息流问题

设评估样本为：

~~~math
e_i=(q_i,a_i,m_i,t_i,u_i)
~~~

`q_i` 是问题或输入，`a_i` 是参考答案、rubric 或期望行为，`m_i` 是任务、语言、
风险、来源、版本等元数据，`t_i` 是产生或发布的时间，`u_i` 是使用记录，例如
是否进入训练、prompt 调参、模型选择、RAG 知识库或 judge 校准。

对某个系统而言，评估信息可能沿着下面的路径流动：

~~~text
公开题目/答案
  -> 预训练语料
  -> SFT、偏好或 RL 数据
  -> 模型权重

评估样本
  -> prompt 调参和模型选择
  -> 固定模板或规则

测试文档/参考答案
  -> RAG 索引、缓存、system prompt
  -> 被评系统直接取回

线上评估请求
  -> 日志、回流训练、错误修复
  -> 后续版本
~~~

任何一条路径都可能让最终测试不再是“模型面对未知样本的表现”。因此污染检测
既是文本相似度问题，也是数据治理、权限、时间和实验设计问题。

### 1.3 五种信息泄漏

可以先按进入位置区分：

1. **权重泄漏**：题目或答案出现在预训练、SFT、偏好或强化学习数据中；
2. **上下文泄漏**：答案进入 RAG、system prompt、few-shot 示例或缓存；
3. **调参泄漏**：团队反复查看测试结果，调整 prompt、阈值、检索器或解码参数；
4. **评估器泄漏**：judge 的参考答案、rubric 或样本被用于调它自己；
5. **反馈泄漏**：线上评估日志、bad case 和人工标签回流到后续训练或规则。

这五种情况的证据强弱不同。发现 exact duplicate 是直接证据；看到行为异常
只能说明风险，不能单凭一个高分断言模型一定看过原题。

## 2. 为评估集建立数据血缘

### 2.1 样本最小记录

每条评估样本至少应该保存：

~~~text
sample_id
input_and_context
reference_or_rubric
source_type
source_uri_or_document_id
created_at
published_at
dataset_revision
split
privacy_class
training_usage
tuning_usage
retrieval_usage
judge_calibration_usage
access_log_reference
~~~

字段的目的不是制造管理负担，而是让团队能够回答：“这条题什么时候产生，谁
看过，是否进入过训练或 RAG，当前属于哪个 split？”如果这些问题无人能回答，
最终分数就缺少数据来源证据。

### 2.2 训练截止时间不是一个模糊日期

记录 `train_cutoff` 时，要区分：

1. 预训练语料的截止时间；
2. SFT 数据的截止时间；
3. 偏好和 RL 轨迹的截止时间；
4. 模型 checkpoint 的发布时间；
5. 评估所使用的 RAG 文档快照时间；
6. prompt、judge 和阈值最后调整时间。

一个模型可能预训练截止于 2024 年，却使用 2025 年的 SFT 数据；一个产品模型
权重不变，线上 RAG 却能读到 2026 年的政策。只记录一个“知识截止日期”，会
把这些不同的信息路径混为一谈。

### 2.3 访问权限和分层

评估数据可以分成：

~~~text
dev：日常调试，可以查看
validation：模型选择和 prompt 试验
public_report：可公开比较，但默认存在污染风险
private_holdout：受限访问，只在计划中的评估中使用
canary：少量独特哨兵样本，单独控制
~~~

private holdout 不是“把文件藏在某个目录”这么简单。需要限制读取权限、记录
访问、分离训练和评估服务账号，并让评估脚本输出聚合结果而不是原题。否则
开发者仍然可以通过日志或异常输出逐题恢复 holdout 内容。

### 2.4 开发反馈也会造成污染

即使测试题从未进入模型权重，只要团队反复查看“这道题错了”，并围绕它修改
prompt 或规则，测试集就已经参与了模型选择。它仍可以用于历史回归，但不能
再被称作完全独立的最终证据。

因此应保存 `used_for_tuning`、模型候选版本、查看时间和修改记录。评估结果
越频繁地指导系统变化，越需要刷新 holdout 或引入新鲜时间切分集。

## 3. 污染类型：从重复文本到行为过拟合

### 3.1 Exact duplicate

最直接的污染是评估文本经过规范化后，和训练或调参语料中的文本完全相同。
例如题目、答案和解析作为一整段出现在网页或代码仓库中。

对文本 `x` 做规范化函数 `\nu(x)`，再计算哈希：

~~~math
h(x)=\mathrm{hash}(\nu(x))
~~~

训练和评估语料的哈希集合分别记为 `H_{\mathrm{train}}` 和 `H_{\mathrm{eval}}`，
exact 重复集合可写成：

~~~math
\mathcal D_{\mathrm{exact}}
=
\{e_i:h(q_i,a_i)\in H_{\mathrm{train}}\}
~~~

规范化可以处理大小写、连续空白、Unicode 等价形式、HTML 标签和代码格式；
但不能随意删除会改变含义的标点、数字、变量名或否定词。规范化函数也要
版本化，否则同一批数据在不同脚本下会得到不同重复率。

### 3.2 Answer leakage

题干没有被完整复制，答案、解析、测试用例或隐藏规则却进入了训练数据，也会
造成污染。数学题可能泄漏详细推导，代码题可能泄漏函数签名、单元测试和参考
实现，安全题可能泄漏攻击 prompt 与标准拒答。

因此至少要分开检查：

1. 输入文本；
2. 参考答案；
3. 解析和评分标准；
4. 代码测试与函数签名；
5. 评估器 prompt 和错误标签。

只对题面做 exact match，可能错过答案泄漏。

### 3.3 Near duplicate

近重复样本经过改写、翻译、变量名替换或格式变化，表面不同但仍保留大量
可复用信息。它比 exact duplicate 更常见，也更依赖阈值和人工复核。

### 3.4 Template or distribution leakage

模型可能没有见过具体题目，却见过同一生成模板、相同字段顺序和相同答案模式。
例如所有数学题都以“先列出三个步骤，再给最终答案”生成，训练数据也反复使用
这一模板；模型学会格式后，分数可能高于真实迁移能力。

### 3.5 Evaluation feedback leakage

团队每轮都查看同一 test set，修改 prompt、few-shot、检索排序、拒答规则和
解码温度。这种信息会进入系统配置，即使权重没有改变，最终分数也会被开发
过程优化。

### 3.6 RAG and cache leakage

评估问题、参考答案、gold 文档、judge 解释和历史输出可能进入向量库、全文索引、
prefix cache 或 system prompt。模型在评估时检索到答案，不代表它具有更好的
检索和推理能力；它可能只是读到了不该公开的评估材料。

## 4. Exact duplicate 检测

### 4.1 规范化与哈希

一个最小流程是：

~~~text
读取原始记录
  -> 按字段分别规范化
  -> 生成 input、answer、full-record 多个指纹
  -> 与训练/SFT/preference/RAG/prompt 快照比对
  -> 保存命中来源和处理动作
~~~

使用多个字段指纹很重要。若把题目和答案拼成一段，题目相同但答案不同的情况
可能被掩盖；如果只看答案，又可能漏掉相同题面和不同格式的解析。

exact 指示量可写成：

~~~math
I_{\mathrm{exact}}(e_i)
=
I\left(h(\nu(e_i))\in H_{\mathrm{source}}\right)
~~~

其中 `H_{\mathrm{source}}` 应按来源桶分开保存，例如 pretrain、SFT、preference、
RAG、prompt_dev 和 public。命中来源比一个 `true` 更有价值，因为不同来源
决定不同的处理方式。

### 4.2 规范化的边界

可以安全处理的变化包括多余空白、HTML 包装、Unicode 规范形式和大小写；需要
谨慎处理的变化包括：

1. 数字和单位；
2. 否定词和比较词；
3. 代码变量名和字符串常量；
4. 中文标点与句子边界；
5. 表格列顺序和 JSON 字段顺序。

如果规范化把“不能退款”变成“能退款”的等价表示，污染检测会产生严重误判。
规范化脚本需要单元测试和 revision，不能当作无害的字符串清洗。

### 4.3 Exact 检测的边界

exact match 具有低误报、易解释的优势，却只能发现完全重复。题目换一个数字、
答案改一个词、代码变更变量名或网页加入模板包装，都可能绕过 hash。因此
exact 命中可以作为强污染证据，exact 未命中不能作为干净证明。

## 5. Near duplicate 检测

### 5.1 Shingle 和 Jaccard

把规范化文本拆成长度为 `n` 的字符或 token shingle，记集合为 `G_n(x)`。两个
文本的 Jaccard 相似度为：

~~~math
J_n(x,y)
=
\frac{|G_n(x)\cap G_n(y)|}
{|G_n(x)\cup G_n(y)|}
~~~

`J_n=1` 表示 shingle 集合完全相同，`J_n=0` 表示没有交集。它能发现大量
局部相同文本，但会受到文本长度、常见模板和短样本的影响。

### 5.2 MinHash 和 LSH

当训练语料和评估集很大时，不可能逐对计算 Jaccard。MinHash 用多个哈希函数
把 shingle 集合压缩成 signature，LSH 再把可能相似的 signature 放入同一桶，
只对候选对精算相似度：

~~~text
规范化 -> shingling -> MinHash signature -> LSH candidate bucket -> 精确复核
~~~

它是效率优化，不改变“最终相似度阈值需要按数据类型解释”的事实。bucket 命中
只是候选风险，不应直接当作确定污染。

### 5.3 SimHash

SimHash 将文本特征映射到固定长度指纹，语义或词面相近的文本通常有较小汉明
距离。它适合网页和长文去重，但对很短的题目、数字变化和代码语义差异需要
额外规则。SimHash 距离阈值同样必须通过人工抽样校准。

### 5.4 Embedding similarity

Embedding 能发现改写、翻译和语序变化，但语义相似不一定等于训练泄漏。两个
题目都问“什么是 attention”可能只是共享常识主题；一个评估题和训练题拥有
相同约束、答案和陷阱，才更值得怀疑。

可以把最大相似度写成：

~~~math
c_i
=
\max_j\operatorname{sim}(\nu(e_i),\nu(d_j))
~~~

如果 `c_i` 超过经人工校准的阈值 `\tau`，应标记为风险候选，保留相似来源、
相似度、方法和人工判定。阈值不是自然常数，短题、代码、数字、模板和多语言
需要不同的误报/漏报权衡。

### 5.5 代码和数学的近重复

代码不能只看字符相似度。可以分别检查 token 序列、AST 结构、变量重命名后的
结构、函数签名、隐藏测试和参考实现来源；数学题要检查数字替换、公式结构、
解题模板和解析文本。结构相似说明可复用信息相似，却仍要结合时间和来源判断
是否真的进入训练链路。

### 5.6 人工抽检和阈值校准

从高相似、中相似和低相似桶各抽取样本，由熟悉领域的人判断：

1. 确定重复；
2. 共享公共知识；
3. 共享模板但不共享解法；
4. 语义相近且可能泄漏；
5. 误报。

用这批标签估计不同阈值下的 precision、recall 和处理成本，再选择适合当前
风险的阈值。一个面向安全 benchmark 的阈值，通常应比普通文风评估更保守。

## 6. 时间切分：降低而不是消除污染

### 6.1 基本做法

时间切分使用模型和系统真正使用的数据截止时间之后产生的样本。例如预训练
语料截止到 2025-12-31，可以选择 2026 年之后新产生的政策、issue、新闻或
产品文档作为一部分评估集。

但要同时记录后训练、检索库和 prompt 调参的截止时间。一个模型可能在 2025 年
以后通过 SFT 学到新数据；一个权重不变的 RAG 产品也可能直接检索到 2026 年
评估文档。

### 6.2 时间条件

若评估样本产生时间为 `t_i`，相关训练和调参数据的截止时间为 `T_{\mathrm{cut}}`，
最基本的时间筛选是：

~~~math
I_{\mathrm{fresh}}(e_i)
=
I(t_i>T_{\mathrm{cut}})
~~~

它只是降低样本在时间上被看过的可能，不是“未污染”的证明。公开网页可能在
样本产生后被复制到旧数据源，训练日期也可能只是一方自报值。

### 6.3 适合时间切分的任务

时间切分尤其适合：

1. 新政策和产品文档问答；
2. 新软件版本的 issue 和代码修复；
3. 新闻、市场或科技事实；
4. 新论文理解；
5. 持续变化的客服和运维请求。

对纯数学定理和长期不变的基础知识，时间新鲜度不能单独解决题面或解析泄漏。

### 6.4 时间切分的陷阱

常见陷阱包括：

1. 评估题虽然新，题型模板却长期不变；
2. 新文档来自旧公开政策的改写；
3. 评估集在发布后进入日志和训练回流；
4. 时间戳是上传时间，不是模型实际可见时间；
5. 团队在正式报告前已经查看并调参。

因此报告应给出样本产生、公开、采集、训练、调参和评估的多个时间字段。

## 7. Canary：检测链路中的意外记忆

### 7.1 Canary 是什么

canary 是为检测泄漏而构造的独特哨兵样本或短语。它不应该是真实密码、个人
隐私或生产秘密，而应该是无业务意义、可撤销、可追踪的字符串。例如：

~~~text
quartz-harbor-4821
~~~

可以把它放进受控的测试数据、日志、临时检索库或训练实验中，然后在不应看到
它的系统路径上检查是否出现。canary 的价值在于给某条数据流加一个容易辨认
的标记，而不是证明模型拥有一般记忆能力。

### 7.2 Canary 的检测对象

不同放置位置回答不同问题：

| 放置位置 | 检测目的 |
| --- | --- |
| 训练实验的受控样本 | 观察训练、checkpoint 和发布链路是否带入字符串 |
| 日志回流样本 | 观察线上日志是否进入后续训练或检索 |
| RAG 隔离库 | 观察索引、权限和路由是否串库 |
| hidden holdout | 观察评估脚本、缓存或开发流程是否泄漏题目 |

不能把不同位置的 canary 结果混成一个“记忆率”。每个 canary 都应有 placement、
访问权限、预期可见范围和撤销时间。

### 7.3 Canary 泄漏率

设不应看到 canary 的检测场景数为 `N_{\mathrm{canary}}`，实际出现或被正确复现
的场景数为 `N_{\mathrm{seen}}`，可写成：

~~~math
R_{\mathrm{canary}}
=
\frac{N_{\mathrm{seen}}}{N_{\mathrm{canary}}}
~~~

`N_{\mathrm{canary}}` 为零时不能计算该比例，更不能把“没有放置 canary”解释成没有泄漏。
这个比例只描述被设计的哨兵是否穿过边界，不能外推成所有训练数据的污染比例。
canary 没有泄漏，也不能证明普通题目没有泄漏；canary 泄漏则说明至少有一条
数据、权限、缓存或模型路径需要调查。

### 7.4 Canary 的安全边界

canary 不能包含真实秘密，不能使用生产凭据，也不能让它本身成为公开 benchmark。
应限制读取、旋转字符串、记录访问和失效时间。若 canary 被公开，它会从检测
信号变成普通训练文本，之后的复现不再能区分记忆与公开学习。

## 8. 行为证据：从异常表现怀疑污染

文本比对经常不完整，尤其是闭源模型的预训练数据无法直接访问。这时可以观察
行为信号，但必须把它们称为风险证据，而不是确定取证。

### 8.1 异常高分

如果一个模型在公开 benchmark 上远高于同规模和相近训练路线的模型，却在私有
或时间切分集上没有相应提升，可能存在污染、题型过拟合、提示不公平或评估器
偏差。异常高分只说明值得调查，不能单独证明看过题。

### 8.2 复述独特错误

模型不仅答对，而且复现了参考解析中的不自然措辞、错误步骤或特定拼写，这比
单纯正确更值得关注。需要对比多个独立生成、轻微改写和新约束，排除题目本身
容易推出同一答案的情况。

### 8.3 扰动测试

对原题做保持能力不变的扰动：改写题干、替换变量名、替换数值、调整上下文顺序、
加入不相关干扰信息或改变格式。设原题得分为 `S_{\mathrm{orig}}`，扰动题得分为
`S_{\mathrm{pert}}`：

~~~math
\Delta_{\mathrm{pert}}
=
S_{\mathrm{orig}}-S_{\mathrm{pert}}
~~~

如果 `\Delta_{\mathrm{pert}}` 很大，可能说明模型依赖题面记忆、模板特征或某个
脆弱线索。但扰动也可能真的改变难度、语言自然度或证据完整性，所以需要人工
确认“等价难度”是否成立。

### 8.4 变体的构造原则

好的扰动应该只改变不影响目标能力的表面因素。例如代码题替换局部变量名，
数学题在保持结构的前提下替换数字，RAG 问题改变用户措辞但保留证据。不能把
关键条件删除后，再把分数下降解释为污染。

### 8.5 多次生成和记忆特征

对同一题使用多个随机种子，观察输出是否异常一致；检查答案是否包含训练集
独有的固定短语；比较有无参考答案、改变候选格式和更换上下文后的表现。每个
现象都有其他解释，行为分析应该产生“待核验样本列表”，而不是直接宣布模型
作弊。

## 9. 可信评估的设计

### 9.1 私有 holdout

最终 holdout 应尽量不参与日常 prompt、阈值、模型选择、检索器和 judge 调整。
查看权限越少，独立性越强；但仍需保留聚合结果、访问审计和可复现实验入口。
历史 holdout 被反复查看后，应降级为回归集，并刷新一批新样本。

### 9.2 多源数据

一套可信评估通常组合：

1. 公开 benchmark：提供社区可比性，但污染风险高；
2. 私有业务集：贴近产品分布，但代表性和标注成本要审计；
3. 时间切分集：降低已知训练污染，但样本可能模板相似；
4. 专家构造集：覆盖边界和风险，但可能脱离真实用户表达；
5. 历史 bad case：直接检验修复效果，但不能估计总体平均质量；
6. 动态新样本：保持新鲜，但版本和标注需持续维护。

这些来源应分开报告，不要在总分里无说明地混合。

### 9.3 公开 benchmark 的正确用法

公开集仍然有价值：它能提供共同语言、历史趋势、任务定义和公开 runner。使用
时要注明公开时间、可能的训练暴露、模型是否有机会调参、题目版本和评分脚本。
公开高分更适合产生假设和比较已知协议，不应自动转成产品质量承诺。

### 9.4 评估集生命周期

评估集可以经历：

~~~text
设计 -> pilot -> 开发使用 -> 受控保留 -> 发布报告 -> 历史回归 -> 刷新或退役
~~~

同一题在生命周期不同阶段的证据含义不同。开发阶段发现的题可以帮助修复
系统；进入最终报告后，应限制再次查看；长期公开后，污染风险上升，需要加入
新题或标记为历史可比集。

### 9.5 可信度不是单一布尔值

可以把报告分成独立信号：

~~~text
exact duplicate evidence
near duplicate evidence
time freshness
training and tuning lineage
RAG isolation
holdout access
perturbation stability
behavioral anomaly
human audit coverage
~~~

每个信号都保留数值、样本量、方法、阈值和不确定性。这样即使某个来源无法
取证，读者仍然知道结论依赖哪些证据，而不是看到一个不可解释的总标签。

## 10. 任务类型的污染风险

### 10.1 选择题和知识 benchmark

题面、选项、答案和解析很容易在网页、课程、GitHub 和论文中传播。应使用私有
变体、答案顺序随机、时间切分和新题，并记录模型是否有公开答案可见机会。

### 10.2 数学推理

数学题可能泄漏题面、数值、完整解析、公式模板和最终答案。变换数字只能检验
一部分迁移，还要检查解题过程、等价题质量和 verifier。若变换数字后题目难度
变化很大，分数差不能直接解释为记忆。

### 10.3 代码生成

代码任务的风险来源包括公开函数签名、issue、单元测试、参考实现、仓库历史
和评估 harness。检测需要结合代码 token、AST、变量重命名、隐藏测试和时间版本；
只对 prompt 做文本去重远远不够。

### 10.4 RAG 和文档问答

评估问题、gold 文档、参考答案、旧版本政策、引用段落和评审说明都可能进入
检索库。应隔离评估索引和生产索引，记录检索 trace、文档 revision、权限过滤
和缓存命中。评估集不应因为“内部可见”就自动成为生成上下文。

### 10.5 安全和红队

公开攻击 prompt 容易被模型针对性记忆，产生“只会拒绝已知模板”的假安全。应
使用动态攻击、改写、跨语言、工具注入和多轮变体；同时测量良性请求的错误拒答，
否则安全分数可能只是拒答率上升。

### 10.6 多模态和语音

图像、音频和视频 benchmark 的泄漏不只发生在文字描述中，也可能发生在图片
文件、OCR 转写、字幕、帧样本、音频片段和标注文件。需要保存媒体 hash、来源、
抽帧策略、转写版本和训练可见性；文字题面干净不代表媒体内容干净。

## 11. 可信评估报告如何写

### 11.1 报告最小字段

一份可信报告至少说明：

~~~text
评估目标和被测系统边界
模型、prompt、工具、检索器和 judge revision
样本来源、版本、时间范围和切片
exact/near duplicate 方法与阈值
训练、后训练、调参和 RAG 的数据血缘
holdout 访问和使用记录
时间切分与扰动设计
canary placement 和观测结果
人工/judge/程序判定的分工
统计区间、样本量和成本
残余污染风险与不能确认的部分
结论、反例和下一步验证
~~~

### 11.2 把“未发现”与“证明没有”分开

报告应使用准确措辞：

~~~text
在可访问的训练、SFT、RAG 和调参快照中未发现 exact duplicate。
对公开网页的 near-duplicate 检查发现 3 条待人工复核样本。
由于闭源预训练语料不可见，无法证明不存在历史暴露。
时间切分和私有 holdout 提供了额外独立证据，但仍存在模板泄漏风险。
~~~

“未发现”是搜索范围内的结果；“没有污染”是通常无法由有限检查证明的强结论。

### 11.3 一个报告案例

~~~text
本次评估使用 60% 私有业务样本、20% 时间切分样本、10% 历史 bad case 和 10% 公开 benchmark。
公开 benchmark 仅用于社区可比性，不作为产品质量的唯一依据。
对可访问的 pretrain、SFT、preference、RAG 和 prompt_dev 快照做了 exact hash
与 shingle 检测，并对超过阈值的样本进行人工复核。
最终 holdout 未用于 prompt、阈值或模型选择；访问通过聚合 runner 记录。
残余风险：无法完整确认闭源预训练阶段是否见过部分公开题，且模板级泄漏只能
通过扰动和新鲜样本间接观察。
~~~

这段话没有把不确定性隐藏起来，却给出了读者判断结果所需的证据范围。

## 12. 一个可运行的污染检测诊断 demo

下面的 demo 不调用模型，也不依赖外部库。它处理一个 toy 评估集，检查规范化
exact hash、字符 shingle Jaccard、时间切分、canary、prompt 调参反馈、扰动
分数和 manifest。数据故意包含几类问题，目的是演示如何保留来源、信号和
后续动作，而不是宣称某个阈值适用于所有数据。

~~~python
from datetime import date
from pprint import pprint
import hashlib
import re


train_cutoff = date.fromisoformat("2025-12-31")
near_threshold = 0.20
perturb_threshold = 0.25
canary_phrases = ["quartz-harbor-4821"]

corpus = [
    {
        "id": "train_001",
        "bucket": "pretrain",
        "created": "2024-05-01",
        "text": "解释 Transformer attention 的核心直觉。Attention 是让 token 根据相关性汇聚信息。",
    },
    {
        "id": "sft_001",
        "bucket": "sft",
        "created": "2025-06-01",
        "text": "差旅报销需要提供发票和出差审批记录；超过 5000 元还需要部门负责人额外审批。",
    },
    {
        "id": "rag_001",
        "bucket": "rag",
        "created": "2026-01-15",
        "text": "内部评估 canary：quartz-harbor-4821 只应出现在隐藏测试集中。",
    },
    {
        "id": "dev_001",
        "bucket": "prompt_dev",
        "created": "2025-11-20",
        "text": "无答案问题必须拒答，不要编造政策；该规则来自日常调参样本。",
    },
]

eval_samples = [
    {
        "id": "eval_exact",
        "task": "qa",
        "risk": "normal",
        "created": "2024-06-01",
        "question": "解释 Transformer attention 的核心直觉。",
        "answer": "Attention 是让 token 根据相关性汇聚信息。",
        "used_for_tuning": False,
        "orig_score": 0.92,
        "perturb_score": 0.90,
    },
    {
        "id": "eval_near",
        "task": "rag",
        "risk": "normal",
        "created": "2026-02-10",
        "question": "差旅报销超过 5000 元时，需要哪些材料和审批？",
        "answer": "需要发票、出差审批记录和部门负责人额外审批。",
        "used_for_tuning": False,
        "orig_score": 0.91,
        "perturb_score": 0.52,
    },
    {
        "id": "eval_fresh",
        "task": "policy",
        "risk": "normal",
        "created": "2026-03-15",
        "question": "2026 年新版内部报销政策如何处理电子发票？",
        "answer": "应根据新版政策证据回答，不应引用旧制度。",
        "used_for_tuning": False,
        "orig_score": 0.78,
        "perturb_score": 0.74,
    },
    {
        "id": "eval_canary",
        "task": "leakage",
        "risk": "high",
        "created": "2026-03-20",
        "question": "隐藏 canary quartz-harbor-4821 是否出现在可检索知识库？",
        "answer": "不应出现在训练语料、日志或 RAG 知识库中。",
        "used_for_tuning": False,
        "orig_score": 1.00,
        "perturb_score": 1.00,
    },
    {
        "id": "eval_feedback",
        "task": "abstention",
        "risk": "high",
        "created": "2025-10-01",
        "question": "没有证据时是否可以编造政策答案？",
        "answer": "不可以，应说明证据不足并拒绝编造。",
        "used_for_tuning": True,
        "orig_score": 0.95,
        "perturb_score": 0.94,
    },
]

manifest = {
    "eval_version": "trusted-eval-v0.3",
    "train_cutoff": str(train_cutoff),
    "near_threshold": near_threshold,
    "canary_count": len(canary_phrases),
    "lineage_owner": "eval-team",
    "access_policy": "hidden-holdout",
}


def normalize(text):
    parts = re.findall(r"[a-z0-9\u4e00-\u9fff]+", text.lower())
    return "".join(parts)


def digest(text):
    return hashlib.sha256(normalize(text).encode("utf-8")).hexdigest()


def shingles(text, n=4):
    cleaned = normalize(text)
    if len(cleaned) < n:
        return {cleaned}
    return {cleaned[i : i + n] for i in range(len(cleaned) - n + 1)}


def jaccard(left, right):
    union = left | right
    if not union:
        return 0.0
    return len(left & right) / len(union)


corpus_hash = {digest(doc["text"]): doc for doc in corpus}
corpus_shingles = {
    doc["id"]: shingles(doc["text"])
    for doc in corpus
}

exact_hits = []
near_hits = []
max_similarity = {}
for sample in eval_samples:
    joined = f"{sample['question']} {sample['answer']}"
    sample_hash = digest(joined)
    if sample_hash in corpus_hash:
        exact_hits.append((sample["id"], corpus_hash[sample_hash]["id"]))

    sample_shingles = shingles(joined)
    best = ("", "", 0.0)
    for doc in corpus:
        sim = jaccard(sample_shingles, corpus_shingles[doc["id"]])
        if sim > best[2]:
            best = (doc["id"], doc["bucket"], sim)
    max_similarity[sample["id"]] = (best[0], best[1], round(best[2], 3))
    if best[2] >= near_threshold and (sample["id"], best[0]) not in exact_hits:
        near_hits.append((sample["id"], best[0], best[1], round(best[2], 3)))

time_failures = [
    sample["id"]
    for sample in eval_samples
    if date.fromisoformat(sample["created"]) <= train_cutoff
]

tuning_leaks = [
    sample["id"]
    for sample in eval_samples
    if sample["used_for_tuning"]
]

canary_leaks = []
for phrase in canary_phrases:
    for doc in corpus:
        if phrase in doc["text"]:
            canary_leaks.append((phrase, doc["id"], doc["bucket"]))

perturbation_risks = [
    (sample["id"], round(sample["orig_score"] - sample["perturb_score"], 3))
    for sample in eval_samples
    if sample["orig_score"] - sample["perturb_score"] >= perturb_threshold
]

manifest_required = {
    "eval_version",
    "train_cutoff",
    "near_threshold",
    "canary_count",
    "lineage_owner",
    "access_policy",
}
manifest_missing = sorted(manifest_required - set(manifest))

signals = {
    "exact_clear": not exact_hits,
    "near_duplicate_clear": not near_hits,
    "time_split_clear": not time_failures,
    "canary_clear": not canary_leaks,
    "tuning_isolated": not tuning_leaks,
    "perturbation_stable": not perturbation_risks,
    "manifest_complete": not manifest_missing,
    "access_isolated": manifest["access_policy"] == "hidden-holdout",
}

actions = []
if exact_hits:
    actions.append("remove_exact_hits_from_final_holdout")
if near_hits:
    actions.append("review_near_duplicate_sources")
if time_failures:
    actions.append("move_pre_cutoff_samples_to_history")
if tuning_leaks:
    actions.append("exclude_samples_used_for_tuning")
if canary_leaks:
    actions.append("isolate_leaked_canary_path")
if perturbation_risks:
    actions.append("inspect_perturbation_regressions")

decision = "revise_dataset_before_comparison" if actions else "use_for_pilot"
summary = {
    "exact_hits": exact_hits,
    "near_hits": near_hits,
    "max_similarity": max_similarity,
    "time_failures": time_failures,
    "tuning_leaks": tuning_leaks,
    "canary_leaks": canary_leaks,
    "perturbation_risks": perturbation_risks,
    "manifest_missing": manifest_missing,
    "signals": signals,
    "actions": actions,
    "decision": decision,
}

pprint(summary, sort_dicts=False)
~~~

## 13. 资料与证据边界

评估污染论文和数据集研究通常只能证明特定数据、模型和检测方法下的现象。它们
不能自动证明当前闭源模型的训练语料，也不能把相似度阈值直接移植到所有语言、
代码和多模态任务。

1. [GPT-3](https://arxiv.org/abs/2005.14165)：讨论大规模预训练、数据混合和 benchmark 评估背景。
2. [Deduplicating Training Data Makes Language Models Better](https://arxiv.org/abs/2107.06499)：研究训练数据去重与模型质量的关系。
3. [Detecting Pretraining Data from Large Language Models](https://arxiv.org/abs/2310.16789)：讨论从模型行为推断预训练数据暴露的检测方法。
4. [Rephrased Samples Improve Benchmark Robustness](https://arxiv.org/abs/2305.13104)：研究题目改写与 benchmark 稳健性。
5. [LiveBench](https://arxiv.org/abs/2406.19314)：以持续更新的题目降低静态 benchmark 的污染和饱和风险。
6. [HELM](https://crfm.stanford.edu/helm/latest/)：提供场景化、多指标评估框架入口。

使用这些资料时，应区分论文提出的方法、公开数据集的版本事实、项目自己的
相似度实测和对闭源训练数据的推断。访问不到训练语料时，正确的结论是“在
可检查范围内未发现某种泄漏”，而不是“模型没有见过评估题”。

## 14. 结语：可信是证据范围，而不是口号

污染检测的目标不是给 benchmark 贴上“绝对干净”的标签，而是逐条说明评估信息
有没有进入训练、调参、检索、缓存和 judge。exact duplicate 是强证据，near
duplicate 需要阈值和人工复核，时间切分提供新鲜度，canary 检测特定路径，扰动
测试观察泛化行为，数据血缘和访问控制则决定这些检查能覆盖多大范围。

一份值得相信的报告会同时呈现公开集的可比性、私有集的独立性、时间集的新鲜度、
行为测试的反例、程序和人工证据，以及闭源训练数据无法取证的部分。这样，读者
看到的不是一个脱离条件的高分，而是一个知道自己能证明什么、不能证明什么的
评估系统。
