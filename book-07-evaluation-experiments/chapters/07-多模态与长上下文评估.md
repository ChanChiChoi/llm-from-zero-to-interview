# 第七章：多模态与长上下文评估

一张发票截图、一次会议录音、一段监控视频和一份几十万 token 的合同，看起来
都是“把材料交给模型，再看它的回答”。但回答正确并不自动说明模型读懂了
材料：它可能凭语言先验猜中，也可能读到了文字却把字段关系弄错，还可能在
长文中找到一个特殊字符串，却不能把分散在不同页面的证据合并起来。

多模态评估要回答的是：模型是否使用了图像、音频或视频中的有效信息；它给出的
对象、位置、时间和文本是否与输入一致；当多个模态互相补充或冲突时，模型是否
能说明依据并作出正确判断。长上下文评估要回答的是：随着材料变长，模型是否
仍能检索、比较、整合和遵守早先的约束；它的成本、延迟和错误率是否仍然适合
真实任务。

这两类评估有各自的指标，也共享一条原则：先定义任务契约，再决定证据和分母。
本章先分别讲清多模态与长上下文的测量方法，最后把多页文档、长视频、会议
记录和代码库等交叉任务放在一起分析。读者既能看到一个 VQA 分数是怎样算出
来的，也能理解为什么一个漂亮的 1M context 结果仍不足以支撑通用能力结论。

## 1. 先确定到底在测什么

### 1.1 小白视角：同一个回答可能来自不同能力

假设给模型一张厨房照片，问题是“桌上有几个杯子”。模型回答“3”。这个结果
可能来自几种完全不同的路径：

1. 模型看到了三个杯子，并完成了计数；
2. 模型看到了厨房，但根据训练语料中的常见答案猜了一个数量；
3. 图片中的文字或题目模板泄露了答案；
4. 模型确实找到了杯子，却把另一个物体也算进去，最后碰巧选中正确数字。

如果只保存一个 0/1 的答案标签，这些路径会被压成同一个“正确”。在简单的
封闭题上，这种压缩有时足够实用；在票据、医疗影像、驾驶辅助和长文研究等
任务上，它会掩盖最需要修复的部分。

更完整的评估会同时问四个问题：

1. 最终答案是否正确；
2. 依据是否来自输入，而不是来自题面先验；
3. 证据位置、时间或页码是否正确；
4. 改变图片、采样位置、文档顺序和干扰信息后，能力是否保持。

### 1.2 专家视角：把样本写成可复核的契约

一个多模态或长上下文样本可以抽象为：

~~~math
e_i=(m_i,x_i,y_i,g_i,z_i)
~~~

其中：

- m_i 是输入材料，可以是图像、音频、视频、文档、长文本或它们的组合；
- x_i 是问题、指令和允许的工具说明；
- y_i 是标准答案、字段值、事件区间、代码行为或期望的最终状态；
- g_i 是可选的证据标注，如 bbox、页码、文本 span、时间戳和音频片段；
- z_i 是元数据，如题型、难度、语言、分辨率、时长、上下文长度、插入位置、
  来源、版本和隐私风险。

任务契约还要明确输出结构和失败含义。例如发票任务的输出可能不是一段自然语言，
而是：

~~~json
{
  "invoice_id": "...",
  "date": "...",
  "total": 0.0,
  "currency": "...",
  "evidence": [
    {"page": 1, "bbox": [0, 0, 0, 0]}
  ]
}
~~~

此时“总金额正确但币种错误”“字段正确但证据框偏离”“JSON 解析失败”和
“图片无法读取”不能都记成同一个普通错误。每种失败都对应不同的修复对象：
模型能力、预处理、输出 parser、证据标注、运行环境或任务本身。

### 1.3 结果、过程和迁移

多模态与长上下文任务至少需要保存三层结果：

~~~text
outcome：答案、字段、时间区间或最终任务状态是否正确
evidence：模型指出的证据是否支持答案，位置和范围是否合理
generalization：改变材料、位置、长度、模态组合和干扰后是否仍然正确
~~~

三层不是严格的从属关系。一个模型可以回答正确但指出错误的图像区域；可以
正确转写音频却不能回答音频中的事实问题；可以在原始合同上答对，却在同义
改写或页序变化后失效。报告若只保留 outcome，就无法解释这些差异。

### 1.4 为什么把两条主线放在同一章

多模态和长上下文不是同一个能力。前者的主要难点是模态编码、跨模态对齐和
证据定位，后者的主要难点是长度、位置、状态和多处证据整合。把它们混写成
“更大的输入”会掩盖差异。

它们仍然值得在同一章讨论，因为真实材料经常同时具有这两个属性：多页 PDF
既包含图片和表格，又需要跨页检索；会议视频既包含画面和语音，又要求在长时
间范围内定位决定；代码库既长又包含图表、截图或终端录屏。共享的任务契约、
证据、切片和成本口径，能让这些交叉任务得到一致的分析。

## 2. 共同的能力维度与分数边界

### 2.1 感知不是理解

感知回答“输入里有什么”，包括物体、文字、声音事件、说话人和场景。理解还要
回答“这些对象之间有什么关系”“这段材料支持什么结论”“下一步应该怎么做”。
一个模型能读出表格数字，不代表它理解数字对应的列标题；能转写“会议延期”，
不代表它识别出最终决定的生效日期。

因此至少要把以下维度分开：

| 维度 | 被测问题 | 典型证据 |
| --- | --- | --- |
| 感知 | 输入中的对象、文字、声音和事件是否被识别 | 标签、转写、检测框 |
| 结构 | 空间、版面、时间顺序和字段关系是否正确 | bbox、页码、区间、表格结构 |
| 推理 | 是否能计算、比较、归因或遵守约束 | 最终答案、推导、工具结果 |
| grounding | 回答是否能回指输入中的证据 | claim 与区域、span、时间戳 |
| 忠实性 | 是否编造了输入中不存在的事实 | 事实核对、拒答和引用 |
| 泛化 | 更换材料、顺序、长度和干扰后是否保持 | 变体、扰动和私有 holdout |
| 系统质量 | 是否满足延迟、成本、安全和可用性 | TTFT、P99、资源和副作用 |

### 2.2 用证据向量代替一个总分

对样本 i，可以保存一个证据向量：

~~~math
q_i=(a_i,g_i,f_i,r_i,c_i)
~~~

其中 a_i 是答案结果，g_i 是 grounding，f_i 是事实或过程忠实性，r_i 是鲁棒性
切片结果，c_i 是成本与延迟记录。它们可以是连续分数、布尔结果或带置信区间
的估计，但必须写清分母。

不建议未经说明地计算：

~~~math
Q=\alpha A+\beta G+\gamma F
~~~

因为不同分量可能来自不同样本、不同评审员和不同尺度。若业务确实需要合成
一个排序分数，应公开权重、缺失处理、阈值和敏感性分析，并同时保留原始分量。
综合分数是决策工具，不是一个新的“真实能力”。

### 2.3 小白例子：总分相同，问题不同

两个系统都在 100 张发票上得到 90 分：

| 系统 | 字段准确率 | 证据框正确率 | 关键金额错误 |
| --- | ---: | ---: | ---: |
| A | 0.90 | 0.45 | 8 |
| B | 0.86 | 0.82 | 1 |

如果业务只看文本字段，A 可能暂时占优；如果结果需要审计和自动入账，B 更可靠。
“90 分”没有告诉我们两套系统承担的风险是否相同。

## 3. VQA：答案正确不代表真的看到了图

Visual Question Answering（VQA）把图像和问题交给模型，要求模型给出答案。
题目可以很简单，例如“桌上有几个杯子”，也可以要求跨区域推理，例如
“穿蓝衣服的人拿着的物品位于红色箱子的哪一侧”。

### 3.1 题型决定难度

VQA 至少可以分为：

1. 物体和场景识别；
2. 颜色、材质和状态等属性识别；
3. 计数；
4. 左右、上下、前后和包含关系；
5. 图片文字读取；
6. 图像内多个区域的组合推理；
7. 需要常识但必须以图像事实为前提的问题；
8. 反事实问题，例如遮挡或替换一个对象后答案如何变化。

“图中有什么颜色”与“哪个物体挡住了另一个物体”不能放在同一切片里解释。
至少要按题型、对象数量、文字大小、分辨率和是否需要跨区域推理报告结果。

### 3.2 Soft accuracy 的含义

VQA 常有多个标注员答案。对于样本 i，预测答案为 hat a_i，若与预测等价的
人工答案数为 n_i(hat a_i)，一种常见 soft accuracy 口径为：

~~~math
A_{\mathrm{vqa},i}
=
\min\left(\frac{n_i(\hat{a}_i)}{3},1\right)
~~~

例如十位标注员中有七位写 dog、三位写 puppy。若归一化规则把它们视为等价，
模型回答这两个词都可能得到满分；若不视为等价，两个答案的得分就不同。这里
的除数 3 和十位标注员的具体协议有关，不能把它当作所有 VQA 数据集的普遍
定义。

字符串规范化也要有版本。大小写、冠词、标点、数字词、复数和同义词都可能
改变结果。过宽的同义词表会把错误答案放进正确集合，过窄的规则会把自然的
等价答案判错。规范化器应使用正例与反例独立测试，并保存版本。

### 3.3 语言先验与视觉反事实

问题文本本身可能泄露答案。例如“香蕉是什么颜色”在训练数据中很容易对应
黄色，即使图片中的香蕉是绿色。可以做三类对照：

1. 保持问题不变，交换图片；
2. 保持图片不变，改写问题中的对象；
3. 对目标区域做遮挡、替换或模糊。

设原始样本准确率为 A_orig，打乱图像与问题配对后的准确率为 A_shuffle，可以
观察：

~~~math
D_{\mathrm{visual}}
=
A_{\mathrm{orig}}-A_{\mathrm{shuffle}}
~~~

较大的差值说明图像信息带来了更多贡献，但它仍不是“模型一定看图”的证明。
图像交换可能制造不自然样本，遮挡也可能改变题目难度；结论需要结合自然
反事实和人工抽样。

### 3.4 计数、空间关系和否定

计数题要明确是否允许近似，以及多个相同物体是否都可见。空间题要固定坐标
系和视角，不能把“图像左侧”与“物体自身的左侧”混为一谈。否定题要测试
“图中没有 X”和“图中有一个不是 X 的 Y”这类容易被语言模板带偏的情况。

一个小的错误分析表可以这样组织：

| 预测 | 输入事实 | 结果 | 主要错误 |
| --- | --- | --- | --- |
| 3 个杯子 | 实际 2 个杯子 | 错 | 计数 |
| 左侧 | 目标在右侧 | 错 | 视角或空间关系 |
| 黄色 | 图片中是绿色 | 错 | 语言先验 |
| 有一只狗 | 图片没有狗 | 错 | 幻觉 |

这种分析比简单地把四题记成三个正确更有用，因为它直接指出了后续数据和模型
改进的方向。

### 3.5 VQA 的 grounding 证据

当任务要求模型指出证据区域时，文本答案和区域答案必须分别评分。文本正确、
区域错误，说明结果可能是猜测或从题面先验得到；文本错误、区域正确，则说明
视觉定位可能已经具备，问题可能出在属性判断或语言生成。

图像区域可以用 bbox、point 或 segmentation mask 表示。对 bbox，常用交并比：

~~~math
\mathrm{IoU}(B,\hat B)
=
\frac{|B\cap\hat B|}{|B\cup\hat B|}
~~~

B 是参考框，hat B 是预测框。报告应给出阈值，例如 IoU 大于 0.5 的命中率，
而不是只给平均 IoU；小目标、密集目标和框标注不精确时，单一阈值会产生不同
偏差。

## 4. OCR 与文档理解：从字符到字段关系

OCR 不只是把像素变成字符串。对大模型来说，真正的文档理解还包括阅读顺序、
表格结构、字段语义、跨页关系和证据回指。

### 4.1 字符错误率和词错误率

设参考序列和预测序列的最短编辑路径中，替换、删除和插入次数分别为 S、D 和 I，
参考序列长度为 N，错误率为：

~~~math
\mathrm{ER}
=
\frac{S+D+I}{N}
~~~

对字符序列得到 CER，对词序列得到 WER：

~~~math
\mathrm{CER}
=
\frac{S_c+D_c+I_c}{N_c},
\qquad
\mathrm{WER}
=
\frac{S_w+D_w+I_w}{N_w}
~~~

两者都可能大于 1，因为插入错误可以超过参考长度。空参考文本时分母不能直接
计算，应该单独记为无参考样本、拒绝该切片或使用任务特定的检测指标。

中文通常按字符或分词后的单元统计，英文通常按空格分词，但数字、标点、连字符、
大小写、全半角和日期格式都必须在协议中固定。2026-06-30 与 2026/06/30 是否
等价，不应该由一个全局字符串替换规则偷偷决定。

### 4.2 字段级准确率比平均 CER 更接近业务

发票中总金额、币种和日期的错误风险不同。可以对字段 f 记录：

~~~math
A_f
=
\frac{1}{N_f}\sum_{i=1}^{N_f}
I\left(\nu_f(\hat y_i)=\nu_f(y_i)\right)
~~~

nu_f 是字段专属的归一化函数。金额要处理千分位和小数精度，日期要处理格式
但不能改变日期含义，币种要防止只比较数字。若字段有多个 token，可以再报告
precision、recall 和 F1；一个总 CER 很低的系统仍可能在“总金额”上频繁失败。

可以把关键字段加权，但必须公开权重：

~~~math
A_{\mathrm{field}}
=
\sum_{f\in F}w_f A_f,
\qquad
\sum_{f\in F}w_f=1
~~~

加权分数只表达业务风险偏好，不代表模型的通用文档能力。未加权字段结果仍应
保留。

### 4.3 版面、阅读顺序和表格

文档中的数字只有放回结构后才有含义。评估要检查：

1. 页眉页脚是否被误当成正文；
2. 多栏文字是否按正确顺序读取；
3. 表头是否与数据列对应；
4. 合并单元格和跨页表格是否保持关系；
5. 脚注、单位、注释和括号是否跟随正确字段；
6. 签名、印章和复选框等非文本元素是否被处理。

表格可以同时评估单元格文本、行列结构和问答结果。只比较抽取出的纯文本会
丢失列关系；只看最终问答又可能把结构错误隐藏起来。对于版面区域，bbox
IoU 或区域召回是有用的辅助指标，但框的标注边界需要人工抽样复核。

### 4.4 低质量输入和拒答

真实扫描件会有倾斜、低分辨率、阴影、遮挡、压缩、手写字和中英文混排。评估
集应按这些因素切片，而不是只给一个平均 CER。对于无法可靠读取的图片，系统
可以拒答或请求更高质量输入；“猜一个金额”通常比显式报告不确定性更危险。

拒答也不能简单记为成功。应分别报告正确抽取、合理拒答、错误抽取和无关拒答，
并根据任务风险决定哪类行为更好。

## 5. 图表理解：读数、关系与结论

图表不是一张带文字的图片，而是由坐标轴、刻度、图例、数据系列、单位和视觉
编码共同构成的结构。模型必须先恢复结构，再回答数值或趋势问题。

### 5.1 任务分层

图表任务可以分为：

1. 读取单个数值；
2. 比较两个数据点；
3. 计算差值、比例或增长率；
4. 判断趋势和拐点；
5. 解释异常点；
6. 从多系列图中筛选条件；
7. 将图表转成表格；
8. 根据图表和文字上下文作出业务判断。

单点读数主要测感知和坐标映射，多步计算还测单位、公式和数值推理。不要把
它们混在同一个 accuracy 里解释。

### 5.2 数值误差的口径

对于参考值 v 和预测值 hat v，相对误差可以写成：

~~~math
E_{\mathrm{rel}}
=
\frac{|\hat v-v|}{\max(|v|,\epsilon)}
~~~

epsilon 用来避免参考值为零时分母失效，但它不是可以随便设置的容错。当 v=0
时，应额外报告绝对误差或把任务改成零值命中、符号判断等更合适的指标。百分比、
百分点和比例也要区分：从 10% 到 15% 是增加 5 个百分点，增长率则是 50%。

对于近似读数，容忍区间应由图像分辨率、刻度间距和业务风险共同决定。将
99.8 判作 100 可能合理，将 9.98 亿判作 10 亿则可能已经影响决策。

### 5.3 趋势和派生结论

“曲线在上升”不是一个单独的像素识别问题。评估器需要定义允许的噪声、时间
方向和异常点处理。对增长率：

~~~math
r_t=\frac{v_t-v_{t-1}}{\max(|v_{t-1}|,\epsilon)}
~~~

模型给出的趋势结论只有在输入数值、时间顺序和单位都正确时才算可靠。可以让
模型先输出结构化读数，再由程序计算派生量；这样能把视觉读取错误和计算错误
分开。

### 5.4 图表错误分析

常见错误包括读错轴、混淆图例、忽略单位、把视觉面积当作数值、误读对数轴、
把相关性说成因果性和对密集点产生幻觉。每个错误都应保留原图、题目、模型
读数和参考读数，便于复核评估器是否也读错了图。

## 6. 视频理解：时间是第三种证据坐标

图像中的关系通常可以用空间坐标描述，视频还需要时间坐标。视频模型可能认出
“杯子”和“人”，却不知道人是在拿起杯子之前还是之后打开抽屉。

### 6.1 任务类型

视频评估至少覆盖：

1. 动作和事件识别；
2. 事件发生顺序；
3. 多人交互；
4. 时间区间定位；
5. 视频问答；
6. 关键事件摘要；
7. 异常行为检测；
8. 过程步骤和状态变化。

能由单帧回答的问题应该与真正需要跨帧的问题分开。否则抽帧模型可能通过一
张关键帧取得高分，却没有任何时间推理能力。

### 6.2 时间区间 IoU

参考事件区间为 [s,e]，预测区间为 [hat s,hat e]，时间交并比为：

~~~math
\mathrm{tIoU}
([s,e],[\hat s,\hat e])
=
\frac{\max(0,\min(e,\hat e)-\max(s,\hat s))}
{\max(e,\hat e)-\min(s,\hat s)}
~~~

区间端点是否包含、时间单位、视频变速和剪辑后的时间轴必须固定。短事件的
端点标注本来就可能有数百毫秒差异，单纯套用图像检测的阈值会误判。报告可以
给出多个阈值下的命中率，而不是只挑一个阈值。

### 6.3 采样策略是评估协议的一部分

视频输入通常受帧数、视觉 token 和显存预算限制。均匀采样、关键帧采样、镜头
边界采样和事件候选采样会测到不同能力。评估记录至少要保存：

1. 原始视频时长和帧率；
2. 实际采样帧数和时间戳；
3. 分辨率和压缩方式；
4. 是否提供字幕、音频转写或 OCR；
5. 最大视觉 token 和处理超时。

如果模型可以看到完整字幕，而题目要求回答画面中的动作，就必须做字幕移除、
错配和画面扰动对照，否则无法知道它使用了哪种证据。

### 6.4 视频摘要

摘要没有唯一字符串答案。可以按关键事件覆盖、事实错误、时间顺序和冗余分别
评分。对每个摘要 claim c_j，由人工或可靠 verifier 判断它是否能在视频中找到
证据；摘要质量不应由字数或语言流畅度单独决定。

## 7. 语音评估：转写、语义和交互必须分开

语音系统至少包含输入识别、语义处理和输出合成三层。ASR 错误会污染后续问答，
但问答错误不一定来自 ASR；如果只报告最终任务成功率，就无法定位系统瓶颈。

### 7.1 ASR 的 WER/CER

参考序列长度为 N，编辑距离中的替换、删除和插入分别为 S、D、I：

~~~math
\mathrm{ER}
=
\frac{S+D+I}{N}
~~~

按字符统计得到 CER，按词统计得到 WER。中文的分词器不同会改变 WER，因此应
同时给出规范化规则和分词版本。数字、专有名词、标点和大小写是否纳入比较，
也会改变结论。

一个语音问答系统至少可以保存三层结果：

~~~text
transcript：转写是否正确
semantic_answer：从转写和音频中抽取的答案是否正确
interaction：延迟、打断、恢复和多轮约束是否满足
~~~

### 7.2 说话人、噪声和关键词

会议场景还涉及说话人分离。说话人错误率可以按漏检、误检和说话人混淆在总
参考时长中的比例报告：

~~~math
\mathrm{DER}
=
\frac{T_{\mathrm{miss}}+T_{\mathrm{false}}+T_{\mathrm{conf}}}
{T_{\mathrm{reference}}}
~~~

关键词召回适合测“药品名称”“账户号码”和“停止交易”等高风险片段，但不能
替代整体 WER。噪声、口音、重叠说话、远场回声和代码切换都应作为独立切片。

### 7.3 TTS 与实时体验

TTS 可以评估自然度、可懂度、音色一致性、韵律、停顿、情感和读错专有名词。
MOS、成对偏好和可懂度听评都需要人工标注；自动声学指标可以辅助诊断，但不
能直接代表用户听感。

实时语音助手还要记录首个可听输出的延迟 TTFA、端到端响应时间、打断响应、
错误恢复和多轮状态。不同团队对“首 token”“首音频包”和“用户听到声音”的
定义可能不同，报告要明确计时起点和终点。

## 8. Grounding：把回答连接回证据

### 8.1 Grounding 的对象

Grounding 不是一句“模型看过图片”就能证明的属性，而是答案 claim 与输入
证据之间的可复核关系。证据可能是：

| 输入 | 证据形式 |
| --- | --- |
| 图像 | bbox、point、mask 或区域描述 |
| 文档 | 页码、段落、表格单元格、字符区间 |
| 视频 | 时间区间、关键帧和轨迹 |
| 音频 | 时间片段、说话人和转写 span |
| 长文本 | 文档 id、段落、句子和版本 |

一个 claim 可以需要多个证据。只引用一处相关文字，不代表它支持了结论中的
所有限定词、数字和因果关系。

### 8.2 区域和区间指标

图像 bbox 使用 IoU：

~~~math
\mathrm{IoU}(B,\hat B)
=
\frac{|B\cap\hat B|}{|B\cup\hat B|}
~~~

视频区间使用 tIoU：

~~~math
\mathrm{tIoU}
=
\frac{|T\cap\hat T|}{|T\cup\hat T|}
~~~

文档引用可以将页码和 span 转成集合，分别报告引用精确率和召回率：

~~~math
P_{\mathrm{cite}}
=
\frac{|E_{\mathrm{needed}}\cap E_{\mathrm{cited}}|}
{|E_{\mathrm{cited}}|}
,\qquad
R_{\mathrm{cite}}
=
\frac{|E_{\mathrm{needed}}\cap E_{\mathrm{cited}}|}
{|E_{\mathrm{needed}}|}
~~~

当模型引用了大量无关段落时，召回率可能很高但精确率很低；只引用一段而漏掉
关键限定条件时，精确率可能看起来不错但召回率不足。

### 8.3 答案与证据的联合结果

可以把答案正确和证据合格分别记录，再按业务需要统计联合成功：

~~~math
A_{\mathrm{joint},i}
=
I(\hat y_i=y_i)
\cdot
I(\mathrm{evidence}_i\ \mathrm{supports}\ \hat y_i)
~~~

这个乘积不是通用总分，只表示“既答对又给出支持证据”的样本比例。若答案不
要求模型显式引用，不能事后把缺少证据字段判成模型错误；任务契约必须预先规定
证据是否是成功的一部分。

### 8.4 证据注入与反事实

grounding 评估也会被数据集捷径污染。可以交换证据区域、删除引用段、替换图像
对象或改变视频时间片，然后观察答案和证据是否一起变化。若答案保持不变而
证据随意漂移，说明“给出一个框”可能只是格式服从，不是可靠定位。

## 9. 长上下文：容量、使用和任务成功

### 9.1 能接收不等于能使用

上下文窗口是接口与 runtime 能接收的最大 token 数；有效能力还要看模型能否
在这些 token 中找到证据、理解关系、保持约束、完成推理并在预算内返回结果。
至少要区分：

1. API 或 runtime 上限；
2. tokenizer 后的实际长度；
3. 训练中见过的上下文长度；
4. 有效检索和证据整合能力；
5. 完成一次成功任务的成本和延迟。

一个请求的预算可以近似写成：

~~~math
L_{\mathrm{budget}}
=
L_{\mathrm{input}}
+L_{\mathrm{output}}
+L_{\mathrm{hidden}}
+L_{\mathrm{tool}}
+L_{\mathrm{reserved}}
~~~

L_hidden 代表服务协议中可能消耗预算的隐藏推理或内部 token，L_tool 代表工具
结果，L_reserved 代表系统保留空间。不同 API 是否公开这些字段并不一致，实验
至少应保存可观测的近似值。

### 9.2 Needle-in-a-Haystack 测什么

needle 测试把一个可识别的信息插入长材料，再要求模型找出它。例如：

~~~text
在 100k token 文档中插入：
The secret code is 481516.
问题：secret code 是什么？
~~~

在长度 L 和位置 p 上，召回率可写成：

~~~math
R_{\mathrm{needle}}(L,p)
=
\frac{N_{\mathrm{hit}}(L,p)}
{N_{\mathrm{case}}(L,p)}
~~~

它的优点是生成、判定和复现实验都相对容易，也能暴露中间位置退化。它主要
测显著目标的长距离定位，不等于通用阅读理解。

### 9.3 位置网格和上下文退化

至少应该在开头、前四分之一、中间、后四分之一和结尾放置信息，并在多个长度
上重复。位置最差召回和跨度分别为：

~~~math
R_{\mathrm{worst}}(L)
=
\min_p R_{\mathrm{needle}}(L,p)
~~~

~~~math
\Delta_{\mathrm{pos}}(L)
=
\max_pR_{\mathrm{needle}}(L,p)
-\min_pR_{\mathrm{needle}}(L,p)
~~~

需要同时报告每个位置的原始样本数。只有三个位置各测一次，无法支撑细致的
位置曲线，也无法区分随机波动和稳定的 middle drop。

### 9.4 Needle 的四个局限

needle 可能高估长上下文能力，原因包括：

1. needle 具有特殊格式或词汇，容易被注意；
2. 任务只需要复制局部字符串；
3. 不需要整合多处证据；
4. 不需要处理冲突、时间顺序或版本；
5. 干扰文本与真实材料的分布不同。

因此它应和多针、分散证据、冲突信息、同义改写、长文摘要和代码库任务一起使用。

## 10. 真实长文任务

### 10.1 多证据问答

多文档问答要求模型从多个位置取证，并把证据合并为一个结论。评估应分别记录：

1. 相关文档是否找到；
2. 每个必要证据是否被覆盖；
3. 证据之间是否被正确组合；
4. 版本、时间和权限是否处理正确；
5. 没有足够证据时是否拒答。

必要证据集合为 E_needed，模型引用集合为 E_cited 时，证据覆盖率为：

~~~math
C_{\mathrm{evidence}}
=
\frac{|E_{\mathrm{needed}}\cap E_{\mathrm{cited}}|}
{|E_{\mathrm{needed}}|}
~~~

覆盖率高不代表答案正确，因为模型可能引用了所有段落却错误地合并关系。需要
再记录 claim correctness、引用精确率和冲突处理。

### 10.2 长文摘要

摘要可以从三个层面评估：

- 覆盖：关键事实、事件和限定条件有没有被保留；
- 忠实：摘要中的 claim 是否能在原文中找到支持；
- 压缩：在目标长度下是否去掉了重复内容而没有丢掉高风险细节。

对摘要 claim c_j，可以人工或程序标注是否有来源支持：

~~~math
F_{\mathrm{summary}}
=
\frac{\sum_j w_j I(c_j\ \mathrm{is\ supported})}
{\sum_j w_j}
~~~

w_j 可以对金额、日期、安全限制和否定句给予更高权重，但权重必须与业务风险
关联。只按 ROUGE、字数或语言流畅度评分，会忽略“写得漂亮但事实错误”。

### 10.3 冲突检测和版本比较

真实合同、论文和产品文档经常存在修订版本。任务可以要求模型找出关于付款
期限、接口参数或安全限制的矛盾，并指出各自的来源和版本。

这类任务至少有两个输出：

1. 冲突是否存在；
2. 冲突双方分别是什么、位于哪里、哪个版本更新。

评估器不能只比较“发现了几个冲突”。漏报、误报、版本错配和引用错误都要分开
记录。将两处互相独立的表述误判成冲突，也会损害使用者对系统的信任。

### 10.4 长状态跟踪

在长对话和 Agent 任务中，状态可能包括用户偏好、已完成步骤、权限、预算、
工具结果和待办事项。评估可以在早期设置约束，在中间插入干扰，在后期要求
执行动作；最终要检查状态是否仍然满足，而不只是看模型有没有复述旧信息。

如果 Agent 修改了文件、发出消息或创建订单，外部状态和副作用应作为主要结果。
一段看起来正确的解释不能抵消错误写入。

### 10.5 长上下文代码库

代码库任务要求模型定位定义、理解跨文件调用链、修改多个文件并通过测试。
报告至少包括：

1. patch 是否能应用；
2. 构建和公开测试是否通过；
3. 隐藏测试和回归测试是否通过；
4. 是否改变不相关接口；
5. 复杂度、权限和副作用是否满足契约。

它比“从长文件中找一个函数名”更接近实际的长上下文使用，但成本也更高。代码
评估的外部测试和沙箱要求可与上一章的 Code Eval 方法结合。

## 11. 多模态与长上下文的交叉任务

### 11.1 多页 PDF

多页文档同时考查视觉、版面和长度。测试集应包含：

1. 跨页字段查找；
2. 表格在分页后的行列延续；
3. 页眉页脚和目录干扰；
4. 图文混排；
5. 页码、bbox 和文本 span 引用；
6. 扫描页与可搜索文本页的差异。

如果把 PDF 先转成干净纯文本再评估，只测到了文本长上下文，不能代表视觉文档
理解。相反，只给模型页面截图又可能丢失可搜索文本中的精确字符边界。

### 11.2 长视频和会议记录

长会议可以同时提供音频、视频、字幕和演示文稿。一个“会议决定了什么”的
问题可能需要：

1. 从语音中识别最终发言；
2. 从幻灯片中读取具体数字；
3. 从时间顺序判断决定是在讨论中提出还是最终确认；
4. 给出音频时间戳和幻灯片页码；
5. 处理不同说话人的相互否定。

如果只评估转写文本，无法测到画面与声音的对齐；如果只评估摘要，又可能把
时间和来源错误隐藏起来。

### 11.3 多图表综合分析

当任务同时输入多个图表时，模型可能把同名指标、不同单位或不同时间段混淆。
应在样本 schema 中记录图表 id、单位、时间范围和每个结论所需的证据集合。
改变图表顺序和插入无关图表，可以检查模型是否依赖固定位置。

### 11.4 屏幕录制和工具任务

屏幕录制评估同时涉及视觉定位、状态记忆、操作顺序和副作用。成功定义不能只
是“点击了看起来正确的按钮”，还要检查：

1. 是否在正确应用和账号中操作；
2. 是否没有绕过权限；
3. 是否产生了预期状态；
4. 是否在失败后安全恢复；
5. 是否记录了可审计的操作轨迹。

## 12. 如何选择评估方法

### 12.1 客观判定

当输出可以程序化比较时，优先使用确定性判定：

| 任务 | 主要判定 | 辅助判定 |
| --- | --- | --- |
| OCR 字符 | CER/WER | 关键字段准确率 |
| 发票字段 | 字段 exact/F1 | bbox、页码和人工抽查 |
| 图表数值 | 绝对/相对误差 | 趋势和单位 |
| 图像区域 | IoU、pointing | 区域语义 |
| 视频事件 | tIoU、事件召回 | 顺序和事实性 |
| 代码/工具 | 测试和最终状态 | 日志和解释 |
| 长文引用 | span 精确率/召回率 | claim 支持度 |

自动指标成本低且可复现，但只对它定义过的行为负责。指标实现、参考答案和
测试样本本身仍需抽样审计。

### 12.2 人工评估

开放式摘要、复杂图表解释、视频事实性和证据充分性往往需要人类判断。rubric
应把“事实正确”“证据充分”“覆盖关键细节”“表达清晰”拆开，评审员先看
输入和任务契约，再看答案，避免只被语言流畅度影响。

不同领域需要不同评审员。法律字段、医学影像和金融图表不能只依赖一般语言
质量评分。人工评估还要保存抽样方法、评审员数量、盲法、冲突处理和一致性。

### 12.3 LLM judge 的边界

LLM judge 可以做开放文本的初筛，但它可能偏好更长、措辞更像参考答案或来自
同一家族的输出。使用时要有人工 gold set、顺序交换、候选匿名化、长度控制和
独立 holdout。对于金额数字、表格单元格、bbox、时间区间和工具状态，只要有
可靠程序判定，就不应让 judge 取代它。

judge 的分数是测量结果，不是事实来源。它与程序 verifier 或人工判断冲突时，
应保存冲突样本并调查原因，而不是只选更高的一个分数。

## 13. 错误分析：从分数回到样本

### 13.1 多模态错误树

多模态失败至少可以分为：

~~~text
输入质量或预处理
  -> 图片裁剪、分辨率、帧采样、音频噪声、OCR 转换
感知
  -> 对象、文字、声音事件、说话人
结构
  -> 空间关系、版面、时间边界、图表坐标
推理
  -> 计数、比较、跨模态组合、因果或反事实
grounding
  -> 证据缺失、位置错误、引用范围不足
输出
  -> 解析、单位、格式、拒答和副作用
评估器
  -> 标注、归一化、阈值、judge 或 harness
~~~

错误树的价值在于它给出修复方向。若低分主要来自图片缩放，增加推理数据未必
有效；若 bbox 正确而属性错误，应该改变任务或模型 head；若答案正确但证据
错误，应该重新设计输出契约和 grounding 训练。

### 13.2 长上下文错误树

长上下文失败可以分为：

1. 输入截断或 token 预算不足；
2. 位置退化；
3. 相关段落检索失败；
4. 多处证据没有合并；
5. 冲突或版本处理错误；
6. 约束被后文覆盖；
7. 摘要压缩丢失高风险事实；
8. 长任务的工具状态失配；
9. 引用 parser 或外部验证错误。

“模型记不住”不是一个可操作的错误类别。只有把它落到长度、位置、证据数量、
版本、工具状态和错误样本，才能比较不同修复。

### 13.3 模型错误与评估器错误

图片质量太差、时间戳本身不一致、OCR 参考文本有误、同义答案未被归一化、
judge 偏好长答案，都会制造假失败或假成功。每次评估都应抽查：

1. 模型判错但参考答案是否正确；
2. 证据标注是否覆盖合理范围；
3. parser 是否抽取了正确字段；
4. 阈值是否与任务风险一致；
5. 外部执行环境是否与报告版本一致。

如果评估器错误没有被识别，训练和提示优化会朝着错误目标迭代。

from pprint import pprint


def edit_distance(left, right):
    dp = [[0] * (len(right) + 1) for _ in range(len(left) + 1)]
    for i in range(len(left) + 1):
        dp[i][0] = i
    for j in range(len(right) + 1):
        dp[0][j] = j
    for i, left_item in enumerate(left, start=1):
        for j, right_item in enumerate(right, start=1):
            dp[i][j] = min(
                dp[i - 1][j] + 1,
                dp[i][j - 1] + 1,
                dp[i - 1][j - 1] + (left_item != right_item),
            )
    return dp[-1][-1]


def normalize_answer(text):
    return "".join(char.lower() for char in text if char.isalnum())


def vqa_soft_accuracy(prediction, answers):
    normalized = normalize_answer(prediction)
    matches = sum(normalize_answer(answer) == normalized for answer in answers)
    return min(matches / 3, 1.0)


def box_iou(left, right):
    lx1, ly1, lx2, ly2 = left
    rx1, ry1, rx2, ry2 = right
    ix1, iy1 = max(lx1, rx1), max(ly1, ry1)
    ix2, iy2 = min(lx2, rx2), min(ly2, ry2)
    intersection = max(0, ix2 - ix1) * max(0, iy2 - iy1)
    left_area = max(0, lx2 - lx1) * max(0, ly2 - ly1)
    right_area = max(0, rx2 - rx1) * max(0, ry2 - ry1)
    union = left_area + right_area - intersection
    return intersection / union if union else 0.0


def temporal_iou(left, right):
    left_start, left_end = left
    right_start, right_end = right
    intersection = max(0, min(left_end, right_end) - max(left_start, right_start))
    union = max(left_end, right_end) - min(left_start, right_start)
    return intersection / union if union else 0.0


def sequence_error(reference, prediction):
    reference_items = normalize_answer(reference)
    prediction_items = normalize_answer(prediction)
    return edit_distance(reference_items, prediction_items) / max(len(reference_items), 1)


def word_error_rate(reference, prediction):
    reference_words = reference.lower().split()
    prediction_words = prediction.lower().split()
    return edit_distance(reference_words, prediction_words) / max(len(reference_words), 1)

## 16. 真实项目的评估闭环

### 16.1 从用户任务写输入契约

先记录输入格式、模态是否必需、分辨率或采样限制、输出 schema、证据要求、
允许的工具、拒答规则、延迟预算、隐私约束和外部副作用。多模态项目尤其要
记录预处理版本，因为裁剪、压缩、OCR 转换、视频采样和音频降噪本身就会改变
被测输入。

### 16.2 构建分层数据集

一个可维护的评估集至少包含：

1. 常见用户样本；
2. 边界和低质量样本；
3. 需要多个证据的样本；
4. 反事实和对抗样本；
5. 时间或版本切分样本；
6. 私有 holdout；
7. 历史真实失败样本；
8. 不同语言、设备、分辨率和时长切片。

训练、调参、judge 校准和最终报告的样本要有清楚的数据血缘。公开题目可用于
历史比较，不能替代新鲜和私有证据。

### 16.3 固定 harness 和记录版本

每次运行至少记录：

~~~text
model_revision
prompt_revision
tokenizer_or_processor_revision
image_resize_and_crop_policy
audio_normalization_policy
video_sampling_policy
max_input_and_output_tokens
temperature_and_sampling_count
answer_parser_revision
grounding_parser_revision
verifier_revision
dataset_revision
runtime_and_hardware
~~~

没有这些字段，模型升级、视觉处理器升级和评估器升级混在一起，分数变化就
没有可解释性。

### 16.4 报告切片和不确定性

总体均值必须和切片一起出现。对比例指标，至少报告样本数和置信区间；对时间
区间、bbox 和人工评分，说明阈值、评审员和缺失处理。若多个候选、多个视频
片段或多个用户来自同一任务，重采样单位不能简单当成独立行。

一个长上下文报告可以使用这样的表格：

| 长度 | 位置 | 任务 | 样本数 | 答案正确率 | 证据覆盖率 | P95 延迟 |
| ---: | --- | --- | ---: | ---: | ---: | ---: |
| 32k | start | needle | 100 | 0.98 | 0.98 | 1.2s |
| 32k | middle | multi-evidence | 100 | 0.81 | 0.74 | 1.6s |
| 128k | middle | multi-evidence | 100 | 0.59 | 0.48 | 4.9s |

这张表比“支持 128k”更接近工程事实，因为它同时展示了任务、位置、证据和
成本。

### 16.5 回归测试与线上反馈

每次替换视觉 encoder、采样器、prompt、量化方案、上下文压缩器或推理 runtime
后，都要重跑固定回归集。需要观察：

1. OCR 提升是否损害空间关系；
2. needle 提升是否损害摘要忠实性；
3. 幻觉减少是否带来过多拒答；
4. 视觉 token 减少是否损害小目标；
5. 低延迟优化是否增加跨页或跨帧漏证据；
6. 评分器变化是否造成假回归。

线上还要看用户重试、人工修正、任务完成、引用点击、人工接管和安全事件。
线上会话级结果不能直接与离线题目级 accuracy 相减。

## 17. 常见误区

### 17.1 把多模态评估当成文本评估

只看最终文本答案，会隐藏模型是否真的使用了图像、音频和视频。至少要为需要
视觉细节、时间定位和文档证据的任务保存 grounding 或引用结果。

### 17.2 只测简单 VQA

简单颜色和常见物体问题容易被语言先验解决。数据集应加入计数、空间关系、
OCR、图表、反事实和不存在对象的拒答。

### 17.3 把 context window 当成有效能力

窗口长度是容量声明，不是检索、整合和推理能力。长度、位置、干扰、多证据和
真实任务需要分别评估。

### 17.4 只用 needle 代表长上下文

needle 适合测长距离定位，但不测摘要、冲突处理、版本比较、状态跟踪和代码库
修改。一个系统可以 needle 很强而真实长文任务很弱。

### 17.5 忽略预处理和采样

图片裁剪、视频帧采样、字幕、ASR 转写和 PDF 文本抽取都是评估输入的一部分。
改变它们却把分数变化全部归因于模型，会得到错误结论。

### 17.6 用 LLM judge 评估一切

能用 CER、字段匹配、IoU、tIoU、数值误差、编译测试和最终状态判定时，应优先
使用这些可复现证据。judge 适合开放式质量初筛，但必须用人工样本校准。

### 17.7 只报告平均值

平均值可能掩盖小目标、低资源语言、长时视频、中间位置、关键字段和高风险
拒答的失败。切片和原始失败样本是结论的一部分。

## 18. 练习：从任务设计到证据解释

### 练习一：视觉反事实

设计一组 VQA 样本，要求能够区分“真正看图”和“根据问题猜答案”。写出原始
样本、图像交换样本、遮挡样本、答案归一化规则和错误分类。

### 练习二：发票字段

给定发票号、日期、商家、税额、总金额和币种，分别设计字段级准确率、格式
归一化、关键字段权重和证据 bbox 评估。说明为什么总 CER 不能代替总金额准确率。

### 练习三：视频时间顺序

设计一个必须依赖事件顺序的问题，给出参考时间区间、tIoU 阈值、关键帧采样
协议和字幕干扰对照。说明单帧模型可能怎样投机。

### 练习四：长上下文对照

一个模型在 128k needle 上接近满分，但长文摘要和冲突检测很差。请区分检索、
证据整合、压缩、忠实性和位置偏差，并提出至少三个独立测试。

### 练习五：交叉任务

设计一个长会议评估样本：问题需要同时使用音频、幻灯片和时间顺序。写出输出
schema、必需证据、语音和视觉指标、人工复核规则以及成本记录字段。

## 19. 资料与证据边界

公开 benchmark 支持的是其具体数据、标注、模型接口和评估 harness 下的结论。
VQA 的 soft accuracy 不能自动代表开放式视觉推理；DocVQA 的字段结果不能自动
代表复杂合同审查；ChartQA 不能自动代表真实业务图表；Video-MME 不能覆盖所有
长视频和音视频对齐；LongBench、Lost in the Middle 和 RULER 也不能单独证明
通用的长上下文理解。

可作为方法入口的资料包括：

1. [VQA](https://arxiv.org/abs/1505.00468)：视觉问答任务与多标注答案评估。
2. [DocVQA](https://arxiv.org/abs/2007.00398)：文档视觉问答和字段理解背景。
3. [ChartQA](https://arxiv.org/abs/2203.10244)：图表问答与数值/推理任务。
4. [LongBench](https://arxiv.org/abs/2308.14508)：多任务长上下文评估。
5. [Lost in the Middle](https://arxiv.org/abs/2307.03172)：长上下文位置效应。
6. [Video-MME](https://arxiv.org/abs/2405.21075)：视频理解任务与时序评估。
7. [RULER](https://arxiv.org/abs/2404.06654)：合成长上下文任务与长度退化测试。
8. [MMMU](https://arxiv.org/abs/2311.16502)：多学科多模态理解和推理基准。

使用这些资料时，要记录数据版本、输入预处理、采样策略、解码预算、答案解析、
grounding 标注和评估器版本。论文中的结果说明作者在特定实验条件下观察到
什么，不应被改写成当前系统未经验证的质量承诺。

## 20. 结语：让“看到了”和“用上了”都能被证明

多模态评估先问模型是否正确使用输入模态，再问答案、结构、证据和任务状态
是否正确。VQA 要防语言先验，OCR 要从字符走到字段和版面，图表要检查坐标轴、
单位和派生计算，视频要把时间区间和跨帧关系纳入结果，语音要把转写、语义和
实时交互分开。

长上下文评估不能把窗口长度当成理解能力。needle 是有价值的检索探针，但真实
任务还需要多证据整合、冲突检测、长文摘要、状态跟踪和代码库验证。多页文档、
长会议和屏幕操作则要求模型同时处理模态对齐、位置或时间证据、长距离状态和
外部副作用。

一份可信报告应让读者回答：模型看到了什么，依据在哪里，改变材料和位置后是否
仍然成功，失败来自模型还是评估器，以及获得这些结果消耗了多少时间和资源。
当每个分数都能回到任务契约、样本切片和原始证据时，评估才真正成为能力分析，
而不是一张漂亮但难以解释的排行榜。
