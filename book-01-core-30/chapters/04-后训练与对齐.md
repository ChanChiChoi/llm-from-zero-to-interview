# 第三部分：训练、对齐与推理

## 本文件的阅读路径

本文件从基础模型“会续写但未必会按用户意图回答”的缺口出发。第 19 讲讨论指令数据和行为契约，第 20 讲把监督目标落到 SFT 的标签与 loss，第 21—22 讲比较基于奖励模型的在线策略优化与直接偏好优化，第 23 讲再检查代理目标何时偏离真实目标。图中的路径是教学地图，不表示所有模型都必须按同一流水线完成每一步。

理解不同方法时，先问训练信号来自哪里，比只背方法缩写更有用：SFT 通常使用外部整理的示范回答；离线偏好优化使用已经收集好的 chosen/rejected 对；在线强化学习会采样当前策略或近似当前策略生成的轨迹，再用奖励或验证信号更新策略。这个分类描述的是数据与策略的关系，不意味着每个团队都采用同一顺序，也不意味着方法名能唯一决定数据来源。2026 年发布的一篇 arXiv 后训练综述预印本进一步用轨迹来源区分 off-policy 与 on-policy，并讨论“扩展可达行为”“重塑已有行为”和跨阶段巩固行为等视角；它适合作为梳理方法关系的地图，不是某种训练流程的规范。

| 训练信号 | 典型输入 | 主要改变 | 检查重点 |
| --- | --- | --- | --- |
| 示范数据 | prompt 与目标回答 | 让目标回答变得可模仿 | 目标 token、角色边界、长短回答权重、未监督区域 |
| 固定偏好数据 | 同一输入下的 chosen/rejected 回答 | 在已有候选间调整相对偏好 | 标注标准、reference、长度效应和分布外行为 |
| 策略采样轨迹 | 当前或近似当前策略生成的回答及反馈 | 通过在线反馈更新策略行为 | rollout 分布、奖励有效性、策略漂移和能力回归 |

这种分类帮助读者追踪“谁生成了训练样本、样本在哪个策略分布下产生、反馈怎样进入梯度”，具体方法之间仍有混合、迭代和变体。来源：[Large Language Model Post-Training: A Unified View of Off-Policy and On-Policy Learning](https://arxiv.org/abs/2604.07941)。

还要把“算法名”与“实际训练配方”分开。ICLR 2026 的一项研究比较了不同 LLM 强化学习配方随计算量扩大的表现，指出损失聚合、归一化、课程安排和 off-policy 数据使用等实现选择，会改变达到目标质量所需的计算效率。它支持一个重要的实验设计原则：报告“训练了多少步”或“用了多少 token”还不够，必须说明每个样本如何加权、分母怎样归一化、数据来自哪个策略分布，并在相同评估目标下比较；该研究的配方和任务范围并不构成所有模型的统一排名。[The Art of Scaling Reinforcement Learning Compute for LLMs](https://proceedings.iclr.cc/paper_files/paper/2026/hash/75ea88aca02640cca54c1231db8cacdd-Abstract-Conference.html)

## 第 19 讲：Instruction Tuning

### 19 讲·指令数据的对象

预训练模型按 next-token 目标学习续写；这个目标本身没有规定系统、用户和助手各自的角色边界，也没有直接指定助手应如何遵循指令、处理安全请求或结束一轮对话。模型可能已经能从上下文中完成部分任务，但这不保证它会稳定地按产品所需的方式响应。

Instruction Tuning 用任务指令及目标响应继续训练模型，目的是提高它在指定任务和对话格式下生成目标回答的可能性。它改变的是模型在给定提示下的行为分布，不会凭训练名称自动带来事实正确、安全或对所有用户意图的理解。

这一讲围绕以下问题展开：

1. Base model 为什么不能直接当助手。
2. Instruction Tuning 到底在训练什么。
3. 指令数据通常长什么样。
4. Instruction Tuning、SFT、RLHF、DPO 的关系。
5. Chat template 为什么重要。
6. 指令微调数据质量如何影响模型行为。
7. 如何把后训练 pipeline 拆成数据、目标、行为和评估四个可观测部分。

### 从 Base Model 到 Instruct Model

Base model 的训练目标是 next-token prediction。

它学习的是：

```text
给定前文，预测下一个 token
```

这让模型能学到大量语言、知识和任务模式，但单靠这个目标不能保证它会稳定地区分：

1. 谁是用户。
2. 谁是助手。
3. 应该回答问题还是继续补全文档。
4. 当前要优先遵循哪条指令。
5. 哪类请求需要拒答或转交。
6. 回答应该简洁还是详细。

Instruction tuning 要解决的核心问题是：把模型行为从“文本续写器”调整成“指令跟随助手”。

### Instruction Tuning 是什么

Instruction Tuning 通常指用“任务指令—目标响应”样本对模型做后训练。训练信号可以来自人工示范、经过筛选的公开任务数据或模型生成的数据；是否把它称为 SFT，取决于具体文献和配方。许多实现仍使用 next-token 交叉熵，但监督哪些 token 由数据格式和训练目标决定。

典型样本：

```text
Instruction: 用三句话解释什么是 Transformer。
Response: Transformer 是一种基于注意力机制的神经网络架构。它可以并行处理序列，并通过 self-attention 建模 token 之间的关系。现代大语言模型大多基于 decoder-only Transformer。
```

更接近聊天模型的格式：

```text
User: 用 Python 写一个二分查找。
Assistant: 下面是一个简单实现：...
```

许多指令微调配方用 next-token prediction 拟合目标响应；哪些 token 参与 loss，留到下一节按具体目标说明。

### 为什么很多对话 SFT 只对 Assistant 目标算 Loss

在对话式监督微调中，模型要根据 system、user 和历史对话来生成 assistant 响应。若训练目标就是“给定上下文，模仿目标回答”，常见做法是把上下文 token 保留在 `input_ids` 中，却将这些位置的 `labels` 设为 `-100`，只让目标回答参与 loss。TRL 1.16.0 文档也用 `-100` 表示不计入目标的 label；屏蔽标签不会屏蔽这些 token 进入模型上下文。[SFT Trainer 文档](https://huggingface.co/docs/trl/v1.16.0/sft_trainer)

这是一种目标选择，不是所有语言模型训练都必须遵守的规则。若任务要建模完整对话、预测任意角色的后续消息或继续一段文本，监督用户等上下文 token 也可能符合目标。判断是否屏蔽，应先问“模型要学会生成哪一段”，再检查模板标出的边界是否与答案一致。

看一个简化的因果语言模型样本：

```text
input_ids: [<user>, q, <assistant>, 4, <eos>]
labels:    [-100,   -100, -100,        4, <eos>]
```

这里把完整问题简化成一个 token `q`，并假设模型在预测答案前已经读到 `<assistant>`。模型位置 2 的 logits 预测标签位置 3 的 `4`，位置 3 的 logits 预测 `<eos>`；user 仍是条件输入，但它的目标标签被忽略。若模板把 assistant 起始标记也作为模型需要生成的 token，就应按相同原则调整标签边界。

再用小概率例子看分母的作用。这里用自然对数 `ln` 计算，所以交叉熵单位是 nats/token。假设两个 assistant 目标 token 的正确概率分别为 $1/2$ 和 $1/4$，则 assistant-only 平均交叉熵为 $-(\ln(1/2)+\ln(1/4))/2=1.040$ nats/token（四舍五入到三位小数）。若把两个上下文目标也纳入 loss，并假设它们的正确概率都是 $1/2$，全序列平均值会变为 $-(3\ln(1/2)+\ln(1/4))/4=0.866$ nats/token。助手回答的概率并没有变化；平均值变小只是因为统计口径加入了另外两个目标，不能据此判断回答质量提高。第 20 讲会进一步展开标签移位、mask 和实现。

### Chat Template

Chat template 把结构化消息序列化为模型训练或推理时使用的 token 序列。不同模型可以用不同控制 token 表示角色、轮次结束和工具交接；模板是输入协议的一部分，不是统一的聊天语法。[Transformers v5.17.0 文档](https://huggingface.co/docs/transformers/v5.17.0/chat_templating)

例如：

```text
<|system|>
You are a helpful assistant.
<|user|>
Explain gradient descent.
<|assistant|>
Gradient descent is ...
```

模型实际接收的是序列化并分词后的 token，而不是抽象的“消息对象”。例如，role token、结束 token 和换行形式的变化都会改变输入序列；影响大小要在具体 checkpoint、tokenizer 和任务上测量。

若训练和推理使用不同模板，模型看到的条件序列可能偏离训练格式，进而影响角色边界、回答起点或停止位置。不能仅凭“模板不一致”断定性能会下降多少，应固定权重、提示和解码设置后做对照。

常见的角色和控制标记包括：

1. system、user、assistant 等角色标记。
2. 消息结束或 assistant 回合结束标记。
3. 工具调用与工具返回标记。

它们在具体模板中可能是专用 token，也可能由普通文本和控制 token 组合表示，不能假设不同模型使用同一套词表。

### 模板差分的最小实验

把同一条消息分别序列化成模板 A 和模板 B，先对照 token 数、控制 token、assistant 起始位置和结束标记，再用同一 checkpoint、同一解码设置比较首 token 分布、格式通过率和停止位置。差异是需要测量的结果，不应从单个模板差分推断成所有模型的固定规律。

推理时的 generation prompt 也要与最后一条消息的状态匹配：常见模板会在新 assistant 回合前加入起始标记，但并非所有模型都需要它；若希望模型继续未完成的 assistant 消息，则应使用相应的前缀续写格式。训练已完成的对话样本时，一般不要额外追加一个空 assistant 起始前缀，否则目标边界可能改变。[Transformers 文档](https://huggingface.co/docs/transformers/v5.17.0/chat_templating)

初学者可以把 template 理解为对话的序列化规则；专家还应检查 tokenizer、模板 revision、tool call 路径和 generation prompt 是否一致。TRL 1.16.0 的 assistant-only loss 需要模板正确标出 assistant generation 区域；模板若没有相应标记，生成的 loss mask 可能不符合预期，因此要直接检查 token 与 mask。[TRL 1.16.0 Chat Templates](https://huggingface.co/docs/trl/v1.16.0/chat_templates)

### 指令数据类型

Instruction tuning 数据可以包括：

1. 问答。
2. 摘要。
3. 改写。
4. 翻译。
5. 代码生成。
6. 数学解题。
7. 多轮对话。
8. 工具调用。
9. 安全拒答。
10. 风格控制。

好的指令数据不只是“有问题有答案”，还要覆盖真实用户意图。

### 数据质量、覆盖面与数量如何共同起作用

“数据质量比数量更重要”不是跨模型、任务和预算都成立的定律。有效监督既取决于目标回答是否正确、是否遵循约束，也取决于任务和表达方式的覆盖；增大数据量有时能扩展覆盖，有时也会带来重复、噪声或相互冲突的目标。质量和多样性本身也可能互相牵制。

不同研究给出的不是单一数据配方，而是带边界的观察：

| 研究 | 观察 | 适用边界 |
| --- | --- | --- |
| [FLAN，2022](https://arxiv.org/abs/2210.11416) | 在多种模型上用指令描述的任务集合微调，改善了论文评测中的若干未见任务表现 | 结论限于论文中的模型、任务、数据混合与评测设置；不能据此断言任务越多总越好 |
| [LIMA，2023](https://arxiv.org/abs/2305.11206) | 65B LLaMA 用 1,000 条精选问答做监督微调，在论文的人评中表现较强；其单轮训练模型的多轮测试仍显示出分布外问题 | 该结果不能推出所有模型都只需 1,000 条数据；论文的对照、模型和小规模多轮评测均有限 |
| [QDIT，2024](https://aclanthology.org/2024.findings-emnlp.195/) | 在其数据和实验中，质量与多样性存在取舍；增加多样性改善了最差切片的指令跟随表现 | 指标和增益取决于研究的数据集、模型及多样性定义，不是通用排序规则 |

因此，数据审核至少要分别检查：

1. 目标回答是否正确，并满足指令中的格式、长度或约束。
2. 样本是否覆盖目标任务、表达方式、难度和多轮上下文。
3. 重复、模板化、错误示范和相互矛盾的目标是否集中在特定数据源或切片。
4. 训练和评估数据是否区分，模型是否只学会了标注模板而未改善目标行为。

### Instruction Tuning 和 SFT 的关系

前面所说的 Instruction Tuning 是希望改善的行为目标；SFT（Supervised Fine-Tuning，监督微调）是用带目标输出的样本做监督训练的方法。二者常结合，但 SFT 也可用于非对话任务，指令微调也可能与偏好或其他训练阶段组合。阅读论文和框架配方时，应核对实际数据、目标和更新规则，不要只凭方法名推断流程。

### Instruction Tuning、RLHF、DPO 的关系

一种常见但非必经的后训练路径是：

```text
Base Model
  -> Instruction Tuning / SFT
  -> Preference Optimization, such as RLHF or DPO
  -> Safety tuning and evaluation
```

Instruction Tuning / SFT 用示范回答提供可模仿的目标；RLHF 或 DPO 等偏好优化方法则利用比较信号调整回答的相对偏好。InstructGPT 论文把示范 SFT、奖励模型和 PPO 排成三阶段流程，但这只是一个来源明确的案例，不是所有模型都必须照搬的配方。[InstructGPT](https://arxiv.org/abs/2203.02155)

偏好数据中“更好”的定义由任务、标注规则和评估人群决定。优化它不保证真实用户体验一定改善。常见的目标可能包括：

1. 更有帮助。
2. 更真实。
3. 更安全。
4. 更符合对话风格。
5. 更少输出用户不喜欢的答案。

### 单轮和多轮指令

单轮指令：

```text
User: 解释什么是 overfitting。
Assistant: ...
```

多轮指令：

```text
User: 解释什么是 overfitting。
Assistant: ...
User: 那怎么缓解？
Assistant: ...
```

多轮数据训练模型：

1. 记住上下文。
2. 理解追问。
3. 保持对话一致性。
4. 根据历史信息回答。

如果训练集几乎只有单轮数据，模型就缺少对追问、历史指代和多轮约束的直接监督；预训练或其他数据可能提供部分泛化能力，但不能替代目标场景上的多轮评估。LIMA 的单轮模型能在部分对话中延续上下文，但论文的 10 段多轮测试中有 6 段在三轮内未能跟随提示；加入 30 段多轮样本后，论文报告该测试的对话表现改善。这说明监督覆盖会改变所测行为，不能据此估算所有模型所需的多轮数据量。[LIMA 多轮分析](https://arxiv.org/abs/2305.11206)

### System Prompt 的作用

System prompt 通常是序列化对话中用于提供较高优先级指令的消息，可向模型提供身份、风格或任务规则等上下文；具体角色优先级由模型和模板约定决定。它本身不是权限控制或安全隔离机制；模型是否按它执行仍取决于训练、模板、运行时策略和具体输入。

例如：

```text
You are a helpful, honest, and harmless assistant.
```

它可以表达希望模型遵循的要求，例如：

1. 身份。
2. 语气。
3. 安全规则。
4. 工具使用规范。
5. 输出格式。

因此，不能把“写入 system prompt”当作规则已被可靠执行。重要约束需要在真实提示、冲突指令和边界样本上测试；涉及访问控制或工具权限时，还要由系统侧机制执行。

### 合成指令数据

合成指令数据可以减少逐条撰写的工作，也能围绕目标能力扩展样本；生成调用、去重过滤、质量审核和训练评估仍有成本。Self-Instruct 给出一个具体流程：用少量人工任务作种子，让 GPT-3 生成新任务及输入/输出，再过滤无效或相似样本。该研究在其 GPT-3 实验中生成并过滤出 52,445 条指令和 82,439 个实例；作者抽查 200 个实例时也观察到输出含有噪声。论文报告的基准收益属于该模型、数据和 Super-NaturalInstructions 评测设置，不能推成合成数据总比人工数据便宜或更有效。[Self-Instruct](https://arxiv.org/abs/2212.10560)

使用合成数据时，应保留生成模型与版本、种子任务、生成提示、过滤规则和抽检结果，并把模型在目标任务切片上的表现与数据量一起比较。若生成样本只换措辞、格式高度重复或答案本身有误，增加条数可能只是重复放大同一偏差。

### 指令微调的评估

评估要与训练时承诺改善的行为对应，不能只看训练 loss。可以固定 tokenizer、模板、提示和解码参数，在未参与训练的任务与多轮切片上检查指令遵循、事实、代码/数学、格式、拒答和长上下文表现；涉及偏好时，记录盲评人群、成对比较规则和分歧，而不是只报一个总体分数。

训练 loss 下降只说明模型在所选监督 token 上更贴近目标序列，不证明回答更准确或用户体验更好。InstructGPT 既报告其 API 提示分布上的人类偏好，也检查公开 NLP 基准；这两个结果衡量不同问题，论文讨论也限定在自己的提示与标注设定。[InstructGPT 评估](https://arxiv.org/abs/2203.02155)

### 19 讲·指令数据的失败模式

#### 坑 1：训练和推理 chat template 不一致

训练与推理格式不一致会改变模型看到的 token 序列，但具体影响随模型和模板而异。应核对 tokenizer/template 版本、generation prompt 和结束标记，再用固定 checkpoint 做对照。

#### 坑 2：loss mask 和训练目标不一致

若目标是 assistant-only，却意外把 user token 计入 loss，或把所有 assistant label 都屏蔽，实际优化目标就和预期不符。检查有效目标 token 数、assistant 起止位置及 padding/end token 的标记；若任务本来要预测完整对话，则不应机械套用 assistant-only mask。

#### 坑 3：数据太模板化

格式高度重复可能让模型更常复用固定回答模式；是否损害目标行为要通过不同措辞、任务类型和对话切片评估。

#### 坑 4：过度依赖合成数据

生成模型的错误、偏见和重复模式若未筛查，可能进入训练目标；同时还要核算生成、过滤、人工抽查和训练成本。

#### 坑 5：只做 helpful，不做 safety

如果评估只奖励 helpfulness 而不检查安全和拒答，模型可能在部分危险请求上给出不合要求的响应。要用明确的安全切片检验目标之间的冲突，不能把单一分数当作安全保证。

### Instruction Tuning 的行为差分实验

Instruction Tuning 是目标，SFT 是常见实现方式。要验证哪些监督带来了行为变化，可从同一个 base checkpoint 做消融：通用续写基线、单轮指令样本、多轮样本，以及格式约束样本。除目标数据变量外，要对齐优化器、学习率、训练步数或计算预算，并分别记录输入 token 数与实际参与 loss 的目标 token 数；若数据量不同，还需报告训练样本量和有效监督 token 数，避免把训练量差异误当作数据类型的效果。评估指令遵循、角色边界、格式通过率、原始语言建模损失和安全切片。

Chat template 是实验变量而不是装饰。模板把角色、轮次和结束状态变成具体 token 序列；格式改变后，条件输入也随之改变。最小反事实实验是：用同一批权重分别以训练模板和一个删去控制标记的模板推理，比较首 token 分布、停止位置和多轮一致性，并把差异解释为该模型、提示与解码设定下的观察。

对 assistant-only loss 的解释也要区分“作为上下文”和“作为目标”：system/user token 可以继续影响后续预测，即使它们的 label 被屏蔽。纳入上下文 token 的 loss 会改变目标 token 集合和平均 loss 的分母；它是否有害不能脱离训练目标判断。前面的算例展示了为什么比较 loss 时必须确认监督口径一致。

### 19 讲·指令数据的反例与边界

1. 误区：训练 loss 下降就说明模型更会遵循真实用户意图。
   纠正：loss 只衡量所选目标 token；目标行为要用独立任务和用户场景评估。

2. 误区：屏蔽 user label 后模型就“看不见”用户问题。
   纠正：label mask 控制目标位置，user token 仍作为上下文参与后续预测。

3. 误区：system prompt 能单独保证安全或权限边界。
   纠正：prompt 是模型输入的一部分；关键权限要由运行时和工具侧机制执行。

4. 误区：单轮 benchmark 足以代表对话能力。
   纠正：多轮、格式、长上下文和安全行为需要各自的测试切片。

### 19 讲·指令模板的复核实验

1. 用自己的话解释 base model 和 instruct model 的区别。
2. 写一个单轮 instruction tuning 样本。
3. 写一个多轮 chat template 示例。
4. 说明 assistant-only 目标下哪些标签被屏蔽，为什么这些 token 仍会作为上下文。
5. 设计一个小型数据审计，区分回答正确性、任务覆盖、重复和安全边界。

### 19 讲·从指令数据到行为变化的关键结论

这一讲的关键关系：

1. Base model 学的是续写，不天然等于助手。
2. Instruction Tuning 通过指令及目标响应样本，尝试提高模型在指定任务下生成目标回答的概率。
3. 对话 SFT 常用 assistant-only loss，但监督边界由数据任务和模板决定；label mask 不会屏蔽上下文。
4. Chat template 把角色和轮次编码成模型实际接收的输入序列。
5. 指令数据的正确性、覆盖和分布会影响行为，但模型行为还受预训练、模板、目标和评估设置影响。
6. SFT 与偏好优化经常组合，阶段顺序和数据来源并非固定流水线。

### 19 讲·Instruction Tuning 资料边界

InstructGPT 对特定提示分布上的 SFT、偏好比较与 PPO 路线提供一手案例（[Ouyang et al., 2022](https://arxiv.org/abs/2203.02155)）；FLAN、LIMA 和 Self-Instruct 分别展示多任务指令微调、小规模精选示范和模型生成指令的实验及边界（[FLAN](https://arxiv.org/abs/2210.11416)、[LIMA](https://arxiv.org/abs/2305.11206)、[Self-Instruct](https://arxiv.org/abs/2212.10560)）；质量与多样性的条件性比较见 [QDIT，EMNLP Findings 2024](https://aclanthology.org/2024.findings-emnlp.195/)。模板序列化和 generation prompt 以 [Transformers v5.17.0 文档](https://huggingface.co/docs/transformers/v5.17.0/chat_templating)为例；assistant-only mask 的模板标记以 [TRL v1.16.0 文档](https://huggingface.co/docs/trl/v1.16.0/chat_templates)为例。2026 年后训练综述按轨迹来源讨论 off-policy/on-policy 方法，是方法关系图而非唯一训练流程（[Zhao et al., 2026, arXiv:2604.07941](https://arxiv.org/abs/2604.07941)）。以上来源只支持对应论文和版本范围；模板、数据许可和训练效果仍须按所用 tokenizer、模型、目标与评估设置核验。

## 第 20 讲：SFT

### 20 讲·SFT 的监督边界

SFT 是大模型后训练中的一种监督训练方法。第 19 讲讨论指令数据和目标选择，本讲进一步说明怎样把对话变成 next-token 训练信号。训练结果取决于样本、模板、目标 mask、优化设置和评估任务；做过 SFT 不等于模型必然正确理解意图或具备安全边界。

这一讲围绕以下问题展开：

1. SFT 的训练目标是什么。
2. SFT 数据如何组织成模型输入。
3. 为什么要做 label mask。
4. 全参微调、LoRA 和 QLoRA 的区别。
5. SFT 中常见的数据、训练和评估问题。
6. SFT 和 pretraining、RLHF、DPO 的区别。
7. 如何用数据切片和消融实验判断 SFT 到底改变了什么行为。

### SFT 是什么

SFT 是 Supervised Fine-Tuning，中文通常叫监督微调。

它的基本思想是：给模型输入和目标输出样本，通过监督学习提高目标 token 序列在给定上下文中的概率。这里的“模仿”描述训练信号，不保证生成内容为真，也不保证模型在训练样本之外遵循同一行为。

在聊天模型里，SFT 样本通常长这样：

```text
System: You are a helpful assistant.
User: 什么是梯度下降？
Assistant: 梯度下降是一种通过沿负梯度方向更新参数来最小化损失函数的优化方法。
```

模型输入通常是按模型对应的 chat template 序列化后的对话 token。聊天 SFT 的一种常见配置是只把 assistant 回答作为目标；例如 [TRL v1.16.0 的 SFTTrainer](https://huggingface.co/docs/trl/v1.16.0/sft_trainer) 将其作为可选的 `assistant_only_loss` 设置，并要求模板提供 assistant mask。究竟监督回答、整段对话还是其他片段，仍由任务和数据配方决定；模板与 tokenizer 不匹配会改变实际输入边界。

### SFT 和预训练的区别

预训练和 SFT 都可以用 next-token prediction，但数据和目标不同。

按常见的自回归语言模型配方，可以从以下方面对照（具体数据和目标仍因模型而异）：

1. 预训练语料通常覆盖较广，包含多种文本或其他模态来源。
2. 目标是学习语言、知识和通用模式。
3. 常见做法是对语料中的多个 token 位置计算 loss，也可能按数据目标使用 mask。
4. 产物是 base model。

SFT：

1. 数据是指令、对话或任务样本，通常希望目标示范可靠且覆盖目标行为。
2. 目标是拟合任务示例中指定的输出。
3. 聊天数据常对 assistant 回答计算 loss；其他目标也可以监督更多位置。
4. 产物可以是 instruct/chat checkpoint，也可以是任务适配器或中间模型。

二者都可以使用 next-token prediction，差异主要来自数据分布、上下文组织和哪些 token 被指定为目标。SFT 常用于调整指令响应方式，但单靠这个目标不能保证答案正确、按真实用户意图行动或安全拒绝。

### SFT 训练目标

给定上下文 `x` 和目标 token 序列 `y=(y_1,\ldots,y_T)`，自回归 SFT 的一种常见目标是最大化：

~~~math
\max_\theta P_\theta(y \mid x)
~~~

也就是让模型在看到上下文以及目标序列中先前 token 后，提高下一个目标 token 的概率。实际聊天数据还要由模板决定上下文边界，并由 labels/mask 决定哪些 token 计入目标。

如果目标回答 token 是：

~~~math
y_1,y_2,\ldots,y_T
~~~

训练目标是：

~~~math
\max_\theta \sum_{t=1}^{T}\log P_\theta(y_t \mid x,y_{1:t-1})
~~~

等价于最小化所选目标 token 的负对数似然；只有 assistant 回答被选为目标时，它才是 assistant-only cross entropy。下面会把 token 位置和有效目标数明确写出。

### 数据格式

常见 SFT 数据格式包括三类。

第一类：instruction-output。

```json
{
  "instruction": "解释什么是 overfitting",
  "input": "",
  "output": "Overfitting 指模型在训练集上表现很好，但在新数据上表现变差。"
}
```

第二类：messages。

```json
{
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "解释什么是 overfitting"},
    {"role": "assistant", "content": "Overfitting 指模型在训练集上表现很好，但在新数据上表现变差。"}
  ]
}
```

第三类：多轮对话。

```json
{
  "messages": [
    {"role": "user", "content": "什么是过拟合？"},
    {"role": "assistant", "content": "过拟合是模型过度贴合训练数据。"},
    {"role": "user", "content": "怎么缓解？"},
    {"role": "assistant", "content": "可以使用更多数据、正则化、早停和数据增强。"}
  ]
}
```

真实训练前，需要把结构化消息通过与模型匹配的 chat template 转成 token 序列，并检查实际序列化结果中的角色边界、结束标记和 generation 前缀。JSON 的字段名称本身不是模型输入。

### Label Mask

SFT 的关键实现细节之一是 labels。`input_ids` 决定模型能读取的上下文，labels 决定哪些下一个 token 是监督目标；两者相关，但不是同一张 mask。

假设 token 序列是：

```text
<system> ... <user> ... <assistant> A B C <eos>
```

一种常见的 assistant-only 目标是：

```text
system/user token: 作为上下文读取，但不作为目标
assistant 回答及约定结束标记: 作为目标
```

在 PyTorch 里常用 `-100` 表示 `ignore_index`；[PyTorch 2.14 的 CrossEntropyLoss](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html) 对等于该值的类别索引目标不计算这一项损失，也不产生对应的 logits 梯度：

```text
input_ids: [system tokens, user tokens, assistant tokens]
labels:    [-100, ..., -100, assistant labels]
```

也可以为特定任务监督更多角色或片段。若目标位置与预期不符，训练 loss 仍可能下降，却优化了另一种行为；因此应直接检查序列化后的 token、shift 后的 labels 和有效目标数。

### 一个简化的 Label 构造例子

假设序列是：

```text
[USER, 10, 11, ASSISTANT, 20, 21, EOS]
```

对应 labels 可以是：

```text
[-100, -100, -100, -100, 20, 21, EOS]
```

在这份写法中，labels 与输入 token 按位置对齐；因果语言模型会把位置 `t` 的 logits 对齐到位置 `t+1` 的目标 token。具体由模型内部还是训练调用方执行 shift，取决于所用接口，因此不能在两处重复错位。

所以你要同时理解两件事：

1. attention mask 或因果 mask 控制模型在计算表示时可读取哪些位置。
2. label mask 控制哪些目标 token 参与 loss。
3. causal LM 的 shift 把位置 `t` 的预测与下一个 token 对齐。

### 最小 demo：用 ignore_index 只计算 assistant loss

下面这个 demo 用 PyTorch 展示 causal LM 的 next-token 对齐和 `ignore_index`。`labels` 与 `input_ids` 按 token 位置对齐；模型位置 `t` 的 logits 预测 `labels[t+1]`，因此计算交叉熵前要把 logits 和 labels 分别向相反方向切一位。`-100` 只屏蔽目标 label，不会屏蔽该 token 作为上下文输入。

```python
import torch
import torch.nn.functional as F


torch.manual_seed(0)

batch_size = 1
seq_len = 6
vocab_size = 10

logits = torch.randn(batch_size, seq_len, vocab_size)
labels = torch.tensor([[-100, -100, -100, 4, 5, 6]])

shift_logits = logits[:, :-1, :].contiguous()
shift_labels = labels[:, 1:].contiguous()
active_positions = (shift_labels != -100).sum().item()
if active_positions == 0:
    raise ValueError("the batch must contain at least one next-token target")
loss = F.cross_entropy(
    shift_logits.view(-1, vocab_size),
    shift_labels.view(-1),
    ignore_index=-100,
)

print("active next-token targets:", active_positions)
print("loss:", round(loss.item(), 4))
```
> **代码状态：已验证（2026-10-07；Python 3.13.13；PyTorch 2.12.0+cpu）**


输出中 `active next-token targets` 应该是 3：logits 的位置 2、3、4 分别预测 label 位置 3、4、5 的 token `4、5、6`。前两个有效 assistant token 仍能利用 system/user 上下文，但这些上下文 token 自身不作为预测目标。该 demo 使用随机 logits，只验证 mask 和 shift 的索引关系，不衡量模型质量。

### Label Mask 的手算例子

把一条对话写成角色 token 后，假设序列为：system、user、assistant、assistant 内容、EOS。若只有 assistant 内容和 EOS 参与 loss，labels 可以写成：

```text
input:  [SYS, U1, U2, ASST, A1, A2, EOS]
label:  [-100,-100,-100,-100, A1, A2, EOS]
```

这里的 `-100` 不是词表中的 token，而是损失函数的 ignore index。它不会阻止 user token 进入 attention；模型仍然需要读取问题，才能预测 A1。若 assistant 起始标记按该训练配方不作为目标，它就对应一个被忽略的 label；padding 则应按 batch 的目标约定屏蔽，不能误当成真实 EOS。实际问题可从 shift 后首个有效目标、padding 行和模型的结束配置逐项定位。

可以用三条检查验证实现：有效 label 数是否等于预期目标 token 数；不同长度样本的归一化方式是否符合训练目标；把 user 内容改写而保持 assistant 目标不变时，模型是否仍能利用上下文。第三项需要在固定设置下比较输出或任务指标，不能只由 loss mask 的形状推出。这个例子把“mask”从代码细节还原成了训练目标的选择。

### Packing 和 Padding

SFT 样本长度差异很大。

训练时常见处理：

1. padding：短样本补齐到 batch 最大长度。
2. truncation：太长样本截断。
3. packing：把多个短样本拼成一个长序列。

Padding 简单但可能浪费计算。

Packing 可以减少 padding 带来的空算，但要先确定拼接后的样本是否应互相可见。使用普通 causal attention mask 时，EOS 或 end-of-turn token 标出序列边界，却不会自动阻断后一个样本读取前一个样本的 token；[ACL 2024 的预训练研究](https://aclanthology.org/2024.acl-long.427.pdf)将普通拼接与文档内隔离 mask 分开比较，其效果和运行代价只适用于该论文的模型、数据与任务设定。对 SFT 来说，应按目标决定采用独立样本的 attention mask，还是有意接受跨样本上下文。

无论选择哪种策略，都要检查：

1. 样本边界。
2. EOS 或 end-of-turn token。
3. loss mask 不能串样本错位。
4. 多轮对话不能被错误截断。

还要逐项核对 label shift 是否跨过样本边界、结束标记是否参与监督、padding 目标是否被忽略，以及多轮对话截断后角色和 assistant turn 是否仍完整。仅在文本间插入 EOS 不能代替 attention 隔离；反过来，跨样本可见也不必然是 bug，关键是它是否符合训练样本的条件独立假设和目标。

### 全参微调、LoRA 和 QLoRA

三种方式的取舍可先从哪些参数参与更新、需要保存什么状态来理解。表中的资源差异用于提出测量问题，不代表任务效果排名。

| 方式 | 可训练部分 | 主要资源差异 | 需要验证的边界 |
| --- | --- | --- | --- |
| 全参微调 | 基座参数整体更新 | 需为基座参数计算/保存梯度与优化器状态，另需保存激活 | 目标覆盖、学习率和步数会影响泛化及原有能力 |
| LoRA | 冻结基座，在选定线性层训练低秩矩阵 | 不为冻结基座权重保存梯度和优化器状态，但仍需存基座权重、前向所需激活和适配器状态 | rank、目标层和数据决定适配效果；小参数量不等于质量必然较差或相同 |
| QLoRA | 量化冻结基座，并训练 LoRA 适配器 | 进一步减少基座权重表示占用；激活、适配器优化器状态及临时工作区仍占显存 | 量化格式、计算精度、内核和任务可能影响数值与速度 |

全参微调允许优化器直接调整整个参数集合；它有更大的可调参数空间，但不因此天然拥有更高的实际任务效果。LoRA 则把某个权重矩阵的更新限制为低秩分解。令原矩阵 $W_0\in\mathbb{R}^{d_{\mathrm{out}}\times d_{\mathrm{in}}}$，rank 为 $r$，则常见形式为：

~~~math
W=W_0+\frac{\alpha}{r}BA,\qquad A\in\mathbb{R}^{r\times d_{\mathrm{in}}},\quad B\in\mathbb{R}^{d_{\mathrm{out}}\times r}
~~~

$\alpha$ 是缩放系数；需要训练的矩阵参数数为 $r(d_{\mathrm{in}}+d_{\mathrm{out}})$。例如只看一个 $4096\to11008$ 的线性层，若 $r=8$，完整矩阵有 $4096\times11008=45,088,768$ 个权重；adapter 有 $8\times(4096+11008)=120,832$ 个参数。比值为 $120,832/45,088,768\approx0.00268$，即该矩阵权重数的约 $0.268\%$。这是一个单层的参数量玩具例，不计偏置或其他层，也不代表全模型显存、训练吞吐或质量会按同一比例变化。

低秩分解压缩的是可训练增量，不是让基座前向消失：模型仍要读取基座权重、保存反向计算所需激活，并执行底座前向。[LoRA 原论文](https://arxiv.org/abs/2106.09685)在指定的 RoBERTa、DeBERTa、GPT-2 和 GPT-3 评测中报告了与全参微调相当或更好的结果；这支持“低秩方法在一些设定有效”，不能推出每个任务都相当，也不能把它概括为必然较低的表达能力。

QLoRA 再把冻结的预训练权重用低比特表示，通过量化基座反向传播并更新 adapter。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)报告了 4-bit NF4、double quantization 与 paged optimizer 的组合；在该论文的对照实验中，QLoRA 在若干模型和任务上接近 16-bit 全参微调，但作者明确指出未证明 33B、65B 模型也达到相同表现。它降低基座权重存储量，但实际峰值仍取决于序列长度、batch、激活、优化器状态和临时内存；论文的显存与性能结果不是所有模型、硬件和数据的保证。部署时是否合并 LoRA、如何反量化以及支持哪些量化格式，也取决于所用实现。

### 学习率和训练轮数

SFT 数据常比预训练数据少得多，模型可能更快适配目标分布，也可能过度拟合训练样本；是否发生要看验证集和真实目标任务。

常见注意点：

1. 学习率不能太大。
2. epoch 不能盲目太多。
3. 需要 validation set。
4. 需要保留 base capability eval。
5. 需要观察是否出现灾难性遗忘。

因此不应把“再训几个 epoch”当作固定配方。应同时记录有效监督 token 数、训练/验证损失和目标任务表现；同样的 epoch 数在不同数据量、打包方式和 mask 下意味着不同更新量。

### Catastrophic Forgetting

灾难性遗忘指模型适配新任务时，在先前任务或分布上的表现下降。它是一种需要实际测量的风险，不是每次 SFT 都会出现，也不能只凭训练集 loss 或参数更新方式判断。对 Llama 2 7B Chat 的[一项研究](https://arxiv.org/abs/2401.05605)在限定数据和训练配置下观察到 LoRA 微调也可能出现遗忘；该结果提醒我们 PEFT 不能自动保证旧能力不退化，但不能外推为所有模型的固定退化幅度。

排查时把“可能原因”变成可检验变量：固定数据与训练步数，比较学习率或 rank；固定优化配置，比较数据覆盖；对同一检查点分别测新任务和预先选定的旧能力任务。可用保留集、混合数据或正则化作为实验控制项，但它们的收益需要在目标任务和资源预算内验证，不能视为通用修复。

### SFT 数据质量检查

训练前要检查：

1. 是否有空回答。
2. 是否有角色错乱。
3. assistant 回答是否真实正确。
4. 是否有安全违规样本。
5. 是否有重复模板。
6. 是否有过长样本。
7. 是否包含泄漏评估集。
8. chat template 是否能正确解析。

很多 SFT 失败不是算法问题，而是数据和格式问题。

### SFT 评估

评估要同时看训练目标是否拟合、目标任务是否改善，以及目标范围外是否出现明显回归。可先固定一组训练前基线，再用相同提示、解码设置和评分标准比较训练前后；数据少时还要注意验证集是否与训练样本高度相似。

评估要覆盖多个层面：

1. validation loss。
2. 指令遵循能力。
3. 格式遵循能力。
4. 数学、代码、知识问答。
5. 多轮对话。
6. 安全拒答。
7. 原始 base capability 是否下降。
8. 人类偏好或 pairwise win rate。

不要只看 SFT loss。它只度量所选目标 token 在 teacher-forced 前缀下的预测，不等同于自由生成质量。模型可能 loss 下降，但在不同措辞、长度、多轮上下文或安全边界上仍表现不佳；因此要按目标任务分切片，并把旧能力评测作为回归检查。

### SFT 和 RLHF/DPO 的关系

一种常见流程是在 SFT 后再做偏好优化；[InstructGPT](https://arxiv.org/abs/2203.02155)是一个具体例子，但这不是每种后训练流程的强制顺序。

原因是：

1. SFT 样本可以提供指令响应的起点。
2. 已有的响应能力可供后续生成和比较回答。
3. 偏好目标利用回答间的偏好关系调整策略，但其起点、数据形式和实现由具体方法决定，也不保证独自补齐所有指令或事实能力。

可以这样概括训练信号的差异：

```text
SFT：按示范目标调整 token 概率
偏好优化：按回答间的偏好信号更新模型（具体目标因方法而异）
```

### 20 讲·SFT 训练现场的故障模式

#### 坑 1：labels 没有正确 mask

若目标本应只覆盖回答，模型却被训练去预测 user/system token，优化目标就与预期不同；其他任务也可能有意监督整段对话。

#### 坑 2：chat template 和 tokenizer 不匹配

特殊 token 没加、EOS 不正确、assistant 起始标记不一致，都会影响训练。

#### 坑 3：训练集答案质量差

SFT 是模仿学习。答案错，模型就学错；答案啰嗦，模型就学啰嗦。

#### 坑 4：只看 validation loss

SFT loss 下降不代表真实用户体验提升。

#### 坑 5：过拟合小数据集

模型在训练样本上表现好，但泛化到真实指令时变差。

#### 坑 6：能力退化没被发现

只测指令任务，不测代码、数学、多语言和安全，容易漏掉回归。

### SFT 改变行为的可验证路径

SFT 的关键不是“把 labels 设成 `-100`”这一句实现口诀，而是明确模型究竟被要求预测什么。令序列为 $u_1,\ldots,u_L$，$m_t\in\{0,1\}$ 表示位置 $t$ 的 token 是否是有效训练目标；padding 和被忽略的上下文位置取 0。因果语言模型的位置 $t-1$ 的 logits 预测 $u_t$，所以 assistant-only 的 token 平均损失可写为：

~~~math
L_{\mathrm{SFT}}=-\frac{1}{\sum_{t=2}^{L}m_t}\sum_{t=2}^{L}m_t\log p_\theta(u_t\mid u_{1:t-1})
~~~

分母是参与损失的目标 token 数；它排除 padding 和被 mask 的位置。若一个 batch 内直接按有效 token 总数取平均，较长回答会贡献更多 token 项，并非每条回答等权。若改为先算每条回答的 token 平均、再对回答平均，梯度权重会不同，需要明确选择哪种目标。

用三个 assistant 目标 token 手算：假设模型在各自正确前缀下给正确 token 的概率依次为 $1/2$、$1/4$、$1/2$，且这三个位置的 $m_t=1$。自然对数下，逐项负对数概率是 $-\ln(1/2)=0.6931$、$-\ln(1/4)=1.3863$、$-\ln(1/2)=0.6931$ nats；相加为 $2.7726$，再除以有效目标数 3，得到 $L_{\mathrm{SFT}}\approx0.9242$ nats/token。被 mask 的 user token 虽不出现在求和里，仍可作为这些预测的上下文。若把它们重新纳入目标，损失值和梯度都会改变；改变后的效果取决于任务和数据，不应预先断言一定有害或有益。

排查 SFT 后能力变化时，应一次改变一个因素，而不是先改多个超参数。先固定基座和训练步数，只替换 chat template；再固定 template，只改变 label mask；最后比较不同数据覆盖。每次实验记录目标 token 数、相同切片上的任务指标、输出长度和旧能力回归，才能区分格式差异、监督信号差异与样本覆盖差异。

LoRA 的低秩矩阵形式和参数量已在前文逐步计算。选择 rank 和目标层时，应把它们作为待比较的配置，用固定数据与评测切片测量任务效果和旧能力回归；参数少本身不能预测质量。QLoRA 还要比较基座量化格式、峰值显存和运行速度。最终决策应同时看可训练参数、峰值显存、训练吞吐、部署路径、业务指标和回归表现，而不是只比较训练是否能启动。

### 20 讲·Label mask 的反例与边界

1. 误区：SFT 数据越多越好。
   纠正：低质量数据会让模型学到错误和坏风格。

2. 误区：SFT loss 越低模型越好。
   纠正：还要看真实任务、偏好、安全和能力回归。

3. 误区：LoRA 一定不如全参微调，或参数更少就一定等效。
   纠正：LoRA 在原论文的一些设定中达到相当表现；结果依任务、数据、rank 和目标层而变，参数量不能单独给出质量排序。

4. 误区：SFT 能解决所有对齐问题。
   纠正：SFT 主要教模型模仿好回答，偏好、安全和拒答边界通常还需要额外训练和评估。

### 20 讲·SFT mask 的复核实验

1. 写一个 `messages` 格式的 SFT 样本。
2. 给定一段 user/assistant token 序列，手写 labels 和 `-100` mask。
3. 比较全参 SFT、LoRA、QLoRA 的优缺点。
4. 列出 SFT 数据清洗的 5 个检查项。
5. 设计一个 SFT 评估表，覆盖指令遵循、代码、数学、安全和多轮对话。

### 20 讲·从监督 mask 到 SFT 行为的关键结论

这一讲的关键关系：

1. SFT 用监督信号提高指定目标 token 序列在上下文中的概率。
2. 聊天 SFT 常选 assistant response 为目标，但 mask 由具体任务决定。
3. 目标 mask、attention mask 与 causal shift 控制训练中的不同环节。
4. Label mask、chat template、EOS 和 padding 都是关键实现细节。
5. LoRA/QLoRA 减少可训练参数或基座权重表示的占用，但资源和任务效果仍需实测。
6. SFT 评估不能只看 loss，还要看真实任务、安全、偏好和能力回归。

### 20 讲·SFT 资料边界

LoRA 的低秩适配形式与原始实验见 [Hu et al., 2021](https://arxiv.org/abs/2106.09685)，QLoRA 的量化基座微调设定见 [Dettmers et al., 2023](https://arxiv.org/abs/2305.14314)；LoRA 微调中遗忘风险的测量见 [Kalajdzievski, 2024](https://arxiv.org/abs/2401.05605)。`-100` 作为忽略目标的语义见 [PyTorch 2.14 CrossEntropyLoss 文档](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html)。实际 mask、padding、量化和 adapter 合并行为还要以所用框架版本与运行结果为准。参数量公式只描述可训练矩阵，不等于端到端显存、速度或质量收益。

## 第 21 讲：RLHF

### 21 讲·RLHF 的对象与假设

SFT 用示范回答提供一种监督目标，但一次示范不一定表达了偏好者对多个可接受答案的取舍。RLHF 将偏好比较转成模型优化信号；这个信号仍是有限标注和 Reward Model 学出的代理目标，不是人类意图或回答质量的完整真值。

这一讲围绕以下问题展开：

1. RLHF 要解决什么问题。
2. 偏好数据是什么。
3. Reward Model 如何训练。
4. PPO 在 RLHF 中扮演什么角色。
5. 为什么需要 KL penalty。
6. RLHF 和 SFT、DPO 的区别。
7. Reward hacking、over-optimization 等风险。

### RLHF 是什么

RLHF 是 Reinforcement Learning from Human Feedback，中文是基于人类反馈的强化学习。

一条代表性路线是先用示范训练 SFT policy，再用回答比较训练 Reward Model，最后用 PPO 优化 policy；[InstructGPT](https://arxiv.org/abs/2203.02155)展示了这条具体流程，但不同项目可采用不同阶段、反馈来源和优化方法。

这条路线的基本思想：

```text
用人类偏好训练一个 reward model，再用强化学习优化语言模型，让模型生成更符合人类偏好的回答。
```

一个典型流程：

```text
1. 训练 base model
2. 做 SFT 得到初始 assistant model
3. 收集偏好数据
4. 训练 reward model
5. 用 PPO 等 RL 方法优化 policy model
6. 做安全评估和人工评估
```

这里的 policy model 就是正在被优化的语言模型。

这条链路中有一个容易被忽略的事实：Reward Model 不是人类偏好的“真值函数”，而是从有限标注样本中学出的代理指标。第 21 讲说明它在 RLHF 中承担什么角色；第 23 讲再单独分析它的训练、分布偏移和被利用的方式。InstructGPT 在其 API prompt 分布的人评中报告了偏好提升，也指出模型仍会编造事实、漏跟指令；这不证明该流程能普遍提升所有任务或安全属性。把这些层次分开，才能理解为什么 reward 上升不自动等于模型变好。

### 为什么 SFT 之后还需要 RLHF

SFT 的训练数据通常只有一个目标回答。

但真实对话中，同一个问题可能有多个回答：

```text
回答 A：准确但太啰嗦
回答 B：简洁但漏掉关键条件
回答 C：平衡、准确、清晰
```

SFT 只告诉模型“模仿这个答案”，而 RLHF 可以利用人类偏好告诉模型“这些答案里哪个更好”。

偏好标注可以把若干质量维度纳入 rubric，例如：

1. helpfulness。
2. honesty。
3. harmlessness。
4. 简洁性。
5. 格式遵循。
6. 拒答边界。
7. 用户体验。

这些是可能纳入标注和评估的维度，并非 RLHF 自带的能力保证。比如，提高“安全”权重可能增加误拒答；提高“完整”偏好可能使回答变长。训练前要定义标注标准，再用独立任务集检查实际变化和冲突。

### 偏好数据

偏好数据通常是成对比较。

常见做法是对同一个 prompt 下的一对候选回答做比较，再由标注者依照给定标准选择更偏好的回答；候选可以来自已有 policy，也可以按其他采样方案构造。

例如：

```json
{
  "prompt": "解释什么是 dropout",
  "chosen": "Dropout 是训练时随机丢弃部分神经元来减少过拟合的方法。",
  "rejected": "Dropout 是一种让模型变快的优化器。"
}
```

其中：

1. `chosen` 是人类更偏好的回答。
2. `rejected` 是人类不太偏好的回答。

偏好数据不一定只比较正确性，也可能比较语气、完整性、安全性和有用性。`chosen` 表示在该 prompt、标注者和 rubric 下被选中的样本，不等同于客观正确或所有用户都会偏好的答案；数据覆盖和标注一致性会影响模型学到什么。

### Reward Model

Reward Model（奖励模型，RM）的目标是根据 prompt 和回答输出一个标量，帮助预测比较标签。

输入：

```text
prompt + response
```

输出：

```text
一个标量 reward
```

在训练和评估分布内，较高的分数应倾向对应被偏好的回答；它不是答案正确性、效用或安全性的绝对量尺。只比较同一 prompt 下的分差更有依据，不应把不同 prompt 的分数当成未经校准的统一等级。

常见做法是在同一 prompt 下比较 chosen 与 rejected：模型分别给两个回答打分，再用分差学习已标注的排序。这个目标让 Reward Model 能为 PPO 提供标量信号，但分数并没有跨 prompt 通用的绝对单位。Bradley–Terry 概率、pairwise loss 和可复算例子集中见[第 23 讲的 Pairwise Ranking Loss](#pairwise-ranking-loss)；本讲只需要记住，PPO 接收的是模型从偏好比较中学出的代理分数。

### Reward Model 如何接入策略优化

PPO 不直接读取人类比较标签，而是接收 Reward Model 对整条回答的标量分数。RM 应从偏好 pair 学习把 chosen 排在 rejected 前面，但这个分数只在其标注和生成分布附近提供排序信号，不是正确性分数，也没有绝对单位。Reward Model 的结构、评估和失效模式由第 23 讲集中展开。

### PPO 在 RLHF 中做什么

有了 Reward Model 后，我们希望优化语言模型，让它生成高 reward 的回答。

这就变成一个强化学习问题：

1. 状态：prompt 和当前生成上下文。
2. 动作：下一个 token。
3. 策略：语言模型的 token 分布。
4. 奖励：Reward Model 对完整回答的评分。

PPO 是一种常用 policy optimization 方法，用来更新语言模型参数。

在 PPO-style RLHF 中，四个组件各自持有不同状态：

| 组件 | 读取的数据或状态 | PPO 阶段的作用 | 通常是否更新 |
| --- | --- | --- | --- |
| Policy model | prompt、已生成前缀、当前 token 分布 | 采样回答并接受策略梯度更新 | 是 |
| Reference model | 同一 prompt 和生成前缀 | 提供起始策略的 token log probability，用于 KL shaping | 否 |
| Reward Model | prompt 与完整回答 | 输出序列级代理分数 | PPO 阶段通常冻结 |
| Value model | prompt 与生成前缀状态 | 估计未来 return，降低优势估计方差 | 通常与 policy 一起训练 |

一次 rollout 会把当前 policy 生成的回答交给 Reward Model 打分，同时用 reference 计算偏移惩罚；value model 提供 baseline，PPO 再用采样轨迹更新 policy。Policy 与 value 是否共享参数、RM 是否冻结等实现细节要以具体训练配方为准。

PPO 的 clipped objective（裁剪目标）不是“让每个 token 的概率都变大”，而是根据优势信号调整动作概率，并降低过大策略比率继续改善目标的收益。对某个状态 `s_t` 和动作 `a_t`，策略比率为：

~~~math
r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)}
~~~

优势估计 $A_t$ 表示该动作的估计回报相对于 value baseline 高还是低；$\epsilon$ 是控制裁剪范围的超参数。PPO 通过最大化以下 surrogate objective（代理目标）更新策略：

~~~math
L^{\mathrm{CLIP}}(\theta)=\mathbb{E}_t\left[\min\left(r_t(\theta)A_t,\;\mathrm{clip}(r_t(\theta),1-\epsilon,1+\epsilon)A_t\right)\right]
~~~

当 $A_t>0$ 时，目标倾向提高动作概率；当 $A_t<0$ 时，目标倾向降低动作概率。这里的 clipping 只裁剪代理目标的概率比率项，不是硬性的 trust-region 约束，也不保证更新后的策略比率一定落在 $[1-\epsilon,1+\epsilon]$。它在某个方向的比率超出范围后去掉进一步“改善”目标的激励，同时保留使目标变差的部分。[PPO 原论文](https://arxiv.org/abs/1707.06347)将其称为 clipped surrogate，并指出优化仍由采样与多轮 minibatch 更新组成。

用一项动作的假设值手算：旧策略给该 token 的概率为 0.20，新策略为 0.30，则 $r_t=0.30/0.20=1.5$。设 $\epsilon=0.2$、$A_t=0.5$，裁剪后的比率是 1.2；未裁剪项为 $1.5\times0.5=0.75$，裁剪项为 $1.2\times0.5=0.60$，取两者较小值后该项为 0.60。注意新策略的比率仍是 1.5；裁剪改变的是训练目标，不是把策略概率强制截断。真实 PPO 还会优化 value loss、可能加入 entropy bonus，并处理序列级奖励如何分配到 token，因此 RLHF 不能简化成“拿 reward 做一次交叉熵训练”。

### 为什么需要 Reference Model

如果只最大化 reward，模型可能为了骗过 Reward Model 而偏离原本语言能力。

Reference model 通常是冻结的 SFT checkpoint，用来度量 policy 相对起始分布的变化。这个正则项可以限制漂移，但不保证保留每项能力，也不构成安全边界。

固定 prompt $x$ 时，一个简化的 KL 正则化目标是：

~~~math
J_x(\theta)=\mathbb{E}_{y\sim\pi_\theta(\cdot\mid x)}[r_{\mathrm{rm}}(x,y)]-\beta D_{\mathrm{KL}}\left(\pi_\theta(\cdot\mid x)\Vert\pi_{\mathrm{ref}}(\cdot\mid x)\right)
~~~

这里 $r_{\mathrm{rm}}(x,y)$ 是 Reward Model 对完整回答的序列分数，KL 项比较当前 policy 与 reference 在所有可能回答上的分布；$\beta$ 控制两项的相对权重。训练实现通常用 rollout 近似这个目标。对采样到的回答，一种常见的逐 token log-ratio 估计为：

~~~math
\widehat{R}(x,y)=r_{\mathrm{rm}}(x,y)-\beta\sum_{t=1}^{|y|}
\left[\log\pi_\theta(y_t\mid x,y_{1:t-1})-\log\pi_{\mathrm{ref}}(y_t\mid x,y_{1:t-1})\right]
~~~

用一个单 token、两种可能输出的玩具分布手算。假设 policy 为 $(0.6,0.4)$、reference 为 $(0.5,0.5)$；两种回答的 Reward Model 分数分别为 $1.2$ 和 $0.8$。期望 reward 是 $0.6\times1.2+0.4\times0.8=1.04$。精确 forward KL 为 $0.6\ln(1.2)+0.4\ln(0.8)\approx0.0201$ nats；设 $\beta=2$ reward units/nat，则该 prompt 下的目标为 $J_x\approx1.04-2\times0.0201=0.9997$ reward units。相应地，采到第一个回答时 log-ratio 是 $\ln(1.2)\approx0.1823$，采到第二个时是 $\ln(0.8)\approx-0.2231$，样本惩罚可正可负；按 policy 分布取期望后才得到非负的精确 KL。完整回答还要沿 token 累加估计，结果受长度、EOS 位置和 tokenization 影响，因此要并看平均 KL、长度分布以及 reward 与人工偏好的关系，不能只盯最终 reward。

直觉：

```text
既要提高 reward，也不能偏离原模型太多
```

这样可以在奖励优化和分布漂移之间提供一个可调折中，但不能保证模型不会输出重复文本或钻 reward 空子。

### KL Penalty

KL penalty 惩罚当前 policy 和 reference model 的分布差异。

如果 policy 对某些 token 的概率变化太大，KL 会变大。

它的直接作用是让偏好奖励和策略漂移之间存在可调折中：

1. 限制 policy 相对 reference 的分布变化。
2. 在部分设置下抑制过快追逐 Reward Model 分数。
3. 让训练者观察 KL 与偏好提升之间的权衡。

这些效果不是保证：KL 不会发现 Reward Model 的错误，也不会自动保持语言质量、旧任务能力或安全行为。需要与独立评测一起调节系数。

KL 系数过小可能让 policy 更快偏离 reference，代理奖励风险随之增加；过大则可能限制偏好信号带来的改变。具体关系要在给定数据和模型下测量，不能把系数大小套成固定规律。

### RLHF 的训练流程

更具体的流程：

```text
1. 从 prompt 数据集中采样 prompt
2. policy model 生成回答
3. reward model 给回答打分
4. 计算 policy 和 reference 的 KL penalty
5. 得到最终 reward
6. 用 PPO 更新 policy model
7. 周期性评估安全、偏好、能力回归
```

在 PPO-style RLHF 中，preference pairs 往往先离线收集，policy rollout 则在训练过程中由当前策略反复生成；策略变化后，旧 rollout 与新策略的分布会不同。因此须区分固定偏好数据和在线采样数据，并按方法决定何时刷新 rollout。

### RLHF 和普通强化学习的区别

传统强化学习常见于游戏、机器人等环境。

在常见的 PPO-style 语言模型设置中：

1. action space 是巨大词表。
2. episode 是一段生成文本。
3. reward 常由 learned Reward Model 给出，是人类比较的代理信号。
4. Reward Model 常在完整回答后给序列级分数，再结合逐 token 的 KL shaping；不同实现也可有其他奖励分配。
5. 语言模型已经有很强的预训练先验。

这描述的是一种常见实现，不是所有 RLHF 定义的必要构件。它以已有语言模型为起点，用偏好监督调整生成分布，而非在真实世界中直接获得完整、无噪声的奖励。

### Reward Hacking

Reward hacking 指 policy 找到提高代理 reward 的捷径，但该变化没有带来相应的人类偏好改善。

例子：

1. 回答变得过度奉承。
2. 总是输出看似安全但无帮助的话。
3. 用模板化语言骗过 reward model。
4. 在 reward model 盲区输出错误内容。
5. 为了显得详细而胡编。

原因：Reward Model 只是人类偏好的近似，不是真实偏好的完美表达。

这不仅是概念上的风险。[Stiennon 等人在 TL;DR 摘要任务](https://arxiv.org/abs/2009.01325)中比较了不同优化强度：轻度优化时人工偏好改善；继续追逐一个较早版本的 Reward Model 后，人工偏好相对模型预测下降，极端时二者出现反相关。这个结果限于该摘要数据、模型和 reward 版本，说明需要测量优化强度，不代表所有任务必然出现相同拐点。

### 21 讲·Over-Optimization

过度优化是指 policy 越来越会提升代理指标，但这些提升没有继续转化为独立偏好或任务改善。摘要任务论文观察到 RM 分数与人工偏好逐渐分离；拐点取决于 RM、数据和优化强度，不能只用训练步数或单一 reward 阈值定义。

因此要保留未参与 RM 训练的偏好样本、独立评审和安全/能力回归评估，并按优化强度画出 RM 分数与外部结果的对照。

### RLHF 和 DPO 的关系

在本讲讨论的 PPO-style RLHF 配方中，常见组成是：

1. 显式 reward model。
2. PPO 或其他 RL 优化。
3. 在线采样。
4. KL 控制。

DPO 则直接使用偏好数据优化 policy，不显式训练独立的 Reward Model，也不在固定数据集微调过程中运行 PPO rollout。它仍使用 reference policy 定义隐式 reward 关系；原始 DPO 方法表明，可在其假设下把 KL 约束的 reward maximization 重写为偏好分类目标（[Rafailov et al., 2023](https://arxiv.org/abs/2305.18290)）。偏好数据本身可以由先前 policy 采样并标注，因此“训练时无需在线 rollout”不等于数据从未由模型生成。

简单对比：

```text
RLHF: preference data -> reward model -> PPO optimize policy
DPO: preference data -> directly optimize policy
```

DPO 的标准离线流程省去了显式 reward model 和 PPO 优化器，固定偏好数据集上的工程链路可以更简单；这不代表 DPO 在所有任务上都更稳定或质量更高。效果仍取决于偏好数据、reference 与 policy 的匹配、训练配置和独立评估。若需要根据新策略输出持续采样并更新偏好，仍需考虑在线优化或其他反馈闭环。

### RLHF 的评估

评估时要把用于优化的信号与独立的人类/任务结果并列，并尽量控制 prompt、解码、输出长度与评审标准。除了以下指标，还应报告测试分布、评审者和标注协议，避免把单一总分外推为普遍行为：

1. pairwise win rate。
2. reward model score。
3. 人工偏好评估。
4. helpfulness。
5. honesty。
6. harmlessness。
7. 拒答质量。
8. 原有能力回归。
9. reward hacking 检查。

不能只看 reward model score，因为模型可能过拟合 reward model。

### 一个 toy rollout：奖励为什么要延迟观察

把一次回答看成三个 token 动作：先给出结论，再给出理由，最后给出限定条件。Reward Model 只在完整回答结束后输出序列分数，分数本身没有标出是哪个 token 改变了质量。

做一个简化的 credit assignment 手算：完整回答结束时 Reward Model 给分 $R=2.0$；先忽略逐 token KL，设折扣 $\gamma=1$，则三个时刻的 Monte Carlo return 都是 2.0。若 value baseline 分别估计为 1.2、1.5、1.8，优势 $A_t=G_t-V(s_t)$ 依次是 0.8、0.5、0.2。实际 GAE、token KL 和采样噪声会改变这些优势；这个例子只展示序列级分数如何经过 return/value 估计进入策略更新。

回答长度也会影响累计 KL、可优化的动作数和终止位置；因此报告应同时给出 reward、长度、KL 与人工/客观任务指标，而不是把一个序列级 reward 当作每个 token 的独立质量标注。

### 21 讲·RLHF 的失败模式

#### 坑 1：偏好标注标准不一致

不同标注者对“好回答”的理解不同，会让 reward model 学到噪声。

#### 坑 2：Reward Model 泛化差

训练集上排序准确，但遇到新类型 prompt 打分不可靠。

#### 坑 3：KL 系数设置不合适

系数过小可能造成较大策略漂移，过大则可能压低偏好信号的作用；两种现象都需通过 KL、任务表现和人工偏好曲线判断。

#### 坑 4：只优化 reward score

Reward 上升但人类偏好下降，是 RLHF 的典型风险。

#### 坑 5：安全和 helpfulness 冲突

模型可能为了安全过度拒答，也可能为了 helpfulness 满足危险请求。

### RLHF 的闭环与可观测量

RLHF 不是一条只看最终 reward 的流水线。每个阶段都应保留可以诊断的数据：偏好标注的一致性，Reward Model 的分领域排序与校准，policy 采样的长度和分布变化，PPO 的优势估计、KL 距离、熵、value loss，以及人工和客观任务评估。

设 prompt 来自 $D_{\mathrm{prompt}}$，$r_{\mathrm{rm}}(x,y)$ 是完整回答的代理分数，把上面对固定 prompt 的目标对 prompt 数据集取平均，得到：

~~~math
J(\theta)=\mathbb{E}_{x\sim D_{\mathrm{prompt}}}\left[\mathbb{E}_{y\sim\pi_\theta(\cdot\mid x)}[r_{\mathrm{rm}}(x,y)]-\beta D_{\mathrm{KL}}\left(\pi_\theta(\cdot\mid x)\,\Vert\,\pi_{\mathrm{ref}}(\cdot\mid x)\right)\right]
~~~

这是 prompt 与回答分布上的期望目标；上一节的两回答数例展示了固定一个 prompt 时如何计算其中两项，实际任务还要对 prompt 分布求平均。单条 rollout 只能用抽样 token 的 log-ratio 估计序列 KL。这个式子显示了两个需要测量的方向：$\beta$ 过小可能鼓励追逐代理奖励，过大可能限制偏好适配。PPO 的 clipped objective 仅改变代理目标中的比率项，不是硬性限制，也不能修复错误的 reward 或替代分布外评估。

一个有区分力的实验是沿训练步数画四条曲线：Reward Model 分数、人工偏好、KL 距离和原始能力。若 RM 分数持续上升，而人工偏好持平或下降、KL 漂移或旧能力回归加重，就应怀疑代理目标过度优化；若人工偏好上升但安全误拒答也上升，应分开检查这些质量维度，不要只继续增加训练步数。

### 21 讲·奖励优化的反例与边界

1. 误区：RLHF 直接用人类实时给模型奖励。
   纠正：通常先用人类偏好数据训练 reward model，再用 reward model 提供训练信号。

2. 误区：Reward Model 分数越高模型越好。
   纠正：模型可能 exploit reward model，必须看人工评估和真实任务。

3. 误区：RLHF 可以替代 SFT，或所有方法都必须采用同一顺序。
   纠正：PPO-style RLHF 常以 SFT policy 初始化；这是代表性流程，不是所有偏好学习方法的统一要求。

4. 误区：KL penalty 越小越好。
   纠正：KL 系数会改变偏好适配与分布漂移的折中，方向和幅度需要用任务评估确定。

### 21 讲·从偏好到策略更新的关键结论

这一讲的关键关系：

1. PPO-style RLHF 用成对偏好训练代理 reward，再结合 rollout 优化 policy。
2. Reward Model 分数支持的是其标注分布下的排序预测，不是绝对质量量尺。
3. PPO 用优势和裁剪代理目标更新 policy；clip 不构成硬性的 KL/信赖域限制。
4. Reference KL 可以正则化策略漂移，但不能保证旧能力、安全或语言质量不变。
5. RLHF 可能改善标注所覆盖的偏好维度，也可能产生维度冲突、reward hacking 或过度优化。
6. 评估应并列 reward、人工偏好、任务切片、安全/误拒答、KL 和能力回归。

### 21 讲·RLHF 资料边界

InstructGPT 报告了 GPT-3 上示范 SFT、偏好 Reward Model 与 PPO 的具体三阶段流程和其 API prompt 分布评估（[Ouyang et al., 2022](https://arxiv.org/abs/2203.02155)）。PPO 原论文介绍 clipped surrogate，并在 Atari/机器人控制任务中评估通用算法；它不是专门的语言模型训练论文（[Schulman et al., 2017](https://arxiv.org/abs/1707.06347)）。摘要任务的人类反馈和 RM 过度优化观察限于 TL;DR 等论文设定（[Stiennon et al., 2020](https://arxiv.org/abs/2009.01325)）。DPO 将特定偏好模型与 KL 约束下的奖励优化重写为分类目标，效果范围依原论文假设和实验任务而定（[Rafailov et al., 2023](https://arxiv.org/abs/2305.18290)）。这些来源均不保证任意 RM、偏好数据或 PPO 超参数都能取得相同效果。

## 第 22 讲：DPO

### 22 讲·DPO 的监督边界

DPO 是偏好后训练的代表方法之一。标准 DPO 不显式训练独立的 reward model，也不在固定偏好数据集上运行 PPO rollout，而是把 chosen/rejected 比较写成一个直接优化 policy 的目标。

这一讲围绕以下问题展开：

1. DPO 想解决 RLHF 的什么问题。
2. DPO 使用什么数据。
3. DPO loss 的直觉是什么。
4. Reference model 在 DPO 中的作用。
5. DPO 和 RLHF、SFT 的区别。
6. DPO 的优点、局限和常见坑。
7. 如何从偏好数据、reference model 和长度效应判断 DPO 是否真的改善了行为。

### DPO 是什么

DPO 是 Direct Preference Optimization，中文可译为直接偏好优化。

它直接利用偏好对训练 policy，使它相对于 reference 更偏向 chosen response，而不是单独学习一个绝对 reward 分数。

偏好数据格式通常是：

```json
{
  "prompt": "解释什么是梯度裁剪",
  "chosen": "梯度裁剪是限制梯度范数，避免梯度爆炸导致训练不稳定的方法。",
  "rejected": "梯度裁剪是删除模型中不重要参数的方法。"
}
```

DPO 的目标：

```text
让模型相对更偏向 chosen，而不是 rejected
```

### DPO 为什么出现

第 21 讲介绍的 PPO-style RLHF 是一条代表路线：先用偏好数据训练 Reward Model，再由当前 policy 生成 rollout 并用 PPO 更新。标准离线 DPO 试图简化这条训练闭环：

1. 训练 reward model。
2. 在线采样回答。
3. 用 PPO 优化 policy。
4. 维护 reference model。
5. 调 KL penalty。
6. 处理 reward hacking 和训练不稳定。

它把固定偏好数据上的问题改写成一个更接近监督分类的目标：

```text
给定 chosen/rejected，直接更新 policy，让 chosen 比 rejected 更可能
```

### DPO 和 RLHF 的核心区别

RLHF：

```text
preference data -> reward model -> PPO -> policy model
```

DPO：

```text
preference data -> DPO loss -> policy model
```

标准 DPO 在这个训练阶段不显式训练 reward model，也不反复从当前 policy 在线采样；但它仍需要 reference policy，而且 preference pairs 可以由较早的模型生成后再标注。它与 KL 约束的 reward maximization 之间的联系依赖偏好模型等假设，下面会从这一目标推到 DPO loss。

### DPO 使用的数据

DPO 数据和 reward model 数据类似，都是 preference pair。

每条样本包括：

1. prompt。
2. chosen response。
3. rejected response。

DPO 不要求有单一目标回答，而是要求知道两个回答中哪个更符合偏好。

偏好可以来自：

1. 人类标注。
2. 强模型评判。
3. 安全规则筛选。
4. 用户反馈。
5. 专家偏好。

标注噪声、候选回答来源和 prompt 覆盖都会影响学到的排序；应按领域和来源切片检查，而不要只看训练集 loss。

### DPO 的直觉

对于同一个 prompt，policy 和 reference 都会为 chosen response $y_w$、rejected response $y_l$ 分配条件概率。标准 DPO 比较的是：policy 相对 reference 在多大程度上改变了 chosen 与 rejected 的概率差，而不只是要求 policy 单独提高 chosen 的概率。

直觉：

```text
policy 应该比 reference 更偏向 chosen，但不要无约束乱跑
```

### Reference Model 的作用

DPO 的标准目标使用冻结的 reference policy，常见选择是用于生成候选回答的 SFT checkpoint。它为 chosen/rejected 的序列 log probability 提供基线；在原始推导假设下，policy/reference 的 log-ratio 构成隐式 reward，并对应 KL 约束的最优策略关系。这个 reference 不是硬性距离上限，也不保证保留旧能力或避免过拟合。后续有不使用 reference 的偏好优化方法，但它们采用不同的 reward 定义和目标，不能把 reference 从标准 DPO 公式中直接删去。

### DPO Loss 的直觉

DPO 的推导从一个带 KL 正则的奖励目标开始。对固定 prompt $x$ 和潜在 reward $r(x,y)$，求解：

~~~math
\max_{\pi}\;\mathbb{E}_{y\sim\pi(\cdot\mid x)}[r(x,y)]-\beta D_{\mathrm{KL}}\left(\pi(\cdot\mid x)\Vert\pi_{\mathrm{ref}}(\cdot\mid x)\right),\qquad \beta>0
~~~

在参考分布覆盖相关回答、reward 固定等推导条件下，将该目标的最优策略记作 $\pi_r$，它有闭式形式：

~~~math
\pi_r(y\mid x)=\frac{1}{Z(x)}\pi_{\mathrm{ref}}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right),\qquad Z(x)=\sum_y\pi_{\mathrm{ref}}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right)
~~~

$Z(x)$ 是对所有可能回答求和得到的归一化常数。对上式取对数，可将 reward 写成：

~~~math
r(x,y)=\beta\log\frac{\pi_r(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}+\beta\log Z(x)
~~~

原始 DPO 推导再采用 Bradley–Terry 偏好模型：$p^*(y_w\succ y_l\mid x)=\sigma(r^*(x,y_w)-r^*(x,y_l))$，其中 $\sigma(z)=1/(1+e^{-z})$ 是 sigmoid 函数；理想化推导把前面的 reward 视为这个潜在偏好 reward $r^*$，对应最优策略记为 $\pi^*$。把 reward 表达式代入后，同一个 prompt 的 $\beta\log Z(x)$ 在 chosen 和 rejected 的差值中抵消。再用可训练 policy $\pi_\theta$ 拟合这个偏好概率，得到标准 DPO loss。定义 reference-adjusted margin：

~~~math
g_\theta(x,y_w,y_l)=\left[\log\pi_\theta(y_w\mid x)-\log\pi_\theta(y_l\mid x)\right]-\left[\log\pi_{\mathrm{ref}}(y_w\mid x)-\log\pi_{\mathrm{ref}}(y_l\mid x)\right]
~~~

~~~math
L_{\mathrm{DPO}}(\theta)=-\mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}}\left[\log\sigma\left(\beta g_\theta(x,y_w,y_l)\right)\right]
~~~

这里 $g_\theta(x,y_w,y_l)$ 是上式定义的 reference-adjusted margin；对一个 preference pair 的样本 loss 是 $\ell_{\mathrm{DPO}}=-\log\sigma(\beta g_\theta)$，整体目标对数据集中的 pairs 求平均。它比较 policy 相对 reference 是否更偏向标注为 chosen 的回答。这里使用完整 response 的条件 log probability；在自回归模型中，它是 completion 目标 token 的条件 log probability 之和，具体哪些 token 纳入求和依训练模板和 mask 而定。这个目标仍是对偏好标签的分类损失，降低训练集 loss 不等于事实正确性或整体行为必然改善。

### Beta 参数

推导中的 $\beta$ 是 KL 惩罚系数：固定 reward 时，增大它会提高偏离 reference 的代价，使最优策略更靠近 reference。标准 DPO loss 又将同一个 $\beta$ 乘到 margin 上，因此它同时改变偏好 logit 和单样本梯度尺度；它不是策略概率的硬性上限，也不能脱离学习率、数据、reference 和训练步数单独解释实际更新大小。调参时应并看隐式 reward margin、长度、独立偏好、任务指标和能力回归。

### DPO 和 SFT 的区别

SFT 学的是：

```text
这个 prompt 下，模仿这个目标回答
```

DPO 学的是：

```text
这个 prompt 下，chosen 比 rejected 更好
```

SFT 需要 demonstrations，DPO 需要 preferences。

SFT 更像行为克隆，DPO 更像偏好对齐。

常见但非必需的一条流程是：

```text
Base Model -> SFT -> DPO
```

在这种常见设定中，可训练 policy 从 SFT checkpoint 初始化，reference 则是冻结的 SFT 副本；但偏好数据的候选可能来自更早的模型或其他采样方案，因此数据来源、policy 初始化和 reference 选择要分别记录。

### DPO 的优点

DPO 的优点：

1. 不需要显式 reward model。
2. 不需要 PPO。
3. 训练流程更简单。
4. 对固定偏好数据，标准训练流程通常比带在线 rollout 的 PPO 链路少一些系统组件。
5. 可以直接复用偏好数据。
6. 实现上更接近常规 supervised training。

这些是标准离线 DPO 相对 PPO-style 在线闭环少掉的组件，不意味着 DPO 不需要 reference 前向计算、偏好数据治理或独立验证；简化系统流程也不等于训练一定更稳定或结果更好。

### DPO 的局限

DPO 不是万能的。

需要额外检查的边界包括：

1. 依赖高质量 preference pair。
2. 对偏好数据覆盖范围敏感。
3. 可能过拟合偏好数据风格。
4. 固定数据集不会自动提供新 policy 输出上的反馈，分布变化后可能需要补采偏好或采用在线评估。
5. Reference 与训练 policy 的初始化和候选回答来源不匹配时，reference-adjusted margin 的解释会变弱。
6. 序列 log probability 按 token 求和，长短不同的回答可能使偏好 margin 受到长度和 tokenization 影响。

如果 chosen/rejected 标签噪声大、规则冲突或覆盖不足，模型可能学到不稳定或过窄的偏好；需用独立数据和任务切片验证。

### 一个可手算的 DPO 对照

假设某个 prompt 下，policy 对 chosen/rejected 完整回答的 log probability 分别为 $-2$ 和 $-4$，reference 分别为 $-2.5$ 和 $-3.5$。则 $\Delta_\theta=-2-(-4)=2$，$\Delta_{\mathrm{ref}}=-2.5-(-3.5)=1$，所以 $g=2-1=1$。取 $\beta=0.1$，sigmoid 输入 $\beta g=0.1$，$\sigma(0.1)=1/(1+e^{-0.1})\approx0.5250$，loss 为 $-\ln(0.5250)\approx0.6444$。

把 policy 倒转为 chosen/rejected log probability $-4/-2$，得到 $\Delta_\theta=-2$、$g=-3$、输入 $-0.3$，$\sigma(-0.3)\approx0.4256$，loss 约为 $0.8544$。若进一步把 policy 调成 $-1.5/-4.5$，则 $g=2$，输入 $0.2$，loss 约为 $-\ln(\sigma(0.2))=0.5981$。这些值展示一个偏好对上，模型相对 reference 更符合 chosen 标签时 loss 如何变化；它不证明标签客观正确，也不表示 sigmoid loss 在有限 margin 处会停止优化。训练日志还应同时记录回答长度、margin 和独立评估。

### 最小 demo：DPO loss 如何计算

下面这个 demo 直接使用四个 log probability：policy 对 chosen/rejected 的 log probability，reference 对 chosen/rejected 的 log probability。DPO 比较的是 policy 相对 reference 是否更偏向 chosen。

```python
import torch
import torch.nn.functional as F


def dpo_loss(policy_chosen, policy_rejected, ref_chosen, ref_rejected, beta=0.1):
    tensors = [policy_chosen, policy_rejected, ref_chosen, ref_rejected]
    if not all(t.shape == tensors[0].shape for t in tensors):
        raise ValueError("all log-probability tensors must have the same shape")
    if tensors[0].numel() == 0:
        raise ValueError("at least one preference pair is required")
    if beta <= 0:
        raise ValueError("beta must be positive")
    delta_policy = policy_chosen - policy_rejected
    delta_ref = ref_chosen - ref_rejected
    logits = beta * (delta_policy - delta_ref)
    return -F.logsigmoid(logits).mean()


loss_good = dpo_loss(
    policy_chosen=torch.tensor([-2.0]),
    policy_rejected=torch.tensor([-4.0]),
    ref_chosen=torch.tensor([-2.5]),
    ref_rejected=torch.tensor([-3.5]),
)

loss_bad = dpo_loss(
    policy_chosen=torch.tensor([-4.0]),
    policy_rejected=torch.tensor([-2.0]),
    ref_chosen=torch.tensor([-2.5]),
    ref_rejected=torch.tensor([-3.5]),
)

print("policy prefers chosen loss:", round(loss_good.item(), 4))
print("policy prefers rejected loss:", round(loss_bad.item(), 4))
```
> **代码状态：已验证（2026-10-07；Python 3.13.13；PyTorch 2.12.0+cpu）**


在这两个输入上，chosen 高于 rejected 的排序对应较低 loss，反向排序对应较高 loss，与上面的手算方向一致。它只核对 loss 的计算方向，不训练完整模型，也不说明单个 pair 能代表整体偏好质量。

### 长度偏差问题

标准 DPO 中，完整回答的条件 log probability 按自回归链式分解为目标 completion token 的 log probability 之和；是否把 EOS 等边界 token 纳入目标，要按数据模板和 loss mask 确认：

~~~math
\log\pi_\theta(y\mid x)=\sum_{t=1}^{|y|}\log\pi_\theta(y_t\mid x,y_{<t})
~~~

因此 chosen/rejected 长度和 tokenization 会影响累计的 policy/reference margin。不能把总和与按有效 token 数取平均的实现当成同一个目标。做一个构造例子：chosen 的逐 token policy/reference log-ratio 为 $(0.10,0.05)$，总和是 $0.15$、平均为 $0.075$；rejected 的四个值为 $(0.05,0.04,0.04,0.04)$，总和为 $0.17$、平均为 $0.0425$。用总和计算，reference-adjusted margin 为 $0.15-0.17=-0.02$；改用 token 平均后则为 $0.075-0.0425=0.0325$，排序方向反转。这个例子只说明归约约定会改变目标，不表示真实数据必然有相同偏差。

针对标准 DPO 的 reference 依赖和总 log probability 与生成时长度归一化指标之间的差异，[Simple Preference Optimization (SimPO)](https://arxiv.org/abs/2405.14734)提出用平均 token log probability 构造无 reference 的隐式 reward，并加入目标 margin。作者在 Mistral、Llama 3、Gemma 2 等论文设定和指定评测中报告了结果；这是一种不同的目标设计，不证明它在所有数据和任务上优于 DPO。2026 年预印本 [Normalized Rewards for Preference Optimization](https://arxiv.org/abs/2607.16240)还研究了对 DPO/SimPO 加入长度归一化概率约束，以缓和 preference pair 两端回答 likelihood 同时下降的 likelihood displacement 现象；目前应把它视为特定实验提出的候选方法，而非通用修复。比较不同方法时应记录总和/平均口径、候选长度、tokenizer、EOS/mask 约定及独立任务结果。

### DPO 评估

DPO 后不能只看 DPO loss。

需要评估：

1. pairwise win rate。
2. 人工偏好。
3. helpfulness。
4. truthfulness。
5. safety。
6. over-refusal。
7. 代码、数学、知识能力回归。
8. 输出长度和风格变化。

如果 DPO 后模型更会迎合偏好集，但真实能力下降，这不是成功。

### 22 讲·DPO 的失败模式

#### 坑 1：偏好数据质量差

chosen 不一定真的好，rejected 不一定真的差，模型会学到错误偏好。

#### 坑 2：chosen/rejected 差异太弱

两个回答差不多，训练信号弱，标注噪声影响大。

#### 坑 3：reference model 选错

reference 太弱或和 policy 初始化不匹配，会影响约束效果。

#### 坑 4：只看 win rate

Win rate 提升可能来自风格迎合，而不是事实性或推理能力提升。

#### 坑 5：偏好优化导致过度拒答

如果安全偏好数据处理不好，模型可能学会对很多正常请求也拒答。

### DPO 的小型对照实验

DPO 的训练日志至少应同时记录四类量：chosen/rejected 的平均 token 数、policy 与 reference 的相对 log-probability、偏好对的训练准确率，以及独立评估集上的真实任务指标。只看 DPO loss，会把“模型更会拟合偏好对”误认为“模型更适合用户”。

可以设计三组偏好对来观察不同失败模式。第一组让 chosen 和 rejected 只在事实正确性上不同；第二组让二者事实相同、长度和语气不同；第三组加入正常请求与危险请求的边界样本。若第二组训练后平均输出明显变短或变长，说明长度统计改变了优化方向；若第三组的拒答率上升而安全风险没有下降，说明偏好数据把拒答风格当成了安全代理。

对一个偏好对，令 $g=\Delta_\theta-\Delta_{\mathrm{ref}}$。标准 sigmoid loss 对这个 margin 的导数是：

~~~math
\frac{\partial \ell_{\mathrm{DPO}}}{\partial g}=-\beta\left(1-\sigma(\beta g)\right)
~~~

取 $\beta=0.1$，当 $g=1$ 时，导数约为 $-0.0475$；当 $g=2$ 时，约为 $-0.0450$。正向 margin 增大时，这个单样本标量权重渐近趋近于零，但有限 margin 不会触发一个硬停止点；对模型参数的梯度还要乘上 $g$ 对参数的导数。训练时应观察 $g$ 的分布，而不是只看均值：少量极端样本可能主导更新，导致 policy 在某一风格上过度偏移。把训练集按领域、长度和标注来源切片，通常能更早发现这种问题。

DPO 与 RLHF 的差异也应以可观测对象来区分：RLHF 有 rollout、reward 和策略更新的在线闭环；DPO 直接在固定偏好对上更新 policy。DPO 的工程简单性来自移除了在线环节，但也因此不天然获得新策略分布上的反馈。对于需要持续与环境交互或奖励随状态变化的任务，仍需考虑在线方法或外部 verifier。

### 22 讲·偏好差值的反例与边界

1. 误区：DPO 就是 SFT。
   纠正：SFT 学目标回答，DPO 学 chosen 相对 rejected 的偏好。

2. 误区：任何偏好优化都必须有 reference，或标准 DPO 可以直接删掉 reference。
   纠正：reference 是标准 DPO 公式的一部分；SimPO 等 reference-free 方法重新定义了 reward 和目标，不能与标准公式混为一谈。

3. 误区：DPO 一定优于 PPO-style RLHF。
   纠正：标准离线 DPO 少了在线 rollout 环节；数据、任务和实现决定效果与稳定性，需要按同一评估条件比较。需要新策略反馈或环境交互时，在线优化仍可能适用。

4. 误区：DPO loss 降低就代表模型更好。
   纠正：还要看人工偏好、安全、事实性和能力回归。

### 22 讲·从隐式奖励到 DPO 策略的关键结论

这一讲的关键关系：

1. DPO 是直接偏好优化，用 preference pair 直接训练 policy。
2. DPO 不显式训练 reward model，也不需要 PPO。
3. DPO 的核心是提高 chosen 相对 rejected 的概率优势。
4. 标准 DPO 的 reference 定义隐式 reward 基线；reference 约束不等于能力保留保证。
5. 标准离线 DPO 少了在线 PPO rollout 系统，但结果仍依赖数据、长度口径、reference 和独立评估；其他方法会改写这些选择。
6. DPO 后仍要评估偏好、安全、事实性、长度偏差和能力回归。

## 第 23 讲：Reward Model 与 Reward Hacking

### 代理目标的边界

Reward Model（奖励模型，简称 RM）把 prompt 和 response 映射成一个标量 $r_\phi(x,y)$。它的用途不是给答案颁发绝对质量分，而是把一套明确的偏好标注协议变成可供优化器使用的排序信号。标注可以来自人类、领域专家、教师模型、用户反馈或规则筛选；只有来源确实是人类标注时，才应把学到的目标称为那组标注者在指定任务和标准下的偏好。

例如，同一个“如何缓解过拟合？”问题，回答“使用正则化、早停或数据增强”通常比“增大学习率”更符合基本机器学习知识。但 RM 训练标签告诉我们的是：在给定 prompt、候选生成方式和标注说明下，哪一条被标为更好。它本身不运行实验、不查验证集，也不能仅凭较高的分数证明建议有效。若标注者对简洁和细节的取舍不同，或者偏好数据只覆盖某一类 prompt，RM 继承的是这些判断及覆盖范围。

常见训练样本包含同一 prompt 的 chosen/rejected pair。相同 prompt 让训练目标主要比较两个回答，而不要求不同 prompt 的分数共用绝对尺度。数据增多有助于覆盖更多情形，但无法自动消除标签歧义、错误偏好或采样偏差；这些问题需要明确标注协议、记录分歧，并用独立任务切片检查。RM 只能近似训练数据所表达的目标，不能把偏好变成事实、数学正确性或普遍价值判断。

### Pairwise Ranking Loss

常见 Bradley–Terry 建模把同一 prompt 下 chosen 回答胜过 rejected 回答的概率写成分数差的 sigmoid。记 $r_w=r_\phi(x,y_w)$、$r_l=r_\phi(x,y_l)$，并定义 $\sigma(z)=1/(1+e^{-z})$，则单个偏好 pair 的概率和负对数损失为：

~~~math
P(y_w\succ y_l\mid x)=\sigma(r_w-r_l),\qquad L_i=-\ln\sigma(r_w-r_l)
~~~

对包含 $N$ 个 pair 的数据集，常用目标是逐 pair 损失的平均值：

~~~math
L_{\mathrm{pair}}=\frac{1}{N}\sum_{i=1}^{N}-\ln\sigma(r_{w,i}-r_{l,i})
~~~

若 chosen 分数比 rejected 高，差值为正，模型赋给标注胜者的概率增加，损失降低；排序反了，损失会增大。公式只依赖分差，所以把所有回答分数同时加同一个常数不会改变排序概率。这个训练目标不要求也不建立跨任务的绝对分数刻度。

把 $r_w=3$、$r_l=1$ 代入，差值是 $2$，胜出概率为 $\sigma(2)=1/(1+e^{-2})\approx0.8808$，负对数损失为 $-\ln(0.8808)\approx0.1269$。交换两者后差值为 $-2$，概率约为 $0.1192$，损失约为 $2.1269$。这些数只说明损失如何惩罚错误排序；chosen 标签仍可能不符合事实或外部任务要求。

下面的短 PyTorch demo 使用同一组输入，观察 chosen/rejected 次序反转时 loss 的变化；它不训练完整 RM，也不评估 RM 的泛化。

```python
import torch
import torch.nn.functional as F


def pairwise_reward_loss(chosen_reward, rejected_reward):
    if chosen_reward.shape != rejected_reward.shape:
        raise ValueError("chosen and rejected rewards must have the same shape")
    if chosen_reward.numel() == 0:
        raise ValueError("at least one preference pair is required")
    margin = chosen_reward - rejected_reward
    return -F.logsigmoid(margin).mean()


good_case = pairwise_reward_loss(torch.tensor([3.0]), torch.tensor([1.0]))
bad_case = pairwise_reward_loss(torch.tensor([1.0]), torch.tensor([3.0]))

print("chosen > rejected loss:", round(good_case.item(), 4))
print("chosen < rejected loss:", round(bad_case.item(), 4))
```
> **代码状态：已验证（2026-10-07；Python 3.13.13；PyTorch 2.12.0+cpu）**

在该输入下，输出约为 `0.1269` 和 `2.1269`，与手算一致。实现中的 `.mean()` 对 batch 中各 pair 的负对数损失取平均，和上面的数据集目标相同。它只演示标量分差如何转成训练信号，不包含 backbone、采样、验证集或训练循环。

### Reward Model 的结构

一种常见结构是从语言模型的 backbone 出发，为整段 prompt 与 response 产生隐藏状态，再用标量 reward head 输出一个分数。具体实现可能取 response 末尾、EOS 位置或经过 mask/pooling 得到的表示；“使用最后一个 token”是某类实现选择，不是 RM 的定义。prompt 和 response 的拼接方式、padding mask、截断位置及取哪一个隐藏状态，都可能改变模型实际评分的文本范围，因此需要和训练样本格式一并检查。

简化的数据流可以写成：

```text
LLM encoder/decoder hidden states -> reward head -> scalar score
```

### Reward Model 评估

评估要回答的是：RM 在什么样的样本和标注协议下能复现排序，哪些变化会让它失准，以及这个排序能否预测目标任务。训练 loss 下降只说明模型更贴合训练 pair，不说明它对新回答可靠。下表中的指标互为补充，任何一个都不能单独替代外部任务验证。

| 检查信号 | 具体看什么 | 不能单独推出什么 |
| --- | --- | --- |
| held-out pairwise accuracy / ranking loss | 留出 pair 中 chosen 是否得分更高，以及预测胜率是否接近标签 | 标签协议以外的事实、工具或代码正确性 |
| 分差与概率校准 | 按预测胜率分桶，比较模型给出的胜率与实际标注胜率；分差可观察排序置信度 | 跨 prompt 的分数有共同单位，或校准能自动迁移到新分布 |
| 任务和群体切片 | 按领域、语言、长度、难度、拒答类型分别报告指标及样本数 | 总体均值能代表每个子群体 |
| 反事实与对抗样本 | 只改长度、礼貌词、引用格式或表面模板，检查排序是否随无关特征翻转 | 所有分布外输入都已覆盖 |
| 独立任务验收 | 由人工评审、事实核验、单元测试或可执行 verifier 检查目标属性 | 不同 verifier 测量的是同一个“质量”概念 |

[RewardBench v2](https://arxiv.org/abs/2403.13787v2) 提供 chat、reasoning、safety 等 prompt/chosen/rejected 子集，也纳入答案中带有细微但可核验错误的比较；论文报告所测 reward models 在拒答倾向、推理和指令遵循上的差异。它同样说明 benchmark 只能给出受测样本上的信号：作者指出不少 pair 是半自动构造后人工复核，某些领域可能有伪相关，测试分数与下游训练效果的关系尚未解决，也存在数据污染的可能。因此，不能把单一基准的准确率写成 RM 在真实 policy rollout 上的可靠性保证。

### 分布偏移与 Reward Hacking

RM 是在有限 prompt 和回答分布上训练的；RL 优化中的 policy 则会根据 RM 分数持续改变回答。当新 policy 生成了训练集中少见的长度、格式、语气或推理错误时，RM 仍会给出分数，但这个分数可能外推到未验证区域。偏移不是“出现奇怪文本”才算：一个流畅、礼貌的回答也可能因表面线索得高分，同时在事实或任务目标上失败。

Reward hacking 描述的正是这种错位：优化器成功提高了代理分数，却没有提高目标任务表现，甚至让它变差。原因不一定是模型有意欺骗；只要优化过程能够反复筛选更高分回答，训练数据中的捷径就会被放大。例如，RM 若把篇幅、术语或拒答风格误当成质量线索，policy 就可能增加冗长措辞、回避普通问题，或生成看似完整但有事实错误的答案。

这可以用代理指标被持续优化后的选择效应解释：初始时，RM 分数可能与目标质量正相关；当候选被反复按分数挑选或训练后，样本越来越集中在模型打分较高的区域，RM 的误差也会影响哪些行为被放大。Gao、Schulman 与 Hilton 在合成 proxy/gold reward 设定中观察到，增加对 proxy 的优化在某些条件下会先提高、后降低 gold reward，曲线受 reward model、数据、policy 尺寸和优化方式影响；[Stiennon 等人的摘要任务实验](https://arxiv.org/abs/2009.01325)也报告继续优化较早 RM 后，人类偏好与 RM 预测逐渐分离。这些结果说明非单调退化可能发生，不构成所有任务共享的优化阈值或必然规律。[Gao 等人的研究](https://arxiv.org/abs/2210.10760)

### 最小 demo：代理 reward 和真实偏好可能背离

下面这个 demo 用一个玩具例子说明 reward hacking：Reward Model 可能过度奖励“看起来礼貌和冗长”的回答，但真实用户更喜欢准确、简洁、直接的回答。

```python
responses = [
    {"name": "accurate", "helpful": 9, "polite": 6, "verbose": 3, "true_pref": 9},
    {"name": "fluffy", "helpful": 5, "polite": 10, "verbose": 10, "true_pref": 4},
]


def reward_model_score(item):
    # 一个有缺陷的 RM：过度奖励礼貌和冗长，低估真实 helpfulness。
    return 0.3 * item["helpful"] + 0.4 * item["polite"] + 0.3 * item["verbose"]


for item in responses:
    rm_score = reward_model_score(item)
    print(item["name"], "rm_score=", round(rm_score, 2), "true_pref=", item["true_pref"])
```
> **代码状态：已验证（2026-10-07；Python 3.13.13；标准库）**


手算第一条 `accurate` 的分数：$0.3\times9+0.4\times6+0.3\times3=2.7+2.4+0.9=6.0$；`fluffy` 得到 $0.3\times5+0.4\times10+0.3\times10=1.5+4+3=8.5$。但构造的 `true_pref` 分别是 9 和 4，于是这个有缺陷的代理把偏好顺序完全排反。权重和标签都是人为设定，只用于演示机制，不代表实测用户偏好；代码及其运行约定没有改变。

### Over-Optimization 与 Over-Refusal

Over-optimization 指继续提高 RM 分数，却没有提高目标任务表现，或使目标表现下降。判断时要同时画 RM 指标和独立目标指标随优化步数、KL 或采样强度变化的轨迹，并检查分领域结果。只有 RM 曲线上升、外部指标持平或下降时，才有证据说代理目标与当前评估目标发生分离；一次高分输出不足以证明模型发生了过度优化。

具体曲线取决于优化方法、数据和模型规模。在 Gao 等人的合成研究中，指定的 RL 配置加入 KL penalty 后，没有测得 gold-reward/KL frontier 的改善；作者也提醒结果可能对超参数敏感。因此 KL 可作为调节策略偏移的手段，却不能视为外部质量、事实性或安全性的保证，更不能套用统一最优系数。

Over-refusal（过度拒答）是可能出现的一类目标权衡：如果某个偏好协议或安全评分对拒答奖励过高，模型可能连可安全回答的请求也回避。例如，“怎样安全地用厨房刀切菜？”如果只因出现“刀”就被拒绝，安全目标压过了普通帮助。这个风险不意味着安全训练必然造成过度拒答；应在需要拒答的危险请求、允许安全回答的教育/防御请求和需要澄清的模糊请求上分别统计拒答、误拒和回答质量。[RewardBench](https://arxiv.org/abs/2403.13787v2) 也把不同拒答行为作为评估维度，而不是把拒答率本身当作安全分数。

### 盲区、独立验证与风险控制

偏好 RM 可以判断候选回答更像哪类已标注答案，但许多任务需要额外证据来判定是否正确。代码需要测试或运行结果，数学需要可核算步骤或形式化检查，事实问题需要能追到来源，工具调用需要检查实际执行状态；长上下文、多语言和新型攻击也需要专门切片。偏好排序可以辅助这些评估，却不能替代任务 verifier。

一个可复核的审计应把训练分布内回答、当前 policy 的新回答，以及只改长度/语气/格式的反事实回答分开。对同一组候选同时记录 RM 排序，再使用与任务匹配的人工判断或独立 verifier。举例说，在 4 个成对比较里若 3 个排序一致、1 个冲突，分歧率就是 $1/4=25\%$；这提醒我们回查冲突所在的任务切片，而不是把它和其他指标平均掉。人类偏好、单元测试和事实核验测量的是不同目标，应分栏呈现。

| 风险控制 | 如何使用 | 仍需观察的边界 |
| --- | --- | --- |
| 更清楚的标注协议与分歧记录 | 降低同类样本因标准不明产生的噪声，保留无法统一的偏好 | 共识不等于事实正确，也不代表覆盖所有用户 |
| 分布隔离的留出集与任务切片 | 区分新 prompt、长度、语言、拒答与当前 policy 输出的泛化 | 静态 holdout 不覆盖未来策略搜索到的所有回答 |
| KL 或其他更新约束 | 调节 policy 相对参考策略的变化幅度 | 不能保证外部质量不降，过强约束也可能阻止目标行为变化 |
| 对抗与反事实评估 | 检查无关表面特征变化是否导致 RM 排序翻转 | 评估集只覆盖已设计的扰动 |
| 独立人工、事实、代码和安全评估 | 分别检查目标属性，比较其与 RM 分数随优化的变化 | 不同评估器的适用范围和误差必须单独说明 |
| 按 policy 输出补充偏好样本 | 发现新分布中的错误并改善覆盖 | 若只采纳 RM 已偏好的输出，可能把原偏差再次写入标签 |

这些做法是风险控制和观测手段，不是一次性修复。尤其不能只在每轮结束时重训 RM：新样本的标注标准、来源模型和独立核验方式都应记录，否则可能只让 proxy 更好地拟合上一轮 policy 的风格。

### 常见失效判断

- **标注协议含混**：同一个 pair 让标注者按不同目标判断，训练误差混合了偏好冲突；先明确标准、保留分歧，再解释可达到的排序上限。
- **验证集和训练样本太近**：高准确率可能只反映相似 prompt 或格式；按 prompt、来源和时间隔离留出样本，并检查当前 policy 生成内容。
- **只看总体准确率**：总体均值会掩盖某领域或某种拒答行为的失败；必须保留分层指标、样本数与不确定性。
- **把 reward 当作任务质量**：跨 prompt 的标量缺少天然统一刻度；要回到人工协议或具体 verifier 检验目标。
- **把拒答率当作安全**：对危险请求拒绝与对普通请求误拒是两种结果；需要同时报告漏拒和误拒。

1. 写一个 chosen/rejected 样本，并说明两种回答的排序依据和可能分歧。
2. 用自己的话解释 pairwise ranking loss，手算一个正向与反向分差。

5. 解释为什么安全评估要同时看危险请求的漏拒和正常请求的误拒。

### 本讲结论与资料边界

RM 把指定偏好协议压缩成可优化的排序代理；pairwise loss 训练的是 chosen/rejected 的相对次序，不能建立绝对质量刻度。policy 优化会改变生成分布，并可能放大 RM 依赖的表面捷径，因此应对模型分数和独立任务表现做并行、分层观察。KL、数据扩展和 adversarial evaluation 都只能降低或暴露风险，不能单独证明外部质量、安全或事实性。

InstructGPT 提供在其 prompt 分布和标注流程下使用 RM/PPO 的代表性证据（[Ouyang et al., 2022](https://arxiv.org/html/2203.02155)）；摘要偏好研究展示了指定任务上的过度优化现象（[Stiennon et al., 2020](https://arxiv.org/html/2009.01325)）；合成 proxy/gold reward 研究分析优化规模和方法的影响（[Gao et al., 2022](https://arxiv.org/html/2210.10760)）；RewardBench v2 的评测结构和局限见[论文](https://arxiv.org/abs/2403.13787v2)。这些来源分别支持各自实验或方法范围，不能推出所有任务共有的 RM 退化规律。本文玩具分数、四对分歧示例均为构造输入，不是实测指标。
