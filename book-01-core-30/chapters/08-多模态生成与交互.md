## 第 34 讲：Diffusion Model 与图像生成

### 34.1 生成问题的另一种答案

语言模型通常按顺序预测下一个离散 token。图像生成面对的是一个高维连续对象：像素之间有空间关联，很多不同像素组合都可能对应自然图像。扩散模型把生成改写成一个可构造监督信号的去噪问题：规定怎样逐步给真实图像加噪，再训练模型预测噪声或等价状态，采样时反向逐步更新图像。

这个过程可以理解为两条链：

```text
训练已知：清晰图像 -> 加噪 -> 噪声图像
模型学习：噪声图像 -> 去噪 -> 清晰图像
```

“加噪”和“去噪”是直觉，不是完整算法。真正重要的是噪声调度、网络预测的参数化、条件注入方式和采样器如何近似反向过程。

### 34.2 Forward process：把图像变成噪声

设原始图像为 `x_0`，第 `t` 步的噪声图像为 `x_t`，且每个噪声率满足 `0<β_t<1`。定义 `α_t=1-β_t` 及累计信号保留率：

~~~math
\alpha_t=1-\beta_t,\qquad
\bar\alpha_t=\prod_{s=1}^{t}\alpha_s
~~~

前向链的一步转移是：

~~~math
q(x_t\mid x_{t-1})=
\mathcal{N}\left(\sqrt{\alpha_t}x_{t-1},\beta_t I\right)
~~~

经过推导，可以直接从 `x_0` 采样任意时间步：

~~~math
q(x_t\mid x_0)=
\mathcal{N}\left(
\sqrt{\bar\alpha_t}x_0,
(1-\bar\alpha_t)I
\right)
~~~

等价的采样表达式是：

~~~math
x_t=\sqrt{\bar\alpha_t}x_0+
\sqrt{1-\bar\alpha_t}\,\epsilon,qquad
\epsilon\sim\mathcal{N}(0,I)
~~~

当 `t` 较小时，`\bar\alpha_t` 较大，原图信号占比高；当 `t` 较大时，信号系数下降，噪声占比上升。闭式公式让训练可以随机抽取 `t`，而不必每次真的执行前面所有加噪步骤。这一前向过程和简化噪声预测目标来自 DDPM 的标准推导（[Ho et al., 2020](https://arxiv.org/abs/2006.11239)）。

手算两步可以看到信号与噪声如何混合。设 `β_1=0.1`、`β_2=0.2`，则 `α_1=0.9`、`α_2=0.8`，`\bar{α}_2=0.9×0.8=0.72`。取二维 `x_0=(1,0)` 和已知噪声 `ε=(0,1)`，有 `x_2=√0.72(1,0)+√0.28(0,1)≈(0.8485,0.5292)`。此时第一维主要保留原图信号，第二维来自噪声；实际训练从许多图像、时间步和噪声样本重复构造这样的监督数据。

### 34.3 Reverse process：模型到底预测什么

反向过程的目标是学习 `p_θ(x_{t-1}|x_t)`。常见实现让网络预测加入的噪声：

~~~math
L_{\epsilon}=\mathbb{E}_{x_0,\epsilon,t}
\left[\|\epsilon-\epsilon_\theta(x_t,t,c)\|_2^2\right]
~~~

其中 `c` 可以是文本条件，`ε_θ` 是去噪网络。根据预测的噪声可以估计原图：

~~~math
\hat x_0=\frac{x_t-
\sqrt{1-\bar\alpha_t}\,\epsilon_\theta(x_t,t,c)}
{\sqrt{\bar\alpha_t}}
~~~

在常见的 DDPM 噪声参数化和固定方差设置下，网络预测的噪声也给出反向转移的均值：

~~~math
\mu_\theta(x_t,t,c)=
\frac{1}{\sqrt{\alpha_t}}
\left(x_t-
\frac{\beta_t}{\sqrt{1-\bar\alpha_t}}
\epsilon_\theta(x_t,t,c)\right)
~~~

这是条件反向转移 `p_θ(x_{t-1}|x_t,c)` 的均值，不是完整的采样结果；反向方差和是否额外采噪声还由具体 sampler 设置决定。

模型也可以直接预测 `x_0`，或者预测 velocity `v`。三种参数化在不同噪声区间的梯度和采样表现可能不同，不能把“扩散模型就是预测噪声”当成不可改变的定义。

这里写的是简化的噪声预测目标，实际训练还可能按时间步加权或采用 `x_0`、velocity 等参数化。训练时，真实噪声 `ε` 是已知的，因此均方误差容易计算；采样时没有真实图像，模型只能依赖当前 `x_t`、时间步和条件连续迭代。训练损失下降也不保证采样器、噪声调度和条件强度都设置正确。

沿用上一节的 `x_2≈(0.8485,0.5292)` 和真实 `ε=(0,1)`，假设网络预测 `ε_θ=(0.2,0.6)`。按两个维度取平均的噪声 MSE 为 `[(0.2-0)^2+(0.6-1)^2]/2=(0.04+0.16)/2=0.10`。代回 `x_0` 估计式得 `x̂_0≈((0.8485,0.5292)-√0.28(0.2,0.6))/√0.72≈(0.8753,0.2494)`。对反向步 `t=2`，相同预测给出 `μ_θ≈((0.8485,0.5292)-[0.2/√0.28](0.2,0.6))/√0.8≈(0.8642,0.3381)`。预测噪声有误差，所以重建值偏离 `(1,0)`，反向均值也会偏离真实前一状态；若准确预测 `(0,1)`，`x_0` 估计式会还原原向量。这一教学计算说明误差如何传到图像状态，不是模型采样结果。

### 34.4 U-Net 与 DiT

U-Net 通过下采样路径获得全局上下文，再通过上采样路径恢复空间分辨率，并用 skip connection 保留局部细节。时间步 embedding 可以注入每一层，文本条件通常通过 cross-attention 进入中间特征。

Diffusion Transformer（DiT）则把 latent 切成 patch token，用 Transformer 处理这些 token（[Peebles and Xie, 2022](https://arxiv.org/abs/2212.09748)）。它的优势是结构与 Transformer 的规模扩展规律更直接，计算量可以通过深度、宽度和 token 数控制；代价是 token 数增长会带来明显的注意力成本。

这两种主干不是“卷积已经过时”或“Transformer 一定更好”的简单替代关系。输入分辨率、数据规模、硬件、条件复杂度和采样速度都会影响选择。DiT 论文的重要信息是：在其研究设置中，增加模型计算量和 token 数与更低的 FID 相关；这不是对所有数据集和部署预算的普遍保证。

2026 年一项针对 Diffusion Transformer 的规模研究进一步拟合预训练损失与计算量的关系。摘要报告的直接实验覆盖约 `10^17` 到 `6×10^18` FLOPs，并给出 1B 参数模型在 `1.5×10^21` FLOPs 下的生成损失预测；该预测点是直接实验上限的 250 倍，应读作外推而不是实测。这类工作可以帮助提出“扩模型还是增加训练计算”的候选方案，但真正选型仍要在目标数据、分辨率和采样预算上复验（[Scaling Laws for Diffusion Transformers](https://proceedings.iclr.cc/paper_files/paper/2026/hash/880d8999c07a8efc9bbbeb0c38f50765-Abstract-Conference.html)）。

### 34.5 Latent Diffusion：先压缩，再生成

像素空间的 `512×512×3` 张量维度很高，在每一个去噪步都处理它成本很大。Latent Diffusion 先用 VAE 把图像压缩为较小的 latent：

```text
image -> VAE encoder -> z
z + noise -> latent diffusion -> clean latent
clean latent -> VAE decoder -> image
```

若 VAE 的空间下采样倍数为 `f`，latent 空间的高宽大约为 `H/f` 和 `W/f`。压缩会显著降低扩散主干成本，但也可能丢失高频纹理和精细文字。最终图片的质量不仅由 diffusion 网络决定，还由 VAE 的重建质量决定。

例如，假设一个教学配置把 `512×512×3` 的 RGB 图像编码成 `64×64×4` latent，即 `f=8`、latent 通道数为 4。原图有 `512×512×3=786,432` 个标量，latent 有 `64×64×4=16,384` 个标量，数量比为 `786,432/16,384=48`。空间位置少了 64 倍，标量数少了 48 倍；这不是总 FLOPs 或延迟也减少 48 倍的保证，因为编码/解码器、主干通道和注意力结构也消耗计算，且较强压缩会损失细节。具体 `f` 与通道数必须按 VAE/checkpoint 核对。

Latent Diffusion 的代表性公开方法见 [Rombach et al., 2022](https://arxiv.org/abs/2112.10752)。Stable Diffusion 一类系统还使用文本编码器和 cross-attention，让每一步去噪都能读取 prompt。SDXL 增加了更大的主干、额外文本编码器和多种条件方式（[Podell et al., 2023](https://arxiv.org/abs/2307.01952)）；这些公开论文可以支持对其公开组件的描述，但不能据此推断所有商业闭源生成器的内部实现。

### 34.6 Classifier-Free Guidance 的方向和代价

训练时随机丢弃条件，模型既学习有条件预测，也学习无条件预测。Classifier-Free Guidance 的原始方法见 [Ho and Salimans, 2022](https://arxiv.org/abs/2207.12598)；采样时把两者组合：

~~~math
\epsilon_{\mathrm{cfg}}=
\left(1+w\right)\epsilon_\theta(x_t,t,c)
-w\epsilon_\theta(x_t,t,\varnothing)
~~~

Ho–Salimans 原论文的 `w` 记法在 `w=0` 时返回条件预测。若把乘在预测差上的系数记为 `s`，同一公式可写成 `ε_uncond+s(ε_cond−ε_uncond)`，此时 `s=1+w`。软件参数名 `guidance_scale` 不一定直接等于论文的 `w`；例如 Diffusers v0.35.1 的经典 Stable Diffusion pipeline 文档将 `guidance_scale=1` 设为不启用 CFG（[版本化实现文档](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/pipelines/stable_diffusion/pipeline_stable_diffusion.py)）。复现或调整参数时应核对目标版本实际使用的公式和无 guidance 基线。

~~~math
\epsilon_{\mathrm{cfg}}=
\epsilon_\theta(x_t,t,\varnothing)
+s\left[
\epsilon_\theta(x_t,t,c)-
\epsilon_\theta(x_t,t,\varnothing)
\right],\qquad s=1+w
~~~

用一个数值例子对齐两种记法：若无条件预测为 `0.2`、条件预测为 `0.5`，则论文参数 `w=2` 对应实现参数 `s=3`，得到 `(1+2)×0.5-2×0.2=1.1`，也等于 `0.2+3×(0.5-0.2)=1.1`。不能拿相同数值的 `w` 和 `s` 当作同一强度。

指导强度用于在条件遵循与样本多样性之间取舍，增加 guidance 不等于图像更正确（[Ho and Salimans, 2022](https://arxiv.org/abs/2207.12598)）。过大的 guidance 在一些模型与设置下会造成过曝等伪影，也可能放大错误条件；相关噪声调度与 guidance rescale 分析只适用于论文讨论的模型和设置（[Lin et al., 2023](https://arxiv.org/abs/2305.08891)）。每个采样步都需要条件和无条件两条预测分支；实现可将它们合并成一次增大 batch 的 forward，但计算量仍受两组预测影响。

### 34.7 采样器、步数和训练—推理一致性

最朴素的反向采样需要很多时间步。DDIM 保留 DDPM 的训练目标，构造非马尔可夫采样路径来减少反向步数；DPM-Solver 把采样写成扩散 ODE，并用专用高阶求解器减少模型函数评估，二者都无需为新采样器重训模型（[DDIM](https://arxiv.org/abs/2010.02502)；[DPM-Solver](https://arxiv.org/abs/2206.00927)）。较少的函数评估有机会降低延迟，但实际质量和速度取决于 checkpoint、噪声日程、采样设置与硬件，不能把论文在特定数据上的改进视为通用保证。

另一个容易被忽略的问题是训练和推理的噪声边界是否一致。若训练过程最后仍保留少量信号，但推理却从纯高斯噪声开始，模型会面对分布偏移。Lin et al. 在论文所测的常见日程（包括其分析的 Stable Diffusion 设置）中报告了非零 terminal SNR，并讨论了零终端 SNR、`v` 预测、采样起点和 guidance rescale 等修正；这说明相关边界需要按 checkpoint 核查，不代表所有扩散管线都存在同一缺陷（[arXiv:2305.08891](https://arxiv.org/abs/2305.08891)）。噪声 schedule、预测参数化和采样起点需要作为一个整体调试。

实际部署应记录：采样步数、每步耗时、VAE 编解码耗时、条件编码耗时、显存峰值和失败重试率。单独报告生成图片的平均耗时，无法判断瓶颈在哪里。

### 34.8 自回归生成和扩散生成的差异

自回归模型把对象分解成有序 token：

```text
y_1 -> y_2 -> ... -> y_T
```

扩散模型从整体噪声状态开始，多次更新同一个连续对象：

```text
x_T -> x_{T-1} -> ... -> x_0
```

前者天然适合精确的离散序列概率和流式输出，后者可以在每一步同时修改全局结构，适合图像的并行空间 refinement。扩散的代价是多步迭代和采样器依赖；自回归图像生成的代价则常表现为很长的离散序列和逐 token 延迟。现代系统也会把两者结合，例如在压缩 latent 上使用 Transformer，再使用扩散或 flow matching 进行连续生成。

### 34.9 一个可运行的加噪与 guidance 练习

下面的示例按 Python 3.8+、PyTorch 2.x 环境准备，输入是两个 `[2,3]` 张量和 `alpha_bar∈[0,1]`，只演示 forward noising 和 CFG 的代数形式，不会生成图片。代码使用基础张量运算及 [`torch.isfinite`](https://docs.pytorch.org/docs/stable/generated/torch.isfinite.html) 等接口；这里的 `guidance_scale=3` 使用实现常见的 `s` 记法，对应论文 `w=2`；当无条件预测为 `0.2`、条件预测为 `0.5` 时，输出每个元素约为 `1.1`。保存为独立 Python 文件运行后，预期 noisy shape 为 `(2,3)`。本例未运行，版本范围未作本地兼容性验证。

```python
import math
import torch


torch.manual_seed(0)
x0 = torch.ones(2, 3)
noise = torch.randn_like(x0)
alpha_bar = torch.tensor(0.4)
if alpha_bar.ndim != 0 or not torch.isfinite(alpha_bar) or not 0 <= alpha_bar.item() <= 1:
    raise ValueError("alpha_bar must be a finite scalar in [0, 1]")
xt = alpha_bar.sqrt() * x0 + (1 - alpha_bar).sqrt() * noise

eps_uncond = torch.full_like(xt, 0.2)
eps_cond = torch.full_like(xt, 0.5)
guidance_scale = 3.0
if not math.isfinite(guidance_scale):
    raise ValueError("guidance_scale must be finite")
eps_cfg = eps_uncond + guidance_scale * (eps_cond - eps_uncond)

print("noisy shape:", tuple(xt.shape))
print("guided prediction:", eps_cfg[0].tolist())
```

### 34.10 生成质量不能只看一张图

生成评估至少要拆成四类：

1. 视觉质量：清晰度、结构和自然度。
2. 条件遵循：主体、属性、关系和数量是否符合 prompt。
3. 多样性：相同条件下是否能产生不同但合理的样本。
4. 安全与版权：是否产生有害内容、未经授权的身份或误导性材料。

FID（由 [Heusel et al., 2017](https://arxiv.org/abs/1706.08500) 提出）之类的分布距离指标可以用于比较一批样本，但它依赖特征提取器，不能直接判断某张图是否遵循 prompt。CLIP 相似度可以提供文本—图像相关性线索，也不能替代人工检查、关系级评估和安全测试。对于文字渲染、手指数量、空间布局等问题，应建立专门的任务集。

### 34.11 扩散系统的失败模式

文字渲染失败往往来自 latent 压缩、训练数据中的文字质量和模型对离散字符结构的弱约束；计数失败可能来自全局语义匹配而不是显式对象建模；构图漂移可能来自 prompt 中多个实体的关系没有被结构化表示；过度 guidance 则会把错误的条件方向强化。

修复不能只调一个 prompt。可以使用更强的文本编码器、区域条件、ControlNet 类结构、图像编辑和重绘、专门的文字模块或后处理检测器；每种方法都会增加复杂度和失败面。工程选择应由目标任务的错误代价决定。

## 第 35 讲：语音模型：Whisper、TTS 与实时对话

### 35.1 语音为什么不是“另一种文本”

文字已经被离散成 token，而语音首先是连续的压力变化。采样率为 `f_s` 的数字音频把每秒声音记录为 `f_s` 个数值；16 kHz 音频的一秒就有 16000 个采样点。直接把所有采样点送入语言模型，序列会很长，且相邻采样点高度相关。

语音还包含文字之外的信息：说话人、音高、音量、重音、停顿、情绪、背景噪声和多人重叠。一个只优化转写准确率的系统，可能听懂了字面内容，却无法处理打断、犹豫和语气。

### 35.2 从波形到声学表示

短时傅里叶变换把波形切成重叠窗口，对每个窗口计算频率成分。令第 `m` 个窗口的波形为 `x_m[n]`，窗口函数为 `w[n]`，则：

~~~math
X(m,k)=\sum_{n=0}^{N-1}x_m[n]w[n]
\exp\left(-j2\pi kn/N\right)
~~~

对幅度谱经过 Mel 滤波器组和对数压缩，就得到常见的 log-Mel spectrogram。它把声音变成随时间变化的二维能量图，适合卷积或 Transformer 编码器处理。

可以用 Whisper 论文报告的声学前端参数做一组帧数手算：采样率 16 kHz、窗口 25 ms、帧移 10 ms，分别对应 `16000 × 0.025 = 400` 个采样点和 `16000 × 0.010 = 160` 个采样点。若对 1 秒音频采用不居中、无 padding、只保留完整窗口的约定，帧数为 `floor((16000 - 400) / 160) + 1 = 98`，80 个 Mel 通道对应 `98 × 80` 的特征矩阵。这个 98 帧是按本例明确约定推得的教学结果；不同前端的 padding 与边界处理会改变实际帧数，不能把它直接当成 Whisper 实现的固定输出 shape（[Whisper 论文 §2.2](https://arxiv.org/html/2212.04356)）。

另一条路线是神经 codec：编码器把波形压缩成若干组离散 codebook index，解码器再重建波形。SoundStream/EnCodec 等工作展示了端到端神经音频压缩路线（[SoundStream](https://arxiv.org/abs/2107.03312)；[EnCodec](https://arxiv.org/abs/2210.13438)）。离散 codec token 可以交给语言模型预测，便于统一“序列建模”；但压缩率、码率和重建误差会决定音质与序列长度。

### 35.3 ASR 的任务和结构

ASR（Automatic Speech Recognition）把语音转成文字：

```text
speech -> text
```

常见结构包括 CTC、encoder-decoder Transformer 和 RNN-T/Transducer。CTC 允许帧级路径包含 blank 与重复标签，再把多条可折叠为目标文本的路径概率求和，免去逐帧人工对齐（[Graves et al., 2006](https://www.cs.toronto.edu/~graves/icml_2006.pdf)）。RNN-T 在声学时间和已生成文本前缀构成的格点上联合预测 blank 或下一个文本 token（[Graves, 2012](https://arxiv.org/abs/1211.3711)）。但 CTC 或 RNN-T 的损失形式本身都不保证流式：声学编码器是否因果或分块、可向右看的时长、partial transcript 的提交规则和 endpoint 策略，共同决定延迟与修订幅度。原始 CTC 论文的实验使用双向 LSTM，说明“CTC”不能直接等同于“在线识别”。encoder-decoder Transformer 可利用更长上下文，但若编码器要看完整输入，就需要额外设计分块、单调注意力或其他受限上下文策略才能低延迟输出。

Whisper 代表了大规模弱监督、多语言、多任务的 encoder-decoder 路线。论文报告训练数据约 68 万小时，其中描述了 96 种其他语言约 11.7 万小时以及约 12.5 万小时的跨语言到英语翻译数据；这些是训练混合中的描述维度，论文没有据此证明它们是互斥桶，不能把数字相加重算总量。长音频推理以 30 秒窗口为单位，时间戳滑窗和解码回退等策略会影响长音频表现（[Radford et al., 2022](https://arxiv.org/html/2212.04356)）。这些证据只支持论文所测模型、数据和协议下的结论，不保证所有语言、口音、噪声和实时场景都有相同效果。

### 35.4 WER、CER 与“听对了任务”

先固定大小写、标点、数字展开、Unicode 规范化和分词规则。若对整套语料汇总计数，参考词数为 `N>0`，替换、删除和插入数分别为 `S`、`D`、`I`，则词错误率为：

~~~math
\mathrm{WER}=\frac{S+D+I}{N}
~~~

中文等语言通常还会报告字符错误率，其中参考字符数 `N_c>0`，并须说明“字符”按何种规范化和计数单位定义：

~~~math
\mathrm{CER}=\frac{S_c+D_c+I_c}{N_c}
~~~

这里的分子、分母是对纳入的参考片段汇总后的计数；若改为先算每句 WER/CER 再做不加权平均，短句和长句的权重会变化，结果不等价，报告时要说清口径。插入数可能使错误率大于 1；空参考文本没有可用分母，应单独报告，不能静默丢弃。WER/CER 是转写层指标，不直接等于任务成功率。把“关掉二号阀门”听成“打开二号阀门”，只错了一个固定分词下的词，却改变了动作方向；把电话号码的一位数字听错，平均 CER 可能仍然很低，但业务风险很高。因此评估要另外记录关键词召回、数字准确率、实体准确率和任务意图保持率。

可以手算一个短例子。参考转写是“关闭二号阀门”，系统输出“开启二号阀门”。按字计算，两个字符串各有 6 个汉字，“关/开”和“闭/启”两处不同，编辑距离为 2，所以 CER 为 `2/6≈0.333`。若把它们按固定词表切成“关闭 / 二号 / 阀门”和“开启 / 二号 / 阀门”，则替换数为 1、参考词数为 3，WER 为 `1/3≈0.333`。两个分数都只反映转写差异；实际系统还应把这个方向相反的阀门命令单独计入任务错误，因为转写接近不等于执行安全。

### 35.5 流式识别的延迟账本

实时语音助手的用户感知延迟可以拆成：

~~~math
L_{\mathrm{e2e}}=
L_{\mathrm{capture}}+L_{\mathrm{endpoint}}
+L_{\mathrm{ASR}}+L_{\mathrm{LLM}}
+L_{\mathrm{TTS}}+L_{\mathrm{network}}
~~~

这是所有阶段串行执行时的近似账本。流式系统会让 ASR、LLM、TTS 和网络传输按 chunk 重叠，真实首响由关键路径决定，不能把各阶段的完整运行时间机械相加。`endpoint` 是系统判断用户暂时说完所等待的时间。等待太久，用户觉得迟钝；过早截断，系统会丢掉后半句。评测应固定计时起点和终点，区分模型产出首个音频块（TTFC）与客户端实际播出首音（TTFA），并记录首个稳定可理解片段、最终任务完成、打断后停止旧音频的时间及 p50/p95/p99，而不是只看平均值。

实时因子（RTF）常用于描述处理速度：

~~~math
\mathrm{RTF}=\frac{\text{处理音频所用时间}}
{\text{音频时长}}
~~~

`RTF<1` 表示离线处理速度快于音频播放速度，但实时体验仍可能被 endpoint、网络和模型排队拖慢。

例如，假设一段语音说完后，endpoint 等待 `240 ms`，ASR 用 `110 ms`，LLM 用 `280 ms`，TTS 生成首个可播放 chunk 用 `130 ms`，网络传输用 `40 ms`。从“用户说完”开始计时，首个音频响应约为 `240+110+280+130+40=800 ms`；若从两秒语音的开头计时，则端到端首响约为 `2,800 ms`。这两个数字描述的是同一链路、不同计时起点。若把模型推理从 `280 ms` 降到 `180 ms`，首响只下降 `100 ms`；若 endpoint 改善 `100 ms`，收益相同。这个账本能指出优化空间，也提醒我们必须先统一计时起点、首响定义和网络边界，再比较不同系统。

### 35.6 TTS 不只是把文字读出来

一个典型 TTS 链路包括文本规范化、音素或 grapheme 表示、声学模型和声码器：

```text
text normalization -> phoneme/text representation -> acoustic model -> vocoder -> waveform
```

文本规范化要处理数字、缩写、日期和单位；声学模型决定音高、时长、能量和韵律；声码器把声学特征转换为波形。高质量 TTS 还要控制音色、发音稳定性、情绪、停顿和多语言切换。

因此 TTS 评估不能只看一个“自然度”分数：至少要分开检查可懂度、发音、韵律、说话人一致性、chunk 连续性和首音延迟。主观评分依赖听者、材料、问题和播放条件；跨论文或产品比较前要核对评测协议，单一平均分不能替代这些切片。用于实时助手时，合成器需要流式输出音频，并允许用户在回答中途打断。如果 TTS 已经把整段回答一次性生成完，系统可能无法快速停止播放；如果切得过碎，韵律又会不自然。

### 35.7 级联语音助手与语音原生模型

级联系统的优点是模块成熟、数据和评估工具多、错误容易定位；缺点是 ASR 错误会传给 LLM，文本中间层会丢失语气，多个模块会叠加延迟。

语音原生路线可以让模型直接处理音频或 codec token，并生成语音 token。Moshi 论文给出用户与助手并行音频流的全双工研究系统，说明这种接口能表达重叠发言；论文中的延迟结果属于作者模型与实验设置，不可直接当作所有实时语音产品的保证（[Moshi 论文](https://arxiv.org/html/2410.00037)）：

```text
audio/codec tokens -> multimodal reasoning -> audio/codec tokens
```

它有机会保留说话人的停顿、情绪和重叠信息，也有机会实现更自然的全双工交互。但它需要更复杂的配对数据和安全控制，且“听懂”与“说得自然”不能用一个指标概括。产品中常见的做法仍是混合：文字 LLM 负责工具调用和长链路推理，语音模型负责低延迟输入输出。

2026 年的具体原生语音例子和时间戳/流式机制见[第二十一册 Qwen3.5-Omni 专题](../../book-21-transformer-architecture-evolution/chapters/93-qwen3.5-omni-aria-aut-timestamp与流式语音.md)；本讲只保留可迁移的系统接口和评估主线。

### 35.8 打断、重叠说话和状态机

语音对话不是简单的请求—响应循环。系统至少要区分：用户正在说话、用户暂时停顿、系统正在生成、系统正在播放、用户打断、多人同时说话和连接中断。

可以用状态机描述：

```text
LISTENING -> THINKING -> SPEAKING
     ^          |           |
     |          v           v
     +------ INTERRUPTED <-+
```

收到打断事件后，系统需要停止音频播放、取消未完成的 TTS chunk、保留或丢弃当前文本生成状态，并把新的语音片段送入 ASR。若只在业务逻辑层“忽略旧答案”，底层音频仍可能继续播放，用户就会听到新旧回答重叠。

实现上可给每轮生成分配递增的 `turn_id`：收到打断后先让播放器停止当前轮次，再取消 ASR/LLM/TTS 中仍可取消的任务；即使某个旧 chunk 因网络延迟稍后到达，客户端也按 `turn_id` 丢弃。还要把“用户短暂停顿”“明确结束一轮”和“打断后开启新一轮”分开建模，否则 endpoint 可能过早截断，或旧轮次在新轮次开始后复活。

### 35.9 语音安全与隐私

语音包含声音身份、环境背景和可能的敏感对话。音色克隆需要明确的授权和可追溯记录；录音存储需要最小化、加密、访问审计和删除策略。对高风险操作，不能把“听到一个人的声音”直接当成身份认证。

语音模型还可能放大有害建议的说服力。系统应对高风险内容采用文字与语音一致的策略，给关键数字、药物剂量和操作步骤提供可见文本或确认环节。防护重点是降低冒充、误听和不可逆操作，而不是简单地让模型拒绝所有语音请求。

### 35.10 一个可复核的帧移数量和错误率示例

两段代码都按 Python 3.6+ 标准库编写，无第三方依赖。第一段把音频长度换算为完整的 hop 区间数；它不读取 STFT 窗长，也不计算谱帧。第二段按 Unicode code point 计算字符编辑距离，不做文本规范化。将每段分别保存为 `.py` 文件运行。

```python
import math


def complete_hop_intervals(duration_seconds, sample_rate=16000, hop_ms=20):
    if (
        not isinstance(duration_seconds, (int, float))
        or isinstance(duration_seconds, bool)
        or not math.isfinite(duration_seconds)
        or duration_seconds < 0
    ):
        raise ValueError("duration_seconds must be finite and non-negative")
    if not isinstance(sample_rate, int) or isinstance(sample_rate, bool) or sample_rate <= 0:
        raise ValueError("sample_rate must be a positive integer")
    if (
        not isinstance(hop_ms, (int, float))
        or isinstance(hop_ms, bool)
        or not math.isfinite(hop_ms)
        or hop_ms <= 0
    ):
        raise ValueError("hop_ms must be positive and finite")
    hop_samples = round(sample_rate * hop_ms / 1000)
    if hop_samples <= 0:
        raise ValueError("hop is shorter than one sample")
    total_samples = round(duration_seconds * sample_rate)
    return total_samples // hop_samples


for seconds in (1, 5, 30):
    print(seconds, "seconds ->", complete_hop_intervals(seconds), "hop intervals")
```

按默认 16 kHz 和 20 ms 帧移，hop 为 `16000 × 0.020 = 320` 个采样点。1、5、30 秒的完整 hop 区间数分别为 `16000/320=50`、`80000/320=250` 和 `480000/320=1500`。若时长不足一个 hop，结果为 0；这与 STFT 帧数不同，后者还取决于窗口长度和 padding。

```python
def edit_distance(reference, hypothesis):
    if not isinstance(reference, str) or not isinstance(hypothesis, str):
        raise TypeError("reference and hypothesis must be strings")
    rows = len(reference) + 1
    cols = len(hypothesis) + 1
    dp = [[0] * cols for _ in range(rows)]
    for i in range(rows):
        dp[i][0] = i
    for j in range(cols):
        dp[0][j] = j
    for i in range(1, rows):
        for j in range(1, cols):
            substitution = dp[i - 1][j - 1] + (reference[i - 1] != hypothesis[j - 1])
            insertion = dp[i][j - 1] + 1
            deletion = dp[i - 1][j] + 1
            dp[i][j] = min(substitution, insertion, deletion)
    return dp[-1][-1]


def character_error_rate(reference, hypothesis):
    if not reference:
        raise ValueError("CER is undefined for an empty reference; report it separately")
    return edit_distance(reference, hypothesis) / len(reference)


reference = "打开二号阀门"
hypothesis = "打开二号阀"
distance = edit_distance(reference, hypothesis)
print("edit distance:", distance)
print("CER:", character_error_rate(reference, hypothesis))
```

## 第 36 讲：视频生成与时序世界建模

### 36.1 视频比图像多了什么

图像生成只需构造一个空间状态；视频生成要构造一串状态，并让这些状态之间形成可信的变化。视频可以表示为：

~~~math
X\in\mathbb{R}^{T\times H\times W\times C}
~~~

`T` 是帧数，`H` 和 `W` 是空间尺寸，`C` 是通道数。时间维度带来新的约束：一个物体不能在没有遮挡或运动解释时突然换身份，光照和背景不能无缘无故跳变，动作要具有连续性，物体交互要至少在视觉上自洽。

单独生成每一帧通常会得到闪烁、形变和身份漂移。把所有帧直接拼接成长序列又会遇到巨大的 token 和注意力成本。因此视频生成的核心是同时处理“压缩”和“连续性”。

### 36.2 时空 patch 和 token 预算

若每个时空块覆盖 `q` 帧、空间大小为 `p×p`，粗略 token 数为：

~~~math
N_{\mathrm{tubelet}}=
\left\lceil\frac{T}{q}\right\rceil
\left\lceil\frac{H}{p}\right\rceil
\left\lceil\frac{W}{p}\right\rceil
~~~

例如 16 帧、`336×336`、`q=2`、`p=14` 时，原始 patch 数为：

~~~math
8\times24\times24=4608
~~~

64 帧和 `672×672` 则会达到 `32×48×48=73728` 个块。真实系统通常先进行时空 VAE 压缩、分层 latent 建模、窗口注意力或 token 合并，所以原始数字不是最终显存预算；它能帮助我们看出为何时长和分辨率会迅速变贵。

### 36.3 视频生成路线的演进与取舍

第一条路线把图像扩散模型扩展到时间维度。Ho 等人的 Video Diffusion Models 将图像 U-Net 改成时空分解的 3D U-Net：卷积仍在空间内计算，并在空间注意力块后增加沿帧轴工作的时间注意力；联合图像与视频训练复用图像建模能力，再以条件采样逐段延长视频（[论文](https://arxiv.org/abs/2204.03458)）。Make-A-Video 延续预训练文生图模型的迁移思路，用图文配对数据学习语义、用无文本配对的视频学习运动，再加时空模块、插帧和超分辨率；这降低了对文本—视频配对数据的依赖，但运动和高分辨率细节仍依赖额外模块（[论文](https://arxiv.org/abs/2209.14792)）。

第二条路线先把视频编码成时空 latent，再用 Transformer 或 DiT 预测噪声或速度。CogVideoX 是一个具体实例：3D 因果 VAE 同时压缩空间与时间维，Transformer 联合处理文本和视频 patch；论文报告的配置可生成 10 秒、16 fps、768×1360 的视频。这些数字属于该论文的模型和评测设置，不是通用能力保证（[论文](https://arxiv.org/abs/2408.06072)）。压缩能缩短序列，但 VAE 重建质量会限制细节与运动保真；若对全部 latent token 做稠密自注意力，序列长度为 N 时，每头需要处理约 N×N 个 query-key 配对。举例说，N 从 4,096 增至 8,192，配对数从 16,777,216 增至 67,108,864，变为 4 倍；这是形状账本，不包含窗口化、稀疏注意力或具体 kernel 的影响。

第三条路线采用分层级联：先生成低分辨率或稀疏时间帧，再交替做空间超分辨率、时间超分辨率和插帧。Imagen Video 的论文系统由 7 个子模型构成，并报告 1280×768、24 fps、128 帧（约 5.3 秒）的输出；分阶段设计便于分别控制画质和帧率，但每一级都会增加计算，也可能引入跨阶段误差，局部时间窗口还可能难以维持全片运动一致性（[论文](https://arxiv.org/abs/2210.02303)）。Lumiere 探索另一种取舍：Space-Time U-Net 在时空多尺度表示中一次处理完整片段，再用重叠窗口做空间超分辨率；作者指出它仍受显存约束，且不处理多镜头场景切换（[论文](https://arxiv.org/abs/2401.12945)）。所以级联、全片时空建模和 latent Transformer 各有成本与边界，不能仅凭示例画质排出通用优劣。

把它们并列起来，可以看到设计核心是在图像先验复用、时序范围、latent 压缩和显存之间选择折中；表中的约束是论文中具体方案的瓶颈提示，不是每个同类系统的必然缺陷。

| 路线 | 代表方案 | 主要机制 | 需要重点核对的代价或边界 |
| --- | --- | --- | --- |
| 时空分解 U-Net | Video Diffusion Models、Make-A-Video | 复用图像扩散主干，增加时间卷积或注意力 | 固定片段长度、时间模块成本与后续延展策略 |
| latent Transformer | CogVideoX | 3D VAE 压缩时空 latent，再以 Transformer 联合处理文本和视频 | VAE 重建损失；稠密全注意力的 token 配对量按 N² 增长 |
| 时空级联 | Imagen Video | base video model 与空间/时间超分辨率子模型串接 | 多级采样成本、跨阶段误差和局部窗口的一致性 |
| 全片时空网络 | Lumiere | Space-Time U-Net 一次处理片段完整时长 | 高分辨率空间超分辨率仍受显存和窗口约束；多镜头转场未覆盖 |

### 36.4 条件控制与长视频一致性

文本条件通常由文本编码器变成上下文向量，再通过 cross-attention 或条件调制进入视频去噪网络。图像条件可以提供主体和风格，深度、姿态、光流和轨迹则可以提供结构控制。

一个 prompt 可能同时包含主体、属性、动作、镜头和时间顺序：

```text
一只白色小狗先坐下，然后抬头看向窗外，镜头缓慢向右移动。
```

系统需要分别满足：小狗颜色稳定、主体身份稳定、动作先后正确、镜头运动符合描述。把整句话作为一个向量，未必能让模型显式表示“先”和“然后”。时间分段、轨迹条件、关键帧和分层生成可以改善可控性，但每个额外控制信号都会增加数据和接口复杂度。

### 36.5 逼真视频与 world model 的距离

视频生成会迫使模型学习一些外观和运动的统计规律，因此人们常把它与 world model 联系起来。但“生成一段看起来合理的视频”和“具备可交互、可预测、可反事实的世界模型”是不同命题。

严格意义上的世界预测模型可以写成：给定过去观察 `o_{1:t}` 和动作 `a_{t:t+k}`，模型预测未来状态或观察：

~~~math
\hat o_{t+1:t+k}=F_\theta(o_{1:t},a_{t:t+k})
~~~

如果模型只根据文本生成一段视觉上合理的运动，它可能没有接受真实动作，也没有在新环境中进行可检验的状态转移。要讨论世界建模，至少需要测试：

1. 未来帧预测，而不是只看从噪声采样的漂亮结果。
2. 动作条件下的结果是否随动作改变。
3. 遮挡后物体能否保持身份和位置。
4. 反事实动作是否得到一致的结果。
5. 新物体、新场景和新组合上的泛化。
6. 长时间滚动预测是否累积崩坏。

近期的路线实例是 World-in-Context（arXiv v1，2026-10-23）：它把视角模式、角色动作和摄像机运动编码为上下文控制 token，并提出 IT-RoPE 表示累计控制变化；作者在 WBench 上评估该方法。这个预印本展示了一种显式控制接口，不证明其他模型共有这组机制或已具备一般物理理解（[论文](https://arxiv.org/html/2610.33169)）。

因此，Sora 等模型的公开演示可以支持“高质量文本到视频”和“模型可能学习了部分时空规律”的判断；它不能单独证明模型已经具备可交互、可验证的物理世界模型。对闭源模型的内部 tokenizer、数据配方和具体网络结构，也应以官方技术说明为准，不能用社区逆向猜测替代一手证据。

### 36.6 Sora 的资料边界

本节把 OpenAI 于 2024 年 2 月发布的 Sora 技术说明作为历史研究案例：该报告公开了文本条件扩散、时空 patch 表示等研究方向，但明确不包含模型和实现细节（[官方研究说明](https://openai.com/index/video-generation-models-as-world-simulators/)）。截至 2026-10-29，OpenAI Help Center 记录 Sora 网页与应用于 2026-04-26 停止服务，Sora API 于 2026-09-24 停止服务（[停止服务说明](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation)）。历史技术报告说明的是当时公开研究，不代表当前可用的产品或 API，也不支持对未披露内部实现的推断。

书写 Sora 时应采用三层表述：

1. 可以直接引用公开页面展示的输入输出能力。
2. 可以引用技术说明中明确给出的训练或建模原则。
3. 对未公开的架构细节、数据规模和训练配方，只能标为未披露或研究推测。

二手综述可以帮助了解讨论脉络，但不能用来证明闭源模型内部事实。这个证据边界不仅适用于 Sora，也适用于所有快速迭代的商业多模态模型。

### 36.7 视频生成的评估矩阵

单帧质量高不代表视频好。一个完整评估至少包含：

| 维度 | 关注点 | 例子 |
| --- | --- | --- |
| 单帧质量 | 清晰度、结构、纹理 | 人脸、物体边缘、文字 |
| 文本对齐 | 主体、属性、动作、镜头 | 是否先坐下再抬头 |
| 时间一致性 | 身份、位置、颜色和背景 | 手指数量、衣服纹理 |
| 运动合理性 | 速度、碰撞、重力和遮挡 | 球落地、门被推开 |
| 长程一致性 | 跨较长时间的状态 | 物体离开后是否合理返回 |
| 可控性 | 条件变化是否带来预期变化 | 改变轨迹、姿态或关键帧 |
| 安全与来源 | 伤害、身份、版权、出处 | 深度伪造和误导性证据 |

FVD（视频生成的 Fréchet 距离指标，见 [Unterthiner et al.](https://arxiv.org/abs/1812.01717)）等自动指标可以提供批量比较线索，但会受特征提取器、视频长度、采样率和数据分布影响。文本—视频相似度也可能奖励“看起来像”而不是真正完成动作。可靠评估要同时使用自动指标、人工偏好、任务型检查和失败案例审计。

一个近期例子是 2026 年提出的 WBench。它把交互式视频世界模型评估拆成视频质量、场景设定遵循、交互遵循、跨轮一致性和物理合理性五个维度，包含 289 个案例和 1,058 轮交互；交互类型包括导航、主体动作、事件编辑和视角切换。论文还报告用专家视觉模型与多模态模型组成 22 个自动子指标，并以人工判断校验。它的设计说明：单轮 prompt 对齐或单帧画质无法替代多轮动作之后的状态一致性检查；不过这仍是一个具体 benchmark，其任务集、模型接口和自动评分器不能代表所有世界模型能力，也不能直接证明真实环境中的物理理解。[WBench 论文](https://arxiv.org/html/2605.25874)

### 36.8 视频理解与视频生成不能混为一谈

视频理解回答“已经发生了什么”，视频生成回答“在条件下应该生成什么”。理解模型可以使用抽帧、时序编码器、音视频联合模型和长视频检索；生成模型则要从噪声或 latent 状态构造未来画面。

两者有交叉：视频 caption 和动作标签可以为生成模型提供训练监督，生成模型也可能学习到有助于预测的时序结构。但生成得像真的，并不保证能准确回答视频中的细节；理解模型在 benchmark 上分数高，也不意味着它能生成连续的未来。

### 36.9 视频系统的安全和来源

视频比静态图片更容易被当作“发生过的证据”。人物身份、声音、场景和动作可以被组合成具有强误导性的内容。防护应覆盖生成前、生成中和生成后：

1. 对敏感人物、真实事件和高风险场景设置更严格的策略。
2. 对生成请求和输出保留审计记录，限制批量滥用。
3. 使用来源标识、内容凭证或水印帮助下游识别生成来源；例如 [C2PA 规范](https://spec.c2pa.org/specifications/specifications/2.2/index.html)定义了可携带来源信息的内容凭证。
4. 对身份冒充、未经授权肖像和版权风格做专门测试。
5. 把安全评估纳入质量回归，而不是只在发布前做一次检查。

水印或来源凭证不能证明内容真实，也可能被裁剪或转换破坏；它们的作用是增加追溯线索，不能替代事实核验。

### 36.10 视频 token 估算代码

下面的纯 Python demo 按 Python 3.6+ 标准库编写，无第三方依赖；输入正整数帧数、分辨率、tubelet 和 patch size，输出未压缩时空 patch 数。不满一个 patch/tubelet 按补齐计，可独立保存并运行。

```python
def video_tokens(frames, height, width, tubelet=2, patch_size=14):
    for value, name in [
        (frames, "frames"),
        (height, "height"),
        (width, "width"),
        (tubelet, "tubelet"),
        (patch_size, "patch_size"),
    ]:
        if not isinstance(value, int) or isinstance(value, bool) or value <= 0:
            raise ValueError(f"{name} must be a positive integer")
    time_tokens = (frames + tubelet - 1) // tubelet
    height_tokens = (height + patch_size - 1) // patch_size
    width_tokens = (width + patch_size - 1) // patch_size
    return time_tokens * height_tokens * width_tokens


settings = [
    (16, 336, 336),
    (64, 336, 336),
    (64, 672, 672),
]

for frames, height, width in settings:
    count = video_tokens(frames, height, width)
    print(f"{frames} frames {height}x{width} -> {count} raw tokens")
```

预期 raw token 数依次为 `4608`、`18432`、`73728`。这是 patch 计数，不是模型实际接收的 token 数，也不等同于服务端计费 token。

这个估算可以继续与实际系统对照：记录 VAE 压缩后的 latent 形状、模型真正使用的 token 数、注意力窗口和每一步采样耗时。原始 patch 数与服务端计费 token 可能完全不是同一个量，不能把两者混用。

### 36.11 本部分的贯穿结论

CLIP 让图像和语言可以在共同空间中比较，VLM 让视觉特征参与语言生成，扩散模型让连续图像和视频可以通过逐步 refinement 生成，语音模型把时间信号接入识别和对话，视频模型进一步面对跨帧的状态和运动。

贯穿这些主题的不是某个模型名字，而是同一组工程问题：表示是否保留了任务所需的信息，训练目标是否奖励证据而不是流畅猜测，压缩是否在成本和细节之间取得可接受平衡，评估是否覆盖真实失败，系统是否能在不确定时回退或请求核验。多模态能力的边界必须通过任务、数据和服务条件来描述，而不能由输入格式或演示样例单独决定。
