# 第五部分：综合复习与技术表达

前四部分已经分别讲过语言模型、Transformer、训练与推理、多模态系统。真正困难的地方在于：现实中的技术问题很少按照章节标题出现。你遇到的可能是“模型最近变笨了”“延迟突然升高”“图片问答经常数错”“训练 loss 下降但线上质量变差”，而不是“请解释某个公式”。

因此，综合复习不是把前面的定义再抄一遍，也不是把一组固定题目背熟。它要训练两种可迁移的能力：第一，把模糊现象变成明确的任务契约和可验证假设；第二，把见过的知识变成能够在陌生数据、陌生约束和时间压力下重新推导的判断。本部分用开放问题诊断和学习迁移两条主线来完成这件事。

初学者可以把它看成一套“从现象到证据”的工作方法：先说清楚问题，再找最可能的原因，设计最小实验，读懂结果，最后比较方案。熟悉模型的读者则应关注实验的因果有效性、指标与目标的错位、样本污染、统计不确定性和成本—质量曲线。只有能解释“为什么知道”和“如果结果相反怎么办”，知识才真正脱离了摘要。

## 第 37 讲：开放技术问题的系统拆解

### 37.1 闭合问题与开放问题

闭合问题有相对明确的对象和答案空间，例如“因果语言模型为什么需要右移 labels”“GQA 为什么能减少 KV cache”。回答这类问题时，定义、公式、张量形状和一个小例子通常足够。

开放问题则从一个现象或目标开始，缺少完整条件。例如：

```text
模型的数学能力变差了，应该怎样改进？
```

这句话至少隐藏了八个未知量：变差的是哪个数据分布，下降发生在训练还是线上，最终答案还是过程质量，是否伴随延迟或成本变化，评估集是否被污染，生成参数是否改变，是否只有某种语言或题型受影响，以及“改进”允许增加多少数据、算力和人工审核。

如果直接回答“增加数学数据、加入过程监督、提高推理预算”，这些建议可能都合理，却没有说明它们针对哪个原因，也没有说明如何知道某个改动真的有效。开放问题的核心不是列出更多名词，而是把不确定性组织成实验。

### 37.2 先写任务契约，再讨论方案

一个可用的任务契约至少包含输入、输出、目标、约束、证据和失败处理。可以把它抽象为：

~~~math
\mathcal{C}=(I,O,G,K,E,F)
~~~

其中：

- `I`：输入分布和数据切片；
- `O`：输出格式与可执行动作；
- `G`：真正要优化的目标；
- `K`：硬约束，如延迟、显存、许可和安全；
- `E`：判断结果所需的证据；
- `F`：失败时的回退、重试或人工接管。

以“数学能力变差”为例，先把它改写成可测量的契约：在固定题型切片和固定生成预算下，最终答案准确率从 72% 降到 61%；p95 延迟不能增加超过 20%；对需要计算器或代码执行的题目，工具结果必须可复核；无法确认时允许返回不确定状态。这样，后续讨论才有共同对象。

小白容易把“模型答错”当作唯一目标。专家需要再问一步：是答案错、过程错、格式错、工具用错，还是评估器错？如果不把这些对象分开，改进一个指标可能只是把错误搬到了另一个位置。

### 37.3 症状、机制与根因

同一个表面症状可以由完全不同的机制造成。数学答案下降可能来自数据分布、tokenizer、训练目标、解码策略、工具连接或评估污染；视觉问答下降可能来自图像预处理、视觉 token 压缩、连接器、答案生成或 OCR 回退。

可以先画一条最小因果链：

```text
数据与切分 -> 表示与输入 -> 模型与训练 -> 推理与工具 -> 评估与产品指标
```

每一层都要问两个问题：如果这一层是原因，哪个可观察量应该一起变化？如果干预这一层，其他条件如何保持不变？例如，若怀疑 tokenizer 造成数字能力下降，可以比较同一批题目在不同 tokenizer 下的 token 长度、数字边界和训练 loss；若只继续增加数学数据而不做这个对照，就无法排除表示问题。

一个实用的错误归因表如下：

| 观察到的现象 | 可能机制 | 首先测什么 | 不应直接推出的结论 |
| --- | --- | --- | --- |
| loss 下降、答案变差 | 训练目标与任务不一致、数据污染 | 独立验证集、切片 loss、答案准确率 | 模型容量不足 |
| 平均准确率不变、p95 变高 | 生成变长、工具重试、排队 | 输出长度、工具事件、队列等待 | 模型变慢 |
| 视觉描述流畅但计数错误 | 全局语义先验、细节被压缩 | 反事实图片、局部 crop、计数集 | 语言模型不会推理 |
| 加大采样后分数上升 | 候选覆盖改善或评估器偏置 | 独立 verifier、候选相关性、单位成本 | 单次回答质量变高 |
| 新模型 benchmark 变好、业务失败 | 分布错位、协议/工具不匹配 | 真实任务回放、外部状态验收 | benchmark 无价值 |

表格不是排查顺序的替代品。它的作用是防止我们把熟悉的方法名当作根因。每个候选机制都应该对应一个观测、一个干预和一个可能推翻它的结果。

### 37.4 用信息价值安排实验顺序

工程时间有限，不可能一次验证所有假设。实验优先级可以用“预期信息价值”来近似思考。假设集合为 `H`，当前对假设的信念为 `P(h)`，实验 `e` 可能产生结果 `r`，则信息增益的一个抽象写法是：

~~~math
\mathrm{IG}(e)=H(P(H))-
\mathbb{E}_{r\sim P(r\mid e)}
\left[H(P(H\mid r,e))\right]
~~~

`H(·)` 是熵。这个公式不要求你真的计算概率；它提醒我们优先做能够区分多个原因的实验，而不是只做“看起来有用”的改动。

在产品环境中，还要考虑实验成本和错误风险。可以把实验价值写成：

~~~math
\mathrm{VOI}(e)=
\frac{\mathrm{ExpectedDecisionGain}(e)
\times\mathrm{RiskReduction}(e)}
{\mathrm{Cost}(e)+\mathrm{OpportunityCost}(e)}
~~~

例如，重新训练一个大模型可能直接改变结果，却很难解释为什么；先用同一 checkpoint 做 greedy、self-consistency、工具验证和不同数据切片对照，成本小、区分度高，通常更值得先做。若系统涉及真实转账、发布代码或医疗建议，还要把不可逆风险纳入实验成本，优先使用离线回放和沙箱。

### 37.5 Worked example：数学推理能力下降

假设一个 7B 模型在内部数学集上的准确率从 72% 降至 61%，但通用问答没有明显变化。我们不先选择方案，而是建立基线表：

| 切片 | 旧版本 | 新版本 | 变化 |
| --- | ---: | ---: | ---: |
| 算术 | 0.86 | 0.79 | -0.07 |
| 代数 | 0.74 | 0.62 | -0.12 |
| 几何文字题 | 0.60 | 0.57 | -0.03 |
| 代码可验证题 | 0.78 | 0.77 | -0.01 |
| 无答案泄漏变体 | 0.70 | 0.59 | -0.11 |

这个切片已经排除了“所有数学均匀下降”的简单叙述。代数和无泄漏变体下降明显，代码可验证题基本不变，说明可能存在数据、格式或解码交互，而不是单纯的通用能力消失。

#### 第一组实验：评估是否稳定

固定 checkpoint、prompt、temperature、top-p、最大输出长度和答案解析器，重复三次评估。若同一版本的波动已经接近 0.11，就不能把一次分数差异当成模型退化。对二项结果，可用近似标准误：

~~~math
\mathrm{SE}(\hat p)\approx
\sqrt{\frac{\hat p(1-\hat p)}{n}}
~~~

这只是独立样本的粗略近似；题目之间高度相关时，需要按题目来源或模板做成组 bootstrap，而不是机械套公式。

#### 第二组实验：区分数据、训练和推理

用旧版本和新版本在四个条件下运行同一题集：原始 prompt/原始解码、原始 prompt/固定 greedy、改写 prompt/原始解码、工具验证/原始解码。如果只改解码就恢复，问题更可能在生成选择；如果只有工具验证恢复，说明模型内部过程可能没有稳定收敛；如果所有条件都下降，则继续看训练数据和表示。

#### 第三组实验：检查训练目标

抽取训练和验证中相同题型，分别记录完整序列 loss、答案 token loss、步骤 token loss 和最终答案准确率。SFT 可能让解释变得更长，但只要最后一个数错，业务上仍然失败。若步骤 loss 下降、答案准确率下降，需要检查 label mask、答案解析、数据中间步骤和偏好模型是否奖励了冗长表达。

#### 第四组实验：检查污染和切分

对评估题做数字、实体和语序改写，保持解题结构不变；再构造组合新题，并检查训练语料中的近重复。若原题分数很高、改写题大幅下降，说明结果可能依赖记忆或表面模式。这个实验不能证明模型没有推理能力，却能证明原 benchmark 不足以支持强结论。

经过这些实验，可能得到不同决策：

1. 只是解码问题：先修正默认参数和答案解析，不急着重新训练。
2. 只有无泄漏题下降：先治理数据配比和污染，再比较训练方案。
3. 答案 loss 与步骤 loss 失配：检查 mask、过程标注和 verifier。
4. 工具验证有效但延迟超预算：采用难题路由，给简单题保留便宜路径。
5. 所有切片都下降且表示长度异常：检查 tokenizer、上下文截断和 checkpoint 恢复。

这比“加数学数据”更像工程判断，因为每个方案都由观测支持，并且明确了下一步如何证伪。

### 37.6 Worked example：幻觉不是一个单一指标

把“幻觉严重”直接当成一个比例，会掩盖不同错误的修复路径。可以拆成四类：

1. 事实幻觉：输出与可核验事实冲突。
2. 证据幻觉：引用不存在、无关或不足以支持结论的资料。
3. 推理幻觉：前提正确，但计算、因果或逻辑关系错误。
4. 工具幻觉：声称调用了工具、读取了文件或完成了动作，但事件账本没有记录。

一个合同助手的回答可以被表示为 claim 集合 `C={c_1,\ldots,c_m}`，每个 claim 需要对应证据集合 `E_i`。支持率可定义为：

~~~math
\mathrm{SupportRate}=
\frac{\sum_{i=1}^{m}w_i\mathbf{1}
\left[E_i\Rightarrow c_i\right]}
{\sum_{i=1}^{m}w_i}
~~~

这里的指示函数在证据足以支持 claim 时取 1，否则取 0；`w_i` 可以按照风险、金额或可逆性设定。没有证据的回答不一定全部错误，但应该降低断言强度或触发核验。对高风险 claim，系统可能宁愿返回“当前材料无法确认”，也不应使用流畅语言填补空白。

诊断实验可以建立四个对照：无检索、检索但不强制引用、检索且要求 claim—evidence 对齐、检索加外部计算器。若引用支持率上升但答案完整性下降，说明检索或引用格式挤占了上下文；若工具调用增加但错误不降，可能是工具选择或结果解释有问题，而不是工具数量不够。

### 37.7 Worked example：设计统一多模态系统

“设计一个能处理文本、图像、语音和视频的模型”也不能直接落到“使用统一 Transformer”。先区分目标任务：实时语音对话关心首包延迟和打断，发票审核关心 OCR 和字段证据，视频检索关心时间覆盖，开放创作关心生成质量和安全来源。

一个合理的设计分层如下：

```text
模态适配层：采样、裁剪、codec、OCR、时间戳和许可
表示层：patch、频谱、离散 token、latent 与位置元数据
融合层：prefix、cross-attention、query resampler 或统一序列
推理层：语言生成、工具调用、检索、verifier 和状态管理
服务层：缓存、批处理、流式传输、回退、审计和权限
```

每层都要有独立的测试。图像输入通过接口不代表小字可读；统一 embedding 形状不代表语义对齐；模型生成文本不代表引用证据；端到端语音不代表能正确处理打断。架构讨论的质量，取决于能否说出每个接口的可观测量和失败回退。

### 37.8 新模型信息的证据等级

快速发布的模型容易造成一种错觉：只要记住模型名和宣传语，就掌握了最新技术。更可靠的做法是给陈述标注证据等级：

| 等级 | 信息来源 | 可以支持的陈述 |
| --- | --- | --- |
| A | 原论文、官方技术报告、模型卡 | 方法、训练目标、公开实验和明确限制 |
| B | 官方产品页、API 文档、system card | 对外提供的接口、公开展示和产品约束 |
| C | 高质量复现、独立评测、公开代码 | 在特定设置下的实现行为和可复现实验 |
| D | 社区逆向、传闻、单次 demo | 研究假设或待核验线索 |

A 级资料也不意味着普遍有效；论文实验有数据、硬件和评估口径。B 级资料不等于内部架构披露。D 级信息可以启发实验，但不应写成“该模型一定采用某组件”。当无法核验时，最专业的表述不是填补空白，而是说明已知事实、未知部分和验证方法。

### 37.9 质量、延迟、成本与安全的取舍

开放问题经常要求“同时提高质量并降低成本”。在没有额外约束时，这句话是不完整的。可以把一次服务配置表示为：

~~~math
\mathbf{m}=(Q,L,C,R)
~~~

其中 `Q` 是任务质量，`L` 是延迟，`C` 是单位成本，`R` 是风险。配置 `a` 若在所有维度不差、至少一项更好，就支配配置 `b`；不能被其他配置支配的点形成 Pareto 前沿。

工程上通常不是寻找绝对最优点，而是按照请求类型选择不同点：简单请求走小模型和短上下文，复杂请求增加 verifier 或检索，高风险请求增加证据和人工确认。报告结果时要同时给出质量、p95 延迟、单位成功成本、拒答和风险事件；只展示平均准确率，会把真正的产品取舍隐藏起来。

### 37.10 开放问题中的安全推理

安全不是开放题最后附加的一句“注意风险”。它应该在任务契约中出现：输入是否含有个人信息，输出是否会触发外部动作，错误是否可逆，证据是否可审计，谁有权批准高风险步骤。

例如，调试一个代码 Agent 时，除了测试通过率，还要记录它是否读取了不应读取的文件、是否修改了无关路径、是否执行了未经批准的网络命令；调试一个语音助手时，还要记录声音身份授权、录音留存和高风险建议的确认流程。安全实验应使用隔离环境、合成数据和无害回归样本，不能为了“测试注入”而把真实凭据暴露给模型。

### 37.11 一个最小的实验优先级示例

下面的纯 Python 代码把几个候选实验按照预期收益、风险降低和成本排序。数字是教学构造，不是某个产品的实测值；它展示的是怎样把口头建议改成可比较的决策记录。

```python
experiments = [
    {
        "name": "固定解码参数重跑",
        "decision_gain": 0.55,
        "risk_reduction": 0.20,
        "cost": 1.0,
    },
    {
        "name": "无泄漏改写集",
        "decision_gain": 0.90,
        "risk_reduction": 0.75,
        "cost": 2.0,
    },
    {
        "name": "重新训练大模型",
        "decision_gain": 0.80,
        "risk_reduction": 0.40,
        "cost": 25.0,
    },
    {
        "name": "工具验证回放",
        "decision_gain": 0.70,
        "risk_reduction": 0.85,
        "cost": 4.0,
    },
]


def value_of_information(item):
    return item["decision_gain"] * item["risk_reduction"] / item["cost"]


ranked = sorted(experiments, key=value_of_information, reverse=True)
for item in ranked:
    print(item["name"], round(value_of_information(item), 3))
```

运行结果会把“无泄漏改写集”和“工具验证回放”排在大规模重训之前。真实项目还要加入数据新鲜度、并行资源、实验风险和结果可复用性；但只要把排序依据写出来，团队就能讨论假设，而不是争论谁的经验更强。

### 37.12 技术判断应留下什么证据

一次开放问题分析至少应该留下四种产物：

1. 问题契约：目标、约束、失败定义和风险边界。
2. 假设表：每个可能原因、支持证据、反证和优先级。
3. 实验记录：数据切片、固定变量、运行版本、指标和异常。
4. 决策记录：选择了什么、放弃了什么、为什么、下一步如何复核。

这些产物比一段听起来完整的口头表达更可靠。它们允许另一个人复现实验，也允许在结果相反时快速修正判断。技术表达的底层不是修辞，而是让因果链和证据链可检查。

### 37.13 本讲的核心思想

开放问题没有唯一台词，但有可重复的推理纪律：先定义任务契约，再把症状拆成机制假设；先做区分度高、风险低的实验，再决定是否增加数据、模型或推理预算；报告质量时同时报告证据、成本、延迟和安全。未知事实应保持未知，直到有足够等级的资料或受控实验支持它。

## 第 38 讲：学习迁移与技术表达

### 38.1 “见过”不等于“会用”

阅读一个公式时产生的熟悉感，很容易被误认为掌握。真正遇到空白纸张、陌生题目或代码错误时，能否从定义重建公式、解释变量、写出 shape、预测失败模式，才是更强的证据。

可以把知识状态分成四层：

1. 识别：看到术语能说出大概主题。
2. 回忆：没有原文也能给出定义、公式和变量。
3. 迁移：换数据、换约束或换表述后仍能使用机制。
4. 诊断：结果异常时能提出实验，区分多个原因。

很多“复习完成”只证明了第一层。大模型工程需要至少达到后三层，因为线上问题不会把缺失信息整理成教材小节。

### 38.2 检索练习与间隔安排的证据

学习科学中的一个稳定发现是：主动回忆比反复重读更能暴露遗忘，间隔安排通常比一次性集中重复更有利于延迟保持。Roediger 与 Karpicke 的实验把重复阅读和立即测试进行比较，发现短期测试可能让重读占优，但延迟测试中先前测试带来更好的保持；Cepeda 等人的综述和定量综合则显示，分散练习的收益受保持间隔、练习间隔和材料类型影响，不存在一个适用于所有人的固定天数。

这两个结论不能机械翻译成“每天用某个间隔就一定最好”。对技术学习而言，更合理的实现是：第一次学完后关闭资料，重建核心公式；几天后用改写问题检索；再过一段时间做代码或反事实实验；如果失败，记录具体缺口并重新安排。时间表服务于检索难度，而不是替代理解。

可以用一个衰减模型作为工作假设，而不是心理规律的精确公式：

~~~math
R(t)=R_0\exp\left(-\frac{t}{\tau}\right)
~~~

`R(t)` 表示在时间 `t` 后回忆成功的近似概率，`τ` 是个人、材料和练习方式共同决定的时间尺度。一次成功的主动检索可能增加 `τ`，一次失败则说明当前间隔过长或理解不完整。这个模型的价值在于帮助安排测量，不在于预测每个人的记忆曲线。

### 38.3 用四种产物证明一个知识点

对本书中的每个核心知识点，至少制作四种不同产物：

#### 解释产物

用自己的语言说明它解决了什么旧问题。比如，不能只说“KV Cache 加速推理”，而要说明自回归 decode 每一步都会重复计算历史键值，缓存把已确认的历史表示保留下来，代价是显存随层数、头数、序列长度和 dtype 增长。

#### 推导产物

不看原文写出公式，并解释每个符号和边界。对 attention，要能从 `QK^T` 的 shape 推到 mask 和 softmax；对 DPO，要能说明 chosen/rejected 的 log probability 如何与 reference 差值组合。

#### 实现产物

写一个最小版本，哪怕只处理小数组。代码必须有输入 shape、输出 shape、一个断言和一个能解释的结果；只复制框架 API 不足以证明理解。

#### 破坏产物

主动构造会让它失败的情况：padding、重复样本、长序列、小目标、噪声、分布外问题、错误工具结果或权限冲突。能指出反例，说明你知道方法的适用边界。

可以把四类证据写成一个粗略的学习强度分数：

~~~math
S_{\mathrm{mastery}}=
0.2E+0.25D+0.25I+0.30B
~~~

`E,D,I,B` 分别表示解释、推导、实现和破坏测试的质量。权重只是记录工具，不是普遍真理；对安全和部署主题，破坏测试的权重应更高，对数学基础，推导权重可能更高。

### 38.4 第一册的依赖图

第一册不是 38 个互相独立的名词，而是一张依赖图。前面的概念为后面的概念提供变量和问题背景：

```text
概率与优化
    -> tokenizer / embedding / attention
    -> Transformer block / position / context
    -> pretraining / data / scaling / distributed training
    -> SFT / preference / reward / reasoning
    -> decoding / KV cache / IO / quantization
    -> evaluation / safety / product reliability
    -> CLIP / VLM / diffusion / speech / video
    -> open problem diagnosis and technical communication
```

如果 attention 的 shape 没有真正掌握，后面很难准确理解 KV cache；如果 SFT label mask 没有掌握，DPO 的 response log probability 就容易错位；如果评估与证据边界没有掌握，所谓“最新模型能力”就会退化成宣传语的抄写。

复习应沿依赖边逐步恢复，而不是每周随机刷一个热门名词。随机抽题仍然有价值，但它应该用来检测迁移，不应成为唯一学习顺序。

### 38.5 把 12 周看成资源分配问题

固定 12 周不是知识规律，而是一个可调整的项目边界。设每周可投入时间为 `h_w`，概念、推导、实现、实验和表达的时间比例为 `a,b,c,d,e`，则：

~~~math
a+b+c+d+e=1,qquad
H_k=\sum_{w\in W_k}h_w
~~~

`H_k` 是主题 `k` 可获得的总时间。若某主题只有阅读没有实现，比例 `c` 接近零，即使笔记很长，迁移证据仍然不足。

一个较完整的节奏可以这样安排：

| 周次 | 主线 | 必须留下的证据 | 为什么此时安排 |
| --- | --- | --- | --- |
| 1--2 | 概率、next-token、loss、优化 | 手算交叉熵和一个 loss 诊断 | 后面所有训练目标都依赖这些变量 |
| 3--4 | tokenizer、attention、mask、block、RoPE | shape 推导、mask 反例、最小 attention | 建立 Transformer 的信息流 |
| 5--6 | 数据、预训练、scaling、分布式 | 数据审计表、预算账本、通信分析 | 把模型放回训练系统 |
| 7--8 | SFT、RLHF、DPO、reward、reasoning | label mask、偏好 loss、失败偏好样本 | 理解行为如何被后训练改变 |
| 9--10 | decode、cache、IO、量化、评估安全 | 容量估算、延迟曲线、错误切片 | 连接模型与线上服务 |
| 11 | CLIP、VLM、diffusion、语音、视频 | 一个多模态成本与证据实验 | 扩展到非文本信号 |
| 12 | 综合开放问题和未知变体 | 诊断报告、项目复盘、完整回放 | 检查能否跨主题迁移 |

每个阶段都应包含短检索、间隔回忆和一次综合实验。若第 8 周发现 attention shape 仍然混乱，应回到第 3--4 周的依赖，而不是为了赶日历继续向后堆概念。计划的作用是暴露资源不足，不能把日历完成率当成能力指标。

### 38.6 项目叙述是一条证据链

技术项目不能只写成“用了某模型，指标提升了”。一个可信的项目叙述至少要连接问题、数据、方法、基线、实验、失败和下一步：

```text
业务问题 -> 任务契约 -> 数据与切分 -> baseline
    -> 干预 -> 指标变化 -> 失败归因 -> 下一步实验
```

例如，做一个领域 SFT 项目时，不能只说“训练后更聪明”。应说明：原模型在什么输入上失败，训练数据如何去重和划分，assistant-only mask 是否正确，base 与 SFT 是否使用同一 prompt 和 decoding，格式通过率、事实支持率、拒答率和延迟怎样变化，哪些切片出现回归。

一个小型结果表比形容词更有说服力：

| 指标 | Base | SFT | 变化 | 解释 |
| --- | ---: | ---: | ---: | --- |
| 任务关键词命中 | 0.62 | 0.84 | +0.22 | 目标任务改善 |
| JSON 格式通过 | 0.48 | 0.91 | +0.43 | 协议遵循改善 |
| 证据支持率 | 0.77 | 0.73 | -0.04 | 需检查过度断言 |
| 高风险误答 | 0.06 | 0.08 | +0.02 | 不能只看平均质量 |
| p95 延迟 | 820 ms | 910 ms | +90 ms | 输出变长或服务配置变化 |

这张表没有告诉我们 SFT 一定值得上线，但它提供了继续调查的方向：格式改善是否以事实性和安全为代价，延迟增加是否可接受，是否需要更好的数据或路由。项目表达的核心不是把结果包装得漂亮，而是让别人能够复核你的因果判断。

### 38.7 模拟交流应当是测量工具

一次模拟技术交流不是表演，也不是把原题再背一遍。它应当像一次实验：固定时长和主题，使用没有提前背过的轻微变体，记录问题、回答、追问、停顿、公式错误和无法解释的 trade-off。

可以把一次表现拆成不同维度：

~~~math
S_{\mathrm{session}}=
w_dD+w_mM+w_xX+w_fF+w_rR
~~~

`D` 是定义准确性，`M` 是机制和公式，`X` 是实验/证据，`F` 是失败与取舍，`R` 是风险意识。权重应随目标岗位改变：研究岗位提高机制和实验权重，推理服务岗位提高资源账本，Agent 岗位提高权限与恢复。

一次得分不能代表趋势。至少要保留多次记录，比较相同主题在不同时间的变化，并把每个错误归入可修复类别。若某次只问到熟悉题目而表现很好，不能把它当成迁移成功；若轻微改写就失败，应增加反事实与组合题。

### 38.8 错误日志要指向下一次动作

“这题不会”不是可执行的错误类别。更有用的分类包括：

| 错误类别 | 典型表现 | 下一次动作 |
| --- | --- | --- |
| 定义缺失 | 说不清方法解决什么问题 | 写问题—机制—输出三句因果链 |
| 变量/shape 错误 | 公式会背但维度不一致 | 手算一个小 batch 并加断言 |
| 目标错位 | 优化 loss 与业务指标混淆 | 写出训练目标和最终验收的差别 |
| 工程遗漏 | 不提显存、延迟、失败回退 | 补资源账本和异常状态 |
| 评估错位 | 只报平均分 | 增加切片、反事实和置信区间 |
| 证据越界 | 把社区推测说成模型事实 | 给句子标 A/B/C/D 证据等级 |
| 表达失序 | 先列十个方法，没有目标 | 用任务契约开头，删掉无关名词 |

错误日志最好记录“下一次要做的最小动作”，例如“明天不看资料手算带 padding 的 attention mask”，而不是“再看一遍 Transformer”。动作越具体，复盘越容易闭环。

### 38.9 用未知变体做迁移评估

熟悉题目上的高分很容易被记忆解释。迁移评估应改变输入、约束或输出协议，同时保留底层机制。例如：

1. 把普通文本题改成带表格和缺失字段的题，检查是否会处理证据不完整。
2. 把单轮 SFT 样本改成多轮对话，检查 label mask 和上下文边界。
3. 把标准 attention 改成带 padding 和不同长度 batch，检查 mask 与最后有效 token。
4. 把单模型质量题改成质量、延迟、成本和安全同时存在的系统题。
5. 把已知模型名替换成未公开细节的产品描述，检查是否能区分事实与推测。

迁移分数可以单独记录：

~~~math
\mathrm{TransferGap}=
\mathrm{Score}_{\mathrm{familiar}}
-\mathrm{Score}_{\mathrm{variant}}
~~~

差距大并不意味着所有知识都没有学会；它指出了知识依赖表面线索的地方。应进一步按定义、推导、实现、评估和安全分桶，找到最小修复单元。

### 38.10 第一册的最终综合评估

读完第一册后，综合评估不应是把 38 个标题逐个朗读。更好的评估包含四个部分：

#### 机制重建

随机抽取一个核心对象，要求从定义写到公式和 shape，例如从 next-token 目标推到 cross entropy，或从 Q/K/V 推到 attention 输出。评分重点是变量关系和边界，而不是术语数量。

#### 实验设计

给出一个异常现象，例如“loss 下降但真实任务变差”，要求写出至少三个可区分假设、固定变量和结果解释。没有实验控制的方案建议只能算猜测。

#### 最小实现

在不调用大型模型 API 的情况下，写一个小实现验证 mask、log probability、cache 容量、对比损失或 token 预算。代码应有输入、输出、断言和已知失败案例。

#### 未知变体

对一个没有见过的模态、模型版本或系统约束，要求说明哪些事实已知、哪些只是推测、下一步如何核验。它测的是方法迁移，不是新闻记忆。

综合结果可以写成证据表，而不是一个神秘总分：

| 证据 | 结果 | 仍需补什么 |
| --- | --- | --- |
| 公式与 shape | 通过/部分通过 | 哪个变量仍混淆 |
| 最小实现 | 通过/失败 | 哪个断言失败 |
| 反事实实验 | 通过/失败 | 哪种边界未覆盖 |
| 真实项目复盘 | 有/无 | 是否有 baseline 和失败切片 |
| 未知变体 | 稳定/不稳定 | 事实边界或迁移能力缺口 |

这种记录比“已经完成第一册”更诚实，也更容易决定下一轮时间投入。学习目标不是让所有主题都达到相同深度，而是知道每个主题目前的证据强度和下一步动作。

### 38.11 一个间隔复习调度的最小实现

下面的代码是一个教学用调度器。它不声称能精确预测遗忘，只把“成功检索延长间隔、失败检索缩短间隔、变体任务降低置信度”变成可观察的状态。真正的学习效果仍要由延迟测试和陌生题表现验证。

```python
from dataclasses import dataclass


@dataclass
class Topic:
    name: str
    interval_days: float = 1.0
    strength: float = 0.4
    next_day: float = 0.0


def review(topic, day, recall_ok, variant_ok):
    if recall_ok and variant_ok:
        topic.strength = min(1.0, topic.strength + 0.12)
        topic.interval_days = min(28.0, topic.interval_days * 1.8)
    elif recall_ok:
        topic.strength = min(1.0, topic.strength + 0.04)
        topic.interval_days = max(1.0, topic.interval_days * 1.2)
    else:
        topic.strength = max(0.0, topic.strength - 0.10)
        topic.interval_days = 1.0
    topic.next_day = day + topic.interval_days


topics = [Topic("attention"), Topic("DPO"), Topic("VLM")]
events = [
    (0, "attention", True, True),
    (0, "DPO", True, False),
    (1, "VLM", False, False),
    (2, "attention", True, True),
    (3, "DPO", True, True),
]

by_name = {topic.name: topic for topic in topics}
for day, name, recall_ok, variant_ok in events:
    review(by_name[name], day, recall_ok, variant_ok)

for topic in topics:
    print(topic.name, round(topic.strength, 2), round(topic.next_day, 1))
```

这个实现故意保留了简化：没有根据题目难度、响应时间、提示依赖和长期保持真实估计参数。它的教学价值在于展示状态更新；工程上可以把每次复习的题目版本、延迟、错误类别和证据产物一起保存，之后再分析哪些间隔和任务类型真正带来迁移。

### 38.12 从“会说”到“能负责”

技术表达的最后一层不是语言流畅，而是能够对判断负责。一个成熟的回答或报告应当让读者知道：结论是什么，依据是什么，哪些条件成立，哪里可能失败，下一步如何验证。如果使用了论文结果，要说明论文设置；如果使用了产品页，要说明它只证明公开接口；如果使用了自己的实验，要报告数据、版本和限制。

这也是本书各章共同的收束方式。语言模型的公式、Transformer 的 shape、训练的 loss、推理的 cache、多模态的证据和 Agent 的权限，都不应停留在名词表中。它们要进入同一个工作循环：定义问题、建立机制模型、做最小实验、记录失败、比较取舍、保留证据。

## 资料与证据边界

本部分关于技术诊断的内容是对前四部分方法的综合，不把任何单一公司的招聘流程当作普遍标准。开放问题的实验、评分和学习调度示例都是教学构造，数值用于展示变量关系，不能替代目标团队或真实项目的测量。

复习方法部分核验了两篇经典学习科学研究：

1. Roediger III and Karpicke, *Test-Enhanced Learning*，Psychological Science, 2006，DOI：[10.1111/j.1467-9280.2006.01693.x](https://doi.org/10.1111/j.1467-9280.2006.01693.x)。研究比较重复阅读和测试对延迟保持的影响，支持把主动检索视为学习过程的一部分；它不提供适用于所有技术主题的固定复习日历。
2. Cepeda et al., *Distributed practice in verbal recall tasks: A review and quantitative synthesis*，Psychological Bulletin, 2006，DOI：[10.1037/0033-2909.132.3.354](https://doi.org/10.1037/0033-2909.132.3.354)。综述与定量综合支持分散练习的总体价值，并强调练习间隔、保持间隔和材料条件会影响收益；本章因此把 12 周安排写成可调整的资源模板，而不是硬规则。

前四部分使用的模型论文和官方资料仍是本部分技术例子的依据，包括 Transformer、GPT-3、Chinchilla、SFT/RLHF、DPO、CLIP、VLM、Diffusion、Whisper、视频生成，以及 PyTorch、Transformers、TRL、vLLM 等官方文档。对最新闭源模型，本章只沿用已经核验的公开输入输出或技术报告，不根据社区推测补写内部结构。链接和资料边界的具体条目以前四部分各章末的资料清单为准。
